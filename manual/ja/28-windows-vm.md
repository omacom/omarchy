# Windows VM

Omarchy では、x86_64 マシン上で Docker VM を通じて Windows を実行する簡単な方法を提供しています。Omarchy メニュー（`Super + Space`）から _Install > Windows_ を使ってインストールできます。

これにはマシンに KVM 仮想化が必要ですが、ほとんどのマシンが対応しています。ただし、BIOS で無効になっていることもあり、その場合はインストーラーが知らせてくれます。ディスク容量も必要です。Windows に割り当てる分に加え、イメージ自体に約 10GB が必要です。

インストーラーでは、割り当てる RAM の量、CPU コア数、ディスク容量（64GB 以上が現実的な下限です）を尋ね、次に Windows のユーザー名とパスワードを尋ねます。空欄のままにすると `docker` / `admin` になります。ダウンロードには時間がかかります。10-15 分が普通です。進行状況はブラウザーで `http://127.0.0.1:8006` から確認できます。コンソールを開く前に、ブラウザーで同じユーザー名とパスワードの入力を求められます。

## 使い方

インストールが終わったら、アプリランチャーから _Windows_ を起動してください。VM がまだ動いていなければ起動し、RDP で全画面接続します。コールドスタート時は 15-30 秒待ってください。

RDP セッションでは音声、マイク、共有クリップボードが使えるため、Linux と Windows の間でテキストをコピーするのもそのまま機能します。解像度はウィンドウに追従し、Omarchy はディスプレイのスケーリングをそのまま渡すので、HiDPI 画面でもぼやけたひどい表示にはなりません。

RDP ウィンドウを閉じると、VM は自動的にシャットダウンします。動かしっぱなしにしたい場合、たとえば中で何かを作業させている場合は、代わりに `omarchy windows vm launch --keep-alive` で起動してください。

残りの操作も同じコマンドで行います。

```bash
omarchy windows vm status    # is it running?
omarchy windows vm stop      # shut it down
omarchy windows vm launch    # start and connect
```

## ファイルの共有

ホームディレクトリ内の `~/Windows` ディレクトリは、自動的に VM と共有されます。Windows からアクセスしたいファイルはそこに置いてください。VM はファイルシステムの他の部分には一切アクセスできないため、Windows 側に厄介なものがあっても安全です。VM 自身の仮想ディスクは `~/.windows` にあります。

それらのおなじみのホームパスは、それぞれ独自のファイルシステム上に置かれます。自分が所有するディレクトリへのシンボリックリンクでも構いません。仮想ディスクをより大きなドライブに置く場合に便利です。インストーラーは、必ずしもホームディレクトリを含むファイルシステムではなく、実際に `~/.windows` を含むファイルシステムの空き容量を測定します。

ディスク用パスと共有用パスは、重ならない別々のディレクトリにしてください。削除時には意図的にディスクディレクトリを空にしますが、共有ディレクトリは保持されます。削除の直前に、Omarchy は制限付きの包含チェックを行い、そのチェックがタイムアウトしたり、2 つのツリーが別々であることを証明できなかったりした場合は、何も削除しません。

VM の起動前に、Omarchy はその 2 つのディレクトリを開いて固定し、正確なディレクトリ inode を `/var/lib/omarchy/windows/mounts` 以下にあるユーザーごとのプライベートなアンカーにバインドマウントします。Docker から見えるのは、root で保護されたそれらのアンカーだけです。これにより、カスタムのディスク配置を保持しながら、特権コンテナがチェック済みのパスを使用する前に、あなたとして実行されている別のプロセスがそのパスをすり替えることを防ぎます。既存のディスク用ディレクトリと共有ディレクトリは、移行時にモード `0700` に厳格化され、他のローカルアカウントが中身を閲覧できないようになります。

VM のポートは localhost にのみバインドされるため、ネットワーク上の何ものも Windows マシンに到達できません。Web コンソールでも、設定済みの Windows ユーザー名とパスワードが必要であり、別のローカルアカウントがポート 8006 経由で VM を操作することはできません。

## 制限とライセンス

この構成では GPU パススルーはありません。そのため、ゲームや動画編集には向きません。Microsoft Office や、どうしても必要なものを実行するには最適な方法です。

インストールされるバージョンは Windows 11 Pro で、ライセンス認証はされていません。制限された機能を使うには、自分のライセンスキーが必要です。

このコンピューターが Windows を搭載して出荷された場合、Omarchy をインストールした後でも OEM キーはファームウェア内に残っています。`omarchy windows key` で表示できます。そのキーはこのマシンに紐付けられています。このハードウェアに再インストールした Windows は認証できますが、通常 VM は認証できません。

リソース割り当ては後から変更できます。ターミナルで `omarchy windows vm install` を実行すると、回答に基づいて VM の設定が書き換えられます。compose ファイル自体は現在 `/var/lib/omarchy/windows/docker-compose.yml` にあり、root が所有しています。これは意図的なもので、あなたとして実行されているプロセスがそれを書き換え、特権的な起動処理にディスク全体をコンテナへマウントさせることができないようにするためです。手動で編集する必要がある場合（たとえば USB デバイスをマウントする場合）は、`sudo` で編集し、すべてのオプションについては [Dockur Windows プロジェクト](https://github.com/dockur/windows) を参照してください。

すべてを削除するには、Omarchy メニューから _Remove > Windows_ を使ってください。これにより `~/.windows` 内の VM のディスクと、Windows 内にインストールされたすべてが削除されるため、必要なものは先に VM からコピーしておいてください。共有用の `~/Windows` フォルダーはそのまま残ります。
