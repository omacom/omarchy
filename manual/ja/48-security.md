# セキュリティ

Omarchy はセキュリティを極めて真剣に考えています。これは _現実の世界_ で _本当の仕事_ をするために使えるオペレーティングシステムを目指したものだからです。ノートパソコンを失くしても、セキュリティ上の緊急事態にはなりません。私たちがやっているのは次のとおりです:

1. *ディスク全体の暗号化が必須*: これはデータの物理的な保護を確実にするうえで最も重要なステップです。コンピューターを紛失したり盗まれたりしても、データは標準的な LUKS (Linux Unified Key Setup) を使って完全に暗号化されています。
2. *Firewall はデフォルトで有効*: [LocalSend](https://localsend.org/) 用のポート 53317 を除き、すべての受信トラフィックはデフォルトでブロックされます。ssh でさえ、_Setup > Security > SSHD_ から有効にするまではオフのままで、そのセットアップの一環としてポート 22 が開かれます（ブルートフォース対策のレート制限付き）。コンテナがうっかり世界中に公開されてしまわないよう、[ufw-docker](https://github.com/chaifeng/ufw-docker) のセットアップを使って Docker へのアクセスまでロックダウンしています。
3. *Arch は常に最新のアップデートを提供*: Omarchy の基盤となるディストリビューションである Arch はローリングリリースです。つまり、どこかのパッケージでセキュリティ脆弱性が発見されてパッチが当てられれば、`omarchy-update` を使ってすぐにインストールできるようになります。そのため、常にあらゆるものの最新で最も安全なバージョンを実行できます。
4. *Omarchy は独自のパッケージとミラーを維持*: Omarchy はデフォルトで、Arch 独自の core/extra/multilib リポジトリと、Omarchy 独自の Omarchy Package Repository のパッケージだけに依存します。AUR から直接ソフトウェアをインストールすることはできますが、ベースインストールではそうしません。サードパーティのブラウザなど、ごく一部のオプションインストールだけが AUR から取得します。
5. *Cloudflare が DDoS から私たちを守る*: Omarchy の配信インフラストラクチャ ― ISO、Omarchy パッケージ、Arch ミラー ― は、Cloudflare の強固な DDoS シールドの背後で保護され、同社の CDN 上でホストされています。これにより、卓越した可用性が得られます。

## パスワードを変更する

暗号化されたインストールには 2 つのパスワードがあります。起動時にドライブのロックを解除するためのものと、ログインや `sudo` に使うものです。Setup では両方が同じものになります。どちらも Omarchy メニューの _Update > Password_ で変更できます ― 最初のものは _Drive Encryption_、2 番目のものは _User_ です。ドライブのパスワードを変更する際は、まず現在のパスワードの入力を求められるので、手元に用意しておいてください。変更が中断された場合は、_Drive Encryption_ をもう一度実行してください。今ドライブのロックを解除するパスワードの入力を求められ、変更を完了します。

## 使用済みのマシンを人に渡す

マシンを他の人に渡す場合、再インストールする必要はありません。Omarchy メニューで _Setup > Reset Computer_ を実行し、確認のために `reset` と入力して再起動してください。これにより、すべてのユーザーアカウントと `/home` 内のすべてが消去され、インストール後に行ったパッケージやシステムの変更はすべて破棄され、マシンの識別情報 ― ネットワーク接続、ホストキー、その他すべて ― が消去されます。次に起動してくるのは初回起動時のセットアップウィザードで、新しい所有者が自分の名前、パスワード、暗号化パスワードを入力できる状態になっています。

これはインストーラーが取得するベースラインスナップショットを復元することで動作するため、Omarchy ISO からインストールされたマシンでのみ利用できます。また、暗号化されていないドライブでは、リセットは安全な消去ではなく通常の削除になります。そのため、データが機密性の高いものだった場合は、代わりに新規インストールを行ってください。

## パスワードなしの sudo

`sudo` にパスワードを聞かれるのが煩わしくなることがあります。AI agent が長時間にわたってシステム作業を代行しているときに最もよくあります。_Setup > Security > Passwordless Sudo_ では、アクセスを許可する期間を尋ねられます: **15分**、**1時間**、**1日**、または **永続的** です。アクセスが有効な間、メニューバーの他のインジケーターの横に赤い警告アイコンが表示されます。それをクリックするか、コマンドをもう一度実行すると、アクセスをオフにできます。`omarchy-sudo-passwordless 30` のように、任意の分数（1 から 1440 まで）を渡すこともできますし、`omarchy-sudo-passwordless permanent` を使うこともできます。

時間制限付きのアクセスは自動的に期限切れになります。期限を過ぎてサスペンドから復帰した場合も、直ちに期限切れになります。コンピューターを再起動すると、早めに終了します。永続的なアクセスは再起動後も存続し、無効にするまで有効なままです。

Omarchy の設定パッケージを更新または削除すると、その有効期限サポートが変更される前に、一時的な許可はすべて終了します。コマンドが認証エラーやクリーンアップエラーを報告した場合は、別の許可を有効にしようとする前にそれを解決してください。エラーが出たからといって、パスワードなしのアクセスが無効になっているとは限りません。

この点ははっきり理解しておいてください。これが有効な間、あなたのユーザーとして実行されているものはすべて、尋ねられることなく root として何でもできてしまいます。それこそがこの機能の目的なのですが、同時にリスクのすべてでもあります。

## 署名キー

すべての ISO 署名と Omarchy リポジトリパッケージに対する公開鍵は `40DFB630FF42BCFFB047046CF0134EE680CAC571` です（[openpgp.org で確認](https://keys.openpgp.org/search?q=pkgs%40omarchy.org)）。`omarchy/omarchy-keyring` パッケージにもこの鍵が含まれており、将来のあらゆる更新をシームレスに展開するために使われます。

任意の ISO リリースの署名は、URL に .sig を追加することで見つけることができます。例: https://iso.omarchy.org/omarchy-x.x.x.iso.sig.
