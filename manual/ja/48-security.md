# セキュリティ

Omarchy はセキュリティを極めて真剣に考えています。これは _現実の世界_ で _本当の仕事_ をするために使えるオペレーティングシステムとして設計されています。ノートパソコンをなくしても、セキュリティ上の緊急事態にはつながらないようにするためです。私たちの取り組みは次のとおりです：

1. *デフォルトでフルディスク暗号化が有効*：これはあなたのデータの物理的な保護を確保するうえで最も重要なステップです。コンピューターを紛失したり盗まれたりしても、データは標準の LUKS (Linux Unified Key Setup) を使って完全に暗号化されています。インストーラーでは使い捨てのマシン向けにオプトアウトできます（[はじめに](02-getting-started.md) を参照）。暗号化なしでインストールした場合、この保護は一切なく、ドライブを手にした人は誰でも読み取ることができます。
2. *デフォルトでファイアウォールが有効*：すべての受信トラフィックはデフォルトでブロックされ、少数の例外があります：[LocalSend](https://localsend.org/) 用のポート 53317、Docker ブリッジアドレス (172.17.0.1) にあるコンピューター自身のリゾルバへの DNS クエリで、Docker がコンテナに割り当てるプライベートアドレス範囲から受け付けられるもの、そしてマルチキャスト DNS (ポート 5353) です。これにより、ネットワーク上のプリンターやその他のデバイスが互いを検出でき、あなたのコンピューターの名前もそこで通知されます。これらに加えて、ファイアウォールは ping、ルーターからアドレスを取得すること (DHCP)、そして UPnP 検出に対する UFW の標準的な許可を保持します。ssh でさえ、_Setup > Security > SSHD_ から有効にするまでオフになっており、そのセットアップの一環としてポート 22 を開きます（ブルートフォースに対してレート制限付き）。Docker アクセスも [ufw-docker](https://github.com/chaifeng/ufw-docker) のセットアップを使ってロックダウンし、コンテナが誤って世界に公開されるのを防いでいます。
3. *Arch は常に最新のアップデートを提供*：Omarchy の基盤となるディストロである Arch は、ローリングディストリビューションです。つまり、どのパッケージでもセキュリティ脆弱性が発見され修正されれば、`omarchy-update` を使ってすぐにインストールできるようになります。その方法で、常にすべてについて最新で最も安全なバージョンを実行できます。
4. *Omarchy は独自のパッケージとミラーを維持*：Omarchy はデフォルトで、Arch 自身の core/extra/multilib リポジトリと、独自の Omarchy Package Repository のパッケージのみに依存します。AUR から直接ソフトウェアをインストールできますが、ベースインストールではそうしません — サードパーティ製ブラウザのような、ごく一部のオプションインストールだけが AUR から取得します。
5. *Cloudflare が DDoS から保護*：Omarchy の配布インフラ — ISO、Omarchy パッケージ、Arch ミラー — は Cloudflare の強固な DDoS シールドの背後で保護され、その CDN 上でホストされています。これにより優れた可用性が得られます。

## パスワードの変更

暗号化されたインストールには 2 つのパスワードがあります：起動時にドライブのロックを解除するものと、ログインと `sudo` に使うものです。セットアップでは両方が同じに設定されます。どちらも Omarchy メニューの _Update > Password_ から変更できます — 前者は _Drive Encryption_、後者は _User_ です。ドライブのパスワードを変更する際は、まず現在のパスワードの入力を求められるので、手元に用意しておいてください。変更が中断された場合は、_Drive Encryption_ をもう一度実行してください：現在ドライブのロックを解除できるパスワードを尋ね、変更を完了します。

## 使用済みのマシンを譲り渡す

マシンを他の人に渡す場合、再インストールする必要はありません。Omarchy メニューで _Setup > Reset Computer_ を実行し、確認のために `reset` と入力して、再起動してください。これにより、すべてのユーザーアカウントと `/home` 内のすべてが消去され、インストール後に行ったすべてのパッケージとシステム変更が破棄され、マシンのアイデンティティ — ネットワーク接続、ホストキー、そのすべて — がクリアされます。再起動後に表示されるのは初回起動時のセットアップウィザードで、新しい所有者が自分の名前、パスワード、暗号化パスワードを入力できる状態になっています。

これはインストーラーが取得したベースラインスナップショットを復元することで動作するため、Omarchy ISO からインストールされたマシンでのみ利用できます。また、暗号化されていないドライブでは、リセットはセキュアな消去ではなく削除にすぎないため、データが機密性の高いものであった場合は、代わりに新規インストールを行ってください。

## パスワードなしの sudo

`sudo` にパスワードを聞かれるのをやめさせたい場合があります。最も多いのは、AI エージェントが長時間のシステム作業を代行しているときです。_Setup > Security > Passwordless Sudo_ では、アクセスを許可する期間を尋ねます：**15分**、**1時間**、**1日**、または **永続的** です。アクセスが有効な間は、他のメニューバーインジケーターの横に赤い警告アイコンが表示されます。それをクリックするか、コマンドをもう一度実行するとアクセスをオフにできます。`omarchy-sudo-passwordless 30` のように独自の分数（1 から 1440 まで）を渡すことも、`omarchy-sudo-passwordless permanent` を使うこともできます。

時間制限付きアクセスは自動的に期限切れになります。期限を跨いだサスペンドから復帰した直後も含まれます。コンピューターを再起動すると早期に終了します。永続的なアクセスは再起動後も維持され、無効にするまで有効なままです。

Omarchy の設定パッケージを更新または削除すると、その有効期限サポートが変更される前に、一時的な許可はすべて終了します。コマンドが承認またはクリーンアップのエラーを報告した場合は、別の許可を有効にしようとする前に解決してください；エラーはパスワードなしアクセスが無効であることを意味しません。

この点ははっきり理解しておいてください：これがオンになっている間、あなたのユーザーとして実行されているものはすべて、尋ねられることなく root として何でもできます。それがまさに目的であり、同時にまさにリスクでもあります。

## 署名キー

すべての ISO 署名と Omarchy リポジトリパッケージの公開鍵は `40DFB630FF42BCFFB047046CF0134EE680CAC571` です（[openpgp.org で確認](https://keys.openpgp.org/search?q=pkgs%40omarchy.org)）。`omarchy/omarchy-keyring` パッケージにもこれが含まれており、潜在的な更新をシームレスに展開するために使用されます。

ISO リリースの署名は、その URL に `.sig` を追加することで見つけることができます。例：`https://iso.omarchy.org/omarchy-x.x.x.iso.sig`。
