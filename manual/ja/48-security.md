# セキュリティ

Omarchyはセキュリティを極めて真剣に考えています。これは、_現実の仕事_ を _現実の世界_ で行うために使えるオペレーティングシステムを目指したものです。ノートパソコンを紛失しても、それがセキュリティ上の緊急事態につながらないようにします。Omarchyでは次のようにしています。

1. *フルディスク暗号化が必須です*: これは、あなたのデータを物理的に保護するための最も重要なステップです。コンピュータを紛失したり盗まれたりしても、データは標準のLUKS (Linux Unified Key Setup)を使って完全に暗号化されています。
2. *ファイアウォールはデフォルトで有効です*: [LocalSend](https://localsend.org/)のためのポート53317を除き、着信トラフィックはすべてデフォルトでブロックされます。sshでさえ、_Setup > Security > SSHD_から有効にするまではオフであり、このセットアップの一環としてポート22を開きます（ブルートフォースに対してレート制限がかかります）。さらに、コンテナがうっかり世界に公開されてしまわないよう、[ufw-docker](https://github.com/chaifeng/ufw-docker)のセットアップを使ってDockerへのアクセスも厳しく制限しています。
3. *Archには常に対最新のアップデートがあります*: Omarchyのベースである基盤ディストリビューションのArchは、ローリングリリースのディストリビューションです。つまり、どのパッケージでセキュリティ脆弱性が発見されパッチが適用されても、`omarchy-update`を使って素早くインストールできます。そうすることで、常にすべての最新で最も安全なバージョンを実行できます。
4. *Omarchyは独自のパッケージとミラーを維持しています*: Omarchyはデフォルトで、Arch自身のcore/extra/multilibリポジトリと、Omarchy独自のOmarchy Package Repositoryのパッケージのみに依存します。AURから直接ソフトウェアをインストールすることもできますが、ベースインストールではそうしません。サードパーティ製ブラウザのような、ごく少数のオプションインストールだけがAURから取得します。
5. *CloudflareがDDoSから守っています*: Omarchyの配布インフラストラクチャ —— ISO、Omarchyのパッケージ、Archミラー —— は、Cloudflareの強固なDDoSシールドの背後で保護され、そのCDNでホストされています。これにより、優れた可用性が提供されます。

## パスワードの変更

暗号化されたインストールには2つのパスワードがあります。起動時にドライブのロックを解除するものと、ログインおよび`sudo`に使うものです。セットアップでは、この2つが同じに設定されます。どちらもOmarchyメニューの_Update > Password_で変更できます —— 最初のものは_Drive Encryption_、2つ目は_User_です。ドライブのパスワードを変更する際は、まず現在のパスワードの入力を求められるので、手元に用意しておいてください。変更が中断された場合は、もう一度_Drive Encryption_を実行してください。現在ドライブのロックを解除できるパスワードの入力を求められ、変更を完了します。

## すでに使用したマシンを譲り渡す

マシンを他の誰かに譲る場合、再インストールする必要はありません。Omarchyメニューで_Setup > Reset Computer_を実行し、確認のために`reset`と入力して、再起動してください。これにより、すべてのユーザーアカウントと`/home`内のすべてが消去され、インストール以降にあなたが行ったすべてのパッケージとシステム変更が破棄され、マシンの識別情報 —— ネットワーク接続、ホストキー、その他すべて —— が消去されます。再起動後に表示されるのは、初回起動時のセットアップウィザードであり、新しい所有者が自分の名前、パスワード、暗号化パスワードを入力する準備ができています。

これは、インストーラーが取得したベースラインスナップショットを復元することで動作するため、Omarchy ISOからインストールされたマシンでのみ利用できます。また、暗号化されていないドライブでは、リセットはセキュアイレースではなく削除に過ぎないため、データが機密性の高いものであった場合は、代わりに新規インストールを行ってください。

## パスワードレスsudo

`sudo`にパスワードを尋ねられるのを止めたくなることがあります。最も多いのは、AIエージェントがあなたのために長時間のシステム作業を行っているときです。_Setup > Security > Passwordless Sudo_では、アクセスを許可する期間を尋ねられます。**15分**、**1時間**、**1日**、または**永続**です。アクセスが有効な間、他のメニューバーインジケーターの横に赤い警告アイコンが表示されます。それをクリックするか、コマンドを再度実行することで、アクセスをオフにできます。`omarchy-sudo-passwordless 30`で独自の分数（1から1440まで）を渡すことや、`omarchy-sudo-passwordless permanent`を使うこともできます。

時間制限付きのアクセスは自動的に期限切れになり、期限を越えてサスペンドから復帰した直後も含まれます。コンピュータを再起動すると、早期に終了します。永続的なアクセスは再起動後も維持され、無効にするまで有効なままです。

Omarchyの設定パッケージを更新または削除すると、その期限サポートが変更される前に、一時的な許可は終了します。コマンドが認証またはクリーンアップのエラーを報告した場合は、別の許可を有効にしようとする前に、そのエラーを解決してください。エラーはパスワードレスアクセスが無効であることを意味するものではありません。

この点については率直に見極めてください。有効な間は、あなたのユーザーとして実行されているものはすべて、尋ねられることなくrootとして何でもできます。それがこの機能の目的ならすべてであり、同時にリスクのすべてでもあります。

## 署名キー

すべてのISO署名とOmarchyリポジトリパッケージの公開キーは`40DFB630FF42BCFFB047046CF0134EE680CAC571`です（[openpgp.orgで確認](https://keys.openpgp.org/search?q=pkgs%40omarchy.org)）。`omarchy/omarchy-keyring`パッケージにもこれが含まれており、将来の潜在的な更新をシームレスに展開するために使用されます。

任意のISOリリースの署名は、そのURLに`.sig`を加えることで見つけることができます。例：`https://iso.omarchy.org/omarchy-x.x.x.iso.sig`。
