# セキュリティ

Omarchyはセキュリティを極めて真剣に考えています。これは、_Real World_ で _Real Work_ を行うために使えるオペレーティングシステムを目指したものです。ラップトップを紛失しても、セキュリティ上の緊急事態につながらないようにするためです。具体的には、以下の対策を行っています。

1. *デフォルトでフルディスク暗号化がオン*: これは、データの物理的な保護を確保するうえで最も重要なステップです。コンピューターを紛失したり盗まれたりしても、データは標準的なLUKS（Linux Unified Key Setup）を使って完全に暗号化されています。インストーラーでは使い捨て用のマシン向けに無効化することもできます（[はじめに](02-getting-started.md)を参照）。暗号化なしでインストールした場合はこの保護は一切なく、ドライブを手にした者は誰でも内容を読み取れます。
2. *ファイアウォールがデフォルトで有効*: すべての着信トラフィックはデフォルトでブロックされ、いくつかの例外があります。[LocalSend](https://localsend.org/)用のポート53317、Dockerブリッジアドレス（172.17.0.1）にあるコンピューター自体のリゾルバーへのDNSクエリ（Dockerがコンテナに割り当てるプライベートアドレス範囲から受け付けます）、そしてマルチキャストDNS（ポート5353）です。これにより、ネットワーク上のプリンターなどのデバイス同士が互いを見つけられるようになり、あなたのコンピューターの名前もそこで通知されます。これらに加えて、ファイアウォールはping、ルーターからアドレスを取得すること（DHCP）、UPnP検出に対するUFWの標準的な許可も維持します。sshでさえ、_Setup > Security > SSHD_ から有効にするまでオフのままです。これを行うと、SSH鍵が承認され、パスワードログインがオフになり、その時点で初めてポート22が開きます（ブルートフォース対策のレート制限付き）。さらに、[ufw-docker](https://github.com/chaifeng/ufw-docker)セットアップを使ってDockerへのアクセスも厳しく制限し、コンテナがうっかり世界中に公開されてしまうことを防いでいます。
3. *Archは常に最新のアップデートを提供*: Omarchyの基盤となっているディストロであるArchは、ローリングリリースディストリビューションです。つまり、どのパッケージでも、セキュリティ脆弱性が発見され修正されれば、`omarchy-update` を使ってすぐにインストールできるようになります。そうすることで、常にすべてが最新で最も安全なバージョンで動作します。
4. *Omarchyは独自のパッケージとミラーを維持*: Omarchyはデフォルトで、Arch自身のcore/extra/multilibリポジトリ（ARMマシンではArch Linux ARMのもの、Apple Siliconではそれに加えてAsahi ALARM）と、独自のOmarchy Package Repositoryのパッケージのみに依存します。AURから直接ソフトウェアをインストールすることもできますが、ベースインストールではそうしません。AURから取得するのは、サードパーティ製ブラウザのような、ごく一部の任意インストールだけです。
5. *CloudflareがDDoSから保護*: Omarchyの配布インフラストラクチャ（ISO、Omarchyパッケージ、Archミラー）は、Cloudflareの強固なDDoSシールドの背後で保護され、同社のCDN上でホストされています。これにより、優れた可用性が提供されます。

## パスワードの変更

暗号化されたインストールでは、パスワードが2つあります。ブート時にドライブのロックを解除するものと、ログインと `sudo` に使うものです。セットアップでは、この2つは同じものになります。Omarchyメニューの _Update > Password_ を使うと、両方を一度に変更でき、同じ状態に保てます。現在のドライブパスワードを聞かれた後、新しいパスワードを聞かれ、ドライブのパスワードを変更してから、ログインパスワードをそれに合わせて設定します。ドライブ暗号化がない場合は、ログインパスワードだけを変更します。変更が中断された場合は、もう一度 _Update > Password_ を実行してください。現在ドライブのロックを解除できるパスワードを聞かれ、変更を完了し、ログインパスワードをそれに設定します。別の暗号化ドライブのパスワードを変更するには、ターミナルで `omarchy-drive-password` を実行してください。

## すでに使ったマシンを譲渡する

マシンを他の人に譲る場合、再インストールする必要はありません。Omarchyメニューの _Remove > Factory Reset_ を実行し、確認のために `reset` と入力し、必要であればドライブ暗号化パスワードを入力して、再起動してください。これにより、すべてのユーザーアカウントと `/home` 内のすべてが消去され、インストール以降に行ったすべてのパッケージとシステム変更が破棄され、マシンのアイデンティティ（ネットワーク接続、ホスト鍵、その他すべて）がクリアされます。再起動後に表示されるのは初回ブート時のセットアップウィザードで、新しい所有者が自分の名前、パスワード、暗号化パスワードを入力できる状態になっています。

これは、インストーラーが取得するベースラインスナップショットを復元することで動作するため、Omarchy ISOからインストールされたマシンでのみ利用できます。また、暗号化されていないドライブでは、リセットは安全な消去ではなく単なる削除になるため、データが機密性の高いものだった場合は、代わりに新規インストールを行ってください。

## パスワード不要のsudo

`sudo` にいちいち聞かれるのをやめさせたい場合があります。最も多いのは、AIエージェントが長時間にわたってシステム作業を行っている場合です。_Setup > Security > Passwordless Sudo_ では、アクセスを許可する期間を尋ねられます。**15分**、**1時間**、**1日**、**永続** のいずれかです。アクセスが有効な間は、メニューバーの他のインジケーターの横に赤い警告アイコンが表示されます。それをクリックするか、コマンドを再度実行すると、アクセスをオフにできます。`omarchy-sudo-passwordless 30` のように、独自の分数（1から1440まで）を渡すこともできますし、`omarchy-sudo-passwordless permanent` を使うこともできます。

時間指定のアクセスは自動的に期限切れになります。有効期限を過ぎたサスペンドからの復帰直後も含まれます。コンピューターを再起動すると、早期に終了します。永続アクセスは再起動後も存続し、無効にするまで有効なままです。

Omarchyの設定パッケージを更新または削除すると、その有効期限サポートが変更される前に、一時的な許可はすべて終了します。コマンドが承認エラーやクリーンアップエラーを報告した場合は、別の許可を有効化しようとする前に、その問題を解決してください。エラーが発生しても、パスワード不要のアクセスが無効になっているとは限りません。

この点については、はっきり認識しておいてください。有効な間は、あなたのユーザーとして実行されるものはすべて、尋ねられることなくrootとして何でもできます。それがこの機能の目的なのですが、同時にリスクでもあります。

## 署名キー

すべてのISO署名とOmarchyリポジトリパッケージの公開鍵は `40DFB630FF42BCFFB047046CF0134EE680CAC571` です（[openpgp.orgで確認](https://keys.openpgp.org/search?q=pkgs%40omarchy.org)）。`omarchy/omarchy-keyring` パッケージにもこれが含まれており、将来の潜在的なアップデートもシームレスに展開するために使われます。

ISOリリースの署名は、そのURLに `.sig` を追加することで見つけることができます。例：`https://iso.omarchy.org/omarchy-x.x.x.iso.sig`。
