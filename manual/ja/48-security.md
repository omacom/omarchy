# セキュリティ

Omarchy はセキュリティを極めて真剣に受け止めています。これは、_現実の世界_で_本当の仕事_をするために使えるオペレーティングシステムを目指したものです。ノートパソコンを失くしても、セキュリティ上の緊急事態にはならないように。では、私たちが何をしているか紹介します：

1. *フルディスク暗号化がデフォルトで有効*：これは、データの物理的な保護を確保するうえで最も重要なステップです。コンピューターを紛失したり盗まれたりしても、データは標準的な LUKS（Linux Unified Key Setup）を使って完全に暗号化されています。インストーラーでは、使い捨てのマシン向けに無効化も選べます（[はじめに](02-getting-started.md) を参照）。暗号化なしでインストールした場合、この保護は一切なく、ドライブを手にした誰でも中身を読めます。
2. *ファイアウォールがデフォルトで有効*：受信トラフィックはすべてデフォルトでブロックされ、例外はごくわずかです：[LocalSend](https://localsend.org/) 用のポート 53317、コンピューター自身のリゾルバ宛ての DNS クエリで Docker ブリッジアドレス（172.17.0.1）へ向け、Docker がそのコンテナに割り当てるプライベートアドレス範囲から受け付けるもの、そしてマルチキャスト DNS（ポート 5353）です。これにより、ネットワーク上のプリンターやその他のデバイス同士が互いを見つけられるようになり、あなたのコンピューターの名前もそこに知らせます。これらに加えて、ファイアウォールは ping、ルーターからアドレスを取得すること（DHCP）、UPnP 検出に対する UFW の標準的な許可も維持します。ssh すら、_設定 > セキュリティ > SSHD_ から有効にするまではオフのままで、その設定の一部としてポート 22 が開きます（ブルートフォース対策のレート制限付き）。さらに、[ufw-docker](https://github.com/chaifeng/ufw-docker) の設定を使って Docker へのアクセスを厳しく制限し、コンテナがうっかり世界中に公開されてしまうのを防ぎます。
3. *Arch は常に最新のアップデートを提供*：Omarchy の基盤となるディストリビューションである Arch は、ローリングリリースのディストリビューションです。つまり、どのパッケージでセキュリティ脆弱性が発見され修正されても、`omarchy-update` を使ってすぐにインストールできます。そうすれば、常にすべて最新で最も安全なバージョンを実行できます。
4. *Omarchy は独自のパッケージとミラーを維持*：Omarchy はデフォルトで、Arch 自体の core/extra/multilib リポジトリと、独自の Omarchy Package Repository のパッケージにのみ依存します。AUR から直接ソフトウェアをインストールすることもできますが、ベースインストールではそうしません。AUR から取得するのは、サードパーティ製ブラウザーなど、ごく一部の任意インストールだけです。
5. *Cloudflare が DDoS から守る*：Omarchy の配布インフラ――ISO、Omarchy パッケージ、Arch ミラー――は、Cloudflare の強固な DDoS シールドの背後で保護され、同社の CDN でホストされています。これにより、優れた可用性が得られます。

## パスワードの変更

暗号化されたインストールには 2 つのパスワードがあります：起動時にドライブのロックを解除するものと、ログインと `sudo` に使うものです。セットアップでは両方が同じに設定されます。どちらも Omarchy メニューの _アップデート > パスワード_ から変更できます――前者は _ドライブ暗号化_、後者は _ユーザー_ です。ドライブのパスワードを変更する際は、まず現在のパスワードの入力を求められるので、手元に用意しておいてください。変更が中断された場合は、_ドライブ暗号化_ をもう一度実行してください：現在ドライブのロックを解除できるパスワードを尋ね、変更を完了します。

## すでに使ったマシンを譲る

マシンを他の人に譲る場合、再インストールする必要はありません。Omarchy メニューで _削除 > ファクトリーリセット_ を実行し、確認のために `reset` と入力して、再起動してください。これにより、すべてのユーザーアカウントと `/home` 内のすべてが消去され、インストール後に追加したすべてのパッケージとシステム変更が破棄され、マシンの識別情報――ネットワーク接続、ホスト鍵、そのすべて――が消去されます。再起動後に表示されるのは初回起動時のセットアップウィザードで、新しい所有者が自分の名前、パスワード、暗号化パスワードを入力できる状態になっています。

これは、インストーラーが取得したベースラインスナップショットを復元することで動作するため、Omarchy ISO からインストールされたマシンでのみ利用できます。また、暗号化されていないドライブでは、リセットはセキュアな消去ではなく単なる削除なので、データが機密性の高いものだった場合は、代わりに新規インストールを行ってください。

## パスワードレス sudo

`sudo` にいちいち聞かれるのをやめさせたい場合があります。最も多いのは、AI エージェントが長時間のシステム作業を代わりに行っているときです。_設定 > セキュリティ > パスワードレス sudo_ では、アクセスを許可する期間を尋ねます：**15分**、**1時間**、**1日**、または**永続**です。アクセスが有効な間、他のメニューバーインジケーターの横に赤い警告アイコンが表示されます。それをクリックするか、コマンドをもう一度実行するとアクセスをオフにできます。`omarchy-sudo-passwordless 30` のように自分の分数（1 から 1440 まで）を渡すこともできますし、`omarchy-sudo-passwordless permanent` を使うこともできます。

時間制限付きアクセスは自動的に期限切れになります。期限を跨いだサスペンドから復帰した直後も含まれます。コンピューターを再起動すると、早めに終了します。永続アクセスは再起動後も維持され、無効にするまで有効なままです。

Omarchy の設定パッケージをアップデートまたは削除すると、その有効期限サポートが変更される前に、一時的な許可は終了します。コマンドが認可エラーまたはクリーンアップエラーを報告した場合は、別の許可を有効にしようとする前に解決してください。エラーが出たからといって、パスワードレスアクセスが無効であるとは限りません。

この点ははっきり理解しておいてください：これがオンの間、あなたのユーザーとして実行されているものはすべて、尋ねられることなく root として何でもできます。それこそが目的であり、同時にリスクでもあります。

## 署名鍵

すべての ISO 署名と Omarchy リポジトリパッケージの公開鍵は `40DFB630FF42BCFFB047046CF0134EE680CAC571` です（[openpgp.org で確認](https://keys.openpgp.org/search?q=pkgs%40omarchy.org)）。`omarchy/omarchy-keyring` パッケージにもこれが含まれており、将来の潜在的なアップデートをシームレスに展開するために使われます。

どの ISO リリースの署名も、その URL に `.sig` を追加することで見つけられます。例：`https://iso.omarchy.org/omarchy-x.x.x.iso.sig`。
