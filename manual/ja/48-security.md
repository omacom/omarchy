# セキュリティ

Omarchy はセキュリティを極めて真剣に考えている。これは、_現実の世界_ で _本物の仕事_ をするために使えるオペレーティングシステムを目指したものだ。ノートパソコンを紛失しても、セキュリティ上の緊急事態にはならないように。そのために、われわれは次のことをしている：

1. *フルディスク暗号化がデフォルトで有効*：これは、データの物理的な保護を確保するうえで最も重要なステップだ。コンピュータを紛失したり盗まれたりしても、データは標準的な LUKS (Linux Unified Key Setup) を使って完全に暗号化されている。インストーラーでは、使い捨てのマシン向けにこれを無効化することもできる（[はじめに](02-getting-started.md) を参照）。ただし、暗号化なしでインストールした場合はこの保護は一切なく、ドライブを手にした人間は誰でも中身を読むことができる。
2. *ファイアウォールがデフォルトで有効*：すべての受信トラフィックはデフォルトでブロックされる。例外はわずかで、[LocalSend](https://localsend.org/) 用のポート 53317、Docker ブリッジアドレス (172.17.0.1) にあるコンピュータ自身のリゾルバへの DNS クエリ（Docker がコンテナに与えるプライベートアドレス範囲から受け付ける）、そしてマルチキャスト DNS (ポート 5353) だ。最後のものは、ネットワーク上のプリンターやその他のデバイスが互いを見つけられるようにし、そこにあなたのコンピュータの名前も通知する。これらに加えて、ファイアウォールは ping、ルーターからアドレスを取得すること (DHCP)、UPnP 検出に対する UFW の標準的な許可も維持する。ssh さえも、_Setup > Security > SSHD_ から有効にするまではオフのままだ。これを有効にすると SSH キーが認可され、パスワードログインが無効になり、その後でのみポート 22 が開く（ブルートフォース対策のレート制限付き）。さらに、[ufw-docker](https://github.com/chaifeng/ufw-docker) のセットアップを使って Docker へのアクセスも厳しく制限し、コンテナがうっかり世界中に公開されてしまうことがないようにしている。
3. *Arch は常に最新のアップデートを提供する*：Omarchy の基盤となるディストリビューションである Arch は、ローリングディストリビューションだ。つまり、どこかのパッケージでセキュリティ脆弱性が発見され、パッチが適用されれば、`omarchy-update` を使ってすぐにインストールできるようになる。そのため、常におよそすべてのソフトウェアの最新かつ最も安全なバージョンを実行できる。
4. *Omarchy は独自のパッケージとミラーを維持している*：Omarchy はデフォルトで、Arch 独自の core/extra/multilib リポジトリ（ARM マシンでは Arch Linux ARM、Apple Silicon では Asahi ALARM も加わる）と、独自の Omarchy Package Repository のパッケージにのみ依存する。AUR から直接ソフトウェアをインストールすることもできるが、ベースインストールはそうしない。AUR から取得するのは、サードパーティ製ブラウザのような、少数のオプションインストールだけだ。
5. *Cloudflare が DDoS から守ってくれる*：Omarchy の配布インフラストラクチャ（ISO、Omarchy パッケージ、Arch ミラー）は、Cloudflare の強固な DDoS シールドの背後に保護され、同社の CDN でホストされている。これにより、優れた可用性が実現する。

## パスワードの変更

暗号化したインストールにはパスワードが 2 つある。起動時にドライブのロックを解除するものと、ログインと `sudo` に使うものだ。セットアップでは、この 2 つは同じものになる。どちらも Omarchy メニューの _Update > Password_ から変更でき、1 つ目は _Drive Encryption_、2 つ目は _User_ を選ぶ。ドライブのパスワードを変更する際は最初に現在のパスワードを求められるので、手元に用意しておくこと。変更が中断された場合は、_Drive Encryption_ をもう一度実行すること。現在ドライブのロックを解除するパスワードを求められ、変更を最後まで完了してくれる。

## 使用済みのマシンを他人に渡す

誰かにマシンを譲る場合でも、再インストールする必要はない。Omarchy メニューで _Remove > Factory Reset_ を実行し、確認のために `reset` と入力し、求められたらドライブ暗号化パスワードを入力して、再起動する。これにより、すべてのユーザーアカウントと `/home` 内のすべてのものが消去され、インストール後に行ったすべてのパッケージとシステムの変更が破棄され、ネットワーク接続、ホストキー、その他すべてを含むマシンのアイデンティティが消去される。再起動後に表示されるのは初回起動時のセットアップウィザードで、新しい所有者が自分の名前、パスワード、暗号化パスワードを入力できる状態になっている。

これは、インストーラーが取得するベースラインスナップショットを復元することで動作するため、Omarchy ISO からインストールされたマシンでのみ利用できる。また、暗号化のないドライブでは、リセットはセキュアな消去ではなく単なる削除になるため、データが機密性の高いものだった場合は、代わりに新規インストールを行うこと。

## パスワードなしの sudo

`sudo` にいちいち聞いてほしくない場合がある。最も多いのは、AI エージェントに長時間のシステム作業を任せているときだ。_Setup > Security > Passwordless Sudo_ では、アクセスを許可する期間を尋ねられる。**15分**、**1時間**、**1日**、**永続的** のいずれかだ。アクセスが有効な間は、他のメニューバーインジケーターの横に赤い警告アイコンが表示される。それをクリックするか、このコマンドをもう一度実行すると、アクセスをオフにできる。`omarchy-sudo-passwordless 30` のように、独自の分数（1 から 1440 まで）を渡すこともできれば、`omarchy-sudo-passwordless permanent` を使うこともできる。

時間制限付きのアクセスは自動的に期限切れになる。期限を過ぎてしまったサスペンドから復帰した直後も同様だ。コンピュータを再起動すると、早めに終了する。永続的なアクセスは再起動後も維持され、無効化するまで有効なままになる。

Omarchy の設定パッケージを更新または削除すると、その有効期限サポートが変わる前に、一時的な許可はすべて終了する。コマンドが認可エラーまたはクリーンアップエラーを報告した場合は、別の許可を有効化しようとする前に、その問題を解決すること。エラーが出たからといって、パスワードなしのアクセスが無効になっているとは限らない。

この点については、はっきりと自覚しておくこと。これが有効な間、あなたのユーザーで実行されているものはすべて、一切確認されることなく root として何でもできる。それこそがこの機能の目的なのだが、それこそがリスクのすべてでもある。

## 署名キー

すべての ISO 署名と Omarchy リポジトリパッケージ用の公開鍵は `40DFB630FF42BCFFB047046CF0134EE680CAC571` だ（[openpgp.org で検証](https://keys.openpgp.org/search?q=pkgs%40omarchy.org)）。`omarchy/omarchy-keyring` パッケージにもこれが含まれており、将来のアップデートもシームレスに展開するために使われる。

任意の ISO リリースの署名は、その URL に `.sig` を追加することで見つけることができる。たとえば `https://iso.omarchy.org/omarchy-x.x.x.iso.sig` のように。
