# トラブルシューティング

### アップデートでシステムを壊してしまった！

まず[システムをロールバック](47-system-snapshots.md)して、最近のアップデート前のバージョンに戻してみてください。それでダメなら、`omarchy-debug` を使って Discord の #omarchy-help であなたの問題を共有してください。それでもすべてダメなら、`omarchy-reinstall` を使ってデフォルトの設定とパッケージを再インストールできます。

### 一部のアプリがディスプレイで大きすぎるのはなぜ？

Omarchy は 2x の高解像度ディスプレイを想定しているため、モニターパネルで倍率を選ぶまでは `GDK_SCALE` を 2 に設定します。1x ディスプレイを使っていて GTK や X11 のアプリが大きすぎる場合は、モニターパネルでそのディスプレイに 1x を選ぶか、`~/.config/hypr/monitors.lua` に `hl.env("GDK_SCALE", "1")` を追加してください（その後、大きすぎるアプリは再起動してください）。[モニターに関するマニュアル](33-monitors.md)を参照してください。

Spotify では、`Ctrl + Minus` で UI を縮小でき（`Ctrl + Plus` で拡大できます）。

### Super キーのバインドがすべて効かなくなったのはなぜ？

一部の ASUS ROG および TUF ノートPCでは、`Fn + Super` が見落としやすい組み合わせになっていて、ファームウェアの Windows キーロック（ゲーム中に誤ってゲームから離れないようにするためのもの）を切り替えます。画面上には何も表示されません。ロックがオンの間、Super は何も出力しません。そのため Super を使う Omarchy のバインドがすべて止まり、Hyprland が壊れたように見えます。

`~/.config/hypr/` を掘り下げる前に `Fn + Super` を一度押してください。それで Super が戻らなければ、ロックをオンのままにしないようもう一度押してください。これは Fn ロックではありません。Fn ロックは F キー列の動作を変えるだけです。

### Wi-Fi、Bluetooth、オーディオ、トラックパッドが突然動かなくなった

再起動する前に、問題のあるサブシステムだけを再起動してみてください。Omarchy メニューの _Update > Hardware_ には Wi-Fi、Bluetooth、Audio、Trackpad があり、そのうち1つを再読み込みすれば、「5分前まで動いていたのに」という状況の大半は解消します。再接続しない Bluetooth ヘッドセット、サスペンド後に反応しなくなったトラックパッド、モニターを外したら消えたサウンドなどです。

### 外部スピーカーから音が出ないのはなぜ？

おそらくプライマリ出力として設定されていないからです。バーの右側にあるスピーカーアイコンをクリックすると音量ポップアップが開き、そこで出力デバイスを選べます（アプリごとの音量ミックスもできます）。

### ノートPCのスピーカーの音がおかしい

一部のノートPCでは、Omarchy が自動的にスピーカーチューニングを適用し、内蔵スピーカーの周波数特性を補正します。`omarchy audio tuning status` であなたのマシンで有効になっているかどうかが分かり、`omarchy audio tuning off` でオフにしてスピーカーそのままの音を聞くこともできます。

### パスワードでログインや sudo ができないのはなぜ？

おそらく入力を何度も間違えてロックアウトされたのでしょう。ロック画面でこれが起きている場合は、`CTRL + ALT + F2` を押して新しい TTY を開始し、root としてログインしてから `faillock --reset --user [your-username]` を実行できます。それでロックアウトがリセットされ、使えるようになります。

### パスワードは通るのに、ログイン画面に戻ってしまう

セッション環境ファイルが壊れていると、パスワードが正しくてもデスクトップが起動しないことがあります。`~/.config/uwsm/env.d/` を編集した後は特に確認する価値があります。

`Ctrl + Alt + F2` を押し、通常のユーザー名とパスワードでログインして、現在のブートのユーザージャーナルを確認してください：

```bash
journalctl --user -b -t uwsm_env-preloader --no-pager
```

環境出力マークが見つからなかったというメッセージの直前に、`bad substitution` のような、あなたの環境ファイルのいずれかを名指しするエラーを探してください。もう一度ログインを試す前に、そのファイルを `env.d` の外に移動してください。たとえば、エラーが `99-custom` を名指ししている場合：

```bash
mkdir -p ~/.config/uwsm/disabled
mv -i ~/.config/uwsm/env.d/99-custom ~/.config/uwsm/disabled/
```

UWSM は構文エラーのあるファイルをスキップしますが、ファイル実行時にだけ現れる `bad substitution` のような致命的なエラーは、デスクトップの起動を妨げることがあります。システムスナップショットのロールバックではこれらのファイルは修復されません。`/home` はロールバックされないからです。

ログインできるようになったら、保存したコピーを修正してから戻してください。`sh -n` はファイルを実行せずに構文エラーを検出しますが、source されたときに発生するすべてのエラーを検出できるわけではありません。変更をテストしている間は、動作するターミナルを開いたままにしてください。

### 1Password SSH Agent / CLI の 1Password 認証プロンプトが表示されないのはなぜ？

これには2つの理由が考えられます：

リッチな承認プロンプトを表示するには、Settings > Advanced > Use Hardware Acceleration をオンにする必要があります。_注：これが機能し始めるには再起動が必要です。_

 ![troubleshooting-1password](images/troubleshooting-1password.webp)

あるいは、起動してから 1Password を一度も起動していない場合も、プロンプトは表示されません。
