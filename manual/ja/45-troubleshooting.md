# トラブルシューティング

### アップデートでシステムを壊してしまった！

まずは最近のアップデート前のバージョンに[システムをロールバック](47-system-snapshots.md)してみてください。それでダメなら、`omarchy-debug` を使って Discord の #omarchy-help で問題を共有してください。それでも全部ダメなら、`omarchy-reinstall` を使ってデフォルトの設定とパッケージを再インストールできます。

### なぜ一部のアプリがディスプレイでこんなに大きく表示されるのか？

Omarchy は 2x の高解像度ディスプレイを前提としているため、モニターパネルでスケールを選択するまでは `GDK_SCALE` を 2 に設定します。1x ディスプレイで GTK や X11 アプリが大きすぎる場合は、モニターパネルでそのディスプレイに 1x を選ぶか、`~/.config/hypr/monitors.lua` に `hl.env("GDK_SCALE", "1")` を追加してください（その後、大きすぎるアプリを再起動してください）。[モニターに関するマニュアル](33-monitors.md) を参照してください。

Spotify については、`Ctrl + Minus` で UI を縮小できます（`Ctrl + Plus` で拡大できます）。

### Super キーのキーバインドが全部効かなくなったのはなぜ？

一部の ASUS ROG および TUF ノートパソコンでは、`Fn + Super` は見落としやすいコンビネーションで、ファームウェアの Windows キーロックを切り替えます（ゲーム中に誤ってゲームを離脱しないようにするためのものです）。画面上には何も表示されません。ロックがオンの間、Super は何も出力しません。だから Super を使う Omarchy のバインドはすべて止まり、Hyprland が壊れたように見えます。

`~/.config/hypr/` を掘り下げる前に、まず `Fn + Super` を一度押してください。それで Super が戻らない場合は、ロックをオンのままにしないよう、もう一度押してください。これは Fn ロックではありません。Fn ロックは F キー行の動作を変えるだけです。

### Wi-Fi、Bluetooth、オーディオ、トラックパッドが突然動かなくなった

再起動する前に、問題のあるサブシステムだけを再起動してみてください。Omarchy メニューの _Update > Hardware_ には Wi-Fi、Bluetooth、Audio、Trackpad があり、そのうちの一つをリロードすれば、「5分前まで動いていたのに」という状況の大半は解消します。再接続できない Bluetooth ヘッドセット、サスペンド後に反応しなくなったトラックパッド、モニターを外したら消えたサウンドなどです。

### 外部スピーカーから音が出ないのはなぜ？

おそらくプライマリ出力に設定されていないからです。バーの右側にあるスピーカーアイコンをクリックすると音量ポップアップが開き、そこで出力デバイスを選べます（アプリごとの音量ミックスもできます）。

### ノートパソコンのスピーカーの音がおかしい

一部のノートパソコンでは、Omarchy が内蔵スピーカーの周波数特性を補正するスピーカーチューニングを自動的に適用します。`omarchy audio tuning status` で自分のマシンで有効かどうかが分かり、スピーカーの生の音を聞きたい場合は `omarchy audio tuning off` でオフにできます。

### パスワードでログインも sudo もできないのはなぜ？

おそらく10回間違えてロックアウトされたのでしょう。ロックアウトは2分後に自動的に解除されます。待てない場合で、これがロック画面で起きている場合は、`CTRL + ALT + F2` を押して新しい TTY を起動し、root でログインしてから `faillock --reset --user [your-username]` を実行できます。それでロックアウトがリセットされ、元通り使えます。

### パスワードは受け付けられるのに、ログイン画面に戻ってしまう

セッション環境ファイルが壊れていると、パスワードが正しくてもデスクトップが起動しないことがあります。特に `~/.config/uwsm/env.d/` を編集した後は確認する価値があります。

`Ctrl + Alt + F2` を押し、通常のユーザー名とパスワードでログインして、現在のブートのユーザージャーナルを確認してください：

```bash
journalctl --user -b -t uwsm_env-preloader --no-pager
```

`bad substitution` のような、環境ファイルの一つを名指しするエラーを探してください。env output mark が見つからなかったというメッセージの直前にあるはずです。再度ログインを試す前に、そのファイルを `env.d` から移動してください。たとえば、エラーが `99-custom` を名指ししている場合：

```bash
mkdir -p ~/.config/uwsm/disabled
mv -i ~/.config/uwsm/env.d/99-custom ~/.config/uwsm/disabled/
```

UWSM は構文エラーのあるファイルをスキップしますが、`bad substitution` のようにファイルの実行中にのみ現れる致命的なエラーは、依然としてデスクトップの起動を妨げることがあります。システムスナップショットのロールバックではこれらのファイルは修復されません。`/home` はロールバックされないからです。

ログインできるようになったら、保存したコピーを修正してから元に戻してください。`sh -n` はファイルを実行せずに構文エラーを検出しますが、ソースされたときに発生するすべてのエラーを検出できるわけではありません。変更をテストしている間は、動作するターミナルを開いたままにしてください。

### 1Password SSH Agent / CLI の 1Password 認証プロンプトが表示されないのはなぜ？

これには2つの理由が考えられます：

リッチな承認プロンプトを表示するには、Settings > Advanced > Use Hardware Acceleration をオンにする必要があります。_注：これが動作し始めるには再起動が必要です。_

 ![troubleshooting-1password](images/troubleshooting-1password.webp)

あるいは、起動してから 1Password を一度も起動していない場合も、プロンプトは表示されません。
