### エージェントのインストールとアップデート

Hermes を除き、これらのエージェントは mise の遅延インストールを使う: 初回起動で CLI がインストールされ、以降の起動ではそれを再利用する。mise はまた、インストール済みエージェントに新しいリリースがないか、最大で4時間に1回、起動直前かシェルプロンプトでバックグラウンドで確認する。そのアップデートが失敗したりオフラインだったりすれば、インストール済みのバージョンが動く。`omarchy update` は Omarchy の残りと一緒にインストール済みエージェントもアップデートし、`mup` は mise 管理ツールだけをアップデートする。

`claude update`、`codex update`、アプリ内のアップデートボタンといったエージェント自身のアップデーターでは、mise 管理のインストールはアップデートされない。`codex update` は失敗し、`claude update` は成功したと報告しながら mise が追跡しない別コピーをインストールすることがある。エージェント純正のインストーラーとアップデーターを使いたいなら、`disable_tools` に追加すること。[プリインストール済み CLI ツール](18-development-tools.md#preinstalled-cli-tools) を参照。

設定済みのすべての遅延ツールを必要になる前にインストールするには、`mise install --include-lazy` を実行すること。これにはエージェントだけでなく Omarchy の他のデフォルト CLI ツールも含まれる。単一ツールのインストールや独自のインストールの利用については [プリインストール済み CLI ツール](18-development-tools.md#preinstalled-cli-tools) を参照。

`grok` は mise のファーストパーティ `grok` パッケージ経由で、`claude` や `codex` と同じ方法でインストールされる。`grok` を実行するか、_Setup > Defaults > Agent_ で選ぶこと。x.ai の `curl | bash` インストーラーは使うな。その方法では `~/.grok/bin` に2つ目のコピーが置かれ、`PATH` の先頭に追加され、Omarchy のラッパーが上書きされる。

`dsh` はブラウザ UI を `127.0.0.1:3080` で開き、起動ディレクトリをデフォルトのワークスペースとする。そのブラウザ UI は開始プロンプトを受け取らないため、`omarchy agent prompt` で開くとプロンプトがクリップボードに置かれるので貼り付けること。Omarchy は DeepSeek の承認なし権限プリセットでこれを起動する。DeepSeek Harness は公式モデル API を使うとセッションログを DeepSeek にアップロードする。そのブラウザ UI の _Settings > General > Upload Session Log_ でオフにすること。送信したフィードバックもセッションと一緒にアップロードされる。ただし `DSH_TELEMETRY_MODE=DISABLED` で起動した場合は別だ。

### デフォルトのエージェント

デフォルトのエージェントは `omarchy default agent <name>` で、または Omarchy Menu (`Super + Space`) の _Setup > Defaults > Agent_ で選ぶこと。エージェントがまだインストールされていなければ、選ぶとまずインストールされる。新しい Omarchy では、一度だけの通知でこの選択を促される。

Claude を選ぶと、Chromium、Chrome、Brave、Brave Origin、Edge 用にそのブラウザ拡張機能のセットアップも試みる。拡張機能のセットアップは全ユーザーに適用され、システムパスワードを求められることがある。キャンセルしたり拡張機能のインストールに失敗したりしても、Claude は選択され起動する。ブラウザを再起動し、促されたら拡張機能を有効化し、Claude にサインインして接続を完了すること。Claude で `/chrome` を実行して接続を確認する。Firefox と Zen はこの拡張機能に対応していない。このセットアップが追加される前からすでに Claude がデフォルトだった場合は、もう一度選ぶと拡張機能がインストールされる。

選択が終われば、`Super + Shift + Ctrl + A` で専用のターミナルウィンドウでデフォルトのエージェントが起動する（まだ選んでいなければピッカーが表示される）。`omarchy agent prompt "Review this project"` でタスクに直行させることもできる。Freebuff と DeepSeek Harness は開始プロンプトを受け取らないため、代わりにプロンプトがクリップボードに置かれた状態で開くので貼り付けること。この方法で起動したエージェントは、それぞれの確認で止まらないモードで無人で動く。だから本当に作業を始める覚悟をしておくこと！ MiniMax Code の対話セッションにはそうしたモードがないため、通常どおり権限を求めてくる。また、エージェントはホームディレクトリに対する信頼を覚えることを拒否するため、`$HOME` から起動した場合は代わりに `~/Work` で開始する。

ターミナルのショートカットもある: `a` は現在のターミナルでインラインにデフォルトのエージェントを実行し、`c`、`cx`、`cy` は OpenCode、Claude Code、Codex を直接起動する（こちらも自動承認モードだ）。テーマの変更もエージェントに同期される: Claude Code、Pi、OpenCode、Hermes（Omarchy がインストール済みの場合）は、Omarchy のテーマを切り替えると一緒に追従する。

### エージェントパネル

トップバーにはエージェントのアイコンがある。エージェントをまだセットアップしていなければ、そのパネルで Claude、Codex、Grok へのサインインを順に案内し、最初に設定したものがデフォルトのエージェントになる。その後は、パネルにすべてのサブスクリプションが1ページにまとまる: 各エージェントとアカウントとそのプラン、5時間セッション制限と週間制限それぞれのメーターとリセットまでの時間（ホバーで正確なパーセンテージ）、またはプリペイド残高の残りが、今週のトークンや最もよく使ったモデルなど、すべてを通じて使ったものを切り替えて表示する一行の下に並ぶ。_Make something_ の下では、新しいテーマ、プラグイン、アプリのためのスタータープロンプトが用意され、タスクをデフォルトのエージェントに任せる。アプリは Omarchy 自身の Hype、Monologue、Omacut と同じ方法で、C++ と Qt Quick で、omarchy-app エージェントスキルに従って作られ、必要なコンパイラーと Qt の部品はインストール済みで付いてくる。Claude Code、Codex、Grok、Kimi、Cursor とその Grok Bot 枠、GitHub Copilot、Muse、Antigravity、Kimchi、Devin は制限付きでそのまま利用でき、Hermes、Mistral Vibe、Qwen Code は一度使うとセッションとトークンが表示される。pi、omp、opencode 経由で使うプロバイダーのプランとキーも表示される: OpenCode Zen と Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan、Synthetic が制限付きで、Fireworks、OpenRouter、DeepSeek がプリペイド残高付きで、そして Local models の下に自分のハードウェアで動かすモデルが表示される。すべてのエージェントは、請求元のもとで一度だけ数えられる。何種類のハーネス経由で駆動しても同じだ。

バーのアイコンを左クリックするとパネルが開き、右クリックするとデフォルトのエージェントが起動する。その背後にある使用状況の記録は15分ごとに `omarchy agent usage-update` で再生成され、パネルは同期フォルダー経由で他のマシンからの使用状況をマージすることもできる。すべての設定については `$OMARCHY_PATH/shell/plugins/agents/` の README を参照すること。

### 複数のサブスクリプション

Claude、Codex、Grok のプランを複数契約しているなら — 例えば個人の Max と仕事用など — Omarchy はすべてをサインインしたままにして、その間を移動できる。エージェントパネルの + でサブスクリプションを追加すると、その場で順に案内される。または `omarchy agent account add claude Work`（`codex` や `grok` でもよい）を使うこと。CLI がなければインストールされる。プロバイダーの最初のアカウントは、CLI が常に見る場所で、通常のブラウザ経由でサインインする。それ以降はすべてプライベートウィンドウ経由でサインインする。ブラウザで既にサインインしているアカウントを誤って拾わないためだ。そこで追加したいアカウントとしてサインインし、既に開いているプライベートウィンドウは先に閉じること。CLI からログアウトしてこれをやっては絶対にいけない: ログアウトすると保存されたサインインが取り消され、そのアカウントは再度追加し直さなければならなくなる。

SSH 経由で別の Omarchy マシンにサブスクリプションのログインをコピーするには、`omarchy agent account copy user@laptop` を実行すること。送信側は、宛先に受信側がインストールされていない場合に一時的な受信側を提供するので、古い Omarchy マシンでもアップデートなしでアカウントを受け取れる。インストール済みの受信側が優先される。これはすべての Claude、Codex、Grok のサブスクリプションをコピーする。`omarchy agent account copy laptop claude` のようにプロバイダー名を追加して選択することもできる。アカウント名とコマンド ID はコピー元と一致する。宛先に既に存在するアカウントも含む。無関係な宛先アカウントで名前が競合した場合は数字のサフィックスが付く。設定、スキル、プラグイン、会話履歴は各マシンにローカルなまま残る。

宛先の既存の認証情報は保持される。コピー元アカウントが既にそこでサインインしていれば、その名前が認証情報を置き換えることなく同期され、他のアカウントはその横に追加される。一致するアカウントの保存済み認証情報を置き換えるには、宛先でそのアカウントのセッションを終了した後で `omarchy agent account copy --replace laptop claude` を使うこと。新しい宛先にはコピー元のアクティブなアカウントと切り替え設定も引き継がれる。既に使われている宛先は自身のものを保持する。

認証情報は SSH を経由し、宛先のプライベートファイルに保存される。だから信頼するマシンにだけコピーすること。これは一度きりのコピーであり、継続的な同期ではない。Codex のリフレッシュトークンは別のマシンでローテーションされることがあり、コピーしたログインは更新が必要な状態になることがある。複数マシンで同時使用するには、別々にサインインするのが最も確実だ。[Codex のアカウント認証ガイダンス](https://developers.openai.com/codex/auth/ci-cd-auth) を参照すること。

プロバイダーごとにアクティブなアカウントは1つだけであり、新しいセッションはすべてそれで開始する: `cx`、`cy`、素の `claude`、`codex`、`grok`、`omarchy agent` 経由で起動するものすべて、`PATH` で CLI を見つけるスクリプトやエディターもだ。`omarchy agent account use work` で切り替え（`omarchy agent account use main` で戻す）、またはパネルでアカウントの番号を押してから `Enter` を押すこと（Use ボタンをクリックしてもよい）。既に動いているセッションは開始したアカウントのまま残る。会話履歴、設定、スキル、プラグインはアカウント間で共有される。だから同じフォルダーで `claude --continue` すれば、新しいアカウントで中断した場所から再開できる。

アカウントが複数あると、パネルには各アカウントの制限が並んで表示され、アクティブなものに印が付く。デフォルトでは、アクティブなアカウントが制限の95%を超えると通知され、通知をクリックすると最も余裕のあるアカウントに切り替わる。パネルでアカウントの行にホバーして Use の横に現れる Autoswitch をクリックするか（`m` を押してもよい）、`omarchy agent account mode auto` を実行すれば、自動で切り替わるようになる。有効な間、Autoswitch が Use の代わりになり、もう一度クリックすると通知に戻る。`omarchy agent account mode auto 90` のように数字を追加して閾値を変更すること。すべてのアカウントが閾値を超えた場合は、一度だけ、その旨とどのアカウントが最初に解放されるかが知らされる。アクティブなアカウントが閾値まで15ポイント以内（デフォルトでは80%）にある間、その制限は15分ごとではなく3分ごとに確認される。

`omarchy agent account list` はすべてのアカウントと最新の制限を表示し、`omarchy agent account remove work` は1つを忘れ、`omarchy agent account rename primary Hey` は名前を変更する（パネルでアカウント名をクリックしてもよい）。これらのコマンドはデフォルトのエージェントのアカウントに対して動作する。別のプロバイダーにアクセスするには、`omarchy agent account use codex side` のように先に名前を指定すること。`~/.claude` や `~/.codex` に既にあったログインは _Main_ アカウントであり、そのままの場所に残る。約8時間以上使われていないアカウントは _Sign-in required_ と表示されることがある。クリックすればパネル内でそのアカウントに再びサインインできる。またはそのアカウントでセッションを開始すれば自動でサインインが更新される。アカウント追加時にあった MCP サーバーはそのアカウントにも付いてくるが、後から `claude mcp add` で追加したものは追加したアカウントにしか届かない。Claude Desktop や CLI バイナリーへの絶対パスで設定されたツールは切り替えに追従しない。明示的な `CLAUDE_CONFIG_DIR`、`CODEX_HOME`、`GROK_HOME` は選択したアカウントより優先される。

### クラッシュ診断

Omarchy は systemd-coredump でプロセスのクラッシュを監視している。何かが segfault すると、「Process crashed」通知が届く — クリックすると、クラッシュが Omarchy の diagnose-crash スキルとともにデフォルトのエージェントに渡され、そのスキルがエージェントにコアダンプから事実を確かめ、そのクラッシュをアップストリームに報告する価値があるかどうかを判断する手順を案内する。`coredumpctl list` の任意の PID に対して `omarchy agent crash <pid>` で手動で実行することもできる。

監視はデフォルトでオンだ。_Trigger > Toggle > Crash Capture_ で（または `omarchy toggle crash-capture` で）オフにすると通知は止まる。`omarchy agent crash <pid>` は手動では引き続き動作する。

クラッシュはプログラムごとに黙らせることもできる。診断の最後に提示されるのがそれだ。`omarchy crash mute hyprland` はそのプログラムだけ通知を止め、`omarchy crash mute hyprland off` で元に戻り、`omarchy crash mute` だけではミュートしたものの一覧が表示される。バイナリーのパスでも名前と同じように使えるので、`omarchy crash mute /usr/bin/hyprland` でも同じことになる。空白を含む名前は `omarchy crash mute 'Some App'` のように引用すること。他のものはすべて引き続き通知され、ミュートしたプログラムは引き続きクラッシュする — これはリマインダーを隠すだけで、何も直らない。

### デスクトップアプリ

_Install > AI_ メニューにはグラフィカルな AI アプリもいくつかある: ChatGPT デスクトップアプリ、Claude デスクトップアプリ（Anthropic の Linux ベータで、Chat、Cowork、Claude Code のタブ付き）、xAI のモデルとチャットする Grok Bot、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexity デスクトップアプリ、T3 Code だ。Grok Bot はデスクトップチャットアプリだ。コーディングエージェントは `grok` コマンドだ。

Hermes Desktop は知っておくべきものだ。マシンには Hermes は1つしかなく、それはアプリのものだからだ: Hermes は決してアプリ経由でしかインストールされず、デフォルトのエージェントが実行する `hermes` コマンドはアプリのものだ。Hermes をデフォルトのエージェントに選ぶと、_Install > AI_ の項目と同じものがインストールされる: パッケージと、Hermes 自身のインストーラーによってセットアップされる `~/.hermes` 配下の Hermes ランタイムで、初回は数分かかる。そのランタイムこそが、ターミナルの `hermes` コマンド、デフォルトのエージェント、アプリのすべてが使う唯一の Hermes であり、Omarchy のリリースを待たずに `hermes update` で自己更新する。インストールすると Hermes に Omarchy テーマが `omarchy` という名前のスキンとして渡され、すべての Hermes の表面がテーマ切り替えに追従する。追従させたくなければ、Hermes の Appearance 設定か `/skin` で別のものを選ぶこと。Omarchy はその選択を変更しない。_Remove > AI_ でアプリを削除すると、まずゲートウェイを含めて Hermes が閉じられ、そのランタイムも一緒に削除される。チャット、メモリー、Hermes が自分のために書いたスキルは、そう指示しない限り保持される: そのデータと接続設定も削除するかどうかを聞かれ、デフォルトは「いいえ」だ。

OpenClaw のデスクトップ体験はその Control UI で、自身のローカルゲートウェイをバックエンドとするウェブアプリとして開く。OpenClaw は `~/.openclaw` にあり、自己更新する: Control UI の「Update Gateway」ボタンを使うか `openclaw update` を実行すると、ゲートウェイは新しいバージョンで再起動する。Omarchy は新規インストールが開始するリリースを選ぶだけだ。_Remove > AI_ で OpenClaw を削除すると、ゲートウェイサービスとアプリが一緒に削除され、その後 `~/.openclaw` も削除するかどうかを聞かれる。そこにはチャットと認証情報が OpenClaw 自体やダウンロードするプラグインランタイムと一緒に保存されているからだ。デフォルトでは保持され、OpenClaw を再びインストールするとそれを再び拾う。

Herdr Desktop は [Herdr](https://herdr.dev) のデスクトップアプリだ: スペース、タブ、ターミナルとコーディングエージェントのペインがあり、ウィンドウを閉じてもそのコアで動き続ける。パッケージではなく Herdr 自身のインストーラーから来るため、`~/.local/share/herdr-app` にあり、まだ持っていなければ `~/.local/bin/herdr-core` にコアも一緒に持ち込み、両方とも自己更新する。Omarchy が `Super + Ctrl + Return` で提供する `herdr` コマンドの横にあり、それを置き換えるものではない。インストールすると Herdr の Omarchy テーマが選ばれ、以降は Omarchy のテーマに追従する。Herdr はライトモード用とダークモード用にテーマを1つずつ保持する。だからダークとライトの Omarchy テーマを切り替えた後は、もう一方のモード用に Herdr のテーマピッカーで Omarchy をもう一度選ぶこと。

T3 Code はパッケージではなく、`~/.local/share/t3code` の公式 AppImage リリースから動作し、自己更新する。インストール時に Stable チャンネルで始めるか Nightly チャンネルで始めるかを聞かれる。後で T3 Code の設定で切り替えること。スレッドと設定は `~/.t3` にあり、_Remove > AI_ で T3 Code を削除すると一緒に削除される。

### ローカルモデル

コーディングエージェント用に自分のマシンでオープンモデルを動かすこと。プロンプトとコードはマシン上に残る。モデルに送ったものがマシンから出ることはない。まずは次から始めること:

```bash
omarchy agent local use best
```

または、トップバーのエージェントパネルで + を選び、次に Local AI を選ぶ。これはモデルがこのマシンに合う場合に表示される。初回は、モデルを実行する Podman がインストールされ、NVIDIA マシンでは GPU を使えるようにする NVIDIA のコンテナツールキットがインストールされる。次に Omarchy がこのマシンに推奨されるモデルを選び、ダウンロードして起動する。数十 GB のダウンロードと、モデル実行中はマシンのメモリーの大半が使われることを覚悟すること: Flash Next は完全な 256K コンテキストで約 100 GiB を使う。必要なメモリーを他のモデルが占有している場合は、停止した状態でセットアップされ、どれかを止めれば開始できるようになる。モデルはログアウト時に停止する。他の用途にメモリーが必要なときは自分で止めること。

`omarchy agent local list` は選択肢を表示し、合わないものについてはその理由を説明する。別のものをセットアップするには、`omarchy agent local use <recipe>` を実行すること。現在、128 GB の Strix Halo マシン向けに `qwen3.8-flash-next-gufo` と `qwen3.8-27b-gufo` が利用できる。27B は約 40 GiB を使うため、他の作業の余地が残る。新しいレシピと推奨はパッケージ経由で `omarchy update` とともに届く。

セットアップしたモデルごとに、サブスクリプションの横のエージェントパネルに専用の行ができる: 再生で起動し、一時停止で止めてメモリーを解放し、ターミナルボタンでそのモデル上でエージェントを開く。メモリーに一緒に収まる場合は複数を同時に実行できる。収まらない場合は、Omarchy がどの実行中のモデルを止めるべきかを伝える。行をドラッグして並び替え、選択した行で Delete を押すとモデルとそのダウンロードが削除される。

コマンドラインからは、`omarchy agent local start <recipe>` と `omarchy agent local stop <recipe>` が同じことをし、`omarchy agent local status` はすべてのモデルを表示し、`omarchy agent --local` は最後に起動したモデル上でデフォルトのエージェントを開く（デフォルトのエージェントがローカルモデルを使えない場合は pi）。OpenAI 互換のクライアントも接続できる: `status` は各モデルのアドレス（最初のものは `http://127.0.0.1:11435/v1`）を表示し、レシピ名がモデルとなり、キーは `~/.config/omarchy/agent-local/key` にある。

`omarchy agent local remove <recipe>` はモデルと、他のどのモデルも使っていないダウンロードを削除する。

サードパーティのランタイムにはその発行元のラベルが付けられる。Omarchy はすべてのモデルをネットワークアクセスなしで実行する。

### ローカル LLM

Omarchy はローカル LLM モデルを実行する2つの方法を推奨する: LM Studio と Ollama だ。LM Studio はオープンウェイトモデルを見つけ、インストールし、実行するための GUI インターフェイスを提供する。手軽に始めるのに最適な方法だ。Ollama は同様のことを行う CLI を提供する。だがローカルモデルが初めてなら、私なら LM Studio から始める。どちらも Omarchy Menu の _Install > AI_ でインストールできる。

### Omarchy スキル

エージェントスキルは AI が特定のツールを特定の方法で使うのを助ける。Omarchy にはシステムをカスタマイズするためのデフォルトスキルが付属している。Hyprland の設定を調整したり、バーを調整したり、ゼロから新しいテーマを作ったりするようなことだ。これは Claude Code (`~/.claude/skills`)、Codex (`~/.codex/skills`)、Pi (`~/.pi/agent/skills`)、Antigravity (`~/.gemini/config/skills`)、Hermes (`~/.hermes/skills` と各 `~/.hermes/profiles/*/skills`)、そして汎用の `~/.agents/skills` のスキルディレクトリにシンボリックリンクされている。だからほとんどのハーネスが自動で拾う。

だがこのスキルは実験的なものとして扱うべきだ。モデルによって効果はまちまちだ。まずプランモードで実行するのが最善だ。エージェントが何を変更したいのか把握できるからだ。そして、変更をロールバックしたり、エージェントがすべてをめちゃくちゃにした場合には `omarchy reinstall configs` を実行したりする覚悟をしておくこと。
