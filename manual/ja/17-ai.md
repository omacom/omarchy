### エージェントのインストールと更新

Hermes と OpenClaw を除き、これらのエージェントは mise の遅延インストールを使用します。初回起動時に CLI がインストールされ、それ以降の起動ではそれが再利用されます。mise はまた、インストール済みエージェントに新しいリリースがないか、最大で4時間に1回、起動直前またはシェルのプロンプトでバックグラウンドで確認します。その更新が失敗したり、オフラインだったりした場合、インストール済みのバージョンが動作します。`omarchy update` は Omarchy の残りと一緒にインストール済みエージェントを更新し、`mup` は mise で管理されたツールだけを更新します。

`claude update`、`codex update`、アプリ内の更新ボタンなど、エージェント独自のアップデーターは、mise で管理されたインストールを更新しません。`codex update` は失敗し、`claude update` は成功したと報告しながら、mise が追跡しない別コピーをインストールすることがあります。エージェント独自のインストーラーとアップデーターを使いたい場合は、それを `disable_tools` に追加してください。[プリインストールされた CLI ツール](18-development-tools.md#preinstalled-cli-tools) を参照してください。

必要になる前に、設定されたすべての遅延ツールをインストールするには、`mise install --include-lazy` を実行してください。これにはエージェントだけでなく、Omarchy の他のデフォルト CLI ツールも含まれます。単一のツールのインストールや独自のインストールの使用については、[プリインストールされた CLI ツール](18-development-tools.md#preinstalled-cli-tools) を参照してください。

`grok` は、`claude` や `codex` と同じ方法で、mise のファーストパーティ `grok` パッケージ経由でインストールされます。`grok` を実行するか、_Agent > Harness_ で選択してください。x.ai の `curl | bash` インストーラーは使わないでください。その方法では `~/.grok/bin` に2つ目のコピーが配置され、`PATH` の先頭に追加されて、Omarchy のラッパーが上書きされます。

`dsh` は `127.0.0.1:3080` でブラウザー UI を開き、起動したディレクトリをデフォルトのワークスペースにします。そのブラウザー UI は開始プロンプトを受け付けないので、`omarchy agent prompt` は貼り付けられるようプロンプトをクリップボードに入れた状態でそれを開きます。Omarchy は DeepSeek の承認なし権限プリセットでそれを起動します。DeepSeek Harness は、公式モデル API を使用するとセッションログを DeepSeek にアップロードします。そのブラウザー UI の _Settings > General > Upload Session Log_ でオフにしてください。送信したフィードバックもセッションと一緒にアップロードされます。ただし、`DSH_TELEMETRY_MODE=DISABLED` で起動した場合は除きます。

### デフォルトエージェント

`omarchy default agent <name>` を使うか、Omarchy Menu（`Super + Space`）の _Agent > Harness_ でデフォルトエージェントを選んでください。そのエージェントがまだインストールされていない場合、選択すると先にインストールされ、アプリランチャーで Agent の隣に独自のランチャーも得ます。新しい Omarchy では、この選択を一度だけの通知で促します。

Claude を選ぶと、Chromium、Chrome、Brave、Brave Origin、Edge 用のブラウザー拡張機能のセットアップも試みます。拡張機能のセットアップは全ユーザーに適用され、システムパスワードを求められる場合があります。キャンセルしたり拡張機能のインストールに失敗したりしても、Claude は選択され起動します。ブラウザーを再起動し、プロンプトが表示されたら拡張機能を有効にし、Claude にサインインして接続を完了してください。Claude で `/chrome` を実行して接続を確認してください。Firefox と Zen はこの拡張機能をサポートしていません。このセットアップが追加される前に既に Claude がデフォルトだった場合は、もう一度選択して拡張機能をインストールしてください。

選択すると、`Super + Shift + Ctrl + A` で専用のターミナルウィンドウでデフォルトエージェントを起動します（まだ選んでいない場合はピッカーが表示されます）。`omarchy agent prompt "Review this project"` を使ってタスクに直接投入することもできます。Freebuff と DeepSeek Harness は開始プロンプトを受け付けないので、代わりに貼り付けられるようプロンプトをクリップボードに入れて開きます。この方法で起動したエージェントは、それぞれの止まって聞かないモードで無人で動作します。だから本当に作業を始める準備をしておいてください！MiniMax Code には対話セッション用のそうしたモードがないので、通常どおり権限を求めます。またエージェントはホームディレクトリへの信頼を記憶することを拒否するので、`$HOME` からの起動は代わりに `~/Work` で開始します。

ターミナルショートカットもあります。`a` は現在のターミナルでインラインでデフォルトエージェントを実行し、`c`、`cx`、`cy` は OpenCode、Claude Code、Codex を直接起動します（こちらも自動承認モードです）。テーマの変更もエージェントに同期します。Claude Code、Pi、OpenCode、Hermes（Omarchy がインストールした後は）はすべて、Omarchy のテーマを切り替えるとそれに従います。

### エージェントへの指示

すべてのエージェント用の個人ルールは、`~/.agents/skills` にある共有スキルと並んで `~/.agents/AGENTS.md` に入れます。_Agent > Instructions_ で開いてください。そこでは独自のグローバルファイルを保持する各ハーネスへもリンクされます。`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`~/.pi/agent/AGENTS.md`、`~/.config/opencode/AGENTS.md`、Copilot の `~/.copilot/copilot-instructions.md` などです。Crush と Amp は `~/.config/AGENTS.md` リンクを読み、omp、Kimi、DeepSeek Harness は `~/.agents/AGENTS.md` を直接読みます。デフォルトエージェントを選ぶとそこにもリンクされます。すでに持っていた指示ファイルは、共有ファイルがまだなかった場合は共有ファイルになり、そうでない場合はリンクの隣に `.bak` として保持されます。別のエージェントをインストールした後に再リンクするには `omarchy agent instructions` を実行してください。

### エージェントパネル

トップバーにはエージェントアイコンがあります。エージェントをまだセットアップしていない場合、そのパネルでは Claude、Codex、Grok へのサインインを順に案内し、最初のものがデフォルトエージェントになります。その後は、パネルですべてのサブスクリプションを1ページにまとめます。各エージェントとアカウントにそのプランを表示し、5時間セッション制限と週間制限ごとにリセットまでの時間とメーター（ホバーで正確なパーセンテージ）を、またはプリペイド残高を表示します。その上にある行には、今週のトークンや最もよく使ったモデルなど、すべてのエージェントにわたる使用量が順に切り替わって表示されます。_Make something cool_ では、新しいテーマ、プラグイン、アプリ、ゲーム用のスタータープロンプトが提供され、タスクをデフォルトエージェントに引き渡します。アプリは Omarchy 自身の Hype、Monologue、Omacut と同じ方法で、C++ と Qt Quick で、omarchy-make-app エージェントスキルに従って作られ、必要なコンパイラーと Qt の部品はインストール済みで提供されます。ゲームは `~/Games/vibes` にある単一の three.js ページで、omarchy-make-game エージェントスキルに従い、すべて現在のテーマの1つの Game Vibes ランチャーから開きます。three.js をウェブから読み込むので、開始には接続が必要です。Claude Code、Codex、Grok、Kimi、Cursor とその Grok Bot 枠、GitHub Copilot、Muse、Antigravity、Devin は制限付きでそのまますぐ使えるよう対応し、Kimchi はそのプラン、プリペイドクレジット、支出予算で対応し、Hermes、Mistral Vibe、Qwen Code は使用した後にセッションとトークンを表示します。pi、omp、opencode 経由で使うプロバイダープランとキーも表示されます。制限付きで OpenCode Zen と Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan、Synthetic、プリペイド残高で OpenRouter と DeepSeek、過去30日間の支出で Fireworks、そして Local models の下に自分のハードウェアで実行するモデルです。すべてのエージェントは、課金する側の下で一度だけ数えられます。何つのハーネス経由で動かしても同じです。

バーアイコンを左クリックするか `Super + Ctrl + X` を押してパネルを開き、右クリックでデフォルトエージェントを起動し、中央クリックで更新します。その背後にある使用量記録は `omarchy agent usage update` によって15分ごとに再生成され、パネルは同期フォルダーを経由して他のマシンからの使用量を統合することもできます。すべての設定については `$OMARCHY_PATH/shell/plugins/agents/` にある README を参照してください。

### 複数のサブスクリプション

個人用の Max と仕事用など、Claude、Codex、Grok のプランを複数払っている場合、Omarchy はそれらすべてをサインインしたままにして、それらの間を移動できます。エージェントパネルで + を使ってサブスクリプションを追加すると、そこで順に案内されます。または `omarchy agent account add claude Work`（または `codex`、または `grok`）を使ってください。CLI がなければインストールします。プロバイダーの最初のサブスクリプションは通常のブラウザー経由でサインインします。CLI が常に見ている場所そのものです。それ以降の各アカウントはプライベートウィンドウ経由でサインインします。そうすればブラウザーがすでにサインインしているアカウントを誤って取得してしまうことがありません。追加しようとしているアカウントでそこにサインインし、既に開いていたプライベートウィンドウは先に閉じてください。このために CLI からログアウトしてはいけません。ログアウトすると保存されたサインインが取り消され、そのアカウントは再度追加しなければならなくなります。

サブスクリプションのログインを SSH 経由で別の Omarchy マシンにコピーするには、`omarchy agent account copy user@laptop` を実行してください。送信側は受信先にインストール済みがない場合に一時的な受信側を提供します。そのため、古い Omarchy マシンでも更新なしでアカウントを受信できます。インストール済みの受信側が優先されます。これは Claude、Codex、Grok のすべてのサブスクリプションをコピーします。選択するにはプロバイダー名を追加します。例: `omarchy agent account copy laptop claude`。アカウント名とコマンド ID は、コピー先にすでに存在するアカウントを含め、コピー元と一致します。無関係なコピー先アカウントは名前が衝突する場合に数字サフィックスを受け取り、設定、スキル、プラグイン、会話履歴は各マシンにローカルなままになります。

コピー先の既存の資格情報は保持されます。そこで既にサインインしているコピー元アカウントは、資格情報を置き換えることなく名前が同期され、他のアカウントはその隣に追加されます。一致するアカウントの保存済み資格情報を置き換えるには、コピー先でそのアカウントのセッションを終了した後に `omarchy agent account copy --replace laptop claude` を使用してください。新規のコピー先はコピー元の有効なアカウントと切り替え設定も取得し、既に確立したコピー先は独自のものを保持します。

資格情報は SSH 経由で移動し、コピー先のプライベートファイルに保存されます。だから信頼するマシンにだけコピーしてください。これは一度だけのコピーであり、継続的な同期ではありません。Codex のリフレッシュトークンは別のマシンによってローテーションされることがあり、コピーしたログインは更新が必要になります。複数のマシンで同時使用するには、個別のサインインが最も信頼できる選択のままです。[Codex のアカウント認証ガイダンス](https://developers.openai.com/codex/auth/ci-cd-auth) を参照してください。

プロバイダーごとに有効なアカウントは1つで、新しいセッションはすべてそれとして開始します。`cx`、`cy`、単なる `claude`、`codex`、`grok`、`omarchy agent` 経由で起動したもの、`PATH` で CLI を見つけるスクリプトやエディターなどです。`omarchy agent account use work` で切り替え（`omarchy agent account use main` で戻す）、またはパネルでアカウントの番号を押してから `Enter` を押す（またはその Use ボタンをクリックする）ことで切り替えます。実行中の Claude セッションも次のメッセージから切り替わります。すべての Claude セッションは `~/.claude` で動作し、そこには常に有効なアカウントのサインインが保持されます。古い Omarchy によってアカウント専用フォルダーで開始した Claude セッションは、終了するまでそのサインインを保持します。そのため、切り替えではそれらのセッションに名前を付け、それらがなくなると自動的に完了します。実行中の Codex と Grok のセッションは、開始したアカウントのままです。会話履歴、設定、スキル、プラグインはアカウント間で共有されるので、同じフォルダーで `claude --continue` すると、新しいアカウントで中断したところから続きます。

アカウントが複数ある場合、パネルでは各アカウントの制限が横並びに表示され、有効なものに印が付きます。デフォルトでは、有効なアカウントが制限の95%を超えると Omarchy が通知し、通知をクリックすると最も余裕のあるアカウントに切り替わります。パネルでアカウントの行にホバーして Use の隣に表示される Autoswitch をクリックする（または `m` を押す）か、`omarchy agent account mode auto` を実行すると、代わりに自動で切り替わります。有効な間は Autoswitch が Use の代わりになり、もう一度クリックすると通知に戻ります。しきい値を変更するには `omarchy agent account mode auto 90` のように数字を追加します。すべてのアカウントがしきい値を超えている場合は、どのアカウントが最初に空くかと一緒に一度だけ通知します。有効なアカウントがしきい値まで15ポイント以内にある間（デフォルトでは80%）、制限は15分ごとではなく3分ごとに確認されます。

`omarchy agent account list` はすべてのアカウントと最新の制限を表示し、`omarchy agent account remove work` は1つを忘れ、`omarchy agent account rename primary Hey` は1つの名前を変更します（またはパネルでアカウント名をクリック）。これらのコマンドはデフォルトエージェントのアカウントに対して動作します。別のプロバイダーに到達するには、先にその名前を指定します。例: `omarchy agent account use codex side`。`~/.claude` または `~/.codex` に既に持っていたログインは _Main_ アカウントです。Codex のものはそのままの場所に残ります。Claude のものは別のアカウントが有効な間、専用フォルダーで待機します。約8時間以上未使用のアカウントは _Sign-in required_ と表示されることがあります。クリックしてパネルですぐにそのアカウントに再サインインするか、それに切り替えてセッションを開始すると、サインインが自動的に更新されます。`claude mcp add` で追加した MCP サーバーは、すべて `~/.claude` で動作するので、すべての Claude アカウントに届きます。Codex と Grok の場合、アカウントが追加された時に持っていたサーバーはそのアカウントにも付いてきますが、それ以降のサーバーは追加したアカウントにしか届きません。Claude Desktop は独自のサインインを保持し、CLI バイナリへの絶対パスで設定された Codex や Grok のツールは切り替えに従いません。明示的な `CLAUDE_CONFIG_DIR`、`CODEX_HOME`、または `GROK_HOME` は選択したアカウントよりも優先されます。

### クラッシュ診断

Omarchy はプロセスのクラッシュについて systemd-coredump を監視します。デフォルトエージェントを選ぶと、コアをダンプしたあなたのプログラムはこれにより "Process crashed" 通知を出します。クリックすると、そのクラッシュは Omarchy の omarchy-diagnose-crash スキルと一緒にデフォルトエージェントに引き渡され、そのスキルはコアダンプから事実を確立し、そのクラッシュを上流に報告する価値があるかどうかを決める手順をエージェントに案内します。`omarchy agent crash <pid>` を使って `coredumpctl list` の任意の PID に対して手動で実行することもできます。

監視はデフォルトでオンです。_Trigger > Toggle > Crash Capture Off_ で（または `omarchy toggle crash-capture` で）オフにすると通知は止まります。`omarchy agent crash <pid>` は手動では引き続き動作します。

クラッシュはプログラム1つずつ消すこともできます。それは診断が最後に提案することです。`omarchy crash mute hyprland` はそのプログラムだけの通知を止め、`omarchy crash mute hyprland off` は戻し、`omarchy crash mute` 単体ではミュートしたものを一覧表示します。名前と同様にバイナリのパスも受け付けるので、`omarchy crash mute /usr/bin/hyprland` でも同じです。スペースを含む名前は引用してください。例: `omarchy crash mute 'Some App'`。他のすべては引き続き通知し、ミュートしたプログラムは引き続きクラッシュします。これはリマインダーを隠すだけで、何も直しません。

### デスクトップアプリ

_Install > AI_ メニューにはグラフィカルな AI アプリもいくつかあります。Amp Desktop、Antigravity Desktop、ChatGPT デスクトップアプリ、Claude デスクトップアプリ（Chat、Cowork、Claude Code タブ付きの Anthropic の Linux ベータ）、xAI のモデルとチャットする Grok Bot、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexity デスクトップアプリ、T3 Code です。Grok Bot はデスクトップチャットアプリです。コーディングエージェントは `grok` コマンドです。

Hermes Desktop は知っておくべき存在です。なぜならマシンには1つの Hermes しかなく、それはアプリのものだからです。Hermes はアプリ経由でしかインストールされず、デフォルトエージェントが実行する `hermes` コマンドはアプリのものです。Hermes をデフォルトエージェントに選ぶと、_Install > AI_ エントリーと同じものがインストールされます。パッケージと、Hermes 独自のインストーラーでセットアップされた `~/.hermes` 以下の Hermes ランタイムです。初回は数分かかります。そのランタイムはターミナルの `hermes` コマンド、デフォルトエージェント、アプリがすべて使う唯一の Hermes であり、Omarchy のリリースを待つのではなく `hermes update` で自己更新します。インストールすると、Omarchy テーマが `omarchy` という名前のスキンとして Hermes にも渡されます。すべての Hermes 画面はテーマ切り替えに従います。そうしたくない場合は Hermes の Appearance 設定で、または `/skin` で別のものを選んでください。Omarchy はその選択に干渉しません。_Remove > AI_ でアプリを削除すると、まず Hermes がゲートウェイを含めて閉じられ、そのランタイムも一緒に削除されます。チャット、メモリー、Hermes が自分のために書いたスキルは、指示しない限り保持されます。そのデータと接続設定も一緒に削除するかどうかを聞かれます。デフォルトはいいえです。

OpenClaw のデスクトップ体験はその Control UI で、独自のローカルゲートウェイをバックエンドにしたウェブアプリとして開きます。OpenClaw は `~/.openclaw` にあり自己更新します。Control UI の "Update Gateway" ボタンを使うか `openclaw update` を実行すると、ゲートウェイは新しいバージョンで再起動します。Omarchy は新規インストールが開始するリリースを選ぶだけです。OpenClaw はデフォルトエージェントにもなれます。_Agent > Harness_ で選ぶと同じコピーが `~/.openclaw` にセットアップされ、エージェントはゲートウェイに接続された OpenClaw のターミナル UI を開きます。_Remove > AI_ で OpenClaw を削除すると、ゲートウェイサービスとアプリも一緒に削除され、その後 `~/.openclaw` も削除するかどうかを聞かれます。そこには OpenClaw 自体とダウンロードするプラグインランタイムと並んでチャットと資格情報が入っているからです。デフォルトでは保持され、OpenClaw を再インストールするとそれを再び拾い上げます。

Herdr Desktop は [Herdr](https://herdr.dev) デスクトップアプリです。ウィンドウを閉じてもコアで動き続けるターミナルとコーディングエージェントのスペース、タブ、ペインです。パッケージではなく Herdr 独自のインストーラーから提供されるので、`~/.local/share/herdr-app` にあり、まだ持っていない場合はそのコアを `~/.local/bin/herdr-core` に一緒に持ち込み、その両方を自己更新します。Omarchy が `Super + Ctrl + Return` で提供する `herdr` コマンドを置き換えるのではなく、その隣に位置し、そのコマンドの直接キーを得ます。`Alt + Return` と `Alt + Shift + Return` はペインを下または右に分割し、`Alt + Escape` は閉じ、`Ctrl + Alt + Arrow` はペイン間を移動し、`Alt + 1..9` と `Alt + Left/Right` はタブを選び、`Alt + Up/Down` はスペース間を移動します。`Ctrl + 1..9` はスペースを選び、`Alt + Shift + Up/Down` はエージェント間を順に進みます。`Ctrl + Space` プレフィックスキーはターミナル専用のままです。アプリはシーケンスのために素の Ctrl キーを保持できないからです。Omarchy はこれらを `~/.config/herdr-app/keys.json` に書き込み、`omarchy-refresh-herdr-app` で元に戻します。インストールすると Herdr の Omarchy テーマが選ばれ、それ以降あなたの Omarchy テーマに従います。Herdr はライトモード用に1つ、ダーク用に1つのテーマを保持します。ダークな Omarchy テーマとライトな Omarchy テーマを切り替えた後は、もう一方のモード用に Herdr のテーマピッカーで Omarchy をもう一度選んでください。

T3 Code は、パッケージではなく `~/.local/share/t3code` にある公式 AppImage リリースから動作するので、自己更新します。インストールすると Stable チャネルか Nightly チャネルで開始するか聞かれます。後で T3 Code の設定で切り替えてください。スレッドと設定は `~/.t3` にあり、_Remove > AI_ で T3 Code を削除するとそれらも一緒に削除されます。

### ローカルモデル

コーディングエージェント用に自分のマシンでオープンモデルを実行してください。プロンプトとコードはマシン上に留まります。モデルに送信したものがマシンから出ることはありません。次から始めてください:

```bash
omarchy models use best text
```

または、トップバーのエージェントパネルで + を選んでから Local AI を選んでください。これはモデルがこのマシンに合う場合に表示されます。モデルを実行する Podman は Omarchy に付属し、NVIDIA マシンでは GPU を提供する NVIDIA のコンテナツールキットも付属します。どちらかがない場合、初回セットアップでインストールされます。その後 Omarchy はこのマシンに推奨されるモデルを選び、ダウンロードし、起動します。数十 GB のダウンロードと、モデル実行中にマシンのメモリーのほとんどが使用されることを覚悟してください。Flash Next は完全な 256K コンテキストで約100 GiB を使用します。必要なメモリーを他のモデルが占有している場合は、停止した状態でセットアップされ、1つ停止すれば開始できるようになります。モデルはログアウト時に停止します。他のことにメモリーが必要なときは自分で停止してください。

`omarchy models list` は選択肢を表示し、一部が合わない理由を説明します。別のものをセットアップするには、`omarchy models use <recipe>` を実行してください。現在、128 GB Strix Halo マシン用に `qwen3.8-flash-next-gufo` と `qwen3.8-27b-gufo` が利用可能です。27B は約40 GiB を使うので、他の作業の余地が残ります。Intel の Arc B390 搭載の64 GB ラップトップでは、`qwen3.6-35b-a3b-llamacpp` が約30 GiB で動作します。新しいレシピと推奨はパッケージ経由で `omarchy update` と一緒に届きます。

セットアップしたモデルごとに、サブスクリプションの隣にエージェントパネルで独自の行が表示されます。再生で開始、停止で止めてメモリーを解放、ターミナルボタンでそのモデルでエージェントを開きます。メモリーに一緒に収まる場合は複数を同時に実行できます。収まらない場合、Omarchy はどの実行中のモデルを止めるべきかを知らせます。行をドラッグして並び替え、選択した行で Delete を押すとモデルとそのダウンロードを削除します。

セットアップしたモデルごとに、モデルの名前でそのメーカーのロゴ付きで、アプリランチャーにも独自のエントリーが表示されます。これは Claude、Codex、Grok にサインインすると1つ追加されるのと同じです。そのモデルでエージェントを開き、実行中でなければ先にモデルを開始します。ターミナルに読み込み中と表示され、準備ができるとエージェントに引き渡します。モデルを削除するとそのエントリーも削除されます。

すべてのモデルがコーディング用とは限りません。画像、動画、音楽モデルは代わりに Fantasi で開きます。これはこのマシンで動作するモデルで絵、動画、音楽を作る Omarchy のアプリで、ランチャーエントリーからもエージェントパネルの行からも開きます。

モデルはセットアップされたとおりに動き続けます。そのため Omarchy の更新でエージェントの下で再起動することはありません。セットアップしたモデル用に Omarchy が新しいランタイムや新しいウェイトを持っている場合、その行に更新ボタンが表示されます。押すとモデルはバックグラウンドで再びセットアップされ、変更されたものだけをダウンロードし、新しいバージョンで再起動します。停止していたモデルは停止したままです。`omarchy models update` はターミナルからすべてのモデルについて同じことを行います。

コマンドラインから、`omarchy models start <recipe>` と `omarchy models stop <recipe>` も同じことを行い、`omarchy models status` はすべてのモデルを表示し、`omarchy agent --local` は最後に開始したモデルでデフォルトエージェントを開きます。pi、OpenCode、Qwen Code が1つを使えます。他のデフォルトでは pi で開き、pi がなければ OpenCode で開きます。pi はセットアップしたすべてのモデルと、ペアリングしたマシンにあるモデルも独自のモデルピッカーに一覧表示するので、単なる `pi` でもそれらに到達できます。任意の OpenAI 互換クライアントも接続できます。`status` は各モデルのアドレスを表示し（最初は `http://127.0.0.1:11435/v1`）、レシピ名がモデルで、キーは `~/.config/omarchy/agent-local/key` にあります。

`omarchy models remove <recipe>` はモデルと、他のモデルが使っていないダウンロードを削除します。

サードパーティのランタイムにはその発行元がラベル付けされます。Omarchy はすべてのモデルをネットワークアクセスなしで実行します。

### ローカル LLMs

Omarchy はローカル LLM モデルを実行する2つの方法を推奨します。LM Studio と Ollama です。LM Studio はオープンウェイトモデルを見つけ、インストールし、実行するための GUI インターフェースを提供します。簡単にはじめる素晴らしい方法です。Ollama は同様にする CLI を提供します。しかしローカルモデルが初めてなら、私なら LM Studio から始めます。どちらも Omarchy Menu の _Install > AI_ でインストールできます。

### Omarchy スキル

エージェントスキルは、AI が特定の方法で特定のツールを使う助けになります。Omarchy にはそのうち7つが付属します。omarchy スキルは、Hyprland 設定の調整やバーの調整など、システムのカスタマイズをカバーします。omarchy-make-theme、omarchy-make-plugin、omarchy-make-app、omarchy-make-game は何か新しいものを作ることをカバーし、omarchy-contribute はバグの報告や修正の上流への送信をカバーし、omarchy-diagnose-crash はクラッシュのコアダンプを通して作業します。これらは Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` と各 `~/.hermes/profiles/*/skills`）、汎用の `~/.agents/skills` の場所のスキルディレクトリにシンボリックリンクされているので、ほとんどのハーネスが自動的に拾います。同名の自分のスキルフォルダーが優先されます。

しかしこれらのスキルは実験的なものと考えるべきです。モデルによって効果の出し方は異なります。まずプランモードで実行するのが最善です。そうすればエージェントが何を変更しようとしているか把握できます。そして、エージェントがすべてを台無しにした場合に備え、変更をロールバックしたり、`omarchy reinstall configs` を呼び出したりする準備をしておいてください。
