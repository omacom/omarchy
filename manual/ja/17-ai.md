### エージェントのインストールとアップデート

Hermes を除き、これらのエージェントは mise の遅延インストールを使う。初回起動時に CLI がインストールされ、以降の起動ではそれが再利用される。また mise は、インストール済みエージェントの新リリースを、起動直前、またはシェルのプロンプト時にバックグラウンドで、最大で4時間に一度だけチェックする。そのアップデートが失敗したり、オフラインだったりしても、インストール済みのバージョンが動作する。`omarchy update` を実行すれば、Omarchy の他の部分と一緒にインストール済みエージェントもアップデートされる。`mup` は mise が管理するツールだけをアップデートする。

`claude update`、`codex update` のようなエージェント自身のアップデータや、アプリ内のアップデートボタンでは、mise が管理するインストールはアップデートされない。`codex update` は失敗し、`claude update` は成功したと報告しながら、mise が追跡しない別コピーをインストールすることがある。エージェントのネイティブインストーラとアップデータを使いたいなら、それを `disable_tools` に追加すること。詳細は [事前インストール済みの CLI ツール](18-development-tools.md#preinstalled-cli-tools) を参照。

必要になる前に設定済みの遅延ツールをすべてインストールするには、`mise install --include-lazy` を実行する。これにはエージェントだけでなく、Omarchy の他のデフォルト CLI ツールも含まれる。単一ツールのインストールや、独自のインストールを使う方法については [事前インストール済みの CLI ツール](18-development-tools.md#preinstalled-cli-tools) を参照。

`grok` は mise のファーストパーティ `grok` パッケージ経由でインストールされる。`claude` や `codex` と同じ方式だ。`grok` を実行するか、_Setup > Defaults > Agent_ で選択すればいい。x.ai にある `curl | bash` インストーラは使うな。その方法では `~/.grok/bin` に2つ目のコピーが配置され、`PATH` の先頭に追加され、Omarchy のラッパーが上書きされる。

`dsh` は `127.0.0.1:3080` でブラウザ UI を開き、起動したディレクトリがデフォルトのワークスペースになる。そのブラウザ UI は開始プロンプトを受け取らないため、`omarchy agent prompt` で開くと、プロンプトはクリップボードに入った状態で開くので貼り付ければいい。Omarchy は DeepSeek の承認不要プリセットでこれを起動する。DeepSeek Harness は、公式モデル API を使うとセッションログを DeepSeek にアップロードする。それを止めるには、ブラウザ UI の _Settings > General > Upload Session Log_ でオフにすること。送信したフィードバックもセッションと一緒にアップロードされる。ただし `DSH_TELEMETRY_MODE=DISABLED` を付けて起動した場合は別だ。

### デフォルトのエージェント

デフォルトのエージェントは、`omarchy default agent <name>` か、Omarchy Menu（`Super + Space`）の _Setup > Defaults > Agent_ で選択する。エージェントがまだインストールされていなければ、選択するとまずインストールされる。インストールしたばかりの Omarchy では、一度だけ表示される通知でこの選択を促される。

Claude を選択すると、Chromium、Chrome、Brave、Brave Origin、Edge 用のブラウザ拡張機能のセットアップも試みる。この拡張機能のセットアップはすべてのユーザーに適用され、システムパスワードを求められることがある。キャンセルしても、拡張機能のインストールに失敗しても、Claude の選択と起動はそのまま行われる。ブラウザを再起動し、求められたら拡張機能を有効にして、Claude にサインインすれば接続は完了だ。接続を確認するには Claude で `/chrome` を実行する。Firefox と Zen はこの拡張機能に対応していない。すでにこのセットアップが追加される前から Claude がデフォルトだった場合は、もう一度選択し直せば拡張機能がインストールされる。

選択が終われば、`Super + Shift + Ctrl + A` でデフォルトエージェントが専用のターミナルウィンドウで起動する（まだ選択していなければピッカーが表示される）。`omarchy agent prompt "Review this project"` のようにすれば、タスクを直接渡して起動することもできる。Freebuff と DeepSeek Harness は開始プロンプトを受け取らないため、その代わりプロンプトがクリップボードに入った状態で開くので貼り付ければいい。この方法で起動したエージェントは、それぞれの「止まって聞くな」モードで無人で動作する。だから本当にいろいろ実行するつもりで備えておくこと！MiniMax Code にはインタラクティブセッション向けのそうしたモードがないため、通常通り権限を求めてくる。また、エージェントがホームディレクトリに対する信頼を覚えることを拒否するため、`$HOME` からの起動は代わりに `~/Work` で開始される。

ターミナル用ショートカットもある。`a` は現在のターミナル内でデフォルトエージェントをインライン実行し、`c`、`cx`、`cy` は OpenCode、Claude Code、Codex を直接起動する（これも自動承認モードだ）。テーマの変更もエージェントに同期される。Claude Code、Pi、OpenCode、Hermes（Omarchy がインストール済みの場合）は、Omarchy のテーマを切り替えると一緒に追従する。

### エージェントパネル

トップバーにはエージェントのアイコンがある。エージェントをまだセットアップしていなければ、そのパネルが Claude、Codex、Grok へのサインインを順に案内し、最初の一つがデフォルトエージェントになる。その後は、パネルにすべてのサブスクリプションが1ページにまとめて表示される。各エージェントとアカウントについて、そのプラン、5時間セッション制限と週間制限それぞれのメーターとリセットまでの時間（ホバーすると正確なパーセンテージが表示される）、またはプリペイド残高が、全エージェント横断の利用状況（今週のトークン数や最もよく使ったモデルなど）を切り替え表示する行の下に並ぶ。_Make something_ の下では、新しいテーマ、プラグイン、アプリ向けのスタータープロンプトが用意されており、タスクをデフォルトエージェントに渡せる。アプリは Omarchy 自身の Hype、Monologue、Omacut と同じ方法で、C++ と Qt Quick を使い、omarchy-app エージェントスキルに従って構築される。必要なコンパイラと Qt の部品はインストール済みだ。Claude Code、Codex、Grok、Kimi、Cursor とその Grok Bot の利用枠、GitHub Copilot、Muse、Antigravity、Kimchi、Devin は、制限付きで最初から対応している。Hermes、Mistral Vibe、Qwen Code は、使うようになるとセッションとトークンが表示される。pi、omp、opencode 経由で使うプロバイダのプランとキーも表示される。制限付きでは OpenCode Zen と Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan、Synthetic、プリペイド残高付きでは Fireworks、OpenRouter、DeepSeek、そして自分のハードウェアで実行するモデルは Local models の下に表示される。すべてのエージェントは、どれだけ多くのハーネス経由で使っても、請求元のもとで一度だけ数えられる。

バーのアイコンを左クリックするとパネルが開き、右クリックするとデフォルトエージェントが起動する。その背後にある利用記録は `omarchy agent usage-update` によって15分ごとに再生成され、パネルは同期フォルダ経由で他のマシンからの利用状況をマージすることもできる。設定の詳細は `$OMARCHY_PATH/shell/plugins/agents/` にある README を参照。

### 複数のサブスクリプション

個人用の Max と仕事用など、Claude、Codex、Grok のプランを複数契約しているなら、Omarchy はそれらすべてをサインインしたまま保持し、切り替えて使える。サブスクリプションを追加するには、エージェントパネルの + を使う。その場で順に案内してくれる。または `omarchy agent account add claude Work`（`codex` や `grok` でもよい）を実行する。CLI がなければインストールされる。プロバイダの最初のアカウントは、CLI が常に見ている場所そのもので、通常のブラウザ経由でサインインする。それ以降のアカウントはすべてプライベートウィンドウ経由でサインインする。ブラウザですでにサインインしているアカウントを誤って拾わないためだ。そこでは追加しようとしているアカウントとしてサインインし、先にすでに開いているプライベートウィンドウは閉じておくこと。このために CLI からログアウトしては絶対にいけない。ログアウトすると保存済みのサインインが取り消され、そのアカウントは再度追加しなければならなくなる。

サブスクリプションのログインを SSH 経由で別の Omarchy マシンにコピーするには、`omarchy agent account copy user@laptop` を実行する。送信側は、宛先に受信側がインストールされていない場合、一時的な受信側を提供する。だから古い Omarchy マシンでもアップデートなしでアカウントを受け取れる。インストール済みの受信側が優先される。これにより Claude、Codex、Grok のすべてのサブスクリプションがコピーされる。選択するには `omarchy agent account copy laptop claude` のようにプロバイダ名を追加する。アカウント名とコマンド ID は送信元と一致する。宛先にすでに存在するアカウントも含む。無関係な宛先アカウントで名前が競合した場合は数字のサフィックスが付く。設定、スキル、プラグイン、会話履歴は各マシンにローカルのまま残る。

宛先の既存の資格情報は保持される。送信元アカウントがすでにそこでサインインしていれば、その名前は資格情報を置き換えることなく同期され、他のアカウントはその横に追加される。一致するアカウントの保存済み資格情報を置き換えるには、宛先でそのアカウントのセッションを終了した後、`omarchy agent account copy --replace laptop claude` を使う。新規の宛先には送信元のアクティブアカウントと切り替え設定も引き継がれる。確立済みの宛先は自身の設定を保持する。

資格情報は SSH 経由で移動し、宛先ではプライベートファイルに保存される。だから信頼できるマシンにだけコピーすること。これは一回限りのコピーであり、継続的な同期ではない。Codex のリフレッシュトークンは別のマシンによってローテーションされることがあり、コピーしたログインは更新が必要な状態になることがある。複数マシンで同時に使うなら、別々にサインインするのがやはり最も確実だ。[Codex のアカウント認証ガイダンス](https://developers.openai.com/codex/auth/ci-cd-auth) を参照。

プロバイダごとにアクティブなアカウントは一つで、すべての新しいセッションはそのアカウントとして開始される。`cx`、`cy`、素の `claude`、`codex`、`grok`、`omarchy agent` 経由で起動されるものすべて、そして `PATH` 上で CLI を見つけるスクリプトやエディタがそうだ。切り替えは `omarchy agent account use work`（戻すには `omarchy agent account use main`）で行うか、パネルでアカウントの番号を押してから `Enter` を押す（またはその Use ボタンをクリックする）。すでに実行中のセッションは、開始したアカウントのままになる。会話履歴、設定、スキル、プラグインはアカウント間で共有される。だから同じフォルダで `claude --continue` を実行すれば、新しいアカウントで中断したところから再開できる。

アカウントが複数あると、パネルには各アカウントの制限が横並びに表示され、アクティブなものに印が付く。デフォルトでは、アクティブなアカウントが制限の95%を超えると Omarchy が通知し、通知をクリックすると最も余裕のあるアカウントに切り替わる。自動で切り替えさせるには、パネルでアカウントの行にホバーして Use の横に表示される Autoswitch をクリックする（または `m` を押す）か、`omarchy agent account mode auto` を実行する。有効な間は Autoswitch が Use の代わりになり、再度クリックすると通知に戻る。`omarchy agent account mode auto 90` のように数字を追加すればしきい値を変更できる。すべてのアカウントがしきい値を超えている場合は、そのことと、どのアカウントが最初に解放されるかが一度だけ知らされる。アクティブなアカウントがしきい値から15ポイント以内（デフォルトでは80%）にある間、その制限は15分ごとではなく3分ごとにチェックされる。

`omarchy agent account list` はすべてのアカウントとその最新の制限を表示し、`omarchy agent account remove work` は一つを忘れ、`omarchy agent account rename primary Hey` は一つの名前を変更する（またはパネルでアカウント名をクリックする）。これらのコマンドはデフォルトエージェントのアカウントに対して動作する。別のプロバイダにアクセスするには、`omarchy agent account use codex side` のように先に名前を指定する。`~/.claude` や `~/.codex` にすでにあったログインが _Main_ アカウントで、その場所にそのまま残る。約8時間以上使われていないアカウントは _Sign-in required_ と表示されることがある。クリックすればパネル内でそのアカウントに再度サインインできる。またはそのアカウントでセッションを開始すれば、サインインは自動で更新される。アカウント追加時に持っていた MCP サーバーはそのアカウントにも付いてくるが、後から `claude mcp add` で追加したものは、追加したアカウントにしか届かない。Claude Desktop や、CLI バイナリへの絶対パスで設定されたツールは切り替えに追従しない。明示的な `CLAUDE_CONFIG_DIR`、`CODEX_HOME`、`GROK_HOME` は選択したアカウントより優先される。

### クラッシュ診断

Omarchy はプロセスのクラッシュについて systemd-coredump を監視している。何かがセグメンテーションフォルトを起こすと、「Process crashed」という通知が表示される。それをクリックすると、クラッシュは Omarchy の diagnose-crash スキルと一緒にデフォルトエージェントに渡される。そのスキルは、コアダンプから事実を確立し、そのクラッシュが上流に報告する価値があるかどうかを判断する手順をエージェントに案内する。`coredumpctl list` にある任意の PID に対して `omarchy agent crash <pid>` を使えば、手動で実行することもできる。

監視はデフォルトでオンだ。_Trigger > Toggle > Crash Capture_ で（または `omarchy toggle crash-capture` で）オフにすると通知は止まる。`omarchy agent crash <pid>` は手動では引き続き動作する。

クラッシュはプログラムごとに一つずつ黙らせることもできる。診断の最後に提案されるのがそれだ。`omarchy crash mute hyprland` はそのプログラムについてだけ通知を止め、`omarchy crash mute hyprland off` で元に戻し、`omarchy crash mute` を単独で実行するとミュートしたものが一覧表示される。名前と同じくらい気軽にバイナリのパスも受け付ける。だから `omarchy crash mute /usr/bin/hyprland` でも同じことになる。スペースを含む名前は `omarchy crash mute 'Some App'` のように引用すること。他のものはすべて引き続き通知され、ミュートされたプログラムも引き続きクラッシュする。これはリマインダーを隠すだけで、何も直してはいない。

### デスクトップアプリ

_Install > AI_ メニューにはグラフィカルな AI アプリもいくつかある。ChatGPT デスクトップアプリ、Claude デスクトップアプリ（Chat、Cowork、Claude Code のタブを備えた Anthropic の Linux ベータ）、xAI のモデルとチャットするための Grok Bot、Hermes Desktop、OpenClaw、Perplexity デスクトップアプリ、T3 Code だ。Grok Bot はデスクトップチャットアプリだ。コーディングエージェントは `grok` コマンドの方だ。

Hermes Desktop については知っておくべきだ。マシンには Hermes が一つしかなく、それはアプリのものだからだ。Hermes がインストールされるのは常にアプリ経由だけであり、デフォルトエージェントが実行する `hermes` コマンドはアプリのものだ。Hermes をデフォルトエージェントとして選択すると、_Install > AI_ の項目がインストールするのと同じものがインストールされる。パッケージと、Hermes 自身のインストーラによってセットアップされる `~/.hermes` 配下の Hermes ランタイムだ。初回は数分かかる。そのランタイムこそが、ターミナルの `hermes` コマンド、デフォルトエージェント、アプリのすべてが使う唯一の Hermes であり、Omarchy のリリースを待つのではなく `hermes update` で自身をアップデートする。インストールすると、Omarchy テーマが `omarchy` という名前のスキンとして Hermes にも渡され、テーマを切り替えるとすべての Hermes の画面がそれに追従する。そうしたくないなら、Hermes の Appearance 設定か `/skin` で別のものを選び直せばいい。Omarchy はその選択には干渉しない。_Remove > AI_ でアプリを削除すると、まず Hermes がゲートウェイも含めて終了し、そのランタイムも一緒に削除される。チャット、メモリ、Hermes が自らのために書いたスキルは、他に指示しない限り保持される。そのデータと接続設定も一緒に削除すべきかどうかを、デフォルトは「いいえ」で尋ねてくる。

OpenClaw のデスクトップ体験はその Control UI であり、自身のローカルゲートウェイをバックエンドとするウェブアプリとして開く。OpenClaw は `~/.openclaw` にあり、自身をアップデートする。Control UI の「Update Gateway」ボタンを使うか `openclaw update` を実行すれば、ゲートウェイは新しいバージョンで再起動する。Omarchy が決めるのは、新規インストールが開始するリリースだけだ。_Remove > AI_ で OpenClaw を削除すると、ゲートウェイサービスとアプリが一緒に削除され、その後 `~/.openclaw` も削除すべきかどうかを尋ねてくる。そこには OpenClaw 自体やダウンロードするプラグインランタイムと一緒に、チャットや資格情報が保持されているからだ。デフォルトでは保持され、OpenClaw を再度インストールすればそれを再び拾う。

T3 Code はパッケージからではなく、`~/.local/share/t3code` にある公式 AppImage リリースから動作するため、自身をアップデートする。インストール時には Stable チャンネルで始めるか Nightly チャンネルで始めるかを尋ねてくる。後から T3 Code の設定で切り替えられる。スレッドと設定は `~/.t3` にあり、_Remove > AI_ で T3 Code を削除するとそれらも一緒に削除される。

### ローカルモデル

コーディングエージェントのために、自分のマシンでオープンモデルを実行しよう。プロンプトとコードはマシン上に残り、モデルに送られたものがマシンから出ていくことはない。まずは次を実行する。

```bash
omarchy agent local use best
```

または、トップバーのエージェントパネルで + を選択し、次に Local AI を選択する。これはモデルがこのマシンに収まる場合に表示される。初回は、モデルを実行する Podman がインストールされる。続いて Omarchy がこのマシンに推奨されるモデルを選び、ダウンロードし、開始する。ダウンロードは数十 GB になり、モデル実行中はマシンのメモリの大半が使われると覚悟すること。Flash Next は完全な 256K コンテキストでは約 100 GiB を使う。必要なメモリを他のモデルが占有している場合は、停止した状態でセットアップされ、一つを停止すれば開始できる状態になる。モデルはログアウト時に停止する。メモリが他の用途に必要なときは自分で停止すること。

`omarchy agent local list` は選択肢を表示し、収まらないものについてはその理由を説明する。別のものをセットアップするには、`omarchy agent local use <recipe>` を実行する。現在、128 GB の Strix Halo マシン向けに `qwen3.8-flash-next-halogen` と `qwen3.8-27b-gufo` が利用できる。新しいレシピと推奨はパッケージ経由で `omarchy update` と一緒に届く。

セットアップしたモデルごとに、サブスクリプションの横のエージェントパネルに専用の行ができる。再生で開始し、一時停止で停止してメモリを解放し、ターミナルボタンでそのモデル上でエージェントを開く。メモリに一緒に収まる場合は複数を同時に実行できる。一つが収まらない場合は、Omarchy がどの実行中モデルを停止すべきかを教えてくれる。行をドラッグすれば並べ替えでき、選択した行で Delete を押せばモデルとそのダウンロードが削除される。

コマンドラインからは、`omarchy agent local start <recipe>` と `omarchy agent local stop <recipe>` が同じことを行い、`omarchy agent local status` はすべてのモデルを表示し、`omarchy agent --local` は最後に開始したモデル上でデフォルトエージェントを開く（デフォルトエージェントがローカルモデルを使えない場合は pi）。OpenAI 互換の任意のクライアントも接続できる。`status` は各モデルのアドレスを表示し（最初は `http://127.0.0.1:11435/v1`）、レシピ名がモデルで、キーは `~/.config/omarchy/agent-local/key` にある。

`omarchy agent local remove <recipe>` はモデルと、他のどのモデルも使っていないダウンロードを削除する。

サードパーティのランタイムにはその発行元が表示される。Omarchy はすべてのモデルをネットワークアクセスなしで実行する。

### ローカル LLM

Omarchy が推奨するローカル LLM モデルの実行方法は2つある。LM Studio と Ollama だ。LM Studio はオープンウェイトモデルを見つけ、インストールし、実行するための GUI インターフェースを提供する。手軽に始めるには最適な方法だ。Ollama は同様のことを行う CLI を提供する。だがローカルモデルが初めてなら、私なら LM Studio から始める。どちらも Omarchy Menu の _Install > AI_ でインストールできる。

### Omarchy スキル

エージェントスキルは、AI が特定のツールを特定の方法で使えるよう助けるものだ。Omarchy にはシステムをカスタマイズするためのデフォルトスキルが同梱されている。Hyprland の設定を微調整したり、バーを調整したり、テーマをゼロから新規作成したりするようなことだ。これは Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` と各 `~/.hermes/profiles/*/skills`）、そして汎用の `~/.agents/skills` の場所にあるスキルディレクトリにシンボリックリンクされている。そのため大半のハーネスが自動で拾ってくれる。

だがこのスキルは実験的なものとして扱うべきだ。モデルによって効果の出方は異なる。まずはプランモードで実行し、エージェントが何を変更したいのか把握するのが最善だ。そして、エージェントがすべてをめちゃくちゃにしたら、変更をロールバックしたり、場合によっては `omarchy reinstall configs` を実行したりする覚悟をしておくこと。
