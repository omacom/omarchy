### エージェントのインストールと更新

Hermes と OpenClaw を除き、すべてのエージェントは Omarchy 独自のリポジトリにあるパッケージです。_Install > AI > CLI_ から、または `omarchy install ai cli <command>` でインストールできます。再び削除するには _Remove > AI > CLI_ を使います。サインイン情報と履歴は残ります。まだインストールされていないエージェントを選ぶことでもインストールされます。エージェントパネルでスターを付ける、`omarchy default agent <name>` で選ぶ、またはそのサブスクリプションにサインインすることです。Omarchy は各エージェントの新リリースを1時間以内に全チャンネルへ公開し、`omarchy update` がシステムの他の部分と一緒にインストールします。

pacman が最新状態に保つため、エージェント自身のアップデーターはオフになっています。`claude update` やアプリ内の更新ボタンは機能しません。エージェントを独自のインストーラーから実行したいなら、それを使い、Omarchy のパッケージはインストールしないでください。すでに `PATH` 上にあるコピーはインストール済みとして扱われます。Omarchy のコピーより前に2つ目のコピーを `PATH` 上に置く `curl | bash` インストーラーは避けてください。x.ai の `grok` 用インストーラーがその例です。

`dsh` は `127.0.0.1:3080` でブラウザ UI を開き、起動ディレクトリをデフォルトのワークスペースにします。そのブラウザ UI は開始プロンプトを受け取らないため、`omarchy agent prompt` はプロンプトをクリップボードに載せた状態で開き、貼り付けられるようにします。Omarchy は DeepSeek の承認不要の権限プリセットで起動します。DeepSeek Harness は、公式モデル API を使うとセッションログを DeepSeek にアップロードします。そのブラウザ UI の _Settings > General > Upload Session Log_ でオフにしてください。送信したフィードバックもセッションと一緒にアップロードされます。ただし `DSH_TELEMETRY_MODE=DISABLED` で起動した場合は除きます。

### デフォルトのエージェント

エージェントパネルでエージェント横のスターでデフォルトのエージェントを選んでください。デフォルトにはスターが塗りつぶされます。または `omarchy default agent <name>` でも選べます。これは、そこに行がないハーネスも受け付けます。エージェントがまだインストールされていなければ、選ぶことでまずインストールされ、アプリランチャーに Agent の隣に独自のランチャーも作られます。新鮮な Omarchy では、一度だけの通知でセットアップを促し、エージェントパネルを開きます。

Claude を選ぶと、Chromium、Chrome、Brave、Brave Origin、Edge 用のブラウザ拡張機能のセットアップも試みます。拡張機能のセットアップは全ユーザーに適用され、システムパスワードを求めることがあります。キャンセルしたり拡張機能のインストールに失敗したりしても、Claude は選択され起動します。ブラウザを再起動し、求められたら拡張機能を有効化し、Claude にサインインして接続を完了してください。接続を確認するには Claude で `/chrome` を実行してください。Firefox と Zen はこの拡張機能に対応していません。このセットアップが追加される前にすでに Claude がデフォルトだった場合は、再度選択して拡張機能をインストールしてください。

選択したら、`Super + Shift + Ctrl + A` で専用のターミナルウィンドウでデフォルトのエージェントを起動します。まだ選んでいなければピッカーが表示されます。`omarchy agent prompt "Review this project"` でタスクに直行させることもできます。Freebuff と DeepSeek Harness は開始プロンプトを受け取らないため、代わりにプロンプトをクリップボードに載せて開き、貼り付けられるようにします。この方法で起動したエージェントは、それぞれの確認で止まらないモードで無人実行されます。本当に何かをしでかすので、そのつもりでいてください。MiniMax Code の対話セッションにはそうしたモードがないため、通常どおり権限を求めます。また、エージェントはホームディレクトリへの信頼を覚えることを拒否するため、`$HOME` からの起動は代わりに `~/Work` で始まります。

ターミナルショートカットもあります。`a` は現在のターミナル内でデフォルトのエージェントをインライン実行し、`c`、`cx`、`cy`、`ca` は OpenCode、Claude Code、Codex、Antigravity を直接起動します。これらも自動承認モードです。テーマ変更はエージェントにも同期されます。Claude Code、Pi、OpenCode、Hermes（Omarchy がインストールした後）は、Omarchy のテーマを切り替えると一緒に追従します。

### エージェントへの指示

すべてのエージェント向けの個人的なルールは、共有スキル `~/.agents/skills` の隣にある `~/.agents/AGENTS.md` に入れます。エージェントパネルの + の横にあるドキュメントアイコンで開くか、`omarchy agent instructions --edit` を使ってください。これは、独自のグローバルファイルを持つ各ハーネスにもリンクします。`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`~/.pi/agent/AGENTS.md`、`~/.config/opencode/AGENTS.md`、Copilot の `~/.copilot/copilot-instructions.md` などです。Crush と Amp は `~/.config/AGENTS.md` リンクを読み、omp、Kimi、DeepSeek Harness は `~/.agents/AGENTS.md` を直接読みます。デフォルトのエージェントを選ぶことでもリンクされます。すでに持っていた指示ファイルは、共有ファイルがまだなければ共有ファイルになります。そうでなければ、リンクの隣に `.bak` として保持されます。別のエージェントをインストールした後は `omarchy agent instructions` を実行して再リンクしてください。

### エージェントパネル

トップバーにはエージェントアイコンがあります。エージェントをセットアップする前、そのパネルでは3つの開始方法が提示されます。Claude、Codex、Grok、Gemini、Muse、Cursor、Copilot のサブスクリプションにサインインする。または More の下にある OpenCode Go、MiniMax、Synthetic、Z.ai のコーディングプラン。Fireworks、OpenCode Zen and Go、OpenRouter で従量課金する。または More の下にある DeepSeek や、OpenCode がサインインできる他のプロバイダーで、すべて OpenCode で実行する。または、このコンピューターに合うモデルがある場合、そのコンピューターに最適なモデルを実行する。最初に完了したものがデフォルトのエージェントになり、パネルの + は後からでも同じ3つを提示します。その後は、パネルはすべてのサブスクリプションを1ページにまとめます。各エージェントとアカウントとそのプラン、5時間セッション制限と週間制限それぞれのメーターとリセットまでの時間（ホバーで正確なパーセンテージ）、またはプリペイド残高。そしてその上には、すべてを通じて使ったものを切り替えて表示する行があります。今週のトークンや最も使ったモデルなどです。_Make something cool_ の下では、新しいテーマ、プラグイン、アプリ、ゲーム用のスタータープロンプトが提示され、タスクをデフォルトのエージェントに渡します。アプリは Omarchy 独自の Hype、Monologue、Omacut と同じ方法で、C++ と Qt Quick で構築され、omarchy-make-app エージェントスキルに従います。必要なコンパイラと Qt の部品はインストール済みです。ゲームは `~/Games/vibes` にある単一の three.js ページで、omarchy-make-game エージェントスキルに従い、すべて現在のテーマの1つの Game Vibes ランチャーから開きます。three.js をウェブから読み込むため、起動には接続が必要です。Claude Code、Codex、Grok、Kimi、Cursor とその Grok Bot の割り当て、GitHub Copilot、Muse、Gemini（Antigravity 経由）、Devin は制限付きですぐに使え、Kimchi はそのプラン、プリペイドクレジット、支出予算付きで、Hermes、Mistral Vibe、Qwen Code は一度使うとセッションとトークンを表示します。pi、omp、opencode 経由で使うプロバイダーのプランとキーも表示されます。OpenCode Zen and Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan、Synthetic は制限付き、OpenRouter と DeepSeek はプリペイド残高付き、Fireworks は過去30日間の支出付きです。自分のハードウェアで実行するコーディングモデルは独自の行を持ち、そのトークンも合計に数えられます。[ローカルモデル](#local-models) の説明のとおりです。すべてのエージェントは、請求する側の下で一度だけ数えられます。いくつハーネス経由で駆動しても同じです。

左クリックでバーアイコンを押すか `Super + Ctrl + X` を押すとパネルが開き、右クリックでデフォルトのエージェントを起動し、中央クリックで更新します。その背後にある使用記録は15分ごとに `omarchy agent usage update` で再生成され、パネルは同期フォルダ経由で他のマシンからの使用状況をマージすることもできます。全設定については `$OMARCHY_PATH/shell/plugins/agents/` の README を見てください。

### 複数のサブスクリプション

複数の Claude、Codex、Grok プランに支払っている場合、たとえば個人用の Max と仕事用など、Omarchy はすべてサインインしたまま切り替えられます。エージェントパネルの + でサブスクリプションを追加すると、その場で手順を案内します。または `omarchy agent account add claude Work`（`codex` や `grok` も可）を使います。同じ + とコマンドで Gemini（`gemini`）と OpenCode（`opencode`）にサインインし、Fireworks（`fireworks`）や OpenRouter（`openrouter`）の API キーを OpenCode に保存します。コマンドは Copilot（`copilot`）、Cursor（`cursor`）、Muse（`muse`）にもサインインします。これらはそれぞれ1つのサインインだけを保持します。CLI がなければインストールします。プロバイダーの最初のアカウントは、CLI が常に見る場所で、通常のブラウザ経由でサインインします。それ以降はすべてプライベートウィンドウ経由でサインインします。そのため、ブラウザですでにサインインしているアカウントを誤って拾うことはありません。追加するアカウントとしてそこでサインインし、先にすでに開いているプライベートウィンドウを閉じてください。このために CLI から絶対にログアウトしないでください。ログアウトすると保存したサインインが取り消され、そのアカウントを再度追加しなければならなくなります。

サブスクリプションログインを SSH 経由で別の Omarchy マシンにコピーするには、`omarchy agent account copy user@laptop` を実行してください。宛先に受信側がインストールされていない場合、送信側が一時的な受信側を供給します。そのため古い Omarchy マシンでも更新なしでアカウントを受け取れます。インストール済みの受信側が優先されます。これはすべての Claude、Codex、Grok サブスクリプションをコピーします。選択するにはプロバイダー名を追加してください。例：`omarchy agent account copy laptop claude`。アカウント名とコマンド ID はソースと一致します。宛先にすでに存在するアカウントも含みます。無関係な宛先アカウントは名前が競合すると数字のサフィックスを受け、設定、スキル、プラグイン、会話履歴は各マシンにローカルのまま残ります。

宛先に既存の資格情報は保持されます。ソースアカウントがすでにそこでサインインしていれば、その名前は資格情報を置き換えずに同期され、他のアカウントはその横に追加されます。一致するアカウントの保存済み資格情報を置き換えるには、宛先でそのアカウントのセッションを終了した後、`omarchy agent account copy --replace laptop claude` を使ってください。新鮮な宛先にはソースのアクティブアカウントと切り替え設定も引き継がれます。確立した宛先は自分のものを保持します。

資格情報は SSH 経由で移動し、宛先のプライベートファイルに保存されます。そのため、信頼するマシンにだけコピーしてください。これは一度きりのコピーであり、継続的な同期ではありません。Codex のリフレッシュトークンは別のマシンでローテーションされることがあり、コピーしたログインは更新が必要になります。複数のマシンで同時に使うには、別々のサインインが最も信頼できます。[Codex のアカウント認証ガイダンス](https://developers.openai.com/codex/auth/ci-cd-auth) を見てください。

プロバイダーごとにアクティブなアカウントは1つで、すべての新しいセッションはそれで始まります。`cx`、`cy`、素の `claude`、`codex`、`grok`、`omarchy agent` 経由で起動したもの、`PATH` 上で CLI を見つけるスクリプトやエディタです。`omarchy agent account use work` で切り替え（`omarchy agent account use main` で戻す）、またはパネルでアカウントの数字を押してから `Enter` を押す（またはそのスターをクリックする）ことで切り替えます。実行中の Claude セッションも次のメッセージから切り替わります。すべての Claude セッションは `~/.claude` で実行され、そこには常にアクティブアカウントのサインインが入っています。古い Omarchy でアカウント独自のフォルダで始まった Claude セッションは、終了するまでそのサインインを保持します。そのため切り替えではそれらのセッション名を挙げ、消えたら自然に完了します。実行中の Codex と Grok セッションは開始したアカウントのままです。会話履歴、設定、スキル、プラグインはアカウント間で共有されるため、同じフォルダで `claude --continue` をすると、新しいアカウントで中断したところから再開します。

アカウントが複数ある場合、パネルは各アカウントの制限を並べて表示し、使用中のものには塗りつぶされたスターが付きます。アクティブアカウントが制限の95%を超えると Omarchy が通知し、通知をクリックすると最も余裕のあるアカウントに切り替わります。自動では決して切り替えません。閾値は `omarchy agent account threshold 90` で変更してください。すべてのアカウントが閾値を超えた場合は、一度だけその旨と、どのアカウントが最初に空くかが知らされます。アクティブアカウントが閾値から15ポイント以内（デフォルトで80%）にある間、その制限は15分ごとではなく3分ごとにチェックされます。

`omarchy agent account list` はすべてのアカウントと最新の制限を表示し、`omarchy agent account remove work` は1つ忘れ、`omarchy agent account rename primary Hey` は名前を変更します（またはパネルでアカウント名をクリック）。これらのコマンドはデフォルトのエージェントのアカウントに対して動作します。別のプロバイダーに到達するには、まずその名前を指定してください。例：`omarchy agent account use codex side`。`~/.claude` や `~/.codex` にすでに持っていたログインは _Main_ アカウントです。Codex のものはそのまま残ります。Claude のものは、別のアカウントがアクティブな間、独自のフォルダで待ちます。約8時間以上使われていないアカウントは _Sign-in required_ と表示されることがあります。クリックしてそのアカウントでパネル内で再度サインインするか、それに切り替えてセッションを開始すると、サインインは自動で更新されます。`claude mcp add` で追加した MCP サーバーは、すべての Claude アカウントに届きます。すべて `~/.claude` で実行されるためです。Codex と Grok では、アカウント追加時に持っていたサーバーはそのアカウントにも付いてきますが、後のものは追加したアカウントにしか届きません。Claude Desktop は独自のサインインを保持し、CLI バイナリへの絶対パスで設定された Codex や Grok ツールは切り替えに従いません。明示的な `CLAUDE_CONFIG_DIR`、`CODEX_HOME`、`GROK_HOME` は選択したアカウントより優先されます。

### クラッシュ診断

Omarchy は systemd-coredump でプロセスクラッシュを監視します。デフォルトのエージェントを選んだら、あなたのプログラムがコアダンプすると「Process crashed」通知が来ます。クリックすると、クラッシュは Omarchy の omarchy-diagnose-crash スキルとともにデフォルトのエージェントに渡され、エージェントはコアダンプから事実を確立し、クラッシュが上流に報告する価値があるかどうかを判断する手順を進みます。`coredumpctl list` の任意の PID に対して `omarchy agent crash <pid>` で手動で実行することもできます。

監視はデフォルトでオンです。_Trigger > Toggle > Crash Capture Off_ で（または `omarchy toggle crash-capture` で）オフにすると通知は止まります。`omarchy agent crash <pid>` は手動では引き続き動作します。

クラッシュはプログラムごとに1つずつ消すこともできます。それが診断の最後に提示されるものです。`omarchy crash mute hyprland` はそのプログラムだけの通知を止め、`omarchy crash mute hyprland off` で戻し、`omarchy crash mute` だけではミュートしたものの一覧を表示します。バイナリのパスも名前と同じように受け付けるため、`omarchy crash mute /usr/bin/hyprland` でも同じです。スペースを含む名前は引用してください。例：`omarchy crash mute 'Some App'`。他のすべては引き続き通知され、ミュートしたプログラムは引き続きクラッシュします。これはリマインダーを隠すだけで、何も修正しません。

### デスクトップアプリ

_Install > AI > Desktop_ にはグラフィカルな AI アプリがあります。Amp Desktop、Antigravity Desktop、ChatGPT デスクトップアプリ、Claude デスクトップアプリ（Anthropic の Linux ベータ、Chat、Cowork、Claude Code タブ付き）、xAI のモデルとチャットする Grok Bot、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexity デスクトップアプリ、T3 Code です。Grok Bot はデスクトップチャットアプリです。コーディングエージェントは `grok` コマンドです。

Hermes Desktop は知っておくべきものです。マシンに Hermes は1つしかなく、それはアプリのものだからです。Hermes はアプリ経由でしかインストールされず、デフォルトのエージェントが実行する `hermes` コマンドはアプリのものです。Hermes をデフォルトのエージェントとして選ぶと、_Install > AI > Desktop_ の項目と同じものがインストールされます。パッケージと、Hermes 独自のインストーラーで `~/.hermes` の下にセットアップされる Hermes ランタイムです。初回は数分かかります。そのランタイムは、ターミナルの `hermes` コマンド、デフォルトのエージェント、アプリのすべてが使う唯一の Hermes であり、Omarchy のリリースを待たずに `hermes update` で自己更新します。インストールすると、Hermes に Omarchy テーマが `omarchy` という名前のスキンとして渡され、すべての Hermes 画面はテーマを切り替えるたびにそれに従います。従わせたくなければ Hermes の Appearance 設定で別のものを選ぶか `/skin` を使ってください。Omarchy はその選択を放っておきます。_Remove > AI > Desktop_ でアプリを削除すると、まずゲートウェイを含め Hermes が閉じ、そのランタイムも一緒に削除され、伝えない限りチャット、メモリ、Hermes が自分のために書いたスキルは保持されます。データと接続設定も削除するかどうかを尋ね、デフォルトは「いいえ」です。

OpenClaw のデスクトップ体験は Control UI です。独自のローカルゲートウェイをバックエンドとするウェブアプリとして開きます。OpenClaw は `~/.openclaw` に住み、自己更新します。Control UI の「Update Gateway」ボタンを使うか `openclaw update` を実行すると、ゲートウェイは新しいバージョンで再起動します。Omarchy は新鮮なインストールが開始するリリースを選ぶだけです。OpenClaw はデフォルトのエージェントにもなれます。`omarchy default agent openclaw` で選ぶと、`~/.openclaw` に同じコピーがセットアップされ、エージェントはそのゲートウェイに接続した OpenClaw のターミナル UI を開きます。_Remove > AI > Desktop_ で OpenClaw を削除すると、ゲートウェイサービスとアプリが一緒に削除され、その後 `~/.openclaw` も削除するかどうかを尋ねます。そこにはチャットと資格情報が、OpenClaw 自体とダウンロードしたプラグインランタイムと一緒にあります。デフォルトでは保持され、OpenClaw を再びインストールすると再び拾います。

Herdr Desktop は [Herdr](https://herdr.dev) デスクトップアプリです。ウィンドウを閉じてもそのコアで実行し続けるターミナルとコーディングエージェントのスペース、タブ、ペインです。パッケージではなく Herdr 独自のインストーラーから来るため、`~/.local/share/herdr-app` に住み、まだ持っていない場合は `~/.local/bin/herdr-core` にコアを持ってきて、両方を自己更新します。Omarchy が `Super + Ctrl + Return` で提供する `herdr` コマンドの隣に座り、置き換えはしません。そしてそのコマンドの直接キーを受けます。`Alt + Return` と `Alt + Shift + Return` はペインを下または右に分割し、`Alt + Escape` は閉じ、`Ctrl + Alt + Arrow` はペイン間を移動し、`Alt + 1..9` と `Alt + Left/Right` はタブを選び、`Alt + Up/Down` はスペース間を移動します。`Ctrl + 1..9` はスペースを選び、`Alt + Shift + Up/Down` はエージェントを順に進みます。`Ctrl + Space` プレフィックスキーはターミナル専用のままです。アプリは素の Ctrl キーをシーケンスのために保持できないためです。Omarchy はこれらを `~/.config/herdr-app/keys.json` に書き、`omarchy-refresh-herdr-app` が戻します。インストールすると Herdr の Omarchy テーマが選ばれ、それ以降 Omarchy テーマに従います。Herdr はライトモード用に1つ、ダークモード用に1つのテーマを保持します。そのため、ダークな Omarchy テーマとライトな Omarchy テーマを切り替えた後は、もう一方のモードのために Herdr のテーマピッカーでもう一度 Omarchy を選んでください。

T3 Code は、パッケージではなく `~/.local/share/t3code` にある公式 AppImage リリースから実行されるため、自己更新します。インストール時に Stable チャンネルで始めるか Nightly チャンネルで始めるかを尋ねます。後から T3 Code の設定で切り替えてください。スレッドと設定は `~/.t3` に住み、_Remove > AI > Desktop_ で T3 Code を削除すると一緒に削除されます。

### ローカルモデル

コーディングエージェント用に、自分のマシンでオープンモデルを実行してください。プロンプトとコードはマシンに残り、モデルに送られたものは何も外に出ません。次から始めてください。

```bash
omarchy models use best text
```

これで、このマシンに最適なテキストモデル、エージェントが使うタイプがセットアップされます。画像、動画、音楽モデルにもそれぞれ最適なものがあります。`omarchy models use best image`、`video`、`music` です。`omarchy models use best` を実行すると、各タイプのこのマシン向けの選択が見られます。

またはエージェントパネルで + を選んでください。_Use a local model_ の下に、このマシンに合うすべてのコーディングモデルが、推奨のものを先頭に一覧されます。モデルを実行する Podman は Omarchy に付属し、NVIDIA マシンでは NVIDIA のコンテナツールキットも付属して GPU を使えるようにします。どちらかが欠けていれば、最初のセットアップでインストールします。その後 Omarchy はこのマシンに推奨のモデルを選び、ダウンロードして開始します。数十GB のダウンロードと、モデル実行中のマシンメモリの大半の使用を見込んでください。Flash Next は完全な 256K コンテキストで約 100 GiB を使います。必要なメモリを他のモデルが占めていれば、停止した状態でセットアップされ、1つ止めたら開始できるようになります。モデルはログアウトで止まります。他のことのためにメモリが必要なときは自分で止めてください。

`omarchy models list` は選択肢を表示し、合わない理由を説明します。別のものをセットアップするには `omarchy models use <recipe>` を実行してください。今日では、128 GB Strix Halo マシン用に `qwen3.8-flash-next-gufo` と `qwen3.8-27b-gufo` が利用できます。27B は約 40 GiB を使うため、他の仕事の余地が残ります。Intel の Arc B390 を搭載した 64 GB ラップトップでは、`qwen3.6-35b-a3b-llamacpp` が約 30 GiB で動作します。新しいレシピと推奨は `omarchy update` でパッケージ経由で届きます。

追加したコーディングモデルはエージェントパネルに、サブスクリプションの隣に独自の行を持ちます。再生で開始、ポーズで停止してメモリを解放、Tailscale マークで実行中に tailnet 上の他のマシンと共有、ターミナルボタンでそのモデル上でエージェントを開きます。その行はダウンロード、ロード、停止の様子を表示し、開始するのに十分な空きメモリがないときはその旨を伝え、エラーで停止したときはログへのリンクを表示します。メモリに一緒に収まる場合は複数を同時に実行できます。選択した行で Delete を押すと、ダウンロードごとモデルをこのマシンから削除します。+ で再びセットアップできます。ターミナルからセットアップしたコーディングモデルは、追加するまで + の下で待ちます。ペアリングしたマシン（`omarchy models pair <host>`）が実行するモデルも同様です。

セットアップしたすべてのコーディングモデルは、アプリランチャーにも、モデル名の下にそのメーカーのロゴ付きで独自の項目を持ちます。Claude、Codex、Grok にサインインすると項目が追加されるのと同じです。それはそのモデル上でエージェントを開き、実行していなければまずモデルを開始します。ターミナルはロード中を表示し、上がったらエージェントに引き渡します。モデルを削除するとその項目も削除されます。

すべてのモデルがコーディング用ではありません。画像、動画、音楽モデルは代わりに Fantasi で開きます。Fantasi は、このマシンで実行されるモデルで画像、動画、音楽を作る Omarchy のアプリであり、そこか `omarchy models` で管理されます。

モデルはセットアップされたまま正確に実行され続けるため、Omarchy の更新でエージェントの下で再起動されることは決してありません。Omarchy が、セットアップしたモデルについて新しいランタイムや新しいウェイトを持っている場合、その行に更新ボタンが表示されます。押すとモデルはバックグラウンドで再びセットアップされ、変わった分だけダウンロードし、新しいバージョンで再起動します。停止していたモデルは停止したままです。`omarchy models update` はターミナルからすべてのモデルに対して同じことをします。

コマンドラインから、`omarchy models start <recipe>` と `omarchy models stop <recipe>` が同じことをし、`omarchy models status` はすべてのモデルを表示し、`omarchy agent --local-model <recipe>` はデフォルトのエージェントが何であれ、そのモデルを pi で開きます。ローカルモデルを、エージェントホットキー、Quake コンソール、_Make something_ が開くものにするには、`omarchy default agent local` を実行するか、エージェントパネルで実行中のモデルにスターを付けてください。pi はセットアップしたすべてのモデルと、ペアリングしたマシン上のモデルも独自のモデルピッカーに一覧するため、素の `pi` でも到達できます。OpenAI 互換のクライアントも接続できます。`status` は各モデルのアドレスを示し（最初は `http://127.0.0.1:11435/v1`）、レシピ名がモデルで、キーは `~/.config/omarchy/agent-local/key` にあります。

`omarchy models remove <recipe>` はモデルと、他のどのモデルも使っていないダウンロードを削除します。

サードパーティのランタイムにはその発行元がラベルされます。Omarchy はすべてのモデルをネットワークアクセスなしで実行します。

### ローカル LLM

Omarchy はローカル LLM モデルを実行する方法として、LM Studio と Ollama の2つを推奨します。LM Studio は、オープンウェイトモデルを見つけ、インストールし、実行するための GUI インターフェースを提供します。簡単に始めるには素晴らしい方法です。Ollama は同様のことをする CLI を提供します。しかしローカルモデルが初めてなら、私は LM Studio から始めます。LM Studio は _Install > AI > Desktop_ から、Ollama は Omarchy Menu の _Install > AI > CLI_ からインストールしてください。

### Omarchy スキル

エージェントスキルは、AI が特定のツールを特定の方法で使うのを助け、Omarchy は7つを提供します。omarchy スキルは、Hyprland 設定をいじったりバーを調整したりするような、システムのカスタマイズをカバーします。omarchy-make-theme、omarchy-make-plugin、omarchy-make-app、omarchy-make-game は新しいものを作ることをカバーし、omarchy-contribute はバグの報告や修正の上流への送信をカバーし、omarchy-diagnose-crash はクラッシュのコアダンプを調べます。これらは Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` と各 `~/.hermes/profiles/*/skills`）、そして汎用の `~/.agents/skills` 場所のスキルディレクトリにシンボリックリンクされているため、ほとんどのハーネスが自動で拾います。同名の自分のスキルフォルダが優先されます。

しかしこれらのスキルは実験的なものとして扱うべきです。モデルごとに使い方が異なって効果も変わります。まずプランモードで実行するのが最善です。そうすればエージェントが何を変更したいかが分かります。そして変更をロールバックする、あるいはエージェントがすべてを台無しにしたら `omarchy reinstall configs` を呼び出す準備をしておいてください。
