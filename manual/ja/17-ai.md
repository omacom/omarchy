### エージェントのインストールと更新

Hermesを除き、これらのエージェントはmiseの遅延インストールを使う。初回起動時にCLIがインストールされ、2回目以降はそれを再利用する。miseはまた、インストール済みエージェントの新リリースを最大で4時間に1度だけ、起動直前か、シェルプロンプトでバックグラウンドでチェックする。その更新が失敗したりオフラインだったりすれば、インストール済みのバージョンが動く。`omarchy update`はOmarchyの他の部分と一緒にインストール済みエージェントを更新し、`mup`はmise管理のツールだけを更新する。

`claude update`、`codex update`、あるいはアプリ内の更新ボタンのような、エージェント自体のアップデーターは、mise管理のインストールを更新しない。`codex update`は失敗するし、`claude update`は成功したと報告しながら、miseが追跡しない別コピーをインストールすることがある。エージェント本来のインストーラーとアップデーターを使いたいなら、それを`disable_tools`に追加すること。[プリインストールされたCLIツール](18-development-tools.md#preinstalled-cli-tools)を見てほしい。

必要になる前に、設定済みの遅延ツールをすべてインストールするには、`mise install --include-lazy`を実行する。これにはエージェントだけでなく、Omarchyの他のデフォルトCLIツールも含まれる。単一ツールのインストールや、自分のインストールを使う方法については[プリインストールされたCLIツール](18-development-tools.md#preinstalled-cli-tools)を見てほしい。

`grok`は、`claude`や`codex`と同じように、miseのファーストパーティ`grok`パッケージ経由でインストールされる。`grok`を実行するか、_Setup > Defaults > Agent_で選ぶこと。x.aiの`curl | bash`インストーラーは避けること。その経路は`~/.grok/bin`に2つ目のコピーを置き、`PATH`の先頭にそれを加え、Omarchyのラッパーを上書きする。

`dsh`は`127.0.0.1:3080`でブラウザUIを開き、起動したディレクトリをデフォルトのワークスペースにする。そのブラウザUIは開始プロンプトを受け取らないので、`omarchy agent prompt`はプロンプトをクリップボードに入れた状態で開くので、貼り付けて使ってほしい。OmarchyはDeepSeekの承認なし権限プリセットでこれを起動する。DeepSeek Harnessは、公式モデルAPIを使うとセッションログをDeepSeekにアップロードする。そのブラウザUIの_Settings > General > Upload Session Log_でオフにできる。送ったフィードバックもセッションと一緒にアップロードされる。ただし`DSH_TELEMETRY_MODE=DISABLED`で起動すれば別だ。

### デフォルトのエージェント

デフォルトのエージェントは`omarchy default agent <name>`で、あるいはOmarchy Menu（`Super + Space`）の_Setup > Defaults > Agent_で選ぶ。そのエージェントがまだインストールされていなければ、選んだ時点で先にインストールされる。新しいOmarchyでは、一度だけの通知でこの選択をするよう促される。

Claudeを選ぶと、Chromium、Chrome、Brave、Brave Origin、Edge向けにそのブラウザ拡張機能のセットアップも試みる。拡張機能のセットアップは全ユーザーに適用され、システムパスワードを求められることがある。キャンセルしたり拡張機能のインストールが失敗したりしても、Claudeは選択され、起動する。ブラウザを再起動し、求められたら拡張機能を有効にし、Claudeにサインインして接続を完了すること。接続を確認するにはClaudeで`/chrome`を実行する。FirefoxとZenはこの拡張機能に対応していない。Claudeがこのセットアップが追加される前から既にデフォルトだった場合は、もう一度選び直して拡張機能をインストールすること。

一度選べば、`Super + Shift + Ctrl + A`でデフォルトのエージェントが専用ターミナルウィンドウで起動する（まだ選んでいなければピッカーが表示される）。`omarchy agent prompt "Review this project"`のように、タスクを直接与えて起動もできる。FreebuffとDeepSeek Harnessは開始プロンプトを受け取らないので、代わりにプロンプトをクリップボードに入れた状態で開く。こうして起動したエージェントは、それぞれの「止まって聞かない」モードで無人で動くので、実際にいろいろやる覚悟をしておくこと！ MiniMax Codeにはインタラクティブセッション向けのそのようなモードがないので、通常通り権限を求めてくる。そして、エージェントはホームディレクトリに対する信頼を覚えることを拒否するので、`$HOME`からの起動は代わりに`~/Work`で開始する。

ターミナル用ショートカットもある。`a`は現在のターミナル内でデフォルトのエージェントをインラインで実行し、`c`、`cx`、`cy`はOpenCode、Claude Code、Codexを直接起動する（こちらも自動承認モードで）。テーマの変更もエージェントに同期される。Claude Code、Pi、OpenCode、Hermes（Omarchyがインストールした後）は、Omarchyのテーマを切り替えると一緒に追従する。

### エージェントパネル

トップバーにはエージェントアイコンがある。エージェントをセットアップする前は、そのパネルがClaude、Codex、Grokへのサインインを案内し、最初に設定したものがデフォルトのエージェントになる。その後は、パネルはすべてのサブスクリプションを1ページにまとめる。各エージェントとアカウント、そのプラン、5時間のセッション制限と週次制限それぞれのメーターとリセットまでの時間（ホバーで正確なパーセンテージが見える）、あるいはプリペイド残高が、それらすべてを通して使った内容をローテーション表示する行の下に並ぶ。たとえば今週のトークン数や最も使ったモデルなどだ。_Make something_の下では、新しいテーマ、プラグイン、アプリのためのスタータープロンプトが用意され、タスクをデフォルトのエージェントに渡す。アプリはOmarchy自体のHype、Monologue、Omacutと同じ方法で、C++とQt Quickで、omarchy-appエージェントスキルに従って構築され、必要なコンパイラとQtの部品はインストール済みで付いてくる。Claude Code、Codex、Grok、Kimi、CursorとそのGrok Bot枠、GitHub Copilot、Muse、Antigravity、Kimchi、Devinは、制限付きで最初からカバーされる。Hermes、Mistral Vibe、Qwen Codeは、一度使えばセッションとトークンが表示される。pi、omp、opencode経由で使うプロバイダーのプランとキーも表示される。制限付きのOpenCode ZenとGo、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan、Synthetic、プリペイド残高のFireworks、OpenRouter、DeepSeek、そして自分自身のハードウェアで動かすモデルはLocal modelsの下に並ぶ。すべてのエージェントは、請求元のもとで一度だけ数えられる。何個のハーネス経由で駆動しても同じだ。

バーのアイコンを左クリックするとパネルが開き、右クリックするとデフォルトのエージェントが起動する。その背後にある使用記録は、`omarchy agent usage-update`によって15分ごとに再生成され、パネルは同期フォルダ経由で他のマシンからの使用量をマージすることもできる。完全な設定については、`$OMARCHY_PATH/shell/plugins/agents/`の下にあるREADMEを見てほしい。

### 複数のサブスクリプション

Claude、Codex、Grokのプランを複数払っている場合、たとえば個人のMaxと仕事用など、Omarchyはすべてをサインインしたまま保ち、それらの間を行き来できる。サブスクリプションはエージェントパネルの+で追加でき、その場で案内してくれる。あるいは`omarchy agent account add claude Work`（または`codex`、または`grok`）でも追加できる。CLIがなければインストールする。プロバイダーごとの最初のアカウントは、CLIがいつも探す場所で、通常のブラウザ経由でサインインする。それ以降のすべてのアカウントはプライベートウィンドウ経由でサインインするので、ブラウザが既にサインインしているアカウントを間違って拾うことがない。そこで追加したいアカウントとしてサインインし、既に開いているプライベートウィンドウは先に閉じること。そのためにCLIからログアウトしてはいけない。ログアウトすると保存されたサインインが失効し、そのアカウントは再び追加し直さなければならなくなる。

サブスクリプションのログインをSSH経由で別のOmarchyマシンにコピーするには、`omarchy agent account copy user@laptop`を実行する。送信側は、宛先に受信側がインストールされていない場合、一時的な受信側を提供するので、古いOmarchyマシンでも更新なしにアカウントを受け取れる。インストール済みの受信側が優先される。これはClaude、Codex、Grokすべてのサブスクリプションをコピーする。`omarchy agent account copy laptop claude`のようにプロバイダー名を追加して選択できる。アカウント名とコマンドIDは転送元と一致する。宛先に既に存在するアカウントも含めてだ。無関係な宛先アカウントは、名前が競合すれば数字の接尾辞を受け取り、設定、スキル、プラグイン、会話履歴は各マシンにローカルなまま残る。

宛先に既存の認証情報は保持される。転送元アカウントが既にそこでサインインしていれば、その名前が同期されるが認証情報は置き換えられない。他のアカウントはその横に追加される。一致するアカウントの保存済み認証情報を置き換えるには、宛先でそのアカウントのセッションを終了した後で、`omarchy agent account copy --replace laptop claude`を使う。新しい宛先は転送元のアクティブなアカウントと切り替え設定も受け取る。既に定着した宛先は自身のものを保持する。

認証情報はSSH経由で移動し、宛先ではプライベートファイルに保存されるので、信頼できるマシンにだけコピーすること。これは一度きりのコピーであり、継続的な同期ではない。Codexのリフレッシュトークンは別のマシンによってローテーションされることがあり、コピーしたログインは更新が必要な状態になる。複数のマシンで同時に使うには、別々にサインインするのが最も確実な選択だ。[Codex's account authentication guidance](https://developers.openai.com/codex/auth/ci-cd-auth)を見てほしい。

プロバイダーごとにアクティブなアカウントは1つで、すべての新しいセッションはそれとして開始する。`cx`、`cy`、素の`claude`、`codex`、`grok`、`omarchy agent`経由で起動するあらゆるもの、そして`PATH`上でCLIを見つけるスクリプトやエディタもそうだ。`omarchy agent account use work`で切り替え（`omarchy agent account use main`で戻す）、あるいはパネルでアカウントの数字を押してから`Enter`を押す（またはそのUseボタンをクリックする）。既に実行中のセッションは、開始したアカウントのまま残る。会話履歴、設定、スキル、プラグインはアカウント間で共有されるので、同じフォルダで`claude --continue`すれば、新しいアカウントで中断したところから続けられる。

アカウントが複数あると、パネルは各アカウントの制限を並べて表示し、アクティブなものに印を付ける。デフォルトでは、アクティブなアカウントが制限の95%を超えるとOmarchyが通知し、通知をクリックすると最も余裕のあるアカウントに切り替わる。パネルのアカウントの行にホバーして、Useの横に表示されるAutoswitchをクリックする（または`m`を押す）か、`omarchy agent account mode auto`を実行すれば、代わりに自動で切り替わる。それがオンの間は、AutoswitchがUseの場所を取り、それを再びクリックすると通知に戻る。`omarchy agent account mode auto 90`のように数字を追加するとしきい値を変更できる。すべてのアカウントがしきい値を超えていれば、一度だけそれを知らされ、どのアカウントが最初に解放されるかも知らされる。アクティブなアカウントがしきい値から15ポイント以内（デフォルトでは80%）にある間は、その制限は15分ごとではなく3分ごとにチェックされる。

`omarchy agent account list`はすべてのアカウントとその最新の制限を表示し、`omarchy agent account remove work`は1つを忘れ、`omarchy agent account rename primary Hey`は1つを改名する（またはパネルでアカウント名をクリックする）。これらのコマンドはデフォルトのエージェントのアカウントに対して動作する。別のプロバイダーに届くには、`omarchy agent account use codex side`のように先に名前を指定すること。`~/.claude`や`~/.codex`に既に持っていたログインは_Main_アカウントであり、その場所に残る。約8時間以上使われていないアカウントは_Sign-in required_と表示されることがある。それをクリックするとパネルですぐにそのアカウントに再サインインできる。あるいはそのアカウントでセッションを開始すれば、サインインが自動的に更新される。アカウントが追加されたときに持っていたMCPサーバーはそれに付いてくるが、`claude mcp add`で後から追加したものは、追加したアカウントにしか届かない。Claude Desktopと、CLIバイナリへの絶対パスで設定されたツールは切り替えに追従しない。明示的な`CLAUDE_CONFIG_DIR`、`CODEX_HOME`、`GROK_HOME`は、選択したアカウントより優先される。

### クラッシュ診断

Omarchyはプロセスのクラッシュについてsystemd-coredumpを監視する。何かがセグメンテーション違反を起こすと、「Process crashed」通知が届く。それをクリックすると、クラッシュはデフォルトのエージェントに、Omarchyのdiagnose-crashスキルと一緒に渡される。そのスキルは、コアダンプから事実を確立し、そのクラッシュがアップストリームに報告する価値があるかどうかを判断する手順をエージェントに案内する。`coredumpctl list`の任意のPIDに対して`omarchy agent crash <pid>`で手動で実行もできる。

監視はデフォルトでオンだ。_Trigger > Toggle > Crash Capture_の下で（または`omarchy toggle crash-capture`で）オフにすると通知は止まる。`omarchy agent crash <pid>`は手動では引き続き動作する。

クラッシュはプログラムごとに1つずつ黙らせることもできる。それが診断の最後に提示されることだ。`omarchy crash mute hyprland`はそのプログラムだけの通知を止め、`omarchy crash mute hyprland off`はそれを戻し、`omarchy crash mute`単独ではミュートしたものの一覧を表示する。バイナリのパスでも名前でも同じように受け付けるので、`omarchy crash mute /usr/bin/hyprland`でも同じことになる。`omarchy crash mute 'Some App'`のように、スペースを含む名前は引用符で囲むこと。他のすべては引き続き通知され、ミュートされたプログラムは引き続きクラッシュする。これはリマインダーを隠すだけで、何も直さない。

### デスクトップアプリ

_Install > AI_メニューには、グラフィカルなAIアプリもいくつかある。ChatGPTデスクトップアプリ、Claudeデスクトップアプリ（AnthropicのLinuxベータで、Chat、Cowork、Claude Codeのタブを持つ）、xAIのモデルとチャットするためのGrok Bot、Hermes Desktop、OpenClaw、Perplexityデスクトップアプリ、そしてT3 Codeだ。Grok Botはデスクトップチャットアプリだ。コーディングエージェントは`grok`コマンドの方だ。

Hermes Desktopは知っておくべきものだ。なぜならマシンにはHermesが1つしかなく、それはアプリのものだからだ。Hermesは常にアプリ経由でのみインストールされ、デフォルトのエージェントが実行する`hermes`コマンドはアプリのものだ。Hermesをデフォルトのエージェントに選ぶと、_Install > AI_の項目がするのと同じものがインストールされる。そのパッケージと、Hermes自体のインストーラーによってセットアップされた`~/.hermes`の下のHermesランタイムで、初回は数分かかる。そのランタイムこそが、ターミナルの`hermes`コマンド、デフォルトのエージェント、アプリのすべてが使う唯一のHermesであり、Omarchyのリリースを待つのではなく、`hermes update`で自分自身を更新する。インストールすると、Hermesには`omarchy`という名前のスキンとしてOmarchyのテーマも渡され、すべてのHermesの表面はテーマを切り替えるとそれに追従する。そうしたくなければHermesのAppearance設定の下か`/skin`で別のものを選ぶこと。Omarchyはその選択に干渉しない。_Remove > AI_の下でアプリを削除すると、まずHermesが閉じられ、ゲートウェイも含め、そのランタイムも一緒に削除される。そして、チャット、メモリ、Hermesが自分のために書いたスキルは、そう指示しない限り保持される。そのデータと接続設定も一緒に削除すべきかどうかを、デフォルトは「いいえ」で尋ねてくる。

OpenClawのデスクトップ体験はControl UIであり、それは自身のローカルゲートウェイをバックエンドにしたWebアプリとして開く。OpenClawは`~/.openclaw`に住み、自分自身を更新する。Control UIの「Update Gateway」ボタンを使うか`openclaw update`を実行すると、ゲートウェイは新しいバージョンで再起動する。Omarchyが選ぶのは、新規インストールがどのリリースから始まるかだけだ。_Remove > AI_の下でOpenClawを削除すると、ゲートウェイサービスとアプリが一緒に削除され、その後`~/.openclaw`も削除すべきかどうか尋ねてくる。そこにはOpenClaw自体やダウンロードするプラグインランタイムと一緒に、チャットと認証情報が入っているからだ。デフォルトは保持であり、OpenClawを再びインストールすればそれを拾い直す。

T3 Codeはパッケージからではなく、`~/.local/share/t3code`にある公式AppImageリリースから動くので、自分自身を更新する。インストールすると、StableチャンネルかNightlyチャンネルかどちらで始めるか尋ねてくる。後からT3 Codeの設定で切り替えられる。スレッドと設定は`~/.t3`に住み、_Remove > AI_の下でT3 Codeを削除するとそれらも一緒に削除される。

### ローカルLLM

OmarchyがローカルLLMモデルを実行する方法としておすすめするのは、LM StudioとOllamaの2つだ。LM Studioは、オープンウェイトモデルを見つけ、インストールし、実行するためのGUIインターフェイスを提供する。手軽に始めるのに最適な方法だ。Ollamaは同様のことをするためのCLIを提供する。だがローカルモデルが初めてなら、私ならLM Studioから始める。どちらもOmarchy Menuの_Install > AI_の下でインストールできる。

### Omarchy Skill

エージェントスキルは、AIが特定のツールを特定の方法で使うのを助けるものであり、Omarchyにはシステムをカスタマイズするためのデフォルトスキルが付属している。Hyprlandの設定をいじったり、バーを調整したり、ゼロから新しいテーマを作ったりするようなことだ。これはClaude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills`と各`~/.hermes/profiles/*/skills`）、そして汎用の`~/.agents/skills`の場所にあるスキルディレクトリにシンボリックリンクされているので、ほとんどのハーネスが自動的に拾う。

だがこのスキルは実験的なものとして扱うべきだ。モデルによって効果の出方は異なる。まずプランモードで実行するのが最善で、そうすればエージェントが何を変更したいのか把握できる。そして、エージェントがすべてをめちゃくちゃにした場合は、変更をロールバックしたり、`omarchy reinstall configs`を呼び出したりする覚悟をしておくこと。
