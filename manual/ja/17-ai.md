### エージェントのインストールと更新

Hermes を除き、これらのエージェントは mise の遅延インストールを使う。初回起動時に CLI をインストールし、以降の起動ではそれを再利用する。mise はまた、インストール済みエージェントの新しいリリースを最大で 4 時間に 1 回、起動直前かシェルプロンプトでバックグラウンドで確認する。その更新が失敗したりオフラインだったりすれば、インストール済みのバージョンが動作する。`omarchy update` は Omarchy の残りと一緒にインストール済みエージェントを更新し、`mup` は mise 管理のツールだけを更新する。

`claude update`、`codex update` のようなエージェント独自のアップデーターやアプリ内の更新ボタンでは、mise 管理のインストールは更新されない。`codex update` は失敗し、`claude update` は成功したと報告しながら mise が追跡しない別コピーをインストールすることがある。エージェントのネイティブなインストーラーとアップデーターを使いたいなら、それを `disable_tools` に追加すること。詳細は [プリインストールされた CLI ツール](18-development-tools.md#preinstalled-cli-tools) を参照。

設定済みの遅延ツールをすべて必要になる前にインストールするには、`mise install --include-lazy` を実行する。これにはエージェントだけでなく Omarchy の他のデフォルト CLI ツールも含まれる。単一ツールのインストールや独自インストールの使用については [プリインストールされた CLI ツール](18-development-tools.md#preinstalled-cli-tools) を参照。

`grok` は mise のファーストパーティ `grok` パッケージ経由で、`claude` や `codex` と同じ方法でインストールされる。`grok` を実行するか、_Agent > Harness_ で選択する。x.ai の `curl | bash` インストーラーは使わないこと。その方法では `~/.grok/bin` に 2 つ目のコピーが置かれ、`PATH` の先頭に追加され、Omarchy のラッパーが上書きされる。

`dsh` は `127.0.0.1:3080` でブラウザ UI を開き、起動したディレクトリをデフォルトのワークスペースとする。そのブラウザ UI は開始プロンプトを受け付けないため、`omarchy agent prompt` ではプロンプトをクリップボードに入れた状態で開くので、それを貼り付ける。Omarchy は DeepSeek の承認なし権限プリセットでこれを起動する。DeepSeek Harness は公式モデル API を使うとセッションログを DeepSeek にアップロードする。それをオフにするにはブラウザ UI の _Settings > General > Upload Session Log_ で設定する。送信したフィードバックもセッションと一緒にアップロードされる。ただし `DSH_TELEMETRY_MODE=DISABLED` を付けて起動した場合は別だ。

### デフォルトのエージェント

デフォルトのエージェントは `omarchy default agent <name>` で選ぶか、Omarchy Menu（`Super + Space`）の _Agent > Harness_ で選ぶ。エージェントがまだインストールされていなければ、選ぶとまずインストールされる。Omarchy をインストールした直後には、1 回限りの通知でこの選択を促される。

Claude を選ぶと、Chromium、Chrome、Brave、Brave Origin、Edge 用のブラウザ拡張機能のセットアップも試みる。拡張機能のセットアップはすべてのユーザーに適用され、システムパスワードを求められることがある。キャンセルしたり拡張機能のインストールに失敗したりしても、Claude は選択され起動される。ブラウザを再起動し、求められたら拡張機能を有効にし、Claude にサインインして接続を完了すること。接続を確認するには Claude で `/chrome` を実行する。Firefox と Zen はこの拡張機能に対応していない。このセットアップが追加される前から Claude がデフォルトだった場合は、もう一度選択すれば拡張機能がインストールされる。

選択が済めば、`Super + Shift + Ctrl + A` で専用のターミナルウィンドウでデフォルトのエージェントが起動する（まだ選んでいなければピッカーが表示される）。`omarchy agent prompt "Review this project"` でいきなりタスクに取り掛からせることもできる。Freebuff と DeepSeek Harness は開始プロンプトを受け付けないため、代わりにプロンプトをクリップボードに入れた状態で開くので、それを貼り付ける。この方法で起動したエージェントは、それぞれの止まって聞くなモードで無人で動作する。だから本当に作業を始める覚悟をしておくこと！ MiniMax Code にはインタラクティブセッション向けのそのようなモードがないため、通常どおり権限を求める。そしてエージェントはホームディレクトリに対する信頼を覚えることを拒否するため、`$HOME` から起動した場合は代わりに `~/Work` で開始される。

ターミナルのショートカットもある。`a` は現在のターミナル内でデフォルトのエージェントをインラインで実行し、`c`、`cx`、`cy` は OpenCode、Claude Code、Codex を直接起動する（こちらも自動承認モードで）。テーマの変更もエージェントに同期される。Claude Code、Pi、OpenCode、Hermes（Omarchy がインストールした後は）はすべて、Omarchy のテーマを切り替えるとそれに追従する。

### エージェントへの指示

すべてのエージェントに対する個人的なルールは、共有スキルのある `~/.agents/skills` の隣の `~/.agents/AGENTS.md` に記述する。_Agent > Instructions_ で開ける。そこから、独自のグローバルファイルを持つ各ハーネスへもリンクされる。`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`~/.pi/agent/AGENTS.md`、`~/.config/opencode/AGENTS.md`、Copilot の `~/.copilot/copilot-instructions.md` などだ。Crush と Amp は `~/.config/AGENTS.md` リンクを読み、omp、Kimi、DeepSeek Harness は `~/.agents/AGENTS.md` を直接読む。デフォルトのエージェントを選ぶときにもリンクされる。すでに持っていた指示ファイルは、共有のものがまだなければそれが共有のものになる。そうでなければ、リンクの隣に `.bak` として残される。別のエージェントをインストールした後に再リンクするには `omarchy agent instructions` を実行する。

### エージェントパネル

トップバーにはエージェントのアイコンがある。エージェントを設定する前は、そのパネルが Claude、Codex、Grok へのサインインを順に案内し、最初に設定したものがデフォルトのエージェントになる。その後は、パネルはすべてのサブスクリプションを 1 ページにまとめる。各エージェントとアカウントとそのプラン、5 時間セッションと週次上限それぞれのメーターとリセットまでの時間（ホバーすると正確なパーセンテージが表示される）、あるいはプリペイド残高が、すべてのアカウントを通じた使用状況（今週のトークン数や最も使ったモデルなど）を順に切り替えて表示する行の下に表示される。_Make something_ の下では、新しいテーマ、プラグイン、アプリ、ゲームのためのスタータープロンプトが提供され、タスクをデフォルトのエージェントに任せる。アプリは Omarchy 自身の Hype、Monologue、Omacut と同じ方法で、C++ と Qt Quick で構築され、omarchy-make-app エージェントスキルに従い、必要なコンパイラと Qt の部品はインストール済みだ。ゲームは `~/Games/vibes` にある単一の three.js ページで、omarchy-make-game エージェントスキルに従い、すべて現在のテーマの 1 つの Game Vibes ランチャーから開く。three.js をウェブから読み込むため、起動には接続が必要だ。Claude Code、Codex、Grok、Kimi、Cursor とその Grok Bot の利用枠、GitHub Copilot、Muse、Antigravity、Kimchi、Devin は上限とともに最初から対応している。Hermes、Mistral Vibe、Qwen Code は一度使うとセッションとトークンが表示される。pi、omp、opencode 経由で使うプロバイダーのプランやキーも表示される。上限付きの OpenCode Zen と Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan、Synthetic、プリペイド残高付きの Fireworks、OpenRouter、DeepSeek、そして Local models の下で自分のハードウェアで実行するモデルだ。すべてのエージェントは、課金元ごとに 1 回だけ数えられ、いくつのハーネス経由で使っても重複しない。

バーのアイコンを左クリックするとパネルが開き、右クリックするとデフォルトのエージェントが起動する。その裏側の使用記録は `omarchy agent usage-update` によって 15 分ごとに再生成され、パネルは同期されたフォルダ経由で他のマシンからの使用状況を統合することもできる。設定の全容については `$OMARCHY_PATH/shell/plugins/agents/` にある README を参照。

### 複数のサブスクリプション

Claude、Codex、Grok のプランを複数契約している場合 ― たとえば個人の Max と仕事用など ― Omarchy はすべてをサインイン状態に保ち、それらを切り替えることができる。サブスクリプションを追加するには、エージェントパネルの + を使う。その場で手順を案内してくれる。あるいは `omarchy agent account add claude Work`（または `codex`、または `grok`）を実行する。CLI がなければインストールされる。プロバイダーの最初のアカウントは通常のブラウザ経由でサインインする。CLI が常に参照する場所だ。それ以降のアカウントはすべてプライベートウィンドウ経由でサインインする。ブラウザですでにサインインしているアカウントを誤って拾わないためだ。そこでは追加しようとしているアカウントとしてサインインし、あらかじめ開いているプライベートウィンドウは先に閉じておくこと。これを行うために CLI からログアウトしては決してならない。ログアウトすると保存されたサインインが取り消され、そのアカウントを再度追加しなければならなくなる。

サブスクリプションのログインを SSH 経由で別の Omarchy マシンにコピーするには `omarchy agent account copy user@laptop` を実行する。宛先にレシーバーがインストールされていない場合、送信側が一時的なレシーバーを提供するため、古い Omarchy マシンでも更新なしでアカウントを受け取れる。インストール済みのレシーバーが優先される。これにより Claude、Codex、Grok のすべてのサブスクリプションがコピーされる。プロバイダー名を追加して選択することもできる。たとえば `omarchy agent account copy laptop claude` だ。アカウント名とコマンド ID は送信元と一致し、宛先にすでに存在するアカウントも含む。関係のない宛先アカウントで名前が競合した場合は数字のサフィックスが付く。設定、スキル、プラグイン、会話履歴は各マシンにローカルなままとなる。

宛先に既存の認証情報は保持される。すでにそこでサインインしている送信元アカウントは、認証情報を置き換えることなく名前だけが同期される。他のアカウントはそれに並べて追加される。一致するアカウントの保存済み認証情報を置き換えるには、宛先でそのアカウントのセッションを終了した後、`omarchy agent account copy --replace laptop claude` を使う。新規の宛先には送信元のアクティブなアカウントと切り替え設定も引き継がれる。すでに使われている宛先は自身の設定を保持する。

認証情報は SSH 経由で送信され、宛先のプライベートファイルに保存されるため、信頼できるマシンにだけコピーすること。これは 1 回限りのコピーであり、継続的な同期ではない。Codex のリフレッシュトークンは別のマシンでローテーションされることがあり、コピーしたログインは更新が必要になる場合がある。複数のマシンで同時に使うには、個別にサインインするのが最も確実な方法であることに変わりはない。[Codex のアカウント認証ガイダンス](https://developers.openai.com/codex/auth/ci-cd-auth) を参照。

プロバイダーごとにアクティブなアカウントは 1 つで、新しいセッションはすべてそれとして開始される。`cx`、`cy`、プレーンな `claude`、`codex`、`grok`、`omarchy agent` 経由で起動するもの、`PATH` 上で CLI を見つけるスクリプトやエディタが対象だ。切り替えは `omarchy agent account use work`（戻すときは `omarchy agent account use main`）で行うか、パネルでアカウントの番号を押して `Enter` を押す（またはその Use ボタンをクリックする）。実行中の Claude セッションも次のメッセージから切り替わる。すべての Claude セッションは `~/.claude` で動作し、そこには常にアクティブなアカウントのサインインが入っている。古い Omarchy でアカウント専用フォルダから開始された Claude セッションは、終了するまでそのサインインを保持する。そのため切り替え時にはそれらのセッション名を表示し、それらが終了すれば自動で完了する。実行中の Codex と Grok のセッションは開始時のアカウントのままとなる。会話履歴、設定、スキル、プラグインはアカウント間で共有されるため、同じフォルダで `claude --continue` を使えば新しいアカウントで前回の続きから再開できる。

アカウントが複数ある場合、パネルは各アカウントの上限を横並びで表示し、アクティブなものに印を付ける。デフォルトでは、アクティブなアカウントが上限の 95% を超えると Omarchy が通知し、その通知をクリックすると余裕が最も大きいアカウントに切り替わる。自動で切り替えさせたい場合は、パネルでアカウントの行にホバーして Use の横に表示される Autoswitch をクリックする（または `m` を押す）か、`omarchy agent account mode auto` を実行する。有効な間は Autoswitch が Use の場所を占め、もう一度クリックすると通知に戻る。しきい値を変更するには `omarchy agent account mode auto 90` のように数値を追加する。すべてのアカウントがしきい値を超えた場合は、どのアカウントが最初に空くかとともに 1 回だけ通知される。アクティブなアカウントがしきい値まで 15 ポイント以内（デフォルトでは 80%）にある間は、上限は 15 分ごとではなく 3 分ごとに確認される。

`omarchy agent account list` はすべてのアカウントと最新の上限を表示し、`omarchy agent account remove work` は 1 つを削除し、`omarchy agent account rename primary Hey` は名前を変更する（またはパネルでアカウント名をクリックする）。これらのコマンドはデフォルトのエージェントのアカウントに対して動作する。別のプロバイダーを対象にするには、まずそれを名前に含める。たとえば `omarchy agent account use codex side` だ。`~/.claude` や `~/.codex` にすでにあったログインは _Main_ アカウントだ。Codex のものはその場に留まり、Claude のものは別のアカウントがアクティブな間、専用フォルダで待機する。約 8 時間以上使われなかったアカウントは _Sign-in required_ と表示されることがある。それをクリックするとパネルでそのアカウントに再サインインできる。あるいはそのアカウントに切り替えてセッションを開始すれば、サインインは自動で更新される。`claude mcp add` で追加した MCP サーバーはすべての Claude アカウントに届く。すべて `~/.claude` で動作するためだ。Codex と Grok では、アカウント追加時に持っていたサーバーはそのアカウントにも引き継がれるが、後から追加したものは追加したアカウントにしか届かない。Claude Desktop は独自のサインインを保持し、CLI バイナリへの絶対パスで設定された Codex や Grok のツールは切り替えに追従しない。明示的な `CLAUDE_CONFIG_DIR`、`CODEX_HOME`、`GROK_HOME` は選択したアカウントより優先される。

### クラッシュ診断

Omarchy はプロセスのクラッシュを systemd-coredump で監視している。何かがセグメンテーション違反を起こすと「Process crashed」通知が届く。それをクリックすると、クラッシュは Omarchy の diagnose-crash スキルとともにデフォルトのエージェントに渡される。そのスキルは、コアダンプから事実を確定し、そのクラッシュがアップストリームに報告する価値があるかどうかを判断する手順をエージェントに案内する。`coredumpctl list` で得た任意の PID に対して `omarchy agent crash <pid>` で手動で実行することもできる。

この監視はデフォルトでオンだ。_Trigger > Toggle > Crash Capture_ でオフにする（または `omarchy toggle crash-capture`）と通知が止まる。`omarchy agent crash <pid>` は引き続き手動で使える。

クラッシュはプログラム単位で黙らせることもでき、診断の最後にその選択肢が提示される。`omarchy crash mute hyprland` はそのプログラムの通知だけを止め、`omarchy crash mute hyprland off` で元に戻り、`omarchy crash mute` を単独で実行するとミュートしたものの一覧を表示する。バイナリのパスでも名前でも問題なく使えるので、`omarchy crash mute /usr/bin/hyprland` でも同じだ。スペースを含む名前は `omarchy crash mute 'Some App'` のように引用符で囲む。それ以外は引き続き通知され、ミュートしたプログラムもクラッシュはする。これはリマインダーを隠すだけで、何も直してはいない。

### デスクトップアプリ

_Install > AI_ メニューにはグラフィカルな AI アプリもいくつかある。ChatGPT デスクトップアプリ、Claude デスクトップアプリ（Chat、Cowork、Claude Code タブを備えた Anthropic の Linux ベータ）、xAI のモデルとチャットするための Grok Bot、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexity デスクトップアプリ、T3 Code だ。Grok Bot はデスクトップチャットアプリだ。コーディングエージェントは `grok` コマンドだ。

Hermes Desktop は知っておくべき存在だ。1 台のマシンには Hermes は 1 つしかなく、それはアプリのものだからだ。Hermes はアプリ経由でだけインストールされ、デフォルトのエージェントが実行する `hermes` コマンドはアプリのものだ。Hermes をデフォルトのエージェントに選ぶと、_Install > AI_ の項目と同じものがインストールされる。パッケージと、Hermes 自身のインストーラーによって `~/.hermes` の下にセットアップされる Hermes ランタイムだ。初回は数分かかる。そのランタイムは、ターミナルの `hermes` コマンド、デフォルトのエージェント、アプリのすべてが使う唯一の Hermes であり、Omarchy のリリースを待たずに `hermes update` で自身を更新する。インストールすると、Hermes には Omarchy テーマが `omarchy` という名前のスキンとして渡され、テーマを切り替えるとすべての Hermes の画面がそれに追従する。そうしたくない場合は Hermes の Appearance 設定か `/skin` で別のものを選べばよい。Omarchy はその選択には干渉しない。_Remove > AI_ でアプリを削除すると、まずゲートウェイを含めて Hermes を終了し、そのランタイムも一緒に削除する。チャット、メモリ、Hermes が自分のために書いたスキルは、指示しない限り残される。そのデータと接続設定も一緒に削除するかどうかを、デフォルトでいいえとして尋ねてくる。

OpenClaw のデスクトップ体験は Control UI で、独自のローカルゲートウェイをバックエンドとするウェブアプリとして開く。OpenClaw は `~/.openclaw` にあり、自身を更新する。Control UI の「Update Gateway」ボタンを使うか `openclaw update` を実行すれば、ゲートウェイは新しいバージョンで再起動する。Omarchy は新規インストールがどのリリースから始まるかだけを決める。_Remove > AI_ で OpenClaw を削除すると、ゲートウェイサービスとアプリが一緒に削除され、その後 `~/.openclaw` も削除するかどうか尋ねる。そこには OpenClaw 自体やダウンロードするプラグインランタイムとともにチャットや認証情報が入っているからだ。デフォルトは残す設定で、OpenClaw を再インストールすれば再びそれを使う。

Herdr Desktop は [Herdr](https://herdr.dev) デスクトップアプリだ。スペース、タブ、ターミナルとコーディングエージェントのペインを備え、ウィンドウを閉じてもそのコアで実行が続く。パッケージではなく Herdr 自身のインストーラーから導入されるため、`~/.local/share/herdr-app` に置かれ、まだコアがない場合は `~/.local/bin/herdr-core` にコアも一緒に持ち込み、両方を自身で更新する。これは、Omarchy が `Super + Ctrl + Return` で提供する `herdr` コマンドを置き換えるのではなく、それと並んで存在し、そのコマンドの直接キーを引き継ぐ。`Alt + Return` と `Alt + Shift + Return` でペインを下または右に分割し、`Alt + Escape` で閉じ、`Ctrl + Alt + Arrow` でペイン間を移動し、`Alt + 1..9` と `Alt + Left/Right` でタブを選び、`Alt + Up/Down` でスペース間を移動する。`Ctrl + 1..9` でスペースを選び、`Alt + Shift + Up/Down` でエージェントを順に切り替える。`Ctrl + Space` プレフィックスキーはターミナル専用のままとなる。アプリはシーケンスのためだけに単なる Ctrl キーを保持できないからだ。Omarchy はこれらを `~/.config/herdr-app/keys.json` に書き込み、`omarchy-refresh-herdr-app` で元に戻す。インストールすると Herdr の Omarchy テーマが選択され、以降は Omarchy テーマに追従する。Herdr はライトモード用とダークモード用にそれぞれ 1 つのテーマを保持するため、ダークな Omarchy テーマとライトな Omarchy テーマを切り替えた後は、もう一方のモードのために Herdr のテーマピッカーで Omarchy をもう一度選択すること。

T3 Code はパッケージではなく `~/.local/share/t3code` にある公式 AppImage リリースから動作するため、自身を更新する。インストール時に Stable チャネルで始めるか Nightly チャネルで始めるかを尋ねる。後から T3 Code の設定で切り替えられる。スレッドと設定は `~/.t3` にあり、_Remove > AI_ で T3 Code を削除するとそれらも一緒に削除される。

### ローカルモデル

コーディングエージェントのために、自分のマシンでオープンモデルを実行する。プロンプトとコードはマシンに残り、モデルに送ったものが外に出ることはない。まずは次から始める。

```bash
omarchy agent local use best
```

あるいは、トップバーのエージェントパネルで + を選んでから Local AI を選ぶ。モデルがこのマシンに適合する場合に表示される。初めてのときは、モデルを実行する Podman がインストールされ、NVIDIA マシンではモデルに GPU を使わせる NVIDIA のコンテナツールキットもインストールされる。その後 Omarchy はこのマシンに推奨されるモデルを選び、ダウンロードして起動する。ダウンロードは数十 GB に及ぶこと、モデル実行中はマシンのメモリの大半が使われることを想定しておくこと。Flash Next はフル 256K コンテキストで約 100 GiB を使う。必要なメモリを他のモデルが占有している場合は、停止した状態でセットアップされ、そのうち 1 つを止めればすぐに起動できる状態になる。モデルはログアウト時に停止する。他の用途でメモリが必要なときは自分で停止すること。

`omarchy agent local list` は選択肢を表示し、一部が適合しない理由を説明する。別のものをセットアップするには `omarchy agent local use <recipe>` を実行する。現在は、128 GB の Strix Halo マシン向けに `qwen3.8-flash-next-gufo` と `qwen3.8-27b-gufo` が利用できる。27B は約 40 GiB を使うため、他の作業用の余地が残る。Intel の Arc B390 を搭載した 64 GB ノート PC では、`qwen3.6-35b-a3b-llamacpp` が約 30 GiB で動作する。新しいレシピと推奨はパッケージ経由で `omarchy update` とともに提供される。

セットアップしたモデルごとに、サブスクリプションの隣にエージェントパネルで専用の行が与えられる。再生ボタンで起動し、一時停止ボタンで停止してメモリを解放し、ターミナルボタンでそのモデル上でエージェントを開く。メモリに収まれば複数を同時に実行できる。収まらない場合は、Omarchy がどの実行中モデルを止めるべきかを知らせる。行をドラッグして並べ替えでき、選択した行で Delete を押すとモデルとそのダウンロードが削除される。

セットアップしたモデルはすべて、アプリランチャーにも専用のエントリを持つ。モデル名とその開発元のロゴ付きで、Claude、Codex、Grok にサインインしたときにエントリが追加されるのと同様だ。それを開くとそのモデル上でエージェントが開き、モデルが実行されていなければ先にモデルを起動する。ターミナルに読み込み中であることが表示され、起動が完了するとエージェントに引き継がれる。モデルを削除するとそのエントリも削除される。

モデルはセットアップされたままの状態で動作し続けるため、Omarchy の更新でエージェントの下でモデルが再起動することは決してない。セットアップ済みモデル向けに Omarchy がより新しいランタイムやより新しいウェイトを持つようになると、その行に更新ボタンが表示される。それを押すとモデルはバックグラウンドで再セットアップされ、変更された部分だけをダウンロードし、新しいバージョンで再起動する。停止していたモデルは停止したままとなる。`omarchy agent local update` はターミナルからすべてのモデルに対して同じことをする。

コマンドラインからは、`omarchy agent local start <recipe>` と `omarchy agent local stop <recipe>` が同じことを行い、`omarchy agent local status` はすべてのモデルを表示し、`omarchy agent --local` は最後に起動したモデル上でデフォルトのエージェントを開く。pi、OpenCode、Qwen Code がそれを利用でき、それ以外のデフォルトの場合は pi で開く。pi は自身のモデルピッカーに、セットアップしたすべてのモデルと、ペアリングしたマシン上のモデルも一覧表示するため、プレーンな `pi` からもそれらにアクセスできる。OpenAI 互換のあらゆるクライアントも接続できる。`status` は各モデルのアドレスを表示し（最初のものは `http://127.0.0.1:11435/v1`）、レシピ名がモデルとなり、キーは `~/.config/omarchy/agent-local/key` にある。

`omarchy agent local remove <recipe>` はモデルと、他のモデルが使っていないダウンロードを削除する。

サードパーティのランタイムにはその発行元が表示される。Omarchy はすべてのモデルをネットワークアクセスなしで実行する。

### ローカル LLM

Omarchy はローカル LLM モデルを実行する方法として、LM Studio と Ollama の 2 つを推奨している。LM Studio はオープンウェイトモデルを探し、インストールし、実行するための GUI インターフェースを提供する。手軽に始めるのに最適な方法だ。Ollama は同様のことを行う CLI を提供する。だがローカルモデルが初めてなら、私なら LM Studio から始める。どちらも Omarchy Menu の _Install > AI_ からインストールできる。

### Omarchy Skill

エージェントスキルは AI が特定のツールを特定の方法で使うのを助けるもので、Omarchy にはシステムをカスタマイズするためのデフォルトスキルが同梱されている。Hyprland の設定を微調整したり、バーを調整したり、テーマを一から新しく作ったりするようなことだ。これは Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` と各 `~/.hermes/profiles/*/skills`）、そして汎用の `~/.agents/skills` の場所のスキルディレクトリにシンボリックリンクされているため、ほとんどのハーネスが自動的に拾う。

だがこのスキルは実験的なものと考えるべきだ。モデルによって効果の現れ方は異なる。まずはプランモードで実行するのが最善だ。そうすればエージェントが何を変更したいのか把握できる。そして、エージェントがすべてをめちゃくちゃにした場合は、変更をロールバックしたり、`omarchy reinstall configs` を実行したりする覚悟をしておくこと。
