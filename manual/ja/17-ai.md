### エージェントのインストールと更新

HermesとOpenClawを除き、これらのエージェントはmiseの遅延インストールを使います：初回起動時にCLIがインストールされ、それ以降の起動ではそれが再利用されます。miseはまた、インストール済みのエージェントに新しいリリースがないか、最大で4時間に1回、起動直前か、シェルプロンプトでバックグラウンドで確認します。その更新が失敗したり、オフラインだったりした場合、インストール済みのバージョンが実行されます。`omarchy update`は、Omarchyの他の部分と一緒にインストール済みのエージェントも更新し、`mup`はmise管理のツールだけを更新します。

`claude update`、`codex update`、アプリ内の更新ボタンなど、エージェント自身のアップデーターは、mise管理のインストールを更新しません。`codex update`は失敗し、`claude update`は成功したと報告しながら、miseが追跡しない別コピーをインストールすることがあります。エージェントのネイティブなインストーラーとアップデーターを使いたい場合は、それを`disable_tools`に追加してください；[Preinstalled CLI tools](18-development-tools.md#preinstalled-cli-tools)を参照してください。

設定されたすべての遅延ツールを必要になる前にインストールするには、`mise install --include-lazy`を実行します。これには、エージェントだけでなく、Omarchyの他のデフォルトCLIツールも含まれます。単一のツールをインストールしたり、独自のインストールを使ったりする方法については、[Preinstalled CLI tools](18-development-tools.md#preinstalled-cli-tools)を参照してください。

`grok`は、miseのファーストパーティ`grok`パッケージ経由で、`claude`や`codex`と同じ方法でインストールされます。`grok`を実行するか、_Agent > Harness_で選択してください。x.aiの`curl | bash`インストーラーは避けてください。その方法では`~/.grok/bin`に2つ目のコピーが配置され、それが`PATH`の先頭に追加され、Omarchyのラッパーが上書きされます。

`dsh`はブラウザUIを`127.0.0.1:3080`で開き、起動したディレクトリをデフォルトのワークスペースとします。そのブラウザUIは開始プロンプトを受け付けないので、`omarchy agent prompt`は、クリップボードにプロンプトを入れた状態でそれを開き、貼り付けられるようにします。Omarchyは、DeepSeekの承認不要の権限プリセットでこれを起動します。DeepSeek Harnessは、公式のモデルAPIを使うと、セッションログをDeepSeekにアップロードします；そのブラウザUIの_Settings > General > Upload Session Log_でオフにしてください。送信するフィードバックもセッションと一緒にアップロードされます。ただし、`DSH_TELEMETRY_MODE=DISABLED`で起動した場合は除きます。

### デフォルトのエージェント

デフォルトのエージェントは、`omarchy default agent <name>`で、またはOmarchy Menu（`Super + Space`）の_Agent > Harness_で選択します。そのエージェントがまだインストールされていない場合、選択するとまずインストールされ、アプリランチャー内でAgentの隣に専用のランチャーも得ます。新しくインストールしたOmarchyでは、この選択を促す一度きりの通知が表示されます。

Claudeを選択すると、Chromium、Chrome、Brave、Brave Origin、Edge向けに、そのブラウザ拡張機能のセットアップも試みます。拡張機能のセットアップはすべてのユーザーに適用され、システムパスワードを求められる場合があります；キャンセルしたり、拡張機能のインストールに失敗したりしても、Claudeは選択されて起動します。ブラウザを再起動し、求められたら拡張機能を有効にし、Claudeにサインインして接続を完了してください。Claudeで`/chrome`を実行して接続を確認してください。FirefoxとZenはこの拡張機能をサポートしていません。このセットアップが追加される前にClaudeがすでにデフォルトだった場合は、それを再選択して拡張機能をインストールしてください。

選択が終わると、`Super + Shift + Ctrl + A`でデフォルトのエージェントが専用のターミナルウィンドウで起動します（まだ選択していない場合はピッカーが表示されます）。`omarchy agent prompt "Review this project"`で、タスクを直接指定して起動することもできます。FreebuffとDeepSeek Harnessは開始プロンプトを受け付けないので、代わりにクリップボードにプロンプトを入れた状態で開き、貼り付けられるようにします。この方法で起動されたエージェントは、各々の「立ち止まって確認しない」モードで無人で実行されます。ですから、本当に処理を実行する覚悟をしてください！MiniMax Codeにはインタラクティブセッション向けのそのようなモードがないので、通常どおり権限を求めます。また、エージェントはホームディレクトリへの信頼を覚えることを拒否するため、`$HOME`からの起動は代わりに`~/Work`で開始されます。

ターミナル用ショートカットもあります：`a`は現在のターミナル内でデフォルトのエージェントをインラインで実行し、`c`、`cx`、`cy`はOpenCode、Claude Code、Codexを直接起動します（これも自動承認モードです）。テーマの変更もエージェントに同期されます：Claude Code、Pi、OpenCode、Hermes（Omarchyがインストール済みの場合）はすべて、Omarchyのテーマを切り替えたときに追随します。

### あなたのエージェント指示

すべてのエージェントに共通する個人的なルールは、`~/.agents/skills`にある共有スキルと並んで、`~/.agents/AGENTS.md`に入れます。これを_Agent > Instructions_で開くと、それを、`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`~/.pi/agent/AGENTS.md`、`~/.config/opencode/AGENTS.md`、Copilotの`~/.copilot/copilot-instructions.md`など、独自のグローバルファイルを持つ各ハーネスにもリンクします。CrushとAmpは`~/.config/AGENTS.md`リンクを読み、omp、Kimi、DeepSeek Harnessは`~/.agents/AGENTS.md`を直接読み取ります。デフォルトのエージェントを選択すると、それにもリンクされます。すでに持っていた指示ファイルは、まだ共通のものがなければ共通のものになり；そうでなければ、リンクの隣に`.bak`として保持されます。別のエージェントをインストールした後に再リンクするには、`omarchy agent instructions`を実行してください。

### エージェントパネル

トップバーにはエージェントアイコンがあります。エージェントをまだセットアップしていない場合、そのパネルではClaude、Codex、またはGrokへのサインインを順を追って案内し、最初のものがデフォルトのエージェントになります。その後は、パネルはすべてのサブスクリプションを1ページにまとめます：各エージェントとアカウントとそのプラン、各々の5時間セッション制限と週間制限に対するメーターとリセットまでの時間（ホバーすると正確なパーセンテージが表示されます）、あるいはプリペイド残高の表示。画面上部には、「今週のトークン」や「最もよく使ったモデル」など、すべてにわたって使った内容を循環して表示する行があります。_Make something cool_の下では、新しいテーマ、プラグイン、アプリ、またはゲームのスタータープロンプトが提供され、タスクをデフォルトのエージェントに引き渡します。アプリは、Omarchy自身のHype、Monologue、Omacutと同じ方法で、C++とQt Quickで構築され、omarchy-make-appエージェントスキルに従い、それらに必要なコンパイラとQtコンポーネントはインストール済みです。ゲームは`~/Games/vibes`にある単一のthree.jsページで、omarchy-make-gameエージェントスキルに従い、すべて現在のテーマの1つのGame Vibesランチャーから開きます；これらはthree.jsをウェブから読み込むので、起動には接続が必要です。Claude Code、Codex、Grok、Kimi、CursorとそのGrok Bot枠、GitHub Copilot、Muse、Antigravity、Devinは、制限付きで標準でカバーされ、Kimchiはそのプラン、プリペイドクレジット、支出予算で、Hermes、Mistral Vibe、Qwen Codeは一度使うとセッションとトークンを表示します。pi、omp、opencode経由で使うプロバイダーのプランと鍵も表示されます：OpenCode ZenとGo、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan、Syntheticが制限付きで；OpenRouterとDeepSeekがプリペイド残高で；Fireworksが過去30日間の支出で表示されます。自身のハードウェアで実行するモデルのトークンも合計に算入されます；モデル自体には独自のパネルがあり、[Local models](#local-models)で説明されています。すべてのエージェントは、その請求元のもとで一度だけ数えられ、どのハーネスを通じて使っても同じです。

バーのアイコンを左クリックするか、`Super + Ctrl + X`を押すとパネルが開き、右クリックするとデフォルトのエージェントが起動し、中央クリックすると更新されます。その背後にある使用記録は、`omarchy agent usage update`によって15分ごとに再生成され、パネルは同期されたフォルダ経由であなたの他のマシンの利用状況もマージできます。すべての設定については、`$OMARCHY_PATH/shell/plugins/agents/`にあるREADMEを参照してください。

### 複数のサブスクリプション

Claude、Codex、またはGrokのプランを複数支払っている場合、例えば個人のMaxと仕事用の一つなど、Omarchyはすべてをサインイン状態のまま保持して、それらを切り替えることができます。エージェントパネルの+でサブスクリプションを追加すると、そこで手順を案内します。または`omarchy agent account add claude Work`（または`codex`、または`grok`）で追加できます。CLIがなければインストールします。プロバイダーごとに最初のアカウントは、CLIが常に見ている場所で、あなたの通常のブラウザからサインインします。それ以降のすべてのアカウントはプライベートウィンドウからサインインします。そうすることで、ブラウザで既にサインインしているアカウントを誤って拾うことがありません；そこでは追加しようとしているアカウントでサインインし、あらかじめ既に開いているプライベートウィンドウは閉じてください。このためにCLIからログアウトしてはいけません：ログアウトすると保存済みのサインインが取り消され、そのアカウントを再度追加しなければならなくなります。

サブスクリプションのログインをSSH経由で別のOmarchyマシンにコピーするには、`omarchy agent account copy user@laptop`を実行します。送信側は、宛先に受信側がインストールされていない場合に一時的な受信側を提供するため、古いOmarchyマシンも更新なしにアカウントを受け取ることができます。インストール済みの受信側が優先されます。これはClaude、Codex、Grokのすべてのサブスクリプションをコピーします；選択するにはプロバイダー名を追加してください。例：`omarchy agent account copy laptop claude`。アカウント名とコマンドIDは送信元と一致し、宛先にすでに存在するアカウントも含みます。関係ない宛先アカウントは名前が競合した場合に数字のサフィックスを受け取り、設定、スキル、プラグイン、会話履歴はマシンごとにローカルなまま残ります。

宛先の既存の認証情報は保持されます。送信元アカウントがそこで既にサインインしている場合、その名前は認証情報を置き換えることなく同期されます；他のアカウントはその隣に追加されます。一致するアカウントの保存済み認証情報を置き換えるには、宛先でそのアカウントのセッションを終了した後、`omarchy agent account copy --replace laptop claude`を使ってください。新規の宛先には、送信元のアクティブなアカウントと切り替え設定も引き渡されます；確立済みの宛先は自身の設定を保持します。

認証情報はSSH経由で移動し、宛先のプライベートファイルに保存されるので、信頼できるマシンにのみコピーしてください。これは一度きりのコピーであり、継続的な同期ではありません。Codexのリフレッシュトークンは別のマシンによってローテーションされる場合があり、コピーしたログインは更新が必要になります；複数のマシンで同時に使用するには、個別のサインインが最も信頼できる選択肢です。[Codexのアカウント認証ガイダンス](https://developers.openai.com/codex/auth/ci-cd-auth)を参照してください。

プロバイダーごとにアクティブなのは1つのアカウントで、すべての新しいセッションはそのアカウントから始まります：`cx`、`cy`、素の`claude`、`codex`、または`grok`、`omarchy agent`経由で起動されるすべてのもの、そして`PATH`上でCLIを見つけるスクリプトやエディタが該当します。切り替えは`omarchy agent account use work`（戻るには`omarchy agent account use main`）で、またはパネルでアカウントの番号を押してから`Enter`を押して（またはそのUseボタンをクリックして）行います。実行中のClaudeセッションも、次回のメッセージから切り替わります：すべてのClaudeセッションは`~/.claude`で実行され、そこには常にアクティブなアカウントのサインインがあります。古いOmarchyでアカウント独自のフォルダで開始されたClaudeセッションは、終了するまでそのサインインを保持します。そのため切り替えではそれらのセッション名を表示し、それらがなくなると自動で完了します。実行中のCodexとGrokセッションは、開始したアカウントのまま残ります。会話履歴、設定、スキル、プラグインはアカウント間で共有されるので、同じフォルダで`claude --continue`を実行すると、新しいアカウントで中断した場所から再開できます。

複数のアカウントがある場合、パネルは各アカウントの制限を横並びに表示し、アクティブなものをマークします。デフォルトでは、アクティブなアカウントが制限の95%を超えるとOmarchyから通知があり、通知をクリックすると余裕が最も大きいアカウントに切り替わります。パネルでアカウントの行にホバーして、Useの横に表示されるAutoswitchをクリックする（または`m`を押す）か、`omarchy agent account mode auto`を実行すると、自動で切り替えさせることができます；これがオンの間は、AutoswitchがUseの位置を取って代わり、それをもう一度クリックすると通知に戻ります。閾値を変更するには、数字を追加してください。例：`omarchy agent account mode auto 90`。すべてのアカウントが閾値を超えている場合、そのことが一度だけ知らされ、どのアカウントが最初に空くかも示されます。アクティブなアカウントが閾値から15ポイント以内にある間（デフォルトでは80%）、その制限は15分ごとではなく3分ごとにチェックされます。

`omarchy agent account list`はすべてのアカウントとその最新の制限を表示し、`omarchy agent account remove work`は1つを忘れ、`omarchy agent account rename primary Hey`は1つの名前を変更します（またはパネルでアカウントの名前をクリックします）。これらのコマンドは、ご利用のデフォルトのエージェントのアカウントに対して動作します；他のプロバイダーにアクセスするには、最初にその名前を指定してください。例：`omarchy agent account use codex side`。`~/.claude`や`~/.codex`にすでに持っていたログインが_Main_アカウントです。Codexのログインはそのままの場所に残ります；Claudeのログインは、別のアカウントがアクティブな間、自身のフォルダに待機します。約8時間以上使われていないアカウントは_Sign-in required_と表示される場合があります；クリックするとパネルですぐにそのアカウントで再度サインインできます。またはそれに切り替えてセッションを開始すると、サインインは自動で更新されます。`claude mcp add`で追加したMCPサーバーは、すべてのClaudeアカウントに届きます。なぜなら、それらはすべて`~/.claude`で実行されるからです；CodexとGrokでは、アカウントが追加されたときに持っていたサーバーはそれに引き継がれますが、それ以降のものは追加したアカウントにのみ届きます。Claude Desktopは独自のサインインを保持し、CLIバイナリへの絶対パスで設定されたCodexやGrokのツールは切り替えに追随しません。明示的な`CLAUDE_CONFIG_DIR`、`CODEX_HOME`、または`GROK_HOME`は、選択したアカウントに対して優先されます。

### クラッシュ診断

Omarchyは、プロセスのクラッシュについてsystemd-coredumpを監視します。デフォルトのエージェントを選ぶと、コアをダンプしたあなたのプログラムは「Process crashed」通知を表示します — それをクリックすると、クラッシュがデフォルトのエージェントに引き渡され、Omarchyのomarchy-diagnose-crashスキルもあわせて渡されます。そのスキルは、コアダンプから事実を確立し、クラッシュを上流に報告する価値があるかどうかを判断する手順をエージェントに案内します。`omarchy agent crash <pid>`で、`coredumpctl list`の任意のPIDに対して手動で実行することもできます。

監視はデフォルトでオンです。_Trigger > Toggle > Crash Capture Off_で（または`omarchy toggle crash-capture`で）オフにすると通知は止まります；`omarchy agent crash <pid>`は手動では引き続き機能します。

クラッシュはプログラムごとに黙らせることもでき、それが診断の最後に提示される選択肢です。`omarchy crash mute hyprland`はそのプログラムだけの通知を止め、`omarchy crash mute hyprland off`で元に戻り、`omarchy crash mute`を単独で実行するとミュートしたものが一覧表示されます。名前と同じくらい気軽にバイナリのパスも受け付けるので、`omarchy crash mute /usr/bin/hyprland`でも同じことができます。空白を含む名前は引用してください。例：`omarchy crash mute 'Some App'`。それ以外のすべては引き続き通知され、ミュートしたプログラムは引き続きクラッシュします — これはリマインダーを隠すもので、何かを修正するものではありません。

### デスクトップアプリ

_Install > AI_メニューには、いくつかのグラフィカルなAIアプリも含まれています：Amp Desktop、Antigravity Desktop、ChatGPTデスクトップアプリ、Claudeデスクトップアプリ（Chat、Cowork、Claude Codeタブを備えたAnthropicのLinuxベータ）、xAIのモデルとチャットするGrok Bot、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexityデスクトップアプリ、T3 Codeです。Grok Botはデスクトップチャットアプリです。コーディングエージェントは`grok`コマンドです。

Hermes Desktopは知っておくべきものです。なぜなら、1台のマシンにHermesは1つしかなく、それはそのアプリのものだからです：Hermesはアプリ経由でしかインストールされることがなく、デフォルトのエージェントが実行する`hermes`コマンドは、そのアプリのものです。Hermesをデフォルトのエージェントに選ぶと、_Install > AI_エントリと同じものをインストールします：パッケージと、Hermes自身のインストーラーによってセットアップされる`~/.hermes`配下のHermesランタイムです。初回は数分かかります。そのランタイムこそが、ターミナルの`hermes`コマンド、デフォルトのエージェント、アプリのすべてが使う唯一のHermesであり、Omarchyのリリースを待つのではなく、`hermes update`で自己更新します。インストールすると、HermesにOmarchyテーマを`omarchy`という名のスキンとして渡し、テーマを切り替えるとHermesのすべての画面がそれに追随します；そうならない方がよければ、HermesのAppearance設定、または`/skin`で別のものを選択してください。Omarchyはその選択には干渉しません。_Remove > AI_でアプリを削除すると、まずゲートウェイを含むHermesを閉じ、そのランタイムを持ち去り、そう指示しない限り、あなたのチャット、メモリ、Hermesが自身のために書いたスキルは保持します：そのデータと接続設定も一緒に消すべきかどうかをデフォルト「いいえ」で尋ねます。

OpenClawのデスクトップ体験はそのControl UIであり、独自のローカルゲートウェイをバックエンドとするウェブアプリとして開きます。OpenClawは`~/.openclaw`に存在し、自己更新します：Control UIの「Update Gateway」ボタンを使うか、`openclaw update`を実行すると、ゲートウェイは新しいバージョンで再起動します。Omarchyが選ぶのは、新規インストールが開始するリリースだけです。OpenClawをデフォルトのエージェントにすることもできます：_Agent > Harness_でそれを選ぶと、`~/.openclaw`に同じコピーがセットアップされ、エージェントはそのゲートウェイに接続されたOpenClawのターミナルUIを開きます。_Remove > AI_でOpenClawを削除すると、ゲートウェイサービスとアプリを持ち去り、続いて`~/.openclaw`も削除すべきか尋ねます。そこにはOpenClaw自体とそれがダウンロードするプラグインランタイムと並んで、あなたのチャットと認証情報があるからです；デフォルトでは保持され、OpenClawを再インストールするとそれを再び取り込みます。

Herdr Desktopは[Herdr](https://herdr.dev)のデスクトップアプリです：ウィンドウを閉じてもそのコアで実行され続けるターミナルとコーディングエージェントのスペース、タブ、ペインです。パッケージではなくHerdr自身のインストーラーから提供されるため、`~/.local/share/herdr-app`に存在し、まだ持っていない場合、`~/.local/bin/herdr-core`にコアを持ち込み、その両方を自己更新します。これはOmarchyが`Super + Ctrl + Return`で提供する`herdr`コマンドを置き換えるのではなく、それと並んで存在し、そのコマンドのダイレクトキーを引き継ぎます：`Alt + Return`と`Alt + Shift + Return`はペインを下または右へ分割し、`Alt + Escape`はそれを閉じ、`Ctrl + Alt + Arrow`はペイン間を移動し、`Alt + 1..9`と`Alt + Left/Right`はタブを選択し、`Alt + Up/Down`はスペース間を移動します。`Ctrl + 1..9`はスペースを選択し、`Alt + Shift + Up/Down`はエージェント間を順に移動します。`Ctrl + Space`プレフィックスキーはターミナル専用のままです。アプリはシーケンスのためだけに素のCtrlキーを保持できないからです。Omarchyはこれらを`~/.config/herdr-app/keys.json`に書き込み、`omarchy-refresh-herdr-app`で元に戻します。インストールすると、HerdrのOmarchyテーマが選ばれ、それ以降はあなたのOmarchyテーマに追随します。Herdrはライトモード用に1つのテーマ、ダークモード用にもう1つのテーマを保持するため、ダークなOmarchyテーマとライトなOmarchyテーマを切り替えた後は、HerdrのテーマピッカーでOmarchyをもう一度、もう一方のモードに対して選んでください。

T3 Codeは、パッケージではなく`~/.local/share/t3code`にある公式のAppImageリリースから実行されるので、自己更新します。インストール時に、Stableチャネルで開始するかNightlyチャネルで開始するか尋ねられます；後でT3 Codeの設定で切り替えてください。あなたのスレッドと設定は`~/.t3`に存在し、_Remove > AI_でT3 Codeを削除するとそれらも一緒に削除されます。

### ローカルモデル

あなた自身のマシン上でオープンモデルをコーディングエージェント向けに実行します。あなたのプロンプトとコードはマシン上に留まります；モデルに送られたものは何もマシンから出ていきません。次から始めてください：

```bash
omarchy models use best text
```

これにより、このマシンに最適なテキストモデルがセットアップされます。あなたのエージェントが使うタイプです。画像、動画、音楽モデルにもそれぞれ最適なものがあります：`omarchy models use best image`、`video`、または`music`です。このマシンに対する各タイプの選出を見るには、`omarchy models use best`を実行してください。

または、トップバーでエージェントアイコンの隣にあるキラキラのアイコンから、あるいはSuper + Ctrl + Alt + Xでローカルモデルパネルを開き、+を選択します。このアイコンは、モデルがこのマシンに適合するときに現れます。モデルを実行するPodmanはOmarchyに付属し、NVIDIAマシンではNVIDIAのコンテナツールキットも付属します。これによりGPUが使えます；どちらかが欠けている場合、最初のセットアップでインストールされます。次にOmarchyはこのマシンに推奨されるモデルを選び、ダウンロードして起動します。数十GBのダウンロードと、モデルの実行中はマシンのメモリの大半が使用されることを覚悟してください：Flash Nextは完全な256Kコンテキストで約100 GiBを使います。他のモデルが必要なメモリを保持している場合、停止した状態でセットアップされ、そのうちの1つを停止すれば起動する準備ができます。モデルはログアウト時に停止します；メモリが他に必要なときは自分で停止してください。

`omarchy models list`は選択肢を表示し、適合しないものがある理由を説明します。別のものをセットアップするには、`omarchy models use <recipe>`を実行します。現在、128 GB Strix Haloマシン向けに`qwen3.8-flash-next-gufo`と`qwen3.8-27b-gufo`が利用可能で；27Bは約40 GiBを使うため、他の作業用の余地を残します。IntelのArc B390を搭載した64 GBラップトップでは、`qwen3.6-35b-a3b-llamacpp`が約30 GiBで動作します。新しいレシピと推奨は、`omarchy update`とともに、パッケージ経由で到着します。

セットアップしたすべてのモデルは、ローカルモデルパネルで独自の行を取得します：開始するには再生、停止してメモリを解放するには一時停止、あなたのエージェントを開くにはターミナルボタンです。画面上部では、バーはマシンのメモリが、Omarchy自体（システムとあなたのアプリ）、実行中の各モデル、そして空いている領域にどのように分割されているかを示します。停止したモデルをポイントすると、そのバーは、それが適合するかどうか、あるいは不足分がどれほどかを示します。複数のモデルがメモリに収まれば同時に実行できます；適合しない場合、Omarchyはどの実行中のモデルを停止すべきかを教えてくれます。そのロゴで行をドラッグして並べ替え、選択した行でDeleteを押してモデルとそのダウンロードを削除します。

セットアップしたすべてのコーディングモデルは、アプリランチャーにも、モデルの名前とそのメーカーのロゴで独自のエントリを取得します。これは、Claude、Codex、Grokにサインインするとエントリが追加されるのと同様です。それはそのモデルであなたのエージェントを開き、まだ実行されていない場合はモデルをまず起動します：ターミナルは読み込み中の様子を表示し、準備が整い次第、エージェントに処理を引き渡します。モデルを削除するとそのエントリも削除されます。

すべてのモデルがコーディング用ではありません。画像、動画、音楽モデルは代わりにFantasiで開きます。これはこのマシン上で実行されるモデルを使って写真、動画、音楽を作るためのOmarchyのアプリで、そこで選ぶか、ローカルモデルパネルの行から選びます。

モデルはセットアップされたとおり正確に動作し続けるため、Omarchyの更新があなたのエージェントの下でそれを再起動することはありません。セットアップしたモデルに対して、Omarchyに新しいランタイムや新しい重みがある場合、その行に更新ボタンが表示されます：それを押すとモデルはバックグラウンドで再びセットアップされ、変更されたものだけがダウンロードされ、新しいバージョンで再起動します。停止していたモデルは停止したままです。`omarchy models update`はターミナルからすべてのモデルについて同じことを行います。

コマンドラインから、`omarchy models start <recipe>`と`omarchy models stop <recipe>`が同じことを行い、`omarchy models status`はすべてのモデルを示し、`omarchy agent --local`は最後に開始したモデルでデフォルトのエージェントを開きます。pi、OpenCode、Qwen Codeはそれを使うことができ；他のデフォルトの場合、piで開くか、piを持っていない場合はOpenCodeで開きます。piは、セットアップしたすべてのモデルと、ペアリングしたマシン上のモデルも、その独自のモデルピッカーにも表示するので、素の`pi`でもそれらに到達できます。OpenAI互換のクライアントも接続できます：`status`は各モデルのアドレスを示します（最初のものは`http://127.0.0.1:11435/v1`）。レシピ名がモデル名であり、鍵は`~/.config/omarchy/agent-local/key`にあります。

`omarchy models remove <recipe>`はモデルと、他のモデルが使わないダウンロードを削除します。

サードパーティのランタイムは、その発行者でラベル付けされます。Omarchyはすべてのモデルをネットワークアクセスなしに実行します。

### ローカルLLM

OmarchyはローカルLLMモデルを実行する2つの方法を推奨します：LM StudioとOllamaです。LM Studioはオープンウェイトモデルを見つけ、インストールし、実行するためのGUIインターフェイスを提供します。簡単に始めるには素晴らしい方法です。Ollamaも同様なことを行うCLIを提供しています。しかし、ローカルモデルに初めて触れるなら、私ならLM Studioから始めます。どちらもOmarchy Menuの_Install > AI_の下でインストールできます。

### Omarchyスキル

エージェントスキルは、AIが特定のツールを特定の方法で使うことを助け、Omarchyにはそのうちの7つが付属します。omarchyスキルは、あなたのHyprland設定を調整したり、バーを調整したりするような、システムのカスタマイズをカバーします。omarchy-make-theme、omarchy-make-plugin、omarchy-make-app、omarchy-make-gameは新しいものを作ることをカバーし、omarchy-contributeはバグを報告したり、修正を上流に送信したりすることをカバーし、omarchy-diagnose-crashはクラッシュのコアダンプを調査します。これらは、Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills`および各`~/.hermes/profiles/*/skills`）、および汎用の`~/.agents/skills`ディレクトリといったスキルディレクトリにシンボリックリンクされており、ほとんどのハーネスはこれらを自動で取り込みます。同名の自身のスキルフォルダが優先されます。

ただし、これらのスキルは実験的なものと捉えるべきです。異なるモデルはさまざまな効果でそれを使います。まず計画モードで実行するのが最良であり、そうすればエージェントが何を変更したいか把握できます。そして、エージェントがすべてを台無しにしたら、変更をロールバックしたり、`omarchy reinstall configs`を呼び出すことも辞さない覚悟でいてください。
