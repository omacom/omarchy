### エージェントのインストールと更新

Hermes と OpenClaw を除き、これらのエージェントは mise の遅延インストールを使います。初回起動時に CLI がインストールされ、それ以降の起動ではそれが再利用されます。mise はまた、インストール済みエージェントに新しいリリースがないか、起動直前またはシェルプロンプトでバックグラウンドで、最大で 4 時間に 1 回だけ確認します。その更新が失敗したりオフラインだったりした場合、インストール済みのバージョンが動作します。`omarchy update` は Omarchy の残りと一緒にインストール済みエージェントを更新し、`mup` は mise 管理ツールのみを更新します。

エージェント独自のアップデーター、例えば `claude update`、`codex update`、またはアプリ内の更新ボタンは、mise 管理のインストールを更新しません。`codex update` は失敗し、`claude update` は成功したと報告しながら mise が追跡しない別コピーをインストールすることがあります。エージェント独自のインストーラーとアップデーターを使いたい場合は、それを `disable_tools` に追加してください。[Preinstalled CLI tools](18-development-tools.md#preinstalled-cli-tools) を参照してください。

設定済みの遅延ツールをすべて、必要になる前にインストールするには、`mise install --include-lazy` を実行してください。これにはエージェントだけでなく、Omarchy の他のデフォルト CLI ツールも含まれます。単一ツールのインストールや独自のインストールを使う方法については [Preinstalled CLI tools](18-development-tools.md#preinstalled-cli-tools) を参照してください。

`grok` は mise のファーストパーティ `grok` パッケージ経由でインストールされます。`claude` や `codex` と同じ方法です。`grok` を実行するか、エージェントパネルでスターを付けてください。x.ai の `curl | bash` インストーラーは避けてください。その方法だと `~/.grok/bin` に 2 つ目のコピーが置かれ、`PATH` の先頭に追加され、Omarchy のラッパーが上書きされます。

`dsh` はブラウザ UI を `127.0.0.1:3080` で開き、起動ディレクトリをデフォルトのワークスペースとします。そのブラウザ UI は開始プロンプトを受け取らないので、`omarchy agent prompt` はプロンプトをクリップボードに載せて貼り付けられる状態で開きます。Omarchy は DeepSeek の承認なし権限プリセットで起動します。DeepSeek Harness は公式モデル API を使用するとセッションログを DeepSeek にアップロードします。そのブラウザ UI の _Settings > General > Upload Session Log_ でオフにしてください。送信するフィードバックもセッションと一緒にアップロードされます。ただし `DSH_TELEMETRY_MODE=DISABLED` で起動した場合は除きます。

### デフォルトエージェント

デフォルトエージェントは、エージェントパネルでエージェントの横にあるスターで選んでください。デフォルトには塗りつぶされたスターが表示されます。または `omarchy default agent <name>` でも選べます。こちらはそこに行がないどのハーネスでも受け付けます。エージェントがまだインストールされていなければ、選ぶとまずインストールされ、アプリランチャーで Agent の横に独自のランチャーも得ます。新規の Omarchy では、一度だけの通知でセットアップに誘われ、その通知を開くとエージェントパネルが開きます。

Claude を選ぶと、Chromium、Chrome、Brave、Brave Origin、Edge 用のブラウザ拡張機能のセットアップも試みます。拡張機能のセットアップは全ユーザーに適用され、システムパスワードを求めることがあります。キャンセルしたり拡張機能のインストールに失敗したりしても、Claude は選択され起動します。ブラウザを再起動し、求められたら拡張機能を有効にし、Claude にサインインして接続を完了してください。接続を確認するには Claude で `/chrome` を実行してください。Firefox と Zen はこの拡張機能に対応していません。このセットアップが追加される前に既に Claude がデフォルトだった場合は、再度選択して拡張機能をインストールしてください。

選んだら、`Super + Shift + Ctrl + A` でデフォルトエージェントが専用のターミナルウィンドウで起動します（まだ選んでいなければピッカーが表示されます）。`omarchy agent prompt "Review this project"` でタスクに直行させることもできます。Freebuff と DeepSeek Harness は開始プロンプトを受け取らないので、代わりにプロンプトをクリップボードに載せて貼り付けられる状態で開きます。この方法で起動したエージェントは、それぞれの止まって聞かないモードで無人で動作するので、本当に物事を実行する覚悟をしておいてください！MiniMax Code にはインタラクティブセッション向けのそのようなモードがないので、通常通り権限を求めます。また、エージェントはホームディレクトリに対する信頼を覚えることを拒否するため、`$HOME` からの起動は代わりに `~/Work` で始まります。

ターミナルのショートカットもあります。`a` は現在のターミナル内でデフォルトエージェントをインラインで実行し、`c`、`cx`、`cy` は OpenCode、Claude Code、Codex を直接起動します（こちらも自動承認モードです）。テーマ変更もエージェントに同期します。Claude Code、Pi、OpenCode、Hermes（Omarchy がインストール済みの場合）は、Omarchy テーマを切り替えたときに一緒に追随します。

### あなたのエージェント指示

すべてのエージェント向けの個人的なルールは `~/.agents/AGENTS.md` に置き、共有スキルは `~/.agents/skills` の隣に置きます。エージェントパネルの + の横にあるドキュメントアイコンで開くか、`omarchy agent instructions --edit` で開いてください。後者は独自のグローバルファイルを保持する各ハーネスにもリンクします。`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`~/.pi/agent/AGENTS.md`、`~/.config/opencode/AGENTS.md`、Copilot の `~/.copilot/copilot-instructions.md` などです。Crush と Amp は `~/.config/AGENTS.md` リンクを読み取り、omp、Kimi、DeepSeek Harness は `~/.agents/AGENTS.md` を直接読み取ります。デフォルトエージェントを選ぶとそこにもリンクされます。既に持っていた指示ファイルは、共有のものがまだなければ共有のものになり、そうでなければリンクの横に `.bak` として保持されます。別のエージェントをインストールした後に再リンクするには `omarchy agent instructions` を実行してください。

### エージェントパネル

トップバーにはエージェントアイコンがあります。エージェントをセットアップする前、そのパネルでは 3 つの開始方法が提供されます。Claude、Codex、Grok、Gemini、Muse、Cursor、Copilot サブスクリプションにサインインするか、More の下にある OpenCode Go、MiniMax、Synthetic、Z.ai コーディングプランを利用する方法。Fireworks、OpenCode Zen と Go、OpenRouter で従量課金するか、More の下にある DeepSeek や OpenCode がサインインできる他のどのプロバイダーでも従量課金する方法で、いずれも OpenCode で実行されます。または、あなたのコンピューターに合うモデルがある場合、そのコンピューターに最適なモデルを実行する方法です。最初に終えたものがデフォルトエージェントになり、パネルの +、または Omarchy Menu の _Agent > Add_ から後で同じ 3 つが提供されます。その後は、パネルはすべてのサブスクリプションを 1 ページにまとめます。各エージェントとアカウントにそのプラン、5 時間セッションと週間制限それぞれのメーターとリセットまでの時間（正確なパーセンテージはホバーで表示）、または前払い残高が表示され、それらの上には、例えば今週のトークンや最もよく使ったモデルなど、すべてを通して使用したものがローテーション表示される行があります。_Make something cool_ の下では、新しいテーマ、プラグイン、アプリ、ゲームのスタータープロンプトが提供され、タスクをデフォルトエージェントに渡します。アプリは Omarchy 独自の Hype、Monologue、Omacut と同じ方法で、C++ と Qt Quick で構築され、omarchy-make-app エージェントスキルに従い、必要なコンパイラと Qt 部品はインストール済みで来ます。ゲームは `~/Games/vibes` にある単一の three.js ページで、omarchy-make-game エージェントスキルに従い、すべて現在のテーマの 1 つの Game Vibes ランチャーから開きます。それらは Web から three.js を読み込むので、開始には接続が必要です。Claude Code、Codex、Grok、Kimi、Cursor とその Grok Bot 枠、GitHub Copilot、Muse、Gemini（Antigravity 経由）、Devin は制限付きでそのまま利用でき、Kimchi はそのプラン、前払いクレジット、支出予算付きで利用でき、Hermes、Mistral Vibe、Qwen Code は使用した後にセッションとトークンを表示します。pi、omp、opencode 経由で使うプロバイダープランとキーも表示されます。OpenCode Zen と Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan、Synthetic は制限付きで、OpenRouter と DeepSeek は前払い残高付きで、Fireworks は過去 30 日間の支出付きで表示されます。自分のハードウェアで実行するモデルのトークンも合計にカウントされます。モデル自体には独自のパネルがあり、[Local models](#local-models) で説明します。すべてのエージェントは、それを請求する側の下で一度だけカウントされます。いくつのハーネス経由で駆動しても同じです。

バーアイコンを左クリックするか `Super + Ctrl + X` を押すとパネルが開き、右クリックするとデフォルトエージェントが起動し、中クリックすると更新されます。その背後にある使用記録は `omarchy agent usage update` によって 15 分ごとに再生成され、パネルは同期フォルダ経由で他のマシンからの使用量をマージすることさえできます。完全な設定については `$OMARCHY_PATH/shell/plugins/agents/` の下にある README を参照してください。

### 複数のサブスクリプション

Claude、Codex、Grok のプランを複数支払っている場合、例えば個人の Max と仕事用など、Omarchy はそれらすべてをサインインした状態に保ち、間を移動できます。エージェントパネルの + でサブスクリプションを追加してください。その場で順に案内します。または `omarchy agent account add claude Work`（または `codex`、または `grok`）でも追加できます。同じ + とコマンドで Gemini（`gemini`）と OpenCode（`opencode`）にサインインし、Fireworks（`fireworks`）または OpenRouter（`openrouter`）の API キーを OpenCode に保存します。このコマンドは Copilot（`copilot`）、Cursor（`cursor`）、Muse（`muse`）にもサインインします。それらはそれぞれ単一のサインインを保持します。CLI がなければインストールします。プロバイダーの最初のアカウントは、CLI がいつも見る通常のブラウザ経由でサインインします。それ以降はすべてプライベートウィンドウ経由でサインインするので、ブラウザが既にサインインしているアカウントを誤って拾うことはありません。追加するアカウントとしてそこでサインインし、既に開いているプライベートウィンドウは先に閉じてください。これのために CLI から決してログアウトしないでください。ログアウトすると保存されたサインインが取り消され、そのアカウントを再度追加しなければならなくなります。

SSH 経由で別の Omarchy マシンにサブスクリプションログインをコピーするには、`omarchy agent account copy user@laptop` を実行してください。宛先にインストールされたものがない場合、送信側が一時的な受信側を提供するので、古い Omarchy マシンでも更新なしでアカウントを受け取れます。インストール済みの受信側が優先されます。これはすべての Claude、Codex、Grok サブスクリプションをコピーします。選択するにはプロバイダー名を追加してください。例：`omarchy agent account copy laptop claude`。アカウント名とコマンド ID はソースと一致し、宛先に既に存在するアカウントも含まれます。無関係な宛先アカウントは名前が衝突した場合に数字サフィックスを受け、設定、スキル、プラグイン、会話履歴は各マシンにローカルなままです。

既存の宛先認証情報は保持されます。ソースアカウントが既にそこでサインインしている場合、その認証情報を置き換えずに名前が同期されます。他のアカウントはそれに並んで追加されます。一致するアカウントの保存済み認証情報を置き換えるには、宛先でそのアカウントのセッションを終了した後、`omarchy agent account copy --replace laptop claude` を使用してください。新規の宛先はソースのアクティブアカウントと切り替え設定も受け取ります。確立済みの宛先は自身のものを保持します。

認証情報は SSH 経由で移動し、宛先のプライベートファイルに保存されるので、信頼するマシンにのみコピーしてください。これは一度限りのコピーであり、継続的な同期ではありません。Codex のリフレッシュトークンは別のマシンによってローテーションされることがあり、コピーしたログインが更新を必要とする状態になることがあります。複数のマシンで同時に使用するには個別のサインインが最も信頼できる選択です。[Codex のアカウント認証ガイダンス](https://developers.openai.com/codex/auth/ci-cd-auth) を参照してください。

プロバイダーごとにアクティブなアカウントは 1 つで、すべての新しいセッションはそれとして開始します。`cx`、`cy`、通常の `claude`、`codex`、`grok`、`omarchy agent` 経由で起動されるもの、`PATH` 上で CLI を見つけるスクリプトやエディタもそうです。`omarchy agent account use work` で切り替え（`omarchy agent account use main` で戻す）、またはパネルでアカウントの数字を押してから `Enter` を押す（またはそのスターをクリックする）ことで切り替えます。実行中の Claude セッションも次のメッセージから切り替わります。すべての Claude セッションは `~/.claude` で実行され、そこには常にアクティブアカウントのサインインが保持されます。古い Omarchy によってアカウント独自のフォルダで開始された Claude セッションは、終了するまでそのサインインを保持するので、切り替えではそれらのセッションを名前で示し、それらがなくなると自動的に完了します。実行中の Codex と Grok セッションは開始したアカウントのままです。会話履歴、設定、スキル、プラグインはアカウント間で共有されるので、同じフォルダでの `claude --continue` は新しいアカウントで中断したところから再開します。

複数のアカウントがある場合、パネルは各アカウントの制限を並べて表示し、使用中のものには塗りつぶされたスターが付きます。アクティブアカウントが制限の 95% を超えると Omarchy が通知し、通知をクリックすると最も余裕のあるアカウントに切り替わります。自動で切り替えることは決してありません。閾値は `omarchy agent account threshold 90` で変更してください。すべてのアカウントが閾値を超えている場合は、一度だけそのことと、どのアカウントが最初に解放されるかが通知されます。アクティブアカウントがその閾値まで 15 ポイント以内（デフォルトでは 80%）にある間、その制限は 15 分ごとではなく 3 分ごとにチェックされます。

`omarchy agent account list` はすべてのアカウントとその最新の制限を表示し、`omarchy agent account remove work` は 1 つを忘れ、`omarchy agent account rename primary Hey` は 1 つの名前を変更します（またはパネルでアカウント名をクリックします）。これらのコマンドはデフォルトエージェントのアカウントに対して動作します。別のプロバイダーにアクセスするには、先に名前を指定してください。例：`omarchy agent account use codex side`。`~/.claude` または `~/.codex` に既に持っていたログインが _Main_ アカウントです。Codex のものはそのままの場所に残り、Claude のものは別のアカウントがアクティブな間、独自のフォルダで待機します。約 8 時間以上使用していないアカウントは _Sign-in required_ と表示されることがあります。クリックしてパネル内でそのアカウントに再サインインするか、それに切り替えてセッションを開始すれば、サインインは自動で更新されます。`claude mcp add` で追加した MCP サーバーは、すべて `~/.claude` で実行されるため、すべての Claude アカウントに届きます。Codex と Grok については、アカウント追加時に持っていたサーバーはそのアカウントにも付いてきますが、後のものは追加したアカウントにのみ届きます。Claude Desktop は独自のサインインを保持し、CLI バイナリへの絶対パスで設定された Codex または Grok ツールは切り替えに従いません。明示的な `CLAUDE_CONFIG_DIR`、`CODEX_HOME`、または `GROK_HOME` は選択したアカウントよりも優先されます。

### クラッシュ診断

Omarchy は systemd-coredump でプロセスクラッシュを監視します。デフォルトエージェントを選んだら、あなたのプログラムがコアをダンプすると「Process crashed」通知が表示されます。クリックすると、クラッシュはデフォルトエージェントに渡され、Omarchy の omarchy-diagnose-crash スキルとともに渡されます。そのスキルはエージェントを、コアダンプから事実を確立し、そのクラッシュを上流に報告する価値があるかどうかを決める手順を案内します。`coredumpctl list` の任意の PID に対して `omarchy agent crash <pid>` で手動で実行することもできます。

監視はデフォルトでオンです。_Trigger > Toggle > Crash Capture Off_ でオフにする（または `omarchy toggle crash-capture` で）と通知は止まります。`omarchy agent crash <pid>` は手動では引き続き動作します。

クラッシュはプログラムごとに 1 つずつ黙らせることもできます。それが診断の最後に提供されるものです。`omarchy crash mute hyprland` はそのプログラムのみの通知を止め、`omarchy crash mute hyprland off` は戻し、`omarchy crash mute` だけではミュートしたものが一覧表示されます。バイナリのパスでも名前でも同じように受け付けるので、`omarchy crash mute /usr/bin/hyprland` でも同じことです。スペースを含む名前は引用してください。例：`omarchy crash mute 'Some App'`。他のすべては引き続き通知され、ミュートされたプログラムも引き続きクラッシュします。これはリマインダーを隠すもので、何も修正しません。

### デスクトップアプリ

_Install > AI_ メニューにはいくつかのグラフィカル AI アプリも含まれます。Amp Desktop、Antigravity Desktop、ChatGPT desktop app、Claude desktop app（Anthropic の Linux ベータで、Chat、Cowork、Claude Code タブ付き）、Grok Bot（xAI のモデルとチャットするため）、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexity desktop app、T3 Code です。Grok Bot はデスクトップチャットアプリです。コーディングエージェントは `grok` コマンドです。

Hermes Desktop は知っておくべきものです。なぜならマシンには 1 つの Hermes があり、それはアプリのものだからです。Hermes はアプリ経由でのみインストールされ、デフォルトエージェントが実行する `hermes` コマンドはアプリのものです。Hermes をデフォルトエージェントとして選ぶと、_Install > AI_ エントリと同じものがインストールされます。パッケージと、Hermes 独自のインストーラーによってセットアップされた `~/.hermes` の下の Hermes ランタイムで、初回は数分かかります。そのランタイムが、ターミナルの `hermes` コマンド、デフォルトエージェント、アプリすべてが使う唯一の Hermes で、Omarchy リリースを待つのではなく `hermes update` で自己更新します。インストールすると、Hermes に Omarchy テーマが `omarchy` という名前のスキンとして渡され、すべての Hermes 表面はテーマを切り替えるとそれに追随します。追随させたくなければ Hermes の Appearance 設定または `/skin` で別のものを選んでください。Omarchy はその選択をそのままにします。_Remove > AI_ でアプリを削除すると、まず Hermes が閉じられ（ゲートウェイも含む）、そのランタイムも一緒に取り除かれ、チャット、メモリ、Hermes が自身のために書いたスキルは、そう指示しない限り保持されます。そうしたデータと接続設定も削除するかどうかを問い、デフォルトはいいえです。

OpenClaw のデスクトップ体験はその Control UI で、独自のローカルゲートウェイに支えられた Web アプリとして開きます。OpenClaw は `~/.openclaw` に住み、自己更新します。Control UI の「Update Gateway」ボタンを使うか `openclaw update` を実行すると、ゲートウェイは新しいバージョンで再起動します。Omarchy は新規インストールが開始するリリースを選ぶだけです。OpenClaw はあなたのデフォルトエージェントにもなれます。_Agent > Harness_ で選ぶと `~/.openclaw` に同じコピーがセットアップされ、エージェントはそのゲートウェイに接続された OpenClaw のターミナル UI を開きます。_Remove > AI_ で OpenClaw を削除すると、ゲートウェイサービスとアプリが一緒に取り除かれ、その後 `~/.openclaw` も削除するかどうかを尋ねます。なぜならそこにはチャットと認証情報が OpenClaw 自体とダウンロードするプラグインランタイムと並んで保持されているからです。デフォルトでは保持され、OpenClaw を再度インストールするとそれを再び拾います。

Herdr Desktop は [Herdr](https://herdr.dev) デスクトップアプリです。スペース、タブ、そしてターミナルとコーディングエージェントのペインがあり、ウィンドウを閉じてもそのコアで実行し続けます。これはパッケージではなく Herdr 独自のインストーラーから来るので、`~/.local/share/herdr-app` に住み、まだ持っていない場合は `~/.local/bin/herdr-core` にそのコアも一緒に持ち込み、両方を自己更新します。これは Omarchy が `Super + Ctrl + Return` で提供する `herdr` コマンドの隣にあり、それを置き換えるのではなく、そのコマンドの直接キーを得ます。`Alt + Return` と `Alt + Shift + Return` はペインを下または右に分割し、`Alt + Escape` は閉じ、`Ctrl + Alt + Arrow` はペイン間を移動し、`Alt + 1..9` と `Alt + Left/Right` はタブを選び、`Alt + Up/Down` はスペース間を移動します。`Ctrl + 1..9` はスペースを選び、`Alt + Shift + Up/Down` はエージェント間をステップします。`Ctrl + Space` プレフィックスキーはターミナル専用のままです。アプリはシーケンスのために通常の Ctrl キーを保持できないからです。Omarchy はこれらを `~/.config/herdr-app/keys.json` に書き込み、`omarchy-refresh-herdr-app` が戻します。インストールすると Herdr の Omarchy テーマが選ばれ、それ以降あなたの Omarchy テーマに追随します。Herdr はライトモード用に 1 つ、ダーク用に 1 つのテーマを保持するので、ダークとライトの Omarchy テーマを切り替えた後は、もう一方のモード用に Herdr のテーマピッカーで Omarchy をもう一度選んでください。

T3 Code はパッケージではなく `~/.local/share/t3code` にある公式 AppImage リリースから実行されるので、自己更新します。インストール時に Stable チャンネルか Nightly チャンネルで開始するかどうかを尋ねます。後で T3 Code の設定で切り替えてください。あなたのスレッドと設定は `~/.t3` に住み、_Remove > AI_ で T3 Code を削除すると一緒に取り除かれます。

### ローカルモデル

コーディングエージェント用に自分のマシンでオープンモデルを実行してください。プロンプトとコードはマシン上に留まります。モデルに送られたものはマシンから出ません。次で開始してください：

```bash
omarchy models use best text
```

それはこのマシンに最適なテキストモデルをセットアップします。エージェントが使うタイプです。画像、動画、音楽モデルにもそれぞれ最適なものがあります。`omarchy models use best image`、`video`、`music` です。`omarchy models use best` を実行すると、このマシン向けの各種類の選択が表示されます。

またはトップバーのエージェントアイコンの隣にあるスパークルアイコンから、または Super + Ctrl + Alt + X でローカルモデルパネルを開き、+ を選んでください。アイコンはモデルがこのマシンに合う場合に表示されます。モデルを実行する Podman は Omarchy に付属し、NVIDIA マシンでは NVIDIA のコンテナツールキットも付属して GPU を提供します。どちらかがない場合、最初のセットアップでインストールされます。Omarchy は次にこのマシンに推奨されるモデルを選び、ダウンロードし、開始します。数十 GB のダウンロードと、モデル実行中はマシンのメモリの大半が使用されることを想定してください。Flash Next は完全な 256K コンテキストで約 100 GiB を使用します。他のモデルが必要なメモリを保持している場合、停止した状態でセットアップされ、1 つを停止したら開始できる準備ができます。モデルはログアウト時に停止します。他の用途でメモリが必要なときは自分で停止してください。

`omarchy models list` は選択肢を表示し、一部が合わない理由を説明します。別のものをセットアップするには `omarchy models use <recipe>` を実行してください。現在、128 GB Strix Halo マシン向けに `qwen3.8-flash-next-gufo` と `qwen3.8-27b-gufo` が利用できます。27B は約 40 GiB を使うので、他の作業用の余地を残します。Intel の Arc B390 を搭載した 64 GB ラップトップでは、`qwen3.6-35b-a3b-llamacpp` が約 30 GiB で動作します。新しいレシピと推奨は `omarchy update` によりパッケージ経由で届きます。

セットアップしたモデルごとにローカルモデルパネルに独自の行が得られます。再生で開始、ポーズで停止してメモリを解放し、ターミナルボタンでその上でエージェントを開きます。上部全体には、Omarchy 自体（システムとあなたのアプリ）、実行中の各モデル、そして空きメモリの間でマシンのメモリがどのように分割されているかを示すバーが表示されます。停止したモデルをポイントすると、そのバーは合うかどうか、またはどれだけ不足しているかを表示します。メモリに一緒に収まる場合はいくつかを同時に実行できます。収まらない場合は、Omarchy がどの実行中モデルを停止すべきか伝えます。ロゴでドラッグして行を並べ替え、選択した行で Delete を押すとモデルとそのダウンロードが削除されます。

セットアップしたコーディングモデルごとに、アプリランチャーに独自のエントリも得られます。モデルの名前とそのメーカーのロゴ付きで、Claude、Codex、Grok にサインインすると追加されるのと同じ方法です。それはそのモデル上でエージェントを開き、実行中でなければまずモデルを開始します。ターミナルには読み込みが表示され、準備ができたらエージェントに引き渡されます。モデルを削除するとそのエントリも削除されます。

すべてのモデルがコーディング用ではありません。画像、動画、音楽モデルは代わりに Fantasi で開きます。Fantasi はこのマシンで実行されるモデルで写真、動画、音楽を作るための Omarchy アプリで、そこで選ぶか、ローカルモデルパネルの行から選びます。

モデルはセットアップされた通りに正確に実行し続けるので、Omarchy の更新でエージェントの下で再起動することは決してありません。Omarchy がセットアップ済みモデル向けに新しいランタイムや新しいウェイトを持っている場合、その行には更新ボタンが表示されます。押すとモデルはバックグラウンドで再びセットアップされ、変更されたものだけをダウンロードし、新しいバージョンで再起動します。停止していたモデルは停止したままです。`omarchy models update` はターミナルからすべてのモデルに対して同じことをします。

コマンドラインからは、`omarchy models start <recipe>` と `omarchy models stop <recipe>` が同じことをし、`omarchy models status` はすべてのモデルを表示し、`omarchy agent --local-model <recipe>` はあなたのデフォルトエージェントが何であれ、そのモデルを pi で開きます。ローカルモデルをエージェントホットキー、Quake コンソール、_Make something_ が開くものにするには、`omarchy default agent local` を実行するか、_Agent > Harness_ で _Local model_ を選んでください。pi はセットアップしたすべてのモデルと、ペアリングしたマシン上のモデルも独自のモデルピッカーに一覧表示するので、通常の `pi` でもそれらに届きます。OpenAI 互換のどのクライアントも接続できます。`status` は各モデルのアドレスを示します（最初は `http://127.0.0.1:11435/v1`）、レシピ名がモデルで、キーは `~/.config/omarchy/agent-local/key` にあります。

`omarchy models remove <recipe>` はモデルと、他のどのモデルも使っていないダウンロードを削除します。

サードパーティランタイムにはその発行者のラベルが付きます。Omarchy はすべてのモデルをネットワークアクセスなしで実行します。

### ローカル LLM

Omarchy はローカル LLM モデルを実行する 2 つの方法を推奨します。LM Studio と Ollama です。LM Studio はオープンウェイトモデルを見つけ、インストールし、実行するための GUI インターフェイスを提供します。簡単に始めるのに最適な方法です。Ollama は同様にする CLI を提供します。しかしローカルモデルが初めてなら、私は LM Studio から始めるでしょう。どちらも Omarchy Menu の _Install > AI_ でインストールできます。

### Omarchy スキル

エージェントスキルは AI が特定の方法で特定のツールを使うのを助け、Omarchy にはそのうち 7 つが付属します。omarchy スキルはシステムのカスタマイズをカバーします。例えば Hyprland 設定を調整したりバーを調整したりします。omarchy-make-theme、omarchy-make-plugin、omarchy-make-app、omarchy-make-game は新しいものを作ることをカバーし、omarchy-contribute はバグ報告や修正を上流に送ることをカバーし、omarchy-diagnose-crash はクラッシュのコアダンプを調べます。これらは Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` と各 `~/.hermes/profiles/*/skills`）、そして汎用の `~/.agents/skills` 場所のスキルディレクトリにシンボリックリンクされているので、ほとんどのハーネスは自動で拾います。同名の独自スキルフォルダが優先されます。

しかしこれらのスキルは実験的なものとして扱うべきです。異なるモデルはそれぞれ異なる効果で使用します。まずプランモードで実行するのが最善です。そうすればエージェントが何を変更したいか把握できます。そして変更をロールバックする、あるいはエージェントがすべてを台無しにした場合は `omarchy reinstall configs` を呼び出す準備をしておいてください。
