### エージェントのインストールとアップデート

Hermes を除き、これらのエージェントは mise の lazy installation を使います。初回起動時に CLI がインストールされ、以降の起動ではそれが再利用されます。mise はまた、インストール済みエージェントの新しいリリースを、起動直前、またはシェルプロンプトでのバックグラウンドで、最大で 4 時間に 1 回チェックします。そのアップデートが失敗したり、オフラインだったりした場合は、インストール済みのバージョンが動きます。`omarchy update` は、インストール済みエージェントを Omarchy の他の部分と一緒にアップデートし、`mup` は mise が管理するツールだけをアップデートします。

`claude update` や `codex update`、アプリ内のアップデートボタンなど、エージェント自身のアップデーターは、mise が管理するインストールをアップデートしません。`codex update` は失敗し、`claude update` は成功したと報告しながら、mise が追跡しない別コピーをインストールすることがあります。エージェントのネイティブなインストーラーとアップデーターを使いたければ、それを `disable_tools` に追加してください。[プリインストールされた CLI ツール](18-development-tools.md#preinstalled-cli-tools) を参照してください。

設定済みのすべての lazy tool を、必要になる前にインストールするには、`mise install --include-lazy` を実行してください。これには、エージェントだけでなく、Omarchy の他のデフォルト CLI ツールも含まれます。単一のツールのインストールや、独自のインストールを使う方法については、[プリインストールされた CLI ツール](18-development-tools.md#preinstalled-cli-tools) を参照してください。

`grok` は、`claude` や `codex` と同じように、mise 公式の `grok` パッケージを通じてインストールされます。`grok` を実行するか、_Setup > Defaults > Agent_ で選択してください。x.ai の `curl | bash` インストーラーは使わないでください。その方法では `~/.grok/bin` に 2 つ目のコピーが置かれ、それが `PATH` の先頭に prepend され、Omarchy の wrapper が上書きされます。

`dsh` は `127.0.0.1:3080` でブラウザ UI を開き、起動したディレクトリがデフォルトのワークスペースになります。そのブラウザ UI は開始プロンプトを受け付けないので、`omarchy agent prompt` は、プロンプトをクリップボードに載せて貼り付けられる状態で開きます。Omarchy は、DeepSeek の no-approval permission preset でこれを起動します。DeepSeek Harness は、公式のモデル API を使っているとき、セッションログを DeepSeek にアップロードします。ブラウザ UI の _Settings > General > Upload Session Log_ でオフにしてください。送信したフィードバックもセッションと一緒にアップロードされます。ただし、`DSH_TELEMETRY_MODE=DISABLED` を付けて起動した場合は別です。

### デフォルトのエージェント

デフォルトのエージェントは、`omarchy default agent <name>` で選ぶか、Omarchy Menu（`Super + Space`）の _Setup > Defaults > Agent_ で選んでください。エージェントがまだインストールされていなければ、選択することでまずそれがインストールされます。新しい Omarchy では、1 回限りの通知でこの選択をするよう促されます。

Claude を選択すると、Chromium、Chrome、Brave、Brave Origin、Edge 用に、そのブラウザ拡張機能のセットアップも試みます。拡張機能のセットアップはすべてのユーザーに適用され、システムパスワードを求められることがあります。キャンセルしたり、拡張機能のインストールが失敗したりしても、Claude は選択されて起動します。ブラウザを再起動し、求められたら拡張機能を有効にし、Claude にサインインして接続を完了してください。Claude で `/chrome` を実行すると接続を確認できます。Firefox と Zen はこの拡張機能をサポートしません。このセットアップが追加される前に Claude がすでにデフォルトだった場合は、そのままもう一度選択すれば拡張機能がインストールされます。

選択が終われば、`Super + Shift + Ctrl + A` でデフォルトのエージェントが専用のターミナルウィンドウで起動します（まだ選んでいなければ、ピッカーが表示されます）。`omarchy agent prompt "Review this project"` のように、タスクに直接投入して起動することもできます。Freebuff と DeepSeek Harness は開始プロンプトを受け付けないので、代わりにプロンプトをクリップボードに載せて貼り付けられる状態で開きます。このように起動したエージェントは、それぞれの don't-stop-to-ask モードで無人で動くので、実際にあれこれ実行する覚悟をしておいてください！ MiniMax Code には対話セッション用のそうしたモードがないので、通常どおり権限を求めてきます。そして、エージェントはホームディレクトリへの信頼を覚えることを拒否するので、`$HOME` からの起動は代わりに `~/Work` で始まります。

ターミナル用ショートカットもあります。`a` は現在のターミナルでインラインにデフォルトのエージェントを実行し、`c`、`cx`、`cy` は OpenCode、Claude Code、Codex を直接起動します（これも auto-approving モードです）。テーマ変更もエージェントに同期します。Omarchy のテーマを切り替えると、Claude Code、Pi、OpenCode、そして Hermes（Omarchy がインストールした後）がすべて追従します。

### エージェントパネル

トップバーにはエージェントアイコンがあります。エージェントをまだ設定していない場合、そのパネルが Claude、Codex、または Grok へのサインインを案内し、最初に設定したものがデフォルトのエージェントになります。その後は、パネルがすべてのサブスクリプションを 1 ページに載せます。各エージェントとアカウント、そのプラン、5 時間のセッション制限と週間制限それぞれのメーターとリセットまでの時間（ホバーすると正確なパーセンテージ）、または残りのプリペイド残高。そしてその上に、トークンの今週の使用量や一番よく使うモデルなど、全体の使用状況を入れ替わりで表示する 1 行が回ります。_Make something_ の下では、新しいテーマ、プラグイン、アプリのスタータープロンプトが用意されており、タスクをデフォルトのエージェントに渡します。アプリは、Omarchy 自身の Hype、Monologue、Omacut と同じやり方で、C++ と Qt Quick で、omarchy-app agent skill に従って構築され、必要なコンパイラと Qt の部品はインストール済みです。Claude Code、Codex、Grok、Kimi、Cursor とその Grok Bot allowance、GitHub Copilot、Muse、Antigravity、Kimchi、Devin は、制限付きでそのまま利用できます。Hermes、Mistral Vibe、Qwen Code は、1 度使うとセッションとトークンが表示されます。pi、omp、opencode を通じて使うプロバイダーのプランとキーも表示されます。制限付きで OpenCode Zen と Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan、Synthetic。プリペイド残高で Fireworks、OpenRouter、DeepSeek。そして自分のハードウェアで動かすモデルは Local models の下に表示されます。すべてのエージェントは、それを請求する側の下でのみ 1 回だけカウントされ、いくつの harness を通じて駆動しても変わりません。

バーのアイコンを左クリックするとパネルが開き、右クリックするとデフォルトのエージェントが起動します。その裏側の使用記録は `omarchy agent usage-update` によって 15 分ごとに再生成され、パネルは同期フォルダ経由で他のマシンからの使用状況をマージすることさえできます。完全な設定については、`$OMARCHY_PATH/shell/plugins/agents/` にある README を参照してください。

### 複数のサブスクリプション

Claude、Codex、または Grok のプランを複数支払っている場合（例えば、個人の Max と仕事用など）、Omarchy はそれらすべてのサインインを保持し、それらの間を移動できます。エージェントパネルで + を使ってサブスクリプションを追加すると、その場で案内してくれます。または `omarchy agent account add claude Work`（または `codex` や `grok`）で追加できます。CLI がなければインストールします。プロバイダーの最初の アカウントは、CLI が常に見ているまさにその場所で、通常のブラウザを通じてサインインします。それ以降はすべてプライベートウィンドウでサインインするので、ブラウザがすでにサインインしているアカウントを誤って拾うことはありません。そこでは追加しようとしているアカウントとしてサインインし、すでに開いていたプライベートウィンドウは先に閉じてください。これをするときに、決して CLI からログアウトしないでください。ログアウトすると保存されたサインインが無効になり、そのアカウントは再び追加しなければならなくなります。

サブスクリプションログインを SSH 経由で別の Omarchy マシンにコピーするには、`omarchy agent account copy user@laptop` を実行してください。送信側は、送信先に receiver がインストールされていない場合、一時的な receiver を提供するので、古い Omarchy マシンでもアップデートなしにアカウントを受け取れます。インストール済みの receiver が優先します。これはすべての Claude、Codex、Grok のサブスクリプションをコピーします。選択するにはプロバイダー名を追加してください。例：`omarchy agent account copy laptop claude`。アカウント名とコマンド ID はコピー元と一致し、送信先にすでに存在するアカウントも含みます。無関係な送信先アカウントは、名前が衝突した場合に数値の suffix が付けられます。設定、スキル、プラグイン、会話履歴は各マシンにローカルなままです。

既存の送信先の認証情報は保持されます。すでにそこでサインインしているコピー元アカウントは、認証情報を置き換えることなく名前が同期されます。他のアカウントは、それに加えて追加されます。一致するアカウントの保存された認証情報を置き換えるには、送信先でそのアカウントのセッションを終了した後、`omarchy agent account copy --replace laptop claude` を使ってください。新しい送信先は、コピー元のアクティブなアカウントと切り替え設定も引き継ぎます。すでに確立した送信先は独自のものが維持されます。

認証情報は SSH を通じて移動し、送信先のプライベートなファイルに保存されるので、信頼するマシンにだけコピーしてください。これは 1 回限りのコピーであり、継続的な同期ではありません。Codex の refresh token は他のマシンによってローテーションされることがあり、コピーしたログインが更新を必要とする状態になることがあります。複数マシンで同時に使う場合は、別々にサインインするのが最も確実な選択です。[Codex のアカウント認証ガイダンス](https://developers.openai.com/codex/auth/ci-cd-auth) を参照してください。

プロバイダーごとにアクティブなアカウントは 1 つだけで、すべての新しいセッションはそれで始まります。`cx`、`cy`、素の `claude`、`codex`、`grok`、`omarchy agent` 経由で起動されるもの、そして `PATH` 上で CLI を見つけるスクリプトやエディタがそうです。`omarchy agent account use work`（戻す場合は `omarchy agent account use main`）で切り替えるか、パネルでアカウントの番号を押してから `Enter` を押してください（または、その Use ボタンをクリックしてください）。すでに実行中のセッションは、開始したときのアカウントのままです。会話履歴、設定、スキル、プラグインはアカウント間で共有されるので、同じフォルダで `claude --continue` とすれば、新しいアカウントで中断した場所から再開できます。

アカウントが複数ある場合、パネルは各アカウントの制限を並べて表示し、アクティブなものをマークします。デフォルトでは、アクティブなアカウントが制限の 95% を超えると Omarchy が通知し、通知をクリックすると最も余裕のあるアカウントに切り替わります。パネルでアカウントの行にホバーし、Use の隣に現れる Autoswitch をクリックするか（または `m` を押すか）、`omarchy agent account mode auto` を実行すれば、代わりに自動で切り替えるようになります。有効の間は Autoswitch が Use の代わりになり、もう一度クリックすると通知に戻ります。`omarchy agent account mode auto 90` のように数値を追加するとしきい値を変更できます。すべてのアカウントがしきい値を超えている場合は、どのアカウントが最初に解放されるかとともに、そのことが 1 回だけ知らされます。アクティブなアカウントがしきい値から 15 ポイント以内（デフォルトでは 80%）にある間、その制限は 15 分ごとではなく 3 分ごとにチェックされます。

`omarchy agent account list` はすべてのアカウントと最新の制限を表示し、`omarchy agent account remove work` はアカウントを 1 つ忘れ、`omarchy agent account rename primary Hey` は名前を変更します（パネルでアカウント名をクリックしてもできます）。これらのコマンドはデフォルトのエージェントのアカウントに作用します。もう一方のプロバイダーに触れるには、まずそれを指定してください。例：`omarchy agent account use codex side`。`~/.claude` や `~/.codex` にすでにあったログインは _Main_ アカウントで、そのままそこに残ります。約 8 時間以上使用していないアカウントは _Sign-in required_ と表示されることがあります。クリックすればパネルでそのアカウントにすぐ再サインインでき、またはそのアカウントでセッションを開始すると、自動でサインインが更新されます。アカウントが追加されたときにあった MCP サーバーはそのアカウントに引き継がれますが、`claude mcp add` で後から追加したものは、追加したアカウントにしか届きません。Claude Desktop や、CLI バイナリへの絶対パスで設定されたツールは、切り替えに追従しません。明示的な `CLAUDE_CONFIG_DIR`、`CODEX_HOME`、または `GROK_HOME` は、選択されたアカウントに優先します。

### クラッシュ診断

Omarchy はプロセスのクラッシュについて systemd-coredump を監視しています。何かが segfault すると、「Process crashed」通知が届きます。それをクリックすると、クラッシュはデフォルトのエージェントに、Omarchy の diagnose-crash skill とともに渡されます。その skill は、core dump から事実を確立し、クラッシュを upstream に報告する価値があるかどうかを判断するようエージェントを導きます。`omarchy agent crash <pid>` を使い、`coredumpctl list` の任意の PID に対して手動で実行することもできます。

監視はデフォルトでオンです。_Trigger > Toggle > Crash Capture_ の下で（または `omarchy toggle crash-capture` で）オフにすると通知は止まります。`omarchy agent crash <pid>` は手動では引き続き動作します。

クラッシュはプログラムごとに 1 つずつ黙らせることもでき、それは診断が最後に提案するものです。`omarchy crash mute hyprland` はそのプログラムだけ通知を止め、`omarchy crash mute hyprland off` は元に戻し、`omarchy crash mute` だけだとミュートしたものが一覧表示されます。名前と同じくらい気軽にバイナリのパスも受け付け、`omarchy crash mute /usr/bin/hyprland` でも同じことになります。スペースを含む名前は引用してください。例：`omarchy crash mute 'Some App'`。他のすべてのものは引き続き通知され、ミュートしたプログラムは引き続きクラッシュします。これはリマインダーを隠すだけで、何も直しません。

### デスクトップアプリ

_Install > AI_ メニューには、グラフィカルな AI アプリもいくつかあります。ChatGPT desktop app、Claude desktop app（Chat、Cowork、Claude Code タブ付きの Anthropic の Linux beta）、xAI のモデルとチャットする Grok Bot、Hermes Desktop、OpenClaw、Perplexity desktop app、そして T3 Code です。Grok Bot はデスクトップチャットアプリです。コーディングエージェントは `grok` コマンドです。

Hermes Desktop は知っておくべきものです。マシンには Hermes は 1 つしかなく、それはこのアプリのものだからです。Hermes はアプリを通じてのみインストールされ、デフォルトのエージェントが実行する `hermes` コマンドもアプリのものです。Hermes をデフォルトのエージェントに選ぶと、_Install > AI_ の項目がインストールするのと同じものがインストールされます。そのパッケージと、Hermes 自身のインストーラーがセットアップした `~/.hermes` 配下の Hermes runtime です。初回は数分かかります。その runtime が、ターミナルの `hermes` コマンド、デフォルトのエージェント、そしてアプリのすべてが使う、その 1 つの Hermes です。それは Omarchy のリリースを待つのではなく、`hermes update` で自らアップデートします。インストールすると、Hermes には `omarchy` という名前のスキンとして Omarchy テーマも渡されるので、テーマを切り替えるとすべての Hermes サーフェスが追従します。そうしたくない場合は、Hermes の Appearance 設定で、または `/skin` で別のものを選んでください。Omarchy はその選択に干渉しません。_Remove > AI_ の下でアプリを削除すると、まず Hermes が（gateway を含めて）閉じられ、その runtime も一緒に取り除かれ、チャット、メモリ、そして Hermes が自身のために書いたスキルは、他に指示しない限り保持されます。そのデータと接続設定も一緒に削除するか、デフォルトは no として尋ねてきます。

OpenClaw のデスクトップエクスペリエンスはその Control UI です。これは、独自のローカル gateway をバックエンドとしてウェブアプリとして開きます。OpenClaw は `~/.openclaw` に住み、自らアップデートします。Control UI の「Update Gateway」ボタンを使うか、`openclaw update` を実行すると、gateway は新しいバージョンで再起動します。Omarchy が選ぶのは、新規インストールがどのリリースから始まるかだけです。_Remove > AI_ の下で OpenClaw を削除すると、gateway サービスとアプリが一緒に取り除かれ、その後 `~/.openclaw` も削除するかどうか尋ねられます。そこには OpenClaw 自体やダウンロードした plugin runtime と並んで、チャットと認証情報が入っているためです。デフォルトでは保持され、OpenClaw を再インストールすれば再び拾い上げられます。

T3 Code は、パッケージからではなく、`~/.local/share/t3code` にある公式の AppImage リリースから実行されるので、自らアップデートします。インストールすると、Stable チャンネルで始めるか Nightly チャンネルで始めるかが尋ねられます。後で T3 Code の設定で切り替えてください。スレッドと設定は `~/.t3` にあり、_Remove > AI_ の下で T3 Code を削除すると、それらも一緒に取り除かれます。

### ローカルモデル

コーディングエージェント用に、自分のマシン上でオープンモデルを動かしましょう。プロンプトとコードはマシン上に残り、モデルに送られたものは何もマシンから出ません。次で始めましょう。

```bash
omarchy agent local use best
```

または、トップバーのエージェントパネルで + を選んでから Local AI を選んでください。これは、モデルがこのマシンに収まる場合に表示されます。初回は、モデルを動かす Podman がインストールされ、NVIDIA マシンではそれらに GPU を渡す NVIDIA の container toolkit がインストールされます。次に Omarchy が、このマシンに推奨されるモデルを選び、ダウンロードして起動します。ダウンロードは数十 GB になり、モデルが動いている間はマシンのメモリの大半が使用されると想定してください。Flash Next は 256K の完全なコンテキストで約 100 GiB を使います。必要なメモリを他のモデルが押さえている場合、停止した状態でセットアップされるので、どれかを止めればいつでも起動できます。モデルはログアウト時に止まります。メモリを他のものに必要なときは、自分で止めてください。

`omarchy agent local list` は選択肢を表示し、収まらないものがなぜ収まらないのかを説明します。別のものをセットアップするには、`omarchy agent local use <recipe>` を実行してください。現在、128 GB の Strix Halo マシンでは `qwen3.8-flash-next-gufo` と `qwen3.8-27b-gufo` が利用できます。27B は約 40 GiB を使うので、他の作業用の余地が残ります。新しい recipe と推奨は、パッケージを通じて `omarchy update` とともに届きます。

セットアップしたモデルは、エージェントパネルでサブスクリプションの隣に、それぞれ専用の行ができます。再生で起動し、一時停止で止めてメモリを解放し、ターミナルボタンでその上でエージェントを開きます。メモリに一緒に収まる場合は複数を同時に実行できます。収まらない場合、Omarchy はどの実行中のモデルを止めればよいか知らせます。行をドラッグして並べ替え、選択した行で Delete を押すと、モデルとそのダウンロードが削除されます。

コマンドラインから、`omarchy agent local start <recipe>` と `omarchy agent local stop <recipe>` が同じことをし、`omarchy agent local status` はすべてのモデルを表示し、`omarchy agent --local` は最後に起動したモデル上でデフォルトのエージェントを開きます（デフォルトのエージェントがローカルモデルを使えない場合は pi です）。OpenAI 互換の任意のクライアントも接続できます。`status` は各モデルのアドレスを表示し（最初のものは `http://127.0.0.1:11435/v1`）、recipe 名がモデル名で、キーは `~/.config/omarchy/agent-local/key` にあります。

`omarchy agent local remove <recipe>` は、モデルと、他のどのモデルも使っていないダウンロードを削除します。

サードパーティの runtime には、その publisher がラベル表示されます。Omarchy はすべてのモデルをネットワークアクセスなしで実行します。

### ローカル LLM

Omarchy は、ローカル LLM モデルを動かす方法として LM Studio と Ollama の 2 つを推奨しています。LM Studio は、オープンのウェイトモデルを見つけ、インストールし、実行するための GUI インターフェイスを提供します。手軽に始めるには素晴らしい方法です。Ollama は同様のことを行う CLI を提供します。しかし、ローカルモデルが初めてなら、私なら LM Studio から始めます。どちらも Omarchy Menu の _Install > AI_ でインストールできます。

### Omarchy Skill

Agent skills は、AI が特定のツールを特定の方法で使う助けをし、Omarchy はシステムをカスタマイズするためのデフォルトの skill が付属します。Hyprland config を調整したり、バーを直したり、テーマをゼロから作ったりするようなことです。これは、Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` と各 `~/.hermes/profiles/*/skills`）、そして汎用の `~/.agents/skills` の skill ディレクトリにシンボリックリンクされており、ほとんどの harness が自動で拾います。

ただし、この skill は実験的なものとして扱うべきです。モデルごとに使う効果も異なります。まず plan mode で実行するのが最善です。そうすれば、エージェントが何を変更したいのか把握できます。そして、エージェントがすべてをめちゃくちゃにしたら、変更をロールバックしたり、さらには `omarchy reinstall configs` を呼び出したりする覚悟をしておいてください。
