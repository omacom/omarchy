### エージェントのインストールと更新

HermesとOpenClawを除き、これらのエージェントはmiseのlazy installationを使います。初回起動時にCLIがインストールされ、それ以降の起動ではそれが再利用されます。miseはまた、インストール済みエージェントに新しいリリースがないかを、最大で4時間に1回、起動直前またはshellプロンプトでバックグラウンドで確認します。その更新が失敗したりオフラインだったりした場合、インストール済みのバージョンが動作します。`omarchy update`は、Omarchyの他の部分と一緒にインストール済みエージェントも更新し、`mup`はmise管理のツールだけを更新します。

`claude update`、`codex update`、アプリ内の更新ボタンなど、エージェント自身のアップデーターは、mise管理のインストールを更新しません。`codex update`は失敗し、`claude update`は成功したと報告しながら、miseが追跡しない別のコピーをインストールすることがあります。エージェントのネイティブインストーラーとアップデーターを使いたい場合は、それを`disable_tools`に追加してください。[プリインストールされたCLIツール](18-development-tools.md#preinstalled-cli-tools)を参照してください。

必要なタイミングより前に、設定済みのすべてのlazyツールをインストールするには、`mise install --include-lazy`を実行してください。これにはエージェントに加え、Omarchyの他のデフォルトCLIツールも含まれます。単一ツールのインストールや独自のインストールを使う方法については、[プリインストールされたCLIツール](18-development-tools.md#preinstalled-cli-tools)を参照してください。

`grok`は、`claude`や`codex`と同じように、miseのファーストパーティ`grok`パッケージ経由でインストールされます。`grok`を実行するか、_Agent > Harness_で選択してください。x.aiの`curl | bash`インストーラーはやめてください。その方法では`~/.grok/bin`に2つ目のコピーが配置され、`PATH`の先頭にそれが追加され、Omarchyのラッパーが上書きされます。

`dsh`はブラウザUIを`127.0.0.1:3080`で開き、起動したディレクトリをデフォルトのワークスペースとします。そのブラウザUIは開始プロンプトを受け取らないので、`omarchy agent prompt`で開くとプロンプトがクリップボードに置かれ、貼り付けられるようになります。OmarchyはこれをDeepSeekのno-approval権限プリセットで起動します。DeepSeek Harnessは、公式モデルAPIを使うとセッションログをDeepSeekにアップロードします。そのブラウザUIの_Settings > General > Upload Session Log_でオフにしてください。送信するフィードバックもセッションと一緒にアップロードされます。ただし、`DSH_TELEMETRY_MODE=DISABLED`で起動した場合は除きます。

### デフォルトエージェント

デフォルトエージェントは`omarchy default agent <name>`で選ぶか、Omarchy Menu（`Super + Space`）の_Agent > Harness_で選びます。エージェントがまだインストールされていない場合、選択するとまずそれがインストールされ、アプリランチャー内のAgentの隣に、そのエージェント専用のランチャーも追加されます。新鮮なOmarchyでは、1回限りの通知でこの選択を促されます。

Claudeを選ぶと、Chromium、Chrome、Brave、Brave Origin、Edge向けのブラウザ拡張機能のセットアップも試みます。拡張機能のセットアップはすべてのユーザーに適用され、システムパスワードを求められる場合があります。キャンセルしたり拡張機能のインストールに失敗したりしても、Claudeは選択され起動します。ブラウザを再起動し、プロンプトが表示されたら拡張機能を有効にし、Claudeにサインインして接続を完了してください。接続を確認するにはClaudeで`/chrome`を実行してください。FirefoxとZenはこの拡張機能をサポートしていません。このセットアップが追加される前にすでにClaudeがデフォルトだった場合、もう一度選択すれば拡張機能がインストールされます。

選択が完了したら、`Super + Shift + Ctrl + A`でデフォルトエージェントを専用ターミナルウィンドウで起動します（まだ選択していない場合はピッカーが表示されます）。`omarchy agent prompt "Review this project"`を使えば、タスクに直行させることもできます。FreebuffとDeepSeek Harnessは開始プロンプトを受け取らないので、代わりにプロンプトをクリップボードに置いた状態で開きます。この方法で起動したエージェントは、それぞれの、止まって尋ねないモードで無人で動作します。実際にいろいろ実行する心構えをしておいてください！MiniMax Codeにはインタラクティブセッション向けのそのようなモードがないので、通常どおり権限を求めてきます。また、エージェントはホームディレクトリへの信頼を記憶することを拒否するので、`$HOME`からの起動は代わりに`~/Work`で始まります。

ターミナルショートカットもあります。`a`は現在のターミナル内でデフォルトエージェントをインライン実行し、`c`、`cx`、`cy`はOpenCode、Claude Code、Codexを直接起動します（こちらも自動承認モードです）。テーマ変更もエージェントに同期されます。Claude Code、Pi、OpenCode、Hermes（Omarchyがインストール済みの場合）は、Omarchyテーマを切り替えるとそれに追従します。

### あなたのエージェント指示

すべてのエージェント向けの個人ルールは、共有skillsが入った`~/.agents/skills`の隣にある`~/.agents/AGENTS.md`に置きます。_Agent > Instructions_で開いてください。これにより、独自のグローバルファイルを保持する各harnessにもリンクされます。`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`~/.pi/agent/AGENTS.md`、`~/.config/opencode/AGENTS.md`、Copilotの`~/.copilot/copilot-instructions.md`などです。CrushとAmpは`~/.config/AGENTS.md`リンクを読み、omp、Kimi、DeepSeek Harnessは`~/.agents/AGENTS.md`を直接読みます。デフォルトエージェントを選ぶことでもリンクされます。すでに持っていた指示ファイルは、共有のものがまだなかった場合は共有用となり、そうでない場合はリンクの隣に`.bak`として保持されます。別のエージェントをインストールした後に再リンクするには、`omarchy agent instructions`を実行してください。

### エージェントパネル

トップバーにはエージェントのアイコンがあります。エージェントをセットアップする前は、そのパネルがClaude、Codex、Grokへのサインインを案内し、最初に設定したものがデフォルトエージェントになります。その後は、このパネルがすべてのサブスクリプションを1ページにまとめます。各エージェントとアカウント、そのプラン、5時間セッション制限と週間制限それぞれのメーターとリセットまでの時間（ホバーで正確なパーセンテージ）、またはプリペイド残高が表示され、その上には、今週のトークン数や最も使用したモデルなど、すべてを通じて使用したものが順に切り替わる行があります。_Make something cool_の下では、新しいテーマ、プラグイン、アプリ、ゲーム向けのスタータープロンプトが提供され、そのタスクはデフォルトエージェントに引き渡されます。アプリはOmarchy独自のHype、Monologue、Omacutと同じ方法で、C++とQt Quickで構築され、omarchy-make-appエージェントskillに従い、必要なコンパイラとQtの部品はインストール済みで提供されます。ゲームはomarchy-make-gameエージェントskillに従い、`~/Games/vibes`内の単一のthree.jsページとなり、すべてが現在のテーマの1つのGame Vibesランチャーから開きます。three.jsはWebから読み込むので、開始するには接続が必要です。Claude Code、Codex、Grok、Kimi、CursorとそのGrok Bot枠、GitHub Copilot、Muse、Antigravity、Devinは、その制限とともに最初からカバーされ、Kimchiはそのプラン、プリペイドクレジット、支出予算とともにカバーされ、Hermes、Mistral Vibe、Qwen Codeは使用後にそのセッションとトークンを表示します。pi、omp、opencode経由で利用するプロバイダーのプランやキーも表示されます。OpenCode ZenとGo、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan、Syntheticは制限とともに、OpenRouterとDeepSeekはプリペイド残高とともに、Fireworksは過去30日間の支出とともに表示されます。自身のハードウェア上で実行するモデルのトークンも合計に算入されます。モデル自体には専用パネルがあり、[Local models](#local-models)の下で説明します。すべてのエージェントは、課金者ごとに1回だけ数えられ、いくつのharness経由で使っても変わりません。

バーアイコンを左クリックするか`Super + Ctrl + X`を押すとパネルが開き、右クリックでデフォルトエージェントを起動し、中クリックで更新します。その背後にある利用記録は、`omarchy agent usage update`によって15分ごとに再生成され、パネルは同期フォルダ経由で他のマシンからの利用状況をマージすることもできます。完全な設定については、`$OMARCHY_PATH/shell/plugins/agents/`の下のREADMEを参照してください。

### 複数のサブスクリプション

個人用のMaxと仕事用など、Claude、Codex、Grokのプランを複数支払っている場合、Omarchyはすべてをサインインしたままにして、その間を移動できます。エージェントパネルの+でサブスクリプションを追加すると、その場で案内してくれます。または`omarchy agent account add claude Work`（あるいは`codex`や`grok`）でも追加できます。CLIがなければインストールされます。プロバイダーの初のアカウントは、CLIが常に見ているまさにその場所で、通常のブラウザ経由でサインインします。それ以降のすべてのアカウントはプライベートウィンドウ経由でサインインします。これにより、ブラウザで既にサインインしているアカウントが誤って拾われることがなくなります。そこでは追加しようとしているアカウントとしてサインインし、それ以前に開いていたプライベートウィンドウがあれば先に閉じてください。これを行うために絶対にCLIからログアウトしないでください。ログアウトすると保存済みサインインが無効になり、そのアカウントは再度追加しなければならなくなります。

サブスクリプションログインをSSH経由で別のOmarchyマシンにコピーするには、`omarchy agent account copy user@laptop`を実行してください。宛先にレシーバーがインストールされていない場合、送信側が一時的なレシーバーを供給します。そのため、古いOmarchyマシンでも更新なしでアカウントを受け取れます。インストール済みのレシーバーが優先されます。これはClaude、Codex、Grokのすべてのサブスクリプションをコピーします。プロバイダー名を追加すればそれらを選択でき、`omarchy agent account copy laptop claude`のようになります。アカウント名とコマンドIDはソースと一致し、宛先にすでに存在するアカウントも含まれます。無関係な宛先アカウントについては、名前が競合した場合に数字サフィックスが付きます。設定、skills、プラグイン、会話履歴は各マシンローカルに留まります。

既存の宛先認証情報は保持されます。そこですでにサインインしているソースアカウントは、認証情報を置き換えることなく名前が同期され、他のアカウントはそれに並べて追加されます。一致するアカウントの保存済み認証情報を置き換えるには、宛先でそのアカウントのセッションを終了した後、`omarchy agent account copy --replace laptop claude`を使ってください。新鮮な宛先は、ソースのアクティブアカウントと切り替え設定も取得します。確立済みの宛先は独自のものを保持します。

認証情報はSSH経由で移動し、宛先のプライベートファイルに保存されます。信頼できるマシンにだけコピーしてください。これは1回限りのコピーで、継続的な同期ではありません。Codexのリフレッシュトークンは別のマシンによってローテーションされる場合があり、コピーしたログインが更新を必要とする状態になることがあります。複数マシンで同時に使う場合は、個別にサインインするのが最も確実な選択です。[Codexのアカウント認証ガイダンス](https://developers.openai.com/codex/auth/ci-cd-auth)を参照してください。

プロバイダーごとにアクティブなアカウントは1つで、すべての新規セッションはそれとして開始します。`cx`、`cy`、素の`claude`、`codex`、`grok`、`omarchy agent`経由で起動されるもの、`PATH`上でCLIを見つけるスクリプトやエディタもそうです。切り替えは`omarchy agent account use work`（戻すには`omarchy agent account use main`）で行うか、パネルでアカウントの番号を押してから`Enter`を押す（またはUseボタンをクリックする）ことで行います。実行中のClaudeセッションも次のメッセージから切り替わります。すべてのClaudeセッションは`~/.claude`で実行され、そこには常にアクティブなアカウントのサインインが入っています。古いOmarchyによってアカウント固有フォルダで開始されたClaudeセッションは、終了するまでそのサインインを保持します。そのため切り替えではそれらのセッション名を表示し、それらがなくなったら自動で完了します。実行中のCodexおよびGrokセッションは、開始したアカウントのままです。会話履歴、設定、skills、プラグインはアカウント間で共有されるので、同じフォルダで`claude --continue`を実行すると、新しいアカウントで中断した場所から続きます。

アカウントが複数ある場合、パネルでは各アカウントの制限が横並びで表示され、アクティブなものに印が付きます。デフォルトでは、アクティブなアカウントが制限の95%を超えると通知が送られ、その通知をクリックすると余裕が最も大きいアカウントに切り替わります。パネルでアカウントの行にホバーして、Useの横に現れるAutoswitchをクリックする（または`m`を押す）か、`omarchy agent account mode auto`を実行すると、自動的に切り替わるようになります。これがオンの間はAutoswitchがUseの代わりになり、再度クリックすると通知に戻ります。`omarchy agent account mode auto 90`のように数字を加えればしきい値を変更できます。すべてのアカウントがしきい値を超えている場合は、一度だけその知らせがあり、どれが最初に空くかも示されます。アクティブなアカウントがそのしきい値から15ポイント以内（デフォルトで80%）にある間、その制限は15分ごとではなく3分ごとに確認されます。

`omarchy agent account list`はすべてのアカウントと最新の制限を表示し、`omarchy agent account remove work`は1つを忘れ、`omarchy agent account rename primary Hey`は名前を変更します（またはパネルでアカウント名をクリックします）。これらのコマンドはデフォルトエージェントのアカウントに対して動作します。別のプロバイダーにアクセスするには、先にそれを名前指定してください。例：`omarchy agent account use codex side`。`~/.claude`や`~/.codex`にすでに持っていたログインが_Main_アカウントです。Codexのものはその場に留まります。Claudeのものは、別のアカウントがアクティブな間は独自のフォルダで待機します。約8時間以上未使用のアカウントは_Sign-in required_と表示される場合があります。クリックすればパネル内で直ちにそのアカウントに再サインインでき、またはそのアカウントに切り替えてセッションを開始すれば、サインインが自動的に更新されます。`claude mcp add`で追加したMCPサーバーは、すべて`~/.claude`で実行されるので、すべてのClaudeアカウントに届きます。CodexとGrokの場合、アカウント追加時に持っていたサーバーはそのアカウントに付いて行きますが、後のものは追加したアカウントのみに届きます。Claude Desktopは独自のサインインを保持し、CLIバイナリへの絶対パスで設定されたCodexまたはGrokツールはこの切り替えに従いません。明示的な`CLAUDE_CONFIG_DIR`、`CODEX_HOME`、`GROK_HOME`は、選択されたアカウントよりも優先されます。

### クラッシュ診断

Omarchyはプロセスのクラッシュについてsystemd-coredumpを監視します。デフォルトエージェントを選ぶと、コアダンプするあなたのプログラムはすべて「Process crashed」通知を表示します。クリックすると、Omarchyのomarchy-diagnose-crash skillとともにそのクラッシュがデフォルトエージェントに渡されます。そのskillは、コアダンプから事実を確立し、そのクラッシュを上流に報告する価値があるかどうかを決める手順をエージェントに案内します。`coredumpctl list`で得た任意のPIDに対して`omarchy agent crash <pid>`を使い、手動で実行することもできます。

この監視はデフォルトでオンです。_Trigger > Toggle > Crash Capture Off_の下（あるいは`omarchy toggle crash-capture`）でオフにすると通知は止まります。`omarchy agent crash <pid>`は手動では引き続き動作します。

クラッシュはプログラム1つずつ無音化もでき、診断の最後で提案されるのがそれです。`omarchy crash mute hyprland`はそのプログラムだけの通知を止め、`omarchy crash mute hyprland off`はそれを取り戻し、`omarchy crash mute`単独では無音化したものをリストします。バイナリのパスも名前と同じくらい気軽に受け付けます。`omarchy crash mute /usr/bin/hyprland`でも同じことになります。空白を含む名前は引用符で囲んでください。例：`omarchy crash mute 'Some App'`。他のすべては引き続き通知し、無音化したプログラムも引き続きクラッシュします。これはリマインダーを隠すもので、何も修正しません。

### デスクトップアプリ

_Install > AI_メニューには、グラフィカルなAIアプリもいくつか入っています：Amp Desktop、Antigravity Desktop、ChatGPTデスクトップアプリ、Claudeデスクトップアプリ（Chat、Cowork、Claude Codeのタブを持つAnthropicのLinux beta）、xAIのモデルとチャットするGrok Bot、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexityデスクトップアプリ、T3 Codeです。Grok Botはデスクトップチャットアプリです。コーディングエージェントは`grok`コマンドです。

Hermes Desktopは知っておくべき存在です。なぜなら、マシンには1つのHermesしかなく、それはこのアプリのものだからです。Hermesは決してアプリ経由以外でインストールされず、デフォルトエージェントが実行する`hermes`コマンドはアプリのものです。Hermesをデフォルトエージェントとして選ぶと、_Install > AI_項目がするのと全く同じものがインストールされます：パッケージと、Hermes独自のインストーラーによってセットアップされた`~/.hermes`下のHermesランタイムで、初回は数分かかります。そのランタイムこそが、ターミナルの`hermes`コマンド、デフォルトエージェント、アプリがすべて使う唯一のHermesであり、Omarchyのリリースを待つことなく、`hermes update`で自身を更新します。インストールすると、HermesにはOmarchyテーマが`omarchy`という名前のskinとして付与され、すべてのHermesの表面がテーマ切り替えに追従します。そうしたくない場合は、HermesのAppearance設定、または`/skin`で別のものを選んでください。Omarchyはその選択には干渉しません。_Remove > AI_でアプリを削除すると、まずHermesが閉じられ（ゲートウェイを含む）、そのランタイムも一緒に削除されますが、あなたがそう指示しない限り、あなたのチャット、メモリ、Hermesが自分自身のために書いたskillsは保持されます。そのデータと接続設定も削除するかどうかを尋ねますが、デフォルトはnoです。

OpenClawのデスクトップ体験は、そのControl UIです。これは独自のローカルゲートウェイをバックエンドとするWebアプリとして開きます。OpenClawは`~/.openclaw`にあり、自身を更新します。Control UIの「Update Gateway」ボタンを使うか`openclaw update`を実行してください。ゲートウェイは新しいバージョンで再起動します。Omarchyが選ぶのは、新規インストールが開始するリリースだけです。OpenClawはデフォルトエージェントにもなれます。_Agent > Harness_で選ぶと、`~/.openclaw`にその同じコピーがセットアップされ、エージェントはゲートウェイに接続されたOpenClawのターミナルUIを開きます。_Remove > AI_でOpenClawを削除すると、ゲートウェイサービスとアプリが一緒に削除され、その後、`~/.openclaw`も削除するかどうか尋ねます。そこにはOpenClaw自体やダウンロードするプラグインランタイムに加え、チャットと認証情報も保持されているからです。デフォルトでは保持し、OpenClawを再度インストールするとそれを再び取り上げます。

Herdr Desktopは[Herdr](https://herdr.dev)のデスクトップアプリです。ウィンドウを閉じてもそのコアで実行し続けるターミナルとコーディングエージェントのスペース、タブ、ペインを提供します。パッケージではなくHerdr独自のインストーラーから提供されるので、`~/.local/share/herdr-app`に配置され、まだ持っていない場合は`~/.local/bin/herdr-core`にそのコアも一緒に持ち込み、両方とも自身で更新します。これはOmarchyが`Super + Ctrl + Return`に用意する`herdr`コマンドを置き換えるのではなく、それと並んで存在し、そのコマンドのダイレクトキーを取得します：`Alt + Return`と`Alt + Shift + Return`はペインを下または右に分割し、`Alt + Escape`は閉じ、`Ctrl + Alt + Arrow`はペイン間を移動し、`Alt + 1..9`と`Alt + Left/Right`はタブを選び、`Alt + Up/Down`はスペース間を移動します。`Ctrl + 1..9`はスペースを選び、`Alt + Shift + Up/Down`はエージェントを順に移動します。`Ctrl + Space`のプレフィックスキーはターミナル専用に留まります。アプリはシーケンスの平のCtrlキーを保持できないからです。Omarchyはこれらを`~/.config/herdr-app/keys.json`に書き込み、`omarchy-refresh-herdr-app`で復元します。インストールするとHerdrのOmarchyテーマが選ばれ、それ以降あなたのOmarchyテーマに追従します。Herdrはライトモード用に1つ、ダーク用に1つのテーマを保持するので、ダークなOmarchyテーマとライトなOmarchyテーマを切り替えた後は、もう一方のモード用にHerdrのテーマピッカーでOmarchyをもう一度選んでください。

T3 Codeは、パッケージではなく`~/.local/share/t3code`にある公式AppImageリリースから実行され、自身で更新します。インストールするとStableチャネルで開始するかNightlyチャネルで開始するか尋ねます。後でT3 Codeの設定で切り替えてください。あなたのスレッドと設定は`~/.t3`にあり、_Remove > AI_でT3 Codeを削除すると、それらも一緒に削除されます。

### ローカルモデル

あなた自身のマシンでオープンなモデルを実行して、コーディングエージェントに使わせましょう。あなたのプロンプトとコードはマシンに留まり、モデルに送られたものは何もマシンから出ていきません。次から始めてください。

```bash
omarchy models use best text
```

これにより、そのマシンに最適なテキストモデルがセットアップされます。これはあなたのエージェントが使う種類です。画像、ビデオ、音楽のモデルにもそれぞれ最適なものがあります。`omarchy models use best image`、`video`、または`music`です。各種類についてそのマシンでの選択を確認するには、`omarchy models use best`を実行してください。

あるいは、トップバーのエージェントアイコンの横にある輝きアイコンから、あるいはSuper + Ctrl + Alt + Xでローカルモデルパネルを開き、+を選択してください。そのアイコンは、モデルがそのマシンに適合すると表示されます。モデルを実行するPodmanはOmarchyに付属し、NVIDIAマシンではNVIDIAのコンテナツールキットも付属してGPUを提供します。どちらかがない場合、最初のセットアップでインストールされます。その後、Omarchyはそのマシンに推奨されるモデルを選び、ダウンロードして開始します。数十GBのダウンロードと、実行中はマシン メモリの大半が使用されることを覚悟してください。Flash Nextはフル256Kコンテキストで約100 GiBを使います。必要なメモリを他のモデルが占有している場合、そのモデルは停止状態でセットアップされ、そのうち1つを停止すれば開始できる状態になります。モデルはログアウトで停止します。メモリが他に要る時は自分で止めてください。

`omarchy models list`は選択肢を表示し、一部が適合しない理由を説明します。別のものをセットアップするには`omarchy models use <recipe>`を実行してください。今日、128 GB Strix Haloマシン向けに`qwen3.8-flash-next-gufo`と`qwen3.8-27b-gufo`が利用可能で、27Bは約40 GiBを使うので他の作業の余地が残ります。IntelのArc B390を搭載した64 GBラップトップでは、`qwen3.6-35b-a3b-llamacpp`が約30 GiBで動作します。新しいレシピと推奨事項は、パッケージ経由で`omarchy update`とともに到着します。

セットアップしたモデルごとに、ローカルモデルパネルに独自の行ができ、再生ボタンで開始、一時停止ボタンで停止してメモリを解放、ターミナルボタンでそのモデル上でエージェントを開きます。上部全体にバーが表示され、マシンのメモリがOmarchy自体（システムとあなたのアプリ）、実行中の各モデル、空き容量にどのように分割されているかが示されます。停止中のモデルにポインタを合わせると、バーはそれが収まるかどうか、あるいはどれだけ不足しているかを表示します。メモリに一緒に収まる場合は複数を同時に実行できます。1つが収まらない場合、Omarchyはどの実行中モデルを止めればいいかを伝えます。行はロゴでドラッグして順序を変更でき、選択した行でDeleteを押すとそのモデルとダウンロードが削除されます。

セットアップしたモデルごとに、アプリランチャーにも独自のエントリが加わります。そのモデル名で、メーカーのロゴが付き、Claude、Codex、Grokへサインインすると追加されるのと同じ方法です。これによりそのモデル上でエージェントが開き、実行中でなければまずそのモデルを開始します。ターミナルにはロード中であることが表示され、立ち上がったらエージェントに引き継ぎます。モデルを削除するとそのエントリも削除されます。

すべてのモデルがコーディング向けというわけではありません。画像、ビデオ、音楽のモデルは代わりにFantasiで開きます。Fantasiは、このマシン上で実行されるモデルで画像、ビデオ、音楽を作るためのOmarchyのアプリで、ランチャーエントリとローカルモデルパネルのその行のどちらからも開けます。

モデルはセットアップされた通りのまま実行され続けるので、Omarchyのアップデートでエージェントの下でモデルが再起動されることは決してありません。Omarchyが、セットアップ済みモデル向けの新しいランタイムや新しいウェイトを持っている場合、その行には更新ボタンが表示されます。押すとモデルがバックグラウンドで再度セットアップされ、変更されたものだけがダウンロードされ、新しいバージョンで再起動します。停止していたモデルは停止したままです。`omarchy models update`はターミナルからすべてのモデルについて同じことを行います。

コマンドラインから、`omarchy models start <recipe>`と`omarchy models stop <recipe>`は同じことを行い、`omarchy models status`はすべてのモデルを表示し、`omarchy agent --local`は最後に開始したモデル上でデフォルトエージェントを開きます。pi、OpenCode、Qwen Codeが利用できます。他のデフォルトの場合はpiで開き、piがない場合はOpenCodeで開きます。piは自身のモデルピッカーにも、セットアップしたすべてのモデルとペアリングしたマシンのモデルをリストします。そのため素の`pi`でもそれらに到達できます。OpenAI互換クライアントも接続できます。`status`には各モデルのアドレスが表示され（最初は`http://127.0.0.1:11435/v1`）、レシピ名がモデルとなり、キーは`~/.config/omarchy/agent-local/key`にあります。

`omarchy models remove <recipe>`はモデルと、他のモデルが使用していないダウンロードを削除します。

サードパーティ製ランタイムにはその発行元がラベル付けされます。Omarchyはすべてのモデルをネットワークアクセスなしで実行します。

### ローカルLLM

Omarchyは、ローカルLLMモデルを実行する方法としてLM StudioとOllamaの2つをお勧めします。LM Studioは、オープンウェイトモデルを見つけ、インストールし、実行するためのGUIインターフェイスを提供します。手軽に始めるには素晴らしい方法です。Ollamaは、同様のことを行うためのCLIを提供します。しかし、ローカルモデルに慣れていないなら、私ならLM Studioから始めます。どちらもOmarchy Menuの_Install > AI_でインストールできます。

### Omarchy skills

エージェントskillは、AIに特定のツールを特定の方法で使わせる助けとなり、Omarchyはその7つを提供します。omarchy skillは、Hyprland設定の調整やバーの調整など、システムのカスタマイズをカバーします。omarchy-make-theme、omarchy-make-plugin、omarchy-make-app、omarchy-make-gameは新しいものを作ることをカバーし、omarchy-contributeはバグ報告や修正の上流送信をカバーし、omarchy-diagnose-crashはクラッシュのコアダンプに取り組みます。これらはClaude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills`と各`~/.hermes/profiles/*/skills`）、汎用的な`~/.agents/skills`のskillディレクトリにシンボリックリンクされており、ほとんどのharnessが自動的に取得します。同じ名前の独自のskillフォルダがある場合はそちらが優先されます。

ただし、これらのskillは実験的なものとして扱ってください。異なるモデルはそれぞれ異なる効用で使用するでしょう。まずプランモードで実行するのが最善です。そうすればエージェントが何を変更したいのか把握できます。そして、エージェントがすべてを台無しにしたら、変更をロールバックしたり、`omarchy reinstall configs`を呼び出す準備さえしておいてください。
