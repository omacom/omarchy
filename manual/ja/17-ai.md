### エージェントのインストールと更新

Hermes と OpenClaw を除き、これらのエージェントは mise の遅延インストールを使います。初回起動時に CLI がインストールされ、それ以降の起動ではそれが再利用されます。mise はまた、インストール済みのエージェントに新しいリリースがないか、最大で4時間に一度、起動直前またはシェルプロンプトでバックグラウンドで確認します。その更新が失敗したり、オフラインだったりした場合は、インストール済みのバージョンが動作します。`omarchy update` は、インストール済みのエージェントを Omarchy の他の部分と一緒に更新し、`mup` は mise 管理のツールだけを更新します。

`claude update`、`codex update`、アプリ内の更新ボタンなど、エージェント自身のアップデーターは mise 管理のインストールを更新しません。`codex update` は失敗し、`claude update` は成功したと報告しながら、mise が追跡しない別のコピーをインストールすることがあります。エージェント独自のインストーラーとアップデーターを使いたい場合は、それを `disable_tools` に追加してください。[プリインストールされた CLI ツール](18-development-tools.md#preinstalled-cli-tools) を参照してください。

必要になる前に設定済みの遅延ツールをすべてインストールするには、`mise install --include-lazy` を実行してください。これにはエージェントだけでなく、Omarchy の他のデフォルト CLI ツールも含まれます。単一のツールのインストールや、独自のインストールを使う方法については、[プリインストールされた CLI ツール](18-development-tools.md#preinstalled-cli-tools) を参照してください。

`grok` は、`claude` や `codex` と同じように、mise のファーストパーティ `grok` パッケージ経由でインストールされます。`grok` を実行するか、エージェントパネルでスターを付けてください。x.ai の `curl | bash` インストーラーは避けてください。その方法だと `~/.grok/bin` に2つ目のコピーが置かれ、`PATH` の先頭に追加され、Omarchy のラッパーが上書きされます。

`dsh` は `127.0.0.1:3080` でブラウザ UI を開き、起動したディレクトリをデフォルトのワークスペースとします。そのブラウザ UI は開始プロンプトを受け取らないので、`omarchy agent prompt` はプロンプトをクリップボードに入れた状態でそれを開き、貼り付けられるようにします。Omarchy は DeepSeek の承認なし権限プリセットでこれを起動します。DeepSeek Harness は、公式モデル API を使うとセッションログを DeepSeek にアップロードします。そのブラウザ UI の _Settings > General > Upload Session Log_ でオフにしてください。送信したフィードバックもセッションと一緒にアップロードされます。ただし `DSH_TELEMETRY_MODE=DISABLED` で起動した場合は除きます。

### デフォルトエージェント

デフォルトエージェントは、エージェントパネルでエージェントの横にあるスター（デフォルトのものでは塗りつぶされています）か、`omarchy default agent <name>` で選んでください。後者は、そこに項目がないハーネスでも指定できます。エージェントがまだインストールされていない場合、選ぶとまずインストールされ、アプリランチャーの Agent の横に専用のランチャーも追加されます。新しい Omarchy では、一度だけ表示される通知でセットアップを促され、それを開くとエージェントパネルが開きます。

Claude を選ぶと、Chromium、Chrome、Brave、Brave Origin、Edge 用のブラウザ拡張機能のセットアップも試みます。その拡張機能のセットアップはすべてのユーザーに適用され、システムパスワードを求められることがあります。キャンセルしたり拡張機能のインストールに失敗したりしても、Claude は選択されて起動します。ブラウザを再起動し、求められたら拡張機能を有効化し、Claude にサインインして接続を完了してください。接続を確認するには Claude で `/chrome` を実行してください。Firefox と Zen はこの拡張機能に対応していません。Claude がすでにデフォルトだった状態でこのセットアップが追加された場合は、もう一度選択すると拡張機能がインストールされます。

一度選べば、`Super + Shift + Ctrl + A` で専用のターミナルウィンドウでデフォルトエージェントが起動します（まだ選んでいない場合はピッカーが表示されます）。`omarchy agent prompt "Review this project"` のように、タスクを直接渡して起動することもできます。Freebuff と DeepSeek Harness は開始プロンプトを受け取らないので、代わりにプロンプトをクリップボードに入れた状態で開きます。この方法で起動したエージェントは、それぞれの「止まって聞かない」モードで無人で動作します。本当にいろいろ実行しますので、その覚悟をしておいてください！ MiniMax Code には対話セッション用のそうしたモードがないので、通常どおり権限を求めます。また、エージェントはホームディレクトリに対する信頼を覚えることを拒否するため、`$HOME` から起動した場合は代わりに `~/Work` で始まります。

ターミナルのショートカットもあります。`a` は現在のターミナルでデフォルトエージェントをインラインで実行し、`c`、`cx`、`cy` は OpenCode、Claude Code、Codex を直接起動します（これも自動承認モードです）。テーマの変更もエージェントに同期されます。Claude Code、Pi、OpenCode、そして Hermes（Omarchy がインストールした後）は、Omarchy のテーマを切り替えるとそれに追随します。

### あなたのエージェントへの指示

すべてのエージェント向けの個人的なルールは、`~/.agents/skills` の共有スキルと並んで、`~/.agents/AGENTS.md` に入れます。エージェントパネルの + の横にあるドキュメントアイコンで開くか、`omarchy agent instructions --edit` で開いてください。後者は、独自のグローバルファイルを持つ各ハーネスにもリンクします：`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`~/.pi/agent/AGENTS.md`、`~/.config/opencode/AGENTS.md`、Copilot の `~/.copilot/copilot-instructions.md` などです。Crush と Amp は `~/.config/AGENTS.md` リンクを読み、omp、Kimi、DeepSeek Harness は `~/.agents/AGENTS.md` を直接読みます。デフォルトエージェントを選ぶと、そちらにもリンクされます。すでに持っていた指示ファイルは、共有のものがまだない場合はそれが共有のものになり、そうでない場合はリンクの横に `.bak` として保持されます。別のエージェントをインストールした後に再リンクするには、`omarchy agent instructions` を実行してください。

### エージェントパネル

トップバーにはエージェントアイコンがあります。エージェントをセットアップする前は、そのパネルには開始方法が3つ提示されます：Claude、Codex、Grok、Gemini、Muse、Cursor、または Copilot のサブスクリプションにサインインする（または More の下にある OpenCode Go、MiniMax、Synthetic、または Z.ai のコーディングプラン）；Fireworks、OpenCode Zen and Go、OpenRouter、または More の下にある DeepSeek や OpenCode がサインインするその他のプロバイダーで従量課金する（これらはすべて OpenCode で実行されます）；または、あなたのコンピューターに合うモデルがある場合、そのコンピューターに最適なモデルを実行する、のいずれかです。最初に完了したものがあなたのデフォルトエージェントになり、パネルの +、または Omarchy Menu の _Agent > Add_ から、後からでも同じ3つが提示されます。その後は、パネルはすべてのサブスクリプションを1ページにまとめます：各エージェントとアカウントとそのプラン、5時間セッション制限と週間制限それぞれのメーターとリセットまでの時間（ホバーで正確なパーセンテージ表示）、またはプリペイド残高が、それらすべてを通じて使ったものを順に切り替えて表示する行の下に並びます。例えば今週のトークン数や最もよく使ったモデルなどです。_Make something cool_ の下では、新しいテーマ、プラグイン、アプリ、ゲームのスタータープロンプトが提示され、そのタスクをデフォルトエージェントに渡します。アプリは Omarchy 自身の Hype、Monologue、Omacut と同じ作り方で、C++ と Qt Quick で、omarchy-make-app エージェントスキルに従って構築され、必要なコンパイラと Qt の部品はインストール済みで付いてきます。ゲームは `~/Games/vibes` の単一の three.js ページで、omarchy-make-game エージェントスキルに従い、すべて現在のテーマの1つの Game Vibes ランチャーから開きます。これらは three.js をウェブから読み込むので、開始には接続が必要です。Claude Code、Codex、Grok、Kimi、Cursor とその Grok Bot 枠、GitHub Copilot、Muse、Gemini（Antigravity 経由）、Devin は制限付きでそのまま利用でき、Kimchi はプラン、プリペイドクレジット、支出予算付きで利用でき、Hermes、Mistral Vibe、Qwen Code は一度使うとセッションとトークンが表示されます。pi、omp、opencode 経由で使うプロバイダーのプランとキーも表示されます：OpenCode Zen and Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan、Synthetic は制限付き；OpenRouter と DeepSeek はプリペイド残高付き；Fireworks は過去30日間の支出付きです。自分のハードウェアで実行するモデルのトークンも合計に算入されます。モデル自体には専用のパネルがあり、[ローカルモデル](#local-models) の下で説明します。すべてのエージェントは、課金する側の下で、通すハーネスの数にかかわらず、1回だけ数えられます。

バーのアイコンを左クリックするか `Super + Ctrl + X` を押すとパネルが開き、右クリックでデフォルトエージェントが起動し、中クリックで更新します。その背後にある使用記録は、`omarchy agent usage update` によって15分ごとに再生成され、パネルは同期フォルダ経由で他のマシンからの使用状況を統合することもできます。完全な設定については、`$OMARCHY_PATH/shell/plugins/agents/` の下にある README を参照してください。

### 複数のサブスクリプション

Claude、Codex、または Grok のプランを複数払っている場合 — 例えば個人の Max と仕事用など —、Omarchy はそれらをすべてサインインしたままにして、切り替えて移動できます。サブスクリプションを追加するには、エージェントパネルの + を使うとその場で手順を案内するか、`omarchy agent account add claude Work`（または `codex`、または `grok`）を実行してください。同じ + とコマンドで Gemini（`gemini`）と OpenCode（`opencode`）にサインインし、Fireworks（`fireworks`）または OpenRouter（`openrouter`）の API キーを OpenCode に保存します。このコマンドでは Copilot（`copilot`）、Cursor（`cursor`）、Muse（`muse`）にもサインインします。それらについてはサインインはそれぞれ1つだけ保持されます。CLI がない場合はインストールされます。プロバイダーの最初のアカウントは通常のブラウザ経由でサインインします。ちょうど CLI がいつも見に行く場所です。それ以降の各アカウントはプライベートウィンドウ経由でサインインするので、ブラウザですでにサインインしているアカウントが間違って選ばれることはありません。追加しようとしているアカウントとしてそこでサインインし、すでに開いていたプライベートウィンドウは先に閉じてください。このために CLI からログアウトしてはいけません：ログアウトすると保存済みのサインインが取り消され、そのアカウントをもう一度追加しなければならなくなります。

サブスクリプションのログインを SSH 経由で別の Omarchy マシンにコピーするには、`omarchy agent account copy user@laptop` を実行してください。送信側は、宛先に受信側がインストールされていない場合、一時的な受信側を提供します。そのため古い Omarchy マシンでも更新なしにアカウントを受け取れます。インストール済みの受信側が優先されます。これは Claude、Codex、Grok のすべてのサブスクリプションをコピーします。プロバイダー名を追加するとそれらを選択できます。例えば `omarchy agent account copy laptop claude` です。アカウント名とコマンド ID は送信元と一致します。宛先にすでに存在するアカウントも含みます。関係のない宛先のアカウントで名前が競合する場合は数字の接尾辞が付き、設定、スキル、プラグイン、会話履歴は各マシンにローカルなままです。

宛先に既存の認証情報は保持されます。送信元アカウントがすでにそこでサインインしている場合、その名前は同期されますが認証情報は置き換えられません。他のアカウントはその横に追加されます。一致するアカウントの保存済み認証情報を置き換えるには、宛先でそのアカウントのセッションを終了した後で、`omarchy agent account copy --replace laptop claude` を使ってください。新しい宛先には送信元のアクティブなアカウントと切り替え設定も引き継がれます。すでに確立された宛先は自分のものを保持します。

認証情報は SSH 経由で移動し、宛先ではプライベートファイルに保存されます。信頼できるマシンにのみコピーしてください。これは一度きりのコピーであり、継続的な同期ではありません。Codex のリフレッシュトークンは別のマシンによってローテーションされることがあり、コピーされたログインは更新が必要な状態になることがあります。複数のマシンで同時に使うには、別々のサインインが最も確実な選択です。[Codexのアカウント認証ガイダンス](https://developers.openai.com/codex/auth/ci-cd-auth) を参照してください。

プロバイダーごとにアクティブなアカウントは1つで、すべての新しいセッションはそれで始まります：`cx`、`cy`、素の `claude`、`codex`、または `grok`、`omarchy agent` 経由で起動したもの、`PATH` で CLI を見つけるスクリプトやエディタもです。切り替えは `omarchy agent account use work`（戻すのは `omarchy agent account use main`）で行うか、パネルでアカウントの数字を押してから `Enter` を押す（またはそのスターをクリックする）ことで行います。実行中の Claude セッションも、次のメッセージから切り替わります：すべての Claude セッションは `~/.claude` で実行され、そこには常にアクティブなアカウントのサインインが入っています。古い Omarchy によってアカウント専用フォルダで開始された Claude セッションは、終了するまでそのサインインを保持します。そのため、この切り替えではそれらのセッションの名前が言及され、それらがなくなると自動的に完了します。実行中の Codex と Grok セッションは開始時のアカウントのままでいます。会話履歴、設定、スキル、プラグインはアカウント間で共有されるので、同じフォルダでの `claude --continue` は新しいアカウントで中断したところから続きます。

アカウントが複数ある場合、パネルは各アカウントの制限を並べて表示し、使用中のものには塗りつぶされたスターが付きます。アクティブなアカウントが制限の95%を超えると Omarchy が通知し、通知をクリックすると余裕が最も大きいアカウントに切り替わります。自動で切り替えることは決してありません。しきい値を変えるには `omarchy agent account threshold 90` を使ってください。すべてのアカウントがしきい値を超えている場合は、一度だけ通知され、最初に空くアカウントも合わせて知らされます。アクティブなアカウントがしきい値まで15ポイント以内（デフォルトでは80%）にある間、その制限は15分ごとではなく3分ごとに確認されます。

`omarchy agent account list` はすべてのアカウントと最新の制限を表示し、`omarchy agent account remove work` は1つを忘れ、`omarchy agent account rename primary Hey` は名前を変更します（またはパネルでアカウント名をクリックします）。これらのコマンドはあなたのデフォルトエージェントのアカウントに対して動作します。別のプロバイダーにアクセスするには、最初にその名前を指定してください。例えば `omarchy agent account use codex side` です。`~/.claude` または `~/.codex` にすでに持っていたログインが _Main_ アカウントです。Codex のものはそのままの場所に残ります。Claude のものは、別のアカウントがアクティブな間、専用フォルダで待機します。約8時間以上使われていないアカウントは _Sign-in required_ と表示されることがあります。クリックするとパネルですぐにそのアカウントにもう一度サインインでき、またはそれに切り替えてセッションを開始するとサインインが自動的に更新されます。`claude mcp add` で追加した MCP サーバーは、すべての Claude アカウントで使えます。なぜならそれらはすべて `~/.claude` で実行されるからです。Codex と Grok については、アカウント追加時に持っていたサーバーはそのアカウントに付いてきますが、それ以降のものは追加したアカウントでのみ使えます。Claude Desktop は独自のサインインを保持し、CLI バイナリへの絶対パスで設定された Codex や Grok のツールは切り替えに追随しません。明示的な `CLAUDE_CONFIG_DIR`、`CODEX_HOME`、または `GROK_HOME` は選択されたアカウントより優先されます。

### クラッシュ診断

Omarchy は systemd-coredump でプロセスのクラッシュを監視します。デフォルトエージェントを選んだ後は、あなたのプログラムがコアをダンプするたびに「Process crashed」通知が表示されます — クリックすると、そのクラッシュは Omarchy の omarchy-diagnose-crash スキルとともにデフォルトエージェントに渡されます。そのスキルは、コアダンプから事実を確立し、そのクラッシュが上流に報告する価値があるかどうかを判断する手順をエージェントに案内します。`coredumpctl list` の任意の PID に対して `omarchy agent crash <pid>` で手動で実行することもできます。

この監視はデフォルトで有効です。_Trigger > Toggle > Crash Capture Off_ で（または `omarchy toggle crash-capture` で）オフにすると通知は止まります。`omarchy agent crash <pid>` は手動では引き続き動作します。

クラッシュはプログラムごとに1つずつ黙らせることもできます。それが診断の最後に提示されるものです。`omarchy crash mute hyprland` はそのプログラムだけの通知を止め、`omarchy crash mute hyprland off` は元に戻し、`omarchy crash mute` を単独で実行するとミュートしたものが一覧表示されます。バイナリのパスでも名前でも同じように指定できるので、`omarchy crash mute /usr/bin/hyprland` も同じことをします。名前にスペースが含まれる場合は、`omarchy crash mute 'Some App'` のように引用してください。他のすべてのものは引き続き通知され、ミュートされたプログラムも引き続きクラッシュします — これはリマインダーを隠すもので、何も修正しません。

### デスクトップアプリ

_Install > AI_ メニューには、グラフィカルな AI アプリもいくつかあります：Amp Desktop、Antigravity Desktop、ChatGPT デスクトップアプリ、Claude デスクトップアプリ（Anthropic の Linux ベータ、Chat、Cowork、Claude Code のタブ付き）、xAI のモデルとチャットするための Grok Bot、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexity デスクトップアプリ、T3 Code です。Grok Bot はデスクトップチャットアプリです。コーディングエージェントの方は `grok` コマンドです。

Hermes Desktop は知っておくべき存在です。1台のマシンには Hermes は1つだけあり、それはこのアプリのものだからです：Hermes は常にこのアプリ経由でのみインストールされ、デフォルトエージェントが実行する `hermes` コマンドはこのアプリのものです。Hermes をデフォルトエージェントとして選ぶと、_Install > AI_ の項目と同じものがインストールされます：そのパッケージと、Hermes 自身のインストーラーによってセットアップされる `~/.hermes` の下の Hermes ランタイムで、初回は数分かかります。そのランタイムこそが、ターミナルの `hermes` コマンド、デフォルトエージェント、そしてアプリがすべて使う唯一の Hermes で、Omarchy のリリースを待つのではなく `hermes update` で自己更新します。インストールすると、Hermes には `omarchy` という名前のスキンとして Omarchy テーマも渡され、すべての Hermes の画面がテーマ切り替えに追随します。そうしたくない場合は、Hermes の Appearance 設定か `/skin` で別のものを選んでください。Omarchy はその選択に干渉しません。_Remove > AI_ でアプリを削除すると、まず Hermes が（ゲートウェイを含めて）閉じられ、そのランタイムも一緒に削除されますが、チャット、メモリ、Hermes が自分のために書いたスキルは、指示しない限り保持されます：そのデータと接続設定も一緒に削除するかどうかを尋ねます（デフォルトはいいえです）。

OpenClaw のデスクトップ体験はその Control UI で、独自のローカルゲートウェイをバックエンドとするウェブアプリとして開きます。OpenClaw は `~/.openclaw` にあり、自己更新します：Control UI の「Update Gateway」ボタンを使うか `openclaw update` を実行すると、ゲートウェイは新しいバージョンで再起動します。Omarchy は、新規インストールがどのリリースから始まるかを選ぶだけです。OpenClaw はデフォルトエージェントにもなれます：_Agent > Harness_ で選ぶと、`~/.openclaw` にある同じコピーがセットアップされ、エージェントはそのゲートウェイに接続された OpenClaw のターミナル UI を開きます。_Remove > AI_ で OpenClaw を削除すると、ゲートウェイサービスとアプリも一緒に削除され、次に `~/.openclaw` も削除するかどうか尋ねます。そこには OpenClaw 自体やダウンロードしたプラグインランタイムと並んで、あなたのチャットと認証情報が入っているからです。デフォルトでは保持され、OpenClaw を再インストールするとそれを再び使います。

Herdr Desktop は [Herdr](https://herdr.dev) デスクトップアプリです：スペース、タブ、ペインにターミナルとコーディングエージェントが並び、ウィンドウを閉じてもコアの中で動き続けます。これはパッケージではなく Herdr 自身のインストーラーから来るので、`~/.local/share/herdr-app` にあり、まだ持っていない場合は `~/.local/bin/herdr-core` にコアも一緒に持ち込み、どちらも自己更新します。これは Omarchy が `Super + Ctrl + Return` で提供する `herdr` コマンドの横に置かれ、それに置き換わるものではなく、そのコマンドの直接キーを取得します：`Alt + Return` と `Alt + Shift + Return` はペインを下または右に分割し、`Alt + Escape` はそれを閉じ、`Ctrl + Alt + Arrow` はペイン間を移動し、`Alt + 1..9` と `Alt + Left/Right` はタブを選択し、`Alt + Up/Down` はスペース間を移動します。`Ctrl + 1..9` はスペースを選択し、`Alt + Shift + Up/Down` はエージェント間を順に移動します。`Ctrl + Space` プレフィックスキーはターミナル専用のままです。アプリはシーケンスのために素の Ctrl キーを保持できないからです。Omarchy はこれらを `~/.config/herdr-app/keys.json` に書き込み、`omarchy-refresh-herdr-app` で元に戻します。インストールすると Herdr の Omarchy テーマが選ばれ、それ以降あなたの Omarchy テーマに追随します。Herdr はライトモード用とダークモード用に1つずつテーマを保持するので、ダークな Omarchy テーマとライトな Omarchy テーマを切り替えた後は、もう一方のモードのために Herdr のテーマピッカーで Omarchy をもう一度選んでください。

T3 Code は、パッケージではなく `~/.local/share/t3code` の公式 AppImage リリースから実行されるので、自己更新します。インストールすると、Stable チャネルで始めるか Nightly チャネルで始めるか尋ねます。後から T3 Code の設定で切り替えてください。あなたのスレッドと設定は `~/.t3` にあり、_Remove > AI_ で T3 Code を削除するとそれらも一緒に削除されます。

### ローカルモデル

コーディングエージェント向けに、自分のマシンでオープンモデルを実行しましょう。プロンプトとコードはそのマシンに残ります。モデルに送られたものがそのマシンから出ることはありません。次から始めてください：

```bash
omarchy models use best text
```

これはこのマシンに最適なテキストモデルをセットアップします。エージェントが使うタイプのモデルです。画像、動画、音楽モデルにもそれぞれ最適なものがあります：`omarchy models use best image`、`video`、または `music` です。`omarchy models use best` を実行すると、このマシンに対する各タイプのおすすめが表示されます。

または、トップバーのエージェントアイコンの横にあるスパークルアイコンから、または Super + Ctrl + Alt + X でローカルモデルパネルを開き、+ を選択してください。このアイコンは、モデルがこのマシンに合うときに表示されます。モデルを実行する Podman は Omarchy に付いてきます。NVIDIA マシンでは NVIDIA のコンテナツールキットも付いてきて、それが GPU を使えるようにします。どちらかが欠けている場合、最初のセットアップでインストールされます。次に Omarchy はこのマシンにおすすめのモデルを選び、ダウンロードし、起動します。数十GB のダウンロードと、モデル実行中はマシンのメモリの大半が使用されることを覚悟してください：Flash Next は完全な 256K コンテキストで約 100 GiB を使います。必要なメモリを他のモデルが占有している場合、停止した状態でセットアップされ、どれかを停止すれば起動できるようになります。モデルはログアウトで停止します。他のことにメモリが必要なときは自分で停止してください。

`omarchy models list` は選択肢を表示し、合わないものがある理由を説明します。別のものをセットアップするには、`omarchy models use <recipe>` を実行してください。現在、128 GB の Strix Halo マシン向けに `qwen3.8-flash-next-gufo` と `qwen3.8-27b-gufo` が利用できます。27B は約 40 GiB を使うので、他の作業用の余地が残ります。Intel の Arc B390 を搭載した 64 GB ラップトップでは、`qwen3.6-35b-a3b-llamacpp` が約 30 GiB で動作します。新しいレシピとおすすめは、パッケージ経由で `omarchy update` と一緒に届きます。

セットアップした各モデルは、ローカルモデルパネルに専用の行を持ちます：再生で起動し、一時停止で停止してメモリを解放し、ターミナルボタンでそのモデルでエージェントを開きます。上部にはバーがあり、マシンのメモリが Omarchy 自体（システムとあなたのアプリ）、実行中の各モデル、そして空き容量にどう配分されているかを示します。停止中のモデルをポイントすると、そのバーはそれが収まるかどうか、またはどれだけ不足しているかを示します。メモリに一緒に収まる場合は複数を同時に実行できます。収まらない場合、Omarchy はどの実行中モデルを停止すべきかを知らせます。ロゴで 行をドラッグすると並び替えでき、選択した行で Delete を押すとモデルとそのダウンロードが削除されます。

セットアップした各コーディングモデルは、アプリランチャーにも専用の項目を持ちます。モデルの名前とそのメーカーのロゴ付きで、Claude、Codex、Grok にサインインすると追加されるのと同じ形式です。それを開くとそのモデルでエージェントが開き、モデルが実行中でなければ先に起動します：ターミナルには読み込み中であることが表示され、起動したらエージェントに引き渡されます。モデルを削除すると、その項目も削除されます。

すべてのモデルがコーディング用とは限りません。画像、動画、音楽モデルは代わりに Fantasi で開きます。これはこのマシンで実行されるモデルで画像、動画、音楽を作るための Omarchy アプリで、そこで選ぶか、ローカルモデルパネルの行から選べます。

モデルはセットアップされたとおりに動き続けるので、Omarchy の更新でエージェントの下にあるモデルが再起動されることは決してありません。Omarchy が、セットアップ済みモデルのより新しいランタイムまたはより新しいウェイトを持っている場合、その行に更新ボタンが表示されます：押すと、変更された分だけをダウンロードしながらバックグラウンドでモデルが再セットアップされ、新しいバージョンで再起動します。停止していたモデルは停止したままです。`omarchy models update` はターミナルからすべてのモデルに対して同じことをします。

コマンドラインからは、`omarchy models start <recipe>` と `omarchy models stop <recipe>` が同じことをし、`omarchy models status` はすべてのモデルを表示し、`omarchy agent --local` は、デフォルトエージェントが何であれ、最後に起動したモデルを pi で開きます。そのモデルを、エージェントホットキー、Quake コンソール、そして _Make something_ が開くものにするには、`omarchy default agent local` を実行するか、_Agent > Harness_ で _Local model_ を選んでください。pi はまた、セットアップしたすべてのモデルと、ペアリングしたマシンにあるモデルを独自のモデルピッカーにも表示するので、素の `pi` からもアクセスできます。OpenAI 互換のクライアントも接続できます：`status` は各モデルのアドレスを示します（最初のものは `http://127.0.0.1:11435/v1`）、モデルはレシピ名で、キーは `~/.config/omarchy/agent-local/key` にあります。

`omarchy models remove <recipe>` は、モデルと、他のモデルが使っていないダウンロードを削除します。

サードパーティのランタイムは、その発行者とともに表示されます。Omarchy はすべてのモデルをネットワークアクセスなしで実行します。

### ローカル LLM

Omarchy はローカル LLM モデルを実行する方法として2つをおすすめします：LM Studio と Ollama です。LM Studio は、オープンウェイトモデルを見つけ、インストールし、実行するための GUI インターフェースを提供します。簡単に始めるには素晴らしい方法です。Ollama は同様のことを行う CLI を提供します。でもローカルモデルが初めてなら、私は LM Studio から始めるでしょう。どちらも Omarchy Menu の _Install > AI_ でインストールできます。

### Omarchy スキル

エージェントスキルは、AI が特定のツールを特定の方法で使う助けになり、Omarchy には7つ付いてきます。omarchy スキルはシステムのカスタマイズをカバーします。例えば Hyprland の設定を微調整したりバーを調整したりするようなことです。omarchy-make-theme、omarchy-make-plugin、omarchy-make-app、omarchy-make-game は何か新しいものを作ることをカバーし、omarchy-contribute はバグを報告したり修正を上流に送ったりすることをカバーし、omarchy-diagnose-crash はクラッシュのコアダンプを調査します。これらは Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` と各 `~/.hermes/profiles/*/skills`）、そして汎用の `~/.agents/skills` の場所にあるスキルディレクトリにシンボリックリンクされているので、ほとんどのハーネスが自動的に拾います。同じ名前のあなた自身のスキルフォルダが優先されます。

でもこれらのスキルは実験的なものとみなすべきです。モデルによって効果の現れ方は異なります。まずプランモードで実行するのが最善です。そうすればエージェントが何を変更したいのか把握できます。そして、エージェントがすべてをめちゃくちゃにした場合に備えて、変更をロールバックしたり、`omarchy reinstall configs` を実行したりする準備をしておいてください。
