### エージェントのインストールと更新

Hermes と OpenClaw を除き、これらのエージェントは mise の遅延インストールを使います：初回起動時に CLI がインストールされ、それ以降の起動ではそれが再利用されます。mise はまた、インストール済みエージェントに新しいリリースがないかを、起動の直前、またはシェルプロンプトでのバックグラウンドで、最大で4時間に1回チェックします。その更新が失敗したり、オフラインだったりした場合は、インストール済みのバージョンが動作します。`omarchy update` は、インストール済みエージェントを Omarchy 本体の残りと一緒に更新し、`mup` は mise で管理されたツールだけを更新します。

エージェント自体のアップデーター、たとえば `claude update`、`codex update`、またはアプリ内の更新ボタンでは、mise で管理されたインストールは更新されません。`codex update` は失敗し、`claude update` は成功したと報告しながら、mise が追跡しない別コピーをインストールすることがあります。エージェント独自のインストーラーとアップデーターを使いたい場合は、それを `disable_tools` に追加してください。[プリインストールされた CLI ツール](18-development-tools.md#preinstalled-cli-tools) を参照してください。

必要になる前に、設定済みの遅延ツールをすべてインストールするには、`mise install --include-lazy` を実行してください。これにはエージェントだけでなく、Omarchy のその他のデフォルト CLI ツールも含まれます。単一のツールのインストールや、独自のインストールを使う方法については、[プリインストールされた CLI ツール](18-development-tools.md#preinstalled-cli-tools) を参照してください。

`grok` は、`claude` や `codex` と同じように、mise のファーストパーティ `grok` パッケージ経由でインストールされます。`grok` を実行するか、エージェントパネルでスターを付けてください。x.ai の `curl | bash` インストーラーは避けてください。その方法では `~/.grok/bin` に2つ目のコピーが配置され、`PATH` の先頭に追加されて、Omarchy のラッパーが上書きされます。

`dsh` は `127.0.0.1:3080` でブラウザー UI を開き、起動したディレクトリをデフォルトのワークスペースとします。そのブラウザー UI は開始プロンプトを受け付けないので、`omarchy agent prompt` では、貼り付けられるようにプロンプトをクリップボードに入れた状態で開きます。Omarchy は DeepSeek の承認不要の権限プリセットでこれを起動します。DeepSeek Harness は、公式モデル API を使うとセッションログを DeepSeek にアップロードします；ブラウザー UI の _Settings > General > Upload Session Log_ でそれをオフにしてください。送信するフィードバックもセッションと一緒にアップロードされます。ただし、`DSH_TELEMETRY_MODE=DISABLED` を付けて起動した場合は除きます。

### デフォルトのエージェント

デフォルトのエージェントは、エージェントパネルでエージェントの横にあるスターで選べます。デフォルトになったものはスターが塗りつぶされます。または `omarchy default agent <name>` でも選べます。こちらは、そこに項目がないハーネスも受け付けます。エージェントがまだインストールされていない場合は、選ぶとまずインストールされ、アプリランチャーでも Agent の横に専用のランチャーが用意されます。Omarchy がまっさらな状態なら、一度きりの通知で設定するよう促され、それを開くとエージェントパネルが開きます。

Claude を選ぶと、Chromium、Chrome、Brave、Brave Origin、Edge 用のブラウザー拡張機能のセットアップも試みます。この拡張機能のセットアップはすべてのユーザーに適用され、システムパスワードを求められることがあります；キャンセルしたり、拡張機能のインストールに失敗したりしても、Claude は選択され、起動します。ブラウザーを再起動し、プロンプトが表示されたら拡張機能を有効にし、Claude にサインインして接続を完了してください。接続を確認するには Claude で `/chrome` を実行してください。Firefox と Zen はこの拡張機能に対応していません。Claude がこのセットアップが追加される前からすでにデフォルトだった場合は、もう一度選択すると拡張機能がインストールされます。

選択したら、`Super + Shift + Ctrl + A` で専用のターミナルウィンドウでデフォルトのエージェントを起動します（まだ選んでいない場合はピッカーが表示されます）。`omarchy agent prompt "Review this project"` を使って、タスクを直接渡して起動することもできます。Freebuff と DeepSeek Harness は開始プロンプトを受け付けないので、代わりに貼り付けられるようにプロンプトをクリップボードに入れた状態で開きます。このように起動したエージェントは、それぞれの確認で止まらないモードで無人で動作します。実際に勝手にいろいろやる覚悟をしておいてください！ MiniMax Code には対話セッション用のそのようなモードがないので、通常通り権限を求めてきます。また、エージェントはホームディレクトリに対する信頼を覚えることを拒否するため、`$HOME` から起動した場合は代わりに `~/Work` で開始します。

ターミナル用のショートカットもあります：`a` は現在のターミナルでデフォルトのエージェントをインラインで実行し、`c`、`cx`、`cy` は OpenCode、Claude Code、Codex を直接起動します（こちらも自動承認モードです）。テーマ変更もエージェントに同期されます：Claude Code、Pi、OpenCode、Hermes（Omarchy がインストールした後）は、すべて Omarchy のテーマを切り替えるとそれに追従します。

### エージェントへの指示

すべてのエージェントに対する個人的なルールは、`~/.agents/skills` の共有スキルと並んで、`~/.agents/AGENTS.md` に置きます。これを開くには、エージェントパネルで + の横にあるドキュメントアイコンを使うか、`omarchy agent instructions --edit` を実行してください。後者は、独自のグローバルファイルを持つ各ハーネスにもこれをリンクします：`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`~/.pi/agent/AGENTS.md`、`~/.config/opencode/AGENTS.md`、Copilot の `~/.copilot/copilot-instructions.md` などです。Crush と Amp は `~/.config/AGENTS.md` のリンクを読み、omp、Kimi、DeepSeek Harness は `~/.agents/AGENTS.md` を直接読みます。デフォルトのエージェントを選ぶときにもリンクされます。すでに持っていた指示ファイルは、共有のものがまだなかった場合は共有のものになり、そうでない場合はリンクの横に `.bak` として残されます。別のエージェントをインストールした後に再リンクするには、`omarchy agent instructions` を実行してください。

### エージェントパネル

上部バーにはエージェントアイコンがあります。エージェントをまだ設定していない場合、そのパネルでは3つの始め方が提示されます：Claude、Codex、Grok、Gemini、Muse、Cursor、Copilot のサブスクリプションにサインインするか、More の下の OpenCode Go、MiniMax、Synthetic、Z.ai のコーディングプラン；Fireworks、OpenCode Zen and Go、OpenRouter、または More の下の DeepSeek や OpenCode がサインインできるその他のプロバイダーで従量課金し、これらはすべて OpenCode で動作；または、お使いのコンピューターに合うモデルがある場合に、そのコンピューターに最適なモデルを実行する、の3つです。最初に終えたものがデフォルトのエージェントになり、後からパネルの + でも同じ3つが提示されます。その後は、このパネルはすべてのサブスクリプションを1ページにまとめます：各エージェントとアカウント、そのプラン、5時間セッション制限と週間制限それぞれのメーターとリセットまでの時間（ホバーで正確なパーセンテージ）、またはプリペイド残高の残りが、それらすべてにわたって使ったものを順に切り替えて表示する行の下に並びます。たとえば今週のトークンや最よく使ったモデルなどです。_Make something cool_ の下では、新しいテーマ、プラグイン、アプリ、ゲームのスタータープロンプトが提示され、そのタスクをデフォルトのエージェントに渡します。アプリは、Omarchy 自体の Hype、Monologue、Omacut と同じ作り方で、C++ と Qt Quick で構築され、omarchy-make-app エージェントスキルに従い、それらが必要とするコンパイラと Qt の要素はインストールされた状態で入っています。ゲームは `~/Games/vibes` の単一の three.js ページで、omarchy-make-game エージェントスキルに従い、すべて現在のテーマの1つの Game Vibes ランチャーから開きます；これらは Web から three.js を読み込むので、開始には接続が必要です。Claude Code、Codex、Grok、Kimi、Cursor とその Grok Bot の利用枠、GitHub Copilot、Muse、Gemini（Antigravity 経由）、Devin は、それぞれの制限と一緒にすぐに使えます。Kimchi はそのプラン、プリペイドクレジット、支出予算と一緒に、Hermes、Mistral Vibe、Qwen Code は一度使うとセッションとトークンを表示します。pi、omp、opencode 経由で使うプロバイダーのプランとキーも表示されます：OpenCode Zen and Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan、Synthetic はそれぞれの制限と一緒に；OpenRouter と DeepSeek はプリペイド残高と一緒に；Fireworks は過去30日間の支出と一緒に表示されます。自分のハードウェアで実行するモデルからのトークンも合計に算入されます；モデル自体には専用のパネルがあり、[ローカルモデル](#local-models) で説明されています。すべてのエージェントは、請求元のもとで1回だけ数えられ、いくつのハーネス経由で駆動しても変わりません。

左クリックでバーアイコンを押すか、`Super + Ctrl + X` を押すとパネルが開き、右クリックでデフォルトのエージェントを起動し、中央クリックで更新します。その背後にある使用記録は、`omarchy agent usage update` によって15分ごとに再生成され、このパネルは同期フォルダ経由で他のマシンの使用量を統合することさえできます。完全な設定については、`$OMARCHY_PATH/shell/plugins/agents/` の README を参照してください。

### 複数のサブスクリプション

個人用の Max と仕事用など、Claude、Codex、Grok のプランを複数支払っている場合、Omarchy はすべてサインインした状態を保ち、それらの間で移動できます。サブスクリプションを追加するには、エージェントパネルの + を使い、そこで手順が案内されます。または `omarchy agent account add claude Work`（`codex` や `grok` でも）を使います。同じ + とコマンドで Gemini（`gemini`）と OpenCode（`opencode`）にサインインし、OpenCode に Fireworks（`fireworks`）や OpenRouter（`openrouter`）の API キーを保存できます；このコマンドは Copilot（`copilot`）、Cursor（`cursor`）、Muse（`muse`）にもサインインします。それらはそれぞれ1つのサインインだけを保持します。CLI がなければインストールします。プロバイダーの最初のアカウントは、CLI がいつも参照する場所である、通常のブラウザー経由でサインインします。それ以降のアカウントはすべてプライベートウィンドウ経由でサインインするので、ブラウザーがすでにサインインしているアカウントが誤って選択されることはありません；そこで追加しようとしているアカウントとしてサインインし、すでに開いているプライベートウィンドウがあれば先に閉じてください。CLI からログアウトしてこれをやってはいけません：ログアウトすると保存済みのサインインが取り消され、そのアカウントを再度追加しなければならなくなります。

SSH 経由でサブスクリプションのログインを別の Omarchy マシンにコピーするには、`omarchy agent account copy user@laptop` を実行してください。宛先に受信側がインストールされていない場合、送信側が一時的な受信側を提供するので、古い Omarchy マシンでも更新なしにアカウントを受け取れます。インストール済みの受信側が優先されます。これで Claude、Codex、Grok のすべてのサブスクリプションがコピーされます；選択するにはプロバイダー名を追加してください。たとえば `omarchy agent account copy laptop claude` のようにします。アカウント名とコマンド ID は、宛先にすでに存在するアカウントも含め、送信元に一致します。無関係な宛先アカウントについては、名前が衝突した場合に数字の接尾辞が付けられ、設定、スキル、プラグイン、会話履歴は各マシンにローカルなまま残ります。

宛先の既存の認証情報は保持されます。送信元アカウントがすでにそこでサインインしている場合は、その名前だけが同期され、認証情報は置き換えられません；その他のアカウントはその横に追加されます。一致するアカウントの保存済み認証情報を置き換えるには、宛先でそのアカウントのセッションを終了した後、`omarchy agent account copy --replace laptop claude` を使ってください。新しい宛先には、送信元のアクティブなアカウントと切り替え設定も引き継がれます；すでに確立された宛先では自身の設定が保持されます。

認証情報は SSH 経由で転送され、宛先のプライベートファイルに保存されるので、信頼できるマシンにだけコピーしてください。これは一度きりのコピーで、継続的な同期ではありません。Codex のリフレッシュトークンは別のマシンによってローテーションされることがあり、コピーされたログインに更新が必要になることがあります；複数のマシンで同時に使うには、別々のサインインが最も信頼できる選択肢であることに変わりありません。[Codex のアカウント認証ガイダンス](https://developers.openai.com/codex/auth/ci-cd-auth) を参照してください。

プロバイダーごとに1アカウントがアクティブであり、すべての新しいセッションはそのアカウントとして開始します：`cx`、`cy`、素の `claude`、`codex`、`grok`、`omarchy agent` 経由で起動されるものすべて、`PATH` 上の CLI を見つけるスクリプトやエディタもそうです。切り替えは `omarchy agent account use work` で（元に戻すには `omarchy agent account use main`）、またはパネルでアカウントの番号を押してから `Enter` を押す（またはスターをクリックする）ことで行います。実行中の Claude セッションも切り替わり、次のメッセージから反映されます：すべての Claude セッションは `~/.claude` で実行され、そこには常にアクティブなアカウントのサインインが保持されています。古い Omarchy がアカウント自身のフォルダで開始した Claude セッションは、終了するまでそのサインインを保持するので、切り替え時にはそれらのセッションが名前で示され、それらがなくなったら自動的に完了します。実行中の Codex と Grok のセッションは、開始したアカウントのままです。会話履歴、設定、スキル、プラグインはアカウント間で共有されるので、同じフォルダで `claude --continue` をすると、新しいアカウントで中断したところから続きができます。

アカウントが複数ある場合、パネルには各アカウントの制限が並べて表示され、使用中のものはスターが塗りつぶされます。アクティブなアカウントが制限の95%を超えると Omarchy が通知し、その通知をクリックすると余裕が最も大きいアカウントに切り替わります。自動で切り替わることは決してありません。このしきい値は `omarchy agent account threshold 90` で変更できます。すべてのアカウントがしきい値を超えている場合は、その旨が1回だけ通知され、最初に余裕が出るアカウントも通知されます。アクティブなアカウントがしきい値まで15ポイント以内（デフォルトでは80%）にある間、その制限は15分ごとではなく3分ごとにチェックされます。

`omarchy agent account list` はすべてのアカウントと最新の制限を表示し、`omarchy agent account remove work` はアカウントを忘れ、`omarchy agent account rename primary Hey` は名前を変更します（またはパネルでアカウント名をクリックします）。これらのコマンドはデフォルトのエージェントのアカウントに対して動作します；別のプロバイダーにアクセスするには、まずそれを指定してください。たとえば `omarchy agent account use codex side` のようにします。`~/.claude` や `~/.codex` にすでに持っていたログインが _Main_ アカウントです。Codex のものはそのままの場所にあります；Claude のものは、別のアカウントがアクティブな間、自身のフォルダで待機します。約8時間以上使われていないアカウントは _Sign-in required_ と表示されることがあります；クリックするとパネルですぐにそのアカウントに再サインインするか、アカウントを切り替えてセッションを開始すれば自動的にサインインが更新されます。`claude mcp add` で追加した MCP サーバーは、すべての Claude アカウントに届きます。なぜなら、それらはすべて `~/.claude` で実行されるからです；Codex と Grok では、アカウントが追加された時点で持っていたサーバーはそのアカウントにも付きますが、その後に追加したものは、追加したアカウントにしか届きません。Claude Desktop は自身のサインインを保持しますし、CLI バイナリへの絶対パスで設定された Codex や Grok のツールは切り替えに追従しません。明示的な `CLAUDE_CONFIG_DIR`、`CODEX_HOME`、または `GROK_HOME` は、選択されたアカウントより優先されます。

### クラッシュの診断

Omarchy は systemd-coredump を監視してプロセスのクラッシュを検出します。デフォルトのエージェントを選んだら、プログラムがコアダンプするたびに「Process crashed」通知が表示されます。これをクリックすると、そのクラッシュは Omarchy の omarchy-diagnose-crash スキルとともにデフォルトのエージェントに手渡されます。このスキルは、コアダンプから事実を確立し、そのクラッシュが上流へ報告する価値があるかどうかを判断するよう、エージェントを案内します。`coredumpctl list` の任意の PID に対して `omarchy agent crash <pid>` で手動でも実行できます。

監視はデフォルトでオンになっています。_Trigger > Toggle > Crash Capture Off_ でオフにする（または `omarchy toggle crash-capture` で）すると通知は止まります；`omarchy agent crash <pid>` は引き続き手動で動作します。

クラッシュはプログラムごとに黙らせることもでき、診断の最後にそれが提示されます。`omarchy crash mute hyprland` はそのプログラムだけの通知を止め、`omarchy crash mute hyprland off` で元に戻り、`omarchy crash mute` を単独で実行するとミュートされたものが一覧表示されます。バイナリの名前と同じくらい気軽にパスでも指定でき、`omarchy crash mute /usr/bin/hyprland` でも同じことができます。空白を含む名前は、`omarchy crash mute 'Some App'` のように引用してください。その他のものは引き続き通知され、ミュートされたプログラムは引き続きクラッシュします。これはリマインダーを隠すだけで、何も修正はしません。

### デスクトップアプリ

_Install > AI_ メニューには、いくつかのグラフィカルな AI アプリも入っています：Amp Desktop、Antigravity Desktop、ChatGPT デスクトップアプリ、Claude デスクトップアプリ（Anthropic の Linux ベータ、Chat、Cowork、Claude Code の各タブ付き）、xAI のモデルとチャットするための Grok Bot、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexity デスクトップアプリ、T3 Code です。Grok Bot はデスクトップチャットアプリです。コーディングエージェントは `grok` コマンドの方です。

Hermes Desktop は知っておくべき存在です。1台のマシンには Hermes が1つしかなく、それはこのアプリのものだからです：Hermes はこのアプリ経由でしかインストールされることがなく、デフォルトのエージェントが実行する `hermes` コマンドはこのアプリのものです。Hermes をデフォルトのエージェントに選ぶと、_Install > AI_ の項目がインストールするのと同じものがインストールされます：そのパッケージと、Hermes 自身のインストーラーが `~/.hermes` の下にセットアップする Hermes ランタイムです。初回は数分かかります。そのランタイムは1つだけの Hermes で、ターミナルの `hermes` コマンド、デフォルトのエージェント、アプリのすべてがそれを使い、Omarchy のリリースを待たずに `hermes update` で自身を更新します。これをインストールすると、Hermes には `omarchy` という名前のスキンとして Omarchy のテーマも手渡され、すべての Hermes の画面はテーマ切り替えに追従します；そうならない方がよければ、Hermes の Appearance 設定か `/skin` で別のものを選んでください。Omarchy はその選択には干渉しません。_Remove > AI_ でこのアプリを削除すると、まず Hermes がゲートウェイも含めて終了し、そのランタイムも一緒に削除されますが、あなたのチャット、メモリ、Hermes が自分のために書いたスキルは、指示しない限り保持します：そのデータと接続設定も一緒に削除するかどうかを、デフォルトで「いいえ」の選択で尋ねます。

OpenClaw のデスクトップ体験は、その Control UI です。これは、独自のローカルゲートウェイをバックエンドとする Web アプリとして開きます。OpenClaw は `~/.openclaw` にあり、自身を更新します：Control UI の「Update Gateway」ボタンを使うか、`openclaw update` を実行すると、ゲートウェイが新しいバージョンで再起動します。Omarchy が選ぶのは、新規インストールが開始するリリースだけです。OpenClaw はデフォルトのエージェントにもなれます：`omarchy default agent openclaw` で選ぶと、その同じコピーが `~/.openclaw` にセットアップされ、エージェントとして、ゲートウェイに接続された OpenClaw のターミナル UI が開きます。_Remove > AI_ で OpenClaw を削除すると、ゲートウェイサービスとアプリが一緒に削除され、その後 `~/.openclaw` も削除するかどうか尋ねます。そこには OpenClaw 本体や它がダウンロードするプラグインランタイムと並んで、あなたのチャットと認証情報も保持されているからです；デフォルトでは保持され、OpenClaw を再びインストールするとそれが再び利用されるようになります。

Herdr Desktop は [Herdr](https://herdr.dev) のデスクトップアプリです：スペース、タブ、ターミナルやコーディングエージェントのペインがあり、ウィンドウを閉じてもそのコアで実行され続けます。これはパッケージではなく Herdr 自身のインストーラーから来るので、`~/.local/share/herdr-app` に配置され、まだ持っていない場合はそのコアを `~/.local/bin/herdr-core` に一緒に持ってきて、両方を自身で更新します。これは、Omarchy が `Super + Ctrl + Return` で提供する `herdr` コマンドと並んで存在し、それを置き換えたりはしません。そしてそのコマンドのダイレクトキーを取得します：`Alt + Return` と `Alt + Shift + Return` でペインを下または右に分割し、`Alt + Escape` で閉じ、`Ctrl + Alt + Arrow` でペイン間を移動し、`Alt + 1..9` と `Alt + Left/Right` でタブを選択し、`Alt + Up/Down` でスペース間を移動します。`Ctrl + 1..9` でスペースを選択し、`Alt + Shift + Up/Down` でエージェントを順に切り替えます。`Ctrl + Space` 前置キーはターミナル専用のままです。このアプリはシーケンスのために素の Ctrl キーを保持できないからです。Omarchy はこれらを `~/.config/herdr-app/keys.json` に書き込み、`omarchy-refresh-herdr-app` で元に戻ります。これをインストールすると Herdr の Omarchy テーマが選択され、その後はあなたの Omarchy テーマに追従します。Herdr はライトモード用とダークモード用に1つずつテーマを保持するので、暗い Omarchy テーマと明るい Omarchy テーマを切り替えた後は、もう一方のモード用に Herdr のテーマピッカーで Omarchy をもう一度選んでください。

T3 Code は、パッケージではなく `~/.local/share/t3code` の公式 AppImage リリースから実行されるので、自身を更新します。これをインストールすると、Stable チャンネルで開始するか Nightly チャンネルで開始するか尋ねます；後で T3 Code の設定で切り替えてください。あなたのスレッドと設定は `~/.t3` にあり、_Remove > AI_ で T3 Code を削除すると一緒に削除されます。

### ローカルモデル

コーディングエージェント用に、オープンなモデルを自分のマシンで実行します。あなたのプロンプトとコードはマシン上に留まります；モデルに送られたものがマシンの外に出ることはありません。まずは次から始めてください：

```bash
omarchy models use best text
```

これにより、そのマシンに最適なテキストモデル（エージェントが使う種類）がセットアップされます。画像、動画、音楽モデルにもそれぞれ最適なものがあります：`omarchy models use best image`、`video`、または `music` です。`omarchy models use best` を実行すると、このマシンに対する各種類のおすすめが表示されます。

または、上部バーでエージェントアイコンの横にあるキラキラのアイコンから、あるいは Super + Ctrl + Alt + X でローカルモデルパネルを開き、+ を選んでください。このアイコンは、このマシンに合うモデルがある場合に表示されます。モデルを実行する Podman は Omarchy に付属し、NVIDIA マシンではモデルに GPU を提供する NVIDIA のコンテナツールキットも付属します；いずれかがない場合は、最初のセットアップでインストールされます。次に Omarchy はこのマシンに推奨されるモデルを選び、ダウンロードして、起動します。数十 GB のダウンロードと、モデル実行中はマシンのメモリの大半が使用されることを覚悟してください：Flash Next は、その全 256K コンテキストで約100 GiB を使います。必要なメモリを他のモデルが占有している場合、それは停止状態でセットアップされ、どれかを止めたら開始できる状態になります。このモデルはログアウト時に停止します；他の用途にメモリが必要なときは自分で止めてください。

`omarchy models list` で選択肢が表示され、一部が適合しない理由が説明されます。別のものをセットアップするには、`omarchy models use <recipe>` を実行してください。現在、128 GB の Strix Halo マシン用に `qwen3.8-flash-next-gufo` と `qwen3.8-27b-gufo` が利用できます；27B は約40 GiB を使うので、他の作業の余地も残ります。Intel の Arc B390 を搭載した 64 GB のラップトップでは、`qwen3.6-35b-a3b-llamacpp` が約30 GiB で動作します。新しいレシピとおすすめは、`omarchy update` でパッケージ経由で届きます。

セットアップしたモデルごとに、ローカルモデルパネルに専用の行ができます：再生で開始、停止で止めてメモリを解放し、ターミナルボタンでそのモデルでエージェントを開きます。上部全体にわたるバーは、マシンのメモリが Omarchy 本体（システムとアプリ）、実行中の各モデル、空きの間でどのように配分されているかを示します。停止中のモデルを指すと、そのバーはそれが収まるかどうか、またはどれだけ不足しているかを表示します。メモリに一緒に収まる場合は複数を同時に実行できます；どれか収まらない場合、Omarchy は実行中のどのモデルを止めるべきかを伝えます。行はロゴでドラッグして並び替えでき、選択した行で Delete を押すとそのモデルとダウンロードが削除されます。

セットアップしたすべてのコーディングモデルは、アプリランチャーにも専用の項目を持ちます。Claude、Codex、Grok にサインインすると追加されるのと同じように、モデルの名前とそのメーカーのロゴで表示されます。それを開くとそのモデルの上でエージェントが起動し、モデルが動作していない場合は最初にモデルを開始します：ターミナルにロード中と表示され、準備できたらエージェントに引き渡します。モデルを削除するとその項目も削除されます。

すべてのモデルがコーディング用ではありません。画像、動画、音楽モデルは、代わりに Fantasi で開きます。Fantasi は、このマシンで動作するモデルで画像、動画、音楽を作るための Omarchy のアプリで、そこか、ローカルモデルパネルの行から選択します。

モデルはセットアップされたとおりに正確に動作し続けるので、Omarchy の更新でエージェントの背後でモデルが再起動されることは決してありません。Omarchy が、セットアップしたモデル用に新しいランタイムや新しい重みを持っている場合、その行に更新ボタンが表示されます：それを押すと、モデルがバックグラウンドで再セットアップされ、変更された部分だけがダウンロードされて、新しいバージョンで再起動します。停止中だったモデルは停止したままです。`omarchy models update` は、ターミナルからすべてのモデルに対して同じことをします。

コマンドラインから、`omarchy models start <recipe>` と `omarchy models stop <recipe>` でも同じことが行われ、`omarchy models status` ですべてのモデルが表示され、`omarchy agent --local-model <recipe>` では、デフォルトのエージェントが何であれ、そのモデルを pi で開きます。エージェントのホットキー、Quake コンソール、_Make something_ が開く対象をローカルモデルにするには、`omarchy default agent local` を実行するか、エージェントパネルで実行中のモデルにスターを付けください。pi は自身のモデルピッカーにも、セットアップしたすべてのモデルと、ペアリングしたマシン上のモデルを一覧表示するので、素の `pi` でもそれらにアクセスできます。OpenAI 互換のクライアントならどれも接続できます：`status` に各モデルのアドレスが表示され（最初は `http://127.0.0.1:11435/v1`）、モデルはレシピ名で、キーは `~/.config/omarchy/agent-local/key` にあります。

`omarchy models remove <recipe>` は、そのモデルと、他のモデルが使わないダウンロードを削除します。

サードパーティのランタイムには、その発行元のラベルが付いています。Omarchy はすべてのモデルをネットワークアクセスなしで実行します。

### ローカル LLM

Omarchy では、ローカル LLM モデルを実行するには LM Studio と Ollama の2つをおすすめしています。LM Studio は、オープンな重みモデルを見つけ、インストールし、実行するための GUI インターフェイスを提供します。簡単に始めるのに最適な方法です。Ollama も同様のことができる CLI を提供します。でもローカルモデルが初めてなら、私なら LM Studio から始めます。どちらも Omarchy メニューの _Install > AI_ でインストールできます。

### Omarchy のスキル

エージェントスキルは、AI が特定のツールを特定の方法で使うのを助けるもので、Omarchy には7つ入っています。omarchy スキルは、Hyprland の設定を微調整したり、バーを調整したりするような、システムのカスタマイズを扱います。omarchy-make-theme、omarchy-make-plugin、omarchy-make-app、omarchy-make-game は何か新しいものを作ること、omarchy-contribute はバグを報告したり、修正を上流に送ったりすること、omarchy-diagnose-crash はクラッシュのコアダンプを調査することを担当します。これらは Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` および各 `~/.hermes/profiles/*/skills`）、汎用の `~/.agents/skills` の場所のスキルディレクトリにシンボリックリンクされているので、たいていのハーネスは自動的にそれらを拾います。同じ名前の独自スキルフォルダがある場合はそちらが優先されます。

ただし、これらのスキルは実験的なものとして扱ってください。異なるモデルはそれぞれ効果が異なります。最初は plan モードで実行するのが最善です。そうすれば、エージェントが何を変更しようとしているか想像がつきます。そして、エージェントがすべてをめちゃくちゃにした場合に備えて、変更をロールバックしたり、さらには `omarchy reinstall configs` を呼び出したりする準備をしておいてください。
