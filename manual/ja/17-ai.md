### エージェントのインストールと更新

Hermes と OpenClaw を除き、これらのエージェントは mise の遅延インストールを使用します。初回起動時に CLI がインストールされ、それ以降の起動ではそれが再利用されます。mise はまた、インストール済みエージェントに新しいリリースがないかを、最大で 4 時間に 1 回、起動直前またはシェルプロンプトでバックグラウンドで確認します。その更新が失敗したり、オフラインだったりした場合は、インストール済みのバージョンが動作します。`omarchy update` は、インストール済みエージェントを Omarchy の他の部分と一緒に更新し、`mup` は mise 管理ツールだけを更新します。

`claude update`、`codex update` のようなエージェント独自のアップデーターや、アプリ内の更新ボタンは、mise 管理のインストールを更新しません。`codex update` は失敗し、`claude update` は成功したと報告しながら、mise が追跡しない別のコピーをインストールすることがあります。エージェント独自のインストーラーとアップデーターを使いたい場合は、それを `disable_tools` に追加してください。[Preinstalled CLI tools](18-development-tools.md#preinstalled-cli-tools) を参照してください。

必要になる前に、設定済みの遅延ツールをすべてインストールするには、`mise install --include-lazy` を実行してください。これには、エージェントだけでなく、Omarchy の他のデフォルト CLI ツールも含まれます。単一のツールのインストール、または独自のインストールを使用する方法については、[Preinstalled CLI tools](18-development-tools.md#preinstalled-cli-tools) を参照してください。

`grok` は、`claude` や `codex` と同じ方法で、mise のファーストパーティ `grok` パッケージ経由でインストールされます。`grok` を実行するか、_Agent > Harness_ で選択してください。x.ai の `curl | bash` インストーラーは使わないでください。その方法では、`~/.grok/bin` に 2 つ目のコピーが配置され、`PATH` の先頭に追加され、Omarchy のラッパーが上書きされます。

`dsh` は、`127.0.0.1:3080` でブラウザ UI を開き、起動ディレクトリをデフォルトのワークスペースにします。そのブラウザ UI は開始プロンプトを受け付けないので、`omarchy agent prompt` は、クリップボードにプロンプトを入れた状態でそれを開き、貼り付けられるようにします。Omarchy は、DeepSeek の承認なし権限プリセットでこれを起動します。DeepSeek Harness は、公式モデル API を使用すると、セッションログを DeepSeek にアップロードします。そのブラウザ UI の _Settings > General > Upload Session Log_ でオフにしてください。送信したフィードバックもセッションと一緒にアップロードされます。ただし、`DSH_TELEMETRY_MODE=DISABLED` で起動した場合は除きます。

### デフォルトエージェント

`omarchy default agent <name>` で、または Omarchy Menu（`Super + Space`）の _Agent > Harness_ で、デフォルトエージェントを選択してください。エージェントがまだインストールされていない場合、選択するとまずそれがインストールされ、アプリランチャー内でも Agent の隣に独自のランチャーができます。新規の Omarchy では、1 回限りの通知でこの選択をするよう促されます。

Claude を選択すると、Chromium、Chrome、Brave、Brave Origin、Edge 用のブラウザ拡張機能のセットアップも試みます。拡張機能のセットアップはすべてのユーザーに適用され、システムパスワードを求められる場合があります。キャンセルしたり、拡張機能のインストールが失敗したりしても、Claude は選択され、起動します。ブラウザを再起動し、求められたら拡張機能を有効にし、Claude にサインインして接続を完了してください。Claude で `/chrome` を実行して接続を確認してください。Firefox と Zen はこの拡張機能に対応していません。このセットアップが追加される前に Claude がすでにデフォルトだった場合は、再度選択して拡張機能をインストールしてください。

選択が完了したら、`Super + Shift + Ctrl + A` で、専用のターミナルウィンドウでデフォルトエージェントが起動します（まだ選択していない場合はピッカーが表示されます）。`omarchy agent prompt "Review this project"` で、タスクを直接渡して起動することもできます。Freebuff と DeepSeek Harness は開始プロンプトを受け付けないので、代わりにクリップボードにプロンプトを入れた状態で開きます。この方法で起動されたエージェントは、それぞれの止まって確認しないモードで無人で動作するので、実際に作業を行う心構えが必要です！MiniMax Code には、その対話セッション向けのそのようなモードがないので、通常どおり権限を求めます。また、エージェントはホームディレクトリに対する信頼を覚えることを拒否するため、`$HOME` からの起動は代わりに `~/Work` で開始されます。

ターミナルショートカットもあります。`a` は現在のターミナル内でインラインでデフォルトエージェントを実行し、`c`、`cx`、`cy` は OpenCode、Claude Code、Codex を直接開始します（これも自動承認モードです）。テーマの変更もエージェントに同期されます。Claude Code、Pi、OpenCode、Hermes（Omarchy がインストールした後）は、Omarchy テーマを切り替えるとそれに追従します。

### エージェントへの指示

すべてのエージェントに対する個人ルールは、`~/.agents/skills` の共有スキルの隣にある `~/.agents/AGENTS.md` に入ります。_Agent > Instructions_ で開いてください。そこでは、独自のグローバルファイルを保持する各ハーネスにもリンクされます。`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`~/.pi/agent/AGENTS.md`、`~/.config/opencode/AGENTS.md`、Copilot の `~/.copilot/copilot-instructions.md` などです。Crush と Amp は `~/.config/AGENTS.md` リンクを読み、omp、Kimi、DeepSeek Harness は `~/.agents/AGENTS.md` を直接読みます。デフォルトエージェントを選択すると、それにもリンクされます。すでに持っていた指示ファイルは、まだ共有ファイルがなかった場合は共有のものになり、そうでない場合はリンクの隣に `.bak` として保持されます。別のエージェントをインストールした後に再リンクするには、`omarchy agent instructions` を実行してください。

### エージェントパネル

トップバーにはエージェントアイコンがあります。まだエージェントをセットアップしていない場合、そのパネルでは Claude、Codex、Grok へのサインインを順に案内し、最初のものがデフォルトエージェントになります。その後は、パネルはすべてのサブスクリプションを 1 ページにまとめます。各エージェントとアカウントとそのプラン、各 5 時間セッションと週間制限に対するメーターとリセットまでの時間（ホバーで正確な割合を表示）、または残りのプリペイド残高が、すべてのアカウントで使用した内容、たとえば今週のトークンや最も使用したモデルなどを順に表示する行の下に表示されます。_Make something cool_ の下では、新しいテーマ、プラグイン、アプリ、ゲームのためのスタータープロンプトが提供され、そのタスクをデフォルトエージェントに渡します。アプリは、Omarchy 独自の Hype、Monologue、Omacut と同じ方法で、C++ と Qt Quick で構築され、omarchy-make-app エージェントスキルに従い、必要なコンパイラーと Qt の要素はインストール済みです。ゲームは `~/Games/vibes` の単一の three.js ページで、omarchy-make-game エージェントスキルに従い、すべて現在のテーマの 1 つの Game Vibes ランチャーから開きます。これらは Web から three.js を読み込むので、開始には接続が必要です。Claude Code、Codex、Grok、Kimi、Cursor とその Grok Bot 枠、GitHub Copilot、Muse、Antigravity、Devin は、それぞれの制限とともに最初から対応し、Kimchi はそのプラン、プリペイドクレジット、支出予算とともに対応し、Hermes、Mistral Vibe、Qwen Code は使用後にセッションとトークンを表示します。pi、omp、opencode 経由で使用するプロバイダープランとキーも表示されます。制限付きの OpenCode Zen と Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan、Synthetic、プリペイド残高付きの OpenRouter と DeepSeek、過去 30 日間の支出付きの Fireworks です。自分のハードウェアで実行するモデルからのトークンも合計に加算されます。そのモデル自体には独自のパネルがあり、[Local models](#local-models) で説明します。すべてのエージェントは、課金者ごとに 1 回だけカウントされ、いくつのハーネス経由で駆動しても変わりません。

バーアイコンを左クリックするか `Super + Ctrl + X` を押すとパネルが開き、右クリックでデフォルトエージェントが起動し、中クリックで更新します。その背後にある使用記録は、`omarchy agent usage update` によって 15 分ごとに再生成され、パネルは同期フォルダ経由で他のマシンからの使用状況をマージもできます。完全な設定については、`$OMARCHY_PATH/shell/plugins/agents/` の README を参照してください。

### 複数のサブスクリプション

個人の Max と仕事用など、Claude、Codex、Grok のプランを複数支払っている場合、Omarchy はすべてをサインインしたままにし、それらの間を移動できます。エージェントパネルの + でサブスクリプションを追加してください。その場で順に案内します。または `omarchy agent account add claude Work`（または `codex`、または `grok`）で追加してください。CLI がなければインストールします。プロバイダーに対する最初のアカウントは、CLI がいつも参照する場所で、通常のブラウザ経由でサインインします。それ以降はすべてプライベートウィンドウ経由でサインインするので、ブラウザですでにサインインしているアカウントを誤って取得してしまうことがありません。追加するアカウントとしてそこでサインインし、すでに開いていたプライベートウィンドウは先に閉じてください。このために CLI からログアウトすることは絶対にしないでください。ログアウトすると保存済みのサインインが取り消され、そのアカウントを再度追加しなければならなくなります。

サブスクリプションログインを SSH 経由で別の Omarchy マシンにコピーするには、`omarchy agent account copy user@laptop` を実行してください。宛先に一時的なレシーバーがインストールされていない場合、送信者がそれを提供するので、古い Omarchy マシンでも更新なしにアカウントを受け取れます。インストール済みのレシーバーが優先されます。これは Claude、Codex、Grok のすべてのサブスクリプションをコピーします。プロバイダー名を追加して選択できます。たとえば `omarchy agent account copy laptop claude` です。アカウント名とコマンド ID はソースと一致し、宛先にすでにあるアカウントも含みます。無関係な宛先アカウントの名前が競合する場合は、数字のサフィックスが付けられ、設定、スキル、プラグイン、会話履歴は各マシンにローカルなままになります。

宛先の既存の資格情報は保持されます。ソースアカウントがすでにそこにサインインしている場合は、その資格情報を置き換えずに名前が同期され、他のアカウントはそれに並べて追加されます。マッチするアカウントの保存済み資格情報を置き換えるには、宛先でそのアカウントのセッションを終了した後に、`omarchy agent account copy --replace laptop claude` を使用してください。新規の宛先はソースのアクティブアカウントと切り替え設定も引き継ぎ、すでに確立された宛先は自身のものを保持します。

資格情報は SSH 経由で移動し、宛先のプライベートファイルに保存されるので、信頼するマシンにだけコピーしてください。これは 1 回限りのコピーで、継続的な同期ではありません。Codex のリフレッシュトークンは別のマシンによってローテーションされる場合があり、コピーされたログインに更新が必要になることがあります。複数のマシンで同時に使用するには、別々にサインインするのが最も確実な選択です。[Codex's account authentication guidance](https://developers.openai.com/codex/auth/ci-cd-auth) を参照してください。

プロバイダーごとに 1 つのアカウントがアクティブであり、すべての新しいセッションはそのアカウントで開始します。`cx`、`cy`、単純な `claude`、`codex`、`grok`、`omarchy agent` 経由で起動されるものすべて、`PATH` 上の CLI を見つけるスクリプトやエディターも同様です。`omarchy agent account use work` で切り替え（`omarchy agent account use main` で元に戻す）、またはパネルでアカウントの番号を押してから `Enter` を押してください（またはその Use ボタンをクリックしてください）。実行中の Claude セッションも、次のメッセージから切り替わります。すべての Claude セッションは `~/.claude` で実行され、そこには常にアクティブアカウントのサインインが保持されます。古い Omarchy でアカウント独自のフォルダで開始された Claude セッションは、終了するまでそのサインインを保持します。そのため、切り替え時にそれらのセッションの名前が表示され、それらがなくなると自動的に完了します。実行中の Codex と Grok のセッションは、開始したアカウントのままです。会話履歴、設定、スキル、プラグインはアカウント間で共有されるので、同じフォルダで `claude --continue` を実行すると、新しいアカウントで中断したところから再開できます。

複数のアカウントがある場合、パネルは各アカウントの制限を並べて表示し、アクティブなものにマークを付けます。デフォルトでは、アクティブアカウントが制限の 95% を超えると通知され、通知をクリックすると最も余裕のあるアカウントに切り替わります。パネルでアカウントの行にホバーし、Use の隣に表示される Autoswitch をクリックするか（または `m` を押す）、`omarchy agent account mode auto` を実行すると、自動で切り替わるようになります。有効の間は Autoswitch が Use の代わりになり、再度クリックすると通知に戻ります。`omarchy agent account mode auto 90` のように数字を追加してしきい値を変更してください。すべてのアカウントがしきい値を超えた場合は、最初に解放されるアカウントとともに一度だけ通知されます。アクティブアカウントがしきい値から 15 ポイント以内（デフォルトで 80%）にある間、その制限は 15 分ごとではなく 3 分ごとに確認されます。

`omarchy agent account list` はすべてのアカウントと最新の制限を表示し、`omarchy agent account remove work` は 1 つを削除し、`omarchy agent account rename primary Hey` は 1 つを名前変更します（またはパネルでアカウントの名前をクリックします）。これらのコマンドはデフォルトエージェントのアカウントに対して動作します。別のプロバイダーにアクセスするには、`omarchy agent account use codex side` のように先に名前を指定してください。`~/.claude` または `~/.codex` にすでにあったログインは _Main_ アカウントです。Codex のものはその場に残ります。Claude のものは、別のアカウントがアクティブな間は独自のフォルダで待機します。約 8 時間以上使用されていないアカウントは _Sign-in required_ と表示される場合があります。クリックしてパネル内でそのアカウントに再度サインインするか、アカウントに切り替えてセッションを開始すると、サインインは自動で更新されます。`claude mcp add` で追加した MCP サーバーは、すべての Claude アカウントで使用できます。すべてのアカウントが `~/.claude` で実行されるためです。Codex と Grok では、アカウント追加時に持っていたサーバーはそのアカウントに一緒に移りますが、後からのサーバーは追加したアカウントにしか届きません。Claude Desktop は独自のサインインを保持し、CLI バイナリーへの絶対パスで設定された Codex や Grok のツールは切り替えに追従しません。明示的な `CLAUDE_CONFIG_DIR`、`CODEX_HOME`、`GROK_HOME` は、選択したアカウントよりも優先されます。

### クラッシュの診断

Omarchy は systemd-coredump でプロセスのクラッシュを監視します。デフォルトエージェントを選択したら、自分のプログラムがコアをダンプすると、"Process crashed" 通知が表示されます。クリックすると、クラッシュは Omarchy の omarchy-diagnose-crash スキルとともにデフォルトエージェントに渡されます。そのスキルは、コアダンプから事実を確立し、クラッシュを上流に報告する価値があるかどうかを判断する手順をエージェントに案内します。`coredumpctl list` の任意の PID に対して、`omarchy agent crash <pid>` で手動で実行することもできます。

監視はデフォルトでオンです。_Trigger > Toggle > Crash Capture Off_ で（または `omarchy toggle crash-capture` で）オフにすると通知が止まります。`omarchy agent crash <pid>` は手動では引き続き動作します。

クラッシュはプログラムごとに 1 つずつ無音化することもでき、これは診断が最後に提案するものです。`omarchy crash mute hyprland` はそのプログラムだけの通知を止め、`omarchy crash mute hyprland off` はそれを戻し、`omarchy crash mute` だけでは、無音化したものがリスト表示されます。バイナリーのパスでも名前でも同様に受け付けるので、`omarchy crash mute /usr/bin/hyprland` でも同じです。スペースを含む名前は、`omarchy crash mute 'Some App'` のように引用してください。他のすべては引き続き通知され、無音化されたプログラムは引き続きクラッシュします。これによってリマインダーは非表示になりますが、何も修正されません。

### デスクトップアプリ

_Install > AI_ メニューには、いくつかのグラフィカル AI アプリも含まれています。Amp Desktop、Antigravity Desktop、ChatGPT デスクトップアプリ、Claude デスクトップアプリ（Chat、Cowork、Claude Code タブ付きの Anthropic の Linux ベータ）、xAI のモデルとチャットするための Grok Bot、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexity デスクトップアプリ、T3 Code です。Grok Bot はデスクトップチャットアプリです。コーディングエージェントは `grok` コマンドです。

Hermes Desktop は知っておくべき存在です。1 台のマシンには 1 つの Hermes があり、それはアプリのものだからです。Hermes はアプリ経由でしかインストールされず、デフォルトエージェントが実行する `hermes` コマンドはアプリのものです。Hermes をデフォルトエージェントとして選択すると、_Install > AI_ エントリーと同じものがインストールされます。パッケージと、Hermes 独自のインストーラーでセットアップされた `~/.hermes` の下の Hermes ランタイムです。初回は数分かかります。そのランタイムは、ターミナル `hermes` コマンド、デフォルトエージェント、アプリがすべて使用する 1 つの Hermes であり、Omarchy のリリースを待つのではなく、`hermes update` で自己更新します。インストールすると、Hermes に Omarchy テーマが `omarchy` という名前のスキンとして渡され、すべての Hermes サーフェスはテーマ切り替えに追従します。追従させたくない場合は、Hermes の Appearance 設定で別のものを選択するか、`/skin` で選択してください。Omarchy はその選択をそのままにします。_Remove > AI_ でアプリを削除すると、まず Hermes（ゲートウェイを含む）が閉じられ、そのランタイムも一緒に削除されますが、チャット、メモリー、Hermes が自身のために書いたスキルは、指示しない限り保持されます。そのデータと接続設定も削除するかどうかを尋ね、デフォルトはいいえです。

OpenClaw のデスクトップ体験は、その Control UI で、独自のローカルゲートウェイをバックエンドとする Web アプリとして開きます。OpenClaw は `~/.openclaw` にあり、自己更新します。Control UI の "Update Gateway" ボタンを使用するか、`openclaw update` を実行すると、ゲートウェイは新しいバージョンで再起動します。Omarchy は、新規インストールが開始するリリースを選択するだけです。OpenClaw をデフォルトエージェントにもできます。_Agent > Harness_ で選択すると、`~/.openclaw` に同じコピーがセットアップされ、エージェントはそのゲートウェイに接続された OpenClaw のターミナル UI を開きます。_Remove > AI_ で OpenClaw を削除すると、ゲートウェイサービスとアプリが一緒に削除され、その後 `~/.openclaw` も削除するかどうかを尋ねます。そこにはチャットと資格情報が OpenClaw 自体やダウンロードしたプラグインランタイムと一緒に保存されているからです。デフォルトでは保持され、OpenClaw を再度インストールするとそれを再び取り込みます。

Herdr Desktop は [Herdr](https://herdr.dev) デスクトップアプリです。ターミナルとコーディングエージェントのスペース、タブ、ペインがあり、ウィンドウを閉じてもそのコアで実行を続けます。これはパッケージではなく Herdr 独自のインストーラーから提供されるので、`~/.local/share/herdr-app` にあり、まだ持っていない場合は `~/.local/bin/herdr-core` にコアも一緒に持ち込み、どちらも自己更新します。これは、Omarchy が `Super + Ctrl + Return` で提供する `herdr` コマンドの隣にあり、それを置き換えるものではありません。そのコマンドの直接キーを取得します。`Alt + Return` と `Alt + Shift + Return` はペインを下または右に分割し、`Alt + Escape` はそれを閉じ、`Ctrl + Alt + Arrow` はペイン間を移動し、`Alt + 1..9` と `Alt + Left/Right` はタブを選択し、`Alt + Up/Down` はスペース間を移動します。`Ctrl + 1..9` はスペースを選択し、`Alt + Shift + Up/Down` はエージェントを順に切り替えます。`Ctrl + Space` プレフィックスキーはターミナル専用のままです。アプリはシーケンスのためだけに単なる Ctrl キーを保持できないからです。Omarchy はこれらを `~/.config/herdr-app/keys.json` に書き込み、`omarchy-refresh-herdr-app` がそれを元に戻します。インストールすると、Herdr の Omarchy テーマが選択され、その後は Omarchy テーマに追従します。Herdr はライトモード用に 1 つ、ダークモード用に 1 つのテーマを保持するので、ダークとライトの Omarchy テーマを切り替えた後は、もう一方のモードに対して Herdr のテーマピッカーで Omarchy をもう一度選択してください。

T3 Code は、パッケージではなく `~/.local/share/t3code` の公式 AppImage リリースから動作するので、自己更新します。インストールすると、Stable チャネルで始めるか Nightly チャネルで始めるかを尋ねます。後で T3 Code の設定で切り替えてください。スレッドと設定は `~/.t3` にあり、_Remove > AI_ で T3 Code を削除すると、それらも一緒に削除されます。

### ローカルモデル

コーディングエージェントのために、自分のマシンでオープンモデルを実行してください。プロンプトとコードはマシンに留まります。モデルに送信されたものがマシンから出ることはありません。次から始めてください。

```bash
omarchy models use best text
```

それにより、このマシンに最適なテキストモデル、つまりエージェントが使用する種類がセットアップされます。画像、動画、音楽モデルにもそれぞれ最適なものがあります。`omarchy models use best image`、`video`、`music` です。`omarchy models use best` を実行すると、このマシンの種類ごとの選択を確認できます。

または、トップバーのエージェントアイコンの隣にあるスパークルアイコンから、または Super + Ctrl + Shift + X でローカルモデルパネルを開き、+ を選択してください。このアイコンは、モデルがこのマシンに適合する場合に表示されます。モデルを実行する Podman は Omarchy に付属しています。NVIDIA マシン上の NVIDIA のコンテナツールキットも同様で、GPU を提供します。どちらかが欠けている場合、最初のセットアップでインストールされます。その後 Omarchy は、このマシンに推奨されるモデルを選択し、ダウンロードし、起動します。数十 GB のダウンロードと、モデル実行中にマシンのメモリーの大部分が使用されることを想定してください。Flash Next は、そのフル 256K コンテキストで約 100 GiB を使用します。他のモデルが必要なメモリーを保持している場合、停止した状態でセットアップされ、それらを 1 つ停止すると開始できるようになります。モデルはログアウト時に停止します。他のもののためにメモリーが必要な場合は、自分で停止してください。

`omarchy models list` はオプションを表示し、適合しないものがある理由を説明します。別のものをセットアップするには、`omarchy models use <recipe>` を実行してください。現在、128 GB の Strix Halo マシン用に `qwen3.8-flash-next-gufo` と `qwen3.8-27b-gufo` が利用できます。27B は約 40 GiB を使うので、他の作業用の余地を残します。Intel の Arc B390 を搭載した 64 GB のラップトップでは、`qwen3.6-35b-a3b-llamacpp` が約 30 GiB で動作します。新しいレシピと推奨は、パッケージ経由で `omarchy update` とともに届きます。

セットアップしたモデルごとに、ローカルモデルパネルに独自の行が表示されます。再生で開始、停止で一時停止してメモリーを解放、ターミナルボタンでその上でエージェントを開きます。上部全体にわたるバーは、マシンのメモリーが Omarchy 自体（システムとアプリ）、実行中の各モデル、空き容量でどのように分割されているかを示します。停止中のモデルを指すと、バーは適合するかどうか、またはどれだけ不足しているかを示します。メモリーに一緒に収まる場合は、複数を同時に実行できます。収まらない場合、Omarchy は停止すべき実行中のモデルを教えてくれます。ロゴで線をドラッグして並べ替えることができ、選択した行で Delete を押すと、モデルとそのダウンロードを削除できます。

セットアップしたモデルごとに、モデル名とそのメーカーのロゴでアプリランチャーに独自のエントリーも表示されます。これは、Claude、Codex、Grok にサインインすると追加されるのと同じ方法です。これにより、そのモデル上でエージェントが開き、実行されていない場合は先にモデルが開始されます。ターミナルには読み込み中であることが表示され、準備ができたらエージェントに引き継がれます。モデルを削除すると、そのエントリーも削除されます。

すべてのモデルがコーディング用ではありません。画像、動画、音楽モデルは、代わりにこのマシンで実行されるモデルで写真、動画、音楽を作る Omarchy のアプリである Fantasi で開きます。ランチャーエントリーと、ローカルモデルパネルの行から開きます。

モデルはセットアップされたとおりに実行を続けるので、Omarchy の更新でエージェントの下で再起動することはありません。Omarchy に、セットアップしたモデル向けの新しいランタイムや新しいウェイトがある場合、その行に更新ボタンが表示されます。押すと、モデルはバックグラウンドで再度セットアップされ、変更されたものだけをダウンロードし、新しいバージョンで再起動します。停止していたモデルは停止したままです。`omarchy models update` は、ターミナルからすべてのモデルに対して同じことをします。

コマンドラインから、`omarchy models start <recipe>` と `omarchy models stop <recipe>` で同じことができ、`omarchy models status` はすべてのモデルを表示し、`omarchy agent --local` は最後に開始したモデル上でデフォルトエージェントを開きます。pi、OpenCode、Qwen Code はそのいずれかを使用できます。デフォルトが他のものの場合、pi で開き、pi がない場合は OpenCode で開きます。pi は、セットアップしたすべてのモデルと、ペアリングしたマシンのモデルも独自のモデルピッカーにリストするので、単なる `pi` でもそれらに到達できます。OpenAI 互換のクライアントでも接続できます。`status` は各モデルのアドレスを表示し（最初は `http://127.0.0.1:11435/v1`）、レシピ名がモデルで、キーは `~/.config/omarchy/agent-local/key` にあります。

`omarchy models remove <recipe>` は、モデルと、他のモデルが使用しないダウンロードを削除します。

サードパーティのランタイムには、その発行者のラベルが付いています。Omarchy は、ネットワークアクセスなしですべてのモデルを実行します。

### ローカル LLM

Omarchy は、ローカル LLM モデルを実行する 2 つの方法を推奨します。LM Studio と Ollama です。LM Studio は、オープンウェイトモデルを見つけ、インストールし、実行するための GUI インターフェースを提供します。簡単に始めるには素晴らしい方法です。Ollama は、同じことを行う CLI を提供します。ただし、ローカルモデルが初めてなら、私なら LM Studio から始めます。どちらも Omarchy Menu の _Install > AI_ でインストールできます。

### Omarchy スキル

エージェントスキルは、AI が特定の方法で特定のツールを使用するのを支援し、Omarchy にはそれが 7 つ同梱されています。omarchy スキルは、Hyprland 設定の微調整やバーの調整など、システムのカスタマイズをカバーします。omarchy-make-theme、omarchy-make-plugin、omarchy-make-app、omarchy-make-game は新しいものを作ることをカバーし、omarchy-contribute はバグの報告や上流への修正の送信をカバーし、omarchy-diagnose-crash はクラッシュのコアダンプを調査します。これらは、Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` と各 `~/.hermes/profiles/*/skills`）、そして汎用の `~/.agents/skills` の場所のスキルディレクトリにシンボリックリンクされているので、ほとんどのハーネスが自動的に取得します。同名の独自のスキルフォルダが優先されます。

ただし、これらのスキルは実験的なものとして扱ってください。モデルが違えば、効果の出方も違います。まずはプランモードで実行するのが最適で、エージェントが何を変更したいのか把握できます。そして、変更をロールバックする、あるいはエージェントがすべてをめちゃくちゃにした場合に `omarchy reinstall configs` を実行する覚悟をしておいてください。
