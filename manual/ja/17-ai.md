### エージェントのインストールとアップデート

Hermes と OpenClaw を除き、これらのエージェントは mise の lazy installation を使います。初回起動時に CLI がインストールされ、それ以降の起動ではそれが再利用されます。mise はまた、インストール済みエージェントに新しいリリースがないか、最大で 4 時間に 1 回、起動直前、または shell プロンプトでバックグラウンドで確認します。そのアップデートが失敗したり、オフラインだったりした場合は、インストール済みのバージョンが動作します。`omarchy update` は Omarchy の他の部分と一緒にインストール済みエージェントをアップデートし、`mup` は mise で管理されているツールだけをアップデートします。

エージェント独自の updater、例えば `claude update`、`codex update`、アプリ内のアップデートボタンなどでは、mise で管理されているインストールはアップデートされません。`codex update` は失敗し、`claude update` は成功したと報告しながら、mise が追跡しない別のコピーをインストールすることがあります。エージェント独自の installer と updater を使いたい場合は、それを `disable_tools` に追加してください。[プリインストールされた CLI ツール](18-development-tools.md#preinstalled-cli-tools) を参照してください。

必要になる前に、設定されたすべての lazy tool をインストールするには、`mise install --include-lazy` を実行してください。これには、エージェントだけでなく、Omarchy の他のデフォルト CLI ツールも含まれます。単一のツールをインストールしたり、自分のインストールを使ったりする方法については、[プリインストールされた CLI ツール](18-development-tools.md#preinstalled-cli-tools) を参照してください。

`grok` は、`claude` や `codex` と同じように、mise の first-party `grok` パッケージ経由でインストールされます。`grok` を実行するか、_Agent > Harness_ で選択してください。x.ai の `curl | bash` installer は使わないでください。その方法だと `~/.grok/bin` に 2 つ目のコピーが配置され、`PATH` の先頭に追加され、Omarchy の wrapper が上書きされます。

`dsh` は `127.0.0.1:3080` でそのブラウザ UI を開き、起動ディレクトリをデフォルトの workspace とします。そのブラウザ UI は開始時のプロンプトを受け付けないので、`omarchy agent prompt` では、貼り付けられるようにプロンプトをクリップボードに入れた状態で開きます。Omarchy は DeepSeek の承認なし permission preset で起動します。DeepSeek Harness は、公式のモデル API を使うと、session ログを DeepSeek にアップロードします。そのブラウザ UI の _Settings > General > Upload Session Log_ でオフにしてください。送信したフィードバックも session と一緒にアップロードされます。ただし、`DSH_TELEMETRY_MODE=DISABLED` で起動した場合は除きます。

### デフォルトのエージェント

デフォルトのエージェントは `omarchy default agent <name>` で選ぶか、Omarchy Menu（`Super + Space`）の _Agent > Harness_ で選んでください。そのエージェントがまだインストールされていなければ、選択するとまずインストールされ、Agent の隣の app launcher にそのエージェント専用の launcher も追加されます。新品の Omarchy では、一度だけ表示される通知でこの選択をするよう促されます。

Claude を選択すると、Chromium、Chrome、Brave、Brave Origin、Edge 用にそのブラウザ拡張機能のセットアップも試みます。拡張機能のセットアップはすべてのユーザーに適用され、システムパスワードを求められることがあります。キャンセルしたり、拡張機能のインストールに失敗したりしても、Claude は選択されて起動します。ブラウザを再起動し、プロンプトが表示されたら拡張機能を有効にし、Claude にサインインして接続を完了してください。接続を確認するには Claude で `/chrome` を実行してください。Firefox と Zen はこの拡張機能に対応していません。このセットアップが追加される前にすでに Claude がデフォルトだった場合は、再度選択すると拡張機能がインストールされます。

選択が終わると、`Super + Shift + Ctrl + A` で専用のターミナルウィンドウでデフォルトのエージェントが起動します（まだ選択していなければ picker が表示されます）。`omarchy agent prompt "Review this project"` を使えば、タスクを直接渡して起動することもできます。Freebuff と DeepSeek Harness は開始時のプロンプトを受け付けないので、代わりに貼り付けられるようにプロンプトをクリップボードに入れた状態で開きます。この方法で起動されたエージェントは、それぞれの、止まって確認を求めないモードで unattended に動作します。実際にいろいろ実行する心構えをしておいてください！ MiniMax Code の対話型 session にはそのようなモードがないので、通常どおり権限を求めます。また、エージェントはホームディレクトリに対する信頼を覚えることを拒否するため、`$HOME` から起動した場合は代わりに `~/Work` から開始します。

ターミナル用のショートカットもあります。`a` は現在のターミナルでデフォルトのエージェントをインラインで実行し、`c`、`cx`、`cy` は OpenCode、Claude Code、Codex を直接起動します（こちらも自動承認モードです）。テーマの変更もエージェントに同期されます。Claude Code、Pi、OpenCode、Hermes（Omarchy がインストールした後）は、Omarchy のテーマを切り替えると一緒に追従します。

### エージェントへの指示

すべてのエージェントに対する個人的なルールは、`~/.agents/skills` の共有 skills の隣の `~/.agents/AGENTS.md` に入れます。_Agent > Instructions_ で開いてください。そこでは、独自のグローバルファイルを保持する各 harness へもリンクされます。`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`~/.pi/agent/AGENTS.md`、`~/.config/opencode/AGENTS.md`、Copilot の `~/.copilot/copilot-instructions.md` などです。Crush と Amp は `~/.config/AGENTS.md` リンクを読み、omp、Kimi、DeepSeek Harness は `~/.agents/AGENTS.md` を直接読みます。デフォルトのエージェントを選ぶと、そこへもリンクされます。すでに持っていた instructions ファイルがあり、共有ファイルがまだなければ、それが共有ファイルになります。そうでなければ、リンクの隣に `.bak` として保持されます。別のエージェントをインストールした後に再リンクするには、`omarchy agent instructions` を実行してください。

### エージェントパネル

トップバーにはエージェントアイコンがあります。エージェントをまだセットアップしていなければ、そのパネルでは Claude、Codex、Grok へのサインインを順に案内し、最初にサインインしたものがデフォルトのエージェントになります。その後は、パネルですべてのサブスクリプションが 1 ページにまとまります。各エージェントとアカウントとそのプラン、それぞれの 5 時間 session 制限と週間制限に対するメーターとリセットまでの時間（ホバーすると正確なパーセンテージが表示されます）、または残りのプリペイド残高が表示され、その上には、今週のトークン数や最もよく使ったモデルなど、全体での使用状況をローテーション表示する行があります。_Make something cool_ の下では、新しいテーマ、プラグイン、アプリ、ゲームのためのスタータープロンプトが提供され、タスクはデフォルトのエージェントに渡されます。アプリは、Omarchy 自身の Hype、Monologue、Omacut と同じ方法で、C++ と Qt Quick を使って、omarchy-make-app エージェント skill に従って構築され、必要なコンパイラと Qt の部品はインストール済みとして提供されます。ゲームは `~/Games/vibes` の単一の three.js ページで、omarchy-make-game エージェント skill に従い、すべて現在のテーマの 1 つの Game Vibes launcher から開きます。three.js をウェブから読み込むので、起動には接続が必要です。Claude Code、Codex、Grok、Kimi、Cursor とその Grok Bot 枠、GitHub Copilot、Muse、Antigravity、Devin は制限付きでそのまま利用でき、Kimchi はそのプラン、プリペイドクレジット、支出予算付きで、Hermes、Mistral Vibe、Qwen Code は一度使うとその session とトークンが表示されます。pi、omp、opencode 経由で使うプロバイダーのプランと鍵も表示されます。OpenCode Zen と Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan、Synthetic は制限付きで、OpenRouter と DeepSeek はプリペイド残高付きで、Fireworks は過去 30 日間の支出付きです。自分のハードウェアで実行するモデルからのトークンも合計に含まれます。モデル自体には専用のパネルがあり、[ローカルモデル](#local-models) で説明します。すべてのエージェントは、課金する側の下で 1 回だけ数えられます。使用する harness の数に関係しません。

バーのアイコンを左クリックするか `Super + Ctrl + X` を押すとパネルが開き、右クリックするとデフォルトのエージェントが起動し、中クリックすると更新されます。その背後にある使用記録は、`omarchy agent usage update` によって 15 分ごとに再生成され、パネルは同期フォルダ経由で他のマシンからの使用状況をマージすることもできます。設定全体については `$OMARCHY_PATH/shell/plugins/agents/` の README を参照してください。

### 複数のサブスクリプション

Claude、Codex、Grok のプランを複数契約している場合、例えば個人の Max と仕事用など、Omarchy はすべてをサインインした状態に保ち、その間を移動できます。サブスクリプションを追加するには、エージェントパネルの + を使うと、その場で順に案内されます。または `omarchy agent account add claude Work`（または `codex`、`grok`）を使ってください。CLI がなければインストールされます。プロバイダーの最初のアカウントは、CLI が常に見ている場所で、通常のブラウザ経由でサインインします。それ以降のアカウントはすべてプライベートウィンドウ経由でサインインします。これにより、ブラウザですでにサインインしているアカウントが誤って拾われることはありません。追加するアカウントとしてそこでサインインし、すでに開いているプライベートウィンドウは先に閉じてください。このために CLI からログアウトしてはいけません。ログアウトすると保存されたサインインが無効になり、そのアカウントを再度追加しなければならなくなります。

SSH 経由で別の Omarchy マシンにサブスクリプションログインをコピーするには、`omarchy agent account copy user@laptop` を実行してください。送信側は、宛先に receiver がインストールされていない場合、一時的な receiver を提供します。そのため、古い Omarchy マシンでもアップデートなしでアカウントを受け取れます。インストール済みの receiver が優先されます。これにより、すべての Claude、Codex、Grok サブスクリプションがコピーされます。プロバイダー名を追加するとそれらを選択できます。例えば `omarchy agent account copy laptop claude` のようにします。アカウント名とコマンド ID は送信元と一致します。宛先にすでに存在するアカウントも含みます。関係のない宛先アカウントで名前が競合した場合は、数字の suffix が付けられ、設定、skills、プラグイン、会話履歴は各マシンにローカルなままです。

既存の宛先の認証情報は保持されます。送信元アカウントがすでにそこでサインインしている場合は、その認証情報を置き換えずに名前が同期されます。他のアカウントはそれに並べて追加されます。一致するアカウントの保存済み認証情報を置き換えるには、宛先でそのアカウントの session を終了した後、`omarchy agent account copy --replace laptop claude` を使ってください。新品の宛先は、送信元のアクティブなアカウントと切り替え設定も受け取ります。確立済みの宛先は自身の設定を保持します。

認証情報は SSH 経由で移動し、宛先のプライベートファイルに保存されます。信頼できるマシンにだけコピーしてください。これは一度限りのコピーであり、継続的な同期ではありません。Codex の refresh token は他のマシンによってローテーションされることがあり、コピーされたログインは更新が必要な状態になることがあります。複数のマシンで同時に使う場合は、別々にサインインするのが最も確実な選択です。[Codex のアカウント認証ガイダンス](https://developers.openai.com/codex/auth/ci-cd-auth) を参照してください。

プロバイダーごとにアクティブなアカウントは 1 つで、すべての新しい session はそのアカウントで開始します。`cx`、`cy`、素の `claude`、`codex`、`grok`、`omarchy agent` 経由で起動されるものすべて、そして `PATH` 上の CLI を見つける scripts やエディタもそうです。切り替えは `omarchy agent account use work`（戻す場合は `omarchy agent account use main`）で行うか、パネルでアカウントの番号を押してから `Enter` を押す（またはその Use ボタンをクリックする）ことで行います。実行中の Claude session も、次のメッセージから切り替わります。すべての Claude session は `~/.claude` で実行され、そこには常にアクティブなアカウントのサインインが入っています。古い Omarchy によってアカウント専用のフォルダで開始された Claude session は、終了するまでそのサインインを保持します。そのため、切り替えではそれらの session の名前が表示され、それらがなくなると自動的に完了します。実行中の Codex と Grok の session は、開始したアカウントのままです。会話履歴、設定、skills、プラグインはアカウント間で共有されるので、同じフォルダでの `claude --continue` は新しいアカウントで中断したところから続けられます。

アカウントが複数ある場合、パネルでは各アカウントの制限が並べて表示され、アクティブなものがマークされます。アクティブなアカウントが制限の 95% を超えると Omarchy が通知し、通知をクリックすると最も余裕のあるアカウントに切り替わります。自動で切り替わることはありません。しきい値は `omarchy agent account threshold 90` で変更してください。すべてのアカウントがしきい値を超えている場合は、どのアカウントが最初に解放されるかと合わせて、一度だけ知らされます。アクティブなアカウントがしきい値まで 15 ポイント以内（デフォルトでは 80%）にある間は、その制限は 15 分ごとではなく 3 分ごとに確認されます。

`omarchy agent account list` はすべてのアカウントとその最新の制限を表示し、`omarchy agent account remove work` は 1 つを忘れ、`omarchy agent account rename primary Hey` は 1 つの名前を変更します（またはパネルでアカウント名をクリックします）。これらのコマンドはデフォルトのエージェントのアカウントに対して動作します。別のプロバイダーにアクセスするには、先にその名前を指定してください。例えば `omarchy agent account use codex side` のようにします。`~/.claude` または `~/.codex` にすでにあったログインが _Main_ アカウントです。Codex のものはその場に残ります。Claude のものは、別のアカウントがアクティブな間、専用のフォルダで待機します。約 8 時間以上使われていないアカウントは _Sign-in required_ と表示されることがあります。クリックするとパネルですぐにそのアカウントに再度サインインできます。または、そのアカウントに切り替えて session を開始すると、サインインは自動的に更新されます。`claude mcp add` で追加した MCP サーバーは、すべての Claude アカウントで使えます。すべてが `~/.claude` で実行されるためです。Codex と Grok については、アカウントが追加された時点で持っていたサーバーはそのアカウントにも引き継がれますが、それ以降のものは追加したアカウントにしか届きません。Claude Desktop は独自のサインインを保持し、CLI バイナリへの絶対パスで設定された Codex または Grok のツールは切り替えに追従しません。明示的な `CLAUDE_CONFIG_DIR`、`CODEX_HOME`、`GROK_HOME` は、選択されたアカウントより優先されます。

### クラッシュ診断

Omarchy は systemd-coredump でプロセスのクラッシュを監視しています。デフォルトのエージェントを選んだ後は、あなたのプログラムのいずれかが core をダンプすると「Process crashed」通知が表示されます。クリックすると、クラッシュはデフォルトのエージェントに渡され、Omarchy の omarchy-diagnose-crash skill と一緒に渡されます。この skill は、core dump から事実を確立し、そのクラッシュを upstream に報告する価値があるかどうかを判断する手順をエージェントに案内します。`coredumpctl list` の任意の PID に対して `omarchy agent crash <pid>` で手動で実行することもできます。

監視はデフォルトでオンです。_Trigger > Toggle > Crash Capture Off_ で（または `omarchy toggle crash-capture` で）オフにすると通知は止まります。`omarchy agent crash <pid>` は手動では引き続き動作します。

クラッシュはプログラムごとに 1 つずつ黙らせることもできます。これは診断の最後に提示されるものです。`omarchy crash mute hyprland` はそのプログラムだけの通知を止め、`omarchy crash mute hyprland off` で元に戻し、`omarchy crash mute` だけだとミュートしたものが一覧表示されます。名前と同じくらいバイナリのパスも受け付けるので、`omarchy crash mute /usr/bin/hyprland` でも同じことができます。名前にスペースが含まれる場合は、`omarchy crash mute 'Some App'` のように引用してください。他のものはすべて通知され続け、ミュートされたプログラムもクラッシュし続けます。これはリマインダーを隠すだけで、何も修正しません。

### デスクトップアプリ

_Install > AI_ メニューには、いくつかのグラフィカルな AI アプリも含まれます。Amp Desktop、Antigravity Desktop、ChatGPT desktop app、Claude desktop app（Chat、Cowork、Claude Code タブ付きの Anthropic の Linux beta）、xAI のモデルとチャットするための Grok Bot、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexity desktop app、T3 Code です。Grok Bot はデスクトップチャットアプリです。コーディングエージェントは `grok` コマンドです。

Hermes Desktop は知っておくべきものです。マシンには Hermes が 1 つだけあり、それはアプリのものだからです。Hermes はアプリ経由でしかインストールされず、デフォルトのエージェントが実行する `hermes` コマンドはアプリのものです。Hermes をデフォルトのエージェントとして選択すると、_Install > AI_ 項目と同じものがインストールされます。パッケージと、Hermes 独自の installer によってセットアップされた `~/.hermes` の Hermes runtime です。初回は数分かかります。その runtime が、ターミナルの `hermes` コマンド、デフォルトのエージェント、アプリのすべてが使う唯一の Hermes で、Omarchy のリリースを待つのではなく、`hermes update` で自己アップデートします。インストールすると、Hermes には `omarchy` という名前の skin として Omarchy テーマも渡され、すべての Hermes の surface はテーマを切り替えるとそれに追従します。そうしたくない場合は、Hermes の Appearance 設定、または `/skin` で別のものを選んでください。Omarchy はその選択に干渉しません。_Remove > AI_ でアプリを削除すると、まず Hermes が終了し、gateway も含め、その runtime も一緒に削除されます。ただし、指示しない限り、チャット、メモリ、Hermes が自身のために書いた skills は保持されます。そのデータと接続設定も削除するかどうかを尋ね、デフォルトはいいえです。

OpenClaw のデスクトップ体験はその Control UI で、独自のローカルゲートウェイに支えられたウェブアプリとして開きます。OpenClaw は `~/.openclaw` にあり、自己アップデートします。Control UI の「Update Gateway」ボタンを使うか `openclaw update` を実行すると、gateway は新しいバージョンで再起動します。Omarchy は、新規インストールがどのリリースから始まるかだけを選びます。OpenClaw をデフォルトのエージェントにすることもできます。_Agent > Harness_ で選択すると、`~/.openclaw` にある同じコピーがセットアップされ、エージェントは gateway に接続された OpenClaw のターミナル UI を開きます。_Remove > AI_ で OpenClaw を削除すると、gateway サービスとアプリが一緒に削除され、その後、`~/.openclaw` も削除するかどうかを尋ねます。そこには、OpenClaw 自体やダウンロードする plugin runtime と一緒に、チャットと認証情報も入っているからです。デフォルトでは保持され、OpenClaw を再度インストールするとまた利用されます。

Herdr Desktop は [Herdr](https://herdr.dev) のデスクトップアプリです。ターミナルとコーディングエージェントの spaces、tabs、panes があり、ウィンドウを閉じてもその core で動き続けます。パッケージではなく Herdr 独自の installer から提供されるので、`~/.local/share/herdr-app` にあり、まだ持っていなければ `~/.local/bin/herdr-core` にその core も一緒に配置し、両方とも自己アップデートします。`Super + Ctrl + Return` で Omarchy が提供する `herdr` コマンドの隣にあり、それを置き換えることはありません。そしてそのコマンドの直接キーが与えられます。`Alt + Return` と `Alt + Shift + Return` は pane を下または右に分割し、`Alt + Escape` はそれを閉じ、`Ctrl + Alt + Arrow` は pane 間を移動し、`Alt + 1..9` と `Alt + Left/Right` は tab を選び、`Alt + Up/Down` は spaces 間を移動します。`Ctrl + 1..9` は space を選び、`Alt + Shift + Up/Down` はエージェント間を移動します。`Ctrl + Space` prefix キーはターミナル専用のままです。アプリは sequence のために素の Ctrl キーを保持できないからです。Omarchy はこれらを `~/.config/herdr-app/keys.json` に書き込み、`omarchy-refresh-herdr-app` で元に戻します。インストールすると Herdr の Omarchy テーマが選ばれ、それ以降は Omarchy テーマに追従します。Herdr は light mode 用と dark mode 用に 1 つずつテーマを保持するので、暗い Omarchy テーマと明るい Omarchy テーマを切り替えた後は、もう一方のモードのために Herdr のテーマ picker で Omarchy をもう一度選んでください。

T3 Code は、パッケージからではなく、`~/.local/share/t3code` にある公式の AppImage リリースから実行されるので、自己アップデートします。インストール時に、Stable チャンネルで始めるか Nightly チャンネルで始めるかを尋ねます。後で T3 Code の設定で切り替えてください。threads と設定は `~/.t3` にあり、_Remove > AI_ で T3 Code を削除すると、それらも一緒に削除されます。

### ローカルモデル

コーディングエージェントのために、自分のマシンでオープンモデルを実行してください。プロンプトとコードはマシン上に留まります。モデルに送られたものがマシンから出ることはありません。次から始めてください。

```bash
omarchy models use best text
```

これにより、このマシンに最適なテキストモデルがセットアップされます。エージェントが使うタイプです。画像、動画、音楽モデルにもそれぞれ最適なものがあります。`omarchy models use best image`、`video`、`music` です。`omarchy models use best` を実行すると、このマシンに対する各タイプのおすすめが表示されます。

または、トップバーのエージェントアイコンの隣にある sparkles アイコンから、または Super + Ctrl + Alt + X でローカルモデルパネルを開き、+ を選択してください。このアイコンは、モデルがこのマシンに収まるときに表示されます。モデルを実行する Podman は Omarchy に付属し、NVIDIA マシンでは NVIDIA の container toolkit も付属します。これにより GPU が使えるようになります。どちらかが欠けていれば、最初のセットアップでインストールされます。次に Omarchy は、このマシンに推奨されるモデルを選んでダウンロードし、起動します。数十 GB のダウンロードと、モデル実行中にマシンのメモリのほとんどが使用されることを想定してください。Flash Next は、完全な 256K context で約 100 GiB を使います。必要なメモリを他のモデルが占有していれば、停止した状態でセットアップされ、そのうち 1 つを止めると起動できるようになります。モデルはログアウト時に停止します。メモリが他の用途に必要なときは、自分で止めてください。

`omarchy models list` は選択肢を表示し、収まらないものについてはその理由を説明します。別のものをセットアップするには、`omarchy models use <recipe>` を実行してください。現在、128 GB の Strix Halo マシン用に `qwen3.8-flash-next-gufo` と `qwen3.8-27b-gufo` が利用できます。27B は約 40 GiB を使うので、他の作業の余地が残ります。Intel の Arc B390 を搭載した 64 GB のラップトップでは、`qwen3.6-35b-a3b-llamacpp` が約 30 GiB で動作します。新しい recipes と推奨事項は、パッケージ経由で `omarchy update` と一緒に届きます。

セットアップしたすべてのモデルは、ローカルモデルパネルに専用の行を持ちます。play で起動し、pause で停止してメモリを解放し、ターミナルボタンでそのモデルでエージェントを開きます。上部には、Omarchy 自体（システムとアプリ）、実行中の各モデル、空き容量の間でマシンのメモリがどのように分割されているかを示すバーがあります。停止中のモデルをポイントすると、そのバーは収まるかどうか、またはどれだけ不足しているかを表示します。メモリに一緒に収まれば複数を同時に実行できます。収まらない場合は、Omarchy はどの実行中のモデルを止めるべきかを表示します。ロゴでドラッグして行を並べ替え、選択した行で Delete を押すと、モデルとそのダウンロードが削除されます。

セットアップしたすべてのコーディングモデルは、モデルの名前とそのメーカーのロゴで、Claude、Codex、Grok にサインインすると追加されるのと同じように、app launcher にも専用の項目を持ちます。それを開くと、そのモデルでエージェントが開きます。モデルが実行されていなければ、先にモデルを起動します。ターミナルには読み込み中が表示され、起動したらエージェントに引き継がれます。モデルを削除すると、その項目も削除されます。

すべてのモデルがコーディング用ではありません。画像、動画、音楽モデルは、代わりに Fantasi で開きます。これは、このマシンで実行されているモデルを使って画像、動画、音楽を作る Omarchy のアプリで、そこ、またはローカルモデルパネルのそのモデルの行から選択します。

モデルは、セットアップされたとおりに正確に動き続けます。そのため、Omarchy のアップデートでエージェントの下でモデルが再起動することはありません。Omarchy に、セットアップしたモデル用の新しい runtime や新しい weights がある場合、その行にアップデートボタンが表示されます。押すと、モデルはバックグラウンドで再セットアップされ、変更されたものだけがダウンロードされ、新しいバージョンで再起動します。停止していたモデルは停止したままです。`omarchy models update` はターミナルからすべてのモデルに対して同じことをします。

コマンドラインから、`omarchy models start <recipe>` と `omarchy models stop <recipe>` が同じことをし、`omarchy models status` はすべてのモデルを表示し、`omarchy agent --local` は、デフォルトのエージェントが何であれ、最後に起動したモデルを pi で開きます。OpenCode と Qwen Code もローカルモデルを使えます。`omarchy models harness opencode` または `omarchy models harness qwen` で代わりにそこで開き、`omarchy models harness pi` で元に戻ります。pi はまた、セットアップしたすべてのモデルと、ペアリングしたマシン上にあるモデルを、独自のモデル picker に一覧表示するので、素の `pi` からもそれらにアクセスできます。OpenAI 互換のクライアントならどれでも接続できます。`status` は各モデルのアドレスを表示し（最初のものは `http://127.0.0.1:11435/v1`）、recipe 名がモデルとなり、鍵は `~/.config/omarchy/agent-local/key` にあります。

`omarchy models remove <recipe>` は、モデルと、他のモデルが使っていないダウンロードを削除します。

サードパーティの runtime には、その publisher がラベル付けされます。Omarchy はすべてのモデルをネットワークアクセスなしで実行します。

### ローカル LLM

Omarchy は、ローカル LLM モデルを実行する方法として、LM Studio と Ollama の 2 つを推奨します。LM Studio は、オープンモデルを見つけてインストールし、実行するための GUI インターフェースを提供します。手軽に始めるのに最適な方法です。Ollama は、同様のことを行う CLI を提供します。しかし、ローカルモデルが初めてなら、私なら LM Studio から始めます。どちらも Omarchy Menu の _Install > AI_ でインストールできます。

### Omarchy skills

エージェント skills は、AI が特定のツールを特定の方法で使うのを助けます。Omarchy には 7 つが付属します。omarchy skill は、Hyprland 設定の調整やバーの調整など、システムのカスタマイズをカバーします。omarchy-make-theme、omarchy-make-plugin、omarchy-make-app、omarchy-make-game は新しいものを作ることをカバーし、omarchy-contribute はバグの報告や upstream への修正の送信をカバーし、omarchy-diagnose-crash はクラッシュの core dump を通じて作業します。これらは、Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` と各 `~/.hermes/profiles/*/skills`）、および汎用の `~/.agents/skills` の場所の skill ディレクトリにシンボリックリンクされているので、ほとんどの harness が自動的に拾います。同名の自分の skill フォルダがあれば、それが優先されます。

ただし、これらの skills は実験的なものとして扱うべきです。モデルによって効果は異なります。まずは plan mode で実行するのが最適です。そうすれば、エージェントが何を変更したいのかが分かります。そして、変更をロールバックする、あるいはエージェントがすべてをめちゃくちゃにしたら `omarchy reinstall configs` を実行する心構えをしておいてください。
