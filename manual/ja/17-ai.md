### エージェントのインストールとアップデート

Hermes を除き、これらのエージェントは mise の遅延インストールを使う。初回起動時に CLI がインストールされ、後の起動ではそれが再利用される。mise はまた、インストール済みエージェントに新しいリリースがないか、最大で 4 時間に 1 回、起動直前あるいはシェルのプロンプトでバックグラウンドで確認する。そのアップデートが失敗したりオフラインだったりすれば、インストール済みのバージョンが動作する。`omarchy update` は、Omarchy の他の部分と一緒にインストール済みエージェントをアップデートし、`mup` は mise 管理下のツールだけをアップデートする。

`claude update`、`codex update` のようなエージェント独自のアップデーターや、アプリ内のアップデートボタンは、mise 管理下のインストールをアップデートしない。`codex update` は失敗し、`claude update` は、mise が追跡しない別コピーをインストールしながら成功したと表示することがある。代わりにエージェントのネイティブなインストーラーとアップデーターを使いたければ、それを `disable_tools` に追加すること。[プリインストールされた CLI ツール](18-development-tools.md#preinstalled-cli-tools) を参照。

必要になる前に設定済みの遅延ツールをすべてインストールするには、`mise install --include-lazy` を実行する。これにはエージェントだけでなく、Omarchy の他のデフォルト CLI ツールも含まれる。単一ツールのインストールや独自インストールの使用については [プリインストールされた CLI ツール](18-development-tools.md#preinstalled-cli-tools) を参照。

`grok` は `claude` や `codex` と同じように、mise のファーストパーティー `grok` パッケージを通じてインストールされる。`grok` を実行するか、_Agent > Harness_ で選ぶこと。x.ai の `curl | bash` インストーラーは避けること。その方法では `~/.grok/bin` に 2 つ目のコピーが入り、`PATH` の先頭にそれが追加され、Omarchy のラッパーが上書きされる。

`dsh` は `127.0.0.1:3080` でそのブラウザー UI を開き、起動したディレクトリーをデフォルトのワークスペースとする。そのブラウザー UI は開始プロンプトを受け付けないため、`omarchy agent prompt` はプロンプトをクリップボードに入れた状態でそれを開き、貼り付けられるようにする。Omarchy は DeepSeek の承認なし権限プリセットでこれを起動する。DeepSeek Harness は、公式モデル API を使うとセッションログを DeepSeek にアップロードする。そのブラウザー UI の _Settings > General > Upload Session Log_ でオフにすること。送信するフィードバックもセッションと一緒にアップロードされる。ただし `DSH_TELEMETRY_MODE=DISABLED` で起動した場合は別だ。

### デフォルトのエージェント

デフォルトのエージェントは `omarchy default agent <name>` で選ぶか、Omarchy Menu（`Super + Space`）の _Agent > Harness_ で選ぶ。そのエージェントがまだインストールされていなければ、選ぶことで先にインストールされる。新しい Omarchy では、一度だけの通知でこの選択を促される。

Claude を選ぶと、Chromium、Chrome、Brave、Brave Origin、Edge 用にそのブラウザー拡張機能のセットアップも試みる。拡張機能のセットアップはすべてのユーザーに適用され、システムパスワードを求められることがある。キャンセルしたり拡張機能のインストールに失敗したりしても、Claude は選択され起動する。ブラウザーを再起動し、求められたら拡張機能を有効にし、Claude にサインインして接続を完了すること。接続を確認するには Claude で `/chrome` を実行する。Firefox と Zen はこの拡張機能をサポートしない。このセットアップが追加される前に既に Claude がデフォルトだった場合、それをもう一度選ぶと拡張機能がインストールされる。

一度選べば、`Super + Shift + Ctrl + A` で専用のターミナルウィンドウでデフォルトのエージェントが起動する（まだ選んでいなければピッカーが表示される）。`omarchy agent prompt "Review this project"` でタスクに直行させることもできる。Freebuff と DeepSeek Harness は開始プロンプトを受け付けないため、代わりにプロンプトをクリップボードに入れた状態で開く。こうして起動したエージェントは、それぞれの止まって尋ねたりしないモードで無人で動作する。だから実際にいろいろやってしまう覚悟をしておくこと！ MiniMax Code には対話セッション用のそうしたモードがないため、いつも通り権限を求める。そしてエージェントはホームディレクトリーへの信頼を記憶するのを拒むため、`$HOME` からの起動は代わりに `~/Work` で開始する。

ターミナルのショートカットもある。`a` は現在のターミナルでインラインにデフォルトのエージェントを実行し、`c`、`cx`、`cy` は OpenCode、Claude Code、Codex を直接起動する（こちらも自動承認モードで）。テーマの変更もエージェントに同期される。Claude Code、Pi、OpenCode、Hermes（Omarchy がインストールした後）は、Omarchy のテーマを切り替えるとそれに追随する。

### エージェントへの指示

すべてのエージェントに対する個人的なルールは、`~/.agents/skills` の共有スキルと並んで `~/.agents/AGENTS.md` に入れる。_Agent > Instructions_ でそれを開く。そこでは、独自のグローバルファイルを保持する各ハーネスへもそれがリンクされる。`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`~/.pi/agent/AGENTS.md`、`~/.config/opencode/AGENTS.md`、Copilot の `~/.copilot/copilot-instructions.md` などだ。Crush と Amp は `~/.config/AGENTS.md` リンクを読み、omp、Kimi、DeepSeek Harness は `~/.agents/AGENTS.md` を直接読む。デフォルトのエージェントを選んでもそれはリンクされる。既に持っていた指示ファイルは、共有のものがまだなければ共有のものになる。そうでなければリンクの隣に `.bak` として残される。別のエージェントをインストールした後に再リンクするには `omarchy agent instructions` を実行する。

### エージェントパネル

トップバーにはエージェントアイコンがある。エージェントをまだセットアップしていない場合、そのパネルでは Claude、Codex、Grok へのサインインを順に案内し、最初に設定したものがデフォルトのエージェントになる。その後は、パネルですべてのサブスクリプションが 1 ページにまとまる。各エージェントとアカウントとそのプラン、それぞれの 5 時間セッション上限と週間上限に対するメーターとリセットまでの時間（ホバーで正確なパーセンテージ表示）、あるいはプリペイド残高が、今週のトークン数や最もよく使ったモデルなど、すべてのエージェントを通じた使用状況を入れ替えで表示する行の下に並ぶ。_Make something_ の下では、新しいテーマ、プラグイン、アプリのためのスタータープロンプトが提供され、タスクをデフォルトのエージェントに引き渡す。アプリは Omarchy 自身の Hype、Monologue、Omacut と同じ方法で、C++ と Qt Quick で、omarchy-app エージェントスキルに従って作られ、必要なコンパイラーと Qt の部品はインストール済みで入っている。Claude Code、Codex、Grok、Kimi、Cursor とその Grok Bot 枠、GitHub Copilot、Muse、Antigravity、Kimchi、Devin は上限付きで最初から対応している。Hermes、Mistral Vibe、Qwen Code は、一度使うとそのセッションとトークンが表示される。pi、omp、opencode 経由で使うプロバイダーのプランとキーも表示される。上限付きの OpenCode Zen と Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan、Synthetic、プリペイド残高付きの Fireworks、OpenRouter、DeepSeek、そして Local models の下で自分のハードウェアで実行するモデルだ。すべてのエージェントは、請求元のもとで 1 回だけ数えられる。何個のハーネス経由で使ってもだ。

バーアイコンを左クリックするとパネルが開き、右クリックするとデフォルトのエージェントが起動する。その背後にある使用記録は `omarchy agent usage-update` によって 15 分ごとに再生成され、パネルは同期フォルダー経由で他のマシンからの使用状況を統合することさえできる。完全な設定については `$OMARCHY_PATH/shell/plugins/agents/` にある README を参照。

### 複数のサブスクリプション

個人の Max と仕事用など、Claude、Codex、Grok のプランを複数支払っている場合、Omarchy はそのすべてをサインインしたままにして、それらの間を移動できる。エージェントパネルの + でサブスクリプションを追加すると、その場で順に案内される。あるいは `omarchy agent account add claude Work`（または `codex`、または `grok`）でもできる。CLI がなければインストールする。プロバイダーに対する最初のアカウントは、CLI がいつも参照する場所である通常のブラウザーを通じてサインインする。その後のアカウントはすべてプライベートウィンドウを通じてサインインする。そのため、ブラウザーで既にサインインしているアカウントを誤って拾うことはない。そこで追加対象のアカウントとしてサインインし、先に既に開いていたプライベートウィンドウは閉じておくこと。これをするために決して CLI からログアウトしてはいけない。ログアウトすると保存されたサインインが失効し、そのアカウントを再度追加しなければならなくなる。

サブスクリプションのログインを SSH 経由で別の Omarchy マシンにコピーするには、`omarchy agent account copy user@laptop` を実行する。宛先に受信側がインストールされていない場合、送信側が一時的な受信側を提供する。そのため古い Omarchy マシンでもアップデートなしでアカウントを受け取れる。インストール済みの受信側が優先される。これは Claude、Codex、Grok のすべてのサブスクリプションをコピーする。選択するには `omarchy agent account copy laptop claude` のようにプロバイダー名を追加する。アカウント名とコマンド ID はコピー元に一致する。宛先に既に存在するアカウントも含む。無関係な宛先アカウントで名前が競合した場合は数字のサフィックスが付き、設定、スキル、プラグイン、会話履歴は各マシンにローカルなままとなる。

宛先の既存の認証情報は保持される。そこで既にサインインしているコピー元アカウントは、認証情報を置き換えることなく名前が同期される。他のアカウントはそれと並んで追加される。一致するアカウントの保存された認証情報を置き換えるには、宛先でそのアカウントのセッションを終了した後に `omarchy agent account copy --replace laptop claude` を使う。新しい宛先にはコピー元のアクティブなアカウントと切り替え設定も渡される。確立済みの宛先は自身のものを保持する。

認証情報は SSH 経由で移動し、宛先のプライベートファイルに保存される。だから信頼するマシンにだけコピーすること。これは一度だけのコピーであり、継続的な同期ではない。Codex のリフレッシュトークンは別のマシンによってローテーションされることがあり、コピーしたログインが更新を必要とする状態になる。複数のマシンで同時に使うには、別々にサインインするのが最も確実な選択だ。[Codex のアカウント認証に関するガイダンス](https://developers.openai.com/codex/auth/ci-cd-auth) を参照。

プロバイダーごとにアクティブなアカウントは 1 つで、すべての新しいセッションはそれとして開始する。`cx`、`cy`、素の `claude`、`codex`、`grok`、`omarchy agent` 経由で起動されるもの、`PATH` 上の CLI を見つけるスクリプトやエディターがそうだ。`omarchy agent account use work` で切り替え（`omarchy agent account use main` で戻る）、またはパネルでアカウントの番号を押してから `Enter` を押す（あるいはその Use ボタンをクリックする）。既に実行中のセッションは開始時のアカウントのままとなる。会話履歴、設定、スキル、プラグインはアカウント間で共有される。そのため同じフォルダーでの `claude --continue` は、新しいアカウントで中断したところから再開する。

アカウントが複数ある場合、パネルでは各アカウントの上限が横並びで表示され、アクティブなものに印が付く。デフォルトでは、アクティブなアカウントが上限の 95% を超えると Omarchy が通知し、その通知をクリックすると最も余裕のあるアカウントに切り替わる。パネルでアカウントの行にホバーして Use の隣に現れる Autoswitch をクリックする（あるいは `m` を押す）、または `omarchy agent account mode auto` を実行すると、代わりに自動で切り替わるようになる。有効な間は Autoswitch が Use の代わりを務め、もう一度クリックすると通知に戻る。`omarchy agent account mode auto 90` のように数字を追加してしきい値を変更する。すべてのアカウントがしきい値を超えている場合は、どのアカウントが最初に空くかと一緒に一度だけ通知される。アクティブなアカウントがそのしきい値まで 15 ポイント以内にある間（デフォルトでは 80%）、その上限は 15 分ごとではなく 3 分ごとに確認される。

`omarchy agent account list` はすべてのアカウントとその最新上限を表示し、`omarchy agent account remove work` は 1 つを忘れさせ、`omarchy agent account rename primary Hey` は 1 つの名前を変更する（またはパネルでアカウント名をクリックする）。これらのコマンドはデフォルトのエージェントのアカウントに対して動作する。別のプロバイダーにアクセスするには、`omarchy agent account use codex side` のように先に名前を付ける。`~/.claude` や `~/.codex` に既にあったログインは _Main_ アカウントで、そのままの場所に残る。約 8 時間以上使われていないアカウントは _Sign-in required_ と表示されることがある。それをクリックするとパネルですぐにそのアカウントに再度サインインできる。あるいはそのアカウントでセッションを開始すれば、自動でサインインが更新される。アカウント追加時に持っていた MCP サーバーはそのアカウントに引き継がれるが、後で `claude mcp add` で追加したものは追加したアカウントにしか到達しない。Claude Desktop や、CLI バイナリーへの絶対パスで設定されたツールは切り替えに追随しない。明示的な `CLAUDE_CONFIG_DIR`、`CODEX_HOME`、`GROK_HOME` は選択したアカウントより優先される。

### クラッシュの診断

Omarchy はプロセスのクラッシュを systemd-coredump で監視する。何かがセグメンテーション違反を起こすと、「Process crashed」通知が来る。それをクリックすると、クラッシュは Omarchy の diagnose-crash スキルと一緒にデフォルトのエージェントに引き渡される。そのスキルは、コアダンプから事実を確立し、そのクラッシュを上流に報告する価値があるかを判断する手順をエージェントに案内する。`coredumpctl list` の任意の PID に対して `omarchy agent crash <pid>` で手動で実行することもできる。

監視はデフォルトでオンだ。_Trigger > Toggle > Crash Capture_ で（あるいは `omarchy toggle crash-capture` で）オフにすると通知は止まる。`omarchy agent crash <pid>` は手動では引き続き使える。

クラッシュはプログラム単位で黙らせることもでき、それが診断の最後に提案されることだ。`omarchy crash mute hyprland` はそのプログラムだけの通知を止め、`omarchy crash mute hyprland off` はそれを戻し、`omarchy crash mute` だけではミュートしたものの一覧が表示される。名前と同様にバイナリーのパスでも受け付けるので、`omarchy crash mute /usr/bin/hyprland` でも同じことになる。スペースを含む名前は `omarchy crash mute 'Some App'` のように引用する。他のものはすべて引き続き通知され、ミュートされたプログラムは引き続きクラッシュする。これはリマインダーを隠すだけで、何も直さない。

### デスクトップアプリ

_Install > AI_ メニューには、グラフィカルな AI アプリもいくつかある。ChatGPT デスクトップアプリ、Claude デスクトップアプリ（Chat、Cowork、Claude Code タブ付きの Anthropic の Linux ベータ版）、xAI のモデルとチャットする Grok Bot、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexity デスクトップアプリ、T3 Code だ。Grok Bot はデスクトップチャットアプリだ。コーディングエージェントは `grok` コマンドだ。

Hermes Desktop は知っておくべきものだ。マシンには Hermes が 1 つだけあり、それはアプリのものだからだ。Hermes はアプリを通してのみインストールされ、デフォルトのエージェントが実行する `hermes` コマンドはアプリのものだ。Hermes をデフォルトのエージェントに選ぶと、_Install > AI_ 項目と同じものがインストールされる。パッケージと、Hermes 自身のインストーラーによってセットアップされる `~/.hermes` 配下の Hermes ランタイムで、初回は数分かかる。そのランタイムが、ターミナルの `hermes` コマンド、デフォルトのエージェント、アプリのすべてが使う唯一の Hermes で、Omarchy のリリースを待たずに `hermes update` で自身をアップデートする。インストールすると、Hermes に Omarchy テーマが `omarchy` という名前のスキンとして渡される。すべての Hermes の表面はテーマを切り替えるとそれに追随する。そうしたくなければ、Hermes の Appearance 設定で、あるいは `/skin` で別のものを選び直すこと。Omarchy はその選択に干渉しない。_Remove > AI_ でアプリを削除すると、まず Hermes がゲートウェイを含めて閉じられ、そのランタイムも一緒に削除される。チャット、メモリー、Hermes が自身のために書いたスキルは、指示しない限り保持される。それらデータと接続設定も削除するか尋ねられ、デフォルトは「いいえ」だ。

OpenClaw のデスクトップ体験はその Control UI で、独自のローカルゲートウェイをバックエンドとするウェブアプリとして開く。OpenClaw は `~/.openclaw` にあり、自身をアップデートする。Control UI の「Update Gateway」ボタンを使うか `openclaw update` を実行すると、ゲートウェイが新しいバージョンで再起動する。Omarchy は新規インストールが開始するリリースを選ぶだけだ。_Remove > AI_ で OpenClaw を削除すると、ゲートウェイサービスとアプリが一緒に削除され、その後 `~/.openclaw` も削除するか尋ねられる。そこには OpenClaw 本体やダウンロードするプラグインランタイムと一緒にチャットと認証情報が入っているからだ。デフォルトは保持で、OpenClaw を再インストールするとそれを再び拾う。

Herdr Desktop は [Herdr](https://herdr.dev) デスクトップアプリだ。スペース、タブ、そしてウィンドウを閉じてもそのコアで動き続けるターミナルとコーディングエージェントのペインがある。パッケージではなく Herdr 自身のインストーラーから来るため、`~/.local/share/herdr-app` にあり、まだ持っていない場合はそのコアを `~/.local/bin/herdr-core` に一緒に持ち込み、その両方を自身でアップデートする。Omarchy が `Super + Ctrl + Return` で提供する `herdr` コマンドを置き換えるのではなく、その隣に置かれ、そのコマンドのダイレクトキーを引き継ぐ。`Alt + Return` と `Alt + Shift + Return` はペインを下または右に分割し、`Alt + Escape` はそれを閉じ、`Ctrl + Alt + Arrow` はペイン間を移動し、`Alt + 1..9` と `Alt + Left/Right` はタブを選び、`Alt + Up/Down` はスペース間を移動する。`Ctrl + 1..9` はスペースを選び、`Alt + Shift + Up/Down` はエージェントを順に移動する。`Ctrl + Space` プレフィックスキーはターミナル専用のままとなる。アプリはシーケンスのために素の Ctrl キーを保持できないからだ。Omarchy はこれらを `~/.config/herdr-app/keys.json` に書き込み、`omarchy-refresh-herdr-app` がそれを戻す。インストールすると Herdr の Omarchy テーマが選ばれ、それ以降はあなたの Omarchy テーマに追随する。Herdr はライトモード用に 1 つ、ダークモード用に 1 つのテーマを保持する。そのため暗い Omarchy テーマと明るい Omarchy テーマを切り替えた後は、もう一方のモードのために Herdr のテーマピッカーで Omarchy をもう一度選ぶこと。

T3 Code はパッケージからではなく、`~/.local/share/t3code` にある公式 AppImage リリースから動作するため、自身をアップデートする。インストールすると、Stable チャネルで始めるか Nightly チャネルで始めるか尋ねられる。後で T3 Code の設定で切り替えること。スレッドと設定は `~/.t3` にあり、_Remove > AI_ で T3 Code を削除するとそれらも一緒に削除される。

### ローカルモデル

コーディングエージェントのために、自分のマシンでオープンモデルを実行する。プロンプトとコードはマシン内にとどまり、モデルに送られたものが外に出ることはない。次で始めること。

```bash
omarchy agent local use best
```

あるいは、トップバーのエージェントパネルで + を選び、次に Local AI を選ぶ。これはモデルがこのマシンに収まる場合に表示される。初めての場合は、モデルを実行する Podman がインストールされ、NVIDIA マシンではそれらに GPU を与える NVIDIA のコンテナツールキットがインストールされる。続いて Omarchy がこのマシンに推奨されるモデルを選び、ダウンロードし、起動する。数十 GB のダウンロードと、モデル実行中のマシンのメモリーの大半の使用を見込むこと。Flash Next は完全な 256K コンテキストで約 100 GiB を使う。他のモデルが必要なメモリーを保持している場合、それは停止状態でセットアップされ、どれかを停止すると開始できる状態になる。モデルはログアウト時に停止する。他のことにメモリーが必要なときは自分で停止すること。

`omarchy agent local list` は選択肢を表示し、収まらないものがある理由を説明する。別のものをセットアップするには `omarchy agent local use <recipe>` を実行する。今日では、128 GB Strix Halo マシン用に `qwen3.8-flash-next-gufo` と `qwen3.8-27b-gufo` が利用可能だ。27B は約 40 GiB を使うため、他の作業の余地が残る。新しいレシピと推奨は、パッケージ経由で `omarchy update` と一緒に届く。

セットアップしたモデルごとに、サブスクリプションの隣でエージェントパネルに独自の行が表示される。再生で開始、停止で止めてメモリーを解放し、ターミナルボタンでそのモデル上でエージェントを開く。メモリーに一緒に収まる場合は複数を同時に実行できる。収まらない場合は、Omarchy がどの実行中モデルを停止すべきか伝える。行をドラッグして並べ替え、選択した行で Delete を押すとモデルとそのダウンロードが削除される。

コマンドラインからは、`omarchy agent local start <recipe>` と `omarchy agent local stop <recipe>` が同じことをし、`omarchy agent local status` はすべてのモデルを表示し、`omarchy agent --local` は最後に起動したモデル上でデフォルトのエージェントを開く（デフォルトのエージェントがローカルモデルを使えない場合は pi）。OpenAI 互換のクライアントも接続できる。`status` は各モデルのアドレスを表示し（最初のものは `http://127.0.0.1:11435/v1`）、レシピ名がモデルで、キーは `~/.config/omarchy/agent-local/key` にある。

`omarchy agent local remove <recipe>` はモデルと、他のモデルが使っていないダウンロードを削除する。

サードパーティーランタイムには発行元がラベル表示される。Omarchy はすべてのモデルをネットワークアクセスなしで実行する。

### ローカル LLM

Omarchy は、ローカル LLM モデルを実行する方法として LM Studio と Ollama の 2 つを推奨する。LM Studio は、オープンウェイトモデルを見つけ、インストールし、実行するための GUI インターフェースを提供する。簡単に始められる素晴らしい方法だ。Ollama は同様のことを CLI で提供する。しかしローカルモデルが初めてなら、私なら LM Studio から始めるだろう。どちらも Omarchy Menu の _Install > AI_ でインストールできる。

### Omarchy スキル

エージェントスキルは、AI が特定のツールを特定の方法で使う助けになる。Omarchy にはシステムを調整するためのデフォルトスキルが同梱されている。Hyprland 設定を調整したり、バーを調整したり、テーマをゼロから作ったりするようなものだ。これは Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` と各 `~/.hermes/profiles/*/skills`）、そして汎用の `~/.agents/skills` の場所のスキルディレクトリーへシンボリックリンクされている。そのためほとんどのハーネスが自動的にそれを拾う。

しかしこのスキルは実験的なものと扱うこと。異なるモデルはそれぞれ異なる成果を出す。まずプランモードで実行するのが最善だ。そうすればエージェントが何を変更したいのか把握できる。そして、エージェントがすべてを滅茶苦茶にしたら、変更をロールバックしたり、`omarchy reinstall configs` を実行したりする覚悟をしておくこと。
