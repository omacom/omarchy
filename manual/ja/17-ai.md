### エージェントのインストールと更新

Hermes を除き、これらのエージェントは mise の遅延インストールを使います：初回起動時に CLI がインストールされ、以降の起動ではそれを再利用します。mise はまた、インストール済みエージェントの新しいリリースを最大で 4 時間に 1 回だけ、起動直前、またはシェルのプロンプトでバックグラウンドで確認します。その更新が失敗したりオフラインだったりしても、インストール済みのバージョンが動作します。`omarchy update` は Omarchy の残りの部分と一緒にインストール済みエージェントを更新し、`mup` は mise 管理のツールだけを更新します。

`claude update`、`codex update`、アプリ内の更新ボタンなど、エージェント自身のアップデーターは、mise 管理のインストールを更新しません。`codex update` は失敗し、`claude update` は成功したと報告しながら mise が追跡しない別コピーをインストールすることがあります。エージェントのネイティブインストーラーとアップデーターを使いたい場合は、それを `disable_tools` に追加してください；[プリインストールされた CLI ツール](18-development-tools.md#preinstalled-cli-tools) を参照してください。

必要になる前に設定済みのすべての遅延ツールをインストールするには、`mise install --include-lazy` を実行してください。これにはエージェントだけでなく、Omarchy の他のデフォルト CLI ツールも含まれます。単一ツールのインストールや独自のインストールを使う方法については、[プリインストールされた CLI ツール](18-development-tools.md#preinstalled-cli-tools) を参照してください。

`grok` は mise のファーストパーティ `grok` パッケージ経由でインストールされます。`claude` や `codex` と同じ方法です。`grok` を実行するか、_Agent > Harness_ で選んでください。x.ai の `curl | bash` インストーラーは避けてください。その方法では `~/.grok/bin` に 2 つ目のコピーが配置され、`PATH` の先頭に追加され、Omarchy のラッパーが上書きされます。

`dsh` はブラウザ UI を `127.0.0.1:3080` で開き、起動ディレクトリをデフォルトのワークスペースにします。そのブラウザ UI は開始プロンプトを受け付けないため、`omarchy agent prompt` はプロンプトをクリップボードに置いた状態でこれを開き、貼り付けられるようにします。Omarchy は DeepSeek の承認不要の権限プリセットでこれを起動します。DeepSeek Harness は、公式モデル API を使うときにセッションログを DeepSeek にアップロードします；ブラウザ UI の _Settings > General > Upload Session Log_ でオフにしてください。送信したフィードバックもセッションと一緒にアップロードされます。ただし `DSH_TELEMETRY_MODE=DISABLED` で起動した場合は除きます。

### デフォルトのエージェント

デフォルトのエージェントは `omarchy default agent <name>` で、または Omarchy Menu（`Super + Space`）の _Agent > Harness_ で選んでください。エージェントがまだインストールされていなければ、選ぶことでまずインストールされます。新しい Omarchy では一度限りの通知でこの選択を促されます。

Claude を選ぶと、Chromium、Chrome、Brave、Brave Origin、Edge 用にそのブラウザ拡張機能のセットアップも試みます。拡張機能のセットアップは全ユーザーに適用され、システムパスワードを求められることがあります；拡張機能のインストールをキャンセルしたり失敗したりしても、Claude は選択され起動します。ブラウザを再起動し、プロンプトが表示されたら拡張機能を有効化し、Claude にサインインして接続を完了してください。接続を確認するには Claude で `/chrome` を実行してください。Firefox と Zen はこの拡張機能に対応していません。このセットアップが追加される前に Claude がすでにデフォルトだった場合は、もう一度選択して拡張機能をインストールしてください。

選択が済むと、`Super + Shift + Ctrl + A` でデフォルトのエージェントを専用ターミナルウィンドウで起動します（まだ選んでいなければピッカーが表示されます）。`omarchy agent prompt "Review this project"` でタスクを指定して直接起動することもできます。Freebuff と DeepSeek Harness は開始プロンプトを受け付けないため、代わりにプロンプトをクリップボードに置いた状態で開きます。この方法で起動したエージェントは、それぞれの「止まって聞かない」モードで無人で動作します。実際にいろいろやってしまうので心しておいてください！MiniMax Code の対話セッションにはそのようなモードがないため、通常通り権限を求めます。また、エージェントはホームディレクトリに対する信頼を覚えることを拒否するため、`$HOME` から起動した場合は代わりに `~/Work` で開始します。

ターミナル用ショートカットもあります：`a` は現在のターミナルでデフォルトのエージェントをインラインで実行し、`c`、`cx`、`cy` は OpenCode、Claude Code、Codex を直接起動します（これも自動承認モードです）。テーマ変更もエージェントに同期されます：Claude Code、Pi、OpenCode、Hermes（Omarchy がインストールした後は）はすべて、Omarchy テーマを切り替えるとそれに追従します。

### エージェントへの指示

すべてのエージェントに対する個人的なルールは、共有スキルがある `~/.agents/skills` の隣の `~/.agents/AGENTS.md` に入れます。_Agent > Instructions_ で開いてください。ここでは、独自のグローバルファイルを保持する各ハーネスにもリンクされます：`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`~/.pi/agent/AGENTS.md`、`~/.config/opencode/AGENTS.md`、Copilot の `~/.copilot/copilot-instructions.md` などです。Crush と Amp は `~/.config/AGENTS.md` リンクを読み、omp、Kimi、DeepSeek Harness は `~/.agents/AGENTS.md` を直接読みます。デフォルトのエージェントを選ぶことでもリンクされます。すでに持っていた指示ファイルは、共有ファイルがまだなければそれが共有ファイルになります；そうでなければリンクの隣に `.bak` として保持されます。別のエージェントをインストールした後に再リンクするには `omarchy agent instructions` を実行してください。

### エージェントパネル

トップバーにはエージェントアイコンがあります。エージェントをセットアップする前は、そのパネルで Claude、Codex、Grok へのサインインを順に案内し、最初のものがデフォルトのエージェントになります。その後は、パネルですべてのサブスクリプションが 1 ページにまとまります：各エージェントとアカウントとそのプラン、5 時間のセッション制限と週間制限それぞれのメーターとリセットまでの時間（ホバーで正確な割合を表示）、または残りのプリペイド残高が、すべてのアカウントを通じた利用状況（今週のトークン数や最も使ったモデルなど）をローテーション表示する行の下に表示されます。_Make something_ では、デフォルトのエージェントにタスクを引き渡す、新しいテーマ、プラグイン、アプリ、ゲーム用のスタータープロンプトを提供します。アプリは Omarchy 自身の Hype、Monologue、Omacut と同じ方法で、C++ と Qt Quick で構築され、omarchy-make-app エージェントスキルに従い、必要なコンパイラと Qt の部品はインストール済みです。ゲームは `~/Games/vibes` にある単一の three.js ページで、omarchy-make-game エージェントスキルに従い、すべて現在のテーマの 1 つの Game Vibes ランチャーから開きます；three.js はウェブから読み込むため、起動には接続が必要です。Claude Code、Codex、Grok、Kimi、Cursor とその Grok Bot 枠、GitHub Copilot、Muse、Antigravity、Kimchi、Devin は制限付きでそのまま利用できます。Hermes、Mistral Vibe、Qwen Code は使ったことがあればセッションとトークンを表示します。pi、omp、opencode 経由で使うプロバイダーのプランとキーも表示されます：OpenCode Zen と Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan、Synthetic は制限付きで；Fireworks、OpenRouter、DeepSeek はプリペイド残高で；そして自分のハードウェアで動かすモデルは Local models の下に表示されます。すべてのエージェントは、課金元ごとに 1 回だけ数えられ、何台のハーネス経由で使っても変わりません。

バーのアイコンを左クリックするとパネルが開き、右クリックするとデフォルトのエージェントが起動します。その基になる使用記録は `omarchy agent usage-update` によって 15 分ごとに再生成され、パネルは同期フォルダ経由で他のマシンからの使用状況をマージすることもできます。設定の詳細については `$OMARCHY_PATH/shell/plugins/agents/` 下の README を参照してください。

### 複数のサブスクリプション

Claude、Codex、Grok のプランを複数契約している場合 — たとえば個人の Max と仕事用 — Omarchy ではすべてサインインしたまま切り替えることができます。サブスクリプションを追加するには、エージェントパネルの + を使うと、その場で順に案内されます。または `omarchy agent account add claude Work`（`codex` や `grok` も同様）でも追加できます。CLI がなければインストールされます。プロバイダーの初回アカウントは、CLI がいつも参照する場所で、通常のブラウザ経由でサインインします。それ以降はすべてプライベートウィンドウ経由でサインインします。これにより、ブラウザで既にサインインしているアカウントを誤って取得することがなくなります；追加するアカウントとしてそこでサインインし、あらかじめ開いているプライベートウィンドウは閉じてください。このために CLI からログアウトしてはいけません：ログアウトすると保存済みのサインインが失効し、そのアカウントを再度追加しなければならなくなります。

サブスクリプションのログインを SSH 経由で別の Omarchy マシンにコピーするには、`omarchy agent account copy user@laptop` を実行してください。送信側は、宛先に受信側がインストールされていない場合、一時的な受信側を提供します。そのため古い Omarchy マシンでも更新なしでアカウントを受け取れます。インストール済みの受信側が優先されます。これはすべての Claude、Codex、Grok サブスクリプションをコピーします；プロバイダー名を追加して選択することもできます。例：`omarchy agent account copy laptop claude`。アカウント名とコマンド ID は送信元と一致します。宛先に既に存在するアカウントも含みます。無関係な宛先アカウントで名前が競合する場合は数値サフィックスが付きます。設定、スキル、プラグイン、会話履歴はマシンごとにローカルのままです。

宛先の既存の認証情報は保持されます。送信元アカウントが既にそこでサインインしている場合、その名前は同期されますが認証情報は置き換えられません；他のアカウントは並んで追加されます。一致するアカウントの保存済み認証情報を置き換えるには、宛先でそのアカウントのセッションを終了した後、`omarchy agent account copy --replace laptop claude` を使ってください。新しい宛先には送信元のアクティブなアカウントと切り替え設定も引き継がれます；既に確立した宛先では独自の設定が保持されます。

認証情報は SSH 経由で移動し、宛先のプライベートファイルに保存されます。信頼できるマシンにのみコピーしてください。これは一度きりのコピーであり、継続的な同期ではありません。Codex のリフレッシュトークンは別のマシンでローテーションされることがあり、コピーしたログインが更新が必要な状態になることがあります；複数マシンで同時利用するには別々のサインインが最も信頼できます。[Codex のアカウント認証ガイダンス](https://developers.openai.com/codex/auth/ci-cd-auth) を参照してください。

プロバイダーごとにアクティブなアカウントは 1 つで、すべての新しいセッションはそれで開始します：`cx`、`cy`、素の `claude`、`codex`、`grok`、`omarchy agent` 経由で起動するものすべて、`PATH` で CLI を見つけるスクリプトやエディタも含まれます。`omarchy agent account use work` で切り替え（`omarchy agent account use main` で元に戻す）、またはパネルでアカウントの番号を押し次に `Enter` を押す（または Use ボタンをクリックする）ことでも切り替えます。実行中の Claude セッションも次のメッセージから切り替わります：すべての Claude セッションは `~/.claude` で動作し、そこには常にアクティブなアカウントのサインインが保持されます。古い Omarchy でアカウント自身のフォルダで開始した Claude セッションは、終了するまでそのサインインを保持します。そのため切り替え時にそうしたセッション名が示され、それらがなくなると自動で完了します。実行中の Codex と Grok セッションは開始時のアカウントのままです。会話履歴、設定、スキル、プラグインはアカウント間で共有されるため、同じフォルダで `claude --continue` を実行すると新しいアカウントで中断したところから再開できます。

アカウントが複数ある場合、パネルでは各アカウントの制限が横並びで表示され、アクティブなものにマークが付きます。デフォルトでは、アクティブなアカウントが制限の 95% を超えると Omarchy が通知し、通知をクリックすると最も余裕のあるアカウントに切り替わります。パネルでアカウントの行にホバーして Use の隣に表示される Autoswitch をクリックする（または `m` を押す）か、`omarchy agent account mode auto` を実行すると、自動で切り替えるようになります；オンの間は Autoswitch が Use の場所を占め、再度クリックすると通知に戻ります。`omarchy agent account mode auto 90` のように数値を追加してしきい値を変更できます。すべてのアカウントがしきい値を超えた場合は、一度だけその旨と、最初に空きが出るアカウントが通知されます。アクティブなアカウントがしきい値まで 15 ポイント以内（デフォルトでは 80%）にある間、その制限は 15 分ごとではなく 3 分ごとに確認されます。

`omarchy agent account list` はすべてのアカウントと最新の制限を表示し、`omarchy agent account remove work` はアカウントを 1 つ忘れ、`omarchy agent account rename primary Hey` は名前を変更します（またはパネルでアカウント名をクリック）。これらのコマンドはデフォルトのエージェントのアカウントに対して動作します；他のプロバイダーを対象にする場合は、先に名前を指定してください。例：`omarchy agent account use codex side`。`~/.claude` や `~/.codex` に既にあったログインは _Main_ アカウントです。Codex のものはそのままの場所にあります；Claude のものは別のアカウントがアクティブな間、専用フォルダで待機します。約 8 時間以上使われていないアカウントは _Sign-in required_ と表示されることがあります；クリックしてパネルでそのアカウントに再サインインするか、切り替えてセッションを開始すれば自動でサインインが更新されます。`claude mcp add` で追加した MCP サーバーは、すべての Claude が `~/.claude` で動作するためすべての Claude アカウントに届きます；Codex と Grok では、アカウント追加時に持っていたサーバーはそのアカウントにも引き継がれますが、後から追加したものは追加したアカウントにしか届きません。Claude Desktop は独自のサインインを保持し、CLI バイナリへの絶対パスで設定された Codex や Grok ツールは切り替えに追従しません。明示的な `CLAUDE_CONFIG_DIR`、`CODEX_HOME`、`GROK_HOME` は選択したアカウントより優先されます。

### クラッシュ診断

Omarchy は systemd-coredump でプロセスのクラッシュを監視します。何かがセグメンテーション違反を起こすと、「Process crashed」通知が表示されます — クリックすると、クラッシュがデフォルトのエージェントに引き渡され、Omarchy の diagnose-crash スキルとともに、コアダンプから事実を確立し、クラッシュを上流に報告する価値があるか判断する過程をエージェントが案内します。`coredumpctl list` の任意の PID に対して `omarchy agent crash <pid>` で手動で実行することもできます。

監視はデフォルトでオンです。_Trigger > Toggle > Crash Capture_ でオフにするか（または `omarchy toggle crash-capture`）、通知は止まります；`omarchy agent crash <pid>` は手動では引き続き動作します。

クラッシュはプログラムごとに黙らせることもできます。これが診断の最後に提示されるものです。`omarchy crash mute hyprland` はそのプログラムのみの通知を停止し、`omarchy crash mute hyprland off` で元に戻り、`omarchy crash mute` 単体ではミュートしたものの一覧を表示します。バイナリのパスでも名前でも同様に受け付けるため、`omarchy crash mute /usr/bin/hyprland` でも同じです。スペースを含む名前は `omarchy crash mute 'Some App'` のように引用してください。他のすべての通知は継続し、ミュートしたプログラムも依然としてクラッシュします — これはリマインダーを隠すだけで、何も修正しません。

### デスクトップアプリ

_Install > AI_ メニューにはグラフィカルな AI アプリもいくつかあります：Antigravity Desktop、ChatGPT デスクトップアプリ、Claude デスクトップアプリ（Anthropic の Linux ベータ、Chat、Cowork、Claude Code タブ付き）、xAI のモデルとチャットする Grok Bot、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexity デスクトップアプリ、T3 Code です。Grok Bot はデスクトップチャットアプリです。コーディングエージェントは `grok` コマンドです。

Hermes Desktop は知っておくべき存在です。1 台のマシンには Hermes は 1 つだけであり、それはアプリのものだからです：Hermes はアプリ経由でしかインストールされず、デフォルトのエージェントが実行する `hermes` コマンドはアプリのものです。Hermes をデフォルトのエージェントに選ぶと、_Install > AI_ 項目と同じものがインストールされます：パッケージと、Hermes 自身のインストーラーによって `~/.hermes` にセットアップされる Hermes ランタイムで、初回は数分かかります。そのランタイムが、ターミナルの `hermes` コマンド、デフォルトのエージェント、アプリすべてが使う唯一の Hermes であり、Omarchy のリリースを待たず `hermes update` で自己更新します。インストールすると Hermes に Omarchy テーマが `omarchy` という名前のスキンとして渡され、すべての Hermes 画面はテーマ切り替えに追従します；そうしたくない場合は Hermes の Appearance 設定か `/skin` で別のものを選んでください。Omarchy はその選択に干渉しません。_Remove > AI_ でアプリを削除すると、まず Hermes が（ゲートウェイ含め）閉じられ、そのランタイムも一緒に削除されますが、チャット、メモリ、Hermes が自身のために書いたスキルは、指示しない限り保持されます：そのデータと接続設定も一緒に削除するか尋ね、デフォルトはいいえです。

OpenClaw のデスクトップ体験はその Control UI で、独自のローカルゲートウェイをバックエンドにウェブアプリとして開きます。OpenClaw は `~/.openclaw` にあり自己更新します：Control UI の「Update Gateway」ボタンを使うか `openclaw update` を実行すると、ゲートウェイが新しいバージョンで再起動します。Omarchy は新鮮なインストールが開始するリリースを選ぶだけです。_Remove > AI_ で OpenClaw を削除するとゲートウェイサービスとアプリが一緒に削除され、次に `~/.openclaw` も削除するか尋ねます。そこには OpenClaw 本体やダウンロードするプラグインランタイムとともにチャットや認証情報が入っているからです；デフォルトは保持し、OpenClaw を再インストールすれば再び拾い上げます。

Herdr Desktop は [Herdr](https://herdr.dev) デスクトップアプリです：ターミナルとコーディングエージェントのスペース、タブ、ペインがあり、ウィンドウを閉じてもそのコアで実行し続けます。パッケージではなく Herdr 自身のインストーラーから提供されるため、`~/.local/share/herdr-app` に配置され、まだ持っていなければ `~/.local/bin/herdr-core` にコアも一緒に持ち込み、両方とも自己更新します。`Super + Ctrl + Return` で Omarchy が提供する `herdr` コマンドの隣にあり置き換えるものではありません。そしてそのコマンドの直接キーを受けます：`Alt + Return` と `Alt + Shift + Return` はペインを下または右に分割し、`Alt + Escape` で閉じ、`Ctrl + Alt + Arrow` でペイン間を移動し、`Alt + 1..9` と `Alt + Left/Right` でタブを選び、`Alt + Up/Down` でスペース間を移動します。`Ctrl + 1..9` はスペースを選び、`Alt + Shift + Up/Down` はエージェント間を移動します。`Ctrl + Space` プレフィックスキーはターミナル専用のままです。アプリはシーケンス用に素の Ctrl キーを保持できないからです。Omarchy はこれらを `~/.config/herdr-app/keys.json` に書き込み、`omarchy-refresh-herdr-app` で元に戻します。インストールすると Herdr の Omarchy テーマが選ばれ、以降 Omarchy テーマに追従します。Herdr はライトモード用とダークモード用に 1 つずつテーマを保持するため、ダークな Omarchy テーマとライトな Omarchy テーマを切り替えた後は、もう一方のモード用に Herdr のテーマピッカーで Omarchy をもう一度選んでください。

T3 Code はパッケージではなく公式 AppImage リリースから `~/.local/share/t3code` で動作するため、自己更新します。インストール時に Stable チャンネルか Nightly チャンネルか尋ねます；後で T3 Code の設定で切り替えられます。スレッドと設定は `~/.t3` にあり、_Remove > AI_ で T3 Code を削除すると一緒に削除されます。

### ローカルモデル

コーディングエージェント用に自分のマシンでオープンモデルを実行してください。プロンプトとコードはマシン上に残ります；モデルに送ったものがマシンの外に出ることはありません。次から始めてください：

```bash
omarchy agent local use best
```

または、トップバーのエージェントパネルで + を選び、次に Local AI を選んでください。これはこのマシンに合うモデルがあるときに表示されます。初回はモデルを実行する Podman がインストールされ、NVIDIA マシンでは GPU を使えるようにする NVIDIA のコンテナツールキットもインストールされます。次に Omarchy はこのマシンに推奨されるモデルを選び、ダウンロードして起動します。数十 GB のダウンロードと、モデル実行中にマシンのメモリの大半が使われることを想定してください：Flash Next はフル 256K コンテキストで約 100 GiB 使います。必要なメモリを他のモデルが占有している場合は、停止した状態でセットアップされ、それらを停止すれば起動できるようになります。モデルはログアウト時に停止します；他の用途にメモリが必要なときは自分で停止してください。

`omarchy agent local list` は選択肢を表示し、一部が合わない理由を説明します。別のものをセットアップするには `omarchy agent local use <recipe>` を実行してください。現在、128 GB Strix Halo マシン用に `qwen3.8-flash-next-gufo` と `qwen3.8-27b-gufo` が利用できます；27B は約 40 GiB を使うため他の作業の余地が残ります。Intel の Arc B390 を搭載した 64 GB ラップトップでは、`qwen3.6-35b-a3b-llamacpp` が約 30 GiB で動作します。新しいレシピと推奨は `omarchy update` でパッケージ経由で届きます。

セットアップしたモデルごとにエージェントパネルに独自の行が、サブスクリプションの隣に表示されます：再生で起動、停止で一時停止してメモリを解放し、ターミナルボタンでそのモデルでエージェントを開きます。メモリに収まれば複数を同時に実行できます；収まらない場合は、Omarchy がどの実行中モデルを停止すべきか伝えます。行をドラッグして並び替え、選択した行で Delete を押してモデルとそのダウンロードを削除できます。

セットアップしたモデルごとにアプリランチャーにも独自の項目が、モデル名とそのメーカーのロゴで表示されます。Claude、Codex、Grok にサインインしたときに項目が追加されるのと同じ方法です。それを開くとそのモデルでエージェントが開き、モデルが実行中でなければ先に起動します：ターミナルに読み込み中と表示され、起動したらエージェントに引き渡します。モデルを削除するとその項目も削除されます。

モデルはセットアップした通りに実行し続けます。そのため Omarchy の更新でエージェントの下で再起動されることは決してありません。Omarchy がセットアップ済みモデルの新しいランタイムや新しいウェイトを持っている場合、その行に更新ボタンが表示されます：押すとモデルがバックグラウンドで再セットアップされ、変更分だけダウンロードし、新しいバージョンで再起動します。停止していたモデルは停止したままです。`omarchy agent local update` はターミナルからすべてのモデルに対して同じことをします。

コマンドラインからは、`omarchy agent local start <recipe>` と `omarchy agent local stop <recipe>` が同じことをし、`omarchy agent local status` はすべてのモデルを表示し、`omarchy agent --local` は最後に起動したモデルでデフォルトのエージェントを開きます。pi、OpenCode、Qwen Code が使えます；他のデフォルトの場合は pi で開きます。pi はセットアップしたすべてのモデルと、ペアリングしたマシン上のモデルも独自のモデルピッカーに一覧表示するため、素の `pi` でもそれらにアクセスできます。OpenAI 互換のクライアントも接続できます：`status` は各モデルのアドレスを表示し（最初のものは `http://127.0.0.1:11435/v1`）、レシピ名がモデル名で、キーは `~/.config/omarchy/agent-local/key` にあります。

`omarchy agent local remove <recipe>` はモデルと、他のモデルが使っていないダウンロードを削除します。

サードパーティのランタイムにはその発行元がラベル付けされます。Omarchy はすべてのモデルをネットワークアクセスなしで実行します。

### ローカル LLM

Omarchy ではローカル LLM モデルを実行する方法として LM Studio と Ollama の 2 つを推奨します。LM Studio はオープンウェイトモデルを見つけ、インストールし、実行するための GUI インターフェースを提供します。簡単に始めるには最適な方法です。Ollama は同様のことを CLI で提供します。ローカルモデルが初めてなら、私なら LM Studio から始めます。どちらも Omarchy Menu の _Install > AI_ でインストールできます。

### Omarchy スキル

エージェントスキルは AI が特定のツールを特定の方法で使うのを助けます。Omarchy にはシステムをカスタマイズするためのデフォルトスキルが付属しています。Hyprland 設定の調整、バーの調整、さらにはテーマをゼロから新規作成するようなことです。これは Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` と各 `~/.hermes/profiles/*/skills`）、汎用の `~/.agents/skills` のスキルディレクトリにシンボリックリンクされているため、ほとんどのハーネスが自動で拾います。

しかし、このスキルは実験的なものとして扱うべきです。モデルによって効果は異なります。まずプランモードで実行し、エージェントが何を変更したいか把握するのが最善です。そして変更をロールバックしたり、エージェントがすべてを台無しにした場合は `omarchy reinstall configs` を実行したりする準備をしておいてください。
