### エージェントのインストールと更新

Hermes と OpenClaw を除き、これらのエージェントは mise の遅延インストールを使う：初回起動時に CLI がインストールされ、以降の起動ではそれを再利用する。mise はまた、インストール済みエージェントの新リリースを、起動直前またはシェルプロンプトでバックグラウンドに、最大で 4 時間に 1 回チェックする。その更新が失敗したりオフラインだったりすれば、インストール済みのバージョンが動作する。`omarchy update` は Omarchy の他の部分と一緒にインストール済みエージェントを更新し、`mup` は mise 管理ツールだけを更新する。

エージェント独自のアップデーター、たとえば `claude update`、`codex update`、アプリ内の更新ボタンなどでは、mise 管理のインストールは更新されない。`codex update` は失敗し、`claude update` は成功したと報告しながら mise が追跡しない別コピーをインストールすることがある。エージェント独自のインストーラーとアップデーターを使いたい場合は、それを `disable_tools` に追加すること。詳しくは [プリインストールされた CLI ツール](18-development-tools.md#preinstalled-cli-tools) を参照。

必要なときに備えて設定済みのすべての遅延ツールをインストールするには、`mise install --include-lazy` を実行する。これにはエージェントだけでなく、Omarchy の他のデフォルト CLI ツールも含まれる。単一ツールのインストールや独自インストールの利用については [プリインストールされた CLI ツール](18-development-tools.md#preinstalled-cli-tools) を参照。

`grok` は、`claude` や `codex` と同じように、mise のファーストパーティ `grok` パッケージ経由でインストールされる。`grok` を実行するか、_Agent > Harness_ で選ぶこと。x.ai の `curl | bash` インストーラーは使わないこと。その方法では `~/.grok/bin` に 2 つ目のコピーが置かれ、`PATH` の先頭に追加され、Omarchy のラッパーが上書きされる。

`dsh` は `127.0.0.1:3080` でブラウザ UI を開き、起動したディレクトリをデフォルトのワークスペースとする。そのブラウザ UI は開始プロンプトを受け取らないため、`omarchy agent prompt` はプロンプトをクリップボードに入れた状態で開くので貼り付けて使う。Omarchy は DeepSeek の承認なし権限プリセットで起動する。DeepSeek Harness は、公式モデル API を使うとセッションログを DeepSeek にアップロードする；ブラウザ UI の _Settings > General > Upload Session Log_ でオフにできる。送信したフィードバックもセッションと一緒にアップロードされる。ただし `DSH_TELEMETRY_MODE=DISABLED` で起動した場合は除く。

### デフォルトのエージェント

デフォルトのエージェントは `omarchy default agent <name>` で、または Omarchy Menu（`Super + Space`）の _Agent > Harness_ で選ぶ。エージェントがまだインストールされていなければ、選ぶことでまずインストールされ、Agent の隣のアプリランチャーにそのエージェント専用のランチャーも追加される。新しい Omarchy では、一度だけの通知でこの選択を促す。

Claude を選ぶと、Chromium、Chrome、Brave、Brave Origin、Edge 用のブラウザ拡張機能のセットアップも試みる。拡張機能のセットアップはすべてのユーザーに適用され、システムパスワードを求められることがある；キャンセルしたり拡張機能のインストールに失敗したりしても、Claude は選択され起動する。ブラウザを再起動し、求められたら拡張機能を有効にし、Claude にサインインして接続を完了すること。接続の確認は Claude で `/chrome` を実行する。Firefox と Zen はこの拡張機能に対応していない。このセットアップが追加される前にすでに Claude がデフォルトだった場合は、もう一度選び直すと拡張機能がインストールされる。

選び終えたら、`Super + Shift + Ctrl + A` で専用のターミナルウィンドウでデフォルトのエージェントを起動する（まだ選んでいなければピッカーが表示される）。`omarchy agent prompt "Review this project"` のようにタスクを直接与えて起動することもできる。Freebuff と DeepSeek Harness は開始プロンプトを受け取らないため、代わりにプロンプトをクリップボードに入れた状態で開くので貼り付けて使う。この方法で起動したエージェントは、それぞれの「止まって聞かない」モードで無人で動作するので、本当に作業を実行する心構えをしておくこと！ MiniMax Code には対話セッション用のそうしたモードがないため、通常どおり権限を求める。また、エージェントはホームディレクトリに対する信頼を記憶することを拒否するため、`$HOME` からの起動は代わりに `~/Work` で開始する。

ターミナル用のショートカットもある：`a` は現在のターミナルでインラインでデフォルトのエージェントを実行し、`c`、`cx`、`cy` は OpenCode、Claude Code、Codex を直接起動する（こちらも自動承認モードだ）。テーマの変更もエージェントに同期される：Omarchy のテーマを切り替えると、Claude Code、Pi、OpenCode、Hermes（Omarchy がインストール済みの場合）が追随する。

### エージェントへの指示

すべてのエージェントに対する個人用ルールは、共有スキル `~/.agents/skills` の隣にある `~/.agents/AGENTS.md` に置く。_Agent > Instructions_ で開ける。そこから、独自のグローバルファイルを持つ各ハーネスにもリンクされる：`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`~/.pi/agent/AGENTS.md`、`~/.config/opencode/AGENTS.md`、Copilot の `~/.copilot/copilot-instructions.md` などだ。Crush と Amp は `~/.config/AGENTS.md` リンクを読み、omp、Kimi、DeepSeek Harness は `~/.agents/AGENTS.md` を直接読む。デフォルトのエージェントを選ぶとそこにもリンクされる。すでに持っていた指示ファイルは、共有用がまだなければ共有用になり、そうでなければリンクの隣に `.bak` として保持される。別のエージェントをインストールした後に再リンクするには `omarchy agent instructions` を実行する。

### エージェントパネル

トップバーにはエージェントアイコンがある。エージェントをセットアップする前は、そのパネルで Claude、Codex、Grok へのサインインを順に案内し、最初に設定したものがデフォルトのエージェントになる。その後は、パネルですべてのサブスクリプションを 1 ページにまとめる：各エージェントとアカウントとそのプラン、5 時間のセッション制限と週間制限それぞれのメーターとリセットまでの時間（ホバーで正確な割合を表示）、またはプリペイド残高を、それら全体での使用状況をローテーション表示する行の下に表示する。例として今週のトークン数や最も使ったモデルなどだ。_Make something cool_ の下では、新しいテーマ、プラグイン、アプリ、ゲームのスタータープロンプトが用意され、タスクをデフォルトのエージェントに渡す。アプリは Omarchy 自身の Hype、Monologue、Omacut と同じように C++ と Qt Quick で構築され、omarchy-make-app エージェントスキルに従い、必要なコンパイラと Qt の部品はインストール済みだ。ゲームは `~/Games/vibes` にある単一の three.js ページで、omarchy-make-game エージェントスキルに従い、すべて現在のテーマの 1 つの Game Vibes ランチャーから開く；three.js をウェブから読み込むため、開始には接続が必要だ。Claude Code、Codex、Grok、Kimi、Cursor とその Grok Bot 枠、GitHub Copilot、Muse、Antigravity、Devin は制限付きで標準対応し、Kimchi はプラン、プリペイドクレジット、支出予算で、Hermes、Mistral Vibe、Qwen Code は一度使うとセッションとトークンを表示する。pi、omp、opencode 経由で使うプロバイダーのプランとキーも表示される：OpenCode Zen と Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan、Synthetic は制限付きで；OpenRouter と DeepSeek はプリペイド残高で；Fireworks は過去 30 日間の支出で。自分のハードウェアで実行するモデルのトークンも合計に含まれる；モデル自体には専用パネルがあり、[ローカルモデル](#local-models) で説明する。すべてのエージェントは、課金元ごとに 1 回だけ数えられ、いくつのハーネス経由で使っても重複しない。

バーのアイコンを左クリックするか `Super + Ctrl + X` を押すとパネルが開き、右クリックでデフォルトのエージェントを起動し、中央クリックで更新する。その背後にある使用記録は `omarchy agent usage update` によって 15 分ごとに再生成され、パネルは同期フォルダ経由で他のマシンからの使用状況を統合することもできる。設定の詳細は `$OMARCHY_PATH/shell/plugins/agents/` の README を参照。

### 複数のサブスクリプション

Claude、Codex、Grok のプランを複数払っている場合 — たとえば個人の Max と仕事用など — Omarchy はすべてをサインインしたままにし、それらを切り替えられる。サブスクリプションの追加は、エージェントパネルの + からその場で案内に従うか、`omarchy agent account add claude Work`（または `codex`、または `grok`）で行う。CLI がなければインストールする。プロバイダーの最初のアカウントは、CLI が常に参照する場所で、通常のブラウザ経由でサインインする。それ以降のアカウントはすべてプライベートウィンドウ経由でサインインするので、ブラウザですでにサインインしているアカウントを誤って拾うことはない；追加するアカウントとしてそこでサインインし、すでに開いているプライベートウィンドウは先に閉じておくこと。このために CLI からログアウトしては決してならない：ログアウトすると保存済みのサインインが取り消され、そのアカウントを再度追加しなければならなくなる。

サブスクリプションのログインを SSH 経由で別の Omarchy マシンにコピーするには、`omarchy agent account copy user@laptop` を実行する。宛先に一時的な受信側がインストールされていない場合、送信側がそれを提供するので、古い Omarchy マシンでも更新なしでアカウントを受け取れる。インストール済みの受信側が優先される。これはすべての Claude、Codex、Grok サブスクリプションをコピーする；プロバイダー名を追加して選択でき、例として `omarchy agent account copy laptop claude` のようにする。アカウント名とコマンド ID は送信元と一致し、宛先にすでに存在するアカウントも含まれる。無関係な宛先アカウントで名前が競合する場合は数値サフィックスが付く。設定、スキル、プラグイン、会話履歴は各マシンにローカルなままとなる。

既存の宛先認証情報は保持される。送信元アカウントがすでにそこでサインインしている場合、その認証情報を置き換えずに名前が同期される；他のアカウントはその横に追加される。一致するアカウントの保存済み認証情報を置き換えるには、宛先でそのアカウントのセッションを終了した後で `omarchy agent account copy --replace laptop claude` を使う。新しい宛先には送信元のアクティブアカウントと切り替え設定も引き継がれる；確立済みの宛先は自身のものを保持する。

認証情報は SSH 経由で移動し、宛先のプライベートファイルに保存されるので、信頼するマシンにだけコピーすること。これは一度きりのコピーであり、継続的な同期ではない。Codex のリフレッシュトークンは別のマシンでローテーションされることがあり、コピーしたログインは更新が必要になることがある；複数のマシンで同時使用するには別々のサインインが最も確実な選択だ。[Codex のアカウント認証ガイダンス](https://developers.openai.com/codex/auth/ci-cd-auth) を参照。

プロバイダーごとにアクティブなアカウントは 1 つで、すべての新しいセッションはそのアカウントで開始する：`cx`、`cy`、素の `claude`、`codex`、`grok`、`omarchy agent` 経由で起動するものすべて、`PATH` 上の CLI を見つけるスクリプトやエディタだ。切り替えは `omarchy agent account use work`（戻すには `omarchy agent account use main`）で、またはパネルでアカウントの番号を押してから `Enter` を押す（または Use ボタンをクリックする）ことで行う。実行中の Claude セッションも次のメッセージから切り替わる：すべての Claude セッションは `~/.claude` で動作し、そこには常にアクティブアカウントのサインインが入っている。古い Omarchy によってアカウント専用フォルダで開始された Claude セッションは、終了するまでそのサインインを保持するので、切り替え時にそうしたセッション名が表示され、それらがなくなれば自動で完了する。実行中の Codex と Grok セッションは開始時のアカウントのままとなる。会話履歴、設定、スキル、プラグインはアカウント間で共有されるので、同じフォルダで `claude --continue` すると新しいアカウントでも前回の続きから再開できる。

アカウントが複数ある場合、パネルでは各アカウントの制限が並べて表示され、アクティブなものに印が付く。デフォルトでは、アクティブアカウントが制限の 95% を超えると Omarchy が通知し、通知をクリックすると最も余裕のあるアカウントに切り替わる。パネルでアカウントの行にホバーして Use の横に現れる Autoswitch をクリックするか（または `m` を押す）、`omarchy agent account mode auto` を実行すると、代わりに自動で切り替わるようにできる；有効な間は Autoswitch が Use の代わりとなり、もう一度クリックすると通知に戻る。`omarchy agent account mode auto 90` のように数値を追加するとしきい値を変更できる。すべてのアカウントがしきい値を超えている場合は、どのアカウントが最初に解放されるかと合わせて一度だけ通知される。アクティブアカウントがしきい値まで 15 ポイント以内（デフォルトでは 80%）にある間、その制限は 15 分ごとではなく 3 分ごとにチェックされる。

`omarchy agent account list` はすべてのアカウントと最新の制限を表示し、`omarchy agent account remove work` は 1 つを忘れ、`omarchy agent account rename primary Hey` は名前を変更する（またはパネルでアカウント名をクリックする）。これらのコマンドはデフォルトのエージェントのアカウントに対して動作する；他のプロバイダーにアクセスするには、先にその名前を指定する。例として `omarchy agent account use codex side` のようにする。`~/.claude` や `~/.codex` にすでにあったログインは _Main_ アカウントだ。Codex のものはその場に留まる；Claude のものは別のアカウントがアクティブな間、専用フォルダで待機する。約 8 時間以上使われていないアカウントは _Sign-in required_ と表示されることがある；クリックするとパネルですぐにそのアカウントに再サインインでき、または切り替えてセッションを開始すれば自動でサインインが更新される。`claude mcp add` で追加した MCP サーバーは、すべて `~/.claude` で動作するためすべての Claude アカウントに届く；Codex と Grok では、アカウント追加時に持っていたサーバーはそのアカウントにも移るが、後から追加したものは追加したアカウントにしか届かない。Claude Desktop は独自のサインインを保持し、CLI バイナリへの絶対パスで設定された Codex または Grok ツールは切り替えに追随しない。明示的な `CLAUDE_CONFIG_DIR`、`CODEX_HOME`、`GROK_HOME` は選択されたアカウントより優先される。

### クラッシュ診断

Omarchy は systemd-coredump でプロセスクラッシュを監視する。デフォルトのエージェントを選ぶと、自分のプログラムがコアダンプしたときに「Process crashed」通知が表示される — クリックすると、クラッシュがデフォルトのエージェントに Omarchy の omarchy-diagnose-crash スキルとともに渡され、エージェントはコアダンプから事実を確立し、そのクラッシュを上流に報告する価値があるかどうかを判断する手順を進める。`coredumpctl list` の任意の PID に対して `omarchy agent crash <pid>` で手動で実行することもできる。

監視はデフォルトで有効だ。_Trigger > Toggle > Crash Capture Off_ で（または `omarchy toggle crash-capture` で）オフにすると通知は止まる；`omarchy agent crash <pid>` は手動では引き続き使える。

クラッシュはプログラムごとに 1 つずつ黙らせることもでき、診断の最後にそれが提案される。`omarchy crash mute hyprland` はそのプログラムだけ通知を止め、`omarchy crash mute hyprland off` で戻し、`omarchy crash mute` 単体ではミュートしたものの一覧を表示する。バイナリのパスでも名前でも同じように受け付けるので、`omarchy crash mute /usr/bin/hyprland` でも同じだ。スペースを含む名前は `omarchy crash mute 'Some App'` のように引用する。他のものはすべて通知され、ミュートされたプログラムもクラッシュし続ける — これはリマインダーを隠すだけで、何も修正しない。

### デスクトップアプリ

_Install > AI_ メニューにはグラフィカルな AI アプリもいくつかある：Amp Desktop、Antigravity Desktop、ChatGPT デスクトップアプリ、Claude デスクトップアプリ（Anthropic の Linux ベータ、Chat、Cowork、Claude Code タブ付き）、xAI のモデルとチャットする Grok Bot、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexity デスクトップアプリ、T3 Code だ。Grok Bot はデスクトップチャットアプリだ。コーディングエージェントは `grok` コマンドだ。

Hermes Desktop は知っておくべき存在だ。1 台のマシンには Hermes は 1 つだけあり、それはアプリのものだからだ：Hermes はアプリ経由でしかインストールされず、デフォルトのエージェントが実行する `hermes` コマンドはアプリのものだ。Hermes をデフォルトのエージェントに選ぶと、_Install > AI_ の項目と同じものがインストールされる：パッケージと、Hermes 自身のインストーラーによってセットアップされる `~/.hermes` 配下の Hermes ランタイムで、初回は数分かかる。そのランタイムが、ターミナルの `hermes` コマンド、デフォルトのエージェント、アプリのすべてが使う唯一の Hermes であり、Omarchy のリリースを待たずに `hermes update` で自己更新する。インストールすると Hermes に Omarchy テーマが `omarchy` という名前のスキンとして渡され、テーマを切り替えるたびにすべての Hermes 画面が追随する；そうしたくない場合は Hermes の Appearance 設定か `/skin` で別のものを選び、その選択は Omarchy が干渉しない。_Remove > AI_ でアプリを削除すると、まず Hermes を終了し（ゲートウェイを含む）、そのランタイムも一緒に削除し、指示しない限りチャット、メモリ、Hermes が自身のために書いたスキルは保持する：そのデータと接続設定も削除するか尋ね、デフォルトは「いいえ」だ。

OpenClaw のデスクトップ体験は Control UI で、独自のローカルゲートウェイをバックエンドとするウェブアプリとして開く。OpenClaw は `~/.openclaw` に置かれ自己更新する：Control UI の「Update Gateway」ボタンを使うか `openclaw update` を実行すると、ゲートウェイは新しいバージョンで再起動する。Omarchy は新規インストールが開始するリリースを選ぶだけだ。OpenClaw をデフォルトのエージェントにすることもできる：_Agent > Harness_ で選ぶと `~/.openclaw` に同じコピーがセットアップされ、エージェントはゲートウェイに接続された OpenClaw のターミナル UI を開く。_Remove > AI_ で OpenClaw を削除するとゲートウェイサービスとアプリが一緒に削除され、その後 `~/.openclaw` も削除するか尋ねる。そこには OpenClaw 自体やダウンロードするプラグインランタイムとともにチャットや認証情報が入っているからだ；デフォルトでは保持され、OpenClaw を再インストールすると再び拾い上げる。

Herdr Desktop は [Herdr](https://herdr.dev) デスクトップアプリだ：ウィンドウを閉じてもそのコアで動き続けるターミナルとコーディングエージェントのスペース、タブ、ペインだ。パッケージではなく Herdr 独自のインストーラーから提供されるため、`~/.local/share/herdr-app` に置かれ、まだなければ `~/.local/bin/herdr-core` にコアも一緒に持ち込み、両方とも自己更新する。Omarchy が `Super + Ctrl + Return` で提供する `herdr` コマンドの横にあり、それを置き換えるのではなく、そのコマンドの直接キーを取得する：`Alt + Return` と `Alt + Shift + Return` でペインを下または右に分割し、`Alt + Escape` で閉じ、`Ctrl + Alt + Arrow` でペイン間を移動し、`Alt + 1..9` と `Alt + Left/Right` でタブを選び、`Alt + Up/Down` でスペース間を移動する。`Ctrl + 1..9` でスペースを選び、`Alt + Shift + Up/Down` でエージェントを順に進める。`Ctrl + Space` プレフィックスキーはターミナル専用のままとなる。アプリはシーケンスのために素の Ctrl キーを保持できないからだ。Omarchy はこれらを `~/.config/herdr-app/keys.json` に書き込み、`omarchy-refresh-herdr-app` で戻す。インストールすると Herdr の Omarchy テーマが選ばれ、以降は Omarchy テーマに追随する。Herdr はライトモード用に 1 つ、ダークモード用に 1 つのテーマを保持するため、ダークな Omarchy テーマとライトな Omarchy テーマを切り替えた後は、もう一方のモード用に Herdr のテーマピッカーで Omarchy をもう一度選ぶこと。

T3 Code はパッケージではなく `~/.local/share/t3code` にある公式 AppImage リリースから動作するため、自己更新する。インストール時に Stable チャネルで始めるか Nightly チャネルで始めるか尋ねる；後で T3 Code の設定で切り替えられる。スレッドと設定は `~/.t3` にあり、_Remove > AI_ で T3 Code を削除すると一緒に削除される。

### ローカルモデル

自分のマシンでオープンモデルを実行してコーディングエージェントに使う。プロンプトとコードはマシン上に留まる；モデルに送ったものが外に出ることはない。まずは次から始める：

```bash
omarchy models use best text
```

それにより、このマシンに最適なテキストモデル、そのエージェントが使う種類のものがセットアップされる。画像、動画、音楽モデルにもそれぞれ最適なものがある：`omarchy models use best image`、`video`、または `music` だ。`omarchy models use best` を実行すると、このマシンに対する各種の推奨が表示される。

または、トップバーのエージェントアイコンの隣にあるキラキラアイコンから、または Super + Ctrl + Alt + X でローカルモデルパネルを開き、+ を選ぶ。このマシンに適合するモデルがある場合にアイコンが表示される。モデルを実行する Podman は Omarchy に付属し、NVIDIA マシンでは GPU を提供する NVIDIA のコンテナツールキットも付属する；どちらかが欠けていれば、最初のセットアップでインストールされる。次に Omarchy がこのマシンに推奨されるモデルを選び、ダウンロードし、起動する。数十 GB のダウンロードと、モデル実行中はマシンのメモリの大半が使われることを想定すること：Flash Next は完全な 256K コンテキストで約 100 GiB を使う。必要なメモリを他のモデルが占有している場合、停止した状態でセットアップされ、1 つを停止すれば起動できるようになる。モデルはログアウト時に停止する；他の用途でメモリが必要なときは自分で停止すること。

`omarchy models list` は選択肢を表示し、一部が適合しない理由を説明する。別のものをセットアップするには `omarchy models use <recipe>` を実行する。現在、128 GB の Strix Halo マシン向けに `qwen3.8-flash-next-gufo` と `qwen3.8-27b-gufo` が利用できる；27B は約 40 GiB を使うため、他の作業の余地が残る。Intel の Arc B390 を搭載した 64 GB ラップトップでは、`qwen3.6-35b-a3b-llamacpp` が約 30 GiB で動作する。新しいレシピと推奨は `omarchy update` でパッケージ経由で届く。

セットアップしたモデルごとにローカルモデルパネルに専用の行ができる：再生で起動し、一時停止で停止してメモリを解放し、ターミナルボタンでそのモデルでエージェントを開く。上部にはバーがあり、マシンのメモリが Omarchy 自体（システムとアプリ）、実行中の各モデル、空き容量にどう分割されているかを表示する。停止中のモデルにポイントするとバーに適合するか、どれだけ不足しているかを表示する。メモリに収まれば複数を同時に実行できる；収まらない場合は、Omarchy がどの実行中モデルを停止すべきか伝える。ロゴでドラッグして行を並び替え、選択した行で Delete を押すとモデルとそのダウンロードを削除する。

セットアップしたコーディングモデルごとに、アプリランチャーにモデルの名前とメーカーのロゴで専用の項目も追加される。Claude、Codex、Grok にサインインすると追加されるのと同じだ。それを開くとそのモデルでエージェントが開き、モデルが実行中でなければ先に起動する：ターミナルに読み込みが表示され、準備ができたらエージェントに引き継ぐ。モデルを削除するとその項目も削除される。

すべてのモデルがコーディング用ではない。画像、動画、音楽モデルは代わりに Fantasi で開く。Fantasi はこのマシンで実行するモデルで絵、動画、音楽を作る Omarchy のアプリで、そこで選ぶか、ローカルモデルパネルの行から選ぶ。

モデルはセットアップされたとおりに動き続けるため、Omarchy の更新でエージェントの下で再起動することは決してない。セットアップしたモデルに対して新しいランタイムや新しいウェイトが Omarchy にある場合、その行に更新ボタンが表示される：押すとモデルはバックグラウンドで再セットアップされ、変更された分だけダウンロードし、新しいバージョンで再起動する。停止していたモデルは停止したままだ。`omarchy models update` はターミナルからすべてのモデルに対して同じことをする。

コマンドラインからは、`omarchy models start <recipe>` と `omarchy models stop <recipe>` でも同じことができ、`omarchy models status` はすべてのモデルを表示し、`omarchy agent --local` はデフォルトのエージェントが何であれ、最後に起動したモデルを pi で開く。OpenCode と Qwen Code もローカルモデルを使える：代わりに `omarchy models harness opencode` または `omarchy models harness qwen` でそこで開き、`omarchy models harness pi` で戻る。pi はセットアップしたすべてのモデルと、ペアリングしたマシンのモデルも自身のモデルピッカーに一覧表示するので、素の `pi` でもそれらにアクセスできる。OpenAI 互換のクライアントならどれでも接続できる：`status` は各モデルのアドレスを表示し（最初は `http://127.0.0.1:11435/v1`）、レシピ名がモデル名となり、キーは `~/.config/omarchy/agent-local/key` にある。

`omarchy models remove <recipe>` はモデルと、他のモデルが使わないダウンロードを削除する。

サードパーティ製ランタイムにはその発行元のラベルが付く。Omarchy はすべてのモデルをネットワークアクセスなしで実行する。

### ローカル LLM

Omarchy はローカル LLM モデルを実行する方法として LM Studio と Ollama の 2 つを推奨する。LM Studio はオープンウェイトモデルを見つけ、インストールし、実行するための GUI インターフェイスを提供する。簡単に始められる優れた方法だ。Ollama は同様のことを行う CLI を提供する。しかしローカルモデルが初めてなら、私なら LM Studio から始める。どちらも Omarchy Menu の _Install > AI_ でインストールできる。

### Omarchy スキル

エージェントスキルは AI が特定のツールを特定の方法で使うのを助け、Omarchy には 7 つ同梱されている。omarchy スキルは Hyprland 設定の微調整やバーの調整など、システムのカスタマイズをカバーする。omarchy-make-theme、omarchy-make-plugin、omarchy-make-app、omarchy-make-game は新しいものを作ることをカバーし、omarchy-contribute はバグ報告や修正の上流への送信をカバーし、omarchy-diagnose-crash はクラッシュのコアダンプを調査する。これらは Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` と各 `~/.hermes/profiles/*/skills`）、汎用の `~/.agents/skills` の場所にあるスキルディレクトリにシンボリックリンクされるため、ほとんどのハーネスが自動で拾い上げる。同名の自分のスキルフォルダが優先される。

ただし、これらのスキルは実験的なものとして扱うべきだ。モデルによって効果は異なる。まずプランモードで実行し、エージェントが何を変更したいか把握するのが最善だ。そして、変更をロールバックしたり、エージェントがすべてをめちゃくちゃにした場合に `omarchy reinstall configs` を実行したりする準備をしておくこと。
