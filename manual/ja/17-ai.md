### エージェントのインストールと更新

Hermes と OpenClaw を除き、これらのエージェントは mise の遅延インストールを使用します。初回起動時に CLI がインストールされ、それ以降の起動ではそれが再利用されます。mise はまた、インストール済みのエージェントについて、起動直前またはシェルプロンプトでバックグラウンドで、最大で 4 時間に 1 回だけ新リリースをチェックします。その更新が失敗したり、オフラインだったりした場合、インストール済みのバージョンが動作します。`omarchy update` は、インストール済みのエージェントを Omarchy の他の部分と一緒に更新し、`mup` は mise 管理ツールのみを更新します。

`claude update`、`codex update`、またはアプリ内の更新ボタンなど、エージェント独自のアップデーターは、mise 管理下のインストールを更新しません。`codex update` は失敗し、`claude update` は成功したと報告しながら、mise が追跡しない別コピーをインストールすることがあります。エージェント本来のインストーラーとアップデーターを使いたい場合は、それを `disable_tools` に追加してください。[プリインストールされた CLI ツール](18-development-tools.md#preinstalled-cli-tools) を参照してください。

必要になる前に、設定済みのすべての遅延ツールをインストールするには、`mise install --include-lazy` を実行してください。これには Omarchy の他のデフォルト CLI ツールもエージェントも含まれます。単一ツールのインストールや、独自のインストールを使う方法については、[プリインストールされた CLI ツール](18-development-tools.md#preinstalled-cli-tools) を参照してください。

`grok` は、`claude` や `codex` と同じように、mise のファーストパーティ `grok` パッケージ経由でインストールされます。`grok` を実行するか、エージェントパネルでスターを付けてください。x.ai の `curl | bash` インストーラーは避けてください。その方法では `~/.grok/bin` に 2 つ目のコピーが置かれ、`PATH` の先頭にそれが追加され、Omarchy のラッパーが上書きされます。

`dsh` は `127.0.0.1:3080` でブラウザ UI を開き、起動ディレクトリをデフォルトのワークスペースとします。そのブラウザ UI は開始プロンプトを受け取らないので、`omarchy agent prompt` は、貼り付けられるようプロンプトをクリップボードに入れた状態でそれを開きます。Omarchy は DeepSeek の承認なしプリセットでそれを起動します。DeepSeek Harness は、公式モデル API を使用するとセッションログを DeepSeek にアップロードします。そのブラウザ UI の _Settings > General > Upload Session Log_ でそれをオフにしてください。送信したフィードバックもセッションと一緒にアップロードされます。ただし、`DSH_TELEMETRY_MODE=DISABLED` で起動した場合は除きます。

### デフォルトのエージェント

エージェントパネルでエージェントの横にあるスターでデフォルトのエージェントを選んでください。デフォルトのものではスターが埋まっています。または `omarchy default agent <name>` でも選べます。これは、そこに項目がないハーネスも受け付けます。そのエージェントがまだインストールされていない場合、選ぶとまずインストールされ、Agent の横にアプリランチャー内に独自のランチャーも追加されます。新規インストールした Omarchy では、1 回限りの通知でセットアップを勧めてきます。その通知でエージェントパネルが開きます。

Claude を選ぶと、Chromium、Chrome、Brave、Brave Origin、Edge 用のブラウザ拡張機能のセットアップも試みます。この拡張機能のセットアップは全ユーザーに適用され、システムパスワードを求められることがあります。拡張機能のインストールをキャンセルしたり失敗したりしても、Claude は選択され、起動します。ブラウザを再起動し、プロンプトが表示されたら拡張機能を有効にし、Claude にサインインして接続を完了してください。Claude で `/chrome` を実行して接続を確認してください。Firefox と Zen はこの拡張機能をサポートしていません。このセットアップが追加される前に Claude がすでにデフォルトだった場合は、もう一度選択して拡張機能をインストールしてください。

選択が終わると、`Super + Shift + Ctrl + A` で専用のターミナルウィンドウでデフォルトのエージェントが起動します（まだ選んでいない場合はピッカーが表示されます）。`omarchy agent prompt "Review this project"` で、タスクを直接渡して起動することもできます。Freebuff と DeepSeek Harness は開始プロンプトを受け取らないので、代わりに貼り付けられるようプロンプトをクリップボードに入れた状態で開きます。このように起動したエージェントは、それぞれの確認で止まらないモードで無人で動作します。実際にいろいろ実行する心構えをしておいてください！MiniMax Code には対話セッション向けのそのようなモードがないので、通常どおり権限を求めてきます。また、エージェントはホームディレクトリに対する信頼を記憶することを拒否するので、`$HOME` からの起動は代わりに `~/Work` で開始します。

ターミナル用ショートカットもあります。`a` は現在のターミナルでインラインにデフォルトのエージェントを実行し、`c`、`cx`、`cy` は OpenCode、Claude Code、Codex を直接起動します（こちらも自動承認モードです）。テーマの変更もエージェントに同期されます。Claude Code、Pi、OpenCode、Hermes（Omarchy がインストールした後は）は、Omarchy のテーマを切り替えるとそれに追随します。

### エージェントへの指示

すべてのエージェント向けの個人ルールは、`~/.agents/skills` の共有スキルと並んで `~/.agents/AGENTS.md` に入れます。エージェントパネルの + の横にあるドキュメントアイコンで開くか、`omarchy agent instructions --edit` で開いてください。後者は、独自のグローバルファイルを保持する各ハーネスにもそれをリンクします。`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`~/.pi/agent/AGENTS.md`、`~/.config/opencode/AGENTS.md`、Copilot の `~/.copilot/copilot-instructions.md` などです。Crush と Amp は `~/.config/AGENTS.md` リンクを読み、omp、Kimi、DeepSeek Harness は `~/.agents/AGENTS.md` を直接読みます。デフォルトのエージェントを選ぶことでもリンクされます。すでに持っていた指示ファイルは、共有ファイルがまだなかった場合はそれが共有ファイルになり、そうでない場合はリンクの横に `.bak` として保持されます。別のエージェントをインストールした後で再リンクするには、`omarchy agent instructions` を実行してください。

### エージェントパネル

トップバーにはエージェントアイコンがあります。エージェントをセットアップする前、そのパネルでは 3 つの開始方法が提示されます。Claude、Codex、Grok、Gemini、Muse、Cursor、Copilot のサブスクリプションにサインインするか、More の下の OpenCode Go、MiniMax、Synthetic、Z.ai のコーディングプランにサインインすること。Fireworks、OpenCode Zen and Go、OpenRouter、または More の下の DeepSeek や OpenCode がサインインするその他のプロバイダーで従量課金すること。これらはすべて OpenCode で実行されます。あるいは、このコンピューターに合うモデルがある場合に、そのコンピューターに最適なモデルを実行することです。最初に終えたものがデフォルトのエージェントになり、パネルの + では後から同じ 3 つが提示されます。その後は、パネルですべてのサブスクリプションが 1 ページに表示されます。各エージェントとアカウント、そのプラン、5 時間セッションと週間制限それぞれのメーターとリセットまでの時間（ホバーで正確な割合が表示されます）、またはプリペイド残高が、それらすべてにわたって使用したものをローテーション表示する行の下に表示されます。たとえば今週のトークン数や最も使用したモデルなどです。_Make something cool_ の下では、新しいテーマ、プラグイン、アプリ、ゲームのためのスタータープロンプトが提示され、タスクがデフォルトのエージェントに渡されます。アプリは Omarchy 自身の Hype、Monologue、Omacut と同じように、C++ と Qt Quick で、omarchy-make-app エージェントスキルに従って構築され、必要なコンパイラと Qt の部品はインストール済みで提供されます。ゲームは `~/Games/vibes` の単一の three.js ページで、omarchy-make-game エージェントスキルに従い、すべて現在のテーマの 1 つの Game Vibes ランチャーから開きます。それらは Web から three.js を読み込むので、開始には接続が必要です。Claude Code、Codex、Grok、Kimi、Cursor とその Grok Bot の枠、GitHub Copilot、Muse、Gemini（Antigravity 経由）、Devin は、制限付きでそのまま利用できます。Kimchi はそのプラン、プリペイドクレジット、支出予算付きで利用でき、Hermes、Mistral Vibe、Qwen Code は一度使うとセッションとトークンが表示されます。pi、omp、opencode 経由で使用するプロバイダーのプランとキーも表示されます。OpenCode Zen and Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan、Synthetic は制限付きで、OpenRouter と DeepSeek はプリペイド残高付きで、Fireworks は過去 30 日間の支出付きで表示されます。自分のハードウェアで実行するコーディングモデルは独自の行を持ち、そのトークンも合計にカウントされます。[ローカルモデル](#local-models) で説明しているとおりです。すべてのエージェントは、請求元のもとで、どれだけのハーネス経由で駆動しても 1 回だけ数えられます。

バーのアイコンを左クリックするか `Super + Ctrl + X` を押すとパネルが開き、右クリックでデフォルトのエージェントが起動し、中央クリックで更新されます。その背後にある使用記録は、`omarchy agent usage update` によって 15 分ごとに再生成され、パネルは同期フォルダ経由で他のマシンの使用状況をマージすることさえできます。全設定については `$OMARCHY_PATH/shell/plugins/agents/` の README を参照してください。

### 複数のサブスクリプション

個人の Max と仕事用など、Claude、Codex、Grok のプランを複数支払っている場合、Omarchy はそれらすべてをサインインしたままにし、それらの間を移動できます。エージェントパネルで + を使ってサブスクリプションを追加してください。その場で手順を案内します。または `omarchy agent account add claude Work`（あるいは `codex`、`grok`）でも追加できます。同じ + とコマンドで、Gemini（`gemini`）と OpenCode（`opencode`）にサインインし、Fireworks（`fireworks`）または OpenRouter（`openrouter`）の API キーを OpenCode に保存できます。このコマンドでは Copilot（`copilot`）、Cursor（`cursor`）、Muse（`muse`）にもサインインできます。これらはそれぞれ 1 つのサインインのみを保持します。CLI がなければインストールします。プロバイダーの最初のアカウントは、CLI がいつも確認する場所そのままで、通常のブラウザ経由でサインインします。それ以降のすべてのアカウントはプライベートウィンドウ経由でサインインします。これにより、ブラウザで既にサインインしているアカウントが誤って選択されることがありません。追加するアカウントとしてそこでサインインし、既に開いていたプライベートウィンドウがあれば先に閉じてください。CLI から決してログアウトしてこれをしないでください。ログアウトすると保存されたサインインが取り消され、そのアカウントを再度追加しなければならなくなります。

サブスクリプションのログインを SSH 経由で別の Omarchy マシンにコピーするには、`omarchy agent account copy user@laptop` を実行してください。宛先に受信側がインストールされていない場合、送信側が一時的な受信側を提供するので、古い Omarchy マシンでも更新なしでアカウントを受け取れます。インストール済みの受信側が優先されます。これは Claude、Codex、Grok のすべてのサブスクリプションをコピーします。プロバイダー名を追加して選択できます。たとえば `omarchy agent account copy laptop claude` のようにします。アカウント名とコマンド ID は、宛先に既に存在するアカウントを含め、送信元と一致します。無関係な宛先アカウントは名前が衝突した場合に数字のサフィックスを受け取り、設定、スキル、プラグイン、会話履歴は各マシンにローカルなまま残ります。

宛先の既存の認証情報は保持されます。送信元アカウントが既にそこでサインインしている場合、その認証情報を置き換えることなく名前が同期されます。その他のアカウントはそれと並んで追加されます。一致するアカウントの保存済み認証情報を置き換えるには、宛先でそのアカウントのセッションを終了した後で、`omarchy agent account copy --replace laptop claude` を使用してください。新規の宛先は送信元のアクティブなアカウントと切り替え設定も引き継ぎます。既に確立した宛先は独自のものを保持します。

認証情報は SSH 経由で移動し、宛先のプライベートファイルに保存されるので、信頼するマシンにのみコピーしてください。これは 1 回限りのコピーであり、継続的な同期ではありません。Codex のリフレッシュトークンは別のマシンによってローテーションされることがあり、コピーしたログインが更新を必要とする状態になることがあります。複数のマシンで同時に使用する場合は、個別にサインインするのが最も確実な選択です。[Codex のアカウント認証ガイダンス](https://developers.openai.com/codex/auth/ci-cd-auth) を参照してください。

プロバイダーごとにアクティブなのは 1 アカウントで、すべての新しいセッションはそれで開始します。`cx`、`cy`、素の `claude`、`codex`、`grok`、`omarchy agent` 経由で起動するもの、`PATH` 上で CLI を見つけるスクリプトやエディターなどです。`omarchy agent account use work` で切り替え（`omarchy agent account use main` で戻します）、またはパネルでアカウントの番号を押してから `Enter` を押す（あるいはそのスターをクリックする）ことで切り替えます。実行中の Claude セッションも、次のメッセージから切り替わります。すべての Claude セッションは `~/.claude` で実行され、そこには常にアクティブなアカウントのサインインが保持されます。古い Omarchy によってアカウント独自のフォルダで開始された Claude セッションは、終了するまでそのサインインを保持します。そのため、切り替え時にそれらのセッション名が示され、それらがなくなったら自動的に完了します。実行中の Codex と Grok のセッションは開始時のアカウントのままです。会話履歴、設定、スキル、プラグインはアカウント間で共有されるので、同じフォルダで `claude --continue` すると、新しいアカウントで中断したところから再開できます。

アカウントが複数ある場合、パネルでは各アカウントの制限が並んで表示され、使用中のものには埋まったスターが付きます。アクティブなアカウントが制限の 95% を超えると Omarchy が通知し、その通知をクリックすると最も余裕のあるアカウントに切り替わります。自動で切り替わることは決してありません。しきい値は `omarchy agent account threshold 90` で変更してください。すべてのアカウントがしきい値を超えている場合、そのことが 1 回通知され、最初に空くアカウントも一緒に示されます。アクティブなアカウントがしきい値の 15 ポイント以内（デフォルトでは 80%）にある間、その制限は 15 分ごとではなく 3 分ごとにチェックされます。

`omarchy agent account list` はすべてのアカウントと最新の制限を表示し、`omarchy agent account remove work` は 1 つを忘れ、`omarchy agent account rename primary Hey` は 1 つの名前を変更します（またはパネルでアカウント名をクリックします）。これらのコマンドはデフォルトのエージェントのアカウントに対して動作します。別のプロバイダーにアクセスするには、`omarchy agent account use codex side` のように先にプロバイダー名を指定してください。`~/.claude` や `~/.codex` に既にあったログインが _Main_ アカウントです。Codex のものはその場に残ります。Claude のものは、別のアカウントがアクティブな間は独自のフォルダで待機します。約 8 時間以上使用されていないアカウントでは _Sign-in required_ が表示されることがあります。クリックしてパネルですぐにそのアカウントで再度サインインするか、そのアカウントに切り替えてセッションを開始してください。そうすればサインインは自動的に更新されます。`claude mcp add` で追加した MCP サーバーは、すべての Claude が `~/.claude` で実行されるため、すべての Claude アカウントで使用できます。Codex と Grok については、アカウント追加時に持っていたサーバーはそのアカウントに引き継がれますが、後からのものは追加したアカウントでのみ使用できます。Claude Desktop は独自のサインインを保持し、CLI バイナリへの絶対パスで設定された Codex や Grok のツールは切り替えに追随しません。明示的な `CLAUDE_CONFIG_DIR`、`CODEX_HOME`、または `GROK_HOME` は選択したアカウントより優先されます。

### クラッシュ診断

Omarchy はプロセスのクラッシュを systemd-coredump で監視します。デフォルトのエージェントを選んだ後は、コアダンプする自分のプログラムがあると「Process crashed」通知が表示されます。それをクリックすると、Omarchy の omarchy-diagnose-crash スキルとともに、そのクラッシュがデフォルトのエージェントに渡されます。そのスキルは、コアダンプから事実を確立し、そのクラッシュをアップストリームに報告する価値があるかどうかを判断する手順をエージェントに案内します。`coredumpctl list` の任意の PID に対して `omarchy agent crash <pid>` で手動で実行することもできます。

監視はデフォルトでオンです。_Trigger > Toggle > Crash Capture Off_ の下でオフにすると（または `omarchy toggle crash-capture` で）、通知が止まります。`omarchy agent crash <pid>` は手動では引き続き使用できます。

クラッシュはプログラムごとに 1 つずつ黙らせることもできます。これは診断の最後に提示されるものです。`omarchy crash mute hyprland` はそのプログラムのみ通知を止め、`omarchy crash mute hyprland off` は復活させ、`omarchy crash mute` 単体では何をミュートしたか一覧表示します。バイナリのパスも名前と同じくらい気軽に使えるので、`omarchy crash mute /usr/bin/hyprland` でも同じです。空白を含む名前は、`omarchy crash mute 'Some App'` のように引用してください。その他のものはすべて引き続き通知され、ミュートしたプログラムも引き続きクラッシュします。これはリマインダーを隠すだけで、何も修正しません。

### デスクトップアプリ

_Install > AI_ メニューには、Amp Desktop、Antigravity Desktop、ChatGPT デスクトップアプリ、Claude デスクトップアプリ（Chat、Cowork、Claude Code タブ付きの Anthropic の Linux ベータ）、xAI のモデルとチャットするための Grok Bot、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexity デスクトップアプリ、T3 Code といった、グラフィカルな AI アプリもいくつか含まれています。Grok Bot はデスクトップチャットアプリです。コーディングエージェントは `grok` コマンドです。

Hermes Desktop は知っておくべきものです。1 台のマシンには 1 つの Hermes があり、それはこのアプリのものだからです。Hermes はアプリ経由でしかインストールされず、デフォルトのエージェントが実行する `hermes` コマンドはアプリのものです。Hermes をデフォルトのエージェントとして選ぶと、_Install > AI_ の項目と同じものがインストールされます。パッケージと、Hermes 自身のインストーラーによってセットアップされる `~/.hermes` の Hermes ランタイムです。初回は数分かかります。そのランタイムは、ターミナルの `hermes` コマンド、デフォルトのエージェント、アプリがすべて使う唯一の Hermes で、Omarchy のリリースを待つのではなく `hermes update` で自己更新します。インストールすると Hermes に Omarchy テーマが `omarchy` という名前のスキンとして渡され、すべての Hermes の画面はテーマ切り替えに追随します。追随させたくなければ、Hermes の Appearance 設定の下で別のものを選ぶか `/skin` で選んでください。Omarchy はその選択に干渉しません。_Remove > AI_ の下でアプリを削除すると、まず Hermes（ゲートウェイを含む）が閉じられ、そのランタイムも一緒に削除されますが、チャット、メモリー、Hermes が自身のために書いたスキルは、指示しない限り保持されます。削除時に、そのデータと接続設定も削除するかどうかを尋ね、デフォルトはいいえです。

OpenClaw のデスクトップ体験は Control UI です。これは独自のローカルゲートウェイをバックエンドとしてウェブアプリとして開きます。OpenClaw は `~/.openclaw` にあり、自己更新します。Control UI の「Update Gateway」ボタンを使うか `openclaw update` を実行すると、ゲートウェイは新しいバージョンで再起動します。Omarchy が選ぶのは、新規インストールが開始するリリースだけです。OpenClaw をデフォルトのエージェントにすることもできます。`omarchy default agent openclaw` で選ぶと、`~/.openclaw` に同じコピーがセットアップされ、エージェントはそのゲートウェイに接続された OpenClaw のターミナル UI を開きます。_Remove > AI_ の下で OpenClaw を削除すると、ゲートウェイサービスとアプリも一緒に削除され、その後で `~/.openclaw` も削除するかどうかを尋ねます。そこにはチャットと認証情報が OpenClaw 自体やダウンロードしたプラグインランタイムと並んで保存されているためです。デフォルトでは保持され、OpenClaw を再インストールするとそれを再び引き継ぎます。

Herdr Desktop は [Herdr](https://herdr.dev) のデスクトップアプリです。ターミナルとコーディングエージェントのスペース、タブ、ペインがあり、ウィンドウを閉じてもそのコアで実行し続けます。これはパッケージではなく Herdr 自身のインストーラーから提供されるので、`~/.local/share/herdr-app` にあり、まだ持っていない場合は `~/.local/bin/herdr-core` にそのコアも一緒に導入され、両方とも自己更新します。これは Omarchy が `Super + Ctrl + Return` に提供する `herdr` コマンドの代わりではなく、その横に位置し、そのコマンドの直接キーを取得します。`Alt + Return` と `Alt + Shift + Return` はペインを下または右に分割し、`Alt + Escape` はそれを閉じ、`Ctrl + Alt + Arrow` はペイン間を移動し、`Alt + 1..9` と `Alt + Left/Right` はタブを選択し、`Alt + Up/Down` はスペース間を移動します。`Ctrl + 1..9` はスペースを選択し、`Alt + Shift + Up/Down` はエージェント間を順に移動します。`Ctrl + Space` プレフィックスキーはターミナル専用のままです。アプリは単純な Ctrl キーをシーケンスとして保持できないためです。Omarchy はこれらを `~/.config/herdr-app/keys.json` に書き込み、`omarchy-refresh-herdr-app` で元に戻します。インストールすると Herdr の Omarchy テーマが選ばれ、それ以降は Omarchy テーマに追随します。Herdr はライトモード用とダークモード用に 1 つずつテーマを保持するので、暗い Omarchy テーマと明るい Omarchy テーマの間を切り替えた後は、もう一方のモードのために Herdr のテーマピッカーでもう一度 Omarchy を選択してください。

T3 Code は、パッケージではなく `~/.local/share/t3code` の公式 AppImage リリースから実行され、自己更新します。インストール時に Stable チャネルの開始か Nightly チャネルの開始かを尋ねます。後で T3 Code の設定で切り替えてください。スレッドと設定は `~/.t3` にあります。_Remove > AI_ の下で T3 Code を削除すると、それらも一緒に削除されます。

### ローカルモデル

コーディングエージェント向けに、自分のマシンでオープンモデルを実行してください。プロンプトとコードはそのマシン上に留まります。モデルに送信されるものはマシンから出ていきません。次から始めてください。

```bash
omarchy models use best text
```

これで、このマシンに最適なテキストモデルがセットアップされます。エージェントが使うタイプのモデルです。画像、動画、音楽モデルにもそれぞれ最適なものがあります。`omarchy models use best image`、`video`、または `music` です。`omarchy models use best` を実行すると、各種類についてこのマシンでの選択が表示されます。

あるいは、エージェントパネルで + を選んでください。_Use a local model_ の下に、このマシンに合うすべてのコーディングモデルが列挙され、推奨されるものが最初に表示されます。モデルを実行する Podman は Omarchy に付属し、NVIDIA マシンでは NVIDIA のコンテナツールキットも付属します。これがモデルに GPU を与えます。どちらかが不足している場合、初回のセットアップでインストールされます。次に Omarchy がこのマシン向けに推奨されるモデルを選び、ダウンロードして起動します。モデル実行中は、数十 GB のダウンロードと、マシンのメモリーの大半が使用されることを覚悟してください。Flash Next は、フル 256K コンテキストで約 100 GiB を使用します。必要なメモリーを他のモデルが占有している 경우、1 つ停止したら開始できるよう、停止状態でセットアップされます。モデルはログアウト時に停止します。他のことにメモリーが必要なときは自分で停止してください。

`omarchy models list` は選択肢を表示し、合わないものがある理由を説明します。別のものをセットアップするには、`omarchy models use <recipe>` を実行してください。現在、128 GB Strix Halo マシン向けに `qwen3.8-flash-next-gufo` と `qwen3.8-27b-gufo` が利用可能です。27B は約 40 GiB を使用するので、他の作業の余地が残ります。Intel の Arc B390 を搭載した 64 GB のノート PC では、`qwen3.6-35b-a3b-llamacpp` が約 30 GiB で動作します。新しいレシピと推奨はパッケージ経由で `omarchy update` と一緒に届きます。

追加したコーディングモデルは、サブスクリプションの横にエージェントパネルで独自の行を持ちます。再生で開始、停止で停止してメモリーを解放、Tailscale マークで実行中に tailnet 上の他のマシンと共有、ターミナルボタンでそのモデルでエージェントを開きます。その行には、進行に応じてダウンロード、ロード、停止が表示され、開始に十分な空きメモリーがない場合にはそう表示され、エラーで停止したときはログへのリンクが表示されます。メモリーに一緒に収まる場合は複数を同時に実行できます。選択した行で Delete を押すと、ダウンロードを含め、そのモデルがこのマシンから削除されます。+ で再びセットアップできます。ターミナルからセットアップしたコーディングモデルは、あなたが追加するまで + の下で待機します。ペアリングしたマシン（`omarchy models pair <host>`）が実行するモデルも同様です。

セットアップしたすべてのコーディングモデルは、モデルの名前で、制作者のロゴとともに、Claude、Codex、Grok にサインインすると追加されるのと同じように、アプリランチャーにも独自の項目を持ちます。それはそのモデルでエージェントを開き、実行中でなければまずモデルを開始します。ターミナルにロードが表示され、起動したらエージェントに引き継がれます。モデルを削除するとその項目も削除されます。

すべてのモデルがコーディング用ではありません。画像、動画、音楽のモデルは、代わりに Fantasi で開きます。これはこのマシンで実行されるモデルで画像、動画、音楽を作る Omarchy のアプリであり、そこで、または `omarchy models` で管理されます。

モデルはセットアップされたとおりに正確に実行し続けるので、Omarchy の更新で、エージェントの下にあるモデルが再起動されることは決してありません。Omarchy に、セットアップ済みモデル向けの新しいランタイムや新しいウェイトがある場合、その行に更新ボタンが表示されます。それを押すと、変更されたものだけをダウンロードしてモデルがバックグラウンドで再びセットアップされ、新しいバージョンで再起動します。停止していたモデルは停止したままです。`omarchy models update` はターミナルからすべてのモデルに対して同じことをします。

コマンドラインからは、`omarchy models start <recipe>` と `omarchy models stop <recipe>` が同じことをし、`omarchy models status` はすべてのモデルを表示し、`omarchy agent --local-model <recipe>` は、デフォルトのエージェントが何であれ、pi でそのモデルを開きます。ローカルモデルをエージェントホットキー、Quake コンソール、_Make something_ が開くものにするには、`omarchy default agent local` を実行するか、エージェントパネルで実行中のモデルにスターを付けてください。pi はまた、セットアップしたすべてのモデルと、ペアリングしたマシン上のモデルを、独自のモデルピッカーに列挙します。そのため、素の `pi` でもそれらにアクセスできます。OpenAI 互換のクライアントも接続できます。`status` は各モデルのアドレスを表示し（最初は `http://127.0.0.1:11435/v1`）、レシピ名がモデルで、キーは `~/.config/omarchy/agent-local/key` にあります。

`omarchy models remove <recipe>` はモデルと、他のモデルが使用しないダウンロードを削除します。

サードパーティのランタイムには、その発行元のラベルが付けられます。Omarchy はすべてのモデルをネットワークアクセスなしで実行します。

### ローカル LLM

Omarchy はローカル LLM モデルを実行する方法として、LM Studio と Ollama の 2 つを推奨しています。LM Studio は、オープンウェイトモデルを見つけ、インストールし、実行するための GUI インターフェイスを提供します。簡単にはじめるのに最適な方法です。Ollama は CLI で同様のことを可能にします。しかし、ローカルモデルが初めてなら、私なら LM Studio から始めます。どちらも Omarchy メニューの _Install > AI_ の下でインストールできます。

### Omarchy スキル

エージェントスキルは、AI が特定の方法で特定のツールを使うのを助け、Omarchy はそのうち 7 つを提供します。omarchy スキルは、Hyprland 設定を調整したりバーを調整したりするような、システムのカスタマイズをカバーします。omarchy-make-theme、omarchy-make-plugin、omarchy-make-app、omarchy-make-game は何か新しいものを作ることをカバーし、omarchy-contribute はバグを報告したり修正をアップストリームに送ったりすることをカバーし、omarchy-diagnose-crash はクラッシュのコアダンプに取り組みます。これらは Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` と各 `~/.hermes/profiles/*/skills`）、および汎用の `~/.agents/skills` の場所のスキルディレクトリにシンボリックリンクされるので、ほとんどのハーネスが自動的に取得します。同じ名前の独自のスキルフォルダが優先されます。

しかし、これらのスキルは実験的なものとして扱うべきです。モデルによって効果の出し方が異なります。まずプランモードで実行するのが最適です。そうすれば、エージェントが何を変更したいのか把握できます。そして、エージェントがすべてを台無しにした場合に備えて、変更をロールバックしたり、`omarchy reinstall configs` を実行したりする準備をしておいてください。
