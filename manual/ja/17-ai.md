### エージェントのインストールとアップデート

Hermesを除き、これらのエージェントはmiseのlazy installationを使います：初回起動時にCLIがインストールされ、以降の起動ではそれを再利用します。miseはまた、インストール済みエージェントに新しいリリースがないか、起動直前、またはシェルプロンプトでバックグラウンドで、最大で4時間に1回チェックします。そのアップデートが失敗したり、オフラインだったりした場合、インストール済みのバージョンが実行されます。`omarchy update`はOmarchyの他の部分と一緒にインストール済みエージェントをアップデートし、`mup`はmiseで管理されるツールだけをアップデートします。

`claude update`や`codex update`といったエージェント独自のアップデータや、アプリ内のアップデートボタンでは、miseで管理されるインストールはアップデートされません。`codex update`は失敗し、`claude update`は成功したと報告しながら、miseが追跡しない別コピーをインストールすることがあります。エージェントのネイティブなインストーラーとアップデータを使いたい場合は、それを`disable_tools`に追加してください；[プリインストールされたCLIツール](18-development-tools.md#preinstalled-cli-tools)を参照してください。

必要になる前に、設定されたすべてのlazyツールをインストールするには、`mise install --include-lazy`を実行してください。これにはエージェントだけでなく、Omarchyの他のデフォルトCLIツールも含まれます。単一ツールのインストールや独自のインストールを使う方法については、[プリインストールされたCLIツール](18-development-tools.md#preinstalled-cli-tools)を参照してください。

`grok`は、`claude`や`codex`と同じように、miseのファーストパーティ`grok`パッケージでインストールされます。`grok`を実行するか、_Agent > Harness_で選択してください。x.aiの`curl | bash`インストーラーは使わないでください。その方法では`~/.grok/bin`に2つ目のコピーが置かれ、`PATH`の先頭に追加され、Omarchyのラッパーが上書きされます。

`dsh`は`127.0.0.1:3080`でブラウザUIを開き、起動したディレクトリをデフォルトのワークスペースとします。そのブラウザUIは開始プロンプトを受け付けないため、`omarchy agent prompt`ではプロンプトをクリップボードに入れた状態で開きます。貼り付けてください。OmarchyはDeepSeekの承認なし権限プリセットでこれを起動します。DeepSeek Harnessは、公式モデルAPIを使うとセッションログをDeepSeekにアップロードします；ブラウザUIの_Settings > General > Upload Session Log_でオフにしてください。送信したフィードバックもセッションと一緒にアップロードされます。`DSH_TELEMETRY_MODE=DISABLED`で起動した場合を除きます。

### デフォルトのエージェント

デフォルトのエージェントは`omarchy default agent <name>`で、またはOmarchy Menu（`Super + Space`）の_Agent > Harness_で選択してください。エージェントがまだインストールされていない場合、選択すると先にインストールされます。新しいOmarchyでは、一度だけ表示される通知でこの選択をするよう促されます。

Claudeを選択すると、Chromium、Chrome、Brave、Brave Origin、Edge向けにそのブラウザ拡張機能のセットアップも試みます。拡張機能のセットアップはすべてのユーザーに適用され、システムパスワードを求められることがあります；キャンセルしたり、拡張機能のインストールに失敗したりしても、Claudeは選択され、起動します。ブラウザを再起動し、求められたら拡張機能を有効化し、Claudeにサインインして接続を完了してください。接続を確認するには、Claudeで`/chrome`を実行してください。FirefoxとZenはこの拡張機能に対応していません。このセットアップが追加される前にClaudeがすでにデフォルトだった場合は、もう一度選択して拡張機能をインストールしてください。

選択が終われば、`Super + Shift + Ctrl + A`でデフォルトのエージェントが専用のターミナルウィンドウで起動します（まだ選択していない場合はピッカーが表示されます）。`omarchy agent prompt "Review this project"`でタスクを直接渡して起動することもできます。FreebuffとDeepSeek Harnessは開始プロンプトを受け付けないため、代わりにプロンプトをクリップボードに入れた状態で開きます。貼り付けてください。この方法で起動したエージェントは、各々の「止まって聞かない」モードで無人で実行されます。実際にいろいろやる覚悟をしておいてください！MiniMax Codeにはインタラクティブセッション向けのそのようなモードがないため、通常通り権限を求めます。また、エージェントはホームディレクトリに対する信頼を覚えることを拒否するため、`$HOME`からの起動は代わりに`~/Work`で開始します。

ターミナルショートカットもあります：`a`は現在のターミナル内でデフォルトのエージェントをインラインで実行し、`c`、`cx`、`cy`はOpenCode、Claude Code、Codexを直接起動します（こちらも自動承認モードです）。テーマの変更もエージェントに同期されます：Claude Code、Pi、OpenCode、Hermes（Omarchyがインストールした後）は、Omarchyのテーマを切り替えると一緒に追従します。

### あなたのエージェント指示

すべてのエージェントに対する個人的なルールは、共有スキルがある`~/.agents/skills`の隣の`~/.agents/AGENTS.md`に入れます。_Agent > Instructions_で開いてください。ここでは、独自のグローバルファイルを持つ各ハーネスへもリンクされます：`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`~/.pi/agent/AGENTS.md`、`~/.config/opencode/AGENTS.md`、Copilotの`~/.copilot/copilot-instructions.md`などです。CrushとAmpは`~/.config/AGENTS.md`リンクを読み、omp、Kimi、DeepSeek Harnessは`~/.agents/AGENTS.md`を直接読みます。デフォルトのエージェントを選択すると、そこへもリンクされます。すでに持っていた指示ファイルは、共有ファイルがまだなかった場合はそれが共有ファイルになり、そうでない場合はリンクの隣に`.bak`として保持されます。別のエージェントをインストールした後でリンクし直すには、`omarchy agent instructions`を実行してください。

### エージェントパネル

トップバーにはエージェントアイコンがあります。エージェントをまだセットアップしていない場合、そのパネルがClaude、Codex、またはGrokへのサインインを案内し、最初のものがデフォルトのエージェントになります。その後は、パネルがすべてのサブスクリプションを1ページにまとめます：各エージェントとアカウントとそのプラン、5時間セッション制限と週間制限それぞれのメーターとリセットまでの時間（ホバーで正確なパーセンテージを表示）、またはプリペイド残高が、そのすべてを通して使った内容を切り替えて表示する行の下に表示されます。今週のトークン数や最も使ったモデルなどです。_Make something_の下では、新しいテーマ、プラグイン、またはアプリのスタータープロンプトが提供され、タスクをデフォルトのエージェントに渡します。アプリはOmarchy自身のHype、Monologue、Omacutと同じように、C++とQt Quickで、omarchy-appエージェントスキルに従って構築され、必要なコンパイラとQtの部品はインストール済みで付いてきます。Claude Code、Codex、Grok、Kimi、CursorとそのGrok Bot枠、GitHub Copilot、Muse、Antigravity、Kimchi、Devinは、制限付きでそのまま利用できます。Hermes、Mistral Vibe、Qwen Codeは、一度使うとセッションとトークンが表示されます。pi、omp、opencodeを通じて使うプロバイダーのプランやキーも表示されます：制限付きのOpenCode ZenとGo、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan、Synthetic；プリペイド残高付きのFireworks、OpenRouter、DeepSeek；そしてLocal modelsの下で、自分のハードウェアで実行するモデルです。すべてのエージェントは、課金する側の下で1回だけ数えられます。何つのハーネスを通して駆動しても同じです。

パネルはバーのアイコンを左クリックし、デフォルトのエージェントの起動は右クリックです。その背後にある使用記録は15分ごとに`omarchy agent usage-update`で再生成され、パネルは同期フォルダを介して他のマシンからの使用状況をマージすることもできます。設定の詳細については、`$OMARCHY_PATH/shell/plugins/agents/`にあるREADMEを参照してください。

### 複数のサブスクリプション

Claude、Codex、またはGrokのプランを複数支払っている場合 — たとえば個人のMaxと仕事用 — Omarchyはすべてをサインインしたままにして、その間を移動できます。サブスクリプションはエージェントパネルの+で追加でき、その場で案内されます。または`omarchy agent account add claude Work`（`codex`または`grok`でも）で追加できます。CLIがなければインストールされます。プロバイダーの最初のアカウントは、CLIが常に参照する場所である通常のブラウザを通じてサインインします。それ以降のすべてのアカウントはプライベートウィンドウを通じてサインインします。そのため、ブラウザですでにサインインしているアカウントが誤って選ばれることはありません；そこで追加するアカウントとしてサインインし、すでに開いているプライベートウィンドウは先に閉じてください。このためにCLIからログアウトしないでください：ログアウトすると保存されたサインインが取り消され、そのアカウントを再度追加しなければならなくなります。

サブスクリプションログインをSSH経由で別のOmarchyマシンにコピーするには、`omarchy agent account copy user@laptop`を実行してください。送信側は、送信先にレシーバーがインストールされていない場合に一時的なレシーバーを提供するため、古いOmarchyマシンでもアップデートなしでアカウントを受け取れます。インストール済みのレシーバーが優先されます。これによりすべてのClaude、Codex、Grokサブスクリプションがコピーされます；選択するには、`omarchy agent account copy laptop claude`のようにプロバイダー名を追加してください。アカウント名とコマンドIDは、送信先にすでに存在するアカウントを含め、送信元と一致します。無関係な送信先アカウントは名前が衝突すると数値サフィックスを受け取り、設定、スキル、プラグイン、会話履歴は各マシンにローカルなまま残ります。

送信先の既存の認証情報は保持されます。そこですでにサインインしている送信元アカウントは、認証情報を置き換えることなく名前が同期され；他のアカウントはその横に追加されます。一致するアカウントの保存済み認証情報を置き換えるには、送信先でそのアカウントのセッションを終了した後、`omarchy agent account copy --replace laptop claude`を使ってください。新しい送信先は送信元のアクティブなアカウントと切り替え設定も取得します；確立済みの送信先は自分のものを保持します。

認証情報はSSHを通じて移動し、送信先のプライベートファイルに保存されるため、信頼するマシンにだけコピーしてください。これは一度だけのコピーであり、継続的な同期ではありません。Codexのリフレッシュトークンは別のマシンでローテーションされることがあり、コピーしたログインは更新が必要な状態になることがあります；複数のマシンで同時に使うには、別々のサインインが最も確実な選択です。[Codexのアカウント認証ガイダンス](https://developers.openai.com/codex/auth/ci-cd-auth)を参照してください。

プロバイダーごとにアクティブなアカウントは1つで、すべての新しいセッションはそれとして開始します：`cx`、`cy`、素の`claude`、`codex`、または`grok`、`omarchy agent`を通じて起動されるものすべて、そして`PATH`上でCLIを見つけるスクリプトやエディタです。`omarchy agent account use work`で切り替え（`omarchy agent account use main`で戻す）、またはパネルでアカウントの番号を押してから`Enter`を押す（またはそのUseボタンをクリックする）ことで切り替えます。すでに実行中のセッションは、開始したアカウントのままです。会話履歴、設定、スキル、プラグインはアカウント間で共有されるため、同じフォルダでの`claude --continue`は新しいアカウントで中断したところから続けられます。

アカウントが複数ある場合、パネルは各アカウントの制限を横に並べて表示し、アクティブなものをマークします。デフォルトでは、アクティブなアカウントが制限の95%を超えるとOmarchyが通知し、通知をクリックすると最も余裕のあるアカウントに切り替えます。パネルでアカウントの行にホバーして、Useの横に表示されるAutoswitchをクリックする（または`m`を押す）か、`omarchy agent account mode auto`を実行すると、代わりに自動で切り替わります；オンの間はAutoswitchがUseの代わりになり、再度クリックすると通知に戻ります。`omarchy agent account mode auto 90`のように数値を追加してしきい値を変更してください。すべてのアカウントがしきい値を超えている場合、最も早く解放されるアカウントとともに一度だけ通知されます。アクティブなアカウントがしきい値から15ポイント以内（デフォルトでは80%）にある間、その制限は15分ごとではなく3分ごとにチェックされます。

`omarchy agent account list`はすべてのアカウントと最新の制限を表示し、`omarchy agent account remove work`は1つを忘れ、`omarchy agent account rename primary Hey`は1つの名前を変更します（またはパネルでアカウント名をクリックします）。これらのコマンドはデフォルトのエージェントのアカウントに対して動作します；他のプロバイダーにアクセスするには、`omarchy agent account use codex side`のように先に名前を指定してください。`~/.claude`または`~/.codex`にすでにあったログインは_Main_アカウントであり、その場所に残ります。約8時間以上使われていないアカウントは_Sign-in required_と表示されることがあります；クリックするとパネルですぐにそのアカウントに再度サインインでき、またはそのアカウントでセッションを開始すれば自動的にサインインが更新されます。アカウント追加時に持っていたMCPサーバーはそのアカウントにも付いてきますが、`claude mcp add`で後から追加したものは、追加したアカウントにしか届きません。Claude Desktopや、CLIバイナリへの絶対パスで設定されたツールは切り替えに追従しません。明示的な`CLAUDE_CONFIG_DIR`、`CODEX_HOME`、または`GROK_HOME`は、選択されたアカウントより優先されます。

### クラッシュ診断

Omarchyはプロセスのクラッシュについてsystemd-coredumpを監視します。何かがセグメンテーション違反を起こすと、「Process crashed」通知が届きます — クリックすると、クラッシュはOmarchyのdiagnose-crashスキルとともにデフォルトのエージェントに渡されます。このスキルは、コアダンプから事実を確立し、クラッシュが上流に報告する価値があるかどうかを決める手順をエージェントに案内します。`coredumpctl list`の任意のPIDに対して`omarchy agent crash <pid>`で手動で実行することもできます。

監視はデフォルトでオンです。_Trigger > Toggle > Crash Capture_で（または`omarchy toggle crash-capture`で）オフにすると通知は止まります；`omarchy agent crash <pid>`は手動では引き続き動作します。

クラッシュはプログラムごとに1つずつ黙らせることもできます。それが診断の最後に提案されることです。`omarchy crash mute hyprland`はそのプログラムだけの通知を止め、`omarchy crash mute hyprland off`で戻し、`omarchy crash mute`単独ではミュートしたものの一覧を表示します。名前と同様にバイナリのパスも受け付けるため、`omarchy crash mute /usr/bin/hyprland`でも同じことができます。スペースを含む名前は、`omarchy crash mute 'Some App'`のように引用してください。他のすべては引き続き通知され、ミュートされたプログラムも引き続きクラッシュします — これはリマインダーを隠すだけで、何も修正しません。

### デスクトップアプリ

_Install > AI_メニューにはいくつかのグラフィカルなAIアプリも入っています：ChatGPTデスクトップアプリ、Claudeデスクトップアプリ（AnthropicのLinuxベータで、Chat、Cowork、Claude Codeタブ付き）、xAIのモデルとチャットするためのGrok Bot、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexityデスクトップアプリ、T3 Codeです。Grok Botはデスクトップチャットアプリです。コーディングエージェントは`grok`コマンドです。

Hermes Desktopは知っておくべきものです。なぜなら、マシンには1つのHermesしかなく、それはアプリのものだからです：Hermesは常にアプリを通じてのみインストールされ、デフォルトのエージェントが実行する`hermes`コマンドはアプリのものです。Hermesをデフォルトのエージェントとして選択すると、_Install > AI_エントリと同じものがインストールされます：パッケージと、Hermes自身のインストーラーでセットアップされる`~/.hermes`の下のHermesランタイムです。初回は数分かかります。そのランタイムが、ターミナルの`hermes`コマンド、デフォルトのエージェント、アプリのすべてが使う唯一のHermesであり、Omarchyのリリースを待つのではなく`hermes update`で自身をアップデートします。インストールすると、Hermesには`omarchy`という名前のスキンとしてOmarchyテーマも渡されます。テーマを切り替えると、すべてのHermes画面がそれに追従します；そうしたくなければ、HermesのAppearance設定、または`/skin`で別のものを選択してください。Omarchyはその選択には干渉しません。_Remove > AI_でアプリを削除すると、まずHermesが閉じられ（ゲートウェイを含む）、そのランタイムも一緒に取り除かれ、そう指示しない限りあなたのチャット、メモリ、Hermesが自分のために書いたスキルは保持されます：そのデータと接続設定も削除するかどうかを尋ね、デフォルトは「いいえ」です。

OpenClawのデスクトップ体験はそのControl UIであり、自身のローカルゲートウェイをバックエンドとするWebアプリとして開きます。OpenClawは`~/.openclaw`にあり、自身をアップデートします：Control UIの「Update Gateway」ボタンを使うか、`openclaw update`を実行すると、ゲートウェイは新しいバージョンで再起動します。Omarchyは、新規インストールがどのリリースから始まるかだけを選びます。_Remove > AI_でOpenClawを削除すると、ゲートウェイサービスとアプリが一緒に取り除かれ、その後`~/.openclaw`も削除するかどうかを尋ねます。そこにはOpenClaw本体やダウンロードするプラグインランタイムと並んで、あなたのチャットと認証情報が入っているからです；デフォルトでは保持され、OpenClawを再度インストールするとまた拾われます。

Herdr Desktopは[Herdr](https://herdr.dev)デスクトップアプリです：ウィンドウを閉じてもそのコアで実行され続けるターミナルとコーディングエージェントのスペース、タブ、ペインです。パッケージではなくHerdr自身のインストーラーから来るため、`~/.local/share/herdr-app`にあり、まだ持っていない場合は`~/.local/bin/herdr-core`にそのコアも持ってきて、両方とも自身をアップデートします。Omarchyが`Super + Ctrl + Return`に提供する`herdr`コマンドを置き換えるのではなく、その横に置かれ、そのコマンドのダイレクトキーを取得します：`Alt + Return`と`Alt + Shift + Return`はペインを下または右に分割し、`Alt + Escape`は閉じ、`Ctrl + Alt + Arrow`はペイン間を移動し、`Alt + 1..9`と`Alt + Left/Right`はタブを選択し、`Alt + Up/Down`はスペース間を移動します。`Ctrl + 1..9`はスペースを選択し、`Alt + Shift + Up/Down`はエージェント間をステップ移動します。`Ctrl + Space`プレフィックスキーはターミナル専用のままです。アプリはシーケンスのために素のCtrlキーを保持できないからです。Omarchyはこれらを`~/.config/herdr-app/keys.json`に書き込み、`omarchy-refresh-herdr-app`で元に戻します。インストールするとHerdrのOmarchyテーマが選択され、それ以降はあなたのOmarchyテーマに追従します。Herdrはライトモード用に1つ、ダーク用に1つのテーマを保持するため、ダークなOmarchyテーマとライトなOmarchyテーマを切り替えた後は、もう一方のモードのためにHerdrのテーマピッカーでOmarchyをもう一度選択してください。

T3 Codeはパッケージからではなく、`~/.local/share/t3code`にある公式AppImageリリースから実行されるため、自身をアップデートします。インストールすると、Stableチャンネルで始めるかNightlyチャンネルで始めるかを尋ねます；後でT3 Codeの設定で切り替えてください。あなたのスレッドと設定は`~/.t3`にあり、_Remove > AI_でT3 Codeを削除するとそれらも一緒に削除されます。

### ローカルモデル

コーディングエージェントのために、自分のマシンでオープンモデルを実行してください。あなたのプロンプトとコードはマシン上に残ります；モデルに送られたものはマシンから出ません。次で開始してください：

```bash
omarchy agent local use best
```

または、トップバーのエージェントパネルで+、次にLocal AIを選択してください。これはモデルがこのマシンに収まる場合に表示されます。初回は、モデルを実行するPodmanがインストールされ、NVIDIAマシンではそれらにGPUを提供するNVIDIAのコンテナツールキットがインストールされます。次にOmarchyはこのマシンに推奨されるモデルを選び、ダウンロードして開始します。数十GBのダウンロードと、モデル実行中にマシンのメモリの大部分が使用されることを想定してください：Flash Nextは、その完全な256Kコンテキストで約100 GiBを使います。必要なメモリを他のモデルが保持している場合、停止した状態でセットアップされ、1つを停止すれば開始できる状態になります。モデルはログアウト時に停止します；他の用途にメモリが必要なときは自分で停止してください。

`omarchy agent local list`はオプションを表示し、一部が収まらない理由を説明します。別のものをセットアップするには、`omarchy agent local use <recipe>`を実行してください。現在、128 GB Strix Haloマシン向けに`qwen3.8-flash-next-gufo`と`qwen3.8-27b-gufo`が利用できます；27Bは約40 GiBを使うため、他の作業用の余裕が残ります。新しいレシピと推奨は、パッケージを通じて`omarchy update`で届きます。

セットアップしたすべてのモデルは、サブスクリプションの隣に、エージェントパネルで独自の行を持ちます：再生で開始、一時停止で停止してメモリを解放、ターミナルボタンでその上でエージェントを開きます。メモリに一緒に収まる場合は複数を同時に実行できます；1つが収まらない場合、Omarchyはどの実行中のモデルを停止すべきかを伝えます。行をドラッグして並べ替え、選択した行でDeleteを押すとモデルとそのダウンロードを削除します。

コマンドラインからは、`omarchy agent local start <recipe>`と`omarchy agent local stop <recipe>`が同じことをし、`omarchy agent local status`はすべてのモデルを表示し、`omarchy agent --local`は最後に開始したモデル上でデフォルトのエージェントを開きます。pi、OpenCode、Qwen Codeは1つを使えます；他のデフォルトの場合はpiで開きます。piは、セットアップしたすべてのモデルと、ペアリングしたマシン上のモデルも、自身のモデルピッカーにリストするため、素の`pi`でもそれらにアクセスできます。OpenAI互換のクライアントならどれでも接続できます：`status`は各モデルのアドレス（最初は`http://127.0.0.1:11435/v1`）を表示し、レシピ名がモデルで、キーは`~/.config/omarchy/agent-local/key`にあります。

`omarchy agent local remove <recipe>`はモデルと、他のモデルが使っていないダウンロードを削除します。

サードパーティのランタイムには、その提供元のラベルが付けられます。Omarchyはすべてのモデルをネットワークアクセスなしで実行します。

### ローカルLLM

OmarchyはローカルLLMモデルを実行する2つの方法を推奨します：LM StudioとOllamaです。LM Studioは、オープンウェイトモデルを見つけ、インストールし、実行するためのGUIインターフェースを提供します。手軽に始めるには最適な方法です。Ollamaは同様のことを行うCLIを提供します。しかしローカルモデルが初めてなら、私はLM Studioから始めるでしょう。どちらもOmarchy Menuの_Install > AI_でインストールできます。

### Omarchy Skill

エージェントスキルは、AIが特定のツールを特定の方法で使うのを助け、Omarchyにはシステムをカスタマイズするためのデフォルトスキルが付属しています。Hyprland設定を微調整したり、バーを調整したり、さらにはテーマを一から新しく作ったりするようなことです。これは、Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills`と各`~/.hermes/profiles/*/skills`）、そして汎用の`~/.agents/skills`場所のスキルディレクトリにシンボリックリンクされているため、ほとんどのハーネスが自動的に拾います。

しかし、このスキルは実験的なものとして扱うべきです。モデルによって効果は異なります。まずプランモードで実行するのが最善です。そうすれば、エージェントが何を変更したいのかが分かります。そして、エージェントがすべてをめちゃくちゃにしたら、変更をロールバックしたり、`omarchy reinstall configs`を呼び出したりする準備をしておいてください。
