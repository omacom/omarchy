### エージェントのインストールとアップデート

Hermes と OpenClaw を除き、これらのエージェントは mise の遅延インストールを使います。初回起動時に CLI がインストールされ、それ以降の起動ではそれが再利用されます。mise はまた、インストール済みエージェントの新しいリリースを、起動直前またはシェルプロンプトでバックグラウンドに、最大で 4 時間に一度だけチェックします。そのアップデートが失敗したりオフラインだったりした場合、インストール済みのバージョンが動作します。`omarchy update` は、Omarchy の他の部分と一緒にインストール済みエージェントをアップデートし、`mup` は mise で管理されているツールだけをアップデートします。

`claude update`、`codex update`、アプリ内のアップデートボタンなど、エージェント独自のアップデーターは、mise で管理されているインストールをアップデートしません。`codex update` は失敗し、`claude update` は成功したと報告しながら、mise が追跡しない別のコピーをインストールすることがあります。エージェント独自のインストーラーとアップデーターを使いたい場合は、それを `disable_tools` に追加してください。[プリインストールされた CLI ツール](18-development-tools.md#preinstalled-cli-tools) を参照してください。

必要なときに備えて設定済みの遅延ツールをすべてインストールするには、`mise install --include-lazy` を実行してください。これにはエージェントだけでなく、Omarchy の他のデフォルト CLI ツールも含まれます。単一のツールのインストールや、独自のインストールを使う方法については [プリインストールされた CLI ツール](18-development-tools.md#preinstalled-cli-tools) を参照してください。

`grok` は mise のファーストパーティ `grok` パッケージ経由でインストールされます。`claude` や `codex` と同じ方法です。`grok` を実行するか、エージェントパネルでスターを付けてください。x.ai の `curl | bash` インストーラーは使わないでください。その方法だと `~/.grok/bin` に 2 つ目のコピーが置かれ、`PATH` の前に追加され、Omarchy のラッパーが上書きされます。

`dsh` は `127.0.0.1:3080` でブラウザ UI を開き、起動したディレクトリをデフォルトのワークスペースにします。そのブラウザ UI は開始プロンプトを受け取らないので、`omarchy agent prompt` はクリップボードにプロンプトを入れた状態でそれを開き、貼り付けられるようにします。Omarchy は DeepSeek の承認なし権限プリセットでこれを起動します。DeepSeek Harness は、公式モデル API を使うとセッションログを DeepSeek にアップロードします。そのブラウザ UI の _Settings > General > Upload Session Log_ でこれをオフにしてください。送信したフィードバックもセッションと一緒にアップロードされます。ただし `DSH_TELEMETRY_MODE=DISABLED` で起動した場合は除きます。

### デフォルトのエージェント

エージェントパネルでエージェントの横にあるスターでデフォルトのエージェントを選んでください。デフォルトにはスターが塗りつぶされています。または `omarchy default agent <name>` を使います。これは、そこに行がないハーネスも受け付けます。エージェントがまだインストールされていなければ、選ぶことでまずインストールされ、アプリランチャーで Agent の横に独自のランチャーも得ます。新品の Omarchy は一度だけの通知で設定を促し、それを開くとエージェントパネルが開きます。

Claude を選択すると、Chromium、Chrome、Brave、Brave Origin、Edge 用のブラウザ拡張機能のセットアップも試みます。拡張機能のセットアップはすべてのユーザーに適用され、システムパスワードを求められることがあります。キャンセルしたり拡張機能のインストールが失敗したりしても、Claude は選択され起動します。ブラウザを再起動し、求められたら拡張機能を有効化し、Claude にサインインして接続を完了してください。Claude で `/chrome` を実行して接続を確認してください。Firefox と Zen はこの拡張機能をサポートしていません。Claude がこのセットアップが追加される前からすでにデフォルトだった場合は、もう一度選択して拡張機能をインストールしてください。

選択が終わったら、`Super + Shift + Ctrl + A` で専用のターミナルウィンドウでデフォルトのエージェントが起動します（まだ選択していなければピッカーが表示されます）。`omarchy agent prompt "Review this project"` を使ってタスクに直行させることもできます。Freebuff と DeepSeek Harness は開始プロンプトを受け取らないので、代わりにクリップボードにプロンプトを入れた状態で開き、貼り付けられるようにします。この方法で起動したエージェントは、それぞれの確認で止まらないモードで無人で動作します。だから、本当に作業を実行する心構えをしておいてください！MiniMax Code には対話セッション用のそうしたモードがないので、通常どおり権限を求めます。またエージェントはホームディレクトリに対する信頼を覚えることを拒否するため、`$HOME` からの起動は代わりに `~/Work` で開始します。

ターミナルショートカットもあります。`a` は現在のターミナル内でデフォルトのエージェントをインラインで実行し、`c`、`cx`、`cy`、`ca` は OpenCode、Claude Code、Codex、Antigravity を直接起動します（こちらも自動承認モードです）。テーマの変更もエージェントに同期されます。Claude Code、Pi、OpenCode、Hermes（Omarchy がインストールした後は）は、Omarchy のテーマを切り替えるとそれに追従します。

### エージェントへの指示

すべてのエージェントに対する個人的なルールは `~/.agents/AGENTS.md` に入れます。`~/.agents/skills` の共有スキルの隣です。エージェントパネルの + の横にあるドキュメントアイコンで開くか、`omarchy agent instructions --edit` を使ってください。後者は、独自のグローバルファイルを保持する各ハーネスにもこれをリンクします。`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`~/.pi/agent/AGENTS.md`、`~/.config/opencode/AGENTS.md`、Copilot の `~/.copilot/copilot-instructions.md` などです。Crush と Amp は `~/.config/AGENTS.md` リンクを読み、omp、Kimi、DeepSeek Harness は `~/.agents/AGENTS.md` を直接読みます。デフォルトのエージェントを選ぶことでもリンクされます。すでに持っていた指示ファイルは、共有のものがまだなければ共有のものになります。そうでなければリンクの横に `.bak` として保持されます。別のエージェントをインストールした後に再リンクするには `omarchy agent instructions` を実行してください。

### エージェントパネル

トップバーにはエージェントアイコンがあります。エージェントを設定する前は、そのパネルは 3 つの始め方を提供します。Claude、Codex、Grok、Gemini、Muse、Cursor、Copilot のサブスクリプションにサインインするか、More の下の OpenCode Go、MiniMax、Synthetic、Z.ai のコーディングプランを使うか、Fireworks、OpenCode Zen and Go、OpenRouter、または More の下の DeepSeek か OpenCode がサインインするその他のプロバイダーで従量課金し、すべて OpenCode で実行するか、お使いのコンピューターに合うものがあれば、そのコンピューターに最適なモデルを実行するかです。最初に終えたものがデフォルトのエージェントになり、パネルの + は後から同じ 3 つを提供します。その後は、パネルはすべてのサブスクリプションを 1 ページにまとめます。各エージェントとアカウントとそのプラン、5 時間セッションと週間上限それぞれのメーターとリセットまでの時間（正確なパーセンテージはホバーで表示）、またはプリペイド残高が、全アカウントでの使用量、例えば今週のトークンや最もよく使ったモデルなどを巡回表示する行の下に並びます。_Make something cool_ の下では、新しいテーマ、プラグイン、アプリ、ゲームのスタータープロンプトが提供され、タスクをデフォルトのエージェントに渡します。アプリは Omarchy 自身の Hype、Monologue、Omacut と同じ方法で、C++ と Qt Quick で構築され、omarchy-make-app エージェントスキルに従います。必要なコンパイラと Qt の部品はインストール済みで付属します。ゲームは `~/Games/vibes` の単一の three.js ページで、omarchy-make-game エージェントスキルに従い、すべて現在のテーマの 1 つの Game Vibes ランチャーから開きます。three.js をウェブから読み込むので、開始には接続が必要です。Claude Code、Codex、Grok、Kimi、Cursor とその Grok Bot 枠、GitHub Copilot、Muse、Gemini（Antigravity 経由）、Devin は上限付きでそのまま利用でき、Kimchi はそのプラン、プリペイドクレジット、支出予算付きで、Hermes、Mistral Vibe、Qwen Code は一度使うとセッションとトークンを表示します。pi、omp、opencode 経由で使うプロバイダープランとキーも表示されます。OpenCode Zen and Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan、Synthetic は上限付きで、OpenRouter と DeepSeek はプリペイド残高付きで、Fireworks は過去 30 日間の支出付きです。自分のハードウェアで実行するコーディングモデルは独自の行を持ち、そのトークンも合計に算入されます。[ローカルモデル](#local-models) で説明しているとおりです。すべてのエージェントは、請求元のもとで一度だけ数えられます。何個のハーネス経由で駆動しても同じです。

バーアイコンを左クリックするか `Super + Ctrl + X` を押すとパネルが開き、右クリックでデフォルトのエージェントが起動し、中クリックで更新します。その背後にある使用記録は 15 分ごとに `omarchy agent usage update` で再生成され、パネルは同期フォルダ経由で他のマシンからの使用量を統合することもできます。設定の詳細については `$OMARCHY_PATH/shell/plugins/agents/` の README を参照してください。

### 複数のサブスクリプション

Claude、Codex、Grok のプランを複数支払っている場合、例えば個人の Max と仕事用など、Omarchy はすべてサインインしたままにして、それらを移動できます。エージェントパネルの + でサブスクリプションを追加してください。その場で順を追って案内します。または `omarchy agent account add claude Work`（または `codex`、または `grok`）を使ってください。同じ + とコマンドで Gemini（`gemini`）と OpenCode（`opencode`）にサインインし、Fireworks（`fireworks`）または OpenRouter（`openrouter`）の API キーを OpenCode に保存します。コマンドは Copilot（`copilot`）、Cursor（`cursor`）、Muse（`muse`）にもサインインします。それらはそれぞれ単一のサインインを保持します。CLI がなければインストールします。プロバイダーの最初のアカウントは、CLI がいつも参照する通常のブラウザ経由でサインインします。それ以降のすべてのアカウントはプライベートウィンドウ経由でサインインします。ブラウザがすでにサインインしているアカウントが誤って拾われないようにするためです。追加するアカウントとしてそこでサインインし、すでに開いていたプライベートウィンドウは先に閉じてください。このために CLI からログアウトしてはいけません。ログアウトすると保存したサインインが失効し、そのアカウントを再度追加しなければならなくなります。

別の Omarchy マシンに SSH 経由でサブスクリプションのログインをコピーするには、`omarchy agent account copy user@laptop` を実行してください。宛先に受信側がインストールされていなければ送信側が一時的な受信側を提供するので、古い Omarchy マシンでもアップデートなしにアカウントを受け取れます。インストール済みの受信側が優先されます。これはすべての Claude、Codex、Grok サブスクリプションをコピーします。選択するには `omarchy agent account copy laptop claude` のようにプロバイダー名を追加してください。アカウント名とコマンド ID は送信元に一致します。宛先にすでに存在するアカウントを含みます。関係ない宛先アカウントは名前が競合すれば数値サフィックスを受け取り、設定、スキル、プラグイン、会話履歴は各マシンにローカルなままです。

既存の宛先の認証情報は保持されます。そこで既にサインインしている送信元アカウントは、認証情報を置き換えることなく名前が同期され、他のアカウントはその横に追加されます。一致するアカウントの保存済み認証情報を置き換えるには、宛先でそのアカウントのセッションを終了した後に `omarchy agent account copy --replace laptop claude` を使ってください。新品の宛先は送信元のアクティブなアカウントと切り替え設定も引き継ぎます。確立済みの宛先は自身のものを保持します。

認証情報は SSH 経由で移動し、宛先のプライベートファイルに保存されるので、信頼するマシンにのみコピーしてください。これは一度だけのコピーであり、継続的な同期ではありません。Codex のリフレッシュトークンは別のマシンでローテーションされることがあり、コピーしたログインが更新を必要とする状態になることがあります。複数のマシンで同時に使うには、別々のサインインが最も確実な選択です。[Codex のアカウント認証ガイダンス](https://developers.openai.com/codex/auth/ci-cd-auth) を参照してください。

プロバイダーごとに 1 つのアカウントがアクティブであり、すべての新しいセッションはそれとして開始します。`cx`、`cy`、素の `claude`、`codex`、`grok`、`omarchy agent` 経由で起動されるもの、`PATH` 上で CLI を見つけるスクリプトやエディターがそうです。`omarchy agent account use work` で切り替え（`omarchy agent account use main` で元に戻す）、またはパネルでアカウントの番号を押してから `Enter` を押す（またはそのスターをクリックする）ことで切り替えます。実行中の Claude セッションも次のメッセージから切り替わります。すべての Claude セッションは `~/.claude` で実行され、そこには常にアクティブなアカウントのサインインが入っています。古い Omarchy でアカウント自身のフォルダで開始された Claude セッションは、終了するまでそのサインインを保持するので、切り替えではそれらのセッションの名前が言われ、消えたら自動で完了します。実行中の Codex と Grok セッションは開始したアカウントのままです。会話履歴、設定、スキル、プラグインはアカウント間で共有されるので、同じフォルダで `claude --continue` をすると新しいアカウントで中断したところから再開できます。

アカウントが複数ある場合、パネルは各アカウントの上限を並べて表示し、使用中のものに塗りつぶされたスターが付きます。アクティブなアカウントが上限の 95% を超えると Omarchy が通知し、通知をクリックすると余裕が最も大きいアカウントに切り替わります。自動で切り替えることは決してありません。しきい値は `omarchy agent account threshold 90` で変更してください。すべてのアカウントがしきい値を超えている場合、そのことは一度だけ通知され、どのアカウントが最初に空くかも一緒に知らされます。アクティブなアカウントがしきい値まで 15 ポイント以内（デフォルトで 80%）にある間は、その上限は 15 分ごとではなく 3 分ごとにチェックされます。

`omarchy agent account list` はすべてのアカウントとその最新の上限を表示し、`omarchy agent account remove work` は 1 つを忘れ、`omarchy agent account rename primary Hey` は 1 つをリネームします（またはパネルでアカウントの名前をクリックします）。これらのコマンドはデフォルトのエージェントのアカウントに対して動作します。他のプロバイダーに届くには、まず名前を付けてください。例えば `omarchy agent account use codex side` のようにします。`~/.claude` や `~/.codex` にすでにあったログインが _Main_ アカウントです。Codex のものはその場に残ります。Claude のものは別のアカウントがアクティブな間、自身のフォルダで待機します。約 8 時間以上使われていないアカウントは _Sign-in required_ と表示されることがあります。クリックしてパネルですぐにそのアカウントにもう一度サインインするか、そのアカウントに切り替えてセッションを開始すれば、サインインは自動で更新されます。`claude mcp add` で追加した MCP サーバーはすべての Claude アカウントに届きます。全部 `~/.claude` で実行されるからです。Codex と Grok については、アカウント追加時に持っていたサーバーはそのアカウントに一緒に移りますが、それ以降のものは追加したアカウントにしか届きません。Claude Desktop は独自のサインインを保持し、CLI バイナリへの絶対パスで設定された Codex や Grok のツールは切り替えに従いません。明示的な `CLAUDE_CONFIG_DIR`、`CODEX_HOME`、`GROK_HOME` は選択したアカウントより優先されます。

### クラッシュ診断

Omarchy はプロセスのクラッシュについて systemd-coredump を監視します。デフォルトのエージェントを選んだら、コアダンプしたあなたのプログラムはどれでも「Process crashed」通知を出し、それをクリックすると、クラッシュはデフォルトのエージェントに Omarchy の omarchy-diagnose-crash スキルとともに引き渡されます。そのスキルは、コアダンプから事実を確立し、クラッシュを上流に報告する価値があるかどうかを判断するようエージェントを導きます。`coredumpctl list` の任意の PID に対して `omarchy agent crash <pid>` で手動で実行することもできます。

監視はデフォルトでオンです。_Trigger > Toggle > Crash Capture Off_ でオフにする（または `omarchy toggle crash-capture` で）すると通知は止まります。`omarchy agent crash <pid>` は手動では引き続き動作します。

クラッシュはプログラムごとに 1 つずつ黙らせることもできます。それが診断が最後に提案することです。`omarchy crash mute hyprland` はそのプログラムだけの通知を止め、`omarchy crash mute hyprland off` で元に戻し、`omarchy crash mute` だけだとミュートしたものを一覧します。名前と同じくらい気軽にバイナリのパスも受け付けるので、`omarchy crash mute /usr/bin/hyprland` でも同じことです。スペースを含む名前は `omarchy crash mute 'Some App'` のように引用してください。他のすべては引き続き通知し、ミュートしたプログラムは引き続きクラッシュします。これはリマインダーを隠すだけで、何も直しません。

### デスクトップアプリ

_Install > AI_ メニューにはグラフィカルな AI アプリもいくつかあります。Amp Desktop、Antigravity Desktop、ChatGPT デスクトップアプリ、Claude デスクトップアプリ（Anthropic の Linux ベータ、Chat、Cowork、Claude Code タブ付き）、xAI のモデルとチャットする Grok Bot、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexity デスクトップアプリ、T3 Code です。Grok Bot はデスクトップチャットアプリです。コーディングエージェントは `grok` コマンドです。

Hermes Desktop は知っておくべき存在です。マシンには Hermes は 1 つだけあり、それはアプリのものだからです。Hermes はアプリ経由でしかインストールされず、デフォルトのエージェントが実行する `hermes` コマンドはアプリのものです。Hermes をデフォルトのエージェントとして選択すると、_Install > AI_ の項目がするのと同じものがインストールされます。パッケージと、Hermes 自身のインストーラーでセットアップされる `~/.hermes` の Hermes ランタイムです。初回は数分かかります。そのランタイムは、ターミナルの `hermes` コマンド、デフォルトのエージェント、アプリのすべてが使う唯一の Hermes であり、Omarchy のリリースを待つのではなく `hermes update` で自己更新します。インストールすると Hermes に Omarchy テーマが `omarchy` という名前のスキンとして渡され、すべての Hermes の表面はテーマ切り替えに追従します。そうしたくなければ Hermes の Appearance 設定で、または `/skin` で別のものを選んでください。Omarchy はその選択に干渉しません。_Remove > AI_ でアプリを削除すると、ゲートウェイを含めてまず Hermes が閉じられ、そのランタイムも一緒に削除され、チャット、メモリ、Hermes が自身のために書いたスキルは保持されます。ただしそうしないよう指示した場合は除きます。そのデータと接続設定も削除するかどうかを尋ね、デフォルトはいいえです。

OpenClaw のデスクトップ体験は Control UI であり、独自のローカルゲートウェイをバックエンドにしたウェブアプリとして開きます。OpenClaw は `~/.openclaw` に住み、自己更新します。Control UI の「Update Gateway」ボタンを使うか `openclaw update` を実行してください。ゲートウェイは新しいバージョンで再起動します。Omarchy は新品のインストールが開始するリリースを選ぶだけです。OpenClaw はデフォルトのエージェントにもなれます。`omarchy default agent openclaw` で選択すると `~/.openclaw` に同じコピーがセットアップされ、エージェントはゲートウェイに接続された OpenClaw のターミナル UI を開きます。_Remove > AI_ で OpenClaw を削除すると、ゲートウェイサービスとアプリが一緒に削除され、その後 `~/.openclaw` も削除するかどうかを尋ねます。そこには OpenClaw 自体やダウンロードするプラグインランタイムとともにチャットと認証情報が入っているからです。デフォルトは保持し、OpenClaw を再度インストールするとそれを再び拾います。

Herdr Desktop は [Herdr](https://herdr.dev) デスクトップアプリです。ウィンドウを閉じてもそのコアで動き続けるターミナルとコーディングエージェントのスペース、タブ、ペインです。パッケージではなく Herdr 自身のインストーラーから来るので、`~/.local/share/herdr-app` に住み、まだ持っていなければ `~/.local/bin/herdr-core` にそのコアを一緒に持ってきて、両方を自己更新します。Omarchy が `Super + Ctrl + Return` で提供する `herdr` コマンドを置き換えるのではなく、その横に座り、そのコマンドのダイレクトキーを受けます。`Alt + Return` と `Alt + Shift + Return` はペインを下または右に分割し、`Alt + Escape` はそれを閉じ、`Ctrl + Alt + Arrow` はペイン間を移動し、`Alt + 1..9` と `Alt + Left/Right` はタブを選び、`Alt + Up/Down` はスペース間を移動します。`Ctrl + 1..9` はスペースを選び、`Alt + Shift + Up/Down` はエージェントを順に辿ります。`Ctrl + Space` プレフィックスキーはターミナル専用のままです。アプリはシーケンスのために素の Ctrl キーを保持できないからです。Omarchy はこれらを `~/.config/herdr-app/keys.json` に書き、`omarchy-refresh-herdr-app` で元に戻します。インストールすると Herdr の Omarchy テーマが選ばれ、それ以降あなたの Omarchy テーマに追従します。Herdr はライトモード用に 1 つ、ダーク用に 1 つのテーマを保持するので、ダークとライトの Omarchy テーマを切り替えた後は、もう一方のモード用に Herdr のテーマピッカーで Omarchy をもう一度選んでください。

T3 Code はパッケージではなく `~/.local/share/t3code` の公式 AppImage リリースから実行されるので、自己更新します。インストール時に Stable チャンネルで開始するか Nightly チャンネルで開始するかを尋ねます。後で T3 Code の設定で切り替えてください。スレッドと設定は `~/.t3` に住み、_Remove > AI_ で T3 Code を削除するとそれらも一緒に削除されます。

### ローカルモデル

自分のマシンでオープンモデルを実行してコーディングエージェントに使ってください。プロンプトとコードはマシンに残り、モデルに送られたものはマシンから出ません。次で始めてください。

```bash
omarchy models use best text
```

これでこのマシンに最適なテキストモデルがセットアップされます。エージェントが使うタイプのものです。画像、動画、音楽モデルにもそれぞれ最適なものがあります。`omarchy models use best image`、`video`、または `music` です。`omarchy models use best` を実行すると、このマシンに対する各タイプの選択が表示されます。

またはエージェントパネルで + を選んでください。_Use a local model_ の下に、このマシンに合うすべてのコーディングモデルが、推奨のものを最初に一覧表示されます。モデルを実行する Podman は Omarchy に付属し、NVIDIA マシンでは NVIDIA のコンテナツールキットも付属し、モデルに GPU を与えます。どちらかが欠けていれば、最初のセットアップでインストールされます。次に Omarchy はこのマシンに推奨されるモデルを選び、ダウンロードして開始します。ダウンロードは数十 GB になり、モデル実行中はマシンのメモリのほとんどが使用中になると予想してください。Flash Next は完全な 256K コンテキストで約 100 GiB を使います。必要なメモリを他のモデルが占有していれば、停止した状態でセットアップされ、1 つ停止すれば開始できる準備ができます。モデルはログアウト時に停止します。他のことにメモリが必要なときは自分で停止してください。

`omarchy models list` は選択肢を表示し、一部が合わない理由を説明します。別のものをセットアップするには `omarchy models use <recipe>` を実行してください。現在、128 GB の Strix Halo マシン向けに `qwen3.8-flash-next-gufo` と `qwen3.8-27b-gufo` が利用可能です。27B は約 40 GiB を取るので、他の作業の余地が残ります。Intel の Arc B390 を搭載した 64 GB のラップトップでは、`qwen3.6-35b-a3b-llamacpp` が約 30 GiB で動作します。新しいレシピと推奨は `omarchy update` で、パッケージ経由で届きます。

追加したコーディングモデルはエージェントパネルでサブスクリプションの横に独自の行を持ちます。再生で開始、停止で停止してメモリを解放、実行中に tailnet 上の他のマシンと共有する Tailscale マーク、その上でエージェントを開くターミナルボタンです。その行はダウンロード、読み込み、停止の様子を随時表示し、開始するのに十分な空きメモリがないときはそう言い、エラーで停止したときはログにリンクします。メモリに一緒に収まる場合は複数を同時に実行できます。選択した行で Delete を押すと、ダウンロードを含めてそのモデルをこのマシンから削除します。+ で再びセットアップできます。ターミナルからセットアップしたコーディングモデルは、追加するまで + の下で待機します。ペアリングしたマシン（`omarchy models pair <host>`）が実行するモデルも同様です。

セットアップしたすべてのコーディングモデルは、アプリランチャーにも独自の項目を持ちます。モデルの名前で、作成元のロゴ付きで、Claude、Codex、Grok にサインインすると追加されるのと同じ方法です。それを開くとそのモデルでエージェントが開き、実行していなければまずモデルが開始します。ターミナルは読み込みの様子を表示し、起動したらエージェントに引き渡します。モデルを削除するとその項目も削除されます。

すべてのモデルがコーディング用ではありません。画像、動画、音楽モデルは代わりに Fantasi で開きます。Fantasi はこのマシンで実行されるモデルで画像、動画、音楽を作るための Omarchy のアプリであり、そこで、または `omarchy models` で管理されます。

モデルはセットアップされたとおりに正確に動き続けるので、Omarchy のアップデートでエージェントの下で再起動されることは決してありません。Omarchy が、セットアップしたモデルの新しいランタイムや新しい重みを持っている場合、その行にアップデートボタンが表示されます。押すとモデルはバックグラウンドで再びセットアップされ、変更されたものだけをダウンロードし、新しいバージョンで再起動します。停止していたモデルは停止したままです。`omarchy models update` はターミナルからすべてのモデルに対して同じことをします。

コマンドラインからは、`omarchy models start <recipe>` と `omarchy models stop <recipe>` が同じことをし、`omarchy models status` はすべてのモデルを表示し、`omarchy agent --local-model <recipe>` は、デフォルトのエージェントが何であれ、そのモデルを pi で開きます。ローカルモデルを、エージェントホットキー、Quake コンソール、_Make something_ が開くものにするには、`omarchy default agent local` を実行するか、エージェントパネルで実行中のモデルにスターを付けてください。pi はセットアップしたすべてのモデルと、ペアリングしたマシンのモデルも、独自のモデルピッカーに一覧表示するので、素の `pi` でもそれらに届きます。OpenAI 互換のクライアントも接続できます。`status` は各モデルのアドレスを表示し（最初は `http://127.0.0.1:11435/v1`）、レシピ名がモデルであり、キーは `~/.config/omarchy/agent-local/key` にあります。

`omarchy models remove <recipe>` はモデルと、他のモデルが使わないダウンロードを削除します。

サードパーティのランタイムには発行元のラベルが付けられます。Omarchy はすべてのモデルをネットワークアクセスなしで実行します。

### ローカル LLM

Omarchy はローカル LLM モデルを実行する方法として 2 つを推奨します。LM Studio と Ollama です。LM Studio は、オープンウェイトモデルを見つけ、インストールし、実行するための GUI インターフェイスを提供します。簡単に始めるには素晴らしい方法です。Ollama は同様のことをするための CLI を提供します。でもローカルモデルが初めてなら、私なら LM Studio から始めます。どちらも Omarchy メニューの _Install > AI_ でインストールできます。

### Omarchy スキル

エージェントスキルは、AI が特定のツールを特定の方法で使うのを助け、Omarchy には 7 つが付属します。omarchy スキルはシステムのカスタマイズをカバーします。Hyprland 設定を微調整したりバーを調整したりするようなことです。omarchy-make-theme、omarchy-make-plugin、omarchy-make-app、omarchy-make-game は新しいものを作ることをカバーし、omarchy-contribute はバグを報告したり修正を上流に送ったりすることをカバーし、omarchy-diagnose-crash はクラッシュのコアダンプを調査します。これらは Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` と各 `~/.hermes/profiles/*/skills`）、そして汎用の `~/.agents/skills` の場所のスキルディレクトリにシンボリックリンクされているので、ほとんどのハーネスは自動で拾います。同じ名前の独自のスキルフォルダが優先されます。

でも、これらのスキルは実験的なものとして扱うべきです。モデルによって効果の現れ方は異なります。まずプランモードで実行するのが最善です。エージェントが何を変更したいのか把握できるからです。そして、エージェントがすべてをめちゃくちゃにした場合に備えて、変更をロールバックしたり、`omarchy reinstall configs` を呼び出したりする準備をしておいてください。
