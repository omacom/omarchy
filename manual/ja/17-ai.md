### エージェントのインストールとアップデート

Hermes を除き、これらのエージェントは mise の遅延インストールを使う。初回起動時に CLI がインストールされ、以降の起動ではそれを再利用する。mise はまた、インストール済みエージェントの新リリースを最大で4時間に1回だけチェックする。起動直前か、シェルプロンプトでバックグラウンドでだ。そのアップデートが失敗したりオフラインだったりすれば、インストール済みバージョンが実行される。`omarchy update` は Omarchy の残りとともにインストール済みエージェントをアップデートし、`mup` は mise 管理ツールだけをアップデートする。

エージェント自身のアップデーター、例えば `claude update`、`codex update`、アプリ内のアップデートボタンなどは、mise 管理のインストールをアップデートしない。`codex update` は失敗し、`claude update` は成功したと報告しながら mise が追跡しない別コピーをインストールすることがある。エージェントのネイティブインストーラーとアップデーターを使いたければ、`disable_tools` に追加すること。[インストール済み CLI ツール](18-development-tools.md#preinstalled-cli-tools) を参照。

設定されたすべての遅延ツールを必要になる前にインストールするには、`mise install --include-lazy` を実行する。これにはエージェントだけでなく Omarchy の他のデフォルト CLI ツールも含まれる。単一ツールのインストールや独自インストールの利用については [インストール済み CLI ツール](18-development-tools.md#preinstalled-cli-tools) を参照。

`grok` は `claude` や `codex` と同じように、mise のファーストパーティ `grok` パッケージ経由でインストールされる。`grok` を実行するか、_Agent > Harness_ で選択すること。x.ai の `curl | bash` インストーラーは避けること。その方法では `~/.grok/bin` に2つ目のコピーが置かれ、`PATH` の先頭に追加され、Omarchy のラッパーが上書きされる。

`dsh` は `127.0.0.1:3080` でブラウザ UI を開き、起動ディレクトリをデフォルトのワークスペースとする。そのブラウザ UI は開始プロンプトを受け取らないため、`omarchy agent prompt` はプロンプトをクリップボードに入れた状態で開くので貼り付けること。Omarchy は DeepSeek の承認なし権限プリセットで起動する。DeepSeek Harness は公式モデル API を使うとセッションログを DeepSeek にアップロードする。オフにするにはブラウザ UI の _Settings > General > Upload Session Log_ で設定する。送信したフィードバックもセッションとともにアップロードされる。`DSH_TELEMETRY_MODE=DISABLED` で起動した場合を除く。

### デフォルトエージェント

デフォルトエージェントは `omarchy default agent <name>` で、または Omarchy Menu (`Super + Space`) の _Agent > Harness_ で選ぶ。エージェントがまだインストールされていなければ、選ぶとまずインストールされる。新しい Omarchy では、一度きりの通知でこの選択を促される。

Claude を選ぶと、Chromium、Chrome、Brave、Brave Origin、Edge 用のブラウザ拡張機能のセットアップも試みる。拡張機能のセットアップはすべてのユーザーに適用され、システムパスワードを求められることがある。キャンセルしたり拡張機能のインストールに失敗したりしても、Claude は選択され起動する。ブラウザを再起動し、求められたら拡張機能を有効化し、Claude にサインインして接続を完了すること。接続を確認するには Claude で `/chrome` を実行する。Firefox と Zen はこの拡張機能に対応していない。すでにこのセットアップが追加される前から Claude がデフォルトだった場合は、もう一度選択すると拡張機能がインストールされる。

一度選べば、`Super + Shift + Ctrl + A` でデフォルトエージェントが専用ターミナルウィンドウで起動する（まだ選んでいなければピッカーが表示される）。`omarchy agent prompt "Review this project"` でタスクに直行させることもできる。Freebuff と DeepSeek Harness は開始プロンプトを受け取らないため、代わりにプロンプトをクリップボードに入れた状態で開くので貼り付けること。この方法で起動したエージェントは、それぞれの止まって聞かないモードで無人で実行される。だから実際に何かをする覚悟をしておくこと！ MiniMax Code には対話セッション用のそのようなモードがないため、通常通り権限を求める。そしてエージェントはホームディレクトリに対する信頼を覚えることを拒否するため、`$HOME` から起動した場合は代わりに `~/Work` で開始する。

ターミナルのショートカットもある。`a` は現在のターミナル内でデフォルトエージェントを実行し、`c`、`cx`、`cy` は OpenCode、Claude Code、Codex を直接起動する（こちらも自動承認モードで）。テーマ変更もエージェントに同期される。Claude Code、Pi、OpenCode、Hermes（Omarchy がインストール済みの場合）は、Omarchy テーマを切り替えると一緒に追従する。

### エージェントへの指示

すべてのエージェントに対する個人的なルールは、共有スキルがある `~/.agents/skills` の隣の `~/.agents/AGENTS.md` に置く。_Agent > Instructions_ で開ける。そこでは、独自のグローバルファイルを持つ各ハーネスにもリンクされる。`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`~/.pi/agent/AGENTS.md`、`~/.config/opencode/AGENTS.md`、Copilot の `~/.copilot/copilot-instructions.md` などだ。Crush と Amp は `~/.config/AGENTS.md` リンクを読み、omp、Kimi、DeepSeek Harness は `~/.agents/AGENTS.md` を直接読む。デフォルトエージェントを選ぶとそこにもリンクされる。すでに持っていた指示ファイルは、共有ファイルがまだなければ共有ファイルになり、そうでなければリンクの隣に `.bak` として残される。別のエージェントをインストールした後に再リンクするには `omarchy agent instructions` を実行する。

### エージェントパネル

トップバーにはエージェントアイコンがある。エージェントをまだセットアップしていない場合、そのパネルでは Claude、Codex、Grok へのサインインを順に案内し、最初の一つがデフォルトエージェントになる。その後は、パネルですべてのサブスクリプションが1ページにまとまる。各エージェントとアカウントとそのプラン、5時間セッション制限と週間制限それぞれのメーターとリセットまでの時間（ホバーで正確なパーセンテージ）、または残りのプリペイド残高が、すべての利用を横断してローテーションする行の下に表示される。例えば今週のトークン数や最もよく使ったモデルなどだ。_Make something_ の下では、新しいテーマ、プラグイン、アプリ、ゲーム用のスタータープロンプトが用意され、タスクをデフォルトエージェントに渡す。アプリは Omarchy 自身の Hype、Monologue、Omacut と同じ方法で、C++ と Qt Quick で、omarchy-app エージェントスキルに従ってビルドされ、必要なコンパイラと Qt 部品はインストール済みだ。ゲームは `~/Games/vibes` にある単一の three.js ページで、web-game エージェントスキルに従い、すべて現在のテーマの1つの Game Vibes ランチャーから開く。three.js をウェブから読み込むため、開始には接続が必要だ。Claude Code、Codex、Grok、Kimi、Cursor とその Grok Bot 枠、GitHub Copilot、Muse、Antigravity、Kimchi、Devin は制限付きで最初からカバーされ、Hermes、Mistral Vibe、Qwen Code は使用後にセッションとトークンを表示する。pi、omp、opencode 経由で使うプロバイダーのプランとキーも表示される。OpenCode Zen と Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan、Synthetic は制限付きで、Fireworks、OpenRouter、DeepSeek はプリペイド残高付きで、自分のハードウェアで実行するモデルは Local models の下に表示される。すべてのエージェントは、課金元ごとに1回だけ数えられ、何個のハーネス経由で使っても変わらない。

バーアイコンを左クリックでパネル、右クリックでデフォルトエージェントを起動する。その背後にある利用記録は15分ごとに `omarchy agent usage-update` で再生成され、パネルは同期フォルダ経由で他のマシンの利用状況を統合することもできる。設定の詳細は `$OMARCHY_PATH/shell/plugins/agents/` の下の README を参照。

### 複数のサブスクリプション

複数の Claude、Codex、Grok プランに支払っている場合、例えば個人の Max と仕事用など、Omarchy はすべてをサインイン状態に保ち、切り替えられる。サブスクリプションを追加するにはエージェントパネルの + を使うと、その場で案内される。または `omarchy agent account add claude Work`（`codex` や `grok` も可）を使う。CLI がなければインストールされる。プロバイダーの最初のアカウントは、CLI がいつも見る場所である通常のブラウザ経由でサインインする。それ以降はすべてプライベートウィンドウ経由でサインインする。そのためブラウザですでにサインインしているアカウントを誤って拾うことはない。追加するアカウントとしてそこでサインインし、あらかじめ開いていたプライベートウィンドウは閉じておくこと。決して CLI からログアウトしてこれを行わないこと。ログアウトすると保存されたサインインが失効し、そのアカウントを再度追加しなければならなくなる。

サブスクリプションのログインを SSH 経由で別の Omarchy マシンにコピーするには、`omarchy agent account copy user@laptop` を実行する。宛先に受信側がインストールされていない場合、送信側が一時的な受信側を提供するため、古い Omarchy マシンでもアップデートなしでアカウントを受け取れる。インストール済みの受信側が優先される。これはすべての Claude、Codex、Grok サブスクリプションをコピーする。プロバイダー名を追加して選択することもでき、例えば `omarchy agent account copy laptop claude` のようにする。アカウント名とコマンド ID は送信元と一致し、宛先にすでに存在するアカウントも含む。無関係な宛先アカウントで名前が競合した場合は数字サフィックスが付く。設定、スキル、プラグイン、会話履歴は各マシンにローカルなまま残る。

既存の宛先認証情報は保持される。すでにそこでサインインしている送信元アカウントは、認証情報を置き換えずに名前が同期される。他のアカウントはその隣に追加される。一致するアカウントの保存済み認証情報を置き換えるには、宛先でそのアカウントのセッションを終了した後、`omarchy agent account copy --replace laptop claude` を使う。新しい宛先には送信元のアクティブアカウントと切り替え設定も引き継がれる。すでに確立された宛先は自身の設定を保持する。

認証情報は SSH 経由で移動し、宛先ではプライベートファイルに保存される。だから信頼するマシンにだけコピーすること。これは一度きりのコピーで、継続的な同期ではない。Codex のリフレッシュトークンは別のマシンでローテーションされることがあり、コピーしたログインが更新を必要とする状態になる可能性がある。複数のマシンで同時に使うには、個別にサインインするのが最も確実だ。[Codex のアカウント認証ガイダンス](https://developers.openai.com/codex/auth/ci-cd-auth) を参照。

プロバイダーごとに1つのアカウントがアクティブで、すべての新しいセッションはそれとして開始する。`cx`、`cy`、通常の `claude`、`codex`、`grok`、`omarchy agent` 経由で起動されるものすべて、そして `PATH` 上で CLI を見つけるスクリプトやエディタだ。切り替えは `omarchy agent account use work`（戻すには `omarchy agent account use main`）で、またはパネルでアカウントの番号を押してから `Enter` を押す（または Use ボタンをクリックする）。実行中の Claude セッションも次のメッセージから切り替わる。すべての Claude セッションは `~/.claude` で実行され、そこには常にアクティブアカウントのサインインが保持される。古い Omarchy によってアカウント専用フォルダで開始された Claude セッションは、終了するまでそのサインインを保持するため、切り替え時にはそれらのセッション名が示され、終了したら自動的に完了する。実行中の Codex と Grok セッションは開始したアカウントのまま残る。会話履歴、設定、スキル、プラグインはアカウント間で共有されるため、同じフォルダで `claude --continue` を実行すると新しいアカウントで中断したところから再開できる。

アカウントが複数ある場合、パネルでは各アカウントの制限が横並びで表示され、アクティブなものに印が付く。デフォルトでは、アクティブアカウントが制限の95%を超えると Omarchy が通知し、通知をクリックすると最も余裕のあるアカウントに切り替わる。パネルでアカウントの行にホバーして Use の横に表示される Autoswitch をクリックする（または `m` を押す）、または `omarchy agent account mode auto` を実行すると自動で切り替わるようにできる。有効な間は Autoswitch が Use の代わりになり、再度クリックすると通知に戻る。数字を追加して閾値を変更でき、例えば `omarchy agent account mode auto 90` のようにする。すべてのアカウントが閾値を超えた場合、そのことと最初に空くアカウントが一度だけ通知される。アクティブアカウントが閾値から15ポイント以内にある間（デフォルトでは80%）、制限は15分ごとではなく3分ごとにチェックされる。

`omarchy agent account list` はすべてのアカウントと最新の制限を表示し、`omarchy agent account remove work` は1つを削除し、`omarchy agent account rename primary Hey` は名前を変更する（またはパネルでアカウント名をクリックする）。これらのコマンドはデフォルトエージェントのアカウントに対して動作する。別のプロバイダーにアクセスするには、先に名前を指定する。例えば `omarchy agent account use codex side` のようにする。`~/.claude` や `~/.codex` にすでにあったログインが _Main_ アカウントだ。Codex のものはそのままの場所に残る。Claude のものは別のアカウントがアクティブな間は専用フォルダで待機する。約8時間以上使われていないアカウントは _Sign-in required_ と表示されることがある。クリックするとパネルですぐにそのアカウントに再サインインできる。または切り替えてセッションを開始すると自動でサインインが更新される。`claude mcp add` で追加した MCP サーバーは、すべて `~/.claude` で実行されるためすべての Claude アカウントに届く。Codex と Grok では、アカウント追加時に持っていたサーバーはそのアカウントに引き継がれるが、後から追加したものは追加したアカウントにしか届かない。Claude Desktop は独自のサインインを保持し、CLI バイナリへの絶対パスで設定された Codex や Grok ツールは切り替えに従わない。明示的な `CLAUDE_CONFIG_DIR`、`CODEX_HOME`、`GROK_HOME` は選択されたアカウントより優先される。

### クラッシュ診断

Omarchy は systemd-coredump でプロセスクラッシュを監視する。何かがセグメンテーションフォルトを起こすと「Process crashed」通知が届く。クリックすると、クラッシュはデフォルトエージェントに渡され、Omarchy の diagnose-crash スキルも一緒に渡される。そのスキルは、コアダンプから事実を確立し、そのクラッシュを上流に報告する価値があるかどうかを判断する手順をエージェントに案内する。`coredumpctl list` の任意の PID に対して `omarchy agent crash <pid>` で手動で実行することもできる。

監視はデフォルトで有効だ。_Trigger > Toggle > Crash Capture_ で（または `omarchy toggle crash-capture` で）オフにすると通知は止まる。`omarchy agent crash <pid>` は手動では引き続き動作する。

クラッシュはプログラムごとに黙らせることもできる。それが診断の最後に提案されることだ。`omarchy crash mute hyprland` はそのプログラムだけの通知を止め、`omarchy crash mute hyprland off` で戻し、`omarchy crash mute` 単体ではミュートしたもの一覧を表示する。バイナリのパスでも名前でも同じように受け付けるため、`omarchy crash mute /usr/bin/hyprland` でも同じだ。スペースを含む名前は引用する。例えば `omarchy crash mute 'Some App'` のように。ほかのものはすべて通知され続け、ミュートしたプログラムもクラッシュし続ける。これはリマインダーを隠すだけで、何も修正しない。

### デスクトップアプリ

_Install > AI_ メニューにはグラフィカルな AI アプリもいくつかある。ChatGPT デスクトップアプリ、Claude デスクトップアプリ（Anthropic の Linux ベータ版で、Chat、Cowork、Claude Code タブ付き）、xAI のモデルとチャットする Grok Bot、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexity デスクトップアプリ、T3 Code だ。Grok Bot はデスクトップチャットアプリだ。コーディングエージェントは `grok` コマンドだ。

Hermes Desktop は知っておくべきものだ。マシンに1つしか Hermes はなく、それはアプリのものだからだ。Hermes は常にアプリ経由でのみインストールされ、デフォルトエージェントが実行する `hermes` コマンドはアプリのものだ。Hermes をデフォルトエージェントとして選ぶと、_Install > AI_ の項目と同じものがインストールされる。パッケージと、Hermes 自身のインストーラーによってセットアップされた `~/.hermes` 配下の Hermes ランタイムで、初回は数分かかる。そのランタイムが、ターミナルの `hermes` コマンド、デフォルトエージェント、アプリすべてが使う唯一の Hermes で、Omarchy リリースを待つのではなく `hermes update` で自身をアップデートする。インストールすると Hermes に Omarchy テーマが `omarchy` という名前のスキンとして渡され、すべての Hermes 画面がテーマ切り替えに追従する。そうしたくなければ、Hermes の Appearance 設定か `/skin` で別のものを選び、Omarchy はその選択をそのままにする。_Remove > AI_ でアプリを削除すると、まず gateway を含め Hermes を閉じ、そのランタイムも一緒に削除する。チャット、メモリ、Hermes が自身のために書いたスキルは、指示しない限り保持される。データと接続設定も削除するかどうかを聞かれ、デフォルトはいいえだ。

OpenClaw のデスクトップ体験は Control UI で、独自のローカル gateway をバックエンドとするウェブアプリとして開く。OpenClaw は `~/.openclaw` にあり、自身をアップデートする。Control UI の「Update Gateway」ボタンを使うか `openclaw update` を実行すると、gateway は新バージョンで再起動する。Omarchy は新規インストールが開始するリリースを選ぶだけだ。_Remove > AI_ で OpenClaw を削除すると gateway サービスとアプリが一緒に削除され、その後 `~/.openclaw` も削除するかどうかを聞かれる。そこにはチャットや認証情報とともに OpenClaw 本体やダウンロードしたプラグインランタイムが入っているからだ。デフォルトでは保持され、OpenClaw を再度インストールするとまた利用できる。

Herdr Desktop は [Herdr](https://herdr.dev) デスクトップアプリだ。ウィンドウを閉じてもコアで動き続けるターミナルとコーディングエージェントのスペース、タブ、ペインを持つ。パッケージではなく Herdr 自身のインストーラーから提供されるため、`~/.local/share/herdr-app` に置かれ、まだ持っていなければ `~/.local/bin/herdr-core` にコアも持ってきて、両方とも自身をアップデートする。Omarchy が `Super + Ctrl + Return` で提供する `herdr` コマンドを置き換えるのではなく、その横に置かれ、そのコマンドの直接キーを取得する。`Alt + Return` と `Alt + Shift + Return` でペインを下または右に分割し、`Alt + Escape` で閉じ、`Ctrl + Alt + Arrow` でペイン間を移動し、`Alt + 1..9` と `Alt + Left/Right` でタブを選び、`Alt + Up/Down` でスペース間を移動する。`Ctrl + 1..9` でスペースを選び、`Alt + Shift + Up/Down` でエージェントを順に移動する。`Ctrl + Space` プレフィックスキーはターミナル専用のままである。アプリはシーケンスのために通常の Ctrl キーを保持できないからだ。Omarchy はこれらを `~/.config/herdr-app/keys.json` に書き込み、`omarchy-refresh-herdr-app` で戻す。インストールすると Herdr の Omarchy テーマが選ばれ、以降は Omarchy テーマに追従する。Herdr はライトモード用とダークモード用に1つずつテーマを保持するため、ダークな Omarchy テーマとライトな Omarchy テーマを切り替えた後は、もう一方のモード用に Herdr のテーマピッカーで Omarchy をもう一度選ぶこと。

T3 Code はパッケージではなく、`~/.local/share/t3code` にある公式 AppImage リリースから実行され、自身をアップデートする。インストール時には Stable チャンネルで始めるか Nightly チャンネルで始めるかを聞かれる。後で T3 Code の設定で切り替えられる。スレッドと設定は `~/.t3` にあり、_Remove > AI_ で T3 Code を削除すると一緒に削除される。

### ローカルモデル

自分のマシンでオープンモデルを実行してコーディングエージェントに使う。プロンプトとコードはマシン上に留まり、モデルに送られたものはマシン外に出ない。以下から始める。

```bash
omarchy agent local use best
```

または、トップバーのエージェントパネルで + を選び、次に Local AI を選ぶ。これはモデルがこのマシンに合う場合に表示される。初回は、モデルを実行する Podman がインストールされ、NVIDIA マシンでは GPU を使えるようにする NVIDIA のコンテナツールキットもインストールされる。次に Omarchy がこのマシンに推奨されるモデルを選び、ダウンロードして開始する。数十 GB のダウンロードと、モデル実行中にマシンのメモリの大半が使われることを予想しておくこと。Flash Next はフル 256K コンテキストで約 100 GiB を使う。必要なメモリを他のモデルが占有している場合、停止状態でセットアップされ、1つ停止すれば開始できるようになる。モデルはログアウト時に停止する。他のことにメモリが必要になったら自分で停止すること。

`omarchy agent local list` は選択肢を表示し、一部が合わない理由を説明する。別のものをセットアップするには `omarchy agent local use <recipe>` を実行する。現在、128 GB Strix Halo マシン向けに `qwen3.8-flash-next-gufo` と `qwen3.8-27b-gufo` が利用可能だ。27B は約 40 GiB を使うため他の作業の余地が残る。Intel の Arc B390 を搭載した 64 GB ラップトップでは、`qwen3.6-35b-a3b-llamacpp` が約 30 GiB で実行される。新しいレシピと推奨はパッケージ経由で `omarchy update` とともに届く。

セットアップしたすべてのモデルは、サブスクリプションの隣にエージェントパネルで独自の行を持つ。再生で開始、停止で止めてメモリを解放し、ターミナルボタンでそのモデル上でエージェントを開く。メモリに収まれば複数を同時に実行できる。収まらなければ、Omarchy がどの実行中モデルを停止すべきかを知らせる。行をドラッグして並べ替え、選択した行で Delete を押すとモデルとそのダウンロードが削除される。

セットアップしたすべてのモデルはアプリランチャーにも独自の項目を持ち、モデル名とメーカーのロゴが付き、Claude、Codex、Grok にサインインしたときに項目が追加されるのと同じだ。そのモデル上でエージェントを開き、実行中でなければまずモデルを開始する。ターミナルで読み込みが表示され、準備できたらエージェントに渡される。モデルを削除するとその項目も削除される。

コマンドラインからは、`omarchy agent local start <recipe>` と `omarchy agent local stop <recipe>` が同じことをし、`omarchy agent local status` はすべてのモデルを表示し、`omarchy agent --local` は最後に開始したモデル上でデフォルトエージェントを開く。pi、OpenCode、Qwen Code は利用できる。その他のデフォルトの場合は pi で開く。pi はセットアップしたすべてのモデルと、ペアリングしたマシンのモデルも自身のモデルピッカーに一覧表示するため、通常の `pi` でもそこにアクセスできる。任意の OpenAI 互換クライアントも接続できる。`status` は各モデルのアドレスを表示し（最初は `http://127.0.0.1:11435/v1`）、レシピ名がモデルで、キーは `~/.config/omarchy/agent-local/key` にある。

`omarchy agent local remove <recipe>` はモデルと、他のモデルが使っていないダウンロードを削除する。

サードパーティ製ランタイムにはその発行元のラベルが付けられる。Omarchy はすべてのモデルをネットワークアクセスなしで実行する。

### ローカル LLM

Omarchy はローカル LLM モデルを実行する方法として LM Studio と Ollama の2つを推奨する。LM Studio はオープンウェイトモデルを見つけ、インストールし、実行するための GUI インターフェイスを提供する。簡単に始められる優れた方法だ。Ollama は同様のことを行う CLI を提供する。しかしローカルモデルが初めてなら、私なら LM Studio から始める。どちらも Omarchy Menu の _Install > AI_ でインストールできる。

### Omarchy スキル

エージェントスキルは AI が特定のツールを特定の方法で使うのを助ける。Omarchy にはシステムをカスタマイズするためのデフォルトスキルが同梱されている。Hyprland 設定を調整したり、バーを調整したり、ゼロから新しいテーマを作成したりといったことだ。これは Claude Code (`~/.claude/skills`)、Codex (`~/.codex/skills`)、Pi (`~/.pi/agent/skills`)、Antigravity (`~/.gemini/config/skills`)、Hermes (`~/.hermes/skills` と各 `~/.hermes/profiles/*/skills`)、汎用の `~/.agents/skills` のスキルディレクトリにシンボリックリンクされており、ほとんどのハーネスが自動で拾う。

しかしこのスキルは実験的なものとして扱うべきだ。モデルによって効果は異なる。まずプランモードで実行するのが最善だ。そうすればエージェントが何を変更したいか分かる。そして変更をロールバックしたり、エージェントがすべてを台無しにした場合は `omarchy reinstall configs` を実行したりする覚悟をしておくこと。
