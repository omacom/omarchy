# AI

### エージェントのインストールと更新

Hermes を除き、これらのエージェントは mise の遅延インストールを使う：初回の起動で CLI がインストールされ、以降の起動ではそれを再利用する。mise はインストール済みエージェントの新しいリリースもチェックするが、4時間に最大で一度だけ、起動の直前か、シェルプロンプトでバックグラウンドで行う。その更新が失敗したりオフラインだったりすれば、インストール済みのバージョンが動作する。`omarchy update` は Omarchy の残りと一緒にインストール済みエージェントを更新し、`mup` は mise 管理のツールだけを更新する。

`claude update`、`codex update`、アプリ内の更新ボタンといったエージェント自身のアップデーターは、mise 管理のインストールを更新しない。`codex update` は失敗するし、`claude update` は成功したと報告しながら、mise が追跡しない別コピーをインストールすることがある。代わりにエージェントのネイティブなインストーラーとアップデーターを使いたければ、それを `disable_tools` に追加すること；[プリインストールされた CLI ツール](18-development-tools.md#preinstalled-cli-tools) を参照。

必要になる前に、設定済みの遅延ツールをすべてインストールするには、`mise install --include-lazy` を実行する。これにはエージェントだけでなく、Omarchy の他のデフォルト CLI ツールも含まれる。単一ツールのインストールや独自のインストールを使う方法については、[プリインストールされた CLI ツール](18-development-tools.md#preinstalled-cli-tools) を参照。

`grok` は `claude` や `codex` と同じ方法で、mise のファーストパーティ `grok` パッケージ経由でインストールされる。`grok` を実行するか、_Setup > Defaults > Agent_ で選ぶこと。x.ai の `curl | bash` インストーラーは避けること。その方法では `~/.grok/bin` に2つ目のコピーが入って `PATH` の先頭にそれが追加され、Omarchy のラッパーが上書きされる。

`dsh` はブラウザ UI を `127.0.0.1:3080` で開き、起動ディレクトリをデフォルトのワークスペースとする。そのブラウザ UI は開始プロンプトを受け取らないため、`omarchy agent prompt` はプロンプトをクリップボードに載せた状態でこれを開き、貼り付けられるようにする。Omarchy は DeepSeek の承認不要の権限プリセットでこれを起動する。DeepSeek Harness は公式のモデル API を使うとセッションログを DeepSeek にアップロードする；そのブラウザ UI の _Settings > General > Upload Session Log_ でオフにすること。送信したフィードバックもセッションと一緒にアップロードされる。`DSH_TELEMETRY_MODE=DISABLED` で起動した場合は除く。

### デフォルトのエージェント

`omarchy default agent <name>` か、Omarchy Menu（`Super + Space`）の _Setup > Defaults > Agent_ で、デフォルトのエージェントを選ぶこと。エージェントがまだインストールされていなければ、選ぶことでまずインストールされる。新規の Omarchy では、一度限りの通知でこの選択を促される。

Claude を選ぶと、Chromium、Chrome、Brave、Brave Origin、Edge 用のブラウザ拡張機能の設定も試みる。拡張機能の設定はすべてのユーザーに適用され、システムのパスワードを求められることがある；キャンセルしたり拡張機能のインストールに失敗したりしても、Claude は選択され、起動する。ブラウザを再起動し、求められたら拡張機能を有効にして、Claude にサインインし、接続を完了させること。Claude で `/chrome` を実行して接続を確認すること。Firefox と Zen はこの拡張機能に対応していない。すでに Claude がデフォルトになっていて、この設定が追加される前だった場合は、もう一度選んで拡張機能をインストールすること。

選んだ後は、`Super + Shift + Ctrl + A` で専用のターミナルウィンドウにデフォルトのエージェントが起動する（まだ選んでいなければ、ピッカーが表示される）。`omarchy agent prompt "Review this project"` でタスクに直行させることもできる。Freebuff と DeepSeek Harness は開始プロンプトを受け取らないため、代わりにプロンプトをクリップボードに載せて開き、貼り付けられるようにする。この方法で起動したエージェントは、それぞれの止まって尋ねないモードで無人で動作する。だから本当に物事を実行してしまう心構えをしておくこと！MiniMax Code の対話セッションにはそうしたモードがないため、通常通り権限を求める。そして、エージェントはホームディレクトリに対する信頼を記憶することを拒否するため、`$HOME` からの起動は代わりに `~/Work` で始まる。

ターミナルのショートカットもある：`a` は現在のターミナルでデフォルトのエージェントをインラインで実行し、`c`、`cx`、`cy` は OpenCode、Claude Code、Codex を直接起動する（こちらも自動承認モードで）。テーマの変更もエージェントに同期される：Claude Code、Pi、OpenCode、Hermes（Omarchy がインストールした後）は、Omarchy のテーマを切り替えるとそれに追従する。

### エージェントパネル

トップバーにはエージェントのアイコンがある。エージェントをまだ設定していない場合、そのパネルが Claude、Codex、Grok のいずれかへのサインインを順に案内し、最初の一つがデフォルトのエージェントになる。その後は、そのパネルがすべてのサブスクリプションを1ページにまとめる：各エージェントとアカウントとそのプラン、それぞれの5時間セッション制限と週間制限のメーターとリセットまでの時間（ホバーすると正確なパーセンテージが表示される）、あるいはプリペイドの残高が、全エージェント横断で使ったもの（今週のトークン数や最もよく使ったモデルなど）を順に切り替えて表示する行の下に並ぶ。_Make something_ の下では、新しいテーマ、プラグイン、アプリのためのスタータープロンプトが提示され、タスクをデフォルトのエージェントに渡す。アプリは Omarchy 自身の Hype、Monologue、Omacut と同じように、C++ と Qt Quick で、omarchy-app エージェントスキルに従って作られる。必要なコンパイラと Qt の部品はインストール済みで付いてくる。Claude Code、Codex、Grok、Kimi、Cursor とその Grok Bot の枠、GitHub Copilot、Muse、Antigravity、Kimchi、Devin は、制限とともに最初から対応しているし、Hermes、Mistral Vibe、Qwen Code は一度使うとセッションとトークンを表示する。pi、omp、opencode 経由で使うプロバイダーのプランとキーも表示される：制限とともに OpenCode Zen と Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan、Synthetic；プリペイドの残高とともに Fireworks、OpenRouter、DeepSeek；そして自分のハードウェアで動かすモデルは Local models の下に。すべてのエージェントは、請求元のもとで一度だけ数えられる。いくつのハーネス経由で動かしても同じだ。

バーアイコンを左クリックするとパネルが開き、右クリックするとデフォルトのエージェントが起動する。その背後にある使用記録は `omarchy agent usage-update` によって15分ごとに再生成され、パネルは同期フォルダ経由で他のマシンからの使用状況をマージすることさえできる。完全な設定については、`$OMARCHY_PATH/shell/plugins/agents/` にある README を参照。

### 複数のサブスクリプション

Claude、Codex、Grok のプランを複数契約している場合—たとえば個人の Max と仕事用の一つ—Omarchy はすべてをサインインしたままにして、その間を移動できる。エージェントパネルの + でサブスクリプションを追加すると、その場で手順を案内してくれる。または `omarchy agent account add claude Work`（`codex` でも `grok` でも）を使うこと。CLI がなければインストールされる。プロバイダーごとの最初のアカウントは、CLI がいつも参照する場所で、通常のブラウザ経由でサインインする。それ以降のものはすべてプライベートウィンドウ経由でサインインする。だからブラウザですでにサインインしているアカウントが間違って拾われることはない；そこで、追加しようとしているアカウントとしてサインインすること。そして、すでに開いているプライベートウィンドウがあれば、先に閉じておくこと。このために CLI から絶対にログアウトしないこと：ログアウトすると保存されたサインインが失効し、そのアカウントは改めて追加しなければならなくなる。

SSH 経由で別の Omarchy マシンにサブスクリプションのログインをコピーするには、`omarchy agent account copy user@laptop` を実行する。送信側は、宛先に受信側がインストールされていない場合、一時的な受信側を提供する。だから古い Omarchy マシンでも更新なしでアカウントを受け取れる。インストール済みの受信側が優先される。これは Claude、Codex、Grok のすべてのサブスクリプションをコピーする；`omarchy agent account copy laptop claude` のようにプロバイダー名を追加して選択すること。アカウント名とコマンド ID は送信元と一致し、宛先にすでに存在するアカウントも含まれる。無関係な宛先のアカウントは、名前が競合すれば数値の接尾辞を受け取る。設定、スキル、プラグイン、会話履歴は各マシンにローカルなまま残る。

宛先に既存の認証情報は保持される。送信元のアカウントがすでにそこでサインインしている場合、その名前は同期されるが、認証情報は置き換えられない；他のアカウントはその横に追加される。一致するアカウントの保存済み認証情報を置き換えるには、宛先でそのアカウントのセッションを終了した後、`omarchy agent account copy --replace laptop claude` を使うこと。まっさらな宛先は、送信元のアクティブなアカウントと切り替えの好みも受け取る；確立済みの宛先は自分のものを保持する。

認証情報は SSH を通って移動し、宛先のプライベートファイルに保存される。だから信頼するマシンにだけコピーすること。これは一度限りのコピーであり、継続的な同期ではない。Codex のリフレッシュトークンは別のマシンによってローテーションされることがあり、コピーしたログインが更新を必要とする状態になることがある；複数のマシンで同時に使うには、別々のサインインが最も確実な選択だ。[Codex のアカウント認証ガイダンス](https://developers.openai.com/codex/auth/ci-cd-auth) を参照。

プロバイダーごとにアクティブなのは1アカウントだけで、すべての新しいセッションはそれで始まる：`cx`、`cy`、素の `claude`、`codex`、`grok`、`omarchy agent` 経由で起動されるものすべて、そして `PATH` 上で CLI を見つけるスクリプトやエディタも。`omarchy agent account use work` で切り替え（`omarchy agent account use main` で戻す）、またはパネルでアカウントの番号を押してから `Enter` を押す（あるいは Use ボタンをクリックする）。すでに実行中のセッションは、開始したアカウントのままになる。会話履歴、設定、スキル、プラグインはアカウント間で共有される。だから同じフォルダで `claude --continue` とすれば、新しいアカウントでも中断した場所から再開できる。

アカウントが複数あると、パネルは各アカウントの制限を並べて表示し、アクティブなものに印が付く。デフォルトでは、アクティブなアカウントが制限の95%を超えると通知され、通知をクリックすると最も余裕のあるアカウントへ切り替わる。パネルでアカウントの行にホバーして Use の横に現れる Autoswitch をクリックする（または `m` を押す）、あるいは `omarchy agent account mode auto` を実行すると、代わりに自動で切り替わるようになる；オンの間は Autoswitch が Use の代わりに表示され、もう一度クリックすると通知に戻る。`omarchy agent account mode auto 90` のように数値を追加して閾値を変更すること。すべてのアカウントが閾値を超えている場合は、そのことと、最も早く空くアカウントが一度だけ通知される。アクティブなアカウントが閾値まで15ポイント以内（デフォルトでは80%）にある間、その制限は15分ごとではなく3分ごとにチェックされる。

`omarchy agent account list` はすべてのアカウントと最新の制限を表示し、`omarchy agent account remove work` は一つを忘れ、`omarchy agent account rename primary Hey` は名前を変更する（またはパネルでアカウント名をクリックする）。これらのコマンドはデフォルトのエージェントのアカウントに対して動作する；他のプロバイダーに届くには、まずその名前を指定すること。たとえば `omarchy agent account use codex side`。`~/.claude` や `~/.codex` にすでにあったログインは _Main_ アカウントであり、そのままの場所に残る。約8時間以上使われていないアカウントは _Sign-in required_ と表示されることがある；クリックすればそのアカウントへのサインインをパネルですぐにやり直せるし、そのアカウントでセッションを開始すればサインインが自動で更新される。アカウント追加時にあった MCP サーバーはそのアカウントにも引き継がれるが、後から `claude mcp add` で追加したものは、追加したアカウントにしか届かない。Claude Desktop や、CLI バイナリへの絶対パスで設定されたツールは、切り替えに追従しない。明示的な `CLAUDE_CONFIG_DIR`、`CODEX_HOME`、`GROK_HOME` は、選択したアカウントより優先される。

### クラッシュ診断

Omarchy は systemd-coredump を使ってプロセスのクラッシュを監視している。何かが segfault すると、"Process crashed" という通知を受け取る—それをクリックすると、クラッシュは Omarchy の diagnose-crash スキルとともにデフォルトのエージェントに渡される。そのスキルは、コアダンプから事実を確立し、そのクラッシュがアップストリームに報告する価値があるかどうかを判断する手順をエージェントに案内する。`coredumpctl list` にある任意の PID に対して `omarchy agent crash <pid>` で手動で実行することもできる。

監視はデフォルトでオンだ。_Trigger > Toggle > Crash Capture_ でオフにする（または `omarchy toggle crash-capture` を使う）と通知は止まる；`omarchy agent crash <pid>` は手動では引き続き使える。

クラッシュはプログラムごとに個別に黙らせることもでき、診断が最後に提示するのはそれだ。`omarchy crash mute hyprland` はそのプログラムだけの通知を止め、`omarchy crash mute hyprland off` で元に戻し、`omarchy crash mute` を単独で実行するとミュートしたものの一覧が表示される。バイナリのパスでも名前と同じように受け付けるので、`omarchy crash mute /usr/bin/hyprland` でも同じになる。スペースを含む名前は、`omarchy crash mute 'Some App'` のように引用すること。他のものはすべて通知され続け、ミュートしたプログラムもクラッシュし続ける—これはリマインダーを隠すだけで、何も直さない。

### デスクトップアプリ

_Install > AI_ メニューにはグラフィカルな AI アプリもいくつか入っている：ChatGPT デスクトップアプリ、Claude デスクトップアプリ（Chat、Cowork、Claude Code のタブを備えた Anthropic の Linux ベータ）、xAI のモデルとチャットするための Grok Bot、Hermes Desktop、OpenClaw、Perplexity デスクトップアプリ、T3 Code だ。Grok Bot はデスクトップのチャットアプリだ。コーディングエージェントは `grok` コマンドだ。

Hermes Desktop は知っておくべきものだ。なぜなら1台のマシンに Hermes は一つしかなく、それはアプリのものだからだ：Hermes はアプリ経由でしかインストールされたことがなく、デフォルトのエージェントが実行する `hermes` コマンドはアプリのものだ。Hermes をデフォルトのエージェントとして選ぶと、_Install > AI_ の項目がするのと同じものがインストールされる：そのパッケージと、Hermes 自身のインストーラーが設定する `~/.hermes` 配下の Hermes ランタイムであり、初回は数分かかる。そのランタイムは、ターミナルの `hermes` コマンド、デフォルトのエージェント、アプリのすべてが使う唯一の Hermes であって、Omarchy のリリースを待たずに `hermes update` で自身を更新する。インストールすると、Hermes に Omarchy のテーマが `omarchy` という名前のスキンとして渡され、Hermes のあらゆる画面がテーマの切り替えに追従する；そうしたくなければ、Hermes の Appearance 設定か `/skin` で別のものを選ぶこと。その選択は Omarchy がそのままにしておく。_Remove > AI_ でアプリを削除すると、まず Hermes が（gateway も含め）閉じられ、そのランタイムも一緒に削除される。チャット、メモリ、Hermes が自身のために書いたスキルは、そう指示しない限り保持される：そのデータと接続設定も削除するかどうかを尋ね、デフォルトは no だ。

OpenClaw のデスクトップ体験は、その Control UI だ。これは自身のローカルな gateway をバックエンドとする web アプリとして開く。OpenClaw は `~/.openclaw` に収まっており、自身を更新する：Control UI の "Update Gateway" ボタンを使うか、`openclaw update` を実行すると、gateway は新しいバージョンで再起動する。Omarchy が選ぶのは、新規インストールがどのリリースから始まるかだけだ。_Remove > AI_ で OpenClaw を削除すると gateway サービスとアプリも一緒に削除され、その後 `~/.openclaw` も削除するかどうかを尋ねる。そこには OpenClaw 自身やダウンロードするプラグインランタイムとともに、チャットと認証情報が入っているからだ；デフォルトでは保持され、OpenClaw を再インストールすれば再び拾われる。

T3 Code はパッケージからではなく、`~/.local/share/t3code` にある公式の AppImage リリースから動作するため、自身を更新する。インストール時に、Stable チャンネルで始めるか Nightly チャンネルで始めるかを尋ねられる；後から T3 Code の設定で切り替えること。スレッドと設定は `~/.t3` にあり、_Remove > AI_ で T3 Code を削除するとそれらも一緒に削除される。

### ローカルモデル

自分のマシンでオープンモデルを動かして、コーディングエージェントに使おう。プロンプトとコードはマシンに留まる；モデルに送ったものは何もそこから出ていかない。まずはこれで始めること：

```bash
omarchy agent local use best
```

または、トップバーのエージェントパネルで + を選び、続いて Local AI を選ぶこと。これは、このマシンにモデルが収まる場合に表示される。初回は、モデルを実行する Podman がインストールされ、NVIDIA のマシンではモデルに GPU を使わせる NVIDIA のコンテナツールキットもインストールされる。続いて Omarchy はこのマシンに推奨されるモデルを選び、ダウンロードし、起動する。数十 GB のダウンロードと、モデル動作中はマシンのメモリの大半が使用されることを覚悟すること：Flash Next は完全な 256K コンテキストで約 100 GiB を使う。必要なメモリを他のモデルが占有している場合は、停止状態でセットアップされるので、そのうち一つを止めれば起動できる。モデルはログアウト時に停止する；他の用途にメモリが必要になったときは、自分で止めること。

`omarchy agent local list` は選択肢を表示し、一部が収まらない理由を説明する。別のものをセットアップするには、`omarchy agent local use <recipe>` を実行する。現在、128 GB の Strix Halo マシン向けに `qwen3.8-flash-next-halogen` と `qwen3.8-27b-gufo` が利用できる。新しいレシピと推奨は `omarchy update` でパッケージ経由で届く。

セットアップしたモデルごとに、サブスクリプションの隣に、エージェントパネルに専用の行ができる：再生で起動し、一時停止で止めてメモリを解放し、ターミナルボタンでそのモデル上でエージェントを開く。メモリに一緒に収まれば、複数を同時に動かせる；収まらない場合は、どの実行中のモデルを止めるべきかを Omarchy が伝える。行をドラッグして並び替え、選択した行で Delete を押すと、そのモデルとそのダウンロードが削除される。

コマンドラインからも、`omarchy agent local start <recipe>` と `omarchy agent local stop <recipe>` が同じことをし、`omarchy agent local status` はすべてのモデルを表示し、`omarchy agent --local` は最後に起動したモデル上でデフォルトのエージェントを開く（デフォルトのエージェントがローカルモデルを使えない場合は pi）。OpenAI 互換の任意のクライアントも接続できる：`status` が各モデルのアドレスを表示し（最初のものは `http://127.0.0.1:11435/v1`）、レシピ名がモデルとなり、キーは `~/.config/omarchy/agent-local/key` にある。

`omarchy agent local remove <recipe>` はモデルと、他のモデルが使っていないダウンロードを削除する。

サードパーティのランタイムには、そのパブリッシャーが表示される。Omarchy はすべてのモデルをネットワークアクセスなしで実行する。

### ローカル LLM

Omarchy はローカル LLM モデルを実行する2つの方法を推奨している：LM Studio と Ollama だ。LM Studio は、オープンウェイトモデルを見つけてインストールし、実行するための GUI インターフェースを提供する。手軽に始めるには素晴らしい方法だ。Ollama も同様のことができる CLI を提供する。しかしローカルモデルが初めてなら、私は LM Studio から始める。どちらも Omarchy Menu の _Install > AI_ でインストールできる。

### Omarchy スキル

エージェントスキルは、AI が特定のツールを特定の方法で使う助けをするものだ。そして Omarchy には、システムをカスタマイズするためのデフォルトスキルが付属している。Hyprland 設定を調整したり、バーを直したり、ゼロから新しいテーマを作ったりするようなことだ。これは Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` と各 `~/.hermes/profiles/*/skills`）、汎用の `~/.agents/skills` の各場所にあるスキルディレクトリへシンボリックリンクされているため、ほとんどのハーネスが自動的に拾う。

しかし、このスキルは実験的なものとして扱うべきだ。モデルごとに使い方の効果は異なる。最初は plan mode で実行するのが最善だ。そうすれば、エージェントが何を変更しようとしているのかが分かる。そして変更をロールバックしたり、エージェントがすべてを台無しにした場合は `omarchy reinstall configs` を呼び出したりする覚悟をしておくこと。
