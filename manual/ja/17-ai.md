### エージェントのインストールと更新

Hermes を除き、これらのエージェントは mise の遅延インストールを使います。初回起動時に CLI がインストールされ、以降の起動ではそれが再利用されます。mise はまた、インストール済みのエージェントに新しいリリースがないかを、最大で4時間に1回、起動する直前か、シェルのプロンプトでバックグラウンドでチェックします。その更新に失敗したり、オフラインだったりした場合は、インストール済みのバージョンが動作します。`omarchy update` は、インストール済みのエージェントを Omarchy の残りの部分と一緒に更新します。`mup` は mise が管理するツールだけを更新します。

エージェント自身のアップデーター、たとえば `claude update`、`codex update`、アプリ内の更新ボタンなどは、mise が管理するインストールを更新しません。`codex update` は失敗しますし、`claude update` は成功したと報告しながら、mise が追跡しない別コピーをインストールすることがあります。エージェント本来のインストーラーとアップデーターを使いたい場合は、それを `disable_tools` に追加してください。[プリインストールされた CLI ツール](18-development-tools.md#preinstalled-cli-tools) を参照してください。

必要なものすべてを事前にまとめてインストールしておくには、`mise install --include-lazy` を実行してください。これにはエージェントだけでなく、Omarchy の他のデフォルト CLI ツールも含まれます。単一のツールをインストールしたり、自分のインストールを使ったりする方法については [プリインストールされた CLI ツール](18-development-tools.md#preinstalled-cli-tools) を参照してください。

`grok` は、`claude` や `codex` と同じように、mise のファーストパーティ `grok` パッケージ経由でインストールされます。`grok` を実行するか、_Setup > Defaults > Agent_ で選んでください。x.ai の `curl | bash` インストーラーは使わないでください。その方法だと `~/.grok/bin` に2つ目のコピーが置かれ、`PATH` の先頭にそれが追加され、Omarchy の wrapper が上書きされてしまいます。

`dsh` はブラウザー UI を `127.0.0.1:3080` で開き、起動したディレクトリーをデフォルトのワークスペースとします。そのブラウザー UI は開始プロンプトを受け取れないので、`omarchy agent prompt` は、プロンプトをクリップボードに入れた状態でそれを開き、貼り付けられるようにします。Omarchy は DeepSeek の承認なし権限プリセットでこれを起動します。DeepSeek Harness は、公式モデル API を使うとセッションログを DeepSeek にアップロードします。ブラウザー UI の _Settings > General > Upload Session Log_ でこれをオフにしてください。あなたが送信したフィードバックもセッションと一緒にアップロードされます。ただし、`DSH_TELEMETRY_MODE=DISABLED` で起動した場合は除きます。

### デフォルトエージェント

デフォルトエージェントは `omarchy default agent <name>` で選ぶか、Omarchy Menu（`Super + Space`）の _Setup > Defaults > Agent_ で選んでください。そのエージェントがまだインストールされていなければ、選んだ時点でまずインストールされます。新しい Omarchy では、この選択を一度だけの通知で促します。

Claude を選ぶと、Chromium、Chrome、Brave、Brave Origin、Edge 用のブラウザー拡張機能のセットアップも試みます。この拡張機能のセットアップはすべてのユーザーに適用され、システムパスワードを求められることがあります。キャンセルしたり、拡張機能のインストールに失敗したりしても、Claude は選ばれ、起動します。ブラウザーを再起動し、求められたら拡張機能を有効にし、Claude にサインインして接続を完了させてください。Claude で `/chrome` を実行すれば接続を確認できます。Firefox と Zen はこの拡張機能に対応していません。もしこのセットアップが追加される前から Claude がすでにデフォルトだった場合は、その拡張機能をインストールするためにもう一度選んでください。

選んだ後は、`Super + Shift + Ctrl + A` で、デフォルトエージェントが専用のターミナルウィンドウで起動します（まだ選んでいない場合はピッカーが表示されます）。`omarchy agent prompt "Review this project"` のようにすれば、そのままタスクに取りかからせることもできます。Freebuff と DeepSeek Harness は開始プロンプトを受け取れないので、その代わりプロンプトがクリップボードに入った状態で開きます。このように起動されたエージェントは、それぞれの、立ち止まって尋ねないモードで無人で動作します。本当に色々やってしまいますので、そのつもりでいてください！ MiniMax Code には対話セッション用のそのようなモードがないので、通常どおり権限を求めます。そして、エージェントはホームディレクトリーへの信頼を覚えることを拒否するので、`$HOME` から起動した場合は、代わりに `~/Work` で開始します。

ターミナルのショートカットもあります。`a` は現在のターミナルでインラインにデフォルトエージェントを実行し、`c`、`cx`、`cy` は OpenCode、Claude Code、Codex を直接起動します（こちらも自動承認モードです）。テーマの変更もエージェントに同期されます。Claude Code、Pi、OpenCode、そして Hermes（Omarchy がインストールした後は）は、Omarchy のテーマを切り替えると一緒に追従します。

### エージェントパネル

トップバーにはエージェントのアイコンがあります。まだエージェントをセットアップしていない場合、そのパネルは Claude、Codex、Grok へのサインインを案内し、最初に設定したものがデフォルトエージェントになります。その後は、パネルはすべてのサブスクリプションを1ページにまとめます。各エージェントとアカウントとそのプラン、5時間のセッション制限と週間制限それぞれのメーターとリセットまでの時間（ホバーすると正確なパーセントが表示されます）、またはプリペイド残高が、全エージェントを通して使った内容、たとえば今週のトークン数や最もよく使ったモデルなどを巡回表示する行の下に並びます。_Make something_ の下では、新しいテーマ、プラグイン、アプリを作るためのスタータープロンプトが用意され、それらのタスクをデフォルトエージェントに引き渡します。アプリは Omarchy 自身の Hype、Monologue、Omacut と同じやり方で、C++ と Qt Quick で構築され、omarchy-app エージェントスキルに従います。必要なコンパイラーと Qt の部品はインストール済みです。Claude Code、Codex、Grok、Kimi、Cursor とその Grok Bot の許容量、GitHub Copilot、Muse、Antigravity、Kimchi、Devin は、制限付きで最初からカバーされています。Hermes、Mistral Vibe、Qwen Code は、一度使えばセッションとトークンが表示されます。pi、omp、opencode 経由で使うプロバイダープランとキーも表示されます。OpenCode Zen と Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan、Synthetic はそれらの制限とともに、Fireworks、OpenRouter、DeepSeek はプリペイド残高とともに、そして自分で所有するハードウェアで実行するモデルは Local models の下に表示されます。すべてのエージェントは、請求元のもとで1回だけ数えられます。いくつの harness 経由でそれを動かしても同じです。

バーのアイコンを左クリックするとパネルが開き、右クリックするとデフォルトエージェントが起動します。その背景にある使用記録は、`omarchy agent usage-update` によって15分ごとに再生成され、パネルは同期フォルダーを介して他のマシンからの使用状況をマージすることもできます。すべての設定については、`$OMARCHY_PATH/shell/plugins/agents/` にある README を参照してください。

### 複数のサブスクリプション

複数の Claude、Codex、Grok のプランに料金を支払っている場合、たとえば個人の Max と仕事用プランがある場合、Omarchy はそのすべてにサインインした状態を保ち、それらを行き来できます。サブスクリプションは、エージェントパネルの + から追加でき、その場で案内してくれます。または `omarchy agent account add claude Work`（あるいは `codex` や `grok`）でも追加できます。CLI が欠けていればインストールされます。プロバイダーの最初のアカウントは、通常のブラウザー経由で、CLI がいつも確認するその場所でサインインします。それ以降のすべてのアカウントはプライベートウィンドウ経由でサインインするので、ブラウザーですでにサインインしているアカウントが誤って選ばれることはありません。そこでは、追加しようとしているアカウントとしてサインインし、すでに開いているプライベートウィンドウがあれば先に閉じてください。このために CLI からログアウトしてはいけません。ログアウトすると保存されたサインインが無効になり、そのアカウントは再度追加し直さなければならなくなります。

サブスクリプションのログインを SSH 経由で別の Omarchy マシンにコピーするには、`omarchy agent account copy user@laptop` を実行してください。送信先に受信側がインストールされていない場合、送信側が一時的な受信側を提供するので、古い Omarchy マシンでも更新なしにアカウントを受け取れます。インストール済みの受信側が優先されます。これにより、Claude、Codex、Grok のすべてのサブスクリプションがコピーされます。選択する場合はプロバイダー名を追加してください。たとえば `omarchy agent account copy laptop claude` のようにします。アカウント名とコマンド ID は、宛先にもうすでに存在するアカウントを含め、ソース側と一致します。無関係な宛先アカウントで名前が衝突する場合は数値の接尾辞が付き、設定、スキル、プラグイン、会話履歴は各マシンにローカルなままとどまります。

宛先にある既存の認証情報は保持されます。すでにそこでサインインしているソースアカウントは、その認証情報を置き換えることなく名前が同期されます。他のアカウントはその横に追加されます。一致するアカウントの保存済み認証情報を置き換えるには、宛先でそのアカウントのセッションを終了した後、`omarchy agent account copy --replace laptop claude` を使ってください。未使用の宛先は、ソース側のアクティブなアカウントと切替の好みも受け継ぎます。設定済みの宛先は自身のものを保持します。

認証情報は SSH 経由で移動し、宛先のプライベートファイルに保存されるので、信頼できるマシンにのみコピーしてください。これは一度だけのコピーであり、継続的な同期ではありません。Codex のリフレッシュトークンは別のマシンによってローテーションされることがあり、コピーしたログインは更新が必要な状態になることがあります。複数マシンで同時に使うには、別々にサインインするのがやはり最も確実な選択です。[Codex のアカウント認証ガイダンス](https://developers.openai.com/codex/auth/ci-cd-auth) を参照してください。

プロバイダーごとに1つのアカウントがアクティブとなり、すべての新しいセッションはそのアカウントで開始します。`cx`、`cy`、素の `claude`、`codex`、`grok`、`omarchy agent` 経由で起動したものすべて、`PATH` 上で CLI を見つけるスクリプトやエディターもそうです。切り替えは `omarchy agent account use work`（戻す場合は `omarchy agent account use main`）で行うか、パネルでアカウントの番号を押し、次に `Enter` を押す（またはその Use ボタンをクリックする）ことで行います。すでに動作しているセッションは、開始したときのアカウントのままです。会話履歴、設定、スキル、プラグインはアカウント間で共有されるので、同じフォルダーでの `claude --continue` は、新しいアカウントで中断したところから続けられます。

複数のアカウントがあると、パネルは各アカウントの制限を並べて表示し、アクティブなものにマークが付きます。デフォルトでは、アクティブなアカウントが制限の95％を超えると Omarchy が通知し、その通知をクリックすると、最も余裕のあるアカウントに切り替わります。自動で切り替えるようにするには、パネルでアカウントの行にホバーして、Use のそばに表示される Autoswitch をクリックする（または `m` を押す）か、`omarchy agent account mode auto` を実行してください。有効な間は、Autoswitch が Use の代わりとなり、もう一度クリックすると通知のみに戻ります。たとえば `omarchy agent account mode auto 90` のように、数値を追加するとしきい値を変更できます。すべてのアカウントがしきい値を超えている場合は、一度だけその旨が通知され、どのアカウントが最初に空くかも示されます。アクティブなアカウントがしきい値から15ポイント以内にある間（デフォルトでは80％）、その制限は15分ごとではなく3分ごとにチェックされます。

`omarchy agent account list` はすべてのアカウントとその最新の制限を表示し、`omarchy agent account remove work` は1つを忘れ、`omarchy agent account rename primary Hey` は1つの名前を変更します（またはパネルでアカウント名をクリックします）。これらのコマンドはデフォルトエージェントのアカウントに対して動作します。もう一方のプロバイダーにアクセスするには、先に名前を指定してください。たとえば `omarchy agent account use codex side` のようにします。`~/.claude` や `~/.codex` にすでに持っていたログインは _Main_ アカウントであり、そのままその場所にとどまります。約8時間以上使われなかったアカウントは _Sign-in required_ と表示されることがあります。クリックしてパネル内でそのアカウントに再度サインインするか、そのアカウントでセッションを開始してください。後者だと自動的にサインインが更新されます。アカウントが追加された時点で持っていた MCP サーバーはそのアカウントに付いてきますが、後で `claude mcp add` で追加したものは、追加したアカウントのみに届きます。Claude Desktop と、CLI バイナリーへの絶対パスで構成されたツールは切り替えに追従しません。明示的な `CLAUDE_CONFIG_DIR`、`CODEX_HOME`、`GROK_HOME` は、選択されたアカウントより優先されます。

### クラッシュ診断

Omarchy は systemd-coredump でプロセスクラッシュを監視します。何かが segfault すると、「Process crashed」という通知が届きます。それをクリックすると、クラッシュはデフォルトエージェントに引き渡され、Omarchy の diagnose-crash スキルも一緒に渡されます。そのスキルは、core dump から事実を立証し、そのクラッシュを upstream に報告する価値があるかどうかを決める手順を、エージェントに案内します。`coredumpctl list` の任意の PID に対して、`omarchy agent crash <pid>` で手動で実行することもできます。

監視はデフォルトでオンです。_Trigger > Toggle > Crash Capture_ でオフにする（または `omarchy toggle crash-capture` を使う）と通知は止まります。`omarchy agent crash <pid>` は手動では引き続き動作します。

クラッシュはプログラムごとに黙らせることもでき、それは診断の最後に提示されるものです。`omarchy crash mute hyprland` を使うと、そのプログラムに対する通知だけが止まります。`omarchy crash mute hyprland off` で元に戻り、`omarchy crash mute` を単独で使うと、何をミュートしたかが一覧表示されます。バイナリーのパスでも名前でも同様に受け付けるので、`omarchy crash mute /usr/bin/hyprland` でも同じことです。スペースを含む名前は、たとえば `omarchy crash mute 'Some App'` のように引用してください。他のすべてのものは引き続き通知されますし、ミュートされたプログラムは引き続きクラッシュします。これはリマインダーを隠すだけであり、何も直しません。

### Desktop apps

_Install > AI_ メニューには、いくつかのグラフィカル AI アプリも入っています。ChatGPT desktop app、Claude desktop app（Chat、Cowork、Claude Code のタブを備えた Anthropic の Linux beta）、xAI のモデルとチャットするための Grok Bot、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexity desktop app、T3 Code です。Grok Bot がデスクトップチャットアプリです。コーディングエージェントは `grok` コマンドです。

Hermes Desktop については知っておく必要があります。1台のマシンには Hermes は1つだけあり、それはアプリのものだからです。Hermes がインストールされるのは常にアプリ経由のみであり、デフォルトエージェントが実行する `hermes` コマンドはアプリのものです。Hermes をデフォルトエージェントとして選ぶと、_Install > AI_ の項目と同じものがインストールされます。つまりパッケージと、Hermes 自身のインストーラーがセットアップする `~/.hermes` 配下の Hermes ランタイムで、初回は数分かかります。そのランタイムは、ターミナルの `hermes` コマンド、デフォルトエージェント、アプリがすべて使う、唯一の Hermes であり、Omarchy のリリースを待たずに `hermes update` で自ら更新します。インストールすると、Hermes には Omarchy テーマが `omarchy` という名前のスキンとして渡され、すべての Hermes の表面はテーマを切り替えるたびにそれに追従します。そうしたくない場合は、Hermes の Appearance 設定で、または `/skin` で別を選んでください。Omarchy はその選択には干渉しません。_Remove > AI_ でアプリを削除すると、まず gateway を含めて Hermes が閉じられ、そのランタイムも一緒に削除されます。チャット、メモリ、Hermes が自ら書いたスキルは、あなたが別の指示をしない限り保持されます。そのデータと接続設定も一緒に削除するかどうかを尋ねますが、デフォルトは「いいえ」です。

OpenClaw のデスクトップ体験は Control UI であり、自身のローカル gateway をバックエンドにウェブアプリとして開きます。OpenClaw は `~/.openclaw` にあり、自ら更新します。Control UI の「Update Gateway」ボタンを使うか `openclaw update` を実行してください。gateway は新しいバージョンで再起動します。Omarchy が決めるのは、初回インストールがどのリリースから始まるかだけです。_Remove > AI_ で OpenClaw を削除すると、gateway サービスとアプリが一緒に削除されます。その後、`~/.openclaw` も削除するかどうかを尋ねます。そこには OpenClaw 自体やダウンロードするプラグインランタイムと一緒に、チャットや認証情報が保存されているからです。デフォルトは保持であり、OpenClaw を再度インストールすればそれらを取り戻します。

Herdr Desktop は [Herdr](https://herdr.dev) のデスクトップアプリです。ターミナルとコーディングエージェントのスペース、タブ、ペインが含まれ、ウィンドウを閉じてもそのコアで実行し続けます。これはパッケージからではなく Herdr 自身のインストーラーから入ってくるので、`~/.local/share/herdr-app` にあり、まだ持っていない場合は `~/.local/bin/herdr-core` にコアも持ってきて、その両方を自ら更新します。これは、`Super + Ctrl + Return` で Omarchy が提供する `herdr` コマンドを置き換えるものではなく、その横に置かれるものであり、そのコマンドの直接キーを受け継ぎます。`Alt + Return` と `Alt + Shift + Return` はペインを下または右に分割し、`Alt + Escape` はそれを閉じ、`Ctrl + Alt + Arrow` はペイン間を移動し、`Alt + 1..9` と `Alt + Left/Right` はタブを選び、`Alt + Up/Down` はスペース間を移動します。`Ctrl + 1..9` はスペースを選び、`Alt + Shift + Up/Down` はエージェントを順に切り替えます。`Ctrl + Space` のプリフィックスキーはターミナル専用のままです。アプリはシーケンスのため素の Ctrl キーを保持できないからです。Omarchy はこれらを `~/.config/herdr-app/keys.json` に書き込み、`omarchy-refresh-herdr-app` がそれらを元に戻します。インストールすると Herdr の Omarchy テーマが選ばれ、以後はあなたの Omarchy テーマに追従します。Herdr は light mode 用に1つ、dark mode 用に1つのテーマを保持するので、dark な Omarchy テーマと light な Omarchy テーマの切り替えを行った後は、もう一方のモード用に Herdr のテーマピッカーでもう一度 Omarchy を選んでください。

T3 Code は、パッケージからではなく、`~/.local/share/t3code` にある公式 AppImage リリースから動作するので、自ら更新します。インストールすると、Stable チャンネルで開始するか、Nightly チャンネルで開始するかを尋ねます。後に T3 Code の設定で切り替えてください。あなたのスレッドと設定は `~/.t3` にあり、_Remove > AI_ で T3 Code を削除するとそれらも一緒に削除されます。

### ローカルモデル

コーディングエージェント用に、自分のマシンでオープンなモデルを実行してください。あなたのプロンプトとコードはそのマシンに残ります。モデルに送信されるものがそこから外に出ることはありません。まず以下のものから始めてください。

```bash
omarchy agent local use best
```

あるいは、トップバーのエージェントパネルで + を選び、次に Local AI を選んでください。これはこのマシンに適したモデルがある場合に表示されます。初回は、モデルを実行する Podman がインストールされ、NVIDIA マシンでは、モデルに GPU を与える NVIDIA の container toolkit がインストールされます。次に Omarchy はこのマシンに推奨されるモデルを選び、ダウンロードして開始します。モデルの実行中は、数十 GB のダウンロードと、マシンのメモリの大半が使われることを想定してください。Flash Next は、フル 256K コンテキストで約 100 GiB を使います。必要なメモリを他のモデルが占有している 경우、そのモデルは停止状態でセットアップされ、どれかを停止すると開始できるようになります。モデルはログアウト時に停止します。メモリが別の用途に必要な場合は、自分の手で停止してください。

`omarchy agent local list` は選択肢を表示し、なぜいくつかは適していないかを説明します。別のものをセットアップするには、`omarchy agent local use <recipe>` を実行してください。現在、128 GB Strix Halo マシン向けに、`qwen3.8-flash-next-gufo` と `qwen3.8-27b-gufo` が利用できます。27B は約 40 GiB を使いますので、他の作業にも余地が残ります。新しいレシピと推奨は、`omarchy update` によってパッケージ経由で届きます。

セットアップしたすべてのモデルは、サブスクリプションの隣に、エージェントパネルで独自の行を持ちます。再生で起動し、一時停止で停止してそのメモリを解放し、ターミナルボタンでその上でエージェントを開きます。メモリに収まる限り複数のものを同時に実行できます。収まらないものがある場合は、Omarchy はどの実行中のモデルを停止すべきかを教えてくれます。行をドラッグして並び替え、選択した行で Delete を押すと、モデルとそのダウンロードが削除されます。

コマンドラインからは、`omarchy agent local start <recipe>` と `omarchy agent local stop <recipe>` が同じことを行い、`omarchy agent local status` はすべてのモデルを表示し、`omarchy agent --local` は最後に起動したモデル上でデフォルトエージェントを開きます（デフォルトエージェントがローカルモデルを使えない場合は pi）。OpenAI 互換のクライアントでも接続できます。`status` は各モデルのアドレスを表示し（最初は `http://127.0.0.1:11435/v1`）、レシピ名がモデルとなり、キーは `~/.config/omarchy/agent-local/key` にあります。

`omarchy agent local remove <recipe>` はモデルと、他のどのモデルも使わないダウンロードを削除します。

サードパーティ製のランタイムは、その発行元が表示されます。Omarchy はすべてのモデルをネットワークアクセスなしで実行します。

### ローカル LLM

Omarchy では、ローカル LLM モデルを実行する方法として、LM Studio と Ollama の2つを推奨しています。LM Studio はオープンウェイトモデルを見つけてインストールし、実行するための GUI インターフェイスを提供します。手軽に始めるには素晴らしい方法です。Ollama も同様のことを CLI で提供します。ただ、ローカルモデルに慣れていないなら、私なら LM Studio から始めます。どちらも Omarchy Menu の _Install > AI_ からインストールできます。

### The Omarchy Skill

エージェントスキルは、AI が特定のツールを特定の方法で使う助けになるもので、Omarchy にはシステムをカスタマイズするためのデフォルトスキルが同梱されています。Hyprland の設定を調整したり、バーを調整したり、ゼロから新しいテーマを作り出したりするようなことです。これは Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` および各 `~/.hermes/profiles/*/skills`）、そして汎用の `~/.agents/skills` の場所へ、スキルのディレクトリーにシンボリックリンクされており、ほとんどの harness が自動的に拾います。

ただし、このスキルは実験的なものとして扱うべきです。使うモデルによって、その効果はさまざまです。まず plan mode で実行するのが最善であり、そうすればエージェントが何を変更したいか把握できます。そして、もしエージェントがすべてを台無しにしてしまったら、変更をロールバックしたり、`omarchy reinstall configs` を実行したりする覚悟をしておいてください。
