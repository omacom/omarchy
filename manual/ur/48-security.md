# سیکیورٹی

Omarchy سیکیورٹی کو انتہائی سنجیدگی سے لیتا ہے۔ اس کا مقصد ایک ایسا آپریٹنگ سسٹم بننا ہے جسے آپ _حقیقی دنیا_ میں _حقیقی کام_ کرنے کے لیے استعمال کر سکیں۔ جہاں لیپ ٹاپ کھو جانا کسی سیکیورٹی ہنگامی صورتحال کا سبب نہ بن سکے۔ تو ہم یہ کرتے ہیں:

1. *فل ڈسک انکرپشن بطور ڈیفالٹ آن ہوتی ہے*: یہ آپ کے ڈیٹا کی جسمانی حفاظت کو یقینی بنانے کے لیے سب سے اہم قدم ہے۔ اگر آپ کا کمپیوٹر کھو جائے یا چوری ہو جائے تو ڈیٹا معیاری LUKS (Linux Unified Key Setup) کے ذریعے مکمل طور پر انکرپٹڈ ہوتا ہے۔ انسٹالر آپ کو ضائع کر دینے والی مشینوں کے لیے اس سے دستبردار ہونے کا اختیار دیتا ہے (دیکھیں [شروعات کریں](02-getting-started.md))؛ انکرپشن کے بغیر انسٹال میں یہ تحفظ بالکل نہیں ہوتا، اور جس کے ہاتھ ڈرائیو لگ جائے وہ اسے پڑھ سکتا ہے۔
2. *فائر وال بطور ڈیفالٹ فعال ہوتی ہے*: تمام آنے والی ٹریفک بطور ڈیفالٹ بلاک ہوتی ہے، چند استثناؤں کے ساتھ: [LocalSend](https://localsend.org/) کے لیے پورٹ 53317؛ Docker bridge ایڈریس (172.17.0.1) پر کمپیوٹر کے اپنے resolver کو DNS درخواستیں، جو ان پرائیویٹ ایڈریس رینجز سے قبول کی جاتی ہیں جو Docker اپنے containers کو دیتا ہے؛ اور multicast DNS (پورٹ 5353)، جو printers اور آپ کے نیٹ ورک پر موجود دیگر ڈیوائسز کو ایک دوسرے کو تلاش کرنے دیتا ہے اور وہاں آپ کے کمپیوٹر کے نام کا اعلان بھی کرتا ہے۔ ان کے علاوہ، فائر وال ping، آپ کے router سے ایڈریس حاصل کرنے (DHCP)، اور UPnP تلاش کے لیے UFW کی معیاری اجازتوں کو برقرار رکھتی ہے۔ یہاں تک کہ ssh بھی اس وقت تک بند رہتا ہے جب تک آپ اسے _Setup > Security > SSHD_ کے ذریعے آن نہ کریں، جو setup کے حصے کے طور پر پورٹ 22 کھولتا ہے (brute force کے خلاف rate limited)۔ ہم [ufw-docker](https://github.com/chaifeng/ufw-docker) setup کے ذریعے Docker تک رسائی کو بھی بند کر دیتے ہیں تاکہ آپ کے containers غلطی سے دنیا کے سامنے ظاہر نہ ہو جائیں۔
3. *Arch کے پاس ہمیشہ تازہ ترین اپڈیٹس ہوتی ہیں*: Arch، وہ بنیادی distro جس پر Omarchy بنایا گیا ہے، ایک rolling distribution ہے۔ اس کا مطلب ہے کہ کسی بھی package میں دریافت اور patch کی گئی کوئی بھی سیکیورٹی کمزوری `omarchy-update` کے ذریعے انسٹال کے لیے جلد دستیاب ہو جاتی ہے۔ اس طرح آپ ہمیشہ ہر چیز کے تازہ ترین، سب سے محفوظ ورژن چلا رہے ہوتے ہیں۔
4. *Omarchy اپنے packages اور mirror خود برقرار رکھتا ہے*: Omarchy بطور ڈیفالٹ صرف Arch کی اپنی core/extra/multilib repositories اور اپنی Omarchy Package Repository کے packages پر انحصار کرتا ہے۔ آپ براہ راست AUR سے سافٹ ویئر انسٹال کر سکتے ہیں، لیکن بنیادی انسٹال ایسا نہیں کرتا — صرف چند اختیاری انسٹالز، جیسے third-party browsers، AUR سے حاصل کرتے ہیں۔
5. *Cloudflare ہمیں DDoS سے بچاتا ہے*: Omarchy کی تقسیم کا انفراسٹرکچر — ISOs، Omarchy packages، Arch mirror — Cloudflare کی زبردست DDoS شیلڈ کے پیچھے محفوظ ہے اور ان کے CDN پر hosted ہے۔ یہ شاندار دستیابی فراہم کرتا ہے۔

## اپنے پاس ورڈز تبدیل کرنا

انکرپٹڈ انسٹال پر آپ کے دو پاس ورڈ ہوتے ہیں: ایک وہ جو boot کے وقت ڈرائیو کو کھولتا ہے، اور دوسرا وہ جس سے آپ لاگ ان کرتے اور `sudo` استعمال کرتے ہیں۔ Setup دونوں کو ایک ہی بنا دیتا ہے۔ دونوں کو Omarchy مینو میں _Update > Password_ کے تحت تبدیل کیا جا سکتا ہے — پہلے کے لیے _Drive Encryption_، دوسرے کے لیے _User_۔ ڈرائیو کا پاس ورڈ تبدیل کرنے پر پہلے موجودہ پاس ورڈ مانگا جاتا ہے، اس لیے اسے تیار رکھیں۔ اگر تبدیلی درمیان میں رک جائے تو دوبارہ _Drive Encryption_ چلائیں: یہ وہ پاس ورڈ مانگے گا جو اس وقت ڈرائیو کو کھولتا ہے اور تبدیلی مکمل کر دے گا۔

## استعمال شدہ مشین کسی اور کے حوالے کرنا

اگر آپ اپنی مشین کسی اور کو دے رہے ہیں تو آپ کو اسے دوبارہ انسٹال کرنے کی ضرورت نہیں۔ Omarchy مینو میں _Remove > Factory Reset_ چلائیں، تصدیق کے لیے `reset` لکھیں، اور reboot کریں۔ یہ ہر user account اور `/home` میں موجود ہر چیز کو مٹا دیتا ہے، انسٹال کے بعد سے آپ کے شامل کیے گئے تمام packages اور سسٹم تبدیلیاں پھینک دیتا ہے، اور مشین کی شناخت صاف کر دیتا ہے — network connections، host keys، سب کچھ۔ جو واپس آتا ہے وہ پہلے boot والا setup wizard ہے، اپنے نئے مالک کے لیے اپنا نام، پاس ورڈ اور انکرپشن پاس ورڈ درج کرنے کے لیے تیار۔

یہ انسٹالر کے لیے گئے baseline snapshot کو بحال کر کے کام کرتا ہے، اس لیے یہ صرف Omarchy ISO سے انسٹال کی گئی مشینوں پر دستیاب ہے۔ اور انکرپشن کے بغیر ڈرائیو پر، reset محفوظ مٹاؤ کے بجائے صرف حذف کرنا ہے، اس لیے اگر ڈیٹا حساس تھا تو اس کے بجائے نیا انسٹال کریں۔

## بغیر پاس ورڈ کے sudo

کبھی کبھی آپ چاہتے ہیں کہ `sudo` پوچھنا بند کر دے، اکثر اس وقت جب کوئی AI agent آپ کے لیے سسٹم کا طویل کام کر رہا ہو۔ _Setup > Security > Passwordless Sudo_ پوچھتا ہے کہ رسائی کتنی دیر کے لیے دی جائے: **15 منٹ**، **1 گھنٹہ**، **1 دن**، یا **مستقل طور پر**۔ رسائی فعال ہونے کے دوران دیگر مینو بار اشاروں کے ساتھ ایک سرخ انتباہی نشان ظاہر ہوتا ہے۔ رسائی بند کرنے کے لیے اس پر کلک کریں یا کمانڈ دوبارہ چلائیں۔ آپ `omarchy-sudo-passwordless 30` کے ساتھ اپنے منٹوں کی تعداد (1 سے 1440 تک) بھی دے سکتے ہیں، یا `omarchy-sudo-passwordless permanent` استعمال کر سکتے ہیں۔

وقت مقررہ رسائی خودکار طور پر ختم ہو جاتی ہے، بشمول deadline پار کرنے والے suspend سے resume ہونے کے فوراً بعد۔ کمپیوٹر کو دوبارہ شروع کرنے سے یہ وقت سے پہلے ختم ہو جاتی ہے۔ مستقل رسائی reboots کے بعد بھی برقرار رہتی ہے اور اس وقت تک فعال رہتی ہے جب تک آپ اسے غیر فعال نہ کر دیں۔

Omarchy کے settings package کو اپڈیٹ یا ہٹانے سے کسی بھی عارضی اجازت کی expiry support تبدیل ہونے سے پہلے وہ ختم ہو جاتی ہے۔ اگر کمانڈ authorization یا cleanup کی خرابی کی اطلاع دے تو ایک اور اجازت فعال کرنے کی کوشش سے پہلے اسے حل کریں؛ خرابی کا مطلب یہ نہیں کہ بغیر پاس ورڈ کی رسائی غیر فعال ہے۔

اس بارے میں واضح نظر رکھیں: جب یہ آن ہو تو، آپ کے user کے طور پر چلنے والی کوئی بھی چیز بغیر پوچھے root کے طور پر کچھ بھی کر سکتی ہے۔ یہی اس کا پورا مقصد ہے، اور یہی اس کا پورا خطرہ بھی ہے۔
