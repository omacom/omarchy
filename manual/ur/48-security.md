# سیکیورٹی

Omarchy سیکیورٹی کو انتہائی سنجیدگی سے لیتا ہے۔ یہ ایک ایسا آپریٹنگ سسٹم بننے کے لیے ہے جسے آپ _حقیقی دنیا_ میں _حقیقی کام_ کرنے کے لیے استعمال کر سکیں۔ جہاں لیپ ٹاپ گم ہو جانے سے سیکیورٹی ہنگامی صورتحال پیدا نہ ہو۔ تو ہم یہ کرتے ہیں:

1. *Full-disk encryption بطور ڈیفالٹ آن ہے*: یہ آپ کے ڈیٹا کے طبعی تحفظ کو محفوظ بنانے کے لیے سب سے اہم قدم ہے۔ اگر آپ کا کمپیوٹر گم ہو جائے یا چوری ہو جائے، تو ڈیٹا معیاری LUKS (Linux Unified Key Setup) کا استعمال کرتے ہوئے مکمل طور پر خفیہ کردہ ہے۔ انسٹالر آپ کو throw-away مشینوں کے لیے اس سے دستبردار ہونے دیتا ہے (دیکھیں [شروعات کریں](02-getting-started.md)); encryption کے بغیر انسٹال میں اس میں سے کوئی تحفظ نہیں ہوتا، اور ڈرائیو رکھنے والا کوئی بھی شخص اسے پڑھ سکتا ہے۔
2. *Firewall بطور ڈیفالٹ فعال ہے*: تمام آنے والی ٹریفک بطور ڈیفالٹ مسدود ہے، چند استثناؤں کے ساتھ: [LocalSend](https://localsend.org/) کے لیے پورٹ 53317؛ کمپیوٹر کے اپنے resolver کو Docker bridge ایڈریس (172.17.0.1) پر DNS استفسارات، جو ان private ایڈریس رینجز سے قبول کیے جاتے ہیں جو Docker اپنے containers کو دیتا ہے؛ اور multicast DNS (پورٹ 5353)، جو printers اور آپ کے نیٹ ورک پر موجود دیگر آلات کو ایک دوسرے کو تلاش کرنے دیتا ہے اور وہاں آپ کے کمپیوٹر کے نام کا بھی اعلان کرتا ہے۔ ان کے اوپر، firewall ping، آپ کے router سے ایڈریس حاصل کرنے (DHCP)، اور UPnP دریافت کے لیے UFW کی معیاری اجازتیں برقرار رکھتا ہے۔ یہاں تک کہ ssh بھی اس وقت تک بند رہتا ہے جب تک آپ اسے _Setup > Security > SSHD_ کے ذریعے آن نہ کریں، جو آپ کی SSH کلید کو اختیار دیتا ہے، پاس ورڈ لاگ ان بند کر دیتا ہے، اور تب ہی پورٹ 22 کھولتا ہے (brute force کے خلاف rate limited)۔ ہم [ufw-docker](https://github.com/chaifeng/ufw-docker) سیٹ اپ کا استعمال کرتے ہوئے Docker رسائی کو بھی بند کر دیتے ہیں تاکہ آپ کے containers کو حادثاتی طور پر دنیا کے سامنے ظاہر ہونے سے روکا جا سکے۔
3. *Arch کے پاس ہمیشہ تازہ ترین اپڈیٹس ہوتی ہیں*: Arch، وہ بنیادی distro جس پر Omarchy بنایا گیا ہے، ایک rolling distribution ہے۔ اس کا مطلب ہے کہ کسی بھی پیکج میں دریافت اور درست کی جانے والی کوئی بھی سیکیورٹی کمزوری `omarchy-update` کا استعمال کرتے ہوئے انسٹال کے لیے جلد دستیاب ہو جاتی ہے۔ اس طرح آپ ہمیشہ ہر چیز کے تازہ ترین، سب سے محفوظ ورژن چلا رہے ہوتے ہیں۔
4. *Omarchy اپنے پیکجز اور mirror برقرار رکھتا ہے*: Omarchy بطور ڈیفالٹ صرف Arch کے اپنے core/extra/multilib repositories (ARM مشینوں پر Arch Linux ARM کے، نیز Apple Silicon پر Asahi ALARM) اور اپنے Omarchy Package Repository کے پیکجز پر انحصار کرتا ہے۔ آپ براہ راست AUR سے سافٹ ویئر انسٹال کر سکتے ہیں، لیکن base install ایسا نہیں کرتا — صرف چند اختیاری انسٹالز، جیسے third-party browsers، AUR سے حاصل کرتے ہیں۔
5. *Cloudflare ہمیں DDoS سے بچاتا ہے*: Omarchy کی تقسیم کا بنیادی ڈھانچہ — ISOs، Omarchy پیکجز، Arch mirror — Cloudflare کی زبردست DDoS شیلڈ کے پیچھے محفوظ ہے اور ان کے CDN پر میزبانی کی گئی ہے۔ یہ شاندار دستیابی فراہم کرتا ہے۔

## اپنے پاس ورڈز تبدیل کرنا

encrypted انسٹال پر آپ کے پاس دو پاس ورڈز ہوتے ہیں: ایک جو boot پر ڈرائیو کو unlock کرتا ہے، اور ایک جس سے آپ لاگ ان اور `sudo` کرتے ہیں۔ Setup انہیں ایک جیسا بنا دیتا ہے۔ دونوں کو Omarchy مینو میں _Update > Password_ کے تحت تبدیل کیا جا سکتا ہے — پہلے کے لیے _Drive Encryption_، دوسرے کے لیے _User_۔ ڈرائیو کا پاس ورڈ تبدیل کرنے پر پہلے موجودہ پاس ورڈ مانگا جاتا ہے، لہذا اسے قریب رکھیں۔ اگر تبدیلی میں رکاوٹ آ جائے، تو _Drive Encryption_ دوبارہ چلائیں: یہ وہ پاس ورڈ مانگے گا جو ابھی ڈرائیو کو unlock کرتا ہے اور تبدیلی مکمل کر دے گا۔

## ایسی مشین آگے دینا جسے آپ پہلے ہی استعمال کر چکے ہیں

اگر آپ اپنی مشین کسی اور کو دے رہے ہیں، تو آپ کو اسے دوبارہ انسٹال کرنے کی ضرورت نہیں ہے۔ Omarchy مینو میں _Remove > Factory Reset_ چلائیں، تصدیق کے لیے `reset` ٹائپ کریں، اگر کہا جائے تو اپنا drive encryption پاس ورڈ درج کریں، اور reboot کریں۔ یہ ہر user اکاؤنٹ اور `/home` میں موجود ہر چیز کو مٹا دیتا ہے، انسٹالیشن کے بعد سے کیے گئے تمام پیکجز اور سسٹم تبدیلیوں کو پھینک دیتا ہے، اور مشین کی شناخت صاف کر دیتا ہے — network کنکشنز، host keys، اور سب کچھ۔ جو واپس آتا ہے وہ پہلے boot کا setup wizard ہوتا ہے، جو اپنے نئے مالک کے لیے اپنا نام، پاس ورڈ اور encryption پاس ورڈ درج کرنے کے لیے تیار ہوتا ہے۔

یہ installer کے لیے گئے baseline snapshot کو بحال کر کے کام کرتا ہے، لہذا یہ صرف Omarchy ISO سے انسٹال شدہ مشینوں پر دستیاب ہے۔ اور encryption کے بغیر ڈرائیو پر، reset محفوظ مٹاؤ کے بجائے حذف کرنا ہوتا ہے، لہذا اگر ڈیٹا حساس تھا، تو اس کے بجائے fresh install کریں۔

## پاس ورڈ کے بغیر sudo

کبھی کبھی آپ چاہتے ہیں کہ `sudo` پوچھنا بند کر دے، اکثر اس وقت جب کوئی AI agent آپ کے لیے سسٹم کا طویل کام کر رہا ہو۔ _Setup > Security > Passwordless Sudo_ پوچھتا ہے کہ کتنی دیر تک رسائی کی اجازت دی جائے: **15 منٹ**، **1 گھنٹہ**، **1 دن**، یا **مستقل طور پر**۔ جب رسائی فعال ہوتی ہے تو دیگر مینو بار اشاروں کے ساتھ ایک سرخ انتباہی آئیکن ظاہر ہوتا ہے۔ رسائی بند کرنے کے لیے اس پر کلک کریں یا کمانڈ دوبارہ چلائیں۔ آپ `omarchy-sudo-passwordless 30` کے ساتھ اپنی مرضی کی منٹوں کی تعداد (1 سے 1440 تک) بھی دے سکتے ہیں، یا `omarchy-sudo-passwordless permanent` استعمال کر سکتے ہیں۔

وقتی رسائی خودبخود ختم ہو جاتی ہے، بشمول deadline کو عبور کرنے والے suspend سے resume ہونے کے فوراً بعد۔ کمپیوٹر کو restart کرنے سے یہ جلد ختم ہو جاتی ہے۔ مستقل رسائی reboots کے بعد بھی برقرار رہتی ہے اور اس وقت تک فعال رہتی ہے جب تک آپ اسے غیر فعال نہ کر دیں۔

Omarchy کے settings پیکج کو اپڈیٹ یا ہٹانے سے کسی بھی عارضی grant کی expiry support تبدیل ہونے سے پہلے وہ ختم ہو جاتی ہے۔ اگر کمانڈ authorization یا cleanup کی خرابی کی اطلاع دے، تو ایک اور grant فعال کرنے کی کوشش کرنے سے پہلے اسے حل کریں؛ خرابی کا مطلب یہ نہیں ہے کہ پاس ورڈ کے بغیر رسائی غیر فعال ہے۔

اس بارے میں واضح نظر رکھیں: جب یہ آن ہوتا ہے، تو آپ کے user کے طور پر چلنے والی کوئی بھی چیز بغیر پوچھے root کے طور پر کچھ بھی کر سکتی ہے۔ یہی اس کا پورا مقصد ہے، اور یہی اس کا پورا خطرہ بھی ہے۔
