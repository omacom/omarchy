# ڈیولپمنٹ ٹولز

## متبادل ایڈیٹرز

Omarchy نئی انسٹالیشنز پر ڈیفالٹ ایڈیٹر کے طور پر Plain کے ساتھ آتا ہے اور [Neovim](https://neovim.io/) پہلے سے انسٹال ہوتا ہے، لیکن اگر آپ کو کچھ زیادہ مین اسٹریم اور مانوس چاہیے تو آپ Omarchy Menu (`Super + Space`) چلا کر _Install > Editor_ کے تحت آپشنز دیکھ سکتے ہیں۔ وہاں ہمارے پاس VSCode، Cursor، Zed، Sublime Text، Helix، Vim اور Emacs درج ہیں۔ اگر آپ کو وہاں اپنی مطلوبہ چیز نہ ملے تو _Install > Package_ دیکھیں کہ آیا وہ کسی Arch پیکیج میں موجود ہے یا نہیں (اور اگر نہ ہو تو AUR چیک کرنے کے لیے _Install > AUR_ آزمائیں)۔

اصل `vi` ایڈیٹر بھی شروع سے ہی دستیاب ہے۔ ٹرمینل میں کسی فائل میں ترمیم کرنے کے لیے `vi filename` چلائیں۔

`VSCode`، `Cursor`، `VSCodium` اور `Helix` کے لیے تھیم میچنگ پیش کی جاتی ہے۔

آپ سسٹم بھر کا ڈیفالٹ ایڈیٹر `Setup > Defaults > Editor` کے تحت سیٹ کر سکتے ہیں۔

## ماحول

Omarchy، Omarchy Menu (`Super + Space`) کے _Install > Development_ سیکشن کے ذریعے ڈیولپمنٹ انوائرمنٹس کی پوری ایک بڑی تعداد سیٹ اپ کرنے کی سہولت دیتا ہے۔ وہاں آپ کو یقیناً _Ruby on Rails_ ملے گا، لیکن JavaScript کے تینوں بڑے رن ٹائمز (Node.js، Bun، Deno) بھی، اور Laravel اور Symfony جیسے مقبول PHP فریم ورکس بھی۔ اوہ، اور Go، Rust، Python، Java، Elixir (Phoenix کے ساتھ)، .NET، OCaml، Zig، Clojure اور Scala بھی موجود ہیں۔ یہ واقعی بہت وسیع انتخاب ہے!

ان میں سے بیشتر انوائرمنٹس کو [Mise](https://mise.jdx.dev/) منظم کرتا ہے۔ یہ ایک ایسا ٹول ہے جو آپ کو ایک ہی مشین پر کسی پروگرامنگ لینگوئج کے متعدد ورژنز انسٹال اور چلانے دیتا ہے۔ یہ Ruby کے لیے rbenv یا rvm یا Python کے لیے virtualenv جیسا ہے، لیکن یہ بہت سے مختلف انوائرمنٹس کے لیے کام کرتا ہے۔

مثال کے طور پر Ruby انسٹال کرنے کے لیے آپ `mise use -g ruby` چلائیں گے، جو Ruby کو انسٹال بھی کرے گا اور اسے گلوبل ڈیفالٹ کے طور پر سیٹ بھی کر دے گا۔ یا، اگر آپ کے پروجیکٹ میں .ruby-version فائل موجود ہے تو آپ اس پروجیکٹ کی روٹ میں بس `mise i` چلا سکتے ہیں۔

## پہلے سے انسٹال شدہ CLI ٹولز

Omarchy، `gh`، `uv` جیسے ٹولز اور بیشتر [کوڈنگ ایجنٹس](17-ai.md) کو [mise کی lazy installation](https://mise.jdx.dev/dev-tools/shims.html#lazy-tools) کے ذریعے دستیاب کرتا ہے۔ پہلی بار جب آپ ان میں سے کوئی چلاتے ہیں تو mise اسے انسٹال کر دیتا ہے۔ اس کے بعد کوڈنگ ایجنٹس چلنے سے پہلے اپ ڈیٹ چیک کرتے ہیں، زیادہ سے زیادہ ہر چار گھنٹے میں ایک بار؛ دوسرے ٹولز، جیسے `gh` اور `uv`، آپ کے اپ ڈیٹ کرنے تک انسٹال شدہ ورژن ہی دوبارہ استعمال کرتے ہیں۔

آپ ڈیفالٹس کو دیکھ بھی سکتے ہیں یا انہیں پہلے سے انسٹال بھی کر سکتے ہیں:

```bash
mise ls --current              # List the tools configured for this directory
mise install gh               # Install one tool now
mise install --include-lazy    # Install all configured tools, including lazy tools
```

انسٹال شدہ ٹولز کو باقی Omarchy کے ساتھ اپ ڈیٹ کرنے کے لیے `omarchy update` چلائیں۔ `mup` ایلیاس صرف mise کے زیرِ انتظام ٹولز کو اپ ڈیٹ کرتا ہے۔ اپنی کنفیگریشن میں کوئی اور ٹول شامل کرنے کے لیے `mise use -g <tool>` استعمال کریں۔

Python سیٹ اپ mise کے ذریعے `uv` بھی انسٹال کرتا ہے۔ Python ڈیولپمنٹ انوائرمنٹ ہٹانے سے بھی `uv` ایک آزاد ٹول کے طور پر دستیاب رہتا ہے۔

### اپنی انسٹالیشن استعمال کرنا

mise کے کمانڈز `PATH` پر `~/.local/bin` سے پہلے آتے ہیں، اس لیے جو ٹول آپ نے خود انسٹال کیا ہو، مثال کے طور پر Claude Code یا Cursor کے اپنے انسٹالر سے، اس کی جگہ بھی mise والی کاپی ہی چلتی ہے۔ ڈیسک ٹاپ سے لانچ کی گئی ایپس کو بھی سسٹم پیکیجز سے پہلے mise کے کمانڈز ملتے ہیں، اس لیے جو ایپ `gh` چلاتی ہے اسے mise والی کاپی ملتی ہے خواہ آپ نے pacman سے `github-cli` انسٹال کر رکھا ہو، اور mise پہلی بار وہ کاپی انسٹال کر دیتا ہے۔ اس کے بجائے اپنی کاپی استعمال کرنے کے لیے `~/.config/mise/config.toml` میں mise والی کاپی کو غیر فعال کر دیں۔ مثال کے طور پر، اگر آپ نے Cursor CLI خود انسٹال کیا ہو:

```toml
[settings]
disable_tools = ["cursor-agent"]
```

اگر آپ کے پاس پہلے سے `[settings]` ٹیبل موجود ہے تو اندراج وہیں شامل کریں؛ موجودہ `disable_tools` فہرست کو بدلنے کے بجائے اس میں اضافہ کریں۔ یقینی بنائیں کہ آپ کی انسٹالیشن `PATH` پر موجود ہے۔ mise کا ٹول نام استعمال کریں، جو اس کے کمانڈ سے مختلف ہو سکتا ہے: مثال کے طور پر `oh-my-pi`، `omp` فراہم کرتا ہے۔ ڈیفالٹ ایجنٹ لانچر بھی `~/.local/bin` میں صارف کے انسٹال کردہ Cursor یا Muse کو ترجیح دیتا ہے۔

### ڈیفالٹس ہٹانا اور بحال کرنا

_Remove > Preinstalls_، Omarchy کی پہلے سے انسٹال شدہ ویب ایپس، TUIs اور ایپس کو ہٹا دیتا ہے، اور انہیں `~/.config/mise/miserc.toml` میں `ignored_config_paths` میں شامل کرکے mise کو آپ کے صارف کے لیے Omarchy کے ٹول اعلانات چھوڑنے پر مجبور کرتا ہے۔ _Install > Preinstalls_ انہیں واپس لے آتا ہے اور وہ لائن دوبارہ ہٹا دیتا ہے۔ جو ٹولز آپ خود اعلان کرتے ہیں، اپنی کنفیگ میں یا کسی پروجیکٹ کی `mise.toml` میں، وہ دونوں صورتوں میں کام کرتے رہتے ہیں۔ اگر آپ پری انسٹالز ہٹانے کے بعد کوئی ڈیفالٹ ایجنٹ منتخب کرتے ہیں یا Python سیٹ اپ کرتے ہیں تو وہ ٹول آپ کی اپنی کنفیگ میں شامل کر دیا جاتا ہے۔ mise کی یہ سیٹنگ صرف آپ کے صارف پر لاگو ہوتی ہے، اور دوسرے صارفین کا اپنا انتخاب برقرار رہتا ہے؛ تاہم ایپس پیکیجز ہیں، اس لیے انہیں ہٹانے یا بحال کرنے سے وہ مشین پر موجود ہر شخص کے لیے بدل جاتی ہیں۔

## Docker

[Docker](https://www.docker.com/) کو کسی تعارف کی شاید ہی ضرورت ہو۔ یہ آپ کو الگ تھلگ کنٹینرز چلانے دیتا ہے، اور Omarchy اسے اچھی طرح چلانے کے لیے درکار ہر چیز انسٹال کرتا ہے، بشمول خود Docker اور [Docker Compose](https://docs.docker.com/compose/)۔

ڈیفالٹ طور پر آپ کا صارف `docker` گروپ میں *شامل نہیں* ہے۔ وہ گروپ مؤثر طور پر بغیر پاس ورڈ والا root ہے — اس میں موجود کوئی بھی چیز `docker run -v /:/host` چلا کر مشین پر قبضہ کر سکتی ہے — اس لیے آپ کے طور پر چلنے والا کوئی ایک بدمعاش اسکرپٹ یا ڈپینڈنسی بصورتِ دیگر root سے صرف ایک کمانڈ دور ہوتا۔ چنانچہ کمانڈ لائن پر آپ Docker کو `sudo` کے ساتھ چلاتے ہیں (`sudo docker ps`، `sudo docker compose up`)، اور وہ گرافیکل ٹولز جو ڈیمن سے بات کرتے ہیں — Windows VM — ضرورت پڑنے پر آپ سے اجازت مانگتے ہیں۔ اگر آپ گروپ کے بغیر والے سیٹ اپ کی سہولت واپس چاہتے ہیں اور اس کے بدلے ہونے والے سمجھوتے کو سمجھتے ہیں تو اسے **Setup > Security > Sudoless Docker** سے فعال کریں (یا `omarchy-setup-security-sudoless-docker` چلائیں)، جو انتباہ کے بعد آپ کو `docker` گروپ میں شامل کر دیتا ہے؛ اس کے بعد سادہ `docker` اور `d` ایلیاس دوبارہ `sudo` کے بغیر کام کرتے ہیں۔

آپ Omarchy مینو میں _Install > Development > Docker DB_ استعمال کرکے مقامی ڈیولپمنٹ کے لیے عام ڈیٹا بیسز Docker میں سیٹ اپ کر سکتے ہیں۔

## GitHub CLI

[GitHub CLI](https://cli.github.com/) ٹرمینل سے ریپوزٹریز، ایشوز اور پل ریکویسٹس کے ساتھ کام کرنے کے لیے `gh` کے طور پر دستیاب ہے۔ پہلی بار استعمال پر اسے انسٹال اور تصدیق کرنے کے لیے `gh auth login` چلائیں، پھر کسی ریپوزٹری کو کلون کرنے کے لیے `gh repo clone org/repo` چلائیں۔ اس کے کمانڈز جاننے کے لیے `gh --help` چلائیں۔

پل ریکویسٹس کے لیے ٹرمینل انٹرفیس کے طور پر `ghui` چلائیں؛ mise اسے بھی پہلی بار استعمال پر انسٹال کر دیتا ہے۔ خود Git کے ساتھ کام کرنے کے لیے [Lazygit](https://github.com/jesseduffield/lazygit) پہلے سے انسٹال ہے۔
