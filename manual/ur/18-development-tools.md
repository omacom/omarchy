# ڈیولپمنٹ ٹولز

## متبادل ایڈیٹرز

Omarchy نئی انسٹالیشنز پر Plain کو بطور پہلے سے طے شدہ ایڈیٹر کے ساتھ آتا ہے اور [Neovim](https://neovim.io/) پہلے سے انسٹال ہوتا ہے، لیکن اگر آپ کو کچھ زیادہ مرکزی دھارے کا اور مانوس چاہیے تو آپ Omarchy Menu (`Super + Space`) چلا کر _Install > Editor_ کے تحت موجود اختیارات دیکھ سکتے ہیں۔ وہاں ہمارے پاس VSCode، Cursor، Zed، Sublime Text، Helix، Vim، اور Emacs درج ہیں۔ اگر آپ کو اپنی مطلوبہ چیز وہاں نہ ملے تو _Install > Package_ دیکھیں، اور دیکھیں کہ آیا وہ کسی Arch پیکیج میں موجود ہے یا نہیں (اور اگر نہ ہو تو AUR چیک کرنے کے لیے _Install > AUR_ آزمائیں)۔

اصل `vi` ایڈیٹر بھی بکس سے نکلتے ہی دستیاب ہے۔ ٹرمینل میں کسی فائل میں ترمیم کرنے کے لیے `vi filename` چلائیں۔

`VSCode`، `Cursor`، `VSCodium`، اور `Helix` کے لیے تھیم کا میل پیش کیا جاتا ہے۔

آپ `Setup > Defaults > Editor` کے تحت پورے سسٹم کے لیے پہلے سے طے شدہ ایڈیٹر مقرر کر سکتے ہیں۔

## ماحول

Omarchy، Omarchy Menu (`Super + Space`) کے _Install > Development_ حصے کے ذریعے ترقیاتی ماحول کی ایک پوری بڑی تعداد قائم کرنے کی سہولت دیتا ہے۔ بلاشبہ آپ کو وہاں _Ruby on Rails_ ملے گا، لیکن JavaScript کے تینوں بڑے رن ٹائمز (Node.js، Bun، Deno) بھی ملیں گے، نیز Laravel اور Symfony جیسے مقبول PHP فریم ورکس بھی۔ اوہ، اور Go، Rust، Python، Java، Elixir (Phoenix کے ساتھ)، .NET، OCaml، Zig، Clojure، اور Scala بھی موجود ہیں۔ یہ واقعی بہت وسیع انتخاب ہے!

ان میں سے بیشتر ماحول [Mise](https://mise.jdx.dev/) کے ذریعے منظم کیے جاتے ہیں۔ یہ ایک ایسا ٹول ہے جو آپ کو ایک ہی مشین پر کسی پروگرامنگ زبان کے متعدد ورژن انسٹال کرنے اور چلانے دیتا ہے۔ یہ Ruby کے لیے rbenv یا rvm کی طرح، یا Python کے لیے virtualenv کی طرح ہے، لیکن یہ بہت سے مختلف ماحول کے لیے کام کرتا ہے۔

مثال کے طور پر Ruby انسٹال کرنے کے لیے آپ `mise use -g ruby` چلائیں گے، جو Ruby کو انسٹال بھی کرے گا اور اسے عالمی پہلے سے طے شدہ بھی مقرر کر دے گا۔ یا، اگر آپ کے پراجیکٹ میں .ruby-version فائل ہے، تو آپ اس پراجیکٹ کی روٹ میں بس `mise i` چلا سکتے ہیں۔

## پہلے سے انسٹال شدہ CLI ٹولز

`uv`، Node.js، اور `playwright-cli` (تاکہ ایجنٹس انسٹال شدہ Chrome استعمال کرتے ہوئے براؤزر چلا سکیں) پیکیجز کے طور پر انسٹال آتے ہیں، اور `omarchy update` انہیں باقی سسٹم کے ساتھ اپ ٹو ڈیٹ رکھتا ہے۔ [Hunk](https://github.com/modem-dev/hunk) اور GitHub، Basecamp، Cloudflare اور HEY CLIs _Install > CLI_ کے تحت بس ایک انتخاب کی دوری پر ہیں، اور [کوڈنگ ایجنٹس](17-ai.md) _Install > AI > CLI_ کے تحت ہیں۔

mise صرف انہی رن ٹائمز کو منظم کرتا ہے جو آپ _Install > Development_ سے قائم کرتے ہیں؛ Omarchy اس کے ذریعے خود سے کچھ بھی انسٹال نہیں کرتا۔ انہیں باقی Omarchy کے ساتھ اپ ڈیٹ کرنے کے لیے `omarchy update` چلائیں؛ `mup` عرف صرف mise کے ذریعے منظم ٹولز کو اپ ڈیٹ کرتا ہے۔ اپنی کنفیگریشن میں کوئی اور ٹول شامل کرنے کے لیے `mise use -g <tool>` استعمال کریں۔

## Docker

[Docker](https://www.docker.com/) کو شاید ہی کسی تعارف کی ضرورت ہو۔ یہ آپ کو الگ تھلگ کنٹینرز چلانے دیتا ہے، اور Omarchy اسے اچھی طرح چلانے کے لیے درکار ہر چیز انسٹال کرتا ہے، بشمول خود Docker اور [Docker Compose](https://docs.docker.com/compose/)۔

پہلے سے طے شدہ طور پر آپ کا صارف `docker` گروپ میں *نہیں* ہے۔ وہ گروپ درحقیقت بغیر پاس ورڈ کے root ہے — اس میں موجود کوئی بھی چیز `docker run -v /:/host` چلا کر مشین پر قبضہ کر سکتی ہے — اس لیے بطور آپ چلنے والی کوئی ایک بدمعاش اسکرپٹ یا ڈیپنڈنسی بصورت دیگر root سے صرف ایک کمانڈ کی دوری پر ہوگی۔ چنانچہ کمانڈ لائن پر آپ Docker کو `sudo` کے ساتھ چلاتے ہیں (`sudo docker ps`، `sudo docker compose up`)، اور ڈیمن سے بات کرنے والے گرافیکل ٹولز — Windows VM — ضرورت پڑنے پر آپ سے اجازت مانگتے ہیں۔ اگر آپ گروپ کے بغیر والی سہولت واپس چاہتے ہیں اور اس کے بدلے میں ہونے والے سمجھوتے کو سمجھتے ہیں، تو اسے **Setup > Security > Sudoless Docker** سے فعال کریں (یا `omarchy-setup-security-sudoless-docker` چلائیں)، جو ایک انتباہ کے بعد آپ کو `docker` گروپ میں شامل کر دیتا ہے؛ پھر سادہ `docker` اور `d` عرف دوبارہ `sudo` کے بغیر کام کرتے ہیں۔

آپ Omarchy مینو میں _Install > Development > Docker DB_ استعمال کر کے مقامی ترقی کے لیے عام ڈیٹابیس Docker میں قائم کر سکتے ہیں۔

## GitHub CLI

[GitHub CLI](https://cli.github.com/) یعنی `gh`، ٹرمینل سے ریپوزیٹریوں، ایشوز، اور pull requests کے ساتھ کام کرنے کے لیے ہے۔ جب آپ وہاں GitHub میں سائن ان کرنے کا انتخاب کرتے ہیں تو _Setup > Git_ اسے انسٹال کر دیتا ہے، یا اسے _Install > CLI > GitHub_ سے الگ سے انسٹال کریں۔ پھر `gh repo clone org/repo` کسی ریپوزیٹری کو کلون کرتا ہے؛ اس کی کمانڈز دریافت کرنے کے لیے `gh --help` چلائیں۔

[Lazygit](https://github.com/jesseduffield/lazygit) خود Git کے ساتھ کام کرنے کے لیے پہلے سے انسٹال ہے۔
