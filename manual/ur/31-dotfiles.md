# Dotfiles

Omarchy بنیادی طور پر نام نہاد dotfiles کے ذریعے ترتیب دیا جاتا ہے جو `~/.config` میں رہتی ہیں۔ انہیں آپ کی فائلیں سمجھا جاتا ہے جن میں آپ تبدیلیاں کر سکتے ہیں۔ جو فائلیں `/usr/share/omarchy` میں رہتی ہیں وہ خود Omarchy کی ہیں، اور آپ کو ان کے ساتھ چھیڑ چھاڑ نہیں کرنی چاہیے۔ اگر آپ کو `/usr/share/omarchy` میں کچھ بھی تبدیل کرنے کی ضرورت ہے تو اس کے بجائے آپ کو `~/.config` میں اس کی قدر کو تبدیل کرنا چاہیے۔

اہم ترتیبات کو Omarchy مینیو (`Super + Space`) سے براہ راست ترمیم کیا جا سکتا ہے، جیسے _Setup > Keyboard > Keybindings_، _Setup > Input_، اور _Setup > Config > [file]_۔ جب آپ اس طریقے سے کرتے ہیں تو، کوئی بھی عمل جسے config میں ترمیم کے بعد دوبارہ شروع کرنے کی ضرورت ہوگی وہ ایڈیٹر چھوڑنے کے بعد خود بخود ہو جائے گا (بذریعہ ڈیفالٹ Neovim — `:wq`، یاد رکھیں! — لیکن آپ اسے _Setup > Defaults > Editor_ کے ذریعے تبدیل کر سکتے ہیں)۔

یہاں `~/.config` میں اہم فائلوں کی فہرست ہے اور وہ کس چیز کو کنٹرول کرتی ہیں:

| File                  | Purpose              |
| ----------------------- | --------------------- |
| `~/.config/hypr/hyprland.lua` | مرکزی Hyprland کنفگ۔ Omarchy کے ڈیفالٹس کے علاوہ نیچے دی گئی آپ کی override فائلیں لوڈ کرتی ہے۔ [Hyprland configs کے بارے میں مزید جانیں](https://wiki.hypr.land/Configuring/)۔  |
| `~/.config/hypr/bindings.lua` | آپ کی اپنی کی بائنڈنگز اور ڈیفالٹس کی overrides۔ |
| `~/.config/hypr/monitors.lua` | مانیٹر کی وہ ترتیبات جن کا مانیٹر پینل احاطہ نہیں کرتا، جیسے گردش، اضافی موڈز، یا کسی مانیٹر کو بند رکھنا۔ |
| `~/.config/hypr/input.lua` | آپ کے کی بورڈ لے آؤٹ، ماؤس، اور ٹریک پیڈ کی ترتیبات کو کنٹرول کرتی ہے۔ |
| `~/.config/hypr/looknfeel.lua` | خالی جگہوں، کناروں، اینیمیشنز، اور باقی ظاہری شکل کو کنٹرول کرتی ہے۔ |
| `~/.config/hypr/autostart.lua` | سیشن کے ساتھ شروع ہونے والے اضافی عمل کو کنٹرول کرتی ہے۔ |
| `~/.config/omarchy/shell.json` | Omarchy شیل کو کنٹرول کرتی ہے: بار کی پوزیشن، لے آؤٹ، اور ویجٹس، علاوہ screensaver، lock، اور idle کے اوقات۔ |
| `~/.config/foot/foot.ini` | آپ کے ٹرمینل کو کنٹرول کرتی ہے (foot ڈیفالٹ ہے)۔ |
| `~/.XCompose` | آپ کے فوری رسائی والے ایموجی اور نام/ای میل کی خودکار تکمیل کی تعریف کرتی ہے۔ تبدیلیاں کرنے کے بعد `omarchy-restart-xcompose` چلانا یقینی بنائیں۔ |

اگر آپ اپنی سیٹ اپ کو بہتر بنانے کے لیے بہت سی تبدیلیاں کر لیتے ہیں، تو ان تمام dotfiles کا بیک اپ لینا اچھا خیال ہے۔ [Stow اس کے لیے ایک بہترین طریقہ ہے](https://www.youtube.com/watch?v=NoFiYOqnC4o)۔

### سیشن کے ساتھ اپنی ایپس شروع کرنا

اگر آپ چاہتے ہیں کہ ہر بار لاگ ان ہونے پر کچھ چلے — ایک sync daemon، ایک chat ایپ، آپ کی اپنی اسکرپٹ — تو اسے `~/.config/hypr/autostart.lua` میں ڈالیں:

```lua
o.launch_on_start("my-service")
```

اس سے کمانڈ سیشن کے حصے کے طور پر شروع ہوتی ہے، اس لیے جب آپ دوبارہ لاگ آؤٹ کرتے ہیں تو اسے صحیح طریقے سے صاف کر دیا جاتا ہے۔

### سسٹم ایونٹس پر اسکرپٹس چلانا

Omarchy چند لمحات میں hooks فائر کرتا ہے، اور آپ ان پر اپنی اسکرپٹس لگا سکتے ہیں۔ وہ `~/.config/omarchy/hooks/<event>.d/` میں رہتے ہیں، ہر ایونٹ کے لیے ایک ڈائریکٹری، اور وہاں موجود ہر قابلِ عمل فائل ایونٹ ہونے پر چلتی ہے:

| Event | When it runs |
| ----- | ------------ |
| `post-boot` | ڈیسک ٹاپ شروع ہونے کے فوراً بعد |
| `post-update` | `omarchy update` کے اختتام کے قریب، packages، migrations، اور service restarts کے بعد، mise ٹولز اپ ڈیٹ ہونے سے پہلے |
| `pre-refresh-pacman` | `omarchy refresh pacman` کے package config کو دوبارہ sync کرنے کے بعد، اس کے packages کو اپ ڈیٹ کرنے سے پہلے؛ چینل کی تبدیلی اسی refresh مرحلے کے دوران اسے چلاتی ہے |
| `theme-set` | تھیم کی تبدیلی کے بعد (تھیم کا نام `$1` میں) |
| `font-set` | فونٹ کی تبدیلی کے بعد (فونٹ کا نام `$1` میں) |
| `battery-low` | جب بیٹری کم ہو جائے (فیصد `$1` میں) |

`pre-refresh-pacman` hook وہ جگہ ہے جہاں کسٹم repositories یا `IgnorePkg` لائنیں ہونی چاہئیں، کیونکہ یہ package transaction سے پہلے چلتا ہے۔ اپ ڈیٹ سے متعلق دونوں hooks آپ کے صارف کے طور پر اس وقت چلتے ہیں جب Omarchy اپنی cached sudo اجازت صاف کر دیتا ہے، اس لیے جو hook `sudo` استعمال کرتا ہے اسے اپنی اجازت درکار ہوگی اور وہ آپ سے پاس ورڈ مانگ سکتا ہے۔

ان میں سے ہر ڈائریکٹری میں پہلے سے ایک `.sample` فائل موجود ہے جو hook کی شکل دکھاتی ہے — اسے کام میں لانے کے لیے نام سے `.sample` ہٹا دیں۔ کسی اور جگہ لکھی گئی اسکرپٹ انسٹال کرنے کے لیے `omarchy hook install post-boot ~/my-hook` استعمال کریں، جو اسے کاپی کر کے قابلِ عمل بنا دیتا ہے۔

### اپنے مینیو کے اندراجات شامل کرنا

Omarchy مینیو (`Super + Space`) کو `~/.config/omarchy/extensions/omarchy-menu.jsonc` میں ترمیم کر کے اپنی قطاروں کے ساتھ بڑھایا جا سکتا ہے۔ اندراجات ایک نقطہ دار id کے ذریعے کلید بند ہوتے ہیں، اور id ہی انہیں درخت میں رکھتا ہے، اس لیے `personal` روٹ مینیو پر ظاہر ہوتا ہے اور `personal.notes` اس کے اندر ظاہر ہوتا ہے:

```jsonc
"personal": {"icon":"","label":"Personal"},
"personal.notes": {"icon":"󰎞","label":"Notes","action":"omarchy-launch-editor ~/notes"},
```

موجودہ id کو دوبارہ استعمال کریں اور آپ نئی قطار شامل کرنے کے بجائے اس قطار کو تبدیل کر دیں گے۔ فائل میں تمام دستیاب فیلڈز تبصروں کے طور پر دستاویزی شکل میں موجود ہیں۔

### اپنے شیل exports، functions، اور aliases شامل کرنا

Omarchy بہت سے آسان aliases اور مددگار functions کے ساتھ آتا ہے، لیکن اپنے شامل کرنا بہت عام بات ہے۔ آپ کو aliases، functions، اور exports دونوں کو `~/.bashrc` میں شامل کرنا چاہیے۔ یہ فائل اپ ڈیٹس پر تبدیل نہیں ہوگی۔ اگر آپ Omarchy کے کسی ڈیفالٹ کو تبدیل کرنا چاہتے ہیں، تو آپ انہیں یہاں محفوظ طریقے سے بھی شامل کر سکتے ہیں۔

### ڈیسک ٹاپ کے لیے environment variables مقرر کرنا

ڈیسک ٹاپ سیشن کے exports `~/.config/uwsm/env.d/` میں ہوتے ہیں۔ یہ فائلیں آپ کے ڈیسک ٹاپ شروع ہونے سے پہلے چلتی ہیں، اس لیے شیل کی خرابی آپ کو لاگ ان اسکرین پر واپس بھیج سکتی ہے۔ ان میں ترمیم کرتے وقت ایک کام کرنے والا ٹرمینل کھلا رکھیں۔ کسی override کو غیر فعال کرنے کے لیے، اسے `env.d` سے باہر منتقل کریں۔ اگر کوئی تبدیلی لاگ ان کو روکتی ہے تو [login recovery](45-troubleshooting.md#my-password-is-accepted-but-i-return-to-the-login-screen) دیکھیں۔

### اندرونی Omarchy فائلوں کو تبدیل کرنا

دیکھیں، یہ آپ کا کمپیوٹر ہے۔ آپ اس کے ساتھ جو چاہیں کر سکتے ہیں، لیکن میں `/usr/share/omarchy` میں موجود فائلوں میں براہ راست تبدیلیاں کرنے کے خلاف مشورہ دوں گا۔ وہ Omarchy pacman package سے تعلق رکھتی ہیں، اس لیے آپ کی تبدیلیاں اگلی اپ ڈیٹ پر بس تبدیل ہو جائیں گی۔ اس کے بجائے آپ کے لیے بہتر ہے کہ جن ڈیفالٹ قدروں کو آپ پسند نہیں کرتے انہیں `~/.config/*` فولڈر میں تبدیل کر دیں۔

آپ اس طریقے سے تقریباً ہر چیز تبدیل کر سکتے ہیں، جیسے ڈیفالٹ کی بائنڈنگز۔ بس `~/.config/hypr/bindings.lua` میں ترمیم کر کے، مثال کے طور پر، [Obsidian](https://obsidian.md/) کو [Joplin](https://joplinapp.org/) سے بدل دیں (`omarchy-pkg-add joplin-bin` کے ساتھ انسٹال کریں):

```lua
o.rebind("SUPER + SHIFT + O", "Joplin", "joplin-desktop")
```

`o.rebind` اپنی جگہ لینے والی بائنڈنگ شامل کرنے سے پہلے موجودہ بائنڈنگ کو ہٹا دیتا ہے۔ یہ `o.bind` جیسے ہی دلائل لیتا ہے، بشمول launch helpers اور binding options۔ بائنڈنگ شامل کرنے کے لیے `o.bind` استعمال کریں، یا اسے تبدیل کیے بغیر ہٹانے کے لیے `hl.unbind` استعمال کریں۔

اگر آپ اندرونی Omarchy فائلوں پر ہیکنگ کرنے پر اصرار کرتے ہیں، تو _Update > Channel > Dev_ کے ذریعے dev چینل پر سوئچ کریں۔ اس سے Omarchy `~/omarchy` میں سورس کوڈ کے git checkout سے منسلک ہو جاتا ہے، جسے آپ دل بھر کر تبدیل کرنے کے لیے آزاد ہیں۔ یہاں کوئی آپ کو یہ بتانے والا نہیں کہ کیا کرنا ہے!

### کسی بھی تبدیلی کو ری سیٹ کرنا

اگر آپ ترتیبات کو خراب کر دیتے ہیں، تو آپ انہیں Omarchy مینیو میں _Update > Config_ کے ذریعے ہمیشہ ڈیفالٹس پر واپس لا سکتے ہیں۔ یا سب کچھ ری سیٹ کرنے کے لیے `omarchy reinstall configs` چلا کر۔
