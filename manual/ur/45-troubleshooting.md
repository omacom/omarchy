# خرابیوں کا ازالہ

### اپ ڈیٹ سے میرا سسٹم خراب ہو گیا ہے!

پہلے اپنے حالیہ اپ ڈیٹ سے پہلے والے ورژن پر [اپنا سسٹم واپس لے جانے](47-system-snapshots.md) کی کوشش کریں۔ اگر یہ کام نہ کرے تو Discord میں #omarchy-help پر اپنے مسئلے کے ساتھ شیئر کرنے کے لیے `omarchy-debug` استعمال کریں۔ اور اگر یہ سب بھی ناکام ہو جائے تو آپ `omarchy-reinstall` استعمال کر کے ڈیفالٹ کنفگز اور پیکجز دوبارہ انسٹال کر سکتے ہیں۔

### میرے ڈسپلے پر کچھ ایپس اتنی بڑی کیوں نظر آتی ہیں؟

Omarchy فرض کرتا ہے کہ آپ کے پاس 2x ہائی ریزولوشن ڈسپلے ہے، اس لیے یہ `GDK_SCALE` کو 2 پر سیٹ کر دیتا ہے جب تک آپ مانیٹر پینل میں اسکیل منتخب نہ کر لیں۔ اگر آپ 1x ڈسپلے پر ہیں اور GTK یا X11 ایپس بہت بڑی نظر آتی ہیں تو مانیٹر پینل میں اس کے لیے 1x منتخب کریں، یا `~/.config/hypr/monitors.lua` میں `hl.env("GDK_SCALE", "1")` شامل کریں (اور پھر جو ایپ بہت بڑی نظر آ رہی ہو اسے دوبارہ شروع کریں)۔ [مانیٹرز پر مینوئل](33-monitors.md) دیکھیں۔

Spotify کے لیے، آپ UI کو چھوٹا کرنے کے لیے `Ctrl + Minus` استعمال کر سکتے ہیں (اور اسے بڑا کرنے کے لیے `Ctrl + Plus`)۔

### میرے تمام Super کی بائنڈز نے کام کرنا کیوں بند کر دیا؟

کچھ ASUS ROG اور TUF لیپ ٹاپس پر، `Fn + Super` ایک آسانی سے نظر انداز ہو جانے والا مجموعہ ہے جو فرم ویئر کے Windows-key لاک کو ٹوگل کرتا ہے (یہ گیمنگ کے لیے ہے تاکہ آپ غلطی سے گیم سے باہر نہ نکل جائیں)۔ اسکرین پر کچھ بھی آپ کو نہیں بتاتا کہ یہ ہو گیا ہے۔ جب لاک آن ہوتا ہے تو Super بالکل کچھ بھی نہیں بھیجتا — اس لیے Super استعمال کرنے والا ہر Omarchy بائنڈ بس رک جاتا ہے، اور ایسا لگتا ہے جیسے Hyprland خراب ہو گیا ہو۔

`~/.config/hypr/` میں کھوج شروع کرنے سے پہلے ایک بار `Fn + Super` دبائیں، اور اگر اس سے Super واپس نہ آئے تو اسے دوبارہ دبائیں تاکہ آپ لاک کو آن نہ چھوڑ دیں۔ یہ Fn-lock نہیں ہے، جو صرف F-key قطار کے کام کو بدلتا ہے۔

### میرا Wi-Fi، Bluetooth، آڈیو، یا ٹریک پیڈ اچانک کام کرنا بند کر گیا ہے

ری بوٹ کرنے سے پہلے، خرابی پیدا کرنے والے سب سسٹم کو اکیلے دوبارہ شروع کرنے کی کوشش کریں۔ Omarchy مینو میں _Update > Hardware_ کے تحت Wi-Fi، Bluetooth، Audio، اور Trackpad موجود ہیں، اور ان میں سے کسی ایک کو دوبارہ لوڈ کرنے سے "یہ پانچ منٹ پہلے کام کر رہا تھا" والی بیشتر صورتحال ٹھیک ہو جاتی ہے — ایک Bluetooth ہیڈسیٹ جو دوبارہ کنیکٹ نہ ہو رہا ہو، ایک ٹریک پیڈ جو سسپینڈ کے بعد بند ہو گیا ہو، آواز جو مانیٹر ان پلگ کرتے وقت غائب ہو گئی ہو۔

### میرے بیرونی اسپیکرز کیوں نہیں بج رہے؟

شاید اس لیے کہ وہ پرائمری آؤٹ پٹ کے طور پر سیٹ نہیں ہیں۔ بار کے دائیں طرف اسپیکر آئیکن پر کلک کریں، اور یہ والیوم پاپ اپ کھول دے گا جہاں آپ آؤٹ پٹ ڈیوائس منتخب کر سکتے ہیں (اور فی ایپ والیوم کو مکس بھی کر سکتے ہیں)۔

### میرے لیپ ٹاپ اسپیکرز کی آواز عجیب لگتی ہے

کچھ لیپ ٹاپس پر، Omarchy خودکار طور پر ایک اسپیکر ٹیوننگ لاگو کرتا ہے جو بلٹ ان اسپیکرز کی فریکوئنسی رسپانس کو درست کرتی ہے۔ `omarchy audio tuning status` آپ کو بتاتا ہے کہ آیا آپ کی مشین پر کوئی ٹیوننگ فعال ہے، اور اگر آپ اسپیکرز کو خام حالت میں سننا پسند کریں تو `omarchy audio tuning off` اسے بند کر دیتا ہے۔

### میں اپنے پاس ورڈ سے لاگ ان یا sudo کیوں نہیں کر سکتا؟

آپ نے شاید اسے بہت بار غلط ٹائپ کیا ہے اور لاک آؤٹ ہو گئے ہیں۔ اگر یہ لاک اسکرین پر ہو رہا ہے تو آپ نیا TTY شروع کرنے کے لیے `CTRL + ALT + F2` دبا سکتے ہیں جہاں آپ root کے طور پر لاگ ان کر سکتے ہیں، پھر `faillock --reset --user [your-username]` چلائیں۔ اس سے لاک آؤٹ ری سیٹ ہو جائے گا، اور آپ کا کام ہو جائے گا۔

### میرا پاس ورڈ قبول ہو جاتا ہے، لیکن میں لاگ ان اسکرین پر واپس آ جاتا ہوں

خراب سیشن انوائرنمنٹ فائل ڈیسک ٹاپ کو شروع ہونے سے روک سکتی ہے چاہے آپ کا پاس ورڈ درست ہی کیوں نہ ہو۔ `~/.config/uwsm/env.d/` میں ترمیم کے بعد یہ خاص طور پر چیک کرنے کے قابل ہے۔

`Ctrl + Alt + F2` دبائیں، اپنے عام صارف نام اور پاس ورڈ سے لاگ ان کریں، اور موجودہ بوٹ کا یوزر جرنل دیکھیں:

```bash
journalctl --user -b -t uwsm_env-preloader --no-pager
```

ایسی غلطی تلاش کریں جس میں آپ کی انوائرنمنٹ فائلوں میں سے کسی کا نام ہو، جیسے `bad substitution`، اس پیغام سے بالکل پہلے کہ env آؤٹ پٹ مارک نہیں ملا۔ دوبارہ لاگ ان کرنے کی کوشش سے پہلے اس فائل کو `env.d` سے باہر منتقل کریں۔ مثال کے طور پر، اگر غلطی میں `99-custom` کا نام آتا ہے:

```bash
mkdir -p ~/.config/uwsm/disabled
mv -i ~/.config/uwsm/env.d/99-custom ~/.config/uwsm/disabled/
```

UWSM نحو کی غلطی والی فائل کو چھوڑ دیتا ہے، لیکن ایک مہلک غلطی جو صرف فائل چلنے کے دوران ظاہر ہوتی ہے، جیسے `bad substitution`، پھر بھی ڈیسک ٹاپ کو شروع ہونے سے روک سکتی ہے۔ سسٹم اسنیپ شاٹ رول بیک ان فائلوں کی مرمت نہیں کرتا، کیونکہ `/home` کو رول بیک نہیں کیا جاتا۔

جب آپ لاگ ان کر سکیں تو محفوظ شدہ کاپی کو واپس منتقل کرنے سے پہلے اسے ٹھیک کریں۔ `sh -n` فائل کو چلائے بغیر نحو کی غلطیاں پکڑ لیتا ہے، لیکن سورس کیے جانے پر ہونے والی ہر غلطی کو نہیں پکڑ سکتا۔ تبدیلیوں کی جانچ کرتے وقت ایک چلتا ہوا ٹرمینل کھلا رکھیں۔

### 1Password SSH Agent / CLI کے لیے میری 1Password اجازت کی پرامپٹس کیوں ظاہر نہیں ہوتیں؟

یہ 2 وجوہات کی بنا پر ہو سکتا ہے:

تفصیلی منظوری پرامپٹ ظاہر ہونے کے لیے، Settings > Advanced > Use Hardware Acceleration کو آن کرنا ضروری ہے۔ _نوٹ: اس کے کام شروع کرنے کے لیے ری بوٹ درکار ہے۔_

 ![troubleshooting-1password](images/troubleshooting-1password.webp)
