Omarchy میں آپ کے لیے کوئی ڈیفالٹ منتخب کیے بغیر نیچے دیے گئے کوڈنگ ایجنٹس کے لانچرز شامل ہیں۔ پہلی بار استعمال پر اس کی CLI انسٹال کرنے کے لیے کمانڈ چلائیں، پھر جب کہا جائے تو تصدیق کریں۔ Hermes اور OpenClaw اس سے مستثنیٰ ہیں: ان کے لیے mise کے ذریعے کچھ انسٹال نہیں ہوتا، اور ان میں سے کسی کو منتخب کرنے پر اس کی اپنی خودکار اپ ڈیٹ ہونے والی کاپی سیٹ اپ ہو جاتی ہے، جیسا کہ نیچے _ڈیسک ٹاپ ایپس_ میں بیان کیا گیا ہے۔

### ایجنٹس انسٹال اور اپ ڈیٹ کرنا

Hermes اور OpenClaw کے علاوہ، یہ ایجنٹس mise کی سست انسٹالیشن استعمال کرتے ہیں: پہلی بار شروع کرنے پر CLI انسٹال ہو جاتی ہے، اور بعد میں شروع کرنے پر اسی کو دوبارہ استعمال کیا جاتا ہے۔ mise انسٹال شدہ ایجنٹ کے لیے نئی ریلیز بھی زیادہ سے زیادہ ہر چار گھنٹے میں ایک بار چیک کرتا ہے، شروع ہونے سے بالکل پہلے یا پس منظر میں شیل پرمپٹ پر۔ اگر وہ اپ ڈیٹ ناکام ہو جائے یا آپ آف لائن ہوں تو انسٹال شدہ ورژن چلتا ہے۔ `omarchy update` انسٹال شدہ ایجنٹس کو Omarchy کے باقی حصے کے ساتھ اپ ڈیٹ کرتا ہے، اور `mup` صرف mise کے زیر انتظام ٹولز اپ ڈیٹ کرتا ہے۔

کسی ایجنٹ کا اپنا اپڈیٹر، جیسے `claude update`، `codex update` یا کسی ایپ میں اپ ڈیٹ کا بٹن، mise کے زیر انتظام انسٹال کو اپ ڈیٹ نہیں کرتا۔ `codex update` ناکام ہو جاتا ہے، اور `claude update` کامیابی کی اطلاع دے سکتا ہے جبکہ وہ ایک الگ کاپی انسٹال کر رہا ہو جسے mise ٹریک نہیں کرتا۔ اگر آپ اس کے بجائے کسی ایجنٹ کا اپنا انسٹالر اور اپڈیٹر استعمال کرنا چاہتے ہیں تو اسے `disable_tools` میں شامل کریں؛ دیکھیں [پہلے سے انسٹال شدہ CLI ٹولز](18-development-tools.md#preinstalled-cli-tools)۔

تمام ترتیب شدہ سست ٹولز کو ضرورت پڑنے سے پہلے انسٹال کرنے کے لیے `mise install --include-lazy` چلائیں۔ اس میں ایجنٹس کے ساتھ Omarchy کے دوسرے ڈیفالٹ CLI ٹولز بھی شامل ہیں۔ کسی ایک ٹول کو انسٹال کرنے یا اپنی انسٹالیشن استعمال کرنے کے لیے دیکھیں [پہلے سے انسٹال شدہ CLI ٹولز](18-development-tools.md#preinstalled-cli-tools)۔

`grok` کو mise کے فرسٹ پارٹی `grok` پیکیج کے ذریعے انسٹال کیا جاتا ہے، اسی طرح جیسے `claude` اور `codex` کو کیا جاتا ہے۔ `grok` چلائیں، یا اسے _Agent > Harness_ کے تحت منتخب کریں۔ x.ai پر موجود `curl | bash` انسٹالر کو چھوڑ دیں۔ وہ راستہ `~/.grok/bin` میں دوسری کاپی رکھتا ہے، اسے `PATH` میں سب سے پہلے شامل کر دیتا ہے، اور Omarchy کے ریپر کو اوور رائٹ کر دیتا ہے۔

`dsh` اپنا براؤزر UI `127.0.0.1:3080` پر کھولتا ہے، جس میں لانچ ڈائریکٹری اس کی ڈیفالٹ ورک اسپیس ہوتی ہے۔ اس کا براؤزر UI کوئی ابتدائی پرمپٹ نہیں لیتا، لہٰذا `omarchy agent prompt` اسے اس پرمپٹ کے ساتھ کھولتا ہے جو آپ کے کلپ بورڈ پر چسپاں کرنے کے لیے موجود ہوتا ہے۔ Omarchy اسے DeepSeek کے بغیر منظوری والے اجازت پری سیٹ کے ساتھ شروع کرتا ہے۔ جب آپ اس کا سرکاری ماڈل API استعمال کرتے ہیں تو DeepSeek Harness سیشن لاگز DeepSeek پر اپ لوڈ کرتا ہے؛ اسے اس کے براؤزر UI میں _Settings > General > Upload Session Log_ کے تحت بند کر دیں۔ جو فیڈ بیک آپ اسے بھیجتے ہیں وہ بھی سیشن کے ساتھ اپ لوڈ ہو جاتا ہے، جب تک کہ آپ اسے `DSH_TELEMETRY_MODE=DISABLED` کے ساتھ شروع نہ کریں۔

### ڈیفالٹ ایجنٹ

اپنا ڈیفالٹ ایجنٹ `omarchy default agent <name>` کے ساتھ یا Omarchy Menu (`Super + Space`) میں _Agent > Harness_ کے تحت منتخب کریں۔ اگر ایجنٹ ابھی انسٹال نہیں ہوا تو اسے منتخب کرنے پر وہ پہلے انسٹال ہو جاتا ہے، اور اسے ایپ لانچر میں Agent کے ساتھ ساتھ اپنا ایک لانچر بھی مل جاتا ہے۔ ایک نئی Omarchy آپ کو ایک بار کی اطلاع کے ساتھ یہ انتخاب کرنے کی دعوت دے گی۔

Claude کو منتخب کرنے پر Chromium، Chrome، Brave، Brave Origin اور Edge کے لیے اس کی براؤزر ایکسٹینشن سیٹ اپ کرنے کی بھی کوشش کی جاتی ہے۔ ایکسٹینشن کا سیٹ اپ تمام صارفین پر لاگو ہوتا ہے اور آپ سے آپ کا سسٹم پاس ورڈ مانگ سکتا ہے؛ منسوخ کرنے یا ایکسٹینشن کی انسٹالیشن ناکام ہونے پر بھی Claude منتخب اور شروع ہو جاتا ہے۔ اپنا براؤزر دوبارہ شروع کریں، کہا جائے تو ایکسٹینشن فعال کریں، اور اسے جوڑنا مکمل کرنے کے لیے Claude میں سائن ان کریں۔ کنکشن چیک کرنے کے لیے Claude میں `/chrome` چلائیں۔ Firefox اور Zen اس ایکسٹینشن کی حمایت نہیں کرتے۔ اگر یہ سیٹ اپ شامل کیے جانے سے پہلے ہی Claude آپ کا ڈیفالٹ تھا تو ایکسٹینشن انسٹال کرنے کے لیے اسے دوبارہ منتخب کریں۔

جب آپ انتخاب کر لیں تو `Super + Shift + Ctrl + A` ڈیفالٹ ایجنٹ کو ایک مخصوص ٹرمینل ونڈو میں شروع کرتا ہے (یا اگر آپ نے ابھی انتخاب نہیں کیا تو منتخب کنندہ سامنے لاتا ہے)۔ آپ اسے `omarchy agent prompt "Review this project"` کے ساتھ سیدھا کسی کام میں بھی شروع کر سکتے ہیں۔ Freebuff اور DeepSeek Harness کوئی ابتدائی پرمپٹ نہیں لیتے، لہٰذا وہ اس کے بجائے آپ کے کلپ بورڈ پر موجود پرمپٹ کے ساتھ کھلتے ہیں تاکہ آپ اسے چسپاں کر سکیں۔ اس طرح شروع کیے گئے ایجنٹس اپنے متعلقہ نہ رکنے اور نہ پوچھنے والے طریقوں میں بغیر نگرانی کے چلتے ہیں، لہٰذا اس کے لیے تیار رہیں کہ وہ واقعی کچھ کریں گے! MiniMax Code کے پاس اپنے انٹرایکٹو سیشنز کے لیے ایسا کوئی طریقہ نہیں ہے، لہٰذا وہ معمول کے مطابق اجازتیں مانگتا ہے۔ اور چونکہ ایجنٹس آپ کی ہوم ڈائریکٹری کے لیے بھروسا یاد رکھنے سے انکار کرتے ہیں، اس لیے `$HOME` سے شروع کی گئی لانچیں اس کے بجائے `~/Work` میں شروع ہوتی ہیں۔

ٹرمینل شارٹ کٹس بھی ہیں: `a` موجودہ ٹرمینل میں ڈیفالٹ ایجنٹ کو ان لائن چلاتا ہے، جبکہ `c`، `cx` اور `cy` براہ راست OpenCode، Claude Code اور Codex شروع کرتے ہیں (ایک بار پھر ان کے خودکار منظوری والے طریقوں میں)۔ تھیم کی تبدیلیاں ایجنٹس کے ساتھ بھی ہم آہنگ ہو جاتی ہیں: جب آپ Omarchy کی تھیم تبدیل کرتے ہیں تو Claude Code، Pi، OpenCode اور Hermes (جب Omarchy نے اسے انسٹال کر لیا ہو) سب اس کے ساتھ ساتھ چلتے ہیں۔

### آپ کی ایجنٹ ہدایات

ہر ایجنٹ کے لیے ذاتی قواعد `~/.agents/AGENTS.md` میں جاتے ہیں، `~/.agents/skills` میں مشترکہ اسکلز کے ساتھ۔ اسے _Agent > Instructions_ کے تحت کھولیں، جو اسے ہر اس ہارنس میں بھی جوڑ دیتا ہے جو اپنی عالمی فائل رکھتا ہے: `~/.claude/CLAUDE.md`، `~/.codex/AGENTS.md`، `~/.pi/agent/AGENTS.md`، `~/.config/opencode/AGENTS.md`، Copilot کی `~/.copilot/copilot-instructions.md`، وغیرہ وغیرہ۔ Crush اور Amp `~/.config/AGENTS.md` والا لنک پڑھتے ہیں، جبکہ omp، Kimi اور DeepSeek Harness براہ راست `~/.agents/AGENTS.md` پڑھتے ہیں۔ ڈیفالٹ ایجنٹ منتخب کرنے پر وہ بھی اسے جوڑ دیتا ہے۔ اگر پہلے سے کوئی ہدایات فائل آپ کے پاس موجود تھی اور ابھی کوئی مشترکہ فائل نہیں تھی تو وہی مشترکہ بن جاتی ہے؛ ورنہ اسے لنک کے ساتھ `.bak` کے طور پر رکھا جاتا ہے۔ ایک اور ایجنٹ انسٹال کرنے کے بعد دوبارہ جوڑنے کے لیے `omarchy agent instructions` چلائیں۔

### ایجنٹس پینل

اوپر والی بار میں ایک ایجنٹس آئیکن ہے۔ اس سے پہلے کہ آپ نے کوئی ایجنٹ سیٹ اپ کیا ہو، اس کا پینل آپ کو Claude، Codex یا Grok میں سائن ان کرنے کے مراحل سے گزارتا ہے، اور پہلا والا آپ کا ڈیفالٹ ایجنٹ بن جاتا ہے۔ اس کے بعد، پینل ہر سبسکرپشن کو ایک صفحے پر رکھتا ہے: ہر ایجنٹ اور اکاؤنٹ اس کے پلان کے ساتھ، اس کی 5 گھنٹے کے سیشن اور ہفتہ وار حدود میں سے ہر ایک کے لیے ایک میٹر ری سیٹ ہونے تک کے وقت کے ساتھ (درست فیصد کے لیے ہوور کریں)، یا باقی پری پیڈ بیلنس، ایک سطر کے نیچے جو ان سب میں آپ کے استعمال کی چیزوں میں گھومتی رہتی ہے، جیسے اس ہفتے کے ٹوکنز اور آپ کا سب سے زیادہ استعمال شدہ ماڈل۔ _Make something cool_ کے تحت یہ نئی تھیم، پلگ ان، ایپ یا گیم کے لیے ابتدائی پرمپٹس پیش کرتا ہے جو کام آپ کے ڈیفالٹ ایجنٹ کے حوالے کرتے ہیں۔ ایپس اسی طرح بنائی جاتی ہیں جس طرح Omarchy کی اپنی Hype، Monologue اور Omacut ہیں، C++ اور Qt Quick میں، omarchy-make-app ایجنٹ اسکل کی پیروی کرتے ہوئے، اور انہیں درکار کمپائلر اور Qt کے حصے انسٹال شدہ آتے ہیں۔ گیمز `~/Games/vibes` میں ایک واحد three.js صفحہ ہوتی ہیں، omarchy-make-game ایجنٹ اسکل کی پیروی کرتے ہوئے، اور سب موجودہ تھیم میں ایک Game Vibes لانچر سے کھلتی ہیں؛ وہ three.js ویب سے لوڈ کرتی ہیں، لہٰذا انہیں شروع ہونے کے لیے کنکشن درکار ہوتا ہے۔ Claude Code، Codex، Grok، Kimi، Cursor اور اس کا Grok Bot الاؤنس، GitHub Copilot، Muse، Antigravity اور Devin اپنی حدود کے ساتھ ابتدا ہی سے شامل ہیں، Kimchi اپنے پلان، پری پیڈ کریڈٹس اور اخراجات کے بجٹس کے ساتھ، اور Hermes، Mistral Vibe اور Qwen Code جب آپ انہیں استعمال کر لیں تو اپنے سیشنز اور ٹوکنز دکھاتے ہیں۔ فراہم کنندہ کے پلانز اور کیز جو آپ pi، omp یا opencode کے ذریعے استعمال کرتے ہیں وہ بھی ظاہر ہوتے ہیں: OpenCode Zen اور Go، Z.ai GLM Coding Plan، Ollama Cloud، MiniMax Token Plan اور Synthetic اپنی حدود کے ساتھ؛ OpenRouter اور DeepSeek اپنے پری پیڈ بیلنسز کے ساتھ؛ Fireworks پچھلے 30 دنوں میں اپنے اخراجات کے ساتھ؛ اور وہ ماڈلز جو آپ Local models کے تحت اپنے ہارڈ ویئر پر چلاتے ہیں۔ ہر ایجنٹ کو ایک بار گنا جاتا ہے، اس کے تحت جو بھی اس کا بل دیتا ہے، آپ اسے کتنے ہی ہارنسز کے ذریعے چلائیں۔

پینل کے لیے بار آئیکن پر بائیں کلک کریں یا `Super + Ctrl + X` دبائیں، اپنے ڈیفالٹ ایجنٹ کو شروع کرنے کے لیے دائیں کلک کریں، اور تازہ کرنے کے لیے درمیانی کلک کریں۔ اس کے پیچھے موجود استعمال کے ریکارڈز ہر 15 منٹ بعد `omarchy agent usage update` کے ذریعے دوبارہ بنائے جاتے ہیں، اور پینل ایک ہم آہنگ فولڈر کے ذریعے آپ کی دوسری مشینوں سے استعمال کو ضم بھی کر سکتا ہے۔ مکمل ترتیبات کے لیے `$OMARCHY_PATH/shell/plugins/agents/` کے تحت README دیکھیں۔

### متعدد سبسکرپشنز

اگر آپ ایک سے زیادہ Claude، Codex یا Grok پلان کی ادائیگی کرتے ہیں — مثلاً ایک ذاتی Max اور ایک کام والا — تو Omarchy ان سب کو سائن ان رکھ سکتا ہے اور ان کے درمیان منتقل ہو سکتا ہے۔ ایجنٹس پینل میں + کے ساتھ سبسکرپشن شامل کریں، جو آپ کو وہیں اس کے مراحل سے گزارتا ہے، یا `omarchy agent account add claude Work` (یا `codex` یا `grok`) کے ساتھ شامل کریں۔ اگر CLI موجود نہ ہو تو یہ اسے انسٹال کر دیتا ہے۔ کسی فراہم کنندہ کا پہلا اکاؤنٹ آپ کے عام براؤزر کے ذریعے سائن ان ہوتا ہے، بالکل وہیں جہاں CLI ہمیشہ دیکھتا ہے۔ اس کے بعد والا ہر اکاؤنٹ ایک نجی ونڈو کے ذریعے سائن ان ہوتا ہے، تاکہ وہ اکاؤنٹ جس میں آپ کا براؤزر پہلے ہی سائن ان ہے غلطی سے نہ پکڑا جائے؛ وہاں اس اکاؤنٹ کے طور پر سائن ان کریں جسے آپ شامل کر رہے ہیں، اور پہلے سے کھلی ہوئی کسی بھی نجی ونڈو کو پہلے بند کر دیں۔ اس کے لیے CLI سے کبھی لاگ آؤٹ نہ کریں: لاگ آؤٹ کرنے سے محفوظ شدہ سائن ان منسوخ ہو جاتا ہے، اور اس اکاؤنٹ کو دوبارہ شامل کرنا پڑے گا۔

اپنے سبسکرپشن لاگ انز کو SSH کے ذریعے کسی دوسری Omarchy مشین پر نقل کرنے کے لیے `omarchy agent account copy user@laptop` چلائیں۔ جب منزل پر کوئی انسٹال نہ ہو تو بھیجنے والا ایک عارضی وصول کنندہ فراہم کرتا ہے، تاکہ پرانی Omarchy مشینیں بغیر اپ ڈیٹ کے اکاؤنٹس وصول کر سکیں۔ انسٹال شدہ وصول کنندگان کو ترجیح حاصل ہوتی ہے۔ یہ تمام Claude، Codex اور Grok سبسکرپشنز کی نقل کرتا ہے؛ انہیں منتخب کرنے کے لیے فراہم کنندگان کے نام شامل کریں، جیسے `omarchy agent account copy laptop claude` میں ہے۔ اکاؤنٹ کے نام اور کمانڈ آئی ڈیز ماخذ سے ملتے ہیں، بشمول وہ اکاؤنٹس جو منزل پر پہلے سے موجود ہیں۔ غیر متعلقہ منزل اکاؤنٹس کو اگر ان کے ناموں میں تصادم ہو تو عددی لاحقہ ملتا ہے، اور ترتیبات، اسکلز، پلگ انز اور گفتگو کی تاریخ ہر مشین پر مقامی رہتی ہے۔

منزل کی موجودہ اسناد برقرار رکھی جاتی ہیں۔ وہ ماخذ اکاؤنٹ جو وہاں پہلے سے سائن ان ہے اس کا نام اس کی اسناد کو بدلے بغیر ہم آہنگ کر دیا جاتا ہے؛ دوسرے اکاؤنٹس اس کے ساتھ شامل کر دیے جاتے ہیں۔ مماثل اکاؤنٹس کے لیے محفوظ شدہ اسناد کو بدلنے کے لیے، منزل پر اس اکاؤنٹ کے سیشنز بند کرنے کے بعد `omarchy agent account copy --replace laptop claude` استعمال کریں۔ ایک نئی منزل کو ماخذ کا فعال اکاؤنٹ اور تبدیلی کی ترجیحات بھی ملتی ہیں؛ ایک قائم شدہ منزل اپنی ترجیحات برقرار رکھتی ہے۔

اسناد SSH کے ذریعے سفر کرتی ہیں اور منزل پر نجی فائلوں میں محفوظ ہوتی ہیں، لہٰذا صرف ان مشینوں پر نقل کریں جن پر آپ بھروسا کرتے ہیں۔ یہ ایک بار کی نقل ہے، جاری ہم آہنگی نہیں۔ Codex کے ریفریش ٹوکنز کو دوسری مشین گھما سکتی ہے، جس سے نقل شدہ لاگ ان کو تجدید کی ضرورت پڑ جاتی ہے؛ متعدد مشینوں پر بیک وقت استعمال کے لیے الگ الگ سائن ان سب سے قابل اعتماد انتخاب رہتے ہیں۔ دیکھیں [Codex کی اکاؤنٹ تصدیق کی رہنمائی](https://developers.openai.com/codex/auth/ci-cd-auth)۔

ہر فراہم کنندہ کے لیے ایک اکاؤنٹ فعال ہوتا ہے، اور ہر نیا سیشن اسی کے طور پر شروع ہوتا ہے: `cx`، `cy`، ایک سادہ `claude`، `codex` یا `grok`، `omarchy agent` کے ذریعے شروع کی گئی کوئی بھی چیز، اور اسکرپٹس یا ایڈیٹرز جو `PATH` پر CLI تلاش کرتے ہیں۔ `omarchy agent account use work` کے ساتھ تبدیل کریں (اور `omarchy agent account use main` کے ساتھ واپس جائیں)، یا پینل میں اکاؤنٹ کا نمبر دبا کر پھر `Enter` دبا کر (یا اس کے Use بٹن پر کلک کر کے) تبدیل کریں۔ چل رہے Claude سیشنز بھی اپنے اگلے پیغام سے تبدیل ہو جاتے ہیں: ہر Claude سیشن `~/.claude` میں چلتا ہے، جس میں ہمیشہ فعال اکاؤنٹ کا سائن ان ہوتا ہے۔ پرانی Omarchy کے ذریعے کسی اکاؤنٹ کے اپنے فولڈر میں شروع کیا گیا Claude سیشن اس سائن ان کو بند ہونے تک رکھتا ہے، لہٰذا تبدیلی ان سیشنز کے نام بتاتی ہے اور ان کے ختم ہونے پر خود مکمل ہو جاتی ہے۔ چل رہے Codex اور Grok سیشنز اسی اکاؤنٹ پر رہتے ہیں جس سے وہ شروع ہوئے تھے۔ گفتگو کی تاریخ، ترتیبات، اسکلز اور پلگ انز اکاؤنٹس میں مشترکہ ہوتے ہیں، لہٰذا اسی فولڈر میں `claude --continue` نئے اکاؤنٹ پر وہیں سے شروع ہوتا ہے جہاں آپ نے چھوڑا تھا۔

ایک سے زیادہ اکاؤنٹ کے ساتھ، پینل ہر اکاؤنٹ کی حدود ساتھ ساتھ دکھاتا ہے، جس میں فعال اکاؤنٹ نشان زد ہوتا ہے۔ بطور ڈیفالٹ Omarchy آپ کو اس وقت مطلع کرتا ہے جب فعال اکاؤنٹ کسی حد کے 95% سے گزر جاتا ہے، اور اطلاع پر کلک کرنے سے سب سے زیادہ گنجائش والے اکاؤنٹ پر منتقل ہو جاتا ہے۔ پینل میں کسی اکاؤنٹ کی سطر پر ہوور کریں اور Use کے ساتھ ظاہر ہونے والے Autoswitch پر کلک کریں (یا `m` دبائیں)، یا `omarchy agent account mode auto` چلائیں، تاکہ وہ اس کے بجائے خود تبدیل ہو جائے؛ جب یہ فعال ہو تو Autoswitch Use کی جگہ لے لیتا ہے، اور اس پر دوبارہ کلک کرنے سے واپس مطلع کرنے پر آ جاتا ہے۔ حد تبدیل کرنے کے لیے ایک نمبر شامل کریں، جیسے `omarchy agent account mode auto 90` میں ہے۔ اگر ہر اکاؤنٹ حد سے اوپر ہو تو آپ کو اس کے بارے میں ایک بار بتایا جائے گا، اس کے ساتھ کہ کون سا اکاؤنٹ سب سے پہلے خالی ہوتا ہے۔ جب کوئی فعال اکاؤنٹ اپنی حد کے 15 پوائنٹس کے اندر ہو (ڈیفالٹ پر 80%) تو اس کی حدود ہر 15 کے بجائے ہر تین منٹ بعد چیک کی جاتی ہیں۔

`omarchy agent account list` ہر اکاؤنٹ اور اس کی تازہ ترین حدود دکھاتا ہے، `omarchy agent account remove work` ایک کو بھلا دیتا ہے، اور `omarchy agent account rename primary Hey` ایک کا نام بدل دیتا ہے (یا پینل میں اکاؤنٹ کے نام پر کلک کریں)۔ یہ کمانڈز آپ کے ڈیفالٹ ایجنٹ کے اکاؤنٹس پر کام کرتی ہیں؛ دوسرے فراہم کنندہ تک پہنچنے کے لیے پہلے اس کا نام لیں، جیسے `omarchy agent account use codex side` میں ہے۔ وہ لاگ ان جو آپ کے پاس `~/.claude` یا `~/.codex` میں پہلے سے تھا وہ _Main_ اکاؤنٹ ہے۔ Codex کا وہیں رہتا ہے جہاں وہ ہے؛ Claude کا جب کوئی دوسرا اکاؤنٹ فعال ہو تو اپنے فولڈر میں انتظار کرتا ہے۔ آٹھ گھنٹے سے زیادہ عرصے تک غیر استعمال شدہ چھوڑا گیا اکاؤنٹ _Sign-in required_ دکھا سکتا ہے؛ اس اکاؤنٹ کو پینل میں ہی دوبارہ سائن ان کرنے کے لیے اس پر کلک کریں، یا اس پر منتقل ہو کر ایک سیشن شروع کریں، جو سائن ان کو خود تازہ کر دیتا ہے۔ `claude mcp add` کے ساتھ آپ جو MCP سرورز شامل کرتے ہیں وہ ہر Claude اکاؤنٹ تک پہنچتے ہیں، کیونکہ وہ سب `~/.claude` میں چلتے ہیں؛ Codex اور Grok کے لیے، اکاؤنٹ شامل کیے جانے کے وقت آپ کے پاس موجود سرورز اس کے ساتھ آ جاتے ہیں، لیکن بعد والے صرف اس اکاؤنٹ تک پہنچتے ہیں جس میں آپ نے انہیں شامل کیا تھا۔ Claude Desktop اپنا سائن ان رکھتا ہے، اور CLI بائنری کے مطلق راستے کے ساتھ ترتیب شدہ Codex یا Grok ٹولز تبدیلی کی پیروی نہیں کرتے۔ ایک واضح `CLAUDE_CONFIG_DIR`، `CODEX_HOME` یا `GROK_HOME` منتخب شدہ اکاؤنٹ پر ترجیح رکھتا ہے۔

### کریش کی تشخیص

Omarchy پراسیس کریشز کے لیے systemd-coredump پر نظر رکھتا ہے۔ جب آپ نے ڈیفالٹ ایجنٹ منتخب کر لیا ہو تو آپ کا کوئی بھی پروگرام جو کور ڈمپ کرے ایک "پراسیس کریش ہو گیا" اطلاع لاتا ہے — اس پر کلک کریں، اور کریش آپ کے ڈیفالٹ ایجنٹ کے حوالے کر دیا جاتا ہے Omarchy کی omarchy-diagnose-crash اسکل کے ساتھ، جو ایجنٹ کو کور ڈمپ سے حقائق قائم کرنے اور یہ فیصلہ کرنے کے مراحل سے گزارتی ہے کہ آیا کریش upstream کو رپورٹ کرنے کے قابل ہے۔ آپ اسے `coredumpctl list` سے کسی بھی PID کے خلاف `omarchy agent crash <pid>` کے ساتھ ہاتھ سے بھی چلا سکتے ہیں۔

یہ نگرانی بطور ڈیفالٹ فعال ہے۔ اسے _Trigger > Toggle > Crash Capture Off_ کے تحت (یا `omarchy toggle crash-capture` کے ساتھ) بند کر دیں اور اطلاعات رک جاتی ہیں؛ `omarchy agent crash <pid>` ہاتھ سے پھر بھی کام کرتا ہے۔

کریشز کو ایک وقت میں ایک پروگرام کے حساب سے خاموش بھی کیا جا سکتا ہے، جو تشخیص آخر میں آپ کو پیش کرتی ہے۔ `omarchy crash mute hyprland` صرف اس پروگرام کے لیے اطلاعات روکتا ہے، `omarchy crash mute hyprland off` انہیں واپس لاتا ہے، اور `omarchy crash mute` اکیلا یہ فہرست دیتا ہے کہ آپ نے کیا خاموش کیا ہے۔ یہ بائنری کا راستہ اس کے نام کی طرح خوشی سے لیتا ہے، لہٰذا `omarchy crash mute /usr/bin/hyprland` بھی وہی کام کرتا ہے۔ جس نام میں جگہ ہو اسے اقتباس میں لکھیں، جیسے `omarchy crash mute 'Some App'` میں ہے۔ باقی سب کچھ پھر بھی مطلع کرتا ہے، اور خاموش کیا گیا پروگرام پھر بھی کریش ہوتا ہے — یہ یاد دہانی کو چھپاتا ہے، یہ کچھ ٹھیک نہیں کرتا۔

### ڈیسک ٹاپ ایپس

_Install > AI_ مینو میں چند گرافیکل AI ایپس بھی ہیں: Amp Desktop، Antigravity Desktop، ChatGPT ڈیسک ٹاپ ایپ، Claude ڈیسک ٹاپ ایپ (Anthropic کا Linux بیٹا، Chat، Cowork اور Claude Code ٹیبز کے ساتھ)، xAI کے ماڈلز کے ساتھ گفتگو کے لیے Grok Bot، Herdr Desktop، Hermes Desktop، OpenClaw، Perplexity ڈیسک ٹاپ ایپ، اور T3 Code۔ Grok Bot ڈیسک ٹاپ چیٹ ایپ ہے۔ کوڈنگ ایجنٹ `grok` کمانڈ ہے۔

Hermes Desktop وہ ہے جس کے بارے میں جاننا ضروری ہے، کیونکہ ایک مشین کے پاس ایک Hermes ہوتا ہے، اور وہ ایپ کا ہوتا ہے: Hermes ہمیشہ صرف ایپ کے ذریعے انسٹال ہوتا ہے، اور جو `hermes` کمانڈ ڈیفالٹ ایجنٹ چلاتا ہے وہ ایپ کی ہوتی ہے۔ Hermes کو ڈیفالٹ ایجنٹ کے طور پر منتخب کرنے پر وہی چیز انسٹال ہوتی ہے جو _Install > AI_ اندراج کرتا ہے: پیکیج، اور Hermes کے اپنے انسٹالر کے ذریعے سیٹ اپ کردہ `~/.hermes` کے تحت ایک Hermes رن ٹائم، جس میں پہلی بار چند منٹ لگتے ہیں۔ وہ رن ٹائم وہ واحد Hermes ہے جسے ٹرمینل کی `hermes` کمانڈ، ڈیفالٹ ایجنٹ اور ایپ سب استعمال کرتے ہیں، اور یہ Omarchy ریلیز کا انتظار کرنے کے بجائے `hermes update` کے ساتھ خود کو اپ ڈیٹ کرتا ہے۔ اسے انسٹال کرنے پر Hermes کو Omarchy تھیم `omarchy` نامی اسکن کے طور پر بھی دی جاتی ہے، جس کی ہر Hermes سطح آپ کے تھیمز تبدیل کرنے پر پیروی کرتی ہے؛ اگر آپ ایسا نہ چاہتے ہوں تو Hermes کی Appearance ترتیبات کے تحت یا `/skin` کے ساتھ کوئی اور منتخب کریں، اور Omarchy اس انتخاب کو چھونے نہیں دیتا۔ _Remove > AI_ کے تحت ایپ ہٹانے پر پہلے Hermes بند ہو جاتا ہے، گیٹ وے سمیت، وہ رن ٹائم اس کے ساتھ لے جاتا ہے، اور آپ کی چیٹس، یادیں اور وہ اسکلز جو Hermes نے خود اپنے لیے لکھی تھیں برقرار رکھتا ہے جب تک کہ آپ اسے دوسری صورت نہ بتائیں: یہ پوچھتا ہے، جس کا ڈیفالٹ نہیں ہے، کہ آیا وہ ڈیٹا اور آپ کی کنکشن ترتیبات بھی جانی چاہئیں۔

OpenClaw کا ڈیسک ٹاپ تجربہ اس کا Control UI ہے، جو اپنے لوکل گیٹ وے کی پشت پر ایک ویب ایپ کے طور پر کھلتا ہے۔ OpenClaw `~/.openclaw` میں رہتا ہے اور خود کو اپ ڈیٹ کرتا ہے: Control UI کا "Update Gateway" بٹن استعمال کریں یا `openclaw update` چلائیں، اور گیٹ وے نئے ورژن پر دوبارہ شروع ہو جاتا ہے۔ Omarchy صرف وہ ریلیز منتخب کرتا ہے جس سے ایک نئی انسٹالیشن شروع ہوتی ہے۔ OpenClaw آپ کا ڈیفالٹ ایجنٹ بھی ہو سکتا ہے: اسے _Agent > Harness_ کے تحت منتخب کرنے پر `~/.openclaw` میں وہی کاپی سیٹ اپ ہو جاتی ہے، اور ایجنٹ OpenClaw کا ٹرمینل UI اس کے گیٹ وے سے منسلک کھولتا ہے۔ _Remove > AI_ کے تحت OpenClaw ہٹانے پر گیٹ وے سروس اور ایپ اس کے ساتھ جاتی ہیں اور پھر پوچھا جاتا ہے کہ آیا `~/.openclaw` بھی جانا چاہیے، کیونکہ اس میں OpenClaw کے ساتھ ساتھ آپ کی چیٹس اور اسناد اور وہ پلگ ان رن ٹائمز ہوتے ہیں جو یہ ڈاؤن لوڈ کرتا ہے؛ ڈیفالٹ اسے برقرار رکھتا ہے، اور OpenClaw کو دوبارہ انسٹال کرنے پر یہ اسے دوبارہ اٹھا لیتا ہے۔

Herdr Desktop [Herdr](https://herdr.dev) ڈیسک ٹاپ ایپ ہے: ٹرمینلز اور کوڈنگ ایجنٹس کی اسپیسز، ٹیبز اور پینز جو ونڈو بند کرنے پر اس کے کور میں چلتے رہتے ہیں۔ یہ کسی پیکیج کے بجائے Herdr کے اپنے انسٹالر سے آتا ہے، لہٰذا یہ `~/.local/share/herdr-app` میں رہتا ہے، جب آپ کے پاس پہلے سے کوئی نہ ہو تو اپنے کور کو `~/.local/bin/herdr-core` میں ساتھ لاتا ہے، اور دونوں کو خود اپ ڈیٹ کرتا ہے۔ یہ اس `herdr` کمانڈ کے ساتھ ساتھ رہتا ہے جو Omarchy `Super + Ctrl + Return` پر فراہم کرتا ہے اسے بدلنے کے بجائے، اور اسے اس کمانڈ کی براہ راست کیز ملتی ہیں: `Alt + Return` اور `Alt + Shift + Return` پین کو نیچے یا دائیں تقسیم کرتے ہیں، `Alt + Escape` اسے بند کرتا ہے، `Ctrl + Alt + Arrow` پینز کے درمیان منتقل کرتا ہے، `Alt + 1..9` اور `Alt + Left/Right` ٹیب منتخب کرتے ہیں، اور `Alt + Up/Down` اسپیسز کے درمیان منتقل کرتے ہیں۔ `Ctrl + 1..9` اسپیس منتخب کرتا ہے اور `Alt + Shift + Up/Down` ایجنٹس میں آگے پیچھے جاتا ہے۔ `Ctrl + Space` پریفکس کیز صرف ٹرمینل کے لیے رہتی ہیں، کیونکہ ایپ کسی سلسلے کے لیے سادہ Ctrl کی کو تھامے نہیں رکھ سکتی۔ Omarchy انہیں `~/.config/herdr-app/keys.json` میں لکھتا ہے، اور `omarchy-refresh-herdr-app` انہیں واپس رکھ دیتا ہے۔ اسے انسٹال کرنے پر Herdr کی Omarchy تھیم منتخب ہوتی ہے، جو اس کے بعد سے آپ کی Omarchy تھیم کی پیروی کرتی ہے۔ Herdr ہلکے موڈ کے لیے ایک تھیم اور گہرے موڈ کے لیے ایک تھیم رکھتا ہے، لہٰذا گہری اور ہلکی Omarchy تھیم کے درمیان تبدیل کرنے کے بعد، دوسرے موڈ کے لیے Herdr کے تھیم منتخب کنندہ میں ایک بار پھر Omarchy منتخب کریں۔

T3 Code کسی پیکیج کے بجائے `~/.local/share/t3code` میں اپنی سرکاری AppImage ریلیز سے چلتا ہے، لہٰذا یہ خود کو اپ ڈیٹ کرتا ہے۔ اسے انسٹال کرنے پر پوچھا جاتا ہے کہ آیا Stable یا Nightly چینل پر شروع کرنا ہے؛ بعد میں T3 Code کی ترتیبات میں تبدیل کریں۔ آپ کے تھریڈز اور ترتیبات `~/.t3` میں رہتے ہیں، اور _Remove > AI_ کے تحت T3 Code ہٹانے پر وہ اس کے ساتھ جاتے ہیں۔

### لوکل ماڈلز

اپنے کوڈنگ ایجنٹس کے لیے اپنی مشین پر ایک اوپن ماڈل چلائیں۔ آپ کے پرمپٹس اور کوڈ مشین پر رہتے ہیں؛ ماڈل کو بھیجی گئی کوئی چیز اس سے باہر نہیں جاتی۔ اس سے شروع کریں:

```bash
omarchy models use best text
```

یا، اوپر والی بار میں ایجنٹس پینل میں، + اور پھر Local AI منتخب کریں، جو اس وقت ظاہر ہوتا ہے جب کوئی ماڈل اس مشین کے مطابق ہو۔ Podman، جو ماڈلز چلاتا ہے، Omarchy کے ساتھ آتا ہے، اسی طرح NVIDIA مشین پر NVIDIA کا کنٹینر ٹول کٹ بھی آتا ہے، جو انہیں GPU دیتا ہے؛ اگر ان میں سے کوئی موجود نہ ہو تو پہلا سیٹ اپ اسے انسٹال کر دیتا ہے۔ پھر Omarchy اس مشین کے لیے تجویز کردہ ماڈل منتخب کرتا ہے، اسے ڈاؤن لوڈ کرتا ہے، اور اسے شروع کرتا ہے۔ دسیوں GB کے ڈاؤن لوڈ کی توقع رکھیں اور جب ماڈل چل رہا ہو تو مشین کی زیادہ تر میموری استعمال میں ہوگی: Flash Next اپنے مکمل 256K کانٹیکسٹ کے ساتھ تقریباً 100 GiB استعمال کرتا ہے۔ اگر دوسرے ماڈلز اس میموری کو روکے ہوئے ہوں جس کی اسے ضرورت ہے تو یہ رکا ہوا سیٹ اپ ہوتا ہے، جب آپ کسی ایک کو روکیں تو شروع ہونے کے لیے تیار۔ ماڈل لاگ آؤٹ پر رک جاتا ہے؛ جب آپ کو کسی اور چیز کے لیے میموری درکار ہو تو اسے خود روک دیں۔

`omarchy models list` اختیارات دکھاتا ہے اور بتاتا ہے کہ کچھ کیوں مناسب نہیں ہیں۔ کوئی اور سیٹ اپ کرنے کے لیے `omarchy models use <recipe>` چلائیں۔ آج، 128 GB Strix Halo مشینوں کے لیے `qwen3.8-flash-next-gufo` اور `qwen3.8-27b-gufo` دستیاب ہیں؛ 27B تقریباً 40 GiB لیتا ہے، لہٰذا یہ دوسرے کام کے لیے جگہ چھوڑتا ہے۔ Intel کے Arc B390 والی 64 GB لیپ ٹاپ پر، `qwen3.6-35b-a3b-llamacpp` تقریباً 30 GiB میں چلتا ہے۔ نئی ترکیبیں اور تجاویز پیکیج کے ذریعے `omarchy update` کے ساتھ آتی ہیں۔

آپ جو بھی ماڈل سیٹ اپ کرتے ہیں اسے ایجنٹس پینل میں آپ کی سبسکرپشنز کے ساتھ اپنی سطر ملتی ہے: اسے شروع کرنے کے لیے چلائیں، اسے روکنے اور اس کی میموری خالی کرنے کے لیے روکیں، اور اس پر اپنے ایجنٹ کو کھولنے کے لیے ٹرمینل بٹن۔ جب وہ میموری میں ایک ساتھ مناسب ہوں تو کئی ایک ساتھ چل سکتے ہیں؛ اگر کوئی مناسب نہ ہو تو Omarchy بتاتا ہے کہ کون سا چل رہا ماڈل روکنا ہے۔ سطروں کو دوبارہ ترتیب دینے کے لیے انہیں گھسیٹیں، اور منتخب سطر پر Delete دبائیں تاکہ ماڈل اور اس کا ڈاؤن لوڈ ہٹ جائے۔

آپ جو بھی ماڈل سیٹ اپ کرتے ہیں اسے ایپ لانچر میں بھی اپنی اندراج ملتی ہے، ماڈل کے نام کے تحت اور اس کے بنانے والے کے لوگو کے ساتھ، اسی طرح جس طرح Claude، Codex یا Grok میں سائن ان کرنے پر ایک ملتی ہے۔ یہ آپ کے ایجنٹ کو اس ماڈل پر کھولتا ہے، اور اگر ماڈل چل نہ رہا ہو تو پہلے اسے شروع کرتا ہے: ٹرمینل اسے لوڈ ہوتا ہوا دکھاتا ہے اور تیار ہونے پر ایجنٹ کے حوالے کر دیتا ہے۔ ماڈل ہٹانے سے اس کی اندراج ختم ہو جاتی ہے۔

ہر ماڈل کوڈنگ کے لیے نہیں ہوتا۔ تصویر، ویڈیو اور موسیقی کے ماڈلز اس کے بجائے Fantasi میں کھلتے ہیں، جو اس مشین پر چلنے والے ماڈل کے ساتھ تصاویر، ویڈیو اور موسیقی بنانے کے لیے Omarchy کی ایپ ہے، ان کی لانچر اندراج سے اور ایجنٹس پینل میں ان کی سطر سے۔

ایک ماڈل بالکل ویسا ہی چلتا رہتا ہے جیسا اسے سیٹ اپ کیا گیا تھا، لہٰذا Omarchy اپ ڈیٹ آپ کے ایجنٹس کے نیچے کسی کو کبھی دوبارہ شروع نہیں کرتی۔ جب Omarchy کے پاس آپ کے سیٹ اپ کردہ ماڈل کے لیے نیا رن ٹائم یا نئے ویٹس ہوں تو اس کی سطر ایک اپ ڈیٹ بٹن دکھاتی ہے: اسے دبائیں اور ماڈل پس منظر میں دوبارہ سیٹ اپ ہو جاتا ہے، صرف وہی ڈاؤن لوڈ کرتا ہے جو بدلا ہے، اور نئے ورژن پر دوبارہ شروع ہو جاتا ہے۔ جو ماڈل رکا ہوا تھا وہ رکا رہتا ہے۔ `omarchy models update` ٹرمینل سے ہر ماڈل کے لیے یہی کرتا ہے۔

کمانڈ لائن سے، `omarchy models start <recipe>` اور `omarchy models stop <recipe>` یہی کرتے ہیں، `omarchy models status` ہر ماڈل دکھاتا ہے، اور `omarchy agent --local` آپ کے ڈیفالٹ ایجنٹ کو آخری شروع کیے گئے ماڈل پر کھولتا ہے۔ pi، OpenCode اور Qwen Code ایک کو استعمال کر سکتے ہیں؛ کسی اور ڈیفالٹ کے ساتھ یہ pi میں کھلتا ہے، یا اگر آپ کے پاس pi نہ ہو تو OpenCode میں کھلتا ہے۔ pi ان تمام ماڈلز کی بھی فہرست دیتا ہے جو آپ نے سیٹ اپ کیے ہیں، اور ان کی بھی جو ان مشینوں پر ہیں جن کے ساتھ آپ نے جوڑا بنایا ہے، اپنے ماڈل منتخب کنندہ میں، لہٰذا سادہ `pi` بھی ان تک پہنچتا ہے۔ کوئی بھی OpenAI سے ہم آہنگ کلائنٹ بھی جڑ سکتا ہے: `status` ہر ماڈل کا پتہ دکھاتا ہے (پہلا `http://127.0.0.1:11435/v1` ہے)، ترکیب کا نام ماڈل ہے، اور کی `~/.config/omarchy/agent-local/key` میں ہے۔

`omarchy models remove <recipe>` ایک ماڈل اور وہ ڈاؤن لوڈز حذف کر دیتا ہے جنہیں کوئی دوسرا ماڈل استعمال نہیں کرتا۔

تیسرے فریق کے رن ٹائمز پر ان کے ناشر کا لیبل لگا ہوتا ہے۔ Omarchy ہر ماڈل کو بغیر کسی نیٹ ورک رسائی کے چلاتا ہے۔

### لوکل LLMs

Omarchy لوکل LLM ماڈلز چلانے کے دو طریقے تجویز کرتا ہے: LM Studio اور Ollama۔ LM Studio اوپن ویٹ ماڈلز تلاش کرنے، انہیں انسٹال کرنے اور انہیں چلانے کے لیے ایک GUI انٹرفیس فراہم کرتا ہے۔ آسانی سے شروع کرنے کا یہ ایک بہترین طریقہ ہے۔ Ollama اسی طرح کرنے کے لیے ایک CLI پیش کرتا ہے۔ لیکن اگر آپ لوکل ماڈلز میں نئے ہیں تو میں LM Studio سے شروع کروں گا۔ آپ Omarchy Menu میں _Install > AI_ کے تحت دونوں میں سے کوئی بھی انسٹال کر سکتے ہیں۔

### Omarchy اسکلز

ایجنٹ اسکلز AI کو مخصوص ٹولز کو مخصوص طریقے سے استعمال کرنے میں مدد دیتی ہیں، اور Omarchy ان میں سے سات فراہم کرتا ہے۔ omarchy اسکل نظام کی حسب ضرورت تیاری کا احاطہ کرتی ہے، جیسے آپ کی Hyprland ترتیب میں رد و بدل کرنا یا بار کو ایڈجسٹ کرنا۔ omarchy-make-theme، omarchy-make-plugin، omarchy-make-app اور omarchy-make-game کچھ نیا بنانے کا احاطہ کرتے ہیں، omarchy-contribute کسی بگ کی اطلاع دینے یا upstream کو ٹھیک بھیجنے کا احاطہ کرتا ہے، اور omarchy-diagnose-crash کسی کریش کے کور ڈمپ پر کام کرتا ہے۔ یہ Claude Code (`~/.claude/skills`)، Codex (`~/.codex/skills`)، Pi (`~/.pi/agent/skills`)، Antigravity (`~/.gemini/config/skills`)، Hermes (`~/.hermes/skills` اور ہر `~/.hermes/profiles/*/skills`)، اور عام `~/.agents/skills` مقام کے لیے اسکل ڈائریکٹریوں میں سم لنک شدہ ہیں، لہٰذا زیادہ تر ہارنسز انہیں خودکار طور پر اٹھا لیتے ہیں۔ اسی نام کا آپ کا اپنا اسکل فولڈر ترجیح رکھتا ہے۔

لیکن آپ کو ان اسکلز کو تجرباتی سمجھنا چاہیے۔ مختلف ماڈلز اسے مختلف اثر کے ساتھ استعمال کریں گے۔ بہتر ہے کہ پہلے پلان موڈ میں چلائیں، تاکہ آپ کو اندازہ ہو کہ ایجنٹ کیا بدلنا چاہے گا۔ اور پھر تبدیلیوں کو واپس کرنے یا یہاں تک کہ `omarchy reinstall configs` چلانے کے لیے تیار رہیں، اگر ایجنٹ ہر چیز کا ستیاناس کر دے۔
