Omarchy ذیل میں دیے گئے کوڈنگ ایجنٹس کے لیے لانچرز شامل کرتا ہے، بغیر آپ کے لیے ڈیفالٹ منتخب کیے۔ پہلی بار استعمال پر اس کا CLI نصب کرنے کے لیے ایک کمانڈ چلائیں، پھر اشارہ ملنے پر تصدیق کریں۔ Hermes اور OpenClaw مستثنیات ہیں: ان کے لیے mise کے ذریعے کچھ بھی نصب نہیں کیا جاتا، اور ان میں سے کسی کو منتخب کرنے سے اس کی اپنی خود اپ ڈیٹ ہونے والی کاپی سیٹ اپ ہو جاتی ہے، جیسا کہ نیچے _ڈیسک ٹاپ ایپس_ میں بیان کیا گیا ہے۔

### ایجنٹس نصب اور اپ ڈیٹ کرنا

Hermes اور OpenClaw کے علاوہ، یہ ایجنٹس mise کی سست تنصیب استعمال کرتے ہیں: پہلی بار شروع کرنا CLI نصب کر دیتا ہے، اور بعد میں شروع کرنا اسی کو دوبارہ استعمال کرتا ہے۔ mise ایک نصب شدہ ایجنٹ کے لیے نئی ریلیز بھی زیادہ سے زیادہ ہر چار گھنٹے میں ایک بار چیک کرتا ہے، شروع ہونے سے عین پہلے یا پس منظر میں شیل پرامپٹ پر۔ اگر وہ اپ ڈیٹ ناکام ہو جائے یا آپ آف لائن ہوں، تو نصب شدہ ورژن چلتا ہے۔ `omarchy update` نصب شدہ ایجنٹس کو باقی Omarchy کے ساتھ اپ ڈیٹ کرتا ہے، اور `mup` صرف mise کے زیر انتظام ٹولز کو اپ ڈیٹ کرتا ہے۔

کسی ایجنٹ کا اپنا اپڈیٹر، جیسے `claude update`، `codex update`، یا کسی ایپ میں اپ ڈیٹ بٹن، mise کے زیر انتظام انسٹال کو اپ ڈیٹ نہیں کرتا۔ `codex update` ناکام ہو جاتی ہے، اور `claude update` کامیابی کی اطلاع دیتے ہوئے ایک الگ کاپی نصب کر سکتی ہے جسے mise ٹریک نہیں کرتا۔ اگر آپ اس کے بجائے کسی ایجنٹ کا مقامی انسٹالر اور اپڈیٹر استعمال کرنا چاہتے ہیں، تو اسے `disable_tools` میں شامل کریں؛ دیکھیں [پہلے سے نصب CLI ٹولز](18-development-tools.md#preinstalled-cli-tools)۔

تمام تشکیل شدہ سست ٹولز کو ضرورت پڑنے سے پہلے نصب کرنے کے لیے، `mise install --include-lazy` چلائیں۔ اس میں ایجنٹس کے ساتھ ساتھ Omarchy کے دیگر ڈیفالٹ CLI ٹولز بھی شامل ہیں۔ ایک واحد ٹول نصب کرنے یا اپنی تنصیب استعمال کرنے کے لیے [پہلے سے نصب CLI ٹولز](18-development-tools.md#preinstalled-cli-tools) دیکھیں۔

`grok` mise کے فرسٹ پارٹی `grok` پیکیج کے ذریعے نصب کیا جاتا ہے، اسی طرح جیسے `claude` اور `codex`۔ `grok` چلائیں، یا اسے ایجنٹس پینل میں ستارے سے نشان زد کریں۔ x.ai پر موجود `curl | bash` انسٹالر کو چھوڑ دیں۔ وہ راستہ `~/.grok/bin` میں دوسری کاپی رکھ دیتا ہے، اسے `PATH` کے شروع میں شامل کر دیتا ہے، اور Omarchy کے ریپر کو اوور رائٹ کر دیتا ہے۔

`dsh` اپنا براؤزر UI `127.0.0.1:3080` پر کھولتا ہے، جس میں لانچ ڈائریکٹری اس کی ڈیفالٹ ورک اسپیس ہوتی ہے۔ اس کا براؤزر UI کوئی ابتدائی پرامپٹ نہیں لیتا، لہٰذا `omarchy agent prompt` اسے اس پرامپٹ کے ساتھ کھولتا ہے جو آپ کے کلپ بورڈ پر چسپاں کرنے کے لیے موجود ہوتا ہے۔ Omarchy اسے DeepSeek کے بغیر منظوری والے اجازت پری سیٹ کے ساتھ شروع کرتا ہے۔ DeepSeek Harness سیشن لاگز DeepSeek کو اپ لوڈ کرتا ہے جب آپ اس کا سرکاری ماڈل API استعمال کرتے ہیں؛ اسے اس کے براؤزر UI میں _Settings > General > Upload Session Log_ کے تحت بند کر دیں۔ جو فیڈ بیک آپ اسے بھیجتے ہیں وہ بھی سیشن کے ساتھ اپ لوڈ ہو جاتا ہے، جب تک کہ آپ اسے `DSH_TELEMETRY_MODE=DISABLED` کے ساتھ شروع نہ کریں۔

### ڈیفالٹ ایجنٹ

ایجنٹس پینل میں کسی ایجنٹ کے ساتھ موجود ستارے سے اپنا ڈیفالٹ ایجنٹ منتخب کریں، جو ڈیفالٹ پر بھرا ہوا ہوتا ہے، یا `omarchy default agent <name>` کے ساتھ، جو وہاں لائن کے بغیر کسی بھی ہارنس کو بھی لیتا ہے۔ اگر ایجنٹ ابھی نصب نہیں ہوا ہے، تو اسے منتخب کرنا پہلے اسے نصب کر دیتا ہے، اور اسے ایپ لانچر میں Agent کے ساتھ ساتھ اپنا لانچر بھی مل جاتا ہے۔ ایک تازہ Omarchy آپ کو ایک بار کی اطلاع کے ساتھ ایک سیٹ اپ کرنے کی دعوت دیتا ہے، جو ایجنٹس پینل کھولتی ہے۔

Claude کو منتخب کرنا Chromium، Chrome، Brave، Brave Origin، اور Edge کے لیے اس کی براؤزر ایکسٹینشن سیٹ اپ کرنے کی بھی کوشش کرتا ہے۔ ایکسٹینشن سیٹ اپ تمام صارفین پر لاگو ہوتا ہے اور آپ سے آپ کا سسٹم پاس ورڈ مانگ سکتا ہے؛ منسوخ کرنے یا ناکام ایکسٹینشن تنصیب کے باوجود Claude منتخب اور شروع ہو جاتا ہے۔ اپنا براؤزر دوبارہ شروع کریں، اشارہ ملنے پر ایکسٹینشن فعال کریں، اور اسے جوڑنا مکمل کرنے کے لیے Claude میں سائن ان کریں۔ کنکشن چیک کرنے کے لیے Claude میں `/chrome` چلائیں۔ Firefox اور Zen اس ایکسٹینشن کی حمایت نہیں کرتے۔ اگر یہ سیٹ اپ شامل ہونے سے پہلے Claude پہلے ہی آپ کا ڈیفالٹ تھا، تو ایکسٹینشن نصب کرنے کے لیے اسے دوبارہ منتخب کریں۔

جب آپ منتخب کر چکے ہوں، تو `Super + Shift + Ctrl + A` ڈیفالٹ ایجنٹ کو ایک مخصوص ٹرمینل ونڈو میں شروع کرتا ہے (یا اگر آپ نے ابھی تک منتخب نہیں کیا تو پکر لے آتا ہے)۔ آپ اسے `omarchy agent prompt "Review this project"` کے ساتھ سیدھا کسی کام میں بھی شروع کر سکتے ہیں۔ Freebuff اور DeepSeek Harness کوئی ابتدائی پرامپٹ نہیں لیتے، لہٰذا اس کے بجائے وہ اس پرامپٹ کے ساتھ کھلتے ہیں جو آپ کے کلپ بورڈ پر چسپاں کرنے کے لیے موجود ہوتا ہے۔ اس طرح شروع کیے گئے ایجنٹس اپنے اپنے رکنے اور پوچھنے سے گریز والے موڈز میں بغیر نگرانی کے چلتے ہیں، لہٰذا تیار رہیں کہ وہ واقعی کچھ کریں گے! MiniMax Code کے پاس اس کے انٹرایکٹو سیشنز کے لیے ایسا کوئی موڈ نہیں ہے، لہٰذا وہ معمول کے مطابق اجازتیں مانگتا ہے۔ اور چونکہ ایجنٹس آپ کی ہوم ڈائریکٹری کے لیے اعتماد یاد رکھنے سے انکار کرتے ہیں، اس لیے `$HOME` سے لانچ اس کے بجائے `~/Work` میں شروع ہوتے ہیں۔

ٹرمینل شارٹ کٹس بھی ہیں: `a` موجودہ ٹرمینل میں ڈیفالٹ ایجنٹ کو ان لائن چلاتا ہے، جبکہ `c`، `cx`، اور `cy` OpenCode، Claude Code، اور Codex کو براہ راست شروع کرتے ہیں (ایک بار پھر ان کے خودکار منظوری والے موڈز میں)۔ تھیم کی تبدیلیاں ایجنٹس کے ساتھ بھی ہم آہنگ ہو جاتی ہیں: Claude Code، Pi، OpenCode، اور Hermes (جب Omarchy نے اسے نصب کر لیا ہو) سب اس وقت ساتھ چلتے ہیں جب آپ Omarchy تھیم تبدیل کرتے ہیں۔

### آپ کی ایجنٹ ہدایات

ہر ایجنٹ کے لیے ذاتی اصول `~/.agents/AGENTS.md` میں جاتے ہیں، `~/.agents/skills` میں مشترکہ مہارتوں کے ساتھ۔ اسے ایجنٹس پینل میں + کے ساتھ موجود دستاویز آئیکن سے کھولیں، یا `omarchy agent instructions --edit` کے ساتھ، جو اسے ہر اس ہارنس میں بھی لنک کر دیتا ہے جو اپنی عالمی فائل رکھتا ہے: `~/.claude/CLAUDE.md`، `~/.codex/AGENTS.md`، `~/.pi/agent/AGENTS.md`، `~/.config/opencode/AGENTS.md`، Copilot کی `~/.copilot/copilot-instructions.md`، اور اسی طرح۔ Crush اور Amp `~/.config/AGENTS.md` لنک پڑھتے ہیں، جبکہ omp، Kimi، اور DeepSeek Harness براہ راست `~/.agents/AGENTS.md` پڑھتے ہیں۔ ڈیفالٹ ایجنٹ منتخب کرنا بھی اسے لنک کر دیتا ہے۔ اگر کوئی ہدایات فائل آپ کے پاس پہلے سے موجود تھی تو اگر ابھی تک کوئی مشترکہ فائل نہیں تھی تو وہی مشترکہ بن جاتی ہے؛ ورنہ اسے لنک کے ساتھ `.bak` کے طور پر رکھا جاتا ہے۔ ایک اور ایجنٹ نصب کرنے کے بعد دوبارہ لنک کرنے کے لیے `omarchy agent instructions` چلائیں۔

### ایجنٹس پینل

اوپر والی بار میں ایک ایجنٹس آئیکن ہے۔ اس سے پہلے کہ آپ نے کوئی ایجنٹ سیٹ اپ کیا ہو، اس کا پینل شروع کرنے کے تین طریقے پیش کرتا ہے: Claude، Codex، Grok، Gemini، Muse، Cursor، یا Copilot سبسکرپشن میں سائن ان کریں، یا More کے تحت OpenCode Go، MiniMax، Synthetic، یا Z.ai کوڈنگ پلان میں؛ Fireworks، OpenCode Zen and Go، OpenRouter، یا More کے تحت DeepSeek یا کسی بھی دوسرے فراہم کنندہ کے ساتھ جتنا استعمال کریں اتنا ادا کریں جس میں OpenCode سائن ان کرتا ہے، سب OpenCode میں چلتے ہیں؛ یا اپنے کمپیوٹر کے لیے بہترین ماڈل چلائیں، جب کوئی اس میں فٹ آتا ہو۔ جسے آپ سب سے پہلے مکمل کرتے ہیں وہ آپ کا ڈیفالٹ ایجنٹ بن جاتا ہے، اور پینل میں +، یا Omarchy Menu میں _Agent > Add_، بعد میں وہی تین پیش کرتا ہے۔ اس کے بعد، پینل ہر سبسکرپشن کو ایک صفحے پر رکھتا ہے: ہر ایجنٹ اور اکاؤنٹ اس کے پلان کے ساتھ، اس کی 5 گھنٹے کے سیشن اور ہفتہ وار حدود میں سے ہر ایک کے لیے ایک میٹر اس کے ری سیٹ ہونے تک کے وقت کے ساتھ (درست فیصد کے لیے ہوور کریں)، یا باقی پری پیڈ بیلنس، ایک لائن کے نیچے جو ان سب میں آپ کے استعمال کی چیزوں میں سے گھومتی رہتی ہے، جیسے اس ہفتے کے ٹوکنز اور آپ کا سب سے زیادہ استعمال شدہ ماڈل۔ _Make something cool_ کے تحت یہ ایک نئی تھیم، پلگ ان، ایپ، یا گیم کے لیے ابتدائی پرامپٹ پیش کرتا ہے جو کام آپ کے ڈیفالٹ ایجنٹ کے حوالے کر دیتے ہیں۔ ایپس اسی طرح بنائی جاتی ہیں جس طرح Omarchy کی اپنی Hype، Monologue، اور Omacut ہیں، C++ اور Qt Quick میں، omarchy-make-app ایجنٹ مہارت کی پیروی کرتے ہوئے، اور انہیں درکار کمپائلر اور Qt کے حصے نصب آتے ہیں۔ گیمز `~/Games/vibes` میں ایک واحد three.js صفحہ ہیں، omarchy-make-game ایجنٹ مہارت کی پیروی کرتے ہوئے، اور سب موجودہ تھیم میں ایک Game Vibes لانچر سے کھلتی ہیں؛ وہ three.js ویب سے لوڈ کرتی ہیں، لہٰذا انہیں شروع ہونے کے لیے کنکشن درکار ہوتا ہے۔ Claude Code، Codex، Grok، Kimi، Cursor اور اس کا Grok Bot الاؤنس، GitHub Copilot، Muse، Gemini (Antigravity کے ذریعے)، اور Devin اپنی حدود کے ساتھ ابتدا ہی سے شامل ہیں، Kimchi اپنے پلان، پری پیڈ کریڈٹس، اور اخراجات کے بجٹس کے ساتھ، اور Hermes، Mistral Vibe، اور Qwen Code ایک بار جب آپ انہیں استعمال کر چکے ہوں تو اپنے سیشنز اور ٹوکنز دکھاتے ہیں۔ فراہم کنندہ کے پلانز اور کیز جو آپ pi، omp، یا opencode کے ذریعے استعمال کرتے ہیں وہ بھی ظاہر ہوتے ہیں: OpenCode Zen and Go، Z.ai GLM Coding Plan، Ollama Cloud، MiniMax Token Plan، اور Synthetic اپنی حدود کے ساتھ؛ OpenRouter اور DeepSeek اپنے پری پیڈ بیلنسز کے ساتھ؛ Fireworks پچھلے 30 دنوں میں اس کے اخراجات کے ساتھ۔ اپنے ہارڈ ویئر پر چلائے جانے والے ماڈلز کے ٹوکنز بھی مجموعوں میں شمار ہوتے ہیں؛ خود ماڈلز کا اپنا پینل ہے، جسے [مقامی ماڈل](#local-models) کے تحت بیان کیا گیا ہے۔ ہر ایجنٹ کو ایک بار شمار کیا جاتا ہے، اس کے تحت جو بھی اس کا بل دیتا ہے، آپ اسے کتنے ہی ہارنسز کے ذریعے چلائیں۔

پینل کے لیے بار آئیکن پر بائیں کلک کریں یا `Super + Ctrl + X` دبائیں، اپنے ڈیفالٹ ایجنٹ کو شروع کرنے کے لیے دائیں کلک کریں، اور تازہ کرنے کے لیے درمیانی کلک کریں۔ اس کے پیچھے موجود استعمال کے ریکارڈز ہر 15 منٹ بعد `omarchy agent usage update` کے ذریعے دوبارہ بنائے جاتے ہیں، اور پینل ایک ہم آہنگ فولڈر کے ذریعے آپ کی دوسری مشینوں سے استعمال کو بھی ضم کر سکتا ہے۔ مکمل ترتیبات کے لیے `$OMARCHY_PATH/shell/plugins/agents/` کے تحت README دیکھیں۔

### کئی سبسکرپشنز

اگر آپ ایک سے زیادہ Claude، Codex، یا Grok پلان کے لیے ادائیگی کرتے ہیں — مثلاً ایک ذاتی Max اور ایک کام والا — تو Omarchy ان سب کو سائن ان رکھ سکتا ہے اور ان کے درمیان منتقل ہو سکتا ہے۔ ایجنٹس پینل میں + کے ساتھ ایک سبسکرپشن شامل کریں، جو آپ کو وہیں اس سے گزارتا ہے، یا `omarchy agent account add claude Work` کے ساتھ (یا `codex`، یا `grok`)۔ وہی + اور کمانڈ Gemini (`gemini`) اور OpenCode (`opencode`) میں سائن ان کرتے ہیں، اور OpenCode میں Fireworks (`fireworks`) یا OpenRouter (`openrouter`) API key محفوظ کرتے ہیں؛ یہ کمانڈ Copilot (`copilot`)، Cursor (`cursor`)، اور Muse (`muse`) میں بھی سائن ان کرتی ہے۔ وہ ہر ایک ایک واحد سائن ان رکھتے ہیں۔ اگر CLI غائب ہو تو یہ اسے نصب کر دیتا ہے۔ کسی فراہم کنندہ کے لیے پہلا اکاؤنٹ آپ کے عام براؤزر کے ذریعے سائن ان کرتا ہے، عین وہیں جہاں CLI ہمیشہ دیکھتا ہے۔ اس کے بعد کا ہر ایک نجی ونڈو کے ذریعے سائن ان کرتا ہے، تاکہ وہ اکاؤنٹ جس میں آپ کا براؤزر پہلے ہی سائن ان ہے غلطی سے نہ اٹھا لیا جائے؛ وہاں اس اکاؤنٹ کے طور پر سائن ان کریں جسے آپ شامل کر رہے ہیں، اور پہلے سے کھلی ہوئی کسی بھی نجی ونڈو کو پہلے بند کر دیں۔ ایسا کرنے کے لیے CLI سے کبھی لاگ آؤٹ نہ ہوں: لاگ آؤٹ کرنا محفوظ شدہ سائن ان کو منسوخ کر دیتا ہے، اور اس اکاؤنٹ کو دوبارہ شامل کرنا پڑے گا۔

اپنے سبسکرپشن لاگ انز کو SSH کے ذریعے دوسری Omarchy مشین پر نقل کرنے کے لیے، `omarchy agent account copy user@laptop` چلائیں۔ بھیجنے والا ایک عارضی وصول کنندہ فراہم کرتا ہے جب منزل کے پاس کوئی نصب نہ ہو، تاکہ پرانی Omarchy مشینیں بغیر اپ ڈیٹ کے اکاؤنٹس وصول کر سکیں۔ نصب شدہ وصول کنندگان کو ترجیح حاصل ہوتی ہے۔ یہ تمام Claude، Codex، اور Grok سبسکرپشنز نقل کرتا ہے؛ انہیں منتخب کرنے کے لیے فراہم کنندہ کے نام شامل کریں، جیسے `omarchy agent account copy laptop claude` میں۔ اکاؤنٹ کے نام اور کمانڈ IDs ماخذ سے میل کھاتے ہیں، بشمول منزل پر پہلے سے موجود اکاؤنٹس۔ غیر متعلقہ منزل اکاؤنٹس کو عددی لاحقہ ملتا ہے اگر ان کے نام متصادم ہوں، اور ترتیبات، مہارتیں، پلگ انز، اور گفتگو کی تاریخ ہر مشین کے لیے مقامی رہتی ہے۔

موجودہ منزل اسناد رکھی جاتی ہیں۔ ایک ماخذ اکاؤنٹ جو وہاں پہلے ہی سائن ان ہے اس کا نام اس کی اسناد کو بدلے بغیر ہم آہنگ ہو جاتا ہے؛ دوسرے اکاؤنٹس اس کے ساتھ شامل کر دیے جاتے ہیں۔ میل کھاتے اکاؤنٹس کے لیے محفوظ شدہ اسناد کو بدلنے کے لیے، منزل پر اس اکاؤنٹ کے سیشنز چھوڑنے کے بعد `omarchy agent account copy --replace laptop claude` استعمال کریں۔ ایک تازہ منزل کو ماخذ کا فعال اکاؤنٹ اور سوئچنگ ترجیحات بھی ملتی ہیں؛ ایک قائم شدہ منزل اپنی رکھتی ہے۔

اسناد SSH کے ذریعے سفر کرتی ہیں اور منزل پر نجی فائلوں میں محفوظ ہوتی ہیں، لہٰذا صرف ان مشینوں پر نقل کریں جن پر آپ اعتماد کرتے ہیں۔ یہ ایک بار کی نقل ہے، جاری ہم آہنگی نہیں۔ Codex ریفریش ٹوکنز کو دوسری مشین گھما سکتی ہے، جس سے نقل شدہ لاگ ان کو تجدید کی ضرورت پڑ جاتی ہے؛ کئی مشینوں پر بیک وقت استعمال کے لیے الگ سائن انز سب سے قابل اعتماد انتخاب رہتے ہیں۔ دیکھیں [Codex کی اکاؤنٹ تصدیق کی رہنمائی](https://developers.openai.com/codex/auth/ci-cd-auth)۔

فی فراہم کنندہ ایک اکاؤنٹ فعال ہوتا ہے، اور ہر نیا سیشن اسی کے طور پر شروع ہوتا ہے: `cx`، `cy`، ایک سادہ `claude`، `codex`، یا `grok`، `omarchy agent` کے ذریعے شروع کی گئی کوئی بھی چیز، اور اسکرپٹس یا ایڈیٹرز جو CLI کو `PATH` پر پاتے ہیں۔ `omarchy agent account use work` کے ساتھ سوئچ کریں (اور `omarchy agent account use main` کے ساتھ واپس)، یا پینل میں کسی اکاؤنٹ کا نمبر دبا کر پھر `Enter` دبا کر (یا اس کے ستارے پر کلک کر کے)۔ چل رہے Claude سیشنز بھی سوئچ ہو جاتے ہیں، ان کے اگلے پیغام سے: ہر Claude سیشن `~/.claude` میں چلتا ہے، جس میں ہمیشہ فعال اکاؤنٹ کا سائن ان ہوتا ہے۔ پرانے Omarchy کے ذریعے کسی اکاؤنٹ کے اپنے فولڈر میں شروع کیا گیا Claude سیشن اس سائن ان کو اس وقت تک رکھتا ہے جب تک وہ بند نہ ہو جائے، لہٰذا سوئچ ان سیشنز کا نام لیتا ہے اور ان کے ختم ہوتے ہی خود ہی مکمل ہو جاتا ہے۔ چل رہے Codex اور Grok سیشنز اسی اکاؤنٹ پر رہتے ہیں جس سے انہوں نے شروع کیا تھا۔ گفتگو کی تاریخ، ترتیبات، مہارتیں، اور پلگ انز اکاؤنٹس میں مشترکہ ہیں، لہٰذا اسی فولڈر میں `claude --continue` وہیں سے اٹھاتا ہے جہاں آپ نے نئے اکاؤنٹ پر چھوڑا تھا۔

ایک سے زیادہ اکاؤنٹ کے ساتھ، پینل ہر اکاؤنٹ کی حدود ساتھ ساتھ دکھاتا ہے، جس میں استعمال میں موجود پر بھرا ہوا ستارہ ہوتا ہے۔ Omarchy آپ کو مطلع کرتا ہے جب فعال اکاؤنٹ کسی حد کے 95% سے گزر جاتا ہے، اور اطلاع پر کلک کرنا سب سے زیادہ گنجائش والے اکاؤنٹ پر سوئچ کر دیتا ہے۔ یہ کبھی خود سے سوئچ نہیں کرتا۔ حد کو `omarchy agent account threshold 90` کے ساتھ تبدیل کریں۔ اگر ہر اکاؤنٹ حد سے اوپر ہو، تو آپ کو اس کے بارے میں ایک بار سنایا جائے گا، اس کے ساتھ کہ کون سا اکاؤنٹ سب سے پہلے آزاد ہوتا ہے۔ جب تک ایک فعال اکاؤنٹ اپنی حد کے 15 پوائنٹس کے اندر ہو (ڈیفالٹ پر 80%)، اس کی حدود ہر 15 کے بجائے ہر تین منٹ بعد چیک کی جاتی ہیں۔

`omarchy agent account list` ہر اکاؤنٹ اور اس کی تازہ ترین حدود دکھاتا ہے، `omarchy agent account remove work` ایک کو بھول جاتا ہے، اور `omarchy agent account rename primary Hey` ایک کا نام بدلتا ہے (یا پینل میں کسی اکاؤنٹ کے نام پر کلک کریں)۔ یہ کمانڈز آپ کے ڈیفالٹ ایجنٹ کے اکاؤنٹس پر کام کرتی ہیں؛ دوسرے فراہم کنندہ تک پہنچنے کے لیے، پہلے اس کا نام لیں، جیسے `omarchy agent account use codex side` میں۔ `~/.claude` یا `~/.codex` میں آپ کے پاس پہلے سے موجود لاگ ان _Main_ اکاؤنٹ ہے۔ Codex کا وہیں رہتا ہے جہاں وہ ہے؛ Claude کا ایک اپنے فولڈر میں انتظار کرتا ہے جبکہ دوسرا اکاؤنٹ فعال ہوتا ہے۔ تقریباً آٹھ گھنٹے سے زیادہ غیر استعمال شدہ چھوڑا گیا اکاؤنٹ _Sign-in required_ دکھا سکتا ہے؛ اس اکاؤنٹ کو پینل میں ہی دوبارہ سائن ان کرنے کے لیے اس پر کلک کریں، یا اس پر سوئچ کریں اور ایک سیشن شروع کریں، جو سائن ان کو خود تازہ کر دیتا ہے۔ `claude mcp add` کے ساتھ آپ جو MCP سرورز شامل کرتے ہیں وہ ہر Claude اکاؤنٹ تک پہنچتے ہیں، کیونکہ وہ سب `~/.claude` میں چلتے ہیں؛ Codex اور Grok کے لیے، جب اکاؤنٹ شامل کیا گیا تھا اس وقت آپ کے پاس موجود سرورز اس کے ساتھ آ جاتے ہیں، لیکن بعد والے صرف اسی اکاؤنٹ تک پہنچتے ہیں جس میں آپ نے انہیں شامل کیا تھا۔ Claude Desktop اپنا سائن ان رکھتا ہے، اور CLI بائنری کے مطلق راستے کے ساتھ تشکیل شدہ Codex یا Grok ٹولز سوئچ کی پیروی نہیں کرتے۔ ایک واضح `CLAUDE_CONFIG_DIR`، `CODEX_HOME`، یا `GROK_HOME` منتخب اکاؤنٹ پر ترجیح لیتا ہے۔

### کریش کی تشخیص

Omarchy پروسیس کریشز کے لیے systemd-coredump کی نگرانی کرتا ہے۔ جب آپ نے ڈیفالٹ ایجنٹ منتخب کر لیا ہو، تو آپ کا کوئی بھی پروگرام جو کور ڈمپ کرے ایک "Process crashed" اطلاع لاتا ہے — اس پر کلک کریں، اور کریش آپ کے ڈیفالٹ ایجنٹ کے حوالے کر دیا جاتا ہے Omarchy کی omarchy-diagnose-crash مہارت کے ساتھ، جو ایجنٹ کو کور ڈمپ سے حقائق قائم کرنے اور یہ فیصلہ کرنے میں لے جاتی ہے کہ آیا کریش upstream رپورٹ کرنے کے قابل ہے۔ آپ اسے `coredumpctl list` سے کسی بھی PID کے خلاف ہاتھ سے بھی چلا سکتے ہیں `omarchy agent crash <pid>` کے ساتھ۔

نگرانی بطور ڈیفالٹ آن ہوتی ہے۔ اسے _Trigger > Toggle > Crash Capture Off_ کے تحت بند کر دیں (یا `omarchy toggle crash-capture` کے ساتھ) اور اطلاعات رک جاتی ہیں؛ `omarchy agent crash <pid>` ہاتھ سے پھر بھی کام کرتا ہے۔

کریشز کو ایک وقت میں ایک پروگرام کے حساب سے خاموش بھی کیا جا سکتا ہے، جو تشخیص آخر میں آپ کو پیش کرتی ہے۔ `omarchy crash mute hyprland` صرف اس پروگرام کے لیے اطلاعات روک دیتا ہے، `omarchy crash mute hyprland off` انہیں واپس لاتا ہے، اور `omarchy crash mute` اپنے طور پر فہرست دیتا ہے کہ آپ نے کیا خاموش کیا ہے۔ یہ بائنری کا راستہ اس کے نام کی طرح خوشی سے لیتا ہے، لہٰذا `omarchy crash mute /usr/bin/hyprland` وہی کام کرتا ہے۔ کسی نام کو جس میں جگہ ہو کوٹ کریں، جیسے `omarchy crash mute 'Some App'` میں۔ باقی سب کچھ پھر بھی مطلع کرتا ہے، اور خاموش کیا گیا پروگرام پھر بھی کریش ہوتا ہے — یہ یاد دہانی چھپاتا ہے، یہ کچھ ٹھیک نہیں کرتا۔

### ڈیسک ٹاپ ایپس

_Install > AI_ مینو چند گرافیکل AI ایپس بھی رکھتا ہے: Amp Desktop، Antigravity Desktop، ChatGPT ڈیسک ٹاپ ایپ، Claude ڈیسک ٹاپ ایپ (Anthropic کا Linux بیٹا، Chat، Cowork، اور Claude Code ٹیبز کے ساتھ)، Grok Bot xAI کے ماڈلز کے ساتھ بات چیت کے لیے، Herdr Desktop، Hermes Desktop، OpenClaw، Perplexity ڈیسک ٹاپ ایپ، اور T3 Code۔ Grok Bot ڈیسک ٹاپ چیٹ ایپ ہے۔ کوڈنگ ایجنٹ `grok` کمانڈ ہے۔

Hermes Desktop وہ ہے جس کے بارے میں جاننا ضروری ہے، کیونکہ ایک مشین کے پاس ایک Hermes ہوتا ہے، اور وہ ایپ کا ہوتا ہے: Hermes صرف ایپ کے ذریعے ہی نصب ہوتا ہے، اور ڈیفالٹ ایجنٹ جو `hermes` کمانڈ چلاتا ہے وہ ایپ کی ہوتی ہے۔ Hermes کو ڈیفالٹ ایجنٹ کے طور پر منتخب کرنا وہی چیز نصب کرتا ہے جو _Install > AI_ اندراج کرتا ہے: پیکیج، اور `~/.hermes` کے تحت ایک Hermes رن ٹائم جو Hermes کے اپنے انسٹالر کے ذریعے سیٹ اپ ہوتا ہے، جس میں پہلی بار چند منٹ لگتے ہیں۔ وہ رن ٹائم وہ واحد Hermes ہے جسے ٹرمینل `hermes` کمانڈ، ڈیفالٹ ایجنٹ اور ایپ سب استعمال کرتے ہیں، اور یہ Omarchy ریلیز کا انتظار کرنے کے بجائے `hermes update` کے ساتھ خود کو اپ ڈیٹ کرتا ہے۔ اسے نصب کرنا Hermes کو Omarchy تھیم بھی `omarchy` نامی سکن کے طور پر دیتا ہے، جس کی ہر Hermes سطح پیروی کرتی ہے جب آپ تھیمز تبدیل کرتے ہیں؛ اگر آپ نہیں چاہتے کہ ایسا ہو تو Hermes کی Appearance ترتیبات کے تحت یا `/skin` کے ساتھ کوئی اور منتخب کریں، اور Omarchy اس انتخاب کو چھوڑ دیتا ہے۔ _Remove > AI_ کے تحت ایپ کو ہٹانا پہلے Hermes کو بند کرتا ہے، گیٹ وے سمیت، اس رن ٹائم کو اس کے ساتھ لے جاتا ہے، اور آپ کی چیٹس، یادیں، اور وہ مہارتیں جو Hermes نے اپنے لیے لکھی تھیں رکھتا ہے جب تک کہ آپ اسے دوسری صورت نہ کہیں: یہ پوچھتا ہے، بطور ڈیفالٹ نہیں کے ساتھ، کہ آیا وہ ڈیٹا اور آپ کی کنکشن ترتیبات بھی جانی چاہئیں۔

OpenClaw کا ڈیسک ٹاپ تجربہ اس کا Control UI ہے، جو اس کے اپنے مقامی گیٹ وے کی پشت پناہی والی ویب ایپ کے طور پر کھلتا ہے۔ OpenClaw `~/.openclaw` میں رہتا ہے اور خود کو اپ ڈیٹ کرتا ہے: Control UI کا "Update Gateway" بٹن استعمال کریں یا `openclaw update` چلائیں، اور گیٹ وے نئے ورژن پر دوبارہ شروع ہو جاتا ہے۔ Omarchy صرف اس ریلیز کا انتخاب کرتا ہے جس سے تازہ تنصیب شروع ہوتی ہے۔ OpenClaw آپ کا ڈیفالٹ ایجنٹ بھی ہو سکتا ہے: اسے _Agent > Harness_ کے تحت منتخب کرنا اسی کاپی کو `~/.openclaw` میں سیٹ اپ کرتا ہے، اور ایجنٹ OpenClaw کا ٹرمینل UI اس کے گیٹ وے سے منسلک کھولتا ہے۔ _Remove > AI_ کے تحت OpenClaw کو ہٹانا گیٹ وے سروس اور ایپ کو اس کے ساتھ لے جاتا ہے اور پھر پوچھتا ہے کہ آیا `~/.openclaw` بھی جانا چاہیے، کیونکہ اس میں خود OpenClaw اور اس کے ڈاؤن لوڈ کردہ پلگ ان رن ٹائمز کے ساتھ آپ کی چیٹس اور اسناد موجود ہوتی ہیں؛ ڈیفالٹ اسے رکھتا ہے، اور OpenClaw کو دوبارہ نصب کرنا اسے واپس اٹھا لیتا ہے۔

Herdr Desktop [Herdr](https://herdr.dev) ڈیسک ٹاپ ایپ ہے: ٹرمینلز اور کوڈنگ ایجنٹس کی جگہیں، ٹیبز، اور پینز جو اس کے کور میں چلتے رہتے ہیں جب آپ ونڈو بند کرتے ہیں۔ یہ پیکیج کے بجائے Herdr کے اپنے انسٹالر سے آتا ہے، لہٰذا یہ `~/.local/share/herdr-app` میں رہتا ہے، جب آپ کے پاس ابھی تک کوئی نہ ہو تو اپنے کور کو `~/.local/bin/herdr-core` میں ساتھ لاتا ہے، اور دونوں کو خود اپ ڈیٹ کرتا ہے۔ یہ اس `herdr` کمانڈ کے ساتھ بیٹھتا ہے جو Omarchy `Super + Ctrl + Return` پر فراہم کرتا ہے اسے بدلنے کے بجائے، اور اس کمانڈ کی براہ راست کیز حاصل کرتا ہے: `Alt + Return` اور `Alt + Shift + Return` ایک پین کو نیچے یا دائیں تقسیم کرتے ہیں، `Alt + Escape` اسے بند کرتا ہے، `Ctrl + Alt + Arrow` پینز کے درمیان منتقل ہوتا ہے، `Alt + 1..9` اور `Alt + Left/Right` ایک ٹیب منتخب کرتے ہیں، اور `Alt + Up/Down` جگہوں کے درمیان منتقل ہوتے ہیں۔ `Ctrl + 1..9` ایک جگہ منتخب کرتا ہے اور `Alt + Shift + Up/Down` ایجنٹس میں سے گزرتا ہے۔ `Ctrl + Space` پریفکس کیز صرف ٹرمینل رہتی ہیں، کیونکہ ایپ کسی تسلسل کے لیے سادہ Ctrl کی کو نہیں پکڑ سکتی۔ Omarchy انہیں `~/.config/herdr-app/keys.json` میں لکھتا ہے، اور `omarchy-refresh-herdr-app` انہیں واپس رکھتا ہے۔ اسے نصب کرنا Herdr کی Omarchy تھیم منتخب کرتا ہے، جو اس کے بعد سے آپ کی Omarchy تھیم کی پیروی کرتی ہے۔ Herdr ہلکے موڈ کے لیے ایک تھیم اور تاریک کے لیے ایک رکھتا ہے، لہٰذا تاریک اور ہلکی Omarchy تھیم کے درمیان سوئچ کرنے کے بعد، دوسرے موڈ کے لیے Herdr کے تھیم پکر میں ایک بار پھر Omarchy منتخب کریں۔

T3 Code پیکیج کے بجائے `~/.local/share/t3code` میں اپنی سرکاری AppImage ریلیز سے چلتا ہے، لہٰذا یہ خود کو اپ ڈیٹ کرتا ہے۔ اسے نصب کرنا پوچھتا ہے کہ آیا Stable یا Nightly چینل پر شروع کرنا ہے؛ بعد میں T3 Code کی ترتیبات میں سوئچ کریں۔ آپ کے تھریڈز اور ترتیبات `~/.t3` میں رہتے ہیں، اور _Remove > AI_ کے تحت T3 Code کو ہٹانا انہیں اس کے ساتھ لے جاتا ہے۔

### مقامی ماڈل

اپنے کوڈنگ ایجنٹس کے لیے اپنی مشین پر ایک اوپن ماڈل چلائیں۔ آپ کے پرامپٹ اور کوڈ مشین پر رہتے ہیں؛ ماڈل کو بھیجی گئی کوئی چیز اسے نہیں چھوڑتی۔ اس سے شروع کریں:

```bash
omarchy models use best text
```

یہ اس مشین کے لیے بہترین ٹیکسٹ ماڈل سیٹ اپ کرتا ہے، اس قسم کا جو آپ کے ایجنٹس استعمال کرتے ہیں۔ تصویر، ویڈیو اور موسیقی کے ماڈلز کا اپنا بہترین ہوتا ہے: `omarchy models use best image`، `video` یا `music`۔ اس مشین کے لیے ہر قسم کی پسند دیکھنے کے لیے `omarchy models use best` چلائیں۔

یا مقامی ماڈلز پینل کو اوپر والی بار میں اس کے چمک آئیکن سے کھولیں، ایجنٹس آئیکن کے ساتھ، یا Super + Ctrl + Alt + X کے ساتھ، اور + منتخب کریں۔ آئیکن اس وقت ظاہر ہوتا ہے جب کوئی ماڈل اس مشین میں فٹ آتا ہو۔ Podman، جو ماڈلز چلاتا ہے، Omarchy کے ساتھ آتا ہے، جیسا کہ NVIDIA مشین پر NVIDIA کا کنٹینر ٹول کٹ، جو انہیں GPU دیتا ہے؛ اگر کوئی بھی غائب ہو، تو پہلا سیٹ اپ اسے نصب کر دیتا ہے۔ پھر Omarchy اس مشین کے لیے تجویز کردہ ماڈل منتخب کرتا ہے، اسے ڈاؤن لوڈ کرتا ہے، اور اسے شروع کرتا ہے۔ دسیوں GB کے ڈاؤن لوڈ کی توقع رکھیں اور ماڈل چلتے وقت مشین کی زیادہ تر میموری استعمال میں ہوگی: Flash Next اپنے مکمل 256K سیاق و سباق کے ساتھ تقریباً 100 GiB استعمال کرتا ہے۔ اگر دوسرے ماڈلز وہ میموری رکھے ہوئے ہوں جس کی اسے ضرورت ہے، تو یہ رکا ہوا سیٹ اپ ہوتا ہے، ایک کو روکتے ہی شروع ہونے کے لیے تیار۔ ماڈل لاگ آؤٹ پر رک جاتا ہے؛ جب آپ کو کسی اور چیز کے لیے میموری درکار ہو تو اسے خود روک دیں۔

`omarchy models list` اختیارات دکھاتا ہے اور بتاتا ہے کہ کچھ کیوں فٹ نہیں آتے۔ ایک اور سیٹ اپ کرنے کے لیے، `omarchy models use <recipe>` چلائیں۔ آج، `qwen3.8-flash-next-gufo` اور `qwen3.8-27b-gufo` 128 GB Strix Halo مشینوں کے لیے دستیاب ہیں؛ 27B تقریباً 40 GiB لیتا ہے، لہٰذا یہ دوسرے کام کے لیے جگہ چھوڑتا ہے۔ Intel کے Arc B390 والی 64 GB لیپ ٹاپ پر، `qwen3.6-35b-a3b-llamacpp` تقریباً 30 GiB میں چلتا ہے۔ نئی ترکیبیں اور تجاویز پیکیج کے ذریعے `omarchy update` کے ساتھ آتی ہیں۔

آپ جو بھی ماڈل سیٹ اپ کرتے ہیں اسے مقامی ماڈلز پینل میں اپنی لائن ملتی ہے: اسے شروع کرنے کے لیے چلائیں، اسے روکنے اور اس کی میموری آزاد کرنے کے لیے روکیں، اور اس پر اپنا ایجنٹ کھولنے کے لیے ٹرمینل بٹن۔ اوپر کے پار، ایک بار دکھاتا ہے کہ مشین کی میموری Omarchy خود (سسٹم اور آپ کی ایپس)، ہر چلتے ماڈل، اور جو آزاد ہے کے درمیان کیسے تقسیم ہے۔ ایک رکے ہوئے ماڈل کی طرف اشارہ کریں اور بار دکھاتا ہے کہ آیا یہ فٹ آتا ہے، یا کتنا کم ہے۔ کئی ایک ساتھ چل سکتے ہیں جب وہ میموری میں ایک ساتھ فٹ آ جائیں؛ اگر کوئی فٹ نہ آئے، تو Omarchy بتاتا ہے کہ کون سا چلتا ماڈل روکنا ہے۔ انہیں دوبارہ ترتیب دینے کے لیے لائنوں کو ان کے لوگو سے گھسیٹیں، اور ماڈل اور اس کے ڈاؤن لوڈ کو ہٹانے کے لیے منتخب لائن پر Delete دبائیں۔

آپ جو بھی کوڈنگ ماڈل سیٹ اپ کرتے ہیں اسے ایپ لانچر میں اپنی انٹری بھی ملتی ہے، ماڈل کے نام کے تحت اور اس کے بنانے والے کے لوگو کے ساتھ، اسی طرح جیسے Claude، Codex یا Grok میں سائن ان کرنا ایک شامل کرتا ہے۔ یہ اس ماڈل پر آپ کا ایجنٹ کھولتا ہے، اور اگر ماڈل نہ چل رہا ہو تو پہلے اسے شروع کرتا ہے: ٹرمینل اسے لوڈ ہوتا دکھاتا ہے اور تیار ہوتے ہی ایجنٹ کے حوالے کر دیتا ہے۔ ماڈل ہٹانا اس کی انٹری ہٹا دیتا ہے۔

ہر ماڈل کوڈنگ کے لیے نہیں ہوتا۔ تصویر، ویڈیو اور موسیقی کے ماڈلز اس کے بجائے Fantasi میں کھلتے ہیں، Omarchy کی اس مشین پر چلتے ماڈل کے ساتھ تصویریں، ویڈیو اور موسیقی بنانے کی ایپ، وہاں منتخب یا مقامی ماڈلز پینل میں ان کی لائن سے۔

ایک ماڈل بالکل ویسا ہی چلتا رہتا ہے جیسا اسے سیٹ اپ کیا گیا تھا، لہٰذا Omarchy اپ ڈیٹ کبھی آپ کے ایجنٹس کے نیچے ایک کو دوبارہ شروع نہیں کرتا۔ جب Omarchy کے پاس آپ کے سیٹ اپ کردہ ماڈل کے لیے نیا رن ٹائم یا نئے ویٹس ہوں، تو اس کی لائن ایک اپ ڈیٹ بٹن دکھاتی ہے: اسے دبائیں اور ماڈل پس منظر میں دوبارہ سیٹ اپ ہو جاتا ہے، صرف وہ ڈاؤن لوڈ کرتا ہے جو تبدیل ہوا، اور نئے ورژن پر دوبارہ شروع ہو جاتا ہے۔ جو ماڈل رکا ہوا تھا وہ رکا رہتا ہے۔ `omarchy models update` ٹرمینل سے ہر ماڈل کے لیے وہی کرتا ہے۔

کمانڈ لائن سے، `omarchy models start <recipe>` اور `omarchy models stop <recipe>` وہی کرتے ہیں، `omarchy models status` ہر ماڈل دکھاتا ہے، اور `omarchy agent --local` آپ کے شروع کردہ آخری ماڈل کو pi میں کھولتا ہے، آپ کا ڈیفالٹ ایجنٹ جو بھی ہو۔ اس ماڈل کو وہ بنانے کے لیے جو ایجنٹ ہاٹ کی، Quake کنسول، اور _Make something_ کھولتے ہیں، `omarchy default agent local` چلائیں یا _Agent > Harness_ کے تحت _Local model_ منتخب کریں۔ pi ہر اس ماڈل کی فہرست بھی دیتا ہے جو آپ نے سیٹ اپ کیا ہے، اور وہ جو ان مشینوں پر ہیں جن کے ساتھ آپ نے جوڑا بنایا ہے، اپنے ماڈل پکر میں، لہٰذا سادہ `pi` بھی ان تک پہنچتا ہے۔ کوئی بھی OpenAI سے ہم آہنگ کلائنٹ بھی جڑ سکتا ہے: `status` ہر ماڈل کا پتہ دکھاتا ہے (پہلا `http://127.0.0.1:11435/v1` ہے)، ترکیب کا نام ماڈل ہے، اور کی `~/.config/omarchy/agent-local/key` میں ہے۔

`omarchy models remove <recipe>` ایک ماڈل اور وہ ڈاؤن لوڈز حذف کر دیتا ہے جو کوئی دوسرا ماڈل استعمال نہیں کرتا۔

فریق ثالث کے رن ٹائمز پر ان کے ناشر کے ساتھ لیبل لگا ہوتا ہے۔ Omarchy ہر ماڈل کو بغیر نیٹ ورک رسائی کے چلاتا ہے۔

### مقامی LLMs

Omarchy مقامی LLM ماڈلز چلانے کے دو طریقے تجویز کرتا ہے: LM Studio اور Ollama۔ LM Studio اوپن ویٹ ماڈلز تلاش کرنے، انہیں نصب کرنے، اور انہیں چلانے کے لیے GUI انٹرفیس فراہم کرتا ہے۔ یہ آسانی سے شروع کرنے کا بہترین طریقہ ہے۔ Ollama اسی طرح کرنے کے لیے CLI پیش کرتا ہے۔ لیکن اگر آپ مقامی ماڈلز میں نئے ہیں، تو میں LM Studio سے شروع کروں گا۔ آپ Omarchy Menu میں _Install > AI_ کے تحت کسی کو بھی نصب کر سکتے ہیں۔

### Omarchy کی مہارتیں

ایجنٹ مہارتیں AI کو مخصوص ٹولز کو مخصوص طریقے سے استعمال کرنے میں مدد دیتی ہیں، اور Omarchy ان میں سے سات فراہم کرتا ہے۔ omarchy مہارت سسٹم کو اپنی پسند کے مطابق بنانے کا احاطہ کرتی ہے، جیسے آپ کی Hyprland کنفگ کو ٹھیک کرنا یا بار کو ایڈجسٹ کرنا۔ omarchy-make-theme، omarchy-make-plugin، omarchy-make-app، اور omarchy-make-game کچھ نیا بنانے کا احاطہ کرتی ہیں، omarchy-contribute بگ رپورٹ کرنے یا upstream فکس بھیجنے کا احاطہ کرتی ہے، اور omarchy-diagnose-crash کسی کریش کے کور ڈمپ پر کام کرتی ہے۔ وہ Claude Code (`~/.claude/skills`)، Codex (`~/.codex/skills`)، Pi (`~/.pi/agent/skills`)، Antigravity (`~/.gemini/config/skills`)، Hermes (`~/.hermes/skills` اور ہر `~/.hermes/profiles/*/skills`)، اور عام `~/.agents/skills` مقام کے لیے مہارت ڈائریکٹریوں میں سم لنک شدہ ہیں، لہٰذا زیادہ تر ہارنس انہیں خود بخود اٹھا لیتے ہیں۔ اسی نام والا آپ کا اپنا مہارت فولڈر ترجیح لیتا ہے۔

لیکن آپ کو ان مہارتوں کو تجرباتی سمجھنا چاہیے۔ مختلف ماڈلز اسے مختلف اثر کے ساتھ استعمال کریں گے۔ پہلے پلان موڈ میں چلانا بہتر ہے، تاکہ آپ کو اندازہ ہو کہ ایجنٹ کیا تبدیل کرنا چاہے گا۔ اور پھر تبدیلیوں کو واپس کرنے یا حتیٰ کہ `omarchy reinstall configs` کو چلانے کے لیے تیار رہیں، اگر ایجنٹ ہر چیز کی گڑبڑ کر دے۔
