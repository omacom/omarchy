Omarchy آپ کے لیے کوئی ڈیفالٹ منتخب کیے بغیر نیچے دیے گئے کوڈنگ ایجنٹس کے لانچر شامل کرتا ہے۔ پہلی بار استعمال پر اس کا CLI انسٹال کرنے کے لیے کمانڈ چلائیں، پھر اشارہ ملنے پر تصدیق کریں۔ Hermes اور OpenClaw استثنا ہیں: ان کے لیے mise کے ذریعے کچھ بھی انسٹال نہیں ہوتا، اور ان میں سے کسی کو منتخب کرنے پر اس کی اپنی خودکار طور پر اپڈیٹ ہونے والی کاپی سیٹ اپ ہو جاتی ہے، جیسا کہ نیچے _ڈیسک ٹاپ ایپس_ میں بیان کیا گیا ہے۔

### ایجنٹس انسٹال اور اپڈیٹ کرنا

Hermes اور OpenClaw کے علاوہ، یہ ایجنٹس mise کی سست انسٹالیشن استعمال کرتے ہیں: پہلی لانچ پر CLI انسٹال ہو جاتا ہے، اور بعد کی لانچز اسی کو دوبارہ استعمال کرتی ہیں۔ mise انسٹال شدہ ایجنٹ کے لیے نئی ریلیز بھی چیک کرتا ہے، زیادہ سے زیادہ ہر چار گھنٹے میں ایک بار، شروع ہونے سے ذرا پہلے یا پس منظر میں شیل پرامپٹ پر۔ اگر وہ اپڈیٹ ناکام ہو جائے یا آپ آف لائن ہوں تو انسٹال شدہ ورژن چلتا ہے۔ `omarchy update` انسٹال شدہ ایجنٹس کو باقی Omarchy کے ساتھ اپڈیٹ کرتا ہے، اور `mup` صرف mise کے زیر انتظام ٹولز کو اپڈیٹ کرتا ہے۔

کسی ایجنٹ کا اپنا اپڈیٹر، جیسے `claude update`، `codex update`، یا کسی ایپ میں اپڈیٹ بٹن، mise کے زیر انتظام انسٹال کو اپڈیٹ نہیں کرتا۔ `codex update` ناکام ہو جاتا ہے، اور `claude update` کامیابی کی اطلاع دے سکتا ہے جبکہ ایک الگ کاپی انسٹال کر دیتا ہے جسے mise ٹریک نہیں کرتا۔ اگر آپ اس کے بجائے کسی ایجنٹ کا اپنا انسٹالر اور اپڈیٹر استعمال کرنا چاہتے ہیں تو اسے `disable_tools` میں شامل کریں؛ دیکھیں [پہلے سے انسٹال شدہ CLI ٹولز](18-development-tools.md#preinstalled-cli-tools)۔

تمام تشکیل شدہ سست ٹولز کو ضرورت پڑنے سے پہلے انسٹال کرنے کے لیے `mise install --include-lazy` چلائیں۔ اس میں ایجنٹس کے ساتھ ساتھ Omarchy کے دیگر ڈیفالٹ CLI ٹولز بھی شامل ہیں۔ ایک اکیلا ٹول انسٹال کرنے یا اپنی انسٹالیشن استعمال کرنے کے لیے دیکھیں [پہلے سے انسٹال شدہ CLI ٹولز](18-development-tools.md#preinstalled-cli-tools)۔

`grok` mise کے فرسٹ پارٹی `grok` پیکیج کے ذریعے انسٹال ہوتا ہے، اسی طرح جیسے `claude` اور `codex`۔ `grok` چلائیں، یا ایجنٹس پینل میں اس پر ستارہ لگائیں۔ x.ai پر موجود `curl | bash` انسٹالر کو چھوڑ دیں۔ وہ راستہ `~/.grok/bin` میں دوسری کاپی رکھ دیتا ہے، اسے `PATH` کے شروع میں شامل کر دیتا ہے، اور Omarchy کے ریپر کو اوور رائٹ کر دیتا ہے۔

`dsh` اپنا براؤزر UI `127.0.0.1:3080` پر کھولتا ہے، جس میں لانچ ڈائرکٹری اس کا ڈیفالٹ ورک اسپیس ہوتی ہے۔ اس کا براؤزر UI کوئی ابتدائی پرامپٹ نہیں لیتا، لہٰذا `omarchy agent prompt` اسے آپ کے کلپ بورڈ پر موجود پرامپٹ کے ساتھ کھولتا ہے تاکہ آپ اسے پیسٹ کر سکیں۔ Omarchy اسے DeepSeek کے بغیر منظوری والے اجازت پری سیٹ کے ساتھ شروع کرتا ہے۔ جب آپ اس کا آفیشل ماڈل API استعمال کرتے ہیں تو DeepSeek Harness سیشن لاگز DeepSeek کو اپ لوڈ کرتا ہے؛ اسے اس کے براؤزر UI میں _Settings > General > Upload Session Log_ کے تحت بند کر دیں۔ آپ جو فیڈ بیک اسے بھیجتے ہیں وہ بھی سیشن کے ساتھ اپ لوڈ ہو جاتا ہے، الا یہ کہ آپ اسے `DSH_TELEMETRY_MODE=DISABLED` کے ساتھ شروع کریں۔

### ڈیفالٹ ایجنٹ

اپنے ڈیفالٹ ایجنٹ کو ایجنٹس پینل میں کسی ایجنٹ کے ساتھ والے ستارے سے منتخب کریں، جو ڈیفالٹ پر بھرا ہوا ہوتا ہے، یا `omarchy default agent <name>` سے، جو وہاں لائن نہ رکھنے والے کسی بھی ہارنس کو بھی قبول کرتا ہے۔ اگر ایجنٹ ابھی انسٹال نہیں ہوا تو اسے منتخب کرنے پر پہلے وہ انسٹال ہو جاتا ہے، اور اسے ایپ لانچر میں Agent کے ساتھ اس کا اپنا لانچر بھی مل جاتا ہے۔ تازہ Omarchy آپ کو ایک بار کی اطلاع کے ساتھ ایک ایجنٹ سیٹ اپ کرنے کی دعوت دیتا ہے، جو ایجنٹس پینل کھولتی ہے۔

Claude منتخب کرنے پر Chromium، Chrome، Brave، Brave Origin، اور Edge کے لیے اس کی براؤزر ایکسٹینشن سیٹ اپ کرنے کی بھی کوشش کی جاتی ہے۔ ایکسٹینشن سیٹ اپ تمام صارفین پر لاگو ہوتا ہے اور آپ سے آپ کا سسٹم پاس ورڈ مانگ سکتا ہے؛ منسوخ کرنے یا ایکسٹینشن انسٹال ناکام ہونے پر بھی Claude منتخب ہو جاتا ہے اور لانچ ہو جاتا ہے۔ اپنا براؤزر دوبارہ شروع کریں، اشارہ ملنے پر ایکسٹینشن فعال کریں، اور اسے منسلک کرنے کا عمل مکمل کرنے کے لیے Claude میں سائن ان کریں۔ کنکشن چیک کرنے کے لیے Claude میں `/chrome` چلائیں۔ Firefox اور Zen اس ایکسٹینشن کو سپورٹ نہیں کرتے۔ اگر یہ سیٹ اپ شامل کیے جانے سے پہلے ہی Claude آپ کا ڈیفالٹ تھا تو ایکسٹینشن انسٹال کرنے کے لیے اسے دوبارہ منتخب کریں۔

منتخب کرنے کے بعد، `Super + Shift + Ctrl + A` ڈیفالٹ ایجنٹ کو ایک مخصوص ٹرمینل ونڈو میں لانچ کرتا ہے (یا اگر آپ نے ابھی تک کوئی منتخب نہیں کیا تو چننے والا کھول دیتا ہے)۔ آپ اسے `omarchy agent prompt "Review this project"` کے ساتھ سیدھا کسی کام میں بھی لانچ کر سکتے ہیں۔ Freebuff اور DeepSeek Harness کوئی ابتدائی پرامپٹ نہیں لیتے، لہٰذا وہ اس کے بجائے آپ کے کلپ بورڈ پر موجود پرامپٹ کے ساتھ کھلتے ہیں تاکہ آپ اسے پیسٹ کر سکیں۔ اس طرح لانچ کیے گئے ایجنٹس اپنے متعلقہ نہ رکنے، نہ پوچھنے والے موڈز میں بغیر نگرانی کے چلتے ہیں، لہٰذا تیار رہیں کہ وہ واقعی کچھ کر گزریں گے! MiniMax Code کے انٹرایکٹو سیشنز کے لیے ایسا کوئی موڈ نہیں ہے، لہٰذا وہ معمول کے مطابق اجازتیں مانگتا ہے۔ اور چونکہ ایجنٹس آپ کی ہوم ڈائرکٹری کے لیے ٹرسٹ یاد رکھنے سے انکار کرتے ہیں، اس لیے `$HOME` سے لانچز اس کے بجائے `~/Work` میں شروع ہوتی ہیں۔

ٹرمینل شارٹ کٹس بھی ہیں: `a` موجودہ ٹرمینل میں ڈیفالٹ ایجنٹ کو ان لائن چلاتا ہے، جبکہ `c`، `cx`، اور `cy` OpenCode، Claude Code، اور Codex کو براہ راست شروع کرتے ہیں (ایک بار پھر ان کے خودکار منظوری دینے والے موڈز میں)۔ تھیم کی تبدیلیاں ایجنٹس کے ساتھ بھی ہم آہنگ ہو جاتی ہیں: جب آپ Omarchy تھیم تبدیل کرتے ہیں تو Claude Code، Pi، OpenCode، اور Hermes (ایک بار جب Omarchy نے اسے انسٹال کر لیا ہو) سب اس کے ساتھ چلتے ہیں۔

### آپ کی ایجنٹ ہدایات

ہر ایجنٹ کے لیے ذاتی قواعد `~/.agents/AGENTS.md` میں جاتے ہیں، مشترکہ اسکلز کے ساتھ `~/.agents/skills` میں۔ اسے ایجنٹس پینل میں + کے ساتھ والے دستاویز آئیکن سے کھولیں، یا `omarchy agent instructions --edit` سے، جو اسے ہر اس ہارنس میں بھی لنک کر دیتا ہے جو اپنی عالمی فائل رکھتا ہے: `~/.claude/CLAUDE.md`، `~/.codex/AGENTS.md`، `~/.pi/agent/AGENTS.md`، `~/.config/opencode/AGENTS.md`، Copilot کی `~/.copilot/copilot-instructions.md`، وغیرہ۔ Crush اور Amp `~/.config/AGENTS.md` لنک پڑھتے ہیں، جبکہ omp، Kimi، اور DeepSeek Harness براہ راست `~/.agents/AGENTS.md` پڑھتے ہیں۔ ڈیفالٹ ایجنٹ منتخب کرنے پر وہ بھی لنک ہو جاتا ہے۔ اگر کوئی ہدایات فائل آپ کے پاس پہلے سے موجود تھی اور ابھی کوئی مشترکہ فائل نہیں تھی تو وہی مشترکہ فائل بن جاتی ہے؛ ورنہ اسے لنک کے ساتھ `.bak` کے طور پر رکھا جاتا ہے۔ ایک اور ایجنٹ انسٹال کرنے کے بعد دوبارہ لنک کرنے کے لیے `omarchy agent instructions` چلائیں۔

### ایجنٹس پینل

اوپر والی بار میں ایک ایجنٹس آئیکن ہے۔ ایجنٹ سیٹ اپ کرنے سے پہلے، اس کا پینل شروع کرنے کے تین طریقے پیش کرتا ہے: Claude، Codex، Grok، Gemini، Muse، Cursor، یا Copilot سبسکرپشن میں سائن ان کریں، یا More کے تحت OpenCode Go، MiniMax، Synthetic، یا Z.ai کوڈنگ پلان؛ Fireworks، OpenCode Zen اور Go، OpenRouter کے ساتھ جتنا استعمال اتنی ادائیگی کریں، یا More کے تحت DeepSeek یا کوئی بھی دوسرا فراہم کنندہ جس میں OpenCode سائن ان کرتا ہے، یہ سب OpenCode میں چلتے ہیں؛ یا اپنے کمپیوٹر کے لیے بہترین ماڈل چلائیں، جب کوئی اس میں فٹ آتا ہو۔ آپ جو پہلا طریقہ مکمل کرتے ہیں وہی آپ کا ڈیفالٹ ایجنٹ بن جاتا ہے، اور پینل میں +، یا Omarchy Menu میں _Agent > Add_، بعد میں وہی تین طریقے پیش کرتا ہے۔ اس کے بعد، پینل ہر سبسکرپشن کو ایک صفحے پر رکھتا ہے: ہر ایجنٹ اور اکاؤنٹ اس کے پلان کے ساتھ، اس کی 5 گھنٹے کے سیشن اور ہفتہ وار حدود میں سے ہر ایک کے لیے ایک میٹر جس کے ساتھ اس کے ری سیٹ ہونے تک کا وقت ہوتا ہے (درست فیصد کے لیے ہوور کریں)، یا باقی پری پیڈ بیلنس، ایک لائن کے نیچے جو آپ کے ان سب میں مجموعی استعمال کے درمیان گھومتی رہتی ہے، جیسے اس ہفتے کے ٹوکنز اور آپ کا سب سے زیادہ استعمال شدہ ماڈل۔ _کچھ زبردست بنائیں_ کے تحت یہ نئی تھیم، پلگ ان، ایپ، یا گیم کے لیے ابتدائی پرامپٹس پیش کرتا ہے جو کام آپ کے ڈیفالٹ ایجنٹ کے حوالے کر دیتے ہیں۔ ایپس اسی طرح بنائی جاتی ہیں جیسے Omarchy کی اپنی Hype، Monologue، اور Omacut ہیں، C++ اور Qt Quick میں، omarchy-make-app ایجنٹ اسکل کی پیروی کرتے ہوئے، اور انہیں درکار کمپائلر اور Qt اجزا انسٹال شدہ آتے ہیں۔ گیمز `~/Games/vibes` میں ایک واحد three.js صفحہ ہوتی ہیں، omarchy-make-game ایجنٹ اسکل کی پیروی کرتے ہوئے، اور سب موجودہ تھیم میں ایک Game Vibes لانچر سے کھلتی ہیں؛ وہ ویب سے three.js لوڈ کرتی ہیں، لہٰذا شروع ہونے کے لیے انہیں کنکشن درکار ہوتا ہے۔ Claude Code، Codex، Grok، Kimi، Cursor اور اس کا Grok Bot الاؤنس، GitHub Copilot، Muse، Gemini (Antigravity کے ذریعے)، اور Devin اپنی حدود کے ساتھ پہلے سے شامل ہیں، Kimchi اپنے پلان، پری پیڈ کریڈٹس، اور خرچ کے بجٹس کے ساتھ، اور Hermes، Mistral Vibe، اور Qwen Code ایک بار جب آپ نے انہیں استعمال کر لیا ہو تو اپنے سیشنز اور ٹوکنز دکھاتے ہیں۔ pi، omp، یا opencode کے ذریعے استعمال کیے جانے والے فراہم کنندگان کے پلانز اور کیز بھی ظاہر ہوتے ہیں: OpenCode Zen اور Go، Z.ai GLM Coding Plan، Ollama Cloud، MiniMax Token Plan، اور Synthetic اپنی حدود کے ساتھ؛ OpenRouter اور DeepSeek اپنے پری پیڈ بیلنسز کے ساتھ؛ Fireworks پچھلے 30 دنوں میں اپنے خرچ کے ساتھ۔ آپ کے اپنے ہارڈ ویئر پر چلائے جانے والے ماڈلز کے ٹوکنز بھی مجموعوں میں شمار ہوتے ہیں؛ خود ماڈلز کا اپنا پینل ہے، جو [مقامی ماڈلز](#local-models) کے تحت بیان کیا گیا ہے۔ ہر ایجنٹ ایک بار شمار ہوتا ہے، اس کے تحت جو اس کا بل دیتا ہے، چاہے آپ اسے کتنے ہی ہارنسز کے ذریعے چلائیں۔

پینل کے لیے بار آئیکن پر بایاں کلک کریں یا `Super + Ctrl + X` دبائیں، اپنے ڈیفالٹ ایجنٹ کو لانچ کرنے کے لیے دایاں کلک کریں، اور ریفریش کرنے کے لیے درمیانی کلک کریں۔ اس کے پیچھے استعمال کے ریکارڈز ہر 15 منٹ بعد `omarchy agent usage update` کے ذریعے دوبارہ بنائے جاتے ہیں، اور پینل ہم آہنگ شدہ فولڈر کے ذریعے آپ کی دیگر مشینوں سے استعمال کو بھی ضم کر سکتا ہے۔ مکمل ترتیبات کے لیے `$OMARCHY_PATH/shell/plugins/agents/` کے تحت README دیکھیں۔

### کئی سبسکرپشنز

اگر آپ ایک سے زیادہ Claude، Codex، یا Grok پلان کی ادائیگی کرتے ہیں — مثلاً ایک ذاتی Max اور ایک کام کا — تو Omarchy ان سب کو سائن ان رکھ سکتا ہے اور ان کے درمیان منتقل ہو سکتا ہے۔ ایجنٹس پینل میں + کے ساتھ سبسکرپشن شامل کریں، جو آپ کو وہیں اس عمل سے گزارتا ہے، یا `omarchy agent account add claude Work` سے (یا `codex`، یا `grok`)۔ وہی + اور کمانڈ Gemini (`gemini`) اور OpenCode (`opencode`) میں سائن ان کرتے ہیں، اور OpenCode میں Fireworks (`fireworks`) یا OpenRouter (`openrouter`) API کی محفوظ کرتے ہیں؛ کمانڈ Copilot (`copilot`)، Cursor (`cursor`)، اور Muse (`muse`) میں بھی سائن ان کرتی ہے۔ وہ ہر ایک اکیلا سائن ان رکھتے ہیں۔ اگر CLI موجود نہ ہو تو یہ اسے انسٹال کر دیتا ہے۔ کسی فراہم کنندہ کے لیے پہلا اکاؤنٹ آپ کے عام براؤزر کے ذریعے سائن ان ہوتا ہے، بالکل وہیں جہاں CLI ہمیشہ دیکھتا ہے۔ اس کے بعد ہر اکاؤنٹ ایک نجی ونڈو کے ذریعے سائن ان ہوتا ہے، تاکہ جس اکاؤنٹ میں آپ کا براؤزر پہلے سے سائن ان ہے وہ غلطی سے نہ منتخب ہو جائے؛ وہاں اس اکاؤنٹ کے طور پر سائن ان کریں جو آپ شامل کر رہے ہیں، اور پہلے سے کھلی ہوئی کوئی بھی نجی ونڈو پہلے بند کر دیں۔ اس کے لیے کبھی CLI سے لاگ آؤٹ نہ کریں: لاگ آؤٹ کرنے سے محفوظ شدہ سائن ان منسوخ ہو جاتا ہے، اور اس اکاؤنٹ کو دوبارہ شامل کرنا پڑے گا۔

اپنی سبسکرپشن لاگ انز کو SSH پر دوسری Omarchy مشین پر کاپی کرنے کے لیے `omarchy agent account copy user@laptop` چلائیں۔ اگر منزل پر کوئی انسٹال شدہ وصول کنندہ نہ ہو تو بھیجنے والا ایک عارضی وصول کنندہ فراہم کرتا ہے، تاکہ پرانی Omarchy مشینیں اپڈیٹ کے بغیر اکاؤنٹس وصول کر سکیں۔ انسٹال شدہ وصول کنندگان کو ترجیح حاصل ہوتی ہے۔ یہ تمام Claude، Codex، اور Grok سبسکرپشنز کاپی کرتا ہے؛ انہیں منتخب کرنے کے لیے فراہم کنندگان کے نام شامل کریں، جیسے `omarchy agent account copy laptop claude`۔ اکاؤنٹ کے نام اور کمانڈ IDs ماخذ سے ملتے ہیں، بشمول وہ اکاؤنٹس جو منزل پر پہلے سے موجود ہیں۔ اگر غیر متعلقہ منزل اکاؤنٹس کے نام ٹکراتے ہیں تو انہیں عددی لاحقہ مل جاتا ہے، اور ترتیبات، اسکلز، پلگ انز، اور گفتگو کی تاریخ ہر مشین پر مقامی رہتی ہے۔

منزل کی موجودہ اسناد برقرار رکھی جاتی ہیں۔ کوئی ماخذ اکاؤنٹ جو وہاں پہلے سے سائن ان ہے اس کا نام اس کی اسناد کو بدلے بغیر ہم آہنگ ہو جاتا ہے؛ دیگر اکاؤنٹس اس کے ساتھ شامل کر دیے جاتے ہیں۔ ملتے جلتے اکاؤنٹس کے لیے محفوظ شدہ اسناد کو تبدیل کرنے کے لیے، منزل پر اس اکاؤنٹ کے سیشنز بند کرنے کے بعد `omarchy agent account copy --replace laptop claude` استعمال کریں۔ تازہ منزل کو ماخذ کا فعال اکاؤنٹ اور سوئچنگ ترجیحات بھی مل جاتی ہیں؛ قائم شدہ منزل اپنی ترجیحات برقرار رکھتی ہے۔

اسناد SSH کے ذریعے سفر کرتی ہیں اور منزل پر نجی فائلوں میں محفوظ ہوتی ہیں، لہٰذا صرف ان مشینوں پر کاپی کریں جن پر آپ کو بھروسا ہے۔ یہ ایک بار کی کاپی ہے، جاری ہم آہنگی نہیں۔ Codex ریفریش ٹوکنز کو دوسری مشین گھما سکتی ہے، جس سے کاپی شدہ لاگ ان کو تجدید کی ضرورت پڑ جاتی ہے؛ کئی مشینوں پر بیک وقت استعمال کے لیے الگ سائن انز سب سے قابل اعتماد انتخاب ہیں۔ دیکھیں [Codex کی اکاؤنٹ تصدیق رہنمائی](https://developers.openai.com/codex/auth/ci-cd-auth)۔

فی فراہم کنندہ ایک اکاؤنٹ فعال ہوتا ہے، اور ہر نیا سیشن اسی کے طور پر شروع ہوتا ہے: `cx`، `cy`، سادہ `claude`، `codex`، یا `grok`، `omarchy agent` کے ذریعے لانچ کی گئی کوئی بھی چیز، اور اسکرپٹس یا ایڈیٹرز جو `PATH` پر CLI تلاش کرتے ہیں۔ `omarchy agent account use work` سے سوئچ کریں (اور `omarchy agent account use main` سے واپس)، یا پینل میں کسی اکاؤنٹ کا نمبر دبا کر پھر `Enter` دبا کر (یا اس کے ستارے پر کلک کر کے)۔ چلتے ہوئے Claude سیشنز بھی سوئچ ہو جاتے ہیں، ان کے اگلے پیغام سے: ہر Claude سیشن `~/.claude` میں چلتا ہے، جس میں ہمیشہ فعال اکاؤنٹ کا سائن ان ہوتا ہے۔ کسی پرانی Omarchy کے ذریعے اکاؤنٹ کے اپنے فولڈر میں شروع کیا گیا Claude سیشن وہ سائن ان اس وقت تک رکھتا ہے جب تک وہ بند نہ ہو جائے، لہٰذا سوئچ ان سیشنز کے نام بتاتا ہے اور ان کے ختم ہونے پر خود مکمل ہو جاتا ہے۔ چلتے ہوئے Codex اور Grok سیشنز اس اکاؤنٹ پر رہتے ہیں جس سے وہ شروع ہوئے تھے۔ گفتگو کی تاریخ، ترتیبات، اسکلز، اور پلگ انز اکاؤنٹس میں مشترکہ ہوتے ہیں، لہٰذا اسی فولڈر میں `claude --continue` نئے اکاؤنٹ پر وہیں سے شروع ہوتا ہے جہاں آپ نے چھوڑا تھا۔

ایک سے زیادہ اکاؤنٹ ہونے پر، پینل ہر اکاؤنٹ کی حدود ساتھ ساتھ دکھاتا ہے، جس میں استعمال میں موجود اکاؤنٹ پر بھرا ہوا ستارہ ہوتا ہے۔ جب فعال اکاؤنٹ کسی حد کے 95% سے گزر جاتا ہے تو Omarchy آپ کو مطلع کرتا ہے، اور اطلاع پر کلک کرنے سے سب سے زیادہ گنجائش والے اکاؤنٹ پر سوئچ ہو جاتا ہے۔ یہ کبھی خود سے سوئچ نہیں کرتا۔ حد کو `omarchy agent account threshold 90` سے تبدیل کریں۔ اگر ہر اکاؤنٹ حد سے اوپر ہو تو آپ کو ایک بار اس کے بارے میں بتایا جائے گا، اس کے ساتھ کہ کون سا اکاؤنٹ سب سے پہلے آزاد ہوگا۔ جب کوئی فعال اکاؤنٹ اپنی حد کے 15 پوائنٹس کے اندر ہو (ڈیفالٹ پر 80%) تو اس کی حدود ہر 15 کے بجائے ہر تین منٹ بعد چیک کی جاتی ہیں۔

`omarchy agent account list` ہر اکاؤنٹ اور اس کی تازہ ترین حدود دکھاتا ہے، `omarchy agent account remove work` ایک کو بھلا دیتا ہے، اور `omarchy agent account rename primary Hey` ایک کا نام تبدیل کرتا ہے (یا پینل میں کسی اکاؤنٹ کے نام پر کلک کریں)۔ یہ کمانڈز آپ کے ڈیفالٹ ایجنٹ کے اکاؤنٹس پر کام کرتی ہیں؛ دوسرے فراہم کنندہ تک پہنچنے کے لیے پہلے اس کا نام لیں، جیسے `omarchy agent account use codex side`۔ `~/.claude` یا `~/.codex` میں جو لاگ ان آپ کے پاس پہلے سے تھا وہ _Main_ اکاؤنٹ ہے۔ Codex کا وہیں رہتا ہے جہاں وہ ہے؛ Claude کا اس وقت اپنے فولڈر میں انتظار کرتا ہے جب کوئی دوسرا اکاؤنٹ فعال ہو۔ تقریباً آٹھ گھنٹے سے زیادہ عرصے تک غیر استعمال شدہ رہ جانے والا اکاؤنٹ _Sign-in required_ دکھا سکتا ہے؛ اس اکاؤنٹ کو پینل میں ہی دوبارہ سائن ان کرنے کے لیے اس پر کلک کریں، یا اس پر سوئچ کر کے ایک سیشن شروع کریں، جو خود ہی سائن ان کو تازہ کر دیتا ہے۔ `claude mcp add` کے ساتھ شامل کیے گئے MCP سرورز ہر Claude اکاؤنٹ تک پہنچتے ہیں، کیونکہ وہ سب `~/.claude` میں چلتے ہیں؛ Codex اور Grok کے لیے، اکاؤنٹ شامل کیے جانے کے وقت آپ کے پاس موجود سرورز اس کے ساتھ آ جاتے ہیں، لیکن بعد والے صرف اس اکاؤنٹ تک پہنچتے ہیں جس میں آپ نے انہیں شامل کیا تھا۔ Claude Desktop اپنا سائن ان رکھتا ہے، اور CLI بائنری کے مطلق راستے کے ساتھ تشکیل شدہ Codex یا Grok ٹولز سوئچ کی پیروی نہیں کرتے۔ واضح `CLAUDE_CONFIG_DIR`، `CODEX_HOME`، یا `GROK_HOME` منتخب شدہ اکاؤنٹ پر فوقیت رکھتا ہے۔

### کریش تشخیص

Omarchy پروسیس کریشز کے لیے systemd-coredump پر نظر رکھتا ہے۔ ایک بار جب آپ نے ڈیفالٹ ایجنٹ منتخب کر لیا ہو تو، آپ کا کوئی بھی پروگرام جو core ڈمپ کرتا ہے وہ "Process crashed" اطلاع لاتا ہے — اس پر کلک کریں، اور کریش آپ کے ڈیفالٹ ایجنٹ کے حوالے کر دیا جاتا ہے Omarchy کی omarchy-diagnose-crash اسکل کے ساتھ، جو ایجنٹ کو core ڈمپ سے حقائق قائم کرنے اور یہ فیصلہ کرنے میں رہنمائی کرتی ہے کہ آیا کریش upstream رپورٹ کرنے کے قابل ہے۔ آپ اسے `coredumpctl list` سے کسی بھی PID کے خلاف ہاتھ سے بھی `omarchy agent crash <pid>` کے ساتھ چلا سکتے ہیں۔

یہ نگرانی بطور ڈیفالٹ آن ہوتی ہے۔ اسے _Trigger > Toggle > Crash Capture Off_ کے تحت بند کر دیں (یا `omarchy toggle crash-capture` کے ساتھ) اور اطلاعات رک جائیں گی؛ `omarchy agent crash <pid>` ہاتھ سے پھر بھی کام کرتا ہے۔

کریشز کو ایک وقت میں ایک پروگرام کے لیے بھی خاموش کیا جا سکتا ہے، جو تشخیص آخر میں آپ کو پیش کرتی ہے۔ `omarchy crash mute hyprland` صرف اس پروگرام کے لیے اطلاعات روک دیتا ہے، `omarchy crash mute hyprland off` انہیں واپس لاتا ہے، اور اکیلا `omarchy crash mute` وہ فہرست دکھاتا ہے جو آپ نے خاموش کی ہے۔ یہ بائنری کا راستہ اس کے نام کی طرح خوشی سے قبول کرتا ہے، لہٰذا `omarchy crash mute /usr/bin/hyprland` بھی وہی کام کرتا ہے۔ جس نام میں جگہ ہو اسے کوٹس میں لکھیں، جیسے `omarchy crash mute 'Some App'`۔ باقی سب کچھ پھر بھی مطلع کرتا ہے، اور خاموش کیا گیا پروگرام پھر بھی کریش ہوتا ہے — یہ یاد دہانی چھپاتا ہے، یہ کچھ ٹھیک نہیں کرتا۔

### ڈیسک ٹاپ ایپس

_Install > AI_ مینیو میں چند گرافیکل AI ایپس بھی ہیں: Amp Desktop، Antigravity Desktop، ChatGPT ڈیسک ٹاپ ایپ، Claude ڈیسک ٹاپ ایپ (Anthropic کا Linux بیٹا، Chat، Cowork، اور Claude Code ٹیبز کے ساتھ)، xAI کے ماڈلز کے ساتھ بات چیت کے لیے Grok Bot، Herdr Desktop، Hermes Desktop، OpenClaw، Perplexity ڈیسک ٹاپ ایپ، اور T3 Code۔ Grok Bot ڈیسک ٹاپ چیٹ ایپ ہے۔ کوڈنگ ایجنٹ `grok` کمانڈ ہے۔

Hermes Desktop وہ ہے جس کے بارے میں جاننا ضروری ہے، کیونکہ کسی مشین پر ایک Hermes ہوتا ہے، اور وہ ایپ کا ہوتا ہے: Hermes ہمیشہ صرف ایپ کے ذریعے انسٹال ہوتا ہے، اور ڈیفالٹ ایجنٹ جو `hermes` کمانڈ چلاتا ہے وہ ایپ کی ہوتی ہے۔ Hermes کو ڈیفالٹ ایجنٹ کے طور پر منتخب کرنا وہی چیز انسٹال کرتا ہے جو _Install > AI_ اندراج کرتا ہے: پیکیج، اور Hermes کے اپنے انسٹالر کے ذریعے سیٹ اپ کردہ `~/.hermes` کے تحت ایک Hermes رن ٹائم، جس میں پہلی بار چند منٹ لگتے ہیں۔ وہ رن ٹائم وہ واحد Hermes ہے جسے ٹرمینل `hermes` کمانڈ، ڈیفالٹ ایجنٹ اور ایپ سب استعمال کرتے ہیں، اور یہ Omarchy ریلیز کا انتظار کرنے کے بجائے `hermes update` سے خود کو اپڈیٹ کرتا ہے۔ اسے انسٹال کرنے پر Hermes کو Omarchy تھیم بطور اسکن بھی مل جاتی ہے جس کا نام `omarchy` ہے، جس کی ہر Hermes سطح آپ کے تھیمز تبدیل کرنے پر پیروی کرتی ہے؛ اگر آپ نہیں چاہتے کہ ایسا ہو تو Hermes کی Appearance ترتیبات کے تحت یا `/skin` کے ساتھ کوئی اور منتخب کریں، اور Omarchy اس انتخاب کو چھوڑ دیتا ہے۔ _Remove > AI_ کے تحت ایپ کو ہٹانے پر پہلے Hermes بند ہو جاتا ہے، گیٹ وے سمیت، وہ رن ٹائم اس کے ساتھ لے جاتا ہے، اور آپ کی چیٹس، یادیں، اور وہ اسکلز جو Hermes نے خود اپنے لیے لکھی تھیں برقرار رکھتا ہے الا یہ کہ آپ اسے دوسری صورت بتائیں: یہ پوچھتا ہے، جس کا ڈیفالٹ نہیں ہے، کہ آیا وہ ڈیٹا اور آپ کی کنکشن ترتیبات بھی جانی چاہئیں۔

OpenClaw کا ڈیسک ٹاپ تجربہ اس کا Control UI ہے، جو اس کے اپنے مقامی گیٹ وے کی پشت پناہی میں ایک ویب ایپ کے طور پر کھلتا ہے۔ OpenClaw `~/.openclaw` میں رہتا ہے اور خود کو اپڈیٹ کرتا ہے: Control UI کا "Update Gateway" بٹن استعمال کریں یا `openclaw update` چلائیں، اور گیٹ وے نئے ورژن پر دوبارہ شروع ہو جاتا ہے۔ Omarchy صرف وہ ریلیز منتخب کرتا ہے جس سے تازہ انسٹال شروع ہوتا ہے۔ OpenClaw آپ کا ڈیفالٹ ایجنٹ بھی ہو سکتا ہے: اسے _Agent > Harness_ کے تحت منتخب کرنے پر `~/.openclaw` میں وہی کاپی سیٹ اپ ہو جاتی ہے، اور ایجنٹ اس کے گیٹ وے سے منسلک OpenClaw کا ٹرمینل UI کھولتا ہے۔ _Remove > AI_ کے تحت OpenClaw کو ہٹانے پر گیٹ وے سروس اور ایپ اس کے ساتھ جاتی ہیں اور پھر پوچھا جاتا ہے کہ آیا `~/.openclaw` بھی جانا چاہیے، کیونکہ اس میں OpenClaw خود اور اس کے ڈاؤن لوڈ کردہ پلگ ان رن ٹائمز کے ساتھ آپ کی چیٹس اور اسناد بھی ہوتی ہیں؛ ڈیفالٹ اسے برقرار رکھتا ہے، اور OpenClaw دوبارہ انسٹال کرنے پر اسے واپس اٹھا لیا جاتا ہے۔

Herdr Desktop [Herdr](https://herdr.dev) ڈیسک ٹاپ ایپ ہے: ٹرمینلز اور کوڈنگ ایجنٹس کے اسپیسز، ٹیبز، اور پینز جو ونڈو بند کرنے پر اس کے کور میں چلتے رہتے ہیں۔ یہ پیکیج کے بجائے Herdr کے اپنے انسٹالر سے آتی ہے، لہٰذا یہ `~/.local/share/herdr-app` میں رہتی ہے، جب آپ کے پاس پہلے سے کوئی نہ ہو تو `~/.local/bin/herdr-core` میں اپنا کور ساتھ لاتی ہے، اور دونوں خود کو اپڈیٹ کرتے ہیں۔ یہ `Super + Ctrl + Return` پر Omarchy کی فراہم کردہ `herdr` کمانڈ کے ساتھ رہتی ہے اسے تبدیل کیے بغیر، اور اس کمانڈ کی براہ راست کیز حاصل کرتی ہے: `Alt + Return` اور `Alt + Shift + Return` پین کو نیچے یا دائیں تقسیم کرتے ہیں، `Alt + Escape` اسے بند کرتا ہے، `Ctrl + Alt + Arrow` پینز کے درمیان منتقل ہوتا ہے، `Alt + 1..9` اور `Alt + Left/Right` ٹیب منتخب کرتے ہیں، اور `Alt + Up/Down` اسپیسز کے درمیان منتقل ہوتے ہیں۔ `Ctrl + 1..9` اسپیس منتخب کرتا ہے اور `Alt + Shift + Up/Down` ایجنٹس میں آگے بڑھتا ہے۔ `Ctrl + Space` پریفکس کیز صرف ٹرمینل تک محدود رہتی ہیں، کیونکہ ایپ کسی تسلسل کے لیے سادہ Ctrl کی کو نہیں پکڑ سکتی۔ Omarchy یہ `~/.config/herdr-app/keys.json` میں لکھتا ہے، اور `omarchy-refresh-herdr-app` انہیں واپس رکھ دیتا ہے۔ اسے انسٹال کرنے پر Herdr کی Omarchy تھیم منتخب ہو جاتی ہے، جو اس کے بعد سے آپ کی Omarchy تھیم کی پیروی کرتی ہے۔ Herdr ہلکے موڈ کے لیے ایک تھیم اور گہرے موڈ کے لیے ایک تھیم رکھتا ہے، لہٰذا گہری اور ہلکی Omarchy تھیم کے درمیان سوئچ کرنے کے بعد، دوسرے موڈ کے لیے Herdr کے تھیم چننے والے میں ایک بار پھر Omarchy منتخب کریں۔

T3 Code پیکیج کے بجائے `~/.local/share/t3code` میں اپنی آفیشل AppImage ریلیز سے چلتا ہے، لہٰذا یہ خود کو اپڈیٹ کرتا ہے۔ اسے انسٹال کرنے پر پوچھا جاتا ہے کہ Stable یا Nightly چینل سے شروع کرنا ہے؛ بعد میں T3 Code کی ترتیبات میں سوئچ کریں۔ آپ کے تھریڈز اور ترتیبات `~/.t3` میں رہتی ہیں، اور _Remove > AI_ کے تحت T3 Code کو ہٹانے پر وہ اس کے ساتھ جاتی ہیں۔

### مقامی ماڈلز

اپنے کوڈنگ ایجنٹس کے لیے اپنی مشین پر ایک اوپن ماڈل چلائیں۔ آپ کے پرامپٹس اور کوڈ مشین پر رہتے ہیں؛ ماڈل کو بھیجی گئی کوئی چیز اس سے باہر نہیں جاتی۔ اس سے شروع کریں:

```bash
omarchy models use best text
```

یہ اس مشین کے لیے بہترین ٹیکسٹ ماڈل سیٹ اپ کرتا ہے، اس قسم کا جو آپ کے ایجنٹس استعمال کرتے ہیں۔ امیج، ویڈیو اور میوزک ماڈلز کا اپنا بہترین ہوتا ہے: `omarchy models use best image`، `video` یا `music`۔ اس مشین کے لیے ہر قسم کا انتخاب دیکھنے کے لیے `omarchy models use best` چلائیں۔

یا اوپر والی بار میں ایجنٹس آئیکن کے ساتھ اس کے چمکتے آئیکن سے مقامی ماڈلز پینل کھولیں، یا Super + Ctrl + Alt + X کے ساتھ، اور + منتخب کریں۔ آئیکن اس وقت ظاہر ہوتا ہے جب کوئی ماڈل اس مشین میں فٹ آتا ہو۔ Podman، جو ماڈلز چلاتا ہے، Omarchy کے ساتھ آتا ہے، اسی طرح NVIDIA مشین پر NVIDIA کا کنٹینر ٹول کٹ بھی، جو انہیں GPU دیتا ہے؛ اگر ان میں سے کوئی غائب ہو تو پہلا سیٹ اپ اسے انسٹال کر دیتا ہے۔ پھر Omarchy اس مشین کے لیے تجویز کردہ ماڈل منتخب کرتا ہے، اسے ڈاؤن لوڈ کرتا ہے، اور شروع کر دیتا ہے۔ دسیوں GB کے ڈاؤن لوڈ کی توقع رکھیں اور یہ کہ ماڈل چلتے وقت مشین کی زیادہ تر میموری استعمال میں ہوگی: Flash Next اپنے مکمل 256K سیاق و سباق کے ساتھ تقریباً 100 GiB استعمال کرتا ہے۔ اگر دوسرے ماڈلز وہ میموری رکھتے ہوں جس کی اسے ضرورت ہے تو یہ بند حالت میں سیٹ اپ ہو جاتا ہے، آپ کے ایک کو روکنے پر شروع ہونے کے لیے تیار۔ ماڈل لاگ آؤٹ پر رک جاتا ہے؛ جب آپ کو کسی اور چیز کے لیے میموری درکار ہو تو اسے خود روک دیں۔

`omarchy models list` اختیارات دکھاتا ہے اور بتاتا ہے کہ کچھ کیوں فٹ نہیں آتے۔ کوئی اور سیٹ اپ کرنے کے لیے `omarchy models use <recipe>` چلائیں۔ آج، 128 GB Strix Halo مشینوں کے لیے `qwen3.8-flash-next-gufo` اور `qwen3.8-27b-gufo` دستیاب ہیں؛ 27B تقریباً 40 GiB لیتا ہے، لہٰذا یہ دوسرے کام کے لیے جگہ چھوڑتا ہے۔ Intel کے Arc B390 والی 64 GB لیپ ٹاپ پر، `qwen3.6-35b-a3b-llamacpp` تقریباً 30 GiB میں چلتا ہے۔ نئی ترکیبیں اور سفارشات پیکیج کے ذریعے `omarchy update` کے ساتھ آتی ہیں۔

آپ جو بھی ماڈل سیٹ اپ کرتے ہیں اسے مقامی ماڈلز پینل میں اپنی لائن ملتی ہے: اسے شروع کرنے کے لیے پلے، اسے روکنے اور اس کی میموری آزاد کرنے کے لیے پاز، اور اس پر اپنے ایجنٹ کو کھولنے کے لیے ٹرمینل بٹن۔ اوپر کے پار، ایک بار دکھاتا ہے کہ مشین کی میموری خود Omarchy (سسٹم اور آپ کی ایپس)، ہر چلتے ہوئے ماڈل، اور جو آزاد ہے کے درمیان کیسے تقسیم ہے۔ رکے ہوئے ماڈل کی طرف اشارہ کریں اور بار دکھاتا ہے کہ آیا یہ فٹ آتا ہے، یا کتنا کم ہے۔ کئی ایک ساتھ چل سکتے ہیں جب وہ میموری میں ایک ساتھ فٹ آتے ہوں؛ اگر کوئی فٹ نہ آئے تو Omarchy بتاتا ہے کہ کس چلتے ہوئے ماڈل کو روکنا ہے۔ انہیں دوبارہ ترتیب دینے کے لیے لائنوں کو ان کے لوگو سے گھسیٹیں، اور ماڈل اور اس کا ڈاؤن لوڈ ہٹانے کے لیے منتخب لائن پر Delete دبائیں۔

آپ جو بھی کوڈنگ ماڈل سیٹ اپ کرتے ہیں اسے ایپ لانچر میں بھی اپنی انٹری ملتی ہے، ماڈل کے نام کے تحت اور اس کے بنانے والے کے لوگو کے ساتھ، اسی طرح جیسے Claude، Codex یا Grok میں سائن ان کرنے پر ایک شامل ہو جاتی ہے۔ یہ اس ماڈل پر آپ کا ایجنٹ کھولتا ہے، اور اگر ماڈل چل نہ رہا ہو تو پہلے اسے شروع کرتا ہے: ٹرمینل اسے لوڈ ہوتا دکھاتا ہے اور تیار ہونے پر ایجنٹ کے حوالے کر دیتا ہے۔ ماڈل ہٹانے سے اس کی انٹری بھی ہٹ جاتی ہے۔

ہر ماڈل کوڈنگ کے لیے نہیں ہوتا۔ امیج، ویڈیو اور میوزک ماڈلز اس کے بجائے Fantasi میں کھلتے ہیں، Omarchy کی ایپ جو اس مشین پر چلتے ہوئے ماڈل کے ساتھ تصاویر، ویڈیو اور موسیقی بنانے کے لیے ہے، وہاں منتخب کی گئی یا مقامی ماڈلز پینل میں ان کی لائن سے۔

کوئی ماڈل بالکل اسی طرح چلتا رہتا ہے جیسے اسے سیٹ اپ کیا گیا تھا، لہٰذا Omarchy اپڈیٹ کبھی آپ کے ایجنٹس کے تحت کسی کو دوبارہ شروع نہیں کرتا۔ جب Omarchy کے پاس آپ کے سیٹ اپ کردہ ماڈل کے لیے نیا رن ٹائم یا نئے ویٹس ہوں تو اس کی لائن ایک اپڈیٹ بٹن دکھاتی ہے: اسے دبائیں اور ماڈل پس منظر میں دوبارہ سیٹ اپ ہو جاتا ہے، صرف وہی ڈاؤن لوڈ کرتا ہے جو تبدیل ہوا ہو، اور نئے ورژن پر دوبارہ شروع ہو جاتا ہے۔ جو ماڈل رکا ہوا تھا وہ رکا رہتا ہے۔ `omarchy models update` ٹرمینل سے ہر ماڈل کے لیے بھی یہی کرتا ہے۔

کمانڈ لائن سے، `omarchy models start <recipe>` اور `omarchy models stop <recipe>` بھی یہی کرتے ہیں، `omarchy models status` ہر ماڈل دکھاتا ہے، اور `omarchy agent --local-model <recipe>` اس ماڈل کو pi میں کھولتا ہے، چاہے آپ کا ڈیفالٹ ایجنٹ کچھ بھی ہو۔ اپنے مقامی ماڈل کو وہ بنانے کے لیے جو ایجنٹ ہاٹ کی، Quake کنسول، اور _کچھ بنائیں_ کھولتے ہیں، `omarchy default agent local` چلائیں یا _Agent > Harness_ کے تحت _مقامی ماڈل_ منتخب کریں۔ pi اپنے ماڈل چننے والے میں آپ کے سیٹ اپ کردہ ہر ماڈل، اور جن مشینوں کے ساتھ آپ نے جوڑا بنایا ہے ان پر موجود ماڈلز کی فہرست بھی دیتا ہے، لہٰذا سادہ `pi` بھی ان تک پہنچتا ہے۔ کوئی بھی OpenAI-مطابق کلائنٹ بھی منسلک ہو سکتا ہے: `status` ہر ماڈل کا پتہ دکھاتا ہے (پہلا `http://127.0.0.1:11435/v1` ہے)، ترکیب کا نام ماڈل ہے، اور کی `~/.config/omarchy/agent-local/key` میں ہے۔

`omarchy models remove <recipe>` ماڈل اور وہ ڈاؤن لوڈز حذف کر دیتا ہے جو کوئی دوسرا ماڈل استعمال نہیں کرتا۔

تھرڈ پارٹی رن ٹائمز پر ان کے ناشر کا لیبل ہوتا ہے۔ Omarchy ہر ماڈل کو بغیر نیٹ ورک رسائی کے چلاتا ہے۔

### مقامی LLMs

Omarchy مقامی LLM ماڈلز چلانے کے دو طریقے تجویز کرتا ہے: LM Studio اور Ollama۔ LM Studio اوپن ویٹ ماڈلز تلاش کرنے، انہیں انسٹال کرنے، اور چلانے کے لیے GUI انٹرفیس فراہم کرتا ہے۔ آسانی سے شروع کرنے کا یہ بہترین طریقہ ہے۔ Ollama اسی طرح کرنے کے لیے CLI پیش کرتا ہے۔ لیکن اگر آپ مقامی ماڈلز میں نئے ہیں تو میں LM Studio سے شروع کروں گا۔ آپ Omarchy Menu میں _Install > AI_ کے تحت دونوں میں سے کوئی بھی انسٹال کر سکتے ہیں۔

### Omarchy اسکلز

ایجنٹ اسکلز AI کو مخصوص ٹولز کو مخصوص طریقے سے استعمال کرنے میں مدد دیتی ہیں، اور Omarchy ان میں سے سات فراہم کرتا ہے۔ omarchy اسکل سسٹم کو اپنی پسند کے مطابق بنانے کا احاطہ کرتی ہے، جیسے آپ کی Hyprland کنفگ کو ٹھیک کرنا یا بار کو ایڈجسٹ کرنا۔ omarchy-make-theme، omarchy-make-plugin، omarchy-make-app، اور omarchy-make-game کچھ نیا بنانے کا احاطہ کرتی ہیں، omarchy-contribute باگ رپورٹ کرنے یا upstream فکس بھیجنے کا احاطہ کرتی ہے، اور omarchy-diagnose-crash کریش کے core ڈمپ پر کام کرتی ہے۔ یہ Claude Code (`~/.claude/skills`)، Codex (`~/.codex/skills`)، Pi (`~/.pi/agent/skills`)، Antigravity (`~/.gemini/config/skills`)، Hermes (`~/.hermes/skills` اور ہر `~/.hermes/profiles/*/skills`)، اور عام `~/.agents/skills` مقام کے لیے اسکل ڈائرکٹریوں میں سم لنک شدہ ہیں، لہٰذا زیادہ تر ہارنسز انہیں خودکار طور پر اٹھا لیتے ہیں۔ اسی نام کا آپ کا اپنا اسکل فولڈر فوقیت رکھتا ہے۔

لیکن آپ کو ان اسکلز کو تجرباتی سمجھنا چاہیے۔ مختلف ماڈلز اسے مختلف اثر کے ساتھ استعمال کریں گے۔ بہتر ہے کہ پہلے پلان موڈ میں چلائیں، تاکہ آپ کو اندازہ ہو کہ ایجنٹ کیا تبدیل کرنا چاہے گا۔ اور پھر تبدیلیوں کو واپس کرنے یا حتیٰ کہ `omarchy reinstall configs` چلانے کے لیے تیار رہیں، اگر ایجنٹ ہر چیز کا گڑبڑ کر دے۔
