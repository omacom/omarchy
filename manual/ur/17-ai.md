### ایجنٹس انسٹال اور اپ ڈیٹ کرنا

Hermes کے سوا، یہ ایجنٹس mise کی lazy تنصیب استعمال کرتے ہیں: پہلی بار لانچ کرنے پر CLI انسٹال ہوتی ہے، اور بعد کے لانچ اسی کو دوبارہ استعمال کرتے ہیں۔ mise انسٹال شدہ ایجنٹ کے لیے نئی ریلیز کی جانچ بھی ہر چار گھنٹے میں زیادہ سے زیادہ ایک بار کرتا ہے، شروع ہونے سے عین پہلے یا shell پرامپٹ پر پس منظر میں۔ اگر وہ اپ ڈیٹ ناکام ہو جائے یا آپ آف لائن ہوں، تو انسٹال شدہ ورژن چلتا ہے۔ `omarchy update` انسٹال شدہ ایجنٹس کو باقی Omarchy کے ساتھ اپ ڈیٹ کرتا ہے، اور `mup` صرف mise کے زیرِ انتظام ٹولز کو اپ ڈیٹ کرتا ہے۔

کسی ایجنٹ کا اپنا updater، جیسے `claude update`، `codex update`، یا کسی ایپ میں موجود اپ ڈیٹ بٹن، mise کے زیرِ انتظام انسٹال کو اپ ڈیٹ نہیں کرتا۔ `codex update` ناکام ہو جاتا ہے، اور `claude update` کامیابی کی اطلاع دیتے ہوئے ایک الگ کاپی انسٹال کر سکتا ہے جسے mise ٹریک نہیں کرتا۔ اگر آپ اس کے بجائے کسی ایجنٹ کا اپنا انسٹالر اور updater استعمال کرنا پسند کریں، تو اسے `disable_tools` میں شامل کریں؛ دیکھیں [Preinstalled CLI tools](18-development-tools.md#preinstalled-cli-tools)۔

تمام تشکیل شدہ lazy ٹولز کو ضرورت پڑنے سے پہلے انسٹال کرنے کے لیے، `mise install --include-lazy` چلائیں۔ اس میں ایجنٹس کے ساتھ ساتھ Omarchy کے دیگر ڈیفالٹ CLI ٹولز بھی شامل ہیں۔ کسی ایک ٹول کو انسٹال کرنے یا اپنی تنصیب استعمال کرنے کے لیے دیکھیں [Preinstalled CLI tools](18-development-tools.md#preinstalled-cli-tools)۔

`grok` کو mise کے فرسٹ پارٹی `grok` پیکیج کے ذریعے انسٹال کیا جاتا ہے، بالکل اسی طرح جیسے `claude` اور `codex` کو۔ `grok` چلائیں، یا اسے _Setup > Defaults > Agent_ کے تحت منتخب کریں۔ x.ai پر موجود `curl | bash` انسٹالر کو چھوڑ دیں۔ وہ راستہ `~/.grok/bin` میں دوسری کاپی رکھ دیتا ہے، اسے `PATH` پر آگے کر دیتا ہے، اور Omarchy کے wrapper کو اوور رائٹ کر دیتا ہے۔

`dsh` اپنا browser UI `127.0.0.1:3080` پر کھولتا ہے، جس میں لانچ ڈائریکٹری اس کی ڈیفالٹ workspace ہوتی ہے۔ اس کا browser UI کوئی ابتدائی پرامپٹ نہیں لیتا، اس لیے `omarchy agent prompt` اسے پرامپٹ کو آپ کے clipboard پر رکھ کر کھولتا ہے تاکہ آپ اسے paste کر سکیں۔ Omarchy اسے DeepSeek کے no-approval permission preset کے ساتھ شروع کرتا ہے۔ جب آپ اس کا آفیشل ماڈل API استعمال کرتے ہیں تو DeepSeek Harness سیشن لاگز DeepSeek کو اپ لوڈ کرتا ہے؛ اسے اس کے browser UI میں _Settings > General > Upload Session Log_ کے تحت بند کریں۔ آپ جو فیڈبیک اسے بھیجتے ہیں وہ بھی سیشن کے ساتھ اپ لوڈ ہوتا ہے، الا یہ کہ آپ اسے `DSH_TELEMETRY_MODE=DISABLED` کے ساتھ شروع کریں۔

### ڈیفالٹ ایجنٹ

اپنا ڈیفالٹ ایجنٹ `omarchy default agent <name>` سے یا Omarchy Menu (`Super + Space`) میں _Setup > Defaults > Agent_ کے تحت منتخب کریں۔ اگر ایجنٹ ابھی انسٹال نہیں ہوا، تو اسے منتخب کرنے سے وہ پہلے انسٹال ہو جائے گا۔ نئی Omarchy ایک بار کی نوٹیفکیشن کے ساتھ آپ کو یہ انتخاب کرنے کی دعوت دے گی۔

Claude کو منتخب کرنے سے Chromium، Chrome، Brave، Brave Origin، اور Edge کے لیے اس کی browser extension ترتیب دینے کی کوشش بھی ہوتی ہے۔ extension کی ترتیب تمام صارفین پر لاگو ہوتی ہے اور آپ سے آپ کا سسٹم پاس ورڈ مانگ سکتی ہے؛ extension کی تنصیب منسوخ کرنے یا ناکام ہونے پر بھی Claude منتخب اور لانچ ہو جاتا ہے۔ اپنا browser دوبارہ شروع کریں، اشارہ ملنے پر extension فعال کریں، اور اسے جوڑنا مکمل کرنے کے لیے Claude میں سائن ان کریں۔ کنکشن جانچنے کے لیے Claude میں `/chrome` چلائیں۔ Firefox اور Zen اس extension کی حمایت نہیں کرتے۔ اگر اس ترتیب کے شامل ہونے سے پہلے ہی Claude آپ کا ڈیفالٹ تھا، تو extension انسٹال کرنے کے لیے اسے دوبارہ منتخب کریں۔

منتخب کرنے کے بعد، `Super + Shift + Ctrl + A` ڈیفالٹ ایجنٹ کو ایک مخصوص ٹرمینل ونڈو میں لانچ کرتا ہے (یا اگر آپ نے ابھی انتخاب نہیں کیا تو picker سامنے لاتا ہے)۔ آپ اسے `omarchy agent prompt "Review this project"` کے ساتھ سیدھا کسی کام میں بھی لانچ کر سکتے ہیں۔ Freebuff اور DeepSeek Harness کوئی ابتدائی پرامپٹ نہیں لیتے، اس لیے وہ اس کے بجائے پرامپٹ کو آپ کے clipboard پر رکھ کر کھلتے ہیں تاکہ آپ اسے paste کر سکیں۔ اس طرح لانچ کیے گئے ایجنٹس اپنے متعلقہ don't-stop-to-ask موڈز میں بغیر نگرانی کے چلتے ہیں، لہٰذا تیار رہیں کہ وہ واقعی کچھ کریں گے! MiniMax Code کے interactive سیشنز کے لیے ایسا کوئی موڈ نہیں ہے، اس لیے وہ معمول کے مطابق اجازتیں مانگتا ہے۔ اور چونکہ ایجنٹس آپ کی home ڈائریکٹری کے لیے trust یاد رکھنے سے انکار کرتے ہیں، اس لیے `$HOME` سے لانچ اس کے بجائے `~/Work` میں شروع ہوتے ہیں۔

ٹرمینل شارٹ کٹس بھی ہیں: `a` ڈیفالٹ ایجنٹ کو موجودہ ٹرمینل میں inline چلاتا ہے، جبکہ `c`، `cx`، اور `cy` OpenCode، Claude Code، اور Codex کو براہِ راست شروع کرتے ہیں (دوبارہ، ان کے auto-approving موڈز میں)۔ تھیم کی تبدیلیاں ایجنٹس کے ساتھ بھی sync ہوتی ہیں: جب آپ Omarchy تھیم بدلتے ہیں تو Claude Code، Pi، OpenCode، اور Hermes (ایک بار جب Omarchy اسے انسٹال کر لے) سب ساتھ ساتھ بدل جاتے ہیں۔

### ایجنٹس پینل

اوپر والی bar میں ایک ایجنٹس آئیکن ہے۔ ایجنٹ ترتیب دینے سے پہلے، اس کا پینل آپ کو Claude، Codex، یا Grok میں سائن ان کرنے کے مراحل سے گزارتا ہے، اور پہلا والا آپ کا ڈیفالٹ ایجنٹ بن جاتا ہے۔ اس کے بعد، پینل ہر سبسکرپشن کو ایک ہی صفحے پر رکھتا ہے: ہر ایجنٹ اور اکاؤنٹ اس کے پلان کے ساتھ، اس کی 5-hour سیشن اور ہفتہ وار حدود میں سے ہر ایک کے لیے ایک میٹر جس میں reset ہونے تک کا وقت دکھایا جاتا ہے (درست فیصد کے لیے hover کریں)، یا باقی ماندہ prepaid بیلنس، ایک سطر کے نیچے جو ان سب میں آپ کے استعمال کی چیزوں کے درمیان گردش کرتی رہتی ہے، جیسے اس ہفتے کے tokens اور آپ کا سب سے زیادہ استعمال شدہ ماڈل۔ _Make something_ کے تحت یہ نئی تھیم، plugin، یا ایپ کے لیے starter پرامپٹس پیش کرتا ہے جو کام آپ کے ڈیفالٹ ایجنٹ کے حوالے کر دیتے ہیں۔ ایپس اسی طرح بنائی جاتی ہیں جیسے Omarchy کی اپنی Hype، Monologue، اور Omacut ہیں، C++ اور Qt Quick میں، omarchy-app ایجنٹ skill کی پیروی کرتے ہوئے، اور انہیں درکار compiler اور Qt کے اجزا انسٹال شدہ آتے ہیں۔ Claude Code، Codex، Grok، Kimi، Cursor اور اس کا Grok Bot الاؤنس، GitHub Copilot، Muse، Antigravity، Kimchi، اور Devin اپنی حدود کے ساتھ ابتدا ہی سے شامل ہیں، اور Hermes، Mistral Vibe، اور Qwen Code ایک بار جب آپ انہیں استعمال کر لیں تو اپنے سیشنز اور tokens دکھاتے ہیں۔ pi، omp، یا opencode کے ذریعے استعمال کیے جانے والے Provider پلانز اور keys بھی ظاہر ہوتے ہیں: OpenCode Zen اور Go، Z.ai GLM Coding Plan، Ollama Cloud، MiniMax Token Plan، اور Synthetic اپنی حدود کے ساتھ؛ Fireworks، OpenRouter، اور DeepSeek اپنے prepaid بیلنسز کے ساتھ؛ اور وہ ماڈلز جو آپ اپنے ہارڈویئر پر Local models کے تحت چلاتے ہیں۔ ہر ایجنٹ کو ایک بار گنا جاتا ہے، اسی کے تحت جو اس کا بل دیتا ہے، چاہے آپ اسے کتنے ہی harnesses کے ذریعے چلائیں۔

پینل کے لیے bar آئیکن پر left-click کریں، اپنے ڈیفالٹ ایجنٹ کو لانچ کرنے کے لیے right-click کریں۔ اس کے پیچھے موجود استعمال کے ریکارڈ ہر 15 منٹ میں `omarchy agent usage-update` کے ذریعے دوبارہ بنائے جاتے ہیں، اور پینل synced فولڈر کے ذریعے آپ کی دوسری مشینوں سے استعمال کو ضم بھی کر سکتا ہے۔ مکمل ترتیبات کے لیے `$OMARCHY_PATH/shell/plugins/agents/` کے تحت README دیکھیں۔

### کئی سبسکرپشنز

اگر آپ ایک سے زیادہ Claude، Codex، یا Grok پلان کی ادائیگی کرتے ہیں — مثلاً ایک ذاتی Max اور ایک کام کا — تو Omarchy ان سب کو سائن ان رکھ سکتا ہے اور ان کے درمیان منتقل ہو سکتا ہے۔ ایجنٹس پینل میں + کے ساتھ سبسکرپشن شامل کریں، جو آپ کو وہیں اس کے مراحل سے گزارتا ہے، یا `omarchy agent account add claude Work` کے ساتھ (یا `codex`، یا `grok`)۔ اگر CLI موجود نہیں تو یہ اسے انسٹال کر دیتا ہے۔ کسی provider کا پہلا اکاؤنٹ آپ کے عام browser کے ذریعے سائن ان ہوتا ہے، بالکل وہیں جہاں CLI ہمیشہ دیکھتا ہے۔ اس کے بعد ہر اکاؤنٹ ایک private ونڈو کے ذریعے سائن ان ہوتا ہے، تاکہ جس اکاؤنٹ میں آپ کا browser پہلے سے سائن ان ہے وہ غلطی سے نہ پکڑا جائے؛ وہاں اس اکاؤنٹ کے طور پر سائن ان کریں جسے آپ شامل کر رہے ہیں، اور پہلے سے کھلی ہوئی کوئی بھی private ونڈو پہلے بند کر دیں۔ اس کے لیے کبھی CLI سے لاگ آؤٹ نہ ہوں: لاگ آؤٹ کرنے سے محفوظ شدہ سائن ان منسوخ ہو جاتا ہے، اور اس اکاؤنٹ کو دوبارہ شامل کرنا پڑے گا۔

اپنی سبسکرپشن لاگ انز کو SSH کے ذریعے کسی دوسری Omarchy مشین پر کاپی کرنے کے لیے، `omarchy agent account copy user@laptop` چلائیں۔ جب منزل پر کوئی انسٹال نہ ہو تو بھیجنے والا ایک عارضی receiver فراہم کرتا ہے، لہٰذا پرانی Omarchy مشینیں بغیر کسی اپ ڈیٹ کے اکاؤنٹس وصول کر سکتی ہیں۔ انسٹال شدہ receivers کو ترجیح حاصل ہوتی ہے۔ یہ تمام Claude، Codex، اور Grok سبسکرپشنز کاپی کرتا ہے؛ انہیں منتخب کرنے کے لیے provider کے نام شامل کریں، جیسے `omarchy agent account copy laptop claude` میں۔ اکاؤنٹ کے نام اور کمانڈ IDs ماخذ سے میل کھاتے ہیں، بشمول وہ اکاؤنٹس جو منزل پر پہلے سے موجود ہیں۔ غیر متعلقہ منزل اکاؤنٹس کو اگر ان کے ناموں میں تصادم ہو تو عددی لاحقہ ملتا ہے، اور ترتیبات، skills، plugins، اور گفتگو کی تاریخ ہر مشین پر مقامی رہتی ہے۔

منزل کی موجودہ اسناد برقرار رکھی جاتی ہیں۔ کوئی ماخذ اکاؤنٹ جو وہاں پہلے سے سائن ان ہے، اس کا نام اس کی اسناد کو بدلے بغیر sync ہو جاتا ہے؛ دوسرے اکاؤنٹس اس کے ساتھ شامل کر دیے جاتے ہیں۔ میل کھاتے اکاؤنٹس کی محفوظ شدہ اسناد بدلنے کے لیے، منزل پر اس اکاؤنٹ کے سیشنز بند کرنے کے بعد `omarchy agent account copy --replace laptop claude` استعمال کریں۔ نئی منزل کو ماخذ کا فعال اکاؤنٹ اور switching ترجیحات بھی ملتی ہیں؛ قائم شدہ منزل اپنی ترجیحات برقرار رکھتی ہے۔

اسناد SSH کے ذریعے سفر کرتی ہیں اور منزل پر private فائلوں میں محفوظ ہوتی ہیں، لہٰذا صرف ان مشینوں پر کاپی کریں جن پر آپ کو اعتماد ہے۔ یہ ایک بار کی کاپی ہے، جاری synchronization نہیں۔ Codex refresh tokens کو کوئی دوسری مشین rotate کر سکتی ہے، جس سے کاپی شدہ لاگ ان کو تجدید کی ضرورت پڑ جاتی ہے؛ کئی مشینوں پر بیک وقت استعمال کے لیے الگ الگ سائن ان سب سے قابلِ اعتماد انتخاب رہتے ہیں۔ دیکھیں [Codex's account authentication guidance](https://developers.openai.com/codex/auth/ci-cd-auth)۔

ہر provider کا ایک اکاؤنٹ فعال ہوتا ہے، اور ہر نیا سیشن اسی کے طور پر شروع ہوتا ہے: `cx`، `cy`، سادہ `claude`، `codex`، یا `grok`، `omarchy agent` کے ذریعے لانچ کی گئی کوئی بھی چیز، اور scripts یا editors جو CLI کو `PATH` پر پاتے ہیں۔ `omarchy agent account use work` سے switch کریں (اور `omarchy agent account use main` سے واپس)، یا پینل میں کسی اکاؤنٹ کا نمبر دبا کر پھر `Enter` دبا کر (یا اس کے Use بٹن پر کلک کر کے)۔ جو سیشنز پہلے سے چل رہے ہیں وہ اسی اکاؤنٹ پر رہتے ہیں جس سے وہ شروع ہوئے تھے۔ گفتگو کی تاریخ، ترتیبات، skills، اور plugins اکاؤنٹس کے درمیان مشترک ہیں، لہٰذا اسی فولڈر میں `claude --continue` نئے اکاؤنٹ پر وہیں سے آگے بڑھتا ہے جہاں آپ نے چھوڑا تھا۔

ایک سے زیادہ اکاؤنٹ ہونے پر، پینل ہر اکاؤنٹ کی حدود ساتھ ساتھ دکھاتا ہے، جس میں فعال اکاؤنٹ نمایاں ہوتا ہے۔ بطورِ ڈیفالٹ Omarchy آپ کو مطلع کرتا ہے جب فعال اکاؤنٹ کسی حد کے 95% سے آگے نکل جائے، اور نوٹیفکیشن پر کلک کرنے سے سب سے زیادہ گنجائش والے اکاؤنٹ پر switch ہو جاتا ہے۔ پینل میں کسی اکاؤنٹ کی سطر پر hover کریں اور Use کے ساتھ ظاہر ہونے والے Autoswitch پر کلک کریں (یا `m` دبائیں)، یا `omarchy agent account mode auto` چلائیں، تاکہ یہ اس کے بجائے خود بخود switch ہو جائے؛ جب یہ فعال ہو، تو Autoswitch Use کی جگہ لے لیتا ہے، اور اسے دوبارہ کلک کرنے سے مطلع کرنے پر واپس آ جاتا ہے۔ حد بدلنے کے لیے کوئی نمبر شامل کریں، جیسے `omarchy agent account mode auto 90` میں۔ اگر ہر اکاؤنٹ حد سے اوپر ہو، تو آپ کو ایک بار اس کی اطلاع ملے گی، اس کے ساتھ کہ کون سا اکاؤنٹ سب سے پہلے خالی ہوتا ہے۔ جب کوئی فعال اکاؤنٹ اپنی حد سے 15 پوائنٹس کے اندر ہو (ڈیفالٹ پر 80%)، تو اس کی حدود ہر 15 کے بجائے ہر تین منٹ میں جانچی جاتی ہیں۔

`omarchy agent account list` ہر اکاؤنٹ اور اس کی تازہ ترین حدود دکھاتا ہے، `omarchy agent account remove work` ایک کو بھلا دیتا ہے، اور `omarchy agent account rename primary Hey` ایک کا نام بدل دیتا ہے (یا پینل میں کسی اکاؤنٹ کے نام پر کلک کریں)۔ یہ کمانڈز آپ کے ڈیفالٹ ایجنٹ کے اکاؤنٹس پر کام کرتی ہیں؛ دوسرے provider تک پہنچنے کے لیے، پہلے اس کا نام لیں، جیسے `omarchy agent account use codex side` میں۔ جو لاگ ان آپ کے پاس پہلے سے `~/.claude` یا `~/.codex` میں تھا وہ _Main_ اکاؤنٹ ہے اور وہیں رہتا ہے جہاں وہ ہے۔ تقریباً آٹھ گھنٹے سے زیادہ عرصے تک غیر استعمال شدہ اکاؤنٹ _Sign-in required_ دکھا سکتا ہے؛ اس اکاؤنٹ کو پینل میں ہی دوبارہ سائن ان کرنے کے لیے اس پر کلک کریں، یا اس میں کوئی سیشن شروع کریں، جو سائن ان کو خود بخود تازہ کر دیتا ہے۔ جب کوئی اکاؤنٹ شامل کیا گیا تھا اس وقت آپ کے پاس موجود MCP servers اس کے ساتھ آ جاتے ہیں، لیکن جنہیں آپ بعد میں `claude mcp add` سے شامل کرتے ہیں وہ صرف اسی اکاؤنٹ تک پہنچتے ہیں جس میں آپ نے انہیں شامل کیا تھا۔ Claude Desktop اور وہ ٹولز جو CLI binary کے absolute راستے کے ساتھ تشکیل شدہ ہیں، switch کی پیروی نہیں کرتے۔ واضح `CLAUDE_CONFIG_DIR`، `CODEX_HOME`، یا `GROK_HOME` منتخب اکاؤنٹ پر ترجیح لیتا ہے۔

### کریش کی تشخیص

Omarchy عمل کے کریشز کے لیے systemd-coredump پر نظر رکھتا ہے۔ جب کوئی چیز segfault کرتی ہے، تو آپ کو "Process crashed" نوٹیفکیشن ملے گی — اس پر کلک کریں، اور کریش آپ کے ڈیفالٹ ایجنٹ کے حوالے کر دیا جاتا ہے Omarchy کی diagnose-crash skill کے ساتھ، جو ایجنٹ کو core dump سے حقائق قائم کرنے اور یہ فیصلہ کرنے کے مراحل سے گزارتی ہے کہ آیا کریش upstream کو رپورٹ کرنے کے قابل ہے۔ آپ اسے `coredumpctl list` سے کسی بھی PID کے خلاف ہاتھ سے بھی `omarchy agent crash <pid>` کے ساتھ چلا سکتے ہیں۔

یہ نگرانی بطورِ ڈیفالٹ فعال ہے۔ اسے _Trigger > Toggle > Crash Capture_ کے تحت (یا `omarchy toggle crash-capture` کے ساتھ) بند کر دیں تو نوٹیفکیشنز رک جاتی ہیں؛ `omarchy agent crash <pid>` ہاتھ سے پھر بھی کام کرتا ہے۔

کریشز کو ایک وقت میں ایک پروگرام کے حساب سے خاموش بھی کیا جا سکتا ہے، جو تشخیص آپ کو آخر میں پیش کرتی ہے۔ `omarchy crash mute hyprland` صرف اس پروگرام کے لیے نوٹیفکیشنز روکتا ہے، `omarchy crash mute hyprland off` انہیں واپس لاتا ہے، اور `omarchy crash mute` اکیلا وہ فہرست دیتا ہے جو آپ نے خاموش کی ہے۔ یہ binary کا راستہ اس کے نام کی طرح خوشی سے لیتا ہے، لہٰذا `omarchy crash mute /usr/bin/hyprland` بھی وہی کام کرتا ہے۔ جس نام میں space ہو اسے quotes میں لکھیں، جیسے `omarchy crash mute 'Some App'` میں۔ باقی سب کچھ اب بھی مطلع کرتا ہے، اور خاموش کیا گیا پروگرام اب بھی کریش ہوتا ہے — یہ یاد دہانی کو چھپاتا ہے، کچھ ٹھیک نہیں کرتا۔

### Desktop ایپس

_Install > AI_ مینو میں چند گرافیکل AI ایپس بھی ہیں: ChatGPT desktop ایپ، Claude desktop ایپ (Anthropic کا Linux beta، Chat، Cowork، اور Claude Code ٹیبز کے ساتھ)، xAI کے ماڈلز سے چیٹ کے لیے Grok Bot، Herdr Desktop، Hermes Desktop، OpenClaw، Perplexity desktop ایپ، اور T3 Code۔ Grok Bot desktop چیٹ ایپ ہے۔ کوڈنگ ایجنٹ `grok` کمانڈ ہے۔

Hermes Desktop وہ ہے جس کے بارے میں جاننا ضروری ہے، کیونکہ کسی مشین پر ایک Hermes ہوتا ہے، اور وہ ایپ کا ہوتا ہے: Hermes ہمیشہ صرف ایپ کے ذریعے انسٹال ہوتا ہے، اور ڈیفالٹ ایجنٹ جو `hermes` کمانڈ چلاتا ہے وہ ایپ کی ہے۔ Hermes کو ڈیفالٹ ایجنٹ کے طور پر منتخب کرنا وہی چیز انسٹال کرتا ہے جو _Install > AI_ اندراج کرتا ہے: پیکیج، اور Hermes کے اپنے انسٹالر کے ذریعے ترتیب دیا گیا `~/.hermes` کے تحت ایک Hermes runtime، جس میں پہلی بار چند منٹ لگتے ہیں۔ وہ runtime وہی ایک Hermes ہے جسے ٹرمینل `hermes` کمانڈ، ڈیفالٹ ایجنٹ اور ایپ سب استعمال کرتے ہیں، اور یہ Omarchy ریلیز کا انتظار کرنے کے بجائے `hermes update` سے خود کو اپ ڈیٹ کرتا ہے۔ اسے انسٹال کرنے سے Hermes کو Omarchy تھیم `omarchy` نامی skin کے طور پر بھی مل جاتی ہے، جس کی ہر Hermes سطح آپ کے تھیم بدلنے کے ساتھ پیروی کرتی ہے؛ اگر آپ نہیں چاہتے کہ ایسا ہو تو Hermes کی Appearance ترتیبات میں یا `/skin` کے ساتھ کوئی اور منتخب کریں، اور Omarchy اس انتخاب کو چھوڑ دیتا ہے۔ _Remove > AI_ کے تحت ایپ کو ہٹانے سے پہلے Hermes بند ہوتا ہے، gateway سمیت، وہ runtime اس کے ساتھ لے جاتا ہے، اور آپ کی چیٹس، یادیں، اور وہ skills جو Hermes نے خود اپنے لیے لکھی تھیں برقرار رکھتا ہے الا یہ کہ آپ اسے دوسری صورت کہیں: یہ پوچھتا ہے، ڈیفالٹ no کے ساتھ، کہ آیا وہ ڈیٹا اور آپ کی کنکشن ترتیبات بھی جانی چاہئیں۔

OpenClaw کا desktop تجربہ اس کا Control UI ہے، جو اپنے مقامی gateway کی پشت پناہی سے web ایپ کے طور پر کھلتا ہے۔ OpenClaw `~/.openclaw` میں رہتا ہے اور خود کو اپ ڈیٹ کرتا ہے: Control UI کا "Update Gateway" بٹن استعمال کریں یا `openclaw update` چلائیں، اور gateway نئے ورژن پر دوبارہ شروع ہو جاتا ہے۔ Omarchy صرف وہ ریلیز منتخب کرتا ہے جس سے نئی تنصیب شروع ہوتی ہے۔ _Remove > AI_ کے تحت OpenClaw کو ہٹانے سے gateway سروس اور ایپ اس کے ساتھ جاتے ہیں اور پھر پوچھا جاتا ہے کہ آیا `~/.openclaw` کو بھی جانا چاہیے، کیونکہ اس میں آپ کی چیٹس اور اسناد OpenClaw خود اور اس کے ڈاؤن لوڈ کردہ plugin runtimes کے ساتھ موجود ہوتی ہیں؛ ڈیفالٹ اسے برقرار رکھتا ہے، اور OpenClaw کو دوبارہ انسٹال کرنے سے یہ اسے واپس اٹھا لیتا ہے۔

Herdr Desktop [Herdr](https://herdr.dev) desktop ایپ ہے: ٹرمینلز اور کوڈنگ ایجنٹس کے spaces، tabs، اور panes جو ونڈو بند کرنے پر بھی اس کے core میں چلتے رہتے ہیں۔ یہ کسی پیکیج کے بجائے Herdr کے اپنے انسٹالر سے آتا ہے، لہٰذا یہ `~/.local/share/herdr-app` میں رہتا ہے، جب آپ کے پاس پہلے سے کوئی نہ ہو تو `~/.local/bin/herdr-core` میں اپنا core ساتھ لاتا ہے، اور دونوں کو خود اپ ڈیٹ کرتا ہے۔ یہ اس `herdr` کمانڈ کے ساتھ ساتھ بیٹھتا ہے جو Omarchy `Super + Ctrl + Return` پر فراہم کرتا ہے، اس کی جگہ نہیں لیتا، اور اس کمانڈ کی direct keys حاصل کرتا ہے: `Alt + Return` اور `Alt + Shift + Return` کسی pane کو نیچے یا دائیں تقسیم کرتے ہیں، `Alt + Escape` اسے بند کرتا ہے، `Ctrl + Alt + Arrow` panes کے درمیان منتقل ہوتا ہے، `Alt + 1..9` اور `Alt + Left/Right` کوئی tab منتخب کرتے ہیں، اور `Alt + Up/Down` spaces کے درمیان منتقل ہوتے ہیں۔ `Ctrl + 1..9` کوئی space منتخب کرتا ہے اور `Alt + Shift + Up/Down` ایجنٹس میں آگے پیچھے جاتا ہے۔ `Ctrl + Space` prefix keys صرف ٹرمینل تک رہتی ہیں، کیونکہ ایپ کسی تسلسل کے لیے سادہ Ctrl key کو تھام نہیں سکتی۔ Omarchy انہیں `~/.config/herdr-app/keys.json` میں لکھتا ہے، اور `omarchy-refresh-herdr-app` انہیں واپس رکھ دیتا ہے۔ اسے انسٹال کرنے سے Herdr کی Omarchy تھیم منتخب ہوتی ہے، جو اس کے بعد سے آپ کی Omarchy تھیم کی پیروی کرتی ہے۔ Herdr light موڈ کے لیے ایک تھیم اور dark کے لیے ایک رکھتا ہے، لہٰذا dark اور light Omarchy تھیم کے درمیان switch کرنے کے بعد، دوسرے موڈ کے لیے Herdr کے تھیم picker میں ایک بار پھر Omarchy منتخب کریں۔

T3 Code کسی پیکیج کے بجائے `~/.local/share/t3code` میں اپنی آفیشل AppImage ریلیز سے چلتا ہے، لہٰذا یہ خود کو اپ ڈیٹ کرتا ہے۔ اسے انسٹال کرنے پر پوچھا جاتا ہے کہ Stable یا Nightly چینل پر شروع کرنا ہے؛ بعد میں T3 Code کی ترتیبات میں switch کریں۔ آپ کے threads اور ترتیبات `~/.t3` میں رہتے ہیں، اور _Remove > AI_ کے تحت T3 Code کو ہٹانے سے وہ اس کے ساتھ جاتے ہیں۔

### مقامی ماڈلز

اپنے کوڈنگ ایجنٹس کے لیے اپنی مشین پر کوئی کھلا ماڈل چلائیں۔ آپ کے پرامپٹس اور کوڈ مشین پر رہتے ہیں؛ ماڈل کو بھیجی گئی کوئی چیز اسے نہیں چھوڑتی۔ اس سے شروع کریں:

```bash
omarchy agent local use best
```

یا، اوپر والی bar میں ایجنٹس پینل میں، + اور پھر Local AI منتخب کریں، جو اس وقت ظاہر ہوتا ہے جب کوئی ماڈل اس مشین میں فٹ آتا ہو۔ پہلی بار، یہ Podman انسٹال کرتا ہے، جو ماڈلز چلاتا ہے، اور NVIDIA مشین پر NVIDIA کا container toolkit، جو انہیں GPU فراہم کرتا ہے۔ پھر Omarchy اس مشین کے لیے تجویز کردہ ماڈل منتخب کرتا ہے، اسے ڈاؤن لوڈ کرتا ہے، اور اسے شروع کرتا ہے۔ دسیوں GB کے ڈاؤن لوڈ کی توقع رکھیں اور یہ کہ ماڈل چلنے کے دوران مشین کی زیادہ تر میموری استعمال میں ہوگی: Flash Next اپنے مکمل 256K context کے ساتھ تقریباً 100 GiB استعمال کرتا ہے۔ اگر دوسرے ماڈلز وہ میموری لیے ہوئے ہوں جس کی اسے ضرورت ہے، تو یہ بند حالت میں ترتیب دیا جاتا ہے، ایک بار جب آپ کسی ایک کو روکیں تو شروع ہونے کے لیے تیار۔ ماڈل لاگ آؤٹ پر رک جاتا ہے؛ جب آپ کو کسی اور کام کے لیے میموری درکار ہو تو اسے خود روکیں۔

`omarchy agent local list` اختیارات دکھاتا ہے اور بتاتا ہے کہ کچھ کیوں فٹ نہیں آتے۔ کوئی اور ترتیب دینے کے لیے، `omarchy agent local use <recipe>` چلائیں۔ آج، 128 GB Strix Halo مشینوں کے لیے `qwen3.8-flash-next-gufo` اور `qwen3.8-27b-gufo` دستیاب ہیں؛ 27B تقریباً 40 GiB لیتا ہے، لہٰذا یہ دوسرے کام کے لیے جگہ چھوڑ دیتا ہے۔ نئی recipes اور تجاویز پیکیج کے ذریعے `omarchy update` کے ساتھ آتی ہیں۔

آپ جو بھی ماڈل ترتیب دیتے ہیں اسے ایجنٹس پینل میں آپ کی سبسکرپشنز کے ساتھ اپنی سطر ملتی ہے: اسے شروع کرنے کے لیے play، اسے روکنے اور اس کی میموری خالی کرنے کے لیے pause، اور اس پر اپنا ایجنٹ کھولنے کے لیے ٹرمینل بٹن۔ کئی ایک ساتھ چل سکتے ہیں جب وہ میموری میں ایک ساتھ فٹ آتے ہوں؛ اگر کوئی فٹ نہ آئے، تو Omarchy بتاتا ہے کہ کون سا چلتا ہوا ماڈل روکنا ہے۔ سطروں کو دوبارہ ترتیب دینے کے لیے انہیں drag کریں، اور منتخب سطر پر Delete دبائیں تاکہ کوئی ماڈل اور اس کا ڈاؤن لوڈ ہٹ جائے۔

کمانڈ لائن سے، `omarchy agent local start <recipe>` اور `omarchy agent local stop <recipe>` بھی یہی کرتے ہیں، `omarchy agent local status` ہر ماڈل دکھاتا ہے، اور `omarchy agent --local` آپ کے ڈیفالٹ ایجنٹ کو آخری شروع کیے گئے ماڈل پر کھولتا ہے (pi اگر آپ کا ڈیفالٹ ایجنٹ مقامی ماڈل استعمال نہیں کر سکتا)۔ کوئی بھی OpenAI-compatible client بھی جڑ سکتا ہے: `status` ہر ماڈل کا پتہ دکھاتا ہے (پہلا `http://127.0.0.1:11435/v1` ہے)، recipe کا نام ہی ماڈل ہے، اور key `~/.config/omarchy/agent-local/key` میں ہے۔

`omarchy agent local remove <recipe>` کسی ماڈل اور وہ ڈاؤن لوڈز حذف کر دیتا ہے جنہیں کوئی دوسرا ماڈل استعمال نہیں کرتا۔

فریقِ ثالث کے runtimes پر ان کے publisher کا لیبل لگا ہوتا ہے۔ Omarchy ہر ماڈل کو بغیر کسی نیٹ ورک رسائی کے چلاتا ہے۔

### مقامی LLMs

Omarchy مقامی LLM ماڈلز چلانے کے دو طریقے تجویز کرتا ہے: LM Studio اور Ollama۔ LM Studio کھلے وزن والے ماڈلز تلاش کرنے، انہیں انسٹال کرنے، اور انہیں چلانے کے لیے GUI انٹرفیس فراہم کرتا ہے۔ یہ آسانی سے شروع کرنے کا بہترین طریقہ ہے۔ Ollama اسی طرح کرنے کے لیے CLI پیش کرتا ہے۔ لیکن اگر آپ مقامی ماڈلز میں نئے ہیں، تو میں LM Studio سے شروع کروں گا۔ آپ Omarchy Menu میں _Install > AI_ کے تحت دونوں میں سے کوئی بھی انسٹال کر سکتے ہیں۔

### Omarchy Skill

ایجنٹ skills AI کو مخصوص ٹولز کو مخصوص طریقے سے استعمال کرنے میں مدد دیتی ہیں، اور Omarchy سسٹم کو اپنی مرضی کے مطابق بنانے کے لیے ایک ڈیفالٹ skill کے ساتھ آتا ہے۔ جیسے اپنی Hyprland config میں تبدیلی کرنا، bar کو ایڈجسٹ کرنا، یا یہاں تک کہ شروع سے نئی تھیم بنانا۔ یہ Claude Code (`~/.claude/skills`)، Codex (`~/.codex/skills`)، Pi (`~/.pi/agent/skills`)، Antigravity (`~/.gemini/config/skills`)، Hermes (`~/.hermes/skills` اور ہر `~/.hermes/profiles/*/skills`)، اور عام `~/.agents/skills` مقام کے لیے skill ڈائریکٹریوں میں symlinked ہے، لہٰذا زیادہ تر harnesses اسے خود بخود اٹھا لیتے ہیں۔

لیکن آپ کو اس skill کو تجرباتی سمجھنا چاہیے۔ مختلف ماڈلز اسے مختلف اثر کے ساتھ استعمال کریں گے۔ بہتر ہے کہ پہلے plan موڈ میں چلائیں، تاکہ آپ کو اندازہ ہو کہ ایجنٹ کیا بدلنا چاہے گا۔ اور پھر تبدیلیوں کو rollback کرنے یا یہاں تک کہ `omarchy reinstall configs` چلانے کے لیے تیار رہیں، اگر ایجنٹ ہر چیز کا ستیاناس کر دے۔
