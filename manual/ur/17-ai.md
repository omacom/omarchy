### ایجنٹس انسٹال اور اپ ڈیٹ کرنا

Hermes کے علاوہ، یہ ایجنٹس mise کی lazy تنصیب استعمال کرتے ہیں: پہلا اجرا CLI انسٹال کرتا ہے، اور بعد کے اجراه اسی کو دوبارہ استعمال کرتے ہیں۔ mise انسٹال شدہ ایجنٹ کے لیے نئی release بھی زیادہ سے زیادہ ہر چار گھنٹے میں ایک بار چیک کرتا ہے، اس کے شروع ہونے سے درست پہلے یا پس منظر میں shell prompt پر۔ اگر وہ اپ ڈیٹ ناکام ہو جائے یا آپ آف لائن ہوں، تو انسٹال شدہ ورژن چلتا ہے۔ `omarchy update` Omarchy کے باقی حصے کے ساتھ انسٹال شدہ ایجنٹس کو اپ ڈیٹ کرتا ہے، اور `mup` صرف mise کے زیر انتظام ٹولز کو اپ ڈیٹ کرتا ہے۔

ایک ایجنٹ کا اپنا اپڈیٹر، جیسے `claude update`، `codex update`، یا کسی ایپ میں اپ ڈیٹ کا بٹن، mise کے زیر انتظام تنصیب کو اپ ڈیٹ نہیں کرتا۔ `codex update` ناکام ہو جاتا ہے، اور `claude update` کامیابی کی اطلاع دیتے ہوئے ایک الگ کاپی انسٹال کر سکتا ہے جسے mise ٹریک نہیں کرتا۔ اگر آپ اس کے بجائے کسی ایجنٹ کا اپنا انسٹالر اور اپڈیٹر استعمال کرنا چاہتے ہیں، تو اسے `disable_tools` میں شامل کریں؛ دیکھیں [پہلے سے انسٹال شدہ CLI ٹولز](18-development-tools.md#preinstalled-cli-tools)۔

تمام ترتیب شدہ lazy ٹولز کو ضرورت پڑنے سے پہلے انسٹال کرنے کے لیے، `mise install --include-lazy` چلائیں۔ اس میں ایجنٹس کے ساتھ ساتھ Omarchy کے دوسرے ڈیفالٹ CLI ٹولز بھی شامل ہیں۔ ایک اکیلا ٹول انسٹال کرنے یا اپنی تنصیب استعمال کرنے کے لیے دیکھیں [پہلے سے انسٹال شدہ CLI ٹولز](18-development-tools.md#preinstalled-cli-tools)۔

`grok` mise کے فرسٹ پارٹی `grok` پیکیج کے ذریعے انسٹال ہوتا ہے، اسی طرح جیسے `claude` اور `codex`۔ `grok` چلائیں، یا اسے _Setup > Defaults > Agent_ کے تحت منتخب کریں۔ x.ai پر موجود `curl | bash` انسٹالر کو چھوڑ دیں۔ وہ راستہ `~/.grok/bin` میں ایک دوسری کاپی رکھتا ہے، اسے `PATH` پر پہلے لگاتا ہے، اور Omarchy کے wrapper کو اوور رائٹ کر دیتا ہے۔

`dsh` اپنا browser UI `127.0.0.1:3080` پر کھولتا ہے، اور اجرا کرنے والی ڈائرکٹری اس کا ڈیفالٹ workspace ہوتی ہے۔ اس کا browser UI کوئی ابتدائی prompt نہیں لیتا، اس لیے `omarchy agent prompt` اسے آپ کے clipboard پر موجود prompt کے ساتھ کھولتا ہے تاکہ آپ اسے paste کریں۔ Omarchy اسے DeepSeek کے بغیر منظوری کی اجازت والے preset کے ساتھ شروع کرتا ہے۔ DeepSeek Harness جب آپ اس کی آفیشل ماڈل API استعمال کرتے ہیں تو session logs DeepSeek کو اپ لوڈ کرتا ہے؛ اسے اس کے browser UI میں _Settings > General > Upload Session Log_ کے تحت بند کریں۔ آپ جو فیڈبیک اسے بھیجتے ہیں وہ بھی session کے ساتھ اپ لوڈ ہوتا ہے، جب تک کہ آپ اسے `DSH_TELEMETRY_MODE=DISABLED` کے ساتھ شروع نہ کریں۔

### ڈیفالٹ ایجنٹ

اپنا ڈیفالٹ ایجنٹ `omarchy default agent <name>` کے ساتھ یا Omarchy Menu (`Super + Space`) میں _Setup > Defaults > Agent_ کے تحت منتخب کریں۔ اگر ایجنٹ ابھی انسٹال نہیں ہوا ہے، تو اسے منتخب کرنا اسے پہلے انسٹال کرتا ہے۔ ایک بالکل نیا Omarchy آپ کو ایک بار کی اطلاع کے ساتھ یہ انتخاب کرنے کی دعوت دے گا۔

Claude منتخب کرنا Chromium، Chrome، Brave، Brave Origin، اور Edge کے لیے اس کی browser extension ترتیب دینے کی کوشش بھی کرتا ہے۔ extension کی ترتیب تمام صارفین پر لاگو ہوتی ہے اور آپ سے آپ کا سسٹم پاس ورڈ مانگ سکتی ہے؛ extension کی تنصیب منسوخ کرنا یا اس کا ناکام ہونا تب بھی Claude کو منتخب کر کے اجرا کر دیتا ہے۔ اپنا browser دوبارہ شروع کریں، کہا جائے تو extension فعال کریں، اور اسے جوڑنے کا عمل مکمل کرنے کے لیے Claude میں سائن ان کریں۔ کنکشن چیک کرنے کے لیے Claude میں `/chrome` چلائیں۔ Firefox اور Zen اس extension کی حمایت نہیں کرتے۔ اگر اس ترتیب کے شامل ہونے سے پہلے Claude پہلے ہی آپ کا ڈیفالٹ تھا، تو extension انسٹال کرنے کے لیے اسے دوبارہ منتخب کریں۔

جب آپ انتخاب کر لیں، تو `Super + Shift + Ctrl + A` ڈیفالٹ ایجنٹ کو ایک مخصوص terminal window میں اجرا کرتا ہے (یا اگر آپ نے ابھی انتخاب نہیں کیا ہے تو picker لے آتا ہے)۔ آپ اسے `omarchy agent prompt "Review this project"` کے ساتھ سیدھا کسی کام میں بھی لگا سکتے ہیں۔ Freebuff اور DeepSeek Harness کوئی ابتدائی prompt نہیں لیتے، اس لیے اس کے بجائے وہ آپ کے clipboard پر موجود prompt کے ساتھ کھلتے ہیں تاکہ آپ اسے paste کریں۔ اس طرح اجرا کیے جانے والے ایجنٹس اپنے اپنے رک کر نہ پوچھنے والے طریقوں میں بلا نگرانی چلتے ہیں، اس لیے تیار رہیں کہ وہ واقعی کچھ کریں گے! MiniMax Code کے اپنے انٹرایکٹو sessions کے لیے ایسا کوئی طریقہ نہیں ہے، اس لیے وہ معمول کے مطابق اجازتیں مانگتا ہے۔ اور چونکہ ایجنٹس آپ کی home directory کے لیے trust یاد رکھنے سے انکار کرتے ہیں، اس لیے `$HOME` سے کیے جانے والے اجرا اس کے بجائے `~/Work` میں شروع ہوتے ہیں۔

terminal کے shortcuts بھی ہیں: `a` ڈیفالٹ ایجنٹ کو موجودہ terminal میں inline چلاتا ہے، جبکہ `c`، `cx`، اور `cy` OpenCode، Claude Code، اور Codex کو براہ راست شروع کرتے ہیں (ایک بار پھر ان کے خودکار منظوری والے طریقوں میں)۔ Theme کی تبدیلیاں ایجنٹس کے ساتھ بھی sync ہوتی ہیں: جب آپ Omarchy کی theme بدلتے ہیں تو Claude Code، Pi، OpenCode، اور Hermes (جب Omarchy اسے انسٹال کر چکا ہو) سب اس کے ساتھ ساتھ بدلتے ہیں۔

### ایجنٹس پینل

اوپر والی bar میں ایجنٹس کا آئیکن ہے۔ کسی ایجنٹ کو ترتیب دینے سے پہلے، اس کا پینل آپ کو Claude، Codex، یا Grok میں سائن ان کرنے کے عمل سے گزارتا ہے، اور ان میں سے پہلا آپ کا ڈیفالٹ ایجنٹ بن جاتا ہے۔ اس کے بعد، پینل ہر سبسکرپشن کو ایک صفحے پر رکھتا ہے: ہر ایجنٹ اور اکاؤنٹ اپنے plan کے ساتھ، اس کی 5 گھنٹے کے session اور ہفتہ وار حدود میں سے ہر ایک کے لیے ایک meter اس وقت کے ساتھ جب تک وہ reset نہ ہو (درست فیصد کے لیے hover کریں)، یا باقی ماندہ prepaid بیلنس، اس لائن کے تحت جو ان سب میں آپ کے استعمال کی چیزوں کے درمیان گھومتی رہتی ہے، جیسے اس ہفتے کے tokens اور آپ کا سب سے زیادہ استعمال شدہ ماڈل۔ _Make something_ کے تحت یہ نئی theme، plugin، یا app کے لیے ابتدائی prompts پیش کرتا ہے جو کام آپ کے ڈیفالٹ ایجنٹ کے حوالے کرتے ہیں۔ Apps اسی طرح بنائی جاتی ہیں جیسے Omarchy کی اپنی Hype، Monologue، اور Omacut ہیں، C++ اور Qt Quick میں، omarchy-app agent skill کی پیروی کرتے ہوئے، اور انہیں درکار compiler اور Qt کے اجزاء انسٹال شدہ آتے ہیں۔ Claude Code، Codex، Grok، Kimi، Cursor اور اس کے Grok Bot الاؤنس، GitHub Copilot، Muse، Antigravity، Kimchi، اور Devin اپنی حدود کے ساتھ ابتدا سے ہی شامل ہیں، اور Hermes، Mistral Vibe، اور Qwen Code جب آپ انہیں استعمال کر لیں تو اپنے sessions اور tokens دکھاتے ہیں۔ آپ pi، omp، یا opencode کے ذریعے جو provider plans اور keys استعمال کرتے ہیں وہ بھی نظر آتے ہیں: OpenCode Zen اور Go، Z.ai GLM Coding Plan، Ollama Cloud، MiniMax Token Plan، اور Synthetic اپنی حدود کے ساتھ؛ Fireworks، OpenRouter، اور DeepSeek اپنے prepaid بیلنسز کے ساتھ؛ اور وہ ماڈلز جو آپ اپنے ہارڈویئر پر Local models کے تحت چلاتے ہیں۔ ہر ایجنٹ ایک بار گنا جاتا ہے، اس کے تحت جو اس کا بل ادا کرے، چاہے آپ اسے کتنے ہی harnesses کے ذریعے چلائیں۔

پینل کے لیے bar آئیکن پر بائیں کلک کریں، اپنے ڈیفالٹ ایجنٹ کو اجرا کرنے کے لیے دائیں کلک کریں۔ اس کے پیچھے موجود استعمال کے ریکارڈز ہر 15 منٹ میں `omarchy agent usage-update` کے ذریعے دوبارہ بنائے جاتے ہیں، اور پینل ایک sync شدہ فولڈر کے ذریعے آپ کی دوسری مشینوں سے استعمال کو ضم بھی کر سکتا ہے۔ مکمل ترتیبات کے لیے `$OMARCHY_PATH/shell/plugins/agents/` کے تحت README دیکھیں۔

### متعدد سبسکرپشنز

اگر آپ ایک سے زیادہ Claude، Codex، یا Grok plan کی ادائیگی کرتے ہیں — مثلاً ایک ذاتی Max اور ایک کام کا — تو Omarchy ان سب کو سائن ان رکھ سکتا ہے اور ان کے درمیان آنا جانا کر سکتا ہے۔ ایجنٹس پینل میں + کے ساتھ ایک سبسکرپشن شامل کریں، جو آپ کو وہیںیں عمل سے گزارتا ہے، یا `omarchy agent account add claude Work` کے ساتھ (یا `codex`، یا `grok`)۔ اگر CLI موجود نہ ہو تو یہ اسے انسٹال کرتا ہے۔ کسی provider کے لیے پہلا اکاؤنٹ آپ کے عام browser کے ذریعے سائن ان ہوتا ہے، بالکل وہیں جہاں CLI ہمیشہ دیکھتا ہے۔ اس کے بعد ہر ایک private window کے ذریعے سائن ان ہوتا ہے، تاکہ جس اکاؤنٹ میں آپ کا browser پہلے ہی سائن ان ہے وہ غلطی سے نہ منتخب ہو جائے؛ وہاں اس اکاؤنٹ کے طور پر سائن ان کریں جو آپ شامل کر رہے ہیں، اور پہلے کوئی private window جو آپ کے پاس پہلے سے کھلی ہو اسے بند کر دیں۔ ایسا کرنے کے لیے CLI سے کبھی لاگ آؤٹ نہ کریں: لاگ آؤٹ کرنے سے محفوظ شدہ سائن ان منسوخ ہو جاتا ہے، اور اس اکاؤنٹ کو دوبارہ شامل کرنا پڑے گا۔

اپنے سبسکرپشن لاگ انز کو SSH کے ذریعے کسی دوسری Omarchy مشین پر کاپی کرنے کے لیے، `omarchy agent account copy user@laptop` چلائیں۔ جب منزل پر کوئی انسٹال نہ ہو تو بھیجنے والا ایک عارضی receiver فراہم کرتا ہے، اس لیے پرانی Omarchy مشینیں بھی اپ ڈیٹ کے بغیر اکاؤنٹس وصول کر سکتی ہیں۔ انسٹال شدہ receivers کو ترجیح حاصل ہوتی ہے۔ یہ تمام Claude، Codex، اور Grok سبسکرپشنز کاپی کرتا ہے؛ انہیں منتخب کرنے کے لیے provider کے نام شامل کریں، جیسے `omarchy agent account copy laptop claude` میں۔ اکاؤنٹ کے نام اور command IDs ماخذ سے میل کھاتے ہیں، بشمول وہ اکاؤنٹس جو منزل پر پہلے سے موجود ہوں۔ غیر متعلقہ منزل کے اکاؤنٹس کو اگر ان کے نام ٹکراتے ہیں تو عددی suffix ملتا ہے، اور ترتیبات، skills، plugins، اور گفتگو کی تاریخ ہر مشین تک مقامی رہتی ہے۔

منزل کی موجودہ credentials برقرار رکھی جاتی ہیں۔ ایک ماخذ اکاؤنٹ جو وہاں پہلے ہی سائن ان ہو اس کا نام اس کی credentials بدلے بغیر sync کر دیا جاتا ہے؛ دوسرے اکاؤنٹس اس کے ساتھ شامل کر دیے جاتے ہیں۔ میل کھاتے اکاؤنٹس کے لیے محفوظ شدہ credentials بدلنے کے لیے، منزل پر اس اکاؤنٹ کے sessions چھوڑنے کے بعد `omarchy agent account copy --replace laptop claude` استعمال کریں۔ ایک بالکل نئی منزل کو ماخذ کا فعال اکاؤنٹ اور switching ترجیحات بھی ملتی ہیں؛ ایک قائم شدہ منزل اپنی ترجیحات برقرار رکھتی ہے۔

Credentials SSH کے ذریعے سفر کرتی ہیں اور منزل پر نجی فائلوں میں محفوظ ہوتی ہیں، اس لیے صرف ان مشینوں پر کاپی کریں جن پر آپ کو بھروسا ہو۔ یہ ایک بار کی کاپی ہے، جاری ہم آہنگی نہیں۔ Codex کے refresh tokens کو کسی دوسری مشین کے ذریعے تبدیل کیا جا سکتا ہے، جس سے کاپی شدہ لاگ ان کو تجدید کی ضرورت پڑ جاتی ہے؛ متعدد مشینوں پر بیک وقت استعمال کے لیے الگ الگ سائن ان سب سے قابل اعتماد انتخاب رہتے ہیں۔ دیکھیں [Codex کی اکاؤنٹ تصدیق سے متعلق رہنمائی](https://developers.openai.com/codex/auth/ci-cd-auth)۔

فی provider ایک اکاؤنٹ فعال ہوتا ہے، اور ہر نیا session اسی کے طور پر شروع ہوتا ہے: `cx`، `cy`، ایک سادہ `claude`، `codex`، یا `grok`، `omarchy agent` کے ذریعے اجرا کی گئی کوئی بھی چیز، اور وہ scripts یا ایڈیٹرز جو CLI کو `PATH` پر پاتے ہیں۔ `omarchy agent account use work` کے ساتھ بدلیں (اور `omarchy agent account use main` کے ساتھ واپس)، یا پینل میں کسی اکاؤنٹ کا نمبر دبا کر پھر `Enter` دبا کر (یا اس کے Use بٹن پر کلک کر کے)۔ پہلے سے چل رہے Sessions اسی اکاؤنٹ پر رہتے ہیں جس سے وہ شروع ہوئے تھے۔ گفتگو کی تاریخ، ترتیبات، skills، اور plugins اکاؤنٹس میں مشترکہ ہیں، اس لیے اسی فولڈر میں `claude --continue` نئے اکاؤنٹ پر وہیں سے شروع ہوتا ہے جہاں آپ نے چھوڑا تھا۔

ایک سے زیادہ اکاؤنٹ کے ساتھ، پینل ہر اکاؤنٹ کی حدود ساتھ ساتھ دکھاتا ہے، فعال اکاؤنٹ کو نشان زد کر کے۔ بطور ڈیفالٹ Omarchy آپ کو مطلع کرتا ہے جب فعال اکاؤنٹ کسی حد کے 95% سے آگے بڑھ جائے، اور اطلاع پر کلک کرنا سب سے زیادہ گنجائش والے اکاؤنٹ پر لے جاتا ہے۔ پینل میں کسی اکاؤنٹ کی لائن پر hover کریں اور Use کے ساتھ نظر آنے والے Autoswitch پر کلک کریں (یا `m` دبائیں)، یا `omarchy agent account mode auto` چلائیں، تاکہ یہ اس کے بجائے خود ہی بدل جائے؛ جب یہ آن ہو، Autoswitch Use کی جگہ لے لیتا ہے، اور اس پر دوبارہ کلک کرنا اطلاع دینے پر واپس لے جاتا ہے۔ حد بدلنے کے لیے ایک نمبر شامل کریں، جیسے `omarchy agent account mode auto 90` میں۔ اگر ہر اکاؤنٹ حد سے اوپر ہو، تو آپ کو اس کے بارے میں ایک بار سنا دیا جائے گا، اس کے ساتھ کہ کون سا اکاؤنٹ سب سے پہلے آزاد ہوتا ہے۔ جب تک ایک فعال اکاؤنٹ اپنی حد کے 15 پوائنٹس کے اندر ہو (ڈیفالٹ پر 80%)، اس کی حدود ہر 15 منٹ کے بجائے ہر تین منٹ میں چیک کی جاتی ہیں۔

`omarchy agent account list` ہر اکاؤنٹ اور اس کی تازہ ترین حدود دکھاتا ہے، `omarchy agent account remove work` ایک کو بھلا دیتا ہے، اور `omarchy agent account rename primary Hey` ایک کا نام بدلتا ہے (یا پینل میں کسی اکاؤنٹ کے نام پر کلک کریں)۔ یہ کمانڈز آپ کے ڈیفالٹ ایجنٹ کے اکاؤنٹس پر کام کرتی ہیں؛ دوسرے provider تک پہنچنے کے لیے، پہلے اس کا نام دیں، جیسے `omarchy agent account use codex side` میں۔ وہ لاگ ان جو آپ کے پاس پہلے سے `~/.claude` یا `~/.codex` میں تھا وہ _Main_ اکاؤنٹ ہے اور جہاں ہے وہیں رہتا ہے۔ ایک اکاؤنٹ جو تقریباً آٹھ گھنٹے سے زیادہ غیر استعمال شدہ رہ گیا ہو _Sign-in required_ دکھا سکتا ہے؛ پینل میں درست وہیں اس اکاؤنٹ میں دوبارہ سائن ان کرنے کے لیے اس پر کلک کریں، یا اس میں ایک session شروع کریں، جو سائن ان کو خود ہی تازہ کر دیتا ہے۔ جو MCP servers آپ کے پاس اس وقت تھے جب کوئی اکاؤنٹ شامل کیا گیا تھا وہ اس کے ساتھ آ جاتے ہیں، لیکن جو آپ بعد میں `claude mcp add` کے ساتھ شامل کرتے ہیں وہ صرف اسی اکاؤنٹ تک پہنچتے ہیں جس میں آپ نے انہیں شامل کیا تھا۔ Claude Desktop اور وہ ٹولز جو CLI binary کے مکمل راستے کے ساتھ ترتیب دیے گئے ہوں، تبدیلی کی پیروی نہیں کرتے۔ ایک واضح `CLAUDE_CONFIG_DIR`، `CODEX_HOME`، یا `GROK_HOME` منتخب شدہ اکاؤنٹ پر ترجیح رکھتا ہے۔

### کریش کی تشخیص

Omarchy عمل کے کریشز کے لیے systemd-coredump پر نظر رکھتا ہے۔ جب کوئی چیز segfault کرتی ہے، تو آپ کو ایک "Process crashed" اطلاع ملے گی — اس پر کلک کریں، اور کریش آپ کے ڈیفالٹ ایجنٹ کے حوالے کر دیا جاتا ہے Omarchy کی diagnose-crash skill کے ساتھ، جو ایجنٹ کو core dump سے حقائق قائم کرنے اور یہ فیصلہ کرنے کے عمل سے گزارتی ہے کہ آیا کریش upstream رپورٹ کرنے کے قابل ہے۔ آپ اسے `coredumpctl list` سے کسی بھی PID کے خلاف `omarchy agent crash <pid>` کے ساتھ ہاتھ سے بھی چلا سکتے ہیں۔

یہ نگرانی بطور ڈیفالٹ آن ہے۔ اسے _Trigger > Toggle > Crash Capture_ کے تحت (یا `omarchy toggle crash-capture` کے ساتھ) بند کریں اور اطلاعات رک جاتی ہیں؛ `omarchy agent crash <pid>` اب بھی ہاتھ سے کام کرتا ہے۔

کریشز کو ایک وقت میں ایک پروگرام کے حساب سے خاموش بھی کیا جا سکتا ہے، یہی وہ چیز ہے جو تشخیص آخر میں آپ کو پیش کرتی ہے۔ `omarchy crash mute hyprland` صرف اس پروگرام کے لیے اطلاعات روکتا ہے، `omarchy crash mute hyprland off` انہیں واپس لے آتا ہے، اور `omarchy crash mute` اکیلا وہ فہرست دکھاتا ہے جو آپ نے خاموش کی ہے۔ یہ binary کے راستے کو اس کے نام کی طرح خوشی سے لیتا ہے، اس لیے `omarchy crash mute /usr/bin/hyprland` بھی وہی کام کرتا ہے۔ کسی ایسے نام کو quote کریں جس میں جگہ ہو، جیسے `omarchy crash mute 'Some App'` میں۔ باقی سب کچھ اب بھی مطلع کرتا ہے، اور خاموش کیا گیا پروگرام اب بھی کریش ہوتا ہے — یہ یاد دہانی چھپاتا ہے، یہ کچھ ٹھیک نہیں کرتا۔

### ڈیسک ٹاپ ایپس

_Install > AI_ مینو میں چند گرافیکل AI ایپس بھی ہیں: ChatGPT desktop app، Claude desktop app (Anthropic کا Linux beta، Chat، Cowork، اور Claude Code tabs کے ساتھ)، xAI کے ماڈلز کے ساتھ گفتگو کے لیے Grok Bot، Hermes Desktop، OpenClaw، Perplexity desktop app، اور T3 Code۔ Grok Bot ڈیسک ٹاپ چیٹ ایپ ہے۔ کوڈنگ ایجنٹ `grok` کمانڈ ہے۔

Hermes Desktop وہ ہے جس کے بارے میں جاننا ضروری ہے، کیونکہ ایک مشین کے پاس ایک Hermes ہوتا ہے، اور وہ ایپ کا ہوتا ہے: Hermes ہمیشہ صرف ایپ کے ذریعے انسٹال ہوتا ہے، اور ڈیفالٹ ایجنٹ جو `hermes` کمانڈ چلاتا ہے وہ ایپ کی ہوتی ہے۔ Hermes کو ڈیفالٹ ایجنٹ کے طور پر منتخب کرنا وہی چیز انسٹال کرتا ہے جو _Install > AI_ والا اندراج کرتا ہے: پیکیج، اور `~/.hermes` کے تحت ایک Hermes runtime جو Hermes کے اپنے انسٹالر کے ذریعے ترتیب دیا گیا ہو، جس میں پہلی بار چند منٹ لگتے ہیں۔ وہ runtime وہی ایک Hermes ہے جسے terminal کی `hermes` کمانڈ، ڈیفالٹ ایجنٹ اور ایپ سب استعمال کرتے ہیں، اور یہ Omarchy کی release کا انتظار کرنے کے بجائے `hermes update` کے ساتھ خود کو اپ ڈیٹ کرتا ہے۔ اسے انسٹال کرنا Hermes کو Omarchy theme بطور skin بھی دیتا ہے جس کا نام `omarchy` ہے، جس کی پیروی ہر Hermes سطح کرتی ہے جب آپ themes بدلتے ہیں؛ اگر آپ نہیں چاہتے کہ ایسا ہو تو Hermes کی Appearance ترتیبات کے تحت یا `/skin` کے ساتھ کوئی اور منتخب کریں، اور Omarchy اس انتخاب کو چھوڑ دیتا ہے۔ _Remove > AI_ کے تحت ایپ کو ہٹانا پہلے Hermes کو بند کرتا ہے، gateway سمیت، اس runtime کو اپنے ساتھ لے جاتا ہے، اور آپ کی چیٹس، یادیں، اور وہ skills جو Hermes نے اپنے لیے لکھی تھیں برقرار رکھتا ہے جب تک کہ آپ اسے اس کے برعکس نہ کہیں: یہ پوچھتا ہے، ڈیفالٹ کے طور پر نہیں کے ساتھ، کہ آیا وہ ڈیٹا اور آپ کی کنکشن ترتیبات بھی جانی چاہئیں۔

OpenClaw کا ڈیسک ٹاپ تجربہ اس کا Control UI ہے، جو اپنے مقامی gateway کی پشت پناہی کے ساتھ ایک web app کے طور پر کھلتا ہے۔ OpenClaw `~/.openclaw` میں رہتا ہے اور خود کو اپ ڈیٹ کرتا ہے: Control UI کا "Update Gateway" بٹن استعمال کریں یا `openclaw update` چلائیں، اور gateway نئے ورژن پر دوبارہ شروع ہو جاتا ہے۔ Omarchy صرف اس release کا انتخاب کرتا ہے جس سے ایک نئی تنصیب شروع ہوتی ہے۔ _Remove > AI_ کے تحت OpenClaw کو ہٹانا gateway service اور ایپ کو اپنے ساتھ لے جاتا ہے اور پھر پوچھتا ہے کہ آیا `~/.openclaw` بھی جانا چاہیے، کیونکہ اس میں خود OpenClaw اور اس کے ڈاؤن لوڈ کیے گئے plugin runtimes کے ساتھ آپ کی چیٹس اور credentials موجود ہوتی ہیں؛ ڈیفالٹ اسے برقرار رکھتا ہے، اور OpenClaw کو دوبارہ انسٹال کرنا اسے واپس منتخب کر لیتا ہے۔

T3 Code کسی پیکیج کے بجائے `~/.local/share/t3code` میں اپنی آفیشل AppImage release سے چلتا ہے، اس لیے یہ خود کو اپ ڈیٹ کرتا ہے۔ اسے انسٹال کرنا پوچھتا ہے کہ آیا Stable یا Nightly channel پر شروع کرنا ہے؛ بعد میں T3 Code کی ترتیبات میں بدلیں۔ آپ کے threads اور ترتیبات `~/.t3` میں رہتی ہیں، اور _Remove > AI_ کے تحت T3 Code کو ہٹانا انہیں اپنے ساتھ لے جاتا ہے۔

### لوکل ماڈلز

اپنے کوڈنگ ایجنٹس کے لیے اپنی مشین پر ایک open model چلائیں۔ آپ کے prompts اور کوڈ مشین پر ہی رہتے ہیں؛ ماڈل کو بھیجی گئی کوئی چیز اس سے باہر نہیں جاتی۔ اس کے ساتھ شروع کریں:

```bash
omarchy agent local use best
```

یا، اوپر والی bar میں ایجنٹس پینل میں، + اور پھر Local AI منتخب کریں، جو اس وقت نظر آتا ہے جب کوئی ماڈل اس مشین کے لیے موزوں ہو۔ پہلی بار، یہ Podman انسٹال کرتا ہے، جو ماڈلز چلاتا ہے، اور NVIDIA مشین پر NVIDIA کا container toolkit، جو انہیں GPU دیتا ہے۔ پھر Omarchy اس مشین کے لیے تجویز کردہ ماڈل منتخب کرتا ہے، اسے ڈاؤن لوڈ کرتا ہے، اور اسے شروع کرتا ہے۔ توقع رکھیں کہ دسیوں GB کا ڈاؤن لوڈ ہوگا اور ماڈل چلتے ہوئے مشین کی زیادہ تر میموری استعمال میں ہوگی: Flash Next اپنے مکمل 256K context کے ساتھ تقریباً 100 GiB استعمال کرتا ہے۔ اگر دوسرے ماڈلز اسے درکار میموری رکھے ہوئے ہوں، تو یہ رکا ہوا ترتیب دیا جاتا ہے، ایک کو روکنے پر شروع ہونے کے لیے تیار۔ ماڈل لاگ آؤٹ پر رک جاتا ہے؛ جب آپ کو کسی اور کام کے لیے میموری درکار ہو تو اسے خود روکیں۔

`omarchy agent local list` آپشنز دکھاتا ہے اور بتاتا ہے کہ کچھ کیوں موزوں نہیں ہیں۔ کوئی اور ترتیب دینے کے لیے، `omarchy agent local use <recipe>` چلائیں۔ آج، 128 GB Strix Halo مشینوں کے لیے `qwen3.8-flash-next-halogen` اور `qwen3.8-27b-gufo` دستیاب ہیں۔ نئی recipes اور تجاویز پیکیج کے ذریعے `omarchy update` کے ساتھ آتی ہیں۔

ہر ماڈل جسے آپ ترتیب دیتے ہیں اسے ایجنٹس پینل میں اپنی لائن ملتی ہے، آپ کی سبسکرپشنز کے ساتھ: اسے شروع کرنے کے لیے play، اسے روکنے اور اس کی میموری آزاد کرنے کے لیے pause، اور اس پر اپنے ایجنٹ کو کھولنے کے لیے terminal بٹن۔ کئی ایک ساتھ چل سکتے ہیں جب وہ میموری میں ایک ساتھ آ جائیں؛ اگر کوئی نہ آئے، تو Omarchy بتاتا ہے کہ کون سا چل رہا ماڈل روکنا ہے۔ انہیں دوبارہ ترتیب دینے کے لیے لائنز کو گھسیٹیں، اور منتخب لائن پر Delete دبائیں تاکہ کوئی ماڈل اور اس کا ڈاؤن لوڈ ہٹا دیا جائے۔

command line سے، `omarchy agent local start <recipe>` اور `omarchy agent local stop <recipe>` بھی یہی کرتے ہیں، `omarchy agent local status` ہر ماڈل دکھاتا ہے، اور `omarchy agent --local` آپ کے ڈیفالٹ ایجنٹ کو آخری شروع کیے گئے ماڈل پر کھولتا ہے (pi اگر آپ کا ڈیفالٹ ایجنٹ لوکل ماڈل استعمال نہیں کر سکتا)۔ کوئی بھی OpenAI سے ہم آہنگ client بھی جڑ سکتا ہے: `status` ہر ماڈل کا پتہ دکھاتا ہے (پہلا `http://127.0.0.1:11435/v1` ہے)، recipe کا نام ماڈل ہے، اور key `~/.config/omarchy/agent-local/key` میں ہے۔

`omarchy agent local remove <recipe>` ایک ماڈل اور وہ ڈاؤن لوڈز حذف کرتا ہے جو کوئی دوسرا ماڈل استعمال نہیں کرتا۔

فریق ثالث کے runtimes پر ان کے publisher کا لیبل لگا ہوتا ہے۔ Omarchy ہر ماڈل کو بغیر کسی نیٹ ورک رسائی کے چلاتا ہے۔

### لوکل LLMs

Omarchy لوکل LLM ماڈلز چلانے کے دو طریقے تجویز کرتا ہے: LM Studio اور Ollama۔ LM Studio open-weight ماڈلز تلاش کرنے، انہیں انسٹال کرنے، اور انہیں چلانے کے لیے ایک GUI انٹرفیس فراہم کرتا ہے۔ آسانی سے شروع کرنے کا یہ ایک بہترین طریقہ ہے۔ Ollama اسی طرح کرنے کے لیے ایک CLI پیش کرتا ہے۔ لیکن اگر آپ لوکل ماڈلز میں نئے ہیں، تو میں LM Studio سے شروع کروں گا۔ آپ Omarchy Menu میں _Install > AI_ کے تحت کسی کو بھی انسٹال کر سکتے ہیں۔

### Omarchy Skill

Agent skills AI کو مخصوص ٹولز کو ایک مخصوص طریقے سے استعمال کرنے میں مدد دیتی ہیں، اور Omarchy سسٹم کو اپنی مرضی کے مطابق بنانے کے لیے ایک ڈیفالٹ skill کے ساتھ آتا ہے۔ جیسے اپنی Hyprland config میں رد و بدل کرنا، bar کو ایڈجسٹ کرنا، یا شروع سے ایک نئی theme بنانا بھی۔ یہ Claude Code (`~/.claude/skills`)، Codex (`~/.codex/skills`)، Pi (`~/.pi/agent/skills`)، Antigravity (`~/.gemini/config/skills`)، Hermes (`~/.hermes/skills` اور ہر `~/.hermes/profiles/*/skills`)، اور عام `~/.agents/skills` مقام کے لیے skill ڈائرکٹریوں میں symlink شدہ ہے، اس لیے زیادہ تر harnesses اسے خودکار طور پر اٹھا لیتے ہیں۔

لیکن آپ کو اس skill کو تجرباتی سمجھنا چاہیے۔ مختلف ماڈلز اسے مختلف اثر کے ساتھ استعمال کریں گے۔ بہتر ہے کہ پہلے اسے plan mode میں چلائیں، تاکہ آپ کو اندازہ ہو کہ ایجنٹ کیا بدلنا چاہے گا۔ اور پھر تبدیلیوں کو واپس کرنے یا حتیٰ کہ `omarchy reinstall configs` چلانے کے لیے بھی تیار رہیں، اگر ایجنٹ ہر چیز کا ستیاناس کر دے۔
