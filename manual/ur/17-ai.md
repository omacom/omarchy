### ایجنٹس نصب اور اپ ڈیٹ کرنا

Hermes کے سوا، یہ ایجنٹس mise کی سست تنصیب استعمال کرتے ہیں: پہلی مرتبہ لانچ کرنے پر CLI نصب ہو جاتا ہے، اور بعد کی لانچز اسی کو دوبارہ استعمال کرتی ہیں۔ mise نصب شدہ ایجنٹ کے لیے نئی ریلیز کی جانچ بھی زیادہ سے زیادہ ہر چار گھنٹے میں ایک مرتبہ کرتا ہے، یا تو اس کے شروع ہونے سے عین پہلے یا پس منظر میں shell prompt پر۔ اگر وہ اپ ڈیٹ ناکام ہو جائے یا آپ آف لائن ہوں تو نصب شدہ ورژن چلتا ہے۔ `omarchy update` نصب شدہ ایجنٹس کو باقی Omarchy کے ساتھ اپ ڈیٹ کرتا ہے، اور `mup` صرف mise کے زیر انتظام ٹولز کو اپ ڈیٹ کرتا ہے۔

کسی ایجنٹ کا اپنا اپڈیٹر، جیسے `claude update`، `codex update` یا کسی ایپ میں موجود اپ ڈیٹ بٹن، mise کے زیر انتظام تنصیب کو اپ ڈیٹ نہیں کرتا۔ `codex update` ناکام ہو جاتا ہے، اور `claude update` کامیابی کی اطلاع دیتے ہوئے ایک الگ کاپی نصب کر سکتا ہے جسے mise ٹریک نہیں کرتا۔ اگر آپ اس کے بجائے کسی ایجنٹ کا اپنا انسٹالر اور اپڈیٹر استعمال کرنا چاہیں تو اسے `disable_tools` میں شامل کریں؛ دیکھیں [پہلے سے نصب شدہ CLI ٹولز](18-development-tools.md#preinstalled-cli-tools)۔

تمام ترتیب شدہ سست ٹولز کو ضرورت پڑنے سے پہلے نصب کرنے کے لیے `mise install --include-lazy` چلائیں۔ اس میں ایجنٹس کے ساتھ ساتھ Omarchy کے دیگر ڈیفالٹ CLI ٹولز بھی شامل ہیں۔ کسی ایک ٹول کو نصب کرنے یا اپنی تنصیب استعمال کرنے کے لیے دیکھیں [پہلے سے نصب شدہ CLI ٹولز](18-development-tools.md#preinstalled-cli-tools)۔

`grok` mise کے فرسٹ پارٹی `grok` پیکیج کے ذریعے نصب ہوتا ہے، بالکل اسی طرح جیسے `claude` اور `codex`۔ `grok` چلائیں، یا اسے _Agent > Harness_ کے تحت منتخب کریں۔ x.ai پر موجود `curl | bash` انسٹالر کو چھوڑ دیں۔ وہ راستہ `~/.grok/bin` میں ایک دوسری کاپی رکھ دیتا ہے، اسے `PATH` کے آغاز میں شامل کر دیتا ہے، اور Omarchy کے wrapper کو اوور رائٹ کر دیتا ہے۔

`dsh` اپنا براؤزر UI `127.0.0.1:3080` پر کھولتا ہے، جس میں لانچ ڈائریکٹری اس کی ڈیفالٹ workspace ہوتی ہے۔ اس کا براؤزر UI کوئی ابتدائی prompt نہیں لیتا، چنانچہ `omarchy agent prompt` اسے اس prompt کے ساتھ کھولتا ہے جو آپ کے clipboard پر چسپاں کرنے کے لیے موجود ہوتا ہے۔ Omarchy اسے DeepSeek کے بغیر منظوری والے permission preset کے ساتھ شروع کرتا ہے۔ جب آپ اس کا سرکاری ماڈل API استعمال کرتے ہیں تو DeepSeek Harness سیشن لاگز DeepSeek کو اپ لوڈ کرتا ہے؛ اسے اس کے براؤزر UI میں _Settings > General > Upload Session Log_ کے تحت بند کر دیں۔ جو آراء آپ اسے بھیجتے ہیں وہ بھی سیشن کے ساتھ اپ لوڈ ہوتی ہیں، الا یہ کہ آپ اسے `DSH_TELEMETRY_MODE=DISABLED` کے ساتھ شروع کریں۔

### ڈیفالٹ ایجنٹ

اپنا ڈیفالٹ ایجنٹ `omarchy default agent <name>` سے یا Omarchy Menu (`Super + Space`) میں _Agent > Harness_ کے تحت منتخب کریں۔ اگر ایجنٹ ابھی نصب نہیں ہوا تو اسے منتخب کرنے سے وہ پہلے نصب ہو جائے گا۔ نیا Omarchy ایک مرتبہ آنے والی اطلاع کے ذریعے آپ کو یہ انتخاب کرنے کی دعوت دے گا۔

Claude منتخب کرنے پر Chromium، Chrome، Brave، Brave Origin اور Edge کے لیے اس کی براؤزر توسیع ترتیب دینے کی بھی کوشش کی جاتی ہے۔ توسیع کی ترتیب تمام صارفین پر لاگو ہوتی ہے اور آپ سے آپ کا سسٹم پاس ورڈ مانگ سکتی ہے؛ منسوخ کرنے یا توسیع کی تنصیب ناکام ہونے پر بھی Claude منتخب اور لانچ ہو جاتا ہے۔ اپنا براؤزر دوبارہ شروع کریں، اشارہ ملنے پر توسیع فعال کریں، اور اسے جوڑنا مکمل کرنے کے لیے Claude میں سائن ان کریں۔ کنکشن جانچنے کے لیے Claude میں `/chrome` چلائیں۔ Firefox اور Zen اس توسیع کی حمایت نہیں کرتے۔ اگر یہ ترتیب شامل کیے جانے سے پہلے ہی Claude آپ کا ڈیفالٹ تھا تو توسیع نصب کرنے کے لیے اسے دوبارہ منتخب کریں۔

منتخب کر لینے کے بعد، `Super + Shift + Ctrl + A` ڈیفالٹ ایجنٹ کو ایک مخصوص ٹرمینل ونڈو میں لانچ کرتا ہے (یا اگر آپ نے ابھی انتخاب نہیں کیا تو picker سامنے لاتا ہے)۔ آپ اسے `omarchy agent prompt "Review this project"` کے ذریعے سیدھا کسی کام میں بھی لانچ کر سکتے ہیں۔ Freebuff اور DeepSeek Harness کوئی ابتدائی prompt نہیں لیتے، چنانچہ وہ اس کے بجائے اس prompt کے ساتھ کھلتے ہیں جو آپ کے clipboard پر چسپاں کرنے کے لیے موجود ہوتا ہے۔ اس طرح لانچ کیے گئے ایجنٹس اپنے متعلقہ رکنے اور پوچھنے سے گریز والے طریقوں میں بغیر نگرانی کے چلتے ہیں، لہٰذا تیار رہیں کہ وہ واقعی کچھ کر گزریں گے! MiniMax Code کے انٹرایکٹو سیشنز کے لیے ایسا کوئی طریقہ موجود نہیں، چنانچہ وہ معمول کے مطابق اجازتیں مانگتا ہے۔ اور چونکہ ایجنٹس آپ کی home ڈائریکٹری کے لیے بھروسا یاد رکھنے سے انکار کرتے ہیں، اس لیے `$HOME` سے ہونے والی لانچز اس کے بجائے `~/Work` میں شروع ہوتی ہیں۔

ٹرمینل شارٹ کٹس بھی موجود ہیں: `a` ڈیفالٹ ایجنٹ کو موجودہ ٹرمینل میں ان لائن چلاتا ہے، جبکہ `c`، `cx` اور `cy` OpenCode، Claude Code اور Codex کو براہ راست شروع کرتے ہیں (ایک بار پھر ان کے خودکار منظوری والے طریقوں میں)۔ تھیم کی تبدیلیاں ایجنٹس کے ساتھ بھی ہم آہنگ ہو جاتی ہیں: جب آپ Omarchy تھیم بدلتے ہیں تو Claude Code، Pi، OpenCode اور Hermes (جب Omarchy اسے نصب کر لے) سب اس کے ساتھ بدل جاتے ہیں۔

### آپ کی ایجنٹ ہدایات

ہر ایجنٹ کے لیے ذاتی اصول `~/.agents/AGENTS.md` میں جاتے ہیں، مشترکہ اسکلز کے برابر میں `~/.agents/skills` میں۔ اسے _Agent > Instructions_ کے تحت کھولیں، جو اسے ہر اس harness میں بھی جوڑ دیتا ہے جو اپنی عالمی فائل رکھتا ہے: `~/.claude/CLAUDE.md`، `~/.codex/AGENTS.md`، `~/.pi/agent/AGENTS.md`، `~/.config/opencode/AGENTS.md`، Copilot کی `~/.copilot/copilot-instructions.md`، وغیرہ۔ Crush اور Amp `~/.config/AGENTS.md` والا لنک پڑھتے ہیں، جبکہ omp، Kimi اور DeepSeek Harness `~/.agents/AGENTS.md` کو براہ راست پڑھتے ہیں۔ ڈیفالٹ ایجنٹ منتخب کرنے پر وہ بھی اسے جوڑ دیتا ہے۔ اگر آپ کے پاس پہلے سے کوئی ہدایات فائل موجود تھی اور ابھی کوئی مشترکہ فائل نہیں تھی تو وہی مشترکہ بن جاتی ہے؛ ورنہ اسے لنک کے برابر میں `.bak` کے طور پر رکھا جاتا ہے۔ ایک اور ایجنٹ نصب کرنے کے بعد دوبارہ جوڑنے کے لیے `omarchy agent instructions` چلائیں۔

### ایجنٹس پینل

اوپری بار میں ایجنٹس کا ایک آئیکن موجود ہے۔ ایجنٹ ترتیب دینے سے پہلے، اس کا پینل آپ کو Claude، Codex یا Grok میں سائن ان کرنے کے مراحل سے گزارتا ہے، اور ان میں سے پہلا آپ کا ڈیفالٹ ایجنٹ بن جاتا ہے۔ اس کے بعد، پینل ہر سبسکرپشن کو ایک ہی صفحے پر رکھ دیتا ہے: ہر ایجنٹ اور اکاؤنٹ اپنے منصوبے کے ساتھ، اس کی 5 گھنٹے کے سیشن اور ہفتہ وار حدود میں سے ہر ایک کے لیے ایک میٹر جس کے ساتھ اس کے ری سیٹ ہونے تک کا وقت بھی ہوتا ہے (درست فیصد کے لیے اس پر ہوور کریں)، یا باقی ماندہ پیشگی ادا شدہ بیلنس، ایک ایسی سطر کے نیچے جو ان سب میں آپ کے استعمال کی چیزوں کے درمیان گردش کرتی رہتی ہے، جیسے اس ہفتے کے ٹوکنز اور آپ کا سب سے زیادہ استعمال شدہ ماڈل۔ _Make something_ کے تحت یہ نئی تھیم، پلگ ان یا ایپ کے لیے ابتدائی prompts پیش کرتا ہے جو کام آپ کے ڈیفالٹ ایجنٹ کے حوالے کر دیتے ہیں۔ ایپس اسی طرح بنائی جاتی ہیں جیسے Omarchy کی اپنی Hype، Monologue اور Omacut ہیں، C++ اور Qt Quick میں، omarchy-app ایجنٹ اسکل کی پیروی کرتے ہوئے، اور انہیں درکار compiler اور Qt اجزا نصب شدہ آتے ہیں۔ Claude Code، Codex، Grok، Kimi، Cursor اور اس کا Grok Bot الاؤنس، GitHub Copilot، Muse، Antigravity، Kimchi اور Devin اپنی حدود کے ساتھ ابتدا ہی سے شامل ہیں، اور Hermes، Mistral Vibe اور Qwen Code کو ایک مرتبہ استعمال کر لینے کے بعد ان کے سیشنز اور ٹوکنز نظر آتے ہیں۔ pi، omp یا opencode کے ذریعے استعمال کیے جانے والے فراہم کنندہ منصوبے اور کلیدیں بھی نظر آتی ہیں: OpenCode Zen اور Go، Z.ai GLM Coding Plan، Ollama Cloud، MiniMax Token Plan اور Synthetic اپنی حدود کے ساتھ؛ Fireworks، OpenRouter اور DeepSeek اپنے پیشگی ادا شدہ بیلنس کے ساتھ؛ اور وہ ماڈلز جو آپ اپنے ہارڈویئر پر Local models کے تحت چلاتے ہیں۔ ہر ایجنٹ ایک ہی مرتبہ شمار ہوتا ہے، اسی کے تحت جو اس کا بل بھیجتا ہے، خواہ آپ اسے کتنے ہی harnesses کے ذریعے چلائیں۔

پینل کے لیے بار آئیکن پر بایاں کلک کریں، اپنے ڈیفالٹ ایجنٹ کو لانچ کرنے کے لیے دایاں کلک کریں۔ اس کے پیچھے موجود استعمال کے ریکارڈز ہر 15 منٹ بعد `omarchy agent usage-update` کے ذریعے دوبارہ بنائے جاتے ہیں، اور پینل ایک ہم آہنگ فولڈر کے ذریعے آپ کی دوسری مشینوں کے استعمال کو بھی ضم کر سکتا ہے۔ مکمل ترتیبات کے لیے `$OMARCHY_PATH/shell/plugins/agents/` کے تحت README دیکھیں۔

### متعدد سبسکرپشنز

اگر آپ ایک سے زیادہ Claude، Codex یا Grok منصوبوں کے لیے ادائیگی کرتے ہیں — مثلاً ایک ذاتی Max اور ایک دفتری — تو Omarchy ان سب کو سائن ان رکھ سکتا ہے اور ان کے درمیان منتقل ہو سکتا ہے۔ ایجنٹس پینل میں + کے ذریعے ایک سبسکرپشن شامل کریں، جو آپ کو وہیں اس کے مراحل سے گزارتا ہے، یا `omarchy agent account add claude Work` (یا `codex`، یا `grok`) کے ذریعے۔ اگر CLI موجود نہ ہو تو یہ اسے نصب کر دیتا ہے۔ کسی فراہم کنندہ کے لیے پہلا اکاؤنٹ آپ کے معمول کے براؤزر کے ذریعے سائن ان ہوتا ہے، عین وہیں جہاں CLI ہمیشہ دیکھتا ہے۔ اس کے بعد کا ہر اکاؤنٹ ایک نجی ونڈو کے ذریعے سائن ان ہوتا ہے، تاکہ جس اکاؤنٹ میں آپ کا براؤزر پہلے سے سائن ان ہے وہ غلطی سے نہ پکڑا جائے؛ وہاں اس اکاؤنٹ کے طور پر سائن ان کریں جسے آپ شامل کر رہے ہیں، اور پہلے سے کھلی ہوئی کسی بھی نجی ونڈو کو پہلے بند کر دیں۔ اس کے لیے کبھی CLI سے لاگ آؤٹ نہ کریں: لاگ آؤٹ کرنے سے محفوظ شدہ سائن ان منسوخ ہو جاتا ہے، اور اس اکاؤنٹ کو دوبارہ شامل کرنا پڑے گا۔

اپنی سبسکرپشن لاگ انز کو SSH کے ذریعے کسی دوسری Omarchy مشین پر نقل کرنے کے لیے `omarchy agent account copy user@laptop` چلائیں۔ جب منزل پر کوئی وصول کنندہ نصب نہ ہو تو بھیجنے والا ایک عارضی وصول کنندہ فراہم کرتا ہے، چنانچہ پرانی Omarchy مشینیں بھی بغیر اپ ڈیٹ کے اکاؤنٹس وصول کر سکتی ہیں۔ نصب شدہ وصول کنندگان کو ترجیح حاصل ہوتی ہے۔ یہ تمام Claude، Codex اور Grok سبسکرپشنز نقل کرتا ہے؛ انہیں منتخب کرنے کے لیے فراہم کنندگان کے نام شامل کریں، جیسے `omarchy agent account copy laptop claude` میں۔ اکاؤنٹ کے نام اور کمانڈ IDs ماخذ سے مطابقت رکھتے ہیں، بشمول وہ اکاؤنٹس جو منزل پر پہلے سے موجود ہوں۔ اگر غیر متعلق منزل اکاؤنٹس کے ناموں میں تصادم ہو تو انہیں ایک عددی لاحقہ مل جاتا ہے، اور ترتیبات، اسکلز، پلگ انز اور گفتگو کی تاریخ ہر مشین پر مقامی رہتی ہے۔

منزل کے موجودہ اسناد برقرار رکھے جاتے ہیں۔ جو ماخذ اکاؤنٹ وہاں پہلے سے سائن ان ہو اس کا نام اس کے اسناد بدلے بغیر ہم آہنگ کر دیا جاتا ہے؛ دوسرے اکاؤنٹس اس کے ساتھ شامل کر دیے جاتے ہیں۔ مطابقت رکھنے والے اکاؤنٹس کے محفوظ شدہ اسناد بدلنے کے لیے، منزل پر اس اکاؤنٹ کے سیشنز بند کرنے کے بعد `omarchy agent account copy --replace laptop claude` استعمال کریں۔ نئی منزل کو ماخذ کا فعال اکاؤنٹ اور تبدیلی کی ترجیحات بھی ملتی ہیں؛ قائم شدہ منزل اپنی ترجیحات برقرار رکھتی ہے۔

اسناد SSH کے ذریعے سفر کرتے ہیں اور منزل پر نجی فائلوں میں محفوظ ہوتے ہیں، چنانچہ صرف ان مشینوں پر نقل کریں جن پر آپ کو بھروسا ہو۔ یہ ایک مرتبہ کی نقل ہے، جاری ہم آہنگی نہیں۔ Codex کے refresh tokens کسی دوسری مشین کے ذریعے بدلے جا سکتے ہیں، جس سے نقل شدہ لاگ ان کو تجدید کی ضرورت پڑ سکتی ہے؛ کئی مشینوں پر بیک وقت استعمال کے لیے الگ الگ سائن انز ہی سب سے قابل اعتماد انتخاب ہیں۔ دیکھیں [Codex کی اکاؤنٹ تصدیق رہنمائی](https://developers.openai.com/codex/auth/ci-cd-auth)۔

فی فراہم کنندہ ایک اکاؤنٹ فعال ہوتا ہے، اور ہر نیا سیشن اسی کے طور پر شروع ہوتا ہے: `cx`، `cy`، سادہ `claude`، `codex` یا `grok`، `omarchy agent` کے ذریعے لانچ کی گئی کوئی بھی چیز، اور وہ اسکرپٹس یا ایڈیٹرز جو CLI کو `PATH` پر تلاش کرتے ہیں۔ `omarchy agent account use work` سے تبدیل کریں (اور `omarchy agent account use main` سے واپس آئیں)، یا پینل میں کسی اکاؤنٹ کا نمبر دبا کر پھر `Enter` دبا کر (یا اس کے Use بٹن پر کلک کر کے)۔ جو سیشنز پہلے سے چل رہے ہیں وہ اسی اکاؤنٹ پر رہتے ہیں جس سے وہ شروع ہوئے تھے۔ گفتگو کی تاریخ، ترتیبات، اسکلز اور پلگ انز اکاؤنٹس میں مشترکہ ہوتے ہیں، چنانچہ اسی فولڈر میں `claude --continue` وہیں سے آگے بڑھتا ہے جہاں آپ نے نئے اکاؤنٹ پر چھوڑا تھا۔

ایک سے زیادہ اکاؤنٹ ہونے پر، پینل ہر اکاؤنٹ کی حدود ساتھ ساتھ دکھاتا ہے، جس میں فعال اکاؤنٹ نشان زد ہوتا ہے۔ بطور ڈیفالٹ جب فعال اکاؤنٹ کسی حد کے 95% سے آگے بڑھتا ہے تو Omarchy آپ کو مطلع کرتا ہے، اور اطلاع پر کلک کرنے سے سب سے زیادہ گنجائش والے اکاؤنٹ پر منتقل ہو جاتا ہے۔ پینل میں کسی اکاؤنٹ کی سطر پر ہوور کریں اور Use کے برابر میں ظاہر ہونے والے Autoswitch پر کلک کریں (یا `m` دبائیں)، یا `omarchy agent account mode auto` چلائیں، تاکہ یہ خود بخود تبدیل ہو جائے؛ جب یہ فعال ہو تو Autoswitch، Use کی جگہ لے لیتا ہے، اور اس پر دوبارہ کلک کرنے سے اطلاع دینے پر واپس آ جاتا ہے۔ حد بدلنے کے لیے ایک نمبر شامل کریں، جیسے `omarchy agent account mode auto 90` میں۔ اگر ہر اکاؤنٹ حد سے اوپر ہو تو آپ کو ایک مرتبہ اس کی اطلاع ملے گی، اس کے ساتھ کہ کون سا اکاؤنٹ سب سے پہلے خالی ہوگا۔ جب کوئی فعال اکاؤنٹ اپنی حد کے 15 پوائنٹس کے اندر ہو (ڈیفالٹ پر 80%) تو اس کی حدود ہر 15 کے بجائے ہر تین منٹ بعد جانچی جاتی ہیں۔

`omarchy agent account list` ہر اکاؤنٹ اور اس کی تازہ ترین حدود دکھاتا ہے، `omarchy agent account remove work` ایک کو بھلا دیتا ہے، اور `omarchy agent account rename primary Hey` ایک کا نام بدل دیتا ہے (یا پینل میں کسی اکاؤنٹ کے نام پر کلک کریں)۔ یہ کمانڈز آپ کے ڈیفالٹ ایجنٹ کے اکاؤنٹس پر کام کرتی ہیں؛ دوسرے فراہم کنندہ تک پہنچنے کے لیے پہلے اس کا نام لیں، جیسے `omarchy agent account use codex side` میں۔ `~/.claude` یا `~/.codex` میں جو لاگ ان آپ کے پاس پہلے سے موجود تھا وہ _Main_ اکاؤنٹ ہے اور وہیں رہتا ہے۔ جو اکاؤنٹ تقریباً آٹھ گھنٹے سے زیادہ عرصے تک استعمال نہ ہوا ہو وہ _Sign-in required_ دکھا سکتا ہے؛ اس اکاؤنٹ کو پینل ہی میں دوبارہ سائن ان کرنے کے لیے اس پر کلک کریں، یا اس میں ایک سیشن شروع کریں، جو سائن ان کو خود بخود تازہ کر دیتا ہے۔ جب کوئی اکاؤنٹ شامل کیا گیا تھا اس وقت آپ کے پاس موجود MCP servers اس میں ساتھ آ جاتے ہیں، لیکن جنہیں آپ بعد میں `claude mcp add` سے شامل کرتے ہیں وہ صرف اسی اکاؤنٹ تک پہنچتے ہیں جس میں آپ نے انہیں شامل کیا تھا۔ Claude Desktop اور CLI binary کے مطلق راستے کے ساتھ ترتیب شدہ ٹولز اس تبدیلی کی پیروی نہیں کرتے۔ واضح `CLAUDE_CONFIG_DIR`، `CODEX_HOME` یا `GROK_HOME` منتخب شدہ اکاؤنٹ پر فوقیت رکھتا ہے۔

### کریش کی تشخیص

Omarchy عمل کے کریشز کے لیے systemd-coredump پر نظر رکھتا ہے۔ جب کوئی چیز segfault کرتی ہے تو آپ کو "Process crashed" اطلاع ملے گی — اس پر کلک کریں، اور کریش آپ کے ڈیفالٹ ایجنٹ کے حوالے کر دیا جاتا ہے Omarchy کی diagnose-crash اسکل کے ساتھ، جو ایجنٹ کو core dump سے حقائق قائم کرنے اور یہ فیصلہ کرنے کے مراحل سے گزارتی ہے کہ آیا کریش upstream کو رپورٹ کرنے کے قابل ہے۔ آپ اسے `coredumpctl list` سے حاصل شدہ کسی بھی PID کے مقابل ہاتھ سے بھی `omarchy agent crash <pid>` کے ذریعے چلا سکتے ہیں۔

یہ نگرانی بطور ڈیفالٹ فعال ہے۔ اسے _Trigger > Toggle > Crash Capture_ کے تحت (یا `omarchy toggle crash-capture` کے ذریعے) بند کر دیں تو اطلاعات رک جاتی ہیں؛ `omarchy agent crash <pid>` ہاتھ سے پھر بھی کام کرتا ہے۔

کریشز کو ایک وقت میں ایک پروگرام کے حساب سے خاموش بھی کیا جا سکتا ہے، جو تشخیص آخر میں آپ کو پیش کرتی ہے۔ `omarchy crash mute hyprland` صرف اس پروگرام کے لیے اطلاعات روک دیتا ہے، `omarchy crash mute hyprland off` انہیں واپس لاتا ہے، اور اکیلا `omarchy crash mute` وہ فہرست دکھاتا ہے جو آپ نے خاموش کی ہے۔ یہ binary کا راستہ بھی اتنی ہی خوشی سے لیتا ہے جتنا اس کا نام، چنانچہ `omarchy crash mute /usr/bin/hyprland` بھی وہی کام کرتا ہے۔ جس نام میں جگہ ہو اسے اقتباس میں لکھیں، جیسے `omarchy crash mute 'Some App'` میں۔ باقی سب کچھ بدستور مطلع کرتا ہے، اور خاموش کیا گیا پروگرام بدستور کریش ہوتا ہے — یہ یاد دہانی چھپاتا ہے، کچھ ٹھیک نہیں کرتا۔

### ڈیسک ٹاپ ایپس

_Install > AI_ مینو میں چند گرافیکل AI ایپس بھی شامل ہیں: ChatGPT ڈیسک ٹاپ ایپ، Claude ڈیسک ٹاپ ایپ (Anthropic کا Linux بیٹا، Chat، Cowork اور Claude Code ٹیبز کے ساتھ)، xAI کے ماڈلز سے گفتگو کے لیے Grok Bot، Herdr Desktop، Hermes Desktop، OpenClaw، Perplexity ڈیسک ٹاپ ایپ، اور T3 Code۔ Grok Bot ڈیسک ٹاپ چیٹ ایپ ہے۔ کوڈنگ ایجنٹ `grok` کمانڈ ہے۔

Hermes Desktop وہ ہے جس کے بارے میں جاننا ضروری ہے، کیونکہ کسی مشین پر ایک ہی Hermes ہوتا ہے، اور وہ اس ایپ کا ہوتا ہے: Hermes ہمیشہ صرف ایپ کے ذریعے نصب ہوتا ہے، اور جو `hermes` کمانڈ ڈیفالٹ ایجنٹ چلاتا ہے وہ اسی ایپ کی ہوتی ہے۔ Hermes کو ڈیفالٹ ایجنٹ کے طور پر منتخب کرنا وہی چیز نصب کرتا ہے جو _Install > AI_ اندراج کرتا ہے: پیکیج، اور `~/.hermes` کے تحت ایک Hermes runtime جو Hermes کے اپنے انسٹالر کے ذریعے ترتیب دیا جاتا ہے، جس میں پہلی مرتبہ چند منٹ لگتے ہیں۔ وہی runtime وہ واحد Hermes ہے جسے ٹرمینل کی `hermes` کمانڈ، ڈیفالٹ ایجنٹ اور ایپ سب استعمال کرتے ہیں، اور یہ Omarchy ریلیز کا انتظار کرنے کے بجائے `hermes update` کے ذریعے خود کو اپ ڈیٹ کرتا ہے۔ اسے نصب کرنے پر Hermes کو Omarchy تھیم بطور ایک skin بھی ملتی ہے جس کا نام `omarchy` ہے، جس کی پیروی Hermes کی ہر سطح تھیمز بدلنے پر کرتی ہے؛ اگر آپ نہ چاہیں کہ ایسا ہو تو Hermes کی Appearance ترتیبات کے تحت یا `/skin` کے ذریعے کوئی اور منتخب کریں، اور Omarchy اس انتخاب کو چھوڑ دیتا ہے۔ _Remove > AI_ کے تحت ایپ ہٹانے سے پہلے Hermes بند ہو جاتا ہے، gateway سمیت، وہ runtime اس کے ساتھ چلا جاتا ہے، اور آپ کی چیٹس، یادیں اور وہ اسکلز جو Hermes نے اپنے لیے لکھی تھیں برقرار رہتی ہیں الا یہ کہ آپ اسے دوسری صورت کہیں: یہ پوچھتا ہے، جس میں ڈیفالٹ نہیں ہے، کہ آیا وہ ڈیٹا اور آپ کی کنکشن ترتیبات بھی جانی چاہئیں۔

OpenClaw کا ڈیسک ٹاپ تجربہ اس کا Control UI ہے، جو اس کے اپنے مقامی gateway کی پشت پناہی میں ایک ویب ایپ کے طور پر کھلتا ہے۔ OpenClaw `~/.openclaw` میں رہتا ہے اور خود کو اپ ڈیٹ کرتا ہے: Control UI کا "Update Gateway" بٹن استعمال کریں یا `openclaw update` چلائیں، اور gateway نئے ورژن پر دوبارہ شروع ہو جاتا ہے۔ Omarchy صرف وہ ریلیز منتخب کرتا ہے جس سے نئی تنصیب شروع ہوتی ہے۔ _Remove > AI_ کے تحت OpenClaw ہٹانے سے gateway سروس اور ایپ اس کے ساتھ چلے جاتے ہیں اور پھر پوچھا جاتا ہے کہ آیا `~/.openclaw` بھی جانا چاہیے، کیونکہ اس میں OpenClaw کے ساتھ ساتھ آپ کی چیٹس اور اسناد اور اس کے ڈاؤن لوڈ کردہ پلگ ان runtimes موجود ہوتے ہیں؛ ڈیفالٹ اسے برقرار رکھتا ہے، اور OpenClaw دوبارہ نصب کرنے پر یہ اسے واپس اٹھا لیتا ہے۔

Herdr Desktop، [Herdr](https://herdr.dev) ڈیسک ٹاپ ایپ ہے: ٹرمینلز اور کوڈنگ ایجنٹس کے spaces، tabs اور panes جو ونڈو بند کرنے پر بھی اس کے core میں چلتے رہتے ہیں۔ یہ کسی پیکیج کے بجائے Herdr کے اپنے انسٹالر سے آتا ہے، چنانچہ یہ `~/.local/share/herdr-app` میں رہتا ہے، جب آپ کے پاس پہلے سے کوئی موجود نہ ہو تو اپنے core کو `~/.local/bin/herdr-core` میں ساتھ لاتا ہے، اور دونوں کو خود اپ ڈیٹ کرتا ہے۔ یہ اس `herdr` کمانڈ کے برابر میں بیٹھتا ہے جو Omarchy `Super + Ctrl + Return` پر فراہم کرتا ہے، اس کی جگہ لینے کے بجائے، اور اسے اس کمانڈ کی براہ راست کلیدیں ملتی ہیں: `Alt + Return` اور `Alt + Shift + Return` کسی pane کو نیچے یا دائیں تقسیم کرتے ہیں، `Alt + Escape` اسے بند کرتا ہے، `Ctrl + Alt + Arrow` panes کے درمیان منتقل ہوتا ہے، `Alt + 1..9` اور `Alt + Left/Right` ایک ٹیب منتخب کرتے ہیں، اور `Alt + Up/Down` spaces کے درمیان منتقل ہوتے ہیں۔ `Ctrl + 1..9` ایک space منتخب کرتا ہے اور `Alt + Shift + Up/Down` ایجنٹس کے درمیان قدم بڑھاتا ہے۔ `Ctrl + Space` prefix کلیدیں صرف ٹرمینل کے لیے رہتی ہیں، کیونکہ ایپ کسی سلسلے کے لیے سادہ Ctrl کلید کو تھام نہیں سکتی۔ Omarchy انہیں `~/.config/herdr-app/keys.json` میں لکھتا ہے، اور `omarchy-refresh-herdr-app` انہیں واپس رکھ دیتا ہے۔ اسے نصب کرنے پر Herdr کی Omarchy تھیم منتخب ہو جاتی ہے، جو اس کے بعد سے آپ کی Omarchy تھیم کی پیروی کرتی ہے۔ Herdr ہلکے موڈ کے لیے ایک تھیم اور گہرے موڈ کے لیے ایک تھیم رکھتا ہے، چنانچہ گہری اور ہلکی Omarchy تھیم کے درمیان بدلنے کے بعد، دوسرے موڈ کے لیے Herdr کے تھیم picker میں ایک بار پھر Omarchy منتخب کریں۔

T3 Code کسی پیکیج کے بجائے `~/.local/share/t3code` میں اپنی سرکاری AppImage ریلیز سے چلتا ہے، چنانچہ یہ خود کو اپ ڈیٹ کرتا ہے۔ اسے نصب کرنے پر پوچھا جاتا ہے کہ Stable یا Nightly چینل پر شروع کرنا ہے؛ بعد میں T3 Code کی ترتیبات میں تبدیل کریں۔ آپ کے تھریڈز اور ترتیبات `~/.t3` میں رہتے ہیں، اور _Remove > AI_ کے تحت T3 Code ہٹانے سے وہ بھی اس کے ساتھ چلے جاتے ہیں۔

### مقامی ماڈلز

اپنے کوڈنگ ایجنٹس کے لیے اپنی مشین پر ایک کھلا ماڈل چلائیں۔ آپ کے prompts اور کوڈ مشین پر رہتے ہیں؛ ماڈل کو بھیجی گئی کوئی چیز اس سے باہر نہیں جاتی۔ اس سے شروع کریں:

```bash
omarchy agent local use best
```

یا، اوپری بار کے ایجنٹس پینل میں، + اور پھر Local AI منتخب کریں، جو اس وقت نظر آتا ہے جب کوئی ماڈل اس مشین کے لیے موزوں ہو۔ پہلی مرتبہ، یہ Podman نصب کرتا ہے، جو ماڈلز چلاتا ہے، اور NVIDIA مشین پر NVIDIA کا container toolkit، جو انہیں GPU فراہم کرتا ہے۔ پھر Omarchy اس مشین کے لیے تجویز کردہ ماڈل منتخب کرتا ہے، اسے ڈاؤن لوڈ کرتا ہے، اور شروع کرتا ہے۔ دسیوں GB کے ڈاؤن لوڈ کی توقع رکھیں اور یہ بھی کہ جب ماڈل چل رہا ہو تو مشین کی زیادہ تر میموری استعمال میں ہوگی: Flash Next اپنے مکمل 256K سیاق و سباق کے ساتھ تقریباً 100 GiB استعمال کرتا ہے۔ اگر دوسرے ماڈلز وہ میموری لیے ہوئے ہوں جس کی اسے ضرورت ہے تو یہ بند حالت میں ترتیب دیا جاتا ہے، جب آپ کسی ایک کو روکیں تو شروع ہونے کے لیے تیار۔ ماڈل لاگ آؤٹ پر رک جاتا ہے؛ جب آپ کو کسی اور کام کے لیے میموری درکار ہو تو اسے خود روک دیں۔

`omarchy agent local list` اختیارات دکھاتا ہے اور بتاتا ہے کہ کچھ کیوں موزوں نہیں ہیں۔ کوئی دوسرا ترتیب دینے کے لیے `omarchy agent local use <recipe>` چلائیں۔ آج، 128 GB Strix Halo مشینوں کے لیے `qwen3.8-flash-next-gufo` اور `qwen3.8-27b-gufo` دستیاب ہیں؛ 27B تقریباً 40 GiB لیتا ہے، چنانچہ یہ دوسرے کام کے لیے جگہ چھوڑ دیتا ہے۔ نئی ترکیبیں اور تجاویز پیکیج کے ذریعے `omarchy update` کے ساتھ آتی ہیں۔

آپ کے ترتیب دیے گئے ہر ماڈل کو ایجنٹس پینل میں آپ کی سبسکرپشنز کے برابر میں اپنی سطر ملتی ہے: اسے شروع کرنے کے لیے play، اسے روکنے اور اس کی میموری خالی کرنے کے لیے pause، اور اس پر اپنا ایجنٹ کھولنے کے لیے ٹرمینل بٹن۔ جب وہ میموری میں ایک ساتھ سما جائیں تو کئی ایک ساتھ چل سکتے ہیں؛ اگر کوئی نہ سمائے تو Omarchy بتاتا ہے کہ کون سا چلتا ہوا ماڈل روکنا ہے۔ انہیں دوبارہ ترتیب دینے کے لیے سطریں گھسیٹیں، اور منتخب سطر پر Delete دبا کر کسی ماڈل اور اس کے ڈاؤن لوڈ کو ہٹا دیں۔

کمانڈ لائن سے، `omarchy agent local start <recipe>` اور `omarchy agent local stop <recipe>` بھی یہی کرتے ہیں، `omarchy agent local status` ہر ماڈل دکھاتا ہے، اور `omarchy agent --local` آپ کے ڈیفالٹ ایجنٹ کو آخری شروع کیے گئے ماڈل پر کھولتا ہے (اگر آپ کا ڈیفالٹ ایجنٹ مقامی ماڈل استعمال نہ کر سکے تو pi)۔ کوئی بھی OpenAI سے مطابقت رکھنے والا client بھی جڑ سکتا ہے: `status` ہر ماڈل کا پتہ دکھاتا ہے (پہلا `http://127.0.0.1:11435/v1` ہے)، ترکیب کا نام ہی ماڈل ہے، اور کلید `~/.config/omarchy/agent-local/key` میں ہے۔

`omarchy agent local remove <recipe>` کسی ماڈل اور ان ڈاؤن لوڈز کو حذف کر دیتا ہے جنہیں کوئی دوسرا ماڈل استعمال نہیں کرتا۔

فریق ثالث کے runtimes پر ان کے ناشر کا لیبل لگا ہوتا ہے۔ Omarchy ہر ماڈل کو بغیر نیٹ ورک رسائی کے چلاتا ہے۔

### مقامی LLMs

Omarchy مقامی LLM ماڈلز چلانے کے دو طریقے تجویز کرتا ہے: LM Studio اور Ollama۔ LM Studio کھلے وزن والے ماڈلز تلاش کرنے، انہیں نصب کرنے اور چلانے کے لیے ایک GUI انٹرفیس فراہم کرتا ہے۔ آسانی سے آغاز کرنے کا یہ ایک بہترین طریقہ ہے۔ Ollama اسی طرح کا کام کرنے کے لیے ایک CLI پیش کرتا ہے۔ لیکن اگر آپ مقامی ماڈلز میں نئے ہیں تو میں LM Studio سے آغاز کروں گا۔ آپ Omarchy Menu میں _Install > AI_ کے تحت ان میں سے کوئی بھی نصب کر سکتے ہیں۔

### Omarchy اسکل

ایجنٹ اسکلز AI کو مخصوص ٹولز کو مخصوص انداز میں استعمال کرنے میں مدد دیتی ہیں، اور Omarchy نظام کو اپنی مرضی کے مطابق بنانے کے لیے ایک ڈیفالٹ اسکل کے ساتھ آتا ہے۔ جیسے اپنی Hyprland ترتیب میں ردوبدل کرنا، بار کو ایڈجسٹ کرنا، یا حتیٰ کہ ابتدا سے ایک نئی تھیم بنانا۔ یہ Claude Code (`~/.claude/skills`)، Codex (`~/.codex/skills`)، Pi (`~/.pi/agent/skills`)، Antigravity (`~/.gemini/config/skills`)، Hermes (`~/.hermes/skills` اور ہر `~/.hermes/profiles/*/skills`) اور عمومی `~/.agents/skills` مقام کے لیے اسکل ڈائریکٹریوں میں symlinked ہے، چنانچہ زیادہ تر harnesses اسے خود بخود اٹھا لیتے ہیں۔

لیکن آپ کو اس اسکل کو تجرباتی سمجھنا چاہیے۔ مختلف ماڈلز اسے مختلف اثر کے ساتھ استعمال کریں گے۔ بہتر ہے کہ پہلے اسے plan mode میں چلائیں، تاکہ آپ کو اندازہ ہو کہ ایجنٹ کیا بدلنا چاہے گا۔ اور پھر تبدیلیاں واپس لینے یا حتیٰ کہ `omarchy reinstall configs` چلانے کے لیے تیار رہیں، اگر ایجنٹ ہر چیز کا ستیاناس کر دے۔
