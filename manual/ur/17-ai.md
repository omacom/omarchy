### ایجنٹس کو انسٹال اور اپ ڈیٹ کرنا

Hermes کے علاوہ، یہ ایجنٹس mise کی lazy installation استعمال کرتے ہیں: پہلی لانچ پر CLI انسٹال ہوتا ہے، اور بعد کی لانچز اسی کو دوبارہ استعمال کرتی ہیں۔ mise انسٹال شدہ ایجنٹ کے لیے نئی ریلیز بھی زیادہ سے زیادہ ہر چار گھنٹے میں ایک بار چیک کرتا ہے، اس کے شروع ہونے سے عین پہلے یا پس منظر میں shell prompt پر۔ اگر وہ اپ ڈیٹ ناکام ہو جائے یا آپ offline ہوں، تو انسٹال شدہ ورژن چلتا ہے۔ `omarchy update` انسٹال شدہ ایجنٹس کو باقی Omarchy کے ساتھ اپ ڈیٹ کرتا ہے، اور `mup` صرف mise کے زیر انتظام ٹولز کو اپ ڈیٹ کرتا ہے۔

کسی ایجنٹ کا اپنا اپڈیٹر، جیسے `claude update`، `codex update`، یا کسی ایپ میں اپ ڈیٹ بٹن، mise کے زیر انتظام انسٹال کو اپ ڈیٹ نہیں کرتا۔ `codex update` ناکام ہو جاتا ہے، اور `claude update` کامیابی کی اطلاع دے سکتا ہے جبکہ ایک الگ نقل انسٹال کر دیتا ہے جسے mise track نہیں کرتا۔ اگر آپ اس کے بجائے کسی ایجنٹ کا اپنا انسٹالر اور اپڈیٹر استعمال کرنا پسند کریں، تو اسے `disable_tools` میں شامل کریں؛ دیکھیں [پہلے سے انسٹال شدہ CLI ٹولز](18-development-tools.md#preinstalled-cli-tools)۔

ضرورت پڑنے سے پہلے تمام configured lazy ٹولز انسٹال کرنے کے لیے، `mise install --include-lazy` چلائیں۔ اس میں ایجنٹس کے ساتھ ساتھ Omarchy کے دوسرے ڈیفالٹ CLI ٹولز بھی شامل ہیں۔ ایک اکیلا ٹول انسٹال کرنے یا اپنا انسٹال استعمال کرنے کے لیے دیکھیں [پہلے سے انسٹال شدہ CLI ٹولز](18-development-tools.md#preinstalled-cli-tools)۔

`grok` mise کے first-party `grok` package کے ذریعے انسٹال ہوتا ہے، اسی طرح جیسے `claude` اور `codex`۔ `grok` چلائیں، یا اسے _Setup > Defaults > Agent_ کے تحت منتخب کریں۔ x.ai پر `curl | bash` انسٹالر کو چھوڑ دیں۔ وہ راستہ `~/.grok/bin` میں دوسری نقل رکھتا ہے، اسے `PATH` پر آگے رکھتا ہے، اور Omarchy کے wrapper کو overwrite کر دیتا ہے۔

`dsh` اپنا browser UI `127.0.0.1:3080` پر کھولتا ہے، جس میں لانچ ڈائریکٹری اس کا ڈیفالٹ workspace ہوتی ہے۔ اس کا browser UI کوئی ابتدائی prompt نہیں لیتا، لہٰذا `omarchy agent prompt` اسے اس prompt کے ساتھ کھولتا ہے جو آپ کے clipboard پر paste کرنے کے لیے موجود ہوتا ہے۔ Omarchy اسے DeepSeek کے no-approval permission preset کے ساتھ شروع کرتا ہے۔ DeepSeek Harness جب آپ اس کا سرکاری ماڈل API استعمال کرتے ہیں تو session logs DeepSeek کو upload کرتا ہے؛ اسے اس کے browser UI میں _Settings > General > Upload Session Log_ کے تحت بند کریں۔ جو feedback آپ اسے بھیجتے ہیں وہ بھی session کے ساتھ upload ہو جاتی ہے، الا یہ کہ آپ اسے `DSH_TELEMETRY_MODE=DISABLED` کے ساتھ شروع کریں۔

### ڈیفالٹ ایجنٹ

اپنا ڈیفالٹ ایجنٹ `omarchy default agent <name>` کے ساتھ یا Omarchy Menu (`Super + Space`) میں _Setup > Defaults > Agent_ کے تحت منتخب کریں۔ اگر ایجنٹ ابھی انسٹال نہیں ہوا، تو اسے منتخب کرنے سے وہ پہلے انسٹال ہو جائے گا۔ ایک نئی Omarchy ایک بار کی اطلاع کے ساتھ آپ کو یہ انتخاب کرنے کی دعوت دے گی۔

Claude منتخب کرنے سے Chromium، Chrome، Brave، Brave Origin اور Edge کے لیے اس کی browser extension ترتیب دینے کی کوشش بھی ہوتی ہے۔ extension کی ترتیب تمام صارفین پر لاگو ہوتی ہے اور آپ سے آپ کا system password مانگ سکتی ہے؛ منسوخ کرنے یا extension انسٹال ناکام ہونے پر بھی Claude منتخب اور لانچ ہو جاتا ہے۔ اپنا browser دوبارہ شروع کریں، اشارہ ملنے پر extension فعال کریں، اور اسے جوڑنا مکمل کرنے کے لیے Claude میں sign in کریں۔ کنکشن چیک کرنے کے لیے Claude میں `/chrome` چلائیں۔ Firefox اور Zen اس extension کی حمایت نہیں کرتے۔ اگر یہ ترتیب شامل ہونے سے پہلے ہی Claude آپ کا ڈیفالٹ تھا، تو extension انسٹال کرنے کے لیے اسے دوبارہ منتخب کریں۔

منتخب کرنے کے بعد، `Super + Shift + Ctrl + A` ڈیفالٹ ایجنٹ کو ایک مخصوص terminal window میں لانچ کرتا ہے (یا اگر آپ نے ابھی انتخاب نہیں کیا تو picker سامنے لاتا ہے)۔ آپ اسے `omarchy agent prompt "Review this project"` کے ساتھ سیدھا کسی کام میں بھی لانچ کر سکتے ہیں۔ Freebuff اور DeepSeek Harness کوئی ابتدائی prompt نہیں لیتے، لہٰذا وہ اس کے بجائے paste کرنے کے لیے prompt آپ کے clipboard پر رکھ کر کھلتے ہیں۔ اس طرح لانچ کیے گئے ایجنٹس اپنے متعلقہ don't-stop-to-ask modes میں بغیر نگرانی چلتے ہیں، لہٰذا تیار رہیں کہ وہ واقعی کچھ کریں گے! MiniMax Code کے interactive sessions کے لیے ایسا کوئی mode نہیں ہے، لہٰذا وہ معمول کے مطابق اجازتیں مانگتا ہے۔ اور چونکہ ایجنٹس آپ کی home directory کے لیے trust یاد رکھنے سے انکار کرتے ہیں، اس لیے `$HOME` سے لانچز اس کے بجائے `~/Work` میں شروع ہوتی ہیں۔

terminal shortcuts بھی ہیں: `a` موجودہ terminal میں ڈیفالٹ ایجنٹ کو inline چلاتا ہے، جبکہ `c`، `cx` اور `cy` OpenCode، Claude Code اور Codex کو براہ راست شروع کرتے ہیں (ایک بار پھر ان کے auto-approving modes میں)۔ تھیم کی تبدیلیاں ایجنٹس کے ساتھ بھی sync ہوتی ہیں: جب آپ Omarchy تھیم بدلتے ہیں تو Claude Code، Pi، OpenCode اور Hermes (ایک بار جب Omarchy نے اسے انسٹال کر لیا ہو) سب اس کے ساتھ چلتے ہیں۔

### ایجنٹس پینل

top bar میں ایک agents icon ہے۔ آپ کے کسی ایجنٹ کو ترتیب دینے سے پہلے، اس کا پینل آپ کو Claude، Codex یا Grok میں sign in کرنے کے مراحل سے گزارتا ہے، اور پہلا والا آپ کا ڈیفالٹ ایجنٹ بن جاتا ہے۔ اس کے بعد، پینل ہر subscription کو ایک ہی صفحے پر رکھتا ہے: ہر ایجنٹ اور account اپنے plan کے ساتھ، اس کی 5-hour session اور weekly حدود میں سے ہر ایک کے لیے ایک meter جس میں reset ہونے تک کا وقت بھی ہو (درست فیصد کے لیے hover کریں)، یا باقی prepaid balance، ایک سطر کے نیچے جو ان سب میں آپ کے استعمال کی چیزوں کے درمیان گردش کرتی رہتی ہے، جیسے اس ہفتے کے tokens اور آپ کا سب سے زیادہ استعمال شدہ ماڈل۔ _Make something_ کے تحت یہ ایک نئی تھیم، plugin یا ایپ کے لیے starter prompts پیش کرتا ہے جو کام آپ کے ڈیفالٹ ایجنٹ کے حوالے کر دیتے ہیں۔ ایپس اسی طرح بنائی جاتی ہیں جیسے Omarchy کی اپنی Hype، Monologue اور Omacut ہیں، C++ اور Qt Quick میں، omarchy-app agent skill کی پیروی کرتے ہوئے، اور انہیں درکار compiler اور Qt اجزا انسٹال شدہ آتے ہیں۔ Claude Code، Codex، Grok، Kimi، Cursor اور اس کا Grok Bot allowance، GitHub Copilot، Muse، Antigravity، Kimchi اور Devin اپنی حدود کے ساتھ پہلے سے شامل ہیں، اور Hermes، Mistral Vibe اور Qwen Code آپ کے انہیں استعمال کرنے کے بعد اپنے sessions اور tokens دکھاتے ہیں۔ pi، omp یا opencode کے ذریعے آپ جو provider plans اور keys استعمال کرتے ہیں وہ بھی ظاہر ہوتے ہیں: OpenCode Zen اور Go، Z.ai GLM Coding Plan، Ollama Cloud، MiniMax Token Plan اور Synthetic اپنی حدود کے ساتھ؛ Fireworks، OpenRouter اور DeepSeek اپنے prepaid balances کے ساتھ؛ اور وہ ماڈلز جو آپ اپنے hardware پر Local models کے تحت چلاتے ہیں۔ ہر ایجنٹ کو ایک ہی بار شمار کیا جاتا ہے، اس کے تحت جس سے اس کا bill آتا ہے، چاہے آپ اسے کتنے ہی harnesses کے ذریعے چلائیں۔

پینل کے لیے bar icon پر left-click کریں، اپنے ڈیفالٹ ایجنٹ کو لانچ کرنے کے لیے right-click کریں۔ اس کے پیچھے موجود usage records ہر 15 منٹ میں `omarchy agent usage-update` کے ذریعے دوبارہ بنائے جاتے ہیں، اور پینل ایک synced folder کے ذریعے آپ کی دوسری مشینوں کے استعمال کو بھی ضم کر سکتا ہے۔ مکمل settings کے لیے `$OMARCHY_PATH/shell/plugins/agents/` کے تحت README دیکھیں۔

### متعدد subscriptions

اگر آپ ایک سے زیادہ Claude، Codex یا Grok plan کی ادائیگی کرتے ہیں — مثلاً ایک ذاتی Max اور ایک کام کا — تو Omarchy ان سب کو signed in رکھ سکتا ہے اور ان کے درمیان منتقل ہو سکتا ہے۔ agents panel میں + کے ساتھ ایک subscription شامل کریں، جو آپ کو وہیں اس کے مراحل سے گزارتا ہے، یا `omarchy agent account add claude Work` کے ساتھ (یا `codex`، یا `grok`)۔ اگر CLI موجود نہیں تو یہ اسے انسٹال کر دیتا ہے۔ کسی provider کا پہلا account آپ کے عام browser کے ذریعے sign in ہوتا ہے، عین وہیں جہاں CLI ہمیشہ دیکھتا ہے۔ اس کے بعد ہر ایک private window کے ذریعے sign in ہوتا ہے، تاکہ جس account میں آپ کا browser پہلے سے signed in ہے وہ غلطی سے نہ پکڑا جائے؛ وہاں اس account کے طور پر sign in کریں جسے آپ شامل کر رہے ہیں، اور پہلے سے کھلی ہوئی کوئی بھی private window پہلے بند کر دیں۔ ایسا کرنے کے لیے CLI سے کبھی log out نہ کریں: log out کرنے سے محفوظ شدہ sign-in منسوخ ہو جاتا ہے، اور اس account کو دوبارہ شامل کرنا پڑے گا۔

اپنے subscription logins کو SSH کے ذریعے کسی دوسری Omarchy مشین پر copy کرنے کے لیے، `omarchy agent account copy user@laptop` چلائیں۔ بھیجنے والا اس وقت ایک عارضی receiver فراہم کرتا ہے جب منزل پر کوئی انسٹال نہ ہو، لہٰذا پرانی Omarchy مشینیں بغیر کسی update کے accounts وصول کر سکتی ہیں۔ انسٹال شدہ receivers کو ترجیح حاصل ہوتی ہے۔ یہ تمام Claude، Codex اور Grok subscriptions copy کرتا ہے؛ انہیں منتخب کرنے کے لیے provider کے نام شامل کریں، جیسے `omarchy agent account copy laptop claude`۔ Account کے نام اور command IDs ماخذ سے ملتے ہیں، بشمول وہ accounts جو منزل پر پہلے سے موجود ہوں۔ غیر متعلقہ منزل accounts کو، اگر ان کے ناموں میں تصادم ہو، ایک عددی suffix ملتا ہے، اور settings، skills، plugins اور conversation history ہر مشین پر مقامی رہتی ہیں۔

منزل کے موجودہ credentials برقرار رکھے جاتے ہیں۔ کوئی ماخذ account جو وہاں پہلے سے signed in ہو، اس کا نام اس کے credentials بدلے بغیر synchronize ہو جاتا ہے؛ دوسرے accounts اس کے ساتھ شامل کر دیے جاتے ہیں۔ ملتے جلتے accounts کے لیے محفوظ شدہ credentials بدلنے کے لیے، منزل پر اس account کے sessions بند کرنے کے بعد `omarchy agent account copy --replace laptop claude` استعمال کریں۔ ایک نئی منزل کو ماخذ کا فعال account اور switching ترجیحات بھی ملتی ہیں؛ ایک قائم شدہ منزل اپنی ترجیحات برقرار رکھتی ہے۔

Credentials SSH کے ذریعے سفر کرتے ہیں اور منزل پر private files میں محفوظ ہوتے ہیں، لہٰذا صرف ان مشینوں پر copy کریں جن پر آپ کو اعتماد ہو۔ یہ ایک بار کی copy ہے، جاری synchronization نہیں۔ Codex refresh tokens کسی دوسری مشین کے ذریعے rotate کیے جا سکتے ہیں، جس سے copy شدہ login کو تجدید کی ضرورت پڑ جاتی ہے؛ متعدد مشینوں پر بیک وقت استعمال کے لیے الگ الگ sign-ins سب سے قابل اعتماد انتخاب رہتے ہیں۔ دیکھیں [Codex کی account authentication رہنمائی](https://developers.openai.com/codex/auth/ci-cd-auth)۔

فی provider ایک account فعال ہوتا ہے، اور ہر نیا session اسی کے طور پر شروع ہوتا ہے: `cx`، `cy`، ایک سادہ `claude`، `codex` یا `grok`، `omarchy agent` کے ذریعے لانچ کی گئی کوئی بھی چیز، اور scripts یا editors جو CLI کو `PATH` پر پاتے ہیں۔ `omarchy agent account use work` کے ساتھ switch کریں (اور `omarchy agent account use main` کے ساتھ واپس)، یا پینل میں کسی account کا نمبر دبا کر پھر `Enter` دبا کر (یا اس کے Use بٹن پر click کر کے)۔ جو sessions پہلے سے چل رہے ہیں وہ اسی account پر رہتے ہیں جس سے وہ شروع ہوئے تھے۔ Conversation history، settings، skills اور plugins accounts کے درمیان shared ہوتے ہیں، لہٰذا اسی folder میں `claude --continue` نئے account پر وہیں سے آگے بڑھتا ہے جہاں آپ نے چھوڑا تھا۔

ایک سے زیادہ account کے ساتھ، پینل ہر account کی حدود ساتھ ساتھ دکھاتا ہے، جس میں فعال account نشان زد ہوتا ہے۔ بطور ڈیفالٹ Omarchy آپ کو اس وقت مطلع کرتا ہے جب فعال account کسی حد کے 95% سے گزر جائے، اور اطلاع پر click کرنے سے سب سے زیادہ گنجائش والے account پر switch ہو جاتا ہے۔ پینل میں کسی account کی سطر پر hover کریں اور Use کے پاس ظاہر ہونے والے Autoswitch پر click کریں (یا `m` دبائیں)، یا `omarchy agent account mode auto` چلائیں، تاکہ یہ اس کے بجائے خود بخود switch ہو جائے؛ جب یہ فعال ہو، تو Autoswitch Use کی جگہ لے لیتا ہے، اور اس پر دوبارہ click کرنے سے اطلاع دینے پر واپس چلا جاتا ہے۔ threshold بدلنے کے لیے ایک نمبر شامل کریں، جیسے `omarchy agent account mode auto 90`۔ اگر ہر account threshold سے اوپر ہو، تو آپ کو اس کے بارے میں ایک بار سنا دیا جائے گا، اس کے ساتھ کہ کون سا account سب سے پہلے خالی ہوگا۔ جب کوئی فعال account اپنے threshold کے 15 points کے اندر ہو (ڈیفالٹ پر 80%)، تو اس کی حدود ہر 15 کے بجائے ہر تین منٹ میں چیک کی جاتی ہیں۔

`omarchy agent account list` ہر account اور اس کی تازہ ترین حدود دکھاتا ہے، `omarchy agent account remove work` ایک کو بھلا دیتا ہے، اور `omarchy agent account rename primary Hey` ایک کا نام بدل دیتا ہے (یا پینل میں کسی account کے نام پر click کریں)۔ یہ commands آپ کے ڈیفالٹ ایجنٹ کے accounts پر کام کرتی ہیں؛ دوسرے provider تک پہنچنے کے لیے، پہلے اس کا نام لیں، جیسے `omarchy agent account use codex side`۔ `~/.claude` یا `~/.codex` میں جو login آپ کے پاس پہلے سے تھا وہ _Main_ account ہے اور وہیں رہتا ہے جہاں وہ ہے۔ کوئی account جو تقریباً آٹھ گھنٹے سے زیادہ عرصے تک غیر استعمال شدہ رہ جائے وہ _Sign-in required_ دکھا سکتا ہے؛ اس account کو پینل میں ہی دوبارہ sign in کرنے کے لیے اس پر click کریں، یا اس میں ایک session شروع کریں، جو sign-in کو خود بخود تازہ کر دیتا ہے۔ جب کوئی account شامل کیا گیا تھا اس وقت آپ کے پاس موجود MCP servers اس میں ساتھ آتے ہیں، لیکن جنہیں آپ بعد میں `claude mcp add` کے ساتھ شامل کرتے ہیں وہ صرف اسی account تک پہنچتے ہیں جس میں آپ نے انہیں شامل کیا تھا۔ Claude Desktop اور وہ ٹولز جو کسی CLI binary کے absolute path کے ساتھ configured ہوں، switch کی پیروی نہیں کرتے۔ ایک واضح `CLAUDE_CONFIG_DIR`، `CODEX_HOME` یا `GROK_HOME` منتخب شدہ account پر ترجیح لیتا ہے۔

### Crash کی تشخیص

Omarchy process crashes کے لیے systemd-coredump پر نظر رکھتا ہے۔ جب کوئی چیز segfault کرتی ہے، تو آپ کو «Process crashed» اطلاع ملے گی — اس پر click کریں، اور crash آپ کے ڈیفالٹ ایجنٹ کے حوالے کر دیا جاتا ہے Omarchy کی diagnose-crash skill کے ساتھ، جو ایجنٹ کو core dump سے حقائق قائم کرنے اور یہ فیصلہ کرنے کے مراحل سے گزارتی ہے کہ آیا crash کی اطلاع upstream دینا مناسب ہے۔ آپ اسے `coredumpctl list` سے کسی بھی PID کے خلاف `omarchy agent crash <pid>` کے ساتھ ہاتھ سے بھی چلا سکتے ہیں۔

یہ نگرانی بطور ڈیفالٹ فعال ہے۔ اسے _Trigger > Toggle > Crash Capture_ کے تحت (یا `omarchy toggle crash-capture` کے ساتھ) بند کریں اور اطلاعات رک جاتی ہیں؛ `omarchy agent crash <pid>` ہاتھ سے پھر بھی کام کرتا ہے۔

Crashes کو ایک وقت میں ایک program کے حساب سے بھی خاموش کیا جا سکتا ہے، جو تشخیص آپ کو آخر میں پیش کرتی ہے۔ `omarchy crash mute hyprland` صرف اس program کے لیے اطلاعات روکتا ہے، `omarchy crash mute hyprland off` انہیں واپس لاتا ہے، اور اکیلا `omarchy crash mute` وہ فہرست دکھاتا ہے جو آپ نے mute کی ہے۔ یہ binary کے path کو اس کے نام کی طرح خوشی سے قبول کرتا ہے، لہٰذا `omarchy crash mute /usr/bin/hyprland` بھی وہی کام کرتا ہے۔ کسی ایسے نام کو جس میں space ہو quote کریں، جیسے `omarchy crash mute 'Some App'`۔ باقی سب کچھ پھر بھی مطلع کرتا ہے، اور muted program پھر بھی crash ہوتا ہے — یہ یاد دہانی کو چھپاتا ہے، یہ کچھ ٹھیک نہیں کرتا۔

### Desktop apps

_Install > AI_ menu میں چند graphical AI ایپس بھی ہیں: ChatGPT desktop app، Claude desktop app (Anthropic کا Linux beta، Chat، Cowork اور Claude Code tabs کے ساتھ)، xAI کے ماڈلز کے ساتھ گفتگو کے لیے Grok Bot، Hermes Desktop، OpenClaw، Perplexity desktop app، اور T3 Code۔ Grok Bot desktop chat ایپ ہے۔ کوڈنگ ایجنٹ `grok` کمانڈ ہے۔

Hermes Desktop کے بارے میں جاننا ضروری ہے، کیونکہ ایک مشین میں ایک Hermes ہوتا ہے، اور وہ ایپ کا ہوتا ہے: Hermes ہمیشہ صرف ایپ کے ذریعے انسٹال ہوتا ہے، اور جو `hermes` کمانڈ ڈیفالٹ ایجنٹ چلاتا ہے وہ ایپ کی ہوتی ہے۔ Hermes کو ڈیفالٹ ایجنٹ کے طور پر منتخب کرنا وہی چیز انسٹال کرتا ہے جو _Install > AI_ entry کرتی ہے: package، اور `~/.hermes` کے تحت ایک Hermes runtime جو Hermes کے اپنے انسٹالر کے ذریعے ترتیب دیا گیا ہو، جس میں پہلی بار چند منٹ لگتے ہیں۔ وہ runtime وہی ایک Hermes ہے جسے terminal کی `hermes` کمانڈ، ڈیفالٹ ایجنٹ اور ایپ سب استعمال کرتے ہیں، اور یہ Omarchy ریلیز کا انتظار کرنے کے بجائے `hermes update` کے ساتھ خود کو اپ ڈیٹ کرتا ہے۔ اسے انسٹال کرنے سے Hermes کو Omarchy تھیم بطور skin بھی ملتی ہے جس کا نام `omarchy` ہے، جس کی پیروی ہر Hermes surface تھیمز بدلنے کے ساتھ کرتی ہے؛ اگر آپ نہ چاہیں کہ ایسا ہو تو Hermes کی Appearance settings کے تحت یا `/skin` کے ساتھ کوئی اور منتخب کریں، اور Omarchy اس انتخاب کو چھوڑ دیتا ہے۔ _Remove > AI_ کے تحت ایپ کو ہٹانے سے پہلے Hermes بند ہو جاتا ہے، gateway سمیت، وہ runtime اس کے ساتھ لے جاتا ہے، اور آپ کی chats، memories اور وہ skills جو Hermes نے خود اپنے لیے لکھی تھیں برقرار رکھتا ہے الا یہ کہ آپ اسے دوسری صورت کہیں: یہ پوچھتا ہے، بطور ڈیفالٹ نہیں پر، کہ آیا وہ data اور آپ کی connection settings بھی چلی جانی چاہئیں۔

OpenClaw کا desktop تجربہ اس کا Control UI ہے، جو اپنے مقامی gateway کی پشت پناہی سے ایک web app کے طور پر کھلتا ہے۔ OpenClaw `~/.openclaw` میں رہتا ہے اور خود کو اپ ڈیٹ کرتا ہے: Control UI کا «Update Gateway» بٹن استعمال کریں یا `openclaw update` چلائیں، اور gateway نئے ورژن پر دوبارہ شروع ہو جاتا ہے۔ Omarchy صرف وہ ریلیز منتخب کرتا ہے جس سے ایک نیا انسٹال شروع ہوتا ہے۔ _Remove > AI_ کے تحت OpenClaw کو ہٹانے سے gateway service اور ایپ اس کے ساتھ چلی جاتی ہے اور پھر پوچھا جاتا ہے کہ آیا `~/.openclaw` بھی چلا جانا چاہیے، کیونکہ اس میں خود OpenClaw اور اس کے download کیے گئے plugin runtimes کے ساتھ آپ کی chats اور credentials بھی ہوتے ہیں؛ بطور ڈیفالٹ یہ اسے برقرار رکھتا ہے، اور OpenClaw کو دوبارہ انسٹال کرنے سے یہ اسے دوبارہ اٹھا لیتا ہے۔

T3 Code کسی package کے بجائے `~/.local/share/t3code` میں اپنی سرکاری AppImage ریلیز سے چلتا ہے، لہٰذا یہ خود کو اپ ڈیٹ کرتا ہے۔ اسے انسٹال کرنے پر پوچھا جاتا ہے کہ Stable یا Nightly channel پر شروع کرنا ہے؛ بعد میں T3 Code کی settings میں switch کریں۔ آپ کے threads اور settings `~/.t3` میں رہتے ہیں، اور _Remove > AI_ کے تحت T3 Code کو ہٹانے سے وہ اس کے ساتھ چلے جاتے ہیں۔

### مقامی LLMs

Omarchy مقامی LLM ماڈلز چلانے کے دو طریقے تجویز کرتا ہے: LM Studio اور Ollama۔ LM Studio open-weight ماڈلز تلاش کرنے، انہیں انسٹال کرنے اور انہیں چلانے کے لیے ایک GUI interface فراہم کرتا ہے۔ آسانی سے شروع کرنے کا یہ ایک بہترین طریقہ ہے۔ Ollama اسی طرح کرنے کے لیے ایک CLI پیش کرتا ہے۔ لیکن اگر آپ مقامی ماڈلز میں نئے ہیں، تو میں LM Studio سے شروع کروں گا۔ آپ Omarchy Menu میں _Install > AI_ کے تحت دونوں میں سے کوئی بھی انسٹال کر سکتے ہیں۔

### Omarchy Skill

Agent skills AI کو مخصوص ٹولز کو مخصوص طریقے سے استعمال کرنے میں مدد دیتی ہیں، اور Omarchy system کو حسب ضرورت بنانے کے لیے ایک ڈیفالٹ skill کے ساتھ آتا ہے۔ جیسے آپ کی Hyprland config میں ردوبدل کرنا، bar کو adjust کرنا، یا یہاں تک کہ شروع سے ایک نئی تھیم بنانا۔ یہ Claude Code (`~/.claude/skills`)، Codex (`~/.codex/skills`)، Pi (`~/.pi/agent/skills`)، Antigravity (`~/.gemini/config/skills`)، Hermes (`~/.hermes/skills` اور ہر `~/.hermes/profiles/*/skills`)، اور عام `~/.agents/skills` مقام کے لیے skill directories میں symlinked ہے، لہٰذا زیادہ تر harnesses اسے خود بخود اٹھا لیتے ہیں۔

لیکن آپ کو اس skill کو تجرباتی سمجھنا چاہیے۔ مختلف ماڈلز اسے مختلف اثر کے ساتھ استعمال کریں گے۔ بہتر ہے کہ پہلے اسے plan mode میں چلائیں، تاکہ آپ کو اندازہ ہو کہ ایجنٹ کیا بدلنا چاہے گا۔ اور پھر تبدیلیوں کو rollback کرنے یا یہاں تک کہ `omarchy reinstall configs` چلانے کے لیے تیار رہیں، اگر ایجنٹ ہر چیز کا ستیاناس کر دے۔
