### ایجنٹس کو انسٹال اور اپ ڈیٹ کرنا

Hermes اور OpenClaw کے علاوہ، یہ ایجنٹس mise کی سست انسٹالیشن استعمال کرتے ہیں: پہلی لانچ پر CLI انسٹال ہوتا ہے، اور بعد کی لانچز اسی کو دوبارہ استعمال کرتی ہیں۔ mise کسی انسٹال شدہ ایجنٹ کے نئے ریلیز کی جانچ بھی زیادہ سے زیادہ ہر چار گھنٹے میں ایک بار کرتا ہے، شروع ہونے سے عین پہلے یا پس منظر میں شیل پرامپٹ پر۔ اگر وہ اپ ڈیٹ ناکام ہو جائے یا آپ آف لائن ہوں تو انسٹال شدہ ورژن چلتا ہے۔ `omarchy update` باقی Omarchy کے ساتھ انسٹال شدہ ایجنٹس کو بھی اپ ڈیٹ کرتا ہے، اور `mup` صرف mise کے زیر انتظام ٹولز کو اپ ڈیٹ کرتا ہے۔

کسی ایجنٹ کا اپنا اپ ڈیٹر، جیسے `claude update`، `codex update`، یا کسی ایپ میں اپ ڈیٹ بٹن، mise کے زیر انتظام انسٹال کو اپ ڈیٹ نہیں کرتا۔ `codex update` ناکام ہو جاتا ہے، اور `claude update` کامیابی کی رپورٹ دے کر ایک الگ کاپی انسٹال کر سکتا ہے جسے mise ٹریک نہیں کرتا۔ اگر آپ اس کے بجائے کسی ایجنٹ کا اپنا انسٹالر اور اپ ڈیٹر استعمال کرنا چاہتے ہیں تو اسے `disable_tools` میں شامل کریں؛ دیکھیں [پہلے سے انسٹال شدہ CLI ٹولز](18-development-tools.md#preinstalled-cli-tools)۔

تمام کنفیگر شدہ سست ٹولز کو ضرورت پڑنے سے پہلے انسٹال کرنے کے لیے `mise install --include-lazy` چلائیں۔ اس میں ایجنٹس کے ساتھ Omarchy کے دیگر ڈیفالٹ CLI ٹولز بھی شامل ہیں۔ کسی ایک ٹول کو انسٹال کرنے یا اپنی انسٹالیشن استعمال کرنے کے لیے دیکھیں [پہلے سے انسٹال شدہ CLI ٹولز](18-development-tools.md#preinstalled-cli-tools)۔

`grok` mise کے فرسٹ پارٹی `grok` پیکیج کے ذریعے انسٹال ہوتا ہے، اسی طرح جیسے `claude` اور `codex`۔ `grok` چلائیں، یا اسے _Agent > Harness_ کے تحت منتخب کریں۔ x.ai پر موجود `curl | bash` انسٹالر کو چھوڑ دیں۔ وہ راستہ `~/.grok/bin` میں دوسری کاپی رکھ دیتا ہے، اسے `PATH` کے شروع میں شامل کر دیتا ہے، اور Omarchy کے ریپر کو اوور رائٹ کر دیتا ہے۔

`dsh` اپنا براؤزر UI `127.0.0.1:3080` پر کھولتا ہے، جس میں لانچ ڈائریکٹری اس کی ڈیفالٹ ورک اسپیس ہوتی ہے۔ اس کا براؤزر UI کوئی ابتدائی پرامپٹ نہیں لیتا، لہٰذا `omarchy agent prompt` اسے اس پرامپٹ کے ساتھ کھولتا ہے جو آپ کے کلپ بورڈ پر چسپاں کرنے کے لیے موجود ہوتا ہے۔ Omarchy اسے DeepSeek کے بغیر منظوری والے اجازت پری سیٹ کے ساتھ شروع کرتا ہے۔ جب آپ اس کا آفیشل ماڈل API استعمال کرتے ہیں تو DeepSeek Harness سیشن لاگز DeepSeek کو اپ لوڈ کرتا ہے؛ اسے اس کے براؤزر UI میں _Settings > General > Upload Session Log_ کے تحت بند کر دیں۔ آپ جو فیڈبیک اسے بھیجتے ہیں وہ بھی سیشن کے ساتھ اپ لوڈ ہو جاتا ہے، الا یہ کہ آپ اسے `DSH_TELEMETRY_MODE=DISABLED` کے ساتھ شروع کریں۔

### ڈیفالٹ ایجنٹ

اپنا ڈیفالٹ ایجنٹ `omarchy default agent <name>` کے ساتھ یا Omarchy Menu (`Super + Space`) میں _Agent > Harness_ کے تحت منتخب کریں۔ اگر ایجنٹ ابھی انسٹال نہیں ہے تو اسے منتخب کرنے پر پہلے وہ انسٹال ہو جاتا ہے، اور اسے ایپ لانچر میں Agent کے ساتھ اس کا اپنا لانچر بھی مل جاتا ہے۔ نئی Omarchy ایک بار کی اطلاع کے ذریعے آپ کو یہ انتخاب کرنے کی دعوت دے گی۔

Claude کو منتخب کرنے پر Chromium، Chrome، Brave، Brave Origin اور Edge کے لیے اس کی براؤزر ایکسٹینشن سیٹ اپ کرنے کی بھی کوشش کی جاتی ہے۔ ایکسٹینشن سیٹ اپ تمام صارفین پر لاگو ہوتا ہے اور آپ سے آپ کا سسٹم پاس ورڈ مانگ سکتا ہے؛ منسوخ کرنے یا ایکسٹینشن انسٹال ناکام ہونے پر بھی Claude منتخب اور لانچ ہو جاتا ہے۔ اپنا براؤزر دوبارہ شروع کریں، کہا جائے تو ایکسٹینشن فعال کریں، اور اسے جوڑنا مکمل کرنے کے لیے Claude میں سائن ان کریں۔ کنکشن جانچنے کے لیے Claude میں `/chrome` چلائیں۔ Firefox اور Zen اس ایکسٹینشن کی حمایت نہیں کرتے۔ اگر یہ سیٹ اپ شامل ہونے سے پہلے ہی Claude آپ کا ڈیفالٹ تھا تو ایکسٹینشن انسٹال کرنے کے لیے اسے دوبارہ منتخب کریں۔

انتخاب مکمل ہونے کے بعد، `Super + Shift + Ctrl + A` ڈیفالٹ ایجنٹ کو ایک مخصوص ٹرمینل ونڈو میں لانچ کرتا ہے (یا اگر آپ نے ابھی انتخاب نہیں کیا تو پکر سامنے لاتا ہے)۔ آپ اسے `omarchy agent prompt "Review this project"` کے ساتھ براہ راست کسی کام میں بھی لانچ کر سکتے ہیں۔ Freebuff اور DeepSeek Harness کوئی ابتدائی پرامپٹ نہیں لیتے، لہٰذا وہ اس کے بجائے پرامپٹ کو آپ کے کلپ بورڈ پر رکھ کر کھلتے ہیں تاکہ آپ اسے چسپاں کر سکیں۔ اس طرح لانچ کیے گئے ایجنٹس اپنے متعلقہ رکنے اور پوچھنے کے بغیر والے موڈز میں بغیر نگرانی چلتے ہیں، لہٰذا تیار رہیں کہ وہ واقعی کچھ کر گزریں گے! MiniMax Code کے انٹرایکٹو سیشنز کے لیے ایسا کوئی موڈ نہیں ہے، لہٰذا وہ معمول کے مطابق اجازتیں مانگتا ہے۔ اور چونکہ ایجنٹس آپ کی ہوم ڈائریکٹری کے لیے اعتماد یاد رکھنے سے انکار کرتے ہیں، اس لیے `$HOME` سے لانچز اس کے بجائے `~/Work` میں شروع ہوتی ہیں۔

ٹرمینل شارٹ کٹس بھی ہیں: `a` موجودہ ٹرمینل میں ڈیفالٹ ایجنٹ کو ان لائن چلاتا ہے، جبکہ `c`، `cx` اور `cy` OpenCode، Claude Code اور Codex کو براہ راست شروع کرتے ہیں (ایک بار پھر ان کے خودکار منظوری والے موڈز میں)۔ تھیم کی تبدیلیاں ایجنٹس کے ساتھ بھی ہم آہنگ ہو جاتی ہیں: جب آپ Omarchy تھیم تبدیل کرتے ہیں تو Claude Code، Pi، OpenCode اور Hermes (جب Omarchy اسے انسٹال کر لے) سب اس کے ساتھ بدل جاتے ہیں۔

### آپ کی ایجنٹ ہدایات

ہر ایجنٹ کے لیے ذاتی اصول `~/.agents/AGENTS.md` میں جاتے ہیں، `~/.agents/skills` میں مشترکہ اسکلز کے ساتھ۔ اسے _Agent > Instructions_ کے تحت کھولیں، جو اسے ہر اس ہارنس میں بھی لنک کر دیتا ہے جو اپنی عالمی فائل رکھتا ہے: `~/.claude/CLAUDE.md`، `~/.codex/AGENTS.md`، `~/.pi/agent/AGENTS.md`، `~/.config/opencode/AGENTS.md`، Copilot کی `~/.copilot/copilot-instructions.md`، وغیرہ۔ Crush اور Amp `~/.config/AGENTS.md` لنک پڑھتے ہیں، جبکہ omp، Kimi اور DeepSeek Harness براہ راست `~/.agents/AGENTS.md` پڑھتے ہیں۔ ڈیفالٹ ایجنٹ منتخب کرنے پر وہ بھی لنک ہو جاتا ہے۔ اگر آپ کے پاس پہلے سے کوئی ہدایات فائل تھی اور ابھی کوئی مشترکہ فائل نہیں تھی تو وہی مشترکہ بن جاتی ہے؛ بصورت دیگر اسے لنک کے ساتھ `.bak` کے طور پر رکھا جاتا ہے۔ ایک اور ایجنٹ انسٹال کرنے کے بعد دوبارہ لنک کرنے کے لیے `omarchy agent instructions` چلائیں۔

### ایجنٹس پینل

ٹاپ بار میں ایجنٹس کا آئیکن ہے۔ ایجنٹ سیٹ اپ کرنے سے پہلے، اس کا پینل آپ کو Claude، Codex یا Grok میں سائن ان کرنے کے مراحل سے گزارتا ہے، اور ان میں سے پہلا آپ کا ڈیفالٹ ایجنٹ بن جاتا ہے۔ اس کے بعد، پینل ہر سبسکرپشن کو ایک صفحے پر رکھتا ہے: ہر ایجنٹ اور اکاؤنٹ اس کے پلان کے ساتھ، اس کی 5 گھنٹے کے سیشن اور ہفتہ وار حدود میں سے ہر ایک کے لیے ایک میٹر جس میں ری سیٹ ہونے تک کا وقت دکھایا جاتا ہے (درست فیصد کے لیے ہوور کریں)، یا باقی ماندہ پری پیڈ بیلنس، اس لائن کے تحت جو آپ کے ان سب میں استعمال کی گئی چیزوں کے درمیان گھومتی ہے، جیسے اس ہفتے کے ٹوکنز اور آپ کا سب سے زیادہ استعمال شدہ ماڈل۔ _Make something cool_ کے تحت یہ نئی تھیم، پلگن، ایپ یا گیم کے لیے ابتدائی پرامپٹس پیش کرتا ہے جو کام آپ کے ڈیفالٹ ایجنٹ کے حوالے کر دیتے ہیں۔ ایپس اسی طرح بنائی جاتی ہیں جیسے Omarchy کی اپنی Hype، Monologue اور Omacut ہیں، C++ اور Qt Quick میں، omarchy-make-app ایجنٹ اسکل کی پیروی کرتے ہوئے، اور انہیں درکار کمپائلر اور Qt اجزا انسٹال شدہ آتے ہیں۔ گیمز `~/Games/vibes` میں ایک واحد three.js صفحہ ہوتی ہیں، omarchy-make-game ایجنٹ اسکل کی پیروی کرتے ہوئے، اور سب موجودہ تھیم میں ایک Game Vibes لانچر سے کھلتی ہیں؛ وہ ویب سے three.js لوڈ کرتی ہیں، لہٰذا شروع ہونے کے لیے انہیں کنکشن درکار ہوتا ہے۔ Claude Code، Codex، Grok، Kimi، Cursor اور اس کا Grok Bot الاؤنس، GitHub Copilot، Muse، Antigravity اور Devin اپنی حدود کے ساتھ ابتدا ہی سے شامل ہیں، Kimchi اپنے پلان، پری پیڈ کریڈٹس اور اخراجات کے بجٹس کے ساتھ، اور Hermes، Mistral Vibe اور Qwen Code استعمال کرنے کے بعد اپنے سیشنز اور ٹوکنز دکھاتے ہیں۔ pi، omp یا opencode کے ذریعے استعمال کیے جانے والے پرووائیڈر پلانز اور کیز بھی ظاہر ہوتی ہیں: OpenCode Zen اور Go، Z.ai GLM Coding Plan، Ollama Cloud، MiniMax Token Plan اور Synthetic اپنی حدود کے ساتھ؛ OpenRouter اور DeepSeek اپنے پری پیڈ بیلنسز کے ساتھ؛ Fireworks پچھلے 30 دن کے اخراجات کے ساتھ۔ اپنے ہارڈویئر پر چلائے جانے والے ماڈلز کے ٹوکنز بھی کُل میں شمار ہوتے ہیں؛ خود ماڈلز کا اپنا پینل ہے، جو [لوکل ماڈلز](#local-models) کے تحت بیان کیا گیا ہے۔ ہر ایجنٹ ایک بار شمار ہوتا ہے، اسی کے تحت جو اس کا بل دیتا ہے، چاہے آپ اسے کتنے ہی ہارنسز کے ذریعے چلائیں۔

پینل کے لیے بار آئیکن پر بائیں کلک کریں یا `Super + Ctrl + X` دبائیں، اپنے ڈیفالٹ ایجنٹ کو لانچ کرنے کے لیے دائیں کلک کریں، اور تازہ کاری کے لیے درمیانی کلک کریں۔ اس کے پیچھے موجود استعمال کے ریکارڈز ہر 15 منٹ بعد `omarchy agent usage update` کے ذریعے دوبارہ بنائے جاتے ہیں، اور پینل ایک ہم آہنگ فولڈر کے ذریعے آپ کی دیگر مشینوں کے استعمال کو بھی ضم کر سکتا ہے۔ مکمل ترتیبات کے لیے `$OMARCHY_PATH/shell/plugins/agents/` کے تحت README دیکھیں۔

### متعدد سبسکرپشنز

اگر آپ ایک سے زیادہ Claude، Codex یا Grok پلان کی ادائیگی کرتے ہیں — مثلاً ایک ذاتی Max اور ایک کام کا — تو Omarchy ان سب کو سائن ان رکھ سکتا ہے اور ان کے درمیان منتقل ہو سکتا ہے۔ ایجنٹس پینل میں + کے ساتھ سبسکرپشن شامل کریں، جو آپ کو وہیں اس عمل سے گزارتا ہے، یا `omarchy agent account add claude Work` (یا `codex`، یا `grok`) کے ساتھ۔ اگر CLI موجود نہ ہو تو یہ اسے انسٹال کر دیتا ہے۔ کسی پرووائیڈر کے لیے پہلا اکاؤنٹ آپ کے عام براؤزر کے ذریعے سائن ان ہوتا ہے، عین وہیں جہاں CLI ہمیشہ دیکھتا ہے۔ اس کے بعد ہر اکاؤنٹ ایک نجی ونڈو کے ذریعے سائن ان ہوتا ہے، تاکہ آپ کا براؤزر جس اکاؤنٹ میں پہلے سے سائن ان ہے وہ غلطی سے نہ پکڑا جائے؛ وہاں اس اکاؤنٹ کے طور پر سائن ان کریں جسے آپ شامل کر رہے ہیں، اور پہلے سے کھلی کوئی نجی ونڈو پہلے بند کر دیں۔ اس کے لیے کبھی CLI سے لاگ آؤٹ نہ ہوں: لاگ آؤٹ کرنے سے محفوظ شدہ سائن ان منسوخ ہو جاتا ہے، اور اس اکاؤنٹ کو دوبارہ شامل کرنا پڑے گا۔

اپنی سبسکرپشن لاگ انز کو SSH کے ذریعے کسی دوسری Omarchy مشین پر نقل کرنے کے لیے `omarchy agent account copy user@laptop` چلائیں۔ جب منزل پر کوئی انسٹال شدہ نہ ہو تو بھیجنے والا ایک عارضی وصول کنندہ فراہم کرتا ہے، لہٰذا پرانی Omarchy مشینیں بغیر اپ ڈیٹ کے اکاؤنٹس وصول کر سکتی ہیں۔ انسٹال شدہ وصول کنندگان کو ترجیح حاصل ہوتی ہے۔ یہ تمام Claude، Codex اور Grok سبسکرپشنز نقل کرتا ہے؛ انہیں منتخب کرنے کے لیے پرووائیڈر کے نام شامل کریں، جیسے `omarchy agent account copy laptop claude`۔ اکاؤنٹ کے نام اور کمانڈ IDs ماخذ سے میل کھاتے ہیں، بشمول وہ اکاؤنٹس جو منزل پر پہلے سے موجود ہیں۔ غیر متعلقہ منزل اکاؤنٹس کو اگر ان کے ناموں میں تصادم ہو تو عددی لاحقہ مل جاتا ہے، اور ترتیبات، اسکلز، پلگنز اور گفتگو کی تاریخ ہر مشین پر مقامی رہتی ہے۔

منزل کی موجودہ اسناد برقرار رکھی جاتی ہیں۔ کوئی ماخذ اکاؤنٹ جو وہاں پہلے سے سائن ان ہے اس کا نام اس کی اسناد کو بدلے بغیر ہم آہنگ کر دیا جاتا ہے؛ دیگر اکاؤنٹس اس کے ساتھ شامل کر دیے جاتے ہیں۔ میل کھاتے اکاؤنٹس کے لیے محفوظ شدہ اسناد کو تبدیل کرنے کے لیے، منزل پر اس اکاؤنٹ کے سیشنز بند کرنے کے بعد `omarchy agent account copy --replace laptop claude` استعمال کریں۔ نئی منزل کو ماخذ کا فعال اکاؤنٹ اور تبدیلی کی ترجیحات بھی ملتی ہیں؛ قائم شدہ منزل اپنی ترجیحات برقرار رکھتی ہے۔

اسناد SSH کے ذریعے سفر کرتی ہیں اور منزل پر نجی فائلوں میں محفوظ ہوتی ہیں، لہٰذا صرف ان مشینوں پر نقل کریں جن پر آپ اعتماد کرتے ہیں۔ یہ ایک بار کی نقل ہے، جاری ہم آہنگی نہیں۔ Codex ریفریش ٹوکنز کسی دوسری مشین کے ذریعے تبدیل کیے جا سکتے ہیں، جس سے نقل شدہ لاگ ان کو تجدید کی ضرورت پڑ سکتی ہے؛ متعدد مشینوں پر بیک وقت استعمال کے لیے الگ سائن انز سب سے قابل اعتماد انتخاب رہتے ہیں۔ دیکھیں [Codex کی اکاؤنٹ تصدیق کی رہنمائی](https://developers.openai.com/codex/auth/ci-cd-auth)۔

ہر پرووائیڈر کے لیے ایک اکاؤنٹ فعال ہوتا ہے، اور ہر نیا سیشن اسی کے طور پر شروع ہوتا ہے: `cx`، `cy`، سادہ `claude`، `codex` یا `grok`، `omarchy agent` کے ذریعے لانچ کی گئی کوئی بھی چیز، اور اسکرپٹس یا ایڈیٹرز جو `PATH` پر CLI تلاش کرتے ہیں۔ `omarchy agent account use work` کے ساتھ تبدیل کریں (اور `omarchy agent account use main` کے ساتھ واپس)، یا پینل میں کسی اکاؤنٹ کا نمبر دبا کر پھر `Enter` دبائیں (یا اس کے Use بٹن پر کلک کریں)۔ چلتے ہوئے Claude سیشنز بھی اپنے اگلے پیغام سے تبدیل ہو جاتے ہیں: ہر Claude سیشن `~/.claude` میں چلتا ہے، جس میں ہمیشہ فعال اکاؤنٹ کا سائن ان ہوتا ہے۔ پرانی Omarchy کے ذریعے کسی اکاؤنٹ کے اپنے فولڈر میں شروع کیا گیا Claude سیشن بند ہونے تک وہی سائن ان رکھتا ہے، لہٰذا تبدیلی ان سیشنز کا نام لیتی ہے اور ان کے ختم ہوتے ہی خود مکمل ہو جاتی ہے۔ چلتے ہوئے Codex اور Grok سیشنز اسی اکاؤنٹ پر رہتے ہیں جس سے وہ شروع ہوئے تھے۔ گفتگو کی تاریخ، ترتیبات، اسکلز اور پلگنز اکاؤنٹس کے درمیان مشترکہ ہیں، لہٰذا اسی فولڈر میں `claude --continue` نئے اکاؤنٹ پر وہیں سے جاری رہتا ہے جہاں آپ نے چھوڑا تھا۔

ایک سے زیادہ اکاؤنٹ ہونے پر، پینل ہر اکاؤنٹ کی حدود ساتھ ساتھ دکھاتا ہے، فعال کو نشان زد کر کے۔ جب فعال اکاؤنٹ کسی حد کے 95% سے تجاوز کرتا ہے تو Omarchy آپ کو مطلع کرتا ہے، اور اطلاع پر کلک کرنے سے سب سے زیادہ گنجائش والے اکاؤنٹ پر منتقل ہو جاتا ہے۔ یہ کبھی خود سے تبدیل نہیں ہوتا۔ حد کو `omarchy agent account threshold 90` کے ساتھ تبدیل کریں۔ اگر ہر اکاؤنٹ حد سے اوپر ہو تو آپ کو ایک بار اس کی اطلاع ملے گی، اس کے ساتھ کہ کون سا اکاؤنٹ سب سے پہلے خالی ہوتا ہے۔ جب کوئی فعال اکاؤنٹ اپنی حد کے 15 پوائنٹس کے اندر ہو (ڈیفالٹ پر 80%) تو اس کی حدود ہر 15 کے بجائے ہر تین منٹ بعد جانچی جاتی ہیں۔

`omarchy agent account list` ہر اکاؤنٹ اور اس کی تازہ ترین حدود دکھاتا ہے، `omarchy agent account remove work` ایک کو بھلا دیتا ہے، اور `omarchy agent account rename primary Hey` ایک کا نام بدل دیتا ہے (یا پینل میں کسی اکاؤنٹ کے نام پر کلک کریں)۔ یہ کمانڈز آپ کے ڈیفالٹ ایجنٹ کے اکاؤنٹس پر کام کرتی ہیں؛ دوسرے پرووائیڈر تک پہنچنے کے لیے پہلے اس کا نام لیں، جیسے `omarchy agent account use codex side`۔ `~/.claude` یا `~/.codex` میں آپ کا پہلے سے موجود لاگ ان _Main_ اکاؤنٹ ہے۔ Codex کا وہیں رہتا ہے جہاں وہ ہے؛ Claude کا اس وقت اپنے فولڈر میں انتظار کرتا ہے جب کوئی دوسرا اکاؤنٹ فعال ہوتا ہے۔ تقریباً آٹھ گھنٹے سے زیادہ عرصے تک غیر استعمال شدہ اکاؤنٹ _Sign-in required_ دکھا سکتا ہے؛ اس اکاؤنٹ میں دوبارہ سائن ان کرنے کے لیے پینل میں ہی اس پر کلک کریں، یا اس پر منتقل ہو کر سیشن شروع کریں، جو سائن ان کو خود تازہ کر دیتا ہے۔ `claude mcp add` کے ساتھ شامل کیے گئے MCP سرورز ہر Claude اکاؤنٹ تک پہنچتے ہیں، کیونکہ وہ سب `~/.claude` میں چلتے ہیں؛ Codex اور Grok کے لیے، اکاؤنٹ شامل کرتے وقت آپ کے پاس موجود سرورز اس کے ساتھ آ جاتے ہیں، لیکن بعد والے صرف اسی اکاؤنٹ تک پہنچتے ہیں جس میں آپ نے انہیں شامل کیا تھا۔ Claude Desktop اپنا سائن ان خود رکھتا ہے، اور CLI بائنری کے مطلق راستے کے ساتھ کنفیگر شدہ Codex یا Grok ٹولز تبدیلی کی پیروی نہیں کرتے۔ واضح `CLAUDE_CONFIG_DIR`، `CODEX_HOME` یا `GROK_HOME` منتخب اکاؤنٹ پر فوقیت رکھتا ہے۔

### کریش کی تشخیص

Omarchy عمل کے کریشز کے لیے systemd-coredump پر نظر رکھتا ہے۔ ڈیفالٹ ایجنٹ منتخب کرنے کے بعد، آپ کا کوئی بھی پروگرام جو core ڈمپ کرے وہ "Process crashed" اطلاع لاتا ہے — اس پر کلک کریں، اور کریش آپ کے ڈیفالٹ ایجنٹ کے حوالے کر دیا جاتا ہے Omarchy کی omarchy-diagnose-crash اسکل کے ساتھ، جو ایجنٹ کو core ڈمپ سے حقائق قائم کرنے اور یہ فیصلہ کرنے کے مراحل سے گزارتی ہے کہ آیا کریش اوپر رپورٹ کرنے کے قابل ہے۔ آپ اسے `coredumpctl list` سے کسی بھی PID کے خلاف `omarchy agent crash <pid>` کے ساتھ دستی طور پر بھی چلا سکتے ہیں۔

نگرانی بطور ڈیفالٹ آن ہوتی ہے۔ اسے _Trigger > Toggle > Crash Capture Off_ کے تحت (یا `omarchy toggle crash-capture` کے ساتھ) بند کر دیں تو اطلاعات رک جاتی ہیں؛ `omarchy agent crash <pid>` دستی طور پر پھر بھی کام کرتا ہے۔

کریشز کو ایک وقت میں ایک پروگرام کے لیے خاموش بھی کیا جا سکتا ہے، جو تشخیص آخر میں آپ کو پیش کرتی ہے۔ `omarchy crash mute hyprland` صرف اس پروگرام کے لیے اطلاعات روک دیتا ہے، `omarchy crash mute hyprland off` انہیں واپس لاتا ہے، اور اکیلا `omarchy crash mute` وہ فہرست دکھاتا ہے جو آپ نے خاموش کی ہے۔ یہ بائنری کے راستے کو بھی اس کے نام کی طرح خوشی سے قبول کرتا ہے، لہٰذا `omarchy crash mute /usr/bin/hyprland` بھی وہی کام کرتا ہے۔ جس نام میں جگہ ہو اسے اقتباس میں رکھیں، جیسے `omarchy crash mute 'Some App'`۔ باقی سب کچھ پھر بھی مطلع کرتا ہے، اور خاموش کیا گیا پروگرام پھر بھی کریش ہوتا ہے — یہ یاد دہانی کو چھپاتا ہے، یہ کچھ ٹھیک نہیں کرتا۔

### ڈیسک ٹاپ ایپس

_Install > AI_ مینو میں چند گرافیکل AI ایپس بھی ہیں: Amp Desktop، Antigravity Desktop، ChatGPT ڈیسک ٹاپ ایپ، Claude ڈیسک ٹاپ ایپ (Anthropic کا Linux بیٹا، Chat، Cowork اور Claude Code ٹیبز کے ساتھ)، xAI کے ماڈلز کے ساتھ چیٹ کے لیے Grok Bot، Herdr Desktop، Hermes Desktop، OpenClaw، Perplexity ڈیسک ٹاپ ایپ، اور T3 Code۔ Grok Bot ڈیسک ٹاپ چیٹ ایپ ہے۔ کوڈنگ ایجنٹ `grok` کمانڈ ہے۔

Hermes Desktop وہ ہے جس کے بارے میں جاننا ضروری ہے، کیونکہ کسی مشین پر ایک Hermes ہوتا ہے، اور وہ ایپ کا ہوتا ہے: Hermes ہمیشہ صرف ایپ کے ذریعے انسٹال ہوتا ہے، اور ڈیفالٹ ایجنٹ جو `hermes` کمانڈ چلاتا ہے وہ ایپ کی ہوتی ہے۔ Hermes کو ڈیفالٹ ایجنٹ کے طور پر منتخب کرنا وہی چیز انسٹال کرتا ہے جو _Install > AI_ اندراج کرتا ہے: پیکیج، اور Hermes کے اپنے انسٹالر کے ذریعے `~/.hermes` کے تحت سیٹ اپ کردہ Hermes رن ٹائم، جس میں پہلی بار چند منٹ لگتے ہیں۔ وہ رن ٹائم وہ واحد Hermes ہے جسے ٹرمینل `hermes` کمانڈ، ڈیفالٹ ایجنٹ اور ایپ سب استعمال کرتے ہیں، اور یہ Omarchy ریلیز کا انتظار کرنے کے بجائے `hermes update` کے ساتھ خود کو اپ ڈیٹ کرتا ہے۔ اسے انسٹال کرنے پر Hermes کو Omarchy تھیم بطور اسکن بھی مل جاتی ہے جس کا نام `omarchy` ہے، جس کی Hermes کی ہر سطح تھیمز تبدیل کرنے پر پیروی کرتی ہے؛ اگر آپ نہیں چاہتے تو Hermes کی Appearance ترتیبات میں یا `/skin` کے ساتھ کوئی اور منتخب کریں، اور Omarchy اس انتخاب کو چھوڑ دیتا ہے۔ _Remove > AI_ کے تحت ایپ کو ہٹانے پر پہلے Hermes بند ہو جاتا ہے، گیٹ وے سمیت، وہ رن ٹائم اس کے ساتھ لے جاتا ہے، اور آپ کی چیٹس، یادیں اور وہ اسکلز جو Hermes نے اپنے لیے لکھیں برقرار رکھتا ہے الا یہ کہ آپ اسے بصورت دیگر کہیں: یہ پوچھتا ہے، ڈیفالٹ کے طور پر نہیں، کہ آیا وہ ڈیٹا اور آپ کی کنکشن ترتیبات بھی جانی چاہئیں۔

OpenClaw کا ڈیسک ٹاپ تجربہ اس کا Control UI ہے، جو اپنے لوکل گیٹ وے کی پشت پناہی میں ایک ویب ایپ کے طور پر کھلتا ہے۔ OpenClaw `~/.openclaw` میں رہتا ہے اور خود کو اپ ڈیٹ کرتا ہے: Control UI کا "Update Gateway" بٹن استعمال کریں یا `openclaw update` چلائیں، اور گیٹ وے نئے ورژن پر دوبارہ شروع ہو جاتا ہے۔ Omarchy صرف وہ ریلیز منتخب کرتا ہے جس سے نئی انسٹال شروع ہوتی ہے۔ OpenClaw آپ کا ڈیفالٹ ایجنٹ بھی ہو سکتا ہے: اسے _Agent > Harness_ کے تحت منتخب کرنے پر `~/.openclaw` میں وہی کاپی سیٹ اپ ہو جاتی ہے، اور ایجنٹ اس کے گیٹ وے سے منسلک OpenClaw کا ٹرمینل UI کھولتا ہے۔ _Remove > AI_ کے تحت OpenClaw کو ہٹانے پر گیٹ وے سروس اور ایپ اس کے ساتھ جاتی ہیں اور پھر پوچھا جاتا ہے کہ آیا `~/.openclaw` بھی جانا چاہیے، کیونکہ اس میں خود OpenClaw اور اس کے ڈاؤن لوڈ کردہ پلگن رن ٹائمز کے ساتھ آپ کی چیٹس اور اسناد موجود ہوتی ہیں؛ ڈیفالٹ اسے برقرار رکھتا ہے، اور OpenClaw کو دوبارہ انسٹال کرنے پر یہ اسے واپس اٹھا لیتا ہے۔

Herdr Desktop [Herdr](https://herdr.dev) ڈیسک ٹاپ ایپ ہے: ٹرمینلز اور کوڈنگ ایجنٹس کی اسپیسز، ٹیبز اور پینز جو ونڈو بند کرنے پر اس کے کور میں چلتے رہتے ہیں۔ یہ کسی پیکیج کے بجائے Herdr کے اپنے انسٹالر سے آتی ہے، لہٰذا یہ `~/.local/share/herdr-app` میں رہتی ہے، جب آپ کے پاس پہلے سے کوئی نہ ہو تو `~/.local/bin/herdr-core` میں اپنا کور ساتھ لاتی ہے، اور دونوں خود کو اپ ڈیٹ کرتے ہیں۔ یہ اس `herdr` کمانڈ کے ساتھ بیٹھتی ہے جو Omarchy `Super + Ctrl + Return` پر فراہم کرتا ہے، اس کی جگہ لینے کے بجائے، اور اس کمانڈ کی براہ راست کیز حاصل کرتی ہے: `Alt + Return` اور `Alt + Shift + Return` کسی پین کو نیچے یا دائیں تقسیم کرتے ہیں، `Alt + Escape` اسے بند کرتا ہے، `Ctrl + Alt + Arrow` پینز کے درمیان منتقل کرتا ہے، `Alt + 1..9` اور `Alt + Left/Right` ٹیب منتخب کرتے ہیں، اور `Alt + Up/Down` اسپیسز کے درمیان منتقل کرتے ہیں۔ `Ctrl + 1..9` اسپیس منتخب کرتا ہے اور `Alt + Shift + Up/Down` ایجنٹس میں مرحلہ وار جاتا ہے۔ `Ctrl + Space` پریفکس کیز صرف ٹرمینل تک رہتی ہیں، کیونکہ ایپ کسی سلسلے کے لیے سادہ Ctrl کی نہیں پکڑ سکتی۔ Omarchy یہ `~/.config/herdr-app/keys.json` میں لکھتا ہے، اور `omarchy-refresh-herdr-app` انہیں واپس رکھ دیتا ہے۔ اسے انسٹال کرنے پر Herdr کی Omarchy تھیم منتخب ہو جاتی ہے، جو اس کے بعد آپ کی Omarchy تھیم کی پیروی کرتی ہے۔ Herdr ہلکے موڈ کے لیے ایک اور گہرے موڈ کے لیے ایک تھیم رکھتا ہے، لہٰذا گہری اور ہلکی Omarchy تھیم کے درمیان تبدیل کرنے کے بعد، دوسرے موڈ کے لیے Herdr کے تھیم پکر میں ایک بار پھر Omarchy منتخب کریں۔

T3 Code کسی پیکیج کے بجائے `~/.local/share/t3code` میں اپنی آفیشل AppImage ریلیز سے چلتا ہے، لہٰذا یہ خود کو اپ ڈیٹ کرتا ہے۔ اسے انسٹال کرنے پر پوچھا جاتا ہے کہ Stable یا Nightly چینل پر شروع کرنا ہے؛ بعد میں T3 Code کی ترتیبات میں تبدیل کریں۔ آپ کے تھریڈز اور ترتیبات `~/.t3` میں رہتی ہیں، اور _Remove > AI_ کے تحت T3 Code کو ہٹانے پر وہ اس کے ساتھ جاتی ہیں۔

### لوکل ماڈلز

اپنے کوڈنگ ایجنٹس کے لیے اپنی مشین پر کوئی اوپن ماڈل چلائیں۔ آپ کے پرامپٹس اور کوڈ مشین پر رہتے ہیں؛ ماڈل کو بھیجی گئی کوئی چیز اس سے باہر نہیں جاتی۔ اس سے شروع کریں:

```bash
omarchy models use best text
```

یہ اس مشین کے لیے بہترین ٹیکسٹ ماڈل سیٹ اپ کرتا ہے، اسی قسم کا جو آپ کے ایجنٹ استعمال کرتے ہیں۔ امیج، ویڈیو اور میوزک ماڈلز کا اپنا بہترین ہوتا ہے: `omarchy models use best image`، `video` یا `music`۔ اس مشین کے لیے ہر قسم کا انتخاب دیکھنے کے لیے `omarchy models use best` چلائیں۔

یا لوکل ماڈلز پینل کو ٹاپ بار میں ایجنٹس آئیکن کے ساتھ اس کے چمک آئیکن سے، یا Super + Ctrl + Alt + X کے ساتھ کھولیں، اور + منتخب کریں۔ آئیکن اس وقت ظاہر ہوتا ہے جب کوئی ماڈل اس مشین پر پورا اترتا ہے۔ Podman، جو ماڈلز چلاتا ہے، Omarchy کے ساتھ آتا ہے، اسی طرح NVIDIA مشین پر NVIDIA کا کنٹینر ٹول کٹ بھی، جو انہیں GPU فراہم کرتا ہے؛ اگر ان میں سے کوئی غائب ہو تو پہلا سیٹ اپ اسے انسٹال کر دیتا ہے۔ پھر Omarchy اس مشین کے لیے تجویز کردہ ماڈل منتخب کرتا ہے، اسے ڈاؤن لوڈ کرتا ہے، اور شروع کرتا ہے۔ دسیوں GB کے ڈاؤن لوڈ اور ماڈل چلتے وقت مشین کی زیادہ تر میموری کے استعمال کی توقع رکھیں: Flash Next اپنے مکمل 256K سیاق و سباق کے ساتھ تقریباً 100 GiB استعمال کرتا ہے۔ اگر دیگر ماڈلز اسے درکار میموری پر قابض ہوں تو یہ رکا ہوا سیٹ اپ ہوتا ہے، جب آپ کسی ایک کو روکیں تو شروع ہونے کے لیے تیار۔ ماڈل لاگ آؤٹ پر رک جاتا ہے؛ جب آپ کو کسی اور کام کے لیے میموری درکار ہو تو اسے خود روک دیں۔

`omarchy models list` اختیارات دکھاتا ہے اور بتاتا ہے کہ کچھ کیوں پورا نہیں اترتے۔ کوئی اور سیٹ اپ کرنے کے لیے `omarchy models use <recipe>` چلائیں۔ آج، 128 GB Strix Halo مشینوں کے لیے `qwen3.8-flash-next-gufo` اور `qwen3.8-27b-gufo` دستیاب ہیں؛ 27B تقریباً 40 GiB لیتا ہے، لہٰذا یہ دیگر کام کے لیے جگہ چھوڑتا ہے۔ Intel کے Arc B390 والے 64 GB لیپ ٹاپ پر، `qwen3.6-35b-a3b-llamacpp` تقریباً 30 GiB میں چلتا ہے۔ نئی ترکیبیں اور سفارشات پیکیج کے ذریعے `omarchy update` کے ساتھ آتی ہیں۔

آپ کے سیٹ اپ کردہ ہر ماڈل کو لوکل ماڈلز پینل میں اپنی لائن ملتی ہے: اسے شروع کرنے کے لیے پلے، اسے روکنے اور اس کی میموری خالی کرنے کے لیے پاز، اور اس پر اپنا ایجنٹ کھولنے کے لیے ٹرمینل بٹن۔ اوپر کے پار، ایک بار دکھاتا ہے کہ مشین کی میموری خود Omarchy (سسٹم اور آپ کی ایپس)، ہر چلتے ماڈل، اور خالی جگہ کے درمیان کیسے تقسیم ہے۔ رکے ہوئے ماڈل کی طرف اشارہ کریں تو بار دکھاتا ہے کہ آیا وہ پورا اترتا ہے، یا کتنا کم ہے۔ کئی ایک ساتھ چل سکتے ہیں جب وہ میموری میں ایک ساتھ پورا اتریں؛ اگر کوئی پورا نہ اترے تو Omarchy بتاتا ہے کہ کون سا چلتا ماڈل روکنا ہے۔ لائنوں کو ان کے لوگو سے کھینچ کر دوبارہ ترتیب دیں، اور ماڈل اور اس کا ڈاؤن لوڈ ہٹانے کے لیے منتخب لائن پر Delete دبائیں۔

آپ کے سیٹ اپ کردہ ہر کوڈنگ ماڈل کو ایپ لانچر میں بھی اپنا اندراج ملتا ہے، ماڈل کے نام کے تحت اور اس کے بنانے والے کے لوگو کے ساتھ، اسی طرح جیسے Claude، Codex یا Grok میں سائن ان کرنے پر ایک شامل ہو جاتا ہے۔ یہ اس ماڈل پر آپ کا ایجنٹ کھولتا ہے، اور اگر ماڈل نہ چل رہا ہو تو پہلے اسے شروع کرتا ہے: ٹرمینل اسے لوڈ ہوتا دکھاتا ہے اور تیار ہونے پر ایجنٹ کے حوالے کر دیتا ہے۔ ماڈل ہٹانے سے اس کا اندراج ہٹ جاتا ہے۔

ہر ماڈل کوڈنگ کے لیے نہیں ہوتا۔ امیج، ویڈیو اور میوزک ماڈلز اس کے بجائے Fantasi میں کھلتے ہیں، Omarchy کی ایپ جو اس مشین پر چلتے ماڈل کے ساتھ تصویریں، ویڈیو اور موسیقی بنانے کے لیے ہے، وہیں یا لوکل ماڈلز پینل میں ان کی لائن سے منتخب کیے گئے۔

کوئی ماڈل عین اسی طرح چلتا رہتا ہے جیسے اسے سیٹ اپ کیا گیا تھا، لہٰذا Omarchy اپ ڈیٹ آپ کے ایجنٹس کے نیچے کبھی اسے دوبارہ شروع نہیں کرتا۔ جب Omarchy کے پاس آپ کے سیٹ اپ کردہ ماڈل کے لیے نیا رن ٹائم یا نئے ویٹس ہوں تو اس کی لائن پر اپ ڈیٹ بٹن ظاہر ہوتا ہے: اسے دبائیں تو ماڈل پس منظر میں دوبارہ سیٹ اپ ہو جاتا ہے، صرف وہی ڈاؤن لوڈ کرتا ہے جو بدلا ہو، اور نئے ورژن پر دوبارہ شروع ہو جاتا ہے۔ جو ماڈل رکا ہوا تھا وہ رکا رہتا ہے۔ `omarchy models update` ٹرمینل سے ہر ماڈل کے لیے یہی کرتا ہے۔

کمانڈ لائن سے، `omarchy models start <recipe>` اور `omarchy models stop <recipe>` یہی کرتے ہیں، `omarchy models status` ہر ماڈل دکھاتا ہے، اور `omarchy agent --local` آپ کا ڈیفالٹ ایجنٹ کچھ بھی ہو، pi میں آخری شروع کیا گیا ماڈل کھولتا ہے۔ OpenCode اور Qwen Code بھی لوکل ماڈل استعمال کر سکتے ہیں: `omarchy models harness opencode` یا `omarchy models harness qwen` انہیں اس کے بجائے وہاں کھولتا ہے، اور `omarchy models harness pi` واپس جاتا ہے۔ pi آپ کے سیٹ اپ کردہ ہر ماڈل، اور ان مشینوں پر موجود ماڈلز جن کے ساتھ آپ نے جوڑا بنایا ہے، کو بھی اپنے ماڈل پکر میں فہرست کرتا ہے، لہٰذا سادہ `pi` بھی ان تک پہنچتا ہے۔ کوئی بھی OpenAI-مطابق کلائنٹ بھی جڑ سکتا ہے: `status` ہر ماڈل کا پتہ دکھاتا ہے (پہلا `http://127.0.0.1:11435/v1` ہے)، ترکیب کا نام ماڈل ہے، اور کی `~/.config/omarchy/agent-local/key` میں ہے۔

`omarchy models remove <recipe>` کسی ماڈل اور وہ ڈاؤن لوڈز حذف کر دیتا ہے جنہیں کوئی اور ماڈل استعمال نہیں کرتا۔

تھرڈ پارٹی رن ٹائمز پر ان کے پبلشر کا لیبل لگا ہوتا ہے۔ Omarchy ہر ماڈل کو بغیر نیٹ ورک رسائی کے چلاتا ہے۔

### لوکل LLMs

Omarchy لوکل LLM ماڈلز چلانے کے دو طریقے تجویز کرتا ہے: LM Studio اور Ollama۔ LM Studio اوپن ویٹ ماڈلز تلاش کرنے، انہیں انسٹال کرنے اور چلانے کے لیے GUI انٹرفیس فراہم کرتا ہے۔ آسانی سے شروع کرنے کا یہ بہترین طریقہ ہے۔ Ollama اسی کام کے لیے CLI پیش کرتا ہے۔ لیکن اگر آپ لوکل ماڈلز میں نئے ہیں تو میں LM Studio سے شروع کروں گا۔ آپ Omarchy Menu میں _Install > AI_ کے تحت دونوں میں سے کوئی انسٹال کر سکتے ہیں۔

### Omarchy اسکلز

ایجنٹ اسکلز AI کو مخصوص ٹولز کو مخصوص طریقے سے استعمال کرنے میں مدد دیتی ہیں، اور Omarchy ان میں سے سات فراہم کرتا ہے۔ omarchy اسکل سسٹم کو اپنی مرضی کے مطابق بنانے کا احاطہ کرتی ہے، جیسے آپ کی Hyprland کنفیگ کو بہتر بنانا یا بار کو ایڈجسٹ کرنا۔ omarchy-make-theme، omarchy-make-plugin، omarchy-make-app اور omarchy-make-game کچھ نیا بنانے کا احاطہ کرتی ہیں، omarchy-contribute کسی بگ کی رپورٹ کرنے یا اوپر کوئی فکس بھیجنے کا احاطہ کرتی ہے، اور omarchy-diagnose-crash کسی کریش کے core ڈمپ پر کام کرتی ہے۔ انہیں Claude Code (`~/.claude/skills`)، Codex (`~/.codex/skills`)، Pi (`~/.pi/agent/skills`)، Antigravity (`~/.gemini/config/skills`)، Hermes (`~/.hermes/skills` اور ہر `~/.hermes/profiles/*/skills`)، اور عام `~/.agents/skills` مقام کے لیے اسکل ڈائریکٹریوں میں سم لنک کیا گیا ہے، لہٰذا زیادہ تر ہارنسز انہیں خودکار طور پر اٹھا لیتے ہیں۔ اسی نام کا آپ کا اپنا اسکل فولڈر فوقیت رکھتا ہے۔

لیکن آپ کو ان اسکلز کو تجرباتی سمجھنا چاہیے۔ مختلف ماڈلز اسے مختلف اثر کے ساتھ استعمال کریں گے۔ بہتر ہے پہلے پلان موڈ میں چلائیں، تاکہ آپ کو اندازہ ہو کہ ایجنٹ کیا تبدیل کرنا چاہے گا۔ اور پھر تبدیلیوں کو واپس کرنے یا یہاں تک کہ `omarchy reinstall configs` چلانے کے لیے تیار رہیں، اگر ایجنٹ سب کچھ درہم برہم کر دے۔
