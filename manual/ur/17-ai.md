### ایجنٹس کو انسٹال کرنا اور اپڈیٹ کرنا

Hermes کے علاوہ، یہ ایجنٹس mise کی lazy installation استعمال کرتے ہیں: پہلا لانچ CLI انسٹال کرتا ہے، اور بعد کے لانچز اسی کو دوبارہ استعمال کرتے ہیں۔ mise انسٹال شدہ ایجنٹ کے لیے نئی ریلیز بھی چیک کرتا ہے، زیادہ سے زیادہ ہر چار گھنٹے میں ایک بار، شروع ہونے سے ذرا پہلے یا shell prompt پر پس منظر میں۔ اگر وہ اپڈیٹ ناکام ہو جائے یا آپ offline ہوں، تو انسٹال شدہ ورژن چلتا ہے۔ `omarchy update` باقی Omarchy کے ساتھ انسٹال شدہ ایجنٹس کو اپڈیٹ کرتا ہے، اور `mup` صرف mise کے زیر انتظام ٹولز کو اپڈیٹ کرتا ہے۔

کسی ایجنٹ کا اپنا updater، جیسے `claude update`، `codex update`، یا کسی ایپ میں update بٹن، mise کے زیر انتظام انسٹالیشن کو اپڈیٹ نہیں کرتا۔ `codex update` ناکام ہو جاتا ہے، اور `claude update` کامیابی کی اطلاع دے سکتا ہے جبکہ ایک الگ کاپی انسٹال کر رہا ہو جسے mise ٹریک نہیں کرتا۔ اگر آپ اس کے بجائے کسی ایجنٹ کا اپنا installer اور updater استعمال کرنا چاہتے ہیں، تو اسے `disable_tools` میں شامل کریں؛ دیکھیں [پہلے سے انسٹال شدہ CLI ٹولز](18-development-tools.md#preinstalled-cli-tools)۔

تمام configured lazy ٹولز کو ضرورت پڑنے سے پہلے انسٹال کرنے کے لیے `mise install --include-lazy` چلائیں۔ اس میں ایجنٹس کے ساتھ ساتھ Omarchy کے دیگر ڈیفالٹ CLI ٹولز بھی شامل ہیں۔ ایک ٹول انسٹال کرنے یا اپنی انسٹالیشن استعمال کرنے کے لیے دیکھیں [پہلے سے انسٹال شدہ CLI ٹولز](18-development-tools.md#preinstalled-cli-tools)۔

`grok` mise کے first-party `grok` پیکیج کے ذریعے انسٹال ہوتا ہے، اسی طرح جیسے `claude` اور `codex`۔ `grok` چلائیں، یا اسے _Agent > Harness_ کے تحت منتخب کریں۔ x.ai پر موجود `curl | bash` installer کو چھوڑ دیں۔ وہ راستہ `~/.grok/bin` میں دوسری کاپی رکھتا ہے، اسے `PATH` کے شروع میں شامل کرتا ہے، اور Omarchy کے wrapper کو اووررائٹ کر دیتا ہے۔

`dsh` اپنا براؤزر UI `127.0.0.1:3080` پر کھولتا ہے، جس میں لانچ ڈائریکٹری اس کا ڈیفالٹ workspace ہوتی ہے۔ اس کا براؤزر UI کوئی starting prompt نہیں لیتا، لہٰذا `omarchy agent prompt` اسے اس prompt کے ساتھ کھولتا ہے جو آپ کے clipboard پر paste کرنے کے لیے موجود ہوتا ہے۔ Omarchy اسے DeepSeek کے no-approval permission preset کے ساتھ شروع کرتا ہے۔ جب آپ اس کا سرکاری model API استعمال کرتے ہیں تو DeepSeek Harness سیشن لاگز DeepSeek کو اپ لوڈ کرتا ہے؛ اسے اس کے براؤزر UI میں _Settings > General > Upload Session Log_ کے تحت بند کر دیں۔ جو feedback آپ اسے بھیجتے ہیں وہ بھی سیشن کے ساتھ اپ لوڈ ہوتا ہے، الا یہ کہ آپ اسے `DSH_TELEMETRY_MODE=DISABLED` کے ساتھ شروع کریں۔

### ڈیفالٹ ایجنٹ

اپنا ڈیفالٹ ایجنٹ `omarchy default agent <name>` کے ساتھ یا Omarchy Menu (`Super + Space`) میں _Agent > Harness_ کے تحت منتخب کریں۔ اگر ایجنٹ ابھی انسٹال نہیں ہوا، تو اسے منتخب کرنا پہلے اسے انسٹال کرتا ہے۔ ایک تازہ Omarchy ایک بار کی notification کے ساتھ آپ کو یہ انتخاب کرنے کی دعوت دے گا۔

Claude منتخب کرنا Chromium، Chrome، Brave، Brave Origin، اور Edge کے لیے اس کی براؤزر extension ترتیب دینے کی کوشش بھی کرتا ہے۔ extension کی ترتیب تمام صارفین پر لاگو ہوتی ہے اور آپ سے آپ کا system password مانگ سکتی ہے؛ منسوخ کرنا یا extension کی ناکام انسٹالیشن پھر بھی Claude کو منتخب اور لانچ کر دیتی ہے۔ اپنے براؤزر کو دوبارہ شروع کریں، اشارہ ملنے پر extension فعال کریں، اور اسے جوڑنا مکمل کرنے کے لیے Claude میں سائن ان کریں۔ کنکشن چیک کرنے کے لیے Claude میں `/chrome` چلائیں۔ Firefox اور Zen اس extension کی حمایت نہیں کرتے۔ اگر اس ترتیب کے شامل ہونے سے پہلے Claude پہلے ہی آپ کا ڈیفالٹ تھا، تو extension انسٹال کرنے کے لیے اسے دوبارہ منتخب کریں۔

ایک بار منتخب کر لینے کے بعد، `Super + Shift + Ctrl + A` ڈیفالٹ ایجنٹ کو ایک مخصوص terminal window میں لانچ کرتا ہے (یا اگر آپ نے ابھی انتخاب نہیں کیا تو picker سامنے لاتا ہے)۔ آپ اسے `omarchy agent prompt "Review this project"` کے ساتھ سیدھا کسی کام میں بھی لانچ کر سکتے ہیں۔ Freebuff اور DeepSeek Harness کوئی starting prompt نہیں لیتے، لہٰذا وہ اس کے بجائے paste کرنے کے لیے آپ کے clipboard پر موجود prompt کے ساتھ کھلتے ہیں۔ اس طرح لانچ کیے گئے ایجنٹس اپنے متعلقہ don't-stop-to-ask موڈز میں بغیر نگرانی چلتے ہیں، لہٰذا تیار رہیں کہ وہ دراصل کچھ کریں گے! MiniMax Code کے پاس اپنے interactive سیشنز کے لیے ایسا کوئی موڈ نہیں ہے، لہٰذا وہ معمول کے مطابق اجازتیں مانگتا ہے۔ اور چونکہ ایجنٹس آپ کی home directory کے لیے trust یاد رکھنے سے انکار کرتے ہیں، اس لیے `$HOME` سے لانچز اس کے بجائے `~/Work` میں شروع ہوتے ہیں۔

terminal شارٹ کٹس بھی ہیں: `a` mevcut terminal میں ڈیفالٹ ایجنٹ کو inline چلاتا ہے، جبکہ `c`، `cx`، اور `cy` OpenCode، Claude Code، اور Codex کو براہ راست شروع کرتے ہیں (ایک بار پھر ان کے auto-approving موڈز میں)۔ Theme تبدیلیاں ایجنٹس کے ساتھ بھی sync ہوتی ہیں: جب آپ Omarchy theme بدلتے ہیں تو Claude Code، Pi، OpenCode، اور Hermes (ایک بار جب Omarchy نے اسے انسٹال کر لیا ہو) سب اس کے ساتھ چلتے ہیں۔

### آپ کی ایجنٹ ہدایات

ہر ایجنٹ کے لیے ذاتی قواعد `~/.agents/AGENTS.md` میں جاتے ہیں، `~/.agents/skills` میں مشترکہ skills کے ساتھ۔ اسے _Agent > Instructions_ کے تحت کھولیں، جو اسے ہر اس ہارنس میں بھی لنک کرتا ہے جو اپنی global فائل رکھتا ہے: `~/.claude/CLAUDE.md`، `~/.codex/AGENTS.md`، `~/.pi/agent/AGENTS.md`، `~/.config/opencode/AGENTS.md`، Copilot کی `~/.copilot/copilot-instructions.md`، اور اسی طرح مزید۔ Crush اور Amp `~/.config/AGENTS.md` لنک پڑھتے ہیں، جبکہ omp، Kimi، اور DeepSeek Harness `~/.agents/AGENTS.md` کو براہ راست پڑھتے ہیں۔ ڈیفالٹ ایجنٹ منتخب کرنا اسے بھی لنک کرتا ہے۔ جو ہدایات فائل آپ کے پاس پہلے سے تھی وہ مشترکہ فائل بن جاتی ہے اگر ابھی کوئی موجود نہ تھی؛ ورنہ اسے لنک کے ساتھ `.bak` کے طور پر رکھا جاتا ہے۔ ایک اور ایجنٹ انسٹال کرنے کے بعد دوبارہ لنک کرنے کے لیے `omarchy agent instructions` چلائیں۔

### ایجنٹس پینل

اوپر والی بار میں ایک ایجنٹس آئیکن ہے۔ کسی ایجنٹ کو ترتیب دینے سے پہلے، اس کا پینل آپ کو Claude، Codex، یا Grok میں سائن ان کرنے کے عمل سے گزارتا ہے، اور ان میں سے پہلا آپ کا ڈیفالٹ ایجنٹ بن جاتا ہے۔ اس کے بعد، پینل ہر سبسکرپشن کو ایک صفحے پر رکھتا ہے: ہر ایجنٹ اور اکاؤنٹ اس کے plan کے ساتھ، اس کی 5 گھنٹے کے سیشن اور ہفتہ وار حدود میں سے ہر ایک کے لیے ایک میٹر جس کے ساتھ اس کے reset ہونے تک کا وقت ہو (درست فیصد کے لیے hover کریں)، یا باقی prepaid balance، ایک لائن کے نیچے جو ان سب میں آپ کے استعمال کی چیزوں کے درمیان گھومتی ہے، جیسے اس ہفتے کے tokens اور آپ کا سب سے زیادہ استعمال شدہ ماڈل۔ _Make something_ کے تحت یہ نئے theme، plugin، ایپ، یا گیم کے لیے starter prompts پیش کرتا ہے جو کام آپ کے ڈیفالٹ ایجنٹ کے حوالے کرتے ہیں۔ ایپس اسی طرح بنائی جاتی ہیں جیسے Omarchy کی اپنی Hype، Monologue، اور Omacut ہیں، C++ اور Qt Quick میں، omarchy-app ایجنٹ skill کی پیروی کرتے ہوئے، اور انہیں درکار compiler اور Qt اجزا انسٹال شدہ آتے ہیں۔ گیمز `~/Games/vibes` میں ایک واحد three.js صفحہ ہوتے ہیں، web-game ایجنٹ skill کی پیروی کرتے ہوئے، اور سب mevcut theme میں ایک Game Vibes لانچر سے کھلتے ہیں؛ وہ three.js ویب سے لوڈ کرتے ہیں، لہٰذا شروع ہونے کے لیے انہیں کنکشن درکار ہوتا ہے۔ Claude Code، Codex، Grok، Kimi، Cursor اور اس کا Grok Bot allowance، GitHub Copilot، Muse، Antigravity، Kimchi، اور Devin اپنی حدود کے ساتھ باکس سے باہر ہی شامل ہیں، اور Hermes، Mistral Vibe، اور Qwen Code ایک بار جب آپ نے انہیں استعمال کر لیا ہو تو اپنے سیشنز اور tokens دکھاتے ہیں۔ pi، omp، یا opencode کے ذریعے استعمال کیے گئے Provider plans اور keys بھی ظاہر ہوتے ہیں: OpenCode Zen اور Go، Z.ai GLM Coding Plan، Ollama Cloud، MiniMax Token Plan، اور Synthetic اپنی حدود کے ساتھ؛ Fireworks، OpenRouter، اور DeepSeek اپنے prepaid balances کے ساتھ؛ اور وہ ماڈلز جو آپ Local models کے تحت اپنے hardware پر چلاتے ہیں۔ ہر ایجنٹ کو ایک بار گنا جاتا ہے، اس کے تحت جو اس کا بل دیتا ہے، چاہے آپ اسے کتنے ہی ہارنسز کے ذریعے چلائیں۔

پینل کے لیے بار آئیکن پر بائیں کلک کریں، اپنے ڈیفالٹ ایجنٹ کو لانچ کرنے کے لیے دائیں کلک کریں۔ اس کے پیچھے موجود استعمال کے ریکارڈز `omarchy agent usage-update` کے ذریعے ہر 15 منٹ میں دوبارہ بنائے جاتے ہیں، اور پینل ایک synced فولڈر کے ذریعے آپ کی دیگر مشینوں سے استعمال کو بھی ضم کر سکتا ہے۔ مکمل settings کے لیے `$OMARCHY_PATH/shell/plugins/agents/` کے تحت README دیکھیں۔

### متعدد سبسکرپشنز

اگر آپ ایک سے زیادہ Claude، Codex، یا Grok plan کی ادائیگی کرتے ہیں — مثلاً ایک ذاتی Max اور ایک کام کا — تو Omarchy ان سب کو سائن ان رکھ سکتا ہے اور ان کے درمیان منتقل ہو سکتا ہے۔ ایجنٹس پینل میں + کے ساتھ سبسکرپشن شامل کریں، جو آپ کو وہیں اس عمل سے گزارتا ہے، یا `omarchy agent account add claude Work` کے ساتھ (یا `codex`، یا `grok`)۔ اگر CLI موجود نہ ہو تو یہ اسے انسٹال کرتا ہے۔ کسی provider کے لیے پہلا اکاؤنٹ آپ کے معمول کے براؤزر کے ذریعے سائن ان کرتا ہے، بالکل وہیں جہاں CLI ہمیشہ دیکھتا ہے۔ اس کے بعد ہر ایک private window کے ذریعے سائن ان کرتا ہے، تاکہ جس اکاؤنٹ میں آپ کا براؤزر پہلے سے سائن ان ہے وہ غلطی سے منتخب نہ ہو جائے؛ وہاں اس اکاؤنٹ کے طور پر سائن ان کریں جسے آپ شامل کر رہے ہیں، اور پہلے سے کھلی ہوئی کسی private window کو پہلے بند کر دیں۔ ایسا کرنے کے لیے CLI سے کبھی لاگ آؤٹ نہ کریں: لاگ آؤٹ کرنا محفوظ شدہ سائن ان کو منسوخ کر دیتا ہے، اور اس اکاؤنٹ کو دوبارہ شامل کرنا پڑے گا۔

اپنے سبسکرپشن لاگ انز کو SSH پر دوسری Omarchy مشین پر کاپی کرنے کے لیے `omarchy agent account copy user@laptop` چلائیں۔ جب منزل پر کوئی انسٹال نہ ہو تو بھیجنے والا ایک عارضی receiver فراہم کرتا ہے، تاکہ پرانی Omarchy مشینیں بغیر اپڈیٹ کے اکاؤنٹس وصول کر سکیں۔ انسٹال شدہ receivers کو ترجیح حاصل ہوتی ہے۔ یہ تمام Claude، Codex، اور Grok سبسکرپشنز کاپی کرتا ہے؛ انہیں منتخب کرنے کے لیے provider کے نام شامل کریں، جیسے `omarchy agent account copy laptop claude` میں۔ اکاؤنٹ کے نام اور command IDs ماخذ سے ملتے ہیں، بشمول وہ اکاؤنٹس جو منزل پر پہلے سے موجود ہیں۔ غیر متعلقہ منزل اکاؤنٹس کو اگر ان کے نام متصادم ہوں تو عددی suffix ملتا ہے، اور settings، skills، plugins، اور گفتگو کی تاریخ ہر مشین پر مقامی رہتی ہے۔

منزل کی موجودہ credentials رکھی جاتی ہیں۔ وہاں پہلے سے سائن ان ماخذ اکاؤنٹ کا نام اس کی credentials کو بدلے بغیر sync کر دیا جاتا ہے؛ دیگر اکاؤنٹس اس کے ساتھ شامل کر دیے جاتے ہیں۔ ملتے جلتے اکاؤنٹس کی محفوظ شدہ credentials کو بدلنے کے لیے، منزل پر اس اکاؤنٹ کے سیشنز بند کرنے کے بعد `omarchy agent account copy --replace laptop claude` استعمال کریں۔ ایک تازہ منزل کو ماخذ کا فعال اکاؤنٹ اور switching ترجیحات بھی ملتی ہیں؛ ایک قائم شدہ منزل اپنی ترجیحات رکھتی ہے۔

Credentials SSH کے ذریعے سفر کرتی ہیں اور منزل پر private فائلوں میں محفوظ ہوتی ہیں، لہٰذا صرف ان مشینوں پر کاپی کریں جن پر آپ کو بھروسا ہے۔ یہ ایک بار کی کاپی ہے، جاری synchronization نہیں۔ Codex refresh tokens کو دوسری مشین گھما سکتی ہے، جس سے کاپی شدہ لاگ ان کو تجدید کی ضرورت پڑ جاتی ہے؛ کئی مشینوں پر بیک وقت استعمال کے لیے الگ سائن انز سب سے قابل اعتماد انتخاب ہیں۔ دیکھیں [Codex کی اکاؤنٹ تصدیق رہنمائی](https://developers.openai.com/codex/auth/ci-cd-auth)۔

فی provider ایک اکاؤنٹ فعال ہوتا ہے، اور ہر نیا سیشن اسی کے طور پر شروع ہوتا ہے: `cx`، `cy`، ایک سادہ `claude`، `codex`، یا `grok`، `omarchy agent` کے ذریعے لانچ کی گئی کوئی بھی چیز، اور scripts یا editors جو CLI کو `PATH` پر پاتے ہیں۔ `omarchy agent account use work` کے ساتھ سوئچ کریں (اور `omarchy agent account use main` کے ساتھ واپس)، یا پینل میں اکاؤنٹ کا نمبر دبا کر پھر `Enter` دبا کر (یا اس کے Use بٹن پر کلک کر کے)۔ چلتے ہوئے Claude سیشنز بھی سوئچ کرتے ہیں، ان کے اگلے پیغام سے: ہر Claude سیشن `~/.claude` میں چلتا ہے، جو ہمیشہ فعال اکاؤنٹ کا سائن ان رکھتا ہے۔ کسی بڑی عمر کے Omarchy کے ذریعے اکاؤنٹ کے اپنے فولڈر میں شروع کیا گیا Claude سیشن اس سائن ان کو اس وقت تک رکھتا ہے جب تک وہ بند نہ ہو، لہٰذا سوئچ ان سیشنز کا نام لیتا ہے اور ان کے ختم ہونے پر خود مکمل ہو جاتا ہے۔ چلتے ہوئے Codex اور Grok سیشنز اس اکاؤنٹ پر رہتے ہیں جس سے وہ شروع ہوئے تھے۔ گفتگو کی تاریخ، settings، skills، اور plugins اکاؤنٹس کے درمیان مشترکہ ہیں، لہٰذا اسی فولڈر میں `claude --continue` نئے اکاؤنٹ پر وہیں سے شروع ہوتا ہے جہاں آپ نے چھوڑا تھا۔

ایک سے زیادہ اکاؤنٹ کے ساتھ، پینل ہر اکاؤنٹ کی حدود ساتھ ساتھ دکھاتا ہے، جس میں فعال اکاؤنٹ نشان زد ہوتا ہے۔ ڈیفالٹ طور پر Omarchy آپ کو مطلع کرتا ہے جب فعال اکاؤنٹ کسی حد کے 95% سے گزر جاتا ہے، اور notification پر کلک کرنا سب سے زیادہ گنجائش والے اکاؤنٹ پر سوئچ کرتا ہے۔ اسے خود سوئچ کروانے کے بجائے، پینل میں اکاؤنٹ کی لائن پر hover کریں اور Use کے ساتھ ظاہر ہونے والے Autoswitch پر کلک کریں (یا `m` دبائیں)، یا `omarchy agent account mode auto` چلائیں؛ جب یہ آن ہو، تو Autoswitch Use کی جگہ لے لیتا ہے، اور اس پر دوبارہ کلک کرنا مطلع کرنے پر واپس لے جاتا ہے۔ threshold بدلنے کے لیے ایک نمبر شامل کریں، جیسے `omarchy agent account mode auto 90` میں۔ اگر ہر اکاؤنٹ threshold سے اوپر ہو، تو آپ کو ایک بار اس کے بارے میں بتایا جائے گا، ساتھ میں یہ بھی کہ کون سا اکاؤنٹ پہلے آزاد ہوتا ہے۔ جب تک فعال اکاؤنٹ اپنے threshold کے 15 پوائنٹس کے اندر ہو (ڈیفالٹ پر 80%)، اس کی حدود ہر 15 کے بجائے ہر تین منٹ میں چیک کی جاتی ہیں۔

`omarchy agent account list` ہر اکاؤنٹ اور اس کی تازہ ترین حدود دکھاتا ہے، `omarchy agent account remove work` ایک کو بھول جاتا ہے، اور `omarchy agent account rename primary Hey` ایک کا نام بدلتا ہے (یا پینل میں اکاؤنٹ کے نام پر کلک کریں)۔ یہ کمانڈز آپ کے ڈیفالٹ ایجنٹ کے اکاؤنٹس پر کام کرتی ہیں؛ دوسرے provider تک پہنچنے کے لیے پہلے اس کا نام لیں، جیسے `omarchy agent account use codex side` میں۔ جو لاگ ان آپ کے پاس `~/.claude` یا `~/.codex` میں پہلے سے تھا وہ _Main_ اکاؤنٹ ہے۔ Codex کا وہیں رہتا ہے جہاں وہ ہے؛ Claude کا ایک اپنے فولڈر میں انتظار کرتا ہے جبکہ دوسرا اکاؤنٹ فعال ہوتا ہے۔ تقریباً آٹھ گھنٹے سے زیادہ عرصے تک غیر استعمال شدہ چھوڑا گیا اکاؤنٹ _Sign-in required_ دکھا سکتا ہے؛ پینل میں ہی اس اکاؤنٹ میں دوبارہ سائن ان کرنے کے لیے اس پر کلک کریں، یا اس پر سوئچ کر کے ایک سیشن شروع کریں، جو سائن ان کو خود تازہ کر دیتا ہے۔ `claude mcp add` کے ساتھ شامل کیے گئے MCP سرورز ہر Claude اکاؤنٹ تک پہنچتے ہیں، کیونکہ وہ سب `~/.claude` میں چلتے ہیں؛ Codex اور Grok کے لیے، جب اکاؤنٹ شامل کیا گیا تھا اس وقت آپ کے پاس موجود سرورز اس کے ساتھ آتے ہیں، لیکن بعد والے صرف اس اکاؤنٹ تک پہنچتے ہیں جس میں آپ نے انہیں شامل کیا تھا۔ Claude Desktop اپنا سائن ان رکھتا ہے، اور CLI binary کے absolute path کے ساتھ configured Codex یا Grok ٹولز سوئچ کی پیروی نہیں کرتے۔ ایک واضح `CLAUDE_CONFIG_DIR`، `CODEX_HOME`، یا `GROK_HOME` منتخب اکاؤنٹ پر ترجیح لیتا ہے۔

### کریش کی تشخیص

Omarchy process کریشز کے لیے systemd-coredump کو دیکھتا ہے۔ جب کوئی چیز segfault کرتی ہے، تو آپ کو "Process crashed" notification ملے گا — اس پر کلک کریں، اور کریش آپ کے ڈیفالٹ ایجنٹ کے حوالے کر دیا جاتا ہے Omarchy کی diagnose-crash skill کے ساتھ، جو ایجنٹ کو core dump سے حقائق قائم کرنے اور یہ فیصلہ کرنے کے عمل سے گزارتی ہے کہ آیا کریش اوپر کی طرف رپورٹ کرنے کے قابل ہے۔ آپ اسے `coredumpctl list` سے کسی بھی PID کے خلاف `omarchy agent crash <pid>` کے ساتھ ہاتھ سے بھی چلا سکتے ہیں۔

دیکھنا ڈیفالٹ طور پر آن ہے۔ اسے _Trigger > Toggle > Crash Capture_ کے تحت بند کر دیں (یا `omarchy toggle crash-capture` کے ساتھ) اور notifications رک جائیں گی؛ `omarchy agent crash <pid>` ہاتھ سے پھر بھی کام کرتا ہے۔

کریشز کو ایک وقت میں ایک پروگرام کے حساب سے بھی خاموش کیا جا سکتا ہے، جو تشخیص آپ کو آخر میں پیش کرتی ہے۔ `omarchy crash mute hyprland` صرف اس پروگرام کے لیے notifications روکتا ہے، `omarchy crash mute hyprland off` انہیں واپس لاتا ہے، اور `omarchy crash mute` خود فہرست دیتا ہے کہ آپ نے کیا mute کیا ہے۔ یہ binary کا path اسی خوشی سے لیتا ہے جیسے اس کا نام، لہٰذا `omarchy crash mute /usr/bin/hyprland` بھی وہی کام کرتا ہے۔ جس نام میں space ہو اسے quote کریں، جیسے `omarchy crash mute 'Some App'` میں۔ باقی سب کچھ پھر بھی مطلع کرتا ہے، اور mute کیا گیا پروگرام پھر بھی کریش ہوتا ہے — یہ یاد دہانی کو چھپاتا ہے، یہ کچھ ٹھیک نہیں کرتا۔

### ڈیسک ٹاپ ایپس

_Install > AI_ مینو چند graphical AI ایپس بھی رکھتا ہے: ChatGPT ڈیسک ٹاپ ایپ، Claude ڈیسک ٹاپ ایپ (Anthropic کا Linux beta، Chat، Cowork، اور Claude Code ٹیبز کے ساتھ)، xAI کے ماڈلز کے ساتھ چیٹ کرنے کے لیے Grok Bot، Herdr Desktop، Hermes Desktop، OpenClaw، Perplexity ڈیسک ٹاپ ایپ، اور T3 Code۔ Grok Bot ڈیسک ٹاپ چیٹ ایپ ہے۔ کوڈنگ ایجنٹ `grok` کمانڈ ہے۔

Hermes Desktop وہ ہے جس کے بارے میں جاننا ضروری ہے، کیونکہ ایک مشین کے پاس ایک Hermes ہوتا ہے، اور وہ ایپ کا ہوتا ہے: Hermes ہمیشہ صرف ایپ کے ذریعے انسٹال ہوتا ہے، اور جو `hermes` کمانڈ ڈیفالٹ ایجنٹ چلاتا ہے وہ ایپ کی ہوتی ہے۔ Hermes کو ڈیفالٹ ایجنٹ کے طور پر منتخب کرنا وہی چیز انسٹال کرتا ہے جو _Install > AI_ اندراج کرتا ہے: پیکیج، اور `~/.hermes` کے تحت Hermes runtime جو Hermes کے اپنے installer کے ذریعے ترتیب دیا گیا ہو، جس میں پہلی بار چند منٹ لگتے ہیں۔ وہ runtime وہی ایک Hermes ہے جسے terminal `hermes` کمانڈ، ڈیفالٹ ایجنٹ اور ایپ سب استعمال کرتے ہیں، اور یہ Omarchy ریلیز کا انتظار کرنے کے بجائے `hermes update` کے ساتھ خود کو اپڈیٹ کرتا ہے۔ اسے انسٹال کرنا Hermes کو Omarchy theme بھی `omarchy` نامی skin کے طور پر دیتا ہے، جس کی ہر Hermes سطح پیروی کرتی ہے جب آپ themes بدلتے ہیں؛ اگر آپ نہیں چاہتے کہ ایسا ہو تو Hermes کی Appearance settings کے تحت یا `/skin` کے ساتھ کوئی اور منتخب کریں، اور Omarchy اس انتخاب کو چھوڑ دیتا ہے۔ _Remove > AI_ کے تحت ایپ کو ہٹانا پہلے Hermes کو بند کرتا ہے، gateway سمیت، اس runtime کو اس کے ساتھ لے جاتا ہے، اور آپ کی چیٹس، یادیں، اور وہ skills رکھتا ہے جو Hermes نے خود اپنے لیے لکھی تھیں جب تک آپ اسے دوسری صورت نہ بتائیں: یہ پوچھتا ہے، ڈیفالٹ طور پر نہیں کے ساتھ، کہ آیا وہ ڈیٹا اور آپ کی کنکشن settings بھی جانی چاہئیں۔

OpenClaw کا ڈیسک ٹاپ تجربہ اس کا Control UI ہے، جو اپنے مقامی gateway کی پشت پناہی سے ایک ویب ایپ کے طور پر کھلتا ہے۔ OpenClaw `~/.openclaw` میں رہتا ہے اور خود کو اپڈیٹ کرتا ہے: Control UI کا "Update Gateway" بٹن استعمال کریں یا `openclaw update` چلائیں، اور gateway نئے ورژن پر دوبارہ شروع ہو جاتا ہے۔ Omarchy صرف اس ریلیز کا انتخاب کرتا ہے جس سے تازہ انسٹال شروع ہوتا ہے۔ _Remove > AI_ کے تحت OpenClaw کو ہٹانا gateway service اور ایپ کو اس کے ساتھ لے جاتا ہے اور پھر پوچھتا ہے کہ آیا `~/.openclaw` بھی جانا چاہیے، کیونکہ اس میں آپ کی چیٹس اور credentials کے ساتھ ساتھ خود OpenClaw اور اس کے ڈاؤن لوڈ کردہ plugin runtimes موجود ہوتے ہیں؛ ڈیفالٹ اسے رکھتا ہے، اور OpenClaw کو دوبارہ انسٹال کرنا اسے واپس اٹھا لیتا ہے۔

Herdr Desktop [Herdr](https://herdr.dev) ڈیسک ٹاپ ایپ ہے: terminals اور کوڈنگ ایجنٹس کے spaces، tabs، اور panes جو اس کے core میں چلتے رہتے ہیں جب آپ window بند کرتے ہیں۔ یہ پیکیج کے بجائے Herdr کے اپنے installer سے آتا ہے، لہٰذا یہ `~/.local/share/herdr-app` میں رہتا ہے، جب آپ کے پاس ابھی کوئی نہ ہو تو اپنے core کو `~/.local/bin/herdr-core` میں ساتھ لاتا ہے، اور دونوں کو خود اپڈیٹ کرتا ہے۔ یہ اس `herdr` کمانڈ کے ساتھ بیٹھتا ہے جسے Omarchy `Super + Ctrl + Return` پر فراہم کرتا ہے، اسے بدلنے کے بجائے، اور اس کمانڈ کی براہ راست keys حاصل کرتا ہے: `Alt + Return` اور `Alt + Shift + Return` ایک pane کو نیچے یا دائیں تقسیم کرتے ہیں، `Alt + Escape` اسے بند کرتا ہے، `Ctrl + Alt + Arrow` panes کے درمیان منتقل ہوتا ہے، `Alt + 1..9` اور `Alt + Left/Right` ایک ٹیب منتخب کرتے ہیں، اور `Alt + Up/Down` spaces کے درمیان منتقل ہوتے ہیں۔ `Ctrl + 1..9` ایک space منتخب کرتا ہے اور `Alt + Shift + Up/Down` ایجنٹس کے درمیان قدم بڑھاتا ہے۔ `Ctrl + Space` prefix keys صرف terminal کے لیے رہتی ہیں، کیونکہ ایپ کسی sequence کے لیے سادہ Ctrl key کو روک نہیں سکتی۔ Omarchy انہیں `~/.config/herdr-app/keys.json` میں لکھتا ہے، اور `omarchy-refresh-herdr-app` انہیں واپس رکھتا ہے۔ اسے انسٹال کرنا Herdr کا Omarchy theme منتخب کرتا ہے، جو اس کے بعد سے آپ کے Omarchy theme کی پیروی کرتا ہے۔ Herdr light mode کے لیے ایک theme اور dark کے لیے ایک رکھتا ہے، لہٰذا dark اور light Omarchy theme کے درمیان سوئچ کرنے کے بعد، دوسرے موڈ کے لیے Herdr کے theme picker میں ایک بار پھر Omarchy منتخب کریں۔

T3 Code پیکیج کے بجائے `~/.local/share/t3code` میں اپنی سرکاری AppImage ریلیز سے چلتا ہے، لہٰذا یہ خود کو اپڈیٹ کرتا ہے۔ اسے انسٹال کرنا پوچھتا ہے کہ آیا Stable یا Nightly چینل پر شروع کرنا ہے؛ بعد میں T3 Code کی settings میں سوئچ کریں۔ آپ کے threads اور settings `~/.t3` میں رہتے ہیں، اور _Remove > AI_ کے تحت T3 Code کو ہٹانا انہیں اس کے ساتھ لے جاتا ہے۔

### مقامی ماڈلز

اپنے کوڈنگ ایجنٹس کے لیے اپنی مشین پر ایک open ماڈل چلائیں۔ آپ کے prompts اور کوڈ مشین پر رہتے ہیں؛ ماڈل کو بھیجی گئی کوئی چیز اسے نہیں چھوڑتی۔ اس سے شروع کریں:

```bash
omarchy agent local use best
```

یا، اوپر والی بار کے ایجنٹس پینل میں، + اور پھر Local AI منتخب کریں، جو اس وقت ظاہر ہوتا ہے جب کوئی ماڈل اس مشین میں فٹ ہو۔ پہلی بار، یہ Podman انسٹال کرتا ہے، جو ماڈلز چلاتا ہے، اور NVIDIA مشین پر NVIDIA کا container toolkit، جو انہیں GPU دیتا ہے۔ Omarchy پھر اس مشین کے لیے تجویز کردہ ماڈل منتخب کرتا ہے، اسے ڈاؤن لوڈ کرتا ہے، اور اسے شروع کرتا ہے۔ درجنوں GB کے ڈاؤن لوڈ کی توقع کریں اور ماڈل چلتے وقت مشین کی زیادہ تر memory استعمال میں ہوگی: Flash Next اپنے مکمل 256K context کے ساتھ تقریباً 100 GiB استعمال کرتا ہے۔ اگر دیگر ماڈلز وہ memory روکے ہوئے ہوں جس کی اسے ضرورت ہے، تو یہ بند حالت میں ترتیب دیا جاتا ہے، ایک کو روکنے پر شروع ہونے کے لیے تیار۔ ماڈل لاگ آؤٹ پر رک جاتا ہے؛ جب آپ کو کسی اور چیز کے لیے memory درکار ہو تو اسے خود روک دیں۔

`omarchy agent local list` اختیارات دکھاتا ہے اور بتاتا ہے کہ کچھ کیوں فٹ نہیں ہوتے۔ ایک اور ترتیب دینے کے لیے `omarchy agent local use <recipe>` چلائیں۔ آج، 128 GB Strix Halo مشینوں کے لیے `qwen3.8-flash-next-gufo` اور `qwen3.8-27b-gufo` دستیاب ہیں؛ 27B تقریباً 40 GiB لیتا ہے، لہٰذا یہ دیگر کام کے لیے جگہ چھوڑتا ہے۔ Intel کے Arc B390 کے ساتھ 64 GB لیپ ٹاپ پر، `qwen3.6-35b-a3b-llamacpp` تقریباً 30 GiB میں چلتا ہے۔ نئی recipes اور تجاویز پیکیج کے ذریعے `omarchy update` کے ساتھ آتی ہیں۔

آپ کے ترتیب دیے گئے ہر ماڈل کو ایجنٹس پینل میں اپنی لائن ملتی ہے، آپ کی سبسکرپشنز کے ساتھ: شروع کرنے کے لیے play، اسے روکنے اور اس کی memory آزاد کرنے کے لیے pause، اور اس پر اپنے ایجنٹ کو کھولنے کے لیے terminal بٹن۔ کئی ایک ساتھ چل سکتے ہیں جب وہ میموری میں ایک ساتھ فٹ ہوں؛ اگر ایک فٹ نہ ہو، تو Omarchy بتاتا ہے کہ کس چلتے ہوئے ماڈل کو روکنا ہے۔ انہیں دوبارہ ترتیب دینے کے لیے لائنوں کو گھسیٹیں، اور منتخب لائن پر Delete دبائیں تاکہ ماڈل اور اس کا ڈاؤن لوڈ ہٹا دیا جائے۔

آپ کے ترتیب دیے گئے ہر ماڈل کو ایپ لانچر میں بھی اپنی اندراج ملتی ہے، ماڈل کے نام کے تحت اور اس کے بنانے والے کے لوگو کے ساتھ، اسی طرح جیسے Claude، Codex یا Grok میں سائن ان کرنا ایک شامل کرتا ہے۔ یہ آپ کے ایجنٹ کو اس ماڈل پر کھولتا ہے، اور اگر ماڈل نہ چل رہا ہو تو پہلے اسے شروع کرتا ہے: terminal اسے لوڈ ہوتا دکھاتا ہے اور تیار ہونے پر ایجنٹ کے حوالے کر دیتا ہے۔ ماڈل ہٹانا اس کا اندراج ہٹا دیتا ہے۔

کمانڈ لائن سے، `omarchy agent local start <recipe>` اور `omarchy agent local stop <recipe>` بھی وہی کرتے ہیں، `omarchy agent local status` ہر ماڈل دکھاتا ہے، اور `omarchy agent --local` آپ کے ڈیفالٹ ایجنٹ کو آخری شروع کیے گئے ماڈل پر کھولتا ہے۔ pi، OpenCode اور Qwen Code ایک استعمال کر سکتے ہیں؛ کسی اور ڈیفالٹ کے ساتھ یہ pi میں کھلتا ہے۔ pi آپ کے ترتیب دیے گئے ہر ماڈل، اور جن مشینوں کے ساتھ آپ نے جوڑا بنایا ہے ان پر موجود ماڈلز کو بھی، اپنے model picker میں فہرست کرتا ہے، لہٰذا سادہ `pi` بھی ان تک پہنچتا ہے۔ کوئی بھی OpenAI-compatible client بھی جڑ سکتا ہے: `status` ہر ماڈل کا پتہ دکھاتا ہے (پہلا `http://127.0.0.1:11435/v1` ہے)، recipe کا نام ماڈل ہے، اور key `~/.config/omarchy/agent-local/key` میں ہے۔

`omarchy agent local remove <recipe>` ایک ماڈل اور وہ ڈاؤن لوڈز حذف کرتا ہے جو کوئی اور ماڈل استعمال نہیں کرتا۔

Third-party runtimes پر ان کے publisher کے ساتھ لیبل لگا ہوتا ہے۔ Omarchy ہر ماڈل کو بغیر کسی network access کے چلاتا ہے۔

### مقامی LLMs

Omarchy مقامی LLM ماڈلز چلانے کے دو طریقے تجویز کرتا ہے: LM Studio اور Ollama۔ LM Studio open-weight ماڈلز تلاش کرنے، انہیں انسٹال کرنے، اور انہیں چلانے کے لیے GUI انٹرفیس فراہم کرتا ہے۔ آسانی سے شروع کرنے کا یہ ایک بہترین طریقہ ہے۔ Ollama اسی طرح کرنے کے لیے CLI پیش کرتا ہے۔ لیکن اگر آپ مقامی ماڈلز میں نئے ہیں، تو میں LM Studio سے شروع کروں گا۔ آپ Omarchy Menu میں _Install > AI_ کے تحت دونوں میں سے کوئی بھی انسٹال کر سکتے ہیں۔

### Omarchy Skill

Agent skills AI کو مخصوص ٹولز کو مخصوص طریقے سے استعمال کرنے میں مدد دیتے ہیں، اور Omarchy system کو اپنی مرضی کے مطابق بنانے کے لیے ایک ڈیفالٹ skill کے ساتھ آتا ہے۔ جیسے اپنی Hyprland config کو بدلنا، بار کو ایڈجسٹ کرنا، یا شروع سے ایک نیا theme بنانا۔ یہ Claude Code (`~/.claude/skills`)، Codex (`~/.codex/skills`)، Pi (`~/.pi/agent/skills`)، Antigravity (`~/.gemini/config/skills`)، Hermes (`~/.hermes/skills` اور ہر `~/.hermes/profiles/*/skills`)، اور عام `~/.agents/skills` مقام کے لیے skill directories میں symlinked ہے، لہٰذا زیادہ تر ہارنسز اسے خودکار طور پر اٹھا لیتے ہیں۔

لیکن آپ کو اس skill کو تجرباتی سمجھنا چاہیے۔ مختلف ماڈلز اسے مختلف اثر کے ساتھ استعمال کریں گے۔ بہتر ہے کہ پہلے اسے plan mode میں چلائیں، تاکہ آپ کو اندازہ ہو کہ ایجنٹ کیا بدلنا چاہے گا۔ اور پھر تبدیلیاں rollback کرنے یا حتیٰ کہ `omarchy reinstall configs` چلانے کے لیے تیار رہیں، اگر ایجنٹ ہر چیز کا گڑبڑ کر دے۔
