### ایجنٹس انسٹال اور اپ ڈیٹ کرنا

Hermes اور OpenClaw کے علاوہ، یہ ایجنٹس mise کی سست انسٹالیشن استعمال کرتے ہیں: پہلی بار لانچ کرنے پر CLI انسٹال ہو جاتا ہے، اور بعد کے لانچ اسی کو دوبارہ استعمال کرتے ہیں۔ mise انسٹال شدہ ایجنٹ کے لیے نئی ریلیز بھی چیک کرتا ہے، زیادہ سے زیادہ ہر چار گھنٹے میں ایک بار، شروع ہونے سے ذرا پہلے یا پس منظر میں shell prompt پر۔ اگر وہ اپ ڈیٹ ناکام ہو جائے یا آپ آف لائن ہوں، تو انسٹال شدہ ورژن چلتا ہے۔ `omarchy update` باقی Omarchy کے ساتھ انسٹال شدہ ایجنٹس کو اپ ڈیٹ کرتا ہے، اور `mup` صرف mise کے زیر انتظام ٹولز کو اپ ڈیٹ کرتا ہے۔

کسی ایجنٹ کا اپنا اپڈیٹر، جیسے `claude update`، `codex update`، یا کسی ایپ میں اپ ڈیٹ بٹن، mise کے زیر انتظام انسٹال کو اپ ڈیٹ نہیں کرتا۔ `codex update` ناکام ہو جاتا ہے، اور `claude update` کامیابی کی اطلاع دے سکتا ہے جبکہ ایک الگ کاپی انسٹال کر دیتا ہے جسے mise ٹریک نہیں کرتا۔ اگر آپ اس کے بجائے کسی ایجنٹ کا اپنا انسٹالر اور اپڈیٹر استعمال کرنا چاہتے ہیں، تو اسے `disable_tools` میں شامل کریں؛ دیکھیں [پہلے سے انسٹال شدہ CLI ٹولز](18-development-tools.md#preinstalled-cli-tools)۔

تمام کنفیگر شدہ lazy ٹولز کو ضرورت پڑنے سے پہلے انسٹال کرنے کے لیے `mise install --include-lazy` چلائیں۔ اس میں ایجنٹس کے علاوہ Omarchy کے دیگر ڈیفالٹ CLI ٹولز بھی شامل ہیں۔ ایک ٹول انسٹال کرنے یا اپنی انسٹالیشن استعمال کرنے کے لیے دیکھیں [پہلے سے انسٹال شدہ CLI ٹولز](18-development-tools.md#preinstalled-cli-tools)۔

`grok` mise کے فرسٹ پارٹی `grok` پیکیج کے ذریعے انسٹال ہوتا ہے، اسی طرح جیسے `claude` اور `codex`۔ `grok` چلائیں، یا ایجنٹس پینل میں اسے ستارہ لگائیں۔ x.ai پر `curl | bash` انسٹالر کو چھوڑ دیں۔ وہ راستہ `~/.grok/bin` میں دوسری کاپی رکھتا ہے، اسے `PATH` کے شروع میں شامل کرتا ہے، اور Omarchy کے wrapper کو اوور رائٹ کر دیتا ہے۔

`dsh` اپنا browser UI `127.0.0.1:3080` پر کھولتا ہے، جس میں لانچ ڈائرکٹری اس کی ڈیفالٹ workspace ہوتی ہے۔ اس کا browser UI کوئی ابتدائی prompt نہیں لیتا، لہٰذا `omarchy agent prompt` اسے آپ کے clipboard پر موجود prompt کے ساتھ کھولتا ہے تاکہ آپ اسے paste کریں۔ Omarchy اسے DeepSeek کے no-approval permission preset کے ساتھ شروع کرتا ہے۔ DeepSeek Harness آپ کے سیشن لاگز DeepSeek کو اپ لوڈ کرتا ہے جب آپ اس کا آفیشل ماڈل API استعمال کرتے ہیں؛ اسے اس کے browser UI میں _Settings > General > Upload Session Log_ کے تحت بند کر دیں۔ آپ جو فیڈبیک اسے بھیجتے ہیں وہ بھی سیشن کے ساتھ اپ لوڈ ہوتا ہے، جب تک کہ آپ اسے `DSH_TELEMETRY_MODE=DISABLED` کے ساتھ شروع نہ کریں۔

### ڈیفالٹ ایجنٹ

اپنا ڈیفالٹ ایجنٹ ایجنٹس پینل میں کسی ایجنٹ کے ساتھ والے ستارے سے منتخب کریں، جو ڈیفالٹ پر بھرا ہوا ہوتا ہے، یا `omarchy default agent <name>` سے، جو وہاں لائن نہ رکھنے والے کسی بھی harness کو بھی قبول کرتا ہے۔ اگر ایجنٹ ابھی انسٹال نہیں ہوا، تو اسے منتخب کرنا پہلے اسے انسٹال کرتا ہے، اور اسے app launcher میں Agent کے ساتھ اس کا اپنا لانچر بھی ملتا ہے۔ ایک تازہ Omarchy آپ کو ایک بار کی اطلاع کے ساتھ ایک سیٹ اپ کرنے کی دعوت دیتا ہے، جو ایجنٹس پینل کھولتی ہے۔

Claude کو منتخب کرنا Chromium، Chrome، Brave، Brave Origin، اور Edge کے لیے اس کا browser extension سیٹ اپ کرنے کی کوشش بھی کرتا ہے۔ extension کا سیٹ اپ تمام صارفین پر لاگو ہوتا ہے اور آپ سے آپ کا سسٹم پاس ورڈ مانگ سکتا ہے؛ منسوخ کرنا یا extension انسٹال ناکام ہونا تب بھی Claude کو منتخب اور لانچ کرتا ہے۔ اپنا browser دوبارہ شروع کریں، اشارہ ملنے پر extension فعال کریں، اور اسے منسلک کرنا مکمل کرنے کے لیے Claude میں سائن ان کریں۔ کنکشن چیک کرنے کے لیے Claude میں `/chrome` چلائیں۔ Firefox اور Zen اس extension کی حمایت نہیں کرتے۔ اگر یہ سیٹ اپ شامل ہونے سے پہلے Claude پہلے ہی آپ کا ڈیفالٹ تھا، تو extension انسٹال کرنے کے لیے اسے دوبارہ منتخب کریں۔

منتخب کرنے کے بعد، `Super + Shift + Ctrl + A` ڈیفالٹ ایجنٹ کو ایک مخصوص terminal ونڈو میں لانچ کرتا ہے (یا اگر آپ نے ابھی منتخب نہیں کیا تو picker لاتا ہے)۔ آپ اسے `omarchy agent prompt "Review this project"` کے ساتھ سیدھا کسی کام میں بھی لانچ کر سکتے ہیں۔ Freebuff اور DeepSeek Harness کوئی ابتدائی prompt نہیں لیتے، لہٰذا وہ اس کے بجائے آپ کے clipboard پر موجود prompt کے ساتھ کھلتے ہیں تاکہ آپ paste کریں۔ اس طرح لانچ ہونے والے ایجنٹس اپنے متعلقہ don't-stop-to-ask موڈز میں بغیر نگرانی چلتے ہیں، لہٰذا تیار رہیں کہ وہ واقعی کچھ کریں گے! MiniMax Code کے interactive سیشنز کے لیے ایسا کوئی موڈ نہیں ہے، لہٰذا وہ معمول کے مطابق اجازتیں مانگتا ہے۔ اور چونکہ ایجنٹس آپ کی home ڈائرکٹری کے لیے trust یاد رکھنے سے انکار کرتے ہیں، اس لیے `$HOME` سے لانچ اس کے بجائے `~/Work` میں شروع ہوتے ہیں۔

terminal شارٹ کٹس بھی ہیں: `a` موجودہ terminal میں ڈیفالٹ ایجنٹ کو inline چلاتا ہے، جبکہ `c`، `cx`، اور `cy` OpenCode، Claude Code، اور Codex کو براہ راست شروع کرتے ہیں (پھر ان کے auto-approving موڈز میں)۔ تھیم کی تبدیلیاں ایجنٹس کے ساتھ بھی sync ہوتی ہیں: Claude Code، Pi، OpenCode، اور Hermes (جب Omarchy اسے انسٹال کر لے) سب اس وقت ساتھ بدلتے ہیں جب آپ Omarchy تھیم تبدیل کرتے ہیں۔

### آپ کے ایجنٹ کی ہدایات

ہر ایجنٹ کے لیے ذاتی قواعد `~/.agents/AGENTS.md` میں جاتے ہیں، `~/.agents/skills` میں مشترکہ skills کے ساتھ۔ اسے ایجنٹس پینل میں + کے ساتھ والے دستاویز آئیکن سے کھولیں، یا `omarchy agent instructions --edit` سے، جو اسے ہر اس harness میں بھی لنک کرتا ہے جو اپنی عالمی فائل رکھتا ہے: `~/.claude/CLAUDE.md`، `~/.codex/AGENTS.md`، `~/.pi/agent/AGENTS.md`، `~/.config/opencode/AGENTS.md`، Copilot کی `~/.copilot/copilot-instructions.md`، وغیرہ۔ Crush اور Amp `~/.config/AGENTS.md` لنک پڑھتے ہیں، جبکہ omp، Kimi، اور DeepSeek Harness `~/.agents/AGENTS.md` کو براہ راست پڑھتے ہیں۔ ڈیفالٹ ایجنٹ منتخب کرنا اسے بھی لنک کرتا ہے۔ آپ کی پہلے سے موجود ہدایات فائل مشترکہ فائل بن جاتی ہے اگر ابھی کوئی نہیں تھی؛ ورنہ اسے لنک کے ساتھ `.bak` کے طور پر رکھا جاتا ہے۔ دوسرا ایجنٹ انسٹال کرنے کے بعد دوبارہ لنک کرنے کے لیے `omarchy agent instructions` چلائیں۔

### ایجنٹس پینل

اوپر والی بار میں ایک ایجنٹس آئیکن ہے۔ ایجنٹ سیٹ اپ کرنے سے پہلے، اس کا پینل شروع کرنے کے تین طریقے پیش کرتا ہے: Claude، Codex، Grok، Gemini، Muse، Cursor، یا Copilot سبسکرپشن میں سائن ان کریں، یا More کے تحت OpenCode Go، MiniMax، Synthetic، یا Z.ai کوڈنگ پلان؛ Fireworks، OpenCode Zen and Go، OpenRouter کے ساتھ استعمال کے حساب سے ادائیگی کریں، یا More کے تحت DeepSeek یا کوئی اور فراہم کنندہ جس میں OpenCode سائن ان کرتا ہے، سب OpenCode میں چلتے ہیں؛ یا اپنے کمپیوٹر کے لیے بہترین ماڈل چلائیں، جب کوئی اس میں فٹ ہو۔ آپ جو پہلا مکمل کرتے ہیں وہ آپ کا ڈیفالٹ ایجنٹ بن جاتا ہے، اور پینل میں + بعد میں وہی تین پیش کرتا ہے۔ اس کے بعد، پینل ہر سبسکرپشن کو ایک صفحے پر رکھتا ہے: ہر ایجنٹ اور اکاؤنٹ اس کے پلان کے ساتھ، اس کی 5-hour سیشن اور ہفتہ وار حدود میں سے ہر ایک کے لیے ایک میٹر جس میں reset ہونے تک کا وقت ہو (درست فیصد کے لیے hover کریں)، یا باقی prepaid بیلنس، ایک لائن کے تحت جو ان سب میں آپ کے استعمال کی چیزوں میں گردش کرتی ہے، جیسے اس ہفتے کے tokens اور آپ کا سب سے زیادہ استعمال شدہ ماڈل۔ _Make something cool_ کے تحت یہ ایک نئی تھیم، plugin، ایپ، یا گیم کے لیے ابتدائی prompts پیش کرتا ہے جو کام آپ کے ڈیفالٹ ایجنٹ کے حوالے کرتے ہیں۔ ایپس اسی طرح بنائی جاتی ہیں جیسے Omarchy کی اپنی Hype، Monologue، اور Omacut ہیں، C++ اور Qt Quick میں، omarchy-make-app ایجنٹ skill کی پیروی کرتے ہوئے، اور انہیں درکار compiler اور Qt حصے انسٹال شدہ آتے ہیں۔ گیمز `~/Games/vibes` میں ایک واحد three.js صفحہ ہوتی ہیں، omarchy-make-game ایجنٹ skill کی پیروی کرتے ہوئے، اور سب موجودہ تھیم میں ایک Game Vibes لانچر سے کھلتی ہیں؛ وہ three.js ویب سے لوڈ کرتی ہیں، لہٰذا انہیں شروع ہونے کے لیے کنکشن درکار ہے۔ Claude Code، Codex، Grok، Kimi، Cursor اور اس کا Grok Bot الاؤنس، GitHub Copilot، Muse، Gemini (Antigravity کے ذریعے)، اور Devin اپنی حدود کے ساتھ ابتدا سے ہی شامل ہیں، Kimchi اپنے پلان، prepaid کریڈٹس، اور خرچ بجٹ کے ساتھ، اور Hermes، Mistral Vibe، اور Qwen Code اپنے سیشنز اور tokens دکھاتے ہیں جب آپ انہیں استعمال کر لیں۔ فراہم کنندہ پلانز اور keys جو آپ pi، omp، یا opencode کے ذریعے استعمال کرتے ہیں وہ بھی ظاہر ہوتے ہیں: OpenCode Zen and Go، Z.ai GLM Coding Plan، Ollama Cloud، MiniMax Token Plan، اور Synthetic اپنی حدود کے ساتھ؛ OpenRouter اور DeepSeek اپنے prepaid بیلنس کے ساتھ؛ Fireworks گزشتہ 30 دنوں میں اپنے خرچ کے ساتھ۔ کوڈنگ ماڈلز جو آپ اپنے ہارڈویئر پر چلاتے ہیں انہیں اپنی لائنیں ملتی ہیں، اور ان کے tokens بھی مجموعوں میں شمار ہوتے ہیں، جیسا کہ [مقامی ماڈلز](#local-models) کے تحت بیان کیا گیا ہے۔ ہر ایجنٹ ایک بار شمار ہوتا ہے، اس کے تحت جو اس کا بل دیتا ہے، چاہے آپ اسے کتنے ہی harnesses کے ذریعے چلائیں۔

پینل کے لیے بار آئیکن پر بائیں کلک کریں یا `Super + Ctrl + X` دبائیں، اپنے ڈیفالٹ ایجنٹ کو لانچ کرنے کے لیے دائیں کلک کریں، اور refresh کے لیے درمیانی کلک کریں۔ اس کے پیچھے استعمال کے ریکارڈز ہر 15 منٹ میں `omarchy agent usage update` کے ذریعے دوبارہ بنائے جاتے ہیں، اور پینل ایک sync شدہ فولڈر کے ذریعے آپ کی دوسری مشینوں سے استعمال کو ضم بھی کر سکتا ہے۔ مکمل ترتیبات کے لیے `$OMARCHY_PATH/shell/plugins/agents/` کے تحت README دیکھیں۔

### کئی سبسکرپشنز

اگر آپ ایک سے زیادہ Claude، Codex، یا Grok پلان کی ادائیگی کرتے ہیں — مثلاً ایک ذاتی Max اور ایک کام والا — تو Omarchy ان سب کو سائن ان رکھ سکتا ہے اور ان کے درمیان منتقل ہو سکتا ہے۔ ایجنٹس پینل میں + کے ساتھ سبسکرپشن شامل کریں، جو آپ کو وہیں اس سے گزارتا ہے، یا `omarchy agent account add claude Work` (یا `codex`، یا `grok`) کے ساتھ۔ وہی + اور کمانڈ Gemini (`gemini`) اور OpenCode (`opencode`) میں سائن ان کرتے ہیں، اور OpenCode میں Fireworks (`fireworks`) یا OpenRouter (`openrouter`) API key محفوظ کرتے ہیں؛ کمانڈ Copilot (`copilot`)، Cursor (`cursor`)، اور Muse (`muse`) میں بھی سائن ان کرتی ہے۔ وہ ہر ایک واحد سائن ان رکھتے ہیں۔ اگر CLI غائب ہے تو یہ اسے انسٹال کرتا ہے۔ کسی فراہم کنندہ کے لیے پہلا اکاؤنٹ آپ کے عام browser کے ذریعے سائن ان ہوتا ہے، بالکل وہاں جہاں CLI ہمیشہ دیکھتا ہے۔ اس کے بعد ہر ایک private ونڈو کے ذریعے سائن ان ہوتا ہے، تاکہ جس اکاؤنٹ میں آپ کا browser پہلے سے سائن ان ہے وہ غلطی سے نہ اٹھایا جائے؛ وہاں اس اکاؤنٹ کے طور پر سائن ان کریں جسے آپ شامل کر رہے ہیں، اور پہلے سے کھلی ہوئی کوئی private ونڈو پہلے بند کر دیں۔ ایسا کرنے کے لیے CLI سے کبھی لاگ آؤٹ نہ کریں: لاگ آؤٹ کرنا محفوظ شدہ سائن ان کو منسوخ کر دیتا ہے، اور اس اکاؤنٹ کو دوبارہ شامل کرنا پڑے گا۔

اپنے سبسکرپشن لاگ انز کو SSH پر دوسری Omarchy مشین پر کاپی کرنے کے لیے `omarchy agent account copy user@laptop` چلائیں۔ بھیجنے والا ایک عارضی receiver فراہم کرتا ہے جب منزل پر کوئی انسٹال نہ ہو، تاکہ پرانی Omarchy مشینیں اپ ڈیٹ کے بغیر اکاؤنٹس وصول کر سکیں۔ انسٹال شدہ receivers کو ترجیح حاصل ہے۔ یہ تمام Claude، Codex، اور Grok سبسکرپشنز کاپی کرتا ہے؛ انہیں منتخب کرنے کے لیے فراہم کنندہ کے نام شامل کریں، جیسے `omarchy agent account copy laptop claude`۔ اکاؤنٹ کے نام اور کمانڈ IDs ماخذ سے ملتے ہیں، بشمول منزل پر پہلے سے موجود اکاؤنٹس۔ غیر متعلق منزل اکاؤنٹس کو عددی suffix ملتا ہے اگر ان کے نام متصادم ہوں، اور ترتیبات، skills، plugins، اور گفتگو کی تاریخ ہر مشین پر مقامی رہتی ہے۔

موجودہ منزل اسناد رکھی جاتی ہیں۔ وہاں پہلے سے سائن ان ماخذ اکاؤنٹ کا نام اس کی اسناد کو بدلے بغیر sync کیا جاتا ہے؛ دوسرے اکاؤنٹس اس کے ساتھ شامل کیے جاتے ہیں۔ مماثل اکاؤنٹس کے لیے محفوظ شدہ اسناد بدلنے کے لیے، منزل پر اس اکاؤنٹ کے سیشنز بند کرنے کے بعد `omarchy agent account copy --replace laptop claude` استعمال کریں۔ ایک تازہ منزل کو ماخذ کا فعال اکاؤنٹ اور switching ترجیحات بھی ملتی ہیں؛ ایک قائم منزل اپنی رکھتی ہے۔

اسناد SSH کے ذریعے سفر کرتی ہیں اور منزل پر private فائلوں میں محفوظ ہوتی ہیں، لہٰذا صرف ان مشینوں پر کاپی کریں جن پر آپ اعتماد کرتے ہیں۔ یہ ایک بار کی کاپی ہے، جاری synchronization نہیں۔ Codex refresh tokens دوسری مشین کے ذریعے rotate کیے جا سکتے ہیں، جس سے کاپی شدہ لاگ ان کو تجدید کی ضرورت پڑ جاتی ہے؛ کئی مشینوں پر بیک وقت استعمال کے لیے الگ سائن انز سب سے قابل اعتماد انتخاب رہتے ہیں۔ دیکھیں [Codex کی اکاؤنٹ تصدیق رہنمائی](https://developers.openai.com/codex/auth/ci-cd-auth)۔

فی فراہم کنندہ ایک اکاؤنٹ فعال ہوتا ہے، اور ہر نیا سیشن اسی کے طور پر شروع ہوتا ہے: `cx`، `cy`، ایک سادہ `claude`، `codex`، یا `grok`، `omarchy agent` کے ذریعے لانچ ہونے والی کوئی بھی چیز، اور اسکرپٹس یا ایڈیٹرز جو CLI کو `PATH` پر پاتے ہیں۔ `omarchy agent account use work` سے switch کریں (اور `omarchy agent account use main` سے واپس)، یا پینل میں کسی اکاؤنٹ کا نمبر دبا کر پھر `Enter` دبا کر (یا اس کے ستارے پر کلک کر کے)۔ چلتے ہوئے Claude سیشنز بھی switch ہوتے ہیں، ان کے اگلے پیغام سے: ہر Claude سیشن `~/.claude` میں چلتا ہے، جس میں ہمیشہ فعال اکاؤنٹ کا سائن ان ہوتا ہے۔ پرانی Omarchy کے ذریعے کسی اکاؤنٹ کے اپنے فولڈر میں شروع کیا گیا Claude سیشن وہ سائن ان اس وقت تک رکھتا ہے جب تک وہ بند نہ ہو، لہٰذا switch ان سیشنز کا نام لیتا ہے اور ان کے ختم ہونے پر خود مکمل ہو جاتا ہے۔ چلتے ہوئے Codex اور Grok سیشنز اس اکاؤنٹ پر رہتے ہیں جس سے وہ شروع ہوئے تھے۔ گفتگو کی تاریخ، ترتیبات، skills، اور plugins اکاؤنٹس میں مشترکہ ہوتے ہیں، لہٰذا اسی فولڈر میں `claude --continue` وہیں سے اٹھاتا ہے جہاں آپ نے نئے اکاؤنٹ پر چھوڑا تھا۔

ایک سے زیادہ اکاؤنٹ کے ساتھ، پینل ہر اکاؤنٹ کی حدود ساتھ ساتھ دکھاتا ہے، استعمال میں ہونے والے پر بھرا ہوا ستارہ۔ Omarchy آپ کو مطلع کرتا ہے جب فعال اکاؤنٹ کسی حد کا 95% گزار لیتا ہے، اور اطلاع پر کلک کرنا سب سے زیادہ گنجائش والے اکاؤنٹ پر switch کر دیتا ہے۔ یہ کبھی خود سے switch نہیں کرتا۔ حد `omarchy agent account threshold 90` سے تبدیل کریں۔ اگر ہر اکاؤنٹ حد سے اوپر ہے، تو آپ کو ایک بار اس کے بارے میں سنایا جائے گا، ساتھ یہ بھی کہ کون سا اکاؤنٹ سب سے پہلے آزاد ہوتا ہے۔ جب فعال اکاؤنٹ اپنی حد کے 15 پوائنٹس کے اندر ہوتا ہے (ڈیفالٹ پر 80%)، تو اس کی حدود ہر 15 کے بجائے ہر تین منٹ میں چیک کی جاتی ہیں۔

`omarchy agent account list` ہر اکاؤنٹ اور اس کی تازہ ترین حدود دکھاتا ہے، `omarchy agent account remove work` ایک کو بھول جاتا ہے، اور `omarchy agent account rename primary Hey` ایک کا نام بدلتا ہے (یا پینل میں کسی اکاؤنٹ کے نام پر کلک کریں)۔ یہ کمانڈز آپ کے ڈیفالٹ ایجنٹ کے اکاؤنٹس پر کام کرتی ہیں؛ دوسرے فراہم کنندہ تک پہنچنے کے لیے پہلے اس کا نام لیں، جیسے `omarchy agent account use codex side`۔ آپ کا پہلے سے موجود لاگ ان `~/.claude` یا `~/.codex` میں _Main_ اکاؤنٹ ہے۔ Codex کا وہیں رہتا ہے جہاں ہے؛ Claude کا اس وقت اپنے فولڈر میں انتظار کرتا ہے جب دوسرا اکاؤنٹ فعال ہو۔ تقریباً آٹھ گھنٹے سے زیادہ غیر استعمال شدہ اکاؤنٹ _Sign-in required_ دکھا سکتا ہے؛ پینل میں ہی اس اکاؤنٹ کو دوبارہ سائن ان کرنے کے لیے اس پر کلک کریں، یا اس پر switch کریں اور سیشن شروع کریں، جو سائن ان کو خود تازہ کر دیتا ہے۔ `claude mcp add` سے شامل کیے گئے MCP سرورز ہر Claude اکاؤنٹ تک پہنچتے ہیں، کیونکہ وہ سب `~/.claude` میں چلتے ہیں؛ Codex اور Grok کے لیے، جب اکاؤنٹ شامل کیا گیا تھا اس وقت آپ کے پاس موجود سرورز اس کے ساتھ آتے ہیں، لیکن بعد والے صرف اس اکاؤنٹ تک پہنچتے ہیں جس میں آپ نے انہیں شامل کیا تھا۔ Claude Desktop اپنا سائن ان رکھتا ہے، اور CLI binary کے مطلق راستے کے ساتھ کنفیگر شدہ Codex یا Grok ٹولز switch کی پیروی نہیں کرتے۔ ایک واضح `CLAUDE_CONFIG_DIR`، `CODEX_HOME`، یا `GROK_HOME` منتخب اکاؤنٹ پر ترجیح لیتا ہے۔

### کریش تشخیص

Omarchy process کریشز کے لیے systemd-coredump پر نظر رکھتا ہے۔ جب آپ ڈیفالٹ ایجنٹ منتخب کر لیں، تو آپ کا کوئی بھی پروگرام جو core dump کرے "Process crashed" اطلاع لاتا ہے — اس پر کلک کریں، اور کریش آپ کے ڈیفالٹ ایجنٹ کے حوالے کیا جاتا ہے Omarchy کی omarchy-diagnose-crash skill کے ساتھ، جو ایجنٹ کو core dump سے حقائق قائم کرنے اور یہ فیصلہ کرنے میں رہنمائی کرتی ہے کہ آیا کریش upstream رپورٹ کرنے کے قابل ہے۔ آپ اسے `coredumpctl list` سے کسی بھی PID کے خلاف ہاتھ سے بھی چلا سکتے ہیں `omarchy agent crash <pid>` کے ساتھ۔

نگرانی بطور ڈیفالٹ آن ہے۔ اسے _Trigger > Toggle > Crash Capture Off_ کے تحت بند کریں (یا `omarchy toggle crash-capture` کے ساتھ) اور اطلاعات رک جاتی ہیں؛ `omarchy agent crash <pid>` ہاتھ سے پھر بھی کام کرتا ہے۔

کریشز کو ایک وقت میں ایک پروگرام کے لیے خاموش بھی کیا جا سکتا ہے، جو تشخیص آخر میں آپ کو پیش کرتی ہے۔ `omarchy crash mute hyprland` صرف اس پروگرام کے لیے اطلاعات روکتا ہے، `omarchy crash mute hyprland off` انہیں واپس لاتا ہے، اور `omarchy crash mute` اکیلا وہ فہرست دیتا ہے جو آپ نے خاموش کیا ہے۔ یہ binary کا راستہ اس کے نام کی طرح خوشی سے لیتا ہے، لہٰذا `omarchy crash mute /usr/bin/hyprland` وہی کام کرتا ہے۔ کسی ایسے نام کو quote کریں جس میں space ہو، جیسے `omarchy crash mute 'Some App'`۔ باقی سب پھر بھی مطلع کرتا ہے، اور خاموش پروگرام پھر بھی کریش ہوتا ہے — یہ یاد دہانی چھپاتا ہے، یہ کچھ ٹھیک نہیں کرتا۔

### Desktop ایپس

_Install > AI_ مینو میں چند گرافیکل AI ایپس بھی ہیں: Amp Desktop، Antigravity Desktop، ChatGPT desktop app، Claude desktop app (Anthropic کا Linux beta، Chat، Cowork، اور Claude Code ٹیبز کے ساتھ)، Grok Bot xAI کے ماڈلز کے ساتھ چیٹ کے لیے، Herdr Desktop، Hermes Desktop، OpenClaw، Perplexity desktop app، اور T3 Code۔ Grok Bot desktop چیٹ ایپ ہے۔ کوڈنگ ایجنٹ `grok` کمانڈ ہے۔

Hermes Desktop وہ ہے جس کے بارے میں جاننا ضروری ہے، کیونکہ ایک مشین میں ایک Hermes ہوتا ہے، اور وہ ایپ کا ہوتا ہے: Hermes ہمیشہ صرف ایپ کے ذریعے انسٹال ہوتا ہے، اور ڈیفالٹ ایجنٹ جو `hermes` کمانڈ چلاتا ہے وہ ایپ کی ہوتی ہے۔ Hermes کو ڈیفالٹ ایجنٹ کے طور پر منتخب کرنا وہی چیز انسٹال کرتا ہے جو _Install > AI_ اندراج کرتا ہے: پیکیج، اور Hermes کے اپنے انسٹالر کے ذریعے سیٹ اپ کردہ `~/.hermes` کے تحت ایک Hermes runtime، جو پہلی بار چند منٹ لیتا ہے۔ وہ runtime وہ ایک Hermes ہے جسے terminal `hermes` کمانڈ، ڈیفالٹ ایجنٹ اور ایپ سب استعمال کرتے ہیں، اور یہ Omarchy ریلیز کا انتظار کرنے کے بجائے `hermes update` کے ساتھ خود کو اپ ڈیٹ کرتا ہے۔ اسے انسٹال کرنا Hermes کو Omarchy تھیم بھی `omarchy` نامی skin کے طور پر دیتا ہے، جس کی ہر Hermes سطح پیروی کرتی ہے جب آپ تھیمز تبدیل کرتے ہیں؛ اگر آپ چاہتے ہیں کہ ایسا نہ ہو تو Hermes کی Appearance ترتیبات کے تحت یا `/skin` کے ساتھ کوئی اور منتخب کریں، اور Omarchy اس انتخاب کو چھوڑ دیتا ہے۔ _Remove > AI_ کے تحت ایپ کو ہٹانا پہلے Hermes کو بند کرتا ہے، gateway سمیت، اس runtime کو اس کے ساتھ لے جاتا ہے، اور آپ کی چیٹس، یادیں، اور وہ skills جو Hermes نے خود کے لیے لکھی تھیں رکھتا ہے جب تک آپ اسے دوسری صورت نہ بتائیں: یہ پوچھتا ہے، بطور ڈیفالٹ نہیں، کہ آیا وہ ڈیٹا اور آپ کی کنکشن ترتیبات بھی جانی چاہئیں۔

OpenClaw کا desktop تجربہ اس کا Control UI ہے، جو اس کے اپنے مقامی gateway کی حمایت یافتہ web app کے طور پر کھلتا ہے۔ OpenClaw `~/.openclaw` میں رہتا ہے اور خود کو اپ ڈیٹ کرتا ہے: Control UI کا "Update Gateway" بٹن استعمال کریں یا `openclaw update` چلائیں، اور gateway نئے ورژن پر دوبارہ شروع ہوتا ہے۔ Omarchy صرف وہ ریلیز منتخب کرتا ہے جس سے تازہ انسٹال شروع ہوتا ہے۔ OpenClaw آپ کا ڈیفالٹ ایجنٹ بھی ہو سکتا ہے: اسے `omarchy default agent openclaw` کے ساتھ منتخب کرنا `~/.openclaw` میں وہی کاپی سیٹ اپ کرتا ہے، اور ایجنٹ OpenClaw کا terminal UI اس کے gateway سے منسلک کھولتا ہے۔ _Remove > AI_ کے تحت OpenClaw کو ہٹانا gateway سروس اور ایپ کو اس کے ساتھ لے جاتا ہے اور پھر پوچھتا ہے کہ آیا `~/.openclaw` بھی جانا چاہیے، کیونکہ اس میں آپ کی چیٹس اور اسناد OpenClaw خود اور اس کے ڈاؤن لوڈ کردہ plugin runtimes کے ساتھ ہوتے ہیں؛ ڈیفالٹ اسے رکھتا ہے، اور OpenClaw دوبارہ انسٹال کرنا اسے واپس اٹھا لیتا ہے۔

Herdr Desktop [Herdr](https://herdr.dev) desktop ایپ ہے: terminals اور کوڈنگ ایجنٹس کے spaces، tabs، اور panes جو ونڈو بند کرنے پر اس کے core میں چلتے رہتے ہیں۔ یہ پیکیج کے بجائے Herdr کے اپنے انسٹالر سے آتا ہے، لہٰذا یہ `~/.local/share/herdr-app` میں رہتا ہے، جب آپ کے پاس ابھی کوئی نہ ہو تو `~/.local/bin/herdr-core` میں اپنا core ساتھ لاتا ہے، اور دونوں خود کو اپ ڈیٹ کرتے ہیں۔ یہ اس `herdr` کمانڈ کے ساتھ بیٹھتا ہے جو Omarchy `Super + Ctrl + Return` پر فراہم کرتا ہے اسے بدلنے کے بجائے، اور اس کمانڈ کی براہ راست keys حاصل کرتا ہے: `Alt + Return` اور `Alt + Shift + Return` pane کو نیچے یا دائیں تقسیم کرتے ہیں، `Alt + Escape` اسے بند کرتا ہے، `Ctrl + Alt + Arrow` panes کے درمیان منتقل کرتا ہے، `Alt + 1..9` اور `Alt + Left/Right` tab منتخب کرتے ہیں، اور `Alt + Up/Down` spaces کے درمیان منتقل کرتے ہیں۔ `Ctrl + 1..9` space منتخب کرتا ہے اور `Alt + Shift + Up/Down` ایجنٹس میں قدم بڑھاتا ہے۔ `Ctrl + Space` prefix keys صرف terminal تک رہتی ہیں، کیونکہ ایپ ترتیب کے لیے سادہ Ctrl key نہیں رکھ سکتی۔ Omarchy یہ `~/.config/herdr-app/keys.json` میں لکھتا ہے، اور `omarchy-refresh-herdr-app` انہیں واپس رکھتا ہے۔ اسے انسٹال کرنا Herdr کی Omarchy تھیم منتخب کرتا ہے، جو اس کے بعد سے آپ کی Omarchy تھیم کی پیروی کرتی ہے۔ Herdr light موڈ کے لیے ایک تھیم اور dark کے لیے ایک رکھتا ہے، لہٰذا dark اور light Omarchy تھیم کے درمیان switch کرنے کے بعد، دوسرے موڈ کے لیے Herdr کے تھیم picker میں Omarchy ایک بار پھر منتخب کریں۔

T3 Code پیکیج کے بجائے `~/.local/share/t3code` میں اس کی آفیشل AppImage ریلیز سے چلتا ہے، لہٰذا یہ خود کو اپ ڈیٹ کرتا ہے۔ اسے انسٹال کرنا پوچھتا ہے کہ Stable یا Nightly چینل پر شروع کرنا ہے؛ بعد میں T3 Code کی ترتیبات میں switch کریں۔ آپ کے threads اور ترتیبات `~/.t3` میں رہتے ہیں، اور _Remove > AI_ کے تحت T3 Code کو ہٹانا انہیں اس کے ساتھ لے جاتا ہے۔

### مقامی ماڈلز

اپنے کوڈنگ ایجنٹس کے لیے اپنے مشین پر ایک open ماڈل چلائیں۔ آپ کے prompts اور کوڈ مشین پر رہتے ہیں؛ ماڈل کو بھیجی گئی کوئی چیز اسے نہیں چھوڑتی۔ اس سے شروع کریں:

```bash
omarchy models use best text
```

یہ اس مشین کے لیے بہترین text ماڈل سیٹ اپ کرتا ہے، وہ قسم جو آپ کے ایجنٹس استعمال کرتے ہیں۔ Image، video اور music ماڈلز کا اپنا بہترین ہوتا ہے: `omarchy models use best image`، `video` یا `music`۔ اس مشین کے لیے ہر قسم کی پسند دیکھنے کے لیے `omarchy models use best` چلائیں۔

یا ایجنٹس پینل میں + منتخب کریں: _Use a local model_ کے تحت یہ ہر کوڈنگ ماڈل کی فہرست دیتا ہے جو اس مشین میں فٹ ہوتا ہے، تجویز کردہ پہلے۔ Podman، جو ماڈلز چلاتا ہے، Omarchy کے ساتھ آتا ہے، اسی طرح NVIDIA مشین پر NVIDIA کا container toolkit بھی، جو انہیں GPU دیتا ہے؛ اگر کوئی غائب ہو، تو پہلا سیٹ اپ اسے انسٹال کرتا ہے۔ پھر Omarchy اس مشین کے لیے تجویز کردہ ماڈل منتخب کرتا ہے، اسے ڈاؤن لوڈ کرتا ہے، اور اسے شروع کرتا ہے۔ دسیوں GB کے ڈاؤن لوڈ اور ماڈل چلتے وقت مشین کی زیادہ تر میموری استعمال ہونے کی توقع کریں: Flash Next اپنے مکمل 256K context کے ساتھ تقریباً 100 GiB استعمال کرتا ہے۔ اگر دوسرے ماڈلز اسے درکار میموری رکھتے ہیں، تو یہ بند حالت میں سیٹ اپ ہوتا ہے، ایک کو بند کرنے پر شروع ہونے کے لیے تیار۔ ماڈل logout پر رک جاتا ہے؛ جب آپ کو کسی اور چیز کے لیے میموری درکار ہو تو اسے خود بند کر دیں۔

`omarchy models list` اختیارات دکھاتا ہے اور بتاتا ہے کہ کچھ کیوں فٹ نہیں ہوتے۔ دوسرا سیٹ اپ کرنے کے لیے `omarchy models use <recipe>` چلائیں۔ آج، `qwen3.8-flash-next-gufo` اور `qwen3.8-27b-gufo` 128 GB Strix Halo مشینوں کے لیے دستیاب ہیں؛ 27B تقریباً 40 GiB لیتا ہے، لہٰذا یہ دوسرے کام کے لیے جگہ چھوڑتا ہے۔ Intel کے Arc B390 والے 64 GB لیپ ٹاپ پر، `qwen3.6-35b-a3b-llamacpp` تقریباً 30 GiB میں چلتا ہے۔ نئی recipes اور تجاویز پیکیج کے ذریعے `omarchy update` کے ساتھ آتی ہیں۔

آپ جو کوڈنگ ماڈل شامل کرتے ہیں اسے ایجنٹس پینل میں اپنی لائن ملتی ہے، آپ کی سبسکرپشنز کے ساتھ: اسے شروع کرنے کے لیے play، اسے روکنے اور اس کی میموری آزاد کرنے کے لیے pause، چلتے وقت اسے اپنے tailnet پر دوسری مشینوں کے ساتھ شیئر کرنے کے لیے Tailscale نشان، اور اس پر اپنا ایجنٹ کھولنے کے لیے terminal بٹن۔ اس کی لائن ڈاؤن لوڈ، لوڈ یا رکنا جیسے ہوتا ہے دکھاتی ہے، اور کہتی ہے جب شروع کرنے کے لیے کافی مفت میموری نہ ہو، یا جب یہ غلطی کے ساتھ رکے تو اس کے logs سے لنک کرتی ہے۔ کئی ایک ساتھ چل سکتے ہیں جب وہ میموری میں ایک ساتھ فٹ ہوں۔ منتخب لائن پر Delete دبائیں تاکہ ماڈل اس مشین سے ہٹ جائے، ڈاؤن لوڈ سمیت؛ + اسے دوبارہ سیٹ اپ کر سکتا ہے۔ terminal سے سیٹ اپ کردہ کوڈنگ ماڈل + کے تحت انتظار کرتا ہے جب تک آپ اسے شامل نہ کریں، اور اسی طرح وہ ماڈلز جو آپ نے جوڑی ہوئی مشین (`omarchy models pair <host>`) چلاتی ہے۔

آپ جو ہر کوڈنگ ماڈل سیٹ اپ کرتے ہیں اسے app launcher میں بھی اپنا اندراج ملتا ہے، ماڈل کے نام کے تحت اور اس کے بنانے والے کے logo کے ساتھ، اسی طرح جیسے Claude، Codex یا Grok میں سائن ان کرنا ایک شامل کرتا ہے۔ یہ اس ماڈل پر آپ کا ایجنٹ کھولتا ہے، اور اگر ماڈل نہیں چل رہا تو پہلے اسے شروع کرتا ہے: terminal اسے لوڈ ہوتا دکھاتا ہے اور تیار ہونے پر ایجنٹ کے حوالے کرتا ہے۔ ماڈل ہٹانا اس کا اندراج ہٹا دیتا ہے۔

ہر ماڈل کوڈنگ کے لیے نہیں ہے۔ Image، video اور music ماڈلز اس کے بجائے Fantasi میں کھلتے ہیں، Omarchy کی ایپ اس مشین پر چلنے والے ماڈل سے تصاویر، video اور music بنانے کے لیے، اور وہاں یا `omarchy models` کے ساتھ ان کا انتظام کیا جاتا ہے۔

ایک ماڈل بالکل ویسا ہی چلتا رہتا ہے جیسا اسے سیٹ اپ کیا گیا تھا، لہٰذا Omarchy اپ ڈیٹ آپ کے ایجنٹس کے تحت کبھی ایک کو دوبارہ شروع نہیں کرتا۔ جب Omarchy کے پاس آپ کے سیٹ اپ کردہ ماڈل کے لیے نیا runtime یا نئے weights ہوں، تو اس کی لائن اپ ڈیٹ بٹن دکھاتی ہے: اسے دبائیں اور ماڈل پس منظر میں دوبارہ سیٹ اپ ہوتا ہے، صرف وہ ڈاؤن لوڈ کرتا ہے جو بدلا ہے، اور نئے ورژن پر دوبارہ شروع ہوتا ہے۔ جو ماڈل بند تھا وہ بند رہتا ہے۔ `omarchy models update` terminal سے ہر ماڈل کے لیے یہی کرتا ہے۔

کمانڈ لائن سے، `omarchy models start <recipe>` اور `omarchy models stop <recipe>` یہی کرتے ہیں، `omarchy models status` ہر ماڈل دکھاتا ہے، اور `omarchy agent --local-model <recipe>` اس ماڈل کو pi میں کھولتا ہے، چاہے آپ کا ڈیفالٹ ایجنٹ کچھ بھی ہو۔ اپنے مقامی ماڈل کو وہ بنانے کے لیے جو ایجنٹ hotkey، Quake console، اور _Make something_ کھولتے ہیں، `omarchy default agent local` چلائیں یا ایجنٹس پینل میں چلتے ہوئے ماڈل کو ستارہ لگائیں۔ pi ان تمام ماڈلز کی فہرست بھی دیتا ہے جو آپ نے سیٹ اپ کیے ہیں، اور جو آپ نے جوڑی ہوئی مشینوں پر ہیں، اپنے ماڈل picker میں، لہٰذا سادہ `pi` بھی ان تک پہنچتا ہے۔ کوئی بھی OpenAI-compatible کلائنٹ بھی منسلک ہو سکتا ہے: `status` ہر ماڈل کا پتہ دکھاتا ہے (پہلا `http://127.0.0.1:11435/v1` ہے)، recipe نام ماڈل ہے، اور key `~/.config/omarchy/agent-local/key` میں ہے۔

`omarchy models remove <recipe>` ایک ماڈل اور وہ ڈاؤن لوڈز حذف کرتا ہے جو کوئی دوسرا ماڈل استعمال نہیں کرتا۔

Third-party runtimes کو ان کے publisher کے ساتھ لیبل کیا جاتا ہے۔ Omarchy ہر ماڈل کو network رسائی کے بغیر چلاتا ہے۔

### مقامی LLMs

Omarchy مقامی LLM ماڈلز چلانے کے دو طریقے تجویز کرتا ہے: LM Studio اور Ollama۔ LM Studio open-weight ماڈلز تلاش کرنے، انہیں انسٹال کرنے، اور انہیں چلانے کے لیے GUI انٹرفیس فراہم کرتا ہے۔ یہ آسانی سے شروع کرنے کا بہترین طریقہ ہے۔ Ollama اسی طرح کرنے کے لیے CLI پیش کرتا ہے۔ لیکن اگر آپ مقامی ماڈلز میں نئے ہیں، تو میں LM Studio سے شروع کروں گا۔ آپ Omarchy Menu میں _Install > AI_ کے تحت دونوں میں سے کوئی انسٹال کر سکتے ہیں۔

### Omarchy کی skills

ایجنٹ skills AI کو مخصوص ٹولز مخصوص طریقے سے استعمال کرنے میں مدد دیتی ہیں، اور Omarchy ان میں سے سات فراہم کرتا ہے۔ omarchy skill سسٹم کو اپنی پسند کے مطابق بنانے کا احاطہ کرتی ہے، جیسے اپنی Hyprland config میں تبدیلی یا بار کو ایڈجسٹ کرنا۔ omarchy-make-theme، omarchy-make-plugin، omarchy-make-app، اور omarchy-make-game کچھ نیا بنانے کا احاطہ کرتے ہیں، omarchy-contribute upstream بگ رپورٹ کرنے یا fix بھیجنے کا احاطہ کرتی ہے، اور omarchy-diagnose-crash کریش کے core dump پر کام کرتی ہے۔ یہ Claude Code (`~/.claude/skills`)، Codex (`~/.codex/skills`)، Pi (`~/.pi/agent/skills`)، Antigravity (`~/.gemini/config/skills`)، Hermes (`~/.hermes/skills` اور ہر `~/.hermes/profiles/*/skills`)، اور عام `~/.agents/skills` مقام کے لیے skill ڈائرکٹریوں میں symlinked ہیں، لہٰذا زیادہ تر harnesses انہیں خودکار طور پر اٹھا لیتے ہیں۔ آپ کا اپنا اسی نام کا skill فولڈر ترجیح لیتا ہے۔

لیکن آپ کو ان skills کو تجرباتی سمجھنا چاہیے۔ مختلف ماڈلز اسے مختلف اثر کے ساتھ استعمال کریں گے۔ بہتر ہے پہلے plan موڈ میں چلائیں، تاکہ آپ کو اندازہ ہو کہ ایجنٹ کیا بدلنا چاہے گا۔ اور پھر تبدیلیاں واپس لینے یا حتیٰ کہ `omarchy reinstall configs` چلانے کے لیے تیار رہیں، اگر ایجنٹ سب کچھ خراب کر دے۔
