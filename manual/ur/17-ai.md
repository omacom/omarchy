### ایجنٹس انسٹال اور اپڈیٹ کرنا

Hermes اور OpenClaw کے سوا، یہ ایجنٹس mise کی سست انسٹالیشن استعمال کرتے ہیں: پہلا لانچ CLI انسٹال کرتا ہے، اور بعد کے لانچز اسی کو دوبارہ استعمال کرتے ہیں۔ mise انسٹال شدہ ایجنٹ کے لیے نئی ریلیز بھی زیادہ سے زیادہ ہر چار گھنٹے میں ایک بار چیک کرتا ہے، شروع ہونے سے ذرا پہلے یا پس منظر میں shell prompt پر۔ اگر وہ اپڈیٹ ناکام ہو جائے یا آپ آف لائن ہوں، تو انسٹال شدہ ورژن چلتا ہے۔ `omarchy update` انسٹال شدہ ایجنٹس کو باقی Omarchy کے ساتھ اپڈیٹ کرتا ہے، اور `mup` صرف mise کے زیر انتظام ٹولز کو اپڈیٹ کرتا ہے۔

کسی ایجنٹ کا اپنا اپڈیٹر، جیسے `claude update`، `codex update`، یا کسی ایپ میں اپڈیٹ بٹن، mise کے زیر انتظام انسٹال کو اپڈیٹ نہیں کرتا۔ `codex update` ناکام ہو جاتا ہے، اور `claude update` کامیابی کی اطلاع دیتے ہوئے ایک الگ کاپی انسٹال کر سکتا ہے جسے mise ٹریک نہیں کرتا۔ اگر آپ اس کے بجائے کسی ایجنٹ کا مقامی انسٹالر اور اپڈیٹر استعمال کرنا چاہتے ہیں، تو اسے `disable_tools` میں شامل کریں؛ دیکھیں [پہلے سے انسٹال شدہ CLI ٹولز](18-development-tools.md#preinstalled-cli-tools)۔

تمام کنفیگر شدہ سست ٹولز کو ضرورت پڑنے سے پہلے انسٹال کرنے کے لیے، `mise install --include-lazy` چلائیں۔ اس میں ایجنٹس کے ساتھ ساتھ Omarchy کے دیگر ڈیفالٹ CLI ٹولز بھی شامل ہیں۔ ایک ٹول انسٹال کرنے یا اپنی انسٹالیشن استعمال کرنے کے لیے [پہلے سے انسٹال شدہ CLI ٹولز](18-development-tools.md#preinstalled-cli-tools) دیکھیں۔

`grok` mise کے فرسٹ پارٹی `grok` پیکیج کے ذریعے انسٹال ہوتا ہے، اسی طرح جیسے `claude` اور `codex`۔ `grok` چلائیں، یا اسے agents پینل میں ستارہ زد کریں۔ x.ai پر `curl | bash` انسٹالر کو چھوڑ دیں۔ وہ راستہ `~/.grok/bin` میں ایک دوسری کاپی رکھتا ہے، اسے `PATH` کے شروع میں شامل کر دیتا ہے، اور Omarchy کے wrapper کو اوور رائٹ کر دیتا ہے۔

`dsh` اپنا browser UI `127.0.0.1:3080` پر کھولتا ہے، جس میں لانچ ڈائرکٹری اس کا ڈیفالٹ workspace ہوتی ہے۔ اس کا browser UI کوئی ابتدائی prompt نہیں لیتا، چنانچہ `omarchy agent prompt` اسے آپ کے clipboard پر موجود prompt کے ساتھ کھولتا ہے تاکہ آپ اسے پیسٹ کر سکیں۔ Omarchy اسے DeepSeek کے no-approval permission preset کے ساتھ شروع کرتا ہے۔ DeepSeek Harness جب آپ اس کا سرکاری ماڈل API استعمال کرتے ہیں تو سیشن لاگز DeepSeek کو اپ لوڈ کرتا ہے؛ اسے اپنے browser UI میں _Settings > General > Upload Session Log_ کے تحت بند کر دیں۔ آپ جو فیڈبیک اسے بھیجتے ہیں وہ بھی سیشن کے ساتھ اپ لوڈ ہو جاتا ہے، الا یہ کہ آپ اسے `DSH_TELEMETRY_MODE=DISABLED` کے ساتھ شروع کریں۔

### ڈیفالٹ ایجنٹ

agents پینل میں کسی ایجنٹ کے پاس موجود ستارے سے اپنا ڈیفالٹ ایجنٹ منتخب کریں، جو ڈیفالٹ پر بھرا ہوا ہوتا ہے، یا `omarchy default agent <name>` کے ساتھ، جو وہاں لائن نہ رکھنے والے کسی harness کو بھی لیتا ہے۔ اگر ایجنٹ ابھی انسٹال نہیں ہوا ہے، تو اسے منتخب کرنا پہلے اسے انسٹال کرتا ہے، اور اسے app launcher میں Agent کے پاس اپنا لانچر بھی مل جاتا ہے۔ ایک تازہ Omarchy آپ کو ایک بار کی اطلاع کے ذریعے ایک سیٹ اپ کرنے کی دعوت دیتا ہے، جو agents پینل کھولتی ہے۔

Claude منتخب کرنا Chromium، Chrome، Brave، Brave Origin، اور Edge کے لیے اس کا browser extension سیٹ اپ کرنے کی بھی کوشش کرتا ہے۔ extension کا سیٹ اپ تمام صارفین پر لاگو ہوتا ہے اور آپ سے آپ کا سسٹم پاس ورڈ مانگ سکتا ہے؛ منسوخ کرنا یا ناکام extension انسٹال بھی Claude کو منتخب اور لانچ کر دیتا ہے۔ اپنا براؤزر دوبارہ شروع کریں، اشارہ ملے تو extension فعال کریں، اور اسے جوڑنا مکمل کرنے کے لیے Claude میں سائن ان کریں۔ کنکشن چیک کرنے کے لیے Claude میں `/chrome` چلائیں۔ Firefox اور Zen اس extension کی حمایت نہیں کرتے۔ اگر اس سیٹ اپ کے شامل ہونے سے پہلے ہی Claude آپ کا ڈیفالٹ تھا، تو extension انسٹال کرنے کے لیے اسے دوبارہ منتخب کریں۔

منتخب کرنے کے بعد، `Super + Shift + Ctrl + A` ڈیفالٹ ایجنٹ کو ایک مخصوص ٹرمینل ونڈو میں لانچ کرتا ہے (یا اگر آپ نے ابھی انتخاب نہیں کیا ہے تو picker لے آتا ہے)۔ آپ اسے `omarchy agent prompt "Review this project"` کے ساتھ براہ راست کسی کام میں بھی لانچ کر سکتے ہیں۔ Freebuff اور DeepSeek Harness کوئی ابتدائی prompt نہیں لیتے، چنانچہ وہ اس کے بجائے آپ کے clipboard پر موجود prompt کے ساتھ کھلتے ہیں تاکہ آپ اسے پیسٹ کر سکیں۔ اس طرح لانچ کیے گئے ایجنٹس اپنے متعلقہ don't-stop-to-ask طریقوں میں بے نظار چلتے ہیں، چنانچہ تیار رہیں کہ وہ واقعی کچھ کر گزریں گے! MiniMax Code کے interactive سیشنز کے لیے ایسا کوئی طریقہ نہیں ہے، چنانچہ وہ معمول کے مطابق اجازتیں مانگتا ہے۔ اور چونکہ ایجنٹس آپ کی home ڈائرکٹری کے لیے اعتماد یاد رکھنے سے انکار کرتے ہیں، اس لیے `$HOME` سے لانچز اس کے بجائے `~/Work` میں شروع ہوتے ہیں۔

ٹرمینل شارٹ کٹس بھی ہیں: `a` موجودہ ٹرمینل میں ڈیفالٹ ایجنٹ کو inline چلاتا ہے، جب کہ `c`، `cx`، `cy`، اور `ca` OpenCode، Claude Code، Codex، اور Antigravity کو براہ راست شروع کرتے ہیں (ایک بار پھر ان کے auto-approving طریقوں میں)۔ تھیم کی تبدیلیاں ایجنٹس کے ساتھ بھی ہم آہنگ ہو جاتی ہیں: Claude Code، Pi، OpenCode، اور Hermes (جب Omarchy نے اسے انسٹال کر لیا ہو) سب اس وقت ساتھ چلتے ہیں جب آپ Omarchy تھیم تبدیل کرتے ہیں۔

### آپ کی ایجنٹ ہدایات

ہر ایجنٹ کے لیے ذاتی قواعد `~/.agents/AGENTS.md` میں جاتے ہیں، `~/.agents/skills` میں مشترکہ اسکلز کے پاس۔ اسے agents پینل میں + کے پاس دستاویز کے آئیکن سے کھولیں، یا `omarchy agent instructions --edit` کے ساتھ، جو اسے ہر اس harness میں بھی لنک کر دیتا ہے جو اپنی عالمی فائل رکھتا ہے: `~/.claude/CLAUDE.md`، `~/.codex/AGENTS.md`، `~/.pi/agent/AGENTS.md`، `~/.config/opencode/AGENTS.md`، Copilot کی `~/.copilot/copilot-instructions.md`، اور اسی طرح۔ Crush اور Amp `~/.config/AGENTS.md` لنک پڑھتے ہیں، جب کہ omp، Kimi، اور DeepSeek Harness `~/.agents/AGENTS.md` کو براہ راست پڑھتے ہیں۔ ڈیفالٹ ایجنٹ منتخب کرنا اسے بھی لنک کر دیتا ہے۔ کوئی ہدایات فائل جو آپ کے پاس پہلے سے تھی، اگر ابھی کوئی مشترکہ فائل نہیں تھی تو وہی مشترکہ بن جاتی ہے؛ ورنہ اسے لنک کے پاس `.bak` کے طور پر رکھا جاتا ہے۔ ایک اور ایجنٹ انسٹال کرنے کے بعد دوبارہ لنک کرنے کے لیے `omarchy agent instructions` چلائیں۔

### agents پینل

اوپر والی بار میں ایک agents آئیکن ہے۔ ایجنٹ سیٹ اپ کرنے سے پہلے، اس کا پینل شروع کرنے کے تین طریقے پیش کرتا ہے: Claude، Codex، Grok، Gemini، Muse، Cursor، یا Copilot سبسکرپشن میں سائن ان کریں، یا More کے تحت OpenCode Go، MiniMax، Synthetic، یا Z.ai کوڈنگ پلان؛ Fireworks، OpenCode Zen and Go، OpenRouter کے ساتھ جتنا استعمال کریں اتنا ادا کریں، یا More کے تحت DeepSeek یا کوئی اور فراہم کنندہ جس میں OpenCode سائن ان کرتا ہے، سب OpenCode میں چلتے ہیں؛ یا اپنے کمپیوٹر کے لیے بہترین ماڈل چلائیں، جب کوئی اس میں فٹ آتا ہو۔ آپ جو پہلا مکمل کرتے ہیں وہ آپ کا ڈیفالٹ ایجنٹ بن جاتا ہے، اور پینل میں + بعد میں وہی تین پیش کرتا ہے۔ اس کے بعد، پینل ہر سبسکرپشن کو ایک صفحے پر رکھتا ہے: ہر ایجنٹ اور اکاؤنٹ اس کے پلان کے ساتھ، اس کی 5-hour سیشن اور ہفتہ وار حدود میں سے ہر ایک کے لیے ایک میٹر جس میں اس کے ری سیٹ ہونے تک کا وقت ہو (درست فیصد کے لیے ہوور کریں)، یا باقی پری پیڈ بیلنس، ایک لائن کے تحت جو آپ کے ان سب میں استعمال کے درمیان گردش کرتی ہے، جیسے اس ہفتے کے ٹوکنز اور آپ کا سب سے زیادہ استعمال شدہ ماڈل۔ _Make something cool_ کے تحت یہ نئی تھیم، پلگ ان، ایپ، یا گیم کے لیے ابتدائی prompts پیش کرتا ہے جو کام آپ کے ڈیفالٹ ایجنٹ کے سپرد کرتے ہیں۔ ایپس اسی طرح بنائی جاتی ہیں جس طرح Omarchy کی اپنی Hype، Monologue، اور Omacut ہیں، C++ اور Qt Quick میں، omarchy-make-app ایجنٹ اسکل کی پیروی کرتے ہوئے، اور انہیں درکار compiler اور Qt اجزا انسٹال شدہ آتے ہیں۔ گیمز `~/Games/vibes` میں ایک واحد three.js صفحہ ہوتی ہیں، omarchy-make-game ایجنٹ اسکل کی پیروی کرتے ہوئے، اور سب موجودہ تھیم میں ایک Game Vibes لانچر سے کھلتی ہیں؛ وہ ویب سے three.js لوڈ کرتی ہیں، چنانچہ انہیں شروع ہونے کے لیے کنکشن چاہیے۔ Claude Code، Codex، Grok، Kimi، Cursor اور اس کا Grok Bot الاؤنس، GitHub Copilot، Muse، Gemini (Antigravity کے ذریعے)، اور Devin اپنی حدود کے ساتھ باکس سے باہر شامل ہیں، Kimchi اپنے پلان، پری پیڈ کریڈٹس، اور اخراجات کے بجٹس کے ساتھ، اور Hermes، Mistral Vibe، اور Qwen Code جب آپ انہیں استعمال کر چکے ہوں تو اپنے سیشنز اور ٹوکنز دکھاتے ہیں۔ فراہم کنندہ پلانز اور کیز جو آپ pi، omp، یا opencode کے ذریعے استعمال کرتے ہیں وہ بھی ظاہر ہوتے ہیں: OpenCode Zen and Go، Z.ai GLM Coding Plan، Ollama Cloud، MiniMax Token Plan، اور Synthetic اپنی حدود کے ساتھ؛ OpenRouter اور DeepSeek اپنے پری پیڈ بیلنسز کے ساتھ؛ Fireworks پچھلے 30 دنوں میں اپنے اخراجات کے ساتھ۔ کوڈنگ ماڈلز جو آپ اپنے ہارڈویئر پر چلاتے ہیں انہیں اپنی لائنیں ملتی ہیں، اور ان کے ٹوکنز بھی مجموعوں میں شمار ہوتے ہیں، جیسا کہ [لوکل ماڈلز](#local-models) کے تحت بیان کیا گیا ہے۔ ہر ایجنٹ کو ایک بار شمار کیا جاتا ہے، اس کے تحت جو اس کا بل دیتا ہے، چاہے آپ اسے کتنے ہی harnesses کے ذریعے چلائیں۔

پینل کے لیے بار آئیکن پر بایاں کلک کریں یا `Super + Ctrl + X` دبائیں، اپنے ڈیفالٹ ایجنٹ کو لانچ کرنے کے لیے دایاں کلک کریں، اور ریفریش کرنے کے لیے درمیانی کلک کریں۔ اس کے پیچھے استعمال کے ریکارڈز ہر 15 منٹ میں `omarchy agent usage update` کے ذریعے دوبارہ بنائے جاتے ہیں، اور پینل ایک ہم آہنگ فولڈر کے ذریعے آپ کی دیگر مشینوں سے استعمال کو بھی ضم کر سکتا ہے۔ مکمل سیٹنگز کے لیے `$OMARCHY_PATH/shell/plugins/agents/` کے تحت README دیکھیں۔

### کئی سبسکرپشنز

اگر آپ ایک سے زیادہ Claude، Codex، یا Grok پلان کی ادائیگی کرتے ہیں — مثلاً ایک ذاتی Max اور ایک کام کا — تو Omarchy ان سب کو سائن ان رکھ سکتا ہے اور ان کے درمیان منتقل ہو سکتا ہے۔ agents پینل میں + کے ساتھ سبسکرپشن شامل کریں، جو آپ کو وہیں اس سے گزارتا ہے، یا `omarchy agent account add claude Work` کے ساتھ (یا `codex`، یا `grok`)۔ وہی + اور کمانڈ Gemini (`gemini`) اور OpenCode (`opencode`) میں سائن ان کرتے ہیں، اور OpenCode میں Fireworks (`fireworks`) یا OpenRouter (`openrouter`) API key محفوظ کرتے ہیں؛ کمانڈ Copilot (`copilot`)، Cursor (`cursor`)، اور Muse (`muse`) میں بھی سائن ان کرتی ہے۔ وہ ہر ایک واحد سائن ان رکھتے ہیں۔ اگر CLI غائب ہے تو یہ اسے انسٹال کر دیتا ہے۔ کسی فراہم کنندہ کے لیے پہلا اکاؤنٹ آپ کے عام براؤزر کے ذریعے سائن ان ہوتا ہے، ٹھیک وہیں جہاں CLI ہمیشہ دیکھتا ہے۔ اس کے بعد ہر ایک نجی ونڈو کے ذریعے سائن ان ہوتا ہے، تاکہ وہ اکاؤنٹ جس میں آپ کا براؤزر پہلے سے سائن ان ہے غلطی سے نہ اٹھایا جائے؛ وہاں اس اکاؤنٹ کے طور پر سائن ان کریں جسے آپ شامل کر رہے ہیں، اور پہلے سے کھلی ہوئی کوئی نجی ونڈو پہلے بند کر دیں۔ اس کے لیے CLI سے کبھی لاگ آؤٹ نہ کریں: لاگ آؤٹ کرنا محفوظ شدہ سائن ان کو منسوخ کر دیتا ہے، اور وہ اکاؤنٹ دوبارہ شامل کرنا پڑے گا۔

اپنے سبسکرپشن لاگ انز کو SSH پر ایک اور Omarchy مشین پر کاپی کرنے کے لیے، `omarchy agent account copy user@laptop` چلائیں۔ بھیجنے والا ایک عارضی وصول کنندہ فراہم کرتا ہے جب منزل کے پاس کوئی انسٹال نہ ہو، چنانچہ پرانی Omarchy مشینیں بغیر اپڈیٹ کے اکاؤنٹس وصول کر سکتی ہیں۔ انسٹال شدہ وصول کنندگان کو ترجیح حاصل ہے۔ یہ تمام Claude، Codex، اور Grok سبسکرپشنز کاپی کرتا ہے؛ انہیں منتخب کرنے کے لیے فراہم کنندہ کے نام شامل کریں، جیسے `omarchy agent account copy laptop claude` میں۔ اکاؤنٹ کے نام اور کمانڈ IDs ماخذ سے ملتے ہیں، بشمول منزل پر پہلے سے موجود اکاؤنٹس۔ غیر متعلقہ منزل اکاؤنٹس کو اگر ان کے نام متصادم ہوں تو عددی لاحقہ ملتا ہے، اور سیٹنگز، اسکلز، پلگ انز، اور گفتگو کی تاریخ ہر مشین کے لیے مقامی رہتی ہے۔

منزل کی موجودہ اسناد برقرار رکھی جاتی ہیں۔ کوئی ماخذ اکاؤنٹ جو وہاں پہلے سے سائن ان ہو، اس کا نام اس کی اسناد کو بدلے بغیر ہم آہنگ کر دیا جاتا ہے؛ دیگر اکاؤنٹس اس کے ساتھ شامل کر دیے جاتے ہیں۔ مماثل اکاؤنٹس کے لیے محفوظ شدہ اسناد بدلنے کے لیے، منزل پر اس اکاؤنٹ کے سیشنز بند کرنے کے بعد `omarchy agent account copy --replace laptop claude` استعمال کریں۔ ایک تازہ منزل کو ماخذ کا فعال اکاؤنٹ اور سوئچنگ ترجیحات بھی ملتی ہیں؛ ایک قائم شدہ منزل اپنی برقرار رکھتی ہے۔

اسناد SSH کے ذریعے سفر کرتی ہیں اور منزل پر نجی فائلوں میں محفوظ ہوتی ہیں، چنانچہ صرف ان مشینوں پر کاپی کریں جن پر آپ اعتماد کرتے ہیں۔ یہ ایک بار کی کاپی ہے، جاری ہم آہنگی نہیں۔ Codex ریفریش ٹوکنز کو ایک اور مشین گھما سکتی ہے، جس سے کاپی شدہ لاگ ان کو تجدید کی ضرورت پڑ جاتی ہے؛ کئی مشینوں پر بیک وقت استعمال کے لیے الگ سائن انز سب سے قابل اعتماد انتخاب ہیں۔ دیکھیں [Codex کی اکاؤنٹ تصدیق رہنمائی](https://developers.openai.com/codex/auth/ci-cd-auth)۔

فی فراہم کنندہ ایک اکاؤنٹ فعال ہوتا ہے، اور ہر نیا سیشن اسی کے طور پر شروع ہوتا ہے: `cx`، `cy`، ایک سادہ `claude`، `codex`، یا `grok`، `omarchy agent` کے ذریعے لانچ کیا گیا کچھ بھی، اور اسکرپٹس یا ایڈیٹرز جو CLI کو `PATH` پر پاتے ہیں۔ `omarchy agent account use work` سے سوئچ کریں (اور `omarchy agent account use main` سے واپس)، یا پینل میں کسی اکاؤنٹ کا نمبر دبا کر اور پھر `Enter` دبا کر (یا اس کے ستارے پر کلک کر کے)۔ چلتے ہوئے Claude سیشنز بھی سوئچ کرتے ہیں، ان کے اگلے پیغام سے: ہر Claude سیشن `~/.claude` میں چلتا ہے، جس میں ہمیشہ فعال اکاؤنٹ کا سائن ان ہوتا ہے۔ کسی اکاؤنٹ کے اپنے فولڈر میں پرانی Omarchy کے ذریعے شروع کیا گیا Claude سیشن وہ سائن ان اس وقت تک رکھتا ہے جب تک وہ بند نہ ہو جائے، چنانچہ سوئچ ان سیشنز کا نام لیتا ہے اور ان کے ختم ہونے پر خود مکمل ہو جاتا ہے۔ چلتے ہوئے Codex اور Grok سیشنز اس اکاؤنٹ پر رہتے ہیں جس سے وہ شروع ہوئے تھے۔ گفتگو کی تاریخ، سیٹنگز، اسکلز، اور پلگ انز اکاؤنٹس میں مشترکہ ہوتے ہیں، چنانچہ اسی فولڈر میں `claude --continue` وہیں سے اٹھاتا ہے جہاں آپ نے نئے اکاؤنٹ پر چھوڑا تھا۔

ایک سے زیادہ اکاؤنٹ کے ساتھ، پینل ہر اکاؤنٹ کی حدود ساتھ ساتھ دکھاتا ہے، استعمال میں موجود پر بھرا ہوا ستارہ ہوتا ہے۔ Omarchy آپ کو مطلع کرتا ہے جب فعال اکاؤنٹ کسی حد کے 95% سے گزر جاتا ہے، اور اطلاع پر کلک کرنا سب سے زیادہ گنجائش والے اکاؤنٹ پر سوئچ کر دیتا ہے۔ یہ کبھی خود سوئچ نہیں کرتا۔ حد کو `omarchy agent account threshold 90` سے تبدیل کریں۔ اگر ہر اکاؤنٹ حد سے اوپر ہے، تو آپ کو ایک بار اس کے بارے میں سنایا جائے گا، ساتھ میں کون سا اکاؤنٹ سب سے پہلے آزاد ہوتا ہے۔ جب کہ کوئی فعال اکاؤنٹ اپنی حد کے 15 پوائنٹس کے اندر ہوتا ہے (ڈیفالٹ پر 80%)، اس کی حدود ہر 15 کے بجائے ہر تین منٹ میں چیک کی جاتی ہیں۔

`omarchy agent account list` ہر اکاؤنٹ اور اس کی تازہ ترین حدود دکھاتا ہے، `omarchy agent account remove work` ایک کو بھول جاتا ہے، اور `omarchy agent account rename primary Hey` ایک کا نام بدلتا ہے (یا پینل میں کسی اکاؤنٹ کے نام پر کلک کریں)۔ یہ کمانڈز آپ کے ڈیفالٹ ایجنٹ کے اکاؤنٹس پر کام کرتی ہیں؛ دوسرے فراہم کنندہ تک پہنچنے کے لیے، پہلے اس کا نام لیں، جیسے `omarchy agent account use codex side` میں۔ وہ لاگ ان جو آپ کے پاس پہلے سے `~/.claude` یا `~/.codex` میں تھا وہ _Main_ اکاؤنٹ ہے۔ Codex کا وہیں رہتا ہے جہاں ہے؛ Claude کا جب ایک اور اکاؤنٹ فعال ہو تو اپنے فولڈر میں انتظار کرتا ہے۔ تقریباً آٹھ گھنٹے سے زیادہ عرصے تک غیر استعمال شدہ چھوڑا گیا اکاؤنٹ _Sign-in required_ دکھا سکتا ہے؛ اس اکاؤنٹ کو پینل میں ہی دوبارہ سائن ان کرنے کے لیے اس پر کلک کریں، یا اس پر سوئچ کریں اور سیشن شروع کریں، جو سائن ان کو خود تازہ کر دیتا ہے۔ MCP سرورز جو آپ `claude mcp add` سے شامل کرتے ہیں وہ ہر Claude اکاؤنٹ تک پہنچتے ہیں، کیونکہ وہ سب `~/.claude` میں چلتے ہیں؛ Codex اور Grok کے لیے، جب کوئی اکاؤنٹ شامل کیا گیا تھا اس وقت آپ کے پاس موجود سرورز اس تک ساتھ آتے ہیں، لیکن بعد والے صرف اس اکاؤنٹ تک پہنچتے ہیں جس میں آپ نے انہیں شامل کیا تھا۔ Claude Desktop اپنا سائن ان رکھتا ہے، اور CLI بائنری کے مطلق راستے کے ساتھ کنفیگر شدہ Codex یا Grok ٹولز سوئچ کی پیروی نہیں کرتے۔ ایک واضح `CLAUDE_CONFIG_DIR`، `CODEX_HOME`، یا `GROK_HOME` منتخب اکاؤنٹ پر ترجیح لیتا ہے۔

### کریش تشخیص

Omarchy عمل کے کریشز کے لیے systemd-coredump دیکھتا ہے۔ جب آپ ڈیفالٹ ایجنٹ منتخب کر لیتے ہیں، تو آپ کا کوئی بھی پروگرام جو core ڈمپ کرتا ہے وہ "Process crashed" اطلاع لاتا ہے — اس پر کلک کریں، اور کریش آپ کے ڈیفالٹ ایجنٹ کے سپرد کر دیا جاتا ہے Omarchy کی omarchy-diagnose-crash اسکل کے ساتھ، جو ایجنٹ کو core ڈمپ سے حقائق قائم کرنے اور یہ فیصلہ کرنے میں لے جاتی ہے کہ آیا کریش upstream رپورٹ کرنے کے قابل ہے۔ آپ اسے `coredumpctl list` سے کسی PID کے خلاف `omarchy agent crash <pid>` کے ساتھ ہاتھ سے بھی چلا سکتے ہیں۔

دیکھنا بطور ڈیفالٹ آن ہوتا ہے۔ اسے _Trigger > Toggle > Crash Capture Off_ کے تحت بند کر دیں (یا `omarchy toggle crash-capture` کے ساتھ) اور اطلاعات رک جاتی ہیں؛ `omarchy agent crash <pid>` ہاتھ سے اب بھی کام کرتا ہے۔

کریشز کو ایک وقت میں ایک پروگرام کے لیے خاموش بھی کیا جا سکتا ہے، جو تشخیص آخر میں آپ کو پیش کرتی ہے۔ `omarchy crash mute hyprland` صرف اس پروگرام کے لیے اطلاعات روکتا ہے، `omarchy crash mute hyprland off` انہیں واپس لاتا ہے، اور اکیلا `omarchy crash mute` وہ فہرست دیتا ہے جو آپ نے خاموش کیا ہے۔ یہ بائنری کا راستہ اس کے نام کی طرح خوشی سے لیتا ہے، چنانچہ `omarchy crash mute /usr/bin/hyprland` بھی وہی کرتا ہے۔ اس میں جگہ والے نام کو کوٹ کریں، جیسے `omarchy crash mute 'Some App'` میں۔ باقی سب اب بھی مطلع کرتا ہے، اور خاموش پروگرام اب بھی کریش ہوتا ہے — یہ یاد دہانی چھپاتا ہے، یہ کچھ ٹھیک نہیں کرتا۔

### ڈیسک ٹاپ ایپس

_Install > AI_ مینو میں چند گرافیکل AI ایپس بھی ہیں: Amp Desktop، Antigravity Desktop، ChatGPT ڈیسک ٹاپ ایپ، Claude ڈیسک ٹاپ ایپ (Anthropic کا Linux بیٹا، Chat، Cowork، اور Claude Code ٹیبز کے ساتھ)، xAI کے ماڈلز سے بات چیت کے لیے Grok Bot، Herdr Desktop، Hermes Desktop، OpenClaw، Perplexity ڈیسک ٹاپ ایپ، اور T3 Code۔ Grok Bot ڈیسک ٹاپ چیٹ ایپ ہے۔ کوڈنگ ایجنٹ `grok` کمانڈ ہے۔

Hermes Desktop وہ ہے جس کے بارے میں جاننا ضروری ہے، کیونکہ کسی مشین کے پاس ایک Hermes ہوتا ہے، اور وہ ایپ کا ہوتا ہے: Hermes ہمیشہ صرف ایپ کے ذریعے انسٹال ہوتا ہے، اور ڈیفالٹ ایجنٹ جو `hermes` کمانڈ چلاتا ہے وہ ایپ کی ہوتی ہے۔ Hermes کو ڈیفالٹ ایجنٹ کے طور پر منتخب کرنا وہی انسٹال کرتا ہے جو _Install > AI_ اندراج کرتا ہے: پیکیج، اور Hermes کے اپنے انسٹالر کے ذریعے سیٹ اپ کردہ `~/.hermes` کے تحت ایک Hermes runtime، جس میں پہلی بار چند منٹ لگتے ہیں۔ وہ runtime وہی ایک Hermes ہے جسے ٹرمینل `hermes` کمانڈ، ڈیفالٹ ایجنٹ اور ایپ سب استعمال کرتے ہیں، اور یہ Omarchy ریلیز کا انتظار کرنے کے بجائے `hermes update` سے خود اپڈیٹ ہوتا ہے۔ اسے انسٹال کرنا Hermes کو Omarchy تھیم بھی `omarchy` نامی skin کے طور پر دیتا ہے، جس کی ہر Hermes سطح پیروی کرتی ہے جب آپ تھیمز تبدیل کرتے ہیں؛ اگر آپ چاہتے ہیں کہ ایسا نہ ہو تو Hermes کی Appearance سیٹنگز کے تحت یا `/skin` سے کوئی اور منتخب کریں، اور Omarchy اس انتخاب کو چھوڑ دیتا ہے۔ _Remove > AI_ کے تحت ایپ کو ہٹانا پہلے Hermes کو بند کرتا ہے، گیٹ وے سمیت، اس runtime کو اس کے ساتھ لے جاتا ہے، اور آپ کی چیٹس، یادیں، اور وہ اسکلز جو Hermes نے اپنے لیے لکھی تھیں برقرار رکھتا ہے الا یہ کہ آپ اسے دوسری صورت کہیں: یہ پوچھتا ہے، بطور ڈیفالٹ نہیں پر، کہ آیا وہ ڈیٹا اور آپ کی کنکشن سیٹنگز بھی جانی چاہئیں۔

OpenClaw کا ڈیسک ٹاپ تجربہ اس کا Control UI ہے، جو اس کے اپنے لوکل گیٹ وے کی پشت پر ایک ویب ایپ کے طور پر کھلتا ہے۔ OpenClaw `~/.openclaw` میں رہتا ہے اور خود اپڈیٹ ہوتا ہے: Control UI کا "Update Gateway" بٹن استعمال کریں یا `openclaw update` چلائیں، اور گیٹ وے نئے ورژن پر دوبارہ شروع ہو جاتا ہے۔ Omarchy صرف وہ ریلیز منتخب کرتا ہے جس سے تازہ انسٹال شروع ہوتا ہے۔ OpenClaw آپ کا ڈیفالٹ ایجنٹ بھی ہو سکتا ہے: اسے `omarchy default agent openclaw` سے منتخب کرنا `~/.openclaw` میں وہی کاپی سیٹ اپ کرتا ہے، اور ایجنٹ OpenClaw کا ٹرمینل UI اس کے گیٹ وے سے منسلک کھولتا ہے۔ _Remove > AI_ کے تحت OpenClaw کو ہٹانا گیٹ وے سروس اور ایپ کو اس کے ساتھ لے جاتا ہے اور پھر پوچھتا ہے کہ آیا `~/.openclaw` بھی جانا چاہیے، کیونکہ اس میں OpenClaw خود اور اس کے ڈاؤن لوڈ کردہ پلگ ان runtimes کے ساتھ آپ کی چیٹس اور اسناد ہوتی ہیں؛ ڈیفالٹ اسے رکھتا ہے، اور OpenClaw دوبارہ انسٹال کرنا اسے واپس اٹھا لیتا ہے۔

Herdr Desktop [Herdr](https://herdr.dev) ڈیسک ٹاپ ایپ ہے: ٹرمینلز اور کوڈنگ ایجنٹس کے spaces، ٹیبز، اور panes جو ونڈو بند کرنے پر اس کے core میں چلتے رہتے ہیں۔ یہ پیکیج کے بجائے Herdr کے اپنے انسٹالر سے آتا ہے، چنانچہ یہ `~/.local/share/herdr-app` میں رہتا ہے، جب آپ کے پاس ابھی کوئی نہ ہو تو `~/.local/bin/herdr-core` میں اپنا core ساتھ لاتا ہے، اور دونوں خود اپڈیٹ ہوتے ہیں۔ یہ `Super + Ctrl + Return` پر Omarchy کی بھیجی گئی `herdr` کمانڈ کے پاس بیٹھتا ہے اسے بدلے بغیر، اور اس کمانڈ کی براہ راست کیز حاصل کرتا ہے: `Alt + Return` اور `Alt + Shift + Return` pane کو نیچے یا دائیں تقسیم کرتے ہیں، `Alt + Escape` اسے بند کرتا ہے، `Ctrl + Alt + Arrow` panes کے درمیان منتقل ہوتا ہے، `Alt + 1..9` اور `Alt + Left/Right` ٹیب منتخب کرتے ہیں، اور `Alt + Up/Down` spaces کے درمیان منتقل ہوتے ہیں۔ `Ctrl + 1..9` space منتخب کرتا ہے اور `Alt + Shift + Up/Down` ایجنٹس میں قدم رکھتا ہے۔ `Ctrl + Space` prefix کیز صرف ٹرمینل رہتی ہیں، کیونکہ ایپ تسلسل کے لیے سادہ Ctrl کی کو نہیں پکڑ سکتی۔ Omarchy انہیں `~/.config/herdr-app/keys.json` میں لکھتا ہے، اور `omarchy-refresh-herdr-app` انہیں واپس رکھتا ہے۔ اسے انسٹال کرنا Herdr کی Omarchy تھیم منتخب کرتا ہے، جو اس کے بعد سے آپ کی Omarchy تھیم کی پیروی کرتی ہے۔ Herdr ہلکے موڈ کے لیے ایک تھیم اور گہرے کے لیے ایک رکھتا ہے، چنانچہ گہری اور ہلکی Omarchy تھیم کے درمیان سوئچ کرنے کے بعد، دوسرے موڈ کے لیے Herdr کے تھیم picker میں Omarchy ایک بار پھر منتخب کریں۔

T3 Code پیکیج کے بجائے `~/.local/share/t3code` میں اپنے سرکاری AppImage ریلیز سے چلتا ہے، چنانچہ یہ خود اپڈیٹ ہوتا ہے۔ اسے انسٹال کرنا پوچھتا ہے کہ Stable یا Nightly چینل پر شروع کرنا ہے؛ بعد میں T3 Code کی سیٹنگز میں سوئچ کریں۔ آپ کے تھریڈز اور سیٹنگز `~/.t3` میں رہتے ہیں، اور _Remove > AI_ کے تحت T3 Code کو ہٹانا انہیں اس کے ساتھ لے جاتا ہے۔

### لوکل ماڈلز

اپنے کوڈنگ ایجنٹس کے لیے اپنی مشین پر ایک اوپن ماڈل چلائیں۔ آپ کے prompts اور کوڈ مشین پر رہتے ہیں؛ ماڈل کو بھیجا گیا کچھ بھی اسے نہیں چھوڑتا۔ اس سے شروع کریں:

```bash
omarchy models use best text
```

یہ اس مشین کے لیے بہترین ٹیکسٹ ماڈل سیٹ اپ کرتا ہے، وہ قسم جو آپ کے ایجنٹس استعمال کرتے ہیں۔ تصویر، ویڈیو اور موسیقی ماڈلز کا اپنا بہترین ہوتا ہے: `omarchy models use best image`، `video` یا `music`۔ اس مشین کے لیے ہر قسم کا انتخاب دیکھنے کے لیے `omarchy models use best` چلائیں۔

یا agents پینل میں + منتخب کریں: _Use a local model_ کے تحت یہ ہر کوڈنگ ماڈل کی فہرست دیتا ہے جو اس مشین میں فٹ آتا ہے، تجویز کردہ پہلے۔ Podman، جو ماڈلز چلاتا ہے، Omarchy کے ساتھ آتا ہے، اسی طرح NVIDIA مشین پر NVIDIA کا container toolkit آتا ہے، جو انہیں GPU دیتا ہے؛ اگر کوئی بھی غائب ہو، تو پہلا سیٹ اپ اسے انسٹال کرتا ہے۔ پھر Omarchy اس مشین کے لیے تجویز کردہ ماڈل منتخب کرتا ہے، اسے ڈاؤن لوڈ کرتا ہے، اور شروع کرتا ہے۔ دسیوں GB کے ڈاؤن لوڈ اور ماڈل چلتے وقت مشین کی زیادہ تر میموری استعمال میں ہونے کی توقع کریں: Flash Next اپنے مکمل 256K context کے ساتھ تقریباً 100 GiB استعمال کرتا ہے۔ اگر دوسرے ماڈلز اسے درکار میموری رکھتے ہوں، تو یہ روکا ہوا سیٹ اپ ہوتا ہے، جب آپ کسی ایک کو روکیں تو شروع ہونے کے لیے تیار۔ ماڈل logout پر رک جاتا ہے؛ جب آپ کو کسی اور چیز کے لیے میموری چاہیے ہو تو اسے خود روک دیں۔

`omarchy models list` اختیارات دکھاتا ہے اور بتاتا ہے کہ کچھ کیوں فٹ نہیں آتے۔ ایک اور سیٹ اپ کرنے کے لیے، `omarchy models use <recipe>` چلائیں۔ آج، 128 GB Strix Halo مشینوں کے لیے `qwen3.8-flash-next-gufo` اور `qwen3.8-27b-gufo` دستیاب ہیں؛ 27B تقریباً 40 GiB لیتا ہے، چنانچہ یہ دوسرے کام کے لیے جگہ چھوڑتا ہے۔ Intel کے Arc B390 والی 64 GB لیپ ٹاپ پر، `qwen3.6-35b-a3b-llamacpp` تقریباً 30 GiB میں چلتا ہے۔ نئی ترکیبیں اور تجاویز پیکیج کے ذریعے `omarchy update` کے ساتھ آتی ہیں۔

آپ جو کوڈنگ ماڈل شامل کرتے ہیں اسے agents پینل میں اپنی لائن ملتی ہے، آپ کی سبسکرپشنز کے پاس: شروع کرنے کے لیے play، روکنے اور اس کی میموری آزاد کرنے کے لیے pause، چلتے وقت اسے اپنے tailnet پر دیگر مشینوں کے ساتھ شیئر کرنے کے لیے Tailscale نشان، اور اس پر اپنا ایجنٹ کھولنے کے لیے ٹرمینل بٹن۔ اس کی لائن جاتے جاتے ڈاؤن لوڈ، لوڈ یا روکنا دکھاتی ہے، اور کہتی ہے جب شروع کرنے کے لیے کافی خالی میموری نہ ہو، یا جب یہ خرابی سے رک گیا ہو تو اس کے لاگز سے لنک کرتی ہے۔ کئی ایک ساتھ چل سکتے ہیں جب وہ میموری میں ایک ساتھ فٹ آتے ہوں۔ منتخب لائن پر Delete دبائیں تاکہ ماڈل اس مشین سے ہٹ جائے، ڈاؤن لوڈ سمیت؛ + اسے دوبارہ سیٹ اپ کر سکتا ہے۔ ٹرمینل سے سیٹ اپ کردہ کوڈنگ ماڈل + کے تحت انتظار کرتا ہے جب تک آپ اسے شامل نہ کریں، اور اسی طرح وہ ماڈلز جو آپ کی جوڑی بنائی گئی مشین (`omarchy models pair <host>`) چلاتی ہے۔

آپ جو ہر کوڈنگ ماڈل سیٹ اپ کرتے ہیں اسے app launcher میں بھی اپنا اندراج ملتا ہے، ماڈل کے نام کے تحت اور اس کے بنانے والے کے لوگو کے ساتھ، اسی طرح جیسے Claude، Codex یا Grok میں سائن ان کرنا ایک شامل کرتا ہے۔ یہ اس ماڈل پر آپ کا ایجنٹ کھولتا ہے، اور اگر ماڈل نہ چل رہا ہو تو پہلے اسے شروع کرتا ہے: ٹرمینل اسے لوڈ ہوتا دکھاتا ہے اور تیار ہونے پر ایجنٹ کے سپرد کر دیتا ہے۔ ماڈل ہٹانا اس کا اندراج ہٹا دیتا ہے۔

ہر ماڈل کوڈنگ کے لیے نہیں ہوتا۔ تصویر، ویڈیو اور موسیقی ماڈلز اس کے بجائے Fantasi میں کھلتے ہیں، اس مشین پر چلنے والے ماڈل سے تصاویر، ویڈیو اور موسیقی بنانے کے لیے Omarchy کی ایپ، اور وہاں یا `omarchy models` کے ساتھ منظم کیے جاتے ہیں۔

کوئی ماڈل بالکل ویسا ہی چلتا رہتا ہے جیسا اسے سیٹ اپ کیا گیا تھا، چنانچہ Omarchy اپڈیٹ آپ کے ایجنٹس کے تحت کبھی کسی کو دوبارہ شروع نہیں کرتا۔ جب Omarchy کے پاس آپ کے سیٹ اپ کردہ ماڈل کے لیے نیا runtime یا نئے weights ہوں، تو اس کی لائن اپڈیٹ بٹن دکھاتی ہے: اسے دبائیں اور ماڈل پس منظر میں دوبارہ سیٹ اپ ہو جاتا ہے، صرف وہ ڈاؤن لوڈ کرتے ہوئے جو تبدیل ہوا، اور نئے ورژن پر دوبارہ شروع ہوتا ہے۔ جو ماڈل روکا ہوا تھا وہ روکا ہوا رہتا ہے۔ `omarchy models update` ٹرمینل سے ہر ماڈل کے لیے یہی کرتا ہے۔

کمانڈ لائن سے، `omarchy models start <recipe>` اور `omarchy models stop <recipe>` یہی کرتے ہیں، `omarchy models status` ہر ماڈل دکھاتا ہے، اور `omarchy agent --local-model <recipe>` اس ماڈل کو pi میں کھولتا ہے، چاہے آپ کا ڈیفالٹ ایجنٹ کچھ بھی ہو۔ اپنے لوکل ماڈل کو وہ بنانے کے لیے جو ایجنٹ hotkey، Quake کنسول، اور _Make something_ کھولتے ہیں، `omarchy default agent local` چلائیں یا agents پینل میں چلتے ماڈل کو ستارہ زد کریں۔ pi ہر ماڈل کی فہرست بھی دیتا ہے جو آپ نے سیٹ اپ کیا ہے، اور وہ جو آپ کی جوڑی بنائی گئی مشینوں پر ہیں، اپنے ماڈل picker میں، چنانچہ سادہ `pi` بھی ان تک پہنچتا ہے۔ کوئی بھی OpenAI سے ہم آہنگ کلائنٹ بھی جڑ سکتا ہے: `status` ہر ماڈل کا پتہ دکھاتا ہے (پہلا `http://127.0.0.1:11435/v1` ہے)، ترکیب کا نام ماڈل ہے، اور key `~/.config/omarchy/agent-local/key` میں ہے۔

`omarchy models remove <recipe>` کسی ماڈل اور وہ ڈاؤن لوڈز حذف کرتا ہے جو کوئی اور ماڈل استعمال نہیں کرتا۔

تھرڈ پارٹی runtimes کو ان کے ناشر کے ساتھ لیبل کیا جاتا ہے۔ Omarchy ہر ماڈل کو بغیر نیٹ ورک رسائی کے چلاتا ہے۔

### لوکل LLMs

Omarchy لوکل LLM ماڈلز چلانے کے دو طریقے تجویز کرتا ہے: LM Studio اور Ollama۔ LM Studio اوپن ویٹ ماڈلز تلاش کرنے، انہیں انسٹال کرنے، اور چلانے کے لیے GUI انٹرفیس فراہم کرتا ہے۔ آسانی سے شروع کرنے کا یہ بہترین طریقہ ہے۔ Ollama اسی طرح کرنے کے لیے CLI پیش کرتا ہے۔ لیکن اگر آپ لوکل ماڈلز میں نئے ہیں، تو میں LM Studio سے آغاز کروں گا۔ آپ Omarchy Menu میں _Install > AI_ کے تحت کوئی بھی انسٹال کر سکتے ہیں۔

### Omarchy اسکلز

ایجنٹ اسکلز AI کو مخصوص ٹولز کو مخصوص طریقے سے استعمال کرنے میں مدد دیتی ہیں، اور Omarchy ان میں سے سات بھیجتا ہے۔ omarchy اسکل سسٹم کو اپنی مرضی کے مطابق بنانے کا احاطہ کرتی ہے، جیسے آپ کی Hyprland کنفیگ کو ٹھیک کرنا یا بار کو ایڈجسٹ کرنا۔ omarchy-make-theme، omarchy-make-plugin، omarchy-make-app، اور omarchy-make-game کچھ نیا بنانے کا احاطہ کرتے ہیں، omarchy-contribute کسی بگ کی اطلاع دینے یا upstream فکس بھیجنے کا احاطہ کرتی ہے، اور omarchy-diagnose-crash کسی کریش کے core ڈمپ پر کام کرتی ہے۔ وہ Claude Code (`~/.claude/skills`)، Codex (`~/.codex/skills`)، Pi (`~/.pi/agent/skills`)، Antigravity (`~/.gemini/config/skills`)، Hermes (`~/.hermes/skills` اور ہر `~/.hermes/profiles/*/skills`)، اور عام `~/.agents/skills` مقام کے لیے اسکل ڈائرکٹریز میں symlink کی گئی ہیں، چنانچہ زیادہ تر harnesses انہیں خودکار طور پر اٹھا لیتے ہیں۔ اسی نام کا آپ کا اپنا اسکل فولڈر ترجیح لیتا ہے۔

لیکن آپ کو ان اسکلز کو تجرباتی سمجھنا چاہیے۔ مختلف ماڈلز اسے مختلف اثر کے لیے استعمال کریں گے۔ بہتر ہے پہلے plan mode میں چلائیں، تاکہ آپ کو اندازہ ہو کہ ایجنٹ کیا تبدیل کرنا چاہے گا۔ اور پھر تبدیلیاں واپس لینے یا حتیٰ کہ `omarchy reinstall configs` چلانے کے لیے تیار رہیں، اگر ایجنٹ ہر چیز کا گڑبڑ کر دے۔
