### ایجنٹس کو install اور update کرنا

Hermes کے سوا، یہ agents mise کی lazy installation استعمال کرتے ہیں: پہلی launch CLI کو install کرتی ہے، اور بعد کی launches اسی کو دوبارہ استعمال کرتی ہیں۔ mise کسی installed agent کے لیے نئی release بھی زیادہ سے زیادہ ہر چار گھنٹے میں ایک بار چیک کرتا ہے، اس کے start ہونے سے عین پہلے یا shell prompt پر background میں۔ اگر وہ update ناکام ہو جائے یا آپ offline ہوں، تو installed version ہی چلتا ہے۔ `omarchy update` باقی Omarchy کے ساتھ installed agents کو بھی update کرتا ہے، اور `mup` صرف mise-managed tools کو update کرتا ہے۔

کسی agent کا اپنا updater، جیسے `claude update`، `codex update`، یا کسی app میں update button، mise-managed install کو update نہیں کرتا۔ `codex update` ناکام ہو جاتا ہے، اور `claude update` کامیابی کی اطلاع دیتے ہوئے ایک الگ copy install کر سکتا ہے جسے mise track نہیں کرتا۔ اگر آپ اس کے بجائے کسی agent کا اپنا native installer اور updater استعمال کرنا چاہتے ہیں، تو اسے `disable_tools` میں شامل کریں؛ دیکھیں [پہلے سے install شدہ CLI tools](18-development-tools.md#preinstalled-cli-tools)۔

تمام configured lazy tools کو ضرورت پڑنے سے پہلے install کرنے کے لیے `mise install --include-lazy` چلائیں۔ اس میں agents کے ساتھ ساتھ Omarchy کے دیگر default CLI tools بھی شامل ہیں۔ کسی ایک tool کو install کرنے یا اپنی خود کی installation استعمال کرنے کے لیے دیکھیں [پہلے سے install شدہ CLI tools](18-development-tools.md#preinstalled-cli-tools)۔

`grok` mise کے first-party `grok` package کے ذریعے install ہوتا ہے، بالکل اسی طرح جیسے `claude` اور `codex`۔ `grok` چلائیں، یا اسے _Setup > Defaults > Agent_ کے تحت منتخب کریں۔ x.ai پر موجود `curl | bash` installer کو چھوڑ دیں۔ وہ راستہ `~/.grok/bin` میں ایک دوسری copy رکھ دیتا ہے، اسے `PATH` پر prepend کر دیتا ہے، اور Omarchy کے wrapper کو overwrite کر دیتا ہے۔

`dsh` اپنا browser UI `127.0.0.1:3080` پر کھولتا ہے، جس میں launch directory اس کا default workspace ہوتا ہے۔ اس کا browser UI کوئی starting prompt نہیں لیتا، لہٰذا `omarchy agent prompt` اسے اس prompt کے ساتھ کھولتا ہے جو آپ کے clipboard پر paste کرنے کے لیے موجود ہوتا ہے۔ Omarchy اسے DeepSeek کے no-approval permission preset کے ساتھ شروع کرتا ہے۔ جب آپ اس کا official model API استعمال کرتے ہیں تو DeepSeek Harness session logs DeepSeek کو upload کرتا ہے؛ اسے اس کے browser UI میں _Settings > General > Upload Session Log_ کے تحت بند کر دیں۔ جو feedback آپ اسے بھیجتے ہیں وہ بھی session کے ساتھ upload ہو جاتا ہے، الا یہ کہ آپ اسے `DSH_TELEMETRY_MODE=DISABLED` کے ساتھ شروع کریں۔

### ڈیفالٹ ایجنٹ

اپنا default agent `omarchy default agent <name>` سے یا Omarchy Menu (`Super + Space`) میں _Setup > Defaults > Agent_ کے تحت منتخب کریں۔ اگر agent ابھی install نہیں ہوا، تو اسے منتخب کرنے سے وہ پہلے install ہو جائے گا۔ ایک نئی Omarchy آپ کو ایک بار کی notification کے ذریعے یہ انتخاب کرنے کی دعوت دے گی۔

Claude کو منتخب کرنا Chromium، Chrome، Brave، Brave Origin، اور Edge کے لیے اس کے browser extension کو setup کرنے کی بھی کوشش کرتا ہے۔ extension setup تمام users پر لاگو ہوتا ہے اور آپ سے آپ کا system password مانگ سکتا ہے؛ extension install کو cancel کرنے یا اس کے ناکام ہونے پر بھی Claude منتخب ہو جاتا ہے اور launch ہو جاتا ہے۔ اپنا browser restart کریں، اشارہ ملنے پر extension کو enable کریں، اور اسے connect کرنے کا عمل مکمل کرنے کے لیے Claude میں sign in کریں۔ connection چیک کرنے کے لیے Claude میں `/chrome` چلائیں۔ Firefox اور Zen اس extension کو support نہیں کرتے۔ اگر اس setup کے شامل کیے جانے سے پہلے ہی Claude آپ کا default تھا، تو extension install کرنے کے لیے اسے دوبارہ منتخب کریں۔

ایک بار منتخب کر لینے کے بعد، `Super + Shift + Ctrl + A` default agent کو ایک مخصوص terminal window میں launch کرتا ہے (یا اگر آپ نے ابھی تک کوئی منتخب نہیں کیا تو picker سامنے لاتا ہے)۔ آپ اسے `omarchy agent prompt "Review this project"` کے ساتھ سیدھا کسی task میں بھی launch کر سکتے ہیں۔ Freebuff اور DeepSeek Harness کوئی starting prompt نہیں لیتے، لہٰذا وہ اس کے بجائے اس prompt کے ساتھ کھلتے ہیں جو آپ کے clipboard پر paste کرنے کے لیے موجود ہوتا ہے۔ اس طرح launch کیے گئے agents اپنے متعلقہ don't-stop-to-ask modes میں بغیر نگرانی کے چلتے ہیں، لہٰذا تیار رہیں کہ وہ واقعی کچھ کر گزریں گے! MiniMax Code کے interactive sessions کے لیے ایسا کوئی mode نہیں ہے، لہٰذا وہ معمول کے مطابق permissions مانگتا ہے۔ اور چونکہ agents آپ کی home directory کے لیے trust یاد رکھنے سے انکار کرتے ہیں، اس لیے `$HOME` سے ہونے والی launches اس کے بجائے `~/Work` میں شروع ہوتی ہیں۔

terminal shortcuts بھی موجود ہیں: `a` default agent کو موجودہ terminal میں inline چلاتا ہے، جبکہ `c`، `cx`، اور `cy` OpenCode، Claude Code، اور Codex کو براہِ راست شروع کرتے ہیں (ایک بار پھر ان کے auto-approving modes میں)۔ Theme کی تبدیلیاں agents کے ساتھ بھی sync ہوتی ہیں: جب آپ Omarchy theme بدلتے ہیں تو Claude Code، Pi، OpenCode، اور Hermes (ایک بار جب Omarchy اسے install کر لے) سب اس کے ساتھ چلتے ہیں۔

### ایجنٹس پینل

top bar میں ایک agents icon موجود ہے۔ کسی agent کو setup کرنے سے پہلے، اس کا panel آپ کو Claude، Codex، یا Grok میں sign in کرنے کے مراحل سے گزارتا ہے، اور ان میں سے پہلا آپ کا default agent بن جاتا ہے۔ اس کے بعد، panel ہر subscription کو ایک ہی page پر رکھ دیتا ہے: ہر agent اور account اپنے plan کے ساتھ، اس کی 5-hour session اور weekly limits میں سے ہر ایک کے لیے ایک meter اس وقت کے ساتھ کہ وہ کب reset ہوگی (درست percentage کے لیے hover کریں)، یا باقی ماندہ prepaid balance، ایک ایسی line کے نیچے جو ان سب میں آپ کے استعمال کی گئی چیزوں کے درمیان گھومتی رہتی ہے، جیسے اس ہفتے کے tokens اور آپ کا سب سے زیادہ استعمال ہونے والا model۔ _Make something_ کے تحت یہ ایک نئی theme، plugin، یا app کے لیے starter prompts پیش کرتا ہے جو task آپ کے default agent کے حوالے کر دیتے ہیں۔ Apps اسی طرح بنائی جاتی ہیں جیسے Omarchy کی اپنی Hype، Monologue، اور Omacut بنائی گئی ہیں، C++ اور Qt Quick میں، omarchy-app agent skill کی پیروی کرتے ہوئے، اور انہیں درکار compiler اور Qt کے اجزا install شدہ آتے ہیں۔ Claude Code، Codex، Grok، Kimi، Cursor اور اس کا Grok Bot allowance، GitHub Copilot، Muse، Antigravity، Kimchi، اور Devin اپنی limits کے ساتھ out of the box شامل ہیں، اور Hermes، Mistral Vibe، اور Qwen Code ایک بار جب آپ انہیں استعمال کر لیں تو اپنے sessions اور tokens دکھاتے ہیں۔ وہ provider plans اور keys جو آپ pi، omp، یا opencode کے ذریعے استعمال کرتے ہیں وہ بھی ظاہر ہوتی ہیں: OpenCode Zen اور Go، Z.ai GLM Coding Plan، Ollama Cloud، MiniMax Token Plan، اور Synthetic اپنی limits کے ساتھ؛ Fireworks، OpenRouter، اور DeepSeek اپنے prepaid balances کے ساتھ؛ اور Local models کے تحت وہ models جو آپ اپنے خود کے hardware پر چلاتے ہیں۔ ہر agent کو ایک ہی بار گنا جاتا ہے، اس کے تحت جو بھی اس کا bill ادا کرتا ہو، چاہے آپ اسے کتنے ہی harnesses کے ذریعے چلائیں۔

panel کے لیے bar icon پر left-click کریں، اپنے default agent کو launch کرنے کے لیے right-click کریں۔ اس کے پیچھے موجود usage records ہر 15 منٹ بعد `omarchy agent usage-update` کے ذریعے دوبارہ بنائے جاتے ہیں، اور panel ایک synced folder کے ذریعے آپ کی دیگر machines سے usage کو merge بھی کر سکتا ہے۔ مکمل settings کے لیے `$OMARCHY_PATH/shell/plugins/agents/` کے تحت README دیکھیں۔

### متعدد سبسکرپشنز

اگر آپ ایک سے زیادہ Claude، Codex، یا Grok plan کے لیے ادائیگی کرتے ہیں — مثلاً ایک ذاتی Max اور ایک کام والا — تو Omarchy ان سب کو signed in رکھ سکتا ہے اور ان کے درمیان منتقل ہو سکتا ہے۔ agents panel میں + کے ساتھ کوئی subscription شامل کریں، جو آپ کو وہیں اس کے مراحل سے گزارتا ہے، یا `omarchy agent account add claude Work` (یا `codex`، یا `grok`) کے ساتھ۔ اگر CLI موجود نہیں ہے تو یہ اسے install کر دیتا ہے۔ کسی provider کے لیے پہلا account آپ کے عام browser کے ذریعے sign in ہوتا ہے، بالکل وہیں جہاں CLI ہمیشہ دیکھتا ہے۔ اس کے بعد ہر ایک private window کے ذریعے sign in ہوتا ہے، تاکہ وہ account جس میں آپ کا browser پہلے سے signed in ہے غلطی سے نہ منتخب ہو جائے؛ وہاں اس account کے طور پر sign in کریں جسے آپ شامل کر رہے ہیں، اور پہلے سے کھلی ہوئی کسی بھی private window کو پہلے بند کر دیں۔ اس کے لیے کبھی بھی CLI سے log out نہ کریں: log out کرنے سے محفوظ شدہ sign-in منسوخ ہو جاتا ہے، اور اس account کو دوبارہ شامل کرنا پڑے گا۔

اپنے subscription logins کو SSH کے ذریعے کسی دوسری Omarchy machine پر copy کرنے کے لیے `omarchy agent account copy user@laptop` چلائیں۔ جب destination کے پاس کوئی installed نہیں ہوتا تو sender ایک عارضی receiver فراہم کرتا ہے، لہٰذا پرانی Omarchy machines بغیر کسی update کے accounts وصول کر سکتی ہیں۔ Installed receivers کو ترجیح حاصل ہوتی ہے۔ یہ تمام Claude، Codex، اور Grok subscriptions copy کرتا ہے؛ انہیں منتخب کرنے کے لیے provider کے نام شامل کریں، جیسے `omarchy agent account copy laptop claude` میں۔ Account کے نام اور command IDs source سے match کرتے ہیں، بشمول وہ accounts جو destination پر پہلے سے موجود ہیں۔ غیر متعلقہ destination accounts کو اگر ان کے ناموں میں تصادم ہو تو ایک numeric suffix مل جاتا ہے، اور settings، skills، plugins، اور conversation history ہر machine پر local ہی رہتی ہیں۔

موجودہ destination credentials برقرار رکھے جاتے ہیں۔ کوئی source account جو وہاں پہلے سے signed in ہو اس کا نام اس کے credentials کو بدلے بغیر synchronize ہو جاتا ہے؛ دیگر accounts اس کے ساتھ شامل کر دیے جاتے ہیں۔ match کرنے والے accounts کے لیے محفوظ شدہ credentials کو بدلنے کے لیے، destination پر اس account کے sessions بند کرنے کے بعد `omarchy agent account copy --replace laptop claude` استعمال کریں۔ ایک نئی destination کو source کا active account اور switching preferences بھی مل جاتے ہیں؛ ایک قائم شدہ destination اپنے برقرار رکھتی ہے۔

Credentials SSH کے ذریعے سفر کرتے ہیں اور destination پر private files میں محفوظ ہوتے ہیں، لہٰذا صرف ان machines پر copy کریں جن پر آپ کو اعتماد ہو۔ یہ ایک بار کی copy ہے، جاری synchronization نہیں۔ Codex refresh tokens کسی دوسری machine کے ذریعے rotate کیے جا سکتے ہیں، جس سے ایک copied login کو renewal کی ضرورت پڑ سکتی ہے؛ کئی machines پر بیک وقت استعمال کے لیے الگ الگ sign-ins ہی سب سے قابلِ اعتماد انتخاب ہیں۔ دیکھیں [Codex کی اکاؤنٹ authentication رہنمائی](https://developers.openai.com/codex/auth/ci-cd-auth)۔

فی provider ایک account active ہوتا ہے، اور ہر نیا session اسی کے طور پر شروع ہوتا ہے: `cx`، `cy`، ایک سادہ `claude`، `codex`، یا `grok`، `omarchy agent` کے ذریعے launch کی گئی کوئی بھی چیز، اور وہ scripts یا editors جو CLI کو `PATH` پر پاتے ہیں۔ `omarchy agent account use work` کے ساتھ switch کریں (اور `omarchy agent account use main` کے ساتھ واپس)، یا panel میں کسی account کا number دبا کر پھر `Enter` دبا کر (یا اس کے Use button پر click کر کے)۔ جو sessions پہلے سے چل رہے ہیں وہ اسی account پر رہتے ہیں جس سے وہ شروع ہوئے تھے۔ Conversation history، settings، skills، اور plugins accounts کے درمیان shared ہوتی ہیں، لہٰذا اسی folder میں `claude --continue` وہیں سے اٹھاتا ہے جہاں آپ نے نئے account پر چھوڑا تھا۔

ایک سے زیادہ account ہونے پر، panel ہر account کی limits کو ساتھ ساتھ دکھاتا ہے، جس میں active کو نشان زد کیا جاتا ہے۔ بطورِ default Omarchy آپ کو اس وقت مطلع کرتا ہے جب active account کسی limit کے 95% سے آگے گزر جائے، اور notification پر click کرنے سے اس account پر switch ہو جاتا ہے جس کے پاس سب سے زیادہ گنجائش ہو۔ اس کے بجائے اسے خود بخود switch کرانے کے لیے panel میں کسی account کی line پر hover کریں اور Use کے ساتھ ظاہر ہونے والے Autoswitch پر click کریں (یا `m` دبائیں)، یا `omarchy agent account mode auto` چلائیں؛ جب یہ on ہو، تو Autoswitch Use کی جگہ لے لیتا ہے، اور اس پر دوبارہ click کرنا اطلاع دینے پر واپس لے جاتا ہے۔ threshold بدلنے کے لیے کوئی number شامل کریں، جیسے `omarchy agent account mode auto 90` میں۔ اگر ہر account threshold سے اوپر ہو، تو آپ کو ایک بار اس کے بارے میں بتایا جائے گا، اس کے ساتھ کہ کون سا account سب سے پہلے خالی ہوتا ہے۔ جب کوئی active account اپنے threshold کے 15 points کے اندر ہو (default پر 80%)، تو اس کی limits ہر 15 منٹ کے بجائے ہر تین منٹ بعد چیک کی جاتی ہیں۔

`omarchy agent account list` ہر account اور اس کی تازہ ترین limits دکھاتا ہے، `omarchy agent account remove work` ایک کو بھلا دیتا ہے، اور `omarchy agent account rename primary Hey` ایک کا نام بدل دیتا ہے (یا panel میں کسی account کے نام پر click کریں)۔ یہ commands آپ کے default agent کے accounts پر کام کرتی ہیں؛ دوسرے provider تک پہنچنے کے لیے پہلے اس کا نام لیں، جیسے `omarchy agent account use codex side` میں۔ وہ login جو آپ کے پاس پہلے سے `~/.claude` یا `~/.codex` میں موجود تھا وہ _Main_ account ہے اور وہیں رہتا ہے جہاں وہ ہے۔ کوئی account جو تقریباً آٹھ گھنٹے سے زیادہ عرصے تک استعمال نہ ہوا ہو _Sign-in required_ دکھا سکتا ہے؛ اس account کو panel میں ہی دوبارہ sign in کرنے کے لیے اس پر click کریں، یا اس میں کوئی session شروع کریں، جو sign-in کو خود بخود refresh کر دیتا ہے۔ وہ MCP servers جو کسی account کے شامل کیے جانے کے وقت آپ کے پاس تھے اس کے ساتھ آ جاتے ہیں، لیکن وہ جو آپ بعد میں `claude mcp add` کے ساتھ شامل کرتے ہیں صرف اس account تک پہنچتے ہیں جس میں آپ نے انہیں شامل کیا تھا۔ Claude Desktop اور وہ tools جو کسی CLI binary کے absolute path کے ساتھ configure کیے گئے ہوں switch کی پیروی نہیں کرتے۔ ایک واضح `CLAUDE_CONFIG_DIR`، `CODEX_HOME`، یا `GROK_HOME` منتخب شدہ account پر ترجیح لیتا ہے۔

### کریش کی تشخیص

Omarchy process crashes کے لیے systemd-coredump پر نظر رکھتا ہے۔ جب کوئی چیز segfault کرتی ہے، تو آپ کو ایک "Process crashed" notification ملے گی — اس پر click کریں، اور crash آپ کے default agent کے حوالے کر دیا جاتا ہے Omarchy کی diagnose-crash skill کے ساتھ، جو agent کو core dump سے حقائق قائم کرنے اور یہ فیصلہ کرنے کے مراحل سے گزارتی ہے کہ آیا crash upstream رپورٹ کرنے کے قابل ہے۔ آپ اسے `coredumpctl list` سے کسی بھی PID کے خلاف `omarchy agent crash <pid>` کے ساتھ ہاتھ سے بھی چلا سکتے ہیں۔

یہ نگرانی بطورِ default on ہوتی ہے۔ اسے _Trigger > Toggle > Crash Capture_ کے تحت (یا `omarchy toggle crash-capture` کے ساتھ) بند کر دیں اور notifications رک جائیں گی؛ `omarchy agent crash <pid>` ہاتھ سے پھر بھی کام کرتا ہے۔

Crashes کو ایک وقت میں ایک program کے حساب سے بھی خاموش کیا جا سکتا ہے، جو تشخیص آپ کو آخر میں پیش کرتی ہے۔ `omarchy crash mute hyprland` صرف اس program کے لیے notifications روک دیتا ہے، `omarchy crash mute hyprland off` انہیں واپس لاتا ہے، اور `omarchy crash mute` اکیلا یہ فہرست دیتا ہے کہ آپ نے کیا mute کیا ہے۔ یہ binary کے path کو اس کے نام کی طرح ہی خوشی سے قبول کرتا ہے، لہٰذا `omarchy crash mute /usr/bin/hyprland` بھی وہی کام کرتا ہے۔ کسی ایسے نام کو جس میں space ہو quote کریں، جیسے `omarchy crash mute 'Some App'` میں۔ باقی سب کچھ پھر بھی مطلع کرتا ہے، اور muted program پھر بھی crash ہوتا ہے — یہ reminder کو چھپاتا ہے، یہ کسی چیز کو ٹھیک نہیں کرتا۔

### ڈیسک ٹاپ ایپس

_Install > AI_ menu میں چند graphical AI apps بھی موجود ہیں: ChatGPT desktop app، Claude desktop app (Anthropic کا Linux beta، Chat، Cowork، اور Claude Code tabs کے ساتھ)، xAI کے models کے ساتھ chat کرنے کے لیے Grok Bot، Hermes Desktop، OpenClaw، Perplexity desktop app، اور T3 Code۔ Grok Bot desktop chat app ہے۔ coding agent `grok` command ہے۔

Hermes Desktop وہ ہے جس کے بارے میں جاننا ضروری ہے، کیونکہ ایک machine کے پاس ایک ہی Hermes ہوتا ہے، اور وہ app کا ہوتا ہے: Hermes ہمیشہ صرف app کے ذریعے install ہوتا ہے، اور وہ `hermes` command جو default agent چلاتا ہے وہ app کی ہوتی ہے۔ Hermes کو default agent کے طور پر منتخب کرنا وہی چیز install کرتا ہے جو _Install > AI_ entry کرتی ہے: package، اور `~/.hermes` کے تحت ایک Hermes runtime جو Hermes کے اپنے installer کے ذریعے setup کیا گیا ہو، جس میں پہلی بار چند منٹ لگتے ہیں۔ وہ runtime وہی ایک Hermes ہے جسے terminal کی `hermes` command، default agent اور app سب استعمال کرتے ہیں، اور یہ Omarchy release کا انتظار کرنے کے بجائے `hermes update` کے ساتھ خود کو update کرتا ہے۔ اسے install کرنا Hermes کو Omarchy theme بھی ایک skin کے طور پر دیتا ہے جس کا نام `omarchy` ہے، جس کی پیروی Hermes کی ہر surface theme بدلنے پر کرتی ہے؛ اگر آپ نہیں چاہتے کہ ایسا ہو تو Hermes کی Appearance settings کے تحت یا `/skin` کے ساتھ کوئی اور منتخب کریں، اور Omarchy اس انتخاب کو چھوڑ دیتا ہے۔ _Remove > AI_ کے تحت app کو ہٹانا پہلے Hermes کو بند کرتا ہے، gateway سمیت، اس runtime کو اس کے ساتھ لے جاتا ہے، اور آپ کی chats، memories، اور وہ skills برقرار رکھتا ہے جو Hermes نے اپنے لیے لکھی تھیں الا یہ کہ آپ اسے دوسری صورت کہیں: یہ پوچھتا ہے، جس کا default no ہے، کہ آیا وہ data اور آپ کی connection settings بھی جانی چاہئیں۔

OpenClaw کا desktop تجربہ اس کا Control UI ہے، جو ایک web app کے طور پر کھلتا ہے جس کے پیچھے اس کا اپنا local gateway ہوتا ہے۔ OpenClaw `~/.openclaw` میں رہتا ہے اور خود کو update کرتا ہے: Control UI کا "Update Gateway" button استعمال کریں یا `openclaw update` چلائیں، اور gateway نئے version پر restart ہو جاتا ہے۔ Omarchy صرف اس release کا انتخاب کرتا ہے جس سے ایک نئی install شروع ہوتی ہے۔ _Remove > AI_ کے تحت OpenClaw کو ہٹانا gateway service اور app کو اس کے ساتھ لے جاتا ہے اور پھر پوچھتا ہے کہ آیا `~/.openclaw` بھی جانا چاہیے، کیونکہ اس میں OpenClaw کے ساتھ ساتھ آپ کی chats اور credentials اور وہ plugin runtimes موجود ہوتے ہیں جو یہ download کرتا ہے؛ default اسے برقرار رکھتا ہے، اور OpenClaw کو دوبارہ install کرنا اسے واپس اٹھا لیتا ہے۔

T3 Code کسی package کے بجائے `~/.local/share/t3code` میں اپنی official AppImage release سے چلتا ہے، لہٰذا یہ خود کو update کرتا ہے۔ اسے install کرنا پوچھتا ہے کہ آیا Stable یا Nightly channel پر شروع کرنا ہے؛ بعد میں T3 Code کی settings میں switch کریں۔ آپ کے threads اور settings `~/.t3` میں رہتے ہیں، اور _Remove > AI_ کے تحت T3 Code کو ہٹانا انہیں اس کے ساتھ لے جاتا ہے۔

### لوکل ماڈلز

اپنے coding agents کے لیے اپنی خود کی machine پر ایک open model چلائیں۔ آپ کے prompts اور code machine پر ہی رہتے ہیں؛ model کو بھیجی گئی کوئی چیز اس سے باہر نہیں جاتی۔ اس سے شروع کریں:

```bash
omarchy agent local use best
```

یا، top bar میں agents panel میں، + اور پھر Local AI منتخب کریں، جو اس وقت ظاہر ہوتا ہے جب کوئی model اس machine پر fit بیٹھتا ہو۔ پہلی بار، یہ Podman install کرتا ہے، جو models چلاتا ہے، اور NVIDIA machine پر NVIDIA کا container toolkit، جو انہیں GPU فراہم کرتا ہے۔ پھر Omarchy اس machine کے لیے تجویز کردہ model منتخب کرتا ہے، اسے download کرتا ہے، اور اسے شروع کرتا ہے۔ دسیوں GB کی download کی توقع رکھیں اور یہ کہ model چلتے وقت machine کی زیادہ تر memory استعمال میں ہوگی: Flash Next اپنے مکمل 256K context کے ساتھ تقریباً 100 GiB استعمال کرتا ہے۔ اگر دوسرے models وہ memory روکے ہوئے ہوں جس کی اسے ضرورت ہے، تو یہ stopped حالت میں setup ہو جاتا ہے، ایک بار جب آپ کسی ایک کو روک دیں تو شروع ہونے کے لیے تیار۔ model logout پر رک جاتا ہے؛ جب آپ کو کسی اور کام کے لیے memory درکار ہو تو اسے خود روک دیں۔

`omarchy agent local list` اختیارات دکھاتا ہے اور بتاتا ہے کہ کچھ کیوں fit نہیں بیٹھتے۔ کوئی دوسرا setup کرنے کے لیے `omarchy agent local use <recipe>` چلائیں۔ آج، 128 GB Strix Halo machines کے لیے `qwen3.8-flash-next-gufo` اور `qwen3.8-27b-gufo` دستیاب ہیں؛ 27B تقریباً 40 GiB لیتا ہے، لہٰذا یہ دوسرے کام کے لیے جگہ چھوڑ دیتا ہے۔ نئی recipes اور تجاویز package کے ذریعے `omarchy update` کے ساتھ آتی ہیں۔

آپ کے setup کیے گئے ہر model کو agents panel میں، آپ کی subscriptions کے ساتھ، اس کی اپنی line ملتی ہے: اسے شروع کرنے کے لیے play، اسے روکنے اور اس کی memory خالی کرنے کے لیے pause، اور اس پر اپنا agent کھولنے کے لیے terminal button۔ کئی ایک ساتھ چل سکتے ہیں جب وہ memory میں ایک ساتھ fit بیٹھتے ہوں؛ اگر کوئی fit نہ بیٹھے، تو Omarchy بتاتا ہے کہ کس چلتے ہوئے model کو روکنا ہے۔ lines کو دوبارہ ترتیب دینے کے لیے انہیں drag کریں، اور کسی model اور اس کے download کو ہٹانے کے لیے منتخب line پر Delete دبائیں۔

command line سے، `omarchy agent local start <recipe>` اور `omarchy agent local stop <recipe>` بھی یہی کرتے ہیں، `omarchy agent local status` ہر model دکھاتا ہے، اور `omarchy agent --local` آپ کے default agent کو آخری model پر کھولتا ہے جو آپ نے شروع کیا تھا (pi اگر آپ کا default agent local model استعمال نہیں کر سکتا)۔ کوئی بھی OpenAI-compatible client بھی connect کر سکتا ہے: `status` ہر model کا address دکھاتا ہے (پہلا `http://127.0.0.1:11435/v1` ہے)، recipe کا نام ہی model ہے، اور key `~/.config/omarchy/agent-local/key` میں موجود ہے۔

`omarchy agent local remove <recipe>` کسی model اور وہ downloads حذف کر دیتا ہے جو کوئی دوسرا model استعمال نہیں کرتا۔

Third-party runtimes کو ان کے publisher کے ساتھ label کیا جاتا ہے۔ Omarchy ہر model کو بغیر کسی network access کے چلاتا ہے۔

### لوکل LLMs

Omarchy local LLM models چلانے کے دو طریقے تجویز کرتا ہے: LM Studio اور Ollama۔ LM Studio open-weight models تلاش کرنے، انہیں install کرنے، اور انہیں چلانے کے لیے ایک GUI interface فراہم کرتا ہے۔ آسانی سے شروع کرنے کا یہ ایک بہترین طریقہ ہے۔ Ollama بھی اسی طرح کرنے کے لیے ایک CLI پیش کرتا ہے۔ لیکن اگر آپ local models میں نئے ہیں، تو میں LM Studio سے شروع کروں گا۔ آپ Omarchy Menu میں _Install > AI_ کے تحت دونوں میں سے کوئی بھی install کر سکتے ہیں۔

### Omarchy Skill

Agent skills AI کو مخصوص tools کو ایک مخصوص طریقے سے استعمال کرنے میں مدد دیتی ہیں، اور Omarchy system کو اپنی مرضی کے مطابق ڈھالنے کے لیے ایک default skill کے ساتھ آتا ہے۔ جیسے اپنی Hyprland config کو tweak کرنا، bar کو adjust کرنا، یا یہاں تک کہ شروع سے ایک نئی theme بنانا۔ یہ Claude Code (`~/.claude/skills`)، Codex (`~/.codex/skills`)، Pi (`~/.pi/agent/skills`)، Antigravity (`~/.gemini/config/skills`)، Hermes (`~/.hermes/skills` اور ہر `~/.hermes/profiles/*/skills`)، اور generic `~/.agents/skills` location کے لیے skill directories میں symlink کی گئی ہے، لہٰذا زیادہ تر harnesses اسے خود بخود اٹھا لیتی ہیں۔

لیکن آپ کو اس skill کو تجرباتی سمجھنا چاہیے۔ مختلف models اسے مختلف اثر کے ساتھ استعمال کریں گے۔ بہتر ہے کہ پہلے اسے plan mode میں چلائیں، تاکہ آپ کو اندازہ ہو کہ agent کیا بدلنا چاہے گا۔ اور پھر تبدیلیوں کو rollback کرنے یا یہاں تک کہ `omarchy reinstall configs` چلانے کے لیے تیار رہیں، اگر agent ہر چیز کا گڑبڑ گھٹالا کر دے۔
