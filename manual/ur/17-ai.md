### ایجنٹس انسٹال اور اپ ڈیٹ کرنا

Hermes کے سوا، یہ ایجنٹس mise کی سست انسٹالیشن استعمال کرتے ہیں: پہلی بار لانچ کرنے پر CLI انسٹال ہوتا ہے، اور بعد کی لانچز اسی کو دوبارہ استعمال کرتی ہیں۔ mise انسٹال شدہ ایجنٹ کے لیے نئی ریلیز بھی زیادہ سے زیادہ ہر چار گھنٹے میں ایک بار چیک کرتا ہے، شروع ہونے سے عین پہلے یا پس منظر میں shell پرامپٹ پر۔ اگر وہ اپ ڈیٹ ناکام ہو جائے یا آپ آف لائن ہوں تو انسٹال شدہ ورژن چلتا ہے۔ `omarchy update` انسٹال شدہ ایجنٹس کو باقی Omarchy کے ساتھ اپ ڈیٹ کرتا ہے، اور `mup` صرف mise کے زیر انتظام ٹولز کو اپ ڈیٹ کرتا ہے۔

کسی ایجنٹ کا اپنا اپڈیٹر، جیسے `claude update`، `codex update` یا کسی ایپ میں اپ ڈیٹ بٹن، mise کے زیر انتظام انسٹال کو اپ ڈیٹ نہیں کرتا۔ `codex update` ناکام ہو جاتا ہے، اور `claude update` کامیابی کی اطلاع دے سکتا ہے حالانکہ اس نے ایک الگ کاپی انسٹال کی ہوتی ہے جسے mise ٹریک نہیں کرتا۔ اگر آپ اس کے بجائے کسی ایجنٹ کا اپنا انسٹالر اور اپڈیٹر استعمال کرنا چاہتے ہیں تو اسے `disable_tools` میں شامل کریں؛ [پہلے سے انسٹال شدہ CLI ٹولز](18-development-tools.md#preinstalled-cli-tools) دیکھیں۔

ضرورت پڑنے سے پہلے تمام تشکیل شدہ lazy ٹولز انسٹال کرنے کے لیے `mise install --include-lazy` چلائیں۔ اس میں ایجنٹس کے ساتھ ساتھ Omarchy کے دوسرے ڈیفالٹ CLI ٹولز بھی شامل ہیں۔ ایک ٹول انسٹال کرنے یا اپنی انسٹالیشن استعمال کرنے کے لیے [پہلے سے انسٹال شدہ CLI ٹولز](18-development-tools.md#preinstalled-cli-tools) دیکھیں۔

`grok` mise کے فرسٹ پارٹی `grok` پیکیج کے ذریعے انسٹال ہوتا ہے، بالکل اسی طرح جیسے `claude` اور `codex`۔ `grok` چلائیں، یا اسے _Agent > Harness_ کے تحت منتخب کریں۔ x.ai پر موجود `curl | bash` انسٹالر کو چھوڑ دیں۔ وہ راستہ `~/.grok/bin` میں ایک دوسری کاپی رکھتا ہے، اسے `PATH` کے شروع میں شامل کرتا ہے، اور Omarchy کے wrapper کو اوور رائٹ کر دیتا ہے۔

`dsh` اپنا براؤزر UI `127.0.0.1:3080` پر کھولتا ہے، جس میں لانچ ڈائریکٹری اس کی ڈیفالٹ workspace ہوتی ہے۔ اس کا براؤزر UI کوئی ابتدائی پرامپٹ نہیں لیتا، چنانچہ `omarchy agent prompt` اسے اس طرح کھولتا ہے کہ پرامپٹ آپ کے کلپ بورڈ پر چسپاں کرنے کے لیے موجود ہوتا ہے۔ Omarchy اسے DeepSeek کے no-approval اجازت preset کے ساتھ شروع کرتا ہے۔ جب آپ اس کا آفیشل ماڈل API استعمال کرتے ہیں تو DeepSeek Harness سیشن لاگز DeepSeek کو اپ لوڈ کرتا ہے؛ اسے اس کے براؤزر UI میں _Settings > General > Upload Session Log_ کے تحت بند کریں۔ جو تاثرات آپ اسے بھیجتے ہیں وہ بھی سیشن کے ساتھ اپ لوڈ ہوتے ہیں، الا یہ کہ آپ اسے `DSH_TELEMETRY_MODE=DISABLED` کے ساتھ شروع کریں۔

### ڈیفالٹ ایجنٹ

اپنا ڈیفالٹ ایجنٹ `omarchy default agent <name>` کے ساتھ یا Omarchy Menu (`Super + Space`) میں _Agent > Harness_ کے تحت منتخب کریں۔ اگر ایجنٹ ابھی انسٹال نہیں ہوا تو اسے منتخب کرنے سے وہ پہلے انسٹال ہو جاتا ہے۔ ایک تازہ Omarchy ایک بار کی اطلاع کے ساتھ آپ کو یہ انتخاب کرنے کی دعوت دے گا۔

Claude منتخب کرنے سے Chromium، Chrome، Brave، Brave Origin اور Edge کے لیے اس کی براؤزر توسیع ترتیب دینے کی کوشش بھی ہوتی ہے۔ توسیع کی ترتیب تمام صارفین پر لاگو ہوتی ہے اور آپ سے آپ کا سسٹم پاس ورڈ مانگ سکتی ہے؛ منسوخ کرنے یا توسیع کی انسٹالیشن ناکام ہونے پر بھی Claude منتخب اور لانچ ہو جاتا ہے۔ اپنا براؤزر دوبارہ شروع کریں، اشارہ ملنے پر توسیع فعال کریں، اور اسے جوڑنا مکمل کرنے کے لیے Claude میں سائن ان کریں۔ کنکشن چیک کرنے کے لیے Claude میں `/chrome` چلائیں۔ Firefox اور Zen اس توسیع کی حمایت نہیں کرتے۔ اگر یہ ترتیب شامل ہونے سے پہلے ہی Claude آپ کا ڈیفالٹ تھا تو توسیع انسٹال کرنے کے لیے اسے دوبارہ منتخب کریں۔

منتخب کرنے کے بعد، `Super + Shift + Ctrl + A` ڈیفالٹ ایجنٹ کو ایک مخصوص ٹرمینل ونڈو میں لانچ کرتا ہے (یا اگر آپ نے ابھی انتخاب نہیں کیا تو picker سامنے لاتا ہے)۔ آپ اسے `omarchy agent prompt "Review this project"` کے ساتھ سیدھا کسی کام میں بھی لانچ کر سکتے ہیں۔ Freebuff اور DeepSeek Harness کوئی ابتدائی پرامپٹ نہیں لیتے، چنانچہ وہ اس کے بجائے اس طرح کھلتے ہیں کہ پرامپٹ آپ کے کلپ بورڈ پر چسپاں کرنے کے لیے موجود ہوتا ہے۔ اس طرح لانچ کیے گئے ایجنٹس اپنے متعلقہ don't-stop-to-ask موڈز میں بغیر نگرانی کے چلتے ہیں، چنانچہ تیار رہیں کہ وہ واقعی کچھ کریں گے! MiniMax Code کے انٹرایکٹو سیشنز کے لیے ایسا کوئی موڈ نہیں، چنانچہ وہ معمول کے مطابق اجازتیں مانگتا ہے۔ اور چونکہ ایجنٹس آپ کی home ڈائریکٹری کے لیے اعتماد یاد رکھنے سے انکار کرتے ہیں، اس لیے `$HOME` سے لانچز اس کے بجائے `~/Work` میں شروع ہوتی ہیں۔

ٹرمینل شارٹ کٹس بھی ہیں: `a` ڈیفالٹ ایجنٹ کو موجودہ ٹرمینل میں ہی چلاتا ہے، جبکہ `c`، `cx` اور `cy` OpenCode، Claude Code اور Codex کو براہ راست شروع کرتے ہیں (ایک بار پھر ان کے auto-approving موڈز میں)۔ تھیم کی تبدیلیاں بھی ایجنٹس کے ساتھ ہم آہنگ ہوتی ہیں: جب آپ Omarchy تھیم بدلتے ہیں تو Claude Code، Pi، OpenCode اور Hermes (جب Omarchy نے اسے انسٹال کر لیا ہو) سب اس کے ساتھ چلتے ہیں۔

### آپ کی ایجنٹ ہدایات

ہر ایجنٹ کے لیے ذاتی قواعد `~/.agents/AGENTS.md` میں جاتے ہیں، `~/.agents/skills` میں مشترکہ skills کے ساتھ۔ اسے _Agent > Instructions_ کے تحت کھولیں، جو اسے ہر اس harness میں بھی لنک کرتا ہے جو اپنی عالمی فائل رکھتا ہے: `~/.claude/CLAUDE.md`، `~/.codex/AGENTS.md`، `~/.pi/agent/AGENTS.md`، `~/.config/opencode/AGENTS.md`، Copilot کی `~/.copilot/copilot-instructions.md`، وغیرہ۔ Crush اور Amp `~/.config/AGENTS.md` لنک پڑھتے ہیں، جبکہ omp، Kimi اور DeepSeek Harness `~/.agents/AGENTS.md` کو براہ راست پڑھتے ہیں۔ ڈیفالٹ ایجنٹ منتخب کرنے سے وہ بھی لنک ہو جاتا ہے۔ اگر ابھی کوئی مشترکہ فائل موجود نہیں تھی تو آپ کی پہلے سے موجود ہدایات فائل مشترکہ فائل بن جاتی ہے؛ بصورت دیگر اسے لنک کے ساتھ `.bak` کے طور پر رکھا جاتا ہے۔ ایک اور ایجنٹ انسٹال کرنے کے بعد دوبارہ لنک کرنے کے لیے `omarchy agent instructions` چلائیں۔

### ایجنٹس پینل

ٹاپ بار میں ایک ایجنٹس آئیکن ہے۔ ایجنٹ ترتیب دینے سے پہلے، اس کا پینل آپ کو Claude، Codex یا Grok میں سائن ان کرنے کے مراحل سے گزارتا ہے، اور پہلا والا آپ کا ڈیفالٹ ایجنٹ بن جاتا ہے۔ اس کے بعد، پینل ہر سبسکرپشن کو ایک صفحے پر رکھتا ہے: ہر ایجنٹ اور اکاؤنٹ اس کے پلان کے ساتھ، اس کی 5 گھنٹے کے سیشن اور ہفتہ وار حدود میں سے ہر ایک کے لیے ایک میٹر جس کے ساتھ ری سیٹ ہونے تک کا وقت ہوتا ہے (عین فیصد کے لیے hover کریں)، یا باقی پری پیڈ بیلنس، ایک سطر کے نیچے جو ان سب میں آپ کے استعمال کے درمیان گردش کرتی ہے، جیسے اس ہفتے کے ٹوکن اور آپ کا سب سے زیادہ استعمال شدہ ماڈل۔ _Make something_ کے تحت یہ نئی تھیم، پلگ ان، ایپ یا گیم کے لیے ابتدائی پرامپٹس پیش کرتا ہے جو کام آپ کے ڈیفالٹ ایجنٹ کے حوالے کرتے ہیں۔ ایپس اسی طرح بنائی جاتی ہیں جیسے Omarchy کی اپنی Hype، Monologue اور Omacut ہیں، C++ اور Qt Quick میں، omarchy-make-app ایجنٹ skill کی پیروی کرتے ہوئے، اور انہیں درکار compiler اور Qt اجزا انسٹال شدہ آتے ہیں۔ گیمز `~/Games/vibes` میں ایک واحد three.js صفحہ ہوتی ہیں، omarchy-make-game ایجنٹ skill کی پیروی کرتے ہوئے، اور سب موجودہ تھیم میں ایک Game Vibes لانچر سے کھلتی ہیں؛ وہ three.js ویب سے لوڈ کرتی ہیں، چنانچہ شروع ہونے کے لیے انہیں کنکشن درکار ہوتا ہے۔ Claude Code، Codex، Grok، Kimi، Cursor اور اس کا Grok Bot الاؤنس، GitHub Copilot، Muse، Antigravity، Kimchi اور Devin اپنی حدود کے ساتھ ابتدا ہی سے شامل ہیں، اور Hermes، Mistral Vibe اور Qwen Code آپ کے انہیں استعمال کرنے کے بعد اپنے سیشنز اور ٹوکن دکھاتے ہیں۔ pi، omp یا opencode کے ذریعے آپ جو فراہم کنندہ پلان اور keys استعمال کرتے ہیں وہ بھی ظاہر ہوتے ہیں: OpenCode Zen اور Go، Z.ai GLM Coding Plan، Ollama Cloud، MiniMax Token Plan اور Synthetic اپنی حدود کے ساتھ؛ Fireworks، OpenRouter اور DeepSeek اپنے پری پیڈ بیلنس کے ساتھ؛ اور وہ ماڈل جو آپ اپنے ہارڈویئر پر Local models کے تحت چلاتے ہیں۔ ہر ایجنٹ ایک بار گنا جاتا ہے، اس کے تحت جو اس کا بل دیتا ہے، خواہ آپ اسے کتنے ہی harnesses کے ذریعے چلائیں۔

پینل کے لیے بار آئیکن پر بائیں کلک کریں، اپنے ڈیفالٹ ایجنٹ کو لانچ کرنے کے لیے دائیں کلک کریں۔ اس کے پیچھے استعمال کے ریکارڈ ہر 15 منٹ بعد `omarchy agent usage-update` کے ذریعے دوبارہ بنائے جاتے ہیں، اور پینل ایک synced فولڈر کے ذریعے آپ کی دوسری مشینوں کے استعمال کو بھی ضم کر سکتا ہے۔ مکمل ترتیبات کے لیے `$OMARCHY_PATH/shell/plugins/agents/` کے تحت README دیکھیں۔

### متعدد سبسکرپشنز

اگر آپ ایک سے زیادہ Claude، Codex یا Grok پلان کی ادائیگی کرتے ہیں — مثلاً ایک ذاتی Max اور ایک کام والا — تو Omarchy ان سب کو سائن ان رکھ سکتا ہے اور ان کے درمیان منتقل ہو سکتا ہے۔ ایجنٹس پینل میں + کے ساتھ سبسکرپشن شامل کریں، جو آپ کو وہیں اس کے مراحل سے گزارتا ہے، یا `omarchy agent account add claude Work` (یا `codex`، یا `grok`) کے ساتھ۔ اگر CLI موجود نہیں تو یہ اسے انسٹال کرتا ہے۔ کسی فراہم کنندہ کے لیے پہلا اکاؤنٹ آپ کے عام براؤزر کے ذریعے سائن ان ہوتا ہے، عین وہیں جہاں CLI ہمیشہ دیکھتا ہے۔ اس کے بعد ہر ایک نجی ونڈو کے ذریعے سائن ان ہوتا ہے، تاکہ جس اکاؤنٹ میں آپ کا براؤزر پہلے سے سائن ان ہے وہ غلطی سے نہ پکڑا جائے؛ وہاں اس اکاؤنٹ کے طور پر سائن ان کریں جو آپ شامل کر رہے ہیں، اور پہلے سے کھلی ہوئی کوئی نجی ونڈو پہلے بند کریں۔ اس کے لیے کبھی CLI سے لاگ آؤٹ نہ کریں: لاگ آؤٹ کرنے سے محفوظ شدہ سائن ان منسوخ ہو جاتا ہے، اور اس اکاؤنٹ کو دوبارہ شامل کرنا پڑے گا۔

اپنے سبسکرپشن لاگ انز کو SSH کے ذریعے کسی دوسری Omarchy مشین پر کاپی کرنے کے لیے `omarchy agent account copy user@laptop` چلائیں۔ جب منزل پر کوئی انسٹال نہ ہو تو بھیجنے والا ایک عارضی وصول کنندہ فراہم کرتا ہے، چنانچہ پرانی Omarchy مشینیں اپ ڈیٹ کے بغیر اکاؤنٹس وصول کر سکتی ہیں۔ انسٹال شدہ وصول کنندگان کو ترجیح حاصل ہوتی ہے۔ یہ تمام Claude، Codex اور Grok سبسکرپشنز کاپی کرتا ہے؛ انہیں منتخب کرنے کے لیے فراہم کنندگان کے نام شامل کریں، جیسے `omarchy agent account copy laptop claude` میں۔ اکاؤنٹ کے نام اور command IDs ماخذ سے ملتے ہیں، بشمول وہ اکاؤنٹس جو منزل پر پہلے سے موجود ہیں۔ اگر غیر متعلقہ منزل اکاؤنٹس کے ناموں میں تصادم ہو تو انہیں عددی لاحقہ ملتا ہے، اور ترتیبات، skills، پلگ ان اور گفتگو کی تاریخ ہر مشین پر مقامی رہتی ہے۔

منزل کی موجودہ اسناد برقرار رکھی جاتی ہیں۔ کوئی ماخذ اکاؤنٹ جو وہاں پہلے سے سائن ان ہے اس کا نام اس کی اسناد بدلے بغیر ہم آہنگ ہو جاتا ہے؛ دوسرے اکاؤنٹس اس کے ساتھ شامل ہو جاتے ہیں۔ ملتے جلتے اکاؤنٹس کے لیے محفوظ شدہ اسناد بدلنے کے لیے، منزل پر اس اکاؤنٹ کے سیشنز بند کرنے کے بعد `omarchy agent account copy --replace laptop claude` استعمال کریں۔ ایک تازہ منزل کو ماخذ کا فعال اکاؤنٹ اور سوئچنگ ترجیحات بھی ملتی ہیں؛ ایک قائم شدہ منزل اپنی ترجیحات برقرار رکھتی ہے۔

اسناد SSH کے ذریعے سفر کرتی ہیں اور منزل پر نجی فائلوں میں محفوظ ہوتی ہیں، چنانچہ صرف ان مشینوں پر کاپی کریں جن پر آپ اعتماد کرتے ہیں۔ یہ ایک بار کی کاپی ہے، جاری ہم آہنگی نہیں۔ Codex refresh ٹوکن کسی دوسری مشین کے ذریعے بدلے جا سکتے ہیں، جس سے کاپی شدہ لاگ ان کو تجدید کی ضرورت پڑتی ہے؛ کئی مشینوں پر بیک وقت استعمال کے لیے الگ الگ سائن ان سب سے قابل اعتماد انتخاب ہیں۔ [Codex کی اکاؤنٹ تصدیق کی رہنمائی](https://developers.openai.com/codex/auth/ci-cd-auth) دیکھیں۔

فی فراہم کنندہ ایک اکاؤنٹ فعال ہوتا ہے، اور ہر نیا سیشن اسی کے طور پر شروع ہوتا ہے: `cx`، `cy`، ایک سادہ `claude`، `codex` یا `grok`، `omarchy agent` کے ذریعے لانچ کی گئی کوئی بھی چیز، اور اسکرپٹس یا ایڈیٹرز جو CLI کو `PATH` پر پاتے ہیں۔ `omarchy agent account use work` کے ساتھ سوئچ کریں (اور `omarchy agent account use main` کے ساتھ واپس)، یا پینل میں کسی اکاؤنٹ کا نمبر دبا کر پھر `Enter` دبا کر (یا اس کے Use بٹن پر کلک کر کے)۔ چلتے ہوئے Claude سیشنز بھی اپنے اگلے پیغام سے سوئچ ہو جاتے ہیں: ہر Claude سیشن `~/.claude` میں چلتا ہے، جس میں ہمیشہ فعال اکاؤنٹ کا سائن ان ہوتا ہے۔ پرانی Omarchy کے ذریعے کسی اکاؤنٹ کے اپنے فولڈر میں شروع کیا گیا Claude سیشن اس سائن ان کو بند ہونے تک رکھتا ہے، چنانچہ سوئچ ان سیشنز کے نام بتاتا ہے اور ان کے ختم ہونے پر خود مکمل ہو جاتا ہے۔ چلتے ہوئے Codex اور Grok سیشنز اسی اکاؤنٹ پر رہتے ہیں جس سے وہ شروع ہوئے تھے۔ گفتگو کی تاریخ، ترتیبات، skills اور پلگ ان اکاؤنٹس کے درمیان مشترکہ ہوتے ہیں، چنانچہ اسی فولڈر میں `claude --continue` نئے اکاؤنٹ پر وہیں سے جاری رہتا ہے جہاں آپ نے چھوڑا تھا۔

ایک سے زیادہ اکاؤنٹ کے ساتھ، پینل ہر اکاؤنٹ کی حدود ساتھ ساتھ دکھاتا ہے، فعال والے کو نشان زد کر کے۔ بطور ڈیفالٹ Omarchy آپ کو مطلع کرتا ہے جب فعال اکاؤنٹ کسی حد کے %95 سے گزر جاتا ہے، اور اطلاع پر کلک کرنے سے سب سے زیادہ گنجائش والے اکاؤنٹ پر سوئچ ہو جاتا ہے۔ پینل میں کسی اکاؤنٹ کی سطر پر hover کریں اور Use کے ساتھ ظاہر ہونے والے Autoswitch پر کلک کریں (یا `m` دبائیں)، یا خود بخود سوئچ کرنے کے لیے `omarchy agent account mode auto` چلائیں؛ جب یہ آن ہوتا ہے تو Autoswitch Use کی جگہ لے لیتا ہے، اور اس پر دوبارہ کلک کرنے سے مطلع کرنے پر واپس آ جاتا ہے۔ حد بدلنے کے لیے نمبر شامل کریں، جیسے `omarchy agent account mode auto 90` میں۔ اگر ہر اکاؤنٹ حد سے اوپر ہو تو آپ کو ایک بار اس کے بارے میں بتایا جائے گا، اس کے ساتھ کہ کون سا اکاؤنٹ سب سے پہلے آزاد ہوتا ہے۔ جب کوئی فعال اکاؤنٹ اپنی حد کے 15 پوائنٹس کے اندر ہو (ڈیفالٹ پر %80)، تو اس کی حدود ہر 15 کے بجائے ہر تین منٹ بعد چیک کی جاتی ہیں۔

`omarchy agent account list` ہر اکاؤنٹ اور اس کی تازہ ترین حدود دکھاتا ہے، `omarchy agent account remove work` ایک کو بھول جاتا ہے، اور `omarchy agent account rename primary Hey` ایک کا نام بدلتا ہے (یا پینل میں کسی اکاؤنٹ کے نام پر کلک کریں)۔ یہ کمانڈز آپ کے ڈیفالٹ ایجنٹ کے اکاؤنٹس پر کام کرتی ہیں؛ دوسرے فراہم کنندہ تک پہنچنے کے لیے پہلے اس کا نام بتائیں، جیسے `omarchy agent account use codex side` میں۔ `~/.claude` یا `~/.codex` میں آپ کے پاس پہلے سے موجود لاگ ان _Main_ اکاؤنٹ ہے۔ Codex کا وہیں رہتا ہے جہاں وہ ہے؛ Claude کا ایک دوسرے اکاؤنٹ کے فعال ہونے کے دوران اپنے فولڈر میں انتظار کرتا ہے۔ تقریباً آٹھ گھنٹے سے زیادہ غیر استعمال شدہ چھوڑا گیا اکاؤنٹ _Sign-in required_ دکھا سکتا ہے؛ اس اکاؤنٹ کو پینل میں ہی دوبارہ سائن ان کرنے کے لیے اس پر کلک کریں، یا اس پر سوئچ کر کے سیشن شروع کریں، جو سائن ان کو خود تازہ کر دیتا ہے۔ `claude mcp add` کے ساتھ آپ جو MCP سرور شامل کرتے ہیں وہ ہر Claude اکاؤنٹ تک پہنچتے ہیں، چونکہ وہ سب `~/.claude` میں چلتے ہیں؛ Codex اور Grok کے لیے، اکاؤنٹ شامل کرتے وقت آپ کے پاس موجود سرور اس کے ساتھ آ جاتے ہیں، لیکن بعد والے صرف اسی اکاؤنٹ تک پہنچتے ہیں جس میں آپ نے انہیں شامل کیا تھا۔ Claude Desktop اپنا سائن ان برقرار رکھتا ہے، اور CLI بائنری کے مطلق راستے کے ساتھ تشکیل شدہ Codex یا Grok ٹولز سوئچ کی پیروی نہیں کرتے۔ ایک واضح `CLAUDE_CONFIG_DIR`، `CODEX_HOME` یا `GROK_HOME` منتخب شدہ اکاؤنٹ پر فوقیت رکھتا ہے۔

### کریش کی تشخیص

Omarchy عمل کے کریشز کے لیے systemd-coredump کی نگرانی کرتا ہے۔ جب کوئی چیز segfault کرتی ہے تو آپ کو "Process crashed" اطلاع ملے گی — اس پر کلک کریں، اور کریش آپ کے ڈیفالٹ ایجنٹ کے حوالے کر دیا جاتا ہے Omarchy کی diagnose-crash skill کے ساتھ، جو ایجنٹ کو core dump سے حقائق قائم کرنے اور یہ فیصلہ کرنے کے مراحل سے گزارتی ہے کہ آیا کریش upstream رپورٹ کرنے کے قابل ہے۔ آپ اسے `coredumpctl list` سے کسی بھی PID کے خلاف `omarchy agent crash <pid>` کے ساتھ ہاتھ سے بھی چلا سکتے ہیں۔

نگرانی بطور ڈیفالٹ آن ہوتی ہے۔ اسے _Trigger > Toggle > Crash Capture_ کے تحت (یا `omarchy toggle crash-capture` کے ساتھ) بند کریں اور اطلاعات رک جاتی ہیں؛ `omarchy agent crash <pid>` ہاتھ سے پھر بھی کام کرتا ہے۔

کریشز کو ایک وقت میں ایک پروگرام کے حساب سے خاموش بھی کیا جا سکتا ہے، جو تشخیص آخر میں آپ کو پیش کرتی ہے۔ `omarchy crash mute hyprland` صرف اس پروگرام کے لیے اطلاعات روکتا ہے، `omarchy crash mute hyprland off` انہیں واپس لاتا ہے، اور اکیلا `omarchy crash mute` وہ فہرست دیتا ہے جو آپ نے خاموش کیا ہے۔ یہ بائنری کا راستہ اس کے نام کی طرح خوشی سے لیتا ہے، چنانچہ `omarchy crash mute /usr/bin/hyprland` وہی کام کرتا ہے۔ جس نام میں جگہ ہو اسے اقتباس میں رکھیں، جیسے `omarchy crash mute 'Some App'` میں۔ باقی سب کچھ پھر بھی مطلع کرتا ہے، اور خاموش کیا گیا پروگرام پھر بھی کریش ہوتا ہے — یہ یاد دہانی چھپاتا ہے، یہ کچھ ٹھیک نہیں کرتا۔

### ڈیسک ٹاپ ایپس

_Install > AI_ مینو چند گرافیکل AI ایپس بھی رکھتا ہے: ChatGPT ڈیسک ٹاپ ایپ، Claude ڈیسک ٹاپ ایپ (Anthropic کا Linux بیٹا، Chat، Cowork اور Claude Code ٹیبز کے ساتھ)، xAI کے ماڈلز کے ساتھ چیٹ کے لیے Grok Bot، Herdr Desktop، Hermes Desktop، OpenClaw، Perplexity ڈیسک ٹاپ ایپ، اور T3 Code۔ Grok Bot ڈیسک ٹاپ چیٹ ایپ ہے۔ کوڈنگ ایجنٹ `grok` کمانڈ ہے۔

Hermes Desktop وہ ہے جس کے بارے میں جاننا ضروری ہے، کیونکہ ایک مشین میں ایک Hermes ہوتا ہے، اور وہ ایپ کا ہوتا ہے: Hermes ہمیشہ صرف ایپ کے ذریعے انسٹال ہوتا ہے، اور ڈیفالٹ ایجنٹ جو `hermes` کمانڈ چلاتا ہے وہ ایپ کی ہوتی ہے۔ Hermes کو ڈیفالٹ ایجنٹ کے طور پر منتخب کرنا وہی چیز انسٹال کرتا ہے جو _Install > AI_ اندراج کرتا ہے: پیکیج، اور Hermes کے اپنے انسٹالر کے ذریعے ترتیب دیا گیا `~/.hermes` کے تحت ایک Hermes رن ٹائم، جس میں پہلی بار چند منٹ لگتے ہیں۔ وہ رن ٹائم وہ واحد Hermes ہے جسے ٹرمینل `hermes` کمانڈ، ڈیفالٹ ایجنٹ اور ایپ سب استعمال کرتے ہیں، اور یہ Omarchy ریلیز کا انتظار کرنے کے بجائے `hermes update` کے ساتھ خود کو اپ ڈیٹ کرتا ہے۔ اسے انسٹال کرنے سے Hermes کو Omarchy تھیم بطور `omarchy` نامی skin بھی ملتی ہے، جس کی ہر Hermes سطح آپ کے تھیم بدلنے پر پیروی کرتی ہے؛ اگر آپ نہیں چاہتے کہ ایسا ہو تو Hermes کی Appearance ترتیبات کے تحت یا `/skin` کے ساتھ کوئی اور منتخب کریں، اور Omarchy اس انتخاب کو چھوڑ دیتا ہے۔ _Remove > AI_ کے تحت ایپ ہٹانے سے پہلے Hermes بند ہوتا ہے، gateway سمیت، وہ رن ٹائم اپنے ساتھ لے جاتا ہے، اور آپ کی چیٹس، یادیں اور وہ skills جو Hermes نے خود کے لیے لکھی تھیں برقرار رکھتا ہے الا یہ کہ آپ اسے اس کے برعکس کہیں: یہ پوچھتا ہے، ڈیفالٹ نہیں کے ساتھ، کہ آیا وہ ڈیٹا اور آپ کی کنکشن ترتیبات بھی جانی چاہئیں۔

OpenClaw کا ڈیسک ٹاپ تجربہ اس کا Control UI ہے، جو اس کے اپنے مقامی gateway کی پشت پناہی سے ایک ویب ایپ کے طور پر کھلتا ہے۔ OpenClaw `~/.openclaw` میں رہتا ہے اور خود کو اپ ڈیٹ کرتا ہے: Control UI کا "Update Gateway" بٹن استعمال کریں یا `openclaw update` چلائیں، اور gateway نئے ورژن پر دوبارہ شروع ہوتا ہے۔ Omarchy صرف وہ ریلیز منتخب کرتا ہے جس سے تازہ انسٹال شروع ہوتا ہے۔ _Remove > AI_ کے تحت OpenClaw ہٹانے سے gateway سروس اور ایپ اس کے ساتھ جاتی ہے اور پھر پوچھتا ہے کہ آیا `~/.openclaw` بھی جانا چاہیے، چونکہ اس میں OpenClaw خود اور اس کے ڈاؤن لوڈ کردہ پلگ ان رن ٹائمز کے ساتھ آپ کی چیٹس اور اسناد ہوتی ہیں؛ ڈیفالٹ اسے برقرار رکھتا ہے، اور OpenClaw دوبارہ انسٹال کرنے سے یہ واپس مل جاتا ہے۔

Herdr Desktop [Herdr](https://herdr.dev) ڈیسک ٹاپ ایپ ہے: ٹرمینلز اور کوڈنگ ایجنٹس کی spaces، ٹیبز اور panes جو آپ کے ونڈو بند کرنے پر اس کے core میں چلتے رہتے ہیں۔ یہ کسی پیکیج کے بجائے Herdr کے اپنے انسٹالر سے آتی ہے، چنانچہ یہ `~/.local/share/herdr-app` میں رہتی ہے، جب آپ کے پاس پہلے سے کوئی نہ ہو تو اپنے core کو `~/.local/bin/herdr-core` میں ساتھ لاتی ہے، اور دونوں خود کو اپ ڈیٹ کرتے ہیں۔ یہ Omarchy کی فراہم کردہ `herdr` کمانڈ کے ساتھ `Super + Ctrl + Return` پر بیٹھتی ہے اسے بدلنے کے بجائے، اور اس کمانڈ کی براہ راست keys حاصل کرتی ہے: `Alt + Return` اور `Alt + Shift + Return` کسی pane کو نیچے یا دائیں تقسیم کرتے ہیں، `Alt + Escape` اسے بند کرتا ہے، `Ctrl + Alt + Arrow` panes کے درمیان منتقل ہوتا ہے، `Alt + 1..9` اور `Alt + Left/Right` ٹیب منتخب کرتے ہیں، اور `Alt + Up/Down` spaces کے درمیان منتقل ہوتے ہیں۔ `Ctrl + 1..9` space منتخب کرتا ہے اور `Alt + Shift + Up/Down` ایجنٹس میں مرحلہ وار آگے بڑھتا ہے۔ `Ctrl + Space` prefix keys صرف ٹرمینل کے لیے رہتی ہیں، چونکہ ایپ کسی ترتیب کے لیے سادہ Ctrl key نہیں پکڑ سکتی۔ Omarchy یہ `~/.config/herdr-app/keys.json` میں لکھتا ہے، اور `omarchy-refresh-herdr-app` انہیں واپس رکھتا ہے۔ اسے انسٹال کرنے سے Herdr کی Omarchy تھیم منتخب ہوتی ہے، جو اس کے بعد سے آپ کی Omarchy تھیم کی پیروی کرتی ہے۔ Herdr ہلکے موڈ کے لیے ایک تھیم اور گہرے موڈ کے لیے ایک رکھتا ہے، چنانچہ گہری اور ہلکی Omarchy تھیم کے درمیان سوئچ کرنے کے بعد، دوسرے موڈ کے لیے Herdr کے تھیم picker میں ایک بار پھر Omarchy منتخب کریں۔

T3 Code کسی پیکیج کے بجائے `~/.local/share/t3code` میں اپنی آفیشل AppImage ریلیز سے چلتا ہے، چنانچہ یہ خود کو اپ ڈیٹ کرتا ہے۔ اسے انسٹال کرنے سے پوچھا جاتا ہے کہ آیا Stable یا Nightly چینل پر شروع کرنا ہے؛ بعد میں T3 Code کی ترتیبات میں سوئچ کریں۔ آپ کے تھریڈز اور ترتیبات `~/.t3` میں رہتی ہیں، اور _Remove > AI_ کے تحت T3 Code ہٹانے سے وہ اس کے ساتھ جاتی ہیں۔

### مقامی ماڈل

اپنے کوڈنگ ایجنٹس کے لیے اپنی مشین پر ایک کھلا ماڈل چلائیں۔ آپ کے پرامپٹس اور کوڈ مشین پر رہتے ہیں؛ ماڈل کو بھیجی گئی کوئی چیز اسے نہیں چھوڑتی۔ اس سے شروع کریں:

```bash
omarchy agent local use best
```

یا، ٹاپ بار میں ایجنٹس پینل میں، + اور پھر Local AI منتخب کریں، جو اس وقت ظاہر ہوتا ہے جب کوئی ماڈل اس مشین میں فٹ آتا ہو۔ پہلی بار، یہ Podman انسٹال کرتا ہے، جو ماڈل چلاتا ہے، اور NVIDIA مشین پر NVIDIA کا container toolkit، جو انہیں GPU دیتا ہے۔ پھر Omarchy اس مشین کے لیے تجویز کردہ ماڈل منتخب کرتا ہے، اسے ڈاؤن لوڈ کرتا ہے، اور اسے شروع کرتا ہے۔ دسیوں GB کے ڈاؤن لوڈ اور ماڈل چلنے کے دوران مشین کی زیادہ تر میموری استعمال میں ہونے کی توقع رکھیں: Flash Next اپنے مکمل 256K سیاق و سباق کے ساتھ تقریباً 100 GiB استعمال کرتا ہے۔ اگر دوسرے ماڈل اسے درکار میموری روکے ہوئے ہوں تو یہ رکا ہوا ترتیب دیا جاتا ہے، ایک کو روکنے پر شروع ہونے کے لیے تیار۔ ماڈل لاگ آؤٹ پر رک جاتا ہے؛ جب آپ کو کسی اور چیز کے لیے میموری درکار ہو تو اسے خود روکیں۔

`omarchy agent local list` اختیارات دکھاتا ہے اور بیان کرتا ہے کہ کچھ کیوں فٹ نہیں آتے۔ ایک اور ترتیب دینے کے لیے `omarchy agent local use <recipe>` چلائیں۔ آج، 128 GB Strix Halo مشینوں کے لیے `qwen3.8-flash-next-gufo` اور `qwen3.8-27b-gufo` دستیاب ہیں؛ 27B تقریباً 40 GiB لیتا ہے، چنانچہ یہ دوسرے کام کے لیے جگہ چھوڑتا ہے۔ Intel کے Arc B390 کے ساتھ 64 GB لیپ ٹاپ پر، `qwen3.6-35b-a3b-llamacpp` تقریباً 30 GiB میں چلتا ہے۔ نئی recipes اور تجاویز پیکیج کے ذریعے `omarchy update` کے ساتھ آتی ہیں۔

آپ کے ترتیب دیے گئے ہر ماڈل کو ایجنٹس پینل میں اپنی سطر ملتی ہے، آپ کی سبسکرپشنز کے ساتھ: شروع کرنے کے لیے play، اسے روکنے اور اس کی میموری آزاد کرنے کے لیے pause، اور اس پر اپنا ایجنٹ کھولنے کے لیے ٹرمینل بٹن۔ کئی ایک ساتھ چل سکتے ہیں جب وہ میموری میں ایک ساتھ فٹ آتے ہوں؛ اگر کوئی فٹ نہ آئے تو Omarchy بتاتا ہے کہ کس چلتے ہوئے ماڈل کو روکنا ہے۔ انہیں دوبارہ ترتیب دینے کے لیے سطریں گھسیٹیں، اور ماڈل اور اس کا ڈاؤن لوڈ ہٹانے کے لیے منتخب سطر پر Delete دبائیں۔

آپ کے ترتیب دیے گئے ہر ماڈل کو ایپ لانچر میں بھی اپنی اندراج ملتی ہے، ماڈل کے نام کے تحت اور اس کے بنانے والے کے لوگو کے ساتھ، جس طرح Claude، Codex یا Grok میں سائن ان کرنے سے ایک شامل ہوتا ہے۔ یہ اس ماڈل پر آپ کا ایجنٹ کھولتی ہے، اور اگر ماڈل نہ چل رہا ہو تو پہلے اسے شروع کرتی ہے: ٹرمینل اسے لوڈ ہوتا دکھاتا ہے اور تیار ہونے پر ایجنٹ کے حوالے کرتا ہے۔ ماڈل ہٹانے سے اس کی اندراج ہٹ جاتی ہے۔

ایک ماڈل عین اسی طرح چلتا رہتا ہے جیسے اسے ترتیب دیا گیا تھا، چنانچہ Omarchy اپ ڈیٹ کبھی آپ کے ایجنٹس کے نیچے ایک کو دوبارہ شروع نہیں کرتا۔ جب Omarchy کے پاس آپ کے ترتیب دیے گئے ماڈل کے لیے نیا رن ٹائم یا نئے weights ہوں تو اس کی سطر اپ ڈیٹ بٹن دکھاتی ہے: اسے دبائیں اور ماڈل پس منظر میں دوبارہ ترتیب دیا جاتا ہے، صرف وہ ڈاؤن لوڈ کرتے ہوئے جو بدلا ہے، اور نئے ورژن پر دوبارہ شروع ہوتا ہے۔ جو ماڈل رکا ہوا تھا وہ رکا رہتا ہے۔ `omarchy agent local update` ٹرمینل سے ہر ماڈل کے لیے یہی کرتا ہے۔

کمانڈ لائن سے، `omarchy agent local start <recipe>` اور `omarchy agent local stop <recipe>` یہی کرتے ہیں، `omarchy agent local status` ہر ماڈل دکھاتا ہے، اور `omarchy agent --local` آپ کے ڈیفالٹ ایجنٹ کو آخری شروع کیے گئے ماڈل پر کھولتا ہے۔ pi، OpenCode اور Qwen Code ایک استعمال کر سکتے ہیں؛ کسی دوسرے ڈیفالٹ کے ساتھ یہ pi میں کھلتا ہے۔ pi آپ کے ترتیب دیے گئے ہر ماڈل، اور جن مشینوں کے ساتھ آپ نے جوڑا بنایا ہے ان پر موجود ماڈلز کو بھی، اپنے ماڈل picker میں فہرست کرتا ہے، چنانچہ سادہ `pi` بھی ان تک پہنچتا ہے۔ کوئی بھی OpenAI سے مطابقت رکھنے والا کلائنٹ بھی جڑ سکتا ہے: `status` ہر ماڈل کا پتہ دکھاتا ہے (پہلا `http://127.0.0.1:11435/v1` ہے)، recipe نام ماڈل ہے، اور key `~/.config/omarchy/agent-local/key` میں ہے۔

`omarchy agent local remove <recipe>` ایک ماڈل اور وہ ڈاؤن لوڈز حذف کرتا ہے جو کوئی دوسرا ماڈل استعمال نہیں کرتا۔

فریق ثالث رن ٹائمز پر ان کے ناشر کا لیبل ہوتا ہے۔ Omarchy ہر ماڈل کو بغیر نیٹ ورک رسائی کے چلاتا ہے۔

### مقامی LLMs

Omarchy مقامی LLM ماڈل چلانے کے دو طریقے تجویز کرتا ہے: LM Studio اور Ollama۔ LM Studio کھلے وزن والے ماڈل تلاش کرنے، انہیں انسٹال کرنے اور انہیں چلانے کے لیے GUI انٹرفیس فراہم کرتا ہے۔ آسانی سے شروع کرنے کا یہ ایک بہترین طریقہ ہے۔ Ollama اسی طرح کرنے کے لیے CLI پیش کرتا ہے۔ لیکن اگر آپ مقامی ماڈلز میں نئے ہیں تو میں LM Studio سے آغاز کروں گا۔ آپ Omarchy Menu میں _Install > AI_ کے تحت دونوں میں سے کوئی انسٹال کر سکتے ہیں۔

### The Omarchy Skill

ایجنٹ skills AI کو مخصوص ٹولز کو مخصوص طریقے سے استعمال کرنے میں مدد دیتی ہیں، اور Omarchy سسٹم کو اپنی مرضی کے مطابق بنانے کے لیے ایک ڈیفالٹ skill کے ساتھ آتا ہے۔ جیسے آپ کی Hyprland config میں رد و بدل کرنا، بار کو ایڈجسٹ کرنا، یا حتیٰ کہ شروع سے ایک نئی تھیم بنانا۔ یہ Claude Code (`~/.claude/skills`)، Codex (`~/.codex/skills`)، Pi (`~/.pi/agent/skills`)، Antigravity (`~/.gemini/config/skills`)، Hermes (`~/.hermes/skills` اور ہر `~/.hermes/profiles/*/skills`)، اور عام `~/.agents/skills` مقام کے لیے skill ڈائریکٹریوں میں symlinked ہے، چنانچہ زیادہ تر harnesses اسے خود بخود اٹھا لیتے ہیں۔

لیکن آپ کو اس skill کو تجرباتی سمجھنا چاہیے۔ مختلف ماڈل اسے مختلف اثر کے ساتھ استعمال کریں گے۔ بہتر ہے پہلے plan موڈ میں چلائیں، تاکہ آپ کو اندازہ ہو کہ ایجنٹ کیا بدلنا چاہے گا۔ اور پھر تبدیلیاں واپس لینے یا حتیٰ کہ `omarchy reinstall configs` چلانے کے لیے تیار رہیں، اگر ایجنٹ ہر چیز کا گڑبڑ کر دے۔
