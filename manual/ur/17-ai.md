### ایجنٹس انسٹال اور اپ ڈیٹ کرنا

Hermes اور OpenClaw کے سوا، یہ ایجنٹس mise کی سست انسٹالیشن استعمال کرتے ہیں: پہلی لانچ پر CLI انسٹال ہوتا ہے، اور بعد کی لانچز اسی کو دوبارہ استعمال کرتی ہیں۔ mise انسٹال شدہ ایجنٹ کے لیے نئی ریلیز کی جانچ بھی زیادہ سے زیادہ ہر چار گھنٹے میں ایک بار کرتا ہے، اس کے شروع ہونے سے عین پہلے یا پس منظر میں شیل پرامپٹ پر۔ اگر وہ اپ ڈیٹ ناکام ہو جائے یا آپ آف لائن ہوں تو انسٹال شدہ ورژن چلتا ہے۔ `omarchy update` انسٹال شدہ ایجنٹس کو باقی Omarchy کے ساتھ اپ ڈیٹ کرتا ہے، اور `mup` صرف mise کے زیر انتظام ٹولز کو اپ ڈیٹ کرتا ہے۔

کسی ایجنٹ کا اپنا اپڈیٹر، جیسے `claude update`، `codex update`، یا کسی ایپ میں اپ ڈیٹ کا بٹن، mise کے زیر انتظام انسٹال کو اپ ڈیٹ نہیں کرتا۔ `codex update` ناکام ہو جاتا ہے، اور `claude update` کامیابی کی اطلاع دے سکتا ہے جبکہ وہ ایک الگ کاپی انسٹال کر رہا ہو جسے mise ٹریک نہیں کرتا۔ اگر آپ اس کے بجائے کسی ایجنٹ کا اپنا انسٹالر اور اپڈیٹر استعمال کرنا چاہتے ہیں تو اسے `disable_tools` میں شامل کریں؛ دیکھیں [پہلے سے انسٹال شدہ CLI ٹولز](18-development-tools.md#preinstalled-cli-tools)۔

تمام ترتیب شدہ سست ٹولز کو ضرورت پڑنے سے پہلے انسٹال کرنے کے لیے `mise install --include-lazy` چلائیں۔ اس میں ایجنٹس کے ساتھ ساتھ Omarchy کے دوسرے ڈیفالٹ CLI ٹولز بھی شامل ہیں۔ ایک اکیلا ٹول انسٹال کرنے یا اپنی انسٹالیشن استعمال کرنے کے لیے دیکھیں [پہلے سے انسٹال شدہ CLI ٹولز](18-development-tools.md#preinstalled-cli-tools)۔

`grok` mise کے فرسٹ پارٹی `grok` پیکیج کے ذریعے انسٹال ہوتا ہے، اسی طرح جیسے `claude` اور `codex`۔ `grok` چلائیں، یا اسے _Agent > Harness_ کے تحت منتخب کریں۔ x.ai پر موجود `curl | bash` انسٹالر کو چھوڑ دیں۔ وہ راستہ `~/.grok/bin` میں دوسری کاپی رکھتا ہے، اسے `PATH` کے شروع میں شامل کر دیتا ہے، اور Omarchy کے ریپر کو اوور رائٹ کر دیتا ہے۔

`dsh` اپنا براؤزر UI `127.0.0.1:3080` پر کھولتا ہے، جس میں لانچ ڈائریکٹری اس کا ڈیفالٹ ورک اسپیس ہوتی ہے۔ اس کا براؤزر UI کوئی ابتدائی پرامپٹ نہیں لیتا، لہٰذا `omarchy agent prompt` اسے اس پرامپٹ کے ساتھ کھولتا ہے جو آپ کے کلپ بورڈ پر چسپاں کرنے کے لیے موجود ہوتا ہے۔ Omarchy اسے DeepSeek کے بغیر منظوری والے اجازت پری سیٹ کے ساتھ شروع کرتا ہے۔ جب آپ اس کا سرکاری ماڈل API استعمال کرتے ہیں تو DeepSeek Harness سیشن لاگز DeepSeek کو اپ لوڈ کرتا ہے؛ اسے اس کے براؤزر UI میں _Settings > General > Upload Session Log_ کے تحت بند کریں۔ آپ جو رائے اسے بھیجتے ہیں وہ بھی سیشن کے ساتھ اپ لوڈ ہوتی ہے، الا یہ کہ آپ اسے `DSH_TELEMETRY_MODE=DISABLED` کے ساتھ شروع کریں۔

### ڈیفالٹ ایجنٹ

اپنا ڈیفالٹ ایجنٹ `omarchy default agent <name>` کے ساتھ یا Omarchy Menu (`Super + Space`) میں _Agent > Harness_ کے تحت منتخب کریں۔ اگر ایجنٹ ابھی انسٹال نہیں ہوا تو اسے منتخب کرنے سے وہ پہلے انسٹال ہو جاتا ہے، اور اسے ایپ لانچر میں Agent کے ساتھ ساتھ اس کا اپنا لانچر بھی مل جاتا ہے۔ ایک تازہ Omarchy آپ کو یک وقتی اطلاع کے ساتھ یہ انتخاب کرنے کی دعوت دے گا۔

Claude کو منتخب کرنا Chromium، Chrome، Brave، Brave Origin اور Edge کے لیے اس کی براؤزر ایکسٹینشن ترتیب دینے کی بھی کوشش کرتا ہے۔ ایکسٹینشن کی ترتیب تمام صارفین پر لاگو ہوتی ہے اور آپ سے آپ کا سسٹم پاس ورڈ مانگ سکتی ہے؛ منسوخ کرنے یا ایکسٹینشن کی انسٹالیشن ناکام ہونے کے باوجود Claude منتخب اور لانچ ہو جاتا ہے۔ اپنا براؤزر دوبارہ شروع کریں، اشارہ ملنے پر ایکسٹینشن فعال کریں، اور اسے جوڑنا مکمل کرنے کے لیے Claude میں سائن ان کریں۔ کنکشن جانچنے کے لیے Claude میں `/chrome` چلائیں۔ Firefox اور Zen اس ایکسٹینشن کی حمایت نہیں کرتے۔ اگر یہ ترتیب شامل کیے جانے سے پہلے ہی Claude آپ کا ڈیفالٹ تھا تو ایکسٹینشن انسٹال کرنے کے لیے اسے دوبارہ منتخب کریں۔

ایک بار منتخب کر لینے کے بعد، `Super + Shift + Ctrl + A` ڈیفالٹ ایجنٹ کو ایک مخصوص ٹرمینل ونڈو میں لانچ کرتا ہے (یا اگر آپ نے ابھی تک انتخاب نہیں کیا تو منتخب کنندہ سامنے لاتا ہے)۔ آپ اسے `omarchy agent prompt "Review this project"` کے ساتھ سیدھا کسی کام میں بھی لانچ کر سکتے ہیں۔ Freebuff اور DeepSeek Harness کوئی ابتدائی پرامپٹ نہیں لیتے، لہٰذا اس کے بجائے وہ اس پرامپٹ کے ساتھ کھلتے ہیں جو آپ کے کلپ بورڈ پر چسپاں کرنے کے لیے موجود ہوتا ہے۔ اس طرح لانچ کیے گئے ایجنٹس اپنے متعلقہ رکنے اور پوچھنے سے گریز والے طریقوں میں بغیر نگرانی کے چلتے ہیں، لہٰذا اس کے لیے تیار رہیں کہ وہ واقعی کچھ کریں گے! MiniMax Code کے پاس اس کے انٹرایکٹو سیشنز کے لیے ایسا کوئی طریقہ نہیں ہے، لہٰذا وہ معمول کے مطابق اجازتیں مانگتا ہے۔ اور چونکہ ایجنٹس آپ کی ہوم ڈائریکٹری کے لیے اعتماد یاد رکھنے سے انکار کرتے ہیں، اس لیے `$HOME` سے لانچز اس کے بجائے `~/Work` میں شروع ہوتی ہیں۔

ٹرمینل شارٹ کٹس بھی ہیں: `a` ڈیفالٹ ایجنٹ کو موجودہ ٹرمینل میں ان لائن چلاتا ہے، جبکہ `c`، `cx` اور `cy` OpenCode، Claude Code اور Codex کو براہ راست شروع کرتے ہیں (ایک بار پھر ان کے خودکار منظوری والے طریقوں میں)۔ تھیم کی تبدیلیاں ایجنٹس کے ساتھ بھی ہم آہنگ ہوتی ہیں: جب آپ Omarchy تھیم تبدیل کرتے ہیں تو Claude Code، Pi، OpenCode اور Hermes (ایک بار جب Omarchy اسے انسٹال کر لے) سب اس کے ساتھ چلتے ہیں۔

### آپ کی ایجنٹ ہدایات

ہر ایجنٹ کے لیے ذاتی قواعد `~/.agents/AGENTS.md` میں جاتے ہیں، مشترکہ مہارتوں کے ساتھ `~/.agents/skills` میں۔ اسے _Agent > Instructions_ کے تحت کھولیں، جو اسے ہر اس ہارنس میں بھی جوڑ دیتا ہے جو اپنی عالمی فائل رکھتا ہے: `~/.claude/CLAUDE.md`، `~/.codex/AGENTS.md`، `~/.pi/agent/AGENTS.md`، `~/.config/opencode/AGENTS.md`، Copilot کی `~/.copilot/copilot-instructions.md`، وغیرہ۔ Crush اور Amp `~/.config/AGENTS.md` لنک کو پڑھتے ہیں، جبکہ omp، Kimi اور DeepSeek Harness براہ راست `~/.agents/AGENTS.md` کو پڑھتے ہیں۔ ڈیفالٹ ایجنٹ منتخب کرنا اسے بھی جوڑ دیتا ہے۔ اگر کوئی ہدایات فائل آپ کے پاس پہلے سے موجود تھی اور ابھی کوئی مشترکہ فائل نہیں تھی تو وہی مشترکہ بن جاتی ہے؛ بصورت دیگر اسے لنک کے ساتھ ساتھ `.bak` کے طور پر رکھا جاتا ہے۔ ایک اور ایجنٹ انسٹال کرنے کے بعد دوبارہ جوڑنے کے لیے `omarchy agent instructions` چلائیں۔

### ایجنٹس پینل

اوپر والی بار میں ایجنٹس کا آئیکن ہے۔ اس سے پہلے کہ آپ نے کوئی ایجنٹ ترتیب دیا ہو، اس کا پینل آپ کو Claude، Codex یا Grok میں سائن ان کرنے کے مراحل سے گزارتا ہے، اور ان میں سے پہلا آپ کا ڈیفالٹ ایجنٹ بن جاتا ہے۔ اس کے بعد، پینل ہر سبسکرپشن کو ایک صفحے پر رکھتا ہے: ہر ایجنٹ اور اکاؤنٹ اس کے پلان کے ساتھ، اس کی 5 گھنٹے کے سیشن اور ہفتہ وار حدود میں سے ہر ایک کے لیے ایک میٹر اس وقت کے ساتھ جب تک وہ دوبارہ ترتیب نہیں پاتی (درست فیصد کے لیے ہوور کریں)، یا باقی پری پیڈ بیلنس، اس لائن کے نیچے جو ان سب میں آپ کے استعمال کے درمیان گردش کرتی ہے، جیسے اس ہفتے کے ٹوکنز اور آپ کا سب سے زیادہ استعمال شدہ ماڈل۔ _کچھ شاندار بنائیں_ کے تحت یہ نئی تھیم، پلگ ان، ایپ یا گیم کے لیے ابتدائی پرامپٹس پیش کرتا ہے جو کام آپ کے ڈیفالٹ ایجنٹ کے حوالے کرتے ہیں۔ ایپس اسی طرح بنائی جاتی ہیں جس طرح Omarchy کی اپنی Hype، Monologue اور Omacut ہیں، C++ اور Qt Quick میں، omarchy-make-app ایجنٹ مہارت کی پیروی کرتے ہوئے، اور انہیں درکار کمپائلر اور Qt کے اجزا انسٹال شدہ آتے ہیں۔ گیمز `~/Games/vibes` میں ایک اکیلی three.js صفحہ ہوتی ہیں، omarchy-make-game ایجنٹ مہارت کی پیروی کرتے ہوئے، اور سب موجودہ تھیم میں ایک Game Vibes لانچر سے کھلتی ہیں؛ وہ three.js ویب سے لوڈ کرتی ہیں، لہٰذا شروع ہونے کے لیے انہیں کنکشن درکار ہوتا ہے۔ Claude Code، Codex، Grok، Kimi، Cursor اور اس کا Grok Bot الاؤنس، GitHub Copilot، Muse، Antigravity اور Devin اپنی حدود کے ساتھ ابتدا ہی سے شامل ہیں، Kimchi اپنے پلان، پری پیڈ کریڈٹس اور اخراجات کے بجٹس کے ساتھ، اور Hermes، Mistral Vibe اور Qwen Code ایک بار جب آپ انہیں استعمال کر لیں تو اپنے سیشنز اور ٹوکنز دکھاتے ہیں۔ وہ فراہم کنندہ پلانز اور کیز بھی ظاہر ہوتی ہیں جو آپ pi، omp یا opencode کے ذریعے استعمال کرتے ہیں: OpenCode Zen اور Go، Z.ai GLM Coding Plan، Ollama Cloud، MiniMax Token Plan اور Synthetic اپنی حدود کے ساتھ؛ OpenRouter اور DeepSeek اپنے پری پیڈ بیلنسز کے ساتھ؛ Fireworks پچھلے 30 دنوں میں اس کے اخراجات کے ساتھ۔ آپ کے اپنے ہارڈ ویئر پر چلائے گئے ماڈلز کے ٹوکنز بھی مجموعوں میں شمار ہوتے ہیں؛ خود ماڈلز کا اپنا پینل ہوتا ہے، جو [مقامی ماڈلز](#local-models) کے تحت بیان کیا گیا ہے۔ ہر ایجنٹ ایک بار شمار ہوتا ہے، اس کے تحت جو بھی اس کا بل دیتا ہے، آپ اسے کتنے ہی ہارنسز کے ذریعے چلائیں۔

پینل کے لیے بار آئیکن پر بائیں کلک کریں یا `Super + Ctrl + X` دبائیں، اپنے ڈیفالٹ ایجنٹ کو لانچ کرنے کے لیے دائیں کلک کریں، اور تازہ کرنے کے لیے درمیانی کلک کریں۔ اس کے پیچھے استعمال کے ریکارڈ ہر 15 منٹ میں `omarchy agent usage update` کے ذریعے دوبارہ بنائے جاتے ہیں، اور پینل ہم آہنگ فولڈر کے ذریعے آپ کی دوسری مشینوں سے استعمال کو بھی ضم کر سکتا ہے۔ مکمل ترتیبات کے لیے `$OMARCHY_PATH/shell/plugins/agents/` کے تحت README دیکھیں۔

### متعدد سبسکرپشنز

اگر آپ ایک سے زیادہ Claude، Codex یا Grok پلان کی ادائیگی کرتے ہیں — مثلاً ایک ذاتی Max اور ایک کام کا — تو Omarchy ان سب کو سائن ان رکھ سکتا ہے اور ان کے درمیان منتقل ہو سکتا ہے۔ ایجنٹس پینل میں + کے ساتھ سبسکرپشن شامل کریں، جو آپ کو وہیں اس کے مراحل سے گزارتا ہے، یا `omarchy agent account add claude Work` کے ساتھ (یا `codex`، یا `grok`)۔ اگر CLI غائب ہو تو یہ اسے انسٹال کر دیتا ہے۔ کسی فراہم کنندہ کے لیے پہلا اکاؤنٹ آپ کے عام براؤزر کے ذریعے سائن ان ہوتا ہے، بالکل وہیں جہاں CLI ہمیشہ دیکھتا ہے۔ اس کے بعد ہر ایک نجی ونڈو کے ذریعے سائن ان ہوتا ہے، تاکہ جس اکاؤنٹ میں آپ کا براؤزر پہلے سے سائن ان ہے وہ غلطی سے نہ اٹھایا جائے؛ وہاں اس اکاؤنٹ کے طور پر سائن ان کریں جو آپ شامل کر رہے ہیں، اور پہلے سے کھلی ہوئی کوئی بھی نجی ونڈو پہلے بند کریں۔ اس کے لیے کبھی CLI سے لاگ آؤٹ نہ کریں: لاگ آؤٹ کرنا محفوظ شدہ سائن ان کو منسوخ کر دیتا ہے، اور اس اکاؤنٹ کو دوبارہ شامل کرنا پڑے گا۔

اپنی سبسکرپشن کے لاگ انز کو SSH کے ذریعے دوسری Omarchy مشین پر نقل کرنے کے لیے `omarchy agent account copy user@laptop` چلائیں۔ جب منزل پر کوئی انسٹال نہ ہو تو بھیجنے والا ایک عارضی وصول کنندہ فراہم کرتا ہے، لہٰذا پرانی Omarchy مشینیں بغیر کسی اپ ڈیٹ کے اکاؤنٹس وصول کر سکتی ہیں۔ انسٹال شدہ وصول کنندگان کو ترجیح حاصل ہوتی ہے۔ یہ تمام Claude، Codex اور Grok سبسکرپشنز نقل کرتا ہے؛ انہیں منتخب کرنے کے لیے فراہم کنندگان کے نام شامل کریں، جیسے `omarchy agent account copy laptop claude` میں۔ اکاؤنٹ کے نام اور کمانڈ IDs ماخذ سے میل کھاتے ہیں، بشمول وہ اکاؤنٹس جو منزل پر پہلے سے موجود ہیں۔ اگر غیر متعلقہ منزل اکاؤنٹس کے نام آپس میں ٹکرائیں تو انہیں عددی لاحقہ ملتا ہے، اور ترتیبات، مہارتیں، پلگ انز اور گفتگو کی سرگزشت ہر مشین کے لیے مقامی رہتی ہے۔

منزل کی موجودہ اسناد برقرار رکھی جاتی ہیں۔ کوئی ماخذ اکاؤنٹ جو وہاں پہلے سے سائن ان ہو اس کا نام اس کی اسناد کو بدلے بغیر ہم آہنگ ہو جاتا ہے؛ دوسرے اکاؤنٹس اس کے ساتھ شامل کر دیے جاتے ہیں۔ میل کھاتے اکاؤنٹس کے لیے محفوظ شدہ اسناد کو تبدیل کرنے کے لیے، منزل پر اس اکاؤنٹ کے سیشنز بند کرنے کے بعد `omarchy agent account copy --replace laptop claude` استعمال کریں۔ ایک تازہ منزل کو ماخذ کا فعال اکاؤنٹ اور تبدیلی کی ترجیحات بھی ملتی ہیں؛ ایک قائم شدہ منزل اپنی ترجیحات برقرار رکھتی ہے۔

اسناد SSH کے ذریعے سفر کرتی ہیں اور منزل پر نجی فائلوں میں محفوظ ہوتی ہیں، لہٰذا صرف ان مشینوں پر نقل کریں جن پر آپ اعتماد کرتے ہیں۔ یہ یک وقتی نقل ہے، جاری ہم آہنگی نہیں۔ Codex ریفریش ٹوکنز کو دوسری مشین گھما سکتی ہے، جس سے نقل شدہ لاگ ان کو تجدید کی ضرورت پڑ جاتی ہے؛ کئی مشینوں پر بیک وقت استعمال کے لیے الگ الگ سائن ان سب سے قابل اعتماد انتخاب رہتے ہیں۔ دیکھیں [Codex کی اکاؤنٹ تصدیق رہنمائی](https://developers.openai.com/codex/auth/ci-cd-auth)۔

فی فراہم کنندہ ایک اکاؤنٹ فعال ہوتا ہے، اور ہر نیا سیشن اسی کے طور پر شروع ہوتا ہے: `cx`، `cy`، ایک سادہ `claude`، `codex` یا `grok`، `omarchy agent` کے ذریعے لانچ کی گئی کوئی بھی چیز، اور اسکرپٹس یا ایڈیٹرز جو CLI کو `PATH` پر پاتے ہیں۔ `omarchy agent account use work` کے ساتھ تبدیل کریں (اور `omarchy agent account use main` کے ساتھ واپس)، یا پینل میں اکاؤنٹ کا نمبر دبا کر پھر `Enter` دبا کر (یا اس کے Use بٹن پر کلک کر کے)۔ چلتے ہوئے Claude سیشنز بھی تبدیل ہو جاتے ہیں، ان کے اگلے پیغام سے: ہر Claude سیشن `~/.claude` میں چلتا ہے، جس میں ہمیشہ فعال اکاؤنٹ کا سائن ان ہوتا ہے۔ پرانی Omarchy کے ذریعے اکاؤنٹ کے اپنے فولڈر میں شروع کیا گیا Claude سیشن وہ سائن ان اس وقت تک رکھتا ہے جب تک وہ بند نہ ہو جائے، لہٰذا تبدیلی ان سیشنز کا نام بتاتی ہے اور ان کے ختم ہوتے ہی خود مکمل ہو جاتی ہے۔ چلتے ہوئے Codex اور Grok سیشنز اسی اکاؤنٹ پر رہتے ہیں جس سے وہ شروع ہوئے تھے۔ گفتگو کی سرگزشت، ترتیبات، مہارتیں اور پلگ انز اکاؤنٹس کے درمیان مشترکہ ہوتی ہیں، لہٰذا اسی فولڈر میں `claude --continue` نئے اکاؤنٹ پر وہیں سے اٹھاتا ہے جہاں آپ نے چھوڑا تھا۔

ایک سے زیادہ اکاؤنٹ کے ساتھ، پینل ہر اکاؤنٹ کی حدود ساتھ ساتھ دکھاتا ہے، جس میں فعال کو نشان زد کیا جاتا ہے۔ بطور ڈیفالٹ Omarchy آپ کو مطلع کرتا ہے جب فعال اکاؤنٹ کسی حد کے 95% سے گزر جاتا ہے، اور اطلاع پر کلک کرنا سب سے زیادہ گنجائش والے اکاؤنٹ پر منتقل کر دیتا ہے۔ خودکار طور پر تبدیل کرنے کے لیے پینل میں اکاؤنٹ کی لائن پر ہوور کریں اور Use کے ساتھ ظاہر ہونے والے Autoswitch پر کلک کریں (یا `m` دبائیں)، یا `omarchy agent account mode auto` چلائیں؛ جب یہ فعال ہو تو Autoswitch Use کی جگہ لے لیتا ہے، اور اس پر دوبارہ کلک کرنا اطلاع دینے پر واپس لے جاتا ہے۔ حد تبدیل کرنے کے لیے نمبر شامل کریں، جیسے `omarchy agent account mode auto 90` میں۔ اگر ہر اکاؤنٹ حد سے اوپر ہو تو آپ کو ایک بار اس کے بارے میں سنایا جائے گا، اس کے ساتھ کہ کون سا اکاؤنٹ سب سے پہلے خالی ہوتا ہے۔ جبکہ فعال اکاؤنٹ اپنی حد کے 15 پوائنٹس کے اندر ہوتا ہے (ڈیفالٹ پر 80%)، اس کی حدود ہر 15 کے بجائے ہر تین منٹ میں جانچی جاتی ہیں۔

`omarchy agent account list` ہر اکاؤنٹ اور اس کی تازہ ترین حدود دکھاتا ہے، `omarchy agent account remove work` ایک کو بھول جاتا ہے، اور `omarchy agent account rename primary Hey` ایک کا نام بدلتا ہے (یا پینل میں اکاؤنٹ کے نام پر کلک کریں)۔ یہ کمانڈز آپ کے ڈیفالٹ ایجنٹ کے اکاؤنٹس پر کام کرتی ہیں؛ دوسرے فراہم کنندہ تک پہنچنے کے لیے پہلے اس کا نام لیں، جیسے `omarchy agent account use codex side` میں۔ `~/.claude` یا `~/.codex` میں آپ کے پاس پہلے سے موجود لاگ ان _Main_ اکاؤنٹ ہے۔ Codex کا وہیں رہتا ہے جہاں وہ ہے؛ Claude کا اس وقت اپنے فولڈر میں انتظار کرتا ہے جب کوئی دوسرا اکاؤنٹ فعال ہو۔ تقریباً آٹھ گھنٹے سے زیادہ غیر استعمال شدہ چھوڑا گیا اکاؤنٹ _Sign-in required_ دکھا سکتا ہے؛ پینل میں ہی اس اکاؤنٹ میں دوبارہ سائن ان کرنے کے لیے اس پر کلک کریں، یا اس پر منتقل ہو کر سیشن شروع کریں، جو سائن ان کو خود تازہ کر دیتا ہے۔ `claude mcp add` کے ساتھ آپ جو MCP سرورز شامل کرتے ہیں وہ ہر Claude اکاؤنٹ تک پہنچتے ہیں، کیونکہ وہ سب `~/.claude` میں چلتے ہیں؛ Codex اور Grok کے لیے، جب اکاؤنٹ شامل کیا گیا تھا اس وقت آپ کے پاس موجود سرورز اس کے ساتھ آتے ہیں، لیکن بعد والے صرف اس اکاؤنٹ تک پہنچتے ہیں جس میں آپ نے انہیں شامل کیا تھا۔ Claude Desktop اپنا سائن ان رکھتا ہے، اور CLI بائنری کے مطلق راستے کے ساتھ ترتیب شدہ Codex یا Grok ٹولز تبدیلی کی پیروی نہیں کرتے۔ واضح `CLAUDE_CONFIG_DIR`، `CODEX_HOME` یا `GROK_HOME` منتخب اکاؤنٹ پر ترجیح لیتا ہے۔

### کریش کی تشخیص

Omarchy عمل کے کریشز کے لیے systemd-coredump کی نگرانی کرتا ہے۔ ایک بار جب آپ ڈیفالٹ ایجنٹ منتخب کر لیں تو، آپ کا کوئی بھی پروگرام جو core ڈمپ کرے وہ “Process crashed” اطلاع لاتا ہے — اس پر کلک کریں، اور کریش آپ کے ڈیفالٹ ایجنٹ کے حوالے کر دیا جاتا ہے Omarchy کی omarchy-diagnose-crash مہارت کے ساتھ، جو ایجنٹ کو core ڈمپ سے حقائق قائم کرنے اور یہ فیصلہ کرنے کے مراحل سے گزارتی ہے کہ آیا کریش upstream رپورٹ کرنے کے قابل ہے۔ آپ اسے `coredumpctl list` سے کسی بھی PID کے خلاف `omarchy agent crash <pid>` کے ساتھ ہاتھ سے بھی چلا سکتے ہیں۔

نگرانی بطور ڈیفالٹ فعال ہے۔ اسے _Trigger > Toggle > Crash Capture Off_ کے تحت بند کریں (یا `omarchy toggle crash-capture` کے ساتھ) اور اطلاعات رک جاتی ہیں؛ `omarchy agent crash <pid>` ہاتھ سے پھر بھی کام کرتا ہے۔

کریشز کو ایک وقت میں ایک پروگرام کے حساب سے خاموش بھی کیا جا سکتا ہے، جو تشخیص آخر میں آپ کو پیش کرتی ہے۔ `omarchy crash mute hyprland` صرف اس پروگرام کے لیے اطلاعات روکتا ہے، `omarchy crash mute hyprland off` انہیں واپس لاتا ہے، اور اکیلا `omarchy crash mute` وہ فہرست دیتا ہے جو آپ نے خاموش کی ہے۔ یہ بائنری کا راستہ اس کے نام کی طرح خوشی سے لیتا ہے، لہٰذا `omarchy crash mute /usr/bin/hyprland` بھی وہی کام کرتا ہے۔ اس نام کو کوٹس میں رکھیں جس میں جگہ ہو، جیسے `omarchy crash mute 'Some App'` میں۔ باقی سب کچھ پھر بھی مطلع کرتا ہے، اور خاموش کیا گیا پروگرام پھر بھی کریش ہوتا ہے — یہ یاد دہانی کو چھپاتا ہے، یہ کچھ ٹھیک نہیں کرتا۔

### ڈیسک ٹاپ ایپس

_Install > AI_ مینو میں چند گرافیکل AI ایپس بھی ہیں: Amp Desktop، Antigravity Desktop، ChatGPT ڈیسک ٹاپ ایپ، Claude ڈیسک ٹاپ ایپ (Anthropic کا Linux بیٹا، Chat، Cowork اور Claude Code ٹیبز کے ساتھ)، xAI کے ماڈلز کے ساتھ چیٹ کرنے کے لیے Grok Bot، Herdr Desktop، Hermes Desktop، OpenClaw، Perplexity ڈیسک ٹاپ ایپ، اور T3 Code۔ Grok Bot ڈیسک ٹاپ چیٹ ایپ ہے۔ کوڈنگ ایجنٹ `grok` کمانڈ ہے۔

Hermes Desktop وہ ہے جس کے بارے میں جاننا ضروری ہے، کیونکہ کسی مشین کے پاس ایک Hermes ہوتا ہے، اور وہ ایپ کا ہوتا ہے: Hermes ہمیشہ صرف ایپ کے ذریعے انسٹال ہوتا ہے، اور ڈیفالٹ ایجنٹ جو `hermes` کمانڈ چلاتا ہے وہ ایپ کی ہوتی ہے۔ Hermes کو ڈیفالٹ ایجنٹ کے طور پر منتخب کرنا وہی چیز انسٹال کرتا ہے جو _Install > AI_ اندراج کرتا ہے: پیکیج، اور Hermes کے اپنے انسٹالر کے ذریعے ترتیب شدہ `~/.hermes` کے تحت Hermes رن ٹائم، جس میں پہلی بار چند منٹ لگتے ہیں۔ وہ رن ٹائم وہ واحد Hermes ہے جسے ٹرمینل `hermes` کمانڈ، ڈیفالٹ ایجنٹ اور ایپ سب استعمال کرتے ہیں، اور یہ Omarchy ریلیز کا انتظار کرنے کے بجائے `hermes update` کے ساتھ خود کو اپ ڈیٹ کرتا ہے۔ اسے انسٹال کرنا Hermes کو Omarchy تھیم بھی `omarchy` نامی سکن کے طور پر دیتا ہے، جس کی پیروی Hermes کی ہر سطح تھیمز تبدیل کرتے وقت کرتی ہے؛ اگر آپ نہیں چاہتے کہ ایسا ہو تو Hermes کی Appearance ترتیبات کے تحت یا `/skin` کے ساتھ کوئی اور منتخب کریں، اور Omarchy اس انتخاب کو ویسا ہی چھوڑ دیتا ہے۔ _Remove > AI_ کے تحت ایپ کو ہٹانا پہلے Hermes کو بند کرتا ہے، گیٹ وے سمیت، اس رن ٹائم کو اس کے ساتھ لے جاتا ہے، اور آپ کی چیٹس، یادیں اور وہ مہارتیں جو Hermes نے خود اپنے لیے لکھی تھیں برقرار رکھتا ہے الا یہ کہ آپ اسے دوسری صورت کہیں: یہ پوچھتا ہے، نہیں کو ڈیفالٹ رکھتے ہوئے، کہ آیا وہ ڈیٹا اور آپ کی کنکشن ترتیبات بھی جانی چاہئیں۔

OpenClaw کا ڈیسک ٹاپ تجربہ اس کا Control UI ہے، جو اس کے اپنے مقامی گیٹ وے کی پشت پناہی سے ویب ایپ کے طور پر کھلتا ہے۔ OpenClaw `~/.openclaw` میں رہتا ہے اور خود کو اپ ڈیٹ کرتا ہے: Control UI کا “Update Gateway” بٹن استعمال کریں یا `openclaw update` چلائیں، اور گیٹ وے نئے ورژن پر دوبارہ شروع ہو جاتا ہے۔ Omarchy صرف وہ ریلیز منتخب کرتا ہے جس سے تازہ انسٹال شروع ہوتا ہے۔ OpenClaw آپ کا ڈیفالٹ ایجنٹ بھی ہو سکتا ہے: اسے _Agent > Harness_ کے تحت منتخب کرنا `~/.openclaw` میں وہی کاپی ترتیب دیتا ہے، اور ایجنٹ اس کے گیٹ وے سے منسلک OpenClaw کا ٹرمینل UI کھولتا ہے۔ _Remove > AI_ کے تحت OpenClaw کو ہٹانا گیٹ وے سروس اور ایپ کو اس کے ساتھ لے جاتا ہے اور پھر پوچھتا ہے کہ آیا `~/.openclaw` بھی جانا چاہیے، کیونکہ اس میں OpenClaw خود اور اس کے ڈاؤن لوڈ کردہ پلگ ان رن ٹائمز کے ساتھ ساتھ آپ کی چیٹس اور اسناد بھی ہوتی ہیں؛ ڈیفالٹ اسے برقرار رکھتا ہے، اور OpenClaw دوبارہ انسٹال کرنا اسے واپس اٹھا لیتا ہے۔

Herdr Desktop [Herdr](https://herdr.dev) ڈیسک ٹاپ ایپ ہے: ٹرمینلز اور کوڈنگ ایجنٹس کی جگہیں، ٹیبز اور پینز جو ونڈو بند کرنے پر اس کے کور میں چلتی رہتی ہیں۔ یہ پیکیج کے بجائے Herdr کے اپنے انسٹالر سے آتی ہے، لہٰذا یہ `~/.local/share/herdr-app` میں رہتی ہے، جب آپ کے پاس پہلے سے کوئی نہ ہو تو `~/.local/bin/herdr-core` میں اپنے کور کو ساتھ لاتی ہے، اور دونوں کو خود اپ ڈیٹ کرتی ہے۔ یہ اس `herdr` کمانڈ کے ساتھ ساتھ رہتی ہے جو Omarchy `Super + Ctrl + Return` پر فراہم کرتا ہے اسے تبدیل کیے بغیر، اور اس کمانڈ کی براہ راست کیز حاصل کرتی ہے: `Alt + Return` اور `Alt + Shift + Return` پین کو نیچے یا دائیں تقسیم کرتے ہیں، `Alt + Escape` اسے بند کرتا ہے، `Ctrl + Alt + Arrow` پینز کے درمیان منتقل ہوتا ہے، `Alt + 1..9` اور `Alt + Left/Right` ٹیب منتخب کرتے ہیں، اور `Alt + Up/Down` جگہوں کے درمیان منتقل ہوتے ہیں۔ `Ctrl + 1..9` جگہ منتخب کرتا ہے اور `Alt + Shift + Up/Down` ایجنٹس میں قدم بہ قدم چلتا ہے۔ `Ctrl + Space` پریفکس کیز صرف ٹرمینل کے لیے رہتی ہیں، کیونکہ ایپ تسلسل کے لیے سادہ Ctrl کی کو نہیں پکڑ سکتی۔ Omarchy یہ `~/.config/herdr-app/keys.json` میں لکھتا ہے، اور `omarchy-refresh-herdr-app` انہیں واپس رکھتا ہے۔ اسے انسٹال کرنا Herdr کی Omarchy تھیم منتخب کرتا ہے، جو اس کے بعد سے آپ کی Omarchy تھیم کی پیروی کرتی ہے۔ Herdr ہلکے موڈ کے لیے ایک تھیم اور گہرے موڈ کے لیے ایک تھیم رکھتا ہے، لہٰذا گہری اور ہلکی Omarchy تھیم کے درمیان تبدیل کرنے کے بعد، دوسرے موڈ کے لیے Herdr کے تھیم منتخب کنندہ میں ایک بار پھر Omarchy منتخب کریں۔

T3 Code پیکیج کے بجائے `~/.local/share/t3code` میں اپنی سرکاری AppImage ریلیز سے چلتا ہے، لہٰذا یہ خود کو اپ ڈیٹ کرتا ہے۔ اسے انسٹال کرنا پوچھتا ہے کہ Stable یا Nightly چینل پر شروع کرنا ہے؛ بعد میں T3 Code کی ترتیبات میں تبدیل کریں۔ آپ کے تھریڈز اور ترتیبات `~/.t3` میں رہتی ہیں، اور _Remove > AI_ کے تحت T3 Code کو ہٹانا انہیں اس کے ساتھ لے جاتا ہے۔

### مقامی ماڈلز

اپنے کوڈنگ ایجنٹس کے لیے اپنی مشین پر کھلا ماڈل چلائیں۔ آپ کے پرامپٹس اور کوڈ مشین پر رہتے ہیں؛ ماڈل کو بھیجی گئی کوئی چیز اسے نہیں چھوڑتی۔ اس سے شروع کریں:

```bash
omarchy models use best text
```

یہ اس مشین کے لیے بہترین ٹیکسٹ ماڈل ترتیب دیتا ہے، اسی قسم کا جو آپ کے ایجنٹس استعمال کرتے ہیں۔ تصویر، ویڈیو اور موسیقی کے ماڈلز کا اپنا بہترین ہوتا ہے: `omarchy models use best image`، `video` یا `music`۔ اس مشین کے لیے ہر قسم کا انتخاب دیکھنے کے لیے `omarchy models use best` چلائیں۔

یا مقامی ماڈلز پینل کو اوپر والی بار میں ایجنٹس آئیکن کے ساتھ اس کے چمک آئیکن سے کھولیں، یا Super + Ctrl + Alt + X کے ساتھ، اور + منتخب کریں۔ آئیکن اس وقت ظاہر ہوتا ہے جب کوئی ماڈل اس مشین میں فٹ آتا ہے۔ Podman، جو ماڈلز چلاتا ہے، Omarchy کے ساتھ آتا ہے، اسی طرح NVIDIA مشین پر NVIDIA کا کنٹینر ٹول کٹ بھی، جو انہیں GPU دیتا ہے؛ اگر ان میں سے کوئی غائب ہو تو پہلی ترتیب اسے انسٹال کر دیتی ہے۔ پھر Omarchy اس مشین کے لیے تجویز کردہ ماڈل منتخب کرتا ہے، اسے ڈاؤن لوڈ کرتا ہے، اور اسے شروع کرتا ہے۔ دسیوں GB کے ڈاؤن لوڈ کی توقع رکھیں اور جب ماڈل چل رہا ہو تو مشین کی زیادہ تر میموری استعمال میں ہوگی: Flash Next اپنے مکمل 256K سیاق و سباق کے ساتھ تقریباً 100 GiB استعمال کرتا ہے۔ اگر دوسرے ماڈلز اسے درکار میموری رکھتے ہوں تو یہ رکا ہوا ترتیب پاتا ہے، آپ کے ایک کو روکتے ہی شروع ہونے کے لیے تیار۔ ماڈل لاگ آؤٹ پر رک جاتا ہے؛ جب آپ کو کسی اور کام کے لیے میموری درکار ہو تو اسے خود روکیں۔

`omarchy models list` اختیارات دکھاتا ہے اور بتاتا ہے کہ کچھ کیوں فٹ نہیں آتے۔ ایک اور ترتیب دینے کے لیے `omarchy models use <recipe>` چلائیں۔ آج، 128 GB Strix Halo مشینوں کے لیے `qwen3.8-flash-next-gufo` اور `qwen3.8-27b-gufo` دستیاب ہیں؛ 27B تقریباً 40 GiB لیتا ہے، لہٰذا یہ دوسرے کام کے لیے جگہ چھوڑتا ہے۔ Intel کے Arc B390 والی 64 GB لیپ ٹاپ پر، `qwen3.6-35b-a3b-llamacpp` تقریباً 30 GiB میں چلتا ہے۔ نئی ترکیبیں اور تجاویز پیکیج کے ذریعے `omarchy update` کے ساتھ آتی ہیں۔

آپ جو بھی ماڈل ترتیب دیتے ہیں اسے مقامی ماڈلز پینل میں اپنی لائن ملتی ہے: اسے شروع کرنے کے لیے چلائیں، اسے روکنے اور اس کی میموری خالی کرنے کے لیے توقف کریں، اور اس پر اپنے ایجنٹ کو کھولنے کے لیے ٹرمینل بٹن۔ اوپر کے پار، ایک بار دکھاتا ہے کہ مشین کی میموری خود Omarchy (سسٹم اور آپ کی ایپس)، ہر چلتے ہوئے ماڈل، اور جو خالی ہے اس کے درمیان کیسے تقسیم ہے۔ رکے ہوئے ماڈل کی طرف اشارہ کریں اور بار دکھاتا ہے کہ آیا یہ فٹ آتا ہے، یا یہ کتنا کم ہے۔ کئی ایک ساتھ چل سکتے ہیں جب وہ میموری میں ایک ساتھ فٹ آتے ہیں؛ اگر کوئی فٹ نہ آئے تو Omarchy بتاتا ہے کہ کون سا چلتا ہوا ماڈل روکنا ہے۔ انہیں دوبارہ ترتیب دینے کے لیے لائنوں کو ان کے لوگو سے گھسیٹیں، اور ماڈل اور اس کا ڈاؤن لوڈ ہٹانے کے لیے منتخب لائن پر Delete دبائیں۔

آپ جو بھی کوڈنگ ماڈل ترتیب دیتے ہیں اسے ایپ لانچر میں بھی اپنی اندراج ملتی ہے، ماڈل کے نام کے تحت اور اس کے بنانے والے کے لوگو کے ساتھ، اسی طرح جیسے Claude، Codex یا Grok میں سائن ان کرنا ایک شامل کرتا ہے۔ یہ اس ماڈل پر آپ کا ایجنٹ کھولتا ہے، اور اگر ماڈل نہ چل رہا ہو تو پہلے اسے شروع کرتا ہے: ٹرمینل اسے لوڈ ہوتا دکھاتا ہے اور جب یہ تیار ہو جائے تو ایجنٹ کے حوالے کر دیتا ہے۔ ماڈل ہٹانا اس کی اندراج ہٹا دیتا ہے۔

ہر ماڈل کوڈنگ کے لیے نہیں ہوتا۔ تصویر، ویڈیو اور موسیقی کے ماڈلز اس کے بجائے Fantasi میں کھلتے ہیں، Omarchy کی اس مشین پر چلنے والے ماڈل کے ساتھ تصاویر، ویڈیو اور موسیقی بنانے کی ایپ، جو وہاں یا مقامی ماڈلز پینل میں ان کی لائن سے منتخب کی جاتی ہے۔

ماڈل بالکل اسی طرح چلتا رہتا ہے جیسے اسے ترتیب دیا گیا تھا، لہٰذا Omarchy اپ ڈیٹ کبھی آپ کے ایجنٹس کے تحت ایک کو دوبارہ شروع نہیں کرتا۔ جب Omarchy کے پاس آپ کے ترتیب شدہ ماڈل کے لیے نیا رن ٹائم یا نئے ویٹس ہوں تو اس کی لائن اپ ڈیٹ بٹن دکھاتی ہے: اسے دبائیں اور ماڈل پس منظر میں دوبارہ ترتیب پاتا ہے، صرف وہ ڈاؤن لوڈ کرتا ہے جو تبدیل ہوا، اور نئے ورژن پر دوبارہ شروع ہو جاتا ہے۔ جو ماڈل رکا ہوا تھا وہ رکا رہتا ہے۔ `omarchy models update` ٹرمینل سے ہر ماڈل کے لیے یہی کرتا ہے۔

کمانڈ لائن سے، `omarchy models start <recipe>` اور `omarchy models stop <recipe>` یہی کرتے ہیں، `omarchy models status` ہر ماڈل دکھاتا ہے، اور `omarchy agent --local` آپ کے ڈیفالٹ ایجنٹ کو آخری ماڈل پر کھولتا ہے جو آپ نے شروع کیا تھا۔ pi، OpenCode اور Qwen Code ایک استعمال کر سکتے ہیں؛ کسی اور ڈیفالٹ کے ساتھ یہ pi میں کھلتا ہے، یا OpenCode میں اگر آپ کے پاس pi نہ ہو۔ pi آپ کے ترتیب شدہ ہر ماڈل، اور جن مشینوں کے ساتھ آپ نے جوڑا بنایا ہے ان پر موجود ماڈلز کو بھی، اپنے ماڈل منتخب کنندہ میں درج کرتا ہے، لہٰذا سادہ `pi` بھی ان تک پہنچتا ہے۔ کوئی بھی OpenAI سے ہم آہنگ کلائنٹ بھی جڑ سکتا ہے: `status` ہر ماڈل کا پتہ دکھاتا ہے (پہلا `http://127.0.0.1:11435/v1` ہے)، ترکیب کا نام ماڈل ہے، اور کی `~/.config/omarchy/agent-local/key` میں ہے۔

`omarchy models remove <recipe>` ماڈل اور وہ ڈاؤن لوڈز حذف کرتا ہے جنہیں کوئی اور ماڈل استعمال نہیں کرتا۔

فریق ثالث کے رن ٹائمز ان کے ناشر کے ساتھ لیبل کیے جاتے ہیں۔ Omarchy ہر ماڈل کو بغیر نیٹ ورک رسائی کے چلاتا ہے۔

### مقامی LLMs

Omarchy مقامی LLM ماڈلز چلانے کے دو طریقے تجویز کرتا ہے: LM Studio اور Ollama۔ LM Studio اوپن ویٹ ماڈلز تلاش کرنے، انہیں انسٹال کرنے اور چلانے کے لیے GUI انٹرفیس فراہم کرتا ہے۔ آسانی سے شروع کرنے کا یہ بہترین طریقہ ہے۔ Ollama اسی طرح کرنے کے لیے CLI پیش کرتا ہے۔ لیکن اگر آپ مقامی ماڈلز میں نئے ہیں تو میں LM Studio سے شروع کروں گا۔ آپ Omarchy Menu میں _Install > AI_ کے تحت دونوں میں سے کوئی بھی انسٹال کر سکتے ہیں۔

### Omarchy کی مہارتیں

ایجنٹ مہارتیں AI کو مخصوص ٹولز کو مخصوص طریقے سے استعمال کرنے میں مدد دیتی ہیں، اور Omarchy ان میں سے سات فراہم کرتا ہے۔ omarchy مہارت سسٹم کو اپنی پسند کے مطابق ڈھالنے کا احاطہ کرتی ہے، جیسے آپ کی Hyprland ترتیب میں ردوبدل کرنا یا بار کو ایڈجسٹ کرنا۔ omarchy-make-theme، omarchy-make-plugin، omarchy-make-app اور omarchy-make-game کچھ نیا بنانے کا احاطہ کرتی ہیں، omarchy-contribute بگ کی اطلاع دینے یا upstream فکس بھیجنے کا احاطہ کرتی ہے، اور omarchy-diagnose-crash کریش کے core ڈمپ پر کام کرتی ہے۔ انہیں Claude Code (`~/.claude/skills`)، Codex (`~/.codex/skills`)، Pi (`~/.pi/agent/skills`)، Antigravity (`~/.gemini/config/skills`)، Hermes (`~/.hermes/skills` اور ہر `~/.hermes/profiles/*/skills`)، اور عام `~/.agents/skills` مقام کے لیے مہارت ڈائریکٹریوں میں علامتی طور پر جوڑا گیا ہے، لہٰذا زیادہ تر ہارنسز انہیں خودکار طور پر اٹھا لیتے ہیں۔ اسی نام کا آپ کا اپنا مہارت فولڈر ترجیح لیتا ہے۔

لیکن آپ کو ان مہارتوں کو تجرباتی سمجھنا چاہیے۔ مختلف ماڈلز اسے مختلف اثر کے ساتھ استعمال کریں گے۔ پہلے پلان موڈ میں چلانا بہتر ہے، تاکہ آپ کو اندازہ ہو کہ ایجنٹ کیا تبدیل کرنا چاہے گا۔ اور پھر تبدیلیوں کو واپس کرنے یا یہاں تک کہ `omarchy reinstall configs` چلانے کے لیے تیار رہیں، اگر ایجنٹ ہر چیز کا گڑبڑ کر دے۔
