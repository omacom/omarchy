Omarchy میں ذیل کے کوڈنگ ایجنٹس کے لانچرز شامل ہیں، بغیر آپ کے لیے کوئی ڈیفالٹ منتخب کیے۔ پہلی بار استعمال پر اس کا CLI انسٹال کرنے کے لیے کمانڈ چلائیں، پھر اشارہ ملنے پر تصدیق کریں۔ Hermes اور OpenClaw استثنا ہیں: ان کے لیے mise کے ذریعے کچھ انسٹال نہیں ہوتا، اور ان میں سے کسی کو منتخب کرنا اس کی اپنی خود بخود اپ ڈیٹ ہونے والی کاپی سیٹ اپ کرتا ہے، جیسا کہ ذیل میں _ڈیسک ٹاپ ایپس_ بیان کرتا ہے۔

### ایجنٹ انسٹال اور اپ ڈیٹ کرنا

Hermes اور OpenClaw کے سوا، یہ ایجنٹ mise کی سست انسٹالیشن استعمال کرتے ہیں: پہلی لانچ CLI انسٹال کرتی ہے، اور بعد کی لانچز اسی کو دوبارہ استعمال کرتی ہیں۔ mise انسٹال شدہ ایجنٹ کے لیے نئی ریلیز کی جانچ بھی زیادہ سے زیادہ ہر چار گھنٹے میں ایک بار کرتا ہے، شروع ہونے سے ذرا پہلے یا پس منظر میں شیل پرامپٹ پر۔ اگر وہ اپ ڈیٹ ناکام ہو جائے یا آپ آف لائن ہوں، تو انسٹال شدہ ورژن چلتا ہے۔ `omarchy update` انسٹال شدہ ایجنٹس کو بقایا Omarchy کے ساتھ اپ ڈیٹ کرتا ہے، اور `mup` صرف mise کے زیر انتظام ٹولز کو اپ ڈیٹ کرتا ہے۔

کسی ایجنٹ کا اپنا اپڈیٹر، جیسے `claude update`، `codex update`، یا کسی ایپ میں اپ ڈیٹ بٹن، mise کے زیر انتظام انسٹال کو اپ ڈیٹ نہیں کرتا۔ `codex update` ناکام ہو جاتا ہے، اور `claude update` کامیابی کی اطلاع دے سکتا ہے جبکہ ایک الگ کاپی انسٹال کر رہا ہو جسے mise ٹریک نہیں کرتا۔ اگر آپ اس کے بجائے کسی ایجنٹ کا مقامی انسٹالر اور اپڈیٹر استعمال کرنا پسند کرتے ہیں، تو اسے `disable_tools` میں شامل کریں؛ دیکھیں [پہلے سے انسٹال شدہ CLI ٹولز](18-development-tools.md#preinstalled-cli-tools)۔

تمام تشکیل شدہ سست ٹولز کو ضرورت پڑنے سے پہلے انسٹال کرنے کے لیے، `mise install --include-lazy` چلائیں۔ اس میں ایجنٹس کے ساتھ ساتھ Omarchy کے دوسرے ڈیفالٹ CLI ٹولز بھی شامل ہیں۔ ایک واحد ٹول انسٹال کرنے یا اپنی انسٹالیشن استعمال کرنے کے لیے دیکھیں [پہلے سے انسٹال شدہ CLI ٹولز](18-development-tools.md#preinstalled-cli-tools)۔

`grok` mise کے فرسٹ پارٹی `grok` پیکیج کے ذریعے انسٹال ہوتا ہے، اسی طرح جیسے `claude` اور `codex`۔ `grok` چلائیں، یا اسے _Agent > Harness_ کے تحت منتخب کریں۔ x.ai پر `curl | bash` انسٹالر کو چھوڑ دیں۔ وہ راستہ `~/.grok/bin` میں دوسری کاپی رکھتا ہے، اسے `PATH` پر پہلے لگاتا ہے، اور Omarchy کے ریپر کو اوور رائٹ کر دیتا ہے۔

`dsh` اپنا براؤزر UI `127.0.0.1:3080` پر کھولتا ہے، جس میں لانچ ڈائریکٹری اس کا ڈیفالٹ ورک اسپیس ہوتی ہے۔ اس کا براؤزر UI کوئی ابتدائی پرامپٹ نہیں لیتا، لہٰذا `omarchy agent prompt` اسے آپ کے کلپ بورڈ پر پرامپٹ کے ساتھ کھولتا ہے تاکہ آپ پیسٹ کر سکیں۔ Omarchy اسے DeepSeek کے بغیر منظوری والے اجازت پری سیٹ کے ساتھ شروع کرتا ہے۔ DeepSeek Harness سیشن لاگز DeepSeek کو اپ لوڈ کرتا ہے جب آپ اس کا آفیشل ماڈل API استعمال کرتے ہیں؛ اسے اس کے براؤزر UI میں _Settings > General > Upload Session Log_ کے تحت بند کریں۔ جو فیڈ بیک آپ اسے بھیجتے ہیں وہ بھی سیشن کے ساتھ اپ لوڈ ہوتا ہے، الا یہ کہ آپ اسے `DSH_TELEMETRY_MODE=DISABLED` کے ساتھ شروع کریں۔

### ڈیفالٹ ایجنٹ

اپنا ڈیفالٹ ایجنٹ `omarchy default agent <name>` سے یا Omarchy Menu (`Super + Space`) میں _Agent > Harness_ کے تحت منتخب کریں۔ اگر ایجنٹ ابھی انسٹال نہیں ہے، تو اسے منتخب کرنا پہلے اسے انسٹال کرتا ہے، اور اسے ایپ لانچر میں Agent کے ساتھ ساتھ اس کا اپنا لانچر بھی ملتا ہے۔ ایک تازہ Omarchy ایک بار کی اطلاع کے ساتھ آپ کو یہ انتخاب کرنے کی دعوت دے گا۔

Claude کو منتخب کرنا Chromium، Chrome، Brave، Brave Origin، اور Edge کے لیے اس کی براؤزر ایکسٹینشن سیٹ اپ کرنے کی بھی کوشش کرتا ہے۔ ایکسٹینشن سیٹ اپ تمام صارفین پر لاگو ہوتا ہے اور آپ سے آپ کا سسٹم پاس ورڈ مانگ سکتا ہے؛ منسوخ کرنا یا ایکسٹینشن انسٹال کا ناکام ہونا پھر بھی Claude کو منتخب اور لانچ کرتا ہے۔ اپنے براؤزر کو دوبارہ شروع کریں، اشارہ ملنے پر ایکسٹینشن فعال کریں، اور اسے جوڑنا مکمل کرنے کے لیے Claude میں سائن ان کریں۔ کنکشن چیک کرنے کے لیے Claude میں `/chrome` چلائیں۔ Firefox اور Zen اس ایکسٹینشن کی حمایت نہیں کرتے۔ اگر یہ سیٹ اپ شامل کیے جانے سے پہلے ہی Claude آپ کا ڈیفالٹ تھا، تو ایکسٹینشن انسٹال کرنے کے لیے اسے دوبارہ منتخب کریں۔

منتخب کرنے کے بعد، `Super + Shift + Ctrl + A` ڈیفالٹ ایجنٹ کو ایک مخصوص ٹرمینل ونڈو میں لانچ کرتا ہے (یا اگر آپ نے ابھی انتخاب نہیں کیا تو پکر سامنے لاتا ہے)۔ آپ اسے `omarchy agent prompt "Review this project"` سے سیدھا کسی کام میں بھی لانچ کر سکتے ہیں۔ Freebuff اور DeepSeek Harness کوئی ابتدائی پرامپٹ نہیں لیتے، لہٰذا وہ اس کے بجائے آپ کے کلپ بورڈ پر پرامپٹ کے ساتھ کھلتے ہیں تاکہ آپ پیسٹ کر سکیں۔ اس طرح لانچ کیے گئے ایجنٹ اپنے متعلقہ نہ رکنے، نہ پوچھنے والے موڈز میں بغیر نگرانی کے چلتے ہیں، لہٰذا اس کے لیے تیار رہیں کہ وہ واقعی کچھ کریں گے! MiniMax Code کے انٹرایکٹو سیشنز کے لیے ایسا کوئی موڈ نہیں ہے، لہٰذا یہ معمول کے مطابق اجازتیں مانگتا ہے۔ اور چونکہ ایجنٹ آپ کی ہوم ڈائریکٹری کے لیے اعتماد یاد رکھنے سے انکار کرتے ہیں، اس لیے `$HOME` سے لانچز اس کے بجائے `~/Work` میں شروع ہوتی ہیں۔

ٹرمینل شارٹ کٹس بھی ہیں: `a` موجودہ ٹرمینل میں ڈیفالٹ ایجنٹ کو ان لائن چلاتا ہے، جبکہ `c`، `cx`، اور `cy` OpenCode، Claude Code، اور Codex کو براہ راست شروع کرتے ہیں (دوبارہ ان کے خودکار منظوری والے موڈز میں)۔ تھیم کی تبدیلیاں ایجنٹس کے ساتھ بھی ہم آہنگ ہوتی ہیں: Claude Code، Pi، OpenCode، اور Hermes (جب Omarchy نے اسے انسٹال کر لیا ہو) سب اس وقت ساتھ چلتے ہیں جب آپ Omarchy تھیم تبدیل کرتے ہیں۔

### آپ کی ایجنٹ ہدایات

ہر ایجنٹ کے لیے ذاتی قواعد `~/.agents/AGENTS.md` میں جاتے ہیں، `~/.agents/skills` میں مشترکہ اسکلز کے ساتھ۔ اسے _Agent > Instructions_ کے تحت کھولیں، جو اسے ہر اس ہارنس میں بھی لنک کرتا ہے جو اپنی عالمی فائل رکھتا ہے: `~/.claude/CLAUDE.md`، `~/.codex/AGENTS.md`، `~/.pi/agent/AGENTS.md`، `~/.config/opencode/AGENTS.md`، Copilot کی `~/.copilot/copilot-instructions.md`، اور اسی طرح۔ Crush اور Amp `~/.config/AGENTS.md` لنک پڑھتے ہیں، جبکہ omp، Kimi، اور DeepSeek Harness `~/.agents/AGENTS.md` کو براہ راست پڑھتے ہیں۔ ڈیفالٹ ایجنٹ منتخب کرنا اسے بھی لنک کرتا ہے۔ آپ کے پاس پہلے سے موجود ہدایات فائل مشترکہ فائل بن جاتی ہے اگر ابھی کوئی نہیں تھی؛ بصورت دیگر اسے لنک کے ساتھ `.bak` کے طور پر رکھا جاتا ہے۔ ایک اور ایجنٹ انسٹال کرنے کے بعد دوبارہ لنک کرنے کے لیے `omarchy agent instructions` چلائیں۔

### ایجنٹس پینل

اوپر والی بار میں ایک ایجنٹس آئیکن ہے۔ کسی ایجنٹ کو سیٹ اپ کرنے سے پہلے، اس کا پینل آپ کو Claude، Codex، یا Grok میں سائن ان کرنے کی راہ دکھاتا ہے، اور پہلا والا آپ کا ڈیفالٹ ایجنٹ بن جاتا ہے۔ اس کے بعد، پینل ہر سبسکرپشن کو ایک صفحے پر رکھتا ہے: ہر ایجنٹ اور اکاؤنٹ اس کے پلان کے ساتھ، اس کی 5 گھنٹے کے سیشن اور ہفتہ وار حدود میں سے ہر ایک کے لیے ایک میٹر جس میں ری سیٹ ہونے تک کا وقت ہوتا ہے (عین فیصد کے لیے ہوور کریں)، یا بقیہ پری پیڈ بیلنس، ایک لائن کے نیچے جو ان سب میں آپ کے استعمال کیے گئے کو گھماتی ہے، جیسے اس ہفتے کے ٹوکنز اور آپ کا سب سے زیادہ استعمال شدہ ماڈل۔ _Make something cool_ کے تحت یہ ایک نئی تھیم، پلگ ان، ایپ، یا گیم کے لیے ابتدائی پرامپٹس پیش کرتا ہے جو کام آپ کے ڈیفالٹ ایجنٹ کے حوالے کرتے ہیں۔ ایپس اسی طرح بنائی جاتی ہیں جیسے Omarchy کی اپنی Hype، Monologue، اور Omacut ہیں، C++ اور Qt Quick میں، omarchy-make-app ایجنٹ اسکل کی پیروی کرتے ہوئے، اور انہیں درکار کمپائلر اور Qt حصے انسٹال شدہ آتے ہیں۔ گیمز `~/Games/vibes` میں ایک واحد three.js صفحہ ہوتی ہیں، omarchy-make-game ایجنٹ اسکل کی پیروی کرتے ہوئے، اور سب موجودہ تھیم میں ایک Game Vibes لانچر سے کھلتی ہیں؛ وہ ویب سے three.js لوڈ کرتی ہیں، لہٰذا شروع ہونے کے لیے انہیں کنکشن کی ضرورت ہوتی ہے۔ Claude Code، Codex، Grok، Kimi، Cursor اور اس کا Grok Bot الاؤنس، GitHub Copilot، Muse، Antigravity، اور Devin اپنی حدود کے ساتھ باکس سے باہر شامل ہیں، Kimchi اپنے پلان، پری پیڈ کریڈٹس، اور خرچ کے بجٹ کے ساتھ، اور Hermes، Mistral Vibe، اور Qwen Code اپنے سیشنز اور ٹوکنز دکھاتے ہیں جب آپ انہیں استعمال کر چکے ہوں۔ pi، omp، یا opencode کے ذریعے استعمال کیے گئے فراہم کنندہ پلانز اور کیز بھی ظاہر ہوتے ہیں: OpenCode Zen اور Go، Z.ai GLM Coding Plan، Ollama Cloud، MiniMax Token Plan، اور Synthetic اپنی حدود کے ساتھ؛ OpenRouter اور DeepSeek اپنے پری پیڈ بیلنس کے ساتھ؛ Fireworks پچھلے 30 دنوں میں اس کے خرچ کے ساتھ۔ آپ کے اپنے ہارڈویئر پر چلائے گئے ماڈلز کے ٹوکنز بھی مجموعوں میں شمار ہوتے ہیں؛ خود ماڈلز کا اپنا پینل ہے، جو [مقامی ماڈلز](#local-models) کے تحت بیان کیا گیا ہے۔ ہر ایجنٹ ایک بار شمار ہوتا ہے، اس کے تحت جو اس کا بل دیتا ہے، چاہے آپ اسے کتنے ہی ہارنسز کے ذریعے چلائیں۔

پینل کے لیے بار آئیکن پر بائیں کلک کریں یا `Super + Ctrl + X` دبائیں، اپنے ڈیفالٹ ایجنٹ کو لانچ کرنے کے لیے دائیں کلک کریں، اور ریفریش کرنے کے لیے درمیانی کلک کریں۔ اس کے پیچھے استعمال کے ریکارڈز ہر 15 منٹ میں `omarchy agent usage update` کے ذریعے دوبارہ بنائے جاتے ہیں، اور پینل ایک ہم آہنگ فولڈر کے ذریعے آپ کی دوسری مشینوں سے استعمال کو بھی ضم کر سکتا ہے۔ مکمل ترتیبات کے لیے `$OMARCHY_PATH/shell/plugins/agents/` کے تحت README دیکھیں۔

### متعدد سبسکرپشنز

اگر آپ ایک سے زیادہ Claude، Codex، یا Grok پلان کی ادائیگی کرتے ہیں — مثلاً ایک ذاتی Max اور ایک کام والا — تو Omarchy ان سب کو سائن ان رکھ سکتا ہے اور ان کے درمیان منتقل ہو سکتا ہے۔ ایجنٹس پینل میں + سے سبسکرپشن شامل کریں، جو آپ کو وہیں اس سے گزارتا ہے، یا `omarchy agent account add claude Work` سے (یا `codex`، یا `grok`)۔ اگر CLI غائب ہے تو یہ اسے انسٹال کرتا ہے۔ کسی فراہم کنندہ کے لیے پہلا اکاؤنٹ آپ کے عام براؤزر کے ذریعے سائن ان ہوتا ہے، ٹھیک وہیں جہاں CLI ہمیشہ دیکھتا ہے۔ اس کے بعد ہر ایک نجی ونڈو کے ذریعے سائن ان ہوتا ہے، تاکہ جس اکاؤنٹ میں آپ کا براؤزر پہلے سے سائن ان ہے وہ غلطی سے نہ پکڑا جائے؛ وہاں اس اکاؤنٹ کے طور پر سائن ان کریں جو آپ شامل کر رہے ہیں، اور پہلے سے کھلی ہوئی کوئی نجی ونڈو پہلے بند کریں۔ اس کے لیے CLI سے کبھی لاگ آؤٹ نہ کریں: لاگ آؤٹ کرنا محفوظ شدہ سائن ان کو منسوخ کر دیتا ہے، اور اس اکاؤنٹ کو دوبارہ شامل کرنا پڑے گا۔

اپنے سبسکرپشن لاگ انز کو SSH پر دوسری Omarchy مشین پر کاپی کرنے کے لیے، `omarchy agent account copy user@laptop` چلائیں۔ بھیجنے والا ایک عارضی وصول کنندہ فراہم کرتا ہے جب منزل کے پاس کوئی انسٹال نہیں ہوتا، لہٰذا پرانی Omarchy مشینیں بغیر اپ ڈیٹ کے اکاؤنٹس وصول کر سکتی ہیں۔ انسٹال شدہ وصول کنندگان کو ترجیح حاصل ہوتی ہے۔ یہ تمام Claude، Codex، اور Grok سبسکرپشنز کاپی کرتا ہے؛ انہیں منتخب کرنے کے لیے فراہم کنندہ کے نام شامل کریں، جیسے `omarchy agent account copy laptop claude` میں۔ اکاؤنٹ کے نام اور کمانڈ IDs ماخذ سے ملتے ہیں، بشمول منزل پر پہلے سے موجود اکاؤنٹس۔ اگر ان کے نام متصادم ہوں تو غیر متعلق منزل اکاؤنٹس کو عددی لاحقہ ملتا ہے، اور ترتیبات، اسکلز، پلگ انز، اور گفتگو کی تاریخ ہر مشین کے لیے مقامی رہتی ہے۔

موجودہ منزل اسناد رکھی جاتی ہیں۔ وہاں پہلے سے سائن ان ماخذ اکاؤنٹ کا نام اس کی اسناد کو بدلے بغیر ہم آہنگ کیا جاتا ہے؛ دوسرے اکاؤنٹس اس کے ساتھ شامل کیے جاتے ہیں۔ ملتے جلتے اکاؤنٹس کے لیے محفوظ شدہ اسناد کو تبدیل کرنے کے لیے، منزل پر اس اکاؤنٹ کے سیشنز چھوڑنے کے بعد `omarchy agent account copy --replace laptop claude` استعمال کریں۔ ایک تازہ منزل کو ماخذ کا فعال اکاؤنٹ اور سوئچنگ ترجیحات بھی ملتی ہیں؛ ایک قائم شدہ منزل اپنی رکھتی ہے۔

اسناد SSH کے ذریعے سفر کرتی ہیں اور منزل پر نجی فائلوں میں محفوظ ہوتی ہیں، لہٰذا صرف ان مشینوں پر کاپی کریں جن پر آپ اعتماد کرتے ہیں۔ یہ ایک بار کی کاپی ہے، جاری ہم آہنگی نہیں۔ Codex ریفریش ٹوکنز کو دوسری مشین گھما سکتی ہے، جس سے کاپی شدہ لاگ ان کو تجدید کی ضرورت پڑ جاتی ہے؛ کئی مشینوں پر بیک وقت استعمال کے لیے الگ سائن انز سب سے قابل اعتماد انتخاب رہتے ہیں۔ دیکھیں [Codex کی اکاؤنٹ تصدیق رہنمائی](https://developers.openai.com/codex/auth/ci-cd-auth)۔

فی فراہم کنندہ ایک اکاؤنٹ فعال ہوتا ہے، اور ہر نیا سیشن اسی کے طور پر شروع ہوتا ہے: `cx`، `cy`، ایک سادہ `claude`، `codex`، یا `grok`، `omarchy agent` کے ذریعے لانچ کی گئی کوئی بھی چیز، اور اسکرپٹس یا ایڈیٹرز جو `PATH` پر CLI پاتے ہیں۔ `omarchy agent account use work` سے سوئچ کریں (اور `omarchy agent account use main` سے واپس)، یا پینل میں کسی اکاؤنٹ کا نمبر دبا کر پھر `Enter` دبا کر (یا اس کے Use بٹن پر کلک کر کے)۔ چل رہے Claude سیشنز بھی سوئچ کرتے ہیں، ان کے اگلے پیغام سے: ہر Claude سیشن `~/.claude` میں چلتا ہے، جو ہمیشہ فعال اکاؤنٹ کا سائن ان رکھتا ہے۔ پرانے Omarchy کے ذریعے کسی اکاؤنٹ کے اپنے فولڈر میں شروع کیا گیا Claude سیشن وہ سائن ان اس وقت تک رکھتا ہے جب تک وہ بند نہ ہو، لہٰذا سوئچ ان سیشنز کا نام لیتا ہے اور ان کے ختم ہونے پر خود مکمل ہو جاتا ہے۔ چل رہے Codex اور Grok سیشنز اسی اکاؤنٹ پر رہتے ہیں جس سے وہ شروع ہوئے تھے۔ گفتگو کی تاریخ، ترتیبات، اسکلز، اور پلگ انز اکاؤنٹس میں مشترکہ ہیں، لہٰذا اسی فولڈر میں `claude --continue` نئے اکاؤنٹ پر وہیں سے اٹھاتا ہے جہاں آپ نے چھوڑا تھا۔

ایک سے زیادہ اکاؤنٹ کے ساتھ، پینل ہر اکاؤنٹ کی حدود ساتھ ساتھ دکھاتا ہے، جس میں فعال نشان زد ہوتا ہے۔ بطور ڈیفالٹ Omarchy آپ کو مطلع کرتا ہے جب فعال اکاؤنٹ کسی حد کے 95% سے گزر جاتا ہے، اور اطلاع پر کلک کرنا سب سے زیادہ گنجائش والے اکاؤنٹ پر سوئچ کر دیتا ہے۔ پینل میں کسی اکاؤنٹ کی لائن پر ہوور کریں اور Use کے ساتھ ظاہر ہونے والے Autoswitch پر کلک کریں (یا `m` دبائیں)، یا `omarchy agent account mode auto` چلائیں، تاکہ یہ خود سوئچ کرے؛ جب یہ آن ہوتا ہے، تو Autoswitch Use کی جگہ لے لیتا ہے، اور دوبارہ کلک کرنا مطلع کرنے پر واپس جاتا ہے۔ حد تبدیل کرنے کے لیے نمبر شامل کریں، جیسے `omarchy agent account mode auto 90` میں۔ اگر ہر اکاؤنٹ حد سے اوپر ہے، تو آپ کو ایک بار اس کے بارے میں سنایا جائے گا، ساتھ میں یہ بھی کہ کون سا اکاؤنٹ سب سے پہلے آزاد ہوتا ہے۔ جبکہ ایک فعال اکاؤنٹ اپنی حد کے 15 پوائنٹس کے اندر ہوتا ہے (ڈیفالٹ پر 80%)، اس کی حدود ہر 15 کے بجائے ہر تین منٹ میں چیک کی جاتی ہیں۔

`omarchy agent account list` ہر اکاؤنٹ اور اس کی تازہ ترین حدود دکھاتا ہے، `omarchy agent account remove work` ایک کو بھول جاتا ہے، اور `omarchy agent account rename primary Hey` ایک کا نام بدلتا ہے (یا پینل میں کسی اکاؤنٹ کے نام پر کلک کریں)۔ یہ کمانڈز آپ کے ڈیفالٹ ایجنٹ کے اکاؤنٹس پر کام کرتی ہیں؛ دوسرے فراہم کنندہ تک پہنچنے کے لیے، پہلے اس کا نام لیں، جیسے `omarchy agent account use codex side` میں۔ `~/.claude` یا `~/.codex` میں آپ کے پاس پہلے سے موجود لاگ ان _Main_ اکاؤنٹ ہے۔ Codex کا وہیں رہتا ہے جہاں ہے؛ Claude کا اپنے فولڈر میں انتظار کرتا ہے جبکہ دوسرا اکاؤنٹ فعال ہوتا ہے۔ تقریباً آٹھ گھنٹے سے زیادہ غیر استعمال شدہ چھوڑا گیا اکاؤنٹ _Sign-in required_ دکھا سکتا ہے؛ اس اکاؤنٹ کو پینل میں ہی دوبارہ سائن ان کرنے کے لیے اس پر کلک کریں، یا اس پر سوئچ کر کے سیشن شروع کریں، جو خود سائن ان کو تازہ کرتا ہے۔ `claude mcp add` سے شامل کیے گئے MCP سرورز ہر Claude اکاؤنٹ تک پہنچتے ہیں، چونکہ وہ سب `~/.claude` میں چلتے ہیں؛ Codex اور Grok کے لیے، اکاؤنٹ شامل کیے جانے کے وقت آپ کے پاس موجود سرورز اس کے ساتھ آتے ہیں، لیکن بعد والے صرف اس اکاؤنٹ تک پہنچتے ہیں جس میں آپ نے انہیں شامل کیا تھا۔ Claude Desktop اپنا سائن ان رکھتا ہے، اور CLI بائنری کے مطلق راستے کے ساتھ تشکیل شدہ Codex یا Grok ٹولز سوئچ کی پیروی نہیں کرتے۔ ایک واضح `CLAUDE_CONFIG_DIR`، `CODEX_HOME`، یا `GROK_HOME` منتخب اکاؤنٹ پر ترجیح لیتا ہے۔

### کریش کی تشخیص

Omarchy عمل کے کریشز کے لیے systemd-coredump دیکھتا ہے۔ جب آپ ڈیفالٹ ایجنٹ منتخب کر لیتے ہیں، تو آپ کا کوئی بھی پروگرام جو کور ڈمپ کرتا ہے ایک "Process crashed" اطلاع لاتا ہے — اس پر کلک کریں، اور کریش آپ کے ڈیفالٹ ایجنٹ کے حوالے کیا جاتا ہے Omarchy کی omarchy-diagnose-crash اسکل کے ساتھ، جو ایجنٹ کو کور ڈمپ سے حقائق قائم کرنے اور یہ فیصلہ کرنے میں لے جاتی ہے کہ آیا کریش upstream رپورٹ کرنے کے قابل ہے۔ آپ اسے `coredumpctl list` سے کسی بھی PID کے خلاف ہاتھ سے بھی چلا سکتے ہیں `omarchy agent crash <pid>` سے۔

دیکھنا بطور ڈیفالٹ آن ہے۔ اسے _Trigger > Toggle > Crash Capture Off_ کے تحت بند کریں (یا `omarchy toggle crash-capture` سے) اور اطلاعات رک جاتی ہیں؛ `omarchy agent crash <pid>` ہاتھ سے پھر بھی کام کرتا ہے۔

کریشز کو ایک وقت میں ایک پروگرام بھی خاموش کیا جا سکتا ہے، جو تشخیص آخر میں آپ کو پیش کرتا ہے۔ `omarchy crash mute hyprland` صرف اس پروگرام کے لیے اطلاعات روکتا ہے، `omarchy crash mute hyprland off` انہیں واپس لاتا ہے، اور `omarchy crash mute` خود ان کی فہرست دیتا ہے جو آپ نے خاموش کیے ہیں۔ یہ بائنری کا راستہ اس کے نام کی طرح خوشی سے لیتا ہے، لہٰذا `omarchy crash mute /usr/bin/hyprland` وہی کام کرتا ہے۔ کسی ایسے نام کو جس میں جگہ ہو کوٹ کریں، جیسے `omarchy crash mute 'Some App'` میں۔ باقی سب پھر بھی مطلع کرتا ہے، اور خاموش پروگرام پھر بھی کریش ہوتا ہے — یہ یاد دہانی چھپاتا ہے، یہ کچھ ٹھیک نہیں کرتا۔

### ڈیسک ٹاپ ایپس

_Install > AI_ مینو چند گرافیکل AI ایپس بھی رکھتا ہے: Amp Desktop، Antigravity Desktop، ChatGPT ڈیسک ٹاپ ایپ، Claude ڈیسک ٹاپ ایپ (Anthropic کا Linux بیٹا، Chat، Cowork، اور Claude Code ٹیبز کے ساتھ)، xAI کے ماڈلز سے چیٹ کرنے کے لیے Grok Bot، Herdr Desktop، Hermes Desktop، OpenClaw، Perplexity ڈیسک ٹاپ ایپ، اور T3 Code۔ Grok Bot ڈیسک ٹاپ چیٹ ایپ ہے۔ کوڈنگ ایجنٹ `grok` کمانڈ ہے۔

Hermes Desktop وہ ہے جس کے بارے میں جاننا ضروری ہے، کیونکہ ایک مشین کے پاس ایک Hermes ہوتا ہے، اور وہ ایپ کا ہوتا ہے: Hermes ہمیشہ صرف ایپ کے ذریعے انسٹال ہوتا ہے، اور ڈیفالٹ ایجنٹ جو `hermes` کمانڈ چلاتا ہے وہ ایپ کی ہوتی ہے۔ Hermes کو ڈیفالٹ ایجنٹ کے طور پر منتخب کرنا وہی چیز انسٹال کرتا ہے جو _Install > AI_ اندراج کرتا ہے: پیکیج، اور Hermes کے اپنے انسٹالر کے ذریعے سیٹ اپ `~/.hermes` کے تحت ایک Hermes رن ٹائم، جو پہلی بار چند منٹ لیتا ہے۔ وہ رن ٹائم وہ واحد Hermes ہے جسے ٹرمینل `hermes` کمانڈ، ڈیفالٹ ایجنٹ اور ایپ سب استعمال کرتے ہیں، اور یہ Omarchy ریلیز کا انتظار کرنے کے بجائے `hermes update` سے خود اپ ڈیٹ ہوتا ہے۔ اسے انسٹال کرنا Hermes کو Omarchy تھیم بطور اسکن بھی دیتا ہے جس کا نام `omarchy` ہے، جس کی ہر Hermes سطح پیروی کرتی ہے جب آپ تھیمز تبدیل کرتے ہیں؛ اگر آپ پسند کرتے ہیں کہ ایسا نہ ہو تو Hermes کی Appearance ترتیبات کے تحت یا `/skin` سے دوسری منتخب کریں، اور Omarchy اس انتخاب کو چھوڑ دیتا ہے۔ _Remove > AI_ کے تحت ایپ کو ہٹانا پہلے Hermes کو بند کرتا ہے، گیٹ وے سمیت، اس رن ٹائم کو اس کے ساتھ لے جاتا ہے، اور آپ کی چیٹس، یادیں، اور وہ اسکلز جو Hermes نے خود اپنے لیے لکھیں رکھی جاتی ہیں الا یہ کہ آپ اسے دوسری صورت کہیں: یہ پوچھتا ہے، ڈیفالٹ نہیں پر، کہ آیا وہ ڈیٹا اور آپ کی کنکشن ترتیبات بھی جانی چاہئیں۔

OpenClaw کا ڈیسک ٹاپ تجربہ اس کا Control UI ہے، جو اس کے اپنے مقامی گیٹ وے کی پشت پر ویب ایپ کے طور پر کھلتا ہے۔ OpenClaw `~/.openclaw` میں رہتا ہے اور خود اپ ڈیٹ ہوتا ہے: Control UI کا "Update Gateway" بٹن استعمال کریں یا `openclaw update` چلائیں، اور گیٹ وے نئے ورژن پر دوبارہ شروع ہوتا ہے۔ Omarchy صرف وہ ریلیز منتخب کرتا ہے جس سے تازہ انسٹال شروع ہوتا ہے۔ OpenClaw آپ کا ڈیفالٹ ایجنٹ بھی ہو سکتا ہے: اسے _Agent > Harness_ کے تحت منتخب کرنا `~/.openclaw` میں وہی کاپی سیٹ اپ کرتا ہے، اور ایجنٹ OpenClaw کا ٹرمینل UI اس کے گیٹ وے سے منسلک کھولتا ہے۔ _Remove > AI_ کے تحت OpenClaw کو ہٹانا گیٹ وے سروس اور ایپ کو اس کے ساتھ لے جاتا ہے اور پھر پوچھتا ہے کہ آیا `~/.openclaw` کو بھی جانا چاہیے، چونکہ وہ OpenClaw خود اور اس کے ڈاؤن لوڈ کردہ پلگ ان رن ٹائمز کے ساتھ آپ کی چیٹس اور اسناد رکھتا ہے؛ ڈیفالٹ اسے رکھتا ہے، اور OpenClaw دوبارہ انسٹال کرنا اسے واپس اٹھا لیتا ہے۔

Herdr Desktop [Herdr](https://herdr.dev) ڈیسک ٹاپ ایپ ہے: ٹرمینلز اور کوڈنگ ایجنٹس کی جگہیں، ٹیبز، اور پینز جو ونڈو بند کرنے پر اس کے کور میں چلتے رہتے ہیں۔ یہ پیکیج کے بجائے Herdr کے اپنے انسٹالر سے آتا ہے، لہٰذا یہ `~/.local/share/herdr-app` میں رہتا ہے، جب آپ کے پاس پہلے سے نہیں ہوتا تو `~/.local/bin/herdr-core` میں اپنا کور ساتھ لاتا ہے، اور دونوں خود اپ ڈیٹ ہوتے ہیں۔ یہ اس `herdr` کمانڈ کے ساتھ بیٹھتا ہے جو Omarchy `Super + Ctrl + Return` پر فراہم کرتا ہے بجائے اسے تبدیل کرنے کے، اور اس کمانڈ کی براہ راست کیز حاصل کرتا ہے: `Alt + Return` اور `Alt + Shift + Return` پین کو نیچے یا دائیں تقسیم کرتے ہیں، `Alt + Escape` اسے بند کرتا ہے، `Ctrl + Alt + Arrow` پینز کے درمیان منتقل ہوتا ہے، `Alt + 1..9` اور `Alt + Left/Right` ٹیب منتخب کرتے ہیں، اور `Alt + Up/Down` جگہوں کے درمیان منتقل ہوتے ہیں۔ `Ctrl + 1..9` جگہ منتخب کرتا ہے اور `Alt + Shift + Up/Down` ایجنٹس میں قدم بڑھاتا ہے۔ `Ctrl + Space` پریفکس کیز صرف ٹرمینل رہتی ہیں، چونکہ ایپ ترتیب کے لیے سادہ Ctrl کی نہیں رکھ سکتی۔ Omarchy انہیں `~/.config/herdr-app/keys.json` میں لکھتا ہے، اور `omarchy-refresh-herdr-app` انہیں واپس رکھتا ہے۔ اسے انسٹال کرنا Herdr کی Omarchy تھیم منتخب کرتا ہے، جو اس کے بعد آپ کی Omarchy تھیم کی پیروی کرتی ہے۔ Herdr ہلکے موڈ کے لیے ایک تھیم اور تاریک کے لیے ایک رکھتا ہے، لہٰذا تاریک اور ہلکی Omarchy تھیم کے درمیان تبدیل کرنے کے بعد، دوسرے موڈ کے لیے Herdr کے تھیم پکر میں ایک بار پھر Omarchy منتخب کریں۔

T3 Code پیکیج کے بجائے `~/.local/share/t3code` میں اپنی آفیشل AppImage ریلیز سے چلتا ہے، لہٰذا یہ خود اپ ڈیٹ ہوتا ہے۔ اسے انسٹال کرنا پوچھتا ہے کہ آیا Stable یا Nightly چینل پر شروع کرنا ہے؛ بعد میں T3 Code کی ترتیبات میں تبدیل کریں۔ آپ کے تھریڈز اور ترتیبات `~/.t3` میں رہتے ہیں، اور _Remove > AI_ کے تحت T3 Code کو ہٹانا انہیں اس کے ساتھ لے جاتا ہے۔

### مقامی ماڈلز

اپنے کوڈنگ ایجنٹس کے لیے اپنی مشین پر کھلا ماڈل چلائیں۔ آپ کے پرامپٹس اور کوڈ مشین پر رہتے ہیں؛ ماڈل کو بھیجی گئی کوئی چیز اسے نہیں چھوڑتی۔ اس سے شروع کریں:

```bash
omarchy models use best text
```

یہ اس مشین کے لیے بہترین ٹیکسٹ ماڈل سیٹ اپ کرتا ہے، وہ قسم جو آپ کے ایجنٹ استعمال کرتے ہیں۔ امیج، ویڈیو اور میوزک ماڈلز کی اپنی بہترین ہوتی ہے: `omarchy models use best image`، `video` یا `music`۔ اس مشین کے لیے ہر قسم کی پسند دیکھنے کے لیے `omarchy models use best` چلائیں۔

یا اوپر والی بار میں ایجنٹس آئیکن کے ساتھ اس کے چمک آئیکن سے مقامی ماڈلز پینل کھولیں، یا Super + Ctrl + Alt + X سے، اور + منتخب کریں۔ آئیکن اس وقت ظاہر ہوتا ہے جب کوئی ماڈل اس مشین پر فٹ بیٹھتا ہے۔ Podman، جو ماڈلز چلاتا ہے، Omarchy کے ساتھ آتا ہے، اسی طرح NVIDIA مشین پر NVIDIA کا کنٹینر ٹول کٹ، جو انہیں GPU دیتا ہے؛ اگر کوئی غائب ہے، تو پہلا سیٹ اپ اسے انسٹال کرتا ہے۔ پھر Omarchy اس مشین کے لیے تجویز کردہ ماڈل منتخب کرتا ہے، اسے ڈاؤن لوڈ کرتا ہے، اور اسے شروع کرتا ہے۔ دسیوں GB کے ڈاؤن لوڈ اور ماڈل چلتے وقت مشین کی زیادہ تر میموری استعمال میں ہونے کی توقع رکھیں: Flash Next اپنے مکمل 256K سیاق و سباق کے ساتھ تقریباً 100 GiB استعمال کرتا ہے۔ اگر دوسرے ماڈل اسے درکار میموری رکھتے ہیں، تو یہ رکا ہوا سیٹ اپ ہوتا ہے، جب آپ ایک کو روکیں تو شروع ہونے کے لیے تیار۔ ماڈل لاگ آؤٹ پر رک جاتا ہے؛ جب آپ کو کسی اور چیز کے لیے میموری درکار ہو تو اسے خود روکیں۔

`omarchy models list` اختیارات دکھاتا ہے اور بیان کرتا ہے کہ کچھ کیوں فٹ نہیں بیٹھتے۔ ایک اور سیٹ اپ کرنے کے لیے، `omarchy models use <recipe>` چلائیں۔ آج، `qwen3.8-flash-next-gufo` اور `qwen3.8-27b-gufo` 128 GB Strix Halo مشینوں کے لیے دستیاب ہیں؛ 27B تقریباً 40 GiB لیتا ہے، لہٰذا یہ دوسرے کام کے لیے جگہ چھوڑتا ہے۔ Intel کے Arc B390 کے ساتھ 64 GB لیپ ٹاپ پر، `qwen3.6-35b-a3b-llamacpp` تقریباً 30 GiB میں چلتا ہے۔ نئی ترکیبیں اور سفارشات پیکیج کے ذریعے `omarchy update` کے ساتھ آتی ہیں۔

آپ کے سیٹ اپ کردہ ہر ماڈل کو مقامی ماڈلز پینل میں اپنی لائن ملتی ہے: اسے شروع کرنے کے لیے چلائیں، اسے روکنے اور اس کی میموری آزاد کرنے کے لیے روکیں، اور اس پر اپنے ایجنٹ کو کھولنے کے لیے ٹرمینل بٹن۔ اوپر کے پار، ایک بار دکھاتا ہے کہ مشین کی میموری Omarchy خود (سسٹم اور آپ کی ایپس)، ہر چل رہے ماڈل، اور جو آزاد ہے کے درمیان کیسے تقسیم ہے۔ رکے ہوئے ماڈل کی طرف اشارہ کریں اور بار دکھاتا ہے کہ آیا یہ فٹ بیٹھتا ہے، یا کتنا کم ہے۔ کئی ایک ساتھ چل سکتے ہیں جب وہ میموری میں اکٹھے فٹ بیٹھتے ہیں؛ اگر ایک فٹ نہیں بیٹھتا، تو Omarchy کہتا ہے کہ کس چل رہے ماڈل کو روکنا ہے۔ لائنز کو ان کے لوگو سے گھسیٹ کر دوبارہ ترتیب دیں، اور منتخب لائن پر Delete دبائیں تاکہ ماڈل اور اس کا ڈاؤن لوڈ ہٹ جائے۔

آپ کے سیٹ اپ کردہ ہر ماڈل کو ایپ لانچر میں بھی اپنا اندراج ملتا ہے، ماڈل کے نام کے تحت اور اس کے بنانے والے کے لوگو کے ساتھ، اسی طرح جیسے Claude، Codex یا Grok میں سائن ان کرنا ایک شامل کرتا ہے۔ یہ اس ماڈل پر آپ کا ایجنٹ کھولتا ہے، اور اگر ماڈل نہیں چل رہا تو پہلے اسے شروع کرتا ہے: ٹرمینل اسے لوڈ ہوتا دکھاتا ہے اور جب یہ تیار ہو تو ایجنٹ کے حوالے کر دیتا ہے۔ ماڈل ہٹانا اس کا اندراج ہٹا دیتا ہے۔

ہر ماڈل کوڈنگ کے لیے نہیں ہے۔ امیج، ویڈیو اور میوزک ماڈل اس کے بجائے Fantasi میں کھلتے ہیں، Omarchy کی اس مشین پر چل رہے ماڈل سے تصویریں، ویڈیو اور موسیقی بنانے کی ایپ، ان کے لانچر اندراج سے اور مقامی ماڈلز پینل میں ان کی لائن سے۔

ایک ماڈل ٹھیک اسی طرح چلتا رہتا ہے جیسے اسے سیٹ اپ کیا گیا تھا، لہٰذا Omarchy اپ ڈیٹ کبھی آپ کے ایجنٹس کے تحت ایک کو دوبارہ شروع نہیں کرتا۔ جب Omarchy کے پاس آپ کے سیٹ اپ کردہ ماڈل کے لیے نیا رن ٹائم یا نئے وزن ہوتے ہیں، تو اس کی لائن اپ ڈیٹ بٹن دکھاتی ہے: اسے دبائیں اور ماڈل پس منظر میں دوبارہ سیٹ اپ ہوتا ہے، صرف جو تبدیل ہوا ڈاؤن لوڈ کرتے ہوئے، اور نئے ورژن پر دوبارہ شروع ہوتا ہے۔ جو ماڈل رکا ہوا تھا وہ رکا رہتا ہے۔ `omarchy models update` ٹرمینل سے ہر ماڈل کے لیے وہی کرتا ہے۔

کمانڈ لائن سے، `omarchy models start <recipe>` اور `omarchy models stop <recipe>` وہی کرتے ہیں، `omarchy models status` ہر ماڈل دکھاتا ہے، اور `omarchy agent --local` آپ کے ڈیفالٹ ایجنٹ کو آخری شروع کردہ ماڈل پر کھولتا ہے۔ pi، OpenCode اور Qwen Code ایک استعمال کر سکتے ہیں؛ کسی دوسرے ڈیفالٹ کے ساتھ یہ pi میں کھلتا ہے، یا OpenCode میں اگر آپ کے پاس pi نہیں ہے۔ pi آپ کے سیٹ اپ کردہ ہر ماڈل، اور ان مشینوں پر جو آپ نے جوڑی ہیں، اپنے ماڈل پکر میں بھی فہرست دیتا ہے، لہٰذا سادہ `pi` بھی ان تک پہنچتا ہے۔ کوئی بھی OpenAI مطابق کلائنٹ بھی جڑ سکتا ہے: `status` ہر ماڈل کا پتہ دکھاتا ہے (پہلا `http://127.0.0.1:11435/v1` ہے)، ترکیب کا نام ماڈل ہے، اور کی `~/.config/omarchy/agent-local/key` میں ہے۔

`omarchy models remove <recipe>` ماڈل اور وہ ڈاؤن لوڈز حذف کرتا ہے جو کوئی دوسرا ماڈل استعمال نہیں کرتا۔

فریق ثالث رن ٹائمز ان کے ناشر کے ساتھ لیبل شدہ ہیں۔ Omarchy ہر ماڈل کو بغیر نیٹ ورک تک رسائی کے چلاتا ہے۔

### مقامی LLMs

Omarchy مقامی LLM ماڈل چلانے کے دو طریقے تجویز کرتا ہے: LM Studio اور Ollama۔ LM Studio اوپن ویٹ ماڈل تلاش کرنے، انہیں انسٹال کرنے، اور انہیں چلانے کے لیے GUI انٹرفیس فراہم کرتا ہے۔ یہ آسانی سے شروع کرنے کا بہترین طریقہ ہے۔ Ollama اسی طرح کرنے کے لیے CLI پیش کرتا ہے۔ لیکن اگر آپ مقامی ماڈلز میں نئے ہیں، تو میں LM Studio سے شروع کروں گا۔ آپ Omarchy Menu میں _Install > AI_ کے تحت کوئی بھی انسٹال کر سکتے ہیں۔

### Omarchy اسکلز

ایجنٹ اسکلز AI کو مخصوص ٹولز کو مخصوص طریقے سے استعمال کرنے میں مدد دیتی ہیں، اور Omarchy ان میں سے سات فراہم کرتا ہے۔ omarchy اسکل سسٹم کو موافق بنانے کا احاطہ کرتی ہے، جیسے اپنی Hyprland کنفگ کو ٹھیک کرنا یا بار کو ایڈجسٹ کرنا۔ omarchy-make-theme، omarchy-make-plugin، omarchy-make-app، اور omarchy-make-game کچھ نیا بنانے کا احاطہ کرتی ہیں، omarchy-contribute بگ رپورٹ کرنے یا upstream فکس بھیجنے کا احاطہ کرتی ہے، اور omarchy-diagnose-crash کریش کے کور ڈمپ پر کام کرتی ہے۔ وہ Claude Code (`~/.claude/skills`)، Codex (`~/.codex/skills`)، Pi (`~/.pi/agent/skills`)، Antigravity (`~/.gemini/config/skills`)، Hermes (`~/.hermes/skills` اور ہر `~/.hermes/profiles/*/skills`)، اور عام `~/.agents/skills` مقام کے لیے اسکل ڈائریکٹریوں میں سم لنک شدہ ہیں، لہٰذا زیادہ تر ہارنسز انہیں خود بخود اٹھا لیتے ہیں۔ اسی نام کا آپ کا اپنا اسکل فولڈر ترجیح لیتا ہے۔

لیکن آپ کو ان اسکلز کو تجرباتی سمجھنا چاہیے۔ مختلف ماڈل اسے مختلف اثر کے لیے استعمال کریں گے۔ بہتر ہے پہلے پلان موڈ میں چلائیں، تاکہ آپ کو اندازہ ہو کہ ایجنٹ کیا تبدیل کرنا چاہے گا۔ اور پھر تبدیلیوں کو واپس کرنے یا حتیٰ کہ `omarchy reinstall configs` کو طلب کرنے کے لیے تیار رہیں، اگر ایجنٹ ہر چیز کی گڑبڑ کر دے۔
