### ایجنٹ انسٹال اور اپ ڈیٹ کرنا

Hermes کے علاوہ، یہ ایجنٹس mise کی lazy installation استعمال کرتے ہیں: پہلا لانچ CLI انسٹال کرتا ہے، اور بعد کے لانچز اسی کو دوبارہ استعمال کرتے ہیں۔ mise انسٹال شدہ ایجنٹ کے لیے نئی ریلیز بھی چیک کرتا ہے، زیادہ سے زیادہ ہر چار گھنٹے میں ایک بار، شروع ہونے سے بالکل پہلے یا پس منظر میں shell prompt پر۔ اگر وہ اپ ڈیٹ ناکام ہو جائے یا آپ آف لائن ہوں، تو انسٹال شدہ ورژن چلتا ہے۔ `omarchy update` انسٹال شدہ ایجنٹس کو باقی Omarchy کے ساتھ اپ ڈیٹ کرتا ہے، اور `mup` صرف mise کے زیر انتظام ٹولز کو اپ ڈیٹ کرتا ہے۔

کسی ایجنٹ کا اپنا updater، جیسے `claude update`، `codex update`، یا کسی ایپ میں update بٹن، mise کے زیر انتظام انسٹال کو اپ ڈیٹ نہیں کرتا۔ `codex update` ناکام ہو جاتا ہے، اور `claude update` کامیابی کی اطلاع دیتے ہوئے ایک الگ کاپی انسٹال کر سکتا ہے جسے mise ٹریک نہیں کرتا۔ اگر آپ اس کے بجائے کسی ایجنٹ کا اپنا installer اور updater استعمال کرنا چاہتے ہیں، تو اسے `disable_tools` میں شامل کریں؛ دیکھیں [پہلے سے انسٹال شدہ CLI ٹولز](18-development-tools.md#preinstalled-cli-tools)۔

تمام configured lazy ٹولز کو ضرورت پڑنے سے پہلے انسٹال کرنے کے لیے `mise install --include-lazy` چلائیں۔ اس میں ایجنٹس کے ساتھ ساتھ Omarchy کے دیگر ڈیفالٹ CLI ٹولز بھی شامل ہیں۔ ایک ٹول انسٹال کرنے یا اپنی انسٹالیشن استعمال کرنے کے لیے دیکھیں [پہلے سے انسٹال شدہ CLI ٹولز](18-development-tools.md#preinstalled-cli-tools)۔

`grok` mise کے first-party `grok` پیکیج کے ذریعے انسٹال ہوتا ہے، اسی طرح جیسے `claude` اور `codex`۔ `grok` چلائیں، یا اسے _Setup > Defaults > Agent_ کے تحت منتخب کریں۔ x.ai پر موجود `curl | bash` installer کو چھوڑ دیں۔ وہ راستہ `~/.grok/bin` میں دوسری کاپی رکھتا ہے، اسے `PATH` کے شروع میں شامل کرتا ہے، اور Omarchy کے wrapper کو overwrite کر دیتا ہے۔

`dsh` اپنا browser UI `127.0.0.1:3080` پر کھولتا ہے، جس میں لانچ ڈائریکٹری اس کا ڈیفالٹ workspace ہوتی ہے۔ اس کا browser UI کوئی ابتدائی prompt نہیں لیتا، اس لیے `omarchy agent prompt` اسے آپ کے clipboard پر موجود prompt کے ساتھ کھولتا ہے تاکہ آپ اسے paste کر سکیں۔ Omarchy اسے DeepSeek کے no-approval permission preset کے ساتھ شروع کرتا ہے۔ جب آپ اس کا آفیشل model API استعمال کرتے ہیں تو DeepSeek Harness سیشن لاگز DeepSeek کو upload کرتا ہے؛ اسے اس کے browser UI میں _Settings > General > Upload Session Log_ کے تحت بند کر دیں۔ آپ جو فیڈبیک اسے بھیجتے ہیں وہ بھی سیشن کے ساتھ upload ہوتا ہے، جب تک آپ اسے `DSH_TELEMETRY_MODE=DISABLED` کے ساتھ شروع نہ کریں۔

### ڈیفالٹ ایجنٹ

اپنا ڈیفالٹ ایجنٹ `omarchy default agent <name>` کے ساتھ یا Omarchy Menu (`Super + Space`) میں _Setup > Defaults > Agent_ کے تحت منتخب کریں۔ اگر ایجنٹ ابھی انسٹال نہیں ہوا، تو اسے منتخب کرنے سے وہ پہلے انسٹال ہو جائے گا۔ تازہ Omarchy ایک بار کی اطلاع کے ساتھ آپ کو یہ انتخاب کرنے کی دعوت دے گا۔

Claude منتخب کرنا Chromium، Chrome، Brave، Brave Origin، اور Edge کے لیے اس کی browser extension ترتیب دینے کی بھی کوشش کرتا ہے۔ extension کی ترتیب تمام صارفین پر لاگو ہوتی ہے اور آپ سے آپ کا سسٹم پاس ورڈ مانگ سکتی ہے؛ extension انسٹال منسوخ کرنے یا ناکام ہونے پر بھی Claude منتخب اور لانچ ہو جاتا ہے۔ اپنا براؤزر دوبارہ شروع کریں، اگر کہا جائے تو extension فعال کریں، اور اسے جوڑنا مکمل کرنے کے لیے Claude میں سائن ان کریں۔ کنکشن چیک کرنے کے لیے Claude میں `/chrome` چلائیں۔ Firefox اور Zen اس extension کی حمایت نہیں کرتے۔ اگر اس ترتیب کے شامل ہونے سے پہلے ہی Claude آپ کا ڈیفالٹ تھا، تو extension انسٹال کرنے کے لیے اسے دوبارہ منتخب کریں۔

ایک بار منتخب کر لینے کے بعد، `Super + Shift + Ctrl + A` ڈیفالٹ ایجنٹ کو ایک مخصوص ٹرمینل ونڈو میں لانچ کرتا ہے (یا اگر آپ نے ابھی انتخاب نہیں کیا تو picker سامنے لاتا ہے)۔ آپ اسے `omarchy agent prompt "Review this project"` کے ساتھ سیدھا کسی کام میں بھی لانچ کر سکتے ہیں۔ Freebuff اور DeepSeek Harness کوئی ابتدائی prompt نہیں لیتے، اس لیے اس کے بجائے وہ آپ کے clipboard پر موجود prompt کے ساتھ کھلتے ہیں تاکہ آپ اسے paste کر سکیں۔ اس طرح لانچ کیے گئے ایجنٹس اپنے متعلقہ don't-stop-to-ask طریقوں میں بغیر نگرانی کے چلتے ہیں، اس لیے تیار رہیں کہ وہ واقعی کچھ کریں گے! MiniMax Code کے interactive سیشنز کے لیے ایسا کوئی طریقہ نہیں ہے، اس لیے وہ معمول کے مطابق اجازتیں مانگتا ہے۔ اور چونکہ ایجنٹس آپ کی home ڈائریکٹری کے لیے trust یاد رکھنے سے انکار کرتے ہیں، اس لیے `$HOME` سے لانچز اس کے بجائے `~/Work` میں شروع ہوتے ہیں۔

ٹرمینل شارٹ کٹس بھی ہیں: `a` ڈیفالٹ ایجنٹ کو موجودہ ٹرمینل میں inline چلاتا ہے، جبکہ `c`، `cx`، اور `cy` OpenCode، Claude Code، اور Codex کو براہ راست شروع کرتے ہیں (ایک بار پھر ان کے auto-approving طریقوں میں)۔ تھیم کی تبدیلیاں ایجنٹس کے ساتھ بھی sync ہوتی ہیں: جب آپ Omarchy تھیم تبدیل کرتے ہیں تو Claude Code، Pi، OpenCode، اور Hermes (جب Omarchy نے اسے انسٹال کر لیا ہو) سب اس کے ساتھ بدلتے ہیں۔

### ایجنٹس پینل

اوپر والی بار میں ایک ایجنٹس آئیکن ہے۔ کسی ایجنٹ کو ترتیب دینے سے پہلے، اس کا پینل آپ کو Claude، Codex، یا Grok میں سائن ان کرنے کے مراحل سے گزارتا ہے، اور ان میں سے پہلا آپ کا ڈیفالٹ ایجنٹ بن جاتا ہے۔ اس کے بعد، پینل ہر سبسکرپشن کو ایک صفحے پر رکھتا ہے: ہر ایجنٹ اور اکاؤنٹ اس کے پلان کے ساتھ، اس کی 5-hour سیشن اور ہفتہ وار حدود میں سے ہر ایک کے لیے ایک میٹر جس میں اس کے reset ہونے تک کا وقت بھی شامل ہے (درست فیصد کے لیے hover کریں)، یا باقی prepaid بیلنس، ایک لائن کے نیچے جو ان سب میں آپ کے استعمال کی چیزوں میں گھومتی رہتی ہے، جیسے اس ہفتے کے tokens اور آپ کا سب سے زیادہ استعمال شدہ ماڈل۔ _Make something_ کے تحت یہ نئی تھیم، plugin، یا ایپ کے لیے starter prompts پیش کرتا ہے جو کام آپ کے ڈیفالٹ ایجنٹ کے حوالے کرتے ہیں۔ ایپس اسی طرح بنائی جاتی ہیں جس طرح Omarchy کی اپنی Hype، Monologue، اور Omacut ہیں، C++ اور Qt Quick میں، omarchy-app ایجنٹ skill کی پیروی کرتے ہوئے، اور انہیں درکار compiler اور Qt کے اجزا انسٹال شدہ آتے ہیں۔ Claude Code، Codex، Grok، Kimi، Cursor اور اس کا Grok Bot الاؤنس، GitHub Copilot، Muse، Antigravity، Kimchi، اور Devin اپنی حدود کے ساتھ ابتدا سے ہی شامل ہیں، اور Hermes، Mistral Vibe، اور Qwen Code ایک بار جب آپ انہیں استعمال کر لیں تو اپنے سیشنز اور tokens دکھاتے ہیں۔ pi، omp، یا opencode کے ذریعے آپ جو provider پلانز اور keys استعمال کرتے ہیں وہ بھی نظر آتے ہیں: OpenCode Zen اور Go، Z.ai GLM Coding Plan، Ollama Cloud، MiniMax Token Plan، اور Synthetic اپنی حدود کے ساتھ؛ Fireworks، OpenRouter، اور DeepSeek اپنے prepaid بیلنسز کے ساتھ؛ اور وہ ماڈلز جو آپ اپنے ہارڈویئر پر Local models کے تحت چلاتے ہیں۔ ہر ایجنٹ ایک بار گنا جاتا ہے، اس کے تحت جس سے اس کا بل آتا ہے، چاہے آپ اسے کتنے ہی harnesses کے ذریعے چلائیں۔

پینل کے لیے بار آئیکن پر left-click کریں، اپنے ڈیفالٹ ایجنٹ کو لانچ کرنے کے لیے right-click کریں۔ اس کے پیچھے کے استعمال کے ریکارڈز ہر 15 منٹ بعد `omarchy agent usage-update` کے ذریعے دوبارہ بنائے جاتے ہیں، اور پینل synced فولڈر کے ذریعے آپ کی دیگر مشینوں سے استعمال کو ضم بھی کر سکتا ہے۔ مکمل ترتیبات کے لیے `$OMARCHY_PATH/shell/plugins/agents/` کے تحت README دیکھیں۔

### متعدد سبسکرپشنز

اگر آپ ایک سے زیادہ Claude، Codex، یا Grok پلان کے لیے ادائیگی کرتے ہیں — مثلاً ایک ذاتی Max اور ایک کام کا — تو Omarchy ان سب کو سائن ان رکھ سکتا ہے اور ان کے درمیان منتقل ہو سکتا ہے۔ ایجنٹس پینل میں + کے ساتھ سبسکرپشن شامل کریں، جو آپ کو وہیں اس کے مراحل سے گزارتا ہے، یا `omarchy agent account add claude Work` (یا `codex`، یا `grok`) کے ساتھ۔ اگر CLI موجود نہیں ہے تو یہ اسے انسٹال کر دیتا ہے۔ کسی provider کے لیے پہلا اکاؤنٹ آپ کے عام براؤزر کے ذریعے سائن ان ہوتا ہے، بالکل وہیں جہاں CLI ہمیشہ دیکھتا ہے۔ اس کے بعد کا ہر اکاؤنٹ ایک private ونڈو کے ذریعے سائن ان ہوتا ہے، تاکہ جس اکاؤنٹ میں آپ کا براؤزر پہلے سے سائن ان ہے وہ غلطی سے نہ منتخب ہو جائے؛ وہاں اس اکاؤنٹ کے طور پر سائن ان کریں جسے آپ شامل کر رہے ہیں، اور پہلے سے کھلی ہوئی کوئی بھی private ونڈو پہلے بند کر دیں۔ اس کے لیے کبھی CLI سے لاگ آؤٹ نہ کریں: لاگ آؤٹ کرنے سے محفوظ شدہ سائن ان منسوخ ہو جاتا ہے، اور اس اکاؤنٹ کو دوبارہ شامل کرنا پڑے گا۔

اپنے سبسکرپشن لاگ انز کو SSH کے ذریعے کسی دوسری Omarchy مشین پر کاپی کرنے کے لیے `omarchy agent account copy user@laptop` چلائیں۔ جب منزل پر کوئی انسٹال نہ ہو تو بھیجنے والا ایک عارضی receiver فراہم کرتا ہے، اس لیے پرانی Omarchy مشینیں بغیر اپ ڈیٹ کے اکاؤنٹس وصول کر سکتی ہیں۔ انسٹال شدہ receivers کو ترجیح حاصل ہے۔ یہ تمام Claude، Codex، اور Grok سبسکرپشنز کاپی کرتا ہے؛ انہیں منتخب کرنے کے لیے provider نام شامل کریں، جیسے `omarchy agent account copy laptop claude` میں۔ اکاؤنٹ کے نام اور command IDs ماخذ سے ملتے ہیں، بشمول وہ اکاؤنٹس جو منزل پر پہلے سے موجود ہیں۔ اگر غیر متعلقہ منزل اکاؤنٹس کے ناموں میں تصادم ہو تو انہیں عددی suffix ملتا ہے، اور ترتیبات، skills، plugins، اور گفتگو کی تاریخ ہر مشین پر مقامی رہتی ہے۔

منزل کی موجودہ credentials برقرار رکھی جاتی ہیں۔ کوئی ماخذ اکاؤنٹ جو وہاں پہلے سے سائن ان ہے، اس کا نام اس کی credentials کو بدلے بغیر sync کر دیا جاتا ہے؛ دیگر اکاؤنٹس اس کے ساتھ شامل کر دیے جاتے ہیں۔ ملتے جلتے اکاؤنٹس کے لیے محفوظ شدہ credentials کو تبدیل کرنے کے لیے، منزل پر اس اکاؤنٹ کے سیشنز بند کرنے کے بعد `omarchy agent account copy --replace laptop claude` استعمال کریں۔ تازہ منزل کو ماخذ کا فعال اکاؤنٹ اور switching ترجیحات بھی ملتی ہیں؛ قائم شدہ منزل اپنی ترجیحات برقرار رکھتی ہے۔

Credentials SSH کے ذریعے سفر کرتی ہیں اور منزل پر private فائلوں میں محفوظ ہوتی ہیں، اس لیے صرف ان مشینوں پر کاپی کریں جن پر آپ کو بھروسہ ہے۔ یہ ایک بار کی کاپی ہے، جاری synchronization نہیں۔ Codex refresh tokens کسی دوسری مشین کے ذریعے rotate کیے جا سکتے ہیں، جس سے کاپی شدہ لاگ ان کو تجدید کی ضرورت پڑ سکتی ہے؛ متعدد مشینوں پر بیک وقت استعمال کے لیے الگ سائن انز سب سے قابل اعتماد انتخاب ہیں۔ دیکھیں [Codex's account authentication guidance](https://developers.openai.com/codex/auth/ci-cd-auth)۔

فی provider ایک اکاؤنٹ فعال ہوتا ہے، اور ہر نیا سیشن اسی کے طور پر شروع ہوتا ہے: `cx`، `cy`، سادہ `claude`، `codex`، یا `grok`، `omarchy agent` کے ذریعے لانچ کی گئی کوئی بھی چیز، اور اسکرپٹس یا editors جو CLI کو `PATH` پر تلاش کرتے ہیں۔ `omarchy agent account use work` کے ساتھ تبدیل کریں (اور `omarchy agent account use main` کے ساتھ واپس)، یا پینل میں کسی اکاؤنٹ کا نمبر دبا کر پھر `Enter` دبا کر (یا اس کے Use بٹن پر کلک کر کے)۔ پہلے سے چل رہے سیشنز اسی اکاؤنٹ پر رہتے ہیں جس سے وہ شروع ہوئے تھے۔ گفتگو کی تاریخ، ترتیبات، skills، اور plugins اکاؤنٹس کے درمیان مشترکہ ہیں، اس لیے اسی فولڈر میں `claude --continue` نئے اکاؤنٹ پر وہیں سے شروع ہوتا ہے جہاں آپ نے چھوڑا تھا۔

ایک سے زیادہ اکاؤنٹ ہونے پر، پینل ہر اکاؤنٹ کی حدود ساتھ ساتھ دکھاتا ہے، جس میں فعال اکاؤنٹ نشان زد ہوتا ہے۔ بطور ڈیفالٹ Omarchy آپ کو مطلع کرتا ہے جب فعال اکاؤنٹ کسی حد کے 95% سے گزر جاتا ہے، اور اطلاع پر کلک کرنے سے سب سے زیادہ گنجائش والے اکاؤنٹ پر switch ہو جاتا ہے۔ پینل میں کسی اکاؤنٹ کی لائن پر hover کریں اور Use کے ساتھ نظر آنے والے Autoswitch پر کلک کریں (یا `m` دبائیں)، یا `omarchy agent account mode auto` چلائیں، تاکہ یہ اس کے بجائے خود بخود switch ہو جائے؛ جب یہ فعال ہو، تو Autoswitch Use کی جگہ لے لیتا ہے، اور اس پر دوبارہ کلک کرنے سے مطلع کرنے پر واپس آ جاتا ہے۔ حد تبدیل کرنے کے لیے نمبر شامل کریں، جیسے `omarchy agent account mode auto 90` میں۔ اگر ہر اکاؤنٹ حد سے اوپر ہے، تو آپ کو ایک بار اس کے بارے میں بتایا جائے گا، اس کے ساتھ کہ کون سا اکاؤنٹ سب سے پہلے آزاد ہوتا ہے۔ جب فعال اکاؤنٹ اپنی حد کے 15 points کے اندر ہو (ڈیفالٹ پر 80%)، تو اس کی حدود ہر 15 کے بجائے ہر تین منٹ بعد چیک کی جاتی ہیں۔

`omarchy agent account list` ہر اکاؤنٹ اور اس کی تازہ ترین حدود دکھاتا ہے، `omarchy agent account remove work` ایک کو بھلا دیتا ہے، اور `omarchy agent account rename primary Hey` ایک کا نام تبدیل کرتا ہے (یا پینل میں کسی اکاؤنٹ کے نام پر کلک کریں)۔ یہ کمانڈز آپ کے ڈیفالٹ ایجنٹ کے اکاؤنٹس پر کام کرتی ہیں؛ دوسرے provider تک پہنچنے کے لیے، پہلے اس کا نام لیں، جیسے `omarchy agent account use codex side` میں۔ جو لاگ ان آپ کے پاس پہلے سے `~/.claude` یا `~/.codex` میں تھا وہ _Main_ اکاؤنٹ ہے اور وہیں رہتا ہے۔ تقریباً آٹھ گھنٹے سے زیادہ عرصے تک غیر استعمال شدہ رہ جانے والا اکاؤنٹ _Sign-in required_ دکھا سکتا ہے؛ پینل میں ہی اس اکاؤنٹ میں دوبارہ سائن ان کرنے کے لیے اس پر کلک کریں، یا اس میں سیشن شروع کریں، جو خود بخود سائن ان کو تازہ کر دیتا ہے۔ جب کوئی اکاؤنٹ شامل کیا گیا تھا اس وقت آپ کے پاس موجود MCP servers اس کے ساتھ آ جاتے ہیں، لیکن جو آپ بعد میں `claude mcp add` کے ساتھ شامل کرتے ہیں وہ صرف اس اکاؤنٹ تک پہنچتے ہیں جس میں آپ نے انہیں شامل کیا تھا۔ Claude Desktop اور CLI binary کے absolute path کے ساتھ configured ٹولز switch کی پیروی نہیں کرتے۔ واضح `CLAUDE_CONFIG_DIR`، `CODEX_HOME`، یا `GROK_HOME` منتخب شدہ اکاؤنٹ پر ترجیح لیتا ہے۔

### Crash کی تشخیص

Omarchy process crashes کے لیے systemd-coredump پر نظر رکھتا ہے۔ جب کوئی چیز segfault کرتی ہے، تو آپ کو "Process crashed" اطلاع ملے گی — اس پر کلک کریں، اور crash آپ کے ڈیفالٹ ایجنٹ کے حوالے کر دیا جاتا ہے Omarchy کی diagnose-crash skill کے ساتھ، جو ایجنٹ کو core dump سے حقائق قائم کرنے اور یہ فیصلہ کرنے کے مراحل سے گزارتی ہے کہ آیا crash کی اطلاع upstream دینے کے قابل ہے۔ آپ اسے `coredumpctl list` سے حاصل کسی بھی PID کے خلاف ہاتھ سے بھی چلا سکتے ہیں `omarchy agent crash <pid>` کے ساتھ۔

یہ نگرانی بطور ڈیفالٹ فعال ہے۔ اسے _Trigger > Toggle > Crash Capture_ کے تحت بند کر دیں (یا `omarchy toggle crash-capture` کے ساتھ) اور اطلاعات بند ہو جائیں گی؛ `omarchy agent crash <pid>` ہاتھ سے پھر بھی کام کرتا ہے۔

Crashes کو ایک وقت میں ایک پروگرام کے لیے بھی خاموش کیا جا سکتا ہے، جو تشخیص آخر میں آپ کو پیش کرتی ہے۔ `omarchy crash mute hyprland` صرف اس پروگرام کے لیے اطلاعات روک دیتا ہے، `omarchy crash mute hyprland off` انہیں واپس لاتا ہے، اور `omarchy crash mute` اکیلا وہ فہرست دیتا ہے جو آپ نے خاموش کی ہے۔ یہ binary کے path کو اس کے نام کی طرح خوشی سے قبول کرتا ہے، اس لیے `omarchy crash mute /usr/bin/hyprland` بھی وہی کام کرتا ہے۔ جس نام میں space ہو اسے quote کریں، جیسے `omarchy crash mute 'Some App'` میں۔ باقی سب کچھ اب بھی مطلع کرتا ہے، اور خاموش کیا گیا پروگرام اب بھی crash ہوتا ہے — یہ یاد دہانی چھپاتا ہے، یہ کچھ ٹھیک نہیں کرتا۔

### ڈیسک ٹاپ ایپس

_Install > AI_ مینو میں چند graphical AI ایپس بھی ہیں: ChatGPT ڈیسک ٹاپ ایپ، Claude ڈیسک ٹاپ ایپ (Anthropic کا Linux beta، Chat، Cowork، اور Claude Code ٹیبز کے ساتھ)، xAI کے ماڈلز کے ساتھ چیٹ کے لیے Grok Bot، Herdr Desktop، Hermes Desktop، OpenClaw، Perplexity ڈیسک ٹاپ ایپ، اور T3 Code۔ Grok Bot ڈیسک ٹاپ چیٹ ایپ ہے۔ کوڈنگ ایجنٹ `grok` کمانڈ ہے۔

Hermes Desktop وہ ہے جس کے بارے میں جاننا ضروری ہے، کیونکہ ایک مشین میں ایک Hermes ہوتا ہے، اور وہ ایپ کا ہوتا ہے: Hermes ہمیشہ صرف ایپ کے ذریعے انسٹال ہوتا ہے، اور ڈیفالٹ ایجنٹ جو `hermes` کمانڈ چلاتا ہے وہ ایپ کی ہے۔ Hermes کو ڈیفالٹ ایجنٹ کے طور پر منتخب کرنا وہی چیز انسٹال کرتا ہے جو _Install > AI_ اندراج کرتا ہے: پیکیج، اور Hermes کے اپنے installer کے ذریعے ترتیب دیا گیا `~/.hermes` کے تحت ایک Hermes runtime، جس میں پہلی بار چند منٹ لگتے ہیں۔ وہ runtime وہی ایک Hermes ہے جسے ٹرمینل کی `hermes` کمانڈ، ڈیفالٹ ایجنٹ اور ایپ سب استعمال کرتے ہیں، اور یہ Omarchy ریلیز کا انتظار کرنے کے بجائے `hermes update` کے ساتھ خود کو اپ ڈیٹ کرتا ہے۔ اسے انسٹال کرنا Hermes کو Omarchy تھیم بھی `omarchy` نامی skin کے طور پر دیتا ہے، جس کی ہر Hermes سطح آپ کے تھیم تبدیل کرنے کے ساتھ پیروی کرتی ہے؛ اگر آپ ایسا نہ چاہتے ہوں تو Hermes کی Appearance ترتیبات کے تحت یا `/skin` کے ساتھ کوئی اور منتخب کریں، اور Omarchy اس انتخاب کو چھوڑ دیتا ہے۔ _Remove > AI_ کے تحت ایپ کو ہٹانا پہلے Hermes کو بند کرتا ہے، gateway سمیت، اس runtime کو اس کے ساتھ لے جاتا ہے، اور آپ کی چیٹس، یادیں، اور وہ skills جو Hermes نے خود اپنے لیے لکھی تھیں برقرار رکھتا ہے جب تک آپ اسے دوسری صورت نہ کہیں: یہ پوچھتا ہے، بطور ڈیفالٹ نہیں کے ساتھ، کہ آیا وہ ڈیٹا اور آپ کی کنکشن ترتیبات بھی جانی چاہئیں۔

OpenClaw کا ڈیسک ٹاپ تجربہ اس کا Control UI ہے، جو اپنے مقامی gateway کی پشت پناہی والی web ایپ کے طور پر کھلتا ہے۔ OpenClaw `~/.openclaw` میں رہتا ہے اور خود کو اپ ڈیٹ کرتا ہے: Control UI کا "Update Gateway" بٹن استعمال کریں یا `openclaw update` چلائیں، اور gateway نئے ورژن پر دوبارہ شروع ہو جاتا ہے۔ Omarchy صرف وہ ریلیز منتخب کرتا ہے جس سے تازہ انسٹال شروع ہوتا ہے۔ _Remove > AI_ کے تحت OpenClaw کو ہٹانا gateway سروس اور ایپ کو اس کے ساتھ لے جاتا ہے اور پھر پوچھتا ہے کہ آیا `~/.openclaw` بھی جانا چاہیے، کیونکہ اس میں آپ کی چیٹس اور credentials کے ساتھ خود OpenClaw اور اس کے ڈاؤن لوڈ کیے گئے plugin runtimes موجود ہیں؛ ڈیفالٹ اسے برقرار رکھتا ہے، اور OpenClaw دوبارہ انسٹال کرنا اسے واپس لے لیتا ہے۔

Herdr Desktop [Herdr](https://herdr.dev) ڈیسک ٹاپ ایپ ہے: ٹرمینلز اور کوڈنگ ایجنٹس کے spaces، tabs، اور panes جو ونڈو بند کرنے پر بھی اس کے core میں چلتے رہتے ہیں۔ یہ کسی پیکیج کے بجائے Herdr کے اپنے installer سے آتا ہے، اس لیے یہ `~/.local/share/herdr-app` میں رہتا ہے، جب آپ کے پاس پہلے سے کوئی نہ ہو تو اپنے core کو `~/.local/bin/herdr-core` میں ساتھ لاتا ہے، اور دونوں کو خود اپ ڈیٹ کرتا ہے۔ یہ اس `herdr` کمانڈ کے ساتھ بیٹھتا ہے جو Omarchy `Super + Ctrl + Return` پر فراہم کرتا ہے، اس کی جگہ لینے کے بجائے۔ اسے انسٹال کرنا Herdr کی Omarchy تھیم منتخب کرتا ہے، جو اس کے بعد سے آپ کی Omarchy تھیم کی پیروی کرتی ہے۔ Herdr light mode کے لیے ایک تھیم اور dark کے لیے ایک رکھتا ہے، اس لیے dark اور light Omarchy تھیم کے درمیان تبدیل کرنے کے بعد، دوسرے mode کے لیے Herdr کے تھیم picker میں ایک بار پھر Omarchy منتخب کریں۔

T3 Code پیکیج کے بجائے `~/.local/share/t3code` میں اپنی آفیشل AppImage ریلیز سے چلتا ہے، اس لیے یہ خود کو اپ ڈیٹ کرتا ہے۔ اسے انسٹال کرنا پوچھتا ہے کہ Stable یا Nightly چینل پر شروع کرنا ہے؛ بعد میں T3 Code کی ترتیبات میں تبدیل کریں۔ آپ کے threads اور ترتیبات `~/.t3` میں رہتے ہیں، اور _Remove > AI_ کے تحت T3 Code کو ہٹانا انہیں اس کے ساتھ لے جاتا ہے۔

### مقامی ماڈلز

اپنے کوڈنگ ایجنٹس کے لیے اپنی مشین پر open ماڈل چلائیں۔ آپ کے prompts اور code مشین پر رہتے ہیں؛ ماڈل کو بھیجی گئی کوئی چیز اسے نہیں چھوڑتی۔ اس سے شروع کریں:

```bash
omarchy agent local use best
```

یا، اوپر والی بار کے ایجنٹس پینل میں، + اور پھر Local AI منتخب کریں، جو اس وقت ظاہر ہوتا ہے جب کوئی ماڈل اس مشین میں فٹ آتا ہو۔ پہلی بار، یہ Podman انسٹال کرتا ہے، جو ماڈلز چلاتا ہے، اور NVIDIA مشین پر NVIDIA کا container toolkit، جو انہیں GPU دیتا ہے۔ پھر Omarchy اس مشین کے لیے تجویز کردہ ماڈل منتخب کرتا ہے، اسے ڈاؤن لوڈ کرتا ہے، اور اسے شروع کرتا ہے۔ دسیوں GB کے ڈاؤن لوڈ کی توقع رکھیں اور جب ماڈل چل رہا ہو تو مشین کی زیادہ تر میموری استعمال میں ہوگی: Flash Next اپنے مکمل 256K context کے ساتھ تقریباً 100 GiB استعمال کرتا ہے۔ اگر دیگر ماڈلز وہ میموری رکھتے ہیں جس کی اسے ضرورت ہے، تو یہ روکا ہوا ترتیب دیا جاتا ہے، ایک بار جب آپ کسی ایک کو روکیں تو شروع ہونے کے لیے تیار۔ ماڈل لاگ آؤٹ پر رک جاتا ہے؛ جب آپ کو کسی اور چیز کے لیے میموری درکار ہو تو اسے خود روک دیں۔

`omarchy agent local list` اختیارات دکھاتا ہے اور بتاتا ہے کہ کچھ کیوں فٹ نہیں آتے۔ کوئی اور ترتیب دینے کے لیے `omarchy agent local use <recipe>` چلائیں۔ آج، `qwen3.8-flash-next-gufo` اور `qwen3.8-27b-gufo` 128 GB Strix Halo مشینوں کے لیے دستیاب ہیں؛ 27B تقریباً 40 GiB لیتا ہے، اس لیے یہ دیگر کام کے لیے جگہ چھوڑتا ہے۔ نئی recipes اور تجاویز پیکیج کے ذریعے `omarchy update` کے ساتھ آتی ہیں۔

آپ جو بھی ماڈل ترتیب دیتے ہیں اسے ایجنٹس پینل میں، آپ کی سبسکرپشنز کے ساتھ، اپنی لائن ملتی ہے: اسے شروع کرنے کے لیے play، اسے روکنے اور اس کی میموری آزاد کرنے کے لیے pause، اور اس پر اپنا ایجنٹ کھولنے کے لیے ٹرمینل بٹن۔ جب وہ میموری میں ایک ساتھ فٹ آتے ہوں تو متعدد ایک ساتھ چل سکتے ہیں؛ اگر کوئی فٹ نہ آئے، تو Omarchy بتاتا ہے کہ کون سا چل رہا ماڈل روکنا ہے۔ انہیں دوبارہ ترتیب دینے کے لیے لائنز کو گھسیٹیں، اور منتخب لائن پر Delete دبائیں تاکہ ماڈل اور اس کا ڈاؤن لوڈ ہٹا دیا جائے۔

کمانڈ لائن سے، `omarchy agent local start <recipe>` اور `omarchy agent local stop <recipe>` وہی کام کرتے ہیں، `omarchy agent local status` ہر ماڈل دکھاتا ہے، اور `omarchy agent --local` آپ کے ڈیفالٹ ایجنٹ کو آخری ماڈل پر کھولتا ہے جو آپ نے شروع کیا تھا (pi اگر آپ کا ڈیفالٹ ایجنٹ مقامی ماڈل استعمال نہیں کر سکتا)۔ کوئی بھی OpenAI-compatible کلائنٹ بھی جڑ سکتا ہے: `status` ہر ماڈل کا پتہ دکھاتا ہے (پہلا `http://127.0.0.1:11435/v1` ہے)، recipe نام ماڈل ہے، اور کلید `~/.config/omarchy/agent-local/key` میں ہے۔

`omarchy agent local remove <recipe>` ماڈل اور وہ ڈاؤن لوڈز حذف کر دیتا ہے جو کوئی اور ماڈل استعمال نہیں کرتا۔

Third-party runtimes پر ان کے publisher کا لیبل لگا ہوتا ہے۔ Omarchy ہر ماڈل کو بغیر نیٹ ورک رسائی کے چلاتا ہے۔

### مقامی LLMs

Omarchy مقامی LLM ماڈلز چلانے کے دو طریقے تجویز کرتا ہے: LM Studio اور Ollama۔ LM Studio open-weight ماڈلز تلاش کرنے، انہیں انسٹال کرنے، اور انہیں چلانے کے لیے GUI انٹرفیس فراہم کرتا ہے۔ یہ آسانی سے شروع کرنے کا بہترین طریقہ ہے۔ Ollama اسی طرح کرنے کے لیے CLI پیش کرتا ہے۔ لیکن اگر آپ مقامی ماڈلز میں نئے ہیں، تو میں LM Studio سے شروع کروں گا۔ آپ Omarchy Menu میں _Install > AI_ کے تحت دونوں میں سے کوئی بھی انسٹال کر سکتے ہیں۔

### Omarchy Skill

ایجنٹ skills AI کو مخصوص ٹولز کو مخصوص طریقے سے استعمال کرنے میں مدد دیتی ہیں، اور Omarchy سسٹم کو اپنی مرضی کے مطابق بنانے کے لیے ایک ڈیفالٹ skill کے ساتھ آتا ہے۔ جیسے اپنی Hyprland config میں تبدیلی کرنا، بار کو ایڈجسٹ کرنا، یا شروع سے نئی تھیم بنانا۔ یہ Claude Code (`~/.claude/skills`)، Codex (`~/.codex/skills`)، Pi (`~/.pi/agent/skills`)، Antigravity (`~/.gemini/config/skills`)، Hermes (`~/.hermes/skills` اور ہر `~/.hermes/profiles/*/skills`)، اور عام `~/.agents/skills` مقام کے skill ڈائریکٹریوں میں symlinked ہے، اس لیے زیادہ تر harnesses اسے خود بخود اٹھا لیتے ہیں۔

لیکن آپ کو اس skill کو تجرباتی سمجھنا چاہیے۔ مختلف ماڈلز اسے مختلف اثر کے ساتھ استعمال کریں گے۔ بہتر ہے پہلے اسے plan mode میں چلائیں، تاکہ آپ کو اندازہ ہو کہ ایجنٹ کیا تبدیل کرنا چاہے گا۔ اور پھر تبدیلیوں کو rollback کرنے یا حتیٰ کہ `omarchy reinstall configs` چلانے کے لیے تیار رہیں، اگر ایجنٹ سب کچھ خراب کر دے۔
