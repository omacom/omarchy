### ایجنٹس انسٹال اور اپڈیٹ کرنا

Hermes اور OpenClaw کے سوا، ہر ایجنٹ Omarchy کے اپنے repository کا package ہے۔ کوئی ایک _Install > AI > CLI_ سے یا `omarchy install ai cli <command>` کے ساتھ انسٹال کریں، اور اسے _Remove > AI > CLI_ سے دوبارہ ہٹائیں، جس سے اس کے sign-in اور history جوں کی توں رہتی ہیں۔ کسی ایسے ایجنٹ کو منتخب کرنا جو ابھی انسٹال نہ ہو، اسے بھی انسٹال کر دیتا ہے: ایجنٹس پینل میں اسے ستارے سے نشان زد کرنا، اسے `omarchy default agent <name>` کے ساتھ منتخب کرنا، یا اس کی subscription میں sign in کرنا۔ Omarchy کسی ایجنٹ کی ہر نئی release کو ایک گھنٹے کے اندر، ہر channel پر شائع کرتا ہے، اور `omarchy update` اسے باقی سسٹم کے ساتھ انسٹال کر دیتا ہے۔

چونکہ pacman انہیں تازہ رکھتا ہے، اس لیے ایجنٹس کے اپنے updater بند ہیں: `claude update` یا کسی ایپ میں update کے بٹن کو کچھ نہیں کرنا۔ اگر آپ کسی ایجنٹ کو اس کے اپنے installer سے چلانا پسند کریں تو وہی استعمال کریں اور Omarchy کا package انسٹال نہ کریں؛ آپ کے `PATH` پر پہلے سے موجود کاپی انسٹال شدہ شمار ہوتی ہے۔ ایسے `curl | bash` installer چھوڑ دیں جو Omarchy کی کاپی سے آگے `PATH` پر دوسری کاپی رکھ دیں، جیسے `grok` کے لیے x.ai کا installer۔

`dsh` اپنا browser UI `127.0.0.1:3080` پر کھولتا ہے، جس میں launch directory اس کی ڈیفالٹ workspace ہوتی ہے۔ اس کا browser UI کوئی ابتدائی prompt نہیں لیتا، اس لیے `omarchy agent prompt` اسے آپ کے clipboard پر موجود prompt کے ساتھ کھولتا ہے تاکہ آپ اسے paste کر سکیں۔ Omarchy اسے DeepSeek کے no-approval permission preset کے ساتھ شروع کرتا ہے۔ DeepSeek Harness، جب آپ اس کا سرکاری model API استعمال کرتے ہیں، تو session logs DeepSeek کو upload کرتا ہے؛ اسے اس کے browser UI میں _Settings > General > Upload Session Log_ کے تحت بند کر دیں۔ آپ اسے جو feedback بھیجتے ہیں وہ بھی session کے ساتھ upload ہو جاتی ہے، الا یہ کہ آپ اسے `DSH_TELEMETRY_MODE=DISABLED` کے ساتھ شروع کریں۔

### ڈیفالٹ ایجنٹ

اپنا ڈیفالٹ ایجنٹ ایجنٹس پینل میں کسی ایجنٹ کے ساتھ والے ستارے سے منتخب کریں، جو ڈیفالٹ پر بھرا ہوا ہوتا ہے، یا `omarchy default agent <name>` کے ساتھ، جو وہاں لائن نہ رکھنے والے کسی بھی harness کو بھی قبول کرتا ہے۔ اگر ایجنٹ ابھی انسٹال نہ ہو تو اسے منتخب کرنے سے پہلے وہ انسٹال ہو جاتا ہے، اور اسے app launcher میں Agent کے ساتھ ساتھ اس کا اپنا launcher بھی مل جاتا ہے۔ نیا Omarchy ایک بار کی notification کے ساتھ آپ کو ایک ایجنٹ سیٹ اپ کرنے کی دعوت دیتا ہے، جو ایجنٹس پینل کھولتی ہے۔

Claude منتخب کرنا Chromium، Chrome، Brave، Brave Origin اور Edge کے لیے اس کی browser extension سیٹ اپ کرنے کی بھی کوشش کرتا ہے۔ extension کا سیٹ اپ تمام users پر لاگو ہوتا ہے اور آپ سے آپ کے سسٹم کا password مانگ سکتا ہے؛ منسوخ کرنا یا extension کی ناکام انسٹالیشن بھی Claude کو منتخب اور launch کر دیتی ہے۔ اپنا browser دوبارہ شروع کریں، ہدایت ملنے پر extension فعال کریں، اور اسے جوڑنا مکمل کرنے کے لیے Claude میں sign in کریں۔ کنکشن جانچنے کے لیے Claude میں `/chrome` چلائیں۔ Firefox اور Zen اس extension کی حمایت نہیں کرتے۔ اگر یہ سیٹ اپ شامل کیے جانے سے پہلے Claude ہی آپ کا ڈیفالٹ تھا، تو extension انسٹال کرنے کے لیے اسے دوبارہ منتخب کریں۔

منتخب کر لینے کے بعد، `Super + Shift + Ctrl + A` ڈیفالٹ ایجنٹ کو ایک مخصوص terminal window میں launch کرتا ہے (یا اگر آپ نے ابھی کوئی منتخب نہ کیا ہو تو picker سامنے لاتا ہے)۔ آپ اسے `omarchy agent prompt "Review this project"` کے ساتھ سیدھا کسی کام میں بھی launch کر سکتے ہیں۔ Freebuff اور DeepSeek Harness کوئی ابتدائی prompt نہیں لیتے، اس لیے وہ اس کے بجائے آپ کے clipboard پر موجود prompt کے ساتھ کھلتے ہیں تاکہ آپ اسے paste کر سکیں۔ اس طرح launch کیے گئے ایجنٹ اپنے متعلقہ don't-stop-to-ask modes میں بغیر نگرانی کے چلتے ہیں، لہٰذا تیار رہیں کہ وہ واقعی کچھ کر گزریں گے! MiniMax Code کے interactive sessions کے لیے ایسا کوئی mode نہیں ہے، اس لیے وہ معمول کے مطابق permissions مانگتا ہے۔ اور چونکہ ایجنٹ آپ کی home directory کے لیے trust یاد رکھنے سے انکار کرتے ہیں، اس لیے `$HOME` سے ہونے والے launch اس کے بجائے `~/Work` میں شروع ہوتے ہیں۔

terminal shortcuts بھی ہیں: `a` موجودہ terminal میں ڈیفالٹ ایجنٹ کو inline چلاتا ہے، جبکہ `c`، `cx`، `cy` اور `ca` OpenCode، Claude Code، Codex اور Antigravity کو براہِ راست شروع کرتے ہیں (دوبارہ، ان کے auto-approving modes میں)۔ Theme کی تبدیلیاں بھی ایجنٹس تک sync ہوتی ہیں: جب آپ Omarchy theme بدلتے ہیں تو Claude Code، Pi، OpenCode اور Hermes (جب Omarchy اسے انسٹال کر چکا ہو) سب اس کے ساتھ چلتے ہیں۔

### آپ کی ایجنٹ ہدایات

ہر ایجنٹ کے لیے ذاتی قواعد `~/.agents/AGENTS.md` میں جاتے ہیں، `~/.agents/skills` میں shared skills کے ساتھ۔ اسے ایجنٹس پینل میں + کے ساتھ والے document icon سے کھولیں، یا `omarchy agent instructions --edit` کے ساتھ، جو اسے ہر اس harness میں بھی link کر دیتا ہے جو اپنی global file رکھتا ہے: `~/.claude/CLAUDE.md`، `~/.codex/AGENTS.md`، `~/.pi/agent/AGENTS.md`، `~/.config/opencode/AGENTS.md`، Copilot کی `~/.copilot/copilot-instructions.md`، وغیرہ۔ Crush اور Amp `~/.config/AGENTS.md` والا link پڑھتے ہیں، جبکہ omp، Kimi اور DeepSeek Harness براہِ راست `~/.agents/AGENTS.md` پڑھتے ہیں۔ ڈیفالٹ ایجنٹ منتخب کرنا بھی اسے link کر دیتا ہے۔ اگر آپ کے پاس پہلے سے کوئی instructions file تھی اور ابھی کوئی shared file موجود نہ تھی تو وہی shared بن جاتی ہے؛ ورنہ اسے link کے ساتھ `.bak` کے طور پر رکھا جاتا ہے۔ کوئی اور ایجنٹ انسٹال کرنے کے بعد دوبارہ link کرنے کے لیے `omarchy agent instructions` چلائیں۔

### ایجنٹس پینل

اوپر والی bar میں ایجنٹس کا icon ہے۔ ایجنٹ سیٹ اپ کرنے سے پہلے، اس کا پینل شروع کرنے کے تین طریقے پیش کرتا ہے: Claude، Codex، Grok، Gemini، Muse، Cursor یا Copilot subscription میں sign in کریں، یا More کے تحت OpenCode Go، MiniMax، Synthetic یا Z.ai coding plan میں؛ Fireworks، OpenCode Zen and Go، OpenRouter کے ساتھ، یا More کے تحت DeepSeek یا کسی بھی دوسرے provider کے ساتھ جس میں OpenCode sign in کرتا ہے، pay as you go کریں، یہ سب OpenCode میں چلتے ہیں؛ یا اپنے کمپیوٹر کے لیے بہترین ماڈل چلائیں، جب کوئی اس میں فٹ آتا ہو۔ آپ ان میں سے جو پہلا مکمل کریں گے وہی آپ کا ڈیفالٹ ایجنٹ بن جائے گا، اور پینل میں + بعد میں بھی یہی تین طریقے پیش کرتا ہے۔ اس کے بعد، پینل ہر subscription کو ایک ہی page پر رکھ دیتا ہے: ہر ایجنٹ اور account اپنے plan کے ساتھ، اس کی 5-hour session اور weekly limits میں سے ہر ایک کے لیے ایک meter جس کے ساتھ اس کے reset ہونے تک کا وقت ہو (درست percentage کے لیے hover کریں)، یا باقی prepaid balance، ایک ایسی لائن کے تحت جو ان سب میں آپ کے استعمال کی چیزوں کو باری باری دکھاتی ہے، جیسے اس ہفتے کے tokens اور آپ کا سب سے زیادہ استعمال شدہ ماڈل۔ _Make something cool_ کے تحت یہ نئے theme، plugin، app یا game کے لیے starter prompts پیش کرتا ہے جو کام آپ کے ڈیفالٹ ایجنٹ کے سپرد کر دیتے ہیں۔ Apps اسی طرح بنتی ہیں جس طرح Omarchy کی اپنی Hype، Monologue اور Omacut بنی ہیں، C++ اور Qt Quick میں، omarchy-make-app agent skill کی پیروی کرتے ہوئے، اور انہیں درکار compiler اور Qt کے اجزا انسٹال شدہ آتے ہیں۔ Games `~/Games/vibes` میں ایک واحد three.js page ہوتی ہیں، omarchy-make-game agent skill کی پیروی کرتے ہوئے، اور سب موجودہ theme میں ایک ہی Game Vibes launcher سے کھلتی ہیں؛ وہ three.js web سے load کرتی ہیں، اس لیے شروع ہونے کے لیے انہیں کنکشن چاہیے۔ Claude Code، Codex، Grok، Kimi، Cursor اور اس کا Grok Bot allowance، GitHub Copilot، Muse، Gemini (Antigravity کے ذریعے) اور Devin اپنی limits کے ساتھ شروع سے شامل ہیں، Kimchi اپنے plan، prepaid credits اور spend budgets کے ساتھ، اور Hermes، Mistral Vibe اور Qwen Code جب آپ انہیں استعمال کر لیں تو اپنے sessions اور tokens دکھاتے ہیں۔ pi، omp یا opencode کے ذریعے استعمال کیے جانے والے provider plans اور keys بھی ظاہر ہوتے ہیں: OpenCode Zen and Go، Z.ai GLM Coding Plan، Ollama Cloud، MiniMax Token Plan اور Synthetic اپنی limits کے ساتھ؛ OpenRouter اور DeepSeek اپنے prepaid balances کے ساتھ؛ Fireworks پچھلے 30 دنوں میں اپنے خرچ کے ساتھ۔ اپنی ہی hardware پر چلائے جانے والے coding models کو ان کی اپنی لائنیں ملتی ہیں، اور ان کے tokens بھی totals میں شمار ہوتے ہیں، جیسا کہ [مقامی ماڈلز](#local-models) کے تحت بیان کیا گیا ہے۔ ہر ایجنٹ ایک ہی بار شمار ہوتا ہے، اس کے تحت جو اس کا bill دیتا ہے، خواہ آپ اسے کتنے ہی harnesses کے ذریعے چلائیں۔

پینل کے لیے bar icon پر left-click کریں یا `Super + Ctrl + X` دبائیں، اپنے ڈیفالٹ ایجنٹ کو launch کرنے کے لیے right-click کریں، اور refresh کے لیے middle-click کریں۔ اس کے پیچھے موجود usage records ہر 15 منٹ بعد `omarchy agent usage update` کے ذریعے دوبارہ بنتے ہیں، اور پینل ایک synced folder کے ذریعے آپ کی دوسری machines سے usage کو بھی ضم کر سکتا ہے۔ مکمل settings کے لیے `$OMARCHY_PATH/shell/plugins/agents/` کے تحت README دیکھیں۔

### متعدد سبسکرپشنز

اگر آپ ایک سے زیادہ Claude، Codex یا Grok plan کے لیے ادائیگی کرتے ہیں — مثلاً ایک ذاتی Max اور ایک کام والا — تو Omarchy ان سب کو signed in رکھ سکتا ہے اور ان کے درمیان منتقل ہو سکتا ہے۔ ایجنٹس پینل میں + کے ساتھ subscription شامل کریں، جو وہیں آپ کو پورے عمل سے گزارتا ہے، یا `omarchy agent account add claude Work` کے ساتھ (یا `codex`، یا `grok`)۔ یہی + اور command Gemini (`gemini`) اور OpenCode (`opencode`) میں sign in کرتے ہیں، اور OpenCode میں Fireworks (`fireworks`) یا OpenRouter (`openrouter`) API key محفوظ کرتے ہیں؛ یہ command Copilot (`copilot`)، Cursor (`cursor`) اور Muse (`muse`) میں بھی sign in کرتا ہے۔ وہ ہر ایک ایک ہی sign-in رکھتے ہیں۔ اگر CLI موجود نہ ہو تو یہ اسے انسٹال کر دیتا ہے۔ کسی provider کا پہلا account آپ کے معمول کے browser سے sign in ہوتا ہے، ٹھیک وہیں جہاں CLI ہمیشہ دیکھتا ہے۔ اس کے بعد ہر account ایک private window سے sign in ہوتا ہے، تاکہ جس account میں آپ کا browser پہلے سے signed in ہے وہ غلطی سے نہ چن لیا جائے؛ وہاں اس account کے طور پر sign in کریں جسے آپ شامل کر رہے ہیں، اور پہلے سے کھلی ہوئی کوئی بھی private window پہلے بند کر دیں۔ اس کے لیے کبھی CLI سے log out نہ کریں: log out کرنے سے محفوظ شدہ sign-in منسوخ ہو جاتا ہے، اور اس account کو دوبارہ شامل کرنا پڑے گا۔

اپنے subscription logins کو SSH کے ذریعے کسی دوسری Omarchy machine پر copy کرنے کے لیے، `omarchy agent account copy user@laptop` چلائیں۔ جب destination کے پاس کوئی receiver انسٹال نہ ہو تو sender ایک عارضی receiver فراہم کرتا ہے، تاکہ پرانی Omarchy machines بغیر update کے accounts وصول کر سکیں۔ انسٹال شدہ receivers کو ترجیح حاصل ہوتی ہے۔ یہ تمام Claude، Codex اور Grok subscriptions copy کرتا ہے؛ انہیں منتخب کرنے کے لیے provider کے نام شامل کریں، جیسے `omarchy agent account copy laptop claude` میں۔ Account کے نام اور command IDs source سے مطابقت رکھتے ہیں، بشمول وہ accounts جو destination پر پہلے سے موجود ہوں۔ اگر ناموں میں تصادم ہو تو غیرمتعلق destination accounts کو عددی suffix ملتا ہے، اور settings، skills، plugins اور conversation history ہر machine پر مقامی رہتی ہیں۔

Destination کی موجودہ credentials برقرار رہتی ہیں۔ کوئی source account جو وہاں پہلے سے signed in ہو، اس کا نام اس کی credentials بدلے بغیر synchronize ہو جاتا ہے؛ دوسرے accounts اس کے ساتھ شامل کر دیے جاتے ہیں۔ مماثل accounts کی محفوظ شدہ credentials بدلنے کے لیے، destination پر اس account کے sessions بند کرنے کے بعد `omarchy agent account copy --replace laptop claude` استعمال کریں۔ نئی destination کو source کا active account اور switching preferences بھی ملتی ہیں؛ قائم شدہ destination اپنی preferences برقرار رکھتی ہے۔

Credentials SSH کے ذریعے سفر کرتی ہیں اور destination پر private files میں محفوظ ہوتی ہیں، لہٰذا صرف ان machines پر copy کریں جن پر آپ کو اعتماد ہے۔ یہ ایک بار کی copy ہے، جاری synchronization نہیں۔ Codex کے refresh tokens کسی دوسری machine کے ذریعے rotate ہو سکتے ہیں، جس سے copy شدہ login کو تجدید کی ضرورت پڑ جاتی ہے؛ کئی machines پر بیک وقت استعمال کے لیے الگ الگ sign-in سب سے قابلِ اعتماد انتخاب رہتے ہیں۔ [Codex کی account authentication رہنمائی](https://developers.openai.com/codex/auth/ci-cd-auth) دیکھیں۔

فی provider ایک account فعال ہوتا ہے، اور ہر نیا session اسی کے طور پر شروع ہوتا ہے: `cx`، `cy`، سادہ `claude`، `codex` یا `grok`، `omarchy agent` کے ذریعے launch کی گئی کوئی بھی چیز، اور وہ scripts یا editors جو CLI کو `PATH` پر پاتے ہیں۔ `omarchy agent account use work` کے ساتھ switch کریں (اور `omarchy agent account use main` کے ساتھ واپس)، یا پینل میں کسی account کا نمبر دبا کر پھر `Enter` دبائیں (یا اس کے ستارے پر click کریں)۔ چلتے ہوئے Claude sessions بھی، ان کے اگلے message سے، switch ہو جاتے ہیں: ہر Claude session `~/.claude` میں چلتا ہے، جس میں ہمیشہ فعال account کا sign-in ہوتا ہے۔ پرانے Omarchy کے ذریعے کسی account کے اپنے folder میں شروع کیا گیا Claude session اس sign-in کو اس کے بند ہونے تک برقرار رکھتا ہے، اس لیے switch ان sessions کے نام بتاتا ہے اور ان کے ختم ہوتے ہی خود مکمل ہو جاتا ہے۔ چلتے ہوئے Codex اور Grok sessions اسی account پر رہتے ہیں جس سے وہ شروع ہوئے تھے۔ Conversation history، settings، skills اور plugins accounts میں مشترک ہوتے ہیں، اس لیے اسی folder میں `claude --continue` نئے account پر وہیں سے آگے بڑھتا ہے جہاں آپ نے چھوڑا تھا۔

ایک سے زیادہ account کے ساتھ، پینل ہر account کی limits شانہ بشانہ دکھاتا ہے، جس میں استعمال میں موجود account پر بھرا ہوا ستارہ ہوتا ہے۔ جب فعال account کسی limit کے 95% سے گزر جاتا ہے تو Omarchy آپ کو مطلع کرتا ہے، اور notification پر click کرنے سے اس account پر switch ہو جاتا ہے جس میں سب سے زیادہ گنجائش ہو۔ یہ خود سے کبھی switch نہیں کرتا۔ threshold کو `omarchy agent account threshold 90` کے ساتھ بدلیں۔ اگر ہر account threshold سے اوپر ہو تو آپ کو ایک بار اس کی اطلاع ملے گی، اس کے ساتھ کہ کون سا account سب سے پہلے آزاد ہوگا۔ جب فعال account اپنے threshold کے 15 points کے اندر ہو (ڈیفالٹ پر 80%)، تو اس کی limits ہر 15 کے بجائے ہر تین منٹ بعد جانچی جاتی ہیں۔

`omarchy agent account list` ہر account اور اس کی تازہ ترین limits دکھاتا ہے، `omarchy agent account remove work` ایک کو بھلا دیتا ہے، اور `omarchy agent account rename primary Hey` ایک کا نام بدل دیتا ہے (یا پینل میں کسی account کے نام پر click کریں)۔ یہ commands آپ کے ڈیفالٹ ایجنٹ کے accounts پر کام کرتی ہیں؛ دوسرے provider تک پہنچنے کے لیے پہلے اس کا نام لیں، جیسے `omarchy agent account use codex side` میں۔ `~/.claude` یا `~/.codex` میں آپ کا پہلے سے موجود login _Main_ account ہے۔ Codex کا وہیں رہتا ہے جہاں وہ ہے؛ جب کوئی دوسرا account فعال ہو تو Claude کا اپنے ہی folder میں انتظار کرتا ہے۔ آٹھ گھنٹوں سے زیادہ غیراستعمال شدہ رہ جانے والا account _Sign-in required_ دکھا سکتا ہے؛ اس account میں دوبارہ sign in کرنے کے لیے پینل ہی میں اس پر click کریں، یا اس پر switch کر کے ایک session شروع کریں، جو sign-in کو خود تازہ کر دیتا ہے۔ `claude mcp add` کے ساتھ شامل کیے گئے MCP servers ہر Claude account تک پہنچتے ہیں، کیونکہ وہ سب `~/.claude` میں چلتے ہیں؛ Codex اور Grok کے لیے، کسی account کے شامل کیے جانے کے وقت آپ کے پاس موجود servers اس تک ساتھ آ جاتے ہیں، لیکن بعد والے صرف اسی account تک پہنچتے ہیں جس میں آپ نے انہیں شامل کیا تھا۔ Claude Desktop اپنا sign-in خود رکھتا ہے، اور کسی CLI binary کے absolute path کے ساتھ configure کیے گئے Codex یا Grok tools switch کی پیروی نہیں کرتے۔ واضح `CLAUDE_CONFIG_DIR`، `CODEX_HOME` یا `GROK_HOME` منتخب account پر فوقیت رکھتا ہے۔

### کریش کی تشخیص

Omarchy process crashes کے لیے systemd-coredump پر نظر رکھتا ہے۔ ڈیفالٹ ایجنٹ منتخب کر لینے کے بعد، آپ کا کوئی بھی program جو core dump کرے، "Process crashed" notification لاتا ہے — اس پر click کریں، اور crash آپ کے ڈیفالٹ ایجنٹ کے سپرد کر دیا جاتا ہے Omarchy کی omarchy-diagnose-crash skill کے ساتھ، جو ایجنٹ کو core dump سے حقائق قائم کرنے اور یہ فیصلہ کرنے میں رہنمائی کرتی ہے کہ آیا crash upstream رپورٹ کرنے کے قابل ہے۔ آپ اسے `coredumpctl list` سے کسی بھی PID کے خلاف `omarchy agent crash <pid>` کے ساتھ ہاتھ سے بھی چلا سکتے ہیں۔

یہ نگرانی بطورِ ڈیفالٹ فعال ہے۔ اسے _Trigger > Toggle > Crash Capture Off_ کے تحت بند کر دیں (یا `omarchy toggle crash-capture` کے ساتھ) تو notifications رک جاتی ہیں؛ `omarchy agent crash <pid>` ہاتھ سے پھر بھی کام کرتا ہے۔

Crashes کو ایک ایک program کے حساب سے خاموش بھی کیا جا سکتا ہے، یہی وہ چیز ہے جو تشخیص آخر میں آپ کو پیش کرتی ہے۔ `omarchy crash mute hyprland` صرف اس program کے لیے notifications روک دیتا ہے، `omarchy crash mute hyprland off` انہیں واپس لے آتا ہے، اور اکیلا `omarchy crash mute` وہ فہرست دکھاتا ہے جو آپ نے mute کی ہے۔ یہ binary کا path بھی اتنی ہی خوشی سے قبول کرتا ہے جتنا اس کا نام، اس لیے `omarchy crash mute /usr/bin/hyprland` بھی یہی کرتا ہے۔ جس نام میں space ہو اسے quote کریں، جیسے `omarchy crash mute 'Some App'` میں۔ باقی سب کچھ پھر بھی مطلع کرتا ہے، اور muted program پھر بھی crash ہوتا ہے — یہ reminder کو چھپاتا ہے، یہ کچھ ٹھیک نہیں کرتا۔

### ڈیسک ٹاپ ایپس

_Install > AI > Desktop_ میں گرافیکل AI ایپس ہیں: Amp Desktop، Antigravity Desktop، ChatGPT desktop app، Claude desktop app (Anthropic کا Linux beta، Chat، Cowork اور Claude Code tabs کے ساتھ)، xAI کے models سے chat کرنے کے لیے Grok Bot، Herdr Desktop، Hermes Desktop، OpenClaw، Perplexity desktop app اور T3 Code۔ Grok Bot desktop chat app ہے۔ کوڈنگ ایجنٹ `grok` command ہے۔

Hermes Desktop وہ ہے جس کے بارے میں جاننا ضروری ہے، کیونکہ کسی machine پر ایک Hermes ہوتا ہے، اور وہ ایپ کا ہوتا ہے: Hermes ہمیشہ صرف ایپ کے ذریعے انسٹال ہوتا ہے، اور ڈیفالٹ ایجنٹ جو `hermes` command چلاتا ہے وہ ایپ ہی کی ہے۔ Hermes کو ڈیفالٹ ایجنٹ کے طور پر منتخب کرنا وہی چیز انسٹال کرتا ہے جو _Install > AI > Desktop_ والی entry کرتی ہے: package، اور `~/.hermes` کے تحت ایک Hermes runtime جو Hermes کے اپنے installer نے سیٹ اپ کیا ہو، جس میں پہلی بار چند منٹ لگتے ہیں۔ وہی runtime وہ واحد Hermes ہے جسے terminal کی `hermes` command، ڈیفالٹ ایجنٹ اور ایپ سب استعمال کرتے ہیں، اور یہ Omarchy release کا انتظار کرنے کے بجائے `hermes update` کے ساتھ خود کو اپڈیٹ کرتا ہے۔ اسے انسٹال کرنا Hermes کو Omarchy theme بھی بطور skin دیتا ہے جس کا نام `omarchy` ہے، جس کی Hermes کی ہر surface theme بدلنے پر پیروی کرتی ہے؛ اگر آپ نہ چاہیں کہ ایسا ہو تو Hermes کی Appearance settings میں یا `/skin` کے ساتھ کوئی اور منتخب کریں، اور Omarchy اس انتخاب کو چھوڑ دیتا ہے۔ _Remove > AI > Desktop_ کے تحت ایپ ہٹانا پہلے Hermes کو بند کرتا ہے، gateway سمیت، اس runtime کو اپنے ساتھ لے جاتا ہے، اور آپ کی chats، memories اور وہ skills برقرار رکھتا ہے جو Hermes نے اپنے لیے لکھی ہوں، الا یہ کہ آپ اسے اس کے برعکس کہیں: یہ پوچھتا ہے، جس کا ڈیفالٹ نہیں ہے، کہ آیا وہ data اور آپ کی connection settings بھی ختم کر دی جائیں۔

OpenClaw کا desktop تجربہ اس کا Control UI ہے، جو اس کے اپنے مقامی gateway کی پشت پناہی میں ایک web app کے طور پر کھلتا ہے۔ OpenClaw `~/.openclaw` میں رہتا ہے اور خود کو اپڈیٹ کرتا ہے: Control UI کا "Update Gateway" بٹن استعمال کریں یا `openclaw update` چلائیں، اور gateway نئے version پر دوبارہ شروع ہو جاتا ہے۔ Omarchy صرف وہ release منتخب کرتا ہے جس سے نئی انسٹالیشن شروع ہوتی ہے۔ OpenClaw آپ کا ڈیفالٹ ایجنٹ بھی ہو سکتا ہے: اسے `omarchy default agent openclaw` کے ساتھ منتخب کرنے سے `~/.openclaw` میں وہی کاپی سیٹ اپ ہو جاتی ہے، اور ایجنٹ اس کے gateway سے منسلک OpenClaw کا terminal UI کھولتا ہے۔ _Remove > AI > Desktop_ کے تحت OpenClaw ہٹانا gateway service اور ایپ کو اپنے ساتھ لے جاتا ہے اور پھر پوچھتا ہے کہ آیا `~/.openclaw` بھی ختم کر دیا جائے، کیونکہ اس میں OpenClaw خود اور اس کے download کیے گئے plugin runtimes کے ساتھ آپ کی chats اور credentials بھی ہوتی ہیں؛ ڈیفالٹ اسے برقرار رکھتا ہے، اور OpenClaw دوبارہ انسٹال کرنا اسے واپس اٹھا لیتا ہے۔

Herdr Desktop، [Herdr](https://herdr.dev) desktop app ہے: terminals اور coding agents کے spaces، tabs اور panes جو window بند کرنے پر بھی اس کے core میں چلتے رہتے ہیں۔ یہ کسی package کے بجائے Herdr کے اپنے installer سے آتا ہے، اس لیے یہ `~/.local/share/herdr-app` میں رہتا ہے، جب آپ کے پاس پہلے سے کوئی موجود نہ ہو تو اپنے core کو `~/.local/bin/herdr-core` میں ساتھ لاتا ہے، اور دونوں کو خود اپڈیٹ کرتا ہے۔ یہ اس `herdr` command کے ساتھ ساتھ رہتا ہے جو Omarchy `Super + Ctrl + Return` پر فراہم کرتا ہے، اس کی جگہ نہیں لیتا، اور اس command کی direct keys حاصل کرتا ہے: `Alt + Return` اور `Alt + Shift + Return` کسی pane کو نیچے یا دائیں تقسیم کرتے ہیں، `Alt + Escape` اسے بند کرتا ہے، `Ctrl + Alt + Arrow` panes کے درمیان منتقل ہوتا ہے، `Alt + 1..9` اور `Alt + Left/Right` tab منتخب کرتے ہیں، اور `Alt + Up/Down` spaces کے درمیان منتقل ہوتے ہیں۔ `Ctrl + 1..9` space منتخب کرتا ہے اور `Alt + Shift + Up/Down` agents میں آگے پیچھے جاتا ہے۔ `Ctrl + Space` prefix keys صرف terminal تک محدود رہتی ہیں، کیونکہ ایپ کسی sequence کے لیے سادہ Ctrl key کو روک نہیں سکتی۔ Omarchy انہیں `~/.config/herdr-app/keys.json` میں لکھتا ہے، اور `omarchy-refresh-herdr-app` انہیں واپس رکھ دیتا ہے۔ اسے انسٹال کرنا Herdr کا Omarchy theme منتخب کرتا ہے، جو اس کے بعد سے آپ کے Omarchy theme کی پیروی کرتا ہے۔ Herdr light mode کے لیے ایک theme اور dark کے لیے ایک رکھتا ہے، اس لیے dark اور light Omarchy theme کے درمیان بدلنے کے بعد، دوسرے mode کے لیے Herdr کے theme picker میں ایک بار پھر Omarchy منتخب کریں۔

T3 Code کسی package کے بجائے `~/.local/share/t3code` میں اپنی سرکاری AppImage release سے چلتا ہے، اس لیے یہ خود کو اپڈیٹ کرتا ہے۔ اسے انسٹال کرنا پوچھتا ہے کہ Stable یا Nightly channel سے شروع کرنا ہے؛ بعد میں T3 Code کی settings میں بدل لیں۔ آپ کے threads اور settings `~/.t3` میں رہتے ہیں، اور _Remove > AI > Desktop_ کے تحت T3 Code ہٹانا انہیں اپنے ساتھ لے جاتا ہے۔

### مقامی ماڈلز

اپنے کوڈنگ ایجنٹس کے لیے اپنی ہی machine پر ایک open model چلائیں۔ آپ کے prompts اور code machine پر ہی رہتے ہیں؛ ماڈل کو بھیجی گئی کوئی چیز اس سے باہر نہیں جاتی۔ اس سے شروع کریں:

```bash
omarchy models use best text
```

یہ اس machine کے لیے بہترین text model سیٹ اپ کرتا ہے، اسی قسم کا جسے آپ کے ایجنٹ استعمال کرتے ہیں۔ Image، video اور music models کا اپنا اپنا بہترین ہوتا ہے: `omarchy models use best image`، `video` یا `music`۔ اس machine کے لیے ہر قسم کا انتخاب دیکھنے کے لیے `omarchy models use best` چلائیں۔

یا ایجنٹس پینل میں + منتخب کریں: _Use a local model_ کے تحت یہ ہر وہ coding model فہرست کرتا ہے جو اس machine میں فٹ آتا ہے، تجویز کردہ سب سے پہلے۔ Podman، جو models چلاتا ہے، Omarchy کے ساتھ آتا ہے، اسی طرح NVIDIA machine پر NVIDIA کا container toolkit بھی، جو انہیں GPU دیتا ہے؛ اگر ان میں سے کوئی غائب ہو تو پہلا سیٹ اپ اسے انسٹال کر دیتا ہے۔ پھر Omarchy اس machine کے لیے تجویز کردہ ماڈل منتخب کرتا ہے، اسے download کرتا ہے، اور اسے شروع کرتا ہے۔ دسیوں GB کے download کی توقع رکھیں اور یہ کہ ماڈل چلتے وقت machine کی زیادہ تر memory استعمال میں ہوگی: Flash Next اپنے مکمل 256K context کے ساتھ تقریباً 100 GiB استعمال کرتا ہے۔ اگر دوسرے models وہ memory روکے ہوئے ہوں جس کی اسے ضرورت ہے، تو یہ بند حالت میں سیٹ اپ ہوتا ہے، کسی ایک کو آپ کے بند کرتے ہی شروع ہونے کے لیے تیار۔ ماڈل logout پر رک جاتا ہے؛ جب آپ کو کسی اور کام کے لیے memory چاہیے ہو تو اسے خود بند کر دیں۔

`omarchy models list` اختیارات دکھاتا ہے اور بتاتا ہے کہ کچھ کیوں فٹ نہیں آتے۔ کوئی اور سیٹ اپ کرنے کے لیے، `omarchy models use <recipe>` چلائیں۔ آج، 128 GB Strix Halo machines کے لیے `qwen3.8-flash-next-gufo` اور `qwen3.8-27b-gufo` دستیاب ہیں؛ 27B تقریباً 40 GiB لیتا ہے، اس لیے یہ دوسرے کام کے لیے جگہ چھوڑ دیتا ہے۔ Intel کے Arc B390 والے 64 GB laptop پر، `qwen3.6-35b-a3b-llamacpp` تقریباً 30 GiB میں چلتا ہے۔ نئی recipes اور تجاویز package کے ذریعے `omarchy update` کے ساتھ آتی ہیں۔

آپ کا شامل کردہ coding model ایجنٹس پینل میں، آپ کی subscriptions کے ساتھ، اپنی لائن حاصل کرتا ہے: اسے شروع کرنے کے لیے play، اسے روکنے اور اس کی memory آزاد کرنے کے لیے pause، چلتے وقت اسے اپنے tailnet پر دوسری machines کے ساتھ share کرنے کے لیے Tailscale کا نشان، اور اس پر اپنا ایجنٹ کھولنے کے لیے terminal بٹن۔ اس کی لائن download، load یا stop کو ہوتے ہوئے دکھاتی ہے، اور یہ بتا دیتی ہے جب اسے شروع کرنے کے لیے کافی آزاد memory نہ ہو، یا جب یہ error کے ساتھ رکا ہو تو اس کے logs سے link کر دیتی ہے۔ جب وہ memory میں ایک ساتھ فٹ آتے ہوں تو کئی ایک ساتھ چل سکتے ہیں۔ کسی منتخب لائن پر Delete دبائیں تو ماڈل اس machine سے ہٹ جاتا ہے، download سمیت؛ + اسے دوبارہ سیٹ اپ کر سکتا ہے۔ terminal سے سیٹ اپ کیا گیا coding model + کے تحت اس وقت تک انتظار کرتا ہے جب تک آپ اسے شامل نہ کریں، اور اس machine کے models بھی جس کے ساتھ آپ نے pair کیا ہو (`omarchy models pair <host>`)۔

آپ کا سیٹ اپ کیا گیا ہر coding model app launcher میں بھی اپنی entry حاصل کرتا ہے، ماڈل کے نام کے تحت اور اس کے بنانے والے کے logo کے ساتھ، جس طرح Claude، Codex یا Grok میں sign in کرنا ایک entry شامل کرتا ہے۔ یہ اس ماڈل پر آپ کا ایجنٹ کھولتا ہے، اور اگر وہ نہ چل رہا ہو تو پہلے ماڈل شروع کرتا ہے: terminal اسے load ہوتے دکھاتا ہے اور تیار ہوتے ہی ایجنٹ کے سپرد کر دیتا ہے۔ ماڈل ہٹانا اس کی entry بھی ہٹا دیتا ہے۔

ہر ماڈل coding کے لیے نہیں ہوتا۔ Image، video اور music models اس کے بجائے Fantasi میں کھلتے ہیں، جو اس machine پر چلنے والے ماڈل کے ساتھ pictures، video اور music بنانے کے لیے Omarchy کی ایپ ہے، اور انہیں وہیں یا `omarchy models` کے ساتھ manage کیا جاتا ہے۔

کوئی ماڈل بالکل ویسا ہی چلتا رہتا ہے جیسا اسے سیٹ اپ کیا گیا تھا، اس لیے Omarchy update کبھی آپ کے ایجنٹس کے نیچے کسی کو دوبارہ شروع نہیں کرتا۔ جب Omarchy کے پاس آپ کے سیٹ اپ کیے گئے ماڈل کے لیے نیا runtime یا نئے weights ہوں، تو اس کی لائن update بٹن دکھاتی ہے: اسے دبائیں تو ماڈل پس منظر میں دوبارہ سیٹ اپ ہو جاتا ہے، صرف وہی download کرتے ہوئے جو بدلا ہو، اور نئے version پر دوبارہ شروع ہو جاتا ہے۔ جو ماڈل رکا ہوا تھا وہ رکا ہی رہتا ہے۔ `omarchy models update` terminal سے ہر ماڈل کے لیے یہی کرتا ہے۔

command line سے، `omarchy models start <recipe>` اور `omarchy models stop <recipe>` یہی کرتے ہیں، `omarchy models status` ہر ماڈل دکھاتا ہے، اور `omarchy agent --local-model <recipe>` اس ماڈل کو pi میں کھولتا ہے، خواہ آپ کا ڈیفالٹ ایجنٹ کوئی بھی ہو۔ اپنے مقامی ماڈل کو وہ بنانے کے لیے جو agent hotkey، Quake console اور _Make something_ کھولتے ہیں، `omarchy default agent local` چلائیں یا ایجنٹس پینل میں چلتے ہوئے ماڈل کو ستارے سے نشان زد کریں۔ pi اپنے model picker میں آپ کے سیٹ اپ کیے گئے ہر ماڈل، اور جن machines کے ساتھ آپ نے pair کیا ہو ان پر موجود models کو بھی فہرست کرتا ہے، اس لیے سادہ `pi` بھی ان تک پہنچتا ہے۔ کوئی بھی OpenAI-compatible client بھی connect ہو سکتا ہے: `status` ہر ماڈل کا address دکھاتا ہے (پہلا `http://127.0.0.1:11435/v1` ہے)، recipe کا نام ہی ماڈل ہے، اور key `~/.config/omarchy/agent-local/key` میں ہے۔

`omarchy models remove <recipe>` کسی ماڈل اور ان downloads کو delete کر دیتا ہے جنہیں کوئی دوسرا ماڈل استعمال نہ کرتا ہو۔

Third-party runtimes پر ان کے publisher کا label ہوتا ہے۔ Omarchy ہر ماڈل کو بغیر network access کے چلاتا ہے۔

### مقامی LLMs

Omarchy مقامی LLM models چلانے کے دو طریقے تجویز کرتا ہے: LM Studio اور Ollama۔ LM Studio open-weight models تلاش کرنے، انہیں انسٹال کرنے اور انہیں چلانے کے لیے GUI interface فراہم کرتا ہے۔ آسانی سے شروع کرنے کا یہ بہترین طریقہ ہے۔ Ollama اسی طرح کرنے کے لیے CLI پیش کرتا ہے۔ لیکن اگر آپ مقامی models میں نئے ہیں تو میں LM Studio سے شروع کروں گا۔ LM Studio کو _Install > AI > Desktop_ سے اور Ollama کو Omarchy Menu میں _Install > AI > CLI_ سے انسٹال کریں۔

### Omarchy کی skills

Agent skills AI کو مخصوص tools کو مخصوص طریقے سے استعمال کرنے میں مدد دیتی ہیں، اور Omarchy ان میں سے سات فراہم کرتا ہے۔ omarchy skill سسٹم کو اپنی پسند کے مطابق ڈھالنے کا احاطہ کرتی ہے، جیسے اپنی Hyprland config میں ردوبدل کرنا یا bar کو adjust کرنا۔ omarchy-make-theme، omarchy-make-plugin، omarchy-make-app اور omarchy-make-game کچھ نیا بنانے کا احاطہ کرتی ہیں، omarchy-contribute کسی bug کی رپورٹ کرنے یا upstream fix بھیجنے کا احاطہ کرتی ہے، اور omarchy-diagnose-crash کسی crash کے core dump پر کام کرتی ہے۔ یہ Claude Code (`~/.claude/skills`)، Codex (`~/.codex/skills`)، Pi (`~/.pi/agent/skills`)، Antigravity (`~/.gemini/config/skills`)، Hermes (`~/.hermes/skills` اور ہر `~/.hermes/profiles/*/skills`) اور عمومی `~/.agents/skills` مقام کے لیے skill directories میں symlink کی گئی ہیں، اس لیے زیادہ تر harnesses انہیں خودکار طور پر اٹھا لیتے ہیں۔ اسی نام کا آپ کا اپنا skill folder فوقیت رکھتا ہے۔

لیکن آپ کو ان skills کو تجرباتی سمجھنا چاہیے۔ مختلف models اسے مختلف اثر کے ساتھ استعمال کریں گے۔ بہتر ہے کہ پہلے plan mode میں چلائیں، تاکہ آپ کو اندازہ ہو کہ ایجنٹ کیا بدلنا چاہے گا۔ اور پھر تبدیلیاں rollback کرنے یا یہاں تک کہ `omarchy reinstall configs` چلانے کے لیے بھی تیار رہیں، اگر ایجنٹ ہر چیز کا ستیاناس کر دے۔
