### ایجنٹس کو نصب اور اپ ڈیٹ کرنا

Hermes کے سوا، یہ ایجنٹس mise کی سست تنصیب استعمال کرتے ہیں: پہلی بار شروع کرنے پر CLI نصب ہوتا ہے، اور بعد کے آغاز اسی کو دوبارہ استعمال کرتے ہیں۔ mise نصب شدہ ایجنٹ کے لیے نئی ریلیز کی جانچ بھی زیادہ سے زیادہ ہر چار گھنٹے میں ایک بار کرتا ہے، شروع ہونے سے عین پہلے یا shell prompt پر پس منظر میں۔ اگر وہ اپ ڈیٹ ناکام ہو جائے یا آپ آف لائن ہوں، تو نصب شدہ ورژن چلتا ہے۔ `omarchy update` نصب شدہ ایجنٹس کو باقی Omarchy کے ساتھ اپ ڈیٹ کرتا ہے، اور `mup` صرف mise کے زیر انتظام tools کو اپ ڈیٹ کرتا ہے۔

کسی ایجنٹ کا اپنا اپڈیٹر، جیسے `claude update`، `codex update`، یا کسی ایپ میں اپ ڈیٹ کا بٹن، mise کے زیر انتظام تنصیب کو اپ ڈیٹ نہیں کرتا۔ `codex update` ناکام ہو جاتا ہے، اور `claude update` کامیابی کی اطلاع دیتے ہوئے ایک الگ نقل نصب کر سکتا ہے جسے mise ٹریک نہیں کرتا۔ اگر آپ اس کے بجائے کسی ایجنٹ کا اپنا انسٹالر اور اپڈیٹر استعمال کرنا چاہیں، تو اسے `disable_tools` میں شامل کریں؛ [پہلے سے نصب CLI tools](18-development-tools.md#preinstalled-cli-tools) دیکھیں۔

تمام تشکیل شدہ سست tools کو ضرورت پڑنے سے پہلے نصب کرنے کے لیے `mise install --include-lazy` چلائیں۔ اس میں ایجنٹس کے ساتھ ساتھ Omarchy کے دیگر ڈیفالٹ CLI tools بھی شامل ہیں۔ کسی ایک tool کو نصب کرنے یا اپنی تنصیب استعمال کرنے کے لیے [پہلے سے نصب CLI tools](18-development-tools.md#preinstalled-cli-tools) دیکھیں۔

`grok` کو mise کے فرسٹ پارٹی `grok` package کے ذریعے نصب کیا جاتا ہے، بالکل اسی طرح جیسے `claude` اور `codex` کو۔ `grok` چلائیں، یا اسے _Setup > Defaults > Agent_ کے تحت منتخب کریں۔ x.ai پر موجود `curl | bash` انسٹالر کو چھوڑ دیں۔ وہ راستہ `~/.grok/bin` میں دوسری نقل رکھتا ہے، اسے `PATH` کے آغاز میں شامل کرتا ہے، اور Omarchy کے wrapper کو اوور رائٹ کر دیتا ہے۔

`dsh` اپنا براؤزر UI `127.0.0.1:3080` پر کھولتا ہے، جس میں آغاز کی ڈائریکٹری اس کی ڈیفالٹ workspace ہوتی ہے۔ اس کا براؤزر UI کوئی ابتدائی prompt نہیں لیتا، لہٰذا `omarchy agent prompt` اسے آپ کے clipboard پر موجود prompt کے ساتھ کھولتا ہے تاکہ آپ اسے paste کر سکیں۔ Omarchy اسے DeepSeek کے بغیر منظوری والے permission preset کے ساتھ شروع کرتا ہے۔ جب آپ اس کا سرکاری ماڈل API استعمال کرتے ہیں تو DeepSeek Harness سیشن لاگز DeepSeek کو اپ لوڈ کرتا ہے؛ اسے اس کے براؤزر UI میں _Settings > General > Upload Session Log_ کے تحت بند کر دیں۔ آپ جو تاثرات اسے بھیجتے ہیں وہ بھی سیشن کے ساتھ اپ لوڈ ہوتے ہیں، الا یہ کہ آپ اسے `DSH_TELEMETRY_MODE=DISABLED` کے ساتھ شروع کریں۔

### ڈیفالٹ ایجنٹ

اپنا ڈیفالٹ ایجنٹ `omarchy default agent <name>` کے ساتھ یا Omarchy Menu (`Super + Space`) میں _Setup > Defaults > Agent_ کے تحت منتخب کریں۔ اگر ایجنٹ ابھی نصب نہیں ہے، تو اسے منتخب کرنے سے پہلے وہ نصب ہو جاتا ہے۔ تازہ Omarchy ایک بار کی اطلاع کے ساتھ آپ کو یہ انتخاب کرنے کی دعوت دے گا۔

Claude کو منتخب کرنے سے Chromium، Chrome، Brave، Brave Origin، اور Edge کے لیے اس کی براؤزر توسیع ترتیب دینے کی بھی کوشش ہوتی ہے۔ توسیع کی ترتیب تمام صارفین پر لاگو ہوتی ہے اور آپ سے آپ کا سسٹم پاس ورڈ مانگ سکتی ہے؛ منسوخ کرنے یا توسیع کی تنصیب ناکام ہونے پر بھی Claude منتخب اور شروع ہو جاتا ہے۔ اپنا براؤزر دوبارہ شروع کریں، اشارہ ملنے پر توسیع فعال کریں، اور اسے جوڑنا مکمل کرنے کے لیے Claude میں سائن ان کریں۔ کنکشن جانچنے کے لیے Claude میں `/chrome` چلائیں۔ Firefox اور Zen اس توسیع کی حمایت نہیں کرتے۔ اگر یہ ترتیب شامل کیے جانے سے پہلے ہی Claude آپ کا ڈیفالٹ تھا، تو توسیع نصب کرنے کے لیے اسے دوبارہ منتخب کریں۔

ایک بار انتخاب کر لینے کے بعد، `Super + Shift + Ctrl + A` ڈیفالٹ ایجنٹ کو ایک مخصوص ٹرمینل ونڈو میں شروع کرتا ہے (یا اگر آپ نے ابھی انتخاب نہیں کیا تو منتخب کنندہ سامنے لاتا ہے)۔ آپ اسے `omarchy agent prompt "Review this project"` کے ساتھ سیدھا کسی کام میں بھی شروع کر سکتے ہیں۔ Freebuff اور DeepSeek Harness کوئی ابتدائی prompt نہیں لیتے، لہٰذا وہ اس کے بجائے آپ کے clipboard پر موجود prompt کے ساتھ کھلتے ہیں تاکہ آپ اسے paste کر سکیں۔ اس طرح شروع کیے گئے ایجنٹس اپنے متعلقہ رک کر نہ پوچھنے والے طریقوں میں بغیر نگرانی کے چلتے ہیں، لہٰذا تیار رہیں کہ وہ واقعی کچھ کریں گے! MiniMax Code کے پاس اس کے انٹرایکٹو سیشنز کے لیے ایسا کوئی طریقہ نہیں ہے، لہٰذا وہ معمول کے مطابق اجازتیں مانگتا ہے۔ اور چونکہ ایجنٹس آپ کی home ڈائریکٹری کے لیے اعتماد یاد رکھنے سے انکار کرتے ہیں، اس لیے `$HOME` سے آغاز اس کے بجائے `~/Work` میں ہوتا ہے۔

ٹرمینل شارٹ کٹس بھی ہیں: `a` ڈیفالٹ ایجنٹ کو موجودہ ٹرمینل میں ان لائن چلاتا ہے، جبکہ `c`، `cx`، اور `cy` OpenCode، Claude Code، اور Codex کو براہ راست شروع کرتے ہیں (دوبارہ، ان کے خودکار منظوری والے طریقوں میں)۔ تھیم کی تبدیلیاں ایجنٹس کے ساتھ بھی ہم آہنگ ہوتی ہیں: جب آپ Omarchy تھیم بدلتے ہیں تو Claude Code، Pi، OpenCode، اور Hermes (ایک بار جب Omarchy نے اسے نصب کر لیا ہو) سب ساتھ ساتھ چلتے ہیں۔

### ایجنٹس پینل

اوپری بار میں ایجنٹس کا آئیکن ہے۔ ایجنٹ ترتیب دینے سے پہلے، اس کا پینل آپ کو Claude، Codex، یا Grok میں سائن ان کرنے کے مراحل سے گزارتا ہے، اور پہلا والا آپ کا ڈیفالٹ ایجنٹ بن جاتا ہے۔ اس کے بعد، پینل ہر سبسکرپشن کو ایک صفحے پر رکھتا ہے: ہر ایجنٹ اور اکاؤنٹ اس کے منصوبے کے ساتھ، اس کی 5 گھنٹے کے سیشن اور ہفتہ وار حدود میں سے ہر ایک کے لیے ایک میٹر جس میں اس کے reset ہونے تک کا وقت بھی شامل ہے (درست فیصد کے لیے hover کریں)، یا باقی ماندہ پیشگی ادا شدہ بیلنس، ایک سطر کے نیچے جو ان سب میں آپ کے استعمال کردہ کا چکر لگاتی ہے، جیسے اس ہفتے کے tokens اور آپ کا سب سے زیادہ استعمال شدہ ماڈل۔ _Make something_ کے تحت یہ نئی تھیم، plugin، یا ایپ کے لیے ابتدائی prompts پیش کرتا ہے جو کام آپ کے ڈیفالٹ ایجنٹ کے حوالے کرتے ہیں۔ ایپس اسی طرح بنائی جاتی ہیں جیسے Omarchy کی اپنی Hype، Monologue، اور Omacut ہیں، C++ اور Qt Quick میں، omarchy-app ایجنٹ skill کی پیروی کرتے ہوئے، اور انہیں درکار compiler اور Qt کے اجزا نصب شدہ آتے ہیں۔ Claude Code، Codex، Grok، Kimi، Cursor اور اس کا Grok Bot الاؤنس، GitHub Copilot، Muse، Antigravity، Kimchi، اور Devin اپنی حدود کے ساتھ ابتدا سے ہی شامل ہیں، اور Hermes، Mistral Vibe، اور Qwen Code ایک بار جب آپ انہیں استعمال کر لیں تو اپنے سیشنز اور tokens دکھاتے ہیں۔ pi، omp، یا opencode کے ذریعے آپ جو فراہم کنندہ منصوبے اور keys استعمال کرتے ہیں وہ بھی ظاہر ہوتے ہیں: OpenCode Zen اور Go، Z.ai GLM Coding Plan، Ollama Cloud، MiniMax Token Plan، اور Synthetic اپنی حدود کے ساتھ؛ Fireworks، OpenRouter، اور DeepSeek اپنے پیشگی ادا شدہ بیلنس کے ساتھ؛ اور وہ ماڈلز جو آپ Local models کے تحت اپنے hardware پر چلاتے ہیں۔ ہر ایجنٹ کو ایک ہی بار شمار کیا جاتا ہے، اسی کے تحت جو اس کا بل دیتا ہے، چاہے آپ اسے کتنے ہی harnesses کے ذریعے چلائیں۔

پینل کے لیے بار آئیکن پر بائیں کلک کریں، اپنے ڈیفالٹ ایجنٹ کو شروع کرنے کے لیے دائیں کلک کریں۔ اس کے پیچھے موجود استعمال کے ریکارڈز ہر 15 منٹ میں `omarchy agent usage-update` کے ذریعے دوبارہ بنائے جاتے ہیں، اور پینل ایک ہم آہنگ فولڈر کے ذریعے آپ کی دیگر مشینوں سے استعمال کو ضم بھی کر سکتا ہے۔ مکمل ترتیبات کے لیے `$OMARCHY_PATH/shell/plugins/agents/` کے تحت README دیکھیں۔

### متعدد سبسکرپشنز

اگر آپ ایک سے زیادہ Claude، Codex، یا Grok منصوبوں کی ادائیگی کرتے ہیں — مثلاً ایک ذاتی Max اور ایک کام والا — تو Omarchy ان سب کو سائن ان رکھ سکتا ہے اور ان کے درمیان منتقل ہو سکتا ہے۔ ایجنٹس پینل میں + کے ساتھ سبسکرپشن شامل کریں، جو آپ کو وہیں اس کے مراحل سے گزارتا ہے، یا `omarchy agent account add claude Work` کے ساتھ (یا `codex`، یا `grok`)۔ اگر CLI موجود نہ ہو تو یہ اسے نصب کرتا ہے۔ کسی فراہم کنندہ کے لیے پہلا اکاؤنٹ آپ کے عام براؤزر کے ذریعے سائن ان ہوتا ہے، عین وہیں جہاں CLI ہمیشہ دیکھتا ہے۔ اس کے بعد ہر ایک نجی ونڈو کے ذریعے سائن ان ہوتا ہے، تاکہ جس اکاؤنٹ میں آپ کا براؤزر پہلے سے سائن ان ہے وہ غلطی سے نہ پکڑا جائے؛ وہاں اس اکاؤنٹ کے طور پر سائن ان کریں جسے آپ شامل کر رہے ہیں، اور پہلے سے کھلی ہوئی کوئی بھی نجی ونڈو پہلے بند کر دیں۔ اس کے لیے کبھی بھی CLI سے لاگ آؤٹ نہ ہوں: لاگ آؤٹ کرنے سے محفوظ شدہ سائن ان منسوخ ہو جاتا ہے، اور اس اکاؤنٹ کو دوبارہ شامل کرنا پڑے گا۔

اپنے سبسکرپشن لاگ انز کو SSH کے ذریعے کسی دوسری Omarchy مشین پر نقل کرنے کے لیے `omarchy agent account copy user@laptop` چلائیں۔ جب منزل پر کوئی نصب نہ ہو تو بھیجنے والا ایک عارضی وصول کنندہ فراہم کرتا ہے، لہٰذا پرانی Omarchy مشینیں بغیر اپ ڈیٹ کے اکاؤنٹس وصول کر سکتی ہیں۔ نصب شدہ وصول کنندگان کو ترجیح حاصل ہوتی ہے۔ یہ تمام Claude، Codex، اور Grok سبسکرپشنز نقل کرتا ہے؛ انہیں منتخب کرنے کے لیے فراہم کنندگان کے نام شامل کریں، جیسے `omarchy agent account copy laptop claude` میں۔ اکاؤنٹ نام اور کمانڈ IDs ماخذ سے مطابقت رکھتے ہیں، جن میں منزل پر پہلے سے موجود اکاؤنٹس بھی شامل ہیں۔ غیر متعلقہ منزل اکاؤنٹس کو اگر ان کے ناموں میں تصادم ہو تو عددی لاحقہ ملتا ہے، اور ترتیبات، skills، plugins، اور گفتگو کی تاریخ ہر مشین پر مقامی رہتی ہے۔

منزل کی موجودہ اسناد برقرار رکھی جاتی ہیں۔ کوئی ماخذ اکاؤنٹ جو وہاں پہلے سے سائن ان ہو، اس کا نام اس کی اسناد کو بدلے بغیر ہم آہنگ ہو جاتا ہے؛ دیگر اکاؤنٹس اس کے ساتھ شامل کر دیے جاتے ہیں۔ مطابقت رکھنے والے اکاؤنٹس کے لیے محفوظ شدہ اسناد کو بدلنے کے لیے، منزل پر اس اکاؤنٹ کے سیشنز بند کرنے کے بعد `omarchy agent account copy --replace laptop claude` استعمال کریں۔ تازہ منزل کو ماخذ کا فعال اکاؤنٹ اور تبدیلی کی ترجیحات بھی ملتی ہیں؛ قائم شدہ منزل اپنی ترجیحات برقرار رکھتی ہے۔

اسناد SSH کے ذریعے سفر کرتی ہیں اور منزل پر نجی فائلوں میں محفوظ ہوتی ہیں، لہٰذا صرف ان مشینوں پر نقل کریں جن پر آپ کو اعتماد ہو۔ یہ ایک بار کی نقل ہے، جاری ہم آہنگی نہیں۔ Codex کے refresh tokens کسی دوسری مشین کے ذریعے گھمائے جا سکتے ہیں، جس سے نقل شدہ لاگ ان کو تجدید کی ضرورت پڑ جاتی ہے؛ متعدد مشینوں پر بیک وقت استعمال کے لیے الگ الگ سائن ان سب سے قابل اعتماد انتخاب رہتے ہیں۔ [Codex کی اکاؤنٹ تصدیق کی رہنمائی](https://developers.openai.com/codex/auth/ci-cd-auth) دیکھیں۔

فی فراہم کنندہ ایک اکاؤنٹ فعال ہوتا ہے، اور ہر نیا سیشن اسی کے طور پر شروع ہوتا ہے: `cx`، `cy`، سادہ `claude`، `codex`، یا `grok`، `omarchy agent` کے ذریعے شروع کی گئی کوئی بھی چیز، اور وہ scripts یا editors جو CLI کو `PATH` پر پاتے ہیں۔ `omarchy agent account use work` کے ساتھ تبدیل کریں (اور `omarchy agent account use main` کے ساتھ واپس)، یا پینل میں کسی اکاؤنٹ کا نمبر دبا کر پھر `Enter` دبا کر (یا اس کے Use بٹن پر کلک کر کے)۔ جو سیشنز پہلے سے چل رہے ہیں وہ اسی اکاؤنٹ پر رہتے ہیں جس سے وہ شروع ہوئے تھے۔ گفتگو کی تاریخ، ترتیبات، skills، اور plugins اکاؤنٹس میں مشترکہ ہیں، لہٰذا اسی فولڈر میں `claude --continue` نئے اکاؤنٹ پر وہیں سے آگے بڑھتا ہے جہاں آپ نے چھوڑا تھا۔

ایک سے زیادہ اکاؤنٹ کے ساتھ، پینل ہر اکاؤنٹ کی حدود ساتھ ساتھ دکھاتا ہے، جس میں فعال اکاؤنٹ نمایاں ہوتا ہے۔ بطور ڈیفالٹ Omarchy آپ کو اطلاع دیتا ہے جب فعال اکاؤنٹ کسی حد کے 95% سے آگے بڑھ جائے، اور اطلاع پر کلک کرنے سے سب سے زیادہ گنجائش والے اکاؤنٹ پر منتقل ہو جاتا ہے۔ پینل میں کسی اکاؤنٹ کی سطر پر hover کریں اور Use کے ساتھ ظاہر ہونے والے Autoswitch پر کلک کریں (یا `m` دبائیں)، یا `omarchy agent account mode auto` چلائیں، تاکہ یہ خود بخود تبدیل ہو جائے؛ جب یہ فعال ہو، تو Autoswitch، Use کی جگہ لے لیتا ہے، اور اس پر دوبارہ کلک کرنے سے اطلاع دینے پر واپس آ جاتا ہے۔ حد تبدیل کرنے کے لیے کوئی نمبر شامل کریں، جیسے `omarchy agent account mode auto 90` میں۔ اگر ہر اکاؤنٹ حد سے اوپر ہو، تو آپ کو اس کے بارے میں ایک بار سنا دیا جائے گا، اس کے ساتھ کہ کون سا اکاؤنٹ سب سے پہلے خالی ہوتا ہے۔ جب کوئی فعال اکاؤنٹ اپنی حد کے 15 پوائنٹس کے اندر ہو (ڈیفالٹ پر 80%)، تو اس کی حدود ہر 15 کے بجائے ہر تین منٹ میں جانچی جاتی ہیں۔

`omarchy agent account list` ہر اکاؤنٹ اور اس کی تازہ ترین حدود دکھاتا ہے، `omarchy agent account remove work` کسی ایک کو بھلا دیتا ہے، اور `omarchy agent account rename primary Hey` کسی ایک کا نام بدل دیتا ہے (یا پینل میں کسی اکاؤنٹ کے نام پر کلک کریں)۔ یہ کمانڈز آپ کے ڈیفالٹ ایجنٹ کے اکاؤنٹس پر کام کرتی ہیں؛ دوسرے فراہم کنندہ تک پہنچنے کے لیے پہلے اس کا نام لیں، جیسے `omarchy agent account use codex side` میں۔ جو لاگ ان آپ کے پاس پہلے سے `~/.claude` یا `~/.codex` میں تھا وہ _Main_ اکاؤنٹ ہے اور وہیں رہتا ہے جہاں وہ ہے۔ تقریباً آٹھ گھنٹوں سے زیادہ غیر استعمال شدہ رہ جانے والا اکاؤنٹ _Sign-in required_ دکھا سکتا ہے؛ اس اکاؤنٹ کو پینل میں ہی دوبارہ سائن ان کرنے کے لیے اس پر کلک کریں، یا اس میں کوئی سیشن شروع کریں، جو سائن ان کو خود بخود تازہ کر دیتا ہے۔ جب کوئی اکاؤنٹ شامل کیا گیا تھا اس وقت آپ کے پاس موجود MCP servers اس کے ساتھ آ جاتے ہیں، لیکن جنہیں آپ بعد میں `claude mcp add` کے ساتھ شامل کرتے ہیں وہ صرف اسی اکاؤنٹ تک پہنچتے ہیں جس میں آپ نے انہیں شامل کیا تھا۔ Claude Desktop اور کسی CLI binary کے مطلق راستے کے ساتھ تشکیل شدہ tools اس تبدیلی کی پیروی نہیں کرتے۔ واضح `CLAUDE_CONFIG_DIR`، `CODEX_HOME`، یا `GROK_HOME` منتخب شدہ اکاؤنٹ پر فوقیت رکھتا ہے۔

### کریش کی تشخیص

Omarchy عمل کے کریشز کے لیے systemd-coredump کی نگرانی کرتا ہے۔ جب کوئی چیز segfault کرتی ہے، تو آپ کو "Process crashed" اطلاع ملے گی — اس پر کلک کریں، اور کریش آپ کے ڈیفالٹ ایجنٹ کے حوالے کر دیا جاتا ہے Omarchy کی diagnose-crash skill کے ساتھ، جو ایجنٹ کو core dump سے حقائق قائم کرنے اور یہ فیصلہ کرنے کے مراحل سے گزارتی ہے کہ آیا کریش upstream کو رپورٹ کرنے کے قابل ہے۔ آپ اسے `coredumpctl list` سے کسی بھی PID کے خلاف `omarchy agent crash <pid>` کے ساتھ دستی طور پر بھی چلا سکتے ہیں۔

نگرانی بطور ڈیفالٹ فعال ہے۔ اسے _Trigger > Toggle > Crash Capture_ کے تحت (یا `omarchy toggle crash-capture` کے ساتھ) بند کر دیں اور اطلاعات رک جاتی ہیں؛ `omarchy agent crash <pid>` دستی طور پر پھر بھی کام کرتا ہے۔

کریشز کو ایک وقت میں ایک پروگرام کے حساب سے خاموش بھی کیا جا سکتا ہے، جو تشخیص اختتام پر آپ کو پیش کرتی ہے۔ `omarchy crash mute hyprland` صرف اس پروگرام کے لیے اطلاعات روکتا ہے، `omarchy crash mute hyprland off` انہیں واپس لاتا ہے، اور اکیلا `omarchy crash mute` وہ فہرست دکھاتا ہے جو آپ نے خاموش کی ہے۔ یہ binary کا راستہ اتنی ہی خوشی سے لیتا ہے جتنا اس کا نام، لہٰذا `omarchy crash mute /usr/bin/hyprland` بھی وہی کام کرتا ہے۔ جس نام میں جگہ ہو اسے اقتباس میں لکھیں، جیسے `omarchy crash mute 'Some App'` میں۔ باقی سب کچھ پھر بھی اطلاع دیتا ہے، اور خاموش کیا گیا پروگرام پھر بھی کریش ہوتا ہے — یہ یاد دہانی چھپاتا ہے، کچھ ٹھیک نہیں کرتا۔

### ڈیسک ٹاپ ایپس

_Install > AI_ مینو میں چند گرافیکل AI ایپس بھی ہیں: ChatGPT ڈیسک ٹاپ ایپ، Claude ڈیسک ٹاپ ایپ (Anthropic کا Linux beta، Chat، Cowork، اور Claude Code ٹیبز کے ساتھ)، xAI کے ماڈلز کے ساتھ گفتگو کے لیے Grok Bot، Hermes Desktop، OpenClaw، Perplexity ڈیسک ٹاپ ایپ، اور T3 Code۔ Grok Bot ڈیسک ٹاپ چیٹ ایپ ہے۔ کوڈنگ ایجنٹ `grok` کمانڈ ہے۔

Hermes Desktop وہ ہے جس کے بارے میں جاننا ضروری ہے، کیونکہ کسی مشین پر ایک ہی Hermes ہوتا ہے، اور وہ ایپ کا ہوتا ہے: Hermes ہمیشہ صرف ایپ کے ذریعے نصب ہوتا ہے، اور جو `hermes` کمانڈ ڈیفالٹ ایجنٹ چلاتا ہے وہ ایپ کی ہوتی ہے۔ Hermes کو ڈیفالٹ ایجنٹ کے طور پر منتخب کرنا وہی چیز نصب کرتا ہے جو _Install > AI_ اندراج کرتا ہے: package، اور `~/.hermes` کے تحت ایک Hermes runtime جو Hermes کے اپنے انسٹالر کے ذریعے ترتیب دیا گیا ہو، جس میں پہلی بار چند منٹ لگتے ہیں۔ وہ runtime وہی ایک Hermes ہے جسے ٹرمینل کی `hermes` کمانڈ، ڈیفالٹ ایجنٹ اور ایپ سب استعمال کرتے ہیں، اور یہ Omarchy ریلیز کا انتظار کرنے کے بجائے `hermes update` کے ساتھ خود کو اپ ڈیٹ کرتا ہے۔ اسے نصب کرنے سے Hermes کو Omarchy تھیم بطور skin بھی ملتا ہے جس کا نام `omarchy` ہے، جس کی پیروی Hermes کی ہر سطح آپ کے تھیمز بدلنے کے ساتھ کرتی ہے؛ اگر آپ نہ چاہیں تو Hermes کی Appearance ترتیبات کے تحت یا `/skin` کے ساتھ کوئی اور منتخب کریں، اور Omarchy اس انتخاب کو چھوڑ دیتا ہے۔ _Remove > AI_ کے تحت ایپ کو ہٹانے سے پہلے Hermes بند ہوتا ہے، gateway سمیت، وہ runtime اس کے ساتھ لے جاتا ہے، اور آپ کی چیٹس، یادیں، اور وہ skills جو Hermes نے اپنے لیے لکھی تھیں برقرار رکھتا ہے الا یہ کہ آپ اسے دوسری صورت کہیں: یہ پوچھتا ہے، جس کا ڈیفالٹ انکار ہے، کہ آیا وہ ڈیٹا اور آپ کی کنکشن ترتیبات بھی جانی چاہئیں۔

OpenClaw کا ڈیسک ٹاپ تجربہ اس کا Control UI ہے، جو اپنے مقامی gateway کی پشت پناہی سے ایک ویب ایپ کے طور پر کھلتا ہے۔ OpenClaw `~/.openclaw` میں رہتا ہے اور خود کو اپ ڈیٹ کرتا ہے: Control UI کا "Update Gateway" بٹن استعمال کریں یا `openclaw update` چلائیں، اور gateway نئے ورژن پر دوبارہ شروع ہو جاتا ہے۔ Omarchy صرف وہ ریلیز منتخب کرتا ہے جس سے تازہ تنصیب شروع ہوتی ہے۔ _Remove > AI_ کے تحت OpenClaw کو ہٹانے سے gateway سروس اور ایپ اس کے ساتھ جاتی ہے اور پھر پوچھا جاتا ہے کہ آیا `~/.openclaw` بھی جانا چاہیے، کیونکہ اس میں آپ کی چیٹس اور اسناد OpenClaw کے ساتھ ساتھ اور اس کے ڈاؤن لوڈ کردہ plugin runtimes بھی ہوتے ہیں؛ ڈیفالٹ اسے برقرار رکھتا ہے، اور OpenClaw کو دوبارہ نصب کرنے سے یہ اسے واپس اٹھا لیتا ہے۔

T3 Code اپنے سرکاری AppImage ریلیز سے `~/.local/share/t3code` میں چلتا ہے نہ کہ کسی package سے، لہٰذا یہ خود کو اپ ڈیٹ کرتا ہے۔ اسے نصب کرنے پر پوچھا جاتا ہے کہ آیا Stable یا Nightly چینل پر آغاز کرنا ہے؛ بعد میں T3 Code کی ترتیبات میں تبدیل کریں۔ آپ کے تھریڈز اور ترتیبات `~/.t3` میں رہتے ہیں، اور _Remove > AI_ کے تحت T3 Code کو ہٹانے سے وہ اس کے ساتھ جاتے ہیں۔

### لوکل ماڈلز

اپنے کوڈنگ ایجنٹس کے لیے اپنی مشین پر کوئی کھلا ماڈل چلائیں۔ آپ کے prompts اور کوڈ مشین پر ہی رہتے ہیں؛ ماڈل کو بھیجی گئی کوئی چیز اس سے باہر نہیں جاتی۔ اس سے آغاز کریں:

```bash
omarchy agent local use best
```

یا، اوپری بار کے ایجنٹس پینل میں، + اور پھر Local AI منتخب کریں، جو اس وقت ظاہر ہوتا ہے جب کوئی ماڈل اس مشین کے لیے موزوں ہو۔ پہلی بار، یہ Podman نصب کرتا ہے، جو ماڈلز چلاتا ہے۔ پھر Omarchy اس مشین کے لیے تجویز کردہ ماڈل منتخب کرتا ہے، اسے ڈاؤن لوڈ کرتا ہے، اور اسے شروع کرتا ہے۔ دسیوں GB کے ڈاؤن لوڈ کی توقع رکھیں اور ماڈل چلنے کے دوران مشین کی زیادہ تر میموری استعمال میں رہے گی: Flash Next اپنے مکمل 256K context کے ساتھ تقریباً 100 GiB استعمال کرتا ہے۔ اگر دیگر ماڈلز اسے درکار میموری پر قابض ہوں، تو یہ رکا ہوا ترتیب دیا جاتا ہے، ایک بار جب آپ کسی ایک کو روکیں تو شروع ہونے کے لیے تیار۔ ماڈل لاگ آؤٹ پر رک جاتا ہے؛ جب آپ کو کسی اور چیز کے لیے میموری درکار ہو تو اسے خود روک دیں۔

`omarchy agent local list` اختیارات دکھاتا ہے اور بتاتا ہے کہ کچھ کیوں موزوں نہیں ہیں۔ کوئی اور ترتیب دینے کے لیے `omarchy agent local use <recipe>` چلائیں۔ آج، 128 GB Strix Halo مشینوں کے لیے `qwen3.8-flash-next-halogen` اور `qwen3.8-27b-gufo` دستیاب ہیں۔ نئی recipes اور تجاویز `omarchy update` کے ساتھ، package کے ذریعے آتی ہیں۔

آپ جو بھی ماڈل ترتیب دیتے ہیں اسے ایجنٹس پینل میں، آپ کی سبسکرپشنز کے ساتھ، اپنی سطر ملتی ہے: اسے شروع کرنے کے لیے play، اسے روکنے اور اس کی میموری خالی کرنے کے لیے pause، اور اس پر اپنا ایجنٹ کھولنے کے لیے ٹرمینل بٹن۔ جب وہ میموری میں ایک ساتھ سما جائیں تو متعدد ایک ساتھ چل سکتے ہیں؛ اگر کوئی ایک نہ سمائے، تو Omarchy بتاتا ہے کہ کون سا چلتا ہوا ماڈل روکنا ہے۔ سطروں کو دوبارہ ترتیب دینے کے لیے انہیں گھسیٹیں، اور منتخب سطر پر Delete دبا کر ماڈل اور اس کا ڈاؤن لوڈ ہٹا دیں۔

کمانڈ لائن سے، `omarchy agent local start <recipe>` اور `omarchy agent local stop <recipe>` بھی وہی کرتے ہیں، `omarchy agent local status` ہر ماڈل دکھاتا ہے، اور `omarchy agent --local` آپ کے ڈیفالٹ ایجنٹ کو آخری شروع کیے گئے ماڈل پر کھولتا ہے (pi اگر آپ کا ڈیفالٹ ایجنٹ لوکل ماڈل استعمال نہ کر سکے)۔ کوئی بھی OpenAI سے مطابقت رکھنے والا client بھی جڑ سکتا ہے: `status` ہر ماڈل کا پتہ دکھاتا ہے (پہلا `http://127.0.0.1:11435/v1` ہے)، recipe کا نام ہی ماڈل ہے، اور key `~/.config/omarchy/agent-local/key` میں ہے۔

`omarchy agent local remove <recipe>` کسی ماڈل اور وہ ڈاؤن لوڈز حذف کرتا ہے جنہیں کوئی اور ماڈل استعمال نہیں کرتا۔

تیسرے فریق کے runtimes پر ان کے ناشر کا لیبل لگا ہوتا ہے۔ Omarchy ہر ماڈل کو بغیر نیٹ ورک رسائی کے چلاتا ہے۔

### لوکل LLMs

Omarchy لوکل LLM ماڈلز چلانے کے دو طریقے تجویز کرتا ہے: LM Studio اور Ollama۔ LM Studio کھلے وزن والے ماڈلز تلاش کرنے، انہیں نصب کرنے، اور انہیں چلانے کے لیے GUI انٹرفیس فراہم کرتا ہے۔ یہ آسانی سے آغاز کرنے کا بہترین طریقہ ہے۔ Ollama اسی طرح کرنے کے لیے CLI پیش کرتا ہے۔ لیکن اگر آپ لوکل ماڈلز میں نئے ہیں، تو میں LM Studio سے آغاز کروں گا۔ آپ Omarchy Menu میں _Install > AI_ کے تحت دونوں میں سے کوئی ایک نصب کر سکتے ہیں۔

### Omarchy Skill

ایجنٹ skills AI کو مخصوص tools کو مخصوص طریقے سے استعمال کرنے میں مدد دیتی ہیں، اور Omarchy سسٹم کو اپنی مرضی کے مطابق بنانے کے لیے ایک ڈیفالٹ skill کے ساتھ آتا ہے۔ جیسے اپنی Hyprland config میں ردوبدل کرنا، بار کو ایڈجسٹ کرنا، یا حتیٰ کہ ابتدا سے نئی تھیم بنانا۔ یہ Claude Code (`~/.claude/skills`)، Codex (`~/.codex/skills`)، Pi (`~/.pi/agent/skills`)، Antigravity (`~/.gemini/config/skills`)، Hermes (`~/.hermes/skills` اور ہر `~/.hermes/profiles/*/skills`)، اور عمومی `~/.agents/skills` مقام کے لیے skill ڈائریکٹریوں میں symlinked ہے، لہٰذا زیادہ تر harnesses اسے خود بخود اٹھا لیتے ہیں۔

لیکن آپ کو اس skill کو تجرباتی سمجھنا چاہیے۔ مختلف ماڈلز اسے مختلف اثر کے ساتھ استعمال کریں گے۔ بہتر ہے کہ پہلے اسے plan mode میں چلائیں، تاکہ آپ کو اندازہ ہو کہ ایجنٹ کیا بدلنا چاہے گا۔ اور پھر تبدیلیاں واپس لینے یا حتیٰ کہ `omarchy reinstall configs` چلانے کے لیے تیار رہیں، اگر ایجنٹ ہر چیز کا ستیاناس کر دے۔
