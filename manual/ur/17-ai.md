### ایجنٹ انسٹال کرنا اور اپ ڈیٹ کرنا

Hermes کے علاوہ، یہ ایجنٹ mise کی لیزی انسٹالیشن استعمال کرتے ہیں: پہلی بار لانچ کرنے پر CLI انسٹال ہو جاتی ہے، اور بعد کے لانچ اسی کو دوبارہ استعمال کرتے ہیں۔ mise انسٹال شدہ ایجنٹ کے لیے نئی ریلیز کی جانچ بھی زیادہ سے زیادہ ہر چار گھنٹے میں ایک بار کرتا ہے، اس کے شروع ہونے سے عین پہلے یا پس منظر میں شیل پرامپٹ پر۔ اگر وہ اپ ڈیٹ ناکام ہو جائے یا آپ آف لائن ہوں، تو انسٹال شدہ ورژن چلتا ہے۔ `omarchy update` انسٹال شدہ ایجنٹس کو باقی Omarchy کے ساتھ اپ ڈیٹ کرتا ہے، اور `mup` صرف mise کے زیر انتظام ٹولز کو اپ ڈیٹ کرتا ہے۔

کسی ایجنٹ کا اپنا اپڈیٹر، جیسے `claude update`، `codex update`، یا کسی ایپ میں اپ ڈیٹ بٹن، mise کے زیر انتظام انسٹالیشن کو اپ ڈیٹ نہیں کرتا۔ `codex update` ناکام ہو جاتا ہے، اور `claude update` کامیابی کی اطلاع دے سکتا ہے جبکہ ایک الگ کاپی انسٹال کر رہا ہو جس کو mise ٹریک نہیں کرتا۔ اگر آپ اس کے بجائے کسی ایجنٹ کا اپنا انسٹالر اور اپڈیٹر استعمال کرنا چاہتے ہیں، تو اسے `disable_tools` میں شامل کریں؛ دیکھیں [پہلے سے انسٹال شدہ CLI ٹولز](18-development-tools.md#preinstalled-cli-tools)۔

تمام تشکیل شدہ لیزی ٹولز کو ضرورت پڑنے سے پہلے انسٹال کرنے کے لیے `mise install --include-lazy` چلائیں۔ اس میں ایجنٹس کے ساتھ ساتھ Omarchy کے دیگر ڈیفالٹ CLI ٹولز بھی شامل ہیں۔ ایک ٹول انسٹال کرنے یا اپنی انسٹالیشن استعمال کرنے کے لیے دیکھیں [پہلے سے انسٹال شدہ CLI ٹولز](18-development-tools.md#preinstalled-cli-tools)۔

`grok` mise کے فرسٹ پارٹی `grok` پیکیج کے ذریعے انسٹال ہوتا ہے، اسی طرح جیسے `claude` اور `codex`۔ `grok` چلائیں، یا اسے _Agent > Harness_ کے تحت منتخب کریں۔ x.ai پر موجود `curl | bash` انسٹالر کو چھوڑ دیں۔ وہ راستہ `~/.grok/bin` میں دوسری کاپی رکھتا ہے، اسے `PATH` کے شروع میں لگا دیتا ہے، اور Omarchy کے ریپر کو اوور رائٹ کر دیتا ہے۔

`dsh` اپنا براؤزر UI `127.0.0.1:3080` پر کھولتا ہے، جس میں لانچ ڈائریکٹری اس کی ڈیفالٹ ورک اسپیس ہوتی ہے۔ اس کا براؤزر UI کوئی ابتدائی پرامپٹ نہیں لیتا، لہٰذا `omarchy agent prompt` اسے آپ کے کلپ بورڈ پر موجود پرامپٹ کے ساتھ کھولتا ہے تاکہ آپ اسے پیسٹ کر سکیں۔ Omarchy اسے DeepSeek کے بغیر منظوری والے اجازت پری سیٹ کے ساتھ شروع کرتا ہے۔ جب آپ اس کا آفیشل ماڈل API استعمال کرتے ہیں تو DeepSeek Harness سیشن لاگز DeepSeek کو اپ لوڈ کرتا ہے؛ اسے اس کے براؤزر UI میں _Settings > General > Upload Session Log_ کے تحت بند کر دیں۔ آپ اسے جو تاثرات بھیجتے ہیں وہ بھی سیشن کے ساتھ اپ لوڈ ہو جاتے ہیں، الا یہ کہ آپ اسے `DSH_TELEMETRY_MODE=DISABLED` کے ساتھ شروع کریں۔

### ڈیفالٹ ایجنٹ

اپنا ڈیفالٹ ایجنٹ `omarchy default agent <name>` سے یا Omarchy Menu (`Super + Space`) میں _Agent > Harness_ کے تحت منتخب کریں۔ اگر ایجنٹ ابھی انسٹال نہیں ہوا، تو اسے منتخب کرنے سے پہلے وہ انسٹال ہو جاتا ہے۔ ایک نئی Omarchy آپ کو ایک بار کی اطلاع کے ذریعے یہ انتخاب کرنے کی دعوت دے گی۔

Claude منتخب کرنا Chromium، Chrome، Brave، Brave Origin، اور Edge کے لیے اس کی براؤزر ایکسٹینشن ترتیب دینے کی بھی کوشش کرتا ہے۔ ایکسٹینشن کی ترتیب تمام صارفین پر لاگو ہوتی ہے اور آپ سے آپ کا سسٹم پاس ورڈ مانگ سکتی ہے؛ منسوخ کرنے یا ایکسٹینشن کی انسٹالیشن ناکام ہونے پر بھی Claude منتخب اور لانچ ہو جاتا ہے۔ اپنا براؤزر دوبارہ شروع کریں، اشارہ ملنے پر ایکسٹینشن فعال کریں، اور اسے جوڑنا مکمل کرنے کے لیے Claude میں سائن ان کریں۔ کنکشن جانچنے کے لیے Claude میں `/chrome` چلائیں۔ Firefox اور Zen اس ایکسٹینشن کی حمایت نہیں کرتے۔ اگر یہ ترتیب شامل کیے جانے سے پہلے ہی Claude آپ کا ڈیفالٹ تھا، تو ایکسٹینشن انسٹال کرنے کے لیے اسے دوبارہ منتخب کریں۔

منتخب کرنے کے بعد، `Super + Shift + Ctrl + A` ڈیفالٹ ایجنٹ کو ایک مخصوص ٹرمینل ونڈو میں لانچ کرتا ہے (یا اگر آپ نے ابھی انتخاب نہیں کیا تو چننے والا سامنے لاتا ہے)۔ آپ اسے `omarchy agent prompt "Review this project"` کے ذریعے سیدھا کسی کام میں بھی لانچ کر سکتے ہیں۔ Freebuff اور DeepSeek Harness کوئی ابتدائی پرامپٹ نہیں لیتے، لہٰذا وہ اس کے بجائے آپ کے کلپ بورڈ پر موجود پرامپٹ کے ساتھ کھلتے ہیں تاکہ آپ اسے پیسٹ کر سکیں۔ اس طرح لانچ کیے گئے ایجنٹ اپنے متعلقہ پوچھنے کے لیے نہ رکنے والے موڈز میں بغیر نگرانی کے چلتے ہیں، لہٰذا اس کے لیے تیار رہیں کہ وہ واقعی کچھ کر گزریں گے! MiniMax Code کے انٹرایکٹو سیشنز کے لیے ایسا کوئی موڈ نہیں ہے، لہٰذا وہ معمول کے مطابق اجازتیں مانگتا ہے۔ اور چونکہ ایجنٹ آپ کی ہوم ڈائریکٹری کے لیے اعتماد یاد رکھنے سے انکار کرتے ہیں، اس لیے `$HOME` سے لانچ اس کے بجائے `~/Work` میں شروع ہوتے ہیں۔

ٹرمینل شارٹ کٹ بھی ہیں: `a` ڈیفالٹ ایجنٹ کو موجودہ ٹرمینل میں ان لائن چلاتا ہے، جبکہ `c`، `cx`، اور `cy` OpenCode، Claude Code، اور Codex کو براہ راست شروع کرتے ہیں (ایک بار پھر ان کے خودکار منظوری والے موڈز میں)۔ تھیم کی تبدیلیاں بھی ایجنٹس کے ساتھ ہم آہنگ ہو جاتی ہیں: جب آپ Omarchy تھیم تبدیل کرتے ہیں تو Claude Code، Pi، OpenCode، اور Hermes (جب Omarchy نے اسے انسٹال کر لیا ہو) سب اس کے ساتھ چلتے ہیں۔

### آپ کی ایجنٹ ہدایات

ہر ایجنٹ کے لیے ذاتی اصول `~/.agents/AGENTS.md` میں جاتے ہیں، `~/.agents/skills` میں مشترکہ اسکلز کے برابر میں۔ اسے _Agent > Instructions_ کے تحت کھولیں، جو اسے ہر اس ہارنس میں بھی لنک کر دیتا ہے جو اپنی عالمی فائل رکھتا ہے: `~/.claude/CLAUDE.md`، `~/.codex/AGENTS.md`، `~/.pi/agent/AGENTS.md`، `~/.config/opencode/AGENTS.md`، Copilot کی `~/.copilot/copilot-instructions.md`، وغیرہ۔ Crush اور Amp `~/.config/AGENTS.md` لنک پڑھتے ہیں، جبکہ omp، Kimi، اور DeepSeek Harness براہ راست `~/.agents/AGENTS.md` پڑھتے ہیں۔ ڈیفالٹ ایجنٹ منتخب کرنے سے وہ بھی لنک ہو جاتا ہے۔ اگر آپ کے پاس پہلے سے کوئی ہدایات فائل تھی تو وہ مشترکہ فائل بن جاتی ہے بشرطیکہ ابھی کوئی موجود نہ ہو؛ بصورت دیگر اسے لنک کے برابر میں `.bak` کے طور پر رکھا جاتا ہے۔ ایک اور ایجنٹ انسٹال کرنے کے بعد دوبارہ لنک کرنے کے لیے `omarchy agent instructions` چلائیں۔

### ایجنٹس پینل

اوپر والی بار میں ایک ایجنٹس آئیکن ہے۔ کسی ایجنٹ کو ترتیب دینے سے پہلے، اس کا پینل آپ کو Claude، Codex، یا Grok میں سائن ان کرواتا ہے، اور ان میں سے پہلا آپ کا ڈیفالٹ ایجنٹ بن جاتا ہے۔ اس کے بعد، پینل ہر سبسکرپشن کو ایک صفحے پر رکھتا ہے: ہر ایجنٹ اور اکاؤنٹ اپنے پلان کے ساتھ، اس کی 5 گھنٹے کے سیشن اور ہفتہ وار حدود میں سے ہر ایک کے لیے ایک میٹر جس کے ساتھ اس کے ری سیٹ ہونے تک کا وقت ہو (درست فیصد کے لیے ہوور کریں)، یا باقی ماندہ پہلے سے ادا شدہ بیلنس، ایک سطر کے نیچے جو ان سب میں آپ کے استعمال کی چیزوں میں سے گھومتی رہتی ہے، جیسے اس ہفتے کے ٹوکنز اور آپ کا سب سے زیادہ استعمال شدہ ماڈل۔ _Make something_ کے تحت یہ نئی تھیم، پلگ ان، یا ایپ کے لیے ابتدائی پرامپٹ پیش کرتا ہے جو کام آپ کے ڈیفالٹ ایجنٹ کے حوالے کر دیتے ہیں۔ ایپس اسی طرح بنائی جاتی ہیں جیسے Omarchy کی اپنی Hype، Monologue، اور Omacut ہیں، C++ اور Qt Quick میں، omarchy-app ایجنٹ اسکل کی پیروی کرتے ہوئے، اور انہیں جن کمپائلر اور Qt حصوں کی ضرورت ہوتی ہے وہ انسٹال شدہ آتے ہیں۔ Claude Code، Codex، Grok، Kimi، Cursor اور اس کا Grok Bot الاؤنس، GitHub Copilot، Muse، Antigravity، Kimchi، اور Devin اپنی حدود کے ساتھ پہلے سے شامل ہیں، اور Hermes، Mistral Vibe، اور Qwen Code جب آپ انہیں استعمال کر لیتے ہیں تو اپنے سیشن اور ٹوکن دکھاتے ہیں۔ pi، omp، یا opencode کے ذریعے آپ جو پرووائیڈر پلان اور کیز استعمال کرتے ہیں وہ بھی ظاہر ہوتے ہیں: OpenCode Zen اور Go، Z.ai GLM Coding Plan، Ollama Cloud، MiniMax Token Plan، اور Synthetic اپنی حدود کے ساتھ؛ Fireworks، OpenRouter، اور DeepSeek اپنے پہلے سے ادا شدہ بیلنس کے ساتھ؛ اور وہ ماڈل جو آپ اپنے ہارڈویئر پر Local models کے تحت چلاتے ہیں۔ ہر ایجنٹ ایک بار گنا جاتا ہے، اس کے تحت جسے اس کا بل جاتا ہے، چاہے آپ اسے کتنے ہی ہارنسز کے ذریعے چلائیں۔

پینل کے لیے بار آئیکن پر بایاں کلک کریں، اپنے ڈیفالٹ ایجنٹ کو لانچ کرنے کے لیے دایاں کلک کریں۔ اس کے پیچھے موجود استعمال کے ریکارڈ ہر 15 منٹ بعد `omarchy agent usage-update` کے ذریعے دوبارہ بنائے جاتے ہیں، اور پینل ایک ہم آہنگ شدہ فولڈر کے ذریعے آپ کی دوسری مشینوں کے استعمال کو بھی ضم کر سکتا ہے۔ مکمل ترتیبات کے لیے `$OMARCHY_PATH/shell/plugins/agents/` کے تحت README دیکھیں۔

### متعدد سبسکرپشنز

اگر آپ ایک سے زیادہ Claude، Codex، یا Grok پلان کی ادائیگی کرتے ہیں — مثلاً ایک ذاتی Max اور ایک کام کا — تو Omarchy ان سب کو سائن ان رکھ سکتا ہے اور ان کے درمیان منتقل ہو سکتا ہے۔ ایجنٹس پینل میں + کے ذریعے سبسکرپشن شامل کریں، جو آپ کو وہیں اس سے گزارتا ہے، یا `omarchy agent account add claude Work` کے ذریعے (یا `codex`، یا `grok`)۔ اگر CLI غائب ہو تو یہ اسے انسٹال کر دیتا ہے۔ کسی پرووائیڈر کا پہلا اکاؤنٹ آپ کے عام براؤزر کے ذریعے سائن ان ہوتا ہے، عین وہیں جہاں CLI ہمیشہ دیکھتا ہے۔ اس کے بعد ہر ایک نجی ونڈو کے ذریعے سائن ان ہوتا ہے، تاکہ جس اکاؤنٹ میں آپ کا براؤزر پہلے سے سائن ان ہے وہ غلطی سے نہ پکڑا جائے؛ وہاں اس اکاؤنٹ کے طور پر سائن ان کریں جسے آپ شامل کر رہے ہیں، اور پہلے سے کھلی ہوئی کوئی بھی نجی ونڈو پہلے بند کر دیں۔ ایسا کرنے کے لیے CLI سے کبھی لاگ آؤٹ نہ کریں: لاگ آؤٹ کرنے سے محفوظ شدہ سائن ان منسوخ ہو جاتا ہے، اور اس اکاؤنٹ کو دوبارہ شامل کرنا پڑے گا۔

اپنے سبسکرپشن لاگ ان کو SSH کے ذریعے کسی دوسری Omarchy مشین پر کاپی کرنے کے لیے `omarchy agent account copy user@laptop` چلائیں۔ جب منزل پر کوئی انسٹال نہ ہو تو بھیجنے والا ایک عارضی وصول کنندہ فراہم کرتا ہے، تاکہ پرانی Omarchy مشینیں بغیر اپ ڈیٹ کے اکاؤنٹس وصول کر سکیں۔ انسٹال شدہ وصول کنندگان کو ترجیح حاصل ہے۔ یہ تمام Claude، Codex، اور Grok سبسکرپشنز کاپی کرتا ہے؛ انہیں منتخب کرنے کے لیے پرووائیڈر کے نام شامل کریں، جیسے `omarchy agent account copy laptop claude` میں ہے۔ اکاؤنٹ کے نام اور کمانڈ ID ماخذ سے میل کھاتے ہیں، ان اکاؤنٹس سمیت جو منزل پر پہلے سے موجود ہیں۔ غیر متعلقہ منزل اکاؤنٹس کو عددی لاحقہ ملتا ہے اگر ان کے نام آپس میں ٹکرائیں، اور ترتیبات، اسکلز، پلگ ان، اور گفتگو کی تاریخ ہر مشین پر مقامی رہتی ہے۔

منزل کی موجودہ اسناد برقرار رکھی جاتی ہیں۔ کوئی ماخذ اکاؤنٹ جو وہاں پہلے سے سائن ان ہو اس کا نام اس کی اسناد بدلے بغیر ہم آہنگ کر دیا جاتا ہے؛ دوسرے اکاؤنٹ اس کے ساتھ شامل کر دیے جاتے ہیں۔ میل کھاتے اکاؤنٹس کے لیے محفوظ شدہ اسناد بدلنے کے لیے، منزل پر اس اکاؤنٹ کے سیشن چھوڑنے کے بعد `omarchy agent account copy --replace laptop claude` استعمال کریں۔ ایک نئی منزل کو ماخذ کا فعال اکاؤنٹ اور سوئچنگ ترجیحات بھی ملتی ہیں؛ ایک قائم شدہ منزل اپنی برقرار رکھتی ہے۔

اسناد SSH کے ذریعے سفر کرتی ہیں اور منزل پر نجی فائلوں میں محفوظ ہوتی ہیں، لہٰذا صرف ان مشینوں پر کاپی کریں جن پر آپ اعتماد کرتے ہیں۔ یہ ایک بار کی کاپی ہے، جاری ہم آہنگی نہیں۔ Codex ریفریش ٹوکن کسی دوسری مشین کے ذریعے بدلے جا سکتے ہیں، جس سے کاپی شدہ لاگ ان کو تجدید کی ضرورت پڑ جاتی ہے؛ کئی مشینوں پر بیک وقت استعمال کے لیے الگ الگ سائن ان سب سے قابل اعتماد انتخاب رہتے ہیں۔ دیکھیں [Codex کی اکاؤنٹ تصدیق کی رہنمائی](https://developers.openai.com/codex/auth/ci-cd-auth)۔

فی پرووائیڈر ایک اکاؤنٹ فعال ہوتا ہے، اور ہر نیا سیشن اسی کے طور پر شروع ہوتا ہے: `cx`، `cy`، ایک سادہ `claude`، `codex`، یا `grok`، `omarchy agent` کے ذریعے لانچ کی گئی کوئی بھی چیز، اور اسکرپٹ یا ایڈیٹر جو CLI کو `PATH` پر پاتے ہیں۔ `omarchy agent account use work` سے سوئچ کریں (اور `omarchy agent account use main` سے واپس)، یا پینل میں کسی اکاؤنٹ کا نمبر دبا کر پھر `Enter` دبا کر (یا اس کے Use بٹن پر کلک کر کے)۔ جو سیشن پہلے سے چل رہے ہیں وہ اسی اکاؤنٹ پر رہتے ہیں جس سے وہ شروع ہوئے تھے۔ گفتگو کی تاریخ، ترتیبات، اسکلز، اور پلگ ان اکاؤنٹس کے درمیان مشترکہ ہیں، لہٰذا اسی فولڈر میں `claude --continue` وہیں سے اٹھاتا ہے جہاں آپ نے نئے اکاؤنٹ پر چھوڑا تھا۔

ایک سے زیادہ اکاؤنٹ کے ساتھ، پینل ہر اکاؤنٹ کی حدود ساتھ ساتھ دکھاتا ہے، فعال کو نشان زد کر کے۔ ڈیفالٹ طور پر Omarchy آپ کو مطلع کرتا ہے جب فعال اکاؤنٹ کسی حد کے 95% سے گزر جائے، اور اطلاع پر کلک کرنے سے سب سے زیادہ گنجائش والے اکاؤنٹ پر سوئچ ہو جاتا ہے۔ پینل میں کسی اکاؤنٹ کی سطر پر ہوور کریں اور Use کے برابر میں ظاہر ہونے والے Autoswitch پر کلک کریں (یا `m` دبائیں)، یا `omarchy agent account mode auto` چلائیں، تاکہ یہ اس کے بجائے خود سوئچ کرے؛ جب یہ آن ہو، تو Autoswitch Use کی جگہ لے لیتا ہے، اور اس پر دوبارہ کلک کرنے سے اطلاع دینے پر واپس چلا جاتا ہے۔ حد بدلنے کے لیے ایک نمبر شامل کریں، جیسے `omarchy agent account mode auto 90` میں ہے۔ اگر ہر اکاؤنٹ حد سے اوپر ہو، تو آپ کو اس کے بارے میں ایک بار سنایا جائے گا، اس کے ساتھ کہ کون سا اکاؤنٹ پہلے خالی ہوتا ہے۔ جب کوئی فعال اکاؤنٹ اپنی حد کے 15 پوائنٹس کے اندر ہو (ڈیفالٹ پر 80%)، تو اس کی حدود ہر 15 کے بجائے ہر تین منٹ بعد جانچی جاتی ہیں۔

`omarchy agent account list` ہر اکاؤنٹ اور اس کی تازہ ترین حدود دکھاتا ہے، `omarchy agent account remove work` ایک کو بھول جاتا ہے، اور `omarchy agent account rename primary Hey` ایک کا نام بدلتا ہے (یا پینل میں کسی اکاؤنٹ کے نام پر کلک کریں)۔ یہ کمانڈز آپ کے ڈیفالٹ ایجنٹ کے اکاؤنٹس پر کام کرتی ہیں؛ دوسرے پرووائیڈر تک پہنچنے کے لیے پہلے اس کا نام لیں، جیسے `omarchy agent account use codex side` میں ہے۔ `~/.claude` یا `~/.codex` میں آپ کے پاس پہلے سے موجود لاگ ان _Main_ اکاؤنٹ ہے اور وہیں رہتا ہے جہاں وہ ہے۔ تقریباً آٹھ گھنٹے سے زیادہ عرصے سے غیر استعمال شدہ چھوڑا گیا اکاؤنٹ _Sign-in required_ دکھا سکتا ہے؛ اس اکاؤنٹ کو پینل میں ہی دوبارہ سائن ان کرنے کے لیے اس پر کلک کریں، یا اس میں ایک سیشن شروع کریں، جو سائن ان کو خود تازہ کر دیتا ہے۔ جب کوئی اکاؤنٹ شامل کیا گیا تھا اس وقت آپ کے پاس موجود MCP سرور اس کے ساتھ آ جاتے ہیں، لیکن جنہیں آپ بعد میں `claude mcp add` سے شامل کرتے ہیں وہ صرف اسی اکاؤنٹ تک پہنچتے ہیں جس میں آپ نے انہیں شامل کیا تھا۔ Claude Desktop اور CLI بائنری کے مطلق راستے کے ساتھ تشکیل شدہ ٹولز سوئچ کی پیروی نہیں کرتے۔ ایک واضح `CLAUDE_CONFIG_DIR`، `CODEX_HOME`، یا `GROK_HOME` منتخب شدہ اکاؤنٹ پر فوقیت رکھتا ہے۔

### کریش کی تشخیص

Omarchy عمل کے کریشز کے لیے systemd-coredump پر نظر رکھتا ہے۔ جب کوئی چیز سیگ فالٹ کرتی ہے، تو آپ کو "Process crashed" اطلاع ملے گی — اس پر کلک کریں، اور کریش آپ کے ڈیفالٹ ایجنٹ کے حوالے کر دیا جاتا ہے Omarchy کی diagnose-crash اسکل کے ساتھ، جو ایجنٹ کو کور ڈمپ سے حقائق قائم کرنے اور یہ فیصلہ کرنے میں لے جاتی ہے کہ آیا کریش کی اطلاع اپ اسٹریم دینا مناسب ہے۔ آپ اسے `coredumpctl list` سے کسی بھی PID کے خلاف ہاتھ سے بھی `omarchy agent crash <pid>` کے ذریعے چلا سکتے ہیں۔

یہ نگرانی ڈیفالٹ طور پر آن ہے۔ اسے _Trigger > Toggle > Crash Capture_ کے تحت (یا `omarchy toggle crash-capture` کے ذریعے) بند کر دیں اور اطلاعات رک جاتی ہیں؛ `omarchy agent crash <pid>` ہاتھ سے پھر بھی کام کرتا ہے۔

کریشز کو ایک وقت میں ایک پروگرام کے حساب سے خاموش بھی کیا جا سکتا ہے، جو تشخیص آخر میں آپ کو پیش کرتی ہے۔ `omarchy crash mute hyprland` صرف اس پروگرام کے لیے اطلاعات روکتا ہے، `omarchy crash mute hyprland off` انہیں واپس لاتا ہے، اور اکیلا `omarchy crash mute` وہ فہرست دیتا ہے جو آپ نے خاموش کی ہے۔ یہ بائنری کا راستہ اس کے نام کی طرح خوشی سے لیتا ہے، لہٰذا `omarchy crash mute /usr/bin/hyprland` بھی وہی کام کرتا ہے۔ جس نام میں جگہ ہو اسے کوٹس میں رکھیں، جیسے `omarchy crash mute 'Some App'` میں ہے۔ باقی سب کچھ پھر بھی مطلع کرتا ہے، اور خاموش کیا گیا پروگرام پھر بھی کریش ہوتا ہے — یہ یاد دہانی چھپاتا ہے، یہ کچھ ٹھیک نہیں کرتا۔

### ڈیسک ٹاپ ایپس

_Install > AI_ مینو میں چند گرافیکل AI ایپس بھی ہیں: ChatGPT ڈیسک ٹاپ ایپ، Claude ڈیسک ٹاپ ایپ (Anthropic کا Linux بیٹا، Chat، Cowork، اور Claude Code ٹیبز کے ساتھ)، xAI کے ماڈلز سے چیٹ کے لیے Grok Bot، Herdr Desktop، Hermes Desktop، OpenClaw، Perplexity ڈیسک ٹاپ ایپ، اور T3 Code۔ Grok Bot ڈیسک ٹاپ چیٹ ایپ ہے۔ کوڈنگ ایجنٹ `grok` کمانڈ ہے۔

Hermes Desktop وہ ہے جس کے بارے میں جاننا ضروری ہے، کیونکہ ایک مشین میں ایک Hermes ہوتا ہے، اور وہ ایپ کا ہوتا ہے: Hermes ہمیشہ صرف ایپ کے ذریعے انسٹال ہوتا ہے، اور ڈیفالٹ ایجنٹ جو `hermes` کمانڈ چلاتا ہے وہ ایپ کی ہے۔ Hermes کو ڈیفالٹ ایجنٹ کے طور پر منتخب کرنا وہی چیز انسٹال کرتا ہے جو _Install > AI_ اندراج کرتا ہے: پیکیج، اور Hermes کے اپنے انسٹالر کے ذریعے ترتیب دیا گیا `~/.hermes` کے تحت ایک Hermes رن ٹائم، جس میں پہلی بار چند منٹ لگتے ہیں۔ وہ رن ٹائم وہی ایک Hermes ہے جسے ٹرمینل کی `hermes` کمانڈ، ڈیفالٹ ایجنٹ اور ایپ سب استعمال کرتے ہیں، اور یہ Omarchy ریلیز کا انتظار کرنے کے بجائے `hermes update` سے خود کو اپ ڈیٹ کرتا ہے۔ اسے انسٹال کرنے سے Hermes کو Omarchy تھیم بطور اسکن بھی ملتی ہے جس کا نام `omarchy` ہے، جس کی پیروی Hermes کی ہر سطح کرتی ہے جب آپ تھیمز بدلتے ہیں؛ اگر آپ چاہتے ہیں کہ ایسا نہ ہو تو Hermes کی Appearance ترتیبات کے تحت یا `/skin` کے ذریعے کوئی اور منتخب کریں، اور Omarchy اس انتخاب کو چھوڑ دیتا ہے۔ _Remove > AI_ کے تحت ایپ ہٹانے سے پہلے Hermes بند ہو جاتا ہے، گیٹ وے سمیت، وہ رن ٹائم اس کے ساتھ لے جاتا ہے، اور آپ کی چیٹس، یادیں، اور وہ اسکلز جو Hermes نے اپنے لیے لکھی تھیں برقرار رکھتا ہے الا یہ کہ آپ اسے دوسری صورت کہیں: یہ پوچھتا ہے، ڈیفالٹ نہیں کے ساتھ، آیا وہ ڈیٹا اور آپ کی کنکشن ترتیبات بھی جانی چاہئیں۔

OpenClaw کا ڈیسک ٹاپ تجربہ اس کا Control UI ہے، جو اپنے مقامی گیٹ وے کی پشت پناہی سے ایک ویب ایپ کے طور پر کھلتا ہے۔ OpenClaw `~/.openclaw` میں رہتا ہے اور خود کو اپ ڈیٹ کرتا ہے: Control UI کا "Update Gateway" بٹن استعمال کریں یا `openclaw update` چلائیں، اور گیٹ وے نئے ورژن پر دوبارہ شروع ہو جاتا ہے۔ Omarchy صرف وہ ریلیز منتخب کرتا ہے جس سے ایک نئی انسٹالیشن شروع ہوتی ہے۔ _Remove > AI_ کے تحت OpenClaw ہٹانے سے گیٹ وے سروس اور ایپ اس کے ساتھ جاتی ہے اور پھر پوچھتا ہے آیا `~/.openclaw` بھی جانا چاہیے، کیونکہ اس میں خود OpenClaw اور اس کے ڈاؤن لوڈ کردہ پلگ ان رن ٹائمز کے ساتھ آپ کی چیٹس اور اسناد موجود ہوتی ہیں؛ ڈیفالٹ اسے برقرار رکھتا ہے، اور OpenClaw دوبارہ انسٹال کرنے سے یہ اسے واپس اٹھا لیتا ہے۔

Herdr Desktop [Herdr](https://herdr.dev) ڈیسک ٹاپ ایپ ہے: ٹرمینلز اور کوڈنگ ایجنٹس کی جگہیں، ٹیبز، اور پینز جو ونڈو بند کرنے پر اس کے کور میں چلتے رہتے ہیں۔ یہ کسی پیکیج کے بجائے Herdr کے اپنے انسٹالر سے آتا ہے، لہٰذا یہ `~/.local/share/herdr-app` میں رہتا ہے، جب آپ کے پاس پہلے سے کوئی نہ ہو تو `~/.local/bin/herdr-core` میں اپنا کور ساتھ لاتا ہے، اور دونوں کو خود اپ ڈیٹ کرتا ہے۔ یہ اس `herdr` کمانڈ کے برابر میں بیٹھتا ہے جو Omarchy `Super + Ctrl + Return` پر فراہم کرتا ہے اسے بدلے بغیر، اور اس کمانڈ کی براہ راست کیز حاصل کرتا ہے: `Alt + Return` اور `Alt + Shift + Return` کسی پین کو نیچے یا دائیں تقسیم کرتے ہیں، `Alt + Escape` اسے بند کرتا ہے، `Ctrl + Alt + Arrow` پینز کے درمیان منتقل ہوتا ہے، `Alt + 1..9` اور `Alt + Left/Right` ٹیب منتخب کرتے ہیں، اور `Alt + Up/Down` جگہوں کے درمیان منتقل ہوتے ہیں۔ `Ctrl + 1..9` جگہ منتخب کرتا ہے اور `Alt + Shift + Up/Down` ایجنٹس میں سے گزرتا ہے۔ `Ctrl + Space` سابقہ کیز صرف ٹرمینل تک رہتی ہیں، کیونکہ ایپ کسی سلسلے کے لیے سادہ Ctrl کی کو تھام نہیں سکتی۔ Omarchy انہیں `~/.config/herdr-app/keys.json` میں لکھتا ہے، اور `omarchy-refresh-herdr-app` انہیں واپس رکھتا ہے۔ اسے انسٹال کرنے سے Herdr کی Omarchy تھیم منتخب ہوتی ہے، جو اس کے بعد آپ کی Omarchy تھیم کی پیروی کرتی ہے۔ Herdr ہلکے موڈ کے لیے ایک تھیم اور گہرے موڈ کے لیے ایک رکھتا ہے، لہٰذا گہری اور ہلکی Omarchy تھیم کے درمیان بدلنے کے بعد، دوسرے موڈ کے لیے Herdr کے تھیم چننے والے میں ایک بار پھر Omarchy منتخب کریں۔

T3 Code کسی پیکیج کے بجائے `~/.local/share/t3code` میں اپنی آفیشل AppImage ریلیز سے چلتا ہے، لہٰذا یہ خود کو اپ ڈیٹ کرتا ہے۔ اسے انسٹال کرنے پر پوچھا جاتا ہے آیا Stable یا Nightly چینل پر شروع کرنا ہے؛ بعد میں T3 Code کی ترتیبات میں بدل لیں۔ آپ کے تھریڈز اور ترتیبات `~/.t3` میں رہتی ہیں، اور _Remove > AI_ کے تحت T3 Code ہٹانے سے وہ اس کے ساتھ جاتی ہیں۔

### لوکل ماڈلز

اپنے کوڈنگ ایجنٹس کے لیے اپنی مشین پر ایک کھلا ماڈل چلائیں۔ آپ کے پرامپٹ اور کوڈ مشین پر رہتے ہیں؛ ماڈل کو بھیجی گئی کوئی چیز اس سے باہر نہیں جاتی۔ اس سے شروع کریں:

```bash
omarchy agent local use best
```

یا، اوپر والی بار کے ایجنٹس پینل میں، + اور پھر Local AI منتخب کریں، جو اس وقت ظاہر ہوتا ہے جب کوئی ماڈل اس مشین میں سما جائے۔ پہلی بار، یہ Podman انسٹال کرتا ہے، جو ماڈل چلاتا ہے، اور NVIDIA مشین پر NVIDIA کا کنٹینر ٹول کٹ، جو انہیں GPU فراہم کرتا ہے۔ پھر Omarchy اس مشین کے لیے تجویز کردہ ماڈل منتخب کرتا ہے، اسے ڈاؤن لوڈ کرتا ہے، اور شروع کرتا ہے۔ دسیوں GB کے ڈاؤن لوڈ کی توقع رکھیں اور جب ماڈل چل رہا ہو تو مشین کی زیادہ تر میموری استعمال میں ہو گی: Flash Next اپنے پورے 256K سیاق و سباق کے ساتھ تقریباً 100 GiB استعمال کرتا ہے۔ اگر دوسرے ماڈل اسے درکار میموری لیے ہوئے ہوں، تو یہ رکا ہوا ترتیب دیا جاتا ہے، جب آپ کسی ایک کو روکیں تو شروع ہونے کے لیے تیار۔ ماڈل لاگ آؤٹ پر رک جاتا ہے؛ جب آپ کو کسی اور کام کے لیے میموری درکار ہو تو اسے خود روک دیں۔

`omarchy agent local list` اختیارات دکھاتا ہے اور بتاتا ہے کہ کچھ کیوں نہیں سما سکتے۔ کوئی اور ترتیب دینے کے لیے `omarchy agent local use <recipe>` چلائیں۔ آج، 128 GB Strix Halo مشینوں کے لیے `qwen3.8-flash-next-gufo` اور `qwen3.8-27b-gufo` دستیاب ہیں؛ 27B تقریباً 40 GiB لیتا ہے، لہٰذا یہ دوسرے کام کے لیے جگہ چھوڑتا ہے۔ نئی ترکیبیں اور سفارشات پیکیج کے ذریعے `omarchy update` کے ساتھ آتی ہیں۔

آپ جو بھی ماڈل ترتیب دیتے ہیں اسے ایجنٹس پینل میں اپنی سطر ملتی ہے، آپ کی سبسکرپشنز کے برابر میں: اسے شروع کرنے کے لیے چلائیں، اسے روکنے اور اس کی میموری خالی کرنے کے لیے روکیں، اور اس پر اپنا ایجنٹ کھولنے کے لیے ٹرمینل بٹن۔ کئی ایک ساتھ چل سکتے ہیں جب وہ میموری میں ایک ساتھ سما جائیں؛ اگر کوئی نہ سمائے، تو Omarchy بتاتا ہے کہ کون سا چلتا ہوا ماڈل روکنا ہے۔ انہیں دوبارہ ترتیب دینے کے لیے سطریں گھسیٹیں، اور کسی ماڈل اور اس کے ڈاؤن لوڈ کو ہٹانے کے لیے منتخب سطر پر Delete دبائیں۔

کمانڈ لائن سے، `omarchy agent local start <recipe>` اور `omarchy agent local stop <recipe>` وہی کرتے ہیں، `omarchy agent local status` ہر ماڈل دکھاتا ہے، اور `omarchy agent --local` آپ کے ڈیفالٹ ایجنٹ کو آخری ماڈل پر کھولتا ہے جو آپ نے شروع کیا تھا۔ pi، OpenCode اور Qwen Code ایک استعمال کر سکتے ہیں؛ کسی اور ڈیفالٹ کے ساتھ یہ pi میں کھلتا ہے۔ pi ہر اس ماڈل کی فہرست بھی دیتا ہے جو آپ نے ترتیب دیا ہے، اور ان کی بھی جن مشینوں کے ساتھ آپ نے جوڑا بنایا ہے، اپنے ماڈل چننے والے میں، لہٰذا سادہ `pi` بھی ان تک پہنچتا ہے۔ کوئی بھی OpenAI سے ہم آہنگ کلائنٹ بھی جڑ سکتا ہے: `status` ہر ماڈل کا پتہ دکھاتا ہے (پہلا `http://127.0.0.1:11435/v1` ہے)، ترکیب کا نام ماڈل ہے، اور کی `~/.config/omarchy/agent-local/key` میں ہے۔

`omarchy agent local remove <recipe>` کسی ماڈل اور ان ڈاؤن لوڈز کو حذف کر دیتا ہے جنہیں کوئی اور ماڈل استعمال نہیں کرتا۔

تیسری پارٹی کے رن ٹائمز پر ان کے ناشر کا لیبل ہوتا ہے۔ Omarchy ہر ماڈل کو بغیر نیٹ ورک رسائی کے چلاتا ہے۔

### لوکل LLMs

Omarchy لوکل LLM ماڈل چلانے کے دو طریقے تجویز کرتا ہے: LM Studio اور Ollama۔ LM Studio کھلے وزن والے ماڈل تلاش کرنے، انہیں انسٹال کرنے، اور انہیں چلانے کے لیے GUI انٹرفیس فراہم کرتا ہے۔ آسانی سے شروع کرنے کا یہ ایک بہترین طریقہ ہے۔ Ollama اسی طرح کرنے کے لیے CLI پیش کرتا ہے۔ لیکن اگر آپ لوکل ماڈلز میں نئے ہیں، تو میں LM Studio سے آغاز کروں گا۔ آپ Omarchy Menu میں _Install > AI_ کے تحت دونوں میں سے کوئی بھی انسٹال کر سکتے ہیں۔

### Omarchy Skill

ایجنٹ اسکلز AI کو مخصوص ٹولز کو مخصوص طریقے سے استعمال کرنے میں مدد دیتی ہیں، اور Omarchy سسٹم کو اپنی مرضی کے مطابق بنانے کے لیے ایک ڈیفالٹ اسکل کے ساتھ آتا ہے۔ جیسے آپ کی Hyprland کنفگ میں تبدیلی کرنا، بار کو ایڈجسٹ کرنا، یا یہاں تک کہ شروع سے ایک نئی تھیم بنانا۔ یہ Claude Code (`~/.claude/skills`)، Codex (`~/.codex/skills`)، Pi (`~/.pi/agent/skills`)، Antigravity (`~/.gemini/config/skills`)، Hermes (`~/.hermes/skills` اور ہر `~/.hermes/profiles/*/skills`)، اور عام `~/.agents/skills` مقام کے لیے اسکل ڈائریکٹریوں میں سم لنک شدہ ہے، لہٰذا زیادہ تر ہارنس اسے خودکار طور پر اٹھا لیتے ہیں۔

لیکن آپ کو اس اسکل کو تجرباتی سمجھنا چاہیے۔ مختلف ماڈل اسے مختلف اثر کے ساتھ استعمال کریں گے۔ بہتر ہے کہ پہلے اسے پلان موڈ میں چلائیں، تاکہ آپ کو اندازہ ہو کہ ایجنٹ کیا بدلنا چاہے گا۔ اور پھر تبدیلیاں واپس لینے یا یہاں تک کہ `omarchy reinstall configs` چلانے کے لیے تیار رہیں، اگر ایجنٹ ہر چیز کا ستیاناس کر دے۔
