### Installing and updating agents

Hermes اور OpenClaw کے علاوہ، یہ ایجنٹس mise کی سست انسٹالیشن استعمال کرتے ہیں: پہلی بار لانچ کرنے پر CLI انسٹال ہوتا ہے، اور بعد کے لانچ اسی کو دوبارہ استعمال کرتے ہیں۔ mise انسٹال شدہ ایجنٹ کے لیے نئی ریلیز بھی چیک کرتا ہے، زیادہ سے زیادہ ہر چار گھنٹے میں ایک بار، شروع ہونے سے عین پہلے یا پس منظر میں شیل پرامپٹ پر۔ اگر وہ اپڈیٹ ناکام ہو جائے یا آپ آف لائن ہوں، تو انسٹال شدہ ورژن چلتا ہے۔ `omarchy update` بقیہ Omarchy کے ساتھ انسٹال شدہ ایجنٹس کو اپڈیٹ کرتا ہے، اور `mup` صرف mise کے زیر انتظام ٹولز کو اپڈیٹ کرتا ہے۔

کسی ایجنٹ کا اپنا اپڈیٹر، جیسے `claude update`، `codex update`، یا کسی ایپ میں اپڈیٹ بٹن، mise کے زیر انتظام انسٹال کو اپڈیٹ نہیں کرتا۔ `codex update` ناکام ہو جاتا ہے، اور `claude update` کامیابی کی اطلاع دے سکتا ہے جبکہ ایک الگ کاپی انسٹال کر رہا ہو جسے mise ٹریک نہیں کرتا۔ اگر آپ اس کے بجائے کسی ایجنٹ کا اپنا انسٹالر اور اپڈیٹر استعمال کرنا پسند کریں، تو اسے `disable_tools` میں شامل کریں؛ دیکھیں [پہلے سے انسٹال شدہ CLI ٹولز](18-development-tools.md#preinstalled-cli-tools)۔

ضرورت پڑنے سے پہلے تمام ترتیب شدہ سست ٹولز انسٹال کرنے کے لیے، `mise install --include-lazy` چلائیں۔ اس میں ایجنٹس کے ساتھ ساتھ Omarchy کے دیگر ڈیفالٹ CLI ٹولز بھی شامل ہیں۔ کسی ایک ٹول کو انسٹال کرنے یا اپنی انسٹالیشن استعمال کرنے کے لیے [پہلے سے انسٹال شدہ CLI ٹولز](18-development-tools.md#preinstalled-cli-tools) دیکھیں۔

`grok` mise کے فرسٹ پارٹی `grok` پیکیج کے ذریعے انسٹال ہوتا ہے، اسی طرح جیسے `claude` اور `codex`۔ `grok` چلائیں، یا اسے ایجنٹس پینل میں اسٹار کریں۔ x.ai پر `curl | bash` انسٹالر کو چھوڑ دیں۔ وہ راستہ `~/.grok/bin` میں دوسری کاپی رکھتا ہے، اسے `PATH` کے شروع میں شامل کرتا ہے، اور Omarchy کے ریپر کو اوور رائٹ کر دیتا ہے۔

`dsh` اپنا براؤزر UI `127.0.0.1:3080` پر کھولتا ہے، جس میں لانچ ڈائریکٹری اس کا ڈیفالٹ ورک اسپیس ہوتی ہے۔ اس کا براؤزر UI کوئی ابتدائی پرامپٹ نہیں لیتا، لہٰذا `omarchy agent prompt` اسے آپ کے کلپ بورڈ پر موجود پرامپٹ کے ساتھ کھولتا ہے تاکہ آپ اسے پیسٹ کر سکیں۔ Omarchy اسے DeepSeek کے بغیر منظوری والے اجازت پری سیٹ کے ساتھ شروع کرتا ہے۔ جب آپ اس کا آفیشل ماڈل API استعمال کرتے ہیں تو DeepSeek Harness سیشن لاگز DeepSeek کو اپ لوڈ کرتا ہے؛ اسے اس کے براؤزر UI میں _Settings > General > Upload Session Log_ کے تحت بند کر دیں۔ جو فیڈبیک آپ اسے بھیجتے ہیں وہ بھی سیشن کے ساتھ اپ لوڈ ہوتا ہے، الا یہ کہ آپ اسے `DSH_TELEMETRY_MODE=DISABLED` کے ساتھ شروع کریں۔

### The default agent

اپنا ڈیفالٹ ایجنٹ ایجنٹس پینل میں کسی ایجنٹ کے ساتھ والے اسٹار سے منتخب کریں، جو ڈیفالٹ پر بھرا ہوا ہوتا ہے، یا `omarchy default agent <name>` سے، جو وہاں لائن کے بغیر کسی بھی ہارنس کو بھی لیتا ہے۔ اگر ایجنٹ ابھی انسٹال نہیں ہوا، تو اسے منتخب کرنے پر پہلے وہ انسٹال ہوتا ہے، اور اسے ایپ لانچر میں Agent کے ساتھ ساتھ اپنا لانچر بھی مل جاتا ہے۔ نیا Omarchy آپ کو ایک بار کی اطلاع کے ذریعے ایک سیٹ اپ کرنے کی دعوت دیتا ہے، جو ایجنٹس پینل کھولتی ہے۔

Claude کو منتخب کرنے پر Chromium، Chrome، Brave، Brave Origin، اور Edge کے لیے اس کی براؤزر ایکسٹینشن سیٹ اپ کرنے کی بھی کوشش کی جاتی ہے۔ ایکسٹینشن سیٹ اپ تمام صارفین پر لاگو ہوتا ہے اور آپ سے آپ کا سسٹم پاس ورڈ مانگ سکتا ہے؛ منسوخ کرنے یا ایکسٹینشن انسٹال ناکام ہونے پر بھی Claude منتخب اور لانچ ہو جاتا ہے۔ اپنا براؤزر دوبارہ شروع کریں، اشارہ ملنے پر ایکسٹینشن فعال کریں، اور اسے جوڑنا مکمل کرنے کے لیے Claude میں سائن ان کریں۔ کنکشن چیک کرنے کے لیے Claude میں `/chrome` چلائیں۔ Firefox اور Zen اس ایکسٹینشن کی حمایت نہیں کرتے۔ اگر یہ سیٹ اپ شامل کیے جانے سے پہلے ہی Claude آپ کا ڈیفالٹ تھا، تو ایکسٹینشن انسٹال کرنے کے لیے اسے دوبارہ منتخب کریں۔

منتخب کر لینے کے بعد، `Super + Shift + Ctrl + A` ڈیفالٹ ایجنٹ کو ایک مخصوص ٹرمینل ونڈو میں لانچ کرتا ہے (یا اگر آپ نے ابھی تک کوئی منتخب نہیں کیا تو پکر سامنے لاتا ہے)۔ آپ اسے `omarchy agent prompt "Review this project"` کے ساتھ سیدھا کسی کام میں بھی لانچ کر سکتے ہیں۔ Freebuff اور DeepSeek Harness کوئی ابتدائی پرامپٹ نہیں لیتے، لہٰذا وہ اس کے بجائے آپ کے کلپ بورڈ پر موجود پرامپٹ کے ساتھ کھلتے ہیں تاکہ آپ اسے پیسٹ کر سکیں۔ اس طرح لانچ کیے گئے ایجنٹس اپنے متعلقہ رکنے اور پوچھنے کے بغیر والے موڈز میں بغیر نگرانی کے چلتے ہیں، لہٰذا تیار رہیں کہ وہ واقعی کچھ کریں گے! MiniMax Code کے انٹرایکٹو سیشنز کے لیے ایسا کوئی موڈ نہیں ہے، لہٰذا وہ معمول کے مطابق اجازتیں مانگتا ہے۔ اور چونکہ ایجنٹس آپ کی ہوم ڈائریکٹری کے لیے اعتماد یاد رکھنے سے انکار کرتے ہیں، اس لیے `$HOME` سے لانچ اس کے بجائے `~/Work` میں شروع ہوتے ہیں۔

ٹرمینل شارٹ کٹس بھی ہیں: `a` موجودہ ٹرمینل میں ڈیفالٹ ایجنٹ کو ان لائن چلاتا ہے، جبکہ `c`، `cx`، اور `cy` OpenCode، Claude Code، اور Codex کو براہ راست شروع کرتے ہیں (ایک بار پھر ان کے خودکار منظوری والے موڈز میں)۔ تھیم کی تبدیلیاں ایجنٹس کے ساتھ بھی ہم آہنگ ہوتی ہیں: جب آپ Omarchy تھیم تبدیل کرتے ہیں تو Claude Code، Pi، OpenCode، اور Hermes (ایک بار جب Omarchy اسے انسٹال کر لے) سب ساتھ ساتھ چلتے ہیں۔

### Your agent instructions

ہر ایجنٹ کے لیے ذاتی اصول `~/.agents/AGENTS.md` میں جاتے ہیں، `~/.agents/skills` میں مشترکہ اسکلز کے ساتھ۔ اسے ایجنٹس پینل میں + کے ساتھ والے دستاویز آئیکن سے کھولیں، یا `omarchy agent instructions --edit` سے، جو اسے ہر اس ہارنس میں بھی لنک کرتا ہے جو اپنی عالمی فائل رکھتا ہے: `~/.claude/CLAUDE.md`، `~/.codex/AGENTS.md`، `~/.pi/agent/AGENTS.md`، `~/.config/opencode/AGENTS.md`، Copilot کی `~/.copilot/copilot-instructions.md`، اور اسی طرح۔ Crush اور Amp `~/.config/AGENTS.md` لنک پڑھتے ہیں، جبکہ omp، Kimi، اور DeepSeek Harness براہ راست `~/.agents/AGENTS.md` پڑھتے ہیں۔ ڈیفالٹ ایجنٹ منتخب کرنے پر وہ بھی لنک ہو جاتا ہے۔ اگر آپ کے پاس پہلے سے کوئی ہدایات فائل تھی اور ابھی کوئی مشترکہ فائل نہیں تھی، تو وہ مشترکہ بن جاتی ہے؛ ورنہ اسے لنک کے ساتھ `.bak` کے طور پر رکھا جاتا ہے۔ ایک اور ایجنٹ انسٹال کرنے کے بعد دوبارہ لنک کرنے کے لیے `omarchy agent instructions` چلائیں۔

### The agents panel

اوپر والی بار میں ایک ایجنٹس آئیکن ہے۔ ایجنٹ سیٹ اپ کرنے سے پہلے، اس کا پینل شروع کرنے کے تین طریقے پیش کرتا ہے: Claude، Codex، Grok، Gemini، Muse، Cursor، یا Copilot سبسکرپشن میں سائن ان کریں، یا More کے تحت OpenCode Go، MiniMax، Synthetic، یا Z.ai کوڈنگ پلان؛ Fireworks، OpenCode Zen and Go، OpenRouter، یا More کے تحت DeepSeek یا کسی بھی دوسرے فراہم کنندہ کے ساتھ جیسے جائیں ویسے ادائیگی کریں جس میں OpenCode سائن ان کرتا ہے، یہ سب OpenCode میں چلتے ہیں؛ یا اپنے کمپیوٹر کے لیے بہترین ماڈل چلائیں، جب کوئی اس میں فٹ آتا ہو۔ جسے آپ پہلے مکمل کریں گے وہ آپ کا ڈیفالٹ ایجنٹ بن جاتا ہے، اور پینل میں + بعد میں بھی وہی تین پیش کرتا ہے۔ اس کے بعد، پینل ہر سبسکرپشن کو ایک صفحے پر رکھتا ہے: ہر ایجنٹ اور اکاؤنٹ اس کے پلان کے ساتھ، اس کی 5-hour سیشن اور ہفتہ وار حدود میں سے ہر ایک کے لیے ایک میٹر ری سیٹ ہونے تک کے وقت کے ساتھ (درست فیصد کے لیے ہوور کریں)، یا باقی پری پیڈ بیلنس، ایک لائن کے تحت جو ان سب میں آپ کے استعمال کردہ کو گھماتی رہتی ہے، جیسے اس ہفتے کے ٹوکنز اور آپ کا سب سے زیادہ استعمال شدہ ماڈل۔ _Make something cool_ کے تحت یہ نئی تھیم، پلگ ان، ایپ، یا گیم کے لیے ابتدائی پرامپٹس پیش کرتا ہے جو کام آپ کے ڈیفالٹ ایجنٹ کے حوالے کرتے ہیں۔ ایپس اسی طرح بنائی جاتی ہیں جیسے Omarchy کی اپنی Hype، Monologue، اور Omacut ہیں، C++ اور Qt Quick میں، omarchy-make-app ایجنٹ اسکل کی پیروی کرتے ہوئے، اور انہیں درکار کمپائلر اور Qt حصے انسٹال شدہ آتے ہیں۔ گیمز `~/Games/vibes` میں ایک واحد three.js صفحہ ہوتی ہیں، omarchy-make-game ایجنٹ اسکل کی پیروی کرتے ہوئے، اور سب موجودہ تھیم میں ایک Game Vibes لانچر سے کھلتی ہیں؛ وہ ویب سے three.js لوڈ کرتی ہیں، لہٰذا شروع ہونے کے لیے انہیں کنکشن درکار ہوتا ہے۔ Claude Code، Codex، Grok، Kimi، Cursor اور اس کا Grok Bot الاؤنس، GitHub Copilot، Muse، Gemini (Antigravity کے ذریعے)، اور Devin اپنی حدود کے ساتھ باکس سے باہر شامل ہیں، Kimchi اپنے پلان، پری پیڈ کریڈٹس، اور اخراجات کے بجٹ کے ساتھ، اور Hermes، Mistral Vibe، اور Qwen Code ایک بار جب آپ انہیں استعمال کر لیں تو اپنے سیشنز اور ٹوکنز دکھاتے ہیں۔ pi، omp، یا opencode کے ذریعے استعمال کیے جانے والے فراہم کنندہ پلانز اور کیز بھی ظاہر ہوتے ہیں: OpenCode Zen and Go، Z.ai GLM Coding Plan، Ollama Cloud، MiniMax Token Plan، اور Synthetic اپنی حدود کے ساتھ؛ OpenRouter اور DeepSeek اپنے پری پیڈ بیلنس کے ساتھ؛ Fireworks پچھلے 30 دنوں میں اپنے اخراجات کے ساتھ۔ اپنے ہارڈویئر پر چلائے جانے والے ماڈلز کے ٹوکنز بھی مجموعوں میں شمار ہوتے ہیں؛ خود ماڈلز کا اپنا پینل ہوتا ہے، جو [Local models](#local-models) کے تحت بیان کیا گیا ہے۔ ہر ایجنٹ ایک بار شمار ہوتا ہے، اس کے تحت جسے بھی اس کا بل آتا ہو، آپ اسے کتنے ہی ہارنسز کے ذریعے چلائیں۔

پینل کے لیے بار آئیکن پر بائیں کلک کریں یا `Super + Ctrl + X` دبائیں، اپنے ڈیفالٹ ایجنٹ کو لانچ کرنے کے لیے دائیں کلک کریں، اور ریفریش کرنے کے لیے درمیانی کلک کریں۔ اس کے پیچھے استعمال کے ریکارڈ ہر 15 منٹ میں `omarchy agent usage update` کے ذریعے دوبارہ بنائے جاتے ہیں، اور پینل ہم آہنگ شدہ فولڈر کے ذریعے آپ کی دوسری مشینوں سے استعمال کو بھی ضم کر سکتا ہے۔ مکمل ترتیبات کے لیے `$OMARCHY_PATH/shell/plugins/agents/` کے تحت README دیکھیں۔

### Several subscriptions

اگر آپ ایک سے زیادہ Claude، Codex، یا Grok پلان کی ادائیگی کرتے ہیں — مثلاً ایک ذاتی Max اور ایک کام والا — تو Omarchy ان سب کو سائن ان رکھ سکتا ہے اور ان کے درمیان منتقل ہو سکتا ہے۔ ایجنٹس پینل میں + کے ساتھ سبسکرپشن شامل کریں، جو آپ کو وہیں اس سے گزارتا ہے، یا `omarchy agent account add claude Work` کے ساتھ (یا `codex`، یا `grok`)۔ وہی + اور کمانڈ Gemini (`gemini`) اور OpenCode (`opencode`) میں سائن ان کرتے ہیں، اور OpenCode میں Fireworks (`fireworks`) یا OpenRouter (`openrouter`) API کی محفوظ کرتے ہیں؛ کمانڈ Copilot (`copilot`)، Cursor (`cursor`)، اور Muse (`muse`) میں بھی سائن ان کرتی ہے۔ وہ ہر ایک ایک واحد سائن ان رکھتے ہیں۔ اگر CLI غائب ہو تو یہ اسے انسٹال کرتا ہے۔ کسی فراہم کنندہ کے لیے پہلا اکاؤنٹ آپ کے عام براؤزر کے ذریعے سائن ان ہوتا ہے، بالکل وہیں جہاں CLI ہمیشہ دیکھتا ہے۔ اس کے بعد ہر ایک نجی ونڈو کے ذریعے سائن ان ہوتا ہے، تاکہ جس اکاؤنٹ میں آپ کا براؤزر پہلے سے سائن ان ہے وہ غلطی سے نہ پکڑا جائے؛ وہاں اس اکاؤنٹ کے طور پر سائن ان کریں جسے آپ شامل کر رہے ہیں، اور پہلے سے کھلی ہوئی کسی بھی نجی ونڈو کو پہلے بند کر دیں۔ اس کے لیے کبھی CLI سے لاگ آؤٹ نہ ہوں: لاگ آؤٹ کرنے سے محفوظ شدہ سائن ان منسوخ ہو جاتا ہے، اور اس اکاؤنٹ کو دوبارہ شامل کرنا پڑے گا۔

اپنی سبسکرپشن لاگ ان کو SSH پر دوسری Omarchy مشین پر کاپی کرنے کے لیے، `omarchy agent account copy user@laptop` چلائیں۔ جب منزل پر کوئی انسٹال نہ ہو تو بھیجنے والا ایک عارضی وصول کنندہ فراہم کرتا ہے، تاکہ پرانی Omarchy مشینیں اپڈیٹ کے بغیر اکاؤنٹس وصول کر سکیں۔ انسٹال شدہ وصول کنندگان کو ترجیح حاصل ہوتی ہے۔ یہ تمام Claude، Codex، اور Grok سبسکرپشنز کاپی کرتا ہے؛ انہیں منتخب کرنے کے لیے فراہم کنندہ کے نام شامل کریں، جیسے `omarchy agent account copy laptop claude` میں۔ اکاؤنٹ کے نام اور کمانڈ IDs ماخذ سے ملتے ہیں، بشمول منزل پر پہلے سے موجود اکاؤنٹس۔ اگر ان کے نام متصادم ہوں تو غیر متعلقہ منزل اکاؤنٹس کو عددی لاحقہ ملتا ہے، اور ترتیبات، اسکلز، پلگ انز، اور گفتگو کی تاریخ ہر مشین پر مقامی رہتی ہے۔

منزل کی موجودہ اسناد برقرار رکھی جاتی ہیں۔ کوئی ماخذ اکاؤنٹ جو وہاں پہلے سے سائن ان ہو اس کا نام اس کی اسناد کو تبدیل کیے بغیر ہم آہنگ ہو جاتا ہے؛ دوسرے اکاؤنٹس اس کے ساتھ شامل کر دیے جاتے ہیں۔ ملتے جلتے اکاؤنٹس کے لیے محفوظ شدہ اسناد تبدیل کرنے کے لیے، منزل پر اس اکاؤنٹ کے سیشنز بند کرنے کے بعد `omarchy agent account copy --replace laptop claude` استعمال کریں۔ تازہ منزل کو ماخذ کا فعال اکاؤنٹ اور سوئچنگ ترجیحات بھی ملتی ہیں؛ قائم شدہ منزل اپنی برقرار رکھتی ہے۔

اسناد SSH کے ذریعے سفر کرتی ہیں اور منزل پر نجی فائلوں میں محفوظ ہوتی ہیں، لہٰذا صرف ان مشینوں پر کاپی کریں جن پر آپ اعتماد کرتے ہیں۔ یہ ایک بار کی کاپی ہے، جاری ہم آہنگی نہیں۔ Codex ریفریش ٹوکنز کو دوسری مشین گھما سکتی ہے، جس سے کاپی شدہ لاگ ان کو تجدید کی ضرورت پڑ جاتی ہے؛ کئی مشینوں پر بیک وقت استعمال کے لیے الگ الگ سائن ان سب سے قابل اعتماد انتخاب رہتے ہیں۔ دیکھیں [Codex's account authentication guidance](https://developers.openai.com/codex/auth/ci-cd-auth)۔

فی فراہم کنندہ ایک اکاؤنٹ فعال ہوتا ہے، اور ہر نیا سیشن اسی کے طور پر شروع ہوتا ہے: `cx`، `cy`، سادہ `claude`، `codex`، یا `grok`، `omarchy agent` کے ذریعے لانچ کردہ کوئی بھی چیز، اور اسکرپٹس یا ایڈیٹرز جو `PATH` پر CLI تلاش کرتے ہیں۔ `omarchy agent account use work` سے سوئچ کریں (اور `omarchy agent account use main` سے واپس)، یا پینل میں کسی اکاؤنٹ کا نمبر دبا کر پھر `Enter` دبا کر (یا اس کے اسٹار پر کلک کر کے)۔ چل رہے Claude سیشنز بھی سوئچ ہوتے ہیں، ان کے اگلے پیغام سے: ہر Claude سیشن `~/.claude` میں چلتا ہے، جس میں ہمیشہ فعال اکاؤنٹ کا سائن ان ہوتا ہے۔ پرانے Omarchy کے ذریعے کسی اکاؤنٹ کے اپنے فولڈر میں شروع کیا گیا Claude سیشن اس سائن ان کو بند ہونے تک رکھتا ہے، لہٰذا سوئچ ان سیشنز کے نام بتاتا ہے اور ان کے ختم ہونے پر خود مکمل ہو جاتا ہے۔ چل رہے Codex اور Grok سیشنز اسی اکاؤنٹ پر رہتے ہیں جس سے وہ شروع ہوئے تھے۔ گفتگو کی تاریخ، ترتیبات، اسکلز، اور پلگ انز اکاؤنٹس میں مشترکہ ہوتے ہیں، لہٰذا اسی فولڈر میں `claude --continue` وہیں سے اٹھاتا ہے جہاں آپ نے نئے اکاؤنٹ پر چھوڑا تھا۔

ایک سے زیادہ اکاؤنٹ کے ساتھ، پینل ہر اکاؤنٹ کی حدود ساتھ ساتھ دکھاتا ہے، استعمال میں موجود پر بھرا ہوا اسٹار کے ساتھ۔ جب فعال اکاؤنٹ کسی حد کے 95% سے گزر جاتا ہے تو Omarchy آپ کو مطلع کرتا ہے، اور اطلاع پر کلک کرنے سے سب سے زیادہ گنجائش والے اکاؤنٹ پر سوئچ ہو جاتا ہے۔ یہ کبھی خود سے سوئچ نہیں کرتا۔ حد کو `omarchy agent account threshold 90` سے تبدیل کریں۔ اگر ہر اکاؤنٹ حد سے اوپر ہو، تو آپ کو اس کے بارے میں ایک بار سننے کو ملے گا، اس کے ساتھ کہ کون سا اکاؤنٹ پہلے آزاد ہوتا ہے۔ جبکہ فعال اکاؤنٹ اپنی حد کے 15 پوائنٹس کے اندر ہو (ڈیفالٹ پر 80%)، اس کی حدود ہر 15 کے بجائے ہر تین منٹ میں چیک کی جاتی ہیں۔

`omarchy agent account list` ہر اکاؤنٹ اور اس کی تازہ ترین حدود دکھاتا ہے، `omarchy agent account remove work` ایک کو بھول جاتا ہے، اور `omarchy agent account rename primary Hey` ایک کا نام تبدیل کرتا ہے (یا پینل میں کسی اکاؤنٹ کے نام پر کلک کریں)۔ یہ کمانڈز آپ کے ڈیفالٹ ایجنٹ کے اکاؤنٹس پر کام کرتی ہیں؛ دوسرے فراہم کنندہ تک پہنچنے کے لیے، پہلے اس کا نام لیں، جیسے `omarchy agent account use codex side` میں۔ `~/.claude` یا `~/.codex` میں آپ کے پاس پہلے سے موجود لاگ ان _Main_ اکاؤنٹ ہے۔ Codex کا وہیں رہتا ہے جہاں وہ ہے؛ Claude کا جب کوئی دوسرا اکاؤنٹ فعال ہو تو اپنے فولڈر میں انتظار کرتا ہے۔ تقریباً آٹھ گھنٹے سے زیادہ غیر استعمال شدہ چھوڑا گیا اکاؤنٹ _Sign-in required_ دکھا سکتا ہے؛ اس اکاؤنٹ کو پینل میں ہی دوبارہ سائن ان کرنے کے لیے اس پر کلک کریں، یا اس پر سوئچ کریں اور سیشن شروع کریں، جو سائن ان کو خود تازہ کر دیتا ہے۔ `claude mcp add` کے ساتھ شامل کیے گئے MCP سرورز ہر Claude اکاؤنٹ تک پہنچتے ہیں، کیونکہ وہ سب `~/.claude` میں چلتے ہیں؛ Codex اور Grok کے لیے، جب اکاؤنٹ شامل کیا گیا تھا اس وقت آپ کے پاس موجود سرورز اس کے ساتھ آتے ہیں، لیکن بعد والے صرف اسی اکاؤنٹ تک پہنچتے ہیں جس میں آپ نے انہیں شامل کیا تھا۔ Claude Desktop اپنا سائن ان رکھتا ہے، اور CLI بائنری کے مطلق راستے کے ساتھ ترتیب شدہ Codex یا Grok ٹولز سوئچ کی پیروی نہیں کرتے۔ واضح `CLAUDE_CONFIG_DIR`، `CODEX_HOME`، یا `GROK_HOME` منتخب اکاؤنٹ پر ترجیح لیتا ہے۔

### Crash diagnosis

Omarchy عمل کے کریشز کے لیے systemd-coredump پر نظر رکھتا ہے۔ ایک بار جب آپ نے ڈیفالٹ ایجنٹ منتخب کر لیا، تو آپ کا کوئی بھی پروگرام جو کور ڈمپ کرے وہ "Process crashed" اطلاع لاتا ہے — اس پر کلک کریں، اور کریش آپ کے ڈیفالٹ ایجنٹ کے حوالے Omarchy کی omarchy-diagnose-crash اسکل کے ساتھ کر دیا جاتا ہے، جو ایجنٹ کو کور ڈمپ سے حقائق قائم کرنے اور یہ فیصلہ کرنے میں رہنمائی کرتی ہے کہ آیا کریش upstream رپورٹ کرنے کے قابل ہے۔ آپ اسے `coredumpctl list` سے کسی بھی PID کے خلاف ہاتھ سے بھی `omarchy agent crash <pid>` سے چلا سکتے ہیں۔

دیکھنا بطور ڈیفالٹ آن ہوتا ہے۔ اسے _Trigger > Toggle > Crash Capture Off_ کے تحت بند کر دیں (یا `omarchy toggle crash-capture` سے) اور اطلاعات رک جاتی ہیں؛ `omarchy agent crash <pid>` ہاتھ سے پھر بھی کام کرتا ہے۔

کریشز کو ایک وقت میں ایک پروگرام کے حساب سے بھی خاموش کیا جا سکتا ہے، جو تشخیص آخر میں آپ کو پیش کرتی ہے۔ `omarchy crash mute hyprland` صرف اس پروگرام کے لیے اطلاعات روکتا ہے، `omarchy crash mute hyprland off` انہیں واپس لاتا ہے، اور اکیلا `omarchy crash mute` فہرست دیتا ہے کہ آپ نے کیا خاموش کیا ہے۔ یہ بائنری کا راستہ اس کے نام کی طرح خوشی سے لیتا ہے، لہٰذا `omarchy crash mute /usr/bin/hyprland` وہی کام کرتا ہے۔ جس نام میں اسپیس ہو اسے کوٹ کریں، جیسے `omarchy crash mute 'Some App'` میں۔ باقی سب پھر بھی مطلع کرتا ہے، اور خاموش کیا گیا پروگرام پھر بھی کریش ہوتا ہے — یہ یاد دہانی چھپاتا ہے، یہ کچھ ٹھیک نہیں کرتا۔

### Desktop apps

_Install > AI_ مینو میں چند گرافیکل AI ایپس بھی شامل ہیں: Amp Desktop، Antigravity Desktop، ChatGPT desktop app، Claude desktop app (Anthropic's Linux beta, with Chat, Cowork, and Claude Code tabs)، Grok Bot for chatting with xAI's models، Herdr Desktop، Hermes Desktop، OpenClaw، Perplexity desktop app، اور T3 Code۔ Grok Bot ڈیسک ٹاپ چیٹ ایپ ہے۔ کوڈنگ ایجنٹ `grok` کمانڈ ہے۔

Hermes Desktop وہ ہے جس کے بارے میں جاننا ضروری ہے، کیونکہ کسی مشین میں ایک Hermes ہوتا ہے، اور وہ ایپ کا ہوتا ہے: Hermes ہمیشہ صرف ایپ کے ذریعے انسٹال ہوتا ہے، اور ڈیفالٹ ایجنٹ جو `hermes` کمانڈ چلاتا ہے وہ ایپ کی ہوتی ہے۔ Hermes کو ڈیفالٹ ایجنٹ کے طور پر منتخب کرنے پر وہی انسٹال ہوتا ہے جو _Install > AI_ اندراج کرتا ہے: پیکیج، اور Hermes کے اپنے انسٹالر کے ذریعے سیٹ اپ کردہ `~/.hermes` کے تحت Hermes رن ٹائم، جس میں پہلی بار چند منٹ لگتے ہیں۔ وہ رن ٹائم وہی ایک Hermes ہے جسے ٹرمینل `hermes` کمانڈ، ڈیفالٹ ایجنٹ اور ایپ سب استعمال کرتے ہیں، اور یہ Omarchy ریلیز کا انتظار کرنے کے بجائے `hermes update` سے خود کو اپڈیٹ کرتا ہے۔ اسے انسٹال کرنے پر Hermes کو Omarchy تھیم بطور اسکن بھی ملتی ہے جس کا نام `omarchy` ہے، جس کی ہر Hermes سطح آپ کے تھیمز تبدیل کرنے پر پیروی کرتی ہے؛ اگر آپ پسند نہ کریں کہ ایسا ہو تو Hermes کی Appearance ترتیبات کے تحت یا `/skin` سے کوئی اور منتخب کریں، اور Omarchy اس انتخاب کو چھوڑ دیتا ہے۔ _Remove > AI_ کے تحت ایپ کو ہٹانے پر پہلے Hermes بند ہوتا ہے، گیٹ وے سمیت، وہ رن ٹائم اس کے ساتھ لے جاتا ہے، اور آپ کی چیٹس، یادیں، اور وہ اسکلز جو Hermes نے خود کے لیے لکھی تھیں برقرار رکھتا ہے الا یہ کہ آپ اسے دوسری صورت کہیں: یہ پوچھتا ہے، ڈیفالٹ نہیں کے ساتھ، کہ آیا وہ ڈیٹا اور آپ کی کنکشن ترتیبات بھی جانی چاہئیں۔

OpenClaw کا ڈیسک ٹاپ تجربہ اس کا Control UI ہے، جو اس کے اپنے مقامی گیٹ وے کی پشت پناہی سے ویب ایپ کے طور پر کھلتا ہے۔ OpenClaw `~/.openclaw` میں رہتا ہے اور خود کو اپڈیٹ کرتا ہے: Control UI کا "Update Gateway" بٹن استعمال کریں یا `openclaw update` چلائیں، اور گیٹ وے نئے ورژن پر دوبارہ شروع ہو جاتا ہے۔ Omarchy صرف وہ ریلیز منتخب کرتا ہے جس سے تازہ انسٹال شروع ہوتا ہے۔ OpenClaw آپ کا ڈیفالٹ ایجنٹ بھی ہو سکتا ہے: اسے `omarchy default agent openclaw` سے منتخب کرنے پر `~/.openclaw` میں وہی کاپی سیٹ اپ ہوتی ہے، اور ایجنٹ OpenClaw کا ٹرمینل UI اس کے گیٹ وے سے منسلک کھولتا ہے۔ _Remove > AI_ کے تحت OpenClaw کو ہٹانے پر گیٹ وے سروس اور ایپ اس کے ساتھ جاتی ہے اور پھر پوچھتا ہے کہ آیا `~/.openclaw` بھی جانا چاہیے، کیونکہ اس میں خود OpenClaw اور اس کے ڈاؤن لوڈ کردہ پلگ ان رن ٹائمز کے ساتھ آپ کی چیٹس اور اسناد ہوتی ہیں؛ ڈیفالٹ اسے برقرار رکھتا ہے، اور OpenClaw کو دوبارہ انسٹال کرنے پر وہ اسے واپس اٹھا لیتا ہے۔

Herdr Desktop [Herdr](https://herdr.dev) ڈیسک ٹاپ ایپ ہے: ٹرمینلز اور کوڈنگ ایجنٹس کے اسپیسز، ٹیبز، اور پینز جو ونڈو بند کرنے پر اس کے کور میں چلتے رہتے ہیں۔ یہ پیکیج کے بجائے Herdr کے اپنے انسٹالر سے آتی ہے، لہٰذا یہ `~/.local/share/herdr-app` میں رہتی ہے، جب آپ کے پاس پہلے سے کوئی نہ ہو تو `~/.local/bin/herdr-core` میں اپنا کور ساتھ لاتی ہے، اور دونوں خود کو اپڈیٹ کرتے ہیں۔ یہ اس `herdr` کمانڈ کے ساتھ بیٹھتی ہے جو Omarchy `Super + Ctrl + Return` پر بھیجتا ہے اسے تبدیل کرنے کے بجائے، اور اس کمانڈ کی براہ راست کیز حاصل کرتی ہے: `Alt + Return` اور `Alt + Shift + Return` پین کو نیچے یا دائیں تقسیم کرتے ہیں، `Alt + Escape` اسے بند کرتا ہے، `Ctrl + Alt + Arrow` پینز کے درمیان منتقل ہوتا ہے، `Alt + 1..9` اور `Alt + Left/Right` ٹیب منتخب کرتے ہیں، اور `Alt + Up/Down` اسپیسز کے درمیان منتقل ہوتے ہیں۔ `Ctrl + 1..9` اسپیس منتخب کرتا ہے اور `Alt + Shift + Up/Down` ایجنٹس میں قدم بڑھاتا ہے۔ `Ctrl + Space` پریفکس کیز صرف ٹرمینل تک رہتی ہیں، کیونکہ ایپ تسلسل کے لیے سادہ Ctrl کی کو تھام نہیں سکتی۔ Omarchy یہ `~/.config/herdr-app/keys.json` میں لکھتا ہے، اور `omarchy-refresh-herdr-app` انہیں واپس رکھتا ہے۔ اسے انسٹال کرنے پر Herdr کی Omarchy تھیم منتخب ہوتی ہے، جو اس کے بعد سے آپ کی Omarchy تھیم کی پیروی کرتی ہے۔ Herdr ہلکے موڈ کے لیے ایک تھیم اور گہرے موڈ کے لیے ایک رکھتا ہے، لہٰذا گہری اور ہلکی Omarchy تھیم کے درمیان سوئچ کرنے کے بعد، دوسرے موڈ کے لیے Herdr کے تھیم پکر میں ایک بار پھر Omarchy منتخب کریں۔

T3 Code پیکیج کے بجائے `~/.local/share/t3code` میں اپنی آفیشل AppImage ریلیز سے چلتا ہے، لہٰذا یہ خود کو اپڈیٹ کرتا ہے۔ اسے انسٹال کرنے پر پوچھا جاتا ہے کہ آیا Stable یا Nightly چینل پر شروع کرنا ہے؛ بعد میں T3 Code کی ترتیبات میں سوئچ کریں۔ آپ کے تھریڈز اور ترتیبات `~/.t3` میں رہتے ہیں، اور _Remove > AI_ کے تحت T3 Code کو ہٹانے پر وہ اس کے ساتھ جاتے ہیں۔

### Local models

اپنے کوڈنگ ایجنٹس کے لیے اپنی مشین پر اوپن ماڈل چلائیں۔ آپ کے پرامپٹس اور کوڈ مشین پر رہتے ہیں؛ ماڈل کو بھیجی گئی کوئی چیز اسے نہیں چھوڑتی۔ اس سے شروع کریں:

```bash
omarchy models use best text
```

یہ اس مشین کے لیے بہترین ٹیکسٹ ماڈل سیٹ اپ کرتا ہے، اس قسم کا جو آپ کے ایجنٹس استعمال کرتے ہیں۔ امیج، ویڈیو اور میوزک ماڈلز کا اپنا بہترین ہوتا ہے: `omarchy models use best image`، `video` یا `music`۔ اس مشین کے لیے ہر قسم کا انتخاب دیکھنے کے لیے `omarchy models use best` چلائیں۔

یا اوپر والی بار میں ایجنٹس آئیکن کے ساتھ اس کے چمک آئیکن سے لوکل ماڈلز پینل کھولیں، یا Super + Ctrl + Alt + X سے، اور + منتخب کریں۔ آئیکن اس وقت ظاہر ہوتا ہے جب کوئی ماڈل اس مشین میں فٹ آتا ہو۔ Podman، جو ماڈلز چلاتا ہے، Omarchy کے ساتھ آتا ہے، جیسا کہ NVIDIA مشین پر NVIDIA کا کنٹینر ٹول کٹ آتا ہے، جو انہیں GPU دیتا ہے؛ اگر کوئی بھی غائب ہو، تو پہلا سیٹ اپ اسے انسٹال کرتا ہے۔ پھر Omarchy اس مشین کے لیے تجویز کردہ ماڈل منتخب کرتا ہے، اسے ڈاؤن لوڈ کرتا ہے، اور شروع کرتا ہے۔ دسیوں GB کے ڈاؤن لوڈ اور ماڈل چلنے کے دوران مشین کی زیادہ تر میموری استعمال میں ہونے کی توقع رکھیں: Flash Next اپنے مکمل 256K سیاق و سباق کے ساتھ تقریباً 100 GiB استعمال کرتا ہے۔ اگر دوسرے ماڈلز وہ میموری رکھتے ہوں جس کی اسے ضرورت ہو، تو یہ رکا ہوا سیٹ اپ ہوتا ہے، ایک کو روکنے پر شروع ہونے کے لیے تیار۔ ماڈل لاگ آؤٹ پر رک جاتا ہے؛ جب آپ کو کسی اور چیز کے لیے میموری درکار ہو تو اسے خود روک دیں۔

`omarchy models list` اختیارات دکھاتا ہے اور بتاتا ہے کہ کچھ کیوں فٹ نہیں آتے۔ کوئی اور سیٹ اپ کرنے کے لیے، `omarchy models use <recipe>` چلائیں۔ آج، 128 GB Strix Halo مشینوں کے لیے `qwen3.8-flash-next-gufo` اور `qwen3.8-27b-gufo` دستیاب ہیں؛ 27B تقریباً 40 GiB لیتا ہے، لہٰذا یہ دوسرے کام کے لیے جگہ چھوڑتا ہے۔ Intel's Arc B390 والے 64 GB لیپ ٹاپ پر، `qwen3.6-35b-a3b-llamacpp` تقریباً 30 GiB میں چلتا ہے۔ نئی ترکیبیں اور سفارشات پیکیج کے ذریعے `omarchy update` کے ساتھ آتی ہیں۔

آپ کے سیٹ اپ کردہ ہر ماڈل کو لوکل ماڈلز پینل میں اپنی لائن ملتی ہے: اسے شروع کرنے کے لیے پلے، اسے روکنے اور اس کی میموری آزاد کرنے کے لیے پاز، اور اس پر اپنا ایجنٹ کھولنے کے لیے ٹرمینل بٹن۔ اوپر کے پار، ایک بار دکھاتا ہے کہ مشین کی میموری خود Omarchy (سسٹم اور آپ کی ایپس)، ہر چل رہے ماڈل، اور جو آزاد ہے کے درمیان کیسے تقسیم ہے۔ رکے ہوئے ماڈل کی طرف اشارہ کریں اور بار دکھاتا ہے کہ آیا یہ فٹ آتا ہے، یا کتنا کم ہے۔ کئی ایک ساتھ چل سکتے ہیں جب وہ میموری میں اکٹھے فٹ آتے ہوں؛ اگر کوئی فٹ نہ آئے، تو Omarchy بتاتا ہے کہ کون سا چل رہا ماڈل روکنا ہے۔ انہیں دوبارہ ترتیب دینے کے لیے لائنوں کو ان کے لوگو سے گھسیٹیں، اور ماڈل اور اس کا ڈاؤن لوڈ ہٹانے کے لیے منتخب لائن پر Delete دبائیں۔

آپ کے سیٹ اپ کردہ ہر کوڈنگ ماڈل کو ایپ لانچر میں بھی اپنی انٹری ملتی ہے، ماڈل کے نام کے تحت اور اس کے بنانے والے کے لوگو کے ساتھ، اسی طرح جیسے Claude، Codex یا Grok میں سائن ان کرنے پر ایک شامل ہوتی ہے۔ یہ اس ماڈل پر آپ کا ایجنٹ کھولتا ہے، اور اگر ماڈل نہیں چل رہا تو پہلے اسے شروع کرتا ہے: ٹرمینل اسے لوڈ ہوتا دکھاتا ہے اور تیار ہونے پر ایجنٹ کے حوالے کر دیتا ہے۔ ماڈل ہٹانے سے اس کی انٹری ہٹ جاتی ہے۔

ہر ماڈل کوڈنگ کے لیے نہیں ہوتا۔ امیج، ویڈیو اور میوزک ماڈلز اس کے بجائے Fantasi میں کھلتے ہیں، Omarchy کی ایپ اس مشین پر چل رہے ماڈل سے تصاویر، ویڈیو اور موسیقی بنانے کے لیے، وہاں یا لوکل ماڈلز پینل میں ان کی لائن سے منتخب کردہ۔

کوئی ماڈل بالکل اسی طرح چلتا رہتا ہے جیسے اسے سیٹ اپ کیا گیا تھا، لہٰذا Omarchy اپڈیٹ کبھی آپ کے ایجنٹس کے تحت ایک کو دوبارہ شروع نہیں کرتا۔ جب Omarchy کے پاس آپ کے سیٹ اپ کردہ ماڈل کے لیے نیا رن ٹائم یا نئے ویٹس ہوں، تو اس کی لائن اپڈیٹ بٹن دکھاتی ہے: اسے دبائیں اور ماڈل پس منظر میں دوبارہ سیٹ اپ ہو جاتا ہے، صرف وہ ڈاؤن لوڈ کرتے ہوئے جو تبدیل ہوا، اور نئے ورژن پر دوبارہ شروع ہو جاتا ہے۔ جو ماڈل رکا ہوا تھا وہ رکا رہتا ہے۔ `omarchy models update` ٹرمینل سے ہر ماڈل کے لیے وہی کرتا ہے۔

کمانڈ لائن سے، `omarchy models start <recipe>` اور `omarchy models stop <recipe>` وہی کرتے ہیں، `omarchy models status` ہر ماڈل دکھاتا ہے، اور `omarchy agent --local-model <recipe>` اس ماڈل کو pi میں کھولتا ہے، آپ کا ڈیفالٹ ایجنٹ جو بھی ہو۔ اپنے لوکل ماڈل کو وہ بنانے کے لیے جو ایجنٹ ہاٹ کی، Quake کنسول، اور _Make something_ کھولتے ہیں، `omarchy default agent local` چلائیں یا ایجنٹس پینل میں چل رہے ماڈل کو اسٹار کریں۔ pi آپ کے سیٹ اپ کردہ ہر ماڈل، اور جن مشینوں کے ساتھ آپ نے جوڑا بنایا ہے ان پر موجود ماڈلز کو بھی، اپنے ماڈل پکر میں فہرست کرتا ہے، لہٰذا سادہ `pi` بھی ان تک پہنچتا ہے۔ کوئی بھی OpenAI-compatible کلائنٹ بھی جڑ سکتا ہے: `status` ہر ماڈل کا پتہ دکھاتا ہے (پہلا `http://127.0.0.1:11435/v1` ہے)، ترکیب کا نام ماڈل ہے، اور کی `~/.config/omarchy/agent-local/key` میں ہے۔

`omarchy models remove <recipe>` ماڈل اور وہ ڈاؤن لوڈز حذف کرتا ہے جو کوئی دوسرا ماڈل استعمال نہیں کرتا۔

تیسرے فریق کے رن ٹائمز پر ان کے پبلشر کا لیبل ہوتا ہے۔ Omarchy ہر ماڈل کو بغیر نیٹ ورک رسائی کے چلاتا ہے۔

Omarchy مقامی LLM ماڈلز چلانے کے دو طریقے تجویز کرتا ہے: LM Studio اور Ollama۔ LM Studio اوپن ویٹ ماڈلز تلاش کرنے، انہیں انسٹال کرنے، اور انہیں چلانے کے لیے GUI انٹرفیس فراہم کرتا ہے۔ آسانی سے شروع کرنے کا یہ بہترین طریقہ ہے۔ Ollama اسی طرح کرنے کے لیے CLI پیش کرتا ہے۔ لیکن اگر آپ مقامی ماڈلز میں نئے ہیں، تو میں LM Studio سے شروع کروں گا۔ آپ Omarchy Menu میں _Install > AI_ کے تحت دونوں میں سے کوئی بھی انسٹال کر سکتے ہیں۔

### The Omarchy skills

ایجنٹ اسکلز AI کو مخصوص ٹولز کو مخصوص طریقے سے استعمال کرنے میں مدد دیتی ہیں، اور Omarchy ان میں سے سات بھیجتا ہے۔ omarchy اسکل سسٹم کو اپنی مرضی کے مطابق بنانے کا احاطہ کرتی ہے، جیسے اپنی Hyprland کنفگ کو ٹھیک کرنا یا بار کو ایڈجسٹ کرنا۔ omarchy-make-theme، omarchy-make-plugin، omarchy-make-app، اور omarchy-make-game کچھ نیا بنانے کا احاطہ کرتی ہیں، omarchy-contribute بگ رپورٹ کرنے یا upstream فکس بھیجنے کا احاطہ کرتی ہے، اور omarchy-diagnose-crash کریش کے کور ڈمپ پر کام کرتی ہے۔ وہ Claude Code (`~/.claude/skills`)، Codex (`~/.codex/skills`)، Pi (`~/.pi/agent/skills`)، Antigravity (`~/.gemini/config/skills`)، Hermes (`~/.hermes/skills` اور ہر `~/.hermes/profiles/*/skills`)، اور عام `~/.agents/skills` مقام کے لیے اسکل ڈائریکٹریوں میں سم لنک شدہ ہیں، لہٰذا زیادہ تر ہارنس انہیں خودکار طور پر اٹھا لیتے ہیں۔ اسی نام کا آپ کا اپنا اسکل فولڈر ترجیح لیتا ہے۔

لیکن آپ کو ان اسکلز کو تجرباتی سمجھنا چاہیے۔ مختلف ماڈلز اسے مختلف اثر کے لیے استعمال کریں گے۔ پہلے پلان موڈ میں چلانا بہترین ہے، تاکہ آپ کو اندازہ ہو کہ ایجنٹ کیا تبدیل کرنا چاہے گا۔ اور پھر تبدیلیوں کو واپس کرنے یا یہاں تک کہ `omarchy reinstall configs` چلانے کے لیے تیار رہیں، اگر ایجنٹ ہر چیز کا گڑبڑ کر دے۔
