### ایجنٹس انسٹال اور اپ ڈیٹ کرنا

Hermes اور OpenClaw کے سوا، یہ ایجنٹس mise کی lazy انسٹالیشن استعمال کرتے ہیں: پہلی لانچ پر CLI انسٹال ہوتا ہے، اور بعد کی لانچز اسی کو دوبارہ استعمال کرتی ہیں۔ mise انسٹال شدہ ایجنٹ کے لیے نئی ریلیز بھی چیک کرتا ہے، زیادہ سے زیادہ ہر چار گھنٹے میں ایک بار، شروع ہونے سے عین پہلے یا shell پرامپٹ پر پس منظر میں۔ اگر وہ اپ ڈیٹ ناکام ہو جائے یا آپ آف لائن ہوں، تو انسٹال شدہ ورژن چلتا ہے۔ `omarchy update` انسٹال شدہ ایجنٹس کو باقی Omarchy کے ساتھ اپ ڈیٹ کرتا ہے، اور `mup` صرف mise کے زیر انتظام ٹولز کو اپ ڈیٹ کرتا ہے۔

ایجنٹ کا اپنا اپڈیٹر، جیسے `claude update`، `codex update`، یا کسی ایپ میں اپ ڈیٹ کا بٹن، mise کے زیر انتظام انسٹال کو اپ ڈیٹ نہیں کرتا۔ `codex update` ناکام ہو جاتا ہے، اور `claude update` کامیابی کی اطلاع دے سکتا ہے جبکہ ایک الگ کاپی انسٹال کر دیتا ہے جسے mise ٹریک نہیں کرتا۔ اگر آپ اس کے بجائے ایجنٹ کا اپنا انسٹالر اور اپڈیٹر استعمال کرنا چاہتے ہیں، تو اسے `disable_tools` میں شامل کریں؛ دیکھیں [پہلے سے انسٹال شدہ CLI ٹولز](18-development-tools.md#preinstalled-cli-tools)۔

تمام ترتیب شدہ lazy ٹولز کو ضرورت پڑنے سے پہلے انسٹال کرنے کے لیے، `mise install --include-lazy` چلائیں۔ اس میں ایجنٹس کے ساتھ ساتھ Omarchy کے دیگر ڈیفالٹ CLI ٹولز بھی شامل ہیں۔ کسی ایک ٹول کو انسٹال کرنے یا اپنی انسٹالیشن استعمال کرنے کے لیے دیکھیں [پہلے سے انسٹال شدہ CLI ٹولز](18-development-tools.md#preinstalled-cli-tools)۔

`grok` mise کے فرسٹ پارٹی `grok` پیکیج کے ذریعے انسٹال ہوتا ہے، اسی طرح جیسے `claude` اور `codex`۔ `grok` چلائیں، یا اسے _Agent > Harness_ کے تحت منتخب کریں۔ x.ai پر `curl | bash` انسٹالر کو چھوڑ دیں۔ وہ راستہ `~/.grok/bin` میں دوسری کاپی رکھ دیتا ہے، اسے `PATH` کے شروع میں شامل کر دیتا ہے، اور Omarchy کے wrapper کو اوور رائٹ کر دیتا ہے۔

`dsh` اپنا براؤزر UI `127.0.0.1:3080` پر کھولتا ہے، جس میں لانچ ڈائریکٹری اس کی ڈیفالٹ workspace ہوتی ہے۔ اس کا براؤزر UI کوئی ابتدائی پرامپٹ نہیں لیتا، لہٰذا `omarchy agent prompt` اسے اس پرامپٹ کے ساتھ کھولتا ہے جو آپ کے کلپ بورڈ پر چسپاں کرنے کے لیے موجود ہوتا ہے۔ Omarchy اسے DeepSeek کے no-approval اجازت preset کے ساتھ شروع کرتا ہے۔ DeepSeek Harness سیشن لاگز کو DeepSeek پر اپ لوڈ کرتا ہے جب آپ اس کا آفیشل ماڈل API استعمال کرتے ہیں؛ اسے اس کے براؤزر UI میں _Settings > General > Upload Session Log_ کے تحت بند کر دیں۔ جو فیڈبیک آپ اسے بھیجتے ہیں وہ بھی سیشن کے ساتھ اپ لوڈ ہوتا ہے، الا یہ کہ آپ اسے `DSH_TELEMETRY_MODE=DISABLED` کے ساتھ شروع کریں۔

### ڈیفالٹ ایجنٹ

اپنا ڈیفالٹ ایجنٹ `omarchy default agent <name>` کے ساتھ یا Omarchy Menu (`Super + Space`) میں _Agent > Harness_ کے تحت منتخب کریں۔ اگر ایجنٹ ابھی انسٹال نہیں ہوا ہے، تو اسے منتخب کرنے سے وہ پہلے انسٹال ہو جاتا ہے، اور اسے ایپ لانچر میں Agent کے ساتھ ساتھ اپنا لانچر بھی مل جاتا ہے۔ تازہ Omarchy آپ کو ایک بار کی اطلاع کے ساتھ یہ انتخاب کرنے کی دعوت دے گا۔

Claude منتخب کرنا Chromium، Chrome، Brave، Brave Origin، اور Edge کے لیے اس کی براؤزر ایکسٹینشن سیٹ اپ کرنے کی بھی کوشش کرتا ہے۔ ایکسٹینشن سیٹ اپ تمام صارفین پر لاگو ہوتا ہے اور آپ سے آپ کا سسٹم پاس ورڈ مانگ سکتا ہے؛ منسوخ کرنے یا ایکسٹینشن انسٹال ناکام ہونے پر بھی Claude منتخب اور لانچ ہو جاتا ہے۔ اپنا براؤزر دوبارہ شروع کریں، اشارہ ملنے پر ایکسٹینشن فعال کریں، اور اسے جوڑنا مکمل کرنے کے لیے Claude میں سائن ان کریں۔ کنکشن چیک کرنے کے لیے Claude میں `/chrome` چلائیں۔ Firefox اور Zen اس ایکسٹینشن کو سپورٹ نہیں کرتے۔ اگر یہ سیٹ اپ شامل ہونے سے پہلے Claude پہلے ہی آپ کا ڈیفالٹ تھا، تو ایکسٹینشن انسٹال کرنے کے لیے اسے دوبارہ منتخب کریں۔

منتخب کر لینے کے بعد، `Super + Shift + Ctrl + A` ڈیفالٹ ایجنٹ کو ایک مخصوص ٹرمینل ونڈو میں لانچ کرتا ہے (یا اگر آپ نے ابھی تک انتخاب نہیں کیا ہے تو picker سامنے لاتا ہے)۔ آپ اسے `omarchy agent prompt "Review this project"` کے ساتھ سیدھا کسی کام میں بھی لانچ کر سکتے ہیں۔ Freebuff اور DeepSeek Harness کوئی ابتدائی پرامپٹ نہیں لیتے، لہٰذا وہ اس کے بجائے اس پرامپٹ کے ساتھ کھلتے ہیں جو آپ کے کلپ بورڈ پر چسپاں کرنے کے لیے موجود ہوتا ہے۔ اس طرح لانچ کیے گئے ایجنٹس اپنے متعلقہ don't-stop-to-ask موڈز میں بلا نگرانی چلتے ہیں، لہٰذا تیار رہیں کہ وہ واقعی کچھ کریں گے! MiniMax Code کے انٹرایکٹو سیشنز کے لیے ایسا کوئی موڈ نہیں ہے، لہٰذا وہ معمول کے مطابق اجازتیں مانگتا ہے۔ اور چونکہ ایجنٹس آپ کی home ڈائریکٹری کے لیے بھروسا یاد رکھنے سے انکار کرتے ہیں، اس لیے `$HOME` سے لانچز اس کے بجائے `~/Work` میں شروع ہوتی ہیں۔

ٹرمینل شارٹ کٹس بھی ہیں: `a` ڈیفالٹ ایجنٹ کو موجودہ ٹرمینل میں inline چلاتا ہے، جبکہ `c`، `cx`، اور `cy` OpenCode، Claude Code، اور Codex کو براہ راست شروع کرتے ہیں (ایک بار پھر ان کے auto-approving موڈز میں)۔ تھیم کی تبدیلیاں ایجنٹس کے ساتھ بھی sync ہوتی ہیں: Claude Code، Pi، OpenCode، اور Hermes (جب Omarchy نے اسے انسٹال کر لیا ہو) سب اس وقت ساتھ چلتے ہیں جب آپ Omarchy تھیم تبدیل کرتے ہیں۔

### آپ کی ایجنٹ ہدایات

ہر ایجنٹ کے لیے ذاتی قواعد `~/.agents/AGENTS.md` میں جاتے ہیں، `~/.agents/skills` میں مشترکہ skills کے ساتھ۔ اسے _Agent > Instructions_ کے تحت کھولیں، جو اسے ہر اس harness میں بھی لنک کرتا ہے جو اپنی عالمی فائل رکھتا ہے: `~/.claude/CLAUDE.md`، `~/.codex/AGENTS.md`، `~/.pi/agent/AGENTS.md`، `~/.config/opencode/AGENTS.md`، Copilot کی `~/.copilot/copilot-instructions.md`، اور اسی طرح۔ Crush اور Amp `~/.config/AGENTS.md` لنک پڑھتے ہیں، جبکہ omp، Kimi، اور DeepSeek Harness `~/.agents/AGENTS.md` کو براہ راست پڑھتے ہیں۔ ڈیفالٹ ایجنٹ منتخب کرنا اسے بھی لنک کر دیتا ہے۔ جو ہدایات فائل آپ کے پاس پہلے سے تھی وہ مشترکہ فائل بن جاتی ہے اگر ابھی تک کوئی نہیں تھی؛ بصورت دیگر اسے لنک کے ساتھ `.bak` کے طور پر رکھا جاتا ہے۔ کوئی اور ایجنٹ انسٹال کرنے کے بعد دوبارہ لنک کرنے کے لیے `omarchy agent instructions` چلائیں۔

### ایجنٹس پینل

اوپر والی بار میں ایجنٹس کا آئیکن ہے۔ ایجنٹ سیٹ اپ کرنے سے پہلے، اس کا پینل آپ کو Claude، Codex، یا Grok میں سائن ان کرنے کے مراحل سے گزارتا ہے، اور پہلا آپ کا ڈیفالٹ ایجنٹ بن جاتا ہے۔ اس کے بعد، پینل ہر سبسکرپشن کو ایک صفحے پر رکھتا ہے: ہر ایجنٹ اور اکاؤنٹ اس کے پلان کے ساتھ، اس کی 5-hour سیشن اور ہفتہ وار حدود میں سے ہر ایک کے لیے ایک میٹر جس میں اس کے reset ہونے تک کا وقت ہو (درست فیصد کے لیے hover کریں)، یا باقی prepaid بیلنس، ایک لائن کے نیچے جو ان سب میں آپ کے استعمال کی چیزوں میں گھومتی رہتی ہے، جیسے اس ہفتے کے ٹوکنز اور آپ کا سب سے زیادہ استعمال شدہ ماڈل۔ _Make something cool_ کے تحت یہ نئی تھیم، پلگ ان، ایپ، یا گیم کے لیے ابتدائی پرامپٹس پیش کرتا ہے جو کام آپ کے ڈیفالٹ ایجنٹ کے حوالے کرتے ہیں۔ ایپس اسی طرح بنائی جاتی ہیں جیسے Omarchy کی اپنی Hype، Monologue، اور Omacut ہیں، C++ اور Qt Quick میں، omarchy-make-app ایجنٹ skill کی پیروی کرتے ہوئے، اور انہیں درکار compiler اور Qt اجزا انسٹال شدہ آتے ہیں۔ گیمز `~/Games/vibes` میں ایک واحد three.js صفحہ ہوتی ہیں، omarchy-make-game ایجنٹ skill کی پیروی کرتے ہوئے، اور سب موجودہ تھیم میں ایک Game Vibes لانچر سے کھلتی ہیں؛ وہ three.js ویب سے لوڈ کرتی ہیں، لہٰذا شروع ہونے کے لیے انہیں کنکشن درکار ہوتا ہے۔ Claude Code، Codex، Grok، Kimi، Cursor اور اس کا Grok Bot الاؤنس، GitHub Copilot، Muse، Antigravity، اور Devin شروع سے ہی اپنی حدود کے ساتھ شامل ہیں، Kimchi اپنے پلان، prepaid کریڈٹس، اور spend بجٹس کے ساتھ، اور Hermes، Mistral Vibe، اور Qwen Code اپنے سیشنز اور ٹوکنز دکھاتے ہیں جب آپ انہیں استعمال کر چکے ہوں۔ pi، omp، یا opencode کے ذریعے استعمال کیے جانے والے Provider پلانز اور keys بھی ظاہر ہوتے ہیں: OpenCode Zen اور Go، Z.ai GLM Coding Plan، Ollama Cloud، MiniMax Token Plan، اور Synthetic اپنی حدود کے ساتھ؛ OpenRouter اور DeepSeek اپنے prepaid بیلنس کے ساتھ؛ Fireworks پچھلے 30 دنوں میں اپنے خرچ کے ساتھ۔ آپ کے اپنے hardware پر چلائے جانے والے ماڈلز کے ٹوکنز بھی مجموعوں میں شمار ہوتے ہیں؛ خود ماڈلز کا اپنا پینل ہوتا ہے، جو [مقامی ماڈل](#local-models) کے تحت بیان کیا گیا ہے۔ ہر ایجنٹ ایک بار شمار ہوتا ہے، اس کے تحت جو بھی اس کا بل دیتا ہے، چاہے آپ اسے کتنے ہی harnesses کے ذریعے چلائیں۔

پینل کے لیے بار آئیکن پر بایاں کلک کریں یا `Super + Ctrl + X` دبائیں، اپنے ڈیفالٹ ایجنٹ کو لانچ کرنے کے لیے دایاں کلک کریں، اور تازہ کرنے کے لیے درمیانی کلک کریں۔ اس کے پیچھے استعمال کے ریکارڈز ہر 15 منٹ بعد `omarchy agent usage update` کے ذریعے دوبارہ بنائے جاتے ہیں، اور پینل synced فولڈر کے ذریعے آپ کی دیگر مشینوں سے استعمال کو بھی ضم کر سکتا ہے۔ مکمل settings کے لیے `$OMARCHY_PATH/shell/plugins/agents/` کے تحت README دیکھیں۔

### متعدد سبسکرپشنز

اگر آپ ایک سے زیادہ Claude، Codex، یا Grok پلان کی ادائیگی کرتے ہیں — مثلاً ایک ذاتی Max اور ایک کام والا — تو Omarchy ان سب کو سائن ان رکھ سکتا ہے اور ان کے درمیان منتقل ہو سکتا ہے۔ ایجنٹس پینل میں + کے ساتھ سبسکرپشن شامل کریں، جو آپ کو وہیں اس کے مراحل سے گزارتا ہے، یا `omarchy agent account add claude Work` کے ساتھ (یا `codex`، یا `grok`)۔ اگر CLI موجود نہیں ہے تو یہ اسے انسٹال کر دیتا ہے۔ کسی provider کے لیے پہلا اکاؤنٹ آپ کے عام براؤزر کے ذریعے سائن ان ہوتا ہے، عین وہیں جہاں CLI ہمیشہ دیکھتا ہے۔ اس کے بعد ہر اکاؤنٹ ایک نجی ونڈو کے ذریعے سائن ان ہوتا ہے، تاکہ جس اکاؤنٹ میں آپ کا براؤزر پہلے سے سائن ان ہے وہ غلطی سے نہ پکڑا جائے؛ وہاں اس اکاؤنٹ کے طور پر سائن ان کریں جسے آپ شامل کر رہے ہیں، اور پہلے سے کھلی ہوئی کوئی بھی نجی ونڈو پہلے بند کر دیں۔ اس کے لیے کبھی CLI سے لاگ آؤٹ نہ کریں: لاگ آؤٹ کرنے سے محفوظ شدہ سائن ان منسوخ ہو جاتا ہے، اور اس اکاؤنٹ کو دوبارہ شامل کرنا پڑے گا۔

اپنی سبسکرپشن لاگ انز کو SSH کے ذریعے کسی دوسری Omarchy مشین پر کاپی کرنے کے لیے، `omarchy agent account copy user@laptop` چلائیں۔ بھیجنے والا ایک عارضی receiver فراہم کرتا ہے جب منزل پر کوئی انسٹال نہ ہو، لہٰذا پرانی Omarchy مشینیں بغیر اپ ڈیٹ کے اکاؤنٹس وصول کر سکتی ہیں۔ انسٹال شدہ receivers کو ترجیح حاصل ہوتی ہے۔ یہ تمام Claude، Codex، اور Grok سبسکرپشنز کاپی کرتا ہے؛ انہیں منتخب کرنے کے لیے provider کے نام شامل کریں، جیسے `omarchy agent account copy laptop claude` میں۔ اکاؤنٹ کے نام اور command IDs ماخذ سے میل کھاتے ہیں، بشمول منزل پر پہلے سے موجود اکاؤنٹس۔ غیر متعلقہ منزل اکاؤنٹس کو عددی لاحقہ ملتا ہے اگر ان کے ناموں میں تصادم ہو، اور settings، skills، پلگ انز، اور گفتگو کی تاریخ ہر مشین پر مقامی رہتی ہے۔

منزل کی موجودہ اسناد برقرار رکھی جاتی ہیں۔ ماخذ اکاؤنٹ جو وہاں پہلے سے سائن ان ہے اس کا نام اس کی اسناد کو بدلے بغیر sync ہو جاتا ہے؛ دیگر اکاؤنٹس اس کے ساتھ شامل کر دیے جاتے ہیں۔ میل کھاتے اکاؤنٹس کے لیے محفوظ شدہ اسناد بدلنے کے لیے، منزل پر اس اکاؤنٹ کے سیشنز بند کرنے کے بعد `omarchy agent account copy --replace laptop claude` استعمال کریں۔ تازہ منزل کو ماخذ کا فعال اکاؤنٹ اور switching ترجیحات بھی ملتی ہیں؛ قائم شدہ منزل اپنی ترجیحات برقرار رکھتی ہے۔

اسناد SSH کے ذریعے سفر کرتی ہیں اور منزل پر نجی فائلوں میں محفوظ ہوتی ہیں، لہٰذا صرف ان مشینوں پر کاپی کریں جن پر آپ بھروسا کرتے ہیں۔ یہ ایک بار کی کاپی ہے، جاری synchronization نہیں۔ Codex refresh ٹوکنز کسی دوسری مشین کے ذریعے rotate ہو سکتے ہیں، جس سے کاپی شدہ لاگ ان کو تجدید کی ضرورت پڑ جاتی ہے؛ متعدد مشینوں پر بیک وقت استعمال کے لیے الگ سائن انز سب سے قابل اعتماد انتخاب رہتے ہیں۔ دیکھیں [Codex کی اکاؤنٹ تصدیق رہنمائی](https://developers.openai.com/codex/auth/ci-cd-auth)۔

فی provider ایک اکاؤنٹ فعال ہوتا ہے، اور ہر نیا سیشن اسی کے طور پر شروع ہوتا ہے: `cx`، `cy`، سادہ `claude`، `codex`، یا `grok`، `omarchy agent` کے ذریعے لانچ کی گئی کوئی بھی چیز، اور اسکرپٹس یا ایڈیٹرز جو CLI کو `PATH` پر پاتے ہیں۔ `omarchy agent account use work` کے ساتھ تبدیل کریں (اور `omarchy agent account use main` کے ساتھ واپس)، یا پینل میں اکاؤنٹ کا نمبر دبا کر پھر `Enter` دبائیں (یا اس کے Use بٹن پر کلک کریں)۔ چلتے ہوئے Claude سیشنز بھی تبدیل ہو جاتے ہیں، ان کے اگلے پیغام سے: ہر Claude سیشن `~/.claude` میں چلتا ہے، جس میں ہمیشہ فعال اکاؤنٹ کا سائن ان ہوتا ہے۔ پرانی Omarchy کے ذریعے اکاؤنٹ کے اپنے فولڈر میں شروع کیا گیا Claude سیشن وہ سائن ان اس وقت تک رکھتا ہے جب تک وہ بند نہ ہو جائے، لہٰذا switch ان سیشنز کے نام بتاتا ہے اور ان کے ختم ہوتے ہی خود مکمل ہو جاتا ہے۔ چلتے ہوئے Codex اور Grok سیشنز اسی اکاؤنٹ پر رہتے ہیں جس سے انہوں نے شروع کیا تھا۔ گفتگو کی تاریخ، settings، skills، اور پلگ انز اکاؤنٹس میں مشترکہ ہوتے ہیں، لہٰذا اسی فولڈر میں `claude --continue` نئے اکاؤنٹ پر وہیں سے اٹھاتا ہے جہاں آپ نے چھوڑا تھا۔

ایک سے زیادہ اکاؤنٹ کے ساتھ، پینل ہر اکاؤنٹ کی حدود ساتھ ساتھ دکھاتا ہے، فعال کو نشان زد کر کے۔ بطور ڈیفالٹ Omarchy آپ کو مطلع کرتا ہے جب فعال اکاؤنٹ کسی حد کے 95% سے گزر جاتا ہے، اور اطلاع پر کلک کرنے سے سب سے زیادہ گنجائش والے اکاؤنٹ پر منتقل ہو جاتا ہے۔ پینل میں اکاؤنٹ کی لائن پر hover کریں اور Use کے ساتھ ظاہر ہونے والے Autoswitch پر کلک کریں (یا `m` دبائیں)، یا `omarchy agent account mode auto` چلائیں، تاکہ یہ خود بخود منتقل ہو جائے؛ جب یہ فعال ہو، تو Autoswitch Use کی جگہ لے لیتا ہے، اور اس پر دوبارہ کلک کرنے سے واپس اطلاع دینے پر آ جاتا ہے۔ حد تبدیل کرنے کے لیے نمبر شامل کریں، جیسے `omarchy agent account mode auto 90` میں۔ اگر ہر اکاؤنٹ حد سے اوپر ہے، تو آپ کو ایک بار اس کے بارے میں سنایا جائے گا، اس کے ساتھ کہ کون سا اکاؤنٹ سب سے پہلے خالی ہوتا ہے۔ جب فعال اکاؤنٹ اپنی حد کے 15 پوائنٹس کے اندر ہوتا ہے (ڈیفالٹ پر 80%)، تو اس کی حدود ہر 15 کے بجائے ہر تین منٹ بعد چیک کی جاتی ہیں۔

`omarchy agent account list` ہر اکاؤنٹ اور اس کی تازہ ترین حدود دکھاتا ہے، `omarchy agent account remove work` ایک کو بھول جاتا ہے، اور `omarchy agent account rename primary Hey` ایک کا نام بدل دیتا ہے (یا پینل میں اکاؤنٹ کے نام پر کلک کریں)۔ یہ کمانڈز آپ کے ڈیفالٹ ایجنٹ کے اکاؤنٹس پر کام کرتی ہیں؛ دوسرے provider تک پہنچنے کے لیے، پہلے اس کا نام بتائیں، جیسے `omarchy agent account use codex side` میں۔ جو لاگ ان آپ کے پاس `~/.claude` یا `~/.codex` میں پہلے سے تھا وہ _Main_ اکاؤنٹ ہے۔ Codex کا وہیں رہتا ہے جہاں وہ ہے؛ Claude کا اپنے فولڈر میں انتظار کرتا ہے جبکہ کوئی دوسرا اکاؤنٹ فعال ہوتا ہے۔ جو اکاؤنٹ تقریباً آٹھ گھنٹے سے زیادہ عرصے سے غیر استعمال شدہ رہا ہو وہ _Sign-in required_ دکھا سکتا ہے؛ پینل میں ہی اس اکاؤنٹ میں دوبارہ سائن ان کرنے کے لیے اس پر کلک کریں، یا اس پر منتقل ہو کر سیشن شروع کریں، جو سائن ان کو خود تازہ کر دیتا ہے۔ `claude mcp add` کے ساتھ شامل کیے گئے MCP سرورز ہر Claude اکاؤنٹ تک پہنچتے ہیں، چونکہ وہ سب `~/.claude` میں چلتے ہیں؛ Codex اور Grok کے لیے، جو سرورز آپ کے پاس اس وقت تھے جب اکاؤنٹ شامل کیا گیا تھا وہ اس کے ساتھ آ جاتے ہیں، لیکن بعد والے صرف اس اکاؤنٹ تک پہنچتے ہیں جس میں آپ نے انہیں شامل کیا تھا۔ Claude Desktop اپنا سائن ان رکھتا ہے، اور CLI بائنری کے مطلق راستے کے ساتھ ترتیب دیے گئے Codex یا Grok ٹولز switch کی پیروی نہیں کرتے۔ واضح `CLAUDE_CONFIG_DIR`، `CODEX_HOME`، یا `GROK_HOME` منتخب اکاؤنٹ پر ترجیح لیتا ہے۔

### کریش کی تشخیص

Omarchy پروسیس کریشز کے لیے systemd-coredump کی نگرانی کرتا ہے۔ جب آپ ڈیفالٹ ایجنٹ منتخب کر لیتے ہیں، تو آپ کا کوئی بھی پروگرام جو core dump کرے وہ "Process crashed" اطلاع لاتا ہے — اس پر کلک کریں، اور کریش آپ کے ڈیفالٹ ایجنٹ کے حوالے کر دیا جاتا ہے Omarchy کی omarchy-diagnose-crash skill کے ساتھ، جو ایجنٹ کو core dump سے حقائق قائم کرنے اور یہ فیصلہ کرنے کے مراحل سے گزارتی ہے کہ آیا کریش upstream رپورٹ کرنے کے قابل ہے۔ آپ اسے `coredumpctl list` سے کسی بھی PID کے خلاف ہاتھ سے بھی `omarchy agent crash <pid>` کے ساتھ چلا سکتے ہیں۔

نگرانی بطور ڈیفالٹ فعال ہے۔ اسے _Trigger > Toggle > Crash Capture Off_ کے تحت بند کر دیں (یا `omarchy toggle crash-capture` کے ساتھ) اور اطلاعات رک جاتی ہیں؛ `omarchy agent crash <pid>` ہاتھ سے پھر بھی کام کرتا ہے۔

کریشز کو ایک وقت میں ایک پروگرام کے حساب سے بھی خاموش کیا جا سکتا ہے، جو تشخیص آخر میں آپ کو پیش کرتی ہے۔ `omarchy crash mute hyprland` صرف اس پروگرام کے لیے اطلاعات روکتا ہے، `omarchy crash mute hyprland off` انہیں واپس لاتا ہے، اور اکیلا `omarchy crash mute` وہ فہرست دیتا ہے جو آپ نے خاموش کی ہے۔ یہ بائنری کا راستہ اس کے نام کی طرح خوشی سے لیتا ہے، لہٰذا `omarchy crash mute /usr/bin/hyprland` بھی وہی کام کرتا ہے۔ جس نام میں جگہ ہو اسے اقتباس میں رکھیں، جیسے `omarchy crash mute 'Some App'` میں۔ باقی سب کچھ پھر بھی مطلع کرتا ہے، اور خاموش کیا گیا پروگرام پھر بھی کریش ہوتا ہے — یہ یاد دہانی چھپاتا ہے، یہ کچھ ٹھیک نہیں کرتا۔

### ڈیسک ٹاپ ایپس

_Install > AI_ مینو میں چند گرافیکل AI ایپس بھی ہیں: Amp Desktop، Antigravity Desktop، ChatGPT ڈیسک ٹاپ ایپ، Claude ڈیسک ٹاپ ایپ (Anthropic کا Linux بیٹا، Chat، Cowork، اور Claude Code ٹیبز کے ساتھ)، xAI کے ماڈلز کے ساتھ چیٹ کے لیے Grok Bot، Herdr Desktop، Hermes Desktop، OpenClaw، Perplexity ڈیسک ٹاپ ایپ، اور T3 Code۔ Grok Bot ڈیسک ٹاپ چیٹ ایپ ہے۔ کوڈنگ ایجنٹ `grok` کمانڈ ہے۔

Hermes Desktop وہ ہے جس کے بارے میں جاننا ضروری ہے، کیونکہ مشین میں ایک Hermes ہوتا ہے، اور وہ ایپ کا ہوتا ہے: Hermes ہمیشہ صرف ایپ کے ذریعے انسٹال ہوتا ہے، اور جو `hermes` کمانڈ ڈیفالٹ ایجنٹ چلاتا ہے وہ ایپ کی ہوتی ہے۔ Hermes کو ڈیفالٹ ایجنٹ کے طور پر منتخب کرنا وہی چیز انسٹال کرتا ہے جو _Install > AI_ اندراج کرتا ہے: پیکیج، اور `~/.hermes` کے تحت ایک Hermes runtime جو Hermes کے اپنے انسٹالر کے ذریعے سیٹ اپ ہوتا ہے، جس میں پہلی بار چند منٹ لگتے ہیں۔ وہ runtime وہی ایک Hermes ہے جسے ٹرمینل `hermes` کمانڈ، ڈیفالٹ ایجنٹ اور ایپ سب استعمال کرتے ہیں، اور یہ Omarchy ریلیز کا انتظار کرنے کے بجائے `hermes update` کے ساتھ خود کو اپ ڈیٹ کرتا ہے۔ اسے انسٹال کرنا Hermes کو Omarchy تھیم بھی `omarchy` نامی skin کے طور پر دیتا ہے، جس کی ہر Hermes سطح پیروی کرتی ہے جب آپ تھیمز تبدیل کرتے ہیں؛ اگر آپ نہیں چاہتے کہ ایسا ہو تو Hermes کی Appearance settings کے تحت یا `/skin` کے ساتھ کوئی اور منتخب کریں، اور Omarchy اس انتخاب کو چھوڑ دیتا ہے۔ _Remove > AI_ کے تحت ایپ ہٹانے سے پہلے Hermes بند ہو جاتا ہے، گیٹ وے سمیت، وہ runtime اس کے ساتھ لے جاتا ہے، اور آپ کی چیٹس، یادیں، اور وہ skills جو Hermes نے اپنے لیے لکھی تھیں برقرار رکھتا ہے الا یہ کہ آپ اسے دوسری صورت کہیں: یہ پوچھتا ہے، ڈیفالٹ نہیں کے ساتھ، کہ آیا وہ ڈیٹا اور آپ کی کنکشن settings بھی جانی چاہئیں۔

OpenClaw کا ڈیسک ٹاپ تجربہ اس کا Control UI ہے، جو اس کے اپنے مقامی گیٹ وے کی پشت پناہی سے ویب ایپ کے طور پر کھلتا ہے۔ OpenClaw `~/.openclaw` میں رہتا ہے اور خود کو اپ ڈیٹ کرتا ہے: Control UI کا "Update Gateway" بٹن استعمال کریں یا `openclaw update` چلائیں، اور گیٹ وے نئے ورژن پر دوبارہ شروع ہو جاتا ہے۔ Omarchy صرف وہ ریلیز منتخب کرتا ہے جس سے تازہ انسٹال شروع ہوتا ہے۔ OpenClaw آپ کا ڈیفالٹ ایجنٹ بھی ہو سکتا ہے: اسے _Agent > Harness_ کے تحت منتخب کرنے سے `~/.openclaw` میں وہی کاپی سیٹ اپ ہو جاتی ہے، اور ایجنٹ اس کے گیٹ وے سے منسلک OpenClaw کا ٹرمینل UI کھولتا ہے۔ _Remove > AI_ کے تحت OpenClaw ہٹانے سے گیٹ وے سروس اور ایپ اس کے ساتھ جاتی ہے اور پھر پوچھتا ہے کہ آیا `~/.openclaw` بھی جانا چاہیے، چونکہ اس میں آپ کی چیٹس اور اسناد OpenClaw کے ساتھ ساتھ اور اس کے ڈاؤن لوڈ کردہ پلگ ان runtimes بھی ہوتے ہیں؛ ڈیفالٹ اسے برقرار رکھتا ہے، اور OpenClaw دوبارہ انسٹال کرنا اسے واپس اٹھا لیتا ہے۔

Herdr Desktop [Herdr](https://herdr.dev) ڈیسک ٹاپ ایپ ہے: ٹرمینلز اور کوڈنگ ایجنٹس کے spaces، ٹیبز، اور panes جو ونڈو بند کرنے پر اس کے core میں چلتے رہتے ہیں۔ یہ پیکیج کے بجائے Herdr کے اپنے انسٹالر سے آتی ہے، لہٰذا یہ `~/.local/share/herdr-app` میں رہتی ہے، جب آپ کے پاس پہلے سے کوئی نہ ہو تو `~/.local/bin/herdr-core` میں اپنا core ساتھ لاتی ہے، اور دونوں خود کو اپ ڈیٹ کرتے ہیں۔ یہ اس `herdr` کمانڈ کے ساتھ بیٹھتی ہے جو Omarchy `Super + Ctrl + Return` پر فراہم کرتا ہے، اسے بدلنے کے بجائے، اور اس کمانڈ کی براہ راست keys حاصل کرتی ہے: `Alt + Return` اور `Alt + Shift + Return` pane کو نیچے یا دائیں تقسیم کرتے ہیں، `Alt + Escape` اسے بند کرتا ہے، `Ctrl + Alt + Arrow` panes کے درمیان منتقل ہوتا ہے، `Alt + 1..9` اور `Alt + Left/Right` ٹیب منتخب کرتے ہیں، اور `Alt + Up/Down` spaces کے درمیان منتقل ہوتے ہیں۔ `Ctrl + 1..9` space منتخب کرتا ہے اور `Alt + Shift + Up/Down` ایجنٹس میں مرحلہ وار چلتا ہے۔ `Ctrl + Space` prefix keys صرف ٹرمینل کے لیے رہتی ہیں، چونکہ ایپ ترتیب کے لیے سادہ Ctrl key نہیں پکڑ سکتی۔ Omarchy یہ `~/.config/herdr-app/keys.json` میں لکھتا ہے، اور `omarchy-refresh-herdr-app` انہیں واپس رکھ دیتا ہے۔ اسے انسٹال کرنا Herdr کی Omarchy تھیم منتخب کرتا ہے، جو اس کے بعد سے آپ کی Omarchy تھیم کی پیروی کرتی ہے۔ Herdr ہلکے موڈ کے لیے ایک تھیم اور گہرے موڈ کے لیے ایک رکھتا ہے، لہٰذا گہری اور ہلکی Omarchy تھیم کے درمیان تبدیل کرنے کے بعد، دوسرے موڈ کے لیے Herdr کے تھیم picker میں Omarchy ایک بار پھر منتخب کریں۔

T3 Code پیکیج کے بجائے `~/.local/share/t3code` میں اپنی آفیشل AppImage ریلیز سے چلتا ہے، لہٰذا یہ خود کو اپ ڈیٹ کرتا ہے۔ اسے انسٹال کرنا پوچھتا ہے کہ Stable یا Nightly چینل پر شروع کرنا ہے؛ بعد میں T3 Code کی settings میں تبدیل کریں۔ آپ کے تھریڈز اور settings `~/.t3` میں رہتے ہیں، اور _Remove > AI_ کے تحت T3 Code ہٹانا انہیں اس کے ساتھ لے جاتا ہے۔

### مقامی ماڈل

اپنے کوڈنگ ایجنٹس کے لیے اپنی مشین پر open ماڈل چلائیں۔ آپ کے پرامپٹس اور کوڈ مشین پر رہتے ہیں؛ ماڈل کو بھیجی گئی کوئی چیز اسے نہیں چھوڑتی۔ اس سے شروع کریں:

```bash
omarchy models use best text
```

یہ اس مشین کے لیے بہترین text ماڈل سیٹ اپ کرتا ہے، وہ قسم جو آپ کے ایجنٹس استعمال کرتے ہیں۔ Image، video اور music ماڈلز کا اپنا بہترین ہوتا ہے: `omarchy models use best image`، `video` یا `music`۔ اس مشین کے لیے ہر قسم کا انتخاب دیکھنے کے لیے `omarchy models use best` چلائیں۔

یا اوپر والی بار میں ایجنٹس آئیکن کے ساتھ اس کے sparkles آئیکن سے، یا Super + Ctrl + Shift + X کے ساتھ، مقامی ماڈلز پینل کھولیں، اور + منتخب کریں۔ آئیکن اس وقت ظاہر ہوتا ہے جب کوئی ماڈل اس مشین میں فٹ آتا ہے۔ Podman، جو ماڈلز چلاتا ہے، Omarchy کے ساتھ آتا ہے، اسی طرح NVIDIA مشین پر NVIDIA کا container toolkit بھی، جو انہیں GPU دیتا ہے؛ اگر کوئی بھی غائب ہو، تو پہلا سیٹ اپ اسے انسٹال کر دیتا ہے۔ پھر Omarchy اس مشین کے لیے تجویز کردہ ماڈل منتخب کرتا ہے، اسے ڈاؤن لوڈ کرتا ہے، اور شروع کرتا ہے۔ دسیوں GB کے ڈاؤن لوڈ کی توقع رکھیں اور ماڈل چلتے وقت مشین کی زیادہ تر میموری استعمال میں ہوگی: Flash Next اپنے مکمل 256K context کے ساتھ تقریباً 100 GiB استعمال کرتا ہے۔ اگر دیگر ماڈلز اسے درکار میموری رکھے ہوئے ہیں، تو یہ رکا ہوا سیٹ اپ ہوتا ہے، جب آپ ایک کو روکیں تو شروع ہونے کے لیے تیار۔ ماڈل لاگ آؤٹ پر رک جاتا ہے؛ جب آپ کو کسی اور چیز کے لیے میموری درکار ہو تو اسے خود روک دیں۔

`omarchy models list` اختیارات دکھاتا ہے اور بتاتا ہے کہ کچھ کیوں فٹ نہیں آتے۔ کوئی اور سیٹ اپ کرنے کے لیے، `omarchy models use <recipe>` چلائیں۔ آج، 128 GB Strix Halo مشینوں کے لیے `qwen3.8-flash-next-gufo` اور `qwen3.8-27b-gufo` دستیاب ہیں؛ 27B تقریباً 40 GiB لیتا ہے، لہٰذا یہ دیگر کام کے لیے جگہ چھوڑ دیتا ہے۔ Intel کے Arc B390 والے 64 GB لیپ ٹاپ پر، `qwen3.6-35b-a3b-llamacpp` تقریباً 30 GiB میں چلتا ہے۔ نئی recipes اور تجاویز پیکیج کے ذریعے `omarchy update` کے ساتھ آتی ہیں۔

آپ کے سیٹ اپ کردہ ہر ماڈل کو مقامی ماڈلز پینل میں اپنی لائن ملتی ہے: شروع کرنے کے لیے play، روکنے اور اس کی میموری خالی کرنے کے لیے pause، اور اس پر اپنا ایجنٹ کھولنے کے لیے ٹرمینل بٹن۔ اوپر کے پار، ایک بار دکھاتا ہے کہ مشین کی میموری Omarchy خود (سسٹم اور آپ کی ایپس)، ہر چلتے ماڈل، اور جو خالی ہے اس کے درمیان کیسے تقسیم ہے۔ رکے ہوئے ماڈل کی طرف اشارہ کریں اور بار دکھاتا ہے کہ آیا یہ فٹ آتا ہے، یا یہ کتنا کم ہے۔ کئی ایک ساتھ چل سکتے ہیں جب وہ میموری میں ایک ساتھ فٹ آتے ہوں؛ اگر ایک فٹ نہ آئے، تو Omarchy بتاتا ہے کہ کون سا چلتا ماڈل روکنا ہے۔ لائنز کو ان کے لوگو سے گھسیٹ کر دوبارہ ترتیب دیں، اور منتخب لائن پر Delete دبائیں تاکہ ماڈل اور اس کا ڈاؤن لوڈ ہٹ جائے۔

آپ کے سیٹ اپ کردہ ہر ماڈل کو ایپ لانچر میں بھی اپنا اندراج ملتا ہے، ماڈل کے نام کے تحت اور اس کے بنانے والے کے لوگو کے ساتھ، اسی طرح جیسے Claude، Codex یا Grok میں سائن ان کرنا ایک شامل کرتا ہے۔ یہ اس ماڈل پر آپ کا ایجنٹ کھولتا ہے، اور اگر ماڈل نہیں چل رہا ہو تو پہلے اسے شروع کرتا ہے: ٹرمینل اسے لوڈ ہوتا دکھاتا ہے اور جب یہ تیار ہو جائے تو ایجنٹ کے حوالے کر دیتا ہے۔ ماڈل ہٹانے سے اس کا اندراج ہٹ جاتا ہے۔

ہر ماڈل کوڈنگ کے لیے نہیں ہوتا۔ Image، video اور music ماڈلز اس کے بجائے Fantasi میں کھلتے ہیں، Omarchy کی ایپ اس مشین پر چلنے والے ماڈل کے ساتھ تصویریں، video اور music بنانے کے لیے، ان کے لانچر اندراج سے اور مقامی ماڈلز پینل میں ان کی لائن سے۔

ماڈل عین اسی طرح چلتا رہتا ہے جیسے اسے سیٹ اپ کیا گیا تھا، لہٰذا Omarchy اپ ڈیٹ کبھی آپ کے ایجنٹس کے تحت اسے دوبارہ شروع نہیں کرتا۔ جب Omarchy کے پاس آپ کے سیٹ اپ کردہ ماڈل کے لیے نیا runtime یا نئے weights ہوں، تو اس کی لائن اپ ڈیٹ بٹن دکھاتی ہے: اسے دبائیں اور ماڈل پس منظر میں دوبارہ سیٹ اپ ہو جاتا ہے، صرف وہی ڈاؤن لوڈ کرتا ہے جو تبدیل ہوا ہو، اور نئے ورژن پر دوبارہ شروع ہو جاتا ہے۔ جو ماڈل رکا ہوا تھا وہ رکا رہتا ہے۔ `omarchy models update` ٹرمینل سے ہر ماڈل کے لیے وہی کرتا ہے۔

کمانڈ لائن سے، `omarchy models start <recipe>` اور `omarchy models stop <recipe>` وہی کرتے ہیں، `omarchy models status` ہر ماڈل دکھاتا ہے، اور `omarchy agent --local` آپ کے ڈیفالٹ ایجنٹ کو آخری ماڈل پر کھولتا ہے جو آپ نے شروع کیا تھا۔ pi، OpenCode اور Qwen Code ایک استعمال کر سکتے ہیں؛ کسی اور ڈیفالٹ کے ساتھ یہ pi میں کھلتا ہے، یا OpenCode میں اگر آپ کے پاس pi نہ ہو۔ pi آپ کے سیٹ اپ کردہ ہر ماڈل، اور جن مشینوں کے ساتھ آپ نے جوڑا بنایا ہے ان پر موجود ماڈلز کو بھی، اپنے ماڈل picker میں فہرست کرتا ہے، لہٰذا سادہ `pi` بھی ان تک پہنچتا ہے۔ کوئی بھی OpenAI-compatible کلائنٹ بھی جڑ سکتا ہے: `status` ہر ماڈل کا پتہ دکھاتا ہے (پہلا `http://127.0.0.1:11435/v1` ہے)، recipe نام ماڈل ہے، اور key `~/.config/omarchy/agent-local/key` میں ہے۔

`omarchy models remove <recipe>` ماڈل اور وہ ڈاؤن لوڈز حذف کر دیتا ہے جو کوئی اور ماڈل استعمال نہیں کرتا۔

تھرڈ پارٹی runtimes کو ان کے publisher کے ساتھ لیبل کیا جاتا ہے۔ Omarchy ہر ماڈل کو بغیر نیٹ ورک رسائی کے چلاتا ہے۔

### مقامی LLMs

Omarchy مقامی LLM ماڈلز چلانے کے دو طریقے تجویز کرتا ہے: LM Studio اور Ollama۔ LM Studio open-weight ماڈلز تلاش کرنے، انہیں انسٹال کرنے، اور چلانے کے لیے GUI انٹرفیس فراہم کرتا ہے۔ آسانی سے شروع کرنے کا یہ بہترین طریقہ ہے۔ Ollama اسی طرح کرنے کے لیے CLI پیش کرتا ہے۔ لیکن اگر آپ مقامی ماڈلز میں نئے ہیں، تو میں LM Studio سے شروع کروں گا۔ آپ Omarchy Menu میں _Install > AI_ کے تحت کوئی بھی انسٹال کر سکتے ہیں۔

### Omarchy skills

ایجنٹ skills AI کو مخصوص ٹولز کو مخصوص طریقے سے استعمال کرنے میں مدد دیتی ہیں، اور Omarchy ان میں سے سات فراہم کرتا ہے۔ omarchy skill سسٹم کو اپنی پسند کے مطابق بنانے کا احاطہ کرتی ہے، جیسے آپ کی Hyprland config کو ٹھیک کرنا یا بار کو ایڈجسٹ کرنا۔ omarchy-make-theme، omarchy-make-plugin، omarchy-make-app، اور omarchy-make-game کچھ نیا بنانے کا احاطہ کرتی ہیں، omarchy-contribute بگ رپورٹ کرنے یا upstream فکس بھیجنے کا احاطہ کرتی ہے، اور omarchy-diagnose-crash کریش کے core dump پر کام کرتی ہے۔ وہ Claude Code (`~/.claude/skills`)، Codex (`~/.codex/skills`)، Pi (`~/.pi/agent/skills`)، Antigravity (`~/.gemini/config/skills`)، Hermes (`~/.hermes/skills` اور ہر `~/.hermes/profiles/*/skills`)، اور عمومی `~/.agents/skills` مقام کے لیے skill ڈائریکٹریوں میں symlink کی گئی ہیں، لہٰذا زیادہ تر harnesses انہیں خود بخود اٹھا لیتے ہیں۔ اسی نام کا آپ کا اپنا skill فولڈر ترجیح لیتا ہے۔

لیکن آپ کو ان skills کو تجرباتی سمجھنا چاہیے۔ مختلف ماڈلز اسے مختلف اثر کے ساتھ استعمال کریں گے۔ پہلے plan موڈ میں چلانا بہتر ہے، تاکہ آپ کو اندازہ ہو کہ ایجنٹ کیا تبدیل کرنا چاہے گا۔ اور پھر تبدیلیاں واپس لینے یا حتیٰ کہ `omarchy reinstall configs` چلانے کے لیے بھی تیار رہیں، اگر ایجنٹ ہر چیز کا ستیاناس کر دے۔
