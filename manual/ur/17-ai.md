### ایجنٹس انسٹال اور اپ ڈیٹ کرنا

Hermes کے علاوہ، یہ ایجنٹس mise کی سست انسٹالیشن استعمال کرتے ہیں: پہلی لانچ پر CLI انسٹال ہوتا ہے، اور بعد کی لانچز اسی کو دوبارہ استعمال کرتی ہیں۔ mise انسٹال شدہ ایجنٹ کے لیے نئی ریلیز بھی زیادہ سے زیادہ ہر چار گھنٹے میں ایک بار چیک کرتا ہے، اس کے شروع ہونے سے عین پہلے یا شیل پرامپٹ پر پس منظر میں۔ اگر وہ اپ ڈیٹ ناکام ہو جائے یا آپ آف لائن ہوں، تو انسٹال شدہ ورژن ہی چلتا ہے۔ `omarchy update` انسٹال شدہ ایجنٹس کو باقی Omarchy کے ساتھ اپ ڈیٹ کرتا ہے، اور `mup` صرف mise کے زیر انتظام ٹولز کو اپ ڈیٹ کرتا ہے۔

کسی ایجنٹ کا اپنا اپ ڈیٹر، جیسے `claude update`، `codex update`، یا کسی ایپ میں اپ ڈیٹ کا بٹن، mise کے زیر انتظام انسٹال کو اپ ڈیٹ نہیں کرتا۔ `codex update` ناکام ہو جاتا ہے، اور `claude update` کامیابی کی اطلاع دے سکتا ہے جبکہ وہ ایک الگ کاپی انسٹال کر رہا ہو جسے mise ٹریک نہیں کرتا۔ اگر آپ اس کے بجائے کسی ایجنٹ کا مقامی انسٹالر اور اپ ڈیٹر استعمال کرنا چاہیں، تو اسے `disable_tools` میں شامل کریں؛ دیکھیں [پہلے سے انسٹال شدہ CLI ٹولز](18-development-tools.md#preinstalled-cli-tools)۔

تمام ترتیب شدہ سست ٹولز کو ضرورت پڑنے سے پہلے انسٹال کرنے کے لیے، `mise install --include-lazy` چلائیں۔ اس میں ایجنٹس کے ساتھ ساتھ Omarchy کے دیگر ڈیفالٹ CLI ٹولز بھی شامل ہیں۔ ایک ہی ٹول انسٹال کرنے یا اپنی انسٹالیشن استعمال کرنے کے لیے [پہلے سے انسٹال شدہ CLI ٹولز](18-development-tools.md#preinstalled-cli-tools) دیکھیں۔

`grok` mise کے فرسٹ پارٹی `grok` پیکیج کے ذریعے انسٹال ہوتا ہے، اسی طرح جیسے `claude` اور `codex`۔ `grok` چلائیں، یا اسے _ایجنٹ > ہارنس_ میں منتخب کریں۔ x.ai پر `curl | bash` انسٹالر سے گریز کریں۔ وہ راستہ `~/.grok/bin` میں دوسری کاپی رکھتا ہے، اسے `PATH` کے شروع میں شامل کرتا ہے، اور Omarchy کے ریپر کو اوور رائٹ کر دیتا ہے۔

`dsh` اپنا براؤزر UI `127.0.0.1:3080` پر کھولتا ہے، جس میں لانچ والی ڈائریکٹری اس کی ڈیفالٹ ورک اسپیس ہوتی ہے۔ اس کا براؤزر UI کوئی ابتدائی پرامپٹ نہیں لیتا، چنانچہ `omarchy agent prompt` اسے یوں کھولتا ہے کہ پرامپٹ آپ کے کلپ بورڈ پر چسپاں کرنے کے لیے موجود ہوتا ہے۔ Omarchy اسے DeepSeek کے بغیر منظوری والے اجازت پری سیٹ کے ساتھ شروع کرتا ہے۔ جب آپ اس کا سرکاری ماڈل API استعمال کرتے ہیں تو DeepSeek Harness سیشن لاگز DeepSeek کو اپ لوڈ کرتا ہے؛ اسے اس کے براؤزر UI میں _ترتیبات > عمومی > سیشن لاگ اپ لوڈ کریں_ میں بند کریں۔ آپ جو رائے اسے بھیجتے ہیں وہ بھی سیشن کے ساتھ اپ لوڈ ہوتی ہے، الا یہ کہ آپ اسے `DSH_TELEMETRY_MODE=DISABLED` کے ساتھ شروع کریں۔

### ڈیفالٹ ایجنٹ

اپنا ڈیفالٹ ایجنٹ `omarchy default agent <name>` سے یا Omarchy Menu (`Super + Space`) میں _ایجنٹ > ہارنس_ میں منتخب کریں۔ اگر ایجنٹ ابھی انسٹال نہیں ہوا، تو اسے منتخب کرنے پر پہلے وہ انسٹال ہو جائے گا۔ نئی Omarchy ایک بار کی اطلاع کے ساتھ آپ کو یہ انتخاب کرنے کی دعوت دے گی۔

Claude کو منتخب کرنے پر اس کی براؤزر ایکسٹینشن کو Chromium، Chrome، Brave، Brave Origin، اور Edge کے لیے ترتیب دینے کی بھی کوشش کی جاتی ہے۔ ایکسٹینشن کی ترتیب تمام صارفین پر لاگو ہوتی ہے اور آپ سے آپ کا سسٹم پاس ورڈ مانگ سکتی ہے؛ منسوخ کرنے یا ایکسٹینشن کی انسٹالیشن ناکام ہونے پر بھی Claude منتخب اور لانچ ہو جاتا ہے۔ اپنا براؤزر دوبارہ شروع کریں، کہا جائے تو ایکسٹینشن فعال کریں، اور اسے جوڑنا مکمل کرنے کے لیے Claude میں سائن ان کریں۔ کنیکشن چیک کرنے کے لیے Claude میں `/chrome` چلائیں۔ Firefox اور Zen اس ایکسٹینشن کی حمایت نہیں کرتے۔ اگر یہ ترتیب شامل ہونے سے پہلے ہی Claude آپ کا ڈیفالٹ تھا، تو ایکسٹینشن انسٹال کرنے کے لیے اسے دوبارہ منتخب کریں۔

منتخب کرنے کے بعد، `Super + Shift + Ctrl + A` ڈیفالٹ ایجنٹ کو ایک مخصوص ٹرمینل ونڈو میں لانچ کرتا ہے (یا اگر آپ نے ابھی انتخاب نہیں کیا تو چننے والا سامنے لاتا ہے)۔ آپ اسے `omarchy agent prompt "Review this project"` سے سیدھا کسی کام میں بھی لانچ کر سکتے ہیں۔ Freebuff اور DeepSeek Harness کوئی ابتدائی پرامپٹ نہیں لیتے، چنانچہ وہ اس کے بجائے یوں کھلتے ہیں کہ پرامپٹ آپ کے کلپ بورڈ پر چسپاں کرنے کے لیے موجود ہوتا ہے۔ اس طرح لانچ کیے گئے ایجنٹس اپنے متعلقہ رکنے اور پوچھنے سے گریز والے انداز میں بغیر نگرانی چلتے ہیں، لہٰذا تیار رہیں کہ وہ واقعی کچھ کر گزریں گے! MiniMax Code کے انٹرایکٹو سیشنز کے لیے ایسا کوئی انداز نہیں، چنانچہ وہ معمول کے مطابق اجازتیں مانگتا ہے۔ اور چونکہ ایجنٹس آپ کی ہوم ڈائریکٹری کے لیے اعتماد یاد رکھنے سے انکار کرتے ہیں، اس لیے `$HOME` سے لانچ اس کے بجائے `~/Work` میں شروع ہوتی ہیں۔

ٹرمینل شارٹ کٹس بھی ہیں: `a` موجودہ ٹرمینل میں ڈیفالٹ ایجنٹ کو ان لائن چلاتا ہے، جبکہ `c`، `cx`، اور `cy` OpenCode، Claude Code، اور Codex کو براہ راست شروع کرتے ہیں (ایک بار پھر ان کے خودکار منظوری والے انداز میں)۔ تھیم کی تبدیلیاں ایجنٹس کے ساتھ بھی ہم آہنگ ہوتی ہیں: جب آپ Omarchy کی تھیم بدلتے ہیں تو Claude Code، Pi، OpenCode، اور Hermes (جب Omarchy نے اسے انسٹال کر لیا ہو) سب اس کے ساتھ بدلتے ہیں۔

### آپ کی ایجنٹ ہدایات

ہر ایجنٹ کے لیے ذاتی قواعد `~/.agents/AGENTS.md` میں جاتے ہیں، `~/.agents/skills` میں مشترکہ مہارتوں کے ساتھ۔ اسے _ایجنٹ > ہدایات_ میں کھولیں، جو اسے ہر اس ہارنس میں بھی لنک کرتا ہے جو اپنی عالمی فائل رکھتا ہے: `~/.claude/CLAUDE.md`، `~/.codex/AGENTS.md`، `~/.pi/agent/AGENTS.md`، `~/.config/opencode/AGENTS.md`، Copilot کی `~/.copilot/copilot-instructions.md`، وغیرہ۔ Crush اور Amp `~/.config/AGENTS.md` لنک پڑھتے ہیں، جبکہ omp، Kimi، اور DeepSeek Harness براہ راست `~/.agents/AGENTS.md` پڑھتے ہیں۔ ڈیفالٹ ایجنٹ منتخب کرنے پر بھی یہ لنک ہو جاتا ہے۔ اگر ابھی کوئی مشترکہ فائل نہیں تھی تو آپ کی پہلے سے موجود ہدایات والی فائل مشترکہ فائل بن جاتی ہے؛ بصورت دیگر اسے لنک کے ساتھ `.bak` کے طور پر رکھا جاتا ہے۔ ایک اور ایجنٹ انسٹال کرنے کے بعد دوبارہ لنک کرنے کے لیے `omarchy agent instructions` چلائیں۔

### ایجنٹس پینل

اوپر والی بار میں ایجنٹس کا آئیکن ہے۔ ایجنٹ ترتیب دینے سے پہلے، اس کا پینل آپ کو Claude، Codex، یا Grok میں سائن ان کرنے کے مراحل سے گزارتا ہے، اور پہلا والا آپ کا ڈیفالٹ ایجنٹ بن جاتا ہے۔ اس کے بعد، پینل ہر سبسکرپشن کو ایک صفحے پر رکھتا ہے: ہر ایجنٹ اور اکاؤنٹ اس کے پلان کے ساتھ، اس کی 5 گھنٹے کے سیشن اور ہفتہ وار حدود میں سے ہر ایک کے لیے ایک میٹر جس میں اس کے دوبارہ ترتیب پانے تک کا وقت دکھایا جاتا ہے (درست فیصد کے لیے ہوور کریں)، یا باقی پری پیڈ بیلنس، ایک سطر کے نیچے جو ان سب میں آپ کے استعمال کی چیزوں میں گھومتی رہتی ہے، جیسے اس ہفتے کے ٹوکنز اور آپ کا سب سے زیادہ استعمال شدہ ماڈل۔ _کچھ بنائیں_ کے تحت یہ نئی تھیم، پلگ ان، ایپ، یا گیم کے لیے ابتدائی پرامپٹس پیش کرتا ہے جو کام آپ کے ڈیفالٹ ایجنٹ کے حوالے کرتے ہیں۔ ایپس اسی طرح بنائی جاتی ہیں جیسے Omarchy کی اپنی Hype، Monologue، اور Omacut ہیں، C++ اور Qt Quick میں، omarchy-make-app ایجنٹ مہارت کی پیروی کرتے ہوئے، اور انہیں درکار کمپائلر اور Qt کے حصے انسٹال شدہ آتے ہیں۔ گیمز `~/Games/vibes` میں ایک واحد three.js صفحہ ہوتی ہیں، omarchy-make-game ایجنٹ مہارت کی پیروی کرتے ہوئے، اور سب موجودہ تھیم میں ایک ہی Game Vibes لانچر سے کھلتی ہیں؛ وہ three.js ویب سے لوڈ کرتی ہیں، چنانچہ شروع ہونے کے لیے انہیں کنیکشن درکار ہوتا ہے۔ Claude Code، Codex، Grok، Kimi، Cursor اور اس کا Grok Bot الاؤنس، GitHub Copilot، Muse، Antigravity، Kimchi، اور Devin اپنی حدود کے ساتھ پہلے سے شامل ہیں، اور Hermes، Mistral Vibe، اور Qwen Code جب آپ انہیں استعمال کر لیں تو اپنے سیشنز اور ٹوکنز دکھاتے ہیں۔ pi، omp، یا opencode کے ذریعے استعمال کیے گئے فراہم کنندہ پلانز اور کیز بھی دکھائی دیتی ہیں: OpenCode Zen اور Go، Z.ai GLM Coding Plan، Ollama Cloud، MiniMax Token Plan، اور Synthetic اپنی حدود کے ساتھ؛ Fireworks، OpenRouter، اور DeepSeek اپنے پری پیڈ بیلنس کے ساتھ؛ اور وہ ماڈلز جو آپ اپنے ہارڈویئر پر چلاتے ہیں، Local models کے تحت۔ ہر ایجنٹ ایک بار گنا جاتا ہے، اس کے بل کرنے والے کے تحت، خواہ آپ اسے کتنے ہی ہارنسز سے چلائیں۔

پینل کے لیے بار آئیکن پر بایاں کلک کریں، اپنے ڈیفالٹ ایجنٹ کو لانچ کرنے کے لیے دایاں کلک کریں۔ اس کے پیچھے استعمال کے ریکارڈ ہر 15 منٹ بعد `omarchy agent usage-update` سے دوبارہ بنائے جاتے ہیں، اور پینل ایک ہم آہنگ فولڈر کے ذریعے آپ کی دیگر مشینوں سے استعمال کو بھی ضم کر سکتا ہے۔ مکمل ترتیبات کے لیے `$OMARCHY_PATH/shell/plugins/agents/` کے تحت README دیکھیں۔

### متعدد سبسکرپشنز

اگر آپ ایک سے زیادہ Claude، Codex، یا Grok پلان کی ادائیگی کرتے ہیں — مثلاً ایک ذاتی Max اور ایک کام والا — تو Omarchy ان سب کو سائن ان رکھ سکتا ہے اور ان کے درمیان منتقل ہو سکتا ہے۔ ایجنٹس پینل میں + سے سبسکرپشن شامل کریں، جو آپ کو وہیں اس کے مراحل سے گزارتا ہے، یا `omarchy agent account add claude Work` (یا `codex`، یا `grok`) سے۔ اگر CLI موجود نہیں تو یہ اسے انسٹال کر دیتا ہے۔ کسی فراہم کنندہ کے لیے پہلا اکاؤنٹ آپ کے معمول کے براؤزر سے سائن ان ہوتا ہے، عین وہیں جہاں CLI ہمیشہ دیکھتا ہے۔ اس کے بعد ہر ایک نجی ونڈو کے ذریعے سائن ان ہوتا ہے، تاکہ جس اکاؤنٹ میں آپ کا براؤزر پہلے سے سائن ان ہے وہ غلطی سے نہ پکڑا جائے؛ وہاں اس اکاؤنٹ کے طور پر سائن ان کریں جسے آپ شامل کر رہے ہیں، اور پہلے سے کھلی ہوئی کوئی نجی ونڈو پہلے بند کر دیں۔ یہ کرنے کے لیے CLI سے کبھی لاگ آؤٹ نہ ہوں: لاگ آؤٹ کرنے سے محفوظ شدہ سائن ان منسوخ ہو جاتا ہے، اور اس اکاؤنٹ کو دوبارہ شامل کرنا پڑے گا۔

اپنے سبسکرپشن لاگ انز کو SSH کے ذریعے دوسری Omarchy مشین پر نقل کرنے کے لیے، `omarchy agent account copy user@laptop` چلائیں۔ جب منزل پر کوئی وصول کنندہ انسٹال نہ ہو تو بھیجنے والا ایک عارضی وصول کنندہ فراہم کرتا ہے، تاکہ پرانی Omarchy مشینیں بغیر اپ ڈیٹ کے اکاؤنٹس وصول کر سکیں۔ انسٹال شدہ وصول کنندگان کو ترجیح حاصل ہوتی ہے۔ یہ تمام Claude، Codex، اور Grok سبسکرپشنز نقل کرتا ہے؛ انہیں منتخب کرنے کے لیے فراہم کنندگان کے نام شامل کریں، جیسے `omarchy agent account copy laptop claude` میں۔ اکاؤنٹ کے نام اور کمانڈ IDs ماخذ سے ملتے ہیں، بشمول منزل پر پہلے سے موجود اکاؤنٹس۔ اگر ان کے نام ٹکراتے ہیں تو غیر متعلق منزل اکاؤنٹس کو عددی لاحقہ ملتا ہے، اور ترتیبات، مہارتیں، پلگ انز، اور گفتگو کی تاریخ ہر مشین پر مقامی رہتی ہے۔

منزل کی موجودہ اسناد برقرار رکھی جاتی ہیں۔ کوئی ماخذ اکاؤنٹ جو وہاں پہلے سے سائن ان ہو، اس کا نام اس کی اسناد بدلے بغیر ہم آہنگ ہو جاتا ہے؛ دیگر اکاؤنٹس اس کے ساتھ شامل ہو جاتے ہیں۔ ملتے جلتے اکاؤنٹس کے لیے محفوظ شدہ اسناد بدلنے کے لیے، منزل پر اس اکاؤنٹ کے سیشنز بند کرنے کے بعد `omarchy agent account copy --replace laptop claude` استعمال کریں۔ نئی منزل کو ماخذ کا فعال اکاؤنٹ اور تبدیلی کی ترجیحات بھی ملتی ہیں؛ قائم شدہ منزل اپنی ترجیحات برقرار رکھتی ہے۔

اسناد SSH کے ذریعے سفر کرتی ہیں اور منزل پر نجی فائلوں میں محفوظ ہوتی ہیں، چنانچہ صرف ان مشینوں پر نقل کریں جن پر آپ اعتماد کرتے ہیں۔ یہ ایک بار کی نقل ہے، جاری ہم آہنگی نہیں۔ Codex کے ریفریش ٹوکنز دوسری مشین کے ذریعے بدلے جا سکتے ہیں، جس سے نقل شدہ لاگ ان کو تجدید کی ضرورت پڑ سکتی ہے؛ کئی مشینوں پر بیک وقت استعمال کے لیے الگ سائن ان سب سے قابل اعتماد انتخاب رہتے ہیں۔ دیکھیں [Codex کی اکاؤنٹ تصدیق رہنمائی](https://developers.openai.com/codex/auth/ci-cd-auth)۔

فی فراہم کنندہ ایک اکاؤنٹ فعال ہوتا ہے، اور ہر نیا سیشن اسی کے طور پر شروع ہوتا ہے: `cx`، `cy`، سادہ `claude`، `codex`، یا `grok`، `omarchy agent` کے ذریعے لانچ کی گئی کوئی بھی چیز، اور اسکرپٹس یا ایڈیٹرز جو CLI کو `PATH` پر پاتے ہیں۔ `omarchy agent account use work` سے بدلیں (اور `omarchy agent account use main` سے واپس)، یا پینل میں کسی اکاؤنٹ کا نمبر دبا کر پھر `Enter` دبا کر (یا اس کے Use بٹن پر کلک کر کے)۔ چلتے ہوئے Claude سیشنز بھی بدل جاتے ہیں، ان کے اگلے پیغام سے: ہر Claude سیشن `~/.claude` میں چلتا ہے، جس میں ہمیشہ فعال اکاؤنٹ کا سائن ان ہوتا ہے۔ کسی پرانی Omarchy کے ذریعے اکاؤنٹ کے اپنے فولڈر میں شروع کیا گیا Claude سیشن بند ہونے تک وہ سائن ان رکھتا ہے، چنانچہ تبدیلی ان سیشنز کا نام لیتی ہے اور ان کے ختم ہوتے ہی خود مکمل ہو جاتی ہے۔ چلتے ہوئے Codex اور Grok سیشنز اسی اکاؤنٹ پر رہتے ہیں جس سے وہ شروع ہوئے تھے۔ گفتگو کی تاریخ، ترتیبات، مہارتیں، اور پلگ انز اکاؤنٹس میں مشترکہ ہوتے ہیں، چنانچہ اسی فولڈر میں `claude --continue` نئے اکاؤنٹ پر وہیں سے جاری رہتا ہے جہاں آپ نے چھوڑا تھا۔

ایک سے زیادہ اکاؤنٹ ہونے پر، پینل ہر اکاؤنٹ کی حدود ساتھ ساتھ دکھاتا ہے، جس میں فعال اکاؤنٹ نشان زد ہوتا ہے۔ بطور ڈیفالٹ Omarchy آپ کو اطلاع دیتا ہے جب فعال اکاؤنٹ کسی حد کے 95% سے گزر جاتا ہے، اور اطلاع پر کلک کرنے سے سب سے زیادہ گنجائش والے اکاؤنٹ پر تبدیلی ہو جاتی ہے۔ پینل میں کسی اکاؤنٹ کی سطر پر ہوور کریں اور Use کے ساتھ ظاہر ہونے والے Autoswitch پر کلک کریں (یا `m` دبائیں)، یا `omarchy agent account mode auto` چلائیں، تاکہ یہ خود بخود بدل جائے؛ جب یہ فعال ہو، تو Autoswitch Use کی جگہ لے لیتا ہے، اور اس پر دوبارہ کلک کرنے سے واپس اطلاع دینے پر آ جاتا ہے۔ حد بدلنے کے لیے نمبر شامل کریں، جیسے `omarchy agent account mode auto 90` میں۔ اگر ہر اکاؤنٹ حد سے اوپر ہو، تو آپ کو ایک بار اس کی اطلاع ملے گی، اس کے ساتھ کہ کون سا اکاؤنٹ سب سے پہلے آزاد ہوتا ہے۔ جب کوئی فعال اکاؤنٹ اپنی حد کے 15 پوائنٹس کے اندر ہو (ڈیفالٹ پر 80%)، تو اس کی حدود ہر 15 کے بجائے ہر تین منٹ بعد چیک کی جاتی ہیں۔

`omarchy agent account list` ہر اکاؤنٹ اور اس کی تازہ ترین حدود دکھاتا ہے، `omarchy agent account remove work` ایک کو بھلا دیتا ہے، اور `omarchy agent account rename primary Hey` ایک کا نام بدلتا ہے (یا پینل میں کسی اکاؤنٹ کے نام پر کلک کریں)۔ یہ کمانڈز آپ کے ڈیفالٹ ایجنٹ کے اکاؤنٹس پر کام کرتی ہیں؛ دوسرے فراہم کنندہ تک پہنچنے کے لیے، پہلے اس کا نام لیں، جیسے `omarchy agent account use codex side` میں۔ `~/.claude` یا `~/.codex` میں آپ کا پہلے سے موجود لاگ ان _مرکزی_ اکاؤنٹ ہے۔ Codex کا وہیں رہتا ہے جہاں وہ ہے؛ جب کوئی دوسرا اکاؤنٹ فعال ہو تو Claude کا اپنے فولڈر میں انتظار کرتا ہے۔ تقریباً آٹھ گھنٹے سے زیادہ عرصے تک غیر استعمال شدہ چھوڑا گیا اکاؤنٹ _سائن ان درکار ہے_ دکھا سکتا ہے؛ اس اکاؤنٹ کو پینل میں ہی دوبارہ سائن ان کرنے کے لیے اس پر کلک کریں، یا اس پر بدل کر سیشن شروع کریں، جو سائن ان کو خود تازہ کر دیتا ہے۔ `claude mcp add` سے شامل کیے گئے MCP سرورز ہر Claude اکاؤنٹ تک پہنچتے ہیں، کیونکہ وہ سب `~/.claude` میں چلتے ہیں؛ Codex اور Grok کے لیے، جب اکاؤنٹ شامل کیا گیا تھا اس وقت آپ کے پاس موجود سرورز اس تک ساتھ آتے ہیں، مگر بعد والے صرف اسی اکاؤنٹ تک پہنچتے ہیں جس میں آپ نے انہیں شامل کیا تھا۔ Claude Desktop اپنا سائن ان خود رکھتا ہے، اور CLI بائنری کے مطلق راستے کے ساتھ ترتیب شدہ Codex یا Grok ٹولز تبدیلی کی پیروی نہیں کرتے۔ واضح `CLAUDE_CONFIG_DIR`، `CODEX_HOME`، یا `GROK_HOME` منتخب اکاؤنٹ پر ترجیح لیتا ہے۔

### کریش کی تشخیص

Omarchy پروسیس کریشز کے لیے systemd-coredump پر نظر رکھتا ہے۔ جب کوئی چیز سیگ فالٹ کرتی ہے، تو آپ کو “عمل کریش ہو گیا” اطلاع ملے گی — اس پر کلک کریں، اور کریش آپ کے ڈیفالٹ ایجنٹ کے حوالے کر دیا جاتا ہے Omarchy کی diagnose-crash مہارت کے ساتھ، جو ایجنٹ کو کور ڈمپ سے حقائق قائم کرنے اور یہ فیصلہ کرنے کے مراحل سے گزارتی ہے کہ آیا کریش اپ اسٹریم رپورٹ کرنے کے قابل ہے۔ آپ اسے `coredumpctl list` سے کسی بھی PID کے خلاف ہاتھ سے بھی `omarchy agent crash <pid>` سے چلا سکتے ہیں۔

نگرانی بطور ڈیفالٹ فعال ہے۔ اسے _ٹرگر > ٹوگل > کریش کیپچر_ میں بند کریں (یا `omarchy toggle crash-capture` سے) اور اطلاعات رک جاتی ہیں؛ `omarchy agent crash <pid>` ہاتھ سے پھر بھی کام کرتا ہے۔

کریشز کو ایک وقت میں ایک پروگرام کے لیے بھی خاموش کیا جا سکتا ہے، جو تشخیص آخر میں آپ کو پیش کرتی ہے۔ `omarchy crash mute hyprland` صرف اس پروگرام کے لیے اطلاعات روکتا ہے، `omarchy crash mute hyprland off` انہیں واپس لاتا ہے، اور اکیلا `omarchy crash mute` وہ فہرست دکھاتا ہے جو آپ نے خاموش کی ہے۔ یہ بائنری کا راستہ اس کے نام کی طرح خوشی سے لیتا ہے، چنانچہ `omarchy crash mute /usr/bin/hyprland` بھی وہی کرتا ہے۔ جس نام میں جگہ ہو اسے اقتباس میں رکھیں، جیسے `omarchy crash mute 'Some App'` میں۔ باقی سب پھر بھی اطلاع دیتے ہیں، اور خاموش پروگرام پھر بھی کریش ہوتا ہے — یہ یاد دہانی چھپاتا ہے، یہ کچھ ٹھیک نہیں کرتا۔

### ڈیسک ٹاپ ایپس

_انسٹال > AI_ مینو میں چند گرافیکل AI ایپس بھی ہیں: Antigravity Desktop، ChatGPT ڈیسک ٹاپ ایپ، Claude ڈیسک ٹاپ ایپ (Anthropic کا Linux بیٹا، Chat، Cowork، اور Claude Code ٹیبز کے ساتھ)، Grok Bot xAI کے ماڈلز سے گفتگو کے لیے، Herdr Desktop، Hermes Desktop، OpenClaw، Perplexity ڈیسک ٹاپ ایپ، اور T3 Code۔ Grok Bot ڈیسک ٹاپ چیٹ ایپ ہے۔ کوڈنگ ایجنٹ `grok` کمانڈ ہے۔

Hermes Desktop وہ ہے جس کے بارے میں جاننا ضروری ہے، کیونکہ کسی مشین پر ایک Hermes ہوتا ہے، اور وہ ایپ کا ہوتا ہے: Hermes ہمیشہ صرف ایپ کے ذریعے انسٹال ہوتا ہے، اور ڈیفالٹ ایجنٹ جو `hermes` کمانڈ چلاتا ہے وہ ایپ کی ہوتی ہے۔ Hermes کو ڈیفالٹ ایجنٹ کے طور پر منتخب کرنا وہی انسٹال کرتا ہے جو _انسٹال > AI_ اندراج کرتا ہے: پیکیج، اور Hermes کے اپنے انسٹالر کے ذریعے ترتیب شدہ `~/.hermes` کے تحت Hermes رن ٹائم، جس میں پہلی بار چند منٹ لگتے ہیں۔ وہ رن ٹائم وہ واحد Hermes ہے جسے ٹرمینل `hermes` کمانڈ، ڈیفالٹ ایجنٹ اور ایپ سب استعمال کرتے ہیں، اور وہ Omarchy ریلیز کا انتظار کرنے کے بجائے `hermes update` سے خود کو اپ ڈیٹ کرتا ہے۔ اسے انسٹال کرنے سے Hermes کو Omarchy تھیم بطور سکن بھی ملتی ہے جس کا نام `omarchy` ہے، جس کی ہر Hermes سطح تھیم بدلنے پر پیروی کرتی ہے؛ اگر آپ نہ چاہیں تو Hermes کی Appearance ترتیبات میں یا `/skin` سے کوئی اور منتخب کریں، اور Omarchy اس انتخاب کو چھوڑ دیتا ہے۔ _ہٹائیں > AI_ میں ایپ ہٹانے سے پہلے Hermes بند ہوتا ہے، گیٹ وے سمیت، وہ رن ٹائم اس کے ساتھ لے جاتا ہے، اور آپ کی چیٹس، یادیں، اور وہ مہارتیں جو Hermes نے خود کے لیے لکھیں برقرار رکھتا ہے الا یہ کہ آپ اسے دوسری صورت کہیں: یہ پوچھتا ہے، ڈیفالٹ نہیں کے ساتھ، کہ آیا وہ ڈیٹا اور آپ کی کنیکشن ترتیبات بھی جانی چاہئیں۔

OpenClaw کا ڈیسک ٹاپ تجربہ اس کا Control UI ہے، جو اپنے مقامی گیٹ وے کی پشت پناہی میں ویب ایپ کے طور پر کھلتا ہے۔ OpenClaw `~/.openclaw` میں رہتا ہے اور خود کو اپ ڈیٹ کرتا ہے: Control UI کا “گیٹ وے اپ ڈیٹ کریں” بٹن استعمال کریں یا `openclaw update` چلائیں، اور گیٹ وے نئے ورژن پر دوبارہ شروع ہو جاتا ہے۔ Omarchy صرف وہ ریلیز منتخب کرتا ہے جس سے نئی انسٹالیشن شروع ہوتی ہے۔ _ہٹائیں > AI_ میں OpenClaw ہٹانے سے گیٹ وے سروس اور ایپ اس کے ساتھ جاتی ہے اور پھر پوچھتا ہے کہ آیا `~/.openclaw` بھی جانا چاہیے، کیونکہ اس میں OpenClaw خود اور اس کے ڈاؤن لوڈ کردہ پلگ ان رن ٹائمز کے ساتھ آپ کی چیٹس اور اسناد ہوتی ہیں؛ ڈیفالٹ اسے برقرار رکھتا ہے، اور OpenClaw دوبارہ انسٹال کرنے سے یہ اسے واپس اٹھا لیتا ہے۔

Herdr Desktop [Herdr](https://herdr.dev) ڈیسک ٹاپ ایپ ہے: ٹرمینلز اور کوڈنگ ایجنٹس کی جگہیں، ٹیبز، اور پینز جو ونڈو بند کرنے پر اس کے کور میں چلتے رہتے ہیں۔ یہ پیکیج کے بجائے Herdr کے اپنے انسٹالر سے آتا ہے، چنانچہ یہ `~/.local/share/herdr-app` میں رہتا ہے، جب آپ کے پاس پہلے سے نہ ہو تو `~/.local/bin/herdr-core` میں اپنے کور کو ساتھ لاتا ہے، اور دونوں خود کو اپ ڈیٹ کرتے ہیں۔ یہ اس `herdr` کمانڈ کے ساتھ بیٹھتا ہے جو Omarchy `Super + Ctrl + Return` پر فراہم کرتا ہے، اس کی جگہ نہیں لیتا، اور اس کمانڈ کی براہ راست کیز حاصل کرتا ہے: `Alt + Return` اور `Alt + Shift + Return` پین کو نیچے یا دائیں تقسیم کرتے ہیں، `Alt + Escape` اسے بند کرتا ہے، `Ctrl + Alt + Arrow` پینز کے درمیان منتقل کرتا ہے، `Alt + 1..9` اور `Alt + Left/Right` ٹیب منتخب کرتے ہیں، اور `Alt + Up/Down` جگہوں کے درمیان منتقل کرتے ہیں۔ `Ctrl + 1..9` جگہ منتخب کرتا ہے اور `Alt + Shift + Up/Down` ایجنٹس میں قدم بہ قدم چلتا ہے۔ `Ctrl + Space` سابقہ کیز صرف ٹرمینل کے لیے رہتی ہیں، کیونکہ ایپ کسی سلسلے کے لیے سادہ Ctrl کی کو نہیں تھام سکتی۔ Omarchy انہیں `~/.config/herdr-app/keys.json` میں لکھتا ہے، اور `omarchy-refresh-herdr-app` انہیں واپس رکھتا ہے۔ اسے انسٹال کرنے سے Herdr کی Omarchy تھیم منتخب ہوتی ہے، جو اس کے بعد سے آپ کی Omarchy تھیم کی پیروی کرتی ہے۔ Herdr ہلکے انداز کے لیے ایک تھیم اور تاریک انداز کے لیے ایک تھیم رکھتا ہے، چنانچہ تاریک اور ہلکی Omarchy تھیم کے درمیان بدلنے کے بعد، دوسرے انداز کے لیے Herdr کے تھیم چننے والے میں Omarchy ایک بار پھر منتخب کریں۔

T3 Code پیکیج کے بجائے `~/.local/share/t3code` میں اپنی سرکاری AppImage ریلیز سے چلتا ہے، چنانچہ یہ خود کو اپ ڈیٹ کرتا ہے۔ اسے انسٹال کرنے پر پوچھا جاتا ہے کہ Stable یا Nightly چینل پر شروع کرنا ہے؛ بعد میں T3 Code کی ترتیبات میں بدلیں۔ آپ کے تھریڈز اور ترتیبات `~/.t3` میں رہتے ہیں، اور _ہٹائیں > AI_ میں T3 Code ہٹانے سے وہ اس کے ساتھ جاتے ہیں۔

### مقامی ماڈلز

اپنے کوڈنگ ایجنٹس کے لیے اپنی مشین پر کھلا ماڈل چلائیں۔ آپ کے پرامپٹس اور کوڈ مشین پر رہتے ہیں؛ ماڈل کو بھیجی گئی کوئی چیز اس سے باہر نہیں جاتی۔ اس سے شروع کریں:

```bash
omarchy agent local use best
```

یا، اوپر والی بار کے ایجنٹس پینل میں، + اور پھر Local AI منتخب کریں، جو اس وقت ظاہر ہوتا ہے جب کوئی ماڈل اس مشین میں پورا اترتا ہے۔ پہلی بار، یہ Podman انسٹال کرتا ہے، جو ماڈلز چلاتا ہے، اور NVIDIA مشین پر NVIDIA کا کنٹینر ٹول کٹ، جو انہیں GPU دیتا ہے۔ پھر Omarchy اس مشین کے لیے تجویز کردہ ماڈل منتخب کرتا ہے، اسے ڈاؤن لوڈ کرتا ہے، اور شروع کرتا ہے۔ دسیوں GB کے ڈاؤن لوڈ کی توقع رکھیں اور جب ماڈل چلے تو مشین کی زیادہ تر میموری استعمال میں ہوگی: Flash Next اپنے مکمل 256K سیاق و سباق کے ساتھ تقریباً 100 GiB استعمال کرتا ہے۔ اگر دیگر ماڈلز کو اسے درکار میموری حاصل ہو، تو یہ بند حالت میں ترتیب پاتا ہے، کسی ایک کو بند کرتے ہی شروع ہونے کے لیے تیار۔ ماڈل لاگ آؤٹ پر رک جاتا ہے؛ جب آپ کو کسی اور کام کے لیے میموری درکار ہو تو اسے خود بند کریں۔

`omarchy agent local list` اختیارات دکھاتا ہے اور بتاتا ہے کہ کچھ کیوں پورے نہیں اترتے۔ کوئی اور ترتیب دینے کے لیے، `omarchy agent local use <recipe>` چلائیں۔ آج، 128 GB Strix Halo مشینوں کے لیے `qwen3.8-flash-next-gufo` اور `qwen3.8-27b-gufo` دستیاب ہیں؛ 27B تقریباً 40 GiB لیتا ہے، چنانچہ یہ دیگر کام کے لیے جگہ چھوڑتا ہے۔ Intel کے Arc B390 والے 64 GB لیپ ٹاپ پر، `qwen3.6-35b-a3b-llamacpp` تقریباً 30 GiB میں چلتا ہے۔ نئی ترکیبیں اور تجاویز پیکیج کے ذریعے `omarchy update` کے ساتھ آتی ہیں۔

آپ کا ترتیب دیا گیا ہر ماڈل ایجنٹس پینل میں آپ کی سبسکرپشنز کے ساتھ اپنی سطر حاصل کرتا ہے: شروع کرنے کے لیے چلائیں، اسے بند کرنے اور اس کی میموری آزاد کرنے کے لیے روکیں، اور اس پر اپنا ایجنٹ کھولنے کے لیے ٹرمینل بٹن۔ کئی ایک ساتھ چل سکتے ہیں جب وہ میموری میں ایک ساتھ پورے اترتے ہوں؛ اگر کوئی پورا نہ اترے، تو Omarchy بتاتا ہے کہ کون سا چلتا ہوا ماڈل بند کرنا ہے۔ انہیں دوبارہ ترتیب دینے کے لیے سطریں گھسیٹیں، اور منتخب سطر پر Delete دبائیں تاکہ ماڈل اور اس کا ڈاؤن لوڈ ہٹ جائے۔

آپ کا ترتیب دیا گیا ہر ماڈل ایپ لانچر میں بھی اپنی اندراج حاصل کرتا ہے، ماڈل کے نام کے تحت اور اس کے بنانے والے کے لوگو کے ساتھ، اسی طرح جیسے Claude، Codex یا Grok میں سائن ان کرنے سے ایک شامل ہوتا ہے۔ یہ اس ماڈل پر آپ کا ایجنٹ کھولتا ہے، اور اگر ماڈل نہ چل رہا ہو تو پہلے اسے شروع کرتا ہے: ٹرمینل اسے لوڈ ہوتا دکھاتا ہے اور تیار ہوتے ہی ایجنٹ کے حوالے کر دیتا ہے۔ ماڈل ہٹانے سے اس کا اندراج ہٹ جاتا ہے۔

کوئی ماڈل عین اسی طرح چلتا رہتا ہے جیسے اسے ترتیب دیا گیا تھا، چنانچہ Omarchy اپ ڈیٹ کبھی آپ کے ایجنٹس کے تحت کسی کو دوبارہ شروع نہیں کرتا۔ جب Omarchy کے پاس آپ کے ترتیب شدہ ماڈل کے لیے نیا رن ٹائم یا نئے وزن ہوں، تو اس کی سطر اپ ڈیٹ بٹن دکھاتی ہے: اسے دبائیں اور ماڈل پس منظر میں دوبارہ ترتیب پاتا ہے، صرف وہ ڈاؤن لوڈ کرتا ہے جو بدلا ہے، اور نئے ورژن پر دوبارہ شروع ہوتا ہے۔ جو ماڈل بند تھا وہ بند رہتا ہے۔ `omarchy agent local update` ٹرمینل سے ہر ماڈل کے لیے یہی کرتا ہے۔

کمانڈ لائن سے، `omarchy agent local start <recipe>` اور `omarchy agent local stop <recipe>` یہی کرتے ہیں، `omarchy agent local status` ہر ماڈل دکھاتا ہے، اور `omarchy agent --local` آپ کے ڈیفالٹ ایجنٹ کو آخری شروع کیے گئے ماڈل پر کھولتا ہے۔ pi، OpenCode اور Qwen Code ایک استعمال کر سکتے ہیں؛ کسی اور ڈیفالٹ کے ساتھ یہ pi میں کھلتا ہے۔ pi آپ کے ترتیب شدہ ہر ماڈل، اور جن مشینوں سے آپ نے جوڑا بنایا ہے ان پر موجود ماڈلز کو بھی، اپنے ماڈل چننے والے میں فہرست کرتا ہے، چنانچہ سادہ `pi` بھی ان تک پہنچتا ہے۔ کوئی بھی OpenAI سے مطابقت رکھنے والا کلائنٹ بھی جڑ سکتا ہے: `status` ہر ماڈل کا پتہ دکھاتا ہے (پہلا `http://127.0.0.1:11435/v1` ہے)، ترکیب کا نام ماڈل ہے، اور کی `~/.config/omarchy/agent-local/key` میں ہے۔

`omarchy agent local remove <recipe>` ماڈل اور وہ ڈاؤن لوڈز حذف کرتا ہے جو کوئی اور ماڈل استعمال نہیں کرتا۔

تیسرے فریق کے رن ٹائمز پر ان کے ناشر کا لیبل لگا ہوتا ہے۔ Omarchy ہر ماڈل کو بغیر نیٹ ورک رسائی کے چلاتا ہے۔

### مقامی LLMs

Omarchy مقامی LLM ماڈلز چلانے کے دو طریقے تجویز کرتا ہے: LM Studio اور Ollama۔ LM Studio کھلے وزن والے ماڈلز تلاش کرنے، انہیں انسٹال کرنے، اور انہیں چلانے کے لیے GUI انٹرفیس فراہم کرتا ہے۔ آسانی سے شروع کرنے کا یہ بہترین طریقہ ہے۔ Ollama اسی طرح کرنے کے لیے CLI پیش کرتا ہے۔ لیکن اگر آپ مقامی ماڈلز میں نئے ہیں، تو میں LM Studio سے شروع کروں گا۔ آپ Omarchy Menu میں _انسٹال > AI_ میں دونوں میں سے کوئی انسٹال کر سکتے ہیں۔

### Omarchy کی مہارت

ایجنٹ مہارتیں AI کو مخصوص ٹولز مخصوص طریقے سے استعمال کرنے میں مدد دیتی ہیں، اور Omarchy سسٹم کو اپنی پسند کے مطابق ڈھالنے کے لیے ایک ڈیفالٹ مہارت کے ساتھ آتا ہے۔ جیسے اپنی Hyprland ترتیب کو ٹھیک کرنا، بار کو ایڈجسٹ کرنا، یا شروع سے نئی تھیم بنانا۔ یہ Claude Code (`~/.claude/skills`)، Codex (`~/.codex/skills`)، Pi (`~/.pi/agent/skills`)، Antigravity (`~/.gemini/config/skills`)، Hermes (`~/.hermes/skills` اور ہر `~/.hermes/profiles/*/skills`)، اور عمومی `~/.agents/skills` مقام کے لیے مہارت ڈائریکٹریوں میں سم لنک شدہ ہے، چنانچہ زیادہ تر ہارنسز اسے خود بخود اٹھا لیتے ہیں۔

لیکن آپ کو اس مہارت کو تجرباتی سمجھنا چاہیے۔ مختلف ماڈلز اسے مختلف اثر کے ساتھ استعمال کریں گے۔ بہتر ہے کہ پہلے پلان موڈ میں چلائیں، تاکہ آپ کو اندازہ ہو کہ ایجنٹ کیا بدلنا چاہے گا۔ اور پھر تبدیلیاں واپس لینے یا حتیٰ کہ `omarchy reinstall configs` چلانے کے لیے تیار رہیں، اگر ایجنٹ سب کچھ خراب کر دے۔
