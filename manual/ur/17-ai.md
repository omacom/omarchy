# AI

Omarchy میں نیچے دیے گئے کوڈنگ ایجنٹس کے لیے لانچرز شامل ہیں، بغیر آپ کے لیے کوئی ڈیفالٹ منتخب کیے۔ پہلی بار استعمال پر اس کا CLI نصب کرنے کے لیے ایک کمانڈ چلائیں، پھر جب کہا جائے تو تصدیق کر لیں۔ Hermes اور OpenClaw اس سے مستثنیٰ ہیں: ان کے لیے mise کے ذریعے کچھ نصب نہیں کیا جاتا، اور ان میں سے کسی کو منتخب کرنے سے اس کی اپنی خود اپ ڈیٹ ہونے والی کاپی ترتیب دی جاتی ہے، جیسا کہ نیچے _ڈیسک ٹاپ ایپس_ میں بیان کیا گیا ہے۔

### ایجنٹس کی تنصیب اور اپ ڈیٹ

Hermes اور OpenClaw کے سوا، یہ ایجنٹس mise کی سست تنصیب استعمال کرتے ہیں: پہلی لانچ CLI نصب کرتی ہے، اور بعد کی لانچیں اسی کو دوبارہ استعمال کرتی ہیں۔ mise نصب شدہ ایجنٹ کے لیے نئی ریلیز کی جانچ بھی زیادہ سے زیادہ ہر چار گھنٹے میں ایک بار کرتا ہے، اس کے شروع ہونے سے عین پہلے یا پس منظر میں shell prompt پر۔ اگر وہ اپ ڈیٹ ناکام ہو جائے یا آپ آف لائن ہوں، تو نصب شدہ ورژن چلتا ہے۔ `omarchy update` نصب شدہ ایجنٹس کو باقی Omarchy کے ساتھ اپ ڈیٹ کرتا ہے، اور `mup` صرف mise کے زیر انتظام ٹولز کو اپ ڈیٹ کرتا ہے۔

ایجنٹ کا اپنا اپڈیٹر، جیسے `claude update`، `codex update`، یا کسی ایپ میں اپ ڈیٹ بٹن، mise کے زیر انتظام تنصیب کو اپ ڈیٹ نہیں کرتا۔ `codex update` ناکام ہو جاتا ہے، اور `claude update` کامیابی کی اطلاع دے سکتا ہے جبکہ ایک الگ کاپی نصب کر رہا ہو جسے mise ٹریک نہیں کرتا۔ اگر آپ اس کے بجائے ایجنٹ کا مقامی انسٹالر اور اپڈیٹر استعمال کرنا چاہتے ہیں، تو اسے `disable_tools` میں شامل کریں؛ دیکھیں [پہلے سے نصب CLI ٹولز](18-development-tools.md#preinstalled-cli-tools)۔

تمام ترتیب شدہ سست ٹولز کو ضرورت پڑنے سے پہلے نصب کرنے کے لیے `mise install --include-lazy` چلائیں۔ اس میں ایجنٹس کے ساتھ ساتھ Omarchy کے دوسرے ڈیفالٹ CLI ٹولز بھی شامل ہیں۔ ایک واحد ٹول نصب کرنے یا اپنی تنصیب استعمال کرنے کے لیے دیکھیں [پہلے سے نصب CLI ٹولز](18-development-tools.md#preinstalled-cli-tools)۔

`grok` mise کے فرسٹ پارٹی `grok` پیکیج کے ذریعے نصب کیا جاتا ہے، اسی طرح جیسے `claude` اور `codex`۔ `grok` چلائیں، یا اسے _ایجنٹ > Harness_ کے تحت منتخب کریں۔ x.ai پر موجود `curl | bash` انسٹالر کو چھوڑ دیں۔ وہ راستہ `~/.grok/bin` میں ایک دوسری کاپی رکھتا ہے، اسے `PATH` پر پہلے لگاتا ہے، اور Omarchy کے wrapper کو اوور رائٹ کر دیتا ہے۔

`dsh` اپنا براؤزر UI `127.0.0.1:3080` پر کھولتا ہے، جس میں لانچ ڈائریکٹری اس کا ڈیفالٹ workspace ہوتی ہے۔ اس کا براؤزر UI کوئی ابتدائی prompt نہیں لیتا، لہٰذا `omarchy agent prompt` اسے آپ کے clipboard پر موجود prompt کے ساتھ کھولتا ہے تاکہ آپ اسے paste کر سکیں۔ Omarchy اسے DeepSeek کے بغیر منظوری والے اجازت preset کے ساتھ شروع کرتا ہے۔ DeepSeek Harness جب آپ اس کا سرکاری ماڈل API استعمال کرتے ہیں تو سیشن لاگز DeepSeek پر اپ لوڈ کرتا ہے؛ اسے اس کے براؤزر UI میں _ترتیبات > عمومی > Upload Session Log_ کے تحت بند کر دیں۔ جو آراء آپ اسے بھیجتے ہیں وہ بھی سیشن کے ساتھ اپ لوڈ ہوتی ہیں، الا یہ کہ آپ اسے `DSH_TELEMETRY_MODE=DISABLED` کے ساتھ شروع کریں۔

### ڈیفالٹ ایجنٹ

اپنا ڈیفالٹ ایجنٹ `omarchy default agent <name>` کے ساتھ یا Omarchy Menu (`Super + Space`) میں _ایجنٹ > Harness_ کے تحت منتخب کریں۔ اگر ایجنٹ ابھی نصب نہیں ہوا، تو اسے منتخب کرنے سے پہلے وہ نصب ہو جاتا ہے، اور اسے app launcher میں Agent کے ساتھ ساتھ اپنا لانچر بھی مل جاتا ہے۔ ایک تازہ Omarchy ایک بار کی اطلاع کے ساتھ آپ کو یہ انتخاب کرنے کی دعوت دے گا۔

Claude کو منتخب کرنا Chromium، Chrome، Brave، Brave Origin، اور Edge کے لیے اس کی براؤزر توسیع ترتیب دینے کی کوشش بھی کرتا ہے۔ توسیع کی ترتیب تمام صارفین پر لاگو ہوتی ہے اور آپ سے آپ کا سسٹم پاس ورڈ مانگ سکتی ہے؛ منسوخ کرنے یا توسیع کی ناکام تنصیب کے باوجود Claude منتخب اور لانچ ہو جاتا ہے۔ اپنا براؤزر دوبارہ شروع کریں، کہا جائے تو توسیع فعال کریں، اور اسے جوڑنا مکمل کرنے کے لیے Claude میں سائن ان کریں۔ کنکشن جانچنے کے لیے Claude میں `/chrome` چلائیں۔ Firefox اور Zen اس توسیع کی حمایت نہیں کرتے۔ اگر یہ ترتیب شامل کیے جانے سے پہلے ہی Claude آپ کا ڈیفالٹ تھا، تو توسیع نصب کرنے کے لیے اسے دوبارہ منتخب کریں۔

جب آپ انتخاب کر لیں، تو `Super + Shift + Ctrl + A` ڈیفالٹ ایجنٹ کو ایک مخصوص ٹرمینل ونڈو میں لانچ کرتا ہے (یا اگر آپ نے ابھی انتخاب نہیں کیا تو منتخب کنندہ سامنے لاتا ہے)۔ آپ اسے `omarchy agent prompt "Review this project"` کے ساتھ سیدھا کسی کام میں بھی لانچ کر سکتے ہیں۔ Freebuff اور DeepSeek Harness کوئی ابتدائی prompt نہیں لیتے، لہٰذا وہ اس کے بجائے آپ کے clipboard پر موجود prompt کے ساتھ کھلتے ہیں تاکہ آپ اسے paste کر سکیں۔ اس طرح لانچ کیے گئے ایجنٹس اپنے متعلقہ نہ رکنے اور نہ پوچھنے والے طریقوں میں بغیر نگرانی کے چلتے ہیں، لہٰذا تیار رہیں کہ وہ واقعی کچھ کریں گے! MiniMax Code کے پاس اس کے انٹرایکٹو سیشنز کے لیے ایسا کوئی طریقہ نہیں ہے، لہٰذا وہ معمول کے مطابق اجازتیں مانگتا ہے۔ اور چونکہ ایجنٹس آپ کی home ڈائریکٹری کے لیے بھروسا یاد رکھنے سے انکار کرتے ہیں، اس لیے `$HOME` سے لانچیں اس کے بجائے `~/Work` میں شروع ہوتی ہیں۔

ٹرمینل شارٹ کٹس بھی ہیں: `a` موجودہ ٹرمینل میں ڈیفالٹ ایجنٹ کو inline چلاتا ہے، جبکہ `c`، `cx`، اور `cy` OpenCode، Claude Code، اور Codex کو براہ راست شروع کرتے ہیں (ایک بار پھر ان کے خود منظوری دینے والے طریقوں میں)۔ تھیم کی تبدیلیاں ایجنٹس کے ساتھ بھی ہم آہنگ ہوتی ہیں: Claude Code، Pi، OpenCode، اور Hermes (جب Omarchy نے اسے نصب کر لیا ہو) سب اس وقت ساتھ دیتے ہیں جب آپ Omarchy تھیم تبدیل کرتے ہیں۔

### آپ کی ایجنٹ ہدایات

ہر ایجنٹ کے لیے ذاتی قواعد `~/.agents/AGENTS.md` میں جاتے ہیں، `~/.agents/skills` میں مشترکہ skills کے ساتھ۔ اسے _ایجنٹ > ہدایات_ کے تحت کھولیں، جو اسے ہر اس harness میں بھی لنک کرتا ہے جو اپنی عالمی فائل رکھتا ہے: `~/.claude/CLAUDE.md`، `~/.codex/AGENTS.md`، `~/.pi/agent/AGENTS.md`، `~/.config/opencode/AGENTS.md`، Copilot کی `~/.copilot/copilot-instructions.md`، اور اسی طرح۔ Crush اور Amp `~/.config/AGENTS.md` لنک پڑھتے ہیں، جبکہ omp، Kimi، اور DeepSeek Harness `~/.agents/AGENTS.md` کو براہ راست پڑھتے ہیں۔ ڈیفالٹ ایجنٹ منتخب کرنا بھی اسے لنک کر دیتا ہے۔ آپ کے پاس پہلے سے موجود ہدایات فائل مشترکہ فائل بن جاتی ہے اگر ابھی کوئی نہ تھی؛ ورنہ اسے لنک کے ساتھ `.bak` کے طور پر رکھا جاتا ہے۔ ایک اور ایجنٹ نصب کرنے کے بعد دوبارہ لنک کرنے کے لیے `omarchy agent instructions` چلائیں۔

### ایجنٹس پینل

اوپر والی بار میں ایک ایجنٹس آئیکن ہے۔ اس سے پہلے کہ آپ نے کوئی ایجنٹ ترتیب دیا ہو، اس کا پینل آپ کو Claude، Codex، یا Grok میں سائن ان کرنے میں رہنمائی کرتا ہے، اور پہلا والا آپ کا ڈیفالٹ ایجنٹ بن جاتا ہے۔ اس کے بعد، پینل ہر سبسکرپشن کو ایک صفحے پر رکھتا ہے: ہر ایجنٹ اور اکاؤنٹ اس کے پلان کے ساتھ، اس کی 5 گھنٹے کے سیشن اور ہفتہ وار حدود میں سے ہر ایک کے لیے ایک میٹر اس کے reset ہونے تک کے وقت کے ساتھ (درست فیصد کے لیے hover کریں)، یا باقی ماندہ پیشگی ادا شدہ بیلنس، ایک لائن کے نیچے جو ان تمام میں آپ کے استعمال کردہ کو گھماتی رہتی ہے، جیسے اس ہفتے کے ٹوکنز اور آپ کا سب سے زیادہ استعمال شدہ ماڈل۔ _کچھ زبردست بنائیں_ کے تحت یہ ایک نئی تھیم، plugin، ایپ، یا گیم کے لیے ابتدائی prompts پیش کرتا ہے جو کام آپ کے ڈیفالٹ ایجنٹ کے حوالے کرتے ہیں۔ ایپس اسی طرح بنائی جاتی ہیں جیسے Omarchy کی اپنی Hype، Monologue، اور Omacut ہیں، C++ اور Qt Quick میں، omarchy-make-app ایجنٹ skill کی پیروی کرتے ہوئے، اور انہیں درکار compiler اور Qt کے حصے نصب آتے ہیں۔ گیمز `~/Games/vibes` میں ایک واحد three.js صفحہ ہوتی ہیں، omarchy-make-game ایجنٹ skill کی پیروی کرتے ہوئے، اور سب موجودہ تھیم میں ایک Game Vibes لانچر سے کھلتی ہیں؛ وہ three.js ویب سے لوڈ کرتی ہیں، لہٰذا انہیں شروع ہونے کے لیے کنکشن درکار ہوتا ہے۔ Claude Code، Codex، Grok، Kimi، Cursor اور اس کا Grok Bot الاؤنس، GitHub Copilot، Muse، Antigravity، اور Devin اپنی حدود کے ساتھ ابتدا ہی سے شامل ہیں، Kimchi اپنے پلان، پیشگی ادا شدہ کریڈٹس، اور اخراجات کے بجٹس کے ساتھ، اور Hermes، Mistral Vibe، اور Qwen Code آپ کے انہیں استعمال کرنے کے بعد اپنے سیشنز اور ٹوکنز دکھاتے ہیں۔ فراہم کنندہ کے پلانز اور keys جو آپ pi، omp، یا opencode کے ذریعے استعمال کرتے ہیں وہ بھی نظر آتے ہیں: OpenCode Zen اور Go، Z.ai GLM Coding Plan، Ollama Cloud، MiniMax Token Plan، اور Synthetic اپنی حدود کے ساتھ؛ OpenRouter اور DeepSeek اپنے پیشگی ادا شدہ بیلنسز کے ساتھ؛ Fireworks پچھلے 30 دنوں میں اپنے اخراجات کے ساتھ۔ آپ کے اپنے hardware پر چلائے گئے ماڈلز کے ٹوکنز بھی مجموعوں میں شمار ہوتے ہیں؛ خود ماڈلز کا اپنا ایک پینل ہے، جو [مقامی ماڈلز](#local-models) کے تحت بیان کیا گیا ہے۔ ہر ایجنٹ ایک بار شمار ہوتا ہے، اس کے تحت جو بھی اس کا بل دیتا ہے، چاہے آپ اسے کتنے ہی harnesses کے ذریعے چلائیں۔

پینل کے لیے بار آئیکن پر بایاں کلک کریں یا `Super + Ctrl + X` دبائیں، اپنے ڈیفالٹ ایجنٹ کو لانچ کرنے کے لیے دایاں کلک کریں، اور تازہ کرنے کے لیے درمیانی کلک کریں۔ اس کے پیچھے استعمال کے ریکارڈز ہر 15 منٹ میں `omarchy agent usage update` کے ذریعے دوبارہ بنائے جاتے ہیں، اور پینل ایک ہم آہنگ فولڈر کے ذریعے آپ کی دوسری مشینوں سے استعمال کو بھی ضم کر سکتا ہے۔ مکمل ترتیبات کے لیے `$OMARCHY_PATH/shell/plugins/agents/` کے تحت README دیکھیں۔

### کئی سبسکرپشنز

اگر آپ ایک سے زیادہ Claude، Codex، یا Grok پلان کے لیے ادائیگی کرتے ہیں — مثلاً ایک ذاتی Max اور ایک کام والا — تو Omarchy ان سب کو سائن ان رکھ سکتا ہے اور ان کے درمیان منتقل ہو سکتا ہے۔ ایجنٹس پینل میں + کے ساتھ ایک سبسکرپشن شامل کریں، جو آپ کو وہیں اس میں رہنمائی کرتا ہے، یا `omarchy agent account add claude Work` کے ساتھ (یا `codex`، یا `grok`)۔ اگر CLI غائب ہو تو یہ اسے نصب کر دیتا ہے۔ کسی فراہم کنندہ کے لیے پہلا اکاؤنٹ آپ کے عام براؤزر کے ذریعے سائن ان کرتا ہے، عین وہیں جہاں CLI ہمیشہ دیکھتا ہے۔ اس کے بعد ہر ایک نجی ونڈو کے ذریعے سائن ان کرتا ہے، تاکہ وہ اکاؤنٹ جس میں آپ کا براؤزر پہلے سے سائن ان ہے غلطی سے نہ پکڑا جائے؛ وہاں اس اکاؤنٹ کے طور پر سائن ان کریں جسے آپ شامل کر رہے ہیں، اور پہلے سے کھلی ہوئی کسی بھی نجی ونڈو کو پہلے بند کر دیں۔ اس کے لیے کبھی CLI سے لاگ آؤٹ نہ کریں: لاگ آؤٹ کرنے سے محفوظ شدہ سائن ان منسوخ ہو جاتا ہے، اور اس اکاؤنٹ کو دوبارہ شامل کرنا پڑے گا۔

اپنے سبسکرپشن لاگ انز کو SSH کے ذریعے کسی دوسری Omarchy مشین پر کاپی کرنے کے لیے `omarchy agent account copy user@laptop` چلائیں۔ بھیجنے والا ایک عارضی وصول کنندہ فراہم کرتا ہے جب منزل پر کوئی نصب نہ ہو، لہٰذا پرانی Omarchy مشینیں بغیر اپ ڈیٹ کے اکاؤنٹس وصول کر سکتی ہیں۔ نصب شدہ وصول کنندگان کو ترجیح حاصل ہے۔ یہ تمام Claude، Codex، اور Grok سبسکرپشنز کاپی کرتا ہے؛ انہیں منتخب کرنے کے لیے فراہم کنندگان کے نام شامل کریں، جیسے `omarchy agent account copy laptop claude` میں۔ اکاؤنٹ کے نام اور کمانڈ IDs ماخذ سے ملتے ہیں، بشمول وہ اکاؤنٹس جو منزل پر پہلے سے موجود ہیں۔ غیر متعلقہ منزل اکاؤنٹس کو عددی لاحقہ ملتا ہے اگر ان کے نام متصادم ہوں، اور ترتیبات، skills، plugins، اور گفتگو کی تاریخ ہر مشین کے لیے مقامی رہتی ہے۔

موجودہ منزل اسناد رکھی جاتی ہیں۔ ایک ماخذ اکاؤنٹ جو وہاں پہلے سے سائن ان ہے اس کا نام اس کی اسناد کو بدلے بغیر ہم آہنگ ہو جاتا ہے؛ دوسرے اکاؤنٹس اس کے ساتھ شامل کر دیے جاتے ہیں۔ ملتے جلتے اکاؤنٹس کے لیے محفوظ شدہ اسناد تبدیل کرنے کے لیے، منزل پر اس اکاؤنٹ کے سیشنز چھوڑنے کے بعد `omarchy agent account copy --replace laptop claude` استعمال کریں۔ ایک تازہ منزل کو ماخذ کا فعال اکاؤنٹ اور تبدیلی کی ترجیحات بھی ملتی ہیں؛ ایک قائم شدہ منزل اپنی ترجیحات برقرار رکھتی ہے۔

اسناد SSH کے ذریعے سفر کرتی ہیں اور منزل پر نجی فائلوں میں محفوظ ہوتی ہیں، لہٰذا صرف ان مشینوں پر کاپی کریں جن پر آپ بھروسا کرتے ہیں۔ یہ ایک بار کی کاپی ہے، جاری ہم آہنگی نہیں۔ Codex refresh ٹوکنز کو دوسری مشین کے ذریعے گھمایا جا سکتا ہے، جس سے کاپی شدہ لاگ ان کو تجدید کی ضرورت پڑ جاتی ہے؛ کئی مشینوں پر بیک وقت استعمال کے لیے الگ الگ سائن ان سب سے قابل اعتماد انتخاب رہتے ہیں۔ دیکھیں [Codex کی اکاؤنٹ تصدیق رہنمائی](https://developers.openai.com/codex/auth/ci-cd-auth)۔

فی فراہم کنندہ ایک اکاؤنٹ فعال ہوتا ہے، اور ہر نیا سیشن اسی کے طور پر شروع ہوتا ہے: `cx`، `cy`، ایک سادہ `claude`، `codex`، یا `grok`، `omarchy agent` کے ذریعے لانچ کی گئی کوئی بھی چیز، اور اسکرپٹس یا ایڈیٹرز جو `PATH` پر CLI تلاش کرتے ہیں۔ `omarchy agent account use work` کے ساتھ تبدیل کریں (اور `omarchy agent account use main` کے ساتھ واپس)، یا پینل میں کسی اکاؤنٹ کا نمبر دبا کر پھر `Enter` دبا کر (یا اس کے Use بٹن پر کلک کر کے)۔ چل رہے Claude سیشنز بھی تبدیل ہو جاتے ہیں، ان کے اگلے پیغام سے: ہر Claude سیشن `~/.claude` میں چلتا ہے، جس میں ہمیشہ فعال اکاؤنٹ کا سائن ان ہوتا ہے۔ ایک پرانی Omarchy کے ذریعے اکاؤنٹ کے اپنے فولڈر میں شروع کیا گیا Claude سیشن اس سائن ان کو اس کے چھوڑنے تک رکھتا ہے، لہٰذا تبدیلی ان سیشنز کے نام بتاتی ہے اور ان کے ختم ہونے کے بعد خود مکمل ہو جاتی ہے۔ چل رہے Codex اور Grok سیشنز اس اکاؤنٹ پر رہتے ہیں جس سے انہوں نے شروع کیا تھا۔ گفتگو کی تاریخ، ترتیبات، skills، اور plugins اکاؤنٹس میں مشترکہ ہیں، لہٰذا اسی فولڈر میں `claude --continue` نئے اکاؤنٹ پر وہیں سے شروع ہوتا ہے جہاں آپ نے چھوڑا تھا۔

ایک سے زیادہ اکاؤنٹ کے ساتھ، پینل ہر اکاؤنٹ کی حدود ساتھ ساتھ دکھاتا ہے، جس میں فعال اکاؤنٹ نشان زد ہوتا ہے۔ بطور ڈیفالٹ Omarchy آپ کو مطلع کرتا ہے جب فعال اکاؤنٹ کسی حد کے 95% سے گزر جاتا ہے، اور اطلاع پر کلک کرنے سے سب سے زیادہ گنجائش والے اکاؤنٹ پر منتقل ہو جاتا ہے۔ اس کے خود بخود تبدیل ہونے کے لیے پینل میں کسی اکاؤنٹ کی لائن پر hover کریں اور Use کے ساتھ نظر آنے والے Autoswitch پر کلک کریں (یا `m` دبائیں)، یا `omarchy agent account mode auto` چلائیں؛ جب یہ آن ہوتا ہے، تو Autoswitch Use کی جگہ لے لیتا ہے، اور اس پر دوبارہ کلک کرنے سے مطلع کرنے پر واپس آ جاتا ہے۔ حد تبدیل کرنے کے لیے ایک نمبر شامل کریں، جیسے `omarchy agent account mode auto 90` میں۔ اگر ہر اکاؤنٹ حد سے اوپر ہو، تو آپ کو ایک بار اس کے بارے میں بتایا جائے گا، اس کے ساتھ کہ کون سا اکاؤنٹ سب سے پہلے خالی ہوتا ہے۔ جبکہ ایک فعال اکاؤنٹ اپنی حد کے 15 پوائنٹس کے اندر ہوتا ہے (ڈیفالٹ پر 80%)، اس کی حدود ہر 15 کے بجائے ہر تین منٹ میں جانچی جاتی ہیں۔

`omarchy agent account list` ہر اکاؤنٹ اور اس کی تازہ ترین حدود دکھاتا ہے، `omarchy agent account remove work` ایک کو بھول جاتا ہے، اور `omarchy agent account rename primary Hey` ایک کا نام بدلتا ہے (یا پینل میں کسی اکاؤنٹ کے نام پر کلک کریں)۔ یہ کمانڈز آپ کے ڈیفالٹ ایجنٹ کے اکاؤنٹس پر کام کرتی ہیں؛ دوسرے فراہم کنندہ تک پہنچنے کے لیے، پہلے اس کا نام بتائیں، جیسے `omarchy agent account use codex side` میں۔ آپ کے پاس `~/.claude` یا `~/.codex` میں پہلے سے موجود لاگ ان _Main_ اکاؤنٹ ہے۔ Codex کا وہیں رہتا ہے جہاں ہے؛ Claude کا جب ایک اور اکاؤنٹ فعال ہو تو اپنے فولڈر میں انتظار کرتا ہے۔ آٹھ گھنٹے سے زیادہ عرصے سے غیر استعمال شدہ رہ جانے والا اکاؤنٹ _سائن ان درکار ہے_ دکھا سکتا ہے؛ پینل میں ہی اس اکاؤنٹ کو دوبارہ سائن ان کرنے کے لیے اس پر کلک کریں، یا اس پر منتقل ہو کر ایک سیشن شروع کریں، جو خود ہی سائن ان کو تازہ کر دیتا ہے۔ آپ `claude mcp add` کے ساتھ شامل کردہ MCP سرورز ہر Claude اکاؤنٹ تک پہنچتے ہیں، کیونکہ وہ سب `~/.claude` میں چلتے ہیں؛ Codex اور Grok کے لیے، جو سرورز آپ کے پاس اس وقت تھے جب ایک اکاؤنٹ شامل کیا گیا تھا وہ اس تک آتے ہیں، لیکن بعد والے صرف اس اکاؤنٹ تک پہنچتے ہیں جس میں آپ نے انہیں شامل کیا تھا۔ Claude Desktop اپنا سائن ان رکھتا ہے، اور CLI بائنری کے مطلق راستے کے ساتھ ترتیب شدہ Codex یا Grok ٹولز تبدیلی کی پیروی نہیں کرتے۔ ایک واضح `CLAUDE_CONFIG_DIR`، `CODEX_HOME`، یا `GROK_HOME` منتخب شدہ اکاؤنٹ پر فوقیت لیتا ہے۔

### کریش کی تشخیص

Omarchy عمل کے کریشوں کے لیے systemd-coredump کو دیکھتا ہے۔ جب آپ نے ایک ڈیفالٹ ایجنٹ منتخب کر لیا ہو، تو آپ کا کوئی بھی پروگرام جو core dump کرے وہ ایک "Process crashed" اطلاع لاتا ہے — اس پر کلک کریں، اور کریش آپ کے ڈیفالٹ ایجنٹ کے حوالے کر دیا جاتا ہے Omarchy کی omarchy-diagnose-crash skill کے ساتھ، جو ایجنٹ کو core dump سے حقائق قائم کرنے اور یہ فیصلہ کرنے میں رہنمائی کرتی ہے کہ آیا کریش upstream رپورٹ کرنے کے قابل ہے۔ آپ اسے `coredumpctl list` سے کسی بھی PID کے خلاف `omarchy agent crash <pid>` کے ساتھ ہاتھ سے بھی چلا سکتے ہیں۔

دیکھنا بطور ڈیفالٹ آن ہے۔ اسے _مححرک > ٹوگل > Crash Capture Off_ کے تحت بند کر دیں (یا `omarchy toggle crash-capture` کے ساتھ) اور اطلاعات رک جاتی ہیں؛ `omarchy agent crash <pid>` اب بھی ہاتھ سے کام کرتا ہے۔

کریشوں کو ایک وقت میں ایک پروگرام کے لیے خاموش بھی کیا جا سکتا ہے، جو تشخیص اختتام پر آپ کو پیش کرتی ہے۔ `omarchy crash mute hyprland` صرف اس پروگرام کے لیے اطلاعات روکتا ہے، `omarchy crash mute hyprland off` انہیں واپس لاتا ہے، اور `omarchy crash mute` اکیلا وہ دکھاتا ہے جو آپ نے خاموش کیا ہے۔ یہ بائنری کا راستہ اس کے نام کی طرح خوشی سے لیتا ہے، لہٰذا `omarchy crash mute /usr/bin/hyprland` بھی وہی کام کرتا ہے۔ کسی ایسے نام کو جس میں space ہو اقتباس میں لکھیں، جیسے `omarchy crash mute 'Some App'` میں۔ باقی سب کچھ اب بھی مطلع کرتا ہے، اور خاموش کیا گیا پروگرام اب بھی کریش ہوتا ہے — یہ یاد دہانی کو چھپاتا ہے، یہ کچھ ٹھیک نہیں کرتا۔

### ڈیسک ٹاپ ایپس

_نصب کریں > AI_ مینو میں چند گرافیکل AI ایپس بھی ہیں: Amp Desktop، Antigravity Desktop، ChatGPT ڈیسک ٹاپ ایپ، Claude ڈیسک ٹاپ ایپ (Anthropic کا Linux بیٹا، Chat، Cowork، اور Claude Code ٹیبز کے ساتھ)، xAI کے ماڈلز کے ساتھ چیٹ کرنے کے لیے Grok Bot، Herdr Desktop، Hermes Desktop، OpenClaw، Perplexity ڈیسک ٹاپ ایپ، اور T3 Code۔ Grok Bot ڈیسک ٹاپ چیٹ ایپ ہے۔ کوڈنگ ایجنٹ `grok` کمانڈ ہے۔

Hermes Desktop وہ ہے جس کے بارے میں جاننا ضروری ہے، کیونکہ ایک مشین میں ایک Hermes ہوتا ہے، اور وہ ایپ کا ہوتا ہے: Hermes ہمیشہ صرف ایپ کے ذریعے نصب کیا جاتا ہے، اور ڈیفالٹ ایجنٹ جو `hermes` کمانڈ چلاتا ہے وہ ایپ کی ہے۔ Hermes کو ڈیفالٹ ایجنٹ کے طور پر منتخب کرنا وہی چیز نصب کرتا ہے جو _نصب کریں > AI_ اندراج کرتا ہے: پیکیج، اور Hermes کے اپنے انسٹالر کے ذریعے ترتیب دیا گیا `~/.hermes` کے تحت ایک Hermes runtime، جس میں پہلی بار چند منٹ لگتے ہیں۔ وہ runtime وہی ایک Hermes ہے جسے ٹرمینل `hermes` کمانڈ، ڈیفالٹ ایجنٹ اور ایپ سب استعمال کرتے ہیں، اور یہ Omarchy ریلیز کا انتظار کرنے کے بجائے `hermes update` کے ساتھ خود کو اپ ڈیٹ کرتا ہے۔ اسے نصب کرنا Hermes کو Omarchy تھیم بھی `omarchy` نامی skin کے طور پر دیتا ہے، جس کی ہر Hermes سطح پیروی کرتی ہے جب آپ تھیمز تبدیل کرتے ہیں؛ اگر آپ چاہتے ہیں کہ ایسا نہ ہو تو Hermes کی Appearance ترتیبات کے تحت یا `/skin` کے ساتھ کوئی اور منتخب کریں، اور Omarchy اس انتخاب کو چھوڑ دیتا ہے۔ _ہٹائیں > AI_ کے تحت ایپ ہٹانا پہلے Hermes کو بند کرتا ہے، gateway سمیت، اس runtime کو اس کے ساتھ لے جاتا ہے، اور آپ کی چیٹس، یادیں، اور وہ skills جو Hermes نے خود اپنے لیے لکھی تھیں رکھتا ہے الا یہ کہ آپ اسے دوسری صورت بتائیں: یہ پوچھتا ہے، بطور ڈیفالٹ نہ کے ساتھ، کہ آیا وہ ڈیٹا اور آپ کی کنکشن ترتیبات بھی جانی چاہئیں۔

OpenClaw کا ڈیسک ٹاپ تجربہ اس کا Control UI ہے، جو اس کے اپنے مقامی gateway کی پشت پناہی سے ایک ویب ایپ کے طور پر کھلتا ہے۔ OpenClaw `~/.openclaw` میں رہتا ہے اور خود کو اپ ڈیٹ کرتا ہے: Control UI کا "Update Gateway" بٹن استعمال کریں یا `openclaw update` چلائیں، اور gateway نئے ورژن پر دوبارہ شروع ہو جاتا ہے۔ Omarchy صرف وہ ریلیز منتخب کرتا ہے جس سے ایک تازہ تنصیب شروع ہوتی ہے۔ OpenClaw آپ کا ڈیفالٹ ایجنٹ بھی ہو سکتا ہے: اسے _ایجنٹ > Harness_ کے تحت منتخب کرنا `~/.openclaw` میں اسی کاپی کو ترتیب دیتا ہے، اور ایجنٹ OpenClaw کا terminal UI اس کے gateway سے منسلک کھولتا ہے۔ _ہٹائیں > AI_ کے تحت OpenClaw ہٹانا gateway سروس اور ایپ کو اس کے ساتھ لے جاتا ہے اور پھر پوچھتا ہے کہ آیا `~/.openclaw` بھی جانا چاہیے، کیونکہ اس میں خود OpenClaw اور اس کے ڈاؤن لوڈ کردہ plugin runtimes کے ساتھ آپ کی چیٹس اور اسناد ہوتی ہیں؛ ڈیفالٹ اسے رکھتا ہے، اور OpenClaw کو دوبارہ نصب کرنا اسے واپس لے لیتا ہے۔

Herdr Desktop [Herdr](https://herdr.dev) ڈیسک ٹاپ ایپ ہے: ٹرمینلز اور کوڈنگ ایجنٹس کے spaces، ٹیبز، اور panes جو آپ کے ونڈو بند کرنے پر اس کے core میں چلتے رہتے ہیں۔ یہ کسی پیکیج کے بجائے Herdr کے اپنے انسٹالر سے آتا ہے، لہٰذا یہ `~/.local/share/herdr-app` میں رہتا ہے، جب آپ کے پاس ابھی کوئی نہ ہو تو `~/.local/bin/herdr-core` میں اپنے core کو ساتھ لاتا ہے، اور دونوں کو خود اپ ڈیٹ کرتا ہے۔ یہ اس `herdr` کمانڈ کے ساتھ بیٹھتا ہے جو Omarchy `Super + Ctrl + Return` پر بھیجتا ہے بجائے اسے تبدیل کرنے کے، اور اس کمانڈ کی براہ راست keys حاصل کرتا ہے: `Alt + Return` اور `Alt + Shift + Return` ایک pane کو نیچے یا دائیں تقسیم کرتے ہیں، `Alt + Escape` اسے بند کرتا ہے، `Ctrl + Alt + Arrow` panes کے درمیان منتقل ہوتا ہے، `Alt + 1..9` اور `Alt + Left/Right` ایک ٹیب منتخب کرتے ہیں، اور `Alt + Up/Down` spaces کے درمیان منتقل ہوتے ہیں۔ `Ctrl + 1..9` ایک space منتخب کرتا ہے اور `Alt + Shift + Up/Down` ایجنٹس میں مرحلہ وار جاتا ہے۔ `Ctrl + Space` prefix keys صرف ٹرمینل کے لیے رہتی ہیں، کیونکہ ایپ کسی تسلسل کے لیے سادہ Ctrl key کو نہیں تھام سکتی۔ Omarchy یہ `~/.config/herdr-app/keys.json` میں لکھتا ہے، اور `omarchy-refresh-herdr-app` انہیں واپس رکھتا ہے۔ اسے نصب کرنا Herdr کی Omarchy تھیم منتخب کرتا ہے، جو اس کے بعد سے آپ کی Omarchy تھیم کی پیروی کرتی ہے۔ Herdr ہلکے موڈ کے لیے ایک تھیم اور گہرے موڈ کے لیے ایک تھیم رکھتا ہے، لہٰذا گہری اور ہلکی Omarchy تھیم کے درمیان تبدیل کرنے کے بعد، دوسرے موڈ کے لیے Herdr کے تھیم منتخب کنندہ میں ایک بار پھر Omarchy منتخب کریں۔

T3 Code کسی پیکیج کے بجائے `~/.local/share/t3code` میں اپنی سرکاری AppImage ریلیز سے چلتا ہے، لہٰذا یہ خود کو اپ ڈیٹ کرتا ہے۔ اسے نصب کرنا پوچھتا ہے کہ Stable یا Nightly چینل پر شروع کرنا ہے؛ بعد میں T3 Code کی ترتیبات میں تبدیل کریں۔ آپ کے تھریڈز اور ترتیبات `~/.t3` میں رہتے ہیں، اور _ہٹائیں > AI_ کے تحت T3 Code ہٹانا انہیں اس کے ساتھ لے جاتا ہے۔

### مقامی ماڈلز

اپنے کوڈنگ ایجنٹس کے لیے اپنی مشین پر ایک اوپن ماڈل چلائیں۔ آپ کے prompts اور کوڈ مشین پر رہتے ہیں؛ ماڈل کو بھیجی گئی کوئی چیز اسے نہیں چھوڑتی۔ اس سے شروع کریں:

```bash
omarchy models use best text
```

یہ اس مشین کے لیے بہترین ٹیکسٹ ماڈل ترتیب دیتا ہے، وہ قسم جو آپ کے ایجنٹس استعمال کرتے ہیں۔ امیج، ویڈیو اور موسیقی ماڈلز کا اپنا بہترین ہوتا ہے: `omarchy models use best image`، `video` یا `music`۔ اس مشین کے لیے ہر قسم کا انتخاب دیکھنے کے لیے `omarchy models use best` چلائیں۔

یا مقامی ماڈلز پینل کو اوپر والی بار میں اس کے چمکتے آئیکن سے، ایجنٹس آئیکن کے ساتھ، یا Super + Ctrl + Alt + X کے ساتھ کھولیں، اور + منتخب کریں۔ آئیکن اس وقت نظر آتا ہے جب کوئی ماڈل اس مشین پر فٹ بیٹھتا ہو۔ Podman، جو ماڈلز چلاتا ہے، Omarchy کے ساتھ آتا ہے، جیسا کہ NVIDIA مشین پر NVIDIA کا کنٹینر ٹول کٹ آتا ہے، جو انہیں GPU دیتا ہے؛ اگر ان میں سے کوئی غائب ہو، تو پہلی ترتیب اسے نصب کر دیتی ہے۔ پھر Omarchy اس مشین کے لیے تجویز کردہ ماڈل منتخب کرتا ہے، اسے ڈاؤن لوڈ کرتا ہے، اور اسے شروع کرتا ہے۔ دسیوں GB کے ڈاؤن لوڈ اور ماڈل چلتے وقت مشین کی زیادہ تر میموری استعمال میں ہونے کی توقع رکھیں: Flash Next اپنے مکمل 256K سیاق و سباق کے ساتھ تقریباً 100 GiB استعمال کرتا ہے۔ اگر دوسرے ماڈلز اسے درکار میموری رکھے ہوئے ہوں، تو یہ رکا ہوا ترتیب دیا جاتا ہے، ایک کو روکنے کے بعد شروع ہونے کے لیے تیار۔ ماڈل لاگ آؤٹ پر رک جاتا ہے؛ جب آپ کو کسی اور چیز کے لیے میموری درکار ہو تو اسے خود روک دیں۔

`omarchy models list` اختیارات دکھاتا ہے اور بتاتا ہے کہ کچھ کیوں فٹ نہیں بیٹھتے۔ ایک اور ترتیب دینے کے لیے `omarchy models use <recipe>` چلائیں۔ آج، `qwen3.8-flash-next-gufo` اور `qwen3.8-27b-gufo` 128 GB Strix Halo مشینوں کے لیے دستیاب ہیں؛ 27B تقریباً 40 GiB لیتا ہے، لہٰذا یہ دوسرے کام کے لیے جگہ چھوڑتا ہے۔ Intel کے Arc B390 کے ساتھ 64 GB لیپ ٹاپ پر، `qwen3.6-35b-a3b-llamacpp` تقریباً 30 GiB میں چلتا ہے۔ نئی ترکیبیں اور تجاویز پیکیج کے ذریعے `omarchy update` کے ساتھ آتی ہیں۔

آپ کے ترتیب دیے گئے ہر ماڈل کو مقامی ماڈلز پینل میں اپنی لائن ملتی ہے: اسے شروع کرنے کے لیے چلائیں، اسے روکنے اور اس کی میموری خالی کرنے کے لیے روکیں، اور اس پر اپنے ایجنٹ کو کھولنے کے لیے ٹرمینل بٹن۔ اوپر کے پار، ایک بار دکھاتا ہے کہ مشین کی میموری خود Omarchy (سسٹم اور آپ کی ایپس)، ہر چل رہے ماڈل، اور جو خالی ہے کے درمیان کیسے تقسیم ہے۔ رکے ہوئے ماڈل کی طرف اشارہ کریں اور بار دکھاتا ہے کہ آیا یہ فٹ بیٹھتا ہے، یا کتنا کم ہے۔ کئی ایک ساتھ چل سکتے ہیں جب وہ میموری میں ایک ساتھ فٹ بیٹھیں؛ اگر ایک فٹ نہ بیٹھے، تو Omarchy بتاتا ہے کہ کون سا چل رہا ماڈل روکنا ہے۔ انہیں دوبارہ ترتیب دینے کے لیے لائنوں کو ان کے لوگو سے گھسیٹیں، اور ماڈل اور اس کے ڈاؤن لوڈ کو ہٹانے کے لیے منتخب لائن پر Delete دبائیں۔

آپ کے ترتیب دیے گئے ہر کوڈنگ ماڈل کو app launcher میں بھی اپنا اندراج ملتا ہے، ماڈل کے نام کے تحت اور اس کے بنانے والے کے لوگو کے ساتھ، جس طرح Claude، Codex یا Grok میں سائن ان کرنے سے ایک شامل ہوتا ہے۔ یہ آپ کے ایجنٹ کو اس ماڈل پر کھولتا ہے، اور اگر ماڈل نہ چل رہا ہو تو پہلے اسے شروع کرتا ہے: ٹرمینل اسے لوڈ ہوتا دکھاتا ہے اور اس کے تیار ہونے کے بعد ایجنٹ کے حوالے کر دیتا ہے۔ ماڈل ہٹانا اس کا اندراج ہٹا دیتا ہے۔

ہر ماڈل کوڈنگ کے لیے نہیں ہوتا۔ امیج، ویڈیو اور موسیقی ماڈلز اس کے بجائے Fantasi میں کھلتے ہیں، جو اس مشین پر چل رہے ماڈل کے ساتھ تصویریں، ویڈیو اور موسیقی بنانے کے لیے Omarchy کی ایپ ہے، وہاں یا مقامی ماڈلز پینل میں ان کی لائن سے منتخب کیے جاتے ہیں۔

ایک ماڈل عین اسی طرح چلتا رہتا ہے جیسے اسے ترتیب دیا گیا تھا، لہٰذا Omarchy اپ ڈیٹ کبھی آپ کے ایجنٹس کے نیچے ایک کو دوبارہ شروع نہیں کرتا۔ جب Omarchy کے پاس آپ کے ترتیب دیے گئے ماڈل کے لیے نیا runtime یا نئے weights ہوں، تو اس کی لائن ایک اپ ڈیٹ بٹن دکھاتی ہے: اسے دبائیں اور ماڈل پس منظر میں دوبارہ ترتیب دیا جاتا ہے، صرف جو بدلا ہے وہ ڈاؤن لوڈ کرتا ہے، اور نئے ورژن پر دوبارہ شروع ہو جاتا ہے۔ جو ماڈل رکا ہوا تھا وہ رکا رہتا ہے۔ `omarchy models update` ٹرمینل سے ہر ماڈل کے لیے یہی کرتا ہے۔

کمانڈ لائن سے، `omarchy models start <recipe>` اور `omarchy models stop <recipe>` یہی کرتے ہیں، `omarchy models status` ہر ماڈل دکھاتا ہے، اور `omarchy agent --local` pi میں آخری ماڈل جو آپ نے شروع کیا تھا کھولتا ہے، چاہے آپ کا ڈیفالٹ ایجنٹ کچھ بھی ہو۔ OpenCode اور Qwen Code بھی مقامی ماڈل استعمال کر سکتے ہیں: `omarchy models harness opencode` یا `omarchy models harness qwen` اس کے بجائے انہیں وہاں کھولتا ہے، اور `omarchy models harness pi` واپس جاتا ہے۔ pi آپ کے ترتیب دیے گئے ہر ماڈل، اور ان مشینوں پر موجود ماڈلز کو بھی جن کے ساتھ آپ نے جوڑا بنایا ہے، اپنے ماڈل منتخب کنندہ میں درج کرتا ہے، لہٰذا سادہ `pi` بھی ان تک پہنچتا ہے۔ کوئی بھی OpenAI سے ہم آہنگ کلائنٹ بھی جڑ سکتا ہے: `status` ہر ماڈل کا پتہ دکھاتا ہے (پہلا `http://127.0.0.1:11435/v1` ہے)، ترکیب کا نام ماڈل ہے، اور key `~/.config/omarchy/agent-local/key` میں ہے۔

`omarchy models remove <recipe>` ایک ماڈل اور وہ ڈاؤن لوڈز حذف کرتا ہے جو کوئی دوسرا ماڈل استعمال نہیں کرتا۔

تھرڈ پارٹی runtimes کو ان کے ناشر کے ساتھ لیبل کیا جاتا ہے۔ Omarchy ہر ماڈل کو بغیر نیٹ ورک رسائی کے چلاتا ہے۔

### مقامی LLMs

Omarchy مقامی LLM ماڈلز چلانے کے دو طریقے تجویز کرتا ہے: LM Studio اور Ollama۔ LM Studio اوپن ویٹ ماڈلز تلاش کرنے، انہیں نصب کرنے، اور انہیں چلانے کے لیے ایک GUI انٹرفیس فراہم کرتا ہے۔ آسانی سے شروع کرنے کے لیے یہ ایک بہترین طریقہ ہے۔ Ollama اسی طرح کرنے کے لیے ایک CLI پیش کرتا ہے۔ لیکن اگر آپ مقامی ماڈلز میں نئے ہیں، تو میں LM Studio سے شروع کروں گا۔ آپ Omarchy Menu میں _نصب کریں > AI_ کے تحت ان میں سے کوئی بھی نصب کر سکتے ہیں۔

### Omarchy skills

ایجنٹ skills AI کو مخصوص ٹولز کو مخصوص طریقے سے استعمال کرنے میں مدد دیتی ہیں، اور Omarchy ان میں سے سات بھیجتا ہے۔ omarchy skill نظام کو اپنی مرضی کے مطابق بنانے کا احاطہ کرتی ہے، جیسے آپ کی Hyprland ترتیب کو ٹھیک کرنا یا بار کو ایڈجسٹ کرنا۔ omarchy-make-theme، omarchy-make-plugin، omarchy-make-app، اور omarchy-make-game کچھ نیا بنانے کا احاطہ کرتی ہیں، omarchy-contribute کسی bug کی اطلاع دینے یا upstream اصلاح بھیجنے کا احاطہ کرتی ہے، اور omarchy-diagnose-crash کسی کریش کے core dump پر کام کرتی ہے۔ یہ Claude Code (`~/.claude/skills`)، Codex (`~/.codex/skills`)، Pi (`~/.pi/agent/skills`)، Antigravity (`~/.gemini/config/skills`)، Hermes (`~/.hermes/skills` اور ہر `~/.hermes/profiles/*/skills`)، اور عمومی `~/.agents/skills` مقام کے لیے skill ڈائریکٹریوں میں symlinked ہیں، لہٰذا زیادہ تر harnesses انہیں خود بخود اٹھا لیتے ہیں۔ اسی نام کے ساتھ آپ کا اپنا skill فولڈر فوقیت لیتا ہے۔

لیکن آپ کو ان skills کو تجرباتی سمجھنا چاہیے۔ مختلف ماڈلز اسے مختلف اثر کے ساتھ استعمال کریں گے۔ پہلے plan موڈ میں چلانا بہتر ہے، تاکہ آپ کو اندازہ ہو کہ ایجنٹ کیا تبدیل کرنا چاہے گا۔ اور پھر تبدیلیوں کو واپس کرنے یا حتیٰ کہ `omarchy reinstall configs` کو کال کرنے کے لیے تیار رہیں، اگر ایجنٹ ہر چیز کی گڑبڑ کر دے۔
