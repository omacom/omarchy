# Windows VM

Omarchy x86_64 مشینوں پر Docker VM کے ذریعے Windows چلانے کا ایک آسان طریقہ پیش کرتا ہے۔ آپ اسے Omarchy مینو (`Super + Space`) سے _Install > Windows_ استعمال کرتے ہوئے انسٹال کر سکتے ہیں۔

اس کے لیے آپ کی مشین کو KVM ورچوئلائزیشن درکار ہے، جو زیادہ تر مشینوں میں ہوتی ہے — لیکن کبھی کبھی یہ BIOS میں بند ہوتی ہے، اور اگر ایسا ہوا تو انسٹالر آپ کو بتا دے گا۔ آپ کو ڈسک کی جگہ بھی چاہیے ہوگی: جتنی آپ Windows کو دیں گے، اس کے علاوہ خود امیج کے لیے تقریباً 10GB۔

انسٹالر پوچھتا ہے کہ کتنی RAM، کتنے CPU کورز اور کتنی ڈسک حوالے کرنی ہے (64GB یا اس سے زیادہ مناسب کم از کم حد ہے)، پھر Windows کے لیے صارف نام اور پاس ورڈ پوچھتا ہے۔ انہیں خالی چھوڑیں تو آپ کو `docker` / `admin` ملتا ہے۔ ڈاؤن لوڈ میں کچھ وقت لگتا ہے — 10-15 منٹ معمول کی بات ہے — اور آپ براؤزر میں `http://127.0.0.1:8006` پر پیش رفت دیکھ سکتے ہیں۔ کنسول کھولنے سے پہلے براؤزر وہی صارف نام اور پاس ورڈ مانگتا ہے۔

## اسے استعمال کرنا

ایک بار انسٹال ہو جائے تو ایپ لانچر سے _Windows_ لانچ کریں۔ اس سے VM شروع ہو جاتی ہے اگر پہلے سے چل نہ رہی ہو، اور آپ کو RDP کے ذریعے فل اسکرین منسلک کر دیتی ہے۔ ٹھنڈی شروعات پر اسے 15-30 سیکنڈ دیں۔

RDP سیشن آواز، آپ کا مائیکروفون اور مشترکہ کلپ بورڈ ساتھ لے جاتا ہے، لہٰذا Linux اور Windows کے درمیان متن کاپی کرنا بس ہو جاتا ہے۔ ریزولوشن آپ کی ونڈو کے مطابق رہتی ہے، اور Omarchy آپ کی ڈسپلے اسکیلنگ آگے پہنچا دیتا ہے، اس لیے HiDPI اسکرین پر یہ دھندلا بکھرا منظر نہیں بنتا۔

جب آپ RDP ونڈو بند کرتے ہیں تو VM خودکار طور پر بند ہو جاتی ہے۔ اگر آپ اسے چلتا چھوڑنا پسند کریں — مثلاً اندر کوئی کام چل رہا ہو — تو اس کے بجائے اسے `omarchy windows vm launch --keep-alive` کے ساتھ لانچ کریں۔

باقی کنٹرولز اسی کمانڈ پر ہیں:

```bash
omarchy windows vm status    # is it running?
omarchy windows vm stop      # shut it down
omarchy windows vm launch    # start and connect
```

## فائلیں شیئر کرنا

آپ کی ہوم ڈائریکٹری میں موجود ڈائریکٹری `~/Windows` خودکار طور پر VM کے ساتھ شیئر ہوتی ہے۔ اگر آپ چاہتے ہیں کہ فائلیں Windows کے لیے قابل رسائی ہوں تو انہیں وہاں رکھیں۔ VM کو آپ کے فائل سسٹم کے کسی اور حصے تک رسائی حاصل نہیں، لہٰذا آپ Windows کی طرف سے آنے والی کسی بھی خرابی سے محفوظ ہیں۔ اس کی اپنی ورچوئل ڈسک `~/.windows` پر دستیاب ہے۔

وہ معروف ہوم راستے اپنے اپنے فائل سسٹمز پر ہی رہتے ہیں۔ وہ آپ کی ملکیت والی ڈائریکٹریوں کے لیے symlinks بھی ہو سکتے ہیں، جو اس وقت مفید ہے جب ورچوئل ڈسک کسی بڑی ڈرائیو پر رہتی ہو۔ انسٹالر اس فائل سسٹم پر خالی جگہ ناپتا ہے جس میں اصل میں `~/.windows` موجود ہو، ضروری نہیں کہ وہ فائل سسٹم جس میں آپ کی ہوم ڈائریکٹری ہو۔

ڈسک اور مشترکہ راستوں کو الگ، غیر اوورلیپ ہونے والی ڈائریکٹریوں کے طور پر رکھیں۔ ہٹانے کا عمل جان بوجھ کر ڈسک ڈائریکٹری کو خالی کرتا ہے لیکن مشترکہ ڈائریکٹری کو محفوظ رکھتا ہے۔ حذف کرنے سے فوراً پہلے، Omarchy ایک محدود کنٹینمنٹ جانچ کرتی ہے اور اگر وہ جانچ وقت ختم کر دے یا ثابت نہ کر سکے کہ دونوں ٹریز الگ ہیں تو کچھ بھی ہٹانے سے انکار کر دیتی ہے۔

VM شروع ہونے سے پہلے، Omarchy ان دونوں ڈائریکٹریوں کو کھولتی اور پن کرتی ہے، پھر عین انہی ڈائریکٹری inodes کو `/var/lib/omarchy/windows/mounts` کے نیچے نجی فی صارف اینکرز پر bind-mount کرتی ہے۔ Docker کو صرف یہ root سے محفوظ اینکرز نظر آتے ہیں۔ اس سے حسب ضرورت ڈسک مقامات برقرار رہتے ہیں جبکہ آپ کے طور پر چلنے والے کسی اور عمل کو اس بات سے روکا جاتا ہے کہ وہ جانچے گئے راستے کو مراعات یافتہ کنٹینر کے استعمال سے پہلے بدل دے۔ منتقلی کے دوران موجودہ ڈسک اور مشترکہ ڈائریکٹریوں کو موڈ `0700` تک سخت کر دیا جاتا ہے تاکہ دوسرے مقامی اکاؤنٹس ان کے مواد کو نہ دیکھ سکیں۔

VM کے پورٹس صرف localhost سے منسلک ہیں، لہٰذا آپ کے نیٹ ورک پر موجود کوئی چیز Windows مشین تک نہیں پہنچ سکتی۔ ویب کنسول کو بھی ترتیب دیا گیا Windows صارف نام اور پاس ورڈ درکار ہوتا ہے، جس سے کسی دوسرے مقامی اکاؤنٹ کو پورٹ 8006 کے ذریعے VM چلانے سے روکا جاتا ہے۔

## حدود اور لائسنسنگ

اس سیٹ اپ کے ساتھ کوئی GPU پاس تھرو نہیں ہے، لہٰذا یہ گیمنگ یا ویڈیو ایڈیٹنگ کے لیے موزوں نہیں۔ یہ Microsoft Office یا جو کچھ بھی آپ کو لازمی طور پر درکار ہو اسے چلانے کا بہترین طریقہ ہے۔

انسٹال ہونے والا ورژن Windows 11 Pro ہے، غیر فعال۔ گیٹ شدہ خصوصیات استعمال کرنے کے لیے آپ کو اپنا لائسنس کلید درکار ہوگی۔

اگر یہ کمپیوٹر Windows کے ساتھ آیا تھا تو Omarchy انسٹال کرنے کے بعد بھی OEM کلید فرم ویئر میں موجود رہتی ہے۔ اسے `omarchy windows key` کے ساتھ پرنٹ کریں۔ وہ کلید اس مشین سے بندھی ہے — وہ اس ہارڈویئر پر دوبارہ انسٹال شدہ Windows کو فعال کر دے گی، لیکن عام طور پر VM کو فعال نہیں کرے گی۔

آپ بعد میں ٹرمینل میں `omarchy windows vm install` چلا کر وسائل کی تقسیم تبدیل کر سکتے ہیں، جو آپ کے جوابات سے VM کی ترتیب کو دوبارہ لکھتا ہے۔ خود compose فائل اب `/var/lib/omarchy/windows/docker-compose.yml` پر رہتی ہے اور اس کی ملکیت root کے پاس ہے — یہ جان بوجھ کر ہے، تاکہ آپ کے طور پر چلنے والا کوئی عمل اسے دوبارہ نہ لکھ سکے اور مراعات یافتہ برنگ اپ آپ کی پوری ڈسک کو کنٹینر میں ماؤنٹ نہ کر دے۔ اگر آپ کو اسے ہاتھ سے ترمیم کرنے کی ضرورت ہو (مثلاً USB ڈیوائس ماؤنٹ کرنے کے لیے)، تو اسے `sudo` کے ساتھ ترمیم کریں اور تمام آپشنز [Dockur Windows پروجیکٹ](https://github.com/dockur/windows) پر دیکھیں۔

اس پوری چیز سے چھٹکارا پانے کے لیے Omarchy مینو سے _Remove > Windows_ استعمال کریں۔ اس سے `~/.windows` میں موجود VM کی ڈسک اور Windows کے اندر انسٹال شدہ سب کچھ حذف ہو جاتا ہے، لہٰذا پہلے VM سے جو کچھ درکار ہو اسے باہر کاپی کر لیں۔ آپ کا مشترکہ `~/Windows` فولڈر چھوڑ دیا جاتا ہے۔
