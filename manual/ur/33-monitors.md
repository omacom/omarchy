# مانیٹرز

Omarchy بطور ڈیفالٹ یہ فرض کرتا ہے کہ آپ 2x کی صلاحیت رکھنے والے retina-class ڈسپلے پر چل رہے ہیں۔ اچھے، کرسپ پروگرامر فونٹس حاصل کرنے کے لیے آپ کو یہی چاہیے۔ تقریباً تمام نئے پریمیم لیپ ٹاپس جن میں high-resolution اسکرینیں ہیں، اسی کے لیے optimize کیے گئے ہیں۔ یہی وہ ہے جو آپ 27" 5K [Apple Studio Display](https://www.apple.com/studio-display/)/[ProArt PA27JCV](https://www.asus.com/us/displays-desktops/monitors/proart/proart-display-5k-pa27jcv/)/[Samsung S9](https://www.samsung.com/us/computing/monitors/5k/27-viewfinity-s9-5k-monitor-with-thunderbolt-4-matte-display-and-smart-features-ls27c900panxza/)/[Kuycon G27P](https://kuycon.us/monitors/G27P/) یا 32" 6K [Apple XDR](https://www.apple.com/pro-display-xdr/)/[ProArt PA32QCV](https://www.asus.com/displays-desktops/monitors/proart/proart-display-6k-pa32qcv/)/[Kuycon G32P](https://kuycon.us/monitors/G32P/) پر چلانا چاہیں گے۔

لیکن اگر آپ 218 یا اس سے زیادہ PPI والے ڈسپلے پر نہیں چل رہے، تو آپ مانیٹر سیٹنگز تبدیل کرنا چاہیں گے۔ مثال کے طور پر، اگر آپ کے پاس 27" یا 32" 4K ہے، تو آپ اوپر والے بار میں موجود مانیٹر پینل سے اس کے لیے fractional اسکیل منتخب کر سکتے ہیں، یا `~/.config/hypr/monitors.lua` کھول کر اور اس combo کے لیے تجویز پر switch کر کے ہر مانیٹر کے لیے ڈیفالٹ set کر سکتے ہیں:

```lua
hl.monitor({ output = "", mode = "preferred", position = "auto", scale = 1.6 })
```

اگر آپ 1080p یا 1440p ڈسپلے استعمال کر رہے ہیں، تو غالباً آپ بس 1x اسکیلنگ استعمال کرنا چاہیں گے، اور GTK اور X11 ایپس کے لیے بھی یہی، تو آپ یہ استعمال کر سکتے ہیں:

```lua
hl.monitor({ output = "", mode = "preferred", position = "auto", scale = 1 })
hl.env("GDK_SCALE", "1")
```

`GDK_SCALE` میں تبدیلیاں تبدیلی کے بعد شروع کی گئی ایپلیکیشنز پر لاگو ہوتی ہیں (اور GTK صرف مکمل اعداد کو مانتا ہے، اس لیے اسے اپنے مانیٹر اسکیل کے قریب ترین integer پر رکھیں)۔ اس لیے یقینی بنائیں کہ تبدیلی کے بعد جو ونڈوز آپ کے پاس حد سے بڑی ہیں انہیں بند کر دیں (یا `Ctrl + Alt + Del` سے تمام ونڈوز بند کر دیں!)۔

آپ `Super + /` استعمال کر کے اوپر جانے کے لیے اور `Super + Alt + /` استعمال کر کے نیچے آنے کے لیے بڑے مانیٹر اسکیلنگ تناسبات (1x, 1.25x, 1.6x, 2x, 3x, 4x) میں سے بھی تیزی سے گزر سکتے ہیں، یا اوپر والے بار میں موجود مانیٹر پینل سے ایک منتخب کر سکتے ہیں۔ یہ صرف اس مانیٹر کو تبدیل کرتے ہیں جس پر آپ focused ہیں، اس لیے لیپ ٹاپ اسکرین اور بیرونی ڈسپلے ہر ایک کا اپنا اسکیل ہو سکتا ہے۔ پینل ہر مانیٹر کی resolution بھی set کرتا ہے۔ آپ کے انتخاب اس فزیکل مانیٹر کے لیے `~/.local/state/omarchy/monitors/settings` میں محفوظ کیے جاتے ہیں، اس لیے وہ reboot کے بعد بھی برقرار رہتے ہیں اور مانیٹر کے ساتھ اس port یا dock تک جاتے ہیں جس میں اسے اگلی بار لگایا جائے۔ وہ `~/.config/hypr/monitors.lua` میں اسی مانیٹر کے لیے کسی بھی اصول پر فوقیت رکھتے ہیں، جسے Omarchy کبھی edit نہیں کرتا۔ چونکہ `GDK_SCALE` تمام اسکرینوں کے لیے ایک ہی قدر ہے، اس لیے منتخب کردہ اسکیل اسے سب سے کم اسکیل والے مانیٹر سے set کرتا ہے، اس لیے X11 ایپس دوسری اسکرین پر حد سے بڑی ہونے کے بجائے زیادہ گھنی اسکرین پر تھوڑی چھوٹی نکلتی ہیں۔

### متن کو بڑا یا چھوٹا کرنا

مانیٹر اسکیلنگ ہر چیز کا سائز تبدیل کرتی ہے۔ اگر آپ کو صرف بڑا یا چھوٹا _متن_ چاہیے، تو اس کے لیے ایک ہی knob ہے:

```
omarchy display text size 14
```

یہ 9 اور 20 کے درمیان pixel سائز لیتا ہے، اور Omarchy shell، GTK ایپلیکیشنز، اور آپ کے terminal کو ایک ساتھ حرکت دیتا ہے، اس لیے پورا ڈیسک ٹاپ تناسب میں رہتا ہے۔ آپ کہاں ہیں یہ دیکھنے کے لیے اسے بغیر کسی argument کے چلائیں، اور ڈیفالٹ پر واپس جانے کے لیے `omarchy display text size reset` چلائیں۔ Foot واحد پیچھے رہ جانے والا ہے: اس کے پاس اپنی config دوبارہ load کرنے کا کوئی طریقہ نہیں ہے، اس لیے چل رہے terminal اپنا پرانا سائز برقرار رکھتے ہیں جب تک آپ نیا نہ کھولیں۔

### لیپ ٹاپ ڈسپلے کو پھیلانا اور میرر کرنا

جب آپ اپنے لیپ ٹاپ سے بیرونی اسکرین منسلک کرتے ہیں، تو ڈسپلے خود بخود extend ہو جاتا ہے۔ لیکن آپ Omarchy مینو میں _Trigger > Hardware_ یا `Super + Ctrl + Alt + Delete` استعمال کر کے اسے اس کے بجائے mirroring میں تبدیل کر سکتے ہیں۔ یہ خاص طور پر مددگار ہے اگر وہ بیرونی اسکرین projector ہے، اور آپ کام کرتے ہوئے کچھ دکھانا چاہتے ہیں۔

جب آپ extend کر رہے ہوں، تو لیپ ٹاپ کا ڈھکن بند کرنے سے اندرونی اسکرین خود بخود بند ہو جائے گی۔ ڈھکن کھولنے سے وہ دوبارہ آن ہو جائے گی۔ آپ Omarchy مینو میں _Trigger > Hardware_ یا `Super + Ctrl + Delete` استعمال کر کے اسے دستی طور پر بھی کنٹرول کر سکتے ہیں۔

### متعدد اسکرینوں کو ترتیب دینا

Hyprland متعدد اسکرینوں کے ساتھ بہت اچھا کام کرتا ہے۔ اوپر والے بار میں موجود مانیٹر پینل انہیں وہیں بناتا ہے جہاں وہ بیٹھی ہیں: ایک کو دوسری کے کنارے کے خلاف drag کر کے اسے وہاں منتقل کریں، اور ترتیب ہر مانیٹر کی دیگر سیٹنگز کے ساتھ محفوظ کر دی جاتی ہے۔ کسی بھی ایسی چیز کے لیے جس کا پینل احاطہ نہیں کرتا، انہیں ترتیب دینے کے طریقے کے بارے میں [Hyprland مانیٹر دستاویزات](https://wiki.hypr.land/Configuring/Basics/Monitors/) میں مزید پڑھیں۔ Omarchy میں، یہ `~/.config/hypr/monitors.lua` میں `hl.monitor` اندراجات کے طور پر جاتی ہیں — فائل کسی مخصوص مانیٹر کو resolution، position، اور rotation پر pin کرنے کے لیے commented مثالوں کے ساتھ آتی ہے۔

ہر مانیٹر کے اپنے ورک اسپیسز 1 سے 10 تک ہوتے ہیں، اس لیے `Super + 1` کا ہمیشہ مطلب اس مانیٹر کا پہلا ورک اسپیس ہوتا ہے جس پر آپ ہیں۔ پس پردہ، Hyprland پھر بھی تمام مانیٹروں میں ورک اسپیسز کو نمبر دیتا ہے: آپ کی لیپ ٹاپ اسکرین (یا پہلا مانیٹر) کو 1–10، اگلے مانیٹر کو 11–20 ملتے ہیں، اور اسی طرح آگے، اور ہر مانیٹر ہر بار جب آپ اسے لگاتے ہیں اپنا block برقرار رکھتا ہے۔ اگر آپ کسی مخصوص مانیٹر کے لیے [ورک اسپیس کے اصول](https://wiki.hypr.land/Configuring/Basics/Workspace-Rules/) یا ونڈو کے اصول لکھتے ہیں تو وہ نمبر استعمال کریں، اس لیے ورک اسپیس 12 آپ کے دوسرے مانیٹر کا دوسرا ورک اسپیس ہے۔ `~/.local/state/omarchy/monitors/workspaces` فہرست دیتا ہے کہ کس مانیٹر کے پاس کون سا block ہے۔

تیر والی keys ان مانیٹروں کے پار کام کرتی ہیں جو آپ کی ترتیب میں ایک کنارہ share کرتے ہیں۔ وہ اسکرینیں جو صرف ایک کونے پر چھوتی ہیں، یا جن کے درمیان خلا ہے، پڑوسی نہیں ہیں، اس لیے ان کے درمیان جانے کے لیے `Ctrl + Alt + Tab` استعمال کریں۔

| ہاٹ کی | مانیٹروں کے پار |
| --- | --- |
| `Super + Arrow` | جب اس سمت میں کوئی ونڈو باقی نہ رہے تو focus اس طرف والے مانیٹر پر منتقل کر دیتی ہے |
| `Super + Shift + Arrow` | اس طرف والے مانیٹر پر موجود ونڈو کے ساتھ swap کر دیتی ہے |
| `Super + Alt + Arrow` | ونڈو کو اس طرف والے مانیٹر پر موجود ایک گروپ میں منتقل کر دیتی ہے |
| `Super + Shift + Ctrl + Arrow` | ونڈو کو اس طرف والے مانیٹر پر، اس ورک اسپیس پر منتقل کر دیتی ہے جو وہ دکھا رہا ہے |
| `Super + Shift + Alt + Arrow` | ورک اسپیس کو اس طرف والے مانیٹر پر منتقل کر دیتی ہے، اگر اس کا نمبر خالی ہو تو وہی نمبر برقرار رکھتی ہے |
| `Ctrl + Alt + Tab` / `Ctrl + Alt + Shift + Tab` | ترتیب کچھ بھی ہو، focus اگلے یا پچھلے مانیٹر پر منتقل کر دیتی ہے |
| `Super + 1-0`, `Super + Tab`, `Super + Scroll Wheel` | اسی مانیٹر پر رہتی ہیں جس پر آپ ہیں |

آپ [Hyprmon](https://github.com/erans/hyprmon/) بھی دیکھ سکتے ہیں، اگر آپ متعدد اسکرینوں کی positioning میں مدد کے لیے TUI چاہتے ہیں۔

### چمک کنٹرول کرنا

مانیٹر کی چمک brightness اوپر/نیچے کے لیے مخصوص function keys سے کنٹرول کی جاتی ہے۔ اگر آپ انہیں دباتے وقت shift کو دبائے رکھیں، تو آپ زیادہ سے زیادہ یا کم سے کم چمک پر چلے جائیں گے۔ keys اس ڈسپلے کو کنٹرول کرتی ہیں جس پر آپ focused ہیں، اس لیے DDC/CI بولنے والے بیرونی مانیٹر بھی اسی طرح adjust کیے جاتے ہیں جیسے لیپ ٹاپ اسکرین۔

### Apple ڈسپلےز

اگر آپ Apple ڈسپلے استعمال کر رہے ہیں، تو باقاعدہ keyboard brightness keys بھی خود بخود کام کریں گی، اگر آپ Apple ڈسپلے پر focused ہیں۔ یہ `asdcontrol` کمانڈ کے ذریعے کیا جاتا ہے۔

نوٹ کریں کہ اگر آپ Apple 6K XDR ڈسپلے استعمال کر رہے ہیں، تو آپ کو اپنی `hyprctl monitors` فہرست میں ایک phantom اسکرین نظر آ سکتی ہے۔ آپ اسے `~/.config/hypr/monitors.lua` میں `hl.monitor({ output = "DP-2", disabled = true })` جیسی کسی چیز سے بند کر سکتے ہیں۔

Intel مشینوں پر، آپ کو Apple ڈسپلےز کو باقاعدہ Thunderbolt کیبل استعمال کر کے منسلک کرنا چاہیے۔ Thunderbolt کے بغیر دیگر مشینوں پر، اسے کام کرانے کے لیے آپ کو عام طور پر [DP + USB-A -> USB-C کیبل](https://www.amazon.com/dp/B0BNX7MS6N) استعمال کرنا ہوگی۔
