# AI

Omarchy obsahuje spouštěče pro níže uvedené kódovací agenty, aniž by za vás vybírala výchozího. Spuštěním příkazu nainstalujete jeho CLI při prvním použití a po zobrazení výzvy se ověříte. Hermes a OpenClaw jsou výjimky: přes mise se pro ně nic neinstaluje a výběr kteréhokoli z nich nastaví jeho vlastní samoaktualizační kopii, jak níže vysvětluje část _Desktopové aplikace_.

### Instalace a aktualizace agentů

Kromě Hermes a OpenClaw tito agenti používají línou instalaci mise: první spuštění nainstaluje CLI a další spuštění ho znovu použijí. mise také nejvýše jednou za čtyři hodiny zkontroluje, zda pro nainstalovaného agenta nevyšla nová verze, těsně před jeho spuštěním nebo na pozadí při zobrazení promptu shellu. Pokud tato aktualizace selže nebo jste offline, spustí se nainstalovaná verze. `omarchy update` aktualizuje nainstalované agenty spolu se zbytkem Omarchy a `mup` aktualizuje pouze nástroje spravované přes mise.

Vlastní aktualizátor agenta, například `claude update`, `codex update` nebo tlačítko aktualizace v aplikaci, neaktualizuje instalaci spravovanou přes mise. `codex update` selže a `claude update` může nahlásit úspěch, přičemž nainstaluje samostatnou kopii, kterou mise nesleduje. Pokud raději chcete používat nativní instalační program a aktualizátor agenta, přidejte ho do `disable_tools`; viz [Předinstalované CLI nástroje](18-development-tools.md#preinstalled-cli-tools).

Chcete-li nainstalovat všechny nakonfigurované líné nástroje dříve, než je budete potřebovat, spusťte `mise install --include-lazy`. To zahrnuje i ostatní výchozí CLI nástroje Omarchy a také agenty. Informace o instalaci jednoho nástroje nebo použití vlastní instalace najdete v části [Předinstalované CLI nástroje](18-development-tools.md#preinstalled-cli-tools).

`grok` se instaluje prostřednictvím prvotřídního balíčku `grok` v mise, stejně jako `claude` a `codex`. Spusťte `grok`, nebo ho vyberte v části _Agent > Harness_. Přeskočte instalační program `curl | bash` na x.ai. Tato cesta umístí druhou kopii do `~/.grok/bin`, přidá ji na začátek `PATH` a přepíše wrapper Omarchy.

`dsh` otevře své prohlížečové UI na `127.0.0.1:3080`, přičemž adresář, ze kterého byl spuštěn, je jeho výchozím pracovním prostorem. Jeho prohlížečové UI nepřijímá žádný počáteční prompt, takže `omarchy agent prompt` ho otevře s promptem ve vaší schránce, abyste ho mohli vložit. Omarchy ho spouští s předvolbou oprávnění DeepSeeku bez schvalování. DeepSeek Harness nahrává protokoly relací společnosti DeepSeek, když používáte její oficiální API modelů; vypněte to v jeho prohlížečovém UI v části _Settings > General > Upload Session Log_. Zpětná vazba, kterou mu pošlete, se nahrává spolu s relací také, pokud ho nespustíte s `DSH_TELEMETRY_MODE=DISABLED`.

### Výchozí agent

Vyberte si výchozího agenta pomocí `omarchy default agent <name>` nebo v části _Agent > Harness_ v Omarchy Menu (`Super + Space`). Pokud agent ještě není nainstalován, jeho výběr ho nejprve nainstaluje a také získá vlastní spouštěč ve spouštěči aplikací, vedle položky Agent. Čerstvá Omarchy vás k tomuto výběru vyzve jednorázovým oznámením.

Výběr Claude se také pokusí nastavit jeho rozšíření prohlížeče pro Chromium, Chrome, Brave, Brave Origin a Edge. Nastavení rozšíření platí pro všechny uživatele a může vyžadovat vaše systémové heslo; zrušení nebo neúspěšná instalace rozšíření přesto vybere a spustí Claude. Restartujte prohlížeč, v případě výzvy povolte rozšíření a přihlaste se do Claude, abyste dokončili jeho připojení. Spusťte v Claude `/chrome` a zkontrolujte připojení. Firefox a Zen toto rozšíření nepodporují. Pokud už byl Claude vaším výchozím agentem předtím, než bylo toto nastavení přidáno, vyberte ho znovu, aby se rozšíření nainstalovalo.

Jakmile si vyberete, `Super + Shift + Ctrl + A` spustí výchozího agenta ve vyhrazeném okně terminálu (nebo zobrazí výběr, pokud jste si ještě nevybrali). Můžete ho také spustit rovnou k úkolu pomocí `omarchy agent prompt "Review this project"`. Freebuff a DeepSeek Harness nepřijímají žádný počáteční prompt, takže se místo toho otevřou s promptem ve vaší schránce, abyste ho mohli vložit. Takto spuštění agenti běží bez dohledu ve svých příslušných režimech, kdy se nezastavují, aby se zeptali, takže buďte připraveni na to, že budou skutečně něco dělat! MiniMax Code pro své interaktivní relace žádný takový režim nemá, takže žádá o oprávnění jako obvykle. A protože agenti odmítají zapamatovat si důvěru pro váš domovský adresář, spuštění z `$HOME` místo toho začínají v `~/Work`.

Existují také zkratky v terminálu: `a` spustí výchozího agenta přímo v aktuálním terminálu, zatímco `c`, `cx` a `cy` spustí přímo OpenCode, Claude Code a Codex (opět v jejich režimech automatického schvalování). Změny motivu se synchronizují i do agentů: Claude Code, Pi, OpenCode a Hermes (jakmile ho Omarchy nainstalovala) se všechny přizpůsobí, když přepnete motiv Omarchy.

### Vaše pokyny pro agenty

Osobní pravidla pro každého agenta patří do `~/.agents/AGENTS.md`, vedle sdílených skillů v `~/.agents/skills`. Otevřete ho v části _Agent > Instructions_, která ho také propojí do každého harnessu, který si udržuje vlastní globální soubor: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` pro Copilot a tak dále. Crush a Amp čtou odkaz `~/.config/AGENTS.md`, zatímco omp, Kimi a DeepSeek Harness čtou přímo `~/.agents/AGENTS.md`. Výběr výchozího agenta ho propojí také. Soubor s pokyny, který jste už měli, se stane sdíleným, pokud ještě žádný neexistoval; jinak je ponechán vedle odkazu jako `.bak`. Po instalaci dalšího agenta spusťte `omarchy agent instructions`, abyste propojení obnovili.

### Panel agentů

Horní lišta má ikonu agentů. Než si agenta nastavíte, její panel vás provede přihlášením do Claude, Codex nebo Grok a první z nich se stane vaším výchozím agentem. Poté panel umístí každé předplatné na jednu stránku: každého agenta a účet s jeho plánem, měřič pro každý z jeho 5hodinových limitů relace a týdenních limitů s časem do jeho resetování (najeďte myší pro přesné procento) nebo zbývající předplacený zůstatek, pod řádkem, který se střídavě mění tím, co jste využili u všech z nich, například tokeny za tento týden a váš nejpoužívanější model. V části _Make something cool_ nabízí úvodní prompty pro nový motiv, plugin, aplikaci nebo hru, které předají úkol vašemu výchozímu agentovi. Aplikace se vytvářejí stejným způsobem jako vlastní Hype, Monologue a Omacut od Omarchy, v C++ a Qt Quick, podle agent skillu omarchy-make-app, a kompilátor a součásti Qt, které potřebují, jsou nainstalované. Hry jsou jedna stránka three.js v `~/Games/vibes`, podle agent skillu omarchy-make-game, a všechny se otevírají z jednoho spouštěče Game Vibes v aktuálním motivu; načítají three.js z webu, takže ke spuštění potřebují připojení. Claude Code, Codex, Grok, Kimi, Cursor a jeho příděl Grok Bot, GitHub Copilot, Muse, Antigravity a Devin jsou pokryty hned po instalaci se svými limity, Kimchi se svým plánem, předplacenými kredity a rozpočty útraty a Hermes, Mistral Vibe a Qwen Code zobrazí své relace a tokeny, jakmile je použijete. Objeví se také plány poskytovatelů a klíče, které používáte prostřednictvím pi, omp nebo opencode: OpenCode Zen a Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan a Synthetic se svými limity; OpenRouter a DeepSeek se svými předplacenými zůstatky; Fireworks se svou útratou za posledních 30 dní. Tokeny z modelů, které spouštíte na vlastním hardwaru, se také započítávají do součtů; samotné modely mají vlastní panel, popsaný v části [Lokální modely](#local-models). Každý agent se započítává jednou, u toho, kdo ho účtuje, bez ohledu na to, přes kolik harnessů ho řídíte.

Kliknutím levým tlačítkem na ikonu na liště nebo stisknutím `Super + Ctrl + X` zobrazíte panel, kliknutím pravým tlačítkem spustíte výchozího agenta a kliknutím prostředním tlačítkem obnovíte. Záznamy o využití, které za ním stojí, se každých 15 minut znovu generují příkazem `omarchy agent usage update` a panel může dokonce sloučit využití z vašich dalších strojů prostřednictvím synchronizované složky. Úplné nastavení najdete v README v `$OMARCHY_PATH/shell/plugins/agents/`.

### Několik předplatných

Pokud platíte za více než jeden plán Claude, Codex nebo Grok — například osobní Max a pracovní — Omarchy je může všechny udržet přihlášené a pohybovat se mezi nimi. Přidejte předplatné pomocí + v panelu agentů, které vás tím provede přímo tam, nebo pomocí `omarchy agent account add claude Work` (nebo `codex`, nebo `grok`). Nainstaluje CLI, pokud chybí. První účet pro poskytovatele se přihlašuje prostřednictvím vašeho běžného prohlížeče, přesně tam, kde ho CLI vždy hledá. Každý další se přihlašuje prostřednictvím soukromého okna, takže účet, ke kterému je váš prohlížeč už přihlášen, není omylem zachycen; přihlaste se tam jako účet, který přidáváte, a nejprve zavřete všechna soukromá okna, která už máte otevřená. Nikdy se kvůli tomu neodhlasujte z CLI: odhlášení zruší uložené přihlášení a tento účet by musel být znovu přidán.

Chcete-li zkopírovat přihlášení k předplatnému na jiný stroj s Omarchy přes SSH, spusťte `omarchy agent account copy user@laptop`. Odesílatel poskytne dočasného příjemce, když cílový stroj žádného nainstalovaného nemá, takže starší stroje s Omarchy mohou přijímat účty bez aktualizace. Nainstalovaní příjemci mají přednost. To zkopíruje všechna předplatná Claude, Codex a Grok; přidejte názvy poskytovatelů, abyste je vybrali, například `omarchy agent account copy laptop claude`. Názvy účtů a ID příkazů odpovídají zdroji, včetně účtů, které už jsou na cíli přítomny. Nesouvisející cílové účty dostanou číselnou příponu, pokud jejich názvy kolidují, a nastavení, skilly, pluginy a historie konverzací zůstávají lokální na každém stroji.

Stávající cílové přihlašovací údaje se zachovají. Zdrojový účet, který je tam už přihlášen, má synchronizovaný název, aniž by byly nahrazeny jeho přihlašovací údaje; ostatní účty se přidají vedle něj. Chcete-li nahradit uložené přihlašovací údaje pro odpovídající účty, použijte `omarchy agent account copy --replace laptop claude` poté, co na cíli ukončíte relace tohoto účtu. Čerstvý cíl také získá aktivní účet a předvolby přepínání zdroje; zavedený cíl si zachová své vlastní.

Přihlašovací údaje cestují přes SSH a ukládají se do soukromých souborů na cíli, takže kopírujte pouze na stroje, kterým důvěřujete. Jedná se o jednorázovou kopii, nikoli o průběžnou synchronizaci. Obnovovací tokeny Codexu může jiný stroj rotovat, takže zkopírované přihlášení bude potřebovat obnovení; samostatná přihlášení zůstávají nejspolehlivější volbou pro současné použití na několika strojích. Viz [Pokyny Codexu k ověřování účtů](https://developers.openai.com/codex/auth/ci-cd-auth).

Jeden účet na poskytovatele je aktivní a každá nová relace začíná jako on: `cx`, `cy`, prosté `claude`, `codex` nebo `grok`, cokoli spuštěného prostřednictvím `omarchy agent` a skripty nebo editory, které nacházejí CLI na `PATH`. Přepněte pomocí `omarchy agent account use work` (a zpět pomocí `omarchy agent account use main`), nebo v panelu stisknutím čísla účtu a poté `Enter` (nebo kliknutím na jeho tlačítko Use). Běžící relace Claude se přepnou také, od své další zprávy: každá relace Claude běží v `~/.claude`, která vždy obsahuje přihlášení aktivního účtu. Relace Claude spuštěná starší Omarchy ve vlastní složce účtu si toto přihlášení ponechává, dokud neskončí, takže přepnutí tyto relace pojmenuje a samo dokončí, jakmile zmizí. Běžící relace Codex a Grok zůstávají na účtu, se kterým začaly. Historie konverzací, nastavení, skilly a pluginy jsou sdíleny napříč účty, takže `claude --continue` ve stejné složce pokračuje tam, kde jste na novém účtu přestali.

S více než jedním účtem panel zobrazuje limity každého účtu vedle sebe, přičemž aktivní je označen. Ve výchozím nastavení vás Omarchy upozorní, když aktivní účet překročí 95 % limitu, a kliknutí na oznámení přepne na účet s největší rezervou. Najeďte myší na řádek účtu v panelu a klikněte na Autoswitch, které se objeví vedle Use (nebo stiskněte `m`), nebo spusťte `omarchy agent account mode auto`, aby se přepínal sám; když je zapnutý, Autoswitch nahradí Use a opětovným kliknutím se vrátíte k upozorňování. Přidejte číslo, abyste změnili práh, například `omarchy agent account mode auto 90`. Pokud je každý účet nad prahem, dozvíte se o tom jednou, spolu s tím, který účet se uvolní jako první. Zatímco je aktivní účet do 15 bodů od svého prahu (80 % při výchozím nastavení), jeho limity se kontrolují každé tři minuty místo každých 15.

`omarchy agent account list` zobrazí každý účet a jeho nejnovější limity, `omarchy agent account remove work` jeden zapomene a `omarchy agent account rename primary Hey` jeden přejmenuje (nebo klikněte na název účtu v panelu). Tyto příkazy pracují s účty vašeho výchozího agenta; chcete-li dosáhnout na jiného poskytovatele, nejprve ho pojmenujte, například `omarchy agent account use codex side`. Přihlášení, které jste už měli v `~/.claude` nebo `~/.codex`, je účet _Main_. Účet Codexu zůstává tam, kde je; účet Claude čeká ve vlastní složce, zatímco je aktivní jiný účet. Účet, který zůstal nepoužívaný déle než zhruba osm hodin, může zobrazit _Sign-in required_; klikněte na něj, abyste tento účet znovu přihlásili přímo v panelu, nebo na něj přepněte a spusťte relaci, což přihlášení obnoví samo. Servery MCP, které přidáte pomocí `claude mcp add`, dosáhnou na každý účet Claude, protože všechny běží v `~/.claude`; u Codexu a Groku servery, které jste měli, když byl účet přidán, přijdou spolu s ním, ale pozdější dosáhnou pouze na účet, do kterého jste je přidali. Claude Desktop si udržuje vlastní přihlášení a nástroje Codex nebo Grok nakonfigurované s absolutní cestou k binárce CLI přepnutí nenásledují. Explicitní `CLAUDE_CONFIG_DIR`, `CODEX_HOME` nebo `GROK_HOME` má přednost před vybraným účtem.

### Diagnostika pádů

Omarchy sleduje systemd-coredump kvůli pádům procesů. Jakmile si vyberete výchozího agenta, každý váš program, který vytvoří core dump, vyvolá oznámení "Process crashed" — klikněte na něj a pád je předán vašemu výchozímu agentovi spolu se skillem omarchy-diagnose-crash od Omarchy, který agenta provede zjištěním faktů z core dumpu a rozhodnutím, zda pád stojí za to nahlásit upstreamu. Můžete ho také spustit ručně proti libovolnému PID z `coredumpctl list` pomocí `omarchy agent crash <pid>`.

Sledování je ve výchozím nastavení zapnuté. Vypněte ho v části _Trigger > Toggle > Crash Capture Off_ (nebo pomocí `omarchy toggle crash-capture`) a oznámení přestanou; `omarchy agent crash <pid>` stále funguje ručně.

Pády lze také ztlumit jeden program po druhém, což vám diagnostika na konci nabízí. `omarchy crash mute hyprland` zastaví oznámení pouze pro tento program, `omarchy crash mute hyprland off` je vrátí zpět a `omarchy crash mute` samo o sobě vypíše, co jste ztlumili. Přijímá cestu k binárce stejně ochotně jako její název, takže `omarchy crash mute /usr/bin/hyprland` dělá totéž. Název s mezerou dejte do uvozovek, například `omarchy crash mute 'Some App'`. Všechno ostatní stále oznamuje a ztlumený program stále padá — to skrývá připomenutí, nic to neopravuje.

### Desktopové aplikace

Menu _Install > AI_ obsahuje také několik grafických AI aplikací: Amp Desktop, Antigravity Desktop, desktopovou aplikaci ChatGPT, desktopovou aplikaci Claude (linuxová beta Anthropicu, s kartami Chat, Cowork a Claude Code), Grok Bot pro chatování s modely xAI, Herdr Desktop, Hermes Desktop, OpenClaw, desktopovou aplikaci Perplexity a T3 Code. Grok Bot je desktopová chatovací aplikace. Kódovací agent je příkaz `grok`.

Hermes Desktop je ta, o které je dobré vědět, protože stroj má jeden Hermes a je to ten z aplikace: Hermes se instaluje pouze prostřednictvím aplikace a příkaz `hermes`, který výchozí agent spouští, je ten z aplikace. Výběr Hermes jako výchozího agenta nainstaluje totéž, co položka _Install > AI_: balíček a runtime Hermes v `~/.hermes` nastavený vlastním instalačním programem Hermes, což poprvé trvá několik minut. Tento runtime je ten jeden Hermes, který používají terminálový příkaz `hermes`, výchozí agent i aplikace, a aktualizuje se sám pomocí `hermes update`, místo aby čekal na vydání Omarchy. Jeho instalace také předá Hermes motiv Omarchy jako skin s názvem `omarchy`, který každý povrch Hermes následuje, když přepínáte motivy; vyberte si jiný v nastavení Appearance v Hermes nebo pomocí `/skin`, pokud raději chcete, aby to nedělal, a Omarchy tuto volbu nechá být. Odebrání aplikace v části _Remove > AI_ nejprve zavře Hermes, včetně brány, vezme s sebou tento runtime a zachová vaše chaty, vzpomínky a skilly, které si Hermes sám napsal, pokud neřeknete jinak: zeptá se, zda mají odejít i tato data a vaše nastavení připojení, přičemž výchozí odpověď je ne.

Desktopovým zážitkem OpenClaw je jeho Control UI, které se otevírá jako webová aplikace podporovaná jeho vlastní lokální bránou. OpenClaw žije v `~/.openclaw` a aktualizuje se sám: použijte tlačítko "Update Gateway" v Control UI nebo spusťte `openclaw update` a brána se restartuje na nové verzi. Omarchy pouze vybírá verzi, od které čerstvá instalace začíná. OpenClaw může být také vaším výchozím agentem: jeho výběr v části _Agent > Harness_ nastaví tutéž kopii v `~/.openclaw` a agent otevře terminálové UI OpenClaw připojené k jeho bráně. Odebrání OpenClaw v části _Remove > AI_ vezme s sebou službu brány a aplikaci a poté se zeptá, zda má odejít i `~/.openclaw`, protože to obsahuje vaše chaty a přihlašovací údaje spolu se samotným OpenClaw a runtime pluginů, které stahuje; ve výchozím nastavení si ho ponechá a opětovná instalace OpenClaw ho zachytí zpět.

Herdr Desktop je desktopová aplikace [Herdr](https://herdr.dev): prostory, karty a panely terminálů a kódovacích agentů, které dál běží v jeho jádru, když okno zavřete. Pochází z vlastního instalačního programu Herdr, nikoli z balíčku, takže žije v `~/.local/share/herdr-app`, přináší s sebou své jádro v `~/.local/bin/herdr-core`, když ho ještě nemáte, a aktualizuje obojí sám. Stojí vedle příkazu `herdr`, který Omarchy dodává na `Super + Ctrl + Return`, místo aby ho nahradil, a získává přímé klávesy tohoto příkazu: `Alt + Return` a `Alt + Shift + Return` rozdělí panel dolů nebo doprava, `Alt + Escape` ho zavře, `Ctrl + Alt + Arrow` se pohybuje mezi panely, `Alt + 1..9` a `Alt + Left/Right` vyberou kartu a `Alt + Up/Down` se pohybují mezi prostory. `Ctrl + 1..9` vybírá prostor a `Alt + Shift + Up/Down` prochází agenty. Klávesy s prefixem `Ctrl + Space` zůstávají pouze pro terminál, protože aplikace nemůže pro sekvenci držet prostou klávesu Ctrl. Omarchy je zapisuje do `~/.config/herdr-app/keys.json` a `omarchy-refresh-herdr-app` je vrátí zpět. Jeho instalace vybere motiv Omarchy pro Herdr, který od té doby následuje váš motiv Omarchy. Herdr si udržuje jeden motiv pro světlý režim a jeden pro tmavý, takže po přepnutí mezi tmavým a světlým motivem Omarchy vyberte Omarchy v nástroji pro výběr motivu v Herdr ještě jednou pro druhý režim.

T3 Code běží ze svého oficiálního vydání AppImage v `~/.local/share/t3code`, nikoli z balíčku, takže se aktualizuje sám. Jeho instalace se zeptá, zda začít na kanálu Stable nebo Nightly; přepněte později v nastavení T3 Code. Vaše vlákna a nastavení žijí v `~/.t3` a odebrání T3 Code v části _Remove > AI_ je vezme s sebou.

### Lokální modely

Spusťte otevřený model na vlastním stroji pro své kódovací agenty. Vaše prompty a kód zůstávají na stroji; nic odeslaného modelu ho neopustí. Začněte tímto:

```bash
omarchy models use best text
```

To nastaví nejlepší textový model pro tento stroj, ten druh, který vaši agenti používají. Modely pro obrázky, video a hudbu mají každý svůj nejlepší: `omarchy models use best image`, `video` nebo `music`. Spusťte `omarchy models use best`, abyste viděli výběr pro každý druh na tomto stroji.

Nebo otevřete panel lokálních modelů z jeho ikony jisker v horní liště, vedle ikony agentů, nebo pomocí Super + Ctrl + Alt + X a zvolte +. Ikona se zobrazí, když se na tento stroj vejde model. Podman, který modely spouští, je součástí Omarchy, stejně jako sada nástrojů pro kontejnery NVIDIA na stroji s NVIDIA, která jim poskytuje GPU; pokud cokoli z toho chybí, první nastavení to nainstaluje. Omarchy pak vybere doporučený model pro tento stroj, stáhne ho a spustí. Očekávejte stažení v řádu desítek GB a využití většiny paměti stroje, zatímco model běží: Flash Next používá asi 100 GiB se svým plným kontextem 256K. Pokud jiné modely drží paměť, kterou potřebuje, je nastaven zastavený, připravený ke spuštění, jakmile jeden zastavíte. Model se při odhlášení zastaví; zastavte ho sami, když paměť potřebujete na něco jiného.

`omarchy models list` zobrazí možnosti a vysvětlí, proč se některé nevejdou. Chcete-li nastavit další, spusťte `omarchy models use <recipe>`. Dnes jsou pro stroje Strix Halo se 128 GB k dispozici `qwen3.8-flash-next-gufo` a `qwen3.8-27b-gufo`; ten 27B zabírá asi 40 GiB, takže nechává prostor pro další práci. Na 64GB notebooku s Intel Arc B390 běží `qwen3.6-35b-a3b-llamacpp` v asi 30 GiB. Nové recepty a doporučení přicházejí s `omarchy update`, prostřednictvím balíčku.

Každý model, který nastavíte, získá vlastní řádek v panelu lokálních modelů: play pro jeho spuštění, pause pro jeho zastavení a uvolnění jeho paměti a tlačítko terminálu pro otevření vašeho agenta na něm. Nahoře lišta ukazuje, jak je paměť stroje rozdělena mezi samotnou Omarchy (systém a vaše aplikace), každý běžící model a co je volné. Ukažte na zastavený model a lišta ukáže, zda se vejde, nebo o kolik mu chybí. Několik jich může běžet najednou, když se společně vejdou do paměti; pokud se jeden nevejde, Omarchy řekne, který běžící model zastavit. Přetažením řádků za jejich logo je přeřadíte a stisknutím Delete na vybraném řádku odstraníte model a jeho stažení.

Každý kódovací model, který nastavíte, také získá vlastní položku ve spouštěči aplikací, pod názvem modelu a s logem jeho tvůrce, stejně jako přihlášení do Claude, Codex nebo Grok přidá jednu. Otevře vašeho agenta na tomto modelu a nejprve model spustí, pokud neběží: terminál ukáže jeho načítání a předá řízení agentovi, jakmile bude připraven. Odebrání modelu odebere jeho položku.

Ne každý model je pro kódování. Modely pro obrázky, video a hudbu se místo toho otevírají ve Fantasi, aplikaci Omarchy pro vytváření obrázků, videa a hudby s modelem běžícím na tomto stroji, vybrané tam nebo z jejich řádku v panelu lokálních modelů.

Model dál běží přesně tak, jak byl nastaven, takže aktualizace Omarchy nikdy nerestartuje jeden pod vašimi agenty. Když má Omarchy novější runtime nebo novější váhy pro model, který jste nastavili, jeho řádek zobrazí tlačítko aktualizace: stiskněte ho a model se znovu nastaví na pozadí, přičemž stáhne pouze to, co se změnilo, a restartuje se na novou verzi. Model, který byl zastavený, zůstane zastavený. `omarchy models update` udělá totéž pro každý model z terminálu.

Z příkazového řádku `omarchy models start <recipe>` a `omarchy models stop <recipe>` dělají totéž, `omarchy models status` zobrazí každý model a `omarchy agent --local` otevře vašeho výchozího agenta na posledním modelu, který jste spustili. pi, OpenCode a Qwen Code jeden mohou použít; u jakéhokoli jiného výchozího agenta se otevře v pi, nebo v OpenCode, pokud pi nemáte. pi také vypíše každý model, který jste nastavili, a ty na strojích, se kterými jste se spárovali, ve svém vlastním nástroji pro výběr modelu, takže prosté `pi` k nim dosáhne také. Připojit se může i libovolný klient kompatibilní s OpenAI: `status` zobrazí adresu každého modelu (první je `http://127.0.0.1:11435/v1`), název receptu je model a klíč je v `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` smaže model a stažení, která žádný jiný model nepoužívá.

Runtime třetích stran jsou označeny svým vydavatelem. Omarchy spouští každý model bez přístupu k síti.

### Lokální LLM

Omarchy doporučuje dva způsoby spouštění lokálních modelů LLM: LM Studio a Ollama. LM Studio poskytuje GUI rozhraní pro hledání modelů s otevřenými váhami, jejich instalaci a spouštění. Je to skvělý způsob, jak snadno začít. Ollama nabízí CLI pro podobné dělání. Pokud ale s lokálními modely začínáte, začal bych s LM Studio. Obě můžete nainstalovat v části _Install > AI_ v Omarchy Menu.

### Skilly Omarchy

Agent skilly pomáhají AI používat konkrétní nástroje konkrétním způsobem a Omarchy jich dodává sedm. Skill omarchy pokrývá přizpůsobení systému, například úpravu vaší konfigurace Hyprland nebo úpravu lišty. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app a omarchy-make-game pokrývají vytvoření něčeho nového, omarchy-contribute pokrývá nahlášení chyby nebo odeslání opravy upstreamu a omarchy-diagnose-crash pracuje s core dumpem pádu. Jsou propojeny symbolickými odkazy do adresářů skillů pro Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` a každý `~/.hermes/profiles/*/skills`) a obecné umístění `~/.agents/skills`, takže je většina harnessů zachytí automaticky. Složka skillu s vaším vlastním názvem se stejným názvem má přednost.

Tyto skilly byste ale měli považovat za experimentální. Různé modely je budou používat s různým účinkem. Nejlepší je nejprve běžet v režimu plánování, abyste měli představu o tom, co by agent rád změnil. A pak buďte připraveni vrátit změny zpět nebo dokonce vyvolat `omarchy reinstall configs`, pokud agent všechno zpřehází.
