### Instalace a aktualizace agentů

S výjimkou Hermes a OpenClaw tito agenti používají línou instalaci přes mise: první spuštění nainstaluje CLI a pozdější spuštění ho znovu použijí. mise také nejvýše jednou za čtyři hodiny zkontroluje, zda pro nainstalovaného agenta nevyšla nová verze, těsně před jeho spuštěním nebo na pozadí při promptu shellu. Pokud tato aktualizace selže nebo jste offline, spustí se nainstalovaná verze. `omarchy update` aktualizuje nainstalované agenty spolu se zbytkem Omarchy a `mup` aktualizuje pouze nástroje spravované přes mise.

Vlastní aktualizátor agenta, jako je `claude update`, `codex update` nebo tlačítko aktualizace v aplikaci, neaktualizuje instalaci spravovanou přes mise. `codex update` selže a `claude update` může hlásit úspěch, přičemž nainstaluje samostatnou kopii, kterou mise nesleduje. Pokud raději chcete používat nativní instalátor a aktualizátor agenta, přidejte ho do `disable_tools`; viz [Předinstalované CLI nástroje](18-development-tools.md#preinstalled-cli-tools).

Chcete-li nainstalovat všechny nakonfigurované líné nástroje dříve, než je budete potřebovat, spusťte `mise install --include-lazy`. To zahrnuje i ostatní výchozí CLI nástroje Omarchy i agenty. Viz [Předinstalované CLI nástroje](18-development-tools.md#preinstalled-cli-tools) pro instalaci jednoho nástroje nebo použití vlastní instalace.

`grok` se instaluje prostřednictvím first-party balíčku `grok` od mise, stejně jako `claude` a `codex`. Spusťte `grok` nebo ho označte hvězdičkou v panelu agentů. Přeskočte instalátor `curl | bash` na x.ai. Tato cesta umístí druhou kopii do `~/.grok/bin`, předřadí ji na `PATH` a přepíše wrapper Omarchy.

`dsh` otevírá své prohlížečové UI na `127.0.0.1:3080`, přičemž spouštěcí adresář je jeho výchozím pracovním prostorem. Jeho prohlížečové UI nepřijímá žádný počáteční prompt, takže `omarchy agent prompt` ho otevře s promptem ve vaší schránce k vložení. Omarchy ho spouští s předvolbou oprávnění no-approval od DeepSeek. DeepSeek Harness nahrává logy relací do DeepSeek, když používáte jeho oficiální API modelů; vypněte to v jeho prohlížečovém UI pod _Settings > General > Upload Session Log_. Zpětná vazba, kterou mu pošlete, se také nahrává spolu s relací, pokud ho nespustíte s `DSH_TELEMETRY_MODE=DISABLED`.

### Výchozí agent

Vyberte si výchozího agenta hvězdičkou vedle agenta v panelu agentů, která je u výchozího vyplněná, nebo pomocí `omarchy default agent <name>`, které přijme i libovolný harness, který tam nemá řádek. Pokud agent ještě není nainstalován, jeho výběr ho nejprve nainstaluje a dostane také vlastní spouštěč ve spouštěči aplikací, vedle Agent. Čerstvé Omarchy vás vyzve k nastavení jednoho jednorázovým oznámením, které otevře panel agentů.

Výběr Claude se také pokusí nastavit jeho rozšíření prohlížeče pro Chromium, Chrome, Brave, Brave Origin a Edge. Nastavení rozšíření platí pro všechny uživatele a může si vyžádat vaše systémové heslo; zrušení nebo neúspěšná instalace rozšíření přesto vybere a spustí Claude. Restartujte prohlížeč, povolte rozšíření, pokud budete vyzváni, a přihlaste se do Claude, abyste dokončili jeho připojení. Spusťte `/chrome` v Claude pro kontrolu připojení. Firefox a Zen toto rozšíření nepodporují. Pokud byl Claude vaším výchozím už před přidáním tohoto nastavení, vyberte ho znovu, abyste rozšíření nainstalovali.

Jakmile si vyberete, `Super + Shift + Ctrl + A` spustí výchozího agenta ve vyhrazeném okně terminálu (nebo vyvolá výběr, pokud jste si ještě nevybrali). Můžete ho také spustit rovnou do úkolu pomocí `omarchy agent prompt "Review this project"`. Freebuff a DeepSeek Harness nepřijímají žádný počáteční prompt, takže se místo toho otevřou s promptem ve vaší schránce k vložení. Takto spuštění agenti běží bez dohledu ve svých příslušných režimech don't-stop-to-ask, takže buďte připraveni na to, že budou skutečně něco dělat! MiniMax Code takový režim pro své interaktivní relace nemá, takže žádá o oprávnění jako obvykle. A protože agenti odmítají zapamatovat si důvěru pro váš domovský adresář, spuštění z `$HOME` místo toho začínají v `~/Work`.

Existují i zkratky v terminálu: `a` spustí výchozího agenta inline v aktuálním terminálu, zatímco `c`, `cx`, `cy` a `ca` spustí přímo OpenCode, Claude Code, Codex a Antigravity (opět v jejich režimech automatického schvalování). Změny motivu se synchronizují i do agentů: Claude Code, Pi, OpenCode a Hermes (jakmile ho Omarchy nainstaluje) všichni následují, když přepnete motiv Omarchy.

### Vaše pokyny pro agenty

Osobní pravidla pro každého agenta patří do `~/.agents/AGENTS.md`, vedle sdílených skills v `~/.agents/skills`. Otevřete ho ikonou dokumentu vedle + v panelu agentů nebo `omarchy agent instructions --edit`, které ho také propojí do každého harnessu, který si udržuje vlastní globální soubor: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, Copilotův `~/.copilot/copilot-instructions.md` a tak dále. Crush a Amp čtou odkaz `~/.config/AGENTS.md`, zatímco omp, Kimi a DeepSeek Harness čtou přímo `~/.agents/AGENTS.md`. Výběr výchozího agenta ho propojí také. Soubor s pokyny, který jste už měli, se stane sdíleným, pokud ještě žádný nebyl; jinak je ponechán vedle odkazu jako `.bak`. Po instalaci dalšího agenta spusťte `omarchy agent instructions` pro opětovné propojení.

### Panel agentů

Horní lišta má ikonu agentů. Než si agenta nastavíte, jeho panel nabízí tři způsoby, jak začít: přihlásit se k předplatnému Claude, Codex, Grok, Gemini, Muse, Cursor nebo Copilot, nebo pod More ke kódovacímu plánu OpenCode Go, MiniMax, Synthetic nebo Z.ai; platit průběžně podle spotřeby u Fireworks, OpenCode Zen and Go, OpenRouter, nebo pod More u DeepSeek či libovolného dalšího poskytovatele, ke kterému se OpenCode přihlašuje, vše běží v OpenCode; nebo spustit nejlepší model pro váš počítač, když se pro něj nějaký hodí. První, který dokončíte, se stane vaším výchozím agentem a + v panelu nabídne stejné tři možnosti i později. Poté panel umístí každé předplatné na jednu stránku: každého agenta a účet s jeho plánem, měřič pro každý z jeho 5hodinových limitů relace a týdenních limitů s časem do jejich resetování (přejetím zobrazíte přesné procento), nebo zbývající předplacený zůstatek, pod řádkem, který střídavě prochází tím, co jste u všech spotřebovali, jako tokeny za tento týden a váš nejpoužívanější model. Pod _Make something cool_ nabízí úvodní prompty pro nový motiv, plugin, aplikaci nebo hru, které předají úkol vašemu výchozímu agentovi. Aplikace se vytvářejí stejným způsobem jako vlastní Hype, Monologue a Omacut od Omarchy, v C++ a Qt Quick, podle agent skill omarchy-make-app, a kompilátor a součásti Qt, které potřebují, jsou předinstalované. Hry jsou jedna stránka three.js v `~/Games/vibes`, podle agent skill omarchy-make-game, a všechny se otevírají z jednoho spouštěče Game Vibes v aktuálním motivu; načítají three.js z webu, takže ke spuštění potřebují připojení. Claude Code, Codex, Grok, Kimi, Cursor a jeho příděl Grok Bot, GitHub Copilot, Muse, Gemini (prostřednictvím Antigravity) a Devin jsou pokryty hned po instalaci se svými limity, Kimchi se svým plánem, předplacenými kredity a rozpočty útraty a Hermes, Mistral Vibe a Qwen Code zobrazují své relace a tokeny, jakmile je použijete. Objeví se i plány a klíče poskytovatelů, které používáte prostřednictvím pi, omp nebo opencode: OpenCode Zen and Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan a Synthetic se svými limity; OpenRouter a DeepSeek se svými předplacenými zůstatky; Fireworks s útratou za posledních 30 dní. Kódovací modely, které provozujete na vlastním hardwaru, dostanou vlastní řádky a jejich tokeny se také započítávají do součtů, jak je popsáno pod [Místní modely](#local-models). Každý agent se započítává jednou, pod tím, kdo ho účtuje, bez ohledu na to, přes kolik harnessů ho řídíte.

Klikněte levým tlačítkem na ikonu na liště nebo stiskněte `Super + Ctrl + X` pro panel, klikněte pravým tlačítkem pro spuštění vašeho výchozího agenta a klikněte prostředním tlačítkem pro obnovení. Záznamy o využití, které za ním stojí, se regenerují každých 15 minut pomocí `omarchy agent usage update` a panel může dokonce sloučit využití z vašich dalších strojů prostřednictvím synchronizované složky. Viz README pod `$OMARCHY_PATH/shell/plugins/agents/` pro úplné nastavení.

### Několik předplatných

Pokud platíte za více než jeden plán Claude, Codex nebo Grok — třeba osobní Max a pracovní — Omarchy je může udržet všechny přihlášené a pohybovat se mezi nimi. Přidejte předplatné pomocí + v panelu agentů, které vás tím provede přímo tam, nebo pomocí `omarchy agent account add claude Work` (nebo `codex`, nebo `grok`). Stejné + a příkaz vás přihlásí do Gemini (`gemini`) a OpenCode (`opencode`) a uloží API klíč Fireworks (`fireworks`) nebo OpenRouter (`openrouter`) v OpenCode; příkaz vás také přihlásí do Copilot (`copilot`), Cursor (`cursor`) a Muse (`muse`). Ty si zachovávají po jednom přihlášení. Nainstaluje CLI, pokud chybí. První účet pro poskytovatele se přihlašuje prostřednictvím vašeho běžného prohlížeče, přesně tam, kde ho CLI vždy hledá. Každý další se poté přihlašuje prostřednictvím soukromého okna, takže účet, ke kterému je váš prohlížeč už přihlášen, není omylem zachycen; přihlaste se tam jako účet, který přidáváte, a nejprve zavřete všechna soukromá okna, která už máte otevřená. Nikdy se za tímto účelem neodhlaszujte z CLI: odhlášení zruší uložené přihlášení a tento účet by musel být znovu přidán.

Chcete-li zkopírovat přihlášení k předplatnému na jiný stroj s Omarchy přes SSH, spusťte `omarchy agent account copy user@laptop`. Odesílatel dodá dočasného příjemce, když cílový stroj žádného nainstalovaného nemá, takže starší stroje s Omarchy mohou přijímat účty bez aktualizace. Nainstalovaní příjemci mají přednost. Tím se zkopírují všechna předplatná Claude, Codex a Grok; přidejte názvy poskytovatelů, abyste je vybrali, jako v `omarchy agent account copy laptop claude`. Názvy účtů a ID příkazů odpovídají zdroji, včetně účtů již přítomných v cíli. Nesouvisející cílové účty dostanou číselnou příponu, pokud jejich názvy kolidují, a nastavení, skills, pluginy a historie konverzací zůstávají místní na každém stroji.

Stávající cílové přihlašovací údaje se zachovají. Zdrojový účet, který už tam je přihlášen, má synchronizovaný název bez nahrazení svých přihlašovacích údajů; ostatní účty se přidají vedle něj. Chcete-li nahradit uložené přihlašovací údaje pro odpovídající účty, použijte `omarchy agent account copy --replace laptop claude` poté, co na cílovém stroji ukončíte relace tohoto účtu. Čerstvý cílový stroj dostane také aktivní účet a předvolby přepínání zdroje; zavedený cílový stroj si ponechá své vlastní.

Přihlašovací údaje putují přes SSH a jsou ukládány do soukromých souborů na cílovém stroji, takže kopírujte pouze na stroje, kterým důvěřujete. Jedná se o jednorázovou kopii, nikoli průběžnou synchronizaci. Refresh tokeny Codex může jiný stroj rotovat, čímž zkopírované přihlášení bude potřebovat obnovení; samostatná přihlášení zůstávají nejspolehlivější volbou pro současné použití na několika strojích. Viz [pokyny Codexu k ověřování účtů](https://developers.openai.com/codex/auth/ci-cd-auth).

Jeden účet na poskytovatele je aktivní a každá nová relace začíná jako on: `cx`, `cy`, prosté `claude`, `codex` nebo `grok`, cokoli spuštěného prostřednictvím `omarchy agent` a skripty nebo editory, které najdou CLI na `PATH`. Přepněte pomocí `omarchy agent account use work` (a zpět pomocí `omarchy agent account use main`), nebo v panelu stisknutím čísla účtu a poté `Enter` (nebo kliknutím na jeho hvězdičku). Běžící relace Claude se také přepnou, od jejich další zprávy: každá relace Claude běží v `~/.claude`, který vždy obsahuje přihlášení aktivního účtu. Relace Claude spuštěná ve vlastní složce účtu starším Omarchy si uchová toto přihlášení, dokud neskončí, takže přepnutí tyto relace pojmenuje a samo dokončí, jakmile zmizí. Běžící relace Codex a Grok zůstávají na účtu, se kterým začaly. Historie konverzací, nastavení, skills a pluginy jsou sdíleny napříč účty, takže `claude --continue` ve stejné složce naváže tam, kde jste na novém účtu skončili.

S více než jedním účtem panel zobrazuje limity každého účtu vedle sebe, s vyplněnou hvězdičkou na tom používaném. Omarchy vás upozorní, když aktivní účet překročí 95 % limitu, a kliknutí na oznámení přepne na účet s největším prostorem. Nikdy nepřepíná samo. Změňte práh pomocí `omarchy agent account threshold 90`. Pokud je každý účet nad prahem, dozvíte se o tom jednou, spolu s tím, který účet se uvolní jako první. Zatímco je aktivní účet do 15 bodů od svého prahu (80 % při výchozím nastavení), jeho limity se kontrolují každé tři minuty namísto každých 15.

`omarchy agent account list` zobrazuje každý účet a jeho nejnovější limity, `omarchy agent account remove work` jeden zapomene a `omarchy agent account rename primary Hey` jeden přejmenuje (nebo klikněte na název účtu v panelu). Tyto příkazy fungují na účtech vašeho výchozího agenta; chcete-li dosáhnout na jiného poskytovatele, nejprve ho pojmenujte, jako v `omarchy agent account use codex side`. Přihlášení, které jste už měli v `~/.claude` nebo `~/.codex`, je účet _Main_. Codexovo zůstává tam, kde je; Claudeovo čeká ve vlastní složce, zatímco je aktivní jiný účet. Účet ponechaný bez použití déle než zhruba osm hodin může zobrazovat _Sign-in required_; klikněte na něj, abyste tento účet znovu přihlásili přímo v panelu, nebo na něj přepněte a spusťte relaci, která přihlášení obnoví sama. Servery MCP, které přidáte pomocí `claude mcp add`, dosáhnou na každý účet Claude, protože všechny běží v `~/.claude`; u Codex a Grok servery, které jste měli, když byl účet přidán, s ním přijdou, ale pozdější dosáhnou pouze na účet, ve kterém jste je přidali. Claude Desktop si udržuje vlastní přihlášení a nástroje Codex nebo Grok nakonfigurované s absolutní cestou k binárce CLI přepnutí nenásledují. Explicitní `CLAUDE_CONFIG_DIR`, `CODEX_HOME` nebo `GROK_HOME` má přednost před vybraným účtem.

### Diagnostika pádů

Omarchy sleduje systemd-coredump kvůli pádům procesů. Jakmile si vyberete výchozího agenta, každý váš program, který dumpne core, vyvolá oznámení "Process crashed" — klikněte na něj a pád je předán vašemu výchozímu agentovi spolu se skill omarchy-diagnose-crash od Omarchy, která agenta provede zjištěním faktů z core dumpu a rozhodnutím, zda pád stojí za nahlášení upstreamu. Můžete ji také spustit ručně proti libovolnému PID z `coredumpctl list` pomocí `omarchy agent crash <pid>`.

Sledování je ve výchozím nastavení zapnuté. Vypněte ho pod _Trigger > Toggle > Crash Capture Off_ (nebo pomocí `omarchy toggle crash-capture`) a oznámení přestanou; `omarchy agent crash <pid>` stále funguje ručně.

Pády lze také ztlumit po jednotlivých programech, což vám diagnostika na konci nabídne. `omarchy crash mute hyprland` zastaví oznámení pouze pro tento program, `omarchy crash mute hyprland off` je vrátí zpět a `omarchy crash mute` samo o sobě vypíše, co jste ztlumili. Přijímá cestu k binárce stejně ochotně jako její název, takže `omarchy crash mute /usr/bin/hyprland` dělá totéž. Název s mezerou dejte do uvozovek, jako v `omarchy crash mute 'Some App'`. Všechno ostatní stále oznamuje a ztlumený program stále padá — toto skrývá připomenutí, nic neopravuje.

### Desktopové aplikace

Nabídka _Install > AI_ obsahuje také několik grafických AI aplikací: Amp Desktop, Antigravity Desktop, desktopovou aplikaci ChatGPT, desktopovou aplikaci Claude (linuxovou betu od Anthropic, s kartami Chat, Cowork a Claude Code), Grok Bot pro chatování s modely xAI, Herdr Desktop, Hermes Desktop, OpenClaw, desktopovou aplikaci Perplexity a T3 Code. Grok Bot je desktopová chatovací aplikace. Kódovací agent je příkaz `grok`.

Hermes Desktop je ta, o které byste měli vědět, protože stroj má jeden Hermes a ten patří aplikaci: Hermes se instaluje vždy pouze prostřednictvím aplikace a příkaz `hermes`, který výchozí agent spouští, je ten od aplikace. Výběr Hermes jako výchozího agenta nainstaluje totéž, co položka _Install > AI_: balíček a runtime Hermes pod `~/.hermes` nastavený vlastním instalátorem Hermes, což poprvé trvá několik minut. Tento runtime je ten jeden Hermes, který používají terminálový příkaz `hermes`, výchozí agent i aplikace, a aktualizuje se sám pomocí `hermes update`, místo aby čekal na vydání Omarchy. Jeho instalace také předá Hermes motiv Omarchy jako skin pojmenovaný `omarchy`, který každá plocha Hermes následuje, když přepínáte motivy; vyberte jiný v nastavení Appearance u Hermes nebo pomocí `/skin`, pokud raději nechcete, aby to dělal, a Omarchy tuto volbu nechá na pokoji. Odstranění aplikace pod _Remove > AI_ nejprve zavře Hermes, včetně brány, vezme s sebou tento runtime a ponechá vaše chaty, vzpomínky a skills, které si Hermes sám pro sebe napsal, pokud neřeknete jinak: zeptá se, s výchozí odpovědí ne, zda mají odejít i tato data a vaše nastavení připojení.

Desktopový zážitek OpenClaw je jeho Control UI, které se otevírá jako webová aplikace podporovaná vlastní místní bránou. OpenClaw žije v `~/.openclaw` a aktualizuje se samo: použijte tlačítko "Update Gateway" v Control UI nebo spusťte `openclaw update` a brána se restartuje na nové verzi. Omarchy pouze vybírá vydání, ze kterého čerstvá instalace začíná. OpenClaw může být také vaším výchozím agentem: jeho výběr pomocí `omarchy default agent openclaw` nastaví tuto samou kopii v `~/.openclaw` a agent otevře terminálové UI OpenClaw připojené k jeho bráně. Odstranění OpenClaw pod _Remove > AI_ vezme s sebou službu brány i aplikaci a poté se zeptá, zda má odejít i `~/.openclaw`, protože to ukrývá vaše chaty a přihlašovací údaje vedle samotného OpenClaw a runtime pluginů, které stahuje; výchozí nastavení ho ponechá a opětovná instalace OpenClaw ho zase vyzvedne.

Herdr Desktop je desktopová aplikace [Herdr](https://herdr.dev): prostory, karty a panely terminálů a kódovacích agentů, které dál běží v jejím jádru, když zavřete okno. Pochází z vlastního instalátoru Herdr namísto balíčku, takže žije v `~/.local/share/herdr-app`, přináší s sebou své jádro v `~/.local/bin/herdr-core`, když ještě žádné nemáte, a aktualizuje obojí sama. Sedí vedle příkazu `herdr`, který Omarchy dodává na `Super + Ctrl + Return`, namísto aby ho nahrazovala, a dostává přímé klávesy tohoto příkazu: `Alt + Return` a `Alt + Shift + Return` rozdělí panel dolů nebo doprava, `Alt + Escape` ho zavře, `Ctrl + Alt + Arrow` se pohybuje mezi panely, `Alt + 1..9` a `Alt + Left/Right` vybírají kartu a `Alt + Up/Down` se pohybují mezi prostory. `Ctrl + 1..9` vybírá prostor a `Alt + Shift + Up/Down` prochází agenty. Prefixové klávesy `Ctrl + Space` zůstávají pouze pro terminál, protože aplikace nemůže držet prostou klávesu Ctrl pro sekvenci. Omarchy je zapisuje do `~/.config/herdr-app/keys.json` a `omarchy-refresh-herdr-app` je vrací zpět. Jeho instalace vybere motiv Omarchy pro Herdr, který od té doby následuje váš motiv Omarchy. Herdr udržuje jeden motiv pro světlý režim a jeden pro tmavý, takže po přepnutí mezi tmavým a světlým motivem Omarchy vyberte Omarchy v nástroji pro výběr motivu Herdr ještě jednou pro druhý režim.

T3 Code běží z oficiálního vydání AppImage v `~/.local/share/t3code` namísto z balíčku, takže se aktualizuje samo. Jeho instalace se zeptá, zda začít na kanálu Stable nebo Nightly; přepněte později v nastavení T3 Code. Vaše vlákna a nastavení žijí v `~/.t3` a odstranění T3 Code pod _Remove > AI_ je vezme s sebou.

### Místní modely

Spusťte otevřený model na vlastním stroji pro své kódovací agenty. Vaše prompty a kód zůstávají na stroji; nic odeslaného modelu ho neopustí. Začněte s:

```bash
omarchy models use best text
```

To nastaví nejlepší textový model pro tento stroj, ten druh, který vaši agenti používají. Obrazové, video a hudební modely mají svůj vlastní nejlepší: `omarchy models use best image`, `video` nebo `music`. Spusťte `omarchy models use best`, abyste viděli výběr každého druhu pro tento stroj.

Nebo vyberte + v panelu agentů: pod _Use a local model_ uvádí každý kódovací model, který se hodí pro tento stroj, doporučený jako první. Podman, který modely spouští, je součástí Omarchy, stejně jako sada nástrojů pro kontejnery NVIDIA na stroji NVIDIA, která jim dává GPU; pokud něco z toho chybí, první nastavení to nainstaluje. Omarchy poté vybere doporučený model pro tento stroj, stáhne ho a spustí. Očekávejte stažení desítek GB a většinu paměti stroje v použití, zatímco model běží: Flash Next používá asi 100 GiB se svým plným kontextem 256K. Pokud jiné modely drží paměť, kterou potřebuje, je nastaven zastavený, připravený ke spuštění, jakmile jeden zastavíte. Model se zastaví při odhlášení; zastavte ho sami, když potřebujete paměť pro něco jiného.

`omarchy models list` zobrazuje možnosti a vysvětluje, proč se některé nehodí. Chcete-li nastavit další, spusťte `omarchy models use <recipe>`. Dnes jsou `qwen3.8-flash-next-gufo` a `qwen3.8-27b-gufo` k dispozici pro stroje Strix Halo se 128 GB; 27B zabírá asi 40 GiB, takže nechává prostor pro další práci. Na 64GB notebooku s Intel Arc B390 běží `qwen3.6-35b-a3b-llamacpp` v asi 30 GiB. Nové recepty a doporučení přicházejí s `omarchy update`, prostřednictvím balíčku.

Kódovací model, který přidáte, dostane vlastní řádek v panelu agentů, vedle vašich předplatných: play pro spuštění, pause pro zastavení a uvolnění paměti, značku Tailscale pro sdílení s ostatními stroji na vašem tailnetu, zatímco běží, a tlačítko terminálu pro otevření agenta na něm. Jeho řádek průběžně zobrazuje stahování, načítání nebo zastavování a říká, kdy není dost volné paměti ke spuštění, nebo odkazuje na jeho logy, když se zastavil s chybou. Několik jich může běžet najednou, když se společně vejdou do paměti. Stiskněte Delete na vybraném řádku, abyste model z tohoto stroje odstranili, včetně stažení; + ho může nastavit znovu. Kódovací model nastavený z terminálu čeká pod +, dokud ho nepřidáte, a stejně tak modely, které provozuje stroj, se kterým jste se spárovali (`omarchy models pair <host>`).

Každý kódovací model, který nastavíte, dostane také vlastní položku ve spouštěči aplikací, pod názvem modelu a s logem jeho tvůrce, stejně jako přihlášení do Claude, Codex nebo Grok přidá jednu. Otevře vašeho agenta na tomto modelu a nejprve model spustí, pokud neběží: terminál zobrazuje jeho načítání a předá agentovi, jakmile bude připraven. Odstranění modelu odstraní jeho položku.

Ne každý model je pro kódování. Obrazové, video a hudební modely se místo toho otevírají ve Fantasi, aplikaci Omarchy pro vytváření obrázků, videa a hudby s modelem běžícím na tomto stroji, a jsou spravovány tam nebo pomocí `omarchy models`.

Model dál běží přesně tak, jak byl nastaven, takže aktualizace Omarchy nikdy nerestartuje žádný pod vašimi agenty. Když má Omarchy novější runtime nebo novější váhy pro model, který jste nastavili, jeho řádek zobrazuje tlačítko aktualizace: stiskněte ho a model se znovu nastaví na pozadí, stáhne pouze to, co se změnilo, a restartuje se na nové verzi. Model, který byl zastaven, zůstane zastaven. `omarchy models update` dělá totéž pro každý model z terminálu.

Z příkazového řádku `omarchy models start <recipe>` a `omarchy models stop <recipe>` dělají totéž, `omarchy models status` zobrazuje každý model a `omarchy agent --local-model <recipe>` otevře tento model v pi, ať je váš výchozí agent jakýkoli. Chcete-li, aby váš místní model byl tím, co otevírá klávesová zkratka agenta, konzole Quake a _Make something_, spusťte `omarchy default agent local` nebo označte hvězdičkou běžící model v panelu agentů. pi také uvádí každý model, který jste nastavili, a ty na strojích, se kterými jste se spárovali, ve svém vlastním nástroji pro výběr modelu, takže prosté `pi` k nim také dosáhne. Připojit se může i libovolný klient kompatibilní s OpenAI: `status` zobrazuje adresu každého modelu (první je `http://127.0.0.1:11435/v1`), název receptu je model a klíč je v `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` smaže model a stažené soubory, které žádný jiný model nepoužívá.

Runtime třetích stran jsou označeny svým vydavatelem. Omarchy spouští každý model bez přístupu k síti.

### Místní LLM

Omarchy doporučuje dva způsoby provozování místních modelů LLM: LM Studio a Ollama. LM Studio poskytuje GUI rozhraní pro hledání modelů s otevřenými váhami, jejich instalaci a spouštění. Je to skvělý způsob, jak snadno začít. Ollama nabízí CLI pro totéž obdobně. Ale pokud jste v místních modelech noví, začal bych s LM Studio. Obojí můžete nainstalovat pod _Install > AI_ v nabídce Omarchy.

### Skills Omarchy

Agent skills pomáhají AI používat konkrétní nástroje konkrétním způsobem a Omarchy jich dodává sedm. Skill omarchy pokrývá přizpůsobení systému, jako je úprava vaší konfigurace Hyprland nebo nastavení lišty. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app a omarchy-make-game pokrývají vytváření něčeho nového, omarchy-contribute pokrývá hlášení chyby nebo odeslání opravy upstreamu a omarchy-diagnose-crash prochází core dump pádu. Jsou propojeny symlinky do adresářů skills pro Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` a každý `~/.hermes/profiles/*/skills`) a generické umístění `~/.agents/skills`, takže je většina harnessů zachytí automaticky. Složka skill vlastního provedení se stejným názvem má přednost.

Ale měli byste tyto skills považovat za experimentální. Různé modely ji budou používat s různým účinkem. Nejlepší je nejprve běžet v režimu plánování, abyste měli představu o tom, co by agent rád změnil. A pak buďte připraveni vrátit změny zpět nebo dokonce vyvolat `omarchy reinstall configs`, pokud agent všechno zpřehází.
