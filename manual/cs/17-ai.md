### Instalace a aktualizace agentů

S výjimkou Hermes používají tito agenti línou instalaci mise: první spuštění nainstaluje CLI a další spuštění jej znovu použijí. mise také nejvýše jednou za čtyři hodiny zkontroluje, zda je pro nainstalovaného agenta nová verze, těsně před jeho spuštěním nebo na pozadí při promptu shellu. Pokud tato aktualizace selže nebo jste offline, spustí se nainstalovaná verze. `omarchy update` aktualizuje nainstalované agenty spolu se zbytkem Omarchy a `mup` aktualizuje pouze nástroje spravované mise.

Vlastní aktualizátor agenta, jako je `claude update`, `codex update` nebo tlačítko aktualizace v aplikaci, neaktualizuje instalaci spravovanou mise. `codex update` selže a `claude update` může hlásit úspěch a přitom nainstalovat samostatnou kopii, kterou mise nesleduje. Pokud byste raději používali nativní instalátor a aktualizátor agenta, přidejte jej do `disable_tools`; viz [Předinstalované nástroje CLI](18-development-tools.md#preinstalled-cli-tools).

Chcete-li nainstalovat všechny nakonfigurované líné nástroje dříve, než je budete potřebovat, spusťte `mise install --include-lazy`. To zahrnuje i ostatní výchozí nástroje CLI Omarchy i agenty. Viz [Předinstalované nástroje CLI](18-development-tools.md#preinstalled-cli-tools) pro instalaci jednoho nástroje nebo použití vlastní instalace.

`grok` se instaluje prostřednictvím first-party balíčku `grok` od mise, stejně jako `claude` a `codex`. Spusťte `grok` nebo jej vyberte v _Setup > Defaults > Agent_. Přeskočte instalátor `curl | bash` na x.ai. Tato cesta umístí druhou kopii do `~/.grok/bin`, přidá ji na začátek `PATH` a přepíše wrapper Omarchy.

`dsh` otevírá své prohlížečové UI na `127.0.0.1:3080`, s adresářem spuštění jako výchozím pracovním prostorem. Jeho prohlížečové UI nepřijímá žádný počáteční prompt, takže `omarchy agent prompt` jej otevře s promptem ve vaší schránce k vložení. Omarchy jej spouští s předvolbou oprávnění DeepSeek bez schvalování. DeepSeek Harness nahrává protokoly relací k DeepSeek, když používáte jeho oficiální API modelů; vypněte to v _Settings > General > Upload Session Log_ v jeho prohlížečovém UI. Zpětná vazba, kterou mu odešlete, se nahrává spolu s relací, pokud jej nespustíte s `DSH_TELEMETRY_MODE=DISABLED`.

### Výchozí agent

Vyberte si výchozího agenta pomocí `omarchy default agent <name>` nebo v _Setup > Defaults > Agent_ v Omarchy Menu (`Super + Space`). Pokud agent ještě není nainstalován, jeho výběr jej nejprve nainstaluje. Čerstvá Omarchy vás k této volbě vyzve jednorázovým oznámením.

Výběr Claude se také pokusí nastavit jeho rozšíření prohlížeče pro Chromium, Chrome, Brave, Brave Origin a Edge. Nastavení rozšíření se vztahuje na všechny uživatele a může vyžadovat vaše systémové heslo; zrušení nebo neúspěšná instalace rozšíření přesto Claude vybere a spustí. Restartujte prohlížeč, povolte rozšíření, pokud k tomu budete vyzváni, a přihlaste se k Claude, abyste dokončili jeho připojení. Spusťte `/chrome` v Claude pro kontrolu připojení. Firefox a Zen toto rozšíření nepodporují. Pokud byl Claude vaším výchozím již před přidáním tohoto nastavení, vyberte jej znovu pro instalaci rozšíření.

Jakmile si vyberete, `Super + Shift + Ctrl + A` spustí výchozího agenta ve vyhrazeném okně terminálu (nebo vyvolá výběr, pokud jste si ještě nevybrali). Můžete jej také spustit přímo do úkolu pomocí `omarchy agent prompt "Review this project"`. Freebuff a DeepSeek Harness nepřijímají žádný počáteční prompt, takže se místo toho otevřou s promptem ve vaší schránce k vložení. Takto spuštění agenti běží bez dohledu ve svých příslušných režimech nezastavuj-se-a-neptej-se, takže buďte připraveni, že budou skutečně něco dělat! MiniMax Code takový režim pro své interaktivní relace nemá, takže žádá o oprávnění jako obvykle. A protože agenti odmítají zapamatovat si důvěru pro váš domovský adresář, spuštění z `$HOME` začínají místo toho v `~/Work`.

Existují i zkratky terminálu: `a` spustí výchozího agenta přímo v aktuálním terminálu, zatímco `c`, `cx` a `cy` spustí přímo OpenCode, Claude Code a Codex (opět v jejich režimech automatického schvalování). Změny tématu se synchronizují i do agentů: Claude Code, Pi, OpenCode a Hermes (jakmile jej Omarchy nainstaluje) všichni následují, když přepnete téma Omarchy.

### Panel agentů

Horní lišta má ikonu agentů. Předtím, než si agenta nastavíte, vás jeho panel provede přihlášením k Claude, Codex nebo Grok a první z nich se stane vaším výchozím agentem. Poté panel umístí každé předplatné na jednu stránku: každý agent a účet s jeho plánem, měřič pro každý z jeho 5hodinových limitů relace a týdenních limitů s časem do jeho resetu (přejetím zobrazíte přesné procento), nebo zbývající předplacený zůstatek, pod řádkem, který rotuje tím, co jste použili napříč všemi z nich, jako tokeny tento týden a váš nejpoužívanější model. Pod _Make something_ nabízí počáteční prompty pro nové téma, plugin nebo aplikaci, které předají úkol vašemu výchozímu agentovi. Aplikace se staví tak, jak se staví vlastní Hype, Monologue a Omacut od Omarchy, v C++ a Qt Quick, podle skillu omarchy-app pro agenty, a kompilátor a části Qt, které potřebují, jsou nainstalované. Claude Code, Codex, Grok, Kimi, Cursor a jeho příděl Grok Bot, GitHub Copilot, Muse, Antigravity, Kimchi a Devin jsou pokryty hned po instalaci se svými limity a Hermes, Mistral Vibe a Qwen Code zobrazí své relace a tokeny, jakmile je použijete. Plány poskytovatelů a klíče, které používáte prostřednictvím pi, omp nebo opencode, se také zobrazí: OpenCode Zen a Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan a Synthetic se svými limity; Fireworks, OpenRouter a DeepSeek se svými předplacenými zůstatky; a modely, které provozujete na vlastním hardwaru pod Local models. Každý agent se počítá jednou, pod tím, kdo jej fakturuje, bez ohledu na to, přes kolik harnessů jej řídíte.

Klikněte levým tlačítkem na ikonu v liště pro panel, pravým tlačítkem pro spuštění výchozího agenta. Záznamy o využití, které za ním stojí, se regenerují každých 15 minut pomocí `omarchy agent usage-update` a panel může dokonce sloučit využití z vašich ostatních strojů prostřednictvím synchronizované složky. Úplné nastavení najdete v README pod `$OMARCHY_PATH/shell/plugins/agents/`.

### Více předplatných

Pokud platíte za více než jeden plán Claude, Codex nebo Grok — například osobní Max a pracovní — Omarchy je může udržet všechny přihlášené a pohybovat se mezi nimi. Přidejte předplatné pomocí + v panelu agentů, které vás tím provede přímo tam, nebo pomocí `omarchy agent account add claude Work` (nebo `codex`, nebo `grok`). Nainstaluje CLI, pokud chybí. První účet pro poskytovatele se přihlašuje přes váš běžný prohlížeč, přesně tam, kam CLI vždy hledí. Každý další se přihlašuje přes soukromé okno, takže účet, ke kterému je váš prohlížeč již přihlášen, nebude omylem zachycen; přihlaste se tam jako účet, který přidáváte, a nejprve zavřete jakékoli soukromé okno, které již máte otevřené. Nikdy se za tímto účelem neodhlasujte z CLI: odhlášení zruší uložené přihlášení a daný účet by musel být přidán znovu.

Chcete-li zkopírovat přihlášení k předplatnému na jiný stroj Omarchy přes SSH, spusťte `omarchy agent account copy user@laptop`. Odesílatel dodá dočasného přijímače, když cíl žádného nainstalovaného nemá, takže starší stroje Omarchy mohou přijímat účty bez aktualizace. Nainstalovaní přijímači mají přednost. To zkopíruje všechna předplatná Claude, Codex a Grok; přidejte názvy poskytovatelů, abyste je vybrali, jako v `omarchy agent account copy laptop claude`. Názvy účtů a ID příkazů odpovídají zdroji, včetně účtů již přítomných v cíli. Nesouvisející cílové účty obdrží číselnou příponu, pokud se jejich názvy střetnou, a nastavení, skilly, pluginy a historie konverzací zůstanou lokální pro každý stroj.

Stávající cílové přihlašovací údaje zůstávají zachovány. Zdrojový účet, který je tam již přihlášen, má synchronizován název, aniž by byly nahrazeny jeho přihlašovací údaje; ostatní účty se přidají vedle něj. Chcete-li nahradit uložené přihlašovací údaje pro odpovídající účty, použijte `omarchy agent account copy --replace laptop claude` po ukončení relací daného účtu v cíli. Čerstvý cíl také obdrží aktivní účet zdroje a preference přepínání; zavedený cíl si ponechá své vlastní.

Přihlašovací údaje putují přes SSH a jsou uloženy v soukromých souborech v cíli, takže kopírujte pouze na stroje, kterým důvěřujete. Jedná se o jednorázovou kopii, ne o průběžnou synchronizaci. Obnovovací tokeny Codex mohou být rotovány jiným strojem, což ponechá zkopírované přihlášení potřebující obnovení; samostatná přihlášení zůstávají nejspolehlivější volbou pro současné použití na několika strojích. Viz [Průvodce ověřováním účtů Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Jeden účet na poskytovatele je aktivní a každá nová relace začíná jako on: `cx`, `cy`, prosté `claude`, `codex` nebo `grok`, cokoli spuštěného přes `omarchy agent` a skripty nebo editory, které najdou CLI na `PATH`. Přepínejte pomocí `omarchy agent account use work` (a zpět pomocí `omarchy agent account use main`), nebo v panelu stisknutím čísla účtu a poté `Enter` (nebo kliknutím na jeho tlačítko Use). Relace, které již běží, zůstanou na účtu, se kterým začaly. Historie konverzací, nastavení, skilly a pluginy jsou sdíleny napříč účty, takže `claude --continue` ve stejné složce pokračuje tam, kde jste na novém účtu přestali.

S více než jedním účtem panel zobrazuje limity každého účtu vedle sebe, s označením aktivního. Ve výchozím nastavení vás Omarchy upozorní, když aktivní účet překročí 95 % limitu, a kliknutí na oznámení přepne na účet s největším prostorem. Přejeďte nad řádek účtu v panelu a klikněte na Autoswitch, který se objeví vedle Use (nebo stiskněte `m`), nebo spusťte `omarchy agent account mode auto`, aby se přepínal sám; když je zapnutý, Autoswitch zaujme místo Use a další kliknutí se vrátí k oznamování. Přidejte číslo pro změnu prahu, jako v `omarchy agent account mode auto 90`. Pokud je každý účet nad prahem, uslyšíte o tom jednou, spolu s tím, který účet se uvolní jako první. Zatímco je aktivní účet do 15 bodů od svého prahu (80 % ve výchozím nastavení), jeho limity se kontrolují každé tři minuty namísto každých 15.

`omarchy agent account list` zobrazuje každý účet a jeho nejnovější limity, `omarchy agent account remove work` jeden zapomene a `omarchy agent account rename primary Hey` jeden přejmenuje (nebo klikněte na název účtu v panelu). Tyto příkazy fungují na účtech vašeho výchozího agenta; chcete-li dosáhnout na jiného poskytovatele, nejprve jej pojmenujte, jako v `omarchy agent account use codex side`. Přihlášení, které jste již měli v `~/.claude` nebo `~/.codex`, je účet _Main_ a zůstává tam, kde je. Účet, který zůstal nepoužitý déle než přibližně osm hodin, může zobrazit _Sign-in required_; klikněte na něj, abyste daný účet znovu přihlásili přímo v panelu, nebo v něm spusťte relaci, která přihlášení obnoví sama. Servery MCP, které jste měli, když byl účet přidán, přijdou spolu s ním, ale ty, které přidáte později pomocí `claude mcp add`, se dostanou pouze k účtu, ve kterém jste je přidali. Claude Desktop a nástroje nakonfigurované s absolutní cestou k binárce CLI přepínač nenásledují. Explicitní `CLAUDE_CONFIG_DIR`, `CODEX_HOME` nebo `GROK_HOME` má přednost před vybraným účtem.

### Diagnóza pádů

Omarchy sleduje systemd-coredump kvůli pádům procesů. Když něco segfaultuje, dostanete oznámení "Process crashed" — klikněte na něj a pád je předán vašemu výchozímu agentovi spolu se skillem diagnose-crash od Omarchy, který agenta provede zjištěním faktů z core dump a rozhodnutím, zda pád stojí za nahlášení upstream. Můžete jej také spustit ručně proti libovolnému PID z `coredumpctl list` pomocí `omarchy agent crash <pid>`.

Sledování je ve výchozím nastavení zapnuté. Vypněte jej v _Trigger > Toggle > Crash Capture_ (nebo pomocí `omarchy toggle crash-capture`) a oznámení přestanou; `omarchy agent crash <pid>` stále funguje ručně.

Pády lze také umlčet po jednom programu, což vám diagnóza nabídne na konci. `omarchy crash mute hyprland` zastaví oznámení pouze pro daný program, `omarchy crash mute hyprland off` je vrátí zpět a samotné `omarchy crash mute` vypíše, co jste umlčeli. Bere cestu binárky stejně ochotně jako její název, takže `omarchy crash mute /usr/bin/hyprland` dělá totéž. Název s mezerou dejte do uvozovek, jako v `omarchy crash mute 'Some App'`. Vše ostatní stále oznamuje a umlčený program stále padá — to skrývá připomínku, nic to neopravuje.

### Desktopové aplikace

Menu _Install > AI_ nese také několik grafických aplikací AI: desktopovou aplikaci ChatGPT, desktopovou aplikaci Claude (linuxová beta od Anthropic, s kartami Chat, Cowork a Claude Code), Grok Bot pro chatování s modely xAI, Hermes Desktop, OpenClaw, desktopovou aplikaci Perplexity a T3 Code. Grok Bot je desktopová chatovací aplikace. Kódovacím agentem je příkaz `grok`.

Hermes Desktop je ten, o kterém je třeba vědět, protože stroj má jednoho Hermes a ten patří aplikaci: Hermes se instaluje pouze a vždy prostřednictvím aplikace a příkaz `hermes`, který výchozí agent spouští, je ten od aplikace. Výběr Hermes jako výchozího agenta nainstaluje totéž, co položka _Install > AI_: balíček a runtime Hermes pod `~/.hermes` nastavený vlastním instalátorem Hermes, což poprvé trvá několik minut. Tento runtime je ten jeden Hermes, který používají terminálový příkaz `hermes`, výchozí agent i aplikace, a aktualizuje se sám pomocí `hermes update`, místo aby čekal na vydání Omarchy. Jeho instalace také předá Hermes téma Omarchy jako skin pojmenovaný `omarchy`, který každý povrch Hermes následuje, když přepínáte témata; vyberte jiný v nastavení Appearance od Hermes nebo pomocí `/skin`, pokud byste raději, aby to nedělal, a Omarchy tuto volbu nechá být. Odstranění aplikace v _Remove > AI_ nejprve zavře Hermes, včetně gateway, vezme s sebou daný runtime a ponechá vaše chaty, vzpomínky a skilly, které Hermes napsal sám pro sebe, pokud mu neřeknete jinak: zeptá se, ve výchozím nastavení ne, zda by tato data a vaše nastavení připojení měla také zmizet.

Desktopová zkušenost OpenClaw je jeho Control UI, která se otevírá jako webová aplikace podporovaná vlastní lokální gateway. OpenClaw žije v `~/.openclaw` a aktualizuje se sám: použijte tlačítko "Update Gateway" v Control UI nebo spusťte `openclaw update` a gateway se restartuje na nové verzi. Omarchy pouze vybírá vydání, ze kterého čerstvá instalace začíná. Odstranění OpenClaw v _Remove > AI_ vezme s sebou službu gateway a aplikaci a poté se zeptá, zda by mělo zmizet i `~/.openclaw`, protože to drží vaše chaty a přihlašovací údaje vedle samotného OpenClaw a runtime pluginů, které stahuje; výchozí nastavení jej ponechává a opětovná instalace OpenClaw jej znovu zachytí.

T3 Code běží ze svého oficiálního vydání AppImage v `~/.local/share/t3code` namísto z balíčku, takže se aktualizuje sám. Jeho instalace se zeptá, zda začít na kanálu Stable nebo Nightly; později přepněte v nastavení T3 Code. Vaše vlákna a nastavení žijí v `~/.t3` a odstranění T3 Code v _Remove > AI_ je vezme s sebou.

### Lokální modely

Spusťte otevřený model na vlastním stroji pro své kódovací agenty. Vaše prompty a kód zůstávají na stroji; nic odeslaného modelu jej neopustí. Začněte s:

```bash
omarchy agent local use best
```

Nebo v panelu agentů v horní liště zvolte + a poté Local AI, která se zobrazí, když se model vejde na tento stroj. Poprvé to nainstaluje Podman, který modely spouští, a na stroji NVIDIA sadu nástrojů NVIDIA pro kontejnery, která jim poskytuje GPU. Omarchy poté vybere doporučený model pro tento stroj, stáhne jej a spustí. Očekávejte stažení v desítkách GB a většinu paměti stroje v použití, zatímco model běží: Flash Next používá přibližně 100 GiB se svým plným kontextem 256K. Pokud jiné modely drží paměť, kterou potřebuje, je nastaven zastavený, připravený ke spuštění, jakmile jeden zastavíte. Model se zastaví při odhlášení; zastavte jej sami, když potřebujete paměť pro něco jiného.

`omarchy agent local list` zobrazuje možnosti a vysvětluje, proč se některé nevejdou. Chcete-li nastavit další, spusťte `omarchy agent local use <recipe>`. Dnes jsou `qwen3.8-flash-next-halogen` a `qwen3.8-27b-gufo` k dispozici pro stroje Strix Halo se 128 GB. Nové recepty a doporučení přicházejí s `omarchy update`, prostřednictvím balíčku.

Každý model, který nastavíte, dostane vlastní řádek v panelu agentů, vedle vašich předplatných: play pro jeho spuštění, pause pro jeho zastavení a uvolnění jeho paměti a tlačítko terminálu pro otevření vašeho agenta na něm. Několik jich může běžet najednou, když se společně vejdou do paměti; pokud se jeden nevejde, Omarchy řekne, který běžící model zastavit. Přetáhněte řádky pro jejich přeřazení a stiskněte Delete na vybraném řádku pro odstranění modelu a jeho stažení.

Z příkazového řádku `omarchy agent local start <recipe>` a `omarchy agent local stop <recipe>` dělají totéž, `omarchy agent local status` zobrazuje každý model a `omarchy agent --local` otevře vašeho výchozího agenta na posledním modelu, který jste spustili (pi, pokud váš výchozí agent nemůže použít lokální model). Připojit se může i libovolný klient kompatibilní s OpenAI: `status` zobrazuje adresu každého modelu (první je `http://127.0.0.1:11435/v1`), název receptu je model a klíč je v `~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` smaže model a stažení, která žádný jiný model nepoužívá.

Runtime třetích stran jsou označeny svým vydavatelem. Omarchy provozuje každý model bez přístupu k síti.

### Lokální LLM

Omarchy doporučuje dva způsoby provozování lokálních modelů LLM: LM Studio a Ollama. LM Studio poskytuje GUI rozhraní pro hledání modelů s otevřenými váhami, jejich instalaci a spouštění. Je to skvělý způsob, jak snadno začít. Ollama nabízí CLI pro totéž podobným způsobem. Ale pokud jste v lokálních modelech noví, začal bych s LM Studio. Obojí můžete nainstalovat v _Install > AI_ v Omarchy Menu.

### Skill Omarchy

Skilly agentů pomáhají AI používat konkrétní nástroje konkrétním způsobem a Omarchy dodává výchozí skill pro přizpůsobení systému. Jako ladění vaší konfigurace Hyprland, úprava lišty, nebo dokonce vytvoření nového tématu od nuly. Je symlinkován do adresářů skillů pro Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` a každý `~/.hermes/profiles/*/skills`) a obecné umístění `~/.agents/skills`, takže jej většina harnessů zachytí automaticky.

Ale měli byste tento skill považovat za experimentální. Různé modely jej použijí s různým efektem. Nejlepší je nejprve běžet v režimu plánování, abyste měli představu, co by agent rád změnil. A poté buďte připraveni vrátit změny zpět, nebo dokonce vyvolat `omarchy reinstall configs`, pokud agent udělá ze všeho nepořádek.
