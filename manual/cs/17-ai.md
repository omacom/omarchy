### Instalace a aktualizace agentů

Kromě Hermes používají tito agenti línou instalaci přes mise: první spuštění nainstaluje CLI a další spuštění ho znovu použijí. mise také nejvýše jednou za čtyři hodiny zkontroluje, zda pro nainstalovaného agenta nevyšla nová verze, těsně před jeho spuštěním nebo na pozadí při zobrazení promptu shellu. Pokud tato aktualizace selže nebo jste offline, spustí se nainstalovaná verze. `omarchy update` aktualizuje nainstalované agenty spolu se zbytkem Omarchy a `mup` aktualizuje pouze nástroje spravované přes mise.

Vlastní aktualizátor agenta, například `claude update`, `codex update` nebo tlačítko aktualizace v aplikaci, neaktualizuje instalaci spravovanou přes mise. `codex update` selže a `claude update` může hlásit úspěch, přičemž nainstaluje samostatnou kopii, kterou mise nesleduje. Pokud raději používáte nativní instalační program a aktualizátor agenta, přidejte ho do `disable_tools`; viz [Předinstalované nástroje CLI](18-development-tools.md#preinstalled-cli-tools).

Chcete-li nainstalovat všechny nakonfigurované lazy nástroje dříve, než je budete potřebovat, spusťte `mise install --include-lazy`. To zahrnuje i ostatní výchozí nástroje CLI v Omarchy vedle agentů. Viz [Předinstalované nástroje CLI](18-development-tools.md#preinstalled-cli-tools) pro instalaci jednoho nástroje nebo použití vlastní instalace.

`grok` se instaluje prostřednictvím balíčku `grok` první strany od mise, stejně jako `claude` a `codex`. Spusťte `grok`, nebo ho vyberte pod _Agent > Harness_. Přeskočte instalační program `curl | bash` na x.ai. Tato cesta umístí druhou kopii do `~/.grok/bin`, přidá ji na začátek `PATH` a přepíše wrapper Omarchy.

`dsh` otevře své prohlížečové UI na `127.0.0.1:3080`, přičemž adresář spuštění je jeho výchozím pracovním prostorem. Jeho prohlížečové UI nepřijímá počáteční prompt, takže `omarchy agent prompt` ho otevře s promptem ve vaší schránce k vložení. Omarchy ho spouští s předvolbou oprávnění bez schvalování od DeepSeek. DeepSeek Harness nahrává protokoly relací do DeepSeek, když používáte jeho oficiální API modelů; vypněte to pod _Settings > General > Upload Session Log_ v jeho prohlížečovém UI. Zpětná vazba, kterou mu odešlete, se nahraje spolu s relací také, pokud ho nespustíte s `DSH_TELEMETRY_MODE=DISABLED`.

### Výchozí agent

Vyberte si výchozího agenta pomocí `omarchy default agent <name>` nebo pod _Agent > Harness_ v Omarchy Menu (`Super + Space`). Pokud agent ještě není nainstalován, jeho výběr ho nejprve nainstaluje. Čerstvé Omarchy vás k tomuto výběru vyzve jednorázovým oznámením.

Výběr Claude se také pokusí nastavit jeho rozšíření prohlížeče pro Chromium, Chrome, Brave, Brave Origin a Edge. Nastavení rozšíření platí pro všechny uživatele a může vyžadovat vaše systémové heslo; zrušení nebo neúspěšná instalace rozšíření přesto vybere a spustí Claude. Restartujte prohlížeč, povolte rozšíření, pokud k tomu budete vyzváni, a přihlaste se do Claude pro dokončení připojení. Spusťte `/chrome` v Claude pro kontrolu připojení. Firefox a Zen toto rozšíření nepodporují. Pokud byl Claude vaším výchozím již před přidáním tohoto nastavení, vyberte ho znovu pro instalaci rozšíření.

Jakmile si vyberete, `Super + Shift + Ctrl + A` spustí výchozího agenta ve vyhrazeném okně terminálu (nebo zobrazí výběr, pokud jste si ještě nevybrali). Můžete ho také spustit přímo do úkolu pomocí `omarchy agent prompt "Review this project"`. Freebuff a DeepSeek Harness nepřijímají počáteční prompt, takže se místo toho otevřou s promptem ve vaší schránce k vložení. Agenti spuštění tímto způsobem běží bez dohledu ve svých příslušných režimech neptat-se-a-nezastavovat, takže buďte připraveni na to, že budou skutečně něco dělat! MiniMax Code takový režim pro své interaktivní relace nemá, takže žádá o oprávnění jako obvykle. A protože agenti odmítají zapamatovat si důvěru pro váš domovský adresář, spuštění z `$HOME` začínají místo toho v `~/Work`.

Existují také zkratky terminálu: `a` spustí výchozího agenta inline v aktuálním terminálu, zatímco `c`, `cx` a `cy` spustí OpenCode, Claude Code a Codex přímo (opět v jejich režimech automatického schvalování). Změny motivu se synchronizují i do agentů: Claude Code, Pi, OpenCode a Hermes (jakmile ho Omarchy nainstaluje) všechny následují, když přepnete motiv Omarchy.

### Vaše pokyny pro agenty

Osobní pravidla pro každého agenta patří do `~/.agents/AGENTS.md`, vedle sdílených skills v `~/.agents/skills`. Otevřete ho pod _Agent > Instructions_, což ho také propojí do každého harnessu, který si udržuje vlastní globální soubor: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` od Copilot a tak dále. Crush a Amp čtou odkaz `~/.config/AGENTS.md`, zatímco omp, Kimi a DeepSeek Harness čtou `~/.agents/AGENTS.md` přímo. Výběr výchozího agenta ho propojí také. Soubor s pokyny, který jste již měli, se stane sdíleným, pokud ještě žádný nebyl; jinak je ponechán vedle odkazu jako `.bak`. Spusťte `omarchy agent instructions` pro opětovné propojení po instalaci dalšího agenta.

### Panel agentů

Horní lišta má ikonu agentů. Než si nastavíte agenta, jeho panel vás provede přihlášením do Claude, Codex nebo Grok a první z nich se stane vaším výchozím agentem. Poté panel umístí každé předplatné na jednu stránku: každého agenta a účet s jeho plánem, ukazatel pro každý z jeho 5hodinových limitů relace a týdenních limitů s časem do resetování (přejetím zobrazíte přesné procento), nebo zbývající předplacený zůstatek, pod řádkem, který střídavě prochází tím, co jste použili napříč všemi, jako tokeny za tento týden a váš nejpoužívanější model. Pod _Make something_ nabízí úvodní prompty pro nový motiv, plugin, aplikaci nebo hru, které předají úkol vašemu výchozímu agentovi. Aplikace jsou vytvářeny stejným způsobem jako vlastní Hype, Monologue a Omacut od Omarchy, v C++ a Qt Quick, podle agent skill omarchy-make-app, a kompilátor a části Qt, které potřebují, jsou předinstalovány. Hry jsou jedna stránka three.js v `~/Games/vibes`, podle agent skill omarchy-make-game, a všechny se otevírají z jednoho spouštěče Game Vibes v aktuálním motivu; načítají three.js z webu, takže ke spuštění potřebují připojení. Claude Code, Codex, Grok, Kimi, Cursor a jeho příděl Grok Bot, GitHub Copilot, Muse, Antigravity, Kimchi a Devin jsou pokryty hned po instalaci se svými limity a Hermes, Mistral Vibe a Qwen Code zobrazí své relace a tokeny, jakmile je použijete. Plány a klíče poskytovatelů, které používáte prostřednictvím pi, omp nebo opencode, se zobrazí také: OpenCode Zen a Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan a Synthetic se svými limity; Fireworks, OpenRouter a DeepSeek se svými předplacenými zůstatky; a modely, které spouštíte na vlastním hardwaru pod Lokální modely. Každý agent se počítá jednou, pod tím, kdo vám ho účtuje, bez ohledu na to, přes kolik harnessů ho ovládáte.

Klikněte levým tlačítkem na ikonu v liště pro panel, pravým tlačítkem spustíte výchozího agenta. Záznamy o využití za ním se regenerují každých 15 minut pomocí `omarchy agent usage-update` a panel může dokonce sloučit využití z vašich ostatních počítačů prostřednictvím synchronizované složky. Úplné nastavení najdete v README pod `$OMARCHY_PATH/shell/plugins/agents/`.

### Několik předplatných

Pokud platíte za více než jeden plán Claude, Codex nebo Grok — řekněme osobní Max a pracovní — Omarchy je může udržet všechny přihlášené a pohybovat se mezi nimi. Přidejte předplatné pomocí + v panelu agentů, který vás tím provede přímo tam, nebo pomocí `omarchy agent account add claude Work` (nebo `codex`, nebo `grok`). Nainstaluje CLI, pokud chybí. První účet u poskytovatele se přihlašuje prostřednictvím vašeho běžného prohlížeče, přesně tam, kde CLI vždy hledá. Každý další se přihlašuje prostřednictvím soukromého okna, aby se omylem nevybral účet, ke kterému je váš prohlížeč již přihlášen; přihlaste se tam jako účet, který přidáváte, a nejprve zavřete všechna soukromá okna, která jste již měli otevřená. Nikdy se za tímto účelem neodhlasujte z CLI: odhlášení zruší uložené přihlášení a ten účet by musel být přidán znovu.

Chcete-li zkopírovat přihlášení k předplatnému na jiný počítač s Omarchy přes SSH, spusťte `omarchy agent account copy user@laptop`. Odesílatel dodá dočasného příjemce, když cílový počítač žádného nainstalovaného nemá, takže starší počítače s Omarchy mohou přijímat účty bez aktualizace. Nainstalovaní příjemci mají přednost. Tím se zkopírují všechna předplatná Claude, Codex a Grok; přidejte názvy poskytovatelů pro jejich výběr, jako v `omarchy agent account copy laptop claude`. Názvy účtů a ID příkazů odpovídají zdroji, včetně účtů již přítomných v cíli. Nesouvisející cílové účty obdrží číselnou příponu, pokud se jejich názvy střetávají, a nastavení, skills, pluginy a historie konverzací zůstávají lokální pro každý počítač.

Stávající cílové přihlašovací údaje jsou zachovány. Zdrojový účet, který je tam již přihlášen, má synchronizován název, aniž by se nahradily jeho přihlašovací údaje; ostatní účty jsou přidány vedle něj. Chcete-li nahradit uložené přihlašovací údaje pro shodující se účty, použijte `omarchy agent account copy --replace laptop claude` po ukončení relací daného účtu v cíli. Čerstvý cíl také získá aktivní účet a předvolby přepínání zdroje; zavedený cíl si ponechá své vlastní.

Přihlašovací údaje cestují přes SSH a jsou uloženy v soukromých souborech v cíli, takže kopírujte pouze na počítače, kterým důvěřujete. Toto je jednorázová kopie, nikoli průběžná synchronizace. Obnovovací tokeny Codex mohou být rotovány jiným počítačem, takže zkopírované přihlášení bude potřebovat obnovení; samostatná přihlášení zůstávají nejspolehlivější volbou pro současné použití na několika počítačích. Viz [průvodce ověřováním účtů Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Jeden účet na poskytovatele je aktivní a každá nová relace začíná jako on: `cx`, `cy`, prosté `claude`, `codex` nebo `grok`, cokoli spuštěného prostřednictvím `omarchy agent` a skripty nebo editory, které najdou CLI na `PATH`. Přepněte pomocí `omarchy agent account use work` (a zpět pomocí `omarchy agent account use main`), nebo v panelu stisknutím čísla účtu a poté `Enter` (nebo kliknutím na jeho tlačítko Use). Běžící relace Claude se přepnou také, od jejich další zprávy: každá relace Claude běží v `~/.claude`, které vždy obsahuje přihlášení aktivního účtu. Relace Claude spuštěná ve vlastní složce účtu starším Omarchy si podrží toto přihlášení, dokud se neukončí, takže přepnutí tyto relace pojmenuje a dokončí se samo, jakmile zmizí. Běžící relace Codex a Grok zůstanou na účtu, se kterým začaly. Historie konverzací, nastavení, skills a pluginy jsou sdíleny napříč účty, takže `claude --continue` ve stejné složce naváže tam, kde jste skončili na novém účtu.

S více než jedním účtem panel zobrazuje limity každého účtu vedle sebe, s označeným aktivním. Ve výchozím nastavení vás Omarchy upozorní, když aktivní účet překročí 95 % limitu, a kliknutí na oznámení přepne na účet s největší rezervou. Přejeďte přes řádek účtu v panelu a klikněte na Autoswitch, které se objeví vedle Use (nebo stiskněte `m`), nebo spusťte `omarchy agent account mode auto`, aby se přepínal sám; když je zapnuté, Autoswitch zaujme místo Use a opětovné kliknutí se vrátí k oznamování. Přidejte číslo pro změnu prahu, jako v `omarchy agent account mode auto 90`. Pokud je každý účet nad prahem, dozvíte se to jednou, spolu s tím, který účet se uvolní jako první. Když je aktivní účet do 15 bodů od svého prahu (80 % ve výchozím nastavení), jeho limity se kontrolují každé tři minuty místo každých 15.

`omarchy agent account list` zobrazí každý účet a jeho nejnovější limity, `omarchy agent account remove work` jeden zapomene a `omarchy agent account rename primary Hey` jeden přejmenuje (nebo klikněte na název účtu v panelu). Tyto příkazy pracují s účty vašeho výchozího agenta; chcete-li dosáhnout na jiného poskytovatele, nejprve ho pojmenujte, jako v `omarchy agent account use codex side`. Přihlášení, které jste již měli v `~/.claude` nebo `~/.codex`, je účet _Main_. Účet Codex zůstává tam, kde je; účet Claude čeká ve vlastní složce, zatímco je aktivní jiný účet. Účet ponechaný bez použití déle než asi osm hodin může zobrazovat _Sign-in required_; klikněte na něj pro opětovné přihlášení daného účtu přímo v panelu, nebo na něj přepněte a spusťte relaci, která přihlášení obnoví sama. Servery MCP, které přidáte pomocí `claude mcp add`, dosáhnou na každý účet Claude, protože všechny běží v `~/.claude`; u Codex a Grok servery, které jste měli při přidání účtu, přijdou spolu s ním, ale pozdější dosáhnou pouze na účet, ve kterém jste je přidali. Claude Desktop si udržuje vlastní přihlášení a nástroje Codex nebo Grok nakonfigurované s absolutní cestou k binárnímu souboru CLI přepnutí nenásledují. Explicitní `CLAUDE_CONFIG_DIR`, `CODEX_HOME` nebo `GROK_HOME` má přednost před vybraným účtem.

### Diagnostika pádů

Omarchy sleduje systemd-coredump kvůli pádům procesů. Když něco segfaultuje, dostanete oznámení „Process crashed“ — klikněte na něj a pád je předán vašemu výchozímu agentovi spolu se skill diagnose-crash od Omarchy, který agenta provede zjištěním faktů z core dump a rozhodnutím, zda pád stojí za nahlášení upstream. Můžete ho také spustit ručně proti libovolnému PID z `coredumpctl list` pomocí `omarchy agent crash <pid>`.

Sledování je ve výchozím nastavení zapnuté. Vypněte ho pod _Trigger > Toggle > Crash Capture_ (nebo pomocí `omarchy toggle crash-capture`) a oznámení přestanou; `omarchy agent crash <pid>` stále funguje ručně.

Pády lze také ztlumit po jednom programu, což vám diagnostika nabídne na konci. `omarchy crash mute hyprland` zastaví oznámení pouze pro daný program, `omarchy crash mute hyprland off` je vrátí zpět a samotné `omarchy crash mute` vypíše, co jste ztlumili. Přijímá cestu k binárnímu souboru stejně ochotně jako jeho název, takže `omarchy crash mute /usr/bin/hyprland` udělá totéž. Název s mezerou dejte do uvozovek, jako v `omarchy crash mute 'Some App'`. Vše ostatní stále oznamuje a ztlumený program stále padá — toto skrývá připomenutí, nic neopravuje.

### Desktopové aplikace

Menu _Install > AI_ také obsahuje několik grafických aplikací AI: Antigravity Desktop, desktopovou aplikaci ChatGPT, desktopovou aplikaci Claude (beta pro Linux od Anthropic, s kartami Chat, Cowork a Claude Code), Grok Bot pro chatování s modely xAI, Herdr Desktop, Hermes Desktop, OpenClaw, desktopovou aplikaci Perplexity a T3 Code. Grok Bot je desktopová chatovací aplikace. Kódovací agent je příkaz `grok`.

Hermes Desktop je ten, o kterém je třeba vědět, protože počítač má jeden Hermes a ten patří aplikaci: Hermes se instaluje pouze prostřednictvím aplikace a příkaz `hermes`, který výchozí agent spouští, je ten od aplikace. Výběr Hermes jako výchozího agenta nainstaluje totéž, co položka _Install > AI_: balíček a runtime Hermes pod `~/.hermes` nastavený vlastním instalačním programem Hermes, což poprvé trvá několik minut. Tento runtime je ten jediný Hermes, který používají příkaz `hermes` v terminálu, výchozí agent i aplikace, a aktualizuje se sám pomocí `hermes update`, místo aby čekal na vydání Omarchy. Jeho instalace také předá Hermes motiv Omarchy jako skin pojmenovaný `omarchy`, který každé rozhraní Hermes následuje při přepínání motivů; vyberte jiný v nastavení Appearance v Hermes nebo pomocí `/skin`, pokud nechcete, aby to dělal, a Omarchy tuto volbu nechá na pokoji. Odstranění aplikace pod _Remove > AI_ nejprve zavře Hermes, včetně gateway, vezme s sebou tento runtime a zachová vaše chaty, vzpomínky a skills, které si Hermes napsal pro sebe, pokud mu neřeknete jinak: zeptá se, s výchozí odpovědí ne, zda mají zmizet i tato data a vaše nastavení připojení.

Desktopový zážitek OpenClaw je jeho Control UI, které se otevírá jako webová aplikace podporovaná vlastní lokální gateway. OpenClaw žije v `~/.openclaw` a aktualizuje se sám: použijte tlačítko „Update Gateway“ v Control UI nebo spusťte `openclaw update` a gateway se restartuje na nové verzi. Omarchy vybírá pouze vydání, ze kterého čerstvá instalace vychází. Odstranění OpenClaw pod _Remove > AI_ vezme s sebou službu gateway a aplikaci a poté se zeptá, zda má zmizet i `~/.openclaw`, protože to obsahuje vaše chaty a přihlašovací údaje spolu se samotným OpenClaw a runtime pluginů, které stahuje; výchozí nastavení ho zachová a opětovná instalace OpenClaw ho znovu převezme.

Herdr Desktop je desktopová aplikace [Herdr](https://herdr.dev): prostory, karty a panely terminálů a kódovacích agentů, které nadále běží v jejím jádru, když zavřete okno. Pochází z vlastního instalačního programu Herdr spíše než z balíčku, takže žije v `~/.local/share/herdr-app`, přináší s sebou své jádro v `~/.local/bin/herdr-core`, když ještě žádné nemáte, a aktualizuje obojí samo. Sedí vedle příkazu `herdr`, který Omarchy dodává na `Super + Ctrl + Return`, místo aby ho nahrazovala, a dostává přímé klávesy tohoto příkazu: `Alt + Return` a `Alt + Shift + Return` rozdělí panel dolů nebo doprava, `Alt + Escape` ho zavře, `Ctrl + Alt + Arrow` se pohybuje mezi panely, `Alt + 1..9` a `Alt + Left/Right` vyberou kartu a `Alt + Up/Down` se pohybují mezi prostory. `Ctrl + 1..9` vybere prostor a `Alt + Shift + Up/Down` krokuje mezi agenty. Klávesy s prefixem `Ctrl + Space` zůstávají pouze pro terminál, protože aplikace nemůže držet prostou klávesu Ctrl pro sekvenci. Omarchy je zapisuje do `~/.config/herdr-app/keys.json` a `omarchy-refresh-herdr-app` je vrátí zpět. Jeho instalace vybere motiv Omarchy v Herdr, který od té doby následuje váš motiv Omarchy. Herdr uchovává jeden motiv pro světlý režim a jeden pro tmavý, takže po přepnutí mezi tmavým a světlým motivem Omarchy vyberte Omarchy ve výběru motivů Herdr ještě jednou pro druhý režim.

T3 Code běží ze svého oficiálního vydání AppImage v `~/.local/share/t3code` spíše než z balíčku, takže se aktualizuje sám. Jeho instalace se zeptá, zda začít na kanálu Stable nebo Nightly; přepněte později v nastavení T3 Code. Vaše vlákna a nastavení žijí v `~/.t3` a odstranění T3 Code pod _Remove > AI_ je vezme s sebou.

### Lokální modely

Spusťte otevřený model na vlastním počítači pro své kódovací agenty. Vaše prompty a kód zůstanou na počítači; nic odeslaného modelu ho neopustí. Začněte s:

```bash
omarchy agent local use best
```

Nebo v panelu agentů v horní liště zvolte + a poté Local AI, které se zobrazí, když se model vejde na tento počítač. Poprvé to nainstaluje Podman, který spouští modely, a na počítači s NVIDIA sadu nástrojů pro kontejnery NVIDIA, která jim poskytne GPU. Omarchy poté vybere doporučený model pro tento počítač, stáhne ho a spustí. Očekávejte stažení desítek GB a to, že většina paměti počítače bude využívána, když model běží: Flash Next používá asi 100 GiB se svým plným kontextem 256K. Pokud jiné modely drží paměť, kterou potřebuje, nastaví se zastavený, připravený ke spuštění, jakmile jeden zastavíte. Model se zastaví při odhlášení; zastavte ho sami, když potřebujete paměť na něco jiného.

`omarchy agent local list` zobrazí možnosti a vysvětlí, proč se některé nevejdou. Chcete-li nastavit další, spusťte `omarchy agent local use <recipe>`. Dnes jsou `qwen3.8-flash-next-gufo` a `qwen3.8-27b-gufo` k dispozici pro počítače Strix Halo se 128 GB; 27B zabírá asi 40 GiB, takže nechává prostor pro jinou práci. Na notebooku se 64 GB s Arc B390 od Intel běží `qwen3.6-35b-a3b-llamacpp` v asi 30 GiB. Nové recepty a doporučení přicházejí s `omarchy update`, prostřednictvím balíčku.

Každý model, který nastavíte, dostane vlastní řádek v panelu agentů, vedle vašich předplatných: přehrát pro spuštění, pozastavit pro zastavení a uvolnění jeho paměti a tlačítko terminálu pro otevření vašeho agenta na něm. Několik jich může běžet najednou, když se společně vejdou do paměti; pokud se jeden nevejde, Omarchy řekne, který běžící model zastavit. Přetažením řádků je můžete přeřadit a stisknutím Delete na vybraném řádku odstraníte model a jeho stažení.

Každý model, který nastavíte, také dostane vlastní položku ve spouštěči aplikací, pod názvem modelu a s logem jeho tvůrce, stejným způsobem, jakým přihlášení do Claude, Codex nebo Grok přidá jednu. Otevře vašeho agenta na daném modelu a nejprve model spustí, pokud neběží: terminál zobrazí jeho načítání a předá řízení agentovi, jakmile je nahoře. Odstranění modelu odstraní jeho položku.

Model nadále běží přesně tak, jak byl nastaven, takže aktualizace Omarchy nikdy nerestartuje žádný pod vašimi agenty. Když má Omarchy novější runtime nebo novější váhy pro model, který jste nastavili, jeho řádek zobrazí tlačítko aktualizace: stiskněte ho a model se znovu nastaví na pozadí, stáhne pouze to, co se změnilo, a restartuje se na nové verzi. Model, který byl zastaven, zůstane zastaven. `omarchy agent local update` udělá totéž pro každý model z terminálu.

Z příkazového řádku dělají totéž `omarchy agent local start <recipe>` a `omarchy agent local stop <recipe>`, `omarchy agent local status` zobrazí každý model a `omarchy agent --local` otevře vašeho výchozího agenta na posledním modelu, který jste spustili. pi, OpenCode a Qwen Code jeden použít mohou; s jakýmkoli jiným výchozím se otevře v pi. pi také vypíše každý model, který jste nastavili, a ty na počítačích, se kterými jste spárováni, ve svém vlastním výběru modelů, takže prosté `pi` k nim dosáhne také. Připojit se může i jakýkoli klient kompatibilní s OpenAI: `status` zobrazí adresu každého modelu (první je `http://127.0.0.1:11435/v1`), název receptu je modelem a klíč je v `~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` smaže model a stažení, která žádný jiný model nepoužívá.

Runtime třetích stran jsou označeny svým vydavatelem. Omarchy spouští každý model bez přístupu k síti.

### Lokální LLM

Omarchy doporučuje dva způsoby spouštění lokálních modelů LLM: LM Studio a Ollama. LM Studio poskytuje GUI rozhraní pro hledání modelů s otevřenými vahami, jejich instalaci a spouštění. Je to skvělý způsob, jak snadno začít. Ollama nabízí CLI pro podobné provádění téhož. Ale pokud jste v lokálních modelech noví, začal bych s LM Studio. Obojí můžete nainstalovat pod _Install > AI_ v Omarchy Menu.

### Skill Omarchy

Skills agentů pomáhají AI používat konkrétní nástroje konkrétním způsobem a Omarchy se dodává s výchozím skill pro přizpůsobení systému. Jako ladění vaší konfigurace Hyprland, úprava lišty nebo dokonce vytvoření nového motivu od nuly. Je symlinkován do adresářů skills pro Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` a každý `~/.hermes/profiles/*/skills`) a obecné umístění `~/.agents/skills`, takže ho většina harnessů převezme automaticky.

Ale měli byste tento skill považovat za experimentální. Různé modely ho využijí s různým účinkem. Nejlepší je nejprve běžet v režimu plánování, abyste měli představu o tom, co by agent rád změnil. A pak buďte připraveni vrátit změny zpět nebo dokonce zavolat `omarchy reinstall configs`, pokud agent všechno zpacká.
