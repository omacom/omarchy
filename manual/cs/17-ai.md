# AI

Omarchy obsahuje spouštěče pro níže uvedené kódovací agenty, aniž by za vás vybírala výchozího. Spuštěním příkazu nainstalujete jeho CLI při prvním použití a po výzvě se přihlásíte. Hermes a OpenClaw jsou výjimkou: pro ně se přes mise nic neinstaluje a výběrem kteréhokoli z nich se nastaví jeho vlastní samoaktualizační kopie, jak níže vysvětluje část _Desktop apps_.

### Instalace a aktualizace agentů

Kromě Hermes a OpenClaw tito agenti používají línou instalaci přes mise: první spuštění nainstaluje CLI a další spuštění ho znovu použijí. mise také nejvýše jednou za čtyři hodiny, těsně před spuštěním nebo na pozadí při promptu shellu, zkontroluje, zda pro nainstalovaného agenta nevyšla nová verze. Pokud tato aktualizace selže nebo jste offline, spustí se nainstalovaná verze. `omarchy update` aktualizuje nainstalované agenty spolu se zbytkem Omarchy a `mup` aktualizuje pouze nástroje spravované přes mise.

Vlastní aktualizátor agenta, jako je `claude update`, `codex update` nebo tlačítko aktualizace v aplikaci, neaktualizuje instalaci spravovanou přes mise. `codex update` selže a `claude update` může hlásit úspěch, přičemž nainstaluje samostatnou kopii, kterou mise nesleduje. Pokud byste raději používali nativní instalační program a aktualizátor agenta, přidejte ho do `disable_tools`; viz [Předinstalované CLI nástroje](18-development-tools.md#preinstalled-cli-tools).

Chcete-li nainstalovat všechny nakonfigurované lazy nástroje dříve, než je budete potřebovat, spusťte `mise install --include-lazy`. To zahrnuje i ostatní výchozí CLI nástroje Omarchy i agenty. Informace o instalaci jednoho nástroje nebo použití vlastní instalace najdete v části [Předinstalované CLI nástroje](18-development-tools.md#preinstalled-cli-tools).

`grok` se instaluje prostřednictvím balíčku `grok` první strany od mise, stejným způsobem jako `claude` a `codex`. Spusťte `grok` nebo ho označte hvězdičkou v panelu agentů. Přeskočte instalační program `curl | bash` na x.ai. Tato cesta umístí druhou kopii do `~/.grok/bin`, předsadí ji na `PATH` a přepíše wrapper Omarchy.

`dsh` otevírá své prohlížečové UI na `127.0.0.1:3080`, přičemž adresář spuštění je jeho výchozím pracovním prostorem. Jeho prohlížečové UI nepřijímá žádný počáteční prompt, takže `omarchy agent prompt` ho otevře s promptem ve vaší schránce k vložení. Omarchy ho spouští s předvolbou oprávnění bez schvalování od DeepSeek. DeepSeek Harness nahrává protokoly relací do DeepSeek, když používáte jeho oficiální API modelů; vypněte to v jeho prohlížečovém UI pod _Settings > General > Upload Session Log_. Zpětná vazba, kterou mu odešlete, se nahrává spolu s relací také, pokud ho nespustíte s `DSH_TELEMETRY_MODE=DISABLED`.

### Výchozí agent

Vyberte si svého výchozího agenta hvězdičkou vedle agenta v panelu agentů, která je u výchozího vyplněná, nebo příkazem `omarchy default agent <name>`, který přijme i jakýkoli harness, jenž tam nemá řádek. Pokud agent ještě není nainstalovaný, jeho výběrem se nejprve nainstaluje a také dostane svůj vlastní spouštěč ve spouštěči aplikací, vedle položky Agent. Čerstvá Omarchy vás k nastavení jednoho vyzve jednorázovým oznámením, které otevře panel agentů.

Výběr Claude se také pokusí nastavit jeho rozšíření prohlížeče pro Chromium, Chrome, Brave, Brave Origin a Edge. Nastavení rozšíření platí pro všechny uživatele a může vyžadovat vaše systémové heslo; zrušení nebo neúspěšná instalace rozšíření přesto Claude vybere a spustí. Restartujte prohlížeč, povolte rozšíření, pokud k tomu budete vyzváni, a přihlaste se do Claude, abyste dokončili jeho připojení. Spuštěním `/chrome` v Claude zkontrolujte připojení. Firefox a Zen toto rozšíření nepodporují. Pokud byl Claude vaším výchozím již před přidáním tohoto nastavení, vyberte ho znovu, abyste rozšíření nainstalovali.

Jakmile si vyberete, `Super + Shift + Ctrl + A` spustí výchozího agenta ve vyhrazeném okně terminálu (nebo vyvolá výběr, pokud jste si ještě nevybrali). Můžete ho také spustit rovnou do úkolu příkazem `omarchy agent prompt "Review this project"`. Freebuff a DeepSeek Harness nepřijímají žádný počáteční prompt, takže se místo toho otevřou s promptem ve vaší schránce k vložení. Takto spuštění agenti pracují bez dozoru ve svých příslušných režimech, kdy se nezastavují, aby se zeptali, takže buďte připraveni na to, že budou skutečně něco dělat! MiniMax Code takový režim pro své interaktivní relace nemá, takže se na oprávnění ptá jako obvykle. A protože agenti odmítají zapamatovat si důvěru k vašemu domovskému adresáři, spuštění z `$HOME` místo toho začínají v `~/Work`.

Existují i terminálové zkratky: `a` spustí výchozího agenta přímo v aktuálním terminálu, zatímco `c`, `cx` a `cy` spustí přímo OpenCode, Claude Code a Codex (opět v jejich režimech automatického schvalování). Změny motivu se synchronizují i do agentů: Claude Code, Pi, OpenCode a Hermes (jakmile ho Omarchy nainstaluje) následují, když přepnete motiv Omarchy.

### Vaše pokyny pro agenty

Osobní pravidla pro každého agenta patří do `~/.agents/AGENTS.md`, vedle sdílených skills v `~/.agents/skills`. Otevřete ho ikonou dokumentu vedle + v panelu agentů nebo příkazem `omarchy agent instructions --edit`, který ho také propojí do každého harnessu, jenž si uchovává vlastní globální soubor: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` od Copilot a tak dále. Crush a Amp čtou odkaz `~/.config/AGENTS.md`, zatímco omp, Kimi a DeepSeek Harness čtou přímo `~/.agents/AGENTS.md`. Výběr výchozího agenta ho propojí také. Soubor s pokyny, který jste už měli, se stane sdíleným, pokud ještě žádný nebyl; jinak je uchován vedle odkazu jako `.bak`. Po instalaci dalšího agenta spusťte `omarchy agent instructions`, abyste ho znovu propojili.

### Panel agentů

Horní panel má ikonu agentů. Než si agenta nastavíte, jeho panel nabízí tři způsoby, jak začít: přihlásit se k předplatnému Claude, Codex, Grok, Gemini, Muse, Cursor nebo Copilot, nebo pod More ke kódovacímu plánu OpenCode Go, MiniMax, Synthetic nebo Z.ai; platit průběžně za použití s Fireworks, OpenCode Zen and Go, OpenRouter, nebo pod More s DeepSeek nebo jakýmkoli jiným poskytovatelem, ke kterému se OpenCode přihlašuje, vše běží v OpenCode; nebo spustit nejlepší model pro váš počítač, když se pro něj nějaký hodí. První, který dokončíte, se stane vaším výchozím agentem a + v panelu, nebo _Agent > Add_ v Omarchy Menu, nabízí stejné tři později. Poté panel umístí každé předplatné na jednu stránku: každého agenta a účet s jeho plánem, měřič pro každý z jeho limitů 5hodinové relace a týdenních limitů s časem do jeho resetování (přesné procento zjistíte najetím), nebo zbývající předplacený zůstatek, pod řádkem, který rotuje tím, co jste využili napříč všemi, jako jsou tokeny za tento týden a váš nejpoužívanější model. Pod _Make something cool_ nabízí úvodní prompty pro nový motiv, plugin, aplikaci nebo hru, které předají úkol vašemu výchozímu agentovi. Aplikace se vytvářejí tak, jak se vytvářejí vlastní Hype, Monologue a Omacut od Omarchy, v C++ a Qt Quick, podle agent skillu omarchy-make-app, a kompilátor a části Qt, které potřebují, jsou nainstalované. Hry jsou jedna stránka three.js v `~/Games/vibes`, podle agent skillu omarchy-make-game, a všechny se otevírají z jednoho spouštěče Game Vibes v aktuálním motivu; načítají three.js z webu, takže ke spuštění potřebují připojení. Claude Code, Codex, Grok, Kimi, Cursor a jeho příděl Grok Bot, GitHub Copilot, Muse, Gemini (prostřednictvím Antigravity) a Devin jsou pokryty hned po instalaci se svými limity, Kimchi se svým plánem, předplacenými kredity a rozpočty útraty, a Hermes, Mistral Vibe a Qwen Code ukazují své relace a tokeny, jakmile je použijete. Objeví se i plány a klíče poskytovatelů, které používáte prostřednictvím pi, omp nebo opencode: OpenCode Zen and Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan a Synthetic se svými limity; OpenRouter a DeepSeek se svými předplacenými zůstatky; Fireworks se svou útratou za posledních 30 dní. Tokeny z modelů, které provozujete na svém vlastním hardwaru, se také započítávají do celkových hodnot; samotné modely mají vlastní panel, popsaný v části [Lokální modely](#local-models). Každý agent se započítává jednou, u toho, kdo ho účtuje, bez ohledu na to, přes kolik harnessů ho ovládáte.

Levým kliknutím na ikonu panelu nebo stisknutím `Super + Ctrl + X` zobrazíte panel, pravým kliknutím spustíte svého výchozího agenta a prostředním kliknutím obnovíte. Záznamy o využití, které za ním stojí, každých 15 minut znovu generuje `omarchy agent usage update` a panel může dokonce sloučit využití z vašich ostatních počítačů prostřednictvím synchronizované složky. Úplné nastavení najdete v README pod `$OMARCHY_PATH/shell/plugins/agents/`.

### Několik předplatných

Pokud platíte za více než jeden plán Claude, Codex nebo Grok — řekněme osobní Max a pracovní — Omarchy je může udržet všechny přihlášené a přecházet mezi nimi. Přidejte předplatné pomocí + v panelu agentů, které vás tím provede přímo tam, nebo příkazem `omarchy agent account add claude Work` (nebo `codex`, nebo `grok`). Stejné + a příkaz vás přihlásí k Gemini (`gemini`) a OpenCode (`opencode`) a uloží klíč API Fireworks (`fireworks`) nebo OpenRouter (`openrouter`) v OpenCode; příkaz vás také přihlásí ke Copilot (`copilot`), Cursor (`cursor`) a Muse (`muse`). Ty si uchovávají po jednom přihlášení. Pokud CLI chybí, nainstaluje ho. První účet u poskytovatele se přihlašuje přes váš běžný prohlížeč, přesně tam, kde to CLI vždy hledá. Každý další se přihlašuje přes soukromé okno, takže účet, ke kterému je váš prohlížeč už přihlášený, není omylem vybrán; přihlaste se tam jako účet, který přidáváte, a nejprve zavřete jakékoli soukromé okno, které už máte otevřené. Kvůli tomu se nikdy neodhlášením z CLI nezabývejte: odhlášení zruší uložené přihlášení a tento účet by bylo nutné přidat znovu.

Chcete-li zkopírovat přihlášení k předplatným na jiný počítač s Omarchy přes SSH, spusťte `omarchy agent account copy user@laptop`. Odesílatel dodá dočasného přijímače, když cílový počítač žádného nainstalovaného nemá, takže starší počítače s Omarchy mohou přijímat účty bez aktualizace. Nainstalovaní přijímači mají přednost. To kopíruje všechna předplatná Claude, Codex a Grok; přidejte názvy poskytovatelů, abyste je vybrali, jako v `omarchy agent account copy laptop claude`. Názvy účtů a ID příkazů odpovídají zdroji, včetně účtů již přítomných v cíli. Nesouvisející cílové účty dostanou číselnou příponu, pokud se jejich názvy střetnou, a nastavení, skills, pluginy a historie konverzací zůstávají místní na každém počítači.

Stávající cílové přihlašovací údaje zůstávají zachovány. Zdrojový účet, který je tam již přihlášený, má synchronizovaný název, aniž by se nahradily jeho přihlašovací údaje; ostatní účty se přidají vedle něj. Chcete-li nahradit uložené přihlašovací údaje u shodných účtů, použijte `omarchy agent account copy --replace laptop claude` poté, co na cílovém počítači ukončíte relace tohoto účtu. Čerstvý cíl také získá aktivní účet a předvolby přepínání zdroje; zavedený cíl si ponechá vlastní.

Přihlašovací údaje cestují přes SSH a ukládají se do soukromých souborů na cílovém počítači, takže kopírujte pouze na počítače, kterým důvěřujete. Jedná se o jednorázovou kopii, ne o probíhající synchronizaci. Refresh tokeny Codex může jiný počítač rotovat, čímž zkopírované přihlášení zůstane potřebující obnovení; samostatná přihlášení zůstávají nejspolehlivější volbou pro současné používání na několika počítačích. Viz [průvodce ověřováním účtů Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Jeden účet na poskytovatele je aktivní a každá nová relace začíná jako on: `cx`, `cy`, prosté `claude`, `codex` nebo `grok`, cokoli spuštěného prostřednictvím `omarchy agent`, a skripty nebo editory, které najdou CLI na `PATH`. Přepněte příkazem `omarchy agent account use work` (a zpět příkazem `omarchy agent account use main`), nebo v panelu stisknutím čísla účtu a poté `Enter` (nebo kliknutím na jeho hvězdičku). Běžící relace Claude se také přepnou od jejich další zprávy: každá relace Claude běží v `~/.claude`, který vždy obsahuje přihlášení aktivního účtu. Relace Claude spuštěná starší Omarchy ve vlastní složce účtu si toto přihlášení uchovává, dokud se neukončí, takže přepnutí tyto relace pojmenuje a samo se dokončí, jakmile zmizí. Běžící relace Codex a Grok zůstávají na účtu, se kterým začaly. Historie konverzací, nastavení, skills a pluginy jsou sdíleny napříč účty, takže `claude --continue` ve stejné složce naváže tam, kde jste na novém účtu přestali.

S více než jedním účtem panel ukazuje limity každého účtu vedle sebe, s vyplněnou hvězdičkou u toho používaného. Omarchy vás upozorní, když aktivní účet překročí 95 % limitu, a kliknutím na oznámení přepnete na účet s největším prostorem. Nikdy nepřepíná sama. Změňte práh příkazem `omarchy agent account threshold 90`. Pokud je každý účet nad prahem, dozvíte se to jednou, spolu s tím, který účet se uvolní jako první. Zatímco je aktivní účet do 15 bodů od svého prahu (80 % při výchozím nastavení), jeho limity se kontrolují každé tři minuty místo každých 15.

`omarchy agent account list` ukáže každý účet a jeho nejnovější limity, `omarchy agent account remove work` jeden zapomene a `omarchy agent account rename primary Hey` jeden přejmenuje (nebo klikněte na název účtu v panelu). Tyto příkazy pracují s účty vašeho výchozího agenta; chcete-li dosáhnout na druhého poskytovatele, nejprve ho pojmenujte, jako v `omarchy agent account use codex side`. Přihlášení, které jste již měli v `~/.claude` nebo `~/.codex`, je účet _Main_. Účet Codex zůstává tam, kde je; účet Claude čeká ve vlastní složce, zatímco je aktivní jiný účet. Účet ponechaný nepoužívaný déle než zhruba osm hodin může zobrazovat _Sign-in required_; klikněte na něj, abyste tento účet znovu přihlásili přímo v panelu, nebo na něj přepněte a spusťte relaci, která přihlášení sama obnoví. Servery MCP, které přidáte příkazem `claude mcp add`, dosáhnou na každý účet Claude, protože všechny běží v `~/.claude`; u Codex a Grok servery, které jste měli v době přidání účtu, s ním přijdou, ale pozdější dosáhnou pouze na účet, ve kterém jste je přidali. Claude Desktop si uchovává vlastní přihlášení a nástroje Codex nebo Grok nakonfigurované s absolutní cestou k binárce CLI přepnutí nenásledují. Explicitní `CLAUDE_CONFIG_DIR`, `CODEX_HOME` nebo `GROK_HOME` má přednost před vybraným účtem.

### Diagnostika pádů

Omarchy sleduje systemd-coredump kvůli pádům procesů. Jakmile si vyberete výchozího agenta, každý váš program, který vyvolá core dump, přinese oznámení "Process crashed" — klikněte na něj a pád se předá vašemu výchozímu agentovi spolu se skillem omarchy-diagnose-crash od Omarchy, který agenta provede zjišťováním faktů z core dumpu a rozhodováním, zda pád stojí za nahlášení upstreamu. Můžete ho také spustit ručně proti jakémukoli PID z `coredumpctl list` příkazem `omarchy agent crash <pid>`.

Sledování je ve výchozím nastavení zapnuté. Vypněte ho pod _Trigger > Toggle > Crash Capture Off_ (nebo příkazem `omarchy toggle crash-capture`) a oznámení přestanou; `omarchy agent crash <pid>` nadále funguje ručně.

Pády lze také umlčet po jednom programu, což je to, co vám diagnostika na konci nabízí. `omarchy crash mute hyprland` zastaví oznámení pouze pro tento program, `omarchy crash mute hyprland off` je přivede zpět a samotné `omarchy crash mute` vypíše, co jste umlčeli. Přijme cestu k binárce stejně ochotně jako její název, takže `omarchy crash mute /usr/bin/hyprland` udělá totéž. Název s mezerou dejte do uvozovek, jako v `omarchy crash mute 'Some App'`. Všechno ostatní nadále upozorňuje a umlčený program nadále padá — to skrývá připomenutí, nic to neopravuje.

### Desktopové aplikace

Nabídka _Install > AI_ obsahuje také několik grafických aplikací AI: Amp Desktop, Antigravity Desktop, desktopovou aplikaci ChatGPT, desktopovou aplikaci Claude (linuxová beta od Anthropic, se záložkami Chat, Cowork a Claude Code), Grok Bot pro chatování s modely xAI, Herdr Desktop, Hermes Desktop, OpenClaw, desktopovou aplikaci Perplexity a T3 Code. Grok Bot je desktopová chatovací aplikace. Kódovací agent je příkaz `grok`.

Hermes Desktop je ta, o které byste měli vědět, protože počítač má jeden Hermes a ten patří aplikaci: Hermes se nikdy neinstaluje jinak než přes aplikaci a příkaz `hermes`, který spouští výchozí agent, je ten od aplikace. Výběr Hermes jako výchozího agenta nainstaluje totéž, co položka _Install > AI_: balíček a runtime Hermes pod `~/.hermes` nastavený vlastním instalačním programem Hermes, což poprvé trvá několik minut. Tento runtime je jediný Hermes, který používají terminálový příkaz `hermes`, výchozí agent i aplikace, a aktualizuje se sám příkazem `hermes update`, místo aby čekal na vydání Omarchy. Jeho instalace také předá Hermes motiv Omarchy jako skin pojmenovaný `omarchy`, který každý povrch Hermes následuje při přepínání motivů; vyberte jiný v nastavení Appearance v Hermes nebo pomocí `/skin`, pokud byste raději, aby to nedělal, a Omarchy tuto volbu nechá být. Odstranění aplikace pod _Remove > AI_ nejprve zavře Hermes, včetně gateway, vezme s sebou tento runtime a zachová vaše chaty, vzpomínky a skills, které si Hermes sám napsal, pokud neřeknete jinak: zeptá se, výchozí odpověď je ne, zda mají odejít i tato data a vaše nastavení připojení.

Desktopovým zážitkem OpenClaw je jeho Control UI, které se otevírá jako webová aplikace podporovaná jeho vlastní místní gateway. OpenClaw žije v `~/.openclaw` a aktualizuje se sám: použijte tlačítko "Update Gateway" v Control UI nebo spusťte `openclaw update` a gateway se na nové verzi restartuje. Omarchy vybírá pouze vydání, od kterého začíná čerstvá instalace. OpenClaw může být také vaším výchozím agentem: jeho výběr pod _Agent > Harness_ nastaví tutéž kopii v `~/.openclaw` a agent otevře terminálové UI OpenClaw připojené k jeho gateway. Odstranění OpenClaw pod _Remove > AI_ s ním vezme službu gateway a aplikaci a poté se zeptá, zda má odejít i `~/.openclaw`, protože to obsahuje vaše chaty a přihlašovací údaje spolu se samotným OpenClaw a runtime pluginů, které stahuje; výchozí nastavení ho zachová a opětovná instalace OpenClaw ho zase vyzvedne.

Herdr Desktop je desktopová aplikace [Herdr](https://herdr.dev): prostory, záložky a panely terminálů a kódovacích agentů, které v jeho jádru běží dál, když okno zavřete. Pochází z vlastního instalačního programu Herdr, nikoli z balíčku, takže žije v `~/.local/share/herdr-app`, přináší s sebou své jádro v `~/.local/bin/herdr-core`, když ještě žádné nemáte, a aktualizuje se sama i ono. Stojí vedle příkazu `herdr`, který Omarchy dodává na `Super + Ctrl + Return`, spíše než aby ho nahrazovala, a získává přímé klávesy tohoto příkazu: `Alt + Return` a `Alt + Shift + Return` rozdělí panel dolů nebo doprava, `Alt + Escape` ho zavře, `Ctrl + Alt + Arrow` přechází mezi panely, `Alt + 1..9` a `Alt + Left/Right` vyberou záložku a `Alt + Up/Down` přecházejí mezi prostory. `Ctrl + 1..9` vybere prostor a `Alt + Shift + Up/Down` prochází agenty. Prefixové klávesy `Ctrl + Space` zůstávají pouze pro terminál, protože aplikace nemůže držet prostou klávesu Ctrl pro sekvenci. Omarchy je zapisuje do `~/.config/herdr-app/keys.json` a `omarchy-refresh-herdr-app` je vrací zpět. Jeho instalace vybere motiv Omarchy od Herdr, který od té doby následuje váš motiv Omarchy. Herdr uchovává jeden motiv pro světlý režim a jeden pro tmavý, takže po přepnutí mezi tmavým a světlým motivem Omarchy vyberte Omarchy ve výběru motivů Herdr ještě jednou pro druhý režim.

T3 Code běží ze svého oficiálního vydání AppImage v `~/.local/share/t3code`, nikoli z balíčku, takže se aktualizuje sám. Jeho instalace se zeptá, zda začít na kanálu Stable, nebo Nightly; později přepněte v nastavení T3 Code. Vaše vlákna a nastavení žijí v `~/.t3` a odstranění T3 Code pod _Remove > AI_ je vezme s sebou.

### Lokální modely

Spusťte otevřený model na svém vlastním počítači pro své kódovací agenty. Vaše prompty a kód zůstávají na počítači; nic odeslaného modelu ho neopustí. Začněte s:

```bash
omarchy models use best text
```

To nastaví nejlepší textový model pro tento počítač, ten druh, který vaši agenti používají. Obrazové, video a hudební modely mají svůj vlastní nejlepší: `omarchy models use best image`, `video` nebo `music`. Spusťte `omarchy models use best`, abyste viděli výběr pro tento počítač pro každý druh.

Nebo otevřete panel lokálních modelů z jeho ikony jisker v horním panelu, vedle ikony agentů, nebo pomocí Super + Ctrl + Alt + X, a zvolte +. Ikona se zobrazí, když se pro tento počítač nějaký model hodí. Podman, který modely spouští, je součástí Omarchy, stejně jako sada nástrojů pro kontejnery NVIDIA na počítači s NVIDIA, která jim poskytuje GPU; pokud něco z toho chybí, první nastavení to nainstaluje. Omarchy pak vybere doporučený model pro tento počítač, stáhne ho a spustí. Očekávejte stažení v řádu desítek GB a to, že během běhu modelu bude využita většina paměti počítače: Flash Next používá asi 100 GiB se svým plným kontextem 256K. Pokud jiné modely drží paměť, kterou potřebuje, je nastaven jako zastavený, připravený ke spuštění, jakmile jeden zastavíte. Model se při odhlášení zastaví; zastavte ho sami, když paměť potřebujete na něco jiného.

`omarchy models list` ukáže možnosti a vysvětlí, proč se některé nehodí. Chcete-li nastavit jiný, spusťte `omarchy models use <recipe>`. Dnes jsou pro počítače Strix Halo se 128 GB k dispozici `qwen3.8-flash-next-gufo` a `qwen3.8-27b-gufo`; 27B zabírá asi 40 GiB, takže nechává prostor pro jinou práci. Na 64GB notebooku s Intel Arc B390 běží `qwen3.6-35b-a3b-llamacpp` v asi 30 GiB. Nové recepty a doporučení přicházejí s `omarchy update`, prostřednictvím balíčku.

Každý model, který nastavíte, dostane vlastní řádek v panelu lokálních modelů: přehrát pro spuštění, pozastavit pro zastavení a uvolnění paměti a tlačítko terminálu pro otevření agenta na něm. Nahoře pruh ukazuje, jak je paměť počítače rozdělena mezi samotnou Omarchy (systém a vaše aplikace), každý běžící model a to, co je volné. Namíříte-li na zastavený model, pruh ukáže, zda se vejde, nebo o kolik mu chybí. Několik jich může běžet najednou, když se spolu vejdou do paměti; pokud se jeden nevejde, Omarchy řekne, který běžící model zastavit. Přetahujte řádky za jejich logo, abyste je přeřadili, a stisknutím Delete na vybraném řádku odeberte model a jeho stažení.

Každý kódovací model, který nastavíte, dostane také vlastní položku ve spouštěči aplikací, pod názvem modelu a s logem jeho tvůrce, tak jako přihlášení k Claude, Codex nebo Grok jednu přidá. Otevře vašeho agenta na tomto modelu a nejprve model spustí, pokud neběží: terminál ukáže jeho načítání a předá řízení agentovi, jakmile bude připraven. Odstranění modelu odebere jeho položku.

Ne každý model je pro kódování. Obrazové, video a hudební modely se místo toho otevírají ve Fantasi, aplikaci Omarchy pro tvorbu obrázků, videa a hudby s modelem běžícím na tomto počítači, vybraném tam nebo z jejich řádku v panelu lokálních modelů.

Model běží dál přesně tak, jak byl nastaven, takže aktualizace Omarchy nikdy nerestartuje žádný pod vašimi agenty. Když má Omarchy novější runtime nebo novější váhy pro model, který máte nastavený, jeho řádek ukáže tlačítko aktualizace: stiskněte ho a model se znovu nastaví na pozadí, stáhne pouze to, co se změnilo, a restartuje se na novou verzi. Model, který byl zastavený, zastavený zůstane. `omarchy models update` udělá totéž pro každý model z terminálu.

Z příkazové řádky `omarchy models start <recipe>` a `omarchy models stop <recipe>` udělají totéž, `omarchy models status` ukáže každý model a `omarchy agent --local-model <recipe>` otevře tento model v pi, ať je váš výchozí agent jakýkoli. Chcete-li, aby váš lokální model byl tím, co otevírá klávesová zkratka agenta, konzole Quake a _Make something_, spusťte `omarchy default agent local` nebo vyberte _Local model_ pod _Agent > Harness_. pi také ve svém vlastním výběru modelů uvádí každý model, který jste nastavili, i ty na počítačích, se kterými jste se spárovali, takže je prosté `pi` také dosáhne. Připojit se může i jakýkoli klient kompatibilní s OpenAI: `status` ukáže adresu každého modelu (první je `http://127.0.0.1:11435/v1`), název receptu je model a klíč je v `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` smaže model a stažení, která žádný jiný model nepoužívá.

Runtime třetích stran jsou označeny jejich vydavatelem. Omarchy spouští každý model bez přístupu k síti.

### Lokální LLM

Omarchy doporučuje dva způsoby provozování lokálních modelů LLM: LM Studio a Ollama. LM Studio poskytuje GUI rozhraní pro hledání modelů s otevřenými váhami, jejich instalaci a spouštění. Je to skvělý způsob, jak snadno začít. Ollama nabízí CLI k obdobnému postupu. Ale pokud s lokálními modely začínáte, začal bych s LM Studio. Obojí můžete nainstalovat pod _Install > AI_ v Omarchy Menu.

### Skilly Omarchy

Agent skills pomáhají AI používat konkrétní nástroje konkrétním způsobem a Omarchy jich dodává sedm. Skill omarchy pokrývá přizpůsobení systému, jako je úprava vaší konfigurace Hyprland nebo nastavení panelu. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app a omarchy-make-game pokrývají tvorbu něčeho nového, omarchy-contribute pokrývá nahlášení chyby nebo odeslání opravy upstreamu a omarchy-diagnose-crash prochází core dump pádu. Jsou propojeny symbolickými odkazy do adresářů skills pro Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` a každý `~/.hermes/profiles/*/skills`) a obecné umístění `~/.agents/skills`, takže je většina harnessů automaticky zachytí. Vaše vlastní složka skillu se stejným názvem má přednost.

Ale měli byste tyto skilly považovat za experimentální. Různé modely je budou používat s různým účinkem. Nejlepší je nejprve běžet v režimu plánování, abyste měli představu o tom, co by agent rád změnil. A pak buďte připraveni vrátit změny zpět, nebo dokonce vyvolat `omarchy reinstall configs`, pokud agent všechno zpustoší.
