### Instalace a aktualizace agentů

S výjimkou Hermes používají tito agenti línou instalaci přes mise: první spuštění nainstaluje CLI a další spuštění je znovu použijí. mise také nejvýše jednou za čtyři hodiny zkontroluje, zda pro nainstalovaného agenta nevyšla nová verze, a to těsně před jeho spuštěním nebo na pozadí při promptu shellu. Pokud tato aktualizace selže nebo jste offline, spustí se nainstalovaná verze. `omarchy update` aktualizuje nainstalované agenty spolu se zbytkem Omarchy a `mup` aktualizuje pouze nástroje spravované přes mise.

Vlastní aktualizátor agenta, jako je `claude update`, `codex update` nebo tlačítko aktualizace v aplikaci, neaktualizuje instalaci spravovanou přes mise. `codex update` selže a `claude update` může hlásit úspěch, přestože nainstaluje samostatnou kopii, kterou mise nesleduje. Pokud byste raději používali nativní instalátor a aktualizátor agenta, přidejte ho do `disable_tools`; viz [Předinstalované nástroje CLI](18-development-tools.md#preinstalled-cli-tools).

Chcete-li nainstalovat všechny nakonfigurované lazy nástroje dříve, než je budete potřebovat, spusťte `mise install --include-lazy`. To zahrnuje i ostatní výchozí nástroje CLI v Omarchy, nejen agenty. Informace o instalaci jednoho nástroje nebo použití vlastní instalace najdete v části [Předinstalované nástroje CLI](18-development-tools.md#preinstalled-cli-tools).

`grok` se instaluje prostřednictvím prvostranového balíčku `grok` od mise, stejně jako `claude` a `codex`. Spusťte `grok` nebo ho vyberte v _Setup > Defaults > Agent_. Přeskočte instalátor `curl | bash` na x.ai. Tato cesta umístí druhou kopii do `~/.grok/bin`, přidá ji na začátek `PATH` a přepíše wrapper od Omarchy.

`dsh` otevírá své prohlížečové UI na `127.0.0.1:3080`, přičemž adresář spuštění je jeho výchozím pracovním prostorem. Jeho prohlížečové UI nepřijímá žádný počáteční prompt, takže `omarchy agent prompt` ho otevře s promptem ve schránce, abyste ho mohli vložit. Omarchy ho spouští s předvolbou oprávnění DeepSeek bez schvalování. DeepSeek Harness nahrává protokoly relací do DeepSeek, když používáte jeho oficiální API modelů; vypněte to v jeho prohlížečovém UI v _Settings > General > Upload Session Log_. Zpětná vazba, kterou mu odešlete, se nahrává spolu s relací, pokud ho nespustíte s `DSH_TELEMETRY_MODE=DISABLED`.

### Výchozí agent

Výchozího agenta vyberte příkazem `omarchy default agent <name>` nebo v _Setup > Defaults > Agent_ v Omarchy Menu (`Super + Space`). Pokud agent ještě není nainstalovaný, jeho výběr ho nejprve nainstaluje. Čerstvá instalace Omarchy vás k této volbě vyzve jednorázovým oznámením.

Výběr Claude se také pokusí nastavit jeho rozšíření prohlížeče pro Chromium, Chrome, Brave, Brave Origin a Edge. Nastavení rozšíření platí pro všechny uživatele a může vyžadovat vaše systémové heslo; zrušení nebo neúspěšná instalace rozšíření přesto Claude vybere a spustí. Restartujte prohlížeč, po vyzvání rozšíření povolte a přihlaste se ke Claude, abyste dokončili jeho připojení. Připojení zkontrolujete spuštěním `/chrome` v Claude. Firefox a Zen toto rozšíření nepodporují. Pokud už byl Claude vaším výchozím agentem před přidáním tohoto nastavení, vyberte ho znovu, aby se rozšíření nainstalovalo.

Jakmile si vyberete, `Super + Shift + Ctrl + A` spustí výchozího agenta ve vyhrazeném okně terminálu (nebo zobrazí výběr, pokud jste si ještě nevybrali). Můžete ho také spustit rovnou do úkolu příkazem `omarchy agent prompt "Review this project"`. Freebuff a DeepSeek Harness nepřijímají žádný počáteční prompt, takže se místo toho otevřou s promptem ve schránce, abyste ho mohli vložit. Takto spuštění agenti běží bez dohledu ve svých příslušných režimech, v nichž se nezastavují, aby se zeptali, takže buďte připraveni, že budou skutečně něco dělat! MiniMax Code žádný takový režim pro své interaktivní relace nemá, takže žádá o oprávnění jako obvykle. A protože agenti odmítají zapamatovat si důvěru pro váš domovský adresář, spuštění z `$HOME` místo toho začínají v `~/Work`.

Existují i zkratky v terminálu: `a` spustí výchozího agenta inline v aktuálním terminálu, zatímco `c`, `cx` a `cy` spustí přímo OpenCode, Claude Code a Codex (opět v jejich režimech automatického schvalování). Změny motivu se synchronizují i do agentů: Claude Code, Pi, OpenCode a Hermes (jakmile ho Omarchy nainstaluje) se všechny přizpůsobí, když přepnete motiv Omarchy.

### Panel agentů

Horní lišta má ikonu agentů. Než si agenta nastavíte, její panel vás provede přihlášením ke Claude, Codex nebo Grok a první z nich se stane vaším výchozím agentem. Poté panel umístí každé předplatné na jednu stránku: každého agenta a účet s jeho plánem, měřič pro každý z jeho 5hodinových limitů relace a týdenních limitů s časem do jejich resetování (přesnou procentní hodnotu zobrazíte najetím), nebo zbývající předplacený zůstatek, pod řádkem, který střídá, co jste u všech dohromady využili, například tokeny za tento týden a váš nejpoužívanější model. V části _Make something_ nabízí úvodní prompty pro nový motiv, plugin nebo aplikaci, které úkol předají vašemu výchozímu agentovi. Aplikace se vytvářejí stejným způsobem jako vlastní aplikace Omarchy Hype, Monologue a Omacut, v C++ a Qt Quick, podle skillu agenta omarchy-app, a kompilátor a součásti Qt, které potřebují, jsou nainstalované. Claude Code, Codex, Grok, Kimi, Cursor a jeho příděl Grok Bot, GitHub Copilot, Muse, Antigravity, Kimchi a Devin jsou pokryty hned po instalaci i se svými limity a Hermes, Mistral Vibe a Qwen Code zobrazí své relace a tokeny, jakmile je použijete. Objeví se i plány a klíče poskytovatelů, které používáte prostřednictvím pi, omp nebo opencode: OpenCode Zen a Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan a Synthetic se svými limity; Fireworks, OpenRouter a DeepSeek se svými předplacenými zůstatky; a modely, které provozujete na vlastním hardwaru, v části Local models. Každý agent se počítá jednou, u toho, kdo ho účtuje, bez ohledu na to, přes kolik harnessů ho ovládáte.

Levé kliknutí na ikonu v liště zobrazí panel, pravé kliknutí spustí vašeho výchozího agenta. Záznamy o využití, které za ním stojí, se každých 15 minut znovu generují příkazem `omarchy agent usage-update` a panel dokonce dokáže sloučit využití z vašich dalších strojů prostřednictvím synchronizované složky. Úplné nastavení najdete v README v `$OMARCHY_PATH/shell/plugins/agents/`.

### Několik předplatných

Pokud platíte za více než jeden plán Claude, Codex nebo Grok — například osobní Max a pracovní — Omarchy je může udržet všechny přihlášené a přepínat mezi nimi. Předplatné přidáte tlačítkem + v panelu agentů, které vás tím provede přímo tam, nebo příkazem `omarchy agent account add claude Work` (nebo `codex`, nebo `grok`). Pokud CLI chybí, nainstaluje ho. První účet u poskytovatele se přihlašuje přes váš běžný prohlížeč, přesně tam, kde to CLI vždy hledá. Každý další se přihlašuje přes soukromé okno, aby se omylem nevybral účet, ke kterému je váš prohlížeč už přihlášený; přihlaste se tam jako účet, který přidáváte, a nejprve zavřete všechna soukromá okna, která už máte otevřená. Nikdy se kvůli tomu neodhlasujte z CLI: odhlášení zruší uložené přihlášení a tento účet by se musel přidat znovu.

Chcete-li zkopírovat přihlášení k předplatným na jiný stroj s Omarchy přes SSH, spusťte `omarchy agent account copy user@laptop`. Odesílatel poskytne dočasného příjemce, když ho cíl nemá nainstalovaného, takže starší stroje s Omarchy mohou přijímat účty bez aktualizace. Nainstalovaní příjemci mají přednost. Tím se zkopírují všechna předplatná Claude, Codex a Grok; jejich výběr provedete přidáním názvů poskytovatelů, například `omarchy agent account copy laptop claude`. Názvy účtů a ID příkazů odpovídají zdroji, včetně účtů, které už na cíli existují. Nesouvisející cílové účty dostanou číselnou příponu, pokud se jejich názvy střetávají, a nastavení, skilly, pluginy a historie konverzací zůstávají lokální na každém stroji.

Existující cílové přihlašovací údaje se zachovají. U zdrojového účtu, který už je tam přihlášený, se synchronizuje jeho název, aniž by se nahradily jeho přihlašovací údaje; ostatní účty se přidají vedle něj. Chcete-li nahradit uložené přihlašovací údaje u odpovídajících účtů, použijte `omarchy agent account copy --replace laptop claude` poté, co na cíli ukončíte relace daného účtu. Čerstvý cíl také získá aktivní účet a předvolby přepínání ze zdroje; zavedený cíl si zachová své vlastní.

Přihlašovací údaje cestují přes SSH a ukládají se do soukromých souborů na cíli, takže kopírujte pouze na stroje, kterým důvěřujete. Jde o jednorázovou kopii, ne o průběžnou synchronizaci. Refresh tokeny Codex může jiný stroj rotovat, čímž zkopírované přihlášení zůstane potřebující obnovení; samostatná přihlášení zůstávají nejspolehlivější volbou pro současné použití na několika strojích. Viz [pokyny Codexu k ověřování účtů](https://developers.openai.com/codex/auth/ci-cd-auth).

Jeden účet na poskytovatele je aktivní a každá nová relace začíná jako on: `cx`, `cy`, prosté `claude`, `codex` nebo `grok`, cokoli spuštěného prostřednictvím `omarchy agent` a skripty nebo editory, které najdou CLI na `PATH`. Přepněte příkazem `omarchy agent account use work` (a zpět příkazem `omarchy agent account use main`) nebo v panelu stisknutím čísla účtu a poté `Enter` (nebo kliknutím na jeho tlačítko Use). Relace, které už běží, zůstávají na účtu, se kterým začaly. Historie konverzací, nastavení, skilly a pluginy se sdílejí mezi účty, takže `claude --continue` ve stejné složce naváže tam, kde jste na novém účtu skončili.

Při více účtech panel zobrazuje limity každého účtu vedle sebe, přičemž aktivní je označený. Ve výchozím nastavení vás Omarchy upozorní, když aktivní účet překročí 95 % limitu, a kliknutí na oznámení přepne na účet s největší rezervou. Najetím na řádek účtu v panelu a kliknutím na Autoswitch, které se objeví vedle Use (nebo stisknutím `m`), nebo spuštěním `omarchy agent account mode auto` zajistíte, že se přepne sám; dokud je zapnutý, Autoswitch zaujímá místo Use a opětovné kliknutí na něj se vrátí k upozorňování. Prahovou hodnotu změníte přidáním čísla, například `omarchy agent account mode auto 90`. Pokud jsou všechny účty nad prahovou hodnotou, dozvíte se to jednou spolu s tím, který účet se uvolní jako první. Dokud je aktivní účet do 15 bodů od své prahové hodnoty (80 % ve výchozím nastavení), jeho limity se kontrolují každé tři minuty místo každých 15.

`omarchy agent account list` zobrazí každý účet a jeho nejnovější limity, `omarchy agent account remove work` jeden zapomene a `omarchy agent account rename primary Hey` jeden přejmenuje (nebo klikněte na název účtu v panelu). Tyto příkazy pracují s účty vašeho výchozího agenta; chcete-li dosáhnout na druhého poskytovatele, nejprve ho pojmenujte, například `omarchy agent account use codex side`. Přihlášení, které jste už měli v `~/.claude` nebo `~/.codex`, je účet _Main_ a zůstává tam, kde je. Účet ponechaný bez použití déle než zhruba osm hodin může zobrazovat _Sign-in required_; kliknutím na něj tento účet znovu přihlásíte přímo v panelu, nebo v něm spusťte relaci, která přihlášení obnoví sama. Servery MCP, které jste měli při přidání účtu, se do něj přenesou, ale ty, které později přidáte příkazem `claude mcp add`, se dostanou pouze do účtu, ve kterém jste je přidali. Claude Desktop a nástroje nakonfigurované s absolutní cestou k binárnímu souboru CLI přepnutí nenásledují. Explicitní `CLAUDE_CONFIG_DIR`, `CODEX_HOME` nebo `GROK_HOME` má přednost před vybraným účtem.

### Diagnostika pádů

Omarchy sleduje systemd-coredump kvůli pádům procesů. Když něco segfaultuje, zobrazí se vám oznámení „Process crashed“ — klikněte na něj a pád se předá vašemu výchozímu agentovi spolu se skillem diagnose-crash od Omarchy, který agenta provede zjištěním faktů z core dumpu a rozhodnutím, zda pád stojí za to nahlásit upstreamu. Můžete ho také spustit ručně proti libovolnému PID z `coredumpctl list` příkazem `omarchy agent crash <pid>`.

Sledování je ve výchozím nastavení zapnuté. Vypněte ho v _Trigger > Toggle > Crash Capture_ (nebo příkazem `omarchy toggle crash-capture`) a oznámení přestanou; `omarchy agent crash <pid>` ručně stále funguje.

Pády lze také ztišit po jednom programu, což vám diagnostika na konci nabídne. `omarchy crash mute hyprland` zastaví oznámení pouze pro tento program, `omarchy crash mute hyprland off` je přivede zpět a samotné `omarchy crash mute` vypíše, co jste ztišili. Přijímá cestu k binárnímu souboru stejně ochotně jako jeho název, takže `omarchy crash mute /usr/bin/hyprland` udělá totéž. Název s mezerou dejte do uvozovek, například `omarchy crash mute 'Some App'`. Vše ostatní stále upozorňuje a ztišený program stále padá — toto skrývá připomenutí, nic neopravuje.

### Desktopové aplikace

Menu _Install > AI_ obsahuje i několik grafických aplikací AI: desktopovou aplikaci ChatGPT, desktopovou aplikaci Claude (Linux beta od Anthropic s kartami Chat, Cowork a Claude Code), Grok Bot pro chatování s modely xAI, Hermes Desktop, OpenClaw, desktopovou aplikaci Perplexity a T3 Code. Grok Bot je desktopová chatovací aplikace. Kódovacím agentem je příkaz `grok`.

Hermes Desktop je ten, o kterém byste měli vědět, protože stroj má jeden Hermes a ten patří aplikaci: Hermes se instaluje výhradně prostřednictvím aplikace a příkaz `hermes`, který výchozí agent spouští, patří aplikaci. Výběr Hermes jako výchozího agenta nainstaluje totéž co položka _Install > AI_: balíček a runtime Hermes v `~/.hermes` nastavený vlastním instalátorem Hermes, což poprvé trvá několik minut. Tento runtime je ten jediný Hermes, který používají příkaz `hermes` v terminálu, výchozí agent i aplikace, a aktualizuje se sám příkazem `hermes update`, místo aby čekal na vydání Omarchy. Jeho instalace také předá Hermes motiv Omarchy jako skin s názvem `omarchy`, který každé rozhraní Hermes následuje při přepínání motivů; vyberte si jiný v nastavení Appearance v Hermes nebo příkazem `/skin`, pokud byste raději, aby to nedělal, a Omarchy tuto volbu nechá být. Odebrání aplikace v _Remove > AI_ nejprve zavře Hermes, včetně gateway, vezme s sebou tento runtime a zachová vaše chaty, vzpomínky a skilly, které si Hermes sám pro sebe napsal, pokud mu neřeknete jinak: zeptá se, přičemž výchozí odpověď je ne, zda mají odejít i tato data a vaše nastavení připojení.

Desktopovým zážitkem OpenClaw je jeho Control UI, které se otevírá jako webová aplikace podporovaná jeho vlastní lokální gateway. OpenClaw žije v `~/.openclaw` a aktualizuje se sám: použijte tlačítko „Update Gateway“ v Control UI nebo spusťte `openclaw update` a gateway se restartuje na nové verzi. Omarchy vybírá pouze vydání, ze kterého čerstvá instalace začíná. Odebrání OpenClaw v _Remove > AI_ s sebou vezme službu gateway i aplikaci a poté se zeptá, zda má odejít i `~/.openclaw`, protože to obsahuje vaše chaty a přihlašovací údaje spolu se samotným OpenClaw a runtime pluginů, které stahuje; výchozí nastavení ho zachovává a opětovná instalace OpenClaw ho znovu převezme.

T3 Code běží ze svého oficiálního vydání AppImage v `~/.local/share/t3code`, nikoli z balíčku, takže se aktualizuje sám. Při instalaci se zeptá, zda začít na kanálu Stable, nebo Nightly; později to přepnete v nastavení T3 Code. Vaše vlákna a nastavení žijí v `~/.t3` a odebrání T3 Code v _Remove > AI_ je vezme s sebou.

### Lokální modely

Provozujte otevřený model na vlastním stroji pro své kódovací agenty. Vaše prompty a kód zůstávají na stroji; nic odeslaného modelu ho neopustí. Začněte tímto:

```bash
omarchy agent local use best
```

Nebo v panelu agentů v horní liště zvolte + a poté Local AI, které se objeví, když se na tento stroj vejde model. Poprvé se tím nainstaluje Podman, který modely provozuje. Omarchy poté vybere doporučený model pro tento stroj, stáhne ho a spustí. Počítejte se stažením desítek GB a s tím, že po dobu běhu modelu bude využita většina paměti stroje: Flash Next používá se svým plným kontextem 256K asi 100 GiB. Pokud jiné modely drží paměť, kterou potřebuje, nastaví se jako zastavený, připravený ke spuštění, jakmile jeden zastavíte. Model se při odhlášení zastaví; zastavte ho sami, když paměť potřebujete na něco jiného.

`omarchy agent local list` zobrazí možnosti a vysvětlí, proč se některé nevejdou. Chcete-li nastavit jiný, spusťte `omarchy agent local use <recipe>`. Dnes jsou pro stroje Strix Halo se 128 GB k dispozici `qwen3.8-flash-next-halogen` a `qwen3.8-27b-gufo`. Nové recepty a doporučení přicházejí s `omarchy update` prostřednictvím balíčku.

Každý model, který nastavíte, dostane vlastní řádek v panelu agentů vedle vašich předplatných: tlačítko přehrávání ho spustí, pauza ho zastaví a uvolní jeho paměť a tlačítko terminálu na něm otevře vašeho agenta. Několik jich může běžet najednou, když se společně vejdou do paměti; pokud se jeden nevejde, Omarchy řekne, který běžící model zastavit. Řádky přetažením přeřadíte a stisknutím Delete na vybraném řádku model i jeho stažení odeberete.

Z příkazového řádku dělají totéž `omarchy agent local start <recipe>` a `omarchy agent local stop <recipe>`, `omarchy agent local status` zobrazí každý model a `omarchy agent --local` otevře vašeho výchozího agenta na posledním modelu, který jste spustili (pi, pokud váš výchozí agent lokální model použít nedokáže). Připojit se může i libovolný klient kompatibilní s OpenAI: `status` zobrazí adresu každého modelu (první je `http://127.0.0.1:11435/v1`), název receptu je model a klíč je v `~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` smaže model a stažení, která žádný jiný model nepoužívá.

Runtime třetích stran jsou označeny svým vydavatelem. Omarchy provozuje každý model bez přístupu k síti.

### Lokální LLM

Omarchy doporučuje dva způsoby provozování lokálních modelů LLM: LM Studio a Ollama. LM Studio poskytuje GUI pro hledání modelů s otevřenými váhami, jejich instalaci a provozování. Je to skvělý způsob, jak snadno začít. Ollama nabízí CLI, které to dělá podobně. Ale pokud s lokálními modely začínáte, začal bych s LM Studio. Obojí můžete nainstalovat v _Install > AI_ v Omarchy Menu.

### Skill Omarchy

Skilly agentů pomáhají AI používat konkrétní nástroje konkrétním způsobem a Omarchy dodává výchozí skill pro přizpůsobení systému. Jako je úprava konfigurace Hyprland, nastavení lišty nebo dokonce vytvoření nového motivu od nuly. Je symlinkován do adresářů skillů pro Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` a každý `~/.hermes/profiles/*/skills`) a do obecného umístění `~/.agents/skills`, takže ho většina harnessů převezme automaticky.

Tento skill byste však měli považovat za experimentální. Různé modely ho budou používat s různým účinkem. Nejlepší je nejprve běžet v režimu plánování, abyste měli představu, co by agent chtěl změnit. A pak buďte připraveni změny vrátit zpět nebo dokonce spustit `omarchy reinstall configs`, pokud agent všechno zpacká.
