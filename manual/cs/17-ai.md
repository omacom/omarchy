# AI

Omarchy obsahuje spouštěče pro níže uvedené kódovací agenty, aniž by za vás vybírala výchozího. Spuštěním příkazu při prvním použití nainstalujete jeho CLI a poté se na výzvu ověříte. Hermes a OpenClaw jsou výjimky: přes mise se pro ně nic neinstaluje a výběr kteréhokoli z nich nastaví jeho vlastní samoaktualizační kopii, jak vysvětlují _Desktopové aplikace_ níže.

### Instalace a aktualizace agentů

Kromě Hermes a OpenClaw používají tito agenti línou instalaci přes mise: první spuštění nainstaluje CLI a pozdější spuštění ho znovu použijí. mise také nejvýše jednou za čtyři hodiny zkontroluje, zda pro nainstalovaného agenta nevyšla nová verze, těsně před jeho spuštěním nebo na pozadí při promptu shellu. Pokud tato aktualizace selže nebo jste offline, spustí se nainstalovaná verze. `omarchy update` aktualizuje nainstalované agenty spolu se zbytkem Omarchy a `mup` aktualizuje pouze nástroje spravované přes mise.

Vlastní aktualizátor agenta, například `claude update`, `codex update` nebo tlačítko aktualizace v aplikaci, neaktualizuje instalaci spravovanou přes mise. `codex update` selže a `claude update` může hlásit úspěch, přičemž nainstaluje samostatnou kopii, kterou mise nesleduje. Pokud raději chcete používat nativní instalátor a aktualizátor agenta, přidejte ho do `disable_tools`; viz [Předinstalované CLI nástroje](18-development-tools.md#preinstalled-cli-tools).

Chcete-li nainstalovat všechny nakonfigurované líné nástroje dříve, než je budete potřebovat, spusťte `mise install --include-lazy`. To zahrnuje i ostatní výchozí CLI nástroje Omarchy i agenty. Viz [Předinstalované CLI nástroje](18-development-tools.md#preinstalled-cli-tools) pro instalaci jednoho nástroje nebo použití vlastní instalace.

`grok` se instaluje prostřednictvím first-party balíčku `grok` od mise, stejně jako `claude` a `codex`. Spusťte `grok` nebo ho vyberte pod _Agent > Harness_. Přeskočte instalátor `curl | bash` na x.ai. Tato cesta umístí druhou kopii do `~/.grok/bin`, přidá ji na začátek `PATH` a přepíše wrapper Omarchy.

`dsh` otevře své prohlížečové UI na `127.0.0.1:3080`, přičemž adresář spuštění je jeho výchozím pracovním prostorem. Jeho prohlížečové UI nepřijímá žádný počáteční prompt, takže `omarchy agent prompt` ho otevře s promptem ve vaší schránce k vložení. Omarchy ho spouští s předvolbou oprávnění bez schvalování od DeepSeeku. DeepSeek Harness nahrává logy relací k DeepSeeku, když používáte jeho oficiální API modelů; vypněte to pod _Settings > General > Upload Session Log_ v jeho prohlížečovém UI. Zpětná vazba, kterou mu pošlete, se nahraje spolu s relací také, pokud ho nespustíte s `DSH_TELEMETRY_MODE=DISABLED`.

### Výchozí agent

Vyberte si výchozího agenta pomocí `omarchy default agent <name>` nebo pod _Agent > Harness_ v Omarchy Menu (`Super + Space`). Pokud agent ještě není nainstalovaný, jeho výběr ho nejprve nainstaluje a také dostane vlastní spouštěč ve spouštěči aplikací, vedle položky Agent. Čerstvá instalace Omarchy vás k tomuto výběru vyzve jednorázovým oznámením.

Výběr Claude se také pokusí nastavit jeho rozšíření prohlížeče pro Chromium, Chrome, Brave, Brave Origin a Edge. Nastavení rozšíření platí pro všechny uživatele a může vyžadovat vaše systémové heslo; zrušení nebo neúspěšná instalace rozšíření přesto Claude vybere a spustí. Restartujte prohlížeč, povolte rozšíření, pokud k tomu budete vyzváni, a přihlaste se do Claude, abyste dokončili jeho připojení. Spusťte `/chrome` v Claude pro kontrolu připojení. Firefox a Zen toto rozšíření nepodporují. Pokud byl Claude vaším výchozím agentem již před přidáním tohoto nastavení, vyberte ho znovu, abyste rozšíření nainstalovali.

Jakmile si vyberete, `Super + Shift + Ctrl + A` spustí výchozího agenta ve vyhrazeném okně terminálu (nebo zobrazí výběr, pokud jste si ještě nevybrali). Můžete ho také spustit rovnou do úkolu pomocí `omarchy agent prompt "Review this project"`. Freebuff a DeepSeek Harness nepřijímají žádný počáteční prompt, takže se místo toho otevřou s promptem ve vaší schránce k vložení. Takto spuštění agenti běží bez dozoru ve svých příslušných režimech, kdy se nezastavují, aby se zeptali, takže buďte připraveni na to, že budou skutečně něco dělat! MiniMax Code takový režim pro své interaktivní relace nemá, takže žádá o oprávnění jako obvykle. A protože agenti odmítají zapamatovat si důvěru pro váš domovský adresář, spuštění z `$HOME` místo toho začínají v `~/Work`.

Existují také zkratky v terminálu: `a` spustí výchozího agenta inline v aktuálním terminálu, zatímco `c`, `cx` a `cy` spustí přímo OpenCode, Claude Code a Codex (opět v jejich režimech automatického schvalování). Změny motivu se synchronizují i do agentů: Claude Code, Pi, OpenCode a Hermes (jakmile ho Omarchy nainstaluje) všichni následují, když přepnete motiv Omarchy.

### Vaše pokyny pro agenty

Osobní pravidla pro každého agenta patří do `~/.agents/AGENTS.md`, vedle sdílených skills v `~/.agents/skills`. Otevřete ho pod _Agent > Instructions_, které ho také propojí do každého harnessu, který si udržuje vlastní globální soubor: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, Copilotův `~/.copilot/copilot-instructions.md` a tak dále. Crush a Amp čtou odkaz `~/.config/AGENTS.md`, zatímco omp, Kimi a DeepSeek Harness čtou přímo `~/.agents/AGENTS.md`. Výběr výchozího agenta ho propojí také. Soubor s pokyny, který jste již měli, se stane sdíleným, pokud ještě žádný neexistoval; jinak je ponechán vedle odkazu jako `.bak`. Po instalaci dalšího agenta spusťte `omarchy agent instructions` pro opětovné propojení.

### Panel agentů

Horní lišta má ikonu agentů. Než si agenta nastavíte, její panel vás provede přihlášením do Claude, Codex nebo Grok a první z nich se stane vaším výchozím agentem. Poté panel umístí každé předplatné na jednu stránku: každý agent a účet se svým plánem, měřič pro každý z jeho 5hodinových limitů relace a týdenních limitů s časem do jeho resetování (přejetím zobrazíte přesné procento), nebo zbývající předplacený zůstatek, pod řádkem, který rotuje tím, co jste použili napříč všemi, jako tokeny tento týden a váš nejpoužívanější model. Pod _Make something cool_ nabízí úvodní prompty pro nový motiv, plugin, aplikaci nebo hru, které předají úkol vašemu výchozímu agentovi. Aplikace se vytvářejí tak, jak se vytvářejí vlastní Hype, Monologue a Omacut od Omarchy, v C++ a Qt Quick, podle agent skillu omarchy-make-app, a kompilátor a části Qt, které potřebují, přicházejí nainstalované. Hry jsou jedna stránka three.js v `~/Games/vibes`, podle agent skillu omarchy-make-game, a všechny se otevírají z jednoho spouštěče Game Vibes v aktuálním motivu; načítají three.js z webu, takže ke spuštění potřebují připojení. Claude Code, Codex, Grok, Kimi, Cursor a jeho příděl Grok Bot, GitHub Copilot, Muse, Antigravity a Devin jsou pokryty hned po instalaci se svými limity, Kimchi se svým plánem, předplacenými kredity a rozpočty útraty, a Hermes, Mistral Vibe a Qwen Code zobrazí své relace a tokeny, jakmile je použijete. Plány poskytovatelů a klíče, které používáte prostřednictvím pi, omp nebo opencode, se také zobrazí: OpenCode Zen a Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan a Synthetic se svými limity; OpenRouter a DeepSeek se svými předplacenými zůstatky; Fireworks se svou útratou za posledních 30 dní. Tokeny z modelů, které provozujete na vlastním hardwaru, se také započítávají do celkových součtů; samotné modely mají vlastní panel, popsaný pod [Místní modely](#local-models). Každý agent se počítá jednou, pod tím, kdo ho účtuje, bez ohledu na to, přes kolik harnessů ho řídíte.

Klikněte levým tlačítkem na ikonu na liště nebo stiskněte `Super + Ctrl + X` pro panel, klikněte pravým tlačítkem pro spuštění výchozího agenta a klikněte prostředním tlačítkem pro obnovení. Záznamy o využití za ním se regenerují každých 15 minut pomocí `omarchy agent usage update` a panel může dokonce sloučit využití z vašich ostatních strojů prostřednictvím synchronizované složky. Viz README pod `$OMARCHY_PATH/shell/plugins/agents/` pro úplná nastavení.

### Několik předplatných

Pokud platíte za více než jeden plán Claude, Codex nebo Grok — například osobní Max a pracovní — Omarchy je může udržet všechny přihlášené a pohybovat se mezi nimi. Přidejte předplatné pomocí + v panelu agentů, které vás tím provede přímo tam, nebo pomocí `omarchy agent account add claude Work` (nebo `codex`, nebo `grok`). Nainstaluje CLI, pokud chybí. První účet pro poskytovatele se přihlašuje přes váš normální prohlížeč, přesně tam, kam CLI vždy hledí. Každý další se přihlašuje přes soukromé okno, takže účet, ke kterému je váš prohlížeč již přihlášen, se omylem nezachytí; přihlaste se tam jako účet, který přidáváte, a nejprve zavřete jakékoli soukromé okno, které již máte otevřené. Nikdy se za tímto účelem neodhlasujte z CLI: odhlášení zruší uložené přihlášení a tento účet by musel být přidán znovu.

Chcete-li zkopírovat přihlášení k předplatnému na jiný stroj Omarchy přes SSH, spusťte `omarchy agent account copy user@laptop`. Odesílatel poskytne dočasného příjemce, když cíl žádného nainstalovaného nemá, takže starší stroje Omarchy mohou přijímat účty bez aktualizace. Nainstalovaní příjemci mají přednost. To zkopíruje všechna předplatná Claude, Codex a Grok; přidejte názvy poskytovatelů, abyste je vybrali, jako v `omarchy agent account copy laptop claude`. Názvy účtů a ID příkazů odpovídají zdroji, včetně účtů již přítomných na cíli. Nesouvisející cílové účty obdrží číselnou příponu, pokud se jejich názvy střetávají, a nastavení, skills, pluginy a historie konverzací zůstávají místní na každém stroji.

Existující cílové přihlašovací údaje zůstanou zachovány. Zdrojový účet, který je tam již přihlášen, má synchronizovaný název, aniž by se nahradily jeho přihlašovací údaje; ostatní účty se přidají vedle něj. Chcete-li nahradit uložené přihlašovací údaje pro odpovídající účty, použijte `omarchy agent account copy --replace laptop claude` po ukončení relací tohoto účtu na cíli. Čerstvý cíl také získá aktivní účet zdroje a preference přepínání; zavedený cíl si ponechá své vlastní.

Přihlašovací údaje cestují přes SSH a ukládají se do soukromých souborů na cíli, takže kopírujte pouze na stroje, kterým důvěřujete. Jedná se o jednorázovou kopii, nikoli o průběžnou synchronizaci. Refresh tokeny Codexu mohou být rotovány jiným strojem, takže zkopírované přihlášení bude potřebovat obnovení; samostatná přihlášení zůstávají nejspolehlivější volbou pro současné použití na několika strojích. Viz [Pokyny k ověřování účtů Codexu](https://developers.openai.com/codex/auth/ci-cd-auth).

Jeden účet na poskytovatele je aktivní a každá nová relace začíná jako on: `cx`, `cy`, prostý `claude`, `codex` nebo `grok`, cokoli spuštěného prostřednictvím `omarchy agent` a skripty nebo editory, které najdou CLI na `PATH`. Přepněte pomocí `omarchy agent account use work` (a zpět pomocí `omarchy agent account use main`) nebo v panelu stisknutím čísla účtu a poté `Enter` (nebo kliknutím na jeho tlačítko Use). Běžící relace Claude se také přepnou, od jejich další zprávy: každá relace Claude běží v `~/.claude`, který vždy obsahuje přihlášení aktivního účtu. Relace Claude spuštěná ve vlastní složce účtu starší verzí Omarchy si toto přihlášení ponechá, dokud neskončí, takže přepnutí tyto relace pojmenuje a samo se dokončí, jakmile zmizí. Běžící relace Codex a Grok zůstávají na účtu, se kterým začaly. Historie konverzací, nastavení, skills a pluginy se sdílejí napříč účty, takže `claude --continue` ve stejné složce pokračuje tam, kde jste na novém účtu skončili.

S více než jedním účtem panel zobrazuje limity každého účtu vedle sebe, s označeným aktivním účtem. Ve výchozím nastavení vás Omarchy upozorní, když aktivní účet překročí 95 % limitu, a kliknutí na oznámení přepne na účet s největším prostorem. Přejeďte přes řádek účtu v panelu a klikněte na Autoswitch, které se objeví vedle Use (nebo stiskněte `m`), nebo spusťte `omarchy agent account mode auto`, aby se přepínal sám; když je zapnutý, Autoswitch zaujme místo Use a opětovným kliknutím se vrátíte k upozorňování. Přidejte číslo pro změnu prahu, jako v `omarchy agent account mode auto 90`. Pokud je každý účet nad prahem, uslyšíte o tom jednou, spolu s tím, který účet se uvolní jako první. Když je aktivní účet do 15 bodů od svého prahu (80 % ve výchozím nastavení), jeho limity se kontrolují každé tři minuty místo každých 15.

`omarchy agent account list` zobrazí každý účet a jeho nejnovější limity, `omarchy agent account remove work` jeden zapomene a `omarchy agent account rename primary Hey` jeden přejmenuje (nebo klikněte na název účtu v panelu). Tyto příkazy pracují s účty vašeho výchozího agenta; chcete-li dosáhnout na jiného poskytovatele, nejprve ho pojmenujte, jako v `omarchy agent account use codex side`. Přihlášení, které jste již měli v `~/.claude` nebo `~/.codex`, je účet _Main_. Codexovo zůstává tam, kde je; Claudeovo čeká ve vlastní složce, zatímco je aktivní jiný účet. Účet ponechaný bez použití déle než asi osm hodin může zobrazit _Sign-in required_; klikněte na něj, abyste tento účet znovu přihlásili přímo v panelu, nebo na něj přepněte a spusťte relaci, která přihlášení obnoví sama. Servery MCP, které přidáte pomocí `claude mcp add`, dosáhnou na každý účet Claude, protože všechny běží v `~/.claude`; pro Codex a Grok servery, které jste měli, když byl účet přidán, přijdou spolu s ním, ale pozdější dosáhnou pouze na účet, ve kterém jste je přidali. Claude Desktop si udržuje vlastní přihlášení a nástroje Codex nebo Grok nakonfigurované s absolutní cestou k binárce CLI přepnutí nenásledují. Explicitní `CLAUDE_CONFIG_DIR`, `CODEX_HOME` nebo `GROK_HOME` má přednost před vybraným účtem.

### Diagnostika pádů

Omarchy sleduje systemd-coredump kvůli pádům procesů. Jakmile si vyberete výchozího agenta, jakýkoli váš program, který vypíše core, přinese oznámení "Process crashed" — klikněte na něj a pád se předá vašemu výchozímu agentovi spolu se skillem omarchy-diagnose-crash od Omarchy, který agenta provede zjištěním faktů z core dumpu a rozhodnutím, zda pád stojí za nahlášení upstreamu. Můžete ho také spustit ručně proti libovolnému PID z `coredumpctl list` pomocí `omarchy agent crash <pid>`.

Sledování je ve výchozím nastavení zapnuté. Vypněte ho pod _Trigger > Toggle > Crash Capture Off_ (nebo pomocí `omarchy toggle crash-capture`) a oznámení přestanou; `omarchy agent crash <pid>` ručně stále funguje.

Pády lze také umlčet jeden program po druhém, což vám diagnostika na konci nabídne. `omarchy crash mute hyprland` zastaví oznámení pouze pro tento program, `omarchy crash mute hyprland off` je přivede zpět a `omarchy crash mute` samo o sobě vypíše, co jste umlčeli. Přijímá cestu k binárce stejně ochotně jako její název, takže `omarchy crash mute /usr/bin/hyprland` dělá totéž. Název s mezerou dejte do uvozovek, jako v `omarchy crash mute 'Some App'`. Všechno ostatní stále upozorňuje a umlčený program stále padá — to skrývá připomenutí, nic to neopravuje.

### Desktopové aplikace

Nabídka _Install > AI_ také obsahuje několik grafických AI aplikací: Amp Desktop, Antigravity Desktop, desktopovou aplikaci ChatGPT, desktopovou aplikaci Claude (linuxová beta od Anthropic, s kartami Chat, Cowork a Claude Code), Grok Bot pro chatování s modely xAI, Herdr Desktop, Hermes Desktop, OpenClaw, desktopovou aplikaci Perplexity a T3 Code. Grok Bot je desktopová chatovací aplikace. Kódovací agent je příkaz `grok`.

Hermes Desktop je ten, o kterém je třeba vědět, protože stroj má jeden Hermes a ten patří aplikaci: Hermes se instaluje pouze prostřednictvím aplikace a příkaz `hermes`, který výchozí agent spouští, patří aplikaci. Výběr Hermes jako výchozího agenta nainstaluje totéž, co položka _Install > AI_: balíček a runtime Hermes pod `~/.hermes` nastavený vlastním instalátorem Hermes, což poprvé trvá několik minut. Tento runtime je ten jeden Hermes, který používají terminálový příkaz `hermes`, výchozí agent i aplikace, a aktualizuje se sám pomocí `hermes update`, místo aby čekal na vydání Omarchy. Jeho instalace také předá Hermes motiv Omarchy jako skin pojmenovaný `omarchy`, který každá plocha Hermes následuje, když přepínáte motivy; vyberte jiný v nastavení Appearance v Hermes nebo pomocí `/skin`, pokud raději chcete, aby to nedělal, a Omarchy tuto volbu nechá být. Odebrání aplikace pod _Remove > AI_ nejprve zavře Hermes, včetně brány, vezme s sebou tento runtime a ponechá vaše chaty, vzpomínky a skills, které si Hermes sám pro sebe napsal, pokud neřeknete jinak: zeptá se, ve výchozím nastavení ne, zda by tato data a vaše nastavení připojení měla také odejít.

Desktopovým zážitkem OpenClaw je jeho Control UI, které se otevírá jako webová aplikace podporovaná vlastní místní bránou. OpenClaw žije v `~/.openclaw` a aktualizuje se sám: použijte tlačítko "Update Gateway" v Control UI nebo spusťte `openclaw update` a brána se restartuje na nové verzi. Omarchy pouze vybírá vydání, ze kterého čerstvá instalace začíná. OpenClaw může být také vaším výchozím agentem: jeho výběr pod _Agent > Harness_ nastaví tutéž kopii v `~/.openclaw` a agent otevře terminálové UI OpenClaw připojené k jeho bráně. Odebrání OpenClaw pod _Remove > AI_ vezme s sebou službu brány i aplikaci a poté se zeptá, zda by `~/.openclaw` mělo také odejít, protože to obsahuje vaše chaty a přihlašovací údaje vedle samotného OpenClaw a runtime pluginů, které stahuje; ve výchozím nastavení si ho ponechá a opětovná instalace OpenClaw ho zase zachytí.

Herdr Desktop je desktopová aplikace [Herdr](https://herdr.dev): prostory, karty a panely terminálů a kódovacích agentů, které dál běží v jeho jádru, když zavřete okno. Pochází z vlastního instalátoru Herdr místo z balíčku, takže žije v `~/.local/share/herdr-app`, přináší své jádro v `~/.local/bin/herdr-core`, když ještě žádné nemáte, a aktualizuje obojí sám. Sedí vedle příkazu `herdr`, který Omarchy dodává na `Super + Ctrl + Return`, spíše než aby ho nahrazoval, a získává přímé klávesy tohoto příkazu: `Alt + Return` a `Alt + Shift + Return` rozdělí panel dolů nebo doprava, `Alt + Escape` ho zavře, `Ctrl + Alt + Arrow` se pohybuje mezi panely, `Alt + 1..9` a `Alt + Left/Right` vybírají kartu a `Alt + Up/Down` se pohybují mezi prostory. `Ctrl + 1..9` vybírá prostor a `Alt + Shift + Up/Down` prochází agenty. Klávesy s prefixem `Ctrl + Space` zůstávají pouze pro terminál, protože aplikace nemůže podržet prostou klávesu Ctrl pro sekvenci. Omarchy je zapisuje do `~/.config/herdr-app/keys.json` a `omarchy-refresh-herdr-app` je vrátí zpět. Jeho instalace vybere motiv Omarchy pro Herdr, který od té doby následuje váš motiv Omarchy. Herdr si udržuje jeden motiv pro světlý režim a jeden pro tmavý, takže po přepnutí mezi tmavým a světlým motivem Omarchy vyberte Omarchy v nástroji pro výběr motivu Herdr ještě jednou pro druhý režim.

T3 Code běží z oficiálního vydání AppImage v `~/.local/share/t3code` místo z balíčku, takže se aktualizuje sám. Jeho instalace se zeptá, zda začít na kanálu Stable nebo Nightly; později přepněte v nastavení T3 Code. Vaše vlákna a nastavení žijí v `~/.t3` a odebrání T3 Code pod _Remove > AI_ je vezme s sebou.

### Místní modely

Spusťte otevřený model na vlastním stroji pro své kódovací agenty. Vaše prompty a kód zůstávají na stroji; nic odeslaného modelu ho neopustí. Začněte s:

```bash
omarchy models use best text
```

To nastaví nejlepší textový model pro tento stroj, ten druh, který vaši agenti používají. Modely obrázků, videa a hudby mají svůj vlastní nejlepší: `omarchy models use best image`, `video` nebo `music`. Spusťte `omarchy models use best`, abyste viděli výběr každého druhu pro tento stroj.

Nebo otevřete panel místních modelů z jeho ikony jisker v horní liště, vedle ikony agentů, nebo pomocí Super + Ctrl + Alt + X, a zvolte +. Ikona se zobrazí, když se model vejde na tento stroj. Podman, který modely spouští, je součástí Omarchy, stejně jako toolkit kontejnerů NVIDIA na stroji NVIDIA, který jim dává GPU; pokud některý chybí, první nastavení ho nainstaluje. Omarchy poté vybere doporučený model pro tento stroj, stáhne ho a spustí. Očekávejte stažení desítek GB a to, že většina paměti stroje bude během běhu modelu využita: Flash Next používá asi 100 GiB se svým plným kontextem 256K. Pokud jiné modely drží paměť, kterou potřebuje, nastaví se zastavený, připravený ke spuštění, jakmile jeden zastavíte. Model se zastaví při odhlášení; zastavte ho sami, když paměť potřebujete na něco jiného.

`omarchy models list` zobrazí možnosti a vysvětlí, proč se některé nevejdou. Chcete-li nastavit jiný, spusťte `omarchy models use <recipe>`. Dnes jsou pro stroje Strix Halo se 128 GB k dispozici `qwen3.8-flash-next-gufo` a `qwen3.8-27b-gufo`; 27B zabírá asi 40 GiB, takže nechává prostor pro jinou práci. Na 64GB laptopu s Intel Arc B390 běží `qwen3.6-35b-a3b-llamacpp` v asi 30 GiB. Nové recepty a doporučení přicházejí s `omarchy update`, prostřednictvím balíčku.

Každý model, který nastavíte, dostane vlastní řádek v panelu místních modelů: play pro spuštění, pause pro zastavení a uvolnění jeho paměti a tlačítko terminálu pro otevření agenta na něm. Přes horní část lišta ukazuje, jak je paměť stroje rozdělena mezi samotnou Omarchy (systém a vaše aplikace), každý běžící model a co je volné. Ukažte na zastavený model a lišta ukáže, zda se vejde, nebo o kolik mu chybí. Několik jich může běžet najednou, když se společně vejdou do paměti; pokud se jeden nevejde, Omarchy řekne, který běžící model zastavit. Přetáhněte řádky podle jejich loga pro změnu pořadí a stiskněte Delete na vybraném řádku pro odebrání modelu a jeho stažení.

Každý model, který nastavíte, také dostane vlastní položku ve spouštěči aplikací, pod názvem modelu a s logem jeho tvůrce, stejně jako přihlášení do Claude, Codex nebo Grok jednu přidá. Otevře vašeho agenta na tomto modelu a nejprve model spustí, pokud neběží: terminál ukáže jeho načítání a předá agentovi, jakmile bude připraven. Odebrání modelu odebere jeho položku.

Ne každý model je pro kódování. Modely obrázků, videa a hudby se místo toho otevírají ve Fantasi, aplikaci Omarchy pro vytváření obrázků, videa a hudby s modelem běžícím na tomto stroji, z jejich položky ve spouštěči a z jejich řádku v panelu místních modelů.

Model dál běží přesně tak, jak byl nastaven, takže aktualizace Omarchy nikdy žádný nerestartuje pod vašimi agenty. Když má Omarchy novější runtime nebo novější váhy pro model, který jste nastavili, jeho řádek zobrazí tlačítko aktualizace: stiskněte ho a model se znovu nastaví na pozadí, stáhne pouze to, co se změnilo, a restartuje na nové verzi. Model, který byl zastaven, zůstane zastaven. `omarchy models update` dělá totéž pro každý model z terminálu.

Z příkazového řádku dělají totéž `omarchy models start <recipe>` a `omarchy models stop <recipe>`, `omarchy models status` zobrazí každý model a `omarchy agent --local` otevře vašeho výchozího agenta na posledním modelu, který jste spustili. pi, OpenCode a Qwen Code jeden mohou použít; s jakýmkoli jiným výchozím agentem se otevře v pi, nebo v OpenCode, pokud pi nemáte. pi také vypíše každý model, který jste nastavili, a ty na strojích, se kterými jste se spárovali, ve svém vlastním nástroji pro výběr modelu, takže je prosté `pi` také dosáhne. Připojit se může i jakýkoli klient kompatibilní s OpenAI: `status` zobrazí adresu každého modelu (první je `http://127.0.0.1:11435/v1`), název receptu je model a klíč je v `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` smaže model a stažení, která žádný jiný model nepoužívá.

Runtime třetích stran jsou označeny svým vydavatelem. Omarchy spouští každý model bez přístupu k síti.

### Místní LLM

Omarchy doporučuje dva způsoby provozování místních modelů LLM: LM Studio a Ollama. LM Studio poskytuje GUI rozhraní pro hledání modelů s otevřenými váhami, jejich instalaci a spouštění. Je to skvělý způsob, jak snadno začít. Ollama nabízí CLI pro totéž podobně. Ale pokud jste v místních modelech noví, začal bych s LM Studio. Obojí můžete nainstalovat pod _Install > AI_ v Omarchy Menu.

### Skills Omarchy

Agent skills pomáhají AI používat konkrétní nástroje konkrétním způsobem a Omarchy jich dodává sedm. Skill omarchy pokrývá přizpůsobení systému, jako úpravu vaší konfigurace Hyprland nebo úpravu lišty. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app a omarchy-make-game pokrývají vytváření něčeho nového, omarchy-contribute pokrývá nahlášení chyby nebo odeslání opravy upstreamu a omarchy-diagnose-crash prochází core dump pádu. Jsou propojeny symlinky do adresářů skills pro Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` a každý `~/.hermes/profiles/*/skills`) a obecné umístění `~/.agents/skills`, takže je většina harnessů zachytí automaticky. Složka skillu s vaším vlastním stejným názvem má přednost.

Ale tyto skills byste měli považovat za experimentální. Různé modely je použijí s různým účinkem. Nejlepší je nejprve běžet v režimu plánování, abyste měli představu o tom, co by agent rád změnil. A pak buďte připraveni vrátit změny nebo dokonce vyvolat `omarchy reinstall configs`, pokud agent udělá ze všeho nepořádek.
