# AI

Omarchy obsahuje spouštěče pro níže uvedené kódovací agenty, aniž by za vás vybírala výchozího. Spuštěním příkazu si při prvním použití nainstalujete jeho CLI a poté se po vyzvání přihlásíte. Hermes a OpenClaw jsou výjimky: přes mise se pro ně nic neinstaluje a výběr kteréhokoli z nich nastaví jeho vlastní samoaktualizační kopii, jak níže vysvětlují _Desktopové aplikace_.

### Instalace a aktualizace agentů

S výjimkou Hermes a OpenClaw tito agenti používají línou instalaci přes mise: první spuštění nainstaluje CLI a další spuštění jej znovu použijí. mise také nejvýše jednou za čtyři hodiny zkontroluje, zda pro nainstalovaného agenta nevyšla nová verze, těsně před jeho spuštěním nebo na pozadí při zobrazení promptu shellu. Pokud tato aktualizace selže nebo jste offline, spustí se nainstalovaná verze. `omarchy update` aktualizuje nainstalované agenty spolu se zbytkem Omarchy a `mup` aktualizuje pouze nástroje spravované přes mise.

Vlastní aktualizátor agenta, například `claude update`, `codex update` nebo tlačítko aktualizace v aplikaci, neaktualizuje instalaci spravovanou přes mise. `codex update` selže a `claude update` může nahlásit úspěch a přitom nainstalovat samostatnou kopii, kterou mise nesleduje. Pokud byste raději používali nativní instalátor a aktualizátor agenta, přidejte jej do `disable_tools`; viz [Předinstalované nástroje CLI](18-development-tools.md#preinstalled-cli-tools).

Chcete-li nainstalovat všechny nakonfigurované líné nástroje dříve, než je budete potřebovat, spusťte `mise install --include-lazy`. To zahrnuje i ostatní výchozí nástroje CLI v Omarchy, stejně jako agenty. Informace o instalaci jednoho nástroje nebo použití vlastní instalace najdete v části [Předinstalované nástroje CLI](18-development-tools.md#preinstalled-cli-tools).

`grok` se instaluje prostřednictvím first-party balíčku `grok` v mise, stejně jako `claude` a `codex`. Spusťte `grok` nebo jej vyberte v nabídce _Agent > Harness_. Přeskočte instalátor `curl | bash` na x.ai. Tato cesta umístí druhou kopii do `~/.grok/bin`, vloží ji na začátek `PATH` a přepíše wrapper Omarchy.

`dsh` otevírá své prohlížečové UI na `127.0.0.1:3080`, přičemž spouštěcí adresář je jeho výchozím pracovním prostorem. Jeho prohlížečové UI nepřijímá žádný počáteční prompt, takže `omarchy agent prompt` jej otevře s promptem ve vaší schránce k vložení. Omarchy jej spouští s předvolbou oprávnění DeepSeeku bez schvalování. DeepSeek Harness nahrává protokoly relací společnosti DeepSeek, když používáte její oficiální API pro modely; vypněte to v jeho prohlížečovém UI v části _Settings > General > Upload Session Log_. Zpětná vazba, kterou mu odešlete, se nahraje spolu s relací také, pokud jej nespustíte s `DSH_TELEMETRY_MODE=DISABLED`.

### Výchozí agent

Vyberte si výchozího agenta pomocí `omarchy default agent <name>` nebo v části _Agent > Harness_ v Omarchy Menu (`Super + Space`). Pokud agent ještě není nainstalován, jeho výběrem se nejprve nainstaluje a také získá vlastní spouštěč ve spouštěči aplikací vedle položky Agent. Čerstvá instalace Omarchy vás k tomuto výběru vyzve jednorázovým oznámením.

Výběr Claude se také pokusí nastavit jeho rozšíření prohlížeče pro Chromium, Chrome, Brave, Brave Origin a Edge. Nastavení rozšíření platí pro všechny uživatele a může vyžadovat vaše systémové heslo; zrušení nebo neúspěšná instalace rozšíření přesto Claude vybere a spustí. Restartujte prohlížeč, po vyzvání rozšíření povolte a přihlaste se do Claude, abyste dokončili jeho připojení. Připojení zkontrolujte spuštěním `/chrome` v Claude. Firefox a Zen toto rozšíření nepodporují. Pokud byl Claude vaším výchozím agentem již před přidáním tohoto nastavení, vyberte jej znovu, abyste rozšíření nainstalovali.

Jakmile si vyberete, `Super + Shift + Ctrl + A` spustí výchozího agenta ve vyhrazeném okně terminálu (nebo zobrazí výběr, pokud jste si ještě nevybrali). Můžete jej také spustit rovnou do úkolu pomocí `omarchy agent prompt "Review this project"`. Freebuff a DeepSeek Harness nepřijímají žádný počáteční prompt, takže se místo toho otevřou s promptem ve vaší schránce k vložení. Takto spuštění agenti běží bez dohledu ve svých příslušných režimech, kdy se nepřestávají ptát, takže buďte připraveni na to, že budou skutečně něco dělat! MiniMax Code takový režim pro své interaktivní relace nemá, takže žádá o oprávnění jako obvykle. A protože agenti odmítají zapamatovat si důvěru pro váš domovský adresář, spuštění z `$HOME` místo toho začínají v `~/Work`.

K dispozici jsou také zkratky v terminálu: `a` spustí výchozího agenta inline v aktuálním terminálu, zatímco `c`, `cx` a `cy` spustí přímo OpenCode, Claude Code a Codex (opět v jejich režimech automatického schvalování). Změny motivu se synchronizují i do agentů: Claude Code, Pi, OpenCode a Hermes (jakmile jej Omarchy nainstaluje) následují, když přepnete motiv Omarchy.

### Vaše pokyny pro agenty

Osobní pravidla pro každého agenta patří do `~/.agents/AGENTS.md`, vedle sdílených skillů v `~/.agents/skills`. Otevřete jej v části _Agent > Instructions_, která jej také propojí do každého harnessu, který si udržuje vlastní globální soubor: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` pro Copilot a tak dále. Crush a Amp čtou odkaz `~/.config/AGENTS.md`, zatímco omp, Kimi a DeepSeek Harness čtou přímo `~/.agents/AGENTS.md`. Výběr výchozího agenta jej také propojí. Soubor s pokyny, který jste již měli, se stane sdíleným, pokud ještě žádný neexistoval; jinak je uchován vedle odkazu jako `.bak`. Po instalaci dalšího agenta spusťte `omarchy agent instructions`, abyste propojení obnovili.

### Panel agentů

Horní lišta má ikonu agentů. Než si agenta nastavíte, její panel vás provede přihlášením do Claude, Codex nebo Grok a první z nich se stane vaším výchozím agentem. Poté panel umístí každé předplatné na jednu stránku: každého agenta a účet s jeho plánem, měřič pro každý z jeho 5hodinových limitů relací a týdenních limitů s časem do jeho resetování (přesnou procentní hodnotu zobrazíte najetím), nebo zbývající předplacený zůstatek, pod řádkem, který se střídá v tom, co jste použili napříč všemi, například tokeny za tento týden a váš nejpoužívanější model. V části _Make something cool_ nabízí úvodní prompty pro nový motiv, plugin, aplikaci nebo hru, které úkol předají vašemu výchozímu agentovi. Aplikace se vytvářejí stejným způsobem jako vlastní aplikace Omarchy Hype, Monologue a Omacut, v C++ a Qt Quick, podle agent skillu omarchy-make-app, a kompilátor a součásti Qt, které potřebují, přicházejí nainstalované. Hry jsou jedna stránka three.js v `~/Games/vibes`, podle agent skillu omarchy-make-game, a všechny se otevírají z jednoho spouštěče Game Vibes v aktuálním motivu; načítají three.js z webu, takže ke spuštění potřebují připojení. Claude Code, Codex, Grok, Kimi, Cursor a jeho příděl Grok Bot, GitHub Copilot, Muse, Antigravity a Devin jsou pokryty hned po vybalení se svými limity, Kimchi se svým plánem, předplacenými kredity a rozpočty útraty a Hermes, Mistral Vibe a Qwen Code zobrazují své relace a tokeny, jakmile je použijete. Plány poskytovatelů a klíče, které používáte prostřednictvím pi, omp nebo opencode, se také zobrazují: OpenCode Zen a Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan a Synthetic se svými limity; OpenRouter a DeepSeek se svými předplacenými zůstatky; Fireworks se svou útratou za posledních 30 dní. Tokeny z modelů, které spouštíte na vlastním hardwaru, se započítávají do celkových součtů také; samotné modely mají vlastní panel, popsaný v části [Lokální modely](#local-models). Každý agent se započítává jednou, u toho, kdo jej účtuje, bez ohledu na to, přes kolik harnessů jej řídíte.

Kliknutím levým tlačítkem na ikonu na liště nebo stisknutím `Super + Ctrl + X` otevřete panel, kliknutím pravým tlačítkem spustíte výchozího agenta a kliknutím prostředním tlačítkem obnovíte. Záznamy o používání, které za ním stojí, každých 15 minut regeneruje `omarchy agent usage update` a panel může dokonce sloučit používání z vašich ostatních počítačů prostřednictvím synchronizované složky. Úplné nastavení najdete v README pod `$OMARCHY_PATH/shell/plugins/agents/`.

### Několik předplatných

Pokud platíte za více než jeden plán Claude, Codex nebo Grok — například osobní Max a pracovní — Omarchy je může udržet všechny přihlášené a pohybovat se mezi nimi. Přidejte předplatné pomocí + v panelu agentů, které vás tím provede přímo tam, nebo pomocí `omarchy agent account add claude Work` (nebo `codex`, nebo `grok`). Pokud chybí, nainstaluje CLI. První účet pro poskytovatele se přihlašuje prostřednictvím vašeho běžného prohlížeče, přesně tam, kam CLI vždy hledí. Každý další se přihlašuje prostřednictvím soukromého okna, takže účet, ke kterému je váš prohlížeč již přihlášen, není omylem zachycen; přihlaste se tam jako účet, který přidáváte, a nejprve zavřete všechna soukromá okna, která jste již měli otevřená. Nikdy se za tímto účelem neodhlasujte z CLI: odhlášení zruší uložené přihlášení a tento účet by bylo nutné přidat znovu.

Chcete-li zkopírovat přihlášení k předplatnému do jiného počítače s Omarchy přes SSH, spusťte `omarchy agent account copy user@laptop`. Odesílatel dodá dočasný přijímač, když cíl žádný nainstalovaný nemá, takže starší počítače s Omarchy mohou přijímat účty bez aktualizace. Nainstalované přijímače mají přednost. To kopíruje všechna předplatná Claude, Codex a Grok; přidejte názvy poskytovatelů, abyste je vybrali, jako v `omarchy agent account copy laptop claude`. Názvy účtů a ID příkazů odpovídají zdroji, včetně účtů již přítomných v cíli. Nesouvisející cílové účty dostanou číselnou příponu, pokud se jejich názvy střetnou, a nastavení, skilly, pluginy a historie konverzací zůstávají lokální na každém počítači.

Stávající cílové přihlašovací údaje se zachovají. Zdrojový účet, který je tam již přihlášen, má synchronizovaný název, aniž by se nahradily jeho přihlašovací údaje; ostatní účty se přidají vedle něj. Chcete-li nahradit uložené přihlašovací údaje pro odpovídající účty, použijte `omarchy agent account copy --replace laptop claude` poté, co ukončíte relace tohoto účtu v cíli. Čerstvý cíl také získá aktivní účet zdroje a předvolby přepínání; zavedený cíl si zachová své vlastní.

Přihlašovací údaje cestují přes SSH a ukládají se do soukromých souborů v cíli, takže kopírujte pouze do počítačů, kterým důvěřujete. Jedná se o jednorázovou kopii, nikoli o průběžnou synchronizaci. Refresh tokeny Codexu může jiný počítač rotovat, takže zkopírované přihlášení bude potřebovat obnovení; samostatná přihlášení zůstávají nejspolehlivější volbou pro současné použití na několika počítačích. Viz [Pokyny Codexu k ověřování účtů](https://developers.openai.com/codex/auth/ci-cd-auth).

Jeden účet na poskytovatele je aktivní a každá nová relace začíná jako on: `cx`, `cy`, prostý `claude`, `codex` nebo `grok`, cokoli spuštěného prostřednictvím `omarchy agent` a skripty nebo editory, které najdou CLI na `PATH`. Přepněte pomocí `omarchy agent account use work` (a zpět pomocí `omarchy agent account use main`) nebo v panelu stisknutím čísla účtu a poté `Enter` (nebo kliknutím na jeho tlačítko Use). Běžící relace Claude se také přepnou, od jejich další zprávy: každá relace Claude běží v `~/.claude`, která vždy obsahuje přihlášení aktivního účtu. Relace Claude spuštěná ve vlastní složce účtu starší verzí Omarchy si toto přihlášení uchová, dokud se neukončí, takže přepínač tyto relace pojmenuje a dokončí se sám, jakmile zmizí. Běžící relace Codex a Grok zůstávají na účtu, se kterým začaly. Historie konverzací, nastavení, skilly a pluginy se sdílejí napříč účty, takže `claude --continue` ve stejné složce naváže tam, kde jste na novém účtu přestali.

S více než jedním účtem panel zobrazuje limity každého účtu vedle sebe, přičemž aktivní je označen. Ve výchozím nastavení vás Omarchy upozorní, když aktivní účet překročí 95 % limitu, a kliknutím na oznámení přepnete na účet s největším prostorem. Najeďte na řádek účtu v panelu a klikněte na Autoswitch, které se objeví vedle Use (nebo stiskněte `m`), nebo spusťte `omarchy agent account mode auto`, aby se přepínalo samo; zatímco je zapnuté, Autoswitch nahradí Use a opětovným kliknutím se vrátíte k upozorňování. Přidejte číslo, abyste změnili práh, jako v `omarchy agent account mode auto 90`. Pokud je každý účet nad prahem, dozvíte se o tom jednou, spolu s tím, který účet se uvolní jako první. Zatímco je aktivní účet do 15 bodů od svého prahu (80 % ve výchozím nastavení), jeho limity se kontrolují každé tři minuty místo každých 15.

`omarchy agent account list` zobrazuje každý účet a jeho nejnovější limity, `omarchy agent account remove work` jeden zapomene a `omarchy agent account rename primary Hey` jeden přejmenuje (nebo klikněte na název účtu v panelu). Tyto příkazy pracují s účty vašeho výchozího agenta; chcete-li dosáhnout na druhého poskytovatele, nejprve jej pojmenujte, jako v `omarchy agent account use codex side`. Přihlášení, které jste již měli v `~/.claude` nebo `~/.codex`, je účet _Main_. Účet Codexu zůstává tam, kde je; účet Claude čeká ve vlastní složce, zatímco je aktivní jiný účet. Účet, který zůstal nepoužívaný déle než přibližně osm hodin, může zobrazovat _Sign-in required_; kliknutím na něj se tento účet znovu přihlásí přímo v panelu, nebo na něj přepněte a spusťte relaci, která přihlášení obnoví sama. Servery MCP, které přidáte pomocí `claude mcp add`, dosáhnou na každý účet Claude, protože všechny běží v `~/.claude`; u Codex a Grok servery, které jste měli, když byl účet přidán, přijdou s ním, ale pozdější dosáhnou pouze na účet, do kterého jste je přidali. Claude Desktop si udržuje vlastní přihlášení a nástroje Codex nebo Grok nakonfigurované s absolutní cestou k binárnímu souboru CLI přepínač nesledují. Explicitní `CLAUDE_CONFIG_DIR`, `CODEX_HOME` nebo `GROK_HOME` má přednost před vybraným účtem.

### Diagnostika pádů

Omarchy sleduje systemd-coredump kvůli pádům procesů. Jakmile si vyberete výchozího agenta, každý váš program, který vytvoří core dump, zobrazí oznámení „Process crashed“ — klikněte na něj a pád se předá vašemu výchozímu agentovi spolu se skillem omarchy-diagnose-crash v Omarchy, který agenta provede zjištěním faktů z core dumpu a rozhodnutím, zda pád stojí za nahlášení upstreamu. Můžete jej také spustit ručně proti libovolnému PID z `coredumpctl list` pomocí `omarchy agent crash <pid>`.

Sledování je ve výchozím nastavení zapnuté. Vypněte jej v části _Trigger > Toggle > Crash Capture Off_ (nebo pomocí `omarchy toggle crash-capture`) a oznámení přestanou; `omarchy agent crash <pid>` stále funguje ručně.

Pády lze také ztlumit po jednotlivých programech, což vám diagnostika nabídne na konci. `omarchy crash mute hyprland` zastaví oznámení pouze pro tento program, `omarchy crash mute hyprland off` je vrátí zpět a `omarchy crash mute` samo o sobě vypíše, co jste ztlumili. Přijímá cestu k binárnímu souboru stejně rádo jako jeho název, takže `omarchy crash mute /usr/bin/hyprland` dělá totéž. Název s mezerou dejte do uvozovek, jako v `omarchy crash mute 'Some App'`. Všechno ostatní stále upozorňuje a ztlumený program stále padá — to skrývá připomenutí, nic to neopravuje.

### Desktopové aplikace

Nabídka _Install > AI_ obsahuje také několik grafických aplikací AI: Amp Desktop, Antigravity Desktop, desktopovou aplikaci ChatGPT, desktopovou aplikaci Claude (linuxová beta od Anthropic, s kartami Chat, Cowork a Claude Code), Grok Bot pro chatování s modely xAI, Herdr Desktop, Hermes Desktop, OpenClaw, desktopovou aplikaci Perplexity a T3 Code. Grok Bot je desktopová chatovací aplikace. Kódovací agent je příkaz `grok`.

Hermes Desktop je ten, o kterém je třeba vědět, protože počítač má jeden Hermes a ten patří aplikaci: Hermes se instaluje pouze prostřednictvím aplikace a příkaz `hermes`, který výchozí agent spouští, patří aplikaci. Výběr Hermes jako výchozího agenta nainstaluje totéž, co položka _Install > AI_: balíček a runtime Hermes v `~/.hermes` nastavený vlastním instalátorem Hermes, což při prvním použití trvá několik minut. Tento runtime je ten jediný Hermes, který používají terminálový příkaz `hermes`, výchozí agent i aplikace, a aktualizuje se sám pomocí `hermes update`, místo aby čekal na vydání Omarchy. Jeho instalace také předá Hermes motiv Omarchy jako skin s názvem `omarchy`, který každé rozhraní Hermes následuje při přepínání motivů; vyberte si jiný v nastavení Appearance v Hermes nebo pomocí `/skin`, pokud byste raději, aby to nedělal, a Omarchy tuto volbu nechá být. Odstranění aplikace v části _Remove > AI_ nejprve zavře Hermes, včetně brány, vezme s sebou tento runtime a zachová vaše chaty, vzpomínky a skilly, které si Hermes sám napsal, pokud neřeknete jinak: zeptá se, výchozí odpověď je ne, zda by tato data a vaše nastavení připojení měla také zmizet.

Desktopovým zážitkem OpenClaw je jeho Control UI, které se otevírá jako webová aplikace podporovaná jeho vlastní lokální bránou. OpenClaw žije v `~/.openclaw` a aktualizuje se sám: použijte tlačítko „Update Gateway“ v Control UI nebo spusťte `openclaw update` a brána se restartuje na nové verzi. Omarchy vybírá pouze vydání, ze kterého čerstvá instalace začíná. OpenClaw může být také vaším výchozím agentem: jeho výběr v části _Agent > Harness_ nastaví tutéž kopii v `~/.openclaw` a agent otevře terminálové UI OpenClaw připojené k jeho bráně. Odstranění OpenClaw v části _Remove > AI_ s sebou vezme službu brány a aplikaci a poté se zeptá, zda by mělo zmizet i `~/.openclaw`, protože to obsahuje vaše chaty a přihlašovací údaje spolu se samotným OpenClaw a runtime pluginů, které stahuje; výchozí nastavení jej zachová a opětovná instalace OpenClaw jej znovu zachytí.

Herdr Desktop je desktopová aplikace [Herdr](https://herdr.dev): prostory, karty a panely terminálů a kódovacích agentů, které dál běží v jejím jádru, když okno zavřete. Pochází z vlastního instalátoru Herdr, nikoli z balíčku, takže žije v `~/.local/share/herdr-app`, přináší své jádro v `~/.local/bin/herdr-core`, když ještě žádné nemáte, a aktualizuje obojí samo. Stojí vedle příkazu `herdr`, který Omarchy dodává na `Super + Ctrl + Return`, spíše než aby jej nahrazovala, a získává přímé klávesy tohoto příkazu: `Alt + Return` a `Alt + Shift + Return` rozdělí panel dolů nebo doprava, `Alt + Escape` jej zavře, `Ctrl + Alt + Arrow` se pohybuje mezi panely, `Alt + 1..9` a `Alt + Left/Right` vybírají kartu a `Alt + Up/Down` se pohybují mezi prostory. `Ctrl + 1..9` vybírá prostor a `Alt + Shift + Up/Down` prochází agenty. Klávesy s prefixem `Ctrl + Space` zůstávají pouze pro terminál, protože aplikace nemůže podržet prostou klávesu Ctrl pro sekvenci. Omarchy je zapisuje do `~/.config/herdr-app/keys.json` a `omarchy-refresh-herdr-app` je vrátí zpět. Jeho instalace vybere motiv Omarchy v Herdr, který od té doby následuje váš motiv Omarchy. Herdr uchovává jeden motiv pro světlý režim a jeden pro tmavý, takže po přepnutí mezi tmavým a světlým motivem Omarchy vyberte Omarchy ve výběru motivu Herdr ještě jednou pro druhý režim.

T3 Code běží z oficiálního vydání AppImage v `~/.local/share/t3code`, nikoli z balíčku, takže se aktualizuje sám. Jeho instalace se zeptá, zda chcete začít na kanálu Stable nebo Nightly; přepněte později v nastavení T3 Code. Vaše vlákna a nastavení žijí v `~/.t3` a odstranění T3 Code v části _Remove > AI_ je vezme s sebou.

### Lokální modely

Spusťte otevřený model na vlastním počítači pro své kódovací agenty. Vaše prompty a kód zůstanou na počítači; nic odeslaného modelu jej neopustí. Začněte s:

```bash
omarchy models use best text
```

To nastaví nejlepší textový model pro tento počítač, ten druh, který vaši agenti používají. Modely pro obrázky, video a hudbu mají každý svůj nejlepší: `omarchy models use best image`, `video` nebo `music`. Spusťte `omarchy models use best`, abyste viděli výběr pro tento počítač pro každý druh.

Nebo otevřete panel lokálních modelů z jeho ikony jisker v horní liště, vedle ikony agentů, nebo pomocí Super + Ctrl + Alt + X, a vyberte +. Ikona se zobrazí, když se na tento počítač vejde model. Podman, který modely spouští, je součástí Omarchy, stejně jako sada nástrojů pro kontejnery NVIDIA na počítači s NVIDIA, která jim poskytuje GPU; pokud cokoli z toho chybí, první nastavení to nainstaluje. Omarchy poté vybere doporučený model pro tento počítač, stáhne jej a spustí. Očekávejte stažení v řádu desítek GB a využití většiny paměti počítače po dobu běhu modelu: Flash Next používá asi 100 GiB s plným kontextem 256K. Pokud jiné modely drží paměť, kterou potřebuje, je nastaven jako zastavený, připravený ke spuštění, jakmile jeden zastavíte. Model se zastaví při odhlášení; zastavte jej sami, když paměť potřebujete na něco jiného.

`omarchy models list` zobrazuje možnosti a vysvětluje, proč se některé nevejdou. Chcete-li nastavit jiný, spusťte `omarchy models use <recipe>`. Dnes jsou pro počítače Strix Halo se 128 GB k dispozici `qwen3.8-flash-next-gufo` a `qwen3.8-27b-gufo`; 27B zabírá asi 40 GiB, takže nechává prostor pro další práci. Na 64GB notebooku s Intel Arc B390 běží `qwen3.6-35b-a3b-llamacpp` v asi 30 GiB. Nové recepty a doporučení přicházejí s `omarchy update`, prostřednictvím balíčku.

Každý model, který nastavíte, získá vlastní řádek v panelu lokálních modelů: tlačítko play jej spustí, pause jej zastaví a uvolní jeho paměť a tlačítko terminálu otevře vašeho agenta na něm. Nahoře lišta ukazuje, jak je paměť počítače rozdělena mezi samotnou Omarchy (systém a vaše aplikace), každý běžící model a volné místo. Najeďte na zastavený model a lišta ukáže, zda se vejde, nebo o kolik mu chybí. Několik jich může běžet najednou, když se společně vejdou do paměti; pokud se jeden nevejde, Omarchy řekne, který běžící model máte zastavit. Přetáhněte řádky za jejich logo, abyste je přeřadili, a stiskněte Delete na vybraném řádku, abyste odstranili model a jeho stažení.

Každý kódovací model, který nastavíte, také získá vlastní položku ve spouštěči aplikací, pod názvem modelu a s logem jeho tvůrce, stejně jako přihlášení do Claude, Codex nebo Grok přidá jednu. Otevře vašeho agenta na tomto modelu a nejprve model spustí, pokud neběží: terminál ukáže jeho načítání a předá řízení agentovi, jakmile bude připraven. Odstranění modelu odstraní jeho položku.

Ne každý model je pro kódování. Modely pro obrázky, video a hudbu se místo toho otevírají ve Fantasi, aplikaci Omarchy pro tvorbu obrázků, videa a hudby s modelem běžícím na tomto počítači, vybraném tam nebo z jejich řádku v panelu lokálních modelů.

Model dál běží přesně tak, jak byl nastaven, takže aktualizace Omarchy nikdy žádný nerestartuje pod vašimi agenty. Když má Omarchy novější runtime nebo novější váhy pro model, který jste nastavili, jeho řádek zobrazí tlačítko aktualizace: stiskněte jej a model se znovu nastaví na pozadí, stáhne pouze to, co se změnilo, a restartuje se na nové verzi. Zastavený model zůstane zastaven. `omarchy models update` dělá totéž pro každý model z terminálu.

Z příkazového řádku `omarchy models start <recipe>` a `omarchy models stop <recipe>` dělají totéž, `omarchy models status` zobrazuje každý model a `omarchy agent --local` otevře poslední model, který jste spustili, v pi, bez ohledu na to, jaký je váš výchozí agent. OpenCode a Qwen Code mohou také používat lokální model: `omarchy models harness opencode` nebo `omarchy models harness qwen` je otevře tam místo toho a `omarchy models harness pi` se vrátí zpět. pi také vypisuje každý model, který jste nastavili, a ty na počítačích, se kterými jste se spárovali, ve svém vlastním výběru modelů, takže prosté `pi` na ně dosáhne také. Připojit se může i každý klient kompatibilní s OpenAI: `status` zobrazuje adresu každého modelu (první je `http://127.0.0.1:11435/v1`), název receptu je model a klíč je v `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` odstraní model a stažení, která žádný jiný model nepoužívá.

Runtime třetích stran jsou označeny svým vydavatelem. Omarchy spouští každý model bez přístupu k síti.

### Lokální LLM

Omarchy doporučuje dva způsoby spouštění lokálních modelů LLM: LM Studio a Ollama. LM Studio poskytuje GUI rozhraní pro vyhledávání modelů s otevřenými váhami, jejich instalaci a spouštění. Je to skvělý způsob, jak snadno začít. Ollama nabízí CLI pro totéž podobným způsobem. Pokud jste ale v lokálních modelech noví, začal bych s LM Studio. Obojí můžete nainstalovat v části _Install > AI_ v Omarchy Menu.

### Skilly Omarchy

Agent skilly pomáhají AI používat konkrétní nástroje konkrétním způsobem a Omarchy jich dodává sedm. Skill omarchy pokrývá přizpůsobení systému, například úpravu konfigurace Hyprland nebo nastavení lišty. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app a omarchy-make-game pokrývají vytváření něčeho nového, omarchy-contribute pokrývá hlášení chyby nebo odeslání opravy upstreamu a omarchy-diagnose-crash prochází core dump pádu. Jsou propojeny symbolickými odkazy do adresářů skillů pro Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` a každý `~/.hermes/profiles/*/skills`) a obecné umístění `~/.agents/skills`, takže je většina harnessů zachytí automaticky. Vlastní složka skillu se stejným názvem má přednost.

Tyto skilly byste ale měli považovat za experimentální. Různé modely jej využijí s různým účinkem. Nejlepší je nejprve běžet v režimu plánování, abyste měli představu o tom, co by agent rád změnil. A poté buďte připraveni vrátit změny zpět nebo dokonce spustit `omarchy reinstall configs`, pokud agent všechno zaneřádí.
