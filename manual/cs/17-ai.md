### Instalace a aktualizace agentů

S výjimkou Hermes a OpenClaw tito agenti používají lazy instalaci přes mise: první spuštění nainstaluje CLI a další spuštění jej znovu použijí. mise také zkontroluje nainstalovaného agenta na novou verzi nejvýše jednou za čtyři hodiny, těsně před jeho spuštěním nebo na pozadí při shell promptu. Pokud tato aktualizace selže nebo jste offline, spustí se nainstalovaná verze. `omarchy update` aktualizuje nainstalované agenty spolu se zbytkem Omarchy a `mup` aktualizuje pouze nástroje spravované přes mise.

Vlastní aktualizátor agenta, například `claude update`, `codex update` nebo tlačítko aktualizace v aplikaci, neaktualizuje instalaci spravovanou přes mise. `codex update` selže a `claude update` může hlásit úspěch, přičemž nainstaluje samostatnou kopii, kterou mise nesleduje. Pokud raději používáte nativní instalátor a aktualizátor agenta, přidejte jej do `disable_tools`; viz [Předinstalované CLI nástroje](18-development-tools.md#preinstalled-cli-tools).

Pro instalaci všech nakonfigurovaných lazy nástrojů předtím, než je budete potřebovat, spusťte `mise install --include-lazy`. To zahrnuje ostatní výchozí CLI nástroje Omarchy i agenty. Viz [Předinstalované CLI nástroje](18-development-tools.md#preinstalled-cli-tools) pro instalaci jediného nástroje nebo použití vlastní instalace.

`grok` se instaluje přes first-party balíček `grok` od mise, stejně jako `claude` a `codex`. Spusťte `grok`, nebo jej vyberte v _Agent > Harness_. Přeskočte instalátor `curl | bash` na x.ai. Tato cesta umístí druhou kopii do `~/.grok/bin`, předřadí ji na `PATH` a přepíše wrapper Omarchy.

`dsh` otevře své prohlížečové UI na `127.0.0.1:3080`, přičemž spouštěcí adresář je jeho výchozím pracovním prostorem. Jeho prohlížečové UI nepřijímá počáteční prompt, takže `omarchy agent prompt` jej otevře s promptem ve vaší schránce k vložení. Omarchy jej spouští s předvolbou oprávnění no-approval od DeepSeek. DeepSeek Harness nahrává protokoly relací společnosti DeepSeek, když používáte její oficiální model API; vypněte to v jeho prohlížečovém UI v _Settings > General > Upload Session Log_. Zpětná vazba, kterou mu pošlete, se nahrává spolu s relací také, pokud jej nespustíte s `DSH_TELEMETRY_MODE=DISABLED`.

### Výchozí agent

Vyberte svého výchozího agenta pomocí `omarchy default agent <name>` nebo v _Agent > Harness_ v Omarchy Menu (`Super + Space`). Pokud agent ještě není nainstalován, jeho výběr jej nejprve nainstaluje a také získá vlastní spouštěč ve spouštěči aplikací vedle Agent. Čerstvá Omarchy vás k této volbě vyzve jednorázovým oznámením.

Výběr Claude se také pokusí nastavit jeho rozšíření prohlížeče pro Chromium, Chrome, Brave, Brave Origin a Edge. Nastavení rozšíření platí pro všechny uživatele a může vyžadovat vaše systémové heslo; zrušení nebo neúspěšná instalace rozšíření přesto vybere a spustí Claude. Restartujte prohlížeč, povolte rozšíření, pokud budete vyzváni, a přihlaste se do Claude, abyste dokončili jeho připojení. Spusťte `/chrome` v Claude pro kontrolu připojení. Firefox a Zen toto rozšíření nepodporují. Pokud byl Claude vaším výchozím již před přidáním tohoto nastavení, vyberte jej znovu pro instalaci rozšíření.

Jakmile si vyberete, `Super + Shift + Ctrl + A` spustí výchozího agenta v samostatném okně terminálu (nebo zobrazí výběr, pokud jste si ještě nevybrali). Můžete jej také spustit přímo do úkolu pomocí `omarchy agent prompt "Review this project"`. Freebuff a DeepSeek Harness nepřijímají počáteční prompt, takže se místo toho otevřou s promptem ve vaší schránce k vložení. Takto spuštění agenti běží bez dozoru ve svých příslušných režimech don't-stop-to-ask, takže buďte připraveni na to, že budou skutečně něco dělat! MiniMax Code takový režim pro své interaktivní relace nemá, takže žádá o oprávnění jako obvykle. A protože agenti odmítají zapamatovat si důvěru pro váš domovský adresář, spuštění z `$HOME` místo toho začínají v `~/Work`.

Existují také zkratky terminálu: `a` spustí výchozího agenta inline v aktuálním terminálu, zatímco `c`, `cx` a `cy` spustí OpenCode, Claude Code a Codex přímo (opět v jejich režimech auto-approving). Změny motivu se synchronizují také do agentů: Claude Code, Pi, OpenCode a Hermes (jakmile jej Omarchy nainstalovala) všechny následují, když přepnete motiv Omarchy.

### Vaše pokyny pro agenty

Osobní pravidla pro každého agenta patří do `~/.agents/AGENTS.md`, vedle sdílených skillů v `~/.agents/skills`. Otevřete jej v _Agent > Instructions_, což jej také propojí do každého harnessu, který si udržuje vlastní globální soubor: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, Copilotův `~/.copilot/copilot-instructions.md` a tak dále. Crush a Amp čtou odkaz `~/.config/AGENTS.md`, zatímco omp, Kimi a DeepSeek Harness čtou `~/.agents/AGENTS.md` přímo. Výběr výchozího agenta jej propojí také. Soubor pokynů, který jste již měli, se stane sdíleným, pokud ještě žádný nebyl; jinak je ponechán vedle odkazu jako `.bak`. Po instalaci dalšího agenta spusťte `omarchy agent instructions` pro opětovné propojení.

### Panel agentů

Horní lišta má ikonu agentů. Před nastavením agenta vás její panel provede přihlášením do Claude, Codex nebo Grok a první z nich se stane vaším výchozím agentem. Poté panel umístí každé předplatné na jednu stránku: každý agent a účet s jeho plánem, měřič pro každý z jeho 5hodinových limitů relace a týdenních limitů s časem do jeho resetu (přejetím zobrazíte přesné procento) nebo zbývající předplacený zůstatek, pod řádkem, který rotuje tím, co jste použili napříč všemi, jako tokeny tento týden a váš nejpoužívanější model. V části _Make something cool_ nabízí startovací prompty pro nový motiv, plugin, aplikaci nebo hru, které předají úkol vašemu výchozímu agentovi. Aplikace jsou vytvářeny tak, jak jsou vlastní Hype, Monologue a Omacut od Omarchy, v C++ a Qt Quick, podle agent skillu omarchy-make-app, a kompilátor a Qt součásti, které potřebují, jsou nainstalovány. Hry jsou jedna stránka three.js v `~/Games/vibes`, podle agent skillu omarchy-make-game, a všechny se otevírají z jednoho spouštěče Game Vibes v aktuálním motivu; načítají three.js z webu, takže ke spuštění potřebují připojení. Claude Code, Codex, Grok, Kimi, Cursor a jeho příděl Grok Bot, GitHub Copilot, Muse, Antigravity a Devin jsou pokryty hned po instalaci se svými limity, Kimchi se svým plánem, předplacenými kredity a rozpočty útraty a Hermes, Mistral Vibe a Qwen Code zobrazují své relace a tokeny, jakmile je použijete. Plány poskytovatelů a klíče, které používáte přes pi, omp nebo opencode, se také zobrazí: OpenCode Zen a Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan a Synthetic se svými limity; OpenRouter a DeepSeek se svými předplacenými zůstatky; Fireworks se svou útratou za posledních 30 dní; a modely, které provozujete na vlastním hardwaru v části Local models. Každý agent se počítá jednou, pod tím, kdo jej fakturuje, bez ohledu na to, přes kolik harnessů jej řídíte.

Klikněte levým tlačítkem na ikonu na liště nebo stiskněte `Super + Ctrl + X` pro panel, klikněte pravým pro spuštění výchozího agenta a prostředním pro obnovení. Záznamy o používání za ním se regenerují každých 15 minut pomocí `omarchy agent usage update` a panel může dokonce sloučit používání z vašich ostatních strojů přes synchronizovanou složku. Viz README v `$OMARCHY_PATH/shell/plugins/agents/` pro úplné nastavení.

### Několik předplatných

Pokud platíte za více než jeden plán Claude, Codex nebo Grok — například osobní Max a pracovní — Omarchy je může udržet všechny přihlášené a pohybovat se mezi nimi. Přidejte předplatné pomocí + v panelu agentů, který vás tím provede přímo tam, nebo pomocí `omarchy agent account add claude Work` (nebo `codex`, nebo `grok`). Nainstaluje CLI, pokud chybí. První účet pro poskytovatele se přihlásí přes váš normální prohlížeč, přesně tam, kde CLI vždy hledá. Každý další se přihlásí přes soukromé okno, takže účet, ke kterému je váš prohlížeč již přihlášen, nebude omylem zachycen; přihlaste se tam jako účet, který přidáváte, a nejprve zavřete všechna soukromá okna, která jste již měli otevřená. Nikdy se kvůli tomu z CLI neodhlasujte: odhlášení zruší uložené přihlášení a tento účet by musel být přidán znovu.

Pro kopírování přihlášení k předplatnému na jiný stroj Omarchy přes SSH spusťte `omarchy agent account copy user@laptop`. Odesílatel dodá dočasného příjemce, když cíl žádného nainstalovaného nemá, takže starší stroje Omarchy mohou přijímat účty bez aktualizace. Nainstalovaní příjemci mají přednost. Toto kopíruje všechna předplatná Claude, Codex a Grok; přidejte názvy poskytovatelů pro jejich výběr, jako v `omarchy agent account copy laptop claude`. Názvy účtů a ID příkazů odpovídají zdroji, včetně účtů již přítomných na cíli. Nesouvisející cílové účty obdrží číselnou příponu, pokud jejich názvy kolidují, a nastavení, skilly, pluginy a historie konverzací zůstávají lokální na každém stroji.

Stávající cílové přihlašovací údaje jsou zachovány. Zdrojový účet již přihlášený tam má synchronizovaný název bez nahrazení svých přihlašovacích údajů; ostatní účty jsou přidány vedle něj. Pro nahrazení uložených přihlašovacích údajů pro odpovídající účty použijte `omarchy agent account copy --replace laptop claude` po ukončení relací tohoto účtu na cíli. Čerstvý cíl také obdrží aktivní účet a preference přepínání zdroje; zavedený cíl si zachová své vlastní.

Přihlašovací údaje cestují přes SSH a jsou uloženy v soukromých souborech na cíli, takže kopírujte pouze na stroje, kterým důvěřujete. Jedná se o jednorázovou kopii, nikoli průběžnou synchronizaci. Refresh tokeny Codexu mohou být rotovány jiným strojem, což zanechá zkopírované přihlášení potřebující obnovení; samostatná přihlášení zůstávají nejspolehlivější volbou pro současné použití na několika strojích. Viz [Průvodce ověřováním účtů Codexu](https://developers.openai.com/codex/auth/ci-cd-auth).

Jeden účet na poskytovatele je aktivní a každá nová relace začíná jako on: `cx`, `cy`, prosté `claude`, `codex` nebo `grok`, cokoli spuštěného přes `omarchy agent`, a skripty nebo editory, které najdou CLI na `PATH`. Přepněte pomocí `omarchy agent account use work` (a zpět pomocí `omarchy agent account use main`), nebo v panelu stisknutím čísla účtu a poté `Enter` (nebo kliknutím na jeho tlačítko Use). Běžící relace Claude se přepnou také, od jejich další zprávy: každá relace Claude běží v `~/.claude`, která vždy obsahuje přihlášení aktivního účtu. Relace Claude spuštěná ve vlastní složce účtu starší Omarchy si toto přihlášení uchová, dokud neskončí, takže přepínač tyto relace pojmenuje a dokončí sám, jakmile zmizí. Běžící relace Codex a Grok zůstávají na účtu, se kterým začaly. Historie konverzací, nastavení, skilly a pluginy jsou sdíleny napříč účty, takže `claude --continue` ve stejné složce pokračuje tam, kde jste na novém účtu skončili.

S více než jedním účtem panel zobrazuje limity každého účtu vedle sebe, s označeným aktivním. Ve výchozím nastavení vás Omarchy upozorní, když aktivní účet překročí 95 % limitu, a kliknutí na oznámení přepne na účet s největším prostorem. Najeďte na řádek účtu v panelu a klikněte na Autoswitch, které se objeví vedle Use (nebo stiskněte `m`), nebo spusťte `omarchy agent account mode auto`, aby se přepínal sám; zatímco je zapnuté, Autoswitch zaujme místo Use a opětovné kliknutí se vrátí k upozorňování. Přidejte číslo pro změnu prahu, jako v `omarchy agent account mode auto 90`. Pokud je každý účet nad prahem, uslyšíte o tom jednou, spolu s tím, který účet se uvolní jako první. Zatímco je aktivní účet do 15 bodů od svého prahu (80 % při výchozím nastavení), jeho limity se kontrolují každé tři minuty místo každých 15.

`omarchy agent account list` zobrazuje každý účet a jeho nejnovější limity, `omarchy agent account remove work` jeden zapomene a `omarchy agent account rename primary Hey` jeden přejmenuje (nebo klikněte na název účtu v panelu). Tyto příkazy pracují s účty vašeho výchozího agenta; pro dosažení jiného poskytovatele jej nejprve pojmenujte, jako v `omarchy agent account use codex side`. Přihlášení, které jste již měli v `~/.claude` nebo `~/.codex`, je účet _Main_. Účet Codexu zůstává tam, kde je; účet Claude čeká ve vlastní složce, zatímco je aktivní jiný účet. Účet ponechaný nepoužívaný déle než asi osm hodin může zobrazovat _Sign-in required_; klikněte na něj pro opětovné přihlášení tohoto účtu přímo v panelu, nebo na něj přepněte a spusťte relaci, což přihlášení obnoví samo. MCP servery, které přidáte pomocí `claude mcp add`, dosáhnou na každý účet Claude, protože všechny běží v `~/.claude`; pro Codex a Grok servery, které jste měli při přidání účtu, přicházejí spolu s ním, ale pozdější dosáhnou pouze na účet, do kterého jste je přidali. Claude Desktop si udržuje vlastní přihlášení a nástroje Codex nebo Grok nakonfigurované s absolutní cestou k binárce CLI přepínač nenásledují. Explicitní `CLAUDE_CONFIG_DIR`, `CODEX_HOME` nebo `GROK_HOME` má přednost před vybraným účtem.

### Diagnostika pádů

Omarchy sleduje systemd-coredump pro pády procesů. Jakmile si vyberete výchozího agenta, jakýkoli váš program, který dumpne core, přinese oznámení "Process crashed" — klikněte na něj a pád je předán vašemu výchozímu agentovi spolu se skillem omarchy-diagnose-crash od Omarchy, který agenta provede stanovením faktů z core dumpu a rozhodnutím, zda pád stojí za nahlášení upstream. Můžete jej také spustit ručně proti libovolnému PID z `coredumpctl list` pomocí `omarchy agent crash <pid>`.

Sledování je ve výchozím nastavení zapnuté. Vypněte jej v _Trigger > Toggle > Crash Capture Off_ (nebo pomocí `omarchy toggle crash-capture`) a oznámení přestanou; `omarchy agent crash <pid>` stále funguje ručně.

Pády lze také ztlumit po jednom programu, což vám diagnostika na konci nabídne. `omarchy crash mute hyprland` zastaví oznámení pouze pro tento program, `omarchy crash mute hyprland off` je vrátí zpět a `omarchy crash mute` samo o sobě vypíše, co jste ztlumili. Přijímá cestu binárky stejně ochotně jako její název, takže `omarchy crash mute /usr/bin/hyprland` dělá totéž. Uvozovkujte název s mezerou, jako v `omarchy crash mute 'Some App'`. Vše ostatní stále oznamuje a ztlumený program stále padá — toto skrývá připomínku, nic neopravuje.

### Desktopové aplikace

Menu _Install > AI_ také obsahuje několik grafických AI aplikací: Amp Desktop, Antigravity Desktop, desktopovou aplikaci ChatGPT, desktopovou aplikaci Claude (Linux beta od Anthropic, se záložkami Chat, Cowork a Claude Code), Grok Bot pro chatování s modely xAI, Herdr Desktop, Hermes Desktop, OpenClaw, desktopovou aplikaci Perplexity a T3 Code. Grok Bot je desktopová chatovací aplikace. Kódovacím agentem je příkaz `grok`.

Hermes Desktop je ten, o kterém je třeba vědět, protože stroj má jeden Hermes a je aplikace: Hermes se instaluje pouze přes aplikaci a příkaz `hermes`, který výchozí agent spouští, je aplikace. Výběr Hermes jako výchozího agenta nainstaluje totéž, co položka _Install > AI_: balíček a runtime Hermes v `~/.hermes` nastavený vlastním instalátorem Hermes, což poprvé trvá několik minut. Tento runtime je ten jeden Hermes, který používají terminálový příkaz `hermes`, výchozí agent i aplikace, a aktualizuje se sám pomocí `hermes update`, spíše než aby čekal na vydání Omarchy. Jeho instalace také předá Hermes motiv Omarchy jako skin pojmenovaný `omarchy`, který každý povrch Hermes následuje, když přepínáte motivy; vyberte jiný v nastavení Appearance Hermes nebo pomocí `/skin`, pokud raději nechcete, a Omarchy tuto volbu nechá být. Odebrání aplikace v _Remove > AI_ nejprve zavře Hermes, včetně gateway, vezme s sebou tento runtime a zachová vaše chaty, vzpomínky a skilly, které Hermes pro sebe napsal, pokud neřeknete jinak: zeptá se, výchozí je ne, zda by tato data a vaše nastavení připojení měla také odejít.

Desktopový zážitek OpenClaw je jeho Control UI, které se otevírá jako webová aplikace podporovaná jeho vlastní lokální gateway. OpenClaw žije v `~/.openclaw` a aktualizuje se sám: použijte tlačítko "Update Gateway" v Control UI nebo spusťte `openclaw update` a gateway se restartuje na nové verzi. Omarchy pouze vybírá vydání, ze kterého čerstvá instalace začíná. OpenClaw může být také vaším výchozím agentem: jeho výběr v _Agent > Harness_ nastaví tutéž kopii v `~/.openclaw` a agent otevře terminálové UI OpenClaw připojené k jeho gateway. Odebrání OpenClaw v _Remove > AI_ vezme s sebou službu gateway a aplikaci a poté se zeptá, zda by `~/.openclaw` mělo také odejít, protože to obsahuje vaše chaty a přihlašovací údaje vedle samotného OpenClaw a runtime pluginů, které stahuje; výchozí je zachovat jej a opětovná instalace OpenClaw jej znovu zachytí.

Herdr Desktop je desktopová aplikace [Herdr](https://herdr.dev): prostory, záložky a panely terminálů a kódovacích agentů, které dál běží v jeho jádru, když zavřete okno. Pochází z vlastního instalátoru Herdr spíše než z balíčku, takže žije v `~/.local/share/herdr-app`, přináší své jádro v `~/.local/bin/herdr-core`, když jej ještě nemáte, a aktualizuje obojí sama. Sedí vedle příkazu `herdr`, který Omarchy dodává na `Super + Ctrl + Return`, spíše než aby jej nahrazovala, a získává přímé klávesy tohoto příkazu: `Alt + Return` a `Alt + Shift + Return` rozdělí panel dolů nebo doprava, `Alt + Escape` jej zavře, `Ctrl + Alt + Arrow` se pohybuje mezi panely, `Alt + 1..9` a `Alt + Left/Right` vybírají záložku a `Alt + Up/Down` se pohybují mezi prostory. `Ctrl + 1..9` vybírá prostor a `Alt + Shift + Up/Down` prochází agenty. Klávesy s prefixem `Ctrl + Space` zůstávají pouze terminálové, protože aplikace nemůže držet prostou klávesu Ctrl pro sekvenci. Omarchy je zapíše do `~/.config/herdr-app/keys.json` a `omarchy-refresh-herdr-app` je vrátí zpět. Jeho instalace vybere motiv Omarchy pro Herdr, který od té doby následuje váš motiv Omarchy. Herdr udržuje jeden motiv pro světlý režim a jeden pro tmavý, takže po přepnutí mezi tmavým a světlým motivem Omarchy vyberte Omarchy v pickeru motivů Herdr ještě jednou pro druhý režim.

T3 Code běží ze svého oficiálního vydání AppImage v `~/.local/share/t3code` spíše než z balíčku, takže se aktualizuje sám. Jeho instalace se zeptá, zda začít na kanálu Stable nebo Nightly; přepněte později v nastavení T3 Code. Vaše vlákna a nastavení žijí v `~/.t3` a odebrání T3 Code v _Remove > AI_ je vezme s sebou.

### Lokální modely

Spusťte otevřený model na vlastním stroji pro své kódovací agenty. Vaše prompty a kód zůstávají na stroji; nic odeslaného modelu jej neopustí. Začněte s:

```bash
omarchy models use best text
```

Nebo v panelu agentů v horní liště vyberte + a poté Local AI, což se zobrazí, když se model vejde na tento stroj. Podman, který modely spouští, je součástí Omarchy, stejně jako sada nástrojů kontejnerů NVIDIA na stroji NVIDIA, která jim dává GPU; pokud cokoli chybí, první nastavení to nainstaluje. Omarchy poté vybere doporučený model pro tento stroj, stáhne jej a spustí. Očekávejte stažení desítek GB a většinu paměti stroje v použití, zatímco model běží: Flash Next používá asi 100 GiB se svým plným kontextem 256K. Pokud jiné modely drží paměť, kterou potřebuje, je nastaven zastavený, připravený ke spuštění, jakmile jeden zastavíte. Model se zastaví při odhlášení; zastavte jej sami, když potřebujete paměť pro něco jiného.

`omarchy models list` zobrazuje možnosti a vysvětluje, proč se některé nevejdou. Pro nastavení dalšího spusťte `omarchy models use <recipe>`. Dnes jsou `qwen3.8-flash-next-gufo` a `qwen3.8-27b-gufo` k dispozici pro stroje Strix Halo se 128 GB; 27B zabírá asi 40 GiB, takže nechává prostor pro další práci. Na 64GB laptopu s Intel Arc B390 běží `qwen3.6-35b-a3b-llamacpp` v asi 30 GiB. Nové recepty a doporučení přicházejí s `omarchy update`, přes balíček.

Každý model, který nastavíte, získá vlastní řádek v panelu agentů, vedle vašich předplatných: play pro spuštění, pause pro zastavení a uvolnění jeho paměti a tlačítko terminálu pro otevření vašeho agenta na něm. Několik může běžet najednou, když se společně vejdou do paměti; pokud se jeden nevejde, Omarchy řekne, který běžící model zastavit. Přetáhněte řádky pro jejich přeřazení a stiskněte Delete na vybraném řádku pro odebrání modelu a jeho stažení.

Každý model, který nastavíte, také získá vlastní položku ve spouštěči aplikací, pod názvem modelu a s logem jeho tvůrce, stejně jako přihlášení do Claude, Codex nebo Grok přidá jednu. Otevře vašeho agenta na tomto modelu a nejprve model spustí, pokud neběží: terminál ukazuje jeho načítání a předá agentovi, jakmile je vzhůru. Odebrání modelu odebere jeho položku.

Ne každý model je pro kódování. Obrazové, video a hudební modely se místo toho otevírají ve Fantasi, aplikaci Omarchy pro vytváření obrázků, videa a hudby s modelem běžícím na tomto stroji, z jejich položky spouštěče a z jejich řádku v panelu agentů.

Model dál běží přesně tak, jak byl nastaven, takže aktualizace Omarchy žádný pod vašimi agenty nerestartuje. Když má Omarchy novější runtime nebo novější váhy pro model, který jste nastavili, jeho řádek zobrazí tlačítko aktualizace: stiskněte jej a model je znovu nastaven na pozadí, stáhne pouze to, co se změnilo, a restartuje se na nové verzi. Model, který byl zastaven, zůstane zastaven. `omarchy models update` dělá totéž pro každý model z terminálu.

Z příkazového řádku `omarchy models start <recipe>` a `omarchy models stop <recipe>` dělají totéž, `omarchy models status` zobrazuje každý model a `omarchy agent --local` otevře vašeho výchozího agenta na posledním modelu, který jste spustili. pi, OpenCode a Qwen Code mohou jeden použít; s jakýmkoli jiným výchozím se otevře v pi, nebo v OpenCode, pokud pi nemáte. pi také vypisuje každý model, který jste nastavili, a ty na strojích, se kterými jste spárováni, ve svém vlastním pickeru modelů, takže prosté `pi` je dosáhne také. Jakýkoli klient kompatibilní s OpenAI se může připojit také: `status` zobrazuje adresu každého modelu (první je `http://127.0.0.1:11435/v1`), název receptu je model a klíč je v `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` smaže model a stažení, která žádný jiný model nepoužívá.

Runtime třetích stran jsou označeny svým vydavatelem. Omarchy spouští každý model bez přístupu k síti.

### Lokální LLM

Omarchy doporučuje dva způsoby spouštění lokálních modelů LLM: LM Studio a Ollama. LM Studio poskytuje GUI rozhraní pro hledání modelů s otevřenými vahami, jejich instalaci a spouštění. Je to skvělý způsob, jak snadno začít. Ollama nabízí CLI pro podobné provádění. Ale pokud jste v lokálních modelech noví, začal bych s LM Studio. Můžete nainstalovat cokoli v _Install > AI_ v Omarchy Menu.

### Skilly Omarchy

Agent skilly pomáhají AI používat konkrétní nástroje konkrétním způsobem a Omarchy dodává sedm z nich. Skill omarchy pokrývá přizpůsobení systému, jako ladění vaší konfigurace Hyprland nebo nastavení lišty. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app a omarchy-make-game pokrývají vytváření něčeho nového, omarchy-contribute pokrývá hlášení chyby nebo odeslání opravy upstream a omarchy-diagnose-crash prochází core dump pádu. Jsou symlinkovány do adresářů skillů pro Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` a každý `~/.hermes/profiles/*/skills`) a obecné umístění `~/.agents/skills`, takže je většina harnessů zachytí automaticky. Složka skillu vašeho vlastního se stejným názvem má přednost.

Ale měli byste tyto skilly považovat za experimentální. Různé modely je využijí s různým účinkem. Nejlepší je nejprve běžet v režimu plánování, abyste měli představu o tom, co by agent rád změnil. A pak buďte připraveni vrátit změny nebo dokonce vyvolat `omarchy reinstall configs`, pokud agent udělá ze všeho nepořádek.
