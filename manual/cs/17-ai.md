### Instalace a aktualizace agentů

S výjimkou Hermes a OpenClaw tito agenti používají línou instalaci přes mise: první spuštění nainstaluje CLI a další spuštění ho znovu použijí. mise také nejvýše jednou za čtyři hodiny zkontroluje, zda pro nainstalovaného agenta nevyšla nová verze, a to těsně před jeho spuštěním nebo na pozadí při zobrazení příkazového řádku shellu. Pokud tato aktualizace selže nebo jste offline, spustí se nainstalovaná verze. `omarchy update` aktualizuje nainstalované agenty spolu se zbytkem Omarchy a `mup` aktualizuje pouze nástroje spravované přes mise.

Vlastní aktualizátor agenta, například `claude update`, `codex update` nebo tlačítko pro aktualizaci v aplikaci, instalaci spravovanou přes mise neaktualizuje. `codex update` selže a `claude update` může hlásit úspěch, přestože nainstaluje samostatnou kopii, kterou mise nesleduje. Pokud raději používáte nativní instalační program a aktualizátor agenta, přidejte ho do `disable_tools`; viz [Předinstalované nástroje CLI](18-development-tools.md#preinstalled-cli-tools).

Chcete-li nainstalovat všechny nakonfigurované líné nástroje dříve, než je budete potřebovat, spusťte `mise install --include-lazy`. To zahrnuje i ostatní výchozí nástroje CLI v Omarchy, nejen agenty. Informace o instalaci jednoho nástroje nebo použití vlastní instalace najdete v části [Předinstalované nástroje CLI](18-development-tools.md#preinstalled-cli-tools).

`grok` se instaluje prostřednictvím balíčku `grok` první strany od mise, stejně jako `claude` a `codex`. Spusťte `grok` nebo ho označte hvězdičkou v panelu agentů. Přeskočte instalační program `curl | bash` na x.ai. Tento způsob umístí druhou kopii do `~/.grok/bin`, přidá ji na začátek `PATH` a přepíše wrapper od Omarchy.

`dsh` otevírá své prohlížečové UI na `127.0.0.1:3080`, přičemž adresář, ze kterého byl spuštěn, je jeho výchozím pracovním prostorem. Jeho prohlížečové UI nepřijímá počáteční prompt, takže `omarchy agent prompt` ho otevře s promptem ve schránce, abyste ho mohli vložit. Omarchy ho spouští s předvolbou oprávnění bez schvalování od DeepSeek. DeepSeek Harness nahrává protokoly relací do DeepSeek, když používáte jeho oficiální API pro modely; vypněte to v jeho prohlížečovém UI v části _Settings > General > Upload Session Log_. Zpětná vazba, kterou mu pošlete, se nahrává spolu s relací také, pokud ho nespustíte s `DSH_TELEMETRY_MODE=DISABLED`.

### Výchozí agent

Vyberte si výchozího agenta hvězdičkou vedle agenta v panelu agentů, která je u výchozího vyplněná, nebo příkazem `omarchy default agent <name>`, který přijme i jakýkoli harness, který tam nemá řádek. Pokud agent ještě není nainstalován, jeho výběr ho nejprve nainstaluje a v spouštěči aplikací vedle položky Agent získá také vlastní spouštěč. Čerstvá instalace Omarchy vás k nastavení jednoho vyzve jednorázovým oznámením, které otevře panel agentů.

Výběr Claude se také pokusí nastavit jeho rozšíření prohlížeče pro Chromium, Chrome, Brave, Brave Origin a Edge. Nastavení rozšíření platí pro všechny uživatele a může vyžadovat vaše systémové heslo; zrušení nebo neúspěšná instalace rozšíření přesto Claude vybere a spustí. Restartujte prohlížeč, po vyzvání povolte rozšíření a přihlaste se ke Claude, abyste připojení dokončili. Připojení zkontrolujete spuštěním `/chrome` v Claude. Firefox a Zen toto rozšíření nepodporují. Pokud byl Claude vaším výchozím agentem už před přidáním tohoto nastavení, vyberte ho znovu, aby se rozšíření nainstalovalo.

Jakmile si vyberete, `Super + Shift + Ctrl + A` spustí výchozího agenta ve vyhrazeném okně terminálu (nebo zobrazí výběr, pokud jste si ještě nevybrali). Můžete ho také spustit rovnou s úkolem pomocí `omarchy agent prompt "Review this project"`. Freebuff a DeepSeek Harness nepřijímají počáteční prompt, takže se místo toho otevřou s promptem ve schránce, abyste ho mohli vložit. Takto spuštění agenti běží bez dohledu ve svých příslušných režimech, ve kterých se nezastavují, aby se zeptali, takže buďte připraveni na to, že budou skutečně něco dělat! MiniMax Code takový režim pro své interaktivní relace nemá, takže žádá o oprávnění jako obvykle. A protože agenti odmítají zapamatovat si důvěru pro váš domovský adresář, spuštění z `$HOME` začínají místo toho v `~/Work`.

Existují i zkratky v terminálu: `a` spustí výchozího agenta přímo v aktuálním terminálu, zatímco `c`, `cx` a `cy` spustí přímo OpenCode, Claude Code a Codex (opět v jejich režimech s automatickým schvalováním). Změny motivu se synchronizují i do agentů: Claude Code, Pi, OpenCode a Hermes (jakmile ho Omarchy nainstalovala) se všechny přizpůsobí, když přepnete motiv Omarchy.

### Vaše pokyny pro agenty

Osobní pravidla pro každého agenta patří do `~/.agents/AGENTS.md`, vedle sdílených skillů v `~/.agents/skills`. Otevřete ho ikonou dokumentu vedle + v panelu agentů nebo příkazem `omarchy agent instructions --edit`, který ho také propojí do každého harnessu, který má svůj vlastní globální soubor: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` pro Copilot a tak dále. Crush a Amp čtou odkaz `~/.config/AGENTS.md`, zatímco omp, Kimi a DeepSeek Harness čtou přímo `~/.agents/AGENTS.md`. Výběr výchozího agenta ho propojí také. Soubor s pokyny, který jste už měli, se stane sdíleným, pokud ještě žádný nebyl; jinak zůstane vedle odkazu jako `.bak`. Po instalaci dalšího agenta spusťte `omarchy agent instructions`, aby se znovu propojil.

### Panel agentů

Horní panel má ikonu agentů. Než si agenta nastavíte, jeho panel nabízí tři způsoby, jak začít: přihlásit se k předplatnému Claude, Codex, Grok, Gemini, Muse, Cursor nebo Copilot, nebo v části More k kódovacímu tarifu OpenCode Go, MiniMax, Synthetic nebo Z.ai; platit průběžně podle spotřeby s Fireworks, OpenCode Zen and Go, OpenRouter, nebo v části More s DeepSeek či jakýmkoli jiným poskytovatelem, ke kterému se OpenCode přihlašuje, přičemž všechny běží v OpenCode; nebo spustit nejlepší model pro váš počítač, když se na něj nějaký hodí. První, který dokončíte, se stane vaším výchozím agentem a + v panelu později nabízí stejné tři možnosti. Poté panel umístí každé předplatné na jednu stránku: každého agenta a účet s jeho tarifem, měřič pro každý z jeho limitů pro 5hodinovou relaci a týdenních limitů s časem do jeho resetování (přesné procento zobrazíte najetím), nebo zbývající předplacený zůstatek, pod řádkem, který se střídavě mění podle toho, co jste u všech spotřebovali, například tokeny za tento týden a váš nejpoužívanější model. V části _Make something cool_ nabízí úvodní prompty pro nový motiv, plugin, aplikaci nebo hru, které předají úkol vašemu výchozímu agentovi. Aplikace se vytvářejí stejným způsobem jako vlastní Hype, Monologue a Omacut od Omarchy, v C++ a Qt Quick, podle skillu pro agenty omarchy-make-app, a kompilátor a součásti Qt, které potřebují, jsou nainstalované. Hry jsou jedna stránka three.js v `~/Games/vibes`, podle skillu pro agenty omarchy-make-game, a všechny se otevírají z jednoho spouštěče Game Vibes v aktuálním motivu; načítají three.js z webu, takže ke spuštění potřebují připojení. Claude Code, Codex, Grok, Kimi, Cursor a jeho příděl Grok Bot, GitHub Copilot, Muse, Gemini (prostřednictvím Antigravity) a Devin jsou pokryty hned po instalaci se svými limity, Kimchi se svým tarifem, předplacenými kredity a rozpočty na útratu a Hermes, Mistral Vibe a Qwen Code zobrazují své relace a tokeny, jakmile je použijete. Objeví se i tarify poskytovatelů a klíče, které používáte prostřednictvím pi, omp nebo opencode: OpenCode Zen and Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan a Synthetic se svými limity; OpenRouter a DeepSeek se svými předplacenými zůstatky; Fireworks se svou útratou za posledních 30 dní. Tokeny z modelů, které provozujete na vlastním hardwaru, se do součtů započítávají také; samotné modely mají vlastní panel, popsaný v části [Lokální modely](#local-models). Každý agent se započítává jednou, u toho, kdo ho účtuje, bez ohledu na to, přes kolik harnessů ho řídíte.

Panel otevřete kliknutím levým tlačítkem na ikonu v panelu nebo stisknutím `Super + Ctrl + X`, kliknutím pravým tlačítkem spustíte výchozího agenta a kliknutím prostředním tlačítkem obnovíte. Záznamy o využití, které za ním stojí, se každých 15 minut znovu generují příkazem `omarchy agent usage update` a panel dokáže dokonce sloučit využití z vašich ostatních počítačů prostřednictvím synchronizované složky. Úplné nastavení najdete v README v `$OMARCHY_PATH/shell/plugins/agents/`.

### Více předplatných

Pokud platíte za více než jeden tarif Claude, Codex nebo Grok — například osobní Max a pracovní — Omarchy je může udržet všechny přihlášené a přepínat mezi nimi. Předplatné přidáte tlačítkem + v panelu agentů, které vás tím provede přímo tam, nebo příkazem `omarchy agent account add claude Work` (nebo `codex`, nebo `grok`). Stejné + a příkaz slouží k přihlášení ke Gemini (`gemini`) a OpenCode (`opencode`) a k uložení klíče API pro Fireworks (`fireworks`) nebo OpenRouter (`openrouter`) v OpenCode; příkaz vás také přihlásí ke Copilot (`copilot`), Cursor (`cursor`) a Muse (`muse`). Ty si zachovávají po jednom přihlášení. Pokud CLI chybí, nainstaluje ho. První účet pro poskytovatele se přihlašuje přes váš běžný prohlížeč, přesně tam, kde ho CLI vždy hledá. Každý další se přihlašuje přes soukromé okno, aby se omylem nevybral účet, ke kterému je váš prohlížeč už přihlášen; přihlaste se tam jako účet, který přidáváte, a nejprve zavřete všechna soukromá okna, která už máte otevřená. Kvůli tomu se nikdy neodhlasujte z CLI: odhlášení zruší uložené přihlášení a tento účet by bylo nutné přidat znovu.

Chcete-li zkopírovat přihlášení k předplatnému na jiný počítač s Omarchy přes SSH, spusťte `omarchy agent account copy user@laptop`. Odesílatel dodá dočasného příjemce, když ho cíl nemá nainstalovaného, takže starší počítače s Omarchy mohou přijímat účty bez aktualizace. Nainstalovaní příjemci mají přednost. Tím se zkopírují všechna předplatná Claude, Codex a Grok; přidejte názvy poskytovatelů, chcete-li je vybrat, například `omarchy agent account copy laptop claude`. Názvy účtů a ID příkazů odpovídají zdroji, včetně účtů, které už na cíli existují. Nesouvisející cílové účty dostanou v případě konfliktu názvů číselnou příponu a nastavení, skilly, pluginy a historie konverzací zůstávají lokálně na každém počítači.

Stávající cílové přihlašovací údaje zůstanou zachovány. Zdrojový účet, který je tam už přihlášen, bude mít synchronizovaný název, aniž by se nahradily jeho přihlašovací údaje; ostatní účty se přidají vedle něj. Chcete-li nahradit uložené přihlašovací údaje u odpovídajících účtů, použijte `omarchy agent account copy --replace laptop claude` poté, co na cíli ukončíte relace daného účtu. Čerstvý cíl také získá aktivní účet a předvolby přepínání ze zdroje; zavedený cíl si zachová své vlastní.

Přihlašovací údaje cestují přes SSH a na cíli se ukládají do soukromých souborů, takže kopírujte pouze na počítače, kterým důvěřujete. Jde o jednorázovou kopii, nikoli průběžnou synchronizaci. Obnovovací tokeny Codex může jiný počítač rotovat, takže zkopírované přihlášení bude potřebovat obnovení; samostatná přihlášení zůstávají nejspolehlivější volbou pro současné používání na několika počítačích. Viz [Pokyny Codex k ověřování účtů](https://developers.openai.com/codex/auth/ci-cd-auth).

Pro každého poskytovatele je aktivní jeden účet a každá nová relace začíná jako on: `cx`, `cy`, prosté `claude`, `codex` nebo `grok`, cokoli spuštěné prostřednictvím `omarchy agent` a skripty nebo editory, které najdou CLI na `PATH`. Přepnete příkazem `omarchy agent account use work` (a zpět příkazem `omarchy agent account use main`) nebo v panelu stisknutím čísla účtu a poté `Enter` (nebo kliknutím na jeho hvězdičku). Běžící relace Claude se přepnou také, od jejich další zprávy: každá relace Claude běží v `~/.claude`, která vždy obsahuje přihlášení aktivního účtu. Relace Claude spuštěná ve vlastní složce účtu starší Omarchy si toto přihlášení uchovává, dokud neskončí, takže přepnutí tyto relace pojmenuje a samo se dokončí, jakmile zmizí. Běžící relace Codex a Grok zůstávají na účtu, se kterým začaly. Historie konverzací, nastavení, skilly a pluginy se mezi účty sdílejí, takže `claude --continue` ve stejné složce naváže tam, kde jste na novém účtu přestali.

S více než jedním účtem panel zobrazuje limity každého účtu vedle sebe, s vyplněnou hvězdičkou u toho používaného. Omarchy vás upozorní, když aktivní účet překročí 95 % limitu, a kliknutí na oznámení přepne na účet s největším prostorem. Sama nikdy nepřepíná. Prahovou hodnotu změníte příkazem `omarchy agent account threshold 90`. Pokud je každý účet nad prahovou hodnotou, dozvíte se o tom jednou, spolu s tím, který účet se uvolní jako první. Když je aktivní účet do 15 bodů od své prahové hodnoty (80 % při výchozím nastavení), jeho limity se kontrolují každé tři minuty místo každých 15.

`omarchy agent account list` zobrazí každý účet a jeho nejnovější limity, `omarchy agent account remove work` jeden zapomene a `omarchy agent account rename primary Hey` jeden přejmenuje (nebo klikněte na název účtu v panelu). Tyto příkazy pracují s účty vašeho výchozího agenta; chcete-li se dostat k jinému poskytovateli, nejprve ho uveďte, například `omarchy agent account use codex side`. Přihlášení, které jste už měli v `~/.claude` nebo `~/.codex`, je účet _Main_. Účet Codex zůstává tam, kde je; účet Claude čeká ve vlastní složce, když je aktivní jiný účet. Účet, který se nepoužívá déle než zhruba osm hodin, může zobrazovat _Sign-in required_; klikněte na něj, abyste tento účet znovu přihlásili přímo v panelu, nebo na něj přepněte a spusťte relaci, která přihlášení obnoví sama. Servery MCP, které přidáte příkazem `claude mcp add`, dosáhnou na každý účet Claude, protože všechny běží v `~/.claude`; u Codex a Grok servery, které jste měli v době přidání účtu, přejdou na něj s ním, ale pozdější dosáhnou pouze na účet, ve kterém jste je přidali. Claude Desktop si uchovává vlastní přihlášení a nástroje Codex nebo Grok nakonfigurované s absolutní cestou k binárnímu souboru CLI přepnutí nenásledují. Explicitní `CLAUDE_CONFIG_DIR`, `CODEX_HOME` nebo `GROK_HOME` má přednost před vybraným účtem.

### Diagnostika pádů

Omarchy sleduje systemd-coredump kvůli pádům procesů. Jakmile si vyberete výchozího agenta, každý váš program, který vytvoří výpis paměti (core dump), vyvolá oznámení „Process crashed“ — klikněte na něj a pád se předá vašemu výchozímu agentovi spolu se skillem omarchy-diagnose-crash od Omarchy, který agenta provede zjištěním faktů z výpisu paměti a rozhodnutím, zda pád stojí za nahlášení upstream. Můžete ho také spustit ručně proti libovolnému PID z `coredumpctl list` příkazem `omarchy agent crash <pid>`.

Sledování je ve výchozím nastavení zapnuté. Vypněte ho v části _Trigger > Toggle > Crash Capture Off_ (nebo příkazem `omarchy toggle crash-capture`) a oznámení přestanou; `omarchy agent crash <pid>` ručně stále funguje.

Pády lze také ztlumit po jednotlivých programech, což vám diagnostika na konci nabídne. `omarchy crash mute hyprland` zastaví oznámení pouze pro tento program, `omarchy crash mute hyprland off` je vrátí a samotné `omarchy crash mute` vypíše, co jste ztlumili. Přijme cestu k binárnímu souboru stejně rádo jako jeho název, takže `omarchy crash mute /usr/bin/hyprland` udělá totéž. Název s mezerou dejte do uvozovek, například `omarchy crash mute 'Some App'`. Všechno ostatní stále oznamuje a ztlumený program stále padá — tím se jen skrývá připomenutí, nic to neopravuje.

### Desktopové aplikace

Nabídka _Install > AI_ obsahuje také několik grafických aplikací AI: Amp Desktop, Antigravity Desktop, desktopovou aplikaci ChatGPT, desktopovou aplikaci Claude (linuxová beta od Anthropic s kartami Chat, Cowork a Claude Code), Grok Bot pro chatování s modely od xAI, Herdr Desktop, Hermes Desktop, OpenClaw, desktopovou aplikaci Perplexity a T3 Code. Grok Bot je desktopová chatovací aplikace. Kódovacím agentem je příkaz `grok`.

Hermes Desktop je ten, o kterém je třeba vědět, protože počítač má jeden Hermes a ten patří aplikaci: Hermes se instaluje pouze prostřednictvím aplikace a příkaz `hermes`, který výchozí agent spouští, je ten od aplikace. Výběr Hermes jako výchozího agenta nainstaluje totéž, co položka _Install > AI_: balíček a runtime Hermes v `~/.hermes` nastavený vlastním instalačním programem Hermes, což při prvním použití trvá několik minut. Tento runtime je ten jediný Hermes, který používají terminálový příkaz `hermes`, výchozí agent i aplikace, a aktualizuje se sám příkazem `hermes update`, místo aby čekal na vydání Omarchy. Jeho instalace také předá Hermes motiv Omarchy jako skin s názvem `omarchy`, který každá plocha Hermes následuje, když přepínáte motivy; vyberte si jiný v nastavení Appearance v Hermes nebo příkazem `/skin`, pokud nechcete, aby to dělal, a Omarchy tuto volbu nechá být. Odebrání aplikace v části _Remove > AI_ nejprve zavře Hermes, včetně brány, vezme s sebou tento runtime a zachová vaše chaty, vzpomínky a skilly, které si Hermes sám pro sebe napsal, pokud neřeknete jinak: zeptá se, přičemž výchozí odpověď je ne, zda mají zmizet i tato data a vaše nastavení připojení.

Desktopovým zážitkem OpenClaw je jeho Control UI, které se otevírá jako webová aplikace podporovaná jeho vlastní lokální bránou. OpenClaw žije v `~/.openclaw` a aktualizuje se sám: použijte tlačítko „Update Gateway“ v Control UI nebo spusťte `openclaw update` a brána se restartuje na nové verzi. Omarchy vybírá pouze vydání, ze kterého čerstvá instalace začíná. OpenClaw může být i vaším výchozím agentem: jeho výběr příkazem `omarchy default agent openclaw` nastaví stejnou kopii v `~/.openclaw` a agent otevře terminálové UI OpenClaw připojené k jeho bráně. Odebrání OpenClaw v části _Remove > AI_ s sebou vezme službu brány a aplikaci a poté se zeptá, zda má zmizet i `~/.openclaw`, protože to obsahuje vaše chaty a přihlašovací údaje spolu se samotným OpenClaw a runtime pluginů, které stahuje; ve výchozím nastavení si ho ponechá a opětovná instalace OpenClaw ho zase najde.

Herdr Desktop je desktopová aplikace [Herdr](https://herdr.dev): prostory, karty a panely terminálů a kódovacích agentů, které dál běží v jeho jádru, když okno zavřete. Pochází z vlastního instalačního programu Herdr, nikoli z balíčku, takže žije v `~/.local/share/herdr-app`, když ještě žádný nemáte, přináší si své jádro v `~/.local/bin/herdr-core` a obojí se samo aktualizuje. Stojí vedle příkazu `herdr`, který Omarchy dodává na `Super + Ctrl + Return`, místo aby ho nahrazoval, a získává přímé klávesy tohoto příkazu: `Alt + Return` a `Alt + Shift + Return` rozdělí panel dolů nebo doprava, `Alt + Escape` ho zavře, `Ctrl + Alt + Arrow` přesouvá mezi panely, `Alt + 1..9` a `Alt + Left/Right` vybírají kartu a `Alt + Up/Down` přesouvají mezi prostory. `Ctrl + 1..9` vybírá prostor a `Alt + Shift + Up/Down` prochází agenty. Klávesy s prefixem `Ctrl + Space` zůstávají pouze pro terminál, protože aplikace nemůže pro sekvenci podržet prostou klávesu Ctrl. Omarchy je zapisuje do `~/.config/herdr-app/keys.json` a `omarchy-refresh-herdr-app` je vrátí zpět. Jeho instalace vybere motiv Omarchy pro Herdr, který od té doby následuje váš motiv Omarchy. Herdr si uchovává jeden motiv pro světlý režim a jeden pro tmavý, takže po přepnutí mezi tmavým a světlým motivem Omarchy vyberte Omarchy ve výběru motivů Herdr ještě jednou pro druhý režim.

T3 Code běží ze svého oficiálního vydání AppImage v `~/.local/share/t3code`, nikoli z balíčku, takže se aktualizuje sám. Jeho instalace se zeptá, zda chcete začít na kanálu Stable nebo Nightly; později přepnete v nastavení T3 Code. Vaše vlákna a nastavení žijí v `~/.t3` a odebrání T3 Code v části _Remove > AI_ je vezme s sebou.

### Lokální modely

Spusťte otevřený model na vlastním počítači pro své kódovací agenty. Vaše prompty a kód zůstávají na počítači; nic odeslaného modelu ho neopustí. Začněte tímto:

```bash
omarchy models use best text
```

Tím se pro tento počítač nastaví nejlepší textový model, tedy druh, který vaši agenti používají. Modely pro obrázky, video a hudbu mají každý svůj nejlepší: `omarchy models use best image`, `video` nebo `music`. Spusťte `omarchy models use best`, abyste viděli výběr pro tento počítač pro každý druh.

Nebo otevřete panel lokálních modelů jeho ikonou jiskřiček v horním panelu, vedle ikony agentů, nebo pomocí Super + Ctrl + Alt + X a zvolte +. Ikona se zobrazí, když se na tento počítač nějaký model hodí. Podman, který modely spouští, je součástí Omarchy, stejně jako sada nástrojů pro kontejnery NVIDIA na počítači NVIDIA, která jim dává GPU; pokud cokoli z toho chybí, první nastavení to nainstaluje. Omarchy poté vybere doporučený model pro tento počítač, stáhne ho a spustí. Očekávejte stažení o velikosti desítek GB a to, že během běhu modelu bude využita většina paměti počítače: Flash Next používá asi 100 GiB se svým plným kontextem 256K. Pokud paměť, kterou potřebuje, zabírají jiné modely, nastaví se jako zastavený, připravený ke spuštění, jakmile jeden zastavíte. Model se při odhlášení zastaví; zastavte ho sami, když paměť potřebujete na něco jiného.

`omarchy models list` zobrazí možnosti a vysvětlí, proč se některé nehodí. Chcete-li nastavit jiný, spusťte `omarchy models use <recipe>`. Dnes jsou pro počítače Strix Halo se 128 GB dostupné `qwen3.8-flash-next-gufo` a `qwen3.8-27b-gufo`; model 27B zabírá asi 40 GiB, takže nechává prostor pro další práci. Na 64GB notebooku s Intel Arc B390 běží `qwen3.6-35b-a3b-llamacpp` v asi 30 GiB. Nové recepty a doporučení přicházejí s `omarchy update`, prostřednictvím balíčku.

Každý model, který nastavíte, získá vlastní řádek v panelu lokálních modelů: tlačítko přehrávání pro jeho spuštění, pauza pro jeho zastavení a uvolnění paměti a tlačítko terminálu pro otevření agenta na něm. Nahoře pruh ukazuje, jak je paměť počítače rozdělena mezi samotnou Omarchy (systém a vaše aplikace), každý běžící model a to, co je volné. Najeďte na zastavený model a pruh ukáže, zda se vejde, nebo o kolik místa mu chybí. Několik jich může běžet najednou, když se do paměti vejdou společně; pokud se jeden nevejde, Omarchy řekne, který běžící model máte zastavit. Přetahováním řádků za jejich logo je můžete přeřadit a stisknutím Delete na vybraném řádku model i jeho stahování odstraníte.

Každý kódovací model, který nastavíte, získá také vlastní záznam ve spouštěči aplikací, pod názvem modelu a s logem jeho tvůrce, stejně jako přihlášení ke Claude, Codex nebo Grok jeden přidá. Otevře vašeho agenta na tomto modelu a model nejprve spustí, pokud neběží: terminál ukáže jeho načítání a předá řízení agentovi, jakmile bude připraven. Odebrání modelu odebere jeho záznam.

Ne každý model je určen ke kódování. Modely pro obrázky, video a hudbu se místo toho otevírají ve Fantasi, aplikaci Omarchy pro tvorbu obrázků, videa a hudby s modelem běžícím na tomto počítači, vybraném tam nebo z jejich řádku v panelu lokálních modelů.

Model dál běží přesně tak, jak byl nastaven, takže aktualizace Omarchy nikdy žádný nerestartuje pod vašimi agenty. Když má Omarchy novější runtime nebo novější váhy pro model, který máte nastavený, jeho řádek zobrazí tlačítko aktualizace: stiskněte ho a model se na pozadí nastaví znovu, přičemž stáhne pouze to, co se změnilo, a restartuje se na nové verzi. Model, který byl zastavený, zůstane zastavený. `omarchy models update` udělá totéž pro každý model z terminálu.

Z příkazového řádku dělají totéž `omarchy models start <recipe>` a `omarchy models stop <recipe>`, `omarchy models status` zobrazí každý model a `omarchy agent --local-model <recipe>` otevře tento model v pi, ať je váš výchozí agent jakýkoli. Chcete-li, aby váš lokální model byl tím, co otevírá klávesová zkratka agenta, konzole Quake a _Make something_, spusťte `omarchy default agent local` nebo označte běžící model hvězdičkou v panelu agentů. pi také vypisuje každý model, který jste nastavili, a ty na počítačích, se kterými jste se spárovali, ve svém vlastním výběru modelů, takže prosté `pi` se k nim dostane také. Připojit se může i každý klient kompatibilní s OpenAI: `status` zobrazí adresu každého modelu (první je `http://127.0.0.1:11435/v1`), název receptu je model a klíč je v `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` odstraní model a stahování, která žádný jiný model nepoužívá.

Runtime třetích stran jsou označeny svým vydavatelem. Omarchy spouští každý model bez přístupu k síti.

### Lokální LLM

Omarchy doporučuje dva způsoby provozování lokálních modelů LLM: LM Studio a Ollama. LM Studio poskytuje grafické rozhraní pro vyhledávání modelů s otevřenými váhami, jejich instalaci a spouštění. Je to skvělý způsob, jak snadno začít. Ollama nabízí CLI pro totéž provedené podobně. Ale pokud s lokálními modely začínáte, začal bych s LM Studio. Obě můžete nainstalovat v části _Install > AI_ v nabídce Omarchy.

### Skilly Omarchy

Skilly pro agenty pomáhají AI používat konkrétní nástroje konkrétním způsobem a Omarchy jich dodává sedm. Skill omarchy pokrývá přizpůsobení systému, například úpravu konfigurace Hyprland nebo nastavení panelu. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app a omarchy-make-game pokrývají vytváření něčeho nového, omarchy-contribute pokrývá nahlášení chyby nebo odeslání opravy upstream a omarchy-diagnose-crash prochází výpis paměti po pádu. Jsou propojeny symbolickými odkazy do adresářů skillů pro Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` a každý `~/.hermes/profiles/*/skills`) a obecného umístění `~/.agents/skills`, takže je většina harnessů zachytí automaticky. Složka skillu s vaším vlastním stejným názvem má přednost.

Ale tyto skilly byste měli považovat za experimentální. Různé modely je budou využívat s různým účinkem. Nejlepší je nejprve běžet v režimu plánování, abyste měli představu o tom, co by agent rád změnil. A pak buďte připraveni vrátit změny zpět nebo dokonce vyvolat `omarchy reinstall configs`, pokud agent všechno zpřehází.
