# AI

Omarchy obsahuje spouštěče pro níže uvedené kódovací agenty, aniž by za vás vybírala výchozího. Spuštěním příkazu nainstalujete jeho CLI při prvním použití a po zobrazení výzvy se ověříte. Hermes a OpenClaw jsou výjimky: přes mise se pro ně nic neinstaluje a výběrem kteréhokoli z nich se nastaví jeho vlastní samoaktualizační kopie, jak níže vysvětluje část _Desktop apps_.

### Instalace a aktualizace agentů

Kromě Hermes a OpenClaw tito agenti používají línou instalaci přes mise: první spuštění nainstaluje CLI a další spuštění je znovu použijí. mise také nejvýše jednou za čtyři hodiny zkontroluje, zda pro nainstalovaného agenta nevyšla nová verze, těsně před jeho spuštěním nebo na pozadí při zobrazení shell promptu. Pokud tato aktualizace selže nebo jste offline, spustí se nainstalovaná verze. `omarchy update` aktualizuje nainstalované agenty spolu se zbytkem Omarchy a `mup` aktualizuje pouze nástroje spravované přes mise.

Vlastní aktualizátor agenta, například `claude update`, `codex update` nebo tlačítko aktualizace v aplikaci, neaktualizuje instalaci spravovanou přes mise. `codex update` selže a `claude update` může hlásit úspěch, přičemž nainstaluje samostatnou kopii, kterou mise nesleduje. Pokud byste raději používali nativní instalátor a aktualizátor agenta, přidejte ho do `disable_tools`; viz [Předinstalované nástroje CLI](18-development-tools.md#preinstalled-cli-tools).

Chcete-li nainstalovat všechny nakonfigurované líné nástroje dříve, než je budete potřebovat, spusťte `mise install --include-lazy`. To zahrnuje i ostatní výchozí nástroje CLI Omarchy i agenty. Informace o instalaci jednoho nástroje nebo použití vlastní instalace najdete v části [Předinstalované nástroje CLI](18-development-tools.md#preinstalled-cli-tools).

`grok` se instaluje přes oficiální balíček `grok` od mise, stejně jako `claude` a `codex`. Spusťte `grok` nebo ho vyberte v části _Agent > Harness_. Přeskočte instalátor `curl | bash` na x.ai. Tato cesta umístí druhou kopii do `~/.grok/bin`, přidá ji na začátek `PATH` a přepíše wrapper Omarchy.

`dsh` otevře své prohlížečové UI na `127.0.0.1:3080`, přičemž adresář spuštění je jeho výchozím pracovním prostorem. Jeho prohlížečové UI nepřijímá žádný počáteční prompt, takže `omarchy agent prompt` ho otevře s promptem ve schránce k vložení. Omarchy ho spouští s předvolbou oprávnění bez schvalování od DeepSeek. DeepSeek Harness nahrává záznamy relací do DeepSeek, když používáte jeho oficiální API modelů; vypněte to v jeho prohlížečovém UI v části _Settings > General > Upload Session Log_. Zpětná vazba, kterou mu odešlete, se nahraje spolu s relací také, pokud ho nespustíte s `DSH_TELEMETRY_MODE=DISABLED`.

### Výchozí agent

Vyberte si výchozího agenta pomocí `omarchy default agent <name>` nebo v části _Agent > Harness_ v Omarchy Menu (`Super + Space`). Pokud agent ještě není nainstalován, jeho výběrem se nejprve nainstaluje a také získá vlastní spouštěč ve spouštěči aplikací vedle položky Agent. Čerstvá instalace Omarchy vás k tomuto výběru vyzve jednorázovým oznámením.

Výběr Claude se také pokusí nastavit jeho rozšíření prohlížeče pro Chromium, Chrome, Brave, Brave Origin a Edge. Nastavení rozšíření se vztahuje na všechny uživatele a může vyžadovat vaše systémové heslo; zrušení nebo neúspěšná instalace rozšíření přesto Claude vybere a spustí. Restartujte prohlížeč, v případě výzvy povolte rozšíření a přihlaste se do Claude, abyste dokončili jeho připojení. Spuštěním `/chrome` v Claude zkontrolujte připojení. Firefox a Zen toto rozšíření nepodporují. Pokud byl Claude vaším výchozím agentem již před přidáním tohoto nastavení, vyberte ho znovu, abyste rozšíření nainstalovali.

Jakmile si vyberete, `Super + Shift + Ctrl + A` spustí výchozího agenta ve vyhrazeném okně terminálu (nebo zobrazí výběr, pokud jste si ještě nevybrali). Můžete ho také spustit přímo do úkolu pomocí `omarchy agent prompt "Review this project"`. Freebuff a DeepSeek Harness nepřijímají žádný počáteční prompt, takže se místo toho otevřou s promptem ve schránce k vložení. Takto spuštění agenti běží bez dozoru ve svých příslušných režimech, kdy se nezastavují, aby se zeptali, takže buďte připraveni na to, že budou skutečně něco dělat! MiniMax Code takový režim pro své interaktivní relace nemá, takže žádá o oprávnění jako obvykle. A protože agenti odmítají zapamatovat si důvěru pro váš domovský adresář, spuštění z `$HOME` místo toho začínají v `~/Work`.

Existují také zkratky terminálu: `a` spustí výchozího agenta přímo v aktuálním terminálu, zatímco `c`, `cx` a `cy` spustí přímo OpenCode, Claude Code a Codex (opět v jejich režimech automatického schvalování). Změny motivu se synchronizují i do agentů: Claude Code, Pi, OpenCode a Hermes (jakmile ho Omarchy nainstaluje) všichni následují, když přepnete motiv Omarchy.

### Vaše pokyny pro agenty

Osobní pravidla pro každého agenta patří do `~/.agents/AGENTS.md`, vedle sdílených skills v `~/.agents/skills`. Otevřete ho v části _Agent > Instructions_, která ho také propojí do každého harnessu, který si udržuje vlastní globální soubor: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` od Copilot a tak dále. Crush a Amp čtou odkaz `~/.config/AGENTS.md`, zatímco omp, Kimi a DeepSeek Harness čtou přímo `~/.agents/AGENTS.md`. Výběr výchozího agenta ho také propojí. Soubor s pokyny, který jste již měli, se stane sdíleným, pokud ještě žádný neexistoval; jinak je uchován vedle odkazu jako `.bak`. Po instalaci dalšího agenta spusťte `omarchy agent instructions`, abyste propojení obnovili.

### Panel agentů

Horní panel má ikonu agentů. Než si agenta nastavíte, jeho panel vás provede přihlášením do Claude, Codex nebo Grok a první z nich se stane vaším výchozím agentem. Poté panel umístí každé předplatné na jednu stránku: každého agenta a účet s jeho plánem, měřič pro každé z jeho 5hodinových limitů relace a týdenních limitů s časem do jeho resetování (přejetím zobrazíte přesné procento), nebo zbývající předplacený zůstatek, pod řádkem, který rotuje tím, co jste použili napříč všemi, jako jsou tokeny tento týden a váš nejpoužívanější model. V části _Make something cool_ nabízí úvodní prompty pro nový motiv, plugin, aplikaci nebo hru, které předají úkol vašemu výchozímu agentovi. Aplikace se vytvářejí stejným způsobem jako vlastní Hype, Monologue a Omacut od Omarchy, v C++ a Qt Quick, podle agent skill omarchy-make-app, a kompilátor a části Qt, které potřebují, jsou nainstalovány. Hry jsou jedna stránka three.js v `~/Games/vibes`, podle agent skill omarchy-make-game, a všechny se otevírají z jednoho spouštěče Game Vibes v aktuálním motivu; načítají three.js z webu, takže ke spuštění potřebují připojení. Claude Code, Codex, Grok, Kimi, Cursor a jeho příděl Grok Bot, GitHub Copilot, Muse, Antigravity a Devin jsou pokryty hned po instalaci se svými limity, Kimchi se svým plánem, předplacenými kredity a rozpočty útraty a Hermes, Mistral Vibe a Qwen Code zobrazují své relace a tokeny, jakmile je použijete. Plány poskytovatelů a klíče, které používáte přes pi, omp nebo opencode, se také zobrazují: OpenCode Zen a Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan a Synthetic se svými limity; OpenRouter a DeepSeek se svými předplacenými zůstatky; Fireworks se svou útratou za posledních 30 dní. Tokeny z modelů, které provozujete na vlastním hardwaru, se také započítávají do součtů; samotné modely mají vlastní panel, popsaný v části [Lokální modely](#local-models). Každý agent se započítává jednou, u toho, kdo ho účtuje, bez ohledu na to, přes kolik harnessů ho řídíte.

Kliknutím levým tlačítkem na ikonu panelu nebo stisknutím `Super + Ctrl + X` otevřete panel, kliknutím pravým tlačítkem spustíte výchozího agenta a kliknutím prostředním tlačítkem obnovíte. Záznamy o využití, které za ním stojí, se každých 15 minut regenerují pomocí `omarchy agent usage update` a panel může dokonce sloučit využití z vašich ostatních počítačů přes synchronizovanou složku. Úplné nastavení najdete v README v `$OMARCHY_PATH/shell/plugins/agents/`.

### Několik předplatných

Pokud platíte za více než jeden plán Claude, Codex nebo Grok — například osobní Max a pracovní — Omarchy je může udržet všechny přihlášené a pohybovat se mezi nimi. Přidejte předplatné pomocí + v panelu agentů, který vás tím provede přímo tam, nebo pomocí `omarchy agent account add claude Work` (nebo `codex`, nebo `grok`). Pokud chybí, nainstaluje CLI. První účet pro poskytovatele se přihlašuje přes váš běžný prohlížeč, přesně tam, kde to CLI vždy hledá. Každý další se přihlašuje přes soukromé okno, takže účet, ke kterému je váš prohlížeč již přihlášen, nebude omylem zachycen; přihlaste se tam jako účet, který přidáváte, a nejprve zavřete všechna soukromá okna, která jste již měli otevřená. Nikdy se za tímto účelem neodhlasujte z CLI: odhlášení zruší uložené přihlášení a tento účet by musel být přidán znovu.

Chcete-li zkopírovat přihlášení k předplatnému na jiný počítač Omarchy přes SSH, spusťte `omarchy agent account copy user@laptop`. Odesílatel poskytne dočasného příjemce, když cíl žádného nainstalovaného nemá, takže starší počítače Omarchy mohou přijímat účty bez aktualizace. Nainstalovaní příjemci mají přednost. To zkopíruje všechna předplatná Claude, Codex a Grok; přidejte názvy poskytovatelů, abyste je vybrali, jako v `omarchy agent account copy laptop claude`. Názvy účtů a ID příkazů odpovídají zdroji, včetně účtů již přítomných v cíli. Nesouvisející cílové účty dostanou číselnou příponu, pokud se jejich názvy střetnou, a nastavení, skills, pluginy a historie konverzací zůstávají lokální na každém počítači.

Stávající cílové přihlašovací údaje zůstanou zachovány. Zdrojový účet, který je tam již přihlášen, má synchronizovaný název, aniž by se nahradily jeho přihlašovací údaje; ostatní účty se přidají vedle něj. Chcete-li nahradit uložené přihlašovací údaje pro odpovídající účty, použijte `omarchy agent account copy --replace laptop claude` poté, co na cíli ukončíte relace tohoto účtu. Čerstvý cíl také získá aktivní účet a předvolby přepínání zdroje; zavedený cíl si ponechá své vlastní.

Přihlašovací údaje cestují přes SSH a ukládají se do soukromých souborů na cíli, takže kopírujte pouze na počítače, kterým důvěřujete. Jedná se o jednorázovou kopii, nikoli o průběžnou synchronizaci. Obnovovací tokeny Codex může jiný počítač rotovat, takže zkopírované přihlášení bude potřebovat obnovení; samostatná přihlášení zůstávají nejspolehlivější volbou pro současné použití na několika počítačích. Viz [Pokyny Codex k ověřování účtů](https://developers.openai.com/codex/auth/ci-cd-auth).

Jeden účet na poskytovatele je aktivní a každá nová relace začíná jako on: `cx`, `cy`, prosté `claude`, `codex` nebo `grok`, cokoli spuštěné přes `omarchy agent` a skripty nebo editory, které najdou CLI na `PATH`. Přepněte pomocí `omarchy agent account use work` (a zpět pomocí `omarchy agent account use main`), nebo v panelu stisknutím čísla účtu a poté `Enter` (nebo kliknutím na jeho tlačítko Use). Běžící relace Claude se také přepnou, od jejich další zprávy: každá relace Claude běží v `~/.claude`, která vždy obsahuje přihlášení aktivního účtu. Relace Claude spuštěná ve vlastní složce účtu starší verzí Omarchy si toto přihlášení uchová, dokud neskončí, takže přepnutí tyto relace pojmenuje a dokončí se samo, jakmile zmizí. Běžící relace Codex a Grok zůstávají na účtu, se kterým začaly. Historie konverzací, nastavení, skills a pluginy jsou sdíleny napříč účty, takže `claude --continue` ve stejné složce pokračuje tam, kde jste na novém účtu skončili.

S více než jedním účtem panel zobrazuje limity každého účtu vedle sebe, přičemž aktivní je označen. Omarchy vás upozorní, když aktivní účet překročí 95 % limitu, a kliknutí na oznámení přepne na účet s největší rezervou. Nikdy se nepřepíná sama. Změňte práh pomocí `omarchy agent account threshold 90`. Pokud je každý účet nad prahem, dozvíte se o tom jednou, spolu s tím, který účet se uvolní jako první. Zatímco je aktivní účet do 15 bodů od svého prahu (80 % při výchozím nastavení), jeho limity se kontrolují každé tři minuty místo každých 15.

`omarchy agent account list` zobrazuje každý účet a jeho nejnovější limity, `omarchy agent account remove work` jeden zapomene a `omarchy agent account rename primary Hey` jeden přejmenuje (nebo klikněte na název účtu v panelu). Tyto příkazy pracují na účtech vašeho výchozího agenta; chcete-li dosáhnout na druhého poskytovatele, nejprve ho pojmenujte, jako v `omarchy agent account use codex side`. Přihlášení, které jste již měli v `~/.claude` nebo `~/.codex`, je účet _Main_. Účet Codex zůstává tam, kde je; účet Claude čeká ve vlastní složce, zatímco je aktivní jiný účet. Účet, který nebyl používán déle než přibližně osm hodin, může zobrazovat _Sign-in required_; klikněte na něj, abyste tento účet znovu přihlásili přímo v panelu, nebo na něj přepněte a spusťte relaci, která přihlášení obnoví sama. MCP servery, které přidáte pomocí `claude mcp add`, dosáhnou na každý účet Claude, protože všechny běží v `~/.claude`; u Codex a Grok servery, které jste měli, když byl účet přidán, přijdou spolu s ním, ale pozdější dosáhnou pouze na účet, ve kterém jste je přidali. Claude Desktop si udržuje vlastní přihlášení a nástroje Codex nebo Grok nakonfigurované s absolutní cestou k binárce CLI přepnutí nenásledují. Explicitní `CLAUDE_CONFIG_DIR`, `CODEX_HOME` nebo `GROK_HOME` má přednost před vybraným účtem.

### Diagnostika pádů

Omarchy sleduje systemd-coredump kvůli pádům procesů. Jakmile si vyberete výchozího agenta, jakýkoli váš program, který vytvoří core dump, přinese oznámení "Process crashed" — klikněte na něj a pád bude předán vašemu výchozímu agentovi spolu s dovedností omarchy-diagnose-crash od Omarchy, která agenta provede zjištěním faktů z core dumpu a rozhodnutím, zda pád stojí za nahlášení upstreamu. Můžete ho také spustit ručně proti libovolnému PID z `coredumpctl list` pomocí `omarchy agent crash <pid>`.

Sledování je ve výchozím nastavení zapnuté. Vypněte ho v části _Trigger > Toggle > Crash Capture Off_ (nebo pomocí `omarchy toggle crash-capture`) a oznámení přestanou; `omarchy agent crash <pid>` stále funguje ručně.

Pády lze také ztlumit po jednotlivých programech, což vám diagnostika na konci nabídne. `omarchy crash mute hyprland` zastaví oznámení pouze pro tento program, `omarchy crash mute hyprland off` je přivede zpět a `omarchy crash mute` samo o sobě vypíše, co jste ztlumili. Přijímá cestu k binárce stejně ochotně jako její název, takže `omarchy crash mute /usr/bin/hyprland` dělá totéž. Název s mezerou dejte do uvozovek, jako v `omarchy crash mute 'Some App'`. Všechno ostatní stále oznamuje a ztlumený program stále padá — to skrývá připomenutí, nic to neopravuje.

### Stolní aplikace

Menu _Install > AI_ obsahuje také několik grafických aplikací AI: Amp Desktop, Antigravity Desktop, desktopovou aplikaci ChatGPT, desktopovou aplikaci Claude (linuxová beta od Anthropic, s kartami Chat, Cowork a Claude Code), Grok Bot pro chatování s modely xAI, Herdr Desktop, Hermes Desktop, OpenClaw, desktopovou aplikaci Perplexity a T3 Code. Grok Bot je desktopová chatovací aplikace. Kódovací agent je příkaz `grok`.

Hermes Desktop je ten, o kterém je třeba vědět, protože počítač má jeden Hermes a ten patří aplikaci: Hermes se instaluje pouze přes aplikaci a příkaz `hermes`, který výchozí agent spouští, patří aplikaci. Výběr Hermes jako výchozího agenta nainstaluje totéž, co položka _Install > AI_: balíček a runtime Hermes v `~/.hermes` nastavený vlastním instalátorem Hermes, což při prvním použití trvá několik minut. Tento runtime je ten jeden Hermes, který používají terminálový příkaz `hermes`, výchozí agent i aplikace, a aktualizuje se sám pomocí `hermes update`, místo aby čekal na vydání Omarchy. Jeho instalace také předá Hermes motiv Omarchy jako skin s názvem `omarchy`, který všechny povrchy Hermes následují, když přepínáte motivy; pokud byste raději, aby to nedělal, vyberte jiný v nastavení Appearance v Hermes nebo pomocí `/skin` a Omarchy tuto volbu nechá být. Odebrání aplikace v části _Remove > AI_ nejprve zavře Hermes včetně brány, vezme s sebou tento runtime a zachová vaše chaty, vzpomínky a skills, které si Hermes sám napsal, pokud neřeknete jinak: zeptá se, s výchozí odpovědí ne, zda mají odejít i tato data a vaše nastavení připojení.

Desktopovým zážitkem OpenClaw je jeho Control UI, které se otevírá jako webová aplikace podporovaná jeho vlastní lokální bránou. OpenClaw žije v `~/.openclaw` a aktualizuje se sám: použijte tlačítko "Update Gateway" v Control UI nebo spusťte `openclaw update` a brána se restartuje na nové verzi. Omarchy pouze vybírá vydání, ze kterého čerstvá instalace začne. OpenClaw může být také vaším výchozím agentem: jeho výběr v části _Agent > Harness_ nastaví tutéž kopii v `~/.openclaw` a agent otevře terminálové UI OpenClaw připojené k jeho bráně. Odebrání OpenClaw v části _Remove > AI_ s sebou vezme službu brány a aplikaci a poté se zeptá, zda má odejít i `~/.openclaw`, protože to obsahuje vaše chaty a přihlašovací údaje spolu se samotným OpenClaw a runtime pluginů, které stahuje; ve výchozím nastavení si ho ponechá a opětovná instalace OpenClaw ho zase najde.

Herdr Desktop je desktopová aplikace [Herdr](https://herdr.dev): prostory, karty a panely terminálů a kódovacích agentů, které dál běží v jejím jádru, když okno zavřete. Pochází z vlastního instalátoru Herdr místo z balíčku, takže žije v `~/.local/share/herdr-app`, když ještě žádné nemáte, přinese své jádro do `~/.local/bin/herdr-core` a aktualizuje obojí samo. Sedí vedle příkazu `herdr`, který Omarchy dodává na `Super + Ctrl + Return`, místo aby ho nahrazovala, a získává přímé klávesy tohoto příkazu: `Alt + Return` a `Alt + Shift + Return` rozdělí panel dolů nebo doprava, `Alt + Escape` ho zavře, `Ctrl + Alt + Arrow` se pohybuje mezi panely, `Alt + 1..9` a `Alt + Left/Right` vybírají kartu a `Alt + Up/Down` se pohybují mezi prostory. `Ctrl + 1..9` vybírá prostor a `Alt + Shift + Up/Down` prochází agenty. Klávesy s prefixem `Ctrl + Space` zůstávají pouze pro terminál, protože aplikace nemůže pro sekvenci podržet prostou klávesu Ctrl. Omarchy je zapisuje do `~/.config/herdr-app/keys.json` a `omarchy-refresh-herdr-app` je vrací zpět. Jeho instalace vybere motiv Omarchy pro Herdr, který od té doby následuje váš motiv Omarchy. Herdr si udržuje jeden motiv pro světlý režim a jeden pro tmavý, takže po přepnutí mezi tmavým a světlým motivem Omarchy vyberte Omarchy ve výběru motivů Herdr ještě jednou pro druhý režim.

T3 Code běží ze svého oficiálního vydání AppImage v `~/.local/share/t3code` místo z balíčku, takže se aktualizuje sám. Jeho instalace se zeptá, zda začít na kanálu Stable nebo Nightly; později přepněte v nastavení T3 Code. Vaše vlákna a nastavení žijí v `~/.t3` a odebrání T3 Code v části _Remove > AI_ je vezme s sebou.

### Lokální modely

Spusťte otevřený model na vlastním počítači pro své kódovací agenty. Vaše prompty a kód zůstávají na počítači; nic odeslaného modelu ho neopustí. Začněte s:

```bash
omarchy models use best text
```

To nastaví nejlepší textový model pro tento počítač, ten druh, který vaši agenti používají. Modely obrázků, videa a hudby mají svůj vlastní nejlepší: `omarchy models use best image`, `video` nebo `music`. Spusťte `omarchy models use best`, abyste viděli výběr pro tento počítač pro každý druh.

Nebo otevřete panel lokálních modelů z jeho ikony jisker v horním panelu, vedle ikony agentů, nebo pomocí Super + Ctrl + Alt + X a zvolte +. Ikona se zobrazí, když se model na tento počítač vejde. Podman, který modely spouští, je součástí Omarchy, stejně jako sada nástrojů pro kontejnery NVIDIA na počítači NVIDIA, která jim poskytuje GPU; pokud některý z nich chybí, první nastavení ho nainstaluje. Omarchy poté vybere doporučený model pro tento počítač, stáhne ho a spustí. Očekávejte stažení desítek GB a to, že většina paměti počítače bude během běhu modelu využita: Flash Next používá asi 100 GiB se svým plným kontextem 256K. Pokud jiné modely drží paměť, kterou potřebuje, je nastaven zastavený, připravený ke spuštění, jakmile jeden zastavíte. Model se zastaví při odhlášení; zastavte ho sami, když paměť potřebujete na něco jiného.

`omarchy models list` zobrazuje možnosti a vysvětluje, proč se některé nevejdou. Chcete-li nastavit další, spusťte `omarchy models use <recipe>`. Dnes jsou pro počítače Strix Halo se 128 GB k dispozici `qwen3.8-flash-next-gufo` a `qwen3.8-27b-gufo`; 27B zabírá asi 40 GiB, takže nechává prostor pro další práci. Na 64GB notebooku s Intel Arc B390 běží `qwen3.6-35b-a3b-llamacpp` v asi 30 GiB. Nové recepty a doporučení přicházejí s `omarchy update`, přes balíček.

Každý model, který nastavíte, získá vlastní řádek v panelu lokálních modelů: tlačítko přehrát pro spuštění, pozastavit pro zastavení a uvolnění paměti a tlačítko terminálu pro otevření agenta na něm. Nahoře lišta ukazuje, jak je paměť počítače rozdělena mezi samotnou Omarchy (systém a vaše aplikace), každý běžící model a to, co je volné. Ukažte na zastavený model a lišta ukáže, zda se vejde, nebo o kolik mu chybí. Několik jich může běžet najednou, když se společně vejdou do paměti; pokud se jeden nevejde, Omarchy řekne, který běžící model zastavit. Přetažením řádků za jejich logo je přeřadíte a stisknutím Delete na vybraném řádku odstraníte model a jeho stažení.

Každý kódovací model, který nastavíte, také získá vlastní položku ve spouštěči aplikací, pod názvem modelu a s logem jeho tvůrce, stejně jako přihlášení do Claude, Codex nebo Grok jednu přidá. Otevře vašeho agenta na tomto modelu a nejprve model spustí, pokud neběží: terminál ukáže jeho načítání a předá agentovi, jakmile bude připraven. Odebrání modelu odebere jeho položku.

Ne každý model je pro kódování. Modely obrázků, videa a hudby se místo toho otevírají ve Fantasi, aplikaci Omarchy pro vytváření obrázků, videa a hudby s modelem běžícím na tomto počítači, vybraném tam nebo z jejich řádku v panelu lokálních modelů.

Model dál běží přesně tak, jak byl nastaven, takže aktualizace Omarchy nikdy žádný nerestartuje pod vašimi agenty. Když má Omarchy novější runtime nebo novější váhy pro model, který jste nastavili, jeho řádek zobrazí tlačítko aktualizace: stiskněte ho a model se znovu nastaví na pozadí, stáhne pouze to, co se změnilo, a restartuje se na nové verzi. Model, který byl zastaven, zůstane zastaven. `omarchy models update` dělá totéž pro každý model z terminálu.

Z příkazového řádku `omarchy models start <recipe>` a `omarchy models stop <recipe>` dělají totéž, `omarchy models status` zobrazuje každý model a `omarchy agent --local` otevře poslední model, který jste spustili, v pi, bez ohledu na to, jaký je váš výchozí agent. OpenCode a Qwen Code mohou také používat lokální model: `omarchy models harness opencode` nebo `omarchy models harness qwen` je místo toho otevře tam a `omarchy models harness pi` se vrátí zpět. pi také vypisuje každý model, který jste nastavili, a ty na počítačích, se kterými jste spárováni, ve svém vlastním výběru modelů, takže je dosáhne i prosté `pi`. Připojit se může i jakýkoli klient kompatibilní s OpenAI: `status` zobrazuje adresu každého modelu (první je `http://127.0.0.1:11435/v1`), název receptu je model a klíč je v `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` smaže model a stažení, která žádný jiný model nepoužívá.

Runtime třetích stran jsou označeny svým vydavatelem. Omarchy spouští každý model bez přístupu k síti.

### Lokální LLM

Omarchy doporučuje dva způsoby provozování lokálních modelů LLM: LM Studio a Ollama. LM Studio poskytuje GUI rozhraní pro hledání modelů s otevřenými váhami, jejich instalaci a spouštění. Je to skvělý způsob, jak snadno začít. Ollama nabízí CLI pro totéž podobně. Ale pokud jste v lokálních modelech noví, začal bych s LM Studio. Obojí můžete nainstalovat v části _Install > AI_ v Omarchy Menu.

### Skilly Omarchy

Agent skills pomáhají AI používat konkrétní nástroje konkrétním způsobem a Omarchy jich dodává sedm. Skill omarchy pokrývá přizpůsobení systému, jako je úprava konfigurace Hyprland nebo nastavení panelu. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app a omarchy-make-game pokrývají vytváření něčeho nového, omarchy-contribute pokrývá nahlášení chyby nebo odeslání opravy upstreamu a omarchy-diagnose-crash prochází core dump pádu. Jsou symlinkovány do adresářů skills pro Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` a každý `~/.hermes/profiles/*/skills`) a obecné umístění `~/.agents/skills`, takže je většina harnessů zachytí automaticky. Složka skillu s vaším vlastním stejným názvem má přednost.

Ale měli byste tyto skills považovat za experimentální. Různé modely je využijí s různým účinkem. Nejlepší je nejprve běžet v plánovacím režimu, abyste měli představu o tom, co by agent rád změnil. A pak buďte připraveni vrátit změny zpět nebo dokonce vyvolat `omarchy reinstall configs`, pokud agent všechno zpacká.
