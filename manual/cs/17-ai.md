### Instalace a aktualizace agentů

S výjimkou Hermes používají tito agenti línou instalaci přes mise: první spuštění nainstaluje CLI a další spuštění ho znovu použijí. mise také nejvýše jednou za čtyři hodiny zkontroluje, zda pro nainstalovaného agenta nevyšla nová verze, a to těsně před jeho spuštěním nebo na pozadí při promptu shellu. Pokud tato aktualizace selže nebo jste offline, spustí se nainstalovaná verze. `omarchy update` aktualizuje nainstalované agenty spolu se zbytkem Omarchy a `mup` aktualizuje pouze nástroje spravované přes mise.

Vlastní aktualizátor agenta, například `claude update`, `codex update` nebo tlačítko aktualizace v aplikaci, neaktualizuje instalaci spravovanou přes mise. `codex update` selže a `claude update` může hlásit úspěch, přičemž nainstaluje samostatnou kopii, kterou mise nesleduje. Pokud byste raději používali nativní instalátor a aktualizátor agenta, přidejte ho do `disable_tools`; viz [Předinstalované CLI nástroje](18-development-tools.md#preinstalled-cli-tools).

Chcete-li nainstalovat všechny nakonfigurované líné nástroje dříve, než je budete potřebovat, spusťte `mise install --include-lazy`. To zahrnuje i ostatní výchozí CLI nástroje Omarchy vedle agentů. Informace o instalaci jednoho nástroje nebo použití vlastní instalace najdete v části [Předinstalované CLI nástroje](18-development-tools.md#preinstalled-cli-tools).

`grok` se instaluje prostřednictvím prvostranového balíčku `grok` od mise, stejně jako `claude` a `codex`. Spusťte `grok` nebo ho vyberte pod _Agent > Harness_. Přeskočte instalátor `curl | bash` na x.ai. Ta cesta vloží druhou kopii do `~/.grok/bin`, přidá ji na začátek `PATH` a přepíše wrapper Omarchy.

`dsh` otevírá své prohlížečové UI na `127.0.0.1:3080`, přičemž adresář spuštění je jeho výchozím pracovním prostorem. Jeho prohlížečové UI nepřijímá počáteční prompt, takže `omarchy agent prompt` ho otevře s promptem ve vaší schránce k vložení. Omarchy ho spouští s předvolbou oprávnění bez schvalování od DeepSeek. DeepSeek Harness nahrává protokoly relací do DeepSeek, když používáte jeho oficiální API modelů; vypněte to v jeho prohlížečovém UI pod _Settings > General > Upload Session Log_. Zpětná vazba, kterou mu odešlete, se také nahrává spolu s relací, pokud ho nespustíte s `DSH_TELEMETRY_MODE=DISABLED`.

### Výchozí agent

Výchozího agenta vyberte příkazem `omarchy default agent <name>` nebo pod _Agent > Harness_ v Omarchy Menu (`Super + Space`). Pokud agent ještě není nainstalován, jeho výběrem se nejprve nainstaluje. Čerstvé Omarchy vás k tomuto výběru vyzve jednorázovým oznámením.

Výběr Claude se také pokusí nastavit jeho rozšíření prohlížeče pro Chromium, Chrome, Brave, Brave Origin a Edge. Nastavení rozšíření platí pro všechny uživatele a může vyžadovat vaše systémové heslo; zrušení nebo neúspěšná instalace rozšíření přesto Claude vybere a spustí. Restartujte prohlížeč, na výzvu povolte rozšíření a přihlaste se do Claude, abyste dokončili jeho připojení. Spuštěním `/chrome` v Claude zkontrolujete připojení. Firefox a Zen toto rozšíření nepodporují. Pokud byl Claude vaším výchozím agentem už před přidáním tohoto nastavení, vyberte ho znovu, abyste rozšíření nainstalovali.

Jakmile si vyberete, `Super + Shift + Ctrl + A` spustí výchozího agenta ve vyhrazeném okně terminálu (nebo vyvolá výběr, pokud jste si ještě nevybrali). Můžete ho také spustit rovnou do úkolu příkazem `omarchy agent prompt "Review this project"`. Freebuff a DeepSeek Harness nepřijímají počáteční prompt, takže se místo toho otevřou s promptem ve vaší schránce k vložení. Takto spuštění agenti běží bez dohledu ve svých příslušných režimech, kdy se nezastavují, aby se zeptali, takže buďte připraveni, že opravdu budou něco dělat! MiniMax Code takový režim pro své interaktivní relace nemá, takže se na oprávnění ptá jako obvykle. A protože agenti odmítají zapamatovat si důvěru pro váš domovský adresář, spuštění z `$HOME` místo toho začínají v `~/Work`.

Existují i zkratky v terminálu: `a` spustí výchozího agenta přímo v aktuálním terminálu, zatímco `c`, `cx` a `cy` spustí přímo OpenCode, Claude Code a Codex (opět v jejich režimech automatického schvalování). Změny tématu se synchronizují i do agentů: Claude Code, Pi, OpenCode a Hermes (jakmile ho Omarchy nainstaluje) se všechny přizpůsobí, když přepnete téma Omarchy.

### Pokyny pro vašeho agenta

Osobní pravidla pro každého agenta patří do `~/.agents/AGENTS.md`, vedle sdílených skillů v `~/.agents/skills`. Otevřete ho pod _Agent > Instructions_, což ho také propojí do každého harnessu, který si udržuje vlastní globální soubor: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, Copilotův `~/.copilot/copilot-instructions.md` a tak dále. Crush a Amp čtou odkaz `~/.config/AGENTS.md`, zatímco omp, Kimi a DeepSeek Harness čtou přímo `~/.agents/AGENTS.md`. Výběr výchozího agenta ho také propojí. Soubor pokynů, který jste už měli, se stane sdíleným, pokud ještě žádný neexistoval; jinak je uchován vedle odkazu jako `.bak`. Po instalaci dalšího agenta spusťte `omarchy agent instructions`, abyste znovu propojili.

### Panel agentů

V horní liště je ikona agentů. Než si agenta nastavíte, její panel vás provede přihlášením do Claude, Codex nebo Grok a první z nich se stane vaším výchozím agentem. Poté panel umístí každé předplatné na jednu stránku: každý agent a účet se svým plánem, měřič pro každý z jeho 5hodinových limitů relace a týdenních limitů s časem do jeho resetu (pro přesné procento najeďte myší) nebo zbývající předplacený zůstatek, pod řádkem, který střídá to, co jste použili napříč všemi, jako tokeny tento týden a váš nejpoužívanější model. Pod _Make something_ nabízí úvodní prompty pro nové téma, plugin, aplikaci nebo hru, které předají úkol vašemu výchozímu agentovi. Aplikace se vytvářejí tak, jak jsou vytvořeny vlastní Hype, Monologue a Omacut od Omarchy, v C++ a Qt Quick, podle agent skillu omarchy-make-app, a kompilátor a části Qt, které potřebují, jsou nainstalovány. Hry jsou jedna stránka three.js v `~/Games/vibes`, podle agent skillu omarchy-make-game, a všechny se otevírají z jednoho spouštěče Game Vibes v aktuálním tématu; načítají three.js z webu, takže ke spuštění potřebují připojení. Claude Code, Codex, Grok, Kimi, Cursor a jeho příděl Grok Bot, GitHub Copilot, Muse, Antigravity, Kimchi a Devin jsou pokryty hned po vybalení se svými limity a Hermes, Mistral Vibe a Qwen Code ukazují své relace a tokeny, jakmile je použijete. Plány poskytovatelů a klíče, které používáte prostřednictvím pi, omp nebo opencode, se také zobrazí: OpenCode Zen a Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan a Synthetic se svými limity; Fireworks, OpenRouter a DeepSeek se svými předplacenými zůstatky; a modely, které provozujete na vlastním hardwaru, pod Lokální modely. Každý agent se počítá jednou, pod tím, kdo ho účtuje, bez ohledu na to, přes kolik harnessů ho ovládáte.

Klikněte levým tlačítkem na ikonu v liště pro panel, pravým tlačítkem pro spuštění výchozího agenta. Záznamy o používání za ním jsou každých 15 minut znovu generovány příkazem `omarchy agent usage-update` a panel může dokonce sloučit používání z vašich ostatních počítačů prostřednictvím synchronizované složky. Úplné nastavení najdete v README pod `$OMARCHY_PATH/shell/plugins/agents/`.

### Několik předplatných

Pokud platíte za více než jeden plán Claude, Codex nebo Grok — například osobní Max a pracovní — Omarchy je může udržet všechny přihlášené a pohybovat se mezi nimi. Přidejte předplatné pomocí + v panelu agentů, které vás tím provede přímo tam, nebo příkazem `omarchy agent account add claude Work` (nebo `codex`, nebo `grok`). Nainstaluje CLI, pokud chybí. První účet pro poskytovatele se přihlašuje prostřednictvím vašeho běžného prohlížeče, přesně tam, kde CLI vždy hledá. Každý další se poté přihlašuje prostřednictvím soukromého okna, takže účet, ke kterému je váš prohlížeč již přihlášen, není omylem zachycen; přihlaste se tam jako účet, který přidáváte, a nejprve zavřete všechna soukromá okna, která jste již měli otevřená. Nikdy se za tímto účelem neodhlásujte z CLI: odhlášení zruší uložené přihlášení a ten účet by musel být znovu přidán.

Chcete-li zkopírovat přihlášení k předplatnému do jiného počítače Omarchy přes SSH, spusťte `omarchy agent account copy user@laptop`. Odesílatel dodá dočasného přijímače, když cílový počítač žádného nainstalovaného nemá, takže starší počítače Omarchy mohou přijímat účty bez aktualizace. Nainstalovaní přijímači mají přednost. To zkopíruje všechna předplatná Claude, Codex a Grok; přidejte názvy poskytovatelů, abyste je vybrali, jako v `omarchy agent account copy laptop claude`. Názvy účtů a ID příkazů odpovídají zdroji, včetně účtů již přítomných v cíli. Nesouvisející cílové účty dostanou číselnou příponu, pokud se jejich názvy střetnou, a nastavení, skilly, pluginy a historie konverzací zůstávají lokální pro každý počítač.

Existující cílové přihlašovací údaje jsou zachovány. Zdrojový účet, který je tam již přihlášen, má synchronizován svůj název, aniž by se nahradily jeho přihlašovací údaje; ostatní účty jsou přidány vedle něj. Chcete-li nahradit uložené přihlašovací údaje pro odpovídající účty, použijte `omarchy agent account copy --replace laptop claude` poté, co na cílovém počítači ukončíte relace tohoto účtu. Čerstvý cílový počítač také získá aktivní účet zdroje a preference přepínání; zavedený cílový počítač si ponechá své vlastní.

Přihlašovací údaje putují přes SSH a jsou uloženy v soukromých souborech na cílovém počítači, takže kopírujte pouze do počítačů, kterým důvěřujete. Jedná se o jednorázovou kopii, nikoli probíhající synchronizaci. Refresh tokeny Codexu mohou být rotovány jiným počítačem, takže zkopírované přihlášení potřebuje obnovení; samostatná přihlášení zůstávají nejspolehlivější volbou pro současné použití na několika počítačích. Viz [pokyny Codexu k ověřování účtu](https://developers.openai.com/codex/auth/ci-cd-auth).

Jeden účet na poskytovatele je aktivní a každá nová relace začíná jako on: `cx`, `cy`, prosté `claude`, `codex` nebo `grok`, cokoli spuštěného prostřednictvím `omarchy agent` a skripty nebo editory, které najdou CLI na `PATH`. Přepněte pomocí `omarchy agent account use work` (a zpět pomocí `omarchy agent account use main`) nebo v panelu stisknutím čísla účtu a poté `Enter` (nebo kliknutím na jeho tlačítko Use). Běžící relace Claude se přepnou také, od své další zprávy: každá relace Claude běží v `~/.claude`, které vždy obsahuje přihlášení aktivního účtu. Relace Claude spuštěná ve vlastní složce účtu starším Omarchy si uchovává toto přihlášení, dokud se neukončí, takže přepnutí tyto relace pojmenuje a dokončí se samo, jakmile zmizí. Běžící relace Codex a Grok zůstávají na účtu, se kterým začaly. Historie konverzací, nastavení, skilly a pluginy jsou sdíleny napříč účty, takže `claude --continue` ve stejné složce pokračuje tam, kde jste na novém účtu přestali.

S více než jedním účtem panel zobrazuje limity každého účtu vedle sebe, s označeným aktivním účtem. Ve výchozím nastavení vás Omarchy upozorní, když aktivní účet překročí 95 % limitu, a kliknutím na oznámení přepne na účet s největším prostorem. Najeďte myší na řádek účtu v panelu a klikněte na Autoswitch, které se objeví vedle Use (nebo stiskněte `m`), nebo spusťte `omarchy agent account mode auto`, aby se přepínalo samo; zatímco je zapnuté, Autoswitch zaujme místo Use a opětovným kliknutím se vrátíte k oznamování. Přidejte číslo, abyste změnili práh, jako v `omarchy agent account mode auto 90`. Pokud je každý účet nad prahem, dozvíte se to jednou, spolu s tím, který účet se uvolní jako první. Zatímco je aktivní účet do 15 bodů od svého prahu (80 % při výchozím nastavení), jeho limity se kontrolují každé tři minuty namísto každých 15.

`omarchy agent account list` zobrazuje každý účet a jeho nejnovější limity, `omarchy agent account remove work` jeden zapomene a `omarchy agent account rename primary Hey` jeden přejmenuje (nebo klikněte na název účtu v panelu). Tyto příkazy pracují na účtech vašeho výchozího agenta; chcete-li dosáhnout na jiného poskytovatele, nejprve ho pojmenujte, jako v `omarchy agent account use codex side`. Přihlášení, které jste již měli v `~/.claude` nebo `~/.codex`, je účet _Main_. Codexův zůstává tam, kde je; Claudeův čeká ve vlastní složce, zatímco je aktivní jiný účet. Účet ponechaný bez použití déle než zhruba osm hodin může zobrazovat _Sign-in required_; klikněte na něj, abyste ten účet znovu přihlásili přímo v panelu, nebo na něj přepněte a spusťte relaci, která přihlášení obnoví sama. MCP servery, které přidáte pomocí `claude mcp add`, dosáhnou na každý účet Claude, protože všechny běží v `~/.claude`; pro Codex a Grok servery, které jste měli, když byl účet přidán, přijdou spolu s ním, ale pozdější dosáhnou pouze na účet, ve kterém jste je přidali. Claude Desktop si udržuje vlastní přihlášení a nástroje Codex nebo Grok nakonfigurované s absolutní cestou k binárce CLI přepnutí nenásledují. Explicitní `CLAUDE_CONFIG_DIR`, `CODEX_HOME` nebo `GROK_HOME` má přednost před vybraným účtem.

### Diagnostika pádů

Omarchy sleduje systemd-coredump pro pády procesů. Když něco segfaultuje, dostanete oznámení „Process crashed“ — klikněte na něj a pád je předán vašemu výchozímu agentovi spolu se skillem diagnose-crash od Omarchy, který agenta provede zjištěním faktů z core dumpu a rozhodnutím, zda pád stojí za nahlášení upstreamu. Můžete ho také spustit ručně proti libovolnému PID z `coredumpctl list` pomocí `omarchy agent crash <pid>`.

Sledování je ve výchozím nastavení zapnuté. Vypněte ho pod _Trigger > Toggle > Crash Capture_ (nebo pomocí `omarchy toggle crash-capture`) a oznámení přestanou; `omarchy agent crash <pid>` stále funguje ručně.

Pády lze také umlčet po jednom programu, což je to, co vám diagnostika na konci nabízí. `omarchy crash mute hyprland` zastaví oznámení pouze pro ten program, `omarchy crash mute hyprland off` je přivede zpět a `omarchy crash mute` samo o sobě vypíše, co jste umlčeli. Přijímá cestu binárky stejně ochotně jako její název, takže `omarchy crash mute /usr/bin/hyprland` udělá totéž. Název s mezerou dejte do uvozovek, jako v `omarchy crash mute 'Some App'`. Všechno ostatní stále oznamuje a umlčený program stále padá — to skrývá připomenutí, nic to neopravuje.

### Desktopové aplikace

Nabídka _Install > AI_ také obsahuje několik grafických AI aplikací: desktopovou aplikaci ChatGPT, desktopovou aplikaci Claude (Linux beta od Anthropic, s kartami Chat, Cowork a Claude Code), Grok Bot pro chatování s modely xAI, Herdr Desktop, Hermes Desktop, OpenClaw, desktopovou aplikaci Perplexity a T3 Code. Grok Bot je desktopová chatovací aplikace. Kódovací agent je příkaz `grok`.

Hermes Desktop je ten, o kterém je třeba vědět, protože počítač má jeden Hermes a ten patří aplikaci: Hermes se vždy instaluje pouze prostřednictvím aplikace a příkaz `hermes`, který výchozí agent spouští, je ten od aplikace. Výběr Hermes jako výchozího agenta nainstaluje totéž, co položka _Install > AI_: balíček a runtime Hermes pod `~/.hermes` nastavený vlastním instalátorem Hermes, což poprvé trvá několik minut. Tento runtime je ten jeden Hermes, který používají terminálový příkaz `hermes`, výchozí agent i aplikace, a aktualizuje se sám pomocí `hermes update`, spíše než aby čekal na vydání Omarchy. Jeho instalace také předá Hermes téma Omarchy jako skin pojmenovaný `omarchy`, který každý povrch Hermes následuje, když přepínáte témata; vyberte jiný v nastavení Appearance Hermes nebo pomocí `/skin`, pokud byste raději, aby to nedělal, a Omarchy tu volbu nechá být. Odebrání aplikace pod _Remove > AI_ nejprve zavře Hermes, včetně gateway, vezme s sebou tento runtime a ponechá vaše chaty, vzpomínky a skilly, které si Hermes napsal sám, pokud neřeknete jinak: zeptá se, s výchozí odpovědí ne, zda by tato data a vaše nastavení připojení měla také zmizet.

Zážitek z desktopu OpenClaw je jeho Control UI, které se otevírá jako webová aplikace podporovaná vlastní lokální gateway. OpenClaw žije v `~/.openclaw` a aktualizuje se sám: použijte tlačítko „Update Gateway“ v Control UI nebo spusťte `openclaw update` a gateway se restartuje na nové verzi. Omarchy vybírá pouze vydání, ze kterého čerstvá instalace začíná. Odebrání OpenClaw pod _Remove > AI_ vezme s sebou službu gateway a aplikaci a poté se zeptá, zda by `~/.openclaw` mělo také zmizet, protože to uchovává vaše chaty a přihlašovací údaje vedle samotného OpenClaw a runtime pluginů, které stahuje; výchozí nastavení ho ponechává a opětovná instalace OpenClaw ho znovu zachytí.

Herdr Desktop je desktopová aplikace [Herdr](https://herdr.dev): prostory, karty a panely terminálů a kódovacích agentů, které stále běží v jejím jádru, když zavřete okno. Pochází z vlastního instalátoru Herdr spíše než z balíčku, takže žije v `~/.local/share/herdr-app`, přináší s sebou své jádro v `~/.local/bin/herdr-core`, když ještě žádné nemáte, a aktualizuje obojí sama. Sedí vedle příkazu `herdr`, který Omarchy dodává na `Super + Ctrl + Return`, spíše než aby ho nahrazovala, a dostává přímé klávesy tohoto příkazu: `Alt + Return` a `Alt + Shift + Return` rozdělí panel dolů nebo doprava, `Alt + Escape` ho zavře, `Ctrl + Alt + Arrow` se pohybuje mezi panely, `Alt + 1..9` a `Alt + Left/Right` vyberou kartu a `Alt + Up/Down` se pohybují mezi prostory. `Ctrl + 1..9` vybere prostor a `Alt + Shift + Up/Down` prochází agenty. Klávesy s prefixem `Ctrl + Space` zůstávají pouze pro terminál, protože aplikace nemůže držet prostou klávesu Ctrl pro sekvenci. Omarchy je zapisuje do `~/.config/herdr-app/keys.json` a `omarchy-refresh-herdr-app` je vrací zpět. Jeho instalace vybere téma Omarchy pro Herdr, které od té doby následuje vaše téma Omarchy. Herdr si uchovává jedno téma pro světlý režim a jedno pro tmavý, takže po přepnutí mezi tmavým a světlým tématem Omarchy vyberte Omarchy ve výběru témat Herdr ještě jednou pro druhý režim.

T3 Code běží ze svého oficiálního vydání AppImage v `~/.local/share/t3code` spíše než z balíčku, takže se aktualizuje sám. Jeho instalace se zeptá, zda začít na kanálu Stable nebo Nightly; později přepněte v nastavení T3 Code. Vaše vlákna a nastavení žijí v `~/.t3` a odebrání T3 Code pod _Remove > AI_ je vezme s sebou.

### Lokální modely

Provozujte otevřený model na vlastním počítači pro své kódovací agenty. Vaše prompty a kód zůstávají na počítači; nic odeslaného modelu ho neopouští. Začněte s:

```bash
omarchy agent local use best
```

Nebo v panelu agentů v horní liště vyberte + a poté Local AI, které se zobrazí, když se model vejde na tento počítač. Poprvé to nainstaluje Podman, který modely spouští, a na počítači NVIDIA sadu nástrojů pro kontejnery NVIDIA, která jim dává GPU. Omarchy poté vybere doporučený model pro tento počítač, stáhne ho a spustí. Očekávejte stažení desítek GB a to, že většina paměti počítače bude během běhu modelu využita: Flash Next používá se svým plným kontextem 256K asi 100 GiB. Pokud jiné modely drží paměť, kterou potřebuje, je nastaven jako zastavený, připravený ke spuštění, jakmile jeden zastavíte. Model se zastaví při odhlášení; zastavte ho sami, když paměť potřebujete na něco jiného.

`omarchy agent local list` zobrazuje možnosti a vysvětluje, proč některé nesedí. Chcete-li nastavit další, spusťte `omarchy agent local use <recipe>`. Dnes jsou pro počítače Strix Halo se 128 GB k dispozici `qwen3.8-flash-next-gufo` a `qwen3.8-27b-gufo`; 27B spotřebuje asi 40 GiB, takže ponechává prostor pro další práci. Na 64GB laptopu s Intel Arc B390 běží `qwen3.6-35b-a3b-llamacpp` v asi 30 GiB. Nové recepty a doporučení přicházejí s `omarchy update`, prostřednictvím balíčku.

Každý model, který nastavíte, dostane vlastní řádek v panelu agentů, vedle vašich předplatných: play pro jeho spuštění, pause pro jeho zastavení a uvolnění jeho paměti a tlačítko terminálu pro otevření vašeho agenta na něm. Několik jich může běžet najednou, když se společně vejdou do paměti; pokud se jeden nevejde, Omarchy řekne, který běžící model zastavit. Přetažením řádků je můžete přeřadit a stisknutím Delete na vybraném řádku odstraníte model a jeho stažení.

Každý model, který nastavíte, také dostane vlastní položku ve spouštěči aplikací, pod názvem modelu a s logem jeho tvůrce, stejně jako přihlášení do Claude, Codex nebo Grok přidá jednu. Otevře vašeho agenta na tom modelu a nejprve model spustí, pokud neběží: terminál ukazuje jeho načítání a předá agentovi, jakmile je připraven. Odebrání modelu odebere jeho položku.

Model stále běží přesně tak, jak byl nastaven, takže aktualizace Omarchy nikdy nerestartuje žádný pod vašimi agenty. Když má Omarchy novější runtime nebo novější váhy pro model, který jste nastavili, jeho řádek zobrazí tlačítko aktualizace: stiskněte ho a model je znovu nastaven na pozadí, přičemž stahuje pouze to, co se změnilo, a restartuje se na nové verzi. Model, který byl zastaven, zůstane zastaven. `omarchy agent local update` udělá totéž pro každý model z terminálu.

Z příkazového řádku `omarchy agent local start <recipe>` a `omarchy agent local stop <recipe>` dělají totéž, `omarchy agent local status` zobrazuje každý model a `omarchy agent --local` otevře vašeho výchozího agenta na posledním modelu, který jste spustili. pi, OpenCode a Qwen Code mohou jeden použít; s jakýmkoli jiným výchozím se otevře v pi. pi také vypisuje každý model, který jste nastavili, a ty na počítačích, se kterými jste spárováni, ve svém vlastním výběru modelů, takže je dosáhne i prosté `pi`. Může se připojit i libovolný klient kompatibilní s OpenAI: `status` zobrazuje adresu každého modelu (první je `http://127.0.0.1:11435/v1`), název receptu je model a klíč je v `~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` smaže model a stažení, která žádný jiný model nepoužívá.

Runtime třetích stran jsou označeny svým vydavatelem. Omarchy provozuje každý model bez přístupu k síti.

### Lokální LLM

Omarchy doporučuje dva způsoby provozování lokálních modelů LLM: LM Studio a Ollama. LM Studio poskytuje GUI rozhraní pro hledání modelů s otevřenými váhami, jejich instalaci a spouštění. Je to skvělý způsob, jak snadno začít. Ollama nabízí CLI pro totéž obdobně. Pokud jste však v lokálních modelech noví, začal bych s LM Studio. Obojí můžete nainstalovat pod _Install > AI_ v Omarchy Menu.

### Skill Omarchy

Agent skilly pomáhají AI používat konkrétní nástroje konkrétním způsobem a Omarchy je dodáván s výchozím skillem pro přizpůsobení systému. Jako je úprava vaší konfigurace Hyprland, úprava lišty nebo dokonce vytvoření nového tématu od nuly. Je propojen symlinkem do adresářů skillů pro Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` a každý `~/.hermes/profiles/*/skills`) a obecné umístění `~/.agents/skills`, takže ho většina harnessů zachytí automaticky.

Tento skill byste však měli považovat za experimentální. Různé modely ho budou používat s různým účinkem. Nejlepší je nejprve běžet v režimu plánování, abyste měli představu o tom, co by agent rád změnil. A poté buďte připraveni vrátit změny zpět nebo dokonce vyvolat `omarchy reinstall configs`, pokud agent všechno zpřehází.
