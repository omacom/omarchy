# AI

Omarchy obsahuje spouštěče pro níže uvedené kódovací agenty, aniž by za vás vybírala výchozího. Spuštěním příkazu nainstalujete jeho CLI při prvním použití, poté se ověříte, když budete vyzváni. Hermes a OpenClaw jsou výjimky: přes mise se pro ně nic neinstaluje a výběrem kteréhokoli z nich se nastaví jeho vlastní samoaktualizační kopie, jak vysvětlují _Desktopové aplikace_ níže.

### Instalace a aktualizace agentů

S výjimkou Hermes a OpenClaw tito agenti používají lazy instalaci přes mise: první spuštění nainstaluje CLI a další spuštění jej znovu použijí. mise také zkontroluje nainstalovaného agenta kvůli nové verzi nejvýše jednou za čtyři hodiny, těsně před jeho spuštěním nebo na pozadí na promptu shellu. Pokud tato aktualizace selže nebo jste offline, spustí se nainstalovaná verze. `omarchy update` aktualizuje nainstalované agenty spolu se zbytkem Omarchy a `mup` aktualizuje pouze nástroje spravované přes mise.

Vlastní aktualizátor agenta, například `claude update`, `codex update` nebo tlačítko aktualizace v aplikaci, neaktualizuje instalaci spravovanou přes mise. `codex update` selže a `claude update` může hlásit úspěch a přitom nainstalovat samostatnou kopii, kterou mise nesleduje. Pokud byste raději používali nativní instalátor a aktualizátor agenta, přidejte ho do `disable_tools`; viz [Předinstalované CLI nástroje](18-development-tools.md#preinstalled-cli-tools).

Chcete-li nainstalovat všechny nakonfigurované lazy nástroje dříve, než je budete potřebovat, spusťte `mise install --include-lazy`. To zahrnuje i ostatní výchozí CLI nástroje Omarchy i agenty. Instalace jednoho nástroje nebo použití vlastní instalace viz [Předinstalované CLI nástroje](18-development-tools.md#preinstalled-cli-tools).

`grok` se instaluje přes first-party balíček `grok` od mise, stejně jako `claude` a `codex`. Spusťte `grok` nebo ho označte hvězdičkou v panelu agentů. Přeskočte instalátor `curl | bash` na x.ai. Ta cesta umístí druhou kopii do `~/.grok/bin`, předřadí ji na `PATH` a přepíše wrapper Omarchy.

`dsh` otevírá své prohlížečové UI na `127.0.0.1:3080`, přičemž spouštěcí adresář je jeho výchozím pracovním prostorem. Jeho prohlížečové UI nepřijímá žádný počáteční prompt, takže `omarchy agent prompt` ho otevře s promptem ve vaší schránce k vložení. Omarchy ho spouští s předvolbou oprávnění no-approval od DeepSeek. DeepSeek Harness nahrává logy relací do DeepSeek, když používáte jeho oficiální API modelů; vypněte to v jeho prohlížečovém UI pod _Settings > General > Upload Session Log_. Zpětná vazba, kterou mu pošlete, se také nahrává spolu s relací, pokud ho nespustíte s `DSH_TELEMETRY_MODE=DISABLED`.

### Výchozí agent

Vyberte si výchozího agenta hvězdičkou vedle agenta v panelu agentů, která je u výchozího vyplněná, nebo pomocí `omarchy default agent <name>`, které přijme i jakýkoli harness, který tam nemá řádek. Pokud agent ještě není nainstalován, jeho výběrem se nejprve nainstaluje a také získá vlastní spouštěč ve spouštěči aplikací, vedle Agent. Čerstvá Omarchy vás vyzve k nastavení jednorázovým oznámením, které otevře panel agentů.

Výběr Claude se také pokusí nastavit jeho rozšíření prohlížeče pro Chromium, Chrome, Brave, Brave Origin a Edge. Nastavení rozšíření platí pro všechny uživatele a může vyžadovat vaše systémové heslo; zrušení nebo neúspěšná instalace rozšíření přesto vybere a spustí Claude. Restartujte prohlížeč, povolte rozšíření, když budete vyzváni, a přihlaste se do Claude, abyste dokončili jeho připojení. Spusťte `/chrome` v Claude pro kontrolu připojení. Firefox a Zen toto rozšíření nepodporují. Pokud byl Claude vaším výchozím agentem už před přidáním tohoto nastavení, vyberte ho znovu pro instalaci rozšíření.

Jakmile si vyberete, `Super + Shift + Ctrl + A` spustí výchozího agenta v samostatném okně terminálu (nebo vyvolá výběr, pokud jste si ještě nevybrali). Můžete ho také spustit rovnou do úkolu pomocí `omarchy agent prompt "Review this project"`. Freebuff a DeepSeek Harness nepřijímají žádný počáteční prompt, takže se místo toho otevřou s promptem ve vaší schránce k vložení. Takto spuštění agenti běží bez dozoru ve svých příslušných režimech don't-stop-to-ask, takže buďte připraveni na to, že budou skutečně něco dělat! MiniMax Code takový režim pro své interaktivní relace nemá, takže žádá o oprávnění jako obvykle. A protože agenti odmítají zapamatovat si důvěru pro váš domovský adresář, spuštění z `$HOME` místo toho začínají v `~/Work`.

Existují i zkratky v terminálu: `a` spustí výchozího agenta inline v aktuálním terminálu, zatímco `c`, `cx` a `cy` spouštějí OpenCode, Claude Code a Codex přímo (opět v jejich režimech automatického schvalování). Změny tématu se synchronizují i do agentů: Claude Code, Pi, OpenCode a Hermes (jakmile ho Omarchy nainstaluje) všechny následují, když přepnete téma Omarchy.

### Vaše pokyny pro agenty

Osobní pravidla pro každého agenta patří do `~/.agents/AGENTS.md`, vedle sdílených skills v `~/.agents/skills`. Otevřete ho ikonou dokumentu vedle + v panelu agentů nebo `omarchy agent instructions --edit`, které ho také propojí do každého harnessu, který si udržuje vlastní globální soubor: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, Copilotův `~/.copilot/copilot-instructions.md` atd. Crush a Amp čtou odkaz `~/.config/AGENTS.md`, zatímco omp, Kimi a DeepSeek Harness čtou `~/.agents/AGENTS.md` přímo. Výběr výchozího agenta ho propojí také. Soubor pokynů, který jste již měli, se stane sdíleným, pokud ještě žádný nebyl; jinak je uchován vedle odkazu jako `.bak`. Po instalaci dalšího agenta spusťte `omarchy agent instructions` pro opětovné propojení.

### Panel agentů

Horní lišta má ikonu agentů. Než si nastavíte agenta, jeho panel nabízí tři způsoby, jak začít: přihlásit se k předplatnému Claude, Codex, Grok, Gemini, Muse, Cursor nebo Copilot, nebo pod More k plánu kódování OpenCode Go, MiniMax, Synthetic nebo Z.ai; platit průběžně s Fireworks, OpenCode Zen a Go, OpenRouter, nebo pod More DeepSeek nebo jakýmkoli jiným poskytovatelem, ke kterému se OpenCode přihlašuje, vše běží v OpenCode; nebo spustit nejlepší model pro váš počítač, když se na něj nějaký vejde. První, který dokončíte, se stane vaším výchozím agentem a + v panelu nabízí tytéž tři možnosti i později. Poté panel umístí každé předplatné na jednu stránku: každý agent a účet s jeho plánem, měřič pro každý z jeho 5hodinových limitů relace a týdenních limitů s časem do jeho resetování (přesné procento zobrazíte najetím), nebo zbývající předplacený zůstatek, pod řádkem, který rotuje tím, co jste napříč všemi použili, jako tokeny tento týden a váš nejpoužívanější model. Pod _Make something cool_ nabízí startovací prompty pro nové téma, plugin, aplikaci nebo hru, které předají úkol vašemu výchozímu agentovi. Aplikace se vytvářejí tak, jak se vytvářejí vlastní Hype, Monologue a Omacut od Omarchy, v C++ a Qt Quick, podle agent skillu omarchy-make-app a kompilátor a části Qt, které potřebují, jsou nainstalované. Hry jsou jedna stránka three.js v `~/Games/vibes`, podle agent skillu omarchy-make-game, a všechny se otevírají z jednoho spouštěče Game Vibes v aktuálním tématu; načítají three.js z webu, takže ke spuštění potřebují připojení. Claude Code, Codex, Grok, Kimi, Cursor a jeho příděl Grok Bot, GitHub Copilot, Muse, Gemini (přes Antigravity) a Devin jsou pokryty hned po instalaci se svými limity, Kimchi se svým plánem, předplacenými kredity a rozpočty útraty a Hermes, Mistral Vibe a Qwen Code zobrazí své relace a tokeny, jakmile je použijete. Plány poskytovatelů a klíče, které používáte přes pi, omp nebo opencode, se také zobrazí: OpenCode Zen a Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan a Synthetic se svými limity; OpenRouter a DeepSeek se svými předplacenými zůstatky; Fireworks se svou útratou za posledních 30 dní. Kódovací modely, které provozujete na vlastním hardwaru, dostanou vlastní řádky a jejich tokeny se také započítávají do součtů, jak je popsáno pod [Místní modely](#local-models). Každý agent se započítává jednou, pod tím, kdo ho účtuje, bez ohledu na to, přes kolik harnessů ho ovládáte.

Kliknutím levým tlačítkem na ikonu v liště nebo stisknutím `Super + Ctrl + X` otevřete panel, kliknutím pravým spustíte výchozího agenta a kliknutím prostředním obnovíte. Záznamy o využití, které za ním stojí, se každých 15 minut regenerují pomocí `omarchy agent usage update` a panel může dokonce sloučit využití z vašich ostatních počítačů přes synchronizovanou složku. Úplné nastavení viz README pod `$OMARCHY_PATH/shell/plugins/agents/`.

### Několik předplatných

Pokud platíte za více než jeden plán Claude, Codex nebo Grok — třeba osobní Max a pracovní — Omarchy je může udržet všechny přihlášené a pohybovat se mezi nimi. Přidejte předplatné pomocí + v panelu agentů, které vás tím provede přímo tam, nebo pomocí `omarchy agent account add claude Work` (nebo `codex`, nebo `grok`). Stejné + a příkaz vás přihlásí do Gemini (`gemini`) a OpenCode (`opencode`) a uloží API klíč Fireworks (`fireworks`) nebo OpenRouter (`openrouter`) v OpenCode; příkaz vás také přihlásí do Copilot (`copilot`), Cursor (`cursor`) a Muse (`muse`). Ty si udržují po jednom přihlášení. Pokud chybí, nainstaluje CLI. První účet pro poskytovatele se přihlašuje přes váš normální prohlížeč, přímo tam, kam CLI vždy hledí. Každý další se přihlašuje přes soukromé okno, aby se omylem nezachytil účet, ke kterému je váš prohlížeč již přihlášen; přihlaste se tam jako účet, který přidáváte, a nejprve zavřete jakékoli soukromé okno, které jste již měli otevřené. Nikdy se za tímto účelem neodhlasujte z CLI: odhlášení zruší uložené přihlášení a ten účet by musel být znovu přidán.

Chcete-li zkopírovat přihlášení k předplatnému do jiného počítače s Omarchy přes SSH, spusťte `omarchy agent account copy user@laptop`. Odesílatel dodá dočasného příjemce, když cíl žádného nainstalovaného nemá, takže starší počítače s Omarchy mohou přijímat účty bez aktualizace. Nainstalovaní příjemci mají přednost. To kopíruje všechna předplatná Claude, Codex a Grok; přidejte názvy poskytovatelů pro jejich výběr, jako v `omarchy agent account copy laptop claude`. Názvy účtů a ID příkazů odpovídají zdroji, včetně účtů již přítomných v cíli. Nesouvisející cílové účty dostanou číselnou příponu, pokud se jejich názvy střetnou, a nastavení, skills, pluginy a historie konverzací zůstávají místní pro každý počítač.

Stávající cílové přihlašovací údaje zůstávají zachovány. Zdrojový účet, který je tam již přihlášen, má synchronizovaný název, aniž by se nahradily jeho přihlašovací údaje; ostatní účty se přidají vedle něj. Chcete-li nahradit uložené přihlašovací údaje pro odpovídající účty, použijte `omarchy agent account copy --replace laptop claude` poté, co ukončíte relace toho účtu v cíli. Čerstvý cíl také získá aktivní účet zdroje a preference přepínání; zavedený cíl si ponechá své vlastní.

Přihlašovací údaje cestují přes SSH a jsou uloženy v soukromých souborech v cíli, takže kopírujte pouze do počítačů, kterým důvěřujete. Jedná se o jednorázovou kopii, nikoli o průběžnou synchronizaci. Refresh tokeny Codex mohou být rotovány jiným počítačem, takže zkopírované přihlášení bude potřebovat obnovení; samostatná přihlášení zůstávají nejspolehlivější volbou pro současné použití na několika počítačích. Viz [Průvodce ověřováním účtů Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Jeden účet na poskytovatele je aktivní a každá nová relace začíná jako on: `cx`, `cy`, prosté `claude`, `codex` nebo `grok`, cokoli spuštěné přes `omarchy agent` a skripty nebo editory, které najdou CLI na `PATH`. Přepněte pomocí `omarchy agent account use work` (a zpět pomocí `omarchy agent account use main`) nebo v panelu stisknutím čísla účtu a poté `Enter` (nebo kliknutím na jeho hvězdičku). Běžící relace Claude se přepnou také, od jejich další zprávy: každá relace Claude běží v `~/.claude`, která vždy obsahuje přihlášení aktivního účtu. Relace Claude spuštěná ve vlastní složce účtu starší Omarchy si podrží to přihlášení, dokud neskončí, takže přepnutí ty relace pojmenuje a dokončí se samo, jakmile zmizí. Běžící relace Codex a Grok zůstávají na účtu, se kterým začaly. Historie konverzací, nastavení, skills a pluginy jsou sdíleny napříč účty, takže `claude --continue` ve stejné složce naváže tam, kde jste na novém účtu skončili.

S více než jedním účtem panel zobrazuje limity každého účtu vedle sebe, s vyplněnou hvězdičkou na tom používaném. Omarchy vás upozorní, když aktivní účet překročí 95 % limitu, a kliknutím na oznámení přepnete na účet s největším prostorem. Nikdy nepřepíná samo. Změňte práh pomocí `omarchy agent account threshold 90`. Pokud je každý účet nad prahem, dozvíte se to jednou, spolu s tím, který účet se uvolní jako první. Zatímco je aktivní účet do 15 bodů od svého prahu (80 % při výchozím nastavení), jeho limity se kontrolují každé tři minuty místo každých 15.

`omarchy agent account list` zobrazí každý účet a jeho nejnovější limity, `omarchy agent account remove work` jeden zapomene a `omarchy agent account rename primary Hey` jeden přejmenuje (nebo klikněte na název účtu v panelu). Tyto příkazy pracují s účty vašeho výchozího agenta; chcete-li dosáhnout na druhého poskytovatele, nejprve ho pojmenujte, jako v `omarchy agent account use codex side`. Přihlášení, které jste již měli v `~/.claude` nebo `~/.codex`, je účet _Main_. Účet Codex zůstává tam, kde je; účet Claude čeká ve vlastní složce, zatímco je aktivní jiný účet. Účet, který zůstal nepoužitý déle než asi osm hodin, může zobrazit _Sign-in required_; klikněte na něj, abyste ten účet znovu přihlásili přímo v panelu, nebo na něj přepněte a spusťte relaci, která přihlášení obnoví sama. MCP servery, které přidáte pomocí `claude mcp add`, dosáhnou na každý účet Claude, protože všechny běží v `~/.claude`; pro Codex a Grok servery, které jste měli, když byl účet přidán, přijdou s ním, ale pozdější dosáhnou pouze na účet, ve kterém jste je přidali. Claude Desktop si udržuje vlastní přihlášení a nástroje Codex nebo Grok nakonfigurované s absolutní cestou k binárce CLI přepnutí nenásledují. Explicitní `CLAUDE_CONFIG_DIR`, `CODEX_HOME` nebo `GROK_HOME` má přednost před vybraným účtem.

### Diagnostika pádů

Omarchy sleduje systemd-coredump kvůli pádům procesů. Jakmile si vyberete výchozího agenta, jakýkoli váš program, který vytvoří core dump, vyvolá oznámení "Process crashed" — klikněte na něj a pád bude předán vašemu výchozímu agentovi spolu se skillem omarchy-diagnose-crash od Omarchy, který agenta provede zjištěním faktů z core dumpu a rozhodnutím, zda pád stojí za nahlášení upstream. Můžete ho také spustit ručně proti jakémukoli PID z `coredumpctl list` pomocí `omarchy agent crash <pid>`.

Sledování je ve výchozím nastavení zapnuté. Vypněte ho pod _Trigger > Toggle > Crash Capture Off_ (nebo pomocí `omarchy toggle crash-capture`) a oznámení přestanou; `omarchy agent crash <pid>` stále funguje ručně.

Pády lze také ztlumit po jednotlivých programech, což vám diagnostika nabídne na konci. `omarchy crash mute hyprland` zastaví oznámení pouze pro ten program, `omarchy crash mute hyprland off` je vrátí zpět a `omarchy crash mute` samo o sobě vypíše, co jste ztlumili. Přijme cestu k binárce stejně rádo jako její název, takže `omarchy crash mute /usr/bin/hyprland` dělá totéž. Název s mezerou dejte do uvozovek, jako v `omarchy crash mute 'Some App'`. Vše ostatní stále oznamuje a ztlumený program stále padá — to skrývá připomenutí, nic to neopravuje.

### Desktopové aplikace

Nabídka _Install > AI_ obsahuje také několik grafických AI aplikací: Amp Desktop, Antigravity Desktop, desktopovou aplikaci ChatGPT, desktopovou aplikaci Claude (linuxovou betu od Anthropic, s kartami Chat, Cowork a Claude Code), Grok Bot pro chatování s modely xAI, Herdr Desktop, Hermes Desktop, OpenClaw, desktopovou aplikaci Perplexity a T3 Code. Grok Bot je desktopová chatovací aplikace. Kódovací agent je příkaz `grok`.

Hermes Desktop je ten, o kterém je třeba vědět, protože počítač má jeden Hermes a ten patří aplikaci: Hermes se instaluje pouze přes aplikaci a příkaz `hermes`, který výchozí agent spouští, je ten od aplikace. Výběr Hermes jako výchozího agenta nainstaluje totéž, co položka _Install > AI_: balíček a runtime Hermes pod `~/.hermes` nastavený vlastním instalátorem Hermes, což poprvé trvá několik minut. Ten runtime je ten jeden Hermes, který používají terminálový příkaz `hermes`, výchozí agent i aplikace, a aktualizuje se sám pomocí `hermes update`, místo aby čekal na vydání Omarchy. Jeho instalace také předá Hermes téma Omarchy jako skin pojmenovaný `omarchy`, který každé rozhraní Hermes následuje, když přepínáte témata; vyberte jiný v nastavení Appearance v Hermes nebo pomocí `/skin`, pokud byste raději, aby to nedělal, a Omarchy tu volbu nechá být. Odstranění aplikace pod _Remove > AI_ nejprve zavře Hermes, včetně gateway, vezme s sebou ten runtime a ponechá vaše chaty, vzpomínky a skills, které si Hermes sám pro sebe napsal, pokud neřeknete jinak: zeptá se, s výchozí odpovědí ne, zda by měla odejít i ta data a vaše nastavení připojení.

Desktopovým zážitkem OpenClaw je jeho Control UI, které se otevírá jako webová aplikace podporovaná vlastní místní gateway. OpenClaw žije v `~/.openclaw` a aktualizuje se sám: použijte tlačítko "Update Gateway" v Control UI nebo spusťte `openclaw update` a gateway se restartuje na nové verzi. Omarchy pouze vybírá vydání, ze kterého čerstvá instalace začíná. OpenClaw může být také vaším výchozím agentem: jeho výběr pomocí `omarchy default agent openclaw` nastaví tutéž kopii v `~/.openclaw` a agent otevře terminálové UI OpenClaw připojené k jeho gateway. Odstranění OpenClaw pod _Remove > AI_ vezme s sebou službu gateway a aplikaci a poté se zeptá, zda by mělo odejít i `~/.openclaw`, protože to obsahuje vaše chaty a přihlašovací údaje spolu se samotným OpenClaw a runtime pluginů, které stahuje; ve výchozím nastavení si ho ponechá a opětovná instalace OpenClaw ho zase najde.

Herdr Desktop je desktopová aplikace [Herdr](https://herdr.dev): prostory, karty a panely terminálů a kódovacích agentů, které dál běží v jeho jádru, když zavřete okno. Pochází z vlastního instalátoru Herdr místo z balíčku, takže žije v `~/.local/share/herdr-app`, přináší s sebou své jádro v `~/.local/bin/herdr-core`, když ještě žádné nemáte, a aktualizuje obojí samo. Sedí vedle příkazu `herdr`, který Omarchy dodává na `Super + Ctrl + Return`, místo aby ho nahrazovala, a dostává přímé klávesy toho příkazu: `Alt + Return` a `Alt + Shift + Return` rozdělí panel dolů nebo doprava, `Alt + Escape` ho zavře, `Ctrl + Alt + Arrow` přesouvá mezi panely, `Alt + 1..9` a `Alt + Left/Right` vybírají kartu a `Alt + Up/Down` přesouvají mezi prostory. `Ctrl + 1..9` vybírá prostor a `Alt + Shift + Up/Down` prochází agenty. Klávesy s prefixem `Ctrl + Space` zůstávají pouze pro terminál, protože aplikace nemůže podržet prostou klávesu Ctrl pro sekvenci. Omarchy je zapisuje do `~/.config/herdr-app/keys.json` a `omarchy-refresh-herdr-app` je vrací zpět. Jeho instalace vybere téma Omarchy pro Herdr, které od té chvíle následuje vaše téma Omarchy. Herdr si udržuje jedno téma pro světlý režim a jedno pro tmavý, takže po přepnutí mezi tmavým a světlým tématem Omarchy vyberte Omarchy ve výběru témat Herdr ještě jednou pro druhý režim.

T3 Code běží z oficiálního vydání AppImage v `~/.local/share/t3code` místo z balíčku, takže se aktualizuje sám. Jeho instalace se zeptá, zda začít na kanálu Stable nebo Nightly; později přepněte v nastavení T3 Code. Vaše vlákna a nastavení žijí v `~/.t3` a odstranění T3 Code pod _Remove > AI_ je vezme s sebou.

### Místní modely

Spusťte otevřený model na vlastním počítači pro své kódovací agenty. Vaše prompty a kód zůstávají na počítači; nic poslaného modelu ho neopustí. Začněte s:

```bash
omarchy models use best text
```

To nastaví nejlepší textový model pro tento počítač, ten druh, který vaši agenti používají. Modely pro obrázky, video a hudbu mají každý svůj nejlepší: `omarchy models use best image`, `video` nebo `music`. Spusťte `omarchy models use best`, abyste viděli výběr každého druhu pro tento počítač.

Nebo vyberte + v panelu agentů: pod _Use a local model_ vypíše každý kódovací model, který se na tento počítač vejde, doporučený jako první. Podman, který modely spouští, je součástí Omarchy, stejně jako sada nástrojů pro kontejnery od NVIDIA na počítači s NVIDIA, která jim dává GPU; pokud některý chybí, první nastavení ho nainstaluje. Omarchy poté vybere doporučený model pro tento počítač, stáhne ho a spustí. Očekávejte stažení desítek GB a využití většiny paměti počítače, zatímco model běží: Flash Next používá asi 100 GiB se svým plným kontextem 256K. Pokud jiné modely drží paměť, kterou potřebuje, je nastaven jako zastavený, připravený ke spuštění, jakmile nějaký zastavíte. Model se zastaví při odhlášení; zastavte ho sami, když potřebujete paměť na něco jiného.

`omarchy models list` zobrazí možnosti a vysvětlí, proč některé nesedí. Chcete-li nastavit jiný, spusťte `omarchy models use <recipe>`. Dnes jsou `qwen3.8-flash-next-gufo` a `qwen3.8-27b-gufo` k dispozici pro počítače Strix Halo se 128 GB; 27B zabírá asi 40 GiB, takže nechává prostor pro jinou práci. Na 64GB notebooku s Intel Arc B390 běží `qwen3.6-35b-a3b-llamacpp` v asi 30 GiB. Nové recepty a doporučení přicházejí s `omarchy update`, přes balíček.

Kódovací model, který přidáte, dostane vlastní řádek v panelu agentů, vedle vašich předplatných: play pro jeho spuštění, pause pro jeho zastavení a uvolnění jeho paměti, značku Tailscale pro jeho sdílení s ostatními počítači na vašem tailnetu, zatímco běží, a tlačítko terminálu pro otevření vašeho agenta na něm. Jeho řádek zobrazuje stahování, načítání nebo zastavování, jak probíhá, a řekne to, když není dost volné paměti pro jeho spuštění, nebo odkáže na jeho logy, když se zastavil s chybou. Několik jich může běžet najednou, když se spolu vejdou do paměti. Stiskněte Delete na vybraném řádku pro odstranění modelu z tohoto počítače, včetně stažení; + ho může znovu nastavit. Kódovací model nastavený z terminálu čeká pod +, dokud ho nepřidáte, stejně jako modely, které spouští počítač, se kterým jste se spárovali (`omarchy models pair <host>`).

Každý kódovací model, který nastavíte, také dostane vlastní položku ve spouštěči aplikací, pod názvem modelu a s logem jeho tvůrce, tak jako přihlášení do Claude, Codex nebo Grok jednu přidá. Otevře vašeho agenta na tom modelu a nejprve model spustí, pokud neběží: terminál zobrazí jeho načítání a předá ho agentovi, jakmile je připraven. Odstranění modelu odstraní jeho položku.

Ne každý model je pro kódování. Modely pro obrázky, video a hudbu se místo toho otevírají ve Fantasi, aplikaci Omarchy pro tvorbu obrázků, videa a hudby s modelem běžícím na tomto počítači, a spravují se tam nebo pomocí `omarchy models`.

Model dál běží přesně tak, jak byl nastaven, takže aktualizace Omarchy ho nikdy nerestartuje pod vašimi agenty. Když má Omarchy novější runtime nebo novější váhy pro model, který jste nastavili, jeho řádek zobrazí tlačítko aktualizace: stiskněte ho a model se znovu nastaví na pozadí, stáhne pouze to, co se změnilo, a restartuje se na nové verzi. Model, který byl zastaven, zůstane zastaven. `omarchy models update` dělá totéž pro každý model z terminálu.

Z příkazového řádku `omarchy models start <recipe>` a `omarchy models stop <recipe>` dělají totéž, `omarchy models status` zobrazí každý model a `omarchy agent --local-model <recipe>` otevře ten model v pi, ať je váš výchozí agent jakýkoli. Chcete-li, aby váš místní model byl tím, co otevírá klávesová zkratka agenta, konzole Quake a _Make something_, spusťte `omarchy default agent local` nebo označte hvězdičkou běžící model v panelu agentů. pi také vypíše každý model, který jste nastavili, a ty na počítačích, se kterými jste se spárovali, ve svém vlastním výběru modelů, takže je prosté `pi` také dosáhne. Připojit se může i jakýkoli klient kompatibilní s OpenAI: `status` zobrazí adresu každého modelu (první je `http://127.0.0.1:11435/v1`), název receptu je model a klíč je v `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` smaže model a stažení, která žádný jiný model nepoužívá.

Runtime třetích stran jsou označeny svým vydavatelem. Omarchy spouští každý model bez přístupu k síti.

### Místní LLM

Omarchy doporučuje dva způsoby provozování místních modelů LLM: LM Studio a Ollama. LM Studio poskytuje GUI rozhraní pro vyhledávání modelů s otevřenými váhami, jejich instalaci a spouštění. Je to skvělý způsob, jak snadno začít. Ollama nabízí CLI pro totéž obdobně. Ale pokud jste v místních modelech noví, začal bych s LM Studio. Obojí můžete nainstalovat pod _Install > AI_ v nabídce Omarchy.

### Skills Omarchy

Agent skills pomáhají AI používat konkrétní nástroje konkrétním způsobem a Omarchy jich dodává sedm. Skill omarchy pokrývá přizpůsobení systému, jako je ladění vaší konfigurace Hyprland nebo úprava lišty. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app a omarchy-make-game pokrývají tvorbu něčeho nového, omarchy-contribute pokrývá nahlášení chyby nebo odeslání opravy upstream a omarchy-diagnose-crash prochází core dump pádu. Jsou propojeny symlinks do adresářů skills pro Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` a každý `~/.hermes/profiles/*/skills`) a obecné umístění `~/.agents/skills`, takže je většina harnessů zachytí automaticky. Složka skillu s vaším vlastním stejným názvem má přednost.

Ale měli byste tyto skills považovat za experimentální. Různé modely je použijí s různým účinkem. Nejlepší je nejprve běžet v režimu plánování, abyste měli představu, co by agent rád změnil. A pak buďte připraveni vrátit změny zpět nebo dokonce vyvolat `omarchy reinstall configs`, pokud agent všechno zpacká.
