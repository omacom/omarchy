### Instalace a aktualizace agentů

Kromě Hermes tito agenti používají línou instalaci přes mise: první spuštění nainstaluje CLI a další spuštění ho znovu použijí. mise také nejvýše jednou za čtyři hodiny zkontroluje, zda pro nainstalovaného agenta nevyšla nová verze, těsně před jeho spuštěním nebo na pozadí při promptu shellu. Pokud tato aktualizace selže nebo jste offline, spustí se nainstalovaná verze. `omarchy update` aktualizuje nainstalované agenty spolu se zbytkem Omarchy a `mup` aktualizuje pouze nástroje spravované přes mise.

Vlastní aktualizátor agenta, například `claude update`, `codex update` nebo tlačítko aktualizace v aplikaci, neaktualizuje instalaci spravovanou přes mise. `codex update` selže a `claude update` může hlásit úspěch, přičemž nainstaluje samostatnou kopii, kterou mise nesleduje. Pokud byste raději používali nativní instalační program a aktualizátor agenta, přidejte ho do `disable_tools`; viz [Předinstalované nástroje CLI](18-development-tools.md#preinstalled-cli-tools).

Chcete-li nainstalovat všechny nakonfigurované líné nástroje dříve, než je budete potřebovat, spusťte `mise install --include-lazy`. To zahrnuje i ostatní výchozí nástroje CLI Omarchy i agenty. Viz [Předinstalované nástroje CLI](18-development-tools.md#preinstalled-cli-tools) pro instalaci jednoho nástroje nebo použití vlastní instalace.

`grok` se instaluje prostřednictvím prvotřídního balíčku `grok` od mise, stejně jako `claude` a `codex`. Spusťte `grok`, nebo ho vyberte v _Setup > Defaults > Agent_. Přeskočte instalační program `curl | bash` na x.ai. Tato cesta umístí druhou kopii do `~/.grok/bin`, předřadí ji na `PATH` a přepíše wrapper Omarchy.

`dsh` otevře své prohlížečové UI na `127.0.0.1:3080`, s adresářem spuštění jako výchozím pracovním prostorem. Jeho prohlížečové UI nepřijímá žádný počáteční prompt, takže `omarchy agent prompt` ho otevře s promptem ve vaší schránce k vložení. Omarchy ho spouští s presetem oprávnění bez schvalování od DeepSeek. DeepSeek Harness nahrává protokoly relací do DeepSeek, když používáte jeho oficiální API modelů; vypněte to v jeho prohlížečovém UI v _Settings > General > Upload Session Log_. Zpětná vazba, kterou mu pošlete, se nahraje spolu s relací také, pokud ho nespustíte s `DSH_TELEMETRY_MODE=DISABLED`.

### Výchozí agent

Vyberte si výchozího agenta pomocí `omarchy default agent <name>` nebo v _Setup > Defaults > Agent_ v Omarchy Menu (`Super + Space`). Pokud agent ještě není nainstalovaný, jeho výběrem se nejprve nainstaluje. Čerstvá Omarchy vás k této volbě vyzve jednorázovým oznámením.

Výběr Claude se také pokusí nastavit jeho rozšíření prohlížeče pro Chromium, Chrome, Brave, Brave Origin a Edge. Nastavení rozšíření platí pro všechny uživatele a může vyžadovat vaše systémové heslo; zrušení nebo neúspěšná instalace rozšíření přesto vybere a spustí Claude. Restartujte prohlížeč, povolte rozšíření, pokud k tomu budete vyzváni, a přihlaste se do Claude, abyste dokončili jeho připojení. Spusťte `/chrome` v Claude a zkontrolujte připojení. Firefox a Zen toto rozšíření nepodporují. Pokud už byl Claude vaším výchozím před přidáním tohoto nastavení, vyberte ho znovu, abyste rozšíření nainstalovali.

Jakmile si vyberete, `Super + Shift + Ctrl + A` spustí výchozího agenta ve vyhrazeném okně terminálu (nebo vyvolá výběr, pokud jste si ještě nevybrali). Můžete ho také spustit rovnou do úkolu pomocí `omarchy agent prompt "Review this project"`. Freebuff a DeepSeek Harness nepřijímají žádný počáteční prompt, takže se místo toho otevřou s promptem ve vaší schránce k vložení. Agenti spuštění tímto způsobem běží bez dozoru ve svých příslušných režimech, kdy se nezastavují, aby se zeptali, takže buďte připraveni na to, že budou skutečně něco dělat! MiniMax Code takový režim pro své interaktivní relace nemá, takže žádá o oprávnění jako obvykle. A protože agenti odmítají zapamatovat si důvěru pro váš domovský adresář, spuštění z `$HOME` začínají místo toho v `~/Work`.

Existují i zkratky terminálu: `a` spustí výchozího agenta inline v aktuálním terminálu, zatímco `c`, `cx` a `cy` spustí přímo OpenCode, Claude Code a Codex (opět v jejich režimech automatického schvalování). Změny motivu se synchronizují i do agentů: Claude Code, Pi, OpenCode a Hermes (jakmile ho Omarchy nainstaluje) všichni následují, když přepnete motiv Omarchy.

### Panel agentů

V horní liště je ikona agentů. Než si agenta nastavíte, její panel vás provede přihlášením do Claude, Codex nebo Grok a první z nich se stane vaším výchozím agentem. Poté panel umístí každé předplatné na jednu stránku: každého agenta a účet s jeho plánem, měřič pro každé z jeho 5hodinových limitů relace a týdenních limitů s časem do jeho resetování (přesné procento zobrazíte najetím), nebo zbývající předplacený zůstatek, pod řádkem, který rotuje tím, co jste použili napříč všemi, jako tokeny tento týden a váš nejpoužívanější model. V části _Make something_ nabízí úvodní prompty pro nový motiv, plugin nebo aplikaci, které předají úkol vašemu výchozímu agentovi. Aplikace se vytvářejí tak, jak se vytvářejí vlastní Hype, Monologue a Omacut Omarchy, v C++ a Qt Quick, podle skillu agenta omarchy-app, a kompilátor a části Qt, které potřebují, se dodávají nainstalované. Claude Code, Codex, Grok, Kimi, Cursor a jeho příděl Grok Bot, GitHub Copilot, Muse, Antigravity, Kimchi a Devin jsou pokryty hned po vybalení se svými limity a Hermes, Mistral Vibe a Qwen Code ukážou své relace a tokeny, jakmile je použijete. Plány poskytovatelů a klíče, které používáte přes pi, omp nebo opencode, se také zobrazí: OpenCode Zen a Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan a Synthetic se svými limity; Fireworks, OpenRouter a DeepSeek se svými předplacenými zůstatky; a modely, které provozujete na vlastním hardwaru v části Local models. Každý agent se počítá jednou, pod tím, kdo ho účtuje, bez ohledu na to, přes kolik harnessů ho řídíte.

Klikněte levým tlačítkem na ikonu v liště pro panel, klikněte pravým tlačítkem pro spuštění výchozího agenta. Záznamy o používání za ním se regenerují každých 15 minut pomocí `omarchy agent usage-update` a panel může dokonce sloučit používání z vašich ostatních strojů přes synchronizovanou složku. Úplné nastavení najdete v README v `$OMARCHY_PATH/shell/plugins/agents/`.

### Několik předplatných

Pokud platíte za více než jeden plán Claude, Codex nebo Grok — například osobní Max a pracovní — Omarchy je může udržet všechny přihlášené a pohybovat se mezi nimi. Přidejte předplatné pomocí + v panelu agentů, který vás tím provede přímo tam, nebo pomocí `omarchy agent account add claude Work` (nebo `codex`, nebo `grok`). Nainstaluje CLI, pokud chybí. První účet pro poskytovatele se přihlašuje přes váš normální prohlížeč, přesně tam, kde CLI vždy hledá. Každý další se poté přihlašuje přes soukromé okno, aby se účet, ke kterému je váš prohlížeč již přihlášen, omylem nezachytil; přihlaste se tam jako účet, který přidáváte, a nejprve zavřete všechna soukromá okna, která už máte otevřená. Nikdy se za tímto účelem neodhlasujte z CLI: odhlášení zruší uložené přihlášení a daný účet by musel být přidán znovu.

Chcete-li zkopírovat přihlášení k předplatnému na jiný stroj Omarchy přes SSH, spusťte `omarchy agent account copy user@laptop`. Odesílatel dodá dočasný přijímač, když ho cíl nemá nainstalovaného, takže starší stroje Omarchy mohou přijímat účty bez aktualizace. Nainstalované přijímače mají přednost. To zkopíruje všechna předplatná Claude, Codex a Grok; přidejte názvy poskytovatelů, abyste je vybrali, jako v `omarchy agent account copy laptop claude`. Názvy účtů a ID příkazů odpovídají zdroji, včetně účtů již přítomných v cíli. Nesouvisející cílové účty obdrží číselnou příponu, pokud se jejich názvy střetávají, a nastavení, skilly, pluginy a historie konverzací zůstávají lokální na každém stroji.

Existující cílové přihlašovací údaje se zachovají. Zdrojový účet, který je tam již přihlášen, má synchronizovaný název bez nahrazení jeho přihlašovacích údajů; ostatní účty se přidají vedle něj. Chcete-li nahradit uložené přihlašovací údaje pro odpovídající účty, použijte `omarchy agent account copy --replace laptop claude` po ukončení relací daného účtu v cíli. Čerstvý cíl také obdrží aktivní účet zdroje a předvolby přepínání; zavedený cíl si ponechá vlastní.

Přihlašovací údaje cestují přes SSH a jsou uloženy v soukromých souborech v cíli, takže kopírujte pouze na stroje, kterým důvěřujete. Jedná se o jednorázovou kopii, nikoli průběžnou synchronizaci. Obnovovací tokeny Codex může jiný stroj rotovat, takže zkopírované přihlášení bude potřebovat obnovení; samostatná přihlášení zůstávají nejspolehlivější volbou pro současné použití na několika strojích. Viz [Pokyny k ověřování účtu Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Jeden účet na poskytovatele je aktivní a každá nová relace začíná jako on: `cx`, `cy`, prosté `claude`, `codex` nebo `grok`, cokoli spuštěného přes `omarchy agent` a skripty nebo editory, které najdou CLI na `PATH`. Přepněte pomocí `omarchy agent account use work` (a zpět pomocí `omarchy agent account use main`), nebo v panelu stisknutím čísla účtu a poté `Enter` (nebo kliknutím na jeho tlačítko Use). Relace, které již běží, zůstávají na účtu, se kterým začaly. Historie konverzací, nastavení, skilly a pluginy se sdílejí napříč účty, takže `claude --continue` ve stejné složce pokračuje tam, kde jste na novém účtu přestali.

S více než jedním účtem panel zobrazuje limity každého účtu vedle sebe, s označeným aktivním. Ve výchozím nastavení vás Omarchy upozorní, když aktivní účet překročí 95 % limitu, a kliknutí na oznámení přepne na účet s největším prostorem. Najeďte na řádek účtu v panelu a klikněte na Autoswitch, které se zobrazí vedle Use (nebo stiskněte `m`), nebo spusťte `omarchy agent account mode auto`, aby se přepínalo samo místo toho; zatímco je zapnuté, Autoswitch zaujme místo Use a opětovným kliknutím se vrátíte k oznamování. Přidejte číslo pro změnu prahu, jako v `omarchy agent account mode auto 90`. Pokud je každý účet nad prahem, dozvíte se o tom jednou, spolu s tím, který účet se uvolní jako první. Zatímco je aktivní účet do 15 bodů od svého prahu (80 % při výchozím nastavení), jeho limity se kontrolují každé tři minuty, nikoli každých 15.

`omarchy agent account list` zobrazí každý účet a jeho nejnovější limity, `omarchy agent account remove work` jeden zapomene a `omarchy agent account rename primary Hey` jeden přejmenuje (nebo klikněte na název účtu v panelu). Tyto příkazy fungují na účtech vašeho výchozího agenta; chcete-li dosáhnout na druhého poskytovatele, nejprve ho pojmenujte, jako v `omarchy agent account use codex side`. Přihlášení, které jste již měli v `~/.claude` nebo `~/.codex`, je účet _Main_ a zůstává tam, kde je. Účet ponechaný nepoužívaný déle než zhruba osm hodin může zobrazovat _Sign-in required_; klikněte na něj, abyste daný účet znovu přihlásili přímo v panelu, nebo v něm spusťte relaci, která přihlášení obnoví sama. Servery MCP, které jste měli, když byl účet přidán, s ním přijdou, ale ty, které přidáte později pomocí `claude mcp add`, se dostanou pouze k účtu, ve kterém jste je přidali. Claude Desktop a nástroje nakonfigurované s absolutní cestou k binárnímu souboru CLI přepínač nenásledují. Explicitní `CLAUDE_CONFIG_DIR`, `CODEX_HOME` nebo `GROK_HOME` má přednost před vybraným účtem.

### Diagnostika pádů

Omarchy sleduje systemd-coredump kvůli pádům procesů. Když něco segfaultne, obdržíte oznámení "Process crashed" — klikněte na něj a pád se předá vašemu výchozímu agentovi spolu se skillem diagnose-crash od Omarchy, který agenta provede zjištěním faktů z výpisu jádra a rozhodnutím, zda pád stojí za nahlášení upstreamu. Můžete ho také spustit ručně proti libovolnému PID z `coredumpctl list` pomocí `omarchy agent crash <pid>`.

Sledování je ve výchozím nastavení zapnuté. Vypněte ho v _Trigger > Toggle > Crash Capture_ (nebo pomocí `omarchy toggle crash-capture`) a oznámení přestanou; `omarchy agent crash <pid>` stále funguje ručně.

Pády lze také ztlumit po jednom programu, což vám diagnostika na konci nabídne. `omarchy crash mute hyprland` zastaví oznámení pouze pro tento program, `omarchy crash mute hyprland off` je přivede zpět a samotné `omarchy crash mute` vypíše, co jste ztlumili. Přijímá cestu binárního souboru stejně ochotně jako jeho název, takže `omarchy crash mute /usr/bin/hyprland` dělá totéž. Název s mezerou uzavřete do uvozovek, jako v `omarchy crash mute 'Some App'`. Všechno ostatní stále oznamuje a ztlumený program stále padá — to skrývá připomenutí, nic to neopravuje.

### Desktopové aplikace

Nabídka _Install > AI_ obsahuje také několik grafických aplikací AI: desktopovou aplikaci ChatGPT, desktopovou aplikaci Claude (linuxovou betu od Anthropic, s kartami Chat, Cowork a Claude Code), Grok Bot pro chatování s modely xAI, Hermes Desktop, OpenClaw, desktopovou aplikaci Perplexity a T3 Code. Grok Bot je desktopová chatovací aplikace. Kódovací agent je příkaz `grok`.

Hermes Desktop je ten, o kterém je třeba vědět, protože stroj má jeden Hermes a ten patří aplikaci: Hermes se instaluje pouze prostřednictvím aplikace a příkaz `hermes`, který výchozí agent spouští, je ten od aplikace. Výběr Hermes jako výchozího agenta nainstaluje totéž, co položka _Install > AI_: balíček a runtime Hermes v `~/.hermes` nastavený vlastním instalačním programem Hermes, což poprvé trvá několik minut. Tento runtime je ten jeden Hermes, který používají terminálový příkaz `hermes`, výchozí agent i aplikace, a aktualizuje se sám pomocí `hermes update`, nikoli čekáním na vydání Omarchy. Jeho instalace také předá Hermes motiv Omarchy jako skin pojmenovaný `omarchy`, který každé rozhraní Hermes následuje při přepínání motivů; vyberte si jiný v nastavení Appearance v Hermes nebo pomocí `/skin`, pokud byste raději, aby to nedělal, a Omarchy tuto volbu nechá na pokoji. Odebrání aplikace v _Remove > AI_ nejprve zavře Hermes, včetně gateway, vezme s sebou tento runtime a ponechá vaše chaty, vzpomínky a skilly, které si Hermes sám pro sebe napsal, pokud neřeknete jinak: zeptá se, s výchozí odpovědí ne, zda má odejít i tato data a vaše nastavení připojení.

Desktopovým zážitkem OpenClaw je jeho Control UI, které se otevírá jako webová aplikace podporovaná vlastní lokální gateway. OpenClaw žije v `~/.openclaw` a aktualizuje se sám: použijte tlačítko "Update Gateway" v Control UI nebo spusťte `openclaw update` a gateway se restartuje na nové verzi. Omarchy volí pouze vydání, od kterého čerstvá instalace začíná. Odebrání OpenClaw v _Remove > AI_ s sebou vezme službu gateway a aplikaci a poté se zeptá, zda má odejít i `~/.openclaw`, protože to uchovává vaše chaty a přihlašovací údaje spolu se samotným OpenClaw a runtime pluginů, které stahuje; výchozí nastavení ho ponechá a opětovná instalace OpenClaw ho znovu převezme.

T3 Code běží ze svého oficiálního vydání AppImage v `~/.local/share/t3code`, nikoli z balíčku, takže se aktualizuje sám. Jeho instalace se zeptá, zda začít na kanálu Stable nebo Nightly; později přepněte v nastavení T3 Code. Vaše vlákna a nastavení žijí v `~/.t3` a odebrání T3 Code v _Remove > AI_ je vezme s sebou.

### Lokální modely

Spusťte otevřený model na vlastním stroji pro své kódovací agenty. Vaše prompty a kód zůstanou na stroji; nic odeslaného do modelu ho neopustí. Začněte s:

```bash
omarchy agent local use best
```

Nebo v panelu agentů v horní liště zvolte + a poté Local AI, které se zobrazí, když se model na tento stroj vejde. Poprvé to nainstaluje Podman, který modely spouští, a na stroji NVIDIA sadu nástrojů pro kontejnery NVIDIA, která jim poskytuje GPU. Omarchy poté vybere doporučený model pro tento stroj, stáhne ho a spustí. Očekávejte stažení desítek GB a většinu paměti stroje v použití, zatímco model běží: Flash Next používá asi 100 GiB se svým plným kontextem 256K. Pokud jiné modely drží paměť, kterou potřebuje, je nastaven jako zastavený, připravený ke spuštění, jakmile jeden zastavíte. Model se zastaví při odhlášení; zastavte ho sami, když potřebujete paměť pro něco jiného.

`omarchy agent local list` zobrazí možnosti a vysvětlí, proč se některé nevejdou. Chcete-li nastavit další, spusťte `omarchy agent local use <recipe>`. Dnes jsou `qwen3.8-flash-next-gufo` a `qwen3.8-27b-gufo` k dispozici pro stroje Strix Halo se 128 GB; 27B zabírá asi 40 GiB, takže ponechává prostor pro jinou práci. Nové recepty a doporučení přicházejí s `omarchy update`, prostřednictvím balíčku.

Každý model, který nastavíte, dostane vlastní řádek v panelu agentů, vedle vašich předplatných: přehrát pro spuštění, pauza pro zastavení a uvolnění jeho paměti a tlačítko terminálu pro otevření vašeho agenta na něm. Několik jich může běžet najednou, když se společně vejdou do paměti; pokud se jeden nevejde, Omarchy řekne, který běžící model zastavit. Přetáhněte řádky pro jejich přeřazení a stiskněte Delete na vybraném řádku pro odebrání modelu a jeho stažení.

Z příkazového řádku `omarchy agent local start <recipe>` a `omarchy agent local stop <recipe>` dělají totéž, `omarchy agent local status` zobrazí každý model a `omarchy agent --local` otevře vašeho výchozího agenta na posledním modelu, který jste spustili (pi, pokud váš výchozí agent nemůže používat lokální model). Připojit se může i libovolný klient kompatibilní s OpenAI: `status` zobrazí adresu každého modelu (první je `http://127.0.0.1:11435/v1`), název receptu je model a klíč je v `~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` smaže model a stažení, která žádný jiný model nepoužívá.

Runtime třetích stran jsou označeny svým vydavatelem. Omarchy spouští každý model bez přístupu k síti.

### Lokální LLM

Omarchy doporučuje dva způsoby provozování lokálních modelů LLM: LM Studio a Ollama. LM Studio poskytuje GUI rozhraní pro hledání modelů s otevřenými vahami, jejich instalaci a spouštění. Je to skvělý způsob, jak snadno začít. Ollama nabízí CLI pro totéž podobně. Ale pokud jste v lokálních modelech noví, začal bych s LM Studio. Obojí můžete nainstalovat v _Install > AI_ v Omarchy Menu.

### Skill Omarchy

Skilly agentů pomáhají AI používat konkrétní nástroje konkrétním způsobem a Omarchy se dodává s výchozím skillem pro přizpůsobení systému. Jako je úprava konfigurace Hyprland, úprava lišty nebo dokonce vytvoření nového motivu od nuly. Je symlinkován do adresářů skillů pro Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` a každý `~/.hermes/profiles/*/skills`) a obecné umístění `~/.agents/skills`, takže ho většina harnessů zachytí automaticky.

Ale tento skill byste měli považovat za experimentální. Různé modely ho budou používat s různým účinkem. Nejlepší je nejprve běžet v režimu plánování, abyste měli představu o tom, co by agent rád změnil. A pak buďte připraveni vrátit změny nebo dokonce vyvolat `omarchy reinstall configs`, pokud agent udělá ze všeho nepořádek.
