# AI

Hermes je výjimkou: při prvním použití se pro něj nic neinstaluje a jeho zvolením se nainstaluje Hermes Desktop, jak níže vysvětluje část _Desktopové aplikace_.

### Instalace a aktualizace agentů

S výjimkou Hermes tito agenti používají línou instalaci přes mise: první spuštění nainstaluje CLI a další spuštění ho znovu použijí. mise také nejvýše jednou za čtyři hodiny zkontroluje, zda pro nainstalovaného agenta nevyšla nová verze, a to těsně před jeho spuštěním nebo na pozadí při promptu shellu. Pokud tato aktualizace selže nebo jste offline, spustí se nainstalovaná verze. `omarchy update` aktualizuje nainstalované agenty spolu se zbytkem Omarchy a `mup` aktualizuje pouze nástroje spravované přes mise.

Vlastní aktualizátor agenta, například `claude update`, `codex update` nebo tlačítko aktualizace v aplikaci, neaktualizuje instalaci spravovanou přes mise. `codex update` selže a `claude update` může ohlásit úspěch a přitom nainstalovat samostatnou kopii, kterou mise nesleduje. Pokud raději chcete používat nativní instalátor a aktualizátor agenta, přidejte ho do `disable_tools`; viz [Předinstalované CLI nástroje](18-development-tools.md#preinstalled-cli-tools).

Chcete-li nainstalovat všechny nakonfigurované líné nástroje dříve, než je budete potřebovat, spusťte `mise install --include-lazy`. To zahrnuje i ostatní výchozí CLI nástroje Omarchy, nejen agenty. Informace o instalaci jednoho nástroje nebo použití vlastní instalace najdete v části [Předinstalované CLI nástroje](18-development-tools.md#preinstalled-cli-tools).

`grok` se instaluje přes oficiální balíček `grok` od mise, stejně jako `claude` a `codex`. Spusťte `grok` nebo ho vyberte v _Agent > Harness_. Přeskočte instalátor `curl | bash` na x.ai. Tudy se druhá kopie umístí do `~/.grok/bin`, přidá se na začátek `PATH` a přepíše wrapper od Omarchy.

`dsh` otevírá své prohlížečové UI na `127.0.0.1:3080`, přičemž adresář spuštění je jeho výchozím pracovním prostorem. Jeho prohlížečové UI nepřijímá úvodní prompt, takže `omarchy agent prompt` ho otevře s promptem ve vaší schránce k vložení. Omarchy ho spouští s předvolbou oprávnění bez schvalování od DeepSeek. DeepSeek Harness nahrává protokoly relací do DeepSeek, když používáte jeho oficiální API pro modely; vypněte to v jeho prohlížečovém UI v _Settings > General > Upload Session Log_. Zpětná vazba, kterou mu odešlete, se nahraje spolu s relací také, pokud ho nespustíte s `DSH_TELEMETRY_MODE=DISABLED`.

### Výchozí agent

Vyberte si výchozího agenta pomocí `omarchy default agent <name>` nebo v _Agent > Harness_ v Omarchy Menu (`Super + Space`). Pokud agent ještě není nainstalovaný, jeho zvolením se nejprve nainstaluje. Čerstvá Omarchy vás k této volbě vyzve jednorázovým oznámením.

Zvolení Claude se také pokusí nastavit jeho rozšíření prohlížeče pro Chromium, Chrome, Brave, Brave Origin a Edge. Nastavení rozšíření platí pro všechny uživatele a může vyžadovat vaše systémové heslo; zrušení nebo neúspěšná instalace rozšíření přesto Claude vybere a spustí. Restartujte prohlížeč, v případě výzvy povolte rozšíření a přihlaste se do Claude, abyste dokončili jeho připojení. Připojení zkontrolujte spuštěním `/chrome` v Claude. Firefox a Zen toto rozšíření nepodporují. Pokud už byl Claude vaším výchozím agentem předtím, než bylo toto nastavení přidáno, vyberte ho znovu, aby se rozšíření nainstalovalo.

Jakmile si vyberete, `Super + Shift + Ctrl + A` spustí výchozího agenta ve vyhrazeném okně terminálu (nebo zobrazí výběr, pokud jste si ještě nevybrali). Můžete ho také spustit rovnou do úkolu pomocí `omarchy agent prompt "Review this project"`. Freebuff a DeepSeek Harness nepřijímají úvodní prompt, takže se místo toho otevřou s promptem ve vaší schránce k vložení. Takto spuštění agenti běží bez dohledu ve svých režimech, ve kterých se nezastavují, aby se zeptali, takže buďte připraveni na to, že budou skutečně něco dělat! MiniMax Code takový režim pro své interaktivní relace nemá, takže žádá o oprávnění jako obvykle. A protože agenti odmítají zapamatovat si důvěru pro váš domovský adresář, spuštění z `$HOME` začínají místo toho v `~/Work`.

Existují i zkratky v terminálu: `a` spustí výchozího agenta inline v aktuálním terminálu, zatímco `c`, `cx` a `cy` spustí přímo OpenCode, Claude Code a Codex (opět v jejich režimech automatického schvalování). Změny motivu se synchronizují i do agentů: Claude Code, Pi, OpenCode a Hermes (jakmile ho Omarchy nainstalovala) se všechny přizpůsobí, když přepnete motiv Omarchy.

### Vaše pokyny pro agenty

Osobní pravidla pro každého agenta patří do `~/.agents/AGENTS.md`, vedle sdílených skills v `~/.agents/skills`. Otevřete ho v _Agent > Instructions_, které ho také propojí do každého harnessu, který si udržuje vlastní globální soubor: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, soubor Copilotu `~/.copilot/copilot-instructions.md` a tak dále. Crush a Amp čtou odkaz `~/.config/AGENTS.md`, zatímco omp, Kimi a DeepSeek Harness čtou přímo `~/.agents/AGENTS.md`. Zvolení výchozího agenta ho propojí také. Soubor s pokyny, který už jste měli, se stane sdíleným, pokud ještě žádný nebyl; jinak zůstane vedle odkazu jako `.bak`. Po instalaci dalšího agenta spusťte `omarchy agent instructions`, abyste propojení obnovili.

### Panel agentů

V horní liště je ikona agentů. Než si agenta nastavíte, její panel vás provede přihlášením do Claude, Codex nebo Grok a první z nich se stane vaším výchozím agentem. Poté panel umístí každé předplatné na jednu stránku: každého agenta a účet s jeho plánem, měřič pro každý z jeho 5hodinových limitů relace a týdenních limitů s časem do resetování (přesnou procentuální hodnotu zobrazíte najetím), nebo zbývající předplacený zůstatek, pod řádkem, který rotuje tím, co jste využili napříč všemi, například tokeny za tento týden a váš nejpoužívanější model. V části _Make something_ nabízí úvodní prompty pro nový motiv, plugin nebo aplikaci, které úkol předají vašemu výchozímu agentovi. Aplikace se vytvářejí tak, jak se vytvářejí vlastní Hype, Monologue a Omacut od Omarchy, v C++ a Qt Quick, podle agent skillu omarchy-app, a kompilátor a součásti Qt, které potřebují, se dodávají nainstalované. Claude Code, Codex, Grok, Kimi, Cursor a jeho příděl Grok Bot, GitHub Copilot, Muse, Antigravity, Kimchi a Devin jsou hned od začátku pokryty i se svými limity a Hermes, Mistral Vibe a Qwen Code zobrazí své relace a tokeny, jakmile je použijete. Objeví se i plány poskytovatelů a klíče, které používáte přes pi, omp nebo opencode: OpenCode Zen a Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan a Synthetic se svými limity; Fireworks, OpenRouter a DeepSeek se svými předplacenými zůstatky; a modely, které provozujete na vlastním hardwaru, v části Local models. Každý agent se počítá jednou, pod tím, kdo vám ho účtuje, bez ohledu na to, přes kolik harnessů ho řídíte.

Levým kliknutím na ikonu v liště otevřete panel, pravým kliknutím spustíte výchozího agenta. Záznamy o využití, které za ním stojí, každých 15 minut znovu generuje `omarchy agent usage-update` a panel může dokonce sloučit využití z vašich ostatních počítačů přes synchronizovanou složku. Úplné nastavení najdete v README v `$OMARCHY_PATH/shell/plugins/agents/`.

### Více předplatných

Pokud platíte za více než jeden plán Claude, Codex nebo Grok — například osobní Max a pracovní — Omarchy je může nechat všechny přihlášené a přepínat mezi nimi. Předplatné přidáte pomocí + v panelu agentů, který vás tím provede přímo tam, nebo pomocí `omarchy agent account add claude Work` (nebo `codex`, nebo `grok`). Pokud CLI chybí, nainstaluje ho. První účet pro poskytovatele se přihlašuje přes váš běžný prohlížeč, přesně tam, kam CLI vždy hledí. Každý další se přihlašuje přes soukromé okno, aby se omylem nevybral účet, ke kterému už je váš prohlížeč přihlášený; přihlaste se tam jako účet, který přidáváte, a nejprve zavřete všechna soukromá okna, která už máte otevřená. Kvůli tomu se nikdy neodhlasujte z CLI: odhlášení zneplatní uložené přihlášení a tento účet by bylo nutné přidat znovu.

Chcete-li zkopírovat přihlášení k předplatným na jiný počítač s Omarchy přes SSH, spusťte `omarchy agent account copy user@laptop`. Odesílatel poskytne dočasného příjemce, když cíl žádného nainstalovaného nemá, takže starší počítače s Omarchy mohou účty přijímat bez aktualizace. Nainstalovaní příjemci mají přednost. Tím se zkopírují všechna předplatná Claude, Codex a Grok; chcete-li je vybrat, přidejte názvy poskytovatelů, například `omarchy agent account copy laptop claude`. Názvy účtů a ID příkazů odpovídají zdroji, včetně účtů, které už na cíli existují. Nesouvisející cílové účty dostanou v případě konfliktu názvů číselnou příponu a nastavení, skills, pluginy a historie konverzací zůstávají lokální na každém počítači.

Stávající cílové přihlašovací údaje zůstanou zachovány. Zdrojový účet, který už tam je přihlášený, má synchronizovaný název, aniž by se nahradily jeho přihlašovací údaje; ostatní účty se přidají vedle něj. Chcete-li nahradit uložené přihlašovací údaje pro odpovídající účty, použijte `omarchy agent account copy --replace laptop claude` poté, co na cíli ukončíte relace tohoto účtu. Čerstvý cíl také získá aktivní účet a předvolby přepínání zdroje; zavedený cíl si ponechá své vlastní.

Přihlašovací údaje putují přes SSH a ukládají se do soukromých souborů na cíli, takže kopírujte pouze na počítače, kterým důvěřujete. Jde o jednorázové kopírování, ne o průběžnou synchronizaci. Obnovovací tokeny Codex může jiný počítač rotovat, čímž zkopírované přihlášení bude potřebovat obnovení; samostatná přihlášení zůstávají nejspolehlivější volbou pro současné použití na více počítačích. Viz [Pokyny Codex k ověřování účtů](https://developers.openai.com/codex/auth/ci-cd-auth).

Jeden účet na poskytovatele je aktivní a každá nová relace začíná jako on: `cx`, `cy`, prostý `claude`, `codex` nebo `grok`, cokoli spuštěného přes `omarchy agent` a skripty nebo editory, které CLI najdou na `PATH`. Přepnete pomocí `omarchy agent account use work` (a zpět pomocí `omarchy agent account use main`) nebo v panelu stisknutím čísla účtu a poté `Enter` (nebo kliknutím na jeho tlačítko Use). Relace, které už běží, zůstávají na účtu, se kterým začaly. Historie konverzací, nastavení, skills a pluginy se sdílejí napříč účty, takže `claude --continue` ve stejné složce naváže tam, kde jste na novém účtu přestali.

Při více než jednom účtu panel zobrazuje limity každého účtu vedle sebe, přičemž aktivní je označený. Omarchy vás ve výchozím nastavení upozorní, když aktivní účet překročí 95 % limitu, a kliknutím na oznámení přepnete na účet s největším zbývajícím prostorem. Najeďte na řádek účtu v panelu a klikněte na Autoswitch, které se objeví vedle Use (nebo stiskněte `m`), nebo spusťte `omarchy agent account mode auto`, aby místo toho přepínal sám; když je zapnuté, Autoswitch zaujme místo Use a opětovným kliknutím se vrátíte k upozorňování. Chcete-li změnit práh, přidejte číslo, například `omarchy agent account mode auto 90`. Pokud je každý účet nad prahem, dozvíte se to jednou, spolu s tím, který účet se uvolní jako první. Když je aktivní účet do 15 bodů od svého prahu (80 % při výchozím nastavení), jeho limity se kontrolují každé tři minuty místo každých 15.

`omarchy agent account list` zobrazí každý účet a jeho nejnovější limity, `omarchy agent account remove work` jeden zapomene a `omarchy agent account rename primary Hey` jeden přejmenuje (nebo klikněte na název účtu v panelu). Tyto příkazy pracují s účty vašeho výchozího agenta; chcete-li dosáhnout na jiného poskytovatele, nejprve ho pojmenujte, například `omarchy agent account use codex side`. Přihlášení, které už jste měli v `~/.claude` nebo `~/.codex`, je účet _Main_ a zůstává tam, kde je. Účet, který se nepoužívá déle než zhruba osm hodin, může zobrazovat _Sign-in required_; kliknutím na něj tento účet přímo v panelu znovu přihlásíte, nebo v něm spusťte relaci, která přihlášení obnoví sama. Servery MCP, které jste měli v době přidání účtu, s ním přijdou, ale ty, které přidáte později pomocí `claude mcp add`, se dostanou pouze k účtu, ve kterém jste je přidali. Claude Desktop a nástroje nakonfigurované s absolutní cestou k binárce CLI přepnutí nenásledují. Výslovné `CLAUDE_CONFIG_DIR`, `CODEX_HOME` nebo `GROK_HOME` má přednost před vybraným účtem.

### Diagnostika pádů

Omarchy sleduje systemd-coredump kvůli pádům procesů. Když něco segfaultuje, dostanete oznámení "Process crashed" — klikněte na něj a pád se předá vašemu výchozímu agentovi spolu se skillem diagnose-crash od Omarchy, který agenta provede zjištěním faktů z výpisu paměti a rozhodnutím, zda pád stojí za nahlášení upstreamu. Můžete ho také ručně spustit proti libovolnému PID z `coredumpctl list` pomocí `omarchy agent crash <pid>`.

Sledování je ve výchozím nastavení zapnuté. Vypněte ho v _Trigger > Toggle > Crash Capture_ (nebo pomocí `omarchy toggle crash-capture`) a oznámení přestanou; `omarchy agent crash <pid>` ručně funguje dál.

Pády lze také umlčet po jednom programu, což vám diagnostika na konci nabídne. `omarchy crash mute hyprland` zastaví oznámení pouze pro tento program, `omarchy crash mute hyprland off` je přivede zpět a samotné `omarchy crash mute` vypíše, co máte umlčené. Přijímá cestu k binárce stejně ochotně jako její název, takže `omarchy crash mute /usr/bin/hyprland` udělá totéž. Název s mezerou dejte do uvozovek, například `omarchy crash mute 'Some App'`. Vše ostatní dál upozorňuje a umlčený program dál padá — to skrývá připomínku, nic to neopravuje.

### Desktopové aplikace

Nabídka _Install > AI_ obsahuje i několik grafických AI aplikací: desktopovou aplikaci ChatGPT, desktopovou aplikaci Claude (linuxovou betaverzi od Anthropic s kartami Chat, Cowork a Claude Code), Grok Bot pro chatování s modely xAI, Herdr Desktop, Hermes Desktop, OpenClaw, desktopovou aplikaci Perplexity a T3 Code. Grok Bot je desktopová chatovací aplikace. Kódovací agent je příkaz `grok`.

Hermes Desktop je ta, o které musíte vědět, protože počítač má jeden Hermes a ten patří aplikaci: Hermes se vždy instaluje pouze přes aplikaci a příkaz `hermes`, který výchozí agent spouští, je ten od aplikace. Zvolení Hermes jako výchozího agenta nainstaluje totéž co položka _Install > AI_: balíček a runtime Hermes v `~/.hermes` nastavený vlastním instalátorem Hermes, což při prvním použití trvá několik minut. Tento runtime je ten jediný Hermes, který používají terminálový příkaz `hermes`, výchozí agent i aplikace, a aktualizuje se sám pomocí `hermes update`, místo aby čekal na vydání Omarchy. Jeho instalace také předá Hermes motiv Omarchy jako skin pojmenovaný `omarchy`, který každá plocha Hermes následuje, když přepínáte motivy; pokud nechcete, aby tomu tak bylo, vyberte jiný v nastavení Appearance v Hermes nebo pomocí `/skin` a Omarchy tuto volbu nechá na pokoji. Odebrání aplikace v _Remove > AI_ nejprve zavře Hermes, včetně gateway, vezme s sebou tento runtime a ponechá vaše chaty, vzpomínky a skills, které si Hermes sám napsal, pokud neurčíte jinak: zeptá se, přičemž výchozí odpověď je ne, zda mají zmizet i tato data a vaše nastavení připojení.

Desktopovým prostředím OpenClaw je jeho Control UI, které se otevírá jako webová aplikace podporovaná jeho vlastní lokální gateway. OpenClaw žije v `~/.openclaw` a aktualizuje se sám: použijte tlačítko "Update Gateway" v Control UI nebo spusťte `openclaw update` a gateway se na nové verzi restartuje. Omarchy pouze vybírá vydání, od kterého čerstvá instalace začíná. Odebrání OpenClaw v _Remove > AI_ s sebou vezme službu gateway a aplikaci a poté se zeptá, zda má zmizet i `~/.openclaw`, protože tam jsou vedle samotného OpenClaw a runtime pluginů, které stahuje, vaše chaty a přihlašovací údaje; výchozí chování ho ponechá a opětovná instalace OpenClaw ho znovu převezme.

Herdr Desktop je desktopová aplikace [Herdr](https://herdr.dev): prostory, karty a panely terminálů a kódovacích agentů, které dál běží v jejím jádru, když okno zavřete. Pochází z vlastního instalátoru Herdr místo z balíčku, takže žije v `~/.local/share/herdr-app`, přináší si své jádro do `~/.local/bin/herdr-core`, když ještě žádné nemáte, a obojí si sama aktualizuje. Sedí vedle příkazu `herdr`, který Omarchy dodává na `Super + Ctrl + Return`, místo aby ho nahrazovala, a dostává přímé klávesy tohoto příkazu: `Alt + Return` a `Alt + Shift + Return` rozdělí panel dolů nebo doprava, `Alt + Escape` ho zavře, `Ctrl + Alt + Arrow` se přesouvá mezi panely, `Alt + 1..9` a `Alt + Left/Right` vybírají kartu a `Alt + Up/Down` se přesouvají mezi prostory. `Ctrl + 1..9` vybírá prostor a `Alt + Shift + Up/Down` prochází agenty. Klávesy s prefixem `Ctrl + Space` zůstávají pouze pro terminál, protože aplikace nemůže pro sekvenci držet prostou klávesu Ctrl. Omarchy je zapisuje do `~/.config/herdr-app/keys.json` a `omarchy-refresh-herdr-app` je vrátí zpět. Jeho instalace vybere motiv Omarchy pro Herdr, který od té doby následuje váš motiv Omarchy. Herdr si udržuje jeden motiv pro světlý režim a jeden pro tmavý, takže po přepnutí mezi tmavým a světlým motivem Omarchy vyberte Omarchy ve výběru motivů Herdr ještě jednou pro druhý režim.

T3 Code běží ze svého oficiálního vydání AppImage v `~/.local/share/t3code` místo z balíčku, takže se aktualizuje sám. Při jeho instalaci se zeptá, zda chcete začít na kanálu Stable nebo Nightly; později to přepnete v nastavení T3 Code. Vaše vlákna a nastavení žijí v `~/.t3` a odebrání T3 Code v _Remove > AI_ je vezme s sebou.

### Lokální modely

Spusťte otevřený model na vlastním počítači pro své kódovací agenty. Vaše prompty a kód zůstanou na počítači; nic odeslaného modelu ho neopustí. Začněte tímto:

```bash
omarchy agent local use best
```

Nebo v panelu agentů v horní liště zvolte + a poté Local AI, které se objeví, když se na tento počítač model vejde. Při prvním použití to nainstaluje Podman, který modely spouští, a na počítači s NVIDIA sadu nástrojů pro kontejnery NVIDIA, která jim poskytne GPU. Omarchy poté vybere doporučený model pro tento počítač, stáhne ho a spustí. Počítejte se stahováním desítek GB a s tím, že zatímco model běží, bude využita většina paměti počítače: Flash Next používá asi 100 GiB se svým plným kontextem 256K. Pokud jiné modely drží paměť, kterou potřebuje, je nastaven jako zastavený, připravený ke spuštění, jakmile jeden zastavíte. Model se zastaví při odhlášení; zastavte ho sami, když paměť potřebujete na něco jiného.

`omarchy agent local list` zobrazí možnosti a vysvětlí, proč některé nesedí. Chcete-li nastavit jiný, spusťte `omarchy agent local use <recipe>`. Dnes jsou pro počítače Strix Halo se 128 GB k dispozici `qwen3.8-flash-next-gufo` a `qwen3.8-27b-gufo`; 27B zabírá asi 40 GiB, takže nechává prostor pro další práci. Nové recepty a doporučení přicházejí s `omarchy update`, přes balíček.

Každý model, který nastavíte, dostane vlastní řádek v panelu agentů, vedle vašich předplatných: play pro spuštění, pause pro zastavení a uvolnění jeho paměti a tlačítko terminálu pro otevření vašeho agenta na něm. Několik jich může běžet najednou, když se společně vejdou do paměti; pokud se jeden nevejde, Omarchy řekne, který běžící model zastavit. Přetažením řádků je můžete přeuspořádat a stisknutím Delete na vybraném řádku odeberete model i jeho stažené soubory.

Z příkazové řádky totéž udělají `omarchy agent local start <recipe>` a `omarchy agent local stop <recipe>`, `omarchy agent local status` zobrazí každý model a `omarchy agent --local` otevře vašeho výchozího agenta na posledním modelu, který jste spustili (pi, pokud váš výchozí agent nemůže používat lokální model). Připojit se může i libovolný klient kompatibilní s OpenAI: `status` zobrazí adresu každého modelu (první je `http://127.0.0.1:11435/v1`), název receptu je model a klíč je v `~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` odstraní model a stažené soubory, které žádný jiný model nepoužívá.

Runtime třetích stran jsou označeny svým vydavatelem. Omarchy spouští každý model bez přístupu k síti.

### Lokální LLM

Omarchy doporučuje dva způsoby provozování lokálních modelů LLM: LM Studio a Ollama. LM Studio poskytuje grafické rozhraní pro hledání modelů s otevřenými váhami, jejich instalaci a spouštění. Je to skvělý způsob, jak snadno začít. Ollama nabízí CLI pro totéž podobným způsobem. Ale pokud jste v lokálních modelech noví, začal bych s LM Studio. Obojí můžete nainstalovat v _Install > AI_ v Omarchy Menu.

### Skill pro Omarchy

Skills agentů pomáhají AI používat konkrétní nástroje konkrétním způsobem a Omarchy se dodává s výchozím skillem pro úpravu systému na míru. Třeba vyladění konfigurace Hyprland, úprava lišty nebo dokonce vytvoření zcela nového motivu. Je symlinkován do adresářů skills pro Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` a každý `~/.hermes/profiles/*/skills`) a obecné umístění `~/.agents/skills`, takže ho většina harnessů automaticky zachytí.

Ale měli byste tento skill považovat za experimentální. Různé modely ho využijí s různým efektem. Nejlepší je nejprve ho spustit v plánovacím režimu, abyste měli představu, co by agent rád změnil. A pak buďte připraveni vrátit změny zpět, nebo dokonce spustit `omarchy reinstall configs`, pokud agent všechno zpacká.
