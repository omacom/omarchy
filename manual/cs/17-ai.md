### Instalace a aktualizace agentů

Kromě Hermes tito agenti používají lazy instalaci přes mise: první spuštění nainstaluje CLI a pozdější spuštění ho znovu použijí. mise také nejvýše jednou za čtyři hodiny, těsně před spuštěním nebo na pozadí na příkazovém řádku shellu, zkontroluje, zda pro nainstalovaného agenta nevyšla nová verze. Pokud tato aktualizace selže nebo jste offline, spustí se nainstalovaná verze. `omarchy update` aktualizuje nainstalované agenty spolu se zbytkem Omarchy a `mup` aktualizuje pouze nástroje spravované přes mise.

Vlastní aktualizátor agenta, například `claude update`, `codex update` nebo tlačítko aktualizace v aplikaci, neaktualizuje instalaci spravovanou přes mise. `codex update` selže a `claude update` může hlásit úspěch a přitom nainstalovat samostatnou kopii, kterou mise nesleduje. Pokud byste raději používali nativní instalátor a aktualizátor agenta, přidejte ho do `disable_tools`; viz [Předinstalované nástroje CLI](18-development-tools.md#preinstalled-cli-tools).

Chcete-li nainstalovat všechny nakonfigurované lazy nástroje dříve, než je budete potřebovat, spusťte `mise install --include-lazy`. Zahrnuje to i ostatní výchozí nástroje CLI v Omarchy i agenty. Informace o instalaci jednoho nástroje nebo použití vlastní instalace najdete v části [Předinstalované nástroje CLI](18-development-tools.md#preinstalled-cli-tools).

`grok` se instaluje přes first-party balíček `grok` od mise, stejně jako `claude` a `codex`. Spusťte `grok` nebo ho vyberte v části _Nastavení > Výchozí > Agent_. Přeskočte instalátor `curl | bash` na x.ai. Ten umístí druhou kopii do `~/.grok/bin`, přidá ji na začátek `PATH` a přepíše wrapper od Omarchy.

`dsh` otevře své prohlížečové UI na `127.0.0.1:3080`, přičemž adresář, ze kterého bylo spuštěno, je jeho výchozím pracovním prostorem. Jeho prohlížečové UI nepřijímá žádný počáteční prompt, takže `omarchy agent prompt` ho otevře s promptem ve vaší schránce, abyste ho mohli vložit. Omarchy ho spouští s předvolbou oprávnění DeepSeek bez schvalování. DeepSeek Harness odesílá záznamy relací společnosti DeepSeek, když používáte její oficiální API modelů; vypněte to v jeho prohlížečovém UI v části _Nastavení > Obecné > Upload Session Log_. Zpětná vazba, kterou mu odešlete, se odesílá spolu s relací také, pokud ho nespustíte s `DSH_TELEMETRY_MODE=DISABLED`.

### Výchozí agent

Vyberte si výchozího agenta pomocí `omarchy default agent <name>` nebo v části _Nastavení > Výchozí > Agent_ v Omarchy Menu (`Super + Space`). Pokud agent ještě není nainstalovaný, jeho výběrem se nejprve nainstaluje. Čerstvá instalace Omarchy vás k této volbě vyzve jednorázovým oznámením.

Výběr Claude se také pokusí nastavit jeho rozšíření prohlížeče pro Chromium, Chrome, Brave, Brave Origin a Edge. Nastavení rozšíření se vztahuje na všechny uživatele a může si vyžádat vaše systémové heslo; zrušení nebo neúspěšná instalace rozšíření přesto Claude vybere a spustí. Restartujte prohlížeč, na výzvu rozšíření povolte a přihlaste se do Claude, abyste dokončili jeho připojení. Připojení zkontrolujete spuštěním `/chrome` v Claude. Firefox a Zen toto rozšíření nepodporují. Pokud už byl Claude vaším výchozím agentem předtím, než bylo toto nastavení přidáno, vyberte ho znovu, aby se rozšíření nainstalovalo.

Jakmile si vyberete, `Super + Shift + Ctrl + A` spustí výchozího agenta ve vyhrazeném okně terminálu (nebo zobrazí výběr, pokud jste si ještě nevybrali). Můžete ho také spustit rovnou do úkolu pomocí `omarchy agent prompt "Review this project"`. Freebuff a DeepSeek Harness nepřijímají žádný počáteční prompt, takže se místo toho otevřou s promptem ve vaší schránce, abyste ho mohli vložit. Takto spuštění agenti běží bez dohledu ve svých režimech, kdy se nezastavují, aby se zeptali, takže buďte připraveni na to, že budou skutečně něco dělat! MiniMax Code takový režim pro své interaktivní relace nemá, takže žádá o oprávnění jako obvykle. A protože agenti odmítají zapamatovat si důvěru pro váš domovský adresář, spouštění z `$HOME` místo toho začínají v `~/Work`.

K dispozici jsou i zkratky v terminálu: `a` spustí výchozího agenta vloženě v aktuálním terminálu, zatímco `c`, `cx` a `cy` spouštějí přímo OpenCode, Claude Code a Codex (opět v jejich režimech automatického schvalování). Změny motivu se synchronizují i do agentů: Claude Code, Pi, OpenCode a Hermes (jakmile ho Omarchy nainstaluje) se všechny přizpůsobí, když přepnete motiv Omarchy.

### Panel agentů

V horní liště je ikona agentů. Než si agenta nastavíte, jeho panel vás provede přihlášením do Claude, Codex nebo Grok a první z nich se stane vaším výchozím agentem. Poté panel umístí každé předplatné na jednu stránku: každého agenta a účet s jeho plánem, měřič pro každé z jeho 5hodinových limitů relace a týdenních limitů s časem do resetování (přesné procento zobrazíte najetím), nebo zbývající předplacený zůstatek, pod řádkem, který střídá, co jste využili napříč všemi, například tokeny za tento týden a váš nejpoužívanější model. V části _Něco vytvořte_ nabízí úvodní prompty pro nový motiv, plugin nebo aplikaci, které úkol předají vašemu výchozímu agentovi. Aplikace se vytvářejí tak, jak se vytvářejí vlastní aplikace Omarchy Hype, Monologue a Omacut, v C++ a Qt Quick, podle skillu agenta omarchy-app, a kompilátor a součásti Qt, které potřebují, jsou nainstalované. Claude Code, Codex, Grok, Kimi, Cursor a jeho příděl Grok Bot, GitHub Copilot, Muse, Antigravity, Kimchi a Devin jsou pokryty hned po instalaci i se svými limity a Hermes, Mistral Vibe a Qwen Code zobrazují své relace a tokeny, jakmile je použijete. Zobrazují se i plány poskytovatelů a klíče, které používáte přes pi, omp nebo opencode: OpenCode Zen a Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan a Synthetic se svými limity; Fireworks, OpenRouter a DeepSeek se svými předplacenými zůstatky; a modely, které provozujete na vlastním hardwaru, v části Lokální modely. Každý agent se počítá jednou, pod tím, kdo vám ho účtuje, bez ohledu na to, přes kolik harnessů ho řídíte.

Panel otevřete kliknutím levým tlačítkem na ikonu v liště, kliknutím pravým tlačítkem spustíte výchozího agenta. Záznamy o využití, které za ním stojí, každých 15 minut znovu generuje `omarchy agent usage-update` a panel dokonce dokáže sloučit využití z vašich ostatních počítačů přes synchronizovanou složku. Úplné nastavení najdete v README v části `$OMARCHY_PATH/shell/plugins/agents/`.

### Několik předplatných

Pokud platíte za víc než jeden plán Claude, Codex nebo Grok — například osobní Max a pracovní — Omarchy je může udržet všechny přihlášené a přepínat mezi nimi. Přidejte předplatné pomocí + v panelu agentů, který vás tím provede přímo tam, nebo pomocí `omarchy agent account add claude Work` (nebo `codex`, nebo `grok`). Pokud CLI chybí, nainstaluje ho. První účet pro poskytovatele se přihlašuje přes váš běžný prohlížeč, přesně tam, kde ho CLI vždy hledá. Každý další se přihlašuje přes soukromé okno, takže účet, ke kterému už je váš prohlížeč přihlášený, se omylem nevybere; přihlaste se tam jako účet, který přidáváte, a nejprve zavřete všechna soukromá okna, která už máte otevřená. Kvůli tomu se nikdy neodhlasujte z CLI: odhlášení zruší uložené přihlášení a ten účet by bylo nutné přidat znovu.

Chcete-li zkopírovat přihlášení k předplatnému na jiný počítač s Omarchy přes SSH, spusťte `omarchy agent account copy user@laptop`. Odesílatel dodá dočasného příjemce, když cíl žádného nainstalovaného nemá, takže starší počítače s Omarchy mohou přijímat účty bez aktualizace. Nainstalovaní příjemci mají přednost. Tím se zkopírují všechna předplatná Claude, Codex a Grok; chcete-li je vybrat, přidejte názvy poskytovatelů, například `omarchy agent account copy laptop claude`. Názvy účtů a ID příkazů odpovídají zdroji, včetně účtů, které už na cíli existují. Nesouvisející cílové účty obdrží číselnou příponu, pokud se jejich názvy střetávají, a nastavení, skilly, pluginy a historie konverzací zůstávají lokální na každém počítači.

Stávající cílové přihlašovací údaje zůstanou zachovány. Zdrojový účet, který už je tam přihlášený, bude mít synchronizovaný název, aniž by se nahradily jeho přihlašovací údaje; ostatní účty se přidají vedle něj. Chcete-li nahradit uložené přihlašovací údaje u odpovídajících účtů, použijte `omarchy agent account copy --replace laptop claude` poté, co na cíli ukončíte relace daného účtu. Čerstvý cíl také obdrží aktivní účet a předvolby přepínání ze zdroje; zavedený cíl si ponechá své vlastní.

Přihlašovací údaje putují přes SSH a ukládají se do soukromých souborů na cíli, takže kopírujte pouze na počítače, kterým důvěřujete. Jde o jednorázovou kopii, nikoli o průběžnou synchronizaci. Obnovovací tokeny Codex může jiný počítač rotovat, takže zkopírované přihlášení bude potřebovat obnovení; samostatná přihlášení zůstávají nejspolehlivější volbou pro současné použití na několika počítačích. Viz [Pokyny Codex k ověřování účtů](https://developers.openai.com/codex/auth/ci-cd-auth).

Pro každého poskytovatele je aktivní jeden účet a každá nová relace začíná jako on: `cx`, `cy`, prosté `claude`, `codex` nebo `grok`, cokoli spuštěného přes `omarchy agent` a skripty nebo editory, které nacházejí CLI v `PATH`. Přepněte pomocí `omarchy agent account use work` (a zpět pomocí `omarchy agent account use main`), nebo v panelu stisknutím čísla účtu a poté `Enter` (nebo kliknutím na jeho tlačítko Use). Relace, které už běží, zůstanou na účtu, se kterým začaly. Historie konverzací, nastavení, skilly a pluginy se sdílejí napříč účty, takže `claude --continue` ve stejné složce pokračuje tam, kde jste na novém účtu přestali.

S více než jedním účtem panel zobrazuje limity každého účtu vedle sebe, přičemž aktivní je označený. Ve výchozím nastavení vás Omarchy upozorní, když aktivní účet překročí 95 % limitu, a kliknutím na oznámení přepne na účet s největší rezervou. Najeďte na řádek účtu v panelu a klikněte na Autoswitch, které se objeví vedle Use (nebo stiskněte `m`), nebo spusťte `omarchy agent account mode auto`, aby místo toho přepínal sám; když je zapnutý, Autoswitch zaujme místo Use a dalším kliknutím se vrátíte k oznamování. Chcete-li změnit práh, přidejte číslo, například `omarchy agent account mode auto 90`. Pokud je každý účet nad prahem, dozvíte se to jednou, spolu s tím, který účet se uvolní jako první. Když je aktivní účet do 15 bodů od svého prahu (80 % při výchozím nastavení), jeho limity se kontrolují každé tři minuty místo každých 15.

`omarchy agent account list` zobrazí každý účet a jeho nejnovější limity, `omarchy agent account remove work` jeden zapomene a `omarchy agent account rename primary Hey` jeden přejmenuje (nebo klikněte na název účtu v panelu). Tyto příkazy pracují s účty vašeho výchozího agenta; chcete-li dosáhnout na druhého poskytovatele, nejprve ho pojmenujte, například `omarchy agent account use codex side`. Přihlášení, které jste už měli v `~/.claude` nebo `~/.codex`, je účet _Main_ a zůstává tam, kde je. Účet, který se nepoužívá déle než zhruba osm hodin, může zobrazovat _Sign-in required_; kliknutím na něj se k danému účtu znovu přihlásíte přímo v panelu, nebo v něm spusťte relaci, která přihlášení obnoví sama. Servery MCP, které jste měli, když byl účet přidán, s ním přijdou, ale ty, které přidáte později pomocí `claude mcp add`, se dostanou pouze k účtu, ve kterém jste je přidali. Claude Desktop a nástroje nakonfigurované s absolutní cestou k binárce CLI přepnutí nenásledují. Výslovné `CLAUDE_CONFIG_DIR`, `CODEX_HOME` nebo `GROK_HOME` má přednost před vybraným účtem.

### Diagnostika pádů

Omarchy sleduje systemd-coredump kvůli pádům procesů. Když něco segfaultuje, zobrazí se vám oznámení "Process crashed" — klikněte na něj a pád se předá vašemu výchozímu agentovi spolu se skillem diagnose-crash od Omarchy, který agenta provede zjištěním faktů z výpisu paměti a rozhodnutím, zda pád stojí za nahlášení upstreamu. Můžete ho také spustit ručně proti libovolnému PID z `coredumpctl list` pomocí `omarchy agent crash <pid>`.

Sledování je ve výchozím nastavení zapnuté. Vypněte ho v části _Spouštěč > Přepnout > Zachytávání pádů_ (nebo pomocí `omarchy toggle crash-capture`) a oznámení přestanou chodit; `omarchy agent crash <pid>` ručně stále funguje.

Pády lze také umlčet po jednom programu, což vám diagnostika na konci nabídne. `omarchy crash mute hyprland` zastaví oznámení pouze pro ten program, `omarchy crash mute hyprland off` je vrátí zpět a samotné `omarchy crash mute` vypíše, co jste umlčeli. Přijímá cestu k binárce stejně ochotně jako její název, takže `omarchy crash mute /usr/bin/hyprland` dělá totéž. Název s mezerou dejte do uvozovek, například `omarchy crash mute 'Some App'`. Vše ostatní dál oznamuje a umlčený program dál padá — to skrývá připomenutí, nic to neopravuje.

### Desktopové aplikace

Nabídka _Instalace > AI_ obsahuje i několik grafických aplikací AI: desktopovou aplikaci ChatGPT, desktopovou aplikaci Claude (linuxovou betaverzi od Anthropic, s kartami Chat, Cowork a Claude Code), Grok Bot pro chatování s modely od xAI, Herdr Desktop, Hermes Desktop, OpenClaw, desktopovou aplikaci Perplexity a T3 Code. Grok Bot je desktopová chatovací aplikace. Kódovací agent je příkaz `grok`.

Hermes Desktop je ten, o kterém byste měli vědět, protože počítač má jeden Hermes a ten patří aplikaci: Hermes se instaluje vždy pouze přes aplikaci a příkaz `hermes`, který výchozí agent spouští, patří aplikaci. Výběr Hermes jako výchozího agenta nainstaluje totéž, co položka _Instalace > AI_: balíček a runtime Hermes v `~/.hermes` nastavený vlastním instalátorem Hermes, což poprvé trvá několik minut. Ten runtime je ten jeden Hermes, který používají terminálový příkaz `hermes`, výchozí agent i aplikace, a aktualizuje se sám pomocí `hermes update`, místo aby čekal na vydání Omarchy. Jeho instalace také předá Hermes motiv Omarchy jako skin s názvem `omarchy`, který každá plocha Hermes následuje, když přepínáte motivy; pokud byste raději, aby to nedělal, vyberte jiný v nastavení Appearance v Hermes nebo pomocí `/skin` a Omarchy tu volbu nechá být. Odebrání aplikace v části _Odebrat > AI_ nejprve zavře Hermes, včetně gateway, vezme s sebou ten runtime a ponechá vaše chaty, vzpomínky a skilly, které Hermes napsal sám pro sebe, pokud mu neřeknete jinak: zeptá se, zda má odejít i tato data a vaše nastavení připojení, přičemž výchozí odpověď je ne.

Desktopovým zážitkem OpenClaw je jeho Control UI, které se otevírá jako webová aplikace podporovaná vlastní lokální gateway. OpenClaw sídlí v `~/.openclaw` a aktualizuje se sám: použijte tlačítko "Update Gateway" v Control UI nebo spusťte `openclaw update` a gateway se restartuje na nové verzi. Omarchy vybírá pouze vydání, od kterého čerstvá instalace začíná. Odebrání OpenClaw v části _Odebrat > AI_ s sebou vezme službu gateway i aplikaci a poté se zeptá, zda má odejít i `~/.openclaw`, protože tam jsou vaše chaty a přihlašovací údaje spolu se samotným OpenClaw a runtime pluginů, které stahuje; výchozí nastavení ho ponechává a opětovná instalace OpenClaw ho zase najde.

Herdr Desktop je desktopová aplikace [Herdr](https://herdr.dev): prostory, karty a panely terminálů a kódovacích agentů, které dál běží v jeho jádru, když zavřete okno. Pochází z vlastního instalátoru Herdr místo z balíčku, takže sídlí v `~/.local/share/herdr-app`, když ještě žádné nemáte, přináší s sebou své jádro v `~/.local/bin/herdr-core` a aktualizuje obojí sám. Sedí vedle příkazu `herdr`, který Omarchy dodává na `Super + Ctrl + Return`, místo aby ho nahrazoval, a dostává přímé klávesy toho příkazu: `Alt + Return` a `Alt + Shift + Return` rozdělí panel dolů nebo doprava, `Alt + Escape` ho zavře, `Ctrl + Alt + Arrow` přesouvá mezi panely, `Alt + 1..9` a `Alt + Left/Right` vybírají kartu a `Alt + Up/Down` přesouvají mezi prostory. `Ctrl + 1..9` vybírá prostor a `Alt + Shift + Up/Down` prochází agenty. Klávesy s prefixem `Ctrl + Space` zůstávají pouze pro terminál, protože aplikace nemůže pro sekvenci držet prostou klávesu Ctrl. Omarchy je zapisuje do `~/.config/herdr-app/keys.json` a `omarchy-refresh-herdr-app` je vrací zpět. Jeho instalace vybere motiv Omarchy pro Herdr, který od té doby následuje váš motiv Omarchy. Herdr si uchovává jeden motiv pro světlý režim a jeden pro tmavý, takže po přepnutí mezi tmavým a světlým motivem Omarchy vyberte Omarchy ve výběru motivů Herdr ještě jednou pro druhý režim.

T3 Code běží ze svého oficiálního vydání AppImage v `~/.local/share/t3code` místo z balíčku, takže se aktualizuje sám. Jeho instalace se zeptá, zda chcete začít na kanálu Stable nebo Nightly; později to přepnete v nastavení T3 Code. Vaše vlákna a nastavení sídlí v `~/.t3` a odebrání T3 Code v části _Odebrat > AI_ je vezme s sebou.

### Lokální modely

Spusťte otevřený model na vlastním počítači pro své kódovací agenty. Vaše prompty a kód zůstávají na počítači; nic odeslaného modelu ho neopouští. Začněte pomocí:

```bash
omarchy agent local use best
```

Nebo v panelu agentů v horní liště zvolte + a poté Local AI, které se zobrazí, když se na tento počítač vejde model. Poprvé se tím nainstaluje Podman, který modely spouští, a na počítači s NVIDIA sada nástrojů pro kontejnery NVIDIA, která jim poskytuje GPU. Omarchy poté vybere doporučený model pro tento počítač, stáhne ho a spustí. Počítejte se stažením desítek GB a s tím, že zatímco model běží, bude se používat většina paměti počítače: Flash Next používá asi 100 GiB se svým plným kontextem 256K. Pokud jiné modely drží paměť, kterou potřebuje, nastaví se jako zastavený, připravený ke spuštění, jakmile nějaký zastavíte. Model se zastaví při odhlášení; zastavte ho sami, když paměť potřebujete na něco jiného.

`omarchy agent local list` zobrazí možnosti a vysvětlí, proč některé nesedí. Chcete-li nastavit jiný, spusťte `omarchy agent local use <recipe>`. Dnes jsou pro počítače Strix Halo se 128 GB k dispozici `qwen3.8-flash-next-gufo` a `qwen3.8-27b-gufo`; 27B zabírá asi 40 GiB, takže nechává prostor pro jinou práci. Nové recepty a doporučení přicházejí s `omarchy update`, přes balíček.

Každý model, který nastavíte, dostane vlastní řádek v panelu agentů, vedle vašich předplatných: tlačítko pro přehrávání ho spustí, tlačítko pro pozastavení ho zastaví a uvolní jeho paměť a tlačítko terminálu otevře vašeho agenta na něm. Několik jich může běžet najednou, když se společně vejdou do paměti; pokud se některý nevejde, Omarchy řekne, který běžící model máte zastavit. Přetažením řádků je můžete přeřadit a stisknutím Delete na vybraném řádku odeberete model a jeho stažení.

Z příkazového řádku dělají totéž `omarchy agent local start <recipe>` a `omarchy agent local stop <recipe>`, `omarchy agent local status` zobrazí každý model a `omarchy agent --local` otevře vašeho výchozího agenta na posledním modelu, který jste spustili (pi, pokud váš výchozí agent nemůže používat lokální model). Připojit se může i libovolný klient kompatibilní s OpenAI: `status` zobrazí adresu každého modelu (první je `http://127.0.0.1:11435/v1`), název receptu je model a klíč je v `~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` smaže model a stažené soubory, které žádný jiný model nepoužívá.

Runtime třetích stran jsou označeny svým vydavatelem. Omarchy spouští každý model bez přístupu k síti.

### Lokální LLM

Omarchy doporučuje dva způsoby provozování lokálních modelů LLM: LM Studio a Ollama. LM Studio poskytuje GUI rozhraní pro hledání modelů s otevřenými vahami, jejich instalaci a spouštění. Je to skvělý způsob, jak snadno začít. Ollama nabízí CLI pro totéž obdobně. Ale pokud s lokálními modely začínáte, začal bych s LM Studio. Obojí můžete nainstalovat v části _Instalace > AI_ v Omarchy Menu.

### Skill Omarchy

Skilly agentů pomáhají AI používat konkrétní nástroje konkrétním způsobem a Omarchy dodává výchozí skill pro přizpůsobení systému. Jako je ladění vaší konfigurace Hyprland, úprava lišty nebo dokonce vytvoření nového motivu od nuly. Je propojený symlinkem do adresářů skillů pro Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` a každé `~/.hermes/profiles/*/skills`) a obecné umístění `~/.agents/skills`, takže ho většina harnessů zachytí automaticky.

Ale tento skill byste měli považovat za experimentální. Různé modely ho budou využívat s různým účinkem. Nejlepší je nejprve běžet v plánovacím režimu, abyste měli představu, co by agent rád změnil. A pak buďte připraveni vrátit změny zpět nebo dokonce vyvolat `omarchy reinstall configs`, pokud agent všechno zpacká.
