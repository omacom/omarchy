### Instalace a aktualizace agentů

S výjimkou Hermes tito agenti používají línou instalaci mise: první spuštění nainstaluje CLI a další spuštění jej znovu použijí. mise také zkontroluje, zda pro nainstalovaného agenta nevyšla nová verze, nejvýše jednou za čtyři hodiny, těsně před jeho spuštěním nebo na pozadí při promptu shellu. Pokud tato aktualizace selže nebo jste offline, spustí se nainstalovaná verze. `omarchy update` aktualizuje nainstalované agenty spolu se zbytkem Omarchy a `mup` aktualizuje pouze nástroje spravované přes mise.

Vlastní aktualizátor agenta, například `claude update`, `codex update` nebo tlačítko aktualizace v aplikaci, neaktualizuje instalaci spravovanou přes mise. `codex update` selže a `claude update` může nahlásit úspěch, přičemž nainstaluje samostatnou kopii, kterou mise nesleduje. Pokud byste raději používali nativní instalátor a aktualizátor agenta, přidejte jej do `disable_tools`; viz [Předinstalované nástroje CLI](18-development-tools.md#preinstalled-cli-tools).

Chcete-li nainstalovat všechny nakonfigurované líné nástroje předem, než je budete potřebovat, spusťte `mise install --include-lazy`. To zahrnuje i ostatní výchozí nástroje CLI Omarchy i agenty. Informace o instalaci jednoho nástroje nebo použití vlastní instalace najdete v části [Předinstalované nástroje CLI](18-development-tools.md#preinstalled-cli-tools).

`grok` se instaluje prostřednictvím balíčku `grok` přímo od mise, stejně jako `claude` a `codex`. Spusťte `grok` nebo jej vyberte v nabídce _Setup > Defaults > Agent_. Přeskočte instalátor `curl | bash` na x.ai. Tato cesta umístí druhou kopii do `~/.grok/bin`, přidá ji na začátek `PATH` a přepíše wrapper Omarchy.

`dsh` otevře své prohlížečové UI na `127.0.0.1:3080`, přičemž adresář spuštění je jeho výchozím pracovním prostorem. Jeho prohlížečové UI nepřijímá žádný počáteční prompt, takže `omarchy agent prompt` jej otevře s promptem ve vaší schránce k vložení. Omarchy jej spouští s předvolbou oprávnění DeepSeek bez schvalování. DeepSeek Harness nahrává protokoly relací k DeepSeek, když používáte jeho oficiální API modelů; vypněte to v jeho prohlížečovém UI v části _Settings > General > Upload Session Log_. Zpětná vazba, kterou mu odešlete, se nahrává spolu s relací také, pokud jej nespustíte s `DSH_TELEMETRY_MODE=DISABLED`.

### Výchozí agent

Vyberte si výchozího agenta pomocí `omarchy default agent <name>` nebo v nabídce _Setup > Defaults > Agent_ v Omarchy Menu (`Super + Space`). Pokud agent ještě není nainstalován, jeho výběrem se nejprve nainstaluje. Čerstvá instalace Omarchy vás k této volbě vyzve jednorázovým oznámením.

Výběr Claude se také pokusí nastavit jeho rozšíření prohlížeče pro Chromium, Chrome, Brave, Brave Origin a Edge. Nastavení rozšíření platí pro všechny uživatele a může vyžadovat vaše systémové heslo; zrušení nebo neúspěšná instalace rozšíření přesto Claude vybere a spustí. Restartujte prohlížeč, v případě výzvy povolte rozšíření a přihlaste se do Claude, abyste dokončili jeho připojení. Spuštěním `/chrome` v Claude zkontrolujete připojení. Firefox a Zen toto rozšíření nepodporují. Pokud už byl Claude vaším výchozím agentem před přidáním tohoto nastavení, vyberte jej znovu, aby se rozšíření nainstalovalo.

Jakmile si vyberete, `Super + Shift + Ctrl + A` spustí výchozího agenta ve vyhrazeném okně terminálu (nebo zobrazí výběr, pokud jste si ještě nevybrali). Můžete jej také spustit rovnou do úkolu pomocí `omarchy agent prompt "Review this project"`. Freebuff a DeepSeek Harness nepřijímají žádný počáteční prompt, takže se místo toho otevřou s promptem ve vaší schránce k vložení. Takto spuštění agenti běží bez dohledu ve svých příslušných režimech, kdy se nezastavují, aby se zeptali, takže buďte připraveni na to, že budou skutečně něco dělat! MiniMax Code takový režim pro své interaktivní relace nemá, takže žádá o oprávnění jako obvykle. A protože agenti odmítají zapamatovat si důvěru pro váš domovský adresář, spuštění z `$HOME` místo toho začínají v `~/Work`.

Existují i terminálové zkratky: `a` spustí výchozího agenta přímo v aktuálním terminálu, zatímco `c`, `cx` a `cy` spustí přímo OpenCode, Claude Code a Codex (opět v jejich režimech automatického schvalování). Změny motivu se také synchronizují k agentům: Claude Code, Pi, OpenCode a Hermes (jakmile jej Omarchy nainstaluje) všichni následují, když přepnete motiv Omarchy.

### Panel agentů

Horní lišta má ikonu agentů. Než si agenta nastavíte, její panel vás provede přihlášením do Claude, Codex nebo Grok a první z nich se stane vaším výchozím agentem. Poté panel umístí každé předplatné na jednu stránku: každého agenta a účet s jeho plánem, měřič pro každý z jeho 5hodinových limitů relací a týdenních limitů s časem do jeho resetu (přejetím zobrazíte přesné procento) nebo zbývající předplacený zůstatek, pod řádkem, který střídá to, co jste použili napříč všemi z nich, jako jsou tokeny za tento týden a váš nejpoužívanější model. V části _Make something_ nabízí úvodní prompty pro nový motiv, plugin nebo aplikaci, které předají úkol vašemu výchozímu agentovi. Aplikace se vytvářejí stejným způsobem jako vlastní Hype, Monologue a Omacut od Omarchy, v C++ a Qt Quick, podle skillu agenta omarchy-app, a kompilátor a části Qt, které potřebují, přicházejí nainstalované. Claude Code, Codex, Grok, Kimi, Cursor a jeho příděl Grok Bot, GitHub Copilot, Muse, Antigravity, Kimchi a Devin jsou pokryty hned po instalaci se svými limity a Hermes, Mistral Vibe a Qwen Code zobrazí své relace a tokeny, jakmile je použijete. Plány poskytovatelů a klíče, které používáte prostřednictvím pi, omp nebo opencode, se také zobrazí: OpenCode Zen a Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan a Synthetic se svými limity; Fireworks, OpenRouter a DeepSeek se svými předplacenými zůstatky; a modely, které provozujete na vlastním hardwaru v části Local models. Každý agent se počítá jednou, u toho, kdo jej fakturuje, bez ohledu na to, přes kolik harnessů jej řídíte.

Kliknutím levým tlačítkem na ikonu na liště otevřete panel, kliknutím pravým tlačítkem spustíte výchozího agenta. Záznamy o využití, které za ním stojí, se každých 15 minut regenerují pomocí `omarchy agent usage-update` a panel může dokonce sloučit využití z vašich ostatních počítačů prostřednictvím synchronizované složky. Úplné nastavení najdete v README v části `$OMARCHY_PATH/shell/plugins/agents/`.

### Několik předplatných

Pokud platíte za více než jeden plán Claude, Codex nebo Grok — například osobní Max a pracovní — Omarchy je může udržet všechny přihlášené a pohybovat se mezi nimi. Přidejte předplatné pomocí + v panelu agentů, který vás tím provede přímo tam, nebo pomocí `omarchy agent account add claude Work` (nebo `codex`, nebo `grok`). Pokud chybí, nainstaluje CLI. První účet pro poskytovatele se přihlašuje prostřednictvím vašeho běžného prohlížeče, přesně tam, kde CLI vždy hledá. Každý další se přihlašuje prostřednictvím soukromého okna, aby se účet, ke kterému je váš prohlížeč již přihlášen, omylem nezachytil; přihlaste se tam jako účet, který přidáváte, a nejprve zavřete všechna soukromá okna, která už máte otevřená. Nikdy se kvůli tomu neodhlášujte z CLI: odhlášení zruší uložené přihlášení a tento účet by bylo nutné přidat znovu.

Chcete-li zkopírovat přihlášení k předplatnému do jiného počítače s Omarchy přes SSH, spusťte `omarchy agent account copy user@laptop`. Odesílatel dodá dočasný přijímač, když cíl žádný nainstalovaný nemá, takže starší počítače s Omarchy mohou přijímat účty bez aktualizace. Nainstalované přijímače mají přednost. Tím se zkopírují všechna předplatná Claude, Codex a Grok; přidáním názvů poskytovatelů je vyberete, jako v `omarchy agent account copy laptop claude`. Názvy účtů a ID příkazů odpovídají zdroji, včetně účtů, které již jsou v cíli přítomny. Nesouvisející cílové účty obdrží číselnou příponu, pokud se jejich názvy střetávají, a nastavení, skilly, pluginy a historie konverzací zůstávají lokální pro každý počítač.

Stávající cílové přihlašovací údaje se zachovají. Zdrojový účet, který je tam již přihlášen, má synchronizovaný svůj název, aniž by se nahradily jeho přihlašovací údaje; ostatní účty se přidají vedle něj. Chcete-li nahradit uložené přihlašovací údaje pro odpovídající účty, použijte `omarchy agent account copy --replace laptop claude` poté, co na cíli ukončíte relace tohoto účtu. Čerstvý cíl také obdrží aktivní účet a předvolby přepínání ze zdroje; zavedený cíl si ponechá své vlastní.

Přihlašovací údaje cestují přes SSH a ukládají se do soukromých souborů na cíli, takže kopírujte pouze do počítačů, kterým důvěřujete. Jedná se o jednorázovou kopii, nikoli průběžnou synchronizaci. Obnovovací tokeny Codex může jiný počítač rotovat, takže zkopírované přihlášení bude potřebovat obnovení; samostatná přihlášení zůstávají nejspolehlivější volbou pro současné použití na několika počítačích. Viz [Pokyny k ověřování účtů Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Jeden účet na poskytovatele je aktivní a každá nová relace začíná jako on: `cx`, `cy`, prosté `claude`, `codex` nebo `grok`, cokoli spuštěné prostřednictvím `omarchy agent` a skripty nebo editory, které najdou CLI na `PATH`. Přepněte pomocí `omarchy agent account use work` (a zpět pomocí `omarchy agent account use main`) nebo v panelu stisknutím čísla účtu a poté `Enter` (nebo kliknutím na jeho tlačítko Use). Relace, které již běží, zůstávají na účtu, se kterým začaly. Historie konverzací, nastavení, skilly a pluginy jsou sdíleny napříč účty, takže `claude --continue` ve stejné složce naváže tam, kde jste na novém účtu přestali.

Při více než jednom účtu panel zobrazuje limity každého účtu vedle sebe, přičemž aktivní je označen. Ve výchozím nastavení vás Omarchy upozorní, když aktivní účet překročí 95 % limitu, a kliknutím na oznámení se přepne na účet s největší rezervou. Najeďte myší na řádek účtu v panelu a klikněte na Autoswitch, které se objeví vedle Use (nebo stiskněte `m`), nebo spusťte `omarchy agent account mode auto`, aby se přepínal sám; když je zapnuté, Autoswitch zaujme místo Use a opětovným kliknutím se vrátíte k upozorňování. Přidáním čísla změníte práh, jako v `omarchy agent account mode auto 90`. Pokud je každý účet nad prahem, dozvíte se o tom jednou, spolu s tím, který účet se uvolní jako první. Zatímco je aktivní účet do 15 bodů od svého prahu (80 % při výchozím nastavení), jeho limity se kontrolují každé tři minuty místo každých 15.

`omarchy agent account list` zobrazí každý účet a jeho nejnovější limity, `omarchy agent account remove work` jeden zapomene a `omarchy agent account rename primary Hey` jeden přejmenuje (nebo klikněte na název účtu v panelu). Tyto příkazy pracují s účty vašeho výchozího agenta; chcete-li dosáhnout na jiného poskytovatele, nejprve jej pojmenujte, jako v `omarchy agent account use codex side`. Přihlášení, které jste již měli v `~/.claude` nebo `~/.codex`, je účet _Main_ a zůstává tam, kde je. Účet, který se nepoužívá déle než přibližně osm hodin, může zobrazovat _Sign-in required_; kliknutím na něj se tento účet znovu přihlásí přímo v panelu, nebo v něm spusťte relaci, která přihlášení sama obnoví. Servery MCP, které jste měli v době přidání účtu, s ním přijdou, ale ty, které přidáte později pomocí `claude mcp add`, se dostanou pouze k účtu, ve kterém jste je přidali. Claude Desktop a nástroje nakonfigurované s absolutní cestou k binárce CLI přepnutí nenásledují. Explicitní `CLAUDE_CONFIG_DIR`, `CODEX_HOME` nebo `GROK_HOME` má přednost před vybraným účtem.

### Diagnostika pádů

Omarchy sleduje systemd-coredump kvůli pádům procesů. Když něco spadne kvůli chybě segmentace, obdržíte oznámení „Process crashed“ — klikněte na něj a pád se předá vašemu výchozímu agentovi spolu se skillem diagnose-crash od Omarchy, který agenta provede zjištěním faktů z výpisu paměti (core dump) a rozhodnutím, zda pád stojí za nahlášení upstreamu. Můžete jej také spustit ručně proti libovolnému PID z `coredumpctl list` pomocí `omarchy agent crash <pid>`.

Sledování je ve výchozím nastavení zapnuté. Vypněte jej v části _Trigger > Toggle > Crash Capture_ (nebo pomocí `omarchy toggle crash-capture`) a oznámení přestanou; `omarchy agent crash <pid>` stále funguje ručně.

Pády lze také ztlumit po jednom programu, což vám diagnostika na konci nabídne. `omarchy crash mute hyprland` zastaví oznámení pouze pro tento program, `omarchy crash mute hyprland off` je vrátí a `omarchy crash mute` samo o sobě vypíše, co jste ztlumili. Přijímá cestu k binárce stejně ochotně jako její název, takže `omarchy crash mute /usr/bin/hyprland` dělá totéž. Název s mezerou uzavřete do uvozovek, jako v `omarchy crash mute 'Some App'`. Všechno ostatní stále upozorňuje a ztlumený program stále padá — toto skrývá připomínku, nic neopravuje.

### Desktopové aplikace

Nabídka _Install > AI_ obsahuje také několik grafických aplikací AI: desktopovou aplikaci ChatGPT, desktopovou aplikaci Claude (linuxová beta od Anthropic, s kartami Chat, Cowork a Claude Code), Grok Bot pro chatování s modely xAI, Herdr Desktop, Hermes Desktop, OpenClaw, desktopovou aplikaci Perplexity a T3 Code. Grok Bot je desktopová chatovací aplikace. Kódovací agent je příkaz `grok`.

Hermes Desktop je ta, o které je dobré vědět, protože počítač má jeden Hermes a ten patří aplikaci: Hermes se instaluje pouze prostřednictvím aplikace a příkaz `hermes`, který výchozí agent spouští, je ten od aplikace. Výběr Hermes jako výchozího agenta nainstaluje totéž co položka _Install > AI_: balíček a runtime Hermes v `~/.hermes` nastavený vlastním instalátorem Hermes, což poprvé trvá několik minut. Tento runtime je ten jediný Hermes, který používají terminálový příkaz `hermes`, výchozí agent i aplikace, a aktualizuje se sám pomocí `hermes update`, místo aby čekal na vydání Omarchy. Jeho instalace také předá Hermes motiv Omarchy jako skin s názvem `omarchy`, který každé rozhraní Hermes následuje, když přepínáte motivy; pokud byste raději, aby to nedělal, vyberte jiný v nastavení Appearance v Hermes nebo pomocí `/skin` a Omarchy tuto volbu nechá být. Odebrání aplikace v části _Remove > AI_ nejprve zavře Hermes, včetně gateway, vezme tento runtime s sebou a ponechá vaše chaty, vzpomínky a skilly, které si Hermes sám pro sebe napsal, pokud neřeknete jinak: zeptá se, s výchozí odpovědí ne, zda by tato data a vaše nastavení připojení měla také zmizet.

Desktopovým prostředím OpenClaw je jeho Control UI, které se otevírá jako webová aplikace podporovaná vlastní lokální gateway. OpenClaw žije v `~/.openclaw` a aktualizuje se sám: použijte tlačítko „Update Gateway“ v Control UI nebo spusťte `openclaw update` a gateway se restartuje na nové verzi. Omarchy pouze vybírá vydání, od kterého čerstvá instalace začne. Odebrání OpenClaw v části _Remove > AI_ s sebou vezme službu gateway a aplikaci a poté se zeptá, zda by `~/.openclaw` mělo také zmizet, protože to obsahuje vaše chaty a přihlašovací údaje spolu se samotným OpenClaw a runtime pluginů, které stahuje; výchozí nastavení jej ponechá a opětovná instalace OpenClaw jej znovu zachytí.

Herdr Desktop je desktopová aplikace [Herdr](https://herdr.dev): prostory, karty a panely terminálů a kódovacích agentů, které nadále běží v jejím jádru, když zavřete okno. Pochází z vlastního instalátoru Herdr, nikoli z balíčku, takže žije v `~/.local/share/herdr-app`, přináší své jádro v `~/.local/bin/herdr-core`, když ještě žádné nemáte, a aktualizuje obojí samo. Sedí vedle příkazu `herdr`, který Omarchy dodává na `Super + Ctrl + Return`, místo aby jej nahrazovala. Jeho instalace vybere motiv Omarchy v Herdr, který od té doby následuje váš motiv Omarchy. Herdr si uchovává jeden motiv pro světlý režim a jeden pro tmavý, takže po přepnutí mezi tmavým a světlým motivem Omarchy vyberte Omarchy v nástroji pro výběr motivu Herdr ještě jednou pro druhý režim.

T3 Code běží ze svého oficiálního vydání AppImage v `~/.local/share/t3code` místo z balíčku, takže se aktualizuje samo. Jeho instalace se zeptá, zda začít na kanálu Stable nebo Nightly; později přepněte v nastavení T3 Code. Vaše vlákna a nastavení žijí v `~/.t3` a odebrání T3 Code v části _Remove > AI_ je vezme s sebou.

### Lokální modely

Spusťte otevřený model na vlastním počítači pro své kódovací agenty. Vaše prompty a kód zůstávají na počítači; nic odeslaného modelu jej neopustí. Začněte pomocí:

```bash
omarchy agent local use best
```

Nebo v panelu agentů na horní liště zvolte + a poté Local AI, která se zobrazí, když se model na tento počítač vejde. Poprvé se tím nainstaluje Podman, který modely spouští, a na počítači NVIDIA sada nástrojů pro kontejnery NVIDIA, která jim poskytne GPU. Omarchy poté vybere doporučený model pro tento počítač, stáhne jej a spustí. Očekávejte stažení desítek GB a využití většiny paměti počítače, zatímco model běží: Flash Next používá přibližně 100 GiB se svým plným kontextem 256K. Pokud jiné modely drží paměť, kterou potřebuje, nastaví se jako zastavený, připravený spustit se, jakmile jeden zastavíte. Model se zastaví při odhlášení; zastavte jej sami, když potřebujete paměť pro něco jiného.

`omarchy agent local list` zobrazí možnosti a vysvětlí, proč se některé nevejdou. Chcete-li nastavit jiný, spusťte `omarchy agent local use <recipe>`. Dnes jsou `qwen3.8-flash-next-gufo` a `qwen3.8-27b-gufo` k dispozici pro počítače Strix Halo se 128 GB; 27B zabírá přibližně 40 GiB, takže ponechává prostor pro jinou práci. Nové recepty a doporučení přicházejí s `omarchy update`, prostřednictvím balíčku.

Každý model, který nastavíte, dostane svůj vlastní řádek v panelu agentů, vedle vašich předplatných: přehrát pro spuštění, pozastavit pro zastavení a uvolnění jeho paměti a tlačítko terminálu pro otevření vašeho agenta na něm. Několik jich může běžet najednou, když se společně vejdou do paměti; pokud se jeden nevejde, Omarchy řekne, který běžící model zastavit. Přetažením řádků je můžete přeřadit a stisknutím Delete na vybraném řádku odstraníte model a jeho stažení.

Z příkazového řádku dělají `omarchy agent local start <recipe>` a `omarchy agent local stop <recipe>` totéž, `omarchy agent local status` zobrazí každý model a `omarchy agent --local` otevře vašeho výchozího agenta na posledním modelu, který jste spustili (pi, pokud váš výchozí agent nemůže použít lokální model). Připojit se může i libovolný klient kompatibilní s OpenAI: `status` zobrazí adresu každého modelu (první je `http://127.0.0.1:11435/v1`), název receptu je model a klíč je v `~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` smaže model a stažení, která žádný jiný model nepoužívá.

Runtime třetích stran jsou označeny svým vydavatelem. Omarchy spouští každý model bez přístupu k síti.

### Lokální LLM

Omarchy doporučuje dva způsoby spouštění lokálních modelů LLM: LM Studio a Ollama. LM Studio poskytuje GUI rozhraní pro vyhledávání modelů s otevřenými vahami, jejich instalaci a spouštění. Je to skvělý způsob, jak snadno začít. Ollama nabízí CLI pro podobné použití. Ale pokud jste v lokálních modelech noví, začal bych s LM Studio. Obojí můžete nainstalovat v části _Install > AI_ v Omarchy Menu.

### Skill Omarchy

Skilly agentů pomáhají AI používat konkrétní nástroje konkrétním způsobem a Omarchy dodává výchozí skill pro přizpůsobení systému. Jako je úprava konfigurace Hyprland, úprava lišty nebo dokonce vytvoření nového motivu od nuly. Je provázán symbolickým odkazem do adresářů skillů pro Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` a každý `~/.hermes/profiles/*/skills`) a obecné umístění `~/.agents/skills`, takže jej většina harnessů zachytí automaticky.

Ale tento skill byste měli považovat za experimentální. Různé modely jej budou používat s různým efektem. Nejlepší je nejprve jej spustit v režimu plánování, abyste měli představu o tom, co by agent rád změnil. A pak buďte připraveni vrátit změny zpět nebo dokonce vyvolat `omarchy reinstall configs`, pokud agent všechno zpustoší.
