Omarchy inajumuisha vizindua (launchers) kwa ajili ya coding agents zilizoorodheshwa hapa chini bila kukuchagulia chaguomsingi. Endesha amri ili kusakinisha CLI yake unapoitumia mara ya kwanza, kisha thibitisha utambulisho wako unapoombwa. Hermes na OpenClaw ndizo tofauti: hakuna kinachosakinishwa kwa ajili yao kupitia mise, na kuchagua mojawapo kati yao huweka nakala yake yenyewe inayojisasisisha yenyewe, kama _Desktop apps_ hapa chini inavyoielezea.

### Kusakinisha na kusasisha agents

Isipokuwa Hermes na OpenClaw, agents hizi hutumia usakinishaji wa uvivu (lazy installation) wa mise: uzinduzi wa kwanza husakinisha CLI, na uzinduzi wa baadaye huitumia tena. mise pia hukagua agent iliyosakinishwa kwa toleo jipya zaidi mara moja tu kwa kila saa nne, mara kabla tu haijaanza au chinichini wakati wa shell prompt. Kama usasisho huo ukishindwa au hauko mtandaoni, toleo lililosakinishwa huendeshwa. `omarchy update` husasisha agents zilizosakinishwa pamoja na Omarchy yote iliyobaki, na `mup` husasisha zana zinazosimamiwa na mise tu.

Kisasishaji cha agent mwenyewe, kama vile `claude update`, `codex update`, au kitufe cha kusasisha ndani ya app, hakisasishi usakinishaji unaosimamiwa na mise. `codex update` hushindwa, na `claude update` linaweza kuripoti mafanikio huku likisakinisha nakala tofauti ambayo mise haifuatilii. Kama ungependelea kutumia kisakinishaji na kisasishaji asilia cha agent, iongeze kwenye `disable_tools`; angalia [Zana za CLI zilizosakinishwa awali](18-development-tools.md#preinstalled-cli-tools).

Kusakinisha zana zote za uvivu zilizosanidiwa kabla hujazihitaji, endesha `mise install --include-lazy`. Hii inajumuisha zana nyingine chaguomsingi za CLI za Omarchy pamoja na agents. Angalia [Zana za CLI zilizosakinishwa awali](18-development-tools.md#preinstalled-cli-tools) kwa ajili ya kusakinisha zana moja au kutumia usakinishaji wako mwenyewe.

`grok` husakinishwa kupitia kifurushi cha mise cha first-party `grok`, kwa namna ileile kama `claude` na `codex`. Endesha `grok`, au ichague chini ya _Agent > Harness_. Ruka kisakinishaji cha `curl | bash` kilichoko x.ai. Njia hiyo huweka nakala ya pili katika `~/.grok/bin`, huiongeza mwanzo mwa `PATH`, na kuandika upya wrapper ya Omarchy.

`dsh` hufungua browser UI yake kwenye `127.0.0.1:3080`, huku saraka ya uzinduzi ikiwa ndiyo workspace yake chaguomsingi. Browser UI yake haikubali prompt ya kuanzia, hivyo `omarchy agent prompt` huifungua huku prompt ikiwa kwenye clipboard yako ili uibandike. Omarchy huianzisha kwa preset ya ruhusa ya DeepSeek ya kutohitaji idhini (no-approval). DeepSeek Harness hupakia kumbukumbu za session (session logs) kwenda DeepSeek unapotumia API yake rasmi ya modeli; zima hilo chini ya _Settings > General > Upload Session Log_ katika browser UI yake. Maoni unayoitumia pia hupakiwa pamoja na session, isipokuwa ukiianzisha kwa `DSH_TELEMETRY_MODE=DISABLED`.

### Agent chaguomsingi

Chagua agent wako chaguomsingi kwa `omarchy default agent <name>` au chini ya _Agent > Harness_ katika Omarchy Menu (`Super + Space`). Kama agent bado haijasakinishwa, kuichagua huisakinisha kwanza, na pia hupata launcher yake yenyewe katika app launcher, karibu na Agent. Omarchy mpya itakualika kufanya uamuzi huu kwa arifa ya mara moja tu.

Kuchagua Claude pia hujaribu kuweka browser extension yake kwa ajili ya Chromium, Chrome, Brave, Brave Origin, na Edge. Usanidi wa extension hutumika kwa watumiaji wote na unaweza kuomba nenosiri lako la mfumo; kughairi au usakinishaji wa extension ulioshindwa bado humchagua na kumzindua Claude. Anzisha upya browser yako, washa extension ukiombwa, na ingia kwenye Claude ili kukamilisha kuiunganisha. Endesha `/chrome` katika Claude kuangalia uhusiano. Firefox na Zen haziungi mkono extension hii. Kama Claude tayari alikuwa ndiye chaguomsingi wako kabla usanidi huu haujaongezwa, mchague tena ili kusakinisha extension.

Ukishachagua, `Super + Shift + Ctrl + A` huzindua agent chaguomsingi katika dirisha maalum la terminal (au huonyesha kiteuzi kama bado hujachagua). Unaweza pia kuizindua moja kwa moja kwenye kazi kwa `omarchy agent prompt "Review this project"`. Freebuff na DeepSeek Harness hazikubali prompt ya kuanzia, hivyo badala yake hufunguka huku prompt ikiwa kwenye clipboard yako ili uibandike. Agents zinazozinduliwa kwa namna hii huendeshwa bila kusimamiwa katika hali zao husika za kutosimama-kuuliza (don't-stop-to-ask), hivyo uwe tayari kwao kufanya vitu kweli! MiniMax Code haina hali kama hiyo kwa sessions zake za mwingiliano, hivyo huomba ruhusa kama kawaida. Na kwa kuwa agents hukataa kukumbuka uaminifu (trust) kwa saraka yako ya nyumbani, uzinduzi kutoka `$HOME` badala yake huanza katika `~/Work`.

Kuna mikato ya terminal pia: `a` huendesha agent chaguomsingi ndani ya terminal ya sasa, huku `c`, `cx`, na `cy` zikianzisha OpenCode, Claude Code, na Codex moja kwa moja (tena katika hali zao za kuidhinisha kiotomatiki). Mabadiliko ya mandhari (theme) pia husawazishwa kwenda kwa agents: Claude Code, Pi, OpenCode, na Hermes (mara Omarchy inapokuwa imemsakinisha) zote hufuata unapobadilisha mandhari ya Omarchy.

### Maagizo ya agent wako

Sheria za kibinafsi kwa kila agent huenda katika `~/.agents/AGENTS.md`, karibu na skills zinazoshirikiwa katika `~/.agents/skills`. Ifungue chini ya _Agent > Instructions_, ambayo pia huiunganisha kwenye kila harness inayoweka faili yake ya jumla yenyewe: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` ya Copilot, na kadhalika. Crush na Amp husoma kiungo cha `~/.config/AGENTS.md`, huku omp, Kimi, na DeepSeek Harness wakisoma `~/.agents/AGENTS.md` moja kwa moja. Kuchagua agent chaguomsingi pia huiunganisha. Faili ya maagizo uliyokuwa nayo tayari huwa ndiyo inayoshirikiwa kama bado hakukuwa na moja; vinginevyo huhifadhiwa karibu na kiungo kama `.bak`. Endesha `omarchy agent instructions` kuunganisha upya baada ya kusakinisha agent nyingine.

### Paneli ya agents

Upau wa juu (top bar) una ikoni ya agents. Kabla hujasanidi agent, paneli yake hukupitisha katika kuingia kwenye Claude, Codex, au Grok, na wa kwanza huwa ndiye agent wako chaguomsingi. Baada ya hapo, paneli huweka kila usajili kwenye ukurasa mmoja: kila agent na akaunti pamoja na mpango wake, kipimo (meter) kwa kila kikomo chake cha session cha saa 5 na cha wiki pamoja na muda uliobaki kabla hakijaresetika (elea juu yake kwa asilimia kamili), au salio lililobaki lililolipwa kabla, chini ya mstari unaozunguka kile ulichotumia katika zote, kama vile tokens wiki hii na modeli unayoitumia zaidi. Chini ya _Make something cool_ hutoa starter prompts kwa ajili ya mandhari mpya, plugin, app, au mchezo unaokabidhi kazi hiyo kwa agent wako chaguomsingi. Apps hujengwa kwa namna ileile ambayo Hype, Monologue, na Omacut za Omarchy zenyewe hujengwa, kwa C++ na Qt Quick, zikifuata omarchy-make-app agent skill, na compiler na vipande vya Qt wanavyohitaji huja vimesakinishwa. Michezo ni ukurasa mmoja wa three.js katika `~/Games/vibes`, ikifuata omarchy-make-game agent skill, na yote hufunguka kutoka launcher moja ya Game Vibes katika mandhari ya sasa; hupakia three.js kutoka kwenye wavuti, hivyo huhitaji muunganiko ili kuanza. Claude Code, Codex, Grok, Kimi, Cursor na posho yake ya Grok Bot, GitHub Copilot, Muse, Antigravity, na Devin hushughulikiwa tayari pamoja na vikomo vyao, Kimchi pamoja na mpango wake, credits zilizolipwa kabla, na bajeti za matumizi, na Hermes, Mistral Vibe, na Qwen Code huonyesha sessions na tokens zao mara tu unapokuwa umezitumia. Mipango ya watoa huduma na funguo (keys) unazozitumia kupitia pi, omp, au opencode pia huonekana: OpenCode Zen na Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan, na Synthetic pamoja na vikomo vyao; OpenRouter na DeepSeek pamoja na salio zao zilizolipwa kabla; Fireworks pamoja na matumizi yake kwa siku 30 zilizopita; na modeli unazoziendesha kwenye hardware yako mwenyewe chini ya Local models. Kila agent huhesabiwa mara moja, chini ya yeyote anayemlipa, haijalishi ni harness ngapi unazompitishia.

Bofya kushoto ikoni ya upau au bonyeza `Super + Ctrl + X` kwa ajili ya paneli, bofya kulia kuzindua agent wako chaguomsingi, na bofya katikati kuburudisha. Rekodi za matumizi zilizo nyuma yake hutengenezwa upya kila baada ya dakika 15 na `omarchy agent usage update`, na paneli inaweza hata kuunganisha matumizi kutoka mashine zako nyingine kupitia folda iliyosawazishwa. Angalia README chini ya `$OMARCHY_PATH/shell/plugins/agents/` kwa mipangilio kamili.

### Usajili kadhaa

Kama unalipia zaidi ya mpango mmoja wa Claude, Codex, au Grok — wa binafsi wa Max na wa kazini, tuseme — Omarchy inaweza kuwaweka wote wakiwa wameingia na kuhama kati yao. Ongeza usajili kwa + katika paneli ya agents, ambayo hukupitisha katika hilo pale pale, au kwa `omarchy agent account add claude Work` (au `codex`, au `grok`). Husakinisha CLI kama haipo. Akaunti ya kwanza kwa mtoa huduma huingia kupitia browser yako ya kawaida, pale pale ambapo CLI hutazama kila wakati. Kila moja baada ya hiyo huingia kupitia dirisha la faragha (private window), hivyo akaunti ambayo browser yako tayari imeingia nayo haichukuliwi kwa makosa; ingia hapo kama akaunti unayoiongeza, na funga dirisha la faragha lolote ulilokuwa umelifungua awali kwanza. Kamwe usitoke kwenye CLI kufanya hivi: kutoka hubatilisha uingiaji uliohifadhiwa, na akaunti hiyo ingelazimika kuongezwa tena.

Kunakili uingiaji wa usajili wako kwenye mashine nyingine ya Omarchy kupitia SSH, endesha `omarchy agent account copy user@laptop`. Mtumaji hutoa mpokeaji wa muda wakati lengwa halina aliyesakinishwa, hivyo mashine za zamani za Omarchy zinaweza kupokea akaunti bila usasisho. Wapokeaji waliosakinishwa huchukua nafasi ya kwanza. Hii hunakili usajili wote wa Claude, Codex, na Grok; ongeza majina ya watoa huduma kuwachagua, kama katika `omarchy agent account copy laptop claude`. Majina ya akaunti na vitambulisho vya amri (command IDs) hulandana na chanzo, pamoja na akaunti tayari zilizopo kwenye lengwa. Akaunti za lengwa zisizohusiana hupokea kiambishi tamati cha nambari kama majina yao yakigongana, na mipangilio, skills, plugins, na historia ya mazungumzo hubaki ndani ya kila mashine.

Vitambulisho vilivyopo vya lengwa huhifadhiwa. Akaunti ya chanzo tayari iliyoingia hapo hupata jina lake kusawazishwa bila kubadilisha vitambulisho vyake; akaunti nyingine huongezwa kando yake. Kubadilisha vitambulisho vilivyohifadhiwa kwa akaunti zinazolandana, tumia `omarchy agent account copy --replace laptop claude` baada ya kuacha sessions za akaunti hiyo kwenye lengwa. Lengwa jipya pia hupata akaunti hai ya chanzo na mapendeleo yake ya kubadilisha; lengwa lililoimarika huhifadhi yake yenyewe.

Vitambulisho husafiri kupitia SSH na huhifadhiwa katika faili za faragha kwenye lengwa, hivyo nakili tu kwenye mashine unazoziamini. Hii ni nakala ya mara moja, si usawazishaji unaoendelea. Codex refresh tokens zinaweza kubadilishwa na mashine nyingine, na kuacha uingiaji ulionakiliwa ukihitaji kusasishwa; uingiaji tofauti hubaki chaguo la kuaminika zaidi kwa matumizi ya wakati mmoja kwenye mashine kadhaa. Angalia [Mwongozo wa Codex wa uthibitishaji wa akaunti](https://developers.openai.com/codex/auth/ci-cd-auth).

Akaunti moja kwa kila mtoa huduma ndiyo hai, na kila session mpya huanza ikiwa hivyo: `cx`, `cy`, `claude`, `codex`, au `grok` ya kawaida, chochote kinachozinduliwa kupitia `omarchy agent`, na scripts au wahariri wanaopata CLI kwenye `PATH`. Badilisha kwa `omarchy agent account use work` (na kurudi kwa `omarchy agent account use main`), au katika paneli kwa kubonyeza nambari ya akaunti kisha `Enter` (au kubofya kitufe chake cha Use). Sessions za Claude zinazoendeshwa pia hubadilika, kuanzia ujumbe wao unaofuata: kila session ya Claude huendeshwa katika `~/.claude`, ambayo huhifadhi uingiaji wa akaunti hai kila wakati. Session ya Claude iliyoanzishwa katika folda ya akaunti yenyewe na Omarchy ya zamani huhifadhi uingiaji huo hadi itakapoacha, hivyo ubadilishaji hutaja sessions hizo na humalizika wenyewe mara zinapoondoka. Sessions za Codex na Grok zinazoendeshwa hubaki kwenye akaunti waliyoanzia. Historia ya mazungumzo, mipangilio, skills, na plugins hushirikiwa katika akaunti, hivyo `claude --continue` katika folda ileile huendelea pale ulipoachia kwenye akaunti mpya.

Ukiwa na zaidi ya akaunti moja, paneli huonyesha vikomo vya kila akaunti kando kwa kando, huku ile hai ikiwa imetiwa alama. Kwa chaguomsingi Omarchy hukujulisha akaunti hai inapopita 95% ya kikomo, na kubofya arifa hubadilisha kwenda kwenye akaunti yenye nafasi zaidi iliyobaki. Elea juu ya mstari wa akaunti katika paneli na ubofye Autoswitch inayoonekana kando ya Use (au bonyeza `m`), au endesha `omarchy agent account mode auto`, ili ibadilishe yenyewe badala yake; ikiwa imewashwa, Autoswitch huchukua nafasi ya Use, na kuibofya tena hurudi kwenye kukujulisha. Ongeza nambari kubadilisha kizingiti, kama katika `omarchy agent account mode auto 90`. Kama kila akaunti imezidi kizingiti, utasikia kuhusu hilo mara moja, pamoja na akaunti ipi itapata nafasi kwanza. Akaunti hai ikiwa ndani ya pointi 15 za kizingiti chake (80% kwa chaguomsingi), vikomo vyake hukaguliwa kila baada ya dakika tatu badala ya kila baada ya 15.

`omarchy agent account list` huonyesha kila akaunti na vikomo vyake vya hivi karibuni, `omarchy agent account remove work` husahau moja, na `omarchy agent account rename primary Hey` hubadilisha jina la moja (au bofya jina la akaunti katika paneli). Amri hizi hufanya kazi kwenye akaunti za agent wako chaguomsingi; kufikia mtoa huduma mwingine, mtaje kwanza, kama katika `omarchy agent account use codex side`. Uingiaji uliokuwa nao tayari katika `~/.claude` au `~/.codex` ni akaunti ya _Main_. Ya Codex hubaki pale ilipo; ya Claude husubiri katika folda yake yenyewe huku akaunti nyingine ikiwa hai. Akaunti iliyoachwa bila kutumika kwa zaidi ya takriban saa nane inaweza kuonyesha _Sign-in required_; ibofye kuingia akaunti hiyo tena papo hapo katika paneli, au badilisha kwenda kwake na uanze session, ambayo huburudisha uingiaji yenyewe. MCP servers unazoongeza kwa `claude mcp add` hufikia kila akaunti ya Claude, kwa kuwa zote huendeshwa katika `~/.claude`; kwa Codex na Grok, servers ulizokuwa nazo akaunti ilipoongezwa huja nayo, lakini zile za baadaye hufikia tu akaunti uliyoziongezea. Claude Desktop huweka uingiaji wake mwenyewe, na zana za Codex au Grok zilizosanidiwa kwa njia kamili (absolute path) kwenda kwenye binary ya CLI hazifuati ubadilishaji. `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, au `GROK_HOME` iliyo wazi huchukua nafasi ya kwanza kuliko akaunti iliyochaguliwa.

### Uchunguzi wa kuanguka (crash diagnosis)

Omarchy hutazama systemd-coredump kwa ajili ya kuanguka kwa processes. Mara tu unapokuwa umechagua agent chaguomsingi, programu yako yoyote inayotupa core huleta arifa ya "Process crashed" — ibofye, na kuanguka huko hukabidhiwa kwa agent wako chaguomsingi pamoja na omarchy-diagnose-crash skill ya Omarchy, ambayo humpitisha agent katika kubaini ukweli kutoka kwenye core dump na kuamua kama kuanguka huko kunastahili kuripotiwa upstream. Unaweza pia kuiendesha mwenyewe dhidi ya PID yoyote kutoka `coredumpctl list` kwa `omarchy agent crash <pid>`.

Utazamaji umewashwa kwa chaguomsingi. Izime chini ya _Trigger > Toggle > Crash Capture Off_ (au kwa `omarchy toggle crash-capture`) na arifa husimama; `omarchy agent crash <pid>` bado hufanya kazi mwenyewe.

Kuanguka kunaweza pia kunyamazishwa programu moja kwa wakati mmoja, ambayo ndiyo uchunguzi hukupa mwishoni. `omarchy crash mute hyprland` husitisha arifa kwa programu hiyo tu, `omarchy crash mute hyprland off` huzirudisha, na `omarchy crash mute` yenyewe huorodhesha ulizonyamazisha. Huchukua njia ya binary kwa furaha ileile kama jina lake, hivyo `omarchy crash mute /usr/bin/hyprland` hufanya jambo lileile. Weka nukuu kwenye jina lenye nafasi ndani yake, kama katika `omarchy crash mute 'Some App'`. Kila kitu kingine bado hujulisha, na programu iliyonyamazishwa bado huanguka — hii huficha ukumbusho, hairekebishi chochote.

### Desktop apps

Menyu ya _Install > AI_ pia hubeba apps chache za AI za picha (graphical AI apps): Amp Desktop, Antigravity Desktop, ChatGPT desktop app, Claude desktop app (beta ya Anthropic ya Linux, yenye vichupo vya Chat, Cowork, na Claude Code), Grok Bot kwa ajili ya kuzungumza na modeli za xAI, Herdr Desktop, Hermes Desktop, OpenClaw, Perplexity desktop app, na T3 Code. Grok Bot ndiyo desktop chat app. Coding agent ni amri ya `grok`.

Hermes Desktop ndiyo ya kujua, kwa sababu mashine ina Hermes mmoja, na ni ya app: Hermes husakinishwa kupitia app tu daima, na amri ya `hermes` ambayo agent chaguomsingi huendesha ni ya app. Kuchagua Hermes kama agent chaguomsingi husakinisha jambo lileile ambalo ingizo la _Install > AI_ hufanya: kifurushi, na Hermes runtime chini ya `~/.hermes` iliyowekwa na kisakinishaji cha Hermes mwenyewe, ambayo huchukua dakika chache mara ya kwanza. Runtime hiyo ndiyo Hermes mmoja ambaye amri ya terminal ya `hermes`, agent chaguomsingi na app zote hutumia, na hujisasisha yenyewe kwa `hermes update` badala ya kusubiri toleo la Omarchy. Kuisakinisha pia humpa Hermes mandhari ya Omarchy kama skin iitwayo `omarchy`, ambayo kila uso wa Hermes hufuata unapobadilisha mandhari; chagua nyingine chini ya mipangilio ya Hermes ya Appearance au kwa `/skin` kama ungependelea isifanye hivyo, na Omarchy huacha uamuzi huo peke yake. Kuondoa app chini ya _Remove > AI_ hufunga Hermes kwanza, gateway ikiwemo, huchukua runtime hiyo pamoja nayo, na huhifadhi mazungumzo yako, kumbukumbu, na skills ambazo Hermes ilijiandikia yenyewe isipokuwa ukiiambia vinginevyo: huuliza, chaguomsingi ikiwa hapana, kama data hiyo na mipangilio yako ya uhusiano inapaswa kwenda pia.

Desktop experience ya OpenClaw ni Control UI yake, ambayo hufunguka kama web app inayoungwa mkono na gateway yake ya ndani yenyewe. OpenClaw huishi katika `~/.openclaw` na hujisasisha yenyewe: tumia kitufe cha Control UI cha "Update Gateway" au endesha `openclaw update`, na gateway huanza upya kwenye toleo jipya. Omarchy huchagua tu toleo ambalo usakinishaji mpya huanzia. OpenClaw pia inaweza kuwa agent wako chaguomsingi: kuichagua chini ya _Agent > Harness_ huweka nakala ileile katika `~/.openclaw`, na agent hufungua terminal UI ya OpenClaw iliyounganishwa kwenye gateway yake. Kuondoa OpenClaw chini ya _Remove > AI_ huchukua huduma ya gateway na app pamoja nayo kisha huuliza kama `~/.openclaw` inapaswa kwenda pia, kwa kuwa hiyo huhifadhi mazungumzo na vitambulisho vyako pamoja na OpenClaw yenyewe na plugin runtimes inazozipakua; chaguomsingi huihifadhi, na kusakinisha OpenClaw tena huirudisha.

Herdr Desktop ni [Herdr](https://herdr.dev) desktop app: spaces, vichupo, na panes za terminals na coding agents zinazoendelea kuendeshwa katika core yake unapofunga dirisha. Hutoka kwenye kisakinishaji cha Herdr mwenyewe badala ya kifurushi, hivyo huishi katika `~/.local/share/herdr-app`, huleta core yake pamoja katika `~/.local/bin/herdr-core` unapokuwa huna moja bado, na hujisasisha yenyewe vyote viwili. Hukaa kando ya amri ya `herdr` ambayo Omarchy hutoa kwenye `Super + Ctrl + Return` badala ya kuibadilisha, na hupata funguo za moja kwa moja za amri hiyo: `Alt + Return` na `Alt + Shift + Return` hugawanya pane kwenda chini au kulia, `Alt + Escape` huifunga, `Ctrl + Alt + Arrow` husonga kati ya panes, `Alt + 1..9` na `Alt + Left/Right` huchagua kichupo, na `Alt + Up/Down` husonga kati ya spaces. `Ctrl + 1..9` huchagua space na `Alt + Shift + Up/Down` hupita katika agents. Funguo za kiambishi awali za `Ctrl + Space` hubaki za terminal-tu, kwa kuwa app haiwezi kushikilia kitufe cha Ctrl cha kawaida kwa mfuatano. Omarchy huziandika hizi kwenye `~/.config/herdr-app/keys.json`, na `omarchy-refresh-herdr-app` huzirudisha. Kuisakinisha huchagua mandhari ya Omarchy ya Herdr, ambayo hufuata mandhari yako ya Omarchy kuanzia hapo. Herdr huhifadhi mandhari moja kwa hali ya mwangaza (light mode) na moja kwa hali ya giza (dark), hivyo baada ya kubadilisha kati ya mandhari ya Omarchy ya giza na ya mwangaza, chagua Omarchy katika kiteuzi cha mandhari cha Herdr mara moja tena kwa hali nyingine.

T3 Code huendeshwa kutoka toleo lake rasmi la AppImage katika `~/.local/share/t3code` badala ya kutoka kwenye kifurushi, hivyo hujisasisha yenyewe. Kuisakinisha huuliza kama uanze kwenye channel ya Stable au Nightly; badilisha baadaye katika mipangilio ya T3 Code. Threads na mipangilio yako huishi katika `~/.t3`, na kuondoa T3 Code chini ya _Remove > AI_ huvichukua pamoja nayo.

### Local models

Endesha modeli huria (open model) kwenye mashine yako mwenyewe kwa ajili ya coding agents zako. Prompts na code yako hubaki kwenye mashine; hakuna kinachotumwa kwa modeli kinachoondoka humo. Anza kwa:

```bash
omarchy models use best text
```

Au, katika paneli ya agents katika upau wa juu, chagua + kisha Local AI, ambayo huonekana wakati modeli inatosha mashine hii. Podman, ambayo huendesha modeli, huja na Omarchy, kama ilivyo NVIDIA's container toolkit kwenye mashine ya NVIDIA, ambayo huzipea GPU; kama mojawapo haipo, usanidi wa kwanza huisakinisha. Kisha Omarchy huchagua modeli iliyopendekezwa kwa mashine hii, huipakua, na kuiwasha. Tarajia upakuaji wa makumi ya GB na kumbukumbu nyingi ya mashine kutumika wakati modeli inaendeshwa: Flash Next hutumia takriban 100 GiB na muktadha wake kamili wa 256K. Kama modeli nyingine zinashikilia kumbukumbu inayohitaji, huwekwa ikiwa imesimamishwa, tayari kuanza mara tu unaposimamisha moja. Modeli husimama unapotoka (logout); isimamishe mwenyewe unapohitaji kumbukumbu kwa kitu kingine.

`omarchy models list` huonyesha chaguo na kuelezea kwa nini baadhi hazitoshi. Kuweka nyingine, endesha `omarchy models use <recipe>`. Leo, `qwen3.8-flash-next-gufo` na `qwen3.8-27b-gufo` zinapatikana kwa mashine za 128 GB Strix Halo; ya 27B huchukua takriban 40 GiB, hivyo huacha nafasi kwa kazi nyingine. Kwenye laptop ya 64 GB yenye Intel's Arc B390, `qwen3.6-35b-a3b-llamacpp` huendeshwa katika takriban 30 GiB. Recipes mpya na mapendekezo hufika na `omarchy update`, kupitia kifurushi.

Kila modeli unayoiweka hupata mstari wake yenyewe katika paneli ya agents, karibu na usajili wako: cheza (play) kuiwasha, sitisha (pause) kuisimamisha na kuachia kumbukumbu yake, na kitufe cha terminal kufungua agent wako juu yake. Kadhaa zinaweza kuendeshwa kwa wakati mmoja zinapotosha kwenye kumbukumbu pamoja; kama moja haitoshi, Omarchy husema ni modeli ipi inayoendeshwa isimamishwe. Buruta mistari kuipanga upya, na bonyeza Delete kwenye mstari uliochaguliwa kuondoa modeli na upakuaji wake.

Kila modeli unayoiweka pia hupata ingizo lake yenyewe katika app launcher, chini ya jina la modeli na kwa nembo ya mtengenezaji wake, kwa namna ileile ambayo kuingia kwenye Claude, Codex au Grok huongeza moja. Hufungua agent wako kwenye modeli hiyo, na huwasha modeli kwanza kama haijaendeshwa: terminal huonyesha inapakia na kukabidhi kwa agent mara tu inapokuwa tayari. Kuondoa modeli huondoa ingizo lake.

Si kila modeli ni ya coding. Modeli za picha, video na muziki badala yake hufunguka katika Fantasi, app ya Omarchy ya kutengeneza picha, video na muziki kwa modeli inayoendeshwa kwenye mashine hii, kutoka ingizo lao la launcher na kutoka mstari wao katika paneli ya agents.

Modeli huendelea kuendeshwa sawasawa na ilivyowekwa, hivyo usasisho wa Omarchy kamwe hauanzishi upya moja chini ya agents zako. Omarchy inapokuwa na runtime mpya au uzito mpya (newer weights) kwa modeli uliyoweka, mstari wake huonyesha kitufe cha kusasisha: kibonyeze na modeli huwekwa upya chinichini, ikipakua tu kile kilichobadilika, na huanza upya kwenye toleo jipya. Modeli iliyokuwa imesimamishwa hubaki imesimamishwa. `omarchy models update` hufanya vivyo hivyo kwa kila modeli kutoka kwenye terminal.

Kutoka kwenye command line, `omarchy models start <recipe>` na `omarchy models stop <recipe>` hufanya vivyo hivyo, `omarchy models status` huonyesha kila modeli, na `omarchy agent --local` hufungua agent wako chaguomsingi kwenye modeli ya mwisho uliyoiwasha. pi, OpenCode na Qwen Code zinaweza kutumia moja; ukiwa na chaguomsingi nyingine yoyote hufunguka katika pi, au katika OpenCode kama huna pi. pi pia huorodhesha kila modeli uliyoweka, na zile zilizoko kwenye mashine ulizooanisha nazo, katika kiteuzi chake cha modeli mwenyewe, hivyo `pi` ya kawaida huzifikia pia. Client yoyote inayolingana na OpenAI inaweza kuunganika pia: `status` huonyesha anwani ya kila modeli (ya kwanza ni `http://127.0.0.1:11435/v1`), jina la recipe ndiyo modeli, na ufunguo uko katika `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` hufuta modeli na upakuaji ambao hakuna modeli nyingine inayotumia.

Third-party runtimes huwekwa lebo na mchapishaji wake. Omarchy huendesha kila modeli bila ufikiaji wa mtandao.

### Local LLMs

Omarchy inapendekeza njia mbili za kuendesha local LLM models: LM Studio na Ollama. LM Studio hutoa GUI interface kwa ajili ya kupata open-weight models, kuzisakinisha, na kuziendesha. Ni njia nzuri ya kuanza kwa urahisi. Ollama hutoa CLI kwa kufanya hivyo vivyo hivyo. Lakini kama wewe ni mpya kwa local models, ningeanza na LM Studio. Unaweza kusakinisha yoyote chini ya _Install > AI_ katika Omarchy Menu.

### The Omarchy skills

Agent skills husaidia AI kutumia zana maalum kwa namna maalum, na Omarchy husafirisha saba kati yao. omarchy skill inahusu kubinafsisha mfumo, kama vile kurekebisha Hyprland config yako au kurekebisha upau. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app, na omarchy-make-game zinahusu kutengeneza kitu kipya, omarchy-contribute inahusu kuripoti bug au kutuma fix upstream, na omarchy-diagnose-crash hupitia core dump ya crash. Zimeunganishwa kwa symlink kwenye saraka za skills kwa ajili ya Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` na kila `~/.hermes/profiles/*/skills`), na eneo la jumla la `~/.agents/skills`, hivyo harness nyingi huzichukua kiotomatiki. Folda ya skill yako mwenyewe yenye jina lileile huchukua nafasi ya kwanza.

Lakini unapaswa kuzichukulia skills hizi kama za majaribio. Modeli tofauti zitaitumia kwa athari tofauti. Ni bora kuendeshwa katika plan mode kwanza, ili uwe na wazo la kile agent angependa kubadilisha. Na kisha uwe tayari kurudisha nyuma mabadiliko (rollback) au hata kutumia `omarchy reinstall configs`, kama agent ataharibu kila kitu.
