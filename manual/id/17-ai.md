### Menginstal dan memperbarui agen

Kecuali Hermes, agen-agen ini menggunakan instalasi lazy dari mise: peluncuran pertama menginstal CLI, dan peluncuran berikutnya memakainya kembali. mise juga memeriksa apakah agen yang terinstal memiliki rilis baru paling banyak sekali setiap empat jam, tepat sebelum ia dimulai atau di latar belakang pada prompt shell. Jika pembaruan itu gagal atau kamu sedang offline, versi yang terinstal akan dijalankan. `omarchy update` memperbarui agen yang terinstal bersama seluruh Omarchy, dan `mup` hanya memperbarui alat yang dikelola mise.

Updater milik agen sendiri, seperti `claude update`, `codex update`, atau tombol pembaruan di sebuah aplikasi, tidak memperbarui instalasi yang dikelola mise. `codex update` gagal, dan `claude update` bisa melaporkan berhasil sambil menginstal salinan terpisah yang tidak dilacak mise. Jika kamu lebih suka menggunakan installer dan updater bawaan agen, tambahkan ia ke `disable_tools`; lihat [Alat CLI yang sudah terinstal](18-development-tools.md#preinstalled-cli-tools).

Untuk menginstal semua alat lazy yang dikonfigurasi sebelum kamu membutuhkannya, jalankan `mise install --include-lazy`. Ini termasuk alat CLI default Omarchy lainnya serta agen-agen tersebut. Lihat [Alat CLI yang sudah terinstal](18-development-tools.md#preinstalled-cli-tools) untuk menginstal satu alat atau menggunakan instalasi kamu sendiri.

`grok` diinstal melalui paket `grok` pihak pertama dari mise, dengan cara yang sama seperti `claude` dan `codex`. Jalankan `grok`, atau pilih ia di bawah _Setup > Defaults > Agent_. Lewati installer `curl | bash` di x.ai. Jalur itu menempatkan salinan kedua di `~/.grok/bin`, menempatkannya di awal `PATH`, dan menimpa wrapper Omarchy.

`dsh` membuka UI browser-nya di `127.0.0.1:3080`, dengan direktori peluncuran sebagai workspace default-nya. UI browser-nya tidak menerima prompt awal, jadi `omarchy agent prompt` membukanya dengan prompt di clipboard kamu untuk ditempel. Omarchy memulainya dengan preset izin no-approval dari DeepSeek. DeepSeek Harness mengunggah log sesi ke DeepSeek saat kamu menggunakan API model resminya; matikan itu di bawah _Settings > General > Upload Session Log_ di UI browser-nya. Feedback yang kamu kirim kepadanya juga diunggah bersama sesinya, kecuali kamu memulainya dengan `DSH_TELEMETRY_MODE=DISABLED`.

### Agen default

Pilih agen default kamu dengan `omarchy default agent <name>` atau di bawah _Setup > Defaults > Agent_ di Omarchy Menu (`Super + Space`). Jika agennya belum terinstal, memilihnya akan menginstalnya terlebih dahulu. Omarchy yang baru akan mengundang kamu untuk membuat pilihan ini dengan notifikasi satu kali.

Memilih Claude juga berusaha menyiapkan ekstensi browser-nya untuk Chromium, Chrome, Brave, Brave Origin, dan Edge. Penyiapan ekstensi berlaku untuk semua pengguna dan mungkin meminta kata sandi sistem kamu; membatalkan atau instalasi ekstensi yang gagal tetap memilih dan meluncurkan Claude. Restart browser kamu, aktifkan ekstensi jika diminta, dan masuk ke Claude untuk menyelesaikan penyambungannya. Jalankan `/chrome` di Claude untuk memeriksa koneksinya. Firefox dan Zen tidak mendukung ekstensi ini. Jika Claude sudah menjadi default kamu sebelum penyiapan ini ditambahkan, pilih ia lagi untuk menginstal ekstensinya.

Setelah kamu memilih, `Super + Shift + Ctrl + A` meluncurkan agen default di jendela terminal khusus (atau memunculkan pemilih jika kamu belum memilih). Kamu juga bisa meluncurkannya langsung ke sebuah tugas dengan `omarchy agent prompt "Review this project"`. Freebuff dan DeepSeek Harness tidak menerima prompt awal, jadi mereka membuka dengan prompt di clipboard kamu untuk ditempel sebagai gantinya. Agen yang diluncurkan dengan cara ini berjalan tanpa pengawasan dalam mode don't-stop-to-ask masing-masing, jadi bersiaplah karena mereka akan benar-benar melakukan sesuatu! MiniMax Code tidak memiliki mode seperti itu untuk sesi interaktifnya, jadi ia meminta izin seperti biasa. Dan karena agen menolak mengingat kepercayaan untuk direktori home kamu, peluncuran dari `$HOME` dimulai di `~/Work` sebagai gantinya.

Ada juga pintasan terminal: `a` menjalankan agen default secara inline di terminal saat ini, sementara `c`, `cx`, dan `cy` memulai OpenCode, Claude Code, dan Codex secara langsung (lagi-lagi dalam mode auto-approving mereka). Perubahan tema juga tersinkron ke agen: Claude Code, Pi, OpenCode, dan Hermes (setelah Omarchy menginstalnya) semuanya mengikuti saat kamu mengganti tema Omarchy.

### Panel agen

Bar atas memiliki ikon agen. Sebelum kamu menyiapkan agen, panelnya memandumu untuk masuk ke Claude, Codex, atau Grok, dan yang pertama menjadi agen default kamu. Setelah itu, panel menempatkan setiap langganan dalam satu halaman: setiap agen dan akun beserta paketnya, meter untuk masing-masing batas sesi 5 jam dan batas mingguannya beserta waktu hingga reset (arahkan kursor untuk persentase pastinya), atau sisa saldo prabayar, di bawah baris yang bergilir menampilkan apa yang telah kamu pakai di semuanya, seperti token minggu ini dan model yang paling sering kamu pakai. Di bawah _Make something_ panel ini menawarkan prompt awal untuk tema, plugin, atau aplikasi baru yang menyerahkan tugasnya ke agen default kamu. Aplikasi dibuat dengan cara yang sama seperti Hype, Monologue, dan Omacut milik Omarchy sendiri, dalam C++ dan Qt Quick, mengikuti skill agen omarchy-app, dan compiler serta komponen Qt yang dibutuhkannya sudah terinstal. Claude Code, Codex, Grok, Kimi, Cursor dan jatah Grok Bot-nya, GitHub Copilot, Muse, Antigravity, Kimchi, dan Devin tercakup langsung dengan batas-batasnya, dan Hermes, Mistral Vibe, dan Qwen Code menampilkan sesi dan token mereka setelah kamu memakainya. Paket dan kunci provider yang kamu pakai melalui pi, omp, atau opencode juga muncul: OpenCode Zen dan Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan, dan Synthetic beserta batas-batasnya; Fireworks, OpenRouter, dan DeepSeek beserta saldo prabayarnya; dan model-model yang kamu jalankan di hardware kamu sendiri di bawah Local models. Setiap agen dihitung sekali, di bawah pihak yang menagihnya, berapa pun harness yang kamu pakai untuk menjalankannya.

Klik kiri ikon bar untuk panel, klik kanan untuk meluncurkan agen default kamu. Catatan penggunaan di baliknya dibuat ulang setiap 15 menit oleh `omarchy agent usage-update`, dan panel bahkan bisa menggabungkan penggunaan dari mesin lain kamu melalui folder yang disinkronkan. Lihat README di bawah `$OMARCHY_PATH/shell/plugins/agents/` untuk pengaturan lengkapnya.

### Beberapa langganan

Jika kamu membayar lebih dari satu paket Claude, Codex, atau Grok — misalnya Max pribadi dan satu untuk pekerjaan — Omarchy bisa membuat semuanya tetap masuk dan berpindah di antaranya. Tambahkan langganan dengan + di panel agen, yang memandumu langsung di sana, atau dengan `omarchy agent account add claude Work` (atau `codex`, atau `grok`). Ia menginstal CLI jika belum ada. Akun pertama untuk sebuah provider masuk melalui browser normal kamu, tepat di tempat CLI selalu mencarinya. Setiap akun setelah itu masuk melalui jendela privat, jadi akun yang sudah terhubung di browser kamu tidak terambil secara tidak sengaja; masuk di sana sebagai akun yang sedang kamu tambahkan, dan tutup dulu jendela privat apa pun yang sudah kamu buka. Jangan pernah logout dari CLI untuk melakukan ini: logout mencabut sesi masuk yang tersimpan, dan akun itu harus ditambahkan lagi.

Untuk menyalin login langganan kamu ke mesin Omarchy lain melalui SSH, jalankan `omarchy agent account copy user@laptop`. Pengirim menyediakan receiver sementara saat tujuan belum memilikinya, jadi mesin Omarchy yang lebih lama bisa menerima akun tanpa pembaruan. Receiver yang terinstal lebih diutamakan. Ini menyalin semua langganan Claude, Codex, dan Grok; tambahkan nama provider untuk memilihnya, seperti pada `omarchy agent account copy laptop claude`. Nama akun dan ID perintah sesuai dengan sumbernya, termasuk akun yang sudah ada di tujuan. Akun tujuan yang tidak terkait menerima akhiran numerik jika namanya konflik, dan pengaturan, skill, plugin, serta riwayat percakapan tetap lokal di setiap mesin.

Kredensial tujuan yang sudah ada dipertahankan. Akun sumber yang sudah masuk di sana namanya disinkronkan tanpa mengganti kredensialnya; akun lain ditambahkan di sampingnya. Untuk mengganti kredensial tersimpan untuk akun yang cocok, gunakan `omarchy agent account copy --replace laptop claude` setelah keluar dari sesi akun tersebut di tujuan. Tujuan yang baru juga mendapatkan akun aktif dan preferensi peralihan dari sumber; tujuan yang sudah mapan mempertahankan miliknya sendiri.

Kredensial berjalan melalui SSH dan disimpan dalam file privat di tujuan, jadi salin hanya ke mesin yang kamu percaya. Ini adalah penyalinan satu kali, bukan sinkronisasi berkelanjutan. Token refresh Codex bisa dirotasi oleh mesin lain, sehingga login hasil salinan perlu diperbarui; sesi masuk terpisah tetap menjadi pilihan paling andal untuk penggunaan bersamaan di beberapa mesin. Lihat [panduan autentikasi akun Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Satu akun per provider aktif, dan setiap sesi baru dimulai sebagai akun itu: `cx`, `cy`, `claude`, `codex`, atau `grok` biasa, apa pun yang diluncurkan melalui `omarchy agent`, dan skrip atau editor yang menemukan CLI di `PATH`. Berpindahlah dengan `omarchy agent account use work` (dan kembali dengan `omarchy agent account use main`), atau di panel dengan menekan nomor akun lalu `Enter` (atau mengklik tombol Use-nya). Sesi yang sudah berjalan tetap pada akun yang memulainya. Riwayat percakapan, pengaturan, skill, dan plugin dibagikan antar akun, jadi `claude --continue` di folder yang sama melanjutkan dari tempat kamu berhenti di akun baru.

Dengan lebih dari satu akun, panel menampilkan batas setiap akun berdampingan, dengan akun aktif ditandai. Secara default Omarchy memberi tahu kamu saat akun aktif melewati 95% dari sebuah batas, dan mengklik notifikasi beralih ke akun dengan ruang tersisa paling banyak. Arahkan kursor ke baris akun di panel dan klik Autoswitch yang muncul di samping Use (atau tekan `m`), atau jalankan `omarchy agent account mode auto`, agar ia beralih sendiri sebagai gantinya; saat aktif, Autoswitch menggantikan posisi Use, dan mengkliknya lagi kembali ke pemberian notifikasi. Tambahkan angka untuk mengubah ambangnya, seperti pada `omarchy agent account mode auto 90`. Jika setiap akun melewati ambang, kamu akan diberi tahu sekali, beserta akun mana yang lebih dulu bebas. Saat akun aktif berada dalam 15 poin dari ambangnya (80% pada default), batasnya diperiksa setiap tiga menit, bukan setiap 15 menit.

`omarchy agent account list` menampilkan setiap akun dan batas terbarunya, `omarchy agent account remove work` melupakan satu akun, dan `omarchy agent account rename primary Hey` mengganti nama satu akun (atau klik nama akun di panel). Perintah-perintah ini bekerja pada akun agen default kamu; untuk mencapai provider lain, sebutkan namanya terlebih dahulu, seperti pada `omarchy agent account use codex side`. Login yang sudah kamu miliki di `~/.claude` atau `~/.codex` adalah akun _Main_ dan tetap di tempatnya. Akun yang tidak dipakai selama lebih dari sekitar delapan jam bisa menampilkan _Sign-in required_; klik ia untuk memasukkan akun itu lagi langsung di panel, atau mulai sesi di dalamnya, yang menyegarkan sesi masuknya sendiri. Server MCP yang kamu miliki saat akun ditambahkan ikut ke akun itu, tetapi yang kamu tambahkan kemudian dengan `claude mcp add` hanya mencapai akun tempat kamu menambahkannya. Claude Desktop dan alat yang dikonfigurasi dengan path absolut ke biner CLI tidak mengikuti peralihan. `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, atau `GROK_HOME` yang eksplisit lebih diutamakan daripada akun yang dipilih.

### Diagnosis crash

Omarchy mengawasi systemd-coredump untuk crash proses. Saat sesuatu mengalami segfault, kamu akan mendapatkan notifikasi "Process crashed" — klik notifikasi itu, dan crash diserahkan ke agen default kamu bersama skill diagnose-crash milik Omarchy, yang memandu agen untuk menetapkan fakta dari core dump dan memutuskan apakah crash tersebut layak dilaporkan ke upstream. Kamu juga bisa menjalankannya secara manual terhadap PID apa pun dari `coredumpctl list` dengan `omarchy agent crash <pid>`.

Pengawasan ini aktif secara default. Matikan di bawah _Trigger > Toggle > Crash Capture_ (atau dengan `omarchy toggle crash-capture`) dan notifikasi berhenti; `omarchy agent crash <pid>` tetap bekerja secara manual.

Crash juga bisa dibisukan satu program pada satu waktu, yang merupakan hal yang ditawarkan diagnosis kepadamu di akhir. `omarchy crash mute hyprland` menghentikan notifikasi hanya untuk program itu, `omarchy crash mute hyprland off` mengembalikannya, dan `omarchy crash mute` sendiri menampilkan apa yang telah kamu bisukan. Ia menerima path biner sama senangnya seperti namanya, jadi `omarchy crash mute /usr/bin/hyprland` melakukan hal yang sama. Kutip nama yang mengandung spasi, seperti pada `omarchy crash mute 'Some App'`. Semua hal lain tetap memberi notifikasi, dan program yang dibisukan tetap crash — ini menyembunyikan pengingat, bukan memperbaiki apa pun.

### Aplikasi desktop

Menu _Install > AI_ juga membawa beberapa aplikasi AI grafis: aplikasi desktop ChatGPT, aplikasi desktop Claude (beta Linux dari Anthropic, dengan tab Chat, Cowork, dan Claude Code), Grok Bot untuk mengobrol dengan model xAI, Hermes Desktop, OpenClaw, aplikasi desktop Perplexity, dan T3 Code. Grok Bot adalah aplikasi chat desktop. Agen coding-nya adalah perintah `grok`.

Hermes Desktop adalah yang perlu diketahui, karena sebuah mesin memiliki satu Hermes, dan itu adalah milik aplikasi: Hermes hanya pernah diinstal melalui aplikasi, dan perintah `hermes` yang dijalankan agen default adalah milik aplikasi. Memilih Hermes sebagai agen default menginstal hal yang sama seperti entri _Install > AI_: paketnya, dan runtime Hermes di bawah `~/.hermes` yang disiapkan oleh installer Hermes sendiri, yang memakan waktu beberapa menit saat pertama kali. Runtime itu adalah satu-satunya Hermes yang dipakai perintah terminal `hermes`, agen default, dan aplikasi, dan ia memperbarui dirinya sendiri dengan `hermes update` daripada menunggu rilis Omarchy. Menginstalnya juga memberikan Hermes tema Omarchy sebagai skin bernama `omarchy`, yang diikuti setiap permukaan Hermes saat kamu mengganti tema; pilih yang lain di bawah pengaturan Appearance Hermes atau dengan `/skin` jika kamu lebih suka ia tidak mengikutinya, dan Omarchy membiarkan pilihan itu. Menghapus aplikasi di bawah _Remove > AI_ menutup Hermes terlebih dahulu, termasuk gateway-nya, membawa runtime itu bersamanya, dan menyimpan chat, memori, dan skill yang ditulis Hermes untuk dirinya sendiri kecuali kamu menyuruhnya sebaliknya: ia bertanya, dengan default tidak, apakah data itu dan pengaturan koneksi kamu juga harus dihapus.

Pengalaman desktop OpenClaw adalah Control UI-nya, yang membuka sebagai aplikasi web yang didukung oleh gateway lokalnya sendiri. OpenClaw tinggal di `~/.openclaw` dan memperbarui dirinya sendiri: gunakan tombol "Update Gateway" di Control UI atau jalankan `openclaw update`, dan gateway restart pada versi baru. Omarchy hanya memilih rilis yang menjadi titik awal instalasi baru. Menghapus OpenClaw di bawah _Remove > AI_ membawa layanan gateway dan aplikasinya, lalu bertanya apakah `~/.openclaw` juga harus dihapus, karena itu menyimpan chat dan kredensial kamu bersama OpenClaw sendiri dan runtime plugin yang diunduhnya; default-nya menyimpannya, dan menginstal OpenClaw lagi akan mengambilnya kembali.

T3 Code berjalan dari rilis AppImage resminya di `~/.local/share/t3code` daripada dari sebuah paket, jadi ia memperbarui dirinya sendiri. Menginstalnya menanyakan apakah akan memulai pada channel Stable atau Nightly; beralih nanti di pengaturan T3 Code. Thread dan pengaturan kamu tinggal di `~/.t3`, dan menghapus T3 Code di bawah _Remove > AI_ membawanya bersamanya.

### Model lokal

Jalankan model terbuka di mesin kamu sendiri untuk agen coding kamu. Prompt dan kode kamu tetap di mesin; tidak ada yang dikirim ke model yang meninggalkannya. Mulai dengan:

```bash
omarchy agent local use best
```

Atau, di panel agen di bar atas, pilih + lalu Local AI, yang muncul saat sebuah model cocok dengan mesin ini. Pertama kali, ini menginstal Podman, yang menjalankan model, dan pada mesin NVIDIA toolkit container NVIDIA, yang memberi mereka GPU. Omarchy kemudian memilih model yang direkomendasikan untuk mesin ini, mengunduhnya, dan memulainya. Harapkan unduhan puluhan GB dan sebagian besar memori mesin terpakai saat model berjalan: Flash Next memakai sekitar 100 GiB dengan konteks penuh 256K-nya. Jika model lain menahan memori yang dibutuhkannya, ia disiapkan dalam keadaan berhenti, siap dimulai setelah kamu menghentikan salah satunya. Model berhenti saat logout; hentikan sendiri saat kamu membutuhkan memori untuk hal lain.

`omarchy agent local list` menampilkan pilihan dan menjelaskan mengapa beberapa tidak cocok. Untuk menyiapkan yang lain, jalankan `omarchy agent local use <recipe>`. Saat ini, `qwen3.8-flash-next-halogen` dan `qwen3.8-27b-gufo` tersedia untuk mesin Strix Halo 128 GB. Recipe dan rekomendasi baru tiba dengan `omarchy update`, melalui paket.

Setiap model yang kamu siapkan mendapatkan barisnya sendiri di panel agen, di samping langganan kamu: play untuk memulainya, pause untuk menghentikannya dan membebaskan memorinya, dan tombol terminal untuk membuka agen kamu di model itu. Beberapa bisa berjalan sekaligus saat mereka muat bersama dalam memori; jika satu tidak muat, Omarchy menyebutkan model berjalan mana yang harus dihentikan. Seret baris untuk menyusun ulang, dan tekan Delete pada baris yang dipilih untuk menghapus model dan unduhannya.

Dari baris perintah, `omarchy agent local start <recipe>` dan `omarchy agent local stop <recipe>` melakukan hal yang sama, `omarchy agent local status` menampilkan setiap model, dan `omarchy agent --local` membuka agen default kamu pada model terakhir yang kamu mulai (pi jika agen default kamu tidak bisa menggunakan model lokal). Klien apa pun yang kompatibel dengan OpenAI juga bisa terhubung: `status` menampilkan alamat setiap model (yang pertama adalah `http://127.0.0.1:11435/v1`), nama recipe adalah modelnya, dan kuncinya ada di `~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` menghapus model dan unduhan yang tidak dipakai model lain.

Runtime pihak ketiga diberi label dengan penerbitnya. Omarchy menjalankan setiap model tanpa akses jaringan.

### LLM lokal

Omarchy merekomendasikan dua cara menjalankan model LLM lokal: LM Studio dan Ollama. LM Studio menyediakan antarmuka GUI untuk menemukan model open-weight, menginstalnya, dan menjalankannya. Ini cara yang bagus untuk memulai dengan mudah. Ollama menawarkan CLI untuk melakukan hal serupa. Tetapi jika kamu baru mengenal model lokal, saya akan mulai dengan LM Studio. Kamu bisa menginstal salah satunya di bawah _Install > AI_ di Omarchy Menu.

### Skill Omarchy

Skill agen membantu AI menggunakan alat tertentu dengan cara tertentu, dan Omarchy disertai skill default untuk menyesuaikan sistem. Seperti mengubah config Hyprland kamu, menyesuaikan bar, atau bahkan membuat tema baru dari awal. Ia di-symlink ke direktori skill untuk Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` dan setiap `~/.hermes/profiles/*/skills`), dan lokasi generik `~/.agents/skills`, jadi sebagian besar harness mengambilnya secara otomatis.

Tetapi kamu harus memperlakukan skill ini sebagai eksperimental. Model yang berbeda akan memakainya dengan efek yang berbeda. Sebaiknya jalankan dalam mode plan terlebih dahulu, agar kamu memiliki gambaran tentang apa yang ingin diubah agen.
