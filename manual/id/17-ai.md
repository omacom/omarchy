Jalankan sebuah perintah untuk memasang CLI-nya pada penggunaan pertama, lalu lakukan autentikasi saat diminta. Hermes dan OpenClaw adalah pengecualiannya: tidak ada yang dipasang untuk keduanya melalui mise, dan memilih salah satunya akan menyiapkan salinan miliknya sendiri yang memperbarui diri sendiri, seperti yang dijelaskan di _Aplikasi desktop_ di bawah ini.

### Memasang dan memperbarui agen

Kecuali Hermes dan OpenClaw, agen-agen ini menggunakan pemasangan malas dari mise: peluncuran pertama memasang CLI-nya, dan peluncuran berikutnya menggunakannya kembali. mise juga memeriksa agen yang terpasang untuk rilis baru paling banyak sekali setiap empat jam, tepat sebelum ia mulai atau di latar belakang pada prompt shell. Jika pembaruan itu gagal atau Anda sedang offline, versi yang terpasanglah yang berjalan. `omarchy update` memperbarui agen yang terpasang bersama seluruh Omarchy, dan `mup` hanya memperbarui alat yang dikelola mise.

Updater milik agen itu sendiri, seperti `claude update`, `codex update`, atau tombol pembaruan di sebuah aplikasi, tidak memperbarui instalasi yang dikelola mise. `codex update` gagal, dan `claude update` dapat melaporkan keberhasilan sambil memasang salinan terpisah yang tidak dilacak mise. Jika Anda lebih suka menggunakan installer dan updater bawaan suatu agen, tambahkan ia ke `disable_tools`; lihat [Alat CLI yang sudah terpasang](18-development-tools.md#preinstalled-cli-tools).

Untuk memasang semua alat malas yang dikonfigurasi sebelum Anda membutuhkannya, jalankan `mise install --include-lazy`. Ini mencakup alat CLI default Omarchy lainnya serta agen-agen tersebut. Lihat [Alat CLI yang sudah terpasang](18-development-tools.md#preinstalled-cli-tools) untuk memasang satu alat atau menggunakan instalasi Anda sendiri.

`grok` dipasang melalui paket first-party `grok` dari mise, dengan cara yang sama seperti `claude` dan `codex`. Jalankan `grok`, atau pilih ia di bawah _Agent > Harness_. Lewati installer `curl | bash` di x.ai. Jalur itu menaruh salinan kedua di `~/.grok/bin`, mendahulukan salinan itu di `PATH`, dan menimpa wrapper Omarchy.

`dsh` membuka UI browsernya di `127.0.0.1:3080`, dengan direktori peluncuran sebagai workspace default-nya. UI browsernya tidak menerima prompt awal, jadi `omarchy agent prompt` membukanya dengan prompt di clipboard Anda untuk ditempelkan. Omarchy memulainya dengan preset izin no-approval dari DeepSeek. DeepSeek Harness mengunggah log sesi ke DeepSeek ketika Anda menggunakan API model resminya; matikan itu di bawah _Settings > General > Upload Session Log_ di UI browsernya. Masukan yang Anda kirimkan kepadanya juga diunggah bersama sesi tersebut, kecuali Anda memulainya dengan `DSH_TELEMETRY_MODE=DISABLED`.

### Agen default

Pilih agen default Anda dengan `omarchy default agent <name>` atau di bawah _Agent > Harness_ di Omarchy Menu (`Super + Space`). Jika agen itu belum terpasang, memilihnya akan memasangnya terlebih dahulu, dan ia juga mendapatkan peluncurnya sendiri di peluncur aplikasi, di samping Agent. Omarchy yang baru akan mengundang Anda untuk membuat pilihan ini dengan notifikasi satu kali.

Memilih Claude juga mencoba menyiapkan ekstensi browsernya untuk Chromium, Chrome, Brave, Brave Origin, dan Edge. Penyiapan ekstensi berlaku untuk semua pengguna dan mungkin meminta kata sandi sistem Anda; membatalkan atau instalasi ekstensi yang gagal tetap akan memilih dan meluncurkan Claude. Restart browser Anda, aktifkan ekstensi jika diminta, dan masuk ke Claude untuk menyelesaikan penyambungannya. Jalankan `/chrome` di Claude untuk memeriksa koneksinya. Firefox dan Zen tidak mendukung ekstensi ini. Jika Claude sudah menjadi default Anda sebelum penyiapan ini ditambahkan, pilih ia lagi untuk memasang ekstensinya.

Setelah Anda memilih, `Super + Shift + Ctrl + A` meluncurkan agen default dalam jendela terminal khusus (atau menampilkan pemilih jika Anda belum memilih). Anda juga dapat meluncurkannya langsung ke sebuah tugas dengan `omarchy agent prompt "Review this project"`. Freebuff dan DeepSeek Harness tidak menerima prompt awal, jadi mereka membuka dengan prompt di clipboard Anda untuk ditempelkan sebagai gantinya. Agen yang diluncurkan dengan cara ini berjalan tanpa pengawasan dalam mode don't-stop-to-ask masing-masing, jadi bersiaplah karena mereka benar-benar akan melakukan sesuatu! MiniMax Code tidak memiliki mode seperti itu untuk sesi interaktifnya, jadi ia meminta izin seperti biasa. Dan karena agen menolak untuk mengingat kepercayaan untuk direktori home Anda, peluncuran dari `$HOME` dimulai di `~/Work` sebagai gantinya.

Ada pintasan terminal juga: `a` menjalankan agen default secara inline di terminal saat ini, sementara `c`, `cx`, dan `cy` memulai OpenCode, Claude Code, dan Codex secara langsung (lagi-lagi dalam mode auto-approving mereka). Perubahan tema juga tersinkron ke agen-agen tersebut: Claude Code, Pi, OpenCode, dan Hermes (setelah Omarchy memasangnya) semuanya mengikuti ketika Anda mengganti tema Omarchy.

### Instruksi agen Anda

Aturan pribadi untuk setiap agen berada di `~/.agents/AGENTS.md`, di samping skill bersama di `~/.agents/skills`. Buka ia di bawah _Agent > Instructions_, yang juga menautkannya ke setiap harness yang menyimpan file globalnya sendiri: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` milik Copilot, dan seterusnya. Crush dan Amp membaca tautan `~/.config/AGENTS.md`, sementara omp, Kimi, dan DeepSeek Harness membaca `~/.agents/AGENTS.md` secara langsung. Memilih agen default juga menautkannya. File instruksi yang sudah Anda miliki menjadi file bersama jika belum ada sebelumnya; jika tidak, ia disimpan di samping tautan sebagai `.bak`. Jalankan `omarchy agent instructions` untuk menautkan ulang setelah memasang agen lain.

### Panel agen

Bar atas memiliki ikon agen. Sebelum Anda menyiapkan sebuah agen, panelnya memandu Anda untuk masuk ke Claude, Codex, atau Grok, dan yang pertama menjadi agen default Anda. Setelah itu, panel menempatkan setiap langganan dalam satu halaman: setiap agen dan akun beserta paketnya, meter untuk setiap batas sesi 5 jam dan batas mingguannya beserta waktu hingga reset (arahkan kursor untuk persentase pastinya), atau sisa saldo prabayar, di bawah satu baris yang berganti-ganti menampilkan apa yang telah Anda gunakan di semua itu, seperti token minggu ini dan model yang paling sering Anda gunakan. Di bawah _Make something cool_ ia menawarkan prompt awal untuk tema, plugin, aplikasi, atau game baru yang menyerahkan tugasnya kepada agen default Anda. Aplikasi dibuat dengan cara yang sama seperti Hype, Monologue, dan Omacut milik Omarchy sendiri, dalam C++ dan Qt Quick, mengikuti skill agen omarchy-make-app, dan compiler serta komponen Qt yang mereka butuhkan sudah terpasang. Game adalah satu halaman three.js tunggal di `~/Games/vibes`, mengikuti skill agen omarchy-make-game, dan semuanya terbuka dari satu peluncur Game Vibes dalam tema saat ini; mereka memuat three.js dari web, jadi mereka membutuhkan koneksi untuk memulai. Claude Code, Codex, Grok, Kimi, Cursor dan jatah Grok Bot-nya, GitHub Copilot, Muse, Antigravity, dan Devin dicakup langsung dengan batas-batas mereka, Kimchi dengan paketnya, kredit prabayar, dan anggaran pengeluarannya, dan Hermes, Mistral Vibe, dan Qwen Code menampilkan sesi dan token mereka setelah Anda menggunakannya. Paket dan kunci provider yang Anda gunakan melalui pi, omp, atau opencode juga muncul: OpenCode Zen dan Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan, dan Synthetic dengan batas-batas mereka; OpenRouter dan DeepSeek dengan saldo prabayar mereka; Fireworks dengan pengeluarannya selama 30 hari terakhir. Token dari model yang Anda jalankan di perangkat keras Anda sendiri juga dihitung ke total; model-model itu sendiri memiliki panel sendiri, yang dijelaskan di bawah [Model lokal](#local-models). Setiap agen dihitung sekali, di bawah siapa pun yang menagihnya, tidak peduli melalui berapa banyak harness Anda menjalankannya.

Klik kiri ikon bar atau tekan `Super + Ctrl + X` untuk panel, klik kanan untuk meluncurkan agen default Anda, dan klik tengah untuk menyegarkan. Catatan penggunaan di baliknya dibuat ulang setiap 15 menit oleh `omarchy agent usage update`, dan panel bahkan dapat menggabungkan penggunaan dari mesin Anda yang lain melalui folder yang disinkronkan. Lihat README di bawah `$OMARCHY_PATH/shell/plugins/agents/` untuk pengaturan lengkapnya.

### Beberapa langganan

Jika Anda membayar lebih dari satu paket Claude, Codex, atau Grok — misalnya Max pribadi dan satu untuk pekerjaan — Omarchy dapat menjaga semuanya tetap masuk dan berpindah di antara mereka. Tambahkan langganan dengan + di panel agen, yang memandu Anda melaluinya langsung di sana, atau dengan `omarchy agent account add claude Work` (atau `codex`, atau `grok`). Ia memasang CLI jika CLI itu belum ada. Akun pertama untuk sebuah provider masuk melalui browser normal Anda, tepat di tempat CLI selalu mencarinya. Setiap akun setelah itu masuk melalui jendela privat, agar akun yang sudah dimasuki browser Anda tidak terambil secara tidak sengaja; masuklah di sana sebagai akun yang Anda tambahkan, dan tutup dulu jendela privat apa pun yang sudah Anda buka. Jangan pernah keluar dari CLI untuk melakukan ini: keluar akan mencabut sesi masuk yang tersimpan, dan akun itu harus ditambahkan lagi.

Untuk menyalin login langganan Anda ke mesin Omarchy lain melalui SSH, jalankan `omarchy agent account copy user@laptop`. Pengirim menyediakan receiver sementara ketika tujuan tidak memiliki receiver yang terpasang, sehingga mesin Omarchy yang lebih lama dapat menerima akun tanpa pembaruan. Receiver yang terpasang mendapat prioritas. Ini menyalin semua langganan Claude, Codex, dan Grok; tambahkan nama provider untuk memilihnya, seperti pada `omarchy agent account copy laptop claude`. Nama akun dan ID perintah cocok dengan sumber, termasuk akun yang sudah ada di tujuan. Akun tujuan yang tidak terkait menerima sufiks numerik jika nama mereka konflik, dan pengaturan, skill, plugin, serta riwayat percakapan tetap lokal di setiap mesin.

Kredensial tujuan yang sudah ada tetap disimpan. Akun sumber yang sudah masuk di sana namanya disinkronkan tanpa mengganti kredensialnya; akun lain ditambahkan di sampingnya. Untuk mengganti kredensial tersimpan untuk akun yang cocok, gunakan `omarchy agent account copy --replace laptop claude` setelah keluar dari sesi akun tersebut di tujuan. Tujuan yang baru juga mendapatkan akun aktif dan preferensi perpindahan dari sumber; tujuan yang sudah mapan mempertahankan miliknya sendiri.

Kredensial berjalan melalui SSH dan disimpan dalam file privat di tujuan, jadi salin hanya ke mesin yang Anda percayai. Ini adalah salinan satu kali, bukan sinkronisasi yang berkelanjutan. Token refresh Codex dapat dirotasi oleh mesin lain, membuat login yang disalin membutuhkan pembaruan; sesi masuk terpisah tetap menjadi pilihan paling andal untuk penggunaan bersamaan di beberapa mesin. Lihat [Panduan autentikasi akun Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Satu akun per provider aktif, dan setiap sesi baru dimulai sebagai akun itu: `cx`, `cy`, `claude`, `codex`, atau `grok` biasa, apa pun yang diluncurkan melalui `omarchy agent`, dan skrip atau editor yang menemukan CLI di `PATH`. Beralihlah dengan `omarchy agent account use work` (dan kembali dengan `omarchy agent account use main`), atau di panel dengan menekan nomor akun lalu `Enter` (atau mengklik tombol Use-nya). Sesi Claude yang sedang berjalan juga beralih, mulai pesan berikutnya: setiap sesi Claude berjalan di `~/.claude`, yang selalu menyimpan sesi masuk akun aktif. Sesi Claude yang dimulai di folder akun sendiri oleh Omarchy yang lebih lama menyimpan sesi masuk itu hingga ia keluar, jadi peralihan menamai sesi-sesi tersebut dan selesai dengan sendirinya setelah sesi-sesi itu hilang. Sesi Codex dan Grok yang sedang berjalan tetap pada akun tempat mereka dimulai. Riwayat percakapan, pengaturan, skill, dan plugin dibagikan antar-akun, jadi `claude --continue` di folder yang sama melanjutkan dari tempat Anda berhenti pada akun baru.

Dengan lebih dari satu akun, panel menunjukkan batas setiap akun berdampingan, dengan akun aktif yang ditandai. Secara default Omarchy memberi tahu Anda ketika akun aktif melewati 95% dari sebuah batas, dan mengklik notifikasi beralih ke akun dengan ruang tersisa terbanyak. Arahkan kursor ke baris akun di panel dan klik Autoswitch yang muncul di samping Use (atau tekan `m`), atau jalankan `omarchy agent account mode auto`, agar ia beralih sendiri sebagai gantinya; saat aktif, Autoswitch mengambil tempat Use, dan mengkliknya lagi kembali ke pemberitahuan saja. Tambahkan angka untuk mengubah ambangnya, seperti pada `omarchy agent account mode auto 90`. Jika setiap akun melewati ambang, Anda akan mendengarnya sekali, bersama akun mana yang bebas terlebih dahulu. Saat akun aktif berada dalam 15 poin dari ambangnya (80% pada default), batasnya diperiksa setiap tiga menit, bukan setiap 15 menit.

`omarchy agent account list` menunjukkan setiap akun dan batas terbarunya, `omarchy agent account remove work` melupakan satu akun, dan `omarchy agent account rename primary Hey` mengganti nama satu akun (atau klik nama akun di panel). Perintah-perintah ini bekerja pada akun agen default Anda; untuk menjangkau provider lain, sebutkan namanya terlebih dahulu, seperti pada `omarchy agent account use codex side`. Login yang sudah Anda miliki di `~/.claude` atau `~/.codex` adalah akun _Main_. Punya Codex tetap di tempatnya; punya Claude menunggu di foldernya sendiri saat akun lain aktif. Akun yang tidak digunakan selama lebih dari sekitar delapan jam dapat menampilkan _Sign-in required_; klik ia untuk masuk lagi ke akun itu langsung di panel, atau beralihlah ke akun itu dan mulai sesi, yang menyegarkan sesi masuk dengan sendirinya. Server MCP yang Anda tambahkan dengan `claude mcp add` menjangkau setiap akun Claude, karena mereka semua berjalan di `~/.claude`; untuk Codex dan Grok, server yang Anda miliki saat akun ditambahkan ikut ke akun itu, tetapi server setelahnya hanya menjangkau akun tempat Anda menambahkannya. Claude Desktop menyimpan sesi masuknya sendiri, dan alat Codex atau Grok yang dikonfigurasi dengan path absolut ke biner CLI tidak mengikuti peralihan. `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, atau `GROK_HOME` yang eksplisit mendapat prioritas atas akun yang dipilih.

### Diagnosis crash

Omarchy mengawasi systemd-coredump untuk crash proses. Setelah Anda memilih agen default, program Anda mana pun yang melakukan dump core akan memunculkan notifikasi "Process crashed" — klik ia, dan crash itu diserahkan kepada agen default Anda bersama skill omarchy-diagnose-crash dari Omarchy, yang memandu agen melalui penetapan fakta dari core dump dan memutuskan apakah crash itu layak dilaporkan ke upstream. Anda juga dapat menjalankannya secara manual terhadap PID mana pun dari `coredumpctl list` dengan `omarchy agent crash <pid>`.

Pengawasan ini aktif secara default. Matikan di bawah _Trigger > Toggle > Crash Capture Off_ (atau dengan `omarchy toggle crash-capture`) dan notifikasinya berhenti; `omarchy agent crash <pid>` tetap bekerja secara manual.

Crash juga dapat dibisukan satu program pada satu waktu, yang merupakan tawaran diagnosis kepada Anda di akhir. `omarchy crash mute hyprland` menghentikan notifikasi hanya untuk program itu, `omarchy crash mute hyprland off` mengembalikannya, dan `omarchy crash mute` sendiri mencantumkan apa yang telah Anda bisukan. Ia menerima path biner sama senangnya seperti namanya, jadi `omarchy crash mute /usr/bin/hyprland` melakukan hal yang sama. Kutip nama yang memiliki spasi di dalamnya, seperti pada `omarchy crash mute 'Some App'`. Semua yang lain tetap memberi notifikasi, dan program yang dibisukan tetap crash — ini menyembunyikan pengingatnya, ini tidak memperbaiki apa pun.

### Aplikasi desktop

Menu _Install > AI_ juga membawa beberapa aplikasi AI grafis: Amp Desktop, Antigravity Desktop, aplikasi desktop ChatGPT, aplikasi desktop Claude (beta Linux dari Anthropic, dengan tab Chat, Cowork, dan Claude Code), Grok Bot untuk mengobrol dengan model xAI, Herdr Desktop, Hermes Desktop, OpenClaw, aplikasi desktop Perplexity, dan T3 Code. Grok Bot adalah aplikasi obrolan desktop. Agen coding-nya adalah perintah `grok`.

Hermes Desktop adalah yang perlu diketahui, karena sebuah mesin memiliki satu Hermes, dan Hermes itu adalah milik aplikasi: Hermes hanya pernah dipasang melalui aplikasi, dan perintah `hermes` yang dijalankan agen default adalah milik aplikasi. Memilih Hermes sebagai agen default memasang hal yang sama seperti yang dilakukan entri _Install > AI_: paketnya, dan runtime Hermes di bawah `~/.hermes` yang disiapkan oleh installer Hermes sendiri, yang memerlukan beberapa menit pada kali pertama. Runtime itulah satu-satunya Hermes yang digunakan perintah terminal `hermes`, agen default, dan aplikasi, dan ia memperbarui dirinya sendiri dengan `hermes update` daripada menunggu rilis Omarchy. Memasangnya juga memberi Hermes tema Omarchy sebagai skin bernama `omarchy`, yang diikuti setiap permukaan Hermes saat Anda mengganti tema; pilih yang lain di bawah pengaturan Appearance Hermes atau dengan `/skin` jika Anda lebih suka ia tidak melakukannya, dan Omarchy membiarkan pilihan itu sendiri. Menghapus aplikasi di bawah _Remove > AI_ menutup Hermes terlebih dahulu, termasuk gateway-nya, mengambil runtime itu bersamanya, dan menyimpan obrolan, memori, dan skill yang ditulis Hermes untuk dirinya sendiri kecuali Anda menyuruhnya sebaliknya: ia menanyakan, dengan default tidak, apakah data itu dan pengaturan koneksi Anda juga harus ikut hilang.

Pengalaman desktop OpenClaw adalah Control UI-nya, yang terbuka sebagai aplikasi web yang didukung oleh gateway lokalnya sendiri. OpenClaw tinggal di `~/.openclaw` dan memperbarui dirinya sendiri: gunakan tombol "Update Gateway" di Control UI atau jalankan `openclaw update`, dan gateway restart pada versi baru. Omarchy hanya memilih rilis tempat instalasi baru dimulai. OpenClaw juga dapat menjadi agen default Anda: memilihnya di bawah _Agent > Harness_ menyiapkan salinan yang sama itu di `~/.openclaw`, dan agen membuka UI terminal OpenClaw yang terhubung ke gateway-nya. Menghapus OpenClaw di bawah _Remove > AI_ mengambil layanan gateway dan aplikasinya bersamanya lalu menanyakan apakah `~/.openclaw` juga harus hilang, karena di situlah obrolan dan kredensial Anda disimpan di samping OpenClaw itu sendiri dan runtime plugin yang ia unduh; default-nya menyimpannya, dan memasang OpenClaw lagi akan mengambilnya kembali.

Herdr Desktop adalah aplikasi desktop [Herdr](https://herdr.dev): space, tab, dan pane terminal serta agen coding yang terus berjalan di core-nya saat Anda menutup jendela. Ia berasal dari installer Herdr sendiri bukan dari sebuah paket, jadi ia tinggal di `~/.local/share/herdr-app`, membawa core-nya di `~/.local/bin/herdr-core` saat Anda belum memilikinya, dan memperbarui keduanya sendiri. Ia berada di samping perintah `herdr` yang dikirimkan Omarchy pada `Super + Ctrl + Return` daripada menggantikannya, dan mendapatkan kunci langsung perintah itu: `Alt + Return` dan `Alt + Shift + Return` membagi pane ke bawah atau ke kanan, `Alt + Escape` menutupnya, `Ctrl + Alt + Arrow` berpindah antar-pane, `Alt + 1..9` dan `Alt + Left/Right` memilih tab, dan `Alt + Up/Down` berpindah antar-space. `Ctrl + 1..9` memilih space dan `Alt + Shift + Up/Down` melangkah melalui agen. Kunci prefix `Ctrl + Space` tetap hanya untuk terminal, karena aplikasi tidak dapat menahan tombol Ctrl biasa untuk sebuah urutan. Omarchy menulis ini ke `~/.config/herdr-app/keys.json`, dan `omarchy-refresh-herdr-app` mengembalikannya. Memasangnya memilih tema Omarchy dari Herdr, yang mengikuti tema Omarchy Anda sejak saat itu. Herdr menyimpan satu tema untuk mode terang dan satu untuk mode gelap, jadi setelah beralih antara tema Omarchy gelap dan terang, pilih Omarchy di pemilih tema Herdr sekali lagi untuk mode yang lain.

T3 Code berjalan dari rilis AppImage resminya di `~/.local/share/t3code` bukan dari sebuah paket, jadi ia memperbarui dirinya sendiri. Memasangnya menanyakan apakah akan memulai di saluran Stable atau Nightly; beralihlah nanti di pengaturan T3 Code. Thread dan pengaturan Anda tinggal di `~/.t3`, dan menghapus T3 Code di bawah _Remove > AI_ mengambil mereka bersamanya.

### Model lokal

Jalankan model terbuka di mesin Anda sendiri untuk agen coding Anda. Prompt dan kode Anda tetap di mesin; tidak ada yang dikirim ke model yang meninggalkannya. Mulailah dengan:

```bash
omarchy models use best text
```

Itu menyiapkan model teks terbaik untuk mesin ini, jenis yang digunakan agen Anda. Model gambar, video, dan musik memiliki yang terbaik milik mereka sendiri: `omarchy models use best image`, `video` atau `music`. Jalankan `omarchy models use best` untuk melihat pilihan setiap jenis untuk mesin ini.

Atau buka panel model lokal dari ikon sparkles-nya di bar atas, di samping ikon agen, atau dengan Super + Ctrl + Alt + X, dan pilih +. Ikonnya muncul ketika ada model yang sesuai dengan mesin ini. Podman, yang menjalankan model-model, disertakan dengan Omarchy, begitu juga toolkit kontainer NVIDIA di mesin NVIDIA, yang memberi mereka GPU; jika salah satunya hilang, penyiapan pertama memasangnya. Omarchy kemudian memilih model yang direkomendasikan untuk mesin ini, mengunduhnya, dan memulainya. Harapkan unduhan puluhan GB dan sebagian besar memori mesin digunakan saat model berjalan: Flash Next menggunakan sekitar 100 GiB dengan konteks penuh 256K-nya. Jika model lain menahan memori yang ia butuhkan, ia disiapkan dalam keadaan berhenti, siap untuk dimulai setelah Anda menghentikan salah satu. Model berhenti saat logout; hentikan sendiri saat Anda membutuhkan memori untuk hal lain.

`omarchy models list` menunjukkan opsi dan menjelaskan mengapa beberapa tidak sesuai. Untuk menyiapkan yang lain, jalankan `omarchy models use <recipe>`. Saat ini, `qwen3.8-flash-next-gufo` dan `qwen3.8-27b-gufo` tersedia untuk mesin Strix Halo 128 GB; yang 27B menggunakan sekitar 40 GiB, jadi ia meninggalkan ruang untuk pekerjaan lain. Di laptop 64 GB dengan Arc B390 dari Intel, `qwen3.6-35b-a3b-llamacpp` berjalan dalam sekitar 30 GiB. Resep dan rekomendasi baru tiba dengan `omarchy update`, melalui paket.

Setiap model yang Anda siapkan mendapatkan barisnya sendiri di panel model lokal: putar untuk memulainya, jeda untuk menghentikannya dan membebaskan memorinya, dan tombol terminal untuk membuka agen Anda padanya. Di bagian atas, sebuah bar menunjukkan bagaimana memori mesin dibagi antara Omarchy itu sendiri (sistem dan aplikasi Anda), setiap model yang berjalan, dan yang bebas. Arahkan kursor ke model yang berhenti dan bar menunjukkan apakah ia muat, atau seberapa jauh kekurangannya. Beberapa dapat berjalan sekaligus ketika mereka muat bersama dalam memori; jika satu tidak muat, Omarchy mengatakan model berjalan mana yang harus dihentikan. Seret baris berdasarkan logonya untuk mengurutkannya kembali, dan tekan Delete pada baris yang dipilih untuk menghapus model dan unduhannya.

Setiap model coding yang Anda siapkan juga mendapatkan entrinya sendiri di peluncur aplikasi, dengan nama model dan logo pembuatnya, seperti masuk ke Claude, Codex atau Grok menambahkan satu entri. Ia membuka agen Anda pada model itu, dan memulai model terlebih dahulu jika ia belum berjalan: terminal menampilkan ia sedang dimuat dan menyerahkan kepada agen setelah ia siap. Menghapus model menghapus entrinya.

Tidak setiap model untuk coding. Model gambar, video, dan musik terbuka di Fantasi sebagai gantinya, aplikasi Omarchy untuk membuat gambar, video, dan musik dengan model yang berjalan di mesin ini, dipilih di sana atau dari barisnya di panel model lokal.

Model tetap berjalan persis seperti saat disiapkan, jadi pembaruan Omarchy tidak pernah merestart model di bawah agen Anda. Ketika Omarchy memiliki runtime yang lebih baru atau bobot yang lebih baru untuk model yang telah Anda siapkan, barisnya menampilkan tombol pembaruan: tekan ia dan model disiapkan lagi di latar belakang, hanya mengunduh yang berubah, dan restart pada versi baru. Model yang berhenti tetap berhenti. `omarchy models update` melakukan hal yang sama untuk setiap model dari terminal.

Dari baris perintah, `omarchy models start <recipe>` dan `omarchy models stop <recipe>` melakukan hal yang sama, `omarchy models status` menunjukkan setiap model, dan `omarchy agent --local` membuka model terakhir yang Anda mulai di pi, apa pun agen default Anda. OpenCode dan Qwen Code juga dapat menggunakan model lokal: `omarchy models harness opencode` atau `omarchy models harness qwen` membukanya di sana sebagai gantinya, dan `omarchy models harness pi` kembali. pi juga mencantumkan setiap model yang telah Anda siapkan, dan yang ada di mesin yang telah Anda pasangkan, di pemilih modelnya sendiri, jadi `pi` biasa juga dapat menjangkau mereka. Klien yang kompatibel dengan OpenAI mana pun juga dapat terhubung: `status` menunjukkan alamat setiap model (yang pertama adalah `http://127.0.0.1:11435/v1`), nama resep adalah modelnya, dan kuncinya ada di `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` menghapus model dan unduhan yang tidak digunakan model lain.

Runtime pihak ketiga diberi label dengan penerbitnya. Omarchy menjalankan setiap model tanpa akses jaringan.

### LLM lokal

Omarchy merekomendasikan dua cara menjalankan model LLM lokal: LM Studio dan Ollama. LM Studio menyediakan antarmuka GUI untuk menemukan model open-weight, memasangnya, dan menjalankannya. Itu cara yang bagus untuk memulai dengan mudah. Ollama menawarkan CLI untuk melakukan hal serupa. Tetapi jika Anda baru mengenal model lokal, saya akan mulai dengan LM Studio. Anda dapat memasang salah satunya di bawah _Install > AI_ di Omarchy Menu.

### Skill Omarchy

Skill agen membantu AI menggunakan alat tertentu dengan cara tertentu, dan Omarchy mengirimkan tujuh di antaranya. Skill omarchy mencakup penyesuaian sistem, seperti mengutak-atik konfigurasi Hyprland Anda atau menyesuaikan bar. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app, dan omarchy-make-game mencakup membuat sesuatu yang baru, omarchy-contribute mencakup melaporkan bug atau mengirim perbaikan ke upstream, dan omarchy-diagnose-crash bekerja melalui core dump sebuah crash. Mereka disymlink ke direktori skill untuk Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` dan setiap `~/.hermes/profiles/*/skills`), dan lokasi generik `~/.agents/skills`, jadi sebagian besar harness mengambilnya secara otomatis. Folder skill milik Anda sendiri dengan nama yang sama mendapat prioritas.

Tetapi Anda harus memperlakukan skill-skill ini sebagai eksperimental. Model yang berbeda akan menggunakannya dengan efek yang berbeda. Sebaiknya jalankan dalam mode perencanaan terlebih dahulu, agar Anda memiliki gambaran tentang apa yang ingin diubah oleh agen. Lalu bersiaplah untuk melakukan rollback perubahan atau bahkan menjalankan `omarchy reinstall configs`, jika agen membuat kekacauan pada semuanya.
