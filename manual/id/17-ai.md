Jalankan sebuah perintah untuk menginstal CLI-nya pada penggunaan pertama, lalu autentikasi saat diminta. ### Menginstal dan memperbarui agent

Kecuali Hermes, agent-agent ini menggunakan instalasi lazy dari mise: peluncuran pertama menginstal CLI, dan peluncuran berikutnya menggunakannya kembali. mise juga memeriksa apakah agent yang terinstal memiliki rilis baru paling banyak sekali setiap empat jam, tepat sebelum ia dimulai atau di latar belakang pada prompt shell. Jika pembaruan itu gagal atau kamu offline, versi yang terinstal yang berjalan. `omarchy update` memperbarui agent yang terinstal bersama seluruh Omarchy, dan `mup` hanya memperbarui tool yang dikelola mise.

Updater milik agent sendiri, seperti `claude update`, `codex update`, atau tombol update di sebuah aplikasi, tidak memperbarui instalasi yang dikelola mise. `codex update` gagal, dan `claude update` dapat melaporkan berhasil padahal menginstal salinan terpisah yang tidak dilacak mise. Jika kamu lebih suka menggunakan installer dan updater bawaan agent, tambahkan ia ke `disable_tools`; lihat [Tool CLI yang sudah terinstal](18-development-tools.md#preinstalled-cli-tools).

Untuk menginstal semua tool lazy yang dikonfigurasi sebelum kamu membutuhkannya, jalankan `mise install --include-lazy`. Ini mencakup tool CLI default Omarchy lainnya serta para agent. Lihat [Tool CLI yang sudah terinstal](18-development-tools.md#preinstalled-cli-tools) untuk menginstal satu tool atau menggunakan instalasi milikmu sendiri.

`grok` diinstal melalui package `grok` first-party dari mise, dengan cara yang sama seperti `claude` dan `codex`. Jalankan `grok`, atau pilih ia di bawah _Setup > Defaults > Agent_. Lewati installer `curl | bash` di x.ai. Cara itu menaruh salinan kedua di `~/.grok/bin`, menempatkannya di awal `PATH`, dan menimpa wrapper Omarchy.

`dsh` membuka UI browser-nya di `127.0.0.1:3080`, dengan direktori peluncuran sebagai workspace default-nya. UI browser-nya tidak menerima prompt awal, jadi `omarchy agent prompt` membukanya dengan prompt di clipboard-mu untuk ditempel. Omarchy menjalankannya dengan preset izin no-approval dari DeepSeek. DeepSeek Harness mengunggah log sesi ke DeepSeek saat kamu menggunakan API model resminya; matikan itu di bawah _Settings > General > Upload Session Log_ di UI browser-nya. Masukan yang kamu kirim kepadanya juga diunggah bersama sesi, kecuali kamu menjalankannya dengan `DSH_TELEMETRY_MODE=DISABLED`.

### Agent default

Pilih agent default-mu dengan `omarchy default agent <name>` atau di bawah _Setup > Defaults > Agent_ di Omarchy Menu (`Super + Space`). Jika agent belum terinstal, memilihnya akan menginstalnya terlebih dahulu. Omarchy baru akan mengajakmu membuat pilihan ini dengan notifikasi satu kali.

Memilih Claude juga mencoba menyiapkan ekstensi browser-nya untuk Chromium, Chrome, Brave, Brave Origin, dan Edge. Penyiapan ekstensi berlaku untuk semua pengguna dan mungkin meminta kata sandi sistemmu; membatalkan atau gagal menginstal ekstensi tetap memilih dan meluncurkan Claude. Restart browser-mu, aktifkan ekstensi jika diminta, dan masuk ke Claude untuk menyelesaikan penyambungannya. Jalankan `/chrome` di Claude untuk memeriksa koneksi. Firefox dan Zen tidak mendukung ekstensi ini. Jika Claude sudah menjadi default-mu sebelum penyiapan ini ditambahkan, pilih lagi untuk menginstal ekstensi.

Setelah kamu memilih, `Super + Shift + Ctrl + A` meluncurkan agent default di jendela terminal khusus (atau memunculkan picker jika kamu belum memilih). Kamu juga bisa meluncurkannya langsung ke sebuah tugas dengan `omarchy agent prompt "Review this project"`. Freebuff dan DeepSeek Harness tidak menerima prompt awal, jadi mereka membuka dengan prompt di clipboard-mu untuk ditempel sebagai gantinya. Agent yang diluncurkan dengan cara ini berjalan tanpa pengawasan dalam mode don't-stop-to-ask masing-masing, jadi bersiaplah karena mereka benar-benar akan melakukan sesuatu! MiniMax Code tidak memiliki mode seperti itu untuk sesi interaktifnya, jadi ia meminta izin seperti biasa. Dan karena agent menolak mengingat trust untuk direktori home-mu, peluncuran dari `$HOME` dimulai di `~/Work` sebagai gantinya.

Ada juga shortcut terminal: `a` menjalankan agent default secara inline di terminal saat ini, sementara `c`, `cx`, dan `cy` memulai OpenCode, Claude Code, dan Codex secara langsung (lagi-lagi dalam mode auto-approving mereka). Perubahan tema juga tersinkron ke agent: Claude Code, Pi, OpenCode, dan Hermes (setelah Omarchy menginstalnya) semuanya mengikuti saat kamu mengganti tema Omarchy.

### Panel agent

Bar atas memiliki ikon agent. Sebelum kamu menyiapkan agent, panelnya memandumu masuk ke Claude, Codex, atau Grok, dan yang pertama menjadi agent default-mu. Setelah itu, panel menempatkan setiap langganan dalam satu halaman: setiap agent dan akun dengan paketnya, meter untuk setiap batas sesi 5 jam dan batas mingguannya beserta waktu hingga ia reset (arahkan kursor untuk persentase pastinya), atau sisa saldo prabayar, di bawah sebuah baris yang bergantian menampilkan apa yang telah kamu gunakan di semua itu, seperti token minggu ini dan model yang paling sering kamu gunakan. Di bawah _Make something_ ia menawarkan prompt awal untuk tema, plugin, atau aplikasi baru yang menyerahkan tugas kepada agent default-mu. Aplikasi dibangun dengan cara yang sama seperti Hype, Monologue, dan Omacut milik Omarchy sendiri, dalam C++ dan Qt Quick, mengikuti skill agent omarchy-app, dan compiler serta komponen Qt yang mereka butuhkan sudah terinstal. Claude Code, Codex, Grok, Kimi, Cursor dan jatah Grok Bot-nya, GitHub Copilot, Muse, Antigravity, Kimchi, dan Devin tercakup langsung dengan batas-batasnya, dan Hermes, Mistral Vibe, dan Qwen Code menampilkan sesi dan token mereka setelah kamu menggunakannya. Paket dan key provider yang kamu gunakan melalui pi, omp, atau opencode juga muncul: OpenCode Zen dan Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan, dan Synthetic dengan batas-batasnya; Fireworks, OpenRouter, dan DeepSeek dengan saldo prabayar mereka; dan model yang kamu jalankan di hardware milikmu sendiri di bawah Local models. Setiap agent dihitung sekali, di bawah pihak yang menagihnya, berapa pun banyaknya harness yang kamu gunakan untuk menjalankannya.

Klik kiri ikon bar untuk panel, klik kanan untuk meluncurkan agent default-mu. Catatan penggunaan di baliknya dibuat ulang setiap 15 menit oleh `omarchy agent usage-update`, dan panel bahkan dapat menggabungkan penggunaan dari mesin lain milikmu melalui folder yang tersinkron. Lihat README di bawah `$OMARCHY_PATH/shell/plugins/agents/` untuk pengaturan lengkapnya.

### Beberapa langganan

Jika kamu membayar lebih dari satu paket Claude, Codex, atau Grok — misalnya Max pribadi dan satu untuk pekerjaan — Omarchy dapat menjaga semuanya tetap masuk dan berpindah di antaranya. Tambahkan langganan dengan + di panel agent, yang memandumu langsung di sana, atau dengan `omarchy agent account add claude Work` (atau `codex`, atau `grok`). Ia menginstal CLI jika belum ada. Akun pertama untuk sebuah provider masuk melalui browser normalmu, tepat di tempat CLI selalu mencarinya. Setiap akun setelah itu masuk melalui jendela privat, sehingga akun yang sudah masuk di browser-mu tidak terambil secara tidak sengaja; masuk di sana sebagai akun yang kamu tambahkan, dan tutup jendela privat yang sudah terbuka sebelumnya terlebih dahulu. Jangan pernah logout dari CLI untuk melakukan ini: logout mencabut login yang tersimpan, dan akun itu harus ditambahkan lagi.

Untuk menyalin login langgananmu ke mesin Omarchy lain melalui SSH, jalankan `omarchy agent account copy user@laptop`. Pengirim menyediakan receiver sementara ketika tujuan tidak memilikinya terinstal, sehingga mesin Omarchy lama dapat menerima akun tanpa update. Receiver yang terinstal diutamakan. Ini menyalin semua langganan Claude, Codex, dan Grok; tambahkan nama provider untuk memilihnya, seperti dalam `omarchy agent account copy laptop claude`. Nama akun dan ID perintah cocok dengan sumber, termasuk akun yang sudah ada di tujuan. Akun tujuan yang tidak terkait menerima akhiran numerik jika namanya bertabrakan, dan pengaturan, skill, plugin, dan riwayat percakapan tetap lokal di setiap mesin.

Kredensial tujuan yang ada tetap dipertahankan. Akun sumber yang sudah masuk di sana namanya disinkronkan tanpa mengganti kredensialnya; akun lain ditambahkan di sampingnya. Untuk mengganti kredensial tersimpan untuk akun yang cocok, gunakan `omarchy agent account copy --replace laptop claude` setelah keluar dari sesi akun itu di tujuan. Tujuan baru juga mendapatkan akun aktif sumber dan preferensi perpindahan; tujuan yang sudah mapan mempertahankan miliknya sendiri.

Kredensial dikirim melalui SSH dan disimpan dalam file privat di tujuan, jadi salin hanya ke mesin yang kamu percaya. Ini adalah penyalinan satu kali, bukan sinkronisasi berkelanjutan. Token refresh Codex dapat dirotasi oleh mesin lain, membuat login salinan membutuhkan perpanjangan; login terpisah tetap menjadi pilihan paling andal untuk penggunaan bersamaan di beberapa mesin. Lihat [panduan autentikasi akun Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Satu akun per provider aktif, dan setiap sesi baru dimulai sebagai akun itu: `cx`, `cy`, `claude`, `codex`, atau `grok` biasa, apa pun yang diluncurkan melalui `omarchy agent`, dan script atau editor yang menemukan CLI di `PATH`. Berpindah dengan `omarchy agent account use work` (dan kembali dengan `omarchy agent account use main`), atau di panel dengan menekan nomor akun lalu `Enter` (atau mengklik tombol Use-nya). Sesi yang sudah berjalan tetap pada akun yang mereka mulai. Riwayat percakapan, pengaturan, skill, dan plugin dibagi antar akun, sehingga `claude --continue` di folder yang sama melanjutkan dari tempat terakhir pada akun baru.

Dengan lebih dari satu akun, panel menunjukkan batas setiap akun berdampingan, dengan yang aktif ditandai. Secara default Omarchy memberitahumu ketika akun aktif melewati 95% dari sebuah batas, dan mengklik notifikasi beralih ke akun dengan ruang tersisa paling banyak. Arahkan kursor ke baris akun di panel dan klik Autoswitch yang muncul di samping Use (atau tekan `m`), atau jalankan `omarchy agent account mode auto`, untuk membuatnya beralih sendiri sebagai gantinya; saat aktif, Autoswitch menggantikan Use, dan mengkliknya lagi kembali ke pemberitahuan. Tambahkan angka untuk mengubah ambang batas, seperti dalam `omarchy agent account mode auto 90`. Jika setiap akun melebihi ambang batas, kamu akan diberitahu sekali, beserta akun mana yang bebas terlebih dahulu. Saat akun aktif berada dalam 15 poin dari ambang batasnya (80% pada default), batasnya diperiksa setiap tiga menit bukan setiap 15.

`omarchy agent account list` menunjukkan setiap akun dan batas terbarunya, `omarchy agent account remove work` melupakan satu akun, dan `omarchy agent account rename primary Hey` mengganti nama satu akun (atau klik nama akun di panel). Perintah-perintah ini bekerja pada akun agent default-mu; untuk menjangkau provider lain, sebutkan namanya terlebih dahulu, seperti dalam `omarchy agent account use codex side`. Login yang sudah kamu miliki di `~/.claude` atau `~/.codex` adalah akun _Main_ dan tetap di tempatnya. Akun yang tidak digunakan lebih dari sekitar delapan jam dapat menunjukkan _Sign-in required_; klik ia untuk masuk akun itu lagi langsung di panel, atau mulai sesi di dalamnya, yang menyegarkan login dengan sendirinya. MCP servers yang kamu miliki saat akun ditambahkan ikut ke akun itu, tetapi yang kamu tambahkan nanti dengan `claude mcp add` hanya mencapai akun tempat kamu menambahkannya. Claude Desktop dan tool yang dikonfigurasi dengan path absolut ke binary CLI tidak mengikuti perpindahan. `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, atau `GROK_HOME` eksplisit diutamakan daripada akun yang dipilih.

### Diagnosis crash

Omarchy memantau systemd-coredump untuk crash proses. Saat sesuatu segfault, kamu akan mendapatkan notifikasi "Process crashed" — klik ia, dan crash diserahkan ke agent default-mu bersama skill diagnose-crash dari Omarchy, yang memandu agent menetapkan fakta dari core dump dan memutuskan apakah crash layak dilaporkan ke upstream. Kamu juga dapat menjalankannya secara manual terhadap PID apa pun dari `coredumpctl list` dengan `omarchy agent crash <pid>`.

Pemantauan aktif secara default. Matikan di bawah _Trigger > Toggle > Crash Capture_ (atau dengan `omarchy toggle crash-capture`) dan notifikasi berhenti; `omarchy agent crash <pid>` masih berfungsi secara manual.

Crash juga dapat dibisukan satu program pada satu waktu, yang ditawarkan diagnosis kepadamu pada akhirnya. `omarchy crash mute hyprland` menghentikan notifikasi untuk program itu saja, `omarchy crash mute hyprland off` mengembalikannya, dan `omarchy crash mute` sendirian mencantumkan apa yang telah kamu bisukan. Ia menerima path binary maupun namanya, jadi `omarchy crash mute /usr/bin/hyprland` melakukan hal yang sama. Kutip nama dengan spasi di dalamnya, seperti dalam `omarchy crash mute 'Some App'`. Semua yang lain tetap memberi notifikasi, dan program yang dibisukan tetap crash — ini menyembunyikan pengingat, bukan memperbaiki apa pun.

### Aplikasi desktop

Menu _Install > AI_ juga membawa beberapa aplikasi AI grafis: aplikasi desktop ChatGPT, aplikasi desktop Claude (beta Linux dari Anthropic, dengan tab Chat, Cowork, dan Claude Code), Grok Bot untuk mengobrol dengan model xAI, Herdr Desktop, Hermes Desktop, OpenClaw, aplikasi desktop Perplexity, dan T3 Code. Grok Bot adalah aplikasi chat desktop. Agent coding adalah perintah `grok`.

Hermes Desktop adalah yang perlu diketahui, karena sebuah mesin memiliki satu Hermes, dan itu milik aplikasi: Hermes hanya pernah diinstal melalui aplikasi, dan perintah `hermes` yang dijalankan agent default adalah milik aplikasi. Memilih Hermes sebagai agent default menginstal hal yang sama seperti yang dilakukan entri _Install > AI_: package, dan runtime Hermes di bawah `~/.hermes` yang disiapkan oleh installer Hermes sendiri, yang memakan beberapa menit saat pertama kali. Runtime itu adalah satu-satunya Hermes yang digunakan perintah `hermes` di terminal, agent default, dan aplikasi, dan ia memperbarui dirinya sendiri dengan `hermes update` daripada menunggu rilis Omarchy. Menginstalnya juga memberi Hermes tema Omarchy sebagai skin bernama `omarchy`, yang diikuti setiap permukaan Hermes saat kamu berganti tema; pilih yang lain di bawah pengaturan Appearance Hermes atau dengan `/skin` jika kamu lebih suka tidak, dan Omarchy membiarkan pilihan itu. Menghapus aplikasi di bawah _Remove > AI_ menutup Hermes terlebih dahulu, termasuk gateway, membawa runtime itu bersamanya, dan menyimpan chat, memori, dan skill yang ditulis Hermes untuk dirinya sendiri kecuali kamu menyuruhnya sebaliknya: ia bertanya, dengan default tidak, apakah data itu dan pengaturan koneksimu juga harus dihapus.

Pengalaman desktop OpenClaw adalah Control UI-nya, yang membuka sebagai aplikasi web yang didukung gateway lokalnya sendiri. OpenClaw tinggal di `~/.openclaw` dan memperbarui dirinya sendiri: gunakan tombol "Update Gateway" di Control UI atau jalankan `openclaw update`, dan gateway restart pada versi baru. Omarchy hanya memilih rilis awal instalasi baru. Menghapus OpenClaw di bawah _Remove > AI_ membawa service gateway dan aplikasinya bersamanya lalu bertanya apakah `~/.openclaw` juga harus dihapus, karena itu menyimpan chat dan kredensialmu di samping OpenClaw itu sendiri dan runtime plugin yang diunduhnya; default menyimpannya, dan menginstal OpenClaw lagi akan mengambilnya kembali.

Herdr Desktop adalah aplikasi desktop [Herdr](https://herdr.dev): spaces, tabs, dan panes terminal dan agent coding yang tetap berjalan di core-nya saat kamu menutup jendela. Ia berasal dari installer Herdr sendiri daripada package, sehingga tinggal di `~/.local/share/herdr-app`, membawa core-nya di `~/.local/bin/herdr-core` saat kamu belum memilikinya, dan memperbarui keduanya sendiri. Ia berada di samping perintah `herdr` yang disertakan Omarchy pada `Super + Ctrl + Return` daripada menggantikannya. Menginstalnya memilih tema Omarchy Herdr, yang mengikuti tema Omarchy-mu sejak saat itu. Herdr menyimpan satu tema untuk mode terang dan satu untuk mode gelap, sehingga setelah berganti antara tema Omarchy gelap dan terang, pilih Omarchy di theme picker Herdr sekali lagi untuk mode lainnya.

T3 Code berjalan dari rilis AppImage resminya di `~/.local/share/t3code` daripada dari package, sehingga memperbarui dirinya sendiri. Menginstalnya bertanya apakah akan memulai di channel Stable atau Nightly; beralih nanti di pengaturan T3 Code. Thread dan pengaturanmu tinggal di `~/.t3`, dan menghapus T3 Code di bawah _Remove > AI_ membawa mereka bersamanya.

### Model lokal

Jalankan model terbuka di mesinmu sendiri untuk agent coding-mu. Prompt dan kodemu tetap di mesin; tidak ada yang dikirim ke model meninggalkan mesin. Mulai dengan:

```bash
omarchy agent local use best
```

Atau, di panel agent di bar atas, pilih + lalu Local AI, yang muncul saat sebuah model cocok untuk mesin ini. Pertama kali, ini menginstal Podman, yang menjalankan model, dan pada mesin NVIDIA toolkit container NVIDIA, yang memberi mereka GPU. Omarchy kemudian memilih model yang direkomendasikan untuk mesin ini, mengunduhnya, dan menjalankannya. Harapkan unduhan puluhan GB dan sebagian besar memori mesin digunakan saat model berjalan: Flash Next menggunakan sekitar 100 GiB dengan konteks 256K penuhnya. Jika model lain menahan memori yang dibutuhkannya, ia disiapkan dalam keadaan berhenti, siap dimulai setelah kamu menghentikan satu. Model berhenti saat logout; hentikan sendiri saat kamu membutuhkan memori untuk sesuatu yang lain.

`omarchy agent local list` menunjukkan opsi dan menjelaskan mengapa beberapa tidak cocok. Untuk menyiapkan yang lain, jalankan `omarchy agent local use <recipe>`. Hari ini, `qwen3.8-flash-next-gufo` dan `qwen3.8-27b-gufo` tersedia untuk mesin Strix Halo 128 GB; 27B menggunakan sekitar 40 GiB, sehingga meninggalkan ruang untuk pekerjaan lain. Recipe dan rekomendasi baru tiba dengan `omarchy update`, melalui package.

Setiap model yang kamu siapkan mendapatkan barisnya sendiri di panel agent, di samping langgananmu: play untuk memulainya, pause untuk menghentikannya dan membebaskan memorinya, dan tombol terminal untuk membuka agent-mu di atasnya. Beberapa dapat berjalan sekaligus saat mereka cocok bersama dalam memori; jika satu tidak cocok, Omarchy menyatakan model berjalan mana yang harus dihentikan. Seret baris untuk mengurutkannya, dan tekan Delete pada baris yang dipilih untuk menghapus model dan unduhannya.

Dari command line, `omarchy agent local start <recipe>` dan `omarchy agent local stop <recipe>` melakukan hal yang sama, `omarchy agent local status` menunjukkan setiap model, dan `omarchy agent --local` membuka agent default-mu pada model terakhir yang kamu mulai (pi jika agent default-mu tidak dapat menggunakan model lokal). Klien kompatibel OpenAI apa pun juga dapat terhubung: `status` menunjukkan alamat setiap model (yang pertama adalah `http://127.0.0.1:11435/v1`), nama recipe adalah modelnya, dan key berada di `~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` menghapus model dan unduhan yang tidak digunakan model lain.

Runtime pihak ketiga diberi label dengan penerbitnya. Omarchy menjalankan setiap model tanpa akses jaringan.

### LLM lokal

Omarchy merekomendasikan dua cara menjalankan model LLM lokal: LM Studio dan Ollama. LM Studio menyediakan antarmuka GUI untuk menemukan model open-weight, menginstalnya, dan menjalankannya. Ini cara yang bagus untuk memulai dengan mudah. Ollama menawarkan CLI untuk melakukan hal serupa. Tetapi jika kamu baru dalam model lokal, saya akan mulai dengan LM Studio. Kamu dapat menginstal salah satunya di bawah _Install > AI_ di Omarchy Menu.

### Skill Omarchy

Skill agent membantu AI menggunakan tool tertentu dengan cara tertentu, dan Omarchy disertakan dengan skill default untuk menyesuaikan sistem. Seperti mengubah konfigurasi Hyprland-mu, menyesuaikan bar, atau bahkan membuat tema baru dari nol. Ia di-symlink ke direktori skill untuk Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` dan setiap `~/.hermes/profiles/*/skills`), dan lokasi generik `~/.agents/skills`, sehingga sebagian besar harness mengambilnya secara otomatis.

Tetapi kamu harus menganggap skill ini eksperimental. Model yang berbeda akan menggunakannya dengan efek berbeda. Sebaiknya jalankan dalam mode plan terlebih dahulu, sehingga kamu memiliki gambaran tentang apa yang ingin diubah agent. Lalu bersiaplah untuk rollback perubahan atau bahkan menjalankan `omarchy reinstall configs`, jika agent membuat segalanya berantakan.
