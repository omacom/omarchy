### Menginstal dan memperbarui agen

Kecuali Hermes dan OpenClaw, agen-agen ini menggunakan instalasi lazy dari mise: peluncuran pertama menginstal CLI, dan peluncuran berikutnya menggunakannya kembali. mise juga memeriksa rilis baru untuk agen yang terinstal paling banyak sekali setiap empat jam, tepat sebelum agen dimulai atau di latar belakang pada prompt shell. Jika pembaruan itu gagal atau kamu offline, versi yang terinstal yang akan berjalan. `omarchy update` memperbarui agen yang terinstal bersama seluruh Omarchy, dan `mup` hanya memperbarui tool yang dikelola mise.

Pembaru bawaan agen itu sendiri, seperti `claude update`, `codex update`, atau tombol pembaruan di sebuah aplikasi, tidak memperbarui instalasi yang dikelola mise. `codex update` gagal, dan `claude update` bisa melaporkan berhasil padahal menginstal salinan terpisah yang tidak dilacak mise. Jika kamu lebih suka menggunakan installer dan pembaru bawaan agen, tambahkan ke `disable_tools`; lihat [Tool CLI yang sudah terinstal](18-development-tools.md#preinstalled-cli-tools).

Untuk menginstal semua tool lazy yang dikonfigurasi sebelum kamu membutuhkannya, jalankan `mise install --include-lazy`. Ini mencakup tool CLI default Omarchy lainnya serta agen-agen tersebut. Lihat [Tool CLI yang sudah terinstal](18-development-tools.md#preinstalled-cli-tools) untuk menginstal satu tool atau menggunakan instalasimu sendiri.

`grok` diinstal melalui paket `grok` first-party dari mise, dengan cara yang sama seperti `claude` dan `codex`. Jalankan `grok`, atau beri bintang di panel agen. Lewati installer `curl | bash` di x.ai. Cara itu menaruh salinan kedua di `~/.grok/bin`, mendahulukannya di `PATH`, dan menimpa wrapper Omarchy.

`dsh` membuka UI browsernya di `127.0.0.1:3080`, dengan direktori peluncuran sebagai workspace default-nya. UI browsernya tidak menerima prompt awal, jadi `omarchy agent prompt` membukanya dengan prompt di clipboard-mu untuk ditempel. Omarchy memulainya dengan preset izin no-approval dari DeepSeek. DeepSeek Harness mengunggah log sesi ke DeepSeek saat kamu menggunakan API model resminya; matikan itu di _Settings > General > Upload Session Log_ di UI browsernya. Masukan yang kamu kirimkan kepadanya juga diunggah bersama sesi, kecuali kamu memulainya dengan `DSH_TELEMETRY_MODE=DISABLED`.

### Agen default

Pilih agen default-mu dengan bintang di samping agen di panel agen, yang terisi pada agen default, atau dengan `omarchy default agent <name>`, yang juga menerima harness apa pun tanpa baris di sana. Jika agennya belum terinstal, memilihnya akan menginstalnya terlebih dahulu, dan ia juga mendapatkan peluncurnya sendiri di peluncur aplikasi, di samping Agent. Omarchy yang baru terinstal mengajakmu menyiapkannya dengan notifikasi satu kali, yang membuka panel agen.

Memilih Claude juga berupaya menyiapkan ekstensi browsernya untuk Chromium, Chrome, Brave, Brave Origin, dan Edge. Penyiapan ekstensi berlaku untuk semua pengguna dan mungkin meminta kata sandi sistemmu; membatalkan atau gagal menginstal ekstensi tetap akan memilih dan meluncurkan Claude. Mulai ulang browsermu, aktifkan ekstensi jika diminta, dan masuk ke Claude untuk menyelesaikan penyambungannya. Jalankan `/chrome` di Claude untuk memeriksa koneksinya. Firefox dan Zen tidak mendukung ekstensi ini. Jika Claude sudah menjadi default-mu sebelum penyiapan ini ditambahkan, pilih lagi untuk menginstal ekstensinya.

Setelah kamu memilih, `Super + Shift + Ctrl + A` meluncurkan agen default di jendela terminal khusus (atau memunculkan pemilih jika kamu belum memilih). Kamu juga bisa meluncurkannya langsung ke sebuah tugas dengan `omarchy agent prompt "Review this project"`. Freebuff dan DeepSeek Harness tidak menerima prompt awal, jadi mereka membuka dengan prompt di clipboard-mu untuk ditempel sebagai gantinya. Agen yang diluncurkan dengan cara ini berjalan tanpa pengawasan dalam mode don't-stop-to-ask masing-masing, jadi bersiaplah karena mereka benar-benar akan melakukan sesuatu! MiniMax Code tidak memiliki mode seperti itu untuk sesi interaktifnya, jadi ia meminta izin seperti biasa. Dan karena agen menolak mengingat kepercayaan untuk direktori home-mu, peluncuran dari `$HOME` dimulai di `~/Work` sebagai gantinya.

Ada pintasan terminal juga: `a` menjalankan agen default secara inline di terminal saat ini, sedangkan `c`, `cx`, dan `cy` memulai OpenCode, Claude Code, dan Codex secara langsung (lagi-lagi dalam mode auto-approving mereka). Perubahan tema juga tersinkron ke agen: Claude Code, Pi, OpenCode, dan Hermes (setelah Omarchy menginstalnya) semuanya ikut berubah saat kamu mengganti tema Omarchy.

### Instruksi agenmu

Aturan pribadi untuk setiap agen ditaruh di `~/.agents/AGENTS.md`, di samping skill bersama di `~/.agents/skills`. Buka dengan ikon dokumen di samping + di panel agen, atau `omarchy agent instructions --edit`, yang juga menautkannya ke setiap harness yang menyimpan file globalnya sendiri: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` milik Copilot, dan seterusnya. Crush dan Amp membaca tautan `~/.config/AGENTS.md`, sedangkan omp, Kimi, dan DeepSeek Harness membaca `~/.agents/AGENTS.md` secara langsung. Memilih agen default juga menautkannya. File instruksi yang sudah kamu miliki menjadi file bersama jika belum ada; jika sudah ada, file itu disimpan di samping tautan sebagai `.bak`. Jalankan `omarchy agent instructions` untuk menautkan ulang setelah menginstal agen lain.

### Panel agen

Bar atas memiliki ikon agen. Sebelum kamu menyiapkan agen, panelnya menawarkan tiga cara untuk memulai: masuk ke langganan Claude, Codex, Grok, Gemini, Muse, Cursor, atau Copilot, atau di bawah More sebuah paket coding OpenCode Go, MiniMax, Synthetic, atau Z.ai; bayar sesuai pemakaian dengan Fireworks, OpenCode Zen and Go, OpenRouter, atau di bawah More DeepSeek atau provider lain mana pun yang dapat dimasuki OpenCode, semuanya berjalan di OpenCode; atau jalankan model terbaik untuk komputermu, jika ada yang cocok. Yang pertama kamu selesaikan menjadi agen default-mu, dan + di panel, atau _Agent > Add_ di Omarchy Menu, menawarkan tiga hal yang sama di kemudian hari. Setelah itu, panel menempatkan setiap langganan dalam satu halaman: setiap agen dan akun beserta paketnya, meter untuk masing-masing batas sesi 5 jam dan batas mingguannya beserta waktu hingga reset (arahkan kursor untuk persentase pastinya), atau sisa saldo prabayar, di bawah sebuah baris yang bergantian menampilkan apa yang telah kamu gunakan di semuanya, seperti token minggu ini dan model yang paling sering kamu gunakan. Di bawah _Make something cool_ ia menawarkan prompt pemula untuk tema, plugin, aplikasi, atau game baru yang menyerahkan tugasnya ke agen default-mu. Aplikasi dibangun dengan cara yang sama seperti Hype, Monologue, dan Omacut milik Omarchy sendiri, dalam C++ dan Qt Quick, mengikuti skill agen omarchy-make-app, dan compiler serta komponen Qt yang mereka butuhkan sudah terinstal. Game adalah satu halaman three.js di `~/Games/vibes`, mengikuti skill agen omarchy-make-game, dan semuanya terbuka dari satu peluncur Game Vibes dalam tema saat ini; mereka memuat three.js dari web, jadi mereka membutuhkan koneksi untuk memulai. Claude Code, Codex, Grok, Kimi, Cursor dan jatah Grok Bot-nya, GitHub Copilot, Muse, Gemini (melalui Antigravity), dan Devin tercakup langsung dengan batas-batasnya, Kimchi dengan paketnya, kredit prabayar, dan anggaran pengeluarannya, dan Hermes, Mistral Vibe, dan Qwen Code menampilkan sesi dan token mereka setelah kamu menggunakannya. Paket dan kunci provider yang kamu gunakan melalui pi, omp, atau opencode juga muncul: OpenCode Zen and Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan, dan Synthetic beserta batas-batasnya; OpenRouter dan DeepSeek beserta saldo prabayarnya; Fireworks beserta pengeluarannya selama 30 hari terakhir. Token dari model yang kamu jalankan di hardware-mu sendiri juga dihitung dalam total; model-model itu sendiri memiliki panelnya sendiri, yang dijelaskan di bawah [Model lokal](#local-models). Setiap agen dihitung sekali, di bawah siapa pun yang menagihnya, berapa pun banyaknya harness yang kamu gunakan untuk menjalankannya.

Klik kiri ikon bar untuk panel, atau tekan `Super + Ctrl + X`, klik kanan untuk meluncurkan agen default-mu, dan klik tengah untuk menyegarkan. Catatan penggunaan di baliknya dibuat ulang setiap 15 menit oleh `omarchy agent usage update`, dan panel bahkan dapat menggabungkan penggunaan dari mesinmu yang lain melalui folder yang disinkronkan. Lihat README di `$OMARCHY_PATH/shell/plugins/agents/` untuk pengaturan lengkapnya.

### Beberapa langganan

Jika kamu membayar lebih dari satu paket Claude, Codex, atau Grok — misalnya Max pribadi dan satu untuk pekerjaan — Omarchy dapat menjaga semuanya tetap masuk dan berpindah di antaranya. Tambahkan langganan dengan + di panel agen, yang memandumu langsung di sana, atau dengan `omarchy agent account add claude Work` (atau `codex`, atau `grok`). + dan perintah yang sama masuk ke Gemini (`gemini`) dan OpenCode (`opencode`), dan menyimpan kunci API Fireworks (`fireworks`) atau OpenRouter (`openrouter`) di OpenCode; perintah itu juga masuk ke Copilot (`copilot`), Cursor (`cursor`), dan Muse (`muse`). Masing-masing dari mereka menyimpan satu kali masuk saja. Ia menginstal CLI jika belum ada. Akun pertama untuk sebuah provider masuk melalui browser normalmu, tepat di tempat CLI selalu mencarinya. Setiap akun setelah itu masuk melalui jendela privat, jadi akun yang sudah dimasuki browsermu tidak terambil secara tidak sengaja; masuklah di sana sebagai akun yang kamu tambahkan, dan tutup dulu jendela privat apa pun yang sudah terbuka. Jangan pernah keluar dari CLI untuk melakukan ini: keluar akan mencabut sesi masuk yang tersimpan, dan akun itu harus ditambahkan lagi.

Untuk menyalin login langgananmu ke mesin Omarchy lain melalui SSH, jalankan `omarchy agent account copy user@laptop`. Pengirim menyediakan penerima sementara ketika tujuan belum memiliki yang terinstal, jadi mesin Omarchy yang lebih lama dapat menerima akun tanpa pembaruan. Penerima yang terinstal diutamakan. Ini menyalin semua langganan Claude, Codex, dan Grok; tambahkan nama provider untuk memilihnya, seperti pada `omarchy agent account copy laptop claude`. Nama akun dan ID perintah cocok dengan sumber, termasuk akun yang sudah ada di tujuan. Akun tujuan yang tidak terkait menerima akhiran angka jika namanya bentrok, dan pengaturan, skill, plugin, serta riwayat percakapan tetap lokal di setiap mesin.

Kredensial tujuan yang sudah ada dipertahankan. Akun sumber yang sudah masuk di sana namanya disinkronkan tanpa mengganti kredensialnya; akun lain ditambahkan di sampingnya. Untuk mengganti kredensial tersimpan untuk akun yang cocok, gunakan `omarchy agent account copy --replace laptop claude` setelah keluar dari sesi akun itu di tujuan. Tujuan yang masih baru juga mendapatkan akun aktif dan preferensi peralihan dari sumber; tujuan yang sudah mapan mempertahankan miliknya sendiri.

Kredensial berjalan melalui SSH dan disimpan dalam file privat di tujuan, jadi salinlah hanya ke mesin yang kamu percaya. Ini adalah penyalinan satu kali, bukan sinkronisasi berkelanjutan. Token refresh Codex dapat dirotasi oleh mesin lain, membuat login yang disalin perlu diperbarui; sesi masuk terpisah tetap menjadi pilihan paling andal untuk penggunaan bersamaan di beberapa mesin. Lihat [panduan autentikasi akun Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Satu akun per provider aktif, dan setiap sesi baru dimulai sebagai akun itu: `cx`, `cy`, `claude`, `codex`, atau `grok` biasa, apa pun yang diluncurkan melalui `omarchy agent`, dan skrip atau editor yang menemukan CLI di `PATH`. Beralihlah dengan `omarchy agent account use work` (dan kembali dengan `omarchy agent account use main`), atau di panel dengan menekan nomor akun lalu `Enter` (atau mengklik bintangnya). Sesi Claude yang sedang berjalan juga beralih, mulai dari pesan berikutnya: setiap sesi Claude berjalan di `~/.claude`, yang selalu menyimpan sesi masuk akun aktif. Sesi Claude yang dimulai di folder akunnya sendiri oleh Omarchy yang lebih lama menyimpan sesi masuk itu hingga keluar, jadi peralihan menyebutkan sesi-sesi tersebut dan selesai dengan sendirinya setelah mereka hilang. Sesi Codex dan Grok yang sedang berjalan tetap pada akun tempat mereka dimulai. Riwayat percakapan, pengaturan, skill, dan plugin dibagikan antar akun, jadi `claude --continue` di folder yang sama melanjutkan dari tempat kamu berhenti di akun baru.

Dengan lebih dari satu akun, panel menampilkan batas setiap akun berdampingan, dengan bintang terisi pada akun yang sedang digunakan. Omarchy memberitahumu ketika akun aktif melewati 95% dari sebuah batas, dan mengklik notifikasi beralih ke akun dengan ruang paling lega. Ia tidak pernah beralih dengan sendirinya. Ubah ambang batasnya dengan `omarchy agent account threshold 90`. Jika setiap akun melebihi ambang batas, kamu akan diberitahu sekali, beserta akun mana yang lebih dulu bebas. Selama akun aktif berada dalam 15 poin dari ambang batasnya (80% pada default), batasnya diperiksa setiap tiga menit, bukan setiap 15 menit.

`omarchy agent account list` menampilkan setiap akun dan batas terbarunya, `omarchy agent account remove work` melupakan satu akun, dan `omarchy agent account rename primary Hey` mengganti nama satu akun (atau klik nama akun di panel). Perintah-perintah ini bekerja pada akun agen default-mu; untuk menjangkau provider lain, sebutkan dulu, seperti pada `omarchy agent account use codex side`. Login yang sudah kamu miliki di `~/.claude` atau `~/.codex` adalah akun _Main_. Milik Codex tetap di tempatnya; milik Claude menunggu di foldernya sendiri selama akun lain aktif. Akun yang tidak digunakan selama lebih dari sekitar delapan jam dapat menampilkan _Sign-in required_; klik untuk masuk ke akun itu lagi langsung di panel, atau beralihlah kepadanya dan mulai sesi, yang menyegarkan sesi masuk dengan sendirinya. Server MCP yang kamu tambahkan dengan `claude mcp add` menjangkau setiap akun Claude, karena semuanya berjalan di `~/.claude`; untuk Codex dan Grok, server yang kamu miliki saat akun ditambahkan ikut bersamanya, tetapi server setelahnya hanya menjangkau akun tempat kamu menambahkannya. Claude Desktop menyimpan sesi masuknya sendiri, dan tool Codex atau Grok yang dikonfigurasi dengan path absolut ke binary CLI tidak mengikuti peralihan. `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, atau `GROK_HOME` yang eksplisit diutamakan atas akun yang dipilih.

### Diagnosis crash

Omarchy mengawasi systemd-coredump untuk crash proses. Setelah kamu memilih agen default, programmu apa pun yang melakukan dump core memunculkan notifikasi "Process crashed" — klik, dan crash itu diserahkan ke agen default-mu bersama skill omarchy-diagnose-crash dari Omarchy, yang memandu agen menetapkan fakta dari core dump dan memutuskan apakah crash itu layak dilaporkan ke upstream. Kamu juga bisa menjalankannya secara manual terhadap PID apa pun dari `coredumpctl list` dengan `omarchy agent crash <pid>`.

Pengawasan aktif secara default. Matikan di _Trigger > Toggle > Crash Capture Off_ (atau dengan `omarchy toggle crash-capture`) dan notifikasi akan berhenti; `omarchy agent crash <pid>` tetap bekerja secara manual.

Crash juga dapat dibungkam satu program pada satu waktu, yang ditawarkan diagnosis kepadamu di akhir. `omarchy crash mute hyprland` menghentikan notifikasi hanya untuk program itu, `omarchy crash mute hyprland off` mengembalikannya, dan `omarchy crash mute` sendiri mencantumkan apa yang telah kamu bungkam. Ia menerima path binary sama senangnya seperti namanya, jadi `omarchy crash mute /usr/bin/hyprland` melakukan hal yang sama. Kutip nama yang mengandung spasi, seperti pada `omarchy crash mute 'Some App'`. Segala sesuatu lain tetap memberi notifikasi, dan program yang dibungkam tetap crash — ini menyembunyikan pengingat, bukan memperbaiki apa pun.

### Aplikasi desktop

Menu _Install > AI_ juga membawa beberapa aplikasi AI grafis: Amp Desktop, Antigravity Desktop, aplikasi desktop ChatGPT, aplikasi desktop Claude (beta Linux dari Anthropic, dengan tab Chat, Cowork, dan Claude Code), Grok Bot untuk mengobrol dengan model xAI, Herdr Desktop, Hermes Desktop, OpenClaw, aplikasi desktop Perplexity, dan T3 Code. Grok Bot adalah aplikasi chat desktop. Agen coding-nya adalah perintah `grok`.

Hermes Desktop adalah yang perlu diketahui, karena sebuah mesin memiliki satu Hermes, dan itu milik aplikasinya: Hermes hanya pernah diinstal melalui aplikasi, dan perintah `hermes` yang dijalankan agen default adalah milik aplikasi. Memilih Hermes sebagai agen default menginstal hal yang sama seperti entri _Install > AI_: paketnya, dan runtime Hermes di `~/.hermes` yang disiapkan oleh installer Hermes sendiri, yang memerlukan beberapa menit saat pertama kali. Runtime itu adalah satu-satunya Hermes yang digunakan perintah terminal `hermes`, agen default, dan aplikasi, dan ia memperbarui dirinya sendiri dengan `hermes update` daripada menunggu rilis Omarchy. Menginstalnya juga memberikan tema Omarchy kepada Hermes sebagai skin bernama `omarchy`, yang diikuti setiap permukaan Hermes saat kamu mengganti tema; pilih yang lain di pengaturan Appearance Hermes atau dengan `/skin` jika kamu lebih suka tidak, dan Omarchy membiarkan pilihan itu. Menghapus aplikasi di _Remove > AI_ menutup Hermes terlebih dahulu, termasuk gateway, membawa runtime itu bersamanya, dan mempertahankan chat, ingatan, dan skill yang ditulis Hermes untuk dirinya sendiri kecuali kamu menyuruhnya lain: ia bertanya, dengan default tidak, apakah data itu dan pengaturan koneksimu juga harus hilang.

Pengalaman desktop OpenClaw adalah Control UI-nya, yang terbuka sebagai aplikasi web yang didukung gateway lokalnya sendiri. OpenClaw tinggal di `~/.openclaw` dan memperbarui dirinya sendiri: gunakan tombol "Update Gateway" di Control UI atau jalankan `openclaw update`, dan gateway akan mulai ulang pada versi baru. Omarchy hanya memilih rilis tempat instalasi baru dimulai. OpenClaw juga bisa menjadi agen default-mu: memilihnya di _Agent > Harness_ menyiapkan salinan yang sama di `~/.openclaw`, dan agen membuka UI terminal OpenClaw yang terhubung ke gateway-nya. Menghapus OpenClaw di _Remove > AI_ membawa layanan gateway dan aplikasinya bersamanya lalu bertanya apakah `~/.openclaw` juga harus hilang, karena di sana tersimpan chat dan kredensialmu di samping OpenClaw itu sendiri dan runtime plugin yang diunduhnya; default-nya mempertahankannya, dan menginstal OpenClaw lagi akan mengambilnya kembali.

Herdr Desktop adalah aplikasi desktop [Herdr](https://herdr.dev): spaces, tab, dan pane berisi terminal dan agen coding yang terus berjalan di core-nya saat kamu menutup jendela. Ia berasal dari installer Herdr sendiri bukan dari paket, jadi ia tinggal di `~/.local/share/herdr-app`, membawa core-nya di `~/.local/bin/herdr-core` ketika kamu belum memilikinya, dan memperbarui keduanya sendiri. Ia berada di samping perintah `herdr` yang disertakan Omarchy pada `Super + Ctrl + Return` daripada menggantikannya, dan mendapatkan tombol langsung perintah itu: `Alt + Return` dan `Alt + Shift + Return` membagi pane ke bawah atau ke kanan, `Alt + Escape` menutupnya, `Ctrl + Alt + Arrow` berpindah antar pane, `Alt + 1..9` dan `Alt + Left/Right` memilih tab, dan `Alt + Up/Down` berpindah antar spaces. `Ctrl + 1..9` memilih space dan `Alt + Shift + Up/Down` melangkah melalui agen. Tombol awalan `Ctrl + Space` tetap hanya untuk terminal, karena aplikasi tidak dapat menahan tombol Ctrl polos untuk sebuah urutan. Omarchy menulis ini ke `~/.config/herdr-app/keys.json`, dan `omarchy-refresh-herdr-app` mengembalikannya. Menginstalnya memilih tema Omarchy dari Herdr, yang mengikuti tema Omarchy-mu sejak saat itu. Herdr menyimpan satu tema untuk mode terang dan satu untuk mode gelap, jadi setelah beralih antara tema Omarchy gelap dan terang, pilih Omarchy di pemilih tema Herdr sekali lagi untuk mode lainnya.

T3 Code berjalan dari rilis AppImage resminya di `~/.local/share/t3code` bukan dari paket, jadi ia memperbarui dirinya sendiri. Menginstalnya bertanya apakah akan memulai di channel Stable atau Nightly; ganti nanti di pengaturan T3 Code. Thread dan pengaturanmu tinggal di `~/.t3`, dan menghapus T3 Code di _Remove > AI_ membawanya bersamanya.

### Model lokal

Jalankan model terbuka di mesinmu sendiri untuk agen coding-mu. Prompt dan kodemu tetap di mesin; tidak ada yang dikirim ke model yang meninggalkannya. Mulai dengan:

```bash
omarchy models use best text
```

Itu menyiapkan model teks terbaik untuk mesin ini, jenis yang digunakan agenmu. Model gambar, video, dan musik memiliki yang terbaiknya sendiri: `omarchy models use best image`, `video`, atau `music`. Jalankan `omarchy models use best` untuk melihat pilihan setiap jenis untuk mesin ini.

Atau buka panel model lokal dari ikon sparkles-nya di bar atas, di samping ikon agen, atau dengan Super + Ctrl + Alt + X, dan pilih +. Ikonnya muncul ketika sebuah model cocok untuk mesin ini. Podman, yang menjalankan model, disertakan dengan Omarchy, begitu juga container toolkit NVIDIA pada mesin NVIDIA, yang memberi mereka GPU; jika salah satunya hilang, penyiapan pertama akan menginstalnya. Omarchy kemudian memilih model yang direkomendasikan untuk mesin ini, mengunduhnya, dan memulainya. Harapkan unduhan puluhan GB dan sebagian besar memori mesin terpakai saat model berjalan: Flash Next menggunakan sekitar 100 GiB dengan konteks 256K penuhnya. Jika model lain menahan memori yang dibutuhkannya, ia disiapkan dalam keadaan berhenti, siap dimulai setelah kamu menghentikan salah satu. Model berhenti saat logout; hentikan sendiri saat kamu membutuhkan memori untuk hal lain.

`omarchy models list` menampilkan opsi dan menjelaskan mengapa beberapa tidak cocok. Untuk menyiapkan yang lain, jalankan `omarchy models use <recipe>`. Saat ini, `qwen3.8-flash-next-gufo` dan `qwen3.8-27b-gufo` tersedia untuk mesin Strix Halo 128 GB; 27B memerlukan sekitar 40 GiB, jadi ia menyisakan ruang untuk pekerjaan lain. Pada laptop 64 GB dengan Arc B390 dari Intel, `qwen3.6-35b-a3b-llamacpp` berjalan dalam sekitar 30 GiB. Resep dan rekomendasi baru datang dengan `omarchy update`, melalui paket.

Setiap model yang kamu siapkan mendapatkan barisnya sendiri di panel model lokal: play untuk memulainya, pause untuk menghentikannya dan membebaskan memorinya, dan tombol terminal untuk membuka agenmu di atasnya. Di bagian atas, sebuah bar menampilkan bagaimana memori mesin dibagi antara Omarchy itu sendiri (sistem dan aplikasimu), setiap model yang berjalan, dan yang bebas. Arahkan ke model yang berhenti dan bar menampilkan apakah ia muat, atau berapa kekurangannya. Beberapa dapat berjalan sekaligus ketika mereka muat bersama dalam memori; jika satu tidak muat, Omarchy menyebutkan model berjalan mana yang harus dihentikan. Seret baris berdasarkan logonya untuk mengurutkannya ulang, dan tekan Delete pada baris yang dipilih untuk menghapus model dan unduhannya.

Setiap model coding yang kamu siapkan juga mendapatkan entrinya sendiri di peluncur aplikasi, dengan nama model dan logo pembuatnya, seperti cara masuk ke Claude, Codex, atau Grok menambahkannya. Ia membuka agenmu pada model itu, dan memulai model terlebih dahulu jika belum berjalan: terminal menampilkannya sedang dimuat dan menyerahkan ke agen setelah siap. Menghapus model menghapus entrinya.

Tidak setiap model untuk coding. Model gambar, video, dan musik terbuka di Fantasi sebagai gantinya, aplikasi Omarchy untuk membuat gambar, video, dan musik dengan model yang berjalan di mesin ini, dipilih di sana atau dari barisnya di panel model lokal.

Sebuah model terus berjalan persis seperti saat disiapkan, jadi pembaruan Omarchy tidak pernah memulai ulangnya di bawah agenmu. Ketika Omarchy memiliki runtime yang lebih baru atau weights yang lebih baru untuk model yang telah kamu siapkan, barisnya menampilkan tombol pembaruan: tekan dan model disiapkan lagi di latar belakang, hanya mengunduh yang berubah, dan mulai ulang pada versi baru. Model yang berhenti tetap berhenti. `omarchy models update` melakukan hal yang sama untuk setiap model dari terminal.

Dari baris perintah, `omarchy models start <recipe>` dan `omarchy models stop <recipe>` melakukan hal yang sama, `omarchy models status` menampilkan setiap model, dan `omarchy agent --local` membuka model terakhir yang kamu mulai di pi, apa pun agen default-mu. Untuk menjadikan model itu yang dibuka hotkey agen, konsol Quake, dan _Make something_, jalankan `omarchy default agent local` atau pilih _Local model_ di _Agent > Harness_. pi juga mencantumkan setiap model yang telah kamu siapkan, dan yang ada di mesin yang telah kamu pasangkan, di pemilih modelnya sendiri, jadi `pi` biasa juga menjangkaunya. Klien apa pun yang kompatibel dengan OpenAI juga dapat terhubung: `status` menampilkan alamat setiap model (yang pertama adalah `http://127.0.0.1:11435/v1`), nama resep adalah modelnya, dan kuncinya ada di `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` menghapus model dan unduhan yang tidak digunakan model lain.

Runtime pihak ketiga dilabeli dengan penerbitnya. Omarchy menjalankan setiap model tanpa akses jaringan.

### LLM lokal

Omarchy merekomendasikan dua cara menjalankan model LLM lokal: LM Studio dan Ollama. LM Studio menyediakan antarmuka GUI untuk menemukan model open-weight, menginstalnya, dan menjalankannya. Itu cara yang bagus untuk memulai dengan mudah. Ollama menawarkan CLI untuk melakukan hal serupa. Tetapi jika kamu baru dalam model lokal, saya akan mulai dengan LM Studio. Kamu dapat menginstal salah satunya di _Install > AI_ di Omarchy Menu.

### Skill Omarchy

Skill agen membantu AI menggunakan tool tertentu dengan cara tertentu, dan Omarchy menyertakan tujuh di antaranya. Skill omarchy mencakup menyesuaikan sistem, seperti mengutak-atik config Hyprland-mu atau menyesuaikan bar. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app, dan omarchy-make-game mencakup membuat sesuatu yang baru, omarchy-contribute mencakup melaporkan bug atau mengirim perbaikan ke upstream, dan omarchy-diagnose-crash menelusuri core dump sebuah crash. Mereka disymlink ke direktori skill untuk Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` dan setiap `~/.hermes/profiles/*/skills`), dan lokasi generik `~/.agents/skills`, jadi sebagian besar harness mengambilnya secara otomatis. Folder skill milikmu sendiri dengan nama yang sama diutamakan.

Tetapi kamu harus memperlakukan skill-skill ini sebagai eksperimental. Model yang berbeda akan menggunakannya dengan efek yang berbeda. Sebaiknya jalankan dalam mode plan terlebih dahulu, agar kamu memiliki gambaran tentang apa yang ingin diubah agen. Lalu bersiaplah untuk mengembalikan perubahan atau bahkan menjalankan `omarchy reinstall configs`, jika agen mengacaukan segalanya.
