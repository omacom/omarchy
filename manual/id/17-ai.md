### Menginstal dan memperbarui agen

Kecuali Hermes dan OpenClaw, agen-agen ini menggunakan instalasi lazy dari mise: peluncuran pertama menginstal CLI, dan peluncuran berikutnya menggunakannya kembali. mise juga memeriksa apakah ada rilis baru untuk agen yang terinstal paling banyak sekali setiap empat jam, tepat sebelum agen dimulai atau di latar belakang pada prompt shell. Jika pembaruan itu gagal atau kamu sedang offline, versi yang terinstal yang dijalankan. `omarchy update` memperbarui agen yang terinstal bersama seluruh Omarchy, dan `mup` hanya memperbarui alat yang dikelola mise.

Pembaru bawaan agen itu sendiri, seperti `claude update`, `codex update`, atau tombol pembaruan di sebuah aplikasi, tidak memperbarui instalasi yang dikelola mise. `codex update` gagal, dan `claude update` dapat melaporkan keberhasilan sambil menginstal salinan terpisah yang tidak dilacak mise. Jika kamu lebih suka menggunakan penginstal dan pembaru bawaan agen, tambahkan agen itu ke `disable_tools`; lihat [Alat CLI yang sudah terpasang](18-development-tools.md#preinstalled-cli-tools).

Untuk menginstal semua alat lazy yang dikonfigurasi sebelum kamu membutuhkannya, jalankan `mise install --include-lazy`. Ini mencakup alat CLI default Omarchy lainnya serta agen-agen tersebut. Lihat [Alat CLI yang sudah terpasang](18-development-tools.md#preinstalled-cli-tools) untuk menginstal satu alat atau menggunakan instalasimu sendiri.

`grok` diinstal melalui paket `grok` pihak pertama dari mise, dengan cara yang sama seperti `claude` dan `codex`. Jalankan `grok`, atau pilih di bawah _Agent > Harness_. Lewati penginstal `curl | bash` di x.ai. Jalur itu menaruh salinan kedua di `~/.grok/bin`, menempatkannya di awal `PATH`, dan menimpa wrapper Omarchy.

`dsh` membuka UI browsernya di `127.0.0.1:3080`, dengan direktori peluncuran sebagai workspace default-nya. UI browsernya tidak menerima prompt awal, jadi `omarchy agent prompt` membukanya dengan prompt di clipboard-mu untuk ditempel. Omarchy memulainya dengan preset izin tanpa persetujuan dari DeepSeek. DeepSeek Harness mengunggah log sesi ke DeepSeek saat kamu menggunakan API model resminya; matikan itu di bawah _Settings > General > Upload Session Log_ di UI browsernya. Masukan yang kamu kirim kepadanya juga diunggah bersama sesi tersebut, kecuali kamu memulainya dengan `DSH_TELEMETRY_MODE=DISABLED`.

### Agen default

Pilih agen default-mu dengan `omarchy default agent <name>` atau di bawah _Agent > Harness_ di Omarchy Menu (`Super + Space`). Jika agennya belum terinstal, memilihnya akan menginstalnya terlebih dahulu, dan agen itu juga mendapatkan peluncurnya sendiri di peluncur aplikasi, di sebelah Agent. Omarchy yang baru terinstal akan mengundangmu untuk membuat pilihan ini dengan notifikasi satu kali.

Memilih Claude juga mencoba menyiapkan ekstensi browsernya untuk Chromium, Chrome, Brave, Brave Origin, dan Edge. Penyiapan ekstensi berlaku untuk semua pengguna dan mungkin meminta kata sandi sistemmu; membatalkan atau instalasi ekstensi yang gagal tetap memilih dan meluncurkan Claude. Mulai ulang browsermu, aktifkan ekstensi jika diminta, dan masuk ke Claude untuk menyelesaikan penyambungannya. Jalankan `/chrome` di Claude untuk memeriksa koneksinya. Firefox dan Zen tidak mendukung ekstensi ini. Jika Claude sudah menjadi default-mu sebelum penyiapan ini ditambahkan, pilih lagi untuk menginstal ekstensinya.

Setelah kamu memilih, `Super + Shift + Ctrl + A` meluncurkan agen default di jendela terminal khusus (atau memunculkan pemilih jika kamu belum memilih). Kamu juga dapat meluncurkannya langsung ke sebuah tugas dengan `omarchy agent prompt "Review this project"`. Freebuff dan DeepSeek Harness tidak menerima prompt awal, jadi keduanya dibuka dengan prompt di clipboard-mu untuk ditempel sebagai gantinya. Agen yang diluncurkan dengan cara ini berjalan tanpa pengawasan dalam mode jangan-berhenti-untuk-bertanya masing-masing, jadi bersiaplah karena mereka benar-benar akan melakukan sesuatu! MiniMax Code tidak memiliki mode seperti itu untuk sesi interaktifnya, jadi ia meminta izin seperti biasa. Dan karena agen menolak mengingat kepercayaan untuk direktori home-mu, peluncuran dari `$HOME` dimulai di `~/Work` sebagai gantinya.

Ada juga pintasan terminal: `a` menjalankan agen default secara inline di terminal saat ini, sementara `c`, `cx`, dan `cy` memulai OpenCode, Claude Code, dan Codex secara langsung (lagi-lagi dalam mode persetujuan otomatis mereka). Perubahan tema juga tersinkron ke agen: Claude Code, Pi, OpenCode, dan Hermes (setelah Omarchy menginstalnya) semuanya mengikuti saat kamu mengganti tema Omarchy.

### Instruksi agenmu

Aturan pribadi untuk setiap agen dimasukkan ke `~/.agents/AGENTS.md`, di sebelah skill bersama di `~/.agents/skills`. Buka file itu di bawah _Agent > Instructions_, yang juga menautkannya ke setiap harness yang menyimpan file globalnya sendiri: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` milik Copilot, dan seterusnya. Crush dan Amp membaca tautan `~/.config/AGENTS.md`, sementara omp, Kimi, dan DeepSeek Harness membaca `~/.agents/AGENTS.md` secara langsung. Memilih agen default juga menautkannya. File instruksi yang sudah kamu miliki menjadi file bersama jika belum ada; jika sudah ada, file itu disimpan di sebelah tautan sebagai `.bak`. Jalankan `omarchy agent instructions` untuk menautkan ulang setelah menginstal agen lain.

### Panel agen

Bar atas memiliki ikon agen. Sebelum kamu menyiapkan agen, panelnya memandumu untuk masuk ke Claude, Codex, atau Grok, dan yang pertama menjadi agen default-mu. Setelah itu, panel menempatkan setiap langganan dalam satu halaman: setiap agen dan akun dengan paketnya, meter untuk setiap batas sesi 5 jam dan batas mingguannya beserta waktu hingga batas itu direset (arahkan kursor untuk melihat persentase pastinya), atau sisa saldo prabayar, di bawah sebuah baris yang bergilir menampilkan apa yang telah kamu gunakan di semua agen tersebut, seperti token minggu ini dan model yang paling sering kamu gunakan. Di bawah _Make something cool_ panel ini menawarkan prompt pemula untuk tema, plugin, aplikasi, atau game baru yang menyerahkan tugasnya ke agen default-mu. Aplikasi dibuat dengan cara yang sama seperti Hype, Monologue, dan Omacut milik Omarchy sendiri, dalam C++ dan Qt Quick, mengikuti skill agen omarchy-make-app, dan compiler serta komponen Qt yang mereka butuhkan sudah terinstal. Game adalah satu halaman three.js di `~/Games/vibes`, mengikuti skill agen omarchy-make-game, dan semuanya dibuka dari satu peluncur Game Vibes dalam tema saat ini; game memuat three.js dari web, jadi mereka membutuhkan koneksi untuk memulai. Claude Code, Codex, Grok, Kimi, Cursor dan jatah Grok Bot-nya, GitHub Copilot, Muse, Antigravity, dan Devin dicakup langsung dengan batas-batas mereka, Kimchi dengan paketnya, kredit prabayar, dan anggaran pengeluarannya, serta Hermes, Mistral Vibe, dan Qwen Code menampilkan sesi dan token mereka setelah kamu menggunakannya. Paket dan kunci provider yang kamu gunakan melalui pi, omp, atau opencode juga muncul: OpenCode Zen dan Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan, dan Synthetic dengan batas-batas mereka; OpenRouter dan DeepSeek dengan saldo prabayar mereka; Fireworks dengan pengeluarannya selama 30 hari terakhir. Token dari model yang kamu jalankan di perangkat kerasmu sendiri juga dihitung ke dalam total; model-model itu sendiri memiliki panelnya sendiri, yang dijelaskan di bawah [Model lokal](#local-models). Setiap agen dihitung sekali, di bawah pihak yang menagihnya, berapa pun banyaknya harness yang kamu gunakan untuk menjalankannya.

Klik kiri ikon bar atau tekan `Super + Ctrl + X` untuk panel, klik kanan untuk meluncurkan agen default-mu, dan klik tengah untuk menyegarkan. Catatan penggunaan di baliknya dibuat ulang setiap 15 menit oleh `omarchy agent usage update`, dan panel bahkan dapat menggabungkan penggunaan dari mesinmu yang lain melalui folder yang disinkronkan. Lihat README di bawah `$OMARCHY_PATH/shell/plugins/agents/` untuk pengaturan lengkapnya.

### Beberapa langganan

Jika kamu membayar lebih dari satu paket Claude, Codex, atau Grok — misalnya Max pribadi dan satu untuk pekerjaan — Omarchy dapat menjaga semuanya tetap masuk dan berpindah di antaranya. Tambahkan langganan dengan + di panel agen, yang memandumu melakukannya langsung di sana, atau dengan `omarchy agent account add claude Work` (atau `codex`, atau `grok`). Perintah itu menginstal CLI jika belum ada. Akun pertama untuk sebuah provider masuk melalui browser normalmu, tepat di tempat CLI selalu mencarinya. Setiap akun setelah itu masuk melalui jendela privat, jadi akun yang sudah digunakan untuk masuk di browsermu tidak terambil secara tidak sengaja; masuk di sana sebagai akun yang sedang kamu tambahkan, dan tutup dulu jendela privat yang sudah terbuka. Jangan pernah keluar dari CLI untuk melakukan ini: keluar akan mencabut sesi masuk yang tersimpan, dan akun itu harus ditambahkan lagi.

Untuk menyalin login langgananmu ke mesin Omarchy lain melalui SSH, jalankan `omarchy agent account copy user@laptop`. Pengirim menyediakan receiver sementara ketika tujuan belum memilikinya terinstal, jadi mesin Omarchy yang lebih lama dapat menerima akun tanpa pembaruan. Receiver yang terinstal didahulukan. Ini menyalin semua langganan Claude, Codex, dan Grok; tambahkan nama provider untuk memilihnya, seperti dalam `omarchy agent account copy laptop claude`. Nama akun dan ID perintah cocok dengan sumbernya, termasuk akun yang sudah ada di tujuan. Akun tujuan yang tidak terkait menerima akhiran angka jika namanya bentrok, dan pengaturan, skill, plugin, serta riwayat percakapan tetap lokal di setiap mesin.

Kredensial tujuan yang sudah ada tetap dipertahankan. Akun sumber yang sudah masuk di sana namanya disinkronkan tanpa mengganti kredensialnya; akun lain ditambahkan di sampingnya. Untuk mengganti kredensial tersimpan untuk akun yang cocok, gunakan `omarchy agent account copy --replace laptop claude` setelah menutup sesi akun tersebut di tujuan. Tujuan yang baru juga mendapatkan akun aktif dan preferensi perpindahan dari sumber; tujuan yang sudah mapan mempertahankan miliknya sendiri.

Kredensial dikirim melalui SSH dan disimpan dalam file privat di tujuan, jadi salinlah hanya ke mesin yang kamu percaya. Ini adalah penyalinan satu kali, bukan sinkronisasi berkelanjutan. Token refresh Codex dapat dirotasi oleh mesin lain, sehingga login hasil salinan membutuhkan perpanjangan; sesi masuk terpisah tetap menjadi pilihan paling andal untuk penggunaan serentak di beberapa mesin. Lihat [Panduan autentikasi akun dari Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Satu akun per provider aktif, dan setiap sesi baru dimulai sebagai akun itu: `cx`, `cy`, `claude`, `codex`, atau `grok` biasa, apa pun yang diluncurkan melalui `omarchy agent`, serta skrip atau editor yang menemukan CLI di `PATH`. Berpindahlah dengan `omarchy agent account use work` (dan kembali dengan `omarchy agent account use main`), atau di panel dengan menekan nomor akun lalu `Enter` (atau mengklik tombol Use-nya). Sesi Claude yang sedang berjalan juga berpindah, mulai pesan berikutnya: setiap sesi Claude berjalan di `~/.claude`, yang selalu menyimpan sesi masuk akun aktif. Sesi Claude yang dimulai di folder akunnya sendiri oleh Omarchy yang lebih lama menyimpan sesi masuk itu hingga ia ditutup, jadi perpindahan tersebut menyebutkan sesi-sesi itu dan selesai dengan sendirinya setelah mereka hilang. Sesi Codex dan Grok yang sedang berjalan tetap menggunakan akun yang mereka mulai. Riwayat percakapan, pengaturan, skill, dan plugin dipakai bersama di semua akun, jadi `claude --continue` di folder yang sama melanjutkan dari tempat kamu berhenti di akun baru.

Dengan lebih dari satu akun, panel menampilkan batas setiap akun secara berdampingan, dengan akun aktif ditandai. Secara default Omarchy memberi tahumu ketika akun aktif melewati 95% dari sebuah batas, dan mengklik notifikasi berpindah ke akun dengan ruang tersisa paling banyak. Arahkan kursor ke baris akun di panel dan klik Autoswitch yang muncul di sebelah Use (atau tekan `m`), atau jalankan `omarchy agent account mode auto`, agar ia berpindah sendiri sebagai gantinya; saat aktif, Autoswitch menggantikan posisi Use, dan mengkliknya lagi kembali ke pemberitahuan. Tambahkan angka untuk mengubah ambangnya, seperti dalam `omarchy agent account mode auto 90`. Jika setiap akun melewati ambang, kamu akan diberi tahu sekali, beserta akun mana yang lebih dulu bebas. Saat akun aktif berada dalam 15 poin dari ambangnya (80% pada default), batasnya diperiksa setiap tiga menit, bukan setiap 15 menit.

`omarchy agent account list` menampilkan setiap akun dan batas terbarunya, `omarchy agent account remove work` melupakan satu akun, dan `omarchy agent account rename primary Hey` mengganti nama satu akun (atau klik nama akun di panel). Perintah-perintah ini bekerja pada akun agen default-mu; untuk menjangkau provider lain, sebutkan namanya terlebih dahulu, seperti dalam `omarchy agent account use codex side`. Login yang sudah kamu miliki di `~/.claude` atau `~/.codex` adalah akun _Main_. Akun Codex tetap di tempatnya; akun Claude menunggu di foldernya sendiri saat akun lain aktif. Akun yang dibiarkan tidak digunakan selama lebih dari sekitar delapan jam dapat menampilkan _Sign-in required_; klik akun itu untuk memasukkan akun tersebut lagi langsung di panel, atau berpindah ke akun itu dan mulai sebuah sesi, yang menyegarkan sesi masuknya sendiri. Server MCP yang kamu tambahkan dengan `claude mcp add` menjangkau setiap akun Claude, karena semuanya berjalan di `~/.claude`; untuk Codex dan Grok, server yang kamu miliki saat sebuah akun ditambahkan ikut ke akun itu, tetapi server yang ditambahkan kemudian hanya menjangkau akun tempat kamu menambahkannya. Claude Desktop menyimpan sesi masuknya sendiri, dan alat Codex atau Grok yang dikonfigurasi dengan path absolut ke biner CLI tidak mengikuti perpindahan. `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, atau `GROK_HOME` yang eksplisit didahulukan daripada akun yang dipilih.

### Diagnosis crash

Omarchy mengawasi systemd-coredump untuk crash proses. Setelah kamu memilih agen default, setiap program milikmu yang melakukan dump core memunculkan notifikasi "Process crashed" — klik notifikasi itu, dan crash diserahkan ke agen default-mu bersama skill omarchy-diagnose-crash dari Omarchy, yang memandu agen untuk menetapkan fakta dari core dump dan memutuskan apakah crash tersebut layak dilaporkan ke upstream. Kamu juga dapat menjalankannya secara manual terhadap PID apa pun dari `coredumpctl list` dengan `omarchy agent crash <pid>`.

Pengawasan ini aktif secara default. Matikan di bawah _Trigger > Toggle > Crash Capture Off_ (atau dengan `omarchy toggle crash-capture`) dan notifikasinya berhenti; `omarchy agent crash <pid>` tetap bekerja secara manual.

Crash juga dapat dibisukan satu program pada satu waktu, yang merupakan hal yang ditawarkan diagnosis kepadamu di akhir. `omarchy crash mute hyprland` menghentikan notifikasi hanya untuk program itu, `omarchy crash mute hyprland off` mengembalikannya, dan `omarchy crash mute` sendiri mencantumkan apa yang telah kamu bisukan. Perintah itu menerima path biner sama senangnya seperti namanya, jadi `omarchy crash mute /usr/bin/hyprland` melakukan hal yang sama. Kutip nama yang mengandung spasi, seperti dalam `omarchy crash mute 'Some App'`. Semua hal lain tetap memberi notifikasi, dan program yang dibisukan tetap crash — ini menyembunyikan pengingatnya, bukan memperbaiki apa pun.

### Aplikasi desktop

Menu _Install > AI_ juga membawa beberapa aplikasi AI grafis: Amp Desktop, Antigravity Desktop, aplikasi desktop ChatGPT, aplikasi desktop Claude (beta Linux dari Anthropic, dengan tab Chat, Cowork, dan Claude Code), Grok Bot untuk mengobrol dengan model xAI, Herdr Desktop, Hermes Desktop, OpenClaw, aplikasi desktop Perplexity, dan T3 Code. Grok Bot adalah aplikasi obrolan desktop. Agen coding-nya adalah perintah `grok`.

Hermes Desktop adalah yang perlu diketahui, karena sebuah mesin memiliki satu Hermes, dan Hermes itu adalah milik aplikasinya: Hermes hanya pernah diinstal melalui aplikasi, dan perintah `hermes` yang dijalankan agen default adalah milik aplikasi. Memilih Hermes sebagai agen default menginstal hal yang sama seperti entri _Install > AI_: paketnya, dan runtime Hermes di bawah `~/.hermes` yang disiapkan oleh penginstal Hermes sendiri, yang membutuhkan beberapa menit pada kali pertama. Runtime itulah satu-satunya Hermes yang digunakan perintah `hermes` terminal, agen default, dan aplikasi, dan ia memperbarui dirinya sendiri dengan `hermes update`, bukan menunggu rilis Omarchy. Menginstalnya juga memberikan tema Omarchy kepada Hermes sebagai skin bernama `omarchy`, yang diikuti setiap permukaan Hermes saat kamu mengganti tema; pilih yang lain di bawah pengaturan Appearance Hermes atau dengan `/skin` jika kamu lebih suka tidak, dan Omarchy membiarkan pilihan itu. Menghapus aplikasi di bawah _Remove > AI_ menutup Hermes terlebih dahulu, termasuk gateway, membawa runtime itu pergi, dan mempertahankan obrolan, memori, serta skill yang ditulis Hermes untuk dirinya sendiri kecuali kamu menyuruhnya sebaliknya: ia bertanya, dengan default tidak, apakah data itu dan pengaturan koneksimu juga harus dihapus.

Pengalaman desktop OpenClaw adalah Control UI-nya, yang terbuka sebagai aplikasi web yang didukung oleh gateway lokalnya sendiri. OpenClaw berada di `~/.openclaw` dan memperbarui dirinya sendiri: gunakan tombol "Update Gateway" di Control UI atau jalankan `openclaw update`, dan gateway dimulai ulang pada versi baru. Omarchy hanya memilih rilis tempat instalasi baru dimulai. OpenClaw juga dapat menjadi agen default-mu: memilihnya di bawah _Agent > Harness_ menyiapkan salinan yang sama di `~/.openclaw`, dan agen membuka UI terminal OpenClaw yang terhubung ke gateway-nya. Menghapus OpenClaw di bawah _Remove > AI_ membawa layanan gateway dan aplikasinya pergi, lalu bertanya apakah `~/.openclaw` juga harus dihapus, karena folder itu menyimpan obrolan dan kredensialmu di samping OpenClaw itu sendiri dan runtime plugin yang diunduhnya; default-nya mempertahankannya, dan menginstal OpenClaw lagi mengambilnya kembali.

Herdr Desktop adalah aplikasi desktop [Herdr](https://herdr.dev): ruang, tab, dan panel terminal serta agen coding yang terus berjalan di core-nya saat kamu menutup jendela. Ia berasal dari penginstal Herdr sendiri, bukan dari sebuah paket, jadi ia berada di `~/.local/share/herdr-app`, membawa core-nya di `~/.local/bin/herdr-core` jika kamu belum memilikinya, dan memperbarui keduanya sendiri. Ia berada di samping perintah `herdr` yang disertakan Omarchy pada `Super + Ctrl + Return`, bukan menggantikannya, dan mendapatkan kunci langsung perintah itu: `Alt + Return` dan `Alt + Shift + Return` membagi panel ke bawah atau ke kanan, `Alt + Escape` menutupnya, `Ctrl + Alt + Arrow` berpindah antar panel, `Alt + 1..9` dan `Alt + Left/Right` memilih tab, dan `Alt + Up/Down` berpindah antar ruang. `Ctrl + 1..9` memilih ruang dan `Alt + Shift + Up/Down` melangkah melalui agen. Kunci awalan `Ctrl + Space` tetap khusus terminal, karena aplikasi tidak dapat menahan tombol Ctrl biasa untuk sebuah urutan. Omarchy menulis ini ke `~/.config/herdr-app/keys.json`, dan `omarchy-refresh-herdr-app` mengembalikannya. Menginstalnya memilih tema Omarchy dari Herdr, yang mengikuti tema Omarchy-mu sejak saat itu. Herdr menyimpan satu tema untuk mode terang dan satu untuk mode gelap, jadi setelah berpindah antara tema Omarchy gelap dan terang, pilih Omarchy di pemilih tema Herdr sekali lagi untuk mode lainnya.

T3 Code berjalan dari rilis AppImage resminya di `~/.local/share/t3code`, bukan dari sebuah paket, jadi ia memperbarui dirinya sendiri. Menginstalnya menanyakan apakah akan memulai pada saluran Stable atau Nightly; ganti nanti di pengaturan T3 Code. Thread dan pengaturanmu berada di `~/.t3`, dan menghapus T3 Code di bawah _Remove > AI_ membawanya pergi.

### Model lokal

Jalankan model terbuka di mesinmu sendiri untuk agen coding-mu. Prompt dan kodemu tetap di mesin; tidak ada yang dikirim ke model meninggalkan mesin itu. Mulailah dengan:

```bash
omarchy models use best text
```

Itu menyiapkan model teks terbaik untuk mesin ini, jenis yang digunakan agenmu. Model gambar, video, dan musik memiliki yang terbaik sendiri: `omarchy models use best image`, `video` atau `music`. Jalankan `omarchy models use best` untuk melihat pilihan setiap jenis untuk mesin ini.

Atau buka panel model lokal dari ikon kilauannya di bar atas, di sebelah ikon agen, atau dengan Super + Ctrl + Shift + X, dan pilih +. Ikon itu muncul ketika sebuah model cocok dengan mesin ini. Podman, yang menjalankan model, disertakan dengan Omarchy, begitu pula toolkit kontainer NVIDIA di mesin NVIDIA, yang memberi mereka GPU; jika salah satunya hilang, penyiapan pertama menginstalnya. Omarchy kemudian memilih model yang direkomendasikan untuk mesin ini, mengunduhnya, dan memulainya. Perkirakan unduhan puluhan GB dan sebagian besar memori mesin digunakan saat model berjalan: Flash Next menggunakan sekitar 100 GiB dengan konteks penuh 256K-nya. Jika model lain menahan memori yang dibutuhkannya, model itu disiapkan dalam keadaan berhenti, siap dimulai setelah kamu menghentikan salah satunya. Model berhenti saat logout; hentikan sendiri saat kamu membutuhkan memori untuk hal lain.

`omarchy models list` menampilkan pilihan-pilihannya dan menjelaskan mengapa beberapa tidak cocok. Untuk menyiapkan yang lain, jalankan `omarchy models use <recipe>`. Saat ini, `qwen3.8-flash-next-gufo` dan `qwen3.8-27b-gufo` tersedia untuk mesin Strix Halo 128 GB; yang 27B menggunakan sekitar 40 GiB, jadi ia menyisakan ruang untuk pekerjaan lain. Di laptop 64 GB dengan Arc B390 dari Intel, `qwen3.6-35b-a3b-llamacpp` berjalan dalam sekitar 30 GiB. Resep dan rekomendasi baru tiba dengan `omarchy update`, melalui paket.

Setiap model yang kamu siapkan mendapatkan barisnya sendiri di panel model lokal: putar untuk memulainya, jeda untuk menghentikannya dan membebaskan memorinya, dan tombol terminal untuk membuka agenmu di model itu. Di bagian atas, sebuah bar menunjukkan bagaimana memori mesin dibagi antara Omarchy itu sendiri (sistem dan aplikasimu), setiap model yang berjalan, dan yang bebas. Arahkan ke model yang berhenti dan bar menunjukkan apakah ia cocok, atau berapa kekurangan yang dimilikinya. Beberapa dapat berjalan sekaligus ketika mereka cocok di memori bersama-sama; jika satu tidak cocok, Omarchy memberi tahu model berjalan mana yang harus dihentikan. Seret baris berdasarkan logonya untuk menyusun ulang, dan tekan Delete pada baris yang dipilih untuk menghapus model dan unduhannya.

Setiap model yang kamu siapkan juga mendapatkan entrinya sendiri di peluncur aplikasi, di bawah nama model dan dengan logo pembuatnya, dengan cara yang sama seperti masuk ke Claude, Codex, atau Grok menambahkan satu entri. Entri itu membuka agenmu pada model tersebut, dan memulai model terlebih dahulu jika belum berjalan: terminal menunjukkan proses pemuatannya dan menyerahkan kepada agen setelah model aktif. Menghapus model menghapus entrinya.

Tidak setiap model untuk coding. Model gambar, video, dan musik dibuka di Fantasi sebagai gantinya, aplikasi Omarchy untuk membuat gambar, video, dan musik dengan model yang berjalan di mesin ini, dari entri peluncurnya dan dari barisnya di panel model lokal.

Model tetap berjalan persis seperti saat disiapkan, jadi pembaruan Omarchy tidak pernah memulai ulang model di bawah agenmu. Saat Omarchy memiliki runtime yang lebih baru atau bobot yang lebih baru untuk model yang telah kamu siapkan, barisnya menampilkan tombol pembaruan: tekan tombol itu dan model disiapkan lagi di latar belakang, mengunduh hanya yang berubah, dan dimulai ulang pada versi baru. Model yang berhenti tetap berhenti. `omarchy models update` melakukan hal yang sama untuk setiap model dari terminal.

Dari baris perintah, `omarchy models start <recipe>` dan `omarchy models stop <recipe>` melakukan hal yang sama, `omarchy models status` menampilkan setiap model, dan `omarchy agent --local` membuka agen default-mu pada model terakhir yang kamu mulai. pi, OpenCode, dan Qwen Code dapat menggunakan satu model; dengan default lain apa pun, ia dibuka di pi, atau di OpenCode jika kamu tidak memiliki pi. pi juga mencantumkan setiap model yang telah kamu siapkan, dan model di mesin yang telah kamu pasangkan, di pemilih modelnya sendiri, jadi `pi` biasa juga dapat menjangkaunya. Klien yang kompatibel dengan OpenAI juga dapat terhubung: `status` menampilkan alamat setiap model (yang pertama adalah `http://127.0.0.1:11435/v1`), nama resep adalah modelnya, dan kuncinya ada di `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` menghapus model dan unduhan yang tidak digunakan model lain.

Runtime pihak ketiga diberi label dengan penerbitnya. Omarchy menjalankan setiap model tanpa akses jaringan.

### LLM lokal

Omarchy merekomendasikan dua cara menjalankan model LLM lokal: LM Studio dan Ollama. LM Studio menyediakan antarmuka GUI untuk menemukan model open-weight, menginstalnya, dan menjalankannya. Itu cara yang bagus untuk memulai dengan mudah. Ollama menawarkan CLI untuk melakukan hal serupa. Tetapi jika kamu baru dalam model lokal, saya akan mulai dengan LM Studio. Kamu dapat menginstal keduanya di bawah _Install > AI_ di Omarchy Menu.

### Skill Omarchy

Skill agen membantu AI menggunakan alat tertentu dengan cara tertentu, dan Omarchy menyertakan tujuh di antaranya. Skill omarchy mencakup penyesuaian sistem, seperti mengutak-atik konfigurasi Hyprland atau menyesuaikan bar. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app, dan omarchy-make-game mencakup pembuatan sesuatu yang baru, omarchy-contribute mencakup pelaporan bug atau pengiriman perbaikan ke upstream, dan omarchy-diagnose-crash mengerjakan core dump dari sebuah crash. Semuanya ditautkan secara simbolis ke direktori skill untuk Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` dan setiap `~/.hermes/profiles/*/skills`), dan lokasi generik `~/.agents/skills`, jadi sebagian besar harness mengambilnya secara otomatis. Folder skill milikmu sendiri dengan nama yang sama didahulukan.

Tetapi kamu harus memperlakukan skill ini sebagai eksperimental. Model yang berbeda akan menggunakannya dengan efek yang berbeda. Sebaiknya jalankan dalam mode rencana terlebih dahulu, agar kamu memiliki gambaran tentang apa yang ingin diubah agen. Lalu bersiaplah untuk mengembalikan perubahan atau bahkan menjalankan `omarchy reinstall configs`, jika agen membuat semuanya berantakan.
