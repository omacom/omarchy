### Memasang dan memperbarui agen

Kecuali Hermes dan OpenClaw, agen-agen ini menggunakan instalasi lazy dari mise: peluncuran pertama memasang CLI, dan peluncuran berikutnya menggunakannya kembali. mise juga memeriksa agen yang terpasang untuk rilis baru paling banyak sekali setiap empat jam, tepat sebelum ia mulai atau di latar belakang pada prompt shell. Jika pembaruan itu gagal atau kamu offline, versi yang terpasang yang berjalan. `omarchy update` memperbarui agen yang terpasang bersama seluruh Omarchy, dan `mup` hanya memperbarui tool yang dikelola mise.

Pembaru bawaan agen itu sendiri, seperti `claude update`, `codex update`, atau tombol pembaruan di sebuah aplikasi, tidak memperbarui instalasi yang dikelola mise. `codex update` gagal, dan `claude update` bisa melaporkan berhasil sambil memasang salinan terpisah yang tidak dilacak mise. Jika kamu lebih suka menggunakan installer dan pembaru bawaan agen, tambahkan ia ke `disable_tools`; lihat [Tool CLI yang sudah terpasang](18-development-tools.md#preinstalled-cli-tools).

Untuk memasang semua tool lazy yang dikonfigurasi sebelum kamu membutuhkannya, jalankan `mise install --include-lazy`. Ini mencakup tool CLI default Omarchy lainnya serta agen-agen tersebut. Lihat [Tool CLI yang sudah terpasang](18-development-tools.md#preinstalled-cli-tools) untuk memasang satu tool atau menggunakan instalasimu sendiri.

`grok` dipasang melalui paket `grok` first-party dari mise, dengan cara yang sama seperti `claude` dan `codex`. Jalankan `grok`, atau pilih di bawah _Agent > Harness_. Lewati installer `curl | bash` di x.ai. Jalur itu menaruh salinan kedua di `~/.grok/bin`, mendahulukannya di `PATH`, dan menimpa wrapper Omarchy.

`dsh` membuka UI browsernya di `127.0.0.1:3080`, dengan direktori peluncuran sebagai workspace default-nya. UI browsernya tidak menerima prompt awal, jadi `omarchy agent prompt` membukanya dengan prompt di clipboard untuk ditempel. Omarchy memulainya dengan preset izin no-approval dari DeepSeek. DeepSeek Harness mengunggah log sesi ke DeepSeek saat kamu menggunakan API model resminya; matikan itu di bawah _Settings > General > Upload Session Log_ di UI browsernya. Feedback yang kamu kirim kepadanya juga diunggah bersama sesi, kecuali kamu memulainya dengan `DSH_TELEMETRY_MODE=DISABLED`.

### Agen default

Pilih agen default-mu dengan `omarchy default agent <name>` atau di bawah _Agent > Harness_ di Omarchy Menu (`Super + Space`). Jika agennya belum terpasang, memilihnya akan memasangnya terlebih dahulu, dan ia juga mendapatkan peluncurnya sendiri di peluncur aplikasi, di sebelah Agent. Omarchy baru akan mengajakmu membuat pilihan ini dengan notifikasi satu kali.

Memilih Claude juga berupaya menyiapkan ekstensi browsernya untuk Chromium, Chrome, Brave, Brave Origin, dan Edge. Penyiapan ekstensi berlaku untuk semua pengguna dan mungkin meminta kata sandi sistemmu; membatalkan atau instalasi ekstensi yang gagal tetap memilih dan meluncurkan Claude. Mulai ulang browsermu, aktifkan ekstensi jika diminta, dan masuk ke Claude untuk menyelesaikan penyambungannya. Jalankan `/chrome` di Claude untuk memeriksa koneksi. Firefox dan Zen tidak mendukung ekstensi ini. Jika Claude sudah menjadi default-mu sebelum penyiapan ini ditambahkan, pilih lagi untuk memasang ekstensi.

Setelah kamu memilih, `Super + Shift + Ctrl + A` meluncurkan agen default di jendela terminal khusus (atau memunculkan pemilih jika kamu belum memilih). Kamu juga bisa meluncurkannya langsung ke sebuah tugas dengan `omarchy agent prompt "Review this project"`. Freebuff dan DeepSeek Harness tidak menerima prompt awal, jadi mereka membuka dengan prompt di clipboard untuk ditempel sebagai gantinya. Agen yang diluncurkan dengan cara ini berjalan tanpa pengawasan dalam mode don't-stop-to-ask masing-masing, jadi bersiaplah karena mereka benar-benar akan melakukan sesuatu! MiniMax Code tidak memiliki mode seperti itu untuk sesi interaktifnya, jadi ia meminta izin seperti biasa. Dan karena agen menolak mengingat kepercayaan untuk direktori home-mu, peluncuran dari `$HOME` sebagai gantinya dimulai di `~/Work`.

Ada juga pintasan terminal: `a` menjalankan agen default secara inline di terminal saat ini, sementara `c`, `cx`, dan `cy` memulai OpenCode, Claude Code, dan Codex secara langsung (lagi-lagi dalam mode auto-approving mereka). Perubahan tema juga tersinkron ke agen: Claude Code, Pi, OpenCode, dan Hermes (setelah Omarchy memasangnya) semuanya mengikuti saat kamu mengganti tema Omarchy.

### Instruksi agenmu

Aturan pribadi untuk setiap agen dimasukkan ke `~/.agents/AGENTS.md`, di sebelah skill bersama di `~/.agents/skills`. Buka di bawah _Agent > Instructions_, yang juga menautkannya ke setiap harness yang menyimpan file globalnya sendiri: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` milik Copilot, dan seterusnya. Crush dan Amp membaca tautan `~/.config/AGENTS.md`, sementara omp, Kimi, dan DeepSeek Harness membaca `~/.agents/AGENTS.md` secara langsung. Memilih agen default juga menautkannya. File instruksi yang sudah kamu miliki menjadi file bersama jika belum ada; jika tidak, ia disimpan di sebelah tautan sebagai `.bak`. Jalankan `omarchy agent instructions` untuk menautkan ulang setelah memasang agen lain.

### Panel agen

Bar atas memiliki ikon agen. Sebelum kamu menyiapkan agen, panelnya memandumu untuk masuk ke Claude, Codex, atau Grok, dan yang pertama menjadi agen default-mu. Setelah itu, panel menaruh setiap langganan di satu halaman: setiap agen dan akun beserta paketnya, meter untuk masing-masing batas sesi 5 jam dan batas mingguannya beserta waktu hingga ia direset (arahkan kursor untuk persentase persisnya), atau sisa saldo prabayar, di bawah sebuah baris yang berganti-ganti menampilkan apa yang telah kamu gunakan di semuanya, seperti token minggu ini dan model yang paling sering kamu gunakan. Di bawah _Make something cool_ ia menawarkan prompt pemula untuk tema, plugin, aplikasi, atau game baru yang menyerahkan tugasnya ke agen default-mu. Aplikasi dibangun dengan cara yang sama seperti Hype, Monologue, dan Omacut milik Omarchy sendiri, dalam C++ dan Qt Quick, mengikuti skill agen omarchy-make-app, dan compiler serta komponen Qt yang mereka butuhkan sudah terpasang. Game adalah satu halaman three.js di `~/Games/vibes`, mengikuti skill agen omarchy-make-game, dan semuanya terbuka dari satu peluncur Game Vibes dalam tema saat ini; mereka memuat three.js dari web, jadi mereka membutuhkan koneksi untuk memulai. Claude Code, Codex, Grok, Kimi, Cursor dan jatah Grok Bot-nya, GitHub Copilot, Muse, Antigravity, dan Devin tercakup sejak awal beserta batasnya, Kimchi beserta paket, kredit prabayar, dan anggaran pengeluarannya, dan Hermes, Mistral Vibe, dan Qwen Code menampilkan sesi dan token mereka setelah kamu menggunakannya. Paket dan kunci provider yang kamu gunakan melalui pi, omp, atau opencode juga muncul: OpenCode Zen dan Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan, dan Synthetic beserta batasnya; OpenRouter dan DeepSeek beserta saldo prabayarnya; Fireworks beserta pengeluarannya selama 30 hari terakhir. Token dari model yang kamu jalankan di hardware-mu sendiri juga dihitung ke total; model itu sendiri memiliki panelnya sendiri, yang dijelaskan di bawah [Model lokal](#local-models). Setiap agen dihitung sekali, di bawah siapa pun yang menagihnya, berapa pun banyak harness yang kamu gunakan untuk menjalankannya.

Klik kiri ikon bar atau tekan `Super + Ctrl + X` untuk panel, klik kanan untuk meluncurkan agen default-mu, dan klik tengah untuk menyegarkan. Catatan penggunaan di baliknya dibuat ulang setiap 15 menit oleh `omarchy agent usage update`, dan panel bahkan bisa menggabungkan penggunaan dari mesinmu yang lain melalui folder yang disinkronkan. Lihat README di bawah `$OMARCHY_PATH/shell/plugins/agents/` untuk pengaturan lengkapnya.

### Beberapa langganan

Jika kamu membayar lebih dari satu paket Claude, Codex, atau Grok — misalnya Max pribadi dan satu untuk pekerjaan — Omarchy bisa menjaga semuanya tetap masuk dan berpindah di antaranya. Tambahkan langganan dengan + di panel agen, yang memandumu melakukannya di sana, atau dengan `omarchy agent account add claude Work` (atau `codex`, atau `grok`). Ia memasang CLI jika hilang. Akun pertama untuk sebuah provider masuk melalui browser normalmu, tepat di tempat CLI selalu mencarinya. Setiap akun setelah itu masuk melalui jendela pribadi, jadi akun yang sudah masuk di browsermu tidak terambil secara tidak sengaja; masuk di sana sebagai akun yang kamu tambahkan, dan tutup dulu jendela pribadi yang sudah kamu buka. Jangan pernah keluar dari CLI untuk melakukan ini: keluar mencabut login yang tersimpan, dan akun itu harus ditambahkan lagi.

Untuk menyalin login langgananmu ke mesin Omarchy lain melalui SSH, jalankan `omarchy agent account copy user@laptop`. Pengirim menyediakan receiver sementara saat tujuan belum memasangnya, jadi mesin Omarchy yang lebih lama bisa menerima akun tanpa pembaruan. Receiver yang terpasang diutamakan. Ini menyalin semua langganan Claude, Codex, dan Grok; tambahkan nama provider untuk memilihnya, seperti pada `omarchy agent account copy laptop claude`. Nama akun dan ID perintah cocok dengan sumber, termasuk akun yang sudah ada di tujuan. Akun tujuan yang tidak terkait menerima sufiks numerik jika namanya bertabrakan, dan pengaturan, skill, plugin, serta riwayat percakapan tetap lokal di setiap mesin.

Kredensial tujuan yang ada tetap dipertahankan. Akun sumber yang sudah masuk di sana namanya disinkronkan tanpa mengganti kredensialnya; akun lain ditambahkan di sampingnya. Untuk mengganti kredensial tersimpan untuk akun yang cocok, gunakan `omarchy agent account copy --replace laptop claude` setelah keluar dari sesi akun itu di tujuan. Tujuan baru juga mendapatkan akun aktif dan preferensi peralihan sumber; tujuan yang sudah mapan mempertahankan miliknya sendiri.

Kredensial berjalan melalui SSH dan disimpan dalam file pribadi di tujuan, jadi salinlah hanya ke mesin yang kamu percaya. Ini adalah penyalinan satu kali, bukan sinkronisasi berkelanjutan. Token refresh Codex bisa dirotasi oleh mesin lain, membuat login yang disalin memerlukan pembaruan; login terpisah tetap menjadi pilihan paling andal untuk penggunaan simultan di beberapa mesin. Lihat [Panduan autentikasi akun Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Satu akun per provider aktif, dan setiap sesi baru dimulai sebagai akun itu: `cx`, `cy`, `claude`, `codex`, atau `grok` biasa, apa pun yang diluncurkan melalui `omarchy agent`, dan skrip atau editor yang menemukan CLI di `PATH`. Beralih dengan `omarchy agent account use work` (dan kembali dengan `omarchy agent account use main`), atau di panel dengan menekan nomor akun lalu `Enter` (atau mengklik tombol Use-nya). Sesi Claude yang berjalan juga beralih, dari pesan berikutnya: setiap sesi Claude berjalan di `~/.claude`, yang selalu menyimpan login akun aktif. Sesi Claude yang dimulai di folder akunnya sendiri oleh Omarchy lama menyimpan login itu hingga ia keluar, jadi peralihan menyebutkan sesi-sesi tersebut dan selesai dengan sendirinya setelah mereka hilang. Sesi Codex dan Grok yang berjalan tetap pada akun yang mereka gunakan saat mulai. Riwayat percakapan, pengaturan, skill, dan plugin dibagikan antar akun, jadi `claude --continue` di folder yang sama melanjutkan dari tempat terakhirmu pada akun baru.

Dengan lebih dari satu akun, panel menampilkan batas masing-masing akun berdampingan, dengan akun aktif ditandai. Secara default Omarchy memberitahumu saat akun aktif melewati 95% dari sebuah batas, dan mengklik notifikasi beralih ke akun dengan ruang paling besar. Arahkan kursor ke baris akun di panel dan klik Autoswitch yang muncul di sebelah Use (atau tekan `m`), atau jalankan `omarchy agent account mode auto`, agar ia beralih sendiri sebagai gantinya; saat aktif, Autoswitch menggantikan tempat Use, dan mengkliknya lagi kembali ke pemberitahuan. Tambahkan angka untuk mengubah ambangnya, seperti pada `omarchy agent account mode auto 90`. Jika setiap akun melewati ambang, kamu akan diberitahu sekali, beserta akun mana yang paling dulu bebas. Saat akun aktif berada dalam 15 poin dari ambangnya (80% pada default), batasnya diperiksa setiap tiga menit, bukan setiap 15 menit.

`omarchy agent account list` menampilkan setiap akun dan batas terbarunya, `omarchy agent account remove work` melupakan satu akun, dan `omarchy agent account rename primary Hey` mengganti nama satu akun (atau klik nama akun di panel). Perintah-perintah ini bekerja pada akun agen default-mu; untuk menjangkau provider lain, sebutkan namanya terlebih dahulu, seperti pada `omarchy agent account use codex side`. Login yang sudah kamu miliki di `~/.claude` atau `~/.codex` adalah akun _Main_. Akun Codex tetap di tempatnya; akun Claude menunggu di foldernya sendiri saat akun lain aktif. Akun yang dibiarkan tidak digunakan lebih dari sekitar delapan jam bisa menampilkan _Sign-in required_; klik untuk memasukkan akun itu lagi langsung di panel, atau beralihlah ke akun itu dan mulai sesi, yang menyegarkan login dengan sendirinya. Server MCP yang kamu tambahkan dengan `claude mcp add` menjangkau setiap akun Claude, karena semuanya berjalan di `~/.claude`; untuk Codex dan Grok, server yang kamu miliki saat akun ditambahkan ikut ke akun itu, tetapi server setelahnya hanya mencapai akun tempat kamu menambahkannya. Claude Desktop menyimpan loginnya sendiri, dan tool Codex atau Grok yang dikonfigurasi dengan path absolut ke binary CLI tidak mengikuti peralihan. `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, atau `GROK_HOME` eksplisit diutamakan atas akun yang dipilih.

### Diagnosis crash

Omarchy mengawasi systemd-coredump untuk crash proses. Setelah kamu memilih agen default, program milikmu yang melakukan dump core akan memunculkan notifikasi "Process crashed" — klik, dan crash diserahkan ke agen default-mu bersama skill omarchy-diagnose-crash dari Omarchy, yang memandu agen untuk menetapkan fakta dari core dump dan memutuskan apakah crash layak dilaporkan ke upstream. Kamu juga bisa menjalankannya secara manual terhadap PID apa pun dari `coredumpctl list` dengan `omarchy agent crash <pid>`.

Pengawasan ini aktif secara default. Matikan di bawah _Trigger > Toggle > Crash Capture Off_ (atau dengan `omarchy toggle crash-capture`) dan notifikasi berhenti; `omarchy agent crash <pid>` tetap bekerja secara manual.

Crash juga bisa dibisukan satu program pada satu waktu, yang ditawarkan diagnosis kepadamu di bagian akhir. `omarchy crash mute hyprland` menghentikan notifikasi hanya untuk program itu, `omarchy crash mute hyprland off` mengembalikannya, dan `omarchy crash mute` sendiri mencantumkan apa yang telah kamu bisukan. Ia menerima path binary sama senangnya seperti namanya, jadi `omarchy crash mute /usr/bin/hyprland` melakukan hal yang sama. Kutip nama yang mengandung spasi, seperti pada `omarchy crash mute 'Some App'`. Segala sesuatu yang lain tetap memberi notifikasi, dan program yang dibisukan tetap crash — ini menyembunyikan pengingat, bukan memperbaiki apa pun.

### Aplikasi desktop

Menu _Install > AI_ juga membawa beberapa aplikasi AI grafis: Amp Desktop, Antigravity Desktop, aplikasi desktop ChatGPT, aplikasi desktop Claude (beta Linux dari Anthropic, dengan tab Chat, Cowork, dan Claude Code), Grok Bot untuk mengobrol dengan model xAI, Herdr Desktop, Hermes Desktop, OpenClaw, aplikasi desktop Perplexity, dan T3 Code. Grok Bot adalah aplikasi chat desktop. Agen coding adalah perintah `grok`.

Hermes Desktop adalah yang perlu diketahui, karena sebuah mesin memiliki satu Hermes, dan itu milik aplikasi: Hermes hanya pernah dipasang melalui aplikasi, dan perintah `hermes` yang dijalankan agen default adalah milik aplikasi. Memilih Hermes sebagai agen default memasang hal yang sama dengan yang dilakukan entri _Install > AI_: paketnya, dan runtime Hermes di bawah `~/.hermes` yang disiapkan oleh installer Hermes sendiri, yang membutuhkan beberapa menit pada kali pertama. Runtime itu adalah satu Hermes yang digunakan perintah terminal `hermes`, agen default, dan aplikasi, dan ia memperbarui dirinya sendiri dengan `hermes update` daripada menunggu rilis Omarchy. Memasangnya juga memberikan Hermes tema Omarchy sebagai skin bernama `omarchy`, yang diikuti setiap permukaan Hermes saat kamu mengganti tema; pilih yang lain di bawah pengaturan Appearance Hermes atau dengan `/skin` jika kamu lebih suka ia tidak mengikutinya, dan Omarchy membiarkan pilihan itu. Menghapus aplikasi di bawah _Remove > AI_ menutup Hermes terlebih dahulu, gateway termasuk, membawa runtime itu pergi, dan mempertahankan chat, memori, dan skill yang ditulis Hermes untuk dirinya sendiri kecuali kamu menyuruhnya lain: ia bertanya, dengan default tidak, apakah data itu dan pengaturan koneksimu juga harus pergi.

Pengalaman desktop OpenClaw adalah Control UI-nya, yang terbuka sebagai aplikasi web yang didukung gateway lokalnya sendiri. OpenClaw tinggal di `~/.openclaw` dan memperbarui dirinya sendiri: gunakan tombol "Update Gateway" di Control UI atau jalankan `openclaw update`, dan gateway mulai ulang pada versi baru. Omarchy hanya memilih rilis yang menjadi titik awal instalasi baru. OpenClaw juga bisa menjadi agen default-mu: memilihnya di bawah _Agent > Harness_ menyiapkan salinan yang sama di `~/.openclaw`, dan agen membuka UI terminal OpenClaw yang terhubung ke gateway-nya. Menghapus OpenClaw di bawah _Remove > AI_ membawa layanan gateway dan aplikasinya pergi lalu bertanya apakah `~/.openclaw` juga harus pergi, karena di sana tersimpan chat dan kredensialmu bersama OpenClaw itu sendiri dan runtime plugin yang diunduhnya; default mempertahankannya, dan memasang OpenClaw lagi akan mengambilnya kembali.

Herdr Desktop adalah aplikasi desktop [Herdr](https://herdr.dev): spaces, tab, dan pane terminal dan agen coding yang tetap berjalan di core-nya saat kamu menutup jendela. Ia berasal dari installer Herdr sendiri, bukan dari paket, jadi ia tinggal di `~/.local/share/herdr-app`, membawa core-nya di `~/.local/bin/herdr-core` saat kamu belum memilikinya, dan memperbarui keduanya sendiri. Ia berada di sebelah perintah `herdr` yang dikirim Omarchy pada `Super + Ctrl + Return` daripada menggantikannya, dan mendapatkan tombol langsung perintah itu: `Alt + Return` dan `Alt + Shift + Return` membagi pane ke bawah atau ke kanan, `Alt + Escape` menutupnya, `Ctrl + Alt + Arrow` berpindah antar pane, `Alt + 1..9` dan `Alt + Left/Right` memilih tab, dan `Alt + Up/Down` berpindah antar spaces. `Ctrl + 1..9` memilih space dan `Alt + Shift + Up/Down` melangkah melalui agen. Tombol awalan `Ctrl + Space` tetap hanya untuk terminal, karena aplikasi tidak bisa menahan tombol Ctrl biasa untuk sebuah urutan. Omarchy menulis ini ke `~/.config/herdr-app/keys.json`, dan `omarchy-refresh-herdr-app` mengembalikannya. Memasangnya memilih tema Omarchy dari Herdr, yang mengikuti tema Omarchy-mu sejak saat itu. Herdr menyimpan satu tema untuk mode terang dan satu untuk mode gelap, jadi setelah beralih antara tema Omarchy gelap dan terang, pilih Omarchy di pemilih tema Herdr sekali lagi untuk mode yang lain.

T3 Code berjalan dari rilis AppImage resminya di `~/.local/share/t3code` daripada dari paket, jadi ia memperbarui dirinya sendiri. Memasangnya bertanya apakah memulai pada channel Stable atau Nightly; beralih nanti di pengaturan T3 Code. Thread dan pengaturanmu tinggal di `~/.t3`, dan menghapus T3 Code di bawah _Remove > AI_ membawanya pergi.

### Model lokal

Jalankan model terbuka di mesinmu sendiri untuk agen coding-mu. Prompt dan kodemu tetap di mesin; tidak ada yang dikirim ke model yang meninggalkannya. Mulai dengan:

```bash
omarchy models use best text
```

Itu menyiapkan model teks terbaik untuk mesin ini, jenis yang digunakan agenmu. Model gambar, video, dan musik memiliki yang terbaik sendiri: `omarchy models use best image`, `video`, atau `music`. Jalankan `omarchy models use best` untuk melihat pilihan masing-masing jenis untuk mesin ini.

Atau buka panel model lokal dari ikon sparkles-nya di bar atas, di sebelah ikon agen, atau dengan Super + Ctrl + Alt + X, dan pilih +. Ikon muncul saat sebuah model cocok dengan mesin ini. Podman, yang menjalankan model, disertakan dengan Omarchy, begitu juga container toolkit NVIDIA pada mesin NVIDIA, yang memberi mereka GPU; jika salah satunya hilang, penyiapan pertama memasangnya. Omarchy lalu memilih model yang direkomendasikan untuk mesin ini, mengunduhnya, dan memulainya. Harapkan unduhan puluhan GB dan sebagian besar memori mesin digunakan saat model berjalan: Flash Next menggunakan sekitar 100 GiB dengan konteks penuh 256K-nya. Jika model lain menahan memori yang dibutuhkan, ia disiapkan dalam keadaan berhenti, siap dimulai setelah kamu menghentikan salah satunya. Model berhenti saat logout; hentikan sendiri saat kamu membutuhkan memori untuk hal lain.

`omarchy models list` menampilkan opsi dan menjelaskan mengapa beberapa tidak cocok. Untuk menyiapkan model lain, jalankan `omarchy models use <recipe>`. Saat ini, `qwen3.8-flash-next-gufo` dan `qwen3.8-27b-gufo` tersedia untuk mesin Strix Halo 128 GB; 27B menggunakan sekitar 40 GiB, jadi ia menyisakan ruang untuk pekerjaan lain. Pada laptop 64 GB dengan Arc B390 dari Intel, `qwen3.6-35b-a3b-llamacpp` berjalan dalam sekitar 30 GiB. Recipe dan rekomendasi baru tiba dengan `omarchy update`, melalui paket.

Setiap model yang kamu siapkan mendapatkan barisnya sendiri di panel model lokal: play untuk memulainya, pause untuk menghentikannya dan membebaskan memorinya, dan tombol terminal untuk membuka agenmu padanya. Di bagian atas, sebuah bar menunjukkan bagaimana memori mesin dibagi antara Omarchy itu sendiri (sistem dan aplikasimu), setiap model yang berjalan, dan yang bebas. Arahkan kursor ke model yang berhenti dan bar menunjukkan apakah ia cocok, atau berapa kekurangan-nya. Beberapa bisa berjalan sekaligus saat mereka cocok dalam memori bersama; jika satu tidak cocok, Omarchy memberitahu model yang berjalan mana yang harus dihentikan. Seret baris berdasarkan logonya untuk mengurutkan ulang, dan tekan Delete pada baris yang dipilih untuk menghapus model dan unduhannya.

Setiap model yang kamu siapkan juga mendapatkan entrinya sendiri di peluncur aplikasi, di bawah nama model dan dengan logo pembuatnya, dengan cara yang sama seperti masuk ke Claude, Codex, atau Grok menambahkan satu entri. Ia membuka agenmu pada model itu, dan memulai model terlebih dahulu jika belum berjalan: terminal menunjukkan ia memuat dan menyerahkan ke agen setelah siap. Menghapus model menghapus entrinya.

Tidak setiap model untuk coding. Model gambar, video, dan musik sebagai gantinya terbuka di Fantasi, aplikasi Omarchy untuk membuat gambar, video, dan musik dengan model yang berjalan di mesin ini, dari entri peluncurnya dan dari barisnya di panel model lokal.

Sebuah model tetap berjalan persis seperti saat disiapkan, jadi pembaruan Omarchy tidak pernah memulai ulang model di bawah agenmu. Saat Omarchy memiliki runtime yang lebih baru atau bobot yang lebih baru untuk model yang telah kamu siapkan, barisnya menampilkan tombol pembaruan: tekan dan model disiapkan lagi di latar belakang, mengunduh hanya yang berubah, dan mulai ulang pada versi baru. Model yang berhenti tetap berhenti. `omarchy models update` melakukan hal yang sama untuk setiap model dari terminal.

Dari baris perintah, `omarchy models start <recipe>` dan `omarchy models stop <recipe>` melakukan hal yang sama, `omarchy models status` menampilkan setiap model, dan `omarchy agent --local` membuka agen default-mu pada model terakhir yang kamu mulai. pi, OpenCode, dan Qwen Code bisa menggunakan satu; dengan default lain apa pun ia terbuka di pi, atau di OpenCode jika kamu tidak memiliki pi. pi juga mencantumkan setiap model yang telah kamu siapkan, dan model pada mesin yang telah kamu pasangkan, di pemilih modelnya sendiri, jadi `pi` biasa juga bisa menjangkaunya. Klien kompatibel OpenAI apa pun juga bisa terhubung: `status` menampilkan alamat setiap model (yang pertama adalah `http://127.0.0.1:11435/v1`), nama recipe adalah modelnya, dan kuncinya ada di `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` menghapus model dan unduhan yang tidak digunakan model lain.

Runtime pihak ketiga dilabeli dengan penerbitnya. Omarchy menjalankan setiap model tanpa akses jaringan.

### LLM lokal

Omarchy merekomendasikan dua cara menjalankan model LLM lokal: LM Studio dan Ollama. LM Studio menyediakan antarmuka GUI untuk menemukan model open-weight, memasangnya, dan menjalankannya. Ini cara yang bagus untuk memulai dengan mudah. Ollama menawarkan CLI untuk melakukan hal serupa. Tetapi jika kamu baru dalam model lokal, saya akan mulai dengan LM Studio. Kamu bisa memasang salah satu di bawah _Install > AI_ di Omarchy Menu.

### Skill Omarchy

Skill agen membantu AI menggunakan tool tertentu dengan cara tertentu, dan Omarchy menyertakan tujuh di antaranya. Skill omarchy mencakup penyesuaian sistem, seperti mengutak-atik config Hyprland-mu atau menyesuaikan bar. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app, dan omarchy-make-game mencakup pembuatan sesuatu yang baru, omarchy-contribute mencakup pelaporan bug atau pengiriman perbaikan ke upstream, dan omarchy-diagnose-crash menelusuri core dump dari sebuah crash. Mereka di-symlink ke direktori skill untuk Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` dan setiap `~/.hermes/profiles/*/skills`), dan lokasi generik `~/.agents/skills`, jadi sebagian besar harness mengambilnya secara otomatis. Folder skill milikmu sendiri dengan nama yang sama diutamakan.

Tetapi kamu harus memperlakukan skill ini sebagai eksperimental. Model yang berbeda akan menggunakannya dengan efek yang berbeda. Sebaiknya jalankan dalam mode plan terlebih dahulu, agar kamu memiliki gambaran tentang apa yang ingin diubah agen. Lalu bersiaplah untuk mengembalikan perubahan atau bahkan menjalankan `omarchy reinstall configs`, jika agen membuat segalanya berantakan.
