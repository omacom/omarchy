### Menginstal dan memperbarui agen

Kecuali Hermes dan OpenClaw, agen-agen ini menggunakan instalasi lazy dari mise: peluncuran pertama menginstal CLI-nya, dan peluncuran berikutnya menggunakannya kembali. mise juga memeriksa apakah ada rilis baru untuk agen yang terinstal paling banyak sekali setiap empat jam, tepat sebelum ia dimulai atau di latar belakang pada prompt shell. Jika pembaruan itu gagal atau Anda sedang offline, versi yang terinstal yang akan berjalan. `omarchy update` memperbarui agen yang terinstal bersama seluruh Omarchy lainnya, dan `mup` hanya memperbarui alat yang dikelola mise.

Updater milik agen itu sendiri, seperti `claude update`, `codex update`, atau tombol pembaruan di sebuah aplikasi, tidak memperbarui instalasi yang dikelola mise. `codex update` akan gagal, dan `claude update` bisa melaporkan berhasil sementara ia menginstal salinan terpisah yang tidak dilacak mise. Jika Anda lebih suka menggunakan installer dan updater bawaan agen, tambahkan ia ke `disable_tools`; lihat [Alat CLI yang sudah terinstal](18-development-tools.md#preinstalled-cli-tools).

Untuk menginstal semua alat lazy yang dikonfigurasi sebelum Anda membutuhkannya, jalankan `mise install --include-lazy`. Ini mencakup alat CLI default Omarchy lainnya serta agen-agen tersebut. Lihat [Alat CLI yang sudah terinstal](18-development-tools.md#preinstalled-cli-tools) untuk menginstal satu alat atau menggunakan instalasi Anda sendiri.

`grok` diinstal melalui paket `grok` pihak pertama dari mise, dengan cara yang sama seperti `claude` dan `codex`. Jalankan `grok`, atau pilih ia di bawah _Agent > Harness_. Lewati installer `curl | bash` di x.ai. Jalur itu menaruh salinan kedua di `~/.grok/bin`, mendahulukannya di `PATH`, dan menimpa wrapper Omarchy.

`dsh` membuka UI browsernya di `127.0.0.1:3080`, dengan direktori peluncuran sebagai workspace default-nya. UI browsernya tidak menerima prompt awal, jadi `omarchy agent prompt` membukanya dengan prompt di clipboard Anda untuk ditempel. Omarchy menjalankannya dengan preset izin tanpa persetujuan dari DeepSeek. DeepSeek Harness mengunggah log sesi ke DeepSeek saat Anda menggunakan API model resminya; matikan itu di bawah _Settings > General > Upload Session Log_ di UI browsernya. Masukan yang Anda kirimkan kepadanya juga diunggah bersama sesi, kecuali Anda menjalankannya dengan `DSH_TELEMETRY_MODE=DISABLED`.

### Agen default

Pilih agen default Anda dengan `omarchy default agent <name>` atau di bawah _Agent > Harness_ di Omarchy Menu (`Super + Space`). Jika agennya belum terinstal, memilihnya akan menginstalnya terlebih dahulu, dan ia juga mendapatkan launcher-nya sendiri di app launcher, di samping Agent. Omarchy yang baru akan mengundang Anda untuk membuat pilihan ini dengan notifikasi satu kali.

Memilih Claude juga mencoba menyiapkan ekstensi browsernya untuk Chromium, Chrome, Brave, Brave Origin, dan Edge. Penyiapan ekstensi berlaku untuk semua pengguna dan mungkin meminta kata sandi sistem Anda; membatalkan atau instalasi ekstensi yang gagal tetap memilih dan meluncurkan Claude. Mulai ulang browser Anda, aktifkan ekstensi jika diminta, dan masuk ke Claude untuk menyelesaikan penyambungannya. Jalankan `/chrome` di Claude untuk memeriksa koneksinya. Firefox dan Zen tidak mendukung ekstensi ini. Jika Claude sudah menjadi default Anda sebelum penyiapan ini ditambahkan, pilih lagi untuk menginstal ekstensinya.

Setelah Anda memilih, `Super + Shift + Ctrl + A` meluncurkan agen default di jendela terminal khusus (atau memunculkan pemilih jika Anda belum memilih). Anda juga bisa meluncurkannya langsung ke sebuah tugas dengan `omarchy agent prompt "Review this project"`. Freebuff dan DeepSeek Harness tidak menerima prompt awal, jadi keduanya dibuka dengan prompt di clipboard Anda untuk ditempel sebagai gantinya. Agen yang diluncurkan dengan cara ini berjalan tanpa pengawasan dalam mode jangan-berhenti-untuk-bertanya masing-masing, jadi bersiaplah karena mereka benar-benar akan melakukan sesuatu! MiniMax Code tidak memiliki mode seperti itu untuk sesi interaktifnya, jadi ia meminta izin seperti biasa. Dan karena agen menolak mengingat kepercayaan untuk direktori home Anda, peluncuran dari `$HOME` dimulai di `~/Work` sebagai gantinya.

Ada juga pintasan terminal: `a` menjalankan agen default secara inline di terminal saat ini, sementara `c`, `cx`, dan `cy` menjalankan OpenCode, Claude Code, dan Codex secara langsung (sekali lagi dalam mode persetujuan otomatis mereka). Perubahan tema juga tersinkron ke agen: Claude Code, Pi, OpenCode, dan Hermes (setelah Omarchy menginstalnya) semuanya mengikuti saat Anda mengganti tema Omarchy.

### Instruksi agen Anda

Aturan pribadi untuk setiap agen berada di `~/.agents/AGENTS.md`, di samping skill bersama di `~/.agents/skills`. Buka ia di bawah _Agent > Instructions_, yang juga menautkannya ke setiap harness yang menyimpan berkas globalnya sendiri: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` milik Copilot, dan seterusnya. Crush dan Amp membaca tautan `~/.config/AGENTS.md`, sementara omp, Kimi, dan DeepSeek Harness membaca `~/.agents/AGENTS.md` secara langsung. Memilih agen default juga menautkannya. Berkas instruksi yang sudah Anda miliki menjadi berkas bersama jika belum ada; jika tidak, ia disimpan di samping tautan sebagai `.bak`. Jalankan `omarchy agent instructions` untuk menautkan ulang setelah menginstal agen lain.

### Panel agen

Bar atas memiliki ikon agen. Sebelum Anda menyiapkan agen, panelnya memandu Anda untuk masuk ke Claude, Codex, atau Grok, dan yang pertama menjadi agen default Anda. Setelah itu, panel menaruh setiap langganan dalam satu halaman: setiap agen dan akun beserta paketnya, meteran untuk masing-masing batas sesi 5 jam dan batas mingguannya beserta waktu hingga ia direset (arahkan kursor untuk melihat persentase pastinya), atau sisa saldo prabayar, di bawah sebuah baris yang bergantian menampilkan apa yang telah Anda gunakan di semuanya, seperti token minggu ini dan model yang paling sering Anda gunakan. Di bawah _Make something cool_ ia menawarkan prompt awal untuk tema, plugin, aplikasi, atau game baru yang menyerahkan tugasnya ke agen default Anda. Aplikasi dibuat dengan cara yang sama seperti Hype, Monologue, dan Omacut milik Omarchy sendiri, dalam C++ dan Qt Quick, mengikuti skill agen omarchy-make-app, dan compiler serta potongan Qt yang mereka butuhkan sudah terinstal. Game adalah satu halaman three.js di `~/Games/vibes`, mengikuti skill agen omarchy-make-game, dan semuanya dibuka dari satu launcher Game Vibes dalam tema saat ini; mereka memuat three.js dari web, jadi mereka membutuhkan koneksi untuk memulai. Claude Code, Codex, Grok, Kimi, Cursor beserta jatah Grok Bot-nya, GitHub Copilot, Muse, Antigravity, dan Devin tercakup sejak awal beserta batasnya, Kimchi beserta paketnya, kredit prabayar, dan anggaran pengeluarannya, dan Hermes, Mistral Vibe, dan Qwen Code menampilkan sesi dan token mereka setelah Anda menggunakannya. Paket dan kunci penyedia yang Anda gunakan melalui pi, omp, atau opencode juga muncul: OpenCode Zen dan Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan, dan Synthetic beserta batasnya; OpenRouter dan DeepSeek beserta saldo prabayarnya; Fireworks beserta pengeluarannya selama 30 hari terakhir. Token dari model yang Anda jalankan di perangkat keras Anda sendiri juga ikut dihitung dalam total; model-model itu sendiri memiliki panelnya sendiri, yang dijelaskan di bawah [Model lokal](#local-models). Setiap agen dihitung sekali, di bawah siapa pun yang menagihnya, berapa pun banyak harness yang Anda gunakan untuk menjalankannya.

Klik kiri ikon bar atau tekan `Super + Ctrl + X` untuk panel, klik kanan untuk meluncurkan agen default Anda, dan klik tengah untuk menyegarkan. Catatan penggunaan di baliknya dibuat ulang setiap 15 menit oleh `omarchy agent usage update`, dan panel bahkan bisa menggabungkan penggunaan dari mesin Anda yang lain melalui folder yang tersinkron. Lihat README di bawah `$OMARCHY_PATH/shell/plugins/agents/` untuk pengaturan lengkapnya.

### Beberapa langganan

Jika Anda membayar lebih dari satu paket Claude, Codex, atau Grok — misalnya satu Max pribadi dan satu untuk pekerjaan — Omarchy bisa menjaga semuanya tetap masuk dan berpindah di antaranya. Tambahkan langganan dengan + di panel agen, yang memandu Anda langsung di sana, atau dengan `omarchy agent account add claude Work` (atau `codex`, atau `grok`). Ia menginstal CLI jika belum ada. Akun pertama untuk sebuah penyedia masuk melalui browser normal Anda, tepat di tempat CLI selalu mencarinya. Setiap akun setelah itu masuk melalui jendela pribadi, jadi akun yang sudah masuk di browser Anda tidak terambil secara tidak sengaja; masuklah di sana sebagai akun yang sedang Anda tambahkan, dan tutup dulu jendela pribadi apa pun yang sudah Anda buka. Jangan pernah keluar dari CLI untuk melakukan ini: keluar akan mencabut sesi masuk yang tersimpan, dan akun itu harus ditambahkan lagi.

Untuk menyalin login langganan Anda ke mesin Omarchy lain melalui SSH, jalankan `omarchy agent account copy user@laptop`. Pengirim menyediakan penerima sementara ketika tujuan tidak memiliki yang terinstal, jadi mesin Omarchy yang lebih lama bisa menerima akun tanpa pembaruan. Penerima yang terinstal diutamakan. Ini menyalin semua langganan Claude, Codex, dan Grok; tambahkan nama penyedia untuk memilihnya, seperti dalam `omarchy agent account copy laptop claude`. Nama akun dan ID perintah cocok dengan sumber, termasuk akun yang sudah ada di tujuan. Akun tujuan yang tidak terkait menerima akhiran angka jika namanya bertabrakan, dan pengaturan, skill, plugin, dan riwayat percakapan tetap lokal di setiap mesin.

Kredensial tujuan yang sudah ada tetap dipertahankan. Akun sumber yang sudah masuk di sana namanya disinkronkan tanpa mengganti kredensialnya; akun lain ditambahkan di sampingnya. Untuk mengganti kredensial tersimpan untuk akun yang cocok, gunakan `omarchy agent account copy --replace laptop claude` setelah menutup sesi akun tersebut di tujuan. Tujuan yang masih baru juga mendapatkan akun aktif dan preferensi perpindahan dari sumber; tujuan yang sudah mapan mempertahankan miliknya sendiri.

Kredensial berjalan melalui SSH dan disimpan dalam berkas pribadi di tujuan, jadi salinlah hanya ke mesin yang Anda percayai. Ini adalah penyalinan satu kali, bukan sinkronisasi berkelanjutan. Token refresh Codex bisa dirotasi oleh mesin lain, membuat login yang disalin perlu diperbarui; masuk secara terpisah tetap menjadi pilihan paling andal untuk penggunaan serentak di beberapa mesin. Lihat [panduan autentikasi akun Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Satu akun per penyedia yang aktif, dan setiap sesi baru dimulai sebagai akun itu: `cx`, `cy`, `claude`, `codex`, atau `grok` biasa, apa pun yang diluncurkan melalui `omarchy agent`, dan script atau editor yang menemukan CLI di `PATH`. Berpindahlah dengan `omarchy agent account use work` (dan kembali dengan `omarchy agent account use main`), atau di panel dengan menekan nomor sebuah akun lalu `Enter` (atau mengklik tombol Use-nya). Sesi Claude yang sedang berjalan juga berpindah, mulai dari pesan berikutnya: setiap sesi Claude berjalan di `~/.claude`, yang selalu menyimpan sesi masuk akun aktif. Sesi Claude yang dimulai di folder akunnya sendiri oleh Omarchy yang lebih lama menyimpan sesi masuk tersebut hingga ia berhenti, jadi perpindahan menyebutkan sesi-sesi itu dan selesai dengan sendirinya setelah mereka hilang. Sesi Codex dan Grok yang sedang berjalan tetap pada akun tempat mereka dimulai. Riwayat percakapan, pengaturan, skill, dan plugin dipakai bersama di semua akun, jadi `claude --continue` di folder yang sama melanjutkan dari tempat Anda berhenti pada akun baru.

Dengan lebih dari satu akun, panel menampilkan batas setiap akun berdampingan, dengan akun aktif ditandai. Omarchy memberi tahu Anda ketika akun aktif melewati 95% dari sebuah batas, dan mengklik notifikasi beralih ke akun dengan ruang tersisa paling banyak. Ia tidak pernah beralih dengan sendirinya. Ubah ambang batasnya dengan `omarchy agent account threshold 90`. Jika setiap akun melewati ambang batas, Anda akan mendengarnya sekali, beserta akun mana yang lebih dulu bebas. Sementara akun aktif berada dalam 15 poin dari ambang batasnya (80% pada default), batasnya diperiksa setiap tiga menit, bukan setiap 15 menit.

`omarchy agent account list` menampilkan setiap akun dan batas terbarunya, `omarchy agent account remove work` melupakan satu akun, dan `omarchy agent account rename primary Hey` mengganti nama satu akun (atau klik nama akun di panel). Perintah-perintah ini bekerja pada akun agen default Anda; untuk menjangkau penyedia lain, sebutkan namanya terlebih dahulu, seperti dalam `omarchy agent account use codex side`. Login yang sudah Anda miliki di `~/.claude` atau `~/.codex` adalah akun _Main_. Akun Codex tetap di tempatnya; akun Claude menunggu di foldernya sendiri sementara akun lain aktif. Akun yang tidak digunakan lebih dari sekitar delapan jam bisa menampilkan _Sign-in required_; klik ia untuk memasukkan akun tersebut lagi langsung di panel, atau beralihlah kepadanya dan mulai sebuah sesi, yang menyegarkan sesi masuknya dengan sendirinya. Server MCP yang Anda tambahkan dengan `claude mcp add` menjangkau setiap akun Claude, karena semuanya berjalan di `~/.claude`; untuk Codex dan Grok, server yang Anda miliki ketika sebuah akun ditambahkan ikut bersamanya, tetapi server setelah itu hanya menjangkau akun tempat Anda menambahkannya. Claude Desktop menyimpan sesi masuknya sendiri, dan alat Codex atau Grok yang dikonfigurasi dengan jalur absolut ke biner CLI tidak mengikuti perpindahan. `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, atau `GROK_HOME` yang eksplisit diutamakan atas akun yang dipilih.

### Diagnosis crash

Omarchy mengawasi systemd-coredump untuk crash proses. Setelah Anda memilih agen default, setiap program Anda yang melakukan dump core memunculkan notifikasi "Process crashed" — klik ia, dan crash tersebut diserahkan ke agen default Anda bersama skill omarchy-diagnose-crash dari Omarchy, yang memandu agen untuk menetapkan fakta dari core dump dan memutuskan apakah crash tersebut layak dilaporkan ke upstream. Anda juga bisa menjalankannya secara manual terhadap PID apa pun dari `coredumpctl list` dengan `omarchy agent crash <pid>`.

Pengawasan ini aktif secara default. Matikan di bawah _Trigger > Toggle > Crash Capture Off_ (atau dengan `omarchy toggle crash-capture`) dan notifikasinya berhenti; `omarchy agent crash <pid>` masih berfungsi secara manual.

Crash juga bisa dibisukan satu program pada satu waktu, yang merupakan hal yang ditawarkan diagnosis kepada Anda di akhir. `omarchy crash mute hyprland` menghentikan notifikasi hanya untuk program itu, `omarchy crash mute hyprland off` membawanya kembali, dan `omarchy crash mute` sendiri menampilkan apa yang telah Anda bisukan. Ia menerima jalur biner sama senangnya seperti namanya, jadi `omarchy crash mute /usr/bin/hyprland` melakukan hal yang sama. Kutip nama yang mengandung spasi, seperti dalam `omarchy crash mute 'Some App'`. Semua yang lain masih memberi notifikasi, dan program yang dibisukan masih crash — ini menyembunyikan pengingat, bukan memperbaiki apa pun.

### Aplikasi desktop

Menu _Install > AI_ juga membawa beberapa aplikasi AI grafis: Amp Desktop, Antigravity Desktop, aplikasi desktop ChatGPT, aplikasi desktop Claude (beta Linux dari Anthropic, dengan tab Chat, Cowork, dan Claude Code), Grok Bot untuk mengobrol dengan model xAI, Herdr Desktop, Hermes Desktop, OpenClaw, aplikasi desktop Perplexity, dan T3 Code. Grok Bot adalah aplikasi obrolan desktop. Agen coding-nya adalah perintah `grok`.

Hermes Desktop adalah yang perlu diketahui, karena sebuah mesin memiliki satu Hermes, dan ia milik aplikasinya: Hermes hanya pernah diinstal melalui aplikasi, dan perintah `hermes` yang dijalankan agen default adalah milik aplikasi. Memilih Hermes sebagai agen default menginstal hal yang sama seperti yang dilakukan entri _Install > AI_: paketnya, dan runtime Hermes di bawah `~/.hermes` yang disiapkan oleh installer Hermes sendiri, yang memakan beberapa menit pada kali pertama. Runtime itu adalah satu-satunya Hermes yang digunakan perintah terminal `hermes`, agen default, dan aplikasi, dan ia memperbarui dirinya sendiri dengan `hermes update` daripada menunggu rilis Omarchy. Menginstalnya juga memberikan tema Omarchy kepada Hermes sebagai skin bernama `omarchy`, yang diikuti setiap permukaan Hermes saat Anda mengganti tema; pilih yang lain di bawah pengaturan Appearance Hermes atau dengan `/skin` jika Anda lebih suka tidak, dan Omarchy membiarkan pilihan itu. Menghapus aplikasi di bawah _Remove > AI_ menutup Hermes terlebih dahulu, termasuk gateway, membawa runtime tersebut bersamanya, dan menyimpan obrolan, ingatan, dan skill yang ditulis Hermes untuk dirinya sendiri kecuali Anda menyuruhnya sebaliknya: ia bertanya, dengan default tidak, apakah data itu dan pengaturan koneksi Anda juga harus dihapus.

Pengalaman desktop OpenClaw adalah Control UI-nya, yang dibuka sebagai aplikasi web yang didukung oleh gateway lokalnya sendiri. OpenClaw berada di `~/.openclaw` dan memperbarui dirinya sendiri: gunakan tombol "Update Gateway" di Control UI atau jalankan `openclaw update`, dan gateway dimulai ulang pada versi baru. Omarchy hanya memilih rilis tempat instalasi baru dimulai. OpenClaw juga bisa menjadi agen default Anda: memilihnya di bawah _Agent > Harness_ menyiapkan salinan yang sama tersebut di `~/.openclaw`, dan agen membuka UI terminal OpenClaw yang terhubung ke gateway-nya. Menghapus OpenClaw di bawah _Remove > AI_ membawa layanan gateway dan aplikasinya bersamanya lalu bertanya apakah `~/.openclaw` juga harus dihapus, karena di sana tersimpan obrolan dan kredensial Anda di samping OpenClaw itu sendiri dan runtime plugin yang diunduhnya; default-nya menyimpannya, dan menginstal OpenClaw lagi akan mengambilnya kembali.

Herdr Desktop adalah aplikasi desktop [Herdr](https://herdr.dev): ruang, tab, dan panel terminal serta agen coding yang tetap berjalan di core-nya ketika Anda menutup jendela. Ia berasal dari installer Herdr sendiri daripada sebuah paket, jadi ia berada di `~/.local/share/herdr-app`, membawa core-nya di `~/.local/bin/herdr-core` ketika Anda belum memilikinya, dan memperbarui keduanya sendiri. Ia berada di samping perintah `herdr` yang disertakan Omarchy pada `Super + Ctrl + Return` daripada menggantikannya, dan mendapatkan tombol langsung perintah tersebut: `Alt + Return` dan `Alt + Shift + Return` membagi panel ke bawah atau ke kanan, `Alt + Escape` menutupnya, `Ctrl + Alt + Arrow` berpindah antar panel, `Alt + 1..9` dan `Alt + Left/Right` memilih tab, dan `Alt + Up/Down` berpindah antar ruang. `Ctrl + 1..9` memilih ruang dan `Alt + Shift + Up/Down` melangkah melalui agen. Tombol awalan `Ctrl + Space` tetap hanya untuk terminal, karena aplikasi tidak bisa menahan tombol Ctrl biasa untuk sebuah urutan. Omarchy menulis ini ke `~/.config/herdr-app/keys.json`, dan `omarchy-refresh-herdr-app` mengembalikannya. Menginstalnya memilih tema Omarchy dari Herdr, yang mengikuti tema Omarchy Anda sejak saat itu. Herdr menyimpan satu tema untuk mode terang dan satu untuk mode gelap, jadi setelah berpindah antara tema Omarchy gelap dan terang, pilih Omarchy di pemilih tema Herdr sekali lagi untuk mode lainnya.

T3 Code berjalan dari rilis AppImage resminya di `~/.local/share/t3code` daripada dari sebuah paket, jadi ia memperbarui dirinya sendiri. Menginstalnya bertanya apakah akan memulai di saluran Stable atau Nightly; beralihlah nanti di pengaturan T3 Code. Utas dan pengaturan Anda berada di `~/.t3`, dan menghapus T3 Code di bawah _Remove > AI_ membawanya bersamanya.

### Model lokal

Jalankan model terbuka di mesin Anda sendiri untuk agen coding Anda. Prompt dan kode Anda tetap di mesin; tidak ada yang dikirim ke model yang meninggalkannya. Mulailah dengan:

```bash
omarchy models use best text
```

Itu menyiapkan model teks terbaik untuk mesin ini, jenis yang digunakan agen Anda. Model gambar, video, dan musik memiliki yang terbaiknya sendiri: `omarchy models use best image`, `video`, atau `music`. Jalankan `omarchy models use best` untuk melihat pilihan setiap jenis untuk mesin ini.

Atau buka panel model lokal dari ikon kilauannya di bar atas, di samping ikon agen, atau dengan Super + Ctrl + Alt + X, dan pilih +. Ikon muncul ketika sebuah model cocok dengan mesin ini. Podman, yang menjalankan model, disertakan dengan Omarchy, begitu juga toolkit container NVIDIA pada mesin NVIDIA, yang memberi mereka GPU; jika salah satunya hilang, penyiapan pertama menginstalnya. Omarchy kemudian memilih model yang direkomendasikan untuk mesin ini, mengunduhnya, dan memulainya. Bersiaplah untuk unduhan puluhan GB dan sebagian besar memori mesin digunakan sementara model berjalan: Flash Next menggunakan sekitar 100 GiB dengan konteks penuh 256K-nya. Jika model lain menahan memori yang dibutuhkannya, ia disiapkan dalam keadaan berhenti, siap dimulai setelah Anda menghentikan satu model. Model berhenti saat logout; hentikan sendiri ketika Anda membutuhkan memori untuk hal lain.

`omarchy models list` menampilkan pilihan dan menjelaskan mengapa beberapa tidak cocok. Untuk menyiapkan yang lain, jalankan `omarchy models use <recipe>`. Saat ini, `qwen3.8-flash-next-gufo` dan `qwen3.8-27b-gufo` tersedia untuk mesin Strix Halo 128 GB; 27B memakan sekitar 40 GiB, jadi ia menyisakan ruang untuk pekerjaan lain. Pada laptop 64 GB dengan Intel Arc B390, `qwen3.6-35b-a3b-llamacpp` berjalan dalam sekitar 30 GiB. Resep dan rekomendasi baru tiba dengan `omarchy update`, melalui paket.

Setiap model yang Anda siapkan mendapatkan barisnya sendiri di panel model lokal: putar untuk memulainya, jeda untuk menghentikannya dan membebaskan memorinya, dan tombol terminal untuk membuka agen Anda padanya. Di bagian atas, sebuah bar menunjukkan bagaimana memori mesin dibagi antara Omarchy itu sendiri (sistem dan aplikasi Anda), setiap model yang berjalan, dan yang masih bebas. Arahkan ke model yang berhenti dan bar menunjukkan apakah ia cocok, atau berapa kekurangannya. Beberapa bisa berjalan sekaligus ketika mereka cocok bersama dalam memori; jika satu tidak cocok, Omarchy menyebutkan model berjalan mana yang harus dihentikan. Seret baris berdasarkan logonya untuk mengurutkannya kembali, dan tekan Delete pada baris yang dipilih untuk menghapus model dan unduhannya.

Setiap model coding yang Anda siapkan juga mendapatkan entrinya sendiri di app launcher, di bawah nama model dan dengan logo pembuatnya, dengan cara yang sama seperti masuk ke Claude, Codex, atau Grok menambahkan satu. Ia membuka agen Anda pada model tersebut, dan memulai model terlebih dahulu jika belum berjalan: terminal menunjukkannya sedang dimuat dan menyerahkan ke agen setelah ia siap. Menghapus model menghapus entrinya.

Tidak setiap model untuk coding. Model gambar, video, dan musik dibuka di Fantasi sebagai gantinya, aplikasi Omarchy untuk membuat gambar, video, dan musik dengan model yang berjalan di mesin ini, dipilih di sana atau dari barisnya di panel model lokal.

Sebuah model terus berjalan persis seperti saat ia disiapkan, jadi pembaruan Omarchy tidak pernah memulai ulang satu model di bawah agen Anda. Ketika Omarchy memiliki runtime yang lebih baru atau bobot yang lebih baru untuk model yang telah Anda siapkan, barisnya menampilkan tombol pembaruan: tekan ia dan model disiapkan lagi di latar belakang, hanya mengunduh yang berubah, dan dimulai ulang pada versi baru. Model yang berhenti tetap berhenti. `omarchy models update` melakukan hal yang sama untuk setiap model dari terminal.

Dari baris perintah, `omarchy models start <recipe>` dan `omarchy models stop <recipe>` melakukan hal yang sama, `omarchy models status` menampilkan setiap model, dan `omarchy agent --local` membuka model terakhir yang Anda mulai di pi, apa pun agen default Anda. OpenCode dan Qwen Code juga bisa menggunakan model lokal: `omarchy models harness opencode` atau `omarchy models harness qwen` membukanya di sana sebagai gantinya, dan `omarchy models harness pi` kembali. pi juga menampilkan setiap model yang telah Anda siapkan, dan yang ada di mesin yang telah Anda pasangkan, di pemilih modelnya sendiri, jadi `pi` biasa juga menjangkaunya. Klien apa pun yang kompatibel dengan OpenAI juga bisa terhubung: `status` menampilkan alamat setiap model (yang pertama adalah `http://127.0.0.1:11435/v1`), nama resep adalah modelnya, dan kuncinya ada di `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` menghapus model dan unduhan yang tidak digunakan model lain.

Runtime pihak ketiga dilabeli dengan penerbitnya. Omarchy menjalankan setiap model tanpa akses jaringan.

### LLM lokal

Omarchy merekomendasikan dua cara menjalankan model LLM lokal: LM Studio dan Ollama. LM Studio menyediakan antarmuka GUI untuk menemukan model open-weight, menginstalnya, dan menjalankannya. Ini cara yang bagus untuk memulai dengan mudah. Ollama menawarkan CLI untuk melakukan hal serupa. Tetapi jika Anda baru mengenal model lokal, saya akan mulai dengan LM Studio. Anda bisa menginstal salah satunya di bawah _Install > AI_ di Omarchy Menu.

### Skill Omarchy

Skill agen membantu AI menggunakan alat tertentu dengan cara tertentu, dan Omarchy menyertakan tujuh di antaranya. Skill omarchy mencakup penyesuaian sistem, seperti mengutak-atik konfigurasi Hyprland Anda atau menyesuaikan bar. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app, dan omarchy-make-game mencakup pembuatan sesuatu yang baru, omarchy-contribute mencakup pelaporan bug atau pengiriman perbaikan ke upstream, dan omarchy-diagnose-crash membahas core dump dari sebuah crash. Mereka ditautkan secara simbolis ke direktori skill untuk Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` dan setiap `~/.hermes/profiles/*/skills`), dan lokasi generik `~/.agents/skills`, jadi sebagian besar harness mengambilnya secara otomatis. Folder skill milik Anda sendiri dengan nama yang sama diutamakan.

Tetapi Anda harus memperlakukan skill ini sebagai eksperimental. Model yang berbeda akan menggunakannya dengan efek yang berbeda. Sebaiknya jalankan dalam mode plan terlebih dahulu, agar Anda memiliki gambaran tentang apa yang ingin diubah agen. Lalu bersiaplah untuk mengembalikan perubahan atau bahkan menjalankan `omarchy reinstall configs`, jika agen membuat semuanya berantakan.
