### Memasang dan memperbarui agen

Kecuali Hermes dan OpenClaw, agen-agen ini menggunakan pemasangan lazy dari mise: peluncuran pertama memasang CLI, dan peluncuran berikutnya menggunakannya kembali. mise juga memeriksa rilis baru untuk agen yang terpasang paling banyak sekali setiap empat jam, tepat sebelum agen dimulai atau di latar belakang pada prompt shell. Jika pembaruan itu gagal atau kamu offline, versi yang terpasang yang berjalan. `omarchy update` memperbarui agen yang terpasang bersama seluruh Omarchy, dan `mup` hanya memperbarui tool yang dikelola mise.

Pembaru bawaan agen itu sendiri, seperti `claude update`, `codex update`, atau tombol pembaruan di sebuah aplikasi, tidak memperbarui pemasangan yang dikelola mise. `codex update` gagal, dan `claude update` dapat melaporkan berhasil sambil memasang salinan terpisah yang tidak dilacak mise. Jika kamu lebih suka menggunakan pemasang dan pembaru native agen, tambahkan ke `disable_tools`; lihat [Tool CLI bawaan](18-development-tools.md#preinstalled-cli-tools).

Untuk memasang semua lazy tool yang dikonfigurasi sebelum kamu membutuhkannya, jalankan `mise install --include-lazy`. Ini termasuk tool CLI default Omarchy lainnya selain para agen. Lihat [Tool CLI bawaan](18-development-tools.md#preinstalled-cli-tools) untuk memasang satu tool atau menggunakan pemasanganmu sendiri.

`grok` dipasang melalui paket `grok` first-party dari mise, dengan cara yang sama seperti `claude` dan `codex`. Jalankan `grok`, atau beri bintang di panel agen. Lewati pemasang `curl | bash` di x.ai. Jalur itu menaruh salinan kedua di `~/.grok/bin`, menempatkannya di awal `PATH`, dan menimpa wrapper Omarchy.

`dsh` membuka UI browsernya di `127.0.0.1:3080`, dengan direktori peluncuran sebagai workspace defaultnya. UI browsernya tidak menerima prompt awal, jadi `omarchy agent prompt` membukanya dengan prompt di clipboard untuk kamu tempel. Omarchy memulainya dengan preset izin no-approval dari DeepSeek. DeepSeek Harness mengunggah log sesi ke DeepSeek saat kamu menggunakan API model resminya; matikan itu di bawah _Settings > General > Upload Session Log_ di UI browsernya. Feedback yang kamu kirimkan kepadanya juga diunggah bersama sesi, kecuali kamu memulainya dengan `DSH_TELEMETRY_MODE=DISABLED`.

### Agen default

Pilih agen defaultmu dengan bintang di samping agen di panel agen, yang terisi pada agen default, atau dengan `omarchy default agent <name>`, yang juga menerima harness apa pun tanpa baris di sana. Jika agen belum terpasang, memilihnya akan memasangnya terlebih dahulu, dan agen itu juga mendapatkan peluncurnya sendiri di peluncur aplikasi, di samping Agent. Omarchy yang baru dipasang mengundangmu untuk menyiapkan satu melalui notifikasi satu kali, yang membuka panel agen.

Memilih Claude juga berupaya menyiapkan ekstensi browsernya untuk Chromium, Chrome, Brave, Brave Origin, dan Edge. Penyiapan ekstensi berlaku untuk semua pengguna dan mungkin meminta kata sandi sistemmu; membatalkan atau gagal memasang ekstensi tetap memilih dan meluncurkan Claude. Mulai ulang browsermu, aktifkan ekstensi jika diminta, dan masuk ke Claude untuk menyelesaikan penyambungannya. Jalankan `/chrome` di Claude untuk memeriksa koneksi. Firefox dan Zen tidak mendukung ekstensi ini. Jika Claude sudah menjadi defaultmu sebelum penyiapan ini ditambahkan, pilih lagi untuk memasang ekstensi.

Setelah kamu memilih, `Super + Shift + Ctrl + A` meluncurkan agen default di jendela terminal khusus (atau menampilkan pemilih jika kamu belum memilih). Kamu juga dapat meluncurkannya langsung ke sebuah tugas dengan `omarchy agent prompt "Review this project"`. Freebuff dan DeepSeek Harness tidak menerima prompt awal, jadi keduanya dibuka dengan prompt di clipboard untuk kamu tempel sebagai gantinya. Agen yang diluncurkan dengan cara ini berjalan tanpa pengawasan dalam mode don't-stop-to-ask masing-masing, jadi siaplah karena mereka benar-benar akan melakukan sesuatu! MiniMax Code tidak memiliki mode seperti itu untuk sesi interaktifnya, jadi ia meminta izin seperti biasa. Dan karena agen menolak mengingat kepercayaan untuk direktori home-mu, peluncuran dari `$HOME` dimulai di `~/Work` sebagai gantinya.

Ada juga pintasan terminal: `a` menjalankan agen default secara inline di terminal saat ini, sedangkan `c`, `cx`, dan `cy` memulai OpenCode, Claude Code, dan Codex secara langsung (lagi-lagi dalam mode auto-approving masing-masing). Perubahan tema juga tersinkron ke agen: Claude Code, Pi, OpenCode, dan Hermes (setelah Omarchy memasangnya) semuanya mengikuti saat kamu mengganti tema Omarchy.

### Instruksi agenmu

Aturan pribadi untuk setiap agen ditempatkan di `~/.agents/AGENTS.md`, di samping skill bersama di `~/.agents/skills`. Buka dengan ikon dokumen di samping + di panel agen, atau `omarchy agent instructions --edit`, yang juga menautkannya ke setiap harness yang menyimpan file globalnya sendiri: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` milik Copilot, dan seterusnya. Crush dan Amp membaca tautan `~/.config/AGENTS.md`, sedangkan omp, Kimi, dan DeepSeek Harness membaca `~/.agents/AGENTS.md` secara langsung. Memilih agen default juga menautkannya. File instruksi yang sudah kamu miliki menjadi file bersama jika belum ada; jika sudah ada, file itu disimpan di samping tautan sebagai `.bak`. Jalankan `omarchy agent instructions` untuk menautkan ulang setelah memasang agen lain.

### Panel agen

Bar atas memiliki ikon agen. Sebelum kamu menyiapkan agen, panelnya menawarkan tiga cara untuk memulai: masuk ke langganan Claude, Codex, Grok, Gemini, Muse, Cursor, atau Copilot, atau di bawah More sebuah paket coding OpenCode Go, MiniMax, Synthetic, atau Z.ai; bayar sesuai pemakaian dengan Fireworks, OpenCode Zen dan Go, OpenRouter, atau di bawah More DeepSeek atau provider lain mana pun yang dapat dimasuki OpenCode, semuanya berjalan di OpenCode; atau jalankan model terbaik untuk komputermu, jika ada yang cocok. Yang pertama kamu selesaikan menjadi agen defaultmu, dan + di panel menawarkan tiga cara yang sama nantinya. Setelah itu, panel menempatkan setiap langganan dalam satu halaman: setiap agen dan akun dengan paketnya, meter untuk masing-masing batas sesi 5 jam dan batas mingguannya beserta waktu hingga batas itu direset (arahkan kursor untuk persentase pastinya), atau saldo prabayar yang tersisa, di bawah sebuah baris yang bergilir menampilkan apa yang telah kamu gunakan di semuanya, seperti token minggu ini dan model yang paling sering kamu gunakan. Di bawah _Make something cool_ panel menawarkan prompt awal untuk tema, plugin, aplikasi, atau game baru yang menyerahkan tugas itu ke agen defaultmu. Aplikasi dibuat dengan cara yang sama seperti Hype, Monologue, dan Omacut milik Omarchy sendiri, dalam C++ dan Qt Quick, mengikuti skill agen omarchy-make-app, dan compiler serta komponen Qt yang dibutuhkannya sudah terpasang. Game adalah satu halaman three.js di `~/Games/vibes`, mengikuti skill agen omarchy-make-game, dan semuanya dibuka dari satu peluncur Game Vibes dalam tema saat ini; game memuat three.js dari web, jadi memerlukan koneksi untuk memulai. Claude Code, Codex, Grok, Kimi, Cursor dan jatah Grok Bot-nya, GitHub Copilot, Muse, Gemini (melalui Antigravity), dan Devin tercakup langsung dengan batas-batasnya, Kimchi dengan paket, kredit prabayar, dan anggaran pengeluarannya, dan Hermes, Mistral Vibe, dan Qwen Code menampilkan sesi dan token mereka setelah kamu menggunakannya. Paket dan key provider yang kamu gunakan melalui pi, omp, atau opencode juga muncul: OpenCode Zen dan Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan, dan Synthetic dengan batas-batasnya; OpenRouter dan DeepSeek dengan saldo prabayarnya; Fireworks dengan pengeluarannya selama 30 hari terakhir. Token dari model yang kamu jalankan di perangkat kerasmu sendiri juga dihitung dalam total; model itu sendiri memiliki panelnya sendiri, yang dijelaskan di bawah [Model lokal](#local-models). Setiap agen dihitung sekali, di bawah pihak yang menagihnya, berapa pun banyaknya harness yang kamu gunakan untuk menjalankannya.

Klik kiri ikon bar atau tekan `Super + Ctrl + X` untuk panel, klik kanan untuk meluncurkan agen defaultmu, dan klik tengah untuk menyegarkan. Catatan penggunaan di baliknya dibuat ulang setiap 15 menit oleh `omarchy agent usage update`, dan panel bahkan dapat menggabungkan penggunaan dari mesinmu yang lain melalui folder yang tersinkron. Lihat README di bawah `$OMARCHY_PATH/shell/plugins/agents/` untuk pengaturan lengkapnya.

### Beberapa langganan

Jika kamu membayar lebih dari satu paket Claude, Codex, atau Grok — misalnya Max pribadi dan satu untuk pekerjaan — Omarchy dapat menjaga semuanya tetap masuk dan berpindah di antaranya. Tambahkan langganan dengan + di panel agen, yang memandumu langsung di sana, atau dengan `omarchy agent account add claude Work` (atau `codex`, atau `grok`). + dan perintah yang sama masuk ke Gemini (`gemini`) dan OpenCode (`opencode`), dan menyimpan API key Fireworks (`fireworks`) atau OpenRouter (`openrouter`) di OpenCode; perintah itu juga masuk ke Copilot (`copilot`), Cursor (`cursor`), dan Muse (`muse`). Masing-masing dari ketiganya menyimpan satu kali masuk saja. Perintah itu memasang CLI jika belum ada. Akun pertama untuk sebuah provider masuk melalui browser normalmu, tepat di tempat CLI selalu mencarinya. Setiap akun setelahnya masuk melalui jendela pribadi, sehingga akun yang sudah dimasuki browsermu tidak terambil secara tidak sengaja; masuklah di sana sebagai akun yang sedang kamu tambahkan, dan tutup jendela pribadi apa pun yang sudah terbuka terlebih dahulu. Jangan pernah keluar dari CLI untuk melakukan ini: keluar akan mencabut login yang tersimpan, dan akun itu harus ditambahkan lagi.

Untuk menyalin login langgananmu ke mesin Omarchy lain melalui SSH, jalankan `omarchy agent account copy user@laptop`. Pengirim menyediakan receiver sementara ketika tujuan tidak memiliki yang terpasang, sehingga mesin Omarchy yang lebih lama dapat menerima akun tanpa pembaruan. Receiver yang terpasang didahulukan. Ini menyalin semua langganan Claude, Codex, dan Grok; tambahkan nama provider untuk memilihnya, seperti pada `omarchy agent account copy laptop claude`. Nama akun dan ID perintah cocok dengan sumber, termasuk akun yang sudah ada di tujuan. Akun tujuan yang tidak terkait menerima akhiran angka jika namanya bertabrakan, dan pengaturan, skill, plugin, serta riwayat percakapan tetap lokal di setiap mesin.

Kredensial tujuan yang sudah ada tetap dipertahankan. Akun sumber yang sudah masuk di sana namanya disinkronkan tanpa mengganti kredensialnya; akun lain ditambahkan di sampingnya. Untuk mengganti kredensial yang tersimpan untuk akun yang cocok, gunakan `omarchy agent account copy --replace laptop claude` setelah menutup sesi akun tersebut di tujuan. Tujuan yang masih baru juga mendapatkan akun aktif dan preferensi perpindahan dari sumber; tujuan yang sudah mapan mempertahankan miliknya sendiri.

Kredensial berjalan melalui SSH dan disimpan dalam file pribadi di tujuan, jadi salin hanya ke mesin yang kamu percaya. Ini adalah penyalinan satu kali, bukan sinkronisasi yang berkelanjutan. Refresh token Codex dapat dirotasi oleh mesin lain, membuat login yang disalin perlu diperbarui; login terpisah tetap menjadi pilihan paling andal untuk penggunaan bersamaan di beberapa mesin. Lihat [Panduan autentikasi akun Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Satu akun per provider yang aktif, dan setiap sesi baru dimulai sebagai akun itu: `cx`, `cy`, `claude`, `codex`, atau `grok` biasa, apa pun yang diluncurkan melalui `omarchy agent`, serta script atau editor yang menemukan CLI di `PATH`. Berpindahlah dengan `omarchy agent account use work` (dan kembali dengan `omarchy agent account use main`), atau di panel dengan menekan nomor akun lalu `Enter` (atau mengklik bintangnya). Sesi Claude yang sedang berjalan juga berpindah, mulai dari pesan berikutnya: setiap sesi Claude berjalan di `~/.claude`, yang selalu menyimpan login akun aktif. Sesi Claude yang dimulai di folder akunnya sendiri oleh Omarchy yang lebih lama menyimpan login itu sampai sesi ditutup, jadi perpindahan menyebutkan sesi-sesi tersebut dan selesai dengan sendirinya setelah sesi-sesi itu hilang. Sesi Codex dan Grok yang sedang berjalan tetap pada akun tempat mereka dimulai. Riwayat percakapan, pengaturan, skill, dan plugin dibagikan antar akun, sehingga `claude --continue` di folder yang sama melanjutkan dari tempat kamu berhenti pada akun baru.

Dengan lebih dari satu akun, panel menampilkan batas setiap akun berdampingan, dengan bintang terisi pada akun yang sedang digunakan. Omarchy memberi tahumu ketika akun aktif melewati 95% dari sebuah batas, dan mengklik notifikasi berpindah ke akun dengan ruang tersisa terbanyak. Ia tidak pernah berpindah sendiri. Ubah ambang batas dengan `omarchy agent account threshold 90`. Jika setiap akun melewati ambang batas, kamu akan diberi tahu sekali, beserta akun mana yang lebih dulu bebas. Saat akun aktif berada dalam 15 poin dari ambang batasnya (80% pada default), batasnya diperiksa setiap tiga menit, bukan setiap 15 menit.

`omarchy agent account list` menampilkan setiap akun dan batas terbarunya, `omarchy agent account remove work` melupakan satu akun, dan `omarchy agent account rename primary Hey` mengganti nama satu akun (atau klik nama akun di panel). Perintah-perintah ini bekerja pada akun agen defaultmu; untuk menjangkau provider lain, sebutkan namanya terlebih dahulu, seperti pada `omarchy agent account use codex side`. Login yang sudah kamu miliki di `~/.claude` atau `~/.codex` adalah akun _Main_. Login Codex tetap di tempatnya; login Claude menunggu di foldernya sendiri saat akun lain aktif. Akun yang dibiarkan tidak digunakan selama lebih dari sekitar delapan jam dapat menampilkan _Sign-in required_; klik untuk masuk lagi ke akun tersebut langsung di panel, atau berpindah ke akun itu dan mulai sesi, yang menyegarkan login dengan sendirinya. Server MCP yang kamu tambahkan dengan `claude mcp add` menjangkau setiap akun Claude, karena semuanya berjalan di `~/.claude`; untuk Codex dan Grok, server yang kamu miliki ketika akun ditambahkan ikut ke akun itu, tetapi server yang ditambahkan kemudian hanya menjangkau akun tempat kamu menambahkannya. Claude Desktop menyimpan loginnya sendiri, dan tool Codex atau Grok yang dikonfigurasi dengan path absolut ke binary CLI tidak mengikuti perpindahan. `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, atau `GROK_HOME` yang eksplisit didahulukan atas akun yang dipilih.

### Diagnosis crash

Omarchy memantau systemd-coredump untuk crash proses. Setelah kamu memilih agen default, programmu apa pun yang melakukan dump core akan memunculkan notifikasi "Process crashed" — klik notifikasi itu, dan crash diserahkan ke agen defaultmu bersama skill omarchy-diagnose-crash dari Omarchy, yang memandu agen menetapkan fakta dari core dump dan memutuskan apakah crash itu layak dilaporkan ke upstream. Kamu juga dapat menjalankannya secara manual terhadap PID apa pun dari `coredumpctl list` dengan `omarchy agent crash <pid>`.

Pemantauan aktif secara default. Matikan di bawah _Trigger > Toggle > Crash Capture Off_ (atau dengan `omarchy toggle crash-capture`) dan notifikasi berhenti; `omarchy agent crash <pid>` masih bekerja secara manual.

Crash juga dapat dibisukan satu program pada satu waktu, yang merupakan tawaran diagnosis kepadamu pada akhirnya. `omarchy crash mute hyprland` menghentikan notifikasi hanya untuk program itu, `omarchy crash mute hyprland off` mengembalikannya, dan `omarchy crash mute` dengan sendirinya mencantumkan apa yang telah kamu bisukan. Perintah itu menerima path binary sama senangnya seperti namanya, jadi `omarchy crash mute /usr/bin/hyprland` melakukan hal yang sama. Kutip nama yang mengandung spasi, seperti pada `omarchy crash mute 'Some App'`. Semua yang lain masih memberi notifikasi, dan program yang dibisukan masih crash — ini menyembunyikan pengingat, bukan memperbaiki apa pun.

### Aplikasi desktop

Menu _Install > AI_ juga membawa beberapa aplikasi AI grafis: Amp Desktop, Antigravity Desktop, aplikasi desktop ChatGPT, aplikasi desktop Claude (beta Linux dari Anthropic, dengan tab Chat, Cowork, dan Claude Code), Grok Bot untuk mengobrol dengan model xAI, Herdr Desktop, Hermes Desktop, OpenClaw, aplikasi desktop Perplexity, dan T3 Code. Grok Bot adalah aplikasi chat desktop. Agen coding-nya adalah perintah `grok`.

Hermes Desktop adalah yang perlu diketahui, karena sebuah mesin memiliki satu Hermes, dan itu milik aplikasinya: Hermes hanya pernah dipasang melalui aplikasi, dan perintah `hermes` yang dijalankan agen default adalah milik aplikasi. Memilih Hermes sebagai agen default memasang hal yang sama seperti yang dilakukan entri _Install > AI_: paketnya, dan runtime Hermes di bawah `~/.hermes` yang disiapkan oleh pemasang Hermes sendiri, yang memerlukan beberapa menit pada kali pertama. Runtime itu adalah satu-satunya Hermes yang digunakan perintah `hermes` di terminal, agen default, dan aplikasi, dan ia memperbarui dirinya sendiri dengan `hermes update` daripada menunggu rilis Omarchy. Memasangnya juga memberikan tema Omarchy kepada Hermes sebagai skin bernama `omarchy`, yang diikuti setiap permukaan Hermes saat kamu mengganti tema; pilih yang lain di bawah pengaturan Appearance Hermes atau dengan `/skin` jika kamu lebih suka tidak, dan Omarchy membiarkan pilihan itu. Menghapus aplikasi di bawah _Remove > AI_ menutup Hermes terlebih dahulu, termasuk gateway, membawa runtime itu bersamanya, dan menyimpan chat, memori, dan skill yang ditulis Hermes untuk dirinya sendiri kecuali kamu menyuruh sebaliknya: ia bertanya, dengan default tidak, apakah data itu dan pengaturan koneksimu juga harus dihapus.

Pengalaman desktop OpenClaw adalah Control UI-nya, yang dibuka sebagai aplikasi web yang didukung oleh gateway lokalnya sendiri. OpenClaw tinggal di `~/.openclaw` dan memperbarui dirinya sendiri: gunakan tombol "Update Gateway" di Control UI atau jalankan `openclaw update`, dan gateway dimulai ulang pada versi baru. Omarchy hanya memilih rilis tempat pemasangan baru dimulai. OpenClaw juga dapat menjadi agen defaultmu: memilihnya dengan `omarchy default agent openclaw` menyiapkan salinan yang sama di `~/.openclaw`, dan agen membuka UI terminal OpenClaw yang terhubung ke gateway-nya. Menghapus OpenClaw di bawah _Remove > AI_ membawa layanan gateway dan aplikasi bersamanya lalu bertanya apakah `~/.openclaw` juga harus dihapus, karena itu menyimpan chat dan kredensialmu di samping OpenClaw itu sendiri dan runtime plugin yang diunduhnya; defaultnya menyimpannya, dan memasang OpenClaw lagi mengambilnya kembali.

Herdr Desktop adalah aplikasi desktop [Herdr](https://herdr.dev): ruang, tab, dan panel terminal serta agen coding yang terus berjalan di core-nya saat kamu menutup jendela. Ia berasal dari pemasang Herdr sendiri bukan dari paket, jadi ia tinggal di `~/.local/share/herdr-app`, membawa core-nya di `~/.local/bin/herdr-core` saat kamu belum memilikinya, dan memperbarui keduanya sendiri. Ia berada di samping perintah `herdr` yang dikirim Omarchy pada `Super + Ctrl + Return` bukan menggantikannya, dan mendapatkan tombol langsung perintah itu: `Alt + Return` dan `Alt + Shift + Return` membagi panel ke bawah atau ke kanan, `Alt + Escape` menutupnya, `Ctrl + Alt + Arrow` berpindah antar panel, `Alt + 1..9` dan `Alt + Left/Right` memilih tab, dan `Alt + Up/Down` berpindah antar ruang. `Ctrl + 1..9` memilih ruang dan `Alt + Shift + Up/Down` melangkah melalui agen. Tombol prefix `Ctrl + Space` tetap hanya untuk terminal, karena aplikasi tidak dapat menahan tombol Ctrl biasa untuk sebuah urutan. Omarchy menulis ini ke `~/.config/herdr-app/keys.json`, dan `omarchy-refresh-herdr-app` mengembalikannya. Memasangnya memilih tema Omarchy Herdr, yang mengikuti tema Omarchy-mu sejak saat itu. Herdr menyimpan satu tema untuk mode terang dan satu untuk mode gelap, jadi setelah berpindah antara tema Omarchy gelap dan terang, pilih Omarchy di pemilih tema Herdr sekali lagi untuk mode lainnya.

T3 Code berjalan dari rilis AppImage resminya di `~/.local/share/t3code` bukan dari paket, jadi ia memperbarui dirinya sendiri. Memasangnya menanyakan apakah akan dimulai pada channel Stable atau Nightly; ganti nanti di pengaturan T3 Code. Thread dan pengaturanmu tinggal di `~/.t3`, dan menghapus T3 Code di bawah _Remove > AI_ membawanya bersamanya.

### Model lokal

Jalankan model terbuka di mesinmu sendiri untuk agen coding-mu. Prompt dan kodemu tetap di mesin; tidak ada yang dikirim ke model yang meninggalkannya. Mulai dengan:

```bash
omarchy models use best text
```

Itu menyiapkan model teks terbaik untuk mesin ini, jenis yang digunakan agenmu. Model gambar, video, dan musik memiliki yang terbaiknya sendiri: `omarchy models use best image`, `video` atau `music`. Jalankan `omarchy models use best` untuk melihat pilihan setiap jenis untuk mesin ini.

Atau buka panel model lokal dari ikon sparkles-nya di bar atas, di samping ikon agen, atau dengan Super + Ctrl + Alt + X, dan pilih +. Ikon muncul ketika sebuah model cocok dengan mesin ini. Podman, yang menjalankan model, disertakan dengan Omarchy, begitu juga container toolkit NVIDIA pada mesin NVIDIA, yang memberi mereka GPU; jika salah satunya hilang, penyiapan pertama memasangnya. Omarchy kemudian memilih model yang direkomendasikan untuk mesin ini, mengunduhnya, dan memulainya. Harapkan unduhan puluhan GB dan sebagian besar memori mesin digunakan saat model berjalan: Flash Next menggunakan sekitar 100 GiB dengan konteks penuh 256K-nya. Jika model lain menahan memori yang dibutuhkannya, ia disiapkan dalam keadaan berhenti, siap dimulai setelah kamu menghentikan salah satu. Model berhenti saat logout; hentikan sendiri saat kamu membutuhkan memori untuk hal lain.

`omarchy models list` menampilkan pilihan dan menjelaskan mengapa beberapa tidak cocok. Untuk menyiapkan yang lain, jalankan `omarchy models use <recipe>`. Saat ini, `qwen3.8-flash-next-gufo` dan `qwen3.8-27b-gufo` tersedia untuk mesin Strix Halo 128 GB; 27B memerlukan sekitar 40 GiB, sehingga menyisakan ruang untuk pekerjaan lain. Pada laptop 64 GB dengan Arc B390 dari Intel, `qwen3.6-35b-a3b-llamacpp` berjalan dalam sekitar 30 GiB. Recipe dan rekomendasi baru tiba dengan `omarchy update`, melalui paket.

Setiap model yang kamu siapkan mendapatkan barisnya sendiri di panel model lokal: play untuk memulainya, pause untuk menghentikannya dan membebaskan memorinya, dan tombol terminal untuk membuka agenmu padanya. Di bagian atas, sebuah bar menunjukkan bagaimana memori mesin dibagi antara Omarchy itu sendiri (sistem dan aplikasimu), setiap model yang berjalan, dan yang bebas. Arahkan ke model yang berhenti dan bar menunjukkan apakah ia cocok, atau berapa kekurangannya. Beberapa dapat berjalan sekaligus ketika mereka cocok dalam memori bersama; jika satu tidak cocok, Omarchy menyebutkan model berjalan mana yang harus dihentikan. Seret baris berdasarkan logonya untuk menyusun ulang, dan tekan Delete pada baris yang dipilih untuk menghapus model dan unduhannya.

Setiap model coding yang kamu siapkan juga mendapatkan entrinya sendiri di peluncur aplikasi, di bawah nama model dan dengan logo pembuatnya, seperti cara masuk ke Claude, Codex, atau Grok menambahkan satu. Ia membuka agenmu pada model itu, dan memulai model terlebih dahulu jika belum berjalan: terminal menampilkannya memuat dan menyerahkan ke agen setelah ia siap. Menghapus model menghapus entrinya.

Tidak setiap model untuk coding. Model gambar, video, dan musik dibuka di Fantasi sebagai gantinya, aplikasi Omarchy untuk membuat gambar, video, dan musik dengan model yang berjalan di mesin ini, dipilih di sana atau dari barisnya di panel model lokal.

Model terus berjalan persis seperti saat disiapkan, jadi pembaruan Omarchy tidak pernah memulai ulang satu model di bawah agenmu. Ketika Omarchy memiliki runtime yang lebih baru atau weights yang lebih baru untuk model yang telah kamu siapkan, barisnya menampilkan tombol pembaruan: tekan dan model disiapkan lagi di latar belakang, hanya mengunduh yang berubah, dan dimulai ulang pada versi baru. Model yang berhenti tetap berhenti. `omarchy models update` melakukan hal yang sama untuk setiap model dari terminal.

Dari command line, `omarchy models start <recipe>` dan `omarchy models stop <recipe>` melakukan hal yang sama, `omarchy models status` menampilkan setiap model, dan `omarchy agent --local-model <recipe>` membuka model itu di pi, apa pun agen defaultmu. Untuk membuat model lokalmu menjadi yang dibuka oleh hotkey agen, konsol Quake, dan _Make something_, jalankan `omarchy default agent local` atau beri bintang pada model yang berjalan di panel agen. pi juga mencantumkan setiap model yang telah kamu siapkan, dan model di mesin yang telah kamu pasangkan, di pemilih modelnya sendiri, jadi `pi` biasa juga menjangkaunya. Klien apa pun yang kompatibel dengan OpenAI juga dapat terhubung: `status` menampilkan alamat setiap model (yang pertama adalah `http://127.0.0.1:11435/v1`), nama recipe adalah modelnya, dan key berada di `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` menghapus model dan unduhan yang tidak digunakan model lain.

Runtime pihak ketiga dilabeli dengan penerbitnya. Omarchy menjalankan setiap model tanpa akses jaringan.

### LLM lokal

Omarchy merekomendasikan dua cara menjalankan model LLM lokal: LM Studio dan Ollama. LM Studio menyediakan antarmuka GUI untuk menemukan model open-weight, memasangnya, dan menjalankannya. Ini cara yang bagus untuk memulai dengan mudah. Ollama menawarkan CLI untuk melakukan hal serupa. Tetapi jika kamu baru dalam model lokal, saya akan mulai dengan LM Studio. Kamu dapat memasang salah satu di bawah _Install > AI_ di Omarchy Menu.

### Skill Omarchy

Skill agen membantu AI menggunakan tool tertentu dengan cara tertentu, dan Omarchy mengirimkan tujuh di antaranya. Skill omarchy mencakup menyesuaikan sistem, seperti mengutak-atik config Hyprland-mu atau menyesuaikan bar. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app, dan omarchy-make-game mencakup membuat sesuatu yang baru, omarchy-contribute mencakup melaporkan bug atau mengirim perbaikan ke upstream, dan omarchy-diagnose-crash bekerja melalui core dump sebuah crash. Mereka di-symlink ke direktori skill untuk Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` dan setiap `~/.hermes/profiles/*/skills`), dan lokasi generik `~/.agents/skills`, jadi sebagian besar harness mengambilnya secara otomatis. Folder skill milikmu sendiri dengan nama yang sama didahulukan.

Tetapi kamu harus memperlakukan skill-skill ini sebagai eksperimental. Model yang berbeda akan menggunakannya dengan efek yang berbeda. Sebaiknya jalankan dalam mode plan terlebih dahulu, agar kamu memiliki gambaran tentang apa yang ingin diubah agen. Dan kemudian bersiaplah untuk melakukan rollback perubahan atau bahkan menjalankan `omarchy reinstall configs`, jika agen membuat semuanya berantakan.
