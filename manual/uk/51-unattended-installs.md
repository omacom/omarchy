# Встановлення без участі користувача

Образ ISO Omarchy може встановити себе сам, коли нікого немає за клавіатурою. Якщо програма встановлення знаходить другий диск із міткою `cidata`, на якому є її файли конфігурації, вона копіює їх, повністю пропускає майстер налаштування й самостійно перезавантажується в готову систему. Не потрібна жодна спеціальна збірка ISO, жоден додатковий пункт у меню завантаження — якщо такого диска не підключено, нічого не змінюється, і ви отримуєте звичайний майстер.

Тому Omarchy чудово підходить як базовий образ для одноразових середовищ розробки: створіть VM у Proxmox або за допомогою Packer, завантажте її, йдіть собі й підключайтеся через SSH. `cidata` — це мітка cloud-init `NoCloud`, тож усі поширені інструменти віртуалізації вже вміють підключати такий диск.

## Файли конфігурації

Ці файли — саме те, що записує власний майстер програми встановлення, тож найпростіший спосіб отримати початковий набір — виконати одне інтерактивне встановлення (скажімо, у VM) і скопіювати те, що воно записало в `/root`:

| Файл | Обов'язковий | Призначення |
|------|----------|---------|
| `user_configuration.json` | Так | Диск, ім'я хоста, часовий пояс, клавіатура |
| `user_credentials.json` | Так | Ім'я користувача та хеш пароля |
| `user_encrypt_installation.txt` | Ні | `true`, коли конфігурація містить блок `disk_encryption` |
| `authorized_keys` | Ні | Публічні ключі SSH, по одному в кожному рядку |
| `tailscale_authkey` | Ні | Ключ автентифікації Tailscale для приєднання до вашого tailnet під час першого завантаження |

Згенеруйте хеш пароля для `user_credentials.json` за допомогою `openssl passwd -6 "yourpassword"`.

Ім'я та email для комітів git не входять до встановлення. Задайте їх, коли машина запрацює, наприклад через SSH, за допомогою `omarchy setup git --name "Jane Doe" --email jane@example.com`.

Ви також можете покласти порожній файл із назвою `defer-provisioning` замість `user_credentials.json`. Це запустить те саме [встановлення з підготовкою для іншого власника](02-getting-started.md), яке можна запустити інтерактивно: машина встановлюється без жодних особистих даних, а той, хто завантажить її першим, вибере свою клавіатуру й створить свого користувача. Це режим для стендів створення образів, де диск узагалі не повинен містити нічиїх облікових даних.

## Доступ через SSH

Коли присутній `authorized_keys`, програма встановлення налаштовує ці ключі як `~/.ssh/authorized_keys` користувача, вмикає `sshd` і відкриває для нього брандмауер. (Стандартне встановлення Omarchy постачається з openssh із вимкненою службою й закритим портом, тож машина без нагляду інакше була б недосяжною.) Встановлення лише додає ваші ключі — воно не послаблює жодних інших параметрів автентифікації демона SSH.

Коли натомість присутній `tailscale_authkey`, машина приєднується до вашого tailnet під час першого завантаження: Tailscale встановлюється з пакетів, що входять до ISO, брандмауер дозволяє інтерфейс tailnet, а фонове завдання виконує приєднання, щойно машина справді отримає мережу, і повторює спроби, доки не досягне успіху. Використовуйте багаторазовий, попередньо авторизований ключ, щоб один образ диска міг обслуговувати багато машин.

## Створення диска cidata

Підійде будь-яка файлова система з правильною міткою. Крихітний ISO — це простий спосіб:

```bash
mkdir cidata
cp user_configuration.json user_credentials.json authorized_keys cidata/
genisoimage -output cidata.iso -volid cidata -joliet -rock cidata/
```

Потім підключіть його до VM разом з ISO Omarchy. Ось повний приклад для Proxmox:

```bash
qm create 101 --name my-omarchy \
  --bios ovmf --machine q35 --cpu host --cores 4 --memory 8192 \
  --ostype l26 --scsihw virtio-scsi-single \
  --efidisk0 local-lvm:0,efitype=4m,pre-enrolled-keys=0 \
  --scsi0 local-lvm:40,discard=on,iothread=1 \
  --net0 virtio,bridge=vmbr0 --vga virtio --serial0 socket \
  --ide2 local:iso/omarchy.iso,media=cdrom \
  --ide3 local:iso/cidata.iso,media=cdrom \
  --boot order='scsi0;ide2'

qm start 101
```

Порядок завантаження навмисно ставить диск першим: порожній диск під час першого завантаження пропускає завантаження далі до ISO, а встановлена система відтоді завжди завантажується з диска.

## Два застереження

Зашифровані встановлення без участі користувача не цілком обходяться без участі — комусь усе одно доведеться ввести парольну фразу LUKS під час першого завантаження. А блок `disk_encryption` у `user_configuration.json` містить цю парольну фразу у відкритому тексті, тож ставтеся до диска cidata, створеного із зашифрованого встановлення, як до секрету, яким він і є.
