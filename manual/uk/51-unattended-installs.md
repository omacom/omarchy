# Встановлення без участі користувача

ISO Omarchy вміє встановлюватися сам, коли за клавіатурою нікого немає. Якщо інсталятор знаходить другий диск із міткою `cidata` та файлами конфігурації на ньому, він копіює їх, повністю пропускає майстер налаштування й сам перезавантажується в готову систему. Жодної спеціальної збірки ISO, жодного додаткового пункту в меню завантаження — без такого диска нічого не змінюється, і ви отримуєте звичайний майстер.

Завдяки цьому Omarchy чудово підходить як базовий образ для одноразових середовищ розробки: створюєте VM у Proxmox або за допомогою Packer, завантажуєте її, йдете геть і заходите по SSH. `cidata` — це мітка `NoCloud` у cloud-init, тож усі поширені інструменти віртуалізації вже вміють підключати такий диск.

## Файли конфігурації

Ці файли — саме те, що записує власний майстер інсталятора, тож найпростіший спосіб отримати стартовий набір — виконати одне інтерактивне встановлення (скажімо, у VM) і скопіювати те, що він записав у `/root`:

| Файл | Обов’язковий | Призначення |
|------|----------|---------|
| `user_configuration.json` | Так | Диск, ім’я хоста, часовий пояс, клавіатура |
| `user_credentials.json` | Так | Ім’я користувача та хеш пароля, а також парольна фраза LUKS для зашифрованого встановлення |
| `user_encrypt_installation.txt` | Ні | `true`, коли конфігурація містить блок `disk_encryption` |
| `authorized_keys` | Ні | Публічні ключі SSH, по одному в рядку |
| `tailscale_authkey` | Ні | Ключ автентифікації Tailscale для приєднання до вашого tailnet під час першого завантаження |

Згенеруйте хеш пароля для `user_credentials.json` командою `openssl passwd -6 "yourpassword"`.

Ім’я та email для комітів git не входять до встановлення. Вкажіть їх, коли машина запрацює, наприклад по SSH, командою `omarchy setup git --name "Jane Doe" --email jane@example.com`.

Ви також можете покласти порожній файл із назвою `defer-provisioning` замість `user_credentials.json`. Це запускає те саме [встановлення з підготовкою для іншого власника](02-getting-started.md), яке можна вибрати інтерактивно: машина встановлюється без жодних особистих даних, а той, хто завантажить її першим, обирає свою клавіатуру й створює свого користувача. Це режим для стендів створення образів, де диск узагалі не має містити нічиїх облікових даних.

## Доступ по SSH

Коли файл `authorized_keys` присутній, встановлення налаштовує ключі як `~/.ssh/authorized_keys` користувача, вмикає `sshd` і відкриває для нього файрвол. (У звичайному встановленні Omarchy постачається openssh із вимкненою службою та закритим портом, тож машина без участі користувача інакше була б недосяжною.) Встановлення лише додає ваші ключі — воно не послаблює жодних інших налаштувань автентифікації демона SSH.

Коли присутній `tailscale_authkey`, машина натомість приєднується до вашого tailnet під час першого завантаження: Tailscale встановлюється з пакетів, що входять до ISO, файрвол дозволяє інтерфейс tailnet, а фонове завдання виконує приєднання, щойно машина справді отримає мережу, і повторює спроби, доки не вдасться. Використовуйте багаторазовий, попередньо авторизований ключ, щоб один образ диска міг обслуговувати багато машин.

## Створення диска cidata

Підійде будь-яка файлова система з правильною міткою. Крихітний ISO — простий спосіб:

```bash
mkdir cidata
cp user_configuration.json user_credentials.json authorized_keys cidata/
genisoimage -output cidata.iso -volid cidata -joliet -rock cidata/
```

Потім підключіть його до VM разом з ISO Omarchy. Ось повний приклад для Proxmox:

```bash
qm create 101 --name my-omarchy \
  --bios ovmf --machine q35 --cpu host --cores 4 --memory 8192 \
  --ostype l26 --scsihw virtio-scsi-single \
  --efidisk0 local-lvm:0,efitype=4m,pre-enrolled-keys=0 \
  --scsi0 local-lvm:40,discard=on,iothread=1 \
  --net0 virtio,bridge=vmbr0 --vga virtio --serial0 socket \
  --ide2 local:iso/omarchy.iso,media=cdrom \
  --ide3 local:iso/cidata.iso,media=cdrom \
  --boot order='scsi0;ide2'

qm start 101
```

Диск у порядку завантаження вказано першим навмисно: порожній диск під час першого завантаження пропускає далі до ISO, а встановлена система відтоді завжди завантажується з диска.

## Два застереження

Зашифровані встановлення без участі користувача не є повністю без участі користувача — хтось усе одно має ввести парольну фразу LUKS під час першого завантаження. І ця парольна фраза вказується на верхньому рівні `user_credentials.json` як `encryption_password` — archinstall читає її саме звідти, а не з блока `disk_encryption` у `user_configuration.json`, — тож ставтеся до диска cidata, створеного із зашифрованого встановлення, як до секрету, яким він і є.
