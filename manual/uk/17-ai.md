# ШІ

Omarchy містить лаунчери для агентів для кодування нижче, не обираючи для вас жодного за замовчуванням. Запустіть команду, щоб встановити її CLI під час першого використання, а потім пройдіть автентифікацію, коли з'явиться запит. Hermes та OpenClaw — винятки: для них через mise нічого не встановлюється, а вибір будь-якого з них налаштовує власну копію, що самооновлюється, як пояснює розділ _Настільні застосунки_ нижче.

### Встановлення та оновлення агентів

За винятком Hermes та OpenClaw, ці агенти використовують ліниве встановлення mise: перший запуск встановлює CLI, а наступні запуски використовують його повторно. mise також перевіряє встановлений агент на наявність нового випуску щонайбільше раз на чотири години, безпосередньо перед його запуском або у фоновому режимі в підказці оболонки. Якщо це оновлення не вдається або ви офлайн, запускається встановлена версія. `omarchy update` оновлює встановлені агенти разом з рештою Omarchy, а `mup` оновлює лише інструменти, керовані mise.

Власний засіб оновлення агента, як-от `claude update`, `codex update` або кнопка оновлення в застосунку, не оновлює встановлення, кероване mise. `codex update` завершується помилкою, а `claude update` може повідомити про успіх, встановивши при цьому окрему копію, яку mise не відстежує. Якщо ви надаєте перевагу використанню рідного засобу встановлення та оновлення агента, додайте його до `disable_tools`; див. [Попередньо встановлені інструменти CLI](18-development-tools.md#preinstalled-cli-tools).

Щоб встановити всі налаштовані ліниві інструменти до того, як вони вам знадобляться, запустіть `mise install --include-lazy`. Це включає інші інструменти CLI Omarchy за замовчуванням, а також агентів. Див. [Попередньо встановлені інструменти CLI](18-development-tools.md#preinstalled-cli-tools), щоб встановити один інструмент або використати власне встановлення.

`grok` встановлюється через фірмовий пакет `grok` від mise, так само як `claude` та `codex`. Запустіть `grok` або виберіть його в _Agent > Harness_. Пропустіть засіб встановлення `curl | bash` на x.ai. Цей шлях розміщує другу копію в `~/.grok/bin`, додає її на початок `PATH` і перезаписує обгортку Omarchy.

`dsh` відкриває свій браузерний інтерфейс на `127.0.0.1:3080`, з каталогом запуску як робочим простором за замовчуванням. Його браузерний інтерфейс не приймає початкову підказку, тож `omarchy agent prompt` відкриває його з підказкою у вашому буфері обміну для вставлення. Omarchy запускає його з пресетом дозволів без схвалення від DeepSeek. DeepSeek Harness завантажує журнали сеансів до DeepSeek, коли ви використовуєте його офіційний API моделей; вимкніть це в _Settings > General > Upload Session Log_ у його браузерному інтерфейсі. Відгуки, які ви йому надсилаєте, також завантажуються разом із сеансом, якщо ви не запустите його з `DSH_TELEMETRY_MODE=DISABLED`.

### Агент за замовчуванням

Виберіть свого агента за замовчуванням за допомогою `omarchy default agent <name>` або в _Agent > Harness_ у меню Omarchy (`Super + Space`). Якщо агент ще не встановлено, вибір його спочатку встановлює його, а також він отримує власний лаунчер у лаунчері застосунків, поруч з Agent. Свіжа Omarchy запросить вас зробити цей вибір за допомогою одноразового сповіщення.

Вибір Claude також намагається налаштувати його розширення для браузера для Chromium, Chrome, Brave, Brave Origin та Edge. Налаштування розширення застосовується до всіх користувачів і може запитати ваш системний пароль; скасування або невдале встановлення розширення все одно вибирає та запускає Claude. Перезапустіть браузер, увімкніть розширення, якщо з'явиться запит, і увійдіть до Claude, щоб завершити його підключення. Запустіть `/chrome` у Claude, щоб перевірити з'єднання. Firefox та Zen не підтримують це розширення. Якщо Claude вже був вашим агентом за замовчуванням до того, як це налаштування було додано, виберіть його знову, щоб встановити розширення.

Після того як ви зробили вибір, `Super + Shift + Ctrl + A` запускає агента за замовчуванням в окремому вікні термінала (або викликає вибір, якщо ви ще не обрали). Ви також можете запустити його одразу до завдання за допомогою `omarchy agent prompt "Review this project"`. Freebuff та DeepSeek Harness не приймають початкову підказку, тож натомість вони відкриваються з підказкою у вашому буфері обміну для вставлення. Агенти, запущені таким чином, працюють без нагляду у своїх відповідних режимах «не зупиняйся, щоб запитати», тож будьте готові до того, що вони справді робитимуть речі! MiniMax Code не має такого режиму для своїх інтерактивних сеансів, тож він запитує дозволи як зазвичай. А оскільки агенти відмовляються запам'ятовувати довіру для вашого домашнього каталогу, запуски з `$HOME` натомість стартують у `~/Work`.

Є також ярлики термінала: `a` запускає агента за замовчуванням вбудовано в поточному терміналі, тоді як `c`, `cx` та `cy` запускають OpenCode, Claude Code та Codex безпосередньо (знову ж таки в їхніх режимах автоматичного схвалення). Зміни теми також синхронізуються з агентами: Claude Code, Pi, OpenCode та Hermes (після того як Omarchy його встановила) усі слідують за вами, коли ви перемикаєте тему Omarchy.

### Ваші інструкції для агента

Особисті правила для кожного агента містяться в `~/.agents/AGENTS.md`, поруч зі спільними навичками в `~/.agents/skills`. Відкрийте його в _Agent > Instructions_, що також пов'язує його з кожним гарнесом, який зберігає власний глобальний файл: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` від Copilot тощо. Crush та Amp читають посилання `~/.config/AGENTS.md`, тоді як omp, Kimi та DeepSeek Harness читають `~/.agents/AGENTS.md` безпосередньо. Вибір агента за замовчуванням також пов'язує його. Файл інструкцій, який у вас уже був, стає спільним, якщо його ще не було; інакше він зберігається поруч із посиланням як `.bak`. Запустіть `omarchy agent instructions`, щоб повторно пов'язати після встановлення іншого агента.

### Панель агентів

Верхня панель має значок агентів. До того як ви налаштували агента, її панель проведе вас через вхід до Claude, Codex або Grok, і перший з них стане вашим агентом за замовчуванням. Після цього панель розміщує кожну підписку на одній сторінці: кожен агент та обліковий запис з його планом, вимірювач для кожного з його 5-годинних сеансових та тижневих лімітів із часом до його скидання (наведіть вказівник, щоб побачити точний відсоток) або залишок передплаченого балансу, під рядком, який циклічно показує те, що ви використали по всіх них, як-от токени цього тижня та вашу найуживанішу модель. У розділі _Make something cool_ вона пропонує стартові підказки для нової теми, плагіна, застосунку або гри, які передають завдання вашому агенту за замовчуванням. Застосунки створюються так само, як власні Hype, Monologue та Omacut від Omarchy, на C++ та Qt Quick, дотримуючись навички агента omarchy-make-app, а компілятор та частини Qt, які їм потрібні, постачаються встановленими. Ігри — це одна сторінка three.js у `~/Games/vibes`, що дотримується навички агента omarchy-make-game, і всі вони відкриваються з одного лаунчера Game Vibes у поточній темі; вони завантажують three.js з вебу, тож для запуску їм потрібне з'єднання. Claude Code, Codex, Grok, Kimi, Cursor та його ліміт Grok Bot, GitHub Copilot, Muse, Antigravity та Devin охоплені одразу з їхніми лімітами, Kimchi з його планом, передплаченими кредитами та бюджетами витрат, а Hermes, Mistral Vibe та Qwen Code показують свої сеанси та токени, щойно ви ними скористалися. Плани провайдерів та ключі, які ви використовуєте через pi, omp або opencode, також відображаються: OpenCode Zen та Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan та Synthetic з їхніми лімітами; OpenRouter та DeepSeek з їхніми передплаченими балансами; Fireworks з його витратами за останні 30 днів. Токени від моделей, які ви запускаєте на власному обладнанні, також зараховуються до загальних підсумків; самі моделі мають власну панель, описану в розділі [Локальні моделі](#local-models). Кожен агент обліковується один раз, за тим, хто виставляє за нього рахунок, незалежно від того, через скільки гарнесів ви ним керуєте.

Клацніть лівою кнопкою миші значок панелі або натисніть `Super + Ctrl + X`, щоб відкрити панель, клацніть правою кнопкою, щоб запустити агента за замовчуванням, і клацніть середньою кнопкою, щоб оновити. Записи використання, що стоять за нею, перегенеровуються кожні 15 хвилин за допомогою `omarchy agent usage update`, а панель навіть може об'єднувати використання з інших ваших машин через синхронізовану папку. Див. README у `$OMARCHY_PATH/shell/plugins/agents/` для повних налаштувань.

### Кілька підписок

Якщо ви платите за більше ніж один план Claude, Codex або Grok — скажімо, особистий Max і робочий — Omarchy може тримати їх усі в стані входу та переміщатися між ними. Додайте підписку за допомогою + на панелі агентів, яка проведе вас через це просто там, або за допомогою `omarchy agent account add claude Work` (або `codex`, або `grok`). Вона встановлює CLI, якщо його бракує. Перший обліковий запис для провайдера входить через ваш звичайний браузер, саме там, де CLI завжди шукає. Кожен наступний входить через приватне вікно, тож обліковий запис, до якого ваш браузер уже ввійшов, не буде підхоплено помилково; увійдіть там як обліковий запис, який ви додаєте, і спочатку закрийте будь-яке приватне вікно, яке у вас уже відкрито. Ніколи не виходьте з CLI, щоб зробити це: вихід скасовує збережений вхід, і цей обліковий запис доведеться додавати знову.

Щоб скопіювати ваші входи підписок на іншу машину Omarchy через SSH, запустіть `omarchy agent account copy user@laptop`. Відправник надає тимчасового отримувача, коли місце призначення не має встановленого, тож старіші машини Omarchy можуть отримувати облікові записи без оновлення. Встановлені отримувачі мають перевагу. Це копіює всі підписки Claude, Codex та Grok; додайте назви провайдерів, щоб вибрати їх, як у `omarchy agent account copy laptop claude`. Назви облікових записів та ідентифікатори команд відповідають джерелу, включно з обліковими записами, які вже є в місці призначення. Незв'язані облікові записи місця призначення отримують числовий суфікс, якщо їхні назви конфліктують, а налаштування, навички, плагіни та історія розмов залишаються локальними для кожної машини.

Існуючі облікові дані місця призначення зберігаються. Обліковий запис джерела, який уже ввійшов там, має синхронізовану назву без заміни його облікових даних; інші облікові записи додаються поруч із ним. Щоб замінити збережені облікові дані для відповідних облікових записів, скористайтеся `omarchy agent account copy --replace laptop claude` після завершення сеансів цього облікового запису в місці призначення. Свіже місце призначення також отримує активний обліковий запис джерела та налаштування перемикання; усталене місце призначення зберігає власні.

Облікові дані передаються через SSH і зберігаються у приватних файлах у місці призначення, тож копіюйте лише на машини, яким ви довіряєте. Це одноразова копія, а не постійна синхронізація. Токени оновлення Codex можуть бути ротовані іншою машиною, внаслідок чого скопійований вхід потребуватиме поновлення; окремі входи залишаються найнадійнішим вибором для одночасного використання на кількох машинах. Див. [Посібник з автентифікації облікового запису Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Один обліковий запис на провайдера активний, і кожен новий сеанс починається як він: `cx`, `cy`, простий `claude`, `codex` або `grok`, будь-що, запущене через `omarchy agent`, а також скрипти або редактори, які знаходять CLI на `PATH`. Перемикайтеся за допомогою `omarchy agent account use work` (і назад за допомогою `omarchy agent account use main`) або на панелі, натиснувши номер облікового запису, а потім `Enter` (або клацнувши його кнопку Use). Запущені сеанси Claude також перемикаються, з їхнього наступного повідомлення: кожен сеанс Claude працює в `~/.claude`, який завжди містить вхід активного облікового запису. Сеанс Claude, запущений у власній папці облікового запису старішою Omarchy, утримує цей вхід, доки не завершиться, тож перемикання називає ці сеанси та завершується самостійно, щойно вони зникнуть. Запущені сеанси Codex та Grok залишаються на обліковому записі, з яким вони почалися. Історія розмов, налаштування, навички та плагіни спільні для всіх облікових записів, тож `claude --continue` у тій самій папці продовжує з того місця, де ви зупинилися на новому обліковому записі.

За наявності більше ніж одного облікового запису панель показує ліміти кожного облікового запису поруч, з позначенням активного. За замовчуванням Omarchy сповіщає вас, коли активний обліковий запис перевищує 95% ліміту, і клацання сповіщення перемикає на обліковий запис із найбільшим запасом. Наведіть вказівник на рядок облікового запису на панелі та клацніть Autoswitch, що з'являється поруч із Use (або натисніть `m`), або запустіть `omarchy agent account mode auto`, щоб він перемикався самостійно; поки це ввімкнено, Autoswitch займає місце Use, а повторне клацання повертає до сповіщень. Додайте число, щоб змінити поріг, як у `omarchy agent account mode auto 90`. Якщо кожен обліковий запис перевищує поріг, ви почуєте про це один раз, разом із тим, який обліковий запис звільниться першим. Поки активний обліковий запис перебуває в межах 15 пунктів від свого порогу (80% за замовчуванням), його ліміти перевіряються кожні три хвилини, а не кожні 15.

`omarchy agent account list` показує кожен обліковий запис та його останні ліміти, `omarchy agent account remove work` забуває один, а `omarchy agent account rename primary Hey` перейменовує один (або клацніть назву облікового запису на панелі). Ці команди працюють з обліковими записами вашого агента за замовчуванням; щоб дістатися до іншого провайдера, спочатку назвіть його, як у `omarchy agent account use codex side`. Вхід, який у вас уже був у `~/.claude` або `~/.codex`, — це обліковий запис _Main_. Обліковий запис Codex залишається там, де він є; обліковий запис Claude чекає у власній папці, поки активний інший обліковий запис. Обліковий запис, який не використовувався більше ніж близько восьми годин, може показувати _Sign-in required_; клацніть його, щоб знову ввійти до цього облікового запису просто на панелі, або перемкніться на нього та почніть сеанс, який оновить вхід самостійно. Сервери MCP, які ви додаєте за допомогою `claude mcp add`, досягають кожного облікового запису Claude, оскільки всі вони працюють у `~/.claude`; для Codex та Grok сервери, які у вас були, коли обліковий запис було додано, переходять до нього, але пізніші досягають лише того облікового запису, в якому ви їх додали. Claude Desktop зберігає власний вхід, а інструменти Codex або Grok, налаштовані з абсолютним шляхом до бінарного файлу CLI, не слідують за перемиканням. Явний `CLAUDE_CONFIG_DIR`, `CODEX_HOME` або `GROK_HOME` має перевагу над вибраним обліковим записом.

### Діагностика аварій

Omarchy стежить за systemd-coredump на предмет аварій процесів. Щойно ви вибрали агента за замовчуванням, будь-яка ваша програма, яка дампить ядро, викликає сповіщення «Process crashed» — клацніть його, і аварія передається вашому агенту за замовчуванням разом із навичкою omarchy-diagnose-crash від Omarchy, яка проводить агента через встановлення фактів із дампу ядра та вирішення, чи варто повідомляти про аварію розробникам. Ви також можете запустити її вручну проти будь-якого PID з `coredumpctl list` за допомогою `omarchy agent crash <pid>`.

Стеження увімкнено за замовчуванням. Вимкніть його в _Trigger > Toggle > Crash Capture Off_ (або за допомогою `omarchy toggle crash-capture`), і сповіщення припиняться; `omarchy agent crash <pid>` усе одно працює вручну.

Аварії також можна заглушити по одній програмі за раз, що діагностика пропонує вам наприкінці. `omarchy crash mute hyprland` зупиняє сповіщення лише для цієї програми, `omarchy crash mute hyprland off` повертає їх назад, а `omarchy crash mute` сам по собі перераховує те, що ви заглушили. Він так само охоче приймає шлях бінарного файлу, як і його назву, тож `omarchy crash mute /usr/bin/hyprland` робить те саме. Візьміть назву з пробілом у лапки, як у `omarchy crash mute 'Some App'`. Все інше все одно сповіщає, а заглушена програма все одно аварійно завершується — це приховує нагадування, воно нічого не виправляє.

### Настільні застосунки

Меню _Install > AI_ також містить кілька графічних застосунків ШІ: Amp Desktop, Antigravity Desktop, настільний застосунок ChatGPT, настільний застосунок Claude (бета-версія Anthropic для Linux із вкладками Chat, Cowork та Claude Code), Grok Bot для спілкування з моделями xAI, Herdr Desktop, Hermes Desktop, OpenClaw, настільний застосунок Perplexity та T3 Code. Grok Bot — це настільний застосунок для чату. Агент для кодування — це команда `grok`.

Hermes Desktop — це той, про який варто знати, оскільки машина має один Hermes, і він належить застосунку: Hermes встановлюється лише через застосунок, а команда `hermes`, яку запускає агент за замовчуванням, належить застосунку. Вибір Hermes як агента за замовчуванням встановлює те саме, що й запис _Install > AI_: пакет і середовище виконання Hermes у `~/.hermes`, налаштоване власним засобом встановлення Hermes, що вперше займає кілька хвилин. Це середовище виконання — це той єдиний Hermes, який використовують термінальна команда `hermes`, агент за замовчуванням та застосунок, і воно оновлює себе за допомогою `hermes update`, а не чекає на випуск Omarchy. Встановлення його також передає Hermes тему Omarchy як скін під назвою `omarchy`, за яким слідує кожна поверхня Hermes, коли ви перемикаєте теми; виберіть інший у налаштуваннях Appearance Hermes або за допомогою `/skin`, якщо ви надаєте перевагу, щоб він цього не робив, і Omarchy залишить цей вибір у спокої. Видалення застосунку в _Remove > AI_ спочатку закриває Hermes, включно зі шлюзом, забирає це середовище виконання з собою і зберігає ваші чати, спогади та навички, які Hermes написав для себе, якщо ви не скажете йому інакше: він запитує, за замовчуванням відповідаючи ні, чи мають ці дані та ваші налаштування з'єднання також зникнути.

Настільний досвід OpenClaw — це його Control UI, який відкривається як вебзастосунок, підтримуваний власним локальним шлюзом. OpenClaw живе в `~/.openclaw` і оновлює себе сам: скористайтеся кнопкою «Update Gateway» у Control UI або запустіть `openclaw update`, і шлюз перезапуститься на новій версії. Omarchy лише вибирає випуск, з якого починається свіже встановлення. OpenClaw також може бути вашим агентом за замовчуванням: вибір його в _Agent > Harness_ налаштовує ту саму копію в `~/.openclaw`, а агент відкриває термінальний інтерфейс OpenClaw, підключений до його шлюзу. Видалення OpenClaw у _Remove > AI_ забирає службу шлюзу та застосунок із собою, а потім запитує, чи має `~/.openclaw` також зникнути, оскільки там зберігаються ваші чати та облікові дані поряд із самим OpenClaw та середовищами виконання плагінів, які він завантажує; за замовчуванням він зберігається, а повторне встановлення OpenClaw підхоплює його назад.

Herdr Desktop — це настільний застосунок [Herdr](https://herdr.dev): простори, вкладки та панелі терміналів і агентів для кодування, які продовжують працювати в його ядрі, коли ви закриваєте вікно. Він походить із власного засобу встановлення Herdr, а не з пакета, тож він живе в `~/.local/share/herdr-app`, приносить своє ядро в `~/.local/bin/herdr-core`, коли у вас його ще немає, і оновлює обидва сам. Він розташований поруч із командою `herdr`, яку Omarchy постачає на `Super + Ctrl + Return`, а не замінює її, і отримує прямі клавіші цієї команди: `Alt + Return` та `Alt + Shift + Return` розділяють панель вниз або праворуч, `Alt + Escape` закриває її, `Ctrl + Alt + Arrow` переміщається між панелями, `Alt + 1..9` та `Alt + Left/Right` вибирають вкладку, а `Alt + Up/Down` переміщаються між просторами. `Ctrl + 1..9` вибирає простір, а `Alt + Shift + Up/Down` крокує через агентів. Клавіші префікса `Ctrl + Space` залишаються лише для термінала, оскільки застосунок не може утримувати просту клавішу Ctrl для послідовності. Omarchy записує їх до `~/.config/herdr-app/keys.json`, а `omarchy-refresh-herdr-app` повертає їх назад. Встановлення його вибирає тему Omarchy для Herdr, яка відтоді слідує за вашою темою Omarchy. Herdr зберігає одну тему для світлого режиму та одну для темного, тож після перемикання між темною та світлою темами Omarchy ще раз виберіть Omarchy у виборі тем Herdr для іншого режиму.

T3 Code працює зі свого офіційного випуску AppImage у `~/.local/share/t3code`, а не з пакета, тож він оновлює себе сам. Встановлення його запитує, чи починати на каналі Stable чи Nightly; перемкніться пізніше в налаштуваннях T3 Code. Ваші потоки та налаштування живуть у `~/.t3`, а видалення T3 Code у _Remove > AI_ забирає їх із собою.

### Локальні моделі

Запускайте відкриту модель на власній машині для ваших агентів для кодування. Ваші підказки та код залишаються на машині; ніщо, надіслане моделі, не покидає її. Почніть із:

```bash
omarchy models use best text
```

Це налаштовує найкращу текстову модель для цієї машини, ту, яку використовують ваші агенти. Моделі зображень, відео та музики мають власну найкращу: `omarchy models use best image`, `video` або `music`. Запустіть `omarchy models use best`, щоб побачити вибір кожного виду для цієї машини.

Або відкрийте панель локальних моделей за її значком блискіток на верхній панелі, поруч зі значком агентів, або за допомогою Super + Ctrl + Alt + X, і виберіть +. Значок з'являється, коли модель підходить для цієї машини. Podman, який запускає моделі, постачається з Omarchy, як і набір інструментів контейнерів NVIDIA на машині NVIDIA, який надає їм GPU; якщо чогось із цього бракує, перше налаштування встановлює це. Потім Omarchy вибирає рекомендовану модель для цієї машини, завантажує її та запускає. Очікуйте завантаження на десятки GB і використання більшої частини пам'яті машини, поки модель працює: Flash Next використовує близько 100 GiB з повним контекстом 256K. Якщо інші моделі утримують потрібну їй пам'ять, вона налаштовується зупиненою, готовою до запуску, щойно ви зупините одну. Модель зупиняється під час виходу з системи; зупиніть її самостійно, коли вам потрібна пам'ять для чогось іншого.

`omarchy models list` показує варіанти та пояснює, чому деякі не підходять. Щоб налаштувати іншу, запустіть `omarchy models use <recipe>`. Сьогодні `qwen3.8-flash-next-gufo` та `qwen3.8-27b-gufo` доступні для машин Strix Halo на 128 GB; 27B займає близько 40 GiB, тож вона залишає місце для іншої роботи. На ноутбуці на 64 GB з Intel's Arc B390, `qwen3.6-35b-a3b-llamacpp` працює приблизно в 30 GiB. Нові рецепти та рекомендації надходять з `omarchy update`, через пакет.

Кожна налаштована вами модель отримує власний рядок на панелі локальних моделей: відтворення, щоб запустити її, пауза, щоб зупинити її та звільнити її пам'ять, і кнопка термінала, щоб відкрити вашого агента на ній. Зверху смуга показує, як пам'ять машини розподілена між самою Omarchy (системою та вашими застосунками), кожною запущеною моделлю та тим, що вільно. Наведіть вказівник на зупинену модель, і смуга покаже, чи вона підходить, або скільки їй бракує. Кілька можуть працювати одночасно, коли вони разом поміщаються в пам'яті; якщо одна не підходить, Omarchy каже, яку запущену модель зупинити. Перетягуйте рядки за їхнім логотипом, щоб змінити їхній порядок, і натисніть Delete на вибраному рядку, щоб видалити модель та її завантаження.

Кожна модель для кодування, яку ви налаштовуєте, також отримує власний запис у лаунчері застосунків, під назвою моделі та з логотипом її виробника, так само як вхід до Claude, Codex або Grok додає один. Він відкриває вашого агента на цій моделі та спочатку запускає модель, якщо вона не працює: термінал показує її завантаження та передає керування агенту, щойно вона запрацює. Видалення моделі видаляє її запис.

Не кожна модель призначена для кодування. Моделі зображень, відео та музики натомість відкриваються у Fantasi, застосунку Omarchy для створення зображень, відео та музики з моделлю, що працює на цій машині, вибраною там або з їхнього рядка на панелі локальних моделей.

Модель продовжує працювати саме так, як її було налаштовано, тож оновлення Omarchy ніколи не перезапускає її під вашими агентами. Коли Omarchy має новіше середовище виконання або новіші ваги для моделі, яку ви налаштували, її рядок показує кнопку оновлення: натисніть її, і модель налаштовується знову у фоновому режимі, завантажуючи лише те, що змінилося, і перезапускається на новій версії. Модель, яка була зупинена, залишається зупиненою. `omarchy models update` робить те саме для кожної моделі з термінала.

З командного рядка `omarchy models start <recipe>` та `omarchy models stop <recipe>` роблять те саме, `omarchy models status` показує кожну модель, а `omarchy agent --local` відкриває останню запущену вами модель у pi, незалежно від того, який ваш агент за замовчуванням. OpenCode та Qwen Code також можуть використовувати локальну модель: `omarchy models harness opencode` або `omarchy models harness qwen` натомість відкриває їх там, а `omarchy models harness pi` повертає назад. pi також перераховує кожну налаштовану вами модель і ті, що на машинах, з якими ви спарилися, у власному виборі моделей, тож простий `pi` також досягає їх. Будь-який клієнт, сумісний з OpenAI, також може підключитися: `status` показує адресу кожної моделі (перша — `http://127.0.0.1:11435/v1`), назва рецепта — це модель, а ключ міститься в `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` видаляє модель і завантаження, які жодна інша модель не використовує.

Сторонні середовища виконання позначені їхнім видавцем. Omarchy запускає кожну модель без доступу до мережі.

### Локальні LLM

Omarchy рекомендує два способи запуску локальних моделей LLM: LM Studio та Ollama. LM Studio надає графічний інтерфейс для пошуку моделей з відкритими вагами, їх встановлення та запуску. Це чудовий спосіб легко почати. Ollama пропонує CLI для подібного. Але якщо ви новачок у локальних моделях, я б почав з LM Studio. Ви можете встановити будь-який з них у _Install > AI_ у меню Omarchy.

### Навички Omarchy

Навички агента допомагають ШІ використовувати конкретні інструменти конкретним способом, і Omarchy постачає сім з них. Навичка omarchy охоплює налаштування системи, як-от налаштування вашої конфігурації Hyprland або регулювання панелі. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app та omarchy-make-game охоплюють створення чогось нового, omarchy-contribute охоплює повідомлення про помилку або надсилання виправлення розробникам, а omarchy-diagnose-crash працює з дампом ядра аварії. Вони символічно пов'язані з каталогами навичок для Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` та кожен `~/.hermes/profiles/*/skills`) і загального розташування `~/.agents/skills`, тож більшість гарнесів підхоплюють їх автоматично. Ваша власна папка навичок з такою самою назвою має перевагу.

Але вам слід ставитися до цих навичок як до експериментальних. Різні моделі використовуватимуть її з різним ефектом. Найкраще спочатку запускати в режимі планування, щоб ви мали уявлення про те, що агент хотів би змінити. А потім будьте готові відкотити зміни або навіть викликати `omarchy reinstall configs`, якщо агент наробить безладу з усього.
