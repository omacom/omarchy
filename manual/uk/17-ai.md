# ШІ

Omarchy містить запускачі для наведених нижче агентів кодування, не обираючи для вас одного за замовчуванням. Запустіть команду, щоб установити її CLI під час першого використання, а потім пройдіть автентифікацію, коли з'явиться запит. Hermes і OpenClaw — винятки: для них нічого не встановлюється через mise, і вибір будь-якого з них налаштовує власну копію, що оновлюється самостійно, як пояснюється нижче в розділі _Настільні застосунки_.

### Установлення й оновлення агентів

За винятком Hermes і OpenClaw, ці агенти використовують ліниве встановлення mise: перший запуск установлює CLI, а наступні використовують його повторно. mise також перевіряє встановлений агент на наявність нового випуску щонайбільше раз на чотири години, безпосередньо перед його запуском або у фоновому режимі при запиті оболонки. Якщо це оновлення не вдалося або ви офлайн, запускається встановлена версія. `omarchy update` оновлює встановлені агенти разом з рештою Omarchy, а `mup` оновлює лише інструменти, керовані mise.

Власний засіб оновлення агента, як-от `claude update`, `codex update` або кнопка оновлення в застосунку, не оновлює встановлення, кероване mise. `codex update` завершується помилкою, а `claude update` може повідомити про успіх, установивши при цьому окрему копію, яку mise не відстежує. Якщо ви надаєте перевагу власному встановлювачу й засобу оновлення агента, додайте його до `disable_tools`; див. [Попередньо встановлені інструменти CLI](18-development-tools.md#preinstalled-cli-tools).

Щоб установити всі налаштовані ліниві інструменти до того, як вони знадобляться, запустіть `mise install --include-lazy`. Сюди входять й інші інструменти CLI Omarchy за замовчуванням, а також агенти. Див. [Попередньо встановлені інструменти CLI](18-development-tools.md#preinstalled-cli-tools) щодо встановлення одного інструмента або використання власного встановлення.

`grok` установлюється через фірмовий пакет `grok` у mise, так само, як `claude` і `codex`. Запустіть `grok` або позначте його зірочкою на панелі агентів. Пропустіть встановлювач `curl | bash` на x.ai. Цей шлях розміщує другу копію в `~/.grok/bin`, додає її на початку `PATH` і перезаписує обгортку Omarchy.

`dsh` відкриває його браузерний UI на `127.0.0.1:3080`, із каталогом запуску як робочим простором за замовчуванням. Його браузерний UI не приймає початкового запиту, тож `omarchy agent prompt` відкриває його із запитом у вашому буфері обміну для вставлення. Omarchy запускає його з попереднім набором дозволів DeepSeek без підтвердження. DeepSeek Harness завантажує журнали сесій до DeepSeek, коли ви використовуєте його офіційний API моделей; вимкніть це в його браузерному UI у розділі _Settings > General > Upload Session Log_. Відгуки, які ви йому надсилаєте, також завантажуються разом із сесією, якщо ви не запустите його з `DSH_TELEMETRY_MODE=DISABLED`.

### Агент за замовчуванням

Оберіть агента за замовчуванням за допомогою зірочки біля агента на панелі агентів, яка заповнена для того, що за замовчуванням, або за допомогою `omarchy default agent <name>`, що також приймає будь-яке середовище виконання, якого немає там у рядку. Якщо агент ще не встановлено, вибір спочатку встановлює його, а також він отримує власний запускач у запускачі застосунків, поруч із Agent. Свіжий Omarchy пропонує налаштувати одного за допомогою одноразового сповіщення, яке відкриває панель агентів.

Вибір Claude також намагається налаштувати його розширення для браузера для Chromium, Chrome, Brave, Brave Origin і Edge. Налаштування розширення стосується всіх користувачів і може запитати ваш системний пароль; скасування або невдале встановлення розширення все одно обирає й запускає Claude. Перезапустіть браузер, увімкніть розширення, якщо з'явиться запит, і увійдіть до Claude, щоб завершити його підключення. Запустіть `/chrome` у Claude, щоб перевірити з'єднання. Firefox і Zen не підтримують це розширення. Якщо Claude уже був вашим агентом за замовчуванням до того, як це налаштування було додано, оберіть його знову, щоб установити розширення.

Після вибору `Super + Shift + Ctrl + A` запускає агента за замовчуванням в окремому вікні терміналу (або викликає засіб вибору, якщо ви ще не обрали). Ви також можете запустити його безпосередньо для завдання за допомогою `omarchy agent prompt "Review this project"`. Freebuff і DeepSeek Harness не приймають початкового запиту, тож натомість вони відкриваються із запитом у вашому буфері обміну для вставлення. Агенти, запущені таким чином, працюють без нагляду у відповідних режимах без зупинок для запитань, тож будьте готові до того, що вони справді щось робитимуть! MiniMax Code не має такого режиму для своїх інтерактивних сесій, тож він запитує дозволи, як зазвичай. А оскільки агенти відмовляються запам'ятовувати довіру до вашого домашнього каталогу, запуски з `$HOME` натомість стартують у `~/Work`.

Існують також ярлики терміналу: `a` запускає агента за замовчуванням вбудовано в поточному терміналі, а `c`, `cx`, `cy` і `ca` запускають OpenCode, Claude Code, Codex і Antigravity безпосередньо (знову ж у їхніх режимах автоматичного підтвердження). Зміни теми також синхронізуються з агентами: Claude Code, Pi, OpenCode і Hermes (щойно Omarchy його встановив) — усі слідують за вами, коли ви змінюєте тему Omarchy.

### Інструкції для ваших агентів

Персональні правила для кожного агента розміщуються в `~/.agents/AGENTS.md`, поруч зі спільними навичками в `~/.agents/skills`. Відкрийте його за допомогою піктограми документа біля + на панелі агентів або `omarchy agent instructions --edit`, що також пов'язує його з кожним середовищем виконання, яке зберігає власний глобальний файл: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, файл Copilot `~/.copilot/copilot-instructions.md` і так далі. Crush і Amp читають посилання `~/.config/AGENTS.md`, а omp, Kimi і DeepSeek Harness читають безпосередньо `~/.agents/AGENTS.md`. Вибір агента за замовчуванням також пов'язує його. Файл інструкцій, який у вас уже був, стає спільним, якщо його ще не було; інакше він зберігається поруч із посиланням як `.bak`. Запустіть `omarchy agent instructions`, щоб повторно пов'язати після встановлення іншого агента.

### Панель агентів

Верхня панель має піктограму агентів. Перш ніж ви налаштуєте агента, його панель пропонує три способи почати: увійти до підписки Claude, Codex, Grok, Gemini, Muse, Cursor або Copilot, або в розділі More — до плану кодування OpenCode Go, MiniMax, Synthetic або Z.ai; платити за фактом використання з Fireworks, OpenCode Zen and Go, OpenRouter або в розділі More — DeepSeek чи будь-яким іншим постачальником, до якого входить OpenCode, усі вони працюють в OpenCode; або запустити найкращу модель для вашого комп'ютера, коли така йому підходить. Перший варіант, який ви завершите, стане вашим агентом за замовчуванням, а + на панелі пізніше пропонує ті самі три. Після цього панель розміщує кожну підписку на одній сторінці: кожного агента й обліковий запис із його планом, індикатор для кожного з його лімітів 5-годинної сесії та тижневого ліміту з часом до його скидання (наведіть курсор, щоб побачити точний відсоток) або залишок передплаченого балансу, під рядком, який циклічно показує, що ви використали серед усіх них, як-от токени цього тижня та вашу найуживанішу модель. У розділі _Make something cool_ вона пропонує початкові запити для нової теми, плагіна, застосунку чи гри, які передають завдання вашому агенту за замовчуванням. Застосунки створюються так само, як власні Hype, Monologue і Omacut від Omarchy, на C++ і Qt Quick, дотримуючись навички агента omarchy-make-app, а потрібні їм компілятор і компоненти Qt постачаються встановленими. Ігри — це одна сторінка three.js у `~/Games/vibes`, що дотримується навички агента omarchy-make-game, і всі вони відкриваються з одного запускача Game Vibes у поточній темі; вони завантажують three.js з інтернету, тож для запуску їм потрібне з'єднання. Claude Code, Codex, Grok, Kimi, Cursor та його ліміт Grok Bot, GitHub Copilot, Muse, Gemini (через Antigravity) і Devin підтримуються з коробки з їхніми лімітами, Kimchi — з його планом, передплаченими кредитами та бюджетами витрат, а Hermes, Mistral Vibe і Qwen Code показують свої сесії й токени, щойно ви ними скористаєтеся. Плани й ключі постачальників, які ви використовуєте через pi, omp або opencode, також відображаються: OpenCode Zen and Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan і Synthetic з їхніми лімітами; OpenRouter і DeepSeek з їхніми передплаченими балансами; Fireworks з його витратами за останні 30 днів. Моделі кодування, які ви запускаєте на власному обладнанні, отримують власні рядки, а їхні токени також зараховуються до загальних підсумків, як описано в розділі [Локальні моделі](#local-models). Кожен агент підраховується один раз, за тим, хто виставляє за нього рахунок, незалежно від того, через скільки середовищ виконання ви ним керуєте.

Клацніть лівою кнопкою миші піктограму панелі або натисніть `Super + Ctrl + X`, щоб відкрити панель, клацніть правою кнопкою, щоб запустити агента за замовчуванням, і клацніть середньою кнопкою, щоб оновити. Записи про використання, що стоять за нею, перегенеровуються кожні 15 хвилин за допомогою `omarchy agent usage update`, а панель навіть може об'єднувати використання з інших ваших машин через синхронізовану папку. Див. README у `$OMARCHY_PATH/shell/plugins/agents/` щодо повних налаштувань.

### Кілька підписок

Якщо ви платите за більше ніж один план Claude, Codex або Grok — наприклад, особистий Max і робочий — Omarchy може тримати їх усі в стані входу й перемикатися між ними. Додайте підписку за допомогою + на панелі агентів, яка проведе вас через це просто там, або за допомогою `omarchy agent account add claude Work` (або `codex`, або `grok`). Той самий + і команда входять до Gemini (`gemini`) і OpenCode (`opencode`) та зберігають ключ API Fireworks (`fireworks`) або OpenRouter (`openrouter`) в OpenCode; команда також входить до Copilot (`copilot`), Cursor (`cursor`) і Muse (`muse`). Вони зберігають по одному входу кожен. Вона встановлює CLI, якщо його бракує. Перший обліковий запис для постачальника входить через ваш звичайний браузер, саме там, де CLI завжди його шукає. Кожен наступний входить через приватне вікно, тож обліковий запис, до якого ваш браузер уже увійшов, не буде підхоплено помилково; увійдіть там як обліковий запис, який додаєте, і спочатку закрийте будь-яке приватне вікно, яке у вас уже відкрито. Ніколи не виходьте з CLI для цього: вихід скасовує збережений вхід, і цей обліковий запис доведеться додавати знову.

Щоб скопіювати ваші входи за підпискою на іншу машину Omarchy через SSH, запустіть `omarchy agent account copy user@laptop`. Відправник надає тимчасового отримувача, коли на пункті призначення його не встановлено, тож старіші машини Omarchy можуть отримувати облікові записи без оновлення. Установлені отримувачі мають пріоритет. Це копіює всі підписки Claude, Codex і Grok; додайте імена постачальників, щоб обрати їх, як у `omarchy agent account copy laptop claude`. Імена облікових записів і ідентифікатори команд відповідають джерелу, включно з обліковими записами, уже наявними на пункті призначення. Незв'язаним обліковим записам на пункті призначення присвоюється числовий суфікс, якщо їхні імена конфліктують, а налаштування, навички, плагіни та історія розмов залишаються локальними для кожної машини.

Існуючі облікові дані на пункті призначення зберігаються. Обліковий запис джерела, який уже увійшов там, має синхронізоване ім'я без заміни його облікових даних; інші облікові записи додаються поруч із ним. Щоб замінити збережені облікові дані для відповідних облікових записів, скористайтеся `omarchy agent account copy --replace laptop claude` після завершення сесій цього облікового запису на пункті призначення. Свіжий пункт призначення також отримує активний обліковий запис джерела та його вподобання щодо перемикання; усталений пункт призначення зберігає власні.

Облікові дані передаються через SSH і зберігаються в приватних файлах на пункті призначення, тож копіюйте лише на машини, яким довіряєте. Це одноразове копіювання, а не постійна синхронізація. Токени оновлення Codex можуть ротуватися іншою машиною, залишаючи скопійований вхід таким, що потребує поновлення; окремі входи залишаються найнадійнішим вибором для одночасного використання на кількох машинах. Див. [Посібник з автентифікації облікових записів Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Один обліковий запис на постачальника активний, і кожна нова сесія починається як він: `cx`, `cy`, звичайний `claude`, `codex` або `grok`, будь-що, запущене через `omarchy agent`, а також скрипти чи редактори, які знаходять CLI на `PATH`. Перемикайтеся за допомогою `omarchy agent account use work` (і назад за допомогою `omarchy agent account use main`) або на панелі, натиснувши номер облікового запису, а потім `Enter` (або клацнувши його зірочку). Запущені сесії Claude також перемикаються, починаючи з їхнього наступного повідомлення: кожна сесія Claude працює в `~/.claude`, який завжди містить вхід активного облікового запису. Сесія Claude, запущена в папці власного облікового запису старішим Omarchy, тримає цей вхід до завершення, тож перемикання називає ці сесії й завершується саме, щойно вони зникнуть. Запущені сесії Codex і Grok залишаються на обліковому записі, з яким вони почалися. Історія розмов, налаштування, навички та плагіни спільні для всіх облікових записів, тож `claude --continue` у тій самій папці продовжує з того місця, де ви зупинилися, на новому обліковому записі.

З більш ніж одним обліковим записом панель показує ліміти кожного облікового запису поруч, із заповненою зірочкою на тому, що використовується. Omarchy сповіщає вас, коли активний обліковий запис перевищує 95% ліміту, і клацання сповіщення перемикає на обліковий запис із найбільшим запасом. Він ніколи не перемикається сам. Змініть поріг за допомогою `omarchy agent account threshold 90`. Якщо кожен обліковий запис перевищує поріг, ви почуєте про це один раз, разом із тим, який обліковий запис звільниться першим. Поки активний обліковий запис перебуває в межах 15 пунктів від свого порогу (80% за замовчуванням), його ліміти перевіряються кожні три хвилини, а не кожні 15.

`omarchy agent account list` показує кожен обліковий запис і його останні ліміти, `omarchy agent account remove work` забуває один, а `omarchy agent account rename primary Hey` перейменовує один (або клацніть ім'я облікового запису на панелі). Ці команди працюють з обліковими записами вашого агента за замовчуванням; щоб дістатися до іншого постачальника, спочатку назвіть його, як у `omarchy agent account use codex side`. Вхід, який у вас уже був у `~/.claude` або `~/.codex`, є обліковим записом _Main_. Обліковий запис Codex залишається там, де він є; обліковий запис Claude чекає у власній папці, поки активний інший обліковий запис. Обліковий запис, залишений невикористаним понад приблизно вісім годин, може показувати _Sign-in required_; клацніть його, щоб знову увійти до цього облікового запису просто на панелі, або перемкніться на нього й почніть сесію, що оновить вхід самостійно. Сервери MCP, які ви додаєте за допомогою `claude mcp add`, досягають кожного облікового запису Claude, оскільки всі вони працюють у `~/.claude`; для Codex і Grok сервери, які у вас були, коли обліковий запис було додано, переходять до нього, але пізніші досягають лише того облікового запису, в якому ви їх додали. Claude Desktop зберігає власний вхід, а інструменти Codex або Grok, налаштовані з абсолютним шляхом до бінарного файлу CLI, не слідують за перемиканням. Явна змінна `CLAUDE_CONFIG_DIR`, `CODEX_HOME` або `GROK_HOME` має пріоритет над обраним обліковим записом.

### Діагностика аварійних завершень

Omarchy стежить за systemd-coredump на предмет аварійних завершень процесів. Щойно ви оберете агента за замовчуванням, будь-яка ваша програма, що створює дамп ядра, викликає сповіщення "Process crashed" — клацніть його, і аварія передається вашому агенту за замовчуванням разом із навичкою omarchy-diagnose-crash від Omarchy, яка проводить агента через встановлення фактів із дампа ядра та вирішення, чи варто повідомляти про аварію розробникам вище за ланцюгом. Ви також можете запустити її вручну для будь-якого PID з `coredumpctl list` за допомогою `omarchy agent crash <pid>`.

Спостереження ввімкнено за замовчуванням. Вимкніть його в розділі _Trigger > Toggle > Crash Capture Off_ (або за допомогою `omarchy toggle crash-capture`), і сповіщення припиняться; `omarchy agent crash <pid>` усе одно працює вручну.

Аварії також можна заглушити по одній програмі, що діагностика й пропонує вам наприкінці. `omarchy crash mute hyprland` припиняє сповіщення лише для цієї програми, `omarchy crash mute hyprland off` повертає їх, а `omarchy crash mute` сам по собі перелічує те, що ви заглушили. Він приймає шлях бінарного файлу так само охоче, як і його ім'я, тож `omarchy crash mute /usr/bin/hyprland` робить те саме. Візьміть ім'я з пробілом у лапки, як у `omarchy crash mute 'Some App'`. Все інше й далі сповіщає, а заглушена програма й далі аварійно завершується — це ховає нагадування, а не виправляє нічого.

### Настільні застосунки

Меню _Install > AI_ також містить кілька графічних застосунків ШІ: Amp Desktop, Antigravity Desktop, настільний застосунок ChatGPT, настільний застосунок Claude (бета-версія Anthropic для Linux, із вкладками Chat, Cowork і Claude Code), Grok Bot для спілкування з моделями xAI, Herdr Desktop, Hermes Desktop, OpenClaw, настільний застосунок Perplexity і T3 Code. Grok Bot — це настільний застосунок для чату. Агент кодування — це команда `grok`.

Hermes Desktop — той, про який варто знати, бо на машині є один Hermes, і він належить застосунку: Hermes установлюється лише через застосунок, і команда `hermes`, яку запускає агент за замовчуванням, належить застосунку. Вибір Hermes як агента за замовчуванням установлює те саме, що й пункт _Install > AI_: пакет і середовище виконання Hermes у `~/.hermes`, налаштоване власним встановлювачем Hermes, що вперше займає кілька хвилин. Це середовище виконання — єдиний Hermes, який використовують термінальна команда `hermes`, агент за замовчуванням і застосунок, і воно оновлюється самостійно за допомогою `hermes update`, а не чекає на випуск Omarchy. Установлення його також передає Hermes тему Omarchy як скін під назвою `omarchy`, за яким кожна поверхня Hermes слідує, коли ви змінюєте теми; оберіть інший у налаштуваннях Appearance Hermes або за допомогою `/skin`, якщо ви надаєте перевагу, щоб цього не було, і Omarchy залишить цей вибір у спокої. Видалення застосунку в розділі _Remove > AI_ спочатку закриває Hermes, включно зі шлюзом, забирає це середовище виконання з собою і зберігає ваші чати, спогади та навички, які Hermes написав для себе, якщо ви не скажете інакше: він запитує, за замовчуванням відповідаючи ні, чи мають також піти ці дані та ваші налаштування з'єднання.

Настільний досвід OpenClaw — це його Control UI, який відкривається як вебзастосунок, підкріплений власним локальним шлюзом. OpenClaw живе в `~/.openclaw` і оновлюється самостійно: скористайтеся кнопкою "Update Gateway" у Control UI або запустіть `openclaw update`, і шлюз перезапуститься на новій версії. Omarchy обирає лише випуск, з якого починається свіже встановлення. OpenClaw також може бути вашим агентом за замовчуванням: вибір його за допомогою `omarchy default agent openclaw` налаштовує ту саму копію в `~/.openclaw`, а агент відкриває термінальний UI OpenClaw, підключений до його шлюзу. Видалення OpenClaw у розділі _Remove > AI_ забирає з собою службу шлюзу та застосунок, а потім запитує, чи має також піти `~/.openclaw`, оскільки там зберігаються ваші чати й облікові дані поруч із самим OpenClaw і середовищами виконання плагінів, які він завантажує; за замовчуванням він зберігається, і повторне встановлення OpenClaw підхопить його назад.

Herdr Desktop — це настільний застосунок [Herdr](https://herdr.dev): простори, вкладки й панелі терміналів та агентів кодування, які продовжують працювати в його ядрі, коли ви закриваєте вікно. Він походить із власного встановлювача Herdr, а не з пакета, тож живе в `~/.local/share/herdr-app`, приносить своє ядро в `~/.local/bin/herdr-core`, коли у вас його ще немає, і оновлює обидва самостійно. Він розташований поруч із командою `herdr`, яку Omarchy постачає на `Super + Ctrl + Return`, а не замінює її, і отримує прямі клавіші цієї команди: `Alt + Return` і `Alt + Shift + Return` розділяють панель вниз або праворуч, `Alt + Escape` закриває її, `Ctrl + Alt + Arrow` переміщує між панелями, `Alt + 1..9` і `Alt + Left/Right` обирають вкладку, а `Alt + Up/Down` переміщують між просторами. `Ctrl + 1..9` обирає простір, а `Alt + Shift + Up/Down` крокує між агентами. Префіксні клавіші `Ctrl + Space` залишаються лише для терміналу, оскільки застосунок не може утримувати звичайну клавішу Ctrl для послідовності. Omarchy записує їх до `~/.config/herdr-app/keys.json`, а `omarchy-refresh-herdr-app` повертає їх назад. Установлення його обирає тему Omarchy для Herdr, яка відтоді слідує за вашою темою Omarchy. Herdr зберігає одну тему для світлого режиму й одну для темного, тож після перемикання між темною та світлою темою Omarchy оберіть Omarchy у засобі вибору теми Herdr ще раз для іншого режиму.

T3 Code запускається з його офіційного випуску AppImage у `~/.local/share/t3code`, а не з пакета, тож він оновлюється самостійно. Установлення його запитує, чи починати на каналі Stable чи Nightly; перемкніть пізніше в налаштуваннях T3 Code. Ваші потоки й налаштування живуть у `~/.t3`, і видалення T3 Code у розділі _Remove > AI_ забирає їх із собою.

### Локальні моделі

Запускайте відкриту модель на власній машині для своїх агентів кодування. Ваші запити й код залишаються на машині; нічого з надісланого до моделі не покидає її. Почніть із:

```bash
omarchy models use best text
```

Це налаштовує найкращу текстову модель для цієї машини, ту, якою користуються ваші агенти. Моделі зображень, відео та музики мають власну найкращу: `omarchy models use best image`, `video` або `music`. Запустіть `omarchy models use best`, щоб побачити вибір для цієї машини для кожного виду.

Або оберіть + на панелі агентів: у розділі _Use a local model_ вона перелічує кожну модель кодування, яка підходить цій машині, рекомендовану першою. Podman, який запускає моделі, постачається з Omarchy, як і інструментарій контейнерів NVIDIA на машині NVIDIA, що надає їм GPU; якщо чогось із цього бракує, перше налаштування встановлює це. Потім Omarchy обирає рекомендовану модель для цієї машини, завантажує її та запускає. Очікуйте завантаження на десятки GB і використання більшої частини пам'яті машини, поки модель працює: Flash Next використовує близько 100 GiB з її повним контекстом 256K. Якщо інші моделі утримують потрібну їй пам'ять, вона налаштовується зупиненою, готовою до запуску, щойно ви зупините одну. Модель зупиняється під час виходу; зупиніть її самі, коли вам потрібна пам'ять для чогось іншого.

`omarchy models list` показує варіанти й пояснює, чому деякі не підходять. Щоб налаштувати іншу, запустіть `omarchy models use <recipe>`. Сьогодні `qwen3.8-flash-next-gufo` і `qwen3.8-27b-gufo` доступні для машин Strix Halo на 128 GB; 27B займає близько 40 GiB, тож вона залишає місце для іншої роботи. На ноутбуці на 64 GB з Arc B390 від Intel `qwen3.6-35b-a3b-llamacpp` працює приблизно в 30 GiB. Нові рецепти й рекомендації надходять з `omarchy update`, через пакет.

Модель кодування, яку ви додаєте, отримує власний рядок на панелі агентів, поруч із вашими підписками: відтворення, щоб запустити її, пауза, щоб зупинити й звільнити її пам'ять, позначка Tailscale, щоб поділитися нею з іншими машинами у вашому tailnet, поки вона працює, і кнопка терміналу, щоб відкрити вашого агента на ній. Її рядок показує завантаження, завантаження в пам'ять або зупинку під час процесу й повідомляє, коли не вистачає вільної пам'яті для її запуску, або посилається на її журнали, коли вона зупинилася з помилкою. Кілька можуть працювати одночасно, коли вони разом поміщаються в пам'яті. Натисніть Delete на обраному рядку, щоб видалити модель із цієї машини, разом із завантаженням; + може налаштувати її знову. Модель кодування, налаштована з терміналу, чекає під +, доки ви її не додасте, так само як моделі, які запускає машина, з якою ви спарилися (`omarchy models pair <host>`).

Кожна модель кодування, яку ви налаштовуєте, також отримує власний запис у запускачі застосунків, під назвою моделі та з логотипом її виробника, так само, як вхід до Claude, Codex або Grok додає один. Він відкриває вашого агента на цій моделі й спочатку запускає модель, якщо вона не працює: термінал показує її завантаження в пам'ять і передає керування агенту, щойно вона підніметься. Видалення моделі видаляє її запис.

Не кожна модель призначена для кодування. Натомість моделі зображень, відео та музики відкриваються у Fantasi, застосунку Omarchy для створення зображень, відео та музики з моделлю, що працює на цій машині, і керуються там або за допомогою `omarchy models`.

Модель продовжує працювати саме так, як її було налаштовано, тож оновлення Omarchy ніколи не перезапускає жодну під вашими агентами. Коли Omarchy має новіше середовище виконання або новіші ваги для моделі, яку ви налаштували, її рядок показує кнопку оновлення: натисніть її, і модель налаштовується знову у фоновому режимі, завантажуючи лише те, що змінилося, і перезапускається на новій версії. Модель, яку було зупинено, залишається зупиненою. `omarchy models update` робить те саме для кожної моделі з терміналу.

З командного рядка `omarchy models start <recipe>` і `omarchy models stop <recipe>` роблять те саме, `omarchy models status` показує кожну модель, а `omarchy agent --local-model <recipe>` відкриває цю модель у pi, незалежно від вашого агента за замовчуванням. Щоб зробити вашу локальну модель тим, що відкривають гаряча клавіша агента, консоль Quake і _Make something_, запустіть `omarchy default agent local` або позначте зірочкою запущену модель на панелі агентів. pi також перелічує кожну модель, яку ви налаштували, і ті, що на машинах, з якими ви спарилися, у власному засобі вибору моделей, тож звичайний `pi` також до них дістається. Будь-який клієнт, сумісний з OpenAI, також може підключитися: `status` показує адресу кожної моделі (перша — `http://127.0.0.1:11435/v1`), назва рецепта є моделлю, а ключ міститься в `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` видаляє модель і завантаження, які не використовує жодна інша модель.

Середовища виконання третіх сторін позначаються їхнім видавцем. Omarchy запускає кожну модель без доступу до мережі.

### Локальні LLM

Omarchy рекомендує два способи запуску локальних моделей LLM: LM Studio та Ollama. LM Studio надає графічний інтерфейс для пошуку моделей з відкритими вагами, їх установлення й запуску. Це чудовий спосіб легко почати. Ollama пропонує CLI для подібного. Але якщо ви новачок у локальних моделях, я б почав із LM Studio. Ви можете встановити будь-який із них у розділі _Install > AI_ у меню Omarchy.

### Навички Omarchy

Навички агента допомагають ШІ використовувати конкретні інструменти конкретним способом, і Omarchy постачає сім із них. Навичка omarchy охоплює налаштування системи, як-от тонке налаштування вашої конфігурації Hyprland або регулювання панелі. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app і omarchy-make-game охоплюють створення чогось нового, omarchy-contribute охоплює повідомлення про помилку або надсилання виправлення розробникам вище за ланцюгом, а omarchy-diagnose-crash працює з дампом ядра аварії. Вони пов'язані символічними посиланнями до каталогів навичок для Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` і кожен `~/.hermes/profiles/*/skills`) і загального розташування `~/.agents/skills`, тож більшість середовищ виконання підхоплюють їх автоматично. Папка навичок вашого авторства з тією самою назвою має пріоритет.

Але ви маєте ставитися до цих навичок як до експериментальних. Різні моделі використовуватимуть їх із різним ефектом. Найкраще спочатку запускати в режимі планування, щоб мати уявлення про те, що агент хотів би змінити. А потім будьте готові відкотити зміни або навіть викликати `omarchy reinstall configs`, якщо агент усе зіпсує.
