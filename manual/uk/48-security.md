# Безпека

Omarchy ставиться до безпеки вкрай серйозно. Це має бути операційна система, яку можна використовувати для _Справжньої Роботи_ у _Справжньому Світі_. Де втрата ноутбука не може призвести до надзвичайної ситуації з безпекою. Ось що ми робимо:

1. *Повне шифрування диска ввімкнено за замовчуванням*: Це найважливіший крок для забезпечення фізичного захисту ваших даних. Якщо ваш комп’ютер загублено або вкрадено, дані повністю зашифровані за допомогою стандартного LUKS (Linux Unified Key Setup). Інсталятор дозволяє відмовитися від цього для одноразових машин (див. [Початок роботи](02-getting-started.md)); встановлення без шифрування не має жодного такого захисту, і будь-хто, хто тримає диск, може його прочитати.
2. *Фаєрвол увімкнено за замовчуванням*: Весь вхідний трафік блокується за замовчуванням, за кількома винятками: порт 53317 для [LocalSend](https://localsend.org/); DNS-запити до власного резолвера комп’ютера за адресою Docker bridge (172.17.0.1), що приймаються з діапазонів приватних адрес, які Docker надає своїм контейнерам; і multicast DNS (порт 5353), який дозволяє принтерам та іншим пристроям у вашій мережі знаходити одне одного, а також оголошує там ім’я вашого комп’ютера. Понад це, фаєрвол зберігає стандартні дозволи UFW для ping, отримання адреси від вашого маршрутизатора (DHCP) та виявлення UPnP. Навіть ssh вимкнено, доки ви не ввімкнете його через _Setup > Security > SSHD_, що відкриває порт 22 (з обмеженням частоти проти brute force) як частину налаштування. Ми навіть обмежуємо доступ до Docker за допомогою налаштування [ufw-docker](https://github.com/chaifeng/ufw-docker), щоб запобігти випадковому відкриттю ваших контейнерів для світу.
3. *Arch завжди має найновіші оновлення*: Arch, базовий дистрибутив, на якому побудовано Omarchy, є rolling distribution. Це означає, що будь-яка вразливість безпеки, яку виявлено й виправлено в будь-якому пакеті, швидко стає доступною для встановлення за допомогою `omarchy-update`. Так ви завжди використовуєте найновіші, найбезпечніші версії всього.
4. *Omarchy підтримує власні пакети та дзеркало*: За замовчуванням Omarchy покладається лише на пакети з власних репозиторіїв Arch core/extra/multilib та власного Omarchy Package Repository. Ви можете встановлювати програмне забезпечення безпосередньо з AUR, але базове встановлення цього не робить — лише кілька необов’язкових встановлень, як-от сторонні браузери, тягнуться з AUR.
5. *Cloudflare захищає нас від DDoS*: Інфраструктура розповсюдження Omarchy — ISO, пакети Omarchy, дзеркало Arch — захищена грізним щитом Cloudflare від DDoS і розміщена на їхній CDN. Це забезпечує чудову доступність.

## Зміна ваших паролів

У зашифрованому встановленні у вас два паролі: один розблоковує диск під час завантаження, а інший ви використовуєте для входу та `sudo`. Setup робить їх однаковими. Обидва можна змінити в розділі _Update > Password_ у меню Omarchy — _Drive Encryption_ для першого, _User_ для другого. Для зміни пароля диска спочатку потрібно ввести поточний, тож тримайте його під рукою. Якщо зміну перервано, запустіть _Drive Encryption_ знову: він запитає пароль, який розблоковує диск зараз, і завершить зміну.

## Передача машини, якою ви вже користувалися

Якщо ви передаєте свою машину комусь іншому, вам не потрібно її перевстановлювати. Запустіть _Setup > Reset Computer_ у меню Omarchy, введіть `reset` для підтвердження та перезавантажтеся. Це зітре кожен обліковий запис користувача та все в `/home`, відкине всі пакети й системні зміни, які ви зробили після встановлення, і очистить ідентичність машини — мережеві підключення, host keys і все. Після перезавантаження з’явиться майстер налаштування з першого завантаження, готовий для нового власника ввести власне ім’я, пароль і пароль шифрування.

Це працює шляхом відновлення базового знімка, який робить інсталятор, тому доступно лише на машинах, встановлених з ISO Omarchy. А на диску без шифрування скидання є видаленням, а не безпечним стиранням, тож якщо дані були чутливими, натомість виконайте чисте встановлення.

## sudo без пароля

Іноді ви хочете, щоб `sudo` припинив запитувати, найчастіше коли агент ШІ виконує для вас довгий відрізок системної роботи. _Setup > Security > Passwordless Sudo_ запитує, на який час дозволити доступ: **15 хвилин**, **1 година**, **1 день** або **Назавжди**. Поки доступ активний, поруч з іншими індикаторами на панелі меню з’являється червоний значок попередження. Клацніть його або запустіть команду знову, щоб вимкнути доступ. Ви також можете передати власну кількість хвилин (від 1 до 1440) за допомогою `omarchy-sudo-passwordless 30` або використати `omarchy-sudo-passwordless permanent`.

Доступ із обмеженням у часі закінчується автоматично, зокрема одразу після відновлення з призупинення, яке перетнуло крайній термін. Перезавантаження комп’ютера завершує його достроково. Постійний доступ переживає перезавантаження та залишається ввімкненим, доки ви його не вимкнете.

Оновлення або видалення пакета налаштувань Omarchy завершує будь-який тимчасовий дозвіл до зміни підтримки його закінчення. Якщо команда повідомляє про помилку авторизації або очищення, усуньте її, перш ніж намагатися ввімкнути інший дозвіл; помилка не означає, що доступ без пароля неактивний.

Дивіться на це тверезо: поки це ввімкнено, все, що працює від вашого користувача, може робити будь-що як root без запиту. У цьому весь сенс, і в цьому ж весь ризик.

## Ключі підпису

Публічний ключ для всіх підписів ISO та пакетів репозиторію Omarchy — `40DFB630FF42BCFFB047046CF0134EE680CAC571` ([перевірити на openpgp.org](https://keys.openpgp.org/search?q=pkgs%40omarchy.org)). Пакет `omarchy/omarchy-keyring` також містить його та використовуватиметься для безшовного розгортання будь-яких потенційних оновлень.

Ви можете знайти підпис для будь-якого випуску ISO, додавши `.sig` до його URL, наприклад `https://iso.omarchy.org/omarchy-x.x.x.iso.sig`.
