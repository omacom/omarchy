# Dotfiles

Omarchy насамперед налаштовується через так звані dotfiles, що живуть у `~/.config`. Вважайте їх своїми файлами для ваших змін. Файли, що живуть у `/usr/share/omarchy`, належать самій Omarchy, і вам не варто з ними возитися. Якщо вам потрібно змінити щось у `/usr/share/omarchy`, натомість слід перевизначити значення в `~/.config`.

Ключові конфіги можна редагувати просто з меню Omarchy (`Super + Space`), наприклад _Setup > Keyboard > Keybindings_, _Setup > Input_ і _Setup > Config > [file]_. Коли ви робите це в такий спосіб, будь-який процес, який потребує перезапуску після редагування конфігів, автоматично перезапуститься, щойно ви вийдете з редактора (Neovim за замовчуванням — `:wq`, пам’ятаєте! — але ви можете змінити це через _Setup > Defaults > Editor_).

Ось список ключових файлів у `~/.config` і того, чим вони керують:

| File                  | Purpose              |
| ----------------------- | --------------------- |
| `~/.config/hypr/hyprland.lua` | Головний конфіг Hyprland. Завантажує налаштування Omarchy за замовчуванням плюс ваші файли перевизначень нижче. [Дізнайтеся більше про конфіги Hyprland](https://wiki.hypr.land/Configuring/).  |
| `~/.config/hypr/bindings.lua` | Ваші власні прив’язки клавіш і перевизначення значень за замовчуванням. |
| `~/.config/hypr/monitors.lua` | Налаштування моніторів, яких не охоплює панель моніторів, як-от поворот, додаткові режими або залишення монітора вимкненим. |
| `~/.config/hypr/input.lua` | Керує розкладкою клавіатури, мишею та налаштуваннями трекпада. |
| `~/.config/hypr/looknfeel.lua` | Керує проміжками, рамками, анімаціями та рештою зовнішнього вигляду. |
| `~/.config/hypr/autostart.lua` | Керує додатковими процесами, що запускаються разом із сеансом. |
| `~/.config/omarchy/shell.json` | Керує оболонкою Omarchy: розташуванням панелі, компонуванням і віджетами, а також часом заставки, блокування та простою. |
| `~/.config/foot/foot.ini` | Керує вашим терміналом (foot є типовим). |
| `~/.XCompose` | Визначає ваші емодзі для швидкого доступу та автодоповнення імені/електронної пошти. Після внесення змін обов’язково запустіть `omarchy-restart-xcompose`. |

Якщо ви зрештою внесете багато змін, щоб налаштувати власну систему під себе, варто зробити резервну копію всіх цих dotfiles. [Stow — чудовий спосіб це зробити](https://www.youtube.com/watch?v=NoFiYOqnC4o).

### Запуск власних застосунків разом із сеансом

Якщо ви хочете, щоб щось запускалося щоразу, коли ви входите в систему, — демон синхронізації, застосунок чату, ваш власний скрипт — помістіть це в `~/.config/hypr/autostart.lua`:

```lua
o.launch_on_start("my-service")
```

Це запускає команду як частину сеансу, тож вона належним чином очищується, коли ви знову виходите із системи.

### Запуск скриптів за системними подіями

Omarchy запускає хуки в кілька моментів, і ви можете навісити на них власні скрипти. Вони живуть у `~/.config/omarchy/hooks/<event>.d/`, по одному каталогу для кожної події, і кожен файл там, що не закінчується на `.sample`, запускається через bash, коли відбувається подія:

| Event | When it runs |
| ----- | ------------ |
| `post-boot` | Одразу після запуску робочого столу |
| `post-update` | Ближче до кінця `omarchy update`, після пакетів, міграцій і перезапусків служб, перед оновленням інструментів mise |
| `pre-refresh-pacman` | Після того, як `omarchy refresh pacman` повторно синхронізує конфіг пакетів, перед оновленням пакетів; перемикання каналу запускає його під час того самого кроку оновлення |
| `theme-set` | Після зміни теми (назва теми в `$1`) |
| `font-set` | Після зміни шрифту (назва шрифту в `$1`) |
| `battery-low` | Коли заряд батареї стає низьким (відсоток у `$1`) |

Хук `pre-refresh-pacman` — це місце, куди належать користувацькі репозиторії або рядки `IgnorePkg`, оскільки він запускається перед пакетною транзакцією. Обидва запускаються від вашого користувача. `post-update` запускається, поки авторизація sudo для `omarchy update` ще свіжа, тож хук, який використовує `sudo`, не питатиме ваш пароль знову; `pre-refresh-pacman` запускається одразу після того, як `omarchy refresh pacman` сама використала sudo.

Кожен із цих каталогів уже містить файл `.sample`, що показує форму хука, — приберіть `.sample` з назви, щоб він запрацював. Щоб встановити скрипт, написаний вами деінде, скористайтеся `omarchy hook install post-boot ~/my-hook`, що копіює його туди та робить виконуваним.

### Додавання власних пунктів меню

Меню Omarchy (`Super + Space`) можна розширити власними рядками, відредагувавши `~/.config/omarchy/extensions/omarchy-menu.jsonc`. Пункти ключуються крапковим id, і саме id розміщує їх у дереві, тож `personal` з’являється в кореневому меню, а `personal.notes` з’являється всередині нього:

```jsonc
"personal": {"icon":"","label":"Personal"},
"personal.notes": {"icon":"󰎞","label":"Notes","action":"omarchy-launch-editor ~/notes"},
```

Використайте наявний id повторно — і ви перевизначите цей рядок замість додавання нового. Файл постачається з усіма доступними полями, задокументованими у вигляді коментарів.

### Додавання власних експортів оболонки, функцій та аліасів

Omarchy постачається з купою ергономічних аліасів і корисних функцій, але дуже часто хочеться додати власні. І аліаси, і функції, і експорти слід додавати в `~/.bashrc`. Цей файл не буде перезаписано під час оновлень. Якщо ви хочете змінити будь-які значення Omarchy за замовчуванням, ви також можете безпечно додати їх сюди.

### Встановлення змінних середовища для робочого столу

Експорти сеансу робочого столу належать до `~/.config/uwsm/env.d/`. Ці файли запускаються перед запуском вашого робочого столу, тож помилка оболонки може відправити вас назад на екран входу. Тримайте робочий термінал відкритим під час їх редагування. Щоб вимкнути перевизначення, перемістіть його з `env.d`. Дивіться [відновлення входу](45-troubleshooting.md#my-password-is-accepted-but-i-return-to-the-login-screen), якщо зміна заважає входу.

### Зміна внутрішніх файлів Omarchy

Слухайте, це ваш комп’ютер. Ви можете робити з ним усе, що захочете, але я порадив би не вносити зміни безпосередньо у файли в `/usr/share/omarchy`. Вони належать пакету Omarchy у pacman, тож ваші зміни просто буде перезаписано під час наступного оновлення. Натомість вам краще просто перевизначити будь-які значення за замовчуванням, які вам не подобаються, у папці `~/.config/*`.

У такий спосіб ви можете змінити майже все, як-от прив’язки клавіш за замовчуванням. Просто відредагуйте `~/.config/hypr/bindings.lua`, щоб, скажімо, замінити [Obsidian](https://obsidian.md/) на [Joplin](https://joplinapp.org/) (встановіть за допомогою `omarchy-pkg-add joplin-bin`):

```lua
o.rebind("SUPER + SHIFT + O", "Joplin", "joplin-desktop")
```

`o.rebind` видаляє наявну прив’язку перед додаванням її заміни. Він приймає ті самі аргументи, що й `o.bind`, включно з помічниками запуску та параметрами прив’язки. Використовуйте `o.bind`, щоб додати прив’язку, або `hl.unbind`, щоб видалити її без заміни.

Якщо ви наполягаєте на тому, щоб колупатися у внутрішніх файлах Omarchy, перемкніться на канал dev через _Update > Channel > Dev_. Це пов’язує Omarchy з git-копією вихідного коду в `~/omarchy`, яку ви можете вільно змінювати, скільки душі завгодно. Тут ніхто не вказуватиме вам, що робити!

### Скидання будь-яких змін

Якщо ви зрештою наробите безладу в конфігураціях, ви завжди можете повернути їх до значень за замовчуванням через _Update > Config_ у меню Omarchy. Або запустивши `omarchy reinstall configs`, щоб скинути все.
