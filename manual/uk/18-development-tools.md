# Інструменти для розробки

## Альтернативні редактори

Omarchy за замовчуванням постачається з [Neovim](https://neovim.io/), але якщо вам хочеться чогось трохи більш мейнстримного й звичного, можете запустити Omarchy Menu (`Super + Space`) і переглянути варіанти в розділі _Install > Editor_. Там у нас є VSCode, Cursor, Zed, Sublime Text, Helix, Vim та Emacs. Якщо не знайдете те, що шукаєте, загляньте в _Install > Package_ і подивіться, чи немає цього серед пакетів Arch (а якщо ні, спробуйте _Install > AUR_, щоб перевірити AUR).

Оригінальний редактор `vi` також доступний одразу з коробки. Виконайте `vi filename`, щоб редагувати файл у терміналі.

Підбір теми пропонується для `VSCode`, `Cursor`, `VSCodium` і `Helix`.

Системний редактор за замовчуванням можна встановити в `Setup > Defaults > Editor`.

## Середовище

Omarchy підтримує налаштування цілої купи середовищ розробки через розділ _Install > Development_ в Omarchy Menu (`Super + Space`). Звісно, там ви знайдете _Ruby on Rails_, а також усі три основні середовища виконання для JavaScript (Node.js, Bun, Deno), а ще популярні PHP-фреймворки, як-от Laravel і Symfony. А, і ще там є Go, Rust, Python, Java, Elixir (з Phoenix), .NET, OCaml, Zig, Clojure та Scala. Вибір дуже широкий!

Більшістю цих середовищ керує [Mise](https://mise.jdx.dev/). Це інструмент, який дає змогу встановлювати й запускати кілька версій мови програмування на одній машині. Він схожий на rbenv або rvm для Ruby чи virtualenv для Python, але працює для купи різних середовищ.

Щоб встановити, скажімо, Ruby, ви виконаєте `mise use -g ruby` — це і встановить Ruby, і зробить її глобальною версією за замовчуванням. Або, якщо ваш проєкт має файл .ruby-version, можете просто виконати `mise i` у корені цього проєкту.

## Попередньо встановлені інструменти CLI

Omarchy робить такі інструменти, як `gh`, `uv` і більшість [агентів для кодування](17-ai.md), доступними через [ліниве встановлення mise](https://mise.jdx.dev/dev-tools/shims.html#lazy-tools). Коли ви запускаєте такий інструмент уперше, mise встановлює його. Наступні запуски використовують встановлену версію; вони не перевіряють наявність оновлення під час кожного запуску.

Ви також можете переглянути версії за замовчуванням або встановити їх заздалегідь:

```bash
mise ls --current              # List the tools configured for this directory
mise install gh               # Install one tool now
mise install --include-lazy    # Install all configured tools, including lazy tools
```

Виконайте `omarchy update`, щоб оновити встановлені інструменти разом з рештою Omarchy. Псевдонім `mup` оновлює лише інструменти, якими керує mise. Щоб додати інший інструмент до власної конфігурації, скористайтеся командою `mise use -g <tool>`.

Під час налаштування Python через mise також встановлюється `uv`. Видалення середовища розробки Python залишає `uv` доступним як незалежний інструмент.

### Використання власного встановлення

Команди mise стоять перед `~/.local/bin` у `PATH`, тож інструмент, який ви встановили самостійно, наприклад власним інсталятором Claude Code або Cursor, усе одно запускатиме копію mise. Програми, запущені з робочого столу, також знаходять команди mise раніше за системні пакети, тож програма, яка запускає `gh`, отримає копію mise, навіть якщо ви встановили `github-cli` через pacman, і mise встановить цю копію під час першого запуску. Щоб натомість використовувати свою копію, вимкніть копію mise у `~/.config/mise/config.toml`. Наприклад, якщо ви самостійно встановили Cursor CLI:

```toml
[settings]
disable_tools = ["cursor-agent"]
```

Якщо у вас уже є таблиця `[settings]`, додайте запис туди; розширте наявний список `disable_tools`, а не замінюйте його. Переконайтеся, що ваше встановлення є в `PATH`. Використовуйте назву інструмента mise, яка може відрізнятися від його команди: наприклад, `oh-my-pi` надає `omp`. Засіб запуску агента за замовчуванням також надає перевагу встановленим користувачем Cursor або Muse у `~/.local/bin`.

### Видалення та відновлення версій за замовчуванням

_Remove Preinstalls_ змушує mise пропускати оголошення інструментів Omarchy для вашого користувача, додаючи їх до `ignored_config_paths` у `~/.config/mise/miserc.toml`. _Restore Preinstalls_ знову видаляє цей рядок. Інструменти, які ви оголошуєте самостійно, у власній конфігурації або в `mise.toml` проєкту, працюватимуть у будь-якому разі. Якщо ви виберете агента за замовчуванням або налаштуєте Python після видалення попередньо встановлених інструментів, цей інструмент буде додано до вашої власної конфігурації. Обидві дії стосуються лише вашого користувача; інші користувачі на машині зберігають власний вибір.

## Docker

[Docker](https://www.docker.com/) навряд чи потребує представлення. Він дає змогу запускати ізольовані контейнери, і Omarchy встановлює все необхідне для його нормальної роботи, зокрема сам Docker і [Docker Compose](https://docs.docker.com/compose/).

За замовчуванням ваш користувач *не* входить до групи `docker`. Ця група фактично дає root без пароля — будь-хто в ній може виконати `docker run -v /:/host` і захопити машину — тож один-єдиний шкідливий скрипт або залежність, запущені від вашого імені, інакше опинилися б за одну команду від root. Тому в командному рядку ви запускаєте Docker через `sudo` (`sudo docker ps`, `sudo docker compose up`), а графічні інструменти, що взаємодіють із демоном, — Windows VM — запитують авторизацію, коли вона їм потрібна. Якщо хочете повернути зручність налаштування без групи й розумієте компроміс, увімкніть це в **Setup > Security > Sudoless Docker** (або виконайте `omarchy-setup-security-sudoless-docker`): після попередження вас буде додано до групи `docker`; тоді звичайний `docker` і псевдонім `d` знову працюватимуть без `sudo`.

Поширені бази даних для локальної розробки в Docker можна налаштувати через _Install > Development > Docker DB_ у меню Omarchy.

## GitHub CLI

[GitHub CLI](https://cli.github.com/) доступний як `gh` для роботи з репозиторіями, задачами та запитами на злиття з термінала. Виконайте `gh auth login`, щоб встановити його під час першого використання й автентифікуватися, а потім `gh repo clone org/repo`, щоб клонувати репозиторій. Виконайте `gh --help`, щоб ознайомитися з його командами.

Для термінального інтерфейсу до запитів на злиття виконайте `ghui`; mise також встановить його під час першого використання. [Lazygit](https://github.com/jesseduffield/lazygit) попередньо встановлено для роботи із самим Git.
