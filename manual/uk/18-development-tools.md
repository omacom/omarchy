# Інструменти розробника

## Альтернативні редактори

Omarchy постачається з Plain як редактором за замовчуванням у нових встановленнях і з попередньо встановленим [Neovim](https://neovim.io/), але якщо вам хочеться чогось трохи більш мейнстримного й знайомого, можете відкрити Omarchy Menu (`Super + Space`) і переглянути варіанти в розділі _Install > Editor_. Там у нас є VSCode, Cursor, Zed, Sublime Text, Helix, Vim та Emacs. Якщо не знайдете того, що шукаєте, загляньте до _Install > Package_ і подивіться, чи немає цього в якомусь пакеті Arch (а якщо ні, спробуйте _Install > AUR_, щоб перевірити AUR).

Оригінальний редактор `vi` також доступний одразу з коробки. Запустіть `vi filename`, щоб редагувати файл у терміналі.

Відповідність теми оформлення пропонується для `VSCode`, `Cursor`, `VSCodium` і `Helix`.

Редактор за замовчуванням для всієї системи можна встановити в `Setup > Defaults > Editor`.

## Середовище

Omarchy підтримує налаштування цілої низки середовищ розробки через розділ _Install > Development_ у Omarchy Menu (`Super + Space`). Ви, звісно, знайдете там _Ruby on Rails_, а також усі три основні середовища виконання для JavaScript (Node.js, Bun, Deno), а також популярні фреймворки PHP на кшталт Laravel і Symfony. О, і там також є Go, Rust, Python, Java, Elixir (з Phoenix), .NET, OCaml, Zig, Clojure і Scala. Вибір дуже широкий!

Більшістю цих середовищ керує [Mise](https://mise.jdx.dev/). Це інструмент, який дозволяє встановлювати й запускати кілька версій мови програмування на одній машині. Це як rbenv або rvm для Ruby чи virtualenv для Python, але він працює для купи різних середовищ.

Щоб встановити, скажімо, Ruby, ви запускаєте `mise use -g ruby` — це і встановить Ruby, і зробить його глобальним варіантом за замовчуванням. Або, якщо ваш проєкт має файл .ruby-version, можете просто запустити `mise i` у корені цього проєкту.

## Попередньо встановлені інструменти CLI

`uv`, Node.js і `playwright-cli` (щоб агенти керували браузером, використовуючи встановлений Chrome) постачаються як встановлені пакети, а `omarchy update` підтримує їх в актуальному стані разом з рештою системи. `ghui`, [Hunk](https://github.com/modem-dev/hunk) і CLI для Basecamp, Cloudflare та HEY — за один вибір у розділі _Install > CLI_, а [агенти для програмування](17-ai.md) — у _Install > AI > CLI_.

mise керує лише тими середовищами виконання, які ви налаштовуєте з _Install > Development_; Omarchy сам по собі через нього нічого не встановлює. Запускайте `omarchy update`, щоб оновлювати їх разом з рештою Omarchy; псевдонім `mup` оновлює лише інструменти, якими керує mise. Щоб додати ще один інструмент до своєї конфігурації, скористайтеся `mise use -g <tool>`.

## Docker

[Docker](https://www.docker.com/) навряд чи потребує представлення. Він дозволяє запускати ізольовані контейнери, і Omarchy встановлює все потрібне, щоб він добре працював, включно з самим Docker і [Docker Compose](https://docs.docker.com/compose/).

За замовчуванням ваш користувач *не* входить до групи `docker`. Ця група — фактично root без пароля: будь-що в ній може виконати `docker run -v /:/host` і захопити машину, тож один-єдиний шкідливий скрипт або залежність, запущена від вашого імені, інакше опинилася б за одну команду від root. Тож у командному рядку ви запускаєте Docker через `sudo` (`sudo docker ps`, `sudo docker compose up`), а графічні інструменти, які спілкуються з демоном, — Windows VM — запитують авторизацію, коли вона їм потрібна. Якщо хочете повернути зручність налаштування без групи й розумієте компроміс, увімкніть це в **Setup > Security > Sudoless Docker** (або запустіть `omarchy-setup-security-sudoless-docker`): після попередження вас буде додано до групи `docker`; тоді звичайний `docker` і псевдонім `d` знову працюватимуть без `sudo`.

Поширені бази даних для локальної розробки в Docker можна налаштувати через _Install > Development > Docker DB_ у меню Omarchy.

## GitHub CLI

[GitHub CLI](https://cli.github.com/) — це `gh` для роботи з репозиторіями, задачами та pull-запитами з термінала. _Setup > Git_ встановлює його, коли ви там вирішуєте увійти до GitHub, після чого `gh repo clone org/repo` клонує репозиторій. Запустіть `gh --help`, щоб ознайомитися з його командами.

_Install > CLI > GitHub_ встановлює GitHub CLI, `gh`, разом із `ghui` — термінальним інтерфейсом до pull-запитів. [Lazygit](https://github.com/jesseduffield/lazygit) попередньо встановлено для роботи із самим Git.
