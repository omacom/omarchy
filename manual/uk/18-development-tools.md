# Інструменти розробки

## Альтернативні редактори

Omarchy постачається з Plain як редактором за замовчуванням на нових установках і з попередньо встановленим [Neovim](https://neovim.io/), але якщо вам хочеться чогось трохи більш поширеного та звичного, ви можете відкрити меню Omarchy (`Super + Space`) і переглянути варіанти в розділі _Встановити > Редактор_. Там перелічено VSCode, Cursor, Zed, Sublime Text, Helix, Vim та Emacs. Якщо ви не знайдете те, що шукаєте, загляньте в _Встановити > Пакет_ і подивіться, чи немає цього в пакеті Arch (а якщо ні, спробуйте _Встановити > AUR_, щоб перевірити AUR).

Оригінальний редактор `vi` також доступний одразу з коробки. Запустіть `vi filename`, щоб редагувати файл у терміналі.

Підбирання теми пропонується для `VSCode`, `Cursor`, `VSCodium` і `Helix`.

Системний редактор за замовчуванням можна встановити в _Налаштування > За замовчуванням > Редактор_.

## Середовище

Omarchy підтримує налаштування цілої низки середовищ розробки через розділ _Встановити > Розробка_ в меню Omarchy (`Super + Space`). Звісно, ви знайдете там _Ruby on Rails_, а також усі три основні середовища виконання для JavaScript (Node.js, Bun, Deno), а також популярні фреймворки PHP, як-от Laravel і Symfony. О, і ще є Go, Rust, Python, Java, Elixir (з Phoenix), .NET, OCaml, Zig, Clojure та Scala. Це дуже широкий вибір!

Більшістю цих середовищ керує [Mise](https://mise.jdx.dev/). Це інструмент, який дозволяє встановлювати й запускати кілька версій мови програмування на одній машині. Це як rbenv або rvm для Ruby чи virtualenv для Python, але він працює для купи різних середовищ.

Щоб встановити, скажімо, Ruby, ви запускаєте `mise use -g ruby`, що і встановить Ruby, і зробить його глобальним за замовчуванням. Або, якщо у вашому проєкті є файл .ruby-version, ви можете просто запустити `mise i` в корені цього проєкту.

## Попередньо встановлені інструменти CLI

Omarchy робить такі інструменти, як `gh`, `uv`, і більшість [агентів для кодування](17-ai.md) доступними через [ліниве встановлення mise](https://mise.jdx.dev/dev-tools/shims.html#lazy-tools). Під час першого запуску одного з них mise його встановлює. Потім агенти для кодування перевіряють наявність оновлення перед запуском, не частіше ніж раз на чотири години; інші інструменти, як-от `gh` та `uv`, повторно використовують встановлену версію, доки ви не оновите.

Ви також можете оглянути значення за замовчуванням або встановити їх заздалегідь:

```bash
mise ls --current              # List the tools configured for this directory
mise install gh               # Install one tool now
mise install --include-lazy    # Install all configured tools, including lazy tools
```

Запустіть `omarchy update`, щоб оновити встановлені інструменти разом з рештою Omarchy. Псевдонім `mup` оновлює лише інструменти, керовані mise. Щоб додати ще один інструмент до власної конфігурації, скористайтеся `mise use -g <tool>`.

Налаштування Python також встановлює `uv` через mise. Видалення середовища розробки Python залишає `uv` доступним як незалежний інструмент.

### Використання власного встановлення

Команди mise стоять перед `~/.local/bin` у `PATH`, тому інструмент, який ви встановили самостійно, наприклад власним установником Claude Code або Cursor, усе одно запускає копію mise. Програми, запущені з робочого столу, також знаходять команди mise раніше за системні пакети, тож програма, яка запускає `gh`, отримує копію mise, навіть якщо ви встановили `github-cli` за допомогою pacman, і mise встановлює цю копію під час першого запуску. Щоб замість неї використовувати свою, вимкніть копію mise у `~/.config/mise/config.toml`. Наприклад, якщо ви самостійно встановили Cursor CLI:

```toml
[settings]
disable_tools = ["cursor-agent"]
```

Якщо у вас уже є таблиця `[settings]`, додайте запис туди; розширте наявний список `disable_tools`, а не замінюйте його. Переконайтеся, що ваше встановлення є в `PATH`. Використовуйте назву інструмента mise, яка може відрізнятися від його команди: наприклад, `oh-my-pi` надає `omp`. Засіб запуску агента за замовчуванням також віддає перевагу встановленим користувачем Cursor або Muse у `~/.local/bin`.

### Видалення та відновлення значень за замовчуванням

_Видалити > Попередньо встановлене_ видаляє попередньо встановлені вебпрограми, TUI та програми Omarchy і змушує mise пропускати декларації інструментів Omarchy для вашого користувача, додаючи їх до `ignored_config_paths` у `~/.config/mise/miserc.toml`. _Встановити > Попередньо встановлене_ повертає їх назад і знову видаляє цей рядок. Інструменти, які ви декларуєте самостійно, у власній конфігурації або в `mise.toml` проєкту, у будь-якому разі продовжують працювати. Якщо ви оберете агента за замовчуванням або налаштуєте Python після видалення попередньо встановленого, цей інструмент буде додано до вашої власної конфігурації. Налаштування mise застосовується лише до вашого користувача, а інші користувачі зберігають свій власний вибір; програми, однак, є пакетами, тож їх видалення або відновлення змінює їх для всіх на машині.

## Docker

[Docker](https://www.docker.com/) навряд чи потребує представлення. Він дозволяє запускати ізольовані контейнери, і Omarchy встановлює все необхідне для його гарної роботи, включно із самим Docker і [Docker Compose](https://docs.docker.com/compose/).

За замовчуванням ваш користувач *не* входить до групи `docker`. Ця група — фактично root без пароля: будь-що в ній може виконати `docker run -v /:/host` і захопити машину, — тож один-єдиний шкідливий скрипт або залежність, запущені від вашого імені, інакше були б за одну команду від root. Тому в командному рядку ви запускаєте Docker із `sudo` (`sudo docker ps`, `sudo docker compose up`), а графічні інструменти, які спілкуються з демоном, — віртуальна машина Windows — запитують авторизацію, коли вона їм потрібна. Якщо ви хочете повернути зручність налаштування без групи й розумієте компроміс, увімкніть його в **Налаштування > Безпека > Docker без sudo** (або запустіть `omarchy-setup-security-sudoless-docker`), що додасть вас до групи `docker` після попередження; тоді звичайний `docker` і псевдонім `d` знову працюватимуть без `sudo`.

Ви можете налаштувати поширені бази даних для локальної розробки в Docker за допомогою _Встановити > Розробка > Docker DB_ у меню Omarchy.

## GitHub CLI

[GitHub CLI](https://cli.github.com/) доступний як `gh` для роботи з репозиторіями, задачами та запитами на злиття з термінала. Запустіть `gh auth login`, щоб встановити його під час першого використання й автентифікуватися, а потім `gh repo clone org/repo`, щоб клонувати репозиторій. Запустіть `gh --help`, щоб ознайомитися з його командами.

Для термінального інтерфейсу до запитів на злиття запустіть `ghui`; mise також встановлює його під час першого використання. [Lazygit](https://github.com/jesseduffield/lazygit) попередньо встановлено для роботи із самим Git.
