# Інструменти для розробки

## Альтернативні редактори

Omarchy постачається з Plain як типовим редактором у нових встановленнях і попередньо встановленим [Neovim](https://neovim.io/), але якщо вам хочеться чогось трохи більш мейнстримного та знайомого, ви можете відкрити Omarchy Menu (`Super + Space`) і переглянути варіанти в розділі _Install > Editor_. Там перелічені VSCode, Cursor, Zed, Sublime Text, Helix, Vim та Emacs. Якщо ви не знайшли те, що шукаєте, загляньте до _Install > Package_ і подивіться, чи немає цього в якомусь пакеті Arch (а якщо ні, спробуйте _Install > AUR_, щоб перевірити AUR).

Оригінальний редактор `vi` також доступний одразу з коробки. Запустіть `vi filename`, щоб редагувати файл у терміналі.

Підбір теми пропонується для `VSCode`, `Cursor`, `VSCodium` і `Helix`.

Типовий редактор для всієї системи можна встановити в розділі `Setup > Defaults > Editor`.

## Середовище

Omarchy підтримує налаштування цілої низки середовищ розробки через розділ _Install > Development_ у Omarchy Menu (`Super + Space`). Там, звісно, ви знайдете _Ruby on Rails_, а також усі три основні середовища виконання для JavaScript (Node.js, Bun, Deno), а ще популярні PHP-фреймворки на кшталт Laravel і Symfony. О, і там також є Go, Rust, Python, Java, Elixir (з Phoenix), .NET, OCaml, Zig, Clojure та Scala. Вибір дуже широкий!

Більшістю цих середовищ керує [Mise](https://mise.jdx.dev/). Це інструмент, який дає змогу встановлювати та запускати кілька версій мови програмування на одному комп’ютері. Це як rbenv або rvm для Ruby чи virtualenv для Python, але він працює для купи різних середовищ.

Щоб встановити, скажімо, Ruby, ви запустили б `mise use -g ruby`, що і встановить Ruby, і зробить його глобальним типовим. Або, якщо у вашому проєкті є файл .ruby-version, ви можете просто запустити `mise i` у корені цього проєкту.

## Попередньо встановлені інструменти CLI

`uv`, Node.js і `playwright-cli` (щоб агенти керували браузером, використовуючи встановлений Chrome) постачаються встановленими як пакети, а `omarchy update` тримає їх оновленими разом із рештою системи. [Hunk](https://github.com/modem-dev/hunk), а також CLI для GitHub, Basecamp, Cloudflare та HEY можна вибрати одним пунктом у розділі _Install > CLI_, а [агенти для кодування](17-ai.md) — у розділі _Install > AI > CLI_.

mise керує лише середовищами виконання, які ви налаштовуєте з _Install > Development_; Omarchy сама через нього нічого не встановлює. Запустіть `omarchy update`, щоб оновити їх разом із рештою Omarchy; аліас `mup` оновлює лише інструменти, якими керує mise. Щоб додати ще один інструмент до власної конфігурації, скористайтеся `mise use -g <tool>`.

## Docker

[Docker](https://www.docker.com/) навряд чи потребує представлення. Він дає змогу запускати ізольовані контейнери, а Omarchy встановлює все необхідне для його нормальної роботи, включно із самим Docker і [Docker Compose](https://docs.docker.com/compose/).

За замовчуванням ваш користувач *не* входить до групи `docker`. Ця група — фактично root без пароля: будь-що в ній може виконати `docker run -v /:/host` і захопити контроль над машиною, тож один-єдиний шахрайський скрипт або залежність, запущені від вашого імені, інакше опинилися б за одну команду від root. Тож у командному рядку ви запускаєте Docker через `sudo` (`sudo docker ps`, `sudo docker compose up`), а графічні інструменти, які спілкуються з демоном, — Windows VM — запитують авторизацію, коли вона їм потрібна. Якщо ви хочете повернути зручність налаштування без групи й розумієте компроміс, увімкніть це в розділі **Setup > Security > Sudoless Docker** (або запустіть `omarchy-setup-security-sudoless-docker`): після попередження це додасть вас до групи `docker`; тоді звичайний `docker` і аліас `d` знову працюватимуть без `sudo`.

Поширені бази даних для локальної розробки в Docker можна налаштувати за допомогою _Install > Development > Docker DB_ у меню Omarchy.

## GitHub CLI

[GitHub CLI](https://cli.github.com/) — це `gh`, для роботи з репозиторіями, issues і pull requests із термінала. _Setup > Git_ встановлює його, коли ви вирішуєте увійти там до GitHub, або встановіть його окремо з _Install > CLI > GitHub_. Тоді `gh repo clone org/repo` клонує репозиторій; запустіть `gh --help`, щоб ознайомитися з його командами.

[Lazygit](https://github.com/jesseduffield/lazygit) попередньо встановлений для роботи із самим Git.
