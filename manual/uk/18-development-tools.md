# Інструменти розробки

## Альтернативні редактори

Omarchy типово постачається з [Neovim](https://neovim.io/), але якщо ви хочете щось більш масове й звичне, відкрийте меню Omarchy (`Super + Space`) і перегляньте варіанти в розділі _Встановити > Редактор_. Там є VSCode, Cursor, Zed, Sublime Text, Helix, Vim та Emacs. Якщо не знайдете потрібного, загляньте до _Встановити > Пакунок_ і перевірте, чи немає його в пакунку Arch (а якщо немає, спробуйте _Встановити > AUR_ і перевірте AUR).

Оригінальний редактор `vi` також доступний одразу. Виконайте `vi filename`, щоб редагувати файл у терміналі.

Відповідність темі пропонується для `VSCode`, `Cursor`, `VSCodium` та `Helix`.

Системний типовий редактор можна встановити в `Налаштування > Типові > Редактор`.

## Середовище

Omarchy підтримує налаштування цілої низки середовищ розробки через розділ _Встановити > Розробка_ в меню Omarchy (`Super + Space`). Звісно, ви знайдете там _Ruby on Rails_, а також усі три основні середовища виконання JavaScript (Node.js, Bun, Deno) і популярні PHP-фреймворки на кшталт Laravel та Symfony. О, і там ще є Go, Rust, Python, Java, Elixir (з Phoenix), .NET, OCaml, Zig, Clojure та Scala. Вибір дуже широкий!

Більшістю цих середовищ керує [Mise](https://mise.jdx.dev/). Це інструмент, який дозволяє встановлювати й запускати кілька версій мови програмування на одній машині. Він схожий на rbenv або rvm для Ruby чи virtualenv для Python, але працює з багатьма різними середовищами.

Щоб встановити, скажімо, Ruby, виконайте `mise use -g ruby` — це і встановить Ruby, і зробить його глобальним типовим середовищем. Або, якщо у вашому проєкті є файл .ruby-version, просто виконайте `mise i` у корені цього проєкту.

## Docker

[Docker](https://www.docker.com/) навряд чи потребує представлення. Він дозволяє запускати ізольовані контейнери, і Omarchy встановлює все необхідне для комфортної роботи з ним, включно із самим Docker і [Docker Compose](https://docs.docker.com/compose/).

Типово ваш користувач *не* входить до групи `docker`. Ця група фактично є root без пароля — будь-що в ній може виконати `docker run -v /:/host` і захопити машину, — тож один-єдиний шкідливий скрипт або залежність, що працює від вашого імені, інакше опинився би за одну команду від root. Тому в командному рядку ви запускаєте Docker через `sudo` (`sudo docker ps`, `sudo docker compose up`), а графічні інструменти, що спілкуються з демоном, — зокрема Windows VM — запитують авторизацію, коли вона потрібна. Якщо хочете повернути зручність налаштування без групи й усвідомлюєте компроміс, увімкніть її в **Налаштування > Безпека > Docker без sudo** (або виконайте `omarchy-setup-security-sudoless-docker`), що додасть вас до групи `docker` після попередження; тоді звичайний `docker` і аліас `d` знову працюватимуть без `sudo`.

Типові бази даних для локальної розробки в Docker можна налаштувати через _Встановити > Розробка > Docker DB_ у меню Omarchy.

## GitHub CLI

[GitHub CLI](https://cli.github.com/) дозволяє автентифікуватися у вашому обліковому записі GitHub і клонувати з його допомогою приватні репозиторії. Він підʼєднаний як один із «ледачих» стабів mise, тож першого разу, коли ви виконаєте `gh`, він встановить себе сам. Для автентифікації виконайте `gh auth login`. Потім ви зможете клонувати приватні репозиторії командою `gh repo clone org/repo`.

За допомогою цієї команди ви також можете виконувати купу інших операцій GitHub. Просто виконайте `gh`, щоб побачити все, що можливо.

Є також стаб `ghui` із ледачим встановленням — для керування вашими pull requests у TUI. А [lazygit](https://github.com/jesseduffield/lazygit) встановлено заздалегідь, якщо ви хочете керувати самим git теж через TUI.
