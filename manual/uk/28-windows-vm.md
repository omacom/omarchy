# Windows VM

Omarchy пропонує простий спосіб запускати Windows через Docker VM на машинах x86_64. Встановити її можна через _Install > Windows_ у меню Omarchy (`Super + Space`).

Вашій машині для цього потрібна віртуалізація KVM, яка є в більшості машин, — але іноді її вимкнено в BIOS, і інсталятор повідомить вам, якщо це так. Також знадобиться місце на диску: стільки, скільки ви віддасте Windows, плюс близько 10GB для самого образу.

Інсталятор запитує, скільки RAM, скільки ядер CPU і скільки місця на диску віддати (64GB або більше — це розумний мінімум), а потім ім'я користувача та пароль для Windows. Залиште їх порожніми — і отримаєте `docker` / `admin`. Завантаження триває довго — 10-15 хвилин є нормою — а стежити за прогресом можна в браузері за адресою `http://127.0.0.1:8006`. Перед відкриттям консолі браузер запитає ті самі ім'я користувача та пароль.

## Використання

Після встановлення запустіть _Windows_ із засобу запуску програм. Це запустить VM, якщо вона ще не працює, і підключить вас через RDP на весь екран. На холодний старт дайте їй 15-30 секунд.

Сеанс RDP передає звук, ваш мікрофон і спільний буфер обміну, тож копіювання тексту між Linux і Windows просто працює. Роздільна здатність підлаштовується під ваше вікно, а Omarchy пропускає масштабування вашого дисплея, тож на екрані HiDPI це не буде розмитою кашею.

Коли ви закриваєте вікно RDP, VM автоматично завершує роботу. Якщо ви волієте залишити її працювати — скажімо, у вас там щось працює — запустіть її натомість командою `omarchy windows vm launch --keep-alive`.

Решта елементів керування доступна в тій самій команді:

```bash
omarchy windows vm status    # is it running?
omarchy windows vm stop      # shut it down
omarchy windows vm launch    # start and connect
```

## Спільний доступ до файлів

Каталог `~/Windows` у вашому домашньому каталозі автоматично надається у спільний доступ VM. Кладіть туди файли, якщо хочете, щоб вони були доступні Windows. VM не має доступу до жодної іншої частини вашої файлової системи, тож ви в безпеці від будь-якої гидоти на боці Windows. Її власний віртуальний диск доступний за адресою `~/.windows`.

Ці знайомі домашні шляхи залишаються на власних файлових системах. Вони також можуть бути символьними посиланнями на каталоги, що належать вам, що корисно, коли віртуальний диск розташований на більшому диску. Інсталятор вимірює вільне місце на файловій системі, яка фактично містить `~/.windows`, а не обов'язково на файловій системі, що містить ваш домашній каталог.

Тримайте диск і спільні шляхи як окремі каталоги, що не перетинаються. Видалення навмисно спорожнює каталог диска, але зберігає спільний каталог. Безпосередньо перед видаленням Omarchy виконує обмежену перевірку стримування і відмовляється будь-що видаляти, якщо ця перевірка перевищує ліміт часу або не може довести, що ці два дерева є окремими.

Перед запуском VM Omarchy відкриває і закріплює ці два каталоги, а потім монтує через bind точні inode каталогів на приватні якорі для кожного користувача нижче `/var/lib/omarchy/windows/mounts`. Docker бачить лише ці якорі, захищені root. Це зберігає користувацькі розташування диска, водночас не даючи іншому процесу, що працює від вашого імені, підмінити перевірений шлях до того, як його використає привілейований контейнер. І наявні каталоги диска, і спільні каталоги під час міграції посилюються до режиму `0700`, щоб інші локальні облікові записи не могли переглядати їхній вміст.

Порти VM прив'язано лише до localhost, тож ніщо у вашій мережі не може дістатися до машини Windows. Вебконсоль також вимагає налаштовані ім'я користувача та пароль Windows, що не дає іншому локальному обліковому запису керувати VM через порт 8006.

## Обмеження та ліцензування

У цій конфігурації немає пробросу GPU, тож вона не підходить для ігор чи редагування відео. Це чудовий спосіб запускати Microsoft Office або будь-що інше, що вам абсолютно необхідне.

Встановлюється версія Windows 11 Pro, неактивована. Вам знадобиться власний ліцензійний ключ, щоб користуватися функціями, які цього вимагають.

Якщо цей комп'ютер постачався з Windows, ключ OEM досі є у прошивці навіть після встановлення Omarchy. Виведіть його командою `omarchy windows key`. Цей ключ прив'язано до цієї машини — він активує Windows, перевстановлену на цьому обладнанні, але зазвичай не активує VM.

Змінити розподіл ресурсів можна пізніше, запустивши `omarchy windows vm install` у терміналі, що перепише конфігурацію VM на основі ваших відповідей. Сам файл compose тепер розташований за адресою `/var/lib/omarchy/windows/docker-compose.yml` і належить root — це навмисно, щоб процес, що працює від вашого імені, не міг переписати його і змусити привілейований запуск змонтувати весь ваш диск у контейнер. Якщо вам потрібно відредагувати його вручну (наприклад, щоб змонтувати пристрій USB), редагуйте його через `sudo` і перегляньте всі параметри в [проєкті Dockur Windows](https://github.com/dockur/windows).

Щоб позбутися всього цього, скористайтеся _Remove > Windows_ у меню Omarchy. Це видалить диск VM у `~/.windows` і все, встановлене всередині Windows, тож спершу скопіюйте з VM усе, що вам потрібно. Ваша спільна папка `~/Windows` залишиться недоторканою.
