# เครื่องมือพัฒนา

## โปรแกรมแก้ไขทางเลือก

Omarchy มาพร้อม [Neovim](https://neovim.io/) เป็นค่าเริ่มต้น แต่ถ้าคุณอยากได้อะไรที่กระแสหลักและคุ้นเคยกว่า คุณสามารถเปิดเมนู Omarchy (`Super + Space`) แล้วดูตัวเลือกใต้ _ติดตั้ง > Editor_ เรามี VSCode, Cursor, Zed, Sublime Text, Helix, Vim และ Emacs อยู่ในรายการนั้น ถ้าคุณไม่เจอสิ่งที่กำลังมองหา ให้ลองดู _ติดตั้ง > Package_ แล้วดูว่ามันอยู่ในแพ็กเกจ Arch หรือเปล่า (และถ้าไม่มี ให้ลอง _ติดตั้ง > AUR_ เพื่อตรวจ AUR)

โปรแกรมแก้ไข `vi` ดั้งเดิมก็พร้อมใช้งานมาให้เลยเช่นกัน รัน `vi filename` เพื่อแก้ไขไฟล์ในเทอร์มินัล

มีการจับคู่ธีมให้สำหรับ `VSCode`, `Cursor`, `VSCodium` และ `Helix`

คุณสามารถตั้งค่าโปรแกรมแก้ไขเริ่มต้นทั่วระบบได้ที่ `ตั้งค่า > Defaults > Editor`

## สภาพแวดล้อม

Omarchy รองรับการตั้งค่าสภาพแวดล้อมพัฒนามากมายผ่านส่วน _ติดตั้ง > Development_ ของเมนู Omarchy (`Super + Space`) คุณจะพบ _Ruby on Rails_ แน่นอน แต่ก็มีรันไทม์หลักทั้งสามตัวสำหรับ JavaScript (Node.js, Bun, Deno) รวมถึงเฟรมเวิร์ก PHP ยอดนิยมอย่าง Laravel และ Symfony ด้วย อ้อ แล้วก็มี Go, Rust, Python, Java, Elixir (พร้อม Phoenix), .NET, OCaml, Zig, Clojure และ Scala ด้วยเช่นกัน ตัวเลือกมันกว้างมากจริง!

สภาพแวดล้อมเหล่านี้ส่วนใหญ่จัดการโดย [Mise](https://mise.jdx.dev/) มันคือเครื่องมือที่ให้คุณติดตั้งและรันภาษาโปรแกรมหลายเวอร์ชันบนเครื่องเดียวกัน มันเหมือน rbenv หรือ rvm สำหรับ Ruby หรือ virtualenv สำหรับ Python แต่ใช้ได้กับสภาพแวดล้อมหลายแบบ

ตัวอย่างเช่น ถ้าจะติดตั้ง Ruby คุณก็รัน `mise use -g ruby` ซึ่งจะทั้งติดตั้ง Ruby และตั้งเป็นค่าเริ่มต้นทั่วระบบ หรือถ้าโปรเจกต์ของคุณมีไฟล์ .ruby-version คุณก็แค่รัน `mise i` ที่รากของโปรเจกต์นั้น

## Docker

[Docker](https://www.docker.com/) แทบไม่ต้องแนะนำอะไรเลย มันให้คุณรันคอนเทนเนอร์แบบแยกเดี่ยวได้ และ Omarchy ติดตั้งทุกอย่างที่จำเป็นเพื่อให้มันทำงานได้ดี รวมถึงตัว Docker เองและ [Docker Compose](https://docs.docker.com/compose/)

โดยค่าเริ่มต้น ผู้ใช้ของคุณจะ *ไม่ได้* อยู่ในกลุ่ม `docker` กลุ่มนั้นเทียบเท่ากับ root แบบไม่ต้องใช้รหัสผ่าน — อะไรก็ตามที่อยู่ในกลุ่มนั้นสามารถ `docker run -v /:/host` และยึดเครื่องได้เลย — ดังนั้นสคริปต์หรือ dependency ที่เป็นอันตรายเพียงตัวเดียวที่รันในนามคุณก็จะอยู่ห่างจาก root เพียงคำสั่งเดียว เพราะฉะนั้นบนคอมมานด์ไลน์ คุณจึงรัน Docker ด้วย `sudo` (`sudo docker ps`, `sudo docker compose up`) และเครื่องมือกราฟิกที่คุยกับ daemon — อย่าง Windows VM — จะขอสิทธิ์เมื่อจำเป็น ถ้าคุณต้องการความสะดวกแบบไม่ต้องอยู่ในกลุ่มกลับคืนมาและเข้าใจข้อแลกเปลี่ยนแล้ว ให้เปิดใช้จาก **ตั้งค่า > Security > Sudoless Docker** (หรือรัน `omarchy-setup-security-sudoless-docker`) ซึ่งจะเพิ่มคุณเข้ากลุ่ม `docker` หลังจากเตือนแล้ว จากนั้น `docker` เปล่า ๆ และนามแฝง `d` ก็จะทำงานได้โดยไม่ต้องใช้ `sudo` อีกครั้ง

คุณสามารถตั้งค่าฐานข้อมูลทั่วไปสำหรับการพัฒนาในเครื่องด้วย Docker ผ่าน _ติดตั้ง > Development > Docker DB_ ในเมนู Omarchy

## GitHub CLI

[GitHub CLI](https://cli.github.com/) ให้คุณยืนยันตัวตนด้วยบัญชี GitHub และโคลนรีโพสิทอรีส่วนตัวผ่านมันได้ มันถูกเชื่อมไว้เป็นหนึ่งใน mise stub แบบโหลดขี้เกียจ ดังนั้นครั้งแรกที่คุณรัน `gh` มันจะติดตั้งตัวเอง หากต้องการยืนยันตัวตน ให้รัน `gh auth login` จากนั้นคุณก็เช็กเอาต์รีโพสิทอรีส่วนตัวได้ด้วย `gh repo clone org/repo`

คุณยังทำการดำเนินการ GitHub อื่น ๆ ได้อีกมากมายด้วยคำสั่งนี้ แค่รัน `gh` เพื่อดูทุกอย่างที่ทำได้

ยังมี stub แบบติดตั้งขี้เกียจสำหรับ `ghui` เพื่อจัดการ pull request ของคุณใน TUI ด้วยเช่นกัน และ [lazygit](https://github.com/jesseduffield/lazygit) ก็ติดตั้งมาให้ล่วงหน้า ถ้าคุณอยากขับ git เองจาก TUI ด้วยเช่นกัน
