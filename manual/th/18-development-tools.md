# เครื่องมือสำหรับนักพัฒนา

## โปรแกรมแก้ไขทางเลือก

Omarchy มาพร้อมกับ Plain เป็นโปรแกรมแก้ไขเริ่มต้นสำหรับการติดตั้งใหม่และติดตั้ง [Neovim](https://neovim.io/) มาให้ล่วงหน้า แต่ถ้าคุณอยากได้อะไรที่ค่อนข้างเป็นกระแสหลักและคุ้นเคยมากกว่า คุณสามารถเปิด Omarchy Menu (`Super + Space`) และดูตัวเลือกภายใต้ _Install > Editor_ ได้ เรามี VSCode, Cursor, Zed, Sublime Text, Helix, Vim และ Emacs อยู่ในรายการนั้น ถ้าคุณไม่เจอสิ่งที่กำลังมองหา ให้ลองดู _Install > Package_ และดูว่ามันอยู่ในแพ็กเกจ Arch หรือไม่ (และถ้าไม่ ให้ลอง _Install > AUR_ เพื่อตรวจสอบ AUR)

โปรแกรมแก้ไข `vi` ดั้งเดิมก็พร้อมใช้งานทันทีเช่นกัน รัน `vi filename` เพื่อแก้ไขไฟล์ในเทอร์มินัล

มีการจับคู่ธีมให้สำหรับ `VSCode`, `Cursor`, `VSCodium` และ `Helix`

คุณสามารถตั้งค่าโปรแกรมแก้ไขเริ่มต้นทั่วทั้งระบบได้ภายใต้ `Setup > Defaults > Editor`

## สภาพแวดล้อม

Omarchy รองรับการตั้งค่าสภาพแวดล้อมการพัฒนามากมายผ่านส่วน _Install > Development_ ของ Omarchy Menu (`Super + Space`) แน่นอนว่าคุณจะเจอ _Ruby on Rails_ แต่ยังมีรันไทม์หลักทั้งสามตัวสำหรับ JavaScript (Node.js, Bun, Deno) รวมถึงเฟรมเวิร์ก PHP ยอดนิยมอย่าง Laravel และ Symfony อ้อ และยังมี Go, Rust, Python, Java, Elixir (พร้อม Phoenix), .NET, OCaml, Zig, Clojure และ Scala ด้วย เป็นตัวเลือกที่กว้างมากจริงๆ!

สภาพแวดล้อมเหล่านี้ส่วนใหญ่จัดการโดย [Mise](https://mise.jdx.dev/) มันเป็นเครื่องมือที่ให้คุณติดตั้งและรันภาษาโปรแกรมหลายเวอร์ชันบนเครื่องเดียวกัน มันเหมือน rbenv หรือ rvm สำหรับ Ruby หรือ virtualenv สำหรับ Python แต่มันใช้ได้กับสภาพแวดล้อม مختلفมากมาย

เช่น ถ้าจะติดตั้ง Ruby คุณจะรัน `mise use -g ruby` ซึ่งจะทั้งติดตั้ง Ruby และตั้งให้เป็นค่าเริ่มต้นระดับโกลบอล หรือถ้าโปรเจกต์ของคุณมีไฟล์ .ruby-version คุณก็แค่รัน `mise i` ในโฟลเดอร์รากของโปรเจกต์นั้นได้เลย

## เครื่องมือ CLI ที่ติดตั้งมาล่วงหน้า

Omarchy ทำให้เครื่องมืออย่างเช่น `gh`, `uv` และ[โค้ดดิ้งเอเจนต์](17-ai.md)ส่วนใหญ่พร้อมใช้งานผ่าน[การติดตั้งแบบ lazy ของ mise](https://mise.jdx.dev/dev-tools/shims.html#lazy-tools) ครั้งแรกที่คุณรันตัวใดตัวหนึ่ง mise จะติดตั้งให้ จากนั้นโค้ดดิ้งเอเจนต์จะตรวจสอบอัปเดตก่อนรัน โดยสูงสุดเพียงสี่ชั่วโมงครั้งเดียว ส่วนเครื่องมืออื่นๆ อย่าง `gh` และ `uv` จะใช้เวอร์ชันที่ติดตั้งไว้ต่อไปจนกว่าคุณจะอัปเดต

คุณยังสามารถตรวจสอบค่าเริ่มต้นหรือติดตั้งล่วงหน้าได้เช่นกัน:

```bash
mise ls --current              # List the tools configured for this directory
mise install gh               # Install one tool now
mise install --include-lazy    # Install all configured tools, including lazy tools
```

รัน `omarchy update` เพื่ออัปเดตเครื่องมือที่ติดตั้งไว้พร้อมกับส่วนอื่นๆ ของ Omarchy นามแฝง `mup` จะอัปเดตเฉพาะเครื่องมือที่ mise จัดการเท่านั้น หากต้องการเพิ่มเครื่องมืออื่นลงในการกำหนดค่าของคุณเอง ให้ใช้ `mise use -g <tool>`

การตั้งค่า Python ยังติดตั้ง `uv` ผ่าน mise ด้วย การลบสภาพแวดล้อมการพัฒนา Python ออกจะยังคงให้ `uv` พร้อมใช้งานเป็นเครื่องมืออิสระ

### การใช้การติดตั้งของคุณเอง

คำสั่งของ mise มาก่อน `~/.local/bin` บน `PATH` ดังนั้นเครื่องมือที่คุณติดตั้งเอง เช่น ด้วยตัวติดตั้งของ Claude Code หรือ Cursor เอง ก็ยังคงรันสำเนาของ mise แอปที่เปิดจากเดสก์ท็อปก็จะเจอคำสั่งของ mise ก่อนแพ็กเกจของระบบเช่นกัน ดังนั้นแอปที่รัน `gh` จะได้สำเนาของ mise แม้ว่าคุณจะติดตั้ง `github-cli` ด้วย pacman และ mise จะติดตั้งสำเนานั้นในครั้งแรก หากต้องการใช้ของคุณแทน ให้ปิดการใช้งานสำเนาของ mise ใน `~/.config/mise/config.toml` ตัวอย่างเช่น ถ้าคุณติดตั้ง Cursor CLI เอง:

```toml
[settings]
disable_tools = ["cursor-agent"]
```

ถ้าคุณมีตาราง `[settings]` อยู่แล้ว ให้เพิ่มรายการนั้นเข้าไปที่นั่น ขยายรายการ `disable_tools` ที่มีอยู่แทนที่จะแทนที่มัน ตรวจสอบให้แน่ใจว่าการติดตั้งของคุณอยู่บน `PATH` ใช้ชื่อเครื่องมือของ mise ซึ่งอาจแตกต่างจากคำสั่งของมัน: ตัวอย่างเช่น `oh-my-pi` ให้คำสั่ง `omp` ตัวเปิดเอเจนต์เริ่มต้นก็เลือกใช้ Cursor หรือ Muse ที่ผู้ใช้ติดตั้งไว้ใน `~/.local/bin` ก่อนเช่นกัน

### การลบและการกู้คืนค่าเริ่มต้น

_Remove > Preinstalls_ จะลบเว็บแอปที่ติดตั้งมาล่วงหน้าของ Omarchy รวมถึง TUIs และแอปต่างๆ และทำให้ mise ข้ามการประกาศเครื่องมือของ Omarchy สำหรับผู้ใช้ของคุณ โดยเพิ่มพวกมันลงใน `ignored_config_paths` ใน `~/.config/mise/miserc.toml` _Install > Preinstalls_ จะนำพวกมันกลับมาและลบบรรทัดนั้นออกอีกครั้ง เครื่องมือที่คุณประกาศเอง ไม่ว่าจะในการกำหนดค่าของคุณเองหรือใน `mise.toml` ของโปรเจกต์ จะยังคงทำงานได้ทั้งสองกรณี หากคุณเลือกเอเจนต์เริ่มต้นหรือตั้งค่า Python หลังจากลบการติดตั้งล่วงหน้า เครื่องมือนั้นจะถูกเพิ่มลงในการกำหนดค่าของคุณเอง การตั้งค่าของ mise ใช้กับผู้ใช้ของคุณเท่านั้น และผู้ใช้คนอื่นยังคงรักษาตัวเลือกของตัวเองไว้ ส่วนแอปต่างๆ เป็นแพ็กเกจ ดังนั้นการลบหรือกู้คืนพวกมันจะเปลี่ยนแปลงสำหรับทุกคนบนเครื่อง

## Docker

[Docker](https://www.docker.com/) แทบไม่จำเป็นต้องแนะนำกันเลย มันช่วยให้คุณรันคอนเทนเนอร์ที่แยกออกมาได้ และ Omarchy ติดตั้งทุกอย่างที่จำเป็นเพื่อให้รันได้ดี รวมถึง Docker เองและ [Docker Compose](https://docs.docker.com/compose/)

โดยค่าเริ่มต้น ผู้ใช้ของคุณ*ไม่ได้*อยู่ในกลุ่ม `docker` กลุ่มนั้นแทบจะเท่ากับ root แบบไม่ต้องใช้รหัสผ่าน — อะไรก็ตามที่อยู่ในกลุ่มนั้นสามารถใช้ `docker run -v /:/host` และเข้ายึดเครื่องได้เลย — ดังนั้นสคริปต์หรือดีเพนเดนซีตัวร้ายเพียงตัวเดียวที่รันในนามของคุณ ก็จะเหลืออีกเพียงคำสั่งเดียวก็กลายเป็น root ได้ ดังนั้นบนบรรทัดคำสั่ง คุณจะรัน Docker ด้วย `sudo` (`sudo docker ps`, `sudo docker compose up`) และเครื่องมือแบบกราฟิกที่สื่อสารกับดีมอน — Windows VM — จะขอการอนุญาตเมื่อต้องการ หากคุณต้องการความสะดวกของการตั้งค่าแบบไม่ต้องใช้ sudo กลับคืนมาและเข้าใจข้อแลกเปลี่ยน ให้เปิดใช้งานจาก **Setup > Security > Sudoless Docker** (หรือรัน `omarchy-setup-security-sudoless-docker`) ซึ่งจะเพิ่มคุณเข้ากลุ่ม `docker` หลังจากแสดงคำเตือน จากนั้น `docker` แบบธรรมดาและนามแฝง `d` จะทำงานโดยไม่ต้องใช้ `sudo` อีกครั้ง

คุณสามารถตั้งค่าฐานข้อมูลทั่วไปสำหรับการพัฒนาในเครื่องใน Docker ได้โดยใช้ _Install > Development > Docker DB_ ในเมนู Omarchy

## GitHub CLI

[GitHub CLI](https://cli.github.com/) พร้อมใช้งานในชื่อ `gh` สำหรับการทำงานกับรีพอซิทอรี issues และ pull requests จากเทอร์มินัล รัน `gh auth login` เพื่อติดตั้งในการใช้งานครั้งแรกและยืนยันตัวตน จากนั้นรัน `gh repo clone org/repo` เพื่อโคลนรีพอซิทอรี รัน `gh --help` เพื่อสำรวจคำสั่งต่างๆ ของมัน

สำหรับอินเทอร์เฟซเทอร์มินัลสำหรับ pull requests ให้รัน `ghui` ซึ่ง mise จะติดตั้งให้ในการใช้งานครั้งแรกเช่นกัน [Lazygit](https://github.com/jesseduffield/lazygit) ถูกติดตั้งมาล่วงหน้าสำหรับการทำงานกับ Git โดยตรง
