### การติดตั้งและอัปเดตเอเจนต์

ยกเว้น Hermes เอเจนต์เหล่านี้ใช้การติดตั้งแบบ lazy ของ mise: การเปิดใช้ครั้งแรกจะติดตั้ง CLI และการเปิดใช้ครั้งต่อ ๆ ไปจะใช้ของเดิม mise ยังตรวจสอบเอเจนต์ที่ติดตั้งไว้ว่ามีรุ่นใหม่หรือไม่ อย่างมากที่สุดหนึ่งครั้งทุกสี่ชั่วโมง ก่อนที่มันจะเริ่ม หรือในเบื้องหลังที่ shell prompt หากการอัปเดตนั้นล้มเหลวหรือคุณออฟไลน์ รุ่นที่ติดตั้งไว้จะทำงาน `omarchy update` จะอัปเดตเอเจนต์ที่ติดตั้งไว้พร้อมกับส่วนที่เหลือของ Omarchy และ `mup` จะอัปเดตเฉพาะเครื่องมือที่ mise จัดการเท่านั้น

ตัวอัปเดตของเอเจนต์เอง เช่น `claude update`, `codex update` หรือปุ่มอัปเดตในแอป จะไม่อัปเดตสิ่งที่ mise จัดการติดตั้งไว้ `codex update` จะล้มเหลว และ `claude update` อาจรายงานว่าสำเร็จในขณะที่ติดตั้งสำเนาแยกต่างหากที่ mise ไม่ได้ติดตาม หากคุณอยากใช้ตัวติดตั้งและตัวอัปเดตแบบเนทีฟของเอเจนต์มากกว่า ให้เพิ่มมันลงใน `disable_tools`; ดู [เครื่องมือ CLI ที่ติดตั้งไว้ล่วงหน้า](18-development-tools.md#preinstalled-cli-tools)

ในการติดตั้งเครื่องมือแบบ lazy ทั้งหมดที่กำหนดค่าไว้ก่อนที่คุณจะต้องการใช้ ให้รัน `mise install --include-lazy` ซึ่งรวมเครื่องมือ CLI เริ่มต้นอื่น ๆ ของ Omarchy รวมถึงเอเจนต์เหล่านี้ด้วย ดู [เครื่องมือ CLI ที่ติดตั้งไว้ล่วงหน้า](18-development-tools.md#preinstalled-cli-tools) สำหรับการติดตั้งเครื่องมือชิ้นเดียวหรือใช้การติดตั้งของคุณเอง

`grok` ถูกติดตั้งผ่านแพ็กเกจ `grok` แบบ first-party ของ mise ในแบบเดียวกับ `claude` และ `codex` รัน `grok` หรือเลือกมันใต้ _Agent > Harness_ ข้ามตัวติดตั้งแบบ `curl | bash` บน x.ai ไปเลย เส้นทางนั้นจะวางสำเนาที่สองไว้ใน `~/.grok/bin`, นำหน้ามันบน `PATH` และเขียนทับ wrapper ของ Omarchy

`dsh` เปิด browser UI ของมันบน `127.0.0.1:3080` โดยมีไดเรกทอรีที่เปิดใช้เป็น workspace เริ่มต้น browser UI ของมันไม่รับพรอมต์เริ่มต้น ดังนั้น `omarchy agent prompt` จะเปิดมันโดยมีพรอมต์อยู่บนคลิปบอร์ดของคุณให้วาง Omarchy เริ่มมันด้วย permission preset แบบ no-approval ของ DeepSeek DeepSeek Harness จะอัปโหลด session log ไปยัง DeepSeek เมื่อคุณใช้ official model API ของมัน; ปิดสิ่งนั้นได้ใต้ _Settings > General > Upload Session Log_ ใน browser UI ของมัน ข้อเสนอแนะที่คุณส่งให้มันจะถูกอัปโหลดไปพร้อมกับ session ด้วย เว้นแต่คุณจะเริ่มมันด้วย `DSH_TELEMETRY_MODE=DISABLED`

### เอเจนต์เริ่มต้น

เลือกเอเจนต์เริ่มต้นของคุณด้วย `omarchy default agent <name>` หรือใต้ _Agent > Harness_ ใน Omarchy Menu (`Super + Space`) หากยังไม่ได้ติดตั้งเอเจนต์ การเลือกมันจะติดตั้งมันก่อน Omarchy ใหม่เอี่ยมจะเชิญชวนให้คุณเลือกสิ่งนี้ด้วยการแจ้งเตือนครั้งเดียว

การเลือก Claude ยังพยายามตั้งค่า browser extension ของมันสำหรับ Chromium, Chrome, Brave, Brave Origin และ Edge ด้วย การตั้งค่า extension นี้ใช้กับผู้ใช้ทั้งหมดและอาจขอรหัสผ่านระบบของคุณ; การยกเลิกหรือการติดตั้ง extension ที่ล้มเหลวยังคงเลือกและเปิดใช้ Claude การรีสตาร์ทเบราว์เซอร์ของคุณ เปิดใช้งาน extension หากได้รับแจ้ง และลงชื่อเข้าใช้ Claude เพื่อเชื่อมต่อให้เสร็จสมบูรณ์ รัน `/chrome` ใน Claude เพื่อตรวจสอบการเชื่อมต่อ Firefox และ Zen ไม่รองรับ extension นี้ หาก Claude เป็นค่าเริ่มต้นของคุณอยู่แล้วก่อนที่จะมีการเพิ่มการตั้งค่านี้ ให้เลือกมันอีกครั้งเพื่อติดตั้ง extension

เมื่อคุณเลือกแล้ว `Super + Shift + Ctrl + A` จะเปิดใช้เอเจนต์เริ่มต้นในหน้าต่างเทอร์มินัลเฉพาะ (หรือแสดงตัวเลือกหากคุณยังไม่ได้เลือก) คุณยังสามารถเปิดใช้มันตรงเข้าสู่งานได้ด้วย `omarchy agent prompt "Review this project"` Freebuff และ DeepSeek Harness ไม่รับพรอมต์เริ่มต้น ดังนั้นพวกมันจะเปิดโดยมีพรอมต์อยู่บนคลิปบอร์ดของคุณให้วางแทน เอเจนต์ที่เปิดใช้ด้วยวิธีนี้จะทำงานโดยไม่มีผู้ดูแลในโหมด don't-stop-to-ask ของแต่ละตัว ดังนั้นจงพร้อมสำหรับพวกมันที่จะลงมือทำสิ่งต่าง ๆ จริง ๆ! MiniMax Code ไม่มีโหมดดังกล่าวสำหรับ interactive session ของมัน ดังนั้นมันจะขอสิทธิ์ตามปกติ และเนื่องจากเอเจนต์ปฏิเสธที่จะจดจำความไว้วางใจสำหรับ home directory ของคุณ การเปิดใช้จาก `$HOME` จะเริ่มใน `~/Work` แทน

ยังมีทางลัดในเทอร์มินัลด้วย: `a` รันเอเจนต์เริ่มต้นแบบ inline ในเทอร์มินัลปัจจุบัน ขณะที่ `c`, `cx` และ `cy` เริ่ม OpenCode, Claude Code และ Codex โดยตรง (ในโหมดอนุมัติอัตโนมัติของพวกมันอีกเช่นกัน) การเปลี่ยนธีมจะซิงก์ไปยังเอเจนต์ด้วยเช่นกัน: Claude Code, Pi, OpenCode และ Hermes (เมื่อ Omarchy ติดตั้งมันแล้ว) ล้วนทำตามเมื่อคุณเปลี่ยนธีม Omarchy

### คำแนะนำสำหรับเอเจนต์ของคุณ

กฎส่วนตัวสำหรับทุกเอเจนต์จะอยู่ใน `~/.agents/AGENTS.md` ข้าง shared skills ใน `~/.agents/skills` เปิดมันใต้ _Agent > Instructions_ ซึ่งยังเชื่อมโยงมันเข้าไปในแต่ละ harness ที่เก็บไฟล์ส่วนกลางของตัวเองไว้: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` ของ Copilot และอื่น ๆ Crush และ Amp อ่านลิงก์ `~/.config/AGENTS.md` ขณะที่ omp, Kimi และ DeepSeek Harness อ่าน `~/.agents/AGENTS.md` โดยตรง การเลือกเอเจนต์เริ่มต้นจะเชื่อมโยงมันด้วยเช่นกัน ไฟล์คำแนะนำที่คุณมีอยู่แล้วจะกลายเป็นไฟล์ที่ใช้ร่วมกันหากยังไม่มีไฟล์ดังกล่าวมาก่อน; มิฉะนั้นมันจะถูกเก็บไว้ข้างลิงก์ในชื่อ `.bak` รัน `omarchy agent instructions` เพื่อเชื่อมโยงใหม่หลังจากติดตั้งเอเจนต์อื่น

### แผงเอเจนต์

แถบบนสุดมีไอคอนเอเจนต์ ก่อนที่คุณจะตั้งค่าเอเจนต์ แผงของมันจะแนะนำคุณตลอดการลงชื่อเข้าใช้ Claude, Codex หรือ Grok และตัวแรกจะกลายเป็นเอเจนต์เริ่มต้นของคุณ หลังจากนั้น แผงจะวางทุกการสมัครสมาชิกไว้ในหน้าเดียว: เอเจนต์และบัญชีแต่ละตัวพร้อมแผนของมัน มิเตอร์สำหรับขีดจำกัดแต่ละอย่างทั้ง session แบบ 5 ชั่วโมงและรายสัปดาห์ พร้อมเวลาจนกว่ามันจะรีเซ็ต (วางเมาส์เหนือเพื่อดูเปอร์เซ็นต์ที่แน่นอน) หรือยอดเงินแบบเติมเงินคงเหลือ ภายใต้บรรทัดที่หมุนเวียนผ่านสิ่งที่คุณใช้ไปในทั้งหมด เช่น โทเคนในสัปดาห์นี้และโมเดลที่คุณใช้มากที่สุด ใต้ _Make something_ มันเสนอพรอมต์เริ่มต้นสำหรับธีม ปลั๊กอิน แอป หรือเกมใหม่ที่มอบงานนั้นให้เอเจนต์เริ่มต้นของคุณ แอปถูกสร้างขึ้นในแบบเดียวกับ Hype, Monologue และ Omacut ของ Omarchy เอง ใน C++ และ Qt Quick ตาม omarchy-make-app agent skill และ compiler และชิ้นส่วน Qt ที่พวกมันต้องการได้รับการติดตั้งมาให้ เกมเป็นหน้า three.js หน้าเดียวใน `~/Games/vibes` ตาม omarchy-make-game agent skill และทั้งหมดเปิดจากตัวเรียกใช้ Game Vibes ตัวเดียวในธีมปัจจุบัน; พวกมันโหลด three.js จากเว็บ ดังนั้นพวกมันต้องการการเชื่อมต่อในการเริ่ม Claude Code, Codex, Grok, Kimi, Cursor และโควตา Grok Bot ของมัน, GitHub Copilot, Muse, Antigravity, Kimchi และ Devin ได้รับการครอบคลุมมาตั้งแต่ต้นพร้อมขีดจำกัดของพวกมัน และ Hermes, Mistral Vibe และ Qwen Code จะแสดง session และโทเคนของพวกมันเมื่อคุณได้ใช้พวกมันแล้ว แผนและคีย์ของผู้ให้บริการที่คุณใช้ผ่าน pi, omp หรือ opencode ก็แสดงขึ้นเช่นกัน: OpenCode Zen และ Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan และ Synthetic พร้อมขีดจำกัดของพวกมัน; Fireworks, OpenRouter และ DeepSeek พร้อมยอดเงินแบบเติมเงินของพวกมัน; และโมเดลที่คุณรันบนฮาร์ดแวร์ของคุณเองใต้ Local models ทุกเอเจนต์ถูกนับเพียงครั้งเดียว ภายใต้ผู้ที่เรียกเก็บเงินจากมัน ไม่ว่าคุณจะขับมันผ่านกี่ harness ก็ตาม

คลิกซ้ายที่ไอคอนแถบเพื่อเปิดแผง คลิกขวาเพื่อเปิดใช้เอเจนต์เริ่มต้นของคุณ บันทึกการใช้งานที่อยู่เบื้องหลังมันจะถูกสร้างใหม่ทุก 15 นาทีโดย `omarchy agent usage-update` และแผงยังสามารถรวมการใช้งานจากเครื่องอื่น ๆ ของคุณผ่านโฟลเดอร์ที่ซิงก์ได้ ดู README ใต้ `$OMARCHY_PATH/shell/plugins/agents/` สำหรับการตั้งค่าแบบเต็ม

### หลายการสมัครสมาชิก

หากคุณจ่ายสำหรับแผน Claude, Codex หรือ Grok มากกว่าหนึ่งแผน — เช่น Max ส่วนตัวและอีกอันสำหรับงาน — Omarchy สามารถให้พวกมันทั้งหมดลงชื่อเข้าใช้อยู่และย้ายไปมาระหว่างพวกมันได้ เพิ่มการสมัครสมาชิกด้วย + ในแผงเอเจนต์ ซึ่งจะแนะนำคุณตลอดกระบวนการตรงนั้นเลย หรือด้วย `omarchy agent account add claude Work` (หรือ `codex` หรือ `grok`) มันจะติดตั้ง CLI หากยังไม่มี บัญชีแรกสำหรับผู้ให้บริการรายหนึ่งจะลงชื่อเข้าใช้ผ่านเบราว์เซอร์ปกติของคุณ ตรงจุดที่ CLI มองหาเสมอ ทุกบัญชีหลังจากนั้นจะลงชื่อเข้าใช้ผ่านหน้าต่างส่วนตัว ดังนั้นบัญชีที่เบราว์เซอร์ของคุณลงชื่อเข้าใช้อยู่แล้วจะไม่ถูกหยิบขึ้นมาโดยผิดพลาด; ลงชื่อเข้าใช้ที่นั่นในฐานะบัญชีที่คุณกำลังเพิ่ม และปิดหน้าต่างส่วนตัวใด ๆ ที่คุณเปิดอยู่ก่อนหน้านั้นก่อน อย่าออกจากระบบของ CLI เพื่อทำสิ่งนี้เด็ดขาด: การออกจากระบบจะเพิกถอนการลงชื่อเข้าใช้ที่บันทึกไว้ และบัญชีนั้นจะต้องถูกเพิ่มอีกครั้ง

ในการคัดลอกการเข้าสู่ระบบการสมัครสมาชิกของคุณไปยังเครื่อง Omarchy อื่นผ่าน SSH ให้รัน `omarchy agent account copy user@laptop` ผู้ส่งจะจัดเตรียมตัวรับชั่วคราวเมื่อปลายทางยังไม่มีตัวรับติดตั้งไว้ ดังนั้นเครื่อง Omarchy รุ่นเก่ากว่าสามารถรับบัญชีได้โดยไม่ต้องอัปเดต ตัวรับที่ติดตั้งไว้จะมีลำดับความสำคัญกว่า สิ่งนี้คัดลอกการสมัครสมาชิก Claude, Codex และ Grok ทั้งหมด; เพิ่มชื่อผู้ให้บริการเพื่อเลือกพวกมัน เช่นใน `omarchy agent account copy laptop claude` ชื่อบัญชีและ ID คำสั่งจะตรงกับต้นทาง รวมถึงบัญชีที่มีอยู่แล้วบนปลายทาง บัญชีปลายทางที่ไม่เกี่ยวข้องจะได้รับส่วนต่อท้ายเป็นตัวเลขหากชื่อของพวกมันขัดกัน และการตั้งค่า ทักษะ ปลั๊กอิน และประวัติการสนทนาจะยังคงเป็นแบบโลคอลในแต่ละเครื่อง

ข้อมูลประจำตัวปลายทางที่มีอยู่จะถูกเก็บไว้ บัญชีต้นทางที่ลงชื่อเข้าใช้ที่นั่นอยู่แล้วจะมีการซิงโครไนซ์ชื่อโดยไม่แทนที่ข้อมูลประจำตัวของมัน; บัญชีอื่น ๆ จะถูกเพิ่มควบคู่ไปกับมัน ในการแทนที่ข้อมูลประจำตัวที่บันทึกไว้สำหรับบัญชีที่ตรงกัน ให้ใช้ `omarchy agent account copy --replace laptop claude` หลังจากออกจาก session ของบัญชีนั้นบนปลายทาง ปลายทางใหม่เอี่ยมจะได้รับบัญชีที่ใช้งานอยู่และการตั้งค่าการสลับของต้นทางด้วย; ปลายทางที่จัดตั้งแล้วจะเก็บของตัวเองไว้

ข้อมูลประจำตัวเดินทางผ่าน SSH และถูกเก็บไว้ในไฟล์ส่วนตัวบนปลายทาง ดังนั้นจงคัดลอกไปยังเครื่องที่คุณไว้วางใจเท่านั้น นี่เป็นการคัดลอกครั้งเดียว ไม่ใช่การซิงโครไนซ์อย่างต่อเนื่อง Codex refresh token สามารถถูกหมุนเวียนโดยเครื่องอื่นได้ ทำให้การเข้าสู่ระบบที่คัดลอกมาจำเป็นต้องต่ออายุ; การลงชื่อเข้าใช้แยกกันยังคงเป็นตัวเลือกที่เชื่อถือได้มากที่สุดสำหรับการใช้พร้อมกันบนหลายเครื่อง ดู [คำแนะนำการยืนยันตัวตนบัญชีของ Codex](https://developers.openai.com/codex/auth/ci-cd-auth)

หนึ่งบัญชีต่อผู้ให้บริการหนึ่งรายจะใช้งานอยู่ และทุก session ใหม่จะเริ่มต้นเป็นบัญชีนั้น: `cx`, `cy`, `claude`, `codex` หรือ `grok` ธรรมดา สิ่งใดก็ตามที่เปิดใช้ผ่าน `omarchy agent` และสคริปต์หรือโปรแกรมแก้ไขที่พบ CLI บน `PATH` สลับด้วย `omarchy agent account use work` (และกลับด้วย `omarchy agent account use main`) หรือในแผงโดยกดหมายเลขของบัญชีแล้วกด `Enter` (หรือคลิกปุ่ม Use ของมัน) session ของ Claude ที่กำลังทำงานอยู่ก็สลับด้วยเช่นกัน ตั้งแต่ข้อความถัดไปของพวกมัน: ทุก session ของ Claude ทำงานใน `~/.claude` ซึ่งเก็บการลงชื่อเข้าใช้ของบัญชีที่ใช้งานอยู่ไว้เสมอ session ของ Claude ที่เริ่มในโฟลเดอร์เฉพาะของบัญชีโดย Omarchy รุ่นเก่ากว่าจะเก็บการลงชื่อเข้าใช้นั้นไว้จนกว่ามันจะออก ดังนั้นการสลับจะระบุชื่อ session เหล่านั้นและจะเสร็จสิ้นเองเมื่อพวกมันหายไป session ของ Codex และ Grok ที่กำลังทำงานอยู่จะยังคงอยู่บนบัญชีที่พวกมันเริ่มต้นด้วย ประวัติการสนทนา การตั้งค่า ทักษะ และปลั๊กอินถูกใช้ร่วมกันข้ามบัญชี ดังนั้น `claude --continue` ในโฟลเดอร์เดียวกันจะหยิบจากจุดที่คุณค้างไว้บนบัญชีใหม่

เมื่อมีมากกว่าหนึ่งบัญชี แผงจะแสดงขีดจำกัดของแต่ละบัญชีเคียงข้างกัน โดยมีบัญชีที่ใช้งานอยู่ทำเครื่องหมายไว้ โดยค่าเริ่มต้น Omarchy จะแจ้งเตือนคุณเมื่อบัญชีที่ใช้งานอยู่ผ่าน 95% ของขีดจำกัด และการคลิกการแจ้งเตือนจะสลับไปยังบัญชีที่มีพื้นที่เหลือมากที่สุด วางเมาส์เหนือบรรทัดของบัญชีในแผงและคลิก Autoswitch ที่ปรากฏข้าง Use (หรือกด `m`) หรือรัน `omarchy agent account mode auto` เพื่อให้มันสลับด้วยตัวเองแทน; ขณะที่มันเปิดอยู่ Autoswitch จะแทนที่ Use และการคลิกมันอีกครั้งจะกลับไปเป็นการแจ้งเตือน เพิ่มตัวเลขเพื่อเปลี่ยนเกณฑ์ เช่นใน `omarchy agent account mode auto 90` หากทุกบัญชีเกินเกณฑ์ คุณจะได้รับแจ้งเกี่ยวกับเรื่องนั้นหนึ่งครั้ง พร้อมกับว่าบัญชีใดจะว่างก่อน ขณะที่บัญชีที่ใช้งานอยู่ภายใน 15 จุดจากเกณฑ์ของมัน (80% ที่ค่าเริ่มต้น) ขีดจำกัดของมันจะถูกตรวจสอบทุกสามนาทีแทนที่จะเป็นทุก 15 นาที

`omarchy agent account list` แสดงทุกบัญชีและขีดจำกัดล่าสุดของพวกมัน `omarchy agent account remove work` ลบบัญชีหนึ่ง และ `omarchy agent account rename primary Hey` เปลี่ยนชื่อบัญชีหนึ่ง (หรือคลิกชื่อบัญชีในแผง) คำสั่งเหล่านี้ทำงานบนบัญชีของเอเจนต์เริ่มต้นของคุณ; ในการเข้าถึงผู้ให้บริการอื่น ให้ระบุชื่อมันก่อน เช่นใน `omarchy agent account use codex side` การเข้าสู่ระบบที่คุณมีอยู่แล้วใน `~/.claude` หรือ `~/.codex` คือบัญชี _Main_ ของ Codex จะยังคงอยู่ที่เดิม; ของ Claude จะรออยู่ในโฟลเดอร์ของตัวเองขณะที่บัญชีอื่นใช้งานอยู่ บัญชีที่ไม่ได้ใช้งานนานกว่าประมาณแปดชั่วโมงอาจแสดง _Sign-in required_; คลิกมันเพื่อลงชื่อบัญชีนั้นเข้าใช้อีกครั้งในแผงเลย หรือสลับไปยังมันและเริ่ม session ซึ่งจะรีเฟรชการลงชื่อเข้าใช้ด้วยตัวเอง MCP server ที่คุณเพิ่มด้วย `claude mcp add` จะเข้าถึงทุกบัญชี Claude เนื่องจากพวกมันทั้งหมดทำงานใน `~/.claude`; สำหรับ Codex และ Grok เซิร์ฟเวอร์ที่คุณมีเมื่อบัญชีถูกเพิ่มจะตามไปกับบัญชีนั้น แต่เซิร์ฟเวอร์ที่เพิ่มภายหลังจะเข้าถึงเฉพาะบัญชีที่คุณเพิ่มพวกมันเข้าไป Claude Desktop เก็บการลงชื่อเข้าใช้ของตัวเองไว้ และเครื่องมือ Codex หรือ Grok ที่กำหนดค่าด้วยเส้นทางแบบสัมบูรณ์ไปยังไบนารี CLI จะไม่ทำตามการสลับ `CLAUDE_CONFIG_DIR`, `CODEX_HOME` หรือ `GROK_HOME` ที่ชัดเจนจะมีลำดับความสำคัญกว่าบัญชีที่เลือก

### การวินิจฉัยการแครช

Omarchy เฝ้าดู systemd-coredump สำหรับการแครชของโปรเซส เมื่อบางสิ่ง segfault คุณจะได้รับการแจ้งเตือน "Process crashed" — คลิกมัน และการแครชจะถูกส่งมอบให้เอเจนต์เริ่มต้นของคุณพร้อมกับ diagnose-crash skill ของ Omarchy ซึ่งจะแนะนำเอเจนต์ตลอดการสร้างข้อเท็จจริงจาก core dump และตัดสินใจว่าการแครชนั้นคุ้มค่าที่จะรายงานไปยัง upstream หรือไม่ คุณยังสามารถรันมันด้วยมือกับ PID ใด ๆ จาก `coredumpctl list` ด้วย `omarchy agent crash <pid>` ได้

การเฝ้าดูเปิดอยู่โดยค่าเริ่มต้น ปิดมันใต้ _Trigger > Toggle > Crash Capture_ (หรือด้วย `omarchy toggle crash-capture`) และการแจ้งเตือนจะหยุด; `omarchy agent crash <pid>` ยังคงทำงานด้วยมือได้

การแครชยังสามารถถูกปิดเสียงได้ครั้งละหนึ่งโปรแกรม ซึ่งคือสิ่งที่การวินิจฉัยเสนอให้คุณในตอนท้าย `omarchy crash mute hyprland` หยุดการแจ้งเตือนสำหรับโปรแกรมนั้นเท่านั้น `omarchy crash mute hyprland off` นำมันกลับมา และ `omarchy crash mute` ด้วยตัวเองจะแสดงรายการสิ่งที่คุณปิดเสียงไว้ มันรับเส้นทางของไบนารีได้พอ ๆ กับชื่อของมัน ดังนั้น `omarchy crash mute /usr/bin/hyprland` ทำสิ่งเดียวกัน ใส่เครื่องหมายคำพูดรอบชื่อที่มีช่องว่าง เช่นใน `omarchy crash mute 'Some App'` ทุกอย่างอื่นยังคงแจ้งเตือน และโปรแกรมที่ปิดเสียงไว้ยังคงแครชอยู่ — สิ่งนี้ซ่อนการเตือนความจำ มันไม่ได้แก้ไขอะไรเลย

### แอปเดสก์ท็อป

เมนู _Install > AI_ ยังมีแอป AI แบบกราฟิกอยู่สองสามแอป: Antigravity Desktop, แอปเดสก์ท็อป ChatGPT, แอปเดสก์ท็อป Claude (เบต้าบน Linux ของ Anthropic พร้อมแท็บ Chat, Cowork และ Claude Code), Grok Bot สำหรับแชทกับโมเดลของ xAI, Herdr Desktop, Hermes Desktop, OpenClaw, แอปเดสก์ท็อป Perplexity และ T3 Code Grok Bot คือแอปแชทบนเดสก์ท็อป ส่วน coding agent คือคำสั่ง `grok`

Hermes Desktop คือตัวที่คุณต้องรู้ เนื่องจากเครื่องหนึ่งมี Hermes เพียงหนึ่งเดียว และมันเป็นของแอป: Hermes ถูกติดตั้งผ่านแอปเท่านั้นตลอดไป และคำสั่ง `hermes` ที่เอเจนต์เริ่มต้นรันคือของแอป การเลือก Hermes เป็นเอเจนต์เริ่มต้นจะติดตั้งสิ่งเดียวกับที่รายการ _Install > AI_ ทำ: แพ็กเกจ และ runtime ของ Hermes ใต้ `~/.hermes` ที่ตั้งค่าโดยตัวติดตั้งของ Hermes เอง ซึ่งใช้เวลาสองสามนาทีในครั้งแรก runtime นั้นคือ Hermes หนึ่งเดียวที่คำสั่ง `hermes` ในเทอร์มินัล เอเจนต์เริ่มต้น และแอปทั้งหมดใช้ และมันอัปเดตตัวเองด้วย `hermes update` แทนที่จะรอการเปิดตัวของ Omarchy การติดตั้งมันยังมอบธีม Omarchy ให้ Hermes ในชื่อสกิน `omarchy` ซึ่งทุกพื้นผิวของ Hermes จะทำตามเมื่อคุณเปลี่ยนธีม; เลือกอย่างอื่นใต้การตั้งค่า Appearance ของ Hermes หรือด้วย `/skin` หากคุณอยากให้มันไม่ทำเช่นนั้นมากกว่า และ Omarchy จะปล่อยตัวเลือกนั้นไว้ตามลำพัง การลบแอปใต้ _Remove > AI_ จะปิด Hermes ก่อน รวม gateway เข้าไปด้วย นำ runtime นั้นไปกับมัน และเก็บแชท ความทรงจำ และทักษะที่ Hermes เขียนให้ตัวเองไว้ เว้นแต่คุณจะบอกเป็นอย่างอื่น: มันจะถาม โดยค่าเริ่มต้นคือไม่ ว่าข้อมูลนั้นและการตั้งค่าการเชื่อมต่อของคุณควรหายไปด้วยหรือไม่

ประสบการณ์เดสก์ท็อปของ OpenClaw คือ Control UI ของมัน ซึ่งเปิดเป็นเว็บแอปที่สนับสนุนโดย local gateway ของมันเอง OpenClaw อาศัยอยู่ใน `~/.openclaw` และอัปเดตตัวเอง: ใช้ปุ่ม "Update Gateway" ของ Control UI หรือรัน `openclaw update` และ gateway จะรีสตาร์ทบนรุ่นใหม่ Omarchy เพียงเลือก release ที่การติดตั้งใหม่เอี่ยมจะเริ่มต้นจากเท่านั้น การลบ OpenClaw ใต้ _Remove > AI_ จะนำ gateway service และแอปไปกับมัน จากนั้นถามว่า `~/.openclaw` ควรหายไปด้วยหรือไม่ เนื่องจากที่นั่นเก็บแชทและข้อมูลประจำตัวของคุณไว้ข้าง ๆ OpenClaw เองและ plugin runtime ที่มันดาวน์โหลด; ค่าเริ่มต้นจะเก็บมันไว้ และการติดตั้ง OpenClaw อีกครั้งจะหยิบมันกลับขึ้นมา

Herdr Desktop คือแอปเดสก์ท็อป [Herdr](https://herdr.dev): spaces, tabs และ panes ของเทอร์มินัลและ coding agent ที่ยังคงทำงานในแกนหลักของมันเมื่อคุณปิดหน้าต่าง มันมาจากตัวติดตั้งของ Herdr เองแทนที่จะเป็นแพ็กเกจ ดังนั้นมันอาศัยอยู่ใน `~/.local/share/herdr-app`, นำแกนหลักของมันมาใน `~/.local/bin/herdr-core` เมื่อคุณยังไม่มี และอัปเดตทั้งตัวมันเอง มันอยู่ข้างคำสั่ง `herdr` ที่ Omarchy ส่งมาบน `Super + Ctrl + Return` แทนที่จะแทนที่มัน และได้รับคีย์โดยตรงของคำสั่งนั้น: `Alt + Return` และ `Alt + Shift + Return` แบ่ง pane ลงหรือขวา `Alt + Escape` ปิดมัน `Ctrl + Alt + Arrow` ย้ายระหว่าง panes, `Alt + 1..9` และ `Alt + Left/Right` เลือก tab และ `Alt + Up/Down` ย้ายระหว่าง spaces `Ctrl + 1..9` เลือก space และ `Alt + Shift + Up/Down` ก้าวผ่านเอเจนต์ คีย์ prefix แบบ `Ctrl + Space` ยังคงเป็นเทอร์มินัลเท่านั้น เนื่องจากแอปไม่สามารถถือคีย์ Ctrl ธรรมดาไว้สำหรับลำดับได้ Omarchy เขียนสิ่งเหล่านี้ลงใน `~/.config/herdr-app/keys.json` และ `omarchy-refresh-herdr-app` จะใส่พวกมันกลับคืน การติดตั้งมันจะเลือกธีม Omarchy ของ Herdr ซึ่งจะทำตามธีม Omarchy ของคุณตั้งแต่นั้นเป็นต้นมา Herdr เก็บหนึ่งธีมสำหรับ light mode และอีกหนึ่งสำหรับ dark ดังนั้นหลังจากสลับระหว่างธีม Omarchy แบบเข้มและแบบสว่าง ให้เลือก Omarchy ในตัวเลือกธีมของ Herdr อีกครั้งสำหรับโหมดอื่น

T3 Code ทำงานจาก release แบบ AppImage อย่างเป็นทางการใน `~/.local/share/t3code` แทนที่จะมาจากแพ็กเกจ ดังนั้นมันจึงอัปเดตตัวเอง การติดตั้งมันจะถามว่าจะเริ่มต้นบนช่อง Stable หรือ Nightly; สลับภายหลังได้ในการตั้งค่าของ T3 Code เธรดและการตั้งค่าของคุณอาศัยอยู่ใน `~/.t3` และการลบ T3 Code ใต้ _Remove > AI_ จะนำพวกมันไปกับมัน

### โมเดลแบบโลคอล

รันโมเดลแบบเปิดบนเครื่องของคุณเองสำหรับ coding agent ของคุณ พรอมต์และโค้ดของคุณจะอยู่บนเครื่อง; ไม่มีอะไรที่ส่งไปยังโมเดลออกจากเครื่อง เริ่มต้นด้วย:

```bash
omarchy agent local use best
```

หรือในแผงเอเจนต์ในแถบบนสุด เลือก + แล้วเลือก Local AI ซึ่งจะแสดงขึ้นเมื่อโมเดลพอดีกับเครื่องนี้ ครั้งแรก สิ่งนี้จะติดตั้ง Podman ซึ่งรันโมเดล และบนเครื่อง NVIDIA จะติดตั้ง container toolkit ของ NVIDIA ซึ่งให้ GPU แก่พวกมัน จากนั้น Omarchy จะเลือกโมเดลที่แนะนำสำหรับเครื่องนี้ ดาวน์โหลดมัน และเริ่มมัน คาดว่าจะมีการดาวน์โหลดขนาดหลายสิบ GB และหน่วยความจำส่วนใหญ่ของเครื่องจะถูกใช้งานขณะที่โมเดลทำงาน: Flash Next ใช้ประมาณ 100 GiB กับบริบทเต็มขนาด 256K ของมัน หากโมเดลอื่น ๆ ยึดหน่วยความจำที่มันต้องการไว้ มันจะถูกตั้งค่าในสถานะหยุด พร้อมที่จะเริ่มเมื่อคุณหยุดตัวหนึ่ง โมเดลจะหยุดเมื่อออกจากระบบ; หยุดมันด้วยตัวเองเมื่อคุณต้องการหน่วยความจำสำหรับอย่างอื่น

`omarchy agent local list` แสดงตัวเลือกและอธิบายว่าทำไมบางตัวจึงไม่พอดี ในการตั้งค่าอีกตัวหนึ่ง ให้รัน `omarchy agent local use <recipe>` วันนี้ `qwen3.8-flash-next-gufo` และ `qwen3.8-27b-gufo` พร้อมใช้งานสำหรับเครื่อง Strix Halo ขนาด 128 GB; ตัว 27B ใช้ประมาณ 40 GiB ดังนั้นมันจึงเหลือพื้นที่สำหรับงานอื่น บนแล็ปท็อปขนาด 64 GB ที่มี Arc B390 ของ Intel, `qwen3.6-35b-a3b-llamacpp` ทำงานในประมาณ 30 GiB recipe และคำแนะนำใหม่ ๆ มาพร้อมกับ `omarchy update` ผ่านแพ็กเกจ

ทุกโมเดลที่คุณตั้งค่าจะได้รับบรรทัดของตัวเองในแผงเอเจนต์ ข้างการสมัครสมาชิกของคุณ: เล่นเพื่อเริ่มมัน หยุดชั่วคราวเพื่อหยุดมันและปลดปล่อยหน่วยความจำของมัน และปุ่มเทอร์มินัลเพื่อเปิดเอเจนต์ของคุณบนมัน หลายตัวสามารถทำงานพร้อมกันได้เมื่อพวกมันพอดีในหน่วยความจำร่วมกัน; หากตัวหนึ่งไม่พอดี Omarchy จะบอกว่าโมเดลที่กำลังทำงานตัวใดให้หยุด ลากบรรทัดเพื่อจัดลำดับพวกมันใหม่ และกด Delete บนบรรทัดที่เลือกเพื่อลบโมเดลและการดาวน์โหลดของมัน

ทุกโมเดลที่คุณตั้งค่ายังได้รับรายการของตัวเองในตัวเรียกใช้แอป ภายใต้ชื่อของโมเดลและพร้อมโลโก้ของผู้สร้างมัน ในแบบเดียวกับการลงชื่อเข้าใช้ Claude, Codex หรือ Grok ที่เพิ่มรายการหนึ่ง มันเปิดเอเจนต์ของคุณบนโมเดลนั้น และเริ่มโมเดลก่อนหากมันยังไม่ได้ทำงาน: เทอร์มินัลจะแสดงมันกำลังโหลดและส่งมอบให้เอเจนต์เมื่อมันพร้อม การลบโมเดลจะลบรายการของมัน

โมเดลจะยังคงทำงานต่อไปในแบบเดียวกับที่มันถูกตั้งค่าไว้ ดังนั้นการอัปเดต Omarchy จะไม่รีสตาร์ทโมเดลภายใต้เอเจนต์ของคุณเลย เมื่อ Omarchy มี runtime ที่ใหม่กว่าหรือ weights ที่ใหม่กว่าสำหรับโมเดลที่คุณตั้งค่าไว้ บรรทัดของมันจะแสดงปุ่มอัปเดต: กดมันและโมเดลจะถูกตั้งค่าอีกครั้งในเบื้องหลัง โดยดาวน์โหลดเฉพาะสิ่งที่เปลี่ยนแปลง และรีสตาร์ทบนรุ่นใหม่ โมเดลที่หยุดอยู่จะยังคงหยุดอยู่ `omarchy agent local update` ทำสิ่งเดียวกันสำหรับทุกโมเดลจากเทอร์มินัล

จากบรรทัดคำสั่ง `omarchy agent local start <recipe>` และ `omarchy agent local stop <recipe>` ทำสิ่งเดียวกัน `omarchy agent local status` แสดงทุกโมเดล และ `omarchy agent --local` เปิดเอเจนต์เริ่มต้นของคุณบนโมเดลล่าสุดที่คุณเริ่ม pi, OpenCode และ Qwen Code สามารถใช้โมเดลหนึ่งได้; กับค่าเริ่มต้นอื่นใด มันจะเปิดใน pi pi ยังแสดงรายการทุกโมเดลที่คุณตั้งค่าไว้ และโมเดลบนเครื่องที่คุณจับคู่ด้วย ในตัวเลือกโมเดลของมันเอง ดังนั้น `pi` ธรรมดาจึงเข้าถึงพวกมันได้เช่นกัน ไคลเอนต์ที่เข้ากันได้กับ OpenAI ใด ๆ ก็สามารถเชื่อมต่อได้เช่นกัน: `status` แสดงที่อยู่ของแต่ละโมเดล (ตัวแรกคือ `http://127.0.0.1:11435/v1`) ชื่อ recipe คือโมเดล และคีย์อยู่ใน `~/.config/omarchy/agent-local/key`

`omarchy agent local remove <recipe>` ลบโมเดลและการดาวน์โหลดที่ไม่มีโมเดลอื่นใช้

runtime ของบุคคลที่สามจะถูกระบุด้วยผู้เผยแพร่ของพวกมัน Omarchy รันทุกโมเดลโดยไม่มีการเข้าถึงเครือข่าย

### Local LLMs

Omarchy แนะนำสองวิธีในการรันโมเดล LLM แบบโลคอล: LM Studio และ Ollama LM Studio มีอินเทอร์เฟซ GUI สำหรับค้นหาโมเดลแบบ open-weight ติดตั้งพวกมัน และรันพวกมัน เป็นวิธีที่ยอดเยี่ยมในการเริ่มต้นได้อย่างง่ายดาย Ollama เสนอ CLI สำหรับทำเช่นเดียวกัน แต่หากคุณเพิ่งเริ่มใช้โมเดลแบบโลคอล ผมจะเริ่มด้วย LM Studio คุณสามารถติดตั้งอย่างใดอย่างหนึ่งใต้ _Install > AI_ ใน Omarchy Menu

### The Omarchy Skill

ทักษะของเอเจนต์ช่วยให้ AI ใช้เครื่องมือเฉพาะในวิธีเฉพาะ และ Omarchy ส่งมาพร้อมกับทักษะเริ่มต้นสำหรับการปรับแต่งระบบ เช่นการปรับแต่ง Hyprland config ของคุณ การปรับแถบ หรือแม้แต่การสร้างธีมใหม่ตั้งแต่ต้น มันถูก symlinked เข้าไปในไดเรกทอรีทักษะสำหรับ Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` และแต่ละ `~/.hermes/profiles/*/skills`) และตำแหน่งทั่วไป `~/.agents/skills` ดังนั้น harness ส่วนใหญ่จึงหยิบมันขึ้นมาโดยอัตโนมัติ

แต่คุณควรถือว่าทักษะนี้เป็นสิ่งทดลอง โมเดลที่แตกต่างกันจะใช้มันให้ผลที่แตกต่างกัน ดีที่สุดคือรันใน plan mode ก่อน เพื่อให้คุณมีแนวคิดว่าเอเจนต์อยากเปลี่ยนแปลงอะไร จากนั้นจงเตรียมพร้อมที่จะย้อนกลับการเปลี่ยนแปลง หรือแม้แต่เรียกใช้ `omarchy reinstall configs` หากเอเจนต์ทำทุกอย่างเละเทะ
