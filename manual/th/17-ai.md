### การติดตั้งและอัปเดตเอเจนต์

ยกเว้น Hermes และ OpenClaw เอเจนต์เหล่านี้ใช้การติดตั้งแบบขี้เกียจของ mise: การเรียกใช้ครั้งแรกจะติดตั้ง CLI และการเรียกใช้ครั้งต่อ ๆ ไปจะใช้มันซ้ำ mise ยังตรวจสอบเอเจนต์ที่ติดตั้งแล้วว่ามีรุ่นใหม่หรือไม่มากที่สุดหนึ่งครั้งทุกสี่ชั่วโมง ทันทีก่อนที่มันจะเริ่มหรือในพื้นหลังที่พรอมต์ของเชลล์ หากการอัปเดตนั้นล้มเหลวหรือคุณออฟไลน์ รุ่นที่ติดตั้งไว้จะทำงาน `omarchy update` อัปเดตเอเจนต์ที่ติดตั้งไว้พร้อมกับส่วนที่เหลือของ Omarchy และ `mup` อัปเดตเฉพาะเครื่องมือที่ mise จัดการเท่านั้น

ตัวอัปเดตของเอเจนต์เอง เช่น `claude update`, `codex update`, หรือปุ่มอัปเดตในแอป จะไม่อัปเดตสิ่งที่ติดตั้งไว้ซึ่ง mise จัดการ `codex update` จะล้มเหลว และ `claude update` อาจรายงานว่าสำเร็จในขณะที่ติดตั้งสำเนาแยกต่างหากที่ mise ไม่ได้ติดตาม หากคุณอยากใช้ตัวติดตั้งและตัวอัปเดตดั้งเดิมของเอเจนต์มากกว่า ให้เพิ่มมันไปยัง `disable_tools`; ดู [เครื่องมือ CLI ที่ติดตั้งไว้ล่วงหน้า](18-development-tools.md#preinstalled-cli-tools)

เพื่อติดตั้งเครื่องมือแบบขี้เกียจที่กำหนดค่าไว้ทั้งหมดก่อนที่คุณจะต้องการใช้ ให้รัน `mise install --include-lazy` ซึ่งรวมถึงเครื่องมือ CLI เริ่มต้นอื่น ๆ ของ Omarchy ตลอดจนเอเจนต์ด้วย ดู [เครื่องมือ CLI ที่ติดตั้งไว้ล่วงหน้า](18-development-tools.md#preinstalled-cli-tools) สำหรับการติดตั้งเครื่องมือเพียงตัวเดียวหรือการใช้การติดตั้งของคุณเอง

`grok` ถูกติดตั้งผ่านแพ็กเกจ `grok` โดยตรงของ mise ในวิธีเดียวกับ `claude` และ `codex` รัน `grok` หรือเลือกมันภายใต้ _Agent > Harness_ ข้ามตัวติดตั้ง `curl | bash` บน x.ai เส้นทางนั้นจะวางสำเนาที่สองไว้ใน `~/.grok/bin`, นำหน้ามันบน `PATH`, และเขียนทับตัวห่อหุ้มของ Omarchy

`dsh` เปิด UI บนเบราว์เซอร์ของมันที่ `127.0.0.1:3080` โดยใช้ไดเรกทอรีที่เรียกใช้เป็นเวิร์กสเปซเริ่มต้น UI บนเบราว์เซอร์ของมันไม่รับพรอมต์เริ่มต้น ดังนั้น `omarchy agent prompt` จะเปิดมันโดยมีพรอมต์อยู่บนคลิปบอร์ดของคุณให้วาง Omarchy เริ่มต้นมันด้วยพรีเซ็ตสิทธิ์แบบไม่ต้องขออนุมัติของ DeepSeek DeepSeek Harness อัปโหลดบันทึกเซสชันไปยัง DeepSeek เมื่อคุณใช้ API โมเดลอย่างเป็นทางการของมัน; ปิดสิ่งนั้นภายใต้ _Settings > General > Upload Session Log_ ใน UI บนเบราว์เซอร์ของมัน ข้อเสนอแนะที่คุณส่งให้มันก็จะถูกอัปโหลดพร้อมกับเซสชันด้วย เว้นแต่คุณจะเริ่มต้นมันด้วย `DSH_TELEMETRY_MODE=DISABLED`

### เอเจนต์เริ่มต้น

เลือกเอเจนต์เริ่มต้นของคุณด้วย `omarchy default agent <name>` หรือภายใต้ _Agent > Harness_ ใน Omarchy Menu (`Super + Space`) หากเอเจนต์ยังไม่ได้ติดตั้ง การเลือกมันจะติดตั้งมันก่อน และมันยังจะได้รับตัวเรียกใช้ของมันเองในตัวเรียกใช้แอป ข้าง ๆ Agent Omarchy ใหม่จะเชิญคุณให้เลือกสิ่งนี้ด้วยการแจ้งเตือนเพียงครั้งเดียว

การเลือก Claude ยังพยายามตั้งค่าส่วนขยายเบราว์เซอร์ของมันสำหรับ Chromium, Chrome, Brave, Brave Origin, และ Edge ด้วย การตั้งค่าส่วนขยายใช้กับผู้ใช้ทุกคนและอาจขอรหัสผ่านระบบของคุณ; การยกเลิกหรือการติดตั้งส่วนขยายที่ล้มเหลวยังคงเลือกและเรียกใช้ Claude รีสตาร์ทเบราว์เซอร์ของคุณ เปิดใช้งานส่วนขยายหากได้รับแจ้ง และลงชื่อเข้าใช้ Claude เพื่อเชื่อมต่อมันให้เสร็จ รัน `/chrome` ใน Claude เพื่อตรวจสอบการเชื่อมต่อ Firefox และ Zen ไม่รองรับส่วนขยายนี้ หาก Claude เคยเป็นค่าเริ่มต้นของคุณอยู่แล้วก่อนที่การตั้งค่านี้จะถูกเพิ่มเข้ามา ให้เลือกมันอีกครั้งเพื่อติดตั้งส่วนขยาย

เมื่อคุณเลือกแล้ว `Super + Shift + Ctrl + A` จะเรียกใช้เอเจนต์เริ่มต้นในหน้าต่างเทอร์มินัลเฉพาะ (หรือแสดงตัวเลือกหากคุณยังไม่ได้เลือก) คุณยังสามารถเรียกใช้มันตรงไปยังงานได้ด้วย `omarchy agent prompt "Review this project"` Freebuff และ DeepSeek Harness ไม่รับพรอมต์เริ่มต้น ดังนั้นพวกมันจะเปิดโดยมีพรอมต์อยู่บนคลิปบอร์ดของคุณให้วางแทน เอเจนต์ที่เรียกใช้ด้วยวิธีนี้จะทำงานโดยไม่มีผู้ดูแลในโหมดไม่หยุดถามของแต่ละตัว ดังนั้นเตรียมตัวให้พร้อมเพราะพวกมันจะลงมือทำสิ่งต่าง ๆ จริง ๆ! MiniMax Code ไม่มีโหมดแบบนั้นสำหรับเซสชันแบบโต้ตอบของมัน ดังนั้นมันจะขอสิทธิ์ตามปกติ และเนื่องจากเอเจนต์ปฏิเสธที่จะจดจำความเชื่อถือสำหรับไดเรกทอรีโฮมของคุณ การเรียกใช้จาก `$HOME` จะเริ่มต้นใน `~/Work` แทน

ยังมีทางลัดในเทอร์มินัลด้วย: `a` รันเอเจนต์เริ่มต้นแบบอินไลน์ในเทอร์มินัลปัจจุบัน ขณะที่ `c`, `cx`, และ `cy` เริ่ม OpenCode, Claude Code, และ Codex โดยตรง (อีกครั้งในโหมดอนุมัติอัตโนมัติของพวกมัน) การเปลี่ยนธีมยังซิงค์ไปยังเอเจนต์ด้วย: Claude Code, Pi, OpenCode, และ Hermes (เมื่อ Omarchy ได้ติดตั้งมันแล้ว) ทั้งหมดจะตามไปเมื่อคุณเปลี่ยนธีม Omarchy

### คำแนะนำสำหรับเอเจนต์ของคุณ

กฎส่วนตัวสำหรับเอเจนต์ทุกตัวอยู่ใน `~/.agents/AGENTS.md` ข้าง ๆ สกิลที่แชร์กันใน `~/.agents/skills` เปิดมันภายใต้ _Agent > Instructions_ ซึ่งยังเชื่อมโยงมันไปยังฮาร์เนสแต่ละตัวที่เก็บไฟล์โกลบอลของมันเองด้วย: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` ของ Copilot, และอื่น ๆ Crush และ Amp อ่านลิงก์ `~/.config/AGENTS.md` ขณะที่ omp, Kimi, และ DeepSeek Harness อ่าน `~/.agents/AGENTS.md` โดยตรง การเลือกเอเจนต์เริ่มต้นก็เชื่อมโยงมันด้วย ไฟล์คำแนะนำที่คุณมีอยู่แล้วจะกลายเป็นไฟล์ที่แชร์กันหากยังไม่มีไฟล์ดังกล่าวอยู่; มิฉะนั้นมันจะถูกเก็บไว้ข้าง ๆ ลิงก์เป็น `.bak` รัน `omarchy agent instructions` เพื่อเชื่อมโยงอีกครั้งหลังจากติดตั้งเอเจนต์อีกตัว

### แผงเอเจนต์

แถบด้านบนมีไอคอนเอเจนต์ ก่อนที่คุณจะตั้งค่าเอเจนต์ แผงของมันจะพาคุณผ่านการลงชื่อเข้าใช้ Claude, Codex, หรือ Grok, และตัวแรกจะกลายเป็นเอเจนต์เริ่มต้นของคุณ หลังจากนั้น แผงจะรวมการสมัครสมาชิกทุกอย่างไว้ในหน้าเดียว: เอเจนต์และบัญชีแต่ละตัวพร้อมแพ็กเกจของมัน มิเตอร์สำหรับขีดจำกัดเซสชัน 5 ชั่วโมงและขีดจำกัดรายสัปดาห์แต่ละอย่างพร้อมเวลาจนกว่าจะรีเซ็ต (วางเมาส์เหนือเพื่อดูเปอร์เซ็นต์ที่แน่นอน) หรือยอดเงินแบบเติมเงินที่เหลือ ภายใต้บรรทัดที่สลับวนผ่านสิ่งที่คุณใช้ไปในทุกตัว เช่น โทเคนในสัปดาห์นี้และโมเดลที่คุณใช้มากที่สุด ภายใต้ _Make something cool_ มันเสนอพรอมต์เริ่มต้นสำหรับธีม ปลั๊กอิน แอป หรือเกมใหม่ที่มอบงานให้เอเจนต์เริ่มต้นของคุณ แอปถูกสร้างในแบบเดียวกับที่ Hype, Monologue, และ Omacut ของ Omarchy เองถูกสร้าง ใน C++ และ Qt Quick ตามสกิลเอเจนต์ omarchy-make-app และคอมไพเลอร์และชิ้นส่วน Qt ที่พวกมันต้องการได้รับการติดตั้งมาให้แล้ว เกมเป็นหน้า three.js เดียวใน `~/Games/vibes` ตามสกิลเอเจนต์ omarchy-make-game และทั้งหมดเปิดจากตัวเรียกใช้ Game Vibes เดียวในธีมปัจจุบัน; พวกมันโหลด three.js จากเว็บ ดังนั้นจึงต้องมีการเชื่อมต่อเพื่อเริ่มต้น Claude Code, Codex, Grok, Kimi, Cursor และสิทธิ์ Grok Bot ของมัน, GitHub Copilot, Muse, Antigravity, และ Devin ได้รับการครอบคลุมตั้งแต่แรกพร้อมขีดจำกัดของพวกมัน, Kimchi พร้อมแพ็กเกจ เครดิตแบบเติมเงิน และงบการใช้จ่ายของมัน และ Hermes, Mistral Vibe, และ Qwen Code จะแสดงเซสชันและโทเคนของพวกมันเมื่อคุณได้ใช้งานพวกมันแล้ว แพ็กเกจและคีย์ของผู้ให้บริการที่คุณใช้ผ่าน pi, omp, หรือ opencode ก็ปรากฏเช่นกัน: OpenCode Zen และ Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan, และ Synthetic พร้อมขีดจำกัดของพวกมัน; OpenRouter และ DeepSeek พร้อมยอดเงินแบบเติมเงินของพวกมัน; Fireworks พร้อมการใช้จ่ายย้อนหลัง 30 วันของมัน; และโมเดลที่คุณรันบนฮาร์ดแวร์ของคุณเองภายใต้ Local models เอเจนต์ทุกตัวถูกนับเพียงครั้งเดียว ภายใต้ผู้ที่เรียกเก็บเงินจากคุณสำหรับมัน ไม่ว่าคุณจะขับมันผ่านฮาร์เนสจำนวนเท่าใดก็ตาม

คลิกซ้ายที่ไอคอนแถบหรือกด `Super + Ctrl + X` สำหรับแผง คลิกขวาเพื่อเรียกใช้เอเจนต์เริ่มต้นของคุณ และคลิกกลางเพื่อรีเฟรช บันทึกการใช้งานที่อยู่เบื้องหลังมันถูกสร้างใหม่ทุก 15 นาทีโดย `omarchy agent usage update` และแผงยังสามารถรวมการใช้งานจากเครื่องอื่น ๆ ของคุณผ่านโฟลเดอร์ที่ซิงค์ไว้ได้ด้วย ดู README ภายใต้ `$OMARCHY_PATH/shell/plugins/agents/` สำหรับการตั้งค่าทั้งหมด

### หลายการสมัครสมาชิก

หากคุณจ่ายสำหรับแพ็กเกจ Claude, Codex, หรือ Grok มากกว่าหนึ่งแพ็กเกจ — สมมติว่ามี Max ส่วนตัวและอีกอันสำหรับงาน — Omarchy สามารถให้พวกมันทั้งหมดลงชื่อเข้าใช้ไว้และย้ายไปมาระหว่างพวกมันได้ เพิ่มการสมัครสมาชิกด้วย + ในแผงเอเจนต์ ซึ่งจะพาคุณผ่านมันตรงนั้นเลย หรือด้วย `omarchy agent account add claude Work` (หรือ `codex`, หรือ `grok`) มันจะติดตั้ง CLI หากมันหายไป บัญชีแรกสำหรับผู้ให้บริการจะลงชื่อเข้าใช้ผ่านเบราว์เซอร์ปกติของคุณ ตรงจุดที่ CLI มองหาเสมอ บัญชีหลังจากนั้นทุกบัญชีจะลงชื่อเข้าใช้ผ่านหน้าต่างส่วนตัว ดังนั้นบัญชีที่เบราว์เซอร์ของคุณลงชื่อเข้าใช้อยู่แล้วจะไม่ถูกหยิบขึ้นมาโดยผิดพลาด; ลงชื่อเข้าใช้ที่นั่นเป็นบัญชีที่คุณกำลังเพิ่ม และปิดหน้าต่างส่วนตัวใด ๆ ที่คุณเปิดอยู่ก่อน อย่าออกจากระบบของ CLI เพื่อทำสิ่งนี้: การออกจากระบบจะเพิกถอนการลงชื่อเข้าใช้ที่บันทึกไว้ และบัญชีนั้นจะต้องถูกเพิ่มอีกครั้ง

เพื่อคัดลอกการเข้าสู่ระบบการสมัครสมาชิกของคุณไปยังเครื่อง Omarchy อีกเครื่องผ่าน SSH ให้รัน `omarchy agent account copy user@laptop` ผู้ส่งจะจัดเตรียมตัวรับชั่วคราวเมื่อปลายทางไม่มีมันติดตั้งไว้ ดังนั้นเครื่อง Omarchy รุ่นเก่ากว่าสามารถรับบัญชีได้โดยไม่ต้องอัปเดต ตัวรับที่ติดตั้งไว้จะมีความสำคัญเหนือกว่า สิ่งนี้คัดลอกการสมัครสมาชิก Claude, Codex, และ Grok ทั้งหมด; เพิ่มชื่อผู้ให้บริการเพื่อเลือกพวกมัน เช่นใน `omarchy agent account copy laptop claude` ชื่อบัญชีและ ID คำสั่งจะตรงกับต้นทาง รวมถึงบัญชีที่มีอยู่แล้วบนปลายทาง บัญชีปลายทางที่ไม่เกี่ยวข้องจะได้รับคำต่อท้ายที่เป็นตัวเลขหากชื่อของพวกมันขัดแย้งกัน และการตั้งค่า สกิล ปลั๊กอิน และประวัติการสนทนาจะยังคงอยู่ในเครื่องของแต่ละเครื่อง

ข้อมูลประจำตัวปลายทางที่มีอยู่จะถูกเก็บไว้ บัญชีต้นทางที่ลงชื่อเข้าใช้ที่นั่นแล้วจะมีชื่อของมันซิงค์โดยไม่แทนที่ข้อมูลประจำตัวของมัน; บัญชีอื่น ๆ จะถูกเพิ่มควบคู่ไปกับมัน เพื่อแทนที่ข้อมูลประจำตัวที่บันทึกไว้สำหรับบัญชีที่ตรงกัน ให้ใช้ `omarchy agent account copy --replace laptop claude` หลังจากออกจากเซสชันของบัญชีนั้นบนปลายทาง ปลายทางใหม่ยังจะได้รับบัญชีที่ใช้งานอยู่ของต้นทางและความต้องการในการสลับของมันด้วย; ปลายทางที่ตั้งขึ้นแล้วจะเก็บของมันเองไว้

ข้อมูลประจำตัวเดินทางผ่าน SSH และถูกเก็บไว้ในไฟล์ส่วนตัวบนปลายทาง ดังนั้นให้คัดลอกไปยังเครื่องที่คุณไว้ใจเท่านั้น นี่คือการคัดลอกครั้งเดียว ไม่ใช่การซิงโครไนซ์ต่อเนื่อง โทเคนรีเฟรชของ Codex สามารถถูกหมุนเวียนโดยเครื่องอื่นได้ ทำให้การเข้าสู่ระบบที่คัดลอกมาต้องต่ออายุ; การลงชื่อเข้าใช้แยกกันยังคงเป็นตัวเลือกที่เชื่อถือได้มากที่สุดสำหรับการใช้งานพร้อมกันบนหลายเครื่อง ดู [คำแนะนำการยืนยันตัวตนบัญชีของ Codex](https://developers.openai.com/codex/auth/ci-cd-auth)

หนึ่งบัญชีต่อผู้ให้บริการจะใช้งานอยู่ และเซสชันใหม่ทุกเซสชันจะเริ่มต้นเป็นมัน: `cx`, `cy`, `claude`, `codex`, หรือ `grok` ธรรมดา, สิ่งใดก็ตามที่เรียกใช้ผ่าน `omarchy agent`, และสคริปต์หรือโปรแกรมแก้ไขที่พบ CLI บน `PATH` สลับด้วย `omarchy agent account use work` (และกลับด้วย `omarchy agent account use main`) หรือในแผงโดยการกดหมายเลขของบัญชีแล้วกด `Enter` (หรือคลิกปุ่ม Use ของมัน) เซสชัน Claude ที่กำลังทำงานอยู่ก็สลับเช่นกัน ตั้งแต่ข้อความถัดไปของพวกมัน: เซสชัน Claude ทุกเซสชันทำงานใน `~/.claude` ซึ่งเก็บการลงชื่อเข้าใช้ของบัญชีที่ใช้งานอยู่เสมอ เซสชัน Claude ที่เริ่มในโฟลเดอร์ของบัญชีเองโดย Omarchy รุ่นเก่าจะเก็บการลงชื่อเข้าใช้นั้นไว้จนกว่ามันจะออก ดังนั้นการสลับจะระบุชื่อเซสชันเหล่านั้นและเสร็จสิ้นเองเมื่อพวกมันหายไป เซสชัน Codex และ Grok ที่กำลังทำงานอยู่จะอยู่กับบัญชีที่พวกมันเริ่มต้นด้วย ประวัติการสนทนา การตั้งค่า สกิล และปลั๊กอินถูกแชร์ข้ามบัญชี ดังนั้น `claude --continue` ในโฟลเดอร์เดียวกันจะดำเนินการต่อจากจุดที่คุณค้างไว้บนบัญชีใหม่

ด้วยมากกว่าหนึ่งบัญชี แผงจะแสดงขีดจำกัดของแต่ละบัญชีเคียงข้างกัน โดยบัญชีที่ใช้งานอยู่ถูกทำเครื่องหมายไว้ โดยเริ่มต้น Omarchy จะแจ้งเตือนคุณเมื่อบัญชีที่ใช้งานอยู่ผ่าน 95% ของขีดจำกัด และการคลิกการแจ้งเตือนจะสลับไปยังบัญชีที่มีพื้นที่เหลือมากที่สุด วางเมาส์เหนือบรรทัดของบัญชีในแผงและคลิก Autoswitch ที่ปรากฏข้าง ๆ Use (หรือกด `m`) หรือรัน `omarchy agent account mode auto` เพื่อให้มันสลับเองแทน; ขณะที่มันเปิดอยู่ Autoswitch จะแทนที่ Use และการคลิกมันอีกครั้งจะกลับไปแจ้งเตือน เพิ่มตัวเลขเพื่อเปลี่ยนเกณฑ์ เช่นใน `omarchy agent account mode auto 90` หากทุกบัญชีเกินเกณฑ์ คุณจะได้ยินเกี่ยวกับมันครั้งหนึ่ง พร้อมกับบัญชีใดจะว่างก่อน ขณะที่บัญชีที่ใช้งานอยู่ภายใน 15 จุดของเกณฑ์ของมัน (80% ที่ค่าเริ่มต้น) ขีดจำกัดของมันจะถูกตรวจสอบทุกสามนาทีแทนที่จะเป็นทุก 15 นาที

`omarchy agent account list` แสดงทุกบัญชีและขีดจำกัดล่าสุดของพวกมัน `omarchy agent account remove work` ลืมบัญชีหนึ่ง และ `omarchy agent account rename primary Hey` เปลี่ยนชื่อบัญชีหนึ่ง (หรือคลิกชื่อของบัญชีในแผง) คำสั่งเหล่านี้ทำงานบนบัญชีของเอเจนต์เริ่มต้นของคุณ; เพื่อไปถึงผู้ให้บริการอื่น ให้ระบุชื่อมันก่อน เช่นใน `omarchy agent account use codex side` การเข้าสู่ระบบที่คุณมีอยู่แล้วใน `~/.claude` หรือ `~/.codex` คือบัญชี _Main_ ของ Codex จะยังคงอยู่ที่เดิม; ของ Claude จะรอในโฟลเดอร์ของมันเองขณะที่บัญชีอื่นใช้งานอยู่ บัญชีที่ไม่ได้ใช้งานนานกว่าประมาณแปดชั่วโมงอาจแสดง _Sign-in required_; คลิกมันเพื่อลงชื่อเข้าใช้บัญชีนั้นอีกครั้งตรงในแผง หรือสลับไปยังมันและเริ่มเซสชัน ซึ่งจะรีเฟรชการลงชื่อเข้าใช้เอง เซิร์ฟเวอร์ MCP ที่คุณเพิ่มด้วย `claude mcp add` จะไปถึงทุกบัญชี Claude เนื่องจากพวกมันทั้งหมดทำงานใน `~/.claude`; สำหรับ Codex และ Grok เซิร์ฟเวอร์ที่คุณมีเมื่อบัญชีถูกเพิ่มจะตามไปยังมัน แต่เซิร์ฟเวอร์หลังจากนั้นจะไปถึงเฉพาะบัญชีที่คุณเพิ่มพวกมันไว้ Claude Desktop เก็บการลงชื่อเข้าใช้ของมันเอง และเครื่องมือ Codex หรือ Grok ที่กำหนดค่าด้วยเส้นทางสัมบูรณ์ไปยังไบนารี CLI จะไม่ตามการสลับ `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, หรือ `GROK_HOME` ที่ชัดเจนจะมีความสำคัญเหนือบัญชีที่เลือก

### การวินิจฉัยการแครช

Omarchy เฝ้าดู systemd-coredump สำหรับการแครชของกระบวนการ เมื่อคุณเลือกเอเจนต์เริ่มต้นแล้ว โปรแกรมใด ๆ ของคุณที่ดัมพ์คอร์จะนำการแจ้งเตือน "Process crashed" มา — คลิกมัน และการแครชจะถูกส่งให้เอเจนต์เริ่มต้นของคุณพร้อมกับสกิล omarchy-diagnose-crash ของ Omarchy ซึ่งจะพาเอเจนต์ผ่านการสร้างข้อเท็จจริงจากคอร์ดัมพ์และตัดสินใจว่าการแครชนั้นคุ้มค่าที่จะรายงานไปยัง upstream หรือไม่ คุณยังสามารถรันมันด้วยตนเองกับ PID ใด ๆ จาก `coredumpctl list` ด้วย `omarchy agent crash <pid>`

การเฝ้าดูเปิดอยู่โดยเริ่มต้น ปิดมันภายใต้ _Trigger > Toggle > Crash Capture Off_ (หรือด้วย `omarchy toggle crash-capture`) และการแจ้งเตือนจะหยุด; `omarchy agent crash <pid>` ยังคงทำงานด้วยตนเอง

การแครชยังสามารถปิดเสียงได้ทีละโปรแกรม ซึ่งเป็นสิ่งที่การวินิจฉัยเสนอให้คุณในตอนท้าย `omarchy crash mute hyprland` หยุดการแจ้งเตือนสำหรับโปรแกรมนั้นเท่านั้น `omarchy crash mute hyprland off` นำพวกมันกลับมา และ `omarchy crash mute` ด้วยตัวมันเองแสดงสิ่งที่คุณปิดเสียงไว้ มันรับเส้นทางของไบนารีได้อย่างยินดีเท่ากับชื่อของมัน ดังนั้น `omarchy crash mute /usr/bin/hyprland` จึงทำสิ่งเดียวกัน ใส่เครื่องหมายคำพูดรอบชื่อที่มีช่องว่าง เช่นใน `omarchy crash mute 'Some App'` อย่างอื่นทั้งหมดยังคงแจ้งเตือน และโปรแกรมที่ปิดเสียงไว้ยังคงแครช — สิ่งนี้ซ่อนการเตือน มันไม่ได้แก้อะไรเลย

### แอปบนเดสก์ท็อป

เมนู _Install > AI_ ยังมีแอป AI แบบกราฟิกอยู่สองสามตัวด้วย: Amp Desktop, Antigravity Desktop, แอปเดสก์ท็อป ChatGPT, แอปเดสก์ท็อป Claude (รุ่นเบต้าสำหรับ Linux ของ Anthropic พร้อมแท็บ Chat, Cowork, และ Claude Code), Grok Bot สำหรับแชทกับโมเดลของ xAI, Herdr Desktop, Hermes Desktop, OpenClaw, แอปเดสก์ท็อป Perplexity, และ T3 Code Grok Bot คือแอปแชทบนเดสก์ท็อป เอเจนต์เขียนโค้ดคือคำสั่ง `grok`

Hermes Desktop คือตัวที่ต้องรู้ เพราะเครื่องหนึ่งมี Hermes เดียว และมันเป็นของแอป: Hermes ถูกติดตั้งผ่านแอปเท่านั้น และคำสั่ง `hermes` ที่เอเจนต์เริ่มต้นรันเป็นของแอป การเลือก Hermes เป็นเอเจนต์เริ่มต้นจะติดตั้งสิ่งเดียวกับที่รายการ _Install > AI_ ติดตั้ง: แพ็กเกจ และรันไทม์ Hermes ภายใต้ `~/.hermes` ที่ตัวติดตั้งของ Hermes เองตั้งค่าให้ ซึ่งใช้เวลาไม่กี่นาทีในครั้งแรก รันไทม์นั้นคือ Hermes เดียวที่คำสั่ง `hermes` ในเทอร์มินัล เอเจนต์เริ่มต้น และแอปทั้งหมดใช้ และมันอัปเดตตัวเองด้วย `hermes update` แทนที่จะรอการเปิดตัวของ Omarchy การติดตั้งมันยังมอบธีม Omarchy ให้ Hermes เป็นสกินชื่อ `omarchy` ซึ่งพื้นผิว Hermes ทุกตัวจะตามไปเมื่อคุณเปลี่ยนธีม; เลือกอย่างอื่นภายใต้การตั้งค่า Appearance ของ Hermes หรือด้วย `/skin` หากคุณไม่อยากให้มันเป็นเช่นนั้น และ Omarchy จะปล่อยตัวเลือกนั้นไว้ตามเดิม การลบแอปภายใต้ _Remove > AI_ จะปิด Hermes ก่อน รวมถึงเกตเวย์ นำรันไทม์นั้นไปกับมัน และเก็บแชท ความทรงจำ และสกิลที่ Hermes เขียนให้ตัวเองไว้ เว้นแต่คุณจะบอกมันเป็นอย่างอื่น: มันจะถาม โดยค่าเริ่มต้นคือไม่ ว่าข้อมูลนั้นและการตั้งค่าการเชื่อมต่อของคุณควรไปด้วยหรือไม่

ประสบการณ์บนเดสก์ท็อปของ OpenClaw คือ Control UI ของมัน ซึ่งเปิดเป็นเว็บแอปที่ได้รับการสนับสนุนโดยเกตเวย์ในเครื่องของมันเอง OpenClaw อาศัยอยู่ใน `~/.openclaw` และอัปเดตตัวเอง: ใช้ปุ่ม "Update Gateway" ของ Control UI หรือรัน `openclaw update` และเกตเวย์จะรีสตาร์ทบนรุ่นใหม่ Omarchy เพียงเลือกว่ารุ่นใดที่การติดตั้งใหม่จะเริ่มต้นจาก OpenClaw ยังสามารถเป็นเอเจนต์เริ่มต้นของคุณได้: การเลือกมันภายใต้ _Agent > Harness_ จะตั้งค่าสำเนาเดียวกันนั้นใน `~/.openclaw` และเอเจนต์จะเปิด UI เทอร์มินัลของ OpenClaw ที่เชื่อมต่อกับเกตเวย์ของมัน การลบ OpenClaw ภายใต้ _Remove > AI_ จะนำบริการเกตเวย์และแอปไปกับมัน จากนั้นถามว่า `~/.openclaw` ควรไปด้วยหรือไม่ เนื่องจากที่นั่นเก็บแชทและข้อมูลประจำตัวของคุณควบคู่ไปกับ OpenClaw เองและรันไทม์ปลั๊กอินที่มันดาวน์โหลด; ค่าเริ่มต้นจะเก็บมันไว้ และการติดตั้ง OpenClaw อีกครั้งจะหยิบมันกลับขึ้นมา

Herdr Desktop คือแอปเดสก์ท็อป [Herdr](https://herdr.dev): พื้นที่ แท็บ และบานหน้าต่างของเทอร์มินัลและเอเจนต์เขียนโค้ดที่ยังคงทำงานอยู่ในคอร์ของมันเมื่อคุณปิดหน้าต่าง มันมาจากตัวติดตั้งของ Herdr เองแทนที่จะเป็นแพ็กเกจ ดังนั้นมันจึงอาศัยอยู่ใน `~/.local/share/herdr-app`, นำคอร์ของมันมาใน `~/.local/bin/herdr-core` เมื่อคุณยังไม่มี และอัปเดตทั้งตัวมันเอง มันอยู่ข้าง ๆ คำสั่ง `herdr` ที่ Omarchy ส่งมาบน `Super + Ctrl + Return` แทนที่จะแทนที่มัน และได้รับคีย์ตรงของคำสั่งนั้น: `Alt + Return` และ `Alt + Shift + Return` แยกบานหน้าต่างลงหรือไปทางขวา, `Alt + Escape` ปิดมัน, `Ctrl + Alt + Arrow` ย้ายระหว่างบานหน้าต่าง, `Alt + 1..9` และ `Alt + Left/Right` เลือกแท็บ และ `Alt + Up/Down` ย้ายระหว่างพื้นที่ `Ctrl + 1..9` เลือกพื้นที่และ `Alt + Shift + Up/Down` ก้าวผ่านเอเจนต์ คีย์นำหน้า `Ctrl + Space` ยังคงเป็นเทอร์มินัลเท่านั้น เนื่องจากแอปไม่สามารถถือคีย์ Ctrl ธรรมดาไว้สำหรับลำดับได้ Omarchy เขียนสิ่งเหล่านี้ไปยัง `~/.config/herdr-app/keys.json` และ `omarchy-refresh-herdr-app` จะนำพวกมันกลับมา การติดตั้งมันจะเลือกธีม Omarchy ของ Herdr ซึ่งจะตามธีม Omarchy ของคุณตั้งแต่นั้นเป็นต้นมา Herdr เก็บหนึ่งธีมสำหรับโหมดสว่างและหนึ่งธีมสำหรับโหมดมืด ดังนั้นหลังจากสลับระหว่างธีม Omarchy แบบมืดและแบบสว่าง ให้เลือก Omarchy ในตัวเลือกธีมของ Herdr อีกครั้งสำหรับโหมดอื่น

T3 Code ทำงานจากรุ่น AppImage อย่างเป็นทางการใน `~/.local/share/t3code` แทนที่จะเป็นจากแพ็กเกจ ดังนั้นมันจึงอัปเดตตัวเอง การติดตั้งมันจะถามว่าจะเริ่มต้นบนช่อง Stable หรือ Nightly; สลับภายหลังในการตั้งค่าของ T3 Code เธรดและการตั้งค่าของคุณอาศัยอยู่ใน `~/.t3` และการลบ T3 Code ภายใต้ _Remove > AI_ จะนำพวกมันไปกับมัน

### โมเดลในเครื่อง

รันโมเดลแบบเปิดบนเครื่องของคุณเองสำหรับเอเจนต์เขียนโค้ดของคุณ พรอมต์และโค้ดของคุณยังคงอยู่บนเครื่อง; ไม่มีสิ่งที่ส่งไปยังโมเดลออกจากมัน เริ่มต้นด้วย:

```bash
omarchy agent local use best
```

หรือ ในแผงเอเจนต์ในแถบด้านบน เลือก + แล้วเลือก Local AI ซึ่งจะปรากฏเมื่อโมเดลพอดีกับเครื่องนี้ Podman ซึ่งรันโมเดล มาพร้อมกับ Omarchy เช่นเดียวกับชุดเครื่องมือคอนเทนเนอร์ของ NVIDIA บนเครื่อง NVIDIA ซึ่งให้ GPU แก่พวกมัน; หากอย่างใดอย่างหนึ่งหายไป การตั้งค่าครั้งแรกจะติดตั้งมัน จากนั้น Omarchy จะเลือกโมเดลที่แนะนำสำหรับเครื่องนี้ ดาวน์โหลดมัน และเริ่มมัน คาดว่าจะมีการดาวน์โหลดหลายสิบ GB และหน่วยความจำส่วนใหญ่ของเครื่องถูกใช้ขณะที่โมเดลทำงาน: Flash Next ใช้ประมาณ 100 GiB พร้อมบริบท 256K เต็มของมัน หากโมเดลอื่น ๆ ถือหน่วยความจำที่มันต้องการไว้ มันจะถูกตั้งค่าในสถานะหยุด พร้อมที่จะเริ่มเมื่อคุณหยุดตัวหนึ่ง โมเดลจะหยุดเมื่อออกจากระบบ; หยุดมันเองเมื่อคุณต้องการหน่วยความจำสำหรับอย่างอื่น

`omarchy agent local list` แสดงตัวเลือกและอธิบายว่าทำไมบางตัวจึงไม่พอดี เพื่อตั้งค่าอีกตัว ให้รัน `omarchy agent local use <recipe>` วันนี้ `qwen3.8-flash-next-gufo` และ `qwen3.8-27b-gufo` พร้อมใช้งานสำหรับเครื่อง Strix Halo ขนาด 128 GB; ตัว 27B ใช้ประมาณ 40 GiB ดังนั้นจึงเหลือพื้นที่สำหรับงานอื่น บนแล็ปท็อปขนาด 64 GB พร้อม Arc B390 ของ Intel, `qwen3.6-35b-a3b-llamacpp` ทำงานในประมาณ 30 GiB สูตรและคำแนะนำใหม่มาพร้อมกับ `omarchy update` ผ่านแพ็กเกจ

โมเดลทุกตัวที่คุณตั้งค่าจะได้รับบรรทัดของมันเองในแผงเอเจนต์ ข้าง ๆ การสมัครสมาชิกของคุณ: เล่นเพื่อเริ่มมัน หยุดชั่วคราวเพื่อหยุดมันและปล่อยหน่วยความจำของมัน และปุ่มเทอร์มินัลเพื่อเปิดเอเจนต์ของคุณบนมัน หลายตัวสามารถทำงานพร้อมกันเมื่อพวกมันพอดีในหน่วยความจำด้วยกัน; หากตัวหนึ่งไม่พอดี Omarchy จะบอกว่าโมเดลที่กำลังทำงานตัวใดให้หยุด ลากบรรทัดเพื่อจัดลำดับพวกมันใหม่ และกด Delete บนบรรทัดที่เลือกเพื่อลบโมเดลและการดาวน์โหลดของมัน

โมเดลทุกตัวที่คุณตั้งค่ายังได้รับรายการของมันเองในตัวเรียกใช้แอป ภายใต้ชื่อของโมเดลและพร้อมโลโก้ของผู้สร้างมัน ในแบบเดียวกับการลงชื่อเข้าใช้ Claude, Codex หรือ Grok ที่เพิ่มรายการหนึ่ง มันเปิดเอเจนต์ของคุณบนโมเดลนั้น และเริ่มโมเดลก่อนหากมันไม่ได้ทำงานอยู่: เทอร์มินัลจะแสดงมันกำลังโหลดและส่งต่อให้เอเจนต์เมื่อมันพร้อม การลบโมเดลจะลบรายการของมัน

ไม่ใช่ทุกโมเดลมีไว้สำหรับเขียนโค้ด โมเดลภาพ วิดีโอ และเพลงจะเปิดใน Fantasi แทน แอปของ Omarchy สำหรับสร้างรูปภาพ วิดีโอ และเพลงด้วยโมเดลที่ทำงานบนเครื่องนี้ จากรายการในตัวเรียกใช้ของพวกมันและจากบรรทัดของพวกมันในแผงเอเจนต์

โมเดลจะยังคงทำงานต่อไปอย่างที่มันถูกตั้งค่าไว้ ดังนั้นการอัปเดต Omarchy จะไม่มีวันรีสตาร์ทมันภายใต้เอเจนต์ของคุณ เมื่อ Omarchy มีรันไทม์ที่ใหม่กว่าหรือน้ำหนักที่ใหม่กว่าสำหรับโมเดลที่คุณตั้งค่าไว้ บรรทัดของมันจะแสดงปุ่มอัปเดต: กดมันและโมเดลจะถูกตั้งค่าอีกครั้งในพื้นหลัง โดยดาวน์โหลดเฉพาะสิ่งที่เปลี่ยนแปลง และรีสตาร์ทบนรุ่นใหม่ โมเดลที่หยุดอยู่จะยังคงหยุดอยู่ `omarchy agent local update` ทำสิ่งเดียวกันสำหรับทุกโมเดลจากเทอร์มินัล

จากบรรทัดคำสั่ง `omarchy agent local start <recipe>` และ `omarchy agent local stop <recipe>` ทำสิ่งเดียวกัน `omarchy agent local status` แสดงทุกโมเดล และ `omarchy agent --local` เปิดเอเจนต์เริ่มต้นของคุณบนโมเดลล่าสุดที่คุณเริ่ม pi, OpenCode และ Qwen Code สามารถใช้ตัวหนึ่งได้; ด้วยค่าเริ่มต้นอื่นใดมันจะเปิดใน pi หรือใน OpenCode หากคุณไม่มี pi pi ยังแสดงรายการโมเดลทุกตัวที่คุณตั้งค่าไว้ และโมเดลเหล่านั้นบนเครื่องที่คุณจับคู่ด้วย ในตัวเลือกโมเดลของมันเอง ดังนั้น `pi` ธรรมดาจึงไปถึงพวกมันเช่นกัน ไคลเอนต์ที่เข้ากันได้กับ OpenAI ใด ๆ ก็สามารถเชื่อมต่อได้เช่นกัน: `status` แสดงที่อยู่ของแต่ละโมเดล (ตัวแรกคือ `http://127.0.0.1:11435/v1`) ชื่อสูตรคือโมเดล และคีย์อยู่ใน `~/.config/omarchy/agent-local/key`

`omarchy agent local remove <recipe>` ลบโมเดลและการดาวน์โหลดที่ไม่มีโมเดลอื่นใช้

รันไทม์ของบุคคลที่สามถูกติดป้ายด้วยผู้เผยแพร่ของพวกมัน Omarchy รันทุกโมเดลโดยไม่มีการเข้าถึงเครือข่าย

### LLM ในเครื่อง

Omarchy แนะนำสองวิธีในการรันโมเดล LLM ในเครื่อง: LM Studio และ Ollama LM Studio มีอินเทอร์เฟซ GUI สำหรับค้นหาโมเดลแบบเปิด ติดตั้งพวกมัน และรันพวกมัน มันเป็นวิธีที่ยอดเยี่ยมในการเริ่มต้นอย่างง่ายดาย Ollama เสนอ CLI สำหรับทำเช่นเดียวกัน แต่หากคุณเพิ่งเริ่มใช้โมเดลในเครื่อง ผมจะเริ่มต้นด้วย LM Studio คุณสามารถติดตั้งอย่างใดอย่างหนึ่งภายใต้ _Install > AI_ ใน Omarchy Menu

### สกิลของ Omarchy

สกิลของเอเจนต์ช่วย AI ใช้เครื่องมือเฉพาะในวิธีเฉพาะ และ Omarchy ส่งมาเจ็ดตัว สกิล omarchy ครอบคลุมการปรับแต่งระบบ เช่นการปรับแต่งการกำหนดค่า Hyprland ของคุณหรือการปรับแถบ omarchy-make-theme, omarchy-make-plugin, omarchy-make-app, และ omarchy-make-game ครอบคลุมการสร้างสิ่งใหม่, omarchy-contribute ครอบคลุมการรายงานบั๊กหรือส่งการแก้ไขไปยัง upstream, และ omarchy-diagnose-crash ทำงานผ่านคอร์ดัมพ์ของการแครช พวกมันถูกสร้างลิงก์สัญลักษณ์ไปยังไดเรกทอรีสกิลสำหรับ Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` และแต่ละ `~/.hermes/profiles/*/skills`), และตำแหน่งทั่วไป `~/.agents/skills` ดังนั้นฮาร์เนสส่วนใหญ่จึงหยิบพวกมันขึ้นมาโดยอัตโนมัติ โฟลเดอร์สกิลของคุณเองที่มีชื่อเดียวกันจะมีความสำคัญเหนือกว่า

แต่คุณควรปฏิบัติต่อสกิลเหล่านี้ในฐานะสิ่งที่ยังอยู่ในขั้นทดลอง โมเดลที่แตกต่างกันจะใช้มันให้เกิดผลที่แตกต่างกัน ทางที่ดีที่สุดคือรันในโหมดวางแผนก่อน เพื่อให้คุณมีแนวคิดว่าเอเจนต์อยากเปลี่ยนแปลงอะไร แล้วเตรียมพร้อมที่จะย้อนกลับการเปลี่ยนแปลงหรือแม้กระทั่งเรียกใช้ `omarchy reinstall configs` หากเอเจนต์ทำให้ทุกอย่างยุ่งเหยิง
