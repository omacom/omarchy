### การติดตั้งและอัปเดตเอเจนต์

ยกเว้น Hermes และ OpenClaw เอเจนต์เหล่านี้ใช้การติดตั้งแบบ lazy ของ mise: การเรียกใช้ครั้งแรกจะติดตั้ง CLI และการเรียกใช้ครั้งต่อ ๆ ไปจะใช้ตัวที่ติดตั้งไว้นั้นซ้ำ mise ยังตรวจสอบเอเจนต์ที่ติดตั้งไว้ว่ามีรุ่นใหม่ออกมาหรือไม่ ไม่เกินหนึ่งครั้งทุกสี่ชั่วโมง ก่อนที่มันจะเริ่มพอดีหรือในเบื้องหลังที่พรอมต์ของเชลล์ หากการอัปเดตนั้นล้มเหลวหรือคุณออฟไลน์อยู่ เวอร์ชันที่ติดตั้งไว้จะทำงาน `omarchy update` จะอัปเดตเอเจนต์ที่ติดตั้งไว้พร้อมกับส่วนที่เหลือของ Omarchy และ `mup` จะอัปเดตเฉพาะเครื่องมือที่ mise จัดการเท่านั้น

ตัวอัปเดตของเอเจนต์เอง เช่น `claude update`, `codex update` หรือปุ่มอัปเดตในแอป จะไม่อัปเดตตัวที่ติดตั้งซึ่ง mise จัดการ `codex update` จะล้มเหลว และ `claude update` อาจรายงานว่าสำเร็จขณะติดตั้งสำเนาแยกต่างหากที่ mise ไม่ได้ติดตาม หากคุณอยากใช้ตัวติดตั้งและตัวอัปเดตแบบเนทีฟของเอเจนต์มากกว่า ให้เพิ่มมันลงใน `disable_tools`; ดู [เครื่องมือ CLI ที่ติดตั้งไว้ล่วงหน้า](18-development-tools.md#preinstalled-cli-tools)

หากต้องการติดตั้งเครื่องมือ lazy ที่กำหนดค่าไว้ทั้งหมดก่อนที่คุณจะต้องใช้ ให้รัน `mise install --include-lazy` ซึ่งรวมถึงเครื่องมือ CLI เริ่มต้นอื่น ๆ ของ Omarchy ด้วยเช่นเดียวกับเอเจนต์ ดู [เครื่องมือ CLI ที่ติดตั้งไว้ล่วงหน้า](18-development-tools.md#preinstalled-cli-tools) สำหรับการติดตั้งเครื่องมือเพียงตัวเดียวหรือการใช้การติดตั้งของคุณเอง

`grok` ติดตั้งผ่านแพ็กเกจ `grok` แบบ first-party ของ mise ด้วยวิธีเดียวกันกับ `claude` และ `codex` รัน `grok` หรือติดดาวให้มันในแผงเอเจนต์ ข้ามตัวติดตั้ง `curl | bash` บน x.ai ไปเลย เส้นทางนั้นจะวางสำเนาที่สองไว้ใน `~/.grok/bin`, นำหน้ามันบน `PATH` และเขียนทับ wrapper ของ Omarchy

`dsh` เปิด UI ในเบราว์เซอร์ของมันบน `127.0.0.1:3080` โดยมีไดเรกทอรีที่เรียกใช้เป็น workspace เริ่มต้น UI ในเบราว์เซอร์ของมันไม่รับพรอมต์เริ่มต้น ดังนั้น `omarchy agent prompt` จะเปิดมันโดยมีพรอมต์อยู่บนคลิปบอร์ดของคุณให้วาง Omarchy เริ่มมันด้วยพรีเซ็ตสิทธิ์แบบ no-approval ของ DeepSeek DeepSeek Harness จะอัปโหลดบันทึกเซสชันไปยัง DeepSeek เมื่อคุณใช้ API โมเดลอย่างเป็นทางการของมัน; ปิดการทำงานนั้นได้ภายใต้ _Settings > General > Upload Session Log_ ใน UI ในเบราว์เซอร์ของมัน ข้อเสนอแนะที่คุณส่งให้มันก็จะถูกอัปโหลดไปพร้อมกับเซสชันด้วย เว้นแต่คุณจะเริ่มมันด้วย `DSH_TELEMETRY_MODE=DISABLED`

### เอเจนต์เริ่มต้น

เลือกเอเจนต์เริ่มต้นของคุณด้วยดาวข้างเอเจนต์ในแผงเอเจนต์ ซึ่งจะถูกเติมบนตัวที่เป็นค่าเริ่มต้น หรือด้วย `omarchy default agent <name>` ซึ่งรับ harness ใดก็ได้ที่ไม่มีบรรทัดอยู่ที่นั่นด้วย หากเอเจนต์ยังไม่ได้ติดตั้ง การเลือกมันจะติดตั้งมันก่อน และมันยังได้ตัวเรียกใช้ของตัวเองในตัวเรียกใช้แอป ถัดจาก Agent ด้วย Omarchy ที่ติดตั้งใหม่จะเชิญคุณให้ตั้งค่าด้วยการแจ้งเตือนเพียงครั้งเดียว ซึ่งจะเปิดแผงเอเจนต์

การเลือก Claude ยังพยายามตั้งค่าส่วนขยายเบราว์เซอร์ของมันสำหรับ Chromium, Chrome, Brave, Brave Origin และ Edge ด้วย การตั้งค่าส่วนขยายใช้กับผู้ใช้ทั้งหมดและอาจขอรหัสผ่านระบบของคุณ; การยกเลิกหรือการติดตั้งส่วนขยายที่ล้มเหลวก็ยังคงเลือกและเรียกใช้ Claude อยู่ดี รีสตาร์ทเบราว์เซอร์ของคุณ เปิดใช้งานส่วนขยายหากได้รับแจ้ง และลงชื่อเข้าใช้ Claude เพื่อเชื่อมต่อให้เสร็จสมบูรณ์ รัน `/chrome` ใน Claude เพื่อตรวจสอบการเชื่อมต่อ Firefox และ Zen ไม่รองรับส่วนขยายนี้ หาก Claude เป็นค่าเริ่มต้นของคุณอยู่แล้วก่อนที่จะมีการเพิ่มการตั้งค่านี้เข้ามา ให้เลือกมันอีกครั้งเพื่อติดตั้งส่วนขยาย

เมื่อคุณเลือกแล้ว `Super + Shift + Ctrl + A` จะเรียกใช้เอเจนต์เริ่มต้นในหน้าต่างเทอร์มินัลเฉพาะ (หรือเปิดตัวเลือกหากคุณยังไม่ได้เลือก) คุณยังเรียกใช้มันตรงเข้าสู่งานได้ด้วย `omarchy agent prompt "Review this project"` Freebuff และ DeepSeek Harness ไม่รับพรอมต์เริ่มต้น ดังนั้นพวกมันจะเปิดโดยมีพรอมต์อยู่บนคลิปบอร์ดของคุณให้วางแทน เอเจนต์ที่เรียกใช้ด้วยวิธีนี้จะทำงานโดยไม่มีผู้ดูแลในโหมดไม่หยุดเพื่อถามของแต่ละตัว ดังนั้นเตรียมพร้อมให้พวกมันลงมือทำสิ่งต่าง ๆ จริง ๆ ได้เลย! MiniMax Code ไม่มีโหมดแบบนั้นสำหรับเซสชันแบบอินเทอร์แอกทีฟของมัน ดังนั้นมันจะขอสิทธิ์ตามปกติ และเนื่องจากเอเจนต์ปฏิเสธที่จะจดจำความเชื่อถือสำหรับไดเรกทอรีโฮมของคุณ การเรียกใช้จาก `$HOME` จะเริ่มใน `~/Work` แทน

ยังมีทางลัดในเทอร์มินัลด้วย: `a` รันเอเจนต์เริ่มต้นแบบอินไลน์ในเทอร์มินัลปัจจุบัน ขณะที่ `c`, `cx`, `cy` และ `ca` เริ่ม OpenCode, Claude Code, Codex และ Antigravity โดยตรง (อีกครั้งในโหมดอนุมัติอัตโนมัติของพวกมัน) การเปลี่ยนธีมก็ซิงค์ไปยังเอเจนต์ด้วย: Claude Code, Pi, OpenCode และ Hermes (เมื่อ Omarchy ติดตั้งมันแล้ว) ล้วนตามไปด้วยเมื่อคุณสลับธีมของ Omarchy

### คำแนะนำสำหรับเอเจนต์ของคุณ

กฎส่วนตัวสำหรับทุกเอเจนต์อยู่ใน `~/.agents/AGENTS.md` ถัดจากสกิลที่ใช้ร่วมกันใน `~/.agents/skills` เปิดมันด้วยไอคอนเอกสารข้าง + ในแผงเอเจนต์ หรือ `omarchy agent instructions --edit` ซึ่งยังเชื่อมโยงมันเข้าไปในแต่ละ harness ที่เก็บไฟล์โกลบอลของตัวเองไว้ด้วย: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` ของ Copilot และอื่น ๆ Crush และ Amp อ่านลิงก์ `~/.config/AGENTS.md` ขณะที่ omp, Kimi และ DeepSeek Harness อ่าน `~/.agents/AGENTS.md` โดยตรง การเลือกเอเจนต์เริ่มต้นก็เชื่อมโยงมันเช่นกัน ไฟล์คำแนะนำที่คุณมีอยู่แล้วจะกลายเป็นไฟล์ที่ใช้ร่วมกันหากยังไม่มีไฟล์ดังกล่าว; ไม่อย่างนั้นมันจะถูกเก็บไว้ข้างลิงก์ในชื่อ `.bak` รัน `omarchy agent instructions` เพื่อเชื่อมโยงใหม่หลังจากติดตั้งเอเจนต์อีกตัว

### แผงเอเจนต์

แถบบนมีไอคอนเอเจนต์ ก่อนที่คุณจะตั้งค่าเอเจนต์ แผงของมันเสนอสามวิธีให้เริ่มต้น: ลงชื่อเข้าใช้การสมัครสมาชิก Claude, Codex, Grok, Gemini, Muse, Cursor หรือ Copilot หรือภายใต้ More เป็นแผนเขียนโค้ด OpenCode Go, MiniMax, Synthetic หรือ Z.ai; จ่ายตามการใช้งานจริงกับ Fireworks, OpenCode Zen and Go, OpenRouter หรือภายใต้ More เป็น DeepSeek หรือผู้ให้บริการรายอื่นใดที่ OpenCode ลงชื่อเข้าใช้ ซึ่งทั้งหมดรันใน OpenCode; หรือรันโมเดลที่ดีที่สุดสำหรับคอมพิวเตอร์ของคุณ เมื่อมีตัวที่เหมาะกับมัน ตัวแรกที่คุณทำเสร็จจะกลายเป็นเอเจนต์เริ่มต้นของคุณ และ + ในแผงจะเสนอสามอย่างเดียวกันนั้นในภายหลัง หลังจากนั้น แผงจะวางทุกการสมัครสมาชิกไว้ในหน้าเดียว: เอเจนต์และบัญชีแต่ละตัวพร้อมกับแผนของมัน มาตรวัดสำหรับขีดจำกัดเซสชัน 5 ชั่วโมงและขีดจำกัดรายสัปดาห์ของแต่ละตัวพร้อมกับเวลาจนกว่าจะรีเซ็ต (วางเมาส์เหนือมาตรวัดเพื่อดูเปอร์เซ็นต์ที่แน่นอน) หรือยอดคงเหลือแบบเติมเงินที่เหลืออยู่ ภายใต้บรรทัดที่หมุนเวียนแสดงสิ่งที่คุณใช้ไปในทุกตัว เช่น โทเค็นในสัปดาห์นี้และโมเดลที่คุณใช้มากที่สุด ภายใต้ _Make something cool_ มันเสนอพรอมต์เริ่มต้นสำหรับธีม ปลั๊กอิน แอป หรือเกมใหม่ ซึ่งมอบงานให้เอเจนต์เริ่มต้นของคุณ แอปถูกสร้างในแบบเดียวกับที่ Hype, Monologue และ Omacut ของ Omarchy เองถูกสร้าง คือใน C++ และ Qt Quick โดยทำตามสกิลเอเจนต์ omarchy-make-app และคอมไพเลอร์กับชิ้นส่วน Qt ที่พวกมันต้องการก็ติดตั้งมาให้แล้ว เกมเป็นหน้า three.js เพียงหน้าเดียวใน `~/Games/vibes` โดยทำตามสกิลเอเจนต์ omarchy-make-game และทั้งหมดเปิดจากตัวเรียกใช้ Game Vibes ตัวเดียวในธีมปัจจุบัน; พวกมันโหลด three.js จากเว็บ ดังนั้นพวกมันต้องมีการเชื่อมต่อเพื่อเริ่ม Claude Code, Codex, Grok, Kimi, Cursor และโควตา Grok Bot ของมัน, GitHub Copilot, Muse, Gemini (ผ่าน Antigravity) และ Devin ได้รับการครอบคลุมมาตั้งแต่ต้นพร้อมกับขีดจำกัดของพวกมัน, Kimchi พร้อมกับแผน เครดิตแบบเติมเงิน และงบการใช้จ่ายของมัน และ Hermes, Mistral Vibe และ Qwen Code จะแสดงเซสชันและโทเค็นของพวกมันเมื่อคุณได้ใช้พวกมันแล้ว แผนและคีย์ของผู้ให้บริการที่คุณใช้ผ่าน pi, omp หรือ opencode ก็ปรากฏเช่นกัน: OpenCode Zen and Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan และ Synthetic พร้อมกับขีดจำกัดของพวกมัน; OpenRouter และ DeepSeek พร้อมกับยอดคงเหลือแบบเติมเงินของพวกมัน; Fireworks พร้อมกับการใช้จ่ายของมันในช่วง 30 วันที่ผ่านมา โมเดลเขียนโค้ดที่คุณรันบนฮาร์ดแวร์ของคุณเองจะได้บรรทัดของตัวเอง และโทเค็นของพวกมันก็นับรวมในยอดรวมเช่นกัน ดังที่อธิบายภายใต้ [โมเดลในเครื่อง](#local-models) เอเจนต์ทุกตัวถูกนับเพียงครั้งเดียว ภายใต้ผู้ที่เรียกเก็บเงินสำหรับมัน ไม่ว่าคุณจะขับเคลื่อนมันผ่าน harness กี่ตัวก็ตาม

คลิกซ้ายที่ไอคอนบนแถบหรือกด `Super + Ctrl + X` เพื่อเปิดแผง คลิกขวาเพื่อเรียกใช้เอเจนต์เริ่มต้นของคุณ และคลิกกลางเพื่อรีเฟรช บันทึกการใช้งานที่อยู่เบื้องหลังแผงจะถูกสร้างใหม่ทุก 15 นาทีโดย `omarchy agent usage update` และแผงยังสามารถผสานการใช้งานจากเครื่องอื่น ๆ ของคุณผ่านโฟลเดอร์ที่ซิงค์ได้ด้วย ดู README ภายใต้ `$OMARCHY_PATH/shell/plugins/agents/` สำหรับการตั้งค่าฉบับเต็ม

### การสมัครสมาชิกหลายรายการ

หากคุณจ่ายค่าสมัครแผน Claude, Codex หรือ Grok มากกว่าหนึ่งแผน — เช่น Max ส่วนตัวหนึ่งแผนและอีกหนึ่งแผนสำหรับงาน — Omarchy สามารถคงให้พวกมันทั้งหมดลงชื่อเข้าใช้ไว้และย้ายสลับระหว่างพวกมันได้ เพิ่มการสมัครสมาชิกด้วย + ในแผงเอเจนต์ ซึ่งจะพาคุณทำตามขั้นตอนตรงนั้นเลย หรือด้วย `omarchy agent account add claude Work` (หรือ `codex` หรือ `grok`) + และคำสั่งเดียวกันนั้นยังลงชื่อเข้าใช้ Gemini (`gemini`) และ OpenCode (`opencode`) และบันทึกคีย์ API ของ Fireworks (`fireworks`) หรือ OpenRouter (`openrouter`) ไว้ใน OpenCode; คำสั่งยังลงชื่อเข้าใช้ Copilot (`copilot`), Cursor (`cursor`) และ Muse (`muse`) ด้วย พวกนั้นแต่ละตัวจะเก็บการลงชื่อเข้าใช้ไว้เพียงรายการเดียว มันจะติดตั้ง CLI หากยังไม่มี บัญชีแรกสำหรับผู้ให้บริการรายหนึ่งจะลงชื่อเข้าใช้ผ่านเบราว์เซอร์ปกติของคุณ ตรงตำแหน่งที่ CLI มองหาอยู่เสมอ ทุกบัญชีหลังจากนั้นจะลงชื่อเข้าใช้ผ่านหน้าต่างส่วนตัว ดังนั้นบัญชีที่เบราว์เซอร์ของคุณลงชื่อเข้าใช้อยู่แล้วจะไม่ถูกหยิบมาใช้โดยผิดพลาด; ลงชื่อเข้าใช้ที่นั่นในฐานะบัญชีที่คุณกำลังเพิ่ม และปิดหน้าต่างส่วนตัวใด ๆ ที่คุณเปิดค้างไว้อยู่ก่อน อย่าออกจากระบบของ CLI เพื่อทำสิ่งนี้เด็ดขาด: การออกจากระบบจะเพิกถอนการลงชื่อเข้าใช้ที่บันทึกไว้ และบัญชีนั้นจะต้องถูกเพิ่มเข้ามาอีกครั้ง

หากต้องการคัดลอกการเข้าสู่ระบบการสมัครสมาชิกของคุณไปยังเครื่อง Omarchy อีกเครื่องผ่าน SSH ให้รัน `omarchy agent account copy user@laptop` ผู้ส่งจะจัดหาตัวรับชั่วคราวให้เมื่อปลายทางยังไม่มีตัวรับติดตั้งอยู่ ดังนั้นเครื่อง Omarchy รุ่นเก่ากว่าสามารถรับบัญชีได้โดยไม่ต้องอัปเดต ตัวรับที่ติดตั้งไว้แล้วจะมีความสำคัญเหนือกว่า การดำเนินการนี้จะคัดลอกการสมัครสมาชิก Claude, Codex และ Grok ทั้งหมด; เพิ่มชื่อผู้ให้บริการเพื่อเลือกเฉพาะพวกมัน เช่นใน `omarchy agent account copy laptop claude` ชื่อบัญชีและ ID คำสั่งจะตรงกับต้นทาง รวมถึงบัญชีที่มีอยู่บนปลายทางแล้ว บัญชีปลายทางที่ไม่เกี่ยวข้องกันจะได้รับคำต่อท้ายเป็นตัวเลขหากชื่อของพวกมันขัดกัน และการตั้งค่า สกิล ปลั๊กอิน และประวัติการสนทนาจะยังคงอยู่เฉพาะในแต่ละเครื่อง

ข้อมูลรับรองปลายทางที่มีอยู่จะถูกเก็บไว้ บัญชีต้นทางที่ลงชื่อเข้าใช้ที่นั่นอยู่แล้วจะมีชื่อถูกซิงค์โดยไม่แทนที่ข้อมูลรับรองของมัน; บัญชีอื่น ๆ จะถูกเพิ่มเข้ามาข้าง ๆ หากต้องการแทนที่ข้อมูลรับรองที่บันทึกไว้สำหรับบัญชีที่ตรงกัน ให้ใช้ `omarchy agent account copy --replace laptop claude` หลังจากออกจากเซสชันของบัญชีนั้นบนปลายทางแล้ว ปลายทางใหม่เอี่ยมยังจะได้รับบัญชีที่ใช้งานอยู่และความต้องการในการสลับบัญชีของต้นทางด้วย; ปลายทางที่จัดตั้งไว้แล้วจะเก็บของตัวเองไว้

ข้อมูลรับรองเดินทางผ่าน SSH และถูกเก็บไว้ในไฟล์ส่วนตัวบนปลายทาง ดังนั้นให้คัดลอกไปยังเครื่องที่คุณเชื่อถือเท่านั้น นี่เป็นการคัดลอกเพียงครั้งเดียว ไม่ใช่การซิงโครไนซ์อย่างต่อเนื่อง โทเค็นรีเฟรชของ Codex สามารถถูกหมุนเวียนโดยเครื่องอื่นได้ ทำให้การเข้าสู่ระบบที่คัดลอกมาอาจต้องต่ออายุ; การลงชื่อเข้าใช้แยกกันยังคงเป็นตัวเลือกที่เชื่อถือได้ที่สุดสำหรับการใช้งานพร้อมกันบนหลายเครื่อง ดู [คำแนะนำการยืนยันตัวตนบัญชีของ Codex](https://developers.openai.com/codex/auth/ci-cd-auth)

บัญชีหนึ่งบัญชีต่อผู้ให้บริการหนึ่งรายจะทำงานอยู่ และทุกเซสชันใหม่จะเริ่มต้นในฐานะบัญชีนั้น: `cx`, `cy`, `claude`, `codex` หรือ `grok` ธรรมดา อะไรก็ตามที่เรียกใช้ผ่าน `omarchy agent` และสคริปต์หรือโปรแกรมแก้ไขที่พบ CLI บน `PATH` สลับด้วย `omarchy agent account use work` (และสลับกลับด้วย `omarchy agent account use main`) หรือในแผงโดยการกดหมายเลขของบัญชีแล้วกด `Enter` (หรือคลิกดาวของมัน) เซสชัน Claude ที่กำลังทำงานอยู่ก็สลับเช่นกัน ตั้งแต่ข้อความถัดไปของพวกมัน: ทุกเซสชันของ Claude ทำงานใน `~/.claude` ซึ่งเก็บการลงชื่อเข้าใช้ของบัญชีที่ใช้งานอยู่ไว้เสมอ เซสชัน Claude ที่เริ่มในโฟลเดอร์ของบัญชีเองโดย Omarchy รุ่นเก่าจะเก็บการลงชื่อเข้าใช้นั้นไว้จนกว่ามันจะออก ดังนั้นการสลับจะระบุชื่อเซสชันเหล่านั้นและเสร็จสิ้นด้วยตัวเองเมื่อพวกมันหายไป เซสชัน Codex และ Grok ที่กำลังทำงานอยู่จะยังคงอยู่บนบัญชีที่พวกมันเริ่มต้นด้วย ประวัติการสนทนา การตั้งค่า สกิล และปลั๊กอินถูกใช้ร่วมกันข้ามบัญชี ดังนั้น `claude --continue` ในโฟลเดอร์เดียวกันจะสานต่อจากจุดที่คุณค้างไว้บนบัญชีใหม่

เมื่อมีมากกว่าหนึ่งบัญชี แผงจะแสดงขีดจำกัดของแต่ละบัญชีเคียงข้างกัน โดยมีดาวที่เติมเต็มอยู่บนบัญชีที่ใช้งานอยู่ Omarchy จะแจ้งเตือนคุณเมื่อบัญชีที่ใช้งานอยู่ผ่าน 95% ของขีดจำกัด และการคลิกการแจ้งเตือนจะสลับไปยังบัญชีที่มีพื้นที่เหลือมากที่สุด มันจะไม่สลับด้วยตัวเองเด็ดขาด เปลี่ยนเกณฑ์ได้ด้วย `omarchy agent account threshold 90` หากทุกบัญชีเกินเกณฑ์ คุณจะได้รับแจ้งเพียงครั้งเดียว พร้อมกับบัญชีใดจะว่างก่อน ขณะที่บัญชีที่ใช้งานอยู่ยังอยู่ภายใน 15 คะแนนจากเกณฑ์ของมัน (80% ที่ค่าเริ่มต้น) ขีดจำกัดของมันจะถูกตรวจสอบทุกสามนาทีแทนที่จะเป็นทุก 15 นาที

`omarchy agent account list` แสดงทุกบัญชีและขีดจำกัดล่าสุดของพวกมัน `omarchy agent account remove work` จะลืมบัญชีหนึ่งบัญชี และ `omarchy agent account rename primary Hey` จะเปลี่ยนชื่อบัญชีหนึ่งบัญชี (หรือคลิกชื่อบัญชีในแผง) คำสั่งเหล่านี้ทำงานกับบัญชีของเอเจนต์เริ่มต้นของคุณ; หากต้องการเข้าถึงผู้ให้บริการรายอื่น ให้ระบุชื่อมันก่อน เช่นใน `omarchy agent account use codex side` การเข้าสู่ระบบที่คุณมีอยู่แล้วใน `~/.claude` หรือ `~/.codex` คือบัญชี _Main_ ของ Codex จะยังคงอยู่ที่เดิม; ของ Claude จะรออยู่ในโฟลเดอร์ของมันเองขณะที่บัญชีอื่นกำลังใช้งานอยู่ บัญชีที่ไม่ได้ใช้งานมานานกว่าประมาณแปดชั่วโมงอาจแสดง _Sign-in required_; คลิกมันเพื่อลงชื่อบัญชีนั้นเข้าใช้อีกครั้งตรงในแผง หรือสลับไปยังมันและเริ่มเซสชัน ซึ่งจะรีเฟรชการลงชื่อเข้าใช้ด้วยตัวเอง เซิร์ฟเวอร์ MCP ที่คุณเพิ่มด้วย `claude mcp add` จะเข้าถึงทุกบัญชีของ Claude เนื่องจากพวกมันทั้งหมดทำงานใน `~/.claude`; สำหรับ Codex และ Grok เซิร์ฟเวอร์ที่คุณมีเมื่อตอนที่บัญชีถูกเพิ่มเข้ามาจะติดตามไปยังบัญชีนั้นด้วย แต่เซิร์ฟเวอร์ที่เพิ่มในภายหลังจะเข้าถึงเฉพาะบัญชีที่คุณเพิ่มพวกมันเข้าไปเท่านั้น Claude Desktop เก็บการลงชื่อเข้าใช้ของมันเองไว้ และเครื่องมือ Codex หรือ Grok ที่กำหนดค่าด้วยเส้นทางสัมบูรณ์ไปยังไบนารี CLI จะไม่ตามการสลับบัญชี `CLAUDE_CONFIG_DIR`, `CODEX_HOME` หรือ `GROK_HOME` ที่ระบุอย่างชัดเจนจะมีความสำคัญเหนือบัญชีที่เลือกไว้

### การวินิจฉัยการขัดข้อง

Omarchy เฝ้าดู systemd-coredump เพื่อหาการขัดข้องของกระบวนการ เมื่อคุณเลือกเอเจนต์เริ่มต้นแล้ว โปรแกรมใด ๆ ของคุณที่ dump core จะทำให้เกิดการแจ้งเตือน "Process crashed" — คลิกมัน และการขัดข้องจะถูกส่งมอบให้เอเจนต์เริ่มต้นของคุณพร้อมกับสกิล omarchy-diagnose-crash ของ Omarchy ซึ่งจะพาเอเจนต์เดินผ่านการสืบหาข้อเท็จจริงจาก core dump และการตัดสินใจว่าการขัดข้องนั้นคุ้มค่าที่จะรายงานไปยัง upstream หรือไม่ คุณยังรันมันด้วยมือกับ PID ใดก็ได้จาก `coredumpctl list` ด้วย `omarchy agent crash <pid>` ได้เช่นกัน

การเฝ้าดูเปิดอยู่โดยค่าเริ่มต้น ปิดมันได้ภายใต้ _Trigger > Toggle > Crash Capture Off_ (หรือด้วย `omarchy toggle crash-capture`) และการแจ้งเตือนจะหยุด; `omarchy agent crash <pid>` ยังคงทำงานด้วยมือได้

การขัดข้องยังสามารถถูกปิดเสียงได้ทีละโปรแกรม ซึ่งเป็นสิ่งที่การวินิจฉัยเสนอให้คุณในตอนท้าย `omarchy crash mute hyprland` หยุดการแจ้งเตือนสำหรับโปรแกรมนั้นเท่านั้น `omarchy crash mute hyprland off` จะนำพวกมันกลับมา และ `omarchy crash mute` ด้วยตัวมันเองเพียงอย่างเดียวจะแสดงรายการสิ่งที่คุณปิดเสียงไว้ มันรับเส้นทางของไบนารีได้อย่างยินดีพอ ๆ กับชื่อของมัน ดังนั้น `omarchy crash mute /usr/bin/hyprland` ก็ทำสิ่งเดียวกัน ใส่เครื่องหมายคำพูดครอบชื่อที่มีช่องว่าง เช่นใน `omarchy crash mute 'Some App'` ทุกอย่างอื่นยังคงแจ้งเตือนอยู่ และโปรแกรมที่ถูกปิดเสียงก็ยังคงขัดข้องอยู่ — สิ่งนี้เพียงซ่อนการเตือนความจำเท่านั้น มันไม่ได้แก้ไขอะไรเลย

### แอปบนเดสก์ท็อป

เมนู _Install > AI_ ยังมีแอป AI แบบกราฟิกอีกสองสามตัวด้วย: Amp Desktop, Antigravity Desktop, แอปเดสก์ท็อป ChatGPT, แอปเดสก์ท็อป Claude (เบต้าสำหรับ Linux ของ Anthropic พร้อมแท็บ Chat, Cowork และ Claude Code), Grok Bot สำหรับแชทกับโมเดลของ xAI, Herdr Desktop, Hermes Desktop, OpenClaw, แอปเดสก์ท็อป Perplexity และ T3 Code Grok Bot คือแอปแชทบนเดสก์ท็อป ส่วนเอเจนต์เขียนโค้ดคือคำสั่ง `grok`

Hermes Desktop เป็นตัวที่ต้องรู้ไว้ เพราะเครื่องหนึ่งเครื่องจะมี Hermes เพียงตัวเดียว และมันเป็นของแอป: Hermes จะถูกติดตั้งผ่านแอปเท่านั้นเสมอ และคำสั่ง `hermes` ที่เอเจนต์เริ่มต้นเรียกใช้ก็เป็นของแอป การเลือก Hermes เป็นเอเจนต์เริ่มต้นจะติดตั้งสิ่งเดียวกับที่รายการ _Install > AI_ ติดตั้ง: ตัวแพ็กเกจ และรันไทม์ของ Hermes ภายใต้ `~/.hermes` ที่ตั้งค่าโดยตัวติดตั้งของ Hermes เอง ซึ่งใช้เวลาสองสามนาทีในครั้งแรก รันไทม์นั้นคือ Hermes ตัวเดียวที่คำสั่ง `hermes` ในเทอร์มินัล เอเจนต์เริ่มต้น และแอปทั้งหมดใช้ร่วมกัน และมันอัปเดตตัวเองด้วย `hermes update` แทนที่จะรอการเปิดตัวของ Omarchy การติดตั้งมันยังมอบธีม Omarchy ให้ Hermes เป็นสกินชื่อ `omarchy` ซึ่งทุกพื้นผิวของ Hermes จะทำตามเมื่อคุณสลับธีม; เลือกตัวอื่นภายใต้การตั้งค่า Appearance ของ Hermes หรือด้วย `/skin` หากคุณไม่อยากให้มันเป็นเช่นนั้น และ Omarchy จะไม่แตะต้องตัวเลือกนั้นของคุุณ การลบแอปภายใต้ _Remove > AI_ จะปิด Hermes ก่อน รวมถึง gateway ด้วย แล้วนำรันไทม์นั้นออกไปด้วย และเก็บแชท ความทรงจำ และสกิลที่ Hermes เขียนขึ้นให้ตัวเองของคุณไว้ เว้นแต่คุณจะบอกให้ทำอย่างอื่น: มันจะถาม โดยค่าเริ่มต้นคือไม่ ว่าข้อมูลนั้นและการตั้งค่าการเชื่อมต่อของคุณควรจะถูกลบไปด้วยหรือไม่

ประสบการณ์บนเดสก์ท็อปของ OpenClaw คือ Control UI ของมัน ซึ่งเปิดเป็นเว็บแอปที่ได้รับการสนับสนุนโดย gateway ในเครื่องของมันเอง OpenClaw อาศัยอยู่ใน `~/.openclaw` และอัปเดตตัวเอง: ใช้ปุ่ม "Update Gateway" ของ Control UI หรือรัน `openclaw update` และ gateway จะรีสตาร์ทบนเวอร์ชันใหม่ Omarchy เพียงเลือกเวอร์ชันที่การติดตั้งใหม่จะเริ่มต้นจากเท่านั้น OpenClaw ยังสามารถเป็นเอเจนต์เริ่มต้นของคุณได้ด้วย: การเลือกมันด้วย `omarchy default agent openclaw` จะตั้งค่าสำเนาเดียวกันนั้นใน `~/.openclaw` และเอเจนต์จะเปิด UI ในเทอร์มินัลของ OpenClaw ที่เชื่อมต่อกับ gateway ของมัน การลบ OpenClaw ภายใต้ _Remove > AI_ จะนำบริการ gateway และแอปออกไปด้วย จากนั้นจะถามว่า `~/.openclaw` ควรจะถูกลบไปด้วยหรือไม่ เนื่องจากที่นั่นเก็บแชทและข้อมูลรับรองของคุณไว้พร้อมกับ OpenClaw เองและรันไทม์ปลั๊กอินที่มันดาวน์โหลดมา; ค่าเริ่มต้นจะเก็บมันไว้ และการติดตั้ง OpenClaw อีกครั้งจะหยิบมันกลับมาใช้

Herdr Desktop คือแอปเดสก์ท็อป [Herdr](https://herdr.dev): spaces, tabs และ panes ของเทอร์มินัลและเอเจนต์เขียนโค้ดที่ยังคงทำงานอยู่ในแกนหลักของมันเมื่อคุณปิดหน้าต่าง มันมาจากตัวติดตั้งของ Herdr เองแทนที่จะเป็นแพ็กเกจ ดังนั้นมันอาศัยอยู่ใน `~/.local/share/herdr-app`, นำแกนหลักของมันมาไว้ใน `~/.local/bin/herdr-core` เมื่อคุณยังไม่มี และอัปเดตทั้งสองอย่างด้วยตัวเอง มันอยู่ข้างคำสั่ง `herdr` ที่ Omarchy จัดส่งมาบน `Super + Ctrl + Return` แทนที่จะแทนที่คำสั่งนั้น และได้รับคีย์ตรงของคำสั่งนั้น: `Alt + Return` และ `Alt + Shift + Return` จะแยก pane ลงหรือไปทางขวา `Alt + Escape` ปิดมัน `Ctrl + Alt + Arrow` ย้ายระหว่าง panes `Alt + 1..9` และ `Alt + Left/Right` เลือกแท็บ และ `Alt + Up/Down` ย้ายระหว่าง spaces `Ctrl + 1..9` เลือก space และ `Alt + Shift + Up/Down` จะก้าวผ่านเอเจนต์ คีย์คำนำหน้า `Ctrl + Space` ยังคงใช้ได้เฉพาะในเทอร์มินัล เนื่องจากแอปไม่สามารถถือคีย์ Ctrl ธรรมดาไว้สำหรับลำดับคีย์ได้ Omarchy เขียนคีย์เหล่านี้ไปยัง `~/.config/herdr-app/keys.json` และ `omarchy-refresh-herdr-app` จะใส่พวกมันกลับคืน การติดตั้งมันจะเลือกธีม Omarchy ของ Herdr ซึ่งจะทำตามธีม Omarchy ของคุณนับจากนั้น Herdr เก็บธีมหนึ่งไว้สำหรับโหมดสว่างและอีกหนึ่งไว้สำหรับโหมดมืด ดังนั้นหลังจากสลับระหว่างธีม Omarchy แบบมืดและแบบสว่างแล้ว ให้เลือก Omarchy ในตัวเลือกธีมของ Herdr อีกครั้งสำหรับอีกโหมด

T3 Code ทำงานจากรุ่น AppImage อย่างเป็นทางการใน `~/.local/share/t3code` แทนที่จะมาจากแพ็กเกจ ดังนั้นมันจึงอัปเดตตัวเอง การติดตั้งมันจะถามว่าจะเริ่มบนช่อง Stable หรือ Nightly; สลับภายหลังได้ในการตั้งค่าของ T3 Code เธรดและการตั้งค่าของคุณอาศัยอยู่ใน `~/.t3` และการลบ T3 Code ภายใต้ _Remove > AI_ จะนำพวกมันออกไปด้วย

### โมเดลในเครื่อง

รันโมเดลแบบเปิดบนเครื่องของคุณเองสำหรับเอเจนต์เขียนโค้ดของคุณ พรอมต์และโค้ดของคุณอยู่บนเครื่อง; ไม่มีอะไรที่ส่งไปยังโมเดลออกจากเครื่องไป เริ่มต้นด้วย:

```bash
omarchy models use best text
```

นั่นจะตั้งค่าโมเดลข้อความที่ดีที่สุดสำหรับเครื่องนี้ ซึ่งเป็นชนิดที่เอเจนต์ของคุณใช้ โมเดลภาพ วิดีโอ และเพลง ต่างก็มีตัวที่ดีที่สุดของตัวเอง: `omarchy models use best image`, `video` หรือ `music` รัน `omarchy models use best` เพื่อดูว่าตัวเลือกของแต่ละชนิดสำหรับเครื่องนี้คืออะไร

หรือเลือก + ในแผงเอเจนต์: ภายใต้ _Use a local model_ มันจะแสดงทุกโมเดลเขียนโค้ดที่พอดีกับเครื่องนี้ โดยตัวที่แนะนำอยู่เป็นอันดับแรก Podman ซึ่งใช้รันโมเดล มาพร้อมกับ Omarchy เช่นเดียวกับชุดเครื่องมือคอนเทนเนอร์ของ NVIDIA บนเครื่อง NVIDIA ซึ่งมอบ GPU ให้แก่พวกมัน; หากอย่างใดอย่างหนึ่งขาดหายไป การตั้งค่าครั้งแรกจะติดตั้งมัน จากนั้น Omarchy จะเลือกโมเดลที่แนะนำสำหรับเครื่องนี้ ดาวน์โหลดมัน และเริ่มมัน คาดไว้ว่าจะมีการดาวน์โหลดขนาดหลายสิบ GB และหน่วยความจำส่วนใหญ่ของเครื่องจะถูกใช้ขณะโมเดลทำงาน: Flash Next ใช้ประมาณ 100 GiB กับบริบทเต็มขนาด 256K หากโมเดลอื่น ๆ ถือหน่วยความจำที่มันต้องการอยู่ มันจะถูกตั้งค่าไว้ในสถานะหยุด พร้อมที่จะเริ่มเมื่อคุณหยุดตัวใดตัวหนึ่ง โมเดลจะหยุดเมื่อออกจากระบบ; หยุดมันด้วยตัวเองเมื่อคุณต้องการหน่วยความจำสำหรับอย่างอื่น

`omarchy models list` แสดงตัวเลือกต่าง ๆ และอธิบายว่าทำไมบางตัวจึงไม่พอดี หากต้องการตั้งค่าอีกตัวหนึ่ง ให้รัน `omarchy models use <recipe>` ในวันนี้ `qwen3.8-flash-next-gufo` และ `qwen3.8-27b-gufo` พร้อมใช้งานสำหรับเครื่อง Strix Halo ขนาด 128 GB; ตัว 27B ใช้ประมาณ 40 GiB ดังนั้นมันจึงเหลือพื้นที่สำหรับงานอื่น บนแล็ปท็อปขนาด 64 GB ที่มี Arc B390 ของ Intel `qwen3.6-35b-a3b-llamacpp` ทำงานในประมาณ 30 GiB สูตรและคำแนะนำใหม่ ๆ มาพร้อมกับ `omarchy update` ผ่านทางแพ็กเกจ

โมเดลเขียนโค้ดที่คุณเพิ่มจะได้บรรทัดของตัวเองในแผงเอเจนต์ ข้าง ๆ การสมัครสมาชิกของคุณ: เล่นเพื่อเริ่มมัน หยุดชั่วคราวเพื่อหยุดมันและคืนหน่วยความจำของมัน เครื่องหมาย Tailscale เพื่อแชร์มันกับเครื่องอื่น ๆ บน tailnet ของคุณขณะที่มันทำงาน และปุ่มเทอร์มินัลเพื่อเปิดเอเจนต์ของคุณบนมัน บรรทัดของมันจะแสดงการดาวน์โหลด การโหลด หรือการหยุดตามที่เกิดขึ้น และจะบอกเมื่อมีหน่วยความจำว่างไม่เพียงพอที่จะเริ่มมัน หรือเชื่อมโยงไปยังบันทึกของมันเมื่อมันหยุดลงด้วยข้อผิดพลาด หลายตัวสามารถทำงานพร้อมกันได้เมื่อพวกมันพอดีในหน่วยความจำรวมกัน กด Delete บนบรรทัดที่เลือกเพื่อลบโมเดลออกจากเครื่องนี้ รวมทั้งไฟล์ที่ดาวน์โหลดทั้งหมด; + สามารถตั้งค่ามันขึ้นมาอีกครั้งได้ โมเดลเขียนโค้ดที่ตั้งค่าจากเทอร์มินัลจะรออยู่ภายใต้ + จนกว่าคุณจะเพิ่มมัน และโมเดลที่เครื่องซึ่งคุณจับคู่ด้วย (`omarchy models pair <host>`) กำลังรันอยู่ก็เช่นกัน

โมเดลเขียนโค้ดทุกตัวที่คุณตั้งค่ายังได้รายการของตัวเองในตัวเรียกใช้แอป ภายใต้ชื่อของโมเดลและพร้อมโลโก้ของผู้สร้างมัน ในแบบเดียวกับการลงชื่อเข้าใช้ Claude, Codex หรือ Grok ที่เพิ่มรายการหนึ่งเข้ามา มันจะเปิดเอเจนต์ของคุณบนโมเดลนั้น และเริ่มโมเดลก่อนหากมันยังไม่ได้ทำงานอยู่: เทอร์มินัลจะแสดงให้เห็นว่ามันกำลังโหลด และส่งมอบต่อให้เอเจนต์เมื่อมันพร้อม การลบโมเดลจะลบรายการของมันออก

ไม่ใช่ทุกโมเดลที่มีไว้สำหรับเขียนโค้ด โมเดลภาพ วิดีโอ และเพลงจะเปิดใน Fantasi แทน ซึ่งเป็นแอปของ Omarchy สำหรับสร้างภาพ วิดีโอ และเพลงด้วยโมเดลที่ทำงานบนเครื่องนี้ และถูกจัดการที่นั่นหรือด้วย `omarchy models`

โมเดลจะยังคงทำงานต่อไปอย่างที่มันถูกตั้งค่าไว้ ดังนั้นการอัปเดต Omarchy จะไม่รีสตาร์ทโมเดลภายใต้เอเจนต์ของคุณ เมื่อ Omarchy มีรันไทม์ที่ใหม่กว่าหรือน้ำหนักที่ใหม่กว่าสำหรับโมเดลที่คุณได้ตั้งค่าไว้ บรรทัดของมันจะแสดงปุ่มอัปเดต: กดมันแล้วโมเดลจะถูกตั้งค่าขึ้นอีกครั้งในเบื้องหลัง โดยดาวน์โหลดเฉพาะสิ่งที่เปลี่ยนแปลงไปเท่านั้น และรีสตาร์ทบนเวอร์ชันใหม่ โมเดลที่หยุดอยู่จะยังคงหยุดอยู่ `omarchy models update` ทำสิ่งเดียวกันสำหรับทุกโมเดลจากเทอร์มินัล

จากบรรทัดคำสั่ง `omarchy models start <recipe>` และ `omarchy models stop <recipe>` ทำสิ่งเดียวกัน `omarchy models status` แสดงทุกโมเดล และ `omarchy agent --local-model <recipe>` จะเปิดโมเดลนั้นใน pi ไม่ว่าเอเจนต์เริ่มต้นของคุณจะเป็นอะไรก็ตาม หากต้องการทำให้โมเดลในเครื่องของคุณเป็นสิ่งที่ปุ่มลัดเอเจนต์ คอนโซล Quake และ _Make something_ เปิด ให้รัน `omarchy default agent local` หรือติดดาวโมเดลที่กำลังทำงานอยู่ในแผงเอเจนต์ pi ยังแสดงทุกโมเดลที่คุณได้ตั้งค่าไว้ และโมเดลที่อยู่บนเครื่องที่คุณได้จับคู่ด้วย ในตัวเลือกโมเดลของมันเอง ดังนั้น `pi` ธรรมดาก็เข้าถึงพวกมันได้เช่นกัน ไคลเอนต์ใด ๆ ที่เข้ากันได้กับ OpenAI ก็สามารถเชื่อมต่อได้เช่นกัน: `status` แสดงที่อยู่ของแต่ละโมเดล (ตัวแรกคือ `http://127.0.0.1:11435/v1`) ชื่อสูตรคือชื่อโมเดล และคีย์อยู่ใน `~/.config/omarchy/agent-local/key`

`omarchy models remove <recipe>` จะลบโมเดลและการดาวน์โหลดที่ไม่มีโมเดลอื่นใช้

รันไทม์ของบุคคลที่สามจะถูกติดป้ายด้วยผู้เผยแพร่ของพวกมัน Omarchy รันทุกโมเดลโดยไม่มีการเข้าถึงเครือข่าย

### LLM ในเครื่อง

Omarchy แนะนำสองวิธีในการรันโมเดล LLM ในเครื่อง: LM Studio และ Ollama LM Studio ให้อินเทอร์เฟซแบบ GUI สำหรับการค้นหาโมเดลแบบ open-weight การติดตั้งพวกมัน และการรันพวกมัน เป็นวิธีที่ยอดเยี่ยมในการเริ่มต้นได้อย่างง่ายดาย Ollama เสนอ CLI สำหรับทำสิ่งเดียวกันในลักษณะคล้ายกัน แต่หากคุณยังใหม่กับโมเดลในเครื่อง ฉันขอแนะนำให้เริ่มด้วย LM Studio คุณสามารถติดตั้งอย่างใดอย่างหนึ่งได้ภายใต้ _Install > AI_ ในเมนู Omarchy

### สกิลของ Omarchy

สกิลของเอเจนต์ช่วยให้ AI ใช้เครื่องมือเฉพาะเจาะจงในวิธีเฉพาะเจาะจง และ Omarchy จัดส่งมาพร้อมกับสกิลเจ็ดตัว สกิล omarchy ครอบคลุมการปรับแต่งระบบ เช่น การปรับแต่งไฟล์คอนฟิก Hyprland ของคุณหรือการปรับแถบ omarchy-make-theme, omarchy-make-plugin, omarchy-make-app และ omarchy-make-game ครอบคลุมการสร้างสิ่งใหม่ ๆ omarchy-contribute ครอบคลุมการรายงานบั๊กหรือการส่งการแก้ไขไปยัง upstream และ omarchy-diagnose-crash จะทำงานไล่ผ่าน core dump ของการขัดข้อง พวกมันถูก symlink เข้าไปในไดเรกทอรีสกิลสำหรับ Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` และแต่ละ `~/.hermes/profiles/*/skills`) และตำแหน่งแบบทั่วไป `~/.agents/skills` ดังนั้น harness ส่วนใหญ่จึงหยิบพวกมันขึ้นมาโดยอัตโนมัติ โฟลเดอร์สกิลของคุณเองที่มีชื่อเดียวกันจะมีความสำคัญเหนือกว่า

แต่คุณควรปฏิบัติต่อสกิลเหล่านี้เสมือนเป็นของทดลอง โมเดลที่แตกต่างกันจะใช้มันให้เกิดผลที่แตกต่างกัน ทางที่ดีที่สุดคือรันในโหมดวางแผนก่อน เพื่อที่คุณจะได้เห็นแนวคิดว่าเอเจนต์อยากจะเปลี่ยนแปลงอะไร จากนั้นเตรียมพร้อมที่จะย้อนกลับการเปลี่ยนแปลง หรือแม้กระทั่งเรียกใช้ `omarchy reinstall configs` หากเอเจนต์ทำทุกอย่างเละเทะไปหมด
