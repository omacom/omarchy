### การติดตั้งและอัปเดต agent

ยกเว้น Hermes และ OpenClaw, agent เหล่านี้ใช้การติดตั้งแบบ lazy ของ mise: การเรียกใช้ครั้งแรกจะติดตั้ง CLI และการเรียกใช้ครั้งต่อ ๆ ไปจะใช้ตัวที่ติดตั้งไว้ mise ยังตรวจสอบว่า agent ที่ติดตั้งไว้มีรุ่นใหม่ออกมาหรือไม่ โดยตรวจไม่เกินหนึ่งครั้งทุกสี่ชั่วโมง ก่อนที่มันจะเริ่มทำงาน หรือในเบื้องหลังที่ shell prompt หากการอัปเดตนั้นล้มเหลวหรือคุณออฟไลน์อยู่ เวอร์ชันที่ติดตั้งไว้จะทำงาน `omarchy update` จะอัปเดต agent ที่ติดตั้งไว้พร้อมกับส่วนอื่น ๆ ของ Omarchy และ `mup` จะอัปเดตเฉพาะเครื่องมือที่ mise จัดการเท่านั้น

ตัวอัปเดตของ agent เอง เช่น `claude update`, `codex update` หรือปุ่มอัปเดตในแอป จะไม่อัปเดตตัวติดตั้งที่ mise จัดการ `codex update` จะล้มเหลว และ `claude update` อาจรายงานว่าสำเร็จในขณะที่ติดตั้งสำเนาแยกต่างหากที่ mise ไม่ได้ติดตาม หากคุณอยากใช้ตัวติดตั้งและตัวอัปเดตดั้งเดิมของ agent มากกว่า ให้เพิ่มมันลงใน `disable_tools`; ดู [เครื่องมือ CLI ที่ติดตั้งมาล่วงหน้า](18-development-tools.md#preinstalled-cli-tools)

หากต้องการติดตั้ง lazy tool ที่กำหนดค่าไว้ทั้งหมดก่อนที่คุณจะจำเป็นต้องใช้ ให้รัน `mise install --include-lazy` ซึ่งรวมถึงเครื่องมือ CLI ค่าเริ่มต้นอื่น ๆ ของ Omarchy ด้วยเช่นเดียวกับ agent ต่าง ๆ ดู [เครื่องมือ CLI ที่ติดตั้งมาล่วงหน้า](18-development-tools.md#preinstalled-cli-tools) สำหรับการติดตั้งเครื่องมือเดียวหรือการใช้ตัวติดตั้งของคุณเอง

`grok` ถูกติดตั้งผ่านแพ็กเกจ `grok` โดยตรงของ mise ในแบบเดียวกับ `claude` และ `codex` รัน `grok` หรือติดดาวให้มันในแผง agents ข้ามตัวติดตั้ง `curl | bash` บน x.ai ไปเลย เส้นทางนั้นจะวางสำเนาที่สองไว้ใน `~/.grok/bin`, แทรกมันไว้ด้านหน้าของ `PATH` และเขียนทับ wrapper ของ Omarchy

`dsh` เปิด browser UI ของมันที่ `127.0.0.1:3080` โดยใช้ไดเรกทอรีที่เรียกใช้เป็น workspace เริ่มต้น browser UI ของมันไม่รับ prompt เริ่มต้น ดังนั้น `omarchy agent prompt` จะเปิดมันโดยวาง prompt ไว้บน clipboard ของคุณให้แปะเอง Omarchy เริ่มมันด้วยชุดสิทธิ์แบบ no-approval ของ DeepSeek DeepSeek Harness จะอัปโหลดบันทึกเซสชันไปยัง DeepSeek เมื่อคุณใช้ model API อย่างเป็นทางการของมัน; ปิดการทำงานนั้นได้ภายใต้ _Settings > General > Upload Session Log_ ใน browser UI ของมัน ข้อเสนอแนะที่คุณส่งให้มันก็จะถูกอัปโหลดไปพร้อมกับเซสชันด้วย เว้นแต่คุณจะเริ่มมันด้วย `DSH_TELEMETRY_MODE=DISABLED`

### agent ค่าเริ่มต้น

เลือก agent ค่าเริ่มต้นของคุณด้วยดาวข้าง agent ในแผง agents ซึ่งจะถูกเติมเต็มสำหรับตัวค่าเริ่มต้น หรือด้วย `omarchy default agent <name>` ซึ่งรับ harness ใด ๆ ที่ไม่มีแถวอยู่ที่นั่นได้ด้วย หาก agent ยังไม่ได้ติดตั้ง การเลือกมันจะติดตั้งมันก่อน และมันยังได้ตัวเรียกใช้ของตัวเองใน app launcher ข้าง Agent ด้วย Omarchy ที่ติดตั้งใหม่จะเชิญคุณให้ตั้งค่าด้วยการแจ้งเตือนเพียงครั้งเดียว ซึ่งจะเปิดแผง agents

การเลือก Claude ยังพยายามตั้งค่าส่วนขยายเบราว์เซอร์ของมันสำหรับ Chromium, Chrome, Brave, Brave Origin และ Edge ด้วย การตั้งค่าส่วนขยายมีผลกับผู้ใช้ทั้งหมดและอาจขอรหัสผ่านระบบของคุณ; การยกเลิกหรือการติดตั้งส่วนขยายที่ล้มเหลวก็ยังคงเลือกและเปิด Claude อยู่ดี รีสตาร์ทเบราว์เซอร์ของคุณ เปิดใช้งานส่วนขยายหากระบบแจ้ง และลงชื่อเข้าใช้ Claude เพื่อเชื่อมต่อให้เสร็จ รัน `/chrome` ใน Claude เพื่อตรวจสอบการเชื่อมต่อ Firefox และ Zen ไม่รองรับส่วนขยายนี้ หาก Claude เป็นค่าเริ่มต้นของคุณอยู่แล้วก่อนที่จะมีการเพิ่มการตั้งค่านี้ ให้เลือกมันอีกครั้งเพื่อติดตั้งส่วนขยาย

เมื่อคุณเลือกแล้ว `Super + Shift + Ctrl + A` จะเปิด agent ค่าเริ่มต้นในหน้าต่าง terminal แยกต่างหาก (หรือเปิดตัวเลือกขึ้นมาหากคุณยังไม่ได้เลือก) คุณยังเปิดมันให้ทำงานทันทีได้ด้วย `omarchy agent prompt "Review this project"` Freebuff และ DeepSeek Harness ไม่รับ prompt เริ่มต้น ดังนั้นพวกมันจะเปิดโดยวาง prompt ไว้บน clipboard ของคุณให้แปะแทน agent ที่เปิดด้วยวิธีนี้จะทำงานโดยไม่มีผู้ดูแลในโหมด don't-stop-to-ask ของแต่ละตัว ดังนั้นเตรียมพร้อมให้พวกมันลงมือทำสิ่งต่าง ๆ จริง ๆ ได้เลย! MiniMax Code ไม่มีโหมดดังกล่าวสำหรับเซสชันแบบโต้ตอบของมัน ดังนั้นมันจะขอสิทธิ์ตามปกติ และเนื่องจาก agent ปฏิเสธที่จะจดจำความไว้วางใจสำหรับไดเรกทอรีบ้านของคุณ การเปิดจาก `$HOME` จะเริ่มใน `~/Work` แทน

ยังมีทางลัดใน terminal ด้วย: `a` รัน agent ค่าเริ่มต้นแบบ inline ใน terminal ปัจจุบัน ขณะที่ `c`, `cx` และ `cy` เริ่ม OpenCode, Claude Code และ Codex โดยตรง (อีกครั้งในโหมดอนุมัติอัตโนมัติของพวกมัน) การเปลี่ยนธีมยังซิงค์ไปยัง agent ด้วย: Claude Code, Pi, OpenCode และ Hermes (เมื่อ Omarchy ติดตั้งมันแล้ว) จะเปลี่ยนตามทั้งหมดเมื่อคุณสลับธีม Omarchy

### คำสั่งสำหรับ agent ของคุณ

กฎส่วนตัวสำหรับทุก agent อยู่ใน `~/.agents/AGENTS.md` ข้าง shared skills ใน `~/.agents/skills` เปิดมันด้วยไอคอนเอกสารข้าง + ในแผง agents หรือ `omarchy agent instructions --edit` ซึ่งยังเชื่อมมันเข้าไปในแต่ละ harness ที่เก็บไฟล์ global ของตัวเองไว้ด้วย: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` ของ Copilot และอื่น ๆ Crush และ Amp อ่านลิงก์ `~/.config/AGENTS.md` ขณะที่ omp, Kimi และ DeepSeek Harness อ่าน `~/.agents/AGENTS.md` โดยตรง การเลือก agent ค่าเริ่มต้นก็เชื่อมมันด้วยเช่นกัน ไฟล์คำสั่งที่คุณมีอยู่แล้วจะกลายเป็นไฟล์ที่ใช้ร่วมกันหากยังไม่มีไฟล์ดังกล่าว; มิฉะนั้นมันจะถูกเก็บไว้ข้างลิงก์ในชื่อ `.bak` รัน `omarchy agent instructions` เพื่อเชื่อมใหม่หลังจากติดตั้ง agent อีกตัว

### แผง agents

แถบบนสุดมีไอคอน agents ก่อนที่คุณจะตั้งค่า agent แผงของมันมีสามวิธีให้เริ่มต้น: ลงชื่อเข้าใช้การสมัครสมาชิก Claude, Codex, Grok, Gemini, Muse, Cursor หรือ Copilot หรือภายใต้ More เป็นแผน coding ของ OpenCode Go, MiniMax, Synthetic หรือ Z.ai; จ่ายตามใช้จริงกับ Fireworks, OpenCode Zen and Go, OpenRouter หรือภายใต้ More เป็น DeepSeek หรือผู้ให้บริการรายอื่นใดที่ OpenCode ลงชื่อเข้าใช้ได้ โดยทั้งหมดรันใน OpenCode; หรือรันโมเดลที่ดีที่สุดสำหรับคอมพิวเตอร์ของคุณ เมื่อมีโมเดลที่เหมาะกับมัน ตัวแรกที่คุณตั้งค่าเสร็จจะกลายเป็น agent ค่าเริ่มต้นของคุณ และเครื่องหมาย + ในแผง หรือ _Agent > Add_ ใน Omarchy Menu จะเสนอสามวิธีเดียวกันนั้นในภายหลัง หลังจากนั้น แผงจะวางทุกการสมัครสมาชิกไว้ในหน้าเดียว: แต่ละ agent และบัญชีพร้อมแผนของมัน มาตรวัดสำหรับขีดจำกัดเซสชัน 5 ชั่วโมงและรายสัปดาห์ของแต่ละตัวพร้อมเวลาจนกว่าจะรีเซ็ต (เลื่อนเมาส์ไปวางเพื่อดูเปอร์เซ็นต์ที่แน่นอน) หรือยอดคงเหลือแบบเติมเงินที่เหลืออยู่ ภายใต้บรรทัดที่หมุนเวียนสิ่งที่คุณใช้ไปในทุกตัว เช่น tokens ในสัปดาห์นี้และโมเดลที่คุณใช้มากที่สุด ภายใต้ _Make something cool_ มันเสนอ prompt เริ่มต้นสำหรับธีม ปลั๊กอิน แอป หรือเกมใหม่ที่มอบงานนั้นให้ agent ค่าเริ่มต้นของคุณ แอปถูกสร้างในแบบเดียวกับ Hype, Monologue และ Omacut ของ Omarchy เอง ใน C++ และ Qt Quick โดยทำตาม agent skill ชื่อ omarchy-make-app และ compiler และชิ้นส่วน Qt ที่พวกมันต้องการก็ติดตั้งมาให้แล้ว เกมเป็นหน้า three.js เดียวใน `~/Games/vibes` โดยทำตาม agent skill ชื่อ omarchy-make-game และทั้งหมดเปิดจากตัวเรียกใช้ Game Vibes เดียวในธีมปัจจุบัน; พวกมันโหลด three.js จากเว็บ ดังนั้นพวกมันต้องมีการเชื่อมต่อเพื่อเริ่มทำงาน Claude Code, Codex, Grok, Kimi, Cursor และโควตา Grok Bot ของมัน, GitHub Copilot, Muse, Gemini (ผ่าน Antigravity) และ Devin ได้รับการครอบคลุมมาตั้งแต่แรกพร้อมขีดจำกัดของพวกมัน, Kimchi พร้อมแผน เครดิตเติมเงิน และงบการใช้จ่ายของมัน และ Hermes, Mistral Vibe และ Qwen Code จะแสดงเซสชันและ tokens ของพวกมันเมื่อคุณได้ใช้พวกมันแล้ว แผนและคีย์ของผู้ให้บริการที่คุณใช้ผ่าน pi, omp หรือ opencode ก็ปรากฏด้วยเช่นกัน: OpenCode Zen and Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan และ Synthetic พร้อมขีดจำกัดของพวกมัน; OpenRouter และ DeepSeek พร้อมยอดคงเหลือแบบเติมเงินของพวกมัน; Fireworks พร้อมยอดใช้จ่ายในช่วง 30 วันที่ผ่านมา Tokens จากโมเดลที่คุณรันบนฮาร์ดแวร์ของคุณเองก็นับรวมในยอดรวมด้วย; โมเดลเหล่านั้นเองมีแผงของตัวเอง ซึ่งอธิบายไว้ภายใต้ [โมเดลในเครื่อง](#local-models) ทุก agent จะถูกนับเพียงครั้งเดียว ภายใต้ผู้ที่เรียกเก็บเงินจากมัน ไม่ว่าคุณจะขับเคลื่อนมันผ่าน harness กี่ตัวก็ตาม

คลิกซ้ายที่ไอคอนบนแถบหรือกด `Super + Ctrl + X` เพื่อเปิดแผง คลิกขวาเพื่อเปิด agent ค่าเริ่มต้นของคุณ และคลิกกลางเพื่อรีเฟรช บันทึกการใช้งานที่อยู่เบื้องหลังมันจะถูกสร้างใหม่ทุก 15 นาทีโดย `omarchy agent usage update` และแผงยังสามารถรวมการใช้งานจากเครื่องอื่น ๆ ของคุณผ่านโฟลเดอร์ที่ซิงค์ไว้ได้ด้วย ดู README ภายใต้ `$OMARCHY_PATH/shell/plugins/agents/` สำหรับการตั้งค่าทั้งหมด

### การสมัครสมาชิกหลายรายการ

หากคุณจ่ายเงินสำหรับแผน Claude, Codex หรือ Grok มากกว่าหนึ่งแผน — เช่น Max ส่วนตัวและอีกอันสำหรับงาน — Omarchy สามารถให้พวกมันทั้งหมดลงชื่อเข้าใช้ค้างไว้และสลับไปมาระหว่างกันได้ เพิ่มการสมัครสมาชิกด้วยเครื่องหมาย + ในแผง agents ซึ่งจะพาคุณทำตามขั้นตอนตรงนั้นเลย หรือด้วย `omarchy agent account add claude Work` (หรือ `codex` หรือ `grok`) เครื่องหมาย + และคำสั่งเดียวกันนี้ลงชื่อเข้าใช้ Gemini (`gemini`) และ OpenCode (`opencode`) และบันทึก API key ของ Fireworks (`fireworks`) หรือ OpenRouter (`openrouter`) ใน OpenCode; คำสั่งยังลงชื่อเข้าใช้ Copilot (`copilot`), Cursor (`cursor`) และ Muse (`muse`) ด้วย พวกนั้นเก็บการลงชื่อเข้าใช้เพียงรายการเดียวต่อตัว มันจะติดตั้ง CLI หากยังไม่มี บัญชีแรกสำหรับผู้ให้บริการรายหนึ่งจะลงชื่อเข้าใช้ผ่านเบราว์เซอร์ปกติของคุณ ตรงจุดที่ CLI มองหาอยู่เสมอ ทุกบัญชีหลังจากนั้นจะลงชื่อเข้าใช้ผ่านหน้าต่างส่วนตัว ดังนั้นบัญชีที่เบราว์เซอร์ของคุณลงชื่อเข้าใช้อยู่แล้วจะไม่ถูกหยิบมาโดยผิดพลาด; ลงชื่อเข้าใช้ที่นั่นในฐานะบัญชีที่คุณกำลังเพิ่ม และปิดหน้าต่างส่วนตัวใด ๆ ที่คุณเปิดค้างไว้ก่อน อย่าออกจากระบบของ CLI เพื่อทำสิ่งนี้เด็ดขาด: การออกจากระบบจะเพิกถอนการลงชื่อเข้าใช้ที่บันทึกไว้ และบัญชีนั้นจะต้องถูกเพิ่มใหม่อีกครั้ง

หากต้องการคัดลอกการเข้าสู่ระบบการสมัครสมาชิกของคุณไปยังเครื่อง Omarchy อีกเครื่องผ่าน SSH ให้รัน `omarchy agent account copy user@laptop` ผู้ส่งจะจัดหาตัวรับชั่วคราวให้เมื่อปลายทางยังไม่มีตัวรับติดตั้งไว้ ดังนั้นเครื่อง Omarchy รุ่นเก่ากว่าจึงสามารถรับบัญชีได้โดยไม่ต้องอัปเดต ตัวรับที่ติดตั้งไว้จะมีความสำคัญเหนือกว่า การดำเนินการนี้คัดลอกการสมัครสมาชิก Claude, Codex และ Grok ทั้งหมด; เพิ่มชื่อผู้ให้บริการเพื่อเลือกพวกมัน เช่นใน `omarchy agent account copy laptop claude` ชื่อบัญชีและ ID คำสั่งจะตรงกับต้นทาง รวมถึงบัญชีที่มีอยู่แล้วบนปลายทางด้วย บัญชีปลายทางที่ไม่เกี่ยวข้องกันจะได้รับส่วนต่อท้ายเป็นตัวเลขหากชื่อของพวกมันขัดกัน และการตั้งค่า skills ปลั๊กอิน และประวัติการสนทนาจะยังคงอยู่เฉพาะในแต่ละเครื่อง

ข้อมูลประจำตัวที่มีอยู่บนปลายทางจะถูกเก็บไว้ บัญชีต้นทางที่ลงชื่อเข้าใช้อยู่ที่นั่นแล้วจะมีชื่อของมันถูกซิงค์โดยไม่แทนที่ข้อมูลประจำตัวของมัน; บัญชีอื่น ๆ จะถูกเพิ่มควบคู่กันไป หากต้องการแทนที่ข้อมูลประจำตัวที่บันทึกไว้สำหรับบัญชีที่ตรงกัน ให้ใช้ `omarchy agent account copy --replace laptop claude` หลังจากออกจากเซสชันของบัญชีนั้นบนปลายทางแล้ว ปลายทางใหม่ยังได้รับบัญชีที่ใช้งานอยู่และการตั้งค่าการสลับของต้นทางด้วย; ปลายทางที่ตั้งค่าไว้แล้วจะเก็บของตัวเองไว้

ข้อมูลประจำตัวเดินทางผ่าน SSH และถูกเก็บไว้ในไฟล์ส่วนตัวบนปลายทาง ดังนั้นจงคัดลอกไปยังเครื่องที่คุณไว้วางใจเท่านั้น นี่เป็นการคัดลอกเพียงครั้งเดียว ไม่ใช่การซิงโครไนซ์อย่างต่อเนื่อง refresh token ของ Codex สามารถถูกหมุนเวียนโดยเครื่องอื่นได้ ทำให้การเข้าสู่ระบบที่คัดลอกมาต้องต่ออายุ; การลงชื่อเข้าใช้แยกกันยังคงเป็นตัวเลือกที่น่าเชื่อถือที่สุดสำหรับการใช้งานพร้อมกันบนหลายเครื่อง ดู [คำแนะนำการยืนยันตัวตนบัญชีของ Codex](https://developers.openai.com/codex/auth/ci-cd-auth)

บัญชีเดียวต่อผู้ให้บริการหนึ่งรายจะใช้งานอยู่ และทุกเซสชันใหม่จะเริ่มเป็นบัญชีนั้น: `cx`, `cy`, `claude`, `codex` หรือ `grok` ธรรมดา อะไรก็ตามที่เปิดผ่าน `omarchy agent` และสคริปต์หรือ editor ที่พบ CLI บน `PATH` สลับด้วย `omarchy agent account use work` (และสลับกลับด้วย `omarchy agent account use main`) หรือในแผงโดยกดหมายเลขของบัญชีแล้วกด `Enter` (หรือคลิกดาวของมัน) เซสชัน Claude ที่กำลังทำงานอยู่ก็สลับด้วยเช่นกัน ตั้งแต่ข้อความถัดไปของพวกมัน: ทุกเซสชัน Claude ทำงานใน `~/.claude` ซึ่งเก็บการลงชื่อเข้าใช้ของบัญชีที่ใช้งานอยู่ไว้เสมอ เซสชัน Claude ที่เริ่มในโฟลเดอร์ของบัญชีเองโดย Omarchy รุ่นเก่าจะเก็บการลงชื่อเข้าใช้นั้นไว้จนกว่าจะออก ดังนั้นการสลับจะระบุชื่อเซสชันเหล่านั้นและเสร็จสิ้นด้วยตัวเองเมื่อพวกมันหายไป เซสชัน Codex และ Grok ที่กำลังทำงานอยู่จะยังคงอยู่บนบัญชีที่พวกมันเริ่มด้วย ประวัติการสนทนา การตั้งค่า skills และปลั๊กอินถูกใช้ร่วมกันข้ามบัญชี ดังนั้น `claude --continue` ในโฟลเดอร์เดียวกันจะดำเนินการต่อจากจุดที่คุณค้างไว้บนบัญชีใหม่

เมื่อมีมากกว่าหนึ่งบัญชี แผงจะแสดงขีดจำกัดของแต่ละบัญชีเคียงข้างกัน โดยมีดาวที่เติมเต็มอยู่บนบัญชีที่กำลังใช้งาน Omarchy จะแจ้งเตือนคุณเมื่อบัญชีที่ใช้งานอยู่เกิน 95% ของขีดจำกัด และการคลิกการแจ้งเตือนจะสลับไปยังบัญชีที่มีพื้นที่เหลือมากที่สุด มันจะไม่สลับด้วยตัวเอง เปลี่ยนเกณฑ์ได้ด้วย `omarchy agent account threshold 90` หากทุกบัญชีเกินเกณฑ์ คุณจะได้รับแจ้งเพียงครั้งเดียว พร้อมกับบัญชีใดจะว่างก่อน ขณะที่บัญชีที่ใช้งานอยู่ห่างจากเกณฑ์ของมันภายใน 15 จุด (80% ที่ค่าเริ่มต้น) ขีดจำกัดของมันจะถูกตรวจสอบทุกสามนาทีแทนที่จะเป็นทุก 15 นาที

`omarchy agent account list` แสดงทุกบัญชีและขีดจำกัดล่าสุดของมัน `omarchy agent account remove work` ลบบัญชีหนึ่งออก และ `omarchy agent account rename primary Hey` เปลี่ยนชื่อบัญชีหนึ่ง (หรือคลิกชื่อบัญชีในแผง) คำสั่งเหล่านี้ทำงานกับบัญชีของ agent ค่าเริ่มต้นของคุณ; หากต้องการเข้าถึงผู้ให้บริการรายอื่น ให้ระบุชื่อมันก่อน เช่นใน `omarchy agent account use codex side` การเข้าสู่ระบบที่คุณมีอยู่แล้วใน `~/.claude` หรือ `~/.codex` คือบัญชี _Main_ ของ Codex จะอยู่ที่เดิม; ของ Claude จะรออยู่ในโฟลเดอร์ของตัวเองขณะที่บัญชีอื่นใช้งานอยู่ บัญชีที่ไม่ได้ใช้งานนานกว่าประมาณแปดชั่วโมงอาจแสดง _Sign-in required_; คลิกมันเพื่อลงชื่อเข้าใช้บัญชีนั้นอีกครั้งในแผงทันที หรือสลับไปยังมันและเริ่มเซสชัน ซึ่งจะรีเฟรชการลงชื่อเข้าใช้ด้วยตัวเอง MCP server ที่คุณเพิ่มด้วย `claude mcp add` จะเข้าถึงทุกบัญชี Claude เนื่องจากพวกมันทั้งหมดทำงานใน `~/.claude`; สำหรับ Codex และ Grok เซิร์ฟเวอร์ที่คุณมีตอนที่เพิ่มบัญชีจะมาพร้อมกับมัน แต่เซิร์ฟเวอร์ที่เพิ่มในภายหลังจะเข้าถึงเฉพาะบัญชีที่คุณเพิ่มพวกมันเข้าไปเท่านั้น Claude Desktop เก็บการลงชื่อเข้าใช้ของตัวเองไว้ และเครื่องมือ Codex หรือ Grok ที่กำหนดค่าด้วยเส้นทางสัมบูรณ์ไปยังไบนารี CLI จะไม่ทำตามการสลับ ค่า `CLAUDE_CONFIG_DIR`, `CODEX_HOME` หรือ `GROK_HOME` ที่ระบุอย่างชัดเจนจะมีความสำคัญเหนือกว่าบัญชีที่เลือกไว้

### การวินิจฉัยการขัดข้อง

Omarchy เฝ้าดู systemd-coredump สำหรับการขัดข้องของกระบวนการ เมื่อคุณเลือก agent ค่าเริ่มต้นแล้ว โปรแกรมใด ๆ ของคุณที่ dump core จะนำการแจ้งเตือน "Process crashed" มา — คลิกมัน และการขัดข้องจะถูกส่งให้ agent ค่าเริ่มต้นของคุณพร้อมกับ skill ชื่อ omarchy-diagnose-crash ของ Omarchy ซึ่งจะพา agent ไปตามขั้นตอนการสืบหาข้อเท็จจริงจาก core dump และตัดสินใจว่าการขัดข้องนั้นคุ้มค่าที่จะรายงานไปยัง upstream หรือไม่ คุณยังรันมันด้วยตัวเองสำหรับ PID ใด ๆ จาก `coredumpctl list` ด้วย `omarchy agent crash <pid>` ได้ด้วย

การเฝ้าดูเปิดอยู่ตามค่าเริ่มต้น ปิดมันภายใต้ _Trigger > Toggle > Crash Capture Off_ (หรือด้วย `omarchy toggle crash-capture`) และการแจ้งเตือนจะหยุด; `omarchy agent crash <pid>` ยังคงทำงานด้วยตัวเองได้

การขัดข้องยังสามารถปิดเสียงได้ทีละโปรแกรม ซึ่งเป็นสิ่งที่การวินิจฉัยเสนอให้คุณในตอนท้าย `omarchy crash mute hyprland` หยุดการแจ้งเตือนสำหรับโปรแกรมนั้นเท่านั้น `omarchy crash mute hyprland off` นำพวกมันกลับมา และ `omarchy crash mute` อย่างเดียวจะแสดงรายการสิ่งที่คุณปิดเสียงไว้ มันรับเส้นทางของไบนารีได้เป็นอย่างดีเช่นเดียวกับชื่อของมัน ดังนั้น `omarchy crash mute /usr/bin/hyprland` จึงทำสิ่งเดียวกัน ใส่เครื่องหมายคำพูดให้กับชื่อที่มีช่องว่างอยู่ เช่นใน `omarchy crash mute 'Some App'` ทุกอย่างอื่นยังคงแจ้งเตือนอยู่ และโปรแกรมที่ถูกปิดเสียงยังคงขัดข้องอยู่ — นี่เป็นการซ่อนการเตือน ไม่ได้แก้ไขอะไรเลย

### แอปเดสก์ท็อป

เมนู _Install > AI_ ยังมีแอป AI แบบกราฟิกอยู่สองสามตัวด้วย: Amp Desktop, Antigravity Desktop, แอปเดสก์ท็อป ChatGPT, แอปเดสก์ท็อป Claude (Linux beta ของ Anthropic พร้อมแท็บ Chat, Cowork และ Claude Code), Grok Bot สำหรับแชทกับโมเดลของ xAI, Herdr Desktop, Hermes Desktop, OpenClaw, แอปเดสก์ท็อป Perplexity และ T3 Code Grok Bot คือแอปแชทบนเดสก์ท็อป ส่วน coding agent คือคำสั่ง `grok`

Hermes Desktop คือตัวที่คุณควรทำความรู้จัก เพราะเครื่องหนึ่งเครื่องมี Hermes เพียงตัวเดียว และมันเป็นของแอป: Hermes จะถูกติดตั้งผ่านแอปเท่านั้น และคำสั่ง `hermes` ที่ agent ค่าเริ่มต้นรันก็เป็นของแอป การเลือก Hermes เป็น agent ค่าเริ่มต้นจะติดตั้งสิ่งเดียวกับที่รายการ _Install > AI_ ทำ: แพ็กเกจ และ runtime ของ Hermes ภายใต้ `~/.hermes` ที่ตั้งค่าโดยตัวติดตั้งของ Hermes เอง ซึ่งใช้เวลาสองสามนาทีในครั้งแรก runtime นั้นคือ Hermes ตัวเดียวที่คำสั่ง `hermes` ใน terminal, agent ค่าเริ่มต้น และแอปทั้งหมดใช้ และมันอัปเดตตัวเองด้วย `hermes update` แทนที่จะรอการออก Omarchy รุ่นใหม่ การติดตั้งมันยังมอบธีม Omarchy ให้ Hermes ในรูปของ skin ชื่อ `omarchy` ซึ่งทุกพื้นผิวของ Hermes จะทำตามเมื่อคุณสลับธีม; เลือกตัวอื่นภายใต้การตั้งค่า Appearance ของ Hermes หรือด้วย `/skin` หากคุณไม่อยากให้มันทำแบบนั้น และ Omarchy จะไม่ยุ่งกับตัวเลือกนั้น การลบแอปภายใต้ _Remove > AI_ จะปิด Hermes ก่อน รวมถึง gateway ด้วย นำ runtime นั้นไปด้วย และเก็บแชท ความทรงจำ และ skills ที่ Hermes เขียนให้ตัวเองไว้ เว้นแต่คุณจะบอกเป็นอย่างอื่น: มันจะถาม โดยค่าเริ่มต้นคือไม่ ว่าข้อมูลนั้นและการตั้งค่าการเชื่อมต่อของคุณควรหายไปด้วยหรือไม่

ประสบการณ์เดสก์ท็อปของ OpenClaw คือ Control UI ของมัน ซึ่งเปิดเป็น web app ที่หนุนโดย local gateway ของตัวเอง OpenClaw อาศัยอยู่ใน `~/.openclaw` และอัปเดตตัวเอง: ใช้ปุ่ม "Update Gateway" ของ Control UI หรือรัน `openclaw update` และ gateway จะรีสตาร์ทบนเวอร์ชันใหม่ Omarchy เพียงเลือกว่ารุ่นใดที่การติดตั้งใหม่จะเริ่มต้นจาก OpenClaw ยังสามารถเป็น agent ค่าเริ่มต้นของคุณได้ด้วย: การเลือกมันภายใต้ _Agent > Harness_ จะตั้งค่าสำเนาเดียวกันนั้นใน `~/.openclaw` และ agent จะเปิด terminal UI ของ OpenClaw ที่เชื่อมกับ gateway ของมัน การลบ OpenClaw ภายใต้ _Remove > AI_ จะนำบริการ gateway และแอปไปด้วย จากนั้นจะถามว่า `~/.openclaw` ควรหายไปด้วยหรือไม่ เนื่องจากที่นั่นเก็บแชทและข้อมูลประจำตัวของคุณควบคู่ไปกับตัว OpenClaw เองและ runtime ของปลั๊กอินที่มันดาวน์โหลด; ค่าเริ่มต้นจะเก็บมันไว้ และการติดตั้ง OpenClaw อีกครั้งจะหยิบมันกลับมาใช้

Herdr Desktop คือแอปเดสก์ท็อป [Herdr](https://herdr.dev): spaces, tabs และ panes ของ terminal และ coding agent ที่ยังคงทำงานอยู่ใน core ของมันเมื่อคุณปิดหน้าต่าง มันมาจากตัวติดตั้งของ Herdr เองแทนที่จะเป็นแพ็กเกจ ดังนั้นมันจึงอาศัยอยู่ใน `~/.local/share/herdr-app` นำ core ของมันมาด้วยใน `~/.local/bin/herdr-core` เมื่อคุณยังไม่มี และอัปเดตทั้งตัวมันเอง มันอยู่ข้างคำสั่ง `herdr` ที่ Omarchy ส่งมาบน `Super + Ctrl + Return` แทนที่จะแทนที่มัน และได้รับปุ่มโดยตรงของคำสั่งนั้น: `Alt + Return` และ `Alt + Shift + Return` แยก pane ลงหรือไปทางขวา `Alt + Escape` ปิดมัน `Ctrl + Alt + Arrow` ย้ายระหว่าง panes `Alt + 1..9` และ `Alt + Left/Right` เลือกแท็บ และ `Alt + Up/Down` ย้ายระหว่าง spaces `Ctrl + 1..9` เลือก space และ `Alt + Shift + Up/Down` ไล่ไปตาม agent ปุ่มนำหน้า `Ctrl + Space` ยังคงใช้เฉพาะใน terminal เนื่องจากแอปไม่สามารถค้างปุ่ม Ctrl ธรรมดาไว้สำหรับลำดับได้ Omarchy เขียนค่าเหล่านี้ลงใน `~/.config/herdr-app/keys.json` และ `omarchy-refresh-herdr-app` จะนำพวกมันกลับมา การติดตั้งมันจะเลือกธีม Omarchy ของ Herdr ซึ่งจะทำตามธีม Omarchy ของคุณนับจากนั้น Herdr เก็บธีมหนึ่งสำหรับโหมดสว่างและอีกหนึ่งสำหรับโหมดมืด ดังนั้นหลังจากสลับระหว่างธีม Omarchy แบบมืดและแบบสว่างแล้ว ให้เลือก Omarchy ในตัวเลือกธีมของ Herdr อีกครั้งสำหรับอีกโหมดหนึ่ง

T3 Code ทำงานจากรุ่น AppImage อย่างเป็นทางการของมันใน `~/.local/share/t3code` แทนที่จะมาจากแพ็กเกจ ดังนั้นมันจึงอัปเดตตัวเอง การติดตั้งมันจะถามว่าจะเริ่มบนช่อง Stable หรือ Nightly; สลับในภายหลังได้ในการตั้งค่าของ T3 Code thread และการตั้งค่าของคุณอาศัยอยู่ใน `~/.t3` และการลบ T3 Code ภายใต้ _Remove > AI_ จะนำพวกมันไปด้วย

### โมเดลในเครื่อง

รันโมเดลแบบเปิดบนเครื่องของคุณเองสำหรับ coding agent ของคุณ prompt และโค้ดของคุณยังคงอยู่บนเครื่อง; ไม่มีอะไรที่ส่งไปยังโมเดลออกจากเครื่องไป เริ่มต้นด้วย:

```bash
omarchy models use best text
```

นั่นจะตั้งค่าโมเดลข้อความที่ดีที่สุดสำหรับเครื่องนี้ ซึ่งเป็นชนิดที่ agent ของคุณใช้ โมเดลภาพ วิดีโอ และเพลงมีตัวที่ดีที่สุดของตัวเอง: `omarchy models use best image`, `video` หรือ `music` รัน `omarchy models use best` เพื่อดูตัวเลือกของแต่ละชนิดสำหรับเครื่องนี้

หรือเปิดแผง local models จากไอคอนประกายของมันในแถบบนสุด ข้างไอคอน agents หรือด้วย Super + Ctrl + Alt + X และเลือก + ไอคอนจะปรากฏขึ้นเมื่อมีโมเดลที่เหมาะกับเครื่องนี้ Podman ซึ่งรันโมเดลต่าง ๆ มาพร้อมกับ Omarchy เช่นเดียวกับ container toolkit ของ NVIDIA บนเครื่อง NVIDIA ซึ่งให้ GPU แก่พวกมัน; หากตัวใดตัวหนึ่งขาดไป การตั้งค่าครั้งแรกจะติดตั้งมัน จากนั้น Omarchy จะเลือกโมเดลที่แนะนำสำหรับเครื่องนี้ ดาวน์โหลดมัน และเริ่มมัน คาดว่าจะมีการดาวน์โหลดหลายสิบ GB และหน่วยความจำส่วนใหญ่ของเครื่องจะถูกใช้งานขณะที่โมเดลทำงาน: Flash Next ใช้ประมาณ 100 GiB พร้อม context เต็ม 256K ของมัน หากโมเดลอื่น ๆ ถือหน่วยความจำที่มันต้องการอยู่ มันจะถูกตั้งค่าไว้ในสถานะหยุด พร้อมเริ่มเมื่อคุณหยุดตัวใดตัวหนึ่ง โมเดลจะหยุดเมื่อออกจากระบบ; หยุดมันด้วยตัวเองเมื่อคุณต้องการหน่วยความจำสำหรับอย่างอื่น

`omarchy models list` แสดงตัวเลือกและอธิบายว่าทำไมบางตัวจึงไม่พอดี หากต้องการตั้งค่าอีกตัว ให้รัน `omarchy models use <recipe>` วันนี้ `qwen3.8-flash-next-gufo` และ `qwen3.8-27b-gufo` พร้อมใช้งานสำหรับเครื่อง Strix Halo ขนาด 128 GB; ตัว 27B ใช้ประมาณ 40 GiB ดังนั้นมันจึงเหลือพื้นที่สำหรับงานอื่น บนแล็ปท็อปขนาด 64 GB ที่มี Arc B390 ของ Intel `qwen3.6-35b-a3b-llamacpp` ทำงานในประมาณ 30 GiB recipe และคำแนะนำใหม่ ๆ จะมาพร้อมกับ `omarchy update` ผ่านแพ็กเกจ

ทุกโมเดลที่คุณตั้งค่าจะได้แถวของตัวเองในแผง local models: เล่นเพื่อเริ่มมัน หยุดชั่วคราวเพื่อหยุดมันและปล่อยหน่วยความจำของมัน และปุ่ม terminal เพื่อเปิด agent ของคุณบนมัน ที่ด้านบนสุด แถบหนึ่งแสดงให้เห็นว่าหน่วยความจำของเครื่องถูกแบ่งอย่างไรระหว่างตัว Omarchy เอง (ระบบและแอปของคุณ) โมเดลแต่ละตัวที่กำลังทำงาน และสิ่งที่ว่างอยู่ ชี้ไปที่โมเดลที่หยุดอยู่และแถบจะแสดงว่ามันพอดีหรือไม่ หรือขาดไปเท่าใด หลายตัวสามารถทำงานพร้อมกันได้เมื่อพวกมันพอดีในหน่วยความจำด้วยกัน; หากตัวใดตัวหนึ่งไม่พอดี Omarchy จะบอกว่าต้องหยุดโมเดลที่กำลังทำงานตัวใด ลากแถวโดยโลโก้ของพวกมันเพื่อจัดลำดับใหม่ และกด Delete บนแถวที่เลือกไว้เพื่อลบโมเดลและการดาวน์โหลดของมัน

ทุก coding model ที่คุณตั้งค่ายังได้รายการของตัวเองใน app launcher ภายใต้ชื่อของโมเดลและพร้อมโลโก้ของผู้สร้างมัน ในแบบเดียวกับการลงชื่อเข้าใช้ Claude, Codex หรือ Grok ที่เพิ่มรายการหนึ่ง มันเปิด agent ของคุณบนโมเดลนั้น และเริ่มโมเดลก่อนหากมันยังไม่ได้ทำงาน: terminal จะแสดงการโหลดของมันและส่งมอบให้ agent เมื่อมันพร้อม การลบโมเดลจะลบรายการของมันออก

ไม่ใช่ทุกโมเดลสำหรับ coding โมเดลภาพ วิดีโอ และเพลงจะเปิดใน Fantasi แทน ซึ่งเป็นแอปของ Omarchy สำหรับสร้างภาพ วิดีโอ และเพลงด้วยโมเดลที่ทำงานบนเครื่องนี้ โดยเลือกที่นั่นหรือจากแถวของพวกมันในแผง local models

โมเดลจะยังคงทำงานตรงตามที่มันถูกตั้งค่าไว้ ดังนั้นการอัปเดต Omarchy จะไม่มีวันรีสตาร์ทมันภายใต้ agent ของคุณ เมื่อ Omarchy มี runtime ที่ใหม่กว่าหรือ weights ที่ใหม่กว่าสำหรับโมเดลที่คุณตั้งค่าไว้ แถวของมันจะแสดงปุ่มอัปเดต: กดมันและโมเดลจะถูกตั้งค่าใหม่อีกครั้งในเบื้องหลัง โดยดาวน์โหลดเฉพาะสิ่งที่เปลี่ยนแปลง และรีสตาร์ทบนเวอร์ชันใหม่ โมเดลที่หยุดอยู่จะยังคงหยุดอยู่ `omarchy models update` ทำสิ่งเดียวกันสำหรับทุกโมเดลจาก terminal

จาก command line `omarchy models start <recipe>` และ `omarchy models stop <recipe>` ทำสิ่งเดียวกัน `omarchy models status` แสดงทุกโมเดล และ `omarchy agent --local` เปิดโมเดลล่าสุดที่คุณเริ่มไว้ใน pi ไม่ว่า agent ค่าเริ่มต้นของคุณจะเป็นอะไรก็ตาม หากต้องการให้โมเดลนั้นเป็นสิ่งที่ปุ่มลัด agent, Quake console และ _Make something_ เปิด ให้รัน `omarchy default agent local` หรือเลือก _Local model_ ภายใต้ _Agent > Harness_ pi ยังแสดงรายการทุกโมเดลที่คุณตั้งค่าไว้ และโมเดลบนเครื่องที่คุณจับคู่ไว้ ในตัวเลือกโมเดลของมันเองด้วย ดังนั้น `pi` ธรรมดาจึงเข้าถึงพวกมันได้เช่นกัน client ใด ๆ ที่เข้ากันได้กับ OpenAI สามารถเชื่อมต่อได้ด้วย: `status` แสดงที่อยู่ของแต่ละโมเดล (ตัวแรกคือ `http://127.0.0.1:11435/v1`) ชื่อ recipe คือโมเดล และคีย์อยู่ใน `~/.config/omarchy/agent-local/key`

`omarchy models remove <recipe>` ลบโมเดลและการดาวน์โหลดที่ไม่มีโมเดลอื่นใช้

runtime ของบุคคลที่สามจะถูกติดป้ายด้วยผู้เผยแพร่ของพวกมัน Omarchy รันทุกโมเดลโดยไม่มีการเข้าถึงเครือข่าย

### LLM ในเครื่อง

Omarchy แนะนำสองวิธีในการรันโมเดล LLM ในเครื่อง: LM Studio และ Ollama LM Studio มีอินเทอร์เฟซ GUI สำหรับค้นหาโมเดล open-weight ติดตั้งพวกมัน และรันพวกมัน มันเป็นวิธีที่ยอดเยี่ยมในการเริ่มต้นได้อย่างง่ายดาย Ollama มี CLI สำหรับทำเช่นเดียวกัน แต่หากคุณเป็นมือใหม่สำหรับโมเดลในเครื่อง ฉันจะเริ่มด้วย LM Studio คุณสามารถติดตั้งตัวใดตัวหนึ่งได้ภายใต้ _Install > AI_ ใน Omarchy Menu

### skills ของ Omarchy

Agent skills ช่วยให้ AI ใช้เครื่องมือเฉพาะในวิธีเฉพาะ และ Omarchy ส่งมาเจ็ดตัว skill ชื่อ omarchy ครอบคลุมการปรับแต่งระบบ เช่น การปรับ config Hyprland ของคุณหรือการปรับแถบ omarchy-make-theme, omarchy-make-plugin, omarchy-make-app และ omarchy-make-game ครอบคลุมการสร้างสิ่งใหม่ omarchy-contribute ครอบคลุมการรายงานบั๊กหรือส่งการแก้ไขไปยัง upstream และ omarchy-diagnose-crash ไล่ไปตาม core dump ของการขัดข้อง พวกมันถูก symlink เข้าไปในไดเรกทอรี skill สำหรับ Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` และแต่ละ `~/.hermes/profiles/*/skills`) และตำแหน่งทั่วไป `~/.agents/skills` ดังนั้น harness ส่วนใหญ่จึงหยิบพวกมันขึ้นมาโดยอัตโนมัติ โฟลเดอร์ skill ของคุณเองที่มีชื่อเดียวกันจะมีความสำคัญเหนือกว่า

แต่คุณควรปฏิบัติต่อ skills เหล่านี้เสมือนเป็นของทดลอง โมเดลต่าง ๆ จะใช้มันให้ผลลัพธ์แตกต่างกันไป เป็นการดีที่สุดที่จะรันในโหมดวางแผนก่อน เพื่อให้คุณมีแนวคิดว่า agent อยากเปลี่ยนแปลงอะไร จากนั้นเตรียมพร้อมที่จะย้อนกลับการเปลี่ยนแปลงหรือแม้แต่เรียกใช้ `omarchy reinstall configs` หาก agent ทำทุกอย่างเละเทะ
