### การติดตั้งและการอัปเดตเอเจนต์

ยกเว้น Hermes และ OpenClaw เอเจนต์เหล่านี้ใช้การติดตั้งแบบ lazy ของ mise: การเรียกใช้ครั้งแรกจะติดตั้ง CLI และการเรียกใช้ครั้งต่อไปจะนำกลับมาใช้ใหม่ mise ยังตรวจสอบเอเจนต์ที่ติดตั้งแล้วว่ามีรุ่นใหม่หรือไม่ มากที่สุดหนึ่งครั้งทุกสี่ชั่วโมง ก่อนที่มันจะเริ่มทำงานทันทีหรือในเบื้องหลังที่พร้อมต์ของเชลล์ หากการอัปเดตนั้นล้มเหลวหรือคุณออฟไลน์ รุ่นที่ติดตั้งไว้จะทำงาน `omarchy update` อัปเดตเอเจนต์ที่ติดตั้งไปพร้อมกับส่วนที่เหลือของ Omarchy และ `mup` อัปเดตเฉพาะเครื่องมือที่จัดการโดย mise เท่านั้น

โปรแกรมอัปเดตของเอเจนต์เอง เช่น `claude update`, `codex update`, หรือปุ่มอัปเดตในแอป ไม่ได้อัปเดตการติดตั้งที่จัดการโดย mise `codex update` ล้มเหลว และ `claude update` สามารถรายงานว่าสำเร็จขณะติดตั้งสำเนาแยกต่างหากที่ mise ไม่ได้ติดตาม หากคุณต้องการใช้ตัวติดตั้งและโปรแกรมอัปเดตของเอเจนต์เองมากกว่า ให้เพิ่มมันลงใน `disable_tools`; ดู [เครื่องมือ CLI ที่ติดตั้งไว้ล่วงหน้า](18-development-tools.md#preinstalled-cli-tools)

หากต้องการติดตั้งเครื่องมือแบบ lazy ที่กำหนดค่าไว้ทั้งหมดก่อนที่คุณจะต้องการ ให้รัน `mise install --include-lazy` นี่รวมถึงเครื่องมือ CLI ค่าเริ่มต้นอื่น ๆ ของ Omarchy รวมถึงเอเจนต์ต่าง ๆ ดู [เครื่องมือ CLI ที่ติดตั้งไว้ล่วงหน้า](18-development-tools.md#preinstalled-cli-tools) สำหรับการติดตั้งเครื่องมือชิ้นเดียวหรือใช้การติดตั้งของคุณเอง

`grok` ติดตั้งผ่านแพ็กเกจ `grok` แบบ first-party ของ mise ในแบบเดียวกับ `claude` และ `codex` รัน `grok`, หรือเลือกมันใต้ _Agent > Harness_ ข้ามตัวติดตั้ง `curl | bash` บน x.ai เส้นทางนั้นจะวางสำเนาที่สองใน `~/.grok/bin`, เพิ่มมันไว้ข้างหน้าใน `PATH`, และเขียนทับตัวห่อหุ้มของ Omarchy

`dsh` เปิด UI ในเบราว์เซอร์ของมันบน `127.0.0.1:3080`, โดยใช้โฟลเดอร์ที่เรียกใช้เป็น workspace เริ่มต้น UI ในเบราว์เซอร์ของมันไม่รับพรอมต์เริ่มต้น ดังนั้น `omarchy agent prompt` จะเปิดมันโดยมีพรอมต์อยู่บนคลิปบอร์ดของคุณให้วาง Omarchy เริ่มมันด้วยชุดสิทธิ์แบบไม่ต้องอนุมัติของ DeepSeek DeepSeek Harness อัปโหลดบันทึกเซสชันไปยัง DeepSeek เมื่อคุณใช้ API โมเดลอย่างเป็นทางการของมัน; ปิดการทำงานนั้นใต้ _Settings > General > Upload Session Log_ ใน UI ในเบราว์เซอร์ของมัน ความคิดเห็นที่คุณส่งไปยังมันก็ถูกอัปโหลดพร้อมกับเซสชันด้วย เว้นแต่คุณจะเริ่มมันด้วย `DSH_TELEMETRY_MODE=DISABLED`

### เอเจนต์เริ่มต้น

เลือกเอเจนต์เริ่มต้นของคุณด้วย `omarchy default agent <name>` หรือใต้ _Agent > Harness_ ใน Omarchy Menu (`Super + Space`) หากเอเจนต์ยังไม่ได้รับการติดตั้ง การเลือกมันจะติดตั้งมันก่อน และมันยังได้รับตัวเรียกใช้ของตัวเองในตัวเรียกใช้แอป ถัดจาก Agent Omarchy ใหม่จะเชิญคุณให้เลือกสิ่งนี้ด้วยการแจ้งเตือนเพียงครั้งเดียว

การเลือก Claude ยังพยายามตั้งค่าส่วนขยายเบราว์เซอร์ของมันสำหรับ Chromium, Chrome, Brave, Brave Origin, และ Edge การตั้งค่าส่วนขยายใช้กับผู้ใช้ทุกคนและอาจขอรหัสผ่านระบบของคุณ; การยกเลิกหรือการติดตั้งส่วนขยายที่ล้มเหลวก็ยังเลือกและเปิด Claude ให้รีสตาร์ทเบราว์เซอร์ของคุณ เปิดใช้งานส่วนขยายหากได้รับแจ้ง และลงชื่อเข้าใช้ Claude เพื่อเสร็จสิ้นการเชื่อมต่อ รัน `/chrome` ใน Claude เพื่อตรวจสอบการเชื่อมต่อ Firefox และ Zen ไม่รองรับส่วนขยายนี้ หาก Claude เป็นค่าเริ่มต้นของคุณอยู่แล้วก่อนที่การตั้งค่านี้จะถูกเพิ่ม ให้เลือกมันอีกครั้งเพื่อติดตั้งส่วนขยาย

เมื่อคุณเลือกแล้ว `Super + Shift + Ctrl + A` จะเปิดเอเจนต์เริ่มต้นในหน้าต่างเทอร์มินัลเฉพาะ (หรือนำตัวเลือกขึ้นมาหากคุณยังไม่ได้เลือก) คุณยังเปิดมันตรงเข้าสู่งานด้วย `omarchy agent prompt "Review this project"` ได้ Freebuff และ DeepSeek Harness ไม่รับพรอมต์เริ่มต้น ดังนั้นพวกมันจะเปิดโดยมีพรอมต์อยู่บนคลิปบอร์ดของคุณให้วางแทน เอเจนต์ที่เปิดด้วยวิธีนี้ทำงานโดยไม่มีผู้ดูแลในโหมดอย่าหยุดเพื่อถามของแต่ละตัว ดังนั้นเตรียมพร้อมให้พวกมันลงมือทำจริง ๆ ได้เลย! MiniMax Code ไม่มีโหมดดังกล่าวสำหรับเซสชันโต้ตอบของมัน ดังนั้นมันจะขอสิทธิ์ตามปกติ และเนื่องจากเอเจนต์ปฏิเสธที่จะจดจำความไว้วางใจสำหรับโฟลเดอร์บ้านของคุณ การเรียกใช้จาก `$HOME` จะเริ่มใน `~/Work` แทน

นอกจากนี้ยังมีทางลัดในเทอร์มินัลอีกด้วย: `a` รันเอเจนต์เริ่มต้นแบบ inline ในเทอร์มินัลปัจจุบัน ขณะที่ `c`, `cx`, และ `cy` เริ่ม OpenCode, Claude Code, และ Codex โดยตรง (ในโหมดอนุมัติอัตโนมัติของพวกมันอีกเช่นกัน) การเปลี่ยนธีมก็ซิงก์ไปยังเอเจนต์ด้วยเช่นกัน: Claude Code, Pi, OpenCode, และ Hermes (เมื่อ Omarchy ได้ติดตั้งมันแล้ว) ล้วนเปลี่ยนตามเมื่อคุณสลับธีม Omarchy

### คำแนะนำสำหรับเอเจนต์ของคุณ

กฎส่วนตัวสำหรับทุกเอเจนต์อยู่ใน `~/.agents/AGENTS.md`, ถัดจากทักษะที่ใช้ร่วมกันใน `~/.agents/skills` เปิดมันใต้ _Agent > Instructions_, ซึ่งยังเชื่อมโยงมันเข้าไปในแต่ละตัวควบคุมที่เก็บไฟล์ส่วนกลางของตัวเองไว้: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` ของ Copilot, และอื่น ๆ Crush และ Amp อ่านลิงก์ `~/.config/AGENTS.md`, ขณะที่ omp, Kimi, และ DeepSeek Harness อ่าน `~/.agents/AGENTS.md` โดยตรง การเลือกเอเจนต์เริ่มต้นก็เชื่อมโยงมันด้วยเช่นกัน ไฟล์คำแนะนำที่คุณมีอยู่แล้วจะกลายเป็นไฟล์ที่ใช้ร่วมกันหากยังไม่มีไฟล์ดังกล่าว; มิฉะนั้นมันจะถูกเก็บไว้ข้างลิงก์เป็น `.bak` รัน `omarchy agent instructions` เพื่อเชื่อมโยงใหม่อีกครั้งหลังจากติดตั้งเอเจนต์อื่น

### แผงเอเจนต์

แถบบนมีไอคอนเอเจนต์ ก่อนที่คุณจะตั้งค่าเอเจนต์ แผงของมันจะนำทางคุณผ่านการลงชื่อเข้าใช้ Claude, Codex, หรือ Grok และตัวแรกจะกลายเป็นเอเจนต์เริ่มต้นของคุณ หลังจากนั้น แผงจะวางทุกการสมัครสมาชิกไว้ในหน้าเดียว: เอเจนต์และบัญชีแต่ละรายการพร้อมแผนของมัน มาตรวัดสำหรับขีดจำกัดเซสชัน 5 ชั่วโมงและขีดจำกัดรายสัปดาห์แต่ละรายการของมันพร้อมเวลาจนกว่าจะรีเซ็ต (ชี้เมาส์เพื่อดูเปอร์เซ็นต์ที่แน่นอน) หรือยอดคงเหลือแบบเติมเงินที่เหลือ ใต้เส้นที่หมุนเวียนผ่านสิ่งที่คุณใช้ไปในทั้งหมด เช่น โทเค็นในสัปดาห์นี้และโมเดลที่คุณใช้มากที่สุด ใต้ _Make something cool_ มันเสนอพรอมต์เริ่มต้นสำหรับธีม ปลั๊กอิน แอป หรือเกมใหม่ที่มอบงานให้เอเจนต์เริ่มต้นของคุณ แอปต่าง ๆ ถูกสร้างในแบบเดียวกับ Hype, Monologue, และ Omacut ของ Omarchy เอง ใน C++ และ Qt Quick โดยปฏิบัติตามทักษะเอเจนต์ omarchy-make-app และคอมไพเลอร์และชิ้นส่วน Qt ที่พวกมันต้องการก็ได้รับการติดตั้งมาให้ เกมต่าง ๆ เป็นหน้า three.js หน้าเดียวใน `~/Games/vibes` โดยปฏิบัติตามทักษะเอเจนต์ omarchy-make-game และทั้งหมดเปิดจากตัวเรียกใช้ Game Vibes เดียวในธีมปัจจุบัน; พวกมันโหลด three.js จากเว็บ ดังนั้นจึงจำเป็นต้องมีการเชื่อมต่อเพื่อเริ่ม Claude Code, Codex, Grok, Kimi, Cursor และสิทธิ์ Grok Bot ของมัน, GitHub Copilot, Muse, Antigravity, และ Devin ครอบคลุมมาให้ทันทีพร้อมขีดจำกัดของพวกมัน Kimchi พร้อมแผน เครดิตเติมเงิน และงบการใช้จ่ายของมัน และ Hermes, Mistral Vibe, และ Qwen Code แสดงเซสชันและโทเค็นของพวกมันเมื่อคุณได้ใช้งานแล้ว แผนและคีย์ของผู้ให้บริการที่คุณใช้ผ่าน pi, omp, หรือ opencode ก็ปรากฏด้วยเช่นกัน: OpenCode Zen และ Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan, และ Synthetic พร้อมขีดจำกัดของพวกมัน; OpenRouter และ DeepSeek พร้อมยอดคงเหลือแบบเติมเงินของพวกมัน; Fireworks พร้อมการใช้จ่ายของมันในช่วง 30 วันที่ผ่านมา โทเค็นจากโมเดลที่คุณรันบนฮาร์ดแวร์ของคุณเองก็นับรวมในยอดรวมเช่นกัน; โมเดลเหล่านั้นมีแผงของตัวเอง ซึ่งอธิบายไว้ใต้ [โมเดลในเครื่อง](#local-models) เอเจนต์ทุกตัวถูกนับเพียงครั้งเดียว ใต้ผู้ที่เรียกเก็บเงินสำหรับมัน ไม่ว่าคุณจะขับเคลื่อนมันผ่านตัวควบคุมกี่ตัวก็ตาม

คลิกซ้ายที่ไอคอนบนแถบหรือกด `Super + Ctrl + X` สำหรับแผง คลิกขวาเพื่อเปิดเอเจนต์เริ่มต้นของคุณ และคลิกกลางเพื่อรีเฟรช บันทึกการใช้งานที่อยู่เบื้องหลังมันถูกสร้างใหม่ทุก 15 นาทีโดย `omarchy agent usage update` และแผงยังสามารถรวมการใช้งานจากเครื่องอื่น ๆ ของคุณผ่านโฟลเดอร์ที่ซิงก์ได้ ดู README ใต้ `$OMARCHY_PATH/shell/plugins/agents/` สำหรับการตั้งค่าเต็มรูปแบบ

### การสมัครสมาชิกหลายรายการ

หากคุณจ่ายเงินสำหรับแผน Claude, Codex, หรือ Grok มากกว่าหนึ่งแผน — เช่น Max ส่วนตัวและอีกหนึ่งสำหรับงาน — Omarchy สามารถให้พวกมันทั้งหมดลงชื่อเข้าใช้อยู่และสลับไปมาระหว่างพวกมันได้ เพิ่มการสมัครสมาชิกด้วย + ในแผงเอเจนต์ ซึ่งจะนำทางคุณผ่านขั้นตอนนั้นตรงที่นั่น หรือด้วย `omarchy agent account add claude Work` (หรือ `codex`, หรือ `grok`) มันจะติดตั้ง CLI หากยังไม่มี บัญชีแรกสำหรับผู้ให้บริการรายหนึ่งลงชื่อเข้าใช้ผ่านเบราว์เซอร์ปกติของคุณ ตรงตำแหน่งที่ CLI ค้นหาเสมอ บัญชีหลังจากนั้นทุกบัญชีลงชื่อเข้าใช้ผ่านหน้าต่างส่วนตัว ดังนั้นบัญชีที่เบราว์เซอร์ของคุณลงชื่อเข้าใช้อยู่แล้วจะไม่ถูกหยิบขึ้นมาโดยผิดพลาด; ให้ลงชื่อเข้าใช้ที่นั่นเป็นบัญชีที่คุณกำลังเพิ่ม และปิดหน้าต่างส่วนตัวใด ๆ ที่คุณเปิดไว้อยู่แล้วก่อน อย่าออกจากระบบของ CLI เพื่อทำสิ่งนี้เด็ดขาด: การออกจากระบบจะเพิกถอนการลงชื่อเข้าใช้ที่บันทึกไว้ และบัญชีนั้นจะต้องถูกเพิ่มอีกครั้ง

หากต้องการคัดลอกการเข้าสู่ระบบการสมัครสมาชิกของคุณไปยังเครื่อง Omarchy อื่นผ่าน SSH ให้รัน `omarchy agent account copy user@laptop` ผู้ส่งจะจัดเตรียมตัวรับชั่วคราวเมื่อปลายทางยังไม่ได้ติดตั้งไว้ ดังนั้นเครื่อง Omarchy รุ่นเก่ากว่าสามารถรับบัญชีได้โดยไม่ต้องอัปเดต ตัวรับที่ติดตั้งแล้วมีความสำคัญเหนือกว่า นี่จะคัดลอกการสมัครสมาชิก Claude, Codex, และ Grok ทั้งหมด; เพิ่มชื่อผู้ให้บริการเพื่อเลือกพวกมัน เช่น ใน `omarchy agent account copy laptop claude` ชื่อบัญชีและ ID คำสั่งตรงกับต้นทาง รวมถึงบัญชีที่มีอยู่แล้วบนปลายทาง บัญชีปลายทางที่ไม่เกี่ยวข้องจะได้รับคำต่อท้ายที่เป็นตัวเลขหากชื่อของพวกมันขัดแย้งกัน และการตั้งค่า ทักษะ ปลั๊กอิน และประวัติการสนทนาจะยังคงอยู่เฉพาะในแต่ละเครื่อง

ข้อมูลประจำตัวปลายทางที่มีอยู่จะถูกเก็บไว้ บัญชีต้นทางที่ลงชื่อเข้าใช้อยู่แล้วที่นั่นจะได้รับการซิงโครไนซ์ชื่อโดยไม่แทนที่ข้อมูลประจำตัวของมัน; บัญชีอื่น ๆ จะถูกเพิ่มควบคู่ไปกับมัน หากต้องการแทนที่ข้อมูลประจำตัวที่บันทึกไว้สำหรับบัญชีที่ตรงกัน ให้ใช้ `omarchy agent account copy --replace laptop claude` หลังจากออกจากเซสชันของบัญชีนั้นบนปลายทางแล้ว ปลายทางใหม่ยังได้รับบัญชีที่ใช้งานอยู่และค่ากำหนดการสลับของต้นทางด้วย; ปลายทางที่มีอยู่แล้วจะรักษาของตัวเองไว้

ข้อมูลประจำตัวเดินทางผ่าน SSH และถูกจัดเก็บในไฟล์ส่วนตัวบนปลายทาง ดังนั้นให้คัดลอกไปยังเครื่องที่คุณไว้ใจเท่านั้น นี่คือการคัดลอกครั้งเดียว ไม่ใช่การซิงโครไนซ์ต่อเนื่อง โทเค็นรีเฟรชของ Codex สามารถถูกหมุนเวียนได้โดยเครื่องอื่น ทำให้การเข้าสู่ระบบที่คัดลอกมาต้องได้รับการต่ออายุ; การลงชื่อเข้าใช้แยกกันยังคงเป็นตัวเลือกที่น่าเชื่อถือที่สุดสำหรับการใช้งานพร้อมกันบนหลายเครื่อง ดู [คำแนะนำการยืนยันตัวตนบัญชีของ Codex](https://developers.openai.com/codex/auth/ci-cd-auth)

บัญชีหนึ่งบัญชีต่อผู้ให้บริการหนึ่งรายจะใช้งานอยู่ และทุกเซสชันใหม่จะเริ่มเป็นบัญชีนั้น: `cx`, `cy`, `claude`, `codex`, หรือ `grok` ธรรมดา สิ่งใดก็ตามที่เปิดผ่าน `omarchy agent` และสคริปต์หรือตัวแก้ไขที่ค้นหา CLI บน `PATH` สลับด้วย `omarchy agent account use work` (และกลับด้วย `omarchy agent account use main`) หรือในแผงโดยกดหมายเลขของบัญชีแล้วกด `Enter` (หรือคลิกปุ่ม Use ของมัน) เซสชัน Claude ที่กำลังทำงานอยู่ก็สลับด้วยเช่นกัน ตั้งแต่ข้อความถัดไปของพวกมัน: ทุกเซสชัน Claude ทำงานใน `~/.claude` ซึ่งเก็บการลงชื่อเข้าใช้ของบัญชีที่ใช้งานอยู่ไว้เสมอ เซสชัน Claude ที่เริ่มในโฟลเดอร์ของบัญชีเองโดย Omarchy รุ่นเก่าจะเก็บการลงชื่อเข้าใช้นั้นไว้จนกว่ามันจะออก ดังนั้นการสลับจะระบุชื่อเซสชันเหล่านั้นและเสร็จสิ้นด้วยตัวเองเมื่อพวกมันจากไปแล้ว เซสชัน Codex และ Grok ที่กำลังทำงานอยู่จะคงอยู่บนบัญชีที่พวกมันเริ่มต้น ประวัติการสนทนา การตั้งค่า ทักษะ และปลั๊กอินถูกใช้ร่วมกันข้ามบัญชี ดังนั้น `claude --continue` ในโฟลเดอร์เดิมจะดำเนินการต่อจากที่ที่คุณค้างไว้บนบัญชีใหม่

ด้วยบัญชีมากกว่าหนึ่งบัญชี แผงจะแสดงขีดจำกัดของแต่ละบัญชีข้างกัน โดยบัญชีที่ใช้งานอยู่จะถูกทำเครื่องหมายไว้ โดยค่าเริ่มต้น Omarchy จะแจ้งเตือนคุณเมื่อบัญชีที่ใช้งานอยู่ผ่าน 95% ของขีดจำกัด และการคลิกการแจ้งเตือนจะสลับไปยังบัญชีที่มีพื้นที่เหลือมากที่สุด ชี้เมาส์ที่เส้นของบัญชีในแผงและคลิก Autoswitch ที่ปรากฏข้าง Use (หรือกด `m`) หรือรัน `omarchy agent account mode auto` เพื่อให้มันสลับด้วยตัวเองแทน; ขณะที่มันเปิดอยู่ Autoswitch จะแทนที่ Use และการคลิกมันอีกครั้งจะกลับไปเป็นการแจ้งเตือน เพิ่มตัวเลขเพื่อเปลี่ยนเกณฑ์ เช่น ใน `omarchy agent account mode auto 90` หากทุกบัญชีเกินเกณฑ์ คุณจะได้รับแจ้งครั้งเดียว พร้อมกับบัญชีใดจะว่างก่อน ขณะที่บัญชีที่ใช้งานอยู่ภายใน 15 จุดจากเกณฑ์ของมัน (80% ที่ค่าเริ่มต้น) ขีดจำกัดของมันจะถูกตรวจสอบทุกสามนาทีแทนที่จะเป็นทุก 15 นาที

`omarchy agent account list` แสดงทุกบัญชีและขีดจำกัดล่าสุดของพวกมัน `omarchy agent account remove work` ลบบัญชีหนึ่งรายการ และ `omarchy agent account rename primary Hey` เปลี่ยนชื่อบัญชีหนึ่งรายการ (หรือคลิกชื่อของบัญชีในแผง) คำสั่งเหล่านี้ทำงานบนบัญชีของเอเจนต์เริ่มต้นของคุณ; หากต้องการเข้าถึงผู้ให้บริการรายอื่น ให้ระบุชื่อมันก่อน เช่น ใน `omarchy agent account use codex side` การเข้าสู่ระบบที่คุณมีอยู่แล้วใน `~/.claude` หรือ `~/.codex` คือบัญชี _Main_ ของ Codex อยู่ที่เดิม; ของ Claude รออยู่ในโฟลเดอร์ของตัวเองขณะที่บัญชีอื่นใช้งานอยู่ บัญชีที่ไม่ได้ใช้งานมากกว่าประมาณแปดชั่วโมงสามารถแสดง _Sign-in required_; คลิกมันเพื่อลงชื่อบัญชีนั้นเข้าใช้อีกครั้งในแผงทันที หรือสลับไปหามันและเริ่มเซสชัน ซึ่งจะรีเฟรชการลงชื่อเข้าใช้ด้วยตัวเอง เซิร์ฟเวอร์ MCP ที่คุณเพิ่มด้วย `claude mcp add` ไปถึงทุกบัญชี Claude เนื่องจากพวกมันทั้งหมดทำงานใน `~/.claude`; สำหรับ Codex และ Grok เซิร์ฟเวอร์ที่คุณมีเมื่อบัญชีถูกเพิ่มจะตามไปยังบัญชีนั้นด้วย แต่เซิร์ฟเวอร์ในภายหลังจะไปถึงเฉพาะบัญชีที่คุณเพิ่มพวกมันไว้เท่านั้น Claude Desktop เก็บการลงชื่อเข้าใช้ของตัวเองไว้ และเครื่องมือ Codex หรือ Grok ที่กำหนดค่าด้วยเส้นทางสัมบูรณ์ไปยังไบนารี CLI จะไม่ตามการสลับไป ตัวแปร `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, หรือ `GROK_HOME` ที่กำหนดอย่างชัดเจนมีความสำคัญเหนือบัญชีที่เลือก

### การวินิจฉัยการขัดข้อง

Omarchy เฝ้าดู systemd-coredump เพื่อหาการขัดข้องของกระบวนการ เมื่อคุณเลือกเอเจนต์เริ่มต้นแล้ว โปรแกรมของคุณโปรแกรมใดก็ตามที่ dump core จะนำการแจ้งเตือน "Process crashed" มา — คลิกมัน และการขัดข้องจะถูกส่งให้เอเจนต์เริ่มต้นของคุณพร้อมกับทักษะ omarchy-diagnose-crash ของ Omarchy ซึ่งนำทางเอเจนต์ผ่านการสร้างข้อเท็จจริงจาก core dump และการตัดสินใจว่าการขัดข้องนั้นคุ้มค่าที่จะรายงานไปยัง upstream หรือไม่ คุณยังสามารถรันมันด้วยตนเองกับ PID ใด ๆ จาก `coredumpctl list` ด้วย `omarchy agent crash <pid>` ได้เช่นกัน

การเฝ้าดูเปิดอยู่โดยค่าเริ่มต้น ปิดมันใต้ _Trigger > Toggle > Crash Capture Off_ (หรือด้วย `omarchy toggle crash-capture`) และการแจ้งเตือนจะหยุด; `omarchy agent crash <pid>` ยังคงทำงานด้วยตนเองได้

การขัดข้องยังสามารถปิดเสียงได้ครั้งละหนึ่งโปรแกรม ซึ่งคือสิ่งที่การวินิจฉัยเสนอให้คุณในตอนท้าย `omarchy crash mute hyprland` หยุดการแจ้งเตือนสำหรับโปรแกรมนั้นเท่านั้น `omarchy crash mute hyprland off` นำพวกมันกลับมา และ `omarchy crash mute` ด้วยตัวเองจะแสดงรายการสิ่งที่คุณปิดเสียงไว้ มันรับเส้นทางของไบนารีได้อย่างยินดีพอ ๆ กับชื่อของมัน ดังนั้น `omarchy crash mute /usr/bin/hyprland` จึงทำสิ่งเดียวกัน ใส่เครื่องหมายคำพูดรอบชื่อที่มีช่องว่าง เช่น ใน `omarchy crash mute 'Some App'` ทุกอย่างอื่นยังคงแจ้งเตือน และโปรแกรมที่ปิดเสียงยังคงขัดข้อง — นี่ซ่อนตัวเตือน มันไม่ได้แก้ไขสิ่งใด

### แอปบนเดสก์ท็อป

เมนู _Install > AI_ ยังมีแอป AI แบบกราฟิกไม่กี่ตัวอีกด้วย: Amp Desktop, Antigravity Desktop, แอปเดสก์ท็อป ChatGPT, แอปเดสก์ท็อป Claude (เบต้า Linux ของ Anthropic พร้อมแท็บ Chat, Cowork, และ Claude Code), Grok Bot สำหรับแชทกับโมเดลของ xAI, Herdr Desktop, Hermes Desktop, OpenClaw, แอปเดสก์ท็อป Perplexity, และ T3 Code Grok Bot คือแอปแชทบนเดสก์ท็อป ส่วนเอเจนต์เขียนโค้ดคือคำสั่ง `grok`

Hermes Desktop คือตัวที่ต้องรู้ เพราะเครื่องหนึ่งมี Hermes เพียงตัวเดียว และมันเป็นของแอป: Hermes ถูกติดตั้งผ่านแอปเท่านั้น และคำสั่ง `hermes` ที่เอเจนต์เริ่มต้นรันคือของแอป การเลือก Hermes เป็นเอเจนต์เริ่มต้นจะติดตั้งสิ่งเดียวกันกับที่รายการ _Install > AI_ ทำ: แพ็กเกจ และรันไทม์ Hermes ใต้ `~/.hermes` ที่ตั้งค่าโดยตัวติดตั้งของ Hermes เอง ซึ่งใช้เวลาสองสามนาทีในครั้งแรก รันไทม์นั้นคือ Hermes ตัวเดียวที่คำสั่ง `hermes` ในเทอร์มินัล เอเจนต์เริ่มต้น และแอปทั้งหมดใช้ และมันอัปเดตตัวเองด้วย `hermes update` แทนที่จะรอการเปิดตัว Omarchy การติดตั้งมันยังมอบธีม Omarchy ให้ Hermes เป็นสกินชื่อ `omarchy` ซึ่งทุกพื้นผิวของ Hermes จะปฏิบัติตามเมื่อคุณสลับธีม; เลือกสกินอื่นใต้การตั้งค่า Appearance ของ Hermes หรือด้วย `/skin` หากคุณไม่ต้องการให้มันทำเช่นนั้น และ Omarchy จะไม่แตะต้องการเลือกนั้น การลบแอปใต้ _Remove > AI_ จะปิด Hermes ก่อน รวมถึงเกตเวย์ นำรันไทม์นั้นไปด้วย และเก็บแชท ความทรงจำ และทักษะที่ Hermes เขียนให้ตัวเองไว้ เว้นแต่คุณจะบอกเป็นอย่างอื่น: มันจะถาม โดยค่าเริ่มต้นคือไม่ ว่าข้อมูลนั้นและการตั้งค่าการเชื่อมต่อของคุณควรไปด้วยหรือไม่

ประสบการณ์บนเดสก์ท็อปของ OpenClaw คือ Control UI ของมัน ซึ่งเปิดเป็นเว็บแอปที่รองรับโดยเกตเวย์ในเครื่องของตัวเอง OpenClaw อาศัยอยู่ใน `~/.openclaw` และอัปเดตตัวเอง: ใช้ปุ่ม "Update Gateway" ของ Control UI หรือรัน `openclaw update` และเกตเวย์จะรีสตาร์ทบนรุ่นใหม่ Omarchy เพียงเลือกการเปิดตัวที่การติดตั้งใหม่จะเริ่มต้นด้วย OpenClaw ยังสามารถเป็นเอเจนต์เริ่มต้นของคุณได้: การเลือกมันใต้ _Agent > Harness_ จะตั้งค่าสำเนาเดียวกันนั้นใน `~/.openclaw` และเอเจนต์จะเปิด UI ในเทอร์มินัลของ OpenClaw ที่เชื่อมต่อกับเกตเวย์ของมัน การลบ OpenClaw ใต้ _Remove > AI_ จะนำบริการเกตเวย์และแอปไปด้วย จากนั้นถามว่า `~/.openclaw` ควรไปด้วยหรือไม่ เนื่องจากที่นั่นเก็บแชทและข้อมูลประจำตัวของคุณไว้ควบคู่กับ OpenClaw ตัวมันเองและรันไทม์ปลั๊กอินที่มันดาวน์โหลด; ค่าเริ่มต้นจะเก็บมันไว้ และการติดตั้ง OpenClaw อีกครั้งจะหยิบมันกลับขึ้นมา

Herdr Desktop คือแอปเดสก์ท็อป [Herdr](https://herdr.dev): spaces, tabs, และ panes ของเทอร์มินัลและเอเจนต์เขียนโค้ดที่ยังคงทำงานอยู่ในแกนหลักของมันเมื่อคุณปิดหน้าต่าง มันมาจากตัวติดตั้งของ Herdr เองแทนที่จะเป็นแพ็กเกจ ดังนั้นมันจึงอาศัยอยู่ใน `~/.local/share/herdr-app` นำแกนหลักของมันมาใน `~/.local/bin/herdr-core` เมื่อคุณยังไม่มี และอัปเดตทั้งสองอย่างด้วยตัวเอง มันวางอยู่ข้างคำสั่ง `herdr` ที่ Omarchy ส่งมาบน `Super + Ctrl + Return` แทนที่จะแทนที่มัน และได้รับคีย์ตรงของคำสั่งนั้น: `Alt + Return` และ `Alt + Shift + Return` แบ่ง pane ลงหรือไปทางขวา `Alt + Escape` ปิดมัน `Ctrl + Alt + Arrow` ย้ายระหว่าง panes `Alt + 1..9` และ `Alt + Left/Right` เลือก tab และ `Alt + Up/Down` ย้ายระหว่าง spaces `Ctrl + 1..9` เลือก space และ `Alt + Shift + Up/Down` ก้าวผ่านเอเจนต์ คีย์นำหน้า `Ctrl + Space` ยังคงเฉพาะในเทอร์มินัลเท่านั้น เนื่องจากแอปไม่สามารถถือคีย์ Ctrl ธรรมดาไว้สำหรับลำดับได้ Omarchy เขียนคีย์เหล่านี้ไปยัง `~/.config/herdr-app/keys.json` และ `omarchy-refresh-herdr-app` จะนำพวกมันกลับมา การติดตั้งมันจะเลือกธีม Omarchy ของ Herdr ซึ่งจะปฏิบัติตามธีม Omarchy ของคุณตั้งแต่นั้นเป็นต้นมา Herdr เก็บธีมหนึ่งสำหรับโหมดสว่างและอีกหนึ่งสำหรับโหมดมืด ดังนั้นหลังจากสลับระหว่างธีม Omarchy ที่มืดและที่สว่าง ให้เลือก Omarchy ในตัวเลือกธีมของ Herdr อีกครั้งสำหรับโหมดอื่น

T3 Code ทำงานจากการเปิดตัว AppImage อย่างเป็นทางการใน `~/.local/share/t3code` แทนที่จะจากแพ็กเกจ ดังนั้นมันจึงอัปเดตตัวเอง การติดตั้งมันจะถามว่าจะเริ่มบนช่อง Stable หรือ Nightly; สลับภายหลังในการตั้งค่าของ T3 Code กระทู้และการตั้งค่าของคุณอาศัยอยู่ใน `~/.t3` และการลบ T3 Code ใต้ _Remove > AI_ จะนำพวกมันไปด้วย

### โมเดลในเครื่อง

รันโมเดลเปิดบนเครื่องของคุณเองสำหรับเอเจนต์เขียนโค้ดของคุณ พรอมต์และโค้ดของคุณอยู่บนเครื่อง; ไม่มีสิ่งใดที่ส่งไปยังโมเดลออกจากเครื่อง เริ่มต้นด้วย:

```bash
omarchy models use best text
```

นั่นตั้งค่าโมเดลข้อความที่ดีที่สุดสำหรับเครื่องนี้ ประเภทที่เอเจนต์ของคุณใช้ โมเดลภาพ วิดีโอ และเพลงก็มีตัวที่ดีที่สุดของตัวเองเช่นกัน: `omarchy models use best image`, `video` หรือ `music` รัน `omarchy models use best` เพื่อดูตัวเลือกของแต่ละประเภทสำหรับเครื่องนี้

หรือเปิดแผงโมเดลในเครื่องจากไอคอน sparkles ของมันในแถบบน ถัดจากไอคอนเอเจนต์ หรือด้วย Super + Ctrl + Alt + X และเลือก + ไอคอนจะปรากฏเมื่อโมเดลเหมาะกับเครื่องนี้ Podman ซึ่งรันโมเดลต่าง ๆ มาพร้อมกับ Omarchy เช่นเดียวกับชุดเครื่องมือคอนเทนเนอร์ของ NVIDIA บนเครื่อง NVIDIA ซึ่งให้ GPU แก่พวกมัน; หากอย่างใดอย่างหนึ่งหายไป การตั้งค่าครั้งแรกจะติดตั้งมัน จากนั้น Omarchy จะเลือกโมเดลที่แนะนำสำหรับเครื่องนี้ ดาวน์โหลดมัน และเริ่มมัน คาดว่าจะต้องดาวน์โหลดหลายสิบ GB และหน่วยความจำส่วนใหญ่ของเครื่องจะถูกใช้งานขณะที่โมเดลทำงาน: Flash Next ใช้ประมาณ 100 GiB กับบริบท 256K เต็มรูปแบบของมัน หากโมเดลอื่นถือครองหน่วยความจำที่มันต้องการ มันจะถูกตั้งค่าแบบหยุดไว้ พร้อมที่จะเริ่มเมื่อคุณหยุดตัวหนึ่ง โมเดลจะหยุดเมื่อออกจากระบบ; ให้หยุดมันด้วยตัวเองเมื่อคุณต้องการหน่วยความจำสำหรับสิ่งอื่น

`omarchy models list` แสดงตัวเลือกและอธิบายว่าทำไมบางตัวจึงไม่เหมาะสม หากต้องการตั้งค่าตัวอื่น ให้รัน `omarchy models use <recipe>` ปัจจุบัน `qwen3.8-flash-next-gufo` และ `qwen3.8-27b-gufo` พร้อมใช้งานสำหรับเครื่อง Strix Halo ขนาด 128 GB; ตัว 27B ใช้ประมาณ 40 GiB ดังนั้นจึงเหลือพื้นที่สำหรับงานอื่น บนแล็ปท็อป 64 GB ที่มี Arc B390 ของ Intel `qwen3.6-35b-a3b-llamacpp` ทำงานในประมาณ 30 GiB สูตรและคำแนะนำใหม่ ๆ มาพร้อมกับ `omarchy update` ผ่านแพ็กเกจ

โมเดลทุกตัวที่คุณตั้งค่าจะได้รับบรรทัดของตัวเองในแผงโมเดลในเครื่อง: กดเล่นเพื่อเริ่มมัน กดหยุดชั่วคราวเพื่อหยุดมันและเพิ่มหน่วยความจำให้ว่าง และปุ่มเทอร์มินัลเพื่อเปิดเอเจนต์ของคุณบนมัน ข้ามด้านบน แถบหนึ่งแสดงว่าหน่วยความจำของเครื่องแบ่งระหว่าง Omarchy ตัวมันเอง (ระบบและแอปของคุณ) โมเดลที่กำลังทำงานแต่ละตัว และสิ่งที่ว่างอย่างไร ชี้เมาส์ที่โมเดลที่หยุดอยู่และแถบจะแสดงว่ามันเหมาะสมหรือไม่ หรือขาดไปเท่าไร หลายตัวสามารถทำงานพร้อมกันได้เมื่อพวกมันพอดีในหน่วยความจำร่วมกัน; หากตัวหนึ่งไม่พอดี Omarchy จะบอกว่าให้หยุดโมเดลที่กำลังทำงานตัวใด ลากบรรทัดด้วยโลโก้ของพวกมันเพื่อจัดเรียงใหม่ และกด Delete บนบรรทัดที่เลือกเพื่อลบโมเดลและการดาวน์โหลดของมัน

โมเดลเขียนโค้ดทุกตัวที่คุณตั้งค่ายังได้รับรายการของตัวเองในตัวเรียกใช้แอป ภายใต้ชื่อของโมเดลและพร้อมโลโก้ของผู้สร้างมัน ในแบบเดียวกับการลงชื่อเข้าใช้ Claude, Codex หรือ Grok ที่เพิ่มรายการหนึ่ง มันเปิดเอเจนต์ของคุณบนโมเดลนั้น และเริ่มโมเดลก่อนหากมันไม่ได้ทำงานอยู่: เทอร์มินัลแสดงว่ามันกำลังโหลดและส่งมอบให้กับเอเจนต์เมื่อมันพร้อมแล้ว การลบโมเดลจะลบรายการของมัน

ไม่ใช่ทุกโมเดลสำหรับเขียนโค้ด โมเดลภาพ วิดีโอ และเพลงจะเปิดใน Fantasi แทน ซึ่งเป็นแอปของ Omarchy สำหรับสร้างรูปภาพ วิดีโอ และเพลงด้วยโมเดลที่ทำงานบนเครื่องนี้ โดยเลือกที่นั่นหรือจากบรรทัดของพวกมันในแผงโมเดลในเครื่อง

โมเดลยังคงทำงานตรงตามที่มันถูกตั้งค่าไว้ ดังนั้นการอัปเดต Omarchy จึงไม่เคยรีสตาร์ทโมเดลใต้เอเจนต์ของคุณ เมื่อ Omarchy มีรันไทม์ที่ใหม่กว่าหรือเวทที่ใหม่กว่าสำหรับโมเดลที่คุณตั้งค่าไว้ บรรทัดของมันจะแสดงปุ่มอัปเดต: กดมันและโมเดลจะถูกตั้งค่าอีกครั้งในเบื้องหลัง ดาวน์โหลดเฉพาะสิ่งที่เปลี่ยนแปลง และรีสตาร์ทบนรุ่นใหม่ โมเดลที่หยุดอยู่จะยังคงหยุดอยู่ `omarchy models update` ทำสิ่งเดียวกันสำหรับทุกโมเดลจากเทอร์มินัล

จากบรรทัดคำสั่ง `omarchy models start <recipe>` และ `omarchy models stop <recipe>` ทำสิ่งเดียวกัน `omarchy models status` แสดงทุกโมเดล และ `omarchy agent --local` เปิดโมเดลล่าสุดที่คุณเริ่มใน pi ไม่ว่าเอเจนต์เริ่มต้นของคุณจะเป็นอะไร OpenCode และ Qwen Code ก็สามารถใช้โมเดลในเครื่องได้เช่นกัน: `omarchy models harness opencode` หรือ `omarchy models harness qwen` จะเปิดพวกมันที่นั่นแทน และ `omarchy models harness pi` จะกลับไป pi ยังแสดงรายการทุกโมเดลที่คุณตั้งค่าไว้ และโมเดลบนเครื่องที่คุณจับคู่ไว้ ในตัวเลือกโมเดลของมันเอง ดังนั้น `pi` ธรรมดาก็เข้าถึงพวกมันได้เช่นกัน ไคลเอนต์ใด ๆ ที่เข้ากันได้กับ OpenAI ก็สามารถเชื่อมต่อได้เช่นกัน: `status` แสดงที่อยู่ของแต่ละโมเดล (ตัวแรกคือ `http://127.0.0.1:11435/v1`) ชื่อสูตรคือโมเดล และคีย์อยู่ใน `~/.config/omarchy/agent-local/key`

`omarchy models remove <recipe>` ลบโมเดลและการดาวน์โหลดที่ไม่มีโมเดลอื่นใช้

รันไทม์ของบุคคลที่สามจะติดป้ายด้วยผู้เผยแพร่ของพวกมัน Omarchy รันทุกโมเดลโดยไม่มีการเข้าถึงเครือข่าย

### LLM ในเครื่อง

Omarchy แนะนำสองวิธีในการรันโมเดล LLM ในเครื่อง: LM Studio และ Ollama LM Studio ให้ส่วนติดต่อแบบ GUI สำหรับค้นหาโมเดล open-weight ติดตั้งพวกมัน และรันพวกมัน มันเป็นวิธีที่ยอดเยี่ยมในการเริ่มต้นอย่างง่ายดาย Ollama เสนอ CLI สำหรับทำสิ่งเดียวกัน แต่หากคุณยังใหม่กับโมเดลในเครื่อง ฉันขอแนะนำให้เริ่มด้วย LM Studio คุณสามารถติดตั้งอย่างใดอย่างหนึ่งได้ใต้ _Install > AI_ ใน Omarchy Menu

### ทักษะของ Omarchy

ทักษะเอเจนต์ช่วยให้ AI ใช้เครื่องมือเฉพาะในวิธีเฉพาะ และ Omarchy ส่งมาพร้อมกับทักษะเจ็ดอย่าง ทักษะ omarchy ครอบคลุมการปรับแต่งระบบ เช่น การปรับการกำหนดค่า Hyprland ของคุณหรือการปรับแถบ omarchy-make-theme, omarchy-make-plugin, omarchy-make-app, และ omarchy-make-game ครอบคลุมการสร้างสิ่งใหม่ omarchy-contribute ครอบคลุมการรายงานข้อบกพร่องหรือการส่งการแก้ไขไปยัง upstream และ omarchy-diagnose-crash ทำงานผ่าน core dump ของการขัดข้อง พวกมันถูกทำ symlink เชื่อมโยงเข้าไปในไดเรกทอรีทักษะสำหรับ Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` และแต่ละ `~/.hermes/profiles/*/skills`) และตำแหน่งทั่วไป `~/.agents/skills` ดังนั้นตัวควบคุมส่วนใหญ่จึงหยิบพวกมันขึ้นมาโดยอัตโนมัติ โฟลเดอร์ทักษะของคุณเองที่มีชื่อเดียวกันจะมีความสำคัญเหนือกว่า

แต่คุณควรปฏิบัติต่อทักษะเหล่านี้เสมือนเป็นการทดลอง โมเดลที่แตกต่างกันจะใช้มันให้เกิดผลที่แตกต่างกัน มันดีที่สุดที่จะรันในโหมดวางแผนก่อน เพื่อให้คุณมีแนวคิดว่าเอเจนต์ต้องการเปลี่ยนอะไร จากนั้นเตรียมพร้อมที่จะย้อนกลับการเปลี่ยนแปลง หรือแม้กระทั่งเรียกใช้ `omarchy reinstall configs` หากเอเจนต์ทำทุกอย่างยุ่งเหยิงไปหมด
