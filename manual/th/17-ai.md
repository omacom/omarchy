### การติดตั้งและอัปเดตเอเจนต์

ยกเว้น Hermes เอเจนต์เหล่านี้ใช้การติดตั้งแบบ lazy ของ mise: การเปิดใช้ครั้งแรกจะติดตั้ง CLI และการเปิดใช้ครั้งต่อ ๆ ไปจะใช้ตัวที่ติดตั้งไว้ mise ยังตรวจสอบว่าเอเจนต์ที่ติดตั้งไว้มีรุ่นใหม่ออกมาหรือไม่ อย่างมากที่สุดหนึ่งครั้งทุกสี่ชั่วโมง ก่อนที่มันจะเริ่มทำงานพอดี หรือในเบื้องหลังที่พรอมต์ของเชลล์ หากการอัปเดตนั้นล้มเหลวหรือคุณออฟไลน์อยู่ รุ่นที่ติดตั้งไว้จะทำงาน `omarchy update` จะอัปเดตเอเจนต์ที่ติดตั้งไว้พร้อมกับส่วนที่เหลือของ Omarchy และ `mup` จะอัปเดตเฉพาะเครื่องมือที่ mise จัดการเท่านั้น

ตัวอัปเดตของเอเจนต์เอง เช่น `claude update`, `codex update` หรือปุ่มอัปเดตในแอป จะไม่อัปเดตตัวที่ติดตั้งซึ่ง mise จัดการ `codex update` จะล้มเหลว และ `claude update` อาจรายงานว่าสำเร็จในขณะที่ติดตั้งสำเนาแยกอีกตัวที่ mise ไม่ได้ติดตาม หากคุณอยากใช้ตัวติดตั้งและตัวอัปเดตแบบ native ของเอเจนต์มากกว่า ให้เพิ่มมันเข้าไปใน `disable_tools`; ดู [เครื่องมือ CLI ที่ติดตั้งมาล่วงหน้า](18-development-tools.md#preinstalled-cli-tools)

หากต้องการติดตั้งเครื่องมือ lazy ที่กำหนดค่าไว้ทั้งหมดก่อนที่คุณจะต้องการใช้ ให้รัน `mise install --include-lazy` ซึ่งรวมถึงเครื่องมือ CLI เริ่มต้นอื่น ๆ ของ Omarchy ด้วยเช่นเดียวกับเอเจนต์ ดู [เครื่องมือ CLI ที่ติดตั้งมาล่วงหน้า](18-development-tools.md#preinstalled-cli-tools) สำหรับการติดตั้งเครื่องมือตัวเดียวหรือการใช้ตัวติดตั้งของคุณเอง

`grok` ถูกติดตั้งผ่านแพ็กเกจ `grok` แบบ first-party ของ mise ในแบบเดียวกับ `claude` และ `codex` รัน `grok` หรือเลือกมันใต้ _Setup > Defaults > Agent_ ข้ามตัวติดตั้ง `curl | bash` บน x.ai ไปเลย เส้นทางนั้นจะวางสำเนาที่สองไว้ใน `~/.grok/bin` แทรกมันไว้ด้านหน้า `PATH` และเขียนทับ wrapper ของ Omarchy

`dsh` เปิด UI บนเบราว์เซอร์ของมันที่ `127.0.0.1:3080` โดยใช้ไดเรกทอรีที่เปิดใช้เป็น workspace เริ่มต้น UI บนเบราว์เซอร์ของมันไม่รับพรอมต์เริ่มต้น ดังนั้น `omarchy agent prompt` จะเปิดมันพร้อมพรอมต์อยู่บนคลิปบอร์ดของคุณให้วาง Omarchy เริ่มมันด้วยชุดสิทธิ์แบบ no-approval ของ DeepSeek DeepSeek Harness จะอัปโหลดบันทึกเซสชันไปยัง DeepSeek เมื่อคุณใช้ API โมเดลอย่างเป็นทางการของมัน; ปิดสิ่งนั้นได้ใต้ _Settings > General > Upload Session Log_ ใน UI บนเบราว์เซอร์ของมัน ความคิดเห็นที่คุณส่งไปให้มันจะถูกอัปโหลดไปพร้อมกับเซสชันด้วย เว้นแต่คุณจะเริ่มมันด้วย `DSH_TELEMETRY_MODE=DISABLED`

### เอเจนต์เริ่มต้น

เลือกเอเจนต์เริ่มต้นของคุณด้วย `omarchy default agent <name>` หรือใต้ _Setup > Defaults > Agent_ ใน Omarchy Menu (`Super + Space`) หากเอเจนต์ยังไม่ได้ติดตั้ง การเลือกมันจะติดตั้งมันก่อน Omarchy ใหม่เอี่ยมจะเชิญให้คุณตัดสินใจเรื่องนี้ด้วยการแจ้งเตือนเพียงครั้งเดียว

การเลือก Claude ยังพยายามตั้งค่าส่วนขยายเบราว์เซอร์ของมันสำหรับ Chromium, Chrome, Brave, Brave Origin และ Edge ด้วย การตั้งค่าส่วนขยายใช้กับผู้ใช้ทุกคนและอาจขอรหัสผ่านระบบของคุณ; การยกเลิกหรือการติดตั้งส่วนขยายที่ล้มเหลวก็ยังเลือกและเปิด Claude อยู่ดี รีสตาร์ทเบราว์เซอร์ของคุณ เปิดใช้งานส่วนขยายหากได้รับแจ้ง และลงชื่อเข้าใช้ Claude เพื่อเชื่อมต่อให้เสร็จ รัน `/chrome` ใน Claude เพื่อตรวจสอบการเชื่อมต่อ Firefox และ Zen ไม่รองรับส่วนขยายนี้ หาก Claude เป็นค่าเริ่มต้นของคุณอยู่แล้วก่อนที่จะมีการเพิ่มการตั้งค่านี้ ให้เลือกมันอีกครั้งเพื่อติดตั้งส่วนขยาย

เมื่อคุณเลือกแล้ว `Super + Shift + Ctrl + A` จะเปิดเอเจนต์เริ่มต้นในหน้าต่างเทอร์มินัลเฉพาะ (หรือเปิดตัวเลือกหากคุณยังไม่ได้เลือก) คุณยังเปิดมันตรงเข้าสู่งานได้ด้วย `omarchy agent prompt "Review this project"` Freebuff และ DeepSeek Harness ไม่รับพรอมต์เริ่มต้น ดังนั้นพวกมันจะเปิดพร้อมพรอมต์อยู่บนคลิปบอร์ดของคุณให้วางแทน เอเจนต์ที่เปิดด้วยวิธีนี้จะทำงานโดยไม่มีผู้ดูแลในโหมด don't-stop-to-ask ของแต่ละตัว ดังนั้นจงพร้อมให้พวกมันลงมือทำสิ่งต่าง ๆ จริง ๆ! MiniMax Code ไม่มีโหมดแบบนั้นสำหรับเซสชันแบบโต้ตอบของมัน ดังนั้นมันจะขอสิทธิ์ตามปกติ และเนื่องจากเอเจนต์ปฏิเสธที่จะจดจำความไว้วางใจสำหรับไดเรกทอรี home ของคุณ การเปิดใช้จาก `$HOME` จะเริ่มใน `~/Work` แทน

มีทางลัดบนเทอร์มินัลด้วยเช่นกัน: `a` รันเอเจนต์เริ่มต้นแบบ inline ในเทอร์มินัลปัจจุบัน ขณะที่ `c`, `cx` และ `cy` เริ่ม OpenCode, Claude Code และ Codex โดยตรง (ในโหมดอนุมัติอัตโนมัติของพวกมันอีกเช่นกัน) การเปลี่ยนธีมยังซิงก์ไปยังเอเจนต์ด้วย: Claude Code, Pi, OpenCode และ Hermes (เมื่อ Omarchy ติดตั้งมันแล้ว) ล้วนเปลี่ยนตามเมื่อคุณสลับธีม Omarchy

### แผงเอเจนต์

แถบด้านบนมีไอคอนเอเจนต์ ก่อนที่คุณจะตั้งค่าเอเจนต์ แผงของมันจะพาคุณผ่านการลงชื่อเข้าใช้ Claude, Codex หรือ Grok และตัวแรกจะกลายเป็นเอเจนต์เริ่มต้นของคุณ หลังจากนั้น แผงจะวางทุกการสมัครใช้งานไว้ในหน้าเดียว: เอเจนต์และบัญชีแต่ละตัวพร้อมแผนของมัน มิเตอร์สำหรับขีดจำกัดเซสชัน 5 ชั่วโมงและขีดจำกัดรายสัปดาห์ของแต่ละตัวพร้อมเวลาจนกว่าจะรีเซ็ต (วางเมาส์เหนือเพื่อดูเปอร์เซ็นต์ที่แน่นอน) หรือยอดเงินแบบเติมเงินคงเหลือ ใต้บรรทัดที่หมุนเวียนผ่านสิ่งที่คุณใช้ไปในทุกตัว เช่น โทเค็นสัปดาห์นี้และโมเดลที่คุณใช้มากที่สุด ใต้ _Make something_ มันเสนอพรอมต์เริ่มต้นสำหรับธีม ปลั๊กอิน หรือแอปใหม่ ที่ส่งงานให้เอเจนต์เริ่มต้นของคุณ แอปถูกสร้างในแบบเดียวกับที่ Hype, Monologue และ Omacut ของ Omarchy เองถูกสร้าง คือใน C++ และ Qt Quick ตามสกิลเอเจนต์ omarchy-app และคอมไพเลอร์กับชิ้นส่วน Qt ที่พวกมันต้องการก็ติดตั้งมาด้วย Claude Code, Codex, Grok, Kimi, Cursor และโควตา Grok Bot ของมัน, GitHub Copilot, Muse, Antigravity, Kimchi และ Devin ได้รับการครอบคลุมมาตั้งแต่แรกพร้อมขีดจำกัดของพวกมัน และ Hermes, Mistral Vibe และ Qwen Code จะแสดงเซสชันและโทเค็นของพวกมันเมื่อคุณได้ใช้พวกมันแล้ว แผนและคีย์ของผู้ให้บริการที่คุณใช้ผ่าน pi, omp หรือ opencode ก็ปรากฏเช่นกัน: OpenCode Zen และ Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan และ Synthetic พร้อมขีดจำกัดของพวกมัน; Fireworks, OpenRouter และ DeepSeek พร้อมยอดเงินแบบเติมเงินของพวกมัน; และโมเดลที่คุณรันบนฮาร์ดแวร์ของคุณเองใต้ Local models เอเจนต์ทุกตัวถูกนับเพียงครั้งเดียว ใต้ผู้ที่เรียกเก็บเงินจากมัน ไม่ว่าคุณจะขับมันผ่าน harness กี่ตัวก็ตาม

คลิกซ้ายที่ไอคอนแถบเพื่อเปิดแผง คลิกขวาเพื่อเปิดเอเจนต์เริ่มต้นของคุณ บันทึกการใช้งานที่อยู่เบื้องหลังมันถูกสร้างใหม่ทุก 15 นาทีโดย `omarchy agent usage-update` และแผงยังสามารถรวมการใช้งานจากเครื่องอื่น ๆ ของคุณผ่านโฟลเดอร์ที่ซิงก์ได้ ดู README ใต้ `$OMARCHY_PATH/shell/plugins/agents/` สำหรับการตั้งค่าทั้งหมด

### การสมัครใช้งานหลายรายการ

หากคุณจ่ายสำหรับแผน Claude, Codex หรือ Grok มากกว่าหนึ่งแผน — เช่น Max ส่วนตัวและอีกแผนสำหรับงาน — Omarchy สามารถให้พวกมันทั้งหมดลงชื่อเข้าใช้อยู่และย้ายไปมาระหว่างพวกมันได้ เพิ่มการสมัครใช้งานด้วย + ในแผงเอเจนต์ ซึ่งจะพาคุณผ่านขั้นตอนตรงนั้นเลย หรือด้วย `omarchy agent account add claude Work` (หรือ `codex` หรือ `grok`) มันจะติดตั้ง CLI หากขาดอยู่ บัญชีแรกสำหรับผู้ให้บริการจะลงชื่อเข้าใช้ผ่านเบราว์เซอร์ปกติของคุณ ตรงตำแหน่งที่ CLI มองหาเสมอ ทุกบัญชีหลังจากนั้นจะลงชื่อเข้าใช้ผ่านหน้าต่างส่วนตัว ดังนั้นบัญชีที่เบราว์เซอร์ของคุณลงชื่อเข้าใช้อยู่แล้วจะไม่ถูกหยิบมาโดยไม่ตั้งใจ; ลงชื่อเข้าใช้ที่นั่นในฐานะบัญชีที่คุณกำลังเพิ่ม และปิดหน้าต่างส่วนตัวใด ๆ ที่คุณเปิดอยู่แล้วก่อน อย่าออกจากระบบของ CLI เพื่อทำสิ่งนี้เด็ดขาด: การออกจากระบบจะเพิกถอนการลงชื่อเข้าใช้ที่บันทึกไว้ และบัญชีนั้นจะต้องถูกเพิ่มใหม่อีกครั้ง

หากต้องการคัดลอกการเข้าสู่ระบบการสมัครใช้งานของคุณไปยังเครื่อง Omarchy อีกเครื่องผ่าน SSH ให้รัน `omarchy agent account copy user@laptop` ผู้ส่งจะจัดหาตัวรับชั่วคราวเมื่อปลายทางยังไม่ได้ติดตั้งไว้ ดังนั้นเครื่อง Omarchy รุ่นเก่ากว่าสามารถรับบัญชีได้โดยไม่ต้องอัปเดต ตัวรับที่ติดตั้งไว้จะมีความสำคัญก่อน การทำเช่นนี้จะคัดลอกการสมัครใช้งาน Claude, Codex และ Grok ทั้งหมด; เพิ่มชื่อผู้ให้บริการเพื่อเลือกพวกมัน เช่นใน `omarchy agent account copy laptop claude` ชื่อบัญชีและ ID คำสั่งจะตรงกับต้นทาง รวมถึงบัญชีที่มีอยู่แล้วบนปลายทาง บัญชีปลายทางที่ไม่เกี่ยวข้องจะได้รับคำต่อท้ายเป็นตัวเลขหากชื่อของพวกมันขัดแย้งกัน และการตั้งค่า สกิล ปลั๊กอิน และประวัติการสนทนาจะยังคงอยู่เฉพาะเครื่องแต่ละเครื่อง

ข้อมูลประจำตัวปลายทางที่มีอยู่จะถูกเก็บไว้ บัญชีต้นทางที่ลงชื่อเข้าใช้อยู่ที่นั่นแล้วจะมีชื่อซิงโครไนซ์โดยไม่แทนที่ข้อมูลประจำตัวของมัน; บัญชีอื่น ๆ จะถูกเพิ่มควบคู่ไปกับมัน หากต้องการแทนที่ข้อมูลประจำตัวที่บันทึกไว้สำหรับบัญชีที่ตรงกัน ให้ใช้ `omarchy agent account copy --replace laptop claude` หลังจากปิดเซสชันของบัญชีนั้นบนปลายทาง ปลายทางใหม่เอี่ยมยังจะได้รับบัญชีที่ใช้งานอยู่และการกำหนดลักษณะการสลับของต้นทางด้วย; ปลายทางที่ใช้งานมานานแล้วจะเก็บของตัวเองไว้

ข้อมูลประจำตัวเดินทางผ่าน SSH และถูกเก็บไว้ในไฟล์ส่วนตัวบนปลายทาง ดังนั้นคัดลอกไปยังเครื่องที่คุณไว้วางใจเท่านั้น นี่เป็นการคัดลอกครั้งเดียว ไม่ใช่การซิงโครไนซ์อย่างต่อเนื่อง โทเค็นรีเฟรชของ Codex สามารถถูกหมุนเวียนโดยเครื่องอื่นได้ ทำให้การเข้าสู่ระบบที่คัดลอกมาต้องต่ออายุ; การลงชื่อเข้าใช้แยกกันยังคงเป็นตัวเลือกที่เชื่อถือได้ที่สุดสำหรับการใช้งานพร้อมกันบนหลายเครื่อง ดู [คำแนะนำการยืนยันตัวตนบัญชีของ Codex](https://developers.openai.com/codex/auth/ci-cd-auth)

หนึ่งบัญชีต่อผู้ให้บริการจะใช้งานอยู่ และทุกเซสชันใหม่จะเริ่มต้นเป็นบัญชีนั้น: `cx`, `cy`, `claude`, `codex` หรือ `grok` แบบธรรมดา สิ่งใดก็ตามที่เปิดผ่าน `omarchy agent` และสคริปต์หรือตัวแก้ไขที่พบ CLI บน `PATH` สลับด้วย `omarchy agent account use work` (และกลับด้วย `omarchy agent account use main`) หรือในแผงโดยกดหมายเลขของบัญชีแล้วกด `Enter` (หรือคลิกปุ่ม Use ของมัน) เซสชันที่กำลังทำงานอยู่แล้วจะคงอยู่กับบัญชีที่พวกมันเริ่มต้นด้วย ประวัติการสนทนา การตั้งค่า สกิล และปลั๊กอินถูกแชร์ข้ามบัญชี ดังนั้น `claude --continue` ในโฟลเดอร์เดียวกันจะดำเนินการต่อจากจุดที่คุณค้างไว้บนบัญชีใหม่

ด้วยบัญชีมากกว่าหนึ่งบัญชี แผงจะแสดงขีดจำกัดของแต่ละบัญชีเคียงข้างกัน โดยบัญชีที่ใช้งานอยู่จะถูกทำเครื่องหมายไว้ โดยค่าเริ่มต้น Omarchy จะแจ้งเตือนคุณเมื่อบัญชีที่ใช้งานอยู่ผ่าน 95% ของขีดจำกัด และการคลิกการแจ้งเตือนจะสลับไปยังบัญชีที่มีพื้นที่เหลือมากที่สุด วางเมาส์เหนือบรรทัดของบัญชีในแผงและคลิก Autoswitch ที่ปรากฏข้าง Use (หรือกด `m`) หรือรัน `omarchy agent account mode auto` เพื่อให้มันสลับด้วยตัวเองแทน; ขณะที่เปิดอยู่ Autoswitch จะแทนที่ Use และการคลิกอีกครั้งจะกลับไปเป็นการแจ้งเตือน เพิ่มตัวเลขเพื่อเปลี่ยนเกณฑ์ เช่นใน `omarchy agent account mode auto 90` หากทุกบัญชีเกินเกณฑ์ คุณจะได้รับแจ้งเพียงครั้งเดียว พร้อมกับบัญชีใดจะว่างก่อน ขณะที่บัญชีที่ใช้งานอยู่ภายใน 15 จุดจากเกณฑ์ของมัน (80% ที่ค่าเริ่มต้น) ขีดจำกัดของมันจะถูกตรวจสอบทุกสามนาทีแทนที่จะเป็นทุก 15 นาที

`omarchy agent account list` แสดงทุกบัญชีและขีดจำกัดล่าสุดของพวกมัน `omarchy agent account remove work` ลืมบัญชีหนึ่ง และ `omarchy agent account rename primary Hey` เปลี่ยนชื่อบัญชีหนึ่ง (หรือคลิกชื่อบัญชีในแผง) คำสั่งเหล่านี้ทำงานกับบัญชีของเอเจนต์เริ่มต้นของคุณ; หากต้องการเข้าถึงผู้ให้บริการอื่น ให้ระบุชื่อมันก่อน เช่นใน `omarchy agent account use codex side` การเข้าสู่ระบบที่คุณมีอยู่แล้วใน `~/.claude` หรือ `~/.codex` คือบัญชี _Main_ และคงอยู่ที่เดิม บัญชีที่ไม่ได้ใช้มานานกว่าประมาณแปดชั่วโมงอาจแสดง _Sign-in required_; คลิกมันเพื่อลงชื่อบัญชีนั้นเข้าใช้อีกครั้งในแผงเลย หรือเริ่มเซสชันในมัน ซึ่งจะรีเฟรชการลงชื่อเข้าใช้ด้วยตัวเอง เซิร์ฟเวอร์ MCP ที่คุณมีเมื่อบัญชีถูกเพิ่มจะตามไปกับมัน แต่เซิร์ฟเวอร์ที่คุณเพิ่มภายหลังด้วย `claude mcp add` จะไปถึงเฉพาะบัญชีที่คุณเพิ่มพวกมันไว้ Claude Desktop และเครื่องมือที่กำหนดค่าด้วยเส้นทางแบบสัมบูรณ์ไปยังไบนารี CLI จะไม่ตามการสลับนั้นไป `CLAUDE_CONFIG_DIR`, `CODEX_HOME` หรือ `GROK_HOME` ที่ชัดเจนจะมีลำดับความสำคัญเหนือบัญชีที่เลือก

### การวินิจฉัยการแครช

Omarchy เฝ้าดู systemd-coredump สำหรับการแครชของโปรเซส เมื่อบางอย่างเกิด segfault คุณจะได้รับการแจ้งเตือน "Process crashed" — คลิกมัน และการแครชจะถูกส่งให้เอเจนต์เริ่มต้นของคุณพร้อมกับสกิล diagnose-crash ของ Omarchy ซึ่งจะพาเอเจนต์ผ่านการสร้างข้อเท็จจริงจาก core dump และตัดสินใจว่าการแครชนั้นคุ้มค่าที่จะรายงานไปยัง upstream หรือไม่ คุณยังรันมันด้วยมือกับ PID ใด ๆ จาก `coredumpctl list` ด้วย `omarchy agent crash <pid>` ได้ด้วย

การเฝ้าดูเปิดอยู่โดยค่าเริ่มต้น ปิดมันใต้ _Trigger > Toggle > Crash Capture_ (หรือด้วย `omarchy toggle crash-capture`) และการแจ้งเตือนจะหยุด; `omarchy agent crash <pid>` ยังคงทำงานด้วยมือได้

การแครชยังสามารถถูกปิดเสียงได้ทีละโปรแกรม ซึ่งเป็นสิ่งที่การวินิจฉัยเสนอให้คุณในตอนท้าย `omarchy crash mute hyprland` หยุดการแจ้งเตือนสำหรับโปรแกรมนั้นเท่านั้น `omarchy crash mute hyprland off` นำพวกมันกลับมา และ `omarchy crash mute` ด้วยตัวเองจะแสดงสิ่งที่คุณได้ปิดเสียงไว้ มันรับเส้นทางของไบนารีได้พอ ๆ กับชื่อของมัน ดังนั้น `omarchy crash mute /usr/bin/hyprland` จึงทำสิ่งเดียวกัน ใส่เครื่องหมายคำพูดชื่อที่มีช่องว่าง เช่นใน `omarchy crash mute 'Some App'` อย่างอื่นทุกอย่างยังคงแจ้งเตือน และโปรแกรมที่ปิดเสียงไว้ยังคงแครช — สิ่งนี้ซ่อนการเตือน มันไม่ได้แก้อะไรเลย

### แอปเดสก์ท็อป

เมนู _Install > AI_ ยังมีแอป AI แบบกราฟิกอยู่สองสามตัว: แอปเดสก์ท็อป ChatGPT, แอปเดสก์ท็อป Claude (เบต้า Linux ของ Anthropic พร้อมแท็บ Chat, Cowork และ Claude Code), Grok Bot สำหรับแชทกับโมเดลของ xAI, Herdr Desktop, Hermes Desktop, OpenClaw, แอปเดสก์ท็อป Perplexity และ T3 Code Grok Bot คือแอปแชทเดสก์ท็อป เอเจนต์เขียนโค้ดคือคำสั่ง `grok`

Hermes Desktop เป็นตัวที่ต้องรู้ เพราะเครื่องหนึ่งมี Hermes เดียว และมันเป็นของแอป: Hermes ถูกติดตั้งผ่านแอปเท่านั้นเสมอ และคำสั่ง `hermes` ที่เอเจนต์เริ่มต้นรันคือของแอป การเลือก Hermes เป็นเอเจนต์เริ่มต้นจะติดตั้งสิ่งเดียวกับที่รายการ _Install > AI_ ติดตั้ง: แพ็กเกจ และรันไทม์ Hermes ใต้ `~/.hermes` ที่ตั้งค่าโดยตัวติดตั้งของ Hermes เอง ซึ่งใช้เวลาสองสามนาทีในครั้งแรก รันไทม์นั้นคือ Hermes เดียวที่คำสั่ง `hermes` บนเทอร์มินัล เอเจนต์เริ่มต้น และแอปล้วนใช้ และมันอัปเดตตัวเองด้วย `hermes update` แทนที่จะรอการเปิดตัว Omarchy การติดตั้งมันยังมอบธีม Omarchy ให้ Hermes เป็นสกินชื่อ `omarchy` ซึ่งทุกพื้นผิวของ Hermes จะตามไปด้วยเมื่อคุณสลับธีม; เลือกอีกอันใต้การตั้งค่า Appearance ของ Hermes หรือด้วย `/skin` หากคุณไม่อยากให้เป็นเช่นนั้น และ Omarchy จะปล่อยตัวเลือกนั้นไว้ตามลำพัง การลบแอปใต้ _Remove > AI_ จะปิด Hermes ก่อน รวม gateway ด้วย นำรันไทม์นั้นไปด้วย และเก็บแชท ความทรงจำ และสกิลที่ Hermes เขียนให้ตัวเองไว้ เว้นแต่คุณจะบอกเป็นอย่างอื่น: มันจะถาม โดยค่าเริ่มต้นคือไม่ ว่าข้อมูลนั้นและการตั้งค่าการเชื่อมต่อของคุณควรไปด้วยหรือไม่

ประสบการณ์เดสก์ท็อปของ OpenClaw คือ Control UI ของมัน ซึ่งเปิดเป็นเว็บแอปที่สนับสนุนโดย gateway ในเครื่องของมันเอง OpenClaw อาศัยอยู่ใน `~/.openclaw` และอัปเดตตัวเอง: ใช้ปุ่ม "Update Gateway" ของ Control UI หรือรัน `openclaw update` และ gateway จะรีสตาร์ทบนรุ่นใหม่ Omarchy เพียงเลือกว่ารุ่นใดที่การติดตั้งใหม่จะเริ่มต้นจาก การลบ OpenClaw ใต้ _Remove > AI_ จะนำบริการ gateway และแอปไปด้วย จากนั้นถามว่า `~/.openclaw` ควรไปด้วยหรือไม่ เนื่องจากที่นั่นเก็บแชทและข้อมูลประจำตัวของคุณควบคู่ไปกับ OpenClaw เองและรันไทม์ปลั๊กอินที่มันดาวน์โหลด; ค่าเริ่มต้นเก็บมันไว้ และการติดตั้ง OpenClaw อีกครั้งจะหยิบมันกลับมา

Herdr Desktop คือแอปเดสก์ท็อป [Herdr](https://herdr.dev): spaces, tabs และ panes ของเทอร์มินัลและเอเจนต์เขียนโค้ดที่ยังคงทำงานอยู่ใน core ของมันเมื่อคุณปิดหน้าต่าง มันมาจากตัวติดตั้งของ Herdr เองแทนที่จะเป็นแพ็กเกจ ดังนั้นมันอาศัยอยู่ใน `~/.local/share/herdr-app` นำ core ของมันมาไว้ใน `~/.local/bin/herdr-core` เมื่อคุณยังไม่มี และอัปเดตทั้งตัวมันเอง มันอยู่เคียงข้างคำสั่ง `herdr` ที่ Omarchy ส่งมาบน `Super + Ctrl + Return` แทนที่จะแทนที่มัน และได้รับคีย์โดยตรงของคำสั่งนั้น: `Alt + Return` และ `Alt + Shift + Return` แบ่ง pane ลงหรือขวา `Alt + Escape` ปิดมัน `Ctrl + Alt + Arrow` ย้ายระหว่าง panes `Alt + 1..9` และ `Alt + Left/Right` เลือก tab และ `Alt + Up/Down` ย้ายระหว่าง spaces `Ctrl + 1..9` เลือก space และ `Alt + Shift + Up/Down` ก้าวผ่านเอเจนต์ คีย์นำหน้า `Ctrl + Space` ยังคงเป็นเฉพาะเทอร์มินัล เนื่องจากแอปไม่สามารถถือคีย์ Ctrl ธรรมดาไว้สำหรับลำดับได้ Omarchy เขียนสิ่งเหล่านี้ไปยัง `~/.config/herdr-app/keys.json` และ `omarchy-refresh-herdr-app` จะนำพวกมันกลับมา การติดตั้งมันจะเลือกธีม Omarchy ของ Herdr ซึ่งจะตามธีม Omarchy ของคุณต่อจากนั้น Herdr เก็บธีมหนึ่งสำหรับโหมดสว่างและอีกธีมสำหรับโหมดมืด ดังนั้นหลังจากสลับระหว่างธีม Omarchy มืดและสว่าง ให้เลือก Omarchy ในตัวเลือกธีมของ Herdr อีกครั้งสำหรับโหมดอื่น

T3 Code รันจากรุ่น AppImage อย่างเป็นทางการใน `~/.local/share/t3code` แทนที่จะมาจากแพ็กเกจ ดังนั้นมันจึงอัปเดตตัวเอง การติดตั้งมันจะถามว่าจะเริ่มบนช่อง Stable หรือ Nightly; สลับภายหลังในการตั้งค่าของ T3 Code เธรดและการตั้งค่าของคุณอาศัยอยู่ใน `~/.t3` และการลบ T3 Code ใต้ _Remove > AI_ จะนำพวกมันไปด้วย

### โมเดลในเครื่อง

รันโมเดลแบบเปิดบนเครื่องของคุณเองสำหรับเอเจนต์เขียนโค้ดของคุณ พรอมต์และโค้ดของคุณคงอยู่บนเครื่อง; ไม่มีอะไรที่ส่งไปยังโมเดลออกจากเครื่อง เริ่มต้นด้วย:

```bash
omarchy agent local use best
```

หรือในแผงเอเจนต์ในแถบด้านบน เลือก + แล้วเลือก Local AI ซึ่งจะปรากฏเมื่อโมเดลเหมาะกับเครื่องนี้ ครั้งแรก การทำเช่นนี้จะติดตั้ง Podman ซึ่งรันโมเดล และบนเครื่อง NVIDIA จะติดตั้งชุดเครื่องมือ container ของ NVIDIA ซึ่งให้ GPU แก่พวกมัน จากนั้น Omarchy จะเลือกโมเดลที่แนะนำสำหรับเครื่องนี้ ดาวน์โหลดมัน และเริ่มมัน คาดหวังการดาวน์โหลดหลายสิบ GB และหน่วยความจำส่วนใหญ่ของเครื่องจะถูกใช้ขณะโมเดลทำงาน: Flash Next ใช้ประมาณ 100 GiB กับ context เต็ม 256K หากโมเดลอื่นถือหน่วยความจำที่มันต้องการอยู่ มันจะถูกตั้งค่าแบบหยุดไว้ พร้อมเริ่มเมื่อคุณหยุดโมเดลหนึ่ง โมเดลจะหยุดเมื่อออกจากระบบ; หยุดมันด้วยตัวเองเมื่อคุณต้องการหน่วยความจำสำหรับอย่างอื่น

`omarchy agent local list` แสดงตัวเลือกและอธิบายว่าทำไมบางตัวไม่เหมาะ หากต้องการตั้งค่าอีกตัว ให้รัน `omarchy agent local use <recipe>` วันนี้ `qwen3.8-flash-next-gufo` และ `qwen3.8-27b-gufo` มีให้สำหรับเครื่อง Strix Halo 128 GB; 27B ใช้ประมาณ 40 GiB ดังนั้นมันจึงเหลือพื้นที่สำหรับงานอื่น สูตรและคำแนะนำใหม่มาพร้อมกับ `omarchy update` ผ่านแพ็กเกจ

โมเดลทุกตัวที่คุณตั้งค่าจะได้รับบรรทัดของตัวเองในแผงเอเจนต์ ถัดจากการสมัครใช้งานของคุณ: เล่นเพื่อเริ่มมัน หยุดชั่วคราวเพื่อหยุดมันและปล่อยหน่วยความจำของมันให้ว่าง และปุ่มเทอร์มินัลเพื่อเปิดเอเจนต์ของคุณบนมัน หลายตัวสามารถรันพร้อมกันได้เมื่อพวกมันพอดีในหน่วยความจำด้วยกัน; หากตัวหนึ่งไม่พอดี Omarchy จะบอกว่าโมเดลที่กำลังรันตัวใดให้หยุด ลากบรรทัดเพื่อจัดลำดับใหม่ และกด Delete บนบรรทัดที่เลือกเพื่อลบโมเดลและการดาวน์โหลดของมัน

จากบรรทัดคำสั่ง `omarchy agent local start <recipe>` และ `omarchy agent local stop <recipe>` ทำสิ่งเดียวกัน `omarchy agent local status` แสดงทุกโมเดล และ `omarchy agent --local` เปิดเอเจนต์เริ่มต้นของคุณบนโมเดลล่าสุดที่คุณเริ่ม (pi หากเอเจนต์เริ่มต้นของคุณไม่สามารถใช้โมเดลในเครื่องได้) ไคลเอนต์ที่เข้ากันได้กับ OpenAI ใด ๆ ก็สามารถเชื่อมต่อได้เช่นกัน: `status` แสดงที่อยู่ของแต่ละโมเดล (ตัวแรกคือ `http://127.0.0.1:11435/v1`) ชื่อสูตรคือโมเดล และคีย์อยู่ใน `~/.config/omarchy/agent-local/key`

`omarchy agent local remove <recipe>` ลบโมเดลและการดาวน์โหลดที่ไม่มีโมเดลอื่นใช้

รันไทม์ของบุคคลที่สามจะถูกระบุด้วยผู้เผยแพร่ของพวกมัน Omarchy รันทุกโมเดลโดยไม่มีการเข้าถึงเครือข่าย

### LLM ในเครื่อง

Omarchy แนะนำสองวิธีในการรันโมเดล LLM ในเครื่อง: LM Studio และ Ollama LM Studio ให้อินเทอร์เฟซ GUI สำหรับค้นหาโมเดลแบบ open-weight ติดตั้งพวกมัน และรันพวกมัน มันเป็นวิธีที่ยอดเยี่ยมในการเริ่มต้นอย่างง่ายดาย Ollama เสนอ CLI สำหรับทำเช่นเดียวกัน แต่หากคุณยังใหม่กับโมเดลในเครื่อง ผมจะเริ่มด้วย LM Studio คุณสามารถติดตั้งตัวใดตัวหนึ่งใต้ _Install > AI_ ใน Omarchy Menu

### สกิล Omarchy

สกิลเอเจนต์ช่วยให้ AI ใช้เครื่องมือเฉพาะในวิธีเฉพาะ และ Omarchy ส่งมาพร้อมสกิลเริ่มต้นสำหรับการปรับแต่งระบบ เช่น การปรับ config Hyprland ของคุณ การปรับแถบ หรือแม้แต่การสร้างธีมใหม่ตั้งแต่ต้น มันถูก symlink เข้าไปในไดเรกทอรีสกิลสำหรับ Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` และแต่ละ `~/.hermes/profiles/*/skills`) และตำแหน่งทั่วไป `~/.agents/skills` ดังนั้น harness ส่วนใหญ่จะหยิบมันขึ้นมาโดยอัตโนมัติ

แต่คุณควรปฏิบัติต่อสกิลนี้ว่าเป็นตัวทดลอง โมเดลต่าง ๆ จะใช้มันให้เกิดผลต่างกัน มันดีที่สุดที่จะรันในโหมดวางแผนก่อน เพื่อให้คุณมีแนวคิดว่าเอเจนต์อยากเปลี่ยนอะไร จากนั้นจงพร้อมที่จะย้อนกลับการเปลี่ยนแปลงหรือแม้แต่เรียกใช้ `omarchy reinstall configs` หากเอเจนต์ทำทุกอย่างเละเทะ
