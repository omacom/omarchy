### การติดตั้งและอัปเดตเอเจนต์

ยกเว้น Hermes เอเจนต์เหล่านี้ใช้การติดตั้งแบบ lazy ของ mise: การเปิดใช้ครั้งแรกจะติดตั้ง CLI และการเปิดใช้ครั้งต่อ ๆ ไปจะนำมันกลับมาใช้ใหม่ นอกจากนี้ mise ยังตรวจสอบว่าเอเจนต์ที่ติดตั้งไว้มีรุ่นใหม่ออกมาหรือไม่ อย่างมากที่สุดหนึ่งครั้งทุกสี่ชั่วโมง ก่อนที่มันจะเริ่มทำงาน หรือในพื้นหลังที่พรอมต์ของเชลล์ หากการอัปเดตนั้นล้มเหลวหรือคุณออฟไลน์อยู่ รุ่นที่ติดตั้งไว้ก็จะทำงานต่อไป `omarchy update` จะอัปเดตเอเจนต์ที่ติดตั้งไว้พร้อมกับส่วนอื่น ๆ ของ Omarchy และ `mup` จะอัปเดตเฉพาะเครื่องมือที่จัดการโดย mise เท่านั้น

ตัวอัปเดตของเอเจนต์เอง เช่น `claude update`, `codex update` หรือปุ่มอัปเดตในแอป จะไม่อัปเดตการติดตั้งที่จัดการโดย mise `codex update` จะล้มเหลว และ `claude update` อาจรายงานว่าสำเร็จในขณะที่ติดตั้งสำเนาแยกต่างหากที่ mise ไม่ได้ติดตาม หากคุณอยากใช้ตัวติดตั้งและตัวอัปเดตดั้งเดิมของเอเจนต์แทน ให้เพิ่มมันลงใน `disable_tools`; ดู [เครื่องมือ CLI ที่ติดตั้งมาล่วงหน้า](18-development-tools.md#preinstalled-cli-tools)

หากต้องการติดตั้งเครื่องมือแบบ lazy ที่กำหนดค่าไว้ทั้งหมดก่อนที่คุณจะต้องการใช้ ให้รัน `mise install --include-lazy` ซึ่งรวมถึงเครื่องมือ CLI เริ่มต้นตัวอื่น ๆ ของ Omarchy ตลอดจนเหล่าเอเจนต์ด้วย ดู [เครื่องมือ CLI ที่ติดตั้งมาล่วงหน้า](18-development-tools.md#preinstalled-cli-tools) สำหรับการติดตั้งเครื่องมือเพียงตัวเดียวหรือการใช้การติดตั้งของคุณเอง

`grok` ถูกติดตั้งผ่านแพ็กเกจ `grok` แบบ first-party ของ mise ในลักษณะเดียวกับ `claude` และ `codex` รัน `grok` หรือเลือกมันภายใต้ _Setup > Defaults > Agent_ ข้ามตัวติดตั้งแบบ `curl | bash` บน x.ai ไปเลย เส้นทางนั้นจะใส่สำเนาที่สองลงใน `~/.grok/bin`, นำมันมาไว้หน้า `PATH` และเขียนทับ wrapper ของ Omarchy

`dsh` เปิด UI บนเบราว์เซอร์ของมันที่ `127.0.0.1:3080` โดยใช้ไดเรกทอรีที่เปิดใช้เป็นพื้นที่ทำงานเริ่มต้น UI บนเบราว์เซอร์ของมันไม่รับพรอมต์เริ่มต้น ดังนั้น `omarchy agent prompt` จะเปิดมันโดยมีพรอมต์อยู่บนคลิปบอร์ดของคุณให้วาง Omarchy เริ่มมันด้วยค่าตั้งต้นสิทธิ์แบบไม่ต้องขออนุมัติของ DeepSeek DeepSeek Harness จะอัปโหลดบันทึกเซสชันไปยัง DeepSeek เมื่อคุณใช้ API โมเดลอย่างเป็นทางการของมัน; ปิดการทำงานนั้นได้ภายใต้ _Settings > General > Upload Session Log_ ใน UI บนเบราว์เซอร์ของมัน ข้อเสนอแนะที่คุณส่งให้มันก็จะถูกอัปโหลดไปพร้อมกับเซสชันเช่นกัน เว้นแต่คุณจะเริ่มมันด้วย `DSH_TELEMETRY_MODE=DISABLED`

### เอเจนต์เริ่มต้น

เลือกเอเจนต์เริ่มต้นของคุณด้วย `omarchy default agent <name>` หรือภายใต้ _Setup > Defaults > Agent_ ใน Omarchy Menu (`Super + Space`) หากเอเจนต์ยังไม่ได้ถูกติดตั้ง การเลือกมันจะติดตั้งให้ก่อน Omarchy ที่ติดตั้งใหม่จะเชิญชวนให้คุณทำการเลือกนี้ด้วยการแจ้งเตือนเพียงครั้งเดียว

การเลือก Claude ยังพยายามตั้งค่าส่วนขยายเบราว์เซอร์ของมันสำหรับ Chromium, Chrome, Brave, Brave Origin และ Edge ด้วย การตั้งค่าส่วนขยายมีผลกับผู้ใช้ทุกคนและอาจขอรหัสผ่านระบบของคุณ; การยกเลิกหรือการติดตั้งส่วนขยายที่ล้มเหลวก็ยังคงเลือกและเรียกใช้ Claude อยู่ดี รีสตาร์ตเบราว์เซอร์ของคุณ เปิดใช้งานส่วนขยายหากระบบแจ้ง และลงชื่อเข้าใช้ Claude เพื่อเชื่อมต่อมันให้เสร็จ รัน `/chrome` ใน Claude เพื่อตรวจสอบการเชื่อมต่อ Firefox และ Zen ไม่รองรับส่วนขยายนี้ หาก Claude เคยเป็นค่าเริ่มต้นของคุณอยู่แล้วก่อนที่การตั้งค่านี้จะถูกเพิ่มเข้ามา ให้เลือกมันอีกครั้งเพื่อติดตั้งส่วนขยาย

เมื่อคุณเลือกแล้ว `Super + Shift + Ctrl + A` จะเรียกใช้เอเจนต์เริ่มต้นในหน้าต่างเทอร์มินัลเฉพาะ (หรือเปิดตัวเลือกขึ้นมาหากคุณยังไม่ได้เลือก) คุณยังสามารถเรียกใช้มันให้เข้าสู่งานโดยตรงได้ด้วย `omarchy agent prompt "Review this project"` Freebuff และ DeepSeek Harness ไม่รับพรอมต์เริ่มต้น ดังนั้นพวกมันจะเปิดขึ้นโดยมีพรอมต์อยู่บนคลิปบอร์ดของคุณให้วางแทน เอเจนต์ที่เรียกใช้ด้วยวิธีนี้จะทำงานโดยไม่มีผู้ดูแลในโหมดไม่หยุดถามของแต่ละตัว ดังนั้นจงเตรียมพร้อมให้พวกมันลงมือทำสิ่งต่าง ๆ จริง ๆ! MiniMax Code ไม่มีโหมดดังกล่าวสำหรับเซสชันแบบอินเทอร์แอกทีฟของมัน ดังนั้นมันจึงขออนุญาตตามปกติ และเนื่องจากเอเจนต์ปฏิเสธที่จะจดจำความไว้วางใจสำหรับไดเรกทอรีบ้านของคุณ การเรียกใช้จาก `$HOME` จึงเริ่มใน `~/Work` แทน

ยังมีทางลัดในเทอร์มินัลด้วย: `a` รันเอเจนต์เริ่มต้นแบบอินไลน์ในเทอร์มินัลปัจจุบัน ขณะที่ `c`, `cx` และ `cy` เริ่ม OpenCode, Claude Code และ Codex โดยตรง (ในโหมดอนุมัติอัตโนมัติของพวกมันอีกเช่นกัน) การเปลี่ยนธีมก็ซิงก์ไปยังเอเจนต์ด้วยเช่นกัน: Claude Code, Pi, OpenCode และ Hermes (เมื่อ Omarchy ได้ติดตั้งมันแล้ว) ล้วนเปลี่ยนตามเมื่อคุณสลับธีมของ Omarchy

### แผงเอเจนต์

แถบบนสุดมีไอคอนเอเจนต์ ก่อนที่คุณจะตั้งค่าเอเจนต์ แผงของมันจะแนะนำให้คุณลงชื่อเข้าใช้ Claude, Codex หรือ Grok และตัวแรกจะกลายเป็นเอเจนต์เริ่มต้นของคุณ หลังจากนั้น แผงจะนำการสมัครใช้งานทุกอย่างมาไว้ในหน้าเดียว: เอเจนต์และบัญชีแต่ละตัวพร้อมกับแพ็กเกจของมัน มิเตอร์สำหรับขีดจำกัดเซสชัน 5 ชั่วโมงและขีดจำกัดรายสัปดาห์ของแต่ละตัวพร้อมกับเวลาจนกว่าจะรีเซ็ต (วางเมาส์เหนือเพื่อดูเปอร์เซ็นต์ที่แน่นอน) หรือยอดเงินคงเหลือที่ชำระล่วงหน้า ภายใต้บรรทัดที่หมุนเวียนสิ่งที่คุณใช้งานไปในทั้งหมด เช่น โทเคนในสัปดาห์นี้และโมเดลที่คุณใช้มากที่สุด ภายใต้ _Make something_ มันนำเสนอพรอมต์เริ่มต้นสำหรับธีม ปลั๊กอิน หรือแอปใหม่ ที่ส่งมอบงานให้เอเจนต์เริ่มต้นของคุณ แอปถูกสร้างขึ้นในแบบเดียวกับ Hype, Monologue และ Omacut ของ Omarchy เอง คือใน C++ และ Qt Quick โดยทำตามทักษะเอเจนต์ omarchy-app และคอมไพเลอร์และชิ้นส่วน Qt ที่พวกมันต้องการก็ถูกติดตั้งมาให้ Claude Code, Codex, Grok, Kimi, Cursor และโควตา Grok Bot ของมัน, GitHub Copilot, Muse, Antigravity, Kimchi และ Devin ได้รับการครอบคลุมมาตั้งแต่แรกพร้อมกับขีดจำกัดของพวกมัน และ Hermes, Mistral Vibe และ Qwen Code จะแสดงเซสชันและโทเคนของพวกมันเมื่อคุณได้ใช้งานพวกมันแล้ว แพ็กเกจและคีย์ของผู้ให้บริการที่คุณใช้ผ่าน pi, omp หรือ opencode ก็ปรากฏขึ้นเช่นกัน: OpenCode Zen และ Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan และ Synthetic พร้อมกับขีดจำกัดของพวกมัน; Fireworks, OpenRouter และ DeepSeek พร้อมกับยอดเงินคงเหลือที่ชำระล่วงหน้าของพวกมัน; และโมเดลที่คุณรันบนฮาร์ดแวร์ของคุณเองภายใต้ Local models เอเจนต์ทุกตัวถูกนับเพียงครั้งเดียว ภายใต้ผู้ที่เรียกเก็บเงินจากมัน ไม่ว่าคุณจะขับเคลื่อนมันผ่าน harness กี่ตัวก็ตาม

คลิกซ้ายที่ไอคอนบนแถบเพื่อเปิดแผง คลิกขวาเพื่อเรียกใช้เอเจนต์เริ่มต้นของคุณ บันทึกการใช้งานที่อยู่เบื้องหลังมันจะถูกสร้างใหม่ทุก 15 นาทีโดย `omarchy agent usage-update` และแผงยังสามารถผสานการใช้งานจากเครื่องอื่น ๆ ของคุณผ่านโฟลเดอร์ที่ซิงก์ได้ ดู README ภายใต้ `$OMARCHY_PATH/shell/plugins/agents/` สำหรับการตั้งค่าทั้งหมด

### การสมัครใช้งานหลายรายการ

หากคุณจ่ายเงินให้กับแพ็กเกจ Claude, Codex หรือ Grok มากกว่าหนึ่งแพ็กเกจ — เช่น Max ส่วนตัวและอีกอันสำหรับงาน — Omarchy สามารถให้พวกมันลงชื่อเข้าใช้ไว้ทั้งหมดและย้ายไปมาระหว่างพวกมันได้ เพิ่มการสมัครใช้งานด้วยเครื่องหมาย + ในแผงเอเจนต์ ซึ่งจะแนะนำคุณตรงนั้นเลย หรือด้วย `omarchy agent account add claude Work` (หรือ `codex` หรือ `grok`) มันจะติดตั้ง CLI หากยังไม่มีอยู่ บัญชีแรกสำหรับผู้ให้บริการจะลงชื่อเข้าใช้ผ่านเบราว์เซอร์ปกติของคุณ ตรงจุดที่ CLI มองหาอยู่เสมอ ทุกบัญชีหลังจากนั้นจะลงชื่อเข้าใช้ผ่านหน้าต่างส่วนตัว เพื่อที่บัญชีที่เบราว์เซอร์ของคุณลงชื่อเข้าใช้อยู่แล้วจะไม่ถูกหยิบขึ้นมาโดยไม่ตั้งใจ; ลงชื่อเข้าใช้ที่นั่นในฐานะบัญชีที่คุณกำลังเพิ่ม และปิดหน้าต่างส่วนตัวใด ๆ ที่คุณเปิดค้างไว้ก่อน อย่าออกจากระบบของ CLI เพื่อทำสิ่งนี้เป็นอันขาด: การออกจากระบบจะเพิกถอนการลงชื่อเข้าใช้ที่บันทึกไว้ และบัญชีนั้นจะต้องถูกเพิ่มอีกครั้ง

หากต้องการคัดล็อกการลงชื่อเข้าใช้การสมัครใช้งานของคุณไปยังเครื่อง Omarchy อีกเครื่องผ่าน SSH ให้รัน `omarchy agent account copy user@laptop` ผู้ส่งจะจัดหาตัวรับชั่วคราวเมื่อปลายทางยังไม่มีตัวรับที่ติดตั้งไว้ เพื่อให้เครื่อง Omarchy รุ่นเก่ากว่าสามารถรับบัญชีได้โดยไม่ต้องอัปเดต ตัวรับที่ติดตั้งไว้จะมีความสำคัญเหนือกว่า สิ่งนี้คัดลอกการสมัครใช้งาน Claude, Codex และ Grok ทั้งหมด; เพิ่มชื่อผู้ให้บริการเพื่อเลือกพวกมัน เช่นใน `omarchy agent account copy laptop claude` ชื่อบัญชีและ ID คำสั่งจะตรงกับต้นทาง รวมถึงบัญชีที่มีอยู่แล้วบนปลายทาง บัญชีปลายทางที่ไม่เกี่ยวข้องจะได้รับคำต่อท้ายที่เป็นตัวเลขหากชื่อของพวกมันขัดกัน และการตั้งค่า ทักษะ ปลั๊กอิน และประวัติการสนทนาจะยังคงอยู่เฉพาะเครื่องแต่ละเครื่อง

ข้อมูลรับรองปลายทางที่มีอยู่จะถูกเก็บไว้ บัญชีต้นทางที่ลงชื่อเข้าใช้ที่นั่นอยู่แล้วจะมีการซิงโครไนซ์ชื่อโดยไม่แทนที่ข้อมูลรับรองของมัน; บัญชีอื่น ๆ จะถูกเพิ่มควบคู่ไปกับมัน หากต้องการแทนที่ข้อมูลรับรองที่บันทึกไว้สำหรับบัญชีที่ตรงกัน ให้ใช้ `omarchy agent account copy --replace laptop claude` หลังจากออกจากเซสชันของบัญชีนั้นบนปลายทางแล้ว ปลายทางใหม่ยังได้รับบัญชีที่ใช้งานอยู่และค่ากำหนดการสลับของต้นทางด้วย; ปลายทางที่มีอยู่แล้วจะเก็บของตัวเองไว้

ข้อมูลรับรองเดินทางผ่าน SSH และถูกเก็บไว้ในไฟล์ส่วนตัวบนปลายทาง ดังนั้นจงคัดลอกไปยังเครื่องที่คุณไว้วางใจเท่านั้น นี่คือการคัดลอกเพียงครั้งเดียว ไม่ใช่การซิงโครไนซ์อย่างต่อเนื่อง โทเคนรีเฟรชของ Codex อาจถูกหมุนเวียนโดยเครื่องอื่น ทำให้การลงชื่อเข้าใช้ที่คัดลอกมาต้องต่ออายุ; การลงชื่อเข้าใช้แยกกันยังคงเป็นตัวเลือกที่น่าเชื่อถือที่สุดสำหรับการใช้งานพร้อมกันบนหลายเครื่อง ดู [คำแนะนำเรื่องการยืนยันตัวตนบัญชีของ Codex](https://developers.openai.com/codex/auth/ci-cd-auth)

บัญชีหนึ่งบัญชีต่อผู้ให้บริการหนึ่งรายจะใช้งานอยู่ และเซสชันใหม่ทุกเซสชันจะเริ่มเป็นบัญชีนั้น: `cx`, `cy`, `claude`, `codex` หรือ `grok` ธรรมดา อะไรก็ตามที่เรียกใช้ผ่าน `omarchy agent` และสคริปต์หรือเอดิเตอร์ที่พบ CLI บน `PATH` สลับด้วย `omarchy agent account use work` (และกลับด้วย `omarchy agent account use main`) หรือในแผงโดยกดหมายเลขของบัญชีแล้วกด `Enter` (หรือคลิกปุ่ม Use ของมัน) เซสชันที่กำลังทำงานอยู่แล้วจะยังคงอยู่กับบัญชีที่พวกมันเริ่มด้วย ประวัติการสนทนา การตั้งค่า ทักษะ และปลั๊กอินถูกแชร์ข้ามบัญชี ดังนั้น `claude --continue` ในโฟลเดอร์เดียวกันจะดำเนินการต่อจากจุดที่คุณค้างไว้บนบัญชีใหม่

เมื่อมีมากกว่าหนึ่งบัญชี แผงจะแสดงขีดจำกัดของแต่ละบัญชีแบบเคียงข้างกัน โดยบัญชีที่ใช้งานอยู่จะถูกทำเครื่องหมายไว้ โดยค่าเริ่มต้น Omarchy จะแจ้งเตือนคุณเมื่อบัญชีที่ใช้งานอยู่ผ่าน 95% ของขีดจำกัด และการคลิกที่การแจ้งเตือนจะสลับไปยังบัญชีที่มีพื้นที่เหลือมากที่สุด วางเมาส์เหนือบรรทัดของบัญชีในแผงแล้วคลิก Autoswitch ที่ปรากฏอยู่ข้าง Use (หรือกด `m`) หรือรัน `omarchy agent account mode auto` เพื่อให้มันสลับด้วยตัวเองแทน; ขณะที่มันเปิดอยู่ Autoswitch จะเข้าแทนที่ Use และการคลิกมันอีกครั้งจะกลับไปเป็นการแจ้งเตือน เพิ่มตัวเลขเพื่อเปลี่ยนเกณฑ์ เช่นใน `omarchy agent account mode auto 90` หากทุกบัญชีเกินเกณฑ์ คุณจะได้รับแจ้งเพียงครั้งเดียว พร้อมกับว่าบัญชีใดจะว่างก่อน ขณะที่บัญชีที่ใช้งานอยู่ภายใน 15 จุดของเกณฑ์ของมัน (80% ที่ค่าเริ่มต้น) ขีดจำกัดของมันจะถูกตรวจสอบทุกสามนาทีแทนที่จะเป็นทุก 15 นาที

`omarchy agent account list` แสดงทุกบัญชีและขีดจำกัดล่าสุดของมัน `omarchy agent account remove work` ลืมบัญชีหนึ่งบัญชี และ `omarchy agent account rename primary Hey` เปลี่ยนชื่อบัญชีหนึ่งบัญชี (หรือคลิกชื่อบัญชีในแผง) คำสั่งเหล่านี้ทำงานกับบัญชีของเอเจนต์เริ่มต้นของคุณ; หากต้องการเข้าถึงผู้ให้บริการรายอื่น ให้ระบุชื่อมันก่อน เช่นใน `omarchy agent account use codex side` การลงชื่อเข้าใช้ที่คุณมีอยู่แล้วใน `~/.claude` หรือ `~/.codex` คือบัญชี _Main_ และคงอยู่ที่เดิม บัญชีที่ไม่ได้ใช้งานมานานกว่าแปดชั่วโมงโดยประมาณอาจแสดง _Sign-in required_; คลิกมันเพื่อลงชื่อเข้าใช้บัญชีนั้นอีกครั้งตรงในแผง หรือเริ่มเซสชันในมัน ซึ่งจะรีเฟรชการลงชื่อเข้าใช้ด้วยตัวมันเอง เซิร์ฟเวอร์ MCP ที่คุณมีเมื่อบัญชีถูกเพิ่มจะตามไปยังบัญชีนั้นด้วย แต่ตัวที่คุณเพิ่มภายหลังด้วย `claude mcp add` จะไปถึงเฉพาะบัญชีที่คุณเพิ่มพวกมันในนั้นเท่านั้น Claude Desktop และเครื่องมือที่กำหนดค่าด้วยพาธสัมบูรณ์ไปยังไบนารี CLI จะไม่ตามการสลับไป `CLAUDE_CONFIG_DIR`, `CODEX_HOME` หรือ `GROK_HOME` ที่ระบุอย่างชัดเจนจะมีความสำคัญเหนือกว่าบัญชีที่เลือกไว้

### การวินิจฉัยการขัดข้อง

Omarchy เฝ้าดู systemd-coredump สำหรับการขัดข้องของโปรเซส เมื่อบางสิ่งเกิด segfault คุณจะได้รับการแจ้งเตือน "Process crashed" — คลิกมัน และความขัดข้องจะถูกส่งมอบให้เอเจนต์เริ่มต้นของคุณพร้อมกับทักษะ diagnose-crash ของ Omarchy ซึ่งจะนำเอเจนต์ผ่านการสร้างข้อเท็จจริงจาก core dump และการตัดสินใจว่าความขัดข้องนั้นคุ้มค่าที่จะรายงานไปยังต้นทางหรือไม่ คุณยังสามารถรันมันด้วยตนเองกับ PID ใด ๆ จาก `coredumpctl list` ด้วย `omarchy agent crash <pid>` ได้อีกด้วย

การเฝ้าดูเปิดอยู่โดยค่าเริ่มต้น ปิดมันภายใต้ _Trigger > Toggle > Crash Capture_ (หรือด้วย `omarchy toggle crash-capture`) และการแจ้งเตือนจะหยุด; `omarchy agent crash <pid>` ยังคงใช้งานได้ด้วยตนเอง

การขัดข้องยังสามารถถูกปิดเสียงได้ทีละโปรแกรม ซึ่งเป็นสิ่งที่การวินิจฉัยเสนอให้คุณในตอนท้าย `omarchy crash mute hyprland` หยุดการแจ้งเตือนสำหรับโปรแกรมนั้นเท่านั้น `omarchy crash mute hyprland off` นำพวกมันกลับมา และ `omarchy crash mute` เพียงลำพังจะแสดงรายการสิ่งที่คุณได้ปิดเสียงไว้ มันรับพาธของไบนารีได้พอ ๆ กับชื่อของมัน ดังนั้น `omarchy crash mute /usr/bin/hyprland` จึงทำสิ่งเดียวกัน ใส่ชื่อที่มีช่องว่างในเครื่องหมายคำพูด เช่นใน `omarchy crash mute 'Some App'` ทุกอย่างอื่นยังคงแจ้งเตือนอยู่ และโปรแกรมที่ปิดเสียงก็ยังคงขัดข้อง — สิ่งนี้ซ่อนการเตือนความจำ ไม่ได้แก้ไขอะไรเลย

### แอปบนเดสก์ท็อป

เมนู _Install > AI_ ยังมีแอป AI แบบกราฟิกอยู่สองสามตัว: แอปเดสก์ท็อป ChatGPT, แอปเดสก์ท็อป Claude (เบต้า Linux ของ Anthropic พร้อมแท็บ Chat, Cowork และ Claude Code), Grok Bot สำหรับแชตกับโมเดลของ xAI, Hermes Desktop, OpenClaw, แอปเดสก์ท็อป Perplexity และ T3 Code Grok Bot คือแอปแชตบนเดสก์ท็อป ส่วนเอเจนต์เขียนโค้ดคือคำสั่ง `grok`

Hermes Desktop เป็นตัวที่ต้องรู้ไว้ เพราะเครื่องหนึ่งเครื่องมี Hermes เพียงหนึ่งเดียว และมันเป็นของแอป: Hermes ถูกติดตั้งผ่านแอปเท่านั้นเสมอ และคำสั่ง `hermes` ที่เอเจนต์เริ่มต้นรันคือคำสั่งของแอป การเลือก Hermes เป็นเอเจนต์เริ่มต้นจะติดตั้งสิ่งเดียวกับที่รายการ _Install > AI_ ติดตั้ง: ตัวแพ็กเกจ และรันไทม์ Hermes ภายใต้ `~/.hermes` ที่ติดตั้งโดยตัวติดตั้งของ Hermes เอง ซึ่งใช้เวลาสองสามนาทีในครั้งแรก รันไทม์นั้นคือ Hermes เดียวกันที่คำสั่ง `hermes` ในเทอร์มินัล เอเจนต์เริ่มต้น และแอปทั้งหมดใช้ และมันอัปเดตตัวเองด้วย `hermes update` แทนที่จะรอการออก Omarchy รุ่นใหม่ การติดตั้งมันยังมอบธีม Omarchy ให้ Hermes เป็นสกินชื่อ `omarchy` ซึ่งทุกพื้นผิวของ Hermes จะทำตามเมื่อคุณสลับธีม; เลือกอันอื่นภายใต้การตั้งค่า Appearance ของ Hermes หรือด้วย `/skin` หากคุณอยากให้มันไม่ทำเช่นนั้น และ Omarchy จะปล่อยตัวเลือกนั้นไว้ตามเดิม การลบแอปภายใต้ _Remove > AI_ จะปิด Hermes ก่อน รวม gateway ด้วย นำรันไทม์นั้นไปด้วย และเก็บการแชต ความทรงจำ และทักษะที่ Hermes เขียนขึ้นให้ตัวเองของคุณไว้ เว้นแต่คุณจะบอกเป็นอย่างอื่น: มันจะถาม โดยค่าเริ่มต้นเป็นไม่ ว่าข้อมูลนั้นและการตั้งค่าการเชื่อมต่อของคุณควรจะไปพร้อมกันด้วยหรือไม่

ประสบการณ์เดสก์ท็อปของ OpenClaw คือ Control UI ของมัน ซึ่งเปิดเป็นเว็บแอปที่รองรับโดย gateway ในเครื่องของมันเอง OpenClaw อาศัยอยู่ใน `~/.openclaw` และอัปเดตตัวเอง: ใช้ปุ่ม "Update Gateway" ของ Control UI หรือรัน `openclaw update` และ gateway จะรีสตาร์ตบนเวอร์ชันใหม่ Omarchy เลือกเฉพาะรุ่นที่การติดตั้งใหม่จะเริ่มจากเท่านั้น การลบ OpenClaw ภายใต้ _Remove > AI_ จะนำบริการ gateway และแอปไปด้วย แล้วจึงถามว่า `~/.openclaw` ควรจะไปพร้อมกันด้วยหรือไม่ เนื่องจากนั่นเก็บการแชตและข้อมูลรับรองของคุณไว้เคียงข้าง OpenClaw เองและรันไทม์ปลั๊กอินที่มันดาวน์โหลด; ค่าเริ่มต้นจะเก็บมันไว้ และการติดตั้ง OpenClaw อีกครั้งจะหยิบมันกลับขึ้นมา

T3 Code รันจากรุ่น AppImage อย่างเป็นทางการของมันใน `~/.local/share/t3code` แทนที่จะมาจากแพ็กเกจ ดังนั้นมันจึงอัปเดตตัวเอง การติดตั้งมันจะถามว่าจะเริ่มบนช่อง Stable หรือ Nightly; สลับภายหลังได้ในการตั้งค่าของ T3 Code เธรดและการตั้งค่าของคุณอาศัยอยู่ใน `~/.t3` และการลบ T3 Code ภายใต้ _Remove > AI_ จะนำพวกมันไปด้วย

### โมเดลแบบโลคัล

รันโมเดลแบบเปิดบนเครื่องของคุณเองสำหรับเอเจนต์เขียนโค้ดของคุณ พรอมต์และโค้ดของคุณยังคงอยู่บนเครื่อง; ไม่มีอะไรที่ส่งไปยังโมเดลออกจากเครื่องเลย เริ่มต้นด้วย:

```bash
omarchy agent local use best
```

หรือ ในแผงเอเจนต์ในแถบบนสุด เลือก + แล้ว Local AI ซึ่งจะปรากฏขึ้นเมื่อโมเดลเหมาะกับเครื่องนี้ ครั้งแรก การดำเนินการนี้จะติดตั้ง Podman ซึ่งรันโมเดลต่าง ๆ จากนั้น Omarchy จะเลือกโมเดลที่แนะนำสำหรับเครื่องนี้ ดาวน์โหลดมัน และเริ่มมัน คาดว่าจะมีการดาวน์โหลดหลายสิบ GB และหน่วยความจำส่วนใหญ่ของเครื่องจะถูกใช้ขณะโมเดลทำงาน: Flash Next ใช้ประมาณ 100 GiB พร้อมบริบท 256K เต็มรูปแบบ หากโมเดลอื่น ๆ ถือครองหน่วยความจำที่มันต้องการอยู่ มันจะถูกตั้งค่าไว้ในสถานะหยุด พร้อมที่จะเริ่มเมื่อคุณหยุดโมเดลตัวหนึ่ง โมเดลจะหยุดเมื่อออกจากระบบ; หยุดมันด้วยตัวเองเมื่อคุณต้องการหน่วยความจำสำหรับสิ่งอื่น

`omarchy agent local list` แสดงตัวเลือกและอธิบายว่าทำไมบางตัวจึงไม่เหมาะสม หากต้องการตั้งค่าอีกตัว ให้รัน `omarchy agent local use <recipe>` วันนี้ `qwen3.8-flash-next-halogen` และ `qwen3.8-27b-gufo` พร้อมใช้งานสำหรับเครื่อง Strix Halo ขนาด 128 GB สูตรใหม่และคำแนะนำมาพร้อมกับ `omarchy update` ผ่านแพ็กเกจ

โมเดลทุกตัวที่คุณตั้งค่าจะได้รับบรรทัดของตัวเองในแผงเอเจนต์ ถัดจากการสมัครใช้งานของคุณ: เล่นเพื่อเริ่มมัน หยุดชั่วคราวเพื่อหยุดมันและปลดปล่อยหน่วยความจำของมัน และปุ่มเทอร์มินัลเพื่อเปิดเอเจนต์ของคุณบนมัน หลายตัวสามารถทำงานพร้อมกันได้เมื่อพวกมันพอดีในหน่วยความจำด้วยกัน; หากตัวหนึ่งไม่พอดี Omarchy จะบอกว่าให้หยุดโมเดลที่กำลังทำงานตัวใด ลากบรรทัดเพื่อจัดเรียงใหม่ และกด Delete บนบรรทัดที่เลือกเพื่อลบโมเดลและการดาวน์โหลดของมัน

จากบรรทัดคำสั่ง `omarchy agent local start <recipe>` และ `omarchy agent local stop <recipe>` ทำสิ่งเดียวกัน `omarchy agent local status` แสดงโมเดลทุกตัว และ `omarchy agent --local` เปิดเอเจนต์เริ่มต้นของคุณบนโมเดลตัวสุดท้ายที่คุณเริ่ม (pi หากเอเจนต์เริ่มต้นของคุณไม่สามารถใช้โมเดลแบบโลคัลได้) ไคลเอนต์ที่เข้ากันได้กับ OpenAI ใด ๆ ก็สามารถเชื่อมต่อได้เช่นกัน: `status` แสดงที่อยู่ของแต่ละโมเดล (ตัวแรกคือ `http://127.0.0.1:11435/v1`) ชื่อสูตรคือโมเดล และคีย์อยู่ใน `~/.config/omarchy/agent-local/key`

`omarchy agent local remove <recipe>` ลบโมเดลและการดาวน์โหลดที่ไม่มีโมเดลอื่นใช้งาน

รันไทม์ของบุคคลที่สามจะถูกระบุด้วยผู้เผยแพร่ของพวกมัน Omarchy รันทุกโมเดลโดยไม่มีการเข้าถึงเครือข่าย

### LLM แบบโลคัล

Omarchy แนะนำสองวิธีในการรันโมเดล LLM แบบโลคัล: LM Studio และ Ollama LM Studio จัดเตรียมอินเทอร์เฟซ GUI สำหรับการค้นหาโมเดลแบบ open-weight ติดตั้งพวกมัน และรันพวกมัน เป็นวิธีที่ยอดเยี่ยมในการเริ่มต้นได้อย่างง่ายดาย Ollama นำเสนอ CLI สำหรับทำสิ่งเดียวกันในทำนองเดียวกัน แต่หากคุณยังใหม่กับโมเดลแบบโลคัล ฉันจะเริ่มด้วย LM Studio คุณสามารถติดตั้งตัวใดตัวหนึ่งภายใต้ _Install > AI_ ใน Omarchy Menu

### Omarchy Skill

ทักษะของเอเจนต์ช่วยให้ AI ใช้เครื่องมือเฉพาะในวิธีเฉพาะ และ Omarchy มาพร้อมกับทักษะเริ่มต้นสำหรับการปรับแต่งระบบ เหมือนกับการปรับแต่งการกำหนดค่า Hyprland ของคุณ ปรับแถบ หรือแม้แต่การสร้างธีมใหม่ตั้งแต่ต้น มันถูกซิมลิงก์เข้าไปในไดเรกทอรีทักษะสำหรับ Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` และแต่ละ `~/.hermes/profiles/*/skills`) และตำแหน่งทั่วไป `~/.agents/skills` ดังนั้น harness ส่วนใหญ่จึงหยิบมันขึ้นมาโดยอัตโนมัติ

แต่คุณควรถือว่าทักษะนี้เป็นการทดลอง โมเดลที่แตกต่างกันจะใช้มันให้ผลที่แตกต่างกัน ทางที่ดีที่สุดคือรันในโหมดวางแผนก่อน เพื่อที่คุณจะได้ทราบว่าเอเจนต์อยากเปลี่ยนแปลงอะไร แล้วจึงเตรียมพร้อมที่จะย้อนกลับการเปลี่ยนแปลง หรือแม้กระทั่งเรียกใช้ `omarchy reinstall configs` หากเอเจนต์ทำให้ทุกอย่างยุ่งเหยิงไปหมด
