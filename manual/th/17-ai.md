### การติดตั้งและอัปเดตเอเจนต์

ยกเว้น Hermes เอเจนต์เหล่านี้ใช้การติดตั้งแบบขี้เกียจของ mise: การเรียกใช้ครั้งแรกจะติดตั้ง CLI และการเรียกใช้ครั้งต่อ ๆ ไปจะใช้ชุดที่ติดตั้งไว้ mise ยังตรวจสอบเอเจนต์ที่ติดตั้งไว้ว่ามีรุ่นใหม่หรือไม่ อย่างมากที่สุดหนึ่งครั้งทุกสี่ชั่วโมง ทันทีก่อนเริ่มเอเจนต์หรือในเบื้องหลังที่พรอมต์ของเชลล์ ถ้าการอัปเดตนั้นล้มเหลวหรือคุณออฟไลน์ รุ่นที่ติดตั้งไว้จะทำงานแทน `omarchy update` จะอัปเดตเอเจนต์ที่ติดตั้งไว้พร้อมกับส่วนอื่น ๆ ของ Omarchy และ `mup` จะอัปเดตเฉพาะเครื่องมือที่จัดการโดย mise เท่านั้น

ตัวอัปเดตของเอเจนต์เอง เช่น `claude update`, `codex update` หรือปุ่มอัปเดตในแอป จะไม่อัปเดตชุดที่จัดการโดย mise `codex update` จะล้มเหลว และ `claude update` อาจรายงานว่าสำเร็จในขณะที่ติดตั้งสำเนาแยกต่างหากที่ mise ไม่ได้ติดตาม ถ้าคุณอยากใช้ตัวติดตั้งและตัวอัปเดตของเอเจนต์เองมากกว่า ให้เพิ่มเอเจนต์นั้นลงใน `disable_tools`; ดู [Preinstalled CLI tools](18-development-tools.md#preinstalled-cli-tools)

เพื่อติดตั้งเครื่องมือแบบขี้เกียจที่ตั้งค่าไว้ทั้งหมดก่อนที่คุณจะต้องการใช้ ให้รัน `mise install --include-lazy` ซึ่งรวมถึงเครื่องมือ CLI เริ่มต้นตัวอื่น ๆ ของ Omarchy ด้วยเช่นเดียวกับเอเจนต์ต่าง ๆ ดู [Preinstalled CLI tools](18-development-tools.md#preinstalled-cli-tools) สำหรับการติดตั้งเครื่องมือเพียงตัวเดียวหรือใช้ชุดที่คุณติดตั้งเอง

`grok` ถูกติดตั้งผ่านแพ็กเกจ `grok` ของ mise เอง ในแบบเดียวกับ `claude` และ `codex` ให้รัน `grok` หรือเลือกมันภายใต้ _Agent > Harness_ อย่าใช้ตัวติดตั้งแบบ `curl | bash` บน x.ai เพราะเส้นทางนั้นจะใส่สำเนาที่สองไว้ใน `~/.grok/bin` เพิ่มมันไว้หน้าสุดบน `PATH` และเขียนทับตัวห่อหุ้มของ Omarchy

`dsh` จะเปิด UI บนเบราว์เซอร์ของมันที่ `127.0.0.1:3080` โดยใช้ไดเรกทอรีที่เรียกใช้เป็นพื้นที่ทำงานเริ่มต้น UI บนเบราว์เซอร์ของมันไม่รับพรอมต์เริ่มต้น ดังนั้น `omarchy agent prompt` จะเปิดมันพร้อมพรอมต์บนคลิปบอร์ดของคุณให้วาง Omarchy เริ่มมันด้วยชุดสิทธิ์แบบไม่ต้องขออนุมัติของ DeepSeek DeepSeek Harness จะอัปโหลดบันทึกเซสชันไปยัง DeepSeek เมื่อคุณใช้ API โมเดลทางการของมัน; ปิดสิ่งนี้ได้ภายใต้ _Settings > General > Upload Session Log_ ใน UI บนเบราว์เซอร์ของมัน ข้อเสนอแนะที่คุณส่งให้มันก็จะถูกอัปโหลดไปพร้อมกับเซสชันด้วย เว้นแต่คุณจะเริ่มมันด้วย `DSH_TELEMETRY_MODE=DISABLED`

### เอเจนต์เริ่มต้น

เลือกเอเจนต์เริ่มต้นของคุณด้วย `omarchy default agent <name>` หรือภายใต้ _Agent > Harness_ ใน Omarchy Menu (`Super + Space`) ถ้ายังไม่ได้ติดตั้งเอเจนต์นั้น การเลือกมันจะติดตั้งให้ก่อน Omarchy ที่ติดตั้งใหม่จะชวนคุณตัดสินใจเลือกนี้ด้วยการแจ้งเตือนเพียงครั้งเดียว

การเลือก Claude จะพยายามตั้งค่าส่วนขยายเบราว์เซอร์ของมันสำหรับ Chromium, Chrome, Brave, Brave Origin และ Edge ด้วย การตั้งค่าส่วนขยายจะใช้กับผู้ใช้ทุกคนและอาจขอรหัสผ่านระบบของคุณ; การยกเลิกหรือการติดตั้งส่วนขยายที่ล้มเหลวก็ยังคงเลือกและเปิด Claude อยู่ดี รีสตาร์ทเบราว์เซอร์ของคุณ เปิดใช้งานส่วนขยายหากระบบขอ และลงชื่อเข้าใช้ Claude เพื่อเชื่อมต่อให้เสร็จ รัน `/chrome` ใน Claude เพื่อตรวจสอบการเชื่อมต่อ Firefox และ Zen ไม่รองรับส่วนขยายนี้ ถ้า Claude เคยเป็นค่าเริ่มต้นของคุณอยู่แล้วก่อนที่จะเพิ่มการตั้งค่านี้เข้าไป ให้เลือกมันอีกครั้งเพื่อติดตั้งส่วนขยาย

เมื่อคุณเลือกแล้ว `Super + Shift + Ctrl + A` จะเปิดเอเจนต์เริ่มต้นในหน้าต่างเทอร์มินัลเฉพาะ (หรือเปิดตัวเลือกหากคุณยังไม่ได้เลือก) คุณยังสามารถเปิดมันเข้าไปทำงานทันทีได้ด้วย `omarchy agent prompt "Review this project"` Freebuff และ DeepSeek Harness ไม่รับพรอมต์เริ่มต้น ดังนั้นพวกมันจะเปิดพร้อมพรอมต์บนคลิปบอร์ดของคุณให้วางแทน เอเจนต์ที่เปิดด้วยวิธีนี้จะทำงานโดยไม่มีคนดูแลในโหมดไม่ต้องหยุดถามของแต่ละตัว ดังนั้นจงเตรียมใจว่ามันจะลงมือทำสิ่งต่าง ๆ จริง ๆ! MiniMax Code ไม่มีโหมดดังกล่าวสำหรับเซสชันแบบโต้ตอบของมัน ดังนั้นมันจะขอสิทธิ์ตามปกติ และเนื่องจากเอเจนต์ปฏิเสธที่จะจดจำความไว้วางใจสำหรับไดเรกทอรีบ้านของคุณ การเรียกใช้จาก `$HOME` จะไปเริ่มใน `~/Work` แทน

ยังมีทางลัดในเทอร์มินัลด้วย: `a` จะรันเอเจนต์เริ่มต้นในเทอร์มินัลปัจจุบันแบบอินไลน์ ขณะที่ `c`, `cx` และ `cy` จะเริ่ม OpenCode, Claude Code และ Codex โดยตรง (ในโหมดอนุมัติอัตโนมัติของพวกมันอีกเช่นกัน) การเปลี่ยนธีมจะซิงค์ไปยังเอเจนต์ต่าง ๆ ด้วย: Claude Code, Pi, OpenCode และ Hermes (เมื่อ Omarchy ติดตั้งมันแล้ว) จะเปลี่ยนตามทั้งหมดเมื่อคุณสลับธีมของ Omarchy

### คำแนะนำสำหรับเอเจนต์ของคุณ

กฎส่วนตัวสำหรับทุกเอเจนต์จะอยู่ใน `~/.agents/AGENTS.md` ข้าง ๆ สกิลที่ใช้ร่วมกันใน `~/.agents/skills` เปิดมันได้ภายใต้ _Agent > Instructions_ ซึ่งยังเชื่อมมันเข้าไปในแต่ละฮาร์เนสที่เก็บไฟล์โกลบอลของตัวเองไว้: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` ของ Copilot และอื่น ๆ ในทำนองเดียวกัน Crush และ Amp อ่านลิงก์ `~/.config/AGENTS.md` ขณะที่ omp, Kimi และ DeepSeek Harness อ่าน `~/.agents/AGENTS.md` โดยตรง การเลือกเอเจนต์เริ่มต้นก็จะเชื่อมมันด้วยเช่นกัน ไฟล์คำแนะนำที่คุณมีอยู่แล้วจะกลายเป็นไฟล์ที่ใช้ร่วมกันหากยังไม่มีไฟล์ดังกล่าวอยู่; มิฉะนั้นมันจะถูกเก็บไว้ข้าง ๆ ลิงก์ในชื่อ `.bak` รัน `omarchy agent instructions` เพื่อเชื่อมใหม่หลังติดตั้งเอเจนต์อีกตัว

### แผงเอเจนต์

แถบบนสุดมีไอคอนเอเจนต์ ก่อนที่คุณจะตั้งค่าเอเจนต์ แผงของมันจะพาคุณลงชื่อเข้าใช้ Claude, Codex หรือ Grok และตัวแรกจะกลายเป็นเอเจนต์เริ่มต้นของคุณ หลังจากนั้น แผงจะวางการสมัครสมาชิกทุกอันไว้ในหน้าเดียว: เอเจนต์และบัญชีแต่ละรายการพร้อมแผนของมัน มิเตอร์สำหรับขีดจำกัดเซสชัน 5 ชั่วโมงและรายสัปดาห์แต่ละอย่างพร้อมเวลาจนกว่าจะรีเซ็ต (ชี้เมาส์ค้างเพื่อดูเปอร์เซ็นต์ที่แน่นอน) หรือยอดเงินแบบเติมเงินคงเหลือ ภายใต้บรรทัดหนึ่งที่หมุนเวียนสิ่งที่คุณใช้ไปในทุกเอเจนต์เหล่านั้น เช่น โทเค็นในสัปดาห์นี้และโมเดลที่คุณใช้มากที่สุด ภายใต้ _Make something_ มันเสนอพรอมต์เริ่มต้นสำหรับธีม ปลั๊กอิน หรือแอปใหม่ที่จะมอบงานให้เอเจนต์เริ่มต้นของคุณ แอปถูกสร้างในแบบเดียวกับ Hype, Monologue และ Omacut ของ Omarchy เอง คือใน C++ และ Qt Quick ทำตามสกิลเอเจนต์ omarchy-app และคอมไพเลอร์กับชิ้นส่วน Qt ที่พวกมันต้องการก็ติดตั้งมาให้แล้ว Claude Code, Codex, Grok, Kimi, Cursor และโควต้า Grok Bot ของมัน, GitHub Copilot, Muse, Antigravity, Kimchi และ Devin ได้รับการครอบคลุมมาตั้งแต่แรกพร้อมขีดจำกัดของพวกมัน และ Hermes, Mistral Vibe และ Qwen Code จะแสดงเซสชันและโทเค็นของพวกมันเมื่อคุณได้ใช้งานแล้ว แผนและคีย์ของผู้ให้บริการที่คุณใช้ผ่าน pi, omp หรือ opencode ก็จะแสดงขึ้นมาด้วย: OpenCode Zen และ Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan และ Synthetic พร้อมขีดจำกัดของพวกมัน; Fireworks, OpenRouter และ DeepSeek พร้อมยอดเงินแบบเติมเงินของพวกมัน; และโมเดลที่คุณรันบนฮาร์ดแวร์ของคุณเองภายใต้ Local models ทุกเอเจนต์จะถูกนับเพียงครั้งเดียว ภายใต้ผู้ที่เรียกเก็บเงินจากมัน ไม่ว่าคุณจะขับมันผ่านฮาร์เนสกี่ตัวก็ตาม

คลิกซ้ายที่ไอคอนบนแถบเพื่อเปิดแผง คลิกขวาเพื่อเปิดเอเจนต์เริ่มต้นของคุณ บันทึกการใช้งานที่อยู่เบื้องหลังมันจะถูกสร้างใหม่ทุก 15 นาทีโดย `omarchy agent usage-update` และแผงยังสามารถรวมการใช้งานจากเครื่องอื่น ๆ ของคุณผ่านโฟลเดอร์ที่ซิงค์ไว้ได้ด้วย ดู README ภายใต้ `$OMARCHY_PATH/shell/plugins/agents/` สำหรับการตั้งค่าเต็มรูปแบบ

### การสมัครสมาชิกหลายรายการ

ถ้าคุณจ่ายเงินให้แผน Claude, Codex หรือ Grok มากกว่าหนึ่งแผน — เช่นแผน Max ส่วนตัวและอีกแผนสำหรับงาน — Omarchy สามารถให้แผนทั้งหมดลงชื่อเข้าใช้ไว้และย้ายไปมาระหว่างกันได้ เพิ่มการสมัครสมาชิกด้วยเครื่องหมาย + ในแผงเอเจนต์ ซึ่งจะพาคุณทำขั้นตอนนั้นตรงนั้นเลย หรือด้วย `omarchy agent account add claude Work` (หรือ `codex` หรือ `grok`) มันจะติดตั้ง CLI หากยังไม่มี บัญชีแรกสำหรับผู้ให้บริการรายหนึ่งจะลงชื่อเข้าใช้ผ่านเบราว์เซอร์ปกติของคุณ ตรงตำแหน่งที่ CLI คอยมองหาเสมอ ทุกบัญชีหลังจากนั้นจะลงชื่อเข้าใช้ผ่านหน้าต่างส่วนตัว เพื่อไม่ให้บัญชีที่เบราว์เซอร์ของคุณลงชื่อเข้าใช้อยู่แล้วถูกหยิบมาโดยไม่ตั้งใจ; ให้ลงชื่อเข้าใช้ที่นั่นด้วยบัญชีที่คุณกำลังเพิ่ม และปิดหน้าต่างส่วนตัวใด ๆ ที่คุณเปิดค้างอยู่ก่อน ห้ามออกจากระบบใน CLI เพื่อทำสิ่งนี้เป็นอันขาด: การออกจากระบบจะเพิกถอนการลงชื่อเข้าใช้ที่บันทึกไว้ และบัญชีนั้นจะต้องถูกเพิ่มใหม่อีกครั้ง

เพื่อคัดลอกการเข้าสู่ระบบการสมัครสมาชิกของคุณไปยังเครื่อง Omarchy อีกเครื่องผ่าน SSH ให้รัน `omarchy agent account copy user@laptop` ผู้ส่งจะจัดหาตัวรับชั่วคราวให้เมื่อปลายทางยังไม่ได้ติดตั้งไว้ ดังนั้นเครื่อง Omarchy รุ่นเก่ากว่าสามารถรับบัญชีได้โดยไม่ต้องอัปเดต ตัวรับที่ติดตั้งไว้จะมีความสำคัญเหนือกว่า สิ่งนี้จะคัดลอกการสมัครสมาชิก Claude, Codex และ Grok ทั้งหมด; เพิ่มชื่อผู้ให้บริการเพื่อเลือกพวกมัน เช่นใน `omarchy agent account copy laptop claude` ชื่อบัญชีและ ID คำสั่งจะตรงกับต้นทาง รวมถึงบัญชีที่มีอยู่แล้วบนปลายทาง บัญชีปลายทางที่ไม่เกี่ยวข้องกันจะได้รับคำต่อท้ายเป็นตัวเลขหากชื่อของพวกมันชนกัน และการตั้งค่า สกิล ปลั๊กอิน และประวัติการสนทนาจะยังคงอยู่เฉพาะบนแต่ละเครื่อง

ข้อมูลเข้าสู่ระบบปลายทางที่มีอยู่จะถูกเก็บไว้ บัญชีต้นทางที่ลงชื่อเข้าใช้อยู่ที่นั่นแล้วจะมีชื่อซิงค์ให้โดยไม่แทนที่ข้อมูลเข้าสู่ระบบของมัน; บัญชีอื่น ๆ จะถูกเพิ่มเข้าไปควบคู่กัน เพื่อแทนที่ข้อมูลเข้าสู่ระบบที่บันทึกไว้สำหรับบัญชีที่ตรงกัน ให้ใช้ `omarchy agent account copy --replace laptop claude` หลังจากออกจากเซสชันของบัญชีนั้นบนปลายทางแล้ว ปลายทางใหม่เอี่ยมยังจะได้รับบัญชีที่กำลังใช้งานและค่ากำหนดการสลับบัญชีของต้นทางด้วย; ปลายทางที่ใช้งานมานานแล้วจะเก็บของตัวเองไว้

ข้อมูลเข้าสู่ระบบจะเดินทางผ่าน SSH และถูกเก็บในไฟล์ส่วนตัวบนปลายทาง ดังนั้นจึงควรคัดลอกไปยังเครื่องที่คุณไว้ใจเท่านั้น นี่เป็นการคัดลอกครั้งเดียว ไม่ใช่การซิงโครไนซ์อย่างต่อเนื่อง โทเค็นรีเฟรชของ Codex สามารถถูกหมุนเวียนโดยเครื่องอื่นได้ ทำให้การเข้าสู่ระบบที่คัดลอกมาต้องต่ออายุใหม่; การลงชื่อเข้าใช้แยกกันยังคงเป็นตัวเลือกที่น่าเชื่อถือที่สุดสำหรับการใช้งานพร้อมกันบนหลายเครื่อง ดู [คำแนะนำการยืนยันตัวตนบัญชีของ Codex](https://developers.openai.com/codex/auth/ci-cd-auth)

มีบัญชีเพียงหนึ่งบัญชีต่อผู้ให้บริการหนึ่งรายที่กำลังใช้งานอยู่ และทุกเซสชันใหม่จะเริ่มเป็นบัญชีนั้น: `cx`, `cy`, `claude`, `codex` หรือ `grok` แบบธรรมดา สิ่งใดก็ตามที่เปิดผ่าน `omarchy agent` และสคริปต์หรือตัวแก้ไขที่ค้นพบ CLI บน `PATH` ให้สลับด้วย `omarchy agent account use work` (และกลับด้วย `omarchy agent account use main`) หรือในแผงโดยกดหมายเลขของบัญชีแล้วกด `Enter` (หรือคลิกปุ่ม Use ของมัน) เซสชันที่กำลังทำงานอยู่แล้วจะยังคงอยู่บนบัญชีที่พวกมันเริ่มด้วย ประวัติการสนทนา การตั้งค่า สกิล และปลั๊กอินถูกใช้ร่วมกันข้ามบัญชี ดังนั้น `claude --continue` ในโฟลเดอร์เดียวกันจะสานต่อจากจุดที่คุณหยุดไว้บนบัญชีใหม่

เมื่อมีมากกว่าหนึ่งบัญชี แผงจะแสดงขีดจำกัดของแต่ละบัญชีเคียงข้างกัน โดยบัญชีที่กำลังใช้งานอยู่จะถูกทำเครื่องหมายไว้ ตามค่าเริ่มต้น Omarchy จะแจ้งเตือนคุณเมื่อบัญชีที่กำลังใช้งานอยู่ผ่าน 95% ของขีดจำกัด และการคลิกการแจ้งเตือนนั้นจะสลับไปยังบัญชีที่มีพื้นที่เหลือมากที่สุด ชี้เมาส์ค้างบนบรรทัดของบัญชีหนึ่งในแผงและคลิก Autoswitch ที่ปรากฏข้าง ๆ Use (หรือกด `m`) หรือรัน `omarchy agent account mode auto` เพื่อให้มันสลับเองแทน; ขณะที่มันเปิดอยู่ Autoswitch จะเข้ามาแทนที่ Use และการคลิกมันอีกครั้งจะกลับไปเป็นการแจ้งเตือน เพิ่มตัวเลขเพื่อเปลี่ยนเกณฑ์ เช่นใน `omarchy agent account mode auto 90` ถ้าทุกบัญชีเกินเกณฑ์ คุณจะได้รับแจ้งเกี่ยวกับเรื่องนี้เพียงครั้งเดียว พร้อมกับบัญชีใดจะว่างก่อน ขณะที่บัญชีที่กำลังใช้งานอยู่ห่างจากเกณฑ์ไม่เกิน 15 จุด (80% ที่ค่าเริ่มต้น) ขีดจำกัดของมันจะถูกตรวจสอบทุกสามนาทีแทนที่จะเป็นทุก 15 นาที

`omarchy agent account list` แสดงทุกบัญชีและขีดจำกัดล่าสุดของพวกมัน `omarchy agent account remove work` ลบบัญชีหนึ่งออกไป และ `omarchy agent account rename primary Hey` เปลี่ยนชื่อบัญชีหนึ่ง (หรือคลิกชื่อของบัญชีในแผง) คำสั่งเหล่านี้ทำงานกับบัญชีของเอเจนต์เริ่มต้นของคุณ; เพื่อเข้าถึงผู้ให้บริการอีกราย ให้ระบุชื่อมันก่อน เช่นใน `omarchy agent account use codex side` การเข้าสู่ระบบที่คุณมีอยู่แล้วใน `~/.claude` หรือ `~/.codex` คือบัญชี _Main_ และจะอยู่ตรงที่ของมันเดิม บัญชีที่ไม่ได้ใช้งานนานกว่าประมาณแปดชั่วโมงอาจแสดง _Sign-in required_; คลิกมันเพื่อลงชื่อบัญชีนั้นเข้าใช้อีกครั้งได้ในแผงเลย หรือเริ่มเซสชันในบัญชีนั้น ซึ่งจะรีเฟรชการลงชื่อเข้าใช้ด้วยตัวมันเอง เซิร์ฟเวอร์ MCP ที่คุณมีเมื่อตอนที่บัญชีถูกเพิ่มเข้ามาจะตามไปยังบัญชีนั้นด้วย แต่เซิร์ฟเวอร์ที่คุณเพิ่มในภายหลังด้วย `claude mcp add` จะไปถึงเฉพาะบัญชีที่คุณเพิ่มมันเข้าไปเท่านั้น Claude Desktop และเครื่องมือที่ตั้งค่าด้วยพาธสัมบูรณ์ไปยังไบนารี CLI จะไม่ตามการสลับไปด้วย `CLAUDE_CONFIG_DIR`, `CODEX_HOME` หรือ `GROK_HOME` ที่ระบุอย่างชัดเจนจะมีความสำคัญเหนือบัญชีที่เลือกไว้

### การวินิจฉัยการแครช

Omarchy เฝ้าดู systemd-coredump เพื่อหาการแครชของกระบวนการ เมื่อมีบางอย่างเกิด segfault คุณจะได้รับการแจ้งเตือน "Process crashed" — คลิกมัน แล้วการแครชจะถูกส่งให้เอเจนต์เริ่มต้นของคุณพร้อมกับสกิล diagnose-crash ของ Omarchy ซึ่งจะพาเอเจนต์ไล่ตรวจสอบข้อเท็จจริงจาก core dump และตัดสินใจว่าการแครชนั้นคุ้มค่าที่จะรายงานไปยัง upstream หรือไม่ คุณยังสามารถรันมันด้วยมือกับ PID ใด ๆ จาก `coredumpctl list` ได้ด้วย `omarchy agent crash <pid>`

การเฝ้าดูเปิดอยู่ตามค่าเริ่มต้น ปิดมันได้ภายใต้ _Trigger > Toggle > Crash Capture_ (หรือด้วย `omarchy toggle crash-capture`) แล้วการแจ้งเตือนจะหยุด; `omarchy agent crash <pid>` ยังคงทำงานด้วยมือได้

การแครชยังสามารถถูกปิดเสียงได้ครั้งละหนึ่งโปรแกรม ซึ่งเป็นสิ่งที่การวินิจฉัยเสนอให้คุณในตอนท้าย `omarchy crash mute hyprland` หยุดการแจ้งเตือนสำหรับโปรแกรมนั้นเท่านั้น `omarchy crash mute hyprland off` นำมันกลับมา และ `omarchy crash mute` ด้วยตัวมันเองเพียงอย่างเดียวจะแสดงรายการสิ่งที่คุณได้ปิดเสียงไว้ มันรับพาธของไบนารีได้เป็นอย่างดีพอ ๆ กับชื่อ ดังนั้น `omarchy crash mute /usr/bin/hyprland` จึงทำสิ่งเดียวกัน ใส่เครื่องหมายคำพูดครอบชื่อที่มีช่องว่าง เช่นใน `omarchy crash mute 'Some App'` ส่วนโปรแกรมอื่น ๆ ทุกตัวยังคงแจ้งเตือน และโปรแกรมที่ถูกปิดเสียงก็ยังคงแครชอยู่ — สิ่งนี้ซ่อนการเตือนความจำ มันไม่ได้แก้ไขอะไรเลย

### แอปเดสก์ท็อป

เมนู _Install > AI_ ยังมีแอป AI แบบกราฟิกอยู่สองสามตัวด้วย: แอปเดสก์ท็อป ChatGPT, แอปเดสก์ท็อป Claude (รุ่นเบต้าสำหรับ Linux ของ Anthropic พร้อมแท็บ Chat, Cowork และ Claude Code), Grok Bot สำหรับแชทกับโมเดลของ xAI, Herdr Desktop, Hermes Desktop, OpenClaw, แอปเดสก์ท็อป Perplexity และ T3 Code Grok Bot คือแอปแชทบนเดสก์ท็อป ส่วนเอเจนต์เขียนโค้ดคือคำสั่ง `grok`

Hermes Desktop เป็นตัวที่ต้องรู้ไว้ เพราะเครื่องหนึ่งเครื่องจะมี Hermes เดียว และ Hermes นั้นเป็นของแอป: Hermes จะถูกติดตั้งผ่านแอปเท่านั้นตลอดไป และคำสั่ง `hermes` ที่เอเจนต์เริ่มต้นรันก็เป็นของแอป การเลือก Hermes เป็นเอเจนต์เริ่มต้นจะติดตั้งสิ่งเดียวกับที่รายการ _Install > AI_ ติดตั้ง: แพ็กเกจ และรันไทม์ของ Hermes ภายใต้ `~/.hermes` ที่ตั้งค่าโดยตัวติดตั้งของ Hermes เอง ซึ่งใช้เวลาสองสามนาทีในครั้งแรก รันไทม์นั้นคือ Hermes ตัวเดียวที่คำสั่ง `hermes` ในเทอร์มินัล เอเจนต์เริ่มต้น และแอปใช้ร่วมกัน และมันอัปเดตตัวเองด้วย `hermes update` แทนที่จะรอการเปิดตัวของ Omarchy การติดตั้งมันยังมอบธีม Omarchy ให้ Hermes เป็นสกินชื่อ `omarchy` ซึ่งทุกพื้นผิวของ Hermes จะทำตามเมื่อคุณสลับธีม; เลือกอย่างอื่นภายใต้การตั้งค่า Appearance ของ Hermes หรือด้วย `/skin` หากคุณไม่อยากให้มันทำเช่นนั้น และ Omarchy จะปล่อยตัวเลือกนั้นไว้ตามลำพัง การลบแอปภายใต้ _Remove > AI_ จะปิด Hermes ก่อน รวมถึง gateway ด้วย นำรันไทม์นั้นไปกับมัน และเก็บแชท ความทรงจำ และสกิลที่ Hermes เขียนขึ้นให้ตัวเองไว้ เว้นแต่คุณจะบอกเป็นอย่างอื่น: มันจะถาม โดยค่าเริ่มต้นคือไม่ ว่าข้อมูลนั้นและการตั้งค่าการเชื่อมต่อของคุณควรจะไปด้วยหรือไม่

ประสบการณ์เดสก์ท็อปของ OpenClaw คือ Control UI ของมัน ซึ่งเปิดเป็นเว็บแอปที่ได้รับการสนับสนุนจาก gateway โลคัลของตัวมันเอง OpenClaw อาศัยอยู่ใน `~/.openclaw` และอัปเดตตัวเอง: ใช้ปุ่ม "Update Gateway" ของ Control UI หรือรัน `openclaw update` แล้ว gateway จะรีสตาร์ทบนเวอร์ชันใหม่ Omarchy เลือกเพียงรุ่นที่การติดตั้งใหม่จะเริ่มใช้เท่านั้น การลบ OpenClaw ภายใต้ _Remove > AI_ จะนำบริการ gateway และแอปไปด้วย จากนั้นจะถามว่า `~/.openclaw` ควรจะไปด้วยหรือไม่ เนื่องจากที่นั่นเก็บแชทและข้อมูลเข้าสู่ระบบของคุณไว้ควบคู่ไปกับตัว OpenClaw เองและรันไทม์ปลั๊กอินที่มันดาวน์โหลดมา; ค่าเริ่มต้นคือเก็บมันไว้ และการติดตั้ง OpenClaw อีกครั้งจะหยิบมันกลับมาใช้อีก

Herdr Desktop คือแอปเดสก์ท็อป [Herdr](https://herdr.dev): สเปซ แท็บ และเพนของเทอร์มินัลและเอเจนต์เขียนโค้ดที่ยังคงทำงานอยู่ในแกนหลักของมันเมื่อคุณปิดหน้าต่าง มันมาจากตัวติดตั้งของ Herdr เองแทนที่จะเป็นแพ็กเกจ ดังนั้นมันจึงอาศัยอยู่ใน `~/.local/share/herdr-app` นำแกนหลักของมันมาไว้ใน `~/.local/bin/herdr-core` เมื่อคุณยังไม่มี และอัปเดตตัวเองทั้งสองอย่าง มันอยู่ข้าง ๆ คำสั่ง `herdr` ที่ Omarchy ส่งมาบน `Super + Ctrl + Return` แทนที่จะมาแทนที่ และรับปุ่มตรงของคำสั่งนั้น: `Alt + Return` และ `Alt + Shift + Return` แยกเพนลงหรือไปขวา `Alt + Escape` ปิดมัน `Ctrl + Alt + Arrow` ย้ายระหว่างเพน `Alt + 1..9` และ `Alt + Left/Right` เลือกแท็บ และ `Alt + Up/Down` ย้ายระหว่างสเปซ `Ctrl + 1..9` เลือกสเปซ และ `Alt + Shift + Up/Down` ก้าวผ่านเอเจนต์ต่าง ๆ ปุ่มคำนำหน้า `Ctrl + Space` ยังคงเป็นเฉพาะในเทอร์มินัลเท่านั้น เนื่องจากแอปไม่สามารถกดปุ่ม Ctrl ธรรมดาค้างไว้สำหรับลำดับปุ่มได้ Omarchy เขียนปุ่มเหล่านี้ลงใน `~/.config/herdr-app/keys.json` และ `omarchy-refresh-herdr-app` จะใส่พวกมันกลับคืน การติดตั้งมันจะเลือกธีม Omarchy ของ Herdr ซึ่งจะทำตามธีม Omarchy ของคุณนับจากนั้นเป็นต้นไป Herdr เก็บธีมหนึ่งไว้สำหรับโหมดสว่างและอีกหนึ่งสำหรับโหมดมืด ดังนั้นหลังจากสลับระหว่างธีม Omarchy แบบมืดและแบบสว่าง ให้เลือก Omarchy ในตัวเลือกธีมของ Herdr อีกครั้งสำหรับอีกโหมดหนึ่ง

T3 Code ทำงานจากรุ่น AppImage ทางการของมันใน `~/.local/share/t3code` แทนที่จะมาจากแพ็กเกจ ดังนั้นมันจึงอัปเดตตัวเอง การติดตั้งมันจะถามว่าจะเริ่มในช่อง Stable หรือ Nightly; สลับในภายหลังได้ในการตั้งค่าของ T3 Code เธรดและการตั้งค่าของคุณอาศัยอยู่ใน `~/.t3` และการลบ T3 Code ภายใต้ _Remove > AI_ จะนำพวกมันไปด้วย

### โมเดลบนเครื่อง

รันโมเดลเปิดบนเครื่องของคุณเองสำหรับเอเจนต์เขียนโค้ดของคุณ พรอมต์และโค้ดของคุณยังคงอยู่บนเครื่อง; ไม่มีอะไรที่ส่งไปยังโมเดลออกจากเครื่องเลย เริ่มด้วย:

```bash
omarchy agent local use best
```

หรือ ในแผงเอเจนต์ในแถบบนสุด เลือก + แล้วเลือก Local AI ซึ่งจะแสดงขึ้นเมื่อโมเดลเหมาะกับเครื่องนี้ ครั้งแรก การทำเช่นนี้จะติดตั้ง Podman ซึ่งรันโมเดลต่าง ๆ และบนเครื่อง NVIDIA จะติดตั้งชุดเครื่องมือคอนเทนเนอร์ของ NVIDIA ซึ่งให้โมเดลเข้าถึง GPU จากนั้น Omarchy จะเลือกโมเดลที่แนะนำสำหรับเครื่องนี้ ดาวน์โหลดมัน และเริ่มมัน คาดหวังการดาวน์โหลดหลายสิบ GB และหน่วยความจำของเครื่องส่วนใหญ่จะถูกใช้งานขณะที่โมเดลทำงาน: Flash Next ใช้ประมาณ 100 GiB กับบริบทเต็ม 256K ของมัน ถ้าโมเดลอื่น ๆ ครองหน่วยความจำที่มันต้องการอยู่ มันจะถูกตั้งค่าในสถานะหยุด พร้อมเริ่มเมื่อคุณหยุดโมเดลหนึ่งลง โมเดลจะหยุดเมื่อออกจากระบบ; ให้หยุดมันด้วยตัวเองเมื่อคุณต้องการหน่วยความจำสำหรับอย่างอื่น

`omarchy agent local list` แสดงตัวเลือกต่าง ๆ และอธิบายว่าทำไมบางตัวจึงไม่พอดี เพื่อตั้งค่าตัวอื่นอีกตัว ให้รัน `omarchy agent local use <recipe>` ปัจจุบัน `qwen3.8-flash-next-gufo` และ `qwen3.8-27b-gufo` มีให้ใช้สำหรับเครื่อง Strix Halo ขนาด 128 GB; ตัว 27B ใช้ประมาณ 40 GiB ดังนั้นมันจึงเหลือพื้นที่สำหรับงานอื่น สูตรและการแนะนำใหม่ ๆ จะมาถึงพร้อมกับ `omarchy update` ผ่านแพ็กเกจ

โมเดลทุกตัวที่คุณตั้งค่าจะได้รับบรรทัดของตัวเองในแผงเอเจนต์ ข้าง ๆ การสมัครสมาชิกของคุณ: กดเล่นเพื่อเริ่มมัน หยุดชั่วคราวเพื่อหยุดมันและคืนหน่วยความจำของมัน และปุ่มเทอร์มินัลเพื่อเปิดเอเจนต์ของคุณบนมัน หลายตัวสามารถทำงานพร้อมกันได้เมื่อพวกมันพอดีในหน่วยความจำร่วมกัน; ถ้าตัวหนึ่งไม่พอดี Omarchy จะบอกว่าต้องหยุดโมเดลที่กำลังทำงานตัวใด ลากบรรทัดเพื่อจัดลำดับพวกมันใหม่ และกด Delete บนบรรทัดที่เลือกเพื่อลบโมเดลและการดาวน์โหลดของมัน

จากบรรทัดคำสั่ง `omarchy agent local start <recipe>` และ `omarchy agent local stop <recipe>` ทำสิ่งเดียวกัน `omarchy agent local status` แสดงโมเดลทุกตัว และ `omarchy agent --local` เปิดเอเจนต์เริ่มต้นของคุณบนโมเดลตัวสุดท้ายที่คุณเริ่ม (pi หากเอเจนต์เริ่มต้นของคุณใช้โมเดลบนเครื่องไม่ได้) ไคลเอนต์ที่เข้ากันได้กับ OpenAI ใด ๆ สามารถเชื่อมต่อได้เช่นกัน: `status` แสดงที่อยู่ของแต่ละโมเดล (ตัวแรกคือ `http://127.0.0.1:11435/v1`) ชื่อสูตรคือโมเดล และคีย์อยู่ใน `~/.config/omarchy/agent-local/key`

`omarchy agent local remove <recipe>` ลบโมเดลและการดาวน์โหลดที่ไม่มีโมเดลอื่นใช้

รันไทม์ของบุคคลที่สามจะถูกติดป้ายด้วยผู้เผยแพร่ของพวกมัน Omarchy รันโมเดลทุกตัวโดยไม่มีการเข้าถึงเครือข่าย

### LLM บนเครื่อง

Omarchy แนะนำสองวิธีในการรันโมเดล LLM บนเครื่อง: LM Studio และ Ollama LM Studio ให้อินเทอร์เฟซแบบ GUI สำหรับการค้นหาโมเดลแบบ open-weight ติดตั้งพวกมัน และรันพวกมัน เป็นวิธีที่ดีเยี่ยมในการเริ่มต้นได้อย่างง่ายดาย Ollama เสนอ CLI สำหรับทำเช่นเดียวกันในลักษณะคล้าย ๆ กัน แต่ถ้าคุณเป็นมือใหม่เรื่องโมเดลบนเครื่อง ผมขอแนะนำให้เริ่มด้วย LM Studio คุณสามารถติดตั้งตัวใดตัวหนึ่งได้ภายใต้ _Install > AI_ ใน Omarchy Menu

### สกิลของ Omarchy

สกิลของเอเจนต์ช่วยให้ AI ใช้เครื่องมือเฉพาะในวิธีเฉพาะ และ Omarchy มาพร้อมสกิลเริ่มต้นสำหรับการปรับแต่งระบบ เหมือนกับการปรับแต่งการตั้งค่า Hyprland ของคุณ ปรับแถบ หรือแม้แต่การสร้างธีมใหม่ตั้งแต่ศูนย์ มันถูกเชื่อมแบบซิมลิงก์เข้าไปในไดเรกทอรีสกิลสำหรับ Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` และแต่ละ `~/.hermes/profiles/*/skills`) และตำแหน่งทั่วไป `~/.agents/skills` ดังนั้นฮาร์เนสส่วนใหญ่จึงหยิบมันขึ้นมาโดยอัตโนมัติ

แต่คุณควรปฏิบัติต่อสกิลนี้เหมือนเป็นของทดลอง โมเดลที่ต่างกันจะใช้มันให้เกิดผลต่างกัน ทางที่ดีที่สุดคือรันในโหมดวางแผนก่อน เพื่อให้คุณมีภาพว่าเอเจนต์อยากเปลี่ยนอะไร จากนั้นจงเตรียมพร้อมที่จะย้อนกลับการเปลี่ยนแปลง หรือแม้กระทั่งการเรียกใช้ `omarchy reinstall configs` หากเอเจนต์ทำให้ทุกอย่างเละเทะไปหมด
