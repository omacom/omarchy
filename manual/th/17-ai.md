### การติดตั้งและอัปเดตเอเจนต์

ยกเว้น Hermes และ OpenClaw เอเจนต์เหล่านี้ใช้การติดตั้งแบบ lazy ของ mise: การเปิดใช้ครั้งแรกจะติดตั้ง CLI และการเปิดใช้ครั้งต่อ ๆ ไปจะใช้ตัวที่ติดตั้งไว้แล้ว mise ยังตรวจสอบเอเจนต์ที่ติดตั้งไว้ว่ามีรุ่นใหม่ออกมาหรือไม่ อย่างมากที่สุดทุกสี่ชั่วโมง หนึ่งครั้ง คือช่วงก่อนที่มันจะเริ่มทำงาน หรือในเบื้องหลังขณะที่อยู่ที่พรอมต์ของเชลล์ หากการอัปเดตนั้นล้มเหลวหรือคุณออฟไลน์อยู่ รุ่นที่ติดตั้งไว้จะทำงานแทน `omarchy update` จะอัปเดตเอเจนต์ที่ติดตั้งไว้พร้อมกับส่วนที่เหลือของ Omarchy และ `mup` จะอัปเดตเฉพาะเครื่องมือที่ mise จัดการเท่านั้น

ตัวอัปเดตของเอเจนต์เอง เช่น `claude update`, `codex update` หรือปุ่มอัปเดตในแอป จะไม่อัปเดตตัวที่ติดตั้งโดย mise จัดการ `codex update` จะล้มเหลว และ `claude update` อาจรายงานว่าสำเร็จในขณะที่ติดตั้งสำเนาแยกต่างหากที่ mise ไม่ได้ติดตาม หากคุณอยากใช้ตัวติดตั้งและตัวอัปเดตแบบเนทีฟของเอเจนต์มากกว่า ให้เพิ่มมันลงใน `disable_tools`; ดู [เครื่องมือ CLI ที่ติดตั้งมาล่วงหน้า](18-development-tools.md#preinstalled-cli-tools)

หากต้องการติดตั้งเครื่องมือแบบ lazy ทั้งหมดที่กำหนดค่าไว้ก่อนที่คุณจะต้องการใช้ ให้รัน `mise install --include-lazy` ซึ่งรวมถึงเครื่องมือ CLI เริ่มต้นอื่น ๆ ของ Omarchy ด้วย นอกเหนือจากเอเจนต์ ดู [เครื่องมือ CLI ที่ติดตั้งมาล่วงหน้า](18-development-tools.md#preinstalled-cli-tools) สำหรับการติดตั้งเครื่องมือตัวเดียวหรือใช้การติดตั้งของคุณเอง

`grok` ถูกติดตั้งผ่านแพ็กเกจ `grok` แบบ first-party ของ mise ในวิธีเดียวกับ `claude` และ `codex` ให้รัน `grok` หรือติดดาวให้มันในแผงเอเจนต์ ข้ามตัวติดตั้งแบบ `curl | bash` บน x.ai ไปเลย เส้นทางนั้นจะวางสำเนาที่สองไว้ใน `~/.grok/bin`, แทรกมันไว้ด้านหน้าสุดบน `PATH` และเขียนทับตัวห่อหุ้ม (wrapper) ของ Omarchy

`dsh` จะเปิด UI บนเบราว์เซอร์ของมันที่ `127.0.0.1:3080` โดยใช้ไดเรกทอรีที่เปิดใช้เป็นพื้นที่ทำงานเริ่มต้นของมัน UI บนเบราว์เซอร์ของมันไม่รับพรอมต์เริ่มต้น ดังนั้น `omarchy agent prompt` จะเปิดมันโดยวางพรอมต์ไว้บนคลิปบอร์ดของคุณให้คุณแปะ Omarchy เริ่มมันด้วยชุดการตั้งค่าสิทธิ์แบบไม่ต้องขออนุมัติของ DeepSeek DeepSeek Harness จะอัปโหลดบันทึกเซสชันไปยัง DeepSeek เมื่อคุณใช้ API โมเดลอย่างเป็นทางการของมัน; ปิดการทำงานนั้นได้ภายใต้ _Settings > General > Upload Session Log_ ใน UI บนเบราว์เซอร์ของมัน ข้อเสนอแนะที่คุณส่งให้มันก็จะถูกอัปโหลดไปพร้อมกับเซสชันด้วยเช่นกัน เว้นแต่คุณจะเริ่มมันด้วย `DSH_TELEMETRY_MODE=DISABLED`

### เอเจนต์เริ่มต้น

เลือกเอเจนต์เริ่มต้นของคุณด้วยดาวข้างเอเจนต์ในแผงเอเจนต์ ซึ่งจะถูกเติมเต็มบนเอเจนต์เริ่มต้น หรือด้วย `omarchy default agent <name>` ซึ่งรับฮาร์เนสใด ๆ ที่ไม่มีแถวอยู่ที่นั่นด้วย หากเอเจนต์ยังไม่ได้ติดตั้ง การเลือกมันจะติดตั้งมันก่อน และมันยังจะได้ตัวเรียกใช้ของตัวเองในตัวเรียกใช้แอป ถัดจาก Agent ด้วย Omarchy ที่ติดตั้งใหม่จะเชิญคุณให้ตั้งค่าหนึ่งตัวด้วยการแจ้งเตือนเพียงครั้งเดียว ซึ่งจะเปิดแผงเอเจนต์

การเลือก Claude ยังพยายามตั้งค่าส่วนขยายเบราว์เซอร์ของมันสำหรับ Chromium, Chrome, Brave, Brave Origin และ Edge ด้วย การตั้งค่าส่วนขยายใช้กับผู้ใช้ทุกคนและอาจขอรหัสผ่านระบบของคุณ; การยกเลิกหรือการติดตั้งส่วนขยายที่ล้มเหลวก็ยังคงเลือกและเปิดใช้ Claude อยู่ดี รีสตาร์ทเบราว์เซอร์ของคุณ เปิดใช้งานส่วนขยายหากได้รับแจ้ง และลงชื่อเข้าใช้ Claude เพื่อเชื่อมต่อให้เสร็จสมบูรณ์ รัน `/chrome` ใน Claude เพื่อตรวจสอบการเชื่อมต่อ Firefox และ Zen ไม่รองรับส่วนขยายนี้ หาก Claude เป็นค่าเริ่มต้นของคุณอยู่แล้วก่อนที่การตั้งค่านี้จะถูกเพิ่มเข้ามา ให้เลือกมันอีกครั้งเพื่อติดตั้งส่วนขยาย

เมื่อคุณเลือกแล้ว `Super + Shift + Ctrl + A` จะเปิดเอเจนต์เริ่มต้นในหน้าต่างเทอร์มินัลเฉพาะ (หรือแสดงตัวเลือกหากคุณยังไม่ได้เลือก) คุณยังสามารถเปิดมันเข้าสู่งานได้โดยตรงด้วย `omarchy agent prompt "Review this project"` Freebuff และ DeepSeek Harness ไม่รับพรอมต์เริ่มต้น ดังนั้นพวกมันจะเปิดโดยวางพรอมต์ไว้บนคลิปบอร์ดของคุณให้คุณแปะแทน เอเจนต์ที่เปิดใช้ด้วยวิธีนี้จะทำงานโดยไม่มีใครดูแลในโหมดไม่หยุดถามตามแบบของแต่ละตัว ดังนั้นจงเตรียมพร้อมให้พวกมันลงมือทำจริง ๆ! MiniMax Code ไม่มีโหมดดังกล่าวสำหรับเซสชันแบบโต้ตอบของมัน ดังนั้นมันจะขออนุญาตตามปกติ และเนื่องจากเอเจนต์ปฏิเสธที่จะจดจำความไว้วางใจสำหรับไดเรกทอรีบ้านของคุณ การเปิดใช้จาก `$HOME` จะเริ่มใน `~/Work` แทน

มีทางลัดในเทอร์มินัลด้วย: `a` รันเอเจนต์เริ่มต้นแบบอินไลน์ในเทอร์มินัลปัจจุบัน ในขณะที่ `c`, `cx` และ `cy` เริ่ม OpenCode, Claude Code และ Codex โดยตรง (อีกครั้งในโหมดอนุมัติอัตโนมัติของพวกมัน) การเปลี่ยนธีมก็ซิงค์ไปยังเอเจนต์ด้วย: Claude Code, Pi, OpenCode และ Hermes (เมื่อ Omarchy ได้ติดตั้งมันแล้ว) ล้วนเปลี่ยนตามเมื่อคุณเปลี่ยนธีมของ Omarchy

### คำแนะนำสำหรับเอเจนต์ของคุณ

กฎส่วนตัวสำหรับเอเจนต์ทุกตัวอยู่ใน `~/.agents/AGENTS.md` ถัดจากสกิลที่ใช้ร่วมกันใน `~/.agents/skills` เปิดมันด้วยไอคอนเอกสารข้าง + ในแผงเอเจนต์ หรือ `omarchy agent instructions --edit` ซึ่งยังเชื่อมโยงมันเข้าไปในแต่ละฮาร์เนสที่เก็บไฟล์โกลบอลของตัวเอง: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` ของ Copilot และอื่น ๆ Crush และ Amp อ่านลิงก์ `~/.config/AGENTS.md` ในขณะที่ omp, Kimi และ DeepSeek Harness อ่าน `~/.agents/AGENTS.md` โดยตรง การเลือกเอเจนต์เริ่มต้นก็เชื่อมโยงมันด้วยเช่นกัน ไฟล์คำแนะนำที่คุณมีอยู่แล้วจะกลายเป็นไฟล์ที่ใช้ร่วมกันหากยังไม่มีไฟล์ดังกล่าวมาก่อน; มิฉะนั้นมันจะถูกเก็บไว้ข้างลิงก์ในชื่อ `.bak` รัน `omarchy agent instructions` เพื่อเชื่อมโยงใหม่หลังจากติดตั้งเอเจนต์อีกตัว

### แผงเอเจนต์

แถบด้านบนมีไอคอนเอเจนต์ ก่อนที่คุณจะตั้งค่าเอเจนต์ แผงของมันเสนอสามวิธีในการเริ่มต้น: ลงชื่อเข้าใช้การสมัครสมาชิก Claude, Codex, Grok, Gemini, Muse, Cursor หรือ Copilot หรือภายใต้ More เป็นแผนเขียนโค้ด OpenCode Go, MiniMax, Synthetic หรือ Z.ai; จ่ายตามการใช้งานด้วย Fireworks, OpenCode Zen and Go, OpenRouter หรือภายใต้ More เป็น DeepSeek หรือผู้ให้บริการรายอื่นใดที่ OpenCode ลงชื่อเข้าใช้ ซึ่งทั้งหมดทำงานใน OpenCode; หรือรันโมเดลที่ดีที่สุดสำหรับคอมพิวเตอร์ของคุณ เมื่อมีโมเดลที่เหมาะสมกับมัน ตัวแรกที่คุณทำเสร็จจะกลายเป็นเอเจนต์เริ่มต้นของคุณ และ + ในแผงจะเสนอสามวิธีเดียวกันนั้นในภายหลัง หลังจากนั้น แผงจะวางการสมัครสมาชิกทุกอย่างไว้ในหน้าเดียว: เอเจนต์และบัญชีแต่ละตัวพร้อมกับแผนของมัน มิเตอร์สำหรับขีดจำกัดเซสชัน 5 ชั่วโมงและขีดจำกัดรายสัปดาห์แต่ละรายการพร้อมกับเวลาจนกว่ามันจะรีเซ็ต (ชี้เมาส์ค้างไว้เพื่อดูเปอร์เซ็นต์ที่แน่นอน) หรือยอดคงเหลือแบบเติมเงินที่เหลืออยู่ ภายใต้แถวหนึ่งที่หมุนเวียนผ่านสิ่งที่คุณใช้ไปในทั้งหมดนั้น เช่น โทเคนในสัปดาห์นี้และโมเดลที่คุณใช้มากที่สุด ภายใต้ _Make something cool_ มันเสนอพรอมต์เริ่มต้นสำหรับธีมใหม่ ปลั๊กอิน แอป หรือเกม ที่มอบงานนั้นให้เอเจนต์เริ่มต้นของคุณ แอปถูกสร้างขึ้นในแบบเดียวกับที่ Hype, Monologue และ Omacut ของ Omarchy เองถูกสร้าง คือใน C++ และ Qt Quick โดยทำตามสกิลเอเจนต์ omarchy-make-app และคอมไพเลอร์และชิ้นส่วน Qt ที่พวกมันต้องการก็ถูกติดตั้งมาให้ เกมเป็นหน้า three.js หน้าเดียวใน `~/Games/vibes` โดยทำตามสกิลเอเจนต์ omarchy-make-game และทั้งหมดเปิดจากตัวเรียกใช้ Game Vibes ตัวเดียวในธีมปัจจุบัน; พวกมันโหลด three.js จากเว็บ ดังนั้นพวกมันต้องการการเชื่อมต่อในการเริ่มต้น Claude Code, Codex, Grok, Kimi, Cursor และโควตา Grok Bot ของมัน, GitHub Copilot, Muse, Gemini (ผ่าน Antigravity) และ Devin ได้รับการครอบคลุมมาตั้งแต่ต้นพร้อมกับขีดจำกัดของพวกมัน, Kimchi พร้อมกับแผน เงินเครดิตแบบเติมเงิน และงบประมาณการใช้จ่ายของมัน และ Hermes, Mistral Vibe และ Qwen Code จะแสดงเซสชันและโทเคนของพวกมันเมื่อคุณได้ใช้พวกมันแล้ว แผนและคีย์ของผู้ให้บริการที่คุณใช้ผ่าน pi, omp หรือ opencode ก็ปรากฏเช่นกัน: OpenCode Zen and Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan และ Synthetic พร้อมกับขีดจำกัดของพวกมัน; OpenRouter และ DeepSeek พร้อมกับยอดคงเหลือแบบเติมเงินของพวกมัน; Fireworks พร้อมกับการใช้จ่ายของมันในช่วง 30 วันที่ผ่านมา โทเคนจากโมเดลที่คุณรันบนฮาร์ดแวร์ของคุณเองก็นับรวมในยอดรวมด้วย; โมเดลเหล่านั้นเองมีแผงของตัวเอง ซึ่งอธิบายไว้ภายใต้ [โมเดลในเครื่อง](#local-models) เอเจนต์ทุกตัวถูกนับเพียงครั้งเดียว ภายใต้ผู้ที่เรียกเก็บเงินจากมัน ไม่ว่าคุณจะขับเคลื่อนมันผ่านฮาร์เนสกี่ตัวก็ตาม

คลิกซ้ายที่ไอคอนบนแถบหรือกด `Super + Ctrl + X` เพื่อเปิดแผง คลิกขวาเพื่อเปิดเอเจนต์เริ่มต้นของคุณ และคลิกกลางเพื่อรีเฟรช บันทึกการใช้งานที่อยู่เบื้องหลังมันถูกสร้างใหม่ทุก 15 นาทีโดย `omarchy agent usage update` และแผงยังสามารถรวมการใช้งานจากเครื่องอื่น ๆ ของคุณผ่านโฟลเดอร์ที่ซิงค์ไว้ได้ ดู README ภายใต้ `$OMARCHY_PATH/shell/plugins/agents/` สำหรับการตั้งค่าแบบเต็ม

### การสมัครสมาชิกหลายรายการ

หากคุณจ่ายเงินให้แผน Claude, Codex หรือ Grok มากกว่าหนึ่งแผน — เช่น Max ส่วนตัวหนึ่งแผนและแผนสำหรับงานอีกหนึ่งแผน — Omarchy สามารถให้พวกมันทั้งหมดลงชื่อเข้าใช้ไว้และย้ายไปมาระหว่างพวกมันได้ เพิ่มการสมัครสมาชิกด้วย + ในแผงเอเจนต์ ซึ่งจะแนะนำคุณตลอดขั้นตอนตรงนั้นเลย หรือด้วย `omarchy agent account add claude Work` (หรือ `codex` หรือ `grok`) + และคำสั่งเดียวกันนั้นลงชื่อเข้าใช้ Gemini (`gemini`) และ OpenCode (`opencode`) และบันทึกคีย์ API ของ Fireworks (`fireworks`) หรือ OpenRouter (`openrouter`) ใน OpenCode; คำสั่งนั้นยังลงชื่อเข้าใช้ Copilot (`copilot`), Cursor (`cursor`) และ Muse (`muse`) ด้วย สิ่งเหล่านั้นเก็บการลงชื่อเข้าใช้เพียงหนึ่งรายการต่อตัว มันจะติดตั้ง CLI หากยังไม่มี บัญชีแรกสำหรับผู้ให้บริการจะลงชื่อเข้าใช้ผ่านเบราว์เซอร์ปกติของคุณ ตรงจุดที่ CLI มองหาอยู่เสมอ ทุกบัญชีหลังจากนั้นจะลงชื่อเข้าใช้ผ่านหน้าต่างส่วนตัว ดังนั้นบัญชีที่เบราว์เซอร์ของคุณลงชื่อเข้าใช้อยู่แล้วจะไม่ถูกหยิบขึ้นมาโดยไม่ตั้งใจ; ลงชื่อเข้าใช้ที่นั่นในฐานะบัญชีที่คุณกำลังเพิ่ม และปิดหน้าต่างส่วนตัวใด ๆ ที่คุณเปิดไว้อยู่ก่อนก่อน อย่าออกจากระบบ CLI เพื่อทำสิ่งนี้เป็นอันขาด: การออกจากระบบจะเพิกถอนการลงชื่อเข้าใช้ที่บันทึกไว้ และบัญชีนั้นจะต้องถูกเพิ่มอีกครั้ง

หากต้องการคัดลอกการเข้าสู่ระบบการสมัครสมาชิกของคุณไปยังเครื่อง Omarchy อีกเครื่องผ่าน SSH ให้รัน `omarchy agent account copy user@laptop` ผู้ส่งจะจัดหาตัวรับชั่วคราวให้เมื่อปลายทางยังไม่ได้ติดตั้งตัวรับไว้ ดังนั้นเครื่อง Omarchy ที่เก่ากว่าสามารถรับบัญชีได้โดยไม่ต้องอัปเดต ตัวรับที่ติดตั้งไว้จะมีความสำคัญเหนือกว่า สิ่งนี้คัดลอกการสมัครสมาชิก Claude, Codex และ Grok ทั้งหมด; เพิ่มชื่อผู้ให้บริการเพื่อเลือกพวกมัน เช่นใน `omarchy agent account copy laptop claude` ชื่อบัญชีและ ID คำสั่งตรงกับต้นทาง รวมถึงบัญชีที่มีอยู่แล้วบนปลายทาง บัญชีปลายทางที่ไม่เกี่ยวข้องจะได้รับคำต่อท้ายที่เป็นตัวเลขหากชื่อของพวกมันขัดแย้งกัน และการตั้งค่า สกิล ปลั๊กอิน และประวัติการสนทนายังคงอยู่ในเครื่องแต่ละเครื่อง

ข้อมูลประจำตัวปลายทางที่มีอยู่จะถูกเก็บไว้ บัญชีต้นทางที่ลงชื่อเข้าใช้อยู่ที่นั่นแล้วจะมีชื่อของมันถูกซิงโครไนซ์โดยไม่แทนที่ข้อมูลประจำตัวของมัน; บัญชีอื่น ๆ จะถูกเพิ่มควบคู่ไปกับมัน หากต้องการแทนที่ข้อมูลประจำตัวที่บันทึกไว้สำหรับบัญชีที่ตรงกัน ให้ใช้ `omarchy agent account copy --replace laptop claude` หลังจากปิดเซสชันของบัญชีนั้นบนปลายทางแล้ว ปลายทางใหม่ยังจะได้รับบัญชีที่ใช้งานอยู่และการตั้งค่าการสลับของต้นทางด้วย; ปลายทางที่จัดตั้งแล้วจะเก็บของตัวเองไว้

ข้อมูลประจำตัวเดินทางผ่าน SSH และถูกเก็บไว้ในไฟล์ส่วนตัวบนปลายทาง ดังนั้นจงคัดลอกไปยังเครื่องที่คุณไว้วางใจเท่านั้น นี่เป็นการคัดลอกครั้งเดียว ไม่ใช่การซิงโครไนซ์อย่างต่อเนื่อง โทเคนรีเฟรชของ Codex สามารถถูกหมุนเวียนโดยเครื่องอื่นได้ ทำให้การเข้าสู่ระบบที่คัดลอกมาต้องต่ออายุ; การลงชื่อเข้าใช้แยกกันยังคงเป็นตัวเลือกที่เชื่อถือได้มากที่สุดสำหรับการใช้พร้อมกันบนหลายเครื่อง ดู [คำแนะนำการยืนยันตัวตนบัญชีของ Codex](https://developers.openai.com/codex/auth/ci-cd-auth)

หนึ่งบัญชีต่อผู้ให้บริการจะใช้งานอยู่ และทุกเซสชันใหม่จะเริ่มต้นในฐานะบัญชีนั้น: `cx`, `cy`, `claude`, `codex` หรือ `grok` ธรรมดา อะไรก็ตามที่เปิดใช้ผ่าน `omarchy agent` และสคริปต์หรือโปรแกรมแก้ไขที่พบ CLI บน `PATH` สลับด้วย `omarchy agent account use work` (และกลับด้วย `omarchy agent account use main`) หรือในแผงโดยกดหมายเลขของบัญชีแล้วกด `Enter` (หรือคลิกที่ดาวของมัน) เซสชัน Claude ที่กำลังทำงานอยู่ก็สลับด้วยเช่นกัน ตั้งแต่ข้อความถัดไปของพวกมัน: ทุกเซสชันของ Claude ทำงานใน `~/.claude` ซึ่งเก็บการลงชื่อเข้าใช้ของบัญชีที่ใช้งานอยู่ไว้เสมอ เซสชัน Claude ที่เริ่มต้นในโฟลเดอร์ของบัญชีเองโดย Omarchy รุ่นเก่ากว่าจะเก็บการลงชื่อเข้าใช้นั้นไว้จนกว่ามันจะออก ดังนั้นการสลับจะระบุชื่อเซสชันเหล่านั้นและเสร็จสิ้นด้วยตัวเองเมื่อพวกมันจากไปแล้ว เซสชัน Codex และ Grok ที่กำลังทำงานอยู่จะยังคงอยู่บนบัญชีที่พวกมันเริ่มต้นด้วย ประวัติการสนทนา การตั้งค่า สกิล และปลั๊กอินถูกใช้ร่วมกันข้ามบัญชี ดังนั้น `claude --continue` ในโฟลเดอร์เดียวกันจะดำเนินการต่อจากจุดที่คุณค้างไว้บนบัญชีใหม่

เมื่อมีมากกว่าหนึ่งบัญชี แผงจะแสดงขีดจำกัดของแต่ละบัญชีเคียงข้างกัน โดยมีดาวที่เติมเต็มบนตัวที่กำลังใช้งานอยู่ Omarchy จะแจ้งเตือนคุณเมื่อบัญชีที่ใช้งานอยู่ผ่าน 95% ของขีดจำกัด และการคลิกที่การแจ้งเตือนจะสลับไปยังบัญชีที่มีพื้นที่เหลือมากที่สุด มันจะไม่สลับด้วยตัวเองเป็นอันขาด เปลี่ยนเกณฑ์ด้วย `omarchy agent account threshold 90` หากทุกบัญชีเกินเกณฑ์ คุณจะได้รับแจ้งเกี่ยวกับเรื่องนั้นเพียงครั้งเดียว พร้อมกับว่าบัญชีใดจะว่างก่อน ขณะที่บัญชีที่ใช้งานอยู่ห่างจากเกณฑ์ของมันไม่เกิน 15 จุด (80% ที่ค่าเริ่มต้น) ขีดจำกัดของมันจะถูกตรวจสอบทุกสามนาทีแทนที่จะเป็นทุก 15 นาที

`omarchy agent account list` แสดงทุกบัญชีและขีดจำกัดล่าสุดของพวกมัน `omarchy agent account remove work` ลืมไปหนึ่งบัญชี และ `omarchy agent account rename primary Hey` เปลี่ยนชื่อหนึ่งบัญชี (หรือคลิกที่ชื่อบัญชีในแผง) คำสั่งเหล่านี้ทำงานกับบัญชีของเอเจนต์เริ่มต้นของคุณ; หากต้องการเข้าถึงผู้ให้บริการรายอื่น ให้ระบุชื่อมันก่อน เช่นใน `omarchy agent account use codex side` การเข้าสู่ระบบที่คุณมีอยู่แล้วใน `~/.claude` หรือ `~/.codex` คือบัญชี _Main_ ของ Codex จะยังคงอยู่ที่เดิม; ของ Claude จะรออยู่ในโฟลเดอร์ของตัวเองในขณะที่บัญชีอื่นใช้งานอยู่ บัญชีที่ไม่ได้ใช้มานานกว่าประมาณแปดชั่วโมงอาจแสดง _Sign-in required_; คลิกมันเพื่อลงชื่อบัญชีนั้นเข้าใช้อีกครั้งในแผงเลย หรือสลับไปยังมันและเริ่มเซสชัน ซึ่งจะรีเฟรชการลงชื่อเข้าใช้ด้วยตัวเอง เซิร์ฟเวอร์ MCP ที่คุณเพิ่มด้วย `claude mcp add` จะเข้าถึงทุกบัญชี Claude เนื่องจากพวกมันทั้งหมดทำงานใน `~/.claude`; สำหรับ Codex และ Grok เซิร์ฟเวอร์ที่คุณมีเมื่อบัญชีถูกเพิ่มจะตามไปยังบัญชีนั้นด้วย แต่เซิร์ฟเวอร์ในภายหลังจะเข้าถึงเฉพาะบัญชีที่คุณเพิ่มพวกมันเข้าไปเท่านั้น Claude Desktop เก็บการลงชื่อเข้าใช้ของตัวเอง และเครื่องมือ Codex หรือ Grok ที่กำหนดค่าด้วยเส้นทางสัมบูรณ์ไปยังไบนารี CLI จะไม่ตามการสลับไป ค่า `CLAUDE_CONFIG_DIR`, `CODEX_HOME` หรือ `GROK_HOME` ที่ระบุอย่างชัดเจนจะมีความสำคัญเหนือบัญชีที่เลือก

### การวินิจฉัยการขัดข้อง

Omarchy เฝ้าดู systemd-coredump เพื่อหาการขัดข้องของกระบวนการ เมื่อคุณได้เลือกเอเจนต์เริ่มต้นแล้ว โปรแกรมใด ๆ ของคุณที่ดัมพ์ core จะนำมาซึ่งการแจ้งเตือน "Process crashed" — คลิกมัน และการขัดข้องจะถูกส่งมอบให้เอเจนต์เริ่มต้นของคุณพร้อมกับสกิล omarchy-diagnose-crash ของ Omarchy ซึ่งจะแนะนำเอเจนต์ในการสร้างข้อเท็จจริงจาก core dump และตัดสินใจว่าการขัดข้องนั้นคุ้มค่าที่จะรายงานไปยังต้นทางหรือไม่ คุณยังสามารถรันมันด้วยตนเองกับ PID ใด ๆ จาก `coredumpctl list` ด้วย `omarchy agent crash <pid>` ได้

การเฝ้าดูนี้เปิดอยู่โดยค่าเริ่มต้น ปิดมันภายใต้ _Trigger > Toggle > Crash Capture Off_ (หรือด้วย `omarchy toggle crash-capture`) และการแจ้งเตือนจะหยุด; `omarchy agent crash <pid>` ยังคงทำงานด้วยตนเองได้

การขัดข้องยังสามารถถูกปิดเสียงได้ครั้งละหนึ่งโปรแกรม ซึ่งเป็นสิ่งที่การวินิจฉัยเสนอให้คุณในตอนท้าย `omarchy crash mute hyprland` หยุดการแจ้งเตือนสำหรับโปรแกรมนั้นเท่านั้น `omarchy crash mute hyprland off` นำพวกมันกลับมา และ `omarchy crash mute` เพียงอย่างเดียวจะแสดงรายการสิ่งที่คุณได้ปิดเสียงไว้ มันรับเส้นทางของไบนารีได้อย่างยินดีพอ ๆ กับชื่อของมัน ดังนั้น `omarchy crash mute /usr/bin/hyprland` จึงทำสิ่งเดียวกัน ใส่เครื่องหมายคำพูดรอบชื่อที่มีช่องว่างอยู่ในนั้น เช่นใน `omarchy crash mute 'Some App'` ทุกอย่างอื่นยังคงแจ้งเตือน และโปรแกรมที่ถูกปิดเสียงยังคงขัดข้อง — สิ่งนี้ซ่อนการเตือนความจำ มันไม่ได้แก้ไขอะไรเลย

### แอปเดสก์ท็อป

เมนู _Install > AI_ ยังมีแอป AI แบบกราฟิกอยู่สองสามตัว: Amp Desktop, Antigravity Desktop, แอปเดสก์ท็อป ChatGPT, แอปเดสก์ท็อป Claude (เบต้า Linux ของ Anthropic พร้อมแท็บ Chat, Cowork และ Claude Code), Grok Bot สำหรับแชทกับโมเดลของ xAI, Herdr Desktop, Hermes Desktop, OpenClaw, แอปเดสก์ท็อป Perplexity และ T3 Code Grok Bot คือแอปแชทบนเดสก์ท็อป เอเจนต์เขียนโค้ดคือคำสั่ง `grok`

Hermes Desktop เป็นตัวที่คุณต้องรู้ เพราะเครื่องหนึ่งเครื่องมี Hermes เพียงหนึ่งเดียว และมันเป็นของแอป: Hermes ถูกติดตั้งผ่านแอปเท่านั้นเสมอ และคำสั่ง `hermes` ที่เอเจนต์เริ่มต้นรันคือของแอป การเลือก Hermes เป็นเอเจนต์เริ่มต้นจะติดตั้งสิ่งเดียวกับที่รายการ _Install > AI_ ติดตั้ง: ตัวแพ็กเกจ และรันไทม์ Hermes ภายใต้ `~/.hermes` ที่ตัวติดตั้งของ Hermes เองตั้งค่าไว้ ซึ่งใช้เวลาสองสามนาทีในครั้งแรก รันไทม์นั้นคือ Hermes หนึ่งเดียวนั้นที่คำสั่ง `hermes` ในเทอร์มินัล เอเจนต์เริ่มต้น และแอปทั้งหมดใช้ และมันอัปเดตตัวเองด้วย `hermes update` แทนที่จะรอการออกเวอร์ชันของ Omarchy การติดตั้งมันยังมอบธีม Omarchy ให้ Hermes ในฐานะสกินชื่อ `omarchy` ซึ่งทุกพื้นผิวของ Hermes จะทำตามขณะที่คุณเปลี่ยนธีม; เลือกตัวอื่นภายใต้การตั้งค่า Appearance ของ Hermes หรือด้วย `/skin` หากคุณไม่อยากให้มันทำเช่นนั้น และ Omarchy จะปล่อยตัวเลือกนั้นไว้ตามลำพัง การลบแอปภายใต้ _Remove > AI_ จะปิด Hermes ก่อน รวมถึงเกตเวย์ นำรันไทม์นั้นไปด้วย และเก็บแชท ความทรงจำ และสกิลที่ Hermes เขียนให้ตัวเองไว้ เว้นแต่คุณจะบอกเป็นอย่างอื่น: มันจะถาม โดยค่าเริ่มต้นคือไม่ ว่าข้อมูลนั้นและการตั้งค่าการเชื่อมต่อของคุณควรไปด้วยหรือไม่

ประสบการณ์เดสก์ท็อปของ OpenClaw คือ Control UI ของมัน ซึ่งเปิดเป็นเว็บแอปที่ได้รับการสนับสนุนโดยเกตเวย์ในเครื่องของมันเอง OpenClaw อาศัยอยู่ใน `~/.openclaw` และอัปเดตตัวเอง: ใช้ปุ่ม "Update Gateway" ของ Control UI หรือรัน `openclaw update` และเกตเวย์จะรีสตาร์ทบนเวอร์ชันใหม่ Omarchy เพียงเลือกเวอร์ชันที่การติดตั้งใหม่จะเริ่มต้นจากเท่านั้น OpenClaw ยังสามารถเป็นเอเจนต์เริ่มต้นของคุณได้: การเลือกมันด้วย `omarchy default agent openclaw` จะตั้งค่าสำเนาเดียวกันนั้นใน `~/.openclaw` และเอเจนต์จะเปิด UI เทอร์มินัลของ OpenClaw ที่เชื่อมต่อกับเกตเวย์ของมัน การลบ OpenClaw ภายใต้ _Remove > AI_ จะนำบริการเกตเวย์และแอปไปด้วย จากนั้นถามว่า `~/.openclaw` ควรไปด้วยหรือไม่ เนื่องจากที่นั่นเก็บแชทและข้อมูลประจำตัวของคุณควบคู่ไปกับ OpenClaw เองและรันไทม์ปลั๊กอินที่มันดาวน์โหลด; ค่าเริ่มต้นจะเก็บมันไว้ และการติดตั้ง OpenClaw อีกครั้งจะหยิบมันกลับมา

Herdr Desktop คือแอปเดสก์ท็อป [Herdr](https://herdr.dev): พื้นที่ แท็บ และบานหน้าต่างของเทอร์มินัลและเอเจนต์เขียนโค้ดที่ยังคงทำงานในแกนหลักของมันเมื่อคุณปิดหน้าต่าง มันมาจากตัวติดตั้งของ Herdr เองแทนที่จะเป็นแพ็กเกจ ดังนั้นมันจึงอาศัยอยู่ใน `~/.local/share/herdr-app`, นำแกนหลักของมันมาไว้ใน `~/.local/bin/herdr-core` เมื่อคุณยังไม่มี และอัปเดตทั้งสองตัวด้วยตัวเอง มันอยู่ข้างคำสั่ง `herdr` ที่ Omarchy จัดส่งบน `Super + Ctrl + Return` แทนที่จะแทนที่มัน และได้รับคีย์โดยตรงของคำสั่งนั้น: `Alt + Return` และ `Alt + Shift + Return` แยกบานหน้าต่างลงหรือไปทางขวา `Alt + Escape` ปิดมัน `Ctrl + Alt + Arrow` ย้ายระหว่างบานหน้าต่าง `Alt + 1..9` และ `Alt + Left/Right` เลือกแท็บ และ `Alt + Up/Down` ย้ายระหว่างพื้นที่ `Ctrl + 1..9` เลือกพื้นที่ และ `Alt + Shift + Up/Down` ก้าวผ่านเอเจนต์ คีย์คำนำหน้า `Ctrl + Space` ยังคงเป็นของเทอร์มินัลเท่านั้น เนื่องจากแอปไม่สามารถถือคีย์ Ctrl ธรรมดาไว้สำหรับลำดับได้ Omarchy เขียนสิ่งเหล่านี้ไปยัง `~/.config/herdr-app/keys.json` และ `omarchy-refresh-herdr-app` จะนำพวกมันกลับมา การติดตั้งมันจะเลือกธีม Omarchy ของ Herdr ซึ่งทำตามธีม Omarchy ของคุณนับจากนั้นเป็นต้นไป Herdr เก็บธีมหนึ่งธีมสำหรับโหมดสว่างและอีกหนึ่งสำหรับโหมดมืด ดังนั้นหลังจากสลับระหว่างธีม Omarchy แบบมืดและแบบสว่าง ให้เลือก Omarchy ในตัวเลือกธีมของ Herdr อีกครั้งสำหรับโหมดอื่น

T3 Code ทำงานจากเวอร์ชัน AppImage อย่างเป็นทางการของมันใน `~/.local/share/t3code` แทนที่จะมาจากแพ็กเกจ ดังนั้นมันจึงอัปเดตตัวเอง การติดตั้งมันจะถามว่าจะเริ่มบนช่อง Stable หรือ Nightly; สลับในภายหลังในการตั้งค่าของ T3 Code เธรดและการตั้งค่าของคุณอาศัยอยู่ใน `~/.t3` และการลบ T3 Code ภายใต้ _Remove > AI_ จะนำพวกมันไปด้วย

### โมเดลในเครื่อง

รันโมเดลแบบเปิดบนเครื่องของคุณเองสำหรับเอเจนต์เขียนโค้ดของคุณ พรอมต์และโค้ดของคุณยังคงอยู่บนเครื่อง; ไม่มีอะไรที่ส่งไปยังโมเดลที่จะออกจากเครื่อง เริ่มต้นด้วย:

```bash
omarchy models use best text
```

นั่นตั้งค่าโมเดลข้อความที่ดีที่สุดสำหรับเครื่องนี้ ซึ่งเป็นชนิดที่เอเจนต์ของคุณใช้ โมเดลรูปภาพ วิดีโอ และเพลงมีตัวที่ดีที่สุดของตัวเอง: `omarchy models use best image`, `video` หรือ `music` รัน `omarchy models use best` เพื่อดูตัวเลือกของแต่ละชนิดสำหรับเครื่องนี้

หรือเปิดแผงโมเดลในเครื่องจากไอคอนประกายของมันในแถบด้านบน ถัดจากไอคอนเอเจนต์ หรือด้วย Super + Ctrl + Alt + X และเลือก + ไอคอนจะปรากฏเมื่อมีโมเดลที่เหมาะสมกับเครื่องนี้ Podman ซึ่งรันโมเดล มาพร้อมกับ Omarchy เช่นเดียวกับชุดเครื่องมือคอนเทนเนอร์ของ NVIDIA บนเครื่อง NVIDIA ซึ่งให้ GPU แก่พวกมัน; หากอย่างใดอย่างหนึ่งขาดหายไป การตั้งค่าครั้งแรกจะติดตั้งมัน Omarchy จากนั้นจะเลือกโมเดลที่แนะนำสำหรับเครื่องนี้ ดาวน์โหลดมัน และเริ่มมัน คาดว่าจะมีการดาวน์โหลดหลายสิบ GB และหน่วยความจำส่วนใหญ่ของเครื่องจะถูกใช้ในขณะที่โมเดลทำงาน: Flash Next ใช้ประมาณ 100 GiB กับบริบท 256K เต็มรูปแบบของมัน หากโมเดลอื่น ๆ ยึดหน่วยความจำที่มันต้องการไว้ มันจะถูกตั้งค่าไว้ในสถานะหยุด พร้อมที่จะเริ่มเมื่อคุณหยุดโมเดลหนึ่งตัว โมเดลจะหยุดเมื่อออกจากระบบ; หยุดมันด้วยตัวเองเมื่อคุณต้องการหน่วยความจำสำหรับอย่างอื่น

`omarchy models list` แสดงตัวเลือกและอธิบายว่าทำไมบางตัวจึงไม่เหมาะสม หากต้องการตั้งค่าอีกตัวหนึ่ง ให้รัน `omarchy models use <recipe>` วันนี้ `qwen3.8-flash-next-gufo` และ `qwen3.8-27b-gufo` พร้อมใช้งานสำหรับเครื่อง Strix Halo 128 GB; ตัว 27B ใช้ประมาณ 40 GiB ดังนั้นมันจึงเหลือพื้นที่สำหรับงานอื่น บนแล็ปท็อป 64 GB ที่มี Arc B390 ของ Intel, `qwen3.6-35b-a3b-llamacpp` ทำงานในประมาณ 30 GiB สูตรและคำแนะนำใหม่ ๆ มาพร้อมกับ `omarchy update` ผ่านทางแพ็กเกจ

ทุกโมเดลที่คุณตั้งค่าจะได้แถวของตัวเองในแผงโมเดลในเครื่อง: เล่นเพื่อเริ่มมัน หยุดชั่วคราวเพื่อหยุดมันและปลดปล่อยหน่วยความจำของมัน และปุ่มเทอร์มินัลเพื่อเปิดเอเจนต์ของคุณบนมัน ข้ามด้านบน แถบหนึ่งแสดงให้เห็นว่าหน่วยความจำของเครื่องถูกแบ่งระหว่าง Omarchy เอง (ระบบและแอปของคุณ) โมเดลที่กำลังทำงานแต่ละตัว และสิ่งที่ว่างอยู่อย่างไร ชี้ไปที่โมเดลที่หยุดอยู่และแถบจะแสดงว่ามันเหมาะสมหรือไม่ หรือมันขาดไปเท่าไร หลายตัวสามารถทำงานพร้อมกันได้เมื่อพวกมันพอดีในหน่วยความจำด้วยกัน; หากตัวหนึ่งไม่พอดี Omarchy จะบอกว่าโมเดลที่กำลังทำงานตัวใดให้หยุด ลากแถวโดยโลโก้ของพวกมันเพื่อจัดเรียงใหม่ และกด Delete บนแถวที่เลือกเพื่อลบโมเดลและการดาวน์โหลดของมัน

ทุกโมเดลเขียนโค้ดที่คุณตั้งค่ายังได้รายการของตัวเองในตัวเรียกใช้แอป ภายใต้ชื่อของโมเดลและพร้อมโลโก้ของผู้สร้างมัน ในแบบเดียวกับการลงชื่อเข้าใช้ Claude, Codex หรือ Grok จะเพิ่มหนึ่งรายการ มันเปิดเอเจนต์ของคุณบนโมเดลนั้น และเริ่มโมเดลก่อนหากมันยังไม่ได้ทำงาน: เทอร์มินัลจะแสดงมันกำลังโหลดและส่งมอบให้เอเจนต์เมื่อมันพร้อม การลบโมเดลจะลบรายการของมัน

ไม่ใช่ทุกโมเดลที่มีไว้สำหรับเขียนโค้ด โมเดลรูปภาพ วิดีโอ และเพลงเปิดใน Fantasi แทน ซึ่งเป็นแอปของ Omarchy สำหรับสร้างรูปภาพ วิดีโอ และเพลงด้วยโมเดลที่ทำงานบนเครื่องนี้ โดยเลือกที่นั่นหรือจากแถวของพวกมันในแผงโมเดลในเครื่อง

โมเดลยังคงทำงานต่อไปอย่างที่มันถูกตั้งค่าไว้ ดังนั้นการอัปเดต Omarchy จะไม่รีสตาร์ทโมเดลภายใต้เอเจนต์ของคุณ เมื่อ Omarchy มีรันไทม์ที่ใหม่กว่าหรือน้ำหนักที่ใหม่กว่าสำหรับโมเดลที่คุณได้ตั้งค่าไว้ แถวของมันจะแสดงปุ่มอัปเดต: กดมันและโมเดลจะถูกตั้งค่าอีกครั้งในเบื้องหลัง โดยดาวน์โหลดเฉพาะสิ่งที่เปลี่ยนแปลง และรีสตาร์ทบนเวอร์ชันใหม่ โมเดลที่หยุดอยู่จะยังคงหยุดอยู่ `omarchy models update` ทำเช่นเดียวกันสำหรับทุกโมเดลจากเทอร์มินัล

จากบรรทัดคำสั่ง `omarchy models start <recipe>` และ `omarchy models stop <recipe>` ทำเช่นเดียวกัน `omarchy models status` แสดงทุกโมเดล และ `omarchy agent --local-model <recipe>` เปิดโมเดลนั้นใน pi ไม่ว่าเอเจนต์เริ่มต้นของคุณจะเป็นอะไร หากต้องการทำให้โมเดลในเครื่องของคุณเป็นสิ่งที่ปุ่มลัดเอเจนต์ คอนโซล Quake และ _Make something_ เปิด ให้รัน `omarchy default agent local` หรือติดดาวโมเดลที่กำลังทำงานอยู่ในแผงเอเจนต์ pi ยังแสดงรายการทุกโมเดลที่คุณได้ตั้งค่าไว้ และโมเดลเหล่านั้นบนเครื่องที่คุณจับคู่ด้วย ในตัวเลือกโมเดลของมันเอง ดังนั้น `pi` ธรรมดาก็เข้าถึงพวกมันได้เช่นกัน ไคลเอนต์ที่เข้ากันได้กับ OpenAI ใด ๆ ก็สามารถเชื่อมต่อได้เช่นกัน: `status` แสดงที่อยู่ของแต่ละโมเดล (ตัวแรกคือ `http://127.0.0.1:11435/v1`) ชื่อสูตรคือโมเดล และคีย์อยู่ใน `~/.config/omarchy/agent-local/key`

`omarchy models remove <recipe>` ลบโมเดลและการดาวน์โหลดที่ไม่มีโมเดลอื่นใช้

รันไทม์ของบุคคลที่สามถูกติดป้ายด้วยผู้เผยแพร่ของพวกมัน Omarchy รันทุกโมเดลโดยไม่มีการเข้าถึงเครือข่าย

### LLM ในเครื่อง

Omarchy แนะนำสองวิธีในการรันโมเดล LLM ในเครื่อง: LM Studio และ Ollama LM Studio ให้อินเทอร์เฟซ GUI สำหรับค้นหาโมเดลแบบ open-weight ติดตั้งพวกมัน และรันพวกมัน มันเป็นวิธีที่ดีเยี่ยมในการเริ่มต้นได้อย่างง่ายดาย Ollama เสนอ CLI สำหรับทำเช่นเดียวกัน แต่ถ้าคุณเพิ่งเริ่มใช้โมเดลในเครื่อง ผมขอแนะนำให้เริ่มด้วย LM Studio คุณสามารถติดตั้งตัวใดตัวหนึ่งได้ภายใต้ _Install > AI_ ใน Omarchy Menu

### สกิลของ Omarchy

สกิลเอเจนต์ช่วยให้ AI ใช้เครื่องมือเฉพาะในวิธีเฉพาะ และ Omarchy จัดส่งพวกมันมาเจ็ดตัว สกิล omarchy ครอบคลุมการปรับแต่งระบบ เช่น การปรับ config Hyprland ของคุณหรือการปรับแถบ omarchy-make-theme, omarchy-make-plugin, omarchy-make-app และ omarchy-make-game ครอบคลุมการสร้างสิ่งใหม่ omarchy-contribute ครอบคลุมการรายงานบั๊กหรือการส่งการแก้ไขไปยังต้นทาง และ omarchy-diagnose-crash จะดำเนินการผ่าน core dump ของการขัดข้อง พวกมันถูกทำซิมลิงก์เข้าไปในไดเรกทอรีสกิลสำหรับ Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` และแต่ละ `~/.hermes/profiles/*/skills`) และตำแหน่งทั่วไป `~/.agents/skills` ดังนั้นฮาร์เนสส่วนใหญ่จึงหยิบพวกมันขึ้นมาโดยอัตโนมัติ โฟลเดอร์สกิลของคุณเองที่มีชื่อเดียวกันจะมีความสำคัญเหนือกว่า

แต่คุณควรปฏิบัติต่อสกิลเหล่านี้ในฐานะงานทดลอง โมเดลต่าง ๆ จะใช้มันให้เกิดผลต่างกัน ดีที่สุดคือรันในโหมดวางแผนก่อน เพื่อให้คุณมีไอเดียว่าเอเจนต์อยากเปลี่ยนอะไร จากนั้นเตรียมพร้อมที่จะย้อนกลับการเปลี่ยนแปลงหรือแม้แต่เรียกใช้ `omarchy reinstall configs` หากเอเจนต์ทำทุกอย่างพังเละเทะ
