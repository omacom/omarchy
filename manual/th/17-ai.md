### การติดตั้งและอัปเดต agent

นอกจาก Hermes และ OpenClaw แล้ว agent เหล่านี้ใช้การติดตั้งแบบ lazy ของ mise: การเปิดใช้ครั้งแรกจะติดตั้ง CLI และครั้งต่อ ๆ ไปจะใช้ตัวที่ติดตั้งไว้แล้ว mise ยังตรวจสอบ agent ที่ติดตั้งแล้วว่ามีรุ่นใหม่หรือไม่ อย่างมากที่สุดหนึ่งครั้งทุกสี่ชั่วโมง ก่อนที่มันจะเริ่มทำงาน หรือในเบื้องหลังที่ shell prompt หากการอัปเดตนั้นล้มเหลวหรือคุณออฟไลน์อยู่ รุ่นที่ติดตั้งไว้จะทำงาน `omarchy update` จะอัปเดต agent ที่ติดตั้งแล้วไปพร้อมกับส่วนอื่น ๆ ของ Omarchy และ `mup` จะอัปเดตเฉพาะเครื่องมือที่จัดการโดย mise เท่านั้น

ตัวอัปเดตของ agent เอง เช่น `claude update`, `codex update` หรือปุ่มอัปเดตในแอป ไม่ได้อัปเดตสิ่งที่ติดตั้งไว้ซึ่งจัดการโดย mise `codex update` จะล้มเหลว และ `claude update` อาจรายงานว่าสำเร็จในขณะที่ติดตั้งสำเนาแยกต่างหากที่ mise ไม่ได้ติดตาม หากคุณต้องการใช้ installer และตัวอัปเดตดั้งเดิมของ agent มากกว่า ให้เพิ่มมันลงใน `disable_tools`; ดู [เครื่องมือ CLI ที่ติดตั้งไว้ล่วงหน้า](18-development-tools.md#preinstalled-cli-tools)

หากต้องการติดตั้ง lazy tool ที่กำหนดค่าไว้ทั้งหมดก่อนที่คุณจะต้องการใช้ ให้รัน `mise install --include-lazy` ซึ่งรวมถึงเครื่องมือ CLI เริ่มต้นอื่น ๆ ของ Omarchy รวมถึง agent ต่าง ๆ ด้วย ดู [เครื่องมือ CLI ที่ติดตั้งไว้ล่วงหน้า](18-development-tools.md#preinstalled-cli-tools) สำหรับการติดตั้งเครื่องมือเพียงตัวเดียวหรือการใช้การติดตั้งของคุณเอง

`grok` ติดตั้งผ่าน package `grok` อย่างเป็นทางการของ mise ในลักษณะเดียวกับ `claude` และ `codex` รัน `grok` หรือเลือกมันใต้ _Agent > Harness_ อย่าใช้ installer แบบ `curl | bash` บน x.ai เส้นทางนั้นจะวางสำเนาที่สองไว้ใน `~/.grok/bin` เพิ่มมันไว้หน้าสุดบน `PATH` และเขียนทับ wrapper ของ Omarchy

`dsh` เปิด browser UI ของมันบน `127.0.0.1:3080` โดยมีไดเรกทอรีที่เปิดใช้เป็น workspace เริ่มต้น browser UI ของมันไม่รับ prompt เริ่มต้น ดังนั้น `omarchy agent prompt` จะเปิดมันโดยมี prompt อยู่บน clipboard ของคุณให้วาง Omarchy เริ่มมันด้วย permission preset แบบ no-approval ของ DeepSeek DeepSeek Harness จะอัปโหลด session log ไปยัง DeepSeek เมื่อคุณใช้ model API อย่างเป็นทางการของมัน; ปิดการทำงานนี้ได้ใต้ _Settings > General > Upload Session Log_ ใน browser UI ของมัน ความคิดเห็นที่คุณส่งให้มันจะถูกอัปโหลดไปพร้อมกับ session ด้วย เว้นแต่คุณจะเริ่มมันด้วย `DSH_TELEMETRY_MODE=DISABLED`

### Agent เริ่มต้น

เลือก agent เริ่มต้นของคุณด้วย `omarchy default agent <name>` หรือใต้ _Agent > Harness_ ใน Omarchy Menu (`Super + Space`) หาก agent นั้นยังไม่ได้ติดตั้ง การเลือกมันจะติดตั้งมันก่อน และมันจะได้ launcher ของตัวเองใน app launcher ข้าง ๆ Agent ด้วย Omarchy ที่ติดตั้งใหม่จะเชิญคุณให้เลือกนี้ด้วย notification แบบครั้งเดียว

การเลือก Claude ยังพยายามตั้งค่า browser extension ของมันสำหรับ Chromium, Chrome, Brave, Brave Origin และ Edge ด้วย การตั้งค่า extension นี้ใช้กับผู้ใช้ทุกคนและอาจขอรหัสผ่านระบบของคุณ; การยกเลิกหรือการติดตั้ง extension ที่ล้มเหลวก็ยังคงเลือกและเปิด Claude ต่อไป รีสตาร์ทเบราว์เซอร์ของคุณ เปิดใช้งาน extension หากระบบแจ้ง และลงชื่อเข้าใช้ Claude เพื่อเชื่อมต่อให้เสร็จสมบูรณ์ รัน `/chrome` ใน Claude เพื่อตรวจสอบการเชื่อมต่อ Firefox และ Zen ไม่รองรับ extension นี้ หาก Claude เป็นค่าเริ่มต้นของคุณอยู่แล้วก่อนที่จะมีการเพิ่มการตั้งค่านี้ ให้เลือกมันอีกครั้งเพื่อติดตั้ง extension

เมื่อคุณเลือกแล้ว `Super + Shift + Ctrl + A` จะเปิด agent เริ่มต้นในหน้าต่าง terminal แยกต่างหาก (หรือเปิดตัวเลือกขึ้นมาหากคุณยังไม่ได้เลือก) คุณยังสามารถเปิดมันเข้าสู่งานโดยตรงด้วย `omarchy agent prompt "Review this project"` ได้ Freebuff และ DeepSeek Harness ไม่รับ prompt เริ่มต้น ดังนั้นมันจะเปิดโดยมี prompt อยู่บน clipboard ของคุณให้วางแทน agent ที่เปิดด้วยวิธีนี้จะทำงานโดยไม่มีผู้ดูแลในโหมด don't-stop-to-ask ตามลำดับของแต่ละตัว ดังนั้นเตรียมพร้อมให้พวกมันลงมือทำจริง ๆ ได้เลย! MiniMax Code ไม่มีโหมดดังกล่าวสำหรับ interactive session ของมัน ดังนั้นมันจะขออนุญาตตามปกติ และเนื่องจาก agent ปฏิเสธที่จะจดจำความไว้วางใจสำหรับ home directory ของคุณ การเปิดจาก `$HOME` จะเริ่มใน `~/Work` แทน

ยังมีทางลัดใน terminal ด้วย: `a` รัน agent เริ่มต้นแบบ inline ใน terminal ปัจจุบัน ขณะที่ `c`, `cx` และ `cy` เริ่ม OpenCode, Claude Code และ Codex โดยตรง (อีกครั้งในโหมดอนุมัติอัตโนมัติของพวกมัน) การเปลี่ยนธีมจะซิงก์ไปยัง agent ต่าง ๆ ด้วยเช่นกัน: Claude Code, Pi, OpenCode และ Hermes (เมื่อ Omarchy ติดตั้งมันแล้ว) ทั้งหมดจะเปลี่ยนตามเมื่อคุณสลับธีมของ Omarchy

### คำแนะนำสำหรับ agent ของคุณ

กฎส่วนตัวสำหรับทุก agent ให้ใส่ไว้ใน `~/.agents/AGENTS.md` ข้าง ๆ shared skills ใน `~/.agents/skills` เปิดมันใต้ _Agent > Instructions_ ซึ่งยังเชื่อมโยงมันเข้าไปในแต่ละ harness ที่เก็บไฟล์ global ของตัวเองไว้ด้วย: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` ของ Copilot และอื่น ๆ Crush และ Amp อ่านลิงก์ `~/.config/AGENTS.md` ขณะที่ omp, Kimi และ DeepSeek Harness อ่าน `~/.agents/AGENTS.md` โดยตรง การเลือก agent เริ่มต้นก็จะเชื่อมโยงมันเช่นกัน ไฟล์คำแนะนำที่คุณมีอยู่แล้วจะกลายเป็นไฟล์ที่ใช้ร่วมกันหากยังไม่มีไฟล์ดังกล่าวมาก่อน; มิฉะนั้นมันจะถูกเก็บไว้ข้าง ๆ ลิงก์ในชื่อ `.bak` รัน `omarchy agent instructions` เพื่อเชื่อมโยงใหม่หลังจากติดตั้ง agent ตัวอื่น

### แผง agent

แถบบาร์ด้านบนมีไอคอน agent ก่อนที่คุณจะตั้งค่า agent แผงของมันจะแนะนำคุณตลอดขั้นตอนการลงชื่อเข้าใช้ Claude, Codex หรือ Grok และตัวแรกจะกลายเป็น agent เริ่มต้นของคุณ หลังจากนั้น แผงจะรวมทุก subscription ไว้ในหน้าเดียว: แต่ละ agent และบัญชีพร้อมแผนของมัน มิเตอร์สำหรับขีดจำกัด session 5 ชั่วโมงและขีดจำกัดรายสัปดาห์ของแต่ละตัวพร้อมเวลาจนกว่าจะรีเซ็ต (ชี้เพื่อดูเปอร์เซ็นต์ที่แน่นอน) หรือยอดคงเหลือแบบ prepaid ที่เหลืออยู่ ใต้บรรทัดที่สลับหมุนเวียนสิ่งที่คุณใช้ไปในทุกตัว เช่น จำนวน token ในสัปดาห์นี้และโมเดลที่คุณใช้มากที่สุด ใต้ _Make something cool_ มันเสนอ prompt เริ่มต้นสำหรับธีมใหม่ plugin แอป หรือเกม ที่มอบงานให้ agent เริ่มต้นของคุณ แอปถูกสร้างในแบบเดียวกับที่ Hype, Monologue และ Omacut ของ Omarchy เองถูกสร้าง คือใน C++ และ Qt Quick โดยทำตาม agent skill ชื่อ omarchy-make-app และ compiler และชิ้นส่วน Qt ที่พวกมันต้องการก็ติดตั้งมาให้ เกมเป็นหน้า three.js หน้าเดียวใน `~/Games/vibes` โดยทำตาม agent skill ชื่อ omarchy-make-game และทั้งหมดเปิดจาก launcher ชื่อ Game Vibes ตัวเดียวในธีมปัจจุบัน; พวกมันโหลด three.js จากเว็บ ดังนั้นพวกมันต้องการการเชื่อมต่อเพื่อเริ่มใช้งาน Claude Code, Codex, Grok, Kimi, Cursor และโควตา Grok Bot ของมัน, GitHub Copilot, Muse, Antigravity และ Devin ครอบคลุมมาให้พร้อมใช้พร้อมขีดจำกัดของพวกมัน, Kimchi พร้อมแผนของมัน เครดิต prepaid และงบใช้จ่าย และ Hermes, Mistral Vibe และ Qwen Code จะแสดง session และ token ของพวกมันเมื่อคุณได้ใช้งานพวกมันแล้ว แผนและ key ของผู้ให้บริการที่คุณใช้ผ่าน pi, omp หรือ opencode ก็จะแสดงขึ้นมาด้วยเช่นกัน: OpenCode Zen และ Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan และ Synthetic พร้อมขีดจำกัดของพวกมัน; OpenRouter และ DeepSeek พร้อมยอดคงเหลือแบบ prepaid ของพวกมัน; Fireworks พร้อมยอดใช้จ่ายในช่วง 30 วันที่ผ่านมา token จากโมเดลที่คุณรันบนฮาร์ดแวร์ของคุณเองก็นับรวมในยอดรวมด้วยเช่นกัน; โมเดลเหล่านั้นเองมีแผงของตัวเอง ซึ่งอธิบายไว้ใต้ [Local models](#local-models) ทุก agent จะถูกนับเพียงครั้งเดียว ใต้ผู้ที่เรียกเก็บเงินจากมัน ไม่ว่าคุณจะขับเคลื่อนมันผ่าน harness จำนวนเท่าใดก็ตาม

คลิกซ้ายที่ไอคอนบนบาร์หรือกด `Super + Ctrl + X` สำหรับแผง คลิกขวาเพื่อเปิด agent เริ่มต้นของคุณ และคลิกกลางเพื่อรีเฟรช บันทึกการใช้งานที่อยู่เบื้องหลังมันจะถูกสร้างใหม่ทุก 15 นาทีโดย `omarchy agent usage update` และแผงยังสามารถรวมการใช้งานจากเครื่องอื่น ๆ ของคุณผ่านโฟลเดอร์ที่ซิงก์ไว้ ดู README ใต้ `$OMARCHY_PATH/shell/plugins/agents/` สำหรับการตั้งค่าแบบเต็ม

### หลาย subscription

หากคุณจ่ายเงินสำหรับแผน Claude, Codex หรือ Grok มากกว่าหนึ่งแผน — เช่น Max ส่วนตัวหนึ่งและแบบงานอีกหนึ่ง — Omarchy สามารถให้พวกมันทั้งหมดลงชื่อเข้าใช้อยู่และสลับไปมาระหว่างพวกมันได้ เพิ่ม subscription ด้วย + ในแผง agent ซึ่งจะแนะนำคุณตลอดขั้นตอนตรงนั้น หรือด้วย `omarchy agent account add claude Work` (หรือ `codex` หรือ `grok`) มันจะติดตั้ง CLI หากยังไม่มี บัญชีแรกสำหรับผู้ให้บริการรายหนึ่งจะลงชื่อเข้าใช้ผ่านเบราว์เซอร์ปกติของคุณ ตรงตำแหน่งที่ CLI ค้นหาเสมอ ทุกบัญชีหลังจากนั้นจะลงชื่อเข้าใช้ผ่านหน้าต่างส่วนตัว ดังนั้นบัญชีที่เบราว์เซอร์ของคุณลงชื่อเข้าใช้อยู่แล้วจะไม่ถูกหยิบขึ้นมาโดยผิดพลาด; ลงชื่อเข้าใช้ที่นั่นในฐานะบัญชีที่คุณกำลังเพิ่ม และปิดหน้าต่างส่วนตัวใด ๆ ที่คุณเปิดไว้อยู่แล้วก่อน อย่าออกจากระบบของ CLI เพื่อทำสิ่งนี้เด็ดขาด: การออกจากระบบจะเพิกถอนการลงชื่อเข้าใช้ที่บันทึกไว้ และบัญชีนั้นจะต้องถูกเพิ่มอีกครั้ง

หากต้องการคัดลอกการเข้าสู่ระบบ subscription ของคุณไปยังเครื่อง Omarchy อื่นผ่าน SSH ให้รัน `omarchy agent account copy user@laptop` ผู้ส่งจะจัดเตรียมตัวรับชั่วคราวเมื่อปลายทางไม่มีตัวรับติดตั้งอยู่ ดังนั้นเครื่อง Omarchy รุ่นเก่ากว่าสามารถรับบัญชีได้โดยไม่ต้องอัปเดต ตัวรับที่ติดตั้งแล้วจะมีความสำคัญเหนือกว่า สิ่งนี้คัดลอก subscription ของ Claude, Codex และ Grok ทั้งหมด; เพิ่มชื่อผู้ให้บริการเพื่อเลือกพวกมัน เช่นใน `omarchy agent account copy laptop claude` ชื่อบัญชีและ ID คำสั่งจะตรงกับต้นทาง รวมถึงบัญชีที่มีอยู่แล้วบนปลายทาง บัญชีปลายทางที่ไม่เกี่ยวข้องจะได้รับคำต่อท้ายที่เป็นตัวเลขหากชื่อของพวกมันขัดแย้งกัน และการตั้งค่า skills plugins และประวัติการสนทนาจะยังคงอยู่เฉพาะบนแต่ละเครื่อง

ข้อมูลรับรองของปลายทางที่มีอยู่จะถูกเก็บไว้ บัญชีต้นทางที่ลงชื่อเข้าใช้ที่นั่นอยู่แล้วจะมีการซิงค์ชื่อโดยไม่แทนที่ข้อมูลรับรองของมัน; บัญชีอื่น ๆ จะถูกเพิ่มควบคู่ไปกับมัน หากต้องการแทนที่ข้อมูลรับรองที่บันทึกไว้สำหรับบัญชีที่ตรงกัน ให้ใช้ `omarchy agent account copy --replace laptop claude` หลังจากออกจาก session ของบัญชีนั้นบนปลายทาง ปลายทางที่ยังใหม่จะได้รับบัญชีที่ใช้งานอยู่และการตั้งค่าการสลับของต้นทางด้วย; ปลายทางที่จัดตั้งแล้วจะเก็บของตัวเองไว้

ข้อมูลรับรองเดินทางผ่าน SSH และถูกเก็บไว้ในไฟล์ส่วนตัวบนปลายทาง ดังนั้นให้คัดลอกไปยังเครื่องที่คุณไว้วางใจเท่านั้น นี่คือการคัดลอกแบบครั้งเดียว ไม่ใช่การซิงก์อย่างต่อเนื่อง refresh token ของ Codex อาจถูกหมุนเวียนโดยเครื่องอื่น ทำให้การเข้าสู่ระบบที่คัดลอกมาต้องต่ออายุ; การลงชื่อเข้าใช้แยกกันยังคงเป็นตัวเลือกที่น่าเชื่อถือที่สุดสำหรับการใช้งานพร้อมกันบนหลายเครื่อง ดู [คำแนะนำการยืนยันตัวตนบัญชีของ Codex](https://developers.openai.com/codex/auth/ci-cd-auth)

ผู้ให้บริการรายหนึ่งจะมีบัญชีที่ใช้งานอยู่ได้หนึ่งบัญชี และทุก session ใหม่จะเริ่มต้นในฐานะบัญชีนั้น: `cx`, `cy`, `claude`, `codex` หรือ `grok` แบบธรรมดา สิ่งใดก็ตามที่เปิดผ่าน `omarchy agent` และสคริปต์หรือ editor ที่พบ CLI บน `PATH` สลับด้วย `omarchy agent account use work` (และกลับด้วย `omarchy agent account use main`) หรือในแผงโดยกดหมายเลขของบัญชีแล้วกด `Enter` (หรือคลิกปุ่ม Use ของมัน) session ของ Claude ที่กำลังทำงานอยู่ก็จะสลับด้วย จากข้อความถัดไปของพวกมัน: ทุก session ของ Claude ทำงานใน `~/.claude` ซึ่งเก็บการลงชื่อเข้าใช้ของบัญชีที่ใช้งานอยู่เสมอ session ของ Claude ที่เริ่มในโฟลเดอร์ของบัญชีเองโดย Omarchy รุ่นเก่ากว่าจะเก็บการลงชื่อเข้าใช้นั้นไว้จนกว่ามันจะออก ดังนั้นการสลับจะระบุชื่อ session เหล่านั้นและจะเสร็จสิ้นด้วยตัวเองเมื่อพวกมันหายไป session ของ Codex และ Grok ที่กำลังทำงานอยู่จะยังคงอยู่บนบัญชีที่พวกมันเริ่มต้นด้วย ประวัติการสนทนา การตั้งค่า skills และ plugins ถูกใช้ร่วมกันระหว่างบัญชี ดังนั้น `claude --continue` ในโฟลเดอร์เดียวกันจะดำเนินการต่อจากจุดที่คุณค้างไว้บนบัญชีใหม่

เมื่อมีมากกว่าหนึ่งบัญชี แผงจะแสดงขีดจำกัดของแต่ละบัญชีเคียงข้างกัน โดยบัญชีที่ใช้งานอยู่จะถูกทำเครื่องหมายไว้ โดยค่าเริ่มต้น Omarchy จะแจ้งเตือนคุณเมื่อบัญชีที่ใช้งานอยู่ผ่าน 95% ของขีดจำกัด และการคลิก notification จะสลับไปยังบัญชีที่มี headroom มากที่สุด ชี้ที่บรรทัดของบัญชีในแผงและคลิก Autoswitch ที่ปรากฏข้าง ๆ Use (หรือกด `m`) หรือรัน `omarchy agent account mode auto` เพื่อให้มันสลับด้วยตัวเองแทน; ในขณะที่มันเปิดอยู่ Autoswitch จะแทนที่ Use และการคลิกมันอีกครั้งจะกลับไปเป็นการแจ้งเตือน เพิ่มตัวเลขเพื่อเปลี่ยนเกณฑ์ เช่นใน `omarchy agent account mode auto 90` หากทุกบัญชีเกินเกณฑ์ คุณจะได้รับแจ้งหนึ่งครั้ง พร้อมกับบัญชีใดจะว่างก่อน ในขณะที่บัญชีที่ใช้งานอยู่ภายใน 15 จุดจากเกณฑ์ของมัน (80% ที่ค่าเริ่มต้น) ขีดจำกัดของมันจะถูกตรวจสอบทุกสามนาทีแทนที่จะเป็นทุก 15 นาที

`omarchy agent account list` แสดงทุกบัญชีและขีดจำกัดล่าสุดของพวกมัน `omarchy agent account remove work` ลืมบัญชีหนึ่ง และ `omarchy agent account rename primary Hey` เปลี่ยนชื่อบัญชีหนึ่ง (หรือคลิกชื่อบัญชีในแผง) คำสั่งเหล่านี้ทำงานบนบัญชีของ agent เริ่มต้นของคุณ; หากต้องการเข้าถึงผู้ให้บริการรายอื่น ให้ระบุชื่อมันก่อน เช่นใน `omarchy agent account use codex side` การเข้าสู่ระบบที่คุณมีอยู่แล้วใน `~/.claude` หรือ `~/.codex` คือบัญชี _Main_ ของ Codex จะยังคงอยู่ที่เดิม; ของ Claude จะรออยู่ในโฟลเดอร์ของตัวเองในขณะที่บัญชีอื่นกำลังใช้งานอยู่ บัญชีที่ไม่ได้ใช้งานนานกว่าประมาณแปดชั่วโมงอาจแสดง _Sign-in required_; คลิกมันเพื่อลงชื่อบัญชีนั้นเข้าใช้อีกครั้งในแผง หรือสลับไปยังมันและเริ่ม session ซึ่งจะรีเฟรชการลงชื่อเข้าใช้ด้วยตัวเอง MCP server ที่คุณเพิ่มด้วย `claude mcp add` จะเข้าถึงทุกบัญชี Claude เนื่องจากพวกมันทั้งหมดทำงานใน `~/.claude`; สำหรับ Codex และ Grok server ที่คุณมีเมื่อบัญชีถูกเพิ่มจะตามไปกับมัน แต่ server ในภายหลังจะเข้าถึงเฉพาะบัญชีที่คุณเพิ่มพวกมันใน Claude Desktop เก็บการลงชื่อเข้าใช้ของตัวเอง และเครื่องมือ Codex หรือ Grok ที่กำหนดค่าด้วยเส้นทางสัมบูรณ์ไปยังไบนารี CLI จะไม่ตามการสลับไป `CLAUDE_CONFIG_DIR`, `CODEX_HOME` หรือ `GROK_HOME` ที่ระบุอย่างชัดเจนจะมีความสำคัญเหนือกว่าบัญชีที่เลือก

### การวินิจฉัยการขัดข้อง

Omarchy เฝ้าดู systemd-coredump สำหรับการขัดข้องของกระบวนการ เมื่อคุณเลือก agent เริ่มต้นแล้ว โปรแกรมใด ๆ ของคุณที่ dump core จะนำ notification "Process crashed" ขึ้นมา — คลิกมัน และการขัดข้องจะถูกส่งให้ agent เริ่มต้นของคุณพร้อมกับ skill ชื่อ omarchy-diagnose-crash ของ Omarchy ซึ่งจะแนะนำ agent ตลอดขั้นตอนการสร้างข้อเท็จจริงจาก core dump และการตัดสินใจว่าการขัดข้องนั้นคุ้มค่าที่จะรายงานไปยัง upstream หรือไม่ คุณยังสามารถรันมันด้วยตนเองกับ PID ใด ๆ จาก `coredumpctl list` ด้วย `omarchy agent crash <pid>` ได้

การเฝ้าดูเปิดอยู่โดยค่าเริ่มต้น ปิดมันใต้ _Trigger > Toggle > Crash Capture Off_ (หรือด้วย `omarchy toggle crash-capture`) และ notification จะหยุด; `omarchy agent crash <pid>` ยังคงทำงานด้วยตนเองได้

การขัดข้องยังสามารถปิดเสียงได้ทีละโปรแกรม ซึ่งเป็นสิ่งที่การวินิจฉัยเสนอให้คุณในตอนท้าย `omarchy crash mute hyprland` หยุด notification สำหรับโปรแกรมนั้นเท่านั้น `omarchy crash mute hyprland off` นำพวกมันกลับมา และ `omarchy crash mute` เพียงอย่างเดียวจะแสดงรายการสิ่งที่คุณปิดเสียงไว้ มันรับเส้นทางของไบนารีได้อย่างยินดีพอ ๆ กับชื่อของมัน ดังนั้น `omarchy crash mute /usr/bin/hyprland` จึงทำสิ่งเดียวกัน ใส่เครื่องหมายคำพูดชื่อที่มีช่องว่างในมัน เช่นใน `omarchy crash mute 'Some App'` อย่างอื่นทุกอย่างยังคงแจ้งเตือน และโปรแกรมที่ปิดเสียงไว้ยังคงขัดข้องอยู่ — สิ่งนี้ซ่อนการเตือนความจำ มันไม่ได้แก้ไขอะไร

### แอปบนเดสก์ท็อป

เมนู _Install > AI_ ยังมีแอป AI แบบกราฟิกอยู่สองสามตัวด้วย: Amp Desktop, Antigravity Desktop, แอปเดสก์ท็อป ChatGPT, แอปเดสก์ท็อป Claude (เบต้า Linux ของ Anthropic พร้อมแท็บ Chat, Cowork และ Claude Code), Grok Bot สำหรับแชทกับโมเดลของ xAI, Herdr Desktop, Hermes Desktop, OpenClaw, แอปเดสก์ท็อป Perplexity และ T3 Code Grok Bot คือแอปแชทบนเดสก์ท็อป coding agent คือคำสั่ง `grok`

Hermes Desktop เป็นตัวที่ต้องรู้ เพราะเครื่องหนึ่งมี Hermes เดียว และมันเป็นของแอป: Hermes จะติดตั้งผ่านแอปเท่านั้น และคำสั่ง `hermes` ที่ agent เริ่มต้นรันคือของแอป การเลือก Hermes เป็น agent เริ่มต้นจะติดตั้งสิ่งเดียวกับที่รายการ _Install > AI_ ติดตั้ง: package และ Hermes runtime ใต้ `~/.hermes` ที่ตั้งค่าโดย installer ของ Hermes เอง ซึ่งใช้เวลาสองสามนาทีในครั้งแรก runtime นั้นคือ Hermes ตัวเดียวที่คำสั่ง `hermes` ใน terminal, agent เริ่มต้น และแอปทั้งหมดใช้ และมันอัปเดตตัวเองด้วย `hermes update` แทนที่จะรอการเปิดตัว Omarchy การติดตั้งมันยังมอบธีม Omarchy ให้ Hermes เป็น skin ชื่อ `omarchy` ซึ่งทุกพื้นผิวของ Hermes จะทำตามเมื่อคุณสลับธีม; เลือกอีกตัวใต้การตั้งค่า Appearance ของ Hermes หรือด้วย `/skin` หากคุณไม่ต้องการให้มันทำเช่นนั้น และ Omarchy จะปล่อยตัวเลือกนั้นไว้ตามเดิม การลบแอปใต้ _Remove > AI_ จะปิด Hermes ก่อน รวมถึง gateway นำ runtime นั้นไปกับมัน และเก็บแชท ความทรงจำ และ skills ที่ Hermes เขียนให้ตัวเอง เว้นแต่คุณจะบอกเป็นอย่างอื่น: มันจะถาม โดยค่าเริ่มต้นคือไม่ ว่าข้อมูลนั้นและการตั้งค่าการเชื่อมต่อของคุณควรไปด้วยหรือไม่

ประสบการณ์บนเดสก์ท็อปของ OpenClaw คือ Control UI ของมัน ซึ่งเปิดเป็น web app ที่ได้รับการสนับสนุนจาก local gateway ของตัวเอง OpenClaw อาศัยอยู่ใน `~/.openclaw` และอัปเดตตัวเอง: ใช้ปุ่ม "Update Gateway" ของ Control UI หรือรัน `openclaw update` และ gateway จะรีสตาร์ทบนรุ่นใหม่ Omarchy เลือกเพียงรุ่นที่การติดตั้งใหม่จะเริ่มต้นจากเท่านั้น OpenClaw ยังสามารถเป็น agent เริ่มต้นของคุณได้เช่นกัน: การเลือกมันใต้ _Agent > Harness_ จะตั้งค่าสำเนาเดียวกันนั้นใน `~/.openclaw` และ agent จะเปิด terminal UI ของ OpenClaw ที่เชื่อมต่อกับ gateway ของมัน การลบ OpenClaw ใต้ _Remove > AI_ จะนำ gateway service และแอปไปกับมัน จากนั้นจะถามว่า `~/.openclaw` ควรไปด้วยหรือไม่ เนื่องจากที่นั่นเก็บแชทและข้อมูลรับรองของคุณควบคู่ไปกับ OpenClaw เองและ plugin runtime ที่มันดาวน์โหลด; ค่าเริ่มต้นจะเก็บมันไว้ และการติดตั้ง OpenClaw อีกครั้งจะหยิบมันกลับขึ้นมา

Herdr Desktop คือแอปเดสก์ท็อป [Herdr](https://herdr.dev): spaces, tabs และ panes ของ terminal และ coding agent ที่ยังคงทำงานในแกนหลักของมันเมื่อคุณปิดหน้าต่าง มันมาจาก installer ของ Herdr เองแทนที่จะเป็น package ดังนั้นมันอาศัยอยู่ใน `~/.local/share/herdr-app` นำแกนหลักของมันมาพร้อมใน `~/.local/bin/herdr-core` เมื่อคุณยังไม่มี และอัปเดตทั้งสองตัวเอง มันอยู่ข้าง ๆ คำสั่ง `herdr` ที่ Omarchy ส่งมาบน `Super + Ctrl + Return` แทนที่จะแทนที่มัน และได้รับคีย์โดยตรงของคำสั่งนั้น: `Alt + Return` และ `Alt + Shift + Return` แยก pane ลงหรือขวา `Alt + Escape` ปิดมัน `Ctrl + Alt + Arrow` ย้ายระหว่าง panes `Alt + 1..9` และ `Alt + Left/Right` เลือก tab และ `Alt + Up/Down` ย้ายระหว่าง spaces `Ctrl + 1..9` เลือก space และ `Alt + Shift + Up/Down` ก้าวผ่าน agent ต่าง ๆ คีย์นำหน้า `Ctrl + Space` ยังคงเป็นเฉพาะ terminal เนื่องจากแอปไม่สามารถถือคีย์ Ctrl ธรรมดาไว้สำหรับลำดับได้ Omarchy เขียนพวกนี้ไปยัง `~/.config/herdr-app/keys.json` และ `omarchy-refresh-herdr-app` จะนำพวกมันกลับมา การติดตั้งมันจะเลือกธีม Omarchy ของ Herdr ซึ่งจะทำตามธีม Omarchy ของคุณตั้งแต่นั้นเป็นต้นมา Herdr เก็บธีมหนึ่งสำหรับโหมดสว่างและอีกหนึ่งสำหรับโหมดมืด ดังนั้นหลังจากสลับระหว่างธีม Omarchy แบบมืดและแบบสว่าง ให้เลือก Omarchy ในตัวเลือกธีมของ Herdr อีกครั้งสำหรับอีกโหมดหนึ่ง

T3 Code ทำงานจากรุ่น AppImage อย่างเป็นทางการใน `~/.local/share/t3code` แทนที่จะเป็นจาก package ดังนั้นมันอัปเดตตัวเอง การติดตั้งมันจะถามว่าจะเริ่มต้นบนช่อง Stable หรือ Nightly; สลับในภายหลังในการตั้งค่าของ T3 Code thread และการตั้งค่าของคุณอาศัยอยู่ใน `~/.t3` และการลบ T3 Code ใต้ _Remove > AI_ จะนำพวกมันไปกับมัน

### โมเดลในเครื่อง

รันโมเดลแบบเปิดบนเครื่องของคุณเองสำหรับ coding agent ของคุณ prompt และโค้ดของคุณยังคงอยู่บนเครื่อง; ไม่มีอะไรที่ส่งไปยังโมเดลออกจากเครื่อง เริ่มต้นด้วย:

```bash
omarchy models use best text
```

นั่นตั้งค่าโมเดลข้อความที่ดีที่สุดสำหรับเครื่องนี้ ซึ่งเป็นประเภทที่ agent ของคุณใช้ โมเดลภาพ วิดีโอ และเพลงมีตัวที่ดีที่สุดของตัวเอง: `omarchy models use best image`, `video` หรือ `music` รัน `omarchy models use best` เพื่อดูตัวเลือกของแต่ละประเภทสำหรับเครื่องนี้

หรือเปิดแผง local models จากไอคอนประกายของมันในแถบบาร์ด้านบน ข้าง ๆ ไอคอน agent หรือด้วย Super + Ctrl + Alt + X และเลือก + ไอคอนจะแสดงขึ้นเมื่อโมเดลพอดีกับเครื่องนี้ Podman ซึ่งรันโมเดล มาพร้อมกับ Omarchy เช่นเดียวกับ container toolkit ของ NVIDIA บนเครื่อง NVIDIA ซึ่งให้ GPU แก่พวกมัน; หากตัวใดตัวหนึ่งหายไป การตั้งค่าครั้งแรกจะติดตั้งมัน จากนั้น Omarchy จะเลือกโมเดลที่แนะนำสำหรับเครื่องนี้ ดาวน์โหลดมัน และเริ่มมัน คาดหวังการดาวน์โหลดขนาดหลายสิบ GB และหน่วยความจำส่วนใหญ่ของเครื่องจะถูกใช้ขณะโมเดลทำงาน: Flash Next ใช้ประมาณ 100 GiB กับ context แบบเต็ม 256K ของมัน หากโมเดลอื่นถือหน่วยความจำที่มันต้องการ มันจะถูกตั้งค่าในสถานะหยุด พร้อมที่จะเริ่มเมื่อคุณหยุดตัวหนึ่ง โมเดลจะหยุดเมื่อออกจากระบบ; หยุดมันด้วยตัวเองเมื่อคุณต้องการหน่วยความจำสำหรับอย่างอื่น

`omarchy models list` แสดงตัวเลือกและอธิบายว่าทำไมบางตัวจึงไม่พอดี หากต้องการตั้งค่าอีกตัว ให้รัน `omarchy models use <recipe>` วันนี้ `qwen3.8-flash-next-gufo` และ `qwen3.8-27b-gufo` พร้อมใช้งานสำหรับเครื่อง Strix Halo ขนาด 128 GB; ตัว 27B ใช้ประมาณ 40 GiB ดังนั้นมันเหลือพื้นที่สำหรับงานอื่น บนแล็ปท็อป 64 GB ที่มี Arc B390 ของ Intel `qwen3.6-35b-a3b-llamacpp` ทำงานในประมาณ 30 GiB recipe และคำแนะนำใหม่มาพร้อมกับ `omarchy update` ผ่าน package

ทุกโมเดลที่คุณตั้งค่าจะได้บรรทัดของตัวเองในแผง local models: เล่นเพื่อเริ่มมัน หยุดชั่วคราวเพื่อหยุดมันและปลดปล่อยหน่วยความจำของมัน และปุ่ม terminal เพื่อเปิด agent ของคุณบนมัน ข้ามด้านบน บาร์แสดงให้เห็นว่าหน่วยความจำของเครื่องถูกแบ่งระหว่าง Omarchy เอง (ระบบและแอปของคุณ) แต่ละโมเดลที่กำลังทำงาน และสิ่งที่ว่างอย่างไร ชี้ไปที่โมเดลที่หยุดแล้วและบาร์จะแสดงว่ามันพอดีหรือไม่ หรือมันขาดอีกเท่าใด หลายตัวสามารถทำงานพร้อมกันได้เมื่อพวกมันพอดีในหน่วยความจำด้วยกัน; หากตัวหนึ่งไม่พอดี Omarchy จะบอกว่าให้หยุดโมเดลที่กำลังทำงานตัวใด ลากบรรทัดตามโลโก้ของพวกมันเพื่อจัดลำดับใหม่ และกด Delete บนบรรทัดที่เลือกเพื่อลบโมเดลและการดาวน์โหลดของมัน

ทุกโมเดลที่คุณตั้งค่ายังได้รายการของตัวเองใน app launcher ใต้ชื่อของโมเดลและพร้อมโลโก้ของผู้สร้างมัน ในแบบเดียวกับการลงชื่อเข้าใช้ Claude, Codex หรือ Grok ที่เพิ่มรายการหนึ่ง มันเปิด agent ของคุณบนโมเดลนั้น และเริ่มโมเดลก่อนหากมันไม่ได้ทำงานอยู่: terminal จะแสดงมันกำลังโหลดและส่งมอบให้ agent เมื่อมันพร้อม การลบโมเดลจะลบรายการของมัน

ไม่ใช่ทุกโมเดลสำหรับ coding โมเดลภาพ วิดีโอ และเพลงจะเปิดใน Fantasi แทน ซึ่งเป็นแอปของ Omarchy สำหรับสร้างภาพ วิดีโอ และเพลงด้วยโมเดลที่ทำงานบนเครื่องนี้ จากรายการ launcher ของพวกมันและจากบรรทัดของพวกมันในแผง local models

โมเดลจะทำงานต่อไปตรงตามที่มันถูกตั้งค่าไว้ ดังนั้นการอัปเดต Omarchy จะไม่รีสตาร์ทตัวหนึ่งใต้ agent ของคุณ เมื่อ Omarchy มี runtime รุ่นใหม่กว่าหรือ weights รุ่นใหม่กว่าสำหรับโมเดลที่คุณตั้งค่าไว้ บรรทัดของมันจะแสดงปุ่มอัปเดต: กดมันและโมเดลจะถูกตั้งค่าอีกครั้งในเบื้องหลัง โดยดาวน์โหลดเฉพาะสิ่งที่เปลี่ยนแปลง และรีสตาร์ทบนรุ่นใหม่ โมเดลที่หยุดอยู่จะยังคงหยุดอยู่ `omarchy models update` ทำสิ่งเดียวกันสำหรับทุกโมเดลจาก terminal

จาก command line `omarchy models start <recipe>` และ `omarchy models stop <recipe>` ทำสิ่งเดียวกัน `omarchy models status` แสดงทุกโมเดล และ `omarchy agent --local` เปิด agent เริ่มต้นของคุณบนโมเดลล่าสุดที่คุณเริ่ม pi, OpenCode และ Qwen Code สามารถใช้ตัวหนึ่งได้; กับค่าเริ่มต้นอื่นใด มันจะเปิดใน pi หรือใน OpenCode หากคุณไม่มี pi pi ยังแสดงรายการทุกโมเดลที่คุณตั้งค่าไว้ และโมเดลบนเครื่องที่คุณจับคู่ด้วย ในตัวเลือกโมเดลของตัวเอง ดังนั้น `pi` แบบธรรมดาก็เข้าถึงพวกมันได้เช่นกัน client ที่เข้ากันได้กับ OpenAI ตัวใดก็สามารถเชื่อมต่อได้เช่นกัน: `status` แสดงที่อยู่ของแต่ละโมเดล (ตัวแรกคือ `http://127.0.0.1:11435/v1`) ชื่อ recipe คือโมเดล และ key อยู่ใน `~/.config/omarchy/agent-local/key`

`omarchy models remove <recipe>` ลบโมเดลและการดาวน์โหลดที่ไม่มีโมเดลอื่นใช้

runtime ของบุคคลที่สามจะถูกติดป้ายด้วยผู้เผยแพร่ของพวกมัน Omarchy รันทุกโมเดลโดยไม่มีการเข้าถึงเครือข่าย

### LLM ในเครื่อง

Omarchy แนะนำสองวิธีในการรันโมเดล LLM ในเครื่อง: LM Studio และ Ollama LM Studio ให้ GUI interface สำหรับการค้นหาโมเดลแบบ open-weight ติดตั้งพวกมัน และรันพวกมัน มันเป็นวิธีที่ยอดเยี่ยมในการเริ่มต้นได้อย่างง่ายดาย Ollama เสนอ CLI สำหรับทำเช่นเดียวกัน แต่หากคุณยังใหม่กับโมเดลในเครื่อง ฉันจะเริ่มต้นด้วย LM Studio คุณสามารถติดตั้งตัวใดตัวหนึ่งได้ใต้ _Install > AI_ ใน Omarchy Menu

### Skills ของ Omarchy

Agent skills ช่วยให้ AI ใช้เครื่องมือเฉพาะในวิธีเฉพาะ และ Omarchy ส่งมาเจ็ดตัว skill ชื่อ omarchy ครอบคลุมการปรับแต่งระบบ เช่นการปรับ config ของ Hyprland ของคุณหรือการปรับบาร์ omarchy-make-theme, omarchy-make-plugin, omarchy-make-app และ omarchy-make-game ครอบคลุมการสร้างสิ่งใหม่ omarchy-contribute ครอบคลุมการรายงาน bug หรือการส่งการแก้ไขไปยัง upstream และ omarchy-diagnose-crash ทำงานผ่าน core dump ของการขัดข้อง พวกมันถูก symlink เข้าไปในไดเรกทอรี skill สำหรับ Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` และแต่ละ `~/.hermes/profiles/*/skills`) และตำแหน่งทั่วไป `~/.agents/skills` ดังนั้น harness ส่วนใหญ่จะหยิบพวกมันขึ้นมาโดยอัตโนมัติ โฟลเดอร์ skill ของคุณเองที่มีชื่อเดียวกันจะมีความสำคัญเหนือกว่า

แต่คุณควรถือว่า skills เหล่านี้เป็นแบบทดลอง โมเดลต่าง ๆ จะใช้มันให้เกิดผลต่างกัน ทางที่ดีที่สุดคือรันใน plan mode ก่อน เพื่อให้คุณมีไอเดียว่า agent อยากเปลี่ยนแปลงอะไร แล้วเตรียมพร้อมที่จะย้อนกลับการเปลี่ยนแปลงหรือแม้แต่เรียกใช้ `omarchy reinstall configs` หาก agent ทำทุกอย่างเละเทะ
