### การติดตั้งและอัปเดตเอเจนต์

ยกเว้น Hermes และ OpenClaw เอเจนต์ทุกตัวเป็นแพ็กเกจจาก repository ของ Omarchy เอง ติดตั้งตัวหนึ่งจาก _Install > AI > CLI_ หรือด้วย `omarchy install ai cli <command>` และลบมันออกอีกครั้งจาก _Remove > AI > CLI_ ซึ่งจะคงข้อมูลการลงชื่อเข้าใช้และประวัติของคุณไว้ การเลือกเอเจนต์ที่ยังไม่ได้ติดตั้งก็จะติดตั้งให้ด้วยเช่นกัน: การติดดาวมันในแผงเอเจนต์ การเลือกมันด้วย `omarchy default agent <name>` หรือการลงชื่อเข้าใช้การสมัครสมาชิกของมัน Omarchy เผยแพร่เอเจนต์แต่ละรุ่นใหม่ภายในหนึ่งชั่วโมง ไปยังทุก channel และ `omarchy update` จะติดตั้งมันพร้อมกับส่วนที่เหลือของระบบ

เนื่องจาก pacman ดูแลให้พวกมันเป็นปัจจุบันอยู่เสมอ ตัวอัปเดตของเอเจนต์เองจึงถูกปิดไว้: `claude update` หรือปุ่มอัปเดตในแอปจึงไม่มีอะไรให้ทำ หากคุณอยากใช้เอเจนต์จากตัวติดตั้งของมันเอง ให้ใช้ตัวนั้นและปล่อยให้แพ็กเกจของ Omarchy ไม่ได้ติดตั้งไว้; สำเนาที่อยู่บน `PATH` ของคุณอยู่แล้วจะถือว่าติดตั้งแล้ว หลีกเลี่ยงตัวติดตั้งแบบ `curl | bash` ที่วางสำเนาที่สองไว้ก่อนสำเนาของ Omarchy บน `PATH` เช่น ตัวของ x.ai สำหรับ `grok`

`dsh` เปิด UI บนเบราว์เซอร์ของมันที่ `127.0.0.1:3080` โดยใช้โฟลเดอร์ที่เปิดใช้งานเป็น workspace เริ่มต้น UI บนเบราว์เซอร์ของมันไม่รับ prompt เริ่มต้น ดังนั้น `omarchy agent prompt` จะเปิดมันโดยมี prompt อยู่บนคลิปบอร์ดของคุณให้วาง Omarchy เริ่มมันด้วย preset สิทธิ์แบบไม่ต้องขออนุมัติของ DeepSeek DeepSeek Harness จะอัปโหลดบันทึก session ไปยัง DeepSeek เมื่อคุณใช้ API โมเดลอย่างเป็นทางการของมัน; ปิดการทำงานนั้นได้ที่ _Settings > General > Upload Session Log_ ใน UI บนเบราว์เซอร์ของมัน ข้อเสนอแนะที่คุณส่งให้มันก็จะถูกอัปโหลดไปพร้อมกับ session ด้วย เว้นแต่คุณจะเริ่มมันด้วย `DSH_TELEMETRY_MODE=DISABLED`

### เอเจนต์เริ่มต้น

เลือกเอเจนต์เริ่มต้นของคุณด้วยดาวข้างเอเจนต์ในแผงเอเจนต์ ซึ่งจะถูกเติมเต็มบนตัวที่เป็นค่าเริ่มต้น หรือด้วย `omarchy default agent <name>` ซึ่งรับ harness ใด ๆ ที่ไม่มีบรรทัดอยู่ที่นั่นด้วย หากเอเจนต์นั้นยังไม่ได้ติดตั้ง การเลือกมันจะติดตั้งมันก่อน และมันจะได้ตัวเปิดใช้งานของตัวเองในตัวเปิดแอปด้วย ถัดจาก Agent Omarchy ใหม่เอี่ยมจะเชิญคุณให้ตั้งค่าหนึ่งตัวด้วยการแจ้งเตือนครั้งเดียว ซึ่งจะเปิดแผงเอเจนต์

การเลือก Claude ยังพยายามตั้งค่าส่วนขยายเบราว์เซอร์ของมันสำหรับ Chromium, Chrome, Brave, Brave Origin และ Edge ด้วย การตั้งค่าส่วนขยายใช้กับผู้ใช้ทุกคนและอาจขอรหัสผ่านระบบของคุณ; การยกเลิกหรือการติดตั้งส่วนขยายที่ล้มเหลวยังคงเลือกและเปิด Claude อยู่ รีสตาร์ทเบราว์เซอร์ของคุณ เปิดใช้งานส่วนขยายหากได้รับแจ้ง และลงชื่อเข้าใช้ Claude เพื่อเชื่อมต่อให้เสร็จ รัน `/chrome` ใน Claude เพื่อตรวจสอบการเชื่อมต่อ Firefox และ Zen ไม่รองรับส่วนขยายนี้ หาก Claude เป็นค่าเริ่มต้นของคุณอยู่แล้วก่อนที่จะเพิ่มการตั้งค่านี้ ให้เลือกมันอีกครั้งเพื่อติดตั้งส่วนขยาย

เมื่อคุณเลือกแล้ว `Super + Shift + Ctrl + A` จะเปิดเอเจนต์เริ่มต้นในหน้าต่างเทอร์มินัลเฉพาะ (หรือแสดงตัวเลือกหากคุณยังไม่ได้เลือก) คุณยังเปิดมันให้ทำงานทันทีได้ด้วย `omarchy agent prompt "Review this project"` Freebuff และ DeepSeek Harness ไม่รับ prompt เริ่มต้น ดังนั้นพวกมันจะเปิดโดยมี prompt อยู่บนคลิปบอร์ดของคุณให้วางแทน เอเจนต์ที่เปิดด้วยวิธีนี้จะทำงานโดยไม่มีผู้ดูแลในโหมดไม่หยุดเพื่อถามของแต่ละตัว ดังนั้นจงเตรียมพร้อมให้พวกมันลงมือทำสิ่งต่าง ๆ จริง ๆ! MiniMax Code ไม่มีโหมดแบบนั้นสำหรับ session แบบโต้ตอบของมัน ดังนั้นมันจะขอสิทธิ์ตามปกติ และเนื่องจากเอเจนต์ปฏิเสธที่จะจดจำความไว้วางใจสำหรับโฟลเดอร์บ้านของคุณ การเปิดใช้งานจาก `$HOME` จะเริ่มต้นใน `~/Work` แทน

ยังมีทางลัดในเทอร์มินัลด้วย: `a` รันเอเจนต์เริ่มต้นแบบอินไลน์ในเทอร์มินัลปัจจุบัน ขณะที่ `c`, `cx`, `cy` และ `ca` เริ่ม OpenCode, Claude Code, Codex และ Antigravity โดยตรง (ในโหมดอนุมัติอัตโนมัติของพวกมันอีกเช่นกัน) การเปลี่ยนธีมจะซิงค์ไปยังเอเจนต์ด้วยเช่นกัน: Claude Code, Pi, OpenCode และ Hermes (เมื่อ Omarchy ติดตั้งมันแล้ว) จะเปลี่ยนตามทั้งหมดเมื่อคุณเปลี่ยนธีมของ Omarchy

### คำแนะนำสำหรับเอเจนต์ของคุณ

กฎส่วนตัวสำหรับทุกเอเจนต์อยู่ใน `~/.agents/AGENTS.md` ถัดจากสกิลที่ใช้ร่วมกันใน `~/.agents/skills` เปิดมันด้วยไอคอนเอกสารข้าง + ในแผงเอเจนต์ หรือ `omarchy agent instructions --edit` ซึ่งยังเชื่อมโยงมันเข้าไปในแต่ละ harness ที่เก็บไฟล์ส่วนกลางของตัวเองไว้ด้วย: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` ของ Copilot เป็นต้น Crush และ Amp อ่านลิงก์ `~/.config/AGENTS.md` ขณะที่ omp, Kimi และ DeepSeek Harness อ่าน `~/.agents/AGENTS.md` โดยตรง การเลือกเอเจนต์เริ่มต้นจะเชื่อมโยงมันด้วยเช่นกัน ไฟล์คำแนะนำที่คุณมีอยู่แล้วจะกลายเป็นไฟล์ที่ใช้ร่วมกันหากยังไม่มีไฟล์ดังกล่าวมาก่อน; มิฉะนั้นมันจะถูกเก็บไว้ข้างลิงก์ในชื่อ `.bak` รัน `omarchy agent instructions` เพื่อเชื่อมโยงใหม่หลังจากติดตั้งเอเจนต์อีกตัว

### แผงเอเจนต์

แถบบนสุดมีไอคอนเอเจนต์ ก่อนที่คุณจะตั้งค่าเอเจนต์ แผงของมันเสนอสามวิธีในการเริ่มต้น: ลงชื่อเข้าใช้การสมัครสมาชิก Claude, Codex, Grok, Gemini, Muse, Cursor หรือ Copilot หรือภายใต้ More แผนเขียนโค้ด OpenCode Go, MiniMax, Synthetic หรือ Z.ai; จ่ายตามการใช้งานจริงกับ Fireworks, OpenCode Zen and Go, OpenRouter หรือภายใต้ More DeepSeek หรือผู้ให้บริการรายอื่น ๆ ที่ OpenCode ลงชื่อเข้าใช้ได้ ซึ่งทั้งหมดรันใน OpenCode; หรือรันโมเดลที่ดีที่สุดสำหรับคอมพิวเตอร์ของคุณ เมื่อมีตัวที่เหมาะกับมัน ตัวแรกที่คุณทำเสร็จจะกลายเป็นเอเจนต์เริ่มต้นของคุณ และ + ในแผงจะเสนอสามวิธีเดียวกันในภายหลัง หลังจากนั้น แผงจะวางทุกการสมัครสมาชิกไว้ในหน้าเดียว: แต่ละเอเจนต์และบัญชีพร้อมแผนของมัน มิเตอร์สำหรับขีดจำกัด session 5 ชั่วโมงและรายสัปดาห์แต่ละอย่างพร้อมเวลาจนกว่าจะรีเซ็ต (วางเมาส์เหนือเพื่อดูเปอร์เซ็นต์ที่แน่นอน) หรือยอดคงเหลือแบบเติมเงินที่เหลืออยู่ ภายใต้บรรทัดที่หมุนเวียนผ่านสิ่งที่คุณใช้ไปในทุกตัว เช่น โทเค็นในสัปดาห์นี้และโมเดลที่คุณใช้มากที่สุด ภายใต้ _Make something cool_ มันเสนอ prompt เริ่มต้นสำหรับธีม ปลั๊กอิน แอป หรือเกมใหม่ที่มอบงานให้เอเจนต์เริ่มต้นของคุณ แอปถูกสร้างในแบบเดียวกับ Hype, Monologue และ Omacut ของ Omarchy เอง ใน C++ และ Qt Quick โดยทำตามสกิลเอเจนต์ omarchy-make-app และคอมไพเลอร์และชิ้นส่วน Qt ที่พวกมันต้องการได้รับการติดตั้งมาให้แล้ว เกมเป็นหน้า three.js เดียวใน `~/Games/vibes` โดยทำตามสกิลเอเจนต์ omarchy-make-game และทั้งหมดเปิดจากตัวเปิด Game Vibes เดียวในธีมปัจจุบัน; พวกมันโหลด three.js จากเว็บ ดังนั้นจึงต้องมีการเชื่อมต่อจึงจะเริ่มได้ Claude Code, Codex, Grok, Kimi, Cursor และโควตา Grok Bot ของมัน, GitHub Copilot, Muse, Gemini (ผ่าน Antigravity) และ Devin ได้รับการครอบคลุมมาตั้งแต่แรกพร้อมขีดจำกัดของพวกมัน, Kimchi พร้อมแผน เครดิตเติมเงิน และงบการใช้จ่ายของมัน และ Hermes, Mistral Vibe และ Qwen Code แสดง session และโทเค็นของพวกมันเมื่อคุณได้ใช้งานพวกมันแล้ว แผนและคีย์ของผู้ให้บริการที่คุณใช้ผ่าน pi, omp หรือ opencode ก็ปรากฏเช่นกัน: OpenCode Zen and Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan และ Synthetic พร้อมขีดจำกัดของพวกมัน; OpenRouter และ DeepSeek พร้อมยอดคงเหลือแบบเติมเงินของพวกมัน; Fireworks พร้อมยอดการใช้จ่ายในช่วง 30 วันที่ผ่านมาของมัน โมเดลเขียนโค้ดที่คุณรันบนฮาร์ดแวร์ของคุณเองได้บรรทัดของตัวเอง และโทเค็นของพวกมันก็นับรวมในยอดรวมด้วย ดังที่อธิบายภายใต้ [โมเดลในเครื่อง](#local-models) เอเจนต์ทุกตัวถูกนับเพียงครั้งเดียว ภายใต้ผู้ที่เรียกเก็บเงินจากมัน ไม่ว่าคุณจะขับเคลื่อนมันผ่าน harness กี่ตัวก็ตาม

คลิกซ้ายที่ไอคอนแถบหรือกด `Super + Ctrl + X` เพื่อเปิดแผง คลิกขวาเพื่อเปิดเอเจนต์เริ่มต้นของคุณ และคลิกกลางเพื่อรีเฟรช บันทึกการใช้งานที่อยู่เบื้องหลังมันถูกสร้างใหม่ทุก 15 นาทีโดย `omarchy agent usage update` และแผงยังสามารถรวมการใช้งานจากเครื่องอื่น ๆ ของคุณผ่านโฟลเดอร์ที่ซิงค์ไว้ได้ ดู README ภายใต้ `$OMARCHY_PATH/shell/plugins/agents/` สำหรับการตั้งค่าทั้งหมด

### การสมัครสมาชิกหลายรายการ

หากคุณจ่ายเงินสำหรับแผน Claude, Codex หรือ Grok มากกว่าหนึ่งแผน — เช่น Max ส่วนตัวและอีกอันสำหรับงาน — Omarchy สามารถให้พวกมันทั้งหมดลงชื่อเข้าใช้อยู่และย้ายไปมาระหว่างพวกมันได้ เพิ่มการสมัครสมาชิกด้วย + ในแผงเอเจนต์ ซึ่งจะแนะนำคุณตลอดขั้นตอนตรงนั้น หรือด้วย `omarchy agent account add claude Work` (หรือ `codex` หรือ `grok`) + และคำสั่งเดียวกันยังลงชื่อเข้าใช้ Gemini (`gemini`) และ OpenCode (`opencode`) และบันทึกคีย์ API ของ Fireworks (`fireworks`) หรือ OpenRouter (`openrouter`) ใน OpenCode; คำสั่งยังลงชื่อเข้าใช้ Copilot (`copilot`), Cursor (`cursor`) และ Muse (`muse`) ด้วย สิ่งเหล่านั้นเก็บการลงชื่อเข้าใช้เพียงครั้งเดียวแต่ละตัว มันจะติดตั้ง CLI หากยังขาดอยู่ บัญชีแรกสำหรับผู้ให้บริการจะลงชื่อเข้าใช้ผ่านเบราว์เซอร์ปกติของคุณ ตรงตำแหน่งที่ CLI มองหาเสมอ ทุกบัญชีหลังจากนั้นจะลงชื่อเข้าใช้ผ่านหน้าต่างส่วนตัว เพื่อไม่ให้บัญชีที่เบราว์เซอร์ของคุณลงชื่อเข้าใช้อยู่แล้วถูกหยิบขึ้นมาโดยผิดพลาด; ลงชื่อเข้าใช้ที่นั่นในฐานะบัญชีที่คุณกำลังเพิ่ม และปิดหน้าต่างส่วนตัวที่คุณเปิดค้างไว้ก่อน อย่าออกจากระบบของ CLI เพื่อทำสิ่งนี้เด็ดขาด: การออกจากระบบจะเพิกถอนการลงชื่อเข้าใช้ที่บันทึกไว้ และบัญชีนั้นจะต้องถูกเพิ่มอีกครั้ง

หากต้องการคัดลอกข้อมูลลงชื่อเข้าใช้การสมัครสมาชิกของคุณไปยังเครื่อง Omarchy อีกเครื่องผ่าน SSH ให้รัน `omarchy agent account copy user@laptop` ผู้ส่งจะจัดหาตัวรับชั่วคราวเมื่อปลายทางยังไม่ได้ติดตั้งไว้ ดังนั้นเครื่อง Omarchy รุ่นเก่ากว่าสามารถรับบัญชีได้โดยไม่ต้องอัปเดต ตัวรับที่ติดตั้งไว้จะมีความสำคัญเหนือกว่า สิ่งนี้คัดลอกการสมัครสมาชิก Claude, Codex และ Grok ทั้งหมด; เพิ่มชื่อผู้ให้บริการเพื่อเลือกพวกมัน เช่นใน `omarchy agent account copy laptop claude` ชื่อบัญชีและ ID คำสั่งตรงกับต้นทาง รวมถึงบัญชีที่มีอยู่แล้วบนปลายทาง บัญชีปลายทางที่ไม่เกี่ยวข้องจะได้รับคำต่อท้ายเป็นตัวเลขหากชื่อของพวกมันขัดแย้งกัน และการตั้งค่า สกิล ปลั๊กอิน และประวัติการสนทนายังคงอยู่ในเครื่องแต่ละเครื่อง

ข้อมูลประจำตัวปลายทางที่มีอยู่จะถูกเก็บไว้ บัญชีต้นทางที่ลงชื่อเข้าใช้อยู่ที่นั่นแล้วจะมีชื่อที่ซิงค์กันโดยไม่แทนที่ข้อมูลประจำตัวของมัน; บัญชีอื่น ๆ จะถูกเพิ่มควบคู่ไปกับมัน หากต้องการแทนที่ข้อมูลประจำตัวที่บันทึกไว้สำหรับบัญชีที่ตรงกัน ให้ใช้ `omarchy agent account copy --replace laptop claude` หลังจากออกจาก session ของบัญชีนั้นบนปลายทาง ปลายทางใหม่เอี่ยมยังได้รับบัญชีที่ใช้งานอยู่และการตั้งค่าการสลับของต้นทางด้วย; ปลายทางที่ตั้งค่าไว้แล้วจะเก็บของตัวเองไว้

ข้อมูลประจำตัวเดินทางผ่าน SSH และถูกเก็บไว้ในไฟล์ส่วนตัวบนปลายทาง ดังนั้นจงคัดลอกไปยังเครื่องที่คุณไว้วางใจเท่านั้น นี่เป็นการคัดลอกครั้งเดียว ไม่ใช่การซิงโครไนซ์อย่างต่อเนื่อง โทเค็นรีเฟรชของ Codex อาจถูกหมุนเวียนโดยเครื่องอื่น ทำให้การเข้าสู่ระบบที่คัดลอกมาต้องต่ออายุ; การลงชื่อเข้าใช้แยกกันยังคงเป็นตัวเลือกที่น่าเชื่อถือที่สุดสำหรับการใช้งานพร้อมกันบนหลายเครื่อง ดู [คำแนะนำการยืนยันตัวตนบัญชีของ Codex](https://developers.openai.com/codex/auth/ci-cd-auth)

มีบัญชีเดียวต่อผู้ให้บริการที่ใช้งานอยู่ และทุก session ใหม่จะเริ่มต้นในฐานะบัญชีนั้น: `cx`, `cy`, `claude`, `codex` หรือ `grok` เปล่า ๆ สิ่งใดก็ตามที่เปิดผ่าน `omarchy agent` และสคริปต์หรือโปรแกรมแก้ไขที่พบ CLI บน `PATH` สลับด้วย `omarchy agent account use work` (และกลับด้วย `omarchy agent account use main`) หรือในแผงโดยกดหมายเลขของบัญชีแล้วกด `Enter` (หรือคลิกดาวของมัน) session ของ Claude ที่กำลังทำงานอยู่ก็สลับเช่นกัน ตั้งแต่ข้อความถัดไปของพวกมัน: ทุก session ของ Claude รันใน `~/.claude` ซึ่งถือข้อมูลลงชื่อเข้าใช้ของบัญชีที่ใช้งานอยู่เสมอ session ของ Claude ที่เริ่มในโฟลเดอร์ของบัญชีเองโดย Omarchy รุ่นเก่ากว่าจะถือข้อมูลลงชื่อเข้าใช้นั้นไว้จนกว่าจะออก ดังนั้นการสลับจะระบุชื่อ session เหล่านั้นและเสร็จสิ้นด้วยตัวเองเมื่อพวกมันหายไป session ของ Codex และ Grok ที่กำลังทำงานอยู่จะยังคงอยู่ในบัญชีที่พวกมันเริ่มต้นด้วย ประวัติการสนทนา การตั้งค่า สกิล และปลั๊กอินถูกใช้ร่วมกันระหว่างบัญชี ดังนั้น `claude --continue` ในโฟลเดอร์เดียวกันจะดำเนินการต่อจากจุดที่คุณค้างไว้บนบัญชีใหม่

เมื่อมีมากกว่าหนึ่งบัญชี แผงจะแสดงขีดจำกัดของแต่ละบัญชีเคียงข้างกัน โดยมีดาวที่เติมเต็มอยู่บนตัวที่ใช้งานอยู่ Omarchy จะแจ้งเตือนคุณเมื่อบัญชีที่ใช้งานอยู่ผ่าน 95% ของขีดจำกัด และการคลิกการแจ้งเตือนจะสลับไปยังบัญชีที่มีพื้นที่เหลือมากที่สุด มันจะไม่สลับด้วยตัวเอง เปลี่ยนเกณฑ์ด้วย `omarchy agent account threshold 90` หากทุกบัญชีเกินเกณฑ์ คุณจะได้รับแจ้งเพียงครั้งเดียว พร้อมกับว่าบัญชีใดจะว่างก่อน ขณะที่บัญชีที่ใช้งานอยู่ห่างจากเกณฑ์ไม่เกิน 15 จุด (80% ที่ค่าเริ่มต้น) ขีดจำกัดของมันจะถูกตรวจสอบทุกสามนาทีแทนที่จะเป็นทุก 15 นาที

`omarchy agent account list` แสดงทุกบัญชีและขีดจำกัดล่าสุดของมัน `omarchy agent account remove work` ลืมบัญชีหนึ่ง และ `omarchy agent account rename primary Hey` เปลี่ยนชื่อบัญชีหนึ่ง (หรือคลิกชื่อบัญชีในแผง) คำสั่งเหล่านี้ทำงานกับบัญชีของเอเจนต์เริ่มต้นของคุณ; หากต้องการเข้าถึงผู้ให้บริการรายอื่น ให้ระบุชื่อมันก่อน เช่นใน `omarchy agent account use codex side` ข้อมูลเข้าสู่ระบบที่คุณมีอยู่แล้วใน `~/.claude` หรือ `~/.codex` คือบัญชี _Main_ ของ Codex ยังคงอยู่ที่เดิม; ของ Claude รออยู่ในโฟลเดอร์ของตัวเองขณะที่บัญชีอื่นใช้งานอยู่ บัญชีที่ไม่ได้ใช้งานมานานกว่าประมาณแปดชั่วโมงอาจแสดง _Sign-in required_; คลิกมันเพื่อลงชื่อเข้าใช้บัญชีนั้นอีกครั้งในแผงทันที หรือสลับไปยังมันและเริ่ม session ซึ่งจะรีเฟรชการลงชื่อเข้าใช้ด้วยตัวเอง เซิร์ฟเวอร์ MCP ที่คุณเพิ่มด้วย `claude mcp add` จะไปถึงทุกบัญชีของ Claude เนื่องจากพวกมันทั้งหมดรันใน `~/.claude`; สำหรับ Codex และ Grok เซิร์ฟเวอร์ที่คุณมีเมื่อมีการเพิ่มบัญชีจะตามไปกับบัญชีนั้น แต่เซิร์ฟเวอร์ในภายหลังจะไปถึงเฉพาะบัญชีที่คุณเพิ่มพวกมันเข้าไปเท่านั้น Claude Desktop เก็บการลงชื่อเข้าใช้ของตัวเอง และเครื่องมือ Codex หรือ Grok ที่กำหนดค่าด้วยเส้นทางสัมบูรณ์ไปยังไบนารี CLI จะไม่ทำตามการสลับ ค่า `CLAUDE_CONFIG_DIR`, `CODEX_HOME` หรือ `GROK_HOME` ที่ระบุอย่างชัดเจนจะมีความสำคัญเหนือบัญชีที่เลือก

### การวินิจฉัยการขัดข้อง

Omarchy เฝ้าดู systemd-coredump สำหรับการขัดข้องของกระบวนการ เมื่อคุณเลือกเอเจนต์เริ่มต้นแล้ว โปรแกรมใด ๆ ของคุณที่ dump core จะนำการแจ้งเตือน "Process crashed" มา — คลิกมัน และการขัดข้องจะถูกส่งให้เอเจนต์เริ่มต้นของคุณพร้อมกับสกิล omarchy-diagnose-crash ของ Omarchy ซึ่งจะนำเอเจนต์ผ่านการสร้างข้อเท็จจริงจาก core dump และตัดสินใจว่าการขัดข้องนั้นคุ้มค่าที่จะรายงานไปยัง upstream หรือไม่ คุณยังรันมันด้วยมือกับ PID ใด ๆ จาก `coredumpctl list` ด้วย `omarchy agent crash <pid>` ได้ด้วย

การเฝ้าดูเปิดอยู่ตามค่าเริ่มต้น ปิดมันภายใต้ _Trigger > Toggle > Crash Capture Off_ (หรือด้วย `omarchy toggle crash-capture`) และการแจ้งเตือนจะหยุด; `omarchy agent crash <pid>` ยังคงทำงานด้วยมือได้

การขัดข้องยังสามารถถูกปิดเสียงทีละโปรแกรมได้ ซึ่งเป็นสิ่งที่การวินิจฉัยเสนอให้คุณในตอนท้าย `omarchy crash mute hyprland` หยุดการแจ้งเตือนสำหรับโปรแกรมนั้นเท่านั้น `omarchy crash mute hyprland off` นำพวกมันกลับมา และ `omarchy crash mute` ด้วยตัวมันเองแสดงรายการสิ่งที่คุณปิดเสียงไว้ มันรับเส้นทางของไบนารีได้พอ ๆ กับชื่อของมัน ดังนั้น `omarchy crash mute /usr/bin/hyprland` จึงทำสิ่งเดียวกัน ใส่เครื่องหมายคำพูดชื่อที่มีช่องว่าง เช่นใน `omarchy crash mute 'Some App'` อย่างอื่นทุกอย่างยังคงแจ้งเตือน และโปรแกรมที่ปิดเสียงไว้ยังคงขัดข้อง — สิ่งนี้ซ่อนการเตือนความจำ มันไม่ได้แก้ไขอะไรเลย

### แอปบนเดสก์ท็อป

_Install > AI > Desktop_ มีแอป AI แบบกราฟิก: Amp Desktop, Antigravity Desktop, แอปเดสก์ท็อป ChatGPT, แอปเดสก์ท็อป Claude (เบต้า Linux ของ Anthropic พร้อมแท็บ Chat, Cowork และ Claude Code), Grok Bot สำหรับแชทกับโมเดลของ xAI, Herdr Desktop, Hermes Desktop, OpenClaw, แอปเดสก์ท็อป Perplexity และ T3 Code Grok Bot คือแอปแชทบนเดสก์ท็อป เอเจนต์เขียนโค้ดคือคำสั่ง `grok`

Hermes Desktop คือตัวที่ต้องรู้ เพราะเครื่องหนึ่งมี Hermes เดียว และเป็นของแอป: Hermes จะถูกติดตั้งผ่านแอปเท่านั้น และคำสั่ง `hermes` ที่เอเจนต์เริ่มต้นรันเป็นของแอป การเลือก Hermes เป็นเอเจนต์เริ่มต้นจะติดตั้งสิ่งเดียวกับที่รายการ _Install > AI > Desktop_ ทำ: แพ็กเกจ และ runtime ของ Hermes ภายใต้ `~/.hermes` ที่ตั้งค่าโดยตัวติดตั้งของ Hermes เอง ซึ่งใช้เวลาสองสามนาทีในครั้งแรก runtime นั้นคือ Hermes เดียวที่คำสั่ง `hermes` ในเทอร์มินัล เอเจนต์เริ่มต้น และแอปใช้ทั้งหมด และมันอัปเดตตัวเองด้วย `hermes update` แทนที่จะรอการเปิดตัวของ Omarchy การติดตั้งมันยังมอบธีม Omarchy ให้ Hermes เป็นสกินชื่อ `omarchy` ซึ่งทุกพื้นผิวของ Hermes จะทำตามเมื่อคุณเปลี่ยนธีม; เลือกอีกตัวภายใต้การตั้งค่า Appearance ของ Hermes หรือด้วย `/skin` หากคุณไม่อยากให้มันทำเช่นนั้น และ Omarchy จะปล่อยให้ตัวเลือกนั้นเป็นไปตามที่คุณเลือก การลบแอปภายใต้ _Remove > AI > Desktop_ จะปิด Hermes ก่อน รวมถึง gateway ด้วย นำ runtime นั้นไปด้วย และเก็บแชท ความทรงจำ และสกิลที่ Hermes เขียนให้ตัวเองไว้ เว้นแต่คุณจะบอกเป็นอย่างอื่น: มันจะถาม โดยค่าเริ่มต้นคือไม่ ว่าข้อมูลนั้นและการตั้งค่าการเชื่อมต่อของคุณควรหายไปด้วยหรือไม่

ประสบการณ์บนเดสก์ท็อปของ OpenClaw คือ Control UI ของมัน ซึ่งเปิดเป็นเว็บแอปที่สนับสนุนโดย gateway ในเครื่องของตัวเอง OpenClaw อาศัยอยู่ใน `~/.openclaw` และอัปเดตตัวเอง: ใช้ปุ่ม "Update Gateway" ของ Control UI หรือรัน `openclaw update` และ gateway จะรีสตาร์ทบนเวอร์ชันใหม่ Omarchy เพียงเลือกเวอร์ชันที่การติดตั้งใหม่จะเริ่มต้นจาก OpenClaw ยังสามารถเป็นเอเจนต์เริ่มต้นของคุณได้ด้วย: การเลือกมันด้วย `omarchy default agent openclaw` จะตั้งค่าสำเนาเดียวกันนั้นใน `~/.openclaw` และเอเจนต์จะเปิด UI เทอร์มินัลของ OpenClaw ที่เชื่อมกับ gateway ของมัน การลบ OpenClaw ภายใต้ _Remove > AI > Desktop_ จะนำบริการ gateway และแอปไปด้วย จากนั้นถามว่า `~/.openclaw` ควรหายไปด้วยหรือไม่ เนื่องจากที่นั่นเก็บแชทและข้อมูลประจำตัวของคุณไว้ควบคู่กับ OpenClaw เองและ runtime ของปลั๊กอินที่มันดาวน์โหลด; ค่าเริ่มต้นจะเก็บมันไว้ และการติดตั้ง OpenClaw อีกครั้งจะหยิบมันกลับขึ้นมา

Herdr Desktop คือแอปเดสก์ท็อป [Herdr](https://herdr.dev): spaces, tabs และ panes ของเทอร์มินัลและเอเจนต์เขียนโค้ดที่ยังคงทำงานอยู่ในแกนหลักของมันเมื่อคุณปิดหน้าต่าง มันมาจากตัวติดตั้งของ Herdr เองแทนที่จะเป็นแพ็กเกจ ดังนั้นมันจึงอยู่ใน `~/.local/share/herdr-app` นำแกนหลักของมันมาด้วยใน `~/.local/bin/herdr-core` เมื่อคุณยังไม่มี และอัปเดตทั้งสองตัวเอง มันอยู่ข้างคำสั่ง `herdr` ที่ Omarchy จัดส่งบน `Super + Ctrl + Return` แทนที่จะแทนที่มัน และได้รับคีย์โดยตรงของคำสั่งนั้น: `Alt + Return` และ `Alt + Shift + Return` แยก pane ลงหรือขวา `Alt + Escape` ปิดมัน `Ctrl + Alt + Arrow` ย้ายระหว่าง panes `Alt + 1..9` และ `Alt + Left/Right` เลือกแท็บ และ `Alt + Up/Down` ย้ายระหว่าง spaces `Ctrl + 1..9` เลือก space และ `Alt + Shift + Up/Down` ไล่ผ่านเอเจนต์ คีย์นำหน้า `Ctrl + Space` ยังคงเฉพาะเทอร์มินัล เนื่องจากแอปไม่สามารถถือคีย์ Ctrl เปล่า ๆ สำหรับลำดับได้ Omarchy เขียนสิ่งเหล่านี้ไปยัง `~/.config/herdr-app/keys.json` และ `omarchy-refresh-herdr-app` จะนำพวกมันกลับมา การติดตั้งมันจะเลือกธีม Omarchy ของ Herdr ซึ่งจะทำตามธีม Omarchy ของคุณต่อจากนั้น Herdr เก็บธีมหนึ่งสำหรับโหมดสว่างและอีกหนึ่งสำหรับโหมดมืด ดังนั้นหลังจากสลับระหว่างธีม Omarchy แบบมืดและแบบสว่าง ให้เลือก Omarchy ในตัวเลือกธีมของ Herdr อีกครั้งสำหรับอีกโหมดหนึ่ง

T3 Code รันจากรุ่น AppImage อย่างเป็นทางการใน `~/.local/share/t3code` แทนที่จะเป็นจากแพ็กเกจ ดังนั้นมันจึงอัปเดตตัวเอง การติดตั้งมันจะถามว่าจะเริ่มบน channel Stable หรือ Nightly; สลับในภายหลังในการตั้งค่าของ T3 Code เธรดและการตั้งค่าของคุณอยู่ใน `~/.t3` และการลบ T3 Code ภายใต้ _Remove > AI > Desktop_ จะนำพวกมันไปด้วย

### โมเดลในเครื่อง

รันโมเดลแบบเปิดบนเครื่องของคุณเองสำหรับเอเจนต์เขียนโค้ดของคุณ prompt และโค้ดของคุณยังคงอยู่บนเครื่อง; ไม่มีอะไรที่ส่งไปยังโมเดลออกจากเครื่อง เริ่มต้นด้วย:

```bash
omarchy models use best text
```

นั่นจะตั้งค่าโมเดลข้อความที่ดีที่สุดสำหรับเครื่องนี้ ซึ่งเป็นประเภทที่เอเจนต์ของคุณใช้ โมเดลรูปภาพ วิดีโอ และเพลงมีตัวที่ดีที่สุดของตัวเอง: `omarchy models use best image`, `video` หรือ `music` รัน `omarchy models use best` เพื่อดูตัวเลือกของแต่ละประเภทสำหรับเครื่องนี้

หรือเลือก + ในแผงเอเจนต์: ภายใต้ _Use a local model_ มันแสดงรายการโมเดลเขียนโค้ดทุกตัวที่เหมาะกับเครื่องนี้ โดยตัวที่แนะนำอยู่ก่อน Podman ซึ่งรันโมเดล มาพร้อมกับ Omarchy เช่นเดียวกับชุดเครื่องมือคอนเทนเนอร์ของ NVIDIA บนเครื่อง NVIDIA ซึ่งให้ GPU แก่พวกมัน; หากตัวใดตัวหนึ่งขาดหายไป การตั้งค่าครั้งแรกจะติดตั้งมัน จากนั้น Omarchy จะเลือกโมเดลที่แนะนำสำหรับเครื่องนี้ ดาวน์โหลดมัน และเริ่มมัน คาดว่าจะมีการดาวน์โหลดหลายสิบ GB และหน่วยความจำส่วนใหญ่ของเครื่องจะถูกใช้ขณะที่โมเดลทำงาน: Flash Next ใช้ประมาณ 100 GiB กับ context 256K เต็มของมัน หากโมเดลอื่นถือหน่วยความจำที่มันต้องการ มันจะถูกตั้งค่าในสภาพหยุดอยู่ พร้อมที่จะเริ่มเมื่อคุณหยุดตัวหนึ่ง โมเดลจะหยุดเมื่อออกจากระบบ; หยุดมันด้วยตัวเองเมื่อคุณต้องการหน่วยความจำสำหรับอย่างอื่น

`omarchy models list` แสดงตัวเลือกและอธิบายว่าทำไมบางตัวจึงไม่เหมาะ หากต้องการตั้งค่าอีกตัว ให้รัน `omarchy models use <recipe>` วันนี้ `qwen3.8-flash-next-gufo` และ `qwen3.8-27b-gufo` พร้อมใช้งานสำหรับเครื่อง Strix Halo 128 GB; ตัว 27B ใช้ประมาณ 40 GiB ดังนั้นจึงเหลือพื้นที่สำหรับงานอื่น บนแล็ปท็อป 64 GB ที่มี Arc B390 ของ Intel `qwen3.6-35b-a3b-llamacpp` รันในประมาณ 30 GiB สูตรและคำแนะนำใหม่มาพร้อมกับ `omarchy update` ผ่านแพ็กเกจ

โมเดลเขียนโค้ดที่คุณเพิ่มจะได้บรรทัดของตัวเองในแผงเอเจนต์ ข้างการสมัครสมาชิกของคุณ: play เพื่อเริ่มมัน pause เพื่อหยุดมันและปลดปล่อยหน่วยความจำของมัน เครื่องหมาย Tailscale เพื่อแชร์มันกับเครื่องอื่น ๆ บน tailnet ของคุณขณะที่มันทำงาน และปุ่มเทอร์มินัลเพื่อเปิดเอเจนต์ของคุณบนมัน บรรทัดของมันแสดงการดาวน์โหลด การโหลด หรือการหยุดในขณะที่ดำเนินไป และบอกเช่นนั้นเมื่อมีหน่วยความจำว่างไม่เพียงพอที่จะเริ่มมัน หรือเชื่อมโยงไปยังบันทึกของมันเมื่อมันหยุดด้วยข้อผิดพลาด หลายตัวสามารถรันพร้อมกันได้เมื่อพวกมันอยู่ในหน่วยความจำด้วยกันได้ กด Delete บนบรรทัดที่เลือกเพื่อลบโมเดลออกจากเครื่องนี้ รวมถึงการดาวน์โหลดทั้งหมด; + สามารถตั้งค่ามันอีกครั้ง โมเดลเขียนโค้ดที่ตั้งค่าจากเทอร์มินัลจะรออยู่ภายใต้ + จนกว่าคุณจะเพิ่มมัน และโมเดลที่เครื่องที่คุณจับคู่ด้วย (`omarchy models pair <host>`) รันก็เช่นกัน

โมเดลเขียนโค้ดทุกตัวที่คุณตั้งค่ายังได้รายการของตัวเองในตัวเปิดแอป ภายใต้ชื่อของโมเดลและพร้อมโลโก้ของผู้สร้าง ในแบบเดียวกับการลงชื่อเข้าใช้ Claude, Codex หรือ Grok เพิ่มรายการหนึ่ง มันเปิดเอเจนต์ของคุณบนโมเดลนั้น และเริ่มโมเดลก่อนหากมันยังไม่ทำงาน: เทอร์มินัลแสดงมันกำลังโหลดและส่งต่อให้เอเจนต์เมื่อมันพร้อม การลบโมเดลจะลบรายการของมัน

ไม่ใช่ทุกโมเดลสำหรับเขียนโค้ด โมเดลรูปภาพ วิดีโอ และเพลงเปิดใน Fantasi แทน ซึ่งเป็นแอปของ Omarchy สำหรับสร้างรูปภาพ วิดีโอ และเพลงด้วยโมเดลที่ทำงานบนเครื่องนี้ และได้รับการจัดการที่นั่นหรือด้วย `omarchy models`

โมเดลยังคงทำงานได้อย่างที่มันถูกตั้งค่าไว้ ดังนั้นการอัปเดต Omarchy จะไม่รีสตาร์ทตัวใดตัวหนึ่งภายใต้เอเจนต์ของคุณ เมื่อ Omarchy มี runtime ที่ใหม่กว่าหรือ weights ที่ใหม่กว่าสำหรับโมเดลที่คุณตั้งค่าไว้ บรรทัดของมันจะแสดงปุ่มอัปเดต: กดมันและโมเดลจะถูกตั้งค่าอีกครั้งในพื้นหลัง โดยดาวน์โหลดเฉพาะสิ่งที่เปลี่ยนแปลง และรีสตาร์ทบนเวอร์ชันใหม่ โมเดลที่หยุดอยู่จะยังคงหยุดอยู่ `omarchy models update` ทำเช่นเดียวกันสำหรับทุกโมเดลจากเทอร์มินัล

จากบรรทัดคำสั่ง `omarchy models start <recipe>` และ `omarchy models stop <recipe>` ทำเช่นเดียวกัน `omarchy models status` แสดงทุกโมเดล และ `omarchy agent --local-model <recipe>` เปิดโมเดลนั้นใน pi ไม่ว่าเอเจนต์เริ่มต้นของคุณจะเป็นอะไร หากต้องการให้โมเดลในเครื่องของคุณเป็นสิ่งที่ปุ่มลัดเอเจนต์ คอนโซล Quake และ _Make something_ เปิด ให้รัน `omarchy default agent local` หรือติดดาวโมเดลที่กำลังทำงานอยู่ในแผงเอเจนต์ pi ยังแสดงรายการทุกโมเดลที่คุณตั้งค่าไว้ และโมเดลบนเครื่องที่คุณจับคู่ด้วย ในตัวเลือกโมเดลของมันเอง ดังนั้น `pi` เปล่า ๆ จึงไปถึงพวกมันได้เช่นกัน ไคลเอนต์ที่เข้ากันได้กับ OpenAI ใด ๆ ก็เชื่อมต่อได้เช่นกัน: `status` แสดงที่อยู่ของแต่ละโมเดล (ตัวแรกคือ `http://127.0.0.1:11435/v1`) ชื่อสูตรคือโมเดล และคีย์อยู่ใน `~/.config/omarchy/agent-local/key`

`omarchy models remove <recipe>` ลบโมเดลและการดาวน์โหลดที่ไม่มีโมเดลอื่นใช้

runtime ของบุคคลที่สามจะถูกระบุด้วยผู้เผยแพร่ของมัน Omarchy รันทุกโมเดลโดยไม่มีการเข้าถึงเครือข่าย

### LLM ในเครื่อง

Omarchy แนะนำสองวิธีในการรันโมเดล LLM ในเครื่อง: LM Studio และ Ollama LM Studio ให้อินเทอร์เฟซ GUI สำหรับค้นหาโมเดลแบบ open-weight ติดตั้งพวกมัน และรันพวกมัน เป็นวิธีที่ดีในการเริ่มต้นได้อย่างง่ายดาย Ollama เสนอ CLI สำหรับทำเช่นเดียวกัน แต่หากคุณเพิ่งเริ่มต้นกับโมเดลในเครื่อง ฉันจะเริ่มต้นด้วย LM Studio ติดตั้ง LM Studio จาก _Install > AI > Desktop_ และ Ollama จาก _Install > AI > CLI_ ใน Omarchy Menu

### สกิลของ Omarchy

สกิลของเอเจนต์ช่วยให้ AI ใช้เครื่องมือเฉพาะในวิธีเฉพาะ และ Omarchy จัดส่งเจ็ดสกิลนั้น สกิล omarchy ครอบคลุมการปรับแต่งระบบ เช่น การปรับ config ของ Hyprland หรือการปรับแถบ omarchy-make-theme, omarchy-make-plugin, omarchy-make-app และ omarchy-make-game ครอบคลุมการสร้างสิ่งใหม่ omarchy-contribute ครอบคลุมการรายงานบั๊กหรือส่งการแก้ไขไปยัง upstream และ omarchy-diagnose-crash ทำงานผ่าน core dump ของการขัดข้อง พวกมันถูก symlink เข้าไปในไดเรกทอรีสกิลสำหรับ Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` และแต่ละ `~/.hermes/profiles/*/skills`) และตำแหน่งทั่วไป `~/.agents/skills` ดังนั้น harness ส่วนใหญ่จึงหยิบพวกมันขึ้นมาโดยอัตโนมัติ โฟลเดอร์สกิลของคุณเองที่มีชื่อเดียวกันจะมีความสำคัญเหนือกว่า

แต่คุณควรปฏิบัติต่อสกิลเหล่านี้เสมือนเป็นของทดลอง โมเดลที่แตกต่างกันจะใช้มันให้เกิดผลแตกต่างกัน ทางที่ดีที่สุดคือรันในโหมดวางแผนก่อน เพื่อให้คุณมีไอเดียว่าเอเจนต์อยากเปลี่ยนแปลงอะไร แล้วเตรียมพร้อมที่จะย้อนกลับการเปลี่ยนแปลงหรือแม้แต่เรียกใช้ `omarchy reinstall configs` หากเอเจนต์ทำทุกอย่างเละเทะ
