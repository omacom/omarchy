### การติดตั้งและการอัปเดตเอเจนต์

นอกจาก Hermes และ OpenClaw เอเจนต์เหล่านี้ใช้การติดตั้งแบบ lazy ของ mise: การเรียกใช้ครั้งแรกจะติดตั้ง CLI และการเรียกใช้ครั้งต่อ ๆ ไปจะใช้ซ้ำ mise ยังตรวจสอบด้วยว่าเอเจนต์ที่ติดตั้งไว้มีรุ่นใหม่หรือไม่ อย่างมากที่สุดหนึ่งครั้งทุกสี่ชั่วโมง ก่อนที่มันจะเริ่มทำงานหรือในเบื้องหลังที่พรอมต์ของเชลล์ หากการอัปเดตนั้นล้มเหลวหรือคุณออฟไลน์ รุ่นที่ติดตั้งไว้จะทำงาน `omarchy update` จะอัปเดตเอเจนต์ที่ติดตั้งไว้พร้อมกับส่วนที่เหลือของ Omarchy และ `mup` จะอัปเดตเฉพาะเครื่องมือที่ mise จัดการ

ตัวอัปเดตของเอเจนต์เอง เช่น `claude update`, `codex update` หรือปุ่มอัปเดตในแอป จะไม่อัปเดตการติดตั้งที่ mise จัดการ `codex update` จะล้มเหลว และ `claude update` อาจรายงานว่าสำเร็จขณะที่ติดตั้งสำเนาแยกต่างหากที่ mise ไม่ได้ติดตาม หากคุณต้องการใช้ตัวติดตั้งและตัวอัปเดตดั้งเดิมของเอเจนต์แทน ให้เพิ่มมันลงใน `disable_tools`; ดู [เครื่องมือ CLI ที่ติดตั้งไว้ล่วงหน้า](18-development-tools.md#preinstalled-cli-tools)

หากต้องการติดตั้งเครื่องมือ lazy ที่กำหนดค่าไว้ทั้งหมดก่อนที่คุณจะต้องการใช้ ให้รัน `mise install --include-lazy` ซึ่งรวมถึงเครื่องมือ CLI เริ่มต้นอื่น ๆ ของ Omarchy นอกเหนือจากเอเจนต์ด้วย ดู [เครื่องมือ CLI ที่ติดตั้งไว้ล่วงหน้า](18-development-tools.md#preinstalled-cli-tools) สำหรับการติดตั้งเครื่องมือเพียงตัวเดียวหรือการใช้การติดตั้งของคุณเอง

`grok` ติดตั้งผ่านแพ็กเกจ `grok` แบบ first-party ของ mise ในลักษณะเดียวกับ `claude` และ `codex` รัน `grok` หรือติดดาวให้มันในแผงเอเจนต์ ข้ามตัวติดตั้ง `curl | bash` บน x.ai เส้นทางนั้นจะวางสำเนาที่สองไว้ใน `~/.grok/bin`, นำหน้ามันบน `PATH` และเขียนทับ wrapper ของ Omarchy

`dsh` เปิด UI บนเบราว์เซอร์ของมันที่ `127.0.0.1:3080` โดยใช้ไดเรกทอรีที่เรียกใช้เป็นพื้นที่ทำงานเริ่มต้น UI บนเบราว์เซอร์ของมันไม่รับพรอมต์เริ่มต้น ดังนั้น `omarchy agent prompt` จะเปิดมันโดยมีพรอมต์อยู่บนคลิปบอร์ดของคุณให้วาง Omarchy เริ่มมันด้วยพรีเซ็ตสิทธิ์แบบไม่ต้องขออนุมัติของ DeepSeek DeepSeek Harness อัปโหลดบันทึกเซสชันไปยัง DeepSeek เมื่อคุณใช้ API โมเดลอย่างเป็นทางการของมัน; ปิดการทำงานนั้นได้ภายใต้ _Settings > General > Upload Session Log_ ใน UI บนเบราว์เซอร์ของมัน ข้อเสนอแนะที่คุณส่งให้มันจะถูกอัปโหลดไปพร้อมกับเซสชันด้วย เว้นแต่คุณจะเริ่มมันด้วย `DSH_TELEMETRY_MODE=DISABLED`

### เอเจนต์เริ่มต้น

เลือกเอเจนต์เริ่มต้นของคุณด้วยดาวข้างเอเจนต์ในแผงเอเจนต์ ซึ่งจะถูกเติมบนเอเจนต์เริ่มต้น หรือด้วย `omarchy default agent <name>` ซึ่งรับ harness ใด ๆ ที่ไม่มีบรรทัดอยู่ที่นั่นด้วย หากเอเจนต์ยังไม่ได้ติดตั้ง การเลือกมันจะติดตั้งมันก่อน และมันยังจะได้รับตัวเรียกใช้งานของตัวเองในตัวเรียกใช้แอป ถัดจาก Agent ด้วย Omarchy ที่ติดตั้งใหม่จะเชิญให้คุณตั้งค่าหนึ่งตัวด้วยการแจ้งเตือนเพียงครั้งเดียว ซึ่งจะเปิดแผงเอเจนต์

การเลือก Claude ยังพยายามตั้งค่าส่วนขยายเบราว์เซอร์ของมันสำหรับ Chromium, Chrome, Brave, Brave Origin และ Edge ด้วย การตั้งค่าส่วนขยายใช้กับผู้ใช้ทั้งหมดและอาจขอรหัสผ่านระบบของคุณ; การยกเลิกหรือการติดตั้งส่วนขยายที่ล้มเหลวยังคงเลือกและเรียกใช้ Claude อยู่ รีสตาร์ทเบราว์เซอร์ของคุณ เปิดใช้งานส่วนขยายหากได้รับแจ้ง และลงชื่อเข้าใช้ Claude เพื่อเชื่อมต่อให้เสร็จสมบูรณ์ รัน `/chrome` ใน Claude เพื่อตรวจสอบการเชื่อมต่อ Firefox และ Zen ไม่รองรับส่วนขยายนี้ หาก Claude เป็นค่าเริ่มต้นของคุณอยู่แล้วก่อนที่จะมีการเพิ่มการตั้งค่านี้ ให้เลือกมันอีกครั้งเพื่อติดตั้งส่วนขยาย

เมื่อคุณเลือกแล้ว `Super + Shift + Ctrl + A` จะเรียกใช้เอเจนต์เริ่มต้นในหน้าต่างเทอร์มินัลเฉพาะ (หรือเปิดตัวเลือกหากคุณยังไม่ได้เลือก) คุณยังสามารถเรียกใช้มันเข้าสู่งานโดยตรงด้วย `omarchy agent prompt "Review this project"` Freebuff และ DeepSeek Harness ไม่รับพรอมต์เริ่มต้น ดังนั้นพวกมันจะเปิดโดยมีพรอมต์อยู่บนคลิปบอร์ดของคุณให้วางแทน เอเจนต์ที่เรียกใช้ด้วยวิธีนี้จะทำงานโดยไม่มีผู้ดูแลในโหมดไม่หยุดเพื่อถามของแต่ละตัว ดังนั้นจงเตรียมพร้อมให้พวกมันลงมือทำสิ่งต่าง ๆ จริง ๆ! MiniMax Code ไม่มีโหมดดังกล่าวสำหรับเซสชันแบบโต้ตอบของมัน ดังนั้นมันจะขอสิทธิ์ตามปกติ และเนื่องจากเอเจนต์ปฏิเสธที่จะจดจำความเชื่อถือสำหรับไดเรกทอรีบ้านของคุณ การเรียกใช้จาก `$HOME` จะเริ่มใน `~/Work` แทน

ยังมีทางลัดบนเทอร์มินัลด้วย: `a` รันเอเจนต์เริ่มต้นแบบอินไลน์ในเทอร์มินัลปัจจุบัน ขณะที่ `c`, `cx` และ `cy` เริ่ม OpenCode, Claude Code และ Codex โดยตรง (อีกครั้งในโหมดอนุมัติอัตโนมัติของพวกมัน) การเปลี่ยนธีมจะซิงค์ไปยังเอเจนต์ด้วย: Claude Code, Pi, OpenCode และ Hermes (เมื่อ Omarchy ติดตั้งมันแล้ว) ล้วนทำตามเมื่อคุณเปลี่ยนธีม Omarchy

### คำสั่งสำหรับเอเจนต์ของคุณ

กฎส่วนตัวสำหรับทุกเอเจนต์อยู่ใน `~/.agents/AGENTS.md` ถัดจากทักษะที่ใช้ร่วมกันใน `~/.agents/skills` เปิดมันด้วยไอคอนเอกสารข้าง + ในแผงเอเจนต์ หรือ `omarchy agent instructions --edit` ซึ่งยังลิงก์มันเข้าไปในแต่ละ harness ที่เก็บไฟล์ส่วนกลางของตัวเองไว้: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` ของ Copilot และอื่น ๆ Crush และ Amp อ่านลิงก์ `~/.config/AGENTS.md` ขณะที่ omp, Kimi และ DeepSeek Harness อ่าน `~/.agents/AGENTS.md` โดยตรง การเลือกเอเจนต์เริ่มต้นก็ลิงก์มันด้วย ไฟล์คำสั่งที่คุณมีอยู่แล้วจะกลายเป็นไฟล์ที่ใช้ร่วมกันหากยังไม่มีมาก่อน; มิฉะนั้นมันจะถูกเก็บไว้ข้างลิงก์ในชื่อ `.bak` รัน `omarchy agent instructions` เพื่อลิงก์ใหม่หลังจากติดตั้งเอเจนต์อื่น

### แผงเอเจนต์

แถบด้านบนมีไอคอนเอเจนต์ ก่อนที่คุณจะตั้งค่าเอเจนต์ แผงของมันเสนอสามวิธีในการเริ่มต้น: ลงชื่อเข้าใช้การสมัครสมาชิก Claude, Codex, Grok, Gemini, Muse, Cursor หรือ Copilot หรือภายใต้ More แผนเขียนโค้ด OpenCode Go, MiniMax, Synthetic หรือ Z.ai; จ่ายตามการใช้งานด้วย Fireworks, OpenCode Zen and Go, OpenRouter หรือภายใต้ More DeepSeek หรือผู้ให้บริการรายอื่นใดที่ OpenCode ลงชื่อเข้าใช้ได้ ทั้งหมดทำงานใน OpenCode; หรือรันโมเดลที่ดีที่สุดสำหรับคอมพิวเตอร์ของคุณ เมื่อมีตัวที่เหมาะกับมัน ตัวแรกที่คุณทำเสร็จจะกลายเป็นเอเจนต์เริ่มต้นของคุณ และ + ในแผงเสนอสามวิธีเดียวกันในภายหลัง หลังจากนั้น แผงจะวางทุกการสมัครสมาชิกไว้ในหน้าเดียว: แต่ละเอเจนต์และบัญชีพร้อมแผนของมัน มิเตอร์สำหรับขีดจำกัดเซสชัน 5 ชั่วโมงและรายสัปดาห์ของมันพร้อมเวลาจนกว่าจะรีเซ็ต (วางเมาส์เหนือเพื่อดูเปอร์เซ็นต์ที่แน่นอน) หรือยอดคงเหลือแบบเติมเงินที่เหลือ ภายใต้บรรทัดที่หมุนเวียนผ่านสิ่งที่คุณใช้ไปในทั้งหมดนั้น เช่น โทเคนในสัปดาห์นี้และโมเดลที่คุณใช้มากที่สุด ภายใต้ _Make something cool_ มันเสนอพรอมต์เริ่มต้นสำหรับธีม ปลั๊กอิน แอป หรือเกมใหม่ที่มอบงานนั้นให้เอเจนต์เริ่มต้นของคุณ แอปถูกสร้างในแบบเดียวกับที่ Hype, Monologue และ Omacut ของ Omarchy เองถูกสร้าง ใน C++ และ Qt Quick โดยทำตามทักษะเอเจนต์ omarchy-make-app และคอมไพเลอร์และชิ้นส่วน Qt ที่พวกมันต้องการได้รับการติดตั้งมาให้ เกมเป็นหน้า three.js เดี่ยวใน `~/Games/vibes` โดยทำตามทักษะเอเจนต์ omarchy-make-game และทั้งหมดเปิดจากตัวเรียกใช้งาน Game Vibes ตัวเดียวในธีมปัจจุบัน; พวกมันโหลด three.js จากเว็บ ดังนั้นพวกมันจึงต้องการการเชื่อมต่อเพื่อเริ่มต้น Claude Code, Codex, Grok, Kimi, Cursor และโควตา Grok Bot ของมัน, GitHub Copilot, Muse, Gemini (ผ่าน Antigravity) และ Devin ได้รับการครอบคลุมตั้งแต่ต้นพร้อมขีดจำกัดของพวกมัน, Kimchi พร้อมแผน เครดิตเติมเงิน และงบการใช้จ่ายของมัน และ Hermes, Mistral Vibe และ Qwen Code จะแสดงเซสชันและโทเคนของพวกมันเมื่อคุณได้ใช้พวกมันแล้ว แผนและคีย์ของผู้ให้บริการที่คุณใช้ผ่าน pi, omp หรือ opencode ก็ปรากฏเช่นกัน: OpenCode Zen and Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan และ Synthetic พร้อมขีดจำกัดของพวกมัน; OpenRouter และ DeepSeek พร้อมยอดคงเหลือแบบเติมเงินของพวกมัน; Fireworks พร้อมการใช้จ่ายของมันในช่วง 30 วันที่ผ่านมา โมเดลเขียนโค้ดที่คุณรันบนฮาร์ดแวร์ของคุณเองจะมีบรรทัดของตัวเอง และโทเคนของพวกมันก็นับรวมในยอดรวมด้วย ดังที่อธิบายภายใต้ [โมเดลภายในเครื่อง](#local-models) ทุกเอเจนต์ถูกนับเพียงครั้งเดียว ภายใต้ผู้ที่เรียกเก็บเงินมัน ไม่ว่าคุณจะขับมันผ่านกี่ harness ก็ตาม

คลิกซ้ายที่ไอคอนแถบหรือกด `Super + Ctrl + X` สำหรับแผง คลิกขวาเพื่อเรียกใช้เอเจนต์เริ่มต้นของคุณ และคลิกกลางเพื่อรีเฟรช บันทึกการใช้งานที่อยู่เบื้องหลังมันถูกสร้างใหม่ทุก 15 นาทีโดย `omarchy agent usage update` และแผงยังสามารถรวมการใช้งานจากเครื่องอื่น ๆ ของคุณผ่านโฟลเดอร์ที่ซิงค์ได้ ดู README ภายใต้ `$OMARCHY_PATH/shell/plugins/agents/` สำหรับการตั้งค่าทั้งหมด

### การสมัครสมาชิกหลายรายการ

หากคุณจ่ายสำหรับแผน Claude, Codex หรือ Grok มากกว่าหนึ่งแผน — เช่นแผน Max ส่วนตัวและแผนสำหรับงาน — Omarchy สามารถให้พวกมันทั้งหมดลงชื่อเข้าใช้อยู่และย้ายระหว่างกันได้ เพิ่มการสมัครสมาชิกด้วย + ในแผงเอเจนต์ ซึ่งจะแนะนำคุณตลอดขั้นตอนตรงนั้น หรือด้วย `omarchy agent account add claude Work` (หรือ `codex` หรือ `grok`) + และคำสั่งเดียวกันลงชื่อเข้าใช้ Gemini (`gemini`) และ OpenCode (`opencode`) และบันทึกคีย์ API ของ Fireworks (`fireworks`) หรือ OpenRouter (`openrouter`) ใน OpenCode; คำสั่งยังลงชื่อเข้าใช้ Copilot (`copilot`), Cursor (`cursor`) และ Muse (`muse`) ด้วย พวกนั้นเก็บการลงชื่อเข้าใช้เพียงหนึ่งรายการต่อราย มันจะติดตั้ง CLI หากขาดไป บัญชีแรกสำหรับผู้ให้บริการจะลงชื่อเข้าใช้ผ่านเบราว์เซอร์ปกติของคุณ ตรงที่ CLI มองหาเสมอ ทุกบัญชีหลังจากนั้นจะลงชื่อเข้าใช้ผ่านหน้าต่างส่วนตัว ดังนั้นบัญชีที่เบราว์เซอร์ของคุณลงชื่อเข้าใช้อยู่แล้วจะไม่ถูกหยิบขึ้นมาโดยผิดพลาด; ลงชื่อเข้าใช้ที่นั่นในฐานะบัญชีที่คุณกำลังเพิ่ม และปิดหน้าต่างส่วนตัวใด ๆ ที่คุณเปิดไว้อยู่ก่อน อย่าออกจากระบบ CLI เพื่อทำสิ่งนี้เด็ดขาด: การออกจากระบบจะเพิกถอนการลงชื่อเข้าใช้ที่บันทึกไว้ และบัญชีนั้นจะต้องถูกเพิ่มอีกครั้ง

หากต้องการคัดล็อกการเข้าสู่ระบบการสมัครสมาชิกของคุณไปยังเครื่อง Omarchy อื่นผ่าน SSH ให้รัน `omarchy agent account copy user@laptop` ผู้ส่งจะจัดหาตัวรับชั่วคราวเมื่อปลายทางยังไม่ได้ติดตั้งไว้ ดังนั้นเครื่อง Omarchy รุ่นเก่ากว่าสามารถรับบัญชีได้โดยไม่ต้องอัปเดต ตัวรับที่ติดตั้งไว้จะมีความสำคัญเหนือกว่า สิ่งนี้คัดลอกการสมัครสมาชิก Claude, Codex และ Grok ทั้งหมด; เพิ่มชื่อผู้ให้บริการเพื่อเลือกพวกมัน เช่นใน `omarchy agent account copy laptop claude` ชื่อบัญชีและ ID คำสั่งตรงกับต้นทาง รวมถึงบัญชีที่มีอยู่แล้วบนปลายทาง บัญชีปลายทางที่ไม่เกี่ยวข้องจะได้รับส่วนต่อท้ายเป็นตัวเลขหากชื่อของพวกมันขัดกัน และการตั้งค่า ทักษะ ปลั๊กอิน และประวัติการสนทนาจะคงอยู่ภายในเครื่องแต่ละเครื่อง

ข้อมูลประจำตัวที่มีอยู่ของปลายทางจะถูกเก็บไว้ บัญชีต้นทางที่ลงชื่อเข้าใช้ที่นั่นอยู่แล้วจะมีชื่อของมันถูกซิงค์โดยไม่แทนที่ข้อมูลประจำตัวของมัน; บัญชีอื่น ๆ จะถูกเพิ่มควบคู่ไปกับมัน หากต้องการแทนที่ข้อมูลประจำตัวที่บันทึกไว้สำหรับบัญชีที่ตรงกัน ให้ใช้ `omarchy agent account copy --replace laptop claude` หลังจากออกจากเซสชันของบัญชีนั้นบนปลายทาง ปลายทางใหม่ยังจะได้รับบัญชีที่ใช้งานอยู่และการตั้งค่าการสลับของต้นทางด้วย; ปลายทางที่ตั้งค่าไว้แล้วจะเก็บของตัวเองไว้

ข้อมูลประจำตัวเดินทางผ่าน SSH และถูกเก็บไว้ในไฟล์ส่วนตัวบนปลายทาง ดังนั้นให้คัดลอกไปยังเครื่องที่คุณเชื่อถือเท่านั้น นี่เป็นการคัดลอกเพียงครั้งเดียว ไม่ใช่การซิงโครไนซ์ต่อเนื่อง โทเคนรีเฟรชของ Codex สามารถถูกหมุนเวียนโดยเครื่องอื่น ทำให้การเข้าสู่ระบบที่คัดลอกมาต้องต่ออายุ; การลงชื่อเข้าใช้แยกกันยังคงเป็นตัวเลือกที่น่าเชื่อถือที่สุดสำหรับการใช้งานพร้อมกันบนหลายเครื่อง ดู [คำแนะนำการยืนยันตัวตนบัญชีของ Codex](https://developers.openai.com/codex/auth/ci-cd-auth)

บัญชีหนึ่งบัญชีต่อผู้ให้บริการที่ใช้งานอยู่ และทุกเซสชันใหม่จะเริ่มเป็นบัญชีนั้น: `cx`, `cy`, `claude`, `codex` หรือ `grok` แบบธรรมดา อะไรก็ตามที่เรียกใช้ผ่าน `omarchy agent` และสคริปต์หรือตัวแก้ไขที่พบ CLI บน `PATH` สลับด้วย `omarchy agent account use work` (และกลับด้วย `omarchy agent account use main`) หรือในแผงโดยกดหมายเลขของบัญชีแล้วกด `Enter` (หรือคลิกดาวของมัน) เซสชัน Claude ที่กำลังทำงานก็สลับด้วย ตั้งแต่ข้อความถัดไปของพวกมัน: ทุกเซสชัน Claude ทำงานใน `~/.claude` ซึ่งถือการลงชื่อเข้าใช้ของบัญชีที่ใช้งานอยู่เสมอ เซสชัน Claude ที่เริ่มในโฟลเดอร์ของบัญชีเองโดย Omarchy รุ่นเก่ากว่าจะถือการลงชื่อเข้าใช้นั้นจนกว่ามันจะออก ดังนั้นการสลับจะระบุชื่อเซสชันเหล่านั้นและเสร็จสิ้นด้วยตัวเองเมื่อพวกมันจากไป เซสชัน Codex และ Grok ที่กำลังทำงานจะคงอยู่กับบัญชีที่พวกมันเริ่มต้นด้วย ประวัติการสนทนา การตั้งค่า ทักษะ และปลั๊กอินถูกใช้ร่วมกันข้ามบัญชี ดังนั้น `claude --continue` ในโฟลเดอร์เดียวกันจะหยิบสิ่งที่คุณค้างไว้บนบัญชีใหม่ขึ้นมาต่อ

ด้วยบัญชีมากกว่าหนึ่งบัญชี แผงจะแสดงขีดจำกัดของแต่ละบัญชีเคียงข้างกัน โดยมีดาวที่เติมบนบัญชีที่กำลังใช้งาน Omarchy จะแจ้งเตือนคุณเมื่อบัญชีที่ใช้งานอยู่ผ่าน 95% ของขีดจำกัด และคลิกการแจ้งเตือนจะสลับไปยังบัญชีที่มีพื้นที่เหลือมากที่สุด มันจะไม่สลับด้วยตัวเอง เปลี่ยนเกณฑ์ด้วย `omarchy agent account threshold 90` หากทุกบัญชีเกินเกณฑ์ คุณจะได้ยินเกี่ยวกับมันเพียงครั้งเดียว พร้อมกับบัญชีใดจะว่างก่อน ขณะที่บัญชีที่ใช้งานอยู่ภายใน 15 คะแนนจากเกณฑ์ของมัน (80% ที่ค่าเริ่มต้น) ขีดจำกัดของมันจะถูกตรวจสอบทุกสามนาทีแทนที่จะเป็นทุก 15 นาที

`omarchy agent account list` แสดงทุกบัญชีและขีดจำกัดล่าสุดของมัน `omarchy agent account remove work` ลืมหนึ่งบัญชี และ `omarchy agent account rename primary Hey` เปลี่ยนชื่อหนึ่งบัญชี (หรือคลิกชื่อบัญชีในแผง) คำสั่งเหล่านี้ทำงานบนบัญชีของเอเจนต์เริ่มต้นของคุณ; หากต้องการเข้าถึงผู้ให้บริการรายอื่น ให้ระบุชื่อมันก่อน เช่นใน `omarchy agent account use codex side` การเข้าสู่ระบบที่คุณมีอยู่แล้วใน `~/.claude` หรือ `~/.codex` คือบัญชี _Main_ ของ Codex จะคงอยู่ที่เดิม; ของ Claude จะรอในโฟลเดอร์ของตัวเองขณะที่บัญชีอื่นใช้งานอยู่ บัญชีที่ไม่ได้ใช้เป็นเวลามากกว่าประมาณแปดชั่วโมงสามารถแสดง _Sign-in required_; คลิกมันเพื่อลงชื่อบัญชีนั้นเข้าใช้อีกครั้งในแผง หรือสลับไปยังมันและเริ่มเซสชัน ซึ่งจะรีเฟรชการลงชื่อเข้าใช้ด้วยตัวเอง เซิร์ฟเวอร์ MCP ที่คุณเพิ่มด้วย `claude mcp add` จะเข้าถึงทุกบัญชี Claude เนื่องจากพวกมันทั้งหมดทำงานใน `~/.claude`; สำหรับ Codex และ Grok เซิร์ฟเวอร์ที่คุณมีเมื่อบัญชีถูกเพิ่มจะตามไปยังมัน แต่เซิร์ฟเวอร์ในภายหลังจะเข้าถึงเฉพาะบัญชีที่คุณเพิ่มพวกมันในนั้น Claude Desktop เก็บการลงชื่อเข้าใช้ของตัวเองไว้ และเครื่องมือ Codex หรือ Grok ที่กำหนดค่าด้วยเส้นทางสัมบูรณ์ไปยังไบนารี CLI จะไม่ทำตามการสลับ `CLAUDE_CONFIG_DIR`, `CODEX_HOME` หรือ `GROK_HOME` ที่ระบุอย่างชัดเจนจะมีความสำคัญเหนือบัญชีที่เลือก

### การวินิจฉัยการขัดข้อง

Omarchy เฝ้าดู systemd-coredump สำหรับการขัดข้องของกระบวนการ เมื่อคุณเลือกเอเจนต์เริ่มต้นแล้ว โปรแกรมใด ๆ ของคุณที่ dump core จะนำการแจ้งเตือน "Process crashed" มา — คลิกมัน และการขัดข้องจะถูกส่งให้เอเจนต์เริ่มต้นของคุณพร้อมกับทักษะ omarchy-diagnose-crash ของ Omarchy ซึ่งจะแนะนำเอเจนต์ให้สร้างข้อเท็จจริงจาก core dump และตัดสินใจว่าการขัดข้องนั้นคุ้มค่าที่จะรายงานไปยังต้นทางหรือไม่ คุณยังสามารถรันมันด้วยมือกับ PID ใด ๆ จาก `coredumpctl list` ด้วย `omarchy agent crash <pid>` ได้

การเฝ้าดูเปิดอยู่โดยค่าเริ่มต้น ปิดมันภายใต้ _Trigger > Toggle > Crash Capture Off_ (หรือด้วย `omarchy toggle crash-capture`) และการแจ้งเตือนจะหยุด; `omarchy agent crash <pid>` ยังคงทำงานด้วยมือ

การขัดข้องยังสามารถถูกปิดเสียงทีละโปรแกรมได้ ซึ่งเป็นสิ่งที่การวินิจฉัยเสนอให้คุณในตอนท้าย `omarchy crash mute hyprland` หยุดการแจ้งเตือนสำหรับโปรแกรมนั้นเท่านั้น `omarchy crash mute hyprland off` นำพวกมันกลับมา และ `omarchy crash mute` ด้วยตัวเองจะแสดงรายการสิ่งที่คุณปิดเสียงไว้ มันรับเส้นทางของไบนารีได้พอ ๆ กับชื่อของมัน ดังนั้น `omarchy crash mute /usr/bin/hyprland` ทำสิ่งเดียวกัน ใส่เครื่องหมายคำพูดชื่อที่มีช่องว่าง เช่นใน `omarchy crash mute 'Some App'` ทุกอย่างอื่นยังคงแจ้งเตือน และโปรแกรมที่ปิดเสียงยังคงขัดข้อง — สิ่งนี้ซ่อนการเตือน มันไม่ได้แก้ไขอะไร

### แอปบนเดสก์ท็อป

เมนู _Install > AI_ ยังมีแอป AI แบบกราฟิกอยู่สองสามตัว: Amp Desktop, Antigravity Desktop, แอปเดสก์ท็อป ChatGPT, แอปเดสก์ท็อป Claude (เบต้า Linux ของ Anthropic พร้อมแท็บ Chat, Cowork และ Claude Code), Grok Bot สำหรับแชทกับโมเดลของ xAI, Herdr Desktop, Hermes Desktop, OpenClaw, แอปเดสก์ท็อป Perplexity และ T3 Code Grok Bot เป็นแอปแชทบนเดสก์ท็อป เอเจนต์เขียนโค้ดคือคำสั่ง `grok`

Hermes Desktop เป็นตัวที่ต้องรู้ เพราะเครื่องหนึ่งเครื่องมี Hermes เดียว และมันเป็นของแอป: Hermes จะถูกติดตั้งผ่านแอปเท่านั้น และคำสั่ง `hermes` ที่เอเจนต์เริ่มต้นรันเป็นของแอป การเลือก Hermes เป็นเอเจนต์เริ่มต้นจะติดตั้งสิ่งเดียวกับที่รายการ _Install > AI_ ทำ: แพ็กเกจ และรันไทม์ Hermes ภายใต้ `~/.hermes` ที่ติดตั้งโดยตัวติดตั้งของ Hermes เอง ซึ่งใช้เวลาสองสามนาทีในครั้งแรก รันไทม์นั้นคือ Hermes ตัวเดียวที่คำสั่ง `hermes` บนเทอร์มินัล เอเจนต์เริ่มต้น และแอปทั้งหมดใช้ และมันอัปเดตตัวเองด้วย `hermes update` แทนที่จะรอการเปิดตัว Omarchy การติดตั้งมันยังมอบธีม Omarchy ให้ Hermes เป็นสกินชื่อ `omarchy` ซึ่งทุกพื้นผิวของ Hermes จะทำตามเมื่อคุณเปลี่ยนธีม; เลือกอีกอันภายใต้การตั้งค่า Appearance ของ Hermes หรือด้วย `/skin` หากคุณไม่ต้องการให้มันทำเช่นนั้น และ Omarchy จะปล่อยตัวเลือกนั้นไว้ตามเดิม การลบแอปภายใต้ _Remove > AI_ จะปิด Hermes ก่อน รวมถึงเกตเวย์ นำรันไทม์นั้นไปด้วย และเก็บแชท ความทรงจำ และทักษะที่ Hermes เขียนให้ตัวเองไว้ เว้นแต่คุณจะบอกมันเป็นอย่างอื่น: มันจะถาม โดยค่าเริ่มต้นคือไม่ ว่าข้อมูลนั้นและการตั้งค่าการเชื่อมต่อของคุณควรไปด้วยหรือไม่

ประสบการณ์บนเดสก์ท็อปของ OpenClaw คือ Control UI ของมัน ซึ่งเปิดเป็นเว็บแอปที่ได้รับการสนับสนุนโดยเกตเวย์ภายในเครื่องของตัวเอง OpenClaw อาศัยอยู่ใน `~/.openclaw` และอัปเดตตัวเอง: ใช้ปุ่ม "Update Gateway" ของ Control UI หรือรัน `openclaw update` และเกตเวย์จะรีสตาร์ทบนรุ่นใหม่ Omarchy เพียงเลือกการเปิดตัวที่การติดตั้งใหม่จะเริ่มต้นจาก OpenClaw ยังสามารถเป็นเอเจนต์เริ่มต้นของคุณได้: การเลือกมันด้วย `omarchy default agent openclaw` จะติดตั้งสำเนาเดียวกันนั้นใน `~/.openclaw` และเอเจนต์จะเปิด UI บนเทอร์มินัลของ OpenClaw ที่เชื่อมกับเกตเวย์ของมัน การลบ OpenClaw ภายใต้ _Remove > AI_ จะนำบริการเกตเวย์และแอปไปด้วย จากนั้นจะถามว่า `~/.openclaw` ควรไปด้วยหรือไม่ เนื่องจากที่นั่นเก็บแชทและข้อมูลประจำตัวของคุณควบคู่ไปกับ OpenClaw เองและรันไทม์ปลั๊กอินที่มันดาวน์โหลด; ค่าเริ่มต้นจะเก็บมันไว้ และการติดตั้ง OpenClaw อีกครั้งจะหยิบมันกลับมา

Herdr Desktop คือแอปเดสก์ท็อป [Herdr](https://herdr.dev): พื้นที่ แท็บ และบานหน้าต่างของเทอร์มินัลและเอเจนต์เขียนโค้ดที่ยังคงทำงานในแกนหลักของมันเมื่อคุณปิดหน้าต่าง มันมาจากตัวติดตั้งของ Herdr เองแทนที่จะเป็นแพ็กเกจ ดังนั้นมันจึงอาศัยอยู่ใน `~/.local/share/herdr-app` นำแกนหลักของมันมาพร้อมใน `~/.local/bin/herdr-core` เมื่อคุณยังไม่มี และอัปเดตทั้งตัวมันเอง มันอยู่ข้างคำสั่ง `herdr` ที่ Omarchy ส่งมอบบน `Super + Ctrl + Return` แทนที่จะแทนที่มัน และได้รับคีย์โดยตรงของคำสั่งนั้น: `Alt + Return` และ `Alt + Shift + Return` แยกบานหน้าต่างลงหรือไปทางขวา `Alt + Escape` ปิดมัน `Ctrl + Alt + Arrow` ย้ายระหว่างบานหน้าต่าง `Alt + 1..9` และ `Alt + Left/Right` เลือกแท็บ และ `Alt + Up/Down` ย้ายระหว่างพื้นที่ `Ctrl + 1..9` เลือกพื้นที่ และ `Alt + Shift + Up/Down` ขยับผ่านเอเจนต์ คีย์คำนำหน้า `Ctrl + Space` ยังคงเป็นเฉพาะเทอร์มินัล เนื่องจากแอปไม่สามารถถือคีย์ Ctrl ธรรมดาไว้สำหรับลำดับได้ Omarchy เขียนสิ่งเหล่านี้ไปยัง `~/.config/herdr-app/keys.json` และ `omarchy-refresh-herdr-app` จะใส่พวกมันกลับ การติดตั้งมันจะเลือกธีม Omarchy ของ Herdr ซึ่งจะทำตามธีม Omarchy ของคุณต่อจากนั้น Herdr เก็บธีมหนึ่งสำหรับโหมดสว่างและอีกหนึ่งสำหรับโหมดมืด ดังนั้นหลังจากสลับระหว่างธีม Omarchy แบบมืดและแบบสว่าง ให้เลือก Omarchy ในตัวเลือกธีมของ Herdr อีกครั้งสำหรับโหมดอื่น

T3 Code ทำงานจากรุ่น AppImage อย่างเป็นทางการใน `~/.local/share/t3code` แทนที่จะมาจากแพ็กเกจ ดังนั้นมันจึงอัปเดตตัวเอง การติดตั้งมันจะถามว่าจะเริ่มบนช่อง Stable หรือ Nightly; สลับในภายหลังในการตั้งค่าของ T3 Code เธรดและการตั้งค่าของคุณอาศัยอยู่ใน `~/.t3` และการลบ T3 Code ภายใต้ _Remove > AI_ จะนำพวกมันไปด้วย

### โมเดลภายในเครื่อง

รันโมเดลแบบเปิดบนเครื่องของคุณเองสำหรับเอเจนต์เขียนโค้ดของคุณ พรอมต์และโค้ดของคุณอยู่บนเครื่อง; ไม่มีอะไรที่ส่งไปยังโมเดลออกจากมัน เริ่มต้นด้วย:

```bash
omarchy models use best text
```

นั่นจะติดตั้งโมเดลข้อความที่ดีที่สุดสำหรับเครื่องนี้ ซึ่งเป็นชนิดที่เอเจนต์ของคุณใช้ โมเดลรูปภาพ วิดีโอ และเพลงมีตัวที่ดีที่สุดของตัวเอง: `omarchy models use best image`, `video` หรือ `music` รัน `omarchy models use best` เพื่อดูตัวเลือกของแต่ละชนิดสำหรับเครื่องนี้

หรือเลือก + ในแผงเอเจนต์: ภายใต้ _Use a local model_ มันจะแสดงทุกโมเดลเขียนโค้ดที่เหมาะกับเครื่องนี้ โดยตัวที่แนะนำอยู่ก่อน Podman ซึ่งรันโมเดล มาพร้อมกับ Omarchy เช่นเดียวกับชุดเครื่องมือคอนเทนเนอร์ของ NVIDIA บนเครื่อง NVIDIA ซึ่งให้ GPU แก่พวกมัน; หากตัวใดตัวหนึ่งขาดไป การตั้งค่าครั้งแรกจะติดตั้งมัน Omarchy จากนั้นจะเลือกโมเดลที่แนะนำสำหรับเครื่องนี้ ดาวน์โหลดมัน และเริ่มมัน คาดว่าจะมีการดาวน์โหลดหลายสิบ GB และหน่วยความจำส่วนใหญ่ของเครื่องถูกใช้ขณะที่โมเดลทำงาน: Flash Next ใช้ประมาณ 100 GiB กับบริบท 256K เต็มรูปแบบของมัน หากโมเดลอื่นถือหน่วยความจำที่มันต้องการ มันจะถูกตั้งค่าในสถานะหยุด พร้อมเริ่มเมื่อคุณหยุดตัวหนึ่ง โมเดลจะหยุดเมื่อออกจากระบบ; หยุดมันด้วยตัวเองเมื่อคุณต้องการหน่วยความจำสำหรับอย่างอื่น

`omarchy models list` แสดงตัวเลือกและอธิบายว่าทำไมบางตัวจึงไม่เหมาะ หากต้องการตั้งค่าอีกตัว ให้รัน `omarchy models use <recipe>` วันนี้ `qwen3.8-flash-next-gufo` และ `qwen3.8-27b-gufo` มีให้สำหรับเครื่อง Strix Halo ขนาด 128 GB; 27B ใช้ประมาณ 40 GiB ดังนั้นมันจึงเหลือพื้นที่สำหรับงานอื่น บนแล็ปท็อป 64 GB ที่มี Arc B390 ของ Intel `qwen3.6-35b-a3b-llamacpp` ทำงานในประมาณ 30 GiB สูตรและคำแนะนำใหม่มาพร้อมกับ `omarchy update` ผ่านแพ็กเกจ

โมเดลเขียนโค้ดที่คุณเพิ่มจะมีบรรทัดของตัวเองในแผงเอเจนต์ ข้างการสมัครสมาชิกของคุณ: เล่นเพื่อเริ่มมัน หยุดชั่วคราวเพื่อหยุดมันและปลดปล่อยหน่วยความจำของมัน เครื่องหมาย Tailscale เพื่อแชร์มันกับเครื่องอื่น ๆ บน tailnet ของคุณขณะที่มันทำงาน และปุ่มเทอร์มินัลเพื่อเปิดเอเจนต์ของคุณบนมัน บรรทัดของมันแสดงการดาวน์โหลด การโหลด หรือการหยุดขณะที่เกิดขึ้น และบอกเช่นนั้นเมื่อมีหน่วยความจำว่างไม่พอที่จะเริ่มมัน หรือลิงก์ไปยังบันทึกของมันเมื่อมันหยุดด้วยข้อผิดพลาด หลายตัวสามารถทำงานพร้อมกันเมื่อพวกมันพอดีในหน่วยความจำร่วมกัน กด Delete บนบรรทัดที่เลือกเพื่อลบโมเดลออกจากเครื่องนี้ รวมถึงการดาวน์โหลดทั้งหมด; + สามารถตั้งค่ามันได้อีกครั้ง โมเดลเขียนโค้ดที่ตั้งค่าจากเทอร์มินัลจะรอภายใต้ + จนกว่าคุณจะเพิ่มมัน และโมเดลที่เครื่องที่คุณจับคู่ด้วย (`omarchy models pair <host>`) ทำงานก็เช่นกัน

โมเดลเขียนโค้ดทุกตัวที่คุณตั้งค่ายังได้รับรายการของตัวเองในตัวเรียกใช้แอป ภายใต้ชื่อของโมเดลและพร้อมโลโก้ของผู้สร้าง ในแบบเดียวกับการลงชื่อเข้าใช้ Claude, Codex หรือ Grok เพิ่มหนึ่งรายการ มันเปิดเอเจนต์ของคุณบนโมเดลนั้น และเริ่มโมเดลก่อนหากมันยังไม่ทำงาน: เทอร์มินัลแสดงมันกำลังโหลดและส่งต่อให้เอเจนต์เมื่อมันพร้อม การลบโมเดลจะลบรายการของมัน

ไม่ใช่ทุกโมเดลสำหรับเขียนโค้ด โมเดลรูปภาพ วิดีโอ และเพลงจะเปิดใน Fantasi แทน ซึ่งเป็นแอปของ Omarchy สำหรับสร้างรูปภาพ วิดีโอ และเพลงด้วยโมเดลที่ทำงานบนเครื่องนี้ และได้รับการจัดการที่นั่นหรือด้วย `omarchy models`

โมเดลจะยังคงทำงานอย่างที่มันถูกตั้งค่าไว้ ดังนั้นการอัปเดต Omarchy จะไม่รีสตาร์ทตัวหนึ่งภายใต้เอเจนต์ของคุณ เมื่อ Omarchy มีรันไทม์ที่ใหม่กว่าหรือน้ำหนักที่ใหม่กว่าสำหรับโมเดลที่คุณตั้งค่าไว้ บรรทัดของมันจะแสดงปุ่มอัปเดต: กดมันและโมเดลจะถูกตั้งค่าอีกครั้งในเบื้องหลัง โดยดาวน์โหลดเฉพาะสิ่งที่เปลี่ยนแปลง และรีสตาร์ทบนรุ่นใหม่ โมเดลที่หยุดอยู่จะยังคงหยุดอยู่ `omarchy models update` ทำสิ่งเดียวกันสำหรับทุกโมเดลจากเทอร์มินัล

จากบรรทัดคำสั่ง `omarchy models start <recipe>` และ `omarchy models stop <recipe>` ทำสิ่งเดียวกัน `omarchy models status` แสดงทุกโมเดล และ `omarchy agent --local-model <recipe>` เปิดโมเดลนั้นใน pi ไม่ว่าเอเจนต์เริ่มต้นของคุณจะเป็นอะไร หากต้องการให้โมเดลภายในเครื่องของคุณเป็นสิ่งที่ปุ่มลัดเอเจนต์ คอนโซล Quake และ _Make something_ เปิด ให้รัน `omarchy default agent local` หรือติดดาวโมเดลที่กำลังทำงานในแผงเอเจนต์ pi ยังแสดงทุกโมเดลที่คุณตั้งค่าไว้ และโมเดลบนเครื่องที่คุณจับคู่ด้วย ในตัวเลือกโมเดลของตัวเอง ดังนั้น `pi` แบบธรรมดาก็เข้าถึงพวกมันได้เช่นกัน ไคลเอนต์ที่เข้ากันได้กับ OpenAI ใด ๆ ก็สามารถเชื่อมต่อได้เช่นกัน: `status` แสดงที่อยู่ของแต่ละโมเดล (ตัวแรกคือ `http://127.0.0.1:11435/v1`) ชื่อสูตรคือโมเดล และคีย์อยู่ใน `~/.config/omarchy/agent-local/key`

`omarchy models remove <recipe>` ลบโมเดลและการดาวน์โหลดที่ไม่มีโมเดลอื่นใช้

รันไทม์ของบุคคลที่สามจะถูกติดป้ายด้วยผู้เผยแพร่ของมัน Omarchy รันทุกโมเดลโดยไม่มีการเข้าถึงเครือข่าย

### LLM ภายในเครื่อง

Omarchy แนะนำสองวิธีในการรันโมเดล LLM ภายในเครื่อง: LM Studio และ Ollama LM Studio ให้อินเทอร์เฟซ GUI สำหรับค้นหาโมเดลแบบ open-weight ติดตั้งพวกมัน และรันพวกมัน มันเป็นวิธีที่ยอดเยี่ยมในการเริ่มต้นอย่างง่ายดาย Ollama เสนอ CLI สำหรับทำเช่นเดียวกัน แต่หากคุณยังใหม่กับโมเดลภายในเครื่อง ผมคงจะเริ่มด้วย LM Studio คุณสามารถติดตั้งตัวใดตัวหนึ่งภายใต้ _Install > AI_ ในเมนู Omarchy

### ทักษะของ Omarchy

ทักษะเอเจนต์ช่วยให้ AI ใช้เครื่องมือเฉพาะในวิธีเฉพาะ และ Omarchy ส่งมอบเจ็ดทักษะมาให้ ทักษะ omarchy ครอบคลุมการปรับแต่งระบบ เช่นการปรับแต่งคอนฟิก Hyprland ของคุณหรือการปรับแถบ omarchy-make-theme, omarchy-make-plugin, omarchy-make-app และ omarchy-make-game ครอบคลุมการสร้างสิ่งใหม่ omarchy-contribute ครอบคลุมการรายงานข้อบกพร่องหรือการส่งการแก้ไขไปยังต้นทาง และ omarchy-diagnose-crash ทำงานผ่าน core dump ของการขัดข้อง พวกมันถูกทำเป็นซิมลิงก์เข้าไปในไดเรกทอรีทักษะสำหรับ Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` และแต่ละ `~/.hermes/profiles/*/skills`) และตำแหน่งทั่วไป `~/.agents/skills` ดังนั้น harness ส่วนใหญ่จึงหยิบพวกมันขึ้นมาโดยอัตโนมัติ โฟลเดอร์ทักษะของคุณเองที่มีชื่อเดียวกันจะมีความสำคัญเหนือกว่า

แต่คุณควรปฏิบัติต่อทักษะเหล่านี้ว่าเป็นการทดลอง โมเดลที่แตกต่างกันจะใช้มันให้เกิดผลที่แตกต่างกัน ดีที่สุดคือรันในโหมดวางแผนก่อน เพื่อให้คุณมีความคิดว่าเอเจนต์ต้องการเปลี่ยนอะไร จากนั้นจงเตรียมพร้อมที่จะย้อนกลับการเปลี่ยนแปลงหรือแม้แต่เรียกใช้ `omarchy reinstall configs` หากเอเจนต์ทำให้ทุกอย่างยุ่งเหยิง
