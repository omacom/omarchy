### การติดตั้งและการอัปเดตเอเจนต์

ยกเว้น Hermes และ OpenClaw เอเจนต์เหล่านี้ใช้การติดตั้งแบบขี้เกียจของ mise: การเปิดใช้ครั้งแรกจะติดตั้ง CLI และการเปิดใช้ครั้งต่อ ๆ ไปจะใช้ตัวเดิมนั้น mise ยังตรวจสอบด้วยว่ามีรุ่นใหม่ของเอเจนต์ที่ติดตั้งไว้หรือไม่ อย่างมากที่สุดครั้งเดียวทุก ๆ สี่ชั่วโมง ก่อนที่มันจะเริ่มทำงานพอดีหรือในเบื้องหลังที่พรอมต์ของเชลล์ หากการอัปเดตนั้นล้มเหลวหรือคุณออฟไลน์ เวอร์ชันที่ติดตั้งไว้จะทำงาน `omarchy update` จะอัปเดตเอเจนต์ที่ติดตั้งไว้พร้อมกับส่วนที่เหลือของ Omarchy และ `mup` จะอัปเดตเฉพาะเครื่องมือที่ mise จัดการเท่านั้น

ตัวอัปเดตของเอเจนต์เอง เช่น `claude update`, `codex update` หรือปุ่มอัปเดตในแอป จะไม่อัปเดตตัวที่ติดตั้งและจัดการโดย mise `codex update` จะล้มเหลว และ `claude update` สามารถรายงานว่าสำเร็จในขณะที่กำลังติดตั้งสำเนาแยกอีกตัวที่ mise ไม่ได้ติดตาม หากคุณอยากใช้ตัวติดตั้งและตัวอัปเดตแบบดั้งเดิมของเอเจนต์มากกว่า ให้เพิ่มมันลงใน `disable_tools`; ดู [เครื่องมือ CLI ที่ติดตั้งไว้ล่วงหน้า](18-development-tools.md#preinstalled-cli-tools)

หากต้องการติดตั้งเครื่องมือแบบขี้เกียจที่กำหนดค่าไว้ทั้งหมดก่อนที่คุณจะต้องการใช้ ให้เรียกใช้ `mise install --include-lazy` ซึ่งรวมถึงเครื่องมือ CLI เริ่มต้นตัวอื่น ๆ ของ Omarchy ด้วยเช่นเดียวกับเอเจนต์ ดู [เครื่องมือ CLI ที่ติดตั้งไว้ล่วงหน้า](18-development-tools.md#preinstalled-cli-tools) สำหรับการติดตั้งเครื่องมือตัวเดียวหรือการใช้ตัวติดตั้งของคุณเอง

`grok` ถูกติดตั้งผ่านแพ็กเกจ `grok` แบบ first-party ของ mise ในแบบเดียวกันกับ `claude` และ `codex` เรียกใช้ `grok` หรือเลือกมันใต้ _Agent > Harness_ ข้ามตัวติดตั้งแบบ `curl | bash` บน x.ai ไปเลย เส้นทางนั้นจะวางสำเนาที่สองไว้ใน `~/.grok/bin`, นำหน้ามันบน `PATH` และเขียนทับตัวห่อหุ้มของ Omarchy

`dsh` จะเปิดอินเทอร์เฟซผู้ใช้แบบเบราว์เซอร์ของมันบน `127.0.0.1:3080` โดยมีไดเรกทอรีที่เปิดใช้เป็นพื้นที่ทำงานเริ่มต้น อินเทอร์เฟซผู้ใช้แบบเบราว์เซอร์ของมันไม่รับพรอมต์ตอนเริ่มต้น ดังนั้น `omarchy agent prompt` จะเปิดมันโดยมีพรอมต์อยู่บนคลิปบอร์ดของคุณให้วาง Omarchy จะเริ่มมันด้วยชุดสิทธิ์แบบไม่ต้องขออนุมัติของ DeepSeek DeepSeek Harness จะอัปโหลดบันทึกเซสชันไปยัง DeepSeek เมื่อคุณใช้ API โมเดลอย่างเป็นทางการของมัน; ปิดการทำงานนั้นได้ใต้ _Settings > General > Upload Session Log_ ในอินเทอร์เฟซผู้ใช้แบบเบราว์เซอร์ของมัน ความคิดเห็นที่คุณส่งให้มันจะถูกอัปโหลดไปพร้อมกับเซสชันด้วย เว้นแต่คุณจะเริ่มมันด้วย `DSH_TELEMETRY_MODE=DISABLED`

### เอเจนต์เริ่มต้น

เลือกเอเจนต์เริ่มต้นของคุณด้วย `omarchy default agent <name>` หรือใต้ _Agent > Harness_ ใน Omarchy Menu (`Super + Space`) หากเอเจนต์ยังไม่ได้ถูกติดตั้ง การเลือกมันจะติดตั้งมันก่อน และมันยังจะได้รับตัวเปิดใช้ของตัวเองในตัวเปิดใช้แอป ถัดจาก Agent ด้วย Omarchy ที่ติดตั้งใหม่จะชวนให้คุณเลือกสิ่งนี้ด้วยการแจ้งเตือนเพียงครั้งเดียว

การเลือก Claude ยังพยายามตั้งค่าส่วนขยายเบราว์เซอร์ของมันสำหรับ Chromium, Chrome, Brave, Brave Origin และ Edge ด้วย การตั้งค่าส่วนขยายจะใช้กับผู้ใช้ทั้งหมดและอาจขอรหัสผ่านระบบของคุณ; การยกเลิกหรือการติดตั้งส่วนขยายที่ล้มเหลวยังคงเลือกและเปิดใช้ Claude อยู่ดี รีสตาร์ทเบราว์เซอร์ของคุณ เปิดใช้งานส่วนขยายหากระบบขอ และลงชื่อเข้าใช้ Claude เพื่อเชื่อมต่อมันให้เสร็จ เรียกใช้ `/chrome` ใน Claude เพื่อตรวจสอบการเชื่อมต่อ Firefox และ Zen ไม่รองรับส่วนขยายนี้ หาก Claude เคยเป็นค่าเริ่มต้นของคุณอยู่แล้วก่อนที่จะมีการเพิ่มการตั้งค่านี้ ให้เลือกมันอีกครั้งเพื่อติดตั้งส่วนขยาย

เมื่อคุณเลือกแล้ว `Super + Shift + Ctrl + A` จะเปิดเอเจนต์เริ่มต้นในหน้าต่างเทอร์มินัลเฉพาะ (หรือจะแสดงตัวเลือกหากคุณยังไม่ได้เลือก) คุณยังสามารถเปิดมันเข้าสู่งานโดยตรงได้ด้วย `omarchy agent prompt "Review this project"` Freebuff และ DeepSeek Harness ไม่รับพรอมต์ตอนเริ่มต้น ดังนั้นพวกมันจะเปิดโดยมีพรอมต์อยู่บนคลิปบอร์ดของคุณให้วางแทน เอเจนต์ที่เปิดใช้ด้วยวิธีนี้จะทำงานโดยไม่มีผู้ดูแลในโหมดไม่หยุดเพื่อถามของแต่ละตัว ดังนั้นจงเตรียมพร้อมให้พวกมันลงมือทำสิ่งต่าง ๆ จริง ๆ! MiniMax Code ไม่มีโหมดแบบนั้นสำหรับเซสชันแบบโต้ตอบของมัน ดังนั้นมันจะขอสิทธิ์ตามปกติ และเนื่องจากเอเจนต์ปฏิเสธที่จะจดจำความไว้วางใจสำหรับไดเรกทอรีบ้านของคุณ การเปิดใช้จาก `$HOME` จะเริ่มใน `~/Work` แทน

ยังมีทางลัดในเทอร์มินัลด้วย: `a` จะเรียกใช้เอเจนต์เริ่มต้นแบบอินไลน์ในเทอร์มินัลปัจจุบัน ขณะที่ `c`, `cx` และ `cy` จะเริ่ม OpenCode, Claude Code และ Codex โดยตรง (ในโหมดอนุมัติอัตโนมัติของพวกมันอีกเช่นกัน) การเปลี่ยนธีมจะซิงก์ไปยังเอเจนต์ด้วย: Claude Code, Pi, OpenCode และ Hermes (เมื่อ Omarchy ติดตั้งมันแล้ว) จะเปลี่ยนตามทั้งหมดเมื่อคุณเปลี่ยนธีมของ Omarchy

### คำสั่งสำหรับเอเจนต์ของคุณ

กฎส่วนตัวสำหรับทุกเอเจนต์จะอยู่ใน `~/.agents/AGENTS.md` ถัดจากสกิลที่ใช้ร่วมกันใน `~/.agents/skills` เปิดมันได้ใต้ _Agent > Instructions_ ซึ่งยังเชื่อมโยงมันเข้าไปในแต่ละฮาร์เนสที่เก็บไฟล์โกลบอลของตัวเองไว้ด้วย: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` ของ Copilot และอื่น ๆ Crush และ Amp จะอ่านลิงก์ `~/.config/AGENTS.md` ขณะที่ omp, Kimi และ DeepSeek Harness จะอ่าน `~/.agents/AGENTS.md` โดยตรง การเลือกเอเจนต์เริ่มต้นจะเชื่อมโยงมันด้วยเช่นกัน ไฟล์คำสั่งที่คุณมีอยู่แล้วจะกลายเป็นไฟล์ที่ใช้ร่วมกันหากยังไม่มีไฟล์ดังกล่าวอยู่; มิฉะนั้นมันจะถูกเก็บไว้ข้างลิงก์ในชื่อ `.bak` เรียกใช้ `omarchy agent instructions` เพื่อเชื่อมโยงใหม่หลังจากติดตั้งเอเจนต์อีกตัว

### แผงเอเจนต์

แถบบนสุดมีไอคอนเอเจนต์ ก่อนที่คุณจะตั้งค่าเอเจนต์ แผงของมันจะพาคุณผ่านการลงชื่อเข้าใช้ Claude, Codex หรือ Grok และตัวแรกจะกลายเป็นเอเจนต์เริ่มต้นของคุณ หลังจากนั้น แผงจะวางทุกการสมัครใช้งานไว้ในหน้าเดียว: เอเจนต์และบัญชีแต่ละรายการพร้อมแผนของมัน มิเตอร์สำหรับขีดจำกัดเซสชัน 5 ชั่วโมงและขีดจำกัดรายสัปดาห์ของแต่ละรายการพร้อมเวลาจนกว่าจะรีเซ็ต (วางเมาส์เหนือเพื่อดูเปอร์เซ็นต์ที่แน่นอน) หรือยอดเงินเติมเงินคงเหลือ ใต้บรรทัดที่หมุนเวียนผ่านสิ่งที่คุณใช้ไปในทั้งหมด เช่น โทเคนในสัปดาห์นี้และโมเดลที่คุณใช้มากที่สุด ใต้ _Make something cool_ มันจะเสนอพรอมต์เริ่มต้นสำหรับธีม, ปลั๊กอิน, แอป หรือเกมใหม่ ที่มอบงานให้เอเจนต์เริ่มต้นของคุณ แอปถูกสร้างขึ้นในแบบเดียวกับที่ Hype, Monologue และ Omacut ของ Omarchy เองถูกสร้างขึ้น ใน C++ และ Qt Quick โดยทำตามสกิลเอเจนต์ omarchy-make-app และคอมไพเลอร์กับชิ้นส่วน Qt ที่พวกมันต้องการก็มาพร้อมการติดตั้งแล้ว เกมเป็นหน้า three.js หน้าเดียวใน `~/Games/vibes` โดยทำตามสกิลเอเจนต์ omarchy-make-game และทั้งหมดจะเปิดจากตัวเปิดใช้ Game Vibes ตัวเดียวในธีมปัจจุบัน; พวกมันโหลด three.js จากเว็บ ดังนั้นพวกมันจึงต้องการการเชื่อมต่อเพื่อเริ่มใช้งาน Claude Code, Codex, Grok, Kimi, Cursor และโควตา Grok Bot ของมัน, GitHub Copilot, Muse, Antigravity และ Devin ได้รับการรองรับตั้งแต่แกะกล่องพร้อมขีดจำกัดของพวกมัน, Kimchi พร้อมแผน, เครดิตเติมเงิน และงบการใช้จ่ายของมัน และ Hermes, Mistral Vibe และ Qwen Code จะแสดงเซสชันและโทเคนของพวกมันเมื่อคุณได้ใช้พวกมันแล้ว แผนและคีย์ของผู้ให้บริการที่คุณใช้ผ่าน pi, omp หรือ opencode จะปรากฏด้วยเช่นกัน: OpenCode Zen และ Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan และ Synthetic พร้อมขีดจำกัดของพวกมัน; OpenRouter และ DeepSeek พร้อมยอดเงินเติมเงินของพวกมัน; Fireworks พร้อมการใช้จ่ายในช่วง 30 วันที่ผ่านมา โทเคนจากโมเดลที่คุณเรียกใช้บนฮาร์ดแวร์ของคุณเองนับรวมในยอดรวมด้วย; โมเดลเหล่านั้นมีแผงของตัวเอง ซึ่งอธิบายไว้ใต้ [โมเดลแบบโลคัล](#local-models) เอเจนต์ทุกตัวจะถูกนับเพียงครั้งเดียว ภายใต้ผู้ที่เรียกเก็บเงินสำหรับมัน ไม่ว่าคุณจะขับเคลื่อนมันผ่านฮาร์เนสกี่ตัวก็ตาม

คลิกซ้ายที่ไอคอนบนแถบหรือกด `Super + Ctrl + X` เพื่อเปิดแผง คลิกขวาเพื่อเปิดเอเจนต์เริ่มต้นของคุณ และคลิกกลางเพื่อรีเฟรช บันทึกการใช้งานที่อยู่เบื้องหลังมันจะถูกสร้างใหม่ทุก 15 นาทีโดย `omarchy agent usage update` และแผงยังสามารถรวมการใช้งานจากเครื่องอื่น ๆ ของคุณผ่านโฟลเดอร์ที่ซิงก์ไว้ได้ด้วย ดู README ใต้ `$OMARCHY_PATH/shell/plugins/agents/` สำหรับการตั้งค่าทั้งหมด

### การสมัครใช้งานหลายรายการ

หากคุณจ่ายเงินสำหรับแผน Claude, Codex หรือ Grok มากกว่าหนึ่งแผน — เช่น แผน Max ส่วนตัวและแผนสำหรับงาน — Omarchy สามารถทำให้พวกมันทั้งหมดลงชื่อเข้าใช้อยู่และย้ายไปมาระหว่างพวกมันได้ เพิ่มการสมัครใช้งานด้วยเครื่องหมาย + ในแผงเอเจนต์ ซึ่งจะพาคุณผ่านขั้นตอนนั้นตรงนั้นเลย หรือด้วย `omarchy agent account add claude Work` (หรือ `codex` หรือ `grok`) มันจะติดตั้ง CLI หากยังไม่มี บัญชีแรกสำหรับผู้ให้บริการรายหนึ่งจะลงชื่อเข้าใช้ผ่านเบราว์เซอร์ปกติของคุณ ตรงจุดที่ CLI มองหาอยู่เสมอ บัญชีหลังจากนั้นทุกบัญชีจะลงชื่อเข้าใช้ผ่านหน้าต่างส่วนตัว เพื่อที่บัญชีที่เบราว์เซอร์ของคุณลงชื่อเข้าใช้อยู่แล้วจะไม่ถูกหยิบขึ้นมาโดยไม่ตั้งใจ; ลงชื่อเข้าใช้ที่นั่นในฐานะบัญชีที่คุณกำลังเพิ่ม และปิดหน้าต่างส่วนตัวใด ๆ ที่คุณเปิดค้างไว้ก่อน อย่าออกจากระบบของ CLI เพื่อทำสิ่งนี้เด็ดขาด: การออกจากระบบจะเพิกถอนการลงชื่อเข้าใช้ที่บันทึกไว้ และบัญชีนั้นจะต้องถูกเพิ่มใหม่อีกครั้ง

หากต้องการคัดลอกการเข้าสู่ระบบการสมัครใช้งานของคุณไปยังเครื่อง Omarchy อีกเครื่องผ่าน SSH ให้เรียกใช้ `omarchy agent account copy user@laptop` ผู้ส่งจะจัดเตรียมตัวรับชั่วคราวเมื่อปลายทางยังไม่ได้ติดตั้งไว้ ดังนั้นเครื่อง Omarchy รุ่นเก่ากว่าสามารถรับบัญชีได้โดยไม่ต้องอัปเดต ตัวรับที่ติดตั้งไว้จะมีลำดับความสำคัญสูงกว่า การดำเนินการนี้จะคัดลอกการสมัครใช้งาน Claude, Codex และ Grok ทั้งหมด; เพิ่มชื่อผู้ให้บริการเพื่อเลือกพวกมัน เช่นใน `omarchy agent account copy laptop claude` ชื่อบัญชีและรหัสคำสั่งจะตรงกับต้นทาง รวมถึงบัญชีที่มีอยู่แล้วบนปลายทางด้วย บัญชีปลายทางที่ไม่เกี่ยวข้องจะได้รับคำต่อท้ายที่เป็นตัวเลขหากชื่อของพวกมันขัดแย้งกัน และการตั้งค่า, สกิล, ปลั๊กอิน และประวัติการสนทนาจะยังคงอยู่แบบโลคัลในแต่ละเครื่อง

ข้อมูลประจำตัวปลายทางที่มีอยู่จะถูกเก็บไว้ บัญชีต้นทางที่ลงชื่อเข้าใช้อยู่ที่นั่นแล้วจะมีชื่อที่ซิงโครไนซ์โดยไม่แทนที่ข้อมูลประจำตัวของมัน; บัญชีอื่น ๆ จะถูกเพิ่มเข้าไปข้าง ๆ มัน หากต้องการแทนที่ข้อมูลประจำตัวที่บันทึกไว้สำหรับบัญชีที่ตรงกัน ให้ใช้ `omarchy agent account copy --replace laptop claude` หลังจากออกจากเซสชันของบัญชีนั้นบนปลายทางแล้ว ปลายทางที่ยังใหม่จะได้รับบัญชีที่ใช้งานอยู่และการตั้งค่าการสลับของต้นทางด้วย; ปลายทางที่จัดตั้งแล้วจะเก็บของตัวเองไว้

ข้อมูลประจำตัวเดินทางผ่าน SSH และถูกเก็บไว้ในไฟล์ส่วนตัวบนปลายทาง ดังนั้นให้คัดลอกเฉพาะไปยังเครื่องที่คุณไว้วางใจเท่านั้น นี่คือการคัดลอกเพียงครั้งเดียว ไม่ใช่การซิงโครไนซ์อย่างต่อเนื่อง โทเคนรีเฟรชของ Codex สามารถถูกหมุนเวียนโดยเครื่องอื่นได้ ทำให้การเข้าสู่ระบบที่คัดลอกมาต้องต่ออายุ; การลงชื่อเข้าใช้แยกกันยังคงเป็นตัวเลือกที่น่าเชื่อถือที่สุดสำหรับการใช้งานพร้อมกันบนหลายเครื่อง ดู [คำแนะนำการยืนยันตัวตนบัญชีของ Codex](https://developers.openai.com/codex/auth/ci-cd-auth)

บัญชีหนึ่งบัญชีต่อผู้ให้บริการหนึ่งรายจะใช้งานอยู่ และทุกเซสชันใหม่จะเริ่มในฐานะบัญชีนั้น: `cx`, `cy`, `claude`, `codex` หรือ `grok` ธรรมดา, สิ่งใดก็ตามที่เปิดผ่าน `omarchy agent` และสคริปต์หรือตัวแก้ไขที่ค้นพบ CLI บน `PATH` สลับด้วย `omarchy agent account use work` (และกลับด้วย `omarchy agent account use main`) หรือในแผงโดยการกดหมายเลขของบัญชีแล้วกด `Enter` (หรือคลิกปุ่ม Use ของมัน) เซสชัน Claude ที่กำลังทำงานอยู่จะสลับด้วย ตั้งแต่ข้อความถัดไปของพวกมัน: ทุกเซสชันของ Claude จะทำงานใน `~/.claude` ซึ่งเก็บการลงชื่อเข้าใช้ของบัญชีที่ใช้งานอยู่ไว้เสมอ เซสชัน Claude ที่เริ่มต้นในโฟลเดอร์ของบัญชีเองโดย Omarchy รุ่นเก่ากว่าจะเก็บการลงชื่อเข้าใช้นั้นไว้จนกว่ามันจะออก ดังนั้นการสลับจะระบุชื่อเซสชันเหล่านั้นและเสร็จสิ้นด้วยตัวเองเมื่อพวกมันจากไปแล้ว เซสชัน Codex และ Grok ที่กำลังทำงานอยู่จะคงอยู่กับบัญชีที่พวกมันเริ่มต้นด้วย ประวัติการสนทนา, การตั้งค่า, สกิล และปลั๊กอินจะถูกใช้ร่วมกันข้ามบัญชี ดังนั้น `claude --continue` ในโฟลเดอร์เดียวกันจะดำเนินการต่อจากจุดที่คุณค้างไว้บนบัญชีใหม่

เมื่อมีมากกว่าหนึ่งบัญชี แผงจะแสดงขีดจำกัดของแต่ละบัญชีเคียงข้างกัน โดยบัญชีที่ใช้งานอยู่จะถูกทำเครื่องหมายไว้ โดยค่าเริ่มต้น Omarchy จะแจ้งเตือนคุณเมื่อบัญชีที่ใช้งานอยู่เกิน 95% ของขีดจำกัด และการคลิกการแจ้งเตือนจะสลับไปยังบัญชีที่มีพื้นที่เหลือมากที่สุด วางเมาส์เหนือบรรทัดของบัญชีในแผงและคลิก Autoswitch ที่ปรากฏถัดจาก Use (หรือกด `m`) หรือเรียกใช้ `omarchy agent account mode auto` เพื่อให้มันสลับด้วยตัวเองแทน; ขณะที่มันเปิดอยู่ Autoswitch จะแทนที่ Use และการคลิกมันอีกครั้งจะกลับไปเป็นการแจ้งเตือน เพิ่มตัวเลขเพื่อเปลี่ยนเกณฑ์ เช่นใน `omarchy agent account mode auto 90` หากทุกบัญชีเกินเกณฑ์ คุณจะได้รับแจ้งเกี่ยวกับเรื่องนั้นครั้งเดียว พร้อมกับบัญชีใดที่จะว่างก่อน ขณะที่บัญชีที่ใช้งานอยู่ภายใน 15 จุดจากเกณฑ์ของมัน (80% ที่ค่าเริ่มต้น) ขีดจำกัดของมันจะถูกตรวจสอบทุกสามนาทีแทนที่จะเป็นทุก 15 นาที

`omarchy agent account list` จะแสดงทุกบัญชีและขีดจำกัดล่าสุดของพวกมัน, `omarchy agent account remove work` จะลืมบัญชีหนึ่งบัญชี และ `omarchy agent account rename primary Hey` จะเปลี่ยนชื่อบัญชีหนึ่งบัญชี (หรือคลิกชื่อของบัญชีในแผง) คำสั่งเหล่านี้ทำงานกับบัญชีของเอเจนต์เริ่มต้นของคุณ; หากต้องการเข้าถึงผู้ให้บริการรายอื่น ให้ระบุชื่อมันก่อน เช่นใน `omarchy agent account use codex side` การเข้าสู่ระบบที่คุณมีอยู่แล้วใน `~/.claude` หรือ `~/.codex` คือบัญชี _Main_ ของ Codex จะยังคงอยู่ที่เดิม; ของ Claude จะรออยู่ในโฟลเดอร์ของตัวเองขณะที่บัญชีอื่นกำลังใช้งานอยู่ บัญชีที่ไม่ได้ใช้มานานกว่าประมาณแปดชั่วโมงสามารถแสดง _Sign-in required_; คลิกมันเพื่อลงชื่อบัญชีนั้นเข้าใช้อีกครั้งในแผงเลย หรือสลับไปยังมันและเริ่มเซสชัน ซึ่งจะรีเฟรชการลงชื่อเข้าใช้ด้วยตัวเอง เซิร์ฟเวอร์ MCP ที่คุณเพิ่มด้วย `claude mcp add` จะเข้าถึงทุกบัญชี Claude เนื่องจากพวกมันทั้งหมดทำงานใน `~/.claude`; สำหรับ Codex และ Grok เซิร์ฟเวอร์ที่คุณมีเมื่อบัญชีถูกเพิ่มจะตามไปยังบัญชีนั้นด้วย แต่เซิร์ฟเวอร์ในภายหลังจะเข้าถึงเฉพาะบัญชีที่คุณเพิ่มพวกมันเข้าไปเท่านั้น Claude Desktop เก็บการลงชื่อเข้าใช้ของตัวเองไว้ และเครื่องมือ Codex หรือ Grok ที่กำหนดค่าด้วยเส้นทางแบบสัมบูรณ์ไปยังไบนารี CLI จะไม่ตามการสลับไป `CLAUDE_CONFIG_DIR`, `CODEX_HOME` หรือ `GROK_HOME` ที่ระบุอย่างชัดเจนจะมีลำดับความสำคัญเหนือบัญชีที่เลือกไว้

### การวินิจฉัยการแครช

Omarchy จะเฝ้าดู systemd-coredump สำหรับการแครชของกระบวนการ เมื่อคุณเลือกเอเจนต์เริ่มต้นแล้ว โปรแกรมใด ๆ ของคุณที่ทิ้ง core จะทำให้เกิดการแจ้งเตือน "Process crashed" — คลิกมัน และการแครชจะถูกส่งให้เอเจนต์เริ่มต้นของคุณพร้อมกับสกิล omarchy-diagnose-crash ของ Omarchy ซึ่งจะพาเอเจนต์ผ่านการสร้างข้อเท็จจริงจาก core dump และตัดสินใจว่าการแครชนั้นคุ้มค่าที่จะรายงานไปยังต้นทางหรือไม่ คุณยังสามารถเรียกใช้มันด้วยมือกับ PID ใด ๆ จาก `coredumpctl list` ด้วย `omarchy agent crash <pid>` ได้ด้วย

การเฝ้าดูเปิดอยู่โดยค่าเริ่มต้น ปิดมันได้ใต้ _Trigger > Toggle > Crash Capture Off_ (หรือด้วย `omarchy toggle crash-capture`) และการแจ้งเตือนจะหยุด; `omarchy agent crash <pid>` ยังคงใช้งานได้ด้วยมือ

การแครชยังสามารถถูกปิดเสียงได้ครั้งละโปรแกรมหนึ่ง ซึ่งเป็นสิ่งที่การวินิจฉัยเสนอให้คุณในตอนท้าย `omarchy crash mute hyprland` จะหยุดการแจ้งเตือนสำหรับโปรแกรมนั้นเท่านั้น, `omarchy crash mute hyprland off` จะนำพวกมันกลับมา และ `omarchy crash mute` อย่างเดียวจะแสดงรายการสิ่งที่คุณได้ปิดเสียงไว้ มันรับเส้นทางของไบนารีได้พอ ๆ กับชื่อของมัน ดังนั้น `omarchy crash mute /usr/bin/hyprland` จะทำสิ่งเดียวกัน ใส่เครื่องหมายคำพูดในชื่อที่มีช่องว่าง เช่นใน `omarchy crash mute 'Some App'` อย่างอื่นทุกอย่างยังคงแจ้งเตือนอยู่ และโปรแกรมที่ปิดเสียงไว้ยังคงแครชอยู่ — สิ่งนี้ซ่อนการแจ้งเตือน มันไม่ได้แก้ไขอะไรเลย

### แอปบนเดสก์ท็อป

เมนู _Install > AI_ ยังมีแอป AI แบบกราฟิกอยู่สองสามแอปด้วย: Amp Desktop, Antigravity Desktop, แอปเดสก์ท็อป ChatGPT, แอปเดสก์ท็อป Claude (รุ่นเบต้าสำหรับ Linux ของ Anthropic, พร้อมแท็บ Chat, Cowork และ Claude Code), Grok Bot สำหรับแชทกับโมเดลของ xAI, Herdr Desktop, Hermes Desktop, OpenClaw, แอปเดสก์ท็อป Perplexity และ T3 Code Grok Bot คือแอปแชทบนเดสก์ท็อป เอเจนต์เขียนโค้ดคือคำสั่ง `grok`

Hermes Desktop คือแอปที่ต้องรู้ เพราะเครื่องหนึ่งเครื่องจะมี Hermes เดียว และมันเป็นของแอป: Hermes จะถูกติดตั้งผ่านแอปเท่านั้น และคำสั่ง `hermes` ที่เอเจนต์เริ่มต้นเรียกใช้ก็เป็นของแอป การเลือก Hermes เป็นเอเจนต์เริ่มต้นจะติดตั้งสิ่งเดียวกันกับที่รายการ _Install > AI_ ติดตั้ง: แพ็กเกจ และรันไทม์ Hermes ใต้ `~/.hermes` ที่ตั้งค่าโดยตัวติดตั้งของ Hermes เอง ซึ่งจะใช้เวลาสองสามนาทีในครั้งแรก รันไทม์นั้นคือ Hermes ตัวเดียวที่คำสั่ง `hermes` ในเทอร์มินัล, เอเจนต์เริ่มต้น และแอปทั้งหมดใช้ร่วมกัน และมันอัปเดตตัวเองด้วย `hermes update` แทนที่จะรอการเปิดตัว Omarchy การติดตั้งมันยังมอบธีม Omarchy ให้ Hermes เป็นสกินชื่อ `omarchy` ซึ่งทุกพื้นผิวของ Hermes จะทำตามเมื่อคุณเปลี่ยนธีม; เลือกอีกอันได้ใต้การตั้งค่า Appearance ของ Hermes หรือด้วย `/skin` หากคุณไม่อยากให้มันทำแบบนั้น และ Omarchy จะปล่อยตัวเลือกนั้นไว้ตามเดิม การลบแอปใต้ _Remove > AI_ จะปิด Hermes ก่อน รวมถึงเกตเวย์ด้วย, นำรันไทม์นั้นไปด้วย และเก็บการแชท, ความทรงจำ และสกิลที่ Hermes เขียนไว้สำหรับตัวเองของคุณไว้ เว้นแต่คุณจะบอกเป็นอย่างอื่น: มันจะถาม โดยค่าเริ่มต้นคือไม่ ว่าข้อมูลนั้นและการตั้งค่าการเชื่อมต่อของคุณควรจะไปด้วยหรือไม่

ประสบการณ์บนเดสก์ท็อปของ OpenClaw คือ Control UI ของมัน ซึ่งเปิดเป็นเว็บแอปที่ได้รับการสนับสนุนโดยเกตเวย์แบบโลคัลของตัวเอง OpenClaw อาศัยอยู่ใน `~/.openclaw` และอัปเดตตัวเอง: ใช้ปุ่ม "Update Gateway" ของ Control UI หรือเรียกใช้ `openclaw update` และเกตเวย์จะรีสตาร์ทบนเวอร์ชันใหม่ Omarchy จะเลือกเฉพาะรุ่นที่การติดตั้งใหม่จะเริ่มต้นจากเท่านั้น OpenClaw ยังสามารถเป็นเอเจนต์เริ่มต้นของคุณได้ด้วย: การเลือกมันใต้ _Agent > Harness_ จะตั้งค่าสำเนาเดียวกันนั้นใน `~/.openclaw` และเอเจนต์จะเปิดอินเทอร์เฟซผู้ใช้แบบเทอร์มินัลของ OpenClaw ที่เชื่อมต่อกับเกตเวย์ของมัน การลบ OpenClaw ใต้ _Remove > AI_ จะนำบริการเกตเวย์และแอปไปด้วย จากนั้นจะถามว่า `~/.openclaw` ควรจะไปด้วยหรือไม่ เนื่องจากที่นั่นเก็บการแชทและข้อมูลประจำตัวของคุณไว้ข้าง ๆ OpenClaw เองและรันไทม์ปลั๊กอินที่มันดาวน์โหลดมา; ค่าเริ่มต้นจะเก็บมันไว้ และการติดตั้ง OpenClaw อีกครั้งจะหยิบมันกลับขึ้นมา

Herdr Desktop คือแอปเดสก์ท็อป [Herdr](https://herdr.dev): พื้นที่, แท็บ และบานหน้าต่างของเทอร์มินัลและเอเจนต์เขียนโค้ดที่ยังคงทำงานอยู่ในแกนหลักของมันเมื่อคุณปิดหน้าต่าง มันมาจากตัวติดตั้งของ Herdr เองแทนที่จะเป็นแพ็กเกจ ดังนั้นมันจึงอาศัยอยู่ใน `~/.local/share/herdr-app`, นำแกนหลักของมันมาด้วยใน `~/.local/bin/herdr-core` เมื่อคุณยังไม่มี และอัปเดตทั้งตัวมันเอง มันตั้งอยู่ข้างคำสั่ง `herdr` ที่ Omarchy ส่งมาบน `Super + Ctrl + Return` แทนที่จะแทนที่มัน และได้รับปุ่มโดยตรงของคำสั่งนั้น: `Alt + Return` และ `Alt + Shift + Return` จะแยกบานหน้าต่างลงหรือไปทางขวา, `Alt + Escape` จะปิดมัน, `Ctrl + Alt + Arrow` จะย้ายระหว่างบานหน้าต่าง, `Alt + 1..9` และ `Alt + Left/Right` จะเลือกแท็บ และ `Alt + Up/Down` จะย้ายระหว่างพื้นที่ `Ctrl + 1..9` จะเลือกพื้นที่และ `Alt + Shift + Up/Down` จะก้าวผ่านเอเจนต์ ปุ่มนำหน้า `Ctrl + Space` ยังคงเป็นของเทอร์มินัลเท่านั้น เนื่องจากแอปไม่สามารถกดปุ่ม Ctrl ธรรมดาไว้สำหรับลำดับได้ Omarchy เขียนสิ่งเหล่านี้ไปยัง `~/.config/herdr-app/keys.json` และ `omarchy-refresh-herdr-app` จะใส่พวกมันกลับคืน การติดตั้งมันจะเลือกธีม Omarchy ของ Herdr ซึ่งทำตามธีม Omarchy ของคุณตั้งแต่นั้นเป็นต้นมา Herdr เก็บธีมหนึ่งสำหรับโหมดสว่างและอีกธีมหนึ่งสำหรับโหมดมืด ดังนั้นหลังจากสลับระหว่างธีม Omarchy แบบมืดและแบบสว่างแล้ว ให้เลือก Omarchy ในตัวเลือกธีมของ Herdr อีกครั้งสำหรับโหมดอื่น

T3 Code ทำงานจากรุ่น AppImage อย่างเป็นทางการของมันใน `~/.local/share/t3code` แทนที่จะเป็นแพ็กเกจ ดังนั้นมันจึงอัปเดตตัวเอง การติดตั้งมันจะถามว่าจะเริ่มบนช่อง Stable หรือ Nightly; สลับภายหลังได้ในการตั้งค่าของ T3 Code เธรดและการตั้งค่าของคุณอาศัยอยู่ใน `~/.t3` และการลบ T3 Code ใต้ _Remove > AI_ จะนำพวกมันไปด้วย

### โมเดลแบบโลคัล

เรียกใช้โมเดลแบบเปิดบนเครื่องของคุณเองสำหรับเอเจนต์เขียนโค้ดของคุณ พรอมต์และโค้ดของคุณยังคงอยู่บนเครื่อง; ไม่มีอะไรที่ส่งให้โมเดลออกจากเครื่อง เริ่มต้นด้วย:

```bash
omarchy models use best text
```

นั่นจะตั้งค่าโมเดลข้อความที่ดีที่สุดสำหรับเครื่องนี้ ซึ่งเป็นประเภทที่เอเจนต์ของคุณใช้ โมเดลรูปภาพ, วิดีโอ และเพลงมีตัวที่ดีที่สุดของตัวเอง: `omarchy models use best image`, `video` หรือ `music` เรียกใช้ `omarchy models use best` เพื่อดูตัวเลือกของแต่ละประเภทสำหรับเครื่องนี้

หรือเปิดแผงโมเดลแบบโลคัลจากไอคอนประกายแวววาวของมันในแถบบนสุด ถัดจากไอคอนเอเจนต์ หรือด้วย Super + Ctrl + Shift + X และเลือก + ไอคอนจะปรากฏขึ้นเมื่อมีโมเดลที่เหมาะสมกับเครื่องนี้ Podman ซึ่งเรียกใช้โมเดล มาพร้อมกับ Omarchy เช่นเดียวกับชุดเครื่องมือคอนเทนเนอร์ของ NVIDIA บนเครื่อง NVIDIA ซึ่งให้ GPU แก่พวกมัน; หากตัวใดตัวหนึ่งหายไป การตั้งค่าครั้งแรกจะติดตั้งมัน จากนั้น Omarchy จะเลือกโมเดลที่แนะนำสำหรับเครื่องนี้ ดาวน์โหลดมัน และเริ่มมัน คาดว่าจะมีการดาวน์โหลดขนาดหลายสิบ GB และหน่วยความจำส่วนใหญ่ของเครื่องจะถูกใช้งานขณะที่โมเดลทำงาน: Flash Next ใช้ประมาณ 100 GiB โดยมีบริบทเต็ม 256K ของมัน หากโมเดลอื่น ๆ ยึดหน่วยความจำที่มันต้องการไว้ มันจะถูกตั้งค่าในสถานะหยุด พร้อมที่จะเริ่มเมื่อคุณหยุดตัวหนึ่งลง โมเดลจะหยุดเมื่อออกจากระบบ; หยุดมันด้วยตัวเองเมื่อคุณต้องการหน่วยความจำสำหรับอย่างอื่น

`omarchy models list` จะแสดงตัวเลือกและอธิบายว่าทำไมบางตัวไม่พอดี หากต้องการตั้งค่าอีกตัว ให้เรียกใช้ `omarchy models use <recipe>` ในปัจจุบัน `qwen3.8-flash-next-gufo` และ `qwen3.8-27b-gufo` พร้อมใช้งานสำหรับเครื่อง Strix Halo ขนาด 128 GB; ตัว 27B ใช้ประมาณ 40 GiB ดังนั้นมันจึงเหลือพื้นที่สำหรับงานอื่น บนแล็ปท็อปขนาด 64 GB ที่มี Intel's Arc B390, `qwen3.6-35b-a3b-llamacpp` จะทำงานในประมาณ 30 GiB สูตรและคำแนะนำใหม่จะมาพร้อมกับ `omarchy update` ผ่านแพ็กเกจ

โมเดลทุกตัวที่คุณตั้งค่าจะได้รับบรรทัดของตัวเองในแผงโมเดลแบบโลคัล: เล่นเพื่อเริ่มมัน, หยุดชั่วคราวเพื่อหยุดมันและทำให้หน่วยความจำว่าง และปุ่มเทอร์มินัลเพื่อเปิดเอเจนต์ของคุณบนมัน ข้ามด้านบน แถบหนึ่งจะแสดงว่าหน่วยความจำของเครื่องถูกแบ่งระหว่าง Omarchy เอง (ระบบและแอปของคุณ) โมเดลที่กำลังทำงานแต่ละตัว และสิ่งที่ว่างอยู่ อย่างไร ชี้ไปที่โมเดลที่หยุดอยู่และแถบจะแสดงว่ามันพอดีหรือไม่ หรือมันขาดอีกเท่าไหร่ หลายตัวสามารถทำงานพร้อมกันได้เมื่อพวกมันพอดีในหน่วยความจำด้วยกัน; หากตัวหนึ่งไม่พอดี Omarchy จะบอกว่าต้องหยุดโมเดลที่กำลังทำงานตัวใด ลากบรรทัดด้วยโลโก้ของพวกมันเพื่อจัดลำดับใหม่ และกด Delete บนบรรทัดที่เลือกเพื่อลบโมเดลและการดาวน์โหลดของมัน

โมเดลทุกตัวที่คุณตั้งค่ายังได้รับรายการของตัวเองในตัวเปิดใช้แอป ภายใต้ชื่อของโมเดลและพร้อมโลโก้ของผู้สร้าง ในแบบเดียวกับที่การลงชื่อเข้าใช้ Claude, Codex หรือ Grok เพิ่มรายการหนึ่ง มันจะเปิดเอเจนต์ของคุณบนโมเดลนั้น และเริ่มโมเดลก่อนหากมันยังไม่ได้ทำงาน: เทอร์มินัลจะแสดงมันกำลังโหลดและส่งมอบให้เอเจนต์เมื่อมันพร้อม การลบโมเดลจะลบรายการของมัน

ไม่ใช่ทุกโมเดลที่มีไว้สำหรับเขียนโค้ด โมเดลรูปภาพ, วิดีโอ และเพลงจะเปิดใน Fantasi แทน ซึ่งเป็นแอปของ Omarchy สำหรับสร้างรูปภาพ, วิดีโอ และเพลงด้วยโมเดลที่ทำงานบนเครื่องนี้ จากรายการตัวเปิดใช้ของพวกมันและจากบรรทัดของพวกมันในแผงโมเดลแบบโลคัล

โมเดลจะยังคงทำงานอย่างที่มันถูกตั้งค่าไว้ ดังนั้นการอัปเดต Omarchy จะไม่รีสตาร์ทตัวใดตัวหนึ่งภายใต้เอเจนต์ของคุณ เมื่อ Omarchy มีรันไทม์ที่ใหม่กว่าหรือน้ำหนักที่ใหม่กว่าสำหรับโมเดลที่คุณตั้งค่าไว้ บรรทัดของมันจะแสดงปุ่มอัปเดต: กดมันและโมเดลจะถูกตั้งค่าอีกครั้งในเบื้องหลัง โดยดาวน์โหลดเฉพาะสิ่งที่เปลี่ยนแปลง และรีสตาร์ทบนเวอร์ชันใหม่ โมเดลที่เคยหยุดอยู่จะยังคงหยุดอยู่ `omarchy models update` จะทำสิ่งเดียวกันสำหรับทุกโมเดลจากเทอร์มินัล

จากบรรทัดคำสั่ง `omarchy models start <recipe>` และ `omarchy models stop <recipe>` จะทำสิ่งเดียวกัน, `omarchy models status` จะแสดงทุกโมเดล และ `omarchy agent --local` จะเปิดเอเจนต์เริ่มต้นของคุณบนโมเดลล่าสุดที่คุณเริ่ม pi, OpenCode และ Qwen Code สามารถใช้ตัวหนึ่งได้; กับค่าเริ่มต้นตัวอื่น ๆ มันจะเปิดใน pi หรือใน OpenCode หากคุณไม่มี pi pi ยังแสดงรายการทุกโมเดลที่คุณตั้งค่าไว้ และโมเดลบนเครื่องที่คุณจับคู่ด้วย ในตัวเลือกโมเดลของตัวเอง ดังนั้น `pi` ธรรมดาก็เข้าถึงพวกมันได้เช่นกัน ไคลเอนต์ที่เข้ากันได้กับ OpenAI ตัวใดก็สามารถเชื่อมต่อได้เช่นกัน: `status` จะแสดงที่อยู่ของแต่ละโมเดล (ตัวแรกคือ `http://127.0.0.1:11435/v1`) ชื่อสูตรคือโมเดล และคีย์อยู่ใน `~/.config/omarchy/agent-local/key`

`omarchy models remove <recipe>` จะลบโมเดลและการดาวน์โหลดที่ไม่มีโมเดลอื่นใช้

รันไทม์ของบุคคลที่สามจะถูกติดป้ายด้วยผู้เผยแพร่ของมัน Omarchy เรียกใช้ทุกโมเดลโดยไม่มีการเข้าถึงเครือข่าย

### LLM แบบโลคัล

Omarchy แนะนำสองวิธีในการเรียกใช้โมเดล LLM แบบโลคัล: LM Studio และ Ollama LM Studio ให้อินเทอร์เฟซแบบ GUI สำหรับค้นหาโมเดลแบบน้ำหนักเปิด, ติดตั้งพวกมัน และเรียกใช้พวกมัน มันเป็นวิธีที่ยอดเยี่ยมในการเริ่มต้นอย่างง่ายดาย Ollama เสนอ CLI สำหรับทำสิ่งเดียวกันในลักษณะคล้าย ๆ กัน แต่หากคุณยังใหม่กับโมเดลแบบโลคัล ฉันจะเริ่มด้วย LM Studio คุณสามารถติดตั้งตัวใดตัวหนึ่งได้ใต้ _Install > AI_ ใน Omarchy Menu

### สกิลของ Omarchy

สกิลของเอเจนต์ช่วยให้ AI ใช้เครื่องมือเฉพาะในวิธีเฉพาะ และ Omarchy ส่งมาพร้อมเจ็ดสกิล สกิล omarchy ครอบคลุมการปรับแต่งระบบ เช่น การปรับ config Hyprland ของคุณหรือการปรับแถบ omarchy-make-theme, omarchy-make-plugin, omarchy-make-app และ omarchy-make-game ครอบคลุมการสร้างสิ่งใหม่, omarchy-contribute ครอบคลุมการรายงานข้อผิดพลาดหรือการส่งการแก้ไขไปยังต้นทาง และ omarchy-diagnose-crash จะทำงานผ่าน core dump ของการแครช พวกมันถูกเชื่อมโยงเป็นสัญลักษณ์เข้าไปในไดเรกทอรีสกิลสำหรับ Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` และแต่ละ `~/.hermes/profiles/*/skills`) และตำแหน่งทั่วไป `~/.agents/skills` ดังนั้นฮาร์เนสส่วนใหญ่จึงหยิบพวกมันขึ้นมาโดยอัตโนมัติ โฟลเดอร์สกิลของคุณเองที่มีชื่อเดียวกันจะมีลำดับความสำคัญสูงกว่า

แต่คุณควรปฏิบัติต่อสกิลเหล่านี้ในฐานะสิ่งที่ยังอยู่ในขั้นทดลอง โมเดลที่แตกต่างกันจะใช้มันให้เกิดผลที่แตกต่างกัน มันดีที่สุดที่จะทำงานในโหมดวางแผนก่อน เพื่อให้คุณมีความคิดว่าเอเจนต์อยากเปลี่ยนอะไร แล้วจงเตรียมพร้อมที่จะย้อนกลับการเปลี่ยนแปลงหรือแม้แต่เรียกใช้ `omarchy reinstall configs` หากเอเจนต์ทำให้ทุกอย่างยุ่งเหยิงไปหมด
