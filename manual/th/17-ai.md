### การติดตั้งและอัปเดตเอเจนต์

นอกจาก Hermes และ OpenClaw เอเจนต์เหล่านี้ใช้การติดตั้งแบบ lazy ของ mise: การเปิดใช้ครั้งแรกจะติดตั้ง CLI และการเปิดใช้ครั้งต่อ ๆ ไปจะใช้ตัวที่ติดตั้งไว้ mise ยังตรวจสอบด้วยว่าเอเจนต์ที่ติดตั้งไว้มีรุ่นใหม่ออกมาหรือไม่ อย่างมากที่สุดหนึ่งครั้งทุกสี่ชั่วโมง ก่อนที่มันจะเริ่มทำงานไม่นาน หรือในเบื้องหลังที่พรอมต์ของเชลล์ หากการอัปเดตนั้นล้มเหลวหรือคุณออฟไลน์อยู่ รุ่นที่ติดตั้งไว้จะทำงาน `omarchy update` จะอัปเดตเอเจนต์ที่ติดตั้งไว้พร้อมกับส่วนที่เหลือของ Omarchy และ `mup` จะอัปเดตเฉพาะเครื่องมือที่ mise จัดการเท่านั้น

โปรแกรมอัปเดตของเอเจนต์เอง เช่น `claude update`, `codex update` หรือปุ่มอัปเดตในแอป จะไม่อัปเดตตัวที่ติดตั้งผ่าน mise `codex update` จะล้มเหลว และ `claude update` อาจรายงานว่าสำเร็จในขณะที่ติดตั้งสำเนาแยกอีกตัวที่ mise ไม่ได้ติดตาม หากคุณอยากใช้โปรแกรมติดตั้งและโปรแกรมอัปเดตเฉพาะตัวของเอเจนต์มากกว่า ให้เพิ่มมันลงใน `disable_tools`; ดู [เครื่องมือ CLI ที่ติดตั้งไว้ล่วงหน้า](18-development-tools.md#preinstalled-cli-tools)

หากต้องการติดตั้งเครื่องมือ lazy ที่กำหนดค่าไว้ทั้งหมดก่อนที่คุณจะต้องการใช้ ให้รัน `mise install --include-lazy` ซึ่งรวมถึงเครื่องมือ CLI เริ่มต้นอื่น ๆ ของ Omarchy ด้วยเช่นเดียวกับเอเจนต์ต่าง ๆ ดู [เครื่องมือ CLI ที่ติดตั้งไว้ล่วงหน้า](18-development-tools.md#preinstalled-cli-tools) สำหรับการติดตั้งเครื่องมือตัวเดียวหรือใช้การติดตั้งของคุณเอง

`grok` ติดตั้งผ่านแพ็กเกจ `grok` ทางการของ mise ในแบบเดียวกับ `claude` และ `codex` รัน `grok` หรือเลือกมันใต้ _Agent > Harness_ ข้ามโปรแกรมติดตั้งแบบ `curl | bash` บน x.ai ไปเลย เส้นทางนั้นจะวางสำเนาที่สองไว้ใน `~/.grok/bin`, นำหน้ามันบน `PATH` และเขียนทับ wrapper ของ Omarchy

`dsh` เปิด UI บนเบราว์เซอร์ของมันที่ `127.0.0.1:3080` โดยใช้ไดเรกทอรีที่เปิดใช้เป็น workspace เริ่มต้น UI บนเบราว์เซอร์ของมันไม่รับพรอมต์เริ่มต้น ดังนั้น `omarchy agent prompt` จะเปิดมันโดยมีพรอมต์อยู่บนคลิปบอร์ดของคุณให้วาง Omarchy เริ่มมันด้วยชุดสิทธิ์แบบไม่ต้องขออนุมัติของ DeepSeek DeepSeek Harness จะอัปโหลดบันทึกเซสชันไปยัง DeepSeek เมื่อคุณใช้ API โมเดลทางการของมัน; ปิดการทำงานนั้นได้ใต้ _Settings > General > Upload Session Log_ ใน UI บนเบราว์เซอร์ของมัน ความคิดเห็นที่คุณส่งให้มันจะถูกอัปโหลดไปพร้อมกับเซสชันด้วย เว้นแต่คุณจะเริ่มมันด้วย `DSH_TELEMETRY_MODE=DISABLED`

### เอเจนต์เริ่มต้น

เลือกเอเจนต์เริ่มต้นของคุณด้วย `omarchy default agent <name>` หรือใต้ _Agent > Harness_ ใน Omarchy Menu (`Super + Space`) หากเอเจนต์ยังไม่ได้ติดตั้ง การเลือกมันจะติดตั้งมันก่อน และมันยังได้ตัวเรียกใช้ของตัวเองในตัวเรียกใช้แอป ถัดจาก Agent ด้วย Omarchy ที่ติดตั้งใหม่จะชวนให้คุณเลือกนี้ด้วยการแจ้งเตือนครั้งเดียว

การเลือก Claude ยังพยายามตั้งค่าส่วนขยายเบราว์เซอร์ของมันสำหรับ Chromium, Chrome, Brave, Brave Origin และ Edge ด้วย การตั้งค่าส่วนขยายใช้กับผู้ใช้ทุกคนและอาจขอรหัสผ่านระบบของคุณ; การยกเลิกหรือการติดตั้งส่วนขยายที่ล้มเหลวยังคงเลือกและเปิดใช้ Claude อยู่ดี รีสตาร์ทเบราว์เซอร์ของคุณ เปิดใช้งานส่วนขยายหากระบบขอ และลงชื่อเข้าใช้ Claude เพื่อเชื่อมต่อให้เสร็จ รัน `/chrome` ใน Claude เพื่อตรวจสอบการเชื่อมต่อ Firefox และ Zen ไม่รองรับส่วนขยายนี้ หาก Claude เป็นค่าเริ่มต้นของคุณอยู่แล้วก่อนที่จะมีการเพิ่มการตั้งค่านี้ ให้เลือกมันอีกครั้งเพื่อติดตั้งส่วนขยาย

เมื่อคุณเลือกแล้ว `Super + Shift + Ctrl + A` จะเปิดเอเจนต์เริ่มต้นในหน้าต่างเทอร์มินัลเฉพาะ (หรือเปิดตัวเลือกขึ้นมาหากคุณยังไม่ได้เลือก) คุณยังเปิดมันให้เข้าสู่งานได้โดยตรงด้วย `omarchy agent prompt "Review this project"` Freebuff และ DeepSeek Harness ไม่รับพรอมต์เริ่มต้น ดังนั้นพวกมันจะเปิดโดยมีพรอมต์อยู่บนคลิปบอร์ดของคุณให้วางแทน เอเจนต์ที่เปิดใช้ด้วยวิธีนี้จะทำงานโดยไม่มีผู้ดูแลในโหมดไม่หยุดเพื่อถามของแต่ละตัว ดังนั้นเตรียมตัวให้พร้อมสำหรับให้พวกมันลงมือทำสิ่งต่าง ๆ จริง ๆ! MiniMax Code ไม่มีโหมดแบบนั้นสำหรับเซสชันแบบโต้ตอบของมัน ดังนั้นมันจะขอสิทธิ์ตามปกติ และเนื่องจากเอเจนต์ปฏิเสธที่จะจดจำความเชื่อถือสำหรับไดเรกทอรีบ้านของคุณ การเปิดใช้จาก `$HOME` จะเริ่มใน `~/Work` แทน

ยังมีทางลัดในเทอร์มินัลด้วย: `a` รันเอเจนต์เริ่มต้นแบบอินไลน์ในเทอร์มินัลปัจจุบัน ขณะที่ `c`, `cx` และ `cy` เริ่ม OpenCode, Claude Code และ Codex โดยตรง (ในโหมดอนุมัติอัตโนมัติของพวกมันอีกเช่นกัน) การเปลี่ยนธีมยังซิงค์ไปยังเอเจนต์ด้วย: Claude Code, Pi, OpenCode และ Hermes (เมื่อ Omarchy ติดตั้งมันแล้ว) ทั้งหมดจะเปลี่ยนตามเมื่อคุณเปลี่ยนธีมของ Omarchy

### คำแนะนำสำหรับเอเจนต์ของคุณ

กฎส่วนตัวสำหรับเอเจนต์ทุกตัวอยู่ใน `~/.agents/AGENTS.md` ถัดจากสกิลที่แชร์กันใน `~/.agents/skills` เปิดมันใต้ _Agent > Instructions_ ซึ่งยังเชื่อมโยงมันเข้าไปในแต่ละ harness ที่เก็บไฟล์ส่วนกลางของตัวเองไว้: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` ของ Copilot และอื่น ๆ Crush และ Amp อ่านลิงก์ `~/.config/AGENTS.md` ขณะที่ omp, Kimi และ DeepSeek Harness อ่าน `~/.agents/AGENTS.md` โดยตรง การเลือกเอเจนต์เริ่มต้นก็เชื่อมโยงมันด้วยเช่นกัน ไฟล์คำแนะนำที่คุณมีอยู่แล้วจะกลายเป็นไฟล์ที่แชร์กันหากยังไม่มีไฟล์ดังกล่าวอยู่; มิฉะนั้นมันจะถูกเก็บไว้ข้างลิงก์ในชื่อ `.bak` รัน `omarchy agent instructions` เพื่อเชื่อมโยงใหม่หลังจากติดตั้งเอเจนต์อีกตัว

### แผงเอเจนต์

แถบด้านบนมีไอคอนเอเจนต์ ก่อนที่คุณจะตั้งค่าเอเจนต์ แผงของมันจะแนะนำคุณตลอดการลงชื่อเข้าใช้ Claude, Codex หรือ Grok และตัวแรกจะกลายเป็นเอเจนต์เริ่มต้นของคุณ หลังจากนั้น แผงจะวางทุกการสมัครสมาชิกไว้ในหน้าเดียว: เอเจนต์และบัญชีแต่ละรายการพร้อมแผนของมัน มาตรวัดสำหรับขีดจำกัดเซสชัน 5 ชั่วโมงและรายสัปดาห์แต่ละรายการพร้อมเวลาจนกว่ามันจะรีเซ็ต (วางเมาส์เหนือเพื่อดูเปอร์เซ็นต์ที่แน่นอน) หรือยอดเงินแบบเติมเงินคงเหลือ ใต้บรรทัดที่หมุนเวียนสิ่งที่คุณใช้ไปในทุกรายการ เช่น โทเค็นในสัปดาห์นี้และโมเดลที่คุณใช้มากที่สุด ใต้ _Make something cool_ มันเสนอพรอมต์เริ่มต้นสำหรับธีม ปลั๊กอิน แอป หรือเกมใหม่ที่มอบงานนั้นให้เอเจนต์เริ่มต้นของคุณ แอปถูกสร้างในแบบเดียวกับ Hype, Monologue และ Omacut ของ Omarchy เอง ใน C++ และ Qt Quick โดยทำตามสกิลเอเจนต์ omarchy-make-app และคอมไพเลอร์กับชิ้นส่วน Qt ที่พวกมันต้องการก็ติดตั้งมาให้แล้ว เกมเป็นหน้า three.js หน้าเดียวใน `~/Games/vibes` โดยทำตามสกิลเอเจนต์ omarchy-make-game และทั้งหมดเปิดจากตัวเรียกใช้ Game Vibes ตัวเดียวในธีมปัจจุบัน; พวกมันโหลด three.js จากเว็บ ดังนั้นพวกมันต้องการการเชื่อมต่อเพื่อเริ่ม Claude Code, Codex, Grok, Kimi, Cursor และโควตา Grok Bot ของมัน, GitHub Copilot, Muse, Antigravity และ Devin ได้รับการครอบคลุมตั้งแต่แรกพร้อมขีดจำกัดของพวกมัน, Kimchi พร้อมแผน เครดิตแบบเติมเงิน และงบการใช้จ่ายของมัน และ Hermes, Mistral Vibe และ Qwen Code จะแสดงเซสชันและโทเค็นของพวกมันเมื่อคุณใช้พวกมันแล้ว แผนและคีย์ของผู้ให้บริการที่คุณใช้ผ่าน pi, omp หรือ opencode ก็ปรากฏด้วยเช่นกัน: OpenCode Zen และ Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan และ Synthetic พร้อมขีดจำกัดของพวกมัน; OpenRouter และ DeepSeek พร้อมยอดเงินแบบเติมเงินของพวกมัน; Fireworks พร้อมการใช้จ่ายของมันในช่วง 30 วันที่ผ่านมา โทเค็นจากโมเดลที่คุณรันบนฮาร์ดแวร์ของคุณเองก็นับรวมในยอดรวมด้วยเช่นกัน; โมเดลเหล่านั้นเองมีแผงของตัวเอง ซึ่งอธิบายไว้ใต้ [โมเดลในเครื่อง](#local-models) เอเจนต์ทุกตัวถูกนับเพียงครั้งเดียว ภายใต้ผู้ที่เรียกเก็บเงินจากมัน ไม่ว่าคุณจะขับเคลื่อนมันผ่าน harness กี่ตัวก็ตาม

คลิกซ้ายที่ไอคอนบนแถบหรือกด `Super + Ctrl + X` เพื่อเปิดแผง คลิกขวาเพื่อเปิดเอเจนต์เริ่มต้นของคุณ และคลิกกลางเพื่อรีเฟรช บันทึกการใช้งานที่อยู่เบื้องหลังมันจะถูกสร้างใหม่ทุก 15 นาทีโดย `omarchy agent usage update` และแผงยังสามารถรวมการใช้งานจากเครื่องอื่น ๆ ของคุณผ่านโฟลเดอร์ที่ซิงค์กันได้ ดู README ใต้ `$OMARCHY_PATH/shell/plugins/agents/` สำหรับการตั้งค่าทั้งหมด

### การสมัครสมาชิกหลายรายการ

หากคุณจ่ายเงินสำหรับแผน Claude, Codex หรือ Grok มากกว่าหนึ่งแผน — เช่น Max ส่วนตัวและอีกอันสำหรับงาน — Omarchy สามารถให้พวกมันทั้งหมดลงชื่อเข้าใช้อยู่และย้ายไปมาระหว่างพวกมันได้ เพิ่มการสมัครสมาชิกด้วย + ในแผงเอเจนต์ ซึ่งจะแนะนำคุณตลอดขั้นตอนตรงนั้นเลย หรือด้วย `omarchy agent account add claude Work` (หรือ `codex` หรือ `grok`) มันจะติดตั้ง CLI หากยังไม่มี บัญชีแรกสำหรับผู้ให้บริการรายหนึ่งจะลงชื่อเข้าใช้ผ่านเบราว์เซอร์ปกติของคุณ ตรงที่ที่ CLI มองหาเสมอ ทุกบัญชีหลังจากนั้นจะลงชื่อเข้าใช้ผ่านหน้าต่างส่วนตัว ดังนั้นบัญชีที่เบราว์เซอร์ของคุณลงชื่อเข้าใช้อยู่แล้วจะไม่ถูกหยิบมาโดยไม่ตั้งใจ; ลงชื่อเข้าใช้ที่นั่นในฐานะบัญชีที่คุณกำลังเพิ่ม และปิดหน้าต่างส่วนตัวใด ๆ ที่คุณเปิดไว้อยู่แล้วก่อน อย่าออกจากระบบ CLI เพื่อทำสิ่งนี้เด็ดขาด: การออกจากระบบจะเพิกถอนการลงชื่อเข้าใช้ที่บันทึกไว้ และบัญชีนั้นจะต้องถูกเพิ่มอีกครั้ง

หากต้องการคัดลอกการเข้าสู่ระบบการสมัครสมาชิกของคุณไปยังเครื่อง Omarchy อีกเครื่องผ่าน SSH ให้รัน `omarchy agent account copy user@laptop` ผู้ส่งจะจัดหาตัวรับชั่วคราวให้เมื่อปลายทางยังไม่มีตัวรับติดตั้งไว้ ดังนั้นเครื่อง Omarchy รุ่นเก่ากว่าสามารถรับบัญชีได้โดยไม่ต้องอัปเดต ตัวรับที่ติดตั้งไว้จะมีความสำคัญเหนือกว่า นี่จะคัดลอกการสมัครสมาชิก Claude, Codex และ Grok ทั้งหมด; เพิ่มชื่อผู้ให้บริการเพื่อเลือกพวกมัน เช่นใน `omarchy agent account copy laptop claude` ชื่อบัญชีและ ID คำสั่งจะตรงกับต้นทาง รวมถึงบัญชีที่มีอยู่แล้วบนปลายทาง บัญชีปลายทางที่ไม่เกี่ยวข้องจะได้รับคำต่อท้ายเป็นตัวเลขหากชื่อของพวกมันขัดกัน และการตั้งค่า สกิล ปลั๊กอิน และประวัติการสนทนาจะยังคงอยู่ในเครื่องแต่ละเครื่อง

ข้อมูลประจำตัวปลายทางที่มีอยู่จะถูกเก็บไว้ บัญชีต้นทางที่ลงชื่อเข้าใช้ที่นั่นอยู่แล้วจะมีชื่อของมันซิงค์โดยไม่แทนที่ข้อมูลประจำตัวของมัน; บัญชีอื่น ๆ จะถูกเพิ่มควบคู่ไปกับมัน หากต้องการแทนที่ข้อมูลประจำตัวที่บันทึกไว้สำหรับบัญชีที่ตรงกัน ให้ใช้ `omarchy agent account copy --replace laptop claude` หลังจากออกจากเซสชันของบัญชีนั้นบนปลายทางแล้ว ปลายทางใหม่ยังจะได้รับบัญชีที่ใช้งานอยู่และการตั้งค่าการสลับของต้นทางด้วย; ปลายทางที่มีอยู่แล้วจะเก็บของตัวเองไว้

ข้อมูลประจำตัวเดินทางผ่าน SSH และถูกเก็บไว้ในไฟล์ส่วนตัวบนปลายทาง ดังนั้นคัดลอกไปยังเครื่องที่คุณไว้ใจเท่านั้น นี่เป็นการคัดลอกครั้งเดียว ไม่ใช่การซิงโครไนซ์ต่อเนื่อง โทเค็นรีเฟรชของ Codex สามารถถูกหมุนเวียนโดยเครื่องอื่นได้ ทำให้การเข้าสู่ระบบที่คัดลอกมาต้องต่ออายุ; การลงชื่อเข้าใช้แยกกันยังคงเป็นตัวเลือกที่น่าเชื่อถือที่สุดสำหรับการใช้งานพร้อมกันบนหลายเครื่อง ดู [คำแนะนำการยืนยันตัวตนบัญชีของ Codex](https://developers.openai.com/codex/auth/ci-cd-auth)

บัญชีเดียวต่อผู้ให้บริการจะใช้งานอยู่ และทุกเซสชันใหม่จะเริ่มในฐานะบัญชีนั้น: `cx`, `cy`, `claude`, `codex` หรือ `grok` ธรรมดา อะไรก็ตามที่เปิดใช้ผ่าน `omarchy agent` และสคริปต์หรือโปรแกรมแก้ไขที่พบ CLI บน `PATH` สลับด้วย `omarchy agent account use work` (และกลับด้วย `omarchy agent account use main`) หรือในแผงโดยกดหมายเลขของบัญชีแล้วกด `Enter` (หรือคลิกปุ่ม Use ของมัน) เซสชัน Claude ที่กำลังทำงานอยู่ก็สลับด้วยเช่นกัน ตั้งแต่ข้อความถัดไปของพวกมัน: ทุกเซสชัน Claude ทำงานใน `~/.claude` ซึ่งเก็บการลงชื่อเข้าใช้ของบัญชีที่ใช้งานอยู่เสมอ เซสชัน Claude ที่เริ่มในโฟลเดอร์เฉพาะของบัญชีโดย Omarchy รุ่นเก่ากว่าจะเก็บการลงชื่อเข้าใช้นั้นไว้จนกว่ามันจะออก ดังนั้นการสลับจะระบุชื่อเซสชันเหล่านั้นและเสร็จสิ้นเองเมื่อพวกมันหายไป เซสชัน Codex และ Grok ที่กำลังทำงานอยู่จะยังคงอยู่กับบัญชีที่พวกมันเริ่มด้วย ประวัติการสนทนา การตั้งค่า สกิล และปลั๊กอินถูกแชร์ข้ามบัญชี ดังนั้น `claude --continue` ในโฟลเดอร์เดียวกันจะดำเนินการต่อจากจุดที่คุณค้างไว้บนบัญชีใหม่

เมื่อมีมากกว่าหนึ่งบัญชี แผงจะแสดงขีดจำกัดของแต่ละบัญชีเคียงข้างกัน โดยบัญชีที่ใช้งานอยู่จะถูกทำเครื่องหมายไว้ โดยค่าเริ่มต้น Omarchy จะแจ้งเตือนคุณเมื่อบัญชีที่ใช้งานอยู่ผ่าน 95% ของขีดจำกัด และการคลิกการแจ้งเตือนจะสลับไปยังบัญชีที่มีพื้นที่เหลือมากที่สุด วางเมาส์เหนือบรรทัดของบัญชีในแผงและคลิก Autoswitch ที่ปรากฏถัดจาก Use (หรือกด `m`) หรือรัน `omarchy agent account mode auto` เพื่อให้มันสลับเองแทน; ขณะที่เปิดอยู่ Autoswitch จะแทนที่ Use และการคลิกมันอีกครั้งจะกลับไปเป็นการแจ้งเตือน เพิ่มตัวเลขเพื่อเปลี่ยนเกณฑ์ เช่นใน `omarchy agent account mode auto 90` หากทุกบัญชีเกินเกณฑ์ คุณจะได้รับแจ้งเกี่ยวกับเรื่องนั้นหนึ่งครั้ง พร้อมกับว่าบัญชีใดจะว่างก่อน ขณะที่บัญชีที่ใช้งานอยู่ภายใน 15 จุดจากเกณฑ์ของมัน (80% ที่ค่าเริ่มต้น) ขีดจำกัดของมันจะถูกตรวจสอบทุกสามนาทีแทนที่จะเป็นทุก 15 นาที

`omarchy agent account list` แสดงทุกบัญชีและขีดจำกัดล่าสุดของพวกมัน `omarchy agent account remove work` ลบบัญชีหนึ่งออก และ `omarchy agent account rename primary Hey` เปลี่ยนชื่อบัญชีหนึ่ง (หรือคลิกชื่อของบัญชีในแผง) คำสั่งเหล่านี้ทำงานกับบัญชีของเอเจนต์เริ่มต้นของคุณ; หากต้องการเข้าถึงผู้ให้บริการรายอื่น ให้ระบุชื่อมันก่อน เช่นใน `omarchy agent account use codex side` การเข้าสู่ระบบที่คุณมีอยู่แล้วใน `~/.claude` หรือ `~/.codex` คือบัญชี _Main_ ของ Codex จะยังคงอยู่ที่เดิม; ของ Claude จะรออยู่ในโฟลเดอร์ของตัวเองขณะที่บัญชีอื่นใช้งานอยู่ บัญชีที่ไม่ได้ใช้งานนานกว่าประมาณแปดชั่วโมงอาจแสดง _Sign-in required_; คลิกมันเพื่อลงชื่อบัญชีนั้นเข้าใช้ใหม่ในแผงเลย หรือสลับไปยังมันและเริ่มเซสชัน ซึ่งจะรีเฟรชการลงชื่อเข้าใช้เอง เซิร์ฟเวอร์ MCP ที่คุณเพิ่มด้วย `claude mcp add` จะเข้าถึงทุกบัญชี Claude เนื่องจากพวกมันทั้งหมดทำงานใน `~/.claude`; สำหรับ Codex และ Grok เซิร์ฟเวอร์ที่คุณมีเมื่อบัญชีถูกเพิ่มจะตามไปยังบัญชีนั้นด้วย แต่เซิร์ฟเวอร์หลังจากนั้นจะเข้าถึงเฉพาะบัญชีที่คุณเพิ่มพวกมันในนั้นเท่านั้น Claude Desktop เก็บการลงชื่อเข้าใช้ของตัวเองไว้ และเครื่องมือ Codex หรือ Grok ที่กำหนดค่าด้วยเส้นทางสัมบูรณ์ไปยังไบนารี CLI จะไม่ตามการสลับไป `CLAUDE_CONFIG_DIR`, `CODEX_HOME` หรือ `GROK_HOME` ที่ระบุอย่างชัดเจนจะมีความสำคัญเหนือบัญชีที่เลือก

### การวินิจฉัยการขัดข้อง

Omarchy เฝ้าดู systemd-coredump สำหรับการขัดข้องของกระบวนการ เมื่อคุณเลือกเอเจนต์เริ่มต้นแล้ว โปรแกรมใด ๆ ของคุณที่ dump core จะนำการแจ้งเตือน "Process crashed" มา — คลิกมัน และการขัดข้องจะถูกส่งให้เอเจนต์เริ่มต้นของคุณพร้อมกับสกิล omarchy-diagnose-crash ของ Omarchy ซึ่งจะแนะนำเอเจนต์ตลอดการสร้างข้อเท็จจริงจาก core dump และตัดสินใจว่าการขัดข้องนั้นคุ้มค่าที่จะรายงานไปยังต้นทางหรือไม่ คุณยังรันมันด้วยตนเองกับ PID ใด ๆ จาก `coredumpctl list` ด้วย `omarchy agent crash <pid>` ได้ด้วย

การเฝ้าดูเปิดอยู่โดยค่าเริ่มต้น ปิดมันใต้ _Trigger > Toggle > Crash Capture Off_ (หรือด้วย `omarchy toggle crash-capture`) และการแจ้งเตือนจะหยุด; `omarchy agent crash <pid>` ยังคงทำงานด้วยตนเองได้

การขัดข้องยังสามารถถูกปิดเสียงทีละโปรแกรมได้ ซึ่งเป็นสิ่งที่การวินิจฉัยเสนอให้คุณในตอนท้าย `omarchy crash mute hyprland` หยุดการแจ้งเตือนสำหรับโปรแกรมนั้นเท่านั้น `omarchy crash mute hyprland off` นำพวกมันกลับมา และ `omarchy crash mute` ด้วยตัวมันเองจะแสดงรายการสิ่งที่คุณปิดเสียงไว้ มันรับเส้นทางของไบนารีได้อย่างยินดีพอ ๆ กับชื่อของมัน ดังนั้น `omarchy crash mute /usr/bin/hyprland` จะทำสิ่งเดียวกัน ใส่เครื่องหมายคำพูดรอบชื่อที่มีช่องว่าง เช่นใน `omarchy crash mute 'Some App'` ทุกอย่างอื่นยังคงแจ้งเตือน และโปรแกรมที่ปิดเสียงไว้ยังคงขัดข้อง — นี่ซ่อนการเตือน มันไม่ได้แก้ไขอะไรเลย

### แอปเดสก์ท็อป

เมนู _Install > AI_ ยังมีแอป AI แบบกราฟิกอยู่สองสามแอปด้วย: Amp Desktop, Antigravity Desktop, แอปเดสก์ท็อป ChatGPT, แอปเดสก์ท็อป Claude (เบต้า Linux ของ Anthropic ที่มีแท็บ Chat, Cowork และ Claude Code), Grok Bot สำหรับแชทกับโมเดลของ xAI, Herdr Desktop, Hermes Desktop, OpenClaw, แอปเดสก์ท็อป Perplexity และ T3 Code Grok Bot คือแอปแชทบนเดสก์ท็อป เอเจนต์เขียนโค้ดคือคำสั่ง `grok`

Hermes Desktop เป็นตัวที่ต้องรู้ เพราะเครื่องหนึ่งมี Hermes เดียว และมันเป็นของแอป: Hermes จะติดตั้งผ่านแอปเท่านั้นเสมอ และคำสั่ง `hermes` ที่เอเจนต์เริ่มต้นรันก็เป็นของแอป การเลือก Hermes เป็นเอเจนต์เริ่มต้นจะติดตั้งสิ่งเดียวกับที่รายการ _Install > AI_ ติดตั้ง: แพ็กเกจ และรันไทม์ Hermes ใต้ `~/.hermes` ที่ตั้งค่าโดยโปรแกรมติดตั้งของ Hermes เอง ซึ่งใช้เวลาสองสามนาทีในครั้งแรก รันไทม์นั้นคือ Hermes ตัวเดียวที่คำสั่ง `hermes` ในเทอร์มินัล เอเจนต์เริ่มต้น และแอปทั้งหมดใช้ และมันอัปเดตตัวเองด้วย `hermes update` แทนที่จะรอการออก Omarchy การติดตั้งมันยังมอบธีม Omarchy ให้ Hermes เป็นสกินชื่อ `omarchy` ซึ่งทุกพื้นผิวของ Hermes จะทำตามขณะที่คุณเปลี่ยนธีม; เลือกอีกตัวใต้การตั้งค่า Appearance ของ Hermes หรือด้วย `/skin` หากคุณไม่อยากให้มันทำเช่นนั้น และ Omarchy จะปล่อยตัวเลือกนั้นไว้ตามเดิม การลบแอปใต้ _Remove > AI_ จะปิด Hermes ก่อน รวมถึง gateway ด้วย นำรันไทม์นั้นไปกับมัน และเก็บแชท ความทรงจำ และสกิลที่ Hermes เขียนให้ตัวเองของคุณไว้ เว้นแต่คุณจะบอกเป็นอย่างอื่น: มันจะถาม โดยค่าเริ่มต้นคือไม่ ว่าข้อมูลนั้นและการตั้งค่าการเชื่อมต่อของคุณควรไปด้วยหรือไม่

ประสบการณ์เดสก์ท็อปของ OpenClaw คือ Control UI ของมัน ซึ่งเปิดเป็นเว็บแอปที่หนุนโดย gateway ในเครื่องของตัวเอง OpenClaw อยู่ใน `~/.openclaw` และอัปเดตตัวเอง: ใช้ปุ่ม "Update Gateway" ของ Control UI หรือรัน `openclaw update` และ gateway จะรีสตาร์ทบนรุ่นใหม่ Omarchy เพียงเลือกว่ารุ่นใดที่การติดตั้งใหม่จะเริ่มด้วย OpenClaw ยังสามารถเป็นเอเจนต์เริ่มต้นของคุณได้ด้วย: การเลือกมันใต้ _Agent > Harness_ จะตั้งค่าสำเนาเดียวกันนั้นใน `~/.openclaw` และเอเจนต์จะเปิด UI เทอร์มินัลของ OpenClaw ที่เชื่อมต่อกับ gateway ของมัน การลบ OpenClaw ใต้ _Remove > AI_ จะนำบริการ gateway และแอปไปกับมัน จากนั้นถามว่า `~/.openclaw` ควรไปด้วยหรือไม่ เนื่องจากที่นั่นเก็บแชทและข้อมูลประจำตัวของคุณควบคู่ไปกับ OpenClaw เองและรันไทม์ปลั๊กอินที่มันดาวน์โหลด; ค่าเริ่มต้นจะเก็บมันไว้ และการติดตั้ง OpenClaw อีกครั้งจะหยิบมันกลับขึ้นมา

Herdr Desktop คือแอปเดสก์ท็อป [Herdr](https://herdr.dev): spaces, tabs และ panes ของเทอร์มินัลและเอเจนต์เขียนโค้ดที่ยังคงทำงานอยู่ในแกนหลักของมันเมื่อคุณปิดหน้าต่าง มันมาจากโปรแกรมติดตั้งของ Herdr เองแทนที่จะเป็นแพ็กเกจ ดังนั้นมันอยู่ใน `~/.local/share/herdr-app`, นำแกนหลักของมันมาใน `~/.local/bin/herdr-core` เมื่อคุณยังไม่มี และอัปเดตทั้งตัวมันเอง มันอยู่เคียงข้างคำสั่ง `herdr` ที่ Omarchy มีให้บน `Super + Ctrl + Return` แทนที่จะแทนที่มัน และได้คีย์โดยตรงของคำสั่งนั้น: `Alt + Return` และ `Alt + Shift + Return` แยก pane ลงหรือขวา, `Alt + Escape` ปิดมัน, `Ctrl + Alt + Arrow` ย้ายระหว่าง panes, `Alt + 1..9` และ `Alt + Left/Right` เลือก tab และ `Alt + Up/Down` ย้ายระหว่าง spaces `Ctrl + 1..9` เลือก space และ `Alt + Shift + Up/Down` ก้าวผ่านเอเจนต์ คีย์นำหน้า `Ctrl + Space` ยังคงเป็นเฉพาะเทอร์มินัลเท่านั้น เนื่องจากแอปไม่สามารถถือคีย์ Ctrl ธรรมดาไว้สำหรับลำดับได้ Omarchy เขียนสิ่งเหล่านี้ไปยัง `~/.config/herdr-app/keys.json` และ `omarchy-refresh-herdr-app` จะนำพวกมันกลับมา การติดตั้งมันจะเลือกธีม Omarchy ของ Herdr ซึ่งจะทำตามธีม Omarchy ของคุณตั้งแต่นั้นเป็นต้นมา Herdr เก็บธีมหนึ่งสำหรับโหมดสว่างและอีกหนึ่งสำหรับโหมดมืด ดังนั้นหลังจากสลับระหว่างธีม Omarchy แบบมืดและแบบสว่าง ให้เลือก Omarchy ในตัวเลือกธีมของ Herdr อีกครั้งสำหรับโหมดอื่น

T3 Code ทำงานจากรุ่น AppImage ทางการของมันใน `~/.local/share/t3code` แทนที่จะมาจากแพ็กเกจ ดังนั้นมันจึงอัปเดตตัวเอง การติดตั้งมันจะถามว่าจะเริ่มบนช่อง Stable หรือ Nightly; สลับภายหลังในการตั้งค่าของ T3 Code เธรดและการตั้งค่าของคุณอยู่ใน `~/.t3` และการลบ T3 Code ใต้ _Remove > AI_ จะนำพวกมันไปกับมัน

### โมเดลในเครื่อง

รันโมเดลแบบเปิดบนเครื่องของคุณเองสำหรับเอเจนต์เขียนโค้ดของคุณ พรอมต์และโค้ดของคุณอยู่บนเครื่อง; ไม่มีอะไรที่ส่งให้โมเดลออกจากเครื่อง เริ่มต้นด้วย:

```bash
omarchy models use best text
```

นั่นตั้งค่าโมเดลข้อความที่ดีที่สุดสำหรับเครื่องนี้ ชนิดที่เอเจนต์ของคุณใช้ โมเดลภาพ วิดีโอ และเพลงมีตัวที่ดีที่สุดของตัวเอง: `omarchy models use best image`, `video` หรือ `music` รัน `omarchy models use best` เพื่อดูตัวเลือกของแต่ละชนิดสำหรับเครื่องนี้

หรือเปิดแผงโมเดลในเครื่องจากไอคอนประกายของมันในแถบด้านบน ถัดจากไอคอนเอเจนต์ หรือด้วย Super + Ctrl + Alt + X และเลือก + ไอคอนจะปรากฏขึ้นเมื่อมีโมเดลที่พอดีกับเครื่องนี้ Podman ซึ่งรันโมเดลต่าง ๆ มาพร้อมกับ Omarchy เช่นเดียวกับชุดเครื่องมือคอนเทนเนอร์ของ NVIDIA บนเครื่อง NVIDIA ซึ่งให้ GPU แก่พวกมัน; หากอย่างใดอย่างหนึ่งขาดหายไป การตั้งค่าครั้งแรกจะติดตั้งมัน จากนั้น Omarchy จะเลือกโมเดลที่แนะนำสำหรับเครื่องนี้ ดาวน์โหลดมัน และเริ่มมัน คาดหวังการดาวน์โหลดขนาดหลายสิบ GB และหน่วยความจำส่วนใหญ่ของเครื่องจะถูกใช้งานขณะที่โมเดลทำงาน: Flash Next ใช้ประมาณ 100 GiB กับบริบทเต็ม 256K ของมัน หากโมเดลอื่นถือครองหน่วยความจำที่มันต้องการ มันจะถูกตั้งค่าในสถานะหยุด พร้อมเริ่มเมื่อคุณหยุดตัวหนึ่ง โมเดลจะหยุดเมื่อออกจากระบบ; หยุดมันเองเมื่อคุณต้องการหน่วยความจำสำหรับอย่างอื่น

`omarchy models list` แสดงตัวเลือกและอธิบายว่าทำไมบางตัวถึงไม่พอดี หากต้องการตั้งค่าอีกตัว ให้รัน `omarchy models use <recipe>` วันนี้ `qwen3.8-flash-next-gufo` และ `qwen3.8-27b-gufo` พร้อมใช้งานสำหรับเครื่อง Strix Halo ขนาด 128 GB; ตัว 27B ใช้ประมาณ 40 GiB ดังนั้นมันจึงเหลือพื้นที่สำหรับงานอื่น บนแล็ปท็อป 64 GB ที่มี Arc B390 ของ Intel, `qwen3.6-35b-a3b-llamacpp` ทำงานในประมาณ 30 GiB สูตรและคำแนะนำใหม่มาพร้อมกับ `omarchy update` ผ่านแพ็กเกจ

โมเดลทุกตัวที่คุณตั้งค่าจะได้บรรทัดของตัวเองในแผงโมเดลในเครื่อง: เล่นเพื่อเริ่มมัน หยุดชั่วคราวเพื่อหยุดมันและคืนหน่วยความจำของมัน และปุ่มเทอร์มินัลเพื่อเปิดเอเจนต์ของคุณบนมัน ข้ามด้านบน แถบแสดงว่าหน่วยความจำของเครื่องถูกแบ่งระหว่าง Omarchy เอง (ระบบและแอปของคุณ) โมเดลที่กำลังทำงานแต่ละตัว และสิ่งที่ว่างอย่างไร ชี้ไปที่โมเดลที่หยุดอยู่และแถบจะแสดงว่ามันพอดีหรือไม่ หรือขาดอีกเท่าใด หลายตัวสามารถทำงานพร้อมกันได้เมื่อพวกมันพอดีในหน่วยความจำด้วยกัน; หากตัวหนึ่งไม่พอดี Omarchy จะบอกว่าให้หยุดโมเดลที่กำลังทำงานตัวใด ลากบรรทัดโดยโลโก้ของพวกมันเพื่อจัดเรียงใหม่ และกด Delete บนบรรทัดที่เลือกเพื่อลบโมเดลและการดาวน์โหลดของมัน

โมเดลเขียนโค้ดทุกตัวที่คุณตั้งค่ายังได้รายการของตัวเองในตัวเรียกใช้แอป ใต้ชื่อของโมเดลและพร้อมโลโก้ของผู้สร้างมัน ในแบบเดียวกับการลงชื่อเข้าใช้ Claude, Codex หรือ Grok จะเพิ่มรายการหนึ่ง มันเปิดเอเจนต์ของคุณบนโมเดลนั้น และเริ่มโมเดลก่อนหากมันไม่ได้ทำงานอยู่: เทอร์มินัลจะแสดงมันกำลังโหลดและส่งต่อให้เอเจนต์เมื่อมันพร้อม การลบโมเดลจะลบรายการของมัน

ไม่ใช่ทุกโมเดลสำหรับเขียนโค้ด โมเดลภาพ วิดีโอ และเพลงจะเปิดใน Fantasi แทน แอปของ Omarchy สำหรับสร้างภาพ วิดีโอ และเพลงด้วยโมเดลที่ทำงานบนเครื่องนี้ ซึ่งเลือกที่นั่นหรือจากบรรทัดของพวกมันในแผงโมเดลในเครื่อง

โมเดลยังคงทำงานตรงตามที่มันถูกตั้งค่าไว้ ดังนั้นการอัปเดต Omarchy จะไม่มีวันรีสตาร์ทตัวหนึ่งใต้เอเจนต์ของคุณ เมื่อ Omarchy มีรันไทม์ที่ใหม่กว่าหรือน้ำหนักที่ใหม่กว่าสำหรับโมเดลที่คุณตั้งค่าไว้ บรรทัดของมันจะแสดงปุ่มอัปเดต: กดมันและโมเดลจะถูกตั้งค่าใหม่ในเบื้องหลัง โดยดาวน์โหลดเฉพาะสิ่งที่เปลี่ยนแปลง และรีสตาร์ทบนรุ่นใหม่ โมเดลที่หยุดอยู่จะยังคงหยุดอยู่ `omarchy models update` ทำแบบเดียวกันสำหรับทุกโมเดลจากเทอร์มินัล

จากบรรทัดคำสั่ง `omarchy models start <recipe>` และ `omarchy models stop <recipe>` ทำแบบเดียวกัน `omarchy models status` แสดงทุกโมเดล และ `omarchy agent --local` เปิดเอเจนต์เริ่มต้นของคุณบนโมเดลล่าสุดที่คุณเริ่ม pi, OpenCode และ Qwen Code สามารถใช้ตัวหนึ่งได้; กับค่าเริ่มต้นอื่นใดมันจะเปิดใน pi หรือใน OpenCode หากคุณไม่มี pi pi ยังแสดงรายการทุกโมเดลที่คุณตั้งค่าไว้ และโมเดลบนเครื่องที่คุณจับคู่ด้วย ในตัวเลือกโมเดลของตัวเอง ดังนั้น `pi` ธรรมดาก็เข้าถึงพวกมันได้เช่นกัน ไคลเอนต์ที่เข้ากันได้กับ OpenAI ตัวใดก็สามารถเชื่อมต่อได้เช่นกัน: `status` แสดงที่อยู่ของแต่ละโมเดล (ตัวแรกคือ `http://127.0.0.1:11435/v1`) ชื่อสูตรคือโมเดล และคีย์อยู่ใน `~/.config/omarchy/agent-local/key`

`omarchy models remove <recipe>` ลบโมเดลและการดาวน์โหลดที่ไม่มีโมเดลอื่นใช้

รันไทม์ของบุคคลที่สามจะถูกติดป้ายด้วยผู้เผยแพร่ของพวกมัน Omarchy รันทุกโมเดลโดยไม่มีการเข้าถึงเครือข่าย

### LLM ในเครื่อง

Omarchy แนะนำสองวิธีในการรันโมเดล LLM ในเครื่อง: LM Studio และ Ollama LM Studio มีอินเทอร์เฟซ GUI สำหรับค้นหาโมเดล open-weight ติดตั้งพวกมัน และรันพวกมัน มันเป็นวิธีที่ยอดเยี่ยมในการเริ่มต้นอย่างง่ายดาย Ollama มี CLI สำหรับทำแบบเดียวกันในลักษณะคล้ายกัน แต่หากคุณเพิ่งเริ่มใช้โมเดลในเครื่อง ผมจะเริ่มด้วย LM Studio คุณสามารถติดตั้งตัวใดตัวหนึ่งได้ใต้ _Install > AI_ ใน Omarchy Menu

### สกิลของ Omarchy

สกิลเอเจนต์ช่วยให้ AI ใช้เครื่องมือเฉพาะในวิธีเฉพาะ และ Omarchy มีพวกมันเจ็ดสกิล สกิล omarchy ครอบคลุมการปรับแต่งระบบ เช่นการปรับแต่งการกำหนดค่า Hyprland ของคุณหรือการปรับแถบ omarchy-make-theme, omarchy-make-plugin, omarchy-make-app และ omarchy-make-game ครอบคลุมการสร้างสิ่งใหม่ omarchy-contribute ครอบคลุมการรายงานบั๊กหรือส่งการแก้ไขไปยังต้นทาง และ omarchy-diagnose-crash ทำงานผ่าน core dump ของการขัดข้อง พวกมันถูกเชื่อมโยงด้วย symlink เข้าไปในไดเรกทอรีสกิลสำหรับ Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` และแต่ละ `~/.hermes/profiles/*/skills`) และตำแหน่งทั่วไป `~/.agents/skills` ดังนั้น harness ส่วนใหญ่จะหยิบพวกมันขึ้นมาโดยอัตโนมัติ โฟลเดอร์สกิลของคุณเองที่มีชื่อเดียวกันจะมีความสำคัญเหนือกว่า

แต่คุณควรปฏิบัติต่อสกิลเหล่านี้เหมือนเป็นของทดลอง โมเดลต่าง ๆ จะใช้มันให้เกิดผลต่างกัน ควรเริ่มรันในโหมดวางแผนก่อน เพื่อให้คุณมีไอเดียว่าเอเจนต์อยากเปลี่ยนอะไร จากนั้นเตรียมพร้อมที่จะย้อนกลับการเปลี่ยนแปลงหรือแม้แต่เรียกใช้ `omarchy reinstall configs` หากเอเจนต์ทำทุกอย่างพังเละเทะ
