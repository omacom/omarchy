### การติดตั้งและอัปเดต agent

ยกเว้น Hermes, agent เหล่านี้ใช้การติดตั้งแบบ lazy ของ mise: การเปิดใช้ครั้งแรกจะติดตั้ง CLI และการเปิดใช้ครั้งต่อๆ ไปจะใช้ตัวที่ติดตั้งไว้ mise ยังตรวจสอบ agent ที่ติดตั้งแล้วว่ามีรุ่นใหม่หรือไม่ อย่างมากที่สุดทุกสี่ชั่วโมง ก่อนที่มันจะเริ่มทำงาน หรือในพื้นหลังที่ shell prompt หากการอัปเดตนั้นล้มเหลวหรือคุณออฟไลน์ ตัวที่ติดตั้งไว้จะทำงาน `omarchy update` จะอัปเดต agent ที่ติดตั้งแล้วพร้อมกับส่วนที่เหลือของ Omarchy และ `mup` จะอัปเดตเฉพาะเครื่องมือที่ mise จัดการเท่านั้น

ตัวอัปเดตของ agent เอง เช่น `claude update`, `codex update` หรือปุ่มอัปเดตในแอป จะไม่อัปเดตตัวที่ติดตั้งโดย mise `codex update` จะล้มเหลว และ `claude update` อาจรายงานว่าสำเร็จในขณะที่ติดตั้งสำเนาแยกต่างหากที่ mise ไม่ได้ติดตาม หากคุณอยากใช้ตัวติดตั้งและตัวอัปเดตแบบ native ของ agent มากกว่า ให้เพิ่มมันลงใน `disable_tools`; ดู [Preinstalled CLI tools](18-development-tools.md#preinstalled-cli-tools)

เพื่อติดตั้งเครื่องมือ lazy ที่กำหนดค่าไว้ทั้งหมดก่อนที่คุณจะต้องการใช้ ให้รัน `mise install --include-lazy` ซึ่งรวมถึงเครื่องมือ CLI เริ่มต้นอื่นๆ ของ Omarchy ด้วย นอกเหนือจาก agent ต่างๆ ดู [Preinstalled CLI tools](18-development-tools.md#preinstalled-cli-tools) สำหรับการติดตั้งเครื่องมือตัวเดียวหรือใช้การติดตั้งของคุณเอง

`grok` ติดตั้งผ่าน package `grok` แบบ first-party ของ mise ในแบบเดียวกับ `claude` และ `codex` รัน `grok` หรือเลือกมันใต้ _Setup > Defaults > Agent_ ข้ามตัวติดตั้งแบบ `curl | bash` บน x.ai ไปเลย เส้นทางนั้นจะวางสำเนาที่สองไว้ใน `~/.grok/bin`, แทรกมันไว้ข้างหน้าใน `PATH` และเขียนทับ wrapper ของ Omarchy

`dsh` เปิด browser UI ของมันที่ `127.0.0.1:3080` โดยใช้ไดเรกทอรีที่เปิดใช้เป็น workspace เริ่มต้น browser UI ของมันไม่รับ prompt เริ่มต้น ดังนั้น `omarchy agent prompt` จะเปิดมันพร้อมกับ prompt บนคลิปบอร์ดของคุณให้วาง Omarchy เริ่มมันด้วย permission preset แบบ no-approval ของ DeepSeek DeepSeek Harness จะอัปโหลด session log ไปยัง DeepSeek เมื่อคุณใช้ model API อย่างเป็นทางการของมัน; ปิดสิ่งนั้นได้ใต้ _Settings > General > Upload Session Log_ ใน browser UI ของมัน Feedback ที่คุณส่งให้มันจะถูกอัปโหลดไปพร้อมกับ session ด้วย เว้นแต่คุณจะเริ่มมันด้วย `DSH_TELEMETRY_MODE=DISABLED`

### Agent เริ่มต้น

เลือก agent เริ่มต้นของคุณด้วย `omarchy default agent <name>` หรือใต้ _Setup > Defaults > Agent_ ใน Omarchy Menu (`Super + Space`) หาก agent ยังไม่ได้ติดตั้ง การเลือกมันจะติดตั้งมันก่อน Omarchy ที่ติดตั้งใหม่จะเชิญให้คุณตัดสินใจเลือกนี้ด้วยการแจ้งเตือนครั้งเดียว

การเลือก Claude ยังพยายามตั้งค่า browser extension ของมันสำหรับ Chromium, Chrome, Brave, Brave Origin และ Edge ด้วย การตั้งค่า extension ใช้กับผู้ใช้ทุกคนและอาจขอรหัสผ่านระบบของคุณ; การยกเลิกหรือการติดตั้ง extension ที่ล้มเหลวก็ยังคงเลือกและเปิด Claude อยู่ดี รีสตาร์ทเบราว์เซอร์ของคุณ เปิดใช้งาน extension หากระบบถาม และลงชื่อเข้าใช้ Claude เพื่อเชื่อมต่อให้เสร็จ รัน `/chrome` ใน Claude เพื่อตรวจสอบการเชื่อมต่อ Firefox และ Zen ไม่รองรับ extension นี้ หาก Claude เป็นตัวเริ่มต้นของคุณอยู่แล้วก่อนที่จะมีการเพิ่มการตั้งค่านี้ ให้เลือกมันอีกครั้งเพื่อติดตั้ง extension

เมื่อคุณเลือกแล้ว `Super + Shift + Ctrl + A` จะเปิด agent เริ่มต้นในหน้าต่าง terminal เฉพาะ (หรือเปิดตัวเลือกขึ้นมาหากคุณยังไม่ได้เลือก) คุณยังเปิดมันตรงเข้าสู่งานได้ด้วย `omarchy agent prompt "Review this project"` Freebuff และ DeepSeek Harness ไม่รับ prompt เริ่มต้น ดังนั้นพวกมันจะเปิดพร้อมกับ prompt บนคลิปบอร์ดของคุณให้วางแทน Agent ที่เปิดด้วยวิธีนี้จะทำงานโดยไม่มีผู้ดูแลในโหมด don't-stop-to-ask ของแต่ละตัว ดังนั้นเตรียมตัวให้พร้อมเพราะพวกมันจะลงมือทำจริงๆ! MiniMax Code ไม่มีโหมดดังกล่าวสำหรับ session แบบ interactive ของมัน ดังนั้นมันจะขอ permissions ตามปกติ และเนื่องจาก agent ปฏิเสธที่จะจำ trust สำหรับ home directory ของคุณ การเปิดใช้จาก `$HOME` จะเริ่มใน `~/Work` แทน

มีทางลัดใน terminal ด้วย: `a` รัน agent เริ่มต้นแบบ inline ใน terminal ปัจจุบัน ขณะที่ `c`, `cx` และ `cy` เริ่ม OpenCode, Claude Code และ Codex โดยตรง (อีกครั้ง ในโหมดอนุมัติอัตโนมัติของพวกมัน) การเปลี่ยนธีมยังซิงค์ไปยัง agent ต่างๆ ด้วย: Claude Code, Pi, OpenCode และ Hermes (เมื่อ Omarchy ติดตั้งมันแล้ว) จะเปลี่ยนตามทั้งหมดเมื่อคุณสลับธีมของ Omarchy

### แผง agent

แถบบนมีไอคอน agent ก่อนที่คุณจะตั้งค่า agent แผงของมันจะพาคุณลงชื่อเข้าใช้ Claude, Codex หรือ Grok และตัวแรกจะกลายเป็น agent เริ่มต้นของคุณ หลังจากนั้น แผงจะรวมทุกการสมัครสมาชิกไว้ในหน้าเดียว: agent และบัญชีแต่ละรายการพร้อมแผนของมัน มาตรวัดสำหรับ limit ของ session 5 ชั่วโมงและ limit รายสัปดาห์ของแต่ละตัวพร้อมเวลาจนกว่าจะรีเซ็ต (ชี้เมาส์ค้างเพื่อดูเปอร์เซ็นต์ที่แน่นอน) หรือยอดเงินแบบ prepaid ที่เหลืออยู่ ใต้บรรทัดที่หมุนเวียนสิ่งที่คุณใช้ไปในทุกตัว เช่น tokens ในสัปดาห์นี้และโมเดลที่คุณใช้มากที่สุด ใต้ _Make something_ มันมี prompt เริ่มต้นสำหรับธีมใหม่ plugin ใหม่ หรือแอปใหม่ที่มอบงานให้ agent เริ่มต้นของคุณ แอปต่างๆ ถูกสร้างในแบบเดียวกับ Hype, Monologue และ Omacut ของ Omarchy เอง ใน C++ และ Qt Quick โดยทำตาม agent skill ชื่อ omarchy-app และ compiler และชิ้นส่วน Qt ที่พวกมันต้องการก็ติดตั้งมาให้แล้ว Claude Code, Codex, Grok, Kimi, Cursor และโควตา Grok Bot ของมัน, GitHub Copilot, Muse, Antigravity, Kimchi และ Devin ครอบคลุมมาให้ตั้งแต่แรกพร้อม limit ของพวกมัน และ Hermes, Mistral Vibe และ Qwen Code จะแสดง session และ tokens ของพวกมันเมื่อคุณได้ใช้พวกมันแล้ว แผนและ key ของผู้ให้บริการที่คุณใช้ผ่าน pi, omp หรือ opencode ก็จะปรากฏเช่นกัน: OpenCode Zen และ Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan และ Synthetic พร้อม limit ของพวกมัน; Fireworks, OpenRouter และ DeepSeek พร้อมยอดเงินแบบ prepaid ของพวกมัน; และโมเดลที่คุณรันบนฮาร์ดแวร์ของคุณเองใต้ Local models ทุก agent จะถูกนับเพียงครั้งเดียว ภายใต้ผู้ที่เรียกเก็บเงินจากมัน ไม่ว่าคุณจะขับมันผ่าน harness กี่ตัวก็ตาม

คลิกซ้ายที่ไอคอนบนแถบเพื่อเปิดแผง คลิกขวาเพื่อเปิด agent เริ่มต้นของคุณ บันทึกการใช้งานที่อยู่เบื้องหลังมันจะถูกสร้างใหม่ทุก 15 นาทีโดย `omarchy agent usage-update` และแผงยังสามารถรวมการใช้งานจากเครื่องอื่นๆ ของคุณผ่านโฟลเดอร์ที่ซิงค์ได้ ดู README ใต้ `$OMARCHY_PATH/shell/plugins/agents/` สำหรับการตั้งค่าทั้งหมด

### หลายการสมัครสมาชิก

หากคุณจ่ายสำหรับแผน Claude, Codex หรือ Grok มากกว่าหนึ่งแผน — เช่น Max ส่วนตัวและแผนสำหรับงาน — Omarchy สามารถให้พวกมันลงชื่อเข้าใช้อยู่ทั้งหมดและย้ายไปมาระหว่างพวกมันได้ เพิ่มการสมัครสมาชิกด้วย + ในแผง agent ซึ่งจะพาคุณทำขั้นตอนนั้นตรงนั้นเลย หรือด้วย `omarchy agent account add claude Work` (หรือ `codex` หรือ `grok`) มันจะติดตั้ง CLI หากยังไม่มี บัญชีแรกสำหรับผู้ให้บริการรายหนึ่งจะลงชื่อเข้าใช้ผ่านเบราว์เซอร์ปกติของคุณ ตรงที่ที่ CLI มองหาเสมอ ทุกบัญชีหลังจากนั้นจะลงชื่อเข้าใช้ผ่านหน้าต่างส่วนตัว ดังนั้นบัญชีที่เบราว์เซอร์ของคุณลงชื่อเข้าใช้อยู่แล้วจะไม่ถูกหยิบมาโดยไม่ได้ตั้งใจ; ลงชื่อเข้าใช้ที่นั่นในฐานะบัญชีที่คุณกำลังเพิ่ม และปิดหน้าต่างส่วนตัวใดๆ ที่คุณเปิดอยู่ก่อน อย่าออกจากระบบของ CLI เพื่อทำสิ่งนี้เด็ดขาด: การออกจากระบบจะเพิกถอนการลงชื่อเข้าใช้ที่บันทึกไว้ และบัญชีนั้นจะต้องถูกเพิ่มใหม่อีกครั้ง

เพื่อคัดลอกการเข้าสู่ระบบการสมัครสมาชิกของคุณไปยังเครื่อง Omarchy อีกเครื่องผ่าน SSH ให้รัน `omarchy agent account copy user@laptop` ผู้ส่งจะจัดเตรียมตัวรับชั่วคราวเมื่อปลายทางยังไม่ได้ติดตั้งไว้ ดังนั้นเครื่อง Omarchy รุ่นเก่ากว่าสามารถรับบัญชีได้โดยไม่ต้องอัปเดต ตัวรับที่ติดตั้งไว้จะมีลำดับความสำคัญกว่า การคัดลอกนี้จะคัดลอกการสมัครสมาชิก Claude, Codex และ Grok ทั้งหมด; เพิ่มชื่อผู้ให้บริการเพื่อเลือกพวกมัน เช่นใน `omarchy agent account copy laptop claude` ชื่อบัญชีและ command ID จะตรงกับต้นทาง รวมถึงบัญชีที่มีอยู่แล้วบนปลายทาง บัญชีปลายทางที่ไม่เกี่ยวข้องจะได้รับ suffix เป็นตัวเลขหากชื่อของพวกมันขัดกัน และ settings, skills, plugins และประวัติการสนทนาจะยังคงอยู่เฉพาะเครื่องของแต่ละเครื่อง

Credentials ปลายทางที่มีอยู่จะถูกเก็บไว้ บัญชีต้นทางที่ลงชื่อเข้าใช้อยู่ที่นั่นแล้วจะมีชื่อซิงค์ให้ตรงโดยไม่แทนที่ credentials ของมัน; บัญชีอื่นๆ จะถูกเพิ่มเข้าไปข้างๆ เพื่อแทนที่ credentials ที่บันทึกไว้สำหรับบัญชีที่ตรงกัน ให้ใช้ `omarchy agent account copy --replace laptop claude` หลังจากออกจาก session ของบัญชีนั้นบนปลายทางแล้ว ปลายทางที่ใหม่สดยังจะได้รับบัญชีที่ใช้งานอยู่และการตั้งค่าการสลับของต้นทางด้วย; ปลายทางที่ตั้งค่าไว้แล้วจะเก็บของตัวเองไว้

Credentials เดินทางผ่าน SSH และถูกเก็บในไฟล์ส่วนตัวบนปลายทาง ดังนั้นให้คัดลอกไปยังเครื่องที่คุณไว้วางใจเท่านั้น นี่เป็นการคัดลอกครั้งเดียว ไม่ใช่การซิงโครไนซ์ต่อเนื่อง Codex refresh tokens สามารถถูกหมุนโดยเครื่องอื่นได้ ทำให้การเข้าสู่ระบบที่คัดลอกมาต้องต่ออายุ; การลงชื่อเข้าใช้แยกกันยังคงเป็นตัวเลือกที่เชื่อถือได้ที่สุดสำหรับการใช้งานพร้อมกันบนหลายเครื่อง ดู [คำแนะนำการยืนยันตัวตนบัญชีของ Codex](https://developers.openai.com/codex/auth/ci-cd-auth)

บัญชีหนึ่งบัญชีต่อผู้ให้บริการหนึ่งรายจะใช้งานอยู่ และทุก session ใหม่จะเริ่มเป็นบัญชีนั้น: `cx`, `cy`, `claude`, `codex` หรือ `grok` ธรรมดา, อะไรก็ตามที่เปิดผ่าน `omarchy agent` และ scripts หรือ editors ที่พบ CLI บน `PATH` สลับด้วย `omarchy agent account use work` (และสลับกลับด้วย `omarchy agent account use main`) หรือในแผงโดยกดหมายเลขของบัญชีแล้วกด `Enter` (หรือคลิกปุ่ม Use ของมัน) Session ที่กำลังทำงานอยู่แล้วจะยังคงอยู่บนบัญชีที่พวกมันเริ่มด้วย ประวัติการสนทนา, settings, skills และ plugins ถูกแชร์ข้ามบัญชี ดังนั้น `claude --continue` ในโฟลเดอร์เดียวกันจะไปต่อจากจุดที่คุณค้างไว้บนบัญชีใหม่

เมื่อมีมากกว่าหนึ่งบัญชี แผงจะแสดง limit ของแต่ละบัญชีเคียงข้างกัน โดยบัญชีที่ใช้งานอยู่จะถูกทำเครื่องหมายไว้ โดยค่าเริ่มต้น Omarchy จะแจ้งเตือนคุณเมื่อบัญชีที่ใช้งานอยู่ผ่าน 95% ของ limit และคลิกการแจ้งเตือนจะสลับไปยังบัญชีที่มี headroom มากที่สุด ชี้เมาส์ค้างเหนือบรรทัดของบัญชีในแผงและคลิก Autoswitch ที่ปรากฏข้าง Use (หรือกด `m`) หรือรัน `omarchy agent account mode auto` เพื่อให้มันสลับเองแทน; ขณะที่มันเปิดอยู่ Autoswitch จะแทนที่ Use และการคลิกมันอีกครั้งจะกลับไปเป็นการแจ้งเตือน เพิ่มตัวเลขเพื่อเปลี่ยน threshold เช่นใน `omarchy agent account mode auto 90` หากทุกบัญชีเกิน threshold คุณจะได้ยินเรื่องนี้ครั้งเดียว พร้อมกับว่าบัญชีใดจะว่างขึ้นก่อน ในขณะที่บัญชีที่ใช้งานอยู่ห่างจาก threshold ของมันภายใน 15 จุด (80% ที่ค่าเริ่มต้น) limit ของมันจะถูกตรวจสอบทุกสามนาทีแทนที่จะเป็นทุก 15 นาที

`omarchy agent account list` แสดงทุกบัญชีและ limit ล่าสุดของมัน `omarchy agent account remove work` ลบบัญชีหนึ่งบัญชี และ `omarchy agent account rename primary Hey` เปลี่ยนชื่อบัญชีหนึ่งบัญชี (หรือคลิกชื่อบัญชีในแผง) คำสั่งเหล่านี้ทำงานบนบัญชีของ agent เริ่มต้นของคุณ; เพื่อเข้าถึงผู้ให้บริการรายอื่น ให้ระบุชื่อมันก่อน เช่นใน `omarchy agent account use codex side` การเข้าสู่ระบบที่คุณมีอยู่แล้วใน `~/.claude` หรือ `~/.codex` คือบัญชี _Main_ และจะยังคงอยู่ตรงที่มันอยู่ บัญชีที่ไม่ได้ใช้มานานกว่าประมาณแปดชั่วโมงอาจแสดง _Sign-in required_; คลิกมันเพื่อลงชื่อเข้าใช้บัญชีนั้นอีกครั้งตรงในแผง หรือเริ่ม session ในบัญชีนั้น ซึ่งจะรีเฟรชการลงชื่อเข้าใช้ด้วยตัวมันเอง MCP servers ที่คุณมีเมื่อบัญชีถูกเพิ่มจะตามไปยังบัญชีนั้นด้วย แต่ตัวที่คุณเพิ่มภายหลังด้วย `claude mcp add` จะไปถึงเฉพาะบัญชีที่คุณเพิ่มพวกมันในนั้นเท่านั้น Claude Desktop และเครื่องมือที่กำหนดค่าด้วย absolute path ไปยัง binary ของ CLI จะไม่ตามการสลับไปด้วย `CLAUDE_CONFIG_DIR`, `CODEX_HOME` หรือ `GROK_HOME` ที่ระบุชัดเจนจะมีลำดับความสำคัญเหนือบัญชีที่เลือกไว้

### การวินิจฉัยการแครช

Omarchy เฝ้าดู systemd-coredump สำหรับการแครชของ process เมื่อมีอะไร segfault คุณจะได้รับการแจ้งเตือน "Process crashed" — คลิกมัน และการแครชจะถูกส่งให้ agent เริ่มต้นของคุณพร้อมกับ skill diagnose-crash ของ Omarchy ซึ่งจะพา agent ผ่านการหาข้อเท็จจริงจาก core dump และตัดสินใจว่าการแครชนั้นคุ้มค่าที่จะรายงานไปยัง upstream หรือไม่ คุณยังรันมันด้วยมือกับ PID ใดๆ จาก `coredumpctl list` ด้วย `omarchy agent crash <pid>` ได้ด้วย

การเฝ้าดูเปิดอยู่โดยค่าเริ่มต้น ปิดมันได้ใต้ _Trigger > Toggle > Crash Capture_ (หรือด้วย `omarchy toggle crash-capture`) และการแจ้งเตือนจะหยุด; `omarchy agent crash <pid>` ยังทำงานด้วยมือได้อยู่

การแครชยังสามารถปิดเสียงได้ทีละโปรแกรม ซึ่งเป็นสิ่งที่การวินิจฉัยเสนอให้คุณในตอนท้าย `omarchy crash mute hyprland` หยุดการแจ้งเตือนสำหรับโปรแกรมนั้นเท่านั้น `omarchy crash mute hyprland off` นำพวกมันกลับมา และ `omarchy crash mute` ด้วยตัวมันเองเพียงอย่างเดียวจะแสดงรายการสิ่งที่คุณปิดเสียงไว้ มันรับ path ของ binary ได้สบายเหมือนกับชื่อของมัน ดังนั้น `omarchy crash mute /usr/bin/hyprland` ทำสิ่งเดียวกัน ใส่เครื่องหมายคำพูดรอบชื่อที่มีช่องว่าง เช่นใน `omarchy crash mute 'Some App'` ทุกอย่างอื่นยังคงแจ้งเตือนอยู่ และโปรแกรมที่ปิดเสียงไว้ยังคงแครชอยู่ — สิ่งนี้ซ่อนการเตือน มันไม่ได้แก้ไขอะไรเลย

### แอปเดสก์ท็อป

เมนู _Install > AI_ ยังมีแอป AI แบบกราฟิกอยู่สองสามตัว: แอปเดสก์ท็อป ChatGPT, แอปเดสก์ท็อป Claude (เบต้าสำหรับ Linux ของ Anthropic พร้อมแท็บ Chat, Cowork และ Claude Code), Grok Bot สำหรับแชทกับโมเดลของ xAI, Herdr Desktop, Hermes Desktop, OpenClaw, แอปเดสก์ท็อป Perplexity และ T3 Code Grok Bot คือแอปแชทบนเดสก์ท็อป coding agent คือคำสั่ง `grok`

Hermes Desktop คือตัวที่ต้องรู้ไว้ เพราะเครื่องหนึ่งเครื่องมี Hermes เดียว และมันเป็นของแอป: Hermes จะติดตั้งผ่านแอปเท่านั้นเสมอ และคำสั่ง `hermes` ที่ agent เริ่มต้นรันคือของแอป การเลือก Hermes เป็น agent เริ่มต้นจะติดตั้งสิ่งเดียวกับที่รายการ _Install > AI_ ติดตั้ง: package นั้น และ runtime ของ Hermes ใต้ `~/.hermes` ที่ตั้งค่าโดยตัวติดตั้งของ Hermes เอง ซึ่งใช้เวลาสองสามนาทีในครั้งแรก runtime นั้นคือ Hermes ตัวเดียวที่คำสั่ง `hermes` ใน terminal, agent เริ่มต้น และแอปทั้งหมดใช้ และมันอัปเดตตัวเองด้วย `hermes update` แทนที่จะรอ Omarchy release การติดตั้งมันยังมอบธีมของ Omarchy ให้ Hermes เป็น skin ชื่อ `omarchy` ซึ่งทุกพื้นผิวของ Hermes จะทำตามเมื่อคุณสลับธีม; เลือกตัวอื่นใต้การตั้งค่า Appearance ของ Hermes หรือด้วย `/skin` หากคุณไม่อยากให้มันทำเช่นนั้น และ Omarchy จะปล่อยตัวเลือกนั้นไว้ตามเดิม การลบแอปใต้ _Remove > AI_ จะปิด Hermes ก่อน รวมถึง gateway, นำ runtime นั้นไปด้วย และเก็บแชท ความทรงจำ และ skills ที่ Hermes เขียนให้ตัวเองไว้ เว้นแต่คุณจะบอกเป็นอย่างอื่น: มันจะถาม โดยค่าเริ่มต้นคือไม่ ว่าข้อมูลนั้นและการตั้งค่าการเชื่อมต่อของคุณควรไปด้วยหรือไม่

ประสบการณ์เดสก์ท็อปของ OpenClaw คือ Control UI ของมัน ซึ่งเปิดเป็น web app ที่หนุนโดย gateway แบบโลคัลของมันเอง OpenClaw อาศัยอยู่ใน `~/.openclaw` และอัปเดตตัวเอง: ใช้ปุ่ม "Update Gateway" ของ Control UI หรือรัน `openclaw update` และ gateway จะรีสตาร์ทบนเวอร์ชันใหม่ Omarchy เลือกเฉพาะ release ที่การติดตั้งใหม่จะเริ่มจากเท่านั้น การลบ OpenClaw ใต้ _Remove > AI_ จะนำ gateway service และแอปไปด้วย จากนั้นจะถามว่า `~/.openclaw` ควรไปด้วยหรือไม่ เนื่องจากที่นั่นเก็บแชทและ credentials ของคุณไว้ควบคู่กับตัว OpenClaw เองและ plugin runtimes ที่มันดาวน์โหลด; ค่าเริ่มต้นคือเก็บมันไว้ และการติดตั้ง OpenClaw อีกครั้งจะหยิบมันกลับขึ้นมา

Herdr Desktop คือแอปเดสก์ท็อป [Herdr](https://herdr.dev): spaces, tabs และ panes ของ terminals และ coding agents ที่ยังคงทำงานใน core ของมันเมื่อคุณปิดหน้าต่าง มันมาจากตัวติดตั้งของ Herdr เองแทนที่จะเป็น package ดังนั้นมันอาศัยอยู่ใน `~/.local/share/herdr-app`, นำ core ของมันมาด้วยใน `~/.local/bin/herdr-core` เมื่อคุณยังไม่มี และอัปเดตทั้งตัวมันเอง มันอยู่เคียงข้างคำสั่ง `herdr` ที่ Omarchy มาพร้อมบน `Super + Ctrl + Return` แทนที่จะแทนที่มัน การติดตั้งมันจะเลือกธีม Omarchy ของ Herdr ซึ่งจะทำตามธีม Omarchy ของคุณตั้งแต่นั้นเป็นต้นไป Herdr เก็บธีมหนึ่งสำหรับโหมดสว่างและอีกธีมสำหรับโหมดมืด ดังนั้นหลังจากสลับระหว่างธีม Omarchy แบบมืดและแบบสว่าง ให้เลือก Omarchy ในตัวเลือกธีมของ Herdr อีกครั้งสำหรับโหมดอื่น

T3 Code รันจาก AppImage release อย่างเป็นทางการของมันใน `~/.local/share/t3code` แทนที่จะมาจาก package ดังนั้นมันจึงอัปเดตตัวเอง การติดตั้งมันจะถามว่าจะเริ่มบน channel แบบ Stable หรือ Nightly; สลับภายหลังได้ในการตั้งค่าของ T3 Code threads และ settings ของคุณอาศัยอยู่ใน `~/.t3` และการลบ T3 Code ใต้ _Remove > AI_ จะนำพวกมันไปด้วย

### โมเดลแบบโลคัล

รันโมเดลแบบเปิดบนเครื่องของคุณเองสำหรับ coding agent ของคุณ prompts และโค้ดของคุณอยู่บนเครื่อง; ไม่มีอะไรที่ส่งให้โมเดลออกจากเครื่อง เริ่มต้นด้วย:

```bash
omarchy agent local use best
```

หรือในแผง agent บนแถบบน ให้เลือก + แล้วเลือก Local AI ซึ่งจะปรากฏเมื่อโมเดลพอดีกับเครื่องนี้ ครั้งแรก สิ่งนี้จะติดตั้ง Podman ซึ่งรันโมเดลต่างๆ และบนเครื่อง NVIDIA จะติดตั้ง container toolkit ของ NVIDIA ซึ่งให้ GPU แก่พวกมัน จากนั้น Omarchy จะเลือกโมเดลที่แนะนำสำหรับเครื่องนี้ ดาวน์โหลดมัน และเริ่มมัน คาดว่าจะมีการดาวน์โหลดขนาดหลายสิบ GB และหน่วยความจำส่วนใหญ่ของเครื่องจะถูกใช้ขณะที่โมเดลทำงาน: Flash Next ใช้ประมาณ 100 GiB กับ context แบบเต็ม 256K ของมัน หากโมเดลอื่นครองหน่วยความจำที่มันต้องการอยู่ มันจะถูกตั้งค่าในสถานะหยุด พร้อมเริ่มเมื่อคุณหยุดโมเดลหนึ่ง โมเดลจะหยุดเมื่อออกจากระบบ; หยุดมันด้วยตัวเองเมื่อคุณต้องการหน่วยความจำสำหรับอย่างอื่น

`omarchy agent local list` แสดงตัวเลือกต่างๆ และอธิบายว่าทำไมบางตัวไม่พอดี เพื่อตั้งค่าตัวอื่น ให้รัน `omarchy agent local use <recipe>` วันนี้ `qwen3.8-flash-next-gufo` และ `qwen3.8-27b-gufo` มีให้สำหรับเครื่อง Strix Halo ขนาด 128 GB; ตัว 27B ใช้ประมาณ 40 GiB ดังนั้นมันจึงเหลือพื้นที่สำหรับงานอื่น recipes และคำแนะนำใหม่ๆ มากับ `omarchy update` ผ่าน package

ทุกโมเดลที่คุณตั้งค่าจะได้บรรทัดของตัวเองในแผง agent เคียงข้างการสมัครสมาชิกของคุณ: เล่นเพื่อเริ่มมัน หยุดชั่วคราวเพื่อหยุดมันและคืนหน่วยความจำ และปุ่ม terminal เพื่อเปิด agent ของคุณบนมัน หลายตัวสามารถทำงานพร้อมกันได้เมื่อพวกมันพอดีในหน่วยความจำด้วยกัน; หากตัวใดตัวหนึ่งไม่พอดี Omarchy จะบอกว่าต้องหยุดโมเดลที่กำลังทำงานตัวใด ลากบรรทัดเพื่อจัดลำดับใหม่ และกด Delete บนบรรทัดที่เลือกเพื่อลบโมเดลและการดาวน์โหลดของมัน

จาก command line, `omarchy agent local start <recipe>` และ `omarchy agent local stop <recipe>` ทำสิ่งเดียวกัน `omarchy agent local status` แสดงทุกโมเดล และ `omarchy agent --local` เปิด agent เริ่มต้นของคุณบนโมเดลล่าสุดที่คุณเริ่ม (pi หาก agent เริ่มต้นของคุณไม่สามารถใช้โมเดลแบบโลคัลได้) client ใดๆ ที่เข้ากันได้กับ OpenAI ก็สามารถเชื่อมต่อได้เช่นกัน: `status` แสดงที่อยู่ของแต่ละโมเดล (ตัวแรกคือ `http://127.0.0.1:11435/v1`) ชื่อ recipe คือโมเดล และ key อยู่ใน `~/.config/omarchy/agent-local/key`

`omarchy agent local remove <recipe>` ลบโมเดลและการดาวน์โหลดที่ไม่มีโมเดลอื่นใช้

Runtime ของบุคคลที่สามจะถูกระบุด้วยผู้เผยแพร่ของมัน Omarchy รันทุกโมเดลโดยไม่มีการเข้าถึงเครือข่าย

### LLM แบบโลคัล

Omarchy แนะนำสองวิธีในการรันโมเดล LLM แบบโลคัล: LM Studio และ Ollama LM Studio มี GUI interface สำหรับค้นหาโมเดลแบบ open-weight ติดตั้งพวกมัน และรันพวกมัน เป็นวิธีที่ยอดเยี่ยมในการเริ่มต้นอย่างง่ายดาย Ollama มี CLI สำหรับทำแบบเดียวกัน แต่หากคุณเพิ่งเริ่มกับโมเดลแบบโลคัล ผมจะเริ่มด้วย LM Studio คุณสามารถติดตั้งตัวใดตัวหนึ่งได้ใต้ _Install > AI_ ใน Omarchy Menu

### Omarchy Skill

Agent skills ช่วย AI ใช้เครื่องมือเฉพาะในวิธีเฉพาะ และ Omarchy มาพร้อมกับ skill เริ่มต้นสำหรับการปรับแต่งระบบ เช่น การปรับ Hyprland config ของคุณ การปรับแถบ หรือแม้แต่การสร้างธีมใหม่ตั้งแต่ศูนย์ มันถูก symlink เข้าไปในไดเรกทอรี skill สำหรับ Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` และแต่ละ `~/.hermes/profiles/*/skills`) และตำแหน่งทั่วไป `~/.agents/skills` ดังนั้น harness ส่วนใหญ่จะหยิบมันขึ้นมาโดยอัตโนมัติ

แต่คุณควรถือว่า skill นี้เป็นของทดลอง โมเดลที่แตกต่างกันจะใช้มันให้ผลที่แตกต่างกัน ทางที่ดีควรให้มันรันใน plan mode ก่อน เพื่อให้คุณพอเห็นภาพว่า agent อยากเปลี่ยนอะไร จากนั้นเตรียมพร้อมที่จะ rollback การเปลี่ยนแปลง หรือแม้กระทั่งเรียกใช้ `omarchy reinstall configs` หาก agent ทำทุกอย่างพังเละเทะ
