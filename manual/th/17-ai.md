### การติดตั้งและอัปเดต agent

ยกเว้น Hermes, agent เหล่านี้ใช้การติดตั้งแบบ lazy ของ mise: การเรียกใช้ครั้งแรกจะติดตั้ง CLI และการเรียกใช้ครั้งต่อ ๆ ไปจะใช้ตัวที่ติดตั้งไว้ซ้ำ mise ยังตรวจสอบด้วยว่า agent ที่ติดตั้งไว้มีรุ่นใหม่หรือไม่ อย่างมากที่สุดหนึ่งครั้งทุกสี่ชั่วโมง ทันทีก่อนที่มันจะเริ่มทำงาน หรือในพื้นหลังที่ shell prompt หากการอัปเดตนั้นล้มเหลวหรือคุณออฟไลน์อยู่ รุ่นที่ติดตั้งไว้จะทำงานแทน `omarchy update` จะอัปเดต agent ที่ติดตั้งไว้พร้อมกับส่วนอื่น ๆ ของ Omarchy และ `mup` จะอัปเดตเฉพาะเครื่องมือที่จัดการโดย mise เท่านั้น

ตัวอัปเดตของ agent เอง เช่น `claude update`, `codex update` หรือปุ่มอัปเดตในแอป จะไม่อัปเดตตัวที่ติดตั้งและจัดการโดย mise `codex update` จะล้มเหลว และ `claude update` อาจรายงานว่าสำเร็จในขณะที่ติดตั้งสำเนาแยกอีกตัวที่ mise ไม่ได้ติดตาม หากคุณอยากใช้ตัวติดตั้งและตัวอัปเดตแบบ native ของ agent มากกว่า ให้เพิ่มมันลงใน `disable_tools`; ดู [Preinstalled CLI tools](18-development-tools.md#preinstalled-cli-tools)

หากต้องการติดตั้งเครื่องมือแบบ lazy ที่กำหนดค่าไว้ทั้งหมดก่อนที่คุณจะต้องการใช้ ให้รัน `mise install --include-lazy` ซึ่งรวมถึงเครื่องมือ CLI ค่าเริ่มต้นอื่น ๆ ของ Omarchy เช่นเดียวกับ agent ต่าง ๆ ดู [Preinstalled CLI tools](18-development-tools.md#preinstalled-cli-tools) สำหรับการติดตั้งเครื่องมือเพียงตัวเดียวหรือการใช้ตัวติดตั้งของคุณเอง

`grok` ถูกติดตั้งผ่านแพ็กเกจ `grok` แบบ first-party ของ mise ในลักษณะเดียวกับ `claude` และ `codex` รัน `grok` หรือเลือกมันใต้ _Agent > Harness_ ข้ามตัวติดตั้งแบบ `curl | bash` บน x.ai ไปได้เลย เส้นทางนั้นจะวางสำเนาที่สองไว้ใน `~/.grok/bin`, แทรกมันไว้ด้านหน้าบน `PATH` และเขียนทับ wrapper ของ Omarchy

`dsh` เปิด UI บนเบราว์เซอร์ของมันที่ `127.0.0.1:3080` โดยใช้ไดเรกทอรีที่เรียกใช้เป็น workspace ค่าเริ่มต้น UI บนเบราว์เซอร์ของมันไม่รับ prompt เริ่มต้น ดังนั้น `omarchy agent prompt` จะเปิดมันพร้อม prompt บนคลิปบอร์ดของคุณให้วาง Omarchy เริ่มมันด้วย permission preset แบบ no-approval ของ DeepSeek DeepSeek Harness จะอัปโหลด session log ไปยัง DeepSeek เมื่อคุณใช้ model API อย่างเป็นทางการของมัน; ปิดสิ่งนั้นได้ใต้ _Settings > General > Upload Session Log_ ใน UI บนเบราว์เซอร์ของมัน Feedback ที่คุณส่งให้มันจะถูกอัปโหลดไปพร้อมกับ session ด้วยเช่นกัน เว้นแต่คุณจะเริ่มมันด้วย `DSH_TELEMETRY_MODE=DISABLED`

### agent ค่าเริ่มต้น

เลือก agent ค่าเริ่มต้นของคุณด้วย `omarchy default agent <name>` หรือใต้ _Agent > Harness_ ใน Omarchy Menu (`Super + Space`) หาก agent นั้นยังไม่ได้ติดตั้ง การเลือกมันจะติดตั้งมันก่อน Omarchy ที่ติดตั้งใหม่จะเชิญให้คุณตัดสินใจเลือกสิ่งนี้ด้วยการแจ้งเตือนเพียงครั้งเดียว

การเลือก Claude ยังพยายามตั้งค่า browser extension ของมันสำหรับ Chromium, Chrome, Brave, Brave Origin และ Edge ด้วย การตั้งค่า extension ใช้กับผู้ใช้ทุกคนและอาจขอรหัสผ่านระบบของคุณ; การยกเลิกหรือการติดตั้ง extension ที่ล้มเหลวยังคงเลือกและเรียกใช้ Claude อยู่ รีสตาร์ทเบราว์เซอร์ของคุณ เปิดใช้งาน extension หากได้รับแจ้ง และลงชื่อเข้าใช้ Claude เพื่อเชื่อมต่อมันให้เสร็จสมบูรณ์ รัน `/chrome` ใน Claude เพื่อตรวจสอบการเชื่อมต่อ Firefox และ Zen ไม่รองรับ extension นี้ หาก Claude เคยเป็นค่าเริ่มต้นของคุณอยู่แล้วก่อนที่จะมีการเพิ่มการตั้งค่านี้ ให้เลือกมันอีกครั้งเพื่อติดตั้ง extension

เมื่อคุณเลือกแล้ว `Super + Shift + Ctrl + A` จะเรียกใช้ agent ค่าเริ่มต้นในหน้าต่าง terminal เฉพาะ (หรือเปิดตัวเลือกขึ้นมาหากคุณยังไม่ได้เลือก) คุณยังสามารถเรียกใช้มันให้เข้าสู่งานได้โดยตรงด้วย `omarchy agent prompt "Review this project"` Freebuff และ DeepSeek Harness ไม่รับ prompt เริ่มต้น ดังนั้นพวกมันจะเปิดพร้อม prompt บนคลิปบอร์ดของคุณให้วางแทน agent ที่เรียกใช้ด้วยวิธีนี้จะทำงานโดยไม่มีใครดูแลในโหมด don't-stop-to-ask ของแต่ละตัว ดังนั้นเตรียมพร้อมไว้เลยว่าพวกมันจะลงมือทำสิ่งต่าง ๆ จริง ๆ! MiniMax Code ไม่มีโหมดเช่นนั้นสำหรับ session แบบ interactive ของมัน ดังนั้นมันจะขอ permissions ตามปกติ และเนื่องจาก agent ปฏิเสธที่จะจดจำ trust สำหรับ home directory ของคุณ การเรียกใช้จาก `$HOME` จะเริ่มใน `~/Work` แทน

ยังมี shortcut บน terminal ด้วย: `a` รัน agent ค่าเริ่มต้นแบบ inline ใน terminal ปัจจุบัน ขณะที่ `c`, `cx` และ `cy` เริ่ม OpenCode, Claude Code และ Codex โดยตรง (อีกเช่นกัน ในโหมด auto-approving ของพวกมัน) การเปลี่ยนธีมจะซิงค์ไปยัง agent ต่าง ๆ ด้วยเช่นกัน: Claude Code, Pi, OpenCode และ Hermes (เมื่อ Omarchy ติดตั้งมันแล้ว) จะเปลี่ยนตามทั้งหมดเมื่อคุณสลับธีมของ Omarchy

### คำสั่งสำหรับ agent ของคุณ

กฎส่วนตัวสำหรับทุก agent อยู่ใน `~/.agents/AGENTS.md` ถัดจาก skills ที่ใช้ร่วมกันใน `~/.agents/skills` เปิดมันใต้ _Agent > Instructions_ ซึ่งยังเชื่อมโยงมันเข้าไปในแต่ละ harness ที่เก็บไฟล์ global ของตัวเองไว้ด้วย: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` ของ Copilot และอื่น ๆ Crush และ Amp อ่านลิงก์ `~/.config/AGENTS.md` ขณะที่ omp, Kimi และ DeepSeek Harness อ่าน `~/.agents/AGENTS.md` โดยตรง การเลือก agent ค่าเริ่มต้นจะเชื่อมโยงมันด้วยเช่นกัน ไฟล์คำสั่งที่คุณมีอยู่แล้วจะกลายเป็นไฟล์ที่ใช้ร่วมกันหากยังไม่มีไฟล์ดังกล่าวอยู่; มิฉะนั้นมันจะถูกเก็บไว้ข้างลิงก์ในชื่อ `.bak` รัน `omarchy agent instructions` เพื่อเชื่อมโยงใหม่หลังจากติดตั้ง agent ตัวอื่น

### แผง agents

แถบบนสุดมีไอคอน agents ก่อนที่คุณจะตั้งค่า agent แผงของมันจะพาคุณผ่านการลงชื่อเข้าใช้ Claude, Codex หรือ Grok และตัวแรกจะกลายเป็น agent ค่าเริ่มต้นของคุณ หลังจากนั้น แผงจะรวมทุกการสมัครสมาชิกไว้ในหน้าเดียว: แต่ละ agent และบัญชีพร้อมแผนของมัน มิเตอร์สำหรับขีดจำกัด session 5 ชั่วโมงและขีดจำกัดรายสัปดาห์ของแต่ละตัวพร้อมเวลาจนกว่าจะรีเซ็ต (วางเมาส์เหนือเพื่อดูเปอร์เซ็นต์ที่แน่นอน) หรือยอดเงิน prepaid คงเหลือ ใต้บรรทัดที่หมุนเวียนสิ่งที่คุณใช้ไปในทุกตัว เช่น tokens ในสัปดาห์นี้และโมเดลที่คุณใช้มากที่สุด ใต้ _Make something_ มันมี prompt เริ่มต้นสำหรับธีม, plugin หรือแอปใหม่ ที่ส่งงานให้ agent ค่าเริ่มต้นของคุณ แอปถูกสร้างในแบบเดียวกับ Hype, Monologue และ Omacut ของ Omarchy เอง ใน C++ และ Qt Quick โดยทำตาม omarchy-app agent skill และ compiler กับชิ้นส่วน Qt ที่พวกมันต้องการก็มาพร้อมติดตั้งไว้แล้ว Claude Code, Codex, Grok, Kimi, Cursor และโควตา Grok Bot ของมัน, GitHub Copilot, Muse, Antigravity, Kimchi และ Devin ได้รับการครอบคลุมพร้อมขีดจำกัดของพวกมันตั้งแต่แรก และ Hermes, Mistral Vibe และ Qwen Code จะแสดง session และ tokens ของพวกมันเมื่อคุณได้ใช้พวกมันแล้ว แผนและ key ของ provider ที่คุณใช้ผ่าน pi, omp หรือ opencode จะปรากฏด้วยเช่นกัน: OpenCode Zen และ Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan และ Synthetic พร้อมขีดจำกัดของพวกมัน; Fireworks, OpenRouter และ DeepSeek พร้อมยอดเงิน prepaid ของพวกมัน; และโมเดลที่คุณรันบนฮาร์ดแวร์ของคุณเองใต้ Local models ทุก agent ถูกนับเพียงครั้งเดียว ใต้ผู้ที่เรียกเก็บเงินจากมัน ไม่ว่าคุณจะขับเคลื่อนมันผ่าน harness กี่ตัวก็ตาม

คลิกซ้ายที่ไอคอนบนแถบเพื่อเปิดแผง คลิกขวาเพื่อเรียกใช้ agent ค่าเริ่มต้นของคุณ บันทึกการใช้งานที่อยู่เบื้องหลังมันจะถูกสร้างใหม่ทุก 15 นาทีโดย `omarchy agent usage-update` และแผงยังสามารถรวมการใช้งานจากเครื่องอื่น ๆ ของคุณผ่านโฟลเดอร์ที่ซิงค์ไว้ได้อีกด้วย ดู README ใต้ `$OMARCHY_PATH/shell/plugins/agents/` สำหรับการตั้งค่าแบบเต็ม

### การสมัครสมาชิกหลายรายการ

หากคุณจ่ายสำหรับแผน Claude, Codex หรือ Grok มากกว่าหนึ่งแผน — เช่น Max ส่วนตัวและอีกอันสำหรับงาน — Omarchy สามารถให้ทุกแผนลงชื่อเข้าใช้ค้างไว้และย้ายไปมาระหว่างพวกมันได้ เพิ่มการสมัครสมาชิกด้วย + ในแผง agents ซึ่งจะพาคุณผ่านขั้นตอนนั้นตรงนั้นเลย หรือด้วย `omarchy agent account add claude Work` (หรือ `codex` หรือ `grok`) มันจะติดตั้ง CLI หากยังขาดอยู่ บัญชีแรกสำหรับ provider หนึ่งจะลงชื่อเข้าใช้ผ่านเบราว์เซอร์ปกติของคุณ ตรงตำแหน่งที่ CLI มองหาเสมอ ทุกบัญชีหลังจากนั้นจะลงชื่อเข้าใช้ผ่านหน้าต่าง private ดังนั้นบัญชีที่เบราว์เซอร์ของคุณลงชื่อเข้าใช้อยู่แล้วจะไม่ถูกหยิบขึ้นมาโดยไม่ตั้งใจ; ลงชื่อเข้าใช้ที่นั่นในฐานะบัญชีที่คุณกำลังเพิ่ม และปิดหน้าต่าง private ใด ๆ ที่คุณเปิดค้างไว้อยู่ก่อน อย่าออกจากระบบของ CLI เพื่อทำสิ่งนี้เด็ดขาด: การออกจากระบบจะเพิกถอนการลงชื่อเข้าใช้ที่บันทึกไว้ และบัญชีนั้นจะต้องถูกเพิ่มใหม่อีกครั้ง

หากต้องการคัดล็อกข้อมูลลงชื่อเข้าใช้การสมัครสมาชิกของคุณไปยังเครื่อง Omarchy อีกเครื่องผ่าน SSH ให้รัน `omarchy agent account copy user@laptop` ผู้ส่งจะจัดเตรียมตัวรับชั่วคราวให้เมื่อปลายทางไม่มีตัวรับติดตั้งอยู่ ดังนั้นเครื่อง Omarchy รุ่นเก่ากว่าสามารถรับบัญชีได้โดยไม่ต้องอัปเดต ตัวรับที่ติดตั้งไว้จะมีความสำคัญเหนือกว่า สิ่งนี้คัดลอกการสมัครสมาชิก Claude, Codex และ Grok ทั้งหมด; เพิ่มชื่อ provider เพื่อเลือกพวกมัน เช่นใน `omarchy agent account copy laptop claude` ชื่อบัญชีและ command ID จะตรงกับต้นทาง รวมถึงบัญชีที่มีอยู่แล้วบนปลายทาง บัญชีปลายทางที่ไม่เกี่ยวข้องจะได้รับ suffix เป็นตัวเลขหากชื่อของพวกมันขัดกัน และ settings, skills, plugins และประวัติการสนทนาจะยังคงเป็นแบบ local สำหรับแต่ละเครื่อง

ข้อมูลประจำตัวปลายทางที่มีอยู่จะถูกเก็บไว้ บัญชีต้นทางที่ลงชื่อเข้าใช้อยู่ที่นั่นแล้วจะมีชื่อของมันถูกซิงค์โดยไม่แทนที่ข้อมูลประจำตัวของมัน; บัญชีอื่น ๆ จะถูกเพิ่มเข้าไปควบคู่กัน หากต้องการแทนที่ข้อมูลประจำตัวที่บันทึกไว้สำหรับบัญชีที่ตรงกัน ให้ใช้ `omarchy agent account copy --replace laptop claude` หลังจากออกจาก session ของบัญชีนั้นบนปลายทางแล้ว ปลายทางใหม่ยังจะได้รับบัญชีที่ใช้งานอยู่และการตั้งค่าการสลับของต้นทางด้วย; ปลายทางที่มีอยู่แล้วจะเก็บของตัวเองไว้

ข้อมูลประจำตัวเดินทางผ่าน SSH และถูกเก็บไว้ในไฟล์ private บนปลายทาง ดังนั้นคัดลอกไปยังเครื่องที่คุณไว้วางใจเท่านั้น นี่เป็นการคัดลอกเพียงครั้งเดียว ไม่ใช่การซิงโครไนซ์อย่างต่อเนื่อง Codex refresh tokens สามารถถูกหมุนเวียนโดยเครื่องอื่นได้ ทำให้ข้อมูลเข้าสู่ระบบที่คัดลอกมาต้องได้รับการต่ออายุ; การลงชื่อเข้าใช้แยกกันยังคงเป็นตัวเลือกที่น่าเชื่อถือที่สุดสำหรับการใช้งานพร้อมกันบนหลายเครื่อง ดู [Codex's account authentication guidance](https://developers.openai.com/codex/auth/ci-cd-auth)

บัญชีเดียวต่อ provider จะใช้งานอยู่ และทุก session ใหม่จะเริ่มต้นเป็นบัญชีนั้น: `cx`, `cy`, `claude`, `codex` หรือ `grok` แบบธรรมดา, อะไรก็ตามที่เรียกใช้ผ่าน `omarchy agent` และ scripts หรือ editors ที่พบ CLI บน `PATH` สลับด้วย `omarchy agent account use work` (และกลับด้วย `omarchy agent account use main`) หรือในแผงโดยกดหมายเลขของบัญชีแล้วกด `Enter` (หรือคลิกปุ่ม Use ของมัน) session ที่กำลังทำงานอยู่แล้วจะยังคงอยู่บนบัญชีที่พวกมันเริ่มต้นด้วย ประวัติการสนทนา, settings, skills และ plugins ถูกใช้ร่วมกันข้ามบัญชี ดังนั้น `claude --continue` ในโฟลเดอร์เดียวกันจะสานต่อจากจุดที่คุณค้างไว้บนบัญชีใหม่

เมื่อมีมากกว่าหนึ่งบัญชี แผงจะแสดงขีดจำกัดของแต่ละบัญชีเคียงข้างกัน โดยบัญชีที่ใช้งานอยู่จะถูกทำเครื่องหมายไว้ โดยค่าเริ่มต้น Omarchy จะแจ้งเตือนคุณเมื่อบัญชีที่ใช้งานอยู่ผ่าน 95% ของขีดจำกัด และการคลิกการแจ้งเตือนจะสลับไปยังบัญชีที่มี headroom เหลือมากที่สุด วางเมาส์เหนือบรรทัดของบัญชีในแผงและคลิก Autoswitch ที่ปรากฏข้าง Use (หรือกด `m`) หรือรัน `omarchy agent account mode auto` เพื่อให้มันสลับด้วยตัวเองแทน; ขณะที่มันเปิดอยู่ Autoswitch จะมาแทนที่ Use และการคลิกมันอีกครั้งจะกลับไปเป็นการแจ้งเตือน เพิ่มตัวเลขเพื่อเปลี่ยน threshold เช่นใน `omarchy agent account mode auto 90` หากทุกบัญชีเกิน threshold คุณจะได้ยินเรื่องนี้หนึ่งครั้ง พร้อมกับว่าบัญชีใดจะว่างขึ้นก่อน ขณะที่บัญชีที่ใช้งานอยู่ภายใน 15 จุดจาก threshold ของมัน (80% ที่ค่าเริ่มต้น) ขีดจำกัดของมันจะถูกตรวจสอบทุกสามนาทีแทนที่จะเป็นทุก 15 นาที

`omarchy agent account list` แสดงทุกบัญชีและขีดจำกัดล่าสุดของพวกมัน, `omarchy agent account remove work` ลบบัญชีหนึ่งออก และ `omarchy agent account rename primary Hey` เปลี่ยนชื่อบัญชีหนึ่ง (หรือคลิกชื่อของบัญชีในแผง) คำสั่งเหล่านี้ทำงานบนบัญชีของ agent ค่าเริ่มต้นของคุณ; หากต้องการเข้าถึง provider อื่น ให้ระบุชื่อมันก่อน เช่นใน `omarchy agent account use codex side` ข้อมูลเข้าสู่ระบบที่คุณมีอยู่แล้วใน `~/.claude` หรือ `~/.codex` คือบัญชี _Main_ และจะยังคงอยู่ที่เดิม บัญชีที่ไม่ได้ใช้งานนานกว่าประมาณแปดชั่วโมงอาจแสดง _Sign-in required_; คลิกมันเพื่อลงชื่อเข้าใช้บัญชีนั้นอีกครั้งในแผงเลย หรือเริ่ม session ในบัญชีนั้น ซึ่งจะรีเฟรชการลงชื่อเข้าใช้ด้วยตัวเอง MCP servers ที่คุณมีเมื่อบัญชีถูกเพิ่มเข้ามาจะตามมาที่บัญชีนั้นด้วย แต่ตัวที่คุณเพิ่มภายหลังด้วย `claude mcp add` จะไปถึงเฉพาะบัญชีที่คุณเพิ่มพวกมันในเท่านั้น Claude Desktop และเครื่องมือที่กำหนดค่าด้วย absolute path ไปยัง binary ของ CLI จะไม่ตามการสลับไป `CLAUDE_CONFIG_DIR`, `CODEX_HOME` หรือ `GROK_HOME` ที่ระบุอย่างชัดเจนจะมีความสำคัญเหนือบัญชีที่เลือกไว้

### การวินิจฉัยการแครช

Omarchy เฝ้าดู systemd-coredump สำหรับการแครชของ process เมื่อมีบางสิ่ง segfault คุณจะได้รับการแจ้งเตือน "Process crashed" — คลิกมัน และการแครชจะถูกส่งให้ agent ค่าเริ่มต้นของคุณพร้อมกับ diagnose-crash skill ของ Omarchy ซึ่งจะพา agent ผ่านการหาข้อเท็จจริงจาก core dump และการตัดสินใจว่าการแครชนั้นคุ้มค่าที่จะรายงานไปยัง upstream หรือไม่ คุณยังสามารถรันมันด้วยมือกับ PID ใด ๆ จาก `coredumpctl list` ด้วย `omarchy agent crash <pid>` ได้อีกด้วย

การเฝ้าดูเปิดอยู่โดยค่าเริ่มต้น ปิดมันใต้ _Trigger > Toggle > Crash Capture_ (หรือด้วย `omarchy toggle crash-capture`) และการแจ้งเตือนจะหยุดลง; `omarchy agent crash <pid>` ยังคงทำงานด้วยมือได้

การแครชยังสามารถถูกปิดเสียงได้ทีละโปรแกรม ซึ่งเป็นสิ่งที่การวินิจฉัยเสนอให้คุณในตอนท้าย `omarchy crash mute hyprland` หยุดการแจ้งเตือนสำหรับโปรแกรมนั้นเท่านั้น, `omarchy crash mute hyprland off` นำพวกมันกลับมา และ `omarchy crash mute` ด้วยตัวมันเองจะแสดงรายการสิ่งที่คุณปิดเสียงไว้ มันรับ path ของ binary ได้อย่างยินดีพอ ๆ กับชื่อของมัน ดังนั้น `omarchy crash mute /usr/bin/hyprland` ทำสิ่งเดียวกัน ใส่เครื่องหมายคำพูดครอบชื่อที่มีช่องว่างในนั้น เช่นใน `omarchy crash mute 'Some App'` อย่างอื่นทุกอย่างยังคงแจ้งเตือน และโปรแกรมที่ถูกปิดเสียงยังคงแครช — สิ่งนี้ซ่อนการเตือนความจำ มันไม่ได้แก้ไขอะไรเลย

### แอปเดสก์ท็อป

เมนู _Install > AI_ ยังมีแอป AI แบบ graphical อีกสองสามตัวด้วย: แอปเดสก์ท็อป ChatGPT, แอปเดสก์ท็อป Claude (Linux beta ของ Anthropic พร้อมแท็บ Chat, Cowork และ Claude Code), Grok Bot สำหรับแชทกับโมเดลของ xAI, Herdr Desktop, Hermes Desktop, OpenClaw, แอปเดสก์ท็อป Perplexity และ T3 Code Grok Bot คือแอปแชทบนเดสก์ท็อป coding agent คือคำสั่ง `grok`

Hermes Desktop คือตัวที่คุณต้องรู้ไว้ เพราะเครื่องหนึ่งมี Hermes เดียว และมันเป็นของแอป: Hermes จะถูกติดตั้งผ่านแอปเท่านั้นเสมอ และคำสั่ง `hermes` ที่ agent ค่าเริ่มต้นรันคือของแอป การเลือก Hermes เป็น agent ค่าเริ่มต้นจะติดตั้งสิ่งเดียวกับที่รายการ _Install > AI_ ทำ: แพ็กเกจ และ Hermes runtime ใต้ `~/.hermes` ที่ตั้งค่าโดยตัวติดตั้งของ Hermes เอง ซึ่งใช้เวลาสองสามนาทีในครั้งแรก runtime นั้นคือ Hermes ตัวเดียวที่คำสั่ง `hermes` บน terminal, agent ค่าเริ่มต้น และแอปทั้งหมดใช้ และมันอัปเดตตัวเองด้วย `hermes update` แทนที่จะรอ Omarchy ออกใหม่ การติดตั้งมันยังมอบธีม Omarchy ให้ Hermes ในชื่อ skin ว่า `omarchy` ซึ่งทุกพื้นผิวของ Hermes จะตามไปเมื่อคุณสลับธีม; เลือกอีกตัวใต้การตั้งค่า Appearance ของ Hermes หรือด้วย `/skin` หากคุณไม่อยากให้มันเป็นเช่นนั้น และ Omarchy จะปล่อยตัวเลือกนั้นไว้ตามนั้น การลบแอปใต้ _Remove > AI_ จะปิด Hermes ก่อน รวมถึง gateway, นำ runtime นั้นไปกับมันด้วย และเก็บแชท, ความทรงจำ และ skills ที่ Hermes เขียนให้ตัวเองไว้ เว้นแต่คุณจะบอกเป็นอย่างอื่น: มันจะถาม โดยค่าเริ่มต้นคือไม่ ว่าข้อมูลนั้นและการตั้งค่าการเชื่อมต่อของคุณควรจะไปด้วยหรือไม่

ประสบการณ์บนเดสก์ท็อปของ OpenClaw คือ Control UI ของมัน ซึ่งเปิดเป็น web app ที่หนุนโดย local gateway ของมันเอง OpenClaw อาศัยอยู่ใน `~/.openclaw` และอัปเดตตัวเอง: ใช้ปุ่ม "Update Gateway" ของ Control UI หรือรัน `openclaw update` และ gateway จะรีสตาร์ทบนรุ่นใหม่ Omarchy เพียงเลือก release ที่การติดตั้งใหม่จะเริ่มต้นจากเท่านั้น การลบ OpenClaw ใต้ _Remove > AI_ จะนำ gateway service และแอปไปกับมันด้วย จากนั้นถามว่า `~/.openclaw` ควรจะไปด้วยหรือไม่ เนื่องจากที่นั้นเก็บแชทและข้อมูลประจำตัวของคุณไว้ควบคู่กับ OpenClaw เองและ plugin runtimes ที่มันดาวน์โหลดมา; ค่าเริ่มต้นคือเก็บมันไว้ และการติดตั้ง OpenClaw อีกครั้งจะหยิบมันกลับมา

Herdr Desktop คือแอปเดสก์ท็อป [Herdr](https://herdr.dev): spaces, tabs และ panes ของ terminals และ coding agents ที่ยังคงทำงานใน core ของมันเมื่อคุณปิดหน้าต่าง มันมาจากตัวติดตั้งของ Herdr เองแทนที่จะเป็นแพ็กเกจ ดังนั้นมันจึงอาศัยอยู่ใน `~/.local/share/herdr-app`, นำ core ของมันมาไว้ใน `~/.local/bin/herdr-core` เมื่อคุณยังไม่มี และอัปเดตทั้งตัวมันเอง มันอยู่ข้างคำสั่ง `herdr` ที่ Omarchy ส่งมาบน `Super + Ctrl + Return` แทนที่จะแทนที่มัน และได้รับ direct keys ของคำสั่งนั้น: `Alt + Return` และ `Alt + Shift + Return` แยก pane ลงหรือขวา, `Alt + Escape` ปิดมัน, `Ctrl + Alt + Arrow` ย้ายระหว่าง panes, `Alt + 1..9` และ `Alt + Left/Right` เลือก tab และ `Alt + Up/Down` ย้ายระหว่าง spaces `Ctrl + 1..9` เลือก space และ `Alt + Shift + Up/Down` ก้าวผ่าน agents ปุ่ม prefix `Ctrl + Space` ยังคงเป็นแบบ terminal-only เนื่องจากแอปไม่สามารถกดปุ่ม Ctrl ธรรมดาค้างไว้สำหรับลำดับได้ Omarchy เขียนสิ่งเหล่านี้ลงใน `~/.config/herdr-app/keys.json` และ `omarchy-refresh-herdr-app` จะใส่พวกมันกลับมา การติดตั้งมันจะเลือกธีม Omarchy ของ Herdr ซึ่งจะตามธีม Omarchy ของคุณจากนั้นเป็นต้นไป Herdr เก็บธีมหนึ่งไว้สำหรับ light mode และอีกธีมสำหรับ dark mode ดังนั้นหลังจากสลับระหว่างธีม Omarchy แบบ dark และแบบ light ให้เลือก Omarchy ในตัวเลือกธีมของ Herdr อีกครั้งสำหรับอีกโหมด

T3 Code รันจาก release แบบ AppImage อย่างเป็นทางการของมันใน `~/.local/share/t3code` แทนที่จะมาจากแพ็กเกจ ดังนั้นมันจึงอัปเดตตัวเอง การติดตั้งมันจะถามว่าจะเริ่มบน channel แบบ Stable หรือ Nightly; สลับภายหลังได้ในการตั้งค่าของ T3 Code threads และ settings ของคุณอาศัยอยู่ใน `~/.t3` และการลบ T3 Code ใต้ _Remove > AI_ จะนำพวกมันไปกับมันด้วย

### โมเดลแบบโลคัล

รันโมเดลแบบ open บนเครื่องของคุณเองสำหรับ coding agent ของคุณ prompt และโค้ดของคุณยังคงอยู่บนเครื่อง; ไม่มีอะไรที่ส่งให้โมเดลออกจากเครื่องไป เริ่มต้นด้วย:

```bash
omarchy agent local use best
```

หรือ ในแผง agents ในแถบบนสุด เลือก + แล้วเลือก Local AI ซึ่งจะปรากฏขึ้นเมื่อมีโมเดลที่พอดีกับเครื่องนี้ ในครั้งแรก สิ่งนี้จะติดตั้ง Podman ซึ่งรันโมเดล และบนเครื่อง NVIDIA จะติดตั้ง container toolkit ของ NVIDIA ซึ่งให้ GPU แก่พวกมัน จากนั้น Omarchy จะเลือกโมเดลที่แนะนำสำหรับเครื่องนี้ ดาวน์โหลดมัน และเริ่มมัน คาดหวังการดาวน์โหลดขนาดหลายสิบ GB และหน่วยความจำของเครื่องส่วนใหญ่จะถูกใช้ขณะที่โมเดลทำงาน: Flash Next ใช้ประมาณ 100 GiB กับ context แบบเต็ม 256K ของมัน หากโมเดลอื่นถือครองหน่วยความจำที่มันต้องการ มันจะถูกตั้งค่าไว้ในสถานะหยุด พร้อมเริ่มเมื่อคุณหยุดตัวหนึ่งลง โมเดลจะหยุดเมื่อออกจากระบบ; หยุดมันด้วยตัวเองเมื่อคุณต้องการหน่วยความจำสำหรับอย่างอื่น

`omarchy agent local list` แสดงตัวเลือกและอธิบายว่าทำไมบางตัวถึงไม่พอดี หากต้องการตั้งค่าอีกตัว ให้รัน `omarchy agent local use <recipe>` วันนี้ `qwen3.8-flash-next-gufo` และ `qwen3.8-27b-gufo` พร้อมใช้งานสำหรับเครื่อง Strix Halo ขนาด 128 GB; ตัว 27B ใช้ประมาณ 40 GiB ดังนั้นมันจึงเหลือที่ว่างสำหรับงานอื่น recipes และคำแนะนำใหม่มาพร้อมกับ `omarchy update` ผ่านแพ็กเกจ

ทุกโมเดลที่คุณตั้งค่าจะได้บรรทัดของตัวเองในแผง agents ถัดจากการสมัครสมาชิกของคุณ: เล่นเพื่อเริ่มมัน หยุดชั่วคราวเพื่อหยุดมันและคืนหน่วยความจำของมัน และปุ่ม terminal เพื่อเปิด agent ของคุณบนมัน หลายตัวสามารถทำงานพร้อมกันได้เมื่อพวกมันพอดีในหน่วยความจำรวมกัน; หากตัวหนึ่งไม่พอดี Omarchy จะบอกให้หยุดโมเดลที่กำลังทำงานตัวใด ลากบรรทัดเพื่อจัดลำดับพวกมันใหม่ และกด Delete บนบรรทัดที่เลือกเพื่อลบโมเดลและการดาวน์โหลดของมัน

จาก command line, `omarchy agent local start <recipe>` และ `omarchy agent local stop <recipe>` ทำสิ่งเดียวกัน, `omarchy agent local status` แสดงทุกโมเดล และ `omarchy agent --local` เปิด agent ค่าเริ่มต้นของคุณบนโมเดลล่าสุดที่คุณเริ่ม pi, OpenCode และ Qwen Code สามารถใช้ได้หนึ่งตัว; กับค่าเริ่มต้นอื่นใด มันจะเปิดใน pi pi ยังแสดงรายการทุกโมเดลที่คุณตั้งค่าไว้ และโมเดลบนเครื่องที่คุณจับคู่ด้วย ในตัวเลือกโมเดลของมันเอง ดังนั้น `pi` แบบธรรมดาก็เข้าถึงพวกมันได้เช่นกัน client ใด ๆ ที่เข้ากันได้กับ OpenAI สามารถเชื่อมต่อได้ด้วย: `status` แสดงที่อยู่ของแต่ละโมเดล (ตัวแรกคือ `http://127.0.0.1:11435/v1`), ชื่อ recipe คือโมเดล และ key อยู่ใน `~/.config/omarchy/agent-local/key`

`omarchy agent local remove <recipe>` ลบโมเดลและการดาวน์โหลดที่ไม่มีโมเดลอื่นใช้

runtimes ของบุคคลที่สามจะถูกติดป้ายด้วยผู้เผยแพร่ของพวกมัน Omarchy รันทุกโมเดลโดยไม่มีการเข้าถึงเครือข่าย

### LLM แบบโลคัล

Omarchy แนะนำสองวิธีในการรันโมเดล LLM แบบโลคัล: LM Studio และ Ollama LM Studio ให้ GUI interface สำหรับค้นหาโมเดลแบบ open-weight, ติดตั้งพวกมัน และรันพวกมัน มันเป็นวิธีที่ยอดเยี่ยมในการเริ่มต้นได้ง่าย ๆ Ollama มี CLI สำหรับทำเช่นเดียวกัน แต่หากคุณเพิ่งเริ่มใช้โมเดลแบบโลคัล ฉันขอแนะนำให้เริ่มด้วย LM Studio คุณสามารถติดตั้งตัวใดตัวหนึ่งได้ใต้ _Install > AI_ ใน Omarchy Menu

### Omarchy Skill

Agent skills ช่วยให้ AI ใช้เครื่องมือเฉพาะในลักษณะเฉพาะ และ Omarchy มาพร้อมกับ skill ค่าเริ่มต้นสำหรับการปรับแต่งระบบ เช่นเดียวกับการปรับแต่ง Hyprland config ของคุณ การปรับแถบ หรือแม้แต่การสร้างธีมใหม่ตั้งแต่ต้น มันถูก symlink เข้าไปใน skill directories สำหรับ Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` และแต่ละ `~/.hermes/profiles/*/skills`) และตำแหน่ง generic `~/.agents/skills` ดังนั้น harness ส่วนใหญ่จะหยิบมันขึ้นมาโดยอัตโนมัติ

แต่คุณควรปฏิบัติต่อ skill นี้เสมือนเป็นของทดลอง โมเดลต่าง ๆ จะใช้มันให้ผลต่างกัน ดีที่สุดคือรันใน plan mode ก่อน เพื่อให้คุณมีภาพว่า agent อยากเปลี่ยนแปลงอะไร จากนั้นเตรียมพร้อมที่จะ rollback การเปลี่ยนแปลง หรือแม้แต่เรียกใช้ `omarchy reinstall configs` หาก agent ทำทุกอย่างพังเละเทะ
