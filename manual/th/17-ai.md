### การติดตั้งและอัปเดต agent

ยกเว้น Hermes และ OpenClaw, agent เหล่านี้ใช้การติดตั้งแบบ lazy ของ mise: การเรียกใช้ครั้งแรกจะติดตั้ง CLI และการเรียกใช้ครั้งต่อ ๆ ไปจะใช้ตัวที่ติดตั้งไว้ mise ยังตรวจสอบ agent ที่ติดตั้งไว้ว่ามีรุ่นใหม่ออกมาหรือไม่ อย่างมากที่สุดทุกสี่ชั่วโมง ทันทีก่อนที่มันจะเริ่มทำงาน หรือในเบื้องหลังที่ shell prompt หากการอัปเดตนั้นล้มเหลวหรือคุณออฟไลน์อยู่ รุ่นที่ติดตั้งไว้จะทำงาน `omarchy update` จะอัปเดต agent ที่ติดตั้งไว้พร้อมกับส่วนที่เหลือของ Omarchy และ `mup` จะอัปเดตเฉพาะเครื่องมือที่ mise จัดการเท่านั้น

ตัวอัปเดตของ agent เอง เช่น `claude update`, `codex update` หรือปุ่มอัปเดตในแอป จะไม่อัปเดตตัวที่ติดตั้งและจัดการโดย mise `codex update` จะล้มเหลว และ `claude update` อาจรายงานว่าสำเร็จในขณะที่ติดตั้งสำเนาแยกอีกตัวที่ mise ไม่ได้ติดตาม หากคุณอยากใช้ตัวติดตั้งและตัวอัปเดตดั้งเดิมของ agent มากกว่า ให้เพิ่มมันลงใน `disable_tools`; ดู [เครื่องมือ CLI ที่ติดตั้งไว้ล่วงหน้า](18-development-tools.md#preinstalled-cli-tools)

หากต้องการติดตั้งเครื่องมือแบบ lazy ที่กำหนดค่าไว้ทั้งหมดก่อนที่คุณจะจำเป็นต้องใช้ ให้เรียกใช้ `mise install --include-lazy` ซึ่งรวมถึงเครื่องมือ CLI เริ่มต้นอื่น ๆ ของ Omarchy ด้วยเช่นเดียวกับ agent ดู [เครื่องมือ CLI ที่ติดตั้งไว้ล่วงหน้า](18-development-tools.md#preinstalled-cli-tools) สำหรับการติดตั้งเครื่องมือตัวเดียวหรือการใช้ตัวติดตั้งของคุณเอง

`grok` ถูกติดตั้งผ่านแพ็กเกจ `grok` แบบ first-party ของ mise ในลักษณะเดียวกับ `claude` และ `codex` เรียกใช้ `grok` หรือเลือกมันใต้ _Agent > Harness_ ข้ามตัวติดตั้งแบบ `curl | bash` บน x.ai ไปเลย เส้นทางนั้นจะวางสำเนาตัวที่สองไว้ใน `~/.grok/bin`, เพิ่มมันไว้ข้างหน้าบน `PATH` และเขียนทับ wrapper ของ Omarchy

`dsh` เปิด browser UI ของมันที่ `127.0.0.1:3080` โดยมีไดเรกทอรีที่เรียกใช้เป็น workspace เริ่มต้น browser UI ของมันไม่รับ prompt เริ่มต้น ดังนั้น `omarchy agent prompt` จะเปิดมันพร้อม prompt บน clipboard ของคุณให้วาง Omarchy เริ่มมันด้วย permission preset แบบ no-approval ของ DeepSeek DeepSeek Harness จะอัปโหลด session log ไปยัง DeepSeek เมื่อคุณใช้ official model API ของมัน; ปิดการทำงานนั้นได้ใต้ _Settings > General > Upload Session Log_ ใน browser UI ของมัน ข้อเสนอแนะที่คุณส่งให้มันก็จะถูกอัปโหลดไปพร้อมกับ session ด้วยเช่นกัน เว้นแต่คุณจะเริ่มมันด้วย `DSH_TELEMETRY_MODE=DISABLED`

### agent เริ่มต้น

เลือก agent เริ่มต้นของคุณด้วย `omarchy default agent <name>` หรือใต้ _Agent > Harness_ ใน Omarchy Menu (`Super + Space`) หาก agent นั้นยังไม่ได้ติดตั้ง การเลือกมันจะติดตั้งมันก่อน และมันยังจะได้ตัวเรียกใช้ของตัวเองใน app launcher ถัดจาก Agent ด้วย Omarchy ที่ติดตั้งใหม่จะเชิญชวนให้คุณตัดสินใจเลือกนี้ด้วยการแจ้งเตือนเพียงครั้งเดียว

การเลือก Claude ยังพยายามติดตั้ง browser extension ของมันสำหรับ Chromium, Chrome, Brave, Brave Origin และ Edge ด้วย การติดตั้ง extension นี้ใช้กับผู้ใช้ทุกคนและอาจขอรหัสผ่านระบบของคุณ; การยกเลิกหรือการติดตั้ง extension ที่ล้มเหลวก็ยังคงเลือกและเปิด Claude อยู่ดี รีสตาร์ทเบราว์เซอร์ของคุณ เปิดใช้งาน extension หากได้รับข้อความแจ้ง และลงชื่อเข้าใช้ Claude เพื่อเชื่อมต่อให้เสร็จสมบูรณ์ เรียกใช้ `/chrome` ใน Claude เพื่อตรวจสอบการเชื่อมต่อ Firefox และ Zen ไม่รองรับ extension นี้ หาก Claude เคยเป็นค่าเริ่มต้นของคุณอยู่แล้วก่อนที่จะมีการเพิ่มการติดตั้งนี้เข้ามา ให้เลือกมันอีกครั้งเพื่อติดตั้ง extension

เมื่อคุณเลือกแล้ว `Super + Shift + Ctrl + A` จะเปิด agent เริ่มต้นในหน้าต่าง terminal เฉพาะ (หรือแสดงตัวเลือกหากคุณยังไม่ได้เลือก) คุณยังเปิดมันให้ทำงานทันทีได้ด้วย `omarchy agent prompt "Review this project"` Freebuff และ DeepSeek Harness ไม่รับ prompt เริ่มต้น ดังนั้นพวกมันจะเปิดพร้อม prompt บน clipboard ของคุณให้วางแทน agent ที่เปิดด้วยวิธีนี้จะทำงานโดยไม่มีคนดูแลในโหมด don't-stop-to-ask ของแต่ละตัว ดังนั้นเตรียมตัวให้พร้อมสำหรับพวกมันที่จะลงมือทำสิ่งต่าง ๆ จริง ๆ! MiniMax Code ไม่มีโหมดดังกล่าวสำหรับ interactive session ของมัน ดังนั้นมันจะขอสิทธิ์ตามปกติ และเนื่องจาก agent ปฏิเสธที่จะจดจำความไว้วางใจสำหรับ home directory ของคุณ การเปิดจาก `$HOME` จะเริ่มใน `~/Work` แทน

ยังมีทางลัดใน terminal ด้วย: `a` เรียกใช้ agent เริ่มต้นแบบ inline ใน terminal ปัจจุบัน ขณะที่ `c`, `cx` และ `cy` เริ่ม OpenCode, Claude Code และ Codex โดยตรง (ในโหมดอนุมัติอัตโนมัติของพวกมันอีกเช่นกัน) การเปลี่ยนธีมก็ซิงค์ไปยัง agent ด้วย: Claude Code, Pi, OpenCode และ Hermes (เมื่อ Omarchy ติดตั้งมันแล้ว) ล้วนเปลี่ยนตามเมื่อคุณสลับธีมของ Omarchy

### คำสั่งสำหรับ agent ของคุณ

กฎส่วนตัวสำหรับทุก agent ให้ใส่ไว้ใน `~/.agents/AGENTS.md` ถัดจาก shared skills ใน `~/.agents/skills` เปิดมันใต้ _Agent > Instructions_ ซึ่งยังเชื่อมโยงมันเข้าไปในแต่ละ harness ที่เก็บไฟล์ global ของตัวเองไว้ด้วย: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` ของ Copilot และอื่น ๆ Crush และ Amp อ่านลิงก์ `~/.config/AGENTS.md` ขณะที่ omp, Kimi และ DeepSeek Harness อ่าน `~/.agents/AGENTS.md` โดยตรง การเลือก agent เริ่มต้นก็จะเชื่อมโยงมันด้วยเช่นกัน ไฟล์คำสั่งที่คุณมีอยู่แล้วจะกลายเป็นไฟล์ที่ใช้ร่วมกันหากยังไม่มีไฟล์ดังกล่าวอยู่ มิฉะนั้นมันจะถูกเก็บไว้ข้างลิงก์ในชื่อ `.bak` เรียกใช้ `omarchy agent instructions` เพื่อเชื่อมโยงใหม่หลังจากติดตั้ง agent อีกตัว

### แผง agent

แถบบนสุดมีไอคอน agent ก่อนที่คุณจะตั้งค่า agent แผงของมันจะแนะนำคุณตลอดการลงชื่อเข้าใช้ Claude, Codex หรือ Grok และตัวแรกจะกลายเป็น agent เริ่มต้นของคุณ หลังจากนั้น แผงจะรวมทุกการสมัครสมาชิกไว้ในหน้าเดียว: แต่ละ agent และบัญชีพร้อมแผนของมัน มิเตอร์สำหรับขีดจำกัด session 5 ชั่วโมงและขีดจำกัดรายสัปดาห์แต่ละอย่างพร้อมเวลาจนกว่าจะรีเซ็ต (วางเมาส์เหนือเพื่อดูเปอร์เซ็นต์ที่แน่นอน) หรือยอดเงินแบบ prepaid ที่เหลือ ใต้บรรทัดที่หมุนเวียนแสดงสิ่งที่คุณใช้ไปในทุกตัว เช่น token ในสัปดาห์นี้และโมเดลที่คุณใช้มากที่สุด ใต้ _Make something cool_ มันเสนอ prompt เริ่มต้นสำหรับธีม, plugin, แอป หรือเกมใหม่ ที่มอบงานให้ agent เริ่มต้นของคุณ แอปถูกสร้างในแบบเดียวกับ Hype, Monologue และ Omacut ของ Omarchy เอง ใน C++ และ Qt Quick โดยทำตาม agent skill ชื่อ omarchy-make-app และ compiler และชิ้นส่วน Qt ที่พวกมันต้องการก็ติดตั้งมาให้แล้ว เกมเป็นหน้า three.js หน้าเดียวใน `~/Games/vibes` โดยทำตาม agent skill ชื่อ omarchy-make-game และทั้งหมดเปิดจากตัวเรียกใช้ Game Vibes ตัวเดียวในธีมปัจจุบัน; พวกมันโหลด three.js จากเว็บ ดังนั้นพวกมันจึงต้องการการเชื่อมต่อเพื่อเริ่ม Claude Code, Codex, Grok, Kimi, Cursor และสิทธิ์ Grok Bot ของมัน, GitHub Copilot, Muse, Antigravity และ Devin ได้รับการครอบคลุมมาตั้งแต่ต้นพร้อมขีดจำกัดของพวกมัน, Kimchi พร้อมแผน, เครดิตแบบ prepaid และงบการใช้จ่ายของมัน และ Hermes, Mistral Vibe และ Qwen Code จะแสดง session และ token ของพวกมันเมื่อคุณได้ใช้งานพวกมันแล้ว แผนและ key ของผู้ให้บริการที่คุณใช้ผ่าน pi, omp หรือ opencode ก็จะปรากฏขึ้นด้วย: OpenCode Zen และ Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan และ Synthetic พร้อมขีดจำกัดของพวกมัน; OpenRouter และ DeepSeek พร้อมยอดเงินแบบ prepaid ของพวกมัน; Fireworks พร้อมการใช้จ่ายในช่วง 30 วันที่ผ่านมา token จากโมเดลที่คุณรันบนฮาร์ดแวร์ของคุณเองก็นับรวมในยอดรวมด้วย; ตัวโมเดลเองก็มีแผงของตัวเอง ซึ่งอธิบายไว้ใต้ [Local models](#local-models) ทุก agent ถูกนับเพียงครั้งเดียว ใต้ผู้ที่เรียกเก็บเงินจากมัน ไม่ว่าคุณจะขับเคลื่อนมันผ่าน harness กี่ตัวก็ตาม

คลิกซ้ายที่ไอคอนบนแถบหรือกด `Super + Ctrl + X` เพื่อเปิดแผง คลิกขวาเพื่อเปิด agent เริ่มต้นของคุณ และคลิกกลางเพื่อรีเฟรช บันทึกการใช้งานที่อยู่เบื้องหลังมันจะถูกสร้างใหม่ทุก 15 นาทีโดย `omarchy agent usage update` และแผงยังสามารถรวมการใช้งานจากเครื่องอื่น ๆ ของคุณผ่านโฟลเดอร์ที่ซิงค์กันได้ ดู README ใต้ `$OMARCHY_PATH/shell/plugins/agents/` สำหรับการตั้งค่าแบบเต็ม

### การสมัครสมาชิกหลายรายการ

หากคุณจ่ายเงินสำหรับแผน Claude, Codex หรือ Grok มากกว่าหนึ่งแผน — เช่น Max ส่วนตัวและอีกแผนสำหรับงาน — Omarchy สามารถให้ทุกแผนลงชื่อเข้าใช้อยู่และย้ายไปมาระหว่างพวกมันได้ เพิ่มการสมัครสมาชิกด้วยเครื่องหมาย + ในแผง agent ซึ่งจะแนะนำคุณตลอดขั้นตอนตรงนั้นเลย หรือด้วย `omarchy agent account add claude Work` (หรือ `codex` หรือ `grok`) มันจะติดตั้ง CLI หากยังไม่มี บัญชีแรกสำหรับผู้ให้บริการรายหนึ่งจะลงชื่อเข้าใช้ผ่านเบราว์เซอร์ปกติของคุณ ตรงตำแหน่งที่ CLI มองหาเสมอ ทุกบัญชีหลังจากนั้นจะลงชื่อเข้าใช้ผ่านหน้าต่างส่วนตัว ดังนั้นบัญชีที่เบราว์เซอร์ของคุณลงชื่อเข้าใช้อยู่แล้วจะไม่ถูกหยิบขึ้นมาโดยไม่ตั้งใจ; ลงชื่อเข้าใช้ที่นั่นในฐานะบัญชีที่คุณกำลังเพิ่ม และปิดหน้าต่างส่วนตัวใด ๆ ที่คุณเปิดอยู่ก่อน อย่าออกจากระบบของ CLI เพื่อทำสิ่งนี้เด็ดขาด: การออกจากระบบจะเพิกถอนการลงชื่อเข้าใช้ที่บันทึกไว้ และบัญชีนั้นจะต้องถูกเพิ่มใหม่อีกครั้ง

หากต้องการคัดลอกการเข้าสู่ระบบการสมัครสมาชิกของคุณไปยังเครื่อง Omarchy อีกเครื่องผ่าน SSH ให้เรียกใช้ `omarchy agent account copy user@laptop` ผู้ส่งจะจัดเตรียมตัวรับชั่วคราวให้เมื่อปลายทางยังไม่มีตัวรับติดตั้งไว้ ดังนั้นเครื่อง Omarchy รุ่นเก่ากว่าจึงสามารถรับบัญชีได้โดยไม่ต้องอัปเดต ตัวรับที่ติดตั้งไว้จะมีความสำคัญเหนือกว่า สิ่งนี้จะคัดลอกการสมัครสมาชิก Claude, Codex และ Grok ทั้งหมด; เพิ่มชื่อผู้ให้บริการเพื่อเลือกพวกมัน เช่นใน `omarchy agent account copy laptop claude` ชื่อบัญชีและ ID คำสั่งจะตรงกับต้นทาง รวมถึงบัญชีที่มีอยู่แล้วบนปลายทาง บัญชีปลายทางที่ไม่เกี่ยวข้องจะได้รับส่วนต่อท้ายเป็นตัวเลขหากชื่อของพวกมันขัดกัน และการตั้งค่า, skills, plugins และประวัติการสนทนาจะยังคงอยู่เฉพาะเครื่องของแต่ละเครื่อง

ข้อมูลประจำตัวปลายทางที่มีอยู่จะถูกเก็บไว้ บัญชีต้นทางที่ลงชื่อเข้าใช้อยู่ที่นั่นแล้วจะมีชื่อของมันถูกซิงค์โดยไม่แทนที่ข้อมูลประจำตัวของมัน; บัญชีอื่น ๆ จะถูกเพิ่มควบคู่ไปกับมัน หากต้องการแทนที่ข้อมูลประจำตัวที่บันทึกไว้สำหรับบัญชีที่ตรงกัน ให้ใช้ `omarchy agent account copy --replace laptop claude` หลังจากออกจาก session ของบัญชีนั้นบนปลายทาง ปลายทางใหม่ยังจะได้รับบัญชีที่ใช้งานอยู่และการตั้งค่าการสลับของต้นทางด้วย; ปลายทางที่ใช้งานมานานแล้วจะเก็บของตัวเองไว้

ข้อมูลประจำตัวเดินทางผ่าน SSH และถูกเก็บไว้ในไฟล์ส่วนตัวบนปลายทาง ดังนั้นจงคัดลอกไปยังเครื่องที่คุณไว้วางใจเท่านั้น นี่เป็นการคัดลอกเพียงครั้งเดียว ไม่ใช่การซิงโครไนซ์อย่างต่อเนื่อง Codex refresh token อาจถูกหมุนเวียนโดยเครื่องอื่น ทำให้การเข้าสู่ระบบที่คัดลอกมาต้องต่ออายุ; การลงชื่อเข้าใช้แยกกันยังคงเป็นตัวเลือกที่เชื่อถือได้มากที่สุดสำหรับการใช้งานพร้อมกันบนหลายเครื่อง ดู [คำแนะนำการยืนยันตัวตนบัญชีของ Codex](https://developers.openai.com/codex/auth/ci-cd-auth)

หนึ่งบัญชีต่อผู้ให้บริการหนึ่งรายจะใช้งานอยู่ และทุก session ใหม่จะเริ่มเป็นบัญชีนั้น: `cx`, `cy`, `claude`, `codex` หรือ `grok` ธรรมดา, อะไรก็ตามที่เปิดผ่าน `omarchy agent` และสคริปต์หรือ editor ที่พบ CLI บน `PATH` สลับด้วย `omarchy agent account use work` (และกลับด้วย `omarchy agent account use main`) หรือในแผงโดยกดหมายเลขของบัญชีแล้วกด `Enter` (หรือคลิกปุ่ม Use ของมัน) session ของ Claude ที่กำลังทำงานอยู่ก็จะสลับด้วย ตั้งแต่ข้อความถัดไปของพวกมัน: ทุก session ของ Claude ทำงานใน `~/.claude` ซึ่งเก็บการลงชื่อเข้าใช้ของบัญชีที่ใช้งานอยู่เสมอ session ของ Claude ที่เริ่มในโฟลเดอร์ของบัญชีเองโดย Omarchy รุ่นเก่ากว่าจะเก็บการลงชื่อเข้าใช้นั้นไว้จนกว่ามันจะออก ดังนั้นการสลับจะระบุชื่อ session เหล่านั้นและจะเสร็จสิ้นด้วยตัวเองเมื่อพวกมันหายไป session ของ Codex และ Grok ที่กำลังทำงานอยู่จะยังคงอยู่กับบัญชีที่พวกมันเริ่มด้วย ประวัติการสนทนา, การตั้งค่า, skills และ plugins ถูกใช้ร่วมกันข้ามบัญชี ดังนั้น `claude --continue` ในโฟลเดอร์เดียวกันจะดำเนินการต่อจากจุดที่คุณค้างไว้บนบัญชีใหม่

เมื่อมีมากกว่าหนึ่งบัญชี แผงจะแสดงขีดจำกัดของแต่ละบัญชีเคียงข้างกัน โดยบัญชีที่ใช้งานอยู่จะถูกทำเครื่องหมายไว้ Omarchy จะแจ้งเตือนคุณเมื่อบัญชีที่ใช้งานอยู่ใช้เกิน 95% ของขีดจำกัด และการคลิกการแจ้งเตือนจะสลับไปยังบัญชีที่มีพื้นที่เหลือมากที่สุด มันจะไม่สลับด้วยตัวเอง เปลี่ยนเกณฑ์ได้ด้วย `omarchy agent account threshold 90` หากทุกบัญชีเกินเกณฑ์ คุณจะได้รับการแจ้งเพียงครั้งเดียว พร้อมกับว่าบัญชีใดจะว่างขึ้นก่อน ขณะที่บัญชีที่ใช้งานอยู่ภายใน 15 จุดจากเกณฑ์ของมัน (80% ที่ค่าเริ่มต้น) ขีดจำกัดของมันจะถูกตรวจสอบทุกสามนาทีแทนที่จะเป็นทุก 15 นาที

`omarchy agent account list` แสดงทุกบัญชีและขีดจำกัดล่าสุดของพวกมัน, `omarchy agent account remove work` ลืมบัญชีหนึ่งบัญชี และ `omarchy agent account rename primary Hey` เปลี่ยนชื่อบัญชีหนึ่งบัญชี (หรือคลิกชื่อบัญชีในแผง) คำสั่งเหล่านี้ทำงานกับบัญชีของ agent เริ่มต้นของคุณ; หากต้องการเข้าถึงผู้ให้บริการรายอื่น ให้ระบุชื่อมันก่อน เช่นใน `omarchy agent account use codex side` การเข้าสู่ระบบที่คุณมีอยู่แล้วใน `~/.claude` หรือ `~/.codex` คือบัญชี _Main_ ของ Codex จะยังคงอยู่ที่เดิม; ของ Claude จะรออยู่ในโฟลเดอร์ของตัวเองในขณะที่บัญชีอื่นใช้งานอยู่ บัญชีที่ไม่ได้ใช้งานนานกว่าประมาณแปดชั่วโมงอาจแสดง _Sign-in required_; คลิกมันเพื่อลงชื่อเข้าใช้บัญชีนั้นอีกครั้งในแผงเลย หรือสลับไปยังมันและเริ่ม session ซึ่งจะรีเฟรชการลงชื่อเข้าใช้ด้วยตัวเอง MCP server ที่คุณเพิ่มด้วย `claude mcp add` จะเข้าถึงทุกบัญชี Claude เนื่องจากพวกมันทั้งหมดทำงานใน `~/.claude`; สำหรับ Codex และ Grok, server ที่คุณมีเมื่อบัญชีถูกเพิ่มเข้ามาจะตามไปยังบัญชีนั้นด้วย แต่ server ในภายหลังจะเข้าถึงเฉพาะบัญชีที่คุณเพิ่มพวกมันเข้าไปเท่านั้น Claude Desktop เก็บการลงชื่อเข้าใช้ของตัวเองไว้ และเครื่องมือ Codex หรือ Grok ที่กำหนดค่าด้วยเส้นทางสัมบูรณ์ไปยัง CLI binary จะไม่ตามการสลับไป `CLAUDE_CONFIG_DIR`, `CODEX_HOME` หรือ `GROK_HOME` ที่ระบุอย่างชัดเจนจะมีความสำคัญเหนือบัญชีที่เลือกไว้

### การวินิจฉัยการขัดข้อง

Omarchy เฝ้าดู systemd-coredump สำหรับการขัดข้องของ process เมื่อคุณเลือก agent เริ่มต้นแล้ว โปรแกรมใด ๆ ของคุณที่ dump core จะนำการแจ้งเตือน "Process crashed" มา — คลิกมัน และการขัดข้องจะถูกส่งให้ agent เริ่มต้นของคุณพร้อมกับ skill omarchy-diagnose-crash ของ Omarchy ซึ่งจะแนะนำ agent ตลอดการสร้างข้อเท็จจริงจาก core dump และการตัดสินใจว่าการขัดข้องนั้นคุ้มค่าที่จะรายงานไปยัง upstream หรือไม่ คุณยังเรียกใช้มันด้วยตนเองกับ PID ใด ๆ จาก `coredumpctl list` ได้ด้วย `omarchy agent crash <pid>`

การเฝ้าดูนี้เปิดอยู่เป็นค่าเริ่มต้น ปิดมันใต้ _Trigger > Toggle > Crash Capture Off_ (หรือด้วย `omarchy toggle crash-capture`) และการแจ้งเตือนจะหยุด; `omarchy agent crash <pid>` ยังคงทำงานด้วยตนเองได้

การขัดข้องยังสามารถปิดเสียงได้ทีละโปรแกรม ซึ่งเป็นสิ่งที่การวินิจฉัยเสนอให้คุณในตอนท้าย `omarchy crash mute hyprland` หยุดการแจ้งเตือนสำหรับโปรแกรมนั้นเท่านั้น, `omarchy crash mute hyprland off` นำพวกมันกลับมา และ `omarchy crash mute` ด้วยตัวมันเองเพียงอย่างเดียวจะแสดงรายการสิ่งที่คุณปิดเสียงไว้ มันรับเส้นทางของ binary ได้อย่างยินดีพอ ๆ กับชื่อของมัน ดังนั้น `omarchy crash mute /usr/bin/hyprland` จึงทำสิ่งเดียวกัน ใส่เครื่องหมายคำพูดชื่อที่มีช่องว่างในนั้น เช่นใน `omarchy crash mute 'Some App'` ทุกอย่างอื่นยังคงแจ้งเตือนอยู่ และโปรแกรมที่ปิดเสียงไว้ก็ยังคงขัดข้อง — สิ่งนี้ซ่อนตัวเตือนความจำ มันไม่ได้แก้ไขอะไรเลย

### แอปบน Desktop

เมนู _Install > AI_ ยังมีแอป AI แบบกราฟิกอยู่สองสามตัวด้วย: Amp Desktop, Antigravity Desktop, แอป ChatGPT บน Desktop, แอป Claude บน Desktop (รุ่น beta สำหรับ Linux ของ Anthropic, พร้อมแท็บ Chat, Cowork และ Claude Code), Grok Bot สำหรับแชทกับโมเดลของ xAI, Herdr Desktop, Hermes Desktop, OpenClaw, แอป Perplexity บน Desktop และ T3 Code Grok Bot คือแอปแชทบน Desktop ส่วน coding agent คือคำสั่ง `grok`

Hermes Desktop เป็นตัวที่ต้องรู้ไว้ เพราะเครื่องหนึ่งเครื่องมี Hermes เดียว และ Hermes นั้นเป็นของแอป: Hermes จะถูกติดตั้งผ่านแอปเท่านั้น และคำสั่ง `hermes` ที่ agent เริ่มต้นเรียกใช้ก็เป็นของแอป การเลือก Hermes เป็น agent เริ่มต้นจะติดตั้งสิ่งเดียวกับที่รายการ _Install > AI_ ติดตั้ง: แพ็กเกจ และ runtime ของ Hermes ใต้ `~/.hermes` ที่ติดตั้งโดยตัวติดตั้งของ Hermes เอง ซึ่งใช้เวลาสองสามนาทีในครั้งแรก runtime นั้นคือ Hermes ตัวเดียวที่คำสั่ง `hermes` ใน terminal, agent เริ่มต้น และแอปทั้งหมดใช้ และมันอัปเดตตัวเองด้วย `hermes update` แทนที่จะรอการออก Omarchy รุ่นใหม่ การติดตั้งมันยังมอบธีม Omarchy ให้ Hermes เป็น skin ชื่อ `omarchy` ซึ่งทุกพื้นผิวของ Hermes จะทำตามเมื่อคุณสลับธีม; เลือกอีกอันใต้การตั้งค่า Appearance ของ Hermes หรือด้วย `/skin` หากคุณไม่อยากให้มันทำแบบนั้น และ Omarchy จะปล่อยตัวเลือกนั้นไว้ตามเดิม การลบแอปใต้ _Remove > AI_ จะปิด Hermes ก่อน รวมถึง gateway, นำ runtime นั้นไปด้วย และเก็บแชท, ความทรงจำ และ skills ที่ Hermes เขียนให้ตัวเองไว้ เว้นแต่คุณจะบอกเป็นอย่างอื่น: มันจะถาม โดยค่าเริ่มต้นคือไม่ ว่าข้อมูลนั้นและการตั้งค่าการเชื่อมต่อของคุณควรจะไปด้วยหรือไม่

ประสบการณ์บน Desktop ของ OpenClaw คือ Control UI ของมัน ซึ่งเปิดเป็น web app ที่ได้รับการสนับสนุนโดย local gateway ของตัวเอง OpenClaw อาศัยอยู่ใน `~/.openclaw` และอัปเดตตัวเอง: ใช้ปุ่ม "Update Gateway" ของ Control UI หรือเรียกใช้ `openclaw update` และ gateway จะรีสตาร์ทบนรุ่นใหม่ Omarchy เลือกเฉพาะรุ่นที่การติดตั้งใหม่จะเริ่มต้นจากเท่านั้น OpenClaw ยังเป็น agent เริ่มต้นของคุณได้ด้วย: การเลือกมันใต้ _Agent > Harness_ จะติดตั้งสำเนาเดียวกันนั้นใน `~/.openclaw` และ agent จะเปิด terminal UI ของ OpenClaw ที่เชื่อมอยู่กับ gateway ของมัน การลบ OpenClaw ใต้ _Remove > AI_ จะนำ gateway service และแอปไปด้วย จากนั้นจะถามว่า `~/.openclaw` ควรจะไปด้วยหรือไม่ เนื่องจากที่นั่นเก็บแชทและข้อมูลประจำตัวของคุณไว้ควบคู่กับตัว OpenClaw เองและ plugin runtime ที่มันดาวน์โหลด; ค่าเริ่มต้นคือเก็บมันไว้ และการติดตั้ง OpenClaw อีกครั้งจะหยิบมันกลับมา

Herdr Desktop คือแอป [Herdr](https://herdr.dev) บน Desktop: spaces, tabs และ panes ของ terminal และ coding agent ที่ยังคงทำงานอยู่ใน core ของมันเมื่อคุณปิดหน้าต่าง มันมาจากตัวติดตั้งของ Herdr เองแทนที่จะเป็นแพ็กเกจ ดังนั้นมันจึงอาศัยอยู่ใน `~/.local/share/herdr-app`, นำ core ของมันมาด้วยใน `~/.local/bin/herdr-core` เมื่อคุณยังไม่มี และอัปเดตทั้งสองอย่างด้วยตัวเอง มันอยู่ข้างคำสั่ง `herdr` ที่ Omarchy จัดส่งมาด้วยบน `Super + Ctrl + Return` แทนที่จะแทนที่มัน และได้รับปุ่มโดยตรงของคำสั่งนั้น: `Alt + Return` และ `Alt + Shift + Return` แยก pane ลงหรือไปทางขวา, `Alt + Escape` ปิดมัน, `Ctrl + Alt + Arrow` ย้ายระหว่าง panes, `Alt + 1..9` และ `Alt + Left/Right` เลือกแท็บ และ `Alt + Up/Down` ย้ายระหว่าง spaces `Ctrl + 1..9` เลือก space และ `Alt + Shift + Up/Down` ก้าวผ่าน agent ปุ่มนำหน้าแบบ `Ctrl + Space` ยังคงเป็นของ terminal เท่านั้น เนื่องจากแอปไม่สามารถถือปุ่ม Ctrl ธรรมดาไว้สำหรับลำดับได้ Omarchy เขียนสิ่งเหล่านี้ไปยัง `~/.config/herdr-app/keys.json` และ `omarchy-refresh-herdr-app` นำพวกมันกลับมา การติดตั้งมันจะเลือกธีม Omarchy ของ Herdr ซึ่งจะทำตามธีม Omarchy ของคุณต่อจากนั้น Herdr เก็บธีมหนึ่งสำหรับโหมดสว่างและอีกธีมสำหรับโหมดมืด ดังนั้นหลังจากสลับระหว่างธีม Omarchy แบบมืดและแบบสว่างแล้ว ให้เลือก Omarchy ในตัวเลือกธีมของ Herdr อีกครั้งสำหรับอีกโหมด

T3 Code ทำงานจากรุ่น AppImage อย่างเป็นทางการใน `~/.local/share/t3code` แทนที่จะมาจากแพ็กเกจ ดังนั้นมันจึงอัปเดตตัวเอง การติดตั้งมันจะถามว่าจะเริ่มบนช่อง Stable หรือ Nightly; สลับในภายหลังได้ในการตั้งค่าของ T3 Code thread และการตั้งค่าของคุณอาศัยอยู่ใน `~/.t3` และการลบ T3 Code ใต้ _Remove > AI_ จะนำพวกมันไปด้วย

### โมเดลแบบ Local

รันโมเดลแบบเปิดบนเครื่องของคุณเองสำหรับ coding agent ของคุณ prompt และโค้ดของคุณยังคงอยู่บนเครื่อง; ไม่มีอะไรที่ส่งไปยังโมเดลออกจากเครื่อง เริ่มด้วย:

```bash
omarchy models use best text
```

นั่นจะติดตั้งโมเดลข้อความที่ดีที่สุดสำหรับเครื่องนี้ ซึ่งเป็นประเภทที่ agent ของคุณใช้ โมเดลภาพ, วิดีโอ และเพลงก็มีตัวที่ดีที่สุดของตัวเองเช่นกัน: `omarchy models use best image`, `video` หรือ `music` เรียกใช้ `omarchy models use best` เพื่อดูตัวเลือกของแต่ละประเภทสำหรับเครื่องนี้

หรือเปิดแผง local models จากไอคอนประกายของมันในแถบบนสุด ถัดจากไอคอน agent หรือด้วย Super + Ctrl + Alt + X แล้วเลือก + ไอคอนจะปรากฏขึ้นเมื่อมีโมเดลที่พอดีกับเครื่องนี้ Podman ซึ่งรันโมเดล มาพร้อมกับ Omarchy เช่นเดียวกับ container toolkit ของ NVIDIA บนเครื่อง NVIDIA ซึ่งให้ GPU แก่พวกมัน; หากตัวใดตัวหนึ่งขาดไป การติดตั้งครั้งแรกจะติดตั้งมัน จากนั้น Omarchy จะเลือกโมเดลที่แนะนำสำหรับเครื่องนี้ ดาวน์โหลดมัน และเริ่มมัน คาดว่าจะมีการดาวน์โหลดขนาดหลายสิบ GB และหน่วยความจำส่วนใหญ่ของเครื่องจะถูกใช้งานในขณะที่โมเดลทำงาน: Flash Next ใช้ประมาณ 100 GiB กับ context แบบเต็ม 256K ของมัน หากโมเดลอื่นถือครองหน่วยความจำที่มันต้องการ มันจะถูกติดตั้งไว้ในสถานะหยุด พร้อมที่จะเริ่มเมื่อคุณหยุดอีกตัวหนึ่ง โมเดลจะหยุดเมื่อออกจากระบบ; หยุดมันด้วยตัวเองเมื่อคุณต้องการหน่วยความจำสำหรับอย่างอื่น

`omarchy models list` แสดงตัวเลือกและอธิบายว่าทำไมบางตัวจึงไม่พอดี หากต้องการติดตั้งอีกตัว ให้เรียกใช้ `omarchy models use <recipe>` ปัจจุบัน, `qwen3.8-flash-next-gufo` และ `qwen3.8-27b-gufo` มีให้สำหรับเครื่อง Strix Halo ขนาด 128 GB; ตัว 27B ใช้ประมาณ 40 GiB ดังนั้นมันจึงเหลือพื้นที่สำหรับงานอื่น บนแล็ปท็อปขนาด 64 GB ที่มี Intel's Arc B390, `qwen3.6-35b-a3b-llamacpp` ทำงานในประมาณ 30 GiB recipe และคำแนะนำใหม่ ๆ มาพร้อมกับ `omarchy update` ผ่านแพ็กเกจ

ทุกโมเดลที่คุณติดตั้งจะมีบรรทัดของตัวเองในแผง local models: เล่นเพื่อเริ่มมัน, หยุดชั่วคราวเพื่อหยุดมันและปลดปล่อยหน่วยความจำของมัน และปุ่ม terminal เพื่อเปิด agent ของคุณบนมัน ข้ามด้านบน แถบหนึ่งแสดงให้เห็นว่าหน่วยความจำของเครื่องถูกแบ่งระหว่างตัว Omarchy เอง (ระบบและแอปของคุณ), แต่ละโมเดลที่กำลังทำงาน และสิ่งที่ว่างอยู่ อย่างไร ชี้ไปที่โมเดลที่หยุดแล้วและแถบจะแสดงว่ามันพอดีหรือไม่ หรือมันขาดไปเท่าไหร่ หลายตัวสามารถทำงานพร้อมกันได้เมื่อพวกมันพอดีในหน่วยความจำด้วยกัน; หากตัวหนึ่งไม่พอดี Omarchy จะบอกว่าโมเดลที่กำลังทำงานตัวใดให้หยุด ลากบรรทัดด้วยโลโก้ของพวกมันเพื่อจัดเรียงใหม่ และกด Delete บนบรรทัดที่เลือกเพื่อลบโมเดลและไฟล์ดาวน์โหลดของมัน

ทุกโมเดลสำหรับ coding ที่คุณติดตั้งยังได้รับรายการของตัวเองใน app launcher ใต้ชื่อของโมเดลและพร้อมโลโก้ของผู้สร้างมัน ในลักษณะเดียวกับการลงชื่อเข้าใช้ Claude, Codex หรือ Grok จะเพิ่มอีกตัว มันเปิด agent ของคุณบนโมเดลนั้น และเริ่มโมเดลก่อนหากมันยังไม่ได้ทำงาน: terminal จะแสดงมันกำลังโหลดและส่งมอบให้ agent เมื่อมันพร้อม การลบโมเดลจะลบรายการของมัน

ไม่ใช่ทุกโมเดลสำหรับ coding โมเดลภาพ, วิดีโอ และเพลงจะเปิดใน Fantasi แทน ซึ่งเป็นแอปของ Omarchy สำหรับสร้างภาพ, วิดีโอ และเพลงด้วยโมเดลที่ทำงานบนเครื่องนี้ โดยเลือกที่นั่นหรือจากบรรทัดของพวกมันในแผง local models

โมเดลยังคงทำงานต่อไปอย่างที่มันถูกติดตั้งไว้ ดังนั้นการอัปเดต Omarchy จะไม่รีสตาร์ทโมเดลใต้ agent ของคุณ เมื่อ Omarchy มี runtime รุ่นใหม่กว่าหรือน้ำหนักรุ่นใหม่กว่าสำหรับโมเดลที่คุณติดตั้งไว้ บรรทัดของมันจะแสดงปุ่มอัปเดต: กดมันและโมเดลจะถูกติดตั้งใหม่อีกครั้งในเบื้องหลัง โดยดาวน์โหลดเฉพาะสิ่งที่เปลี่ยนแปลง และรีสตาร์ทบนรุ่นใหม่ โมเดลที่หยุดไว้จะยังคงหยุดอยู่ `omarchy models update` ทำสิ่งเดียวกันสำหรับทุกโมเดลจาก terminal

จากบรรทัดคำสั่ง, `omarchy models start <recipe>` และ `omarchy models stop <recipe>` ทำสิ่งเดียวกัน, `omarchy models status` แสดงทุกโมเดล และ `omarchy agent --local` เปิดโมเดลล่าสุดที่คุณเริ่มใน pi ไม่ว่า agent เริ่มต้นของคุณจะเป็นอะไร OpenCode และ Qwen Code สามารถใช้โมเดลแบบ local ได้ด้วย: `omarchy models harness opencode` หรือ `omarchy models harness qwen` เปิดพวกมันที่นั่นแทน และ `omarchy models harness pi` กลับไป pi ยังแสดงรายการทุกโมเดลที่คุณติดตั้งไว้ และโมเดลบนเครื่องที่คุณจับคู่ด้วย ในตัวเลือกโมเดลของตัวมันเอง ดังนั้น `pi` ธรรมดาจึงเข้าถึงพวกมันได้ด้วยเช่นกัน client ที่เข้ากันได้กับ OpenAI ตัวใดก็สามารถเชื่อมต่อได้ด้วย: `status` แสดงที่อยู่ของแต่ละโมเดล (ตัวแรกคือ `http://127.0.0.1:11435/v1`), ชื่อ recipe คือโมเดล และ key อยู่ใน `~/.config/omarchy/agent-local/key`

`omarchy models remove <recipe>` ลบโมเดลและไฟล์ดาวน์โหลดที่ไม่มีโมเดลอื่นใช้

runtime ของบุคคลที่สามจะถูกระบุด้วยชื่อผู้เผยแพร่ของพวกมัน Omarchy รันทุกโมเดลโดยไม่มีการเข้าถึงเครือข่าย

### Local LLMs

Omarchy แนะนำสองวิธีในการรันโมเดล LLM แบบ local: LM Studio และ Ollama LM Studio ให้ GUI interface สำหรับการค้นหาโมเดลแบบ open-weight, การติดตั้งพวกมัน และการรันพวกมัน เป็นวิธีที่ยอดเยี่ยมในการเริ่มต้นอย่างง่ายดาย Ollama เสนอ CLI สำหรับทำอย่างเดียวกันในลักษณะคล้ายกัน แต่หากคุณเพิ่งเริ่มใช้โมเดลแบบ local ผมขอแนะนำให้เริ่มด้วย LM Studio คุณสามารถติดตั้งอย่างใดอย่างหนึ่งใต้ _Install > AI_ ใน Omarchy Menu

### skills ของ Omarchy

Agent skills ช่วยให้ AI ใช้เครื่องมือเฉพาะในวิธีเฉพาะ และ Omarchy จัดส่งมาด้วยเจ็ดอย่าง skill ชื่อ omarchy ครอบคลุมการปรับแต่งระบบ เช่นการปรับแต่ง Hyprland config ของคุณหรือการปรับแถบ omarchy-make-theme, omarchy-make-plugin, omarchy-make-app และ omarchy-make-game ครอบคลุมการสร้างสิ่งใหม่, omarchy-contribute ครอบคลุมการรายงาน bug หรือการส่งการแก้ไขไปยัง upstream และ omarchy-diagnose-crash ทำงานผ่าน core dump ของการขัดข้อง พวกมันถูก symlink เข้าไปใน skill directories สำหรับ Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` และแต่ละ `~/.hermes/profiles/*/skills`) และตำแหน่งทั่วไป `~/.agents/skills` ดังนั้น harness ส่วนใหญ่จะหยิบพวกมันขึ้นมาโดยอัตโนมัติ โฟลเดอร์ skill ของคุณเองที่มีชื่อเดียวกันจะมีความสำคัญเหนือกว่า

แต่คุณควรปฏิบัติต่อ skills เหล่านี้ในฐานะการทดลอง โมเดลที่แตกต่างกันจะใช้มันให้เกิดผลที่แตกต่างกัน ทางที่ดีที่สุดคือรันใน plan mode ก่อน เพื่อให้คุณมีภาพว่า agent อยากจะเปลี่ยนแปลงอะไร จากนั้นเตรียมพร้อมที่จะ rollback การเปลี่ยนแปลง หรือแม้แต่การเรียกใช้ `omarchy reinstall configs` หาก agent ทำให้ทุกอย่างเละเทะ
