# การติดตั้งแบบไม่ต้องเฝ้า

Omarchy ISO สามารถติดตั้งตัวเองได้โดยไม่มีใครอยู่หน้าแป้นพิมพ์ หากตัวติดตั้งพบไดรฟ์ที่สองที่ติดป้าย `cidata` และมีไฟล์การกำหนดค่าของมันอยู่ มันจะคัดลอกไฟล์เหล่านั้นออกมา ข้ามตัวช่วยตั้งค่าไปทั้งหมด และรีบูตเข้าสู่ระบบที่เสร็จสมบูรณ์ด้วยตัวเอง ไม่ต้องใช้ ISO รุ่นพิเศษ ไม่ต้องมีรายการเมนูบูตเพิ่ม — หากไม่มีไดรฟ์ดังกล่าวเชื่อมต่ออยู่ ก็ไม่มีอะไรเปลี่ยนแปลง และคุณจะได้ตัวช่วยตั้งค่าแบบปกติ

สิ่งนี้ทำให้ Omarchy เหมาะอย่างยิ่งสำหรับใช้เป็นอิมเมจพื้นฐานสำหรับสภาพแวดล้อมการพัฒนาที่ใช้แล้วทิ้ง: สร้าง VM ใน Proxmox หรือด้วย Packer บูตมันขึ้นมา เดินจากไป แล้ว SSH เข้าไป `cidata` คือป้าย `NoCloud` ของ cloud-init ดังนั้นเครื่องมือ virtualization ทั่วไปทั้งหมดจึงรู้วิธีเชื่อมต่อไดรฟ์แบบนี้อยู่แล้ว

## ไฟล์การกำหนดค่า

ไฟล์เหล่านี้คือสิ่งที่ตัวช่วยตั้งค่าของตัวติดตั้งเขียนออกมาเองพอดี ดังนั้นวิธีที่ง่ายที่สุดในการได้ชุดเริ่มต้นคือทำการติดตั้งแบบโต้ตอบหนึ่งครั้ง (เช่นใน VM) แล้วคัดลอกสิ่งที่มันเขียนไว้ลงใน `/root`:

| File | Required | Purpose |
|------|----------|---------|
| `user_configuration.json` | ใช่ | ดิสก์, hostname, เขตเวลา, แป้นพิมพ์ |
| `user_credentials.json` | ใช่ | ชื่อผู้ใช้และแฮชของรหัสผ่าน และรหัสผ่าน LUKS สำหรับการติดตั้งแบบเข้ารหัส |
| `user_encrypt_installation.txt` | ไม่ | `true` เมื่อการกำหนดค่านั้นมีบล็อก `disk_encryption` |
| `authorized_keys` | ไม่ | กุญแจสาธารณะ SSH บรรทัดละหนึ่งรายการ |
| `tailscale_authkey` | ไม่ | กุญแจยืนยันตัวตน Tailscale สำหรับเข้าร่วม tailnet ของคุณในการบูตครั้งแรก |

สร้างแฮชของรหัสผ่านสำหรับ `user_credentials.json` ด้วย `openssl passwd -6 "yourpassword"`

ชื่อและอีเมลสำหรับ git commits ไม่ได้เป็นส่วนหนึ่งของการติดตั้ง ตั้งค่าเหล่านั้นเมื่อเครื่องพร้อมใช้งานแล้ว เช่น ผ่าน SSH ด้วย `omarchy setup git --name "Jane Doe" --email jane@example.com`

คุณยังสามารถวางไฟล์ว่างชื่อ `defer-provisioning` แทนที่ `user_credentials.json` ได้ด้วย นั่นจะทำการ[ติดตั้งแบบเตรียมไว้ให้เจ้าของคนอื่น](02-getting-started.md)แบบเดียวกันกับที่คุณเรียกใช้แบบโต้ตอบได้: เครื่องจะติดตั้งโดยไม่มีรายละเอียดส่วนตัวใด ๆ และใครก็ตามที่บูตเครื่องเป็นคนแรกจะเป็นผู้เลือกแป้นพิมพ์และสร้างผู้ใช้ของตัวเอง นั่นคือโหมดสำหรับแท่นทำอิมเมจ ที่ไดรฟ์ไม่ควรมีข้อมูลประจำตัวของใครเลย

## การเข้าถึงผ่าน SSH

เมื่อมี `authorized_keys` อยู่ การติดตั้งจะตั้งค่ากุญแจเหล่านั้นเป็น `~/.ssh/authorized_keys` ของผู้ใช้ เปิดใช้งาน `sshd` และเปิดไฟร์วอลล์ให้มัน (การติดตั้ง Omarchy แบบมาตรฐานจะมาพร้อม openssh ที่ปิดใช้งานบริการไว้และปิดพอร์ตไว้ ดังนั้นเครื่องแบบไม่ต้องเฝ้าจึงจะเข้าถึงไม่ได้หากไม่มีสิ่งนี้) การติดตั้งเพียงเพิ่มกุญแจของคุณเท่านั้น — มันไม่ได้ผ่อนคลายการตั้งค่าการยืนยันตัวตนอื่นใดของ SSH daemon เลย

เมื่อมี `tailscale_authkey` อยู่ เครื่องจะเข้าร่วม tailnet ของคุณในการบูตครั้งแรกแทน: Tailscale จะติดตั้งจากแพ็กเกจที่รวมอยู่ใน ISO ไฟร์วอลล์จะอนุญาตอินเทอร์เฟซ tailnet และงานพื้นหลังจะดำเนินการเข้าร่วมทันทีที่เครื่องมีเครือข่ายจริง โดยจะลองใหม่ไปเรื่อย ๆ จนกว่าจะสำเร็จ ใช้กุญแจแบบใช้ซ้ำได้และที่ได้รับอนุญาตล่วงหน้า เพื่อให้อิมเมจไดรฟ์หนึ่งชุดสามารถใช้กับเครื่องจำนวนมากได้

## การสร้างไดรฟ์ cidata

ระบบไฟล์ใด ๆ ที่มีป้ายถูกต้องก็ใช้ได้ ISO ขนาดเล็กคือวิธีที่ง่าย:

```bash
mkdir cidata
cp user_configuration.json user_credentials.json authorized_keys cidata/
genisoimage -output cidata.iso -volid cidata -joliet -rock cidata/
```

จากนั้นเชื่อมต่อมันเข้ากับ VM พร้อมกับ Omarchy ISO นี่คือตัวอย่างเต็มสำหรับ Proxmox:

```bash
qm create 101 --name my-omarchy \
  --bios ovmf --machine q35 --cpu host --cores 4 --memory 8192 \
  --ostype l26 --scsihw virtio-scsi-single \
  --efidisk0 local-lvm:0,efitype=4m,pre-enrolled-keys=0 \
  --scsi0 local-lvm:40,discard=on,iothread=1 \
  --net0 virtio,bridge=vmbr0 --vga virtio --serial0 socket \
  --ide2 local:iso/omarchy.iso,media=cdrom \
  --ide3 local:iso/cidata.iso,media=cdrom \
  --boot order='scsi0;ide2'

qm start 101
```

ลำดับการบูตจงใจระบุให้ดิสก์อยู่ก่อน: ดิสก์เปล่าจะตกลงไปบูตจาก ISO ในการบูตครั้งแรก และระบบที่ติดตั้งแล้วจะบูตจากดิสก์ตลอดไปหลังจากนั้น

## ข้อควรระวังสองข้อ

การติดตั้งแบบเข้ารหัสโดยไม่ต้องเฝ้า ไม่ได้ไม่ต้องเฝ้าอย่างสมบูรณ์ — ยังต้องมีใครสักคนพิมพ์รหัสผ่าน LUKS ในการบูตครั้งแรก และรหัสผ่านนั้นอยู่ในระดับบนสุดของ `user_credentials.json` ในชื่อ `encryption_password` — archinstall อ่านมันจากตรงนั้น ไม่ได้อ่านจากบล็อก `disk_encryption` ใน `user_configuration.json` — ดังนั้นจงปฏิบัติต่อไดรฟ์ cidata ที่สร้างจากการติดตั้งแบบเข้ารหัสราวกับว่ามันเป็นความลับตามที่มันเป็นจริง ๆ
