# การติดตั้งแบบไม่มีผู้ดูแล

ISO ของ Omarchy สามารถติดตั้งตัวเองได้โดยไม่มีใครอยู่ที่แป้นพิมพ์ หากโปรแกรมติดตั้งพบไดรฟ์ที่สองที่มีป้ายชื่อ `cidata` และมีไฟล์การกำหนดค่าของมันอยู่ โปรแกรมจะคัดลอกไฟล์เหล่านั้นออกมา ข้ามวิซาร์ดการตั้งค่าไปทั้งหมด และรีบูตเข้าสู่ระบบที่เสร็จสมบูรณ์ด้วยตัวเอง ไม่ต้องสร้าง ISO แบบพิเศษ ไม่ต้องมีรายการเมนูบูตเพิ่มเติม — หากไม่มีไดรฟ์ดังกล่าวเชื่อมต่ออยู่ ก็ไม่มีอะไรเปลี่ยนแปลง และคุณจะได้วิซาร์ดตามปกติ

สิ่งนี้ทำให้ Omarchy เหมาะอย่างยิ่งในการใช้เป็นอิมเมจพื้นฐานสำหรับสภาพแวดล้อมการพัฒนาที่ใช้แล้วทิ้ง: สร้าง VM ใน Proxmox หรือด้วย Packer บูตมัน เดินออกไป แล้ว SSH เข้าไป `cidata` คือป้ายชื่อ `NoCloud` ของ cloud-init ดังนั้นเครื่องมือ virtualization ทั่วไปทั้งหมดจึงรู้วิธีเชื่อมต่อไดรฟ์ดังกล่าวอยู่แล้ว

## ไฟล์การกำหนดค่า

ไฟล์เหล่านี้คือสิ่งที่วิซาร์ดของโปรแกรมติดตั้งเองเขียนออกมาทุกประการ ดังนั้นวิธีที่ง่ายที่สุดในการได้ชุดเริ่มต้นคือทำการติดตั้งแบบโต้ตอบหนึ่งครั้ง (ใน VM เป็นต้น) แล้วคัดลอกสิ่งที่มันเขียนไว้ใน `/root`:

| File | Required | Purpose |
|------|----------|---------|
| `user_configuration.json` | Yes | Disk, hostname, timezone, keyboard |
| `user_credentials.json` | Yes | Username and password hash |
| `user_encrypt_installation.txt` | No | `true` when the configuration carries a `disk_encryption` block |
| `authorized_keys` | No | SSH public keys, one per line |
| `tailscale_authkey` | No | Tailscale auth key for joining your tailnet on first boot |

สร้างแฮชของรหัสผ่านสำหรับ `user_credentials.json` ด้วย `openssl passwd -6 "yourpassword"`

ชื่อและอีเมลสำหรับ git commits ไม่ได้เป็นส่วนหนึ่งของการติดตั้ง ตั้งค่าเหล่านั้นเมื่อเครื่องพร้อมใช้งานแล้ว เช่น ผ่าน SSH ด้วย `omarchy setup git --name "Jane Doe" --email jane@example.com`

คุณยังสามารถใส่ไฟล์ว่างชื่อ `defer-provisioning` แทน `user_credentials.json` ได้อีกด้วย นั่นจะรันการติดตั้งแบบ[เตรียมไว้สำหรับเจ้าของอีกคน](02-getting-started.md)แบบเดียวกับที่คุณสามารถเรียกใช้แบบโต้ตอบได้: เครื่องจะติดตั้งโดยไม่มีรายละเอียดส่วนบุคคลใด ๆ และใครก็ตามที่บูตมันเป็นคนแรกจะเลือกแป้นพิมพ์ของตนและสร้างผู้ใช้ของตน นั่นคือโหมดสำหรับเครื่อง imaging rigs ซึ่งไดรฟ์ไม่ควรมีข้อมูลประจำตัวของใครเลย

## การเข้าถึงผ่าน SSH

เมื่อมี `authorized_keys` อยู่ การติดตั้งจะตั้งค่าคีย์เหล่านั้นเป็น `~/.ssh/authorized_keys` ของผู้ใช้ เปิดใช้งาน `sshd` และเปิดไฟร์วอลล์ให้กับมัน (การติดตั้ง Omarchy แบบมาตรฐานมาพร้อมกับ openssh ที่บริการถูกปิดใช้งานและพอร์ตถูกปิด ดังนั้นเครื่องที่ไม่มีผู้ดูแลจะไม่สามารถเข้าถึงได้เลยหากไม่มีสิ่งนี้) การติดตั้งเพียงเพิ่มคีย์ของคุณเท่านั้น — มันไม่ได้ผ่อนปรนการตั้งค่าการยืนยันตัวตนอื่น ๆ ของ SSH daemon แต่อย่างใด

เมื่อมี `tailscale_authkey` อยู่ เครื่องจะเข้าร่วม tailnet ของคุณในการบูตครั้งแรกแทน: Tailscale จะถูกติดตั้งจากแพ็กเกจที่รวมอยู่ใน ISO ไฟร์วอลล์จะอนุญาตอินเทอร์เฟซของ tailnet และงานเบื้องหลังจะดำเนินการเข้าร่วมทันทีที่เครื่องมีเครือข่ายจริง ๆ โดยลองใหม่จนกว่าจะสำเร็จ ใช้คีย์แบบ reusable ที่ได้รับอนุญาตล่วงหน้า เพื่อให้อิมเมจไดรฟ์เดียวสามารถให้บริการเครื่องจำนวนมากได้

## การสร้างไดรฟ์ cidata

ระบบไฟล์ใด ๆ ที่มีป้ายชื่อถูกต้องก็ใช้ได้ ISO ขนาดเล็กเป็นวิธีที่ง่าย:

```bash
mkdir cidata
cp user_configuration.json user_credentials.json authorized_keys cidata/
genisoimage -output cidata.iso -volid cidata -joliet -rock cidata/
```

จากนั้นเชื่อมต่อมันเข้ากับ VM ควบคู่ไปกับ ISO ของ Omarchy นี่คือตัวอย่าง Proxmox แบบเต็ม:

```bash
qm create 101 --name my-omarchy \
  --bios ovmf --machine q35 --cpu host --cores 4 --memory 8192 \
  --ostype l26 --scsihw virtio-scsi-single \
  --efidisk0 local-lvm:0,efitype=4m,pre-enrolled-keys=0 \
  --scsi0 local-lvm:40,discard=on,iothread=1 \
  --net0 virtio,bridge=vmbr0 --vga virtio --serial0 socket \
  --ide2 local:iso/omarchy.iso,media=cdrom \
  --ide3 local:iso/cidata.iso,media=cdrom \
  --boot order='scsi0;ide2'

qm start 101
```

ลำดับการบูตระบุให้ดิสก์มาก่อนโดยตั้งใจ: ดิสก์เปล่าจะตกลงไปบูตจาก ISO ในการบูตครั้งแรก และระบบที่ติดตั้งแล้วจะบูตจากดิสก์ตลอดไปหลังจากนั้น

## ข้อควรระวังสองประการ

การติดตั้งที่เข้ารหัสแบบไม่มีผู้ดูแลนั้นไม่ได้ไม่มีผู้ดูแลอย่างสมบูรณ์ — ยังคงต้องมีใครสักคนพิมพ์ข้อความรหัสผ่าน LUKS ในการบูตครั้งแรก และบล็อก `disk_encryption` ใน `user_configuration.json` มีข้อความรหัสผ่านนั้นเป็นข้อความธรรมดา ดังนั้นจงปฏิบัติต่อไดรฟ์ cidata ที่สร้างจากการติดตั้งที่เข้ารหัสเสมือนเป็นความลับตามที่มันเป็น
