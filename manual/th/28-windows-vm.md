# Windows VM

Omarchy มีวิธีง่าย ๆ ในการเรียกใช้ Windows ผ่าน Docker VM บนเครื่อง x86_64 คุณสามารถติดตั้งได้โดยใช้ _Install > Windows_ จากเมนู Omarchy (`Super + Space`)

เครื่องของคุณต้องใช้การจำลองเสมือนแบบ KVM สำหรับเรื่องนี้ ซึ่งเครื่องส่วนใหญ่ก็รองรับ — แต่บางครั้งมันถูกปิดไว้ใน BIOS และตัวติดตั้งจะแจ้งให้คุณทราบหากเป็นเช่นนั้น คุณยังต้องมีพื้นที่ดิสก์ด้วย: เท่าจำนวนที่คุณมอบให้ Windows บวกอีกประมาณ 10GB สำหรับตัวอิมเมจเอง

ตัวติดตั้งจะถามว่าคุณต้องการมอบ RAM เท่าใด แกน CPU กี่แกน และดิสก์เท่าใด (64GB ขึ้นไปคือขั้นต่ำที่สมเหตุสมผล) จากนั้นจะถามชื่อผู้ใช้และรหัสผ่านของ Windows หากเว้นว่างไว้ คุณจะได้ `docker` / `admin` การดาวน์โหลดจะใช้เวลาสักพัก — 10-15 นาทีถือเป็นเรื่องปกติ — และคุณสามารถติดตามความคืบหน้าได้ในเบราว์เซอร์ที่ `http://127.0.0.1:8006` เบราว์เซอร์จะขอชื่อผู้ใช้และรหัสผ่านเดียวกันก่อนเปิดคอนโซล

## การใช้งาน

เมื่อติดตั้งเสร็จแล้ว ให้เปิด _Windows_ จากตัวเปิดแอป การทำเช่นนั้นจะเริ่ม VM หากมันยังไม่ได้ทำงานอยู่ และเชื่อมต่อคุณผ่าน RDP แบบเต็มหน้าจอ ให้เวลามัน 15-30 วินาทีเมื่อเริ่มแบบเย็น

เซสชัน RDP จะส่งเสียง ไมโครโฟนของคุณ และคลิปบอร์ดที่ใช้ร่วมกัน ดังนั้นการคัดลอกข้อความระหว่าง Linux กับ Windows จึงใช้งานได้ทันที ความละเอียดจะปรับตามหน้าต่างของคุณ และ Omarchy จะส่งค่าการปรับขนาดของจอแสดงผลของคุณผ่านไปด้วย ดังนั้นภาพจึงไม่เบลอจนเละบนหน้าจอ HiDPI

เมื่อคุณปิดหน้าต่าง RDP VM จะปิดลงโดยอัตโนมัติ หากคุณอยากปล่อยให้มันทำงานต่อไปมากกว่า — สมมติว่าคุณมีบางอย่างกำลังทำงานอยู่ในนั้น — ให้เปิดมันด้วย `omarchy windows vm launch --keep-alive` แทน

คำสั่งควบคุมที่เหลืออยู่บนคำสั่งเดียวกัน:

```bash
omarchy windows vm status    # is it running?
omarchy windows vm stop      # shut it down
omarchy windows vm launch    # start and connect
```

## การแชร์ไฟล์

ไดเรกทอรี `~/Windows` ในไดเรกทอรีบ้านของคุณจะถูกแชร์กับ VM โดยอัตโนมัติ วางไฟล์ไว้ที่นั่นหากคุณต้องการให้ Windows เข้าถึงได้ VM จะไม่สามารถเข้าถึงส่วนอื่นใดของระบบไฟล์ของคุณได้ ดังนั้นคุณจึงปลอดภัยจากสิ่งเลวร้ายใด ๆ จากฝั่ง Windows ดิสก์เสมือนของมันเองอยู่ที่ `~/.windows`

พาธบ้านที่คุ้นเคยเหล่านั้นจะอยู่บนระบบไฟล์ของตัวเอง พวกมันยังสามารถเป็น symlink ไปยังไดเรกทอรีที่คุณเป็นเจ้าของได้ด้วย ซึ่งมีประโยชน์เมื่อดิสก์เสมือนอยู่บนไดรฟ์ที่ใหญ่กว่า ตัวติดตั้งจะวัดพื้นที่ว่างบนระบบไฟล์ที่บรรจุ `~/.windows` อยู่จริง ไม่จำเป็นต้องเป็นระบบไฟล์ที่บรรจุไดเรกทอรีบ้านของคุณ

จงเก็บพาธดิสก์และพาธที่แชร์ให้เป็นไดเรกทอรีแยกกันและไม่ทับซ้อนกัน การลบจะล้างไดเรกทอรีดิสก์โดยเจตนา แต่จะคงไดเรกทอรีที่แชร์ไว้ ทันทีก่อนการลบ Omarchy จะทำการตรวจสอบการบรรจุแบบมีขอบเขต และจะปฏิเสธที่จะลบสิ่งใด ๆ หากการตรวจสอบนั้นหมดเวลาหรือไม่สามารถพิสูจน์ได้ว่าทั้งสองทรีแยกจากกัน

ก่อนที่ VM จะเริ่ม Omarchy จะเปิดและตรึงทั้งสองไดเรกทอรีนั้น จากนั้นจะ bind-mount inode ของไดเรกทอรีที่แน่นอนเหล่านั้นไปยังจุดยึดส่วนตัวต่อผู้ใช้ด้านล่าง `/var/lib/omarchy/windows/mounts` Docker จะเห็นเฉพาะจุดยึดที่ได้รับการป้องกันโดย root เหล่านั้นเท่านั้น สิ่งนี้ช่วยรักษาตำแหน่งดิสก์แบบกำหนดเองไว้ ในขณะเดียวกันก็ป้องกันไม่ให้โปรเซสอื่นที่ทำงานในฐานะคุณสลับพาธที่ตรวจสอบแล้วก่อนที่คอนเทนเนอร์ที่มีสิทธิ์พิเศษจะใช้งานมัน ไดเรกทอรีดิสก์และไดเรกทอรีที่แชร์ที่มีอยู่จะถูกจำกัดให้เป็นโหมด `0700` ในระหว่างการย้าย เพื่อให้บัญชีในเครื่องอื่น ๆ ไม่สามารถเรียกดูเนื้อหาภายในได้

พอร์ตของ VM จะถูกผูกไว้กับ localhost เท่านั้น ดังนั้นจึงไม่มีอะไรบนเครือข่ายของคุณที่สามารถเข้าถึงเครื่อง Windows ได้ คอนโซลบนเว็บยังต้องใช้ชื่อผู้ใช้และรหัสผ่านของ Windows ที่กำหนดค่าไว้ ซึ่งจะป้องกันไม่ให้บัญชีในเครื่องอื่นควบคุม VM ผ่านพอร์ต 8006

## ข้อจำกัดและสิทธิ์การใช้งาน

การตั้งค่านี้ไม่มี GPU passthrough ดังนั้นจึงไม่เหมาะสำหรับการเล่นเกมหรือตัดต่อวิดีโอ มันเป็นวิธีที่ยอดเยี่ยมในการเรียกใช้ Microsoft Office หรืออะไรก็ตามที่คุณจำเป็นต้องมีจริง ๆ

เวอร์ชันที่ติดตั้งคือ Windows 11 Pro ที่ยังไม่ได้เปิดใช้งาน คุณจะต้องมีคีย์สิทธิ์การใช้งานของคุณเองเพื่อใช้คุณลักษณะที่ถูกจำกัดไว้

หากคอมพิวเตอร์เครื่องนี้มาพร้อมกับ Windows คีย์ OEM จะยังคงอยู่ในเฟิร์มแวร์แม้หลังจากติดตั้ง Omarchy แล้ว พิมพ์มันออกมาด้วย `omarchy windows key` คีย์นั้นผูกไว้กับเครื่องนี้ — มันจะเปิดใช้งาน Windows ที่ติดตั้งใหม่บนฮาร์ดแวร์นี้ได้ แต่มักจะไม่สามารถเปิดใช้งาน VM ได้

คุณสามารถเปลี่ยนการจัดสรรทรัพยากรในภายหลังได้โดยการเรียกใช้ `omarchy windows vm install` ในเทอร์มินัล ซึ่งจะเขียนการกำหนดค่าของ VM ใหม่จากคำตอบของคุณ ไฟล์ compose เองตอนนี้อยู่ที่ `/var/lib/omarchy/windows/docker-compose.yml` และมี root เป็นเจ้าของ — นั่นเป็นไปโดยเจตนา เพื่อให้โปรเซสที่ทำงานในฐานะคุณไม่สามารถเขียนมันใหม่และให้การเริ่มระบบที่มีสิทธิ์พิเศษ mount ดิสก์ทั้งหมดของคุณเข้าไปในคอนเทนเนอร์ได้ หากคุณจำเป็นต้องแก้ไขมันด้วยมือ (ตัวอย่างเช่น เพื่อ mount อุปกรณ์ USB) ให้แก้ไขมันด้วย `sudo` และดูตัวเลือกทั้งหมดได้ที่ [โปรเจกต์ Dockur Windows](https://github.com/dockur/windows)

หากต้องการกำจัดทั้งหมดนี้ ให้ใช้ _Remove > Windows_ จากเมนู Omarchy การทำเช่นนั้นจะลบดิสก์ของ VM ใน `~/.windows` และทุกอย่างที่ติดตั้งอยู่ภายใน Windows ดังนั้นให้คัดลอกสิ่งที่คุณต้องการออกจาก VM ก่อน โฟลเดอร์ `~/Windows` ที่แชร์ไว้ของคุณจะไม่ถูกแตะต้อง
