# ความปลอดภัย

Omarchy เอาจริงเอาจังเรื่องความปลอดภัยอย่างยิ่ง นี่คือระบบปฏิบัติการที่ตั้งใจให้คุณใช้ทำ _งานจริง_ ใน _โลกจริง_ ได้ สถานการณ์ที่ทำแล็ปท็อปหายต้องไม่กลายเป็นเหตุฉุกเฉินด้านความปลอดภัย นี่คือสิ่งที่เราทำ:

1. *การเข้ารหัสทั้งดิสก์เปิดอยู่เป็นค่าเริ่มต้น*: นี่คือขั้นตอนสำคัญที่สุดในการปกป้องข้อมูลของคุณในเชิงกายภาพ หากคอมพิวเตอร์ของคุณสูญหายหรือถูกขโมย ข้อมูลจะถูกเข้ารหัสอย่างสมบูรณ์โดยใช้ LUKS (Linux Unified Key Setup) มาตรฐาน ตัวติดตั้งอนุญาตให้คุณเลือกไม่ใช้ได้สำหรับเครื่องแบบใช้แล้วทิ้ง (ดู [เริ่มต้นใช้งาน](02-getting-started.md)); การติดตั้งโดยไม่มีการเข้ารหัสจะไม่มีการป้องกันนี้เลย และใครก็ตามที่ถือไดรฟ์อยู่ก็สามารถอ่านข้อมูลได้
2. *ไฟร์วอลล์เปิดใช้งานเป็นค่าเริ่มต้น*: ทราฟฟิกขาเข้าทั้งหมดถูกบล็อกเป็นค่าเริ่มต้น โดยมีข้อยกเว้นเพียงไม่กี่อย่าง: พอร์ต 53317 สำหรับ [LocalSend](https://localsend.org/); คำขอ DNS ไปยังตัวแก้ไขชื่อของคอมพิวเตอร์เองที่ที่อยู่ Docker bridge (172.17.0.1) ซึ่งรับจากช่วงที่อยู่ส่วนตัวที่ Docker มอบให้คอนเทนเนอร์ของตน; และ multicast DNS (พอร์ต 5353) ซึ่งช่วยให้เครื่องพิมพ์และอุปกรณ์อื่น ๆ บนเครือข่ายของคุณค้นพบกันและกัน และยังประกาศชื่อคอมพิวเตอร์ของคุณที่นั่นด้วย นอกเหนือจากนั้น ไฟร์วอลล์ยังคงข้อยกเว้นมาตรฐานของ UFW สำหรับ ping, การรับที่อยู่จากเราเตอร์ของคุณ (DHCP), และการค้นหา UPnP แม้แต่ ssh ยังปิดอยู่จนกว่าคุณจะเปิดผ่าน _Setup > Security > SSHD_ ซึ่งจะอนุญาตคีย์ SSH ของคุณ ปิดการเข้าสู่ระบบด้วยรหัสผ่าน และหลังจากนั้นเท่านั้นจึงจะเปิดพอร์ต 22 (จำกัดอัตราการพยายามเพื่อป้องกัน brute force) เรายังล็อกการเข้าถึง Docker ให้แน่นหนาโดยใช้การตั้งค่า [ufw-docker](https://github.com/chaifeng/ufw-docker) เพื่อป้องกันไม่ให้คอนเทนเนอร์ของคุณถูกเปิดเผยสู่โลกภายนอกโดยไม่ตั้งใจ
3. *Arch ได้รับการอัปเดตล่าสุดอยู่เสมอ*: Arch ซึ่งเป็นดิสโทรพื้นฐานที่ Omarchy สร้างขึ้นต่อยอด เป็นดิสโทรแบบ rolling ซึ่งหมายความว่าช่องโหว่ด้านความปลอดภัยใด ๆ ที่ถูกค้นพบและแก้ไขในแพ็กเกจใด ๆ จะพร้อมให้ติดตั้งได้อย่างรวดเร็วโดยใช้ `omarchy-update` ด้วยวิธีนี้ คุณจะใช้เวอร์ชันล่าสุดและปลอดภัยที่สุดของทุกอย่างอยู่เสมอ
4. *Omarchy ดูแลแพ็กเกจและ mirror ของตัวเอง*: โดยค่าเริ่มต้น Omarchy พึ่งพาเฉพาะแพ็กเกจจาก repository core/extra/multilib ของ Arch เอง (ของ Arch Linux ARM บนเครื่อง ARM บวกกับ Asahi ALARM บน Apple Silicon) และ Omarchy Package Repository ของตัวเองเท่านั้น คุณสามารถติดตั้งซอฟต์แวร์จาก AUR ได้โดยตรง แต่การติดตั้งพื้นฐานไม่ได้ทำเช่นนั้น — มีเพียงการติดตั้งเสริมเพียงไม่กี่อย่าง เช่น เบราว์เซอร์ของบุคคลที่สาม เท่านั้นที่ดึงจาก AUR
5. *Cloudflare ปกป้องเราจาก DDoS*: โครงสร้างพื้นฐานสำหรับการเผยแพร่ Omarchy — ISO ต่าง ๆ, แพ็กเกจ Omarchy, mirror ของ Arch — ได้รับการปกป้องอยู่หลังเกราะป้องกัน DDoS อันแข็งแกร่งของ Cloudflare และโฮสต์อยู่บน CDN ของพวกเขา ซึ่งมอบความพร้อมใช้งานที่ยอดเยี่ยม

## การเปลี่ยนรหัสผ่านของคุณ

คุณมีรหัสผ่านสองชุดในการติดตั้งแบบเข้ารหัส: ชุดหนึ่งสำหรับปลดล็อกไดรฟ์ตอนบูต และอีกชุดหนึ่งสำหรับเข้าสู่ระบบและใช้ `sudo` การตั้งค่าจะทำให้ทั้งสองชุดเป็นรหัสเดียวกัน _Update > Password_ ในเมนู Omarchy จะเปลี่ยนทั้งสองพร้อมกันในครั้งเดียว เพื่อให้ยังคงเป็นรหัสเดียวกัน: มันจะถามรหัสผ่านไดรฟ์ปัจจุบันก่อน จากนั้นถามรหัสใหม่ เปลี่ยนรหัสของไดรฟ์ แล้วตั้งรหัสผ่านเข้าสู่ระบบของคุณให้ตรงกัน หากไม่มีการเข้ารหัสไดรฟ์ มันจะเปลี่ยนเฉพาะรหัสผ่านเข้าสู่ระบบของคุณ หากการเปลี่ยนถูกขัดจังหวะ ให้เรียก _Update > Password_ อีกครั้ง: มันจะถามรหัสผ่านที่ปลดล็อกไดรฟ์อยู่ในตอนนี้ ดำเนินการเปลี่ยนให้เสร็จ และตั้งรหัสผ่านเข้าสู่ระบบของคุณเป็นรหัสนั้น หากต้องการเปลี่ยนรหัสผ่านของไดรฟ์ที่เข้ารหัสอีกไดรฟ์หนึ่ง ให้เรียก `omarchy-drive-password` ในเทอร์มินัล

## การส่งต่อเครื่องที่คุณเคยใช้งานแล้ว

หากคุณกำลังจะส่งมอบเครื่องของคุณให้ผู้อื่น คุณไม่จำเป็นต้องติดตั้งใหม่ เรียก _Remove > Factory Reset_ ในเมนู Omarchy พิมพ์ `reset` เพื่อยืนยัน ใส่รหัสผ่านการเข้ารหัสไดรฟ์ของคุณหากถูกถาม แล้วรีบูต การทำเช่นนั้นจะลบบัญชีผู้ใช้ทุกบัญชีและทุกอย่างใน `/home` ทิ้งแพ็กเกจและการเปลี่ยนแปลงระบบทั้งหมดที่คุณทำตั้งแต่การติดตั้ง และล้างตัวตนของเครื่อง — การเชื่อมต่อเครือข่าย, host keys และทั้งหมด สิ่งที่จะกลับขึ้นมาคือวิซาร์ดการตั้งค่าจากการบูตครั้งแรก พร้อมให้เจ้าของใหม่ใส่ชื่อ รหัสผ่าน และรหัสผ่านการเข้ารหัสของตนเอง

มันทำงานโดยการกู้คืน snapshot พื้นฐานที่ตัวติดตั้งสร้างไว้ จึงใช้ได้เฉพาะบนเครื่องที่ติดตั้งจาก Omarchy ISO เท่านั้น และบนไดรฟ์ที่ไม่มีการเข้ารหัส การรีเซ็ตเป็นเพียงการลบมากกว่าการลบอย่างปลอดภัย ดังนั้นหากข้อมูลนั้นละเอียดอ่อน ให้ติดตั้งใหม่แบบสะอาดแทน

## sudo แบบไม่ใช้รหัสผ่าน

บางครั้งคุณอาจต้องการให้ `sudo` เลิกถามรหัสผ่าน ซึ่งบ่อยที่สุดคือตอนที่ AI agent กำลังทำงานระบบยาว ๆ ให้คุณ _Setup > Security > Passwordless Sudo_ จะถามว่าจะอนุญาตการเข้าถึงนานเท่าใด: **15 นาที**, **1 ชั่วโมง**, **1 วัน**, หรือ **ถาวร** ไอคอนคำเตือนสีแดงจะปรากฏข้างตัวบ่งชี้อื่น ๆ บนแถบเมนูขณะที่การเข้าถึงกำลังทำงาน คลิกที่ไอคอนนั้นหรือเรียกคำสั่งอีกครั้งเพื่อปิดการเข้าถึง คุณยังสามารถระบุจำนวนนาทีของคุณเอง (ตั้งแต่ 1 ถึง 1440) ได้ด้วย `omarchy-sudo-passwordless 30` หรือใช้ `omarchy-sudo-passwordless permanent`

การเข้าถึงแบบมีกำหนดเวลาจะหมดอายุโดยอัตโนมัติ รวมถึงทันทีหลังจากกลับมาจากการพักเครื่องที่ข้ามเส้นตายไปแล้ว การรีสตาร์ทคอมพิวเตอร์จะยุติการเข้าถึงก่อนกำหนด การเข้าถึงแบบถาวรจะคงอยู่ข้ามการรีบูตและยังคงเปิดใช้งานจนกว่าคุณจะปิดมัน

การอัปเดตหรือการลบแพ็กเกจการตั้งค่าของ Omarchy จะยุติการอนุญาตชั่วคราวใด ๆ ก่อนที่การรองรับการหมดอายุของมันจะเปลี่ยนแปลง หากคำสั่งรายงานข้อผิดพลาดเกี่ยวกับการอนุญาตหรือการล้างข้อมูล ให้แก้ไขก่อนพยายามเปิดใช้งานการอนุญาตอื่น; ข้อผิดพลาดไม่ได้หมายความว่าการเข้าถึงแบบไม่ใช้รหัสผ่านไม่ได้ทำงานอยู่

ขอให้มองเรื่องนี้อย่างชัดเจน: ขณะที่มันเปิดอยู่ ทุกอย่างที่ทำงานในฐานะผู้ใช้ของคุณสามารถทำอะไรก็ได้ในฐานะ root โดยไม่ต้องถูกถาม นั่นคือจุดประสงค์ทั้งหมด และนั่นก็คือความเสี่ยงทั้งหมดเช่นกัน

## คีย์สำหรับลงนาม

คีย์สาธารณะสำหรับลายเซ็น ISO ทั้งหมดและแพ็กเกจ repo ของ Omarchy คือ `40DFB630FF42BCFFB047046CF0134EE680CAC571` ([ตรวจสอบที่ openpgp.org](https://keys.openpgp.org/search?q=pkgs%40omarchy.org)) แพ็กเกจ `omarchy/omarchy-keyring` ก็มีคีย์นี้เช่นกัน และจะถูกใช้เพื่อเผยแพร่การอัปเดตที่อาจเกิดขึ้นในอนาคตอย่างราบรื่น

คุณสามารถค้นหาลายเซ็นสำหรับ ISO รุ่นใด ๆ ได้โดยเพิ่ม `.sig` ต่อท้าย URL ของมัน เช่น `https://iso.omarchy.org/omarchy-x.x.x.iso.sig`
