# ความปลอดภัย

Omarchy ให้ความสำคัญกับความปลอดภัยอย่างจริงจังที่สุด นี่คือระบบปฏิบัติการที่ตั้งใจให้คุณใช้ทำ _Real Work_ ใน _Real World_ ได้จริง ที่ที่การทำแล็ปท็อปหายจะไม่มีทางนำไปสู่เหตุฉุกเฉินด้านความปลอดภัย นี่คือสิ่งที่เราทำ:

1. *การเข้ารหัสทั้งดิสก์เปิดใช้งานเป็นค่าเริ่มต้น*: นี่คือขั้นตอนที่สำคัญที่สุดในการปกป้องข้อมูลของคุณในเชิงกายภาพ หากคอมพิวเตอร์ของคุณสูญหายหรือถูกขโมย ข้อมูลจะถูกเข้ารหัสอย่างสมบูรณ์โดยใช้ LUKS (Linux Unified Key Setup) มาตรฐาน ตัวติดตั้งอนุญาตให้คุณเลือกไม่ใช้ได้สำหรับเครื่องแบบใช้แล้วทิ้ง (ดู [เริ่มต้นใช้งาน](02-getting-started.md)) การติดตั้งที่ไม่มีการเข้ารหัสจะไม่มีการปกป้องนี้เลย และใครก็ตามที่ถือไดรฟ์อยู่ก็สามารถอ่านข้อมูลในนั้นได้
2. *Firewall เปิดใช้งานเป็นค่าเริ่มต้น*: ทราฟฟิกขาเข้าทั้งหมดจะถูกบล็อกเป็นค่าเริ่มต้น โดยมีข้อยกเว้นเพียงไม่กี่อย่าง: พอร์ต 53317 สำหรับ [LocalSend](https://localsend.org/) คำขอ DNS ไปยังตัวแปลงชื่อของคอมพิวเตอร์เองที่ที่อยู่ Docker bridge (172.17.0.1) ซึ่งยอมรับจากช่วงที่อยู่ส่วนตัวที่ Docker มอบให้กับคอนเทนเนอร์ของมัน และ multicast DNS (พอร์ต 5353) ซึ่งช่วยให้เครื่องพิมพ์และอุปกรณ์อื่น ๆ บนเครือข่ายของคุณหาเจอกันและกันได้ และยังประกาศชื่อคอมพิวเตอร์ของคุณที่นั่นด้วย นอกเหนือจากนั้น Firewall ยังคงการอนุญาตมาตรฐานของ UFW สำหรับ ping การรับที่อยู่จากเราเตอร์ของคุณ (DHCP) และการค้นพบ UPnP ไว้ แม้แต่ ssh ก็ยังปิดอยู่จนกว่าคุณจะเปิดมันผ่าน _Setup > Security > SSHD_ ซึ่งจะเปิดพอร์ต 22 (จำกัดอัตราเพื่อป้องกัน brute force) เป็นส่วนหนึ่งของการตั้งค่า เรายังล็อกการเข้าถึง Docker ให้แน่นหนาโดยใช้การตั้งค่า [ufw-docker](https://github.com/chaifeng/ufw-docker) เพื่อป้องกันไม่ให้คอนเทนเนอร์ของคุณถูกเปิดเผยออกสู่โลกภายนอกโดยไม่ตั้งใจ
3. *Arch มีอัปเดตล่าสุดเสมอ*: Arch ซึ่งเป็นดิสโทรพื้นฐานที่ Omarchy สร้างขึ้นมานั้น เป็นดิสโทรแบบ rolling ซึ่งหมายความว่าช่องโหว่ด้านความปลอดภัยใด ๆ ที่ถูกค้นพบและแก้ไขในแพ็กเกจใด ๆ จะพร้อมให้ติดตั้งได้อย่างรวดเร็วโดยใช้ `omarchy-update` ด้วยวิธีนี้ คุณจะใช้ทุกอย่างในเวอร์ชันล่าสุดและปลอดภัยที่สุดอยู่เสมอ
4. *Omarchy ดูแลแพ็กเกจและ mirror ของตัวเอง*: โดยค่าเริ่มต้น Omarchy พึ่งพาเฉพาะแพ็กเกจจากที่เก็บ core/extra/multilib ของ Arch เอง และ Omarchy Package Repository ของตัวเองเท่านั้น คุณสามารถติดตั้งซอฟต์แวร์โดยตรงจาก AUR ได้ แต่การติดตั้งพื้นฐานไม่ได้ทำแบบนั้น มีเฉพาะการติดตั้งเสริมเพียงไม่กี่อย่าง เช่น เบราว์เซอร์จากบุคคลที่สาม ที่ดึงมาจาก AUR
5. *Cloudflare ปกป้องเราจาก DDoS*: โครงสร้างพื้นฐานสำหรับการแจกจ่าย Omarchy ไม่ว่าจะเป็น ISO ต่าง ๆ แพ็กเกจ Omarchy และ Arch mirror ได้รับการปกป้องอยู่หลังเกราะป้องกัน DDoS อันแข็งแกร่งของ Cloudflare และโฮสต์อยู่บน CDN ของพวกเขา ซึ่งมอบความพร้อมใช้งานที่ยอดเยี่ยม

## การเปลี่ยนรหัสผ่านของคุณ

ในการติดตั้งที่มีการเข้ารหัส คุณจะมีรหัสผ่านสองชุด: ชุดหนึ่งสำหรับปลดล็อกไดรฟ์ตอนบูต และอีกชุดหนึ่งสำหรับเข้าสู่ระบบและใช้กับ `sudo` การตั้งค่าจะทำให้ทั้งสองชุดเป็นรหัสเดียวกัน ทั้งสองชุดเปลี่ยนได้ภายใต้ _Update > Password_ ในเมนู Omarchy โดย _Drive Encryption_ สำหรับชุดแรก และ _User_ สำหรับชุดที่สอง การเปลี่ยนรหัสผ่านไดรฟ์จะขอให้ใส่รหัสปัจจุบันก่อน ดังนั้นเตรียมมันไว้ให้พร้อม หากการเปลี่ยนแปลงถูกขัดจังหวะ ให้เรียกใช้ _Drive Encryption_ อีกครั้ง มันจะขอรหัสผ่านที่ปลดล็อกไดรฟ์อยู่ในตอนนี้ และจะทำการเปลี่ยนแปลงให้เสร็จสมบูรณ์

## การส่งต่อเครื่องที่คุณใช้งานแล้ว

หากคุณกำลังจะส่งมอบเครื่องของคุณให้คนอื่น คุณไม่จำเป็นต้องติดตั้งใหม่ เรียกใช้ _Remove > Factory Reset_ ในเมนู Omarchy พิมพ์ `reset` เพื่อยืนยัน แล้วรีบูต การทำเช่นนี้จะลบบัญชีผู้ใช้ทุกบัญชีและทุกอย่างใน `/home` ทิ้งแพ็กเกจและการเปลี่ยนแปลงระบบทั้งหมดที่คุณทำมาตั้งแต่ติดตั้ง และล้างตัวตนของเครื่อง ทั้งการเชื่อมต่อเครือข่าย host keys และทุกอย่าง สิ่งที่จะกลับขึ้นมาคือตัวช่วยตั้งค่าจากการบูตครั้งแรก พร้อมให้เจ้าของใหม่ใส่ชื่อ รหัสผ่าน และรหัสผ่านการเข้ารหัสของตัวเอง

มันทำงานโดยการคืนค่า baseline snapshot ที่ตัวติดตั้งบันทึกไว้ ดังนั้นจึงใช้ได้เฉพาะบนเครื่องที่ติดตั้งจาก Omarchy ISO เท่านั้น และบนไดรฟ์ที่ไม่มีการเข้ารหัส การรีเซ็ตเป็นเพียงการลบ ไม่ใช่การลบอย่างปลอดภัย ดังนั้นหากข้อมูลนั้นมีความอ่อนไหว ให้ทำการติดตั้งใหม่ตั้งแต่ต้นแทน

## sudo แบบไม่ต้องใช้รหัสผ่าน

บางครั้งคุณก็ต้องการให้ `sudo` เลิกถามรหัสผ่าน ซึ่งส่วนใหญ่เป็นตอนที่ AI agent กำลังทำงานระบบช่วงยาวให้คุณ _Setup > Security > Passwordless Sudo_ จะถามว่าจะอนุญาตให้เข้าถึงได้นานแค่ไหน: **15 นาที**, **1 ชั่วโมง**, **1 วัน** หรือ **ถาวร** ไอคอนคำเตือนสีแดงจะปรากฏข้างตัวบ่งชี้อื่น ๆ บนแถบเมนูขณะที่การเข้าถึงยังทำงานอยู่ คลิกที่ไอคอนนั้นหรือเรียกใช้คำสั่งอีกครั้งเพื่อปิดการเข้าถึง คุณยังสามารถระบุจำนวนนาทีของคุณเอง (ตั้งแต่ 1 ถึง 1440) ได้ด้วย `omarchy-sudo-passwordless 30` หรือใช้ `omarchy-sudo-passwordless permanent`

การเข้าถึงแบบกำหนดเวลาจะหมดอายุโดยอัตโนมัติ รวมถึงทันทีหลังจากกลับมาจากการระงับการทำงานที่ข้ามเส้นตายไปแล้ว การรีสตาร์ทคอมพิวเตอร์จะยุติมันก่อนเวลา การเข้าถึงแบบถาวรจะยังคงอยู่หลังการรีบูต และจะเปิดใช้งานต่อไปจนกว่าคุณจะปิดมัน

การอัปเดตหรือการลบแพ็กเกจการตั้งค่าของ Omarchy จะยุติสิทธิ์ชั่วคราวใด ๆ ก่อนที่การรองรับการหมดอายุของมันจะเปลี่ยนแปลง หากคำสั่งรายงานข้อผิดพลาดเกี่ยวกับการอนุญาตหรือการล้างข้อมูล ให้แก้ไขให้เรียบร้อยก่อนพยายามเปิดใช้งานสิทธิ์อีกครั้ง ข้อผิดพลาดไม่ได้หมายความว่าการเข้าถึงแบบไม่ต้องใช้รหัสผ่านไม่ได้ทำงานอยู่

มองเรื่องนี้ให้ชัดเจน: ขณะที่มันเปิดอยู่ อะไรก็ตามที่ทำงานในฐานะผู้ใช้ของคุณสามารถทำอะไรก็ได้ในฐานะ root โดยไม่ต้องถูกถามเลย นั่นคือจุดประสงค์ทั้งหมด และนั่นก็คือความเสี่ยงทั้งหมดเช่นกัน
