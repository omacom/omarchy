# ความปลอดภัย

Omarchy ให้ความสำคัญกับความปลอดภัยอย่างจริงจังอย่างยิ่ง นี่ตั้งใจให้เป็นระบบปฏิบัติการที่คุณสามารถใช้ทำงาน _จริง_ ในโลก _จริง_ ได้ ที่ซึ่งการทำแล็ปท็อปหายไม่สามารถนำไปสู่เหตุฉุกเฉินด้านความปลอดภัยได้ ดังนั้นนี่คือสิ่งที่เราทำ:

1. *การเข้ารหัสทั้งดิสก์เป็นข้อบังคับ*: นี่คือขั้นตอนสำคัญที่สุดในการรักษาความปลอดภัยทางกายภาพของข้อมูลของคุณ ถ้าคอมพิวเตอร์ของคุณหายหรือถูกขโมย ข้อมูลจะถูกเข้ารหัสอย่างสมบูรณ์โดยใช้ LUKS (Linux Unified Key Setup) มาตรฐาน
2. *ไฟร์วอลล์เปิดอยู่เป็นค่าเริ่มต้น*: ทราฟฟิกขาเข้าทั้งหมดถูกบล็อกเป็นค่าเริ่มต้นยกเว้นพอร์ต 53317 สำหรับ [LocalSend](https://localsend.org/) แม้แต่ ssh ก็ปิดอยู่จนกว่าคุณจะเปิดมันผ่าน _ตั้งค่า > ความปลอดภัย > SSHD_ ซึ่งเปิดพอร์ต 22 (จำกัดอัตราต่อการเดารหัสแบบ brute force) เป็นส่วนหนึ่งของการตั้งค่า เรายังล็อกดาวน์การเข้าถึง Docker โดยใช้การตั้งค่า [ufw-docker](https://github.com/chaifeng/ufw-docker) เพื่อป้องกันไม่ให้คอนเทนเนอร์ของคุณถูกเปิดสู่โลกภายนอกโดยไม่ได้ตั้งใจ
3. *Arch มีการอัปเดตล่าสุดเสมอ*: Arch ซึ่งเป็น distro พื้นฐานที่ Omarchy สร้างบนนั้น เป็นดิสทริบิวชันแบบ rolling นั่นหมายความว่าช่องโหว่ความปลอดภัยใด ๆ ที่ถูกค้นพบและแพตช์ในแพ็กเกจใด ๆ จะพร้อมให้ติดตั้งอย่างรวดเร็วโดยใช้ `omarchy-update` คุณจึงรันเวอร์ชันล่าสุดและปลอดภัยที่สุดของทุกอย่างเสมอด้วยวิธีนั้น
4. *Omarchy ดูแลแพ็กเกจและมิเรอร์ของตัวเอง*: Omarchy พึ่งพาเฉพาะแพ็กเกจจากที่เก็บ core/extra/multilib ของ Arch เองและ Omarchy Package Repository ของตัวเองเป็นค่าเริ่มต้นเท่านั้น คุณสามารถติดตั้งซอฟต์แวร์โดยตรงจาก AUR ได้ แต่การติดตั้งพื้นฐานไม่ทำเช่นนั้น — มีเพียงการติดตั้งเสริมเพียงไม่กี่รายการ เช่น เบราว์เซอร์ของบุคคลที่สาม ที่ดึงจาก AUR
5. *Cloudflare ปกป้องเราจาก DDoS*: โครงสร้างพื้นฐานการแจกจ่าย Omarchy ทั้งหมด — ISO แพ็กเกจ Omarchy มิเรอร์ Arch — ได้รับการปกป้องหลังเกราะ DDoS ที่แข็งแกร่งของ Cloudflare และโฮสต์บน CDN ของพวกเขา สิ่งนี้ให้ความพร้อมใช้งานที่ยอดเยี่ยม

## การเปลี่ยนรหัสผ่านของคุณ

คุณมีรหัสผ่านสองอันในการติดตั้งแบบเข้ารหัส: อันที่ปลดล็อกไดรฟ์ตอนบูต และอันที่คุณเข้าสู่ระบบและ `sudo` ด้วย การตั้งค่าทำให้ทั้งสองอันเหมือนกัน ทั้งคู่เปลี่ยนได้ภายใต้ _อัปเดต > รหัสผ่าน_ ในเมนู Omarchy — _การเข้ารหัสไดรฟ์_ สำหรับอันแรก _ผู้ใช้_ สำหรับอันที่สอง การเปลี่ยนรหัสผ่านไดรฟ์จะขอรหัสปัจจุบันก่อน ดังนั้นเตรียมมันไว้ใกล้มือ ถ้าการเปลี่ยนแปลงถูกขัดจังหวะ ให้รัน _การเข้ารหัสไดรฟ์_ อีกครั้ง: มันจะขอรหัสผ่านที่ปลดล็อกไดรฟ์ตอนนี้และทำการเปลี่ยนแปลงให้เสร็จ

## การส่งต่อเครื่องที่คุณใช้แล้ว

ถ้าคุณกำลังส่งเครื่องของคุณต่อให้คนอื่น คุณไม่จำเป็นต้องติดตั้งมันใหม่ รัน _ตั้งค่า > รีเซ็ตคอมพิวเตอร์_ ในเมนู Omarchy พิมพ์ `reset` เพื่อยืนยัน แล้วรีบูต นั่นลบบัญชีผู้ใช้ทุกบัญชีและทุกอย่างใน `/home` ทิ้งแพ็กเกจและการเปลี่ยนแปลงระบบทั้งหมดที่คุณทำตั้งแต่ติดตั้ง และล้างตัวตนของเครื่อง — การเชื่อมต่อเครือข่าย คีย์โฮสต์ และทั้งหมด สิ่งที่กลับขึ้นมาคือตัวช่วยตั้งค่าจากการบูตครั้งแรก พร้อมสำหรับเจ้าของคนใหม่ที่จะป้อนชื่อ รหัสผ่าน และรหัสผ่านการเข้ารหัสของตัวเอง

มันทำงานโดยการกู้คืนสแนปช็อตฐานที่ตัวติดตั้งทำไว้ มันจึงมีให้ใช้เฉพาะบนเครื่องที่ติดตั้งจาก ISO ของ Omarchy เท่านั้น และบนไดรฟ์ที่ไม่มีการเข้ารหัส การรีเซ็ตคือการลบแทนที่จะเป็นการลบอย่างปลอดภัย ดังนั้นถ้าข้อมูลนั้นละเอียดอ่อน ให้ติดตั้งใหม่แทน

## sudo แบบไม่ใช้รหัสผ่าน

บางครั้งคุณอยากให้ `sudo` หยุดถาม บ่อยที่สุดคือเมื่อเอเจนต์ AI กำลังทำงานระบบเป็นเวลานานให้คุณ _ตั้งค่า > ความปลอดภัย > Sudo แบบไม่ใช้รหัสผ่าน_ ถามว่าจะอนุญาตการเข้าถึงนานแค่ไหน: **15 นาที**, **1 ชั่วโมง**, **1 วัน** หรือ **ถาวร** ไอคอนคำเตือนสีแดงปรากฏข้างตัวชี้วัดแถบเมนูอื่น ๆ ขณะที่การเข้าถึงทำงานอยู่ คลิกมันหรือรันคำสั่งอีกครั้งเพื่อปิดการเข้าถึง คุณยังส่งจำนวนนาทีของคุณเอง (ตั้งแต่ 1 ถึง 1440) ด้วย `omarchy-sudo-passwordless 30` หรือใช้ `omarchy-sudo-passwordless permanent` ได้

การเข้าถึงแบบกำหนดเวลาหมดอายุโดยอัตโนมัติ รวมถึงทันทีหลังกลับจากการพักเครื่องที่ผ่านเส้นตายไปแล้ว การรีสตาร์ตคอมพิวเตอร์จะสิ้นสุดมันก่อนเวลา การเข้าถึงถาวรอยู่รอดผ่านการรีบูตและยังคงเปิดอยู่จนกว่าคุณจะปิดมัน

การอัปเดตหรือนำแพ็กเกจการตั้งค่าของ Omarchy ออกจะสิ้นสุดสิทธิ์ชั่วคราวใด ๆ ก่อนที่การสนับสนุนการหมดอายุของมันจะเปลี่ยน ถ้าคำสั่งรายงานข้อผิดพลาดด้านการอนุญาตหรือการล้างข้อมูล ให้แก้มันก่อนพยายามเปิดสิทธิ์อื่น; ข้อผิดพลาดไม่ได้หมายความว่าการเข้าถึงแบบไม่ใช้รหัสผ่านไม่ได้ทำงานอยู่

มองเรื่องนี้อย่างชัดเจน: ขณะที่มันเปิดอยู่ อะไรก็ตามที่รันเป็นผู้ใช้ของคุณสามารถทำอะไรก็ได้ในฐานะ root โดยไม่ถูกถาม นั่นคือประเด็นทั้งหมด และมันก็คือความเสี่ยงทั้งหมดเช่นกัน
