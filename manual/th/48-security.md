# ความปลอดภัย

Omarchy ให้ความสำคัญกับความปลอดภัยอย่างจริงจังอย่างยิ่ง นี่คือระบบปฏิบัติการที่ตั้งใจให้คุณใช้ทำ _งานจริง_ ใน _โลกจริง_ ได้ ที่ที่การทำแล็ปท็อปหายต้องไม่กลายเป็นเหตุฉุกเฉินด้านความปลอดภัย นี่คือสิ่งที่เราทำ:

1. *การเข้ารหัสทั้งดิสก์เปิดอยู่โดยค่าเริ่มต้น*: นี่เป็นขั้นตอนที่สำคัญที่สุดในการปกป้องข้อมูลของคุณในเชิงกายภาพ หากคอมพิวเตอร์ของคุณสูญหายหรือถูกขโมย ข้อมูลจะถูกเข้ารหัสไว้อย่างสมบูรณ์โดยใช้ LUKS (Linux Unified Key Setup) มาตรฐาน ตัวติดตั้งให้คุณเลือกไม่ใช้ได้สำหรับเครื่องแบบใช้แล้วทิ้ง (ดู [เริ่มต้นใช้งาน](02-getting-started.md)); การติดตั้งที่ไม่มีการเข้ารหัสจะไม่มีการปกป้องนี้เลย และใครก็ตามที่ได้ไดรฟ์ไปก็สามารถอ่านข้อมูลในนั้นได้
2. *ไฟร์วอลล์เปิดใช้งานอยู่โดยค่าเริ่มต้น*: ทราฟฟิกขาเข้าทั้งหมดจะถูกบล็อกโดยค่าเริ่มต้น โดยมีข้อยกเว้นเพียงไม่กี่อย่าง: พอร์ต 53317 สำหรับ [LocalSend](https://localsend.org/); คำขอ DNS ไปยังตัวแปลงชื่อของเครื่องคอมพิวเตอร์เองที่ที่อยู่ Docker bridge (172.17.0.1) ซึ่งรับจากช่วงที่อยู่ส่วนตัวที่ Docker มอบให้คอนเทนเนอร์ของตน; และ multicast DNS (พอร์ต 5353) ซึ่งช่วยให้เครื่องพิมพ์และอุปกรณ์อื่น ๆ บนเครือข่ายของคุณค้นพบกันและกัน และยังประกาศชื่อคอมพิวเตอร์ของคุณที่นั่นด้วย นอกเหนือจากนั้น ไฟร์วอลล์ยังคงข้อยกเว้นมาตรฐานของ UFW สำหรับ ping, การรับที่อยู่จากเราเตอร์ของคุณ (DHCP) และการค้นพบ UPnP แม้แต่ ssh ยังปิดอยู่จนกว่าคุณจะเปิดใช้งานผ่าน _Setup > Security > SSHD_ ซึ่งจะอนุญาตคีย์ SSH ของคุณ ปิดการเข้าสู่ระบบด้วยรหัสผ่าน และหลังจากนั้นเท่านั้นจึงจะเปิดพอร์ต 22 (จำกัดอัตราเพื่อป้องกันการเดาแบบ brute force) เรายังล็อกการเข้าถึง Docker ให้แน่นหนาโดยใช้การตั้งค่า [ufw-docker](https://github.com/chaifeng/ufw-docker) เพื่อป้องกันไม่ให้คอนเทนเนอร์ของคุณถูกเปิดเผยสู่โลกภายนอกโดยไม่ตั้งใจ
3. *Arch มีอัปเดตล่าสุดอยู่เสมอ*: Arch ซึ่งเป็นดิสโทรพื้นฐานที่ Omarchy สร้างขึ้นต่อยอด เป็นดิสโทรแบบ rolling ซึ่งหมายความว่าช่องโหว่ด้านความปลอดภัยใด ๆ ที่ถูกค้นพบและแก้ไขในแพ็กเกจใด ๆ จะพร้อมให้ติดตั้งได้อย่างรวดเร็วโดยใช้ `omarchy-update` ด้วยวิธีนี้ คุณจะใช้ทุกอย่างในเวอร์ชันล่าสุดและปลอดภัยที่สุดอยู่เสมอ
4. *Omarchy ดูแลแพ็กเกจและ mirror ของตัวเอง*: โดยค่าเริ่มต้น Omarchy พึ่งพาเฉพาะแพ็กเกจจากที่เก็บ core/extra/multilib ของ Arch เอง (ของ Arch Linux ARM บนเครื่อง ARM และ Asahi ALARM เพิ่มเติมบน Apple Silicon) และ Omarchy Package Repository ของตัวเอง คุณสามารถติดตั้งซอฟต์แวร์โดยตรงจาก AUR ได้ แต่การติดตั้งพื้นฐานไม่ได้ทำเช่นนั้น — มีเพียงการติดตั้งเสริมเพียงไม่กี่อย่าง เช่น เบราว์เซอร์ของบุคคลที่สาม เท่านั้นที่ดึงมาจาก AUR
5. *Cloudflare ปกป้องเราจาก DDoS*: โครงสร้างพื้นฐานสำหรับการเผยแพร่ Omarchy — ไฟล์ ISO ต่าง ๆ, แพ็กเกจของ Omarchy, mirror ของ Arch — ได้รับการปกป้องอยู่เบื้องหลังเกราะป้องกัน DDoS อันแข็งแกร่งของ Cloudflare และโฮสต์อยู่บน CDN ของพวกเขา สิ่งนี้ทำให้มีความพร้อมใช้งานที่ยอดเยี่ยม

## การเปลี่ยนรหัสผ่านของคุณ

คุณมีรหัสผ่านสองชุดในการติดตั้งที่เข้ารหัส: ชุดที่ใช้ปลดล็อกไดรฟ์ตอนบูต และชุดที่คุณใช้เข้าสู่ระบบและใช้กับ `sudo` ขั้นตอนการตั้งค่าจะทำให้ทั้งสองชุดเป็นรหัสเดียวกัน ทั้งสองชุดเปลี่ยนได้ภายใต้ _Update > Password_ ในเมนู Omarchy — _Drive Encryption_ สำหรับชุดแรก, _User_ สำหรับชุดที่สอง การเปลี่ยนรหัสผ่านไดรฟ์จะถามรหัสผ่านปัจจุบันของคุณก่อน ดังนั้นเตรียมไว้ให้พร้อม หากการเปลี่ยนแปลงถูกขัดจังหวะ ให้เรียกใช้ _Drive Encryption_ อีกครั้ง: มันจะถามรหัสผ่านที่ปลดล็อกไดรฟ์อยู่ในตอนนี้ และทำการเปลี่ยนแปลงให้เสร็จสมบูรณ์

## การส่งต่อเครื่องที่คุณใช้งานไปแล้ว

หากคุณกำลังส่งมอบเครื่องของคุณให้คนอื่น คุณไม่จำเป็นต้องติดตั้งใหม่ เรียกใช้ _Remove > Factory Reset_ ในเมนู Omarchy พิมพ์ `reset` เพื่อยืนยัน ป้อนรหัสผ่านการเข้ารหัสไดรฟ์ของคุณหากถูกถาม และรีบูต การทำเช่นนี้จะลบบัญชีผู้ใช้ทุกบัญชีและทุกอย่างใน `/home` ทิ้งแพ็กเกจและการเปลี่ยนแปลงระบบทั้งหมดที่คุณทำตั้งแต่การติดตั้ง และล้างตัวตนของเครื่อง — การเชื่อมต่อเครือข่าย, host keys และทั้งหมด สิ่งที่จะกลับขึ้นมาคือตัวช่วยตั้งค่าจากการบูตครั้งแรก พร้อมให้เจ้าของใหม่ป้อนชื่อ รหัสผ่าน และรหัสผ่านการเข้ารหัสของตนเอง

มันทำงานโดยการคืนค่าสแนปช็อตพื้นฐานที่ตัวติดตั้งบันทึกไว้ ดังนั้นจึงใช้ได้เฉพาะบนเครื่องที่ติดตั้งจาก Omarchy ISO เท่านั้น และบนไดรฟ์ที่ไม่มีการเข้ารหัส การรีเซ็ตเป็นเพียงการลบมากกว่าการลบอย่างปลอดภัย ดังนั้นหากข้อมูลนั้นมีความละเอียดอ่อน ให้ทำการติดตั้งใหม่ตั้งแต่ต้นแทน

## Passwordless sudo

บางครั้งคุณก็ต้องการให้ `sudo` เลิกถามรหัสผ่าน ซึ่งพบบ่อยที่สุดเมื่อเอเจนต์ AI กำลังทำงานระบบให้คุณเป็นเวลานาน _Setup > Security > Passwordless Sudo_ จะถามว่าจะอนุญาตให้เข้าถึงได้นานแค่ไหน: **15 นาที**, **1 ชั่วโมง**, **1 วัน** หรือ **ถาวร** ไอคอนคำเตือนสีแดงจะปรากฏอยู่ข้างตัวบ่งชี้อื่น ๆ บนแถบเมนูในขณะที่การเข้าถึงกำลังทำงานอยู่ คลิกที่ไอคอนนั้นหรือเรียกใช้คำสั่งอีกครั้งเพื่อปิดการเข้าถึง คุณยังสามารถระบุจำนวนนาทีของคุณเอง (ตั้งแต่ 1 ถึง 1440) ได้ด้วย `omarchy-sudo-passwordless 30` หรือใช้ `omarchy-sudo-passwordless permanent`

การเข้าถึงแบบมีกำหนดเวลาจะหมดอายุโดยอัตโนมัติ รวมถึงทันทีหลังจากกลับมาจากการพักเครื่องที่ข้ามกำหนดเส้นตายไปแล้ว การรีสตาร์ทคอมพิวเตอร์จะยุติการเข้าถึงก่อนกำหนด การเข้าถึงแบบถาวรจะคงอยู่ข้ามการรีบูตและยังคงเปิดใช้งานอยู่จนกว่าคุณจะปิดใช้งาน

การอัปเดตหรือการลบแพ็กเกจการตั้งค่าของ Omarchy จะยุติการอนุญาตชั่วคราวใด ๆ ก่อนที่การสนับสนุนการหมดอายุของมันจะเปลี่ยนแปลง หากคำสั่งรายงานข้อผิดพลาดเกี่ยวกับการอนุญาตหรือการล้างข้อมูล ให้แก้ไขก่อนที่จะพยายามเปิดใช้งานการอนุญาตอื่น ข้อผิดพลาดไม่ได้หมายความว่าการเข้าถึงแบบไม่ใช้รหัสผ่านจะไม่ทำงาน

จงมองเรื่องนี้อย่างชัดแจ้ง: ในขณะที่มันเปิดอยู่ อะไรก็ตามที่ทำงานในฐานะผู้ใช้ของคุณสามารถทำอะไรก็ได้ในฐานะ root โดยที่ไม่มีใครถาม นั่นคือจุดประสงค์ทั้งหมด และนั่นก็คือความเสี่ยงทั้งหมดเช่นกัน

## คีย์สำหรับลงนาม

คีย์สาธารณะสำหรับลายเซ็น ISO ทั้งหมดและแพ็กเกจในที่เก็บของ Omarchy คือ `40DFB630FF42BCFFB047046CF0134EE680CAC571` ([ตรวจสอบที่ openpgp.org](https://keys.openpgp.org/search?q=pkgs%40omarchy.org)) แพ็กเกจ `omarchy/omarchy-keyring` มีคีย์นี้อยู่ด้วยเช่นกัน และจะถูกใช้เพื่อเผยแพร่การอัปเดตที่อาจเกิดขึ้นในอนาคตอย่างราบรื่น

คุณสามารถค้นหาลายเซ็นสำหรับ ISO รีลีสใด ๆ ได้โดยการเพิ่ม `.sig` ต่อท้าย URL ของมัน เช่น `https://iso.omarchy.org/omarchy-x.x.x.iso.sig`
