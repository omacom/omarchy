# ความปลอดภัย

Omarchy ให้ความสำคัญกับความปลอดภัยอย่างจริงจังที่สุด นี่คือระบบปฏิบัติการที่ตั้งใจให้คุณใช้ทำ _งานจริง_ ใน _โลกจริง_ ที่ซึ่งการทำแล็ปท็อปหายต้องไม่กลายเป็นเหตุฉุกเฉินด้านความปลอดภัย นี่คือสิ่งที่เราทำ:

1. *การเข้ารหัสทั้งดิสก์เป็นข้อบังคับ*: นี่คือขั้นตอนที่สำคัญที่สุดในการรักษาความปลอดภัยทางกายภาพของข้อมูลของคุณ หากคอมพิวเตอร์ของคุณสูญหายหรือถูกขโมย ข้อมูลจะถูกเข้ารหัสอย่างสมบูรณ์โดยใช้ LUKS (Linux Unified Key Setup) มาตรฐาน
2. *Firewall เปิดใช้งานเป็นค่าเริ่มต้น*: ทราฟฟิกขาเข้าทั้งหมดถูกบล็อกเป็นค่าเริ่มต้น ยกเว้นพอร์ต 53317 สำหรับ [LocalSend](https://localsend.org/) แม้แต่ ssh ก็ปิดอยู่จนกว่าคุณจะเปิดผ่าน _Setup > Security > SSHD_ ซึ่งจะเปิดพอร์ต 22 (จำกัดอัตราต่อการเดาสุ่มแบบ brute force) เป็นส่วนหนึ่งของการตั้งค่า เรายังล็อกการเข้าถึง Docker โดยใช้การตั้งค่า [ufw-docker](https://github.com/chaifeng/ufw-docker) เพื่อป้องกันไม่ให้คอนเทนเนอร์ของคุณเผลอเปิดเผยออกสู่โลกโดยไม่ตั้งใจ
3. *Arch มีอัปเดตล่าสุดเสมอ*: Arch ดิสโทรพื้นฐานที่ Omarchy สร้างขึ้นต่อยอด เป็นดิสโทรแบบ rolling ซึ่งหมายความว่าช่องโหว่ด้านความปลอดภัยใดๆ ที่ถูกค้นพบและได้รับการแพตช์ในแพ็กเกจใดๆ จะพร้อมให้ติดตั้งได้อย่างรวดเร็วโดยใช้ `omarchy-update` คุณจะใช้เวอร์ชันล่าสุดและปลอดภัยที่สุดของทุกอย่างอยู่เสมอด้วยวิธีนั้น
4. *Omarchy ดูแลแพ็กเกจและ mirror ของตัวเอง*: Omarchy พึ่งพาเฉพาะแพ็กเกจจาก repository core/extra/multilib ของ Arch เองและ Omarchy Package Repository ของตัวเองเป็นค่าเริ่มต้น คุณสามารถติดตั้งซอฟต์แวร์โดยตรงจาก AUR ได้ แต่การติดตั้งพื้นฐานไม่ได้ทำแบบนั้น — มีเพียงการติดตั้งเสริมไม่กี่รายการ เช่น เบราว์เซอร์ของบุคคลที่สาม ที่ดึงมาจาก AUR
5. *Cloudflare ปกป้องเราจาก DDoS*: โครงสร้างพื้นฐานสำหรับการเผยแพร่ Omarchy — ISO ต่างๆ แพ็กเกจ Omarchy และ mirror ของ Arch — ได้รับการปกป้องอยู่เบื้องหลังเกราะป้องกัน DDoS อันแข็งแกร่งของ Cloudflare และโฮสต์อยู่บน CDN ของพวกเขา ซึ่งให้ความพร้อมใช้งานที่ยอดเยี่ยม

## การเปลี่ยนรหัสผ่านของคุณ

คุณมีรหัสผ่านสองชุดในการติดตั้งแบบเข้ารหัส: ชุดหนึ่งสำหรับปลดล็อกไดรฟ์ตอนบูต และอีกชุดสำหรับล็อกอินและใช้ `sudo` การตั้งค่าจะทำให้ทั้งสองชุดเหมือนกัน ทั้งสองชุดเปลี่ยนได้ภายใต้ _Update > Password_ ในเมนู Omarchy — _Drive Encryption_ สำหรับชุดแรก _User_ สำหรับชุดที่สอง การเปลี่ยนรหัสผ่านไดรฟ์จะถามรหัสผ่านปัจจุบันก่อน ดังนั้นเตรียมไว้ให้พร้อม หากการเปลี่ยนแปลงถูกขัดจังหวะ ให้เรียก _Drive Encryption_ อีกครั้ง: ระบบจะถามรหัสผ่านที่ปลดล็อกไดรฟ์ในขณะนี้ และทำการเปลี่ยนแปลงให้เสร็จสิ้น

## การส่งต่อเครื่องที่คุณเคยใช้งานแล้ว

หากคุณกำลังส่งมอบเครื่องของคุณให้คนอื่น คุณไม่จำเป็นต้องติดตั้งใหม่ เรียก _Setup > Reset Computer_ ในเมนู Omarchy พิมพ์ `reset` เพื่อยืนยัน แล้วรีบูต การทำเช่นนี้จะลบบัญชีผู้ใช้ทุกบัญชีและทุกอย่างใน `/home` ทิ้งแพ็กเกจและการเปลี่ยนแปลงระบบทั้งหมดที่คุณทำตั้งแต่ติดตั้ง และล้างข้อมูลระบุตัวตนของเครื่อง — การเชื่อมต่อเครือข่าย host keys และทุกอย่าง สิ่งที่จะกลับขึ้นมาคือตัวช่วยตั้งค่าจากการบูตครั้งแรก พร้อมให้เจ้าของใหม่กรอกชื่อ รหัสผ่าน และรหัสผ่านการเข้ารหัสของตัวเอง

วิธีนี้ทำงานโดยการคืนค่า snapshot พื้นฐานที่ตัวติดตั้งบันทึกไว้ ดังนั้นจึงใช้ได้เฉพาะกับเครื่องที่ติดตั้งจาก Omarchy ISO เท่านั้น และบนไดรฟ์ที่ไม่มีการเข้ารหัส การรีเซ็ตเป็นเพียงการลบ ไม่ใช่การลบอย่างปลอดภัย ดังนั้นหากข้อมูลนั้นมีความละเอียดอ่อน ให้ติดตั้งใหม่ตั้งแต่ต้นแทน

## sudo แบบไม่ต้องใช้รหัสผ่าน

บางครั้งคุณต้องการให้ `sudo` เลิกถาม ส่วนใหญ่มักเป็นตอนที่ AI agent กำลังทำงานระบบให้คุณเป็นเวลานาน _Setup > Security > Passwordless Sudo_ จะถามว่าจะอนุญาตการเข้าถึงนานแค่ไหน: **15 minutes**, **1 Hour**, **1 Day**, หรือ **Permanently** ไอคอนคำเตือนสีแดงจะปรากฏข้างตัวบ่งชี้อื่นๆ ในแถบเมนูขณะที่การเข้าถึงยังทำงานอยู่ คลิกที่ไอคอนนั้นหรือเรียกคำสั่งอีกครั้งเพื่อปิดการเข้าถึง คุณยังสามารถกำหนดจำนวนนาทีของคุณเอง (ตั้งแต่ 1 ถึง 1440) ด้วย `omarchy-sudo-passwordless 30` หรือใช้ `omarchy-sudo-passwordless permanent` ได้

การเข้าถึงแบบมีกำหนดเวลาจะหมดอายุโดยอัตโนมัติ รวมถึงทันทีหลังจากกลับมาจาก suspend ที่ข้ามกำหนดเวลาไปแล้ว การรีสตาร์ทเครื่องจะสิ้นสุดการเข้าถึงก่อนเวลา การเข้าถึงแบบถาวรจะคงอยู่ข้ามการรีบูตและเปิดใช้งานต่อไปจนกว่าคุณจะปิดใช้งาน

การอัปเดตหรือลบแพ็กเกจการตั้งค่าของ Omarchy จะสิ้นสุดการอนุญาตชั่วคราวใดๆ ก่อนที่การรองรับการหมดอายุของมันจะเปลี่ยนแปลง หากคำสั่งรายงานข้อผิดพลาดเกี่ยวกับการอนุญาตหรือการล้างข้อมูล ให้แก้ไขก่อนที่จะพยายามเปิดใช้งานการอนุญาตอีกครั้ง ข้อผิดพลาดไม่ได้หมายความว่าการเข้าถึงแบบไม่ต้องใช้รหัสผ่านไม่ทำงาน

จงมองเรื่องนี้ให้ชัดเจน: ขณะที่มันเปิดอยู่ อะไรก็ตามที่ทำงานในฐานะผู้ใช้ของคุณสามารถทำอะไรก็ได้ในฐานะ root โดยไม่ถูกถาม นั่นคือจุดประสงค์ทั้งหมด และนั่นก็คือความเสี่ยงทั้งหมดเช่นกัน

## คีย์เซ็นกำกับ

คีย์สาธารณะสำหรับลายเซ็น ISO ทั้งหมดและแพ็กเกจ repo ของ Omarchy คือ `40DFB630FF42BCFFB047046CF0134EE680CAC571` ([ตรวจสอบที่ openpgp.org](https://keys.openpgp.org/search?q=pkgs%40omarchy.org)) แพ็กเกจ `omarchy/omarchy-keyring` มีคีย์นี้อยู่ด้วยเช่นกัน และจะถูกใช้เพื่อเผยแพร่การอัปเดตที่อาจมีขึ้นอย่างราบรื่น

คุณสามารถค้นหาลายเซ็นสำหรับ ISO รีลีสใดๆ ได้โดยการเพิ่ม `.sig` ต่อท้าย URL ของมัน เช่น `https://iso.omarchy.org/omarchy-x.x.x.iso.sig`
