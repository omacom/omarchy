# ความปลอดภัย

Omarchy ให้ความสำคัญกับความปลอดภัยอย่างจริงจังที่สุด นี่คือระบบปฏิบัติการที่ตั้งใจให้คุณใช้ทำ _งานจริง_ ใน _โลกจริง_ ได้ โดยที่การทำแล็ปท็อปหายต้องไม่กลายเป็นเหตุฉุกเฉินด้านความปลอดภัย นี่คือสิ่งที่เราทำ:

1. *การเข้ารหัสทั้งดิสก์เปิดใช้งานเป็นค่าเริ่มต้น*: นี่คือขั้นตอนที่สำคัญที่สุดในการปกป้องข้อมูลของคุณในเชิงกายภาพ หากคอมพิวเตอร์ของคุณสูญหายหรือถูกขโมย ข้อมูลจะถูกเข้ารหัสอย่างสมบูรณ์โดยใช้ LUKS (Linux Unified Key Setup) มาตรฐาน ตัวติดตั้งให้คุณเลือกไม่ใช้ได้สำหรับเครื่องแบบใช้แล้วทิ้ง (ดู [เริ่มต้นใช้งาน](02-getting-started.md)) การติดตั้งที่ไม่มีการเข้ารหัสจะไม่มีการป้องกันนี้เลย และใครก็ตามที่ถือไดรฟ์อยู่สามารถอ่านข้อมูลในนั้นได้
2. *ไฟร์วอลล์เปิดใช้งานเป็นค่าเริ่มต้น*: ทราฟฟิกขาเข้าทั้งหมดถูกบล็อกเป็นค่าเริ่มต้น โดยมีข้อยกเว้นเพียงไม่กี่อย่าง: พอร์ต 53317 สำหรับ [LocalSend](https://localsend.org/) คำขอ DNS ไปยังตัวแก้ไขชื่อของคอมพิวเตอร์เองที่ที่อยู่ Docker bridge (172.17.0.1) ซึ่งยอมรับจากช่วงที่อยู่ส่วนตัวที่ Docker มอบให้คอนเทนเนอร์ของตน และ multicast DNS (พอร์ต 5353) ซึ่งช่วยให้เครื่องพิมพ์และอุปกรณ์อื่น ๆ บนเครือข่ายของคุณค้นหากันเจอ และยังประกาศชื่อคอมพิวเตอร์ของคุณที่นั่นด้วย นอกเหนือจากนั้น ไฟร์วอลล์ยังคงข้อยกเว้นมาตรฐานของ UFW สำหรับ ping การรับที่อยู่จากเราเตอร์ของคุณ (DHCP) และการค้นหา UPnP ไว้ แม้แต่ ssh ก็ยังปิดอยู่จนกว่าคุณจะเปิดผ่าน _ตั้งค่า > ความปลอดภัย > SSHD_ ซึ่งจะเปิดพอร์ต 22 (จำกัดอัตราเพื่อป้องกันการเดารหัสแบบ brute force) เป็นส่วนหนึ่งของการตั้งค่า เรายังล็อกการเข้าถึง Docker โดยใช้การตั้งค่า [ufw-docker](https://github.com/chaifeng/ufw-docker) เพื่อป้องกันไม่ให้คอนเทนเนอร์ของคุณถูกเปิดเผยสู่โลกภายนอกโดยไม่ตั้งใจ
3. *Arch มีอัปเดตล่าสุดเสมอ*: Arch ซึ่งเป็นดิสโทรพื้นฐานที่ Omarchy สร้างขึ้นมานั้น เป็นดิสโทรแบบ rolling ซึ่งหมายความว่าช่องโหว่ด้านความปลอดภัยใด ๆ ที่ถูกค้นพบและแก้ไขในแพ็กเกจใด ๆ จะพร้อมให้ติดตั้งได้อย่างรวดเร็วโดยใช้ `omarchy-update` คุณจึงใช้งานทุกอย่างในเวอร์ชันล่าสุดและปลอดภัยที่สุดอยู่เสมอด้วยวิธีนี้
4. *Omarchy ดูแลแพ็กเกจและ mirror ของตัวเอง*: โดยค่าเริ่มต้น Omarchy พึ่งพาเฉพาะแพ็กเกจจาก repository core/extra/multilib ของ Arch เองและ Omarchy Package Repository ของตัวเองเท่านั้น คุณสามารถติดตั้งซอฟต์แวร์โดยตรงจาก AUR ได้ แต่การติดตั้งพื้นฐานจะไม่ทำเช่นนั้น มีเพียงการติดตั้งเสริมเพียงไม่กี่อย่าง เช่น เบราว์เซอร์จากภายนอก ที่ดึงมาจาก AUR
5. *Cloudflare ปกป้องเราจาก DDoS*: โครงสร้างพื้นฐานสำหรับการแจกจ่ายของ Omarchy — ISO ต่าง ๆ แพ็กเกจของ Omarchy และ Arch mirror — ได้รับการปกป้องอยู่เบื้องหลังเกราะป้องกัน DDoS อันแข็งแกร่งของ Cloudflare และโฮสต์อยู่บน CDN ของพวกเขา ซึ่งให้ availability ที่ยอดเยี่ยม

## การเปลี่ยนรหัสผ่านของคุณ

ในการติดตั้งแบบเข้ารหัส คุณมีรหัสผ่านสองชุด: ชุดหนึ่งสำหรับปลดล็อกไดรฟ์ตอนบูต และอีกชุดหนึ่งสำหรับเข้าสู่ระบบและใช้ `sudo` การตั้งค่าจะทำให้ทั้งสองชุดเหมือนกัน ทั้งสองชุดเปลี่ยนได้ภายใต้ _อัปเดต > รหัสผ่าน_ ในเมนู Omarchy — _การเข้ารหัสไดรฟ์_ สำหรับชุดแรก และ _ผู้ใช้_ สำหรับชุดที่สอง การเปลี่ยนรหัสผ่านไดรฟ์จะขอรหัสผ่านปัจจุบันก่อน ดังนั้นเตรียมไว้ให้พร้อม หากการเปลี่ยนถูกขัดจังหวะ ให้เรียกใช้ _การเข้ารหัสไดรฟ์_ อีกครั้ง ระบบจะขอรหัสผ่านที่ปลดล็อกไดรฟ์อยู่ในตอนนี้ และทำการเปลี่ยนให้เสร็จสมบูรณ์

## การส่งต่อเครื่องที่คุณใช้งานแล้ว

หากคุณกำลังส่งมอบเครื่องของคุณให้คนอื่น คุณไม่จำเป็นต้องติดตั้งใหม่ เรียกใช้ _ตั้งค่า > รีเซ็ตคอมพิวเตอร์_ ในเมนู Omarchy พิมพ์ `reset` เพื่อยืนยัน แล้วรีบูต การทำเช่นนี้จะลบบัญชีผู้ใช้ทุกบัญชีและทุกอย่างใน `/home` ทิ้งแพ็กเกจและการเปลี่ยนแปลงระบบทั้งหมดที่คุณทำตั้งแต่ติดตั้ง และล้างตัวตนของเครื่อง — การเชื่อมต่อเครือข่าย host keys และทั้งหมด สิ่งที่จะกลับขึ้นมาคือวิซาร์ดการตั้งค่าจากการบูตครั้งแรก พร้อมให้เจ้าของคนใหม่ป้อนชื่อ รหัสผ่าน และรหัสผ่านการเข้ารหัสของตัวเอง

วิธีนี้ทำงานโดยการกู้คืน snapshot พื้นฐานที่ตัวติดตั้งบันทึกไว้ จึงใช้ได้เฉพาะกับเครื่องที่ติดตั้งจาก Omarchy ISO เท่านั้น และบนไดรฟ์ที่ไม่มีการเข้ารหัส การรีเซ็ตคือการลบ ไม่ใช่การลบอย่างปลอดภัย ดังนั้นหากข้อมูลนั้นมีความละเอียดอ่อน ให้ติดตั้งใหม่ตั้งแต่ต้นแทน

## sudo แบบไม่ใช้รหัสผ่าน

บางครั้งคุณก็อยากให้ `sudo` เลิกถามรหัสผ่าน ซึ่งพบบ่อยที่สุดเมื่อเอเจนต์ AI กำลังทำงานระบบให้คุณเป็นเวลานาน _ตั้งค่า > ความปลอดภัย > Sudo แบบไม่ใช้รหัสผ่าน_ จะถามว่าจะอนุญาตการเข้าถึงนานเท่าใด: **15 นาที**, **1 ชั่วโมง**, **1 วัน** หรือ **ถาวร** ไอคอนคำเตือนสีแดงจะปรากฏข้างตัวบ่งชี้อื่น ๆ บนแถบเมนูขณะที่การเข้าถึงยังทำงานอยู่ คลิกที่ไอคอนนั้นหรือเรียกใช้คำสั่งอีกครั้งเพื่อปิดการเข้าถึง คุณยังสามารถระบุจำนวนนาทีของคุณเอง (ตั้งแต่ 1 ถึง 1440) ได้ด้วย `omarchy-sudo-passwordless 30` หรือใช้ `omarchy-sudo-passwordless permanent`

การเข้าถึงแบบมีกำหนดเวลาจะหมดอายุโดยอัตโนมัติ รวมถึงทันทีหลังจากกลับมาจากการ suspend ที่ข้ามเส้นตายไปแล้ว การรีสตาร์ตคอมพิวเตอร์จะยุติการเข้าถึงก่อนกำหนด ส่วนการเข้าถึงแบบถาวรจะคงอยู่ข้ามการรีบูต และจะเปิดใช้งานต่อไปจนกว่าคุณจะปิดใช้งาน

การอัปเดตหรือการลบแพ็กเกจการตั้งค่าของ Omarchy จะยุติการอนุญาตชั่วคราวใด ๆ ก่อนที่การรองรับการหมดอายุของมันจะเปลี่ยนแปลง หากคำสั่งรายงานข้อผิดพลาดด้านการอนุญาตหรือการล้างข้อมูล ให้แก้ไขก่อนที่จะพยายามเปิดใช้งานการอนุญาตอื่น ข้อผิดพลาดไม่ได้หมายความว่าการเข้าถึงแบบไม่ใช้รหัสผ่านไม่ได้ทำงานอยู่

จงมองเรื่องนี้ให้ชัดเจน: ขณะที่มันเปิดอยู่ ทุกอย่างที่ทำงานในฐานะผู้ใช้ของคุณสามารถทำอะไรก็ได้ในฐานะ root โดยไม่ต้องถูกถาม นั่นคือจุดประสงค์ทั้งหมด และนั่นก็คือความเสี่ยงทั้งหมดเช่นกัน
