# Инструменти за разработка

## Алтернативни редактори

Omarchy се доставя с [Neovim](https://neovim.io/) по подразбиране, но ако искате нещо малко по-масово и познато, можете да стартирате Omarchy Menu (`Super + Space`) и да видите опциите под _Install > Editor_. Там са изброени VSCode, Cursor, Zed, Sublime Text, Helix, Vim и Emacs. Ако не намирате това, което търсите, разгледайте _Install > Package_ и вижте дали го няма в пакет на Arch (а ако го няма, опитайте _Install > AUR_, за да проверите AUR).

Оригиналният редактор `vi` също е наличен още от самото начало. Стартирайте `vi filename`, за да редактирате файл в терминала.

Съответствие на темата се предлага за `VSCode`, `Cursor`, `VSCodium` и `Helix`.

Можете да зададете редактора по подразбиране за цялата система под `Setup > Defaults > Editor`.

## Среда

Omarchy поддържа настройването на цяла поредица от среди за разработка чрез секцията _Install > Development_ на Omarchy Menu (`Super + Space`). Разбира се, ще намерите _Ruby on Rails_, но също и трите основни среди за изпълнение за JavaScript (Node.js, Bun, Deno), както и популярни PHP рамки като Laravel и Symfony. О, а има също Go, Rust, Python, Java, Elixir (с Phoenix), .NET, OCaml, Zig, Clojure и Scala. Изборът е много широк!

Повечето от тези среди се управляват от [Mise](https://mise.jdx.dev/). Това е инструмент, който ви позволява да инсталирате и стартирате няколко версии на един език за програмиране на една и съща машина. Прилича на rbenv или rvm за Ruby или virtualenv за Python, но работи за куп различни среди.

За да инсталирате, да речем, Ruby, стартирате `mise use -g ruby`, което едновременно ще инсталира Ruby и ще го зададе като глобална стойност по подразбиране. Или, ако проектът ви има файл .ruby-version, можете просто да стартирате `mise i` в корена на този проект.

## Предварително инсталирани CLI инструменти

Omarchy предоставя инструменти като `gh`, `uv` и повечето [агенти за програмиране](17-ai.md) чрез [lazy инсталацията на mise](https://mise.jdx.dev/dev-tools/shims.html#lazy-tools). Първия път, когато стартирате някой от тях, mise го инсталира. При по-късни стартирания се използва повторно инсталираната версия; те не проверяват за актуализация при всяко стартиране.

Можете също да прегледате стойностите по подразбиране или да ги инсталирате предварително:

```bash
mise ls --current              # List the tools configured for this directory
mise install gh               # Install one tool now
mise install --include-lazy    # Install all configured tools, including lazy tools
```

Стартирайте `omarchy update`, за да актуализирате инсталираните инструменти заедно с останалата част от Omarchy. Псевдонимът `mup` актуализира само инструментите, управлявани от mise. За да добавите друг инструмент към собствената си конфигурация, използвайте `mise use -g <tool>`.

Настройката на Python също инсталира `uv` чрез mise. Премахването на средата за разработка с Python оставя `uv` наличен като независим инструмент.

### Използване на собствена инсталация

Командите на mise стоят преди `~/.local/bin` в `PATH`, така че инструмент, който сте инсталирали сами, например със собствения инсталатор на Claude Code или Cursor, все пак стартира копието на mise. Приложенията, стартирани от работния плот, също намират командите на mise преди системните пакети, така че приложение, което стартира `gh`, получава копието на mise, дори ако сте инсталирали `github-cli` с pacman, а mise инсталира това копие при първото стартиране. За да използвате вашето вместо това, деактивирайте копието на mise в `~/.config/mise/config.toml`. Например, ако сте инсталирали Cursor CLI сами:

```toml
[settings]
disable_tools = ["cursor-agent"]
```

Ако вече имате таблица `[settings]`, добавете записа там; разширете съществуващ списък `disable_tools`, вместо да го заменяте. Уверете се, че вашата инсталация е в `PATH`. Използвайте името на инструмента в mise, което може да се различава от командата му: например `oh-my-pi` предоставя `omp`. Стартерът за агента по подразбиране също предпочита инсталирани от потребителя Cursor или Muse в `~/.local/bin`.

### Премахване и възстановяване на стойностите по подразбиране

_Remove Preinstalls_ кара mise да пропуска декларациите на инструментите на Omarchy за вашия потребител, като ги добавя към `ignored_config_paths` в `~/.config/mise/miserc.toml`. _Restore Preinstalls_ отново премахва този ред. Инструментите, които декларирате сами, в собствената си конфигурация или в `mise.toml` на проект, продължават да работят и в двата случая. Ако изберете агент по подразбиране или настроите Python след премахване на предварително инсталираните инструменти, този инструмент се добавя към собствената ви конфигурация. И двете се прилагат само за вашия потребител; другите потребители на машината запазват собствения си избор.

## Docker

[Docker](https://www.docker.com/) едва ли се нуждае от представяне. Той ви позволява да стартирате изолирани контейнери, а Omarchy инсталира всичко необходимо, за да работи добре, включително самия Docker и [Docker Compose](https://docs.docker.com/compose/).

По подразбиране вашият потребител *не* е в групата `docker`. Тази група на практика дава root без парола — всичко в нея може да изпълни `docker run -v /:/host` и да превземе машината — така че един-единствен злонамерен скрипт или зависимост, стартирани от ваше име, иначе биха били само на една команда от root. Затова в командния ред стартирате Docker със `sudo` (`sudo docker ps`, `sudo docker compose up`), а графичните инструменти, които комуникират с демона — Windows VM — искат разрешение, когато им е необходимо. Ако искате удобството на настройка без група обратно и разбирате компромиса, активирайте я от **Setup > Security > Sudoless Docker** (или стартирайте `omarchy-setup-security-sudoless-docker`), което ви добавя към групата `docker` след предупреждение; тогава обикновеното `docker` и псевдонимът `d` отново работят без `sudo`.

Можете да настроите обичайните бази данни за локална разработка в Docker чрез _Install > Development > Docker DB_ в менюто на Omarchy.

## GitHub CLI

[GitHub CLI](https://cli.github.com/) е наличен като `gh` за работа с хранилища, issues и pull requests от терминала. Стартирайте `gh auth login`, за да го инсталирате при първо използване и да се удостоверите, след това `gh repo clone org/repo`, за да клонирате хранилище. Стартирайте `gh --help`, за да разгледате командите му.

За терминален интерфейс към pull requests стартирайте `ghui`; mise също го инсталира при първо използване. [Lazygit](https://github.com/jesseduffield/lazygit) е предварително инсталиран за работа със самия Git.
