# Инсталации без присъствие

ISO образът на Omarchy може да се инсталира сам, без никой пред клавиатурата. Ако инсталаторът открие второ устройство с етикет `cidata`, което носи конфигурационните му файлове, той ги копира, пропуска изцяло съветника за настройка и сам се рестартира в завършената система. Не е нужна специална компилация на ISO образа, нито допълнителен запис в менюто за зареждане — ако няма прикачено такова устройство, нищо не се променя и получавате обичайния съветник.

Това прави Omarchy чудесна основа за еднократни среди за разработка: създавате VM в Proxmox или с Packer, стартирате я, отдалечавате се, влизате през SSH. `cidata` е етикетът `NoCloud` на cloud-init, така че всички обичайни инструменти за виртуализация вече знаят как да прикачат такова устройство.

## Конфигурационните файлове

Файловете са точно това, което пише самият съветник на инсталатора, така че най-лесният начин да получите начален набор е да изпълните една интерактивна инсталация (например във VM) и да копирате това, което е записал в `/root`:

| Файл | Задължителен | Цел |
|------|----------|---------|
| `user_configuration.json` | Да | Диск, име на хост, часова зона, клавиатура |
| `user_credentials.json` | Да | Потребителско име и хеш на паролата, както и паролата за LUKS при криптирана инсталация |
| `user_encrypt_installation.txt` | Не | `true`, когато конфигурацията носи блок `disk_encryption` |
| `authorized_keys` | Не | Публични SSH ключове, по един на ред |
| `tailscale_authkey` | Не | Ключ за удостоверяване в Tailscale за присъединяване към вашия tailnet при първото стартиране |

Генерирайте хеша на паролата за `user_credentials.json` с `openssl passwd -6 "yourpassword"`.

Името и имейлът за git комити не са част от инсталацията. Настройте ги, след като машината заработи, например през SSH, с `omarchy setup git --name "Jane Doe" --email jane@example.com`.

Можете също да поставите празен файл с име `defer-provisioning` на мястото на `user_credentials.json`. Това изпълнява същата [инсталация с подготовка за друг собственик](02-getting-started.md), която можете да задействате интерактивно: машината се инсталира без лични данни, а този, който я стартира пръв, избира клавиатурата си и създава своя потребител. Това е режимът за машини за създаване на образи, при които устройството изобщо не трябва да носи ничии идентификационни данни.

## SSH достъп

Когато присъства `authorized_keys`, инсталацията настройва ключовете като `~/.ssh/authorized_keys` на потребителя, активира `sshd` и отваря защитната стена за него. (Стандартната инсталация на Omarchy се доставя с openssh с деактивирана услуга и затворен порт, така че машина без присъствие иначе би била недостъпна.) Инсталацията само добавя вашите ключове — не отслабва никоя от останалите настройки за удостоверяване на SSH демона.

Когато присъства `tailscale_authkey`, машината вместо това се присъединява към вашия tailnet при първото стартиране: Tailscale се инсталира от пакетите, включени в ISO образа, защитната стена разрешава интерфейса на tailnet, а фонова задача изпълнява присъединяването веднага щом машината действително има мрежа, като опитва отново, докато успее. Използвайте ключ за многократна употреба с предварително разрешение, така че един образ на устройство да може да обслужва много машини.

## Създаване на устройството cidata

Всяка файлова система с правилния етикет работи. Малък ISO образ е лесният начин:

```bash
mkdir cidata
cp user_configuration.json user_credentials.json authorized_keys cidata/
genisoimage -output cidata.iso -volid cidata -joliet -rock cidata/
```

След това го прикачете към VM заедно с ISO образа на Omarchy. Ето пълен пример за Proxmox:

```bash
qm create 101 --name my-omarchy \
  --bios ovmf --machine q35 --cpu host --cores 4 --memory 8192 \
  --ostype l26 --scsihw virtio-scsi-single \
  --efidisk0 local-lvm:0,efitype=4m,pre-enrolled-keys=0 \
  --scsi0 local-lvm:40,discard=on,iothread=1 \
  --net0 virtio,bridge=vmbr0 --vga virtio --serial0 socket \
  --ide2 local:iso/omarchy.iso,media=cdrom \
  --ide3 local:iso/cidata.iso,media=cdrom \
  --boot order='scsi0;ide2'

qm start 101
```

Редът за зареждане поставя диска на първо място нарочно: празният диск преминава към ISO образа при първото стартиране, а инсталираната система оттам нататък винаги се зарежда от диска.

## Две предупреждения

Криптираните инсталации без присъствие не са напълно без присъствие — някой все пак трябва да въведе паролата за LUKS при първото стартиране. И тази парола се поставя на най-горното ниво на `user_credentials.json` като `encryption_password` — archinstall я чете оттам, а не от блока `disk_encryption` в `user_configuration.json` — така че третирайте устройство cidata, създадено от криптирана инсталация, като тайната, която е.
