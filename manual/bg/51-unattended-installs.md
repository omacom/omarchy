# Инсталации без надзор

ISO образът на Omarchy може да се инсталира сам, без никой пред клавиатурата. Ако инсталаторът намери второ устройство с етикет `cidata`, носещо конфигурационните му файлове, той ги копира, пропуска изцяло съветника за настройка и сам се рестартира в готовата система. Не е нужен специален ISO образ, нито допълнителен запис в менюто за зареждане — ако такова устройство не е свързано, нищо не се променя и получавате обикновения съветник.

Това прави Omarchy чудесен базов образ за еднократни среди за разработка: създавате VM в Proxmox или с Packer, стартирате я, отдалечавате се и влизате през SSH. `cidata` е етикетът `NoCloud` на cloud-init, така че всички разпространени инструменти за виртуализация вече знаят как да свържат такова устройство.

## Конфигурационните файлове

Файловете са точно това, което пише собственият съветник на инсталатора, така че най-лесният начин да получите начален комплект е да направите една интерактивна инсталация (например във VM) и да копирате това, което е записал в `/root`:

| Файл | Задължителен | Предназначение |
|------|----------|---------|
| `user_configuration.json` | Да | Диск, име на хост, часова зона, клавиатура |
| `user_credentials.json` | Да | Потребителско име и хеш на паролата |
| `user_encrypt_installation.txt` | Не | `true`, когато конфигурацията съдържа блок `disk_encryption` |
| `authorized_keys` | Не | Публични SSH ключове, по един на ред |
| `tailscale_authkey` | Не | Ключ за удостоверяване в Tailscale за присъединяване към вашия tailnet при първо стартиране |

Генерирайте хеша на паролата за `user_credentials.json` с `openssl passwd -6 "yourpassword"`.

Името и имейлът за git комити не са част от инсталацията. Задайте ги, след като машината заработи, например през SSH, с `omarchy setup git --name "Jane Doe" --email jane@example.com`.

Можете също да поставите празен файл с име `defer-provisioning` на мястото на `user_credentials.json`. Това изпълнява същата [инсталация за подготовка за друг собственик](02-getting-started.md), която можете да стартирате и интерактивно: машината се инсталира без никакви лични данни, а който я стартира пръв, избира клавиатурата си и създава своя потребител. Това е режимът за станции за създаване на образи, където устройството изобщо не трябва да носи нечии данни за вход.

## Достъп през SSH

Когато `authorized_keys` присъства, инсталацията настройва ключовете като `~/.ssh/authorized_keys` на потребителя, активира `sshd` и отваря защитната стена за него. (Стандартната инсталация на Omarchy се доставя с openssh с изключена услуга и затворен порт, така че машина без надзор иначе би била недостъпна.) Инсталацията само добавя вашите ключове — не отслабва никоя от останалите настройки за удостоверяване на SSH демона.

Когато присъства `tailscale_authkey`, машината вместо това се присъединява към вашия tailnet при първо стартиране: Tailscale се инсталира от пакетите, включени в ISO образа, защитната стена разрешава интерфейса на tailnet, а фонов процес извършва присъединяването веднага щом машината действително има мрежа, като повтаря опитите, докато успее. Използвайте многократен, предварително оторизиран ключ, за да може един образ на устройство да обслужва много машини.

## Създаване на устройството cidata

Всяка файлова система с правилния етикет върши работа. Малък ISO образ е лесният начин:

```bash
mkdir cidata
cp user_configuration.json user_credentials.json authorized_keys cidata/
genisoimage -output cidata.iso -volid cidata -joliet -rock cidata/
```

След това го свържете към VM заедно с ISO образа на Omarchy. Ето пълен пример за Proxmox:

```bash
qm create 101 --name my-omarchy \
  --bios ovmf --machine q35 --cpu host --cores 4 --memory 8192 \
  --ostype l26 --scsihw virtio-scsi-single \
  --efidisk0 local-lvm:0,efitype=4m,pre-enrolled-keys=0 \
  --scsi0 local-lvm:40,discard=on,iothread=1 \
  --net0 virtio,bridge=vmbr0 --vga virtio --serial0 socket \
  --ide2 local:iso/omarchy.iso,media=cdrom \
  --ide3 local:iso/cidata.iso,media=cdrom \
  --boot order='scsi0;ide2'

qm start 101
```

Редът на зареждане умишлено поставя диска на първо място: при първото стартиране празният диск преминава към ISO образа, а след това инсталираната система винаги се зарежда от диска.

## Две предупреждения

Криптираните инсталации без надзор не са напълно без надзор — все пак някой трябва да въведе паролата за LUKS при първото стартиране. А блокът `disk_encryption` в `user_configuration.json` носи тази парола в открит текст, така че третирайте устройство cidata, създадено от криптирана инсталация, като тайната, която всъщност е.
