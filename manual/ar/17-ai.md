# الذكاء الاصطناعي

تتضمّن Omarchy مشغّلات لوكلاء البرمجة أدناه دون أن تختار لك وكيلًا افتراضيًا. شغّل أمرًا لتثبيت واجهة سطر الأوامر الخاصة به عند أول استخدام، ثم قم بالمصادقة عند مطالبتك بذلك. Hermes هو الاستثناء: لا يُثبَّت له أي شيء عند أول استخدام، واختياره يثبّت Hermes Desktop، كما يشرح قسم _تطبيقات سطح المكتب_ أدناه.

### تثبيت الوكلاء وتحديثهم

باستثناء Hermes، يستخدم هؤلاء الوكلاء التثبيت الكسول من mise: التثبيت الأول يثبّت واجهة سطر الأوامر، والتشغيلات اللاحقة تعيد استخدامها. تتحقق mise أيضًا من وجود إصدار جديد لوكيل مثبّت مرة واحدة على الأكثر كل أربع ساعات، قبل أن يبدأ مباشرة أو في الخلفية عند موجّه shell. إذا فشل ذلك التحديث أو كنت غير متصل، تعمل النسخة المثبّتة. يحدّث `omarchy update` الوكلاء المثبّتين مع بقية Omarchy، ويحدّث `mup` الأدوات التي تديرها mise فقط.

أداة التحديث الخاصة بالوكيل نفسه، مثل `claude update` أو `codex update` أو زر تحديث في تطبيق، لا تحدّث التثبيت الذي تديره mise. يفشل `codex update`، ويمكن أن يبلّغ `claude update` عن نجاح بينما يثبّت نسخة منفصلة لا تتتبعها mise. إذا كنت تفضّل استخدام مثبّت الوكيل وأداة تحديثه الأصليين، فأضفه إلى `disable_tools`؛ راجع [أدوات CLI المثبّتة مسبقًا](18-development-tools.md#preinstalled-cli-tools).

لتثبيت جميع الأدوات الكسولة التي تم إعدادها قبل أن تحتاج إليها، شغّل `mise install --include-lazy`. يشمل هذا أدوات CLI الافتراضية الأخرى في Omarchy إضافة إلى الوكلاء. راجع [أدوات CLI المثبّتة مسبقًا](18-development-tools.md#preinstalled-cli-tools) لتثبيت أداة واحدة أو استخدام تثبيتك الخاص.

يُثبَّت `grok` عبر حزمة `grok` الرسمية من mise، بالطريقة نفسها مثل `claude` و`codex`. شغّل `grok`، أو اختره تحت _Agent > Harness_. تجاوز مثبّت `curl | bash` على x.ai. ذلك المسار يضع نسخة ثانية في `~/.grok/bin`، ويقدّمها على `PATH`، ويستبدل غلاف Omarchy.

يفتح `dsh` واجهة المتصفح الخاصة به على `127.0.0.1:3080`، مع دليل التشغيل كمساحة عمل افتراضية له. واجهة المتصفح الخاصة به لا تقبل توجيهًا ابتدائيًا، لذا يفتحها `omarchy agent prompt` مع وضع التوجيه في حافظتك لتلصقه. تبدأ Omarchy تشغيله بإعداد إذن DeepSeek المسبق بدون موافقة. يرفع DeepSeek Harness سجلات الجلسة إلى DeepSeek عندما تستخدم واجهة برمجة تطبيقات نموذجه الرسمية؛ عطّل ذلك تحت _Settings > General > Upload Session Log_ في واجهة المتصفح الخاصة به. تُرفع الملاحظات التي ترسلها إليه مع الجلسة أيضًا، ما لم تبدأه بـ `DSH_TELEMETRY_MODE=DISABLED`.

### الوكيل الافتراضي

اختر وكيلك الافتراضي بـ `omarchy default agent <name>` أو تحت _Agent > Harness_ في قائمة Omarchy (`Super + Space`). إذا لم يكن الوكيل مثبّتًا بعد، فإن اختياره يثبّته أولًا. ستدعوك Omarchy جديدة لاتخاذ هذا الاختيار بإشعار يظهر مرة واحدة.

اختيار Claude يحاول أيضًا إعداد إضافة المتصفح الخاصة به لـ Chromium وChrome وBrave وBrave Origin وEdge. ينطبق إعداد الإضافة على جميع المستخدمين وقد يطلب كلمة مرور نظامك؛ إلغاء تثبيت الإضافة أو فشله لا يزال يختار Claude ويشغّله. أعد تشغيل متصفحك، فعّل الإضافة إذا طُلب منك ذلك، وسجّل الدخول إلى Claude لإنهاء توصيلها. شغّل `/chrome` في Claude للتحقق من الاتصال. لا يدعم Firefox وZen هذه الإضافة. إذا كان Claude وكيلك الافتراضي بالفعل قبل إضافة هذا الإعداد، فاختره مرة أخرى لتثبيت الإضافة.

بمجرد أن تختار، يشغّل `Super + Shift + Ctrl + A` الوكيل الافتراضي في نافذة طرفية مخصصة (أو يعرض المنتقي إذا لم تكن قد اخترت بعد). يمكنك أيضًا تشغيله مباشرة في مهمة بـ `omarchy agent prompt "Review this project"`. لا يقبل Freebuff وDeepSeek Harness توجيهًا ابتدائيًا، لذا يفتحان مع وضع التوجيه في حافظتك لتلصقه بدلًا من ذلك. يعمل الوكلاء الذين يُشغَّلون بهذه الطريقة دون مراقبة في أوضاع عدم التوقف للسؤال الخاصة بكل منهم، لذا كن مستعدًا لقيامهم بأشياء فعليًا! ليس لدى MiniMax Code مثل هذا الوضع لجلساته التفاعلية، لذا يطلب الأذونات كالمعتاد. وبما أن الوكلاء يرفضون تذكّر الثقة لدليلك الرئيسي، تبدأ عمليات التشغيل من `$HOME` في `~/Work` بدلًا من ذلك.

توجد اختصارات طرفية أيضًا: يشغّل `a` الوكيل الافتراضي بشكل مضمّن في الطرفية الحالية، بينما يبدأ `c` و`cx` و`cy` كلًا من OpenCode وClaude Code وCodex مباشرة (مرة أخرى في أوضاع الموافقة التلقائية الخاصة بهم). تتزامن تغييرات السمة مع الوكلاء أيضًا: يتبع Claude Code وPi وOpenCode وHermes (بمجرد أن تثبّته Omarchy) جميعًا عندما تبدّل سمة Omarchy.

### تعليمات وكيلك

تذهب القواعد الشخصية لكل وكيل في `~/.agents/AGENTS.md`، بجوار المهارات المشتركة في `~/.agents/skills`. افتحها تحت _Agent > Instructions_، التي تربطها أيضًا بكل بيئة تشغيل تحتفظ بملفها العالمي الخاص: `~/.claude/CLAUDE.md` و`~/.codex/AGENTS.md` و`~/.pi/agent/AGENTS.md` و`~/.config/opencode/AGENTS.md` و`~/.copilot/copilot-instructions.md` الخاص بـ Copilot، وهكذا. يقرأ Crush وAmp رابط `~/.config/AGENTS.md`، بينما يقرأ omp وKimi وDeepSeek Harness `~/.agents/AGENTS.md` مباشرة. اختيار وكيل افتراضي يربطه أيضًا. يصبح ملف تعليمات كان لديك بالفعل هو الملف المشترك إذا لم يكن يوجد واحد بعد؛ وإلا يُحتفظ به بجوار الرابط باسم `.bak`. شغّل `omarchy agent instructions` لإعادة الربط بعد تثبيت وكيل آخر.

### لوحة الوكلاء

يحتوي الشريط العلوي على أيقونة وكلاء. قبل أن تُعدّ وكيلًا، ترشدك لوحته خلال تسجيل الدخول إلى Claude أو Codex أو Grok، ويصبح الأول وكيلك الافتراضي. بعد ذلك، تضع اللوحة كل اشتراك في صفحة واحدة: كل وكيل وحساب مع خطته، وعدّاد لكل من حدود جلسته البالغة 5 ساعات وحدوده الأسبوعية مع الوقت حتى إعادة تعيينه (مرّر للاطلاع على النسبة المئوية الدقيقة)، أو الرصيد المدفوع مسبقًا المتبقي، تحت سطر يتناوب عبر ما استخدمته عبرهم جميعًا، مثل الرموز هذا الأسبوع ونموذجك الأكثر استخدامًا. تحت _Make something_ تقدّم توجيهات بداية لموضوع أو إضافة أو تطبيق أو لعبة جديدة تسلّم المهمة إلى وكيلك الافتراضي. تُبنى التطبيقات بالطريقة التي بُنيت بها تطبيقات Omarchy الخاصة Hype وMonologue وOmacut، بلغة C++ وQt Quick، باتباع مهارة وكيل omarchy-app، ويأتي المترجم وأجزاء Qt التي تحتاجها مثبّتة. الألعاب عبارة عن صفحة three.js واحدة في `~/Games/vibes`، باتباع مهارة وكيل web-game، وتفتح جميعًا من مشغّل Game Vibes واحد في السمة الحالية؛ وهي تحمّل three.js من الويب، لذا تحتاج إلى اتصال للبدء. يتم تغطية Claude Code وCodex وGrok وKimi وCursor وحصة Grok Bot الخاصة به وGitHub Copilot وClaude وAntigravity وKimchi وDevin جاهزة مع حدودهم، ويعرض Hermes وMistral Vibe وQwen Code جلساتهم ورموزهم بمجرد استخدامك لهم. تظهر أيضًا خطط ومفاتيح المزودين التي تستخدمها عبر pi أو omp أو opencode: OpenCode Zen وGo وخطة Z.ai GLM Coding Plan وOllama Cloud وخطة MiniMax Token Plan وSynthetic مع حدودهم؛ وFireworks وOpenRouter وDeepSeek مع أرصدتهم المدفوعة مسبقًا؛ والنماذج التي تشغّلها على أجهزتك الخاصة تحت النماذج المحلية. يُحسب كل وكيل مرة واحدة، تحت من يفوتره، مهما كان عدد بيئات التشغيل التي تديره من خلالها.

انقر بزر الماوس الأيسر على أيقونة الشريط للوحة، وانقر بزر الماوس الأيمن لتشغيل وكيلك الافتراضي. تُعاد توليد سجلات الاستخدام التي تقف وراءها كل 15 دقيقة بواسطة `omarchy agent usage-update`، ويمكن للوحة حتى دمج الاستخدام من أجهزتك الأخرى عبر مجلد متزامن. راجع README تحت `$OMARCHY_PATH/shell/plugins/agents/` للإعدادات الكاملة.

### اشتراكات متعددة

إذا كنت تدفع مقابل أكثر من خطة Claude أو Codex أو Grok واحدة — خطة Max شخصية وخطة عمل، على سبيل المثال — يمكن لـ Omarchy إبقاءهم جميعًا مسجّلين وتتنقل بينهم. أضف اشتراكًا بعلامة + في لوحة الوكلاء، التي ترشدك خلال ذلك هناك مباشرة، أو بـ `omarchy agent account add claude Work` (أو `codex`، أو `grok`). يثبّت واجهة سطر الأوامر إذا كانت مفقودة. يسجّل الحساب الأول لمزود الدخول عبر متصفحك العادي، حيث تبحث واجهة سطر الأوامر دائمًا. كل حساب بعد ذلك يسجّل الدخول عبر نافذة خاصة، بحيث لا يُلتقط الحساب الذي سجّل متصفحك الدخول إليه بالفعل عن طريق الخطأ؛ سجّل الدخول هناك كالحساب الذي تضيفه، وأغلق أي نافذة خاصة مفتوحة لديك بالفعل أولًا. لا تسجّل الخروج أبدًا من واجهة سطر الأوامر للقيام بذلك: تسجيل الخروج يلغي تسجيل الدخول المحفوظ، وسيتعيّن إضافة ذلك الحساب مرة أخرى.

لنسخ معلومات تسجيل دخول اشتراكك إلى جهاز Omarchy آخر عبر SSH، شغّل `omarchy agent account copy user@laptop`. يوفّر المرسل مستقبلًا مؤقتًا عندما لا يكون لدى الوجهة واحد مثبّت، بحيث يمكن لأجهزة Omarchy الأقدم تلقي الحسابات دون تحديث. للمستقبلات المثبّتة الأسبقية. ينسخ هذا جميع اشتراكات Claude وCodex وGrok؛ أضف أسماء المزودين لاختيارهم، كما في `omarchy agent account copy laptop claude`. تطابق أسماء الحسابات ومعرّفات الأوامر المصدر، بما في ذلك الحسابات الموجودة بالفعل على الوجهة. تتلقى حسابات الوجهة غير ذات الصلة لاحقة رقمية إذا تعارضت أسماؤها، وتبقى الإعدادات والمهارات والإضافات وسجل المحادثات محلية لكل جهاز.

تُحفظ بيانات اعتماد الوجهة الحالية. الحساب المصدري المسجّل بالفعل هناك تُزامَن تسميته دون استبدال بيانات اعتماده؛ وتُضاف حسابات أخرى بجانبه. لاستبدال بيانات الاعتماد المحفوظة للحسابات المطابقة، استخدم `omarchy agent account copy --replace laptop claude` بعد إنهاء جلسات ذلك الحساب على الوجهة. تحصل الوجهة الجديدة أيضًا على الحساب النشط وتفضيلات التبديل للمصدر؛ تحتفظ الوجهة القائمة بتفضيلاتها الخاصة.

تنتقل بيانات الاعتماد عبر SSH وتُحفظ في ملفات خاصة على الوجهة، لذا انسخ فقط إلى أجهزة تثق بها. هذه نسخة لمرة واحدة، وليست مزامنة مستمرة. يمكن لجهاز آخر تدوير رموز تحديث Codex، ما يترك تسجيل دخول منسوخًا بحاجة إلى تجديد؛ تبقى عمليات تسجيل الدخول المنفصلة الخيار الأكثر موثوقية للاستخدام المتزامن على عدة أجهزة. راجع [إرشادات Codex لمصادقة الحساب](https://developers.openai.com/codex/auth/ci-cd-auth).

حساب واحد لكل مزود نشط، وكل جلسة جديدة تبدأ به: `cx` و`cy` و`claude` أو `codex` أو `grok` العادي، وأي شيء يُشغَّل عبر `omarchy agent`، والبرامج النصية أو المحررات التي تجد واجهة سطر الأوامر على `PATH`. بدّل بـ `omarchy agent account use work` (وعُد بـ `omarchy agent account use main`)، أو في اللوحة بالضغط على رقم حساب ثم `Enter` (أو النقر على زر Use الخاص به). تتبدّل جلسات Claude قيد التشغيل أيضًا، بدءًا من رسالتها التالية: كل جلسة Claude تعمل في `~/.claude`، التي تحتفظ دائمًا بتسجيل دخول الحساب النشط. جلسة Claude بدأت في مجلد حساب خاص بها بواسطة Omarchy أقدم تحتفظ بتسجيل الدخول ذلك حتى تنتهي، لذا يسمّي التبديل تلك الجلسات وينتهي من تلقاء نفسه بمجرد اختفائها. تبقى جلسات Codex وGrok قيد التشغيل على الحساب الذي بدأت به. يُشارك سجل المحادثات والإعدادات والمهارات والإضافات عبر الحسابات، لذا يستأنف `claude --continue` في المجلد نفسه من حيث توقفت على الحساب الجديد.

مع وجود أكثر من حساب، تعرض اللوحة حدود كل حساب جنبًا إلى جنب، مع تمييز الحساب النشط. افتراضيًا تُعلمك Omarchy عندما يتجاوز الحساب النشط 95% من حد ما، والنقر على الإشعار يبدّل إلى الحساب الذي لديه أكبر مساحة متاحة. مرّر فوق سطر حساب في اللوحة وانقر على Autoswitch الذي يظهر بجوار Use (أو اضغط `m`)، أو شغّل `omarchy agent account mode auto`، لجعله يبدّل من تلقاء نفسه بدلًا من ذلك؛ بينما هو مفعّل، يحل Autoswitch محل Use، والنقر عليه مرة أخرى يعود إلى الإشعار. أضف رقمًا لتغيير العتبة، كما في `omarchy agent account mode auto 90`. إذا كان كل حساب فوق العتبة، فستسمع عن ذلك مرة واحدة، مع أي حساب سيتحرر أولًا. بينما يكون الحساب النشط ضمن 15 نقطة من عتبته (80% افتراضيًا)، تُفحص حدوده كل ثلاث دقائق بدلًا من كل 15.

يعرض `omarchy agent account list` كل حساب وحدوده الأخيرة، وينسى `omarchy agent account remove work` واحدًا، ويعيد `omarchy agent account rename primary Hey` تسمية واحد (أو انقر على اسم حساب في اللوحة). تعمل هذه الأوامر على حسابات وكيلك الافتراضي؛ للوصول إلى المزود الآخر، سمّه أولًا، كما في `omarchy agent account use codex side`. تسجيل الدخول الذي كان لديك بالفعل في `~/.claude` أو `~/.codex` هو حساب _Main_. يبقى حساب Codex حيث هو؛ وينتظر حساب Claude في مجلد خاص به بينما يكون حساب آخر نشطًا. يمكن أن يعرض حساب تُرك دون استخدام لأكثر من حوالي ثماني ساعات _Sign-in required_؛ انقر عليه لتسجيل دخول ذلك الحساب مرة أخرى مباشرة في اللوحة، أو بدّل إليه وابدأ جلسة، ما ينعش تسجيل الدخول من تلقاء نفسه. تصل خوادم MCP التي تضيفها بـ `claude mcp add` إلى كل حساب Claude، لأنها جميعًا تعمل في `~/.claude`؛ بالنسبة إلى Codex وGrok، تأتي الخوادم التي كانت لديك عند إضافة حساب معها إليه، لكن الخوادم اللاحقة تصل فقط إلى الحساب الذي أضفتها فيه. يحتفظ Claude Desktop بتسجيل دخول خاص به، والأدوات Codex أو Grok التي تم إعدادها بمسار مطلق لثنائي واجهة سطر أوامر لا تتبع التبديل. يأخذ `CLAUDE_CONFIG_DIR` أو `CODEX_HOME` أو `GROK_HOME` الصريح الأسبقية على الحساب المحدد.

### تشخيص التوقّف المفاجئ

تراقب Omarchy systemd-coredump لتوقّفات العمليات المفاجئة. عندما يحدث خطأ تجزئة لشيء ما، ستحصل على إشعار "Process crashed" — انقر عليه، ويُسلَّم التوقّف إلى وكيلك الافتراضي مع مهارة diagnose-crash في Omarchy، التي ترشد الوكيل خلال إثبات الحقائق من تفريغ النواة وتقرير ما إذا كان التوقّف يستحق الإبلاغ عنه في المصدر. يمكنك أيضًا تشغيله يدويًا مقابل أي PID من `coredumpctl list` بـ `omarchy agent crash <pid>`.

المراقبة مفعّلة افتراضيًا. عطّلها تحت _Trigger > Toggle > Crash Capture_ (أو بـ `omarchy toggle crash-capture`) وتتوقف الإشعارات؛ يبقى `omarchy agent crash <pid>` يعمل يدويًا.

يمكن أيضًا إسكات التوقّفات برنامجًا واحدًا في كل مرة، وهو ما يعرضه التشخيص عليك في النهاية. يوقف `omarchy crash mute hyprland` الإشعارات لذلك البرنامج فقط، ويعيدها `omarchy crash mute hyprland off`، ويسرد `omarchy crash mute` بمفرده ما أسكتّه. يقبل مسار الثنائي بسعادة مثل اسمه، لذا يفعل `omarchy crash mute /usr/bin/hyprland` الشيء نفسه. ضع اسمًا يحتوي على مسافة بين علامتي اقتباس، كما في `omarchy crash mute 'Some App'`. يستمر كل شيء آخر في الإشعار، ويستمر البرنامج المُسكَت في التوقّف — هذا يخفي التذكير، ولا يصلح أي شيء.

### تطبيقات سطح المكتب

تحمل قائمة _Install > AI_ أيضًا بعض تطبيقات الذكاء الاصطناعي الرسومية: تطبيق ChatGPT لسطح المكتب، وتطبيق Claude لسطح المكتب (نسخة Linux التجريبية من Anthropic، مع علامات تبويب Chat وCowork وClaude Code)، وGrok Bot للدردشة مع نماذج xAI، وHerdr Desktop، وHermes Desktop، وOpenClaw، وتطبيق Perplexity لسطح المكتب، وT3 Code. Grok Bot هو تطبيق الدردشة لسطح المكتب. وكيل البرمجة هو أمر `grok`.

Hermes Desktop هو الذي يجب أن تعرفه، لأن الجهاز لديه Hermes واحد، وهو الخاص بالتطبيق: لا يُثبَّت Hermes أبدًا إلا عبر التطبيق، وأمر `hermes` الذي يشغّله الوكيل الافتراضي هو الخاص بالتطبيق. اختيار Hermes كوكيل افتراضي يثبّت الشيء نفسه الذي يثبّته إدخال _Install > AI_: الحزمة، ووقت تشغيل Hermes تحت `~/.hermes` يُعدّه مثبّت Hermes نفسه، الذي يستغرق بضع دقائق في المرة الأولى. وقت التشغيل ذلك هو Hermes الواحد الذي تستخدمه جميعًا أمر `hermes` الطرفي والوكيل الافتراضي والتطبيق، ويحدّث نفسه بـ `hermes update` بدلًا من انتظار إصدار Omarchy. تثبيته يمنح Hermes أيضًا سمة Omarchy كجلد باسم `omarchy`، تتبعه كل أسطح Hermes أثناء تبديلك للسمات؛ اختر آخر تحت إعدادات Appearance في Hermes أو بـ `/skin` إذا كنت تفضّل ألا يفعل، وستترك Omarchy ذلك الاختيار وشأنه. إزالة التطبيق تحت _Remove > AI_ تغلق Hermes أولًا، بما في ذلك البوابة، وتأخذ وقت التشغيل ذلك معها، وتحتفظ بدردشاتك وذكرياتك والمهارات التي كتبها Hermes لنفسه ما لم تخبره بخلاف ذلك: يسأل، مع افتراض لا، عما إذا كان يجب أن تذهب تلك البيانات وإعدادات اتصالك أيضًا.

تجربة OpenClaw لسطح المكتب هي واجهة Control UI الخاصة به، التي تفتح كتطبيق ويب مدعوم ببوابته المحلية الخاصة. يعيش OpenClaw في `~/.openclaw` ويحدّث نفسه: استخدم زر "Update Gateway" في Control UI أو شغّل `openclaw update`، وتُعاد تشغيل البوابة على الإصدار الجديد. تختار Omarchy فقط الإصدار الذي يبدأ منه تثبيت جديد. إزالة OpenClaw تحت _Remove > AI_ تأخذ خدمة البوابة والتطبيق معها ثم تسأل عما إذا كان يجب أن يذهب `~/.openclaw` أيضًا، لأن ذلك يحتفظ بدردشاتك وبيانات اعتمادك بجانب OpenClaw نفسه وأوقات تشغيل الإضافات التي ينزّلها؛ الافتراضي يحتفظ به، وتثبيت OpenClaw مرة أخرى يلتقطه من جديد.

Herdr Desktop هو تطبيق [Herdr](https://herdr.dev) لسطح المكتب: مساحات وعلامات تبويب وألواح من الطرفيات ووكلاء البرمجة التي تستمر في العمل في نواته عندما تغلق النافذة. يأتي من مثبّت Herdr نفسه بدلًا من حزمة، لذا يعيش في `~/.local/share/herdr-app`، ويجلب نواته معه في `~/.local/bin/herdr-core` عندما لا يكون لديك واحد بعد، ويحدّث كليهما نفسه. يجلس بجانب أمر `herdr` الذي تشحنه Omarchy على `Super + Ctrl + Return` بدلًا من استبداله، ويحصل على مفاتيح ذلك الأمر المباشرة: يقسّم `Alt + Return` و`Alt + Shift + Return` لوحًا لأسفل أو لليمين، ويغلقه `Alt + Escape`، وينقل `Ctrl + Alt + Arrow` بين الألواح، ويختار `Alt + 1..9` و`Alt + Left/Right` علامة تبويب، وينقل `Alt + Up/Down` بين المساحات. يختار `Ctrl + 1..9` مساحة ويتنقّل `Alt + Shift + Up/Down` عبر الوكلاء. تبقى مفاتيح بادئة `Ctrl + Space` للطرفية فقط، لأن التطبيق لا يمكنه الاحتفاظ بمفتاح Ctrl عادي لتسلسل. تكتب Omarchy هذه إلى `~/.config/herdr-app/keys.json`، ويعيدها `omarchy-refresh-herdr-app`. تثبيته يختار سمة Omarchy في Herdr، التي تتبع سمة Omarchy الخاصة بك من ذلك الحين فصاعدًا. يحتفظ Herdr بسمة واحدة للوضع الفاتح وواحدة للوضع الداكن، لذا بعد التبديل بين سمة Omarchy داكنة وفاتحة، اختر Omarchy في منتقي سمات Herdr مرة أخرى للوضع الآخر.

يعمل T3 Code من إصدار AppImage الرسمي الخاص به في `~/.local/share/t3code` بدلًا من حزمة، لذا يحدّث نفسه. تثبيته يسأل عما إذا كنت تريد البدء على قناة Stable أو Nightly؛ بدّل لاحقًا في إعدادات T3 Code. تعيش سلاسل محادثاتك وإعداداتك في `~/.t3`، وإزالة T3 Code تحت _Remove > AI_ تأخذها معه.

### النماذج المحلية

شغّل نموذجًا مفتوحًا على جهازك الخاص لوكلاء البرمجة لديك. تبقى توجيهاتك وشيفرتك على الجهاز؛ لا شيء يُرسل إلى النموذج يغادره. ابدأ بـ:

```bash
omarchy agent local use best
```

أو، في لوحة الوكلاء في الشريط العلوي، اختر + ثم Local AI، التي تظهر عندما يناسب نموذج هذا الجهاز. في المرة الأولى، يثبّت هذا Podman، الذي يشغّل النماذج، وعلى جهاز NVIDIA مجموعة أدوات حاويات NVIDIA، التي تمنحهم GPU. ثم تختار Omarchy النموذج الموصى به لهذا الجهاز، وتنزّله، وتبدأه. توقّع تنزيلًا بعشرات GB وأن تكون معظم ذاكرة الجهاز قيد الاستخدام أثناء تشغيل النموذج: يستخدم Flash Next حوالي 100 GiB مع سياقه الكامل البالغ 256K. إذا احتفظت نماذج أخرى بالذاكرة التي يحتاجها، يُعدّ متوقفًا، جاهزًا للبدء بمجرد إيقافك لواحد. يتوقف النموذج عند تسجيل الخروج؛ أوقفه بنفسك عندما تحتاج الذاكرة لشيء آخر.

يعرض `omarchy agent local list` الخيارات ويشرح سبب عدم ملاءمة بعضها. لإعداد آخر، شغّل `omarchy agent local use <recipe>`. اليوم، يتوفر `qwen3.8-flash-next-gufo` و`qwen3.8-27b-gufo` لأجهزة Strix Halo بسعة 128 GB؛ يأخذ 27B حوالي 40 GiB، لذا يترك مساحة لأعمال أخرى. على حاسوب محمول بسعة 64 GB مع Intel's Arc B390، يعمل `qwen3.6-35b-a3b-llamacpp` في حوالي 30 GiB. تصل الوصفات والتوصيات الجديدة مع `omarchy update`، عبر الحزمة.

يحصل كل نموذج تُعدّه على سطره الخاص في لوحة الوكلاء، بجوار اشتراكاتك: تشغيل لبدئه، وإيقاف مؤقت لإيقافه وتحرير ذاكرته، وزر الطرفية لفتح وكيلك عليه. يمكن تشغيل عدة نماذج في وقت واحد عندما تناسب الذاكرة معًا؛ إذا لم يناسب واحد، تخبرك Omarchy بأي نموذج قيد التشغيل يجب إيقافه. اسحب السطور لإعادة ترتيبها، واضغط Delete على سطر محدد لإزالة نموذج وتنزيله.

يحصل كل نموذج تُعدّه أيضًا على إدخاله الخاص في مشغّل التطبيقات، تحت اسم النموذج ومع شعار صانعه، بالطريقة التي يضيف بها تسجيل الدخول إلى Claude أو Codex أو Grok واحدًا. يفتح وكيلك على ذلك النموذج، ويبدأ النموذج أولًا إذا لم يكن قيد التشغيل: تعرض الطرفية تحميله وتسلّم إلى الوكيل بمجرد أن يصبح جاهزًا. إزالة نموذج تزيل إدخاله.

من سطر الأوامر، يفعل `omarchy agent local start <recipe>` و`omarchy agent local stop <recipe>` الشيء نفسه، ويعرض `omarchy agent local status` كل نموذج، ويفتح `omarchy agent --local` وكيلك الافتراضي على آخر نموذج بدأته. يمكن لـ pi وOpenCode وQwen Code استخدام واحد؛ مع أي افتراضي آخر يفتح في pi. يسرد pi أيضًا كل نموذج أعددته، وتلك الموجودة على أجهزة اقترنت بها، في منتقي نماذجه الخاص، بحيث يصل إليها `pi` العادي أيضًا. يمكن لأي عميل متوافق مع OpenAI الاتصال أيضًا: يعرض `status` عنوان كل نموذج (الأول هو `http://127.0.0.1:11435/v1`)، واسم الوصفة هو النموذج، والمفتاح في `~/.config/omarchy/agent-local/key`.

يحذف `omarchy agent local remove <recipe>` نموذجًا والتنزيلات التي لا يستخدمها أي نموذج آخر.

تُوسم أوقات تشغيل الطرف الثالث بناشرها. تشغّل Omarchy كل نموذج دون وصول إلى الشبكة.

### نماذج LLM المحلية

توصي Omarchy بطريقتين لتشغيل نماذج LLM محلية: LM Studio وOllama. يوفّر LM Studio واجهة GUI للعثور على نماذج ذات أوزان مفتوحة وتثبيتها وتشغيلها. إنها طريقة رائعة للبدء بسهولة. يقدّم Ollama واجهة CLI للقيام بذلك بالمثل. لكن إذا كنت جديدًا على النماذج المحلية، سأبدأ بـ LM Studio. يمكنك تثبيت أي منهما تحت _Install > AI_ في قائمة Omarchy.

### مهارة Omarchy

تساعد مهارات الوكيل الذكاء الاصطناعي على استخدام أدوات محددة بطريقة محددة، وتشحن Omarchy مهارة افتراضية لتكييف النظام. مثل تعديل إعداد Hyprland الخاص بك، أو ضبط الشريط، أو حتى إنشاء سمة جديدة من الصفر. تُربط رمزيًا في دلائل مهارات Claude Code (`~/.claude/skills`) وCodex (`~/.codex/skills`) وPi (`~/.pi/agent/skills`) وAntigravity (`~/.gemini/config/skills`) وHermes (`~/.hermes/skills` وكل `~/.hermes/profiles/*/skills`)، وموقع `~/.agents/skills` العام، بحيث تلتقطها معظم بيئات التشغيل تلقائيًا.

لكن يجب أن تعامل هذه المهارة على أنها تجريبية. ستستخدمها نماذج مختلفة بتأثيرات مختلفة. من الأفضل تشغيلها في وضع الخطة أولًا، بحيث تكون لديك فكرة عما يرغب الوكيل في تغييره. ثم كن مستعدًا للتراجع عن التغييرات أو حتى استدعاء `omarchy reinstall configs`، إذا أحدث الوكيل فوضى في كل شيء.
