# الذكاء الاصطناعي

تتضمن Omarchy مشغّلات لوكلاء البرمجة أدناه دون أن تختار لك واحدًا افتراضيًا. شغّل أمرًا لتثبيت CLI الخاص به عند أول استخدام، ثم قم بالمصادقة عند مطالبتك بذلك. Hermes هو الاستثناء: لا يُثبَّت له شيء عند أول استخدام، واختياره يثبّت Hermes Desktop، كما يوضح قسم _Desktop apps_ أدناه.

### تثبيت الوكلاء وتحديثهم

باستثناء Hermes، يستخدم هؤلاء الوكلاء التثبيت الكسول من mise: أول تشغيل يثبّت CLI، والتشغيلات اللاحقة تعيد استخدامه. كما يتحقق mise من وجود إصدار جديد لوكيل مثبّت مرة واحدة على الأكثر كل أربع ساعات، قبل بدئه مباشرة أو في الخلفية عند موجه shell. إذا فشل ذلك التحديث أو كنت غير متصل بالإنترنت، يعمل الإصدار المثبّت. يحدّث `omarchy update` الوكلاء المثبّتين مع بقية Omarchy، ويحدّث `mup` الأدوات التي يديرها mise فقط.

أداة تحديث الوكيل نفسه، مثل `claude update` أو `codex update` أو زر تحديث في تطبيق، لا تحدّث التثبيت الذي يديره mise. يفشل `codex update`، ويمكن أن يفيد `claude update` بالنجاح بينما يثبّت نسخة منفصلة لا يتتبعها mise. إذا كنت تفضّل استخدام المثبّت والمحدّث الأصليين لوكيل ما، أضفه إلى `disable_tools`؛ راجع [أدوات CLI المثبتة مسبقًا](18-development-tools.md#preinstalled-cli-tools).

لتثبيت جميع الأدوات الكسولة المهيأة قبل أن تحتاجها، شغّل `mise install --include-lazy`. يشمل ذلك أدوات CLI الافتراضية الأخرى في Omarchy إضافة إلى الوكلاء. راجع [أدوات CLI المثبتة مسبقًا](18-development-tools.md#preinstalled-cli-tools) لتثبيت أداة واحدة أو استخدام تثبيتك الخاص.

يُثبَّت `grok` عبر حزمة `grok` الرسمية من mise، بالطريقة نفسها مثل `claude` و`codex`. شغّل `grok`، أو اختره تحت _Setup > Defaults > Agent_. تجاوز مثبّت `curl | bash` على x.ai. فذلك المسار يضع نسخة ثانية في `~/.grok/bin`، ويقدّمها على `PATH`، ويستبدل غلاف Omarchy.

يفتح `dsh` واجهة متصفحه على `127.0.0.1:3080`، مع دليل التشغيل بوصفه مساحة عمله الافتراضية. لا تأخذ واجهة متصفحه موجّه بدء، لذا فإن `omarchy agent prompt` يفتحه مع الموجّه في حافظتك لتلصقه. تبدأه Omarchy بإعداد أذونات DeepSeek المسبق بلا موافقة. يرفع DeepSeek Harness سجلات الجلسات إلى DeepSeek عندما تستخدم API النموذج الرسمي الخاص به؛ عطّل ذلك تحت _Settings > General > Upload Session Log_ في واجهة متصفحه. كما تُرفع الملاحظات التي ترسلها إليه مع الجلسة أيضًا، ما لم تبدأه بـ `DSH_TELEMETRY_MODE=DISABLED`.

### الوكيل الافتراضي

اختر وكيلك الافتراضي بـ `omarchy default agent <name>` أو تحت _Setup > Defaults > Agent_ في قائمة Omarchy (`Super + Space`). إذا لم يكن الوكيل مثبّتًا بعد، فإن اختياره يثبّته أولًا. ستدعوك Omarchy جديدة إلى اتخاذ هذا الخيار بإشعار لمرة واحدة.

اختيار Claude يحاول أيضًا إعداد إضافة متصفحه لـ Chromium وChrome وBrave وBrave Origin وEdge. ينطبق إعداد الإضافة على جميع المستخدمين وقد يطلب كلمة مرور نظامك؛ إلغاء تثبيت الإضافة أو فشله ما يزال يختار Claude ويشغّله. أعد تشغيل متصفحك، فعّل الإضافة إذا طُلب منك، وسجّل الدخول إلى Claude لإنهاء توصيلها. شغّل `/chrome` في Claude للتحقق من الاتصال. لا يدعم Firefox وZen هذه الإضافة. إذا كان Claude وكيلك الافتراضي أصلًا قبل إضافة هذا الإعداد، اختره مرة أخرى لتثبيت الإضافة.

بمجرد أن تختار، يشغّل `Super + Shift + Ctrl + A` الوكيل الافتراضي في نافذة طرفية مخصصة (أو يُظهر المنتقي إذا لم تكن قد اخترت بعد). يمكنك أيضًا تشغيله مباشرة في مهمة بـ `omarchy agent prompt "Review this project"`. لا يأخذ Freebuff وDeepSeek Harness موجّه بدء، لذا يفتحان مع الموجّه في حافظتك لتلصقه بدلًا من ذلك. يعمل الوكلاء المشغّلون بهذه الطريقة دون مراقبة في أوضاعهم الخاصة بعدم التوقف للسؤال، فكن مستعدًا لأن يفعلوا أشياء فعلًا! لا يملك MiniMax Code وضعًا كهذا لجلساته التفاعلية، لذا يطلب الأذونات كالمعتاد. وبما أن الوكلاء يرفضون تذكّر الثقة لدليلك الرئيسي، تبدأ عمليات التشغيل من `$HOME` في `~/Work` بدلًا من ذلك.

هناك اختصارات طرفية أيضًا: يشغّل `a` الوكيل الافتراضي مضمّنًا في الطرفية الحالية، بينما تبدأ `c` و`cx` و`cy` كلًا من OpenCode وClaude Code وCodex مباشرة (مرة أخرى في أوضاع موافقتها التلقائية). تتزامن تغييرات السمة مع الوكلاء أيضًا: Claude Code وPi وOpenCode وHermes (بمجرد أن تثبّته Omarchy) كلها تتبعك عندما تبدّل سمة Omarchy.

### لوحة الوكلاء

يوجد في الشريط العلوي أيقونة وكلاء. قبل أن تُعدّ وكيلًا، ترشدك لوحتها خلال تسجيل الدخول إلى Claude أو Codex أو Grok، ويصبح الأول وكيلك الافتراضي. بعد ذلك، تضع اللوحة كل اشتراك على صفحة واحدة: كل وكيل وحساب مع خطته، وعدّاد لكل من حده لجلسة 5 ساعات وحده الأسبوعي مع الوقت حتى إعادة تعيينه (مرّر المؤشر للنسبة الدقيقة)، أو الرصيد المدفوع مسبقًا المتبقي، تحت سطر يتناوب عبر ما استخدمته عبرها كلها، مثل الرموز هذا الأسبوع ونموذجك الأكثر استخدامًا. تحت _Make something_ تعرض موجّهات بداية لموضوع جديد أو إضافة أو تطبيق تسلّم المهمة إلى وكيلك الافتراضي. تُبنى التطبيقات بالطريقة التي بُنيت بها تطبيقات Omarchy نفسها Hype وMonologue وOmacut، بـ C++ وQt Quick، باتباع مهارة وكيل omarchy-app، والمترجم وقطع Qt التي تحتاجها تأتي مثبّتة. Claude Code وCodex وGrok وKimi وCursor وحصة Grok Bot الخاصة به وGitHub Copilot وMuse وAntigravity وKimchi وDevin مشمولة جاهزة مع حدودها، ويعرض Hermes وMistral Vibe وQwen Code جلساتهم ورموزهم بمجرد أن تستخدمهم. تظهر أيضًا خطط المزودين ومفاتيحهم التي تستخدمها عبر pi أو omp أو opencode: OpenCode Zen وGo وخطة Z.ai GLM Coding Plan وOllama Cloud وخطة MiniMax Token Plan وSynthetic مع حدودها؛ وFireworks وOpenRouter وDeepSeek مع أرصدتها المدفوعة مسبقًا؛ والنماذج التي تشغّلها على عتادك الخاص تحت Local models. يُحسَب كل وكيل مرة واحدة، تحت من يفوتره، مهما كان عدد المسخّرات التي تقوده عبرها.

انقر بالزر الأيسر على أيقونة الشريط للوحة، وانقر بالزر الأيمن لتشغيل وكيلك الافتراضي. تُعاد توليد سجلات الاستخدام خلفها كل 15 دقيقة بـ `omarchy agent usage-update`، ويمكن للوحة حتى دمج الاستخدام من أجهزتك الأخرى عبر مجلد متزامن. راجع README تحت `$OMARCHY_PATH/shell/plugins/agents/` للإعدادات الكاملة.

### اشتراكات متعددة

إذا كنت تدفع مقابل أكثر من خطة واحدة لـ Claude أو Codex أو Grok — خطة Max شخصية وخطة عمل، مثلًا — يمكن لـ Omarchy إبقاءها كلها مسجلة الدخول والتنقل بينها. أضف اشتراكًا بـ + في لوحة الوكلاء، التي ترشدك خلال ذلك هناك تمامًا، أو بـ `omarchy agent account add claude Work` (أو `codex` أو `grok`). يثبّت CLI إذا كان مفقودًا. يسجل الحساب الأول لمزود الدخول عبر متصفحك العادي، حيث يبحث CLI دائمًا تمامًا. كل حساب بعد ذلك يسجل الدخول عبر نافذة خاصة، فلا يُلتقط بالخطأ الحساب الذي سجل متصفحك الدخول إليه أصلًا؛ سجّل الدخول هناك بوصفك الحساب الذي تضيفه، وأغلق أي نافذة خاصة مفتوحة لديك أصلًا أولًا. لا تسجّل الخروج من CLI أبدًا للقيام بذلك: تسجيل الخروج يبطل تسجيل الدخول المحفوظ، وسيتعين إضافة ذلك الحساب مرة أخرى.

لنسخ تسجيلات دخول اشتراكك إلى جهاز Omarchy آخر عبر SSH، شغّل `omarchy agent account copy user@laptop`. يزوّد المرسل مستقبِلًا مؤقتًا عندما لا يكون لدى الوجهة واحد مثبّت، فتتمكن أجهزة Omarchy الأقدم من استقبال الحسابات دون تحديث. للمستقبِلات المثبتة الأسبقية. ينسخ ذلك جميع اشتراكات Claude وCodex وGrok؛ أضف أسماء المزودين لتحديدها، كما في `omarchy agent account copy laptop claude`. تطابق أسماء الحسابات ومعرفات الأوامر المصدر، بما يشمل الحسابات الموجودة أصلًا على الوجهة. تتلقى حسابات الوجهة غير ذات الصلة لاحقة رقمية إذا تعارضت أسماؤها، وتبقى الإعدادات والمهارات والإضافات وسجل المحادثات محلية لكل جهاز.

تُحفَظ بيانات اعتماد الوجهة الحالية. الحساب المصدري المسجل الدخول هناك أصلًا تُزامَن تسميته دون استبدال بيانات اعتماده؛ وتُضاف حسابات أخرى بجانبه. لاستبدال بيانات الاعتماد المحفوظة للحسابات المطابقة، استخدم `omarchy agent account copy --replace laptop claude` بعد إنهاء جلسات ذلك الحساب على الوجهة. كما تحصل الوجهة الجديدة على الحساب النشط للمصدر وتفضيلات التبديل الخاصة به؛ تحتفظ الوجهة الراسخة بتفضيلاتها الخاصة.

تنتقل بيانات الاعتماد عبر SSH وتُخزَّن في ملفات خاصة على الوجهة، فلا تنسخ إلا إلى أجهزة تثق بها. هذه نسخة لمرة واحدة، وليست مزامنة مستمرة. يمكن لجهاز آخر تدوير رموز تحديث Codex، ما يترك تسجيل دخول منسوخًا بحاجة إلى تجديد؛ تبقى تسجيلات الدخول المنفصلة الخيار الأكثر موثوقية للاستخدام المتزامن على عدة أجهزة. راجع [إرشادات Codex لمصادقة الحساب](https://developers.openai.com/codex/auth/ci-cd-auth).

حساب واحد لكل مزود نشط، وكل جلسة جديدة تبدأ به: `cx` و`cy` و`claude` أو `codex` أو `grok` العادي، وأي شيء يُشغَّل عبر `omarchy agent`، والبرامج النصية والمحررات التي تجد CLI على `PATH`. بدّل بـ `omarchy agent account use work` (وعُد بـ `omarchy agent account use main`)، أو في اللوحة بضغط رقم حساب ثم `Enter` (أو النقر على زر Use الخاص به). تبقى الجلسات قيد التشغيل أصلًا على الحساب الذي بدأت به. يُشارَك سجل المحادثات والإعدادات والمهارات والإضافات عبر الحسابات، لذا فإن `claude --continue` في المجلد نفسه يتابع من حيث توقفت على الحساب الجديد.

مع أكثر من حساب واحد، تعرض اللوحة حدود كل حساب جنبًا إلى جنب، مع تمييز النشط. افتراضيًا تنبّهك Omarchy عندما يتجاوز الحساب النشط 95% من حد ما، والنقر على الإشعار يبدّل إلى الحساب ذي أكبر هامش متاح. مرّر المؤشر على سطر حساب في اللوحة وانقر على Autoswitch الذي يظهر بجانب Use (أو اضغط `m`)، أو شغّل `omarchy agent account mode auto`، لجعله يبدّل من تلقاء نفسه بدلًا من ذلك؛ بينما هو مفعّل، تأخذ Autoswitch مكان Use، والنقر عليها مرة أخرى يعود إلى التنبيه. أضف رقمًا لتغيير العتبة، كما في `omarchy agent account mode auto 90`. إذا تجاوز كل حساب العتبة، ستسمع عن ذلك مرة واحدة، مع أي حساب يتحرر أولًا. بينما يكون حساب نشط ضمن 15 نقطة من عتبته (80% عند الافتراضي)، تُفحص حدوده كل ثلاث دقائق بدلًا من كل 15.

يعرض `omarchy agent account list` كل حساب وحدوده الأخيرة، وينسى `omarchy agent account remove work` حسابًا واحدًا، ويعيد `omarchy agent account rename primary Hey` تسمية حساب واحد (أو انقر على اسم حساب في اللوحة). تعمل هذه الأوامر على حسابات وكيلك الافتراضي؛ للوصول إلى المزود الآخر، سمّه أولًا، كما في `omarchy agent account use codex side`. تسجيل الدخول الذي كان لديك أصلًا في `~/.claude` أو `~/.codex` هو الحساب _Main_ ويبقى حيث هو. يمكن لحساب تُرك غير مستخدم لأكثر من نحو ثماني ساعات أن يعرض _Sign-in required_؛ انقر عليه لتسجيل دخول ذلك الحساب مرة أخرى في اللوحة مباشرة، أو ابدأ جلسة فيه، فتتجدّد عملية تسجيل الدخول من تلقاء نفسها. تأتي خوادم MCP التي كانت لديك عندما أُضيف حساب معه إليه، لكن التي تضيفها لاحقًا بـ `claude mcp add` تصل فقط إلى الحساب الذي أضفتها فيه. لا يتبع Claude Desktop والأدوات المهيأة بمسار مطلق إلى ملف CLI التنفيذي التبديل. يأخذ `CLAUDE_CONFIG_DIR` أو `CODEX_HOME` أو `GROK_HOME` الصريح الأسبقية على الحساب المحدد.

### تشخيص الأعطال

تراقب Omarchy systemd-coredump لأعطال العمليات. عندما يحدث خطأ تجزئة لشيء ما، ستحصل على إشعار "Process crashed" — انقر عليه، وستُسلَّم الحادثة إلى وكيلك الافتراضي مع مهارة diagnose-crash الخاصة بـ Omarchy، التي ترشد الوكيل خلال إثبات الوقائع من تفريغ النواة وتقرير ما إذا كانت الحادثة تستحق الإبلاغ عنها إلى المنبع. يمكنك أيضًا تشغيلها يدويًا مقابل أي PID من `coredumpctl list` بـ `omarchy agent crash <pid>`.

المراقبة مفعّلة افتراضيًا. عطّلها تحت _Trigger > Toggle > Crash Capture_ (أو بـ `omarchy toggle crash-capture`) وستتوقف الإشعارات؛ ما يزال `omarchy agent crash <pid>` يعمل يدويًا.

يمكن أيضًا إسكات الأعطال برنامجًا واحدًا في كل مرة، وهو ما يعرضه عليك التشخيص في النهاية. يوقف `omarchy crash mute hyprland` الإشعارات لذلك البرنامج فقط، ويعيدها `omarchy crash mute hyprland off`، ويسرد `omarchy crash mute` وحده ما كتمته. يأخذ مسار الملف التنفيذي بكل سرور مثل اسمه، لذا فإن `omarchy crash mute /usr/bin/hyprland` يفعل الشيء نفسه. ضع اسمًا فيه مسافة بين علامتي اقتباس، كما في `omarchy crash mute 'Some App'`. يستمر كل شيء آخر في الإشعار، ويستمر البرنامج المكتوم في التعطل — هذا يخفي التذكير، ولا يصلح شيئًا.

### تطبيقات سطح المكتب

تحمل قائمة _Install > AI_ أيضًا بعض تطبيقات الذكاء الاصطناعي الرسومية: تطبيق ChatGPT لسطح المكتب، وتطبيق Claude لسطح المكتب (إصدار Anthropic التجريبي لـ Linux، مع تبويبات Chat وCowork وClaude Code)، وGrok Bot للدردشة مع نماذج xAI، وHermes Desktop، وOpenClaw، وتطبيق Perplexity لسطح المكتب، وT3 Code. Grok Bot هو تطبيق الدردشة لسطح المكتب. أما وكيل البرمجة فهو أمر `grok`.

Hermes Desktop هو ما يجب أن تعرفه، لأن للجهاز Hermes واحدًا، وهو خاص بالتطبيق: لا يُثبَّت Hermes أبدًا إلا عبر التطبيق، وأمر `hermes` الذي يشغّله الوكيل الافتراضي خاص بالتطبيق. اختيار Hermes بوصفه الوكيل الافتراضي يثبّت الشيء نفسه الذي يثبّته مدخل _Install > AI_: الحزمة، وبيئة تشغيل Hermes تحت `~/.hermes` يُعدّها مثبّت Hermes نفسه، والتي تستغرق بضع دقائق في المرة الأولى. بيئة التشغيل تلك هي Hermes الواحد الذي تستخدمه أمر `hermes` في الطرفية والوكيل الافتراضي والتطبيق كلها، وتحدّث نفسها بـ `hermes update` بدلًا من انتظار إصدار Omarchy. كما يمنح تثبيتها Hermes سمة Omarchy بوصفها مظهرًا باسم `omarchy`، تتبعه كل أسطح Hermes أثناء تبديلك السمات؛ اختر مظهرًا آخر تحت إعدادات Appearance في Hermes أو بـ `/skin` إذا كنت تفضّل ألا يفعل، وستترك Omarchy ذلك الخيار وشأنه. إزالة التطبيق تحت _Remove > AI_ تغلق Hermes أولًا، البوابة مشمولة، وتأخذ بيئة التشغيل تلك معها، وتبقي محادثاتك وذكرياتك والمهارات التي كتبها Hermes لنفسه ما لم تخبره بخلاف ذلك: يسأل، وافتراضيًا لا، ما إذا كان يجب أن تذهب تلك البيانات وإعدادات اتصالك أيضًا.

تجربة OpenClaw على سطح المكتب هي واجهة Control UI الخاصة به، التي تفتح كتطبيق ويب مدعوم ببوابته المحلية الخاصة. يعيش OpenClaw في `~/.openclaw` ويحدّث نفسه: استخدم زر "Update Gateway" في Control UI أو شغّل `openclaw update`، وستعيد البوابة التشغيل على الإصدار الجديد. تختار Omarchy فقط الإصدار الذي يبدأ منه تثبيت جديد. إزالة OpenClaw تحت _Remove > AI_ تأخذ خدمة البوابة والتطبيق معها ثم تسأل ما إذا كان يجب أن يذهب `~/.openclaw` أيضًا، بما أن ذلك يحتفظ بمحادثاتك وبيانات اعتمادك بجانب OpenClaw نفسه وبيئات تشغيل الإضافات التي ينزّلها؛ الافتراضي يبقيه، وتثبيت OpenClaw مرة أخرى يلتقطه من جديد.

يعمل T3 Code من إصدار AppImage الرسمي الخاص به في `~/.local/share/t3code` بدلًا من حزمة، لذا يحدّث نفسه. يسألك تثبيته ما إذا كنت تريد البدء على قناة Stable أو Nightly؛ بدّل لاحقًا في إعدادات T3 Code. تعيش سلاسل محادثاتك وإعداداتك في `~/.t3`، وإزالة T3 Code تحت _Remove > AI_ تأخذها معها.

### نماذج LLM المحلية

توصي Omarchy بطريقتين لتشغيل نماذج LLM محلية: LM Studio وOllama. توفر LM Studio واجهة GUI للعثور على النماذج مفتوحة الأوزان وتثبيتها وتشغيلها. إنها طريقة رائعة للانطلاق بسهولة. تقدم Ollama واجهة CLI للقيام بذلك بالمثل. لكن إذا كنت جديدًا على النماذج المحلية، سأبدأ بـ LM Studio. يمكنك تثبيت أي منهما تحت _Install > AI_ في قائمة Omarchy.

### مهارة Omarchy

تساعد مهارات الوكلاء الذكاء الاصطناعي على استخدام أدوات محددة بطريقة محددة، وتأتي Omarchy مع مهارة افتراضية لتكييف النظام. مثل تعديل إعداد Hyprland الخاص بك، أو ضبط الشريط، أو حتى إنشاء سمة جديدة من الصفر. إنها مربوطة رمزيًا في دلائل مهارات Claude Code (`~/.claude/skills`) وCodex (`~/.codex/skills`) وPi (`~/.pi/agent/skills`) وAntigravity (`~/.gemini/config/skills`) وHermes (`~/.hermes/skills` وكل `~/.hermes/profiles/*/skills`)، وموقع `~/.agents/skills` العام، فتلتقطها معظم المسخّرات تلقائيًا.

لكن يجب أن تعامل هذه المهارة بوصفها تجريبية. ستستخدمها نماذج مختلفة بتأثير مختلف. من الأفضل التشغيل في وضع التخطيط أولًا، لتكون لديك فكرة عما يود الوكيل تغييره. ثم كن مستعدًا للتراجع عن التغييرات أو حتى استدعاء `omarchy reinstall configs`، إذا أحدث الوكيل فوضى في كل شيء.
