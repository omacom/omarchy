# الذكاء الاصطناعي

يتضمّن Omarchy مشغّلات لوكلاء البرمجة أدناه دون أن يختار لك واحدًا افتراضيًا. شغّل أمرًا لتثبيت واجهة سطر الأوامر الخاصة به عند أول استخدام، ثم نفّذ المصادقة عند الطلب. Hermes استثناء: لا يُثبَّت له شيء عند أول استخدام، واختياره يثبّت Hermes Desktop، كما يشرح قسم _تطبيقات سطح المكتب_ أدناه.

### تثبيت الوكلاء وتحديثهم

باستثناء Hermes، يستخدم هؤلاء الوكلاء التثبيت الكسول من mise: أول تشغيل يثبّت واجهة سطر الأوامر، والتشغيلات اللاحقة تعيد استخدامها. تتحقق mise أيضًا من وجود إصدار جديد لوكيل مثبّت مرة واحدة على الأكثر كل أربع ساعات، قبل أن يبدأ مباشرة أو في الخلفية عند موجّه shell. إذا فشل ذلك التحديث أو كنت غير متصل، يعمل الإصدار المثبّت. يحدّث `omarchy update` الوكلاء المثبّتين مع بقية Omarchy، ويحدّث `mup` الأدوات التي تديرها mise فقط.

أداة التحديث الخاصة بالوكيل نفسه، مثل `claude update` أو `codex update` أو زر تحديث في تطبيق، لا تحدّث التثبيت الذي تديره mise. يفشل `codex update`، ويمكن أن يبلّغ `claude update` عن النجاح بينما يثبّت نسخة منفصلة لا تتعقّبها mise. إذا كنت تفضّل استخدام المثبّت والمحدّث الأصليين للوكيل، أضفه إلى `disable_tools`؛ راجع [أدوات CLI المثبتة مسبقًا](18-development-tools.md#preinstalled-cli-tools).

لتثبيت كل الأدوات الكسولة المهيّأة قبل أن تحتاج إليها، شغّل `mise install --include-lazy`. يشمل هذا أدوات CLI الافتراضية الأخرى في Omarchy بالإضافة إلى الوكلاء. راجع [أدوات CLI المثبتة مسبقًا](18-development-tools.md#preinstalled-cli-tools) لتثبيت أداة واحدة أو استخدام تثبيتك الخاص.

يُثبَّت `grok` عبر حزمة `grok` من الطرف الأول في mise، بالطريقة نفسها التي يثبّت بها `claude` و`codex`. شغّل `grok`، أو اختره تحت _الإعداد > الافتراضيات > الوكيل_. تخطَّ مثبّت `curl | bash` على x.ai. يضع ذلك المسار نسخة ثانية في `~/.grok/bin`، ويقدّمها على `PATH`، ويستبدل غلاف Omarchy.

يفتح `dsh` واجهة متصفحه على `127.0.0.1:3080`، مع مجلد التشغيل كمساحة عمله الافتراضية. لا تأخذ واجهة متصفحه موجّه بدء، لذا فإن `omarchy agent prompt` يفتحها مع الموجّه في حافظتك للصقه. يبدأه Omarchy مع إعداد إذن DeepSeek المسبق بلا موافقة. يرفع DeepSeek Harness سجلات الجلسة إلى DeepSeek عندما تستخدم واجهة برمجة تطبيقات نموذجه الرسمية؛ أوقف ذلك تحت _الإعدادات > عام > رفع سجل الجلسة_ في واجهة متصفحه. تُرفع الملاحظات التي ترسلها إليه مع الجلسة أيضًا، ما لم تبدأه بـ `DSH_TELEMETRY_MODE=DISABLED`.

### الوكيل الافتراضي

اختر وكيلك الافتراضي بـ `omarchy default agent <name>` أو تحت _الإعداد > الافتراضيات > الوكيل_ في قائمة Omarchy (`Super + Space`). إذا لم يكن الوكيل مثبّتًا بعد، فإن اختياره يثبّته أولًا. سيدعوك Omarchy جديد إلى اتخاذ هذا الاختيار بإشعار يظهر مرة واحدة.

يحاول اختيار Claude أيضًا إعداد إضافة متصفحه لـ Chromium وChrome وBrave وBrave Origin وEdge. ينطبق إعداد الإضافة على كل المستخدمين وقد يطلب كلمة مرور نظامك؛ إلغاء تثبيت الإضافة أو فشله ما زال يختار Claude ويشغّله. أعد تشغيل متصفحك، فعّل الإضافة إذا طُلب منك، وسجّل الدخول إلى Claude لإنهاء توصيلها. شغّل `/chrome` في Claude للتحقق من الاتصال. لا يدعم Firefox وZen هذه الإضافة. إذا كان Claude وكيلك الافتراضي قبل إضافة هذا الإعداد، اختره مجددًا لتثبيت الإضافة.

بمجرد أن تختار، يشغّل `Super + Shift + Ctrl + A` الوكيل الافتراضي في نافذة طرفية مخصصة (أو يعرض المنتقي إذا لم تكن قد اخترت بعد). يمكنك أيضًا تشغيله مباشرة في مهمة بـ `omarchy agent prompt "Review this project"`. لا يأخذ Freebuff وDeepSeek Harness موجّه بدء، لذا يفتحان مع الموجّه في حافظتك للصقه بدلًا من ذلك. يعمل الوكلاء المشغّلون بهذه الطريقة دون إشراف في أوضاعهم الخاصة بعدم التوقف للسؤال، لذا كن مستعدًا لهم لفعل أشياء فعلًا! لا يملك MiniMax Code مثل هذا الوضع لجلسته التفاعلية، لذا يطلب الأذونات كالمعتاد. وبما أن الوكلاء يرفضون تذكّر الثقة لمجلدك الرئيسي، تبدأ التشغيلات من `$HOME` في `~/Work` بدلًا من ذلك.

توجد اختصارات طرفية أيضًا: يشغّل `a` الوكيل الافتراضي ضمنيًا في الطرفية الحالية، بينما يبدأ `c` و`cx` و`cy` كلًا من OpenCode وClaude Code وCodex مباشرة (مرة أخرى في أوضاع الموافقة التلقائية الخاصة بهم). تتزامن تغييرات السمة إلى الوكلاء أيضًا: Claude Code وPi وOpenCode وHermes (بمجرد أن يثبّته Omarchy) كلها تتابع عندما تبدّل سمة Omarchy.

### لوحة الوكلاء

يملك الشريط العلوي أيقونة وكلاء. قبل أن تعدّ وكيلًا، ترشدك لوحتها عبر تسجيل الدخول إلى Claude أو Codex أو Grok، ويصبح الأول وكيلك الافتراضي. بعد ذلك، تضع اللوحة كل اشتراك على صفحة واحدة: كل وكيل وحساب مع خطته، وعدّاد لكل من حدود جلسته ذات 5 ساعات وحدوده الأسبوعية مع الوقت المتبقي حتى إعادة تعيينها (مرّر للاطلاع على النسبة الدقيقة)، أو الرصيد المدفوع مسبقًا المتبقي، تحت سطر يدور عبر ما استخدمته عبرها جميعًا، مثل التوكنات هذا الأسبوع ونموذجك الأكثر استخدامًا. تحت _اصنع شيئًا_ تقدّم موجّهات بداية لموضوع أو إضافة أو تطبيق جديد تسلّم المهمة إلى وكيلك الافتراضي. تُبنى التطبيقات بالطريقة نفسها التي تُبنى بها تطبيقات Omarchy الخاصة Hype وMonologue وOmacut، بلغة C++ وQt Quick، باتباع مهارة وكيل omarchy-app، والمترجم وقطع Qt التي تحتاجها تأتي مثبّتة. تتم تغطية Claude Code وCodex وGrok وKimi وCursor وبدل Grok Bot الخاص به وGitHub Copilot وMuse وAntigravity وKimchi وDevin جاهزة مع حدودها، ويُظهر Hermes وMistral Vibe وQwen Code جلساتهم وتوكناتهم بمجرد أن تستخدمها. تظهر أيضًا خطط المزوّدين ومفاتيحهم التي تستخدمها عبر pi أو omp أو opencode: OpenCode Zen وGo وخطة Z.ai GLM Coding Plan وOllama Cloud وخطة MiniMax Token Plan وSynthetic مع حدودها؛ وFireworks وOpenRouter وDeepSeek مع أرصدتها المدفوعة مسبقًا؛ والنماذج التي تشغّلها على عتادك الخاص تحت النماذج المحلية. يُحسب كل وكيل مرة واحدة، تحت من يفوتره، مهما كان عدد الـ harnesses التي تشغّله عبرها.

انقر بالزر الأيسر أيقونة الشريط للوحة، وانقر بالزر الأيمن لتشغيل وكيلك الافتراضي. تُعاد توليد سجلات الاستخدام خلفها كل 15 دقيقة بـ `omarchy agent usage-update`، ويمكن للوحة حتى دمج الاستخدام من أجهزتك الأخرى عبر مجلد متزامن. اطّلع على README تحت `$OMARCHY_PATH/shell/plugins/agents/` للإعدادات الكاملة.

### عدّة اشتراكات

إذا دفعت مقابل أكثر من خطة Claude أو Codex أو Grok واحدة — خطة Max شخصية وخطة عمل، على سبيل المثال — يمكن لـ Omarchy إبقاءها جميعًا مسجّلة الدخول والتنقل بينها. أضف اشتراكًا بـ + في لوحة الوكلاء، التي ترشدك عبر ذلك هناك مباشرة، أو بـ `omarchy agent account add claude Work` (أو `codex`، أو `grok`). يثبّت واجهة سطر الأوامر إذا كانت مفقودة. يسجّل الحساب الأول لمزوّد الدخول عبر متصفحك العادي، هناك بالضبط حيث تبحث واجهة سطر الأوامر دائمًا. كل حساب بعد ذلك يسجّل الدخول عبر نافذة خاصة، لذا لا يُلتقط بالخطأ الحساب الذي متصفحك مسجّل الدخول إليه أصلًا؛ سجّل الدخول هناك كالحساب الذي تضيفه، وأغلق أي نافذة خاصة مفتوحة لديك أصلًا أولًا. لا تسجّل الخروج من واجهة سطر الأوامر أبدًا لفعل هذا: تسجيل الخروج يلغي تسجيل الدخول المحفوظ، وسيتعيّن إضافة ذلك الحساب مجددًا.

لنسخ تسجيلات دخول اشتراكك إلى جهاز Omarchy آخر عبر SSH، شغّل `omarchy agent account copy user@laptop`. يوفّر المرسل مستقبلًا مؤقتًا عندما لا يكون لدى الوجهة واحد مثبّت، لذا يمكن لأجهزة Omarchy الأقدم استقبال الحسابات دون تحديث. للمستقبلات المثبّتة الأسبقية. ينسخ هذا كل اشتراكات Claude وCodex وGrok؛ أضف أسماء المزوّدين لتحديدها، كما في `omarchy agent account copy laptop claude`. تتطابق أسماء الحسابات ومعرّفات الأوامر مع المصدر، بما يشمل الحسابات الموجودة أصلًا على الوجهة. تتلقى حسابات الوجهة غير ذات الصلة لاحقة رقمية إذا تعارضت أسماؤها، وتبقى الإعدادات والمهارات والإضافات وسجل المحادثات محلية لكل جهاز.

تُحفظ بيانات اعتماد الوجهة الحالية. يُزامَن اسم حساب مصدر مسجّل الدخول هناك أصلًا دون استبدال بيانات اعتماده؛ تُضاف حسابات أخرى بجانبه. لاستبدال بيانات الاعتماد المحفوظة للحسابات المطابقة، استخدم `omarchy agent account copy --replace laptop claude` بعد إنهاء جلسات ذلك الحساب على الوجهة. تحصل وجهة جديدة أيضًا على الحساب النشط وتفضيلات التبديل للمصدر؛ تحتفظ وجهة راسخة بخياراتها الخاصة.

تنتقل بيانات الاعتماد عبر SSH وتُخزّن في ملفات خاصة على الوجهة، لذا انسخ فقط إلى أجهزة تثق بها. هذا نسخ لمرة واحدة، وليس مزامنة مستمرة. يمكن لجهاز آخر تدوير توكنات تحديث Codex، تاركًا تسجيل دخول منسوخًا بحاجة إلى التجديد؛ تبقى تسجيلات الدخول المنفصلة الخيار الأكثر موثوقية للاستخدام المتزامن على عدّة أجهزة. راجع [إرشادات Codex لمصادقة الحساب](https://developers.openai.com/codex/auth/ci-cd-auth).

حساب واحد لكل مزوّد نشط، وتبدأ كل جلسة جديدة به: `cx` و`cy` و`claude` أو `codex` أو `grok` العادي، وأي شيء مشغّل عبر `omarchy agent`، والبرامج النصية أو المحرّرات التي تجد واجهة سطر الأوامر على `PATH`. بدّل بـ `omarchy agent account use work` (وعد بـ `omarchy agent account use main`)، أو في اللوحة بالضغط على رقم حساب ثم `Enter` (أو بالنقر على زر الاستخدام الخاص به). تبقى الجلسات قيد التشغيل أصلًا على الحساب الذي بدأت به. يُشارك سجل المحادثات والإعدادات والمهارات والإضافات عبر الحسابات، لذا فإن `claude --continue` في المجلد نفسه يتابع من حيث توقفت على الحساب الجديد.

مع أكثر من حساب واحد، تعرض اللوحة حدود كل حساب جنبًا إلى جنب، مع وضع علامة على النشط. افتراضيًا يخطرك Omarchy عندما يتجاوز الحساب النشط 95% من حد، والنقر على الإشعار يبدّل إلى الحساب ذي أكبر هامش. مرّر خط حساب في اللوحة وانقر Autoswitch الذي يظهر بجانب Use (أو اضغط `m`)، أو شغّل `omarchy agent account mode auto`، ليبدّل من تلقاء نفسه بدلًا من ذلك؛ بينما هو مفعّل، يحلّ Autoswitch محل Use، والنقر عليه مجددًا يعود إلى الإشعار. أضف رقمًا لتغيير العتبة، كما في `omarchy agent account mode auto 90`. إذا تجاوز كل حساب العتبة، ستسمع عنه مرة واحدة، مع أي حساب يتحرر أولًا. بينما يكون الحساب النشط ضمن 15 نقطة من عتبته (80% افتراضيًا)، تُفحص حدوده كل ثلاث دقائق بدلًا من كل 15.

يُظهر `omarchy agent account list` كل حساب وحدوده الأحدث، وينسى `omarchy agent account remove work` واحدًا، ويعيد `omarchy agent account rename primary Hey` تسمية واحد (أو انقر اسم حساب في اللوحة). تعمل هذه الأوامر على حسابات وكيلك الافتراضي؛ للوصول إلى المزوّد الآخر، سمّه أولًا، كما في `omarchy agent account use codex side`. تسجيل الدخول الذي كان لديك أصلًا في `~/.claude` أو `~/.codex` هو الحساب _Main_ ويبقى حيث هو. يمكن أن يُظهر حساب تُرك دون استخدام لأكثر من حوالي ثماني ساعات _يلزم تسجيل الدخول_؛ انقره لتسجيل دخول ذلك الحساب مجددًا في اللوحة مباشرة، أو ابدأ جلسة فيه، مما ينعش تسجيل الدخول من تلقاء نفسه. خوادم MCP التي كانت لديك عندما أُضيف حساب تأتي معه إليه، لكن تلك التي تضيفها لاحقًا بـ `claude mcp add` تصل فقط إلى الحساب الذي أضفتها فيه. لا يتبع Claude Desktop والأدوات المهيّأة بمسار مطلق إلى ثنائي واجهة سطر الأوامر التبديلَ. يأخذ `CLAUDE_CONFIG_DIR` أو `CODEX_HOME` أو `GROK_HOME` صريح الأسبقية على الحساب المحدد.

### تشخيص الأعطال

يراقب Omarchy systemd-coredump لأعطال العمليات. عندما يحدث لشيء خطأ segfault، ستحصل على إشعار "Process crashed" — انقره، وسيُسلَّم العطل إلى وكيلك الافتراضي مع مهارة diagnose-crash في Omarchy، التي ترشد الوكيل عبر إثبات الوقائع من تفريغ النواة وتقرير ما إذا كان العطل يستحق الإبلاغ عنه إلى المنبع. يمكنك أيضًا تشغيله يدويًا ضد أي PID من `coredumpctl list` بـ `omarchy agent crash <pid>`.

المراقبة مفعّلة افتراضيًا. أوقفها تحت _المشغّل > التبديل > التقاط الأعطال_ (أو بـ `omarchy toggle crash-capture`) وستتوقف الإشعارات؛ ما زال `omarchy agent crash <pid>` يعمل يدويًا.

يمكن أيضًا كتم الأعطال برنامجًا واحدًا في كل مرة، وهو ما يقدمه لك التشخيص في النهاية. يوقف `omarchy crash mute hyprland` الإشعارات لذلك البرنامج فقط، ويعيدها `omarchy crash mute hyprland off`، ويسرد `omarchy crash mute` وحده ما كتمته. يأخذ مسار الثنائي بسعادة مثل اسمه، لذا فإن `omarchy crash mute /usr/bin/hyprland` يفعل الشيء نفسه. ضع علامتي اقتباس حول اسم فيه مسافة، كما في `omarchy crash mute 'Some App'`. كل شيء آخر ما زال يخطر، والبرنامج المكتم ما زال يتعطل — هذا يخفي التذكير، ولا يصلح أي شيء.

### تطبيقات سطح المكتب

تحمل قائمة _التثبيت > الذكاء الاصطناعي_ أيضًا بعض تطبيقات الذكاء الاصطناعي الرسومية: تطبيق ChatGPT لسطح المكتب، وتطبيق Claude لسطح المكتب (نسخة Anthropic التجريبية لـ Linux، مع تبويبات Chat وCowork وClaude Code)، وGrok Bot للدردشة مع نماذج xAI، وHermes Desktop، وOpenClaw، وتطبيق Perplexity لسطح المكتب، وT3 Code. Grok Bot هو تطبيق الدردشة لسطح المكتب. وكيل البرمجة هو أمر `grok`.

Hermes Desktop هو التطبيق الذي يجب أن تعرفه، لأن الجهاز يملك Hermes واحدًا، وهو الخاص بالتطبيق: يُثبَّت Hermes فقط أبدًا عبر التطبيق، وأمر `hermes` الذي يشغّله الوكيل الافتراضي هو الخاص بالتطبيق. اختيار Hermes كوكيل افتراضي يثبّت الشيء نفسه الذي تفعله مدخلة _التثبيت > الذكاء الاصطناعي_: الحزمة، ووقت تشغيل Hermes تحت `~/.hermes` مُعدّ بمثبّت Hermes الخاص، الذي يستغرق بضع دقائق في المرة الأولى. وقت التشغيل ذلك هو Hermes الواحد الذي يستخدمه أمر `hermes` الطرفي والوكيل الافتراضي والتطبيق جميعًا، ويحدّث نفسه بـ `hermes update` بدلًا من انتظار إصدار Omarchy. يمنح تثبيته أيضًا Hermes سمة Omarchy كسطح باسم `omarchy`، تتبعه كل أسطح Hermes أثناء تبديلك السمات؛ اختر آخر تحت إعدادات مظهر Hermes أو بـ `/skin` إذا كنت تفضّل ألا يفعل، ويترك Omarchy ذلك الاختيار وشأنه. إزالة التطبيق تحت _الإزالة > الذكاء الاصطناعي_ تغلق Hermes أولًا، بما فيه البوابة، وتأخذ وقت التشغيل ذلك معها، وتحفظ محادثاتك وذكرياتك والمهارات التي كتبها Hermes لنفسه ما لم تخبره بغير ذلك: يسأل، وافتراضيه لا، ما إذا كان يجب أن تذهب تلك البيانات وإعدادات اتصالك أيضًا.

تجربة OpenClaw لسطح المكتب هي واجهة التحكم الخاصة به، التي تفتح كتطبيق ويب مدعوم ببوابته المحلية الخاصة. يعيش OpenClaw في `~/.openclaw` ويحدّث نفسه: استخدم زر "Update Gateway" في واجهة التحكم أو شغّل `openclaw update`، وتعيد البوابة التشغيل على الإصدار الجديد. يختار Omarchy فقط الإصدار الذي يبدأ منه تثبيت جديد. تأخذ إزالة OpenClaw تحت _الإزالة > الذكاء الاصطناعي_ خدمة البوابة والتطبيق معها ثم تسأل ما إذا كان يجب أن يذهب `~/.openclaw` أيضًا، بما أنه يحمل محادثاتك وبيانات اعتمادك بجانب OpenClaw نفسه وأوقات تشغيل الإضافات التي ينزّلها؛ الافتراضي يبقيها، وتثبيت OpenClaw مجددًا يلتقطها مجددًا.

يعمل T3 Code من إصدار AppImage الرسمي الخاص به في `~/.local/share/t3code` بدلًا من حزمة، لذا يحدّث نفسه. يسألك تثبيته ما إذا كنت تريد البدء على قناة Stable أو Nightly؛ بدّل لاحقًا في إعدادات T3 Code. تعيش خيوطك وإعداداتك في `~/.t3`، وتأخذ إزالة T3 Code تحت _الإزالة > الذكاء الاصطناعي_ تلك معها.

### النماذج المحلية

شغّل نموذجًا مفتوحًا على جهازك الخاص لوكلاء برمجتك. تبقى موجّهاتك وشفرتك على الجهاز؛ لا شيء يُرسل إلى النموذج يغادره. ابدأ بـ:

```bash
omarchy agent local use best
```

أو، في لوحة الوكلاء في الشريط العلوي، اختر + ثم Local AI، التي تظهر عندما يناسب نموذج هذا الجهاز. في المرة الأولى، يثبّت هذا Podman، الذي يشغّل النماذج. ثم يختار Omarchy النموذج الموصى به لهذا الجهاز، وينزّله، ويشغّله. توقّع تنزيلًا بعشرات GB ومعظم ذاكرة الجهاز قيد الاستخدام أثناء عمل النموذج: يستخدم Flash Next حوالي 100 GiB مع سياقه الكامل 256K. إذا احتفظت نماذج أخرى بالذاكرة التي يحتاجها، يُعدّ متوقفًا، جاهزًا للبدء بمجرد أن توقف واحدًا. يتوقف النموذج عند تسجيل الخروج؛ أوقفه بنفسك عندما تحتاج الذاكرة لشيء آخر.

يُظهر `omarchy agent local list` الخيارات ويشرح لماذا لا يناسب بعضها. لإعداد آخر، شغّل `omarchy agent local use <recipe>`. اليوم، يتوفر `qwen3.8-flash-next-halogen` و`qwen3.8-27b-gufo` لأجهزة Strix Halo بسعة 128 GB. تصل وصفات وتوصيات جديدة مع `omarchy update`، عبر الحزمة.

يحصل كل نموذج تعدّه على سطره الخاص في لوحة الوكلاء، بجانب اشتراكاتك: التشغيل لبدئه، والإيقاف المؤقت لإيقافه وتحرير ذاكرته، وزر الطرفية لفتح وكيلك عليه. يمكن أن تعمل عدة نماذج في آن واحد عندما تتسع في الذاكرة معًا؛ إذا لم يتسع واحد، يقول Omarchy أي نموذج قيد التشغيل يجب إيقافه. اسحب السطور لإعادة ترتيبها، واضغط Delete على سطر محدد لإزالة نموذج وتنزيله.

من سطر الأوامر، يفعل `omarchy agent local start <recipe>` و`omarchy agent local stop <recipe>` الشيء نفسه، ويُظهر `omarchy agent local status` كل نموذج، ويفتح `omarchy agent --local` وكيلك الافتراضي على آخر نموذج شغّلته (pi إذا لم يستطع وكيلك الافتراضي استخدام نموذج محلي). يمكن لأي عميل متوافق مع OpenAI الاتصال أيضًا: يُظهر `status` عنوان كل نموذج (الأول هو `http://127.0.0.1:11435/v1`)، واسم الوصفة هو النموذج، والمفتاح في `~/.config/omarchy/agent-local/key`.

يحذف `omarchy agent local remove <recipe>` نموذجًا والتنزيلات التي لا يستخدمها نموذج آخر.

تُوسم أوقات التشغيل من أطراف ثالثة بناشرها. يشغّل Omarchy كل نموذج بلا وصول إلى الشبكة.

### نماذج LLM المحلية

يوصي Omarchy بطريقتين لتشغيل نماذج LLM محلية: LM Studio وOllama. توفر LM Studio واجهة رسومية لاكتشاف نماذج الأوزان المفتوحة وتثبيتها وتشغيلها. إنها طريقة رائعة للانطلاق بسهولة. تقدم Ollama واجهة سطر أوامر لفعل ذلك على نحو مماثل. لكن إذا كنت جديدًا على النماذج المحلية، سأبدأ بـ LM Studio. يمكنك تثبيت أي منهما تحت _التثبيت > الذكاء الاصطناعي_ في قائمة Omarchy.

### مهارة Omarchy

تساعد مهارات الوكيل الذكاء الاصطناعي على استخدام أدوات محددة بطريقة محددة، ويأتي Omarchy مع مهارة افتراضية لتكييف النظام. مثل تعديل تكوين Hyprland الخاص بك، أو ضبط الشريط، أو حتى إنشاء سمة جديدة من الصفر. تُربط برابط رمزي إلى مجلدات مهارة Claude Code (`~/.claude/skills`) وCodex (`~/.codex/skills`) وPi (`~/.pi/agent/skills`) وAntigravity (`~/.gemini/config/skills`) وHermes (`~/.hermes/skills` وكل `~/.hermes/profiles/*/skills`)، وموقع `~/.agents/skills` العام، لذا تلتقطها معظم الـ harnesses تلقائيًا.

لكن يجب أن تعامل هذه المهارة كتجريبية. ستستخدمها نماذج مختلفة بفعاليات مختلفة. من الأفضل التشغيل في وضع التخطيط أولًا، لتكون لديك فكرة عما يود الوكيل تغييره. ثم كن مستعدًا للتراجع عن التغييرات أو حتى استدعاء `omarchy reinstall configs`، إذا أفسد الوكيل كل شيء.
