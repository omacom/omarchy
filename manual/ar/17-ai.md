# الذكاء الاصطناعي

تتضمن Omarchy مشغّلات لوكلاء البرمجة أدناه دون أن تختار لك واحدًا افتراضيًا. شغّل أمرًا لتثبيت واجهة سطر الأوامر الخاصة به عند أول استخدام، ثم قم بالمصادقة عندما يُطلب منك ذلك. Hermes هو الاستثناء: لا يُثبَّت أي شيء له عند أول استخدام، واختياره يثبّت Hermes Desktop، كما يشرح قسم _تطبيقات سطح المكتب_ أدناه.

### تثبيت الوكلاء وتحديثهم

باستثناء Hermes، يستخدم هؤلاء الوكلاء التثبيت الكسول الخاص بـ mise: أول تشغيل يثبّت واجهة سطر الأوامر، والتشغيلات اللاحقة تعيد استخدامها. تتحقق mise أيضًا من وجود إصدار جديد لوكيل مثبّت مرة واحدة على الأكثر كل أربع ساعات، قبل بدئه مباشرة أو في الخلفية عند موجّه shell. إذا فشل ذلك التحديث أو كنت غير متصل، يعمل الإصدار المثبّت. يحدّث `omarchy update` الوكلاء المثبّتين مع بقية Omarchy، ويحدّث `mup` الأدوات التي تديرها mise فقط.

أداة التحديث الخاصة بوكيل ما، مثل `claude update` أو `codex update` أو زر تحديث داخل تطبيق، لا تحدّث التثبيت الذي تديره mise. يفشل `codex update`، ويمكن أن يبلّغ `claude update` عن النجاح بينما يثبّت نسخة منفصلة لا تتعقبها mise. إذا كنت تفضّل استخدام المثبّت والمحدّث الأصليين لوكيل ما، أضفه إلى `disable_tools`؛ راجع [أدوات CLI المثبتة مسبقًا](18-development-tools.md#preinstalled-cli-tools).

لتثبيت جميع الأدوات الكسولة المهيّأة قبل أن تحتاج إليها، شغّل `mise install --include-lazy`. يشمل هذا أدوات CLI الافتراضية الأخرى في Omarchy بالإضافة إلى الوكلاء. راجع [أدوات CLI المثبتة مسبقًا](18-development-tools.md#preinstalled-cli-tools) لتثبيت أداة واحدة أو لاستخدام تثبيتك الخاص.

يُثبَّت `grok` عبر حزمة `grok` الرسمية الخاصة بـ mise، بنفس طريقة `claude` و`codex`. شغّل `grok`، أو اختره ضمن _الإعداد > الإعدادات الافتراضية > الوكيل_. تجنّب مثبّت `curl | bash` على x.ai. فذلك المسار يضع نسخة ثانية في `~/.grok/bin`، ويقدّمها على `PATH`، ويكتب فوق غلاف Omarchy.

يفتح `dsh` واجهة المتصفح الخاصة به على `127.0.0.1:3080`، مع مجلد التشغيل كمساحة عمل افتراضية له. لا تأخذ واجهة المتصفح الخاصة به أي موجّه بدء، لذا يفتحها `omarchy agent prompt` مع وضع الموجّه على حافظتك للصقه. تشغّله Omarchy مع إعداد أذونات DeepSeek المسبق بدون موافقة. يرفع DeepSeek Harness سجلات الجلسات إلى DeepSeek عندما تستخدم واجهة برمجة تطبيقات النموذج الرسمية الخاصة به؛ عطّل ذلك ضمن _الإعدادات > عام > Upload Session Log_ في واجهة المتصفح الخاصة به. تُرفع أيضًا التعليقات التي ترسلها إليه مع الجلسة، ما لم تشغّله مع `DSH_TELEMETRY_MODE=DISABLED`.

### الوكيل الافتراضي

اختر وكيلك الافتراضي باستخدام `omarchy default agent <name>` أو ضمن _الإعداد > الإعدادات الافتراضية > الوكيل_ في Omarchy Menu (`Super + Space`). إذا لم يكن الوكيل مثبّتًا بعد، فإن اختياره يثبّته أولًا. ستدعوك Omarchy جديدة إلى اتخاذ هذا الخيار عبر إشعار لمرة واحدة.

يحاول اختيار Claude أيضًا إعداد إضافة المتصفح الخاصة به لـ Chromium وChrome وBrave وBrave Origin وEdge. ينطبق إعداد الإضافة على جميع المستخدمين وقد يطلب كلمة مرور النظام الخاصة بك؛ إلغاء تثبيت الإضافة أو فشله ما زال يختار Claude ويشغّله. أعد تشغيل متصفحك، فعّل الإضافة إذا طُلب منك ذلك، وسجّل الدخول إلى Claude لإنهاء توصيلها. شغّل `/chrome` في Claude للتحقق من الاتصال. لا يدعم Firefox وZen هذه الإضافة. إذا كان Claude وكيلك الافتراضي بالفعل قبل إضافة هذا الإعداد، اختره مرة أخرى لتثبيت الإضافة.

بمجرد أن تختار، يشغّل `Super + Shift + Ctrl + A` الوكيل الافتراضي في نافذة طرفية مخصصة (أو يعرض المنتقي إذا لم تختر بعد). يمكنك أيضًا تشغيله مباشرة في مهمة باستخدام `omarchy agent prompt "Review this project"`. لا يأخذ Freebuff وDeepSeek Harness أي موجّه بدء، لذا يفتحان مع وضع الموجّه على حافظتك للصقه بدلًا من ذلك. يعمل الوكلاء المشغّلون بهذه الطريقة دون مراقبة في أوضاع عدم التوقف للسؤال الخاصة بكل منهم، لذا كن مستعدًا لأن يقوموا بأشياء فعليًا! ليس لدى MiniMax Code مثل هذا الوضع لجلساته التفاعلية، لذا يطلب الأذونات كالمعتاد. وبما أن الوكلاء يرفضون تذكّر الثقة لمجلدك الرئيسي، تبدأ التشغيلات من `$HOME` في `~/Work` بدلًا من ذلك.

توجد اختصارات طرفية أيضًا: يشغّل `a` الوكيل الافتراضي داخل الطرفية الحالية، بينما يشغّل `c` و`cx` و`cy` كلًا من OpenCode وClaude Code وCodex مباشرة (مرة أخرى في أوضاع الموافقة التلقائية الخاصة بهم). تتزامن تغييرات السمة مع الوكلاء أيضًا: يتبع Claude Code وPi وOpenCode وHermes (بمجرد أن تثبّته Omarchy) جميعًا عند تبديل سمة Omarchy.

### لوحة الوكلاء

يحتوي الشريط العلوي على أيقونة وكلاء. قبل أن تعدّ وكيلًا، ترشدك لوحته خطوة بخطوة لتسجيل الدخول إلى Claude أو Codex أو Grok، ويصبح أولها وكيلك الافتراضي. بعد ذلك، تضع اللوحة كل اشتراك على صفحة واحدة: كل وكيل وحساب مع خطته، وعداد لكل من حدود جلسته البالغة 5 ساعات وحدوده الأسبوعية مع الوقت حتى إعادة تعيينه (مرّر للاطلاع على النسبة المئوية الدقيقة)، أو الرصيد المدفوع مسبقًا المتبقي، تحت سطر يدور عبر ما استخدمته عبر جميعها، مثل الرموز هذا الأسبوع ونموذجك الأكثر استخدامًا. ضمن _اصنع شيئًا_ تقدّم موجّهات بداية لموضوع أو إضافة أو تطبيق جديد تسلّم المهمة إلى وكيلك الافتراضي. تُبنى التطبيقات بنفس طريقة بناء Hype وMonologue وOmacut الخاصة بـ Omarchy نفسها، بـ C++ وQt Quick، باتباع مهارة وكيل omarchy-app، وتأتي أدوات الترجمة وقطع Qt التي تحتاج إليها مثبّتة. تتم تغطية Claude Code وCodex وGrok وKimi وCursor وبدل Grok Bot الخاص به وGitHub Copilot وMuse وAntigravity وKimchi وDevin جاهزة مع حدودها، ويُظهر Hermes وMistral Vibe وQwen Code جلساتهم ورموزهم بمجرد أن تستخدمهم. تظهر أيضًا خطط المزوّدين والمفاتيح التي تستخدمها عبر pi أو omp أو opencode: OpenCode Zen وGo وخطة Z.ai GLM Coding Plan وOllama Cloud وخطة MiniMax Token Plan وSynthetic مع حدودها؛ وFireworks وOpenRouter وDeepSeek مع أرصدتها المدفوعة مسبقًا؛ والنماذج التي تشغّلها على أجهزتك الخاصة ضمن النماذج المحلية. يُحسب كل وكيل مرة واحدة، لدى أي جهة تصدر فاتورته، مهما كان عدد الأطر التي تشغّله من خلالها.

انقر بزر الماوس الأيسر على أيقونة الشريط للوحة، وانقر بزر الماوس الأيمن لتشغيل وكيلك الافتراضي. تُعاد توليد سجلات الاستخدام التي تقف خلفها كل 15 دقيقة بواسطة `omarchy agent usage-update`، ويمكن للوحة حتى دمج الاستخدام من أجهزتك الأخرى عبر مجلد متزامن. راجع README ضمن `$OMARCHY_PATH/shell/plugins/agents/` للإعدادات الكاملة.

### اشتراكات متعددة

إذا دفعت مقابل أكثر من خطة واحدة لـ Claude أو Codex أو Grok — خطة Max شخصية وخطة عمل، على سبيل المثال — يمكن لـ Omarchy إبقاؤها جميعًا مسجلًا دخولها والتنقل بينها. أضف اشتراكًا باستخدام + في لوحة الوكلاء، التي ترشدك خطوة بخطوة هناك مباشرة، أو باستخدام `omarchy agent account add claude Work` (أو `codex` أو `grok`). يثبّت واجهة سطر الأوامر إذا كانت مفقودة. يسجّل الحساب الأول لمزوّد الدخول عبر متصفحك العادي، حيث تبحث واجهة سطر الأوامر دائمًا. يسجّل كل حساب بعد ذلك الدخول عبر نافذة خاصة، حتى لا يُلتقط الحساب الذي سجّل متصفحك الدخول إليه بالفعل عن طريق الخطأ؛ سجّل الدخول هناك كالحساب الذي تضيفه، وأغلق أي نافذة خاصة مفتوحة لديك بالفعل أولًا. لا تسجّل الخروج أبدًا من واجهة سطر الأوامر للقيام بذلك: تسجيل الخروج يلغي تسجيل الدخول المحفوظ، وسيتعين إضافة ذلك الحساب مرة أخرى.

لنسخ تسجيلات دخول اشتراكاتك إلى جهاز Omarchy آخر عبر SSH، شغّل `omarchy agent account copy user@laptop`. يوفّر المرسل مستقبلًا مؤقتًا عندما لا يكون لدى الوجهة واحد مثبّت، حتى تتمكن أجهزة Omarchy الأقدم من استقبال الحسابات دون تحديث. تأخذ المستقبلات المثبّتة الأسبقية. ينسخ هذا جميع اشتراكات Claude وCodex وGrok؛ أضف أسماء المزوّدين لتحديدها، كما في `omarchy agent account copy laptop claude`. تتطابق أسماء الحسابات ومعرّفات الأوامر مع المصدر، بما في ذلك الحسابات الموجودة بالفعل على الوجهة. تتلقى حسابات الوجهة غير ذات الصلة لاحقة رقمية إذا تعارضت أسماؤها، وتبقى الإعدادات والمهارات والإضافات وسجل المحادثات محلية لكل جهاز.

تُحفظ بيانات اعتماد الوجهة الحالية. تتم مزامنة اسم حساب مصدر مسجّل دخوله هناك بالفعل دون استبدال بيانات اعتماده؛ وتُضاف حسابات أخرى إلى جانبه. لاستبدال بيانات الاعتماد المحفوظة للحسابات المطابقة، استخدم `omarchy agent account copy --replace laptop claude` بعد إنهاء جلسات ذلك الحساب على الوجهة. تحصل الوجهة الجديدة أيضًا على الحساب النشط وتفضيلات التبديل الخاصة بالمصدر؛ وتحتفظ الوجهة القائمة بتفضيلاتها الخاصة.

تنتقل بيانات الاعتماد عبر SSH وتُخزّن في ملفات خاصة على الوجهة، لذا انسخ فقط إلى أجهزة تثق بها. هذه نسخة لمرة واحدة، وليست مزامنة مستمرة. يمكن لجهاز آخر تدوير رموز تحديث Codex، مما يترك تسجيل دخول منسوخًا بحاجة إلى تجديد؛ تبقى عمليات تسجيل الدخول المنفصلة الخيار الأكثر موثوقية للاستخدام المتزامن على أجهزة متعددة. راجع [إرشادات مصادقة الحساب من Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

حساب واحد لكل مزوّد نشط، وكل جلسة جديدة تبدأ به: `cx` و`cy` و`claude` أو `codex` أو `grok` العادي، وأي شيء يُشغّل عبر `omarchy agent`، والبرامج النصية أو المحرّرات التي تجد واجهة سطر الأوامر على `PATH`. بدّل باستخدام `omarchy agent account use work` (وعد باستخدام `omarchy agent account use main`)، أو في اللوحة بالضغط على رقم حساب ثم `Enter` (أو النقر على زر Use الخاص به). تبقى الجلسات قيد التشغيل بالفعل على الحساب الذي بدأت به. يُشارك سجل المحادثات والإعدادات والمهارات والإضافات عبر الحسابات، لذا يلتقط `claude --continue` في نفس المجلد من حيث توقفت على الحساب الجديد.

مع أكثر من حساب واحد، تعرض اللوحة حدود كل حساب جنبًا إلى جنب، مع تمييز الحساب النشط. افتراضيًا، تخطرك Omarchy عندما يتجاوز الحساب النشط 95% من حد ما، والنقر على الإشعار يبدّل إلى الحساب الذي لديه أكبر هامش. مرّر فوق سطر حساب في اللوحة وانقر على Autoswitch الذي يظهر بجانب Use (أو اضغط `m`)، أو شغّل `omarchy agent account mode auto`، لجعله يبدّل من تلقاء نفسه بدلًا من ذلك؛ أثناء تفعيله، يأخذ Autoswitch مكان Use، والنقر عليه مرة أخرى يعود إلى الإخطار. أضف رقمًا لتغيير العتبة، كما في `omarchy agent account mode auto 90`. إذا تجاوز كل حساب العتبة، ستسمع عن ذلك مرة واحدة، إلى جانب الحساب الذي يتحرّر أولًا. بينما يكون الحساب النشط ضمن 15 نقطة من عتبته (80% افتراضيًا)، تُفحص حدوده كل ثلاث دقائق بدلًا من كل 15 دقيقة.

يعرض `omarchy agent account list` كل حساب وأحدث حدوده، وينسى `omarchy agent account remove work` واحدًا، ويعيد `omarchy agent account rename primary Hey` تسمية واحد (أو انقر على اسم حساب في اللوحة). تعمل هذه الأوامر على حسابات وكيلك الافتراضي؛ للوصول إلى المزوّد الآخر، سمّه أولًا، كما في `omarchy agent account use codex side`. تسجيل الدخول الذي كان لديك بالفعل في `~/.claude` أو `~/.codex` هو حساب _Main_ ويبقى حيث هو. يمكن أن يُظهر حساب تُرك دون استخدام لأكثر من حوالي ثماني ساعات _يلزم تسجيل الدخول_؛ انقر عليه لتسجيل دخول ذلك الحساب مرة أخرى مباشرة في اللوحة، أو ابدأ جلسة فيه، مما ينعش تسجيل الدخول من تلقاء نفسه. تأتي خوادم MCP التي كانت لديك عندما أُضيف حساب معه إليه، لكن تلك التي تضيفها لاحقًا باستخدام `claude mcp add` تصل فقط إلى الحساب الذي أضفتها فيه. لا يتبع Claude Desktop والأدوات المهيّأة بمسار مطلق لملف واجهة سطر الأوامر الثنائي التبديل. يأخذ `CLAUDE_CONFIG_DIR` أو `CODEX_HOME` أو `GROK_HOME` الصريح الأسبقية على الحساب المحدد.

### تشخيص الأعطال

تراقب Omarchy systemd-coredump لأعطال العمليات. عندما يحدث خطأ تجزئة لشيء ما، ستحصل على إشعار "Process crashed" — انقر عليه، ويُسلّم العطل إلى وكيلك الافتراضي مع مهارة diagnose-crash الخاصة بـ Omarchy، التي ترشد الوكيل خطوة بخطوة لإثبات الحقائق من تفريغ النواة وتقرير ما إذا كان العطل يستحق الإبلاغ عنه إلى المنبع. يمكنك أيضًا تشغيله يدويًا مقابل أي PID من `coredumpctl list` باستخدام `omarchy agent crash <pid>`.

المراقبة مفعّلة افتراضيًا. عطّلها ضمن _المشغّل > تبديل > التقاط الأعطال_ (أو باستخدام `omarchy toggle crash-capture`) وستتوقف الإشعارات؛ ما زال `omarchy agent crash <pid>` يعمل يدويًا.

يمكن أيضًا إسكات الأعطال برنامجًا واحدًا في كل مرة، وهو ما يعرضه عليك التشخيص في النهاية. يوقف `omarchy crash mute hyprland` الإشعارات لذلك البرنامج فقط، ويعيدها `omarchy crash mute hyprland off`، ويسرد `omarchy crash mute` وحده ما كتمته. يأخذ مسار الملف الثنائي بنفس السعادة التي يأخذ بها اسمه، لذا يفعل `omarchy crash mute /usr/bin/hyprland` الشيء نفسه. ضع اسمًا يحتوي على مسافة بين علامتي اقتباس، كما في `omarchy crash mute 'Some App'`. كل شيء آخر ما زال يخطر، والبرنامج المكتم ما زال يتعطل — هذا يخفي التذكير، ولا يصلح أي شيء.

### تطبيقات سطح المكتب

تحمل قائمة _التثبيت > الذكاء الاصطناعي_ أيضًا بعض تطبيقات الذكاء الاصطناعي الرسومية: تطبيق ChatGPT لسطح المكتب، وتطبيق Claude لسطح المكتب (إصدار Linux التجريبي من Anthropic، مع علامات تبويب Chat وCowork وClaude Code)، وGrok Bot للدردشة مع نماذج xAI، وHermes Desktop، وOpenClaw، وتطبيق Perplexity لسطح المكتب، وT3 Code. Grok Bot هو تطبيق الدردشة لسطح المكتب. وكيل البرمجة هو أمر `grok`.

Hermes Desktop هو الذي يجب أن تعرفه، لأن الجهاز لديه Hermes واحد، وهو الخاص بالتطبيق: لا يُثبَّت Hermes أبدًا إلا عبر التطبيق، وأمر `hermes` الذي يشغّله الوكيل الافتراضي هو الخاص بالتطبيق. اختيار Hermes كوكيل افتراضي يثبّت الشيء نفسه الذي يفعله إدخال _التثبيت > الذكاء الاصطناعي_: الحزمة، وبيئة تشغيل Hermes ضمن `~/.hermes` أعدّها مثبّت Hermes نفسه، والتي تستغرق بضع دقائق في المرة الأولى. بيئة التشغيل تلك هي Hermes الوحيدة التي تستخدمها جميعًا أمر `hermes` الطرفي والوكيل الافتراضي والتطبيق، وتحدّث نفسها باستخدام `hermes update` بدلًا من انتظار إصدار Omarchy. يمنحها تثبيتها أيضًا سمة Omarchy كمظهر باسم `omarchy`، تتبعه كل أسطح Hermes أثناء تبديل السمات؛ اختر آخر ضمن إعدادات Appearance الخاصة بـ Hermes أو باستخدام `/skin` إذا كنت تفضّل ألا تفعل، وتترك Omarchy ذلك الاختيار وشأنه. إزالة التطبيق ضمن _الإزالة > الذكاء الاصطناعي_ تغلق Hermes أولًا، بما في ذلك البوابة، وتأخذ بيئة التشغيل تلك معها، وتحتفظ بمحادثاتك وذكرياتك والمهارات التي كتبها Hermes لنفسه ما لم تخبرها بخلاف ذلك: تسأل، مع اختيار لا افتراضيًا، ما إذا كان يجب أن تذهب تلك البيانات وإعدادات اتصالك أيضًا.

تجربة OpenClaw لسطح المكتب هي Control UI الخاصة به، التي تفتح كتطبيق ويب مدعوم ببوابته المحلية الخاصة. يعيش OpenClaw في `~/.openclaw` ويحدّث نفسه: استخدم زر "Update Gateway" في Control UI أو شغّل `openclaw update`، وستعيد البوابة التشغيل على الإصدار الجديد. تختار Omarchy فقط الإصدار الذي يبدأ منه التثبيت الجديد. إزالة OpenClaw ضمن _الإزالة > الذكاء الاصطناعي_ تأخذ خدمة البوابة والتطبيق معها ثم تسأل ما إذا كان يجب أن يذهب `~/.openclaw` أيضًا، لأن ذلك يحتفظ بمحادثاتك وبيانات اعتمادك إلى جانب OpenClaw نفسه وبيئات تشغيل الإضافات التي ينزّلها؛ الخيار الافتراضي يحتفظ به، وتثبيت OpenClaw مرة أخرى يلتقطه من جديد.

يعمل T3 Code من إصدار AppImage الرسمي الخاص به في `~/.local/share/t3code` بدلًا من حزمة، لذا يحدّث نفسه. يسألك تثبيته ما إذا كنت تريد البدء على قناة Stable أو Nightly؛ بدّل لاحقًا في إعدادات T3 Code. تعيش سلاسل محادثاتك وإعداداتك في `~/.t3`، وإزالة T3 Code ضمن _الإزالة > الذكاء الاصطناعي_ تأخذها معها.

### النماذج المحلية

شغّل نموذجًا مفتوحًا على جهازك الخاص لوكلاء البرمجة لديك. تبقى موجّهاتك وشفرتك على الجهاز؛ لا شيء يُرسل إلى النموذج يغادره. ابدأ بـ:

```bash
omarchy agent local use best
```

أو، في لوحة الوكلاء في الشريط العلوي، اختر + ثم Local AI، التي تظهر عندما يناسب نموذج هذا الجهاز. في المرة الأولى، يثبّت هذا Podman، الذي يشغّل النماذج، وعلى جهاز NVIDIA مجموعة أدوات حاويات NVIDIA، التي تمنحها GPU. ثم تختار Omarchy النموذج الموصى به لهذا الجهاز، تنزّله، وتشغّله. توقّع تنزيلًا بعشرات GB وأن تكون معظم ذاكرة الجهاز قيد الاستخدام أثناء تشغيل النموذج: يستخدم Flash Next حوالي 100 GiB مع سياقه الكامل البالغ 256K. إذا احتفظت نماذج أخرى بالذاكرة التي يحتاج إليها، يُعدّ متوقفًا، جاهزًا للبدء بمجرد أن توقف واحدًا. يتوقف النموذج عند تسجيل الخروج؛ أوقفه بنفسك عندما تحتاج الذاكرة لشيء آخر.

يعرض `omarchy agent local list` الخيارات ويشرح سبب عدم ملاءمة بعضها. لإعداد آخر، شغّل `omarchy agent local use <recipe>`. اليوم، يتوفر `qwen3.8-flash-next-halogen` و`qwen3.8-27b-gufo` لأجهزة Strix Halo بسعة 128 GB. تصل الوصفات والتوصيات الجديدة مع `omarchy update`، عبر الحزمة.

يحصل كل نموذج تعدّه على سطر خاص به في لوحة الوكلاء، بجانب اشتراكاتك: تشغيل لبدئه، إيقاف مؤقت لإيقافه وتحرير ذاكرته، وزر الطرفية لفتح وكيلك عليه. يمكن تشغيل عدة منها في وقت واحد عندما تناسب الذاكرة معًا؛ إذا لم يناسب واحد، تخبرك Omarchy بالنموذج قيد التشغيل الذي يجب إيقافه. اسحب السطور لإعادة ترتيبها، واضغط Delete على سطر محدد لإزالة نموذج وتنزيله.

من سطر الأوامر، يفعل `omarchy agent local start <recipe>` و`omarchy agent local stop <recipe>` الشيء نفسه، ويعرض `omarchy agent local status` كل نموذج، ويفتح `omarchy agent --local` وكيلك الافتراضي على آخر نموذج بدأته (pi إذا لم يتمكن وكيلك الافتراضي من استخدام نموذج محلي). يمكن لأي عميل متوافق مع OpenAI الاتصال أيضًا: يعرض `status` عنوان كل نموذج (الأول هو `http://127.0.0.1:11435/v1`)، واسم الوصفة هو النموذج، والمفتاح في `~/.config/omarchy/agent-local/key`.

يحذف `omarchy agent local remove <recipe>` نموذجًا والتنزيلات التي لا يستخدمها أي نموذج آخر.

تُوسم بيئات تشغيل الجهات الخارجية بناشرها. تشغّل Omarchy كل نموذج دون أي وصول إلى الشبكة.

### نماذج LLM المحلية

توصي Omarchy بطريقتين لتشغيل نماذج LLM محلية: LM Studio وOllama. توفّر LM Studio واجهة رسومية للعثور على نماذج مفتوحة الأوزان وتثبيتها وتشغيلها. إنها طريقة رائعة للبدء بسهولة. تقدّم Ollama واجهة سطر أوامر للقيام بذلك بالمثل. لكن إذا كنت جديدًا على النماذج المحلية، سأبدأ بـ LM Studio. يمكنك تثبيت أي منهما ضمن _التثبيت > الذكاء الاصطناعي_ في Omarchy Menu.

### مهارة Omarchy

تساعد مهارات الوكلاء الذكاء الاصطناعي على استخدام أدوات محددة بطريقة محددة، وتأتي Omarchy مع مهارة افتراضية لتخصيص النظام. مثل تعديل إعداد Hyprland الخاص بك، أو ضبط الشريط، أو حتى إنشاء سمة جديدة من الصفر. تُربط رمزيًا في مجلدات مهارات Claude Code (`~/.claude/skills`) وCodex (`~/.codex/skills`) وPi (`~/.pi/agent/skills`) وAntigravity (`~/.gemini/config/skills`) وHermes (`~/.hermes/skills` وكل `~/.hermes/profiles/*/skills`)، والموقع العام `~/.agents/skills`، لذا تلتقطها معظم الأطر تلقائيًا.

لكن يجب أن تعامل هذه المهارة كتجريبية. ستستخدمها نماذج مختلفة بتأثير مختلف. من الأفضل التشغيل في وضع التخطيط أولًا، حتى تكون لديك فكرة عما يرغب الوكيل في تغييره. ثم كن مستعدًا للتراجع عن التغييرات أو حتى استدعاء `omarchy reinstall configs`، إذا أحدث الوكيل فوضى في كل شيء.
