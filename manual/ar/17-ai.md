# الذكاء الاصطناعي

يتضمن Omarchy مشغّلات لوكلاء البرمجة أدناه دون أن يختار لك واحدًا افتراضيًا. شغّل أمرًا لتثبيت واجهة سطر الأوامر CLI الخاصة به عند أول استخدام، ثم قم بالمصادقة عند مطالبتك بذلك. Hermes هو الاستثناء: لا يُثبّت أي شيء له عند أول استخدام، واختياره يثبّت Hermes Desktop، كما هو موضح في _تطبيقات سطح المكتب_ أدناه.

### تثبيت الوكلاء وتحديثهم

باستثناء Hermes، يستخدم هؤلاء الوكلاء التثبيت الكسول من mise: أول تشغيل يثبّت واجهة سطر الأوامر CLI، والتشغيلات اللاحقة تعيد استخدامها. يتحقق mise أيضًا من وجود إصدار جديد لوكيل مثبت مرة واحدة على الأكثر كل أربع ساعات، قبل بدئه مباشرة أو في الخلفية عند موجه shell. إذا فشل ذلك التحديث أو كنت غير متصل، يعمل الإصدار المثبت. يحدّث `omarchy update` الوكلاء المثبتين مع بقية Omarchy، ويحدّث `mup` الأدوات التي يديرها mise فقط.

لا يحدّث محدّث الوكيل نفسه، مثل `claude update` أو `codex update` أو زر تحديث في تطبيق، التثبيت الذي يديره mise. يفشل `codex update`، ويمكن أن يفيد `claude update` بالنجاح بينما يثبّت نسخة منفصلة لا يتتبعها mise. إذا كنت تفضل استخدام المثبّت والمحدّث الأصليين لوكيل ما، أضفه إلى `disable_tools`؛ راجع [أدوات CLI المثبتة مسبقًا](18-development-tools.md#preinstalled-cli-tools).

لتثبيت جميع الأدوات الكسولة المهيأة قبل أن تحتاج إليها، شغّل `mise install --include-lazy`. يشمل هذا أدوات CLI الافتراضية الأخرى في Omarchy بالإضافة إلى الوكلاء. راجع [أدوات CLI المثبتة مسبقًا](18-development-tools.md#preinstalled-cli-tools) لتثبيت أداة واحدة أو استخدام تثبيتك الخاص.

يُثبّت `grok` عبر حزمة `grok` الأصلية من mise، بالطريقة نفسها التي يُثبّت بها `claude` و`codex`. شغّل `grok`، أو اختره ضمن _الإعداد > الإعدادات الافتراضية > الوكيل_. تجاوز مثبّت `curl | bash` على x.ai. ذلك المسار يضع نسخة ثانية في `~/.grok/bin`، ويضعها في مقدمة `PATH`، ويكتب فوق مشغّل Omarchy.

يفتح `dsh` واجهة المتصفح الخاصة به على `127.0.0.1:3080`، مع دليل التشغيل كمساحة عمل افتراضية له. لا تأخذ واجهة المتصفح الخاصة به موجهًا ابتدائيًا، لذا فإن `omarchy agent prompt` يفتحه مع الموجه على حافظتك للصقه. يبدأ Omarchy تشغيله بإعداد إذن عدم الموافقة المسبق من DeepSeek. يرفع DeepSeek Harness سجلات الجلسة إلى DeepSeek عندما تستخدم واجهة برمجة تطبيقات نموذجه الرسمية API؛ أوقف ذلك ضمن _الإعدادات > عام > رفع سجل الجلسة_ في واجهة المتصفح الخاصة به. تُرفع الملاحظات التي ترسلها إليه مع الجلسة أيضًا، ما لم تشغّله بـ `DSH_TELEMETRY_MODE=DISABLED`.

### الوكيل الافتراضي

اختر وكيلك الافتراضي بـ `omarchy default agent <name>` أو ضمن _الإعداد > الإعدادات الافتراضية > الوكيل_ في قائمة Omarchy (`Super + Space`). إذا لم يكن الوكيل مثبتًا بعد، فإن اختياره يثبّته أولًا. سيدعوك Omarchy جديد إلى اتخاذ هذا الخيار بإشعار لمرة واحدة.

يحاول اختيار Claude أيضًا إعداد إضافة المتصفح الخاصة به لـ Chromium وChrome وBrave وBrave Origin وEdge. ينطبق إعداد الإضافة على جميع المستخدمين وقد يطلب كلمة مرور النظام الخاصة بك؛ إلغاء تثبيت الإضافة أو فشله لا يزال يختار Claude ويشغّله. أعد تشغيل متصفحك، وفعّل الإضافة إذا طُلب منك ذلك، وسجّل الدخول إلى Claude لإنهاء توصيلها. شغّل `/chrome` في Claude للتحقق من الاتصال. لا يدعم Firefox وZen هذه الإضافة. إذا كان Claude هو وكيلك الافتراضي بالفعل قبل إضافة هذا الإعداد، اختره مرة أخرى لتثبيت الإضافة.

بمجرد أن تختار، يشغّل `Super + Shift + Ctrl + A` الوكيل الافتراضي في نافذة طرفية مخصصة (أو يعرض المنتقي إذا لم تكن قد اخترت بعد). يمكنك أيضًا تشغيله مباشرة في مهمة بـ `omarchy agent prompt "Review this project"`. لا يأخذ Freebuff وDeepSeek Harness موجهًا ابتدائيًا، لذا يفتحان مع الموجه على حافظتك للصقه بدلًا من ذلك. يعمل الوكلاء المشغّلون بهذه الطريقة دون مراقبة في أوضاع عدم التوقف للسؤال الخاصة بكل منهم، لذا كن مستعدًا لهم للقيام بأشياء فعليًا! لا يمتلك MiniMax Code مثل هذا الوضع لجلساته التفاعلية، لذا يطلب الأذونات كالمعتاد. وبما أن الوكلاء يرفضون تذكّر الثقة لدليلك الرئيسي، تبدأ التشغيلات من `$HOME` في `~/Work` بدلًا من ذلك.

هناك اختصارات طرفية أيضًا: يشغّل `a` الوكيل الافتراضي مضمنًا في الطرفية الحالية، بينما يبدأ `c` و`cx` و`cy` كلًا من OpenCode وClaude Code وCodex مباشرة (مرة أخرى في أوضاع الموافقة التلقائية الخاصة بها). تتزامن تغييرات السمة مع الوكلاء أيضًا: يتبع كل من Claude Code وPi وOpenCode وHermes (بمجرد أن يثبّته Omarchy) التغييرات عندما تبدّل سمة Omarchy.

### لوحة الوكلاء

يحتوي الشريط العلوي على أيقونة وكلاء. قبل أن تعدّ وكيلًا، ترشدك لوحتها خلال تسجيل الدخول إلى Claude أو Codex أو Grok، ويصبح الأول وكيلك الافتراضي. بعد ذلك، تضع اللوحة كل اشتراك على صفحة واحدة: كل وكيل وحساب مع خطته، وعداد لكل من حد جلسته البالغ 5 ساعات وحدوده الأسبوعية مع الوقت حتى إعادة تعيينه (مرّر للاطلاع على النسبة المئوية الدقيقة)، أو الرصيد المدفوع مسبقًا المتبقي، تحت سطر يدور عبر ما استخدمته عبرها جميعًا، مثل الرموز هذا الأسبوع ونموذجك الأكثر استخدامًا. ضمن _اصنع شيئًا_ تقدم موجهات ابتدائية لسمة أو إضافة أو تطبيق جديد تسلّم المهمة إلى وكيلك الافتراضي. تُبنى التطبيقات بالطريقة نفسها التي بُنيت بها تطبيقات Omarchy الخاصة Hype وMonologue وOmacut، بلغة C++ وQt Quick، باتباع مهارة وكيل omarchy-app، ويأتي المترجم وقطع Qt التي تحتاجها مثبتة. يتم تغطية Claude Code وCodex وGrok وKimi وCursor ومخصص Grok Bot الخاص به وGitHub Copilot وMuse وAntigravity وKimchi وDevin جاهزة مع حدودها، ويعرض Hermes وMistral Vibe وQwen Code جلساتهم ورموزهم بمجرد استخدامها. تظهر أيضًا خطط ومفاتيح المزودين التي تستخدمها عبر pi أو omp أو opencode: OpenCode Zen وGo وخطة Z.ai GLM Coding Plan وOllama Cloud وخطة MiniMax Token Plan وSynthetic مع حدودها؛ وFireworks وOpenRouter وDeepSeek مع أرصدتها المدفوعة مسبقًا؛ والنماذج التي تشغّلها على أجهزتك الخاصة ضمن النماذج المحلية. يُحسب كل وكيل مرة واحدة، تحت من يفوتره، مهما كان عدد الأطر التي تشغّله عبرها.

انقر بزر الماوس الأيسر على أيقونة الشريط للوحة، وانقر بزر الماوس الأيمن لتشغيل وكيلك الافتراضي. تُعاد إنشاء سجلات الاستخدام وراءها كل 15 دقيقة بواسطة `omarchy agent usage-update`، ويمكن للوحة حتى دمج الاستخدام من أجهزتك الأخرى عبر مجلد متزامن. راجع README ضمن `$OMARCHY_PATH/shell/plugins/agents/` للإعدادات الكاملة.

### اشتراكات متعددة

إذا كنت تدفع مقابل أكثر من خطة Claude أو Codex أو Grok واحدة — خطة Max شخصية وخطة عمل، على سبيل المثال — يمكن لـ Omarchy إبقاءها جميعًا مسجلة الدخول والتنقل بينها. أضف اشتراكًا بعلامة + في لوحة الوكلاء، التي ترشدك خلال ذلك هناك مباشرة، أو بـ `omarchy agent account add claude Work` (أو `codex` أو `grok`). يثبّت واجهة سطر الأوامر CLI إذا كانت مفقودة. يسجّل الحساب الأول لمزود الدخول عبر متصفحك العادي، حيث تبحث واجهة سطر الأوامر دائمًا. يسجّل كل حساب بعد ذلك الدخول عبر نافذة خاصة، بحيث لا يُلتقط الحساب الذي سجّل متصفحك الدخول إليه بالفعل عن طريق الخطأ؛ سجّل الدخول هناك كالحساب الذي تضيفه، وأغلق أي نافذة خاصة مفتوحة لديك بالفعل أولًا. لا تسجّل الخروج من واجهة سطر الأوامر أبدًا للقيام بذلك: تسجيل الخروج يلغي تسجيل الدخول المحفوظ، وسيتعين إضافة ذلك الحساب مرة أخرى.

لنسخ تسجيلات دخول اشتراكاتك إلى جهاز Omarchy آخر عبر SSH، شغّل `omarchy agent account copy user@laptop`. يزود المرسل جهاز استقبال مؤقتًا عندما لا يكون لدى الوجهة واحد مثبت، بحيث يمكن لأجهزة Omarchy الأقدم استقبال الحسابات دون تحديث. تأخذ أجهزة الاستقبال المثبتة الأسبقية. ينسخ هذا جميع اشتراكات Claude وCodex وGrok؛ أضف أسماء المزودين لتحديدها، كما في `omarchy agent account copy laptop claude`. تتطابق أسماء الحسابات ومعرفات الأوامر مع المصدر، بما في ذلك الحسابات الموجودة بالفعل على الوجهة. تتلقى حسابات الوجهة غير ذات الصلة لاحقة رقمية إذا تعارضت أسماؤها، وتبقى الإعدادات والمهارات والإضافات وسجل المحادثات محلية لكل جهاز.

تُحفظ بيانات اعتماد الوجهة الحالية. الحساب المصدري المسجل الدخول هناك بالفعل تتم مزامنة اسمه دون استبدال بيانات اعتماده؛ تُضاف الحسابات الأخرى بجانبه. لاستبدال بيانات الاعتماد المحفوظة للحسابات المطابقة، استخدم `omarchy agent account copy --replace laptop claude` بعد إنهاء جلسات ذلك الحساب على الوجهة. تحصل الوجهة الجديدة أيضًا على الحساب النشط وتفضيلات التبديل للمصدر؛ تحتفظ الوجهة القائمة بتفضيلاتها الخاصة.

تنتقل بيانات الاعتماد عبر SSH وتُخزّن في ملفات خاصة على الوجهة، لذا انسخ فقط إلى أجهزة تثق بها. هذه نسخة لمرة واحدة، وليست مزامنة مستمرة. يمكن لجهاز آخر تدوير رموز تحديث Codex، مما يترك تسجيل دخول منسوخًا بحاجة إلى تجديد؛ تبقى عمليات تسجيل الدخول المنفصلة الخيار الأكثر موثوقية للاستخدام المتزامن على عدة أجهزة. راجع [إرشادات مصادقة الحساب في Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

حساب واحد لكل مزود نشط، وتبدأ كل جلسة جديدة به: `cx` و`cy` و`claude` أو `codex` أو `grok` العادي، وأي شيء يُشغّل عبر `omarchy agent`، والبرامج النصية أو المحررات التي تجد واجهة سطر الأوامر على `PATH`. بدّل بـ `omarchy agent account use work` (وعد بـ `omarchy agent account use main`)، أو في اللوحة بالضغط على رقم الحساب ثم `Enter` (أو النقر على زر الاستخدام الخاص به). تبقى الجلسات قيد التشغيل بالفعل على الحساب الذي بدأت به. يتم مشاركة سجل المحادثات والإعدادات والمهارات والإضافات عبر الحسابات، لذا فإن `claude --continue` في المجلد نفسه يتابع من حيث توقفت على الحساب الجديد.

مع وجود أكثر من حساب واحد، تعرض اللوحة حدود كل حساب جنبًا إلى جنب، مع وضع علامة على الحساب النشط. افتراضيًا، يعلمك Omarchy عندما يتجاوز الحساب النشط 95% من حد ما، والنقر على الإشعار يبدّل إلى الحساب ذي أكبر هامش. مرّر على سطر حساب في اللوحة وانقر على Autoswitch الذي يظهر بجانب Use (أو اضغط `m`)، أو شغّل `omarchy agent account mode auto`، لجعله يبدّل من تلقاء نفسه بدلًا من ذلك؛ أثناء تشغيله، يأخذ Autoswitch مكان Use، والنقر عليه مرة أخرى يعود إلى الإشعار. أضف رقمًا لتغيير العتبة، كما في `omarchy agent account mode auto 90`. إذا تجاوز كل حساب العتبة، ستسمع عن ذلك مرة واحدة، مع أي حساب سيتاح أولًا. بينما يكون الحساب النشط ضمن 15 نقطة من عتبته (80% افتراضيًا)، يتم التحقق من حدوده كل ثلاث دقائق بدلًا من كل 15 دقيقة.

يعرض `omarchy agent account list` كل حساب وآخر حدوده، وينسى `omarchy agent account remove work` واحدًا، ويعيد `omarchy agent account rename primary Hey` تسمية واحد (أو انقر على اسم حساب في اللوحة). تعمل هذه الأوامر على حسابات وكيلك الافتراضي؛ للوصول إلى المزود الآخر، سمّه أولًا، كما في `omarchy agent account use codex side`. تسجيل الدخول الذي كان لديك بالفعل في `~/.claude` أو `~/.codex` هو حساب _Main_ ويبقى حيث هو. يمكن لحساب تُرك غير مستخدم لأكثر من حوالي ثماني ساعات أن يعرض _يلزم تسجيل الدخول_؛ انقر عليه لتسجيل دخول ذلك الحساب مرة أخرى في اللوحة مباشرة، أو ابدأ جلسة فيه، مما ينعش تسجيل الدخول من تلقاء نفسه. تأتي خوادم MCP التي كانت لديك عند إضافة حساب معها إليه، لكن تلك التي تضيفها لاحقًا بـ `claude mcp add` تصل فقط إلى الحساب الذي أضفتها فيه. لا يتبع Claude Desktop والأدوات المهيأة بمسار مطلق إلى ملف تنفيذي لواجهة سطر الأوامر التبديل. يأخذ `CLAUDE_CONFIG_DIR` أو `CODEX_HOME` أو `GROK_HOME` الصريح الأسبقية على الحساب المحدد.

### تشخيص الأعطال

يراقب Omarchy systemd-coredump لأعطال العمليات. عندما يحدث خطأ تجزئة لشيء ما، ستحصل على إشعار "تعطّلت العملية" — انقر عليه، ويُسلّم العطل إلى وكيلك الافتراضي مع مهارة diagnose-crash في Omarchy، التي ترشد الوكيل خلال إثبات الحقائق من تفريغ النواة وتحديد ما إذا كان العطل يستحق الإبلاغ عنه إلى المصدر. يمكنك أيضًا تشغيله يدويًا مقابل أي PID من `coredumpctl list` بـ `omarchy agent crash <pid>`.

المراقبة مفعّلة افتراضيًا. أوقفها ضمن _المشغّل > التبديل > التقاط الأعطال_ (أو بـ `omarchy toggle crash-capture`) وتتوقف الإشعارات؛ لا يزال `omarchy agent crash <pid>` يعمل يدويًا.

يمكن أيضًا إسكات الأعطال برنامجًا واحدًا في كل مرة، وهو ما يقدمه لك التشخيص في النهاية. يوقف `omarchy crash mute hyprland` الإشعارات لذلك البرنامج فقط، ويعيدها `omarchy crash mute hyprland off`، ويسرد `omarchy crash mute` وحده ما كتمته. يقبل مسار الملف التنفيذي بسهولة كاسمه، لذا فإن `omarchy crash mute /usr/bin/hyprland` يفعل الشيء نفسه. ضع اسمًا يحتوي على مسافة بين علامات اقتباس، كما في `omarchy crash mute 'Some App'`. لا يزال كل شيء آخر يعلمك، ولا يزال البرنامج المكتوم يتعطل — هذا يخفي التذكير، ولا يصلح أي شيء.

### تطبيقات سطح المكتب

تحمل قائمة _التثبيت > الذكاء الاصطناعي_ أيضًا بعض تطبيقات الذكاء الاصطناعي الرسومية: تطبيق ChatGPT لسطح المكتب، وتطبيق Claude لسطح المكتب (إصدار Linux التجريبي من Anthropic، مع علامات تبويب Chat وCowork وClaude Code)، وGrok Bot للدردشة مع نماذج xAI، وHerdr Desktop وHermes Desktop وOpenClaw وتطبيق Perplexity لسطح المكتب وT3 Code. Grok Bot هو تطبيق الدردشة لسطح المكتب. وكيل البرمجة هو أمر `grok`.

Hermes Desktop هو التطبيق الذي يجب أن تعرفه، لأن الجهاز لديه Hermes واحد، وهو خاص بالتطبيق: لا يُثبّت Hermes أبدًا إلا عبر التطبيق، وأمر `hermes` الذي يشغّله الوكيل الافتراضي هو خاص بالتطبيق. اختيار Hermes كوكيل افتراضي يثبّت الشيء نفسه الذي يثبّته إدخال _التثبيت > الذكاء الاصطناعي_: الحزمة، وبيئة تشغيل Hermes ضمن `~/.hermes` يعدّها مثبّت Hermes نفسه، والتي تستغرق بضع دقائق في المرة الأولى. بيئة التشغيل تلك هي Hermes الواحدة التي يستخدمها أمر `hermes` الطرفي والوكيل الافتراضي والتطبيق جميعًا، وتحدّث نفسها بـ `hermes update` بدلًا من انتظار إصدار Omarchy. يمنح تثبيته أيضًا Hermes سمة Omarchy كجلد باسم `omarchy`، تتبعه كل أسطح Hermes أثناء تبديل السمات؛ اختر آخر ضمن إعدادات المظهر في Hermes أو بـ `/skin` إذا كنت تفضل ألا يفعل، ويترك Omarchy ذلك الخيار وشأنه. إزالة التطبيق ضمن _الإزالة > الذكاء الاصطناعي_ تغلق Hermes أولًا، بما في ذلك البوابة، وتأخذ بيئة التشغيل تلك معها، وتحتفظ بدردشاتك وذكرياتك والمهارات التي كتبها Hermes لنفسه ما لم تخبره بخلاف ذلك: يسأل، مع اختيار لا افتراضيًا، ما إذا كان يجب أن تذهب تلك البيانات وإعدادات اتصالك أيضًا.

تجربة OpenClaw لسطح المكتب هي واجهة Control UI الخاصة به، التي تفتح كتطبيق ويب مدعوم ببوابته المحلية الخاصة. يعيش OpenClaw في `~/.openclaw` ويحدّث نفسه: استخدم زر "تحديث البوابة" في Control UI أو شغّل `openclaw update`، وتعيد البوابة التشغيل على الإصدار الجديد. يختار Omarchy فقط الإصدار الذي يبدأ منه تثبيت جديد. إزالة OpenClaw ضمن _الإزالة > الذكاء الاصطناعي_ تأخذ خدمة البوابة والتطبيق معها ثم تسأل ما إذا كان يجب أن يذهب `~/.openclaw` أيضًا، بما أن ذلك يحتوي على دردشاتك وبيانات اعتمادك إلى جانب OpenClaw نفسه وبيئات تشغيل الإضافات التي ينزّلها؛ الافتراضي يحتفظ به، وتثبيت OpenClaw مرة أخرى يستعيده.

Herdr Desktop هو تطبيق [Herdr](https://herdr.dev) لسطح المكتب: مساحات وعلامات تبويب وأجزاء من الطرفيات ووكلاء البرمجة التي تستمر في العمل في نواتها عندما تغلق النافذة. يأتي من مثبّت Herdr نفسه بدلًا من حزمة، لذا يعيش في `~/.local/share/herdr-app`، ويجلب نواته معه في `~/.local/bin/herdr-core` عندما لا يكون لديك واحد بعد، ويحدّث نفسه وكليهما. يجلس بجانب أمر `herdr` الذي يشحنه Omarchy على `Super + Ctrl + Return` بدلًا من استبداله. يختار تثبيته سمة Omarchy في Herdr، التي تتبع سمة Omarchy الخاصة بك من ذلك الحين. يحتفظ Herdr بسمة واحدة للوضع الفاتح وواحدة للوضع الداكن، لذا بعد التبديل بين سمة Omarchy داكنة وفاتحة، اختر Omarchy في منتقي سمات Herdr مرة أخرى للوضع الآخر.

يعمل T3 Code من إصدار AppImage الرسمي الخاص به في `~/.local/share/t3code` بدلًا من حزمة، لذا يحدّث نفسه. يسألك تثبيته ما إذا كنت تبدأ على قناة Stable أو Nightly؛ بدّل لاحقًا في إعدادات T3 Code. تعيش سلاسل محادثاتك وإعداداتك في `~/.t3`، وإزالة T3 Code ضمن _الإزالة > الذكاء الاصطناعي_ تأخذها معها.

### النماذج المحلية

شغّل نموذجًا مفتوحًا على جهازك الخاص لوكلاء البرمجة لديك. تبقى موجهاتك ورمزك على الجهاز؛ لا شيء يُرسل إلى النموذج يغادره. ابدأ بـ:

```bash
omarchy agent local use best
```

أو، في لوحة الوكلاء في الشريط العلوي، اختر + ثم Local AI، التي تظهر عندما يناسب نموذج هذا الجهاز. في المرة الأولى، يثبّت هذا Podman، الذي يشغّل النماذج، وعلى جهاز NVIDIA مجموعة أدوات حاويات NVIDIA، التي تمنحها GPU. ثم يختار Omarchy النموذج الموصى به لهذا الجهاز، وينزّله، ويشغّله. توقع تنزيلًا بعشرات GB وأن معظم ذاكرة الجهاز ستكون قيد الاستخدام أثناء تشغيل النموذج: يستخدم Flash Next حوالي 100 GiB مع سياقه الكامل 256K. إذا كانت نماذج أخرى تحتفظ بالذاكرة التي يحتاجها، يُعدّ متوقفًا، جاهزًا للبدء بمجرد إيقاف واحد. يتوقف النموذج عند تسجيل الخروج؛ أوقفه بنفسك عندما تحتاج الذاكرة لشيء آخر.

يعرض `omarchy agent local list` الخيارات ويشرح سبب عدم ملاءمة بعضها. لإعداد آخر، شغّل `omarchy agent local use <recipe>`. اليوم، يتوفر `qwen3.8-flash-next-gufo` و`qwen3.8-27b-gufo` لأجهزة Strix Halo بسعة 128 GB؛ يأخذ 27B حوالي 40 GiB، لذا يترك مساحة لأعمال أخرى. تصل وصفات وتوصيات جديدة مع `omarchy update`، عبر الحزمة.

يحصل كل نموذج تعدّه على سطره الخاص في لوحة الوكلاء، بجانب اشتراكاتك: تشغيل لبدئه، وإيقاف مؤقت لإيقافه وتحرير ذاكرته، وزر الطرفية لفتح وكيلك عليه. يمكن تشغيل عدة منها في وقت واحد عندما تناسب الذاكرة معًا؛ إذا لم يناسب واحد، يخبرك Omarchy بأي نموذج قيد التشغيل يجب إيقافه. اسحب السطور لإعادة ترتيبها، واضغط Delete على سطر محدد لإزالة نموذج وتنزيله.

من سطر الأوامر، يفعل `omarchy agent local start <recipe>` و`omarchy agent local stop <recipe>` الشيء نفسه، ويعرض `omarchy agent local status` كل نموذج، ويفتح `omarchy agent --local` وكيلك الافتراضي على آخر نموذج بدأته (pi إذا لم يتمكن وكيلك الافتراضي من استخدام نموذج محلي). يمكن لأي عميل متوافق مع OpenAI الاتصال أيضًا: يعرض `status` عنوان كل نموذج (الأول هو `http://127.0.0.1:11435/v1`)، واسم الوصفة هو النموذج، والمفتاح موجود في `~/.config/omarchy/agent-local/key`.

يحذف `omarchy agent local remove <recipe>` نموذجًا والتنزيلات التي لا يستخدمها أي نموذج آخر.

تُوسم بيئات تشغيل الجهات الخارجية بناشرها. يشغّل Omarchy كل نموذج دون وصول إلى الشبكة.

### نماذج LLM المحلية

يوصي Omarchy بطريقتين لتشغيل نماذج LLM محلية: LM Studio وOllama. يوفر LM Studio واجهة رسومية GUI لإيجاد النماذج مفتوحة الأوزان وتثبيتها وتشغيلها. إنها طريقة رائعة للبدء بسهولة. يقدم Ollama واجهة سطر أوامر CLI للقيام بذلك بالمثل. لكن إذا كنت جديدًا على النماذج المحلية، فسأبدأ بـ LM Studio. يمكنك تثبيت أي منهما ضمن _التثبيت > الذكاء الاصطناعي_ في قائمة Omarchy.

### مهارة Omarchy

تساعد مهارات الوكيل الذكاء الاصطناعي على استخدام أدوات محددة بطريقة محددة، ويأتي Omarchy مع مهارة افتراضية لتخصيص النظام. مثل تعديل إعداد Hyprland الخاص بك، أو ضبط الشريط، أو حتى إنشاء سمة جديدة من الصفر. إنها مرتبطة رمزيًا في دلائل مهارة Claude Code (`~/.claude/skills`) وCodex (`~/.codex/skills`) وPi (`~/.pi/agent/skills`) وAntigravity (`~/.gemini/config/skills`) وHermes (`~/.hermes/skills` وكل `~/.hermes/profiles/*/skills`)، وموقع `~/.agents/skills` العام، لذا تلتقطها معظم الأطر تلقائيًا.

لكن يجب أن تعامل هذه المهارة كتجريبية. ستستخدمها نماذج مختلفة بتأثيرات مختلفة. من الأفضل تشغيلها في وضع التخطيط أولًا، بحيث يكون لديك فكرة عما يرغب الوكيل في تغييره. ثم كن مستعدًا للتراجع عن التغييرات أو حتى استدعاء `omarchy reinstall configs`، إذا أحدث الوكيل فوضى في كل شيء.
