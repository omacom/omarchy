# الذكاء الاصطناعي

يتضمن Omarchy مشغّلات لوكلاء البرمجة أدناه دون أن يختار لك واحدًا افتراضيًا. شغّل أمرًا لتثبيت الواجهة CLI الخاصة به عند الاستخدام الأول، ثم أكمل المصادقة عند مطالبتك بذلك. يُعد Hermes وOpenClaw الاستثناءين: لا يُثبَّت أي شيء لهما عبر mise، واختيار أيٍّ منهما يُعدّ نسخته الخاصة ذاتية التحديث، كما يشرح قسم _تطبيقات سطح المكتب_ أدناه.

### تثبيت الوكلاء وتحديثهم

باستثناء Hermes وOpenClaw، تستخدم هذه الوكلاء التثبيت الكسول من mise: التشغيل الأول يثبّت الواجهة CLI، والتشغيلات اللاحقة تعيد استخدامها. تتحقق mise أيضًا من وجود إصدار جديد لوكيل مثبّت مرة واحدة على الأكثر كل أربع ساعات، قبل بدئه مباشرة أو في الخلفية عند ظهور موجّه shell. إذا فشل ذلك التحديث أو كنت غير متصل، يعمل الإصدار المثبّت. يحدّث `omarchy update` الوكلاء المثبّتين مع بقية Omarchy، ويحدّث `mup` الأدوات التي تديرها mise فقط.

لا يحدّث محدّث الوكيل نفسه، مثل `claude update` أو `codex update` أو زر تحديث في تطبيق، التثبيت الذي تديره mise. يفشل `codex update`، وقد يفيد `claude update` بالنجاح بينما يثبّت نسخة منفصلة لا تتتبعها mise. إذا كنت تفضّل استخدام المثبّت والمحدّث الأصليين للوكيل، فأضفه إلى `disable_tools`؛ راجع [أدوات CLI المثبتة مسبقًا](18-development-tools.md#preinstalled-cli-tools).

لتثبيت جميع الأدوات الكسولة المهيأة قبل أن تحتاج إليها، شغّل `mise install --include-lazy`. يشمل ذلك أدوات CLI الافتراضية الأخرى في Omarchy إضافة إلى الوكلاء. راجع [أدوات CLI المثبتة مسبقًا](18-development-tools.md#preinstalled-cli-tools) لتثبيت أداة واحدة أو استخدام تثبيتك الخاص.

يُثبَّت `grok` عبر حزمة `grok` الرسمية من mise، بالطريقة نفسها المتبعة مع `claude` و`codex`. شغّل `grok`، أو ضع له نجمة في لوحة الوكلاء. تخطَّ مثبّت `curl | bash` الموجود على x.ai. فذلك المسار يضع نسخة ثانية في `~/.grok/bin`، ويضعها في مقدمة `PATH`، ويستبدل غلاف Omarchy.

يفتح `dsh` واجهة متصفحه على `127.0.0.1:3080`، مع مجلد التشغيل كمساحة عمل افتراضية له. لا تأخذ واجهة متصفحه موجّه بدء، لذا فإن `omarchy agent prompt` يفتحه مع نسخ الموجّه إلى حافظتك للصقه. يبدأ Omarchy به مع إعداد أذونات DeepSeek بعدم طلب الموافقة. يرفع DeepSeek Harness سجلات الجلسة إلى DeepSeek عند استخدامك واجهة API الرسمية لنماذجه؛ أوقف ذلك من _Settings > General > Upload Session Log_ في واجهة متصفحه. تُرفع الملاحظات التي ترسلها إليه مع الجلسة أيضًا، ما لم تبدأ به مع `DSH_TELEMETRY_MODE=DISABLED`.

### الوكيل الافتراضي

اختر وكيلك الافتراضي بواسطة النجمة المجاورة لوكيل في لوحة الوكلاء، وهي مملوءة على الافتراضي، أو بواسطة `omarchy default agent <name>`، الذي يقبل أيضًا أي إطار عمل ليس له سطر هناك. إذا لم يكن الوكيل مثبّتًا بعد، فإن اختياره يثبّته أولًا، ويحصل أيضًا على مشغّل خاص به في مشغّل التطبيقات، بجوار Agent. يدعوك تثبيت Omarchy جديد إلى إعداد واحد عبر إشعار يظهر مرة واحدة، يفتح لوحة الوكلاء.

يحاول اختيار Claude أيضًا إعداد إضافة متصفحه لـ Chromium وChrome وBrave وBrave Origin وEdge. ينطبق إعداد الإضافة على جميع المستخدمين وقد يطلب كلمة مرور نظامك؛ إلغاؤه أو فشل تثبيت الإضافة ما زال يختار Claude ويشغّله. أعد تشغيل متصفحك، فعّل الإضافة إذا طُلب منك ذلك، وسجّل الدخول إلى Claude لإنهاء توصيلها. شغّل `/chrome` في Claude للتحقق من الاتصال. لا يدعم Firefox وZen هذه الإضافة. إذا كان Claude وكيلك الافتراضي بالفعل قبل إضافة هذا الإعداد، فاختره مرة أخرى لتثبيت الإضافة.

بعد أن تختار، يشغّل `Super + Shift + Ctrl + A` الوكيل الافتراضي في نافذة طرفية مخصصة (أو يُظهر المنتقي إذا لم تكن قد اخترت بعد). يمكنك أيضًا تشغيله مباشرة في مهمة بواسطة `omarchy agent prompt "Review this project"`. لا يأخذ Freebuff وDeepSeek Harness موجّه بدء، لذا يفتحان مع نسخ الموجّه إلى حافظتك للصقه بدلًا من ذلك. تعمل الوكلاء المشغّلة بهذه الطريقة دون مراقبة في أوضاع عدم التوقف للسؤال الخاصة بكل منها، لذا كن مستعدًا لأن تقوم بأمور فعليًا! ليس لدى MiniMax Code وضع كهذا لجلساته التفاعلية، لذا يطلب الأذونات كالمعتاد. وبما أن الوكلاء ترفض تذكّر الثقة لمجلدك الرئيسي، فإن التشغيلات من `$HOME` تبدأ في `~/Work` بدلًا من ذلك.

توجد اختصارات طرفية أيضًا: يشغّل `a` الوكيل الافتراضي ضمن الطرفية الحالية، بينما تبدأ `c` و`cx` و`cy` بـ OpenCode وClaude Code وCodex مباشرة (مرة أخرى في أوضاع الموافقة التلقائية الخاصة بها). تتزامن تغييرات السمة مع الوكلاء أيضًا: Claude Code وPi وOpenCode وHermes (بمجرد أن يثبّته Omarchy) كلها تتابعك عندما تبدّل سمة Omarchy.

### تعليمات وكيلك

تذهب القواعد الشخصية لكل وكيل في `~/.agents/AGENTS.md`، بجوار المهارات المشتركة في `~/.agents/skills`. افتحه بواسطة أيقونة المستند المجاورة لـ + في لوحة الوكلاء، أو `omarchy agent instructions --edit`، الذي يربطه أيضًا بكل إطار عمل يحتفظ بملفه العام الخاص: `~/.claude/CLAUDE.md` و`~/.codex/AGENTS.md` و`~/.pi/agent/AGENTS.md` و`~/.config/opencode/AGENTS.md` و`~/.copilot/copilot-instructions.md` الخاص بـ Copilot، وهكذا. يقرأ Crush وAmp رابط `~/.config/AGENTS.md`، بينما يقرأ omp وKimi وDeepSeek Harness ملف `~/.agents/AGENTS.md` مباشرة. اختيار وكيل افتراضي يربطه أيضًا. يصبح ملف تعليمات كان لديك بالفعل هو المشترك إذا لم يكن يوجد واحد بعد؛ وإلا يُحتفظ به بجوار الرابط باسم `.bak`. شغّل `omarchy agent instructions` لإعادة الربط بعد تثبيت وكيل آخر.

### لوحة الوكلاء

يوجد في الشريط العلوي أيقونة للوكلاء. قبل أن تُعد وكيلًا، تعرض لوحته ثلاث طرق للبدء: تسجيل الدخول إلى اشتراك Claude أو Codex أو Grok أو Gemini أو Muse أو Cursor أو Copilot، أو ضمن More خطة برمجة OpenCode Go أو MiniMax أو Synthetic أو Z.ai؛ الدفع حسب الاستخدام مع Fireworks أو OpenCode Zen and Go أو OpenRouter، أو ضمن More مع DeepSeek أو أي مزود آخر يسجّل OpenCode الدخول إليه، وكلها تعمل في OpenCode؛ أو تشغيل أفضل نموذج لجهازك، عندما يناسبه واحد. أول واحد تنهيه يصبح وكيلك الافتراضي، وتعرض علامة + في اللوحة، أو _Agent > Add_ في قائمة Omarchy، الثلاثة نفسها لاحقًا. بعد ذلك، تضع اللوحة كل اشتراك في صفحة واحدة: كل وكيل وحساب مع خطته، ومقياس لكل من حد جلسة 5 ساعات وحدوده الأسبوعية مع الوقت حتى إعادة التعيين (مرّر للاطلاع على النسبة الدقيقة)، أو الرصيد المدفوع مسبقًا المتبقي، تحت سطر يدور عبر ما استخدمته عبرها جميعًا، مثل الرموز هذا الأسبوع ونموذجك الأكثر استخدامًا. ضمن _Make something cool_ تعرض موجّهات بداية لموضوع أو إضافة أو تطبيق أو لعبة جديدة تسلّم المهمة إلى وكيلك الافتراضي. تُبنى التطبيقات بالطريقة التي تُبنى بها تطبيقات Omarchy الخاصة Hype وMonologue وOmacut، بلغة C++ وQt Quick، باتباع مهارة وكيل omarchy-make-app، والمترجم وقطع Qt التي تحتاجها تأتي مثبّتة. الألعاب هي صفحة three.js واحدة في `~/Games/vibes`، باتباع مهارة وكيل omarchy-make-game، وكلها تفتح من مشغّل Game Vibes واحد في السمة الحالية؛ تحمّل three.js من الويب، لذا تحتاج إلى اتصال للبدء. تُغطى Claude Code وCodex وGrok وKimi وCursor وبدل Grok Bot الخاص به وGitHub Copilot وMuse وGemini (عبر Antigravity) وDevin جاهزة مع حدودها، وKimchi مع خطته وأرصدته المدفوعة مسبقًا وميزانيات إنفاقه، ويعرض Hermes وMistral Vibe وQwen Code جلساتها ورموزها بمجرد أن تستخدمها. تظهر أيضًا خطط المزودين ومفاتيحهم التي تستخدمها عبر pi أو omp أو opencode: OpenCode Zen and Go وخطة Z.ai GLM Coding Plan وOllama Cloud وخطة MiniMax Token Plan وSynthetic مع حدودها؛ OpenRouter وDeepSeek مع أرصدتهما المدفوعة مسبقًا؛ Fireworks مع إنفاقه خلال آخر 30 يومًا. تُحتسب رموز النماذج التي تشغّلها على عتادك الخاص ضمن المجاميع أيضًا؛ للنماذج نفسها لوحة خاصة بها، موصوفة ضمن [النماذج المحلية](#local-models). يُحتسب كل وكيل مرة واحدة، لدى من يفوتره، مهما كان عدد أطر العمل التي تقوده عبرها.

انقر بالزر الأيسر على أيقونة الشريط أو اضغط `Super + Ctrl + X` للوحة، وانقر بالزر الأيمن لتشغيل وكيلك الافتراضي، وانقر بالزر الأوسط للتحديث. تُعاد إنشاء سجلات الاستخدام وراءها كل 15 دقيقة بواسطة `omarchy agent usage update`، ويمكن للوحة حتى دمج الاستخدام من أجهزتك الأخرى عبر مجلد متزامن. اطّلع على README ضمن `$OMARCHY_PATH/shell/plugins/agents/` للإعدادات الكاملة.

### اشتراكات متعددة

إذا كنت تدفع مقابل أكثر من خطة Claude أو Codex أو Grok واحدة — خطة Max شخصية وخطة عمل، على سبيل المثال — يمكن لـ Omarchy إبقاءها جميعًا مسجّلة والدخول والتنقل بينها. أضف اشتراكًا بواسطة + في لوحة الوكلاء، الذي يرشدك خلال ذلك هناك مباشرة، أو بواسطة `omarchy agent account add claude Work` (أو `codex`، أو `grok`). تسجّل علامة + والأمر نفسه الدخول إلى Gemini ‏(`gemini`) وOpenCode ‏(`opencode`)، وتحفظ مفتاح API لـ Fireworks ‏(`fireworks`) أو OpenRouter ‏(`openrouter`) في OpenCode؛ يسجّل الأمر أيضًا الدخول إلى Copilot ‏(`copilot`) وCursor ‏(`cursor`) وMuse ‏(`muse`). يحتفظ هؤلاء بتسجيل دخول واحد لكل منهم. يثبّت الواجهة CLI إذا كانت مفقودة. يسجّل الحساب الأول لمزود الدخول عبر متصفحك العادي، حيث تبحث الواجهة CLI دائمًا. يسجّل كل حساب بعد ذلك الدخول عبر نافذة خاصة، بحيث لا يُلتقط الحساب الذي سجّل متصفحك الدخول إليه بالفعل عن طريق الخطأ؛ سجّل الدخول هناك كالحساب الذي تضيفه، وأغلق أي نافذة خاصة قد فتحتها بالفعل أولًا. لا تسجّل الخروج من الواجهة CLI أبدًا للقيام بذلك: تسجيل الخروج يلغي تسجيل الدخول المحفوظ، وسيتعين إضافة ذلك الحساب مرة أخرى.

لنسخ بيانات تسجيل دخول اشتراكاتك إلى جهاز Omarchy آخر عبر SSH، شغّل `omarchy agent account copy user@laptop`. يوفّر المرسل مستقبلًا مؤقتًا عندما لا يكون لدى الوجهة واحد مثبّت، بحيث يمكن لأجهزة Omarchy الأقدم استقبال الحسابات دون تحديث. تأخذ المستقبلات المثبّتة الأسبقية. ينسخ ذلك جميع اشتراكات Claude وCodex وGrok؛ أضف أسماء المزودين لتحديدها، كما في `omarchy agent account copy laptop claude`. تطابق أسماء الحسابات ومعرّفات الأوامر المصدر، بما يشمل الحسابات الموجودة بالفعل على الوجهة. تتلقى حسابات الوجهة غير ذات الصلة لاحقة رقمية إذا تعارضت أسماؤها، وتبقى الإعدادات والمهارات والإضافات وسجل المحادثات محلية لكل جهاز.

تُحتفظ ببيانات اعتماد الوجهة الموجودة. الحساب المصدري المسجّل هناك بالفعل تُزامن اسمه دون استبدال بيانات اعتماده؛ تُضاف الحسابات الأخرى بجواره. لاستبدال بيانات الاعتماد المحفوظة للحسابات المطابقة، استخدم `omarchy agent account copy --replace laptop claude` بعد إنهاء جلسات ذلك الحساب على الوجهة. تحصل الوجهة الجديدة أيضًا على حساب المصدر النشط وتفضيلات التبديل الخاصة به؛ تحتفظ الوجهة الراسخة بتفضيلاتها الخاصة.

تنتقل بيانات الاعتماد عبر SSH وتُخزّن في ملفات خاصة على الوجهة، لذا انسخ فقط إلى أجهزة تثق بها. هذا نسخ لمرة واحدة، وليس مزامنة مستمرة. يمكن لجهاز آخر تدوير رموز تحديث Codex، ما يترك تسجيل دخول منسوخًا بحاجة إلى تجديد؛ تبقى تسجيلات الدخول المنفصلة الخيار الأكثر موثوقية للاستخدام المتزامن على أجهزة متعددة. راجع [إرشادات Codex لمصادقة الحساب](https://developers.openai.com/codex/auth/ci-cd-auth).

حساب واحد لكل مزود نشط، وكل جلسة جديدة تبدأ به: `cx` و`cy` و`claude` أو `codex` أو `grok` العادي، وأي شيء يُشغَّل عبر `omarchy agent`، والبرامج النصية أو المحررات التي تجد الواجهة CLI على `PATH`. بدّل بواسطة `omarchy agent account use work` (وعُد بواسطة `omarchy agent account use main`)، أو في اللوحة بالضغط على رقم حساب ثم `Enter` (أو النقر على نجمته). تتبدّل جلسات Claude قيد التشغيل أيضًا، اعتبارًا من رسالتها التالية: كل جلسة Claude تعمل في `~/.claude`، الذي يحتفظ دائمًا بتسجيل دخول الحساب النشط. جلسة Claude بدأت في مجلد حساب خاص بواسطة Omarchy أقدم تحتفظ بذلك التسجيل حتى تنهي، لذا يسمّي التبديل تلك الجلسات وينتهي من تلقاء نفسه بمجرد رحيلها. تبقى جلسات Codex وGrok قيد التشغيل على الحساب الذي بدأت به. يُشارك سجل المحادثات والإعدادات والمهارات والإضافات عبر الحسابات، لذا فإن `claude --continue` في المجلد نفسه يتابع من حيث توقفت على الحساب الجديد.

مع أكثر من حساب واحد، تعرض اللوحة حدود كل حساب جنبًا إلى جنب، مع نجمة مملوءة على قيد الاستخدام. يعلمك Omarchy عندما يتجاوز الحساب النشط 95% من حد، والنقر على الإشعار يبدّل إلى الحساب ذي أكبر هامش متاح. لا يبدّل أبدًا من تلقاء نفسه. غيّر العتبة بواسطة `omarchy agent account threshold 90`. إذا كان كل حساب فوق العتبة، فستسمع عن ذلك مرة واحدة، مع أي حساب يتحرر أولًا. بينما يكون الحساب النشط ضمن 15 نقطة من عتبته (80% في الافتراضي)، تُفحص حدوده كل ثلاث دقائق بدلًا من كل 15.

يعرض `omarchy agent account list` كل حساب وأحدث حدوده، وينسى `omarchy agent account remove work` واحدًا، ويعيد `omarchy agent account rename primary Hey` تسمية واحد (أو انقر على اسم حساب في اللوحة). تعمل هذه الأوامر على حسابات وكيلك الافتراضي؛ للوصول إلى المزود الآخر، سمّه أولًا، كما في `omarchy agent account use codex side`. تسجيل الدخول الذي كان لديك بالفعل في `~/.claude` أو `~/.codex` هو حساب _Main_. يبقى حساب Codex حيث هو؛ ينتظر حساب Claude في مجلد خاص به بينما يكون حساب آخر نشطًا. يمكن لحساب تُرك دون استخدام لأكثر من حوالي ثماني ساعات أن يعرض _Sign-in required_؛ انقر عليه لتسجيل دخول ذلك الحساب مرة أخرى في اللوحة مباشرة، أو بدّل إليه وابدأ جلسة، ما يحدّث تسجيل الدخول من تلقاء نفسه. تصل خوادم MCP التي تضيفها بواسطة `claude mcp add` إلى كل حساب Claude، لأنها كلها تعمل في `~/.claude`؛ بالنسبة لـ Codex وGrok، الخوادم التي كانت لديك عند إضافة حساب تأتي معه إليه، لكن اللاحقة تصل فقط إلى الحساب الذي أضفتها فيه. يحتفظ Claude Desktop بتسجيل دخول خاص به، وأدوات Codex أو Grok المهيأة بمسار مطلق إلى ملف تنفيذي للواجهة CLI لا تتبع التبديل. يأخذ `CLAUDE_CONFIG_DIR` أو `CODEX_HOME` أو `GROK_HOME` الصريح الأسبقية على الحساب المختار.

### تشخيص الأعطال

يراقب Omarchy برنامج systemd-coredump بحثًا عن أعطال العمليات. بعد أن تختار وكيلًا افتراضيًا، أي برنامج لك يفرّغ النواة يجلب إشعار "Process crashed" — انقر عليه، ويُسلّم العطل إلى وكيلك الافتراضي مع مهارة omarchy-diagnose-crash من Omarchy، التي ترشد الوكيل خلال إثبات الحقائق من تفريغ النواة وتقرير ما إذا كان العطل يستحق الإبلاغ عنه في المصدر. يمكنك أيضًا تشغيله يدويًا مقابل أي PID من `coredumpctl list` بواسطة `omarchy agent crash <pid>`.

المراقبة مفعّلة افتراضيًا. أوقفها ضمن _Trigger > Toggle > Crash Capture Off_ (أو بواسطة `omarchy toggle crash-capture`) وتتوقف الإشعارات؛ ما زال `omarchy agent crash <pid>` يعمل يدويًا.

يمكن أيضًا إسكات الأعطال برنامجًا واحدًا في كل مرة، وهذا ما يعرضه التشخيص عليك في النهاية. يوقف `omarchy crash mute hyprland` الإشعارات لذلك البرنامج فقط، ويعيدها `omarchy crash mute hyprland off`، ويسرد `omarchy crash mute` بمفرده ما كتمته. يقبل مسار الملف التنفيذي بسرور كاسمه، لذا فإن `omarchy crash mute /usr/bin/hyprland` يفعل الشيء نفسه. ضع اسمًا يحتوي على مسافة بين علامتي اقتباس، كما في `omarchy crash mute 'Some App'`. كل شيء آخر ما زال يعلم، والبرنامج المكتم ما زال يتعطل — هذا يخفي التذكير، ولا يصلح شيئًا.

### تطبيقات سطح المكتب

تحمل قائمة _Install > AI_ أيضًا بعض تطبيقات الذكاء الاصطناعي الرسومية: Amp Desktop وAntigravity Desktop وتطبيق ChatGPT لسطح المكتب وتطبيق Claude لسطح المكتب (إصدار Linux التجريبي من Anthropic، مع علامات تبويب Chat وCowork وClaude Code) وGrok Bot للدردشة مع نماذج xAI وHerdr Desktop وHermes Desktop وOpenClaw وتطبيق Perplexity لسطح المكتب وT3 Code. Grok Bot هو تطبيق الدردشة لسطح المكتب. وكيل البرمجة هو أمر `grok`.

Hermes Desktop هو ما يجب أن تعرفه، لأن للجهاز Hermes واحد، وهو الخاص بالتطبيق: يُثبَّت Hermes فقط عبر التطبيق أبدًا، وأمر `hermes` الذي يشغّله الوكيل الافتراضي هو الخاص بالتطبيق. اختيار Hermes كوكيل افتراضي يثبّت الشيء نفسه الذي يثبّته إدخال _Install > AI_: الحزمة، وبيئة تشغيل Hermes ضمن `~/.hermes` أعدّها مثبّت Hermes الخاص، والتي تستغرق بضع دقائق في المرة الأولى. تلك البيئة هي Hermes الواحدة التي يستخدمها أمر `hermes` الطرفي والوكيل الافتراضي والتطبيق جميعًا، وتحدّث نفسها بواسطة `hermes update` بدلًا من انتظار إصدار Omarchy. يمنح تثبيته أيضًا Hermes سمة Omarchy كجلد باسم `omarchy`، تتبعه كل أسطح Hermes أثناء تبديلك السمات؛ اختر آخر ضمن إعدادات مظهر Hermes أو بواسطة `/skin` إذا كنت تفضّل ألا يفعل ذلك، ويترك Omarchy ذلك الخيار وشأنه. إزالة التطبيق ضمن _Remove > AI_ تغلق Hermes أولًا، بما يشمل البوابة، وتأخذ تلك البيئة معها، وتحتفظ بدردشاتك وذكرياتك والمهارات التي كتبتها Hermes لنفسها ما لم تخبرها بخلاف ذلك: تسأل، افتراضيًا لا، ما إذا كان يجب أن تذهب تلك البيانات وإعدادات اتصالك أيضًا.

تجربة OpenClaw لسطح المكتب هي واجهة Control UI الخاصة به، التي تفتح كتطبيق ويب مدعوم ببوابته المحلية الخاصة. يعيش OpenClaw في `~/.openclaw` ويحدّث نفسه: استخدم زر "Update Gateway" في Control UI أو شغّل `openclaw update`، وتعاد تشغيل البوابة على الإصدار الجديد. يختار Omarchy فقط الإصدار الذي يبدأ منه التثبيت الجديد. يمكن أن يكون OpenClaw أيضًا وكيلك الافتراضي: اختياره ضمن _Agent > Harness_ يُعدّ النسخة نفسها في `~/.openclaw`، ويفتح الوكيل واجهة OpenClaw الطرفية المتصلة ببوابته. إزالة OpenClaw ضمن _Remove > AI_ تأخذ خدمة البوابة والتطبيق معها ثم تسأل ما إذا كان يجب أن يذهب `~/.openclaw` أيضًا، لأن ذلك يحتفظ بدردشاتك وبيانات اعتمادك جنبًا إلى OpenClaw نفسه وبيئات تشغيل الإضافات التي ينزّلها؛ الافتراضي يحتفظ به، وتثبيت OpenClaw مرة أخرى يلتقطه من جديد.

Herdr Desktop هو تطبيق Herdr لسطح المكتب من [Herdr](https://herdr.dev): مساحات وعلامات تبويب وأجزاء من الطرفيات ووكلاء البرمجة تبقى قيد التشغيل في نواته عندما تغلق النافذة. يأتي من مثبّت Herdr الخاص بدلًا من حزمة، لذا يعيش في `~/.local/share/herdr-app`، ويجلب نواته في `~/.local/bin/herdr-core` عندما لا يكون لديك واحد بعد، ويحدّث نفسه وكليهما. يجلس إلى جانب أمر `herdr` الذي يشحنه Omarchy على `Super + Ctrl + Return` بدلًا من استبداله، ويحصل على مفاتيح ذلك الأمر المباشرة: `Alt + Return` و`Alt + Shift + Return` تقسمان جزءًا لأسفل أو يمينًا، و`Alt + Escape` تغلقه، و`Ctrl + Alt + Arrow` يتنقل بين الأجزاء، و`Alt + 1..9` و`Alt + Left/Right` تختاران علامة تبويب، و`Alt + Up/Down` يتنقلان بين المساحات. `Ctrl + 1..9` يختار مساحة و`Alt + Shift + Up/Down` يتنقل عبر الوكلاء. تبقى مفاتيح بادئة `Ctrl + Space` للطرفية فقط، لأن التطبيق لا يستطيع الاحتفاظ بمفتاح Ctrl عادي لتسلسل. يكتب Omarchy هذه إلى `~/.config/herdr-app/keys.json`، ويعيدها `omarchy-refresh-herdr-app`. يختار تثبيته سمة Omarchy لـ Herdr، التي تتبع سمة Omarchy الخاصة بك من ذلك الحين. يحتفظ Herdr بسمة واحدة لوضع الإضاءة وواحدة للوضع الداكن، لذا بعد التبديل بين سمة Omarchy داكنة وخفيفة، اختر Omarchy في منتقي سمات Herdr مرة أخرى للوضع الآخر.

يعمل T3 Code من إصدار AppImage الرسمي في `~/.local/share/t3code` بدلًا من حزمة، لذا يحدّث نفسه. يسأل تثبيته ما إذا كنت تريد البدء على قناة Stable أو Nightly؛ بدّل لاحقًا في إعدادات T3 Code. تعيش سلاسل محادثاتك وإعداداتك في `~/.t3`، وإزالة T3 Code ضمن _Remove > AI_ تأخذها معها.

### النماذج المحلية

شغّل نموذجًا مفتوحًا على جهازك الخاص لوكلاء برمجتك. تبقى موجّهاتك وبرمجتك على الجهاز؛ لا شيء يُرسل إلى النموذج يغادره. ابدأ بـ:

```bash
omarchy models use best text
```

ذلك يُعدّ أفضل نموذج نصي لهذا الجهاز، وهو النوع الذي يستخدمه وكلاؤك. لنماذج الصور والفيديو والموسيقى أفضلها الخاص: `omarchy models use best image` أو `video` أو `music`. شغّل `omarchy models use best` لعرض اختيار كل نوع لهذا الجهاز.

أو افتح لوحة النماذج المحلية من أيقونة البريق في الشريط العلوي، بجوار أيقونة الوكلاء، أو بواسطة Super + Ctrl + Alt + X، واختر +. تظهر الأيقونة عندما يناسب نموذج هذا الجهاز. Podman، الذي يشغّل النماذج، يأتي مع Omarchy، كما تأتي مجموعة أدوات حاويات NVIDIA على جهاز NVIDIA، ما يمنحها وحدة GPU؛ إذا كان أي منهما مفقودًا، فإن الإعداد الأول يثبّته. ثم يختار Omarchy النموذج الموصى به لهذا الجهاز وينزّله ويبدأ به. توقّع تنزيلًا بعشرات GB ومعظم ذاكرة الجهاز قيد الاستخدام أثناء تشغيل النموذج: يستخدم Flash Next حوالي 100 GiB مع سياقه الكامل 256K. إذا كانت نماذج أخرى تحتفظ بالذاكرة التي يحتاجها، يُعدّ متوقفًا، جاهزًا للبدء بمجرد أن توقف واحدًا. يتوقف النموذج عند تسجيل الخروج؛ أوقفه بنفسك عندما تحتاج الذاكرة لشيء آخر.

يعرض `omarchy models list` الخيارات ويشرح سبب عدم ملاءمة بعضها. لإعداد آخر، شغّل `omarchy models use <recipe>`. اليوم، يتوفر `qwen3.8-flash-next-gufo` و`qwen3.8-27b-gufo` لأجهزة Strix Halo بسعة 128 GB؛ يأخذ نموذج 27B حوالي 40 GiB، لذا يترك مساحة لأعمال أخرى. على كمبيوتر محمول بسعة 64 GB مع Intel's Arc B390، يعمل `qwen3.6-35b-a3b-llamacpp` في حوالي 30 GiB. تصل الوصفات والتوصيات الجديدة مع `omarchy update`، عبر الحزمة.

يحصل كل نموذج تُعدّه على سطره الخاص في لوحة النماذج المحلية: تشغيل لبدئه، إيقاف مؤقت لإيقافه وتحرير ذاكرته، وزر الطرفية لفتح وكيلك عليه. عبر الأعلى، يعرض شريط كيف تُقسّم ذاكرة الجهاز بين Omarchy نفسه (النظام وتطبيقاتك)، وكل نموذج قيد التشغيل، وما هو حر. وجّه إلى نموذج متوقف ويعرض الشريط ما إذا كان يناسب، أو مقدار نقصه. يمكن لعدة منها العمل في وقت واحد عندما تناسب في الذاكرة معًا؛ إذا لم يناسب واحد، يقول Omarchy أي نموذج قيد التشغيل توقف. اسحب السطور من شعارها لإعادة ترتيبها، واضغط Delete على سطر محدد لإزالة نموذج وتنزيله.

يحصل كل نموذج برمجة تُعدّه أيضًا على إدخاله الخاص في مشغّل التطبيقات، تحت اسم النموذج ومع شعار صانعه، بالطريقة التي يضيف بها تسجيل الدخول إلى Claude أو Codex أو Grok واحدًا. يفتح وكيلك على ذلك النموذج، ويبدأ النموذج أولًا إذا لم يكن قيد التشغيل: تعرض الطرفية تحميله وتسلّم إلى الوكيل بمجرد أن يصبح جاهزًا. إزالة نموذج تزيل إدخاله.

ليس كل نموذج للبرمجة. تفتح نماذج الصور والفيديو والموسيقى في Fantasi بدلًا من ذلك، تطبيق Omarchy لصنع الصور والفيديو والموسيقى بنموذج يعمل على هذا الجهاز، تُختار هناك أو من سطرها في لوحة النماذج المحلية.

يبقى النموذج قيد التشغيل تمامًا كما أُعدّ، لذا لا يعيد تحديث Omarchy أبدًا تشغيل واحد تحت وكلائك. عندما يكون لدى Omarchy بيئة تشغيل أحدث أو أوزان أحدث لنموذج أعددته، يعرض سطره زر تحديث: اضغطه ويُعدّ النموذج مرة أخرى في الخلفية، وينزّل فقط ما تغيّر، ويعيد التشغيل على الإصدار الجديد. النموذج الذي كان متوقفًا يبقى متوقفًا. يفعل `omarchy models update` الشيء نفسه لكل نموذج من الطرفية.

من سطر الأوامر، يفعل `omarchy models start <recipe>` و`omarchy models stop <recipe>` الشيء نفسه، ويعرض `omarchy models status` كل نموذج، ويفتح `omarchy agent --local-model <recipe>` ذلك النموذج في pi، مهما كان وكيلك الافتراضي. لجعل نموذجك المحلي ما يفتحه مفتاح وكيل الاختصار ووحدة تحكم Quake و_Make something_، شغّل `omarchy default agent local` أو اختر _Local model_ ضمن _Agent > Harness_. يسرد pi أيضًا كل نموذج أعددته، وتلك الموجودة على أجهزة قرنتها، في منتقي نموذجه الخاص، بحيث يصل إليها `pi` العادي أيضًا. يمكن لأي عميل متوافق مع OpenAI الاتصال أيضًا: يعرض `status` عنوان كل نموذج (الأول هو `http://127.0.0.1:11435/v1`)، اسم الوصفة هو النموذج، والمفتاح في `~/.config/omarchy/agent-local/key`.

يحذف `omarchy models remove <recipe>` نموذجًا والتنزيلات التي لا يستخدمها أي نموذج آخر.

تُوسم بيئات تشغيل الجهات الخارجية بناشرها. يشغّل Omarchy كل نموذج دون وصول إلى الشبكة.

### نماذج LLM المحلية

يوصي Omarchy بطريقتين لتشغيل نماذج LLM محلية: LM Studio وOllama. يوفّر LM Studio واجهة GUI للعثور على نماذج مفتوحة الأوزان وتثبيتها وتشغيلها. إنها طريقة رائعة للانطلاق بسهولة. تقدّم Ollama واجهة CLI لفعل ذلك بالمثل. لكن إذا كنت جديدًا على النماذج المحلية، سأبدأ بـ LM Studio. يمكنك تثبيت أي منهما ضمن _Install > AI_ في قائمة Omarchy.

### مهارات Omarchy

تساعد مهارات الوكيل الذكاء الاصطناعي على استخدام أدوات محددة بطريقة محددة، ويشحن Omarchy سبعًا منها. تغطي مهارة omarchy تخصيص النظام، مثل تعديل إعداد Hyprland الخاص بك أو ضبط الشريط. تغطي omarchy-make-theme وomarchy-make-plugin وomarchy-make-app وomarchy-make-game صنع شيء جديد، وتغطي omarchy-contribute الإبلاغ عن خطأ أو إرسال إصلاح إلى المصدر، وتعمل omarchy-diagnose-crash عبر تفريغ نواة عطل. تُربط رمزيًا إلى مجلدات مهارات Claude Code ‏(`~/.claude/skills`) وCodex ‏(`~/.codex/skills`) وPi ‏(`~/.pi/agent/skills`) وAntigravity ‏(`~/.gemini/config/skills`) وHermes ‏(`~/.hermes/skills` وكل `~/.hermes/profiles/*/skills`)، وموقع `~/.agents/skills` العام، بحيث تلتقطها معظم أطر العمل تلقائيًا. مجلد مهارة خاص بك بنفس الاسم يأخذ الأسبقية.

لكن يجب أن تعامل هذه المهارات كتجريبية. ستستخدمها نماذج مختلفة بتأثيرات مختلفة. من الأفضل العمل في وضع التخطيط أولًا، بحيث تكون لديك فكرة عما يرغب الوكيل في تغييره. ثم كن مستعدًا للتراجع عن التغييرات أو حتى استدعاء `omarchy reinstall configs`، إذا أحدث الوكيل فوضى في كل شيء.
