# الذكاء الاصطناعي

تتضمن Omarchy مشغّلات لوكلاء البرمجة أدناه دون أن تختار لك واحدًا افتراضيًا. شغّل أمرًا لتثبيت واجهة سطر الأوامر الخاصة به عند أول استخدام، ثم أكمل المصادقة عند مطالبتك. Hermes وOpenClaw هما الاستثناء: لا يُثبَّت أي شيء لهما عبر mise، واختيار أيٍّ منهما يُعدّ نسخته الخاصة ذاتية التحديث، كما يشرح قسم _تطبيقات سطح المكتب_ أدناه.

### تثبيت الوكلاء وتحديثهم

باستثناء Hermes وOpenClaw، يستخدم هؤلاء الوكلاء التثبيت الكسول عبر mise: أول تشغيل يثبّت واجهة سطر الأوامر، والتشغيلات اللاحقة تعيد استخدامها. كما يتحقق mise من وجود إصدار جديد لوكيل مثبّت مرة واحدة على الأكثر كل أربع ساعات، قبل بدئه مباشرة أو في الخلفية عند موجه shell. إذا فشل ذلك التحديث أو كنت غير متصل، يعمل الإصدار المثبّت. يحدّث `omarchy update` الوكلاء المثبّتين مع بقية Omarchy، ويحدّث `mup` الأدوات التي يديرها mise فقط.

لا يحدّث محدّث الوكيل الخاص، مثل `claude update` أو `codex update` أو زر تحديث في تطبيق، التثبيت الذي يديره mise. يفشل `codex update`، وقد يبلّغ `claude update` عن النجاح بينما يثبّت نسخة منفصلة لا يتتبعها mise. إذا كنت تفضّل استخدام المثبّت والمحدّث الأصليين لوكيل ما، أضفه إلى `disable_tools`؛ راجع [أدوات واجهة سطر الأوامر المثبتة مسبقًا](18-development-tools.md#preinstalled-cli-tools).

لتثبيت كل الأدوات الكسولة المهيأة قبل أن تحتاجها، شغّل `mise install --include-lazy`. يشمل هذا أدوات واجهة سطر الأوامر الافتراضية الأخرى في Omarchy بالإضافة إلى الوكلاء. راجع [أدوات واجهة سطر الأوامر المثبتة مسبقًا](18-development-tools.md#preinstalled-cli-tools) لتثبيت أداة واحدة أو استخدام تثبيتك الخاص.

يُثبّت `grok` عبر حزمة `grok` الرسمية من mise، بالطريقة نفسها مثل `claude` و`codex`. شغّل `grok`، أو ضع نجمة عليه في لوحة الوكلاء. تجنّب مثبت `curl | bash` على x.ai. فذلك المسار يضع نسخة ثانية في `~/.grok/bin`، ويقدّمها في `PATH`، ويستبدل غلاف Omarchy.

يفتح `dsh` واجهة متصفحه على `127.0.0.1:3080`، مع دليل التشغيل كمساحة عمل افتراضية له. لا تقبل واجهة متصفحه موجه بدء، لذا فإن `omarchy agent prompt` يفتحه مع الموجه في حافظتك للصقه. تشغّله Omarchy مع إعداد أذونات DeepSeek المسبق بدون موافقة. يرفع DeepSeek Harness سجلات الجلسة إلى DeepSeek عندما تستخدم واجهة برمجة نماذجه الرسمية؛ عطّل ذلك ضمن _Settings > General > Upload Session Log_ في واجهة متصفحه. كما تُرفع الملاحظات التي ترسلها إليه مع الجلسة أيضًا، ما لم تشغّله مع `DSH_TELEMETRY_MODE=DISABLED`.

### الوكيل الافتراضي

اختر وكيلك الافتراضي بالنجمة بجانب وكيل في لوحة الوكلاء، وهي مملوءة على الافتراضي، أو باستخدام `omarchy default agent <name>`، الذي يقبل أيضًا أي منظومة تشغيل غير موجودة في سطر هناك. إذا لم يكن الوكيل مثبّتًا بعد، فإن اختياره يثبّته أولًا، ويحصل أيضًا على مشغّل خاص به في مشغّل التطبيقات، بجانب Agent. تدعوك Omarchy جديدة إلى إعداد واحد مع إشعار لمرة واحدة، يفتح لوحة الوكلاء.

يحاول اختيار Claude أيضًا إعداد إضافة متصفحه لـ Chromium وChrome وBrave وBrave Origin وEdge. ينطبق إعداد الإضافة على كل المستخدمين وقد يطلب كلمة مرور النظام؛ إلغاء تثبيت الإضافة أو فشله لا يزال يختار Claude ويشغّله. أعد تشغيل متصفحك، وفعّل الإضافة إذا طُلب منك، وسجّل الدخول إلى Claude لإنهاء توصيلها. شغّل `/chrome` في Claude للتحقق من الاتصال. لا يدعم Firefox وZen هذه الإضافة. إذا كان Claude وكيلك الافتراضي بالفعل قبل إضافة هذا الإعداد، اختره مرة أخرى لتثبيت الإضافة.

بمجرد الاختيار، يشغّل `Super + Shift + Ctrl + A` الوكيل الافتراضي في نافذة طرفية مخصصة (أو يعرض المنتقي إذا لم تختر بعد). يمكنك أيضًا تشغيله مباشرة في مهمة باستخدام `omarchy agent prompt "Review this project"`. لا يقبل Freebuff وDeepSeek Harness موجه بدء، لذا يفتحان مع الموجه في حافظتك للصقه بدلًا من ذلك. يعمل الوكلاء المشغّلون بهذه الطريقة دون مراقبة في أوضاعهم الخاصة بعدم التوقف للسؤال، لذا كن مستعدًا لقيامهم بأشياء فعلًا! لا يملك MiniMax Code مثل هذا الوضع لجلساته التفاعلية، لذا يطلب الأذونات كالمعتاد. وبما أن الوكلاء يرفضون تذكّر الثقة لدليلك الرئيسي، تبدأ عمليات التشغيل من `$HOME` في `~/Work` بدلًا من ذلك.

توجد اختصارات طرفية أيضًا: يشغّل `a` الوكيل الافتراضي داخل الطرفية الحالية، بينما يشغّل `c` و`cx` و`cy` OpenCode وClaude Code وCodex مباشرة (مرة أخرى في أوضاع الموافقة التلقائية). تتزامن تغييرات السمة مع الوكلاء أيضًا: يتبع Claude Code وPi وOpenCode وHermes (بمجرد أن تثبّته Omarchy) جميعها عند تبديل سمة Omarchy.

### تعليمات وكيلك

تذهب القواعد الشخصية لكل وكيل في `~/.agents/AGENTS.md`، بجانب المهارات المشتركة في `~/.agents/skills`. افتحه بأيقونة المستند بجانب + في لوحة الوكلاء، أو `omarchy agent instructions --edit`، الذي يربطه أيضًا بكل منظومة تشغيل تحتفظ بملفها العالمي الخاص: `~/.claude/CLAUDE.md` و`~/.codex/AGENTS.md` و`~/.pi/agent/AGENTS.md` و`~/.config/opencode/AGENTS.md` و`~/.copilot/copilot-instructions.md` لـ Copilot، وهكذا. يقرأ Crush وAmp رابط `~/.config/AGENTS.md`، بينما يقرأ omp وKimi وDeepSeek Harness `~/.agents/AGENTS.md` مباشرة. اختيار وكيل افتراضي يربطه أيضًا. يصبح ملف تعليمات كان لديك بالفعل هو المشترك إذا لم يكن يوجد واحد بعد؛ وإلا يُحتفظ به بجانب الرابط كـ `.bak`. شغّل `omarchy agent instructions` لإعادة الربط بعد تثبيت وكيل آخر.

### لوحة الوكلاء

تضم الشريط العلوي أيقونة وكلاء. قبل إعداد وكيل، تقدم لوحته ثلاث طرق للبدء: تسجيل الدخول إلى اشتراك Claude أو Codex أو Grok أو Gemini أو Muse أو Cursor أو Copilot، أو ضمن More خطة برمجة OpenCode Go أو MiniMax أو Synthetic أو Z.ai؛ الدفع حسب الاستخدام مع Fireworks أو OpenCode Zen and Go أو OpenRouter، أو ضمن More مع DeepSeek أو أي مزود آخر يسجّل OpenCode الدخول إليه، وكلها تعمل في OpenCode؛ أو تشغيل أفضل نموذج لجهازك، عندما يناسبه واحد. الأول الذي تنهيه يصبح وكيلك الافتراضي، ويقدم + في اللوحة، أو _Agent > Add_ في قائمة Omarchy، الطرق الثلاث نفسها لاحقًا. بعد ذلك، تضع اللوحة كل اشتراك في صفحة واحدة: كل وكيل وحساب مع خطته، وعداد لكل من حد جلسته البالغ 5 ساعات وحدوده الأسبوعية مع الوقت حتى إعادة تعيينه (مرّر للاطلاع على النسبة المئوية الدقيقة)، أو الرصيد المدفوع مسبقًا المتبقي، تحت سطر يدور عبر ما استخدمته عبرها جميعًا، مثل الرموز هذا الأسبوع ونموذجك الأكثر استخدامًا. ضمن _اصنع شيئًا رائعًا_ يقدم موجهات بداية لسمة أو إضافة أو تطبيق أو لعبة جديدة تسلّم المهمة إلى وكيلك الافتراضي. تُبنى التطبيقات بالطريقة التي بُنيت بها تطبيقات Omarchy الخاصة Hype وMonologue وOmacut، بلغة C++ وQt Quick، باتباع مهارة وكيل omarchy-make-app، ويأتي المترجم وقطع Qt التي تحتاجها مثبّتة. الألعاب هي صفحة three.js واحدة في `~/Games/vibes`، باتباع مهارة وكيل omarchy-make-game، وكلها تفتح من مشغّل Game Vibes واحد في السمة الحالية؛ تحمّل three.js من الويب، لذا تحتاج اتصالًا للبدء. يُغطى Claude Code وCodex وGrok وKimi وCursor وبدل Grok Bot الخاص به وGitHub Copilot وMuse وGemini (عبر Antigravity) وDevin جاهزة مع حدودها، وKimchi مع خطته واعتماداته المدفوعة مسبقًا وميزانيات إنفاقه، ويعرض Hermes وMistral Vibe وQwen Code جلساتهم ورموزهم بمجرد استخدامهم. تظهر أيضًا خطط المزودين ومفاتيحهم التي تستخدمها عبر pi أو omp أو opencode: OpenCode Zen and Go وخطة Z.ai GLM Coding Plan وOllama Cloud وخطة MiniMax Token Plan وSynthetic مع حدودها؛ OpenRouter وDeepSeek مع أرصدتهما المدفوعة مسبقًا؛ Fireworks مع إنفاقه على مدى آخر 30 يومًا. تُحتسب الرموز من النماذج التي تشغّلها على أجهزتك الخاصة ضمن الإجماليات أيضًا؛ للنماذج نفسها لوحة خاصة بها، موصوفة ضمن [النماذج المحلية](#local-models). يُحتسب كل وكيل مرة واحدة، تحت من يفوتره، مهما كان عدد منظومات التشغيل التي تقوده عبرها.

انقر بالزر الأيسر على أيقونة الشريط أو اضغط `Super + Ctrl + X` للوحة، وانقر بالزر الأيمن لتشغيل وكيلك الافتراضي، وانقر بالزر الأوسط للتحديث. تُعاد توليد سجلات الاستخدام وراءها كل 15 دقيقة بواسطة `omarchy agent usage update`، ويمكن للوحة حتى دمج الاستخدام من أجهزتك الأخرى عبر مجلد متزامن. راجع README ضمن `$OMARCHY_PATH/shell/plugins/agents/` للإعدادات الكاملة.

### عدة اشتراكات

إذا دفعت لأكثر من خطة Claude أو Codex أو Grok واحدة — خطة Max شخصية وواحدة للعمل، مثلًا — يمكن لـ Omarchy إبقاءها جميعًا مسجلة الدخول والتنقل بينها. أضف اشتراكًا باستخدام + في لوحة الوكلاء، الذي يرشدك خلال ذلك هناك مباشرة، أو باستخدام `omarchy agent account add claude Work` (أو `codex`، أو `grok`). يسجّل + والأمر نفسه الدخول إلى Gemini (`gemini`) وOpenCode (`opencode`)، ويحفظان مفتاح واجهة برمجة Fireworks (`fireworks`) أو OpenRouter (`openrouter`) في OpenCode؛ كما يسجّل الأمر الدخول إلى Copilot (`copilot`) وCursor (`cursor`) وMuse (`muse`). تحتفظ تلك بتسجيل دخول واحد لكل منها. يثبّت واجهة سطر الأوامر إذا كانت مفقودة. يسجّل الحساب الأول لمزود الدخول عبر متصفحك العادي، حيث تبحث واجهة سطر الأوامر دائمًا. كل حساب بعد ذلك يسجّل الدخول عبر نافذة خاصة، حتى لا يُلتقط الحساب الذي سجّل متصفحك الدخول إليه بالفعل عن طريق الخطأ؛ سجّل الدخول هناك كالحساب الذي تضيفه، وأغلق أي نافذة خاصة فتحتها بالفعل أولًا. لا تسجّل الخروج أبدًا من واجهة سطر الأوامر للقيام بذلك: تسجيل الخروج يلغي تسجيل الدخول المحفوظ، وسيتعين إضافة ذلك الحساب مرة أخرى.

لنسخ تسجيلات دخول اشتراكك إلى جهاز Omarchy آخر عبر SSH، شغّل `omarchy agent account copy user@laptop`. يوفّر المرسل مستقبلًا مؤقتًا عندما لا يكون لدى الوجهة واحد مثبّت، لذا يمكن لأجهزة Omarchy الأقدم استلام الحسابات دون تحديث. تأخذ المستقبلات المثبّتة الأسبقية. ينسخ هذا كل اشتراكات Claude وCodex وGrok؛ أضف أسماء المزودين لتحديدها، كما في `omarchy agent account copy laptop claude`. تطابق أسماء الحسابات ومعرّفات الأوامر المصدر، بما في ذلك الحسابات الموجودة بالفعل على الوجهة. تتلقى حسابات الوجهة غير ذات الصلة لاحقة رقمية إذا تعارضت أسماؤها، وتبقى الإعدادات والمهارات والإضافات وسجل المحادثات محلية لكل جهاز.

تُحتفظ ببيانات اعتماد الوجهة الموجودة. حساب مصدر مسجل الدخول هناك بالفعل تُزامن اسمه دون استبدال بيانات اعتماده؛ تُضاف حسابات أخرى بجانبه. لاستبدال بيانات الاعتماد المحفوظة للحسابات المطابقة، استخدم `omarchy agent account copy --replace laptop claude` بعد إنهاء جلسات ذلك الحساب على الوجهة. تحصل وجهة جديدة أيضًا على الحساب النشط وتفضيلات التبديل للمصدر؛ تحتفظ وجهة قائمة بتفضيلاتها الخاصة.

تنتقل بيانات الاعتماد عبر SSH وتُخزّن في ملفات خاصة على الوجهة، لذا انسخ فقط إلى أجهزة تثق بها. هذه نسخة لمرة واحدة، وليست مزامنة مستمرة. يمكن لجهاز آخر تدوير رموز تحديث Codex، ما يترك تسجيل دخول منسوخًا بحاجة إلى تجديد؛ تبقى تسجيلات الدخول المنفصلة الخيار الأكثر موثوقية للاستخدام المتزامن على عدة أجهزة. راجع [إرشادات مصادقة حساب Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

يكون حساب واحد لكل مزود نشطًا، وتبدأ كل جلسة جديدة به: `cx` و`cy` و`claude` أو `codex` أو `grok` عادي، وأي شيء يُشغّل عبر `omarchy agent`، والبرامج النصية أو المحررات التي تجد واجهة سطر الأوامر على `PATH`. بدّل باستخدام `omarchy agent account use work` (وعُد باستخدام `omarchy agent account use main`)، أو في اللوحة بالضغط على رقم حساب ثم `Enter` (أو النقر على نجمته). تتبدّل جلسات Claude قيد التشغيل أيضًا، من رسالتها التالية: كل جلسة Claude تعمل في `~/.claude`، الذي يحتفظ دائمًا بتسجيل دخول الحساب النشط. جلسة Claude بدأت في مجلد حساب خاص بها بواسطة Omarchy أقدم تحتفظ بذلك التسجيل حتى تنتهي، لذا يسمّي التبديل تلك الجلسات وينتهي من تلقاء نفسه بمجرد اختفائها. تبقى جلسات Codex وGrok قيد التشغيل على الحساب الذي بدأت به. يُشارك سجل المحادثات والإعدادات والمهارات والإضافات عبر الحسابات، لذا فإن `claude --continue` في المجلد نفسه يكمل من حيث توقفت على الحساب الجديد.

مع أكثر من حساب واحد، تعرض اللوحة حدود كل حساب جنبًا إلى جنب، مع نجمة مملوءة على المستخدم. تنبّهك Omarchy عندما يتجاوز الحساب النشط 95% من حد، والنقر على الإشعار يبدّل إلى الحساب ذي أكبر هامش. لا يبدّل أبدًا من تلقاء نفسه. غيّر العتبة باستخدام `omarchy agent account threshold 90`. إذا كان كل حساب فوق العتبة، ستسمع عن ذلك مرة واحدة، مع أي حساب يتحرر أولًا. بينما يكون حساب نشط ضمن 15 نقطة من عتبته (80% عند الافتراضي)، تُفحص حدوده كل ثلاث دقائق بدلًا من كل 15.

يعرض `omarchy agent account list` كل حساب وحدوده الأخيرة، وينسى `omarchy agent account remove work` واحدًا، ويعيد `omarchy agent account rename primary Hey` تسمية واحد (أو انقر على اسم حساب في اللوحة). تعمل هذه الأوامر على حسابات وكيلك الافتراضي؛ للوصول إلى المزود الآخر، سمّه أولًا، كما في `omarchy agent account use codex side`. تسجيل الدخول الذي كان لديك بالفعل في `~/.claude` أو `~/.codex` هو حساب _Main_. يبقى حساب Codex حيث هو؛ ينتظر حساب Claude في مجلد خاص به بينما يكون حساب آخر نشطًا. حساب تُرك غير مستخدم لأكثر من حوالي ثماني ساعات يمكن أن يعرض _Sign-in required_؛ انقر عليه لتسجيل دخول ذلك الحساب مرة أخرى مباشرة في اللوحة، أو بدّل إليه وابدأ جلسة، ما يجدد تسجيل الدخول من تلقاء نفسه. تصل خوادم MCP التي تضيفها باستخدام `claude mcp add` إلى كل حساب Claude، بما أنها تعمل جميعًا في `~/.claude`؛ بالنسبة إلى Codex وGrok، تأتي الخوادم التي كانت لديك عند إضافة حساب معه، لكن اللاحقة تصل فقط إلى الحساب الذي أضفتها فيه. يحتفظ Claude Desktop بتسجيل دخول خاص به، وأدوات Codex أو Grok المهيأة بمسار مطلق إلى ثنائي واجهة سطر أوامر لا تتبع التبديل. يأخذ `CLAUDE_CONFIG_DIR` أو `CODEX_HOME` أو `GROK_HOME` صريح الأسبقية على الحساب المختار.

### تشخيص التعطلات

تراقب Omarchy systemd-coredump لتعطلات العمليات. بمجرد اختيار وكيل افتراضي، يجلب أي برنامج لك يفرّغ النواة إشعار «تعطّلت عملية» — انقر عليه، ويُسلّم التعطل إلى وكيلك الافتراضي مع مهارة omarchy-diagnose-crash من Omarchy، التي ترشد الوكيل عبر إثبات الوقائع من تفريغ النواة وتقرير ما إذا كان التعطل يستحق الإبلاغ عنه في المنبع. يمكنك أيضًا تشغيله يدويًا مقابل أي PID من `coredumpctl list` باستخدام `omarchy agent crash <pid>`.

المراقبة مفعّلة افتراضيًا. عطّلها ضمن _Trigger > Toggle > Crash Capture Off_ (أو باستخدام `omarchy toggle crash-capture`) وتتوقف الإشعارات؛ لا يزال `omarchy agent crash <pid>` يعمل يدويًا.

يمكن أيضًا إسكات التعطلات برنامجًا واحدًا في كل مرة، وهو ما يقدمه لك التشخيص في النهاية. يوقف `omarchy crash mute hyprland` الإشعارات لذلك البرنامج فقط، ويعيدها `omarchy crash mute hyprland off`، ويعرض `omarchy crash mute` وحده ما كتمته. يقبل مسار الثنائي بسعادة مثل اسمه، لذا فإن `omarchy crash mute /usr/bin/hyprland` يفعل الشيء نفسه. ضع اسمًا يحتوي مسافة بين علامتي اقتباس، كما في `omarchy crash mute 'Some App'`. يستمر كل شيء آخر في الإشعار، ويستمر البرنامج المكتوم في التعطل — هذا يخفي التذكير، ولا يصلح أي شيء.

### تطبيقات سطح المكتب

تحمل قائمة _Install > AI_ أيضًا بعض تطبيقات الذكاء الاصطناعي الرسومية: Amp Desktop وAntigravity Desktop وتطبيق ChatGPT لسطح المكتب وتطبيق Claude لسطح المكتب (إصدار Linux التجريبي من Anthropic، مع علامات تبويب Chat وCowork وClaude Code)، وGrok Bot للدردشة مع نماذج xAI، وHerdr Desktop وHermes Desktop وOpenClaw وتطبيق Perplexity لسطح المكتب وT3 Code. Grok Bot هو تطبيق الدردشة لسطح المكتب. وكيل البرمجة هو أمر `grok`.

Hermes Desktop هو الذي يجب معرفته، لأن الجهاز لديه Hermes واحد، وهو خاص بالتطبيق: يُثبّت Hermes فقط عبر التطبيق أبدًا، وأمر `hermes` الذي يشغّله الوكيل الافتراضي هو خاص بالتطبيق. اختيار Hermes كوكيل افتراضي يثبّت الشيء نفسه الذي يثبّته إدخال _Install > AI_: الحزمة، وبيئة تشغيل Hermes ضمن `~/.hermes` تُعد بواسطة مثبت Hermes الخاص، الذي يستغرق بضع دقائق في المرة الأولى. تلك البيئة هي Hermes الواحد الذي يستخدمه أمر `hermes` الطرفي والوكيل الافتراضي والتطبيق جميعًا، ويحدّث نفسه باستخدام `hermes update` بدلًا من انتظار إصدار Omarchy. يمنح تثبيته أيضًا Hermes سمة Omarchy كجلد باسم `omarchy`، الذي تتبعه كل أسطح Hermes أثناء تبديل السمات؛ اختر آخر ضمن إعدادات Appearance في Hermes أو باستخدام `/skin` إذا كنت تفضّل ألا يفعل، وتترك Omarchy ذلك الاختيار وشأنه. إزالة التطبيق ضمن _Remove > AI_ تغلق Hermes أولًا، بما في ذلك البوابة، وتأخذ تلك البيئة معها، وتحتفظ بدردشاتك وذكرياتك والمهارات التي كتبها Hermes لنفسه ما لم تخبره بخلاف ذلك: يسأل، افتراضيًا بـ لا، ما إذا كان يجب أن تذهب تلك البيانات وإعدادات اتصالك أيضًا.

تجربة OpenClaw لسطح المكتب هي واجهة Control UI الخاصة به، التي تفتح كتطبيق ويب مدعوم ببوابته المحلية الخاصة. يعيش OpenClaw في `~/.openclaw` ويحدّث نفسه: استخدم زر «Update Gateway» في Control UI أو شغّل `openclaw update`، وتعيد البوابة التشغيل على الإصدار الجديد. تختار Omarchy فقط الإصدار الذي يبدأ منه تثبيت جديد. يمكن أن يكون OpenClaw أيضًا وكيلك الافتراضي: اختياره ضمن _Agent > Harness_ يُعد تلك النسخة نفسها في `~/.openclaw`، ويفتح الوكيل واجهة OpenClaw الطرفية متصلة ببوابته. إزالة OpenClaw ضمن _Remove > AI_ تأخذ خدمة البوابة والتطبيق معها ثم تسأل ما إذا كان يجب أن يذهب `~/.openclaw` أيضًا، بما أنه يحتفظ بدردشاتك وبيانات اعتمادك بجانب OpenClaw نفسه وبيئات تشغيل الإضافات التي ينزّلها؛ الافتراضي يحتفظ به، وتثبيت OpenClaw مرة أخرى يلتقطه من جديد.

Herdr Desktop هو تطبيق سطح مكتب [Herdr](https://herdr.dev): مساحات وعلامات تبويب وأجزاء من الطرفيات ووكلاء برمجة تستمر في العمل في نواته عند إغلاق النافذة. يأتي من مثبت Herdr الخاص بدلًا من حزمة، لذا يعيش في `~/.local/share/herdr-app`، ويجلب نواته معه في `~/.local/bin/herdr-core` عندما لا يكون لديك واحد بعد، ويحدّث نفسه وكليهما. يجلس بجانب أمر `herdr` الذي تشحنه Omarchy على `Super + Ctrl + Return` بدلًا من استبداله، ويحصل على مفاتيح ذلك الأمر المباشرة: يقسّم `Alt + Return` و`Alt + Shift + Return` جزءًا لأسفل أو يمينًا، ويغلقه `Alt + Escape`، وينتقل `Ctrl + Alt + Arrow` بين الأجزاء، ويختار `Alt + 1..9` و`Alt + Left/Right` علامة تبويب، وينتقل `Alt + Up/Down` بين المساحات. يختار `Ctrl + 1..9` مساحة ويتنقل `Alt + Shift + Up/Down` عبر الوكلاء. تبقى مفاتيح بادئة `Ctrl + Space` للطرفية فقط، بما أن التطبيق لا يمكنه الاحتفاظ بمفتاح Ctrl عادي لتسلسل. تكتب Omarchy هذه إلى `~/.config/herdr-app/keys.json`، ويعيدها `omarchy-refresh-herdr-app`. يختار تثبيته سمة Omarchy في Herdr، التي تتبع سمة Omarchy الخاصة بك من ذلك الحين. يحتفظ Herdr بسمة واحدة للوضع الفاتح وواحدة للداكن، لذا بعد التبديل بين سمة Omarchy داكنة وفاتحة، اختر Omarchy في منتقي سمات Herdr مرة أخرى للوضع الآخر.

يعمل T3 Code من إصدار AppImage الرسمي في `~/.local/share/t3code` بدلًا من حزمة، لذا يحدّث نفسه. يسأل تثبيته ما إذا كان سيبدأ على قناة Stable أو Nightly؛ بدّل لاحقًا في إعدادات T3 Code. تعيش سلاسلك وإعداداتك في `~/.t3`، وإزالة T3 Code ضمن _Remove > AI_ تأخذها معها.

### النماذج المحلية

شغّل نموذجًا مفتوحًا على جهازك الخاص لوكلاء برمجتك. تبقى موجهاتك وشيفرتك على الجهاز؛ لا شيء يُرسل إلى النموذج يغادره. ابدأ باستخدام:

```bash
omarchy models use best text
```

يُعد ذلك أفضل نموذج نصي لهذا الجهاز، النوع الذي يستخدمه وكلاؤك. لنماذج الصور والفيديو والموسيقى أفضل خاص بها: `omarchy models use best image` أو `video` أو `music`. شغّل `omarchy models use best` لرؤية اختيار كل نوع لهذا الجهاز.

أو افتح لوحة النماذج المحلية من أيقونة البريق في الشريط العلوي، بجانب أيقونة الوكلاء، أو باستخدام Super + Ctrl + Alt + X، واختر +. تظهر الأيقونة عندما يناسب نموذج هذا الجهاز. يأتي Podman، الذي يشغّل النماذج، مع Omarchy، وكذلك مجموعة أدوات حاويات NVIDIA على جهاز NVIDIA، التي تمنحها GPU؛ إذا كان أي منهما مفقودًا، يثبّته الإعداد الأول. ثم تختار Omarchy النموذج الموصى به لهذا الجهاز، وتنزّله، وتبدأه. توقّع تنزيلًا بعشرات GB ومعظم ذاكرة الجهاز قيد الاستخدام أثناء عمل النموذج: يستخدم Flash Next حوالي 100 GiB مع سياقه الكامل 256K. إذا احتفظت نماذج أخرى بالذاكرة التي يحتاجها، يُعد متوقفًا، جاهزًا للبدء بمجرد إيقاف واحد. يتوقف النموذج عند تسجيل الخروج؛ أوقفه بنفسك عندما تحتاج الذاكرة لشيء آخر.

يعرض `omarchy models list` الخيارات ويشرح سبب عدم ملاءمة بعضها. لإعداد واحد آخر، شغّل `omarchy models use <recipe>`. اليوم، يتوفر `qwen3.8-flash-next-gufo` و`qwen3.8-27b-gufo` لأجهزة Strix Halo بسعة 128 GB؛ يأخذ 27B حوالي 40 GiB، لذا يترك مساحة لعمل آخر. على كمبيوتر محمول بسعة 64 GB مع Intel's Arc B390، يعمل `qwen3.6-35b-a3b-llamacpp` في حوالي 30 GiB. تصل وصفات وتوصيات جديدة مع `omarchy update`، عبر الحزمة.

يحصل كل نموذج تُعده على سطر خاص به في لوحة النماذج المحلية: تشغيل لبدئه، وإيقاف مؤقت لإيقافه وتحرير ذاكرته، وزر طرفية لفتح وكيلك عليه. عبر الأعلى، يعرض شريط كيف تنقسم ذاكرة الجهاز بين Omarchy نفسها (النظام وتطبيقاتك)، وكل نموذج قيد التشغيل، وما هو حر. أشر إلى نموذج متوقف ويعرض الشريط ما إذا كان يناسب، أو كم ينقصه. يمكن تشغيل عدة في وقت واحد عندما تناسب الذاكرة معًا؛ إذا لم يناسب واحد، تخبرك Omarchy أي نموذج قيد التشغيل توقف. اسحب الأسطر بشعارها لإعادة ترتيبها، واضغط Delete على سطر مختار لإزالة نموذج وتنزيله.

يحصل كل نموذج برمجة تُعده أيضًا على إدخال خاص به في مشغّل التطبيقات، تحت اسم النموذج ومع شعار صانعه، بالطريقة التي يضيف بها تسجيل الدخول إلى Claude أو Codex أو Grok واحدًا. يفتح وكيلك على ذلك النموذج، ويبدأ النموذج أولًا إذا لم يكن قيد التشغيل: تعرض الطرفية تحميله وتسلّم إلى الوكيل بمجرد أن يصبح جاهزًا. إزالة نموذج تزيل إدخاله.

ليست كل النماذج للبرمجة. تفتح نماذج الصور والفيديو والموسيقى في Fantasi بدلًا من ذلك، تطبيق Omarchy لصنع الصور والفيديو والموسيقى مع نموذج يعمل على هذا الجهاز، مختار هناك أو من سطرها في لوحة النماذج المحلية.

يبقى نموذج يعمل تمامًا كما أُعد، لذا لا يعيد تحديث Omarchy أبدًا تشغيل واحد تحت وكلائك. عندما يكون لدى Omarchy بيئة تشغيل أحدث أو أوزان أحدث لنموذج أعددته، يعرض سطره زر تحديث: اضغطه ويُعد النموذج مرة أخرى في الخلفية، مع تنزيل ما تغيّر فقط، ويعيد التشغيل على الإصدار الجديد. نموذج كان متوقفًا يبقى متوقفًا. يفعل `omarchy models update` الشيء نفسه لكل نموذج من طرفية.

من سطر الأوامر، يفعل `omarchy models start <recipe>` و`omarchy models stop <recipe>` الشيء نفسه، ويعرض `omarchy models status` كل نموذج، ويفتح `omarchy agent --local` آخر نموذج بدأته في pi، مهما كان وكيلك الافتراضي. لجعل ذلك النموذج ما يفتحه مفتاح الوكيل السريع ووحدة تحكم Quake و_اصنع شيئًا_، شغّل `omarchy default agent local` أو اختر _Local model_ ضمن _Agent > Harness_. يسرد pi أيضًا كل نموذج أعددته، وتلك على أجهزة قرنت بها، في منتقي نماذجه الخاص، لذا فإن `pi` العادي يصل إليها أيضًا. يمكن لأي عميل متوافق مع OpenAI الاتصال أيضًا: يعرض `status` عنوان كل نموذج (الأول هو `http://127.0.0.1:11435/v1`)، واسم الوصفة هو النموذج، والمفتاح في `~/.config/omarchy/agent-local/key`.

يحذف `omarchy models remove <recipe>` نموذجًا والتنزيلات التي لا يستخدمها أي نموذج آخر.

تُعلّم بيئات تشغيل الجهات الخارجية بناشرها. تشغّل Omarchy كل نموذج بدون وصول إلى الشبكة.

### نماذج LLM المحلية

توصي Omarchy بطريقتين لتشغيل نماذج LLM محلية: LM Studio وOllama. توفر LM Studio واجهة رسومية للعثور على نماذج مفتوحة الأوزان وتثبيتها وتشغيلها. إنها طريقة رائعة للبدء بسهولة. تقدم Ollama واجهة سطر أوامر للقيام بذلك بالمثل. لكن إذا كنت جديدًا على النماذج المحلية، سأبدأ بـ LM Studio. يمكنك تثبيت أي منهما ضمن _Install > AI_ في قائمة Omarchy.

### مهارات Omarchy

تساعد مهارات الوكيل الذكاء الاصطناعي على استخدام أدوات محددة بطريقة محددة، وتشحن Omarchy سبعًا منها. تغطي مهارة omarchy تخصيص النظام، مثل تعديل إعداد Hyprland الخاص بك أو ضبط الشريط. تغطي omarchy-make-theme وomarchy-make-plugin وomarchy-make-app وomarchy-make-game صنع شيء جديد، وتغطي omarchy-contribute الإبلاغ عن خطأ أو إرسال إصلاح إلى المنبع، وتعمل omarchy-diagnose-crash عبر تفريغ نواة تعطل. تُربط رمزيًا إلى أدلة مهارات Claude Code (`~/.claude/skills`) وCodex (`~/.codex/skills`) وPi (`~/.pi/agent/skills`) وAntigravity (`~/.gemini/config/skills`) وHermes (`~/.hermes/skills` وكل `~/.hermes/profiles/*/skills`)، وموقع `~/.agents/skills` العام، لذا تلتقطها معظم منظومات التشغيل تلقائيًا. مجلد مهارة خاص بك بنفس الاسم يأخذ الأسبقية.

لكن يجب أن تعامل هذه المهارات كتجريبية. ستستخدمها نماذج مختلفة بتأثير مختلف. من الأفضل العمل في وضع التخطيط أولًا، حتى تكون لديك فكرة عما يريد الوكيل تغييره. ثم كن مستعدًا للتراجع عن التغييرات أو حتى استدعاء `omarchy reinstall configs`، إذا أحدث الوكيل فوضى في كل شيء.
