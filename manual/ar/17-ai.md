تتضمن Omarchy مشغّلات لوكلاء البرمجة أدناه دون أن تختار لك واحدًا افتراضيًا. شغّل أمرًا لتثبيت واجهة سطر الأوامر الخاصة به عند أول استخدام، ثم أكمل المصادقة عند مطالبتك بذلك. ويُعد Hermes وOpenClaw الاستثناءين: لا يُثبَّت أي شيء لهما عبر mise، واختيار أيٍّ منهما يُعِدّ نسخته الخاصة ذاتية التحديث، كما يشرح قسم _تطبيقات سطح المكتب_ أدناه.

### تثبيت الوكلاء وتحديثهم

باستثناء Hermes وOpenClaw، يستخدم هؤلاء الوكلاء التثبيت الكسول الخاص بـ mise: يثبّت الإطلاق الأول واجهة سطر الأوامر، وتعيد الإطلاقات اللاحقة استخدامها. كما يتحقق mise من وجود إصدار جديد لوكيل مثبّت مرة واحدة على الأكثر كل أربع ساعات، قبل بدء تشغيله مباشرة أو في الخلفية عند موجه shell. إذا فشل ذلك التحديث أو كنت غير متصل بالإنترنت، يعمل الإصدار المثبّت. يحدّث الأمر `omarchy update` الوكلاء المثبّتين مع بقية Omarchy، ويحدّث الأمر `mup` الأدوات التي يديرها mise فقط.

لا يحدّث برنامج التحديث الخاص بالوكيل نفسه، مثل `claude update` أو `codex update` أو زر تحديث في تطبيق، التثبيت الذي يديره mise. يفشل الأمر `codex update`، ويمكن أن يفيد الأمر `claude update` بالنجاح بينما يثبّت نسخة منفصلة لا يتتبعها mise. إذا كنت تفضّل استخدام المثبّت والمحدّث الأصليين لوكيل ما، أضفه إلى `disable_tools`؛ راجع [أدوات CLI المثبتة مسبقًا](18-development-tools.md#preinstalled-cli-tools).

لتثبيت جميع الأدوات الكسولة المهيأة قبل أن تحتاج إليها، شغّل `mise install --include-lazy`. يشمل هذا أدوات CLI الافتراضية الأخرى في Omarchy إضافة إلى الوكلاء. راجع [أدوات CLI المثبتة مسبقًا](18-development-tools.md#preinstalled-cli-tools) لتثبيت أداة واحدة أو لاستخدام تثبيتك الخاص.

يُثبَّت `grok` عبر حزمة `grok` الرسمية من mise، بالطريقة نفسها التي يُثبَّت بها `claude` و`codex`. شغّل `grok`، أو اختره تحت _الوكيل > إطار التشغيل_. تجاوز مثبّت `curl | bash` الموجود على x.ai. يضع ذلك المسار نسخة ثانية في `~/.grok/bin`، ويضعها في مقدمة `PATH`، ويستبدل غلاف Omarchy.

يفتح `dsh` واجهة المتصفح الخاصة به على `127.0.0.1:3080`، مع دليل الإطلاق كمساحة عمل افتراضية له. لا تأخذ واجهة المتصفح الخاصة به موجه بدء، لذلك يفتحه الأمر `omarchy agent prompt` مع وضع الموجه في حافظتك لتلصقه. يبدأ Omarchy تشغيله بإعداد أذونات DeepSeek المسبق دون موافقة. يرفع DeepSeek Harness سجلات الجلسات إلى DeepSeek عندما تستخدم واجهة برمجة التطبيقات الرسمية لنماذجه؛ أوقف ذلك تحت _الإعدادات > عام > رفع سجل الجلسة_ في واجهة المتصفح الخاصة به. تُرفع الملاحظات التي ترسلها إليه مع الجلسة أيضًا، ما لم تبدأه بـ `DSH_TELEMETRY_MODE=DISABLED`.

### الوكيل الافتراضي

اختر وكيلك الافتراضي بـ `omarchy default agent <name>` أو تحت _الوكيل > إطار التشغيل_ في قائمة Omarchy (`Super + Space`). إذا لم يكن الوكيل مثبّتًا بعد، فإن اختياره يثبّته أولًا، ويحصل أيضًا على مشغّل خاص به في مشغّل التطبيقات، بجوار الوكيل. ستدعوك Omarchy الجديدة إلى اتخاذ هذا الاختيار بإشعار يظهر مرة واحدة.

يحاول اختيار Claude أيضًا إعداد إضافة المتصفح الخاصة به لـ Chromium وChrome وBrave وBrave Origin وEdge. ينطبق إعداد الإضافة على جميع المستخدمين وقد يطلب كلمة مرور النظام الخاصة بك؛ ومع ذلك فإن الإلغاء أو فشل تثبيت الإضافة ما يزالان يختاران Claude ويشغّلانه. أعد تشغيل متصفحك، وفعّل الإضافة إذا طُلب منك ذلك، وسجّل الدخول إلى Claude لإنهاء اتصاله. شغّل `/chrome` في Claude للتحقق من الاتصال. لا يدعم Firefox وZen هذه الإضافة. إذا كان Claude وكيلك الافتراضي بالفعل قبل إضافة هذا الإعداد، اختره مرة أخرى لتثبيت الإضافة.

بمجرد أن تختار، يطلق `Super + Shift + Ctrl + A` الوكيل الافتراضي في نافذة طرفية مخصصة (أو يعرض المُنتقي إذا لم تكن قد اخترت بعد). يمكنك أيضًا إطلاقه مباشرة في مهمة بـ `omarchy agent prompt "Review this project"`. لا يأخذ Freebuff وDeepSeek Harness موجه بدء، لذلك يفتحان مع وضع الموجه في حافظتك لتلصقه بدلًا من ذلك. يعمل الوكلاء الذين يُطلقون بهذه الطريقة دون إشراف في أوضاع لا تتوقف لتسأل الخاصة بكل منهم، فكن مستعدًا لأن يقوموا بأشياء فعلًا! لا يمتلك MiniMax Code وضعًا كهذا لجلساته التفاعلية، لذلك يطلب الأذونات كالمعتاد. وبما أن الوكلاء يرفضون تذكّر الثقة لدليلك الرئيسي، تبدأ عمليات الإطلاق من `$HOME` في `~/Work` بدلًا من ذلك.

توجد اختصارات طرفية أيضًا: يشغّل `a` الوكيل الافتراضي ضمن الطرفية الحالية، بينما تبدأ `c` و`cx` و`cy` تشغيل OpenCode وClaude Code وCodex مباشرة (في أوضاع الموافقة التلقائية الخاصة بها مرة أخرى). تتزامن تغييرات السمات مع الوكلاء أيضًا: يتبع Claude Code وPi وOpenCode وHermes (بمجرد أن تثبّته Omarchy) جميعها التغيير عندما تبدّل سمة Omarchy.

### تعليمات وكيلك

تذهب القواعد الشخصية لكل وكيل في `~/.agents/AGENTS.md`، بجوار المهارات المشتركة في `~/.agents/skills`. افتحها تحت _الوكيل > التعليمات_، والتي تربطها أيضًا بكل إطار تشغيل يحتفظ بملفه العام الخاص: `~/.claude/CLAUDE.md` و`~/.codex/AGENTS.md` و`~/.pi/agent/AGENTS.md` و`~/.config/opencode/AGENTS.md` و`~/.copilot/copilot-instructions.md` الخاص بـ Copilot، وهكذا دواليك. يقرأ Crush وAmp رابط `~/.config/AGENTS.md`، بينما يقرأ omp وKimi وDeepSeek Harness ملف `~/.agents/AGENTS.md` مباشرة. يربطه اختيار وكيل افتراضي أيضًا. يصبح ملف تعليمات كان لديك بالفعل هو الملف المشترك إذا لم يكن هناك واحد بعد؛ وإلا يُحتفظ به بجوار الرابط باسم `.bak`. شغّل `omarchy agent instructions` لإعادة الربط بعد تثبيت وكيل آخر.

### لوحة الوكلاء

يحتوي الشريط العلوي على أيقونة وكلاء. قبل أن تُعِدّ وكيلًا، ترشدك لوحته خطوة بخطوة لتسجيل الدخول إلى Claude أو Codex أو Grok، ويصبح الأول منها وكيلك الافتراضي. بعد ذلك، تضع اللوحة كل اشتراك على صفحة واحدة: كل وكيل وحساب مع خطته، وعداد لكل من حدود جلسته البالغة 5 ساعات وحدوده الأسبوعية مع الوقت المتبقي حتى إعادة تعيينها (مرّر المؤشر لعرض النسبة المئوية الدقيقة)، أو الرصيد المتبقي المدفوع مسبقًا، تحت سطر يتناوب عبر ما استخدمته عبرها جميعًا، مثل الرموز هذا الأسبوع ونموذجك الأكثر استخدامًا. تحت _اصنع شيئًا رائعًا_ تقدم موجهات بداية لسمة أو إضافة أو تطبيق أو لعبة جديدة تسلّم المهمة إلى وكيلك الافتراضي. تُبنى التطبيقات بالطريقة نفسها التي تُبنى بها تطبيقات Omarchy الخاصة Hype وMonologue وOmacut، بلغة C++ وQt Quick، باتباع مهارة وكيل omarchy-make-app، وتأتي المترجمات وأجزاء Qt التي تحتاج إليها مثبّتة. الألعاب هي صفحة three.js واحدة في `~/Games/vibes`، باتباع مهارة وكيل omarchy-make-game، وتفتح جميعها من مشغّل Game Vibes واحد في السمة الحالية؛ فهي تحمّل three.js من الويب، لذا تحتاج إلى اتصال للبدء. تُغطى Claude Code وCodex وGrok وKimi وCursor وبدل Grok Bot الخاص بها وGitHub Copilot وMuse وAntigravity وDevin جاهزة مع حدودها، وKimchi مع خطتها وأرصدتها المدفوعة مسبقًا وميزانيات إنفاقها، ويعرض Hermes وMistral Vibe وQwen Code جلساتها ورموزها بمجرد أن تستخدمها. تظهر أيضًا خطط المزودين ومفاتيحهم التي تستخدمها عبر pi أو omp أو opencode: OpenCode Zen وGo وخطة Z.ai GLM Coding Plan وOllama Cloud وخطة MiniMax Token Plan وSynthetic مع حدودها؛ وOpenRouter وDeepSeek مع أرصدتهما المدفوعة مسبقًا؛ وFireworks مع إنفاقها على مدار الثلاثين يومًا الماضية. تُحصى أيضًا الرموز من النماذج التي تشغّلها على أجهزتك الخاصة ضمن الإجماليات؛ وللنماذج نفسها لوحة خاصة بها، موصوفة تحت [النماذج المحلية](#local-models). يُحسب كل وكيل مرة واحدة، تحت الجهة التي تفرض رسومه، مهما كان عدد أطر التشغيل التي تقوده عبرها.

انقر بزر أيسر على أيقونة الشريط أو اضغط `Super + Ctrl + X` لعرض اللوحة، وانقر بزر أيمن لإطلاق وكيلك الافتراضي، وانقر بالزر الأوسط للتحديث. تُعاد توليد سجلات الاستخدام التي تقف وراءها كل 15 دقيقة بواسطة `omarchy agent usage update`، ويمكن للوحة حتى دمج الاستخدام من أجهزتك الأخرى عبر مجلد متزامن. اطّلع على README تحت `$OMARCHY_PATH/shell/plugins/agents/` للإعدادات الكاملة.

### اشتراكات متعددة

إذا كنت تدفع مقابل أكثر من خطة واحدة لـ Claude أو Codex أو Grok — خطة Max شخصية وخطة عمل، على سبيل المثال — يمكن لـ Omarchy إبقاءها جميعًا مسجّلة الدخول والتنقل بينها. أضف اشتراكًا بعلامة + في لوحة الوكلاء، التي ترشدك خطوة بخطوة هناك مباشرة، أو بـ `omarchy agent account add claude Work` (أو `codex`، أو `grok`). يثبّت واجهة سطر الأوامر إذا كانت مفقودة. يسجّل الحساب الأول لمزود الدخول عبر متصفحك العادي، تمامًا حيث تبحث واجهة سطر الأوامر دائمًا. يسجّل كل حساب بعد ذلك الدخول عبر نافذة خاصة، حتى لا يُلتقط الحساب الذي سجّل متصفحك الدخول إليه بالفعل عن طريق الخطأ؛ سجّل الدخول هناك كالحساب الذي تضيفه، وأغلق أي نافذة خاصة كانت مفتوحة لديك بالفعل أولًا. لا تسجّل الخروج أبدًا من واجهة سطر الأوامر للقيام بذلك: تسجيل الخروج يلغي تسجيل الدخول المحفوظ، وسيتعيّن إضافة ذلك الحساب مرة أخرى.

لنسخ تسجيلات دخول اشتراكك إلى جهاز Omarchy آخر عبر SSH، شغّل `omarchy agent account copy user@laptop`. يوفّر المرسل مستقبلًا مؤقتًا عندما لا يكون لدى الوجهة واحد مثبّت، لذلك يمكن لأجهزة Omarchy الأقدم استقبال الحسابات دون تحديث. تأخذ المستقبلات المثبّتة الأسبقية. ينسخ هذا جميع اشتراكات Claude وCodex وGrok؛ أضف أسماء المزودين لتحديدها، كما في `omarchy agent account copy laptop claude`. تتطابق أسماء الحسابات ومعرّفات الأوامر مع المصدر، بما يشمل الحسابات الموجودة بالفعل على الوجهة. تتلقى حسابات الوجهة غير ذات الصلة لاحقة رقمية إذا تعارضت أسماؤها، وتبقى الإعدادات والمهارات والإضافات وسجل المحادثات محلية لكل جهاز.

تُحتفظ ببيانات اعتماد الوجهة الموجودة. الحساب المصدري الذي سُجّل الدخول إليه هناك بالفعل تُزامَن تسميته دون استبدال بيانات اعتماده؛ وتُضاف حسابات أخرى بجانبه. لاستبدال بيانات الاعتماد المحفوظة للحسابات المطابقة، استخدم `omarchy agent account copy --replace laptop claude` بعد إنهاء جلسات ذلك الحساب على الوجهة. تحصل الوجهة الجديدة أيضًا على الحساب النشط وتفضيلات التبديل الخاصة بالمصدر؛ وتحتفظ الوجهة القائمة بتفضيلاتها الخاصة.

تنتقل بيانات الاعتماد عبر SSH وتُخزّن في ملفات خاصة على الوجهة، لذلك انسخ فقط إلى أجهزة تثق بها. هذه نسخة لمرة واحدة، وليست مزامنة مستمرة. يمكن لجهاز آخر تدوير رموز تحديث Codex، ما يترك تسجيل دخول منسوخًا بحاجة إلى تجديد؛ تبقى عمليات تسجيل الدخول المنفصلة الخيار الأكثر موثوقية للاستخدام المتزامن على أجهزة متعددة. راجع [إرشادات مصادقة حساب Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

حساب واحد لكل مزود نشط، وتبدأ كل جلسة جديدة به: `cx` و`cy` و`claude` أو `codex` أو `grok` العادية، وأي شيء يُطلق عبر `omarchy agent`، والبرامج النصية أو المحرّرات التي تجد واجهة سطر الأوامر على `PATH`. بدّل بـ `omarchy agent account use work` (وعُد بـ `omarchy agent account use main`)، أو في اللوحة بالضغط على رقم حساب ثم `Enter` (أو بالنقر على زر الاستخدام الخاص به). تتبدّل أيضًا جلسات Claude قيد التشغيل، اعتبارًا من رسالتها التالية: تعمل كل جلسة Claude في `~/.claude`، الذي يحتفظ دائمًا بتسجيل دخول الحساب النشط. تحتفظ جلسة Claude بدأت في مجلد حساب خاص بها بواسطة Omarchy أقدم بذلك تسجيل الدخول حتى تنتهي، لذلك يسمّي التبديل تلك الجلسات وينتهي من تلقاء نفسه بمجرد اختفائها. تبقى جلسات Codex وGrok قيد التشغيل على الحساب الذي بدأت به. يُشارك سجل المحادثات والإعدادات والمهارات والإضافات عبر الحسابات، لذلك يلتقط `claude --continue` في المجلد نفسه من حيث توقفت على الحساب الجديد.

مع أكثر من حساب واحد، تعرض اللوحة حدود كل حساب جنبًا إلى جنب، مع تمييز الحساب النشط. افتراضيًا تُعلمك Omarchy عندما يتجاوز الحساب النشط 95% من حد ما، والنقر على الإشعار يبدّل إلى الحساب الذي لديه أكبر هامش متاح. مرّر المؤشر فوق سطر حساب في اللوحة وانقر على Autoswitch الذي يظهر بجوار Use (أو اضغط `m`)، أو شغّل `omarchy agent account mode auto`، لجعله يبدّل من تلقاء نفسه بدلًا من ذلك؛ أثناء تفعيله، يحل Autoswitch محل Use، والنقر عليه مرة أخرى يعود إلى الإشعار. أضف رقمًا لتغيير العتبة، كما في `omarchy agent account mode auto 90`. إذا تجاوز كل حساب العتبة، ستسمع عن ذلك مرة واحدة، إلى جانب الحساب الذي سيتحرر أولًا. بينما يكون حساب نشط ضمن 15 نقطة من عتبته (80% افتراضيًا)، تُفحص حدوده كل ثلاث دقائق بدلًا من كل 15 دقيقة.

يعرض `omarchy agent account list` كل حساب وأحدث حدوده، وينسى `omarchy agent account remove work` واحدًا، ويعيد `omarchy agent account rename primary Hey` تسمية واحد (أو انقر على اسم حساب في اللوحة). تعمل هذه الأوامر على حسابات وكيلك الافتراضي؛ للوصول إلى المزود الآخر، سمّه أولًا، كما في `omarchy agent account use codex side`. تسجيل الدخول الذي كان لديك بالفعل في `~/.claude` أو `~/.codex` هو حساب _Main_. يبقى حساب Codex حيث هو؛ وينتظر حساب Claude في مجلد خاص به بينما يكون حساب آخر نشطًا. يمكن أن يعرض حساب تُرك دون استخدام لأكثر من ثماني ساعات تقريبًا _تسجيل الدخول مطلوب_؛ انقر عليه لتسجيل دخول ذلك الحساب مرة أخرى مباشرة في اللوحة، أو بدّل إليه وابدأ جلسة، فيُجدّد تسجيل الدخول من تلقاء نفسه. تصل خوادم MCP التي تضيفها بـ `claude mcp add` إلى كل حساب Claude، لأنها تعمل جميعًا في `~/.claude`؛ بالنسبة لـ Codex وGrok، ترافقك الخوادم التي كانت لديك عند إضافة حساب إليه، لكن الخوادم اللاحقة تصل فقط إلى الحساب الذي أضفتها فيه. يحتفظ Claude Desktop بتسجيل دخول خاص به، ولا تتبع أدوات Codex أو Grok المهيأة بمسار مطلق إلى ملف تنفيذي لواجهة سطر الأوامر التبديل. تأخذ `CLAUDE_CONFIG_DIR` أو `CODEX_HOME` أو `GROK_HOME` الصريحة الأسبقية على الحساب المحدد.

### تشخيص الأعطال

تراقب Omarchy برنامج systemd-coredump للبحث عن أعطال العمليات. بمجرد أن تختار وكيلًا افتراضيًا، يجلب أي برنامج لك يفرّغ ذاكرته الأساسية إشعار "Process crashed" — انقر عليه، ويُسلّم العطل إلى وكيلك الافتراضي إلى جانب مهارة omarchy-diagnose-crash الخاصة بـ Omarchy، التي ترشد الوكيل عبر إثبات الوقائع من تفريغ الذاكرة الأساسية وتقرير ما إذا كان العطل يستحق الإبلاغ عنه إلى المطورين. يمكنك أيضًا تشغيله يدويًا مقابل أي PID من `coredumpctl list` بـ `omarchy agent crash <pid>`.

تكون المراقبة مفعّلة افتراضيًا. أوقفها تحت _المشغّل > تبديل > إيقاف التقاط الأعطال_ (أو بـ `omarchy toggle crash-capture`) وتتوقف الإشعارات؛ ما يزال `omarchy agent crash <pid>` يعمل يدويًا.

يمكن أيضًا إسكات الأعطال برنامجًا واحدًا في كل مرة، وهذا ما يقدمه لك التشخيص في النهاية. يوقف `omarchy crash mute hyprland` الإشعارات لذلك البرنامج فقط، ويعيدها `omarchy crash mute hyprland off`، ويسرد `omarchy crash mute` بمفرده ما كتمته. يقبل مسار الملف التنفيذي بسرور مماثل لاسمه، لذلك يقوم `omarchy crash mute /usr/bin/hyprland` بالشيء نفسه. ضع اسمًا يحتوي على مسافة بين علامتي اقتباس، كما في `omarchy crash mute 'Some App'`. ما يزال كل شيء آخر يُشعِر، وما يزال البرنامج المكتوم يتعطل — هذا يخفي التذكير، ولا يصلح أي شيء.

### تطبيقات سطح المكتب

تحمل قائمة _التثبيت > AI_ أيضًا بعض تطبيقات الذكاء الاصطناعي الرسومية: Amp Desktop وAntigravity Desktop وتطبيق ChatGPT لسطح المكتب وتطبيق Claude لسطح المكتب (الإصدار التجريبي من Anthropic لنظام Linux، مع علامات تبويب Chat وCowork وClaude Code) وGrok Bot للدردشة مع نماذج xAI وHerdr Desktop وHermes Desktop وOpenClaw وتطبيق Perplexity لسطح المكتب وT3 Code. يُعد Grok Bot تطبيق دردشة سطح المكتب. وكيل البرمجة هو أمر `grok`.

يُعد Hermes Desktop التطبيق الذي يجب أن تعرفه، لأن الجهاز يمتلك Hermes واحدًا، وهو خاص بالتطبيق: لا يُثبَّت Hermes أبدًا إلا عبر التطبيق، وأمر `hermes` الذي يشغّله الوكيل الافتراضي هو الخاص بالتطبيق. يثبّت اختيار Hermes كوكيل افتراضي الشيء نفسه الذي يثبّته إدخال _التثبيت > AI_: الحزمة، وبيئة تشغيل Hermes تحت `~/.hermes` أعدّها مثبّت Hermes الخاص، والتي تستغرق بضع دقائق في المرة الأولى. بيئة التشغيل تلك هي Hermes الواحد الذي تستخدمه أمر `hermes` الطرفي والوكيل الافتراضي والتطبيق جميعًا، وتحدّث نفسها بـ `hermes update` بدلًا من انتظار إصدار Omarchy. يمنحها تثبيته أيضًا سمة Omarchy كواجهة باسم `omarchy`، تتبعها كل واجهة Hermes أثناء تبديلك للسمات؛ اختر أخرى تحت إعدادات مظهر Hermes أو بـ `/skin` إذا كنت تفضّل ألا تفعل، وستترك Omarchy ذلك الاختيار وشأنه. إزالة التطبيق تحت _إزالة > AI_ تغلق Hermes أولًا، بما في ذلك البوابة، وتأخذ بيئة التشغيل تلك معها، وتحتفظ بمحادثاتك وذكرياتك والمهارات التي كتبها Hermes لنفسه ما لم تخبره بخلاف ذلك: يسألك، افتراضيًا بـ لا، ما إذا كان يجب أن تذهب تلك البيانات وإعدادات اتصالك أيضًا.

تجربة OpenClaw لسطح المكتب هي واجهة Control UI الخاصة به، والتي تفتح كتطبيق ويب مدعوم ببوابته المحلية الخاصة. يعيش OpenClaw في `~/.openclaw` ويحدّث نفسه: استخدم زر "Update Gateway" في Control UI أو شغّل `openclaw update`، وستعيد البوابة التشغيل على الإصدار الجديد. تختار Omarchy فقط الإصدار الذي يبدأ منه تثبيت جديد. يمكن أن يكون OpenClaw أيضًا وكيلك الافتراضي: اختياره تحت _الوكيل > إطار التشغيل_ يُعدّ تلك النسخة نفسها في `~/.openclaw`، ويفتح الوكيل واجهة OpenClaw الطرفية المتصلة ببوابته. تأخذ إزالة OpenClaw تحت _إزالة > AI_ خدمة البوابة والتطبيق معها ثم تسأل ما إذا كان يجب أن يذهب `~/.openclaw` أيضًا، لأن ذلك يحتفظ بمحادثاتك وبيانات اعتمادك إلى جانب OpenClaw نفسه وبيئات تشغيل الإضافات التي ينزّلها؛ الافتراضي يحتفظ به، وتثبيت OpenClaw مرة أخرى يلتقطه من جديد.

يُعد Herdr Desktop تطبيق سطح مكتب [Herdr](https://herdr.dev): مساحات وعلامات تبويب وأجزاء من الطرفيات ووكلاء البرمجة تستمر في العمل في نواته عندما تغلق النافذة. يأتي من مثبّت Herdr الخاص بدلًا من حزمة، لذلك يعيش في `~/.local/share/herdr-app`، ويجلب نواته في `~/.local/bin/herdr-core` عندما لا تمتلك واحدًا بعد، ويحدّث كليهما نفسه. يجلس إلى جانب أمر `herdr` الذي توفره Omarchy على `Super + Ctrl + Return` بدلًا من استبداله، ويحصل على مفاتيح ذلك الأمر المباشرة: يقسّم `Alt + Return` و`Alt + Shift + Return` جزءًا إلى أسفل أو إلى اليمين، ويغلقه `Alt + Escape`، وينقل `Ctrl + Alt + Arrow` بين الأجزاء، ويختار `Alt + 1..9` و`Alt + Left/Right` علامة تبويب، وينقل `Alt + Up/Down` بين المساحات. يختار `Ctrl + 1..9` مساحة، ويتنقل `Alt + Shift + Up/Down` عبر الوكلاء. تبقى مفاتيح بادئة `Ctrl + Space` للطرفية فقط، لأن التطبيق لا يمكنه الاحتفاظ بمفتاح Ctrl عادي لتسلسل. تكتب Omarchy هذه إلى `~/.config/herdr-app/keys.json`، ويعيدها `omarchy-refresh-herdr-app`. يختار تثبيته سمة Omarchy الخاصة بـ Herdr، التي تتبع سمة Omarchy الخاصة بك من حينها فصاعدًا. يحتفظ Herdr بسمة واحدة للوضع الفاتح وواحدة للوضع الداكن، لذلك بعد التبديل بين سمة Omarchy داكنة وفاتحة، اختر Omarchy في منتقي سمات Herdr مرة أخرى للوضع الآخر.

يعمل T3 Code من إصدار AppImage الرسمي الخاص به في `~/.local/share/t3code` بدلًا من حزمة، لذلك يحدّث نفسه. يسأل تثبيته ما إذا كنت تريد البدء على قناة Stable أو Nightly؛ بدّل لاحقًا في إعدادات T3 Code. تعيش سلاسل محادثاتك وإعداداتك في `~/.t3`، وإزالة T3 Code تحت _إزالة > AI_ تأخذها معها.

### النماذج المحلية

شغّل نموذجًا مفتوحًا على جهازك الخاص لوكلاء البرمجة لديك. تبقى موجهاتك وشيفرتك على الجهاز؛ لا شيء يُرسل إلى النموذج يغادره. ابدأ بـ:

```bash
omarchy models use best text
```

يُعدّ ذلك أفضل نموذج نصي لهذا الجهاز، وهو النوع الذي يستخدمه وكلاؤك. للنماذج الصور والفيديو والموسيقى أفضل خاص بها: `omarchy models use best image` أو `video` أو `music`. شغّل `omarchy models use best` لرؤية اختيار كل نوع لهذا الجهاز.

أو افتح لوحة النماذج المحلية من أيقونة البريق الخاصة بها في الشريط العلوي، بجوار أيقونة الوكلاء، أو بـ Super + Ctrl + Alt + X، واختر +. تظهر الأيقونة عندما يناسب نموذج هذا الجهاز. يأتي Podman، الذي يشغّل النماذج، مع Omarchy، كما تأتي مجموعة أدوات حاويات NVIDIA على جهاز NVIDIA، والتي تمنحها GPU؛ إذا كان أي منهما مفقودًا، يثبّته الإعداد الأول. ثم تختار Omarchy النموذج الموصى به لهذا الجهاز، وتنزّله، وتبدأ تشغيله. توقع تنزيلًا بعشرات GB ومعظم ذاكرة الجهاز قيد الاستخدام أثناء تشغيل النموذج: يستخدم Flash Next حوالي 100 GiB مع سياقه الكامل البالغ 256K. إذا احتفظت نماذج أخرى بالذاكرة التي يحتاج إليها، يُعدّ متوقفًا، جاهزًا للبدء بمجرد إيقاف واحد. يتوقف النموذج عند تسجيل الخروج؛ أوقفه بنفسك عندما تحتاج إلى الذاكرة لشيء آخر.

يعرض `omarchy models list` الخيارات ويشرح سبب عدم ملاءمة بعضها. لإعداد نموذج آخر، شغّل `omarchy models use <recipe>`. اليوم، يتوفر `qwen3.8-flash-next-gufo` و`qwen3.8-27b-gufo` لأجهزة Strix Halo بسعة 128 GB؛ يأخذ طراز 27B حوالي 40 GiB، لذلك يترك مساحة لأعمال أخرى. على كمبيوتر محمول بسعة 64 GB مع Arc B390 من Intel، يعمل `qwen3.6-35b-a3b-llamacpp` في حوالي 30 GiB. تصل وصفات وتوصيات جديدة مع `omarchy update`، عبر الحزمة.

يحصل كل نموذج تُعدّه على سطر خاص به في لوحة النماذج المحلية: زر تشغيل لبدئه، وإيقاف مؤقت لإيقافه وتحرير ذاكرته، وزر طرفية لفتح وكيلك عليه. عبر الأعلى، يعرض شريط كيفية تقسيم ذاكرة الجهاز بين Omarchy نفسها (النظام وتطبيقاتك)، وكل نموذج قيد التشغيل، وما هو حر. أشر إلى نموذج متوقف وسيعرض الشريط ما إذا كان يناسب، أو مقدار نقصه. يمكن تشغيل عدة نماذج في وقت واحد عندما تتسع في الذاكرة معًا؛ إذا لم يتسع واحد، تخبرك Omarchy أي نموذج قيد التشغيل يجب إيقافه. اسحب الأسطر بشعارها لإعادة ترتيبها، واضغط Delete على سطر محدد لإزالة نموذج وتنزيله.

يحصل كل نموذج برمجة تُعدّه أيضًا على إدخال خاص به في مشغّل التطبيقات، تحت اسم النموذج ومع شعار صانعه، بالطريقة التي يضيف بها تسجيل الدخول إلى Claude أو Codex أو Grok واحدًا. يفتح وكيلك على ذلك النموذج، ويبدأ النموذج أولًا إذا لم يكن قيد التشغيل: تعرض الطرفية تحميله وتسلّم إلى الوكيل بمجرد أن يصبح جاهزًا. تزيل إزالة نموذج إدخاله.

ليس كل نموذج للبرمجة. تفتح نماذج الصور والفيديو والموسيقى في Fantasi بدلًا من ذلك، تطبيق Omarchy لصنع الصور والفيديو والموسيقى بنموذج يعمل على هذا الجهاز، تُختار هناك أو من سطرها في لوحة النماذج المحلية.

يبقى النموذج يعمل تمامًا كما أُعدّ، لذلك لا يعيد تحديث Omarchy أبدًا تشغيل واحد تحت وكلائك. عندما تمتلك Omarchy بيئة تشغيل أحدث أو أوزانًا أحدث لنموذج أعددته، يعرض سطره زر تحديث: اضغط عليه ويُعدّ النموذج مرة أخرى في الخلفية، وينزّل فقط ما تغيّر، ويعيد التشغيل على الإصدار الجديد. يبقى النموذج الذي كان متوقفًا متوقفًا. يقوم `omarchy models update` بالشيء نفسه لكل نموذج من طرفية.

من سطر الأوامر، يقوم `omarchy models start <recipe>` و`omarchy models stop <recipe>` بالشيء نفسه، ويعرض `omarchy models status` كل نموذج، ويفتح `omarchy agent --local` وكيلك الافتراضي على آخر نموذج بدأته. يمكن لـ pi وOpenCode وQwen Code استخدام واحد؛ مع أي وكيل افتراضي آخر يفتح في pi، أو في OpenCode إذا لم يكن لديك pi. يسرد pi أيضًا كل نموذج أعددته، وتلك الموجودة على أجهزة قارنتها، في منتقي نماذجه الخاص، لذلك يصل إليها `pi` العادي أيضًا. يمكن لأي عميل متوافق مع OpenAI الاتصال أيضًا: يعرض `status` عنوان كل نموذج (الأول هو `http://127.0.0.1:11435/v1`)، اسم الوصفة هو النموذج، والمفتاح موجود في `~/.config/omarchy/agent-local/key`.

يحذف `omarchy models remove <recipe>` نموذجًا والتنزيلات التي لا يستخدمها أي نموذج آخر.

تُوسم بيئات تشغيل الأطراف الثالثة بناشرها. تشغّل Omarchy كل نموذج دون وصول إلى الشبكة.

### نماذج LLM المحلية

توصي Omarchy بطريقتين لتشغيل نماذج LLM المحلية: LM Studio وOllama. يوفر LM Studio واجهة GUI للعثور على النماذج مفتوحة الأوزان وتثبيتها وتشغيلها. إنه طريقة رائعة للبدء بسهولة. يقدم Ollama واجهة CLI للقيام بذلك بشكل مشابه. لكن إذا كنت جديدًا على النماذج المحلية، سأبدأ بـ LM Studio. يمكنك تثبيت أي منهما تحت _التثبيت > AI_ في قائمة Omarchy.

### مهارات Omarchy

تساعد مهارات الوكيل الذكاء الاصطناعي على استخدام أدوات محددة بطريقة محددة، وتوفر Omarchy سبعًا منها. تغطي مهارة omarchy تخصيص النظام، مثل تعديل إعداد Hyprland الخاص بك أو ضبط الشريط. تغطي omarchy-make-theme وomarchy-make-plugin وomarchy-make-app وomarchy-make-game صنع شيء جديد، وتغطي omarchy-contribute الإبلاغ عن خطأ أو إرسال إصلاح إلى المطورين، وتعمل omarchy-diagnose-crash عبر تفريغ ذاكرة عطل ما. تُربط رمزيًا في دلائل مهارات Claude Code (`~/.claude/skills`) وCodex (`~/.codex/skills`) وPi (`~/.pi/agent/skills`) وAntigravity (`~/.gemini/config/skills`) وHermes (`~/.hermes/skills` وكل `~/.hermes/profiles/*/skills`) وموقع `~/.agents/skills` العام، لذلك تلتقطها معظم أطر التشغيل تلقائيًا. تأخذ مجلد مهارة خاص بك بنفس الاسم الأسبقية.

لكن يجب أن تتعامل مع هذه المهارات كمهارات تجريبية. ستستخدمها نماذج مختلفة بفعالية مختلفة. من الأفضل التشغيل في وضع التخطيط أولًا، حتى تكون لديك فكرة عما يرغب الوكيل في تغييره. ثم كن مستعدًا للتراجع عن التغييرات أو حتى استدعاء `omarchy reinstall configs`، إذا أحدث الوكيل فوضى في كل شيء.
