# الذكاء الاصطناعي

تتضمن Omarchy مشغّلات لوكلاء البرمجة أدناه دون اختيار وكيل افتراضي نيابة عنك. شغّل أمرًا لتثبيت CLI الخاص به عند أول استخدام، ثم قم بالمصادقة عند مطالبتك. Hermes وOpenClaw هما الاستثناءان: لا يتم تثبيت أي شيء لهما عبر mise، واختيار أي منهما يجهّز نسخته الخاصة ذاتية التحديث، كما يوضح قسم _تطبيقات سطح المكتب_ أدناه.

### تثبيت الوكلاء وتحديثهم

باستثناء Hermes وOpenClaw، يستخدم هؤلاء الوكلاء التثبيت الكسول في mise: التشغيل الأول يثبّت CLI، والتشغيلات اللاحقة تعيد استخدامه. يتحقق mise أيضًا من وجود إصدار جديد لوكيل مثبت مرة واحدة على الأكثر كل أربع ساعات، قبل بدئه مباشرة أو في الخلفية عند موجه shell. إذا فشل ذلك التحديث أو كنت غير متصل، يعمل الإصدار المثبت. يقوم `omarchy update` بتحديث الوكلاء المثبتين مع بقية Omarchy، و`mup` يحدّث الأدوات التي تديرها mise فقط.

لا يقوم محدّث الوكيل نفسه، مثل `claude update` أو `codex update` أو زر تحديث في تطبيق، بتحديث التثبيت الذي تديره mise. يفشل `codex update`، ويمكن أن يبلغ `claude update` عن النجاح بينما يثبّت نسخة منفصلة لا تتعقبها mise. إذا كنت تفضل استخدام مثبّت الوكيل الأصلي ومحدّثه، أضفه إلى `disable_tools`؛ راجع [أدوات CLI المثبتة مسبقًا](18-development-tools.md#preinstalled-cli-tools).

لتثبيت جميع الأدوات الكسولة المكونة قبل أن تحتاجها، شغّل `mise install --include-lazy`. يشمل هذا أدوات CLI الافتراضية الأخرى في Omarchy وكذلك الوكلاء. راجع [أدوات CLI المثبتة مسبقًا](18-development-tools.md#preinstalled-cli-tools) لتثبيت أداة واحدة أو استخدام تثبيتك الخاص.

يتم تثبيت `grok` عبر حزمة `grok` الرسمية من mise، بالطريقة نفسها مثل `claude` و`codex`. شغّل `grok`، أو اختره ضمن _Agent > Harness_. تخطَّ مثبّت `curl | bash` على x.ai. يضع ذلك المسار نسخة ثانية في `~/.grok/bin`، ويضعها في مقدمة `PATH`، ويستبدل غلاف Omarchy.

يفتح `dsh` واجهة المتصفح الخاصة به على `127.0.0.1:3080`، مع دليل التشغيل بوصفه مساحة عمله الافتراضية. لا تأخذ واجهة المتصفح موجه بدء، لذا فإن `omarchy agent prompt` يفتحه مع الموجه في حافظتك للصقه. يبدأ Omarchy به بإعداد أذونات DeepSeek المسبق بدون موافقة. يرفع DeepSeek Harness سجلات الجلسات إلى DeepSeek عندما تستخدم API النموذج الرسمي الخاص به؛ عطّل ذلك ضمن _Settings > General > Upload Session Log_ في واجهة المتصفح الخاصة به. يتم أيضًا رفع الملاحظات التي ترسلها مع الجلسة، ما لم تبدأه بـ `DSH_TELEMETRY_MODE=DISABLED`.

### الوكيل الافتراضي

اختر وكيلك الافتراضي بـ `omarchy default agent <name>` أو ضمن _Agent > Harness_ في قائمة Omarchy (`Super + Space`). إذا لم يكن الوكيل مثبتًا بعد، فإن اختياره يثبّته أولًا، ويحصل أيضًا على مشغّل خاص به في مشغّل التطبيقات، بجوار Agent. ستدعوك Omarchy جديدة إلى اتخاذ هذا الخيار بإشعار يظهر مرة واحدة.

يحاول اختيار Claude أيضًا إعداد إضافة المتصفح الخاصة به لـ Chromium وChrome وBrave وBrave Origin وEdge. ينطبق إعداد الإضافة على جميع المستخدمين وقد يطلب كلمة مرور النظام؛ إلغاء تثبيت الإضافة أو فشله ما يزال يختار Claude ويشغّله. أعد تشغيل متصفحك، فعّل الإضافة إذا طُلب منك، وسجّل الدخول إلى Claude لإنهاء اتصالها. شغّل `/chrome` في Claude للتحقق من الاتصال. لا يدعم Firefox وZen هذه الإضافة. إذا كان Claude وكيلك الافتراضي بالفعل قبل إضافة هذا الإعداد، اختره مرة أخرى لتثبيت الإضافة.

بمجرد اختيارك، يطلق `Super + Shift + Ctrl + A` الوكيل الافتراضي في نافذة طرفية مخصصة (أو يعرض المنتقي إذا لم تكن قد اخترت بعد). يمكنك أيضًا إطلاقه مباشرة في مهمة بـ `omarchy agent prompt "Review this project"`. لا يأخذ Freebuff وDeepSeek Harness موجه بدء، لذا يفتحان مع الموجه في حافظتك للصقه بدلًا من ذلك. الوكلاء الذين يتم إطلاقهم بهذه الطريقة يعملون دون مراقبة في أوضاعهم الخاصة بعدم التوقف للسؤال، لذا كن مستعدًا لقيامهم بأشياء فعلًا! لا يمتلك MiniMax Code مثل هذا الوضع لجلساته التفاعلية، لذا يطلب الأذونات كالمعتاد. وبما أن الوكلاء يرفضون تذكر الثقة لدليل منزلك، تبدأ عمليات الإطلاق من `$HOME` في `~/Work` بدلًا من ذلك.

توجد اختصارات طرفية أيضًا: `a` يشغّل الوكيل الافتراضي داخل الطرفية الحالية، بينما `c` و`cx` و`cy` تبدأ OpenCode وClaude Code وCodex مباشرة (مرة أخرى في أوضاع الموافقة التلقائية الخاصة بها). تتزامن تغييرات السمة مع الوكلاء أيضًا: Claude Code وPi وOpenCode وHermes (بمجرد أن تثبّته Omarchy) كلها تتبعك عندما تبدّل سمة Omarchy.

### تعليمات وكيلك

تذهب القواعد الشخصية لكل وكيل في `~/.agents/AGENTS.md`، بجوار المهارات المشتركة في `~/.agents/skills`. افتحها ضمن _Agent > Instructions_، والتي تربطها أيضًا بكل أداة تشغيل تحتفظ بملفها العالمي الخاص: `~/.claude/CLAUDE.md` و`~/.codex/AGENTS.md` و`~/.pi/agent/AGENTS.md` و`~/.config/opencode/AGENTS.md` و`~/.copilot/copilot-instructions.md` الخاص بـ Copilot، وما إلى ذلك. يقرأ Crush وAmp رابط `~/.config/AGENTS.md`، بينما يقرأ omp وKimi وDeepSeek Harness `~/.agents/AGENTS.md` مباشرة. اختيار وكيل افتراضي يربطه أيضًا. يصبح ملف تعليمات كان لديك بالفعل هو الملف المشترك إذا لم يكن هناك واحد بعد؛ وإلا يتم الاحتفاظ به بجوار الرابط باسم `.bak`. شغّل `omarchy agent instructions` لإعادة الربط بعد تثبيت وكيل آخر.

### لوحة الوكلاء

يحتوي الشريط العلوي على أيقونة وكلاء. قبل أن تجهّز وكيلًا، ترشدك لوحته خلال تسجيل الدخول إلى Claude أو Codex أو Grok، ويصبح الأول وكيلك الافتراضي. بعد ذلك، تضع اللوحة كل اشتراك في صفحة واحدة: كل وكيل وحساب مع خطته، ومقياس لكل من حد جلسته البالغ 5 ساعات وحدوده الأسبوعية مع الوقت حتى إعادة التعيين (مرّر للاطلاع على النسبة المئوية الدقيقة)، أو الرصيد المدفوع مسبقًا المتبقي، تحت سطر يدور حول ما استخدمته عبر جميعها، مثل الرموز هذا الأسبوع ونموذجك الأكثر استخدامًا. ضمن _Make something cool_ تقدم موجهات بداية لسمة جديدة أو إضافة أو تطبيق أو لعبة تسلّم المهمة إلى وكيلك الافتراضي. تُبنى التطبيقات بالطريقة التي تُبنى بها تطبيقات Omarchy الخاصة Hype وMonologue وOmacut، بـ C++ وQt Quick، باتباع مهارة وكيل omarchy-make-app، ويأتي المترجم وقطع Qt التي تحتاجها مثبتة. الألعاب هي صفحة three.js واحدة في `~/Games/vibes`، باتباع مهارة وكيل omarchy-make-game، وكلها تفتح من مشغّل Game Vibes واحد في السمة الحالية؛ تحمّل three.js من الويب، لذا تحتاج إلى اتصال للبدء. يتم تغطية Claude Code وCodex وGrok وKimi وCursor وبدل Grok Bot الخاص به وGitHub Copilot وMuse وAntigravity وDevin جاهزة مع حدودها، وKimchi مع خطته وأرصدته المدفوعة مسبقًا وميزانيات الإنفاق، وHermes وMistral Vibe وQwen Code تظهر جلساتها ورموزها بمجرد استخدامها. تظهر أيضًا خطط المزودين ومفاتيحهم التي تستخدمها عبر pi أو omp أو opencode: OpenCode Zen وGo، وخطة Z.ai GLM Coding Plan، وOllama Cloud، وخطة MiniMax Token Plan، وSynthetic مع حدودها؛ OpenRouter وDeepSeek مع أرصدتهما المدفوعة مسبقًا؛ Fireworks مع إنفاقه على مدى آخر 30 يومًا. تُحتسب الرموز من النماذج التي تشغّلها على أجهزتك الخاصة ضمن الإجماليات أيضًا؛ النماذج نفسها لها لوحتها الخاصة، الموصوفة ضمن [النماذج المحلية](#local-models). يتم عد كل وكيل مرة واحدة، تحت من يفوتره، مهما كان عدد أدوات التشغيل التي تقوده عبرها.

انقر بزر الماوس الأيسر على أيقونة الشريط أو اضغط `Super + Ctrl + X` للوحة، وانقر بزر الماوس الأيمن لإطلاق وكيلك الافتراضي، وانقر بالزر الأوسط للتحديث. يتم إعادة إنشاء سجلات الاستخدام وراءها كل 15 دقيقة بواسطة `omarchy agent usage update`، ويمكن للوحة حتى دمج الاستخدام من أجهزتك الأخرى عبر مجلد متزامن. راجع README ضمن `$OMARCHY_PATH/shell/plugins/agents/` للإعدادات الكاملة.

### اشتراكات متعددة

إذا دفعت مقابل أكثر من خطة Claude أو Codex أو Grok واحدة — خطة Max شخصية وخطة عمل، على سبيل المثال — يمكن لـ Omarchy إبقاءها جميعًا مسجلة الدخول والتنقل بينها. أضف اشتراكًا بعلامة + في لوحة الوكلاء، التي ترشدك خلال ذلك هناك مباشرة، أو بـ `omarchy agent account add claude Work` (أو `codex`، أو `grok`). يثبّت CLI إذا كان مفقودًا. يسجل الحساب الأول لمزود الدخول عبر متصفحك العادي، حيث يبحث CLI دائمًا. كل حساب بعد ذلك يسجل الدخول عبر نافذة خاصة، بحيث لا يتم التقاط الحساب الذي سجل متصفحك الدخول إليه بالفعل عن طريق الخطأ؛ سجل الدخول هناك كالحساب الذي تضيفه، وأغلق أي نافذة خاصة فتحتها بالفعل أولًا. لا تسجل الخروج من CLI أبدًا للقيام بذلك: تسجيل الخروج يبطل تسجيل الدخول المحفوظ، وسيتعين إضافة ذلك الحساب مرة أخرى.

لنسخ تسجيلات دخول اشتراكك إلى جهاز Omarchy آخر عبر SSH، شغّل `omarchy agent account copy user@laptop`. يوفر المرسل مستقبلًا مؤقتًا عندما لا يكون لدى الوجهة واحد مثبت، بحيث يمكن لأجهزة Omarchy الأقدم استقبال الحسابات دون تحديث. المستقبلون المثبتون لهم الأسبقية. ينسخ هذا جميع اشتراكات Claude وCodex وGrok؛ أضف أسماء المزودين لتحديدها، كما في `omarchy agent account copy laptop claude`. تتطابق أسماء الحسابات ومعرفات الأوامر مع المصدر، بما في ذلك الحسابات الموجودة بالفعل على الوجهة. تتلقى حسابات الوجهة غير ذات الصلة لاحقة رقمية إذا تعارضت أسماؤها، وتبقى الإعدادات والمهارات والإضافات وسجل المحادثات محلية لكل جهاز.

يتم الاحتفاظ ببيانات اعتماد الوجهة الحالية. الحساب المصدري الذي سجل الدخول هناك بالفعل تتم مزامنة اسمه دون استبدال بيانات اعتماده؛ تتم إضافة حسابات أخرى بجانبه. لاستبدال بيانات الاعتماد المحفوظة للحسابات المطابقة، استخدم `omarchy agent account copy --replace laptop claude` بعد إنهاء جلسات ذلك الحساب على الوجهة. تحصل الوجهة الجديدة أيضًا على الحساب النشط وتفضيلات التبديل للمصدر؛ الوجهة المؤسسة تحتفظ بخاصتها.

تنتقل بيانات الاعتماد عبر SSH ويتم تخزينها في ملفات خاصة على الوجهة، لذا انسخ فقط إلى أجهزة تثق بها. هذه نسخة لمرة واحدة، وليست مزامنة مستمرة. يمكن تدوير رموز تحديث Codex بواسطة جهاز آخر، مما يترك تسجيل دخول منسوخًا بحاجة إلى تجديد؛ تبقى تسجيلات الدخول المنفصلة الخيار الأكثر موثوقية للاستخدام المتزامن على عدة أجهزة. راجع [إرشادات مصادقة حساب Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

حساب واحد لكل مزود نشط، وكل جلسة جديدة تبدأ به: `cx` و`cy` و`claude` أو `codex` أو `grok` العادي، وأي شيء يتم إطلاقه عبر `omarchy agent`، والبرامج النصية أو المحررات التي تجد CLI على `PATH`. بدّل بـ `omarchy agent account use work` (وعودة بـ `omarchy agent account use main`)، أو في اللوحة بالضغط على رقم حساب ثم `Enter` (أو النقر على زر Use الخاص به). تتبدل جلسات Claude قيد التشغيل أيضًا، من رسالتها التالية: كل جلسة Claude تعمل في `~/.claude`، الذي يحتفظ دائمًا بتسجيل دخول الحساب النشط. جلسة Claude التي بدأت في مجلد حساب خاص بها بواسطة Omarchy أقدم تحتفظ بتسجيل الدخول ذلك حتى تنتهي، لذا يسمي التبديل تلك الجلسات وينتهي من تلقاء نفسه بمجرد ذهابها. تبقى جلسات Codex وGrok قيد التشغيل على الحساب الذي بدأت به. يتم مشاركة سجل المحادثات والإعدادات والمهارات والإضافات عبر الحسابات، لذا فإن `claude --continue` في المجلد نفسه يكمل من حيث توقفت على الحساب الجديد.

مع أكثر من حساب واحد، تعرض اللوحة حدود كل حساب جنبًا إلى جنب، مع وضع علامة على النشط. بشكل افتراضي، تخطرك Omarchy عندما يتجاوز الحساب النشط 95% من الحد، والنقر على الإشعار يبدل إلى الحساب ذي أكبر هامش. مرّر فوق سطر حساب في اللوحة وانقر على Autoswitch الذي يظهر بجوار Use (أو اضغط `m`)، أو شغّل `omarchy agent account mode auto`، ليبدل من تلقاء نفسه بدلًا من ذلك؛ بينما هو قيد التشغيل، يأخذ Autoswitch مكان Use، والنقر عليه مرة أخرى يعود إلى الإخطار. أضف رقمًا لتغيير العتبة، كما في `omarchy agent account mode auto 90`. إذا تجاوز كل حساب العتبة، ستسمع عن ذلك مرة واحدة، جنبًا إلى جنب مع أي حساب يتحرر أولًا. بينما يكون الحساب النشط ضمن 15 نقطة من عتبته (80% عند الافتراضي)، يتم فحص حدوده كل ثلاث دقائق بدلًا من كل 15.

يعرض `omarchy agent account list` كل حساب وحدوده الأخيرة، و`omarchy agent account remove work` ينسى واحدًا، و`omarchy agent account rename primary Hey` يعيد تسمية واحد (أو انقر على اسم حساب في اللوحة). تعمل هذه الأوامر على حسابات وكيلك الافتراضي؛ للوصول إلى المزود الآخر، سمّه أولًا، كما في `omarchy agent account use codex side`. تسجيل الدخول الذي كان لديك بالفعل في `~/.claude` أو `~/.codex` هو حساب _Main_. يبقى حساب Codex حيث هو؛ حساب Claude ينتظر في مجلد خاص به بينما يكون حساب آخر نشطًا. حساب ترك غير مستخدم لأكثر من حوالي ثماني ساعات يمكن أن يعرض _Sign-in required_؛ انقر عليه لتسجيل دخول ذلك الحساب مرة أخرى مباشرة في اللوحة، أو بدّل إليه وابدأ جلسة، مما ينعش تسجيل الدخول من تلقاء نفسه. خوادم MCP التي تضيفها بـ `claude mcp add` تصل إلى كل حساب Claude، بما أنها كلها تعمل في `~/.claude`؛ بالنسبة إلى Codex وGrok، تأتي الخوادم التي كانت لديك عند إضافة حساب معها، لكن الخوادم اللاحقة تصل فقط إلى الحساب الذي أضفتها فيه. يحتفظ Claude Desktop بتسجيل دخول خاص به، وأدوات Codex أو Grok المكونة بمسار مطلق إلى ثنائي CLI لا تتبع التبديل. يأخذ `CLAUDE_CONFIG_DIR` أو `CODEX_HOME` أو `GROK_HOME` صريح الأسبقية على الحساب المختار.

### تشخيص الأعطال

تراقب Omarchy systemd-coredump لأعطال العمليات. بمجرد اختيارك وكيلًا افتراضيًا، أي برنامج لك يقوم بتفريغ النواة يجلب إشعار "Process crashed" — انقر عليه، ويتم تسليم العطل إلى وكيلك الافتراضي جنبًا إلى جنب مع مهارة omarchy-diagnose-crash في Omarchy، التي ترشد الوكيل خلال إثبات الحقائق من تفريغ النواة وتقرير ما إذا كان العطل يستحق الإبلاغ عنه في المصدر. يمكنك أيضًا تشغيله يدويًا مقابل أي PID من `coredumpctl list` بـ `omarchy agent crash <pid>`.

المراقبة قيد التشغيل افتراضيًا. أطفئها ضمن _Trigger > Toggle > Crash Capture Off_ (أو بـ `omarchy toggle crash-capture`) وتتوقف الإشعارات؛ لا يزال `omarchy agent crash <pid>` يعمل يدويًا.

يمكن أيضًا إسكات الأعطال برنامجًا واحدًا في كل مرة، وهذا ما يقدمه لك التشخيص في النهاية. `omarchy crash mute hyprland` يوقف الإشعارات لذلك البرنامج فقط، و`omarchy crash mute hyprland off` يعيدها، و`omarchy crash mute` بمفرده يسرد ما كتمته. يأخذ مسار الثنائي بسعادة مثل اسمه، لذا فإن `omarchy crash mute /usr/bin/hyprland` يفعل الشيء نفسه. ضع علامة اقتباس حول اسم به مسافة، كما في `omarchy crash mute 'Some App'`. كل شيء آخر لا يزال يُخطر، والبرنامج المكتوم لا يزال يتعطل — هذا يخفي التذكير، ولا يصلح أي شيء.

### تطبيقات سطح المكتب

يحمل قائمة _Install > AI_ أيضًا بعض تطبيقات الذكاء الاصطناعي الرسومية: Amp Desktop وAntigravity Desktop وتطبيق ChatGPT لسطح المكتب وتطبيق Claude لسطح المكتب (إصدار Anthropic التجريبي لنظام Linux، مع علامات تبويب Chat وCowork وClaude Code)، وGrok Bot للدردشة مع نماذج xAI، وHerdr Desktop وHermes Desktop وOpenClaw وتطبيق Perplexity لسطح المكتب، وT3 Code. Grok Bot هو تطبيق الدردشة لسطح المكتب. وكيل البرمجة هو أمر `grok`.

Hermes Desktop هو ما يجب معرفته، لأن الجهاز يمتلك Hermes واحدًا، وهو خاص بالتطبيق: يتم تثبيت Hermes فقط عبر التطبيق أبدًا، وأمر `hermes` الذي يشغّله الوكيل الافتراضي هو الخاص بالتطبيق. اختيار Hermes كوكيل افتراضي يثبّت الشيء نفسه الذي يثبّته إدخال _Install > AI_: الحزمة، ووقت تشغيل Hermes تحت `~/.hermes` يتم إعداده بواسطة مثبّت Hermes الخاص، والذي يستغرق بضع دقائق في المرة الأولى. وقت التشغيل ذلك هو Hermes الوحيد الذي تستخدمه أمر `hermes` الطرفي والوكيل الافتراضي والتطبيق، ويحدّث نفسه بـ `hermes update` بدلًا من انتظار إصدار Omarchy. تثبيته يمنح Hermes أيضًا سمة Omarchy كجلد باسم `omarchy`، تتبعه كل أسطح Hermes أثناء تبديل السمات؛ اختر آخر ضمن إعدادات مظهر Hermes أو بـ `/skin` إذا كنت تفضل عدم ذلك، وتترك Omarchy ذلك الخيار وشأنه. إزالة التطبيق ضمن _Remove > AI_ تغلق Hermes أولًا، بما في ذلك البوابة، وتأخذ وقت التشغيل ذلك معها، وتحتفظ بدردشاتك وذكرياتك والمهارات التي كتبها Hermes لنفسه ما لم تخبره بخلاف ذلك: يسأل، افتراضيًا لا، عما إذا كان يجب أن تذهب تلك البيانات وإعدادات اتصالك أيضًا.

تجربة OpenClaw لسطح المكتب هي واجهة Control UI الخاصة به، والتي تفتح كتطبيق ويب مدعوم ببوابته المحلية الخاصة. يعيش OpenClaw في `~/.openclaw` ويحدّث نفسه: استخدم زر "Update Gateway" في Control UI أو شغّل `openclaw update`، وتعيد البوابة التشغيل على الإصدار الجديد. تختار Omarchy فقط الإصدار الذي يبدأ منه التثبيت الجديد. يمكن أن يكون OpenClaw أيضًا وكيلك الافتراضي: اختياره ضمن _Agent > Harness_ يجهّز تلك النسخة نفسها في `~/.openclaw`، ويفتح الوكيل واجهة OpenClaw الطرفية المرفقة ببوابته. إزالة OpenClaw ضمن _Remove > AI_ تأخذ خدمة البوابة والتطبيق معها ثم تسأل عما إذا كان يجب أن يذهب `~/.openclaw` أيضًا، بما أن ذلك يحتفظ بدردشاتك وبيانات اعتمادك جنبًا إلى جنب مع OpenClaw نفسه وأوقات تشغيل الإضافات التي ينزلها؛ الافتراضي يحتفظ به، وتثبيت OpenClaw مرة أخرى يلتقطه.

Herdr Desktop هو تطبيق [Herdr](https://herdr.dev) لسطح المكتب: مساحات وعلامات تبويب وألواح طرفيات ووكلاء برمجة يستمرون في العمل في نواته عندما تغلق النافذة. يأتي من مثبّت Herdr الخاص بدلًا من حزمة، لذا يعيش في `~/.local/share/herdr-app`، ويجلب نواته في `~/.local/bin/herdr-core` عندما لا تمتلك واحدًا بعد، ويحدّث كليهما نفسه. يجلس بجوار أمر `herdr` الذي تشحنه Omarchy على `Super + Ctrl + Return` بدلًا من استبداله، ويحصل على مفاتيح ذلك الأمر المباشرة: `Alt + Return` و`Alt + Shift + Return` يقسمان لوحًا لأسفل أو يمينًا، و`Alt + Escape` يغلقه، و`Ctrl + Alt + Arrow` يتنقل بين الألواح، و`Alt + 1..9` و`Alt + Left/Right` يختاران علامة تبويب، و`Alt + Up/Down` يتنقلان بين المساحات. `Ctrl + 1..9` يختار مساحة و`Alt + Shift + Up/Down` يخطوان عبر الوكلاء. تبقى مفاتيح بادئة `Ctrl + Space` طرفية فقط، بما أن التطبيق لا يمكنه الاحتفاظ بمفتاح Ctrl عادي لتسلسل. تكتب Omarchy هذه إلى `~/.config/herdr-app/keys.json`، ويعيد `omarchy-refresh-herdr-app` وضعها. تثبيته يختار سمة Omarchy لـ Herdr، التي تتبع سمة Omarchy الخاصة بك من ذلك الحين. يحتفظ Herdr بسمة واحدة لوضع الضوء وواحدة للوضع الداكن، لذا بعد التبديل بين سمة Omarchy داكنة وخفيفة، اختر Omarchy في منتقي سمة Herdr مرة أخرى للوضع الآخر.

يعمل T3 Code من إصدار AppImage الرسمي في `~/.local/share/t3code` بدلًا من حزمة، لذا يحدّث نفسه. تثبيته يسأل عما إذا كنت تريد البدء على قناة Stable أو Nightly؛ بدّل لاحقًا في إعدادات T3 Code. تعيش خيوطك وإعداداتك في `~/.t3`، وإزالة T3 Code ضمن _Remove > AI_ تأخذها معها.

### النماذج المحلية

شغّل نموذجًا مفتوحًا على جهازك لوكلاء البرمجة. تبقى موجهاتك وشفرتك على الجهاز؛ لا شيء يتم إرساله إلى النموذج يغادره. ابدأ بـ:

```bash
omarchy models use best text
```

يجهّز ذلك أفضل نموذج نصي لهذا الجهاز، من النوع الذي يستخدمه وكلاؤك. نماذج الصور والفيديو والموسيقى لها أفضل خاصتها: `omarchy models use best image` أو `video` أو `music`. شغّل `omarchy models use best` لرؤية اختيار كل نوع لهذا الجهاز.

أو افتح لوحة النماذج المحلية من أيقونة البريق في الشريط العلوي، بجوار أيقونة الوكلاء، أو بـ Super + Ctrl + Shift + X، واختر +. تظهر الأيقونة عندما يناسب نموذج هذا الجهاز. Podman، الذي يشغّل النماذج، يأتي مع Omarchy، كما تأتي مجموعة أدوات حاويات NVIDIA على جهاز NVIDIA، والتي تمنحها GPU؛ إذا كان أي منهما مفقودًا، فإن الإعداد الأول يثبّته. ثم تختار Omarchy النموذج الموصى به لهذا الجهاز، تنزّله، وتبدأه. توقع تنزيل عشرات GB ومعظم ذاكرة الجهاز قيد الاستخدام أثناء تشغيل النموذج: Flash Next يستخدم حوالي 100 GiB مع سياقه الكامل 256K. إذا احتفظت نماذج أخرى بالذاكرة التي يحتاجها، يتم إعداده متوقفًا، جاهزًا للبدء بمجرد إيقاف واحد. يتوقف النموذج عند تسجيل الخروج؛ أوقفه بنفسك عندما تحتاج الذاكرة لشيء آخر.

يعرض `omarchy models list` الخيارات ويوضح لماذا لا يناسب بعضها. لإعداد واحد آخر، شغّل `omarchy models use <recipe>`. اليوم، `qwen3.8-flash-next-gufo` و`qwen3.8-27b-gufo` متاحان لأجهزة Strix Halo بسعة 128 GB؛ يستخدم 27B حوالي 40 GiB، لذا يترك مساحة لعمل آخر. على كمبيوتر محمول 64 GB مع Arc B390 من Intel، يعمل `qwen3.6-35b-a3b-llamacpp` في حوالي 30 GiB. تصل وصفات وتوصيات جديدة مع `omarchy update`، عبر الحزمة.

يحصل كل نموذج تجهّزه على سطره الخاص في لوحة النماذج المحلية: شغّل لبدئه، أوقف لإيقافه وتحرير ذاكرته، وزر الطرفية لفتح وكيلك عليه. عبر الأعلى، يظهر شريط كيف يتم تقسيم ذاكرة الجهاز بين Omarchy نفسه (النظام وتطبيقاتك)، وكل نموذج قيد التشغيل، وما هو حر. أشر إلى نموذج متوقف ويظهر الشريط ما إذا كان يناسب، أو كم ينقصه. يمكن تشغيل عدة في وقت واحد عندما تناسب الذاكرة معًا؛ إذا لم يناسب واحد، تقول Omarchy أي نموذج قيد التشغيل يجب إيقافه. اسحب الأسطر بشعارها لإعادة ترتيبها، واضغط Delete على سطر مختار لإزالة نموذج وتنزيله.

يحصل كل نموذج تجهّزه أيضًا على إدخاله الخاص في مشغّل التطبيقات، تحت اسم النموذج ومع شعار صانعه، بالطريقة التي يضيف بها تسجيل الدخول إلى Claude أو Codex أو Grok واحدًا. يفتح وكيلك على ذلك النموذج، ويبدأ النموذج أولًا إذا لم يكن قيد التشغيل: تظهر الطرفية تحميله وتسلّم إلى الوكيل بمجرد أن يكون جاهزًا. إزالة نموذج تزيل إدخاله.

ليس كل نموذج للبرمجة. نماذج الصور والفيديو والموسيقى تفتح في Fantasi بدلًا من ذلك، تطبيق Omarchy لصنع الصور والفيديو والموسيقى مع نموذج يعمل على هذا الجهاز، من إدخال مشغّلها ومن سطرها في لوحة النماذج المحلية.

يستمر النموذج في العمل تمامًا كما تم إعداده، لذا لا يعيد تحديث Omarchy تشغيل واحد أبدًا تحت وكلائك. عندما تمتلك Omarchy وقت تشغيل أحدث أو أوزانًا أحدث لنموذج جهّزته، يعرض سطره زر تحديث: اضغطه ويتم إعداد النموذج مرة أخرى في الخلفية، مع تنزيل ما تغير فقط، ويعيد التشغيل على الإصدار الجديد. نموذج كان متوقفًا يبقى متوقفًا. `omarchy models update` يفعل الشيء نفسه لكل نموذج من طرفية.

من سطر الأوامر، `omarchy models start <recipe>` و`omarchy models stop <recipe>` يفعلان الشيء نفسه، و`omarchy models status` يعرض كل نموذج، و`omarchy agent --local` يفتح وكيلك الافتراضي على آخر نموذج بدأته. يمكن لـ pi وOpenCode وQwen Code استخدام واحد؛ مع أي افتراضي آخر يفتح في pi، أو في OpenCode إذا لم يكن لديك pi. يسرد pi أيضًا كل نموذج جهّزته، وتلك على أجهزة قمت بإقرانها، في منتقي نماذجه الخاص، بحيث يصل إليها `pi` العادي أيضًا. أي عميل متوافق مع OpenAI يمكنه الاتصال أيضًا: يعرض `status` عنوان كل نموذج (الأول هو `http://127.0.0.1:11435/v1`)، اسم الوصفة هو النموذج، والمفتاح في `~/.config/omarchy/agent-local/key`.

يحذف `omarchy models remove <recipe>` نموذجًا والتنزيلات التي لا يستخدمها نموذج آخر.

يتم تصنيف أوقات التشغيل التابعة لجهات خارجية مع ناشرها. تشغّل Omarchy كل نموذج بدون وصول إلى الشبكة.

### نماذج LLM المحلية

توصي Omarchy بطريقتين لتشغيل نماذج LLM محلية: LM Studio وOllama. يوفر LM Studio واجهة رسومية للعثور على نماذج ذات أوزان مفتوحة وتثبيتها وتشغيلها. إنها طريقة رائعة للبدء بسهولة. يقدم Ollama CLI للقيام بذلك بالمثل. لكن إذا كنت جديدًا على النماذج المحلية، سأبدأ بـ LM Studio. يمكنك تثبيت أي منهما ضمن _Install > AI_ في قائمة Omarchy.

### مهارات Omarchy

تساعد مهارات الوكيل الذكاء الاصطناعي على استخدام أدوات محددة بطريقة محددة، وتشحن Omarchy سبعًا منها. تغطي مهارة omarchy تخصيص النظام، مثل تعديل تكوين Hyprland الخاص بك أو تعديل الشريط. تغطي omarchy-make-theme وomarchy-make-plugin وomarchy-make-app وomarchy-make-game صنع شيء جديد، وتغطي omarchy-contribute الإبلاغ عن خطأ أو إرسال إصلاح إلى المصدر، وتعمل omarchy-diagnose-crash عبر تفريغ نواة عطل. يتم ربطها رمزيًا في أدلة المهارات لـ Claude Code (`~/.claude/skills`) وCodex (`~/.codex/skills`) وPi (`~/.pi/agent/skills`) وAntigravity (`~/.gemini/config/skills`) وHermes (`~/.hermes/skills` وكل `~/.hermes/profiles/*/skills`)، وموقع `~/.agents/skills` العام، بحيث تلتقطها معظم أدوات التشغيل تلقائيًا. مجلد مهارة خاص بك بنفس الاسم له الأسبقية.

لكن يجب أن تعامل هذه المهارات على أنها تجريبية. نماذج مختلفة ستستخدمها لتأثير مختلف. من الأفضل التشغيل في وضع التخطيط أولًا، بحيث يكون لديك فكرة عما يرغب الوكيل في تغييره. ثم كن مستعدًا لاستعادة التغييرات أو حتى استدعاء `omarchy reinstall configs`، إذا أحدث الوكيل فوضى في كل شيء.
