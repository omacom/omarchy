# الذكاء الاصطناعي

يتضمّن Omarchy مشغّلات لوكلاء البرمجة أدناه من دون اختيار وكيل افتراضي نيابة عنك. شغّل أمرًا لتثبيت CLI الخاصة به عند أول استخدام، ثم أكمل المصادقة عند مطالبتك بذلك. Hermes هو الاستثناء: لا يُثبَّت أي شيء له عند أول استخدام، واختياره يُثبِّت Hermes Desktop، كما يوضّح قسم _Desktop apps_ أدناه.

### تثبيت الوكلاء وتحديثهم

باستثناء Hermes، يستخدم هؤلاء الوكلاء التثبيت الكسول عبر mise: أول تشغيل يُثبِّت CLI، والتشغيلات اللاحقة تعيد استخدامها. ويتحقق mise أيضًا من وجود إصدار جديد لوكيل مثبّت مرة واحدة على الأكثر كل أربع ساعات، إما قبل بدئه مباشرة وإما في الخلفية عند موجّه shell. وإذا فشل ذلك التحديث أو كنت غير متصل، يعمل الإصدار المثبّت. يُحدِّث `omarchy update` الوكلاء المثبّتين مع بقية Omarchy، ويُحدِّث `mup` الأدوات التي يديرها mise فقط.

لا يُحدِّث المحدّث الخاص بالوكيل نفسه، مثل `claude update` أو `codex update` أو زر تحديث داخل تطبيق، التثبيت الذي يديره mise. يفشل `codex update`، وقد يفيد `claude update` بنجاحه بينما يُثبِّت نسخة منفصلة لا يتتبعها mise. إذا كنت تفضّل استخدام المثبّت والمحدّث الأصليين للوكيل، فأضفه إلى `disable_tools`؛ راجع [Preinstalled CLI tools](18-development-tools.md#preinstalled-cli-tools).

لتثبيت جميع الأدوات الكسولة المهيأة قبل أن تحتاج إليها، شغّل `mise install --include-lazy`. يشمل هذا أدوات CLI الافتراضية الأخرى في Omarchy إضافة إلى الوكلاء. راجع [Preinstalled CLI tools](18-development-tools.md#preinstalled-cli-tools) لتثبيت أداة واحدة أو استخدام تثبيتك الخاص.

يُثبَّت `grok` عبر حزمة `grok` الرسمية من mise، بالطريقة نفسها المتبعة مع `claude` و`codex`. شغّل `grok`، أو اختره ضمن _Setup > Defaults > Agent_. تجاوز مثبّت `curl | bash` على x.ai. فذلك المسار يضع نسخة ثانية في `~/.grok/bin`، ويقدّمها في `PATH`، ويكتب فوق غلاف Omarchy.

يفتح `dsh` واجهة المتصفح الخاصة به على `127.0.0.1:3080`، مع مجلد التشغيل كمساحة عمل افتراضية. لا تقبل واجهة المتصفح الخاصة به موجّه بدء، لذا يفتح `omarchy agent prompt` الواجهة مع وجود الموجّه في الحافظة للصقه. يبدأه Omarchy باستخدام إعداد أذونات عدم الموافقة من DeepSeek. يرفع DeepSeek Harness سجلات الجلسات إلى DeepSeek عند استخدامك API النموذج الرسمي الخاص به؛ أوقف ذلك ضمن _Settings > General > Upload Session Log_ في واجهة المتصفح الخاصة به. وتُرفع الملاحظات التي ترسلها إليه مع الجلسة أيضًا، ما لم تبدأه باستخدام `DSH_TELEMETRY_MODE=DISABLED`.

### الوكيل الافتراضي

اختر وكيلك الافتراضي باستخدام `omarchy default agent <name>` أو ضمن _Setup > Defaults > Agent_ في قائمة Omarchy (`Super + Space`). وإذا لم يكن الوكيل مثبّتًا بعد، فإن اختياره يُثبِّته أولًا. سيدعوك Omarchy جديد إلى اتخاذ هذا الخيار بإشعار يظهر مرة واحدة.

يؤدي اختيار Claude أيضًا إلى محاولة إعداد إضافة المتصفح الخاصة به من أجل Chromium وChrome وBrave وBrave Origin وEdge. ينطبق إعداد الإضافة على جميع المستخدمين وقد يطلب كلمة مرور النظام؛ ومع ذلك فإن الإلغاء أو فشل تثبيت الإضافة لا يمنعان اختيار Claude وتشغيله. أعد تشغيل متصفحك، وفعّل الإضافة إذا طُلب منك ذلك، وسجّل الدخول إلى Claude لإنهاء ربطها. شغّل `/chrome` في Claude للتحقق من الاتصال. لا يدعم Firefox وZen هذه الإضافة. وإذا كان Claude وكيلك الافتراضي بالفعل قبل إضافة هذا الإعداد، فاختره مجددًا لتثبيت الإضافة.

بمجرد أن تختار، يطلق `Super + Shift + Ctrl + A` الوكيل الافتراضي في نافذة طرفية مخصصة (أو يظهر المنتقي إذا لم تختر بعد). ويمكنك أيضًا تشغيله مباشرة في مهمة باستخدام `omarchy agent prompt "Review this project"`. لا يقبل Freebuff وDeepSeek Harness موجّه بدء، لذا يفتحان مع وجود الموجّه في الحافظة للصقه بدلًا من ذلك. يعمل الوكلاء الذين يُشغَّلون بهذه الطريقة من دون مراقبة في أوضاع عدم التوقف للسؤال الخاصة بكل منهم، لذا كن مستعدًا لأن يقوموا بأشياء فعلًا! لا يمتلك MiniMax Code مثل هذا الوضع لجلساته التفاعلية، لذا يطلب الأذونات كالمعتاد. وبما أن الوكلاء يرفضون تذكّر الثقة لمجلدك الرئيسي، فإن التشغيلات من `$HOME` تبدأ في `~/Work` بدلًا من ذلك.

توجد اختصارات طرفية أيضًا: يشغّل `a` الوكيل الافتراضي مضمّنًا في الطرفية الحالية، بينما يبدأ `c` و`cx` و`cy` تشغيل OpenCode وClaude Code وCodex مباشرة (في أوضاع الموافقة التلقائية الخاصة بها أيضًا). تتزامن تغييرات السمة مع الوكلاء أيضًا: يتبع Claude Code وPi وOpenCode وHermes (بمجرد أن يُثبِّته Omarchy) جميعها التغيير عندما تبدّل سمة Omarchy.

### لوحة الوكلاء

يوجد في الشريط العلوي رمز للوكلاء. قبل أن تُعدّ وكيلًا، ترشدك لوحته خلال تسجيل الدخول إلى Claude أو Codex أو Grok، ويصبح الأول منها وكيلك الافتراضي. بعد ذلك، تضع اللوحة كل اشتراك في صفحة واحدة: كل وكيل وحساب مع خطته، وعدّاد لكل من حدّي جلسته البالغة 5 ساعات وحدّه الأسبوعي مع الوقت المتبقي حتى إعادة تعيينه (مرّر المؤشر لعرض النسبة الدقيقة)، أو الرصيد المسبق الدفع المتبقي، تحت سطر يتناوب عبر ما استخدمته عبرها جميعًا، مثل الرموز هذا الأسبوع ونموذجك الأكثر استخدامًا. وضمن _Make something_ تقدّم موجّهات بداية لصنع سمة أو إضافة أو تطبيق جديد تسلّم المهمة إلى وكيلك الافتراضي. تُبنى التطبيقات بالطريقة نفسها التي تُبنى بها تطبيقات Omarchy الخاصة Hype وMonologue وOmacut، باستخدام C++ وQt Quick، باتباع مهارة وكيل omarchy-app، وتأتي المترجمات وأجزاء Qt التي تحتاجها مثبّتة. تتم تغطية Claude Code وCodex وGrok وKimi وCursor ومخصص Grok Bot الخاص به وGitHub Copilot وMuse وAntigravity وKimchi وDevin جاهزة مع حدودها، وتُظهر Hermes وMistral Vibe وQwen Code جلساتها ورموزها بمجرد أن تستخدمها. وتظهر أيضًا خطط المزوّدين ومفاتيحهم التي تستخدمها عبر pi أو omp أو opencode: OpenCode Zen وGo وخطة Z.ai GLM Coding Plan وOllama Cloud وخطة MiniMax Token Plan وSynthetic مع حدودها؛ وFireworks وOpenRouter وDeepSeek مع أرصدتها المسبقة الدفع؛ والنماذج التي تشغّلها على أجهزتك الخاصة ضمن Local models. يُحسب كل وكيل مرة واحدة، تحت من يفوتره، مهما كان عدد أدوات التشغيل التي تقوده عبرها.

انقر بالزر الأيسر على رمز الشريط لفتح اللوحة، وانقر بالزر الأيمن لتشغيل وكيلك الافتراضي. تُعاد إنشاء سجلات الاستخدام التي تقف وراءها كل 15 دقيقة بواسطة `omarchy agent usage-update`، ويمكن للوحة حتى دمج الاستخدام من أجهزتك الأخرى عبر مجلد متزامن. اطّلع على README ضمن `$OMARCHY_PATH/shell/plugins/agents/` للإعدادات الكاملة.

### عدة اشتراكات

إذا كنت تدفع مقابل أكثر من خطة واحدة من Claude أو Codex أو Grok — خطة Max شخصية وخطة عمل، على سبيل المثال — يمكن لـ Omarchy إبقاءها جميعًا مسجّلة الدخول والتنقل بينها. أضف اشتراكًا باستخدام + في لوحة الوكلاء، التي ترشدك خلال ذلك هناك مباشرة، أو باستخدام `omarchy agent account add claude Work` (أو `codex` أو `grok`). سيُثبِّت CLI إذا كانت مفقودة. يسجّل الحساب الأول لمزوّد الدخول عبر متصفحك العادي، تمامًا حيث تبحث CLI دائمًا. ويسجّل كل حساب بعد ذلك الدخول عبر نافذة خاصة، حتى لا يُلتقط بالخطأ الحساب الذي سجّل متصفحك الدخول إليه بالفعل؛ سجّل الدخول هناك بالحساب الذي تضيفه، وأغلق أي نافذة خاصة فتحتها بالفعل أولًا. لا تسجّل الخروج من CLI أبدًا للقيام بذلك: فتسجيل الخروج يُبطل تسجيل الدخول المحفوظ، وسيتعيّن إضافة ذلك الحساب مجددًا.

لنسخ تسجيلات دخول اشتراكاتك إلى جهاز Omarchy آخر عبر SSH، شغّل `omarchy agent account copy user@laptop`. يوفّر المرسل مستقبلًا مؤقتًا عندما لا يكون لدى الوجهة واحد مثبّت، بحيث يمكن لأجهزة Omarchy الأقدم استقبال الحسابات من دون تحديث. تأخذ المستقبلات المثبّتة الأسبقية. ينسخ هذا جميع اشتراكات Claude وCodex وGrok؛ أضف أسماء المزوّدين لتحديدها، كما في `omarchy agent account copy laptop claude`. تتطابق أسماء الحسابات ومعرّفات الأوامر مع المصدر، بما يشمل الحسابات الموجودة بالفعل على الوجهة. وتتلقى حسابات الوجهة غير ذات الصلة لاحقة رقمية إذا تعارضت أسماؤها، وتبقى الإعدادات والمهارات والإضافات وسجل المحادثات محلية لكل جهاز.

تُحفظ بيانات اعتماد الوجهة الموجودة. الحساب المصدري الذي سُجّل دخوله هناك بالفعل تتم مزامنة اسمه من دون استبدال بيانات اعتماده؛ وتُضاف الحسابات الأخرى إلى جانبه. لاستبدال بيانات الاعتماد المحفوظة للحسابات المطابقة، استخدم `omarchy agent account copy --replace laptop claude` بعد إنهاء جلسات ذلك الحساب على الوجهة. وتحصل الوجهة الجديدة أيضًا على الحساب النشط وتفضيلات التبديل الخاصة بالمصدر؛ بينما تحتفظ الوجهة القائمة بتفضيلاتها الخاصة.

تسافر بيانات الاعتماد عبر SSH وتُخزَّن في ملفات خاصة على الوجهة، لذا انسخ فقط إلى أجهزة تثق بها. هذه نسخة لمرة واحدة، وليست مزامنة مستمرة. يمكن لجهاز آخر تدوير رموز تحديث Codex، تاركًا تسجيل دخول منسوخًا بحاجة إلى التجديد؛ وتبقى تسجيلات الدخول المنفصلة الخيار الأكثر موثوقية للاستخدام المتزامن على عدة أجهزة. راجع [Codex's account authentication guidance](https://developers.openai.com/codex/auth/ci-cd-auth).

حساب واحد لكل مزوّد نشط، وكل جلسة جديدة تبدأ به: `cx` و`cy` و`claude` أو `codex` أو `grok` العادية، وأي شيء يُشغَّل عبر `omarchy agent`، والبرامج النصية والمحررات التي تجد CLI على `PATH`. بدّل باستخدام `omarchy agent account use work` (وعُد باستخدام `omarchy agent account use main`)، أو في اللوحة بالضغط على رقم حساب ثم `Enter` (أو بالنقر على زر Use الخاص به). تبقى الجلسات قيد التشغيل بالفعل على الحساب الذي بدأت به. ويُشارك سجل المحادثات والإعدادات والمهارات والإضافات عبر الحسابات، لذا يستأنف `claude --continue` في المجلد نفسه من حيث توقفت على الحساب الجديد.

مع وجود أكثر من حساب، تعرض اللوحة حدود كل حساب جنبًا إلى جنب، مع وضع علامة على الحساب النشط. يُعلمك Omarchy افتراضيًا عندما يتجاوز الحساب النشط 95% من حدّ ما، والنقر على الإشعار يبدّل إلى الحساب صاحب أكبر هامش متاح. مرّر المؤشر فوق سطر حساب في اللوحة وانقر على Autoswitch الذي يظهر بجانب Use (أو اضغط `m`)، أو شغّل `omarchy agent account mode auto`، لجعله يبدّل من تلقاء نفسه بدلًا من ذلك؛ وبينما هو مفعّل، يحلّ Autoswitch محلّ Use، والنقر عليه مجددًا يعيدك إلى الإشعار. أضف رقمًا لتغيير العتبة، كما في `omarchy agent account mode auto 90`. إذا تجاوز كل حساب العتبة، فسيصلك إشعار بذلك مرة واحدة، مع بيان أي حساب سيتحرر أولًا. وبينما يكون حساب نشط ضمن 15 نقطة من عتبته (80% عند الإعداد الافتراضي)، تُفحص حدوده كل ثلاث دقائق بدلًا من كل 15 دقيقة.

يعرض `omarchy agent account list` كل حساب وحدوده الأخيرة، وينسى `omarchy agent account remove work` حسابًا واحدًا، ويعيد `omarchy agent account rename primary Hey` تسمية حساب (أو انقر على اسم حساب في اللوحة). تعمل هذه الأوامر على حسابات وكيلك الافتراضي؛ وللوصول إلى المزوّد الآخر، سمّه أولًا، كما في `omarchy agent account use codex side`. تسجيل الدخول الذي كان لديك بالفعل في `~/.claude` أو `~/.codex` هو حساب _Main_ ويبقى حيث هو. يمكن لحساب تُرك من دون استخدام لأكثر من ثماني ساعات تقريبًا أن يُظهر _Sign-in required_؛ انقر عليه لتسجيل دخول ذلك الحساب مجددًا في اللوحة مباشرة، أو ابدأ جلسة فيه، ما يجدّد تسجيل الدخول من تلقاء نفسه. خوادم MCP التي كانت لديك عندما أُضيف حساب ما تنتقل معه إليه، لكن الخوادم التي تضيفها لاحقًا باستخدام `claude mcp add` تصل فقط إلى الحساب الذي أضفتها فيه. لا يتبع Claude Desktop والأدوات المهيأة بمسار مطلق إلى ثنائي CLI عملية التبديل. يأخذ `CLAUDE_CONFIG_DIR` أو `CODEX_HOME` أو `GROK_HOME` الصريح الأسبقية على الحساب المختار.

### تشخيص الانهيارات

يراقب Omarchy في systemd-coredump انهيارات العمليات. عندما يحدث خطأ تجزئة لشيء ما، ستتلقى إشعار «Process crashed» — انقر عليه، وسيُسلَّم الانهيار إلى وكيلك الافتراضي مع مهارة diagnose-crash الخاصة بـ Omarchy، التي ترشد الوكيل خلال إثبات الوقائع من تفريغ النواة وتقرير ما إذا كان الانهيار يستحق الإبلاغ عنه إلى المطوّرين. يمكنك أيضًا تشغيلها يدويًا مقابل أي PID من `coredumpctl list` باستخدام `omarchy agent crash <pid>`.

المراقبة مفعّلة افتراضيًا. أوقفها ضمن _Trigger > Toggle > Crash Capture_ (أو باستخدام `omarchy toggle crash-capture`) وستتوقف الإشعارات؛ ويستمر `omarchy agent crash <pid>` في العمل يدويًا.

يمكن أيضًا إسكات الانهيارات برنامجًا واحدًا في كل مرة، وهو ما يعرضه عليك التشخيص في النهاية. يوقف `omarchy crash mute hyprland` الإشعارات لذلك البرنامج فقط، ويعيدها `omarchy crash mute hyprland off`، ويعرض `omarchy crash mute` بمفرده ما أسكتّه. يقبل مسار الملف الثنائي بسرور مماثل لاسمه، لذا فإن `omarchy crash mute /usr/bin/hyprland` يفعل الشيء نفسه. ضع اسمًا يحتوي على مسافة بين علامتي اقتباس، كما في `omarchy crash mute 'Some App'`. يستمر كل شيء آخر في الإشعار، ويستمر البرنامج المُسكَت في الانهيار — فهذا يخفي التذكير، ولا يصلح أي شيء.

### تطبيقات سطح المكتب

تحمل قائمة _Install > AI_ أيضًا بعض تطبيقات الذكاء الاصطناعي الرسومية: تطبيق ChatGPT لسطح المكتب، وتطبيق Claude لسطح المكتب (إصدار Anthropic التجريبي لنظام Linux، مع علامات تبويب Chat وCowork وClaude Code)، وGrok Bot للدردشة مع نماذج xAI، وHermes Desktop، وOpenClaw، وتطبيق Perplexity لسطح المكتب، وT3 Code. Grok Bot هو تطبيق الدردشة لسطح المكتب. أما وكيل البرمجة فهو أمر `grok`.

Hermes Desktop هو التطبيق الذي ينبغي أن تعرفه، لأن الجهاز الواحد لديه Hermes واحد، وهو Hermes الخاص بالتطبيق: لا يُثبَّت Hermes أبدًا إلا عبر التطبيق، وأمر `hermes` الذي يشغّله الوكيل الافتراضي هو أمر التطبيق. يؤدي اختيار Hermes كوكيل افتراضي إلى تثبيت الشيء نفسه الذي يثبّته إدخال _Install > AI_: الحزمة، وبيئة تشغيل Hermes ضمن `~/.hermes` أعدّها مثبّت Hermes نفسه، وهو ما يستغرق بضع دقائق في المرة الأولى. بيئة التشغيل تلك هي Hermes الواحدة التي يستخدمها أمر `hermes` الطرفي والوكيل الافتراضي والتطبيق جميعًا، وتحدّث نفسها باستخدام `hermes update` بدلًا من انتظار إصدار Omarchy. يؤدّي تثبيتها أيضًا إلى منح Hermes سمة Omarchy كجلد باسم `omarchy`، تتبعه كل أسطح Hermes أثناء تبديلك السمات؛ اختر جلدًا آخر ضمن إعدادات Appearance في Hermes أو باستخدام `/skin` إذا كنت تفضّل ألا يفعل ذلك، وسيترك Omarchy ذلك الخيار وشأنه. تؤدي إزالة التطبيق ضمن _Remove > AI_ إلى إغلاق Hermes أولًا، بما يشمل البوابة، وتأخذ بيئة التشغيل تلك معها، وتحتفظ بدردشاتك وذكرياتك والمهارات التي كتبها Hermes لنفسه ما لم تطلب غير ذلك: فهي تسأل، مع الإجابة الافتراضية لا، عما إذا كان يجب أن تذهب تلك البيانات وإعدادات اتصالك أيضًا.

تجربة OpenClaw على سطح المكتب هي واجهة Control UI الخاصة به، التي تُفتح كتطبيق ويب مدعوم ببوابته المحلية الخاصة. يعيش OpenClaw في `~/.openclaw` ويحدّث نفسه: استخدم زر «Update Gateway» في Control UI أو شغّل `openclaw update`، وستُعاد تشغيل البوابة على الإصدار الجديد. يختار Omarchy فقط الإصدار الذي يبدأ منه تثبيت جديد. تؤدي إزالة OpenClaw ضمن _Remove > AI_ إلى أخذ خدمة البوابة والتطبيق معها ثم تسأل عما إذا كان يجب أن يذهب `~/.openclaw` أيضًا، بما أنه يحتفظ بدردشاتك وبيانات اعتمادك إلى جانب OpenClaw نفسه وبيئات تشغيل الإضافات التي ينزّلها؛ الإعداد الافتراضي يحتفظ به، وتثبيت OpenClaw مجددًا يلتقطه من جديد.

يعمل T3 Code من إصدار AppImage الرسمي الخاص به في `~/.local/share/t3code` بدلًا من حزمة، لذا يحدّث نفسه. يسألك تثبيته عما إذا كنت تريد البدء على قناة Stable أم Nightly؛ بدّل لاحقًا في إعدادات T3 Code. تعيش سلاسل محادثاتك وإعداداتك في `~/.t3`، وتأخذها إزالة T3 Code ضمن _Remove > AI_ معها.

### النماذج المحلية

شغّل نموذجًا مفتوحًا على جهازك الخاص لوكلاء البرمجة لديك. تبقى موجّهاتك وشفرتك على الجهاز؛ ولا يغادر أي شيء يُرسل إلى النموذج الجهاز. ابدأ باستخدام:

```bash
omarchy agent local use best
```

أو، في لوحة الوكلاء في الشريط العلوي، اختر + ثم Local AI، التي تظهر عندما يناسب نموذج ما هذا الجهاز. في المرة الأولى، يُثبِّت هذا Podman، الذي يشغّل النماذج، وعلى جهاز NVIDIA مجموعة أدوات حاويات NVIDIA، التي تمنحها GPU. بعد ذلك يختار Omarchy النموذج الموصى به لهذا الجهاز، وينزّله، ويبدأه. توقّع تنزيلًا بعشرات GB وبقاء معظم ذاكرة الجهاز قيد الاستخدام أثناء عمل النموذج: يستخدم Flash Next نحو 100 GiB مع سياقه الكامل البالغ 256K. وإذا كانت نماذج أخرى تحتفظ بالذاكرة التي يحتاج إليها، يُعدّ متوقفًا، جاهزًا للبدء بمجرد أن توقف أحدها. يتوقف النموذج عند تسجيل الخروج؛ أوقفه بنفسك عندما تحتاج إلى الذاكرة لشيء آخر.

يعرض `omarchy agent local list` الخيارات ويوضّح سبب عدم ملاءمة بعضها. لإعداد نموذج آخر، شغّل `omarchy agent local use <recipe>`. اليوم، يتوفر `qwen3.8-flash-next-gufo` و`qwen3.8-27b-gufo` لأجهزة Strix Halo بسعة 128 GB؛ يأخذ نموذج 27B نحو 40 GiB، لذا يترك مساحة لأعمال أخرى. تصل الوصفات والتوصيات الجديدة مع `omarchy update`، عبر الحزمة.

يحصل كل نموذج تُعدّه على سطر خاص به في لوحة الوكلاء، بجانب اشتراكاتك: تشغيل لبدئه، وإيقاف مؤقت لإيقافه وتحرير ذاكرته، وزر الطرفية لفتح وكيلك عليه. يمكن أن يعمل عدة نماذج في وقت واحد عندما تتسع في الذاكرة معًا؛ وإذا لم يتسع أحدها، يقول Omarchy أي نموذج قيد التشغيل يجب إيقافه. اسحب الأسطر لإعادة ترتيبها، واضغط Delete على سطر محدد لإزالة نموذج وتنزيله.

من سطر الأوامر، يفعل `omarchy agent local start <recipe>` و`omarchy agent local stop <recipe>` الشيء نفسه، ويعرض `omarchy agent local status` كل نموذج، ويفتح `omarchy agent --local` وكيلك الافتراضي على آخر نموذج بدأته (pi إذا كان وكيلك الافتراضي لا يمكنه استخدام نموذج محلي). يمكن لأي عميل متوافق مع OpenAI الاتصال أيضًا: يعرض `status` عنوان كل نموذج (الأول هو `http://127.0.0.1:11435/v1`)، واسم الوصفة هو النموذج، والمفتاح موجود في `~/.config/omarchy/agent-local/key`.

يحذف `omarchy agent local remove <recipe>` نموذجًا والتنزيلات التي لا يستخدمها أي نموذج آخر.

تُوسم بيئات التشغيل الخارجية بناشرها. يشغّل Omarchy كل نموذج من دون وصول إلى الشبكة.

### نماذج LLM المحلية

يوصي Omarchy بطريقتين لتشغيل نماذج LLM محلية: LM Studio وOllama. يوفّر LM Studio واجهة رسومية للعثور على النماذج ذات الأوزان المفتوحة وتثبيتها وتشغيلها. إنها طريقة رائعة للانطلاق بسهولة. ويقدّم Ollama واجهة CLI للقيام بذلك على نحو مماثل. لكن إذا كنت جديدًا على النماذج المحلية، فسأبدأ بـ LM Studio. يمكنك تثبيت أي منهما ضمن _Install > AI_ في قائمة Omarchy.

### مهارة Omarchy

تساعد مهارات الوكلاء الذكاء الاصطناعي على استخدام أدوات محددة بطريقة محددة، ويأتي Omarchy مع مهارة افتراضية لتكييف النظام. مثل تعديل إعدادات Hyprland، أو ضبط الشريط، أو حتى إنشاء سمة جديدة من الصفر. تُربط رمزيًا في مجلدات مهارات Claude Code (`~/.claude/skills`) وCodex (`~/.codex/skills`) وPi (`~/.pi/agent/skills`) وAntigravity (`~/.gemini/config/skills`) وHermes (`~/.hermes/skills` وكل `~/.hermes/profiles/*/skills`)، والموقع العام `~/.agents/skills`، لذا تلتقطها معظم أدوات التشغيل تلقائيًا.

لكن يجب أن تعامل هذه المهارة على أنها تجريبية. ستستخدمها نماذج مختلفة بدرجات مختلفة من الفعالية. من الأفضل التشغيل في وضع التخطيط أولًا، حتى تكون لديك فكرة عما يود الوكيل تغييره. ثم كن مستعدًا للتراجع عن التغييرات أو حتى استدعاء `omarchy reinstall configs`، إذا أحدث الوكيل فوضى في كل شيء.
