# الذكاء الاصطناعي

يتضمن Omarchy مشغّلات لوكلاء البرمجة أدناه دون أن يختار لك واحدًا افتراضيًا. شغّل أمرًا لتثبيت CLI الخاص به عند أول استخدام، ثم قم بالمصادقة عند مطالبتك بذلك. Hermes هو الاستثناء: لا يُثبَّت أي شيء له عند أول استخدام، واختياره يثبّت Hermes Desktop، كما يوضح قسم _تطبيقات سطح المكتب_ أدناه.

### تثبيت الوكلاء وتحديثهم

باستثناء Hermes، يستخدم هؤلاء الوكلاء التثبيت الكسول من mise: يثبّت أول تشغيل CLI، وتعيد التشغيلات اللاحقة استخدامه. يتحقق mise أيضًا من وجود إصدار جديد لوكيل مثبّت مرة واحدة على الأكثر كل أربع ساعات، قبل بدئه مباشرة أو في الخلفية عند موجّه shell. إذا فشل ذلك التحديث أو كنت غير متصل بالإنترنت، يعمل الإصدار المثبّت. يحدّث `omarchy update` الوكلاء المثبّتين مع بقية Omarchy، ويحدّث `mup` الأدوات التي يديرها mise فقط.

لا يحدّث محدِّث الوكيل الخاص، مثل `claude update` أو `codex update` أو زر تحديث في تطبيق، التثبيت الذي يديره mise. يفشل `codex update`، وقد يبلّغ `claude update` عن النجاح أثناء تثبيت نسخة منفصلة لا يتتبعها mise. إذا كنت تفضّل استخدام مثبّت الوكيل ومحدِّثه الأصليين، أضفه إلى `disable_tools`؛ راجع [أدوات CLI المثبتة مسبقًا](18-development-tools.md#preinstalled-cli-tools).

لتثبيت جميع الأدوات الكسولة المهيّأة قبل أن تحتاجها، شغّل `mise install --include-lazy`. يشمل هذا أيضًا أدوات CLI الافتراضية الأخرى في Omarchy بالإضافة إلى الوكلاء. راجع [أدوات CLI المثبتة مسبقًا](18-development-tools.md#preinstalled-cli-tools) للاطلاع على تثبيت أداة واحدة أو استخدام تثبيتك الخاص.

يُثبَّت `grok` عبر حزمة `grok` الرسمية من mise، بالطريقة نفسها مثل `claude` و`codex`. شغّل `grok`، أو اختره ضمن _Agent > Harness_. تجنّب مثبّت `curl | bash` على x.ai. يضع ذلك المسار نسخة ثانية في `~/.grok/bin`، ويقدّمها على `PATH`، ويستبدل غلاف Omarchy.

يفتح `dsh` واجهة المتصفح الخاصة به على `127.0.0.1:3080`، مع دليل التشغيل كمساحة عمل افتراضية له. لا تأخذ واجهة المتصفح الخاصة به موجّه بدء، لذا يفتحها `omarchy agent prompt` مع وضع الموجّه في حافظتك للصقه. يبدأه Omarchy مع إعداد أذونات DeepSeek المسبق بعدم طلب الموافقة. يرفع DeepSeek Harness سجلات الجلسات إلى DeepSeek عند استخدامك واجهة برمجة تطبيقات نماذجه الرسمية؛ عطّل ذلك ضمن _Settings > General > Upload Session Log_ في واجهة المتصفح الخاصة به. تُرفع الملاحظات التي ترسلها إليه مع الجلسة أيضًا، ما لم تبدأه بـ `DSH_TELEMETRY_MODE=DISABLED`.

### الوكيل الافتراضي

اختر وكيلك الافتراضي بـ `omarchy default agent <name>` أو ضمن _Agent > Harness_ في قائمة Omarchy (`Super + Space`). إذا لم يكن الوكيل مثبّتًا بعد، فإن اختياره يثبّته أولًا. سيدعوك Omarchy جديد إلى اتخاذ هذا الاختيار بإشعار لمرة واحدة.

يحاول اختيار Claude أيضًا إعداد إضافة المتصفح الخاصة به لـ Chromium وChrome وBrave وBrave Origin وEdge. ينطبق إعداد الإضافة على جميع المستخدمين وقد يطلب كلمة مرور النظام الخاصة بك؛ لا يزال إلغاء تثبيت الإضافة أو فشله يختار Claude ويشغّله. أعد تشغيل متصفحك، وفعّل الإضافة إذا طُلب منك ذلك، وسجّل الدخول إلى Claude لإنهاء توصيلها. شغّل `/chrome` في Claude للتحقق من الاتصال. لا يدعم Firefox وZen هذه الإضافة. إذا كان Claude وكيلك الافتراضي من قبل قبل إضافة هذا الإعداد، اختره مرة أخرى لتثبيت الإضافة.

بمجرد اختيارك، يشغّل `Super + Shift + Ctrl + A` الوكيل الافتراضي في نافذة طرفية مخصصة (أو يعرض المنتقي إذا لم تختر بعد). يمكنك أيضًا تشغيله مباشرة في مهمة بـ `omarchy agent prompt "Review this project"`. لا يأخذ Freebuff وDeepSeek Harness موجّه بدء، لذا يفتحان مع وضع الموجّه في حافظتك للصقه بدلًا من ذلك. يعمل الوكلاء المشغّلون بهذه الطريقة دون مراقبة في أوضاع عدم التوقف للسؤال الخاصة بكل منهم، لذا كن مستعدًا لأن يقوموا بأشياء فعلًا! لا يمتلك MiniMax Code مثل هذا الوضع لجلساته التفاعلية، لذا يطلب الأذونات كالمعتاد. وبما أن الوكلاء يرفضون تذكّر الثقة لدليلك الرئيسي، تبدأ عمليات التشغيل من `$HOME` في `~/Work` بدلًا من ذلك.

توجد اختصارات طرفية أيضًا: يشغّل `a` الوكيل الافتراضي داخل الطرفية الحالية، بينما تبدأ `c` و`cx` و`cy` كلًا من OpenCode وClaude Code وCodex مباشرة (مرة أخرى في أوضاع الموافقة التلقائية الخاصة بها). تتم مزامنة تغييرات السمة مع الوكلاء أيضًا: يتبع كل من Claude Code وPi وOpenCode وHermes (بمجرد أن يثبّته Omarchy) خطاك عند تبديل سمة Omarchy.

### تعليمات وكيلك

تذهب القواعد الشخصية لكل وكيل في `~/.agents/AGENTS.md`، بجوار المهارات المشتركة في `~/.agents/skills`. افتحه ضمن _Agent > Instructions_، والذي يربطه أيضًا بكل harness يحتفظ بملفه العام الخاص به: `~/.claude/CLAUDE.md` و`~/.codex/AGENTS.md` و`~/.pi/agent/AGENTS.md` و`~/.config/opencode/AGENTS.md` و`~/.copilot/copilot-instructions.md` الخاص بـ Copilot، وهكذا. يقرأ Crush وAmp رابط `~/.config/AGENTS.md`، بينما يقرأ omp وKimi وDeepSeek Harness ملف `~/.agents/AGENTS.md` مباشرة. يربط اختيار وكيل افتراضي هذا الملف أيضًا. يصبح ملف تعليمات كان لديك بالفعل هو الملف المشترك إذا لم يكن هناك واحد بعد؛ وإلا يُحتفظ به بجوار الرابط باسم `.bak`. شغّل `omarchy agent instructions` لإعادة الربط بعد تثبيت وكيل آخر.

### لوحة الوكلاء

يحتوي الشريط العلوي على أيقونة للوكلاء. قبل أن تعدّ وكيلًا، ترشدك لوحتها خلال تسجيل الدخول إلى Claude أو Codex أو Grok، ويصبح الأول وكيلك الافتراضي. بعد ذلك، تضع اللوحة كل اشتراك على صفحة واحدة: كل وكيل وحساب مع خطته، ومقياس لكل من حد جلسته البالغة 5 ساعات وحدوده الأسبوعية مع الوقت حتى إعادة تعيينه (مرّر للاطلاع على النسبة المئوية الدقيقة)، أو الرصيد المدفوع مسبقًا المتبقي، تحت سطر يدور عبر ما استخدمته عبر جميعها، مثل عدد الرموز هذا الأسبوع ونموذجك الأكثر استخدامًا. ضمن _Make something_ تقدّم موجّهات بداية لسمة أو إضافة أو تطبيق أو لعبة جديدة تسلّم المهمة إلى وكيلك الافتراضي. تُبنى التطبيقات بالطريقة التي بُنيت بها تطبيقات Omarchy الخاصة Hype وMonologue وOmacut، بلغة C++ وQt Quick، باتباع مهارة الوكيل omarchy-make-app، ويأتي المجمّع وأجزاء Qt التي تحتاجها مثبّتة. الألعاب هي صفحة three.js واحدة في `~/Games/vibes`، باتباع مهارة الوكيل omarchy-make-game، وتفتح جميعها من مشغّل Game Vibes واحد في السمة الحالية؛ فهي تحمّل three.js من الويب، لذا تحتاج إلى اتصال لتبدأ. تُغطّى Claude Code وCodex وGrok وKimi وCursor وبدل Grok Bot الخاص به وGitHub Copilot وMuse وAntigravity وKimchi وDevin جاهزة للاستخدام مع حدودها، ويعرض Hermes وMistral Vibe وQwen Code جلساتهم ورموزهم بمجرد استخدامك لهم. تظهر أيضًا خطط المزودين ومفاتيحهم التي تستخدمها عبر pi أو omp أو opencode: OpenCode Zen وGo، وخطة Z.ai GLM Coding Plan، وOllama Cloud، وخطة MiniMax Token Plan، وSynthetic مع حدودها؛ وFireworks وOpenRouter وDeepSeek مع أرصدتها المدفوعة مسبقًا؛ والنماذج التي تشغّلها على أجهزتك الخاصة ضمن Local models. يُحسَب كل وكيل مرة واحدة، تحت الجهة التي تفوتره، مهما كان عدد أدوات harness التي تشغّله عبرها.

انقر بالزر الأيسر على أيقونة الشريط لفتح اللوحة، وانقر بالزر الأيمن لتشغيل وكيلك الافتراضي. تُعاد توليد سجلات الاستخدام التي تقف وراءها كل 15 دقيقة بواسطة `omarchy agent usage-update`، ويمكن للوحة حتى دمج الاستخدام من أجهزتك الأخرى عبر مجلد متزامن. راجع README ضمن `$OMARCHY_PATH/shell/plugins/agents/` للاطلاع على الإعدادات الكاملة.

### اشتراكات متعددة

إذا دفعت مقابل أكثر من خطة واحدة من Claude أو Codex أو Grok — خطة Max شخصية وخطة عمل، على سبيل المثال — يمكن لـ Omarchy إبقاءها جميعًا مسجّلة الدخول والتنقل بينها. أضف اشتراكًا باستخدام + في لوحة الوكلاء، التي ترشدك خلال ذلك هناك مباشرة، أو باستخدام `omarchy agent account add claude Work` (أو `codex`، أو `grok`). يثبّت هذا CLI إذا كان مفقودًا. يسجّل الحساب الأول لمزود الدخول عبر متصفحك العادي، في المكان الذي يبحث فيه CLI دائمًا. يسجّل كل حساب بعد ذلك الدخول عبر نافذة خاصة، بحيث لا يُلتقط عن طريق الخطأ الحساب الذي سجّل متصفحك الدخول إليه بالفعل؛ سجّل الدخول هناك بالحساب الذي تضيفه، وأغلق أي نافذة خاصة لديك مفتوحة بالفعل أولًا. لا تسجّل الخروج من CLI أبدًا للقيام بذلك: يلغي تسجيل الخروج تسجيل الدخول المحفوظ، وسيتعيّن إضافة ذلك الحساب مرة أخرى.

لنسخ تسجيلات دخول اشتراكاتك إلى جهاز Omarchy آخر عبر SSH، شغّل `omarchy agent account copy user@laptop`. يوفّر المرسل مستقبِلًا مؤقتًا عندما لا يكون لدى الوجهة واحد مثبّت، لذا يمكن لأجهزة Omarchy الأقدم استقبال الحسابات دون تحديث. تأخذ المستقبِلات المثبّتة الأسبقية. ينسخ هذا جميع اشتراكات Claude وCodex وGrok؛ أضف أسماء المزودين لتحديدها، كما في `omarchy agent account copy laptop claude`. تتطابق أسماء الحسابات ومعرّفات الأوامر مع المصدر، بما في ذلك الحسابات الموجودة بالفعل على الوجهة. تتلقى حسابات الوجهة غير ذات الصلة لاحقة رقمية إذا تعارضت أسماؤها، وتبقى الإعدادات والمهارات والإضافات وسجل المحادثات محلية لكل جهاز.

تُحفظ بيانات اعتماد الوجهة الموجودة. تتم مزامنة اسم حساب مصدر مسجّل الدخول بالفعل هناك دون استبدال بيانات اعتماده؛ وتُضاف الحسابات الأخرى بجانبه. لاستبدال بيانات الاعتماد المحفوظة للحسابات المطابقة، استخدم `omarchy agent account copy --replace laptop claude` بعد إنهاء جلسات ذلك الحساب على الوجهة. تتلقى الوجهة الجديدة أيضًا الحساب النشط للمصدر وتفضيلات التبديل الخاصة به؛ وتحتفظ الوجهة القائمة بتفضيلاتها الخاصة.

تنتقل بيانات الاعتماد عبر SSH وتُخزَّن في ملفات خاصة على الوجهة، لذا انسخ فقط إلى أجهزة تثق بها. هذه نسخة لمرة واحدة، وليست مزامنة مستمرة. يمكن لجهاز آخر تدوير رموز تحديث Codex، مما يترك تسجيل دخول منسوخًا بحاجة إلى تجديد؛ تبقى عمليات تسجيل الدخول المنفصلة الخيار الأكثر موثوقية للاستخدام المتزامن على عدة أجهزة. راجع [إرشادات مصادقة حساب Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

يكون حساب واحد لكل مزود نشطًا، وتبدأ كل جلسة جديدة به: `cx` و`cy`، أو `claude` أو `codex` أو `grok` عادي، وأي شيء يُشغَّل عبر `omarchy agent`، والبرامج النصية أو المحرّرات التي تجد CLI على `PATH`. بدّل باستخدام `omarchy agent account use work` (وارجع باستخدام `omarchy agent account use main`)، أو في اللوحة بالضغط على رقم حساب ثم `Enter` (أو النقر على زر Use الخاص به). تتبدّل جلسات Claude قيد التشغيل أيضًا، اعتبارًا من رسالتها التالية: تعمل كل جلسة Claude في `~/.claude`، الذي يحتفظ دائمًا بتسجيل دخول الحساب النشط. تحتفظ جلسة Claude التي بدأها Omarchy أقدم في مجلد الحساب الخاص بها بذلك التسجيل حتى تنتهي، لذا يسمّي التبديل تلك الجلسات وينتهي من تلقاء نفسه بمجرد اختفائها. تبقى جلسات Codex وGrok قيد التشغيل على الحساب الذي بدأت به. يُشارَك سجل المحادثات والإعدادات والمهارات والإضافات عبر الحسابات، لذا يكمل `claude --continue` في المجلد نفسه من حيث توقفت على الحساب الجديد.

مع وجود أكثر من حساب واحد، تعرض اللوحة حدود كل حساب جنبًا إلى جنب، مع تمييز الحساب النشط. افتراضيًا، يخطرك Omarchy عندما يتجاوز الحساب النشط 95% من أحد الحدود، والنقر على الإشعار يبدّل إلى الحساب الذي لديه أكبر هامش متاح. مرّر فوق سطر حساب في اللوحة وانقر على Autoswitch الذي يظهر بجوار Use (أو اضغط `m`)، أو شغّل `omarchy agent account mode auto`، لجعله يبدّل من تلقاء نفسه بدلًا من ذلك؛ أثناء تفعيله، يحل Autoswitch محل Use، والنقر عليه مرة أخرى يعود إلى الإخطار. أضف رقمًا لتغيير العتبة، كما في `omarchy agent account mode auto 90`. إذا تجاوز كل حساب العتبة، ستسمع عن ذلك مرة واحدة، مع بيان أي حساب سيتحرر أولًا. بينما يكون حساب نشط ضمن 15 نقطة من عتبته (80% افتراضيًا)، تُفحص حدوده كل ثلاث دقائق بدلًا من كل 15 دقيقة.

يعرض `omarchy agent account list` كل حساب وأحدث حدوده، وينسى `omarchy agent account remove work` حسابًا واحدًا، ويعيد `omarchy agent account rename primary Hey` تسمية حساب واحد (أو انقر على اسم حساب في اللوحة). تعمل هذه الأوامر على حسابات وكيلك الافتراضي؛ للوصول إلى المزود الآخر، سمّه أولًا، كما في `omarchy agent account use codex side`. تسجيل الدخول الذي كان لديك بالفعل في `~/.claude` أو `~/.codex` هو حساب _Main_. يبقى حساب Codex حيث هو؛ وينتظر حساب Claude في مجلد خاص به بينما يكون حساب آخر نشطًا. يمكن لحساب تُرك غير مستخدم لأكثر من حوالي ثماني ساعات أن يعرض _Sign-in required_؛ انقر عليه لتسجيل دخول ذلك الحساب مرة أخرى مباشرة في اللوحة، أو بدّل إليه وابدأ جلسة، مما ينعش تسجيل الدخول من تلقاء نفسه. تصل خوادم MCP التي تضيفها باستخدام `claude mcp add` إلى كل حساب Claude، لأنها جميعًا تعمل في `~/.claude`؛ بالنسبة إلى Codex وGrok، تأتي الخوادم التي كانت لديك عند إضافة حساب معه إليه، لكن الخوادم اللاحقة تصل فقط إلى الحساب الذي أضفتها فيه. يحتفظ Claude Desktop بتسجيل دخول خاص به، ولا تتبع أدوات Codex أو Grok المهيّأة بمسار مطلق إلى ثنائي CLI عملية التبديل. يأخذ `CLAUDE_CONFIG_DIR` أو `CODEX_HOME` أو `GROK_HOME` صريح الأسبقية على الحساب المحدد.

### تشخيص الأعطال

يراقب Omarchy برنامج systemd-coredump بحثًا عن أعطال العمليات. عندما يتعرض شيء ما لخطأ تجزئة، ستحصل على إشعار "Process crashed" — انقر عليه، ويُسلَّم العطل إلى وكيلك الافتراضي مع مهارة diagnose-crash في Omarchy، التي ترشد الوكيل خلال إثبات الحقائق من تفريغ النواة وتقرير ما إذا كان العطل يستحق الإبلاغ عنه في المنبع. يمكنك أيضًا تشغيله يدويًا مقابل أي PID من `coredumpctl list` باستخدام `omarchy agent crash <pid>`.

المراقبة مفعّلة افتراضيًا. أوقفها ضمن _Trigger > Toggle > Crash Capture_ (أو باستخدام `omarchy toggle crash-capture`) وستتوقف الإشعارات؛ لا يزال `omarchy agent crash <pid>` يعمل يدويًا.

يمكن أيضًا إسكات الأعطال برنامجًا واحدًا في كل مرة، وهو ما يعرضه عليك التشخيص في النهاية. يوقف `omarchy crash mute hyprland` الإشعارات لذلك البرنامج فقط، ويعيدها `omarchy crash mute hyprland off`، ويسرد `omarchy crash mute` بمفرده ما كتمته. يقبل هذا الأمر مسار الثنائي بسعادة كما يقبل اسمه، لذا يفعل `omarchy crash mute /usr/bin/hyprland` الشيء نفسه. ضع اسمًا يحتوي على مسافة بين علامتي اقتباس، كما في `omarchy crash mute 'Some App'`. يستمر كل شيء آخر في الإخطار، ويستمر البرنامج المكتوم في التعطل — هذا يخفي التذكير، ولا يصلح أي شيء.

### تطبيقات سطح المكتب

تحمل قائمة _Install > AI_ أيضًا بعض تطبيقات الذكاء الاصطناعي الرسومية: Antigravity Desktop، وتطبيق ChatGPT لسطح المكتب، وتطبيق Claude لسطح المكتب (إصدار Linux التجريبي من Anthropic، مع علامات تبويب Chat وCowork وClaude Code)، وGrok Bot للدردشة مع نماذج xAI، وHerdr Desktop، وHermes Desktop، وOpenClaw، وتطبيق Perplexity لسطح المكتب، وT3 Code. Grok Bot هو تطبيق الدردشة لسطح المكتب. وكيل البرمجة هو أمر `grok`.

Hermes Desktop هو التطبيق الذي يجب أن تعرفه، لأن الجهاز يحتوي على Hermes واحد، وهو الخاص بالتطبيق: لا يُثبَّت Hermes أبدًا إلا عبر التطبيق، وأمر `hermes` الذي يشغّله الوكيل الافتراضي هو الخاص بالتطبيق. يثبّت اختيار Hermes كوكيل افتراضي الشيء نفسه الذي يثبّته إدخال _Install > AI_: الحزمة، ووقت تشغيل Hermes تحت `~/.hermes` يعدّه مثبّت Hermes الخاص، والذي يستغرق بضع دقائق في المرة الأولى. وقت التشغيل ذلك هو Hermes الوحيد الذي يستخدمه أمر `hermes` في الطرفية والوكيل الافتراضي والتطبيق جميعًا، ويحدّث نفسه باستخدام `hermes update` بدلًا من انتظار إصدار Omarchy. يمنح تثبيته أيضًا Hermes سمة Omarchy كسطح باسم `omarchy`، تتبعه كل أسطح Hermes عند تبديل السمات؛ اختر سطحًا آخر ضمن إعدادات Appearance في Hermes أو باستخدام `/skin` إذا كنت تفضّل ألا يفعل ذلك، ويترك Omarchy ذلك الاختيار وشأنه. تغلق إزالة التطبيق ضمن _Remove > AI_ برنامج Hermes أولًا، بما في ذلك البوابة، وتأخذ وقت التشغيل ذلك معها، وتحتفظ بمحادثاتك وذكرياتك والمهارات التي كتبها Hermes لنفسه ما لم تخبره بخلاف ذلك: يسألك، مع افتراض الإجابة لا، عما إذا كان يجب حذف تلك البيانات وإعدادات اتصالك أيضًا.

تجربة OpenClaw على سطح المكتب هي واجهة Control UI الخاصة به، التي تفتح كتطبيق ويب مدعوم ببوابته المحلية الخاصة. يعيش OpenClaw في `~/.openclaw` ويحدّث نفسه: استخدم زر "Update Gateway" في Control UI أو شغّل `openclaw update`، وستعيد البوابة التشغيل على الإصدار الجديد. يختار Omarchy فقط الإصدار الذي يبدأ منه التثبيت الجديد. تأخذ إزالة OpenClaw ضمن _Remove > AI_ خدمة البوابة والتطبيق معها، ثم تسأل عما إذا كان يجب حذف `~/.openclaw` أيضًا، لأن ذلك المجلد يحتفظ بمحادثاتك وبيانات اعتمادك بجانب OpenClaw نفسه وأوقات تشغيل الإضافات التي ينزّلها؛ الافتراضي هو الاحتفاظ به، ويستعيده تثبيت OpenClaw مرة أخرى.

Herdr Desktop هو تطبيق سطح المكتب [Herdr](https://herdr.dev): مساحات وعلامات تبويب وأجزاء من الطرفيات ووكلاء برمجة تستمر في العمل في نواته عند إغلاق النافذة. يأتي من مثبّت Herdr الخاص بدلًا من حزمة، لذا يعيش في `~/.local/share/herdr-app`، ويجلب نواته معه في `~/.local/bin/herdr-core` عندما لا يكون لديك واحد بعد، ويحدّث نفسه وكلاهما. يجلس بجانب أمر `herdr` الذي يوفّره Omarchy على `Super + Ctrl + Return` بدلًا من استبداله، ويحصل على مفاتيح ذلك الأمر المباشرة: يقسّم `Alt + Return` و`Alt + Shift + Return` جزءًا إلى الأسفل أو إلى اليمين، ويغلقه `Alt + Escape`، ويتنقل `Ctrl + Alt + Arrow` بين الأجزاء، ويختار `Alt + 1..9` و`Alt + Left/Right` علامة تبويب، وينتقل `Alt + Up/Down` بين المساحات. يختار `Ctrl + 1..9` مساحة ويتنقل `Alt + Shift + Up/Down` عبر الوكلاء. تبقى مفاتيح البادئة `Ctrl + Space` للطرفية فقط، لأن التطبيق لا يمكنه الاحتفاظ بمفتاح Ctrl عادي لتسلسل. يكتب Omarchy هذه المفاتيح في `~/.config/herdr-app/keys.json`، ويعيدها `omarchy-refresh-herdr-app`. يختار تثبيته سمة Omarchy في Herdr، التي تتبع سمة Omarchy الخاصة بك من ذلك الحين فصاعدًا. يحتفظ Herdr بسمة واحدة للوضع الفاتح وأخرى للوضع الداكن، لذا بعد التبديل بين سمة Omarchy داكنة وفاتحة، اختر Omarchy في منتقي سمات Herdr مرة أخرى للوضع الآخر.

يعمل T3 Code من إصدار AppImage الرسمي الخاص به في `~/.local/share/t3code` بدلًا من حزمة، لذا يحدّث نفسه. يسألك تثبيته عما إذا كنت تريد البدء على قناة Stable أو Nightly؛ بدّل لاحقًا في إعدادات T3 Code. تعيش سلاسل محادثاتك وإعداداتك في `~/.t3`، وتأخذها إزالة T3 Code ضمن _Remove > AI_ معها.

### النماذج المحلية

شغّل نموذجًا مفتوحًا على جهازك الخاص لوكلاء البرمجة لديك. تبقى موجّهاتك وشيفرتك على الجهاز؛ لا يغادر أي شيء يُرسل إلى النموذج الجهاز. ابدأ بـ:

```bash
omarchy agent local use best
```

أو، في لوحة الوكلاء في الشريط العلوي، اختر + ثم Local AI، التي تظهر عندما يناسب نموذج ما هذا الجهاز. في المرة الأولى، يثبّت هذا Podman، الذي يشغّل النماذج، وعلى جهاز NVIDIA يثبّت مجموعة أدوات حاويات NVIDIA، التي تمنحها GPU. ثم يختار Omarchy النموذج الموصى به لهذا الجهاز، وينزّله، ويشغّله. توقّع تنزيلًا بعشرات GB وأن تكون معظم ذاكرة الجهاز قيد الاستخدام أثناء تشغيل النموذج: يستخدم Flash Next حوالي 100 GiB مع سياقه الكامل البالغ 256K. إذا احتجزت نماذج أخرى الذاكرة التي يحتاجها، يُعدّ متوقفًا، جاهزًا للبدء بمجرد إيقافك واحدًا منها. يتوقف النموذج عند تسجيل الخروج؛ أوقفه بنفسك عندما تحتاج الذاكرة لشيء آخر.

يعرض `omarchy agent local list` الخيارات ويشرح سبب عدم ملاءمة بعضها. لإعداد نموذج آخر، شغّل `omarchy agent local use <recipe>`. اليوم، يتوفر `qwen3.8-flash-next-gufo` و`qwen3.8-27b-gufo` لأجهزة Strix Halo بسعة 128 GB؛ يأخذ طراز 27B حوالي 40 GiB، لذا يترك مساحة لعمل آخر. على حاسوب محمول بسعة 64 GB مع Intel's Arc B390، يعمل `qwen3.6-35b-a3b-llamacpp` في حوالي 30 GiB. تصل الوصفات والتوصيات الجديدة مع `omarchy update`، عبر الحزمة.

يحصل كل نموذج تعدّه على سطره الخاص في لوحة الوكلاء، بجوار اشتراكاتك: زر تشغيل لبدئه، وزر إيقاف مؤقت لإيقافه وتحرير ذاكرته، وزر طرفية لفتح وكيلك عليه. يمكن تشغيل عدة نماذج في وقت واحد عندما تتسع لها الذاكرة معًا؛ إذا لم يتسع نموذج، يخبرك Omarchy بأي نموذج قيد التشغيل يجب إيقافه. اسحب الأسطر لإعادة ترتيبها، واضغط Delete على سطر محدد لإزالة نموذج وتنزيله.

يحصل كل نموذج تعدّه أيضًا على إدخاله الخاص في مشغّل التطبيقات، تحت اسم النموذج ومع شعار صانعه، بالطريقة نفسها التي يضيف بها تسجيل الدخول إلى Claude أو Codex أو Grok إدخالًا. يفتح هذا الإدخال وكيلك على ذلك النموذج، ويشغّل النموذج أولًا إذا لم يكن قيد التشغيل: تعرض الطرفية تحميله وتسلّم العمل إلى الوكيل بمجرد جاهزيته. تزيل إزالة نموذج إدخاله.

يستمر النموذج في العمل تمامًا كما أُعدّ، لذا لا يعيد تحديث Omarchy أبدًا تشغيل نموذج تحت وكلائك. عندما يتوفر لدى Omarchy وقت تشغيل أحدث أو أوزان أحدث لنموذج أعددته، يعرض سطره زر تحديث: اضغطه وسيُعاد إعداد النموذج في الخلفية، مع تنزيل ما تغيّر فقط، ويعيد التشغيل على الإصدار الجديد. يبقى النموذج الذي كان متوقفًا متوقفًا. يفعل `omarchy agent local update` الشيء نفسه لكل نموذج من الطرفية.

من سطر الأوامر، يفعل `omarchy agent local start <recipe>` و`omarchy agent local stop <recipe>` الشيء نفسه، ويعرض `omarchy agent local status` كل نموذج، ويفتح `omarchy agent --local` وكيلك الافتراضي على آخر نموذج بدأته. يمكن لـ pi وOpenCode وQwen Code استخدام نموذج محلي؛ ومع أي وكيل افتراضي آخر يفتح في pi. يسرد pi أيضًا كل نموذج أعددته، والنماذج الموجودة على الأجهزة التي اقترنت بها، في منتقي نماذجه الخاص، بحيث يصل إليها `pi` العادي أيضًا. يمكن لأي عميل متوافق مع OpenAI الاتصال أيضًا: يعرض `status` عنوان كل نموذج (الأول هو `http://127.0.0.1:11435/v1`)، واسم الوصفة هو النموذج، والمفتاح موجود في `~/.config/omarchy/agent-local/key`.

يحذف `omarchy agent local remove <recipe>` نموذجًا والتنزيلات التي لا يستخدمها أي نموذج آخر.

تُوسم أوقات تشغيل الجهات الخارجية بناشرها. يشغّل Omarchy كل نموذج دون أي وصول إلى الشبكة.

### نماذج LLM المحلية

يوصي Omarchy بطريقتين لتشغيل نماذج LLM المحلية: LM Studio وOllama. يوفر LM Studio واجهة GUI للعثور على النماذج ذات الأوزان المفتوحة وتثبيتها وتشغيلها. إنها طريقة رائعة للبدء بسهولة. يقدّم Ollama واجهة CLI للقيام بالأمر نفسه تقريبًا. لكن إذا كنت جديدًا على النماذج المحلية، سأبدأ بـ LM Studio. يمكنك تثبيت أي منهما ضمن _Install > AI_ في قائمة Omarchy.

### مهارة Omarchy

تساعد مهارات الوكلاء الذكاء الاصطناعي على استخدام أدوات محددة بطريقة محددة، ويوفّر Omarchy مهارة افتراضية لتصميم النظام حسب الطلب. مثل تعديل إعداد Hyprland الخاص بك، أو ضبط الشريط، أو حتى إنشاء سمة جديدة من الصفر. تُربط هذه المهارة رمزيًا في دلائل مهارات Claude Code (`~/.claude/skills`) وCodex (`~/.codex/skills`) وPi (`~/.pi/agent/skills`) وAntigravity (`~/.gemini/config/skills`) وHermes (`~/.hermes/skills` وكل `~/.hermes/profiles/*/skills`)، وموقع `~/.agents/skills` العام، بحيث تلتقطها معظم أدوات harness تلقائيًا.

لكن يجب أن تعامل هذه المهارة على أنها تجريبية. ستستخدمها النماذج المختلفة بتأثيرات مختلفة. من الأفضل تشغيلها في وضع التخطيط أولًا، بحيث تكون لديك فكرة عما يريد الوكيل تغييره. ثم كن مستعدًا للتراجع عن التغييرات أو حتى استدعاء `omarchy reinstall configs`، إذا أفسد الوكيل كل شيء.
