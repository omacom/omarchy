# الذكاء الاصطناعي

يتضمن Omarchy مشغّلات لوكلاء البرمجة أدناه دون أن يختار لك واحدًا افتراضيًا. شغّل أمرًا لتثبيت واجهة سطر الأوامر الخاصة به عند أول استخدام، ثم قم بالمصادقة عند مطالبتك بذلك. Hermes هو الاستثناء: لا يُثبَّت له أي شيء عند أول استخدام، واختياره يُثبِّت Hermes Desktop، كما توضح _تطبيقات سطح المكتب_ أدناه.

### تثبيت الوكلاء وتحديثهم

باستثناء Hermes، يستخدم هؤلاء الوكلاء التثبيت الكسول من mise: فالتشغيل الأول يُثبِّت واجهة سطر الأوامر، والتشغيلات اللاحقة تعيد استخدامها. كما يتحقق mise من وجود إصدار جديد لوكيل مُثبَّت مرة واحدة على الأكثر كل أربع ساعات، قبل بدئه مباشرة أو في الخلفية عند موجه shell. إذا فشل ذلك التحديث أو كنت غير متصل بالإنترنت، يعمل الإصدار المُثبَّت. يُحدِّث `omarchy update` الوكلاء المُثبَّتين مع بقية Omarchy، ويُحدِّث `mup` الأدوات التي يديرها mise فقط.

أداة التحديث الخاصة بالوكيل نفسه، مثل `claude update` أو `codex update` أو زر تحديث في تطبيق، لا تُحدِّث التثبيت الذي يديره mise. يفشل `codex update`، ويمكن أن يُبلغ `claude update` عن النجاح بينما يُثبِّت نسخة منفصلة لا يتتبعها mise. إذا كنت تفضّل استخدام أداة التثبيت والتحديث الأصلية لوكيل ما، أضفه إلى `disable_tools`؛ راجع [أدوات واجهة سطر الأوامر المُثبَّتة مسبقًا](18-development-tools.md#preinstalled-cli-tools).

لتثبيت جميع الأدوات الكسولة المُعدّة قبل أن تحتاج إليها، شغّل `mise install --include-lazy`. يشمل هذا أدوات واجهة سطر الأوامر الافتراضية الأخرى في Omarchy بالإضافة إلى الوكلاء. راجع [أدوات واجهة سطر الأوامر المُثبَّتة مسبقًا](18-development-tools.md#preinstalled-cli-tools) لتثبيت أداة واحدة أو استخدام تثبيتك الخاص.

يُثبَّت `grok` من خلال حزمة `grok` الرسمية من mise، بالطريقة نفسها مثل `claude` و`codex`. شغّل `grok`، أو اختره تحت _الوكيل > بيئة التشغيل_. تجاوز أداة التثبيت `curl | bash` على x.ai. فذلك المسار يضع نسخة ثانية في `~/.grok/bin`، ويضعها في مقدمة `PATH`، ويستبدل غلاف Omarchy.

يفتح `dsh` واجهة المتصفح الخاصة به على `127.0.0.1:3080`، مع دليل التشغيل كمساحة عمله الافتراضية. لا تأخذ واجهة المتصفح الخاصة به موجه بدء، لذا فإن `omarchy agent prompt` يفتحه مع الموجه في حافظتك للصقه. يبدأه Omarchy بإعداد أذونات عدم طلب الموافقة المسبق من DeepSeek. يُحمِّل DeepSeek Harness سجلات الجلسة إلى DeepSeek عند استخدامك لواجهة برمجة تطبيقات النموذج الرسمية الخاصة به؛ أوقف ذلك تحت _الإعدادات > عام > تحميل سجل الجلسة_ في واجهة المتصفح الخاصة به. كما يُحمَّل التعليق الذي ترسله إليه مع الجلسة أيضًا، ما لم تبدأه بـ `DSH_TELEMETRY_MODE=DISABLED`.

### الوكيل الافتراضي

اختر وكيلك الافتراضي بـ `omarchy default agent <name>` أو تحت _الوكيل > بيئة التشغيل_ في قائمة Omarchy (`Super + Space`). إذا لم يكن الوكيل مُثبَّتًا بعد، فإن اختياره يُثبِّته أولًا. سيدعوك Omarchy جديد لاتخاذ هذا الاختيار بإشعار يظهر مرة واحدة.

يحاول اختيار Claude أيضًا إعداد إضافة المتصفح الخاصة به لـ Chromium وChrome وBrave وBrave Origin وEdge. ينطبق إعداد الإضافة على جميع المستخدمين وقد يطلب كلمة مرور النظام الخاصة بك؛ ومع ذلك فإن إلغاء تثبيت الإضافة أو فشله لا يزال يختار Claude ويشغّله. أعد تشغيل متصفحك، فعّل الإضافة إذا طُلب منك ذلك، وسجّل الدخول إلى Claude لإنهاء توصيله. شغّل `/chrome` في Claude للتحقق من الاتصال. لا يدعم Firefox وZen هذه الإضافة. إذا كان Claude وكيلك الافتراضي بالفعل قبل إضافة هذا الإعداد، اختره مرة أخرى لتثبيت الإضافة.

بمجرد أن تختار، يقوم `Super + Shift + Ctrl + A` بتشغيل الوكيل الافتراضي في نافذة طرفية مخصصة (أو يُظهر المنتقي إذا لم تكن قد اخترت بعد). يمكنك أيضًا تشغيله مباشرة في مهمة بـ `omarchy agent prompt "Review this project"`. لا يأخذ Freebuff وDeepSeek Harness موجه بدء، لذا يفتحان مع الموجه في حافظتك للصقه بدلًا من ذلك. يعمل الوكلاء الذين يُشغَّلون بهذه الطريقة دون مراقبة في أوضاع عدم التوقف للسؤال الخاصة بكل منهم، لذا كن مستعدًا لأن يقوموا بأشياء فعلًا! لا يمتلك MiniMax Code مثل هذا الوضع لجلساته التفاعلية، لذا يطلب الأذونات كالمعتاد. وبما أن الوكلاء يرفضون تذكّر الثقة لدليلك الرئيسي، تبدأ عمليات التشغيل من `$HOME` في `~/Work` بدلًا من ذلك.

توجد اختصارات طرفية أيضًا: يشغّل `a` الوكيل الافتراضي ضمن الطرفية الحالية، بينما يبدأ `c` و`cx` و`cy` بـ OpenCode وClaude Code وCodex مباشرة (مرة أخرى في أوضاع الموافقة التلقائية الخاصة بهم). تتزامن تغييرات السمة مع الوكلاء أيضًا: يتبع Claude Code وPi وOpenCode وHermes (بمجرد أن يُثبِّته Omarchy) جميعها عندما تبدّل سمة Omarchy.

### تعليمات وكيلك

تذهب القواعد الشخصية لكل وكيل في `~/.agents/AGENTS.md`، بجانب المهارات المشتركة في `~/.agents/skills`. افتحه تحت _الوكيل > التعليمات_، والذي يربطه أيضًا في كل بيئة تشغيل تحتفظ بملفها العالمي الخاص: `~/.claude/CLAUDE.md` و`~/.codex/AGENTS.md` و`~/.pi/agent/AGENTS.md` و`~/.config/opencode/AGENTS.md` و`~/.copilot/copilot-instructions.md` الخاص بـ Copilot، وهكذا. يقرأ Crush وAmp رابط `~/.config/AGENTS.md`، بينما يقرأ omp وKimi وDeepSeek Harness `~/.agents/AGENTS.md` مباشرة. اختيار وكيل افتراضي يربطه أيضًا. يصبح ملف تعليمات كان لديك بالفعل هو الملف المشترك إذا لم يكن هناك واحد بعد؛ وإلا يُحتفظ به بجانب الرابط كـ `.bak`. شغّل `omarchy agent instructions` لإعادة الربط بعد تثبيت وكيل آخر.

### لوحة الوكلاء

يحتوي الشريط العلوي على أيقونة للوكلاء. قبل أن تُعدّ وكيلًا، ترشدك لوحته خلال تسجيل الدخول إلى Claude أو Codex أو Grok، ويصبح الأول وكيلك الافتراضي. بعد ذلك، تضع اللوحة كل اشتراك في صفحة واحدة: كل وكيل وحساب مع خطته، ومقياس لكل من حدود جلسته البالغة 5 ساعات وحدوده الأسبوعية مع الوقت حتى إعادة تعيينه (مرّر المؤشر للنسبة المئوية الدقيقة)، أو الرصيد المتبقي المدفوع مسبقًا، تحت سطر يتناوب عبر ما استخدمته عبر جميعها، مثل الرموز هذا الأسبوع ونموذجك الأكثر استخدامًا. تحت _اصنع شيئًا_ تقدم موجهات بداية لسمة أو إضافة أو تطبيق جديد تسلّم المهمة إلى وكيلك الافتراضي. تُبنى التطبيقات بالطريقة التي تُبنى بها تطبيقات Omarchy الخاصة Hype وMonologue وOmacut، بـ C++ وQt Quick، باتباع مهارة وكيل omarchy-app، وتأتي المترجمات وأجزاء Qt التي تحتاج إليها مُثبَّتة. يُغطى Claude Code وCodex وGrok وKimi وCursor ومخصص Grok Bot الخاص به وGitHub Copilot وMuse وAntigravity وKimchi وDevin مباشرة بحدودها، ويُظهر Hermes وMistral Vibe وQwen Code جلساتها ورموزها بمجرد استخدامك لها. تظهر أيضًا خطط ومفاتيح المزودين التي تستخدمها عبر pi أو omp أو opencode: OpenCode Zen وGo وخطة Z.ai GLM Coding Plan وOllama Cloud وخطة MiniMax Token Plan وSynthetic بحدودها؛ وFireworks وOpenRouter وDeepSeek بأرصدتها المدفوعة مسبقًا؛ والنماذج التي تشغّلها على أجهزتك الخاصة تحت النماذج المحلية. يُحسب كل وكيل مرة واحدة، تحت من يفوتره، مهما كان عدد بيئات التشغيل التي تقوده من خلالها.

انقر بزر أيسر على أيقونة الشريط للوحة، وانقر بزر أيمن لتشغيل وكيلك الافتراضي. تُجدَّد سجلات الاستخدام التي تقف وراءها كل 15 دقيقة بواسطة `omarchy agent usage-update`، ويمكن للوحة حتى دمج الاستخدام من أجهزتك الأخرى عبر مجلد متزامن. راجع README تحت `$OMARCHY_PATH/shell/plugins/agents/` للإعدادات الكاملة.

### اشتراكات متعددة

إذا كنت تدفع مقابل أكثر من خطة واحدة لـ Claude أو Codex أو Grok — خطة Max شخصية وخطة عمل، على سبيل المثال — يمكن لـ Omarchy إبقاءها جميعًا مسجلة الدخول والتنقل بينها. أضف اشتراكًا بعلامة + في لوحة الوكلاء، التي ترشدك خلال ذلك هناك مباشرة، أو بـ `omarchy agent account add claude Work` (أو `codex`، أو `grok`). يُثبِّت واجهة سطر الأوامر إذا كانت مفقودة. يسجّل الحساب الأول لمزود الدخول من خلال متصفحك العادي، حيث تبحث واجهة سطر الأوامر دائمًا. وكل حساب بعد ذلك يسجّل الدخول من خلال نافذة خاصة، بحيث لا يُلتقط بالخطأ الحساب الذي سجّل متصفحك الدخول إليه بالفعل؛ سجّل الدخول هناك كالحساب الذي تضيفه، وأغلق أي نافذة خاصة كانت مفتوحة لديك بالفعل أولًا. لا تسجّل الخروج أبدًا من واجهة سطر الأوامر للقيام بذلك: فتسجيل الخروج يلغي تسجيل الدخول المحفوظ، وسيتعين إضافة ذلك الحساب مرة أخرى.

لنسخ تسجيلات دخول اشتراكك إلى جهاز Omarchy آخر عبر SSH، شغّل `omarchy agent account copy user@laptop`. يوفر المرسل مستقبلًا مؤقتًا عندما لا يكون لدى الوجهة واحد مُثبَّت، بحيث يمكن لأجهزة Omarchy الأقدم استلام الحسابات دون تحديث. تأخذ المستقبلات المُثبَّتة الأسبقية. ينسخ هذا جميع اشتراكات Claude وCodex وGrok؛ أضف أسماء المزودين لاختيارها، كما في `omarchy agent account copy laptop claude`. تتطابق أسماء الحسابات ومعرفات الأوامر مع المصدر، بما في ذلك الحسابات الموجودة بالفعل على الوجهة. تتلقى حسابات الوجهة غير ذات الصلة لاحقة رقمية إذا تعارضت أسماؤها، وتبقى الإعدادات والمهارات والإضافات وسجل المحادثات محلية لكل جهاز.

تُحتفظ ببيانات اعتماد الوجهة الموجودة. الحساب المصدري الذي سُجّل دخوله هناك بالفعل تُزامن اسمه دون استبدال بيانات اعتماده؛ وتُضاف الحسابات الأخرى بجانبه. لاستبدال بيانات الاعتماد المحفوظة للحسابات المطابقة، استخدم `omarchy agent account copy --replace laptop claude` بعد إغلاق جلسات ذلك الحساب على الوجهة. تحصل الوجهة الجديدة أيضًا على الحساب النشط وتفضيلات التبديل الخاصة بالمصدر؛ وتحتفظ الوجهة القائمة بتفضيلاتها الخاصة.

تنتقل بيانات الاعتماد عبر SSH وتُخزّن في ملفات خاصة على الوجهة، لذا انسخ فقط إلى أجهزة تثق بها. هذه نسخة لمرة واحدة، وليست مزامنة مستمرة. يمكن لجهاز آخر تدوير رموز تحديث Codex، مما يترك تسجيل دخول منسوخًا بحاجة إلى تجديد؛ تبقى عمليات تسجيل الدخول المنفصلة الخيار الأكثر موثوقية للاستخدام المتزامن على عدة أجهزة. راجع [إرشادات مصادقة حساب Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

حساب واحد لكل مزود نشط، وكل جلسة جديدة تبدأ به: `cx` و`cy` و`claude` أو `codex` أو `grok` عادي، وأي شيء يُشغَّل عبر `omarchy agent`، والبرامج النصية أو المحررات التي تجد واجهة سطر الأوامر على `PATH`. بدّل بـ `omarchy agent account use work` (وعُد بـ `omarchy agent account use main`)، أو في اللوحة بالضغط على رقم حساب ثم `Enter` (أو النقر على زر الاستخدام الخاص به). تبقى الجلسات التي تعمل بالفعل على الحساب الذي بدأت به. يُشارك سجل المحادثات والإعدادات والمهارات والإضافات عبر الحسابات، لذا فإن `claude --continue` في المجلد نفسه يلتقط من حيث توقفت على الحساب الجديد.

مع أكثر من حساب واحد، تعرض اللوحة حدود كل حساب جنبًا إلى جنب، مع تمييز الحساب النشط. افتراضيًا، يُعلمك Omarchy عندما يتجاوز الحساب النشط 95% من حد ما، والنقر على الإشعار يبدّل إلى الحساب ذي أكبر هامش متاح. مرّر المؤشر فوق سطر حساب في اللوحة وانقر على التبديل التلقائي الذي يظهر بجانب الاستخدام (أو اضغط `m`)، أو شغّل `omarchy agent account mode auto`، لجعله يبدّل من تلقاء نفسه بدلًا من ذلك؛ بينما هو مفعّل، يأخذ التبديل التلقائي مكان الاستخدام، والنقر عليه مرة أخرى يعود إلى الإشعار. أضف رقمًا لتغيير العتبة، كما في `omarchy agent account mode auto 90`. إذا تجاوز كل حساب العتبة، ستسمع عن ذلك مرة واحدة، إلى جانب أي حساب سيتحرر أولًا. بينما يكون الحساب النشط ضمن 15 نقطة من عتبته (80% عند الافتراضي)، تُفحص حدوده كل ثلاث دقائق بدلًا من كل 15.

يعرض `omarchy agent account list` كل حساب وحدوده الأخيرة، وينسى `omarchy agent account remove work` واحدًا، ويعيد `omarchy agent account rename primary Hey` تسمية واحد (أو انقر على اسم حساب في اللوحة). تعمل هذه الأوامر على حسابات وكيلك الافتراضي؛ للوصول إلى المزود الآخر، سمّه أولًا، كما في `omarchy agent account use codex side`. تسجيل الدخول الذي كان لديك بالفعل في `~/.claude` أو `~/.codex` هو حساب _Main_ ويبقى حيث هو. يمكن أن يُظهر حساب لم يُستخدم لأكثر من حوالي ثماني ساعات _يلزم تسجيل الدخول_؛ انقر عليه لتسجيل دخول ذلك الحساب مرة أخرى مباشرة في اللوحة، أو ابدأ جلسة فيه، مما ينعش تسجيل الدخول من تلقاء نفسه. تأتي خوادم MCP التي كانت لديك عند إضافة حساب معه، لكن تلك التي تضيفها لاحقًا بـ `claude mcp add` تصل فقط إلى الحساب الذي أضفتها فيه. لا يتبع Claude Desktop والأدوات المُعدّة بمسار مطلق إلى ثنائي واجهة سطر الأوامر التبديل. يأخذ `CLAUDE_CONFIG_DIR` أو `CODEX_HOME` أو `GROK_HOME` صريح الأسبقية على الحساب المختار.

### تشخيص الانهيار

يراقب Omarchy systemd-coredump لانهيارات العمليات. عندما يتعرض شيء ما لخطأ تجزئة، ستحصل على إشعار "Process crashed" — انقر عليه، ويُسلَّم الانهيار إلى وكيلك الافتراضي مع مهارة diagnose-crash الخاصة بـ Omarchy، التي ترشد الوكيل خلال إثبات الحقائق من تفريغ النواة وتقرير ما إذا كان الانهيار يستحق الإبلاغ عنه إلى المنبع. يمكنك أيضًا تشغيله يدويًا مقابل أي PID من `coredumpctl list` بـ `omarchy agent crash <pid>`.

المراقبة مفعّلة افتراضيًا. أوقفها تحت _المشغّل > تبديل > التقاط الانهيار_ (أو بـ `omarchy toggle crash-capture`) وتتوقف الإشعارات؛ لا يزال `omarchy agent crash <pid>` يعمل يدويًا.

يمكن أيضًا إسكات الانهيارات برنامجًا واحدًا في كل مرة، وهو ما يقدمه لك التشخيص في النهاية. يوقف `omarchy crash mute hyprland` الإشعارات لذلك البرنامج فقط، ويعيدها `omarchy crash mute hyprland off`، ويسرد `omarchy crash mute` بمفرده ما كتمته. يقبل مسار الملف التنفيذي كما يقبل اسمه تمامًا، لذا فإن `omarchy crash mute /usr/bin/hyprland` يفعل الشيء نفسه. ضع اسمًا يحتوي على مسافة بين علامتي اقتباس، كما في `omarchy crash mute 'Some App'`. كل شيء آخر لا يزال يُشعر، والبرنامج المكتوم لا يزال ينهار — هذا يخفي التذكير، ولا يصلح أي شيء.

### تطبيقات سطح المكتب

يحمل قائمة _التثبيت > الذكاء الاصطناعي_ أيضًا بعض تطبيقات الذكاء الاصطناعي الرسومية: تطبيق ChatGPT لسطح المكتب، وتطبيق Claude لسطح المكتب (إصدار Linux التجريبي من Anthropic، مع علامات تبويب Chat وCowork وClaude Code)، وGrok Bot للدردشة مع نماذج xAI، وHerdr Desktop، وHermes Desktop، وOpenClaw، وتطبيق Perplexity لسطح المكتب، وT3 Code. Grok Bot هو تطبيق الدردشة لسطح المكتب. وكيل البرمجة هو أمر `grok`.

Hermes Desktop هو الذي يجب أن تعرفه، لأن الجهاز لديه Hermes واحد، وهو خاص بالتطبيق: لا يُثبَّت Hermes أبدًا إلا من خلال التطبيق، وأمر `hermes` الذي يشغّله الوكيل الافتراضي هو الخاص بالتطبيق. اختيار Hermes كوكيل افتراضي يُثبِّت الشيء نفسه الذي يفعله إدخال _التثبيت > الذكاء الاصطناعي_: الحزمة، وبيئة تشغيل Hermes تحت `~/.hermes` تُعدّها أداة تثبيت Hermes الخاصة، والتي تستغرق بضع دقائق في المرة الأولى. تلك البيئة هي Hermes الوحيدة التي تستخدمها أمر `hermes` الطرفي والوكيل الافتراضي والتطبيق جميعًا، وتُحدِّث نفسها بـ `hermes update` بدلًا من انتظار إصدار Omarchy. كما يمنحها تثبيتها سمة Omarchy كمظهر باسم `omarchy`، تتبعه كل أسطح Hermes أثناء تبديلك للسمات؛ اختر آخر تحت إعدادات مظهر Hermes أو بـ `/skin` إذا كنت تفضّل ألا تتبعه، ويترك Omarchy ذلك الاختيار وشأنه. إزالة التطبيق تحت _إزالة > الذكاء الاصطناعي_ تغلق Hermes أولًا، بما في ذلك البوابة، وتأخذ تلك البيئة معها، وتحتفظ بدردشاتك وذكرياتك والمهارات التي كتبها Hermes لنفسه ما لم تخبره بخلاف ذلك: يسأل، مع افتراضي لا، ما إذا كان يجب أن تذهب تلك البيانات وإعدادات اتصالك أيضًا.

تجربة سطح المكتب لـ OpenClaw هي واجهة التحكم الخاصة به، التي تفتح كتطبيق ويب مدعوم ببوابته المحلية الخاصة. يعيش OpenClaw في `~/.openclaw` ويُحدِّث نفسه: استخدم زر "Update Gateway" في واجهة التحكم أو شغّل `openclaw update`، وتُعاد تشغيل البوابة على الإصدار الجديد. يختار Omarchy فقط الإصدار الذي يبدأ منه التثبيت الجديد. إزالة OpenClaw تحت _إزالة > الذكاء الاصطناعي_ تأخذ خدمة البوابة والتطبيق معها ثم تسأل ما إذا كان يجب أن يذهب `~/.openclaw` أيضًا، لأن ذلك يحتفظ بدردشاتك وبيانات اعتمادك بجانب OpenClaw نفسه وبيئات تشغيل الإضافات التي ينزّلها؛ الافتراضي يحتفظ به، وتثبيت OpenClaw مرة أخرى يلتقطه من جديد.

Herdr Desktop هو تطبيق سطح المكتب [Herdr](https://herdr.dev): مساحات وعلامات تبويب وأجزاء من الطرفيات ووكلاء البرمجة تستمر في العمل في نواته عندما تغلق النافذة. يأتي من أداة تثبيت Herdr الخاصة بدلًا من حزمة، لذا يعيش في `~/.local/share/herdr-app`، ويجلب نواته في `~/.local/bin/herdr-core` عندما لا يكون لديك واحد بعد، ويحدّث كليهما بنفسه. يتعايش مع أمر `herdr` الذي يشحنه Omarchy على `Super + Ctrl + Return` بدلًا من أن يحل محله، ويحصل على مفاتيح ذلك الأمر المباشرة: `Alt + Return` و`Alt + Shift + Return` يقسمان جزءًا لأسفل أو يمينًا، و`Alt + Escape` يغلقه، و`Ctrl + Alt + Arrow` يتنقل بين الأجزاء، و`Alt + 1..9` و`Alt + Left/Right` يختاران علامة تبويب، و`Alt + Up/Down` يتنقلان بين المساحات. يختار `Ctrl + 1..9` مساحة ويخطو `Alt + Shift + Up/Down` عبر الوكلاء. تبقى مفاتيح بادئة `Ctrl + Space` للطرفية فقط، لأن التطبيق لا يمكنه الاحتفاظ بمفتاح Ctrl عادي لتسلسل. يكتب Omarchy هذه إلى `~/.config/herdr-app/keys.json`، ويعيدها `omarchy-refresh-herdr-app`. يختار تثبيته سمة Omarchy الخاصة بـ Herdr، التي تتبع سمة Omarchy الخاصة بك من حينها فصاعدًا. يحتفظ Herdr بسمة واحدة للوضع الفاتح وواحدة للوضع الداكن، لذا بعد التبديل بين سمة Omarchy داكنة وفاتحة، اختر Omarchy في منتقي سمات Herdr مرة أخرى للوضع الآخر.

يعمل T3 Code من إصدار AppImage الرسمي الخاص به في `~/.local/share/t3code` بدلًا من حزمة، لذا يُحدِّث نفسه. يسأل تثبيته ما إذا كنت تريد البدء على قناة Stable أو Nightly؛ بدّل لاحقًا في إعدادات T3 Code. تعيش سلاسل محادثاتك وإعداداتك في `~/.t3`، وإزالة T3 Code تحت _إزالة > الذكاء الاصطناعي_ تأخذها معها.

### النماذج المحلية

شغّل نموذجًا مفتوحًا على جهازك الخاص لوكلاء البرمجة لديك. تبقى موجهاتك ورمزك على الجهاز؛ لا يغادر أي شيء يُرسل إلى النموذج الجهاز. ابدأ بـ:

```bash
omarchy agent local use best
```

أو، في لوحة الوكلاء في الشريط العلوي، اختر + ثم Local AI، التي تظهر عندما يناسب نموذج هذا الجهاز. في المرة الأولى، يُثبِّت هذا Podman، الذي يشغّل النماذج، وعلى جهاز NVIDIA مجموعة أدوات حاويات NVIDIA، التي تمنحها GPU. ثم يختار Omarchy النموذج الموصى به لهذا الجهاز، ينزّله، ويبدأه. توقع تنزيلًا بعشرات GB ومعظم ذاكرة الجهاز قيد الاستخدام أثناء تشغيل النموذج: يستخدم Flash Next حوالي 100 GiB مع سياقه الكامل 256K. إذا احتفظت نماذج أخرى بالذاكرة التي يحتاجها، يُعدّ متوقفًا، جاهزًا للبدء بمجرد إيقافك واحدًا. يتوقف النموذج عند تسجيل الخروج؛ أوقفه بنفسك عندما تحتاج الذاكرة لشيء آخر.

يعرض `omarchy agent local list` الخيارات ويشرح لماذا لا يناسب بعضها. لإعداد آخر، شغّل `omarchy agent local use <recipe>`. اليوم، يتوفر `qwen3.8-flash-next-gufo` و`qwen3.8-27b-gufo` لأجهزة Strix Halo بسعة 128 GB؛ يأخذ 27B حوالي 40 GiB، لذا يترك مساحة لأعمال أخرى. تصل الوصفات والتوصيات الجديدة مع `omarchy update`، من خلال الحزمة.

يحصل كل نموذج تُعدّه على سطر خاص به في لوحة الوكلاء، بجانب اشتراكاتك: تشغيل لبدئه، وإيقاف مؤقت لإيقافه وتحرير ذاكرته، وزر الطرفية لفتح وكيلك عليه. يمكن تشغيل عدة منها في وقت واحد عندما تناسب الذاكرة معًا؛ إذا لم يناسب واحد، يقول Omarchy أي نموذج عامل يجب إيقافه. اسحب السطور لإعادة ترتيبها، واضغط Delete على سطر مختار لإزالة نموذج وتنزيله.

من سطر الأوامر، يفعل `omarchy agent local start <recipe>` و`omarchy agent local stop <recipe>` الشيء نفسه، ويعرض `omarchy agent local status` كل نموذج، ويفتح `omarchy agent --local` وكيلك الافتراضي على آخر نموذج بدأته. يمكن لـ pi وOpenCode وQwen Code استخدام واحد؛ مع أي افتراضي آخر يفتح في pi. يسرد pi أيضًا كل نموذج أعددته، وتلك الموجودة على أجهزة اقترنت بها، في منتقي نماذجه الخاص، لذا فإن `pi` العادي يصل إليها أيضًا. يمكن لأي عميل متوافق مع OpenAI الاتصال أيضًا: يعرض `status` عنوان كل نموذج (الأول هو `http://127.0.0.1:11435/v1`)، واسم الوصفة هو النموذج، والمفتاح في `~/.config/omarchy/agent-local/key`.

يحذف `omarchy agent local remove <recipe>` نموذجًا والتنزيلات التي لا يستخدمها أي نموذج آخر.

تُوسم بيئات تشغيل الطرف الثالث بناشرها. يشغّل Omarchy كل نموذج دون وصول إلى الشبكة.

### نماذج اللغة الكبيرة المحلية

يوصي Omarchy بطريقتين لتشغيل نماذج LLM محلية: LM Studio وOllama. يوفر LM Studio واجهة رسومية للعثور على نماذج مفتوحة الأوزان وتثبيتها وتشغيلها. إنها طريقة رائعة للبدء بسهولة. يقدم Ollama واجهة سطر أوامر للقيام بذلك بالمثل. لكن إذا كنت جديدًا على النماذج المحلية، سأبدأ بـ LM Studio. يمكنك تثبيت أي منهما تحت _التثبيت > الذكاء الاصطناعي_ في قائمة Omarchy.

### مهارة Omarchy

تساعد مهارات الوكلاء الذكاء الاصطناعي على استخدام أدوات محددة بطريقة محددة، ويأتي Omarchy مع مهارة افتراضية لتخصيص النظام. مثل تعديل إعداد Hyprland الخاص بك، أو ضبط الشريط، أو حتى إنشاء سمة جديدة من الصفر. إنها مرتبطة رمزيًا في دلائل مهارات Claude Code (`~/.claude/skills`) وCodex (`~/.codex/skills`) وPi (`~/.pi/agent/skills`) وAntigravity (`~/.gemini/config/skills`) وHermes (`~/.hermes/skills` وكل `~/.hermes/profiles/*/skills`)، والموقع العام `~/.agents/skills`، لذا تلتقطها معظم بيئات التشغيل تلقائيًا.

لكن يجب أن تعامل هذه المهارة كتجريبية. ستستخدمها نماذج مختلفة بتأثيرات مختلفة. من الأفضل تشغيلها في وضع التخطيط أولًا، بحيث يكون لديك فكرة عما يرغب الوكيل في تغييره. ثم كن مستعدًا للتراجع عن التغييرات أو حتى استدعاء `omarchy reinstall configs`، إذا أحدث الوكيل فوضى في كل شيء.
