# الذكاء الاصطناعي

يتضمّن Omarchy مشغِّلات لوكلاء البرمجة أدناه من دون أن يختار واحدًا افتراضيًا نيابةً عنك. شغّل أمرًا لتثبيت واجهة سطر الأوامر الخاصة به عند أول استخدام، ثم أكمل المصادقة عند مطالبتك بذلك. Hermes هو الاستثناء: لا يُثبَّت أي شيء له عند أول استخدام، واختياره يُثبِّت Hermes Desktop، كما يشرح قسم _تطبيقات سطح المكتب_ أدناه.

### تثبيت الوكلاء وتحديثهم

باستثناء Hermes، يستخدم هؤلاء الوكلاء التثبيت الكسول عبر mise: فالتشغيل الأول يُثبِّت واجهة سطر الأوامر، والتشغيلات اللاحقة تعيد استخدامها. يتحقق mise أيضًا من وجود إصدار جديد لوكيل مُثبَّت مرة واحدة على الأكثر كل أربع ساعات، قبل بدئه مباشرةً أو في الخلفية عند موجّه shell. وإذا فشل ذلك التحديث أو كنت غير متصل، فسيعمل الإصدار المُثبَّت. يُحدِّث `omarchy update` الوكلاء المُثبَّتين مع بقية Omarchy، ويُحدِّث `mup` الأدوات التي يديرها mise فقط.

لا يُحدِّث محدِّث الوكيل الخاص، مثل `claude update` أو `codex update` أو زر تحديث داخل تطبيق، التثبيت الذي يديره mise. يفشل `codex update`، وقد يُبلّغ `claude update` عن النجاح بينما يُثبِّت نسخة منفصلة لا يتتبعها mise. وإذا كنت تفضّل استخدام مثبِّت الوكيل ومحدِّثه الأصليين، فأضفه إلى `disable_tools`؛ راجع [أدوات CLI المُثبَّتة مسبقًا](18-development-tools.md#preinstalled-cli-tools).

لتثبيت كل الأدوات الكسولة المهيّأة قبل أن تحتاج إليها، شغّل `mise install --include-lazy`. يشمل هذا أدوات CLI الافتراضية الأخرى في Omarchy إضافةً إلى الوكلاء. راجع [أدوات CLI المُثبَّتة مسبقًا](18-development-tools.md#preinstalled-cli-tools) لتثبيت أداة واحدة أو لاستخدام تثبيتك الخاص.

يُثبَّت `grok` عبر حزمة `grok` الرسمية من mise، بالطريقة نفسها المستخدَمة لـ `claude` و`codex`. شغّل `grok`، أو اختره ضمن _Setup > Defaults > Agent_. تجاوز مثبِّت `curl | bash` على x.ai. فذلك المسار يضع نسخة ثانية في `~/.grok/bin`، ويضعها في مقدّمة `PATH`، ويستبدل غلاف Omarchy.

يفتح `dsh` واجهة المتصفح الخاصة به على `127.0.0.1:3080`، مع كون مجلد التشغيل مساحة العمل الافتراضية له. ولا تأخذ واجهة المتصفح الخاصة به أي موجّه بدء، لذا فإن `omarchy agent prompt` يفتحه مع وجود الموجّه في حافظتك للصقه. يبدأه Omarchy باستخدام إعداد أذونات عدم الموافقة من DeepSeek. يرفع DeepSeek Harness سجلات الجلسة إلى DeepSeek عندما تستخدم واجهة برمجة تطبيقات نماذجه الرسمية؛ أوقف ذلك ضمن _Settings > General > Upload Session Log_ في واجهة المتصفح الخاصة به. كما تُرفَع التعليقات التي ترسلها إليه مع الجلسة أيضًا، ما لم تبدأه باستخدام `DSH_TELEMETRY_MODE=DISABLED`.

### الوكيل الافتراضي

اختر وكيلك الافتراضي باستخدام `omarchy default agent <name>` أو ضمن _Setup > Defaults > Agent_ في Omarchy Menu (`Super + Space`). وإذا لم يكن الوكيل مُثبَّتًا بعد، فإن اختياره يُثبِّته أولًا. وسيَدعوك تثبيت جديد من Omarchy لاتخاذ هذا الخيار عبر إشعار يظهر مرة واحدة.

يحاول اختيار Claude أيضًا إعداد إضافة المتصفح الخاصة به لـ Chromium وChrome وBrave وBrave Origin وEdge. ينطبق إعداد الإضافة على جميع المستخدمين وقد يطلب كلمة مرور نظامك؛ إلغاء تثبيت الإضافة أو فشله لا يزال يختار Claude ويشغّله. أعد تشغيل متصفحك، وفعّل الإضافة إذا طُلب منك ذلك، وسجّل الدخول إلى Claude لإنهاء توصيلها. شغّل `/chrome` في Claude للتحقق من الاتصال. لا يدعم Firefox وZen هذه الإضافة. وإذا كان Claude وكيلك الافتراضي بالفعل قبل إضافة هذا الإعداد، فاختره مرة أخرى لتثبيت الإضافة.

بمجرد أن تختار، يقوم `Super + Shift + Ctrl + A` بتشغيل الوكيل الافتراضي في نافذة طرفية مخصّصة (أو إظهار المنتقي إذا لم تختر بعد). يمكنك أيضًا تشغيله مباشرةً لتنفيذ مهمة باستخدام `omarchy agent prompt "Review this project"`. لا يأخذ Freebuff وDeepSeek Harness أي موجّه بدء، لذا يفتحان مع وجود الموجّه في حافظتك للصقه بدلًا من ذلك. يعمل الوكلاء الذين يُشغَّلون بهذه الطريقة من دون إشراف في أوضاعهم الخاصة بعدم التوقف للسؤال، لذا كن مستعدًا لأن يقوموا بأشياء فعليًا! لا يمتلك MiniMax Code مثل هذا الوضع لجلساته التفاعلية، لذا يطلب الأذونات كالمعتاد. ولأن الوكلاء يرفضون تذكّر الثقة لمجلدك الرئيسي، تبدأ عمليات التشغيل من `$HOME` في `~/Work` بدلًا من ذلك.

هناك أيضًا اختصارات طرفية: يشغّل `a` الوكيل الافتراضي داخل الطرفية الحالية مباشرةً، بينما تبدأ `c` و`cx` و`cy` كلًا من OpenCode وClaude Code وCodex مباشرةً (مجددًا في أوضاع الموافقة التلقائية الخاصة بهم). تتم مزامنة تغييرات السمة إلى الوكلاء أيضًا: يتبع كل من Claude Code وPi وOpenCode وHermes (بمجرد أن يكون Omarchy قد ثبّته) التغيير عندما تبدّل سمة Omarchy.

### لوحة الوكلاء

يحتوي الشريط العلوي على أيقونة وكلاء. قبل أن تقوم بإعداد وكيل، ترشدك لوحته خطوة بخطوة لتسجيل الدخول إلى Claude أو Codex أو Grok، ويصبح الأول منهم وكيلك الافتراضي. وبعد ذلك، تضع اللوحة كل اشتراك على صفحة واحدة: كل وكيل وحساب مع خطته، وعدّاد لكل حدّ من حدود جلسة الـ 5 ساعات والحدود الأسبوعية مع الوقت المتبقي حتى إعادة تعيينه (مرّر المؤشر لمعرفة النسبة الدقيقة)، أو الرصيد المتبقي المدفوع مسبقًا، تحت سطر يتناوب عبر ما استخدمته عبرهم جميعًا، مثل الرموز هذا الأسبوع ونموذجك الأكثر استخدامًا. وضمن _Make something_ تقدّم موجّهات بداية لصنع سمة أو إضافة أو تطبيق جديد تسلّم المهمة إلى وكيلك الافتراضي. تُبنى التطبيقات بالطريقة نفسها التي بُنيت بها تطبيقات Omarchy الخاصة Hype وMonologue وOmacut، بلغة C++ وQt Quick، باتباع مهارة وكيل omarchy-app، والمترجم وأجزاء Qt التي يحتاجونها تأتي مُثبَّتة. تُغطّى Claude Code وCodex وGrok وKimi وCursor وبدل Grok Bot الخاص به وGitHub Copilot وMuse وAntigravity وKimchi وDevin من الصندوق مع حدودهم، ويُظهر Hermes وMistral Vibe وQwen Code جلساتهم ورموزهم بمجرد أن تكون قد استخدمتهم. تظهر أيضًا خطط المزوّدين والمفاتيح التي تستخدمها عبر pi أو omp أو opencode: OpenCode Zen وGo وخطة Z.ai GLM Coding Plan وOllama Cloud وخطة MiniMax Token Plan وSynthetic مع حدودهم؛ وFireworks وOpenRouter وDeepSeek مع أرصدتهم المدفوعة مسبقًا؛ والنماذج التي تشغّلها على عتادك الخاص ضمن النماذج المحلية. يُحتسَب كل وكيل مرة واحدة، تحت الجهة التي تفرض رسومه، مهما كان عدد الأطر التي تشغّله من خلالها.

انقر بالزر الأيسر على أيقونة الشريط للوحة، وانقر بالزر الأيمن لتشغيل وكيلك الافتراضي. تُعاد إنشاء سجلات الاستخدام التي تقف وراءها كل 15 دقيقة بواسطة `omarchy agent usage-update`، ويمكن للوحة حتى دمج الاستخدام من أجهزتك الأخرى عبر مجلد تتم مزامنته. راجع README ضمن `$OMARCHY_PATH/shell/plugins/agents/` لمعرفة الإعدادات الكاملة.

### اشتراكات متعددة

إذا كنت تدفع مقابل أكثر من خطة واحدة من Claude أو Codex أو Grok — خطة Max شخصية وخطة عمل، على سبيل المثال — فيمكن لـ Omarchy أن يحتفظ بها كلها مسجّلة الدخول وأن ينتقل بينها. أضف اشتراكًا باستخدام + في لوحة الوكلاء، التي ترشدك خطوة بخطوة هناك مباشرةً، أو باستخدام `omarchy agent account add claude Work` (أو `codex`، أو `grok`). إنها تُثبِّت واجهة سطر الأوامر إذا كانت مفقودة. يسجّل الحساب الأول للمزوّد الدخول عبر متصفحك العادي، حيث تبحث واجهة سطر الأوامر دائمًا بالضبط. وكل حساب بعد ذلك يسجّل الدخول عبر نافذة خاصة، حتى لا يُلتقط بالخطأ الحساب الذي سجّلتَ الدخول به مسبقًا في متصفحك؛ سجّل الدخول هناك بالحساب الذي تضيفه، وأغلق أي نافذة خاصة قد فتحتها مسبقًا أولًا. لا تسجّل الخروج أبدًا من واجهة سطر الأوامر للقيام بذلك: فتسجيل الخروج يلغي تسجيل الدخول المحفوظ، وسيتعيّن إعادة إضافة ذلك الحساب مرة أخرى.

لنسخ معلومات تسجيل الدخول لاشتراكاتك إلى جهاز Omarchy آخر عبر SSH، شغّل `omarchy agent account copy user@laptop`. يوفّر المُرسل جهاز استقبال مؤقتًا عندما لا يمتلك الوجهة جهاز استقبال مُثبَّتًا، بحيث تتمكن أجهزة Omarchy الأقدم من تلقي الحسابات دون تحديث. تأخذ أجهزة الاستقبال المُثبَّتة الأسبقية. ينسخ هذا كل اشتراكات Claude وCodex وGrok؛ أضف أسماء المزوّدين لاختيارها، كما في `omarchy agent account copy laptop claude`. تتطابق أسماء الحسابات ومعرّفات الأوامر مع المصدر، بما في ذلك الحسابات الموجودة بالفعل على الوجهة. تتلقى حسابات الوجهة غير ذات الصلة لاحقة رقمية إذا تعارضت أسماؤها، وتبقى الإعدادات والمهارات والإضافات وسجل المحادثات محلية لكل جهاز.

تُحفظ بيانات اعتماد الوجهة الحالية. تتم مزامنة اسم حساب مصدر مسجّل الدخول هناك بالفعل دون استبدال بيانات اعتماده؛ وتُضاف حسابات أخرى بجانبه. لاستبدال بيانات الاعتماد المحفوظة للحسابات المطابقة، استخدم `omarchy agent account copy --replace laptop claude` بعد إنهاء جلسات ذلك الحساب على الوجهة. تحصل الوجهة الجديدة أيضًا على الحساب النشط من المصدر وتفضيلات التبديل؛ وتحتفظ الوجهة القائمة بما لديها.

تسافر بيانات الاعتماد عبر SSH وتُخزّن في ملفات خاصة على الوجهة، لذا انسخ فقط إلى أجهزة تثق بها. هذه نسخة لمرة واحدة، وليست مزامنة مستمرة. يمكن لجهاز آخر تدوير رموز تحديث Codex، ما يترك تسجيل دخول منسوخًا بحاجة إلى التجديد؛ تبقى عمليات تسجيل الدخول المنفصلة هي الخيار الأكثر موثوقية للاستخدام المتزامن على عدة أجهزة. راجع [إرشادات Codex للتوثيق بالحساب](https://developers.openai.com/codex/auth/ci-cd-auth).

حساب واحد لكل مزوّد هو النشط، وكل جلسة جديدة تبدأ به: `cx` و`cy` و`claude` أو `codex` أو `grok` العادية، وأي شيء يُشغَّل عبر `omarchy agent`، والبرامج النصية أو المحرّرات التي تعثر على واجهة سطر الأوامر على `PATH`. بدّل باستخدام `omarchy agent account use work` (والعودة باستخدام `omarchy agent account use main`)، أو في اللوحة بالضغط على رقم حساب ثم `Enter` (أو النقر على زر Use الخاص به). تبقى الجلسات التي تعمل بالفعل على الحساب الذي بدأت به. تُشارك سجل المحادثات والإعدادات والمهارات والإضافات عبر الحسابات، لذا فإن `claude --continue` في المجلد نفسه يتابع من حيث توقفت على الحساب الجديد.

مع أكثر من حساب واحد، تعرض اللوحة حدود كل حساب جنبًا إلى جنب، مع وضع علامة على النشط. بشكل افتراضي يُعلمك Omarchy عندما يتجاوز الحساب النشط 95% من حدّ ما، والنقر على الإشعار يبدّل إلى الحساب الذي لديه أكبر مساحة فارغة. مرّر المؤشر فوق سطر حساب في اللوحة وانقر على Autoswitch الذي يظهر بجانب Use (أو اضغط `m`)، أو شغّل `omarchy agent account mode auto`، ليقوم بالتبديل من تلقاء نفسه بدلًا من ذلك؛ وبينما يكون قيد التشغيل، يحل Autoswitch محل Use، والنقر عليه مرة أخرى يعود إلى الإشعار. أضف رقمًا لتغيير الحدّ، كما في `omarchy agent account mode auto 90`. إذا كان كل حساب فوق الحدّ، فستسمع عن ذلك مرة واحدة، إضافة إلى أي حساب يصبح حرًا أولًا. وبينما يكون حساب نشط ضمن 15 نقطة من حدّه (80% افتراضيًا)، تُفحص حدوده كل ثلاث دقائق بدلًا من كل 15 دقيقة.

يُظهر `omarchy agent account list` كل حساب وآخر حدوده، وينسى `omarchy agent account remove work` حسابًا واحدًا، ويعيد `omarchy agent account rename primary Hey` تسمية حساب واحد (أو انقر على اسم حساب في اللوحة). تعمل هذه الأوامر على حسابات وكيلك الافتراضي؛ للوصول إلى المزوّد الآخر، سمّه أولًا، كما في `omarchy agent account use codex side`. تسجيل الدخول الذي كان لديك بالفعل في `~/.claude` أو `~/.codex` هو حساب _Main_ ويبقى حيث هو. يمكن أن يُظهر حساب لم يُستخدم لأكثر من حوالي ثماني ساعات _Sign-in required_؛ انقر عليه لتسجيل دخول ذلك الحساب مرة أخرى هناك مباشرةً في اللوحة، أو ابدأ جلسة فيه، ما يجدد تسجيل الدخول من تلقاء نفسه. خوادم MCP التي كانت لديك عندما أُضيف حساب ما تنتقل معه إليه، لكن الخوادم التي تضيفها لاحقًا باستخدام `claude mcp add` تصل فقط إلى الحساب الذي أضفتها فيه. لا يتبع Claude Desktop والأدوات المهيّأة بمسار مطلق إلى ملف تنفيذي لواجهة سطر الأوامر هذا التبديل. يأخذ `CLAUDE_CONFIG_DIR` أو `CODEX_HOME` أو `GROK_HOME` الصريح الأسبقية على الحساب المحدّد.

### تشخيص الأعطال

يراقب Omarchy systemd-coredump لأعطال العمليات. عندما يحدث خطأ تجزئة في شيء ما، ستصلك إشعار "Process crashed" — انقر عليه، وسيُسلَّم العطل إلى وكيلك الافتراضي مع مهارة diagnose-crash الخاصة بـ Omarchy، التي ترشد الوكيل خطوة بخطوة لتحديد الحقائق من تفريغ الذاكرة الأساسية والحسم فيما إذا كان العطل يستحق الإبلاغ عنه إلى المصدر. يمكنك أيضًا تشغيله يدويًا في مقابل أي PID من `coredumpctl list` باستخدام `omarchy agent crash <pid>`.

المراقبة قيد التشغيل افتراضيًا. أوقفها ضمن _Trigger > Toggle > Crash Capture_ (أو باستخدام `omarchy toggle crash-capture`) وستتوقف الإشعارات؛ ويبقى `omarchy agent crash <pid>` يعمل يدويًا.

يمكن أيضًا إسكات الأعطال لبرنامج واحد في كل مرة، وهو ما يقدمه لك التشخيص في النهاية. يوقف `omarchy crash mute hyprland` الإشعارات لذلك البرنامج فقط، ويعيدها `omarchy crash mute hyprland off`، ويدرج `omarchy crash mute` بمفرده ما أسكتّه. إنه يأخذ مسار الملف التنفيذي بسهولة كأخذه باسمه، لذا فإن `omarchy crash mute /usr/bin/hyprland` يفعل الشيء نفسه. ضع اسمًا يحتوي على مسافة بين علامتي اقتباس، كما في `omarchy crash mute 'Some App'`. تستمر كل الأمور الأخرى في الإشعار، ويبقى البرنامج المُسكَت يتعطل — فهذا يخفي التذكير، ولا يصلح شيئًا.

### تطبيقات سطح المكتب

تحمل قائمة _Install > AI_ أيضًا بعض تطبيقات الذكاء الاصطناعي الرسومية: تطبيق ChatGPT لسطح المكتب، وتطبيق Claude لسطح المكتب (النسخة التجريبية لـ Linux من Anthropic، مع علامات تبويب Chat وCowork وClaude Code)، وGrok Bot للدردشة مع نماذج xAI، وHerdr Desktop، وHermes Desktop، وOpenClaw، وتطبيق Perplexity لسطح المكتب، وT3 Code. Grok Bot هو تطبيق الدردشة لسطح المكتب. ووكيل البرمجة هو أمر `grok`.

Hermes Desktop هو التطبيق الذي يجب أن تعرفه، لأن الجهاز يمتلك Hermes واحدًا، وهو الخاص بالتطبيق: لا يُثبَّت Hermes أبدًا إلا عبر التطبيق، وأمر `hermes` الذي يشغّله الوكيل الافتراضي هو الخاص بالتطبيق. يعمل اختيار Hermes كوكيل افتراضي على تثبيت الشيء نفسه الذي يفعله إدخال _Install > AI_: الحزمة، وبيئة تشغيل Hermes تحت `~/.hermes` تُعدّ بواسطة مثبِّت Hermes الخاص، والتي تستغرق بضع دقائق في المرة الأولى. بيئة التشغيل تلك هي الـ Hermes الوحيدة التي تستخدمها أمرية `hermes` الطرفية والوكيل الافتراضي والتطبيق، وتُحدِّث نفسها باستخدام `hermes update` بدلًا من انتظار إصدار Omarchy. كما أن تثبيتها يمنح Hermes سمة Omarchy كجلد اسمه `omarchy`، تتبعها كل واجهات Hermes عندما تبدّل السمات؛ اختر أخرى ضمن إعدادات Appearance في Hermes أو باستخدام `/skin` إذا كنت تفضّل ألا تفعل، ويترك Omarchy ذلك الخيار وشأنه. إزالة التطبيق ضمن _Remove > AI_ تُغلق Hermes أولًا، بما في ذلك البوّابة، وتأخذ بيئة التشغيل تلك معها، وتحتفظ بدردشاتك وذكرياتك والمهارات التي كتبتها Hermes لنفسها ما لم تطلب غير ذلك: إنها تسأل، مع افتراض الإجابة بالنفي، ما إذا كان يجب أن تذهب تلك البيانات وإعدادات اتصالك أيضًا.

تجربة OpenClaw لسطح المكتب هي واجهة Control UI الخاصة به، التي تُفتح كتطبيق ويب مدعوم ببوّابته المحلية الخاصة. يعيش OpenClaw في `~/.openclaw` ويُحدِّث نفسه: استخدم زر "Update Gateway" في Control UI أو شغّل `openclaw update`، وستُعاد تشغيل البوّابة على الإصدار الجديد. يختار Omarchy فقط الإصدار الذي يبدأ منه التثبيت الجديد. إزالة OpenClaw ضمن _Remove > AI_ تأخذ خدمة البوّابة والتطبيق معها ثم تسأل ما إذا كان يجب أن يذهب `~/.openclaw` أيضًا، لأنه يحتوي على دردشاتك وبيانات اعتمادك إلى جانب OpenClaw نفسه وبيئات تشغيل الإضافات التي ينزّلها؛ الخيار الافتراضي يحتفظ به، وتثبيت OpenClaw مرة أخرى يعيد التقاطه.

Herdr Desktop هو تطبيق سطح المكتب [Herdr](https://herdr.dev): مساحات وعلامات تبويب وألواح من الطرفيات ووكلاء البرمجة التي تستمر في العمل في نواته عندما تغلق النافذة. يأتي من مثبِّت Herdr الخاص وليس من حزمة، لذا فهو يعيش في `~/.local/share/herdr-app`، ويحضر نواته معه في `~/.local/bin/herdr-core` عندما لا تمتلك واحدًا بعد، ويُحدِّث كليهما بنفسه. يجلس بجانب أمر `herdr` الذي يشحنه Omarchy على `Super + Ctrl + Return` بدلًا من استبداله، ويحصل على مفاتيح ذلك الأمر المباشرة: يقسم `Alt + Return` و`Alt + Shift + Return` لوحًا إلى أسفل أو إلى اليمين، ويُغلقه `Alt + Escape`، وينتقل `Ctrl + Alt + Arrow` بين الألواح، ويختار `Alt + 1..9` و`Alt + Left/Right` علامة تبويب، ويتحرك `Alt + Up/Down` بين المساحات. يختار `Ctrl + 1..9` مساحة وينتقل `Alt + Shift + Up/Down` خطوة بخطوة عبر الوكلاء. تبقى مفاتيح بادئة `Ctrl + Space` للطرفية فقط، لأن التطبيق لا يستطيع إمساك مفتاح Ctrl عادي لتسلسل. يكتب Omarchy هذه إلى `~/.config/herdr-app/keys.json`، ويعيدها `omarchy-refresh-herdr-app`. تثبيته يختار سمة Omarchy من Herdr، التي تتبع سمة Omarchy الخاصة بك من ذلك الحين فصاعدًا. يحتفظ Herdr بسمة واحدة للوضع الفاتح وواحدة للداكن، لذا بعد التبديل بين سمة Omarchy داكنة وفاتحة، اختر Omarchy في منتقي سمات Herdr مرة أخرى للوضع الآخر.

يعمل T3 Code من إصدار AppImage الرسمي الخاص به في `~/.local/share/t3code` بدلًا من حزمة، لذا يُحدِّث نفسه. تثبيته يسألك ما إذا كنت تريد البدء على قناة Stable أم Nightly؛ بدّل لاحقًا في إعدادات T3 Code. تعيش سلاسلك وإعداداتك في `~/.t3`، وإزالة T3 Code ضمن _Remove > AI_ تأخذها معه.

### النماذج المحلية

شغّل نموذجًا مفتوحًا على جهازك الخاص لوكلاء برمجتك. تبقى موجّهاتك وشفرتك على الجهاز؛ لا يغادره أي شيء يُرسل إلى النموذج. ابدأ باستخدام:

```bash
omarchy agent local use best
```

أو، في لوحة الوكلاء في الشريط العلوي، اختر + ثم Local AI، التي تظهر عندما يناسب نموذج هذا الجهاز. في المرة الأولى، هذا يُثبِّت Podman، الذي يشغّل النماذج، وعلى جهاز NVIDIA مجموعة أدوات حاويات NVIDIA، التي تمنحهم GPU. ثم يختار Omarchy النموذج الموصى به لهذا الجهاز، وينزّله، ويشغّله. توقّع تنزيلًا بعشرات GB وأن تكون معظم ذاكرة الجهاز قيد الاستخدام أثناء تشغيل النموذج: يستخدم Flash Next حوالي 100 GiB مع سياقه الكامل 256K. إذا كانت نماذج أخرى تحمل الذاكرة التي يحتاجها، فسيُعَدّ متوقفًا، جاهزًا للبدء بمجرد إيقاف واحد. يتوقف النموذج عند تسجيل الخروج؛ أوقفه بنفسك عندما تحتاج الذاكرة لشيء آخر.

يُظهر `omarchy agent local list` الخيارات ويشرح سبب عدم ملاءمة بعضها. لإعداد واحد آخر، شغّل `omarchy agent local use <recipe>`. اليوم، `qwen3.8-flash-next-gufo` و`qwen3.8-27b-gufo` متاحان لأجهزة Strix Halo بسعة 128 GB؛ يأخذ 27B حوالي 40 GiB، لذا فهو يترك مجالًا لعمل آخر. تصل الوصفات والتوصيات الجديدة مع `omarchy update`، عبر الحزمة.

يحصل كل نموذج تقوم بإعداده على سطره الخاص في لوحة الوكلاء، بجانب اشتراكاتك: التشغيل لبدئه، والإيقاف المؤقت لإيقافه وتحرير ذاكرته، وزر الطرفية لفتح وكيلك عليه. يمكن تشغيل عدة منها في آنٍ واحد عندما تتسع ذاكرتهم معًا؛ وإذا لم يتسع واحد منها، يخبرك Omarchy بتشغيل النموذج الذي يجب إيقافه. اسحب السطور لإعادة ترتيبها، واضغط Delete على سطر محدّد لإزالة نموذج وتنزيله.

من سطر الأوامر، يفعل `omarchy agent local start <recipe>` و`omarchy agent local stop <recipe>` الشيء نفسه، ويعرض `omarchy agent local status` كل نموذج، ويفتح `omarchy agent --local` وكيلك الافتراضي على آخر نموذج بدأتَه (pi إذا كان وكيلك الافتراضي لا يستطيع استخدام نموذج محلي). يمكن لأي عميل متوافق مع OpenAI الاتصال أيضًا: يعرض `status` عنوان كل نموذج (الأول هو `http://127.0.0.1:11435/v1`)، واسم الوصفة هو النموذج، والمفتاح موجود في `~/.config/omarchy/agent-local/key`.

يحذف `omarchy agent local remove <recipe>` نموذجًا والتنزيلات التي لا يستخدمها أي نموذج آخر.

تُوسم بيئات تشغيل الجهات الخارجية بناشرها. يشغّل Omarchy كل نموذج دون وصول إلى الشبكة.

### نماذج LLM المحلية

يوصي Omarchy بطريقتين لتشغيل نماذج LLM المحلية: LM Studio وOllama. يوفّر LM Studio واجهة GUI للعثور على النماذج ذات الأوزان المفتوحة وتثبيتها وتشغيلها. إنها طريقة رائعة للبدء بسهولة. يقدّم Ollama واجهة CLI للقيام بذلك بطريقة مماثلة. ولكن إذا كنت جديدًا على النماذج المحلية، سأبدأ بـ LM Studio. يمكنك تثبيت أي منهما ضمن _Install > AI_ في Omarchy Menu.

### مهارة Omarchy

تساعد مهارات الوكيل الذكاء الاصطناعي على استخدام أدوات محددة بطريقة محددة، ويأتي Omarchy مع مهارة افتراضية لتخصيص النظام. مثل تعديل تكوين Hyprland الخاص بك، أو ضبط الشريط، أو حتى إنشاء سمة جديدة من الصفر. تُرتبط رمزيًا في مجلدات مهارات Claude Code (`~/.claude/skills`) وCodex (`~/.codex/skills`) وPi (`~/.pi/agent/skills`) وAntigravity (`~/.gemini/config/skills`) وHermes (`~/.hermes/skills` وكل `~/.hermes/profiles/*/skills`)، والموقع العام `~/.agents/skills`، لذا تلتقطها معظم الأطر تلقائيًا.

لكن يجب أن تعامل هذه المهارة على أنها تجريبية. ستستخدمها نماذج مختلفة بتأثيرات مختلفة. من الأفضل تشغيلها في وضع الخطة أولًا، حتى تكون لديك فكرة عما يرغب الوكيل في تغييره. وبعد ذلك كن مستعدًا للتراجع عن التغييرات أو حتى استدعاء `omarchy reinstall configs`، إذا أحدث الوكيل فوضى في كل شيء.
