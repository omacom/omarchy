# الذكاء الاصطناعي

تتضمن Omarchy مشغّلات لوكلاء البرمجة أدناه دون أن تختار لك واحدًا افتراضيًا. شغّل أمرًا لتثبيت واجهة سطر الأوامر الخاصة به عند أول استخدام، ثم قم بالمصادقة عند مطالبتك بذلك. Hermes هو الاستثناء: لا يُثبَّت له أي شيء عند أول استخدام، واختياره يُثبّت Hermes Desktop، كما يشرح قسم _تطبيقات سطح المكتب_ أدناه.

### تثبيت الوكلاء وتحديثهم

باستثناء Hermes، يستخدم هؤلاء الوكلاء التثبيت الكسول الخاص بـ mise: أول تشغيل يثبّت واجهة سطر الأوامر، والتشغيلات اللاحقة تعيد استخدامها. كما يتحقق mise من وجود إصدار جديد لوكيل مثبّت مرة واحدة على الأكثر كل أربع ساعات، قبل بدء تشغيله مباشرة أو في الخلفية عند موجه shell. إذا فشل ذلك التحديث أو كنت غير متصل بالإنترنت، يعمل الإصدار المثبّت. يحدّث `omarchy update` الوكلاء المثبّتين مع بقية Omarchy، ويحدّث `mup` الأدوات التي يديرها mise فقط.

لا يحدّث المحدّث الخاص بالوكيل نفسه، مثل `claude update` أو `codex update` أو زر تحديث داخل تطبيق، التثبيت الذي يديره mise. يفشل `codex update`، ويمكن أن يفيد `claude update` بالنجاح بينما يثبّت نسخة منفصلة لا يتتبعها mise. إذا كنت تفضّل استخدام المثبّت والمحدّث الأصليين للوكيل، أضفه إلى `disable_tools`؛ راجع [الأدوات المثبتة مسبقًا لواجهة سطر الأوامر](18-development-tools.md#preinstalled-cli-tools).

لتثبيت جميع الأدوات الكسولة المهيأة قبل أن تحتاج إليها، شغّل `mise install --include-lazy`. يشمل ذلك أدوات واجهة سطر الأوامر الافتراضية الأخرى في Omarchy إضافة إلى الوكلاء. راجع [الأدوات المثبتة مسبقًا لواجهة سطر الأوامر](18-development-tools.md#preinstalled-cli-tools) لتثبيت أداة واحدة أو لاستخدام تثبيتك الخاص.

يُثبَّت `grok` عبر حزمة `grok` الرسمية الخاصة بـ mise، بالطريقة نفسها مثل `claude` و`codex`. شغّل `grok`، أو اختره ضمن _الوكيل > أداة التشغيل_. تجاوز مثبّت `curl | bash` على x.ai. فذلك المسار يضع نسخة ثانية في `~/.grok/bin`، ويقدّمها في `PATH`، ويستبدل غلاف Omarchy.

يفتح `dsh` واجهة متصفحه على `127.0.0.1:3080`، مع جعل دليل التشغيل مساحة عمله الافتراضية. لا تقبل واجهة متصفحه موجه بدء، لذا يفتحها `omarchy agent prompt` مع وضع الموجه في الحافظة للصقه. يبدؤه Omarchy بإعداد أذونات عدم الموافقة المسبقة الخاص بـ DeepSeek. يرفع DeepSeek Harness سجلات الجلسة إلى DeepSeek عند استخدامك واجهة برمجة تطبيقات النموذج الرسمية الخاصة به؛ عطّل ذلك ضمن _الإعدادات > عام > رفع سجل الجلسة_ في واجهة متصفحه. تُرفع الملاحظات التي ترسلها إليه مع الجلسة أيضًا، ما لم تبدأه بـ `DSH_TELEMETRY_MODE=DISABLED`.

### الوكيل الافتراضي

اختر وكيلك الافتراضي بـ `omarchy default agent <name>` أو ضمن _الوكيل > أداة التشغيل_ في قائمة Omarchy (`Super + Space`). إذا لم يكن الوكيل مثبّتًا بعد، فإن اختياره يثبّته أولًا. ستدعوك Omarchy جديدة إلى اتخاذ هذا الاختيار بإشعار يظهر مرة واحدة.

يحاول اختيار Claude أيضًا إعداد إضافة متصفحه لـ Chromium وChrome وBrave وBrave Origin وEdge. ينطبق إعداد الإضافة على جميع المستخدمين وقد يطلب كلمة مرور النظام الخاصة بك؛ إلغاء تثبيت الإضافة أو فشله لا يمنع اختيار Claude وتشغيله. أعد تشغيل متصفحك، وفعّل الإضافة إذا طُلب منك ذلك، وسجّل الدخول إلى Claude لإنهاء توصيلها. شغّل `/chrome` في Claude للتحقق من الاتصال. لا يدعم Firefox وZen هذه الإضافة. إذا كان Claude وكيلك الافتراضي بالفعل قبل إضافة هذا الإعداد، اختره مرة أخرى لتثبيت الإضافة.

بمجرد أن تختار، يطلق `Super + Shift + Ctrl + A` الوكيل الافتراضي في نافذة طرفية مخصصة (أو يعرض المنتقي إذا لم تختر بعد). يمكنك أيضًا إطلاقه مباشرة في مهمة بـ `omarchy agent prompt "Review this project"`. لا يقبل Freebuff وDeepSeek Harness موجه بدء، لذا يفتحان مع وضع الموجه في الحافظة للصقه بدلًا من ذلك. يعمل الوكلاء الذين يُطلقون بهذه الطريقة دون مراقبة في أوضاع عدم التوقف للسؤال الخاصة بكل منهم، لذا كن مستعدًا لأن يقوموا بأشياء فعلًا! لا يمتلك MiniMax Code مثل هذا الوضع لجلساته التفاعلية، لذا يطلب الأذونات كالمعتاد. وبما أن الوكلاء يرفضون تذكّر الثقة لدليلك الرئيسي، تبدأ عمليات الإطلاق من `$HOME` في `~/Work` بدلًا من ذلك.

توجد اختصارات طرفية أيضًا: يشغّل `a` الوكيل الافتراضي ضمن الطرفية الحالية، بينما تبدأ `c` و`cx` و`cy` كلًا من OpenCode وClaude Code وCodex مباشرة (مجددًا في أوضاع الموافقة التلقائية الخاصة بها). تتزامن تغييرات السمة مع الوكلاء أيضًا: يتبع كل من Claude Code وPi وOpenCode وHermes (بمجرد أن تثبّته Omarchy) تغييرك لسمة Omarchy.

### تعليمات وكيلك

تذهب القواعد الشخصية لكل وكيل في `~/.agents/AGENTS.md`، بجانب المهارات المشتركة في `~/.agents/skills`. افتحه ضمن _الوكيل > التعليمات_، الذي يربطه أيضًا بكل أداة تشغيل تحتفظ بملفها العام الخاص: `~/.claude/CLAUDE.md` و`~/.codex/AGENTS.md` و`~/.pi/agent/AGENTS.md` و`~/.config/opencode/AGENTS.md` و`~/.copilot/copilot-instructions.md` الخاص بـ Copilot، وهكذا. يقرأ Crush وAmp رابط `~/.config/AGENTS.md`، بينما يقرأ omp وKimi وDeepSeek Harness ملف `~/.agents/AGENTS.md` مباشرة. اختيار وكيل افتراضي يربطه أيضًا. يصبح ملف تعليمات كان لديك بالفعل هو الملف المشترك إذا لم يكن هناك واحد بعد؛ وإلا يُحتفظ به بجانب الرابط باسم `.bak`. شغّل `omarchy agent instructions` لإعادة الربط بعد تثبيت وكيل آخر.

### لوحة الوكلاء

يحتوي الشريط العلوي على أيقونة للوكلاء. قبل أن تُعدّ وكيلًا، ترشدك لوحته خطوة بخطوة لتسجيل الدخول إلى Claude أو Codex أو Grok، ويصبح الأول منها وكيلك الافتراضي. بعد ذلك، تضع اللوحة كل اشتراك في صفحة واحدة: كل وكيل وحساب مع خطته، ومقياس لكل من حدود جلسته البالغة 5 ساعات وحدوده الأسبوعية مع الوقت المتبقي حتى إعادة تعيينها (مرّر المؤشر للاطلاع على النسبة المئوية الدقيقة)، أو الرصيد المدفوع مسبقًا المتبقي، تحت سطر يتناوب عبر ما استخدمته عبرها جميعًا، مثل الرموز هذا الأسبوع ونموذجك الأكثر استخدامًا. ضمن _اصنع شيئًا_ تقدّم موجهات بداية لسمة أو إضافة أو تطبيق جديد تسلّم المهمة إلى وكيلك الافتراضي. تُبنى التطبيقات بالطريقة التي بُنيت بها تطبيقات Omarchy الخاصة Hype وMonologue وOmacut، بـ C++ وQt Quick، باتباع مهارة وكيل omarchy-app، وتأتي المترجمات وأجزاء Qt التي تحتاجها مثبّتة. تُغطّى Claude Code وCodex وGrok وKimi وCursor ومخصصات Grok Bot الخاصة به وGitHub Copilot وMuse وAntigravity وKimchi وDevin جاهزة مع حدودها، ويُظهر Hermes وMistral Vibe وQwen Code جلساتهم ورموزهم بمجرد استخدامك لهم. تظهر أيضًا خطط المزودين ومفاتيحهم التي تستخدمها عبر pi أو omp أو opencode: OpenCode Zen وGo، وخطة Z.ai GLM Coding Plan، وOllama Cloud، وخطة MiniMax Token Plan، وSynthetic مع حدودها؛ وFireworks وOpenRouter وDeepSeek مع أرصدتها المدفوعة مسبقًا؛ والنماذج التي تشغّلها على أجهزتك الخاصة ضمن النماذج المحلية. يُحسب كل وكيل مرة واحدة، تحت من يفوتره، مهما كان عدد أدوات التشغيل التي تشغّله عبرها.

انقر بزر الفأرة الأيسر على أيقونة الشريط للوحة، وانقر بزر الفأرة الأيمن لإطلاق وكيلك الافتراضي. تُعاد إنشاء سجلات الاستخدام وراءها كل 15 دقيقة بـ `omarchy agent usage-update`، ويمكن للوحة حتى دمج الاستخدام من أجهزتك الأخرى عبر مجلد متزامن. راجع README ضمن `$OMARCHY_PATH/shell/plugins/agents/` للاطلاع على الإعدادات الكاملة.

### اشتراكات متعددة

إذا كنت تدفع مقابل أكثر من خطة واحدة لـ Claude أو Codex أو Grok — خطة Max شخصية وخطة عمل، على سبيل المثال — يمكن لـ Omarchy إبقاءها جميعًا مسجلة الدخول والتنقل بينها. أضف اشتراكًا بعلامة + في لوحة الوكلاء، التي ترشدك خطوة بخطوة هناك مباشرة، أو بـ `omarchy agent account add claude Work` (أو `codex`، أو `grok`). يثبّت واجهة سطر الأوامر إذا كانت مفقودة. يسجّل الحساب الأول لمزود الدخول عبر متصفحك العادي، حيث تبحث واجهة سطر الأوامر دائمًا. وكل حساب بعد ذلك يسجّل الدخول عبر نافذة خاصة، حتى لا يُلتقط بالخطأ الحساب الذي سجّل متصفحك الدخول إليه بالفعل؛ سجّل الدخول هناك بالحساب الذي تضيفه، وأغلق أي نافذة خاصة مفتوحة لديك بالفعل أولًا. لا تسجّل الخروج أبدًا من واجهة سطر الأوامر للقيام بذلك: تسجيل الخروج يلغي تسجيل الدخول المحفوظ، وسيتعين إضافة ذلك الحساب مرة أخرى.

لنسخ تسجيلات دخول اشتراكك إلى جهاز Omarchy آخر عبر SSH، شغّل `omarchy agent account copy user@laptop`. يوفّر المرسل مستقبلًا مؤقتًا عندما لا يكون لدى الوجهة واحد مثبّت، بحيث يمكن لأجهزة Omarchy الأقدم استلام الحسابات دون تحديث. تأخذ المستقبلات المثبّتة الأسبقية. ينسخ هذا جميع اشتراكات Claude وCodex وGrok؛ أضف أسماء المزودين لتحديدها، كما في `omarchy agent account copy laptop claude`. تتطابق أسماء الحسابات ومعرفات الأوامر مع المصدر، بما في ذلك الحسابات الموجودة بالفعل على الوجهة. تتلقى حسابات الوجهة غير ذات الصلة لاحقة رقمية إذا تعارضت أسماؤها، وتبقى الإعدادات والمهارات والإضافات وسجل المحادثات محلية لكل جهاز.

تُحتفظ ببيانات اعتماد الوجهة الموجودة. الحساب المصدري الذي سجّل الدخول هناك بالفعل تُزامن تسميته دون استبدال بيانات اعتماده؛ وتُضاف حسابات أخرى بجانبه. لاستبدال بيانات الاعتماد المحفوظة للحسابات المطابقة، استخدم `omarchy agent account copy --replace laptop claude` بعد إنهاء جلسات ذلك الحساب على الوجهة. تحصل الوجهة الجديدة أيضًا على الحساب النشط وتفضيلات التبديل الخاصة بالمصدر؛ وتحتفظ الوجهة القائمة بتفضيلاتها الخاصة.

تنتقل بيانات الاعتماد عبر SSH وتُخزّن في ملفات خاصة على الوجهة، لذا انسخ فقط إلى أجهزة تثق بها. هذه نسخة لمرة واحدة، وليست مزامنة مستمرة. يمكن لجهاز آخر تدوير رموز تحديث Codex، مما يترك تسجيل دخول منسوخًا بحاجة إلى تجديد؛ تبقى تسجيلات الدخول المنفصلة الخيار الأكثر موثوقية للاستخدام المتزامن على عدة أجهزة. راجع [إرشادات مصادقة حساب Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

يكون حساب واحد لكل مزود نشطًا، وتبدأ كل جلسة جديدة به: `cx` و`cy` و`claude` أو `codex` أو `grok` العادية، وأي شيء يُطلق عبر `omarchy agent`، والبرامج النصية أو المحررات التي تجد واجهة سطر الأوامر على `PATH`. بدّل بـ `omarchy agent account use work` (وعُد بـ `omarchy agent account use main`)، أو في اللوحة بالضغط على رقم حساب ثم `Enter` (أو النقر على زر الاستخدام الخاص به). تبقى الجلسات التي تعمل بالفعل على الحساب الذي بدأت به. يُشارك سجل المحادثات والإعدادات والمهارات والإضافات عبر الحسابات، لذا يستمر `claude --continue` في المجلد نفسه من حيث توقفت على الحساب الجديد.

مع أكثر من حساب واحد، تعرض اللوحة حدود كل حساب جنبًا إلى جنب، مع تمييز الحساب النشط. تُعلمك Omarchy افتراضيًا عندما يتجاوز الحساب النشط 95% من حد ما، والنقر على الإشعار يبدّل إلى الحساب ذي أكبر هامش متاح. مرّر المؤشر على سطر حساب في اللوحة وانقر على التبديل التلقائي الذي يظهر بجانب الاستخدام (أو اضغط `m`)، أو شغّل `omarchy agent account mode auto`، ليبدّل من تلقاء نفسه بدلًا من ذلك؛ بينما هو مفعّل، يحل التبديل التلقائي محل الاستخدام، والنقر عليه مرة أخرى يعود إلى الإشعار. أضف رقمًا لتغيير العتبة، كما في `omarchy agent account mode auto 90`. إذا تجاوز كل حساب العتبة، ستسمع عن ذلك مرة واحدة، مع أي حساب سيتحرر أولًا. بينما يكون الحساب النشط ضمن 15 نقطة من عتبته (80% افتراضيًا)، تُفحص حدوده كل ثلاث دقائق بدلًا من كل 15 دقيقة.

يعرض `omarchy agent account list` كل حساب وحدوده الأخيرة، وينسى `omarchy agent account remove work` حسابًا واحدًا، ويعيد `omarchy agent account rename primary Hey` تسمية واحد (أو انقر على اسم حساب في اللوحة). تعمل هذه الأوامر على حسابات وكيلك الافتراضي؛ للوصول إلى المزود الآخر، سمّه أولًا، كما في `omarchy agent account use codex side`. تسجيل الدخول الذي كان لديك بالفعل في `~/.claude` أو `~/.codex` هو الحساب _الرئيسي_ ويبقى حيث هو. يمكن لحساب تُرك دون استخدام لأكثر من حوالي ثماني ساعات أن يُظهر _تسجيل الدخول مطلوب_؛ انقر عليه لتسجيل دخول ذلك الحساب مرة أخرى مباشرة في اللوحة، أو ابدأ جلسة فيه، مما ينعش تسجيل الدخول من تلقاء نفسه. تأتي خوادم MCP التي كانت لديك عند إضافة حساب معها إليه، لكن تلك التي تضيفها لاحقًا بـ `claude mcp add` تصل فقط إلى الحساب الذي أضفتها فيه. لا يتبع Claude Desktop والأدوات المهيأة بمسار مطلق إلى ثنائي واجهة سطر الأوامر التبديل. يأخذ `CLAUDE_CONFIG_DIR` أو `CODEX_HOME` أو `GROK_HOME` الصريح الأسبقية على الحساب المحدد.

### تشخيص الأعطال

تراقب Omarchy systemd-coredump لأعطال العمليات. عندما يحدث خطأ تجزئة لشيء ما، ستتلقى إشعار «تعطّلت عملية» — انقر عليه، وسيُسلّم العطل إلى وكيلك الافتراضي مع مهارة diagnose-crash الخاصة بـ Omarchy، التي ترشد الوكيل عبر إثبات الوقائع من تفريغ النواة وتقرير ما إذا كان العطل يستحق الإبلاغ عنه إلى المطوّرين الأصليين. يمكنك أيضًا تشغيله يدويًا ضد أي PID من `coredumpctl list` بـ `omarchy agent crash <pid>`.

المراقبة مفعّلة افتراضيًا. عطّلها ضمن _المشغّل > التبديل > التقاط الأعطال_ (أو بـ `omarchy toggle crash-capture`) وستتوقف الإشعارات؛ ما يزال `omarchy agent crash <pid>` يعمل يدويًا.

يمكن أيضًا إسكات الأعطال برنامجًا واحدًا في كل مرة، وهو ما يعرضه عليك التشخيص في النهاية. يوقف `omarchy crash mute hyprland` الإشعارات لذلك البرنامج فقط، ويعيدها `omarchy crash mute hyprland off`، ويسرد `omarchy crash mute` وحده ما كتمته. يقبل مسار الثنائي بسهولة اسمه نفسها، لذا يقوم `omarchy crash mute /usr/bin/hyprland` بالشيء نفسه. ضع اسمًا يحتوي على مسافة بين علامتي اقتباس، كما في `omarchy crash mute 'Some App'`. ما يزال كل شيء آخر يُشعر، وما يزال البرنامج المكتوم يتعطل — هذا يخفي التذكير، ولا يصلح أي شيء.

### تطبيقات سطح المكتب

تحمل قائمة _التثبيت > الذكاء الاصطناعي_ أيضًا بعض تطبيقات الذكاء الاصطناعي الرسومية: تطبيق ChatGPT لسطح المكتب، وتطبيق Claude لسطح المكتب (إصدار Anthropic التجريبي لنظام Linux، مع علامات تبويب Chat وCowork وClaude Code)، وGrok Bot للدردشة مع نماذج xAI، وHerdr Desktop، وHermes Desktop، وOpenClaw، وتطبيق Perplexity لسطح المكتب، وT3 Code. Grok Bot هو تطبيق الدردشة لسطح المكتب. وكيل البرمجة هو أمر `grok`.

Hermes Desktop هو التطبيق الذي يجب أن تعرفه، لأن الجهاز لديه Hermes واحد، وهو خاص بالتطبيق: لا يُثبَّت Hermes أبدًا إلا عبر التطبيق، وأمر `hermes` الذي يشغّله الوكيل الافتراضي هو الخاص بالتطبيق. اختيار Hermes كوكيل افتراضي يثبّت الشيء نفسه الذي يثبّته إدخال _التثبيت > الذكاء الاصطناعي_: الحزمة، ووقت تشغيل Hermes ضمن `~/.hermes` يُعدّه مثبّت Hermes الخاص، الذي يستغرق بضع دقائق في المرة الأولى. وقت التشغيل ذلك هو Hermes الوحيد الذي تستخدمه أمر `hermes` الطرفي والوكيل الافتراضي والتطبيق جميعًا، ويحدّث نفسه بـ `hermes update` بدلًا من انتظار إصدار Omarchy. يمنح تثبيته أيضًا Hermes سمة Omarchy كمظهر باسم `omarchy`، تتبعه كل أسطح Hermes أثناء تبديلك للسمات؛ اختر آخر ضمن إعدادات مظهر Hermes أو بـ `/skin` إذا كنت تفضّل ألا يفعل ذلك، وتترك Omarchy ذلك الاختيار وشأنه. إزالة التطبيق ضمن _إزالة > الذكاء الاصطناعي_ تغلق Hermes أولًا، بما في ذلك البوابة، وتأخذ وقت التشغيل ذلك معها، وتحتفظ بدردشاتك وذكرياتك والمهارات التي كتبها Hermes لنفسه ما لم تخبره بخلاف ذلك: يسأل، مفترضًا لا، عما إذا كان يجب أن تذهب تلك البيانات وإعدادات اتصالك أيضًا.

تجربة OpenClaw على سطح المكتب هي واجهة تحكمه، التي تفتح كتطبيق ويب مدعوم ببوابته المحلية الخاصة. يعيش OpenClaw في `~/.openclaw` ويحدّث نفسه: استخدم زر «تحديث البوابة» في واجهة التحكم أو شغّل `openclaw update`، وستعيد البوابة التشغيل على الإصدار الجديد. تختار Omarchy فقط الإصدار الذي يبدأ منه تثبيت جديد. إزالة OpenClaw ضمن _إزالة > الذكاء الاصطناعي_ تأخذ خدمة البوابة والتطبيق معها ثم تسأل عما إذا كان يجب أن يذهب `~/.openclaw` أيضًا، لأن ذلك يحتفظ بدردشاتك وبيانات اعتمادك بجانب OpenClaw نفسه وأوقات تشغيل الإضافات التي ينزّلها؛ الافتراضي يحتفظ به، وتثبيت OpenClaw مرة أخرى يلتقطه من جديد.

Herdr Desktop هو تطبيق سطح المكتب [Herdr](https://herdr.dev): مساحات وعلامات تبويب وأجزاء من الطرفيات ووكلاء البرمجة تستمر في العمل في نواته عندما تغلق النافذة. يأتي من مثبّت Herdr الخاص بدلًا من حزمة، لذا يعيش في `~/.local/share/herdr-app`، ويجلب نواته في `~/.local/bin/herdr-core` عندما لا يكون لديك واحد بعد، ويحدّث نفسه وكليهما. يجلس بجانب أمر `herdr` الذي تشحنه Omarchy على `Super + Ctrl + Return` بدلًا من استبداله، ويحصل على مفاتيح ذلك الأمر المباشرة: يقسم `Alt + Return` و`Alt + Shift + Return` جزءًا إلى أسفل أو إلى اليمين، ويغلقه `Alt + Escape`، وينتقل `Ctrl + Alt + Arrow` بين الأجزاء، ويختار `Alt + 1..9` و`Alt + Left/Right` علامة تبويب، وينتقل `Alt + Up/Down` بين المساحات. يختار `Ctrl + 1..9` مساحة ويخطو `Alt + Shift + Up/Down` عبر الوكلاء. تبقى مفاتيح بادئة `Ctrl + Space` للطرفية فقط، لأن التطبيق لا يمكنه الاحتفاظ بمفتاح Ctrl عادي لتسلسل. تكتب Omarchy هذه إلى `~/.config/herdr-app/keys.json`، ويعيدها `omarchy-refresh-herdr-app`. يختار تثبيته سمة Omarchy الخاصة بـ Herdr، التي تتبع سمة Omarchy الخاصة بك من حينها فصاعدًا. يحتفظ Herdr بسمة واحدة للوضع الفاتح وواحدة للوضع الداكن، لذا بعد التبديل بين سمة Omarchy داكنة وفاتحة، اختر Omarchy في منتقي سمات Herdr مرة أخرى للوضع الآخر.

يعمل T3 Code من إصدار AppImage الرسمي الخاص به في `~/.local/share/t3code` بدلًا من حزمة، لذا يحدّث نفسه. يسألك تثبيته عما إذا كنت تريد البدء على قناة Stable أو Nightly؛ بدّل لاحقًا في إعدادات T3 Code. تعيش سلاسلك وإعداداتك في `~/.t3`، وإزالة T3 Code ضمن _إزالة > الذكاء الاصطناعي_ تأخذها معها.

### النماذج المحلية

شغّل نموذجًا مفتوحًا على جهازك الخاص لوكلاء البرمجة لديك. تبقى موجهاتك وشيفرتك على الجهاز؛ لا شيء يُرسل إلى النموذج يغادره. ابدأ بـ:

```bash
omarchy agent local use best
```

أو، في لوحة الوكلاء في الشريط العلوي، اختر + ثم Local AI، الذي يظهر عندما يناسب نموذج هذا الجهاز. في المرة الأولى، يثبّت هذا Podman، الذي يشغّل النماذج، وعلى جهاز NVIDIA مجموعة أدوات حاويات NVIDIA، التي تمنحها GPU. ثم تختار Omarchy النموذج الموصى به لهذا الجهاز، وتنزّله، وتبدؤه. توقّع تنزيلًا بعشرات GB ومعظم ذاكرة الجهاز قيد الاستخدام أثناء تشغيل النموذج: يستخدم Flash Next حوالي 100 GiB مع سياقه الكامل البالغ 256K. إذا كانت نماذج أخرى تحتفظ بالذاكرة التي يحتاجها، يُعدّ متوقفًا، جاهزًا للبدء بمجرد أن توقف واحدًا. يتوقف النموذج عند تسجيل الخروج؛ أوقفه بنفسك عندما تحتاج الذاكرة لشيء آخر.

يعرض `omarchy agent local list` الخيارات ويشرح لماذا لا يناسب بعضها. لإعداد آخر، شغّل `omarchy agent local use <recipe>`. اليوم، يتوفر `qwen3.8-flash-next-gufo` و`qwen3.8-27b-gufo` لأجهزة Strix Halo بسعة 128 GB؛ يأخذ 27B حوالي 40 GiB، لذا يترك مساحة لأعمال أخرى. تصل الوصفات والتوصيات الجديدة مع `omarchy update`، عبر الحزمة.

يحصل كل نموذج تُعدّه على سطره الخاص في لوحة الوكلاء، بجانب اشتراكاتك: تشغيل لبدئه، وإيقاف مؤقت لإيقافه وتحرير ذاكرته، وزر الطرفية لفتح وكيلك عليه. يمكن تشغيل عدة نماذج في وقت واحد عندما تناسب الذاكرة معًا؛ إذا لم يناسب واحد، تخبرك Omarchy أي نموذج قيد التشغيل يجب إيقافه. اسحب الأسطر لإعادة ترتيبها، واضغط Delete على سطر محدد لإزالة نموذج وتنزيله.

من سطر الأوامر، يقوم `omarchy agent local start <recipe>` و`omarchy agent local stop <recipe>` بالشيء نفسه، ويعرض `omarchy agent local status` كل نموذج، ويفتح `omarchy agent --local` وكيلك الافتراضي على آخر نموذج بدأته (pi إذا كان وكيلك الافتراضي لا يستطيع استخدام نموذج محلي). يمكن لأي عميل متوافق مع OpenAI الاتصال أيضًا: يعرض `status` عنوان كل نموذج (الأول هو `http://127.0.0.1:11435/v1`)، واسم الوصفة هو النموذج، والمفتاح في `~/.config/omarchy/agent-local/key`.

يحذف `omarchy agent local remove <recipe>` نموذجًا والتنزيلات التي لا يستخدمها أي نموذج آخر.

تُوسم أوقات تشغيل الطرف الثالث بناشرها. تشغّل Omarchy كل نموذج دون وصول إلى الشبكة.

### نماذج LLM المحلية

توصي Omarchy بطريقتين لتشغيل نماذج LLM المحلية: LM Studio وOllama. توفر LM Studio واجهة رسومية للعثور على النماذج مفتوحة الأوزان وتثبيتها وتشغيلها. إنها طريقة رائعة للبدء بسهولة. تقدّم Ollama واجهة سطر أوامر للقيام بذلك بالمثل. لكن إذا كنت جديدًا على النماذج المحلية، سأبدأ بـ LM Studio. يمكنك تثبيت أي منهما ضمن _التثبيت > الذكاء الاصطناعي_ في قائمة Omarchy.

### مهارة Omarchy

تساعد مهارات الوكلاء الذكاء الاصطناعي على استخدام أدوات محددة بطريقة محددة، وتشحن Omarchy بمهارة افتراضية لتكييف النظام. مثل تعديل إعدادات Hyprland، أو ضبط الشريط، أو حتى إنشاء سمة جديدة من الصفر. تُربط رمزيًا في دلائل مهارات Claude Code (`~/.claude/skills`) وCodex (`~/.codex/skills`) وPi (`~/.pi/agent/skills`) وAntigravity (`~/.gemini/config/skills`) وHermes (`~/.hermes/skills` وكل `~/.hermes/profiles/*/skills`)، والموقع العام `~/.agents/skills`، بحيث تلتقطها معظم أدوات التشغيل تلقائيًا.

لكن يجب أن تعامل هذه المهارة كتجريبية. ستستخدمها نماذج مختلفة بتأثيرات مختلفة. من الأفضل تشغيلها في وضع التخطيط أولًا، بحيث تكون لديك فكرة عما يرغب الوكيل في تغييره. ثم كن مستعدًا للتراجع عن التغييرات أو حتى استدعاء `omarchy reinstall configs`، إذا أحدث الوكيل فوضى في كل شيء.
