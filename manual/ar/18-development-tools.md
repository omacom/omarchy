# أدوات التطوير

## محررات بديلة

يأتي Omarchy مع Plain كمحرر افتراضي في عمليات التثبيت الجديدة ومع [Neovim](https://neovim.io/) مثبتًا مسبقًا، لكن إذا أردت شيئًا أكثر شيوعًا وألفة، فيمكنك تشغيل قائمة Omarchy (`Super + Space`) ورؤية الخيارات تحت _التثبيت > المحرر_. لدينا VSCode وCursor وZed وSublime Text وHelix وVim وEmacs مدرجة هناك. إذا لم تجد ما تبحث عنه، فاطّلع على _التثبيت > الحزمة_، وانظر ما إذا كان موجودًا في حزمة Arch (وإذا لم يكن كذلك، فجرّب _التثبيت > AUR_ للتحقق من AUR).

محرر `vi` الأصلي متاح أيضًا بشكل افتراضي. شغّل `vi filename` لتحرير ملف في الطرفية.

تُقدَّم مطابقة المظهر لـ `VSCode` و`Cursor` و`VSCodium` و`Helix`.

يمكنك تعيين المحرر الافتراضي على مستوى النظام تحت `Setup > Defaults > Editor`.

## البيئة

يدعم Omarchy إعداد مجموعة كاملة من بيئات التطوير من خلال قسم _التثبيت > التطوير_ في قائمة Omarchy (`Super + Space`). ستجد بالطبع _Ruby on Rails_، لكنك ستجد أيضًا جميع بيئات تشغيل JavaScript الرئيسية الثلاث (Node.js وBun وDeno)، بالإضافة إلى أطر عمل PHP الشائعة مثل Laravel وSymfony. آه، وهناك أيضًا Go وRust وPython وJava وElixir (مع Phoenix) و.NET وOCaml وZig وClojure وScala. إنها مجموعة واسعة جدًا!

تُدار غالبية هذه البيئات بواسطة [Mise](https://mise.jdx.dev/). إنها أداة تتيح لك تثبيت وتشغيل إصدارات متعددة من لغة برمجة على الجهاز نفسه. إنها تشبه rbenv أو rvm لـ Ruby أو virtualenv لـ Python، لكنها تعمل مع مجموعة من البيئات المختلفة.

لتثبيت Ruby، على سبيل المثال، شغّل `mise use -g ruby`، وسيؤدي ذلك إلى تثبيت Ruby وتعيينه كإعداد افتراضي عام. أو، إذا كان مشروعك يحتوي على ملف .ruby-version، فيمكنك ببساطة تشغيل `mise i` في جذر ذلك المشروع.

## أدوات CLI المثبتة مسبقًا

تأتي `uv` وNode.js و`playwright-cli` (ليقود الوكلاء متصفحًا، باستخدام Chrome المثبت) مثبتة كحزم، ويبقيها `omarchy update` محدثة مع بقية النظام. وتفصلك نقرة واحدة عن `ghui` و[Hunk](https://github.com/modem-dev/hunk) وواجهات CLI الخاصة بـ Basecamp وCloudflare وHEY تحت _التثبيت > CLI_، وعن [وكلاء البرمجة](17-ai.md) تحت _التثبيت > AI > CLI_.

يدير mise فقط بيئات التشغيل التي تعدها من _التثبيت > التطوير_؛ ولا يثبت Omarchy أي شيء من خلاله من تلقاء نفسه. شغّل `omarchy update` لتحديثها مع بقية Omarchy؛ ويحدّث الاسم المستعار `mup` الأدوات التي يديرها mise فقط. لإضافة أداة أخرى إلى إعدادك الخاص، استخدم `mise use -g <tool>`.

## Docker

يكاد [Docker](https://www.docker.com/) لا يحتاج إلى أي مقدمة. فهو يتيح لك تشغيل حاويات معزولة، ويثبت Omarchy كل ما يلزم لتشغيله بشكل جيد، بما في ذلك Docker نفسه و[Docker Compose](https://docs.docker.com/compose/).

بشكل افتراضي، حساب المستخدم الخاص بك *ليس* في مجموعة `docker`. فهذه المجموعة هي فعليًا root بدون كلمة مرور — أي شيء فيها يمكنه تشغيل `docker run -v /:/host` والسيطرة على الجهاز — لذا فإن أي نص برمجي مارق أو تبعية واحدة تعمل باسمك ستكون على بعد أمر واحد فقط من root. لذلك، في سطر الأوامر، تشغّل Docker باستخدام `sudo` (`sudo docker ps` و`sudo docker compose up`)، وتطلب الأدوات الرسومية التي تتحدث إلى الخدمة الخلفية — جهاز Windows VM — التفويض عندما تحتاج إليه. إذا أردت استعادة راحة الإعداد بدون مجموعة وكنت تفهم المقايضة، ففعّله من **الإعداد > الأمان > Sudoless Docker** (أو شغّل `omarchy-setup-security-sudoless-docker`)، وسيضيفك ذلك إلى مجموعة `docker` بعد تحذير؛ وبعد ذلك يعمل `docker` العادي والاسم المستعار `d` بدون `sudo` مرة أخرى.

يمكنك إعداد قواعد البيانات الشائعة للتطوير المحلي في Docker باستخدام _التثبيت > التطوير > Docker DB_ في قائمة Omarchy.

## GitHub CLI

[GitHub CLI](https://cli.github.com/) هو `gh`، للعمل مع المستودعات والمشكلات وطلبات السحب من الطرفية. يثبته _الإعداد > Git_ عندما تختار تسجيل الدخول إلى GitHub هناك، وبعد ذلك يستنسخ `gh repo clone org/repo` مستودعًا. شغّل `gh --help` لاستكشاف أوامره.

يثبت _التثبيت > CLI > GitHub_ أداة GitHub CLI، وهي `gh`، إلى جانب `ghui`، وهي واجهة طرفية لطلبات السحب. و[Lazygit](https://github.com/jesseduffield/lazygit) مثبت مسبقًا للعمل مع Git نفسه.
