# أدوات التطوير

## محررات بديلة

تأتي Omarchy مع Plain كمحرر افتراضي في عمليات التثبيت الجديدة ومع [Neovim](https://neovim.io/) مثبّتًا مسبقًا، ولكن إذا كنت تريد شيئًا أكثر شيوعًا وألفة، فيمكنك تشغيل Omarchy Menu (`Super + Space`) والاطلاع على الخيارات ضمن _تثبيت > المحرر_. ستجد هناك VSCode وCursor وZed وSublime Text وHelix وVim وEmacs مدرجة. وإذا لم تجد ما تبحث عنه، فجرّب _تثبيت > الحزمة_، وانظر ما إذا كان موجودًا في حزمة Arch (وإن لم يكن، فجرّب _تثبيت > AUR_ للتحقق من AUR).

محرر `vi` الأصلي متاح أيضًا مباشرة. شغّل `vi filename` لتحرير ملف في الطرفية.

تُتاح مطابقة السمة لـ `VSCode` و`Cursor` و`VSCodium` و`Helix`.

يمكنك تعيين المحرر الافتراضي على مستوى النظام ضمن `Setup > Defaults > Editor`.

## البيئة

تدعم Omarchy إعداد مجموعة كاملة من بيئات التطوير من خلال قسم _تثبيت > التطوير_ في Omarchy Menu (`Super + Space`). ستجد بالطبع _Ruby on Rails_، بل ستجد أيضًا جميع بيئات تشغيل JavaScript الرئيسية الثلاث (Node.js وBun وDeno)، بالإضافة إلى أطر عمل PHP الشائعة مثل Laravel وSymfony. أوه، وهناك أيضًا Go وRust وPython وJava وElixir (مع Phoenix) و.NET وOCaml وZig وClojure وScala. إنها مجموعة واسعة جدًا!

تُدار غالبية هذه البيئات بواسطة [Mise](https://mise.jdx.dev/). إنها أداة تتيح لك تثبيت وتشغيل إصدارات متعددة من لغة برمجة على الجهاز نفسه. إنها أشبه بـ rbenv أو rvm لـ Ruby أو virtualenv لـ Python، لكنها تعمل مع مجموعة من البيئات المختلفة.

لتثبيت Ruby، على سبيل المثال، شغّل `mise use -g ruby`، وسيؤدي ذلك إلى تثبيت Ruby وتعيينه كافتراضي عام في آن واحد. أو، إذا كان مشروعك يحتوي على ملف .ruby-version، فيمكنك ببساطة تشغيل `mise i` في جذر ذلك المشروع.

## أدوات CLI المثبّتة مسبقًا

تجعل Omarchy أدوات مثل `gh` و`uv` ومعظم [وكلاء البرمجة](17-ai.md) متاحة من خلال [التثبيت الكسول في mise](https://mise.jdx.dev/dev-tools/shims.html#lazy-tools). في أول مرة تشغّل فيها إحداها، يثبّتها mise. وبعد ذلك يتحقق وكلاء البرمجة من وجود تحديث قبل تشغيلهم، مرة واحدة على الأكثر كل أربع ساعات؛ أما الأدوات الأخرى، مثل `gh` و`uv`، فتعيد استخدام الإصدار المثبّت حتى تقوم بالتحديث.

يمكنك أيضًا فحص الإعدادات الافتراضية أو تثبيتها مسبقًا:

```bash
mise ls --current              # List the tools configured for this directory
mise install gh               # Install one tool now
mise install --include-lazy    # Install all configured tools, including lazy tools
```

شغّل `omarchy update` لتحديث الأدوات المثبّتة مع بقية Omarchy. ويحدّث الاسم المستعار `mup` الأدوات التي تديرها mise فقط. ولإضافة أداة أخرى إلى إعداداتك الخاصة، استخدم `mise use -g <tool>`.

يثبّت إعداد Python أيضًا `uv` من خلال mise. وإزالة بيئة تطوير Python تُبقي `uv` متاحة كأداة مستقلة.

### استخدام تثبيتك الخاص

تأتي أوامر mise قبل `~/.local/bin` على `PATH`، لذا فإن أداة ثبّتها بنفسك، على سبيل المثال باستخدام مثبّت Claude Code أو Cursor الخاص، ستظل تشغّل نسخة mise. كما تجد التطبيقات التي تُشغَّل من سطح المكتب أوامر mise قبل حزم النظام، لذا فإن تطبيقًا يشغّل `gh` يحصل على نسخة mise حتى لو ثبّتَّ `github-cli` باستخدام pacman، ويثبّت mise تلك النسخة في المرة الأولى. ولاستخدام نسختك بدلًا من ذلك، عطّل نسخة mise في `~/.config/mise/config.toml`. على سبيل المثال، إذا ثبّتَّ Cursor CLI بنفسك:

```toml
[settings]
disable_tools = ["cursor-agent"]
```

إذا كان لديك جدول `[settings]` بالفعل، فأضف الإدخال هناك؛ ووسّع قائمة `disable_tools` موجودة بدلًا من استبدالها. تأكد من أن تثبيتك موجود على `PATH`. استخدم اسم أداة mise، الذي قد يختلف عن أمرها: فـ `oh-my-pi` توفر `omp`، على سبيل المثال. كما يفضّل مشغّل الوكيل الافتراضي أيضًا نسخة Cursor أو Claude Code التي ثبّتها المستخدم في `~/.local/bin`.

### إزالة الإعدادات الافتراضية واستعادتها

تُزيل _إزالة > التثبيتات المسبقة_ تطبيقات الويب وواجهات TUI والتطبيقات المثبّتة مسبقًا في Omarchy، وتجعل mise يتخطى إعلانات أدوات Omarchy الخاصة بمستخدمك، عن طريق إضافتها إلى `ignored_config_paths` في `~/.config/mise/miserc.toml`. وتعيدها _تثبيت > التثبيتات المسبقة_ وتزيل ذلك السطر مرة أخرى. وتستمر الأدوات التي تعلنها بنفسك، في إعداداتك الخاصة أو في `mise.toml` خاص بمشروع، في العمل في كلتا الحالتين. وإذا اخترت وكيلًا افتراضيًا أو أعددت Python بعد إزالة التثبيتات المسبقة، فستُضاف تلك الأداة إلى إعداداتك الخاصة. وينطبق إعداد mise على مستخدمك فقط، ويحتفظ المستخدمون الآخرون بخيارهم الخاص؛ أما التطبيقات فهي حزم، لذا فإن إزالتها أو استعادتها تغيّرها لجميع من على الجهاز.

## Docker

[Docker](https://www.docker.com/) لا يحتاج تقريبًا إلى أي تعريف. فهو يتيح لك تشغيل حاويات معزولة، وتثبّت Omarchy كل ما يلزم لتشغيله بشكل جيد، بما في ذلك Docker نفسه و[Docker Compose](https://docs.docker.com/compose/).

بشكل افتراضي، مستخدمك *ليس* في مجموعة `docker`. فتلك المجموعة هي فعليًا صلاحية root بدون كلمة مرور — إذ يمكن لأي شيء فيها تشغيل `docker run -v /:/host` والسيطرة على الجهاز — لذا فإن برنامجًا نصيًا مارقًا واحدًا أو تبعية واحدة تعمل باسمك ستكون على بعد أمر واحد من root لولا ذلك. لذا على سطر الأوامر تشغّل Docker باستخدام `sudo` (`sudo docker ps`، `sudo docker compose up`)، وتطلب الأدوات الرسومية التي تتحدث إلى الخدمة الخلفية — جهاز VM الذي يعمل بنظام Windows — الإذن عندما تحتاج إليه. وإذا كنت تريد استعادة راحة الإعداد بدون مجموعة وتفهم المقايضة، ففعّله من **Setup > Security > Sudoless Docker** (أو شغّل `omarchy-setup-security-sudoless-docker`)، والذي يضيفك إلى مجموعة `docker` بعد تحذير؛ وبعد ذلك يعمل `docker` العادي والاسم المستعار `d` بدون `sudo` مرة أخرى.

يمكنك إعداد قواعد البيانات الشائعة للتطوير المحلي في Docker باستخدام _تثبيت > التطوير > Docker DB_ في قائمة Omarchy.

## GitHub CLI

[GitHub CLI](https://cli.github.com/) متاح باسم `gh` للعمل مع المستودعات والمشكلات وطلبات السحب من الطرفية. شغّل `gh auth login` لتثبيته عند أول استخدام والمصادقة، ثم `gh repo clone org/repo` لاستنساخ مستودع. شغّل `gh --help` لاستكشاف أوامره.

لواجهة طرفية لطلبات السحب، شغّل `ghui`؛ ويثبّته mise أيضًا عند أول استخدام. و[Lazygit](https://github.com/jesseduffield/lazygit) مثبّت مسبقًا للعمل مع Git نفسه.
