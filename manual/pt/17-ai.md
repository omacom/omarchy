# IA

O Omarchy inclui lançadores para os agentes de programação abaixo sem escolher um predefinido por si. Execute um comando para instalar o respetivo CLI na primeira utilização e, em seguida, autentique-se quando lhe for pedido. O Hermes e o OpenClaw são as exceções: nada é instalado para eles através do mise, e escolher qualquer um deles configura a sua própria cópia, que se atualiza a si própria, como explica _Aplicações de ambiente de trabalho_ abaixo.

### Instalar e atualizar agentes

À exceção do Hermes e do OpenClaw, estes agentes utilizam a instalação lazy do mise: o primeiro arranque instala o CLI e os arranques seguintes reutilizam-no. O mise também procura uma nova versão de um agente instalado, no máximo, de quatro em quatro horas, mesmo antes de este arrancar ou em segundo plano num prompt da shell. Se essa atualização falhar ou se estiver sem ligação, é executada a versão instalada. `omarchy update` atualiza os agentes instalados com o resto do Omarchy, e `mup` atualiza apenas as ferramentas geridas pelo mise.

O atualizador próprio de um agente, como `claude update`, `codex update` ou um botão de atualização numa aplicação, não atualiza a instalação gerida pelo mise. `codex update` falha, e `claude update` pode indicar sucesso ao mesmo tempo que instala uma cópia separada que o mise não acompanha. Se preferir utilizar o instalador e o atualizador nativos de um agente, adicione-o a `disable_tools`; consulte [Ferramentas CLI pré-instaladas](18-development-tools.md#preinstalled-cli-tools).

Para instalar todas as ferramentas lazy configuradas antes de precisar delas, execute `mise install --include-lazy`. Isto inclui as outras ferramentas CLI predefinidas do Omarchy, para além dos agentes. Consulte [Ferramentas CLI pré-instaladas](18-development-tools.md#preinstalled-cli-tools) para instalar uma única ferramenta ou utilizar a sua própria instalação.

O `grok` é instalado através do pacote first-party `grok` do mise, da mesma forma que `claude` e `codex`. Execute `grok`, ou escolha-o em _Agente > Harness_. Evite o instalador `curl | bash` em x.ai. Esse método coloca uma segunda cópia em `~/.grok/bin`, coloca-a no início do `PATH` e substitui o wrapper do Omarchy.

O `dsh` abre a sua interface no browser em `127.0.0.1:3080`, com a pasta a partir da qual foi iniciado como espaço de trabalho predefinido. A interface no browser não aceita um prompt inicial, por isso `omarchy agent prompt` abre-a com o prompt na sua área de transferência para colar. O Omarchy inicia-o com a configuração predefinida de permissões da DeepSeek que não pede aprovações. O DeepSeek Harness envia registos de sessão para a DeepSeek quando utiliza a sua API oficial de modelos; desative isso em _Definições > Geral > Enviar Registo de Sessão_ na interface no browser. O feedback que enviar também é enviado com a sessão, a menos que o inicie com `DSH_TELEMETRY_MODE=DISABLED`.

### O agente predefinido

Escolha o seu agente predefinido com `omarchy default agent <name>` ou em _Agente > Harness_ no Menu Omarchy (`Super + Space`). Se o agente ainda não estiver instalado, ao escolhê-lo este é instalado primeiro, e também recebe um lançador próprio no lançador de aplicações, junto a Agent. Um Omarchy acabado de instalar vai convidá-lo a fazer esta escolha com uma notificação única.

Escolher o Claude também tenta configurar a sua extensão de browser para Chromium, Chrome, Brave, Brave Origin e Edge. A configuração da extensão aplica-se a todos os utilizadores e pode pedir a sua palavra-passe do sistema; cancelar ou falhar a instalação da extensão não impede que o Claude continue a ser selecionado e iniciado. Reinicie o browser, ative a extensão se lhe for pedido e inicie sessão no Claude para concluir a ligação. Execute `/chrome` no Claude para verificar a ligação. O Firefox e o Zen não suportam esta extensão. Se o Claude já era o seu predefinido antes de esta configuração ter sido adicionada, selecione-o novamente para instalar a extensão.

Depois de fazer a sua escolha, `Super + Shift + Ctrl + A` inicia o agente predefinido numa janela de terminal dedicada (ou apresenta o seletor se ainda não tiver feito a escolha). Também pode iniciá-lo diretamente numa tarefa com `omarchy agent prompt "Review this project"`. O Freebuff e o DeepSeek Harness não aceitam um prompt inicial, por isso abrem com o prompt na área de transferência para colar. Os agentes iniciados desta forma são executados sem supervisão nos respetivos modos de não parar para perguntar, por isso esteja preparado para que façam coisas a sério! O MiniMax Code não tem esse modo para as suas sessões interativas, por isso pede permissões como habitualmente. E, como os agentes se recusam a memorizar a confiança relativa à sua pasta pessoal, os arranques a partir de `$HOME` começam antes em `~/Work`.

Também existem atalhos de terminal: `a` executa o agente predefinido diretamente no terminal atual, enquanto `c`, `cx` e `cy` iniciam OpenCode, Claude Code e Codex diretamente (também nos seus modos de aprovação automática). As alterações de tema também são sincronizadas para os agentes: Claude Code, Pi, OpenCode e Hermes (depois de o Omarchy o ter instalado) acompanham-no quando muda o tema do Omarchy.

### As suas instruções para os agentes

As regras pessoais para todos os agentes ficam em `~/.agents/AGENTS.md`, junto às skills partilhadas em `~/.agents/skills`. Abra-o em _Agente > Instruções_, onde também é ligado a cada harness que mantém o seu próprio ficheiro global: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, o `~/.copilot/copilot-instructions.md` do Copilot, e assim por diante. O Crush e o Amp leem a ligação `~/.config/AGENTS.md`, enquanto o omp, o Kimi e o DeepSeek Harness leem `~/.agents/AGENTS.md` diretamente. Escolher um agente predefinido também o liga. Um ficheiro de instruções que já tinha passa a ser o partilhado, caso ainda não existisse nenhum; caso contrário, fica guardado junto à ligação como `.bak`. Execute `omarchy agent instructions` para voltar a fazer a ligação depois de instalar outro agente.

### O painel de agentes

A barra superior tem um ícone de agentes. Antes de configurar um agente, o painel guia-o ao longo do início de sessão no Claude, Codex ou Grok, e o primeiro passa a ser o seu agente predefinido. Depois disso, o painel coloca todas as subscrições numa única página: cada agente e conta com o seu plano, um medidor para cada um dos seus limites de sessão de 5 horas e semanais com o tempo que falta até à reposição (passe o cursor por cima para ver a percentagem exata), ou o saldo pré-pago restante, sob uma linha que alterna entre os seus dados de utilização em todos eles, como os tokens desta semana e o modelo que mais utiliza. Em _Faz algo fixe_, oferece prompts de arranque para um novo tema, plugin, aplicação ou jogo que entregam a tarefa ao seu agente predefinido. As aplicações são construídas da mesma maneira que as próprias Hype, Monologue e Omacut do Omarchy, em C++ e Qt Quick, a seguir a skill de agente omarchy-make-app, e o compilador e os componentes Qt de que necessitam já vêm instalados. Os jogos são uma única página three.js em `~/Games/vibes`, a seguir a skill de agente omarchy-make-game, e todos abrem a partir de um único lançador Game Vibes no tema atual; carregam o three.js a partir da Web, por isso precisam de uma ligação para arrancar. Claude Code, Codex, Grok, Kimi, Cursor e a sua quota Grok Bot, GitHub Copilot, Muse, Antigravity e Devin estão abrangidos de origem com os seus limites, o Kimchi com o seu plano, créditos pré-pagos e orçamentos de gastos, e Hermes, Mistral Vibe e Qwen Code mostram as suas sessões e tokens depois de os ter utilizado. Os planos e chaves de fornecedores que utiliza através do pi, omp ou opencode também aparecem: OpenCode Zen e Go, o Z.ai GLM Coding Plan, Ollama Cloud, o MiniMax Token Plan e Synthetic com os seus limites; OpenRouter e DeepSeek com os seus saldos pré-pagos; Fireworks com os seus gastos dos últimos 30 dias; e os modelos que executa no seu próprio hardware, em Modelos locais. Cada agente é contado uma única vez, na entidade que o fatura, por muitos harnesses que o utilize.

Clique com o botão esquerdo no ícone da barra ou prima `Super + Ctrl + X` para abrir o painel, clique com o botão direito para iniciar o seu agente predefinido e clique com o botão do meio para atualizar. Os registos de utilização que lhe servem de base são regenerados de 15 em 15 minutos por `omarchy agent usage update`, e o painel pode inclusive agregar a utilização das suas outras máquinas através de uma pasta sincronizada. Consulte o README em `$OMARCHY_PATH/shell/plugins/agents/` para ver todas as definições.

### Várias subscrições

Se paga por mais do que um plano Claude, Codex ou Grok — um Max pessoal e um de trabalho, por exemplo — o Omarchy pode manter todos com sessão iniciada e alternar entre eles. Adicione uma subscrição com o + no painel de agentes, que o guia ao longo do processo no próprio painel, ou com `omarchy agent account add claude Work` (ou `codex`, ou `grok`). Instala o CLI se este estiver em falta. A primeira conta de um fornecedor inicia sessão através do seu browser habitual, exatamente no local onde o CLI sempre procura. Todas as seguintes iniciam sessão através de uma janela privada, para que a conta com sessão já iniciada no browser não seja apanhada por engano; inicie aí sessão com a conta que está a adicionar e feche previamente qualquer janela privada que já esteja aberta. Nunca termine a sessão no CLI para fazer isto: terminar a sessão revoga o início de sessão guardado e essa conta teria de ser adicionada novamente.

Para copiar os seus inícios de sessão de subscrição para outra máquina Omarchy através de SSH, execute `omarchy agent account copy user@laptop`. O remetente disponibiliza um recetor temporário quando o destino não tem nenhum instalado, de modo que máquinas Omarchy mais antigas podem receber contas sem uma atualização. Os recetores instalados têm prioridade. Isto copia todas as subscrições Claude, Codex e Grok; para selecionar apenas algumas, acrescente nomes de fornecedores, como em `omarchy agent account copy laptop claude`. Os nomes das contas e os ID de comandos coincidem com os da origem, incluindo contas já presentes no destino. As contas de destino não relacionadas recebem um sufixo numérico se os nomes entrarem em conflito, e definições, skills, plugins e histórico de conversas permanecem locais a cada máquina.

As credenciais de destino existentes são mantidas. Se uma conta da origem já tiver sessão iniciada no destino, o nome é sincronizado sem substituir as credenciais; as restantes contas são acrescentadas ao lado das existentes. Para substituir as credenciais guardadas de contas correspondentes, utilize `omarchy agent account copy --replace laptop claude` depois de encerrar as sessões dessa conta no destino. Um destino novo também recebe a conta ativa e as preferências de alternância da origem; um destino já estabelecido mantém as suas.

As credenciais viajam através de SSH e são guardadas em ficheiros privados no destino, por isso copie apenas para máquinas em que confia. Isto é uma cópia única, não uma sincronização contínua. Os tokens de atualização do Codex podem ser objeto de rotação por outra máquina, o que deixa uma cópia do início de sessão a precisar de renovação; inícios de sessão separados continuam a ser a opção mais fiável para utilização simultânea em várias máquinas. Consulte [o guia de autenticação de contas do Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Uma conta por fornecedor está ativa, e todas as novas sessões arrancam com essa conta: `cx`, `cy`, um simples `claude`, `codex` ou `grok`, qualquer coisa iniciada através de `omarchy agent`, e scripts ou editores que encontrem o CLI no `PATH`. Alterne com `omarchy agent account use work` (e volte com `omarchy agent account use main`), ou no painel, ao premir o número de uma conta e depois `Enter` (ou ao clicar no respetivo botão Use). As sessões Claude em curso também mudam, a partir da mensagem seguinte: todas as sessões Claude são executadas em `~/.claude`, que contém sempre o início de sessão da conta ativa. Uma sessão Claude iniciada por um Omarchy mais antigo na pasta própria de uma conta mantém esse início de sessão até terminar, por isso a operação de mudança identifica essas sessões e conclui-se por si só quando elas já não existirem. As sessões Codex e Grok em curso permanecem na conta com que começaram. Histórico de conversas, definições, skills e plugins são partilhados entre contas, por isso, na mesma pasta, `claude --continue` continua na nova conta exatamente onde tinha parado.

Com mais do que uma conta, o painel mostra os limites de cada conta lado a lado, com a ativa assinalada. Por predefinição, o Omarchy avisa-o quando a conta ativa ultrapassa 95% de um limite, e clicar na notificação muda para a conta com maior margem disponível. Passe o cursor sobre a linha de uma conta no painel e clique no Autoswitch que aparece junto a Use (ou prima `m`), ou execute `omarchy agent account mode auto`, para que a mudança seja feita automaticamente; enquanto estiver ativo, o Autoswitch ocupa o lugar de Use, e clicar nele outra vez volta ao modo de aviso. Acrescente um número para alterar o limiar, como em `omarchy agent account mode auto 90`. Se todas as contas ultrapassarem o limiar, só recebe um aviso, com a indicação da conta que fica livre primeiro. Enquanto uma conta ativa estiver a 15 pontos ou menos do seu limiar (80% com o valor predefinido), os limites são verificados de três em três minutos, em vez de de 15 em 15 minutos.

`omarchy agent account list` mostra todas as contas e os limites mais recentes de cada uma, `omarchy agent account remove work` esquece uma, e `omarchy agent account rename primary Hey` muda o nome de uma (ou clique no nome de uma conta no painel). Estes comandos atuam sobre as contas do seu agente predefinido; para aceder ao outro fornecedor, indique-o primeiro, como em `omarchy agent account use codex side`. O início de sessão que já tinha em `~/.claude` ou `~/.codex` é a conta _Main_. A do Codex fica onde está; a do Claude aguarda numa pasta própria enquanto outra conta estiver ativa. Uma conta sem utilização há mais de cerca de oito horas pode mostrar _Sign-in required_; clique nela para voltar a iniciar sessão nessa conta diretamente no painel, ou mude para ela e inicie uma sessão, o que atualiza o início de sessão por si só. Os servidores MCP que acrescentar com `claude mcp add` abrangem todas as contas Claude, uma vez que todas são executadas em `~/.claude`; no Codex e no Grok, os servidores que já tinha quando uma conta foi adicionada acompanham essa conta, mas os acrescentados depois só abrangem a conta em que foram acrescentados. O Claude Desktop mantém um início de sessão próprio, e as ferramentas Codex ou Grok configuradas com um caminho absoluto para um binário CLI não acompanham a mudança. Um `CLAUDE_CONFIG_DIR`, `CODEX_HOME` ou `GROK_HOME` explícito prevalece sobre a conta selecionada.

### Diagnóstico de falhas

O Omarchy vigia o systemd-coredump à procura de falhas de processos. Depois de escolher um agente predefinido, qualquer programa seu que faça um core dump apresenta uma notificação "Process crashed" — clique nela e a falha é entregue ao seu agente predefinido juntamente com a skill omarchy-diagnose-crash do Omarchy, que guia o agente no estabelecimento dos factos a partir do core dump e na decisão sobre se a falha vale a pena ser comunicada ao projeto original. Também pode executá-la manualmente contra qualquer PID de `coredumpctl list` com `omarchy agent crash <pid>`.

A vigilância está ativada por predefinição. Desative-a em _Acionador > Alternar > Desativar Captura de Falhas_ (ou com `omarchy toggle crash-capture`) e as notificações param; `omarchy agent crash <pid>` continua a funcionar manualmente.

As falhas também podem ser silenciadas programa a programa, que é o que o diagnóstico lhe oferece no final. `omarchy crash mute hyprland` para as notificações apenas para esse programa, `omarchy crash mute hyprland off` volta a apresentá-las, e `omarchy crash mute` por si só lista aquilo que silenciou. Aceita o caminho do binário com a mesma facilidade que o nome, por isso `omarchy crash mute /usr/bin/hyprland` faz o mesmo. Coloque entre aspas um nome com um espaço, como em `omarchy crash mute 'Some App'`. Tudo o resto continua a notificar, e o programa silenciado continua a falhar — isto esconde o lembrete, não corrige nada.

### Aplicações de ambiente de trabalho

O menu _Instalar > IA_ também inclui algumas aplicações gráficas de IA: Amp Desktop, Antigravity Desktop, a aplicação de ambiente de trabalho ChatGPT, a aplicação de ambiente de trabalho Claude (a beta para Linux da Anthropic, com separadores Chat, Cowork e Claude Code), Grok Bot para conversar com os modelos da xAI, Herdr Desktop, Hermes Desktop, OpenClaw, a aplicação de ambiente de trabalho Perplexity e T3 Code. O Grok Bot é a aplicação de conversação para ambiente de trabalho. O agente de programação é o comando `grok`.

O Hermes Desktop é aquele que importa conhecer, porque uma máquina tem um Hermes, e é o da aplicação: o Hermes só é instalado através da aplicação, e o comando `hermes` executado pelo agente predefinido é o da aplicação. Escolher o Hermes como agente predefinido instala o mesmo que a entrada _Instalar > IA_: o pacote e um runtime Hermes em `~/.hermes`, configurado pelo instalador do próprio Hermes, processo que demora alguns minutos na primeira vez. Esse runtime é o único Hermes utilizado pelo comando `hermes` no terminal, pelo agente predefinido e pela aplicação, e atualiza-se a si próprio com `hermes update`, em vez de aguardar uma nova versão do Omarchy. A instalação também entrega ao Hermes o tema Omarchy sob a forma de uma skin chamada `omarchy`, seguida por todas as superfícies do Hermes quando muda de tema; escolha outra nas definições de Aparência do Hermes ou com `/skin`, se preferir que tal não aconteça, e o Omarchy respeita essa escolha sem a alterar. Remover a aplicação em _Remover > IA_ fecha primeiro o Hermes, gateway incluída, remove também esse runtime e mantém as suas conversas, memórias e skills que o Hermes escreveu para si próprio, salvo indicação em contrário da sua parte: pergunta-lhe, com o não como resposta predefinida, se esses dados e as suas definições de ligação também devem ser removidos.

A experiência de ambiente de trabalho do OpenClaw é a sua Control UI, que abre como uma aplicação web suportada pela sua própria gateway local. O OpenClaw vive em `~/.openclaw` e atualiza-se a si próprio: utilize o botão "Update Gateway" da Control UI ou execute `openclaw update`, e a gateway reinicia na nova versão. O Omarchy só escolhe a versão com a qual uma instalação nova arranca. O OpenClaw também pode ser o seu agente predefinido: ao escolhê-lo em _Agente > Harness_, essa mesma cópia é configurada em `~/.openclaw`, e o agente abre a interface de terminal do OpenClaw ligada à sua gateway. Remover o OpenClaw em _Remover > IA_ leva o serviço da gateway e a aplicação com ele e depois pergunta se `~/.openclaw` também deve ser removido, uma vez que é aí que ficam as suas conversas e credenciais juntamente com o próprio OpenClaw e os runtimes de plugins que ele transfere; a predefinição mantém essa pasta, e instalar o OpenClaw outra vez volta a utilizá-la.

O Herdr Desktop é a aplicação de ambiente de trabalho [Herdr](https://herdr.dev): espaços, separadores e painéis de terminais e agentes de programação que continuam a funcionar no seu core quando fecha a janela. É instalado pelo instalador do próprio Herdr e não por um pacote, pelo que fica em `~/.local/share/herdr-app`, traz o seu core em `~/.local/bin/herdr-core` quando ainda não existe um, e atualiza-se a si próprio e ao core. Coexiste com o comando `herdr` que o Omarchy disponibiliza em `Super + Ctrl + Return`, sem o substituir, e recebe as teclas diretas desse comando: `Alt + Return` e `Alt + Shift + Return` dividem um painel para baixo ou para a direita, `Alt + Escape` fecha-o, `Ctrl + Alt + Arrow` move entre painéis, `Alt + 1..9` e `Alt + Left/Right` escolhem um separador, e `Alt + Up/Down` movem entre espaços. `Ctrl + 1..9` escolhe um espaço e `Alt + Shift + Up/Down` percorre os agentes. As teclas de prefixo `Ctrl + Space` ficam apenas no terminal, uma vez que a aplicação não consegue manter premida uma tecla Ctrl simples como parte de uma sequência. O Omarchy escreve-as em `~/.config/herdr-app/keys.json`, e `omarchy-refresh-herdr-app` repõe-nas. Ao ser instalado, escolhe o tema Omarchy do Herdr, que a partir daí acompanha o tema Omarchy que estiver a utilizar. O Herdr guarda um tema para o modo claro e outro para o modo escuro; por isso, depois de alternar entre um tema Omarchy claro e um escuro, escolha Omarchy mais uma vez no seletor de temas do Herdr para o outro modo.

O T3 Code é executado a partir da sua versão oficial AppImage em `~/.local/share/t3code`, em vez de a partir de um pacote, por isso atualiza-se a si próprio. Ao instalá-lo, é-lhe perguntado se pretende começar no canal Stable ou Nightly; mude mais tarde nas definições do T3 Code. As suas conversas e definições ficam em `~/.t3`, e remover o T3 Code em _Remover > IA_ leva-as com ele.

### Modelos locais

Execute um modelo aberto na sua própria máquina para os seus agentes de programação. Os seus prompts e código permanecem na máquina; nada do que é enviado para o modelo sai dela. Comece por:

```bash
omarchy models use best text
```

Ou, no painel de agentes na barra superior, escolha + e depois IA Local, que aparece quando um modelo cabe nesta máquina. O Podman, que executa os modelos, vem com o Omarchy, tal como o toolkit de contentores da NVIDIA numa máquina NVIDIA, que lhes dá acesso à GPU; se algum deles estiver em falta, a primeira configuração instala o que faltar. Em seguida, o Omarchy escolhe o modelo recomendado para esta máquina, transfere-o e inicia-o. Conte com uma transferência de dezenas de GB e com a utilização da maior parte da memória da máquina enquanto o modelo estiver a ser executado: o Flash Next utiliza cerca de 100 GiB com o seu contexto completo de 256K. Se outros modelos ocuparem a memória de que ele precisa, fica configurado parado, pronto para arrancar assim que parar um deles. O modelo para quando termina a sessão; pare-o manualmente quando precisar da memória para outra coisa.

`omarchy models list` mostra as opções e explica a razão pela qual algumas não cabem. Para configurar outro modelo, execute `omarchy models use <recipe>`. Hoje, `qwen3.8-flash-next-gufo` e `qwen3.8-27b-gufo` estão disponíveis para máquinas Strix Halo de 128 GB; o de 27B ocupa cerca de 40 GiB, por isso deixa espaço para outro trabalho. Num portátil de 64 GB com a Arc B390 da Intel, `qwen3.6-35b-a3b-llamacpp` é executado em cerca de 30 GiB. Novas receitas e recomendações chegam com `omarchy update`, através do pacote.

Cada modelo que configurar recebe a sua própria linha no painel de agentes, junto às suas subscrições: reprodução para o iniciar, pausa para o parar e libertar a respetiva memória, e o botão do terminal para abrir o seu agente com esse modelo. Vários podem funcionar ao mesmo tempo quando a memória chega para todos juntos; se um não couber, o Omarchy indica qual dos modelos em execução deve parar. Arraste as linhas para as reordenar e prima Delete numa linha selecionada para remover um modelo e a respetiva transferência.

Cada modelo que configurar também recebe a sua própria entrada no lançador de aplicações, com o nome do modelo e o logótipo do seu criador, da mesma forma que iniciar sessão no Claude, Codex ou Grok adiciona uma entrada. Abre o seu agente com esse modelo e arranca primeiro o modelo se este não estiver a ser executado: o terminal mostra-o a carregar e passa o controlo ao agente assim que estiver pronto. Remover um modelo remove a respetiva entrada.

Nem todos os modelos servem para programar. Os modelos de imagem, vídeo e música abrem antes no Fantasi, a aplicação do Omarchy para criar imagens, vídeo e música com um modelo em execução nesta máquina, tanto a partir da entrada no lançador como da linha no painel de agentes.

Um modelo continua a ser executado exatamente como foi configurado, por isso uma atualização do Omarchy nunca o reinicia enquanto os agentes o utilizam. Quando o Omarchy dispõe de um runtime mais recente ou de pesos mais recentes para um modelo que configurou, a linha desse modelo mostra um botão de atualização: prima-o e o modelo volta a ser configurado em segundo plano, apenas com a transferência do que mudou, e arranca outra vez já na nova versão. Um modelo parado mantém-se parado. `omarchy models update` faz o mesmo para todos os modelos a partir de um terminal.

A partir da linha de comandos, `omarchy models start <recipe>` e `omarchy models stop <recipe>` fazem o mesmo, `omarchy models status` mostra todos os modelos, e `omarchy agent --local` abre o seu agente predefinido no último modelo que iniciou. O pi, o OpenCode e o Qwen Code conseguem utilizar um destes modelos; com qualquer outro agente predefinido, o agente abre no pi ou, se não tiver o pi, no OpenCode. O pi também apresenta todos os modelos que configurou, e os que estão em máquinas com as quais fez o emparelhamento, no seu próprio seletor de modelos, por isso um simples `pi` também chega a eles. Qualquer cliente compatível com a OpenAI também pode estabelecer ligação: `status` mostra o endereço de cada modelo (o primeiro é `http://127.0.0.1:11435/v1`), o nome da receita é o modelo, e a chave está em `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` apaga um modelo e as transferências que nenhum outro modelo utiliza.

Os runtimes de terceiros vêm identificados com o respetivo editor. O Omarchy executa todos os modelos sem acesso à rede.

### LLM locais

O Omarchy recomenda duas formas de executar modelos LLM locais: LM Studio e Ollama. O LM Studio oferece uma interface gráfica para encontrar modelos de pesos abertos, para os instalar e para os executar. É uma excelente forma de começar com facilidade. O Ollama oferece um CLI para fazer o mesmo de forma semelhante. Mas, se está a começar nos modelos locais, eu começaria pelo LM Studio. Pode instalar qualquer um deles em _Instalar > IA_ no Menu Omarchy.

### As skills do Omarchy

As skills de agente ajudam a IA a utilizar ferramentas específicas de uma forma específica, e o Omarchy inclui sete delas. A skill omarchy abrange a personalização do sistema, como ajustar a configuração do Hyprland ou ajustar a barra. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app e omarchy-make-game abrangem a criação de algo novo, omarchy-contribute abrange a comunicação de um erro ou o envio de uma correção ao projeto original, e omarchy-diagnose-crash trabalha sobre o core dump de uma falha. Estão presentes através de symlinks nas pastas de skills do Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` e cada `~/.hermes/profiles/*/skills`) e na localização genérica `~/.agents/skills`, por isso a maior parte dos harnesses as deteta automaticamente. Uma pasta de skill sua com o mesmo nome tem prioridade.

Mas deve encarar estas skills como experimentais. Cada modelo irá usá-las com resultados diferentes. O melhor é executar primeiro em modo de planeamento, para ficar com uma ideia do que o agente pretende alterar. E, depois, esteja preparado para reverter alterações ou até para invocar `omarchy reinstall configs`, se o agente fizer uma grande confusão em tudo.
