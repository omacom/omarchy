# IA

O Omarchy inclui lançadores para os agentes de programação abaixo sem escolher um predefinido por si. Execute um comando para instalar a respetiva CLI na primeira utilização, depois autentique-se quando for pedido. O Hermes é a exceção: nada é instalado para ele na primeira utilização, e escolhê-lo instala o Hermes Desktop, como explica _Aplicações de ambiente de trabalho_ abaixo.

### Instalar e atualizar agentes

Exceto o Hermes, estes agentes utilizam a instalação preguiçosa do mise: a primeira execução instala a CLI, e as execuções seguintes reutilizam-na. O mise também verifica se um agente instalado tem uma nova versão, no máximo uma vez a cada quatro horas, mesmo antes de arrancar ou em segundo plano num prompt da shell. Se essa atualização falhar ou estiver offline, é executada a versão instalada. `omarchy update` atualiza os agentes instalados com o resto do Omarchy, e `mup` atualiza apenas as ferramentas geridas pelo mise.

O atualizador próprio de um agente, como `claude update`, `codex update` ou um botão de atualização numa aplicação, não atualiza a instalação gerida pelo mise. `codex update` falha, e `claude update` pode indicar sucesso enquanto instala uma cópia separada que o mise não acompanha. Se preferir utilizar o instalador e o atualizador nativos de um agente, adicione-o a `disable_tools`; consulte [Ferramentas CLI pré-instaladas](18-development-tools.md#preinstalled-cli-tools).

Para instalar todas as ferramentas preguiçosas configuradas antes de precisar delas, execute `mise install --include-lazy`. Isto inclui as outras ferramentas CLI predefinidas do Omarchy, bem como os agentes. Consulte [Ferramentas CLI pré-instaladas](18-development-tools.md#preinstalled-cli-tools) para instalar uma única ferramenta ou utilizar a sua própria instalação.

O `grok` é instalado através do pacote `grok` oficial do mise, da mesma forma que `claude` e `codex`. Execute `grok`, ou escolha-o em _Agente > Harness_. Ignore o instalador `curl | bash` em x.ai. Esse caminho coloca uma segunda cópia em `~/.grok/bin`, coloca-a no início do `PATH` e substitui o wrapper do Omarchy.

O `dsh` abre a sua interface no browser em `127.0.0.1:3080`, com o diretório de arranque como área de trabalho predefinida. A sua interface no browser não aceita um prompt inicial, por isso `omarchy agent prompt` abre-o com o prompt na área de transferência para colar. O Omarchy arranca-o com a predefinição de permissões sem aprovação da DeepSeek. O DeepSeek Harness carrega os registos de sessão para a DeepSeek quando utiliza a API oficial do modelo; desative isso em _Definições > Geral > Carregar Registo da Sessão_ na sua interface no browser. Os comentários que lhe enviar também são carregados com a sessão, a menos que o inicie com `DSH_TELEMETRY_MODE=DISABLED`.

### O agente predefinido

Escolha o seu agente predefinido com `omarchy default agent <name>` ou em _Agente > Harness_ no Menu Omarchy (`Super + Space`). Se o agente ainda não estiver instalado, ao escolhê-lo ele é instalado primeiro. Uma instalação nova do Omarchy vai convidá-lo a fazer esta escolha com uma notificação única.

Ao escolher o Claude, também é tentada a configuração da sua extensão de browser para Chromium, Chrome, Brave, Brave Origin e Edge. A configuração da extensão aplica-se a todos os utilizadores e pode pedir a sua palavra-passe do sistema; cancelar ou uma instalação falhada da extensão continua a selecionar e a iniciar o Claude. Reinicie o browser, ative a extensão se for pedido e inicie sessão no Claude para concluir a ligação. Execute `/chrome` no Claude para verificar a ligação. O Firefox e o Zen não suportam esta extensão. Se o Claude já era o seu predefinido antes de esta configuração ser adicionada, selecione-o novamente para instalar a extensão.

Depois de escolher, `Super + Shift + Ctrl + A` inicia o agente predefinido numa janela de terminal dedicada (ou apresenta o seletor se ainda não tiver escolhido). Também pode iniciá-lo diretamente numa tarefa com `omarchy agent prompt "Review this project"`. O Freebuff e o DeepSeek Harness não aceitam um prompt inicial, por isso abrem com o prompt na área de transferência para colar. Os agentes iniciados desta forma funcionam sem supervisão nos respetivos modos de não parar para perguntar, por isso esteja preparado para eles fazerem mesmo coisas! O MiniMax Code não tem esse modo para as suas sessões interativas, por isso pede permissões como habitualmente. E como os agentes se recusam a memorizar a confiança para o seu diretório pessoal, os arranques a partir de `$HOME` começam antes em `~/Work`.

Também há atalhos de terminal: `a` executa o agente predefinido inline no terminal atual, enquanto `c`, `cx` e `cy` iniciam OpenCode, Claude Code e Codex diretamente (mais uma vez nos seus modos de aprovação automática). As alterações de tema também são sincronizadas para os agentes: Claude Code, Pi, OpenCode e Hermes (depois de o Omarchy o ter instalado) acompanham-no quando muda o tema do Omarchy.

### As instruções do seu agente

As regras pessoais para todos os agentes ficam em `~/.agents/AGENTS.md`, ao lado das skills partilhadas em `~/.agents/skills`. Abra-o em _Agente > Instruções_, que também o liga a cada harness que mantém o seu próprio ficheiro global: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` do Copilot, e assim por diante. O Crush e o Amp leem a ligação `~/.config/AGENTS.md`, enquanto o omp, o Kimi e o DeepSeek Harness leem `~/.agents/AGENTS.md` diretamente. Escolher um agente predefinido também o liga. Um ficheiro de instruções que já tivesse torna-se o partilhado se ainda não existisse nenhum; caso contrário, é mantido ao lado da ligação como `.bak`. Execute `omarchy agent instructions` para voltar a ligar depois de instalar outro agente.

### O painel de agentes

A barra superior tem um ícone de agentes. Antes de ter configurado um agente, o seu painel guia-o ao longo do início de sessão no Claude, Codex ou Grok, e o primeiro torna-se o seu agente predefinido. Depois disso, o painel coloca todas as subscrições numa só página: cada agente e conta com o seu plano, um medidor para cada um dos seus limites de sessão de 5 horas e semanais com o tempo até ser reposto (passe o cursor por cima para ver a percentagem exata), ou o saldo pré-pago restante, sob uma linha que vai rodando pelo que utilizou em todos eles, como os tokens desta semana e o seu modelo mais utilizado. Em _Criar algo_, oferece prompts iniciais para um novo tema, plugin ou aplicação que entregam a tarefa ao seu agente predefinido. As aplicações são construídas da forma como são construídas as próprias Hype, Monologue e Omacut do Omarchy, em C++ e Qt Quick, com base na skill de agente omarchy-app, e o compilador e os componentes Qt de que precisam já vêm instalados. Claude Code, Codex, Grok, Kimi, o Cursor e a respetiva quota do Grok Bot, GitHub Copilot, Muse, Antigravity, Kimchi e Devin estão abrangidos de origem com os seus limites, e Hermes, Mistral Vibe e Qwen Code mostram as suas sessões e tokens depois de os ter utilizado. Os planos e chaves de fornecedores que utiliza através de pi, omp ou opencode também aparecem: OpenCode Zen e Go, o Z.ai GLM Coding Plan, Ollama Cloud, o MiniMax Token Plan e Synthetic com os seus limites; Fireworks, OpenRouter e DeepSeek com os seus saldos pré-pagos; e os modelos que executa no seu próprio hardware em Modelos locais. Cada agente é contado uma vez, sob quem o fatura, por mais harnesses através dos quais o utilize.

Clique com o botão esquerdo no ícone da barra para abrir o painel, clique com o botão direito para iniciar o seu agente predefinido. Os registos de utilização por trás dele são regenerados a cada 15 minutos por `omarchy agent usage-update`, e o painel pode até fundir a utilização das suas outras máquinas através de uma pasta sincronizada. Consulte o README em `$OMARCHY_PATH/shell/plugins/agents/` para ver todas as definições.

### Várias subscrições

Se pagar por mais do que um plano Claude, Codex ou Grok — um Max pessoal e um de trabalho, por exemplo — o Omarchy pode manter todos com sessão iniciada e alternar entre eles. Adicione uma subscrição com o + no painel de agentes, que o guia ali mesmo, ou com `omarchy agent account add claude Work` (ou `codex`, ou `grok`). Instala a CLI se esta estiver em falta. A primeira conta de um fornecedor inicia sessão através do seu browser normal, exatamente onde a CLI sempre procura. Todas as seguintes iniciam sessão através de uma janela privada, para que a conta em que o seu browser já tem sessão iniciada não seja escolhida por engano; inicie sessão aí como a conta que está a adicionar e feche primeiro qualquer janela privada que já tenha aberta. Nunca termine sessão na CLI para fazer isto: terminar sessão revoga o início de sessão guardado, e essa conta teria de ser adicionada novamente.

Para copiar os inícios de sessão das subscrições para outra máquina Omarchy por SSH, execute `omarchy agent account copy user@laptop`. O remetente fornece um recetor temporário quando o destino não tem um instalado, para que máquinas Omarchy mais antigas possam receber contas sem uma atualização. Os recetores instalados têm precedência. Isto copia todas as subscrições Claude, Codex e Grok; adicione nomes de fornecedores para as selecionar, como em `omarchy agent account copy laptop claude`. Os nomes das contas e os IDs de comando correspondem à origem, incluindo contas já presentes no destino. Contas de destino não relacionadas recebem um sufixo numérico se os seus nomes entrarem em conflito, e as definições, skills, plugins e histórico de conversas permanecem locais a cada máquina.

As credenciais existentes no destino são mantidas. Uma conta de origem que já tenha sessão iniciada lá tem o seu nome sincronizado sem substituir as suas credenciais; as outras contas são adicionadas ao lado dela. Para substituir as credenciais guardadas de contas correspondentes, utilize `omarchy agent account copy --replace laptop claude` depois de sair das sessões dessa conta no destino. Um destino novo também recebe a conta ativa e as preferências de alternância da origem; um destino já estabelecido mantém as suas.

As credenciais viajam por SSH e são guardadas em ficheiros privados no destino, por isso copie apenas para máquinas em que confia. Isto é uma cópia única, não uma sincronização contínua. Os tokens de atualização do Codex podem ser rodados por outra máquina, deixando um início de sessão copiado a precisar de renovação; inícios de sessão separados continuam a ser a escolha mais fiável para utilização simultânea em várias máquinas. Consulte [o guia de autenticação de contas do Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Uma conta por fornecedor está ativa, e todas as novas sessões começam como ela: `cx`, `cy`, um simples `claude`, `codex` ou `grok`, qualquer coisa iniciada através de `omarchy agent`, e scripts ou editores que encontrem a CLI no `PATH`. Alterne com `omarchy agent account use work` (e volte com `omarchy agent account use main`), ou no painel ao premir o número de uma conta e depois `Enter` (ou ao clicar no seu botão Utilizar). As sessões já a correr permanecem na conta com que começaram. O histórico de conversas, as definições, as skills e os plugins são partilhados entre contas, por isso `claude --continue` na mesma pasta continua onde ficou na nova conta.

Com mais do que uma conta, o painel mostra os limites de cada conta lado a lado, com a ativa assinalada. Por predefinição, o Omarchy avisa-o quando a conta ativa ultrapassa 95% de um limite, e clicar na notificação muda para a conta com mais margem. Passe o cursor sobre a linha de uma conta no painel e clique em Autoswitch, que aparece ao lado de Utilizar (ou prima `m`), ou execute `omarchy agent account mode auto`, para que mude por si próprio; enquanto estiver ativado, Autoswitch ocupa o lugar de Utilizar, e clicar nele novamente volta a avisar. Adicione um número para alterar o limiar, como em `omarchy agent account mode auto 90`. Se todas as contas estiverem acima do limiar, será avisado uma vez, juntamente com qual conta se liberta primeiro. Enquanto uma conta ativa estiver a menos de 15 pontos do seu limiar (80% na predefinição), os seus limites são verificados a cada três minutos, em vez de a cada 15.

`omarchy agent account list` mostra todas as contas e os seus limites mais recentes, `omarchy agent account remove work` esquece uma, e `omarchy agent account rename primary Hey` muda o nome de uma (ou clique no nome de uma conta no painel). Estes comandos funcionam nas contas do seu agente predefinido; para chegar ao outro fornecedor, nomeie-o primeiro, como em `omarchy agent account use codex side`. O início de sessão que já tinha em `~/.claude` ou `~/.codex` é a conta _Main_ e fica onde está. Uma conta que fique sem utilização durante mais de cerca de oito horas pode mostrar _Início de sessão necessário_; clique nela para voltar a iniciar sessão nessa conta diretamente no painel, ou inicie uma sessão nela, o que atualiza o início de sessão por si só. Os servidores MCP que tinha quando uma conta foi adicionada acompanham-na, mas os que adicionar mais tarde com `claude mcp add` só chegam à conta em que os adicionou. O Claude Desktop e as ferramentas configuradas com um caminho absoluto para um binário CLI não acompanham a mudança. Um `CLAUDE_CONFIG_DIR`, `CODEX_HOME` ou `GROK_HOME` explícito tem precedência sobre a conta selecionada.

### Diagnóstico de falhas

O Omarchy vigia o systemd-coredump à procura de falhas de processos. Quando algo faz segfault, recebe uma notificação "Process crashed" — clique nela, e a falha é entregue ao seu agente predefinido juntamente com a skill diagnose-crash do Omarchy, que guia o agente a apurar os factos a partir do core dump e a decidir se vale a pena reportar a falha ao projeto original. Também pode executá-lo manualmente contra qualquer PID de `coredumpctl list` com `omarchy agent crash <pid>`.

A vigilância está ativada por predefinição. Desative-a em _Acionador > Alternar > Captura de Falhas_ (ou com `omarchy toggle crash-capture`) e as notificações param; `omarchy agent crash <pid>` continua a funcionar manualmente.

As falhas também podem ser silenciadas programa a programa, que é o que o diagnóstico lhe oferece no fim. `omarchy crash mute hyprland` para as notificações só para esse programa, `omarchy crash mute hyprland off` traz-as de volta, e `omarchy crash mute` por si só lista o que silenciou. Aceita o caminho do binário tão bem como o seu nome, por isso `omarchy crash mute /usr/bin/hyprland` faz a mesma coisa. Coloque entre aspas um nome com um espaço, como em `omarchy crash mute 'Some App'`. Tudo o resto continua a avisar, e o programa silenciado continua a falhar — isto esconde o lembrete, não resolve nada.

### Aplicações de ambiente de trabalho

O menu _Instalar > IA_ também traz algumas aplicações gráficas de IA: a aplicação de ambiente de trabalho do ChatGPT, a aplicação de ambiente de trabalho do Claude (a beta para Linux da Anthropic, com separadores Chat, Cowork e Claude Code), o Grok Bot para conversar com os modelos da xAI, Herdr Desktop, Hermes Desktop, OpenClaw, a aplicação de ambiente de trabalho da Perplexity e T3 Code. O Grok Bot é a aplicação de conversação de ambiente de trabalho. O agente de programação é o comando `grok`.

O Hermes Desktop é o que deve conhecer, porque uma máquina tem um Hermes, e é o da aplicação: o Hermes só é alguma vez instalado através da aplicação, e o comando `hermes` que o agente predefinido executa é o da aplicação. Escolher o Hermes como agente predefinido instala o mesmo que a entrada _Instalar > IA_ instala: o pacote, e um runtime Hermes em `~/.hermes` configurado pelo próprio instalador do Hermes, o que demora alguns minutos na primeira vez. Esse runtime é o único Hermes que o comando `hermes` no terminal, o agente predefinido e a aplicação utilizam, e atualiza-se a si próprio com `hermes update` em vez de esperar por uma versão do Omarchy. Instalá-lo também entrega ao Hermes o tema Omarchy como uma skin chamada `omarchy`, que todas as superfícies do Hermes seguem quando muda de tema; escolha outra nas definições de Aparência do Hermes ou com `/skin` se preferir que não o faça, e o Omarchy deixa essa escolha em paz. Remover a aplicação em _Remover > IA_ fecha primeiro o Hermes, gateway incluído, leva esse runtime com ela e mantém as suas conversas, memórias e as skills que o Hermes escreveu para si próprio, a menos que lhe diga o contrário: pergunta, com não por predefinição, se esses dados e as suas definições de ligação também devem desaparecer.

A experiência de ambiente de trabalho do OpenClaw é a sua Control UI, que abre como uma aplicação web suportada pelo seu próprio gateway local. O OpenClaw vive em `~/.openclaw` e atualiza-se a si próprio: utilize o botão "Update Gateway" da Control UI ou execute `openclaw update`, e o gateway reinicia na nova versão. O Omarchy só escolhe a versão a partir da qual uma instalação nova começa. Remover o OpenClaw em _Remover > IA_ leva o serviço gateway e a aplicação com ele e depois pergunta se `~/.openclaw` também deve desaparecer, uma vez que guarda as suas conversas e credenciais juntamente com o próprio OpenClaw e os runtimes de plugins que descarrega; a predefinição mantém-no, e voltar a instalar o OpenClaw volta a utilizá-lo.

O Herdr Desktop é a aplicação de ambiente de trabalho [Herdr](https://herdr.dev): espaços, separadores e painéis de terminais e agentes de programação que continuam a correr no seu núcleo quando fecha a janela. Vem do próprio instalador do Herdr e não de um pacote, por isso vive em `~/.local/share/herdr-app`, traz o seu núcleo em `~/.local/bin/herdr-core` quando ainda não tem um, e atualiza-se a si próprio e ao núcleo. Fica ao lado do comando `herdr` que o Omarchy fornece em `Super + Ctrl + Return`, em vez de o substituir, e recebe as teclas diretas desse comando: `Alt + Return` e `Alt + Shift + Return` dividem um painel para baixo ou para a direita, `Alt + Escape` fecha-o, `Ctrl + Alt + Arrow` move entre painéis, `Alt + 1..9` e `Alt + Left/Right` escolhem um separador, e `Alt + Up/Down` movem entre espaços. `Ctrl + 1..9` escolhe um espaço e `Alt + Shift + Up/Down` avança entre agentes. As teclas de prefixo `Ctrl + Space` permanecem apenas no terminal, uma vez que a aplicação não consegue manter uma tecla Ctrl simples para uma sequência. O Omarchy escreve estas em `~/.config/herdr-app/keys.json`, e `omarchy-refresh-herdr-app` repõe-nas. Instalá-lo escolhe o tema Omarchy do Herdr, que a partir daí segue o seu tema Omarchy. O Herdr mantém um tema para o modo claro e um para o escuro, por isso, depois de alternar entre um tema Omarchy escuro e um claro, escolha Omarchy no seletor de temas do Herdr mais uma vez para o outro modo.

O T3 Code executa-se a partir da sua versão AppImage oficial em `~/.local/share/t3code` e não a partir de um pacote, por isso atualiza-se a si próprio. Instalá-lo pergunta se quer começar no canal Stable ou Nightly; mude mais tarde nas definições do T3 Code. Os seus tópicos e definições vivem em `~/.t3`, e remover o T3 Code em _Remover > IA_ leva-os com ele.

### Modelos locais

Execute um modelo aberto na sua própria máquina para os seus agentes de programação. Os seus prompts e código permanecem na máquina; nada do que é enviado para o modelo sai dela. Comece com:

```bash
omarchy agent local use best
```

Ou, no painel de agentes na barra superior, escolha + e depois IA Local, que aparece quando um modelo cabe nesta máquina. Na primeira vez, isto instala o Podman, que executa os modelos, e numa máquina NVIDIA o toolkit de contentores da NVIDIA, que lhes dá a GPU. O Omarchy escolhe então o modelo recomendado para esta máquina, descarrega-o e inicia-o. Conte com uma descarga de dezenas de GB e com a maior parte da memória da máquina em utilização enquanto o modelo corre: o Flash Next utiliza cerca de 100 GiB com o seu contexto completo de 256K. Se outros modelos ocuparem a memória de que precisa, ele é configurado parado, pronto para arrancar quando parar um. O modelo para ao terminar sessão; pare-o por si próprio quando precisar da memória para outra coisa.

`omarchy agent local list` mostra as opções e explica por que algumas não cabem. Para configurar outro, execute `omarchy agent local use <recipe>`. Hoje, `qwen3.8-flash-next-gufo` e `qwen3.8-27b-gufo` estão disponíveis para máquinas Strix Halo de 128 GB; o 27B ocupa cerca de 40 GiB, por isso deixa espaço para outro trabalho. Novas receitas e recomendações chegam com `omarchy update`, através do pacote.

Cada modelo que configurar tem a sua própria linha no painel de agentes, ao lado das suas subscrições: reproduzir para o iniciar, pausar para o parar e libertar a sua memória, e o botão de terminal para abrir o seu agente nele. Vários podem correr ao mesmo tempo quando cabem juntos na memória; se um não couber, o Omarchy indica que modelo em execução deve parar. Arraste as linhas para as reordenar e prima Delete numa linha selecionada para remover um modelo e a sua descarga.

A partir da linha de comandos, `omarchy agent local start <recipe>` e `omarchy agent local stop <recipe>` fazem o mesmo, `omarchy agent local status` mostra todos os modelos, e `omarchy agent --local` abre o seu agente predefinido no último modelo que iniciou (pi se o seu agente predefinido não conseguir utilizar um modelo local). Qualquer cliente compatível com OpenAI também se pode ligar: `status` mostra o endereço de cada modelo (o primeiro é `http://127.0.0.1:11435/v1`), o nome da receita é o modelo e a chave está em `~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` elimina um modelo e as descargas que nenhum outro modelo utiliza.

Os runtimes de terceiros são identificados com o seu editor. O Omarchy executa todos os modelos sem acesso à rede.

### LLM locais

O Omarchy recomenda duas formas de executar modelos LLM locais: LM Studio e Ollama. O LM Studio fornece uma interface gráfica para encontrar modelos de pesos abertos, instalá-los e executá-los. É uma ótima forma de começar facilmente. O Ollama oferece uma CLI para fazer o mesmo de forma semelhante. Mas se é novo nos modelos locais, eu começaria pelo LM Studio. Pode instalar qualquer um deles em _Instalar > IA_ no Menu Omarchy.

### A Skill Omarchy

As skills de agente ajudam a IA a utilizar ferramentas específicas de uma forma específica, e o Omarchy traz uma skill predefinida para adaptar o sistema. Como ajustar a sua configuração do Hyprland, ajustar a barra, ou até criar um tema novo de raiz. Está ligada simbolicamente nos diretórios de skills do Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` e cada `~/.hermes/profiles/*/skills`), e na localização genérica `~/.agents/skills`, por isso a maioria dos harnesses a deteta automaticamente.

Mas deve tratar esta skill como experimental. Modelos diferentes vão utilizá-la com efeitos diferentes. É melhor executar primeiro em modo de plano, para ter uma ideia do que o agente gostaria de alterar. E depois esteja preparado para reverter as alterações ou até para executar `omarchy reinstall configs`, se o agente fizer uma confusão com tudo.
