# IA

O Omarchy inclui lançadores para os agentes de programação abaixo sem escolher um predefinido por si. Execute um comando para instalar a respetiva CLI na primeira utilização e, depois, autentique-se quando lhe for pedido. O Hermes é a exceção: na primeira utilização, nada é instalado para ele, e escolhê-lo instala o Hermes Desktop, como se explica em _Aplicações de ambiente de trabalho_ abaixo.

### Instalar e atualizar agentes

Exceto o Hermes, estes agentes usam a instalação lazy do mise: o primeiro arranque instala a CLI e os arranques seguintes reutilizam-na. O mise também verifica se existe uma nova versão de um agente instalado, no máximo uma vez a cada quatro horas, imediatamente antes de o iniciar ou em segundo plano num prompt da shell. Se essa atualização falhar ou se estiver offline, é executada a versão instalada. O `omarchy update` atualiza os agentes instalados juntamente com o resto do Omarchy, e o `mup` atualiza apenas as ferramentas geridas pelo mise.

O atualizador próprio de um agente, como `claude update`, `codex update` ou um botão de atualização numa aplicação, não atualiza a instalação gerida pelo mise. O `codex update` falha, e o `claude update` pode indicar sucesso enquanto instala uma cópia separada que o mise não acompanha. Se preferir usar o instalador e o atualizador nativos de um agente, adicione-o a `disable_tools`; consulte [Ferramentas CLI pré-instaladas](18-development-tools.md#preinstalled-cli-tools).

Para instalar todas as ferramentas lazy configuradas antes de precisar delas, execute `mise install --include-lazy`. Isto inclui as outras ferramentas CLI predefinidas do Omarchy, bem como os agentes. Consulte [Ferramentas CLI pré-instaladas](18-development-tools.md#preinstalled-cli-tools) para instalar uma única ferramenta ou usar a sua própria instalação.

O `grok` é instalado através do pacote `grok` oficial do mise, da mesma forma que o `claude` e o `codex`. Execute `grok`, ou escolha-o em _Configuração > Predefinições > Agente_. Evite o instalador `curl | bash` em x.ai. Esse caminho coloca uma segunda cópia em `~/.grok/bin`, coloca-a à frente no `PATH` e sobrescreve o wrapper do Omarchy.

O `dsh` abre a sua interface de navegador em `127.0.0.1:3080`, tendo o diretório de arranque como área de trabalho predefinida. A interface de navegador não aceita um prompt inicial, por isso o `omarchy agent prompt` abre-a com o prompt na área de transferência para colar. O Omarchy inicia-o com a predefinição de permissões sem aprovação da DeepSeek. O DeepSeek Harness envia os registos de sessão para a DeepSeek quando utiliza a API oficial de modelos da DeepSeek; desative isso em _Definições > Geral > Upload Session Log_ na interface de navegador. Os comentários que lhe enviar também são enviados com a sessão, a menos que o inicie com `DSH_TELEMETRY_MODE=DISABLED`.

### O agente predefinido

Escolha o seu agente predefinido com `omarchy default agent <name>` ou em _Configuração > Predefinições > Agente_ no Menu Omarchy (`Super + Space`). Se o agente ainda não estiver instalado, escolhê-lo instala-o primeiro. Uma instalação nova do Omarchy convida-o a fazer esta escolha com uma notificação única.

Escolher o Claude também tenta configurar a sua extensão de navegador para Chromium, Chrome, Brave, Brave Origin e Edge. A configuração da extensão aplica-se a todos os utilizadores e pode pedir a palavra-passe do sistema; cancelar ou uma instalação da extensão falhada continua a selecionar e a iniciar o Claude. Reinicie o navegador, ative a extensão se lhe for pedido e inicie sessão no Claude para terminar a ligação. Execute `/chrome` no Claude para verificar a ligação. O Firefox e o Zen não suportam esta extensão. Se o Claude já era o seu predefinido antes de esta configuração ser adicionada, selecione-o novamente para instalar a extensão.

Depois de escolher, `Super + Shift + Ctrl + A` inicia o agente predefinido numa janela de terminal dedicada (ou abre o seletor, se ainda não tiver escolhido). Também pode iniciá-lo diretamente numa tarefa com `omarchy agent prompt "Review this project"`. O Freebuff e o DeepSeek Harness não aceitam um prompt inicial, por isso abrem com o prompt na área de transferência para colar. Os agentes iniciados desta forma funcionam sem supervisão nos respetivos modos de não parar para perguntar, por isso prepare-se para eles fazerem mesmo coisas! O MiniMax Code não tem um modo desses para as suas sessões interativas, por isso pede permissões como habitualmente. E, como os agentes se recusam a memorizar a confiança no seu diretório pessoal, os arranques a partir de `$HOME` começam, em vez disso, em `~/Work`.

Também existem atalhos de terminal: `a` executa o agente predefinido inline no terminal atual, enquanto `c`, `cx` e `cy` iniciam diretamente o OpenCode, o Claude Code e o Codex (também nos seus modos de aprovação automática). As mudanças de tema também se sincronizam com os agentes: o Claude Code, o Pi, o OpenCode e o Hermes (depois de o Omarchy o ter instalado) acompanham-no quando muda o tema do Omarchy.

### O painel de agentes

A barra superior tem um ícone de agentes. Antes de ter configurado um agente, o painel orienta-o no início de sessão no Claude, no Codex ou no Grok, e o primeiro torna-se o seu agente predefinido. Depois disso, o painel coloca cada subscrição numa só página: cada agente e conta com o respetivo plano, um medidor para cada um dos seus limites de sessão de 5 horas e semanais com o tempo que falta para a reposição (passe o cursor por cima para ver a percentagem exata), ou o saldo pré-pago restante, sob uma linha que vai rodando pelo que utilizou em todos eles, como os tokens desta semana e o seu modelo mais usado. Em _Criar algo_, oferece prompts iniciais para um novo tema, plugin ou aplicação que entregam a tarefa ao seu agente predefinido. As aplicações são construídas da forma como são construídas as próprias Hype, Monologue e Omacut do Omarchy, em C++ e Qt Quick, seguindo a skill de agente omarchy-app, e o compilador e os componentes Qt de que precisam já vêm instalados. O Claude Code, o Codex, o Grok, o Kimi, o Cursor e a sua quota Grok Bot, o GitHub Copilot, o Muse, o Antigravity, o Kimchi e o Devin estão cobertos de fábrica com os respetivos limites, e o Hermes, o Mistral Vibe e o Qwen Code mostram as suas sessões e tokens depois de os ter utilizado. Os planos de fornecedores e as chaves que utiliza através do pi, do omp ou do opencode também aparecem: o OpenCode Zen e Go, o Z.ai GLM Coding Plan, a Ollama Cloud, o MiniMax Token Plan e o Synthetic com os respetivos limites; o Fireworks, a OpenRouter e a DeepSeek com os respetivos saldos pré-pagos; e os modelos que executa no seu próprio hardware em _Modelos locais_. Cada agente é contado uma vez, por quem o fatura, independentemente de quantos harnesses utilizar para o conduzir.

Clique com o botão esquerdo no ícone da barra para abrir o painel e com o botão direito para iniciar o seu agente predefinido. Os registos de utilização subjacentes são regenerados a cada 15 minutos por `omarchy agent usage-update`, e o painel pode até juntar a utilização das suas outras máquinas através de uma pasta sincronizada. Consulte o README em `$OMARCHY_PATH/shell/plugins/agents/` para ver todas as definições.

### Várias subscrições

Se paga mais do que um plano Claude, Codex ou Grok — um Max pessoal e um de trabalho, por exemplo —, o Omarchy pode manter todos com sessão iniciada e alternar entre eles. Adicione uma subscrição com o + no painel de agentes, que o orienta ali mesmo, ou com `omarchy agent account add claude Work` (ou `codex`, ou `grok`). Instala a CLI, se esta estiver em falta. A primeira conta de um fornecedor inicia sessão através do seu navegador normal, exatamente onde a CLI sempre procura. Todas as seguintes iniciam sessão através de uma janela privada, para que a conta em que o navegador já tem sessão iniciada não seja apanhada por engano; inicie aí sessão como a conta que está a adicionar e feche primeiro qualquer janela privada que já tenha aberta. Nunca termine a sessão na CLI para fazer isto: terminar a sessão revoga o início de sessão guardado, e essa conta teria de ser adicionada novamente.

Para copiar os seus inícios de sessão de subscrições para outra máquina Omarchy através de SSH, execute `omarchy agent account copy user@laptop`. O remetente fornece um recetor temporário quando o destino não tem um instalado, por isso as máquinas Omarchy mais antigas podem receber contas sem uma atualização. Os recetores instalados têm precedência. Isto copia todas as subscrições Claude, Codex e Grok; adicione nomes de fornecedores para as selecionar, como em `omarchy agent account copy laptop claude`. Os nomes das contas e os IDs dos comandos correspondem à origem, incluindo as contas já presentes no destino. As contas de destino não relacionadas recebem um sufixo numérico se os seus nomes entrarem em conflito, e as definições, skills, plugins e histórico de conversas permanecem locais a cada máquina.

As credenciais de destino existentes são mantidas. Uma conta de origem que já tenha sessão iniciada aí tem o seu nome sincronizado sem substituir as suas credenciais; as outras contas são adicionadas ao lado dela. Para substituir as credenciais guardadas das contas correspondentes, utilize `omarchy agent account copy --replace laptop claude` depois de fechar as sessões dessa conta no destino. Um destino novo também recebe a conta ativa e as preferências de alternância da origem; um destino já estabelecido mantém as suas.

As credenciais viajam através de SSH e são guardadas em ficheiros privados no destino, por isso copie apenas para máquinas em que confia. Isto é uma cópia única, não uma sincronização contínua. Os tokens de atualização do Codex podem ser rodados por outra máquina, deixando um início de sessão copiado a precisar de renovação; inícios de sessão separados continuam a ser a escolha mais fiável para utilização simultânea em várias máquinas. Consulte as [orientações de autenticação de contas do Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Uma conta por fornecedor está ativa, e cada nova sessão começa como ela: `cx`, `cy`, um simples `claude`, `codex` ou `grok`, qualquer coisa iniciada através de `omarchy agent`, e scripts ou editores que encontrem a CLI no `PATH`. Alterne com `omarchy agent account use work` (e volte com `omarchy agent account use main`), ou no painel, premindo o número de uma conta e depois `Enter` (ou clicando no seu botão Use). As sessões que já estão a ser executadas permanecem na conta com que começaram. O histórico de conversas, as definições, as skills e os plugins são partilhados entre contas, por isso `claude --continue` na mesma pasta retoma onde ficou na nova conta.

Com mais do que uma conta, o painel mostra os limites de cada conta lado a lado, com a ativa assinalada. Por predefinição, o Omarchy avisa-o quando a conta ativa ultrapassa 95% de um limite, e clicar na notificação muda para a conta com maior margem. Passe o cursor sobre a linha de uma conta no painel e clique em Autoswitch, que aparece ao lado de Use (ou prima `m`), ou execute `omarchy agent account mode auto`, para que alterne sozinha; enquanto estiver ativa, Autoswitch ocupa o lugar de Use, e clicar novamente volta a avisar. Adicione um número para alterar o limiar, como em `omarchy agent account mode auto 90`. Se todas as contas estiverem acima do limiar, será avisado uma vez, juntamente com a indicação de qual é a conta que fica livre primeiro. Enquanto uma conta ativa estiver a menos de 15 pontos do seu limiar (80% na predefinição), os seus limites são verificados a cada três minutos, em vez de a cada 15.

`omarchy agent account list` mostra todas as contas e os seus limites mais recentes, `omarchy agent account remove work` esquece uma, e `omarchy agent account rename primary Hey` muda o nome a uma (ou clique no nome de uma conta no painel). Estes comandos funcionam nas contas do seu agente predefinido; para chegar ao outro fornecedor, indique-o primeiro, como em `omarchy agent account use codex side`. O início de sessão que já tinha em `~/.claude` ou `~/.codex` é a conta _Main_ e fica onde está. Uma conta deixada sem utilização durante mais de cerca de oito horas pode mostrar _Sign-in required_; clique nela para iniciar novamente sessão nessa conta diretamente no painel, ou inicie uma sessão nela, o que atualiza o início de sessão por si só. Os servidores MCP que tinha quando uma conta foi adicionada acompanham-na, mas os que adicionar mais tarde com `claude mcp add` só chegam à conta em que os adicionou. O Claude Desktop e as ferramentas configuradas com um caminho absoluto para um binário da CLI não acompanham a mudança. Um `CLAUDE_CONFIG_DIR`, `CODEX_HOME` ou `GROK_HOME` explícito tem precedência sobre a conta selecionada.

### Diagnóstico de falhas

O Omarchy vigia o systemd-coredump quanto a falhas de processos. Quando algo sofre um segfault, recebe uma notificação "Process crashed" — clique nela, e a falha é entregue ao seu agente predefinido juntamente com a skill diagnose-crash do Omarchy, que orienta o agente no estabelecimento dos factos a partir do core dump e na decisão sobre se a falha vale a pena ser comunicada a montante. Também pode executá-la manualmente contra qualquer PID de `coredumpctl list` com `omarchy agent crash <pid>`.

A vigilância está ativa por predefinição. Desative-a em _Trigger > Toggle > Crash Capture_ (ou com `omarchy toggle crash-capture`) e as notificações param; o `omarchy agent crash <pid>` continua a funcionar manualmente.

As falhas também podem ser silenciadas um programa de cada vez, que é o que o diagnóstico lhe oferece no fim. `omarchy crash mute hyprland` para as notificações apenas desse programa, `omarchy crash mute hyprland off` volta a ativá-las, e `omarchy crash mute`, sozinho, lista o que silenciou. Aceita o caminho do binário tão bem como o seu nome, por isso `omarchy crash mute /usr/bin/hyprland` faz o mesmo. Coloque entre aspas um nome com um espaço, como em `omarchy crash mute 'Some App'`. Tudo o resto continua a notificar, e o programa silenciado continua a falhar — isto esconde o lembrete, não corrige nada.

### Aplicações de ambiente de trabalho

O menu _Instalar > IA_ também inclui algumas aplicações gráficas de IA: a aplicação de ambiente de trabalho do ChatGPT, a aplicação de ambiente de trabalho do Claude (a beta para Linux da Anthropic, com os separadores Chat, Cowork e Claude Code), o Grok Bot para conversar com os modelos da xAI, o Hermes Desktop, o OpenClaw, a aplicação de ambiente de trabalho do Perplexity e o T3 Code. O Grok Bot é a aplicação de conversação para ambiente de trabalho. O agente de programação é o comando `grok`.

O Hermes Desktop é o que importa conhecer, porque uma máquina tem um Hermes, e é o da aplicação: o Hermes só é instalado através da aplicação, e o comando `hermes` que o agente predefinido executa é o da aplicação. Escolher o Hermes como agente predefinido instala o mesmo que a entrada _Instalar > IA_: o pacote e um runtime Hermes em `~/.hermes` configurado pelo instalador próprio do Hermes, o que demora alguns minutos na primeira vez. Esse runtime é o único Hermes que o comando `hermes` do terminal, o agente predefinido e a aplicação utilizam, e atualiza-se a si próprio com `hermes update`, em vez de ficar à espera de uma versão do Omarchy. Instalá-lo também entrega ao Hermes o tema do Omarchy como uma skin chamada `omarchy`, que todas as superfícies do Hermes seguem à medida que muda de tema; escolha outra nas definições de Aparência do Hermes ou com `/skin`, se preferir que não o faça, e o Omarchy respeita essa escolha. Remover a aplicação em _Remover > IA_ fecha primeiro o Hermes, gateway incluído, leva esse runtime consigo e mantém as suas conversas, memórias e as skills que o Hermes escreveu para si próprio, a menos que diga o contrário: pergunta, com não como predefinição, se esses dados e as suas definições de ligação também devem ser removidos.

A experiência de ambiente de trabalho do OpenClaw é a sua Control UI, que se abre como uma aplicação web suportada pelo seu próprio gateway local. O OpenClaw vive em `~/.openclaw` e atualiza-se a si próprio: utilize o botão "Update Gateway" da Control UI ou execute `openclaw update`, e o gateway reinicia na nova versão. O Omarchy apenas escolhe a versão a partir da qual uma instalação nova começa. Remover o OpenClaw em _Remover > IA_ leva consigo o serviço do gateway e a aplicação e, depois, pergunta se `~/.openclaw` também deve ser removido, uma vez que é aí que estão as suas conversas e credenciais, juntamente com o próprio OpenClaw e os runtimes de plugins que descarrega; a predefinição mantém-no, e instalar o OpenClaw novamente volta a utilizá-lo.

O T3 Code funciona a partir da sua versão AppImage oficial em `~/.local/share/t3code`, em vez de a partir de um pacote, por isso atualiza-se a si próprio. Instalá-lo pergunta se quer começar no canal Stable ou Nightly; altere mais tarde nas definições do T3 Code. Os seus tópicos e definições vivem em `~/.t3`, e remover o T3 Code em _Remover > IA_ leva-os consigo.

### LLMs locais

O Omarchy recomenda duas formas de executar modelos LLM locais: o LM Studio e o Ollama. O LM Studio fornece uma interface gráfica para encontrar modelos de pesos abertos, instalá-los e executá-los. É uma ótima forma de começar facilmente. O Ollama oferece uma CLI para fazer o mesmo. Mas, se é novo nos modelos locais, eu começaria pelo LM Studio. Pode instalar qualquer um deles em _Instalar > IA_ no Menu Omarchy.

### A Skill do Omarchy

As skills de agente ajudam a IA a utilizar ferramentas específicas de uma forma específica, e o Omarchy vem com uma skill predefinida para personalizar o sistema. Como ajustar a sua configuração do Hyprland, ajustar a barra ou até criar um tema novo de raiz. Está ligada por symlink aos diretórios de skills do Claude Code (`~/.claude/skills`), do Codex (`~/.codex/skills`), do Pi (`~/.pi/agent/skills`), do Antigravity (`~/.gemini/config/skills`), do Hermes (`~/.hermes/skills` e cada `~/.hermes/profiles/*/skills`) e à localização genérica `~/.agents/skills`, por isso a maioria dos harnesses recolhe-a automaticamente.

Mas deve tratar esta skill como experimental. Modelos diferentes vão utilizá-la com efeitos diferentes. É melhor executá-la primeiro em modo de plano, para ter uma ideia do que o agente gostaria de alterar. E, depois, estar pronto para reverter alterações ou até invocar `omarchy reinstall configs`, se o agente fizer uma confusão com tudo.
