# IA

O Omarchy inclui lançadores para os agentes de programação abaixo sem escolher um predefinido para ti. Executa um comando para instalar a respetiva CLI na primeira utilização e depois autentica-te quando for pedido. Hermes e OpenClaw são as exceções: nada é instalado para eles através do mise, e escolher qualquer um deles configura a sua própria cópia com atualização automática, como a secção _Aplicações de ambiente de trabalho_ abaixo explica.

### Instalar e atualizar agentes

Exceto Hermes e OpenClaw, estes agentes utilizam a instalação lazy do mise: o primeiro arranque instala a CLI, e os arranques posteriores reutilizam-na. O mise também verifica se um agente instalado tem uma nova versão, no máximo uma vez de quatro em quatro horas, mesmo antes de arrancar ou em segundo plano num prompt da shell. Se essa atualização falhar ou estiveres offline, é executada a versão instalada. `omarchy update` atualiza os agentes instalados com o resto do Omarchy, e `mup` atualiza apenas as ferramentas geridas pelo mise.

Um atualizador próprio de um agente, como `claude update`, `codex update`, ou um botão de atualização numa aplicação, não atualiza a instalação gerida pelo mise. `codex update` falha, e `claude update` pode comunicar sucesso enquanto instala uma cópia separada que o mise não acompanha. Se preferires usar o instalador e o atualizador nativos de um agente, adiciona-o a `disable_tools`; vê [Ferramentas CLI pré-instaladas](18-development-tools.md#preinstalled-cli-tools).

Para instalar todas as ferramentas lazy configuradas antes de precisares delas, executa `mise install --include-lazy`. Isto inclui as outras ferramentas CLI predefinidas do Omarchy, bem como os agentes. Vê [Ferramentas CLI pré-instaladas](18-development-tools.md#preinstalled-cli-tools) para instalar uma única ferramenta ou usares a tua própria instalação.

`grok` é instalado através do pacote first-party `grok` do mise, da mesma forma que `claude` e `codex`. Executa `grok`, ou marca-o com uma estrela no painel de agentes. Salta o instalador `curl | bash` em x.ai. Esse caminho coloca uma segunda cópia em `~/.grok/bin`, coloca-a no início de `PATH` e substitui o wrapper do Omarchy.

`dsh` abre a sua interface de browser em `127.0.0.1:3080`, com o diretório de arranque como área de trabalho predefinida. A sua interface de browser não aceita um prompt inicial, por isso `omarchy agent prompt` abre-a com o prompt na tua área de transferência para colares. O Omarchy arranca-o com o preset de permissões sem aprovação da DeepSeek. O DeepSeek Harness envia registos de sessão para a DeepSeek quando usas a sua API oficial de modelos; desativa isso em _Settings > General > Upload Session Log_ na sua interface de browser. O feedback que lhe enviares também é enviado com a sessão, a menos que o arranques com `DSH_TELEMETRY_MODE=DISABLED`.

### O agente predefinido

Escolhe o teu agente predefinido com a estrela ao lado de um agente no painel de agentes, que aparece preenchida no predefinido, ou com `omarchy default agent <name>`, que também aceita qualquer harness sem uma linha lá. Se o agente ainda não estiver instalado, escolhê-lo instala-o primeiro, e também ganha um lançador próprio no lançador de aplicações, ao lado de Agent. Uma instalação nova do Omarchy convida-te a configurar um com uma notificação única, que abre o painel de agentes.

Escolher o Claude também tenta configurar a sua extensão de browser para Chromium, Chrome, Brave, Brave Origin e Edge. A configuração da extensão aplica-se a todos os utilizadores e pode pedir a tua palavra-passe do sistema; cancelar ou uma instalação falhada da extensão continua a selecionar e a arrancar o Claude. Reinicia o browser, ativa a extensão se for pedido e inicia sessão no Claude para terminar de a ligar. Executa `/chrome` no Claude para verificar a ligação. Firefox e Zen não suportam esta extensão. Se o Claude já era o teu predefinido antes de esta configuração ser adicionada, seleciona-o novamente para instalar a extensão.

Depois de escolheres, `Super + Shift + Ctrl + A` arranca o agente predefinido numa janela de terminal dedicada (ou abre o seletor se ainda não tiveres escolhido nenhum). Também podes arrancá-lo diretamente numa tarefa com `omarchy agent prompt "Review this project"`. Freebuff e DeepSeek Harness não aceitam um prompt inicial, por isso abrem com o prompt na tua área de transferência para colares. Os agentes arrancados desta forma executam sem supervisão nos respetivos modos de não parar para perguntar, por isso prepara-te para eles fazerem coisas a sério! O MiniMax Code não tem esse modo para as suas sessões interativas, por isso pede permissões como habitualmente. E como os agentes se recusam a memorizar a confiança para o teu diretório pessoal, os arranques a partir de `$HOME` começam antes em `~/Work`.

Também há atalhos de terminal: `a` executa o agente predefinido inline no terminal atual, enquanto `c`, `cx` e `cy` iniciam OpenCode, Claude Code e Codex diretamente (também nos seus modos de aprovação automática). As mudanças de tema também se sincronizam com os agentes: Claude Code, Pi, OpenCode e Hermes (depois de o Omarchy o ter instalado) acompanham-te a todos quando mudas o tema do Omarchy.

### As tuas instruções para os agentes

As regras pessoais para todos os agentes vão para `~/.agents/AGENTS.md`, ao lado das skills partilhadas em `~/.agents/skills`. Abre-o com o ícone de documento ao lado do + no painel de agentes, ou `omarchy agent instructions --edit`, que também o liga a cada harness que mantém o seu próprio ficheiro global: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, o `~/.copilot/copilot-instructions.md` do Copilot, e assim por diante. Crush e Amp leem a ligação `~/.config/AGENTS.md`, enquanto omp, Kimi e DeepSeek Harness leem `~/.agents/AGENTS.md` diretamente. Escolher um agente predefinido também a liga. Um ficheiro de instruções que já tinhas passa a ser o partilhado se ainda não houvesse nenhum; caso contrário, é guardado ao lado da ligação como `.bak`. Executa `omarchy agent instructions` para voltar a ligar depois de instalares outro agente.

### O painel de agentes

A barra superior tem um ícone de agentes. Antes de teres configurado um agente, o painel oferece três formas de começar: iniciar sessão numa subscrição Claude, Codex, Grok, Gemini, Muse, Cursor ou Copilot, ou, em More, num plano de programação OpenCode Go, MiniMax, Synthetic ou Z.ai; pagar à medida que usas com Fireworks, OpenCode Zen and Go, OpenRouter, ou, em More, DeepSeek ou qualquer outro fornecedor em que o OpenCode inicie sessão, todos executados no OpenCode; ou executar o melhor modelo para o teu computador, quando houver um que lhe sirva. O primeiro que terminares torna-se o teu agente predefinido, e o + no painel, ou _Agent > Add_ no Omarchy Menu, oferece as mesmas três opções mais tarde. Depois disso, o painel coloca todas as subscrições numa só página: cada agente e conta com o seu plano, um medidor para cada um dos seus limites de sessão de 5 horas e semanais com o tempo até reiniciar (passa o rato por cima para veres a percentagem exata), ou o saldo pré-pago restante, sob uma linha que vai rodando pelo que usaste em todos eles, como tokens esta semana e o teu modelo mais usado. Em _Make something cool_, oferece prompts iniciais para um novo tema, plugin, aplicação ou jogo que entregam a tarefa ao teu agente predefinido. As aplicações são construídas da forma como as próprias Hype, Monologue e Omacut do Omarchy são, em C++ e Qt Quick, a seguir a skill de agente omarchy-make-app, e o compilador e as peças Qt de que precisam vêm instalados. Os jogos são uma única página three.js em `~/Games/vibes`, a seguir a skill de agente omarchy-make-game, e todos abrem a partir de um único lançador Game Vibes no tema atual; carregam three.js da Web, por isso precisam de uma ligação para arrancar. Claude Code, Codex, Grok, Kimi, Cursor e a sua quota Grok Bot, GitHub Copilot, Muse, Gemini (através do Antigravity) e Devin estão cobertos de fábrica com os seus limites, Kimchi com o seu plano, créditos pré-pagos e orçamentos de gastos, e Hermes, Mistral Vibe e Qwen Code mostram as suas sessões e tokens depois de os teres usado. Os planos e chaves de fornecedores que usas através de pi, omp ou opencode também aparecem: OpenCode Zen and Go, o Z.ai GLM Coding Plan, Ollama Cloud, o MiniMax Token Plan e Synthetic com os seus limites; OpenRouter e DeepSeek com os seus saldos pré-pagos; Fireworks com os seus gastos nos últimos 30 dias. Os tokens de modelos que executas no teu próprio hardware também contam para os totais; os próprios modelos têm um painel próprio, descrito em [Modelos locais](#local-models). Cada agente é contado uma vez, sob quem o fatura, por mais harnesses que uses para o conduzir.

Clica com o botão esquerdo no ícone da barra ou prime `Super + Ctrl + X` para o painel, clica com o botão direito para arrancar o teu agente predefinido e clica com o botão do meio para atualizar. Os registos de utilização por trás dele são regenerados a cada 15 minutos por `omarchy agent usage update`, e o painel pode até fundir a utilização das tuas outras máquinas através de uma pasta sincronizada. Vê o README em `$OMARCHY_PATH/shell/plugins/agents/` para as definições completas.

### Várias subscrições

Se pagares por mais do que um plano Claude, Codex ou Grok — um Max pessoal e um de trabalho, por exemplo — o Omarchy pode manter todos com sessão iniciada e mover-se entre eles. Adiciona uma subscrição com o + no painel de agentes, que te guia ali mesmo, ou com `omarchy agent account add claude Work` (ou `codex`, ou `grok`). O mesmo + e comando iniciam sessão no Gemini (`gemini`) e no OpenCode (`opencode`), e guardam uma chave API Fireworks (`fireworks`) ou OpenRouter (`openrouter`) no OpenCode; o comando também inicia sessão no Copilot (`copilot`), no Cursor (`cursor`) e no Muse (`muse`). Esses mantêm uma única sessão cada um. Instala a CLI se estiver em falta. A primeira conta de um fornecedor inicia sessão através do teu browser normal, exatamente onde a CLI sempre procura. Cada uma a seguir inicia sessão através de uma janela privada, para que a conta em que o teu browser já tem sessão iniciada não seja apanhada por engano; inicia sessão aí como a conta que estás a adicionar e fecha primeiro qualquer janela privada que já tenhas aberta. Nunca termines sessão na CLI para fazer isto: terminar sessão revoga o início de sessão guardado, e essa conta teria de ser adicionada outra vez.

Para copiar os teus inícios de sessão de subscrição para outra máquina Omarchy por SSH, executa `omarchy agent account copy user@laptop`. O emissor fornece um recetor temporário quando o destino não tem um instalado, por isso máquinas Omarchy mais antigas podem receber contas sem uma atualização. Os recetores instalados têm precedência. Isto copia todas as subscrições Claude, Codex e Grok; adiciona nomes de fornecedores para as selecionar, como em `omarchy agent account copy laptop claude`. Os nomes de contas e os ID de comandos coincidem com a origem, incluindo contas já presentes no destino. As contas do destino não relacionadas recebem um sufixo numérico se os seus nomes entrarem em conflito, e definições, skills, plugins e histórico de conversas permanecem locais a cada máquina.

As credenciais existentes no destino são mantidas. Uma conta de origem que já tenha sessão iniciada lá vê o seu nome sincronizado sem substituir as suas credenciais; as outras contas são adicionadas ao lado dela. Para substituir as credenciais guardadas de contas correspondentes, usa `omarchy agent account copy --replace laptop claude` depois de fechares as sessões dessa conta no destino. Um destino novo também recebe a conta ativa e as preferências de troca da origem; um destino já estabelecido mantém as suas próprias.

As credenciais viajam por SSH e são guardadas em ficheiros privados no destino, por isso copia apenas para máquinas em que confias. Isto é uma cópia única, não uma sincronização contínua. Os tokens de atualização do Codex podem ser rodados por outra máquina, a deixar um início de sessão copiado a precisar de renovação; inícios de sessão separados continuam a ser a escolha mais fiável para utilização simultânea em várias máquinas. Vê [o guia de autenticação de contas do Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Uma conta por fornecedor está ativa, e cada nova sessão começa como ela: `cx`, `cy`, um simples `claude`, `codex` ou `grok`, qualquer coisa arrancada através de `omarchy agent`, e scripts ou editores que encontrem a CLI em `PATH`. Muda com `omarchy agent account use work` (e volta com `omarchy agent account use main`), ou no painel ao premir o número de uma conta e depois `Enter` (ou ao clicar na sua estrela). As sessões Claude em execução também mudam, a partir da sua próxima mensagem: cada sessão Claude executa em `~/.claude`, que guarda sempre o início de sessão da conta ativa. Uma sessão Claude iniciada na pasta própria de uma conta por um Omarchy mais antigo mantém esse início de sessão até sair, por isso a mudança nomeia essas sessões e termina sozinha quando elas desaparecerem. As sessões Codex e Grok em execução mantêm-se na conta com que começaram. O histórico de conversas, definições, skills e plugins são partilhados entre contas, por isso `claude --continue` na mesma pasta continua onde paraste na nova conta.

Com mais do que uma conta, o painel mostra os limites de cada conta lado a lado, com uma estrela preenchida na que está em uso. O Omarchy avisa-te quando a conta ativa passa 95% de um limite, e clicar na notificação muda para a conta com mais margem. Nunca muda sozinho. Altera o limiar com `omarchy agent account threshold 90`. Se todas as contas estiverem acima do limiar, vais saber disso uma vez, juntamente com qual conta fica livre primeiro. Enquanto uma conta ativa estiver a menos de 15 pontos do seu limiar (80% na predefinição), os seus limites são verificados de três em três minutos em vez de de 15 em 15.

`omarchy agent account list` mostra todas as contas e os seus limites mais recentes, `omarchy agent account remove work` esquece uma, e `omarchy agent account rename primary Hey` renomeia uma (ou clica no nome de uma conta no painel). Estes comandos funcionam nas contas do teu agente predefinido; para chegares ao outro fornecedor, nomeia-o primeiro, como em `omarchy agent account use codex side`. O início de sessão que já tinhas em `~/.claude` ou `~/.codex` é a conta _Main_. A do Codex fica onde está; a do Claude espera numa pasta própria enquanto outra conta estiver ativa. Uma conta que fique sem uso por mais de cerca de oito horas pode mostrar _Sign-in required_; clica nela para iniciar sessão nessa conta outra vez diretamente no painel, ou muda para ela e inicia uma sessão, o que atualiza o início de sessão por si só. Os servidores MCP que adicionares com `claude mcp add` chegam a todas as contas Claude, pois todas executam em `~/.claude`; para Codex e Grok, os servidores que tinhas quando uma conta foi adicionada acompanham-na, mas os posteriores só chegam à conta em que os adicionaste. Claude Desktop mantém um início de sessão próprio, e as ferramentas Codex ou Grok configuradas com um caminho absoluto para um binário CLI não seguem a mudança. Um `CLAUDE_CONFIG_DIR`, `CODEX_HOME` ou `GROK_HOME` explícito tem precedência sobre a conta selecionada.

### Diagnóstico de crashes

O Omarchy vigia o systemd-coredump à procura de crashes de processos. Depois de teres escolhido um agente predefinido, qualquer programa teu que faça dump de core traz uma notificação "Process crashed" — clica nela, e o crash é entregue ao teu agente predefinido juntamente com a skill omarchy-diagnose-crash do Omarchy, que guia o agente a estabelecer os factos a partir do core dump e a decidir se o crash vale a pena ser comunicado a montante. Também podes executá-la manualmente contra qualquer PID de `coredumpctl list` com `omarchy agent crash <pid>`.

A vigilância está ativada por predefinição. Desativa-a em _Trigger > Toggle > Crash Capture Off_ (ou com `omarchy toggle crash-capture`) e as notificações param; `omarchy agent crash <pid>` continua a funcionar manualmente.

Os crashes também podem ser silenciados um programa de cada vez, que é o que o diagnóstico te oferece no fim. `omarchy crash mute hyprland` para as notificações só para esse programa, `omarchy crash mute hyprland off` traz-as de volta, e `omarchy crash mute` sozinho lista o que silenciaste. Aceita o caminho do binário tão bem como o seu nome, por isso `omarchy crash mute /usr/bin/hyprland` faz a mesma coisa. Coloca entre aspas um nome com um espaço, como em `omarchy crash mute 'Some App'`. Todo o resto continua a notificar, e o programa silenciado continua a crashar — isto esconde o lembrete, não resolve nada.

### Aplicações de ambiente de trabalho

O menu _Install > AI_ também traz algumas aplicações gráficas de IA: Amp Desktop, Antigravity Desktop, a aplicação de ambiente de trabalho ChatGPT, a aplicação de ambiente de trabalho Claude (a beta Linux da Anthropic, com separadores Chat, Cowork e Claude Code), Grok Bot para conversar com os modelos da xAI, Herdr Desktop, Hermes Desktop, OpenClaw, a aplicação de ambiente de trabalho Perplexity e T3 Code. Grok Bot é a aplicação de chat de ambiente de trabalho. O agente de programação é o comando `grok`.

Hermes Desktop é a que tens de conhecer, porque uma máquina tem um Hermes, e é o da aplicação: o Hermes só é alguma vez instalado através da aplicação, e o comando `hermes` que o agente predefinido executa é o da aplicação. Escolher o Hermes como agente predefinido instala a mesma coisa que a entrada _Install > AI_: o pacote, e um runtime Hermes em `~/.hermes` configurado pelo próprio instalador do Hermes, o que demora alguns minutos na primeira vez. Esse runtime é o único Hermes que o comando `hermes` do terminal, o agente predefinido e a aplicação usam todos, e atualiza-se a si próprio com `hermes update` em vez de esperar por uma versão do Omarchy. Instalá-lo também entrega ao Hermes o tema Omarchy como uma skin chamada `omarchy`, que todas as superfícies Hermes seguem à medida que mudas de tema; escolhe outra nas definições de Appearance do Hermes ou com `/skin` se preferires que não o faça, e o Omarchy deixa essa escolha em paz. Remover a aplicação em _Remove > AI_ fecha primeiro o Hermes, gateway incluído, leva esse runtime com ele, e mantém os teus chats, memórias e as skills que o Hermes escreveu para si próprio, a menos que lhe digas o contrário: pergunta, com não como predefinição, se esses dados e as tuas definições de ligação também devem ir.

A experiência de ambiente de trabalho do OpenClaw é a sua Control UI, que abre como uma aplicação Web apoiada pelo seu próprio gateway local. O OpenClaw vive em `~/.openclaw` e atualiza-se a si próprio: usa o botão "Update Gateway" da Control UI ou executa `openclaw update`, e o gateway reinicia na nova versão. O Omarchy só escolhe a versão a partir da qual uma instalação nova começa. O OpenClaw também pode ser o teu agente predefinido: escolhê-lo em _Agent > Harness_ configura essa mesma cópia em `~/.openclaw`, e o agente abre a interface de terminal do OpenClaw ligada ao seu gateway. Remover o OpenClaw em _Remove > AI_ leva o serviço gateway e a aplicação com ele e depois pergunta se `~/.openclaw` também deve ir, uma vez que isso guarda os teus chats e credenciais ao lado do próprio OpenClaw e dos runtimes de plugins que ele descarrega; a predefinição mantém-no, e instalar o OpenClaw outra vez volta a apanhá-lo.

Herdr Desktop é a aplicação de ambiente de trabalho [Herdr](https://herdr.dev): espaços, separadores e painéis de terminais e agentes de programação que continuam a executar no seu núcleo quando fechas a janela. Vem do próprio instalador do Herdr em vez de um pacote, por isso vive em `~/.local/share/herdr-app`, traz o seu núcleo em `~/.local/bin/herdr-core` quando ainda não tens um, e atualiza ambos por si própria. Fica ao lado do comando `herdr` que o Omarchy fornece em `Super + Ctrl + Return` em vez de o substituir, e recebe as teclas diretas desse comando: `Alt + Return` e `Alt + Shift + Return` dividem um painel para baixo ou para a direita, `Alt + Escape` fecha-o, `Ctrl + Alt + Arrow` move entre painéis, `Alt + 1..9` e `Alt + Left/Right` escolhem um separador, e `Alt + Up/Down` movem entre espaços. `Ctrl + 1..9` escolhe um espaço e `Alt + Shift + Up/Down` passa pelos agentes. As teclas de prefixo `Ctrl + Space` permanecem só no terminal, uma vez que a aplicação não consegue manter uma tecla Ctrl simples para uma sequência. O Omarchy escreve estas em `~/.config/herdr-app/keys.json`, e `omarchy-refresh-herdr-app` volta a colocá-las. Instalá-la escolhe o tema Omarchy do Herdr, que a partir daí segue o teu tema Omarchy. O Herdr mantém um tema para o modo claro e um para o modo escuro, por isso, depois de mudares entre um tema Omarchy escuro e um claro, escolhe Omarchy no seletor de temas do Herdr uma vez mais para o outro modo.

T3 Code executa a partir da sua versão oficial AppImage em `~/.local/share/t3code` em vez de um pacote, por isso atualiza-se a si próprio. Instalá-lo pergunta se deve começar no canal Stable ou Nightly; muda mais tarde nas definições do T3 Code. As tuas threads e definições vivem em `~/.t3`, e remover o T3 Code em _Remove > AI_ leva-as com ele.

### Modelos locais

Executa um modelo aberto na tua própria máquina para os teus agentes de programação. Os teus prompts e código ficam na máquina; nada do que é enviado ao modelo sai dela. Começa com:

```bash
omarchy models use best text
```

Isso configura o melhor modelo de texto para esta máquina, o tipo que os teus agentes usam. Os modelos de imagem, vídeo e música têm um melhor próprio cada um: `omarchy models use best image`, `video` ou `music`. Executa `omarchy models use best` para ver a escolha de cada tipo para esta máquina.

Ou abre o painel de modelos locais a partir do seu ícone de brilhos na barra superior, ao lado do ícone de agentes, ou com Super + Ctrl + Alt + X, e escolhe +. O ícone aparece quando um modelo serve nesta máquina. Podman, que executa os modelos, vem com o Omarchy, tal como o kit de ferramentas de contentores da NVIDIA numa máquina NVIDIA, que lhes dá a GPU; se algum estiver em falta, a primeira configuração instala-o. Depois o Omarchy escolhe o modelo recomendado para esta máquina, descarrega-o e arranca-o. Espera uma descarga de dezenas de GB e a maior parte da memória da máquina em uso enquanto o modelo executa: Flash Next usa cerca de 100 GiB com o seu contexto completo de 256K. Se outros modelos ocuparem a memória de que ele precisa, ele é configurado parado, pronto para arrancar quando parares um. O modelo para ao terminar sessão; para-o tu quando precisares da memória para outra coisa.

`omarchy models list` mostra as opções e explica por que algumas não servem. Para configurar outro, executa `omarchy models use <recipe>`. Hoje, `qwen3.8-flash-next-gufo` e `qwen3.8-27b-gufo` estão disponíveis para máquinas Strix Halo de 128 GB; o 27B usa cerca de 40 GiB, por isso deixa espaço para outro trabalho. Num portátil de 64 GB com Arc B390 da Intel, `qwen3.6-35b-a3b-llamacpp` executa em cerca de 30 GiB. Novas receitas e recomendações chegam com `omarchy update`, através do pacote.

Cada modelo que configurares ganha a sua própria linha no painel de modelos locais: play para o arrancar, pause para o parar e libertar a sua memória, e o botão de terminal para abrir o teu agente nele. Ao longo do topo, uma barra mostra como a memória da máquina está dividida entre o próprio Omarchy (o sistema e as tuas aplicações), cada modelo em execução e o que está livre. Aponta para um modelo parado e a barra mostra se ele serve, ou quanto lhe falta. Vários podem executar ao mesmo tempo quando servem juntos na memória; se um não servir, o Omarchy diz que modelo em execução deves parar. Arrasta linhas pelo seu logótipo para as reordenar, e prime Delete numa linha selecionada para remover um modelo e a sua descarga.

Cada modelo de programação que configurares também ganha a sua própria entrada no lançador de aplicações, sob o nome do modelo e com o logótipo do seu fabricante, da forma como iniciar sessão no Claude, Codex ou Grok adiciona uma. Abre o teu agente nesse modelo, e arranca o modelo primeiro se ele não estiver em execução: o terminal mostra-o a carregar e entrega ao agente quando ele estiver pronto. Remover um modelo remove a sua entrada.

Nem todos os modelos são para programação. Os modelos de imagem, vídeo e música abrem antes no Fantasi, a aplicação do Omarchy para fazer imagens, vídeo e música com um modelo a executar nesta máquina, escolhidos lá ou a partir da sua linha no painel de modelos locais.

Um modelo continua a executar exatamente como foi configurado, por isso uma atualização do Omarchy nunca reinicia um por baixo dos teus agentes. Quando o Omarchy tem um runtime mais recente ou pesos mais recentes para um modelo que tens configurado, a sua linha mostra um botão de atualização: prime-o e o modelo é configurado outra vez em segundo plano, a descarregar apenas o que mudou, e reinicia na nova versão. Um modelo que estava parado continua parado. `omarchy models update` faz o mesmo para todos os modelos a partir de um terminal.

A partir da linha de comandos, `omarchy models start <recipe>` e `omarchy models stop <recipe>` fazem o mesmo, `omarchy models status` mostra todos os modelos, e `omarchy agent --local` abre o último modelo que arrancaste no pi, seja qual for o teu agente predefinido. Para fazer desse modelo o que a tecla de atalho do agente, a consola Quake e _Make something_ abrem, executa `omarchy default agent local` ou escolhe _Local model_ em _Agent > Harness_. O pi também lista todos os modelos que configuraste, e os das máquinas com que emparelhaste, no seu próprio seletor de modelos, por isso um simples `pi` também chega a eles. Qualquer cliente compatível com OpenAI também se pode ligar: `status` mostra o endereço de cada modelo (o primeiro é `http://127.0.0.1:11435/v1`), o nome da receita é o modelo, e a chave está em `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` elimina um modelo e as descargas que nenhum outro modelo usa.

Os runtimes de terceiros são etiquetados com o seu fornecedor. O Omarchy executa todos os modelos sem acesso à rede.

### LLM locais

O Omarchy recomenda duas formas de executar modelos LLM locais: LM Studio e Ollama. O LM Studio fornece uma interface gráfica para encontrar modelos de pesos abertos, instalá-los e executá-los. É uma ótima forma de começar facilmente. O Ollama oferece uma CLI para fazer o mesmo de forma semelhante. Mas se és novo nos modelos locais, eu começaria pelo LM Studio. Podes instalar qualquer um em _Install > AI_ no Omarchy Menu.

### As skills do Omarchy

As skills de agente ajudam a IA a usar ferramentas específicas de uma forma específica, e o Omarchy traz sete delas. A skill omarchy abrange personalizar o sistema, como ajustar a tua configuração Hyprland ou ajustar a barra. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app e omarchy-make-game abrangem fazer algo novo, omarchy-contribute abrange comunicar um erro ou enviar uma correção a montante, e omarchy-diagnose-crash trabalha sobre o core dump de um crash. Estão ligadas por symlink aos diretórios de skills do Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` e cada `~/.hermes/profiles/*/skills`), e à localização genérica `~/.agents/skills`, por isso a maioria dos harnesses apanha-as automaticamente. Uma pasta de skill tua com o mesmo nome tem precedência.

Mas deves tratar estas skills como experimentais. Modelos diferentes vão usá-las com efeitos diferentes. É melhor executar primeiro em modo de plano, para teres uma ideia do que o agente gostaria de mudar. E depois prepara-te para reverter alterações ou até invocar `omarchy reinstall configs`, se o agente fizer uma confusão de tudo.
