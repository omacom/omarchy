# IA

O Omarchy inclui lançadores para os agentes de programação abaixo sem escolher um predefinido por si. Execute um comando para instalar a respetiva CLI na primeira utilização e, em seguida, autentique-se quando lhe for pedido. O Hermes é a exceção: nada é instalado para ele na primeira utilização e, ao escolhê-lo, é instalado o Hermes Desktop, como explica a secção _Aplicações de ambiente de trabalho_ mais abaixo.

### Instalar e atualizar agentes

Com exceção do Hermes, estes agentes utilizam a instalação lazy do mise: a primeira execução instala a CLI e as execuções seguintes reutilizam-na. O mise também verifica se existe uma nova versão de um agente instalado, no máximo uma vez a cada quatro horas, mesmo antes de o iniciar ou em segundo plano numa prompt da shell. Se essa atualização falhar ou estiver offline, é executada a versão instalada. O `omarchy update` atualiza os agentes instalados juntamente com o resto do Omarchy, e o `mup` atualiza apenas as ferramentas geridas pelo mise.

Um atualizador próprio de um agente, como `claude update`, `codex update` ou um botão de atualização numa aplicação, não atualiza a instalação gerida pelo mise. O `codex update` falha, e o `claude update` pode comunicar sucesso enquanto instala uma cópia separada que o mise não acompanha. Se preferir utilizar o instalador e o atualizador nativos de um agente, adicione-o a `disable_tools`; consulte [Ferramentas CLI pré-instaladas](18-development-tools.md#preinstalled-cli-tools).

Para instalar todas as ferramentas lazy configuradas antes de precisar delas, execute `mise install --include-lazy`. Isto inclui as outras ferramentas CLI predefinidas do Omarchy, bem como os agentes. Consulte [Ferramentas CLI pré-instaladas](18-development-tools.md#preinstalled-cli-tools) para instalar uma única ferramenta ou utilizar a sua própria instalação.

O `grok` é instalado através do pacote `grok` próprio do mise, da mesma forma que o `claude` e o `codex`. Execute `grok`, ou escolha-o em _Agente > Harness_. Ignore o instalador `curl | bash` em x.ai. Esse caminho coloca uma segunda cópia em `~/.grok/bin`, coloca-a no início do `PATH` e substitui o wrapper do Omarchy.

O `dsh` abre a sua interface de utilizador no browser em `127.0.0.1:3080`, com o diretório de lançamento como área de trabalho predefinida. A sua interface no browser não aceita um prompt inicial, pelo que o `omarchy agent prompt` a abre com o prompt na área de transferência para colar. O Omarchy inicia-o com a predefinição de permissões sem aprovação da DeepSeek. O DeepSeek Harness envia registos de sessão para a DeepSeek quando utiliza a API oficial de modelos da mesma; desative isso em _Settings > General > Upload Session Log_ na respetiva interface no browser. Os comentários que lhe enviar também são enviados juntamente com a sessão, a menos que o inicie com `DSH_TELEMETRY_MODE=DISABLED`.

### O agente predefinido

Escolha o seu agente predefinido com `omarchy default agent <name>` ou em _Agente > Harness_ no Menu do Omarchy (`Super + Space`). Se o agente ainda não estiver instalado, ao escolhê-lo, ele é instalado primeiro. Uma instalação nova do Omarchy convidá-lo-á a fazer esta escolha através de uma notificação única.

Ao escolher o Claude, tenta também configurar a respetiva extensão de browser para Chromium, Chrome, Brave, Brave Origin e Edge. A configuração da extensão aplica-se a todos os utilizadores e pode pedir a sua palavra-passe do sistema; cancelar ou falhar a instalação da extensão continua a selecionar e a iniciar o Claude. Reinicie o browser, ative a extensão se lhe for pedido e inicie sessão no Claude para concluir a ligação. Execute `/chrome` no Claude para verificar a ligação. O Firefox e o Zen não suportam esta extensão. Se o Claude já era o seu predefinido antes de esta configuração ser adicionada, selecione-o novamente para instalar a extensão.

Depois de escolher, `Super + Shift + Ctrl + A` inicia o agente predefinido numa janela de terminal dedicada (ou abre o seletor se ainda não tiver escolhido). Também pode iniciá-lo diretamente numa tarefa com `omarchy agent prompt "Review this project"`. O Freebuff e o DeepSeek Harness não aceitam um prompt inicial, pelo que abrem com o prompt na área de transferência para colar. Os agentes iniciados desta forma funcionam sem supervisão nos respetivos modos de não parar para perguntar, por isso esteja preparado para que façam realmente coisas! O MiniMax Code não tem esse modo para as suas sessões interativas, pelo que pede permissões como habitualmente. E, uma vez que os agentes se recusam a memorizar a confiança no seu diretório pessoal, os lançamentos a partir de `$HOME` começam antes em `~/Work`.

Também existem atalhos de terminal: `a` executa o agente predefinido inline no terminal atual, enquanto `c`, `cx` e `cy` iniciam diretamente o OpenCode, o Claude Code e o Codex (novamente nos respetivos modos de aprovação automática). As alterações de tema também são sincronizadas com os agentes: o Claude Code, o Pi, o OpenCode e o Hermes (depois de o Omarchy o ter instalado) acompanham-no quando muda o tema do Omarchy.

### As suas instruções para os agentes

As regras pessoais para todos os agentes ficam em `~/.agents/AGENTS.md`, junto às skills partilhadas em `~/.agents/skills`. Abra-o em _Agente > Instruções_, que também o liga a cada harness que mantém o seu próprio ficheiro global: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, o `~/.copilot/copilot-instructions.md` do Copilot, e assim por diante. O Crush e o Amp leem a ligação `~/.config/AGENTS.md`, enquanto o omp, o Kimi e o DeepSeek Harness leem `~/.agents/AGENTS.md` diretamente. Escolher um agente predefinido também cria a ligação para ele. Um ficheiro de instruções que já tinha torna-se o partilhado se ainda não existia nenhum; caso contrário, é mantido ao lado da ligação como `.bak`. Execute `omarchy agent instructions` para voltar a criar as ligações depois de instalar outro agente.

### O painel de agentes

A barra superior tem um ícone de agentes. Antes de ter configurado um agente, o painel orienta-o no início de sessão no Claude, Codex ou Grok, e o primeiro torna-se o seu agente predefinido. Depois disso, o painel coloca todas as subscrições numa única página: cada agente e conta com o seu plano, um medidor para cada um dos seus limites de sessão de 5 horas e semanais, com o tempo até ser reposto (passe o cursor para ver a percentagem exata), ou o saldo pré-pago restante, sob uma linha que vai alternando pelo que utilizou em todos eles, como tokens esta semana e o seu modelo mais utilizado. Em _Criar algo_, oferece prompts iniciais para um novo tema, plugin, aplicação ou jogo, que entregam a tarefa ao seu agente predefinido. As aplicações são construídas da mesma forma que as próprias aplicações Hype, Monologue e Omacut do Omarchy, em C++ e Qt Quick, seguindo a skill de agente omarchy-app, e o compilador e os componentes Qt de que precisam já vêm instalados. Os jogos são uma única página three.js em `~/Games/vibes`, seguindo a skill de agente web-game, e todos abrem a partir de um único lançador Game Vibes no tema atual; carregam o three.js a partir da Web, pelo que precisam de uma ligação para arrancar. O Claude Code, o Codex, o Grok, o Kimi, o Cursor e a sua quota Grok Bot, o GitHub Copilot, o Muse, o Antigravity, o Kimchi e o Devin estão abrangidos de origem com os seus limites, e o Hermes, o Mistral Vibe e o Qwen Code mostram as suas sessões e tokens depois de os ter utilizado. Os planos e chaves de fornecedores que utiliza através do pi, omp ou opencode também aparecem: OpenCode Zen e Go, o Z.ai GLM Coding Plan, Ollama Cloud, o MiniMax Token Plan e Synthetic com os seus limites; Fireworks, OpenRouter e DeepSeek com os seus saldos pré-pagos; e os modelos que executa no seu próprio hardware em Modelos locais. Cada agente é contado uma vez, sob quem o fatura, independentemente de quantos harnesses utilizar para o usar.

Clique com o botão esquerdo no ícone da barra para abrir o painel e clique com o botão direito para iniciar o seu agente predefinido. Os registos de utilização que estão por detrás dele são regenerados a cada 15 minutos por `omarchy agent usage-update`, e o painel pode até fundir a utilização das suas outras máquinas através de uma pasta sincronizada. Consulte o README em `$OMARCHY_PATH/shell/plugins/agents/` para ver as definições completas.

### Várias subscrições

Se pagar por mais do que um plano Claude, Codex ou Grok — um Max pessoal e um de trabalho, por exemplo —, o Omarchy pode manter todos com sessão iniciada e alternar entre eles. Adicione uma subscrição com o + no painel de agentes, que o orienta lá mesmo, ou com `omarchy agent account add claude Work` (ou `codex`, ou `grok`). Instala a CLI se estiver em falta. A primeira conta de um fornecedor inicia sessão através do seu browser normal, exatamente onde a CLI sempre procura. Todas as seguintes iniciam sessão através de uma janela privada, para que a conta em que o seu browser já tem sessão iniciada não seja detetada por engano; inicie sessão aí como a conta que está a adicionar e feche primeiro qualquer janela privada que já tenha aberta. Nunca termine a sessão na CLI para fazer isto: terminar a sessão revoga o início de sessão guardado e essa conta teria de ser adicionada novamente.

Para copiar os seus inícios de sessão de subscrição para outra máquina Omarchy através de SSH, execute `omarchy agent account copy user@laptop`. O emissor fornece um recetor temporário quando o destino não tem um instalado, pelo que as máquinas Omarchy mais antigas podem receber contas sem uma atualização. Os recetores instalados têm precedência. Isto copia todas as subscrições Claude, Codex e Grok; adicione nomes de fornecedores para as selecionar, como em `omarchy agent account copy laptop claude`. Os nomes de contas e os IDs de comandos correspondem à origem, incluindo contas já presentes no destino. As contas de destino não relacionadas recebem um sufixo numérico se os seus nomes entrarem em conflito, e as definições, skills, plugins e histórico de conversas permanecem locais a cada máquina.

As credenciais existentes no destino são mantidas. Uma conta de origem que já tenha sessão iniciada lá vê o seu nome sincronizado sem substituir as suas credenciais; as outras contas são adicionadas ao lado dela. Para substituir as credenciais guardadas de contas correspondentes, utilize `omarchy agent account copy --replace laptop claude` depois de sair das sessões dessa conta no destino. Um destino novo também recebe a conta ativa e as preferências de alternância da origem; um destino já estabelecido mantém as suas.

As credenciais viajam através de SSH e são armazenadas em ficheiros privados no destino, por isso copie apenas para máquinas em que confia. Isto é uma cópia única, não uma sincronização contínua. Os tokens de atualização do Codex podem ser rodados por outra máquina, deixando um início de sessão copiado a precisar de renovação; inícios de sessão separados continuam a ser a escolha mais fiável para utilização simultânea em várias máquinas. Consulte as [orientações de autenticação de contas do Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Uma conta por fornecedor está ativa, e todas as novas sessões começam como ela: `cx`, `cy`, um simples `claude`, `codex` ou `grok`, qualquer coisa lançada através de `omarchy agent`, e scripts ou editores que encontrem a CLI no `PATH`. Alterne com `omarchy agent account use work` (e volte com `omarchy agent account use main`), ou no painel premindo o número de uma conta e depois `Enter` (ou clicando no respetivo botão Use). As sessões Claude em execução também alternam, a partir da mensagem seguinte: todas as sessões Claude funcionam em `~/.claude`, que contém sempre o início de sessão da conta ativa. Uma sessão Claude iniciada na pasta própria de uma conta por um Omarchy mais antigo mantém esse início de sessão até sair, pelo que a alternância nomeia essas sessões e conclui-se sozinha quando desaparecerem. As sessões Codex e Grok em execução permanecem na conta com que começaram. O histórico de conversas, as definições, as skills e os plugins são partilhados entre contas, pelo que `claude --continue` na mesma pasta retoma onde deixou na nova conta.

Com mais do que uma conta, o painel mostra os limites de cada conta lado a lado, com a ativa assinalada. Por predefinição, o Omarchy notifica-o quando a conta ativa ultrapassa 95% de um limite, e clicar na notificação muda para a conta com mais margem. Passe o cursor sobre a linha de uma conta no painel e clique em Autoswitch, que aparece ao lado de Use (ou prima `m`), ou execute `omarchy agent account mode auto`, para que mude por si só; enquanto estiver ativado, Autoswitch ocupa o lugar de Use, e clicar novamente volta ao modo de notificação. Adicione um número para alterar o limiar, como em `omarchy agent account mode auto 90`. Se todas as contas estiverem acima do limiar, será informado uma vez, juntamente com qual conta fica livre primeiro. Enquanto uma conta ativa estiver a menos de 15 pontos do seu limiar (80% na predefinição), os seus limites são verificados a cada três minutos, em vez de a cada 15.

`omarchy agent account list` mostra todas as contas e os seus limites mais recentes, `omarchy agent account remove work` esquece uma, e `omarchy agent account rename primary Hey` renomeia uma (ou clique no nome de uma conta no painel). Estes comandos funcionam nas contas do seu agente predefinido; para aceder ao outro fornecedor, nomeie-o primeiro, como em `omarchy agent account use codex side`. O início de sessão que já tinha em `~/.claude` ou `~/.codex` é a conta _Main_. A do Codex fica onde está; a do Claude aguarda numa pasta própria enquanto outra conta está ativa. Uma conta deixada sem utilização durante mais de cerca de oito horas pode mostrar _Sign-in required_; clique nela para iniciar sessão nessa conta novamente diretamente no painel, ou mude para ela e inicie uma sessão, o que atualiza o início de sessão por si só. Os servidores MCP que adicionar com `claude mcp add` chegam a todas as contas Claude, uma vez que todas funcionam em `~/.claude`; para Codex e Grok, os servidores que tinha quando uma conta foi adicionada acompanham-na, mas os posteriores só chegam à conta em que os adicionou. O Claude Desktop mantém um início de sessão próprio, e as ferramentas Codex ou Grok configuradas com um caminho absoluto para um binário CLI não acompanham a mudança. Um `CLAUDE_CONFIG_DIR`, `CODEX_HOME` ou `GROK_HOME` explícito tem precedência sobre a conta selecionada.

### Diagnóstico de crashes

O Omarchy vigia o systemd-coredump à procura de crashes de processos. Quando algo faz segfault, recebe uma notificação "Process crashed" — clique nela e o crash é entregue ao seu agente predefinido juntamente com a skill diagnose-crash do Omarchy, que orienta o agente para estabelecer os factos a partir do core dump e decidir se o crash vale a pena ser comunicado a montante. Também pode executá-lo manualmente contra qualquer PID de `coredumpctl list` com `omarchy agent crash <pid>`.

A vigilância está ativada por predefinição. Desative-a em _Disparador > Alternar > Captura de Crash_ (ou com `omarchy toggle crash-capture`) e as notificações param; `omarchy agent crash <pid>` continua a funcionar manualmente.

Os crashes também podem ser silenciados um programa de cada vez, que é o que o diagnóstico lhe oferece no final. `omarchy crash mute hyprland` para as notificações apenas para esse programa, `omarchy crash mute hyprland off` volta a ativá-las, e `omarchy crash mute` por si só lista o que silenciou. Aceita o caminho do binário tão bem como o seu nome, pelo que `omarchy crash mute /usr/bin/hyprland` faz o mesmo. Coloque entre aspas um nome com um espaço, como em `omarchy crash mute 'Some App'`. Tudo o resto continua a notificar, e o programa silenciado continua a fazer crash — isto esconde o lembrete, não corrige nada.

### Aplicações de ambiente de trabalho

O menu _Instalar > IA_ também inclui algumas aplicações gráficas de IA: a aplicação de ambiente de trabalho ChatGPT, a aplicação de ambiente de trabalho Claude (a beta para Linux da Anthropic, com separadores Chat, Cowork e Claude Code), Grok Bot para conversar com os modelos da xAI, Herdr Desktop, Hermes Desktop, OpenClaw, a aplicação de ambiente de trabalho Perplexity e T3 Code. O Grok Bot é a aplicação de chat de ambiente de trabalho. O agente de programação é o comando `grok`.

O Hermes Desktop é o que deve conhecer, porque uma máquina tem um Hermes, e é o da aplicação: o Hermes só é alguma vez instalado através da aplicação, e o comando `hermes` que o agente predefinido executa é o da aplicação. Escolher o Hermes como agente predefinido instala a mesma coisa que a entrada _Instalar > IA_: o pacote e um runtime Hermes em `~/.hermes` configurado pelo próprio instalador do Hermes, o que demora alguns minutos na primeira vez. Esse runtime é o único Hermes que o comando `hermes` no terminal, o agente predefinido e a aplicação utilizam, e atualiza-se a si próprio com `hermes update`, em vez de esperar por uma versão do Omarchy. Instalá-lo também entrega ao Hermes o tema Omarchy como uma skin chamada `omarchy`, que todas as superfícies Hermes seguem quando muda de tema; escolha outra nas definições de Appearance do Hermes ou com `/skin` se preferir que não o faça, e o Omarchy deixa essa escolha em paz. Remover a aplicação em _Remover > IA_ fecha primeiro o Hermes, incluindo a gateway, leva esse runtime com ela e mantém as suas conversas, memórias e as skills que o Hermes escreveu para si próprio, a menos que lhe diga o contrário: pergunta, com não como predefinição, se esses dados e as suas definições de ligação também devem desaparecer.

A experiência de ambiente de trabalho do OpenClaw é a sua Control UI, que abre como uma aplicação web suportada pela sua própria gateway local. O OpenClaw vive em `~/.openclaw` e atualiza-se a si próprio: utilize o botão "Update Gateway" da Control UI ou execute `openclaw update`, e a gateway reinicia na nova versão. O Omarchy apenas escolhe a versão a partir da qual uma instalação nova começa. Remover o OpenClaw em _Remover > IA_ leva consigo o serviço da gateway e a aplicação e depois pergunta se `~/.openclaw` também deve desaparecer, uma vez que isso guarda as suas conversas e credenciais juntamente com o próprio OpenClaw e os runtimes de plugins que descarrega; a predefinição mantém-no, e instalar o OpenClaw novamente volta a utilizá-lo.

O Herdr Desktop é a aplicação de ambiente de trabalho [Herdr](https://herdr.dev): espaços, separadores e painéis de terminais e agentes de programação que continuam a funcionar no seu núcleo quando fecha a janela. Vem do próprio instalador do Herdr e não de um pacote, pelo que vive em `~/.local/share/herdr-app`, traz o seu núcleo em `~/.local/bin/herdr-core` quando ainda não tem um, e atualiza ambos por si próprio. Fica ao lado do comando `herdr` que o Omarchy fornece em `Super + Ctrl + Return` em vez de o substituir, e recebe as teclas diretas desse comando: `Alt + Return` e `Alt + Shift + Return` dividem um painel para baixo ou para a direita, `Alt + Escape` fecha-o, `Ctrl + Alt + Arrow` move entre painéis, `Alt + 1..9` e `Alt + Left/Right` escolhem um separador, e `Alt + Up/Down` move entre espaços. `Ctrl + 1..9` escolhe um espaço e `Alt + Shift + Up/Down` percorre os agentes. As teclas de prefixo `Ctrl + Space` permanecem apenas no terminal, uma vez que a aplicação não consegue manter uma tecla Ctrl simples para uma sequência. O Omarchy escreve estas em `~/.config/herdr-app/keys.json`, e `omarchy-refresh-herdr-app` volta a colocá-las. Instalá-lo escolhe o tema Omarchy do Herdr, que a partir daí segue o seu tema Omarchy. O Herdr mantém um tema para o modo claro e um para o modo escuro, pelo que, depois de alternar entre um tema Omarchy escuro e um claro, escolha Omarchy no seletor de temas do Herdr mais uma vez para o outro modo.

O T3 Code funciona a partir da sua versão oficial AppImage em `~/.local/share/t3code` e não de um pacote, pelo que se atualiza a si próprio. Instalá-lo pergunta se deve começar no canal Stable ou Nightly; mude mais tarde nas definições do T3 Code. As suas threads e definições vivem em `~/.t3`, e remover o T3 Code em _Remover > IA_ leva-as consigo.

### Modelos locais

Execute um modelo aberto na sua própria máquina para os seus agentes de programação. Os seus prompts e código permanecem na máquina; nada do que é enviado para o modelo sai dela. Comece com:

```bash
omarchy agent local use best
```

Ou, no painel de agentes na barra superior, escolha + e depois Local AI, que aparece quando um modelo cabe nesta máquina. Na primeira vez, isto instala o Podman, que executa os modelos, e numa máquina NVIDIA o kit de ferramentas de contentores da NVIDIA, que lhes dá acesso à GPU. O Omarchy escolhe então o modelo recomendado para esta máquina, descarrega-o e inicia-o. Conte com uma transferência de dezenas de GB e com a maior parte da memória da máquina a estar em utilização enquanto o modelo está a funcionar: o Flash Next utiliza cerca de 100 GiB com o seu contexto completo de 256K. Se outros modelos ocuparem a memória de que precisa, é configurado parado, pronto para arrancar quando parar um. O modelo para ao terminar a sessão; pare-o você mesmo quando precisar da memória para outra coisa.

`omarchy agent local list` mostra as opções e explica por que algumas não cabem. Para configurar outro, execute `omarchy agent local use <recipe>`. Hoje, `qwen3.8-flash-next-gufo` e `qwen3.8-27b-gufo` estão disponíveis para máquinas Strix Halo de 128 GB; o 27B ocupa cerca de 40 GiB, pelo que deixa espaço para outro trabalho. Num portátil de 64 GB com Arc B390 da Intel, `qwen3.6-35b-a3b-llamacpp` funciona em cerca de 30 GiB. Novas receitas e recomendações chegam com `omarchy update`, através do pacote.

Cada modelo que configurar tem a sua própria linha no painel de agentes, junto às suas subscrições: reproduzir para o iniciar, pausar para o parar e libertar a sua memória, e o botão de terminal para abrir o seu agente nele. Vários podem funcionar ao mesmo tempo quando cabem juntos na memória; se um não couber, o Omarchy diz qual modelo em execução deve parar. Arraste linhas para as reordenar e prima Delete numa linha selecionada para remover um modelo e a sua transferência.

Cada modelo que configurar também tem a sua própria entrada no lançador de aplicações, com o nome do modelo e o logótipo do seu fabricante, da mesma forma que iniciar sessão no Claude, Codex ou Grok adiciona uma. Abre o seu agente nesse modelo e inicia primeiro o modelo se não estiver a funcionar: o terminal mostra-o a carregar e entrega ao agente quando estiver pronto. Remover um modelo remove a sua entrada.

A partir da linha de comandos, `omarchy agent local start <recipe>` e `omarchy agent local stop <recipe>` fazem o mesmo, `omarchy agent local status` mostra todos os modelos, e `omarchy agent --local` abre o seu agente predefinido no último modelo que iniciou. O pi, o OpenCode e o Qwen Code podem utilizar um; com qualquer outro predefinido, abre no pi. O pi também lista todos os modelos que configurou, e os que estão em máquinas com as quais fez emparelhamento, no seu próprio seletor de modelos, pelo que um simples `pi` também os alcança. Qualquer cliente compatível com OpenAI também pode ligar-se: `status` mostra o endereço de cada modelo (o primeiro é `http://127.0.0.1:11435/v1`), o nome da receita é o modelo, e a chave está em `~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` apaga um modelo e as transferências que nenhum outro modelo utiliza.

Os runtimes de terceiros são identificados com o respetivo editor. O Omarchy executa todos os modelos sem acesso à rede.

### LLM locais

O Omarchy recomenda duas formas de executar modelos LLM locais: LM Studio e Ollama. O LM Studio fornece uma interface gráfica para encontrar modelos de pesos abertos, instalá-los e executá-los. É uma ótima forma de começar facilmente. O Ollama oferece uma CLI para fazer o mesmo de forma semelhante. Mas se é novo nos modelos locais, eu começaria pelo LM Studio. Pode instalar qualquer um deles em _Instalar > IA_ no Menu do Omarchy.

### A Skill do Omarchy

As skills de agente ajudam a IA a utilizar ferramentas específicas de uma forma específica, e o Omarchy vem com uma skill predefinida para personalizar o sistema. Como ajustar a sua configuração Hyprland, ajustar a barra, ou até criar um novo tema de raiz. Está ligada através de uma ligação simbólica aos diretórios de skills do Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` e cada `~/.hermes/profiles/*/skills`) e à localização genérica `~/.agents/skills`, pelo que a maioria dos harnesses a deteta automaticamente.

Mas deve tratar esta skill como experimental. Modelos diferentes utilizá-la-ão com efeitos diferentes. É melhor executá-la primeiro em modo de planeamento, para ter uma ideia do que o agente gostaria de alterar. E depois esteja preparado para reverter alterações ou até invocar `omarchy reinstall configs`, se o agente fizer uma confusão com tudo.
