# IA

O Omarchy inclui lançadores para os agentes de programação abaixo sem escolher um predefinido por si. Execute um comando para instalar a respetiva CLI na primeira utilização e, em seguida, autentique-se quando lhe for pedido. O Hermes e o OpenClaw são as exceções: nada é instalado para eles através do mise, e escolher qualquer um deles instala a sua própria cópia com atualização automática, como explica _Aplicações de ambiente de trabalho_ abaixo.

### Instalar e atualizar agentes

Com exceção do Hermes e do OpenClaw, estes agentes utilizam a instalação preguiçosa do mise: o primeiro arranque instala a CLI e os arranques seguintes reutilizam-na. O mise também verifica, no máximo uma vez a cada quatro horas, se um agente instalado tem uma nova versão, mesmo antes de arrancar ou em segundo plano numa linha de comandos da shell. Se essa atualização falhar ou se estiver offline, é executada a versão instalada. `omarchy update` atualiza os agentes instalados com o resto do Omarchy, e `mup` atualiza apenas as ferramentas geridas pelo mise.

O atualizador próprio de um agente, como `claude update`, `codex update` ou um botão de atualização numa aplicação, não atualiza a instalação gerida pelo mise. `codex update` falha, e `claude update` pode indicar sucesso ao instalar uma cópia separada que o mise não acompanha. Se preferir utilizar o instalador e o atualizador nativos de um agente, adicione-o a `disable_tools`; consulte [Ferramentas CLI pré-instaladas](18-development-tools.md#preinstalled-cli-tools).

Para instalar todas as ferramentas preguiçosas configuradas antes de precisar delas, execute `mise install --include-lazy`. Isto inclui as outras ferramentas CLI predefinidas do Omarchy, bem como os agentes. Consulte [Ferramentas CLI pré-instaladas](18-development-tools.md#preinstalled-cli-tools) para instalar uma única ferramenta ou utilizar a sua própria instalação.

O `grok` é instalado através do pacote first-party `grok` do mise, da mesma forma que `claude` e `codex`. Execute `grok`, ou escolha-o em _Agente > Harness_. Ignore o instalador `curl | bash` em x.ai. Esse caminho coloca uma segunda cópia em `~/.grok/bin`, coloca-a no início do `PATH` e substitui o wrapper do Omarchy.

O `dsh` abre a sua interface de utilizador no browser em `127.0.0.1:3080`, com o diretório de arranque como espaço de trabalho predefinido. A sua interface no browser não aceita um prompt inicial, por isso `omarchy agent prompt` abre-a com o prompt na área de transferência para colar. O Omarchy arranca-o com a predefinição de permissões sem aprovação da DeepSeek. O DeepSeek Harness envia registos de sessão para a DeepSeek quando utiliza a API oficial de modelos da mesma; desative isso em _Definições > Geral > Upload Session Log_ na respetiva interface no browser. O feedback que enviar também é enviado com a sessão, a menos que o arranque com `DSH_TELEMETRY_MODE=DISABLED`.

### O agente predefinido

Escolha o seu agente predefinido com `omarchy default agent <name>` ou em _Agente > Harness_ no Menu Omarchy (`Super + Space`). Se o agente ainda não estiver instalado, ao escolhê-lo este é instalado primeiro, e também recebe um lançador próprio no lançador de aplicações, junto a Agente. Um Omarchy acabado de instalar irá convidá-lo a fazer esta escolha com uma notificação única.

Escolher o Claude também tenta configurar a sua extensão de browser para Chromium, Chrome, Brave, Brave Origin e Edge. A configuração da extensão aplica-se a todos os utilizadores e pode pedir a sua palavra-passe do sistema; cancelar ou uma instalação da extensão falhada continua a selecionar e a iniciar o Claude. Reinicie o browser, ative a extensão se lhe for pedido e inicie sessão no Claude para concluir a ligação. Execute `/chrome` no Claude para verificar a ligação. O Firefox e o Zen não suportam esta extensão. Se o Claude já era o seu predefinido antes de esta configuração ser adicionada, selecione-o novamente para instalar a extensão.

Depois de fazer a escolha, `Super + Shift + Ctrl + A` inicia o agente predefinido numa janela de terminal dedicada (ou apresenta o seletor se ainda não tiver escolhido). Também pode iniciá-lo diretamente numa tarefa com `omarchy agent prompt "Review this project"`. O Freebuff e o DeepSeek Harness não aceitam um prompt inicial, por isso abrem com o prompt na área de transferência para colar. Os agentes iniciados desta forma funcionam sem supervisão nos respetivos modos de não parar para perguntar, por isso esteja preparado para que façam realmente coisas! O MiniMax Code não tem esse modo para as suas sessões interativas, por isso pede permissões como habitualmente. E como os agentes se recusam a memorizar a confiança no seu diretório pessoal, os arranques a partir de `$HOME` começam em `~/Work`, em vez disso.

Também há atalhos de terminal: `a` executa o agente predefinido diretamente no terminal atual, enquanto `c`, `cx` e `cy` iniciam OpenCode, Claude Code e Codex diretamente (também nos seus modos de aprovação automática). As alterações de tema também são sincronizadas com os agentes: Claude Code, Pi, OpenCode e Hermes (depois de o Omarchy o ter instalado) acompanham-no quando muda o tema do Omarchy.

### As instruções do seu agente

As regras pessoais para todos os agentes ficam em `~/.agents/AGENTS.md`, junto às skills partilhadas em `~/.agents/skills`. Abra-o em _Agente > Instruções_, que também o liga a cada harness que mantém o seu próprio ficheiro global: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, o `~/.copilot/copilot-instructions.md` do Copilot, e assim por diante. O Crush e o Amp leem a ligação `~/.config/AGENTS.md`, enquanto o omp, o Kimi e o DeepSeek Harness leem `~/.agents/AGENTS.md` diretamente. Escolher um agente predefinido também cria essa ligação. Um ficheiro de instruções que já tinha torna-se o partilhado se ainda não existia nenhum; caso contrário, é mantido junto à ligação como `.bak`. Execute `omarchy agent instructions` para voltar a ligar depois de instalar outro agente.

### O painel de agentes

A barra superior tem um ícone de agentes. Antes de ter configurado um agente, o seu painel orienta-o no início de sessão no Claude, Codex ou Grok, e o primeiro torna-se o seu agente predefinido. Depois disso, o painel coloca todas as subscrições numa única página: cada agente e conta com o seu plano, um medidor para cada um dos seus limites de sessão de 5 horas e semanais com o tempo até ser reposto (passe o cursor para ver a percentagem exata), ou o saldo pré-pago restante, sob uma linha que vai alternando pelo que utilizou em todos eles, como os tokens desta semana e o seu modelo mais utilizado. Em _Criar algo fixe_ oferece prompts iniciais para um novo tema, plugin, aplicação ou jogo que entregam a tarefa ao seu agente predefinido. As aplicações são construídas da forma como as próprias Hype, Monologue e Omacut do Omarchy são, em C++ e Qt Quick, seguindo a skill de agente omarchy-make-app, e o compilador e os componentes Qt de que precisam vêm instalados. Os jogos são uma única página three.js em `~/Games/vibes`, seguindo a skill de agente omarchy-make-game, e todos abrem a partir de um único lançador Game Vibes no tema atual; carregam o three.js a partir da Web, por isso precisam de uma ligação para arrancar. Claude Code, Codex, Grok, Kimi, Cursor e a sua quota do Grok Bot, GitHub Copilot, Muse, Antigravity e Devin estão abrangidos de origem com os seus limites, o Kimchi com o seu plano, créditos pré-pagos e orçamentos de gastos, e Hermes, Mistral Vibe e Qwen Code mostram as suas sessões e tokens depois de os ter utilizado. Os planos e chaves de fornecedores que utiliza através de pi, omp ou opencode também aparecem: OpenCode Zen e Go, o Z.ai GLM Coding Plan, Ollama Cloud, o MiniMax Token Plan e Synthetic com os seus limites; OpenRouter e DeepSeek com os seus saldos pré-pagos; Fireworks com os seus gastos nos últimos 30 dias. Os tokens de modelos que executa no seu próprio hardware também contam para os totais; os próprios modelos têm um painel próprio, descrito em [Modelos locais](#local-models). Cada agente é contado uma vez, sob quem o fatura, independentemente de quantos harnesses utilize para o conduzir.

Clique com o botão esquerdo no ícone da barra ou prima `Super + Ctrl + X` para abrir o painel, clique com o botão direito para iniciar o seu agente predefinido e clique com o botão do meio para atualizar. Os registos de utilização que o sustentam são regenerados a cada 15 minutos por `omarchy agent usage update`, e o painel pode até juntar a utilização das suas outras máquinas através de uma pasta sincronizada. Consulte o README em `$OMARCHY_PATH/shell/plugins/agents/` para ver todas as definições.

### Várias subscrições

Se paga por mais do que um plano Claude, Codex ou Grok — um Max pessoal e um de trabalho, por exemplo — o Omarchy pode manter todos com sessão iniciada e alternar entre eles. Adicione uma subscrição com o + no painel de agentes, que o orienta ali mesmo, ou com `omarchy agent account add claude Work` (ou `codex`, ou `grok`). Instala a CLI se esta estiver em falta. A primeira conta de um fornecedor inicia sessão através do seu browser normal, exatamente onde a CLI sempre procura. Todas as seguintes iniciam sessão através de uma janela privada, para que a conta em que o seu browser já tem sessão iniciada não seja apanhada por engano; inicie sessão aí como a conta que está a adicionar e feche primeiro qualquer janela privada que já tenha aberta. Nunca termine a sessão na CLI para fazer isto: terminar a sessão revoga o início de sessão guardado e essa conta teria de ser adicionada novamente.

Para copiar os seus inícios de sessão de subscrição para outra máquina Omarchy por SSH, execute `omarchy agent account copy user@laptop`. O emissor fornece um recetor temporário quando o destino não tem um instalado, para que máquinas Omarchy mais antigas possam receber contas sem uma atualização. Os recetores instalados têm precedência. Isto copia todas as subscrições Claude, Codex e Grok; adicione nomes de fornecedores para as selecionar, como em `omarchy agent account copy laptop claude`. Os nomes de contas e os ID de comando correspondem à origem, incluindo contas já presentes no destino. Contas de destino não relacionadas recebem um sufixo numérico se os seus nomes entrarem em conflito, e as definições, skills, plugins e histórico de conversas permanecem locais em cada máquina.

As credenciais existentes no destino são mantidas. Uma conta de origem que já tenha sessão iniciada lá tem o seu nome sincronizado sem substituir as suas credenciais; as outras contas são adicionadas ao lado. Para substituir credenciais guardadas de contas correspondentes, utilize `omarchy agent account copy --replace laptop claude` depois de sair das sessões dessa conta no destino. Um destino novo também recebe a conta ativa e as preferências de alternância da origem; um destino já estabelecido mantém as suas.

As credenciais viajam por SSH e são guardadas em ficheiros privados no destino, por isso copie apenas para máquinas em que confia. Isto é uma cópia única, não uma sincronização contínua. Os tokens de atualização do Codex podem ser rodados por outra máquina, deixando um início de sessão copiado a precisar de renovação; inícios de sessão separados continuam a ser a escolha mais fiável para utilização simultânea em várias máquinas. Consulte [as orientações de autenticação de contas do Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Uma conta por fornecedor está ativa, e todas as novas sessões começam como ela: `cx`, `cy`, um simples `claude`, `codex` ou `grok`, qualquer coisa iniciada através de `omarchy agent`, e scripts ou editores que encontrem a CLI no `PATH`. Alterne com `omarchy agent account use work` (e volte com `omarchy agent account use main`), ou no painel premindo o número de uma conta e depois `Enter` (ou clicando no seu botão Utilizar). As sessões Claude em execução também alternam, a partir da mensagem seguinte: todas as sessões Claude funcionam em `~/.claude`, que contém sempre o início de sessão da conta ativa. Uma sessão Claude iniciada na pasta própria de uma conta por um Omarchy mais antigo mantém esse início de sessão até sair, por isso a alternância indica essas sessões e termina sozinha quando elas desaparecerem. As sessões Codex e Grok em execução permanecem na conta com que começaram. O histórico de conversas, as definições, as skills e os plugins são partilhados entre contas, por isso `claude --continue` na mesma pasta retoma onde deixou na nova conta.

Com mais do que uma conta, o painel mostra os limites de cada conta lado a lado, com a ativa assinalada. O Omarchy notifica-o quando a conta ativa ultrapassa 95% de um limite, e clicar na notificação muda para a conta com mais margem. Nunca muda sozinho. Altere o limiar com `omarchy agent account threshold 90`. Se todas as contas estiverem acima do limiar, será informado uma vez, juntamente com qual conta fica livre primeiro. Enquanto uma conta ativa estiver a menos de 15 pontos do seu limiar (80% no valor predefinido), os seus limites são verificados a cada três minutos e não a cada 15.

`omarchy agent account list` mostra todas as contas e os seus limites mais recentes, `omarchy agent account remove work` esquece uma, e `omarchy agent account rename primary Hey` muda o nome de uma (ou clique no nome de uma conta no painel). Estes comandos funcionam nas contas do seu agente predefinido; para chegar ao outro fornecedor, indique-o primeiro, como em `omarchy agent account use codex side`. O início de sessão que já tinha em `~/.claude` ou `~/.codex` é a conta _Main_. A do Codex fica onde está; a do Claude aguarda numa pasta própria enquanto outra conta está ativa. Uma conta deixada sem utilização durante mais de cerca de oito horas pode mostrar _Início de sessão necessário_; clique nela para iniciar sessão nessa conta outra vez diretamente no painel, ou mude para ela e inicie uma sessão, que atualiza o início de sessão por si só. Os servidores MCP que adicionar com `claude mcp add` chegam a todas as contas Claude, uma vez que todas funcionam em `~/.claude`; para Codex e Grok, os servidores que tinha quando uma conta foi adicionada acompanham-na, mas os posteriores só chegam à conta em que os adicionou. O Claude Desktop mantém um início de sessão próprio, e as ferramentas Codex ou Grok configuradas com um caminho absoluto para um binário CLI não acompanham a mudança. Um `CLAUDE_CONFIG_DIR`, `CODEX_HOME` ou `GROK_HOME` explícito tem precedência sobre a conta selecionada.

### Diagnóstico de falhas

O Omarchy vigia o systemd-coredump à procura de falhas de processos. Depois de escolher um agente predefinido, qualquer programa seu que faça um despejo de memória apresenta uma notificação "Process crashed" — clique nela e a falha é entregue ao seu agente predefinido juntamente com a skill omarchy-diagnose-crash do Omarchy, que orienta o agente a estabelecer os factos a partir do despejo de memória e a decidir se vale a pena reportar a falha a montante. Também pode executá-la manualmente contra qualquer PID de `coredumpctl list` com `omarchy agent crash <pid>`.

A vigilância está ativada por predefinição. Desative-a em _Acionador > Alternar > Desativar Captura de Falhas_ (ou com `omarchy toggle crash-capture`) e as notificações param; `omarchy agent crash <pid>` continua a funcionar manualmente.

As falhas também podem ser silenciadas programa a programa, que é o que o diagnóstico lhe oferece no final. `omarchy crash mute hyprland` para as notificações só para esse programa, `omarchy crash mute hyprland off` repõe-nas, e `omarchy crash mute` por si só lista o que silenciou. Aceita o caminho do binário tão bem como o seu nome, por isso `omarchy crash mute /usr/bin/hyprland` faz o mesmo. Coloque entre aspas um nome com um espaço, como em `omarchy crash mute 'Some App'`. Tudo o resto continua a notificar, e o programa silenciado continua a falhar — isto esconde o lembrete, não corrige nada.

### Aplicações de ambiente de trabalho

O menu _Instalar > IA_ também inclui algumas aplicações gráficas de IA: Amp Desktop, Antigravity Desktop, a aplicação de ambiente de trabalho ChatGPT, a aplicação de ambiente de trabalho Claude (a versão beta para Linux da Anthropic, com separadores Chat, Cowork e Claude Code), Grok Bot para conversar com os modelos da xAI, Herdr Desktop, Hermes Desktop, OpenClaw, a aplicação de ambiente de trabalho Perplexity e T3 Code. O Grok Bot é a aplicação de conversação de ambiente de trabalho. O agente de programação é o comando `grok`.

O Hermes Desktop é aquele que importa conhecer, porque uma máquina tem um Hermes, e é o da aplicação: o Hermes só é instalado através da aplicação, e o comando `hermes` que o agente predefinido executa é o da aplicação. Escolher o Hermes como agente predefinido instala a mesma coisa que a entrada _Instalar > IA_: o pacote e um runtime Hermes em `~/.hermes` configurado pelo próprio instalador do Hermes, o que demora alguns minutos na primeira vez. Esse runtime é o único Hermes que o comando de terminal `hermes`, o agente predefinido e a aplicação utilizam, e atualiza-se a si próprio com `hermes update` em vez de esperar por uma versão do Omarchy. Instalá-lo também entrega ao Hermes o tema Omarchy como um skin chamado `omarchy`, que todas as superfícies do Hermes seguem quando muda de temas; escolha outro nas definições de Appearance do Hermes ou com `/skin` se preferir que não o faça, e o Omarchy deixa essa escolha em paz. Remover a aplicação em _Remover > IA_ fecha primeiro o Hermes, gateway incluído, leva esse runtime consigo e mantém as suas conversas, memórias e as skills que o Hermes escreveu para si próprio, a menos que lhe diga o contrário: pergunta, com não como resposta predefinida, se esses dados e as suas definições de ligação também devem desaparecer.

A experiência de ambiente de trabalho do OpenClaw é a sua Control UI, que abre como uma aplicação Web apoiada pelo seu próprio gateway local. O OpenClaw vive em `~/.openclaw` e atualiza-se a si próprio: utilize o botão "Update Gateway" da Control UI ou execute `openclaw update`, e o gateway reinicia na nova versão. O Omarchy só escolhe a versão a partir da qual uma instalação nova começa. O OpenClaw também pode ser o seu agente predefinido: escolhê-lo em _Agente > Harness_ configura essa mesma cópia em `~/.openclaw`, e o agente abre a interface de terminal do OpenClaw ligada ao seu gateway. Remover o OpenClaw em _Remover > IA_ leva consigo o serviço do gateway e a aplicação e depois pergunta se `~/.openclaw` também deve desaparecer, uma vez que aí ficam as suas conversas e credenciais juntamente com o próprio OpenClaw e os runtimes de plugins que descarrega; a predefinição mantém-no, e instalar o OpenClaw novamente volta a apanhá-lo.

O Herdr Desktop é a aplicação de ambiente de trabalho [Herdr](https://herdr.dev): espaços, separadores e painéis de terminais e agentes de programação que continuam a funcionar no seu núcleo quando fecha a janela. Vem do próprio instalador do Herdr e não de um pacote, por isso vive em `~/.local/share/herdr-app`, traz o seu núcleo em `~/.local/bin/herdr-core` quando ainda não tem um, e atualiza ambos. Fica ao lado do comando `herdr` que o Omarchy fornece em `Super + Ctrl + Return` em vez de o substituir, e recebe as teclas diretas desse comando: `Alt + Return` e `Alt + Shift + Return` dividem um painel para baixo ou para a direita, `Alt + Escape` fecha-o, `Ctrl + Alt + Arrow` move entre painéis, `Alt + 1..9` e `Alt + Left/Right` escolhem um separador, e `Alt + Up/Down` movem entre espaços. `Ctrl + 1..9` escolhe um espaço e `Alt + Shift + Up/Down` percorre os agentes. As teclas de prefixo `Ctrl + Space` permanecem apenas no terminal, uma vez que a aplicação não consegue manter uma tecla Ctrl simples para uma sequência. O Omarchy escreve estas em `~/.config/herdr-app/keys.json`, e `omarchy-refresh-herdr-app` repõe-nas. Instalá-lo escolhe o tema Omarchy do Herdr, que a partir daí segue o seu tema Omarchy. O Herdr mantém um tema para o modo claro e um para o modo escuro, por isso, depois de alternar entre um tema Omarchy escuro e um claro, escolha Omarchy no seletor de temas do Herdr mais uma vez para o outro modo.

O T3 Code funciona a partir da sua versão oficial AppImage em `~/.local/share/t3code` e não a partir de um pacote, por isso atualiza-se a si próprio. Instalá-lo pergunta se deve começar no canal Stable ou Nightly; mude mais tarde nas definições do T3 Code. Os seus tópicos e definições vivem em `~/.t3`, e remover o T3 Code em _Remover > IA_ leva-os consigo.

### Modelos locais

Execute um modelo aberto na sua própria máquina para os seus agentes de programação. Os seus prompts e código permanecem na máquina; nada do que é enviado ao modelo sai dela. Comece com:

```bash
omarchy models use best text
```

Isso configura o melhor modelo de texto para esta máquina, do tipo que os seus agentes utilizam. Os modelos de imagem, vídeo e música têm um melhor próprio: `omarchy models use best image`, `video` ou `music`. Execute `omarchy models use best` para ver a escolha de cada tipo para esta máquina.

Ou abra o painel de modelos locais a partir do seu ícone de brilhos na barra superior, junto ao ícone de agentes, ou com Super + Ctrl + Alt + X, e escolha +. O ícone aparece quando um modelo cabe nesta máquina. O Podman, que executa os modelos, vem com o Omarchy, tal como o kit de ferramentas de contentores da NVIDIA numa máquina NVIDIA, que lhes dá a GPU; se algum estiver em falta, a primeira configuração instala-o. Depois, o Omarchy escolhe o modelo recomendado para esta máquina, descarrega-o e inicia-o. Conte com um descarregamento de dezenas de GB e com a maior parte da memória da máquina a estar em utilização enquanto o modelo está a funcionar: o Flash Next utiliza cerca de 100 GiB com o seu contexto completo de 256K. Se outros modelos ocuparem a memória de que precisa, é configurado parado, pronto para arrancar quando parar um. O modelo para ao terminar a sessão; pare-o você mesmo quando precisar da memória para outra coisa.

`omarchy models list` mostra as opções e explica por que algumas não cabem. Para configurar outro, execute `omarchy models use <recipe>`. Hoje, `qwen3.8-flash-next-gufo` e `qwen3.8-27b-gufo` estão disponíveis para máquinas Strix Halo de 128 GB; o 27B ocupa cerca de 40 GiB, por isso deixa espaço para outro trabalho. Num portátil de 64 GB com Arc B390 da Intel, `qwen3.6-35b-a3b-llamacpp` funciona em cerca de 30 GiB. Novas receitas e recomendações chegam com `omarchy update`, através do pacote.

Cada modelo que configurar recebe a sua própria linha no painel de modelos locais: reproduzir para o iniciar, pausar para o parar e libertar a sua memória, e o botão de terminal para abrir o seu agente nele. No topo, uma barra mostra como a memória da máquina está dividida entre o próprio Omarchy (o sistema e as suas aplicações), cada modelo em execução e o que está livre. Aponte para um modelo parado e a barra mostra se cabe, ou quanto lhe falta. Vários podem funcionar ao mesmo tempo quando cabem juntos na memória; se um não couber, o Omarchy diz qual modelo em execução deve parar. Arraste as linhas pelo seu logótipo para as reordenar e prima Delete numa linha selecionada para remover um modelo e o seu descarregamento.

Cada modelo de programação que configurar também recebe a sua própria entrada no lançador de aplicações, com o nome do modelo e o logótipo do seu fabricante, da forma como iniciar sessão no Claude, Codex ou Grok adiciona uma. Abre o seu agente nesse modelo e inicia o modelo primeiro se este não estiver a funcionar: o terminal mostra-o a carregar e entrega ao agente quando estiver pronto. Remover um modelo remove a sua entrada.

Nem todos os modelos são para programação. Os modelos de imagem, vídeo e música abrem no Fantasi, a aplicação do Omarchy para criar imagens, vídeo e música com um modelo a funcionar nesta máquina, escolhido aí ou a partir da sua linha no painel de modelos locais.

Um modelo continua a funcionar exatamente como foi configurado, por isso uma atualização do Omarchy nunca reinicia um sob os seus agentes. Quando o Omarchy tem um runtime mais recente ou pesos mais recentes para um modelo que configurou, a sua linha mostra um botão de atualização: prima-o e o modelo é configurado novamente em segundo plano, descarregando apenas o que mudou, e reinicia na nova versão. Um modelo que estava parado permanece parado. `omarchy models update` faz o mesmo para todos os modelos a partir de um terminal.

A partir da linha de comandos, `omarchy models start <recipe>` e `omarchy models stop <recipe>` fazem o mesmo, `omarchy models status` mostra todos os modelos, e `omarchy agent --local` abre o último modelo que iniciou no pi, qualquer que seja o seu agente predefinido. O OpenCode e o Qwen Code também podem utilizar um modelo local: `omarchy models harness opencode` ou `omarchy models harness qwen` abre-os aí, e `omarchy models harness pi` volta atrás. O pi também lista todos os modelos que configurou, e os que estão em máquinas com as quais emparelhou, no seu próprio seletor de modelos, por isso um simples `pi` também os alcança. Qualquer cliente compatível com OpenAI também se pode ligar: `status` mostra o endereço de cada modelo (o primeiro é `http://127.0.0.1:11435/v1`), o nome da receita é o modelo, e a chave está em `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` apaga um modelo e os descarregamentos que nenhum outro modelo utiliza.

Os runtimes de terceiros são identificados com o seu editor. O Omarchy executa todos os modelos sem acesso à rede.

### LLM locais

O Omarchy recomenda duas formas de executar modelos LLM locais: LM Studio e Ollama. O LM Studio fornece uma interface gráfica para encontrar modelos de pesos abertos, instalá-los e executá-los. É uma excelente forma de começar facilmente. O Ollama oferece uma CLI para fazer o mesmo. Mas, se é novo nos modelos locais, eu começaria pelo LM Studio. Pode instalar qualquer um deles em _Instalar > IA_ no Menu Omarchy.

### As skills do Omarchy

As skills de agente ajudam a IA a utilizar ferramentas específicas de uma forma específica, e o Omarchy inclui sete delas. A skill omarchy abrange adaptar o sistema, como ajustar a sua configuração do Hyprland ou regular a barra. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app e omarchy-make-game abrangem criar algo novo, omarchy-contribute abrange reportar um erro ou enviar uma correção a montante, e omarchy-diagnose-crash trabalha sobre o despejo de memória de uma falha. Estão ligadas por symlinks nos diretórios de skills do Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` e cada `~/.hermes/profiles/*/skills`) e na localização genérica `~/.agents/skills`, por isso a maioria dos harnesses apanha-as automaticamente. Uma pasta de skill sua com o mesmo nome tem precedência.

Mas deve tratar estas skills como experimentais. Modelos diferentes irão utilizá-las com efeitos diferentes. O melhor é executar primeiro em modo de planeamento, para ter uma ideia do que o agente gostaria de alterar. E depois esteja preparado para reverter alterações ou até invocar `omarchy reinstall configs`, se o agente fizer uma confusão com tudo.
