# IA

O Omarchy inclui lançadores para os agentes de programação abaixo sem escolher um predefinido por si. Execute um comando para instalar a respetiva CLI na primeira utilização e, em seguida, autentique-se quando lhe for pedido. O Hermes é a exceção: nada é instalado para ele na primeira utilização, e escolhê-lo instala o Hermes Desktop, como _Aplicações de ambiente de trabalho_ abaixo explica.

### Instalar e atualizar agentes

Exceto o Hermes, estes agentes utilizam a instalação lazy do mise: o primeiro lançamento instala a CLI e os lançamentos posteriores reutilizam-na. O mise também verifica, no máximo uma vez a cada quatro horas, se um agente instalado tem uma nova versão, imediatamente antes de o iniciar ou em segundo plano num prompt da shell. Se essa atualização falhar ou se estiver sem ligação, é executada a versão instalada. O `omarchy update` atualiza os agentes instalados com o resto do Omarchy, e o `mup` atualiza apenas as ferramentas geridas pelo mise.

O atualizador próprio de um agente, como `claude update`, `codex update`, ou um botão de atualização numa aplicação, não atualiza a instalação gerida pelo mise. O `codex update` falha, e o `claude update` pode indicar sucesso ao instalar uma cópia separada que o mise não acompanha. Se preferir utilizar o instalador e o atualizador nativos de um agente, adicione-o a `disable_tools`; consulte [Ferramentas CLI pré-instaladas](18-development-tools.md#preinstalled-cli-tools).

Para instalar todas as ferramentas lazy configuradas antes de precisar delas, execute `mise install --include-lazy`. Isto inclui as outras ferramentas CLI predefinidas do Omarchy, bem como os agentes. Consulte [Ferramentas CLI pré-instaladas](18-development-tools.md#preinstalled-cli-tools) para instalar uma única ferramenta ou utilizar a sua própria instalação.

O `grok` é instalado através do pacote `grok` oficial do mise, da mesma forma que o `claude` e o `codex`. Execute `grok`, ou escolha-o em _Agent > Harness_. Evite o instalador `curl | bash` em x.ai. Esse caminho coloca uma segunda cópia em `~/.grok/bin`, antepõe-na ao `PATH` e substitui o wrapper do Omarchy.

O `dsh` abre a sua interface de browser em `127.0.0.1:3080`, com o diretório de lançamento como área de trabalho predefinida. A sua interface de browser não aceita um prompt inicial, por isso o `omarchy agent prompt` abre-o com o prompt na sua área de transferência para colar. O Omarchy inicia-o com a predefinição de permissões sem aprovação da DeepSeek. O DeepSeek Harness carrega os registos de sessão para a DeepSeek quando utiliza a API oficial de modelos da mesma; desative essa opção em _Settings > General > Upload Session Log_ na sua interface de browser. O feedback que lhe enviar também é carregado com a sessão, a menos que o inicie com `DSH_TELEMETRY_MODE=DISABLED`.

### O agente predefinido

Escolha o seu agente predefinido com `omarchy default agent <name>` ou em _Agent > Harness_ no Omarchy Menu (`Super + Space`). Se o agente ainda não estiver instalado, ao escolhê-lo ele é instalado primeiro. Um Omarchy acabado de instalar irá convidá-lo a fazer esta escolha com uma notificação única.

Escolher o Claude também tenta configurar a sua extensão de browser para Chromium, Chrome, Brave, Brave Origin e Edge. A configuração da extensão aplica-se a todos os utilizadores e pode pedir a sua palavra-passe do sistema; cancelar ou uma instalação da extensão falhada continua a selecionar e a iniciar o Claude. Reinicie o seu browser, ative a extensão se lhe for pedido e inicie sessão no Claude para terminar a ligação. Execute `/chrome` no Claude para verificar a ligação. O Firefox e o Zen não suportam esta extensão. Se o Claude já era o seu predefinido antes de esta configuração ser adicionada, selecione-o novamente para instalar a extensão.

Depois de escolher, `Super + Shift + Ctrl + A` inicia o agente predefinido numa janela de terminal dedicada (ou abre o seletor se ainda não tiver escolhido). Também pode iniciá-lo diretamente numa tarefa com `omarchy agent prompt "Review this project"`. O Freebuff e o DeepSeek Harness não aceitam um prompt inicial, por isso abrem com o prompt na sua área de transferência para colar. Os agentes iniciados desta forma funcionam sem supervisão nos respetivos modos de não estar a parar para perguntar, por isso esteja preparado para que eles façam realmente coisas! O MiniMax Code não tem esse modo para as suas sessões interativas, por isso pede permissões como habitualmente. E, uma vez que os agentes se recusam a memorizar a confiança no seu diretório pessoal, os lançamentos a partir de `$HOME` começam em `~/Work`.

Também há atalhos de terminal: `a` executa o agente predefinido diretamente no terminal atual, enquanto `c`, `cx` e `cy` iniciam diretamente o OpenCode, o Claude Code e o Codex (novamente nos respetivos modos de aprovação automática). As mudanças de tema também são sincronizadas com os agentes: o Claude Code, o Pi, o OpenCode e o Hermes (depois de o Omarchy o ter instalado) acompanham-no quando muda o tema do Omarchy.

### As suas instruções para os agentes

As regras pessoais para todos os agentes vão para `~/.agents/AGENTS.md`, ao lado das skills partilhadas em `~/.agents/skills`. Abra-o em _Agent > Instructions_, que também o liga a cada harness que mantém o seu próprio ficheiro global: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, o `~/.copilot/copilot-instructions.md` do Copilot, e assim por diante. O Crush e o Amp leem a ligação `~/.config/AGENTS.md`, enquanto o omp, o Kimi e o DeepSeek Harness leem `~/.agents/AGENTS.md` diretamente. Escolher um agente predefinido também cria a ligação para ele. Um ficheiro de instruções que já tinha torna-se o partilhado se ainda não existia nenhum; caso contrário, é mantido ao lado da ligação como `.bak`. Execute `omarchy agent instructions` para voltar a criar as ligações depois de instalar outro agente.

### O painel de agentes

A barra superior tem um ícone de agentes. Antes de ter configurado um agente, o seu painel orienta-o ao longo do início de sessão no Claude, Codex ou Grok, e o primeiro torna-se o seu agente predefinido. Depois disso, o painel coloca todas as subscrições numa única página: cada agente e conta com o seu plano, um medidor para cada um dos seus limites de sessão de 5 horas e semanais com o tempo até ser reposto (passe o cursor para ver a percentagem exata), ou o saldo pré-pago restante, sob uma linha que vai rodando pelo que utilizou em todos eles, como os tokens desta semana e o seu modelo mais utilizado. Em _Make something_, oferece prompts iniciais para um novo tema, plugin, aplicação ou jogo que entregam a tarefa ao seu agente predefinido. As aplicações são construídas da forma como as próprias Hype, Monologue e Omacut do Omarchy são, em C++ e Qt Quick, a seguir a skill de agente omarchy-make-app, e o compilador e os componentes Qt de que precisam já vêm instalados. Os jogos são uma única página three.js em `~/Games/vibes`, a seguir a skill de agente omarchy-make-game, e todos abrem a partir de um único lançador Game Vibes no tema atual; carregam o three.js a partir da web, por isso precisam de uma ligação para começar. O Claude Code, o Codex, o Grok, o Kimi, o Cursor e a sua quota do Grok Bot, o GitHub Copilot, o Muse, o Antigravity, o Kimchi e o Devin estão cobertos de origem com os seus limites, e o Hermes, o Mistral Vibe e o Qwen Code mostram as suas sessões e tokens depois de os ter utilizado. Os planos e chaves de fornecedores que utiliza através do pi, omp ou opencode também aparecem: o OpenCode Zen e Go, o Z.ai GLM Coding Plan, a Ollama Cloud, o MiniMax Token Plan e o Synthetic com os seus limites; o Fireworks, a OpenRouter e a DeepSeek com os seus saldos pré-pagos; e os modelos que executa no seu próprio hardware em Local models. Cada agente é contado uma vez, sob quem o fatura, independentemente de quantos harnesses utilizar para o usar.

Clique com o botão esquerdo no ícone da barra para abrir o painel, clique com o botão direito para iniciar o seu agente predefinido. Os registos de utilização por trás dele são regenerados a cada 15 minutos por `omarchy agent usage-update`, e o painel pode até combinar a utilização de outras máquinas suas através de uma pasta sincronizada. Consulte o README em `$OMARCHY_PATH/shell/plugins/agents/` para as definições completas.

### Várias subscrições

Se pagar por mais do que um plano Claude, Codex ou Grok — um Max pessoal e um de trabalho, por exemplo — o Omarchy pode manter todos com sessão iniciada e alternar entre eles. Adicione uma subscrição com o + no painel de agentes, que o orienta ali mesmo, ou com `omarchy agent account add claude Work` (ou `codex`, ou `grok`). Instala a CLI se estiver em falta. A primeira conta de um fornecedor inicia sessão através do seu browser normal, exatamente onde a CLI sempre procura. Todas as seguintes iniciam sessão através de uma janela privada, para que a conta em que o seu browser já tem sessão iniciada não seja apanhada por engano; inicie sessão aí como a conta que está a adicionar e feche primeiro qualquer janela privada que já tenha aberta. Nunca termine sessão na CLI para fazer isto: terminar sessão revoga o início de sessão guardado, e essa conta teria de ser adicionada novamente.

Para copiar os seus inícios de sessão de subscrição para outra máquina Omarchy por SSH, execute `omarchy agent account copy user@laptop`. O emissor fornece um recetor temporário quando o destino não tem um instalado, para que máquinas Omarchy mais antigas possam receber contas sem uma atualização. Os recetores instalados têm precedência. Isto copia todas as subscrições Claude, Codex e Grok; adicione nomes de fornecedores para as selecionar, como em `omarchy agent account copy laptop claude`. Os nomes das contas e os ID de comando correspondem à origem, incluindo contas já presentes no destino. As contas de destino não relacionadas recebem um sufixo numérico se os seus nomes entrarem em conflito, e as definições, skills, plugins e o histórico de conversas permanecem locais a cada máquina.

As credenciais de destino existentes são mantidas. Uma conta de origem que já tenha sessão iniciada aí vê o seu nome sincronizado sem substituir as suas credenciais; as outras contas são adicionadas ao seu lado. Para substituir as credenciais guardadas de contas correspondentes, utilize `omarchy agent account copy --replace laptop claude` depois de fechar as sessões dessa conta no destino. Um destino novo também recebe a conta ativa e as preferências de alternância da origem; um destino já estabelecido mantém as suas próprias.

As credenciais viajam por SSH e são guardadas em ficheiros privados no destino, por isso copie apenas para máquinas em que confia. Isto é uma cópia única, não uma sincronização contínua. Os tokens de atualização do Codex podem ser rodados por outra máquina, a deixar um início de sessão copiado a precisar de renovação; inícios de sessão separados continuam a ser a escolha mais fiável para utilização simultânea em várias máquinas. Consulte a [orientação de autenticação de contas do Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Apenas uma conta por fornecedor está ativa, e cada nova sessão começa como ela: `cx`, `cy`, um simples `claude`, `codex` ou `grok`, qualquer coisa lançada através de `omarchy agent`, e scripts ou editores que encontrem a CLI no `PATH`. Mude com `omarchy agent account use work` (e volte com `omarchy agent account use main`), ou no painel ao premir o número de uma conta e depois `Enter` (ou ao clicar no seu botão Use). As sessões Claude em execução também mudam, a partir da sua próxima mensagem: cada sessão Claude funciona em `~/.claude`, que contém sempre o início de sessão da conta ativa. Uma sessão Claude iniciada na pasta própria de uma conta por um Omarchy mais antigo mantém esse início de sessão até sair, por isso a mudança nomeia essas sessões e termina sozinha quando elas desaparecerem. As sessões Codex e Grok em execução permanecem na conta com que começaram. O histórico de conversas, as definições, as skills e os plugins são partilhados entre contas, por isso `claude --continue` na mesma pasta continua onde ficou na nova conta.

Com mais do que uma conta, o painel mostra os limites de cada conta lado a lado, com a ativa assinalada. Por predefinição, o Omarchy avisa-o quando a conta ativa ultrapassa 95% de um limite, e clicar na notificação muda para a conta com mais margem. Passe o cursor sobre a linha de uma conta no painel e clique em Autoswitch que aparece ao lado de Use (ou prima `m`), ou execute `omarchy agent account mode auto`, para que mude sozinho; enquanto estiver ativado, Autoswitch ocupa o lugar de Use, e clicar novamente volta ao modo de aviso. Adicione um número para alterar o limiar, como em `omarchy agent account mode auto 90`. Se todas as contas estiverem acima do limiar, será avisado uma vez, juntamente com qual conta ficará livre primeiro. Enquanto uma conta ativa estiver a menos de 15 pontos do seu limiar (80% na predefinição), os seus limites são verificados a cada três minutos em vez de a cada 15.

O `omarchy agent account list` mostra todas as contas e os seus limites mais recentes, o `omarchy agent account remove work` esquece uma, e o `omarchy agent account rename primary Hey` muda o nome de uma (ou clique no nome de uma conta no painel). Estes comandos funcionam nas contas do seu agente predefinido; para chegar ao outro fornecedor, indique-o primeiro, como em `omarchy agent account use codex side`. O início de sessão que já tinha em `~/.claude` ou `~/.codex` é a conta _Main_. A do Codex permanece onde está; a do Claude aguarda numa pasta própria enquanto outra conta está ativa. Uma conta deixada sem utilização durante mais de cerca de oito horas pode mostrar _Sign-in required_; clique nela para iniciar sessão nessa conta novamente diretamente no painel, ou mude para ela e inicie uma sessão, o que atualiza o início de sessão por si só. Os servidores MCP que adicionar com `claude mcp add` chegam a todas as contas Claude, uma vez que todas funcionam em `~/.claude`; para o Codex e o Grok, os servidores que tinha quando uma conta foi adicionada acompanham-na, mas os posteriores só chegam à conta em que os adicionou. O Claude Desktop mantém um início de sessão próprio, e as ferramentas Codex ou Grok configuradas com um caminho absoluto para um binário CLI não seguem a mudança. Um `CLAUDE_CONFIG_DIR`, `CODEX_HOME` ou `GROK_HOME` explícito tem precedência sobre a conta selecionada.

### Diagnóstico de falhas

O Omarchy vigia o systemd-coredump à procura de falhas de processos. Quando algo sofre um segfault, recebe uma notificação "Process crashed" — clique nela, e a falha é entregue ao seu agente predefinido juntamente com a skill diagnose-crash do Omarchy, que orienta o agente ao longo do estabelecimento dos factos a partir do core dump e da decisão sobre se a falha merece ser reportada a montante. Também pode executá-la manualmente contra qualquer PID de `coredumpctl list` com `omarchy agent crash <pid>`.

A vigilância está ativada por predefinição. Desative-a em _Trigger > Toggle > Crash Capture_ (ou com `omarchy toggle crash-capture`) e as notificações param; o `omarchy agent crash <pid>` continua a funcionar manualmente.

As falhas também podem ser silenciadas programa a programa, que é o que o diagnóstico lhe oferece no final. O `omarchy crash mute hyprland` para as notificações apenas para esse programa, o `omarchy crash mute hyprland off` traz-as de volta, e o `omarchy crash mute` sozinho lista o que silenciou. Aceita o caminho do binário tão bem como o seu nome, por isso `omarchy crash mute /usr/bin/hyprland` faz a mesma coisa. Coloque entre aspas um nome com um espaço, como em `omarchy crash mute 'Some App'`. Tudo o resto continua a notificar, e o programa silenciado continua a falhar — isto esconde o lembrete, não corrige nada.

### Aplicações de ambiente de trabalho

O menu _Install > AI_ também inclui algumas aplicações gráficas de IA: Antigravity Desktop, a aplicação de ambiente de trabalho do ChatGPT, a aplicação de ambiente de trabalho do Claude (a versão beta para Linux da Anthropic, com separadores Chat, Cowork e Claude Code), o Grok Bot para conversar com os modelos da xAI, o Herdr Desktop, o Hermes Desktop, o OpenClaw, a aplicação de ambiente de trabalho do Perplexity e o T3 Code. O Grok Bot é a aplicação de chat de ambiente de trabalho. O agente de programação é o comando `grok`.

O Hermes Desktop é o que deve conhecer, porque uma máquina tem um Hermes, e é o da aplicação: o Hermes só é instalado através da aplicação, e o comando `hermes` que o agente predefinido executa é o da aplicação. Escolher o Hermes como agente predefinido instala a mesma coisa que a entrada _Install > AI_: o pacote, e um runtime Hermes em `~/.hermes` configurado pelo próprio instalador do Hermes, o que demora alguns minutos na primeira vez. Esse runtime é o único Hermes que o comando `hermes` do terminal, o agente predefinido e a aplicação utilizam, e atualiza-se a si próprio com `hermes update` em vez de estar à espera de uma versão do Omarchy. Instalá-lo também entrega ao Hermes o tema do Omarchy como uma skin chamada `omarchy`, que todas as interfaces do Hermes seguem à medida que muda de tema; escolha outra nas definições de Appearance do Hermes ou com `/skin` se preferir que não o faça, e o Omarchy deixa essa escolha em paz. Remover a aplicação em _Remove > AI_ fecha primeiro o Hermes, gateway incluído, leva esse runtime consigo e mantém as suas conversas, memórias e as skills que o Hermes escreveu para si próprio, a menos que diga o contrário: pergunta, com não por predefinição, se esses dados e as suas definições de ligação também devem desaparecer.

A experiência de ambiente de trabalho do OpenClaw é a sua Control UI, que abre como uma aplicação web suportada pelo seu próprio gateway local. O OpenClaw vive em `~/.openclaw` e atualiza-se a si próprio: utilize o botão "Update Gateway" da Control UI ou execute `openclaw update`, e o gateway reinicia na nova versão. O Omarchy só escolhe a versão com que uma instalação nova começa. Remover o OpenClaw em _Remove > AI_ leva o serviço gateway e a aplicação consigo e depois pergunta se `~/.openclaw` também deve desaparecer, uma vez que isso guarda as suas conversas e credenciais juntamente com o próprio OpenClaw e os runtimes de plugins que descarrega; a predefinição mantém-no, e instalar o OpenClaw novamente volta a apanhá-lo.

O Herdr Desktop é a aplicação de ambiente de trabalho [Herdr](https://herdr.dev): espaços, separadores e painéis de terminais e agentes de programação que continuam a funcionar no seu núcleo quando fecha a janela. Vem do próprio instalador do Herdr em vez de um pacote, por isso vive em `~/.local/share/herdr-app`, traz o seu núcleo em `~/.local/bin/herdr-core` quando ainda não tem um, e atualiza ambos por si próprio. Fica ao lado do comando `herdr` que o Omarchy disponibiliza em `Super + Ctrl + Return` em vez de o substituir, e recebe as teclas diretas desse comando: `Alt + Return` e `Alt + Shift + Return` dividem um painel para baixo ou para a direita, `Alt + Escape` fecha-o, `Ctrl + Alt + Arrow` move entre painéis, `Alt + 1..9` e `Alt + Left/Right` escolhem um separador, e `Alt + Up/Down` move entre espaços. `Ctrl + 1..9` escolhe um espaço e `Alt + Shift + Up/Down` percorre os agentes. As teclas de prefixo `Ctrl + Space` permanecem apenas no terminal, uma vez que a aplicação não consegue manter uma tecla Ctrl simples por uma sequência. O Omarchy escreve estas em `~/.config/herdr-app/keys.json`, e `omarchy-refresh-herdr-app` repõe-nas. Instalá-lo escolhe o tema Omarchy do Herdr, que a partir daí segue o seu tema Omarchy. O Herdr mantém um tema para o modo claro e um para o modo escuro, por isso, depois de alternar entre um tema Omarchy escuro e um claro, escolha Omarchy no seletor de temas do Herdr mais uma vez para o outro modo.

O T3 Code funciona a partir da sua versão AppImage oficial em `~/.local/share/t3code` em vez de a partir de um pacote, por isso atualiza-se a si próprio. Instalá-lo pergunta se quer começar no canal Stable ou Nightly; mude mais tarde nas definições do T3 Code. As suas conversas e definições vivem em `~/.t3`, e remover o T3 Code em _Remove > AI_ leva-as consigo.

### Modelos locais

Execute um modelo aberto na sua própria máquina para os seus agentes de programação. Os seus prompts e código permanecem na máquina; nada do que é enviado para o modelo sai dela. Comece com:

```bash
omarchy agent local use best
```

Ou, no painel de agentes na barra superior, escolha + e depois Local AI, que aparece quando um modelo cabe nesta máquina. Na primeira vez, isto instala o Podman, que executa os modelos, e numa máquina NVIDIA o toolkit de contentores da NVIDIA, que lhes dá acesso à GPU. O Omarchy escolhe então o modelo recomendado para esta máquina, descarrega-o e inicia-o. Conte com uma transferência de dezenas de GB e com a maior parte da memória da máquina em utilização enquanto o modelo está a funcionar: o Flash Next utiliza cerca de 100 GiB com o seu contexto completo de 256K. Se outros modelos ocuparem a memória de que precisa, fica configurado como parado, pronto para iniciar quando parar um. O modelo para ao terminar sessão; pare-o você mesmo quando precisar da memória para outra coisa.

O `omarchy agent local list` mostra as opções e explica por que algumas não cabem. Para configurar outro, execute `omarchy agent local use <recipe>`. Hoje, `qwen3.8-flash-next-gufo` e `qwen3.8-27b-gufo` estão disponíveis para máquinas Strix Halo de 128 GB; o 27B ocupa cerca de 40 GiB, por isso deixa espaço para outro trabalho. Num portátil de 64 GB com a Arc B390 da Intel, `qwen3.6-35b-a3b-llamacpp` funciona em cerca de 30 GiB. Novas receitas e recomendações chegam com o `omarchy update`, através do pacote.

Cada modelo que configurar tem a sua própria linha no painel de agentes, ao lado das suas subscrições: o botão de reprodução para o iniciar, o de pausa para o parar e libertar a sua memória, e o botão de terminal para abrir o seu agente nele. Vários podem funcionar ao mesmo tempo quando cabem juntos na memória; se um não couber, o Omarchy diz qual modelo em execução deve parar. Arraste as linhas para as reordenar e prima Delete numa linha selecionada para remover um modelo e a sua transferência.

Cada modelo que configurar também tem a sua própria entrada no lançador de aplicações, com o nome do modelo e o logótipo do seu criador, da forma como iniciar sessão no Claude, Codex ou Grok adiciona uma. Abre o seu agente nesse modelo e inicia primeiro o modelo se não estiver em execução: o terminal mostra-o a carregar e entrega ao agente quando estiver pronto. Remover um modelo remove a sua entrada.

Um modelo continua a funcionar exatamente como foi configurado, por isso uma atualização do Omarchy nunca reinicia um por baixo dos seus agentes. Quando o Omarchy tem um runtime mais recente ou pesos mais recentes para um modelo que configurou, a sua linha mostra um botão de atualização: prima-o e o modelo é configurado novamente em segundo plano, a descarregar apenas o que mudou, e reinicia na nova versão. Um modelo que estava parado permanece parado. O `omarchy agent local update` faz o mesmo para todos os modelos a partir de um terminal.

A partir da linha de comandos, `omarchy agent local start <recipe>` e `omarchy agent local stop <recipe>` fazem o mesmo, `omarchy agent local status` mostra todos os modelos, e `omarchy agent --local` abre o seu agente predefinido no último modelo que iniciou. O pi, o OpenCode e o Qwen Code podem utilizar um; com qualquer outro predefinido, abre no pi. O pi também lista todos os modelos que configurou, e os que estão em máquinas com que emparelhou, no seu próprio seletor de modelos, por isso um simples `pi` também os alcança. Qualquer cliente compatível com OpenAI também pode ligar-se: o `status` mostra o endereço de cada modelo (o primeiro é `http://127.0.0.1:11435/v1`), o nome da receita é o modelo, e a chave está em `~/.config/omarchy/agent-local/key`.

O `omarchy agent local remove <recipe>` elimina um modelo e as transferências que nenhum outro modelo utiliza.

Os runtimes de terceiros vêm identificados com quem os publica. O Omarchy executa todos os modelos sem acesso à rede.

### LLM locais

O Omarchy recomenda duas formas de executar modelos LLM locais: o LM Studio e o Ollama. O LM Studio fornece uma interface gráfica para encontrar modelos de pesos abertos, instalá-los e executá-los. É uma excelente forma de começar facilmente. O Ollama oferece uma CLI para fazer o mesmo de forma semelhante. Mas se é novo nos modelos locais, eu começaria pelo LM Studio. Pode instalar qualquer um deles em _Install > AI_ no Omarchy Menu.

### A Skill do Omarchy

As skills de agente ajudam a IA a utilizar ferramentas específicas de uma forma específica, e o Omarchy vem com uma skill predefinida para adaptar o sistema. Como ajustar a sua configuração do Hyprland, ajustar a barra, ou até criar um tema novo de raiz. Tem uma ligação simbólica para os diretórios de skills do Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` e cada `~/.hermes/profiles/*/skills`), e para a localização genérica `~/.agents/skills`, por isso a maioria dos harnesses apanha-a automaticamente.

Mas deve tratar esta skill como experimental. Modelos diferentes irão utilizá-la com efeitos diferentes. É melhor executá-la primeiro em modo de planeamento, para ter uma ideia do que o agente gostaria de mudar. E depois esteja preparado para reverter alterações ou até invocar `omarchy reinstall configs`, se o agente fizer uma confusão de tudo.
