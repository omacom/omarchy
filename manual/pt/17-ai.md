# IA

O Omarchy inclui lançadores para os agentes de programação abaixo sem escolher um predefinido para si. Execute um comando para instalar a respetiva CLI na primeira utilização e, em seguida, autentique-se quando lhe for pedido. O Hermes e o OpenClaw são as exceções: nada é instalado para eles através do mise, e escolher qualquer um deles instala a sua própria cópia com atualização automática, como _Aplicações de ambiente de trabalho_ abaixo explica.

### Instalar e atualizar agentes

Com exceção do Hermes e do OpenClaw, estes agentes utilizam a instalação preguiçosa do mise: o primeiro arranque instala a CLI e os arranques seguintes reutilizam-na. O mise também verifica, no máximo uma vez a cada quatro horas, se existe uma nova versão de um agente instalado, mesmo antes de este arrancar ou em segundo plano num prompt da shell. Se essa atualização falhar ou se estiver offline, é executada a versão instalada. O `omarchy update` atualiza os agentes instalados juntamente com o resto do Omarchy, e o `mup` atualiza apenas as ferramentas geridas pelo mise.

O atualizador próprio de um agente, como `claude update`, `codex update` ou um botão de atualização numa aplicação, não atualiza a instalação gerida pelo mise. O `codex update` falha, e o `claude update` pode indicar sucesso enquanto instala uma cópia separada que o mise não acompanha. Se preferir utilizar o instalador e o atualizador nativos de um agente, adicione-o a `disable_tools`; consulte [Ferramentas CLI pré-instaladas](18-development-tools.md#preinstalled-cli-tools).

Para instalar todas as ferramentas preguiçosas configuradas antes de precisar delas, execute `mise install --include-lazy`. Isto inclui as outras ferramentas CLI predefinidas do Omarchy, bem como os agentes. Consulte [Ferramentas CLI pré-instaladas](18-development-tools.md#preinstalled-cli-tools) para instalar uma única ferramenta ou utilizar a sua própria instalação.

O `grok` é instalado através do pacote `grok` oficial do mise, da mesma forma que o `claude` e o `codex`. Execute `grok` ou marque-o com uma estrela no painel de agentes. Ignore o instalador `curl | bash` em x.ai. Esse caminho coloca uma segunda cópia em `~/.grok/bin`, coloca-a no início do `PATH` e substitui o wrapper do Omarchy.

O `dsh` abre a sua UI no browser em `127.0.0.1:3080`, com o diretório de arranque como espaço de trabalho predefinido. A sua UI no browser não aceita um prompt inicial, por isso o `omarchy agent prompt` abre-a com o prompt na área de transferência para colar. O Omarchy arranca-o com a predefinição de permissões sem aprovação do DeepSeek. O DeepSeek Harness envia registos de sessão para o DeepSeek quando utiliza a sua API oficial de modelos; desative isso em _Settings > General > Upload Session Log_ na sua UI no browser. Os comentários que lhe enviar também são enviados com a sessão, a menos que o arranque com `DSH_TELEMETRY_MODE=DISABLED`.

### O agente predefinido

Escolha o seu agente predefinido com a estrela ao lado de um agente no painel de agentes, que aparece preenchida no predefinido, ou com `omarchy default agent <name>`, que também aceita qualquer harness sem uma linha nesse painel. Se o agente ainda não estiver instalado, ao escolhê-lo este é instalado primeiro, e também recebe um lançador próprio no lançador de aplicações, ao lado de Agent. Um Omarchy acabado de instalar convida-o a configurar um com uma notificação única, que abre o painel de agentes.

Escolher o Claude também tenta configurar a sua extensão de browser para o Chromium, o Chrome, o Brave, o Brave Origin e o Edge. A configuração da extensão aplica-se a todos os utilizadores e pode pedir a sua palavra-passe do sistema; cancelar ou uma instalação da extensão falhada continua a selecionar e a iniciar o Claude. Reinicie o browser, ative a extensão se lhe for pedido e inicie sessão no Claude para concluir a ligação. Execute `/chrome` no Claude para verificar a ligação. O Firefox e o Zen não suportam esta extensão. Se o Claude já era o seu predefinido antes de esta configuração ter sido adicionada, selecione-o novamente para instalar a extensão.

Depois de escolher, `Super + Shift + Ctrl + A` inicia o agente predefinido numa janela de terminal dedicada (ou abre o seletor se ainda não tiver escolhido). Também pode iniciá-lo diretamente numa tarefa com `omarchy agent prompt "Review this project"`. O Freebuff e o DeepSeek Harness não aceitam um prompt inicial, por isso abrem com o prompt na área de transferência para colar. Os agentes iniciados desta forma funcionam sem supervisão nos respetivos modos de não parar para perguntar, por isso esteja preparado para eles fazerem mesmo coisas! O MiniMax Code não tem esse modo para as suas sessões interativas, por isso pede permissões como habitualmente. E como os agentes se recusam a memorizar a confiança no seu diretório pessoal, os arranques a partir de `$HOME` começam em `~/Work`.

Também existem atalhos de terminal: `a` executa o agente predefinido em linha no terminal atual, enquanto `c`, `cx`, `cy` e `ca` iniciam diretamente o OpenCode, o Claude Code, o Codex e o Antigravity (novamente nos respetivos modos de aprovação automática). As alterações de tema também são sincronizadas com os agentes: o Claude Code, o Pi, o OpenCode e o Hermes (depois de o Omarchy o ter instalado) acompanham todos quando muda o tema do Omarchy.

### As suas instruções para os agentes

As regras pessoais para todos os agentes vão para `~/.agents/AGENTS.md`, ao lado das competências partilhadas em `~/.agents/skills`. Abra-o com o ícone de documento ao lado do + no painel de agentes, ou com `omarchy agent instructions --edit`, que também o liga a cada harness que mantém o seu próprio ficheiro global: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, o `~/.copilot/copilot-instructions.md` do Copilot, e assim por diante. O Crush e o Amp leem a ligação `~/.config/AGENTS.md`, enquanto o omp, o Kimi e o DeepSeek Harness leem `~/.agents/AGENTS.md` diretamente. Escolher um agente predefinido também o liga. Um ficheiro de instruções que já tinha torna-se o partilhado se ainda não existia nenhum; caso contrário, é mantido ao lado da ligação como `.bak`. Execute `omarchy agent instructions` para voltar a ligar depois de instalar outro agente.

### O painel de agentes

A barra superior tem um ícone de agentes. Antes de ter configurado um agente, o seu painel oferece três formas de começar: iniciar sessão numa subscrição do Claude, Codex, Grok, Gemini, Muse, Cursor ou Copilot, ou em Mais um plano de programação OpenCode Go, MiniMax, Synthetic ou Z.ai; pagar à medida que utiliza com Fireworks, OpenCode Zen and Go, OpenRouter, ou em Mais DeepSeek ou qualquer outro fornecedor em que o OpenCode inicie sessão, todos executados no OpenCode; ou executar o melhor modelo para o seu computador, quando algum se adequa a ele. O primeiro que concluir torna-se o seu agente predefinido, e o + no painel oferece os mesmos três mais tarde. Depois disso, o painel coloca todas as subscrições numa única página: cada agente e conta com o seu plano, um medidor para cada um dos seus limites de sessão de 5 horas e semanais com o tempo até ser reposto (passe o cursor para ver a percentagem exata), ou o saldo pré-pago restante, sob uma linha que alterna pelo que utilizou em todos eles, como os tokens desta semana e o seu modelo mais utilizado. Em _Make something cool_ oferece prompts iniciais para um novo tema, plugin, aplicação ou jogo que entregam a tarefa ao seu agente predefinido. As aplicações são construídas da forma como as próprias Hype, Monologue e Omacut do Omarchy são, em C++ e Qt Quick, seguindo a competência de agente omarchy-make-app, e o compilador e os componentes Qt de que precisam vêm instalados. Os jogos são uma única página three.js em `~/Games/vibes`, seguindo a competência de agente omarchy-make-game, e todos abrem a partir de um único lançador Game Vibes no tema atual; carregam o three.js da web, por isso precisam de uma ligação para arrancar. O Claude Code, o Codex, o Grok, o Kimi, o Cursor e a sua franquia Grok Bot, o GitHub Copilot, o Muse, o Gemini (através do Antigravity) e o Devin estão abrangidos de origem com os seus limites, o Kimchi com o seu plano, créditos pré-pagos e orçamentos de despesa, e o Hermes, o Mistral Vibe e o Qwen Code mostram as suas sessões e tokens depois de os ter utilizado. Os planos e chaves de fornecedores que utiliza através do pi, omp ou opencode também aparecem: o OpenCode Zen and Go, o Z.ai GLM Coding Plan, a Ollama Cloud, o MiniMax Token Plan e o Synthetic com os seus limites; a OpenRouter e o DeepSeek com os seus saldos pré-pagos; o Fireworks com a sua despesa nos últimos 30 dias. Os modelos de programação que executa no seu próprio hardware têm linhas próprias, e os seus tokens também contam para os totais, como descrito em [Modelos locais](#local-models). Cada agente é contado uma vez, sob quem o fatura, independentemente de quantos harnesses utilizar para o usar.

Clique com o botão esquerdo no ícone da barra ou prima `Super + Ctrl + X` para o painel, clique com o botão direito para iniciar o seu agente predefinido e clique com o botão do meio para atualizar. Os registos de utilização por trás dele são regenerados a cada 15 minutos por `omarchy agent usage update`, e o painel pode até fundir a utilização das suas outras máquinas através de uma pasta sincronizada. Consulte o README em `$OMARCHY_PATH/shell/plugins/agents/` para as definições completas.

### Várias subscrições

Se pagar por mais do que um plano Claude, Codex ou Grok — um Max pessoal e um de trabalho, por exemplo — o Omarchy pode manter todos com sessão iniciada e alternar entre eles. Adicione uma subscrição com o + no painel de agentes, que o orienta ali mesmo, ou com `omarchy agent account add claude Work` (ou `codex`, ou `grok`). O mesmo + e comando iniciam sessão no Gemini (`gemini`) e no OpenCode (`opencode`), e guardam uma chave API do Fireworks (`fireworks`) ou da OpenRouter (`openrouter`) no OpenCode; o comando também inicia sessão no Copilot (`copilot`), no Cursor (`cursor`) e no Muse (`muse`). Esses mantêm uma única sessão iniciada cada. Instala a CLI se esta estiver em falta. A primeira conta de um fornecedor inicia sessão através do seu browser normal, exatamente onde a CLI sempre procura. Todas as seguintes iniciam sessão através de uma janela privada, para que a conta em que o seu browser já tem sessão iniciada não seja escolhida por engano; inicie sessão aí como a conta que está a adicionar e feche primeiro qualquer janela privada que já tenha aberta. Nunca termine a sessão da CLI para fazer isto: terminar a sessão revoga o início de sessão guardado, e essa conta teria de ser adicionada novamente.

Para copiar os seus inícios de sessão de subscrição para outra máquina Omarchy por SSH, execute `omarchy agent account copy user@laptop`. O emissor fornece um recetor temporário quando o destino não tem um instalado, para que máquinas Omarchy mais antigas possam receber contas sem uma atualização. Os recetores instalados têm precedência. Isto copia todas as subscrições Claude, Codex e Grok; adicione nomes de fornecedores para as selecionar, como em `omarchy agent account copy laptop claude`. Os nomes das contas e os ID de comando correspondem à origem, incluindo contas já presentes no destino. As contas de destino não relacionadas recebem um sufixo numérico se os seus nomes entrarem em conflito, e as definições, competências, plugins e histórico de conversas permanecem locais em cada máquina.

As credenciais de destino existentes são mantidas. Uma conta de origem que já tem sessão iniciada lá tem o seu nome sincronizado sem substituir as suas credenciais; outras contas são adicionadas ao lado dela. Para substituir as credenciais guardadas de contas correspondentes, utilize `omarchy agent account copy --replace laptop claude` depois de sair das sessões dessa conta no destino. Um destino novo também recebe a conta ativa e as preferências de alternância da origem; um destino já estabelecido mantém as suas próprias.

As credenciais viajam por SSH e são armazenadas em ficheiros privados no destino, por isso copie apenas para máquinas em que confia. Isto é uma cópia única, não uma sincronização contínua. Os tokens de atualização do Codex podem ser rodados por outra máquina, deixando um início de sessão copiado a precisar de renovação; inícios de sessão separados continuam a ser a escolha mais fiável para utilização simultânea em várias máquinas. Consulte [Orientações de autenticação de contas do Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Está ativa uma conta por fornecedor, e todas as novas sessões começam como ela: `cx`, `cy`, um simples `claude`, `codex` ou `grok`, tudo o que for iniciado através de `omarchy agent`, e scripts ou editores que encontrem a CLI no `PATH`. Alterne com `omarchy agent account use work` (e volte com `omarchy agent account use main`), ou no painel premindo o número de uma conta e depois `Enter` (ou clicando na sua estrela). As sessões Claude em execução também alternam, a partir da mensagem seguinte: todas as sessões Claude são executadas em `~/.claude`, que contém sempre o início de sessão da conta ativa. Uma sessão Claude iniciada na pasta própria de uma conta por um Omarchy mais antigo mantém esse início de sessão até sair, por isso a alternância indica essas sessões e termina sozinha quando desaparecerem. As sessões Codex e Grok em execução permanecem na conta com que começaram. O histórico de conversas, as definições, as competências e os plugins são partilhados entre contas, por isso `claude --continue` na mesma pasta retoma onde parou na nova conta.

Com mais do que uma conta, o painel mostra os limites de cada conta lado a lado, com uma estrela preenchida na que está em utilização. O Omarchy notifica-o quando a conta ativa ultrapassa 95% de um limite, e clicar na notificação muda para a conta com maior margem. Nunca muda sozinho. Altere o limiar com `omarchy agent account threshold 90`. Se todas as contas estiverem acima do limiar, será informado uma vez, juntamente com qual a conta que fica livre primeiro. Enquanto uma conta ativa estiver a menos de 15 pontos do seu limiar (80% no valor predefinido), os seus limites são verificados a cada três minutos e não a cada 15.

`omarchy agent account list` mostra todas as contas e os seus limites mais recentes, `omarchy agent account remove work` esquece uma, e `omarchy agent account rename primary Hey` muda o nome de uma (ou clique no nome de uma conta no painel). Estes comandos funcionam nas contas do seu agente predefinido; para aceder ao outro fornecedor, indique-o primeiro, como em `omarchy agent account use codex side`. O início de sessão que já tinha em `~/.claude` ou `~/.codex` é a conta _Main_. O do Codex permanece onde está; o do Claude aguarda numa pasta própria enquanto outra conta estiver ativa. Uma conta que fique sem utilização durante mais de cerca de oito horas pode mostrar _Sign-in required_; clique nela para iniciar novamente sessão nessa conta diretamente no painel, ou mude para ela e inicie uma sessão, o que atualiza o início de sessão sozinho. Os servidores MCP que adicionar com `claude mcp add` chegam a todas as contas Claude, uma vez que todas são executadas em `~/.claude`; para o Codex e o Grok, os servidores que tinha quando uma conta foi adicionada acompanham-na, mas os posteriores só chegam à conta em que os adicionou. O Claude Desktop mantém um início de sessão próprio, e as ferramentas Codex ou Grok configuradas com um caminho absoluto para um binário CLI não acompanham a mudança. Um `CLAUDE_CONFIG_DIR`, `CODEX_HOME` ou `GROK_HOME` explícito tem precedência sobre a conta selecionada.

### Diagnóstico de falhas

O Omarchy observa o systemd-coredump à procura de falhas de processos. Depois de escolher um agente predefinido, qualquer programa seu que gere um core dump traz uma notificação "Process crashed" — clique nela e a falha é entregue ao seu agente predefinido juntamente com a competência omarchy-diagnose-crash do Omarchy, que orienta o agente a estabelecer os factos a partir do core dump e a decidir se vale a pena reportar a falha a montante. Também pode executá-lo manualmente em qualquer PID de `coredumpctl list` com `omarchy agent crash <pid>`.

A observação está ativada por predefinição. Desative-a em _Trigger > Toggle > Crash Capture Off_ (ou com `omarchy toggle crash-capture`) e as notificações param; o `omarchy agent crash <pid>` continua a funcionar manualmente.

As falhas também podem ser silenciadas um programa de cada vez, que é o que o diagnóstico lhe oferece no final. `omarchy crash mute hyprland` para as notificações apenas para esse programa, `omarchy crash mute hyprland off` traz-as de volta, e `omarchy crash mute` sozinho lista o que silenciou. Aceita o caminho do binário tão bem como o seu nome, por isso `omarchy crash mute /usr/bin/hyprland` faz a mesma coisa. Coloque entre aspas um nome com um espaço, como em `omarchy crash mute 'Some App'`. Tudo o resto continua a notificar, e o programa silenciado continua a falhar — isto oculta o lembrete, não resolve nada.

### Aplicações de ambiente de trabalho

O menu _Install > AI_ também inclui algumas aplicações gráficas de IA: Amp Desktop, Antigravity Desktop, a aplicação de ambiente de trabalho do ChatGPT, a aplicação de ambiente de trabalho do Claude (a beta para Linux da Anthropic, com separadores Chat, Cowork e Claude Code), Grok Bot para conversar com os modelos da xAI, Herdr Desktop, Hermes Desktop, OpenClaw, a aplicação de ambiente de trabalho do Perplexity e T3 Code. O Grok Bot é a aplicação de conversação para ambiente de trabalho. O agente de programação é o comando `grok`.

O Hermes Desktop é o que deve conhecer, porque uma máquina tem um Hermes, e é o da aplicação: o Hermes só é alguma vez instalado através da aplicação, e o comando `hermes` que o agente predefinido executa é o da aplicação. Escolher o Hermes como agente predefinido instala a mesma coisa que a entrada _Install > AI_: o pacote e um runtime Hermes em `~/.hermes` configurado pelo próprio instalador do Hermes, o que demora alguns minutos na primeira vez. Esse runtime é o único Hermes que o comando `hermes` no terminal, o agente predefinido e a aplicação utilizam, e atualiza-se a si próprio com `hermes update` em vez de esperar por uma versão do Omarchy. Instalá-lo também entrega ao Hermes o tema do Omarchy como uma skin chamada `omarchy`, que todas as superfícies do Hermes seguem quando muda de tema; escolha outra nas definições Appearance do Hermes ou com `/skin` se preferir que não o faça, e o Omarchy deixa essa escolha em paz. Remover a aplicação em _Remove > AI_ fecha primeiro o Hermes, gateway incluído, leva esse runtime com ela e mantém as suas conversas, memórias e as competências que o Hermes escreveu para si próprio, a menos que lhe diga o contrário: pergunta, com não por predefinição, se esses dados e as suas definições de ligação também devem desaparecer.

A experiência de ambiente de trabalho do OpenClaw é a sua Control UI, que abre como uma aplicação web suportada pelo seu próprio gateway local. O OpenClaw vive em `~/.openclaw` e atualiza-se a si próprio: utilize o botão "Update Gateway" da Control UI ou execute `openclaw update`, e o gateway reinicia na nova versão. O Omarchy apenas escolhe a versão a partir da qual uma instalação nova começa. O OpenClaw também pode ser o seu agente predefinido: escolhê-lo com `omarchy default agent openclaw` configura essa mesma cópia em `~/.openclaw`, e o agente abre a UI de terminal do OpenClaw ligada ao seu gateway. Remover o OpenClaw em _Remove > AI_ leva o serviço de gateway e a aplicação com ele e depois pergunta se `~/.openclaw` também deve desaparecer, uma vez que isso contém as suas conversas e credenciais juntamente com o próprio OpenClaw e os runtimes de plugins que ele transfere; a predefinição mantém-no, e instalar o OpenClaw novamente volta a utilizá-lo.

O Herdr Desktop é a aplicação de ambiente de trabalho [Herdr](https://herdr.dev): espaços, separadores e painéis de terminais e agentes de programação que continuam a funcionar no seu núcleo quando fecha a janela. Vem do próprio instalador do Herdr e não de um pacote, por isso vive em `~/.local/share/herdr-app`, traz o seu núcleo em `~/.local/bin/herdr-core` quando ainda não tem um, e atualiza-se a si próprio em ambos. Fica ao lado do comando `herdr` que o Omarchy fornece em `Super + Ctrl + Return` em vez de o substituir, e recebe as teclas diretas desse comando: `Alt + Return` e `Alt + Shift + Return` dividem um painel para baixo ou para a direita, `Alt + Escape` fecha-o, `Ctrl + Alt + Arrow` move entre painéis, `Alt + 1..9` e `Alt + Left/Right` escolhem um separador, e `Alt + Up/Down` movem entre espaços. `Ctrl + 1..9` escolhe um espaço e `Alt + Shift + Up/Down` percorre os agentes. As teclas de prefixo `Ctrl + Space` permanecem apenas no terminal, uma vez que a aplicação não consegue manter uma tecla Ctrl simples para uma sequência. O Omarchy escreve estas em `~/.config/herdr-app/keys.json`, e o `omarchy-refresh-herdr-app` repõe-nas. Instalá-lo escolhe o tema Omarchy do Herdr, que a partir daí segue o seu tema Omarchy. O Herdr mantém um tema para o modo claro e um para o modo escuro, por isso, depois de alternar entre um tema Omarchy escuro e um claro, escolha Omarchy no seletor de temas do Herdr mais uma vez para o outro modo.

O T3 Code é executado a partir da sua versão oficial AppImage em `~/.local/share/t3code` e não de um pacote, por isso atualiza-se a si próprio. Instalá-lo pergunta se deve começar no canal Stable ou Nightly; mude mais tarde nas definições do T3 Code. Os seus tópicos e definições vivem em `~/.t3`, e remover o T3 Code em _Remove > AI_ leva-os com ele.

### Modelos locais

Execute um modelo aberto na sua própria máquina para os seus agentes de programação. Os seus prompts e código permanecem na máquina; nada do que é enviado para o modelo sai dela. Comece com:

```bash
omarchy models use best text
```

Isso configura o melhor modelo de texto para esta máquina, do tipo que os seus agentes utilizam. Os modelos de imagem, vídeo e música têm o seu próprio melhor: `omarchy models use best image`, `video` ou `music`. Execute `omarchy models use best` para ver a escolha de cada tipo para esta máquina.

Ou escolha + no painel de agentes: em _Use a local model_ lista todos os modelos de programação que cabem nesta máquina, o recomendado primeiro. O Podman, que executa os modelos, vem com o Omarchy, tal como o kit de ferramentas de contentores da NVIDIA numa máquina NVIDIA, que lhes dá a GPU; se algum estiver em falta, a primeira configuração instala-o. O Omarchy escolhe então o modelo recomendado para esta máquina, transfere-o e inicia-o. Conte com uma transferência de dezenas de GB e com a maior parte da memória da máquina em utilização enquanto o modelo estiver a funcionar: o Flash Next utiliza cerca de 100 GiB com o seu contexto completo de 256K. Se outros modelos ocuparem a memória de que precisa, é configurado parado, pronto para arrancar quando parar um. O modelo para ao terminar a sessão; pare-o você mesmo quando precisar da memória para outra coisa.

`omarchy models list` mostra as opções e explica por que motivo algumas não cabem. Para configurar outro, execute `omarchy models use <recipe>`. Hoje, `qwen3.8-flash-next-gufo` e `qwen3.8-27b-gufo` estão disponíveis para máquinas Strix Halo de 128 GB; o 27B ocupa cerca de 40 GiB, por isso deixa espaço para outro trabalho. Num portátil de 64 GB com Arc B390 da Intel, `qwen3.6-35b-a3b-llamacpp` funciona em cerca de 30 GiB. Novas receitas e recomendações chegam com `omarchy update`, através do pacote.

Um modelo de programação que adicionar recebe a sua própria linha no painel de agentes, ao lado das suas subscrições: reproduzir para o iniciar, pausar para o parar e libertar a sua memória, a marca Tailscale para o partilhar com as outras máquinas na sua tailnet enquanto estiver a funcionar, e o botão de terminal para abrir o seu agente nele. A sua linha mostra a transferência, o carregamento ou a paragem à medida que avança, e indica quando não há memória livre suficiente para o iniciar, ou liga aos seus registos quando parou com um erro. Vários podem funcionar ao mesmo tempo quando cabem juntos na memória. Prima Delete numa linha selecionada para remover o modelo desta máquina, transferência e tudo; o + pode configurá-lo novamente. Um modelo de programação configurado a partir de um terminal aguarda em + até o adicionar, e o mesmo acontece aos modelos que uma máquina com a qual emparelhou (`omarchy models pair <host>`) executa.

Todos os modelos de programação que configurar também recebem a sua própria entrada no lançador de aplicações, com o nome do modelo e o logótipo do seu criador, da forma como iniciar sessão no Claude, Codex ou Grok adiciona uma. Abre o seu agente nesse modelo e inicia primeiro o modelo se este não estiver a funcionar: o terminal mostra-o a carregar e entrega ao agente quando estiver pronto. Remover um modelo remove a sua entrada.

Nem todos os modelos são para programação. Os modelos de imagem, vídeo e música abrem no Fantasi, a aplicação do Omarchy para fazer imagens, vídeo e música com um modelo a funcionar nesta máquina, e são geridos lá ou com `omarchy models`.

Um modelo continua a funcionar exatamente como foi configurado, por isso uma atualização do Omarchy nunca reinicia um por baixo dos seus agentes. Quando o Omarchy tem um runtime mais recente ou pesos mais recentes para um modelo que configurou, a sua linha mostra um botão de atualização: prima-o e o modelo é configurado novamente em segundo plano, transferindo apenas o que mudou, e reinicia na nova versão. Um modelo que estava parado permanece parado. O `omarchy models update` faz o mesmo para todos os modelos a partir de um terminal.

A partir da linha de comandos, `omarchy models start <recipe>` e `omarchy models stop <recipe>` fazem o mesmo, `omarchy models status` mostra todos os modelos, e `omarchy agent --local-model <recipe>` abre esse modelo no pi, qualquer que seja o seu agente predefinido. Para fazer do seu modelo local aquilo que a tecla de atalho do agente, a consola Quake e _Make something_ abrem, execute `omarchy default agent local` ou marque com uma estrela um modelo em execução no painel de agentes. O pi também lista todos os modelos que configurou, e os das máquinas com as quais emparelhou, no seu próprio seletor de modelos, por isso um simples `pi` também chega a eles. Qualquer cliente compatível com OpenAI também se pode ligar: `status` mostra o endereço de cada modelo (o primeiro é `http://127.0.0.1:11435/v1`), o nome da receita é o modelo, e a chave está em `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` apaga um modelo e as transferências que nenhum outro modelo utiliza.

Os runtimes de terceiros são identificados com o seu editor. O Omarchy executa todos os modelos sem acesso à rede.

### LLM locais

O Omarchy recomenda duas formas de executar modelos LLM locais: LM Studio e Ollama. O LM Studio fornece uma interface GUI para encontrar modelos de pesos abertos, instalá-los e executá-los. É uma ótima forma de começar facilmente. O Ollama oferece uma CLI para fazer o mesmo de forma semelhante. Mas se é novo nos modelos locais, eu começaria pelo LM Studio. Pode instalar qualquer um deles em _Install > AI_ no Menu Omarchy.

### As competências do Omarchy

As competências de agente ajudam a IA a utilizar ferramentas específicas de uma forma específica, e o Omarchy inclui sete delas. A competência omarchy abrange a personalização do sistema, como ajustar a sua configuração do Hyprland ou ajustar a barra. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app e omarchy-make-game abrangem fazer algo novo, omarchy-contribute abrange reportar um erro ou enviar uma correção a montante, e omarchy-diagnose-crash trabalha a partir do core dump de uma falha. Estão ligadas por ligações simbólicas aos diretórios de competências do Claude Code (`~/.claude/skills`), do Codex (`~/.codex/skills`), do Pi (`~/.pi/agent/skills`), do Antigravity (`~/.gemini/config/skills`), do Hermes (`~/.hermes/skills` e cada `~/.hermes/profiles/*/skills`) e à localização genérica `~/.agents/skills`, por isso a maioria dos harnesses recolhe-as automaticamente. Uma pasta de competência sua com o mesmo nome tem precedência.

Mas deve tratar estas competências como experimentais. Modelos diferentes irão utilizá-la com efeitos diferentes. É melhor executar primeiro em modo de plano, para ter uma ideia do que o agente gostaria de mudar. E depois esteja preparado para reverter alterações ou até invocar `omarchy reinstall configs`, se o agente fizer uma confusão de tudo.
