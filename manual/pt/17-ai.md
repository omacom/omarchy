# IA

O Omarchy inclui lançadores para os agentes de programação abaixo sem escolher um predefinido por si. Execute um comando para instalar a sua CLI na primeira utilização e depois autentique-se quando lhe for pedido. O Hermes é a exceção: nada é instalado para ele na primeira utilização, e escolhê-lo instala o Hermes Desktop, como _Aplicações de ambiente de trabalho_ abaixo explica.

### Instalar e atualizar agentes

Exceto o Hermes, estes agentes usam a instalação preguiçosa do mise: o primeiro arranque instala a CLI, e os arranques posteriores reutilizam-na. O mise também verifica se há uma nova versão de um agente instalado, no máximo uma vez a cada quatro horas, mesmo antes de ele arrancar ou em segundo plano num prompt da shell. Se essa atualização falhar ou se estiver offline, é executada a versão instalada. O `omarchy update` atualiza os agentes instalados com o resto do Omarchy, e o `mup` atualiza apenas as ferramentas geridas pelo mise.

O atualizador próprio de um agente, como `claude update`, `codex update` ou um botão de atualização numa aplicação, não atualiza a instalação gerida pelo mise. O `codex update` falha, e o `claude update` pode comunicar sucesso ao instalar uma cópia separada que o mise não está a acompanhar. Se preferir usar o instalador e o atualizador nativos de um agente, adicione-o a `disable_tools`; consulte [Ferramentas CLI pré-instaladas](18-development-tools.md#preinstalled-cli-tools).

Para instalar todas as ferramentas preguiçosas configuradas antes de precisar delas, execute `mise install --include-lazy`. Isto inclui as outras ferramentas CLI predefinidas do Omarchy, bem como os agentes. Consulte [Ferramentas CLI pré-instaladas](18-development-tools.md#preinstalled-cli-tools) para instalar uma única ferramenta ou usar a sua própria instalação.

O `grok` é instalado através do pacote first-party `grok` do mise, da mesma forma que o `claude` e o `codex`. Execute `grok`, ou escolha-o em _Setup > Defaults > Agent_. Evite o instalador `curl | bash` em x.ai. Esse caminho coloca uma segunda cópia em `~/.grok/bin`, coloca-a no início do `PATH` e substitui o wrapper do Omarchy.

O `dsh` abre a sua interface no browser em `127.0.0.1:3080`, com o diretório de arranque como área de trabalho predefinida. A sua interface no browser não aceita um prompt inicial, por isso `omarchy agent prompt` abre-o com o prompt na área de transferência para colar. O Omarchy inicia-o com a predefinição de permissões sem aprovação da DeepSeek. O DeepSeek Harness envia registos de sessão para a DeepSeek quando usa a sua API oficial de modelos; desative isso em _Settings > General > Upload Session Log_ na interface no browser. Os comentários que lhe enviar também são carregados com a sessão, a menos que o inicie com `DSH_TELEMETRY_MODE=DISABLED`.

### O agente predefinido

Escolha o seu agente predefinido com `omarchy default agent <name>` ou em _Setup > Defaults > Agent_ no Menu Omarchy (`Super + Space`). Se o agente ainda não estiver instalado, escolhê-lo instala-o primeiro. Um Omarchy acabado de instalar vai convidá-lo a fazer esta escolha com uma notificação única.

Escolher o Claude também tenta configurar a sua extensão de browser para Chromium, Chrome, Brave, Brave Origin e Edge. A configuração da extensão aplica-se a todos os utilizadores e pode pedir a sua palavra-passe de sistema; cancelar ou uma instalação falhada da extensão continua a selecionar e a iniciar o Claude. Reinicie o browser, ative a extensão se lhe for pedido e inicie sessão no Claude para terminar a ligação. Execute `/chrome` no Claude para verificar a ligação. O Firefox e o Zen não suportam esta extensão. Se o Claude já era o seu predefinido antes de esta configuração ser adicionada, selecione-o novamente para instalar a extensão.

Depois de escolher, `Super + Shift + Ctrl + A` inicia o agente predefinido numa janela de terminal dedicada (ou abre o seletor se ainda não tiver escolhido). Também pode iniciá-lo diretamente numa tarefa com `omarchy agent prompt "Review this project"`. O Freebuff e o DeepSeek Harness não aceitam um prompt inicial, por isso abrem com o prompt na área de transferência para colar. Os agentes iniciados desta forma funcionam sem supervisão nos respetivos modos de não parar para perguntar, por isso esteja pronto para eles fazerem mesmo coisas! O MiniMax Code não tem esse modo para as suas sessões interativas, por isso pede permissões como habitualmente. E como os agentes se recusam a memorizar a confiança para o seu diretório pessoal, os arranques a partir de `$HOME` começam antes em `~/Work`.

Também há atalhos de terminal: `a` executa o agente predefinido inline no terminal atual, enquanto `c`, `cx` e `cy` iniciam diretamente o OpenCode, o Claude Code e o Codex (mais uma vez nos seus modos de aprovação automática). As alterações de tema também se sincronizam com os agentes: o Claude Code, o Pi, o OpenCode e o Hermes (depois de o Omarchy o ter instalado) acompanham-no quando muda o tema do Omarchy.

### O painel de agentes

A barra superior tem um ícone de agentes. Antes de ter configurado um agente, o painel guia-o no início de sessão no Claude, no Codex ou no Grok, e o primeiro torna-se o seu agente predefinido. Depois disso, o painel coloca todas as subscrições numa só página: cada agente e conta com o seu plano, um medidor para cada um dos seus limites de sessão de 5 horas e semanais com o tempo até ser reposto (passe o cursor para ver a percentagem exata), ou o saldo pré-pago restante, por baixo de uma linha que vai alternando pelo que utilizou em todos eles, como os tokens desta semana e o seu modelo mais usado. Em _Make something_ oferece prompts iniciais para um novo tema, plugin ou aplicação que entregam a tarefa ao seu agente predefinido. As aplicações são construídas da mesma forma que as próprias Hype, Monologue e Omacut do Omarchy, em C++ e Qt Quick, seguindo a skill de agente omarchy-app, e o compilador e os componentes Qt de que precisam vêm instalados. O Claude Code, o Codex, o Grok, o Kimi, o Cursor e a sua permissão Grok Bot, o GitHub Copilot, o Muse, o Antigravity, o Kimchi e o Devin estão abrangidos de origem com os seus limites, e o Hermes, o Mistral Vibe e o Qwen Code mostram as suas sessões e tokens depois de os ter usado. Os planos e chaves de fornecedores que usa através do pi, do omp ou do opencode também aparecem: OpenCode Zen e Go, o Z.ai GLM Coding Plan, a Ollama Cloud, o MiniMax Token Plan e a Synthetic com os seus limites; Fireworks, OpenRouter e DeepSeek com os seus saldos pré-pagos; e os modelos que executa no seu próprio hardware em Local models. Cada agente é contado uma vez, por quem o fatura, por mais harnesses através dos quais o utilize.

Clique com o botão esquerdo no ícone da barra para abrir o painel, clique com o botão direito para iniciar o seu agente predefinido. Os registos de utilização por trás dele são regenerados a cada 15 minutos por `omarchy agent usage-update`, e o painel pode até fundir a utilização das suas outras máquinas através de uma pasta sincronizada. Consulte o README em `$OMARCHY_PATH/shell/plugins/agents/` para ver todas as definições.

### Várias subscrições

Se pagar por mais do que um plano Claude, Codex ou Grok — um Max pessoal e um de trabalho, por exemplo — o Omarchy pode manter todos com sessão iniciada e alternar entre eles. Adicione uma subscrição com o + no painel de agentes, que o guia ali mesmo, ou com `omarchy agent account add claude Work` (ou `codex`, ou `grok`). Instala a CLI se esta estiver em falta. A primeira conta de um fornecedor inicia sessão através do seu browser normal, exatamente onde a CLI sempre procura. Todas as seguintes iniciam sessão através de uma janela privada, para que a conta em que o seu browser já tem sessão iniciada não seja apanhada por engano; inicie sessão aí como a conta que está a adicionar e feche primeiro qualquer janela privada que já tenha aberta. Nunca termine sessão na CLI para fazer isto: terminar sessão revoga o início de sessão guardado, e essa conta teria de ser adicionada outra vez.

Para copiar os seus inícios de sessão de subscrição para outra máquina Omarchy por SSH, execute `omarchy agent account copy user@laptop`. O emissor fornece um recetor temporário quando o destino não tem um instalado, por isso máquinas Omarchy mais antigas podem receber contas sem uma atualização. Os recetores instalados têm precedência. Isto copia todas as subscrições Claude, Codex e Grok; adicione nomes de fornecedores para as selecionar, como em `omarchy agent account copy laptop claude`. Os nomes das contas e os IDs de comando coincidem com a origem, incluindo contas já presentes no destino. Contas de destino não relacionadas recebem um sufixo numérico se os seus nomes entrarem em conflito, e as definições, skills, plugins e histórico de conversas permanecem locais a cada máquina.

As credenciais existentes no destino são mantidas. Uma conta de origem que já tenha sessão iniciada lá tem o seu nome sincronizado sem substituir as suas credenciais; as outras contas são adicionadas ao lado dela. Para substituir as credenciais guardadas de contas correspondentes, use `omarchy agent account copy --replace laptop claude` depois de sair das sessões dessa conta no destino. Um destino novo também recebe a conta ativa e as preferências de alternância da origem; um destino já estabelecido mantém as suas.

As credenciais viajam através do SSH e são guardadas em ficheiros privados no destino, por isso copie apenas para máquinas em que confia. Isto é uma cópia única, não uma sincronização contínua. Os tokens de atualização do Codex podem ser rodados por outra máquina, deixando um início de sessão copiado a precisar de renovação; inícios de sessão separados continuam a ser a escolha mais fiável para utilização simultânea em várias máquinas. Consulte a [orientação de autenticação de contas do Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Uma conta por fornecedor está ativa, e cada nova sessão começa como ela: `cx`, `cy`, um `claude`, `codex` ou `grok` simples, qualquer coisa iniciada através de `omarchy agent`, e scripts ou editores que encontram a CLI no `PATH`. Alterne com `omarchy agent account use work` (e volte com `omarchy agent account use main`), ou no painel premindo o número de uma conta e depois `Enter` (ou clicando no seu botão Use). As sessões que já estão a correr permanecem na conta com que começaram. O histórico de conversas, as definições, as skills e os plugins são partilhados entre contas, por isso `claude --continue` na mesma pasta continua onde parou na nova conta.

Com mais do que uma conta, o painel mostra lado a lado os limites de cada conta, com a ativa assinalada. Por predefinição, o Omarchy notifica-o quando a conta ativa ultrapassa 95% de um limite, e clicar na notificação muda para a conta com mais margem. Passe o cursor sobre a linha de uma conta no painel e clique em Autoswitch que aparece ao lado de Use (ou prima `m`), ou execute `omarchy agent account mode auto`, para que mude sozinho; enquanto estiver ativo, Autoswitch ocupa o lugar de Use, e clicar nele novamente volta a notificar. Adicione um número para alterar o limiar, como em `omarchy agent account mode auto 90`. Se todas as contas estiverem acima do limiar, vai saber disso uma vez, juntamente com a conta que fica livre primeiro. Enquanto uma conta ativa estiver a menos de 15 pontos do seu limiar (80% no valor predefinido), os seus limites são verificados a cada três minutos em vez de a cada 15.

`omarchy agent account list` mostra todas as contas e os seus limites mais recentes, `omarchy agent account remove work` esquece uma, e `omarchy agent account rename primary Hey` muda o nome de uma (ou clique no nome de uma conta no painel). Estes comandos funcionam nas contas do seu agente predefinido; para chegar ao outro fornecedor, nomeie-o primeiro, como em `omarchy agent account use codex side`. O início de sessão que já tinha em `~/.claude` ou `~/.codex` é a conta _Main_ e fica onde está. Uma conta deixada sem utilização durante mais de cerca de oito horas pode mostrar _Sign-in required_; clique nela para iniciar sessão nessa conta outra vez diretamente no painel, ou inicie uma sessão nela, o que atualiza o início de sessão por si só. Os servidores MCP que tinha quando uma conta foi adicionada acompanham-na, mas os que adicionar mais tarde com `claude mcp add` só chegam à conta em que os adicionou. O Claude Desktop e as ferramentas configuradas com um caminho absoluto para um binário da CLI não seguem a mudança. Um `CLAUDE_CONFIG_DIR`, `CODEX_HOME` ou `GROK_HOME` explícito tem precedência sobre a conta selecionada.

### Diagnóstico de falhas

O Omarchy vigia o systemd-coredump quanto a falhas de processos. Quando alguma coisa faz segfault, recebe uma notificação "Process crashed" — clique nela, e a falha é entregue ao seu agente predefinido juntamente com a skill diagnose-crash do Omarchy, que guia o agente no estabelecimento dos factos a partir do core dump e na decisão sobre se vale a pena comunicar a falha a montante. Também pode executá-lo manualmente contra qualquer PID de `coredumpctl list` com `omarchy agent crash <pid>`.

A vigilância está ativa por predefinição. Desative-a em _Trigger > Toggle > Crash Capture_ (ou com `omarchy toggle crash-capture`) e as notificações param; o `omarchy agent crash <pid>` continua a funcionar manualmente.

As falhas também podem ser silenciadas programa a programa, que é o que o diagnóstico lhe oferece no fim. `omarchy crash mute hyprland` para as notificações apenas para esse programa, `omarchy crash mute hyprland off` traz-as de volta, e `omarchy crash mute` sozinho lista o que silenciou. Aceita o caminho do binário com a mesma facilidade que o seu nome, por isso `omarchy crash mute /usr/bin/hyprland` faz a mesma coisa. Coloque entre aspas um nome com um espaço, como em `omarchy crash mute 'Some App'`. Tudo o resto continua a notificar, e o programa silenciado continua a falhar — isto esconde o lembrete, não corrige nada.

### Aplicações de ambiente de trabalho

O menu _Install > AI_ também traz algumas aplicações gráficas de IA: a aplicação de ambiente de trabalho do ChatGPT, a aplicação de ambiente de trabalho do Claude (a beta para Linux da Anthropic, com separadores Chat, Cowork e Claude Code), o Grok Bot para conversar com os modelos da xAI, o Hermes Desktop, o OpenClaw, a aplicação de ambiente de trabalho da Perplexity e o T3 Code. O Grok Bot é a aplicação de conversa para ambiente de trabalho. O agente de programação é o comando `grok`.

O Hermes Desktop é o que deve conhecer, porque uma máquina tem um Hermes, e é o da aplicação: o Hermes só é alguma vez instalado através da aplicação, e o comando `hermes` que o agente predefinido executa é o da aplicação. Escolher o Hermes como agente predefinido instala a mesma coisa que a entrada _Install > AI_: o pacote, e um runtime Hermes em `~/.hermes` configurado pelo instalador próprio do Hermes, o que demora alguns minutos na primeira vez. Esse runtime é o único Hermes que o comando `hermes` no terminal, o agente predefinido e a aplicação usam, e atualiza-se a si próprio com `hermes update` em vez de estar à espera de uma versão do Omarchy. Instalá-lo também entrega ao Hermes o tema Omarchy como uma skin chamada `omarchy`, que todas as superfícies do Hermes seguem quando muda de tema; escolha outra nas definições de Appearance do Hermes ou com `/skin` se preferir que não o faça, e o Omarchy deixa essa escolha em paz. Remover a aplicação em _Remove > AI_ fecha primeiro o Hermes, gateway incluída, leva esse runtime com ele, e mantém as suas conversas, memórias e as skills que o Hermes escreveu para si próprio, a menos que lhe diga o contrário: pergunta, com não por predefinição, se esses dados e as suas definições de ligação também devem ir.

A experiência de ambiente de trabalho do OpenClaw é a sua Control UI, que abre como uma aplicação web suportada pela sua própria gateway local. O OpenClaw vive em `~/.openclaw` e atualiza-se a si próprio: use o botão "Update Gateway" da Control UI ou execute `openclaw update`, e a gateway reinicia na nova versão. O Omarchy apenas escolhe a versão a partir da qual uma instalação nova começa. Remover o OpenClaw em _Remove > AI_ leva o serviço da gateway e a aplicação com ele e depois pergunta se `~/.openclaw` também deve ir, uma vez que guarda as suas conversas e credenciais juntamente com o próprio OpenClaw e os runtimes de plugins que ele transfere; a predefinição mantém-no, e instalar o OpenClaw outra vez volta a apanhá-lo.

O T3 Code corre a partir da sua versão oficial AppImage em `~/.local/share/t3code` em vez de a partir de um pacote, por isso atualiza-se a si próprio. Instalá-lo pergunta se deve começar no canal Stable ou Nightly; mude mais tarde nas definições do T3 Code. As suas threads e definições vivem em `~/.t3`, e remover o T3 Code em _Remove > AI_ leva-as com ele.

### Modelos locais

Execute um modelo aberto na sua própria máquina para os seus agentes de programação. Os seus prompts e código ficam na máquina; nada do que é enviado para o modelo sai dela. Comece com:

```bash
omarchy agent local use best
```

Ou, no painel de agentes na barra superior, escolha + e depois Local AI, que aparece quando um modelo cabe nesta máquina. Da primeira vez, isto instala o Podman, que executa os modelos. Depois, o Omarchy escolhe o modelo recomendado para esta máquina, transfere-o e inicia-o. Conte com uma transferência de dezenas de GB e com a maior parte da memória da máquina em uso enquanto o modelo está a correr: o Flash Next usa cerca de 100 GiB com o seu contexto completo de 256K. Se outros modelos ocuparem a memória de que ele precisa, fica configurado parado, pronto para arrancar quando parar um. O modelo para ao terminar sessão; pare-o você mesmo quando precisar da memória para outra coisa.

`omarchy agent local list` mostra as opções e explica por que razão algumas não cabem. Para configurar outra, execute `omarchy agent local use <recipe>`. Hoje, `qwen3.8-flash-next-halogen` e `qwen3.8-27b-gufo` estão disponíveis para máquinas Strix Halo de 128 GB. Novas receitas e recomendações chegam com `omarchy update`, através do pacote.

Cada modelo que configurar tem a sua própria linha no painel de agentes, ao lado das suas subscrições: reproduzir para o iniciar, pausar para o parar e libertar a sua memória, e o botão de terminal para abrir o seu agente nele. Vários podem correr ao mesmo tempo quando cabem juntos na memória; se um não couber, o Omarchy diz qual o modelo em execução a parar. Arraste as linhas para as reordenar, e prima Delete numa linha selecionada para remover um modelo e a sua transferência.

A partir da linha de comandos, `omarchy agent local start <recipe>` e `omarchy agent local stop <recipe>` fazem o mesmo, `omarchy agent local status` mostra todos os modelos, e `omarchy agent --local` abre o seu agente predefinido no último modelo que iniciou (pi se o seu agente predefinido não conseguir usar um modelo local). Qualquer cliente compatível com OpenAI também se pode ligar: `status` mostra o endereço de cada modelo (o primeiro é `http://127.0.0.1:11435/v1`), o nome da receita é o modelo, e a chave está em `~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` apaga um modelo e as transferências que nenhum outro modelo usa.

Os runtimes de terceiros estão identificados com o seu editor. O Omarchy executa todos os modelos sem acesso à rede.

### LLM locais

O Omarchy recomenda duas formas de executar modelos LLM locais: LM Studio e Ollama. O LM Studio fornece uma interface gráfica para encontrar modelos de pesos abertos, instalá-los e executá-los. É uma ótima forma de começar facilmente. O Ollama oferece uma CLI para fazer o mesmo de forma semelhante. Mas se é novo nos modelos locais, eu começaria pelo LM Studio. Pode instalar qualquer um deles em _Install > AI_ no Menu Omarchy.

### A Skill do Omarchy

As skills de agente ajudam a IA a usar ferramentas específicas de uma forma específica, e o Omarchy vem com uma skill predefinida para personalizar o sistema. Como ajustar a sua configuração Hyprland, ajustar a barra, ou até criar um tema novo de raiz. Está ligada por symlink nos diretórios de skills do Claude Code (`~/.claude/skills`), do Codex (`~/.codex/skills`), do Pi (`~/.pi/agent/skills`), do Antigravity (`~/.gemini/config/skills`), do Hermes (`~/.hermes/skills` e cada `~/.hermes/profiles/*/skills`), e na localização genérica `~/.agents/skills`, por isso a maioria dos harnesses apanha-a automaticamente.

Mas deve tratar esta skill como experimental. Modelos diferentes vão usá-la com efeitos diferentes. É melhor correr primeiro em modo de plano, para ter uma ideia do que o agente gostaria de alterar. E depois esteja pronto para reverter alterações ou até invocar `omarchy reinstall configs`, se o agente fizer uma confusão de tudo.
