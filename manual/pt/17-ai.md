# IA

O Omarchy inclui lançadores para os agentes de programação abaixo sem escolher um predefinido por ti. Executa um comando para instalar a respetiva CLI na primeira utilização e, depois, autentica-te quando te for pedido. O Hermes e o OpenClaw são as exceções: nada é instalado para eles através da mise e, ao escolher qualquer um deles, é instalada a sua própria cópia com atualização automática, como explicam as _Aplicações de ambiente de trabalho_ abaixo.

### Instalar e atualizar agentes

Exceto o Hermes e o OpenClaw, estes agentes usam a instalação preguiçosa da mise: o primeiro lançamento instala a CLI e os lançamentos seguintes reutilizam-na. A mise também verifica, no máximo uma vez a cada quatro horas, se um agente instalado tem uma nova versão, mesmo antes de arrancar ou em segundo plano numa linha de comandos da shell. Se essa atualização falhar ou estiveres offline, é executada a versão instalada. O `omarchy update` atualiza os agentes instalados com o resto do Omarchy, e o `mup` atualiza apenas as ferramentas geridas pela mise.

O atualizador próprio de um agente, como `claude update`, `codex update` ou um botão de atualização numa aplicação, não atualiza a instalação gerida pela mise. O `codex update` falha, e o `claude update` pode comunicar sucesso enquanto instala uma cópia separada que a mise não acompanha. Se preferires usar o instalador e o atualizador nativos de um agente, adiciona-o a `disable_tools`; vê [Ferramentas CLI pré-instaladas](18-development-tools.md#preinstalled-cli-tools).

Para instalares todas as ferramentas preguiçosas configuradas antes de precisares delas, executa `mise install --include-lazy`. Isto inclui as outras ferramentas CLI predefinidas do Omarchy, bem como os agentes. Vê [Ferramentas CLI pré-instaladas](18-development-tools.md#preinstalled-cli-tools) para instalares uma única ferramenta ou usares a tua própria instalação.

O `grok` é instalado através do pacote `grok` próprio da mise, da mesma forma que o `claude` e o `codex`. Executa `grok` ou marca-o com uma estrela no painel de agentes. Evita o instalador `curl | bash` em x.ai. Esse caminho coloca uma segunda cópia em `~/.grok/bin`, coloca-a no início do `PATH` e sobrescreve o wrapper do Omarchy.

O `dsh` abre a sua UI no navegador em `127.0.0.1:3080`, com o diretório de lançamento como workspace predefinido. A sua UI no navegador não aceita um prompt inicial, por isso `omarchy agent prompt` abre-a com o prompt na área de transferência para colares. O Omarchy arranca-o com a predefinição de permissões sem aprovação da DeepSeek. O DeepSeek Harness carrega registos de sessão para a DeepSeek quando usas a API oficial do modelo; desativa isso em _Settings > General > Upload Session Log_ na sua UI no navegador. O feedback que lhe enviares também é carregado com a sessão, a menos que o arranques com `DSH_TELEMETRY_MODE=DISABLED`.

### O agente predefinido

Escolhe o teu agente predefinido com a estrela ao lado de um agente no painel de agentes, que está preenchida no predefinido, ou com `omarchy default agent <name>`, que também aceita qualquer harness sem uma linha ali. Se o agente ainda não estiver instalado, ao escolhê-lo ele é instalado primeiro, e também ganha um lançador próprio no lançador de aplicações, ao lado de Agent. Um Omarchy acabado de instalar convida-te a configurar um com uma notificação única, que abre o painel de agentes.

Escolher o Claude também tenta configurar a sua extensão de navegador para Chromium, Chrome, Brave, Brave Origin e Edge. A configuração da extensão aplica-se a todos os utilizadores e pode pedir a tua palavra-passe do sistema; cancelar ou uma instalação falhada da extensão não impede que o Claude seja selecionado e lançado. Reinicia o navegador, ativa a extensão se te for pedido e inicia sessão no Claude para acabares de a ligar. Executa `/chrome` no Claude para verificares a ligação. O Firefox e o Zen não suportam esta extensão. Se o Claude já era o teu predefinido antes de esta configuração ser adicionada, seleciona-o outra vez para instalares a extensão.

Depois de escolheres, `Super + Shift + Ctrl + A` lança o agente predefinido numa janela de terminal dedicada (ou abre o seletor se ainda não tiveres escolhido nenhum). Também o podes lançar diretamente numa tarefa com `omarchy agent prompt "Review this project"`. O Freebuff e o DeepSeek Harness não aceitam um prompt inicial, por isso abrem com o prompt na área de transferência para colares. Os agentes lançados desta forma funcionam sem supervisão nos respetivos modos de não parar para perguntar, por isso prepara-te para eles fazerem mesmo coisas! O MiniMax Code não tem um modo desses para as suas sessões interativas, por isso pede permissões como habitualmente. E como os agentes se recusam a memorizar confiança para o teu diretório home, os lançamentos a partir de `$HOME` arrancam antes em `~/Work`.

Também há atalhos de terminal: `a` executa o agente predefinido diretamente no terminal atual, enquanto `c`, `cx` e `cy` arrancam diretamente o OpenCode, o Claude Code e o Codex (também nos seus modos de aprovação automática). As mudanças de tema também se sincronizam com os agentes: o Claude Code, o Pi, o OpenCode e o Hermes (depois de o Omarchy o ter instalado) acompanham-te todos quando mudas o tema do Omarchy.

### As tuas instruções para os agentes

As regras pessoais para todos os agentes ficam em `~/.agents/AGENTS.md`, ao lado das skills partilhadas em `~/.agents/skills`. Abre-o com o ícone de documento ao lado do + no painel de agentes, ou com `omarchy agent instructions --edit`, que também o liga a cada harness que mantém o seu próprio ficheiro global: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` do Copilot, e por aí fora. O Crush e o Amp leem a ligação `~/.config/AGENTS.md`, enquanto o omp, o Kimi e o DeepSeek Harness leem `~/.agents/AGENTS.md` diretamente. Escolher um agente predefinido também cria a ligação. Um ficheiro de instruções que já tinhas torna-se o partilhado se ainda não havia nenhum; caso contrário, é guardado ao lado da ligação como `.bak`. Executa `omarchy agent instructions` para voltares a criar as ligações depois de instalares outro agente.

### O painel de agentes

A barra superior tem um ícone de agentes. Antes de configurares um agente, o painel oferece três formas de começar: iniciar sessão numa subscrição Claude, Codex, Grok, Gemini, Muse, Cursor ou Copilot, ou, em More, num plano de programação OpenCode Go, MiniMax, Synthetic ou Z.ai; pagar conforme o uso com Fireworks, OpenCode Zen e Go, OpenRouter ou, em More, DeepSeek ou qualquer outro fornecedor em que o OpenCode inicie sessão, todos executados no OpenCode; ou executar o melhor modelo para o teu computador, quando algum se adequa a ele. O primeiro que concluíres torna-se o teu agente predefinido, e o + no painel oferece os mesmos três mais tarde. Depois disso, o painel coloca todas as subscrições numa única página: cada agente e conta com o seu plano, um medidor para cada um dos seus limites de sessão de 5 horas e semanais com o tempo que falta até à reposição (passa o cursor por cima para veres a percentagem exata), ou o saldo pré-pago restante, sob uma linha que vai rodando pelo que usaste em todos eles, como os tokens desta semana e o teu modelo mais usado. Em _Make something cool_, oferece prompts iniciais para um novo tema, plugin, aplicação ou jogo que entregam a tarefa ao teu agente predefinido. As aplicações são construídas da forma como são construídas as próprias Hype, Monologue e Omacut do Omarchy, em C++ e Qt Quick, seguindo a skill de agente omarchy-make-app, e o compilador e os componentes Qt de que precisam já vêm instalados. Os jogos são uma única página three.js em `~/Games/vibes`, seguindo a skill de agente omarchy-make-game, e todos abrem a partir de um único lançador Game Vibes no tema atual; carregam o three.js a partir da web, por isso precisam de uma ligação para arrancar. Claude Code, Codex, Grok, Kimi, Cursor e a sua franquia Grok Bot, GitHub Copilot, Muse, Gemini (através do Antigravity) e Devin estão cobertos de origem com os seus limites, o Kimchi com o seu plano, créditos pré-pagos e orçamentos de despesa, e o Hermes, o Mistral Vibe e o Qwen Code mostram as suas sessões e tokens depois de os teres usado. Os planos e chaves de fornecedores que usas através do pi, do omp ou do opencode também aparecem: OpenCode Zen e Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan e Synthetic com os seus limites; OpenRouter e DeepSeek com os seus saldos pré-pagos; Fireworks com a sua despesa nos últimos 30 dias. Os tokens de modelos que executas no teu próprio hardware também contam para os totais; os próprios modelos têm um painel próprio, descrito em [Modelos locais](#local-models). Cada agente é contado uma vez, sob quem o fatura, independentemente de quantos harnesses uses para o conduzir.

Clica com o botão esquerdo no ícone da barra ou prime `Super + Ctrl + X` para abrires o painel, clica com o botão direito para lançares o teu agente predefinido e clica com o botão do meio para atualizares. Os registos de utilização por trás dele são regenerados a cada 15 minutos por `omarchy agent usage update`, e o painel pode até fundir a utilização das tuas outras máquinas através de uma pasta sincronizada. Vê o README em `$OMARCHY_PATH/shell/plugins/agents/` para veres todas as definições.

### Várias subscrições

Se pagares por mais do que um plano Claude, Codex ou Grok — um Max pessoal e um de trabalho, por exemplo — o Omarchy pode manter todos com sessão iniciada e alternar entre eles. Adiciona uma subscrição com o + no painel de agentes, que te guia ali mesmo, ou com `omarchy agent account add claude Work` (ou `codex`, ou `grok`). O mesmo + e comando iniciam sessão no Gemini (`gemini`) e no OpenCode (`opencode`), e guardam uma chave API do Fireworks (`fireworks`) ou da OpenRouter (`openrouter`) no OpenCode; o comando também inicia sessão no Copilot (`copilot`), no Cursor (`cursor`) e no Muse (`muse`). Esses mantêm um único início de sessão cada um. Instala a CLI se ela estiver em falta. A primeira conta de um fornecedor inicia sessão através do teu navegador normal, exatamente onde a CLI sempre procura. Todas as seguintes iniciam sessão através de uma janela privada, para que a conta em que o teu navegador já tem sessão iniciada não seja apanhada por engano; inicia aí sessão como a conta que estás a adicionar e fecha primeiro qualquer janela privada que já tenhas aberta. Nunca termines sessão na CLI para fazer isto: terminar sessão revoga o início de sessão guardado, e essa conta teria de ser adicionada novamente.

Para copiares os inícios de sessão das subscrições para outra máquina Omarchy por SSH, executa `omarchy agent account copy user@laptop`. O emissor fornece um recetor temporário quando o destino não tem nenhum instalado, para que máquinas Omarchy mais antigas possam receber contas sem uma atualização. Os recetores instalados têm precedência. Isto copia todas as subscrições Claude, Codex e Grok; adiciona nomes de fornecedores para as selecionares, como em `omarchy agent account copy laptop claude`. Os nomes das contas e os IDs de comando correspondem à origem, incluindo contas já presentes no destino. As contas de destino não relacionadas recebem um sufixo numérico se os seus nomes entrarem em conflito, e as definições, skills, plugins e histórico de conversas ficam locais em cada máquina.

As credenciais de destino existentes são mantidas. Uma conta de origem que já tenha sessão iniciada ali tem o nome sincronizado sem substituir as suas credenciais; as outras contas são adicionadas ao lado dela. Para substituíres as credenciais guardadas de contas correspondentes, usa `omarchy agent account copy --replace laptop claude` depois de fechares as sessões dessa conta no destino. Um destino novo também recebe a conta ativa e as preferências de alternância da origem; um destino já estabelecido mantém as suas.

As credenciais viajam através de SSH e são guardadas em ficheiros privados no destino, por isso copia apenas para máquinas em que confias. Isto é uma cópia única, não uma sincronização contínua. Os tokens de atualização do Codex podem ser rodados por outra máquina, deixando um início de sessão copiado a precisar de renovação; inícios de sessão separados continuam a ser a escolha mais fiável para uma utilização simultânea em várias máquinas. Vê as [orientações de autenticação de contas do Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Uma conta por fornecedor está ativa, e todas as novas sessões arrancam como ela: `cx`, `cy`, um simples `claude`, `codex` ou `grok`, qualquer coisa lançada através de `omarchy agent`, e scripts ou editores que encontram a CLI no `PATH`. Alterna com `omarchy agent account use work` (e volta com `omarchy agent account use main`), ou no painel, premindo o número de uma conta e depois `Enter` (ou clicando na sua estrela). As sessões Claude em execução também alternam, a partir da mensagem seguinte: todas as sessões Claude correm em `~/.claude`, que contém sempre o início de sessão da conta ativa. Uma sessão Claude iniciada na pasta própria de uma conta por um Omarchy mais antigo mantém esse início de sessão até fechar, por isso a alternância nomeia essas sessões e termina sozinha quando elas desaparecerem. As sessões Codex e Grok em execução ficam na conta com que arrancaram. O histórico de conversas, as definições, as skills e os plugins são partilhados entre contas, por isso `claude --continue` na mesma pasta retoma onde ficaste na nova conta.

Com mais do que uma conta, o painel mostra os limites de cada conta lado a lado, com uma estrela preenchida na que está em uso. O Omarchy notifica-te quando a conta ativa passa 95% de um limite, e clicar na notificação muda para a conta com mais margem. Nunca muda sozinho. Altera o limiar com `omarchy agent account threshold 90`. Se todas as contas estiverem acima do limiar, vais saber uma vez, juntamente com qual conta fica livre primeiro. Enquanto uma conta ativa estiver a menos de 15 pontos do seu limiar (80% na predefinição), os seus limites são verificados a cada três minutos, em vez de a cada 15.

`omarchy agent account list` mostra todas as contas e os seus limites mais recentes, `omarchy agent account remove work` esquece uma, e `omarchy agent account rename primary Hey` muda o nome a uma (ou clica no nome de uma conta no painel). Estes comandos funcionam nas contas do teu agente predefinido; para chegares ao outro fornecedor, nomeia-o primeiro, como em `omarchy agent account use codex side`. O início de sessão que já tinhas em `~/.claude` ou `~/.codex` é a conta _Main_. O do Codex fica onde está; o do Claude espera numa pasta própria enquanto outra conta está ativa. Uma conta deixada sem uso durante mais de cerca de oito horas pode mostrar _Sign-in required_; clica nela para iniciares sessão nessa conta outra vez diretamente no painel, ou muda para ela e inicia uma sessão, o que atualiza o início de sessão sozinho. Os servidores MCP que adicionas com `claude mcp add` chegam a todas as contas Claude, uma vez que todas correm em `~/.claude`; no Codex e no Grok, os servidores que tinhas quando uma conta foi adicionada acompanham-na, mas os posteriores só chegam à conta em que os adicionaste. O Claude Desktop mantém um início de sessão próprio, e as ferramentas Codex ou Grok configuradas com um caminho absoluto para um binário da CLI não seguem a alternância. Um `CLAUDE_CONFIG_DIR`, `CODEX_HOME` ou `GROK_HOME` explícito tem precedência sobre a conta selecionada.

### Diagnóstico de falhas

O Omarchy vigia o systemd-coredump para detetar falhas de processos. Depois de escolheres um agente predefinido, qualquer programa teu que faça um core dump faz aparecer uma notificação "Process crashed" — clica nela e a falha é entregue ao teu agente predefinido, juntamente com a skill omarchy-diagnose-crash do Omarchy, que guia o agente na determinação dos factos a partir do core dump e na decisão sobre se vale a pena reportar a falha upstream. Também a podes executar manualmente contra qualquer PID de `coredumpctl list` com `omarchy agent crash <pid>`.

A vigilância está ativada por predefinição. Desativa-a em _Trigger > Toggle > Crash Capture Off_ (ou com `omarchy toggle crash-capture`) e as notificações param; `omarchy agent crash <pid>` continua a funcionar manualmente.

As falhas também podem ser silenciadas programa a programa, que é o que o diagnóstico te oferece no fim. `omarchy crash mute hyprland` para as notificações só para esse programa, `omarchy crash mute hyprland off` volta a ativá-las, e `omarchy crash mute` sozinho lista o que silenciaste. Aceita o caminho do binário com a mesma facilidade com que aceita o nome, por isso `omarchy crash mute /usr/bin/hyprland` faz o mesmo. Coloca entre aspas um nome com um espaço, como em `omarchy crash mute 'Some App'`. Tudo o resto continua a notificar, e o programa silenciado continua a falhar — isto esconde o lembrete, não resolve nada.

### Aplicações de ambiente de trabalho

O menu _Install > AI_ também inclui algumas aplicações gráficas de IA: Amp Desktop, Antigravity Desktop, a aplicação de ambiente de trabalho do ChatGPT, a aplicação de ambiente de trabalho do Claude (a beta para Linux da Anthropic, com separadores Chat, Cowork e Claude Code), Grok Bot para conversar com os modelos da xAI, Herdr Desktop, Hermes Desktop, OpenClaw, a aplicação de ambiente de trabalho do Perplexity e T3 Code. O Grok Bot é a aplicação de chat de ambiente de trabalho. O agente de programação é o comando `grok`.

O Hermes Desktop é o que deves conhecer, porque uma máquina tem um Hermes, e é o da aplicação: o Hermes só é instalado através da aplicação, e o comando `hermes` que o agente predefinido executa é o da aplicação. Escolher o Hermes como agente predefinido instala o mesmo que a entrada _Install > AI_: o pacote e um runtime Hermes em `~/.hermes` configurado pelo instalador próprio do Hermes, o que demora alguns minutos na primeira vez. Esse runtime é o único Hermes que o comando `hermes` no terminal, o agente predefinido e a aplicação usam, e atualiza-se a si próprio com `hermes update`, em vez de estar à espera de uma versão do Omarchy. Instalá-lo também entrega ao Hermes o tema do Omarchy como uma skin chamada `omarchy`, que todas as superfícies do Hermes seguem à medida que mudas de tema; escolhe outra nas definições Appearance do Hermes ou com `/skin` se preferires que não o faça, e o Omarchy deixa essa escolha em paz. Remover a aplicação em _Remove > AI_ fecha primeiro o Hermes, gateway incluído, leva esse runtime com ele e mantém as tuas conversas, memórias e as skills que o Hermes escreveu para si próprio, a menos que digas o contrário: pergunta, com não como predefinição, se esses dados e as tuas definições de ligação também devem desaparecer.

A experiência de ambiente de trabalho do OpenClaw é a sua Control UI, que abre como uma aplicação web suportada pelo seu próprio gateway local. O OpenClaw vive em `~/.openclaw` e atualiza-se a si próprio: usa o botão "Update Gateway" da Control UI ou executa `openclaw update`, e o gateway reinicia na nova versão. O Omarchy só escolhe a versão a partir da qual uma instalação nova arranca. O OpenClaw também pode ser o teu agente predefinido: escolhê-lo com `omarchy default agent openclaw` configura essa mesma cópia em `~/.openclaw`, e o agente abre a UI de terminal do OpenClaw ligada ao seu gateway. Remover o OpenClaw em _Remove > AI_ leva o serviço gateway e a aplicação com ele e depois pergunta se `~/.openclaw` também deve desaparecer, uma vez que guarda as tuas conversas e credenciais, juntamente com o próprio OpenClaw e os runtimes de plugins que descarrega; a predefinição é mantê-lo, e instalar o OpenClaw outra vez volta a apanhá-lo.

O Herdr Desktop é a aplicação de ambiente de trabalho [Herdr](https://herdr.dev): espaços, separadores e painéis de terminais e agentes de programação que continuam a correr no seu núcleo quando fechas a janela. Vem do instalador próprio do Herdr, e não de um pacote, por isso vive em `~/.local/share/herdr-app`, traz o seu núcleo em `~/.local/bin/herdr-core` quando ainda não tens um, e atualiza ambos. Fica ao lado do comando `herdr` que o Omarchy fornece em `Super + Ctrl + Return`, em vez de o substituir, e recebe as teclas diretas desse comando: `Alt + Return` e `Alt + Shift + Return` dividem um painel para baixo ou para a direita, `Alt + Escape` fecha-o, `Ctrl + Alt + Arrow` move entre painéis, `Alt + 1..9` e `Alt + Left/Right` escolhem um separador, e `Alt + Up/Down` movem entre espaços. `Ctrl + 1..9` escolhe um espaço e `Alt + Shift + Up/Down` percorre os agentes. As teclas de prefixo `Ctrl + Space` ficam só no terminal, uma vez que a aplicação não consegue manter uma tecla Ctrl simples para uma sequência. O Omarchy escreve estas em `~/.config/herdr-app/keys.json`, e `omarchy-refresh-herdr-app` repõe-nas. Instalá-lo escolhe o tema Omarchy do Herdr, que a partir daí segue o teu tema Omarchy. O Herdr mantém um tema para o modo claro e um para o modo escuro, por isso, depois de alternares entre um tema Omarchy escuro e um claro, escolhe Omarchy no seletor de temas do Herdr mais uma vez para o outro modo.

O T3 Code corre a partir da sua versão oficial AppImage em `~/.local/share/t3code`, e não a partir de um pacote, por isso atualiza-se a si próprio. Instalá-lo pergunta se queres arrancar no canal Stable ou Nightly; muda mais tarde nas definições do T3 Code. Os teus tópicos e definições vivem em `~/.t3`, e remover o T3 Code em _Remove > AI_ leva-os com ele.

### Modelos locais

Executa um modelo aberto na tua própria máquina para os teus agentes de programação. Os teus prompts e código ficam na máquina; nada do que é enviado ao modelo sai dela. Começa com:

```bash
omarchy models use best text
```

Isto configura o melhor modelo de texto para esta máquina, do tipo que os teus agentes usam. Os modelos de imagem, vídeo e música têm um melhor próprio: `omarchy models use best image`, `video` ou `music`. Executa `omarchy models use best` para veres a escolha de cada tipo para esta máquina.

Ou abre o painel de modelos locais a partir do seu ícone de brilhos na barra superior, ao lado do ícone de agentes, ou com Super + Ctrl + Alt + X, e escolhe +. O ícone aparece quando um modelo se adequa a esta máquina. O Podman, que executa os modelos, vem com o Omarchy, tal como o toolkit de contentores da NVIDIA numa máquina NVIDIA, que lhes dá a GPU; se algum deles estiver em falta, a primeira configuração instala-o. O Omarchy escolhe então o modelo recomendado para esta máquina, descarrega-o e arranca-o. Espera uma descarga de dezenas de GB e a maior parte da memória da máquina em uso enquanto o modelo corre: o Flash Next usa cerca de 100 GiB com o seu contexto completo de 256K. Se outros modelos ocuparem a memória de que ele precisa, é configurado parado, pronto para arrancar quando parares um. O modelo para ao terminar sessão; para-o tu quando precisares da memória para outra coisa.

`omarchy models list` mostra as opções e explica porque é que algumas não se adequam. Para configurares outro, executa `omarchy models use <recipe>`. Hoje, `qwen3.8-flash-next-gufo` e `qwen3.8-27b-gufo` estão disponíveis para máquinas Strix Halo de 128 GB; o 27B usa cerca de 40 GiB, por isso deixa espaço para outro trabalho. Num portátil de 64 GB com a Arc B390 da Intel, `qwen3.6-35b-a3b-llamacpp` corre em cerca de 30 GiB. Novas receitas e recomendações chegam com `omarchy update`, através do pacote.

Cada modelo que configuras ganha a sua própria linha no painel de modelos locais: reproduzir para o arrancar, pausar para o parar e libertar a sua memória, e o botão de terminal para abrires o teu agente nele. No topo, uma barra mostra como a memória da máquina está dividida entre o próprio Omarchy (o sistema e as tuas aplicações), cada modelo em execução e o que está livre. Aponta para um modelo parado e a barra mostra se ele cabe, ou quanto lhe falta. Vários podem correr ao mesmo tempo quando cabem juntos na memória; se um não couber, o Omarchy diz qual modelo em execução deves parar. Arrasta as linhas pelo seu logótipo para as reordenares, e prime Delete numa linha selecionada para removeres um modelo e a sua descarga.

Cada modelo de programação que configuras também ganha a sua própria entrada no lançador de aplicações, sob o nome do modelo e com o logótipo do seu criador, da forma como iniciar sessão no Claude, Codex ou Grok adiciona uma. Abre o teu agente nesse modelo, e arranca o modelo primeiro se ele não estiver a correr: o terminal mostra-o a carregar e entrega ao agente quando ele estiver pronto. Remover um modelo remove a sua entrada.

Nem todos os modelos são para programação. Os modelos de imagem, vídeo e música abrem antes no Fantasi, a aplicação do Omarchy para fazer imagens, vídeo e música com um modelo a correr nesta máquina, escolhidos ali ou na sua linha no painel de modelos locais.

Um modelo continua a correr exatamente como foi configurado, por isso uma atualização do Omarchy nunca reinicia um por baixo dos teus agentes. Quando o Omarchy tem um runtime mais recente ou pesos mais recentes para um modelo que tens configurado, a sua linha mostra um botão de atualização: prime-o e o modelo é configurado outra vez em segundo plano, descarregando apenas o que mudou, e reinicia na nova versão. Um modelo que estava parado fica parado. `omarchy models update` faz o mesmo para todos os modelos a partir de um terminal.

A partir da linha de comandos, `omarchy models start <recipe>` e `omarchy models stop <recipe>` fazem o mesmo, `omarchy models status` mostra todos os modelos, e `omarchy agent --local-model <recipe>` abre esse modelo no pi, seja qual for o teu agente predefinido. Para fazeres do teu modelo local aquilo que a tecla de atalho do agente, a consola Quake e _Make something_ abrem, executa `omarchy default agent local` ou marca com uma estrela um modelo em execução no painel de agentes. O pi também lista todos os modelos que configuraste, e os das máquinas com que emparelhaste, no seu próprio seletor de modelos, por isso um simples `pi` também lhes chega. Qualquer cliente compatível com OpenAI também se pode ligar: `status` mostra o endereço de cada modelo (o primeiro é `http://127.0.0.1:11435/v1`), o nome da receita é o modelo, e a chave está em `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` apaga um modelo e as descargas que nenhum outro modelo usa.

Os runtimes de terceiros estão identificados com o seu editor. O Omarchy executa todos os modelos sem acesso à rede.

### LLM locais

O Omarchy recomenda duas formas de executar modelos LLM locais: LM Studio e Ollama. O LM Studio fornece uma interface gráfica para encontrar modelos de pesos abertos, instalá-los e executá-los. É uma ótima forma de começar facilmente. O Ollama oferece uma CLI para fazer o mesmo. Mas se és novo nos modelos locais, eu começava pelo LM Studio. Podes instalar qualquer um deles em _Install > AI_ no Menu Omarchy.

### As skills do Omarchy

As skills de agente ajudam a IA a usar ferramentas específicas de uma forma específica, e o Omarchy inclui sete delas. A skill omarchy cobre a personalização do sistema, como ajustar a tua configuração do Hyprland ou a barra. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app e omarchy-make-game cobrem criar algo novo, omarchy-contribute cobre reportar um erro ou enviar uma correção upstream, e omarchy-diagnose-crash trabalha sobre o core dump de uma falha. Estão ligadas por symlink aos diretórios de skills do Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` e cada `~/.hermes/profiles/*/skills`) e à localização genérica `~/.agents/skills`, por isso a maioria dos harnesses apanha-as automaticamente. Uma pasta de skill tua com o mesmo nome tem precedência.

Mas deves tratar estas skills como experimentais. Modelos diferentes vão usá-las com efeitos diferentes. É melhor correr primeiro em modo de plano, para teres uma ideia do que o agente gostaria de mudar. E depois estar pronto para reverter alterações ou até invocar `omarchy reinstall configs`, se o agente fizer uma confusão com tudo.
