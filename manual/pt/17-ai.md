# IA

O Omarchy inclui lançadores para os agentes de programação abaixo sem escolher um predefinido por si. Execute um comando para instalar a respetiva CLI na primeira utilização e, em seguida, autentique-se quando lhe for pedido. Hermes é a exceção: nada é instalado para ele na primeira utilização e, se o escolher, é o Hermes Desktop que é instalado, como _Aplicações de ambiente de trabalho_ abaixo explica.

### Instalar e atualizar agentes

Exceto o Hermes, estes agentes utilizam a instalação lazy do mise: o primeiro arranque instala a CLI e os arranques posteriores reutilizam-na. O mise também verifica, no máximo uma vez a cada quatro horas, se um agente instalado tem uma nova versão, imediatamente antes de o iniciar ou em segundo plano num prompt da shell. Se essa atualização falhar ou estiver offline, é executada a versão instalada. `omarchy update` atualiza os agentes instalados com o restante do Omarchy, e `mup` atualiza apenas as ferramentas geridas pelo mise.

O programa de atualização do próprio agente, como `claude update`, `codex update` ou um botão de atualização numa aplicação, não atualiza a instalação gerida pelo mise. `codex update` falha, e `claude update` pode comunicar sucesso enquanto instala uma cópia separada que o mise não acompanha. Se preferir utilizar o instalador e o programa de atualização nativos de um agente, adicione-o a `disable_tools`; consulte [Ferramentas CLI pré-instaladas](18-development-tools.md#preinstalled-cli-tools).

Para instalar todas as ferramentas lazy configuradas antes de precisar delas, execute `mise install --include-lazy`. Isto inclui as outras ferramentas CLI predefinidas do Omarchy, bem como os agentes. Consulte [Ferramentas CLI pré-instaladas](18-development-tools.md#preinstalled-cli-tools) para instalar uma única ferramenta ou utilizar a sua própria instalação.

O `grok` é instalado através do pacote `grok` oficial do mise, da mesma forma que `claude` e `codex`. Execute `grok`, ou escolha-o em _Agent > Harness_. Ignore o instalador `curl | bash` em x.ai. Esse caminho coloca uma segunda cópia em `~/.grok/bin`, coloca-a no início de `PATH` e substitui o wrapper do Omarchy.

O `dsh` abre a sua interface de navegador em `127.0.0.1:3080`, com o diretório de arranque como área de trabalho predefinida. A sua interface de navegador não aceita um prompt inicial, por isso `omarchy agent prompt` abre-a com o prompt na sua área de transferência para colar. O Omarchy inicia-o com a predefinição de permissões sem aprovação da DeepSeek. O DeepSeek Harness envia registos de sessão para a DeepSeek quando utiliza a API oficial do modelo; desative isso em _Settings > General > Upload Session Log_ na sua interface de navegador. Os comentários que lhe enviar também são enviados com a sessão, a menos que o inicie com `DSH_TELEMETRY_MODE=DISABLED`.

### O agente predefinido

Escolha o seu agente predefinido com `omarchy default agent <name>` ou em _Agent > Harness_ no Menu Omarchy (`Super + Space`). Se o agente ainda não estiver instalado, ao escolhê-lo este é instalado primeiro. Um Omarchy acabado de instalar convida-o a fazer esta escolha com uma notificação única.

Escolher o Claude tenta também configurar a sua extensão de navegador para Chromium, Chrome, Brave, Brave Origin e Edge. A configuração da extensão aplica-se a todos os utilizadores e pode pedir a sua palavra-passe do sistema; cancelar ou uma instalação falhada da extensão continua a selecionar e a iniciar o Claude. Reinicie o navegador, ative a extensão se lhe for pedido e inicie sessão no Claude para concluir a ligação. Execute `/chrome` no Claude para verificar a ligação. O Firefox e o Zen não suportam esta extensão. Se o Claude já era o seu agente predefinido antes de esta configuração ter sido adicionada, selecione-o novamente para instalar a extensão.

Depois de escolher, `Super + Shift + Ctrl + A` inicia o agente predefinido numa janela de terminal dedicada (ou abre o seletor se ainda não tiver escolhido). Também pode iniciá-lo diretamente numa tarefa com `omarchy agent prompt "Review this project"`. O Freebuff e o DeepSeek Harness não aceitam um prompt inicial, por isso abrem com o prompt na sua área de transferência para colar. Os agentes iniciados desta forma funcionam sem supervisão nos respetivos modos de não parar para perguntar, por isso prepare-se para que façam coisas a sério! O MiniMax Code não tem um modo desses para as suas sessões interativas, por isso pede permissões como habitualmente. E, como os agentes se recusam a memorizar a confiança para o seu diretório pessoal, os arranques a partir de `$HOME` começam antes em `~/Work`.

Também há atalhos de terminal: `a` executa o agente predefinido diretamente no terminal atual, enquanto `c`, `cx` e `cy` iniciam diretamente o OpenCode, o Claude Code e o Codex (também nos respetivos modos de aprovação automática). As alterações de tema também são sincronizadas com os agentes: Claude Code, Pi, OpenCode e Hermes (depois de o Omarchy o ter instalado) acompanham todos quando muda o tema do Omarchy.

### As suas instruções para os agentes

As regras pessoais para todos os agentes vão para `~/.agents/AGENTS.md`, junto às competências partilhadas em `~/.agents/skills`. Abra-o em _Agent > Instructions_, que também o liga a cada harness que mantém o seu próprio ficheiro global: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, o `~/.copilot/copilot-instructions.md` do Copilot, e assim por diante. O Crush e o Amp leem a ligação `~/.config/AGENTS.md`, enquanto o omp, o Kimi e o DeepSeek Harness leem `~/.agents/AGENTS.md` diretamente. Escolher um agente predefinido também cria a ligação para ele. Um ficheiro de instruções que já tinha passa a ser o partilhado se ainda não existia nenhum; caso contrário, é mantido junto à ligação como `.bak`. Execute `omarchy agent instructions` para voltar a criar as ligações depois de instalar outro agente.

### O painel de agentes

A barra superior tem um ícone de agentes. Antes de ter configurado um agente, o seu painel guia-o através do início de sessão no Claude, Codex ou Grok, e o primeiro passa a ser o seu agente predefinido. Depois disso, o painel coloca todas as subscrições numa única página: cada agente e conta com o seu plano, um medidor para cada um dos seus limites de sessão de 5 horas e semanais com o tempo até ser reposto (passe o cursor por cima para ver a percentagem exata), ou o saldo pré-pago restante, sob uma linha que vai rodando pelo que utilizou em todos eles, como os tokens desta semana e o modelo que mais utilizou. Em _Make something_, oferece prompts iniciais para um novo tema, plugin, aplicação ou jogo que entregam a tarefa ao seu agente predefinido. As aplicações são construídas da forma como são construídas as próprias Hype, Monologue e Omacut do Omarchy, em C++ e Qt Quick, seguindo a competência de agente omarchy-make-app, e o compilador e os componentes Qt de que precisam já vêm instalados. Os jogos são uma única página three.js em `~/Games/vibes`, seguindo a competência de agente omarchy-make-game, e todos abrem a partir de um único lançador Game Vibes no tema atual; carregam o three.js da Web, por isso precisam de uma ligação para arrancar. Claude Code, Codex, Grok, Kimi, Cursor e o seu limite incluído do Grok Bot, GitHub Copilot, Muse, Antigravity, Kimchi e Devin estão abrangidos de origem com os seus limites, e Hermes, Mistral Vibe e Qwen Code mostram as suas sessões e tokens depois de os ter utilizado. Os planos e chaves de fornecedores que utiliza através de pi, omp ou opencode também aparecem: OpenCode Zen e Go, o Z.ai GLM Coding Plan, Ollama Cloud, o MiniMax Token Plan e Synthetic com os seus limites; Fireworks, OpenRouter e DeepSeek com os seus saldos pré-pagos; e os modelos que executa no seu próprio hardware em Local models. Cada agente é contado uma única vez, sob quem o fatura, independentemente de quantos harnesses utilizar para o usar.

Clique com o botão esquerdo no ícone da barra para abrir o painel e com o botão direito para iniciar o seu agente predefinido. Os registos de utilização por trás dele são regenerados a cada 15 minutos por `omarchy agent usage-update`, e o painel pode até juntar a utilização das suas outras máquinas através de uma pasta sincronizada. Consulte o README em `$OMARCHY_PATH/shell/plugins/agents/` para ver todas as definições.

### Várias subscrições

Se paga mais do que um plano Claude, Codex ou Grok — um Max pessoal e um de trabalho, por exemplo — o Omarchy pode manter todos com sessão iniciada e alternar entre eles. Adicione uma subscrição com o + no painel de agentes, que o guia logo ali, ou com `omarchy agent account add claude Work` (ou `codex`, ou `grok`). Instala a CLI se esta estiver em falta. A primeira conta de um fornecedor inicia sessão através do seu navegador normal, exatamente onde a CLI sempre procura. Todas as seguintes iniciam sessão através de uma janela privada, para que a conta em que o seu navegador já tem sessão iniciada não seja escolhida por engano; inicie aí sessão como a conta que está a adicionar e feche primeiro qualquer janela privada que já tenha aberta. Nunca termine sessão na CLI para fazer isto: terminar sessão revoga o início de sessão guardado e essa conta teria de ser adicionada novamente.

Para copiar os inícios de sessão das suas subscrições para outra máquina Omarchy por SSH, execute `omarchy agent account copy user@laptop`. O emissor fornece um recetor temporário quando o destino não tem um instalado, para que máquinas Omarchy mais antigas possam receber contas sem uma atualização. Os recetores instalados têm precedência. Isto copia todas as subscrições Claude, Codex e Grok; adicione nomes de fornecedores para as selecionar, como em `omarchy agent account copy laptop claude`. Os nomes de conta e os IDs de comando correspondem à origem, incluindo contas já presentes no destino. Contas de destino não relacionadas recebem um sufixo numérico se os seus nomes entrarem em conflito, e as definições, competências, plugins e histórico de conversas permanecem locais em cada máquina.

As credenciais de destino existentes são mantidas. Uma conta de origem que já tenha sessão iniciada lá vê o seu nome sincronizado sem substituir as suas credenciais; as outras contas são adicionadas ao lado dela. Para substituir credenciais guardadas de contas correspondentes, utilize `omarchy agent account copy --replace laptop claude` depois de fechar as sessões dessa conta no destino. Um destino novo também recebe a conta ativa e as preferências de alternância da origem; um destino já estabelecido mantém as suas.

As credenciais viajam por SSH e são guardadas em ficheiros privados no destino, por isso copie apenas para máquinas em que confia. Isto é uma cópia única, não uma sincronização contínua. Os tokens de atualização do Codex podem ser rodados por outra máquina, deixando um início de sessão copiado a precisar de renovação; inícios de sessão separados continuam a ser a escolha mais fiável para utilização simultânea em várias máquinas. Consulte o [guia de autenticação de contas do Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Está ativa uma conta por fornecedor e todas as novas sessões começam como ela: `cx`, `cy`, um simples `claude`, `codex` ou `grok`, tudo o que for iniciado através de `omarchy agent` e scripts ou editores que encontrem a CLI em `PATH`. Alterne com `omarchy agent account use work` (e volte com `omarchy agent account use main`), ou no painel premindo o número de uma conta e depois `Enter` (ou clicando no seu botão Use). As sessões Claude em execução também mudam, a partir da mensagem seguinte: todas as sessões Claude funcionam em `~/.claude`, que contém sempre o início de sessão da conta ativa. Uma sessão Claude iniciada na pasta própria de uma conta por um Omarchy mais antigo mantém esse início de sessão até sair, por isso a mudança indica essas sessões e termina sozinha quando elas desaparecerem. As sessões Codex e Grok em execução permanecem na conta com que começaram. O histórico de conversas, as definições, as competências e os plugins são partilhados entre contas, por isso `claude --continue` na mesma pasta continua onde ficou na nova conta.

Com mais do que uma conta, o painel mostra os limites de cada conta lado a lado, com a ativa assinalada. Por predefinição, o Omarchy avisa-o quando a conta ativa ultrapassa 95% de um limite, e clicar na notificação muda para a conta com mais margem. Passe o cursor sobre a linha de uma conta no painel e clique em Autoswitch, que aparece ao lado de Use (ou prima `m`), ou execute `omarchy agent account mode auto`, para que mude sozinho; enquanto estiver ativo, Autoswitch ocupa o lugar de Use, e clicar nele novamente volta ao modo de aviso. Adicione um número para alterar o limiar, como em `omarchy agent account mode auto 90`. Se todas as contas estiverem acima do limiar, será avisado uma única vez, juntamente com a indicação de qual conta fica livre primeiro. Enquanto uma conta ativa estiver a menos de 15 pontos do seu limiar (80% na predefinição), os seus limites são verificados a cada três minutos em vez de a cada 15.

`omarchy agent account list` mostra todas as contas e os seus limites mais recentes, `omarchy agent account remove work` esquece uma, e `omarchy agent account rename primary Hey` muda o nome de uma (ou clique no nome de uma conta no painel). Estes comandos funcionam nas contas do seu agente predefinido; para chegar ao outro fornecedor, indique-o primeiro, como em `omarchy agent account use codex side`. O início de sessão que já tinha em `~/.claude` ou `~/.codex` é a conta _Main_. O do Codex permanece onde está; o do Claude aguarda numa pasta própria enquanto outra conta estiver ativa. Uma conta que fique sem utilização durante mais de cerca de oito horas pode mostrar _Sign-in required_; clique nela para voltar a iniciar sessão nessa conta diretamente no painel, ou mude para ela e inicie uma sessão, o que atualiza o início de sessão sozinho. Os servidores MCP que adicionar com `claude mcp add` chegam a todas as contas Claude, uma vez que todas funcionam em `~/.claude`; no Codex e no Grok, os servidores que tinha quando uma conta foi adicionada acompanham-na, mas os posteriores só chegam à conta em que os adicionou. O Claude Desktop mantém um início de sessão próprio, e as ferramentas Codex ou Grok configuradas com um caminho absoluto para um binário CLI não acompanham a mudança. Um `CLAUDE_CONFIG_DIR`, `CODEX_HOME` ou `GROK_HOME` explícito tem precedência sobre a conta selecionada.

### Diagnóstico de falhas

O Omarchy monitoriza o systemd-coredump quanto a falhas de processos. Quando algo faz segfault, recebe uma notificação "Process crashed" — clique nela e a falha é entregue ao seu agente predefinido juntamente com a competência diagnose-crash do Omarchy, que guia o agente na determinação dos factos a partir do core dump e na decisão sobre se vale a pena reportar a falha a montante. Também pode executá-la manualmente contra qualquer PID de `coredumpctl list` com `omarchy agent crash <pid>`.

A monitorização está ativa por predefinição. Desative-a em _Trigger > Toggle > Crash Capture_ (ou com `omarchy toggle crash-capture`) e as notificações param; `omarchy agent crash <pid>` continua a funcionar manualmente.

As falhas também podem ser silenciadas um programa de cada vez, que é o que o diagnóstico lhe oferece no final. `omarchy crash mute hyprland` para as notificações apenas para esse programa, `omarchy crash mute hyprland off` repõe-nas, e `omarchy crash mute` por si só lista o que silenciou. Aceita o caminho do binário tão bem como o seu nome, por isso `omarchy crash mute /usr/bin/hyprland` faz o mesmo. Coloque entre aspas um nome com um espaço, como em `omarchy crash mute 'Some App'`. Tudo o resto continua a notificar, e o programa silenciado continua a falhar — isto esconde o lembrete, não corrige nada.

### Aplicações de ambiente de trabalho

O menu _Install > AI_ também inclui algumas aplicações gráficas de IA: a aplicação de ambiente de trabalho do ChatGPT, a aplicação de ambiente de trabalho do Claude (a versão beta para Linux da Anthropic, com separadores Chat, Cowork e Claude Code), o Grok Bot para conversar com os modelos da xAI, Herdr Desktop, Hermes Desktop, OpenClaw, a aplicação de ambiente de trabalho da Perplexity e T3 Code. O Grok Bot é a aplicação de conversação para ambiente de trabalho. O agente de programação é o comando `grok`.

O Hermes Desktop é o que deve conhecer, porque uma máquina tem um único Hermes, e é o da aplicação: o Hermes só é alguma vez instalado através da aplicação, e o comando `hermes` que o agente predefinido executa é o da aplicação. Escolher o Hermes como agente predefinido instala o mesmo que a entrada _Install > AI_: o pacote e um runtime Hermes em `~/.hermes` configurado pelo próprio instalador do Hermes, o que demora alguns minutos na primeira vez. Esse runtime é o único Hermes que o comando `hermes` no terminal, o agente predefinido e a aplicação utilizam, e atualiza-se a si próprio com `hermes update` em vez de esperar por uma versão do Omarchy. Instalá-lo também entrega ao Hermes o tema do Omarchy como uma skin chamada `omarchy`, que todas as superfícies do Hermes seguem quando muda de tema; escolha outra nas definições Appearance do Hermes ou com `/skin` se preferir que não o faça, e o Omarchy deixa essa escolha em paz. Remover a aplicação em _Remove > AI_ fecha primeiro o Hermes, gateway incluído, leva esse runtime com ele e mantém as suas conversas, memórias e as competências que o Hermes escreveu para si próprio, a menos que lhe diga o contrário: pergunta, com não por predefinição, se esses dados e as suas definições de ligação também devem ser removidos.

A experiência de ambiente de trabalho do OpenClaw é a sua Control UI, que abre como uma aplicação Web suportada pelo seu próprio gateway local. O OpenClaw vive em `~/.openclaw` e atualiza-se a si próprio: utilize o botão "Update Gateway" da Control UI ou execute `openclaw update`, e o gateway reinicia na nova versão. O Omarchy apenas escolhe a versão a partir da qual uma instalação nova começa. Remover o OpenClaw em _Remove > AI_ leva o serviço gateway e a aplicação com ele e depois pergunta se `~/.openclaw` também deve ser removido, uma vez que guarda as suas conversas e credenciais juntamente com o próprio OpenClaw e os runtimes de plugins que ele transfere; a predefinição mantém-no, e instalar o OpenClaw novamente volta a utilizá-lo.

O Herdr Desktop é a aplicação de ambiente de trabalho [Herdr](https://herdr.dev): espaços, separadores e painéis de terminais e agentes de programação que continuam a funcionar no seu núcleo quando fecha a janela. Vem do próprio instalador do Herdr e não de um pacote, por isso vive em `~/.local/share/herdr-app`, traz o seu núcleo em `~/.local/bin/herdr-core` quando ainda não tem um, e atualiza-se a si próprio e a ele. Fica ao lado do comando `herdr` que o Omarchy disponibiliza em `Super + Ctrl + Return` em vez de o substituir, e recebe as teclas diretas desse comando: `Alt + Return` e `Alt + Shift + Return` dividem um painel para baixo ou para a direita, `Alt + Escape` fecha-o, `Ctrl + Alt + Arrow` move entre painéis, `Alt + 1..9` e `Alt + Left/Right` escolhem um separador, e `Alt + Up/Down` movem entre espaços. `Ctrl + 1..9` escolhe um espaço e `Alt + Shift + Up/Down` percorre os agentes. As teclas de prefixo `Ctrl + Space` permanecem apenas no terminal, uma vez que a aplicação não consegue manter uma tecla Ctrl simples para uma sequência. O Omarchy escreve estas teclas para `~/.config/herdr-app/keys.json`, e `omarchy-refresh-herdr-app` repõe-nas. Instalá-lo escolhe o tema Omarchy do Herdr, que a partir daí segue o seu tema Omarchy. O Herdr mantém um tema para o modo claro e um para o modo escuro, por isso, depois de alternar entre um tema Omarchy escuro e um claro, escolha novamente Omarchy no seletor de temas do Herdr para o outro modo.

O T3 Code funciona a partir da sua versão AppImage oficial em `~/.local/share/t3code` e não de um pacote, por isso atualiza-se a si próprio. Instalá-lo pergunta se deve começar no canal Stable ou Nightly; mude mais tarde nas definições do T3 Code. As suas conversas e definições vivem em `~/.t3`, e remover o T3 Code em _Remove > AI_ leva-as com ele.

### Modelos locais

Execute um modelo aberto na sua própria máquina para os seus agentes de programação. Os seus prompts e código permanecem na máquina; nada do que é enviado ao modelo sai dela. Comece com:

```bash
omarchy agent local use best
```

Ou, no painel de agentes na barra superior, escolha + e depois Local AI, que aparece quando um modelo cabe nesta máquina. Na primeira vez, isto instala o Podman, que executa os modelos e, numa máquina NVIDIA, o kit de ferramentas de contentores da NVIDIA, que lhes dá acesso à GPU. Em seguida, o Omarchy escolhe o modelo recomendado para esta máquina, transfere-o e inicia-o. Conte com uma transferência de dezenas de GB e com a maior parte da memória da máquina em utilização enquanto o modelo funciona: o Flash Next utiliza cerca de 100 GiB com o seu contexto completo de 256K. Se outros modelos ocuparem a memória de que precisa, é configurado parado, pronto para arrancar quando parar um deles. O modelo para ao terminar sessão; pare-o por si quando precisar da memória para outra coisa.

`omarchy agent local list` mostra as opções e explica por que algumas não cabem. Para configurar outro, execute `omarchy agent local use <recipe>`. Atualmente, `qwen3.8-flash-next-gufo` e `qwen3.8-27b-gufo` estão disponíveis para máquinas Strix Halo de 128 GB; o 27B ocupa cerca de 40 GiB, por isso deixa espaço para outro trabalho. Num portátil de 64 GB com Arc B390 da Intel, `qwen3.6-35b-a3b-llamacpp` funciona em cerca de 30 GiB. Novas receitas e recomendações chegam com `omarchy update`, através do pacote.

Cada modelo que configurar recebe a sua própria linha no painel de agentes, junto às suas subscrições: reproduzir para o iniciar, pausa para o parar e libertar a sua memória, e o botão de terminal para abrir o seu agente nele. Vários podem funcionar ao mesmo tempo quando cabem juntos na memória; se um não couber, o Omarchy indica que modelo em execução deve parar. Arraste as linhas para as reordenar e prima Delete numa linha selecionada para remover um modelo e a sua transferência.

Cada modelo que configurar também recebe a sua própria entrada no lançador de aplicações, com o nome do modelo e o logótipo do seu fabricante, da mesma forma que iniciar sessão no Claude, Codex ou Grok adiciona uma. Abre o seu agente nesse modelo e inicia primeiro o modelo se este não estiver a funcionar: o terminal mostra-o a carregar e entrega-o ao agente quando estiver pronto. Remover um modelo remove a sua entrada.

Um modelo continua a funcionar exatamente como foi configurado, por isso uma atualização do Omarchy nunca reinicia um por baixo dos seus agentes. Quando o Omarchy tiver um runtime mais recente ou pesos mais recentes para um modelo que configurou, a sua linha mostra um botão de atualização: prima-o e o modelo é configurado novamente em segundo plano, transferindo apenas o que mudou, e reinicia na nova versão. Um modelo que estava parado permanece parado. `omarchy agent local update` faz o mesmo para todos os modelos a partir de um terminal.

A partir da linha de comandos, `omarchy agent local start <recipe>` e `omarchy agent local stop <recipe>` fazem o mesmo, `omarchy agent local status` mostra todos os modelos, e `omarchy agent --local` abre o seu agente predefinido no último modelo que iniciou. pi, OpenCode e Qwen Code podem utilizar um; com qualquer outro predefinido, abre no pi. O pi também lista todos os modelos que configurou, e os de máquinas com que emparelhou, no seu próprio seletor de modelos, por isso um simples `pi` também chega a eles. Qualquer cliente compatível com OpenAI também se pode ligar: `status` mostra o endereço de cada modelo (o primeiro é `http://127.0.0.1:11435/v1`), o nome da receita é o modelo e a chave está em `~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` elimina um modelo e as transferências que nenhum outro modelo utiliza.

Os runtimes de terceiros estão etiquetados com o seu editor. O Omarchy executa todos os modelos sem acesso à rede.

### LLM locais

O Omarchy recomenda duas formas de executar modelos LLM locais: LM Studio e Ollama. O LM Studio fornece uma interface gráfica para encontrar modelos de pesos abertos, instalá-los e executá-los. É uma ótima forma de começar facilmente. O Ollama oferece uma CLI para fazer o mesmo de forma semelhante. Mas, se é novo nos modelos locais, eu começaria pelo LM Studio. Pode instalar qualquer um deles em _Install > AI_ no Menu Omarchy.

### A Skill do Omarchy

As competências de agente ajudam a IA a utilizar ferramentas específicas de uma forma específica, e o Omarchy vem com uma competência predefinida para adaptar o sistema. Como ajustar a sua configuração do Hyprland, ajustar a barra ou até criar um tema novo de raiz. Está ligada por symlink aos diretórios de competências do Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` e cada `~/.hermes/profiles/*/skills`) e à localização genérica `~/.agents/skills`, por isso a maioria dos harnesses a deteta automaticamente.

Mas deve tratar esta competência como experimental. Modelos diferentes irão utilizá-la com efeitos diferentes. É melhor executar primeiro em modo de plano, para ter uma ideia do que o agente gostaria de alterar. E depois esteja pronto para reverter alterações ou até para invocar `omarchy reinstall configs`, se o agente desorganizar tudo.
