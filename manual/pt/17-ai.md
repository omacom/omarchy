# IA

O Omarchy inclui lançadores para os agentes de programação abaixo sem escolher um predefinido por si. Execute um comando para instalar a respetiva CLI na primeira utilização e, em seguida, autentique-se quando lhe for pedido. O Hermes é a exceção: nada é instalado para ele na primeira utilização, e escolhê-lo instala o Hermes Desktop, como _Aplicações de ambiente de trabalho_ abaixo explica.

### Instalar e atualizar agentes

Exceto o Hermes, estes agentes utilizam a instalação preguiçosa do mise: o primeiro arranque instala a CLI, e os arranques seguintes reutilizam-na. O mise também verifica, no máximo uma vez a cada quatro horas, se um agente instalado tem uma nova versão, imediatamente antes de o iniciar ou em segundo plano numa linha de comandos da shell. Se essa atualização falhar ou estiver offline, a versão instalada é executada. `omarchy update` atualiza os agentes instalados com o resto do Omarchy, e `mup` atualiza apenas as ferramentas geridas pelo mise.

O atualizador próprio de um agente, como `claude update`, `codex update` ou um botão de atualização numa aplicação, não atualiza a instalação gerida pelo mise. `codex update` falha, e `claude update` pode indicar sucesso ao instalar uma cópia separada que o mise não acompanha. Se preferir utilizar o instalador e o atualizador nativos de um agente, adicione-o a `disable_tools`; consulte [Ferramentas CLI pré-instaladas](18-development-tools.md#preinstalled-cli-tools).

Para instalar todas as ferramentas preguiçosas configuradas antes de precisar delas, execute `mise install --include-lazy`. Isto inclui as outras ferramentas CLI predefinidas do Omarchy, bem como os agentes. Consulte [Ferramentas CLI pré-instaladas](18-development-tools.md#preinstalled-cli-tools) para instalar uma única ferramenta ou utilizar a sua própria instalação.

O `grok` é instalado através do pacote first-party `grok` do mise, da mesma forma que `claude` e `codex`. Execute `grok`, ou escolha-o em _Setup > Defaults > Agent_. Ignore o instalador `curl | bash` em x.ai. Esse caminho coloca uma segunda cópia em `~/.grok/bin`, acrescenta-a ao início do `PATH` e substitui o wrapper do Omarchy.

O `dsh` abre a sua interface de utilizador no navegador em `127.0.0.1:3080`, com o diretório de arranque como área de trabalho predefinida. A sua interface no navegador não aceita um prompt inicial, por isso `omarchy agent prompt` abre-a com o prompt na área de transferência para colar. O Omarchy inicia-o com a predefinição de permissões sem aprovação da DeepSeek. O DeepSeek Harness carrega registos de sessão para a DeepSeek quando utiliza a API oficial de modelos da mesma; desative isso em _Settings > General > Upload Session Log_ na sua interface no navegador. Os comentários que lhe enviar também são carregados com a sessão, a menos que o inicie com `DSH_TELEMETRY_MODE=DISABLED`.

### O agente predefinido

Escolha o seu agente predefinido com `omarchy default agent <name>` ou em _Setup > Defaults > Agent_ no Menu do Omarchy (`Super + Space`). Se o agente ainda não estiver instalado, ao escolhê-lo este é instalado primeiro. Uma instalação nova do Omarchy vai convidá-lo a fazer esta escolha com uma notificação única.

Escolher o Claude também tenta configurar a sua extensão de navegador para Chromium, Chrome, Brave, Brave Origin e Edge. A configuração da extensão aplica-se a todos os utilizadores e pode pedir a sua palavra-passe de sistema; cancelar ou uma instalação da extensão falhada continua a selecionar e a iniciar o Claude. Reinicie o navegador, ative a extensão se lhe for pedido e inicie sessão no Claude para concluir a ligação. Execute `/chrome` no Claude para verificar a ligação. O Firefox e o Zen não suportam esta extensão. Se o Claude já era o seu predefinido antes de esta configuração ter sido adicionada, selecione-o novamente para instalar a extensão.

Depois de escolher, `Super + Shift + Ctrl + A` inicia o agente predefinido numa janela de terminal dedicada (ou abre o seletor se ainda não tiver escolhido nenhum). Também pode iniciá-lo diretamente numa tarefa com `omarchy agent prompt "Review this project"`. O Freebuff e o DeepSeek Harness não aceitam um prompt inicial, por isso abrem com o prompt na área de transferência para colar. Os agentes iniciados desta forma funcionam sem supervisão nos respetivos modos de não parar para perguntar, por isso esteja preparado para eles fazerem realmente coisas! O MiniMax Code não tem um modo desses para as suas sessões interativas, por isso pede permissões como habitualmente. E, como os agentes se recusam a memorizar a confiança para o seu diretório pessoal, os arranques a partir de `$HOME` começam em `~/Work`, em vez disso.

Também há atalhos de terminal: `a` executa o agente predefinido no terminal atual, enquanto `c`, `cx` e `cy` iniciam diretamente o OpenCode, o Claude Code e o Codex (também nos seus modos de aprovação automática). As alterações de tema também são sincronizadas com os agentes: Claude Code, Pi, OpenCode e Hermes (depois de o Omarchy o ter instalado) acompanham-no quando muda o tema do Omarchy.

### O painel de agentes

A barra superior tem um ícone de agentes. Antes de ter configurado um agente, o seu painel orienta-o ao longo do início de sessão no Claude, Codex ou Grok, e o primeiro torna-se o seu agente predefinido. Depois disso, o painel coloca todas as subscrições numa só página: cada agente e conta com o seu plano, um medidor para cada um dos seus limites de sessão de 5 horas e semanais com o tempo até ser reposto (passe o cursor por cima para ver a percentagem exata), ou o saldo pré-pago restante, sob uma linha que vai alternando entre aquilo que utilizou em todos eles, como os tokens desta semana e o seu modelo mais utilizado. Em _Make something_, oferece prompts iniciais para um novo tema, plugin ou aplicação que entregam a tarefa ao seu agente predefinido. As aplicações são construídas da mesma forma que as próprias Hype, Monologue e Omacut do Omarchy, em C++ e Qt Quick, seguindo a skill de agente omarchy-app, e o compilador e os componentes Qt de que precisam já vêm instalados. Claude Code, Codex, Grok, Kimi, Cursor e a sua quota do Grok Bot, GitHub Copilot, Muse, Antigravity, Kimchi e Devin estão abrangidos de origem com os seus limites, e Hermes, Mistral Vibe e Qwen Code mostram as suas sessões e tokens depois de os ter utilizado. Os planos e chaves de fornecedores que utiliza através de pi, omp ou opencode também aparecem: OpenCode Zen e Go, o Z.ai GLM Coding Plan, Ollama Cloud, o MiniMax Token Plan e Synthetic com os seus limites; Fireworks, OpenRouter e DeepSeek com os seus saldos pré-pagos; e os modelos que executa no seu próprio hardware em Modelos locais. Cada agente é contado uma vez, sob quem quer que o fature, independentemente da quantidade de harnesses através dos quais o utilize.

Clique com o botão esquerdo no ícone da barra para abrir o painel, clique com o botão direito para iniciar o seu agente predefinido. Os registos de utilização por trás dele são regenerados a cada 15 minutos por `omarchy agent usage-update`, e o painel pode até fundir a utilização de outras máquinas suas através de uma pasta sincronizada. Consulte o README em `$OMARCHY_PATH/shell/plugins/agents/` para ver todas as definições.

### Várias subscrições

Se pagar por mais do que um plano Claude, Codex ou Grok — um Max pessoal e um de trabalho, por exemplo — o Omarchy pode manter todos com sessão iniciada e alternar entre eles. Adicione uma subscrição com o + no painel de agentes, que o orienta ao longo do processo ali mesmo, ou com `omarchy agent account add claude Work` (ou `codex`, ou `grok`). Instala a CLI se esta estiver em falta. A primeira conta de um fornecedor inicia sessão através do seu navegador normal, exatamente onde a CLI sempre procura. Todas as seguintes iniciam sessão através de uma janela privada, para que a conta em que o seu navegador já tem sessão iniciada não seja detetada por engano; inicie sessão aí como a conta que está a adicionar e feche primeiro qualquer janela privada que já tenha aberta. Nunca termine sessão na CLI para fazer isto: terminar sessão revoga o início de sessão guardado, e essa conta teria de ser adicionada novamente.

Para copiar os seus inícios de sessão de subscrição para outra máquina Omarchy por SSH, execute `omarchy agent account copy user@laptop`. O emissor fornece um recetor temporário quando o destino não tem nenhum instalado, por isso máquinas Omarchy mais antigas podem receber contas sem uma atualização. Os recetores instalados têm precedência. Isto copia todas as subscrições Claude, Codex e Grok; adicione nomes de fornecedores para as selecionar, como em `omarchy agent account copy laptop claude`. Os nomes das contas e os IDs de comando correspondem aos da origem, incluindo contas já presentes no destino. Contas de destino não relacionadas recebem um sufixo numérico se os seus nomes entrarem em conflito, e as definições, skills, plugins e histórico de conversas permanecem locais a cada máquina.

As credenciais existentes no destino são mantidas. Uma conta de origem que já tenha sessão iniciada lá vê o seu nome sincronizado sem substituir as suas credenciais; as outras contas são adicionadas ao lado dela. Para substituir as credenciais guardadas de contas correspondentes, utilize `omarchy agent account copy --replace laptop claude` depois de fechar as sessões dessa conta no destino. Um destino novo também recebe a conta ativa e as preferências de troca da origem; um destino já estabelecido mantém as suas próprias.

As credenciais viajam através de SSH e são guardadas em ficheiros privados no destino, por isso copie apenas para máquinas em que confia. Isto é uma cópia única, não uma sincronização contínua. Os tokens de atualização do Codex podem ser rodados por outra máquina, deixando um início de sessão copiado a precisar de renovação; inícios de sessão separados continuam a ser a escolha mais fiável para utilização simultânea em várias máquinas. Consulte [orientações de autenticação de contas do Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Uma conta por fornecedor está ativa, e cada nova sessão começa como ela: `cx`, `cy`, um simples `claude`, `codex` ou `grok`, qualquer coisa iniciada através de `omarchy agent`, e scripts ou editores que encontrem a CLI no `PATH`. Mude com `omarchy agent account use work` (e volte com `omarchy agent account use main`), ou no painel premindo o número de uma conta e depois `Enter` (ou clicando no seu botão Use). As sessões que já estão a ser executadas permanecem na conta com que começaram. O histórico de conversas, as definições, as skills e os plugins são partilhados entre contas, por isso `claude --continue` na mesma pasta retoma onde deixou na conta nova.

Com mais do que uma conta, o painel mostra os limites de cada conta lado a lado, com a ativa assinalada. Por predefinição, o Omarchy notifica-o quando a conta ativa ultrapassa 95% de um limite, e clicar na notificação muda para a conta com mais margem. Passe o cursor por cima da linha de uma conta no painel e clique em Autoswitch, que aparece ao lado de Use (ou prima `m`), ou execute `omarchy agent account mode auto`, para que mude sozinho; enquanto estiver ativo, Autoswitch ocupa o lugar de Use, e clicar nele novamente volta a notificar. Adicione um número para alterar o limiar, como em `omarchy agent account mode auto 90`. Se todas as contas estiverem acima do limiar, será informado uma vez, juntamente com a conta que fica livre primeiro. Enquanto uma conta ativa estiver a menos de 15 pontos do seu limiar (80% na predefinição), os seus limites são verificados a cada três minutos, em vez de a cada 15.

`omarchy agent account list` mostra todas as contas e os seus limites mais recentes, `omarchy agent account remove work` esquece uma, e `omarchy agent account rename primary Hey` muda o nome de uma (ou clique no nome de uma conta no painel). Estes comandos funcionam nas contas do seu agente predefinido; para chegar ao outro fornecedor, indique-o primeiro, como em `omarchy agent account use codex side`. O início de sessão que já tinha em `~/.claude` ou `~/.codex` é a conta _Main_ e permanece onde está. Uma conta que fique sem utilização durante mais de cerca de oito horas pode mostrar _Sign-in required_; clique nela para iniciar sessão nessa conta novamente diretamente no painel, ou inicie uma sessão nela, o que atualiza o início de sessão por si só. Os servidores MCP que tinha quando uma conta foi adicionada acompanham-na, mas os que adicionar mais tarde com `claude mcp add` só chegam à conta em que os adicionou. O Claude Desktop e as ferramentas configuradas com um caminho absoluto para um binário da CLI não acompanham a mudança. Um `CLAUDE_CONFIG_DIR`, `CODEX_HOME` ou `GROK_HOME` explícito tem precedência sobre a conta selecionada.

### Diagnóstico de falhas

O Omarchy observa o systemd-coredump à procura de crashes de processos. Quando algo faz segfault, receberá uma notificação "Process crashed" — clique nela, e o crash é entregue ao seu agente predefinido juntamente com a skill diagnose-crash do Omarchy, que orienta o agente ao longo do estabelecimento dos factos a partir do core dump e da decisão sobre se vale a pena reportar o crash a montante. Também pode executá-la manualmente contra qualquer PID de `coredumpctl list` com `omarchy agent crash <pid>`.

A observação está ativa por predefinição. Desative-a em _Trigger > Toggle > Crash Capture_ (ou com `omarchy toggle crash-capture`) e as notificações param; `omarchy agent crash <pid>` continua a funcionar manualmente.

Os crashes também podem ser silenciados um programa de cada vez, que é o que o diagnóstico lhe propõe no fim. `omarchy crash mute hyprland` para as notificações apenas para esse programa, `omarchy crash mute hyprland off` trazê-las de volta, e `omarchy crash mute` por si só lista o que silenciou. Aceita o caminho do binário tão bem como o seu nome, por isso `omarchy crash mute /usr/bin/hyprland` faz a mesma coisa. Coloque entre aspas um nome com um espaço, como em `omarchy crash mute 'Some App'`. Tudo o resto continua a notificar, e o programa silenciado continua a falhar — isto esconde o lembrete, não corrige nada.

### Aplicações de ambiente de trabalho

O menu _Install > AI_ também inclui algumas aplicações gráficas de IA: a aplicação de ambiente de trabalho do ChatGPT, a aplicação de ambiente de trabalho do Claude (a beta para Linux da Anthropic, com separadores Chat, Cowork e Claude Code), o Grok Bot para conversar com os modelos da xAI, o Hermes Desktop, o OpenClaw, a aplicação de ambiente de trabalho do Perplexity e o T3 Code. O Grok Bot é a aplicação de conversação de ambiente de trabalho. O agente de programação é o comando `grok`.

O Hermes Desktop é o que deve conhecer, porque uma máquina tem um Hermes, e é o da aplicação: o Hermes só é alguma vez instalado através da aplicação, e o comando `hermes` que o agente predefinido executa é o da aplicação. Escolher o Hermes como agente predefinido instala a mesma coisa que a entrada _Install > AI_: o pacote, e um runtime do Hermes em `~/.hermes` configurado pelo instalador próprio do Hermes, o que demora alguns minutos na primeira vez. Esse runtime é o único Hermes que o comando `hermes` do terminal, o agente predefinido e a aplicação utilizam, e atualiza-se a si próprio com `hermes update`, em vez de esperar por uma versão do Omarchy. Instalá-lo também entrega ao Hermes o tema do Omarchy como uma skin chamada `omarchy`, que todas as superfícies do Hermes seguem à medida que muda de tema; escolha outra nas definições de Appearance do Hermes ou com `/skin` se preferir que não o faça, e o Omarchy deixa essa escolha em paz. Remover a aplicação em _Remove > AI_ fecha primeiro o Hermes, gateway incluída, leva esse runtime com ela e mantém as suas conversas, memórias e as skills que o Hermes escreveu para si próprio, a menos que lhe diga o contrário: pergunta, com não por predefinição, se esses dados e as suas definições de ligação também devem desaparecer.

A experiência de ambiente de trabalho do OpenClaw é a sua Control UI, que abre como uma aplicação web apoiada pela sua própria gateway local. O OpenClaw vive em `~/.openclaw` e atualiza-se a si próprio: utilize o botão "Update Gateway" da Control UI ou execute `openclaw update`, e a gateway reinicia na nova versão. O Omarchy apenas escolhe a versão a partir da qual uma instalação nova começa. Remover o OpenClaw em _Remove > AI_ leva consigo o serviço da gateway e a aplicação e, em seguida, pergunta se `~/.openclaw` também deve desaparecer, uma vez que é aí que guarda as suas conversas e credenciais juntamente com o próprio OpenClaw e os runtimes de plugins que este transfere; a predefinição mantém-no, e instalar o OpenClaw novamente volta a retomá-lo.

O T3 Code é executado a partir da sua versão oficial AppImage em `~/.local/share/t3code`, em vez de a partir de um pacote, por isso atualiza-se a si próprio. Instalá-lo pergunta se quer começar no canal Stable ou Nightly; mude mais tarde nas definições do T3 Code. As suas conversas e definições vivem em `~/.t3`, e remover o T3 Code em _Remove > AI_ leva-as consigo.

### Modelos locais

Execute um modelo aberto na sua própria máquina para os seus agentes de programação. Os seus prompts e código permanecem na máquina; nada do que é enviado para o modelo sai dela. Comece com:

```bash
omarchy agent local use best
```

Ou, no painel de agentes na barra superior, escolha + e depois Local AI, que aparece quando um modelo cabe nesta máquina. Na primeira vez, isto instala o Podman, que executa os modelos, e numa máquina NVIDIA o kit de ferramentas de contentores da NVIDIA, que lhes dá acesso à GPU. Em seguida, o Omarchy escolhe o modelo recomendado para esta máquina, transfere-o e inicia-o. Conte com uma transferência de dezenas de GB e com a maior parte da memória da máquina em utilização enquanto o modelo estiver a ser executado: o Flash Next utiliza cerca de 100 GiB com o seu contexto completo de 256K. Se outros modelos ocuparem a memória de que precisa, é configurado parado, pronto para iniciar assim que parar um. O modelo para ao terminar sessão; pare-o você mesmo quando precisar da memória para outra coisa.

`omarchy agent local list` mostra as opções e explica por que motivo algumas não cabem. Para configurar outra, execute `omarchy agent local use <recipe>`. Hoje, `qwen3.8-flash-next-gufo` e `qwen3.8-27b-gufo` estão disponíveis para máquinas Strix Halo de 128 GB; o 27B ocupa cerca de 40 GiB, por isso deixa espaço para outro trabalho. Novas receitas e recomendações chegam com `omarchy update`, através do pacote.

Cada modelo que configurar tem a sua própria linha no painel de agentes, ao lado das suas subscrições: reproduzir para o iniciar, pausa para o parar e libertar a sua memória, e o botão de terminal para abrir o seu agente nele. Vários podem ser executados ao mesmo tempo quando cabem juntos na memória; se um não couber, o Omarchy indica que modelo em execução deve parar. Arraste as linhas para as reordenar e prima Delete numa linha selecionada para remover um modelo e a sua transferência.

A partir da linha de comandos, `omarchy agent local start <recipe>` e `omarchy agent local stop <recipe>` fazem o mesmo, `omarchy agent local status` mostra todos os modelos, e `omarchy agent --local` abre o seu agente predefinido no último modelo que iniciou (pi se o seu agente predefinido não conseguir utilizar um modelo local). Qualquer cliente compatível com OpenAI também se pode ligar: `status` mostra o endereço de cada modelo (o primeiro é `http://127.0.0.1:11435/v1`), o nome da receita é o modelo, e a chave está em `~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` elimina um modelo e as transferências que nenhum outro modelo utiliza.

Os runtimes de terceiros são identificados com o respetivo editor. O Omarchy executa todos os modelos sem acesso à rede.

### LLM locais

O Omarchy recomenda duas formas de executar modelos LLM locais: LM Studio e Ollama. O LM Studio fornece uma interface gráfica para encontrar modelos de pesos abertos, instalá-los e executá-los. É uma ótima forma de começar facilmente. O Ollama oferece uma CLI para fazer o mesmo de forma semelhante. Mas, se é novo nos modelos locais, eu começaria pelo LM Studio. Pode instalar qualquer um deles em _Install > AI_ no Menu do Omarchy.

### A Skill do Omarchy

As skills de agente ajudam a IA a utilizar ferramentas específicas de uma forma específica, e o Omarchy vem com uma skill predefinida para adaptar o sistema. Como ajustar a sua configuração do Hyprland, ajustar a barra, ou até criar um tema novo de raiz. Está presente através de uma ligação simbólica nos diretórios de skills do Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` e cada `~/.hermes/profiles/*/skills`), e na localização genérica `~/.agents/skills`, por isso a maioria dos harnesses recolhe-a automaticamente.

Mas deve tratar esta skill como experimental. Modelos diferentes irão utilizá-la com efeitos diferentes. É melhor executá-la primeiro em modo de planeamento, para ter uma ideia do que o agente gostaria de alterar. E depois esteja pronto para reverter alterações ou até invocar `omarchy reinstall configs`, se o agente fizer uma confusão de tudo.
