# IA

O Omarchy trata os agentes de programação com IA como cidadãos de primeira classe, mas não escolhe um favorito por ti. Em vez disso, todas as principais CLI de agentes de programação vêm pré-configuradas como um iniciador de carregamento diferido. Os iniciadores são pequenos stubs geridos pelo [mise](https://mise.jdx.dev/) em `~/.local/bin/`, por isso nada é transferido até executares um deles pela primeira vez. O Hermes é a exceção: não existe nenhum stub para ele e, ao escolhê-lo, é instalado o Hermes Desktop, como explica _Aplicações de ambiente de trabalho_ mais abaixo. Invoca qualquer um destes e autentica-te quando te for pedido:

| Comando    | Agente                                                            |
|------------|------------------------------------------------------------------|
| `claude`   | [Claude Code](https://code.claude.com/docs/en/overview)          |
| `codex`    | [OpenAI Codex](https://github.com/openai/codex)                  |
| `opencode` | [OpenCode](https://opencode.ai/)                                 |
| `agy`      | [Google Antigravity CLI](https://github.com/google-antigravity/antigravity-cli) |
| `copilot`  | [GitHub Copilot CLI](https://github.com/github/copilot-cli)      |
| `crush`    | [Crush](https://github.com/charmbracelet/crush)                  |
| `grok`     | [Grok Build](https://x.ai/build) da xAI                        |
| `kimi`     | [Kimi Code](https://www.kimi.com/code/docs/en/)                  |
| `pi`       | [Pi de Mario Zechner](https://github.com/badlogic/pi-mono)        |
| `omp`      | [Oh My Pi](https://github.com/can1357/oh-my-pi)                  |
| `ori`      | [Ori](https://openrouter.ai/docs/guides/ori/harness), o harness da OpenRouter |
| `hermes`   | [Hermes](https://hermes-agent.nousresearch.com/), o agente da Nous Research  |
| `muse`     | [Muse Code](https://dev.meta.ai), o agente de programação da Meta           |
| `cursor-agent` | [Cursor CLI](https://cursor.com/cli)                         |

O `ori` é o caso à parte: executa os outros harnesses contra todo o catálogo de modelos da OpenRouter, por isso `ori claude`, `ori codex` ou `ori opencode` iniciam esses agentes no modelo para que os apontares, e `ori code` é o agente do próprio Ori.

Para envolver uma CLI adicional da mesma forma, executa `omarchy-mise-install <package> [command-name]`. Os stubs são mantidos atualizados, juntamente com tudo o resto que o mise gere, quando executas `omarchy update` (ou o alias `mup`).

O `grok` é instalado através do pacote oficial `grok` do mise, da mesma forma que o `claude` e o `codex`. Executa `grok`, ou escolhe-o em _Setup > Defaults > Agent_. Ignora o instalador `curl | bash` da x.ai. Esse caminho coloca uma segunda cópia em `~/.grok/bin`, coloca-a no início do `PATH` e substitui o wrapper do Omarchy.

### O agente predefinido

Escolhe o teu agente predefinido com `omarchy default agent <name>` ou em _Setup > Defaults > Agent_ no Menu Omarchy (`Super + Space`). Se o agente ainda não estiver instalado, ao escolhê-lo ele é instalado primeiro. Um Omarchy acabado de instalar vai convidar-te a fazer esta escolha com uma notificação única.

Escolher o Claude também tenta configurar a respetiva extensão de navegador para Chromium, Chrome, Brave, Brave Origin e Edge. A configuração da extensão aplica-se a todos os utilizadores e pode pedir a tua palavra-passe do sistema; cancelar ou uma instalação falhada da extensão continua a selecionar e a iniciar o Claude. Reinicia o navegador, ativa a extensão se te for pedido e inicia sessão no Claude para terminar a ligação. Executa `/chrome` no Claude para verificar a ligação. O Firefox e o Zen não suportam esta extensão. Se o Claude já era o teu agente predefinido antes de esta configuração ser adicionada, seleciona-o outra vez para instalar a extensão.

[Muse Code](https://dev.meta.ai) — o `muse` da Meta — utiliza um stub do mise pré-instalado, tal como os outros agentes. Ao escolhê-lo como predefinido, é instalado o iniciador oficial da Meta através do backend HTTP do mise. O iniciador verifica e atualiza o binário nativo para a tua máquina.

Depois de teres escolhido, `Super + Shift + Ctrl + A` inicia o agente predefinido numa janela de terminal dedicada (ou abre o seletor se ainda não tiveres escolhido). Também podes iniciá-lo diretamente numa tarefa com `omarchy agent prompt "Review this project"`. Os agentes iniciados desta forma funcionam sem supervisão nos respetivos modos «não parar para perguntar», por isso prepara-te para eles fazerem mesmo coisas! E, como os agentes se recusam a memorizar a confiança na tua pasta pessoal, os arranques a partir de `$HOME` começam antes em `~/Work`.

Também há atalhos de terminal: `a` executa o agente predefinido inline no terminal atual, enquanto `c`, `cx` e `cy` iniciam diretamente o OpenCode, o Claude Code e o Codex (também nos respetivos modos de aprovação automática). As alterações de tema também se sincronizam com os agentes: Claude Code, Pi, OpenCode e Hermes (depois de o Omarchy o ter instalado) acompanham todos quando mudas o tema do Omarchy.

### O painel de agentes

A barra superior tem um ícone de agentes. Antes de teres configurado um agente, o painel desse ícone guia-te no início de sessão no Claude, no Codex ou no Grok, e o primeiro torna-se o teu agente predefinido. Depois disso, o painel coloca todas as subscrições numa só página: cada agente e conta com o respetivo plano, um medidor para cada um dos limites de sessão de 5 horas e semanal, com o tempo até ser reposto (passa o cursor por cima para veres a percentagem exata), ou o saldo pré-pago restante, por baixo de uma linha que vai alternando entre aquilo que utilizaste em todos eles, como os tokens desta semana e o teu modelo mais utilizado. Em _Make something_, oferece prompts iniciais para um novo tema, plugin ou aplicação, que entregam a tarefa ao teu agente predefinido. As aplicações são construídas da mesma forma que as próprias Hype, Monologue e Omacut do Omarchy, em C++ e Qt Quick, seguindo a skill de agente omarchy-app, e o compilador e os componentes Qt de que precisam vêm instalados. Claude Code, Codex, Grok, Fireworks e Kimi estão cobertos de origem. Atualmente, o Kimi comunica limites de quota da conta sem estatísticas locais de tokens ou de prompts.

Clica com o botão esquerdo do rato no ícone da barra para abrir o painel e com o botão direito para iniciar o teu agente predefinido. Os registos de utilização que estão por trás dele são regenerados a cada 15 minutos por `omarchy agent usage-update`, e o painel pode até juntar a utilização das tuas outras máquinas através de uma pasta sincronizada. Consulta o README em `$OMARCHY_PATH/shell/plugins/agents/` para veres todas as definições.

### Várias subscrições

Se pagares por mais do que um plano Claude, Codex ou Grok — um Max pessoal e um de trabalho, por exemplo — o Omarchy pode mantê-los todos com sessão iniciada e alternar entre eles. Adiciona uma subscrição com o + no painel de agentes, que te guia ao longo do processo ali mesmo, ou com `omarchy agent account add claude Work` (ou `codex`, ou `grok`). A CLI é instalada se estiver em falta. A primeira conta de um fornecedor inicia sessão através do teu navegador normal, exatamente onde a CLI sempre procura. Todas as seguintes iniciam sessão através de uma janela privada, para que a conta em que o teu navegador já tem sessão iniciada não seja apanhada por engano; inicia sessão aí com a conta que estás a adicionar e fecha primeiro qualquer janela privada que já tenhas aberta. Nunca termines sessão na CLI para fazer isto: terminar sessão revoga o início de sessão guardado e essa conta teria de ser adicionada outra vez.

Para copiares os teus inícios de sessão de subscrição para outra máquina Omarchy através de SSH, executa `omarchy agent account copy user@laptop`. O emissor fornece um recetor temporário quando o destino não tem nenhum instalado, por isso máquinas Omarchy mais antigas podem receber contas sem uma atualização. Os recetores instalados têm precedência. Isto copia todas as subscrições Claude, Codex e Grok; adiciona nomes de fornecedores para as selecionar, como em `omarchy agent account copy laptop claude`. Os nomes das contas e os ID de comando correspondem à origem, incluindo contas já presentes no destino. Contas do destino não relacionadas recebem um sufixo numérico se os nomes entrarem em conflito, e as definições, skills, plugins e o histórico de conversas permanecem locais em cada máquina.

As credenciais existentes no destino são mantidas. Uma conta de origem que já tenha sessão iniciada lá tem o nome sincronizado sem substituir as credenciais; as outras contas são adicionadas ao lado dela. Para substituir credenciais guardadas de contas correspondentes, utiliza `omarchy agent account copy --replace laptop claude` depois de fechares as sessões dessa conta no destino. Um destino novo também recebe a conta ativa e as preferências de alternância da origem; um destino já estabelecido mantém as suas.

As credenciais viajam através de SSH e são guardadas em ficheiros privados no destino, por isso copia apenas para máquinas em que confias. Isto é uma cópia única, não uma sincronização contínua. Os tokens de atualização do Codex podem ser rodados por outra máquina, deixando um início de sessão copiado a precisar de renovação; inícios de sessão separados continuam a ser a escolha mais fiável para utilização simultânea em várias máquinas. Consulta as [orientações de autenticação de contas do Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Uma conta por fornecedor está ativa, e todas as novas sessões começam com ela: `cx`, `cy`, um simples `claude`, `codex` ou `grok`, tudo o que for iniciado através de `omarchy agent`, e scripts ou editores que encontrem a CLI no `PATH`. Muda com `omarchy agent account use work` (e volta com `omarchy agent account use main`), ou no painel, premindo o número de uma conta e depois `Enter` (ou clicando no respetivo botão Use). As sessões que já estão a funcionar mantêm a conta com que começaram. O histórico de conversas, as definições, as skills e os plugins são partilhados entre contas, por isso `claude --continue` na mesma pasta continua onde tinhas ficado na nova conta.

Com mais do que uma conta, o painel mostra os limites de cada conta lado a lado, com a ativa assinalada. Por predefinição, o Omarchy avisa-te quando a conta ativa ultrapassa 95% de um limite, e clicar na notificação muda para a conta com maior margem disponível. Passa o cursor sobre a linha de uma conta no painel e clica em Autoswitch, que aparece ao lado de Use (ou prime `m`), ou executa `omarchy agent account mode auto`, para que a mudança aconteça sozinha; enquanto estiver ativo, Autoswitch ocupa o lugar de Use, e clicar outra vez volta ao modo de aviso. Adiciona um número para mudar o limiar, como em `omarchy agent account mode auto 90`. Se todas as contas estiverem acima do limiar, vais saber disso uma vez, juntamente com a conta que fica livre primeiro. Enquanto uma conta ativa estiver a 15 pontos do seu limiar (80% no valor predefinido), os respetivos limites são verificados a cada três minutos, em vez de a cada 15.

`omarchy agent account list` mostra todas as contas e os respetivos limites mais recentes, `omarchy agent account remove work` esquece uma, e `omarchy agent account rename primary Hey` muda o nome de uma (ou clica no nome de uma conta no painel). Estes comandos funcionam nas contas do teu agente predefinido; para chegares ao outro fornecedor, indica-o primeiro, como em `omarchy agent account use codex side`. O início de sessão que já tinhas em `~/.claude` ou `~/.codex` é a conta _Main_ e fica onde está. Uma conta que fique sem ser utilizada durante mais de cerca de oito horas pode mostrar _Sign-in required_; clica nela para iniciar sessão nessa conta outra vez diretamente no painel, ou inicia uma sessão nela, o que renova o início de sessão por si só. Os servidores MCP que tinhas quando uma conta foi adicionada acompanham-na, mas aqueles que adicionares mais tarde com `claude mcp add` só chegam à conta em que os adicionaste. O Claude Desktop e ferramentas configuradas com um caminho absoluto para um binário da CLI não acompanham a mudança. Um `CLAUDE_CONFIG_DIR`, `CODEX_HOME` ou `GROK_HOME` explícito tem precedência sobre a conta selecionada.

### Diagnóstico de falhas

O Omarchy vigia o systemd-coredump à procura de falhas de processos. Quando alguma coisa faz segfault, vais receber uma notificação "Process crashed" — clica nela e a falha é entregue ao teu agente predefinido, juntamente com a skill diagnose-crash do Omarchy, que guia o agente para estabelecer os factos a partir do core dump e decidir se vale a pena comunicar a falha a montante. Também podes executá-lo manualmente contra qualquer PID de `coredumpctl list` com `omarchy agent crash <pid>`.

A vigilância está ativa por predefinição. Desliga-a em _Trigger > Toggle > Crash Capture_ (ou com `omarchy toggle crash-capture`) e as notificações param; `omarchy agent crash <pid>` continua a funcionar manualmente.

As falhas também podem ser silenciadas um programa de cada vez, que é aquilo que o diagnóstico te oferece no fim. `omarchy crash mute hyprland` para as notificações apenas para esse programa, `omarchy crash mute hyprland off` traz-las de volta, e `omarchy crash mute` sozinho lista o que silenciaste. Aceita o caminho do binário tão bem como o nome, por isso `omarchy crash mute /usr/bin/hyprland` faz o mesmo. Coloca entre aspas um nome com um espaço, como em `omarchy crash mute 'Some App'`. Tudo o resto continua a avisar, e o programa silenciado continua a falhar — isto esconde o lembrete, não resolve nada.

### Aplicações de ambiente de trabalho

O menu _Install > AI_ também traz algumas aplicações gráficas de IA: a aplicação de ambiente de trabalho do ChatGPT, a aplicação de ambiente de trabalho do Claude (a beta para Linux da Anthropic, com os separadores Chat, Cowork e Claude Code), o Grok Bot para conversar com os modelos da xAI, o Hermes Desktop, o OpenClaw e a aplicação de ambiente de trabalho do Perplexity. O Grok Bot é a aplicação de conversação para ambiente de trabalho. O agente de programação é o comando `grok`.

O Hermes Desktop é aquele que tens de conhecer, porque uma máquina tem um único Hermes, e esse é o da aplicação: o Hermes só é instalado através da aplicação, e o comando `hermes` que o agente predefinido executa é o da aplicação. Escolher o Hermes como agente predefinido instala a mesma coisa que a entrada _Install > AI_: o pacote e um runtime do Hermes em `~/.hermes`, configurado pelo instalador do próprio Hermes, o que demora alguns minutos na primeira vez. Esse runtime é o único Hermes que o comando de terminal `hermes`, o agente predefinido e a aplicação utilizam, e atualiza-se a si próprio com `hermes update`, em vez de estar à espera de uma nova versão do Omarchy. Instalá-lo também entrega ao Hermes o tema do Omarchy como uma skin chamada `omarchy`, que todas as superfícies do Hermes seguem à medida que mudas de tema; escolhe outra nas definições de Appearance do Hermes ou com `/skin` se preferires que não o faça, e o Omarchy não mexe nessa escolha. Remover a aplicação em _Remove > AI_ fecha primeiro o Hermes, gateway incluído, leva esse runtime com ela e mantém as tuas conversas, memórias e as skills que o Hermes escreveu para si próprio, a menos que lhe digas o contrário: pergunta, com «não» por predefinição, se esses dados e as tuas definições de ligação também devem ser removidos.

A experiência de ambiente de trabalho do OpenClaw é o seu Control UI, que abre como uma aplicação web suportada pelo seu próprio gateway local. O OpenClaw vive em `~/.openclaw` e atualiza-se a si próprio: utiliza o botão "Update Gateway" do Control UI ou executa `openclaw update`, e o gateway reinicia na nova versão. O Omarchy só escolhe a versão a partir da qual uma instalação nova começa. Remover o OpenClaw em _Remove > AI_ leva com ele o serviço do gateway e a aplicação e depois pergunta se `~/.openclaw` também deve ser removido, uma vez que é aí que estão as tuas conversas e credenciais, juntamente com o próprio OpenClaw e os runtimes de plugins que ele transfere; a predefinição mantém-no, e instalar o OpenClaw outra vez volta a utilizá-lo.

### LLM locais

O Omarchy recomenda duas formas de executar modelos LLM locais: LM Studio e Ollama. O LM Studio fornece uma interface GUI para encontrar modelos de pesos abertos, instalá-los e executá-los. É uma excelente forma de começar facilmente. O Ollama oferece uma CLI para fazer o mesmo. Mas, se és novo nos modelos locais, eu começaria pelo LM Studio. Podes instalar qualquer um deles em _Install > AI_ no Menu Omarchy.

### A Skill do Omarchy

As skills de agente ajudam a IA a utilizar ferramentas específicas de uma forma específica, e o Omarchy vem com uma skill predefinida para personalizar o sistema. Como ajustar a tua configuração do Hyprland, ajustar a barra ou até criar um tema novo de raiz. Está ligada por symlink para os diretórios de skills do Claude Code (`~/.claude/skills`), do Codex (`~/.codex/skills`), do Pi (`~/.pi/agent/skills`), do Antigravity (`~/.gemini/config/skills`), do Hermes (`~/.hermes/skills` e cada `~/.hermes/profiles/*/skills`) e para a localização genérica `~/.agents/skills`, por isso a maior parte dos harnesses apanha-a automaticamente.

Mas deves tratar esta skill como experimental. Modelos diferentes vão utilizá-la com efeitos diferentes. É melhor executá-la primeiro em modo de planeamento, para teres uma ideia do que o agente gostaria de alterar. E depois prepara-te para reverter alterações ou até para invocar `omarchy reinstall configs`, se o agente fizer uma confusão com tudo.
