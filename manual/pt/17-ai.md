# IA

Executa um comando para instalares a sua CLI na primeira utilização e, depois, autentica-te quando te for pedido. O Hermes e o OpenClaw são as exceções: nada é instalado para eles através do mise, e escolher qualquer um deles configura a sua própria cópia com atualização automática, como _Aplicações de ambiente de trabalho_ explica mais abaixo.

### Instalar e atualizar agentes

À exceção do Hermes e do OpenClaw, estes agentes usam a instalação preguiçosa do mise: o primeiro arranque instala a CLI, e os arranques posteriores reutilizam-na. O mise também verifica se um agente instalado tem uma nova versão, no máximo uma vez a cada quatro horas, mesmo antes de ele arrancar ou em segundo plano num prompt da shell. Se essa atualização falhar ou estiveres offline, a versão instalada é a que funciona. `omarchy update` atualiza os agentes instalados com o resto do Omarchy, e `mup` atualiza apenas as ferramentas geridas pelo mise.

O atualizador próprio de um agente, como `claude update`, `codex update` ou um botão de atualização numa aplicação, não atualiza a instalação gerida pelo mise. `codex update` falha, e `claude update` pode comunicar sucesso enquanto instala uma cópia separada que o mise não acompanha. Se preferires usar o instalador e o atualizador nativos de um agente, adiciona-o a `disable_tools`; vê [Ferramentas CLI pré-instaladas](18-development-tools.md#preinstalled-cli-tools).

Para instalares todas as ferramentas preguiçosas configuradas antes de precisares delas, executa `mise install --include-lazy`. Isto inclui as outras ferramentas CLI predefinidas do Omarchy, além dos agentes. Vê [Ferramentas CLI pré-instaladas](18-development-tools.md#preinstalled-cli-tools) para instalares uma única ferramenta ou usares a tua própria instalação.

O `grok` é instalado através do pacote `grok` oficial do mise, da mesma forma que `claude` e `codex`. Executa `grok`, ou escolhe-o em _Agent > Harness_. Evita o instalador `curl | bash` em x.ai. Esse caminho coloca uma segunda cópia em `~/.grok/bin`, põe-na no início do `PATH` e sobrescreve o wrapper do Omarchy.

O `dsh` abre a sua interface de navegador em `127.0.0.1:3080`, com o diretório de lançamento como o seu espaço de trabalho predefinido. A sua interface de navegador não aceita um prompt inicial, por isso `omarchy agent prompt` abre-a com o prompt na tua área de transferência para colares. O Omarchy arranca-o com a predefinição de permissões sem aprovação da DeepSeek. O DeepSeek Harness carrega registos de sessão para a DeepSeek quando usas a sua API oficial de modelos; desliga isso em _Settings > General > Upload Session Log_ na sua interface de navegador. O feedback que lhe enviares também é carregado com a sessão, a menos que o arranques com `DSH_TELEMETRY_MODE=DISABLED`.

### O agente predefinido

Escolhe o teu agente predefinido com `omarchy default agent <name>` ou em _Agent > Harness_ no Menu Omarchy (`Super + Space`). Se o agente ainda não estiver instalado, escolhê-lo instala-o primeiro, e ele também ganha um lançador próprio no lançador de aplicações, ao lado de Agent. Um Omarchy acabado de instalar vai convidar-te a fazeres esta escolha com uma notificação apresentada uma única vez.

Escolher o Claude também tenta configurar a sua extensão de navegador para Chromium, Chrome, Brave, Brave Origin e Edge. A configuração da extensão aplica-se a todos os utilizadores e pode pedir a tua palavra-passe de sistema; cancelar ou uma instalação da extensão falhada continua a selecionar e a iniciar o Claude. Reinicia o navegador, ativa a extensão se te for pedido e inicia sessão no Claude para concluíres a ligação. Executa `/chrome` no Claude para verificares a ligação. O Firefox e o Zen não suportam esta extensão. Se o Claude já era o teu agente predefinido antes de esta configuração ser adicionada, seleciona-o outra vez para instalares a extensão.

Depois de escolheres, `Super + Shift + Ctrl + A` inicia o agente predefinido numa janela de terminal dedicada (ou abre o seletor, se ainda não tiveres escolhido nenhum). Também podes iniciá-lo diretamente numa tarefa com `omarchy agent prompt "Review this project"`. O Freebuff e o DeepSeek Harness não aceitam um prompt inicial, por isso abrem com o prompt na tua área de transferência para colares. Os agentes iniciados desta forma funcionam sem supervisão nos respetivos modos de não parar para perguntar, por isso prepara-te para que façam mesmo coisas! O MiniMax Code não tem esse modo para as suas sessões interativas, por isso pede permissões como habitualmente. E como os agentes se recusam a memorizar a confiança no teu diretório pessoal, os lançamentos a partir de `$HOME` arrancam em `~/Work`.

Também há atalhos de terminal: `a` executa o agente predefinido diretamente no terminal atual, enquanto `c`, `cx` e `cy` iniciam OpenCode, Claude Code e Codex diretamente (também nos seus modos de aprovação automática). As mudanças de tema também são sincronizadas com os agentes: Claude Code, Pi, OpenCode e Hermes (depois de o Omarchy o ter instalado) acompanham todos quando mudas o tema do Omarchy.

### As tuas instruções para os agentes

As regras pessoais para todos os agentes ficam em `~/.agents/AGENTS.md`, ao lado das competências partilhadas em `~/.agents/skills`. Abre-o em _Agent > Instructions_, que também o liga a cada harness que mantém o seu próprio ficheiro global: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` do Copilot, e assim por diante. O Crush e o Amp leem a ligação `~/.config/AGENTS.md`, enquanto o omp, o Kimi e o DeepSeek Harness leem `~/.agents/AGENTS.md` diretamente. Escolher um agente predefinido também cria a ligação para ele. Um ficheiro de instruções que já tinhas torna-se o partilhado se ainda não existia nenhum; caso contrário, é mantido ao lado da ligação como `.bak`. Executa `omarchy agent instructions` para voltares a criar as ligações depois de instalares outro agente.

### O painel de agentes

A barra superior tem um ícone de agentes. Antes de teres configurado um agente, o seu painel guia-te ao iniciares sessão no Claude, Codex ou Grok, e o primeiro torna-se o teu agente predefinido. Depois disso, o painel reúne todas as subscrições numa única página: cada agente e conta com o seu plano, um medidor para cada um dos seus limites de sessão de 5 horas e semanais com o tempo até ser reposto (passa o cursor por cima para veres a percentagem exata), ou o saldo pré-pago restante, sob uma linha que vai rodando pelo que utilizaste em todos eles, como tokens esta semana e o teu modelo mais utilizado. Em _Make something cool_ oferece prompts iniciais para um novo tema, plugin, aplicação ou jogo que entregam a tarefa ao teu agente predefinido. As aplicações são construídas da mesma forma que as próprias Hype, Monologue e Omacut do Omarchy, em C++ e Qt Quick, seguindo a competência de agente omarchy-make-app, e o compilador e os componentes Qt de que precisam já vêm instalados. Os jogos são uma única página three.js em `~/Games/vibes`, seguindo a competência de agente omarchy-make-game, e todos abrem a partir de um único lançador Game Vibes no tema atual; carregam o three.js a partir da Web, por isso precisam de uma ligação para arrancar. Claude Code, Codex, Grok, Kimi, Cursor e a sua quota do Grok Bot, GitHub Copilot, Muse, Antigravity e Devin estão abrangidos de origem com os seus limites, o Kimchi com o seu plano, créditos pré-pagos e orçamentos de despesas, e Hermes, Mistral Vibe e Qwen Code mostram as suas sessões e tokens depois de os teres utilizado. Os planos e chaves de fornecedores que utilizas através do pi, omp ou opencode também aparecem: OpenCode Zen e Go, o Z.ai GLM Coding Plan, Ollama Cloud, o MiniMax Token Plan e Synthetic com os seus limites; OpenRouter e DeepSeek com os seus saldos pré-pagos; Fireworks com as suas despesas nos últimos 30 dias. Os tokens de modelos que executas no teu próprio hardware também contam para os totais; os próprios modelos têm um painel próprio, descrito em [Modelos locais](#local-models). Cada agente é contado uma vez, sob quem o fatura, independentemente de quantos harnesses uses para o conduzir.

Clica com o botão esquerdo no ícone da barra ou prime `Super + Ctrl + X` para abrires o painel, clica com o botão direito para iniciares o teu agente predefinido e clica com o botão do meio para atualizares. Os registos de utilização que o suportam são regenerados a cada 15 minutos por `omarchy agent usage update`, e o painel pode até fundir a utilização das tuas outras máquinas através de uma pasta sincronizada. Consulta o README em `$OMARCHY_PATH/shell/plugins/agents/` para veres todas as definições.

### Várias subscrições

Se pagares por mais do que um plano Claude, Codex ou Grok — um Max pessoal e um de trabalho, por exemplo — o Omarchy pode manter todos com sessão iniciada e alternar entre eles. Adiciona uma subscrição com o + no painel de agentes, que te guia ali mesmo, ou com `omarchy agent account add claude Work` (ou `codex`, ou `grok`). Instala a CLI se esta estiver em falta. A primeira conta de um fornecedor inicia sessão através do teu navegador normal, exatamente onde a CLI sempre procura. Todas as seguintes iniciam sessão através de uma janela privada, para que a conta em que o teu navegador já tem sessão iniciada não seja apanhada por engano; inicia sessão aí como a conta que estás a adicionar e fecha primeiro qualquer janela privada que já tenhas aberta. Nunca termines a sessão na CLI para fazeres isto: terminar a sessão revoga o início de sessão guardado, e essa conta teria de ser adicionada outra vez.

Para copiares os teus inícios de sessão de subscrição para outra máquina Omarchy por SSH, executa `omarchy agent account copy user@laptop`. O emissor fornece um recetor temporário quando o destino não tem um instalado, para que máquinas Omarchy mais antigas possam receber contas sem uma atualização. Os recetores instalados têm precedência. Isto copia todas as subscrições Claude, Codex e Grok; adiciona nomes de fornecedores para as selecionares, como em `omarchy agent account copy laptop claude`. Os nomes das contas e os ID de comandos correspondem à origem, incluindo contas já presentes no destino. As contas do destino não relacionadas recebem um sufixo numérico se os seus nomes entrarem em conflito, e as definições, competências, plugins e histórico de conversas permanecem locais a cada máquina.

As credenciais existentes no destino são mantidas. Uma conta de origem que já tenha sessão iniciada aí vê o seu nome sincronizado sem que as suas credenciais sejam substituídas; as outras contas são adicionadas ao lado dela. Para substituíres as credenciais guardadas de contas correspondentes, usa `omarchy agent account copy --replace laptop claude` depois de fechares as sessões dessa conta no destino. Um destino novo também recebe a conta ativa e as preferências de alternância da origem; um destino já estabelecido mantém as suas.

As credenciais viajam por SSH e são guardadas em ficheiros privados no destino, por isso copia apenas para máquinas em que confias. Isto é uma cópia única, não uma sincronização contínua. Os tokens de atualização do Codex podem ser rodados por outra máquina, deixando um início de sessão copiado a precisar de renovação; inícios de sessão separados continuam a ser a escolha mais fiável para utilização simultânea em várias máquinas. Vê as [orientações de autenticação de conta do Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Uma conta por fornecedor está ativa, e cada nova sessão começa como ela: `cx`, `cy`, um simples `claude`, `codex` ou `grok`, qualquer coisa lançada através de `omarchy agent`, e scripts ou editores que encontrem a CLI no `PATH`. Alterna com `omarchy agent account use work` (e volta com `omarchy agent account use main`), ou no painel, premindo o número de uma conta e depois `Enter` (ou clicando no seu botão Use). As sessões Claude em execução também alternam, a partir da mensagem seguinte: cada sessão Claude funciona em `~/.claude`, que contém sempre o início de sessão da conta ativa. Uma sessão Claude iniciada na pasta própria de uma conta por um Omarchy mais antigo mantém esse início de sessão até sair, por isso a alternância nomeia essas sessões e conclui-se sozinha quando elas desaparecerem. As sessões Codex e Grok em execução mantêm a conta com que começaram. O histórico de conversas, as definições, competências e plugins são partilhados entre contas, por isso `claude --continue` na mesma pasta continua onde tinhas ficado na nova conta.

Com mais do que uma conta, o painel mostra os limites de cada conta lado a lado, com a ativa assinalada. Por omissão, o Omarchy notifica-te quando a conta ativa ultrapassa 95% de um limite, e clicar na notificação muda para a conta com mais margem. Passa o cursor sobre a linha de uma conta no painel e clica em Autoswitch, que aparece ao lado de Use (ou prime `m`), ou executa `omarchy agent account mode auto`, para que mude sozinho; enquanto estiver ligado, Autoswitch ocupa o lugar de Use, e clicar outra vez nele volta ao modo de notificação. Adiciona um número para alterares o limiar, como em `omarchy agent account mode auto 90`. Se todas as contas estiverem acima do limiar, serás avisado uma vez, juntamente com a indicação de qual conta fica livre primeiro. Enquanto uma conta ativa estiver a menos de 15 pontos do seu limiar (80% no valor predefinido), os seus limites são verificados a cada três minutos em vez de a cada 15.

`omarchy agent account list` mostra todas as contas e os seus limites mais recentes, `omarchy agent account remove work` esquece uma, e `omarchy agent account rename primary Hey` muda o nome a uma (ou clica no nome de uma conta no painel). Estes comandos funcionam nas contas do teu agente predefinido; para chegares ao outro fornecedor, nomeia-o primeiro, como em `omarchy agent account use codex side`. O início de sessão que já tinhas em `~/.claude` ou `~/.codex` é a conta _Main_. A do Codex fica onde está; a do Claude espera numa pasta própria enquanto outra conta estiver ativa. Uma conta que fique sem utilização durante mais de cerca de oito horas pode mostrar _Sign-in required_; clica nela para iniciares sessão nessa conta outra vez diretamente no painel, ou alterna para ela e inicia uma sessão, o que renova o início de sessão por si só. Os servidores MCP que adicionares com `claude mcp add` chegam a todas as contas Claude, uma vez que todas funcionam em `~/.claude`; para Codex e Grok, os servidores que tinhas quando uma conta foi adicionada acompanham-na, mas os posteriores só chegam à conta em que os adicionaste. O Claude Desktop mantém um início de sessão próprio, e as ferramentas Codex ou Grok configuradas com um caminho absoluto para um binário CLI não acompanham a alternância. Um `CLAUDE_CONFIG_DIR`, `CODEX_HOME` ou `GROK_HOME` explícito tem precedência sobre a conta selecionada.

### Diagnóstico de crashes

O Omarchy vigia o systemd-coredump à procura de crashes de processos. Depois de escolheres um agente predefinido, qualquer programa teu que faça um core dump faz surgir uma notificação "Process crashed" — clica nela e o crash é entregue ao teu agente predefinido juntamente com a competência omarchy-diagnose-crash do Omarchy, que guia o agente na determinação dos factos a partir do core dump e na decisão sobre se o crash vale a pena ser comunicado a montante. Também podes executá-lo manualmente contra qualquer PID de `coredumpctl list` com `omarchy agent crash <pid>`.

A vigilância está ligada por omissão. Desliga-a em _Trigger > Toggle > Crash Capture Off_ (ou com `omarchy toggle crash-capture`) e as notificações param; `omarchy agent crash <pid>` continua a funcionar manualmente.

Os crashes também podem ser silenciados programa a programa, que é o que o diagnóstico te oferece no fim. `omarchy crash mute hyprland` para as notificações só para esse programa, `omarchy crash mute hyprland off` traz-as de volta, e `omarchy crash mute` por si só lista o que silenciaste. Aceita o caminho do binário tão bem como o seu nome, por isso `omarchy crash mute /usr/bin/hyprland` faz o mesmo. Coloca entre aspas um nome com um espaço, como em `omarchy crash mute 'Some App'`. Todo o resto continua a notificar, e o programa silenciado continua a falhar — isto esconde o lembrete, não resolve nada.

### Aplicações de ambiente de trabalho

O menu _Install > AI_ também inclui algumas aplicações gráficas de IA: Amp Desktop, Antigravity Desktop, a aplicação de ambiente de trabalho do ChatGPT, a aplicação de ambiente de trabalho do Claude (a beta para Linux da Anthropic, com separadores Chat, Cowork e Claude Code), Grok Bot para conversares com os modelos da xAI, Herdr Desktop, Hermes Desktop, OpenClaw, a aplicação de ambiente de trabalho do Perplexity e T3 Code. O Grok Bot é a aplicação de conversação de ambiente de trabalho. O agente de programação é o comando `grok`.

O Hermes Desktop é o que precisas de conhecer, porque uma máquina tem um Hermes, e é o da aplicação: o Hermes só é instalado através da aplicação, e o comando `hermes` que o agente predefinido executa é o da aplicação. Escolher o Hermes como agente predefinido instala o mesmo que a entrada _Install > AI_: o pacote e um runtime Hermes em `~/.hermes` configurado pelo próprio instalador do Hermes, o que demora alguns minutos na primeira vez. Esse runtime é o único Hermes que o comando `hermes` de terminal, o agente predefinido e a aplicação utilizam, e atualiza-se a si próprio com `hermes update` em vez de esperar por uma versão do Omarchy. Instalá-lo também entrega ao Hermes o tema Omarchy como uma skin chamada `omarchy`, que todas as superfícies do Hermes seguem à medida que mudas de tema; escolhe outra nas definições Appearance do Hermes ou com `/skin` se preferires que não o faça, e o Omarchy deixa essa escolha em paz. Remover a aplicação em _Remove > AI_ fecha primeiro o Hermes, gateway incluído, leva esse runtime com ele e mantém as tuas conversas, memórias e as competências que o Hermes escreveu para si próprio, a menos que digas o contrário: pergunta-te, com não por omissão, se esses dados e as tuas definições de ligação também devem desaparecer.

A experiência de ambiente de trabalho do OpenClaw é a sua Control UI, que abre como uma aplicação Web suportada pelo seu próprio gateway local. O OpenClaw vive em `~/.openclaw` e atualiza-se a si próprio: usa o botão "Update Gateway" da Control UI ou executa `openclaw update`, e o gateway reinicia na nova versão. O Omarchy apenas escolhe a versão a partir da qual uma instalação nova começa. O OpenClaw também pode ser o teu agente predefinido: escolhê-lo em _Agent > Harness_ configura essa mesma cópia em `~/.openclaw`, e o agente abre a interface de terminal do OpenClaw ligada ao seu gateway. Remover o OpenClaw em _Remove > AI_ leva o serviço gateway e a aplicação com ele e depois pergunta se `~/.openclaw` também deve desaparecer, uma vez que aí ficam as tuas conversas e credenciais ao lado do próprio OpenClaw e dos runtimes de plugins que descarrega; por omissão mantém-no, e instalar o OpenClaw outra vez volta a apanhá-lo.

O Herdr Desktop é a aplicação de ambiente de trabalho [Herdr](https://herdr.dev): espaços, separadores e painéis de terminais e agentes de programação que continuam a funcionar no seu núcleo quando fechas a janela. Vem do próprio instalador do Herdr e não de um pacote, por isso vive em `~/.local/share/herdr-app`, traz o seu núcleo em `~/.local/bin/herdr-core` quando ainda não tens um, e atualiza ambos por si próprio. Fica ao lado do comando `herdr` que o Omarchy disponibiliza em `Super + Ctrl + Return` em vez de o substituir, e recebe as teclas diretas desse comando: `Alt + Return` e `Alt + Shift + Return` dividem um painel para baixo ou para a direita, `Alt + Escape` fecha-o, `Ctrl + Alt + Arrow` move entre painéis, `Alt + 1..9` e `Alt + Left/Right` escolhem um separador, e `Alt + Up/Down` movem entre espaços. `Ctrl + 1..9` escolhe um espaço e `Alt + Shift + Up/Down` percorre os agentes. As teclas de prefixo `Ctrl + Space` permanecem só no terminal, uma vez que a aplicação não consegue manter uma tecla Ctrl simples para uma sequência. O Omarchy escreve estas em `~/.config/herdr-app/keys.json`, e `omarchy-refresh-herdr-app` repõe-nas. Instalá-lo escolhe o tema Omarchy do Herdr, que a partir daí segue o teu tema Omarchy. O Herdr mantém um tema para o modo claro e um para o modo escuro, por isso, depois de alternares entre um tema Omarchy escuro e um claro, escolhe Omarchy no seletor de temas do Herdr mais uma vez para o outro modo.

O T3 Code funciona a partir da sua versão oficial AppImage em `~/.local/share/t3code` e não de um pacote, por isso atualiza-se a si próprio. Instalá-lo pergunta se queres começar no canal Stable ou Nightly; muda mais tarde nas definições do T3 Code. As tuas threads e definições vivem em `~/.t3`, e remover o T3 Code em _Remove > AI_ leva-as com ele.

### Modelos locais

Executa um modelo aberto na tua própria máquina para os teus agentes de programação. Os teus prompts e código permanecem na máquina; nada do que é enviado ao modelo sai dela. Começa com:

```bash
omarchy models use best text
```

Isso configura o melhor modelo de texto para esta máquina, do tipo que os teus agentes utilizam. Os modelos de imagem, vídeo e música têm um melhor próprio: `omarchy models use best image`, `video` ou `music`. Executa `omarchy models use best` para veres a escolha de cada tipo para esta máquina.

Ou abre o painel de modelos locais a partir do seu ícone de brilhos na barra superior, ao lado do ícone de agentes, ou com Super + Ctrl + Alt + X, e escolhe +. O ícone aparece quando um modelo cabe nesta máquina. O Podman, que executa os modelos, vem com o Omarchy, tal como o kit de ferramentas de contentores da NVIDIA numa máquina NVIDIA, que lhes dá a GPU; se algum deles estiver em falta, a primeira configuração instala-o. Depois o Omarchy escolhe o modelo recomendado para esta máquina, descarrega-o e inicia-o. Espera um descarregamento de dezenas de GB e a maior parte da memória da máquina em utilização enquanto o modelo estiver a funcionar: o Flash Next usa cerca de 100 GiB com o seu contexto completo de 256K. Se outros modelos ocuparem a memória de que precisa, é configurado parado, pronto para arrancar quando parares um deles. O modelo para ao terminares a sessão; para-o tu próprio quando precisares da memória para outra coisa.

`omarchy models list` mostra as opções e explica por que motivo algumas não cabem. Para configurares outro, executa `omarchy models use <recipe>`. Hoje, `qwen3.8-flash-next-gufo` e `qwen3.8-27b-gufo` estão disponíveis para máquinas Strix Halo de 128 GB; o de 27B ocupa cerca de 40 GiB, por isso deixa espaço para outro trabalho. Num portátil de 64 GB com a Arc B390 da Intel, `qwen3.6-35b-a3b-llamacpp` funciona em cerca de 30 GiB. Novas receitas e recomendações chegam com `omarchy update`, através do pacote.

Cada modelo que configurares ganha a sua própria linha no painel de modelos locais: reproduzir para o iniciares, pausar para o parares e libertares a sua memória, e o botão de terminal para abrires o teu agente nele. Na parte superior, uma barra mostra como a memória da máquina está dividida entre o próprio Omarchy (o sistema e as tuas aplicações), cada modelo em execução e o que está livre. Aponta para um modelo parado e a barra mostra se ele cabe, ou quanto lhe falta. Vários podem funcionar ao mesmo tempo quando cabem juntos na memória; se um não couber, o Omarchy diz qual modelo em execução deves parar. Arrasta as linhas pelo seu logótipo para as reordenares e prime Delete numa linha selecionada para removeres um modelo e o seu descarregamento.

Cada modelo de programação que configurares também ganha a sua própria entrada no lançador de aplicações, com o nome do modelo e o logótipo do seu fabricante, da mesma forma que iniciar sessão no Claude, Codex ou Grok adiciona uma. Abre o teu agente nesse modelo e inicia primeiro o modelo se este não estiver a funcionar: o terminal mostra-o a carregar e entrega ao agente quando estiver pronto. Remover um modelo remove a sua entrada.

Nem todos os modelos são para programação. Os modelos de imagem, vídeo e música abrem no Fantasi, a aplicação do Omarchy para criares imagens, vídeo e música com um modelo a funcionar nesta máquina, escolhidos aí ou a partir da sua linha no painel de modelos locais.

Um modelo continua a funcionar exatamente como foi configurado, por isso uma atualização do Omarchy nunca reinicia um por baixo dos teus agentes. Quando o Omarchy tem um runtime mais recente ou pesos mais recentes para um modelo que configuraste, a sua linha mostra um botão de atualização: prime-o e o modelo é configurado outra vez em segundo plano, descarregando apenas o que mudou, e reinicia na nova versão. Um modelo que estava parado permanece parado. `omarchy models update` faz o mesmo para todos os modelos a partir de um terminal.

A partir da linha de comandos, `omarchy models start <recipe>` e `omarchy models stop <recipe>` fazem o mesmo, `omarchy models status` mostra todos os modelos, e `omarchy agent --local` abre o último modelo que iniciaste no pi, qualquer que seja o teu agente predefinido. O OpenCode e o Qwen Code também podem usar um modelo local: `omarchy models harness opencode` ou `omarchy models harness qwen` abre-os aí, e `omarchy models harness pi` volta atrás. O pi também lista todos os modelos que configuraste, e os que estão em máquinas com as quais emparelhaste, no seu próprio seletor de modelos, por isso um simples `pi` também chega até eles. Qualquer cliente compatível com OpenAI também pode ligar-se: `status` mostra o endereço de cada modelo (o primeiro é `http://127.0.0.1:11435/v1`), o nome da receita é o modelo, e a chave está em `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` elimina um modelo e os descarregamentos que nenhum outro modelo utiliza.

Os runtimes de terceiros são identificados com o respetivo editor. O Omarchy executa todos os modelos sem acesso à rede.

### LLM locais

O Omarchy recomenda duas formas de executares modelos LLM locais: LM Studio e Ollama. O LM Studio fornece uma interface gráfica para encontrares modelos de pesos abertos, instalá-los e executá-los. É uma ótima forma de começares facilmente. O Ollama oferece uma CLI para fazeres o mesmo de forma semelhante. Mas se és novo nos modelos locais, eu começaria pelo LM Studio. Podes instalar qualquer um deles em _Install > AI_ no Menu Omarchy.

### As competências do Omarchy

As competências de agente ajudam a IA a usar ferramentas específicas de uma forma específica, e o Omarchy inclui sete delas. A competência omarchy abrange a personalização do sistema, como ajustar a tua configuração do Hyprland ou regular a barra. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app e omarchy-make-game abrangem a criação de algo novo, omarchy-contribute abrange a comunicação de um erro ou o envio de uma correção a montante, e omarchy-diagnose-crash analisa o core dump de um crash. São ligadas por symlinks aos diretórios de competências do Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` e cada `~/.hermes/profiles/*/skills`) e à localização genérica `~/.agents/skills`, por isso a maioria dos harnesses apanha-as automaticamente. Uma pasta de competências tua com o mesmo nome tem precedência.

Mas deves tratar estas competências como experimentais. Modelos diferentes vão utilizá-las com efeitos diferentes. É melhor funcionares primeiro em modo de plano, para teres uma ideia do que o agente gostaria de mudar. E depois prepara-te para reverteres alterações ou até invocares `omarchy reinstall configs`, se o agente fizer uma confusão com tudo.
