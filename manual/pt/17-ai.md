# IA

O Omarchy inclui lançadores para os agentes de programação abaixo sem escolher um predefinido por si. Execute um comando para instalar a respetiva CLI na primeira utilização e, em seguida, autentique-se quando lhe for pedido. O Hermes é a exceção: nada é instalado para ele na primeira utilização, e escolhê-lo instala o Hermes Desktop, como explica _Aplicações de ambiente de trabalho_ abaixo.

### Instalar e atualizar agentes

Exceto o Hermes, estes agentes utilizam a instalação diferida do mise: o primeiro lançamento instala a CLI, e os lançamentos posteriores reutilizam-na. O mise também verifica se um agente instalado tem uma nova versão, no máximo uma vez de quatro em quatro horas, mesmo antes de arrancar ou em segundo plano num prompt da shell. Se essa atualização falhar ou estiver offline, a versão instalada é executada. O `omarchy update` atualiza os agentes instalados com o resto do Omarchy, e o `mup` atualiza apenas as ferramentas geridas pelo mise.

O próprio atualizador de um agente, como `claude update`, `codex update` ou um botão de atualização numa aplicação, não atualiza a instalação gerida pelo mise. O `codex update` falha, e o `claude update` pode reportar sucesso enquanto instala uma cópia separada que o mise não acompanha. Se preferir utilizar o instalador e o atualizador nativos de um agente, adicione-o a `disable_tools`; consulte [Ferramentas CLI pré-instaladas](18-development-tools.md#preinstalled-cli-tools).

Para instalar todas as ferramentas diferidas configuradas antes de precisar delas, execute `mise install --include-lazy`. Isto inclui as outras ferramentas CLI predefinidas do Omarchy, bem como os agentes. Consulte [Ferramentas CLI pré-instaladas](18-development-tools.md#preinstalled-cli-tools) para instalar uma única ferramenta ou utilizar a sua própria instalação.

O `grok` é instalado através do pacote `grok` próprio do mise, da mesma forma que o `claude` e o `codex`. Execute `grok`, ou escolha-o em _Configuração > Predefinições > Agente_. Ignore o instalador `curl | bash` em x.ai. Esse caminho coloca uma segunda cópia em `~/.grok/bin`, coloca-a no início do `PATH` e sobrescreve o wrapper do Omarchy.

O `dsh` abre a sua interface de browser em `127.0.0.1:3080`, com o diretório de lançamento como o seu espaço de trabalho predefinido. A sua interface de browser não aceita um prompt inicial, por isso `omarchy agent prompt` abre-a com o prompt na sua área de transferência para colar. O Omarchy inicia-o com a predefinição de permissões sem aprovação da DeepSeek. O DeepSeek Harness carrega registos de sessão para a DeepSeek quando utiliza a API oficial do modelo; desative isso em _Definições > Geral > Upload Session Log_ na sua interface de browser. O feedback que lhe enviar também é carregado com a sessão, a menos que o inicie com `DSH_TELEMETRY_MODE=DISABLED`.

### O agente predefinido

Escolha o seu agente predefinido com `omarchy default agent <name>` ou em _Configuração > Predefinições > Agente_ no Menu Omarchy (`Super + Space`). Se o agente ainda não estiver instalado, escolhê-lo instala-o primeiro. Um Omarchy novo vai convidá-lo a fazer esta escolha com uma notificação única.

Escolher o Claude também tenta configurar a sua extensão de browser para Chromium, Chrome, Brave, Brave Origin e Edge. A configuração da extensão aplica-se a todos os utilizadores e pode pedir a sua palavra-passe do sistema; cancelar ou uma instalação da extensão falhada continua a selecionar e a iniciar o Claude. Reinicie o browser, ative a extensão se lhe for pedido e inicie sessão no Claude para terminar a ligação. Execute `/chrome` no Claude para verificar a ligação. O Firefox e o Zen não suportam esta extensão. Se o Claude já era o seu predefinido antes de esta configuração ser adicionada, selecione-o novamente para instalar a extensão.

Depois de escolher, `Super + Shift + Ctrl + A` inicia o agente predefinido numa janela de terminal dedicada (ou abre o seletor se ainda não tiver escolhido). Também pode iniciá-lo diretamente numa tarefa com `omarchy agent prompt "Review this project"`. O Freebuff e o DeepSeek Harness não aceitam um prompt inicial, por isso abrem com o prompt na sua área de transferência para colar. Os agentes iniciados desta forma executam sem supervisão nos respetivos modos de não parar para perguntar, por isso esteja pronto para eles fazerem mesmo coisas! O MiniMax Code não tem esse modo para as suas sessões interativas, por isso pede permissões como habitualmente. E como os agentes se recusam a memorizar confiança para o seu diretório pessoal, os lançamentos a partir de `$HOME` começam antes em `~/Work`.

Também existem atalhos de terminal: `a` executa o agente predefinido em linha no terminal atual, enquanto `c`, `cx` e `cy` iniciam o OpenCode, o Claude Code e o Codex diretamente (novamente nos seus modos de aprovação automática). As mudanças de tema também se sincronizam com os agentes: o Claude Code, o Pi, o OpenCode e o Hermes (depois de o Omarchy o ter instalado) acompanham todos quando muda o tema do Omarchy.

### O painel de agentes

A barra superior tem um ícone de agentes. Antes de ter configurado um agente, o seu painel guia-o pelo início de sessão no Claude, no Codex ou no Grok, e o primeiro torna-se o seu agente predefinido. Depois disso, o painel coloca todas as subscrições numa página: cada agente e conta com o seu plano, um medidor para cada um dos seus limites de sessão de 5 horas e semanais com o tempo até reiniciar (passe o cursor por cima para ver a percentagem exata), ou o saldo pré-pago restante, sob uma linha que roda pelo que utilizou em todos eles, como tokens esta semana e o seu modelo mais utilizado. Em _Criar algo_, oferece prompts iniciais para um novo tema, plugin ou aplicação que entregam a tarefa ao seu agente predefinido. As aplicações são construídas da forma como as próprias Hype, Monologue e Omacut do Omarchy são, em C++ e Qt Quick, seguindo a skill de agente omarchy-app, e o compilador e as peças Qt de que precisam vêm instalados. O Claude Code, o Codex, o Grok, o Kimi, o Cursor e a sua quota Grok Bot, o GitHub Copilot, o Muse, o Antigravity, o Kimchi e o Devin estão cobertos de origem com os seus limites, e o Hermes, o Mistral Vibe e o Qwen Code mostram as suas sessões e tokens depois de os ter utilizado. Os planos de fornecedor e as chaves que utiliza através do pi, do omp ou do opencode também aparecem: o OpenCode Zen e Go, o Z.ai GLM Coding Plan, a Ollama Cloud, o MiniMax Token Plan e o Synthetic com os seus limites; o Fireworks, a OpenRouter e a DeepSeek com os seus saldos pré-pagos; e os modelos que executa no seu próprio hardware em Local models. Cada agente é contado uma vez, sob quem o fatura, por quantos harnesses o conduza.

Clique com o botão esquerdo no ícone da barra para abrir o painel, clique com o botão direito para iniciar o seu agente predefinido. Os registos de utilização por trás dele são regenerados de 15 em 15 minutos por `omarchy agent usage-update`, e o painel pode até fundir a utilização das suas outras máquinas através de uma pasta sincronizada. Consulte o README em `$OMARCHY_PATH/shell/plugins/agents/` para as definições completas.

### Várias subscrições

Se pagar mais do que um plano Claude, Codex ou Grok — um Max pessoal e um de trabalho, por exemplo — o Omarchy pode manter todos com sessão iniciada e mover-se entre eles. Adicione uma subscrição com o + no painel de agentes, que o guia pelo processo mesmo ali, ou com `omarchy agent account add claude Work` (ou `codex`, ou `grok`). Instala a CLI se estiver em falta. A primeira conta de um fornecedor inicia sessão através do seu browser normal, exatamente onde a CLI sempre procura. Todas as seguintes iniciam sessão através de uma janela privada, para que a conta em que o seu browser já tem sessão iniciada não seja apanhada por engano; inicie sessão aí como a conta que está a adicionar e feche primeiro qualquer janela privada que já tenha aberta. Nunca termine sessão na CLI para fazer isto: terminar sessão revoga o início de sessão guardado, e essa conta teria de ser adicionada novamente.

Para copiar os seus inícios de sessão de subscrição para outra máquina Omarchy por SSH, execute `omarchy agent account copy user@laptop`. O remetente fornece um recetor temporário quando o destino não tem um instalado, por isso máquinas Omarchy mais antigas podem receber contas sem uma atualização. Os recetores instalados têm precedência. Isto copia todas as subscrições Claude, Codex e Grok; adicione nomes de fornecedor para as selecionar, como em `omarchy agent account copy laptop claude`. Os nomes de conta e os IDs de comando correspondem à origem, incluindo contas já presentes no destino. Contas de destino não relacionadas recebem um sufixo numérico se os seus nomes entrarem em conflito, e as definições, skills, plugins e histórico de conversas permanecem locais em cada máquina.

As credenciais de destino existentes são mantidas. Uma conta de origem que já tenha sessão iniciada lá tem o seu nome sincronizado sem substituir as suas credenciais; outras contas são adicionadas ao lado dela. Para substituir credenciais guardadas de contas correspondentes, utilize `omarchy agent account copy --replace laptop claude` depois de sair das sessões dessa conta no destino. Um destino novo também recebe a conta ativa e as preferências de troca da origem; um destino estabelecido mantém as suas.

As credenciais viajam por SSH e são armazenadas em ficheiros privados no destino, por isso copie apenas para máquinas em que confia. Isto é uma cópia única, não uma sincronização contínua. Os tokens de atualização do Codex podem ser rodados por outra máquina, deixando um início de sessão copiado a precisar de renovação; inícios de sessão separados continuam a ser a escolha mais fiável para utilização simultânea em várias máquinas. Consulte as [orientações de autenticação de conta do Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Uma conta por fornecedor está ativa, e cada nova sessão começa como ela: `cx`, `cy`, um simples `claude`, `codex` ou `grok`, qualquer coisa iniciada através de `omarchy agent`, e scripts ou editores que encontrem a CLI no `PATH`. Mude com `omarchy agent account use work` (e volte com `omarchy agent account use main`), ou no painel premindo o número de uma conta e depois `Enter` (ou clicando no seu botão Use). As sessões que já estão a executar permanecem na conta com que começaram. O histórico de conversas, as definições, as skills e os plugins são partilhados entre contas, por isso `claude --continue` na mesma pasta continua onde parou na nova conta.

Com mais de uma conta, o painel mostra os limites de cada conta lado a lado, com a ativa marcada. Por predefinição, o Omarchy notifica-o quando a conta ativa passa 95% de um limite, e clicar na notificação muda para a conta com mais margem. Passe o cursor sobre a linha de uma conta no painel e clique no Autoswitch que aparece ao lado de Use (ou prima `m`), ou execute `omarchy agent account mode auto`, para que mude sozinho; enquanto estiver ligado, o Autoswitch toma o lugar de Use, e clicar nele novamente volta a notificar. Adicione um número para mudar o limiar, como em `omarchy agent account mode auto 90`. Se todas as contas estiverem acima do limiar, será informado uma vez, juntamente com qual conta fica livre primeiro. Enquanto uma conta ativa estiver a menos de 15 pontos do seu limiar (80% na predefinição), os seus limites são verificados de três em três minutos em vez de de 15 em 15.

O `omarchy agent account list` mostra todas as contas e os seus limites mais recentes, o `omarchy agent account remove work` esquece uma, e o `omarchy agent account rename primary Hey` muda o nome de uma (ou clique no nome de uma conta no painel). Estes comandos funcionam nas contas do seu agente predefinido; para chegar ao outro fornecedor, nomeie-o primeiro, como em `omarchy agent account use codex side`. O início de sessão que já tinha em `~/.claude` ou `~/.codex` é a conta _Main_ e fica onde está. Uma conta deixada sem utilização durante mais de cerca de oito horas pode mostrar _Sign-in required_; clique nela para iniciar sessão nessa conta novamente no painel, ou inicie uma sessão nela, o que atualiza o início de sessão por si só. Os servidores MCP que tinha quando uma conta foi adicionada acompanham-na, mas os que adicionar depois com `claude mcp add` só chegam à conta em que os adicionou. O Claude Desktop e ferramentas configuradas com um caminho absoluto para um binário CLI não seguem a mudança. Um `CLAUDE_CONFIG_DIR`, `CODEX_HOME` ou `GROK_HOME` explícito tem precedência sobre a conta selecionada.

### Diagnóstico de falhas

O Omarchy observa o systemd-coredump quanto a falhas de processos. Quando algo faz segfault, receberá uma notificação "Process crashed" — clique nela, e a falha é entregue ao seu agente predefinido juntamente com a skill diagnose-crash do Omarchy, que guia o agente pelo estabelecimento dos factos a partir do core dump e pela decisão sobre se a falha vale a pena reportar upstream. Também pode executá-lo manualmente contra qualquer PID de `coredumpctl list` com `omarchy agent crash <pid>`.

A observação está ligada por predefinição. Desligue-a em _Acionador > Alternar > Captura de Falhas_ (ou com `omarchy toggle crash-capture`) e as notificações param; o `omarchy agent crash <pid>` continua a funcionar manualmente.

As falhas também podem ser silenciadas um programa de cada vez, que é o que o diagnóstico lhe oferece no fim. O `omarchy crash mute hyprland` para as notificações só para esse programa, o `omarchy crash mute hyprland off` traz-as de volta, e o `omarchy crash mute` sozinho lista o que silenciou. Aceita o caminho do binário tão bem como o seu nome, por isso `omarchy crash mute /usr/bin/hyprland` faz o mesmo. Coloque entre aspas um nome com um espaço, como em `omarchy crash mute 'Some App'`. Tudo o resto continua a notificar, e o programa silenciado continua a falhar — isto esconde o lembrete, não resolve nada.

### Aplicações de ambiente de trabalho

O menu _Instalar > IA_ também traz algumas aplicações gráficas de IA: a aplicação de ambiente de trabalho do ChatGPT, a aplicação de ambiente de trabalho do Claude (a beta Linux da Anthropic, com separadores Chat, Cowork e Claude Code), o Grok Bot para conversar com os modelos da xAI, o Herdr Desktop, o Hermes Desktop, o OpenClaw, a aplicação de ambiente de trabalho do Perplexity e o T3 Code. O Grok Bot é a aplicação de chat de ambiente de trabalho. O agente de programação é o comando `grok`.

O Hermes Desktop é o que importa conhecer, porque uma máquina tem um Hermes, e é o da aplicação: o Hermes só é alguma vez instalado através da aplicação, e o comando `hermes` que o agente predefinido executa é o da aplicação. Escolher o Hermes como agente predefinido instala o mesmo que a entrada _Instalar > IA_ instala: o pacote, e um runtime Hermes em `~/.hermes` configurado pelo próprio instalador do Hermes, o que demora alguns minutos na primeira vez. Esse runtime é o único Hermes que o comando `hermes` do terminal, o agente predefinido e a aplicação utilizam, e atualiza-se a si próprio com `hermes update` em vez de esperar por uma versão do Omarchy. Instalá-lo também entrega ao Hermes o tema Omarchy como uma skin chamada `omarchy`, que todas as superfícies Hermes seguem à medida que muda de tema; escolha outra nas definições de Appearance do Hermes ou com `/skin` se preferir que não o faça, e o Omarchy deixa essa escolha em paz. Remover a aplicação em _Remover > IA_ fecha primeiro o Hermes, gateway incluída, leva esse runtime consigo e mantém as suas conversas, memórias e as skills que o Hermes escreveu para si próprio, a menos que lhe diga o contrário: pergunta, com não como predefinição, se esses dados e as suas definições de ligação também devem ir.

A experiência de ambiente de trabalho do OpenClaw é a sua Control UI, que abre como uma aplicação web apoiada pela sua própria gateway local. O OpenClaw vive em `~/.openclaw` e atualiza-se a si próprio: utilize o botão "Update Gateway" da Control UI ou execute `openclaw update`, e a gateway reinicia na nova versão. O Omarchy só escolhe a versão a partir da qual uma instalação nova começa. Remover o OpenClaw em _Remover > IA_ leva o serviço de gateway e a aplicação consigo e depois pergunta se `~/.openclaw` também deve ir, uma vez que guarda as suas conversas e credenciais juntamente com o próprio OpenClaw e os runtimes de plugins que descarrega; a predefinição mantém-no, e instalar o OpenClaw novamente volta a apanhá-lo.

O Herdr Desktop é a aplicação de ambiente de trabalho [Herdr](https://herdr.dev): espaços, separadores e painéis de terminais e agentes de programação que continuam a executar no seu núcleo quando fecha a janela. Vem do próprio instalador do Herdr em vez de um pacote, por isso vive em `~/.local/share/herdr-app`, traz o seu núcleo em `~/.local/bin/herdr-core` quando ainda não tem um, e atualiza ambos. Fica ao lado do comando `herdr` que o Omarchy fornece em `Super + Ctrl + Return` em vez de o substituir. Instalá-lo escolhe o tema Omarchy do Herdr, que segue o seu tema Omarchy a partir daí. O Herdr mantém um tema para o modo claro e um para o modo escuro, por isso, depois de mudar entre um tema Omarchy escuro e um claro, escolha Omarchy no seletor de temas do Herdr mais uma vez para o outro modo.

O T3 Code executa a partir da sua versão oficial AppImage em `~/.local/share/t3code` em vez de a partir de um pacote, por isso atualiza-se a si próprio. Instalá-lo pergunta se deve começar no canal Stable ou Nightly; mude depois nas definições do T3 Code. Os seus tópicos e definições vivem em `~/.t3`, e remover o T3 Code em _Remover > IA_ leva-os consigo.

### Modelos locais

Execute um modelo aberto na sua própria máquina para os seus agentes de programação. Os seus prompts e código permanecem na máquina; nada do que é enviado ao modelo sai dela. Comece com:

```bash
omarchy agent local use best
```

Ou, no painel de agentes na barra superior, escolha + e depois Local AI, que aparece quando um modelo cabe nesta máquina. Na primeira vez, isto instala o Podman, que executa os modelos, e numa máquina NVIDIA o toolkit de contentores NVIDIA, que lhes dá a GPU. O Omarchy escolhe depois o modelo recomendado para esta máquina, descarrega-o e inicia-o. Espere uma transferência de dezenas de GB e a maior parte da memória da máquina em uso enquanto o modelo está a executar: o Flash Next utiliza cerca de 100 GiB com o seu contexto completo de 256K. Se outros modelos ocuparem a memória de que precisa, é configurado parado, pronto para iniciar depois de parar um. O modelo para ao terminar sessão; pare-o você mesmo quando precisar da memória para outra coisa.

O `omarchy agent local list` mostra as opções e explica por que algumas não cabem. Para configurar outro, execute `omarchy agent local use <recipe>`. Hoje, `qwen3.8-flash-next-gufo` e `qwen3.8-27b-gufo` estão disponíveis para máquinas Strix Halo de 128 GB; o 27B ocupa cerca de 40 GiB, por isso deixa espaço para outro trabalho. Novas receitas e recomendações chegam com `omarchy update`, através do pacote.

Cada modelo que configurar tem a sua própria linha no painel de agentes, ao lado das suas subscrições: play para o iniciar, pause para o parar e libertar a sua memória, e o botão de terminal para abrir o seu agente nele. Vários podem executar ao mesmo tempo quando cabem juntos na memória; se um não couber, o Omarchy diz que modelo em execução parar. Arraste linhas para as reordenar e prima Delete numa linha selecionada para remover um modelo e a sua transferência.

A partir da linha de comandos, `omarchy agent local start <recipe>` e `omarchy agent local stop <recipe>` fazem o mesmo, `omarchy agent local status` mostra todos os modelos, e `omarchy agent --local` abre o seu agente predefinido no último modelo que iniciou (pi se o seu agente predefinido não puder utilizar um modelo local). Qualquer cliente compatível com OpenAI também pode ligar-se: `status` mostra o endereço de cada modelo (o primeiro é `http://127.0.0.1:11435/v1`), o nome da receita é o modelo, e a chave está em `~/.config/omarchy/agent-local/key`.

O `omarchy agent local remove <recipe>` elimina um modelo e as transferências que nenhum outro modelo utiliza.

Os runtimes de terceiros são etiquetados com o seu editor. O Omarchy executa todos os modelos sem acesso à rede.

### LLMs locais

O Omarchy recomenda duas formas de executar modelos LLM locais: o LM Studio e o Ollama. O LM Studio fornece uma interface GUI para encontrar modelos de pesos abertos, instalá-los e executá-los. É uma ótima forma de começar facilmente. O Ollama oferece uma CLI para fazer o mesmo. Mas se é novo nos modelos locais, eu começaria pelo LM Studio. Pode instalar qualquer um em _Instalar > IA_ no Menu Omarchy.

### A Skill Omarchy

As skills de agente ajudam a IA a utilizar ferramentas específicas de uma forma específica, e o Omarchy vem com uma skill predefinida para adaptar o sistema. Como ajustar a sua config Hyprland, ajustar a barra, ou até criar um novo tema de raiz. Está ligada por symlink aos diretórios de skills para o Claude Code (`~/.claude/skills`), o Codex (`~/.codex/skills`), o Pi (`~/.pi/agent/skills`), o Antigravity (`~/.gemini/config/skills`), o Hermes (`~/.hermes/skills` e cada `~/.hermes/profiles/*/skills`), e a localização genérica `~/.agents/skills`, por isso a maioria dos harnesses apanha-a automaticamente.

Mas deve tratar esta skill como experimental. Modelos diferentes vão utilizá-la com efeitos diferentes. É melhor executar primeiro em modo de plano, para ter uma ideia do que o agente gostaria de mudar. E depois estar pronto para reverter mudanças ou até invocar `omarchy reinstall configs`, se o agente fizer uma confusão de tudo.
