# IA

Execute um comando para instalar a respetiva CLI na primeira utilização e, em seguida, autentique-se quando lhe for pedido. O Hermes é a exceção: nada é instalado para ele na primeira utilização, e escolhê-lo instala o Hermes Desktop, como explica a secção _Aplicações de ambiente de trabalho_ abaixo.

### Instalar e atualizar agentes

Exceto o Hermes, estes agentes usam a instalação lazy do mise: o primeiro arranque instala a CLI, e os arranques seguintes reutilizam-na. O mise também verifica se um agente instalado tem uma nova versão, no máximo uma vez a cada quatro horas, imediatamente antes de arrancar ou em segundo plano numa prompt da shell. Se essa atualização falhar ou se estiver offline, é executada a versão instalada. `omarchy update` atualiza os agentes instalados com o resto do Omarchy, e `mup` atualiza apenas as ferramentas geridas pelo mise.

Um atualizador próprio de um agente, como `claude update`, `codex update` ou um botão de atualização numa aplicação, não atualiza a instalação gerida pelo mise. `codex update` falha, e `claude update` pode comunicar sucesso ao mesmo tempo que instala uma cópia separada que o mise não acompanha. Se preferir usar o instalador e o atualizador nativos de um agente, adicione-o a `disable_tools`; consulte [Ferramentas CLI pré-instaladas](18-development-tools.md#preinstalled-cli-tools).

Para instalar antecipadamente todas as ferramentas lazy configuradas, execute `mise install --include-lazy`. Isto inclui as outras ferramentas CLI predefinidas do Omarchy, bem como os agentes. Consulte [Ferramentas CLI pré-instaladas](18-development-tools.md#preinstalled-cli-tools) para instalar uma única ferramenta ou usar a sua própria instalação.

O `grok` é instalado através do pacote first-party `grok` do mise, da mesma forma que `claude` e `codex`. Execute `grok` ou escolha-o em _Setup > Defaults > Agent_. Ignore o instalador `curl | bash` em x.ai. Esse caminho coloca uma segunda cópia em `~/.grok/bin`, coloca-a no início do `PATH` e substitui o wrapper do Omarchy.

O `dsh` abre a sua interface de navegador em `127.0.0.1:3080`, com o diretório de arranque como espaço de trabalho predefinido. A interface de navegador não aceita um prompt inicial, por isso `omarchy agent prompt` abre-o com o prompt na área de transferência para colar. O Omarchy arranca-o com a predefinição de permissões sem aprovação da DeepSeek. O DeepSeek Harness envia registos de sessão para a DeepSeek quando utiliza a API oficial de modelos da DeepSeek; desative essa opção em _Settings > General > Upload Session Log_ na respetiva interface de navegador. O feedback que enviar também é enviado com a sessão, a menos que o inicie com `DSH_TELEMETRY_MODE=DISABLED`.

### O agente predefinido

Escolha o seu agente predefinido com `omarchy default agent <name>` ou em _Setup > Defaults > Agent_ no Menu Omarchy (`Super + Space`). Se o agente ainda não estiver instalado, o facto de o escolher instala-o primeiro. Uma instalação nova do Omarchy convida a fazer esta escolha com uma notificação única.

Ao escolher o Claude, tenta também configurar a respetiva extensão de navegador para Chromium, Chrome, Brave, Brave Origin e Edge. A configuração da extensão aplica-se a todos os utilizadores e pode pedir a palavra-passe do sistema; cancelar ou uma instalação falhada da extensão continua a selecionar e a iniciar o Claude. Reinicie o navegador, ative a extensão se lhe for pedido e inicie sessão no Claude para concluir a ligação. Execute `/chrome` no Claude para verificar a ligação. O Firefox e o Zen não suportam esta extensão. Se o Claude já era o seu predefinido antes de esta configuração ser adicionada, selecione-o novamente para instalar a extensão.

Depois de escolher, `Super + Shift + Ctrl + A` inicia o agente predefinido numa janela de terminal dedicada (ou apresenta o seletor se ainda não tiver escolhido). Também pode iniciá-lo diretamente numa tarefa com `omarchy agent prompt "Review this project"`. O Freebuff e o DeepSeek Harness não aceitam um prompt inicial, por isso abrem com o prompt na área de transferência para colar. Os agentes iniciados desta forma funcionam sem supervisão nos respetivos modos de não parar para perguntar, por isso esteja preparado para eles fazerem mesmo coisas! O MiniMax Code não tem esse modo para as suas sessões interativas, por isso pede permissões como habitualmente. E, como os agentes se recusam a memorizar a confiança no seu diretório pessoal, os arranques a partir de `$HOME` começam, em vez disso, em `~/Work`.

Também existem atalhos de terminal: `a` executa o agente predefinido diretamente no terminal atual, enquanto `c`, `cx` e `cy` iniciam diretamente OpenCode, Claude Code e Codex (também nos respetivos modos de aprovação automática). As alterações de tema também são sincronizadas com os agentes: Claude Code, Pi, OpenCode e Hermes (depois de o Omarchy o ter instalado) acompanham quando muda o tema do Omarchy.

### O painel de agentes

A barra superior tem um ícone de agentes. Antes de configurar um agente, o respetivo painel acompanha-o ao longo do início de sessão no Claude, Codex ou Grok, e o primeiro torna-se o seu agente predefinido. Depois disso, o painel reúne todas as subscrições numa única página: cada agente e conta com o respetivo plano, um medidor para cada um dos seus limites de sessão de 5 horas e semanal com o tempo até ser reposto (passe o cursor por cima para ver a percentagem exata), ou o saldo pré-pago restante, sob uma linha que alterna entre aquilo que utilizou em todos eles, como tokens esta semana e o seu modelo mais utilizado. Em _Make something_, oferece prompts iniciais para um novo tema, plugin ou aplicação que entregam a tarefa ao seu agente predefinido. As aplicações são construídas da forma como as próprias Hype, Monologue e Omacut do Omarchy são, em C++ e Qt Quick, a seguir a skill de agente omarchy-app, e o compilador e os componentes Qt de que precisam já vêm instalados. Claude Code, Codex, Grok, Kimi, Cursor e a sua quota do Grok Bot, GitHub Copilot, Muse, Antigravity, Kimchi e Devin estão cobertos de origem com os respetivos limites, e Hermes, Mistral Vibe e Qwen Code mostram as suas sessões e tokens depois de os utilizar. Os planos e chaves de fornecedores que utiliza através de pi, omp ou opencode também aparecem: OpenCode Zen e Go, o Z.ai GLM Coding Plan, Ollama Cloud, o MiniMax Token Plan e Synthetic com os respetivos limites; Fireworks, OpenRouter e DeepSeek com os respetivos saldos pré-pagos; e os modelos que executa no seu próprio hardware em Local models. Cada agente é contado uma única vez, sob a entidade que o fatura, independentemente do número de harnesses através dos quais o utiliza.

Clique com o botão esquerdo no ícone da barra para abrir o painel, clique com o botão direito para iniciar o seu agente predefinido. Os registos de utilização subjacentes são regenerados a cada 15 minutos por `omarchy agent usage-update`, e o painel pode até fundir a utilização de outras máquinas suas através de uma pasta sincronizada. Consulte o README em `$OMARCHY_PATH/shell/plugins/agents/` para ver todas as definições.

### Várias subscrições

Se pagar mais do que um plano Claude, Codex ou Grok — um Max pessoal e um do trabalho, por exemplo —, o Omarchy pode manter todos com sessão iniciada e alternar entre eles. Adicione uma subscrição com o + no painel de agentes, que o acompanha no processo ali mesmo, ou com `omarchy agent account add claude Work` (ou `codex`, ou `grok`). Instala a CLI se ela estiver em falta. A primeira conta de um fornecedor inicia sessão através do seu navegador normal, exatamente onde a CLI sempre procura. Todas as seguintes iniciam sessão através de uma janela privada, para que a conta em que o seu navegador já tem sessão iniciada não seja apanhada por engano; inicie sessão aí como a conta que está a adicionar e feche antecipadamente qualquer janela privada que já tenha aberta. Nunca termine sessão na CLI para fazer isto: terminar sessão revoga o início de sessão guardado, e essa conta teria de ser adicionada novamente.

Para copiar os seus inícios de sessão de subscrição para outra máquina Omarchy através de SSH, execute `omarchy agent account copy user@laptop`. Quem envia fornece um recetor temporário quando o destino não tem um instalado, por isso máquinas Omarchy mais antigas podem receber contas sem uma atualização. Os recetores instalados têm precedência. Isto copia todas as subscrições Claude, Codex e Grok; adicione nomes de fornecedores para as selecionar, como em `omarchy agent account copy laptop claude`. Os nomes das contas e os IDs de comando correspondem à origem, a incluir contas já presentes no destino. Contas de destino não relacionadas recebem um sufixo numérico se os seus nomes entrarem em conflito, e as definições, skills, plugins e o histórico de conversas permanecem locais em cada máquina.

As credenciais de destino existentes são mantidas. Uma conta de origem que já tenha sessão iniciada aí vê o seu nome sincronizado sem substituir as suas credenciais; as outras contas são adicionadas ao lado dela. Para substituir as credenciais guardadas de contas correspondentes, utilize `omarchy agent account copy --replace laptop claude` depois de sair das sessões dessa conta no destino. Um destino novo também recebe a conta ativa e as preferências de alternância da origem; um destino já estabelecido mantém as suas.

As credenciais viajam através de SSH e são guardadas em ficheiros privados no destino, por isso copie apenas para máquinas em que confia. Isto é uma cópia única, não uma sincronização contínua. Os tokens de atualização do Codex podem ser rodados por outra máquina, o que deixa um início de sessão copiado a precisar de renovação; inícios de sessão separados continuam a ser a escolha mais fiável para utilização simultânea em várias máquinas. Consulte [o guia de autenticação de contas do Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Uma conta por fornecedor está ativa, e cada nova sessão começa como ela: `cx`, `cy`, um simples `claude`, `codex` ou `grok`, qualquer coisa iniciada através de `omarchy agent`, e scripts ou editores que encontrem a CLI no `PATH`. Alterne com `omarchy agent account use work` (e volte com `omarchy agent account use main`), ou no painel, ao premir o número de uma conta e depois `Enter` (ou ao clicar no seu botão Use). As sessões já em execução permanecem na conta com que começaram. O histórico de conversas, as definições, skills e plugins são partilhados entre contas, por isso `claude --continue` na mesma pasta retoma onde ficou na nova conta.

Com mais do que uma conta, o painel mostra os limites de cada conta lado a lado, com a ativa assinalada. Por predefinição, o Omarchy notifica-o quando a conta ativa ultrapassa 95% de um limite, e clicar na notificação muda para a conta com mais margem. Passe o cursor sobre a linha de uma conta no painel e clique em Autoswitch, que aparece ao lado de Use (ou prima `m`), ou execute `omarchy agent account mode auto`, para que mude sozinho; enquanto estiver ativo, Autoswitch ocupa o lugar de Use, e clicar novamente volta ao modo de notificação. Adicione um número para alterar o limiar, como em `omarchy agent account mode auto 90`. Se todas as contas estiverem acima do limiar, recebe um único aviso, juntamente com a indicação de qual conta fica livre primeiro. Enquanto uma conta ativa estiver a menos de 15 pontos do seu limiar (80% no valor predefinido), os seus limites são verificados a cada três minutos, em vez de a cada 15.

`omarchy agent account list` mostra todas as contas e os seus limites mais recentes, `omarchy agent account remove work` esquece uma, e `omarchy agent account rename primary Hey` muda o nome de uma (ou clique no nome de uma conta no painel). Estes comandos funcionam nas contas do seu agente predefinido; para chegar ao outro fornecedor, indique-o primeiro, como em `omarchy agent account use codex side`. O início de sessão que já tinha em `~/.claude` ou `~/.codex` é a conta _Main_ e permanece onde está. Uma conta que fique sem utilização durante mais de cerca de oito horas pode mostrar _Sign-in required_; clique nela para iniciar sessão novamente nessa conta diretamente no painel, ou inicie uma sessão nela, o que atualiza o início de sessão por si só. Os servidores MCP que tinha quando uma conta foi adicionada acompanham-na, mas os que adicionar mais tarde com `claude mcp add` só chegam à conta em que os adicionou. O Claude Desktop e ferramentas configuradas com um caminho absoluto para um binário da CLI não acompanham a mudança. Um `CLAUDE_CONFIG_DIR`, `CODEX_HOME` ou `GROK_HOME` explícito tem precedência sobre a conta selecionada.

### Diagnóstico de crashes

O Omarchy observa o systemd-coredump à procura de crashes de processos. Quando algo faz segfault, recebe uma notificação "Process crashed" — clique nela e o crash é entregue ao seu agente predefinido juntamente com a skill diagnose-crash do Omarchy, que acompanha o agente ao estabelecer os factos a partir do core dump e ao decidir se vale a pena comunicar o crash a montante. Também pode executá-lo manualmente contra qualquer PID de `coredumpctl list` com `omarchy agent crash <pid>`.

A observação está ativa por predefinição. Desative-a em _Trigger > Toggle > Crash Capture_ (ou com `omarchy toggle crash-capture`) e as notificações param; `omarchy agent crash <pid>` continua a funcionar manualmente.

Os crashes também podem ser silenciados programa a programa, que é o que o diagnóstico lhe oferece no fim. `omarchy crash mute hyprland` para as notificações apenas para esse programa, `omarchy crash mute hyprland off` volta a ativá-las, e `omarchy crash mute` por si só lista o que silenciou. Aceita o caminho do binário tão bem como o seu nome, por isso `omarchy crash mute /usr/bin/hyprland` faz o mesmo. Coloque entre aspas um nome com um espaço, como em `omarchy crash mute 'Some App'`. Tudo o resto continua a notificar, e o programa silenciado continua a falhar — isto esconde o lembrete, não corrige nada.

### Aplicações de ambiente de trabalho

O menu _Install > AI_ também inclui algumas aplicações gráficas de IA: a aplicação de ambiente de trabalho do ChatGPT, a aplicação de ambiente de trabalho do Claude (a beta para Linux da Anthropic, com separadores Chat, Cowork e Claude Code), Grok Bot para conversar com os modelos da xAI, Herdr Desktop, Hermes Desktop, OpenClaw, a aplicação de ambiente de trabalho do Perplexity e T3 Code. O Grok Bot é a aplicação de chat de ambiente de trabalho. O agente de programação é o comando `grok`.

O Hermes Desktop é aquele que importa conhecer, porque uma máquina tem um único Hermes, e é o da aplicação: o Hermes só é alguma vez instalado através da aplicação, e o comando `hermes` que o agente predefinido executa é o da aplicação. Escolher o Hermes como agente predefinido instala o mesmo que a entrada _Install > AI_: o pacote e um runtime Hermes em `~/.hermes` configurado pelo instalador do próprio Hermes, o que demora alguns minutos na primeira vez. Esse runtime é o único Hermes que o comando `hermes` no terminal, o agente predefinido e a aplicação utilizam, e atualiza-se a si próprio com `hermes update`, em vez de esperar por uma versão do Omarchy. Instalá-lo também entrega ao Hermes o tema Omarchy como uma skin chamada `omarchy`, que todas as superfícies do Hermes seguem à medida que muda de tema; escolha outra nas definições de Appearance do Hermes ou com `/skin` se preferir que não o faça, e o Omarchy deixa essa escolha em paz. Remover a aplicação em _Remove > AI_ fecha primeiro o Hermes, com o gateway incluído, leva esse runtime com ela e mantém as suas conversas, memórias e as skills que o Hermes escreveu para si próprio, a menos que diga o contrário: pergunta, com não como predefinição, se esses dados e as suas definições de ligação também devem ser removidos.

A experiência de ambiente de trabalho do OpenClaw é a sua Control UI, que abre como uma aplicação web suportada pelo seu próprio gateway local. O OpenClaw vive em `~/.openclaw` e atualiza-se a si próprio: utilize o botão "Update Gateway" da Control UI ou execute `openclaw update`, e o gateway reinicia com a nova versão. O Omarchy apenas escolhe a versão a partir da qual uma instalação nova começa. Remover o OpenClaw em _Remove > AI_ leva consigo o serviço do gateway e a aplicação e, em seguida, pergunta se `~/.openclaw` também deve ser removido, uma vez que é aí que guarda as suas conversas e credenciais juntamente com o próprio OpenClaw e os runtimes de plugins que ele descarrega; a predefinição é mantê-lo, e instalar o OpenClaw novamente volta a utilizá-lo.

O Herdr Desktop é a aplicação de ambiente de trabalho [Herdr](https://herdr.dev): espaços, separadores e painéis de terminais e agentes de programação que continuam em execução no seu núcleo quando fecha a janela. Vem do instalador do próprio Herdr e não de um pacote, por isso vive em `~/.local/share/herdr-app`, traz o seu núcleo em `~/.local/bin/herdr-core` quando ainda não tem um, e atualiza ambos por si próprio. Fica ao lado do comando `herdr` que o Omarchy disponibiliza em `Super + Ctrl + Return`, em vez de o substituir, e recebe as teclas diretas desse comando: `Alt + Return` e `Alt + Shift + Return` dividem um painel para baixo ou para a direita, `Alt + Escape` fecha-o, `Ctrl + Alt + Arrow` move entre painéis, `Alt + 1..9` e `Alt + Left/Right` escolhem um separador, e `Alt + Up/Down` move entre espaços. `Ctrl + 1..9` escolhe um espaço e `Alt + Shift + Up/Down` percorre os agentes. As teclas de prefixo `Ctrl + Space` permanecem apenas no terminal, uma vez que a aplicação não consegue manter uma tecla Ctrl simples para uma sequência. O Omarchy escreve estas em `~/.config/herdr-app/keys.json`, e `omarchy-refresh-herdr-app` volta a colocá-las. Instalá-lo escolhe o tema Omarchy do Herdr, que a partir daí segue o seu tema Omarchy. O Herdr mantém um tema para o modo claro e um para o modo escuro, por isso, depois de alternar entre um tema Omarchy escuro e um claro, escolha Omarchy mais uma vez no seletor de temas do Herdr para o outro modo.

O T3 Code funciona a partir da sua versão oficial AppImage em `~/.local/share/t3code`, e não de um pacote, por isso atualiza-se a si próprio. Instalá-lo pergunta se quer começar no canal Stable ou Nightly; mude mais tarde nas definições do T3 Code. As suas conversas e definições vivem em `~/.t3`, e remover o T3 Code em _Remove > AI_ leva-as consigo.

### Modelos locais

Execute um modelo aberto na sua própria máquina para os seus agentes de programação. Os seus prompts e código permanecem na máquina; nada do que é enviado para o modelo sai dela. Comece com:

```bash
omarchy agent local use best
```

Ou, no painel de agentes na barra superior, escolha + e depois Local AI, que aparece quando um modelo cabe nesta máquina. Na primeira vez, isto instala o Podman, que executa os modelos, e numa máquina NVIDIA o toolkit de contentores da NVIDIA, que lhes dá acesso à GPU. Em seguida, o Omarchy escolhe o modelo recomendado para esta máquina, descarrega-o e inicia-o. Conte com um descarregamento de dezenas de GB e com a maior parte da memória da máquina em utilização enquanto o modelo estiver em execução: o Flash Next utiliza cerca de 100 GiB com o seu contexto completo de 256K. Se outros modelos ocuparem a memória de que ele precisa, fica configurado parado, pronto para arrancar assim que parar um. O modelo para ao terminar sessão; pare-o quando precisar da memória para outra coisa.

`omarchy agent local list` mostra as opções e explica por que motivo algumas não cabem. Para configurar outro, execute `omarchy agent local use <recipe>`. Hoje, `qwen3.8-flash-next-gufo` e `qwen3.8-27b-gufo` estão disponíveis para máquinas Strix Halo de 128 GB; o modelo de 27B ocupa cerca de 40 GiB, por isso deixa espaço para outro trabalho. Novas receitas e recomendações chegam com `omarchy update`, através do pacote.

Cada modelo que configurar tem a sua própria linha no painel de agentes, ao lado das suas subscrições: o botão de reprodução para o iniciar, o de pausa para o parar e libertar a sua memória, e o botão de terminal para abrir o seu agente nele. Vários podem funcionar ao mesmo tempo quando cabem juntos na memória; se um não couber, o Omarchy indica qual modelo em execução deve parar. Arraste as linhas para as reordenar e prima Delete numa linha selecionada para remover um modelo e o seu descarregamento.

A partir da linha de comandos, `omarchy agent local start <recipe>` e `omarchy agent local stop <recipe>` fazem o mesmo, `omarchy agent local status` mostra todos os modelos, e `omarchy agent --local` abre o seu agente predefinido no último modelo iniciado (pi se o seu agente predefinido não puder usar um modelo local). Qualquer cliente compatível com OpenAI também se pode ligar: `status` mostra o endereço de cada modelo (o primeiro é `http://127.0.0.1:11435/v1`), o nome da receita é o modelo e a chave está em `~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` elimina um modelo e os descarregamentos que nenhum outro modelo utiliza.

Os runtimes de terceiros são assinalados com o respetivo fornecedor. O Omarchy executa todos os modelos sem acesso à rede.

### LLM locais

O Omarchy recomenda duas formas de executar modelos LLM locais: LM Studio e Ollama. O LM Studio oferece uma interface gráfica para encontrar modelos de pesos abertos, instalá-los e executá-los. É uma ótima forma de começar facilmente. O Ollama oferece uma CLI para fazer o mesmo de forma semelhante. Mas, se é novo nos modelos locais, eu começaria pelo LM Studio. Pode instalar qualquer um deles em _Install > AI_ no Menu Omarchy.

### A Skill do Omarchy

As skills de agente ajudam a IA a utilizar ferramentas específicas de uma forma específica, e o Omarchy inclui uma skill predefinida para adaptar o sistema. Como ajustar a sua configuração do Hyprland, ajustar a barra ou até criar um tema novo de raiz. Está ligada por uma ligação simbólica aos diretórios de skills do Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` e cada `~/.hermes/profiles/*/skills`) e à localização genérica `~/.agents/skills`, por isso a maioria dos harnesses identifica-a automaticamente.

Mas deve tratar esta skill como experimental. Modelos diferentes vão utilizá-la com efeitos diferentes. O melhor é executar primeiro em modo de planeamento, para ter uma ideia do que o agente gostaria de alterar.
