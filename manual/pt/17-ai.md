# IA

O Omarchy inclui lançadores para os agentes de programação abaixo sem escolher um predefinido por ti. Executa um comando para instalar a respetiva CLI na primeira utilização e, depois, autentica-te quando te for pedido. O Hermes é a exceção: na primeira utilização nada é instalado para ele, e escolhê-lo instala o Hermes Desktop, como _Desktop apps_ abaixo explica.

### Instalar e atualizar agentes

À exceção do Hermes, estes agentes utilizam a instalação lazy do mise: o primeiro arranque instala a CLI e os arranques seguintes reutilizam-na. O mise também verifica, no máximo uma vez de quatro em quatro horas, se um agente instalado tem uma nova versão, mesmo antes de arrancar ou em segundo plano num prompt da shell. Se essa atualização falhar ou estiveres offline, é executada a versão instalada. `omarchy update` atualiza os agentes instalados com o resto do Omarchy, e `mup` atualiza apenas as ferramentas geridas pelo mise.

O atualizador próprio de um agente, como `claude update`, `codex update` ou um botão de atualização numa aplicação, não atualiza a instalação gerida pelo mise. `codex update` falha, e `claude update` pode indicar sucesso ao instalar uma cópia separada que o mise não acompanha. Se preferires utilizar o instalador e o atualizador nativos de um agente, adiciona-o a `disable_tools`; vê [Ferramentas CLI pré-instaladas](18-development-tools.md#preinstalled-cli-tools).

Para instalares todas as ferramentas lazy configuradas antes de precisares delas, executa `mise install --include-lazy`. Isto inclui as outras ferramentas CLI predefinidas do Omarchy, bem como os agentes. Vê [Ferramentas CLI pré-instaladas](18-development-tools.md#preinstalled-cli-tools) para instalares uma única ferramenta ou utilizares a tua própria instalação.

O `grok` é instalado através do pacote `grok` próprio do mise, da mesma forma que `claude` e `codex`. Executa `grok`, ou escolhe-o em _Agent > Harness_. Ignora o instalador `curl | bash` em x.ai. Esse caminho coloca uma segunda cópia em `~/.grok/bin`, coloca-a no início do `PATH` e substitui o wrapper do Omarchy.

O `dsh` abre a sua interface no navegador em `127.0.0.1:3080`, com a diretoria de arranque como área de trabalho predefinida. A interface no navegador não aceita um prompt inicial, por isso `omarchy agent prompt` abre-o com o prompt na tua área de transferência para colares. O Omarchy inicia-o com a predefinição de permissões sem aprovação da DeepSeek. O DeepSeek Harness envia os registos de sessão para a DeepSeek quando utilizas a sua API oficial de modelos; desativa isso em _Settings > General > Upload Session Log_ na interface no navegador. Os comentários que lhe enviares também são enviados com a sessão, a menos que o inicies com `DSH_TELEMETRY_MODE=DISABLED`.

### O agente predefinido

Escolhe o teu agente predefinido com `omarchy default agent <name>` ou em _Agent > Harness_ no Omarchy Menu (`Super + Space`). Se o agente ainda não estiver instalado, escolhê-lo instala-o primeiro. Um Omarchy acabado de instalar vai convidar-te a fazer esta escolha com uma notificação única.

Escolher o Claude também tenta configurar a sua extensão de navegador para Chromium, Chrome, Brave, Brave Origin e Edge. A configuração da extensão aplica-se a todos os utilizadores e pode pedir a tua palavra-passe do sistema; cancelar ou uma instalação da extensão falhada continua a selecionar e a iniciar o Claude. Reinicia o navegador, ativa a extensão se te for pedido e inicia sessão no Claude para terminares a ligação. Executa `/chrome` no Claude para verificares a ligação. O Firefox e o Zen não suportam esta extensão. Se o Claude já era o teu predefinido antes de esta configuração ter sido adicionada, seleciona-o novamente para instalares a extensão.

Depois de teres escolhido, `Super + Shift + Ctrl + A` inicia o agente predefinido numa janela de terminal dedicada (ou abre o seletor se ainda não tiveres escolhido). Também o podes iniciar diretamente numa tarefa com `omarchy agent prompt "Review this project"`. O Freebuff e o DeepSeek Harness não aceitam um prompt inicial, por isso abrem antes com o prompt na tua área de transferência para colares. Os agentes iniciados desta forma funcionam sem supervisão nos respetivos modos de não parar para perguntar, por isso prepara-te para que eles façam mesmo coisas! O MiniMax Code não tem um modo desses para as suas sessões interativas, por isso pede permissões como habitualmente. E, como os agentes se recusam a memorizar a confiança para a tua diretoria pessoal, os arranques a partir de `$HOME` começam antes em `~/Work`.

Também há atalhos de terminal: `a` executa o agente predefinido inline no terminal atual, enquanto `c`, `cx` e `cy` iniciam diretamente OpenCode, Claude Code e Codex (mais uma vez nos seus modos de aprovação automática). As mudanças de tema também são sincronizadas com os agentes: Claude Code, Pi, OpenCode e Hermes (depois de o Omarchy o ter instalado) acompanham-te quando mudas o tema do Omarchy.

### As tuas instruções para os agentes

As regras pessoais para todos os agentes ficam em `~/.agents/AGENTS.md`, ao lado das skills partilhadas em `~/.agents/skills`. Abre-o em _Agent > Instructions_, que também cria uma ligação para ele em cada harness que mantém o seu próprio ficheiro global: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, o `~/.copilot/copilot-instructions.md` do Copilot, e por aí fora. O Crush e o Amp leem a ligação `~/.config/AGENTS.md`, enquanto omp, Kimi e DeepSeek Harness leem diretamente `~/.agents/AGENTS.md`. Escolher um agente predefinido também cria a ligação para ele. Um ficheiro de instruções que já tinhas torna-se o partilhado se ainda não havia nenhum; caso contrário, é mantido ao lado da ligação como `.bak`. Executa `omarchy agent instructions` para voltares a criar as ligações depois de instalares outro agente.

### O painel de agentes

A barra superior tem um ícone de agentes. Antes de teres configurado um agente, o seu painel acompanha-te no início de sessão no Claude, Codex ou Grok, e o primeiro torna-se o teu agente predefinido. Depois disso, o painel coloca todas as subscrições numa só página: cada agente e conta com o seu plano, um medidor para cada um dos seus limites de sessão de 5 horas e semanais com o tempo até ser reposto (passa o cursor por cima para veres a percentagem exata), ou o saldo pré-pago restante, sob uma linha que vai rodando pelo que utilizaste em todos eles, como tokens esta semana e o teu modelo mais utilizado. Em _Make something_ oferece prompts iniciais para um novo tema, plugin ou aplicação que entregam a tarefa ao teu agente predefinido. As aplicações são construídas da forma como as próprias Hype, Monologue e Omacut do Omarchy são, em C++ e Qt Quick, seguindo a skill de agente omarchy-app, e o compilador e as peças de Qt de que precisam vêm instalados. Claude Code, Codex, Grok, Kimi, Cursor e a sua permissão Grok Bot, GitHub Copilot, Muse, Antigravity, Kimchi e Devin estão cobertos de origem com os seus limites, e Hermes, Mistral Vibe e Qwen Code mostram as suas sessões e tokens depois de os teres utilizado. Os planos e chaves de fornecedores que utilizas através de pi, omp ou opencode também aparecem: OpenCode Zen e Go, o Z.ai GLM Coding Plan, Ollama Cloud, o MiniMax Token Plan e Synthetic com os seus limites; Fireworks, OpenRouter e DeepSeek com os seus saldos pré-pagos; e os modelos que executas no teu próprio hardware em Local models. Cada agente é contado uma vez, sob quem o fatura, por mais harnesses que utilizes para o conduzir.

Clica com o botão esquerdo no ícone da barra para o painel, clica com o botão direito para iniciares o teu agente predefinido. Os registos de utilização por trás dele são regenerados de 15 em 15 minutos por `omarchy agent usage-update`, e o painel pode até juntar a utilização das tuas outras máquinas através de uma pasta sincronizada. Vê o README em `$OMARCHY_PATH/shell/plugins/agents/` para as definições completas.

### Várias subscrições

Se pagares por mais do que um plano Claude, Codex ou Grok — um Max pessoal e um de trabalho, por exemplo — o Omarchy pode manter todos com sessão iniciada e alternar entre eles. Adiciona uma subscrição com o + no painel de agentes, que te acompanha no processo ali mesmo, ou com `omarchy agent account add claude Work` (ou `codex`, ou `grok`). Instala a CLI se ela faltar. A primeira conta de um fornecedor inicia sessão através do teu navegador normal, exatamente onde a CLI sempre procura. Todas as seguintes iniciam sessão através de uma janela privada, para que a conta em que o teu navegador já tem sessão iniciada não seja apanhada por engano; inicia sessão aí como a conta que estás a adicionar e fecha primeiro qualquer janela privada que já tenhas aberta. Nunca termines a sessão na CLI para fazer isto: terminar a sessão revoga o início de sessão guardado, e essa conta teria de ser adicionada novamente.

Para copiares os teus inícios de sessão de subscrição para outra máquina Omarchy por SSH, executa `omarchy agent account copy user@laptop`. O remetente fornece um recetor temporário quando o destino não tem um instalado, para que máquinas Omarchy mais antigas possam receber contas sem uma atualização. Os recetores instalados têm precedência. Isto copia todas as subscrições Claude, Codex e Grok; adiciona nomes de fornecedores para as selecionares, como em `omarchy agent account copy laptop claude`. Os nomes de conta e os IDs de comando correspondem à origem, incluindo contas já presentes no destino. Contas de destino não relacionadas recebem um sufixo numérico se os seus nomes entrarem em conflito, e as definições, skills, plugins e o histórico de conversas permanecem locais a cada máquina.

As credenciais de destino existentes são mantidas. Uma conta de origem que já tem sessão iniciada lá tem o seu nome sincronizado sem substituir as suas credenciais; outras contas são adicionadas ao lado dela. Para substituíres as credenciais guardadas de contas correspondentes, utiliza `omarchy agent account copy --replace laptop claude` depois de fechares as sessões dessa conta no destino. Um destino novo também recebe a conta ativa e as preferências de alternância da origem; um destino já estabelecido mantém as suas.

As credenciais viajam através de SSH e são armazenadas em ficheiros privados no destino, por isso copia apenas para máquinas em que confias. Isto é uma cópia única, não uma sincronização contínua. Os tokens de atualização do Codex podem ser rodados por outra máquina, deixando um início de sessão copiado a precisar de renovação; inícios de sessão separados continuam a ser a escolha mais fiável para utilização simultânea em várias máquinas. Vê o [guia de autenticação de contas do Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Uma conta por fornecedor está ativa, e cada nova sessão começa como ela: `cx`, `cy`, um `claude`, `codex` ou `grok` simples, tudo o que for iniciado através de `omarchy agent`, e scripts ou editores que encontrem a CLI no `PATH`. Alterna com `omarchy agent account use work` (e volta com `omarchy agent account use main`), ou no painel ao carregares no número de uma conta e depois em `Enter` (ou ao clicares no seu botão Use). As sessões que já estão a correr mantêm a conta com que começaram. O histórico de conversas, as definições, as skills e os plugins são partilhados entre contas, por isso `claude --continue` na mesma pasta continua onde tinhas ficado na nova conta.

Com mais do que uma conta, o painel mostra os limites de cada conta lado a lado, com a ativa assinalada. Por predefinição, o Omarchy avisa-te quando a conta ativa passa 95% de um limite, e clicar na notificação muda para a conta com mais margem. Passa o cursor sobre a linha de uma conta no painel e clica no Autoswitch que aparece ao lado de Use (ou carrega em `m`), ou executa `omarchy agent account mode auto`, para que ele mude sozinho; enquanto está ativo, Autoswitch ocupa o lugar de Use, e clicar nele novamente volta a avisar. Adiciona um número para alterares o limiar, como em `omarchy agent account mode auto 90`. Se todas as contas estiverem acima do limiar, vais saber disso uma vez, juntamente com qual conta fica livre primeiro. Enquanto uma conta ativa estiver a menos de 15 pontos do seu limiar (80% na predefinição), os seus limites são verificados de três em três minutos em vez de de 15 em 15.

`omarchy agent account list` mostra todas as contas e os seus limites mais recentes, `omarchy agent account remove work` esquece uma, e `omarchy agent account rename primary Hey` muda o nome a uma (ou clica no nome de uma conta no painel). Estes comandos funcionam nas contas do teu agente predefinido; para chegares ao outro fornecedor, indica-o primeiro, como em `omarchy agent account use codex side`. O início de sessão que já tinhas em `~/.claude` ou `~/.codex` é a conta _Main_ e fica onde está. Uma conta deixada sem utilização durante mais de cerca de oito horas pode mostrar _Sign-in required_; clica nela para iniciares sessão nessa conta de novo diretamente no painel, ou inicia uma sessão nela, o que atualiza o início de sessão por si só. Os servidores MCP que tinhas quando uma conta foi adicionada acompanham-na, mas os que adicionares mais tarde com `claude mcp add` só chegam à conta em que os adicionaste. O Claude Desktop e as ferramentas configuradas com um caminho absoluto para um binário da CLI não acompanham a mudança. Um `CLAUDE_CONFIG_DIR`, `CODEX_HOME` ou `GROK_HOME` explícito tem precedência sobre a conta selecionada.

### Diagnóstico de falhas

O Omarchy vigia o systemd-coredump à procura de falhas de processos. Quando alguma coisa faz segfault, vais receber uma notificação "Process crashed" — clica nela e a falha é entregue ao teu agente predefinido juntamente com a skill diagnose-crash do Omarchy, que acompanha o agente no estabelecimento dos factos a partir do core dump e na decisão sobre se a falha vale a pena ser comunicada a montante. Também a podes executar manualmente contra qualquer PID de `coredumpctl list` com `omarchy agent crash <pid>`.

A vigilância está ativa por predefinição. Desativa-a em _Trigger > Toggle > Crash Capture_ (ou com `omarchy toggle crash-capture`) e as notificações param; `omarchy agent crash <pid>` continua a funcionar manualmente.

As falhas também podem ser silenciadas um programa de cada vez, que é o que o diagnóstico te oferece no fim. `omarchy crash mute hyprland` para as notificações apenas para esse programa, `omarchy crash mute hyprland off` trazê-las de volta, e `omarchy crash mute` por si só lista o que silenciaste. Aceita o caminho do binário tão bem como o seu nome, por isso `omarchy crash mute /usr/bin/hyprland` faz a mesma coisa. Coloca entre aspas um nome com um espaço, como em `omarchy crash mute 'Some App'`. Tudo o resto continua a avisar, e o programa silenciado continua a falhar — isto esconde o lembrete, não resolve nada.

### Aplicações de desktop

O menu _Install > AI_ também inclui algumas aplicações gráficas de IA: a aplicação de desktop do ChatGPT, a aplicação de desktop do Claude (a beta para Linux da Anthropic, com separadores Chat, Cowork e Claude Code), Grok Bot para conversares com os modelos da xAI, Herdr Desktop, Hermes Desktop, OpenClaw, a aplicação de desktop da Perplexity e T3 Code. O Grok Bot é a aplicação de chat de desktop. O agente de programação é o comando `grok`.

O Hermes Desktop é aquele que importa conhecer, porque uma máquina tem um só Hermes, e é o da aplicação: o Hermes só é instalado através da aplicação, e o comando `hermes` que o agente predefinido executa é o da aplicação. Escolher o Hermes como agente predefinido instala a mesma coisa que a entrada _Install > AI_: o pacote e um runtime do Hermes em `~/.hermes` configurado pelo próprio instalador do Hermes, o que demora alguns minutos na primeira vez. Esse runtime é o único Hermes que o comando de terminal `hermes`, o agente predefinido e a aplicação utilizam, e atualiza-se a si próprio com `hermes update` em vez de esperar por uma versão do Omarchy. Instalá-lo também entrega ao Hermes o tema do Omarchy como uma skin chamada `omarchy`, que todas as superfícies do Hermes seguem à medida que mudas de tema; escolhe outra nas definições de Appearance do Hermes ou com `/skin` se preferires que não seja assim, e o Omarchy deixa essa escolha em paz. Remover a aplicação em _Remove > AI_ fecha primeiro o Hermes, gateway incluída, leva esse runtime com ela e mantém as tuas conversas, memórias e as skills que o Hermes escreveu para si próprio, a menos que digas o contrário: pergunta, com não por predefinição, se esses dados e as tuas definições de ligação também devem ir.

A experiência de desktop do OpenClaw é a sua Control UI, que se abre como uma aplicação web apoiada pela sua própria gateway local. O OpenClaw vive em `~/.openclaw` e atualiza-se a si próprio: utiliza o botão "Update Gateway" da Control UI ou executa `openclaw update`, e a gateway reinicia na nova versão. O Omarchy só escolhe a versão a partir da qual uma instalação nova começa. Remover o OpenClaw em _Remove > AI_ leva o serviço da gateway e a aplicação com ele e depois pergunta se `~/.openclaw` também deve ir, uma vez que isso guarda as tuas conversas e credenciais ao lado do próprio OpenClaw e dos runtimes de plugins que ele descarrega; a predefinição mantém-no, e instalar o OpenClaw novamente volta a apanhá-lo.

O Herdr Desktop é a aplicação de desktop [Herdr](https://herdr.dev): espaços, separadores e painéis de terminais e agentes de programação que continuam a correr no seu núcleo quando fechas a janela. Vem do próprio instalador do Herdr e não de um pacote, por isso vive em `~/.local/share/herdr-app`, traz o seu núcleo em `~/.local/bin/herdr-core` quando ainda não tens um, e atualiza ambos. Fica ao lado do comando `herdr` que o Omarchy fornece em `Super + Ctrl + Return` em vez de o substituir, e recebe as teclas diretas desse comando: `Alt + Return` e `Alt + Shift + Return` dividem um painel para baixo ou para a direita, `Alt + Escape` fecha-o, `Ctrl + Alt + Arrow` move entre painéis, `Alt + 1..9` e `Alt + Left/Right` escolhem um separador, e `Alt + Up/Down` movem entre espaços. `Ctrl + 1..9` escolhe um espaço e `Alt + Shift + Up/Down` percorre os agentes. As teclas de prefixo `Ctrl + Space` continuam apenas para o terminal, uma vez que a aplicação não consegue manter uma tecla Ctrl simples para uma sequência. O Omarchy escreve estas em `~/.config/herdr-app/keys.json`, e `omarchy-refresh-herdr-app` volta a colocá-las. Instalá-lo escolhe o tema Omarchy do Herdr, que a partir daí segue o teu tema Omarchy. O Herdr mantém um tema para o modo claro e um para o modo escuro, por isso, depois de alternares entre um tema Omarchy escuro e um claro, escolhe Omarchy no seletor de temas do Herdr mais uma vez para o outro modo.

O T3 Code executa-se a partir da sua versão oficial AppImage em `~/.local/share/t3code` e não a partir de um pacote, por isso atualiza-se a si próprio. Instalá-lo pergunta se queres começar no canal Stable ou Nightly; muda mais tarde nas definições do T3 Code. Os teus tópicos e definições vivem em `~/.t3`, e remover o T3 Code em _Remove > AI_ leva-os com ele.

### Modelos locais

Executa um modelo aberto na tua própria máquina para os teus agentes de programação. Os teus prompts e código permanecem na máquina; nada do que é enviado ao modelo sai dela. Começa com:

```bash
omarchy agent local use best
```

Ou, no painel de agentes na barra superior, escolhe + e depois Local AI, que aparece quando um modelo cabe nesta máquina. Na primeira vez, isto instala o Podman, que executa os modelos, e numa máquina NVIDIA o toolkit de contentores da NVIDIA, que lhes dá a GPU. Depois, o Omarchy escolhe o modelo recomendado para esta máquina, descarrega-o e inicia-o. Conta com uma transferência de dezenas de GB e com a maior parte da memória da máquina em utilização enquanto o modelo está a correr: o Flash Next utiliza cerca de 100 GiB com o seu contexto completo de 256K. Se outros modelos ocuparem a memória de que ele precisa, é configurado parado, pronto para iniciar assim que parares um. O modelo para quando terminas a sessão; para-o tu próprio quando precisares da memória para outra coisa.

`omarchy agent local list` mostra as opções e explica porque é que algumas não cabem. Para configurares outro, executa `omarchy agent local use <recipe>`. Hoje, `qwen3.8-flash-next-gufo` e `qwen3.8-27b-gufo` estão disponíveis para máquinas Strix Halo de 128 GB; o 27B ocupa cerca de 40 GiB, por isso deixa espaço para outro trabalho. Novas receitas e recomendações chegam com `omarchy update`, através do pacote.

Cada modelo que configurares tem a sua própria linha no painel de agentes, ao lado das tuas subscrições: reproduzir para o iniciares, pausa para o parares e libertares a sua memória, e o botão de terminal para abrires o teu agente nele. Vários podem correr ao mesmo tempo quando cabem juntos em memória; se um não couber, o Omarchy diz qual modelo em execução deves parar. Arrasta linhas para as reordenares e carrega em Delete numa linha selecionada para removeres um modelo e a sua transferência.

A partir da linha de comandos, `omarchy agent local start <recipe>` e `omarchy agent local stop <recipe>` fazem o mesmo, `omarchy agent local status` mostra todos os modelos, e `omarchy agent --local` abre o teu agente predefinido no último modelo que iniciaste. pi, OpenCode e Qwen Code podem utilizar um; com qualquer outro predefinido, abre no pi. O pi também lista todos os modelos que configuraste, e os das máquinas com que emparelhaste, no seu próprio seletor de modelos, por isso um simples `pi` também chega a eles. Qualquer cliente compatível com OpenAI também se pode ligar: `status` mostra o endereço de cada modelo (o primeiro é `http://127.0.0.1:11435/v1`), o nome da receita é o modelo, e a chave está em `~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` apaga um modelo e as transferências que nenhum outro modelo utiliza.

Os runtimes de terceiros estão identificados com o seu editor. O Omarchy executa cada modelo sem acesso à rede.

### LLM locais

O Omarchy recomenda duas formas de executar modelos LLM locais: LM Studio e Ollama. O LM Studio fornece uma interface gráfica para encontrares modelos de pesos abertos, instalá-los e executá-los. É uma ótima forma de começares facilmente. O Ollama oferece uma CLI para fazeres o mesmo de forma semelhante. Mas, se és novo nos modelos locais, eu começaria pelo LM Studio. Podes instalar qualquer um deles em _Install > AI_ no Omarchy Menu.

### A Skill do Omarchy

As skills de agentes ajudam a IA a utilizar ferramentas específicas de uma forma específica, e o Omarchy vem com uma skill predefinida para personalizar o sistema. Como ajustar a tua configuração do Hyprland, ajustar a barra, ou até criar um tema novo de raiz. Tem uma ligação simbólica nas diretorias de skills do Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` e cada `~/.hermes/profiles/*/skills`), e na localização genérica `~/.agents/skills`, por isso a maioria dos harnesses apanha-a automaticamente.

Mas deves tratar esta skill como experimental. Modelos diferentes vão utilizá-la com efeitos diferentes. É melhor correres primeiro em modo de plano, para teres uma ideia do que o agente gostaria de alterar. E depois prepara-te para reverteres alterações ou até invocares `omarchy reinstall configs`, se o agente fizer uma confusão com tudo.
