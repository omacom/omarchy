# IA

Executa um comando para instalar a respetiva CLI na primeira utilização, depois autentica-te quando te for pedido. O Hermes e o OpenClaw são as exceções: nada é instalado para eles através do mise, e escolher qualquer um deles instala a sua própria cópia com atualização automática, como explica _Aplicações de ambiente de trabalho_ abaixo.

### Instalar e atualizar agentes

À exceção do Hermes e do OpenClaw, estes agentes usam a instalação lazy do mise: o primeiro arranque instala a CLI, e os arranques seguintes reutilizam-na. O mise também verifica se existe uma nova versão de um agente instalado no máximo uma vez de quatro em quatro horas, mesmo antes de arrancar ou em segundo plano num prompt da shell. Se essa atualização falhar ou estiveres offline, é executada a versão instalada. `omarchy update` atualiza os agentes instalados com o resto do Omarchy, e `mup` atualiza apenas as ferramentas geridas pelo mise.

O atualizador próprio de um agente, como `claude update`, `codex update` ou um botão de atualização numa aplicação, não atualiza a instalação gerida pelo mise. `codex update` falha, e `claude update` pode indicar sucesso ao mesmo tempo que instala uma cópia separada que o mise não acompanha. Se preferires usar o instalador e o atualizador nativos de um agente, adiciona-o a `disable_tools`; vê [Ferramentas CLI pré-instaladas](18-development-tools.md#preinstalled-cli-tools).

Para instalares todas as ferramentas lazy configuradas antes de precisares delas, executa `mise install --include-lazy`. Isto inclui as outras ferramentas CLI predefinidas do Omarchy, bem como os agentes. Vê [Ferramentas CLI pré-instaladas](18-development-tools.md#preinstalled-cli-tools) para instalares uma única ferramenta ou usares a tua própria instalação.

O `grok` é instalado através do pacote `grok` próprio do mise, da mesma forma que o `claude` e o `codex`. Executa `grok`, ou marca-o com uma estrela no painel de agentes. Ignora o instalador `curl | bash` em x.ai. Esse caminho coloca uma segunda cópia em `~/.grok/bin`, coloca-a à frente no `PATH` e substitui o wrapper do Omarchy.

O `dsh` abre a sua interface no navegador em `127.0.0.1:3080`, com a pasta de arranque como área de trabalho predefinida. A sua interface no navegador não aceita um prompt inicial, por isso `omarchy agent prompt` abre-o com o prompt na tua área de transferência para colares. O Omarchy arranca-o com a predefinição de permissões sem aprovação da DeepSeek. O DeepSeek Harness envia os registos de sessão para a DeepSeek quando usas a sua API oficial de modelos; desativa isso em _Settings > General > Upload Session Log_ na sua interface no navegador. Os comentários que lhe enviares também são enviados com a sessão, a menos que o arranques com `DSH_TELEMETRY_MODE=DISABLED`.

### O agente predefinido

Escolhe o teu agente predefinido com a estrela ao lado de um agente no painel de agentes, que aparece preenchida no predefinido, ou com `omarchy default agent <name>`, que também aceita qualquer harness sem uma linha ali. Se o agente ainda não estiver instalado, ao escolhê-lo ele é instalado primeiro, e também ganha um lançador próprio no lançador de aplicações, ao lado de Agent. Um Omarchy novo convida-te a configurares um com uma notificação única, que abre o painel de agentes.

Escolher o Claude também tenta configurar a sua extensão de navegador para Chromium, Chrome, Brave, Brave Origin e Edge. A configuração da extensão aplica-se a todos os utilizadores e pode pedir-te a palavra-passe do sistema; cancelar ou uma instalação falhada da extensão continua a selecionar e a iniciar o Claude. Reinicia o navegador, ativa a extensão se te for pedido e inicia sessão no Claude para acabares de o ligar. Executa `/chrome` no Claude para verificares a ligação. O Firefox e o Zen não suportam esta extensão. Se o Claude já era o teu predefinido antes de esta configuração ser adicionada, seleciona-o outra vez para instalares a extensão.

Depois de escolheres, `Super + Shift + Ctrl + A` inicia o agente predefinido numa janela de terminal dedicada (ou abre o seletor se ainda não tiveres escolhido nenhum). Também o podes iniciar diretamente numa tarefa com `omarchy agent prompt "Review this project"`. O Freebuff e o DeepSeek Harness não aceitam um prompt inicial, por isso abrem com o prompt na tua área de transferência para colares. Os agentes iniciados desta forma executam sem supervisão nos respetivos modos de não parar para perguntar, por isso prepara-te para eles fazerem mesmo coisas! O MiniMax Code não tem um modo desses para as suas sessões interativas, por isso pede permissões como habitualmente. E como os agentes se recusam a memorizar a confiança na tua pasta pessoal, os arranques a partir do `$HOME` começam antes em `~/Work`.

Também há atalhos de terminal: `a` executa o agente predefinido inline no terminal atual, enquanto `c`, `cx` e `cy` iniciam diretamente o OpenCode, o Claude Code e o Codex (outra vez nos seus modos de aprovação automática). As mudanças de tema também se sincronizam com os agentes: o Claude Code, o Pi, o OpenCode e o Hermes (depois de o Omarchy o instalar) acompanham-te a todos quando mudas o tema do Omarchy.

### As tuas instruções para os agentes

As regras pessoais para todos os agentes ficam em `~/.agents/AGENTS.md`, ao lado das skills partilhadas em `~/.agents/skills`. Abre-o com o ícone de documento ao lado do + no painel de agentes, ou com `omarchy agent instructions --edit`, que também cria uma ligação para ele em cada harness que mantém o seu próprio ficheiro global: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, o `~/.copilot/copilot-instructions.md` do Copilot, e por aí fora. O Crush e o Amp leem a ligação `~/.config/AGENTS.md`, enquanto o omp, o Kimi e o DeepSeek Harness leem diretamente `~/.agents/AGENTS.md`. Escolher um agente predefinido também cria a ligação para ele. Um ficheiro de instruções que já tinhas torna-se o partilhado se ainda não existia nenhum; caso contrário, é mantido ao lado da ligação como `.bak`. Executa `omarchy agent instructions` para voltares a criar as ligações depois de instalares outro agente.

### O painel de agentes

A barra superior tem um ícone de agentes. Antes de configurares um agente, o seu painel oferece três formas de começares: iniciar sessão numa subscrição Claude, Codex, Grok, Gemini, Muse, Cursor ou Copilot, ou, em More, num plano de programação OpenCode Go, MiniMax, Synthetic ou Z.ai; pagar à medida da utilização com Fireworks, OpenCode Zen and Go, OpenRouter ou, em More, DeepSeek ou qualquer outro fornecedor em que o OpenCode inicie sessão, todos executados no OpenCode; ou executar o melhor modelo para o teu computador, quando houver um adequado para ele. O primeiro que concluíres torna-se o teu agente predefinido, e o + no painel volta a oferecer os mesmos três mais tarde. Depois disso, o painel coloca todas as subscrições numa só página: cada agente e conta com o seu plano, um indicador para cada um dos seus limites de sessão de 5 horas e semanais com o tempo que falta para ser reposto (passa o cursor por cima para veres a percentagem exata), ou o saldo pré-pago restante, sob uma linha que vai alternando entre o que usaste em todos eles, como os tokens desta semana e o teu modelo mais usado. Em _Make something cool_ oferece prompts iniciais para um novo tema, plugin, aplicação ou jogo, que entregam a tarefa ao teu agente predefinido. As aplicações são construídas da forma como as próprias Hype, Monologue e Omacut do Omarchy são, em C++ e Qt Quick, a seguir a skill de agente omarchy-make-app, e o compilador e as peças Qt de que precisam vêm instalados. Os jogos são uma única página three.js em `~/Games/vibes`, a seguir a skill de agente omarchy-make-game, e todos abrem a partir de um único lançador Game Vibes no tema atual; carregam o three.js a partir da Web, por isso precisam de uma ligação para arrancar. O Claude Code, o Codex, o Grok, o Kimi, o Cursor e a sua franquia Grok Bot, o GitHub Copilot, o Muse, o Gemini (através do Antigravity) e o Devin estão cobertos de origem com os seus limites, o Kimchi com o seu plano, créditos pré-pagos e orçamentos de despesa, e o Hermes, o Mistral Vibe e o Qwen Code mostram as suas sessões e tokens depois de os teres usado. Os planos e chaves de fornecedores que usas através do pi, do omp ou do opencode também aparecem: OpenCode Zen and Go, o Z.ai GLM Coding Plan, a Ollama Cloud, o MiniMax Token Plan e a Synthetic com os seus limites; a OpenRouter e a DeepSeek com os seus saldos pré-pagos; a Fireworks com a sua despesa nos últimos 30 dias. Os modelos de programação que executas no teu próprio hardware ganham linhas próprias, e os seus tokens também contam para os totais, como está descrito em [Modelos locais](#local-models). Cada agente é contado uma vez, sob quem o fatura, independentemente de quantos harnesses uses para o comandar.

Clica com o botão esquerdo no ícone da barra ou prime `Super + Ctrl + X` para abrires o painel, clica com o botão direito para iniciares o teu agente predefinido e clica com o botão do meio para atualizares. Os registos de utilização por trás dele são regenerados de 15 em 15 minutos por `omarchy agent usage update`, e o painel pode até juntar a utilização das tuas outras máquinas através de uma pasta sincronizada. Vê o README em `$OMARCHY_PATH/shell/plugins/agents/` para veres as definições completas.

### Várias subscrições

Se pagares por mais do que um plano Claude, Codex ou Grok — um Max pessoal e um de trabalho, por exemplo —, o Omarchy pode manter todos com sessão iniciada e alternar entre eles. Adiciona uma subscrição com o + no painel de agentes, que te guia ali mesmo, ou com `omarchy agent account add claude Work` (ou `codex`, ou `grok`). O mesmo + e o mesmo comando iniciam sessão no Gemini (`gemini`) e no OpenCode (`opencode`), e guardam uma chave de API Fireworks (`fireworks`) ou OpenRouter (`openrouter`) no OpenCode; o comando também inicia sessão no Copilot (`copilot`), no Cursor (`cursor`) e no Muse (`muse`). Esses mantêm um único início de sessão cada um. Ele instala a CLI se ela estiver em falta. A primeira conta de um fornecedor inicia sessão através do teu navegador normal, exatamente onde a CLI procura sempre. Todas as seguintes iniciam sessão através de uma janela privada, para que a conta em que o teu navegador já tem sessão iniciada não seja escolhida por engano; inicia sessão ali com a conta que estás a adicionar, e fecha primeiro qualquer janela privada que já tenhas aberta. Nunca termines sessão na CLI para fazeres isto: terminar sessão revoga o início de sessão guardado, e essa conta teria de ser adicionada outra vez.

Para copiares os inícios de sessão das tuas subscrições para outra máquina Omarchy por SSH, executa `omarchy agent account copy user@laptop`. O remetente fornece um recetor temporário quando o destino não tem nenhum instalado, para que máquinas Omarchy mais antigas possam receber contas sem uma atualização. Os recetores instalados têm precedência. Isto copia todas as subscrições Claude, Codex e Grok; adiciona nomes de fornecedores para as selecionares, como em `omarchy agent account copy laptop claude`. Os nomes das contas e os IDs de comando correspondem aos da origem, incluindo contas já presentes no destino. As contas do destino não relacionadas recebem um sufixo numérico se os seus nomes entrarem em conflito, e as definições, skills, plugins e o histórico de conversas permanecem locais em cada máquina.

As credenciais de destino existentes são mantidas. Uma conta de origem que já tem sessão iniciada ali tem o seu nome sincronizado sem substituir as suas credenciais; as outras contas são adicionadas ao lado dela. Para substituíres as credenciais guardadas de contas correspondentes, usa `omarchy agent account copy --replace laptop claude` depois de fechares as sessões dessa conta no destino. Um destino novo também recebe a conta ativa e as preferências de troca da origem; um destino já estabelecido mantém as suas.

As credenciais viajam por SSH e são guardadas em ficheiros privados no destino, por isso copia apenas para máquinas em que confias. Isto é uma cópia única, não uma sincronização contínua. Os tokens de atualização do Codex podem ser rodados por outra máquina, o que deixa um início de sessão copiado a precisar de renovação; inícios de sessão separados continuam a ser a escolha mais fiável para uma utilização simultânea em várias máquinas. Vê as [orientações de autenticação de contas do Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Uma conta por fornecedor está ativa, e todas as novas sessões começam como ela: `cx`, `cy`, um simples `claude`, `codex` ou `grok`, qualquer coisa iniciada através de `omarchy agent`, e scripts ou editores que encontrem a CLI no `PATH`. Alterna com `omarchy agent account use work` (e volta com `omarchy agent account use main`), ou no painel ao premires o número de uma conta e depois `Enter` (ou ao clicares na sua estrela). As sessões Claude em execução também alternam, a partir da sua próxima mensagem: todas as sessões Claude executam em `~/.claude`, que guarda sempre o início de sessão da conta ativa. Uma sessão Claude iniciada na pasta própria de uma conta por um Omarchy mais antigo mantém esse início de sessão até fechar, por isso a troca indica essas sessões e termina sozinha quando elas desaparecerem. As sessões Codex e Grok em execução permanecem na conta com que começaram. O histórico de conversas, as definições, as skills e os plugins são partilhados entre contas, por isso `claude --continue` na mesma pasta retoma onde tinhas ficado na nova conta.

Com mais do que uma conta, o painel mostra os limites de cada conta lado a lado, com uma estrela preenchida na que está em uso. O Omarchy avisa-te quando a conta ativa ultrapassa 95% de um limite, e clicar na notificação muda para a conta com mais folga. Ele nunca muda sozinho. Altera o limite de aviso com `omarchy agent account threshold 90`. Se todas as contas estiverem acima do limite, vais saber disso uma vez, juntamente com qual conta fica livre primeiro. Enquanto uma conta ativa estiver a menos de 15 pontos do seu limite (80% na predefinição), os seus limites são verificados de três em três minutos em vez de de 15 em 15 minutos.

`omarchy agent account list` mostra todas as contas e os seus limites mais recentes, `omarchy agent account remove work` esquece uma, e `omarchy agent account rename primary Hey` muda o nome de uma (ou clica no nome de uma conta no painel). Estes comandos funcionam nas contas do teu agente predefinido; para chegares ao outro fornecedor, indica-o primeiro, como em `omarchy agent account use codex side`. O início de sessão que já tinhas em `~/.claude` ou `~/.codex` é a conta _Main_. O do Codex fica onde está; o do Claude espera numa pasta própria enquanto outra conta está ativa. Uma conta que fique sem uso durante mais de cerca de oito horas pode mostrar _Sign-in required_; clica nela para iniciares sessão nessa conta outra vez diretamente no painel, ou muda para ela e inicia uma sessão, o que atualiza o início de sessão sozinho. Os servidores MCP que adicionares com `claude mcp add` chegam a todas as contas Claude, uma vez que todas executam em `~/.claude`; no Codex e no Grok, os servidores que tinhas quando uma conta foi adicionada acompanham-na, mas os posteriores só chegam à conta em que os adicionaste. O Claude Desktop mantém um início de sessão próprio, e as ferramentas Codex ou Grok configuradas com um caminho absoluto para um binário da CLI não acompanham a troca. Um `CLAUDE_CONFIG_DIR`, `CODEX_HOME` ou `GROK_HOME` explícito tem precedência sobre a conta selecionada.

### Diagnóstico de crashes

O Omarchy vigia o systemd-coredump à procura de crashes de processos. Depois de escolheres um agente predefinido, qualquer programa teu que gere um core dump apresenta uma notificação "Process crashed" — clica nela, e o crash é entregue ao teu agente predefinido juntamente com a skill omarchy-diagnose-crash do Omarchy, que orienta o agente a estabelecer os factos a partir do core dump e a decidir se o crash vale a pena ser reportado a montante. Também podes executá-lo manualmente contra qualquer PID de `coredumpctl list` com `omarchy agent crash <pid>`.

A vigilância está ativa por predefinição. Desativa-a em _Trigger > Toggle > Crash Capture Off_ (ou com `omarchy toggle crash-capture`) e as notificações param; `omarchy agent crash <pid>` continua a funcionar manualmente.

Os crashes também podem ser silenciados um programa de cada vez, que é o que o diagnóstico te oferece no fim. `omarchy crash mute hyprland` para as notificações apenas para esse programa, `omarchy crash mute hyprland off` volta a trazê-las, e `omarchy crash mute` sozinho lista o que silenciaste. Ele aceita o caminho do binário com a mesma facilidade com que aceita o seu nome, por isso `omarchy crash mute /usr/bin/hyprland` faz o mesmo. Coloca entre aspas um nome com um espaço, como em `omarchy crash mute 'Some App'`. Tudo o resto continua a notificar, e o programa silenciado continua a ter crashes — isto esconde o lembrete, não resolve nada.

### Aplicações de ambiente de trabalho

O menu _Install > AI_ também traz algumas aplicações gráficas de IA: Amp Desktop, Antigravity Desktop, a aplicação de ambiente de trabalho ChatGPT, a aplicação de ambiente de trabalho Claude (a versão beta para Linux da Anthropic, com separadores Chat, Cowork e Claude Code), Grok Bot para conversares com os modelos da xAI, Herdr Desktop, Hermes Desktop, OpenClaw, a aplicação de ambiente de trabalho Perplexity e T3 Code. O Grok Bot é a aplicação de conversação de ambiente de trabalho. O agente de programação é o comando `grok`.

O Hermes Desktop é o que deves conhecer, porque uma máquina tem um Hermes, e ele é o da aplicação: o Hermes só é instalado através da aplicação, e o comando `hermes` que o agente predefinido executa é o da aplicação. Escolher o Hermes como agente predefinido instala o mesmo que a entrada _Install > AI_ instala: o pacote, e um runtime Hermes em `~/.hermes` configurado pelo próprio instalador do Hermes, o que demora alguns minutos na primeira vez. Esse runtime é o único Hermes que o comando `hermes` de terminal, o agente predefinido e a aplicação usam todos, e ele atualiza-se a si próprio com `hermes update` em vez de esperar por uma versão do Omarchy. Instalá-lo também entrega ao Hermes o tema do Omarchy como uma skin chamada `omarchy`, que todas as superfícies do Hermes seguem à medida que mudas de tema; escolhe outra nas definições Appearance do Hermes ou com `/skin` se preferires que ele não o faça, e o Omarchy deixa essa escolha em paz. Remover a aplicação em _Remove > AI_ fecha primeiro o Hermes, gateway incluído, leva esse runtime com ela, e mantém as tuas conversas, memórias e as skills que o Hermes escreveu para si próprio, a menos que lhe digas o contrário: ela pergunta, com não como predefinição, se esses dados e as tuas definições de ligação também devem desaparecer.

A experiência de ambiente de trabalho do OpenClaw é a sua Control UI, que abre como uma aplicação Web apoiada pelo seu próprio gateway local. O OpenClaw vive em `~/.openclaw` e atualiza-se a si próprio: usa o botão "Update Gateway" da Control UI ou executa `openclaw update`, e o gateway reinicia na nova versão. O Omarchy só escolhe a versão com que uma instalação nova começa. O OpenClaw também pode ser o teu agente predefinido: escolhê-lo com `omarchy default agent openclaw` configura essa mesma cópia em `~/.openclaw`, e o agente abre a interface de terminal do OpenClaw ligada ao seu gateway. Remover o OpenClaw em _Remove > AI_ leva o serviço do gateway e a aplicação com ele e depois pergunta se `~/.openclaw` também deve desaparecer, uma vez que isso guarda as tuas conversas e credenciais juntamente com o próprio OpenClaw e os runtimes de plugins que ele transfere; a predefinição mantém-no, e instalar o OpenClaw outra vez volta a retomá-lo.

O Herdr Desktop é a aplicação de ambiente de trabalho [Herdr](https://herdr.dev): espaços, separadores e painéis de terminais e agentes de programação que continuam a executar no seu núcleo quando fechas a janela. Ele vem do próprio instalador do Herdr e não de um pacote, por isso vive em `~/.local/share/herdr-app`, traz o seu núcleo em `~/.local/bin/herdr-core` quando ainda não tens um, e atualiza ambos. Ele fica ao lado do comando `herdr` que o Omarchy disponibiliza em `Super + Ctrl + Return` em vez de o substituir, e recebe as teclas diretas desse comando: `Alt + Return` e `Alt + Shift + Return` dividem um painel para baixo ou para a direita, `Alt + Escape` fecha-o, `Ctrl + Alt + Arrow` move entre painéis, `Alt + 1..9` e `Alt + Left/Right` escolhem um separador, e `Alt + Up/Down` movem entre espaços. `Ctrl + 1..9` escolhe um espaço e `Alt + Shift + Up/Down` percorre os agentes. As teclas de prefixo `Ctrl + Space` permanecem apenas no terminal, uma vez que a aplicação não consegue manter uma tecla Ctrl simples para uma sequência. O Omarchy escreve estas teclas em `~/.config/herdr-app/keys.json`, e `omarchy-refresh-herdr-app` volta a colocá-las. Instalá-lo escolhe o tema Omarchy do Herdr, que a partir daí segue o teu tema Omarchy. O Herdr mantém um tema para o modo claro e um para o modo escuro, por isso, depois de alternares entre um tema Omarchy escuro e um claro, escolhe Omarchy no seletor de temas do Herdr mais uma vez para o outro modo.

O T3 Code executa a partir da sua versão oficial AppImage em `~/.local/share/t3code` e não a partir de um pacote, por isso atualiza-se a si próprio. Instalá-lo pergunta se queres começar no canal Stable ou Nightly; muda mais tarde nas definições do T3 Code. As tuas conversas e definições vivem em `~/.t3`, e remover o T3 Code em _Remove > AI_ leva-as com ele.

### Modelos locais

Executa um modelo aberto na tua própria máquina para os teus agentes de programação. Os teus prompts e o teu código permanecem na máquina; nada do que é enviado ao modelo sai dela. Começa com:

```bash
omarchy models use best text
```

Isso configura o melhor modelo de texto para esta máquina, do tipo que os teus agentes usam. Os modelos de imagem, vídeo e música têm um melhor próprio: `omarchy models use best image`, `video` ou `music`. Executa `omarchy models use best` para veres a escolha de cada tipo para esta máquina.

Ou escolhe + no painel de agentes: em _Use a local model_ ele lista todos os modelos de programação adequados para esta máquina, com o recomendado primeiro. O Podman, que executa os modelos, vem com o Omarchy, tal como o toolkit de contentores da NVIDIA numa máquina NVIDIA, que lhes dá a GPU; se algum deles estiver em falta, a primeira configuração instala-o. O Omarchy escolhe então o modelo recomendado para esta máquina, transfere-o e arranca-o. Espera uma transferência de dezenas de GB e a maior parte da memória da máquina em uso enquanto o modelo executa: o Flash Next usa cerca de 100 GiB com o seu contexto completo de 256K. Se outros modelos ocuparem a memória de que ele precisa, ele é configurado parado, pronto para arrancar quando parares um deles. O modelo para quando terminas sessão; para-o tu próprio quando precisares da memória para outra coisa.

`omarchy models list` mostra as opções e explica porque é que algumas não servem. Para configurares outro, executa `omarchy models use <recipe>`. Hoje, `qwen3.8-flash-next-gufo` e `qwen3.8-27b-gufo` estão disponíveis para máquinas Strix Halo de 128 GB; o 27B ocupa cerca de 40 GiB, por isso deixa espaço para outro trabalho. Num portátil de 64 GB com a Arc B390 da Intel, `qwen3.6-35b-a3b-llamacpp` executa em cerca de 30 GiB. Novas receitas e recomendações chegam com `omarchy update`, através do pacote.

Um modelo de programação que adicionares ganha uma linha própria no painel de agentes, ao lado das tuas subscrições: reproduzir para o arrancares, pausa para o parares e libertares a sua memória, a marca Tailscale para o partilhares com as outras máquinas da tua tailnet enquanto ele executa, e o botão de terminal para abrires o teu agente nele. A sua linha mostra a transferência, o carregamento ou a paragem à medida que acontecem, e diz isso mesmo quando não há memória livre suficiente para o arrancar, ou cria uma ligação para os seus registos quando ele para com um erro. Vários podem executar ao mesmo tempo quando cabem juntos na memória. Prime Delete numa linha selecionada para removeres o modelo desta máquina, transferência e tudo; o + pode voltar a configurá-lo. Um modelo de programação configurado a partir de um terminal espera sob o + até o adicionares, e o mesmo acontece aos modelos que uma máquina com que emparelhaste (`omarchy models pair <host>`) executa.

Todos os modelos de programação que configurares também ganham uma entrada própria no lançador de aplicações, sob o nome do modelo e com o logótipo do seu fabricante, da forma como iniciar sessão no Claude, no Codex ou no Grok adiciona uma. Ela abre o teu agente nesse modelo, e arranca primeiro o modelo se ele não estiver a executar: o terminal mostra-o a carregar e entrega ao agente quando ele estiver pronto. Remover um modelo remove a sua entrada.

Nem todos os modelos são para programação. Os modelos de imagem, vídeo e música abrem antes no Fantasi, a aplicação do Omarchy para fazeres imagens, vídeo e música com um modelo a executar nesta máquina, e são geridos ali ou com `omarchy models`.

Um modelo continua a executar exatamente como foi configurado, por isso uma atualização do Omarchy nunca reinicia um sob os teus agentes. Quando o Omarchy tem um runtime mais recente ou pesos mais recentes para um modelo que configuraste, a sua linha mostra um botão de atualização: prime-o e o modelo é configurado outra vez em segundo plano, a transferir apenas o que mudou, e reinicia na nova versão. Um modelo que estava parado permanece parado. `omarchy models update` faz o mesmo para todos os modelos a partir de um terminal.

A partir da linha de comando, `omarchy models start <recipe>` e `omarchy models stop <recipe>` fazem o mesmo, `omarchy models status` mostra todos os modelos, e `omarchy agent --local-model <recipe>` abre esse modelo no pi, seja qual for o teu agente predefinido. Para fazeres do teu modelo local aquilo que a tecla de atalho do agente, a consola Quake e _Make something_ abrem, executa `omarchy default agent local` ou marca com uma estrela um modelo em execução no painel de agentes. O pi também lista todos os modelos que configuraste, e os das máquinas com que emparelhaste, no seu próprio seletor de modelos, por isso um simples `pi` também chega a eles. Qualquer cliente compatível com OpenAI também se pode ligar: `status` mostra o endereço de cada modelo (o primeiro é `http://127.0.0.1:11435/v1`), o nome da receita é o modelo, e a chave está em `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` elimina um modelo e as transferências que nenhum outro modelo usa.

Os runtimes de terceiros estão identificados com quem os publica. O Omarchy executa todos os modelos sem acesso à rede.

### LLM locais

O Omarchy recomenda duas formas de executar modelos LLM locais: LM Studio e Ollama. O LM Studio oferece uma interface gráfica para encontrares modelos de pesos abertos, instalá-los e executá-los. É uma ótima forma de começares facilmente. O Ollama oferece uma CLI para fazeres algo semelhante. Mas se estás a começar nos modelos locais, eu começava pelo LM Studio. Podes instalar qualquer um deles em _Install > AI_ no Menu Omarchy.

### As skills do Omarchy

As skills de agente ajudam a IA a usar ferramentas específicas de uma forma específica, e o Omarchy traz sete delas. A skill omarchy cobre a personalização do sistema, como ajustar a tua configuração do Hyprland ou ajustar a barra. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app e omarchy-make-game cobrem fazer algo novo, omarchy-contribute cobre reportar um erro ou enviar uma correção a montante, e omarchy-diagnose-crash trabalha a partir do core dump de um crash. Elas têm ligações simbólicas para as pastas de skills do Claude Code (`~/.claude/skills`), do Codex (`~/.codex/skills`), do Pi (`~/.pi/agent/skills`), do Antigravity (`~/.gemini/config/skills`), do Hermes (`~/.hermes/skills` e cada `~/.hermes/profiles/*/skills`) e para a localização genérica `~/.agents/skills`, por isso a maioria dos harnesses recolhe-as automaticamente. Uma pasta de skill tua com o mesmo nome tem precedência.

Mas deves tratar estas skills como experimentais. Modelos diferentes vão usá-las com efeitos diferentes. É melhor executares primeiro em modo de plano, para teres uma ideia do que o agente gostaria de alterar. E depois está preparado para reverteres as alterações ou até para executares `omarchy reinstall configs`, se o agente fizer uma confusão com tudo.
