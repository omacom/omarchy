# IA

O Omarchy inclui lançadores para os agentes de programação abaixo sem escolher um predefinido para si. Execute um comando para instalar a respetiva CLI na primeira utilização e depois autentique-se quando lhe for pedido. O Hermes e o OpenClaw são as exceções: nada é instalado para eles através do mise, e escolher qualquer um deles configura a sua própria cópia com atualização automática, como _Aplicações de ambiente de trabalho_ abaixo explica.

### Instalar e atualizar agentes

Com exceção do Hermes e do OpenClaw, estes agentes utilizam a instalação lazy do mise: o primeiro arranque instala a CLI e os arranques seguintes reutilizam-na. O mise também verifica se um agente instalado tem uma nova versão, no máximo uma vez a cada quatro horas, mesmo antes de arrancar ou em segundo plano num prompt da shell. Se essa atualização falhar ou se estiver offline, é executada a versão instalada. `omarchy update` atualiza os agentes instalados com o resto do Omarchy, e `mup` atualiza apenas as ferramentas geridas pelo mise.

O atualizador próprio de um agente, como `claude update`, `codex update` ou um botão de atualização numa aplicação, não atualiza a instalação gerida pelo mise. `codex update` falha, e `claude update` pode comunicar sucesso enquanto instala uma cópia separada que o mise não acompanha. Se preferir utilizar o instalador e o atualizador nativos de um agente, adicione-o a `disable_tools`; consulte [Ferramentas CLI pré-instaladas](18-development-tools.md#preinstalled-cli-tools).

Para instalar todas as ferramentas lazy configuradas antes de precisar delas, execute `mise install --include-lazy`. Isto inclui as outras ferramentas CLI predefinidas do Omarchy, bem como os agentes. Consulte [Ferramentas CLI pré-instaladas](18-development-tools.md#preinstalled-cli-tools) para instalar uma única ferramenta ou utilizar a sua própria instalação.

O `grok` é instalado através do pacote `grok` oficial do mise, da mesma forma que o `claude` e o `codex`. Execute `grok`, ou escolha-o em _Agent > Harness_. Ignore o instalador `curl | bash` em x.ai. Esse caminho coloca uma segunda cópia em `~/.grok/bin`, coloca-a no início do `PATH` e sobrescreve o wrapper do Omarchy.

O `dsh` abre a sua interface de navegador em `127.0.0.1:3080`, com o diretório de arranque como área de trabalho predefinida. A sua interface de navegador não aceita um prompt inicial, por isso `omarchy agent prompt` abre-o com o prompt na sua área de transferência para colar. O Omarchy arranca-o com o preset de permissões sem aprovação da DeepSeek. O DeepSeek Harness carrega registos de sessão para a DeepSeek quando utiliza a sua API oficial de modelos; desative isso em _Settings > General > Upload Session Log_ na sua interface de navegador. O feedback que enviar também é carregado com a sessão, a menos que o arranque com `DSH_TELEMETRY_MODE=DISABLED`.

### O agente predefinido

Escolha o seu agente predefinido com `omarchy default agent <name>` ou em _Agent > Harness_ no Menu Omarchy (`Super + Space`). Se o agente ainda não estiver instalado, escolhê-lo instala-o primeiro, e ele também ganha um lançador próprio no lançador de aplicações, ao lado de Agent. Um Omarchy novo convidá-lo-á a fazer esta escolha com uma notificação única.

Escolher o Claude também tenta configurar a sua extensão de navegador para Chromium, Chrome, Brave, Brave Origin e Edge. A configuração da extensão aplica-se a todos os utilizadores e pode pedir a sua palavra-passe do sistema; cancelar ou uma instalação da extensão falhada continua a selecionar e a arrancar o Claude. Reinicie o navegador, ative a extensão se lhe for pedido e inicie sessão no Claude para concluir a ligação. Execute `/chrome` no Claude para verificar a ligação. O Firefox e o Zen não suportam esta extensão. Se o Claude já era o seu predefinido antes de esta configuração ser adicionada, selecione-o novamente para instalar a extensão.

Depois de fazer a escolha, `Super + Shift + Ctrl + A` arranca o agente predefinido numa janela de terminal dedicada (ou abre o seletor se ainda não tiver escolhido). Também pode arrancá-lo diretamente para uma tarefa com `omarchy agent prompt "Review this project"`. O Freebuff e o DeepSeek Harness não aceitam um prompt inicial, por isso abrem com o prompt na sua área de transferência para colar. Os agentes arrancados desta forma funcionam sem supervisão nos respetivos modos de não parar para perguntar, por isso esteja pronto para eles fazerem mesmo coisas! O MiniMax Code não tem esse modo para as suas sessões interativas, por isso pede permissões como habitualmente. E como os agentes se recusam a memorizar a confiança no seu diretório pessoal, os arranques a partir de `$HOME` começam antes em `~/Work`.

Também há atalhos de terminal: `a` executa o agente predefinido inline no terminal atual, enquanto `c`, `cx` e `cy` arrancam o OpenCode, o Claude Code e o Codex diretamente (também nos seus modos de aprovação automática). As alterações de tema também são sincronizadas com os agentes: o Claude Code, o Pi, o OpenCode e o Hermes (depois de o Omarchy o ter instalado) acompanham-no quando muda o tema do Omarchy.

### As instruções do seu agente

As regras pessoais para todos os agentes ficam em `~/.agents/AGENTS.md`, ao lado das skills partilhadas em `~/.agents/skills`. Abra-o em _Agent > Instructions_, que também o liga a cada harness que mantém o seu próprio ficheiro global: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, o `~/.copilot/copilot-instructions.md` do Copilot, e assim por diante. O Crush e o Amp leem a ligação `~/.config/AGENTS.md`, enquanto o omp, o Kimi e o DeepSeek Harness leem `~/.agents/AGENTS.md` diretamente. Escolher um agente predefinido também o liga. Um ficheiro de instruções que já tinha torna-se o partilhado se ainda não existia nenhum; caso contrário, é mantido ao lado da ligação como `.bak`. Execute `omarchy agent instructions` para voltar a ligar depois de instalar outro agente.

### O painel de agentes

A barra superior tem um ícone de agentes. Antes de ter configurado um agente, o painel dele orienta-o a iniciar sessão no Claude, no Codex ou no Grok, e o primeiro torna-se o seu agente predefinido. Depois disso, o painel coloca todas as subscrições numa só página: cada agente e conta com o seu plano, um medidor para cada um dos seus limites de sessão de 5 horas e semanais com o tempo até ao reinício (passe o cursor por cima para ver a percentagem exata), ou o saldo pré-pago restante, sob uma linha que vai rodando pelo que utilizou em todos eles, como os tokens desta semana e o seu modelo mais utilizado. Em _Make something cool_, oferece prompts iniciais para um novo tema, plugin, aplicação ou jogo que entregam a tarefa ao seu agente predefinido. As aplicações são construídas da mesma forma que as próprias Hype, Monologue e Omacut do Omarchy, em C++ e Qt Quick, seguindo a skill de agente omarchy-make-app, e o compilador e as peças Qt de que precisam vêm instalados. Os jogos são uma única página three.js em `~/Games/vibes`, seguindo a skill de agente omarchy-make-game, e todos abrem a partir de um lançador Game Vibes no tema atual; carregam o three.js a partir da web, por isso precisam de uma ligação para arrancar. O Claude Code, o Codex, o Grok, o Kimi, o Cursor e a sua quota Grok Bot, o GitHub Copilot, o Muse, o Antigravity e o Devin estão cobertos de origem com os seus limites, o Kimchi com o seu plano, créditos pré-pagos e orçamentos de despesa, e o Hermes, o Mistral Vibe e o Qwen Code mostram as suas sessões e tokens depois de os ter utilizado. Os planos e as chaves de fornecedores que utiliza através do pi, do omp ou do opencode também aparecem: o OpenCode Zen e Go, o Z.ai GLM Coding Plan, a Ollama Cloud, o MiniMax Token Plan e o Synthetic com os seus limites; a OpenRouter e a DeepSeek com os seus saldos pré-pagos; a Fireworks com a sua despesa nos últimos 30 dias. Os tokens de modelos que executa no seu próprio hardware também contam para os totais; os modelos em si têm um painel próprio, descrito em [Modelos locais](#local-models). Cada agente é contado uma vez, sob quem o fatura, por mais harnesses através dos quais o utilize.

Clique com o botão esquerdo no ícone da barra ou prima `Super + Ctrl + X` para abrir o painel, clique com o botão direito para arrancar o seu agente predefinido e clique com o botão do meio para atualizar. Os registos de utilização que estão por trás dele são regenerados a cada 15 minutos por `omarchy agent usage update`, e o painel pode até fundir a utilização das suas outras máquinas através de uma pasta sincronizada. Consulte o README em `$OMARCHY_PATH/shell/plugins/agents/` para ver todas as definições.

### Várias subscrições

Se pagar por mais de um plano Claude, Codex ou Grok — um Max pessoal e um de trabalho, por exemplo —, o Omarchy pode manter todos com sessão iniciada e passar de uns para os outros. Adicione uma subscrição com o + no painel de agentes, que o orienta logo ali, ou com `omarchy agent account add claude Work` (ou `codex`, ou `grok`). Instala a CLI se ela estiver em falta. A primeira conta de um fornecedor inicia sessão através do seu navegador normal, exatamente onde a CLI sempre procura. Todas as seguintes iniciam sessão através de uma janela privada, para que a conta em que o seu navegador já tem sessão iniciada não seja apanhada por engano; inicie sessão ali como a conta que está a adicionar e feche primeiro qualquer janela privada que já tenha aberta. Nunca termine sessão na CLI para fazer isto: terminar sessão revoga o início de sessão guardado, e essa conta teria de ser adicionada novamente.

Para copiar os seus inícios de sessão de subscrição para outra máquina Omarchy por SSH, execute `omarchy agent account copy user@laptop`. O emissor fornece um recetor temporário quando o destino não tem um instalado, por isso as máquinas Omarchy mais antigas podem receber contas sem uma atualização. Os recetores instalados têm precedência. Isto copia todas as subscrições Claude, Codex e Grok; adicione nomes de fornecedores para as selecionar, como em `omarchy agent account copy laptop claude`. Os nomes das contas e os IDs de comando correspondem à origem, incluindo as contas já presentes no destino. As contas de destino não relacionadas recebem um sufixo numérico se os seus nomes entrarem em conflito, e as definições, skills, plugins e histórico de conversas permanecem locais a cada máquina.

As credenciais de destino existentes são mantidas. Uma conta de origem que já tem sessão iniciada lá tem o nome sincronizado sem substituir as suas credenciais; as outras contas são adicionadas ao lado dela. Para substituir as credenciais guardadas de contas correspondentes, utilize `omarchy agent account copy --replace laptop claude` depois de sair das sessões dessa conta no destino. Um destino novo também recebe a conta ativa e as preferências de troca da origem; um destino já estabelecido mantém as suas.

As credenciais viajam por SSH e são guardadas em ficheiros privados no destino, por isso copie apenas para máquinas em que confia. Isto é uma cópia única, não uma sincronização contínua. Os tokens de atualização do Codex podem ser rodados por outra máquina, deixando um início de sessão copiado a precisar de renovação; inícios de sessão separados continuam a ser a escolha mais fiável para uma utilização simultânea em várias máquinas. Consulte a [orientação de autenticação de contas do Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Uma conta por fornecedor está ativa, e todas as novas sessões começam como ela: `cx`, `cy`, um simples `claude`, `codex` ou `grok`, qualquer coisa arrancada através de `omarchy agent`, e scripts ou editores que encontrem a CLI no `PATH`. Troque com `omarchy agent account use work` (e volte com `omarchy agent account use main`), ou no painel, premindo o número de uma conta e depois `Enter` (ou clicando no botão Use dela). As sessões Claude em execução também trocam, a partir da mensagem seguinte: todas as sessões Claude executam em `~/.claude`, que contém sempre o início de sessão da conta ativa. Uma sessão Claude iniciada na pasta própria de uma conta por um Omarchy mais antigo mantém esse início de sessão até sair, por isso a troca nomeia essas sessões e termina por si só quando elas desaparecerem. As sessões Codex e Grok em execução permanecem na conta com que começaram. O histórico de conversas, as definições, as skills e os plugins são partilhados entre contas, por isso `claude --continue` na mesma pasta continua onde ficou na nova conta.

Com mais de uma conta, o painel mostra os limites de cada conta lado a lado, com a ativa marcada. Por predefinição, o Omarchy avisa-o quando a conta ativa ultrapassa 95% de um limite, e clicar na notificação muda para a conta com mais margem. Passe o cursor sobre a linha de uma conta no painel e clique em Autoswitch, que aparece ao lado de Use (ou prima `m`), ou execute `omarchy agent account mode auto`, para que ele mude por si só; enquanto estiver ligado, o Autoswitch ocupa o lugar do Use, e clicar nele novamente volta a apenas avisar. Adicione um número para alterar o limiar, como em `omarchy agent account mode auto 90`. Se todas as contas estiverem acima do limiar, será avisado uma vez, juntamente com a indicação de qual conta fica livre primeiro. Enquanto uma conta ativa estiver a menos de 15 pontos do seu limiar (80% na predefinição), os seus limites são verificados a cada três minutos em vez de a cada 15.

`omarchy agent account list` mostra todas as contas e os seus limites mais recentes, `omarchy agent account remove work` esquece uma, e `omarchy agent account rename primary Hey` muda o nome de uma (ou clique no nome de uma conta no painel). Estes comandos funcionam nas contas do seu agente predefinido; para chegar ao outro fornecedor, nomeie-o primeiro, como em `omarchy agent account use codex side`. O início de sessão que já tinha em `~/.claude` ou `~/.codex` é a conta _Main_. A do Codex permanece onde está; a do Claude espera numa pasta própria enquanto outra conta estiver ativa. Uma conta deixada sem utilização durante mais de cerca de oito horas pode mostrar _Sign-in required_; clique nela para iniciar sessão nessa conta novamente diretamente no painel, ou mude para ela e inicie uma sessão, o que atualiza o início de sessão por si só. Os servidores MCP que adicionar com `claude mcp add` chegam a todas as contas Claude, uma vez que todas executam em `~/.claude`; para o Codex e o Grok, os servidores que tinha quando uma conta foi adicionada acompanham-na, mas os posteriores só chegam à conta em que os adicionou. O Claude Desktop mantém um início de sessão próprio, e as ferramentas Codex ou Grok configuradas com um caminho absoluto para um binário da CLI não acompanham a troca. Um `CLAUDE_CONFIG_DIR`, `CODEX_HOME` ou `GROK_HOME` explícito tem precedência sobre a conta selecionada.

### Diagnóstico de crashes

O Omarchy observa o systemd-coredump para detetar crashes de processos. Depois de escolher um agente predefinido, qualquer programa seu que faça um core dump traz uma notificação "Process crashed" — clique nela, e o crash é entregue ao seu agente predefinido juntamente com a skill omarchy-diagnose-crash do Omarchy, que orienta o agente a estabelecer os factos a partir do core dump e a decidir se o crash vale a pena ser comunicado a montante. Também pode executá-lo manualmente contra qualquer PID de `coredumpctl list` com `omarchy agent crash <pid>`.

A observação está ligada por predefinição. Desligue-a em _Trigger > Toggle > Crash Capture Off_ (ou com `omarchy toggle crash-capture`) e as notificações param; `omarchy agent crash <pid>` continua a funcionar manualmente.

Os crashes também podem ser silenciados um programa de cada vez, que é o que o diagnóstico lhe oferece no fim. `omarchy crash mute hyprland` para as notificações apenas para esse programa, `omarchy crash mute hyprland off` volta a trazê-las, e `omarchy crash mute` por si só lista o que silenciou. Aceita o caminho do binário tão bem como o nome, por isso `omarchy crash mute /usr/bin/hyprland` faz o mesmo. Coloque entre aspas um nome com um espaço, como em `omarchy crash mute 'Some App'`. Tudo o resto continua a notificar, e o programa silenciado continua a fazer crash — isto esconde o lembrete, não corrige nada.

### Aplicações de ambiente de trabalho

O menu _Install > AI_ também traz algumas aplicações gráficas de IA: Amp Desktop, Antigravity Desktop, a aplicação de ambiente de trabalho do ChatGPT, a aplicação de ambiente de trabalho do Claude (a beta para Linux da Anthropic, com separadores Chat, Cowork e Claude Code), Grok Bot para conversar com os modelos da xAI, Herdr Desktop, Hermes Desktop, OpenClaw, a aplicação de ambiente de trabalho do Perplexity e T3 Code. O Grok Bot é a aplicação de chat de ambiente de trabalho. O agente de programação é o comando `grok`.

O Hermes Desktop é o que deve conhecer, porque uma máquina tem um Hermes, e ele é o da aplicação: o Hermes só é alguma vez instalado através da aplicação, e o comando `hermes` que o agente predefinido executa é o da aplicação. Escolher o Hermes como agente predefinido instala o mesmo que a entrada _Install > AI_: o pacote e um runtime Hermes em `~/.hermes` configurado pelo próprio instalador do Hermes, o que demora alguns minutos na primeira vez. Esse runtime é o único Hermes que o comando de terminal `hermes`, o agente predefinido e a aplicação utilizam, e ele atualiza-se a si próprio com `hermes update` em vez de esperar por uma versão do Omarchy. Instalá-lo também entrega ao Hermes o tema Omarchy como uma skin chamada `omarchy`, que todas as superfícies do Hermes seguem à medida que muda de temas; escolha outra nas definições de Appearance do Hermes ou com `/skin` se preferir que ele não o faça, e o Omarchy deixa essa escolha em paz. Remover a aplicação em _Remove > AI_ fecha primeiro o Hermes, gateway incluído, leva esse runtime consigo e mantém os seus chats, memórias e as skills que o Hermes escreveu para si próprio, a menos que lhe diga o contrário: pergunta, com não como predefinição, se esses dados e as suas definições de ligação também devem ir.

A experiência de ambiente de trabalho do OpenClaw é a sua Control UI, que abre como uma aplicação web apoiada pelo seu próprio gateway local. O OpenClaw vive em `~/.openclaw` e atualiza-se a si próprio: utilize o botão "Update Gateway" da Control UI ou execute `openclaw update`, e o gateway reinicia na nova versão. O Omarchy só escolhe a versão a partir da qual uma instalação nova começa. O OpenClaw também pode ser o seu agente predefinido: escolhê-lo em _Agent > Harness_ configura essa mesma cópia em `~/.openclaw`, e o agente abre a interface de terminal do OpenClaw ligada ao seu gateway. Remover o OpenClaw em _Remove > AI_ leva o serviço do gateway e a aplicação consigo e depois pergunta se `~/.openclaw` também deve ir, uma vez que é aí que ficam os seus chats e credenciais, juntamente com o próprio OpenClaw e os runtimes de plugins que ele descarrega; a predefinição mantém-no, e instalar o OpenClaw novamente volta a retomá-lo.

O Herdr Desktop é a aplicação de ambiente de trabalho [Herdr](https://herdr.dev): espaços, separadores e painéis de terminais e agentes de programação que continuam a executar no seu núcleo quando fecha a janela. Vem do próprio instalador do Herdr e não de um pacote, por isso vive em `~/.local/share/herdr-app`, traz o seu núcleo em `~/.local/bin/herdr-core` quando ainda não tem um, e atualiza ambos. Fica ao lado do comando `herdr` que o Omarchy fornece em `Super + Ctrl + Return`, em vez de o substituir, e recebe as teclas diretas desse comando: `Alt + Return` e `Alt + Shift + Return` dividem um painel para baixo ou para a direita, `Alt + Escape` fecha-o, `Ctrl + Alt + Arrow` move entre painéis, `Alt + 1..9` e `Alt + Left/Right` escolhem um separador, e `Alt + Up/Down` move entre espaços. `Ctrl + 1..9` escolhe um espaço e `Alt + Shift + Up/Down` percorre os agentes. As teclas de prefixo `Ctrl + Space` permanecem apenas para o terminal, uma vez que a aplicação não consegue manter premida uma tecla Ctrl simples para uma sequência. O Omarchy escreve estas teclas em `~/.config/herdr-app/keys.json`, e `omarchy-refresh-herdr-app` repõe-nas. Instalá-lo escolhe o tema Omarchy do Herdr, que a partir daí segue o seu tema Omarchy. O Herdr mantém um tema para o modo claro e um para o modo escuro, por isso, depois de mudar entre um tema Omarchy escuro e um claro, escolha Omarchy no seletor de temas do Herdr mais uma vez para o outro modo.

O T3 Code executa a partir da sua versão oficial em AppImage em `~/.local/share/t3code`, e não a partir de um pacote, por isso atualiza-se a si próprio. Instalá-lo pergunta se deve começar no canal Stable ou Nightly; mude mais tarde nas definições do T3 Code. As suas threads e definições vivem em `~/.t3`, e remover o T3 Code em _Remove > AI_ leva-as consigo.

### Modelos locais

Execute um modelo aberto na sua própria máquina para os seus agentes de programação. Os seus prompts e o seu código permanecem na máquina; nada do que é enviado para o modelo sai dela. Comece com:

```bash
omarchy models use best text
```

Isso configura o melhor modelo de texto para esta máquina, do tipo que os seus agentes utilizam. Os modelos de imagem, vídeo e música têm um melhor próprio: `omarchy models use best image`, `video` ou `music`. Execute `omarchy models use best` para ver a escolha de cada tipo para esta máquina.

Ou abra o painel de modelos locais a partir do seu ícone de brilhos na barra superior, ao lado do ícone de agentes, ou com Super + Ctrl + Alt + X, e escolha +. O ícone aparece quando um modelo cabe nesta máquina. O Podman, que executa os modelos, vem com o Omarchy, tal como o kit de ferramentas de contentores da NVIDIA numa máquina NVIDIA, que lhes dá a GPU; se algum deles estiver em falta, a primeira configuração instala-o. Depois, o Omarchy escolhe o modelo recomendado para esta máquina, descarrega-o e arranca-o. Conte com um download de dezenas de GB e com a maior parte da memória da máquina em utilização enquanto o modelo está a executar: o Flash Next utiliza cerca de 100 GiB com o seu contexto completo de 256K. Se outros modelos ocuparem a memória de que ele precisa, ele é configurado parado, pronto para arrancar quando parar um deles. O modelo para ao terminar sessão; pare-o você mesmo quando precisar da memória para outra coisa.

`omarchy models list` mostra as opções e explica por que algumas não cabem. Para configurar outro, execute `omarchy models use <recipe>`. Hoje, `qwen3.8-flash-next-gufo` e `qwen3.8-27b-gufo` estão disponíveis para máquinas Strix Halo de 128 GB; o 27B ocupa cerca de 40 GiB, por isso deixa espaço para outro trabalho. Num portátil de 64 GB com a Arc B390 da Intel, `qwen3.6-35b-a3b-llamacpp` executa em cerca de 30 GiB. Novas receitas e recomendações chegam com `omarchy update`, através do pacote.

Cada modelo que configurar ganha a sua própria linha no painel de modelos locais: reproduzir para o arrancar, pausa para o parar e libertar a sua memória, e o botão de terminal para abrir o seu agente nele. No topo, uma barra mostra como a memória da máquina está dividida entre o próprio Omarchy (o sistema e as suas aplicações), cada modelo em execução e o que está livre. Aponte para um modelo parado e a barra mostra se ele cabe, ou quanto lhe falta. Vários podem executar ao mesmo tempo quando cabem juntos na memória; se um não couber, o Omarchy diz qual modelo em execução deve parar. Arraste as linhas pelo logótipo delas para as reordenar e prima Delete numa linha selecionada para remover um modelo e o seu download.

Cada modelo que configurar também ganha uma entrada própria no lançador de aplicações, sob o nome do modelo e com o logótipo do seu criador, da mesma forma que iniciar sessão no Claude, no Codex ou no Grok adiciona uma. Ela abre o seu agente nesse modelo e arranca primeiro o modelo se ele não estiver em execução: o terminal mostra-o a carregar e entrega-o ao agente quando ele estiver pronto. Remover um modelo remove a sua entrada.

Nem todos os modelos são para programação. Os modelos de imagem, vídeo e música abrem antes no Fantasi, a aplicação do Omarchy para fazer imagens, vídeo e música com um modelo a executar nesta máquina, a partir da sua entrada no lançador e da sua linha no painel de modelos locais.

Um modelo continua a executar exatamente como foi configurado, por isso uma atualização do Omarchy nunca reinicia um por baixo dos seus agentes. Quando o Omarchy tem um runtime mais recente ou pesos mais recentes para um modelo que configurou, a linha dele mostra um botão de atualização: prima-o e o modelo é configurado novamente em segundo plano, descarregando apenas o que mudou, e reinicia na nova versão. Um modelo que estava parado permanece parado. `omarchy models update` faz o mesmo para todos os modelos a partir de um terminal.

A partir da linha de comandos, `omarchy models start <recipe>` e `omarchy models stop <recipe>` fazem o mesmo, `omarchy models status` mostra todos os modelos, e `omarchy agent --local` abre o seu agente predefinido no último modelo que arrancou. O pi, o OpenCode e o Qwen Code podem utilizar um; com qualquer outro predefinido, abre no pi, ou no OpenCode se não tiver o pi. O pi também lista todos os modelos que configurou, e os das máquinas com que emparelhou, no seu próprio seletor de modelos, por isso um simples `pi` também os alcança. Qualquer cliente compatível com a OpenAI também se pode ligar: `status` mostra o endereço de cada modelo (o primeiro é `http://127.0.0.1:11435/v1`), o nome da receita é o modelo, e a chave está em `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` elimina um modelo e os downloads que nenhum outro modelo utiliza.

Os runtimes de terceiros estão etiquetados com o seu editor. O Omarchy executa todos os modelos sem acesso à rede.

### LLMs locais

O Omarchy recomenda duas formas de executar modelos LLM locais: LM Studio e Ollama. O LM Studio fornece uma interface GUI para encontrar modelos de pesos abertos, instalá-los e executá-los. É uma excelente forma de começar facilmente. O Ollama oferece uma CLI para fazer o mesmo de forma semelhante. Mas se é novo nos modelos locais, eu começaria pelo LM Studio. Pode instalar qualquer um deles em _Install > AI_ no Menu Omarchy.

### As skills do Omarchy

As skills de agente ajudam a IA a utilizar ferramentas específicas de uma forma específica, e o Omarchy fornece sete delas. A skill omarchy abrange a adaptação do sistema, como ajustar a sua configuração do Hyprland ou regular a barra. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app e omarchy-make-game abrangem fazer algo novo, omarchy-contribute abrange comunicar um bug ou enviar uma correção a montante, e omarchy-diagnose-crash trabalha a partir do core dump de um crash. Estão ligadas por symlink aos diretórios de skills do Claude Code (`~/.claude/skills`), do Codex (`~/.codex/skills`), do Pi (`~/.pi/agent/skills`), do Antigravity (`~/.gemini/config/skills`), do Hermes (`~/.hermes/skills` e cada `~/.hermes/profiles/*/skills`) e à localização genérica `~/.agents/skills`, por isso a maioria dos harnesses capta-as automaticamente. Uma pasta de skill sua com o mesmo nome tem precedência.

Mas deve tratar estas skills como experimentais. Modelos diferentes vão utilizá-las com efeitos diferentes. É melhor executar primeiro em modo de plano, para ter uma ideia do que o agente gostaria de alterar. E depois esteja pronto para reverter alterações ou até para invocar `omarchy reinstall configs`, se o agente fizer uma confusão de tudo.
