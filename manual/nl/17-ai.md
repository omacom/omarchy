# AI

Omarchy bevat launchers voor de onderstaande coding agents, zonder een standaard voor je te kiezen. Voer een commando uit om bij het eerste gebruik zijn CLI te installeren en verifieer je vervolgens wanneer daarom wordt gevraagd. Hermes en OpenClaw zijn de uitzonderingen: voor hen wordt niets via mise geïnstalleerd, en als je een van beide kiest, wordt een eigen, zichzelf bijwerkende kopie opgezet, zoals _Desktop-apps_ hieronder uitlegt.

### Agents installeren en bijwerken

Met uitzondering van Hermes en OpenClaw gebruiken deze agents de luie installatie van mise: de eerste start installeert de CLI, en latere starts hergebruiken hem. mise controleert een geïnstalleerde agent ook hooguit eens per vier uur op een nieuwe release, vlak voordat hij start of op de achtergrond bij een shellprompt. Als die update mislukt of je offline bent, draait de geïnstalleerde versie. `omarchy update` werkt geïnstalleerde agents bij samen met de rest van Omarchy, en `mup` werkt alleen door mise beheerde tools bij.

De eigen updater van een agent, zoals `claude update`, `codex update` of een updateknop in een app, werkt de door mise beheerde installatie niet bij. `codex update` mislukt, en `claude update` kan succes melden terwijl het een aparte kopie installeert die mise niet volgt. Als je liever de native installer en updater van een agent gebruikt, voeg hem dan toe aan `disable_tools`; zie [Vooraf geïnstalleerde CLI-tools](18-development-tools.md#preinstalled-cli-tools).

Om alle geconfigureerde lazy tools te installeren voordat je ze nodig hebt, voer je `mise install --include-lazy` uit. Dit omvat ook Omarchy's andere standaard CLI-tools, naast de agents. Zie [Vooraf geïnstalleerde CLI-tools](18-development-tools.md#preinstalled-cli-tools) voor het installeren van een enkele tool of het gebruiken van je eigen installatie.

`grok` wordt geïnstalleerd via het first-party `grok`-pakket van mise, op dezelfde manier als `claude` en `codex`. Voer `grok` uit, of kies hem onder _Agent > Harness_. Sla de `curl | bash`-installer op x.ai over. Dat pad plaatst een tweede kopie in `~/.grok/bin`, zet hem vooraan op `PATH` en overschrijft Omarchy's wrapper.

`dsh` opent zijn browser-UI op `127.0.0.1:3080`, met de startmap als standaard werkruimte. Zijn browser-UI accepteert geen startprompt, dus `omarchy agent prompt` opent hem met de prompt op je klembord om te plakken. Omarchy start hem met de no-approval permissie-preset van DeepSeek. DeepSeek Harness uploadt sessielogs naar DeepSeek wanneer je zijn officiële model-API gebruikt; zet dat uit onder _Settings > General > Upload Session Log_ in zijn browser-UI. Feedback die je hem stuurt, wordt ook met de sessie geüpload, tenzij je hem start met `DSH_TELEMETRY_MODE=DISABLED`.

### De standaardagent

Kies je standaardagent met `omarchy default agent <name>` of onder _Agent > Harness_ in het Omarchy Menu (`Super + Space`). Als de agent nog niet is geïnstalleerd, wordt hij bij het kiezen eerst geïnstalleerd, en hij krijgt ook een eigen launcher in de app launcher, naast Agent. Een verse Omarchy nodigt je met een eenmalige melding uit om deze keuze te maken.

Kiezen voor Claude probeert ook zijn browserextensie voor Chromium, Chrome, Brave, Brave Origin en Edge op te zetten. De installatie van de extensie geldt voor alle gebruikers en kan om je systeemwachtwoord vragen; annuleren of een mislukte extensie-installatie selecteert en start Claude nog steeds. Herstart je browser, schakel de extensie in als daarom wordt gevraagd en log in bij Claude om de verbinding te voltooien. Voer `/chrome` uit in Claude om de verbinding te controleren. Firefox en Zen ondersteunen deze extensie niet. Als Claude al je standaard was voordat deze installatie werd toegevoegd, selecteer hem dan opnieuw om de extensie te installeren.

Zodra je hebt gekozen, start `Super + Shift + Ctrl + A` de standaardagent in een apart terminalvenster (of opent de kiezer als je nog niet hebt gekozen). Je kunt hem ook direct met een taak starten met `omarchy agent prompt "Review this project"`. Freebuff en DeepSeek Harness accepteren geen startprompt, dus zij openen in plaats daarvan met de prompt op je klembord om te plakken. Agents die op deze manier worden gestart, draaien onbeheerd in hun respectieve don't-stop-to-ask-modi, dus wees erop voorbereid dat ze daadwerkelijk dingen gaan doen! MiniMax Code heeft geen dergelijke modus voor zijn interactieve sessies, dus hij vraagt zoals gewoonlijk om toestemming. En omdat agents weigeren vertrouwen te onthouden voor je thuismap, starten launches vanuit `$HOME` in plaats daarvan in `~/Work`.

Er zijn ook terminal-sneltoetsen: `a` voert de standaardagent inline uit in de huidige terminal, terwijl `c`, `cx` en `cy` OpenCode, Claude Code en Codex direct starten (opnieuw in hun auto-goedkeurende modi). Themawijzigingen synchroniseren ook mee naar de agents: Claude Code, Pi, OpenCode en Hermes (zodra Omarchy hem heeft geïnstalleerd) volgen allemaal mee wanneer je van Omarchy-thema wisselt.

### Je agentinstructies

Persoonlijke regels voor elke agent staan in `~/.agents/AGENTS.md`, naast de gedeelde skills in `~/.agents/skills`. Open het onder _Agent > Instructions_, dat het ook koppelt aan elke harness die zijn eigen globale bestand bijhoudt: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, Copilot's `~/.copilot/copilot-instructions.md`, enzovoort. Crush en Amp lezen de link `~/.config/AGENTS.md`, terwijl omp, Kimi en DeepSeek Harness `~/.agents/AGENTS.md` direct lezen. Het kiezen van een standaardagent koppelt het ook. Een instructiebestand dat je al had, wordt het gedeelde bestand als er nog geen was; anders wordt het naast de link bewaard als `.bak`. Voer `omarchy agent instructions` uit om opnieuw te koppelen na het installeren van een andere agent.

### Het agents-paneel

De bovenbalk heeft een agents-icoon. Voordat je een agent hebt ingesteld, leidt zijn paneel je door het inloggen bij Claude, Codex of Grok, en de eerste wordt je standaardagent. Daarna zet het paneel elk abonnement op één pagina: elke agent en elk account met zijn abonnement, een meter voor elk van zijn sessielimieten van 5 uur en wekelijkse limieten met de tijd tot hij reset (beweeg eroverheen voor het exacte percentage), of het resterende prepaid saldo, onder een regel die roteert door wat je bij hen allemaal hebt gebruikt, zoals tokens deze week en je meest gebruikte model. Onder _Make something cool_ biedt het startprompts voor een nieuw thema, plugin, app of game die de taak aan je standaardagent overhandigen. Apps worden gebouwd zoals Omarchy's eigen Hype, Monologue en Omacut, in C++ en Qt Quick, volgens de omarchy-make-app agent skill, en de compiler en Qt-onderdelen die ze nodig hebben, worden meegeleverd. Games zijn één enkele three.js-pagina in `~/Games/vibes`, volgens de omarchy-make-game agent skill, en openen allemaal vanuit één Game Vibes launcher in het huidige thema; ze laden three.js van het web, dus ze hebben een verbinding nodig om te starten. Claude Code, Codex, Grok, Kimi, Cursor en zijn Grok Bot-tegoed, GitHub Copilot, Muse, Antigravity en Devin worden out of the box ondersteund met hun limieten, Kimchi met zijn abonnement, prepaid credits en uitgavenbudgetten, en Hermes, Mistral Vibe en Qwen Code tonen hun sessies en tokens zodra je ze hebt gebruikt. Providerabonnementen en -sleutels die je via pi, omp of opencode gebruikt, verschijnen ook: OpenCode Zen en Go, het Z.ai GLM Coding Plan, Ollama Cloud, het MiniMax Token Plan en Synthetic met hun limieten; OpenRouter en DeepSeek met hun prepaid saldi; Fireworks met zijn uitgaven over de laatste 30 dagen. Tokens van modellen die je op je eigen hardware draait, tellen ook mee voor de totalen; de modellen zelf hebben een eigen paneel, beschreven onder [Lokale modellen](#local-models). Elke agent wordt één keer geteld, onder wie hem ook factureert, hoeveel harnesses je er ook doorheen aanstuurt.

Klik met links op het balkicoon of druk op `Super + Ctrl + X` voor het paneel, klik met rechts om je standaardagent te starten en klik met het midden om te verversen. De gebruiksgegevens erachter worden elke 15 minuten opnieuw gegenereerd door `omarchy agent usage update`, en het paneel kan zelfs gebruik van je andere machines samenvoegen via een gesynchroniseerde map. Zie de README onder `$OMARCHY_PATH/shell/plugins/agents/` voor de volledige instellingen.

### Meerdere abonnementen

Als je voor meer dan één Claude-, Codex- of Grok-abonnement betaalt — bijvoorbeeld een persoonlijk Max-abonnement en een voor werk — kan Omarchy ze allemaal ingelogd houden en ertussen wisselen. Voeg een abonnement toe met de + in het agents-paneel, dat je er daar meteen doorheen leidt, of met `omarchy agent account add claude Work` (of `codex`, of `grok`). Het installeert de CLI als die ontbreekt. Het eerste account voor een provider logt in via je normale browser, precies waar de CLI altijd kijkt. Elk volgend account logt in via een privévenster, zodat het account waarbij je browser al is ingelogd niet per ongeluk wordt opgepikt; log daar in als het account dat je toevoegt, en sluit eerst elk privévenster dat je al open had. Log hiervoor nooit uit bij de CLI: uitloggen trekt de opgeslagen login in, en dat account zou opnieuw moeten worden toegevoegd.

Om je abonnementslogins via SSH naar een andere Omarchy-machine te kopiëren, voer je `omarchy agent account copy user@laptop` uit. De afzender levert een tijdelijke ontvanger wanneer de bestemming er geen heeft geïnstalleerd, zodat oudere Omarchy-machines accounts kunnen ontvangen zonder update. Geïnstalleerde ontvangers hebben voorrang. Dit kopieert alle Claude-, Codex- en Grok-abonnementen; voeg providernamen toe om ze te selecteren, zoals in `omarchy agent account copy laptop claude`. Accountnamen en commando-ID's komen overeen met de bron, inclusief accounts die al op de bestemming aanwezig zijn. Niet-gerelateerde bestemmingsaccounts krijgen een numeriek achtervoegsel als hun namen conflicteren, en instellingen, skills, plugins en gespreksgeschiedenis blijven lokaal op elke machine.

Bestaande inloggegevens op de bestemming blijven behouden. Een bronaccount dat daar al is ingelogd, krijgt zijn naam gesynchroniseerd zonder zijn inloggegevens te vervangen; andere accounts worden ernaast toegevoegd. Om opgeslagen inloggegevens voor overeenkomende accounts te vervangen, gebruik je `omarchy agent account copy --replace laptop claude` nadat je de sessies van dat account op de bestemming hebt afgesloten. Een verse bestemming krijgt ook het actieve account en de wisselvoorkeuren van de bron; een gevestigde bestemming behoudt haar eigen.

Inloggegevens reizen via SSH en worden opgeslagen in privébestanden op de bestemming, dus kopieer alleen naar machines die je vertrouwt. Dit is een eenmalige kopie, geen doorlopende synchronisatie. Codex-refresh-tokens kunnen door een andere machine worden geroteerd, waardoor een gekopieerde login vernieuwing nodig heeft; aparte logins blijven de meest betrouwbare keuze voor gelijktijdig gebruik op meerdere machines. Zie de [authenticatiehandleiding voor accounts van Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Eén account per provider is actief, en elke nieuwe sessie start als dat account: `cx`, `cy`, een gewone `claude`, `codex` of `grok`, alles wat via `omarchy agent` wordt gestart, en scripts of editors die de CLI op `PATH` vinden. Wissel met `omarchy agent account use work` (en terug met `omarchy agent account use main`), of in het paneel door op het nummer van een account te drukken en daarna op `Enter` (of op de Use-knop te klikken). Draaiende Claude-sessies wisselen ook mee, vanaf hun volgende bericht: elke Claude-sessie draait in `~/.claude`, dat altijd de login van het actieve account bevat. Een Claude-sessie die door een oudere Omarchy in de eigen map van een account is gestart, houdt die login vast tot hij stopt, dus de wissel benoemt die sessies en voltooit vanzelf zodra ze weg zijn. Draaiende Codex- en Grok-sessies blijven op het account waarmee ze zijn gestart. Gespreksgeschiedenis, instellingen, skills en plugins worden gedeeld tussen accounts, dus `claude --continue` in dezelfde map pikt op waar je was gebleven op het nieuwe account.

Met meer dan één account toont het paneel de limieten van elk account naast elkaar, met het actieve account gemarkeerd. Omarchy meldt het wanneer het actieve account 95% van een limiet passeert, en klikken op de melding wisselt naar het account met de meeste speelruimte. Het wisselt nooit vanzelf. Wijzig de drempel met `omarchy agent account threshold 90`. Als elk account boven de drempel zit, hoor je dat één keer, samen met welk account als eerste vrijkomt. Terwijl een actief account binnen 15 punten van zijn drempel zit (80% bij de standaard), worden zijn limieten elke drie minuten gecontroleerd in plaats van elke 15.

`omarchy agent account list` toont elk account en zijn laatste limieten, `omarchy agent account remove work` vergeet er een, en `omarchy agent account rename primary Hey` hernoemt er een (of klik op de naam van een account in het paneel). Deze commando's werken op de accounts van je standaardagent; om de andere provider te bereiken, noem je hem eerst, zoals in `omarchy agent account use codex side`. De login die je al had in `~/.claude` of `~/.codex` is het _Main_-account. Die van Codex blijft waar hij is; die van Claude wacht in een eigen map terwijl een ander account actief is. Een account dat langer dan ongeveer acht uur ongebruikt is gebleven, kan _Sign-in required_ tonen; klik erop om dat account direct in het paneel opnieuw in te loggen, of wissel ernaar en start een sessie, wat de login vanzelf ververst. MCP-servers die je toevoegt met `claude mcp add` bereiken elk Claude-account, omdat ze allemaal in `~/.claude` draaien; voor Codex en Grok komen servers die je had toen een account werd toegevoegd mee naar dat account, maar latere alleen naar het account waarin je ze hebt toegevoegd. Claude Desktop houdt een eigen login bij, en Codex- of Grok-tools die zijn geconfigureerd met een absoluut pad naar een CLI-binary volgen de wissel niet. Een expliciete `CLAUDE_CONFIG_DIR`, `CODEX_HOME` of `GROK_HOME` heeft voorrang op het geselecteerde account.

### Crashdiagnose

Omarchy bewaakt systemd-coredump op procescrashes. Zodra je een standaardagent hebt gekozen, brengt elk van jouw programma's dat core dumpt een melding "Process crashed" — klik erop, en de crash wordt overhandigd aan je standaardagent samen met Omarchy's omarchy-diagnose-crash skill, die de agent door het vaststellen van de feiten uit de core dump leidt en beslist of de crash het waard is om upstream te melden. Je kunt hem ook handmatig uitvoeren tegen elke PID uit `coredumpctl list` met `omarchy agent crash <pid>`.

Het bewaken staat standaard aan. Zet het uit onder _Trigger > Toggle > Crash Capture Off_ (of met `omarchy toggle crash-capture`) en de meldingen stoppen; `omarchy agent crash <pid>` werkt nog steeds handmatig.

Crashes kunnen ook per programma worden gedempt, wat de diagnose je aan het einde aanbiedt. `omarchy crash mute hyprland` stopt de meldingen voor alleen dat programma, `omarchy crash mute hyprland off` brengt ze terug, en `omarchy crash mute` op zichzelf somt op wat je hebt gedempt. Het accepteert het pad van de binary net zo graag als zijn naam, dus `omarchy crash mute /usr/bin/hyprland` doet hetzelfde. Zet een naam met een spatie erin tussen aanhalingstekens, zoals in `omarchy crash mute 'Some App'`. Alles anders blijft melden, en het gedempte programma blijft crashen — dit verbergt de herinnering, het lost niets op.

### Desktop-apps

Het menu _Install > AI_ bevat ook een paar grafische AI-apps: Amp Desktop, Antigravity Desktop, de ChatGPT desktop app, de Claude desktop app (Anthropic's Linux-bèta, met Chat-, Cowork- en Claude Code-tabbladen), Grok Bot om te chatten met xAI's modellen, Herdr Desktop, Hermes Desktop, OpenClaw, de Perplexity desktop app en T3 Code. Grok Bot is de desktop-chatapp. De coding agent is het `grok`-commando.

Hermes Desktop is degene die je moet kennen, omdat een machine één Hermes heeft, en die is van de app: Hermes wordt alleen ooit via de app geïnstalleerd, en het `hermes`-commando dat de standaardagent uitvoert, is dat van de app. Hermes kiezen als standaardagent installeert hetzelfde als de vermelding _Install > AI_: het pakket, en een Hermes-runtime onder `~/.hermes` opgezet door Hermes' eigen installer, wat de eerste keer een paar minuten duurt. Die runtime is de ene Hermes die het terminalcommando `hermes`, de standaardagent en de app allemaal gebruiken, en hij werkt zichzelf bij met `hermes update` in plaats van te wachten op een Omarchy-release. Installeren ervan geeft Hermes ook het Omarchy-thema als een skin genaamd `omarchy`, die elk Hermes-oppervlak volgt terwijl je van thema wisselt; kies een andere onder Hermes' Appearance-instellingen of met `/skin` als je liever niet hebt dat hij dat doet, en Omarchy laat die keuze met rust. De app verwijderen onder _Remove > AI_ sluit Hermes eerst, gateway inbegrepen, neemt die runtime met zich mee, en bewaart je chats, herinneringen en de skills die Hermes voor zichzelf heeft geschreven, tenzij je anders aangeeft: hij vraagt, standaard nee, of die gegevens en je verbindingsinstellingen ook weg moeten.

OpenClaw's desktopervaring is zijn Control UI, die opent als een webapp ondersteund door zijn eigen lokale gateway. OpenClaw leeft in `~/.openclaw` en werkt zichzelf bij: gebruik de knop "Update Gateway" in de Control UI of voer `openclaw update` uit, en de gateway herstart op de nieuwe versie. Omarchy kiest alleen de release waarmee een verse installatie begint. OpenClaw kan ook je standaardagent zijn: hem kiezen onder _Agent > Harness_ zet diezelfde kopie op in `~/.openclaw`, en de agent opent OpenClaw's terminal UI gekoppeld aan zijn gateway. OpenClaw verwijderen onder _Remove > AI_ neemt de gateway-service en de app met zich mee en vraagt daarna of `~/.openclaw` ook weg moet, omdat dat je chats en inloggegevens bevat naast OpenClaw zelf en de plugin-runtimes die hij downloadt; standaard blijft het behouden, en OpenClaw opnieuw installeren pikt het weer op.

Herdr Desktop is de [Herdr](https://herdr.dev) desktop app: ruimtes, tabbladen en panelen van terminals en coding agents die in zijn kern blijven draaien wanneer je het venster sluit. Hij komt van Herdr's eigen installer in plaats van een pakket, dus hij leeft in `~/.local/share/herdr-app`, brengt zijn kern mee in `~/.local/bin/herdr-core` wanneer je er nog geen hebt, en werkt beide zichzelf bij. Hij zit naast het `herdr`-commando dat Omarchy levert op `Super + Ctrl + Return` in plaats van het te vervangen, en krijgt de directe toetsen van dat commando: `Alt + Return` en `Alt + Shift + Return` splitsen een paneel omlaag of naar rechts, `Alt + Escape` sluit het, `Ctrl + Alt + Arrow` beweegt tussen panelen, `Alt + 1..9` en `Alt + Left/Right` kiezen een tabblad, en `Alt + Up/Down` bewegen tussen ruimtes. `Ctrl + 1..9` kiest een ruimte en `Alt + Shift + Up/Down` stapt door agents. De prefix-toetsen met `Ctrl + Space` blijven alleen voor de terminal, omdat de app geen gewone Ctrl-toets kan vasthouden voor een reeks. Omarchy schrijft deze naar `~/.config/herdr-app/keys.json`, en `omarchy-refresh-herdr-app` zet ze terug. Installeren kiest Herdr's Omarchy-thema, dat vanaf dan je Omarchy-thema volgt. Herdr houdt één thema voor de lichte modus en één voor de donkere, dus na het wisselen tussen een donker en een licht Omarchy-thema kies je Omarchy nog een keer in Herdr's themakiezer voor de andere modus.

T3 Code draait vanaf zijn officiële AppImage-release in `~/.local/share/t3code` in plaats van vanaf een pakket, dus hij werkt zichzelf bij. Installeren vraagt of je op het Stable- of Nightly-kanaal wilt starten; wissel later in de instellingen van T3 Code. Je threads en instellingen leven in `~/.t3`, en T3 Code verwijderen onder _Remove > AI_ neemt ze met zich mee.

### Lokale modellen

Draai een open model op je eigen machine voor je coding agents. Je prompts en code blijven op de machine; niets dat naar het model wordt gestuurd, verlaat hem. Begin met:

```bash
omarchy models use best text
```

Dat zet het beste tekstmodel voor deze machine op, het soort dat je agents gebruiken. Afbeeldings-, video- en muziekmodellen hebben hun eigen beste: `omarchy models use best image`, `video` of `music`. Voer `omarchy models use best` uit om de keuze van elk soort voor deze machine te zien.

Of open het paneel voor lokale modellen via zijn sparkles-icoon in de bovenbalk, naast het agents-icoon, of met Super + Ctrl + Alt + X, en kies +. Het icoon verschijnt wanneer een model op deze machine past. Podman, dat de modellen draait, wordt met Omarchy meegeleverd, net als NVIDIA's container toolkit op een NVIDIA-machine, die hen de GPU geeft; als een van beide ontbreekt, installeert de eerste setup hem. Omarchy kiest dan het aanbevolen model voor deze machine, downloadt het en start het. Verwacht een download van tientallen GB en dat het grootste deel van het geheugen van de machine in gebruik is terwijl het model draait: Flash Next gebruikt ongeveer 100 GiB met zijn volledige 256K-context. Als andere modellen het geheugen bezet houden dat hij nodig heeft, wordt hij gestopt opgezet, klaar om te starten zodra je er een stopt. Het model stopt bij uitloggen; stop het zelf wanneer je het geheugen voor iets anders nodig hebt.

`omarchy models list` toont de opties en legt uit waarom sommige niet passen. Om een andere op te zetten, voer je `omarchy models use <recipe>` uit. Vandaag zijn `qwen3.8-flash-next-gufo` en `qwen3.8-27b-gufo` beschikbaar voor 128 GB Strix Halo-machines; de 27B neemt ongeveer 40 GiB, dus hij laat ruimte voor ander werk. Op een 64 GB laptop met Intel's Arc B390 draait `qwen3.6-35b-a3b-llamacpp` in ongeveer 30 GiB. Nieuwe recipes en aanbevelingen komen mee met `omarchy update`, via het pakket.

Elk model dat je opzet, krijgt zijn eigen regel in het paneel voor lokale modellen: play om het te starten, pause om het te stoppen en zijn geheugen vrij te maken, en de terminalknop om je agent erop te openen. Bovenaan toont een balk hoe het geheugen van de machine is verdeeld tussen Omarchy zelf (het systeem en je apps), elk draaiend model en wat vrij is. Wijs naar een gestopt model en de balk toont of het past, of hoeveel het tekortkomt. Meerdere kunnen tegelijk draaien wanneer ze samen in het geheugen passen; als er een niet past, zegt Omarchy welk draaiend model je moet stoppen. Sleep regels aan hun logo om ze te herordenen, en druk op Delete op een geselecteerde regel om een model en zijn download te verwijderen.

Elk codingmodel dat je opzet, krijgt ook zijn eigen vermelding in de app launcher, onder de naam van het model en met het logo van zijn maker, zoals inloggen bij Claude, Codex of Grok er een toevoegt. Het opent je agent op dat model, en start het model eerst als het nog niet draait: de terminal toont dat het laadt en draagt over aan de agent zodra het draait. Een model verwijderen verwijdert zijn vermelding.

Niet elk model is voor coding. Afbeeldings-, video- en muziekmodellen openen in plaats daarvan in Fantasi, Omarchy's app voor het maken van afbeeldingen, video en muziek met een model dat op deze machine draait, daar gekozen of vanuit hun regel in het paneel voor lokale modellen.

Een model blijft precies draaien zoals het is opgezet, dus een Omarchy-update herstart er nooit een onder je agents. Wanneer Omarchy een nieuwere runtime of nieuwere weights heeft voor een model dat je hebt opgezet, toont zijn regel een updateknop: druk erop en het model wordt op de achtergrond opnieuw opgezet, waarbij alleen wordt gedownload wat is veranderd, en herstart op de nieuwe versie. Een model dat gestopt was, blijft gestopt. `omarchy models update` doet hetzelfde voor elk model vanuit een terminal.

Vanaf de commandoregel doen `omarchy models start <recipe>` en `omarchy models stop <recipe>` hetzelfde, `omarchy models status` toont elk model, en `omarchy agent --local` opent het laatste model dat je hebt gestart in pi, wat je standaardagent ook is. OpenCode en Qwen Code kunnen ook een lokaal model gebruiken: `omarchy models harness opencode` of `omarchy models harness qwen` opent ze daar in plaats daarvan, en `omarchy models harness pi` gaat terug. pi somt ook elk model op dat je hebt opgezet, en die op machines waarmee je bent gekoppeld, in zijn eigen modelkiezer, dus gewone `pi` bereikt ze ook. Elke OpenAI-compatibele client kan ook verbinden: `status` toont het adres van elk model (het eerste is `http://127.0.0.1:11435/v1`), de recipenaam is het model, en de sleutel staat in `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` verwijdert een model en de downloads die geen ander model gebruikt.

Runtimes van derden worden gelabeld met hun uitgever. Omarchy draait elk model zonder netwerktoegang.

### Lokale LLM's

Omarchy raadt twee manieren aan om lokale LLM-modellen te draaien: LM Studio en Ollama. LM Studio biedt een GUI-interface voor het vinden van open-weight modellen, ze te installeren en ze te draaien. Het is een geweldige manier om gemakkelijk op gang te komen. Ollama biedt een CLI om dat op een vergelijkbare manier te doen. Maar als je nieuw bent met lokale modellen, zou ik beginnen met LM Studio. Je kunt beide installeren onder _Install > AI_ in het Omarchy Menu.

### De Omarchy skills

Agent skills helpen AI om specifieke tools op een specifieke manier te gebruiken, en Omarchy levert er zeven van. De omarchy skill behandelt het op maat aanpassen van het systeem, zoals je Hyprland-config tweaken of de balk aanpassen. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app en omarchy-make-game behandelen het maken van iets nieuws, omarchy-contribute behandelt het melden van een bug of het upstream sturen van een fix, en omarchy-diagnose-crash werkt de core dump van een crash door. Ze zijn gesymlinkt naar de skill-mappen voor Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` en elke `~/.hermes/profiles/*/skills`), en de generieke locatie `~/.agents/skills`, dus de meeste harnesses pikken ze automatisch op. Een eigen skill-map met dezelfde naam heeft voorrang.

Maar je moet deze skills als experimenteel beschouwen. Verschillende modellen zullen het met verschillend effect gebruiken. Het is het beste om eerst in planmodus te draaien, zodat je een idee hebt van wat de agent zou willen veranderen. En wees dan klaar om wijzigingen terug te draaien of zelfs `omarchy reinstall configs` aan te roepen, als de agent er een puinhoop van maakt.
