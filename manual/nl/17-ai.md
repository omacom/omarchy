# AI

Omarchy bevat launchers voor de onderstaande coding agents zonder een standaardkeuze voor je te maken. Voer een commando uit om de CLI ervan bij het eerste gebruik te installeren en verifieer je vervolgens wanneer daarom wordt gevraagd. Hermes en OpenClaw zijn de uitzonderingen: voor hen wordt niets via mise geïnstalleerd, en als je een van beide kiest, wordt de eigen, zichzelf bijwerkende kopie ervan ingesteld, zoals _Desktop-apps_ hieronder uitlegt.

### Agents installeren en bijwerken

Met uitzondering van Hermes en OpenClaw gebruiken deze agents de lazy installation van mise: de eerste start installeert de CLI, en latere starts hergebruiken die. mise controleert ook hoogstens eens per vier uur of er een nieuwe release is voor een geïnstalleerde agent, net voordat die start of op de achtergrond bij een shellprompt. Als die update mislukt of je offline bent, draait de geïnstalleerde versie. `omarchy update` werkt geïnstalleerde agents bij samen met de rest van Omarchy, en `mup` werkt alleen door mise beheerde tools bij.

De eigen updater van een agent, zoals `claude update`, `codex update` of een updateknop in een app, werkt de door mise beheerde installatie niet bij. `codex update` mislukt, en `claude update` kan succes melden terwijl het een aparte kopie installeert die mise niet volgt. Als je liever de native installer en updater van een agent gebruikt, voeg die dan toe aan `disable_tools`; zie [Vooraf geïnstalleerde CLI-tools](18-development-tools.md#preinstalled-cli-tools).

Om alle geconfigureerde lazy tools te installeren voordat je ze nodig hebt, voer je `mise install --include-lazy` uit. Dit omvat ook Omarchy's andere standaard-CLI-tools, naast de agents. Zie [Vooraf geïnstalleerde CLI-tools](18-development-tools.md#preinstalled-cli-tools) voor het installeren van één tool of het gebruiken van je eigen installatie.

`grok` wordt geïnstalleerd via mise's first-party `grok`-pakket, op dezelfde manier als `claude` en `codex`. Voer `grok` uit, of geef het een ster in het agents-paneel. Sla de `curl | bash`-installer op x.ai over. Dat pad zet een tweede kopie in `~/.grok/bin`, zet die vooraan op `PATH` en overschrijft Omarchy's wrapper.

`dsh` opent zijn browser-UI op `127.0.0.1:3080`, met de startmap als standaardwerkruimte. Zijn browser-UI accepteert geen startprompt, dus `omarchy agent prompt` opent hem met de prompt op je klembord om te plakken. Omarchy start hem met DeepSeek's no-approval-permissiepreset. DeepSeek Harness uploadt sessielogs naar DeepSeek wanneer je zijn officiële model-API gebruikt; zet dat uit onder _Settings > General > Upload Session Log_ in zijn browser-UI. Feedback die je hem stuurt, wordt ook met de sessie geüpload, tenzij je hem start met `DSH_TELEMETRY_MODE=DISABLED`.

### De standaardagent

Kies je standaardagent met de ster naast een agent in het agents-paneel, die bij de standaardagent gevuld is, of met `omarchy default agent <name>`, dat ook elke harness accepteert die daar geen regel heeft. Als de agent nog niet is geïnstalleerd, installeert kiezen hem eerst, en hij krijgt ook een eigen launcher in de app launcher, naast Agent. Een verse Omarchy nodigt je uit er een in te stellen met een eenmalige melding, die het agents-paneel opent.

Als je Claude kiest, wordt ook geprobeerd zijn browserextensie in te stellen voor Chromium, Chrome, Brave, Brave Origin en Edge. De extensie-instelling geldt voor alle gebruikers en kan om je systeemwachtwoord vragen; annuleren of een mislukte extensie-installatie selecteert en start Claude nog steeds. Herstart je browser, schakel de extensie in als daarom wordt gevraagd en log in bij Claude om de verbinding af te ronden. Voer `/chrome` uit in Claude om de verbinding te controleren. Firefox en Zen ondersteunen deze extensie niet. Als Claude al je standaardagent was voordat deze instelling werd toegevoegd, selecteer hem dan opnieuw om de extensie te installeren.

Zodra je hebt gekozen, start `Super + Shift + Ctrl + A` de standaardagent in een apart terminalvenster (of opent de kiezer als je nog niet hebt gekozen). Je kunt hem ook rechtstreeks met een taak starten met `omarchy agent prompt "Review this project"`. Freebuff en DeepSeek Harness accepteren geen startprompt, dus zij openen in plaats daarvan met de prompt op je klembord om te plakken. Agents die op deze manier worden gestart, draaien zonder toezicht in hun respectieve don't-stop-to-ask-modi, dus wees erop voorbereid dat ze daadwerkelijk dingen doen! MiniMax Code heeft geen dergelijke modus voor zijn interactieve sessies, dus hij vraagt zoals gewoonlijk om toestemming. En omdat agents weigeren vertrouwen te onthouden voor je thuismap, starten starts vanuit `$HOME` in plaats daarvan in `~/Work`.

Er zijn ook terminalshortcuts: `a` draait de standaardagent inline in de huidige terminal, terwijl `c`, `cx` en `cy` OpenCode, Claude Code en Codex rechtstreeks starten (wederom in hun auto-goedkeurende modi). Themawisselingen synchroniseren ook naar de agents: Claude Code, Pi, OpenCode en Hermes (zodra Omarchy hem heeft geïnstalleerd) volgen allemaal mee wanneer je het Omarchy-thema wisselt.

### Je agentinstructies

Persoonlijke regels voor elke agent gaan in `~/.agents/AGENTS.md`, naast de gedeelde skills in `~/.agents/skills`. Open het met het documentpictogram naast de + in het agents-paneel, of met `omarchy agent instructions --edit`, waarmee het ook wordt gekoppeld aan elke harness die zijn eigen globale bestand bijhoudt: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, Copilot's `~/.copilot/copilot-instructions.md`, enzovoort. Crush en Amp lezen de koppeling `~/.config/AGENTS.md`, terwijl omp, Kimi en DeepSeek Harness `~/.agents/AGENTS.md` rechtstreeks lezen. Een standaardagent kiezen koppelt het ook. Een instructiebestand dat je al had, wordt het gedeelde bestand als er nog geen was; anders wordt het naast de koppeling bewaard als `.bak`. Voer `omarchy agent instructions` uit om opnieuw te koppelen nadat je een andere agent hebt geïnstalleerd.

### Het agents-paneel

De bovenste balk heeft een agents-pictogram. Voordat je een agent hebt ingesteld, biedt het paneel ervan drie manieren om te beginnen: log in op een Claude-, Codex-, Grok-, Gemini-, Muse-, Cursor- of Copilot-abonnement, of onder More een OpenCode Go-, MiniMax-, Synthetic- of Z.ai-codingplan; betaal naar gebruik met Fireworks, OpenCode Zen en Go, OpenRouter, of onder More DeepSeek of een andere provider waarop OpenCode inlogt, allemaal draaiend in OpenCode; of draai het beste model voor je computer, wanneer er een bij past. De eerste die je voltooit, wordt je standaardagent, en de + in het paneel biedt later dezelfde drie aan. Daarna zet het paneel elk abonnement op één pagina: elke agent en elk account met zijn plan, een meter voor elk van zijn 5-uurs sessie- en weeklimieten met de tijd tot hij reset (beweeg erover voor het exacte percentage), of het resterende prepaid saldo, onder een regel die rouleert door wat je bij elkaar hebt gebruikt, zoals tokens deze week en je meest gebruikte model. Onder _Make something cool_ biedt het starterprompts voor een nieuw thema, plugin, app of game die de taak aan je standaardagent geven. Apps worden gebouwd zoals Omarchy's eigen Hype, Monologue en Omacut, in C++ en Qt Quick, volgens de omarchy-make-app agent skill, en de compiler en Qt-onderdelen die ze nodig hebben, worden meegeleverd. Games zijn een enkele three.js-pagina in `~/Games/vibes`, volgens de omarchy-make-game agent skill, en openen allemaal vanuit één Game Vibes-launcher in het huidige thema; ze laden three.js van het web, dus ze hebben een verbinding nodig om te starten. Claude Code, Codex, Grok, Kimi, Cursor en zijn Grok Bot-tegoed, GitHub Copilot, Muse, Gemini (via Antigravity) en Devin worden out of the box gedekt met hun limieten, Kimchi met zijn plan, prepaid credits en uitgavenbudgetten, en Hermes, Mistral Vibe en Qwen Code tonen hun sessies en tokens zodra je ze hebt gebruikt. Providerplannen en sleutels die je via pi, omp of opencode gebruikt, verschijnen ook: OpenCode Zen en Go, het Z.ai GLM Coding Plan, Ollama Cloud, het MiniMax Token Plan en Synthetic met hun limieten; OpenRouter en DeepSeek met hun prepaid saldo's; Fireworks met zijn uitgaven over de afgelopen 30 dagen. Tokens van modellen die je op je eigen hardware draait, tellen ook mee voor de totalen; de modellen zelf hebben een eigen paneel, beschreven onder [Lokale modellen](#local-models). Elke agent wordt één keer geteld, onder wie hem factureert, ongeacht via hoeveel harnesses je hem aanstuurt.

Klik met links op het balkpictogram of druk op `Super + Ctrl + X` voor het paneel, klik met rechts om je standaardagent te starten en klik met de middelste knop om te vernieuwen. De gebruiksgegevens erachter worden elke 15 minuten opnieuw gegenereerd door `omarchy agent usage update`, en het paneel kan zelfs gebruik van je andere machines samenvoegen via een gesynchroniseerde map. Zie de README onder `$OMARCHY_PATH/shell/plugins/agents/` voor de volledige instellingen.

### Meerdere abonnementen

Als je voor meer dan één Claude-, Codex- of Grok-plan betaalt — bijvoorbeeld een persoonlijke Max en een voor werk — kan Omarchy ze allemaal ingelogd houden en ertussen wisselen. Voeg een abonnement toe met de + in het agents-paneel, die je daar meteen doorheen leidt, of met `omarchy agent account add claude Work` (of `codex`, of `grok`). Dezelfde + en hetzelfde commando loggen in op Gemini (`gemini`) en OpenCode (`opencode`), en slaan een Fireworks- (`fireworks`) of OpenRouter- (`openrouter`) API-sleutel op in OpenCode; het commando logt ook in op Copilot (`copilot`), Cursor (`cursor`) en Muse (`muse`). Die houden elk één enkele login bij. Het installeert de CLI als die ontbreekt. Het eerste account voor een provider logt in via je normale browser, precies waar de CLI altijd kijkt. Elk daarna logt in via een privévenster, zodat het account waarop je browser al is ingelogd niet per ongeluk wordt opgepikt; log daar in als het account dat je toevoegt, en sluit eerst elk privévenster dat je al open had. Log hiervoor nooit uit bij de CLI: uitloggen trekt de opgeslagen login in, en dat account zou opnieuw moeten worden toegevoegd.

Om je abonnementslogins via SSH naar een andere Omarchy-machine te kopiëren, voer je `omarchy agent account copy user@laptop` uit. De verzender levert een tijdelijke ontvanger wanneer de bestemming er geen geïnstalleerd heeft, zodat oudere Omarchy-machines accounts kunnen ontvangen zonder een update. Geïnstalleerde ontvangers hebben voorrang. Dit kopieert alle Claude-, Codex- en Grok-abonnementen; voeg providernamen toe om ze te selecteren, zoals in `omarchy agent account copy laptop claude`. Accountnamen en commando-ID's komen overeen met de bron, inclusief accounts die al op de bestemming aanwezig zijn. Niet-gerelateerde bestemmingsaccounts krijgen een numeriek achtervoegsel als hun namen conflicteren, en instellingen, skills, plugins en gespreksgeschiedenis blijven lokaal op elke machine.

Bestaande inloggegevens op de bestemming blijven behouden. Van een bronaccount dat daar al is ingelogd, wordt de naam gesynchroniseerd zonder zijn inloggegevens te vervangen; andere accounts worden ernaast toegevoegd. Om opgeslagen inloggegevens voor overeenkomende accounts te vervangen, gebruik je `omarchy agent account copy --replace laptop claude` nadat je de sessies van dat account op de bestemming hebt afgesloten. Een verse bestemming krijgt ook het actieve account en de wisselvoorkeuren van de bron; een gevestigde bestemming behoudt de zijne.

Inloggegevens reizen via SSH en worden opgeslagen in privébestanden op de bestemming, dus kopieer alleen naar machines die je vertrouwt. Dit is een eenmalige kopie, geen doorlopende synchronisatie. Codex-refresh-tokens kunnen door een andere machine worden geroteerd, waardoor een gekopieerde login vernieuwing nodig heeft; aparte logins blijven de betrouwbaarste keuze voor gelijktijdig gebruik op meerdere machines. Zie [Codex' richtlijnen voor accountauthenticatie](https://developers.openai.com/codex/auth/ci-cd-auth).

Eén account per provider is actief, en elke nieuwe sessie start als dat account: `cx`, `cy`, een gewone `claude`, `codex` of `grok`, alles wat via `omarchy agent` wordt gestart, en scripts of editors die de CLI op `PATH` vinden. Wissel met `omarchy agent account use work` (en terug met `omarchy agent account use main`), of in het paneel door op het nummer van een account en daarna op `Enter` te drukken (of op zijn ster te klikken). Draaiende Claude-sessies wisselen ook mee, vanaf hun volgende bericht: elke Claude-sessie draait in `~/.claude`, dat altijd de login van het actieve account bevat. Een Claude-sessie die door een oudere Omarchy in de eigen map van een account is gestart, behoudt die login tot hij stopt, dus de wissel benoemt die sessies en voltooit vanzelf zodra ze weg zijn. Draaiende Codex- en Grok-sessies blijven op het account waarmee ze zijn gestart. Gespreksgeschiedenis, instellingen, skills en plugins worden gedeeld tussen accounts, dus `claude --continue` in dezelfde map gaat verder waar je was gebleven op het nieuwe account.

Met meer dan één account toont het paneel de limieten van elk account naast elkaar, met een gevulde ster op het account dat in gebruik is. Omarchy meldt het je wanneer het actieve account 95% van een limiet passeert, en klikken op de melding wisselt naar het account met de meeste speelruimte. Het wisselt nooit vanzelf. Wijzig de drempel met `omarchy agent account threshold 90`. Als elk account boven de drempel zit, hoor je dat één keer, samen met welk account als eerste vrijkomt. Terwijl een actief account binnen 15 punten van zijn drempel zit (80% bij de standaard), worden zijn limieten elke drie minuten gecontroleerd in plaats van elke 15.

`omarchy agent account list` toont elk account en zijn nieuwste limieten, `omarchy agent account remove work` vergeet er een, en `omarchy agent account rename primary Hey` hernoemt er een (of klik op de naam van een account in het paneel). Deze commando's werken op de accounts van je standaardagent; om de andere provider te bereiken, noem je die eerst, zoals in `omarchy agent account use codex side`. De login die je al had in `~/.claude` of `~/.codex` is het _Main_-account. Die van Codex blijft waar hij is; die van Claude wacht in een eigen map terwijl een ander account actief is. Een account dat meer dan ongeveer acht uur ongebruikt is gebleven, kan _Sign-in required_ tonen; klik erop om dat account direct in het paneel opnieuw in te loggen, of wissel ernaartoe en start een sessie, wat de login vanzelf vernieuwt. MCP-servers die je toevoegt met `claude mcp add` bereiken elk Claude-account, aangezien ze allemaal in `~/.claude` draaien; voor Codex en Grok komen servers die je had toen een account werd toegevoegd met hem mee, maar latere bereiken alleen het account waarin je ze hebt toegevoegd. Claude Desktop houdt een eigen login bij, en Codex- of Grok-tools die zijn geconfigureerd met een absoluut pad naar een CLI-binary volgen de wissel niet. Een expliciete `CLAUDE_CONFIG_DIR`, `CODEX_HOME` of `GROK_HOME` heeft voorrang op het geselecteerde account.

### Crashdiagnose

Omarchy houdt systemd-coredump in de gaten voor procescrashes. Zodra je een standaardagent hebt gekozen, brengt elk programma van jou dat core dumpt een "Process crashed"-melding — klik erop, en de crash wordt overgedragen aan je standaardagent samen met Omarchy's omarchy-diagnose-crash skill, die de agent door het vaststellen van de feiten uit de core dump leidt en het beslissen of de crash het waard is om upstream te melden. Je kunt het ook handmatig uitvoeren tegen elke PID uit `coredumpctl list` met `omarchy agent crash <pid>`.

Het in de gaten houden staat standaard aan. Zet het uit onder _Trigger > Toggle > Crash Capture Off_ (of met `omarchy toggle crash-capture`) en de meldingen stoppen; `omarchy agent crash <pid>` werkt nog steeds handmatig.

Crashes kunnen ook per programma worden gedempt, wat de diagnose je aan het einde aanbiedt. `omarchy crash mute hyprland` stopt de meldingen alleen voor dat programma, `omarchy crash mute hyprland off` brengt ze terug, en `omarchy crash mute` op zichzelf somt op wat je hebt gedempt. Het accepteert het pad van de binary net zo graag als zijn naam, dus `omarchy crash mute /usr/bin/hyprland` doet hetzelfde. Zet een naam met een spatie erin tussen aanhalingstekens, zoals in `omarchy crash mute 'Some App'`. Al het andere geeft nog steeds meldingen, en het gedempte programma crasht nog steeds — dit verbergt de herinnering, het repareert niets.

### Desktop-apps

Het menu _Install > AI_ bevat ook een paar grafische AI-apps: Amp Desktop, Antigravity Desktop, de ChatGPT-desktopapp, de Claude-desktopapp (Anthropic's Linux-bèta, met Chat-, Cowork- en Claude Code-tabbladen), Grok Bot om met xAI's modellen te chatten, Herdr Desktop, Hermes Desktop, OpenClaw, de Perplexity-desktopapp en T3 Code. Grok Bot is de desktop-chatapp. De coding agent is het `grok`-commando.

Hermes Desktop is degene die je moet kennen, want een machine heeft één Hermes, en die is van de app: Hermes wordt alleen ooit via de app geïnstalleerd, en het `hermes`-commando dat de standaardagent draait, is van de app. Hermes als standaardagent kiezen installeert hetzelfde als de _Install > AI_-vermelding doet: het pakket, en een Hermes-runtime onder `~/.hermes` ingesteld door Hermes' eigen installer, wat de eerste keer een paar minuten duurt. Die runtime is de ene Hermes die het terminal-`hermes`-commando, de standaardagent en de app allemaal gebruiken, en hij werkt zichzelf bij met `hermes update` in plaats van te wachten op een Omarchy-release. Installeren geeft Hermes ook het Omarchy-thema als een skin met de naam `omarchy`, die elk Hermes-oppervlak volgt terwijl je van thema wisselt; kies een andere onder Hermes' Appearance-instellingen of met `/skin` als je liever hebt dat hij dat niet doet, en Omarchy laat die keuze met rust. De app verwijderen onder _Remove > AI_ sluit Hermes eerst, gateway inbegrepen, neemt die runtime mee, en behoudt je chats, herinneringen en de skills die Hermes voor zichzelf heeft geschreven, tenzij je anders aangeeft: het vraagt, standaard nee, of die gegevens en je verbindingsinstellingen ook weg moeten.

OpenClaw's desktopervaring is zijn Control UI, die opent als een webapp ondersteund door zijn eigen lokale gateway. OpenClaw leeft in `~/.openclaw` en werkt zichzelf bij: gebruik de "Update Gateway"-knop van de Control UI of voer `openclaw update` uit, en de gateway herstart op de nieuwe versie. Omarchy kiest alleen de release waarmee een verse installatie begint. OpenClaw kan ook je standaardagent zijn: hem kiezen met `omarchy default agent openclaw` stelt dezelfde kopie in in `~/.openclaw`, en de agent opent OpenClaw's terminal UI gekoppeld aan zijn gateway. OpenClaw verwijderen onder _Remove > AI_ neemt de gatewayservice en de app mee en vraagt daarna of `~/.openclaw` ook weg moet, aangezien dat je chats en inloggegevens bevat naast OpenClaw zelf en de plugin-runtimes die hij downloadt; standaard blijft het behouden, en OpenClaw opnieuw installeren pikt het weer op.

Herdr Desktop is de [Herdr](https://herdr.dev) desktopapp: spaces, tabbladen en panes van terminals en coding agents die blijven draaien in zijn core wanneer je het venster sluit. Hij komt van Herdr's eigen installer in plaats van een pakket, dus hij leeft in `~/.local/share/herdr-app`, brengt zijn core mee in `~/.local/bin/herdr-core` wanneer je er nog geen hebt, en werkt beide zichzelf bij. Hij zit naast het `herdr`-commando dat Omarchy levert op `Super + Ctrl + Return` in plaats van het te vervangen, en krijgt de directe toetsen van dat commando: `Alt + Return` en `Alt + Shift + Return` splitsen een pane naar beneden of naar rechts, `Alt + Escape` sluit hem, `Ctrl + Alt + Arrow` beweegt tussen panes, `Alt + 1..9` en `Alt + Left/Right` kiezen een tabblad, en `Alt + Up/Down` bewegen tussen spaces. `Ctrl + 1..9` kiest een space en `Alt + Shift + Up/Down` stapt door agents. De `Ctrl + Space`-prefix-toetsen blijven alleen voor de terminal, aangezien de app geen gewone Ctrl-toets kan vasthouden voor een reeks. Omarchy schrijft deze naar `~/.config/herdr-app/keys.json`, en `omarchy-refresh-herdr-app` zet ze terug. Installeren kiest Herdr's Omarchy-thema, dat vanaf dan je Omarchy-thema volgt. Herdr houdt één thema bij voor de lichte modus en één voor donker, dus kies na het wisselen tussen een donker en een licht Omarchy-thema nog een keer Omarchy in Herdr's themakiezer voor de andere modus.

T3 Code draait vanaf zijn officiële AppImage-release in `~/.local/share/t3code` in plaats van vanaf een pakket, dus hij werkt zichzelf bij. Installeren vraagt of je op het Stable- of Nightly-kanaal wilt beginnen; wissel later in T3 Code's instellingen. Je threads en instellingen leven in `~/.t3`, en T3 Code verwijderen onder _Remove > AI_ neemt ze mee.

### Lokale modellen

Draai een open model op je eigen machine voor je coding agents. Je prompts en code blijven op de machine; niets dat naar het model wordt gestuurd, verlaat haar. Begin met:

```bash
omarchy models use best text
```

Dat stelt het beste tekstmodel voor deze machine in, het soort dat je agents gebruiken. Image-, video- en muziekmodellen hebben hun eigen beste: `omarchy models use best image`, `video` of `music`. Voer `omarchy models use best` uit om de keuze van elk soort voor deze machine te zien.

Of open het paneel voor lokale modellen vanaf zijn sparkles-pictogram in de bovenste balk, naast het agents-pictogram, of met Super + Ctrl + Alt + X, en kies +. Het pictogram verschijnt wanneer een model bij deze machine past. Podman, die de modellen draait, wordt met Omarchy meegeleverd, net als NVIDIA's container toolkit op een NVIDIA-machine, die ze de GPU geeft; als een van beide ontbreekt, installeert de eerste setup hem. Omarchy kiest dan het aanbevolen model voor deze machine, downloadt het en start het. Verwacht een download van tientallen GB en dat het meeste geheugen van de machine in gebruik is terwijl het model draait: Flash Next gebruikt ongeveer 100 GiB met zijn volledige 256K-context. Als andere modellen het geheugen bezet houden dat hij nodig heeft, wordt hij gestopt ingesteld, klaar om te starten zodra je er een stopt. Het model stopt bij uitloggen; stop hem zelf wanneer je het geheugen voor iets anders nodig hebt.

`omarchy models list` toont de opties en legt uit waarom sommige niet passen. Om een andere in te stellen, voer je `omarchy models use <recipe>` uit. Vandaag zijn `qwen3.8-flash-next-gufo` en `qwen3.8-27b-gufo` beschikbaar voor 128 GB Strix Halo-machines; de 27B neemt ongeveer 40 GiB, dus hij laat ruimte voor ander werk. Op een 64 GB-laptop met Intel's Arc B390 draait `qwen3.6-35b-a3b-llamacpp` in ongeveer 30 GiB. Nieuwe recipes en aanbevelingen arriveren met `omarchy update`, via het pakket.

Elk model dat je instelt, krijgt zijn eigen regel in het paneel voor lokale modellen: play om hem te starten, pause om hem te stoppen en zijn geheugen vrij te maken, en de terminalknop om je agent erop te openen. Bovenaan toont een balk hoe het geheugen van de machine is verdeeld tussen Omarchy zelf (het systeem en je apps), elk draaiend model, en wat vrij is. Wijs naar een gestopt model en de balk toont of hij past, of hoeveel hij tekortkomt. Meerdere kunnen tegelijk draaien wanneer ze samen in het geheugen passen; als er een niet past, zegt Omarchy welk draaiend model je moet stoppen. Sleep regels aan hun logo om ze te herordenen, en druk op Delete op een geselecteerde regel om een model en zijn download te verwijderen.

Elk coding model dat je instelt, krijgt ook zijn eigen vermelding in de app launcher, onder de naam van het model en met het logo van zijn maker, zoals inloggen op Claude, Codex of Grok er een toevoegt. Het opent je agent op dat model, en start het model eerst als het niet draait: de terminal toont dat het laadt en draagt over aan de agent zodra het draait. Een model verwijderen verwijdert zijn vermelding.

Niet elk model is om te coderen. Image-, video- en muziekmodellen openen in plaats daarvan in Fantasi, Omarchy's app om afbeeldingen, video en muziek te maken met een model dat op deze machine draait, daar gekozen of vanaf hun regel in het paneel voor lokale modellen.

Een model blijft precies draaien zoals het was ingesteld, dus een Omarchy-update herstart er nooit een onder je agents. Wanneer Omarchy een nieuwere runtime of nieuwere weights heeft voor een model dat je hebt ingesteld, toont zijn regel een updateknop: druk erop en het model wordt opnieuw ingesteld op de achtergrond, waarbij alleen wordt gedownload wat er is veranderd, en herstart op de nieuwe versie. Een model dat gestopt was, blijft gestopt. `omarchy models update` doet hetzelfde voor elk model vanaf een terminal.

Vanaf de command line doen `omarchy models start <recipe>` en `omarchy models stop <recipe>` hetzelfde, `omarchy models status` toont elk model, en `omarchy agent --local-model <recipe>` opent dat model in pi, wat je standaardagent ook is. Om van je lokale model te maken wat de agent-hotkey, de Quake-console en _Make something_ openen, voer je `omarchy default agent local` uit of geef je een draaiend model een ster in het agents-paneel. pi vermeldt ook elk model dat je hebt ingesteld, en die op machines waarmee je hebt gekoppeld, in zijn eigen modelkiezer, dus een gewone `pi` bereikt ze ook. Elke OpenAI-compatibele client kan ook verbinden: `status` toont het adres van elk model (het eerste is `http://127.0.0.1:11435/v1`), de recipe-naam is het model, en de sleutel staat in `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` verwijdert een model en de downloads die geen ander model gebruikt.

Runtimes van derden zijn gelabeld met hun uitgever. Omarchy draait elk model zonder netwerktoegang.

### Lokale LLM's

Omarchy raadt twee manieren aan om lokale LLM-modellen te draaien: LM Studio en Ollama. LM Studio biedt een GUI-interface om open-weight modellen te vinden, ze te installeren en ze te draaien. Het is een geweldige manier om gemakkelijk aan de slag te gaan. Ollama biedt een CLI om dat op vergelijkbare wijze te doen. Maar als je nieuw bent met lokale modellen, zou ik met LM Studio beginnen. Je kunt beide installeren onder _Install > AI_ in het Omarchy Menu.

### De Omarchy-skills

Agent skills helpen AI om specifieke tools op een specifieke manier te gebruiken, en Omarchy levert er zeven. De omarchy skill dekt het op maat maken van het systeem, zoals je Hyprland-config tweaken of de balk aanpassen. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app en omarchy-make-game dekken iets nieuws maken, omarchy-contribute dekt een bug melden of een fix upstream sturen, en omarchy-diagnose-crash werkt door de core dump van een crash heen. Ze zijn gesymlinkt in de skill-mappen voor Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` en elke `~/.hermes/profiles/*/skills`), en de generieke `~/.agents/skills`-locatie, dus de meeste harnesses pikken ze automatisch op. Een eigen skill-map met dezelfde naam heeft voorrang.

Maar je moet deze skills als experimenteel beschouwen. Verschillende modellen zullen het met verschillend effect gebruiken. Het is het beste om eerst in planmodus te draaien, zodat je een idee hebt van wat de agent zou willen veranderen. En wees dan klaar om wijzigingen terug te draaien of zelfs `omarchy reinstall configs` aan te roepen, als de agent er een puinhoop van maakt.
