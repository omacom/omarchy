# AI

Omarchy bevat launchers voor de onderstaande coding agents zonder een standaard voor je te kiezen. Voer een commando uit om de CLI ervan bij het eerste gebruik te installeren en authenticeer vervolgens wanneer daarom wordt gevraagd. Hermes en OpenClaw zijn de uitzonderingen: er wordt voor hen niets via mise geïnstalleerd, en het kiezen van een van beide zet een eigen, zichzelf bijwerkende kopie op, zoals _Desktop-apps_ hieronder uitlegt.

### Agents installeren en bijwerken

Met uitzondering van Hermes en OpenClaw gebruiken deze agents de luie installatie van mise: de eerste start installeert de CLI en latere starts hergebruiken die. mise controleert ook hooguit eens per vier uur of er een nieuwe release is voor een geïnstalleerde agent, net voordat die start of op de achtergrond bij een shellprompt. Als die update mislukt of je offline bent, draait de geïnstalleerde versie. `omarchy update` werkt geïnstalleerde agents bij samen met de rest van Omarchy, en `mup` werkt alleen door mise beheerde tools bij.

De eigen updater van een agent, zoals `claude update`, `codex update` of een updateknop in een app, werkt de door mise beheerde installatie niet bij. `codex update` mislukt, en `claude update` kan succes melden terwijl het een aparte kopie installeert die mise niet bijhoudt. Als je liever de native installer en updater van een agent gebruikt, voeg die dan toe aan `disable_tools`; zie [Vooraf geïnstalleerde CLI-tools](18-development-tools.md#preinstalled-cli-tools).

Om alle geconfigureerde lazy tools te installeren voordat je ze nodig hebt, voer je `mise install --include-lazy` uit. Dit omvat ook Omarchy's andere standaard-CLI-tools, naast de agents. Zie [Vooraf geïnstalleerde CLI-tools](18-development-tools.md#preinstalled-cli-tools) voor het installeren van één tool of het gebruiken van je eigen installatie.

`grok` wordt geïnstalleerd via mise's eigen `grok`-package, op dezelfde manier als `claude` en `codex`. Voer `grok` uit, of kies het onder _Agent > Harness_. Sla de `curl | bash`-installer op x.ai over. Dat pad plaatst een tweede kopie in `~/.grok/bin`, zet die vooraan op `PATH` en overschrijft Omarchy's wrapper.

`dsh` opent zijn browser-UI op `127.0.0.1:3080`, met de startmap als standaardwerkruimte. De browser-UI neemt geen startprompt aan, dus `omarchy agent prompt` opent het met de prompt op je klembord om te plakken. Omarchy start het met DeepSeek's preset voor machtigingen zonder goedkeuring. DeepSeek Harness uploadt sessielogs naar DeepSeek wanneer je de officiële model-API gebruikt; zet dat uit onder _Settings > General > Upload Session Log_ in de browser-UI. Feedback die je eraan stuurt, wordt ook met de sessie geüpload, tenzij je het start met `DSH_TELEMETRY_MODE=DISABLED`.

### De standaardagent

Kies je standaardagent met `omarchy default agent <name>` of onder _Agent > Harness_ in het Omarchy Menu (`Super + Space`). Als de agent nog niet is geïnstalleerd, installeert het kiezen ervan hem eerst, en hij krijgt ook een eigen launcher in de app launcher, naast Agent. Een verse Omarchy nodigt je met een eenmalige melding uit om deze keuze te maken.

Het kiezen van Claude probeert ook zijn browserextensie in te stellen voor Chromium, Chrome, Brave, Brave Origin en Edge. De installatie van de extensie geldt voor alle gebruikers en kan om je systeemwachtwoord vragen; annuleren of een mislukte installatie van de extensie selecteert en start Claude nog steeds. Herstart je browser, schakel de extensie in als daarom wordt gevraagd en log in bij Claude om de verbinding te voltooien. Voer `/chrome` uit in Claude om de verbinding te controleren. Firefox en Zen ondersteunen deze extensie niet. Als Claude al je standaard was voordat deze installatie werd toegevoegd, selecteer hem dan opnieuw om de extensie te installeren.

Zodra je hebt gekozen, start `Super + Shift + Ctrl + A` de standaardagent in een apart terminalvenster (of opent de kiezer als je nog niet hebt gekozen). Je kunt hem ook rechtstreeks met een taak starten met `omarchy agent prompt "Review this project"`. Freebuff en DeepSeek Harness nemen geen startprompt aan, dus zij openen in plaats daarvan met de prompt op je klembord om te plakken. Agents die op deze manier worden gestart, draaien onbeheerd in hun respectieve modi waarin ze niet stoppen om te vragen, dus wees erop voorbereid dat ze echt dingen gaan doen! MiniMax Code heeft geen dergelijke modus voor zijn interactieve sessies, dus die vraagt zoals gebruikelijk om machtigingen. En omdat agents weigeren vertrouwen te onthouden voor je thuismap, starten launches vanuit `$HOME` in plaats daarvan in `~/Work`.

Er zijn ook terminal-snelkoppelingen: `a` draait de standaardagent inline in de huidige terminal, terwijl `c`, `cx` en `cy` OpenCode, Claude Code en Codex rechtstreeks starten (wederom in hun automatisch goedkeurende modi). Themawisselingen synchroniseren ook mee naar de agents: Claude Code, Pi, OpenCode en Hermes (zodra Omarchy het heeft geïnstalleerd) volgen allemaal mee wanneer je het Omarchy-thema wisselt.

### Je agentinstructies

Persoonlijke regels voor elke agent gaan in `~/.agents/AGENTS.md`, naast de gedeelde skills in `~/.agents/skills`. Open het onder _Agent > Instructions_, dat het ook koppelt aan elke harness die een eigen globaal bestand bijhoudt: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, Copilot's `~/.copilot/copilot-instructions.md`, enzovoort. Crush en Amp lezen de link `~/.config/AGENTS.md`, terwijl omp, Kimi en DeepSeek Harness `~/.agents/AGENTS.md` rechtstreeks lezen. Het kiezen van een standaardagent koppelt het ook. Een instructiebestand dat je al had, wordt het gedeelde bestand als er nog geen was; anders wordt het naast de link bewaard als `.bak`. Voer `omarchy agent instructions` uit om opnieuw te koppelen na het installeren van een andere agent.

### Het agents-paneel

De bovenste balk heeft een agents-icoon. Voordat je een agent hebt ingesteld, leidt het paneel je door het inloggen bij Claude, Codex of Grok, en de eerste wordt je standaardagent. Daarna zet het paneel elk abonnement op één pagina: elke agent en elk account met zijn plan, een meter voor elk van zijn sessielimieten van 5 uur en wekelijkse limieten met de tijd tot hij reset (beweeg erover voor het exacte percentage), of het resterende vooruitbetaalde saldo, onder een regel die rouleert door wat je over al die agents heen hebt gebruikt, zoals tokens deze week en je meest gebruikte model. Onder _Make something cool_ biedt het startprompts voor een nieuw thema, plugin, app of game die de taak aan je standaardagent overhandigen. Apps worden gebouwd zoals Omarchy's eigen Hype, Monologue en Omacut, in C++ en Qt Quick, volgens de omarchy-make-app agent skill, en de compiler en Qt-onderdelen die ze nodig hebben, worden meegeleverd geïnstalleerd. Games zijn één three.js-pagina in `~/Games/vibes`, volgens de omarchy-make-game agent skill, en openen allemaal vanuit één Game Vibes launcher in het huidige thema; ze laden three.js van het web, dus ze hebben een verbinding nodig om te starten. Claude Code, Codex, Grok, Kimi, Cursor en zijn Grok Bot-toelage, GitHub Copilot, Muse, Antigravity en Devin worden standaard gedekt met hun limieten, Kimchi met zijn plan, vooruitbetaalde credits en uitgavenbudgetten, en Hermes, Mistral Vibe en Qwen Code tonen hun sessies en tokens zodra je ze hebt gebruikt. Providerplannen en sleutels die je via pi, omp of opencode gebruikt, verschijnen ook: OpenCode Zen en Go, het Z.ai GLM Coding Plan, Ollama Cloud, het MiniMax Token Plan en Synthetic met hun limieten; OpenRouter en DeepSeek met hun vooruitbetaalde saldi; Fireworks met zijn uitgaven over de afgelopen 30 dagen. Tokens van modellen die je op je eigen hardware draait, tellen ook mee voor de totalen; de modellen zelf hebben een eigen paneel, beschreven onder [Lokale modellen](#local-models). Elke agent wordt één keer geteld, bij wie hem ook factureert, ongeacht via hoeveel harnesses je hem aanstuurt.

Klik met de linkermuisknop op het balkicoon of druk op `Super + Ctrl + X` voor het paneel, klik met de rechtermuisknop om je standaardagent te starten en klik met de middelste muisknop om te vernieuwen. De gebruiksrecords erachter worden elke 15 minuten opnieuw gegenereerd door `omarchy agent usage update`, en het paneel kan zelfs gebruik van je andere machines samenvoegen via een gesynchroniseerde map. Zie de README onder `$OMARCHY_PATH/shell/plugins/agents/` voor de volledige instellingen.

### Meerdere abonnementen

Als je voor meer dan één Claude-, Codex- of Grok-plan betaalt — bijvoorbeeld een persoonlijk Max en een werkplan — kan Omarchy ze allemaal ingelogd houden en ertussen wisselen. Voeg een abonnement toe met de + in het agents-paneel, dat je er daar meteen doorheen leidt, of met `omarchy agent account add claude Work` (of `codex`, of `grok`). Het installeert de CLI als die ontbreekt. Het eerste account voor een provider logt in via je normale browser, precies waar de CLI altijd kijkt. Elk account daarna logt in via een privévenster, zodat het account waarbij je browser al is ingelogd niet per ongeluk wordt opgepikt; log daar in als het account dat je toevoegt en sluit eerst elk privévenster dat je al open had. Log hiervoor nooit uit bij de CLI: uitloggen trekt de opgeslagen aanmelding in, en dat account zou opnieuw moeten worden toegevoegd.

Om je abonnementsaanmeldingen via SSH naar een andere Omarchy-machine te kopiëren, voer je `omarchy agent account copy user@laptop` uit. De afzender levert een tijdelijke ontvanger wanneer de bestemming er geen geïnstalleerd heeft, zodat oudere Omarchy-machines accounts kunnen ontvangen zonder een update. Geïnstalleerde ontvangers hebben voorrang. Dit kopieert alle Claude-, Codex- en Grok-abonnementen; voeg providernamen toe om ze te selecteren, zoals in `omarchy agent account copy laptop claude`. Accountnamen en commando-ID's komen overeen met de bron, inclusief accounts die al op de bestemming aanwezig zijn. Niet-gerelateerde bestemmingsaccounts krijgen een numeriek achtervoegsel als hun namen conflicteren, en instellingen, skills, plugins en gespreksgeschiedenis blijven lokaal op elke machine.

Bestaande bestemmingsgegevens worden bewaard. Een bronaccount dat daar al is ingelogd, krijgt zijn naam gesynchroniseerd zonder zijn gegevens te vervangen; andere accounts worden ernaast toegevoegd. Om opgeslagen gegevens voor overeenkomende accounts te vervangen, gebruik je `omarchy agent account copy --replace laptop claude` nadat je de sessies van dat account op de bestemming hebt afgesloten. Een verse bestemming krijgt ook het actieve account en de wisselvoorkeuren van de bron; een gevestigde bestemming behoudt zijn eigen voorkeuren.

Gegevens reizen via SSH en worden opgeslagen in privébestanden op de bestemming, dus kopieer alleen naar machines die je vertrouwt. Dit is een eenmalige kopie, geen doorlopende synchronisatie. Codex refresh tokens kunnen door een andere machine worden geroteerd, waardoor een gekopieerde aanmelding moet worden vernieuwd; aparte aanmeldingen blijven de betrouwbaarste keuze voor gelijktijdig gebruik op meerdere machines. Zie [Codex's richtlijnen voor accountauthenticatie](https://developers.openai.com/codex/auth/ci-cd-auth).

Per provider is één account actief, en elke nieuwe sessie start als dat account: `cx`, `cy`, een gewone `claude`, `codex` of `grok`, alles wat via `omarchy agent` wordt gestart, en scripts of editors die de CLI op `PATH` vinden. Wissel met `omarchy agent account use work` (en terug met `omarchy agent account use main`), of in het paneel door op het nummer van een account en vervolgens op `Enter` te drukken (of door op de knop Use te klikken). Draaiende Claude-sessies wisselen ook mee, vanaf hun volgende bericht: elke Claude-sessie draait in `~/.claude`, dat altijd de aanmelding van het actieve account bevat. Een Claude-sessie die door een oudere Omarchy in de eigen map van een account is gestart, behoudt die aanmelding tot hij afsluit, dus de wissel benoemt die sessies en rondt vanzelf af zodra ze weg zijn. Draaiende Codex- en Grok-sessies blijven op het account waarmee ze zijn gestart. Gespreksgeschiedenis, instellingen, skills en plugins worden gedeeld tussen accounts, dus `claude --continue` in dezelfde map pakt het op waar je was gebleven op het nieuwe account.

Met meer dan één account toont het paneel de limieten van elk account naast elkaar, met het actieve account gemarkeerd. Standaard meldt Omarchy het je wanneer het actieve account 95% van een limiet passeert, en door op de melding te klikken wissel je naar het account met de meeste speelruimte. Beweeg over de regel van een account in het paneel en klik op de Autoswitch die naast Use verschijnt (of druk op `m`), of voer `omarchy agent account mode auto` uit, om het in plaats daarvan vanzelf te laten wisselen; terwijl het aan staat, neemt Autoswitch de plaats van Use in, en nogmaals klikken gaat terug naar melden. Voeg een getal toe om de drempel te wijzigen, zoals in `omarchy agent account mode auto 90`. Als elk account boven de drempel zit, hoor je dat één keer, samen met welk account als eerste vrijkomt. Terwijl een actief account binnen 15 punten van zijn drempel zit (80% bij de standaard), worden zijn limieten elke drie minuten gecontroleerd in plaats van elke 15.

`omarchy agent account list` toont elk account en zijn laatste limieten, `omarchy agent account remove work` vergeet er een, en `omarchy agent account rename primary Hey` hernoemt er een (of klik op de naam van een account in het paneel). Deze commando's werken op de accounts van je standaardagent; om de andere provider te bereiken, noem je die eerst, zoals in `omarchy agent account use codex side`. De aanmelding die je al had in `~/.claude` of `~/.codex` is het _Main_-account. Die van Codex blijft waar hij is; die van Claude wacht in een eigen map terwijl een ander account actief is. Een account dat langer dan ongeveer acht uur ongebruikt is gebleven, kan _Sign-in required_ tonen; klik erop om dat account meteen in het paneel opnieuw aan te melden, of wissel ernaar en start een sessie, wat de aanmelding vanzelf vernieuwt. MCP-servers die je toevoegt met `claude mcp add` bereiken elk Claude-account, omdat ze allemaal in `~/.claude` draaien; voor Codex en Grok komen servers die je had toen een account werd toegevoegd mee naar dat account, maar latere servers bereiken alleen het account waarin je ze hebt toegevoegd. Claude Desktop bewaart een eigen aanmelding, en Codex- of Grok-tools die zijn geconfigureerd met een absoluut pad naar een CLI-binary volgen de wissel niet. Een expliciete `CLAUDE_CONFIG_DIR`, `CODEX_HOME` of `GROK_HOME` heeft voorrang op het geselecteerde account.

### Crashdiagnose

Omarchy bewaakt systemd-coredump op procescrashes. Zodra je een standaardagent hebt gekozen, brengt elk programma van jou dat een core dumpt een melding "Process crashed" — klik erop, en de crash wordt overhandigd aan je standaardagent samen met Omarchy's omarchy-diagnose-crash skill, die de agent begeleidt bij het vaststellen van de feiten uit de core dump en het beslissen of de crash het waard is om upstream te melden. Je kunt het ook handmatig uitvoeren tegen elke PID uit `coredumpctl list` met `omarchy agent crash <pid>`.

Het bewaken staat standaard aan. Zet het uit onder _Trigger > Toggle > Crash Capture Off_ (of met `omarchy toggle crash-capture`) en de meldingen stoppen; `omarchy agent crash <pid>` werkt nog steeds handmatig.

Crashes kunnen ook per programma worden gedempt, wat de diagnose je aan het einde aanbiedt. `omarchy crash mute hyprland` stopt de meldingen alleen voor dat programma, `omarchy crash mute hyprland off` brengt ze terug, en `omarchy crash mute` op zichzelf somt op wat je hebt gedempt. Het accepteert het pad van de binary net zo graag als zijn naam, dus `omarchy crash mute /usr/bin/hyprland` doet hetzelfde. Zet een naam met een spatie erin tussen aanhalingstekens, zoals in `omarchy crash mute 'Some App'`. Alles anders blijft melden, en het gedempte programma blijft crashen — dit verbergt de herinnering, het lost niets op.

### Desktop-apps

Het menu _Install > AI_ bevat ook een paar grafische AI-apps: Amp Desktop, Antigravity Desktop, de ChatGPT desktop app, de Claude desktop app (Anthropic's Linux-bèta, met tabbladen Chat, Cowork en Claude Code), Grok Bot om met xAI's modellen te chatten, Herdr Desktop, Hermes Desktop, OpenClaw, de Perplexity desktop app en T3 Code. Grok Bot is de desktopchatapp. De coding agent is het `grok`-commando.

Hermes Desktop is degene die je moet kennen, omdat een machine één Hermes heeft, en die is van de app: Hermes wordt alleen ooit via de app geïnstalleerd, en het `hermes`-commando dat de standaardagent draait, is dat van de app. Het kiezen van Hermes als standaardagent installeert hetzelfde als wat het item _Install > AI_ doet: het package en een Hermes-runtime onder `~/.hermes` die is opgezet door Hermes' eigen installer, wat de eerste keer een paar minuten duurt. Die runtime is de ene Hermes die het terminalcommando `hermes`, de standaardagent en de app allemaal gebruiken, en hij werkt zichzelf bij met `hermes update` in plaats van te wachten op een Omarchy-release. Het installeren ervan geeft Hermes ook het Omarchy-thema als een skin met de naam `omarchy`, die elk Hermes-oppervlak volgt terwijl je van thema wisselt; kies een andere onder Hermes' Appearance-instellingen of met `/skin` als je liever niet wilt dat het dat doet, en Omarchy laat die keuze met rust. Het verwijderen van de app onder _Remove > AI_ sluit Hermes eerst, inclusief de gateway, neemt die runtime mee, en bewaart je chats, herinneringen en de skills die Hermes voor zichzelf heeft geschreven, tenzij je anders aangeeft: het vraagt, met nee als standaard, of die gegevens en je verbindingsinstellingen ook moeten verdwijnen.

De desktopervaring van OpenClaw is zijn Control UI, die opent als een webapp die wordt ondersteund door zijn eigen lokale gateway. OpenClaw leeft in `~/.openclaw` en werkt zichzelf bij: gebruik de knop "Update Gateway" in de Control UI of voer `openclaw update` uit, en de gateway herstart op de nieuwe versie. Omarchy kiest alleen de release waarmee een verse installatie begint. OpenClaw kan ook je standaardagent zijn: het kiezen ervan onder _Agent > Harness_ zet diezelfde kopie op in `~/.openclaw`, en de agent opent OpenClaw's terminal UI gekoppeld aan zijn gateway. Het verwijderen van OpenClaw onder _Remove > AI_ neemt de gatewayservice en de app mee en vraagt vervolgens of `~/.openclaw` ook moet verdwijnen, aangezien dat je chats en gegevens bevat naast OpenClaw zelf en de pluginruntimes die het downloadt; de standaard behoudt het, en het opnieuw installeren van OpenClaw pakt het weer op.

Herdr Desktop is de desktopapp van [Herdr](https://herdr.dev): spaces, tabs en panes van terminals en coding agents die blijven draaien in zijn core wanneer je het venster sluit. Het komt van Herdr's eigen installer in plaats van een package, dus het leeft in `~/.local/share/herdr-app`, brengt zijn core mee in `~/.local/bin/herdr-core` wanneer je er nog geen hebt, en werkt beide zelf bij. Het zit naast het `herdr`-commando dat Omarchy levert op `Super + Ctrl + Return` in plaats van het te vervangen, en krijgt de directe toetsen van dat commando: `Alt + Return` en `Alt + Shift + Return` splitsen een pane omlaag of naar rechts, `Alt + Escape` sluit het, `Ctrl + Alt + Arrow` beweegt tussen panes, `Alt + 1..9` en `Alt + Left/Right` kiezen een tab, en `Alt + Up/Down` bewegen tussen spaces. `Ctrl + 1..9` kiest een space en `Alt + Shift + Up/Down` stapt door agents. De prefix-toetsen met `Ctrl + Space` blijven alleen voor de terminal, omdat de app geen gewone Ctrl-toets kan vasthouden voor een reeks. Omarchy schrijft deze naar `~/.config/herdr-app/keys.json`, en `omarchy-refresh-herdr-app` zet ze terug. Het installeren ervan kiest Herdr's Omarchy-thema, dat vanaf dan je Omarchy-thema volgt. Herdr bewaart één thema voor de lichte modus en één voor de donkere, dus nadat je tussen een donker en een licht Omarchy-thema hebt gewisseld, kies je Omarchy nog een keer in Herdr's themakiezer voor de andere modus.

T3 Code draait vanuit zijn officiële AppImage-release in `~/.local/share/t3code` in plaats van vanuit een package, dus het werkt zichzelf bij. Het installeren ervan vraagt of je op het Stable- of Nightly-kanaal wilt starten; wissel later in de instellingen van T3 Code. Je threads en instellingen leven in `~/.t3`, en het verwijderen van T3 Code onder _Remove > AI_ neemt ze mee.

### Lokale modellen

Draai een open model op je eigen machine voor je coding agents. Je prompts en code blijven op de machine; niets dat naar het model wordt gestuurd, verlaat die. Begin met:

```bash
omarchy models use best text
```

Dat zet het beste tekstmodel voor deze machine op, het soort dat je agents gebruiken. Beeld-, video- en muziekmodellen hebben hun eigen beste: `omarchy models use best image`, `video` of `music`. Voer `omarchy models use best` uit om de keuze van elke soort voor deze machine te zien.

Of open het paneel voor lokale modellen vanuit het sparkles-icoon in de bovenste balk, naast het agents-icoon, of met Super + Ctrl + Alt + X, en kies +. Het icoon verschijnt wanneer een model op deze machine past. Podman, dat de modellen draait, wordt met Omarchy meegeleverd, net als NVIDIA's container toolkit op een NVIDIA-machine, die ze de GPU geeft; als een van beide ontbreekt, installeert de eerste installatie het. Omarchy kiest vervolgens het aanbevolen model voor deze machine, downloadt het en start het. Verwacht een download van tientallen GB en dat het grootste deel van het geheugen van de machine in gebruik is terwijl het model draait: Flash Next gebruikt ongeveer 100 GiB met zijn volledige context van 256K. Als andere modellen het geheugen bezet houden dat het nodig heeft, wordt het gestopt opgezet, klaar om te starten zodra je er een stopt. Het model stopt bij uitloggen; stop het zelf wanneer je het geheugen voor iets anders nodig hebt.

`omarchy models list` toont de opties en legt uit waarom sommige niet passen. Om een andere op te zetten, voer je `omarchy models use <recipe>` uit. Vandaag zijn `qwen3.8-flash-next-gufo` en `qwen3.8-27b-gufo` beschikbaar voor Strix Halo-machines met 128 GB; de 27B neemt ongeveer 40 GiB, dus die laat ruimte voor ander werk. Op een laptop van 64 GB met Intel's Arc B390 draait `qwen3.6-35b-a3b-llamacpp` in ongeveer 30 GiB. Nieuwe recepten en aanbevelingen komen aan met `omarchy update`, via het package.

Elk model dat je opzet, krijgt een eigen regel in het paneel voor lokale modellen: play om het te starten, pause om het te stoppen en zijn geheugen vrij te maken, en de terminalknop om je agent erop te openen. Bovenaan toont een balk hoe het geheugen van de machine is verdeeld tussen Omarchy zelf (het systeem en je apps), elk draaiend model en wat vrij is. Wijs naar een gestopt model en de balk toont of het past, of hoeveel het tekortkomt. Meerdere kunnen tegelijk draaien wanneer ze samen in het geheugen passen; als er een niet past, zegt Omarchy welk draaiend model je moet stoppen. Sleep regels aan hun logo om ze te herordenen, en druk op Delete op een geselecteerde regel om een model en zijn download te verwijderen.

Elk model dat je opzet, krijgt ook een eigen item in de app launcher, onder de naam van het model en met het logo van zijn maker, op dezelfde manier als inloggen bij Claude, Codex of Grok er een toevoegt. Het opent je agent op dat model en start het model eerst als het niet draait: de terminal toont dat het laadt en draagt over aan de agent zodra het actief is. Het verwijderen van een model verwijdert zijn item.

Niet elk model is om te coderen. Beeld-, video- en muziekmodellen openen in plaats daarvan in Fantasi, Omarchy's app om afbeeldingen, video en muziek te maken met een model dat op deze machine draait, vanuit hun launcher-item en vanuit hun regel in het paneel voor lokale modellen.

Een model blijft precies draaien zoals het is opgezet, dus een Omarchy-update herstart er nooit een onder je agents. Wanneer Omarchy een nieuwere runtime of nieuwere gewichten heeft voor een model dat je hebt opgezet, toont zijn regel een updateknop: druk erop en het model wordt op de achtergrond opnieuw opgezet, waarbij alleen wordt gedownload wat er is veranderd, en herstart op de nieuwe versie. Een model dat gestopt was, blijft gestopt. `omarchy models update` doet hetzelfde voor elk model vanuit een terminal.

Vanaf de commandoregel doen `omarchy models start <recipe>` en `omarchy models stop <recipe>` hetzelfde, toont `omarchy models status` elk model, en opent `omarchy agent --local` je standaardagent op het laatste model dat je hebt gestart. pi, OpenCode en Qwen Code kunnen er een gebruiken; bij elke andere standaard opent het in pi, of in OpenCode als je geen pi hebt. pi somt ook elk model op dat je hebt opgezet, en die op machines waarmee je bent gekoppeld, in zijn eigen modelkiezer, dus gewone `pi` bereikt ze ook. Elke OpenAI-compatibele client kan ook verbinden: `status` toont het adres van elk model (het eerste is `http://127.0.0.1:11435/v1`), de receptnaam is het model, en de sleutel staat in `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` verwijdert een model en de downloads die geen ander model gebruikt.

Runtimes van derden worden gelabeld met hun uitgever. Omarchy draait elk model zonder netwerktoegang.

### Lokale LLM's

Omarchy raadt twee manieren aan om lokale LLM-modellen te draaien: LM Studio en Ollama. LM Studio biedt een GUI-interface voor het vinden van open-weight modellen, het installeren ervan en het draaien ervan. Het is een geweldige manier om gemakkelijk aan de slag te gaan. Ollama biedt een CLI om dat op vergelijkbare manier te doen. Maar als je nieuw bent met lokale modellen, zou ik beginnen met LM Studio. Je kunt beide installeren onder _Install > AI_ in het Omarchy Menu.

### De Omarchy skills

Agent skills helpen AI om specifieke tools op een specifieke manier te gebruiken, en Omarchy levert er zeven mee. De omarchy skill dekt het op maat maken van het systeem, zoals het tweaken van je Hyprland-config of het aanpassen van de balk. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app en omarchy-make-game dekken het maken van iets nieuws, omarchy-contribute dekt het melden van een bug of het upstream sturen van een fix, en omarchy-diagnose-crash werkt zich door de core dump van een crash heen. Ze zijn gesymlinkt naar de skillmappen voor Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` en elke `~/.hermes/profiles/*/skills`), en de generieke locatie `~/.agents/skills`, dus de meeste harnesses pikken ze automatisch op. Een eigen skillmap met dezelfde naam heeft voorrang.

Maar je moet deze skills als experimenteel beschouwen. Verschillende modellen zullen het met verschillend effect gebruiken. Het is het beste om eerst in planmodus te draaien, zodat je een idee hebt van wat de agent zou willen veranderen. En wees er dan klaar voor om wijzigingen terug te draaien of zelfs `omarchy reinstall configs` aan te roepen, als de agent er een puinhoop van maakt.
