# AI

Omarchy bevat launchers voor de onderstaande coding agents zonder er standaard een voor je te kiezen. Voer een commando uit om bij het eerste gebruik de CLI ervan te installeren en authenticeer vervolgens wanneer daarom wordt gevraagd. Hermes is de uitzondering: er wordt bij het eerste gebruik niets voor geïnstalleerd, en als je Hermes kiest, wordt Hermes Desktop geïnstalleerd, zoals _Desktop-apps_ hieronder uitlegt.

### Agents installeren en bijwerken

Behalve Hermes gebruiken deze agents de luie installatie van mise: bij de eerste start wordt de CLI geïnstalleerd, en latere starts hergebruiken die. mise controleert ook hooguit eens per vier uur of er een nieuwe release is van een geïnstalleerde agent, net voordat die start of op de achtergrond bij een shell-prompt. Als die update mislukt of je offline bent, draait de geïnstalleerde versie. `omarchy update` werkt geïnstalleerde agents bij samen met de rest van Omarchy, en `mup` werkt alleen door mise beheerde tools bij.

De eigen updater van een agent, zoals `claude update`, `codex update`, of een updateknop in een app, werkt de door mise beheerde installatie niet bij. `codex update` mislukt, en `claude update` kan succes melden terwijl het een aparte kopie installeert die mise niet bijhoudt. Als je liever de native installer en updater van een agent gebruikt, voeg die dan toe aan `disable_tools`; zie [Vooraf geïnstalleerde CLI-tools](18-development-tools.md#preinstalled-cli-tools).

Om alle geconfigureerde lazy tools te installeren voordat je ze nodig hebt, voer je `mise install --include-lazy` uit. Dit omvat ook de andere standaard CLI-tools van Omarchy, naast de agents. Zie [Vooraf geïnstalleerde CLI-tools](18-development-tools.md#preinstalled-cli-tools) voor het installeren van één tool of het gebruik van je eigen installatie.

`grok` wordt geïnstalleerd via het first-party `grok`-pakket van mise, op dezelfde manier als `claude` en `codex`. Voer `grok` uit, of kies het onder _Agent > Harness_. Sla de `curl | bash`-installer op x.ai over. Die route zet een tweede kopie in `~/.grok/bin`, zet die vooraan op `PATH`, en overschrijft de wrapper van Omarchy.

`dsh` opent zijn browser-UI op `127.0.0.1:3080`, met de startmap als standaard werkruimte. De browser-UI neemt geen startprompt aan, dus `omarchy agent prompt` opent het met de prompt op je klembord om te plakken. Omarchy start het met de no-approval-permissiepreset van DeepSeek. DeepSeek Harness uploadt sessielogs naar DeepSeek wanneer je zijn officiële model-API gebruikt; zet dat uit onder _Settings > General > Upload Session Log_ in zijn browser-UI. Feedback die je eraan stuurt, wordt ook met de sessie geüpload, tenzij je het start met `DSH_TELEMETRY_MODE=DISABLED`.

### De standaardagent

Kies je standaardagent met `omarchy default agent <name>` of onder _Agent > Harness_ in het Omarchy Menu (`Super + Space`). Als de agent nog niet is geïnstalleerd, wordt hij eerst geïnstalleerd als je hem kiest. Een verse Omarchy nodigt je met een eenmalige melding uit om deze keuze te maken.

Als je Claude kiest, wordt ook geprobeerd zijn browserextensie in te stellen voor Chromium, Chrome, Brave, Brave Origin en Edge. De extensie-installatie geldt voor alle gebruikers en kan om je systeemwachtwoord vragen; annuleren of een mislukte extensie-installatie selecteert en start Claude nog steeds. Herstart je browser, schakel de extensie in als daarom wordt gevraagd, en log in bij Claude om de verbinding te voltooien. Voer `/chrome` uit in Claude om de verbinding te controleren. Firefox en Zen ondersteunen deze extensie niet. Als Claude al je standaard was voordat deze installatie werd toegevoegd, selecteer hem dan opnieuw om de extensie te installeren.

Zodra je hebt gekozen, start `Super + Shift + Ctrl + A` de standaardagent in een apart terminalvenster (of opent de kiezer als je nog niet hebt gekozen). Je kunt hem ook rechtstreeks een taak geven met `omarchy agent prompt "Review this project"`. Freebuff en DeepSeek Harness nemen geen startprompt aan, dus zij openen met de prompt op je klembord om in plaats daarvan te plakken. Agents die op deze manier worden gestart, draaien onbeheerd in hun respectieve don't-stop-to-ask-modi, dus wees erop voorbereid dat ze daadwerkelijk dingen gaan doen! MiniMax Code heeft geen dergelijke modus voor zijn interactieve sessies, dus die vraagt zoals gebruikelijk om toestemming. En omdat agents weigeren vertrouwen voor je thuismap te onthouden, starten launches vanuit `$HOME` in plaats daarvan in `~/Work`.

Er zijn ook terminal-snelkoppelingen: `a` draait de standaardagent inline in de huidige terminal, terwijl `c`, `cx` en `cy` OpenCode, Claude Code en Codex rechtstreeks starten (wederom in hun auto-goedkeurende modi). Themawijzigingen synchroniseren ook naar de agents: Claude Code, Pi, OpenCode en Hermes (zodra Omarchy die heeft geïnstalleerd) volgen allemaal mee wanneer je het Omarchy-thema wisselt.

### Je agentinstructies

Persoonlijke regels voor elke agent gaan in `~/.agents/AGENTS.md`, naast de gedeelde skills in `~/.agents/skills`. Open het onder _Agent > Instructies_, wat het ook koppelt aan elke harness die zijn eigen globale bestand bijhoudt: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` van Copilot, enzovoort. Crush en Amp lezen de link `~/.config/AGENTS.md`, terwijl omp, Kimi en DeepSeek Harness `~/.agents/AGENTS.md` rechtstreeks lezen. Als je een standaardagent kiest, wordt het ook gekoppeld. Een instructiebestand dat je al had, wordt het gedeelde bestand als er nog geen was; anders wordt het naast de link bewaard als `.bak`. Voer `omarchy agent instructions` uit om opnieuw te koppelen nadat je een andere agent hebt geïnstalleerd.

### Het agents-paneel

De bovenbalk heeft een agents-icoon. Voordat je een agent hebt ingesteld, leidt zijn paneel je door het inloggen bij Claude, Codex of Grok, en de eerste wordt je standaardagent. Daarna zet het paneel elk abonnement op één pagina: elke agent en account met zijn abonnement, een meter voor elk van zijn sessielimieten van 5 uur en wekelijkse limieten met de tijd tot hij reset (beweeg eroverheen voor het exacte percentage), of het resterende prepaid saldo, onder een regel die rouleert door wat je bij allemaal hebt gebruikt, zoals tokens deze week en je meest gebruikte model. Onder _Maak iets_ biedt het starterprompts voor een nieuw thema, plugin, app of game die de taak aan je standaardagent overhandigen. Apps worden gebouwd zoals de eigen Hype, Monologue en Omacut van Omarchy, in C++ en Qt Quick, volgens de omarchy-app agent skill, en de compiler en Qt-onderdelen die ze nodig hebben, worden meegeleverd. Games zijn één enkele three.js-pagina in `~/Games/vibes`, volgens de web-game agent skill, en openen allemaal vanuit één Game Vibes-launcher in het huidige thema; ze laden three.js van het web, dus ze hebben een verbinding nodig om te starten. Claude Code, Codex, Grok, Kimi, Cursor en zijn Grok Bot-tegoed, GitHub Copilot, Muse, Antigravity, Kimchi en Devin worden direct ondersteund met hun limieten, en Hermes, Mistral Vibe en Qwen Code tonen hun sessies en tokens zodra je ze hebt gebruikt. Providerabonnementen en -sleutels die je via pi, omp of opencode gebruikt, verschijnen ook: OpenCode Zen en Go, het Z.ai GLM Coding Plan, Ollama Cloud, het MiniMax Token Plan en Synthetic met hun limieten; Fireworks, OpenRouter en DeepSeek met hun prepaid saldo's; en de modellen die je op je eigen hardware draait onder Lokale modellen. Elke agent wordt één keer geteld, onder degene die hem factureert, ongeacht via hoeveel harnesses je hem aanstuurt.

Klik met links op het balkicoon voor het paneel, klik met rechts om je standaardagent te starten. De gebruiksrecords erachter worden elke 15 minuten opnieuw gegenereerd door `omarchy agent usage-update`, en het paneel kan zelfs gebruik van je andere machines samenvoegen via een gesynchroniseerde map. Zie de README onder `$OMARCHY_PATH/shell/plugins/agents/` voor de volledige instellingen.

### Meerdere abonnementen

Als je voor meer dan één Claude-, Codex- of Grok-abonnement betaalt — bijvoorbeeld een persoonlijk Max en een werkabonnement — kan Omarchy ze allemaal ingelogd houden en tussen ze wisselen. Voeg een abonnement toe met de + in het agents-paneel, dat je daar ter plekke doorheen leidt, of met `omarchy agent account add claude Work` (of `codex`, of `grok`). Het installeert de CLI als die ontbreekt. Het eerste account voor een provider logt in via je normale browser, precies waar de CLI altijd kijkt. Elk account daarna logt in via een privévenster, zodat het account waarbij je browser al is ingelogd niet per ongeluk wordt opgepikt; log daar in als het account dat je toevoegt, en sluit eerst elk privévenster dat je al open had. Log hiervoor nooit uit bij de CLI: uitloggen trekt de opgeslagen login in, en dat account zou opnieuw moeten worden toegevoegd.

Om je abonnementslogins via SSH naar een andere Omarchy-machine te kopiëren, voer je `omarchy agent account copy user@laptop` uit. De afzender levert een tijdelijke ontvanger wanneer de bestemming er geen heeft geïnstalleerd, zodat oudere Omarchy-machines accounts kunnen ontvangen zonder update. Geïnstalleerde ontvangers hebben voorrang. Dit kopieert alle Claude-, Codex- en Grok-abonnementen; voeg providernamen toe om ze te selecteren, zoals in `omarchy agent account copy laptop claude`. Accountnamen en commando-ID's komen overeen met de bron, inclusief accounts die al op de bestemming aanwezig zijn. Niet-gerelateerde bestemmingsaccounts krijgen een numeriek achtervoegsel als hun namen conflicteren, en instellingen, skills, plugins en gespreksgeschiedenis blijven lokaal op elke machine.

Bestaande inloggegevens op de bestemming blijven behouden. Een bronaccount dat daar al is ingelogd, krijgt zijn naam gesynchroniseerd zonder zijn inloggegevens te vervangen; andere accounts worden ernaast toegevoegd. Om opgeslagen inloggegevens voor overeenkomende accounts te vervangen, gebruik je `omarchy agent account copy --replace laptop claude` nadat je de sessies van dat account op de bestemming hebt afgesloten. Een verse bestemming krijgt ook het actieve account en de wisselvoorkeuren van de bron; een gevestigde bestemming behoudt haar eigen.

Inloggegevens reizen via SSH en worden opgeslagen in privébestanden op de bestemming, dus kopieer alleen naar machines die je vertrouwt. Dit is een eenmalige kopie, geen doorlopende synchronisatie. Codex-refresh-tokens kunnen door een andere machine worden geroteerd, waardoor een gekopieerde login moet worden vernieuwd; aparte logins blijven de betrouwbaarste keuze voor gelijktijdig gebruik op meerdere machines. Zie [De richtlijnen voor accountauthenticatie van Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Eén account per provider is actief, en elke nieuwe sessie start als dat account: `cx`, `cy`, een gewone `claude`, `codex` of `grok`, alles wat via `omarchy agent` wordt gestart, en scripts of editors die de CLI op `PATH` vinden. Wissel met `omarchy agent account use work` (en terug met `omarchy agent account use main`), of in het paneel door op het nummer van een account te drukken en daarna op `Enter` (of door op zijn knop Use te klikken). Actieve Claude-sessies wisselen ook mee, vanaf hun volgende bericht: elke Claude-sessie draait in `~/.claude`, dat altijd de login van het actieve account bevat. Een Claude-sessie die door een oudere Omarchy in de eigen map van een account is gestart, behoudt die login tot hij stopt, dus de wissel benoemt die sessies en eindigt vanzelf zodra ze weg zijn. Actieve Codex- en Grok-sessies blijven op het account waarmee ze zijn gestart. Gespreksgeschiedenis, instellingen, skills en plugins worden gedeeld tussen accounts, dus `claude --continue` in dezelfde map pakt op waar je was gebleven op het nieuwe account.

Met meer dan één account toont het paneel de limieten van elk account naast elkaar, met het actieve gemarkeerd. Standaard meldt Omarchy je wanneer het actieve account 95% van een limiet overschrijdt, en door op de melding te klikken wissel je naar het account met de meeste ruimte. Beweeg over de regel van een account in het paneel en klik op de Autoswitch die naast Use verschijnt (of druk op `m`), of voer `omarchy agent account mode auto` uit, om het vanzelf te laten wisselen; terwijl het aan staat, neemt Autoswitch de plaats van Use in, en door er opnieuw op te klikken ga je terug naar melden. Voeg een getal toe om de drempel te veranderen, zoals in `omarchy agent account mode auto 90`. Als elk account boven de drempel zit, hoor je dat één keer, samen met welk account als eerste vrijkomt. Terwijl een actief account binnen 15 punten van zijn drempel zit (80% bij de standaard), worden zijn limieten elke drie minuten gecontroleerd in plaats van elke 15.

`omarchy agent account list` toont elk account en zijn laatste limieten, `omarchy agent account remove work` vergeet er één, en `omarchy agent account rename primary Hey` hernoemt er één (of klik op de naam van een account in het paneel). Deze commando's werken op de accounts van je standaardagent; om de andere provider te bereiken, benoem je die eerst, zoals in `omarchy agent account use codex side`. De login die je al had in `~/.claude` of `~/.codex` is het _Main_-account. Die van Codex blijft waar hij is; die van Claude wacht in een eigen map terwijl een ander account actief is. Een account dat meer dan ongeveer acht uur ongebruikt is gebleven, kan _Sign-in required_ tonen; klik erop om dat account direct in het paneel opnieuw in te loggen, of wissel ernaar en start een sessie, wat de login vanzelf vernieuwt. MCP-servers die je toevoegt met `claude mcp add` bereiken elk Claude-account, omdat ze allemaal in `~/.claude` draaien; voor Codex en Grok komen servers die je had toen een account werd toegevoegd met dat account mee, maar latere servers bereiken alleen het account waarin je ze hebt toegevoegd. Claude Desktop houdt een eigen login bij, en Codex- of Grok-tools die zijn geconfigureerd met een absoluut pad naar een CLI-binary volgen de wissel niet. Een expliciete `CLAUDE_CONFIG_DIR`, `CODEX_HOME` of `GROK_HOME` heeft voorrang op het geselecteerde account.

### Crashdiagnose

Omarchy houdt systemd-coredump in de gaten voor procescrashes. Wanneer iets segfault, krijg je een melding "Process crashed" — klik erop, en de crash wordt overhandigd aan je standaardagent samen met de diagnose-crash skill van Omarchy, die de agent door het vaststellen van de feiten uit de core dump leidt en beslist of de crash het waard is om upstream te melden. Je kunt het ook handmatig uitvoeren tegen elke PID uit `coredumpctl list` met `omarchy agent crash <pid>`.

Het toezicht staat standaard aan. Zet het uit onder _Trigger > Toggle > Crash Capture_ (of met `omarchy toggle crash-capture`) en de meldingen stoppen; `omarchy agent crash <pid>` werkt nog steeds handmatig.

Crashes kunnen ook per programma worden gedempt, wat de diagnose je aan het einde aanbiedt. `omarchy crash mute hyprland` stopt de meldingen alleen voor dat programma, `omarchy crash mute hyprland off` brengt ze terug, en `omarchy crash mute` op zichzelf somt op wat je hebt gedempt. Het accepteert het pad van de binary net zo graag als zijn naam, dus `omarchy crash mute /usr/bin/hyprland` doet hetzelfde. Zet een naam met een spatie erin tussen aanhalingstekens, zoals in `omarchy crash mute 'Some App'`. Al het andere blijft melden, en het gedempte programma crasht nog steeds — dit verbergt de herinnering, het fixt niets.

### Desktop-apps

Het menu _Installeren > AI_ bevat ook een paar grafische AI-apps: de ChatGPT desktop app, de Claude desktop app (de Linux-bèta van Anthropic, met Chat-, Cowork- en Claude Code-tabbladen), Grok Bot om te chatten met de modellen van xAI, Herdr Desktop, Hermes Desktop, OpenClaw, de Perplexity desktop app en T3 Code. Grok Bot is de desktop chat-app. De coding agent is het `grok`-commando.

Hermes Desktop is degene die je moet kennen, omdat een machine één Hermes heeft, en die is van de app: Hermes wordt alleen ooit via de app geïnstalleerd, en het `hermes`-commando dat de standaardagent uitvoert, is dat van de app. Hermes kiezen als standaardagent installeert hetzelfde als de vermelding _Installeren > AI_: het pakket, en een Hermes-runtime onder `~/.hermes` die is ingesteld door de eigen installer van Hermes, wat de eerste keer een paar minuten duurt. Die runtime is de ene Hermes die het terminalcommando `hermes`, de standaardagent en de app allemaal gebruiken, en hij werkt zichzelf bij met `hermes update` in plaats van te wachten op een Omarchy-release. Installeren geeft Hermes ook het Omarchy-thema als een skin genaamd `omarchy`, die elk Hermes-oppervlak volgt terwijl je thema's wisselt; kies een andere onder de Appearance-instellingen van Hermes of met `/skin` als je liever niet hebt dat hij dat doet, en Omarchy laat die keuze met rust. De app verwijderen onder _Verwijderen > AI_ sluit eerst Hermes, gateway inbegrepen, neemt die runtime mee, en behoudt je chats, herinneringen en de skills die Hermes voor zichzelf heeft geschreven, tenzij je anders aangeeft: het vraagt, met nee als standaard, of die gegevens en je verbindingsinstellingen ook weg moeten.

De desktopervaring van OpenClaw is zijn Control UI, die opent als een webapp ondersteund door zijn eigen lokale gateway. OpenClaw leeft in `~/.openclaw` en werkt zichzelf bij: gebruik de knop "Update Gateway" in de Control UI of voer `openclaw update` uit, en de gateway herstart op de nieuwe versie. Omarchy kiest alleen de release waarmee een verse installatie begint. OpenClaw verwijderen onder _Verwijderen > AI_ neemt de gatewayservice en de app mee en vraagt daarna of `~/.openclaw` ook weg moet, omdat dat je chats en inloggegevens bevat naast OpenClaw zelf en de pluginruntimes die het downloadt; de standaard behoudt het, en OpenClaw opnieuw installeren pakt het weer op.

Herdr Desktop is de desktop-app van [Herdr](https://herdr.dev): spaces, tabs en panes met terminals en coding agents die in zijn core blijven draaien wanneer je het venster sluit. Het komt van de eigen installer van Herdr in plaats van een pakket, dus het leeft in `~/.local/share/herdr-app`, brengt zijn core mee in `~/.local/bin/herdr-core` wanneer je er nog geen hebt, en werkt beide zelf bij. Het zit naast het `herdr`-commando dat Omarchy levert op `Super + Ctrl + Return` in plaats van het te vervangen, en krijgt de directe toetsen van dat commando: `Alt + Return` en `Alt + Shift + Return` splitsen een pane naar beneden of naar rechts, `Alt + Escape` sluit het, `Ctrl + Alt + Arrow` beweegt tussen panes, `Alt + 1..9` en `Alt + Left/Right` kiezen een tab, en `Alt + Up/Down` bewegen tussen spaces. `Ctrl + 1..9` kiest een space en `Alt + Shift + Up/Down` doorloopt agents. De prefix-toetsen met `Ctrl + Space` blijven alleen voor de terminal, omdat de app geen gewone Ctrl-toets kan vasthouden voor een reeks. Omarchy schrijft deze naar `~/.config/herdr-app/keys.json`, en `omarchy-refresh-herdr-app` zet ze terug. Installeren kiest het Omarchy-thema van Herdr, dat vanaf dan je Omarchy-thema volgt. Herdr bewaart één thema voor de lichte modus en één voor de donkere, dus na het wisselen tussen een donker en een licht Omarchy-thema kies je Omarchy nog een keer in de themakiezer van Herdr voor de andere modus.

T3 Code draait vanaf zijn officiële AppImage-release in `~/.local/share/t3code` in plaats van uit een pakket, dus het werkt zichzelf bij. Installeren vraagt of je op het Stable- of Nightly-kanaal wilt starten; wissel later in de instellingen van T3 Code. Je threads en instellingen leven in `~/.t3`, en T3 Code verwijderen onder _Verwijderen > AI_ neemt ze mee.

### Lokale modellen

Draai een open model op je eigen machine voor je coding agents. Je prompts en code blijven op de machine; niets dat naar het model wordt gestuurd, verlaat haar. Begin met:

```bash
omarchy agent local use best
```

Of kies in het agents-paneel in de bovenbalk + en daarna Lokale AI, wat verschijnt wanneer een model op deze machine past. De eerste keer installeert dit Podman, dat de modellen draait, en op een NVIDIA-machine de container toolkit van NVIDIA, die ze de GPU geeft. Omarchy kiest dan het aanbevolen model voor deze machine, downloadt het en start het. Verwacht een download van tientallen GB en dat het grootste deel van het geheugen van de machine in gebruik is terwijl het model draait: Flash Next gebruikt ongeveer 100 GiB met zijn volledige 256K-context. Als andere modellen het geheugen bezetten dat het nodig heeft, wordt het gestopt ingesteld, klaar om te starten zodra je er een stopt. Het model stopt bij uitloggen; stop het zelf wanneer je het geheugen voor iets anders nodig hebt.

`omarchy agent local list` toont de opties en legt uit waarom sommige niet passen. Om een andere in te stellen, voer je `omarchy agent local use <recipe>` uit. Vandaag zijn `qwen3.8-flash-next-gufo` en `qwen3.8-27b-gufo` beschikbaar voor 128 GB Strix Halo-machines; de 27B neemt ongeveer 40 GiB, dus hij laat ruimte voor ander werk. Op een 64 GB-laptop met Intel's Arc B390 draait `qwen3.6-35b-a3b-llamacpp` in ongeveer 30 GiB. Nieuwe recipes en aanbevelingen komen met `omarchy update`, via het pakket.

Elk model dat je instelt, krijgt zijn eigen regel in het agents-paneel, naast je abonnementen: play om het te starten, pause om het te stoppen en zijn geheugen vrij te geven, en de terminalknop om je agent erop te openen. Meerdere kunnen tegelijk draaien wanneer ze samen in het geheugen passen; als er een niet past, zegt Omarchy welk draaiend model je moet stoppen. Sleep regels om ze opnieuw te ordenen, en druk op Delete op een geselecteerde regel om een model en zijn download te verwijderen.

Elk model dat je instelt, krijgt ook zijn eigen vermelding in de app-launcher, onder de naam van het model en met het logo van zijn maker, net zoals inloggen bij Claude, Codex of Grok er een toevoegt. Het opent je agent op dat model, en start het model eerst als het niet draait: de terminal toont dat het laadt en draagt over aan de agent zodra het draait. Een model verwijderen verwijdert zijn vermelding.

Vanaf de commandoregel doen `omarchy agent local start <recipe>` en `omarchy agent local stop <recipe>` hetzelfde, `omarchy agent local status` toont elk model, en `omarchy agent --local` opent je standaardagent op het laatste model dat je hebt gestart. pi, OpenCode en Qwen Code kunnen er een gebruiken; bij elke andere standaard opent het in pi. pi somt ook elk model op dat je hebt ingesteld, en die op machines waarmee je bent gekoppeld, in zijn eigen modelkiezer, dus gewone `pi` bereikt ze ook. Elke OpenAI-compatibele client kan ook verbinding maken: `status` toont het adres van elk model (het eerste is `http://127.0.0.1:11435/v1`), de recipenaam is het model, en de sleutel staat in `~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` verwijdert een model en de downloads die geen ander model gebruikt.

Runtimes van derden zijn gelabeld met hun uitgever. Omarchy draait elk model zonder netwerktoegang.

### Lokale LLM's

Omarchy raadt twee manieren aan om lokale LLM-modellen te draaien: LM Studio en Ollama. LM Studio biedt een GUI-interface om open-weight modellen te vinden, te installeren en te draaien. Het is een geweldige manier om gemakkelijk te beginnen. Ollama biedt een CLI om dat op vergelijkbare wijze te doen. Maar als je nieuw bent met lokale modellen, zou ik beginnen met LM Studio. Je kunt beide installeren onder _Installeren > AI_ in het Omarchy Menu.

### De Omarchy Skill

Agent skills helpen AI om specifieke tools op een specifieke manier te gebruiken, en Omarchy wordt geleverd met een standaard skill om het systeem op maat te maken. Zoals het aanpassen van je Hyprland-config, het aanpassen van de balk, of zelfs een volledig nieuw thema vanaf nul creëren. Het is gesymlinkt naar de skill-mappen voor Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` en elke `~/.hermes/profiles/*/skills`), en de generieke locatie `~/.agents/skills`, dus de meeste harnesses pikken het automatisch op.

Maar je moet deze skill als experimenteel beschouwen. Verschillende modellen zullen hem met verschillend effect gebruiken. Het is het beste om eerst in planmodus te draaien, zodat je een idee hebt van wat de agent zou willen veranderen. En wees dan klaar om wijzigingen terug te draaien of zelfs `omarchy reinstall configs` aan te roepen, als de agent er een puinhoop van maakt.
