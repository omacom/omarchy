# AI

Omarchy bevat launchers voor de onderstaande codeeragents zonder er standaard een voor je te kiezen. Voer een commando uit om de CLI ervan bij het eerste gebruik te installeren en authenticeer je vervolgens wanneer daarom wordt gevraagd. Hermes is de uitzondering: daarvoor wordt bij het eerste gebruik niets geïnstalleerd, en als je ervoor kiest, wordt Hermes Desktop geïnstalleerd, zoals _Desktop-apps_ hieronder uitlegt.

### Agents installeren en bijwerken

Met uitzondering van Hermes gebruiken deze agents de luie installatie van mise: de eerste keer starten installeert de CLI, en latere keren hergebruiken die. mise controleert een geïnstalleerde agent ook hooguit eens per vier uur op een nieuwe release, vlak voordat hij start of op de achtergrond bij een shellprompt. Als die update mislukt of je offline bent, draait de geïnstalleerde versie. `omarchy update` werkt geïnstalleerde agents bij samen met de rest van Omarchy, en `mup` werkt alleen door mise beheerde tools bij.

De eigen updater van een agent, zoals `claude update`, `codex update` of een updateknop in een app, werkt de door mise beheerde installatie niet bij. `codex update` mislukt, en `claude update` kan succes melden terwijl het een aparte kopie installeert die mise niet bijhoudt. Als je liever de native installer en updater van een agent gebruikt, voeg hem dan toe aan `disable_tools`; zie [Vooraf geïnstalleerde CLI-tools](18-development-tools.md#preinstalled-cli-tools).

Om alle geconfigureerde luie tools te installeren voordat je ze nodig hebt, voer je `mise install --include-lazy` uit. Dit omvat zowel de andere standaard CLI-tools van Omarchy als de agents. Zie [Vooraf geïnstalleerde CLI-tools](18-development-tools.md#preinstalled-cli-tools) voor het installeren van een enkele tool of het gebruiken van je eigen installatie.

`grok` wordt geïnstalleerd via het first-party `grok`-pakket van mise, op dezelfde manier als `claude` en `codex`. Voer `grok` uit, of kies het onder _Agent > Harness_. Sla de `curl | bash`-installer op x.ai over. Die route zet een tweede kopie in `~/.grok/bin`, zet die vooraan op `PATH`, en overschrijft de wrapper van Omarchy.

`dsh` opent zijn browser-UI op `127.0.0.1:3080`, met de startmap als standaard werkruimte. De browser-UI neemt geen startprompt aan, dus `omarchy agent prompt` opent hem met de prompt op je klembord om te plakken. Omarchy start hem met de preset voor machtigingen zonder goedkeuring van DeepSeek. DeepSeek Harness uploadt sessielogs naar DeepSeek wanneer je zijn officiële model-API gebruikt; schakel dat uit onder _Settings > General > Upload Session Log_ in zijn browser-UI. Feedback die je hem stuurt, wordt ook met de sessie geüpload, tenzij je hem start met `DSH_TELEMETRY_MODE=DISABLED`.

### De standaardagent

Kies je standaardagent met `omarchy default agent <name>` of onder _Agent > Harness_ in het Omarchy Menu (`Super + Space`). Als de agent nog niet is geïnstalleerd, installeert het kiezen ervan hem eerst. Een verse Omarchy nodigt je met een eenmalige melding uit om deze keuze te maken.

Claude kiezen probeert ook zijn browserextensie in te stellen voor Chromium, Chrome, Brave, Brave Origin en Edge. De extensie-instelling geldt voor alle gebruikers en kan om je systeemwachtwoord vragen; annuleren of een mislukte extensie-installatie selecteert en start Claude nog steeds. Herstart je browser, schakel de extensie in als daarom wordt gevraagd, en log in bij Claude om het verbinden af te ronden. Voer `/chrome` uit in Claude om de verbinding te controleren. Firefox en Zen ondersteunen deze extensie niet. Als Claude al je standaard was voordat deze instelling werd toegevoegd, selecteer hem dan opnieuw om de extensie te installeren.

Zodra je hebt gekozen, start `Super + Shift + Ctrl + A` de standaardagent in een apart terminalvenster (of opent de kiezer als je nog niet hebt gekozen). Je kunt hem ook rechtstreeks met een taak starten met `omarchy agent prompt "Review this project"`. Freebuff en DeepSeek Harness nemen geen startprompt aan, dus openen zij in plaats daarvan met de prompt op je klembord om te plakken. Agents die op deze manier worden gestart, draaien onbeheerd in hun respectieve niet-stoppen-om-te-vragen-modi, dus wees erop voorbereid dat ze daadwerkelijk dingen gaan doen! MiniMax Code heeft geen dergelijke modus voor zijn interactieve sessies, dus vraagt hij zoals gebruikelijk om machtigingen. En omdat agents weigeren vertrouwen te onthouden voor je thuismap, starten lanceringen vanuit `$HOME` in plaats daarvan in `~/Work`.

Er zijn ook terminalsneltoetsen: `a` draait de standaardagent inline in de huidige terminal, terwijl `c`, `cx` en `cy` OpenCode, Claude Code en Codex rechtstreeks starten (wederom in hun automatisch-goedkeurende modi). Themawijzigingen synchroniseren ook mee naar de agents: Claude Code, Pi, OpenCode en Hermes (zodra Omarchy het heeft geïnstalleerd) volgen allemaal mee wanneer je van Omarchy-thema wisselt.

### Je agentinstructies

Persoonlijke regels voor elke agent gaan in `~/.agents/AGENTS.md`, naast de gedeelde skills in `~/.agents/skills`. Open het onder _Agent > Instructions_, wat het ook koppelt aan elke harness die zijn eigen globale bestand bijhoudt: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, het `~/.copilot/copilot-instructions.md` van Copilot, enzovoort. Crush en Amp lezen de koppeling `~/.config/AGENTS.md`, terwijl omp, Kimi en DeepSeek Harness `~/.agents/AGENTS.md` rechtstreeks lezen. Een standaardagent kiezen koppelt het ook. Een instructiebestand dat je al had, wordt het gedeelde bestand als er nog geen was; anders wordt het naast de koppeling bewaard als `.bak`. Voer `omarchy agent instructions` uit om opnieuw te koppelen na het installeren van een andere agent.

### Het agentspaneel

De bovenste balk heeft een agentspictogram. Voordat je een agent hebt ingesteld, leidt het paneel ervan je door het inloggen bij Claude, Codex of Grok, en de eerste wordt je standaardagent. Daarna zet het paneel elk abonnement op één pagina: elke agent en elk account met zijn abonnement, een meter voor elk van zijn sessielimieten van 5 uur en wekelijkse limieten met de tijd tot hij reset (beweeg erover voor het exacte percentage), of het resterende prepaid saldo, onder een regel die rouleert door wat je over al die agents hebt gebruikt, zoals tokens deze week en je meest gebruikte model. Onder _Make something_ biedt het startprompts voor een nieuw thema, een nieuwe plugin of app die de taak overdraagt aan je standaardagent. Apps worden gebouwd zoals de eigen Hype, Monologue en Omacut van Omarchy, in C++ en Qt Quick, volgens de omarchy-app agent skill, en de compiler en Qt-onderdelen die ze nodig hebben, worden meegeleverd. Claude Code, Codex, Grok, Kimi, Cursor en zijn Grok Bot-tegoed, GitHub Copilot, Muse, Antigravity, Kimchi en Devin worden out of the box ondersteund met hun limieten, en Hermes, Mistral Vibe en Qwen Code tonen hun sessies en tokens zodra je ze hebt gebruikt. Providerabonnementen en -sleutels die je via pi, omp of opencode gebruikt, verschijnen ook: OpenCode Zen en Go, het Z.ai GLM Coding Plan, Ollama Cloud, het MiniMax Token Plan en Synthetic met hun limieten; Fireworks, OpenRouter en DeepSeek met hun prepaid saldi; en de modellen die je op je eigen hardware draait onder Lokale modellen. Elke agent wordt één keer geteld, onder wie hem ook factureert, via hoeveel harnesses je hem ook aanstuurt.

Klik met links op het balkpictogram voor het paneel, klik met rechts om je standaardagent te starten. De gebruiksgegevens erachter worden elke 15 minuten opnieuw gegenereerd door `omarchy agent usage-update`, en het paneel kan zelfs gebruik van je andere machines samenvoegen via een gesynchroniseerde map. Zie de README onder `$OMARCHY_PATH/shell/plugins/agents/` voor de volledige instellingen.

### Meerdere abonnementen

Als je betaalt voor meer dan één Claude-, Codex- of Grok-abonnement — bijvoorbeeld een persoonlijke Max en een voor je werk — kan Omarchy ze allemaal ingelogd houden en ertussen schakelen. Voeg een abonnement toe met de + in het agentspaneel, dat je er daar meteen doorheen leidt, of met `omarchy agent account add claude Work` (of `codex`, of `grok`). Het installeert de CLI als die ontbreekt. Het eerste account voor een provider logt in via je normale browser, precies waar de CLI altijd kijkt. Elk daarna logt in via een privévenster, zodat het account waarop je browser al is ingelogd niet per ongeluk wordt opgepikt; log daar in als het account dat je toevoegt, en sluit eerst elk privévenster dat je al open had. Log hiervoor nooit uit bij de CLI: uitloggen trekt de opgeslagen aanmelding in, en dat account zou opnieuw moeten worden toegevoegd.

Om je abonnementslogins via SSH naar een andere Omarchy-machine te kopiëren, voer je `omarchy agent account copy user@laptop` uit. De afzender levert een tijdelijke ontvanger wanneer de bestemming er geen geïnstalleerd heeft, zodat oudere Omarchy-machines accounts kunnen ontvangen zonder update. Geïnstalleerde ontvangers hebben voorrang. Dit kopieert alle Claude-, Codex- en Grok-abonnementen; voeg providernamen toe om ze te selecteren, zoals in `omarchy agent account copy laptop claude`. Accountnamen en commando-ID's komen overeen met de bron, inclusief accounts die al op de bestemming aanwezig zijn. Niet-gerelateerde bestemmingsaccounts krijgen een numeriek achtervoegsel als hun namen conflicteren, en instellingen, skills, plugins en gespreksgeschiedenis blijven lokaal op elke machine.

Bestaande inloggegevens op de bestemming blijven bewaard. Van een bronaccount dat daar al is ingelogd, wordt de naam gesynchroniseerd zonder de inloggegevens te vervangen; andere accounts worden ernaast toegevoegd. Om opgeslagen inloggegevens voor overeenkomende accounts te vervangen, gebruik je `omarchy agent account copy --replace laptop claude` nadat je de sessies van dat account op de bestemming hebt afgesloten. Een verse bestemming krijgt ook het actieve account en de schakelvoorkeuren van de bron; een gevestigde bestemming behoudt zijn eigen.

Inloggegevens reizen via SSH en worden opgeslagen in privébestanden op de bestemming, dus kopieer alleen naar machines die je vertrouwt. Dit is een eenmalige kopie, geen doorlopende synchronisatie. Codex-verversingstokens kunnen door een andere machine worden geroteerd, waardoor een gekopieerde login vernieuwing nodig heeft; aparte aanmeldingen blijven de betrouwbaarste keuze voor gelijktijdig gebruik op meerdere machines. Zie [de handleiding voor accountauthenticatie van Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Eén account per provider is actief, en elke nieuwe sessie start als dat account: `cx`, `cy`, een gewone `claude`, `codex` of `grok`, alles wat via `omarchy agent` wordt gestart, en scripts of editors die de CLI op `PATH` vinden. Schakel met `omarchy agent account use work` (en terug met `omarchy agent account use main`), of in het paneel door op het nummer van een account te drukken en daarna op `Enter` (of door op de knop Use ervan te klikken). Sessies die al draaien, blijven op het account waarmee ze zijn gestart. Gespreksgeschiedenis, instellingen, skills en plugins worden gedeeld tussen accounts, dus `claude --continue` in dezelfde map gaat verder waar je was gebleven op het nieuwe account.

Met meer dan één account toont het paneel de limieten van elk account naast elkaar, met het actieve account gemarkeerd. Standaard meldt Omarchy je wanneer het actieve account 95% van een limiet overschrijdt, en klikken op de melding schakelt naar het account met de meeste ruimte. Beweeg over de regel van een account in het paneel en klik op Autoswitch die naast Use verschijnt (of druk op `m`), of voer `omarchy agent account mode auto` uit, om het in plaats daarvan vanzelf te laten schakelen; terwijl het aan staat, neemt Autoswitch de plaats van Use in, en er opnieuw op klikken gaat terug naar melden. Voeg een getal toe om de drempel te wijzigen, zoals in `omarchy agent account mode auto 90`. Als elk account boven de drempel zit, hoor je dat één keer, samen met welk account als eerste vrijkomt. Terwijl een actief account binnen 15 punten van zijn drempel zit (80% bij de standaard), worden zijn limieten elke drie minuten gecontroleerd in plaats van elke 15.

`omarchy agent account list` toont elk account en zijn nieuwste limieten, `omarchy agent account remove work` vergeet er een, en `omarchy agent account rename primary Hey` hernoemt er een (of klik op de naam van een account in het paneel). Deze commando's werken op de accounts van je standaardagent; om de andere provider te bereiken, noem je die eerst, zoals in `omarchy agent account use codex side`. De login die je al had in `~/.claude` of `~/.codex` is het _Main_-account en blijft waar hij is. Een account dat meer dan ongeveer acht uur ongebruikt is gelaten, kan _Sign-in required_ tonen; klik erop om dat account meteen in het paneel opnieuw aan te melden, of start een sessie erin, wat de aanmelding vanzelf ververst. MCP-servers die je had toen een account werd toegevoegd, komen mee naar dat account, maar servers die je later toevoegt met `claude mcp add` bereiken alleen het account waarin je ze hebt toegevoegd. Claude Desktop en tools die zijn geconfigureerd met een absoluut pad naar een CLI-binary volgen de schakeling niet. Een expliciete `CLAUDE_CONFIG_DIR`, `CODEX_HOME` of `GROK_HOME` heeft voorrang op het geselecteerde account.

### Crashdiagnose

Omarchy houdt systemd-coredump in de gaten voor procescrashes. Wanneer iets segfault, krijg je een melding "Process crashed" — klik erop, en de crash wordt overgedragen aan je standaardagent samen met de diagnose-crash skill van Omarchy, die de agent begeleidt bij het vaststellen van de feiten uit de core dump en het beslissen of de crash het waard is om upstream te melden. Je kunt het ook met de hand uitvoeren tegen elke PID uit `coredumpctl list` met `omarchy agent crash <pid>`.

Het in de gaten houden staat standaard aan. Schakel het uit onder _Trigger > Toggle > Crash Capture_ (of met `omarchy toggle crash-capture`) en de meldingen stoppen; `omarchy agent crash <pid>` werkt nog steeds met de hand.

Crashes kunnen ook per programma worden gedempt, wat de diagnose je aan het einde aanbiedt. `omarchy crash mute hyprland` stopt de meldingen alleen voor dat programma, `omarchy crash mute hyprland off` brengt ze terug, en `omarchy crash mute` op zichzelf somt op wat je hebt gedempt. Het accepteert het pad van de binary net zo graag als zijn naam, dus `omarchy crash mute /usr/bin/hyprland` doet hetzelfde. Zet een naam met een spatie erin tussen aanhalingstekens, zoals in `omarchy crash mute 'Some App'`. Al het andere meldt nog steeds, en het gedempte programma crasht nog steeds — dit verbergt de herinnering, het repareert niets.

### Desktop-apps

Het menu _Install > AI_ bevat ook een paar grafische AI-apps: de ChatGPT-desktopapp, de Claude-desktopapp (de Linux-bèta van Anthropic, met tabbladen Chat, Cowork en Claude Code), Grok Bot om te chatten met de modellen van xAI, Herdr Desktop, Hermes Desktop, OpenClaw, de Perplexity-desktopapp en T3 Code. Grok Bot is de desktopchatapp. De codeeragent is het `grok`-commando.

Hermes Desktop is degene die je moet kennen, omdat een machine één Hermes heeft, en die is van de app: Hermes wordt alleen ooit via de app geïnstalleerd, en het `hermes`-commando dat de standaardagent draait is dat van de app. Hermes als standaardagent kiezen installeert hetzelfde als de vermelding _Install > AI_ doet: het pakket, en een Hermes-runtime onder `~/.hermes` ingesteld door Hermes' eigen installer, wat de eerste keer een paar minuten duurt. Die runtime is de ene Hermes die het terminalcommando `hermes`, de standaardagent en de app allemaal gebruiken, en hij werkt zichzelf bij met `hermes update` in plaats van te wachten op een Omarchy-release. Installeren ervan geeft Hermes ook het Omarchy-thema als een skin met de naam `omarchy`, die elk Hermes-oppervlak volgt terwijl je van thema wisselt; kies een andere onder de Appearance-instellingen van Hermes of met `/skin` als je liever niet wilt dat hij dat doet, en Omarchy laat die keuze met rust. De app verwijderen onder _Remove > AI_ sluit Hermes eerst, gateway inbegrepen, neemt die runtime mee, en bewaart je chats, herinneringen en de skills die Hermes voor zichzelf heeft geschreven, tenzij je anders aangeeft: het vraagt, met nee als standaard, of die gegevens en je verbindingsinstellingen ook moeten verdwijnen.

De desktopervaring van OpenClaw is zijn Control UI, die opent als een webapp ondersteund door zijn eigen lokale gateway. OpenClaw leeft in `~/.openclaw` en werkt zichzelf bij: gebruik de knop "Update Gateway" van de Control UI of voer `openclaw update` uit, en de gateway herstart op de nieuwe versie. Omarchy kiest alleen de release waarmee een verse installatie start. OpenClaw verwijderen onder _Remove > AI_ neemt de gatewayservice en de app mee en vraagt vervolgens of `~/.openclaw` ook moet verdwijnen, aangezien dat je chats en inloggegevens bewaart naast OpenClaw zelf en de pluginruntimes die het downloadt; de standaard bewaart het, en OpenClaw opnieuw installeren pikt het weer op.

Herdr Desktop is de desktopapp van [Herdr](https://herdr.dev): ruimtes, tabbladen en panelen met terminals en codeeragents die in zijn kern blijven draaien wanneer je het venster sluit. Het komt van Herdr's eigen installer in plaats van een pakket, dus het leeft in `~/.local/share/herdr-app`, brengt zijn kern mee in `~/.local/bin/herdr-core` wanneer je er nog geen hebt, en werkt beide zelf bij. Het zit naast het `herdr`-commando dat Omarchy meelevert op `Super + Ctrl + Return` in plaats van het te vervangen, en krijgt de directe toetsen van dat commando: `Alt + Return` en `Alt + Shift + Return` splitsen een paneel naar beneden of naar rechts, `Alt + Escape` sluit het, `Ctrl + Alt + Arrow` beweegt tussen panelen, `Alt + 1..9` en `Alt + Left/Right` kiezen een tabblad, en `Alt + Up/Down` bewegen tussen ruimtes. `Ctrl + 1..9` kiest een ruimte en `Alt + Shift + Up/Down` stapt door agents. De prefixtoetsen `Ctrl + Space` blijven alleen voor de terminal, aangezien de app geen gewone Ctrl-toets kan vasthouden voor een reeks. Omarchy schrijft deze naar `~/.config/herdr-app/keys.json`, en `omarchy-refresh-herdr-app` zet ze terug. Installeren ervan kiest het Omarchy-thema van Herdr, dat vanaf dan je Omarchy-thema volgt. Herdr bewaart één thema voor de lichte modus en één voor donker, dus kies na het schakelen tussen een donker en een licht Omarchy-thema nog een keer Omarchy in de themakiezer van Herdr voor de andere modus.

T3 Code draait vanaf zijn officiële AppImage-release in `~/.local/share/t3code` in plaats van vanaf een pakket, dus werkt hij zichzelf bij. Installeren ervan vraagt of je wilt starten op het Stable- of Nightly-kanaal; schakel later in de instellingen van T3 Code. Je threads en instellingen leven in `~/.t3`, en T3 Code verwijderen onder _Remove > AI_ neemt ze mee.

### Lokale modellen

Draai een open model op je eigen machine voor je codeeragents. Je prompts en code blijven op de machine; niets dat naar het model wordt gestuurd, verlaat haar. Begin met:

```bash
omarchy agent local use best
```

Of, in het agentspaneel in de bovenste balk, kies + en vervolgens Local AI, wat verschijnt wanneer een model op deze machine past. De eerste keer installeert dit Podman, dat de modellen draait, en op een NVIDIA-machine de containertoolkit van NVIDIA, die ze de GPU geeft. Omarchy kiest vervolgens het aanbevolen model voor deze machine, downloadt het en start het. Verwacht een download van tientallen GB en dat het meeste geheugen van de machine in gebruik is terwijl het model draait: Flash Next gebruikt ongeveer 100 GiB met zijn volledige context van 256K. Als andere modellen het geheugen bezet houden dat het nodig heeft, wordt het gestopt ingesteld, klaar om te starten zodra je er een stopt. Het model stopt bij uitloggen; stop het zelf wanneer je het geheugen voor iets anders nodig hebt.

`omarchy agent local list` toont de opties en legt uit waarom sommige niet passen. Om een andere in te stellen, voer je `omarchy agent local use <recipe>` uit. Vandaag zijn `qwen3.8-flash-next-gufo` en `qwen3.8-27b-gufo` beschikbaar voor Strix Halo-machines met 128 GB; de 27B neemt ongeveer 40 GiB, dus laat hij ruimte voor ander werk. Nieuwe recepten en aanbevelingen komen met `omarchy update`, via het pakket.

Elk model dat je instelt, krijgt zijn eigen regel in het agentspaneel, naast je abonnementen: afspelen om het te starten, pauzeren om het te stoppen en zijn geheugen vrij te maken, en de terminalknop om je agent erop te openen. Meerdere kunnen tegelijk draaien wanneer ze samen in het geheugen passen; als er een niet past, zegt Omarchy welk draaiend model je moet stoppen. Sleep regels om ze opnieuw te ordenen, en druk op Delete op een geselecteerde regel om een model en zijn download te verwijderen.

Vanaf de commandoregel doen `omarchy agent local start <recipe>` en `omarchy agent local stop <recipe>` hetzelfde, `omarchy agent local status` toont elk model, en `omarchy agent --local` opent je standaardagent op het laatste model dat je hebt gestart (pi als je standaardagent geen lokaal model kan gebruiken). Elke met OpenAI compatibele client kan ook verbinden: `status` toont het adres van elk model (het eerste is `http://127.0.0.1:11435/v1`), de receptnaam is het model, en de sleutel staat in `~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` verwijdert een model en de downloads die geen ander model gebruikt.

Runtimes van derden zijn gelabeld met hun uitgever. Omarchy draait elk model zonder netwerktoegang.

### Lokale LLM's

Omarchy raadt twee manieren aan om lokale LLM-modellen te draaien: LM Studio en Ollama. LM Studio biedt een GUI-interface voor het vinden van open-weight modellen, het installeren ervan en het draaien ervan. Het is een geweldige manier om gemakkelijk aan de slag te gaan. Ollama biedt een CLI om dat op vergelijkbare wijze te doen. Maar als je nieuw bent met lokale modellen, zou ik beginnen met LM Studio. Je kunt beide installeren onder _Install > AI_ in het Omarchy Menu.

### De Omarchy Skill

Agent skills helpen AI om specifieke tools op een specifieke manier te gebruiken, en Omarchy wordt geleverd met een standaard skill voor het op maat aanpassen van het systeem. Zoals je Hyprland-config aanpassen, de balk bijstellen, of zelfs een nieuw thema vanaf nul creëren. Het is gesymlinkt naar de skillmappen voor Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` en elke `~/.hermes/profiles/*/skills`), en de generieke locatie `~/.agents/skills`, dus de meeste harnesses pikken het automatisch op.

Maar je moet deze skill als experimenteel beschouwen. Verschillende modellen zullen hem met verschillend effect gebruiken. Het is het beste om eerst in planmodus te draaien, zodat je een idee hebt van wat de agent zou willen veranderen. En wees er dan op voorbereid wijzigingen terug te draaien of zelfs `omarchy reinstall configs` aan te roepen, als de agent er een puinhoop van maakt.
