# AI

Omarchy bevat launchers voor de onderstaande coding agents zonder een standaard voor je te kiezen. Voer een opdracht uit om de CLI ervan te installeren bij het eerste gebruik, en meld je daarna aan wanneer daarom wordt gevraagd. Hermes is de uitzondering: daarvoor wordt bij het eerste gebruik niets geïnstalleerd, en als je ervoor kiest, wordt Hermes Desktop geïnstalleerd, zoals _Desktop-apps_ hieronder uitlegt.

### Agents installeren en bijwerken

Behalve Hermes gebruiken deze agents de lazy installation van mise: de eerste start installeert de CLI, en latere starts hergebruiken die. mise controleert een geïnstalleerde agent ook hoogstens eens per vier uur op een nieuwe release, vlak voordat hij start of op de achtergrond bij een shell-prompt. Als die update mislukt of je offline bent, draait de geïnstalleerde versie. `omarchy update` werkt geïnstalleerde agents bij samen met de rest van Omarchy, en `mup` werkt alleen door mise beheerde tools bij.

De eigen updater van een agent, zoals `claude update`, `codex update` of een updateknop in een app, werkt de door mise beheerde installatie niet bij. `codex update` mislukt, en `claude update` kan succes melden terwijl het een aparte kopie installeert die mise niet bijhoudt. Als je liever de native installer en updater van een agent gebruikt, voeg hem dan toe aan `disable_tools`; zie [Vooraf geïnstalleerde CLI-tools](18-development-tools.md#preinstalled-cli-tools).

Om alle geconfigureerde lazy tools te installeren voordat je ze nodig hebt, voer je `mise install --include-lazy` uit. Dit omvat zowel de andere standaard CLI-tools van Omarchy als de agents. Zie [Vooraf geïnstalleerde CLI-tools](18-development-tools.md#preinstalled-cli-tools) voor het installeren van één tool of het gebruiken van je eigen installatie.

`grok` wordt geïnstalleerd via het first-party `grok`-pakket van mise, op dezelfde manier als `claude` en `codex`. Voer `grok` uit, of kies het onder _Setup > Defaults > Agent_. Sla de `curl | bash`-installer op x.ai over. Dat pad plaatst een tweede kopie in `~/.grok/bin`, zet die vooraan op `PATH` en overschrijft de wrapper van Omarchy.

`dsh` opent zijn browser-UI op `127.0.0.1:3080`, met de startmap als standaard werkruimte. De browser-UI accepteert geen startprompt, dus `omarchy agent prompt` opent hem met de prompt op je klembord om te plakken. Omarchy start hem met de no-approval-permissiepreset van DeepSeek. DeepSeek Harness uploadt sessielogs naar DeepSeek wanneer je zijn officiële model-API gebruikt; schakel dat uit onder _Settings > General > Upload Session Log_ in zijn browser-UI. Feedback die je stuurt, wordt ook met de sessie geüpload, tenzij je hem start met `DSH_TELEMETRY_MODE=DISABLED`.

### De standaardagent

Kies je standaardagent met `omarchy default agent <name>` of onder _Setup > Defaults > Agent_ in het Omarchy Menu (`Super + Space`). Als de agent nog niet is geïnstalleerd, installeert het kiezen ervan hem eerst. Een verse Omarchy nodigt je met een eenmalige melding uit om deze keuze te maken.

Claude kiezen probeert ook zijn browserextensie in te stellen voor Chromium, Chrome, Brave, Brave Origin en Edge. De extensie-installatie geldt voor alle gebruikers en kan om je systeemwachtwoord vragen; annuleren of een mislukte extensie-installatie selecteert en start Claude nog steeds. Herstart je browser, schakel de extensie in als daarom wordt gevraagd en meld je aan bij Claude om de verbinding te voltooien. Voer `/chrome` uit in Claude om de verbinding te controleren. Firefox en Zen ondersteunen deze extensie niet. Als Claude al je standaard was voordat deze installatie werd toegevoegd, selecteer hem dan opnieuw om de extensie te installeren.

Zodra je hebt gekozen, start `Super + Shift + Ctrl + A` de standaardagent in een apart terminalvenster (of opent de kiezer als je nog niet hebt gekozen). Je kunt hem ook direct aan een taak zetten met `omarchy agent prompt "Review this project"`. Freebuff en DeepSeek Harness accepteren geen startprompt, dus die openen in plaats daarvan met de prompt op je klembord om te plakken. Agents die op deze manier worden gestart, draaien zonder toezicht in hun respectieve don't-stop-to-ask-modi, dus wees erop voorbereid dat ze daadwerkelijk dingen gaan doen! MiniMax Code heeft geen dergelijke modus voor zijn interactieve sessies, dus die vraagt zoals gebruikelijk om toestemmingen. En omdat agents weigeren vertrouwen te onthouden voor je thuismap, starten launches vanuit `$HOME` in plaats daarvan in `~/Work`.

Er zijn ook terminal-snelkoppelingen: `a` draait de standaardagent inline in de huidige terminal, terwijl `c`, `cx` en `cy` OpenCode, Claude Code en Codex direct starten (ook weer in hun auto-approving modi). Themaveranderingen synchroniseren ook naar de agents: Claude Code, Pi, OpenCode en Hermes (zodra Omarchy hem heeft geïnstalleerd) volgen allemaal mee wanneer je het Omarchy-thema wisselt.

### Het agentenpaneel

De bovenbalk heeft een agentenpictogram. Voordat je een agent hebt ingesteld, leidt zijn paneel je door het aanmelden bij Claude, Codex of Grok, en de eerste wordt je standaardagent. Daarna zet het paneel elk abonnement op één pagina: elke agent en account met zijn plan, een meter voor elk van zijn 5-uurs sessie- en weeklimieten met de tijd tot hij reset (beweeg erover voor het exacte percentage), of het resterende prepaid-saldo, onder een regel die rouleert door wat je over al die agents heen hebt gebruikt, zoals tokens deze week en je meest gebruikte model. Onder _Make something_ biedt het starterprompts voor een nieuw thema, plugin of app die de taak overhandigen aan je standaardagent. Apps worden gebouwd op de manier waarop Omarchy's eigen Hype, Monologue en Omacut dat zijn, in C++ en Qt Quick, volgens de omarchy-app agent skill, en de compiler en Qt-onderdelen die ze nodig hebben, worden meegeleverd geïnstalleerd. Claude Code, Codex, Grok, Kimi, Cursor en zijn Grok Bot-tegoed, GitHub Copilot, Muse, Antigravity, Kimchi en Devin worden out of the box gedekt met hun limieten, en Hermes, Mistral Vibe en Qwen Code tonen hun sessies en tokens zodra je ze hebt gebruikt. Providerplannen en sleutels die je via pi, omp of opencode gebruikt, verschijnen ook: OpenCode Zen en Go, het Z.ai GLM Coding Plan, Ollama Cloud, het MiniMax Token Plan en Synthetic met hun limieten; Fireworks, OpenRouter en DeepSeek met hun prepaid-saldi; en de modellen die je op je eigen hardware draait onder Local models. Elke agent wordt één keer geteld, onder wie hem ook factureert, ongeacht via hoeveel harnesses je hem aanstuurt.

Klik met links op het balkpictogram voor het paneel, klik met rechts om je standaardagent te starten. De gebruiksrecords erachter worden elke 15 minuten opnieuw gegenereerd door `omarchy agent usage-update`, en het paneel kan zelfs gebruik van je andere machines samenvoegen via een gesynchroniseerde map. Zie de README onder `$OMARCHY_PATH/shell/plugins/agents/` voor de volledige instellingen.

### Meerdere abonnementen

Als je betaalt voor meer dan één Claude-, Codex- of Grok-plan — bijvoorbeeld een persoonlijke Max en een werkplan — kan Omarchy ze allemaal aangemeld houden en tussen ze wisselen. Voeg een abonnement toe met de + in het agentenpaneel, dat je er daar meteen doorheen leidt, of met `omarchy agent account add claude Work` (of `codex`, of `grok`). Het installeert de CLI als die ontbreekt. Het eerste account voor een provider meldt zich aan via je normale browser, precies waar de CLI altijd kijkt. Elk account daarna meldt zich aan via een privévenster, zodat het account waarbij je browser al is aangemeld niet per ongeluk wordt opgepikt; meld je daar aan als het account dat je toevoegt, en sluit eerst elk privévenster dat je al open had. Log hiervoor nooit uit bij de CLI: uitloggen trekt de opgeslagen aanmelding in, en dat account zou opnieuw moeten worden toegevoegd.

Om je abonnementslogins via SSH naar een andere Omarchy-machine te kopiëren, voer je `omarchy agent account copy user@laptop` uit. De verzender levert een tijdelijke ontvanger wanneer de bestemming er geen geïnstalleerd heeft, zodat oudere Omarchy-machines accounts kunnen ontvangen zonder een update. Geïnstalleerde ontvangers hebben voorrang. Dit kopieert alle Claude-, Codex- en Grok-abonnementen; voeg providernamen toe om ze te selecteren, zoals in `omarchy agent account copy laptop claude`. Accountnamen en opdracht-ID's komen overeen met de bron, inclusief accounts die al op de bestemming aanwezig zijn. Niet-gerelateerde bestemmingsaccounts krijgen een numeriek achtervoegsel als hun namen conflicteren, en instellingen, skills, plugins en gespreksgeschiedenis blijven lokaal op elke machine.

Bestaande bestemmingsgegevens blijven behouden. Van een bronaccount dat daar al is aangemeld, wordt de naam gesynchroniseerd zonder zijn gegevens te vervangen; andere accounts worden ernaast toegevoegd. Om opgeslagen gegevens voor overeenkomende accounts te vervangen, gebruik je `omarchy agent account copy --replace laptop claude` nadat je de sessies van dat account op de bestemming hebt afgesloten. Een verse bestemming krijgt ook het actieve account en de wisselvoorkeuren van de bron; een gevestigde bestemming behoudt haar eigen.

Gegevens reizen via SSH en worden opgeslagen in privébestanden op de bestemming, dus kopieer alleen naar machines die je vertrouwt. Dit is een eenmalige kopie, geen doorlopende synchronisatie. Codex refresh tokens kunnen door een andere machine worden geroteerd, waardoor een gekopieerde login vernieuwing nodig heeft; aparte aanmeldingen blijven de betrouwbaarste keuze voor gelijktijdig gebruik op meerdere machines. Zie [Codex' handleiding voor accountauthenticatie](https://developers.openai.com/codex/auth/ci-cd-auth).

Eén account per provider is actief, en elke nieuwe sessie start als dat account: `cx`, `cy`, een gewone `claude`, `codex` of `grok`, alles wat via `omarchy agent` wordt gestart, en scripts of editors die de CLI op `PATH` vinden. Wissel met `omarchy agent account use work` (en terug met `omarchy agent account use main`), of in het paneel door op het nummer van een account en daarna op `Enter` te drukken (of op de Use-knop ervan te klikken). Sessies die al draaien, blijven op het account waarmee ze zijn gestart. Gespreksgeschiedenis, instellingen, skills en plugins worden gedeeld tussen accounts, dus `claude --continue` in dezelfde map gaat verder waar je was gebleven op het nieuwe account.

Met meer dan één account toont het paneel de limieten van elk account naast elkaar, met het actieve account gemarkeerd. Standaard meldt Omarchy het je wanneer het actieve account 95% van een limiet passeert, en klikken op de melding wisselt naar het account met de meeste ruimte. Beweeg over de regel van een account in het paneel en klik op de Autoswitch die naast Use verschijnt (of druk op `m`), of voer `omarchy agent account mode auto` uit, om hem in plaats daarvan zelf te laten wisselen; terwijl het aan staat, neemt Autoswitch de plaats van Use in, en er opnieuw op klikken gaat terug naar melden. Voeg een getal toe om de drempel te wijzigen, zoals in `omarchy agent account mode auto 90`. Als elk account boven de drempel zit, hoor je dat één keer, samen met welk account als eerste vrijkomt. Terwijl een actief account binnen 15 punten van zijn drempel zit (80% bij de standaard), worden zijn limieten elke drie minuten gecontroleerd in plaats van elke 15.

`omarchy agent account list` toont elk account en zijn nieuwste limieten, `omarchy agent account remove work` vergeet er een, en `omarchy agent account rename primary Hey` hernoemt er een (of klik op de naam van een account in het paneel). Deze opdrachten werken op de accounts van je standaardagent; om de andere provider te bereiken, noem je die eerst, zoals in `omarchy agent account use codex side`. De login die je al had in `~/.claude` of `~/.codex` is het _Main_-account en blijft waar hij is. Een account dat meer dan ongeveer acht uur ongebruikt is gebleven, kan _Sign-in required_ tonen; klik erop om dat account opnieuw aan te melden, direct in het paneel, of start er een sessie in, wat de aanmelding vanzelf vernieuwt. MCP-servers die je had toen een account werd toegevoegd, komen mee naar dat account, maar servers die je later toevoegt met `claude mcp add` bereiken alleen het account waarin je ze hebt toegevoegd. Claude Desktop en tools die zijn geconfigureerd met een absoluut pad naar een CLI-binary volgen de wissel niet. Een expliciete `CLAUDE_CONFIG_DIR`, `CODEX_HOME` of `GROK_HOME` heeft voorrang op het geselecteerde account.

### Crashdiagnose

Omarchy houdt systemd-coredump in de gaten voor procescrashes. Wanneer iets segfault, krijg je een melding "Process crashed" — klik erop, en de crash wordt overhandigd aan je standaardagent samen met de diagnose-crash skill van Omarchy, die de agent begeleidt bij het vaststellen van de feiten uit de core dump en het beslissen of de crash het waard is om upstream te melden. Je kunt het ook handmatig draaien tegen elke PID uit `coredumpctl list` met `omarchy agent crash <pid>`.

Het meekijken staat standaard aan. Schakel het uit onder _Trigger > Toggle > Crash Capture_ (of met `omarchy toggle crash-capture`) en de meldingen stoppen; `omarchy agent crash <pid>` werkt nog steeds handmatig.

Crashes kunnen ook één programma tegelijk worden stilgezet, wat de diagnose je aan het einde aanbiedt. `omarchy crash mute hyprland` stopt de meldingen alleen voor dat programma, `omarchy crash mute hyprland off` brengt ze terug, en `omarchy crash mute` op zichzelf somt op wat je hebt gedempt. Het accepteert het pad van de binary net zo graag als zijn naam, dus `omarchy crash mute /usr/bin/hyprland` doet hetzelfde. Zet een naam met een spatie erin tussen aanhalingstekens, zoals in `omarchy crash mute 'Some App'`. Al het andere geeft nog steeds meldingen, en het gedempte programma crasht nog steeds — dit verbergt de herinnering, het repareert niets.

### Desktop-apps

Het menu _Install > AI_ bevat ook een paar grafische AI-apps: de ChatGPT desktop-app, de Claude desktop-app (de Linux-bèta van Anthropic, met Chat-, Cowork- en Claude Code-tabbladen), Grok Bot om te chatten met de modellen van xAI, Hermes Desktop, OpenClaw, de Perplexity desktop-app en T3 Code. Grok Bot is de desktop-chatapp. De coding agent is de opdracht `grok`.

Hermes Desktop is degene die je moet kennen, omdat een machine één Hermes heeft, en die is van de app: Hermes wordt alleen ooit via de app geïnstalleerd, en de opdracht `hermes` die de standaardagent draait is die van de app. Hermes kiezen als standaardagent installeert hetzelfde als wat het item _Install > AI_ doet: het pakket, en een Hermes-runtime onder `~/.hermes` opgezet door Hermes' eigen installer, wat de eerste keer een paar minuten duurt. Die runtime is de ene Hermes die de terminalopdracht `hermes`, de standaardagent en de app allemaal gebruiken, en hij werkt zichzelf bij met `hermes update` in plaats van te wachten op een Omarchy-release. Installeren ervan geeft Hermes ook het Omarchy-thema als een skin genaamd `omarchy`, die elk Hermes-oppervlak volgt terwijl je van thema wisselt; kies een andere onder de Appearance-instellingen van Hermes of met `/skin` als je liever niet hebt dat hij dat doet, en Omarchy laat die keuze met rust. De app verwijderen onder _Remove > AI_ sluit Hermes eerst, inclusief de gateway, neemt die runtime mee, en behoudt je chats, herinneringen en de skills die Hermes voor zichzelf heeft geschreven, tenzij je anders aangeeft: het vraagt, met nee als standaard, of die gegevens en je verbindingsinstellingen ook weg moeten.

De desktopervaring van OpenClaw is zijn Control UI, die opent als een webapp ondersteund door zijn eigen lokale gateway. OpenClaw leeft in `~/.openclaw` en werkt zichzelf bij: gebruik de knop "Update Gateway" van de Control UI of voer `openclaw update` uit, en de gateway herstart op de nieuwe versie. Omarchy kiest alleen de release waarmee een verse installatie begint. OpenClaw verwijderen onder _Remove > AI_ neemt de gateway-service en de app mee en vraagt daarna of `~/.openclaw` ook weg moet, aangezien dat je chats en gegevens bewaart naast OpenClaw zelf en de plugin-runtimes die het downloadt; de standaard behoudt het, en OpenClaw opnieuw installeren pikt het weer op.

T3 Code draait vanaf zijn officiële AppImage-release in `~/.local/share/t3code` in plaats van vanaf een pakket, dus hij werkt zichzelf bij. Installeren ervan vraagt of je wilt starten op het Stable- of Nightly-kanaal; wissel later in de instellingen van T3 Code. Je threads en instellingen leven in `~/.t3`, en T3 Code verwijderen onder _Remove > AI_ neemt ze mee.

### Lokale modellen

Draai een open model op je eigen machine voor je coding agents. Je prompts en code blijven op de machine; niets dat naar het model wordt gestuurd, verlaat haar. Begin met:

```bash
omarchy agent local use best
```

Of kies in het agentenpaneel in de bovenbalk + en daarna Local AI, wat verschijnt wanneer een model op deze machine past. De eerste keer installeert dit Podman, dat de modellen draait, en op een NVIDIA-machine de container toolkit van NVIDIA, die ze de GPU geeft. Omarchy kiest daarna het aanbevolen model voor deze machine, downloadt het en start het. Verwacht een download van tientallen GB en dat het grootste deel van het geheugen van de machine in gebruik is terwijl het model draait: Flash Next gebruikt ongeveer 100 GiB met zijn volledige 256K-context. Als andere modellen het geheugen bezet houden dat het nodig heeft, wordt het gestopt opgezet, klaar om te starten zodra je er een stopt. Het model stopt bij uitloggen; stop het zelf wanneer je het geheugen voor iets anders nodig hebt.

`omarchy agent local list` toont de opties en legt uit waarom sommige niet passen. Om er een andere op te zetten, voer je `omarchy agent local use <recipe>` uit. Vandaag zijn `qwen3.8-flash-next-gufo` en `qwen3.8-27b-gufo` beschikbaar voor 128 GB Strix Halo-machines; de 27B neemt ongeveer 40 GiB, dus hij laat ruimte voor ander werk. Nieuwe recipes en aanbevelingen arriveren met `omarchy update`, via het pakket.

Elk model dat je opzet, krijgt zijn eigen regel in het agentenpaneel, naast je abonnementen: afspelen om hem te starten, pauzeren om hem te stoppen en zijn geheugen vrij te maken, en de terminalknop om je agent erop te openen. Meerdere kunnen tegelijk draaien wanneer ze samen in het geheugen passen; als er een niet past, zegt Omarchy welk draaiend model je moet stoppen. Versleep regels om ze opnieuw te ordenen, en druk op Delete op een geselecteerde regel om een model en zijn download te verwijderen.

Vanaf de opdrachtregel doen `omarchy agent local start <recipe>` en `omarchy agent local stop <recipe>` hetzelfde, `omarchy agent local status` toont elk model, en `omarchy agent --local` opent je standaardagent op het laatste model dat je hebt gestart (pi als je standaardagent geen lokaal model kan gebruiken). Elke OpenAI-compatibele client kan ook verbinding maken: `status` toont het adres van elk model (het eerste is `http://127.0.0.1:11435/v1`), de recipe-naam is het model, en de sleutel staat in `~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` verwijdert een model en de downloads die geen ander model gebruikt.

Runtimes van derden zijn gelabeld met hun uitgever. Omarchy draait elk model zonder netwerktoegang.

### Lokale LLM's

Omarchy raadt twee manieren aan om lokale LLM-modellen te draaien: LM Studio en Ollama. LM Studio biedt een GUI-interface voor het vinden van open-weight-modellen, het installeren ervan en het draaien ervan. Het is een geweldige manier om gemakkelijk aan de slag te gaan. Ollama biedt een CLI om dat op vergelijkbare wijze te doen. Maar als je nieuw bent met lokale modellen, zou ik met LM Studio beginnen. Je kunt beide installeren onder _Install > AI_ in het Omarchy Menu.

### De Omarchy Skill

Agent skills helpen AI om specifieke tools op een specifieke manier te gebruiken, en Omarchy wordt geleverd met een standaard skill voor het op maat maken van het systeem. Zoals het tweaken van je Hyprland-config, het aanpassen van de balk, of zelfs het vanaf nul creëren van een nieuw thema. Het is gesymlinkt in de skill-mappen voor Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` en elke `~/.hermes/profiles/*/skills`), en de generieke locatie `~/.agents/skills`, dus de meeste harnesses pikken het automatisch op.

Maar je moet deze skill als experimenteel beschouwen. Verschillende modellen zullen hem met verschillend effect gebruiken. Het is het beste om eerst in planmodus te draaien, zodat je een idee hebt van wat de agent zou willen veranderen. En wees daarna bereid om veranderingen terug te draaien of zelfs `omarchy reinstall configs` aan te roepen, als de agent er een puinhoop van maakt.
