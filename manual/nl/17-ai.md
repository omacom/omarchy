# AI

Omarchy bevat launchers voor de onderstaande codeeragents zonder een standaard voor je te kiezen. Voer een commando uit om de bijbehorende CLI bij het eerste gebruik te installeren en authenticeer vervolgens wanneer daarom wordt gevraagd. Hermes is de uitzondering: daarvoor wordt bij het eerste gebruik niets geïnstalleerd, en als je het kiest, wordt Hermes Desktop geïnstalleerd, zoals _Desktop apps_ hieronder uitlegt.

### Agents installeren en bijwerken

Met uitzondering van Hermes gebruiken deze agents de luie installatie van mise: de eerste start installeert de CLI en latere starts hergebruiken die. mise controleert een geïnstalleerde agent ook hoogstens eens per vier uur op een nieuwe release, vlak voordat hij start of op de achtergrond bij een shellprompt. Als die update mislukt of je offline bent, draait de geïnstalleerde versie. `omarchy update` werkt geïnstalleerde agents bij met de rest van Omarchy, en `mup` werkt alleen mise-beheerde tools bij.

De eigen updater van een agent, zoals `claude update`, `codex update` of een updateknop in een app, werkt de mise-beheerde installatie niet bij. `codex update` mislukt, en `claude update` kan succes melden terwijl het een aparte kopie installeert die mise niet volgt. Als je liever het eigen installatie- en updateprogramma van een agent gebruikt, voeg het dan toe aan `disable_tools`; zie [Vooraf geïnstalleerde CLI-tools](18-development-tools.md#preinstalled-cli-tools).

Om alle geconfigureerde luie tools te installeren voordat je ze nodig hebt, voer je `mise install --include-lazy` uit. Dit omvat ook de andere standaard-CLI-tools van Omarchy, net als de agents. Zie [Vooraf geïnstalleerde CLI-tools](18-development-tools.md#preinstalled-cli-tools) voor het installeren van één enkele tool of het gebruiken van je eigen installatie.

`grok` wordt geïnstalleerd via het first-party `grok`-pakket van mise, op dezelfde manier als `claude` en `codex`. Voer `grok` uit, of kies het onder _Agent > Harness_. Sla het `curl | bash`-installatieprogramma op x.ai over. Dat pad plaatst een tweede kopie in `~/.grok/bin`, zet die vooraan op `PATH` en overschrijft de wrapper van Omarchy.

`dsh` opent zijn browser-UI op `127.0.0.1:3080`, met de startmap als standaardwerkruimte. De browser-UI neemt geen startprompt aan, dus `omarchy agent prompt` opent het met de prompt op je klembord om te plakken. Omarchy start het met de no-approval-toestemmingspreset van DeepSeek. DeepSeek Harness uploadt sessielogs naar DeepSeek wanneer je zijn officiële model-API gebruikt; zet dat uit onder _Settings > General > Upload Session Log_ in zijn browser-UI. Feedback die je het stuurt, wordt ook met de sessie geüpload, tenzij je het start met `DSH_TELEMETRY_MODE=DISABLED`.

### De standaardagent

Kies je standaardagent met `omarchy default agent <name>` of onder _Agent > Harness_ in het Omarchy Menu (`Super + Space`). Als de agent nog niet is geïnstalleerd, installeert het kiezen ervan hem eerst. Een verse Omarchy nodigt je met een eenmalige melding uit om deze keuze te maken.

Het kiezen van Claude probeert ook zijn browserextensie in te stellen voor Chromium, Chrome, Brave, Brave Origin en Edge. De extensie-installatie geldt voor alle gebruikers en kan om je systeemwachtwoord vragen; annuleren of een mislukte extensie-installatie selecteert en start Claude nog steeds. Herstart je browser, schakel de extensie in als daarom wordt gevraagd en log in bij Claude om de verbinding te voltooien. Voer `/chrome` uit in Claude om de verbinding te controleren. Firefox en Zen ondersteunen deze extensie niet. Als Claude al je standaard was voordat deze installatie werd toegevoegd, selecteer het dan opnieuw om de extensie te installeren.

Zodra je hebt gekozen, start `Super + Shift + Ctrl + A` de standaardagent in een apart terminalvenster (of opent de kiezer als je nog niet hebt gekozen). Je kunt hem ook rechtstreeks met een taak starten met `omarchy agent prompt "Review this project"`. Freebuff en DeepSeek Harness nemen geen startprompt aan, dus zij openen in plaats daarvan met de prompt op je klembord om te plakken. Agents die op deze manier worden gestart, draaien onbeheerd in hun respectieve don't-stop-to-ask-modi, dus wees erop voorbereid dat ze daadwerkelijk dingen gaan doen! MiniMax Code heeft geen dergelijke modus voor zijn interactieve sessies, dus het vraagt zoals gebruikelijk om toestemmingen. En omdat agents weigeren vertrouwen voor je thuismap te onthouden, starten launches vanuit `$HOME` in plaats daarvan in `~/Work`.

Er zijn ook terminalsnelkoppelingen: `a` draait de standaardagent inline in de huidige terminal, terwijl `c`, `cx` en `cy` OpenCode, Claude Code en Codex rechtstreeks starten (ook weer in hun automatisch goedkeurende modi). Themawijzigingen synchroniseren ook naar de agents: Claude Code, Pi, OpenCode en Hermes (zodra Omarchy het heeft geïnstalleerd) volgen allemaal mee wanneer je het Omarchy-thema wisselt.

### Je agentinstructies

Persoonlijke regels voor elke agent staan in `~/.agents/AGENTS.md`, naast de gedeelde skills in `~/.agents/skills`. Open het onder _Agent > Instructions_, wat het ook koppelt aan elke harness die zijn eigen globale bestand bijhoudt: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` van Copilot, enzovoort. Crush en Amp lezen de koppeling `~/.config/AGENTS.md`, terwijl omp, Kimi en DeepSeek Harness `~/.agents/AGENTS.md` rechtstreeks lezen. Het kiezen van een standaardagent koppelt het ook. Een instructiebestand dat je al had, wordt het gedeelde bestand als er nog geen was; anders wordt het naast de koppeling bewaard als `.bak`. Voer `omarchy agent instructions` uit om opnieuw te koppelen na het installeren van een andere agent.

### Het agents-paneel

De bovenste balk heeft een agents-pictogram. Voordat je een agent hebt ingesteld, leidt het paneel je door het inloggen bij Claude, Codex of Grok, en de eerste wordt je standaardagent. Daarna zet het paneel elk abonnement op één pagina: elke agent en elk account met zijn plan, een meter voor elk van zijn 5-uurs sessie- en wekelijkse limieten met de tijd tot hij reset (beweeg erover voor het exacte percentage), of het resterende vooruitbetaalde saldo, onder een regel die roteert door wat je over al die agents hebt gebruikt, zoals tokens deze week en je meest gebruikte model. Onder _Make something_ biedt het starterprompts voor een nieuw thema, plugin, app of game die de taak overdragen aan je standaardagent. Apps worden gebouwd zoals Omarchy's eigen Hype, Monologue en Omacut, in C++ en Qt Quick, volgens de omarchy-make-app agent skill, en de compiler en Qt-stukken die ze nodig hebben, komen meegeïnstalleerd. Games zijn een enkele three.js-pagina in `~/Games/vibes`, volgens de omarchy-make-game agent skill, en openen allemaal vanuit één Game Vibes-launcher in het huidige thema; ze laden three.js van het web, dus ze hebben een verbinding nodig om te starten. Claude Code, Codex, Grok, Kimi, Cursor en zijn Grok Bot-toelage, GitHub Copilot, Muse, Antigravity, Kimchi en Devin worden standaard gedekt met hun limieten, en Hermes, Mistral Vibe en Qwen Code tonen hun sessies en tokens zodra je ze hebt gebruikt. Providerplannen en sleutels die je via pi, omp of opencode gebruikt, verschijnen ook: OpenCode Zen en Go, het Z.ai GLM Coding Plan, Ollama Cloud, het MiniMax Token Plan en Synthetic met hun limieten; Fireworks, OpenRouter en DeepSeek met hun vooruitbetaalde saldi; en de modellen die je op je eigen hardware draait onder Local models. Elke agent wordt één keer geteld, onder wie hem ook factureert, via hoeveel harnesses je hem ook aanstuurt.

Klik met links op het balkpictogram voor het paneel, klik met rechts om je standaardagent te starten. De gebruiksgegevens erachter worden elke 15 minuten opnieuw gegenereerd door `omarchy agent usage-update`, en het paneel kan zelfs gebruik van je andere machines samenvoegen via een gesynchroniseerde map. Zie de README onder `$OMARCHY_PATH/shell/plugins/agents/` voor de volledige instellingen.

### Meerdere abonnementen

Als je voor meer dan één Claude-, Codex- of Grok-plan betaalt — bijvoorbeeld een persoonlijk Max en een werkplan — kan Omarchy ze allemaal ingelogd houden en ertussen wisselen. Voeg een abonnement toe met de + in het agents-paneel, dat je er daar meteen doorheen leidt, of met `omarchy agent account add claude Work` (of `codex`, of `grok`). Het installeert de CLI als die ontbreekt. Het eerste account voor een provider logt in via je normale browser, precies waar de CLI altijd kijkt. Elk volgend account logt in via een privévenster, zodat het account waar je browser al mee is ingelogd niet per ongeluk wordt opgepikt; log daar in als het account dat je toevoegt, en sluit eerst elk privévenster dat je al open had. Log nooit uit uit de CLI om dit te doen: uitloggen trekt de opgeslagen login in, en dat account zou opnieuw moeten worden toegevoegd.

Om je abonnementslogins via SSH naar een andere Omarchy-machine te kopiëren, voer je `omarchy agent account copy user@laptop` uit. De verzender levert een tijdelijke ontvanger wanneer de bestemming er geen heeft geïnstalleerd, zodat oudere Omarchy-machines accounts kunnen ontvangen zonder een update. Geïnstalleerde ontvangers hebben voorrang. Dit kopieert alle Claude-, Codex- en Grok-abonnementen; voeg providernamen toe om ze te selecteren, zoals in `omarchy agent account copy laptop claude`. Accountnamen en commando-ID's komen overeen met de bron, inclusief accounts die al op de bestemming aanwezig zijn. Niet-gerelateerde bestemmingsaccounts krijgen een numeriek achtervoegsel als hun namen conflicteren, en instellingen, skills, plugins en gespreksgeschiedenis blijven lokaal op elke machine.

Bestaande bestemmingsgegevens worden bewaard. Een bronaccount dat daar al is ingelogd, krijgt zijn naam gesynchroniseerd zonder zijn gegevens te vervangen; andere accounts worden ernaast toegevoegd. Om opgeslagen gegevens voor overeenkomende accounts te vervangen, gebruik je `omarchy agent account copy --replace laptop claude` nadat je de sessies van dat account op de bestemming hebt afgesloten. Een verse bestemming krijgt ook het actieve account en de wisselvoorkeuren van de bron; een gevestigde bestemming behoudt zijn eigen voorkeuren.

Gegevens reizen via SSH en worden opgeslagen in privébestanden op de bestemming, dus kopieer alleen naar machines die je vertrouwt. Dit is een eenmalige kopie, geen doorlopende synchronisatie. Codex-refresh-tokens kunnen door een andere machine worden geroteerd, waardoor een gekopieerde login vernieuwing nodig heeft; aparte logins blijven de betrouwbaarste keuze voor gelijktijdig gebruik op meerdere machines. Zie [Codex's richtlijnen voor accountauthenticatie](https://developers.openai.com/codex/auth/ci-cd-auth).

Eén account per provider is actief, en elke nieuwe sessie start als dat account: `cx`, `cy`, een gewone `claude`, `codex` of `grok`, alles wat via `omarchy agent` wordt gestart, en scripts of editors die de CLI op `PATH` vinden. Wissel met `omarchy agent account use work` (en terug met `omarchy agent account use main`), of in het paneel door op het nummer van een account te drukken en daarna op `Enter` (of door op zijn Use-knop te klikken). Draaiende Claude-sessies wisselen ook, vanaf hun volgende bericht: elke Claude-sessie draait in `~/.claude`, dat altijd de login van het actieve account bevat. Een Claude-sessie die door een oudere Omarchy in de eigen map van een account is gestart, behoudt die login tot hij stopt, dus de wissel benoemt die sessies en eindigt vanzelf zodra ze weg zijn. Draaiende Codex- en Grok-sessies blijven op het account waarmee ze zijn gestart. Gespreksgeschiedenis, instellingen, skills en plugins worden gedeeld over accounts, dus `claude --continue` in dezelfde map pakt op waar je was gebleven op het nieuwe account.

Met meer dan één account toont het paneel de limieten van elk account naast elkaar, met het actieve account gemarkeerd. Standaard meldt Omarchy het je wanneer het actieve account 95% van een limiet passeert, en klikken op de melding wisselt naar het account met de meeste speelruimte. Beweeg over de regel van een account in het paneel en klik op de Autoswitch die naast Use verschijnt (of druk op `m`), of voer `omarchy agent account mode auto` uit, om het in plaats daarvan zelf te laten wisselen; terwijl het aan staat, neemt Autoswitch de plaats van Use in, en er opnieuw op klikken gaat terug naar melden. Voeg een nummer toe om de drempel te wijzigen, zoals in `omarchy agent account mode auto 90`. Als elk account boven de drempel zit, hoor je dat één keer, samen met welk account als eerste vrijkomt. Terwijl een actief account binnen 15 punten van zijn drempel zit (80% bij de standaard), worden zijn limieten elke drie minuten gecontroleerd in plaats van elke 15.

`omarchy agent account list` toont elk account en zijn laatste limieten, `omarchy agent account remove work` vergeet er een, en `omarchy agent account rename primary Hey` hernoemt er een (of klik op de naam van een account in het paneel). Deze commando's werken op de accounts van je standaardagent; om de andere provider te bereiken, noem je die eerst, zoals in `omarchy agent account use codex side`. De login die je al had in `~/.claude` of `~/.codex` is het _Main_-account. Die van Codex blijft waar hij is; die van Claude wacht in een eigen map terwijl een ander account actief is. Een account dat meer dan ongeveer acht uur ongebruikt is gebleven, kan _Sign-in required_ tonen; klik erop om dat account opnieuw in te loggen, direct in het paneel, of wissel ernaar en start een sessie, wat de login vanzelf vernieuwt. MCP-servers die je toevoegt met `claude mcp add` bereiken elk Claude-account, omdat ze allemaal in `~/.claude` draaien; voor Codex en Grok komen servers die je had toen een account werd toegevoegd met dat account mee, maar latere servers bereiken alleen het account waarin je ze hebt toegevoegd. Claude Desktop behoudt een eigen login, en Codex- of Grok-tools die zijn geconfigureerd met een absoluut pad naar een CLI-binary volgen de wissel niet. Een expliciete `CLAUDE_CONFIG_DIR`, `CODEX_HOME` of `GROK_HOME` heeft voorrang op het geselecteerde account.

### Crashdiagnose

Omarchy bewaakt systemd-coredump op procescrashes. Wanneer iets segfault, krijg je een melding "Process crashed" — klik erop, en de crash wordt overgedragen aan je standaardagent samen met Omarchy's diagnose-crash skill, die de agent door het vaststellen van de feiten uit de core dump leidt en het beslissen of de crash het waard is om upstream te melden. Je kunt het ook handmatig uitvoeren tegen elke PID uit `coredumpctl list` met `omarchy agent crash <pid>`.

Het bewaken staat standaard aan. Zet het uit onder _Trigger > Toggle > Crash Capture_ (of met `omarchy toggle crash-capture`) en de meldingen stoppen; `omarchy agent crash <pid>` werkt nog steeds handmatig.

Crashes kunnen ook één programma tegelijk worden gedempt, wat de diagnose je aan het einde aanbiedt. `omarchy crash mute hyprland` stopt de meldingen alleen voor dat programma, `omarchy crash mute hyprland off` brengt ze terug, en `omarchy crash mute` op zichzelf somt op wat je hebt gedempt. Het accepteert het pad van de binary net zo graag als zijn naam, dus `omarchy crash mute /usr/bin/hyprland` doet hetzelfde. Zet een naam met een spatie erin tussen aanhalingstekens, zoals in `omarchy crash mute 'Some App'`. Al het andere blijft melden, en het gedempte programma crasht nog steeds — dit verbergt de herinnering, het fixt niets.

### Desktop-apps

Het menu _Install > AI_ bevat ook een paar grafische AI-apps: Antigravity Desktop, de ChatGPT desktop-app, de Claude desktop-app (de Linux-bèta van Anthropic, met Chat-, Cowork- en Claude Code-tabbladen), Grok Bot om met de modellen van xAI te chatten, Herdr Desktop, Hermes Desktop, OpenClaw, de Perplexity desktop-app en T3 Code. Grok Bot is de desktop-chatapp. De codeeragent is het `grok`-commando.

Hermes Desktop is degene die je moet kennen, omdat een machine één Hermes heeft, en die is van de app: Hermes wordt alleen ooit via de app geïnstalleerd, en het `hermes`-commando dat de standaardagent draait, is dat van de app. Hermes kiezen als standaardagent installeert hetzelfde als de vermelding _Install > AI_: het pakket, en een Hermes-runtime onder `~/.hermes` ingesteld door Hermes' eigen installatieprogramma, wat de eerste keer een paar minuten duurt. Die runtime is de ene Hermes die het terminal-`hermes`-commando, de standaardagent en de app allemaal gebruiken, en hij werkt zichzelf bij met `hermes update` in plaats van te wachten op een Omarchy-release. Installeren geeft Hermes ook het Omarchy-thema als een skin genaamd `omarchy`, die elk Hermes-oppervlak volgt als je van thema wisselt; kies een andere onder Hermes' Appearance-instellingen of met `/skin` als je liever niet wilt dat het dat doet, en Omarchy laat die keuze met rust. De app verwijderen onder _Remove > AI_ sluit Hermes eerst, gateway inbegrepen, neemt die runtime mee, en behoudt je chats, herinneringen en de skills die Hermes voor zichzelf heeft geschreven, tenzij je het anders zegt: het vraagt, met nee als standaard, of die gegevens en je verbindingsinstellingen ook moeten verdwijnen.

De desktopervaring van OpenClaw is zijn Control UI, die opent als een webapp ondersteund door zijn eigen lokale gateway. OpenClaw leeft in `~/.openclaw` en werkt zichzelf bij: gebruik de knop "Update Gateway" in de Control UI of voer `openclaw update` uit, en de gateway herstart op de nieuwe versie. Omarchy kiest alleen de release waarmee een verse installatie start. OpenClaw verwijderen onder _Remove > AI_ neemt de gateway-service en de app mee en vraagt daarna of `~/.openclaw` ook moet verdwijnen, omdat dat je chats en gegevens bevat naast OpenClaw zelf en de plugin-runtimes die het downloadt; de standaard behoudt het, en OpenClaw opnieuw installeren pakt het weer op.

Herdr Desktop is de [Herdr](https://herdr.dev) desktop-app: ruimtes, tabbladen en panelen van terminals en codeeragents die blijven draaien in zijn kern wanneer je het venster sluit. Het komt van Herdr's eigen installatieprogramma in plaats van een pakket, dus het leeft in `~/.local/share/herdr-app`, brengt zijn kern mee in `~/.local/bin/herdr-core` wanneer je er nog geen hebt, en werkt beide zelf bij. Het staat naast het `herdr`-commando dat Omarchy levert op `Super + Ctrl + Return` in plaats van het te vervangen, en krijgt de directe toetsen van dat commando: `Alt + Return` en `Alt + Shift + Return` splitsen een paneel omlaag of naar rechts, `Alt + Escape` sluit het, `Ctrl + Alt + Arrow` beweegt tussen panelen, `Alt + 1..9` en `Alt + Left/Right` kiezen een tabblad, en `Alt + Up/Down` bewegen tussen ruimtes. `Ctrl + 1..9` kiest een ruimte en `Alt + Shift + Up/Down` stapt door agents. De `Ctrl + Space`-prefixtoetsen blijven alleen voor terminals, omdat de app geen gewone Ctrl-toets kan vasthouden voor een reeks. Omarchy schrijft deze naar `~/.config/herdr-app/keys.json`, en `omarchy-refresh-herdr-app` zet ze terug. Installeren kiest Herdr's Omarchy-thema, dat vanaf dan je Omarchy-thema volgt. Herdr bewaart één thema voor de lichte modus en één voor de donkere modus, dus na het wisselen tussen een donker en een licht Omarchy-thema kies je Omarchy nog één keer in Herdr's themakiezer voor de andere modus.

T3 Code draait vanaf zijn officiële AppImage-release in `~/.local/share/t3code` in plaats van uit een pakket, dus het werkt zichzelf bij. Installeren vraagt of je op het Stable- of Nightly-kanaal wilt starten; wissel later in de instellingen van T3 Code. Je threads en instellingen leven in `~/.t3`, en T3 Code verwijderen onder _Remove > AI_ neemt ze mee.

### Lokale modellen

Draai een open model op je eigen machine voor je codeeragents. Je prompts en code blijven op de machine; niets dat naar het model wordt gestuurd, verlaat hem. Begin met:

```bash
omarchy agent local use best
```

Of, in het agents-paneel in de bovenste balk, kies + en daarna Local AI, wat verschijnt wanneer een model op deze machine past. De eerste keer installeert dit Podman, dat de modellen draait, en op een NVIDIA-machine NVIDIA's container toolkit, die ze de GPU geeft. Omarchy kiest dan het aanbevolen model voor deze machine, downloadt het en start het. Verwacht een download van tientallen GB en dat het grootste deel van het geheugen van de machine in gebruik is terwijl het model draait: Flash Next gebruikt ongeveer 100 GiB met zijn volledige 256K-context. Als andere modellen het geheugen bezetten dat het nodig heeft, wordt het gestopt ingesteld, klaar om te starten zodra je er een stopt. Het model stopt bij uitloggen; stop het zelf wanneer je het geheugen voor iets anders nodig hebt.

`omarchy agent local list` toont de opties en legt uit waarom sommige niet passen. Om een andere in te stellen, voer je `omarchy agent local use <recipe>` uit. Vandaag zijn `qwen3.8-flash-next-gufo` en `qwen3.8-27b-gufo` beschikbaar voor 128 GB Strix Halo-machines; de 27B neemt ongeveer 40 GiB, dus hij laat ruimte voor ander werk. Op een 64 GB laptop met Intel's Arc B390 draait `qwen3.6-35b-a3b-llamacpp` in ongeveer 30 GiB. Nieuwe recipes en aanbevelingen arriveren met `omarchy update`, via het pakket.

Elk model dat je instelt, krijgt zijn eigen regel in het agents-paneel, naast je abonnementen: play om het te starten, pauze om het te stoppen en zijn geheugen vrij te maken, en de terminalknop om je agent erop te openen. Meerdere kunnen tegelijk draaien wanneer ze samen in het geheugen passen; als er een niet past, zegt Omarchy welk draaiend model je moet stoppen. Sleep regels om ze te herordenen, en druk op Delete bij een geselecteerde regel om een model en zijn download te verwijderen.

Elk model dat je instelt, krijgt ook zijn eigen vermelding in de app-launcher, onder de naam van het model en met het logo van zijn maker, zoals inloggen bij Claude, Codex of Grok er een toevoegt. Het opent je agent op dat model, en start het model eerst als het niet draait: de terminal toont het laden en geeft over aan de agent zodra het draait. Een model verwijderen verwijdert zijn vermelding.

Een model blijft precies draaien zoals het is ingesteld, dus een Omarchy-update herstart er nooit een onder je agents. Wanneer Omarchy een nieuwere runtime of nieuwere gewichten heeft voor een model dat je hebt ingesteld, toont zijn regel een updateknop: druk erop en het model wordt op de achtergrond opnieuw ingesteld, waarbij alleen wordt gedownload wat er is veranderd, en herstart op de nieuwe versie. Een model dat was gestopt, blijft gestopt. `omarchy agent local update` doet hetzelfde voor elk model vanuit een terminal.

Vanaf de commandoregel doen `omarchy agent local start <recipe>` en `omarchy agent local stop <recipe>` hetzelfde, `omarchy agent local status` toont elk model, en `omarchy agent --local` opent je standaardagent op het laatste model dat je hebt gestart. pi, OpenCode en Qwen Code kunnen er een gebruiken; bij elke andere standaard opent het in pi. pi somt ook elk model op dat je hebt ingesteld, en die op machines waarmee je bent gekoppeld, in zijn eigen modelkiezer, dus gewone `pi` bereikt ze ook. Elke OpenAI-compatibele client kan ook verbinden: `status` toont het adres van elk model (het eerste is `http://127.0.0.1:11435/v1`), de recipe-naam is het model, en de sleutel staat in `~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` verwijdert een model en de downloads die geen ander model gebruikt.

Runtimes van derden zijn gelabeld met hun uitgever. Omarchy draait elk model zonder netwerktoegang.

### Lokale LLM's

Omarchy raadt twee manieren aan om lokale LLM-modellen te draaien: LM Studio en Ollama. LM Studio biedt een GUI-interface voor het vinden van open-weight modellen, ze installeren en ze draaien. Het is een geweldige manier om gemakkelijk aan de slag te gaan. Ollama biedt een CLI om dat op vergelijkbare manier te doen. Maar als je nieuw bent met lokale modellen, zou ik beginnen met LM Studio. Je kunt beide installeren onder _Install > AI_ in het Omarchy Menu.

### De Omarchy Skill

Agent skills helpen AI om specifieke tools op een specifieke manier te gebruiken, en Omarchy wordt geleverd met een standaard skill voor het op maat maken van het systeem. Zoals je Hyprland-config tweaken, de balk aanpassen, of zelfs een nieuw thema vanaf nul creëren. Het is gesymlinkt naar de skill-mappen voor Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` en elke `~/.hermes/profiles/*/skills`), en de generieke locatie `~/.agents/skills`, dus de meeste harnesses pikken het automatisch op.

Maar je moet deze skill als experimenteel beschouwen. Verschillende modellen zullen het met verschillend effect gebruiken. Het is het beste om eerst in planmodus te draaien, zodat je een idee hebt van wat de agent zou willen veranderen. En wees dan klaar om wijzigingen terug te draaien of zelfs `omarchy reinstall configs` aan te roepen, als de agent er een puinhoop van maakt.
