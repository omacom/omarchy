# AI

Omarchy bevat launchers voor de onderstaande coding agents zonder een standaard voor je te kiezen. Voer een commando uit om zijn CLI bij het eerste gebruik te installeren, en authentiseer je daarna wanneer daarom wordt gevraagd. Hermes en OpenClaw zijn de uitzonderingen: voor hen wordt niets via mise geïnstalleerd, en het kiezen van een van beide zet zijn eigen zelf-updatende kopie op, zoals _Desktop-apps_ hieronder uitlegt.

### Agents installeren en bijwerken

Met uitzondering van Hermes en OpenClaw gebruiken deze agents de luie installatie van mise: de eerste start installeert de CLI, en latere starts hergebruiken hem. mise controleert een geïnstalleerde agent ook hooguit eens per vier uur op een nieuwe release, net voordat hij start of op de achtergrond bij een shell-prompt. Als die update mislukt of je offline bent, draait de geïnstalleerde versie. `omarchy update` werkt geïnstalleerde agents bij samen met de rest van Omarchy, en `mup` werkt alleen door mise beheerde tools bij.

De eigen updater van een agent, zoals `claude update`, `codex update` of een updateknop in een app, werkt de door mise beheerde installatie niet bij. `codex update` mislukt, en `claude update` kan succes melden terwijl het een aparte kopie installeert die mise niet bijhoudt. Als je liever de eigen installer en updater van een agent gebruikt, voeg hem dan toe aan `disable_tools`; zie [Vooraf geïnstalleerde CLI-tools](18-development-tools.md#preinstalled-cli-tools).

Om alle geconfigureerde luie tools te installeren voordat je ze nodig hebt, voer je `mise install --include-lazy` uit. Dit omvat zowel Omarchy's andere standaard CLI-tools als de agents. Zie [Vooraf geïnstalleerde CLI-tools](18-development-tools.md#preinstalled-cli-tools) voor het installeren van een enkele tool of het gebruiken van je eigen installatie.

`grok` wordt geïnstalleerd via mise's eigen `grok`-pakket, op dezelfde manier als `claude` en `codex`. Voer `grok` uit, of kies hem onder _Agent > Harness_. Sla de `curl | bash`-installer op x.ai over. Dat pad plaatst een tweede kopie in `~/.grok/bin`, zet die vooraan op `PATH` en overschrijft Omarchy's wrapper.

`dsh` opent zijn browser-UI op `127.0.0.1:3080`, met de startmap als zijn standaard werkruimte. Zijn browser-UI accepteert geen startprompt, dus `omarchy agent prompt` opent hem met de prompt op je klembord om te plakken. Omarchy start hem met DeepSeek's permissie-preset zonder goedkeuring. DeepSeek Harness uploadt sessielogs naar DeepSeek wanneer je zijn officiële model-API gebruikt; schakel dat uit onder _Settings > General > Upload Session Log_ in zijn browser-UI. Feedback die je ernaartoe stuurt, wordt ook met de sessie geüpload, tenzij je hem start met `DSH_TELEMETRY_MODE=DISABLED`.

### De standaardagent

Kies je standaardagent met `omarchy default agent <name>` of onder _Agent > Harness_ in het Omarchy Menu (`Super + Space`). Als de agent nog niet is geïnstalleerd, installeert het kiezen ervan hem eerst, en hij krijgt ook een eigen launcher in de app-launcher, naast Agent. Een verse Omarchy nodigt je met een eenmalige melding uit om deze keuze te maken.

Claude kiezen probeert ook zijn browserextensie in te stellen voor Chromium, Chrome, Brave, Brave Origin en Edge. Het instellen van de extensie geldt voor alle gebruikers en kan om je systeemwachtwoord vragen; annuleren of een mislukte extensie-installatie selecteert en start Claude nog steeds. Herstart je browser, schakel de extensie in als daarom wordt gevraagd, en meld je aan bij Claude om het verbinden af te ronden. Voer `/chrome` uit in Claude om de verbinding te controleren. Firefox en Zen ondersteunen deze extensie niet. Als Claude al je standaard was voordat dit instellen werd toegevoegd, selecteer hem dan opnieuw om de extensie te installeren.

Zodra je hebt gekozen, start `Super + Shift + Ctrl + A` de standaardagent in een apart terminalvenster (of opent de kiezer als je nog niet hebt gekozen). Je kunt hem ook rechtstreeks een taak in sturen met `omarchy agent prompt "Review this project"`. Freebuff en DeepSeek Harness accepteren geen startprompt, dus zij openen in plaats daarvan met de prompt op je klembord om te plakken. Agents die op deze manier worden gestart, draaien onbeheerd in hun respectieve modi waarin ze niet stoppen om te vragen, dus wees erop voorbereid dat ze daadwerkelijk dingen gaan doen! MiniMax Code heeft zo'n modus niet voor zijn interactieve sessies, dus die vraagt zoals gebruikelijk om toestemming. En omdat agents weigeren het vertrouwen voor je thuismap te onthouden, starten starts vanuit `$HOME` in plaats daarvan in `~/Work`.

Er zijn ook snelkoppelingen in de terminal: `a` draait de standaardagent inline in de huidige terminal, terwijl `c`, `cx` en `cy` OpenCode, Claude Code en Codex rechtstreeks starten (wederom in hun automatisch goedkeurende modi). Themaveranderingen synchroniseren ook naar de agents: Claude Code, Pi, OpenCode en Hermes (zodra Omarchy hem heeft geïnstalleerd) volgen allemaal mee wanneer je van Omarchy-thema wisselt.

### Je agentinstructies

Persoonlijke regels voor elke agent horen in `~/.agents/AGENTS.md`, naast de gedeelde skills in `~/.agents/skills`. Open het onder _Agent > Instructions_, wat het ook koppelt naar elke harness die zijn eigen globale bestand bijhoudt: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, Copilot's `~/.copilot/copilot-instructions.md`, enzovoort. Crush en Amp lezen de link `~/.config/AGENTS.md`, terwijl omp, Kimi en DeepSeek Harness `~/.agents/AGENTS.md` rechtstreeks lezen. Een standaardagent kiezen koppelt het ook. Een instructiebestand dat je al had, wordt het gedeelde bestand als er nog geen was; anders wordt het naast de link bewaard als `.bak`. Voer `omarchy agent instructions` uit om opnieuw te koppelen nadat je een andere agent hebt geïnstalleerd.

### Het agents-paneel

De bovenbalk heeft een agents-icoon. Voordat je een agent hebt ingesteld, leidt zijn paneel je door het aanmelden bij Claude, Codex of Grok, en de eerste wordt je standaardagent. Daarna zet het paneel elk abonnement op één pagina: elke agent en elk account met zijn plan, een meter voor elk van zijn limieten per sessie van 5 uur en per week met de tijd tot hij reset (beweeg eroverheen voor het exacte percentage), of het resterende prepaid-saldo, onder een regel die rouleert door wat je over hen allemaal heen hebt gebruikt, zoals tokens deze week en je meest gebruikte model. Onder _Make something cool_ biedt het starterprompts voor een nieuw thema, een nieuwe plugin, app of game die de taak aan je standaardagent overhandigen. Apps worden gebouwd zoals Omarchy's eigen Hype, Monologue en Omacut, in C++ en Qt Quick, volgens de omarchy-make-app agent skill, en de compiler en de Qt-onderdelen die ze nodig hebben, worden meegeleverd geïnstalleerd. Games zijn een enkele three.js-pagina in `~/Games/vibes`, volgens de omarchy-make-game agent skill, en openen allemaal vanuit één Game Vibes-launcher in het huidige thema; ze laden three.js van het web, dus ze hebben een verbinding nodig om te starten. Claude Code, Codex, Grok, Kimi, Cursor en zijn Grok Bot-tegoed, GitHub Copilot, Muse, Antigravity en Devin worden direct ondersteund met hun limieten, Kimchi met zijn plan, prepaid-tegoeden en uitgavenbudgetten, en Hermes, Mistral Vibe en Qwen Code tonen hun sessies en tokens zodra je ze hebt gebruikt. Providerplannen en sleutels die je via pi, omp of opencode gebruikt, verschijnen ook: OpenCode Zen en Go, het Z.ai GLM Coding Plan, Ollama Cloud, het MiniMax Token Plan en Synthetic met hun limieten; OpenRouter en DeepSeek met hun prepaid-saldi; Fireworks met zijn uitgaven over de afgelopen 30 dagen; en de modellen die je op je eigen hardware draait onder Lokale modellen. Elke agent wordt één keer geteld, onder wie hem ook factureert, via hoeveel harnesses je hem ook aanstuurt.

Klik met de linkermuisknop op het icoon in de balk of druk op `Super + Ctrl + X` voor het paneel, klik met de rechtermuisknop om je standaardagent te starten en klik met de middelste muisknop om te vernieuwen. De gebruiksgegevens erachter worden elke 15 minuten opnieuw gegenereerd door `omarchy agent usage update`, en het paneel kan zelfs gebruik van je andere machines samenvoegen via een gesynchroniseerde map. Zie de README onder `$OMARCHY_PATH/shell/plugins/agents/` voor de volledige instellingen.

### Meerdere abonnementen

Als je voor meer dan één Claude-, Codex- of Grok-plan betaalt — bijvoorbeeld een persoonlijke Max en een voor je werk — kan Omarchy ze allemaal aangemeld houden en ertussen bewegen. Voeg een abonnement toe met de + in het agents-paneel, dat je er daar meteen doorheen leidt, of met `omarchy agent account add claude Work` (of `codex`, of `grok`). Het installeert de CLI als die ontbreekt. Het eerste account voor een provider meldt zich aan via je normale browser, precies waar de CLI altijd kijkt. Elk account daarna meldt zich aan via een privévenster, zodat het account waarbij je browser al is aangemeld niet per ongeluk wordt opgepikt; meld je daar aan als het account dat je toevoegt, en sluit eerst elk privévenster dat je al open had. Meld je hiervoor nooit af bij de CLI: afmelden trekt de opgeslagen aanmelding in, en dat account zou opnieuw moeten worden toegevoegd.

Om je abonnementsaanmeldingen via SSH naar een andere Omarchy-machine te kopiëren, voer je `omarchy agent account copy user@laptop` uit. De verzender levert een tijdelijke ontvanger wanneer de bestemming er geen geïnstalleerd heeft, zodat oudere Omarchy-machines accounts kunnen ontvangen zonder een update. Geïnstalleerde ontvangers hebben voorrang. Dit kopieert alle Claude-, Codex- en Grok-abonnementen; voeg providernamen toe om ze te selecteren, zoals in `omarchy agent account copy laptop claude`. Accountnamen en commando-ID's komen overeen met de bron, inclusief accounts die al op de bestemming aanwezig zijn. Niet-gerelateerde bestemmingsaccounts krijgen een numeriek achtervoegsel als hun namen conflicteren, en instellingen, skills, plugins en gespreksgeschiedenis blijven lokaal op elke machine.

Bestaande inloggegevens op de bestemming blijven behouden. Van een bronaccount dat daar al is aangemeld, wordt de naam gesynchroniseerd zonder zijn inloggegevens te vervangen; andere accounts worden ernaast toegevoegd. Om opgeslagen inloggegevens voor overeenkomende accounts te vervangen, gebruik je `omarchy agent account copy --replace laptop claude` nadat je de sessies van dat account op de bestemming hebt afgesloten. Een verse bestemming krijgt ook het actieve account en de wisselvoorkeuren van de bron; een reeds ingerichte bestemming behoudt haar eigen voorkeuren.

Inloggegevens reizen via SSH en worden opgeslagen in privébestanden op de bestemming, dus kopieer alleen naar machines die je vertrouwt. Dit is een eenmalige kopie, geen doorlopende synchronisatie. Vernieuwingstokens van Codex kunnen door een andere machine worden geroteerd, waardoor een gekopieerde aanmelding vernieuwd moet worden; aparte aanmeldingen blijven de betrouwbaarste keuze voor gelijktijdig gebruik op meerdere machines. Zie [Codex's richtlijnen voor accountauthenticatie](https://developers.openai.com/codex/auth/ci-cd-auth).

Per provider is één account actief, en elke nieuwe sessie start als dat account: `cx`, `cy`, een gewone `claude`, `codex` of `grok`, alles wat via `omarchy agent` wordt gestart, en scripts of editors die de CLI op `PATH` vinden. Wissel met `omarchy agent account use work` (en terug met `omarchy agent account use main`), of in het paneel door op het nummer van een account en daarna op `Enter` te drukken (of op zijn knop Use te klikken). Draaiende Claude-sessies wisselen ook mee, vanaf hun volgende bericht: elke Claude-sessie draait in `~/.claude`, dat altijd de aanmelding van het actieve account bevat. Een Claude-sessie die door een oudere Omarchy in de eigen map van een account is gestart, behoudt die aanmelding tot hij afsluit, dus de wissel benoemt die sessies en rondt vanzelf af zodra ze weg zijn. Draaiende Codex- en Grok-sessies blijven op het account waarmee ze zijn gestart. Gespreksgeschiedenis, instellingen, skills en plugins worden gedeeld over accounts heen, dus `claude --continue` in dezelfde map gaat verder waar je was gebleven op het nieuwe account.

Met meer dan één account toont het paneel de limieten van elk account naast elkaar, met het actieve account gemarkeerd. Standaard laat Omarchy je weten wanneer het actieve account 95% van een limiet passeert, en klikken op de melding wisselt naar het account met de meeste ruimte. Beweeg over de regel van een account in het paneel en klik op de Autoswitch die naast Use verschijnt (of druk op `m`), of voer `omarchy agent account mode auto` uit, om hem in plaats daarvan vanzelf te laten wisselen; terwijl het aanstaat, neemt Autoswitch de plaats van Use in, en er opnieuw op klikken gaat terug naar melden. Voeg een getal toe om de drempel te veranderen, zoals in `omarchy agent account mode auto 90`. Als elk account boven de drempel zit, hoor je dat één keer, samen met welk account als eerste vrijkomt. Terwijl een actief account binnen 15 punten van zijn drempel zit (80% bij de standaard), worden zijn limieten elke drie minuten gecontroleerd in plaats van elke 15.

`omarchy agent account list` toont elk account en zijn nieuwste limieten, `omarchy agent account remove work` vergeet er een, en `omarchy agent account rename primary Hey` hernoemt er een (of klik op de naam van een account in het paneel). Deze commando's werken op de accounts van je standaardagent; om de andere provider te bereiken, noem je die eerst, zoals in `omarchy agent account use codex side`. De aanmelding die je al had in `~/.claude` of `~/.codex` is het _Main_-account. Die van Codex blijft waar hij is; die van Claude wacht in een eigen map terwijl een ander account actief is. Een account dat meer dan ongeveer acht uur ongebruikt is gebleven, kan _Sign-in required_ tonen; klik erop om dat account opnieuw aan te melden, direct in het paneel, of wissel ernaartoe en start een sessie, wat de aanmelding vanzelf vernieuwt. MCP-servers die je toevoegt met `claude mcp add` bereiken elk Claude-account, aangezien ze allemaal in `~/.claude` draaien; voor Codex en Grok komen servers die je had toen een account werd toegevoegd mee naar dat account, maar latere exemplaren bereiken alleen het account waarin je ze hebt toegevoegd. Claude Desktop houdt een eigen aanmelding bij, en Codex- of Grok-tools die zijn geconfigureerd met een absoluut pad naar een CLI-binary volgen de wissel niet. Een expliciete `CLAUDE_CONFIG_DIR`, `CODEX_HOME` of `GROK_HOME` heeft voorrang op het geselecteerde account.

### Crashdiagnose

Omarchy bewaakt systemd-coredump op procescrashes. Zodra je een standaardagent hebt gekozen, brengt elk programma van jou dat een core dumpt een melding "Process crashed" — klik erop, en de crash wordt overhandigd aan je standaardagent samen met Omarchy's omarchy-diagnose-crash skill, die de agent erdoorheen leidt de feiten uit de core dump vast te stellen en te beslissen of de crash het waard is om upstream te melden. Je kunt het ook met de hand uitvoeren tegen elke PID uit `coredumpctl list` met `omarchy agent crash <pid>`.

Het bewaken staat standaard aan. Schakel het uit onder _Trigger > Toggle > Crash Capture Off_ (of met `omarchy toggle crash-capture`) en de meldingen stoppen; `omarchy agent crash <pid>` werkt nog steeds met de hand.

Crashes kunnen ook per programma worden gesilenced, wat de diagnose je aan het einde aanbiedt. `omarchy crash mute hyprland` stopt de meldingen alleen voor dat programma, `omarchy crash mute hyprland off` brengt ze terug, en `omarchy crash mute` op zichzelf somt op wat je hebt gedempt. Het accepteert het pad van de binary net zo graag als zijn naam, dus `omarchy crash mute /usr/bin/hyprland` doet hetzelfde. Zet een naam met een spatie erin tussen aanhalingstekens, zoals in `omarchy crash mute 'Some App'`. Al het andere geeft nog steeds meldingen, en het gedempte programma crasht nog steeds — dit verbergt de herinnering, het repareert niets.

### Desktop-apps

Het menu _Install > AI_ bevat ook een paar grafische AI-apps: Amp Desktop, Antigravity Desktop, de desktop-app van ChatGPT, de desktop-app van Claude (Anthropic's Linux-bèta, met tabbladen voor Chat, Cowork en Claude Code), Grok Bot om te chatten met de modellen van xAI, Herdr Desktop, Hermes Desktop, OpenClaw, de desktop-app van Perplexity en T3 Code. Grok Bot is de desktop-chatapp. De coding agent is het `grok`-commando.

Hermes Desktop is degene die je moet kennen, omdat een machine één Hermes heeft, en die is van de app: Hermes wordt alleen ooit via de app geïnstalleerd, en het `hermes`-commando dat de standaardagent draait is dat van de app. Hermes als standaardagent kiezen installeert hetzelfde als de vermelding onder _Install > AI_: het pakket, en een Hermes-runtime onder `~/.hermes` opgezet door Hermes' eigen installer, wat de eerste keer een paar minuten duurt. Die runtime is de ene Hermes die het `hermes`-commando in de terminal, de standaardagent en de app allemaal gebruiken, en hij werkt zichzelf bij met `hermes update` in plaats van te wachten op een Omarchy-release. Hem installeren geeft Hermes ook het Omarchy-thema als een skin met de naam `omarchy`, die elk Hermes-oppervlak volgt terwijl je van thema wisselt; kies een andere onder Hermes' Appearance-instellingen of met `/skin` als je liever niet hebt dat hij dat doet, en Omarchy laat die keuze met rust. De app verwijderen onder _Remove > AI_ sluit Hermes eerst, gateway inbegrepen, neemt die runtime mee en behoudt je chats, herinneringen en de skills die Hermes voor zichzelf schreef, tenzij je anders aangeeft: het vraagt, met nee als standaard, of die gegevens en je verbindingsinstellingen ook weg moeten.

De desktopervaring van OpenClaw is zijn Control UI, die opent als een webapp ondersteund door zijn eigen lokale gateway. OpenClaw leeft in `~/.openclaw` en werkt zichzelf bij: gebruik de knop "Update Gateway" van de Control UI of voer `openclaw update` uit, en de gateway herstart op de nieuwe versie. Omarchy kiest alleen de release waarmee een verse installatie begint. OpenClaw kan ook je standaardagent zijn: hem kiezen onder _Agent > Harness_ zet diezelfde kopie op in `~/.openclaw`, en de agent opent OpenClaw's terminal UI gekoppeld aan zijn gateway. OpenClaw verwijderen onder _Remove > AI_ neemt de gateway-service en de app mee en vraagt dan of `~/.openclaw` ook weg moet, aangezien dat je chats en inloggegevens bevat naast OpenClaw zelf en de plugin-runtimes die het downloadt; de standaard behoudt het, en OpenClaw opnieuw installeren pikt het weer op.

Herdr Desktop is de desktop-app van [Herdr](https://herdr.dev): spaces, tabbladen en panelen van terminals en coding agents die blijven draaien in zijn core wanneer je het venster sluit. Hij komt van Herdr's eigen installer in plaats van een pakket, dus hij leeft in `~/.local/share/herdr-app`, brengt zijn core mee in `~/.local/bin/herdr-core` wanneer je er nog geen hebt, en werkt beide zelf bij. Hij zit naast het `herdr`-commando dat Omarchy levert op `Super + Ctrl + Return` in plaats van het te vervangen, en krijgt de directe toetsen van dat commando: `Alt + Return` en `Alt + Shift + Return` splitsen een paneel omlaag of naar rechts, `Alt + Escape` sluit het, `Ctrl + Alt + Arrow` beweegt tussen panelen, `Alt + 1..9` en `Alt + Left/Right` kiezen een tabblad, en `Alt + Up/Down` bewegen tussen spaces. `Ctrl + 1..9` kiest een space en `Alt + Shift + Up/Down` stapt door agents. De prefix-toetsen met `Ctrl + Space` blijven alleen voor de terminal, aangezien de app een gewone Ctrl-toets niet kan vasthouden voor een reeks. Omarchy schrijft deze naar `~/.config/herdr-app/keys.json`, en `omarchy-refresh-herdr-app` zet ze terug. Hem installeren kiest Herdr's Omarchy-thema, dat vanaf dan je Omarchy-thema volgt. Herdr houdt één thema bij voor de lichte modus en één voor de donkere, dus kies na het wisselen tussen een donker en een licht Omarchy-thema nog een keer Omarchy in Herdr's themakiezer voor de andere modus.

T3 Code draait vanaf zijn officiële AppImage-release in `~/.local/share/t3code` in plaats van vanaf een pakket, dus hij werkt zichzelf bij. Hem installeren vraagt of er op het Stable- of Nightly-kanaal moet worden gestart; wissel later in de instellingen van T3 Code. Je threads en instellingen leven in `~/.t3`, en T3 Code verwijderen onder _Remove > AI_ neemt ze mee.

### Lokale modellen

Draai een open model op je eigen machine voor je coding agents. Je prompts en code blijven op de machine; niets dat naar het model wordt gestuurd, verlaat haar. Begin met:

```bash
omarchy agent local use best
```

Of kies in het agents-paneel in de bovenbalk + en dan Local AI, wat verschijnt wanneer een model op deze machine past. Podman, dat de modellen draait, wordt meegeleverd met Omarchy, net als de container toolkit van NVIDIA op een NVIDIA-machine, die hun de GPU geeft; als een van beide ontbreekt, installeert de eerste setup hem. Omarchy kiest dan het aanbevolen model voor deze machine, downloadt het en start het. Verwacht een download van tientallen GB en dat het meeste geheugen van de machine in gebruik is terwijl het model draait: Flash Next gebruikt ongeveer 100 GiB met zijn volledige context van 256K. Als andere modellen het geheugen bezet houden dat hij nodig heeft, wordt hij gestopt opgezet, klaar om te starten zodra je er een stopt. Het model stopt bij het afmelden; stop het zelf wanneer je het geheugen voor iets anders nodig hebt.

`omarchy agent local list` toont de opties en legt uit waarom sommige niet passen. Om een andere op te zetten, voer je `omarchy agent local use <recipe>` uit. Vandaag zijn `qwen3.8-flash-next-gufo` en `qwen3.8-27b-gufo` beschikbaar voor Strix Halo-machines van 128 GB; de 27B neemt ongeveer 40 GiB in, dus hij laat ruimte over voor ander werk. Op een laptop van 64 GB met Intel's Arc B390 draait `qwen3.6-35b-a3b-llamacpp` in ongeveer 30 GiB. Nieuwe recepten en aanbevelingen komen binnen met `omarchy update`, via het pakket.

Elk model dat je opzet, krijgt een eigen regel in het agents-paneel, naast je abonnementen: afspelen om het te starten, pauzeren om het te stoppen en zijn geheugen vrij te maken, en de terminalknop om je agent erop te openen. Meerdere kunnen tegelijk draaien wanneer ze samen in het geheugen passen; als er een niet past, zegt Omarchy welk draaiend model je moet stoppen. Sleep regels om ze opnieuw te ordenen, en druk op Delete op een geselecteerde regel om een model en zijn download te verwijderen.

Elk model dat je opzet, krijgt ook een eigen vermelding in de app-launcher, onder de naam van het model en met het logo van zijn maker, net zoals aanmelden bij Claude, Codex of Grok er een toevoegt. Het opent je agent op dat model, en start het model eerst als het niet draait: de terminal toont dat het laadt en draagt over aan de agent zodra het overeind is. Een model verwijderen verwijdert zijn vermelding.

Niet elk model is om te coderen. Beeld-, video- en muziekmodellen openen in plaats daarvan in Fantasi, Omarchy's app om afbeeldingen, video en muziek te maken met een model dat op deze machine draait, vanuit hun vermelding in de launcher en vanuit hun regel in het agents-paneel.

Een model blijft precies draaien zoals het was opgezet, dus een Omarchy-update herstart er nooit een onder je agents. Wanneer Omarchy een nieuwere runtime of nieuwere gewichten heeft voor een model dat je hebt opgezet, toont zijn regel een updateknop: druk erop en het model wordt opnieuw opgezet op de achtergrond, waarbij alleen wordt gedownload wat er is veranderd, en herstart op de nieuwe versie. Een model dat gestopt was, blijft gestopt. `omarchy agent local update` doet vanuit een terminal hetzelfde voor elk model.

Vanaf de commandoregel doen `omarchy agent local start <recipe>` en `omarchy agent local stop <recipe>` hetzelfde, toont `omarchy agent local status` elk model, en opent `omarchy agent --local` je standaardagent op het laatste model dat je startte. pi, OpenCode en Qwen Code kunnen er een gebruiken; bij elke andere standaard opent het in pi, of in OpenCode als je pi niet hebt. pi vermeldt ook elk model dat je hebt opgezet, en die op machines waarmee je hebt gekoppeld, in zijn eigen modelkiezer, dus een gewone `pi` bereikt ze ook. Elke met OpenAI compatibele client kan ook verbinden: `status` toont het adres van elk model (het eerste is `http://127.0.0.1:11435/v1`), de receptnaam is het model, en de sleutel staat in `~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` verwijdert een model en de downloads die geen ander model gebruikt.

Runtimes van derden worden gelabeld met hun uitgever. Omarchy draait elk model zonder netwerktoegang.

### Lokale LLM's

Omarchy raadt twee manieren aan om lokale LLM-modellen te draaien: LM Studio en Ollama. LM Studio biedt een GUI-interface om open-weight modellen te vinden, ze te installeren en ze te draaien. Het is een geweldige manier om gemakkelijk op gang te komen. Ollama biedt een CLI om dat op vergelijkbare wijze te doen. Maar als je nieuw bent met lokale modellen, zou ik met LM Studio beginnen. Je kunt een van beide installeren onder _Install > AI_ in het Omarchy Menu.

### De Omarchy-skills

Agent skills helpen AI om specifieke tools op een specifieke manier te gebruiken, en Omarchy levert er zeven van mee. De omarchy skill dekt het op maat maken van het systeem, zoals je Hyprland-config tweaken of de balk aanpassen. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app en omarchy-make-game dekken het maken van iets nieuws, omarchy-contribute dekt het melden van een bug of het upstream sturen van een fix, en omarchy-diagnose-crash werkt zich door de core dump van een crash heen. Ze zijn gesymlinkt naar de skill-mappen voor Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` en elke `~/.hermes/profiles/*/skills`) en de generieke locatie `~/.agents/skills`, dus de meeste harnesses pikken ze automatisch op. Een eigen skill-map met dezelfde naam heeft voorrang.

Maar je moet deze skills als experimenteel beschouwen. Verschillende modellen zullen ze met een verschillend effect gebruiken. Het is het beste om eerst in de planmodus te draaien, zodat je een idee hebt van wat de agent zou willen veranderen. En wees er dan klaar voor om wijzigingen terug te draaien of zelfs `omarchy reinstall configs` aan te roepen, als de agent er een puinhoop van maakt.
