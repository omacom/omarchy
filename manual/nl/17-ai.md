# AI

Omarchy bevat launchers voor de onderstaande coding agents zonder een standaardkeuze voor je te maken. Voer een commando uit om bij eerste gebruik de CLI ervan te installeren en verifieer je vervolgens wanneer daarom wordt gevraagd. Hermes en OpenClaw zijn de uitzonderingen: voor hen wordt niets via mise geïnstalleerd en het kiezen van een van beide stelt een eigen, zichzelf bijwerkende kopie in, zoals _Desktop apps_ hieronder uitlegt.

### Agents installeren en bijwerken

Behalve Hermes en OpenClaw gebruiken deze agents de luie installatie van mise: de eerste start installeert de CLI en latere starts hergebruiken die. mise controleert een geïnstalleerde agent ook hoogstens eens per vier uur op een nieuwe release, net voordat hij start of op de achtergrond bij een shellprompt. Als die update mislukt of je offline bent, draait de geïnstalleerde versie. `omarchy update` werkt geïnstalleerde agents bij samen met de rest van Omarchy, en `mup` werkt alleen door mise beheerde tools bij.

De eigen updater van een agent, zoals `claude update`, `codex update` of een updateknop in een app, werkt de door mise beheerde installatie niet bij. `codex update` mislukt en `claude update` kan succes melden terwijl het een afzonderlijke kopie installeert die mise niet bijhoudt. Als je liever de native installer en updater van een agent gebruikt, voeg hem dan toe aan `disable_tools`; zie [Vooraf geïnstalleerde CLI-tools](18-development-tools.md#preinstalled-cli-tools).

Om alle geconfigureerde luie tools te installeren voordat je ze nodig hebt, voer je `mise install --include-lazy` uit. Dit omvat ook Omarchy's andere standaard-CLI-tools, naast de agents. Zie [Vooraf geïnstalleerde CLI-tools](18-development-tools.md#preinstalled-cli-tools) voor het installeren van één enkele tool of het gebruiken van je eigen installatie.

`grok` wordt geïnstalleerd via mise's first-party `grok`-pakket, op dezelfde manier als `claude` en `codex`. Voer `grok` uit of kies het onder _Agent > Harness_. Sla de `curl | bash`-installer op x.ai over. Die route plaatst een tweede kopie in `~/.grok/bin`, zet die vooraan in `PATH` en overschrijft Omarchy's wrapper.

`dsh` opent zijn browser-UI op `127.0.0.1:3080`, met de startmap als standaardwerkruimte. De browser-UI neemt geen startprompt aan, dus `omarchy agent prompt` opent het met de prompt op je klembord om te plakken. Omarchy start het met DeepSeek's preset voor machtigingen zonder goedkeuring. DeepSeek Harness uploadt sessielogs naar DeepSeek wanneer je zijn officiële model-API gebruikt; zet dat uit onder _Settings > General > Upload Session Log_ in zijn browser-UI. Feedback die je eraan stuurt, wordt ook samen met de sessie geüpload, tenzij je het start met `DSH_TELEMETRY_MODE=DISABLED`.

### De standaardagent

Kies je standaardagent met `omarchy default agent <name>` of onder _Agent > Harness_ in het Omarchy Menu (`Super + Space`). Als de agent nog niet is geïnstalleerd, installeert het kiezen ervan hem eerst, en hij krijgt ook een eigen launcher in de app-launcher, naast Agent. Een verse Omarchy nodigt je met een eenmalige melding uit om deze keuze te maken.

Het kiezen van Claude probeert ook zijn browserextensie voor Chromium, Chrome, Brave, Brave Origin en Edge in te stellen. De extensie-installatie geldt voor alle gebruikers en kan om je systeemwachtwoord vragen; het annuleren of mislukken van de extensie-installatie selecteert en start Claude nog steeds. Herstart je browser, schakel de extensie in als daarom wordt gevraagd en meld je aan bij Claude om de verbinding te voltooien. Voer `/chrome` uit in Claude om de verbinding te controleren. Firefox en Zen ondersteunen deze extensie niet. Als Claude al je standaard was voordat deze installatie werd toegevoegd, selecteer het dan opnieuw om de extensie te installeren.

Zodra je hebt gekozen, start `Super + Shift + Ctrl + A` de standaardagent in een speciaal terminalvenster (of opent de kiezer als je nog niet hebt gekozen). Je kunt hem ook rechtstreeks met een taak starten met `omarchy agent prompt "Review this project"`. Freebuff en DeepSeek Harness nemen geen startprompt aan, dus zij openen in plaats daarvan met de prompt op je klembord om te plakken. Agents die op deze manier worden gestart, draaien zonder toezicht in hun respectieve modi waarin ze niet stoppen om te vragen, dus wees erop voorbereid dat ze echt dingen gaan doen! MiniMax Code heeft geen dergelijke modus voor zijn interactieve sessies, dus het vraagt zoals gebruikelijk om machtigingen. En omdat agents weigeren vertrouwen voor je thuismap te onthouden, starten launches vanuit `$HOME` in plaats daarvan in `~/Work`.

Er zijn ook terminal-snelkoppelingen: `a` draait de standaardagent inline in de huidige terminal, terwijl `c`, `cx` en `cy` OpenCode, Claude Code en Codex rechtstreeks starten (opnieuw in hun modi met automatische goedkeuring). Themaswitches synchroniseren ook naar de agents: Claude Code, Pi, OpenCode en Hermes (zodra Omarchy het heeft geïnstalleerd) volgen allemaal mee wanneer je van Omarchy-thema wisselt.

### Je agent-instructies

Persoonlijke regels voor elke agent horen in `~/.agents/AGENTS.md`, naast de gedeelde skills in `~/.agents/skills`. Open het onder _Agent > Instructions_, wat het ook koppelt aan elke harness die een eigen globaal bestand bijhoudt: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, Copilot's `~/.copilot/copilot-instructions.md`, enzovoort. Crush en Amp lezen de koppeling `~/.config/AGENTS.md`, terwijl omp, Kimi en DeepSeek Harness `~/.agents/AGENTS.md` rechtstreeks lezen. Het kiezen van een standaardagent koppelt het ook. Een instructiebestand dat je al had, wordt het gedeelde bestand als er nog geen was; anders wordt het naast de koppeling bewaard als `.bak`. Voer `omarchy agent instructions` uit om opnieuw te koppelen nadat je een andere agent hebt geïnstalleerd.

### Het agentspaneel

De bovenbalk heeft een agents-icoon. Voordat je een agent hebt ingesteld, leidt het paneel je door het aanmelden bij Claude, Codex of Grok, en de eerste wordt je standaardagent. Daarna zet het paneel elk abonnement op één pagina: elke agent en account met zijn abonnement, een meter voor elk van zijn sessielimieten van 5 uur en wekelijkse limieten met de tijd tot hij wordt gereset (beweeg erover voor het exacte percentage), of het resterende vooruitbetaalde saldo, onder een regel die rouleert door wat je over al die agents heen hebt gebruikt, zoals tokens deze week en je meest gebruikte model. Onder _Make something cool_ biedt het starterprompts voor een nieuw thema, plugin, app of game die de taak aan je standaardagent overhandigen. Apps worden gebouwd zoals Omarchy's eigen Hype, Monologue en Omacut, in C++ en Qt Quick, volgens de omarchy-make-app agent skill, en de compiler en Qt-onderdelen die ze nodig hebben, worden meegeleverd geïnstalleerd. Games zijn één enkele three.js-pagina in `~/Games/vibes`, volgens de omarchy-make-game agent skill, en openen allemaal vanuit één Game Vibes-launcher in het huidige thema; ze laden three.js van het web, dus ze hebben een verbinding nodig om te starten. Claude Code, Codex, Grok, Kimi, Cursor en zijn Grok Bot-tegoed, GitHub Copilot, Muse, Antigravity en Devin worden out of the box gedekt met hun limieten, Kimchi met zijn abonnement, vooruitbetaalde credits en uitgavenbudgetten, en Hermes, Mistral Vibe en Qwen Code tonen hun sessies en tokens zodra je ze hebt gebruikt. Providerabonnementen en -sleutels die je via pi, omp of opencode gebruikt, verschijnen ook: OpenCode Zen en Go, het Z.ai GLM Coding Plan, Ollama Cloud, het MiniMax Token Plan en Synthetic met hun limieten; OpenRouter en DeepSeek met hun vooruitbetaalde saldi; Fireworks met zijn uitgaven over de afgelopen 30 dagen. Tokens van modellen die je op je eigen hardware draait, tellen ook mee voor de totalen; de modellen zelf hebben een eigen paneel, beschreven onder [Lokale modellen](#local-models). Elke agent wordt één keer geteld, onder wie hem ook factureert, via hoeveel harnesses je hem ook aanstuurt.

Klik met de linkermuisknop op het balkicoon of druk op `Super + Ctrl + X` voor het paneel, klik met de rechtermuisknop om je standaardagent te starten en klik met de middelste muisknop om te vernieuwen. De gebruiksrecords erachter worden elke 15 minuten opnieuw gegenereerd door `omarchy agent usage update`, en het paneel kan zelfs gebruik van je andere machines samenvoegen via een gesynchroniseerde map. Zie de README onder `$OMARCHY_PATH/shell/plugins/agents/` voor de volledige instellingen.

### Meerdere abonnementen

Als je voor meer dan één Claude-, Codex- of Grok-abonnement betaalt — bijvoorbeeld een persoonlijk Max en een werkabonnement — kan Omarchy ze allemaal aangemeld houden en ertussen wisselen. Voeg een abonnement toe met de + in het agentspaneel, dat je er daar meteen doorheen leidt, of met `omarchy agent account add claude Work` (of `codex`, of `grok`). Het installeert de CLI als die ontbreekt. Het eerste account voor een provider meldt zich aan via je normale browser, precies waar de CLI altijd kijkt. Elk volgend account meldt zich aan via een privévenster, zodat het account waarbij je browser al is aangemeld niet per ongeluk wordt opgepikt; meld je daar aan als het account dat je toevoegt en sluit eerst elk privévenster dat je al open had. Meld je hiervoor nooit af bij de CLI: afmelden trekt de opgeslagen aanmelding in en dat account zou opnieuw moeten worden toegevoegd.

Om je abonnementsaanmeldingen via SSH naar een andere Omarchy-machine te kopiëren, voer je `omarchy agent account copy user@laptop` uit. De verzender levert een tijdelijke ontvanger wanneer de bestemming er geen geïnstalleerd heeft, zodat oudere Omarchy-machines accounts kunnen ontvangen zonder update. Geïnstalleerde ontvangers hebben voorrang. Dit kopieert alle Claude-, Codex- en Grok-abonnementen; voeg providernamen toe om ze te selecteren, zoals in `omarchy agent account copy laptop claude`. Accountnamen en commando-ID's komen overeen met de bron, inclusief accounts die al op de bestemming aanwezig zijn. Niet-gerelateerde bestemmingsaccounts krijgen een numeriek achtervoegsel als hun namen conflicteren, en instellingen, skills, plugins en gespreksgeschiedenis blijven lokaal op elke machine.

Bestaande bestemmingsgegevens worden bewaard. Een bronaccount dat daar al is aangemeld, krijgt zijn naam gesynchroniseerd zonder zijn gegevens te vervangen; andere accounts worden ernaast toegevoegd. Om opgeslagen gegevens voor overeenkomende accounts te vervangen, gebruik je `omarchy agent account copy --replace laptop claude` nadat je de sessies van dat account op de bestemming hebt afgesloten. Een verse bestemming krijgt ook het actieve account en de wisselvoorkeuren van de bron; een gevestigde bestemming behoudt de zijne.

Gegevens reizen via SSH en worden opgeslagen in privébestanden op de bestemming, dus kopieer alleen naar machines die je vertrouwt. Dit is een eenmalige kopie, geen doorlopende synchronisatie. Codex-refresh-tokens kunnen door een andere machine worden geroteerd, waardoor een gekopieerde aanmelding moet worden vernieuwd; afzonderlijke aanmeldingen blijven de betrouwbaarste keuze voor gelijktijdig gebruik op meerdere machines. Zie [Codex's richtlijnen voor accountauthenticatie](https://developers.openai.com/codex/auth/ci-cd-auth).

Eén account per provider is actief en elke nieuwe sessie begint als dat account: `cx`, `cy`, een gewone `claude`, `codex` of `grok`, alles wat via `omarchy agent` wordt gestart, en scripts of editors die de CLI op `PATH` vinden. Wissel met `omarchy agent account use work` (en terug met `omarchy agent account use main`), of in het paneel door op het nummer van een account en dan op `Enter` te drukken (of op de knop Use ervan te klikken). Draaiende Claude-sessies wisselen ook mee, vanaf hun volgende bericht: elke Claude-sessie draait in `~/.claude`, dat altijd de aanmelding van het actieve account bevat. Een Claude-sessie die door een oudere Omarchy in de eigen map van een account is gestart, behoudt die aanmelding totdat hij wordt afgesloten, dus de wissel benoemt die sessies en eindigt vanzelf zodra ze weg zijn. Draaiende Codex- en Grok-sessies blijven op het account waarmee ze zijn gestart. Gespreksgeschiedenis, instellingen, skills en plugins worden gedeeld tussen accounts, dus `claude --continue` in dezelfde map gaat verder waar je op het nieuwe account was gebleven.

Met meer dan één account toont het paneel de limieten van elk account naast elkaar, met het actieve account gemarkeerd. Standaard meldt Omarchy het je wanneer het actieve account 95% van een limiet passeert, en klikken op de melding wisselt naar het account met de meeste speelruimte. Beweeg over de regel van een account in het paneel en klik op de Autoswitch die naast Use verschijnt (of druk op `m`), of voer `omarchy agent account mode auto` uit, om het in plaats daarvan vanzelf te laten wisselen; zolang het aan staat, neemt Autoswitch de plaats van Use in, en opnieuw erop klikken gaat terug naar melden. Voeg een getal toe om de drempel te veranderen, zoals in `omarchy agent account mode auto 90`. Als elk account boven de drempel zit, hoor je dat één keer, samen met welk account als eerste vrijkomt. Zolang een actief account binnen 15 punten van zijn drempel zit (80% bij de standaard), worden zijn limieten elke drie minuten gecontroleerd in plaats van elke 15.

`omarchy agent account list` toont elk account en zijn nieuwste limieten, `omarchy agent account remove work` vergeet er een, en `omarchy agent account rename primary Hey` hernoemt er een (of klik op de naam van een account in het paneel). Deze commando's werken op de accounts van je standaardagent; om de andere provider te bereiken, noem je die eerst, zoals in `omarchy agent account use codex side`. De aanmelding die je al had in `~/.claude` of `~/.codex` is het _Main_-account. Die van Codex blijft waar hij is; die van Claude wacht in een eigen map zolang een ander account actief is. Een account dat langer dan ongeveer acht uur ongebruikt is gebleven, kan _Sign-in required_ tonen; klik erop om dat account meteen in het paneel opnieuw aan te melden, of wissel ernaar en start een sessie, wat de aanmelding vanzelf vernieuwt. MCP-servers die je met `claude mcp add` toevoegt, bereiken elk Claude-account, aangezien ze allemaal in `~/.claude` draaien; voor Codex en Grok komen servers die je had toen een account werd toegevoegd met dat account mee, maar latere bereiken alleen het account waarin je ze hebt toegevoegd. Claude Desktop houdt een eigen aanmelding bij, en Codex- of Grok-tools die zijn geconfigureerd met een absoluut pad naar een CLI-binary volgen de wissel niet. Een expliciete `CLAUDE_CONFIG_DIR`, `CODEX_HOME` of `GROK_HOME` heeft voorrang op het geselecteerde account.

### Crashdiagnose

Omarchy bewaakt systemd-coredump op procescrashes. Zodra je een standaardagent hebt gekozen, brengt elk programma van je dat core dumpt een melding "Process crashed" — klik erop en de crash wordt overhandigd aan je standaardagent, samen met Omarchy's omarchy-diagnose-crash skill, die de agent begeleidt bij het vaststellen van de feiten uit de core dump en het beslissen of de crash het waard is om upstream te melden. Je kunt het ook handmatig draaien tegen elke PID uit `coredumpctl list` met `omarchy agent crash <pid>`.

Het bewaken staat standaard aan. Zet het uit onder _Trigger > Toggle > Crash Capture Off_ (of met `omarchy toggle crash-capture`) en de meldingen stoppen; `omarchy agent crash <pid>` werkt handmatig nog steeds.

Crashes kunnen ook per programma worden gesilenced, wat de diagnose je aan het einde aanbiedt. `omarchy crash mute hyprland` stopt de meldingen alleen voor dat programma, `omarchy crash mute hyprland off` brengt ze terug, en `omarchy crash mute` op zichzelf somt op wat je hebt gedempt. Het neemt het pad van de binary net zo graag als zijn naam, dus `omarchy crash mute /usr/bin/hyprland` doet hetzelfde. Zet een naam met een spatie erin tussen aanhalingstekens, zoals in `omarchy crash mute 'Some App'`. Al het andere meldt nog steeds, en het gedempte programma crasht nog steeds — dit verbergt de herinnering, het fixt niets.

### Desktop-apps

Het menu _Install > AI_ bevat ook een paar grafische AI-apps: Amp Desktop, Antigravity Desktop, de ChatGPT-desktopapp, de Claude-desktopapp (Anthropic's Linux-bèta, met tabbladen Chat, Cowork en Claude Code), Grok Bot om met xAI's modellen te chatten, Herdr Desktop, Hermes Desktop, OpenClaw, de Perplexity-desktopapp en T3 Code. Grok Bot is de desktop-chatapp. De coding agent is het `grok`-commando.

Hermes Desktop is degene die je moet kennen, omdat een machine één Hermes heeft, en die is van de app: Hermes wordt alleen ooit via de app geïnstalleerd, en het `hermes`-commando dat de standaardagent draait, is dat van de app. Hermes als standaardagent kiezen installeert hetzelfde als de vermelding _Install > AI_: het pakket, en een Hermes-runtime onder `~/.hermes` die is ingesteld door Hermes' eigen installer, wat de eerste keer een paar minuten duurt. Die runtime is de ene Hermes die het terminalcommando `hermes`, de standaardagent en de app allemaal gebruiken, en hij werkt zichzelf bij met `hermes update` in plaats van te wachten op een Omarchy-release. Het installeren ervan geeft Hermes ook het Omarchy-thema als een skin met de naam `omarchy`, die elk Hermes-oppervlak volgt terwijl je van thema wisselt; kies een andere onder Hermes' Appearance-instellingen of met `/skin` als je liever hebt dat hij dat niet doet, en Omarchy laat die keuze met rust. Het verwijderen van de app onder _Remove > AI_ sluit Hermes eerst, gateway inbegrepen, neemt die runtime met zich mee en behoudt je chats, herinneringen en de skills die Hermes voor zichzelf heeft geschreven, tenzij je anders aangeeft: het vraagt, standaard nee, of die gegevens en je verbindingsinstellingen ook weg moeten.

OpenClaw's desktopervaring is zijn Control UI, die opent als een webapp die wordt ondersteund door een eigen lokale gateway. OpenClaw woont in `~/.openclaw` en werkt zichzelf bij: gebruik de knop "Update Gateway" in de Control UI of voer `openclaw update` uit, en de gateway herstart op de nieuwe versie. Omarchy kiest alleen de release waarmee een verse installatie begint. OpenClaw kan ook je standaardagent zijn: het kiezen ervan onder _Agent > Harness_ stelt diezelfde kopie in `~/.openclaw` in, en de agent opent OpenClaw's terminal-UI gekoppeld aan zijn gateway. Het verwijderen van OpenClaw onder _Remove > AI_ neemt de gatewayservice en de app met zich mee en vraagt vervolgens of `~/.openclaw` ook weg moet, aangezien dat je chats en gegevens bewaart naast OpenClaw zelf en de plugin-runtimes die het downloadt; de standaard behoudt het, en OpenClaw opnieuw installeren pikt het weer op.

Herdr Desktop is de desktopapp van [Herdr](https://herdr.dev): spaces, tabs en panes van terminals en coding agents die in zijn kern blijven draaien wanneer je het venster sluit. Het komt van Herdr's eigen installer in plaats van een pakket, dus het woont in `~/.local/share/herdr-app`, brengt zijn kern mee in `~/.local/bin/herdr-core` wanneer je er nog geen hebt, en werkt beide zichzelf bij. Het zit naast het `herdr`-commando dat Omarchy levert op `Super + Ctrl + Return` in plaats van het te vervangen, en krijgt de directe toetsen van dat commando: `Alt + Return` en `Alt + Shift + Return` splitsen een pane naar beneden of naar rechts, `Alt + Escape` sluit het, `Ctrl + Alt + Arrow` beweegt tussen panes, `Alt + 1..9` en `Alt + Left/Right` kiezen een tab, en `Alt + Up/Down` bewegen tussen spaces. `Ctrl + 1..9` kiest een space en `Alt + Shift + Up/Down` stapt door agents. De prefix-toetsen met `Ctrl + Space` blijven alleen voor de terminal, aangezien de app een gewone Ctrl-toets niet kan vasthouden voor een reeks. Omarchy schrijft deze naar `~/.config/herdr-app/keys.json`, en `omarchy-refresh-herdr-app` zet ze terug. Het installeren ervan kiest Herdr's Omarchy-thema, dat vanaf dan je Omarchy-thema volgt. Herdr bewaart één thema voor de lichte modus en één voor de donkere, dus kies na het wisselen tussen een donker en een licht Omarchy-thema Omarchy nog een keer in Herdr's themakiezer voor de andere modus.

T3 Code draait vanuit zijn officiële AppImage-release in `~/.local/share/t3code` in plaats van vanuit een pakket, dus het werkt zichzelf bij. Het installeren ervan vraagt of je op het Stable- of Nightly-kanaal wilt beginnen; wissel later in de instellingen van T3 Code. Je threads en instellingen wonen in `~/.t3`, en het verwijderen van T3 Code onder _Remove > AI_ neemt ze met zich mee.

### Lokale modellen

Draai een open model op je eigen machine voor je coding agents. Je prompts en code blijven op de machine; niets dat naar het model wordt gestuurd, verlaat haar. Begin met:

```bash
omarchy models use best text
```

Dat stelt het beste tekstmodel voor deze machine in, het soort dat je agents gebruiken. Beeld-, video- en muziekmodellen hebben een eigen beste: `omarchy models use best image`, `video` of `music`. Voer `omarchy models use best` uit om de keuze van elk soort voor deze machine te zien.

Of open het paneel voor lokale modellen vanuit zijn sparkles-icoon in de bovenbalk, naast het agents-icoon, of met Super + Ctrl + Alt + X, en kies +. Het icoon verschijnt wanneer een model op deze machine past. Podman, dat de modellen draait, wordt met Omarchy meegeleverd, net als NVIDIA's container toolkit op een NVIDIA-machine, die ze de GPU geeft; als een van beide ontbreekt, installeert de eerste installatie het. Omarchy kiest vervolgens het aanbevolen model voor deze machine, downloadt het en start het. Verwacht een download van tientallen GB en dat het grootste deel van het geheugen van de machine in gebruik is zolang het model draait: Flash Next gebruikt ongeveer 100 GiB met zijn volledige 256K-context. Als andere modellen het geheugen bezet houden dat het nodig heeft, wordt het gestopt ingesteld, klaar om te starten zodra je er een stopt. Het model stopt bij afmelden; stop het zelf wanneer je het geheugen voor iets anders nodig hebt.

`omarchy models list` toont de opties en legt uit waarom sommige niet passen. Om een ander in te stellen, voer je `omarchy models use <recipe>` uit. Vandaag zijn `qwen3.8-flash-next-gufo` en `qwen3.8-27b-gufo` beschikbaar voor 128 GB Strix Halo-machines; de 27B neemt ongeveer 40 GiB, dus hij laat ruimte voor ander werk. Op een 64 GB-laptop met Intel's Arc B390 draait `qwen3.6-35b-a3b-llamacpp` in ongeveer 30 GiB. Nieuwe recipes en aanbevelingen komen mee met `omarchy update`, via het pakket.

Elk model dat je instelt, krijgt een eigen regel in het paneel voor lokale modellen: play om het te starten, pauze om het te stoppen en zijn geheugen vrij te geven, en de terminalknop om je agent erop te openen. Bovenaan toont een balk hoe het geheugen van de machine is verdeeld tussen Omarchy zelf (het systeem en je apps), elk draaiend model en wat vrij is. Wijs naar een gestopt model en de balk toont of het past, of hoeveel het tekortkomt. Meerdere kunnen tegelijk draaien wanneer ze samen in het geheugen passen; als er een niet past, zegt Omarchy welk draaiend model je moet stoppen. Sleep regels aan hun logo om ze opnieuw te ordenen, en druk op Delete op een geselecteerde regel om een model en zijn download te verwijderen.

Elk codingmodel dat je instelt, krijgt ook een eigen vermelding in de app-launcher, onder de naam van het model en met het logo van zijn maker, zoals aanmelden bij Claude, Codex of Grok er een toevoegt. Het opent je agent op dat model en start het model eerst als het niet draait: de terminal toont dat het laadt en draagt over aan de agent zodra het draait. Het verwijderen van een model verwijdert zijn vermelding.

Niet elk model is om te coderen. Beeld-, video- en muziekmodellen openen in plaats daarvan in Fantasi, Omarchy's app om afbeeldingen, video en muziek te maken met een model dat op deze machine draait, daar gekozen of vanuit hun regel in het paneel voor lokale modellen.

Een model blijft precies draaien zoals het was ingesteld, dus een Omarchy-update herstart er nooit een onder je agents. Wanneer Omarchy een nieuwere runtime of nieuwere weights heeft voor een model dat je hebt ingesteld, toont zijn regel een updateknop: druk erop en het model wordt op de achtergrond opnieuw ingesteld, waarbij alleen wordt gedownload wat is veranderd, en herstart op de nieuwe versie. Een model dat was gestopt, blijft gestopt. `omarchy models update` doet hetzelfde voor elk model vanuit een terminal.

Vanaf de commandoregel doen `omarchy models start <recipe>` en `omarchy models stop <recipe>` hetzelfde, `omarchy models status` toont elk model, en `omarchy agent --local` opent je standaardagent op het laatste model dat je hebt gestart. pi, OpenCode en Qwen Code kunnen er een gebruiken; met elke andere standaard opent het in pi, of in OpenCode als je geen pi hebt. pi somt ook elk model op dat je hebt ingesteld, en die op machines waarmee je bent gekoppeld, in zijn eigen modelkiezer, dus gewone `pi` bereikt ze ook. Elke OpenAI-compatibele client kan ook verbinding maken: `status` toont het adres van elk model (de eerste is `http://127.0.0.1:11435/v1`), de recipenaam is het model, en de sleutel staat in `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` verwijdert een model en de downloads die geen ander model gebruikt.

Runtimes van derden worden gelabeld met hun uitgever. Omarchy draait elk model zonder netwerktoegang.

### Lokale LLM's

Omarchy raadt twee manieren aan om lokale LLM-modellen te draaien: LM Studio en Ollama. LM Studio biedt een GUI-interface om open-weight modellen te vinden, te installeren en te draaien. Het is een geweldige manier om gemakkelijk aan de slag te gaan. Ollama biedt een CLI om dat op vergelijkbare wijze te doen. Maar als je nieuw bent met lokale modellen, zou ik met LM Studio beginnen. Je kunt beide installeren onder _Install > AI_ in het Omarchy Menu.

### De Omarchy-skills

Agent skills helpen AI om specifieke tools op een specifieke manier te gebruiken, en Omarchy levert er zeven mee. De omarchy skill dekt het op maat maken van het systeem, zoals het tweaken van je Hyprland-config of het aanpassen van de balk. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app en omarchy-make-game dekken het maken van iets nieuws, omarchy-contribute dekt het melden van een bug of het upstream sturen van een fix, en omarchy-diagnose-crash werkt de core dump van een crash door. Ze zijn gesymlinkt naar de skillmappen voor Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` en elke `~/.hermes/profiles/*/skills`), en de generieke locatie `~/.agents/skills`, dus de meeste harnesses pikken ze automatisch op. Een eigen skillmap met dezelfde naam heeft voorrang.

Maar je moet deze skills als experimenteel beschouwen. Verschillende modellen zullen het met verschillend effect gebruiken. Het is het beste om eerst in planmodus te draaien, zodat je een idee hebt van wat de agent zou willen veranderen. En wees dan klaar om wijzigingen terug te draaien of zelfs `omarchy reinstall configs` aan te roepen, als de agent er een puinhoop van maakt.
