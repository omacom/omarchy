# AI

Omarchy bevat launchers voor de onderstaande coding agents zonder een standaard voor je te kiezen. Voer een commando uit om de CLI ervan bij het eerste gebruik te installeren en authenticeer je vervolgens wanneer daarom wordt gevraagd. Hermes en OpenClaw zijn de uitzonderingen: voor hen wordt niets via mise geïnstalleerd, en als je voor een van beide kiest, wordt de eigen, zichzelf bijwerkende kopie ervan ingesteld, zoals _Desktop-apps_ hieronder uitlegt.

### Agents installeren en bijwerken

Behalve Hermes en OpenClaw gebruiken deze agents de luie installatie van mise: de eerste start installeert de CLI en latere starts hergebruiken die. mise controleert een geïnstalleerde agent ook hooguit eens per vier uur op een nieuwe release, vlak voordat hij start of op de achtergrond bij een shellprompt. Als die update mislukt of je offline bent, draait de geïnstalleerde versie. `omarchy update` werkt geïnstalleerde agents bij samen met de rest van Omarchy, en `mup` werkt alleen door mise beheerde tools bij.

De eigen updater van een agent, zoals `claude update`, `codex update` of een updateknop in een app, werkt de door mise beheerde installatie niet bij. `codex update` mislukt, en `claude update` kan succes melden terwijl het een aparte kopie installeert die mise niet volgt. Als je liever de native installer en updater van een agent gebruikt, voeg die dan toe aan `disable_tools`; zie [Vooraf geïnstalleerde CLI-tools](18-development-tools.md#preinstalled-cli-tools).

Om alle geconfigureerde luie tools te installeren voordat je ze nodig hebt, voer je `mise install --include-lazy` uit. Dit omvat ook de andere standaard-CLI-tools van Omarchy, net als de agents. Zie [Vooraf geïnstalleerde CLI-tools](18-development-tools.md#preinstalled-cli-tools) voor het installeren van één tool of het gebruiken van je eigen installatie.

`grok` wordt geïnstalleerd via het first-party `grok`-pakket van mise, op dezelfde manier als `claude` en `codex`. Voer `grok` uit, of geef het een ster in het agents-paneel. Sla de `curl | bash`-installer op x.ai over. Dat pad plaatst een tweede kopie in `~/.grok/bin`, zet die vooraan op `PATH` en overschrijft de wrapper van Omarchy.

`dsh` opent zijn browser-UI op `127.0.0.1:3080`, met de startmap als standaardwerkruimte. De browser-UI neemt geen startprompt aan, dus `omarchy agent prompt` opent hem met de prompt op je klembord om te plakken. Omarchy start hem met de no-approval-permissiepreset van DeepSeek. DeepSeek Harness uploadt sessielogs naar DeepSeek wanneer je zijn officiële model-API gebruikt; zet dat uit onder _Settings > General > Upload Session Log_ in zijn browser-UI. Feedback die je eraan stuurt, wordt ook met de sessie geüpload, tenzij je hem start met `DSH_TELEMETRY_MODE=DISABLED`.

### De standaardagent

Kies je standaardagent met de ster naast een agent in het agents-paneel, die bij de standaardagent is ingevuld, of met `omarchy default agent <name>`, dat ook elke harness accepteert die daar geen regel heeft. Als de agent nog niet is geïnstalleerd, installeert het kiezen ervan hem eerst, en hij krijgt ook een eigen launcher in de app-launcher, naast Agent. Een verse Omarchy nodigt je uit om er een in te stellen met een eenmalige melding, die het agents-paneel opent.

Als je Claude kiest, wordt ook geprobeerd de browserextensie ervan in te stellen voor Chromium, Chrome, Brave, Brave Origin en Edge. De extensie-installatie geldt voor alle gebruikers en kan om je systeemwachtwoord vragen; annuleren of een mislukte extensie-installatie selecteert en start Claude nog steeds. Herstart je browser, schakel de extensie in als daarom wordt gevraagd en log in bij Claude om de verbinding te voltooien. Voer `/chrome` uit in Claude om de verbinding te controleren. Firefox en Zen ondersteunen deze extensie niet. Als Claude al je standaard was voordat deze installatie werd toegevoegd, selecteer hem dan opnieuw om de extensie te installeren.

Zodra je hebt gekozen, start `Super + Shift + Ctrl + A` de standaardagent in een speciaal terminalvenster (of opent de kiezer als je nog niet hebt gekozen). Je kunt hem ook rechtstreeks met een taak starten met `omarchy agent prompt "Review this project"`. Freebuff en DeepSeek Harness nemen geen startprompt aan, dus zij openen in plaats daarvan met de prompt op je klembord om te plakken. Agents die op deze manier worden gestart, draaien onbeheerd in hun respectieve don't-stop-to-ask-modi, dus wees erop voorbereid dat ze daadwerkelijk dingen gaan doen! MiniMax Code heeft geen dergelijke modus voor zijn interactieve sessies, dus het vraagt zoals gebruikelijk om permissies. En omdat agents weigeren vertrouwen voor je thuismap te onthouden, starten launches vanuit `$HOME` in plaats daarvan in `~/Work`.

Er zijn ook terminal-sneltoetsen: `a` draait de standaardagent inline in de huidige terminal, terwijl `c`, `cx`, `cy` en `ca` OpenCode, Claude Code, Codex en Antigravity rechtstreeks starten (ook weer in hun automatisch-goedkeurende modi). Themawisselingen synchroniseren ook naar de agents: Claude Code, Pi, OpenCode en Hermes (zodra Omarchy hem heeft geïnstalleerd) volgen allemaal mee wanneer je het Omarchy-thema wisselt.

### Je agentinstructies

Persoonlijke regels voor elke agent horen in `~/.agents/AGENTS.md`, naast de gedeelde skills in `~/.agents/skills`. Open het met het documentpictogram naast de + in het agents-paneel, of met `omarchy agent instructions --edit`, dat het ook koppelt in elke harness die een eigen globaal bestand bijhoudt: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, Copilot's `~/.copilot/copilot-instructions.md`, enzovoort. Crush en Amp lezen de link `~/.config/AGENTS.md`, terwijl omp, Kimi en DeepSeek Harness `~/.agents/AGENTS.md` rechtstreeks lezen. Het kiezen van een standaardagent koppelt het ook. Een instructiebestand dat je al had, wordt het gedeelde bestand als er nog geen was; anders wordt het naast de link bewaard als `.bak`. Voer `omarchy agent instructions` uit om opnieuw te koppelen nadat je een andere agent hebt geïnstalleerd.

### Het agents-paneel

De bovenste balk heeft een agents-pictogram. Voordat je een agent hebt ingesteld, biedt het paneel drie manieren om te beginnen: log in op een abonnement van Claude, Codex, Grok, Gemini, Muse, Cursor of Copilot, of onder More een coding-plan van OpenCode Go, MiniMax, Synthetic of Z.ai; betaal per gebruik met Fireworks, OpenCode Zen and Go, OpenRouter, of onder More DeepSeek of elke andere provider waar OpenCode bij inlogt, allemaal gedraaid in OpenCode; of draai het beste model voor jouw computer, wanneer er een bij past. De eerste die je voltooit, wordt je standaardagent, en de + in het paneel biedt later dezelfde drie aan. Daarna zet het paneel elk abonnement op één pagina: elke agent en elk account met zijn plan, een meter voor elk van zijn 5-uurs sessielimieten en wekelijkse limieten met de tijd tot hij reset (beweeg erover voor het exacte percentage), of het resterende prepaid-saldo, onder een regel die rouleert door wat je bij elkaar hebt gebruikt, zoals tokens deze week en je meest gebruikte model. Onder _Make something cool_ biedt het startprompts voor een nieuw thema, plugin, app of game die de taak aan je standaardagent overhandigen. Apps worden gebouwd zoals Omarchy's eigen Hype, Monologue en Omacut, in C++ en Qt Quick, volgens de omarchy-make-app agent skill, en de compiler en Qt-onderdelen die ze nodig hebben, worden meegeleverd. Games zijn een enkele three.js-pagina in `~/Games/vibes`, volgens de omarchy-make-game agent skill, en openen allemaal vanuit één Game Vibes-launcher in het huidige thema; ze laden three.js van het web, dus ze hebben een verbinding nodig om te starten. Claude Code, Codex, Grok, Kimi, Cursor en zijn Grok Bot-tegoed, GitHub Copilot, Muse, Gemini (via Antigravity) en Devin worden out of the box gedekt met hun limieten, Kimchi met zijn plan, prepaid-tegoeden en uitgavenbudgetten, en Hermes, Mistral Vibe en Qwen Code tonen hun sessies en tokens zodra je ze hebt gebruikt. Providerplannen en -sleutels die je via pi, omp of opencode gebruikt, verschijnen ook: OpenCode Zen and Go, het Z.ai GLM Coding Plan, Ollama Cloud, het MiniMax Token Plan en Synthetic met hun limieten; OpenRouter en DeepSeek met hun prepaid-saldi; Fireworks met zijn uitgaven over de afgelopen 30 dagen. Coding-modellen die je op je eigen hardware draait, krijgen hun eigen regels, en hun tokens tellen ook mee in de totalen, zoals beschreven onder [Lokale modellen](#local-models). Elke agent wordt één keer geteld, onder wie hem ook factureert, ongeacht door hoeveel harnesses je hem aanstuurt.

Klik met links op het balkpictogram of druk op `Super + Ctrl + X` voor het paneel, klik met rechts om je standaardagent te starten en klik met het midden om te vernieuwen. De gebruiksrecords erachter worden elke 15 minuten opnieuw gegenereerd door `omarchy agent usage update`, en het paneel kan zelfs gebruik van je andere machines samenvoegen via een gesynchroniseerde map. Zie de README onder `$OMARCHY_PATH/shell/plugins/agents/` voor de volledige instellingen.

### Meerdere abonnementen

Als je betaalt voor meer dan één Claude-, Codex- of Grok-plan — bijvoorbeeld een persoonlijk Max-plan en een werkplan — kan Omarchy ze allemaal ingelogd houden en ertussen wisselen. Voeg een abonnement toe met de + in het agents-paneel, die je er ter plekke doorheen leidt, of met `omarchy agent account add claude Work` (of `codex`, of `grok`). Met dezelfde + en hetzelfde commando log je in op Gemini (`gemini`) en OpenCode (`opencode`), en sla je een API-sleutel van Fireworks (`fireworks`) of OpenRouter (`openrouter`) op in OpenCode; het commando logt ook in op Copilot (`copilot`), Cursor (`cursor`) en Muse (`muse`). Die houden elk één inlog bij. Het installeert de CLI als die ontbreekt. Het eerste account voor een provider logt in via je normale browser, precies waar de CLI altijd kijkt. Elk account daarna logt in via een privévenster, zodat het account waarbij je browser al is ingelogd niet per ongeluk wordt opgepikt; log daar in als het account dat je toevoegt, en sluit eerst elk privévenster dat je al open had. Log nooit uit bij de CLI om dit te doen: uitloggen trekt de opgeslagen inlog in, en dat account zou opnieuw moeten worden toegevoegd.

Om je abonnementsinlogs via SSH naar een andere Omarchy-machine te kopiëren, voer je `omarchy agent account copy user@laptop` uit. De verzender levert een tijdelijke ontvanger wanneer de bestemming er geen heeft geïnstalleerd, zodat oudere Omarchy-machines accounts kunnen ontvangen zonder update. Geïnstalleerde ontvangers hebben voorrang. Dit kopieert alle Claude-, Codex- en Grok-abonnementen; voeg providernamen toe om ze te selecteren, zoals in `omarchy agent account copy laptop claude`. Accountnamen en commando-ID's komen overeen met de bron, inclusief accounts die al op de bestemming aanwezig zijn. Niet-gerelateerde bestemmingsaccounts krijgen een numeriek achtervoegsel als hun namen conflicteren, en instellingen, skills, plugins en gespreksgeschiedenis blijven lokaal op elke machine.

Bestaande bestemmingsgegevens blijven behouden. Een bronaccount dat daar al is ingelogd, krijgt zijn naam gesynchroniseerd zonder zijn gegevens te vervangen; andere accounts worden ernaast toegevoegd. Om opgeslagen gegevens voor overeenkomende accounts te vervangen, gebruik je `omarchy agent account copy --replace laptop claude` nadat je de sessies van dat account op de bestemming hebt afgesloten. Een verse bestemming krijgt ook het actieve account en de wisselvoorkeuren van de bron; een gevestigde bestemming behoudt zijn eigen.

Gegevens reizen via SSH en worden opgeslagen in privébestanden op de bestemming, dus kopieer alleen naar machines die je vertrouwt. Dit is een eenmalige kopie, geen doorlopende synchronisatie. Codex-refresh-tokens kunnen door een andere machine worden geroteerd, waardoor een gekopieerde inlog vernieuwd moet worden; aparte inlogs blijven de betrouwbaarste keuze voor gelijktijdig gebruik op meerdere machines. Zie [de richtlijnen voor accountauthenticatie van Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Eén account per provider is actief, en elke nieuwe sessie begint als dat account: `cx`, `cy`, een gewone `claude`, `codex` of `grok`, alles wat via `omarchy agent` wordt gestart, en scripts of editors die de CLI op `PATH` vinden. Wissel met `omarchy agent account use work` (en terug met `omarchy agent account use main`), of in het paneel door op het nummer van een account en daarna op `Enter` te drukken (of op zijn ster te klikken). Draaiende Claude-sessies wisselen ook mee, vanaf hun volgende bericht: elke Claude-sessie draait in `~/.claude`, dat altijd de inlog van het actieve account bevat. Een Claude-sessie die door een oudere Omarchy in de eigen map van een account is gestart, behoudt die inlog tot hij stopt, dus de wissel benoemt die sessies en eindigt vanzelf zodra ze weg zijn. Draaiende Codex- en Grok-sessies blijven op het account waarmee ze zijn gestart. Gespreksgeschiedenis, instellingen, skills en plugins worden gedeeld tussen accounts, dus `claude --continue` in dezelfde map pikt op waar je was gebleven op het nieuwe account.

Met meer dan één account toont het paneel de limieten van elk account naast elkaar, met een ingevulde ster op het account dat in gebruik is. Omarchy waarschuwt je wanneer het actieve account 95% van een limiet overschrijdt, en klikken op de melding wisselt naar het account met de meeste ruimte. Het wisselt nooit vanzelf. Wijzig de drempel met `omarchy agent account threshold 90`. Als elk account boven de drempel zit, hoor je dat één keer, samen met welk account als eerste vrijkomt. Terwijl een actief account binnen 15 punten van zijn drempel zit (80% bij de standaard), worden zijn limieten elke drie minuten gecontroleerd in plaats van elke 15.

`omarchy agent account list` toont elk account en zijn nieuwste limieten, `omarchy agent account remove work` vergeet er een, en `omarchy agent account rename primary Hey` hernoemt er een (of klik op de naam van een account in het paneel). Deze commando's werken op de accounts van je standaardagent; om de andere provider te bereiken, benoem je die eerst, zoals in `omarchy agent account use codex side`. De inlog die je al had in `~/.claude` of `~/.codex` is het _Main_-account. Die van Codex blijft waar hij is; die van Claude wacht in een eigen map terwijl een ander account actief is. Een account dat meer dan ongeveer acht uur ongebruikt is gebleven, kan _Sign-in required_ tonen; klik erop om dat account direct in het paneel opnieuw in te loggen, of wissel ernaar en start een sessie, wat de inlog vanzelf vernieuwt. MCP-servers die je toevoegt met `claude mcp add` bereiken elk Claude-account, aangezien ze allemaal in `~/.claude` draaien; voor Codex en Grok komen servers die je had toen een account werd toegevoegd mee naar dat account, maar latere alleen naar het account waarin je ze hebt toegevoegd. Claude Desktop houdt een eigen inlog bij, en Codex- of Grok-tools die zijn geconfigureerd met een absoluut pad naar een CLI-binary volgen de wissel niet. Een expliciete `CLAUDE_CONFIG_DIR`, `CODEX_HOME` of `GROK_HOME` heeft voorrang op het geselecteerde account.

### Crashdiagnose

Omarchy houdt systemd-coredump in de gaten voor procescrashes. Zodra je een standaardagent hebt gekozen, brengt elk programma van jou dat core dumpt een melding "Process crashed" — klik erop, en de crash wordt overhandigd aan je standaardagent samen met Omarchy's omarchy-diagnose-crash skill, die de agent door het vaststellen van de feiten uit de core dump leidt en beslist of de crash het waard is om upstream te melden. Je kunt het ook handmatig uitvoeren tegen elke PID uit `coredumpctl list` met `omarchy agent crash <pid>`.

Het kijken is standaard ingeschakeld. Zet het uit onder _Trigger > Toggle > Crash Capture Off_ (of met `omarchy toggle crash-capture`) en de meldingen stoppen; `omarchy agent crash <pid>` werkt nog steeds handmatig.

Crashes kunnen ook per programma worden gedempt, wat de diagnose je aan het einde aanbiedt. `omarchy crash mute hyprland` stopt de meldingen alleen voor dat programma, `omarchy crash mute hyprland off` brengt ze terug, en `omarchy crash mute` op zichzelf vermeldt wat je hebt gedempt. Het accepteert het pad van de binary net zo graag als zijn naam, dus `omarchy crash mute /usr/bin/hyprland` doet hetzelfde. Zet een naam met een spatie erin tussen aanhalingstekens, zoals in `omarchy crash mute 'Some App'`. Al het andere blijft melden, en het gedempte programma crasht nog steeds — dit verbergt de herinnering, het fixt niets.

### Desktop-apps

Het menu _Install > AI_ bevat ook een paar grafische AI-apps: Amp Desktop, Antigravity Desktop, de ChatGPT-desktopapp, de Claude-desktopapp (de Linux-bèta van Anthropic, met tabbladen Chat, Cowork en Claude Code), Grok Bot om te chatten met de modellen van xAI, Herdr Desktop, Hermes Desktop, OpenClaw, de Perplexity-desktopapp en T3 Code. Grok Bot is de desktopchatapp. De coding agent is het `grok`-commando.

Hermes Desktop is degene die je moet kennen, omdat een machine één Hermes heeft, en die is van de app: Hermes wordt alleen ooit via de app geïnstalleerd, en het `hermes`-commando dat de standaardagent draait, is van de app. Hermes kiezen als standaardagent installeert hetzelfde als de vermelding _Install > AI_: het pakket, en een Hermes-runtime onder `~/.hermes` die is ingesteld door Hermes' eigen installer, wat de eerste keer een paar minuten duurt. Die runtime is de ene Hermes die het terminalcommando `hermes`, de standaardagent en de app allemaal gebruiken, en hij werkt zichzelf bij met `hermes update` in plaats van te wachten op een Omarchy-release. Installeren ervan geeft Hermes ook het Omarchy-thema als een skin genaamd `omarchy`, die elk Hermes-oppervlak volgt terwijl je van thema wisselt; kies een andere onder Hermes' Appearance-instellingen of met `/skin` als je liever niet wilt dat hij dat doet, en Omarchy laat die keuze met rust. De app verwijderen onder _Remove > AI_ sluit Hermes eerst, gateway inbegrepen, neemt die runtime mee, en behoudt je chats, herinneringen en de skills die Hermes voor zichzelf heeft geschreven, tenzij je anders aangeeft: het vraagt, standaard nee, of die gegevens en je verbindingsinstellingen ook weg moeten.

De desktopervaring van OpenClaw is zijn Control UI, die opent als een webapp die wordt ondersteund door zijn eigen lokale gateway. OpenClaw leeft in `~/.openclaw` en werkt zichzelf bij: gebruik de knop "Update Gateway" van de Control UI of voer `openclaw update` uit, en de gateway herstart op de nieuwe versie. Omarchy kiest alleen de release waarmee een verse installatie begint. OpenClaw kan ook je standaardagent zijn: hem kiezen met `omarchy default agent openclaw` stelt diezelfde kopie in `~/.openclaw` in, en de agent opent de terminal-UI van OpenClaw die aan zijn gateway is gekoppeld. OpenClaw verwijderen onder _Remove > AI_ neemt de gatewayservice en de app mee en vraagt daarna of `~/.openclaw` ook weg moet, aangezien dat je chats en gegevens bewaart naast OpenClaw zelf en de pluginruntimes die het downloadt; standaard blijft het behouden, en OpenClaw opnieuw installeren pikt het weer op.

Herdr Desktop is de desktopapp van [Herdr](https://herdr.dev): spaces, tabbladen en panelen van terminals en coding agents die in zijn kern blijven draaien wanneer je het venster sluit. Het komt van Herdr's eigen installer in plaats van een pakket, dus het leeft in `~/.local/share/herdr-app`, brengt zijn kern mee in `~/.local/bin/herdr-core` wanneer je er nog geen hebt, en werkt beide zichzelf bij. Het staat naast het `herdr`-commando dat Omarchy levert op `Super + Ctrl + Return` in plaats van het te vervangen, en krijgt de directe toetsen van dat commando: `Alt + Return` en `Alt + Shift + Return` splitsen een paneel naar beneden of naar rechts, `Alt + Escape` sluit het, `Ctrl + Alt + Arrow` beweegt tussen panelen, `Alt + 1..9` en `Alt + Left/Right` kiezen een tabblad, en `Alt + Up/Down` bewegen tussen spaces. `Ctrl + 1..9` kiest een space en `Alt + Shift + Up/Down` stapt door agents. De prefix-toetsen `Ctrl + Space` blijven alleen voor de terminal, aangezien de app een gewone Ctrl-toets niet kan vasthouden voor een reeks. Omarchy schrijft deze naar `~/.config/herdr-app/keys.json`, en `omarchy-refresh-herdr-app` zet ze terug. Installeren ervan kiest Herdr's Omarchy-thema, dat vanaf dan je Omarchy-thema volgt. Herdr houdt één thema voor de lichte modus en één voor de donkere, dus na het wisselen tussen een donker en een licht Omarchy-thema kies je Omarchy nog een keer in Herdr's themakiezer voor de andere modus.

T3 Code draait vanaf zijn officiële AppImage-release in `~/.local/share/t3code` in plaats van een pakket, dus het werkt zichzelf bij. Installeren ervan vraagt of je op het Stable- of Nightly-kanaal wilt beginnen; wissel later in de instellingen van T3 Code. Je threads en instellingen leven in `~/.t3`, en T3 Code verwijderen onder _Remove > AI_ neemt ze mee.

### Lokale modellen

Draai een open model op je eigen machine voor je coding agents. Je prompts en code blijven op de machine; niets dat naar het model wordt gestuurd, verlaat haar. Begin met:

```bash
omarchy models use best text
```

Dat stelt het beste tekstmodel voor deze machine in, het soort dat je agents gebruiken. Beeld-, video- en muziekmodellen hebben hun eigen beste: `omarchy models use best image`, `video` of `music`. Voer `omarchy models use best` uit om de keuze van elk soort voor deze machine te zien.

Of kies + in het agents-paneel: onder _Use a local model_ vermeldt het elk coding-model dat op deze machine past, het aanbevolen model eerst. Podman, dat de modellen draait, wordt met Omarchy meegeleverd, net als NVIDIA's container toolkit op een NVIDIA-machine, die ze de GPU geeft; als een van beide ontbreekt, installeert de eerste installatie het. Omarchy kiest dan het aanbevolen model voor deze machine, downloadt het en start het. Verwacht een download van tientallen GB en dat het grootste deel van het geheugen van de machine in gebruik is terwijl het model draait: Flash Next gebruikt ongeveer 100 GiB met zijn volledige 256K-context. Als andere modellen het geheugen bezetten dat het nodig heeft, wordt het gestopt ingesteld, klaar om te starten zodra je er een stopt. Het model stopt bij uitloggen; stop het zelf wanneer je het geheugen voor iets anders nodig hebt.

`omarchy models list` toont de opties en legt uit waarom sommige niet passen. Om een ander in te stellen, voer je `omarchy models use <recipe>` uit. Vandaag zijn `qwen3.8-flash-next-gufo` en `qwen3.8-27b-gufo` beschikbaar voor 128 GB Strix Halo-machines; de 27B gebruikt ongeveer 40 GiB, dus hij laat ruimte voor ander werk. Op een 64 GB-laptop met Intel's Arc B390 draait `qwen3.6-35b-a3b-llamacpp` in ongeveer 30 GiB. Nieuwe recepten en aanbevelingen arriveren met `omarchy update`, via het pakket.

Een coding-model dat je toevoegt, krijgt zijn eigen regel in het agents-paneel, naast je abonnementen: afspelen om het te starten, pauzeren om het te stoppen en zijn geheugen vrij te geven, het Tailscale-merkteken om het te delen met de andere machines op je tailnet terwijl het draait, en de terminalknop om je agent erop te openen. Zijn regel toont de download, het laden of stoppen terwijl het gebeurt, en zegt het wanneer er niet genoeg vrij geheugen is om het te starten, of linkt naar zijn logs wanneer het met een fout is gestopt. Meerdere kunnen tegelijk draaien wanneer ze samen in het geheugen passen. Druk op Delete op een geselecteerde regel om het model van deze machine te verwijderen, download en alles; + kan het opnieuw instellen. Een coding-model dat vanaf een terminal is ingesteld, wacht onder + tot je het toevoegt, en dat doen ook de modellen die een machine waarmee je hebt gepaard (`omarchy models pair <host>`) draait.

Elk coding-model dat je instelt, krijgt ook zijn eigen vermelding in de app-launcher, onder de naam van het model en met het logo van zijn maker, zoals inloggen op Claude, Codex of Grok er een toevoegt. Het opent je agent op dat model, en start het model eerst als het niet draait: de terminal toont dat het laadt en draagt over aan de agent zodra het actief is. Een model verwijderen verwijdert zijn vermelding.

Niet elk model is om te coderen. Beeld-, video- en muziekmodellen openen in plaats daarvan in Fantasi, Omarchy's app om afbeeldingen, video en muziek te maken met een model dat op deze machine draait, en worden daar beheerd of met `omarchy models`.

Een model blijft precies draaien zoals het is ingesteld, dus een Omarchy-update herstart er nooit een onder je agents. Wanneer Omarchy een nieuwere runtime of nieuwere gewichten heeft voor een model dat je hebt ingesteld, toont zijn regel een updateknop: druk erop en het model wordt op de achtergrond opnieuw ingesteld, waarbij alleen wordt gedownload wat is veranderd, en herstart op de nieuwe versie. Een model dat gestopt was, blijft gestopt. `omarchy models update` doet hetzelfde voor elk model vanaf een terminal.

Vanaf de commandoregel doen `omarchy models start <recipe>` en `omarchy models stop <recipe>` hetzelfde, toont `omarchy models status` elk model, en opent `omarchy agent --local-model <recipe>` dat model in pi, wat je standaardagent ook is. Om je lokale model te maken tot wat de agent-sneltoets, de Quake-console en _Make something_ openen, voer je `omarchy default agent local` uit of geef je een draaiend model een ster in het agents-paneel. pi vermeldt ook elk model dat je hebt ingesteld, en die op machines waarmee je hebt gepaard, in zijn eigen modelkiezer, dus gewone `pi` bereikt ze ook. Elke OpenAI-compatibele client kan ook verbinden: `status` toont het adres van elk model (het eerste is `http://127.0.0.1:11435/v1`), de receptnaam is het model, en de sleutel staat in `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` verwijdert een model en de downloads die geen ander model gebruikt.

Runtimes van derden worden gelabeld met hun uitgever. Omarchy draait elk model zonder netwerktoegang.

### Lokale LLM's

Omarchy raadt twee manieren aan om lokale LLM-modellen te draaien: LM Studio en Ollama. LM Studio biedt een GUI-interface om open-weight-modellen te vinden, ze te installeren en ze te draaien. Het is een geweldige manier om gemakkelijk aan de slag te gaan. Ollama biedt een CLI om dat op vergelijkbare wijze te doen. Maar als je nieuw bent met lokale modellen, zou ik beginnen met LM Studio. Je kunt beide installeren onder _Install > AI_ in het Omarchy Menu.

### De Omarchy-skills

Agent skills helpen AI om specifieke tools op een specifieke manier te gebruiken, en Omarchy levert er zeven. De omarchy skill dekt het op maat maken van het systeem, zoals je Hyprland-config aanpassen of de balk bijstellen. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app en omarchy-make-game dekken het maken van iets nieuws, omarchy-contribute dekt het melden van een bug of het upstream sturen van een fix, en omarchy-diagnose-crash werkt de core dump van een crash door. Ze zijn gesymlinkt in de skill-mappen voor Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` en elke `~/.hermes/profiles/*/skills`), en de generieke locatie `~/.agents/skills`, dus de meeste harnesses pikken ze automatisch op. Een eigen skill-map met dezelfde naam heeft voorrang.

Maar je moet deze skills als experimenteel beschouwen. Verschillende modellen zullen ze met verschillend effect gebruiken. Het is het beste om eerst in planmodus te draaien, zodat je een idee hebt van wat de agent zou willen veranderen. En wees dan klaar om wijzigingen terug te draaien of zelfs `omarchy reinstall configs` aan te roepen, als de agent er een puinhoop van maakt.
