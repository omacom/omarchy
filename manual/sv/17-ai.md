# AI

Omarchy innehåller startprogram för kodningsagenterna nedan utan att välja en standard åt dig. Kör ett kommando för att installera dess CLI vid första användningen och autentisera dig sedan när du uppmanas att göra det. Hermes är undantaget: ingenting installeras för den vid första användningen, och att välja den installerar Hermes Desktop, vilket _Skrivbordsappar_ nedan förklarar.

### Installera och uppdatera agenter

Med undantag för Hermes använder dessa agenter mises lata installation: första starten installerar CLI:t, och senare starter återanvänder det. mise kontrollerar också en installerad agent efter en ny version högst en gång var fjärde timme, precis innan den startar eller i bakgrunden vid en shellprompt. Om uppdateringen misslyckas eller om du är offline körs den installerade versionen. `omarchy update` uppdaterar installerade agenter tillsammans med resten av Omarchy, och `mup` uppdaterar endast mise-hanterade verktyg.

En agents egen uppdaterare, som `claude update`, `codex update` eller en uppdateringsknapp i en app, uppdaterar inte den mise-hanterade installationen. `codex update` misslyckas, och `claude update` kan rapportera att det lyckades samtidigt som den installerar en separat kopia som mise inte spårar. Om du hellre vill använda en agents inbyggda installerare och uppdaterare lägger du till den i `disable_tools`; se [Förinstallerade CLI-verktyg](18-development-tools.md#preinstalled-cli-tools).

För att installera alla konfigurerade lata verktyg innan du behöver dem kör du `mise install --include-lazy`. Detta inkluderar Omarchys andra standard-CLI-verktyg såväl som agenterna. Se [Förinstallerade CLI-verktyg](18-development-tools.md#preinstalled-cli-tools) för att installera ett enskilt verktyg eller använda din egen installation.

`grok` installeras via mises förstaparts-paket `grok`, på samma sätt som `claude` och `codex`. Kör `grok`, eller välj den under _Setup > Defaults > Agent_. Hoppa över `curl | bash`-installeraren på x.ai. Den vägen lägger en andra kopia i `~/.grok/bin`, lägger den först på `PATH` och skriver över Omarchys wrapper.

`dsh` öppnar sitt webbläsargränssnitt på `127.0.0.1:3080`, med startkatalogen som standardarbetsyta. Dess webbläsargränssnitt tar ingen startprompt, så `omarchy agent prompt` öppnar det med prompten på urklippet för att klistra in. Omarchy startar det med DeepSeeks förinställning för behörigheter utan godkännande. DeepSeek Harness laddar upp sessionsloggar till DeepSeek när du använder dess officiella modell-API; stäng av det under _Settings > General > Upload Session Log_ i dess webbläsargränssnitt. Feedback som du skickar till den laddas också upp tillsammans med sessionen, om du inte startar den med `DSH_TELEMETRY_MODE=DISABLED`.

### Standardagenten

Välj din standardagent med `omarchy default agent <name>` eller under _Setup > Defaults > Agent_ i Omarchy Menu (`Super + Space`). Om agenten inte är installerad ännu installerar valet den först. En ny Omarchy-installation bjuder in dig att göra detta val med en engångsavisering.

Att välja Claude försöker också konfigurera dess webbläsartillägg för Chromium, Chrome, Brave, Brave Origin och Edge. Konfigurationen av tillägget gäller alla användare och kan be om ditt systemlösenord; att avbryta eller en misslyckad installation av tillägget väljer och startar ändå Claude. Starta om din webbläsare, aktivera tillägget om du uppmanas att göra det och logga in på Claude för att slutföra anslutningen. Kör `/chrome` i Claude för att kontrollera anslutningen. Firefox och Zen stöder inte detta tillägg. Om Claude redan var din standard innan denna konfiguration lades till väljer du den igen för att installera tillägget.

När du har valt startar `Super + Shift + Ctrl + A` standardagenten i ett dedikerat terminalfönster (eller tar fram väljaren om du inte har valt ännu). Du kan också starta den rakt in i en uppgift med `omarchy agent prompt "Review this project"`. Freebuff och DeepSeek Harness tar ingen startprompt, så de öppnas istället med prompten på urklippet för att klistra in. Agenter som startas på detta sätt körs utan uppsikt i sina respektive lägen där de inte stannar för att fråga, så var beredd på att de faktiskt gör saker! MiniMax Code har inget sådant läge för sina interaktiva sessioner, så den ber om behörigheter som vanligt. Och eftersom agenter vägrar att komma ihåg förtroende för din hemkatalog startar starter från `$HOME` istället i `~/Work`.

Det finns också terminalgenvägar: `a` kör standardagenten inline i den aktuella terminalen, medan `c`, `cx` och `cy` startar OpenCode, Claude Code och Codex direkt (återigen i deras automatiskt godkännande lägen). Temabyten synkroniseras också till agenterna: Claude Code, Pi, OpenCode och Hermes (när Omarchy har installerat den) följer alla med när du byter Omarchy-tema.

### Agentpanelen

Den övre listen har en agentikon. Innan du har konfigurerat en agent vägleder dess panel dig genom att logga in på Claude, Codex eller Grok, och den första blir din standardagent. Därefter samlar panelen varje prenumeration på en sida: varje agent och konto med dess plan, en mätare för var och en av dess gränser för 5-timmarssessioner och veckogränser med tiden tills den återställs (hovra för exakt procent), eller det återstående förbetalda saldot, under en rad som roterar genom vad du har använt över dem alla, som tokens denna vecka och din mest använda modell. Under _Make something_ erbjuder den startprompter för ett nytt tema, plugin eller en ny app som lämnar över uppgiften till din standardagent. Appar byggs på samma sätt som Omarchys egna Hype, Monologue och Omacut, i C++ och Qt Quick, enligt agent-skillen omarchy-app, och kompilatorn och Qt-delarna de behöver följer med installerade. Claude Code, Codex, Grok, Kimi, Cursor och dess Grok Bot-tilldelning, GitHub Copilot, Muse, Antigravity, Kimchi och Devin täcks direkt från start med sina gränser, och Hermes, Mistral Vibe och Qwen Code visar sina sessioner och tokens när du har använt dem. Leverantörsplaner och nycklar som du använder via pi, omp eller opencode dyker också upp: OpenCode Zen och Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan och Synthetic med sina gränser; Fireworks, OpenRouter och DeepSeek med sina förbetalda saldon; och modellerna du kör på din egen hårdvara under Lokala modeller. Varje agent räknas en gång, under den som fakturerar den, oavsett hur många harnessar du kör den genom.

Vänsterklicka på ikonen i listen för panelen, högerklicka för att starta din standardagent. Användningsposterna bakom den återskapas var 15:e minut av `omarchy agent usage-update`, och panelen kan till och med slå samman användning från dina andra maskiner via en synkroniserad mapp. Se README under `$OMARCHY_PATH/shell/plugins/agents/` för de fullständiga inställningarna.

### Flera prenumerationer

Om du betalar för mer än en Claude-, Codex- eller Grok-plan — en personlig Max och en för arbetet, säg — kan Omarchy hålla dem alla inloggade och flytta mellan dem. Lägg till en prenumeration med + i agentpanelen, som vägleder dig genom det direkt där, eller med `omarchy agent account add claude Work` (eller `codex`, eller `grok`). Den installerar CLI:t om det saknas. Det första kontot för en leverantör loggar in genom din normala webbläsare, precis där CLI:t alltid tittar. Varje konto efter det loggar in genom ett privat fönster, så att kontot som din webbläsare redan är inloggad på inte plockas upp av misstag; logga in där som kontot du lägger till, och stäng först alla privata fönster du redan har öppna. Logga aldrig ut ur CLI:t för att göra detta: att logga ut återkallar den sparade inloggningen, och det kontot skulle behöva läggas till igen.

För att kopiera dina prenumerationsinloggningar till en annan Omarchy-maskin över SSH kör du `omarchy agent account copy user@laptop`. Avsändaren tillhandahåller en tillfällig mottagare när destinationen inte har en installerad, så äldre Omarchy-maskiner kan ta emot konton utan en uppdatering. Installerade mottagare har företräde. Detta kopierar alla Claude-, Codex- och Grok-prenumerationer; lägg till leverantörsnamn för att välja dem, som i `omarchy agent account copy laptop claude`. Kontonamn och kommando-ID:n matchar källan, inklusive konton som redan finns på destinationen. Orelaterade destinationskonton får ett numeriskt suffix om deras namn krockar, och inställningar, skills, plugins och konversationshistorik förblir lokala för varje maskin.

Befintliga destinationsuppgifter behålls. Ett källkonto som redan är inloggat där får sitt namn synkroniserat utan att ersätta sina uppgifter; andra konton läggs till bredvid det. För att ersätta sparade uppgifter för matchande konton använder du `omarchy agent account copy --replace laptop claude` efter att ha avslutat det kontots sessioner på destinationen. En ny destination får också källans aktiva konto och växlingsinställningar; en etablerad destination behåller sina egna.

Uppgifter färdas genom SSH och lagras i privata filer på destinationen, så kopiera endast till maskiner du litar på. Detta är en engångskopiering, inte löpande synkronisering. Codex refresh tokens kan roteras av en annan maskin, vilket lämnar en kopierad inloggning i behov av förnyelse; separata inloggningar förblir det mest tillförlitliga valet för samtidig användning på flera maskiner. Se [Codexs vägledning för kontoautentisering](https://developers.openai.com/codex/auth/ci-cd-auth).

Ett konto per leverantör är aktivt, och varje ny session börjar som det: `cx`, `cy`, en vanlig `claude`, `codex` eller `grok`, allt som startas genom `omarchy agent`, och skript eller redigerare som hittar CLI:t på `PATH`. Växla med `omarchy agent account use work` (och tillbaka med `omarchy agent account use main`), eller i panelen genom att trycka på ett kontos nummer och sedan `Enter` (eller klicka på dess Use-knapp). Sessioner som redan körs stannar kvar på kontot de började med. Konversationshistorik, inställningar, skills och plugins delas mellan konton, så `claude --continue` i samma mapp fortsätter där du slutade på det nya kontot.

Med mer än ett konto visar panelen varje kontos gränser sida vid sida, med det aktiva markerat. Som standard meddelar Omarchy dig när det aktiva kontot passerar 95 % av en gräns, och att klicka på aviseringen växlar till kontot med mest utrymme kvar. Hovra över ett kontos rad i panelen och klicka på Autoswitch som dyker upp bredvid Use (eller tryck på `m`), eller kör `omarchy agent account mode auto`, för att få det att växla på egen hand istället; medan det är på tar Autoswitch Uses plats, och att klicka på det igen går tillbaka till att meddela. Lägg till ett nummer för att ändra tröskeln, som i `omarchy agent account mode auto 90`. Om varje konto ligger över tröskeln får du höra om det en gång, tillsammans med vilket konto som frigörs först. Medan ett aktivt konto är inom 15 punkter från sin tröskel (80 % som standard) kontrolleras dess gränser var tredje minut istället för var 15:e.

`omarchy agent account list` visar varje konto och dess senaste gränser, `omarchy agent account remove work` glömmer ett, och `omarchy agent account rename primary Hey` byter namn på ett (eller klicka på ett kontos namn i panelen). Dessa kommandon fungerar på din standardagents konton; för att nå den andra leverantören namnger du den först, som i `omarchy agent account use codex side`. Inloggningen du redan hade i `~/.claude` eller `~/.codex` är _Main_-kontot och stannar där den är. Ett konto som har lämnats oanvänt i mer än ungefär åtta timmar kan visa _Sign-in required_; klicka på det för att logga in det kontot igen direkt i panelen, eller starta en session i det, vilket uppdaterar inloggningen på egen hand. MCP-servrar du hade när ett konto lades till följer med till det, men sådana du lägger till senare med `claude mcp add` når endast kontot du lade till dem i. Claude Desktop och verktyg som konfigurerats med en absolut sökväg till en CLI-binär följer inte med växlingen. Ett explicit `CLAUDE_CONFIG_DIR`, `CODEX_HOME` eller `GROK_HOME` har företräde framför det valda kontot.

### Kraschdiagnostik

Omarchy bevakar systemd-coredump för processkrascher. När något segfaultar får du en avisering om "Process crashed" — klicka på den, så lämnas kraschen över till din standardagent tillsammans med Omarchys diagnose-crash-skill, som vägleder agenten genom att fastställa fakta från core dumpen och avgöra om kraschen är värd att rapportera uppströms. Du kan också köra den för hand mot valfri PID från `coredumpctl list` med `omarchy agent crash <pid>`.

Bevakningen är på som standard. Stäng av den under _Trigger > Toggle > Crash Capture_ (eller med `omarchy toggle crash-capture`) så slutar aviseringarna; `omarchy agent crash <pid>` fungerar fortfarande för hand.

Krascher kan också tystas ett program i taget, vilket är vad diagnosen erbjuder dig i slutet. `omarchy crash mute hyprland` stoppar aviseringarna för endast det programmet, `omarchy crash mute hyprland off` tar tillbaka dem, och `omarchy crash mute` på egen hand listar vad du har tystat. Den tar binärens sökväg lika glatt som dess namn, så `omarchy crash mute /usr/bin/hyprland` gör samma sak. Sätt citattecken runt ett namn med ett mellanslag i, som i `omarchy crash mute 'Some App'`. Allt annat aviserar fortfarande, och det tystade programmet kraschar fortfarande — detta döljer påminnelsen, det fixar ingenting.

### Skrivbordsappar

Menyn _Install > AI_ innehåller också några grafiska AI-appar: ChatGPTs skrivbordsapp, Claudes skrivbordsapp (Anthropics Linux-beta, med flikarna Chat, Cowork och Claude Code), Grok Bot för att chatta med xAIs modeller, Hermes Desktop, OpenClaw, Perplexitys skrivbordsapp och T3 Code. Grok Bot är skrivbordschattappen. Kodningsagenten är kommandot `grok`.

Hermes Desktop är den du bör känna till, eftersom en maskin har en Hermes, och den tillhör appen: Hermes installeras endast någonsin genom appen, och kommandot `hermes` som standardagenten kör är appens. Att välja Hermes som standardagent installerar samma sak som menyposten _Install > AI_ gör: paketet, och en Hermes-runtime under `~/.hermes` som konfigurerats av Hermes egen installerare, vilket tar några minuter första gången. Den runtimen är den enda Hermes som terminalkommandot `hermes`, standardagenten och appen alla använder, och den uppdaterar sig själv med `hermes update` snarare än att vänta på en Omarchy-version. Att installera den ger också Hermes Omarchy-temat som ett skin med namnet `omarchy`, som varje Hermes-yta följer när du byter tema; välj ett annat under Hermes Appearance-inställningar eller med `/skin` om du hellre vill att den inte gör det, och Omarchy lämnar det valet i fred. Att ta bort appen under _Remove > AI_ stänger Hermes först, inklusive gatewayen, tar med sig den runtimen, och behåller dina chattar, minnen och de skills som Hermes skrev åt sig själv om du inte säger något annat: den frågar, med nej som standard, om den datan och dina anslutningsinställningar också ska försvinna.

OpenClaws skrivbordsupplevelse är dess Control UI, som öppnas som en webbapp med stöd av dess egen lokala gateway. OpenClaw bor i `~/.openclaw` och uppdaterar sig själv: använd Control UI:s knapp "Update Gateway" eller kör `openclaw update`, så startar gatewayen om på den nya versionen. Omarchy väljer endast vilken version en ny installation börjar från. Att ta bort OpenClaw under _Remove > AI_ tar med sig gatewaytjänsten och appen och frågar sedan om `~/.openclaw` också ska försvinna, eftersom den innehåller dina chattar och uppgifter tillsammans med OpenClaw själv och de plugin-runtimes den laddar ner; standardvalet behåller den, och att installera OpenClaw igen tar upp den på nytt.

T3 Code körs från sin officiella AppImage-version i `~/.local/share/t3code` snarare än från ett paket, så den uppdaterar sig själv. Att installera den frågar om du vill börja på kanalen Stable eller Nightly; byt senare i T3 Codes inställningar. Dina trådar och inställningar bor i `~/.t3`, och att ta bort T3 Code under _Remove > AI_ tar med sig dem.

### Lokala LLM:er

Omarchy rekommenderar två sätt att köra lokala LLM-modeller: LM Studio och Ollama. LM Studio tillhandahåller ett GUI-gränssnitt för att hitta modeller med öppna vikter, installera dem och köra dem. Det är ett utmärkt sätt att komma igång enkelt. Ollama erbjuder ett CLI för att göra det på liknande sätt. Men om du är ny på lokala modeller skulle jag börja med LM Studio. Du kan installera endera under _Install > AI_ i Omarchy Menu.

### Omarchy-skillen

Agent-skills hjälper AI att använda specifika verktyg på ett specifikt sätt, och Omarchy levereras med en standard-skill för att skräddarsy systemet. Som att justera din Hyprland-konfiguration, anpassa listen, eller till och med skapa ett helt nytt tema från grunden. Den är symlänkad in i skill-katalogerna för Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` och varje `~/.hermes/profiles/*/skills`), och den generiska platsen `~/.agents/skills`, så de flesta harnessar plockar upp den automatiskt.

Men du bör behandla denna skill som experimentell. Olika modeller kommer att använda den med olika effekt. Det är bäst att köra i planläge först, så du har en uppfattning om vad agenten skulle vilja ändra. Och var sedan redo att rulla tillbaka ändringar eller till och med anropa `omarchy reinstall configs`, om agenten ställer till med oreda överallt.
