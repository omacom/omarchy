# AI

Kör ett kommando för att installera dess CLI vid första användningen, och autentisera sedan när du uppmanas att göra det. Hermes och OpenClaw är undantagen: ingenting installeras för dem via mise, och att välja någon av dem sätter upp dess egen självuppdaterande kopia, som _Skrivbordsappar_ nedan förklarar.

### Installera och uppdatera agenter

Med undantag för Hermes och OpenClaw använder dessa agenter mises lata installation: den första starten installerar CLI:t, och senare starter återanvänder det. mise kontrollerar också en installerad agent efter en ny version högst en gång var fjärde timme, precis innan den startar eller i bakgrunden vid en skalprompt. Om den uppdateringen misslyckas eller om du är offline körs den installerade versionen. `omarchy update` uppdaterar installerade agenter tillsammans med resten av Omarchy, och `mup` uppdaterar endast mise-hanterade verktyg.

En agents egen uppdaterare, som `claude update`, `codex update` eller en uppdateringsknapp i en app, uppdaterar inte den mise-hanterade installationen. `codex update` misslyckas, och `claude update` kan rapportera framgång samtidigt som den installerar en separat kopia som mise inte spårar. Om du hellre vill använda en agents inbyggda installerare och uppdaterare lägger du till den i `disable_tools`; se [Förinstallerade CLI-verktyg](18-development-tools.md#preinstalled-cli-tools).

För att installera alla konfigurerade lata verktyg innan du behöver dem kör du `mise install --include-lazy`. Detta inkluderar Omarchys andra standard-CLI-verktyg liksom agenterna. Se [Förinstallerade CLI-verktyg](18-development-tools.md#preinstalled-cli-tools) för att installera ett enskilt verktyg eller använda din egen installation.

`grok` installeras via mises förstaparts-paket `grok`, på samma sätt som `claude` och `codex`. Kör `grok`, eller stjärnmarkera den i agentpanelen. Hoppa över installeraren `curl | bash` på x.ai. Den vägen lägger en andra kopia i `~/.grok/bin`, lägger den först i `PATH` och skriver över Omarchys wrapper.

`dsh` öppnar sitt webbläsar-UI på `127.0.0.1:3080`, med startkatalogen som standardarbetsyta. Dess webbläsar-UI tar ingen startprompt, så `omarchy agent prompt` öppnar den med prompten på urklippet att klistra in. Omarchy startar den med DeepSeeks behörighetsförinställning utan godkännande. DeepSeek Harness laddar upp sessionsloggar till DeepSeek när du använder dess officiella modell-API; stäng av det under _Settings > General > Upload Session Log_ i dess webbläsar-UI. Feedback som du skickar till den laddas också upp tillsammans med sessionen, om du inte startar den med `DSH_TELEMETRY_MODE=DISABLED`.

### Standardagenten

Välj din standardagent med stjärnan bredvid en agent i agentpanelen, som är fylld på standardagenten, eller med `omarchy default agent <name>`, som också tar vilket harness som helst utan en rad där. Om agenten inte är installerad ännu installerar valet den först, och den får också ett eget startprogram i appstartaren, bredvid Agent. En färsk Omarchy bjuder in dig att sätta upp en med en engångsavisering, som öppnar agentpanelen.

Att välja Claude försöker också sätta upp dess webbläsartillägg för Chromium, Chrome, Brave, Brave Origin och Edge. Uppsättningen av tillägget gäller för alla användare och kan be om ditt systemlösenord; att avbryta eller en misslyckad installation av tillägget väljer och startar ändå Claude. Starta om din webbläsare, aktivera tillägget om du uppmanas att göra det, och logga in på Claude för att slutföra anslutningen av det. Kör `/chrome` i Claude för att kontrollera anslutningen. Firefox och Zen stöder inte detta tillägg. Om Claude redan var din standard innan denna uppsättning lades till väljer du den igen för att installera tillägget.

När du väl har valt startar `Super + Shift + Ctrl + A` standardagenten i ett dedikerat terminalfönster (eller tar fram väljaren om du inte har valt ännu). Du kan också starta den rakt in i en uppgift med `omarchy agent prompt "Review this project"`. Freebuff och DeepSeek Harness tar ingen startprompt, så de öppnas i stället med prompten på urklippet att klistra in. Agenter som startas på detta sätt körs obevakade i sina respektive lägen som inte stannar för att fråga, så var redo på att de faktiskt gör saker! MiniMax Code har inget sådant läge för sina interaktiva sessioner, så den ber om behörigheter som vanligt. Och eftersom agenter vägrar att komma ihåg förtroende för din hemkatalog startar starter från `$HOME` i stället i `~/Work`.

Det finns terminalgenvägar också: `a` kör standardagenten inline i den aktuella terminalen, medan `c`, `cx` och `cy` startar OpenCode, Claude Code och Codex direkt (återigen i deras automatiskt godkännande lägen). Temabyten synkas till agenterna också: Claude Code, Pi, OpenCode och Hermes (när Omarchy väl har installerat den) följer alla med när du byter Omarchy-tema.

### Dina agentinstruktioner

Personliga regler för varje agent hör hemma i `~/.agents/AGENTS.md`, bredvid de delade färdigheterna i `~/.agents/skills`. Öppna den med dokumentikonen bredvid + i agentpanelen, eller `omarchy agent instructions --edit`, som också länkar in den i varje harness som behåller sin egen globala fil: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, Copilots `~/.copilot/copilot-instructions.md`, och så vidare. Crush och Amp läser länken `~/.config/AGENTS.md`, medan omp, Kimi och DeepSeek Harness läser `~/.agents/AGENTS.md` direkt. Att välja en standardagent länkar den också. En instruktionsfil som du redan hade blir den delade om det inte fanns någon ännu; annars behålls den bredvid länken som `.bak`. Kör `omarchy agent instructions` för att länka om efter att du har installerat en annan agent.

### Agentpanelen

Det övre fältet har en agentikon. Innan du har satt upp en agent erbjuder dess panel tre sätt att börja: logga in på en prenumeration på Claude, Codex, Grok, Gemini, Muse, Cursor eller Copilot, eller under More en kodningsplan för OpenCode Go, MiniMax, Synthetic eller Z.ai; betala allt eftersom med Fireworks, OpenCode Zen and Go, OpenRouter, eller under More DeepSeek eller vilken annan leverantör som helst som OpenCode loggar in på, alla körs i OpenCode; eller kör den bästa modellen för din dator, när en passar den. Den första du slutför blir din standardagent, och + i panelen erbjuder samma tre senare. Efter det lägger panelen varje prenumeration på en sida: varje agent och konto med sin plan, en mätare för var och en av dess gränser för 5-timmarssessioner och veckogränser med tiden tills den återställs (håll muspekaren över för exakt procent), eller det återstående förbetalda saldot, under en rad som roterar igenom vad du har använt över alla dem, som tokens denna vecka och din mest använda modell. Under _Make something cool_ erbjuder den startprompter för ett nytt tema, plugin, app eller spel som lämnar över uppgiften till din standardagent. Appar byggs på samma sätt som Omarchys egna Hype, Monologue och Omacut, i C++ och Qt Quick, enligt agentfärdigheten omarchy-make-app, och kompilatorn och Qt-delarna de behöver följer med installerade. Spel är en enda three.js-sida i `~/Games/vibes`, enligt agentfärdigheten omarchy-make-game, och alla öppnas från en enda Game Vibes-startare i det aktuella temat; de laddar three.js från webben, så de behöver en anslutning för att starta. Claude Code, Codex, Grok, Kimi, Cursor och dess Grok Bot-tilldelning, GitHub Copilot, Muse, Gemini (genom Antigravity) och Devin täcks från start med sina gränser, Kimchi med sin plan, förbetalda krediter och utgiftsbudgetar, och Hermes, Mistral Vibe och Qwen Code visar sina sessioner och tokens när du väl har använt dem. Leverantörsplaner och nycklar som du använder genom pi, omp eller opencode dyker också upp: OpenCode Zen and Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan och Synthetic med sina gränser; OpenRouter och DeepSeek med sina förbetalda saldon; Fireworks med sina utgifter under de senaste 30 dagarna. Kodningsmodeller som du kör på din egen hårdvara får egna rader, och deras tokens räknas också in i totalsummorna, som beskrivs under [Lokala modeller](#local-models). Varje agent räknas en gång, under vem som än fakturerar den, oavsett hur många harnessar du driver den genom.

Vänsterklicka på fältikonen eller tryck på `Super + Ctrl + X` för panelen, högerklicka för att starta din standardagent, och mittenklicka för att uppdatera. Användningsposterna bakom den genereras om var 15:e minut av `omarchy agent usage update`, och panelen kan till och med slå samman användning från dina andra maskiner via en synkad mapp. Se README under `$OMARCHY_PATH/shell/plugins/agents/` för de fullständiga inställningarna.

### Flera prenumerationer

Om du betalar för mer än en plan för Claude, Codex eller Grok — en personlig Max och en för arbetet, säg — kan Omarchy hålla dem alla inloggade och flytta mellan dem. Lägg till en prenumeration med + i agentpanelen, som guidar dig igenom det direkt där, eller med `omarchy agent account add claude Work` (eller `codex`, eller `grok`). Samma + och kommando loggar in på Gemini (`gemini`) och OpenCode (`opencode`), och sparar en API-nyckel för Fireworks (`fireworks`) eller OpenRouter (`openrouter`) i OpenCode; kommandot loggar också in på Copilot (`copilot`), Cursor (`cursor`) och Muse (`muse`). Dessa behåller en enda inloggning var. Det installerar CLI:t om det saknas. Det första kontot för en leverantör loggar in genom din vanliga webbläsare, precis där CLI:t alltid tittar. Varje konto därefter loggar in genom ett privat fönster, så att kontot som din webbläsare redan är inloggad på inte plockas upp av misstag; logga in där som det konto du lägger till, och stäng först varje privat fönster som du redan hade öppet. Logga aldrig ut ur CLI:t för att göra detta: att logga ut återkallar den sparade inloggningen, och det kontot skulle behöva läggas till igen.

För att kopiera dina prenumerationsinloggningar till en annan Omarchy-maskin över SSH kör du `omarchy agent account copy user@laptop`. Avsändaren tillhandahåller en tillfällig mottagare när destinationen inte har en installerad, så äldre Omarchy-maskiner kan ta emot konton utan en uppdatering. Installerade mottagare har företräde. Detta kopierar alla prenumerationer för Claude, Codex och Grok; lägg till leverantörsnamn för att välja dem, som i `omarchy agent account copy laptop claude`. Kontonamn och kommando-ID:n matchar källan, inklusive konton som redan finns på destinationen. Orelaterade destinationskonton får ett numeriskt suffix om deras namn krockar, och inställningar, färdigheter, plugins och konversationshistorik förblir lokala för varje maskin.

Befintliga destinationsuppgifter behålls. Ett källkonto som redan är inloggat där får sitt namn synkroniserat utan att dess uppgifter ersätts; andra konton läggs till bredvid det. För att ersätta sparade uppgifter för matchande konton använder du `omarchy agent account copy --replace laptop claude` efter att du har avslutat det kontots sessioner på destinationen. En färsk destination får också källans aktiva konto och växlingsinställningar; en etablerad destination behåller sina egna.

Uppgifter färdas genom SSH och lagras i privata filer på destinationen, så kopiera endast till maskiner du litar på. Detta är en engångskopia, inte löpande synkronisering. Codex uppdateringstokens kan roteras av en annan maskin, vilket lämnar en kopierad inloggning i behov av förnyelse; separata inloggningar förblir det mest tillförlitliga valet för samtidig användning på flera maskiner. Se [Codex vägledning för kontoautentisering](https://developers.openai.com/codex/auth/ci-cd-auth).

Ett konto per leverantör är aktivt, och varje ny session börjar som det: `cx`, `cy`, en vanlig `claude`, `codex` eller `grok`, vad som helst som startas genom `omarchy agent`, och skript eller editorer som hittar CLI:t i `PATH`. Växla med `omarchy agent account use work` (och tillbaka med `omarchy agent account use main`), eller i panelen genom att trycka på ett kontos nummer och sedan `Enter` (eller klicka på dess stjärna). Körande Claude-sessioner växlar också, från sitt nästa meddelande: varje Claude-session körs i `~/.claude`, som alltid håller det aktiva kontots inloggning. En Claude-session som startades i ett kontos egen mapp av en äldre Omarchy behåller den inloggningen tills den avslutas, så växlingen namnger dessa sessioner och slutför på egen hand när de är borta. Körande Codex- och Grok-sessioner stannar på det konto de startade med. Konversationshistorik, inställningar, färdigheter och plugins delas över konton, så `claude --continue` i samma mapp plockar upp där du slutade på det nya kontot.

Med mer än ett konto visar panelen varje kontos gränser sida vid sida, med en fylld stjärna på det som används. Omarchy aviserar dig när det aktiva kontot passerar 95 % av en gräns, och att klicka på aviseringen växlar till kontot med mest utrymme kvar. Den växlar aldrig på egen hand. Ändra tröskeln med `omarchy agent account threshold 90`. Om varje konto är över tröskeln får du höra om det en gång, tillsammans med vilket konto som frigörs först. Medan ett aktivt konto är inom 15 poäng från sin tröskel (80 % vid standarden) kontrolleras dess gränser var tredje minut snarare än var 15:e.

`omarchy agent account list` visar varje konto och dess senaste gränser, `omarchy agent account remove work` glömmer ett, och `omarchy agent account rename primary Hey` döper om ett (eller klicka på ett kontos namn i panelen). Dessa kommandon fungerar på din standardagents konton; för att nå den andra leverantören namnger du den först, som i `omarchy agent account use codex side`. Inloggningen som du redan hade i `~/.claude` eller `~/.codex` är _Main_-kontot. Codex stannar där den är; Claudes väntar i en egen mapp medan ett annat konto är aktivt. Ett konto som lämnats oanvänt i mer än ungefär åtta timmar kan visa _Sign-in required_; klicka på det för att logga in det kontot igen direkt i panelen, eller växla till det och starta en session, vilket uppdaterar inloggningen på egen hand. MCP-servrar som du lägger till med `claude mcp add` når varje Claude-konto, eftersom de alla körs i `~/.claude`; för Codex och Grok följer servrar som du hade när ett konto lades till med till det, men senare når endast det konto du lade till dem i. Claude Desktop behåller en egen inloggning, och Codex- eller Grok-verktyg som konfigurerats med en absolut sökväg till en CLI-binär följer inte växlingen. Ett explicit `CLAUDE_CONFIG_DIR`, `CODEX_HOME` eller `GROK_HOME` har företräde framför det valda kontot.

### Kraschdiagnostik

Omarchy bevakar systemd-coredump efter processkrascher. När du väl har valt en standardagent ger varje program du har som dumpar kärnan en avisering om "Process crashed" — klicka på den, och kraschen lämnas över till din standardagent tillsammans med Omarchys färdighet omarchy-diagnose-crash, som guidar agenten genom att fastställa fakta från kärndumpen och avgöra om kraschen är värd att rapportera uppströms. Du kan också köra den för hand mot vilket PID som helst från `coredumpctl list` med `omarchy agent crash <pid>`.

Bevakningen är på som standard. Stäng av den under _Trigger > Toggle > Crash Capture Off_ (eller med `omarchy toggle crash-capture`) och aviseringarna slutar; `omarchy agent crash <pid>` fungerar fortfarande för hand.

Krascher kan också tystas ett program i taget, vilket är vad diagnostiken erbjuder dig i slutet. `omarchy crash mute hyprland` stoppar aviseringarna för endast det programmet, `omarchy crash mute hyprland off` tar tillbaka dem, och `omarchy crash mute` på egen hand listar vad du har tystat. Den tar binärens sökväg lika glatt som dess namn, så `omarchy crash mute /usr/bin/hyprland` gör samma sak. Citera ett namn med ett mellanslag i det, som i `omarchy crash mute 'Some App'`. Allt annat aviserar fortfarande, och det tystade programmet kraschar fortfarande — detta döljer påminnelsen, det fixar ingenting.

### Skrivbordsappar

Menyn _Install > AI_ bär också några grafiska AI-appar: Amp Desktop, Antigravity Desktop, ChatGPT-skrivbordsappen, Claude-skrivbordsappen (Anthropics Linux-beta, med flikarna Chat, Cowork och Claude Code), Grok Bot för att chatta med xAI:s modeller, Herdr Desktop, Hermes Desktop, OpenClaw, Perplexity-skrivbordsappen och T3 Code. Grok Bot är skrivbordschattappen. Kodningsagenten är kommandot `grok`.

Hermes Desktop är den att känna till, eftersom en maskin har en Hermes, och den är appens: Hermes installeras endast någonsin genom appen, och kommandot `hermes` som standardagenten kör är appens. Att välja Hermes som standardagent installerar samma sak som posten _Install > AI_ gör: paketet, och en Hermes-runtime under `~/.hermes` som sätts upp av Hermes egen installerare, vilket tar några minuter första gången. Den runtimen är den enda Hermes som terminalkommandot `hermes`, standardagenten och appen alla använder, och den uppdaterar sig själv med `hermes update` snarare än att vänta på en Omarchy-version. Att installera den ger också Hermes Omarchy-temat som ett skin med namnet `omarchy`, som varje Hermes-yta följer när du byter teman; välj ett annat under Hermes Appearance-inställningar eller med `/skin` om du hellre vill att den inte gör det, och Omarchy lämnar det valet i fred. Att ta bort appen under _Remove > AI_ stänger Hermes först, gatewayen inkluderad, tar den runtimen med sig, och behåller dina chattar, minnen och färdigheterna som Hermes skrev åt sig själv om du inte säger annat till den: den frågar, med nej som standard, om den datan och dina anslutningsinställningar ska försvinna också.

OpenClaws skrivbordserfarenhet är dess Control UI, som öppnas som en webbapp med stöd av dess egen lokala gateway. OpenClaw lever i `~/.openclaw` och uppdaterar sig själv: använd Control UI:s knapp "Update Gateway" eller kör `openclaw update`, och gatewayen startar om på den nya versionen. Omarchy väljer endast den version som en färsk installation börjar från. OpenClaw kan också vara din standardagent: att välja den med `omarchy default agent openclaw` sätter upp samma kopia i `~/.openclaw`, och agenten öppnar OpenClaws terminal-UI kopplat till dess gateway. Att ta bort OpenClaw under _Remove > AI_ tar gatewaytjänsten och appen med sig och frågar sedan om `~/.openclaw` ska försvinna också, eftersom det håller dina chattar och uppgifter tillsammans med OpenClaw själv och plugin-runtimes den laddar ner; standarden behåller den, och att installera OpenClaw igen plockar upp den igen.

Herdr Desktop är skrivbordsappen [Herdr](https://herdr.dev): ytor, flikar och rutor med terminaler och kodningsagenter som fortsätter att köra i dess kärna när du stänger fönstret. Den kommer från Herdrs egen installerare snarare än ett paket, så den lever i `~/.local/share/herdr-app`, tar med sin kärna i `~/.local/bin/herdr-core` när du inte har en ännu, och uppdaterar dem båda själv. Den sitter bredvid kommandot `herdr` som Omarchy levererar på `Super + Ctrl + Return` snarare än att ersätta det, och får det kommandots direkta tangenter: `Alt + Return` och `Alt + Shift + Return` delar en ruta nedåt eller åt höger, `Alt + Escape` stänger den, `Ctrl + Alt + Arrow` flyttar mellan rutor, `Alt + 1..9` och `Alt + Left/Right` väljer en flik, och `Alt + Up/Down` flyttar mellan ytor. `Ctrl + 1..9` väljer en yta och `Alt + Shift + Up/Down` stegar genom agenter. Prefixtangenterna `Ctrl + Space` förblir endast för terminalen, eftersom appen inte kan hålla en vanlig Ctrl-tangent för en sekvens. Omarchy skriver dessa till `~/.config/herdr-app/keys.json`, och `omarchy-refresh-herdr-app` lägger tillbaka dem. Att installera den väljer Herdrs Omarchy-tema, som följer ditt Omarchy-tema från och med då. Herdr behåller ett tema för ljust läge och ett för mörkt, så efter att du har växlat mellan ett mörkt och ett ljust Omarchy-tema väljer du Omarchy i Herdrs temaväljare en gång till för det andra läget.

T3 Code körs från sin officiella AppImage-version i `~/.local/share/t3code` snarare än från ett paket, så den uppdaterar sig själv. Att installera den frågar om den ska börja på kanalen Stable eller Nightly; växla senare i T3 Codes inställningar. Dina trådar och inställningar lever i `~/.t3`, och att ta bort T3 Code under _Remove > AI_ tar dem med sig.

### Lokala modeller

Kör en öppen modell på din egen maskin för dina kodningsagenter. Dina prompter och din kod stannar på maskinen; ingenting som skickas till modellen lämnar den. Börja med:

```bash
omarchy models use best text
```

Det sätter upp den bästa textmodellen för denna maskin, den sort dina agenter använder. Bild-, video- och musikmodeller har en egen bästa: `omarchy models use best image`, `video` eller `music`. Kör `omarchy models use best` för att se varje sorts val för denna maskin.

Eller välj + i agentpanelen: under _Use a local model_ listar den varje kodningsmodell som passar denna maskin, den rekommenderade först. Podman, som kör modellerna, följer med Omarchy, liksom NVIDIA:s container-toolkit på en NVIDIA-maskin, som ger dem GPU:n; om någon av dem saknas installerar den första uppsättningen den. Omarchy väljer sedan den rekommenderade modellen för denna maskin, laddar ner den och startar den. Räkna med en nedladdning på tiotals GB och att det mesta av maskinens minne används medan modellen körs: Flash Next använder ungefär 100 GiB med sitt fulla 256K-sammanhang. Om andra modeller håller minnet den behöver sätts den upp stoppad, redo att starta när du väl stoppar en. Modellen stannar vid utloggning; stoppa den själv när du behöver minnet till något annat.

`omarchy models list` visar alternativen och förklarar varför vissa inte passar. För att sätta upp en annan kör du `omarchy models use <recipe>`. I dag finns `qwen3.8-flash-next-gufo` och `qwen3.8-27b-gufo` tillgängliga för 128 GB Strix Halo-maskiner; 27B tar ungefär 40 GiB, så den lämnar utrymme för annat arbete. På en 64 GB bärbar dator med Intels Arc B390 körs `qwen3.6-35b-a3b-llamacpp` på ungefär 30 GiB. Nya recept och rekommendationer anländer med `omarchy update`, genom paketet.

En kodningsmodell som du lägger till får sin egen rad i agentpanelen, bredvid dina prenumerationer: spela för att starta den, pausa för att stoppa den och frigöra dess minne, Tailscale-märket för att dela den med de andra maskinerna på ditt tailnet medan den körs, och terminalknappen för att öppna din agent på den. Dess rad visar nedladdningen, laddningen eller stoppet allt eftersom, och säger till när det inte finns tillräckligt med ledigt minne för att starta den, eller länkar till dess loggar när den stoppade med ett fel. Flera kan köras samtidigt när de ryms i minnet tillsammans. Tryck på Delete på en vald rad för att ta bort modellen från denna maskin, nedladdning och allt; + kan sätta upp den igen. En kodningsmodell som sätts upp från en terminal väntar under + tills du lägger till den, och det gör också modellerna som en maskin du har parat ihop med (`omarchy models pair <host>`) kör.

Varje kodningsmodell som du sätter upp får också sin egen post i appstartaren, under modellens namn och med dess skapares logotyp, på samma sätt som att logga in på Claude, Codex eller Grok lägger till en. Den öppnar din agent på den modellen, och startar modellen först om den inte körs: terminalen visar att den laddas och lämnar över till agenten när den är uppe. Att ta bort en modell tar bort dess post.

Inte varje modell är för kodning. Bild-, video- och musikmodeller öppnas i Fantasi i stället, Omarchys app för att göra bilder, video och musik med en modell som körs på denna maskin, och hanteras där eller med `omarchy models`.

En modell fortsätter att köra exakt som den sattes upp, så en Omarchy-uppdatering startar aldrig om en under dina agenter. När Omarchy har en nyare runtime eller nyare vikter för en modell du har satt upp visar dess rad en uppdateringsknapp: tryck på den och modellen sätts upp igen i bakgrunden, laddar endast ner det som ändrades, och startar om på den nya versionen. En modell som var stoppad förblir stoppad. `omarchy models update` gör samma sak för varje modell från en terminal.

Från kommandoraden gör `omarchy models start <recipe>` och `omarchy models stop <recipe>` samma sak, `omarchy models status` visar varje modell, och `omarchy agent --local-model <recipe>` öppnar den modellen i pi, oavsett vad din standardagent är. För att göra din lokala modell till det som agentgenvägen, Quake-konsolen och _Make something_ öppnar kör du `omarchy default agent local` eller stjärnmarkerar en körande modell i agentpanelen. pi listar också varje modell du har satt upp, och dem på maskiner du har parat ihop med, i sin egen modellväljare, så vanlig `pi` når dem också. Vilken OpenAI-kompatibel klient som helst kan också ansluta: `status` visar varje modells adress (den första är `http://127.0.0.1:11435/v1`), receptnamnet är modellen, och nyckeln finns i `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` raderar en modell och nedladdningarna som ingen annan modell använder.

Tredjeparts-runtimes märks med sin utgivare. Omarchy kör varje modell utan nätverksåtkomst.

### Lokala LLM:er

Omarchy rekommenderar två sätt att köra lokala LLM-modeller: LM Studio och Ollama. LM Studio tillhandahåller ett GUI-gränssnitt för att hitta modeller med öppna vikter, installera dem och köra dem. Det är ett bra sätt att komma igång enkelt. Ollama erbjuder ett CLI för att göra det på liknande sätt. Men om du är ny på lokala modeller skulle jag börja med LM Studio. Du kan installera någon av dem under _Install > AI_ i Omarchy-menyn.

### Omarchy-färdigheterna

Agentfärdigheter hjälper AI att använda specifika verktyg på ett specifikt sätt, och Omarchy levererar sju av dem. Färdigheten omarchy täcker att skräddarsy systemet, som att justera din Hyprland-konfiguration eller justera fältet. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app och omarchy-make-game täcker att göra något nytt, omarchy-contribute täcker att rapportera en bugg eller skicka en fix uppströms, och omarchy-diagnose-crash arbetar igenom en kraschs kärndump. De är symlänkade in i färdighetskatalogerna för Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` och varje `~/.hermes/profiles/*/skills`), och den generiska platsen `~/.agents/skills`, så de flesta harnessar plockar upp dem automatiskt. En egen färdighetsmapp med samma namn har företräde.

Men du bör behandla dessa färdigheter som experimentella. Olika modeller kommer att använda dem med olika effekt. Det är bäst att köra i planläge först, så att du har en idé om vad agenten skulle vilja ändra. Och var sedan redo att rulla tillbaka ändringar eller till och med anropa `omarchy reinstall configs`, om agenten ställer till med en röra av alltihop.
