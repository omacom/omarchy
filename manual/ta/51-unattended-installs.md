# கவனிப்பாரற்ற நிறுவல்கள்

Omarchy ISO-வால் விசைப்பலகை அருகே யாரும் இல்லாமலேயே தன்னைத்தானே நிறுவிக்கொள்ள முடியும். நிறுவி, அதன் உள்ளமைவுக் கோப்புகளைக் கொண்ட `cidata` என்று பெயரிடப்பட்ட இரண்டாவது இயக்ககத்தைக் கண்டறிந்தால், அவற்றை நகலெடுத்துக்கொண்டு, அமைவு வழிகாட்டியை முழுவதுமாகத் தவிர்த்துவிட்டு, தானாகவே முடிக்கப்பட்ட அமைப்புக்குள் மறுதொடக்கம் செய்யும். சிறப்பு ISO கட்டமைப்பு எதுவும் இல்லை, கூடுதல் துவக்கப் பட்டியல் உள்ளீடும் இல்லை — அத்தகைய இயக்ககம் எதுவும் இணைக்கப்படவில்லை என்றால், எதுவும் மாறாது, உங்களுக்கு வழக்கமான வழிகாட்டியே கிடைக்கும்.

இது Omarchy-ஐ ஒருமுறை பயன்படுத்தித் தூக்கியெறியக்கூடிய மேம்பாட்டுச் சூழல்களுக்கான அடிப்படைப் படிமமாகச் சிறந்ததாக ஆக்குகிறது: Proxmox-இல் அல்லது Packer கொண்டு ஒரு VM-ஐ உருவாக்குங்கள், அதைத் துவக்குங்கள், விலகிச் செல்லுங்கள், SSH வழியாக உள்ளே நுழையுங்கள். `cidata` என்பது cloud-init-இன் `NoCloud` லேபிள், எனவே அனைத்துப் பொதுவான மெய்நிகராக்கக் கருவிகளுக்கும் அத்தகைய இயக்ககத்தை எப்படி இணைப்பது என்று ஏற்கெனவே தெரியும்.

## உள்ளமைவுக் கோப்புகள்

இந்தக் கோப்புகள் நிறுவியின் சொந்த வழிகாட்டி எழுதுவதேதான், எனவே தொடக்கத் தொகுப்பைப் பெறுவதற்கான எளிதான வழி, ஒரு ஊடாடும் நிறுவலை (எடுத்துக்காட்டாக, ஒரு VM-இல்) இயக்கி, அது `/root`-இல் எழுதியவற்றை நகலெடுப்பதுதான்:

| கோப்பு | தேவையா | நோக்கம் |
|------|----------|---------|
| `user_configuration.json` | ஆம் | வட்டு, ஹோஸ்ட்பெயர், நேர மண்டலம், விசைப்பலகை |
| `user_credentials.json` | ஆம் | பயனர்பெயரும் கடவுச்சொல் ஹாஷும், மற்றும் மறையாக்கப்பட்ட நிறுவலுக்கான LUKS கடவுச்சொற்றொடர் |
| `user_encrypt_installation.txt` | இல்லை | உள்ளமைவில் `disk_encryption` தொகுதி இருக்கும்போது `true` |
| `authorized_keys` | இல்லை | SSH பொதுச் சாவிகள், ஒரு வரிக்கு ஒன்று |
| `tailscale_authkey` | இல்லை | முதல் துவக்கத்தில் உங்கள் tailnet-இல் சேர்வதற்கான Tailscale அங்கீகாரச் சாவி |

`user_credentials.json`-க்கான கடவுச்சொல் ஹாஷை `openssl passwd -6 "yourpassword"` கொண்டு உருவாக்குங்கள்.

git கமிட்களுக்கான பெயரும் மின்னஞ்சலும் நிறுவலின் பகுதி அல்ல. எடுத்துக்காட்டாக SSH வழியாக, இயந்திரம் எழுந்ததும் அவற்றை `omarchy setup git --name "Jane Doe" --email jane@example.com` கொண்டு ஒருமுறை அமையுங்கள்.

`user_credentials.json`-க்குப் பதிலாக `defer-provisioning` என்று பெயரிடப்பட்ட வெற்றுக் கோப்பையும் நீங்கள் போடலாம். அது, நீங்கள் ஊடாடும் முறையில் தூண்டக்கூடிய அதே [மற்றொரு உரிமையாளருக்குத் தயார்செய்யும் நிறுவலை](02-getting-started.md) இயக்கும்: இயந்திரம் எந்தத் தனிப்பட்ட விவரங்களும் இல்லாமல் நிறுவப்படும், அதை முதலில் துவக்குபவர் தங்கள் விசைப்பலகையைத் தேர்ந்தெடுத்துத் தங்கள் பயனரை உருவாக்குவார். இயக்ககம் யாருடைய நற்சான்றுகளையும் கொண்டிருக்கவே கூடாத படிமமாக்கும் கருவிகளுக்கான முறை இதுதான்.

## SSH அணுகல்

`authorized_keys` இருக்கும்போது, நிறுவல் அந்தச் சாவிகளைப் பயனரின் `~/.ssh/authorized_keys` ஆக அமைத்து, `sshd`-ஐ இயக்கி, அதற்காக ஃபயர்வாலைத் திறக்கும். (பொதுவான Omarchy நிறுவல் openssh-ஐச் சேவை முடக்கப்பட்டும் போர்ட் மூடப்பட்டும் அனுப்பும், எனவே இல்லையெனில் கவனிப்பாரற்ற இயந்திரத்தை அணுகவே முடியாது.) நிறுவல் உங்கள் சாவிகளை மட்டுமே சேர்க்கும் — அது SSH டீமானின் பிற அங்கீகார அமைப்புகள் எதையும் தளர்த்தாது.

`tailscale_authkey` இருக்கும்போது, அதற்குப் பதிலாக இயந்திரம் முதல் துவக்கத்தில் உங்கள் tailnet-இல் சேரும்: Tailscale ISO-இன் தொகுக்கப்பட்ட தொகுப்புகளிலிருந்து நிறுவப்படும், ஃபயர்வால் tailnet இடைமுகத்தை அனுமதிக்கும், இயந்திரத்துக்கு உண்மையில் பிணையம் கிடைத்தவுடன் ஒரு பின்னணிப் பணி அந்தச் சேர்க்கையை இயக்கும், வெற்றி பெறும் வரை மீண்டும் முயலும். ஒரே இயக்ககப் படிமம் பல இயந்திரங்களுக்குப் பயன்படும் வகையில், மீண்டும் பயன்படுத்தக்கூடிய, முன்-அங்கீகரிக்கப்பட்ட சாவியைப் பயன்படுத்துங்கள்.

## cidata இயக்ககத்தை உருவாக்குதல்

சரியான லேபிளைக் கொண்ட எந்தக் கோப்பு முறைமையும் வேலை செய்யும். சிறிய ISO ஒன்றுதான் எளிதான வழி:

```bash
mkdir cidata
cp user_configuration.json user_credentials.json authorized_keys cidata/
genisoimage -output cidata.iso -volid cidata -joliet -rock cidata/
```

பிறகு அதை Omarchy ISO-வுடன் சேர்த்து VM-இல் இணையுங்கள். இதோ ஒரு முழுமையான Proxmox எடுத்துக்காட்டு:

```bash
qm create 101 --name my-omarchy \
  --bios ovmf --machine q35 --cpu host --cores 4 --memory 8192 \
  --ostype l26 --scsihw virtio-scsi-single \
  --efidisk0 local-lvm:0,efitype=4m,pre-enrolled-keys=0 \
  --scsi0 local-lvm:40,discard=on,iothread=1 \
  --net0 virtio,bridge=vmbr0 --vga virtio --serial0 socket \
  --ide2 local:iso/omarchy.iso,media=cdrom \
  --ide3 local:iso/cidata.iso,media=cdrom \
  --boot order='scsi0;ide2'

qm start 101
```

துவக்க வரிசை வேண்டுமென்றே வட்டை முதலில் பட்டியலிடுகிறது: வெற்று வட்டு முதல் துவக்கத்தில் ISO-வுக்கு வழிவிடும், அதன் பிறகு நிறுவப்பட்ட அமைப்பு எப்போதும் வட்டிலிருந்தே துவங்கும்.

## இரண்டு எச்சரிக்கைகள்

மறையாக்கப்பட்ட கவனிப்பாரற்ற நிறுவல்கள் முழுமையாகக் கவனிப்பாரற்றவை அல்ல — முதல் துவக்கத்தில் யாராவது இன்னும் LUKS கடவுச்சொற்றொடரைத் தட்டச்சு செய்ய வேண்டும். மேலும் அந்தக் கடவுச்சொற்றொடர் `user_credentials.json`-இன் மேல் மட்டத்தில் `encryption_password` ஆகச் செல்லும் — archinstall அதை அங்கேதான் படிக்கும், `user_configuration.json`-இல் உள்ள `disk_encryption` தொகுதியிலிருந்து அல்ல — எனவே மறையாக்கப்பட்ட நிறுவலிலிருந்து உருவாக்கப்பட்ட cidata இயக்ககத்தை அது உண்மையில் இருக்கும் இரகசியமாகவே கருதுங்கள்.
