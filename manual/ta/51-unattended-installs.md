# பங்கேற்காத நிறுவல்கள்

Omarchy ISO விசைப்பலகையில் யாரும் இல்லாமல் தன்னைத்தானே நிறுவ முடியும். நிறுவி, அதன் உள்ளமைவுக் கோப்புகளைக் கொண்டு `cidata` என்று பெயரிடப்பட்ட இரண்டாவது இயக்ககத்தைக் கண்டால், அவற்றை நகலெடுத்து, அமைப்பு வழிகாட்டியை முற்றிலும் தவிர்த்து, தானாகவே முடிந்த கணினியில் மறுதொடக்கம் செய்யும். சிறப்பு ISO கட்டுமானம் இல்லை, கூடுதல் துவக்க மெனு உள்ளீடு இல்லை — அப்படியொரு இயக்ககம் இணைக்கப்படவில்லை என்றால், எதுவும் மாறாது, வழக்கமான வழிகாட்டியே கிடைக்கும்.

இது Omarchy-ஐ ஒருமுறை பயன்படுத்தும் மேம்பாட்டுச் சூழல்களுக்கு ஒரு சிறந்த அடிப்படைப் படமாக ஆக்குகிறது: Proxmox-இலோ Packer-ஐக் கொண்டோ ஒரு VM உருவாக்கி, அதைத் துவக்கி, விலகிச் சென்று, SSH செய்யுங்கள். `cidata` என்பது cloud-init `NoCloud` பெயர், எனவே எல்லாப் பொதுவான மெய்நிகராக்கக் கருவிகளுக்கும் அப்படியொரு இயக்ககத்தை இணைப்பது எப்படி என்று ஏற்கனவே தெரியும்.

## உள்ளமைவுக் கோப்புகள்

கோப்புகள் நிறுவியின் சொந்த வழிகாட்டி எழுதுவதே, எனவே ஒரு தொடக்கத் தொகுப்பைப் பெற எளிதான வழி ஒரு ஊடாடும் நிறுவலை (எடுத்துக்காட்டாக, ஒரு VM-இல்) இயக்கி, அது `/root`-இல் எழுதியதை நகலெடுப்பது:

| கோப்பு | தேவை | நோக்கம் |
|------|----------|---------|
| `user_configuration.json` | ஆம் | வட்டு, புரவலன் பெயர், நேர மண்டலம், விசைப்பலகை |
| `user_credentials.json` | ஆம் | பயனர்பெயர் மற்றும் கடவுச்சொல் ஹாஷ் |
| `user_full_name.txt` | இல்லை | Git முழுப் பெயர் |
| `user_email_address.txt` | இல்லை | Git மின்னஞ்சல் |
| `user_encrypt_installation.txt` | இல்லை | உள்ளமைவு ஒரு `disk_encryption` தொகுதியைக் கொண்டிருக்கும்போது `true` |
| `authorized_keys` | இல்லை | SSH பொது விசைகள், ஒரு வரிக்கு ஒன்று |
| `tailscale_authkey` | இல்லை | முதல் துவக்கத்தில் உங்கள் tailnet-இல் சேர்வதற்கான Tailscale auth விசை |

`user_credentials.json`-க்கான கடவுச்சொல் ஹாஷை `openssl passwd -6 "yourpassword"` என்பதைக் கொண்டு உருவாக்குங்கள்.

`user_credentials.json`-க்குப் பதிலாக `defer-provisioning` என்ற வெற்றுக் கோப்பையும் போடலாம். அது நீங்கள் ஊடாடும் வகையில் தூண்டக்கூடிய அதே [மற்றொரு உரிமையாளருக்கான தயார் நிறுவலை](02-getting-started.md) இயக்குகிறது: கணினி தனிப்பட்ட விவரங்கள் எதுவும் இல்லாமல் நிறுவப்படும், அதை முதலில் துவக்குபவர் தங்கள் விசைப்பலகையைத் தேர்ந்தெடுத்துத் தங்கள் பயனரை உருவாக்குகிறார்கள். இயக்ககம் யாருடைய சான்றுகளையும் கொண்டிருக்கக் கூடாத படமாக்கக் கருவிகளுக்கான பயன்முறை அது.

## SSH அணுகல்

`authorized_keys` இருக்கும்போது, நிறுவல் விசைகளைப் பயனரின் `~/.ssh/authorized_keys` ஆக அமைத்து, `sshd`-ஐ இயக்கி, அதற்குத் தீச்சுவரைத் திறக்கிறது. (ஒரு நிலையான Omarchy நிறுவல் openssh-ஐ சேவை முடக்கப்பட்டு போர்ட் மூடப்பட்ட நிலையில் அனுப்புகிறது, எனவே ஒரு பங்கேற்காத கணினி இல்லையென்றால் அடைய முடியாமல் இருக்கும்.) நிறுவல் உங்கள் விசைகளை மட்டுமே சேர்க்கிறது — SSH டீமனின் வேறு எந்த அங்கீகார அமைப்புகளையும் அது தளர்த்துவதில்லை.

`tailscale_authkey` இருக்கும்போது, கணினி அதற்குப் பதிலாக முதல் துவக்கத்தில் உங்கள் tailnet-இல் சேரும்: Tailscale ISO-வின் தொகுக்கப்பட்ட தொகுப்புகளிலிருந்து நிறுவப்படுகிறது, தீச்சுவர் tailnet இடைமுகத்தை அனுமதிக்கிறது, கணினிக்கு உண்மையில் வலையமைப்பு கிடைத்தவுடன் ஒரு பின்னணி வேலை சேர்க்கையை இயக்கி, வெற்றி பெறும் வரை மீண்டும் முயற்சிக்கிறது. ஒரு இயக்ககப் படம் பல கணினிகளுக்குச் சேவை செய்ய மீண்டும் பயன்படுத்தக்கூடிய, முன்-அங்கீகரிக்கப்பட்ட விசையைப் பயன்படுத்துங்கள்.

## cidata இயக்ககத்தை உருவாக்குதல்

சரியான பெயருடன் எந்தக் கோப்பு முறையும் வேலை செய்யும். ஒரு சிறிய ISO தான் எளிதான வழி:

```bash
mkdir cidata
cp user_configuration.json user_credentials.json authorized_keys cidata/
genisoimage -output cidata.iso -volid cidata -joliet -rock cidata/
```

பிறகு அதை Omarchy ISO-வுடன் சேர்த்து VM-இல் இணைக்கவும். இதோ ஒரு முழு Proxmox எடுத்துக்காட்டு:

```bash
qm create 101 --name my-omarchy \
  --bios ovmf --machine q35 --cpu host --cores 4 --memory 8192 \
  --ostype l26 --scsihw virtio-scsi-single \
  --efidisk0 local-lvm:0,efitype=4m,pre-enrolled-keys=0 \
  --scsi0 local-lvm:40,discard=on,iothread=1 \
  --net0 virtio,bridge=vmbr0 --vga virtio --serial0 socket \
  --ide2 local:iso/omarchy.iso,media=cdrom \
  --ide3 local:iso/cidata.iso,media=cdrom \
  --boot order='scsi0;ide2'

qm start 101
```

துவக்க வரிசை வட்டை முதலில் பட்டியலிடுவது வேண்டுமென்றே: வெற்று வட்டு முதல் துவக்கத்தில் ISO-வுக்கு விழுகிறது, நிறுவப்பட்ட கணினி அதற்குப் பிறகு எப்போதும் வட்டிலிருந்து துவக்குகிறது.

## இரண்டு எச்சரிக்கைகள்

குறியாக்கம் செய்யப்பட்ட பங்கேற்காத நிறுவல்கள் முழுமையாகப் பங்கேற்காதவை அல்ல — முதல் துவக்கத்தில் LUKS கடவுச்சொல் சொற்றொடரை யாராவது இன்னும் தட்டச்சு செய்ய வேண்டும். `user_configuration.json`-இல் உள்ள `disk_encryption` தொகுதி அந்தச் சொற்றொடரை வெற்று உரையில் கொண்டுள்ளது, எனவே குறியாக்கம் செய்யப்பட்ட நிறுவலிலிருந்து கட்டப்பட்ட cidata இயக்ககத்தை அதுவாகவே இருக்கும் இரகசியமாகக் கருதுங்கள்.
