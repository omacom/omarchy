# ஆள் கவனிப்பு இல்லாத நிறுவல்கள்

Omarchy ISO, விசைப்பலகையின் முன் யாரும் இல்லாமலேயே தன்னைத்தானே நிறுவிக்கொள்ள முடியும். நிறுவி, அதன் உள்ளமைவுக் கோப்புகளைக் கொண்ட `cidata` என்று பெயரிடப்பட்ட இரண்டாவது இயக்ககத்தைக் கண்டால், அவற்றை நகலெடுத்து, அமைவு வழிகாட்டியை முழுவதுமாகத் தவிர்த்து, தானாகவே முடிக்கப்பட்ட கணினியில் மறுதொடக்கம் செய்யும். சிறப்பு ISO உருவாக்கம் எதுவும் இல்லை, கூடுதல் துவக்க மெனு உள்ளீடும் இல்லை — அத்தகைய இயக்ககம் எதுவும் இணைக்கப்படவில்லை என்றால், எதுவும் மாறாது, உங்களுக்கு வழக்கமான வழிகாட்டி கிடைக்கும்.

இது Omarchy-ஐ ஒருமுறை பயன்படுத்தித் தூக்கி எறியக்கூடிய dev சூழல்களுக்கான அடிப்படை இமேஜாகச் சிறந்ததாக ஆக்குகிறது: Proxmox-இல் அல்லது Packer கொண்டு ஒரு VM-ஐ உருவாக்கி, அதைத் துவக்கி, விலகிச் சென்று, SSH வழியாக உள்நுழையுங்கள். `cidata` என்பது cloud-init `NoCloud` லேபிள், எனவே அனைத்துப் பொதுவான மெய்நிகராக்கக் கருவிகளுக்கும் அத்தகைய இயக்ககத்தை எப்படி இணைப்பது என்று ஏற்கனவே தெரியும்.

## உள்ளமைவுக் கோப்புகள்

இந்தக் கோப்புகள் நிறுவியின் சொந்த வழிகாட்டி எழுதுவதேதான், எனவே தொடக்கத் தொகுப்பைப் பெறுவதற்கான எளிதான வழி, ஒரு ஊடாடும் நிறுவலை (உதாரணமாக, ஒரு VM-இல்) இயக்கி, அது `/root`-இல் எழுதியதை நகலெடுப்பதுதான்:

| File | Required | Purpose |
|------|----------|---------|
| `user_configuration.json` | Yes | வட்டு, ஹோஸ்ட்பெயர், நேர மண்டலம், விசைப்பலகை |
| `user_credentials.json` | Yes | பயனர்பெயர் மற்றும் கடவுச்சொல் ஹாஷ் |
| `user_encrypt_installation.txt` | No | உள்ளமைவில் `disk_encryption` தொகுதி இருக்கும்போது `true` |
| `authorized_keys` | No | SSH பொது விசைகள், ஒரு வரிக்கு ஒன்று |
| `tailscale_authkey` | No | முதல் துவக்கத்தில் உங்கள் tailnet-இல் சேர்வதற்கான Tailscale அங்கீகார விசை |

`user_credentials.json`-க்கான கடவுச்சொல் ஹாஷை `openssl passwd -6 "yourpassword"` கொண்டு உருவாக்குங்கள்.

git கமிட்களுக்கான பெயரும் மின்னஞ்சலும் நிறுவலின் பகுதி அல்ல. கணினி இயங்கத் தொடங்கியதும் அவற்றை அமையுங்கள், உதாரணமாக SSH வழியாக, `omarchy setup git --name "Jane Doe" --email jane@example.com` கொண்டு.

`user_credentials.json`-க்குப் பதிலாக `defer-provisioning` என்று பெயரிடப்பட்ட வெற்றுக் கோப்பையும் நீங்கள் போடலாம். அது நீங்கள் ஊடாடும் முறையில் தூண்டக்கூடிய அதே [மற்றொரு உரிமையாளருக்குத் தயார்செய்யும் நிறுவலை](02-getting-started.md) இயக்குகிறது: கணினி எந்தத் தனிப்பட்ட விவரங்களும் இல்லாமல் நிறுவப்படும், அதை முதலில் துவக்குபவர் தங்கள் விசைப்பலகையைத் தேர்ந்தெடுத்துத் தங்கள் பயனரை உருவாக்குவார். இயக்ககம் யாருடைய சான்றுகளையும் கொண்டிருக்கவே கூடாத இமேஜிங் ரிக்குகளுக்கான முறை அதுதான்.

## SSH அணுகல்

`authorized_keys` இருக்கும்போது, நிறுவல் அந்த விசைகளைப் பயனரின் `~/.ssh/authorized_keys` ஆக அமைத்து, `sshd`-ஐ இயக்கி, அதற்காக ஃபயர்வாலைத் திறக்கிறது. (ஒரு வழக்கமான Omarchy நிறுவல் openssh-ஐச் சேவை முடக்கப்பட்டு போர்ட் மூடப்பட்ட நிலையில் வழங்குகிறது, எனவே கவனிப்பாரற்ற கணினியை இல்லையெனில் அணுகவே முடியாது.) நிறுவல் உங்கள் விசைகளை மட்டுமே சேர்க்கிறது — அது SSH டீமனின் வேறு எந்த அங்கீகார அமைப்புகளையும் தளர்த்தாது.

`tailscale_authkey` இருக்கும்போது, கணினி அதற்குப் பதிலாக முதல் துவக்கத்தில் உங்கள் tailnet-இல் சேரும்: Tailscale ISO-வின் தொகுக்கப்பட்ட தொகுப்புகளிலிருந்து நிறுவப்படும், ஃபயர்வால் tailnet இடைமுகத்தை அனுமதிக்கும், கணினிக்கு உண்மையில் நெட்வொர்க் கிடைத்தவுடன் ஒரு பின்னணிப் பணி சேர்க்கையை இயக்கி, அது வெற்றிபெறும் வரை மீண்டும் முயற்சிக்கும். மீண்டும் பயன்படுத்தக்கூடிய, முன்-அங்கீகரிக்கப்பட்ட விசையைப் பயன்படுத்துங்கள், இதனால் ஒரு இயக்கக இமேஜ் பல கணினிகளுக்குப் பயன்படும்.

## cidata இயக்ககத்தை உருவாக்குதல்

சரியான லேபிளைக் கொண்ட எந்தக் கோப்பு முறைமையும் வேலை செய்யும். ஒரு சிறிய ISO தான் எளிதான வழி:

```bash
mkdir cidata
cp user_configuration.json user_credentials.json authorized_keys cidata/
genisoimage -output cidata.iso -volid cidata -joliet -rock cidata/
```

பின்னர் அதை Omarchy ISO-வுடன் சேர்த்து VM-இல் இணையுங்கள். இதோ ஒரு முழுமையான Proxmox உதாரணம்:

```bash
qm create 101 --name my-omarchy \
  --bios ovmf --machine q35 --cpu host --cores 4 --memory 8192 \
  --ostype l26 --scsihw virtio-scsi-single \
  --efidisk0 local-lvm:0,efitype=4m,pre-enrolled-keys=0 \
  --scsi0 local-lvm:40,discard=on,iothread=1 \
  --net0 virtio,bridge=vmbr0 --vga virtio --serial0 socket \
  --ide2 local:iso/omarchy.iso,media=cdrom \
  --ide3 local:iso/cidata.iso,media=cdrom \
  --boot order='scsi0;ide2'

qm start 101
```

துவக்க வரிசை வேண்டுமென்றே வட்டை முதலில் பட்டியலிடுகிறது: வெற்று வட்டு முதல் துவக்கத்தில் ISO-வுக்கு விழும், நிறுவப்பட்ட கணினி அதற்குப் பிறகு எப்போதும் வட்டிலிருந்து துவங்கும்.

## இரண்டு எச்சரிக்கைகள்

மறைகுறியாக்கப்பட்ட கவனிப்பாரற்ற நிறுவல்கள் முழுமையாகக் கவனிப்பாரற்றவை அல்ல — முதல் துவக்கத்தில் யாராவது இன்னும் LUKS கடவுச்சொற்றொடரைத் தட்டச்சு செய்ய வேண்டும். மேலும் `user_configuration.json`-இல் உள்ள `disk_encryption` தொகுதி அந்தக் கடவுச்சொற்றொடரை எளிய உரையில் கொண்டுள்ளது, எனவே மறைகுறியாக்கப்பட்ட நிறுவலிலிருந்து உருவாக்கப்பட்ட cidata இயக்ககத்தை அது இருக்கும் இரகசியமாகவே கருதுங்கள்.
