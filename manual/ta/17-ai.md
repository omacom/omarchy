# AI

Omarchy உங்களுக்காக ஒரு இயல்புநிலையைத் தேர்ந்தெடுக்காமல், கீழே உள்ள குறியீட்டு ஏஜென்ட்களுக்கான லாஞ்சர்களை உள்ளடக்கியுள்ளது. முதல் பயன்பாட்டில் அதன் CLI-ஐ நிறுவ ஒரு கட்டளையை இயக்கவும், பின்னர் கேட்கப்படும்போது அங்கீகரிக்கவும். ### ஏஜென்ட்களை நிறுவுதல் மற்றும் புதுப்பித்தல்

Hermes மற்றும் OpenClaw தவிர, இந்த ஏஜென்ட்கள் mise-இன் lazy நிறுவலைப் பயன்படுத்துகின்றன: முதல் தொடக்கம் CLI-ஐ நிறுவுகிறது, பின்னர் வரும் தொடக்கங்கள் அதையே மீண்டும் பயன்படுத்துகின்றன. mise ஒரு நிறுவப்பட்ட ஏஜென்ட்டுக்கு புதிய வெளியீடு உள்ளதா என்பதை நான்கு மணிநேரத்திற்கு ஒரு முறைக்கு மேல் சரிபார்க்காது, அது தொடங்குவதற்கு சற்று முன்பு அல்லது ஒரு shell prompt-இல் பின்னணியில் சரிபார்க்கும். அந்தப் புதுப்பிப்பு தோல்வியடைந்தால் அல்லது நீங்கள் offline-இல் இருந்தால், நிறுவப்பட்ட பதிப்பு இயங்கும். `omarchy update` Omarchy-இன் மற்ற பகுதிகளுடன் சேர்த்து நிறுவப்பட்ட ஏஜென்ட்களையும் புதுப்பிக்கிறது, மேலும் `mup` mise நிர்வகிக்கும் கருவிகளை மட்டும் புதுப்பிக்கிறது.

`claude update`, `codex update` போன்ற ஒரு ஏஜென்ட்டின் சொந்த updater, அல்லது ஒரு செயலியில் உள்ள update பொத்தான், mise நிர்வகிக்கும் நிறுவலைப் புதுப்பிக்காது. `codex update` தோல்வியடைகிறது, மேலும் `claude update` வெற்றி என்று தெரிவித்தாலும் mise கண்காணிக்காத ஒரு தனி நகலை நிறுவக்கூடும். ஒரு ஏஜென்ட்டின் சொந்த நிறுவி மற்றும் updater-ஐ நீங்கள் பயன்படுத்த விரும்பினால், அதை `disable_tools`-இல் சேர்க்கவும்; [முன்பே நிறுவப்பட்ட CLI கருவிகள்](18-development-tools.md#preinstalled-cli-tools) என்பதைப் பார்க்கவும்.

நீங்கள் அவை தேவைப்படுவதற்கு முன்பே கட்டமைக்கப்பட்ட அனைத்து lazy கருவிகளையும் நிறுவ, `mise install --include-lazy` என்பதை இயக்கவும். இதில் ஏஜென்ட்களும் Omarchy-இன் மற்ற இயல்புநிலை CLI கருவிகளும் அடங்கும். ஒரு கருவியை மட்டும் நிறுவுவது அல்லது உங்கள் சொந்த நிறுவலைப் பயன்படுத்துவது பற்றி [முன்பே நிறுவப்பட்ட CLI கருவிகள்](18-development-tools.md#preinstalled-cli-tools) என்பதைப் பார்க்கவும்.

`grok` என்பது `claude` மற்றும் `codex` போலவே mise-இன் முதல்-தரப்பு `grok` package வழியாக நிறுவப்படுகிறது. `grok` என்பதை இயக்கவும், அல்லது ஏஜென்ட்கள் பேனலில் அதை நட்சத்திரமிடவும். x.ai-இல் உள்ள `curl | bash` நிறுவியைத் தவிர்க்கவும். அந்த வழி `~/.grok/bin`-இல் இரண்டாவது நகலை வைக்கிறது, அதை `PATH`-இல் முன்னால் சேர்க்கிறது, மேலும் Omarchy-இன் wrapper-ஐ மேலெழுதுகிறது.

`dsh` அதன் browser UI-ஐ `127.0.0.1:3080`-இல் திறக்கிறது, அதன் இயல்புநிலை workspace ஆக தொடக்க கோப்பகம் இருக்கும். அதன் browser UI தொடக்க prompt-ஐ எடுக்காது, எனவே `omarchy agent prompt` அதை உங்கள் clipboard-இல் ஒட்டுவதற்கான prompt உடன் திறக்கிறது. Omarchy அதை DeepSeek-இன் no-approval அனுமதி முன்னமைப்புடன் தொடங்குகிறது. நீங்கள் அதன் அதிகாரப்பூர்வ மாடல் API-ஐப் பயன்படுத்தும்போது DeepSeek Harness அமர்வு பதிவுகளை DeepSeek-க்கு பதிவேற்றுகிறது; அதன் browser UI-இல் _Settings > General > Upload Session Log_ என்பதன் கீழ் அதை அணைக்கவும். நீங்கள் `DSH_TELEMETRY_MODE=DISABLED` உடன் அதைத் தொடங்காத வரை, நீங்கள் அதற்கு அனுப்பும் கருத்தும் அமர்வுடன் சேர்த்து பதிவேற்றப்படும்.

### இயல்புநிலை ஏஜென்ட்

ஏஜென்ட்கள் பேனலில் ஒரு ஏஜென்ட்டுக்கு அருகில் உள்ள நட்சத்திரம் மூலம் உங்கள் இயல்புநிலை ஏஜென்ட்டைத் தேர்ந்தெடுக்கவும், அது இயல்புநிலையில் நிரப்பப்பட்டிருக்கும், அல்லது `omarchy default agent <name>` மூலம் தேர்ந்தெடுக்கவும், இது அங்கு ஒரு வரி இல்லாத எந்த harness-ஐயும் எடுக்கும். ஏஜென்ட் இன்னும் நிறுவப்படவில்லை என்றால், அதைத் தேர்ந்தெடுப்பது முதலில் அதை நிறுவும், மேலும் அது app launcher-இல் Agent-க்கு அருகில் அதன் சொந்த லாஞ்சரையும் பெறும். புதிய Omarchy ஒரு முறை மட்டுமே வரும் அறிவிப்புடன் ஒன்றை அமைக்க உங்களை அழைக்கிறது, அது ஏஜென்ட்கள் பேனலைத் திறக்கும்.

Claude-ஐத் தேர்ந்தெடுப்பது Chromium, Chrome, Brave, Brave Origin, மற்றும் Edge ஆகியவற்றுக்கான அதன் browser extension-ஐ அமைக்கவும் முயற்சிக்கிறது. extension அமைப்பு அனைத்து பயனர்களுக்கும் பொருந்தும் மற்றும் உங்கள் system password-ஐக் கேட்கலாம்; ரத்து செய்வது அல்லது extension நிறுவல் தோல்வியடைவது Claude-ஐத் தேர்ந்தெடுப்பதையும் தொடங்குவதையும் தடுக்காது. உங்கள் browser-ஐ மறுதொடக்கம் செய்யவும், கேட்கப்பட்டால் extension-ஐ இயக்கவும், மேலும் அதை இணைப்பதை முடிக்க Claude-இல் உள்நுழையவும். இணைப்பைச் சரிபார்க்க Claude-இல் `/chrome` என்பதை இயக்கவும். Firefox மற்றும் Zen இந்த extension-ஐ ஆதரிக்காது. இந்த அமைப்பு சேர்க்கப்படுவதற்கு முன்பே Claude உங்கள் இயல்புநிலையாக இருந்தால், extension-ஐ நிறுவ அதை மீண்டும் தேர்ந்தெடுக்கவும்.

நீங்கள் தேர்ந்தெடுத்த பிறகு, `Super + Shift + Ctrl + A` இயல்புநிலை ஏஜென்ட்டை ஒரு பிரத்யேக terminal சாளரத்தில் தொடங்கும் (அல்லது நீங்கள் இன்னும் தேர்ந்தெடுக்கவில்லை என்றால் picker-ஐக் கொண்டுவரும்). நீங்கள் அதை `omarchy agent prompt "Review this project"` என்று நேரடியாக ஒரு பணிக்குள் தொடங்கலாம். Freebuff மற்றும் DeepSeek Harness தொடக்க prompt-ஐ எடுக்காது, எனவே அவை அதற்கு பதிலாக உங்கள் clipboard-இல் ஒட்டுவதற்கான prompt உடன் திறக்கும். இவ்வாறு தொடங்கப்படும் ஏஜென்ட்கள் அவற்றின் அந்தந்த don't-stop-to-ask முறைகளில் கவனிக்கப்படாமல் இயங்கும், எனவே அவை உண்மையில் விஷயங்களைச் செய்ய தயாராக இருங்கள்! MiniMax Code அதன் ஊடாடும் அமர்வுகளுக்கு அத்தகைய முறை இல்லை, எனவே அது வழக்கம் போல் அனுமதிகளைக் கேட்கும். மேலும் ஏஜென்ட்கள் உங்கள் home directory-க்கான நம்பிக்கையை நினைவில் வைக்க மறுப்பதால், `$HOME`-இலிருந்து தொடங்குவது அதற்கு பதிலாக `~/Work`-இல் தொடங்கும்.

terminal குறுக்குவழிகளும் உள்ளன: `a` தற்போதைய terminal-இல் இயல்புநிலை ஏஜென்ட்டை inline ஆக இயக்குகிறது, அதே நேரத்தில் `c`, `cx`, மற்றும் `cy` ஆகியவை OpenCode, Claude Code, மற்றும் Codex-ஐ நேரடியாகத் தொடங்குகின்றன (மீண்டும் அவற்றின் auto-approving முறைகளில்). Theme மாற்றங்களும் ஏஜென்ட்களுக்கு ஒத்திசைகின்றன: நீங்கள் Omarchy theme-ஐ மாற்றும்போது Claude Code, Pi, OpenCode, மற்றும் Hermes (Omarchy அதை நிறுவிய பிறகு) அனைத்தும் பின்தொடர்கின்றன.

### உங்கள் ஏஜென்ட் அறிவுறுத்தல்கள்

ஒவ்வொரு ஏஜென்ட்டுக்கான தனிப்பட்ட விதிகள் `~/.agents/skills`-இல் உள்ள பகிரப்பட்ட திறன்களுக்கு அருகில் `~/.agents/AGENTS.md`-இல் செல்கின்றன. ஏஜென்ட்கள் பேனலில் + க்கு அருகில் உள்ள document icon மூலம் அதைத் திறக்கவும், அல்லது `omarchy agent instructions --edit` மூலம் திறக்கவும், இது அதன் சொந்த உலகளாவிய கோப்பை வைத்திருக்கும் ஒவ்வொரு harness-இலும் அதை இணைக்கிறது: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, Copilot-இன் `~/.copilot/copilot-instructions.md`, மற்றும் பல. Crush மற்றும் Amp `~/.config/AGENTS.md` இணைப்பைப் படிக்கின்றன, அதே நேரத்தில் omp, Kimi, மற்றும் DeepSeek Harness `~/.agents/AGENTS.md`-ஐ நேரடியாகப் படிக்கின்றன. ஒரு இயல்புநிலை ஏஜென்ட்டைத் தேர்ந்தெடுப்பதும் அதை இணைக்கிறது. இன்னும் எதுவும் இல்லை என்றால் நீங்கள் ஏற்கனவே வைத்திருந்த ஒரு அறிவுறுத்தல் கோப்பு பகிரப்பட்டதாக மாறும்; இல்லையெனில் அது இணைப்புக்கு அருகில் `.bak` ஆக வைக்கப்படும். மற்றொரு ஏஜென்ட்டை நிறுவிய பிறகு மீண்டும் இணைக்க `omarchy agent instructions` என்பதை இயக்கவும்.

### ஏஜென்ட்கள் பேனல்

மேல் பட்டியில் ஒரு ஏஜென்ட்கள் icon உள்ளது. நீங்கள் ஒரு ஏஜென்ட்டை அமைப்பதற்கு முன், அதன் பேனல் தொடங்க மூன்று வழிகளை வழங்குகிறது: ஒரு Claude, Codex, Grok, Gemini, Muse, Cursor, அல்லது Copilot சந்தாவில் உள்நுழையவும், அல்லது More-இன் கீழ் ஒரு OpenCode Go, MiniMax, Synthetic, அல்லது Z.ai குறியீட்டுத் திட்டம்; Fireworks, OpenCode Zen and Go, OpenRouter, அல்லது More-இன் கீழ் DeepSeek அல்லது OpenCode உள்நுழையும் வேறு எந்த provider உடன் கூட நீங்கள் செல்லும்போது செலுத்தவும், அனைத்தும் OpenCode-இல் இயங்கும்; அல்லது உங்கள் கணினிக்கு பொருந்தும்போது அதற்கான சிறந்த மாடலை இயக்கவும். நீங்கள் முதலில் முடிப்பது உங்கள் இயல்புநிலை ஏஜென்ட் ஆகிறது, மேலும் பேனலில் உள்ள + பின்னர் அதே மூன்றையும் வழங்குகிறது. அதற்குப் பிறகு, பேனல் ஒவ்வொரு சந்தாவையும் ஒரே பக்கத்தில் வைக்கிறது: ஒவ்வொரு ஏஜென்ட் மற்றும் கணக்கு அதன் திட்டத்துடன், அதன் 5-மணிநேர அமர்வு மற்றும் வாராந்திர வரம்புகள் ஒவ்வொன்றுக்கும் ஒரு மீட்டர் மற்றும் அது மீட்டமைக்கும் வரையிலான நேரம் (சரியான சதவீதத்திற்கு hover செய்யவும்), அல்லது மீதமுள்ள prepaid இருப்பு, நீங்கள் அவை அனைத்திலும் பயன்படுத்தியதை சுழற்றும் ஒரு வரியின் கீழ், இந்த வாரத்தின் tokens மற்றும் உங்கள் அதிகம் பயன்படுத்தப்பட்ட மாடல் போன்றவை. _Make something cool_ என்பதன் கீழ் அது உங்கள் இயல்புநிலை ஏஜென்ட்டிடம் பணியை ஒப்படைக்கும் ஒரு புதிய theme, plugin, app, அல்லது game-க்கான starter prompt-களை வழங்குகிறது. Omarchy-இன் சொந்த Hype, Monologue, மற்றும் Omacut போலவே C++ மற்றும் Qt Quick-இல், omarchy-make-app ஏஜென்ட் திறனைப் பின்பற்றி செயலிகள் கட்டப்படுகின்றன, மேலும் அவற்றுக்குத் தேவையான compiler மற்றும் Qt பகுதிகள் நிறுவப்பட்டு வருகின்றன. Games என்பது omarchy-make-game ஏஜென்ட் திறனைப் பின்பற்றி `~/Games/vibes`-இல் உள்ள ஒற்றை three.js பக்கம், மேலும் அனைத்தும் தற்போதைய theme-இல் ஒரு Game Vibes லாஞ்சரிலிருந்து திறக்கும்; அவை web-இலிருந்து three.js-ஐ ஏற்றுகின்றன, எனவே அவை தொடங்க ஒரு இணைப்பு தேவை. Claude Code, Codex, Grok, Kimi, Cursor மற்றும் அதன் Grok Bot அனுமதி, GitHub Copilot, Muse, Gemini (Antigravity வழியாக), மற்றும் Devin ஆகியவை அவற்றின் வரம்புகளுடன் பெட்டியிலிருந்தே உள்ளடக்கப்பட்டுள்ளன, Kimchi அதன் திட்டம், prepaid வரவுகள், மற்றும் செலவு பட்ஜெட்டுகளுடன், மேலும் Hermes, Mistral Vibe, மற்றும் Qwen Code நீங்கள் அவற்றைப் பயன்படுத்திய பிறகு அவற்றின் அமர்வுகள் மற்றும் tokens-ஐக் காட்டுகின்றன. நீங்கள் pi, omp, அல்லது opencode வழியாகப் பயன்படுத்தும் Provider திட்டங்கள் மற்றும் key-களும் காட்டப்படும்: OpenCode Zen and Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan, மற்றும் Synthetic அவற்றின் வரம்புகளுடன்; OpenRouter மற்றும் DeepSeek அவற்றின் prepaid இருப்புகளுடன்; Fireworks கடந்த 30 நாட்களில் அதன் செலவுடன். உங்கள் சொந்த hardware-இல் நீங்கள் இயக்கும் குறியீட்டு மாடல்கள் அவற்றின் சொந்த வரிகளைப் பெறுகின்றன, மேலும் அவற்றின் tokens-ம் மொத்தங்களில் கணக்கிடப்படுகின்றன, [உள்ளூர் மாடல்கள்](#local-models) என்பதன் கீழ் விவரிக்கப்பட்டபடி. ஒவ்வொரு ஏஜென்ட்டும் ஒரு முறை மட்டுமே கணக்கிடப்படுகிறது, அதை யார் பில் செய்கிறார்களோ அவரின் கீழ், நீங்கள் எத்தனை harness-கள் வழியாக அதை இயக்கினாலும்.

பேனலுக்கு பட்டி icon-ஐ left-click செய்யவும் அல்லது `Super + Ctrl + X` அழுத்தவும், உங்கள் இயல்புநிலை ஏஜென்ட்டைத் தொடங்க right-click செய்யவும், மற்றும் புதுப்பிக்க middle-click செய்யவும். அதன் பின்னால் உள்ள பயன்பாட்டு பதிவுகள் ஒவ்வொரு 15 நிமிடங்களுக்கும் `omarchy agent usage update` மூலம் மீண்டும் உருவாக்கப்படுகின்றன, மேலும் பேனல் ஒரு ஒத்திசைக்கப்பட்ட கோப்புறை வழியாக உங்கள் மற்ற இயந்திரங்களிலிருந்து பயன்பாட்டையும் இணைக்க முடியும். முழு அமைப்புகளுக்கு `$OMARCHY_PATH/shell/plugins/agents/` என்பதன் கீழ் உள்ள README-ஐப் பார்க்கவும்.

### பல சந்தாக்கள்

நீங்கள் ஒன்றுக்கு மேற்பட்ட Claude, Codex, அல்லது Grok திட்டத்திற்கு பணம் செலுத்தினால் — உதாரணமாக ஒரு தனிப்பட்ட Max மற்றும் ஒரு வேலை திட்டம் — Omarchy அவை அனைத்தையும் உள்நுழைந்த நிலையில் வைத்து அவற்றுக்கிடையே நகர முடியும். ஏஜென்ட்கள் பேனலில் + மூலம் ஒரு சந்தாவைச் சேர்க்கவும், அது அங்கேயே உங்களை அதன் வழியாக அழைத்துச் செல்லும், அல்லது `omarchy agent account add claude Work` (அல்லது `codex`, அல்லது `grok`) மூலம் சேர்க்கவும். அதே + மற்றும் கட்டளை Gemini (`gemini`) மற்றும் OpenCode (`opencode`)-இல் உள்நுழைகிறது, மேலும் OpenCode-இல் ஒரு Fireworks (`fireworks`) அல்லது OpenRouter (`openrouter`) API key-ஐ சேமிக்கிறது; கட்டளை Copilot (`copilot`), Cursor (`cursor`), மற்றும் Muse (`muse`)-இலும் உள்நுழைகிறது. அவை ஒவ்வொன்றும் ஒரு உள்நுழைவை மட்டுமே வைத்திருக்கும். அது காணவில்லை என்றால் CLI-ஐ நிறுவும். ஒரு provider-க்கான முதல் கணக்கு, CLI எப்போதும் பார்க்கும் இடத்திலேயே, உங்கள் சாதாரண browser வழியாக உள்நுழைகிறது. அதற்குப் பிறகு ஒவ்வொன்றும் ஒரு private சாளரம் வழியாக உள்நுழைகிறது, எனவே உங்கள் browser ஏற்கனவே உள்நுழைந்துள்ள கணக்கு தவறுதலாக எடுக்கப்படாது; அங்கு நீங்கள் சேர்க்கும் கணக்காக உள்நுழையவும், மேலும் நீங்கள் ஏற்கனவே திறந்து வைத்திருந்த எந்த private சாளரத்தையும் முதலில் மூடவும். இதைச் செய்ய CLI-இலிருந்து ஒருபோதும் வெளியேற வேண்டாம்: வெளியேறுவது சேமிக்கப்பட்ட உள்நுழைவை ரத்து செய்யும், மேலும் அந்தக் கணக்கு மீண்டும் சேர்க்கப்பட வேண்டும்.

உங்கள் சந்தா உள்நுழைவுகளை SSH வழியாக மற்றொரு Omarchy இயந்திரத்திற்கு நகலெடுக்க, `omarchy agent account copy user@laptop` என்பதை இயக்கவும். இலக்கில் ஒன்று நிறுவப்படவில்லை என்றால் அனுப்புபவர் ஒரு தற்காலிக receiver-ஐ வழங்குகிறார், எனவே பழைய Omarchy இயந்திரங்கள் ஒரு புதுப்பிப்பு இல்லாமல் கணக்குகளைப் பெற முடியும். நிறுவப்பட்ட receiver-கள் முன்னுரிமை பெறுகின்றன. இது அனைத்து Claude, Codex, மற்றும் Grok சந்தாக்களையும் நகலெடுக்கிறது; `omarchy agent account copy laptop claude` என்பதில் உள்ளது போல அவற்றைத் தேர்ந்தெடுக்க provider பெயர்களைச் சேர்க்கவும். கணக்கு பெயர்கள் மற்றும் கட்டளை ID-கள் மூலத்துடன் பொருந்துகின்றன, இலக்கில் ஏற்கனவே உள்ள கணக்குகள் உட்பட. தொடர்பில்லாத இலக்கு கணக்குகளின் பெயர்கள் முரண்பட்டால் அவை ஒரு எண் பின்னொட்டைப் பெறுகின்றன, மேலும் அமைப்புகள், திறன்கள், plugin-கள், மற்றும் உரையாடல் வரலாறு ஒவ்வொரு இயந்திரத்திற்கும் உள்ளூராகவே இருக்கும்.

இருக்கும் இலக்கு நற்சான்றிதழ்கள் வைக்கப்படுகின்றன. அங்கு ஏற்கனவே உள்நுழைந்துள்ள ஒரு மூல கணக்கு அதன் நற்சான்றிதழ்களை மாற்றாமல் அதன் பெயர் ஒத்திசைக்கப்படுகிறது; மற்ற கணக்குகள் அதனுடன் சேர்க்கப்படுகின்றன. பொருந்தும் கணக்குகளுக்கான சேமிக்கப்பட்ட நற்சான்றிதழ்களை மாற்ற, இலக்கில் அந்தக் கணக்கின் அமர்வுகளை விட்டு வெளியேறிய பிறகு `omarchy agent account copy --replace laptop claude` என்பதைப் பயன்படுத்தவும். ஒரு புதிய இலக்கு மூலத்தின் செயலில் உள்ள கணக்கு மற்றும் மாறுதல் விருப்பங்களையும் பெறுகிறது; ஒரு நிறுவப்பட்ட இலக்கு அதன் சொந்தத்தை வைத்திருக்கிறது.

நற்சான்றிதழ்கள் SSH வழியாக பயணம் செய்து இலக்கில் தனிப்பட்ட கோப்புகளில் சேமிக்கப்படுகின்றன, எனவே நீங்கள் நம்பும் இயந்திரங்களுக்கு மட்டும் நகலெடுக்கவும். இது ஒரு முறை நகல், தொடர்ச்சியான ஒத்திசைவு அல்ல. Codex refresh tokens மற்றொரு இயந்திரத்தால் சுழற்றப்படலாம், ஒரு நகலெடுக்கப்பட்ட உள்நுழைவை புதுப்பிக்க வேண்டிய நிலையில் விட்டுவிடும்; பல இயந்திரங்களில் ஒரே நேரத்தில் பயன்படுத்துவதற்கு தனி உள்நுழைவுகள் மிகவும் நம்பகமான தேர்வாக இருக்கும். [Codex's account authentication guidance](https://developers.openai.com/codex/auth/ci-cd-auth) என்பதைப் பார்க்கவும்.

ஒரு provider-க்கு ஒரு கணக்கு செயலில் உள்ளது, மேலும் ஒவ்வொரு புதிய அமர்வும் அதுவாகவே தொடங்குகிறது: `cx`, `cy`, ஒரு எளிய `claude`, `codex`, அல்லது `grok`, `omarchy agent` வழியாக தொடங்கப்பட்ட எதுவும், மற்றும் `PATH`-இல் CLI-ஐக் கண்டறியும் script-கள் அல்லது editor-கள். `omarchy agent account use work` மூலம் மாற்றவும் (மற்றும் `omarchy agent account use main` மூலம் திரும்பவும்), அல்லது பேனலில் ஒரு கணக்கின் எண்ணை அழுத்தி பின்னர் `Enter` (அல்லது அதன் நட்சத்திரத்தை click செய்வதன் மூலம்) மாற்றவும். இயங்கும் Claude அமர்வுகளும் அவற்றின் அடுத்த செய்தியிலிருந்து மாறுகின்றன: ஒவ்வொரு Claude அமர்வும் `~/.claude`-இல் இயங்குகிறது, அது எப்போதும் செயலில் உள்ள கணக்கின் உள்நுழைவை வைத்திருக்கும். ஒரு பழைய Omarchy மூலம் ஒரு கணக்கின் சொந்த கோப்புறையில் தொடங்கப்பட்ட ஒரு Claude அமர்வு அது வெளியேறும் வரை அந்த உள்நுழைவை வைத்திருக்கும், எனவே மாற்றம் அந்த அமர்வுகளைப் பெயரிட்டு அவை போன பிறகு தானாகவே முடிகிறது. இயங்கும் Codex மற்றும் Grok அமர்வுகள் அவை தொடங்கிய கணக்கிலேயே இருக்கும். உரையாடல் வரலாறு, அமைப்புகள், திறன்கள், மற்றும் plugin-கள் கணக்குகள் முழுவதும் பகிரப்படுகின்றன, எனவே அதே கோப்புறையில் `claude --continue` நீங்கள் புதிய கணக்கில் விட்ட இடத்திலிருந்து தொடர்கிறது.

ஒன்றுக்கு மேற்பட்ட கணக்குகளுடன், பேனல் ஒவ்வொரு கணக்கின் வரம்புகளையும் அருகருகே காட்டுகிறது, பயன்பாட்டில் உள்ளதில் ஒரு நிரப்பப்பட்ட நட்சத்திரத்துடன். செயலில் உள்ள கணக்கு ஒரு வரம்பின் 95% ஐ கடக்கும்போது Omarchy உங்களுக்கு அறிவிக்கிறது, மேலும் அறிவிப்பை click செய்வது அதிக இடம் உள்ள கணக்கிற்கு மாற்றுகிறது. அது ஒருபோதும் தானாக மாறாது. `omarchy agent account threshold 90` மூலம் வரம்பை மாற்றவும். ஒவ்வொரு கணக்கும் வரம்பை விட அதிகமாக இருந்தால், எந்தக் கணக்கு முதலில் விடுபடுகிறது என்பதுடன் அதைப் பற்றி ஒரு முறை கேட்பீர்கள். ஒரு செயலில் உள்ள கணக்கு அதன் வரம்பிலிருந்து 15 புள்ளிகளுக்குள் இருக்கும்போது (இயல்புநிலையில் 80%), அதன் வரம்புகள் ஒவ்வொரு 15 நிமிடங்களுக்கும் பதிலாக ஒவ்வொரு மூன்று நிமிடங்களுக்கும் சரிபார்க்கப்படுகின்றன.

`omarchy agent account list` ஒவ்வொரு கணக்கையும் அதன் சமீபத்திய வரம்புகளையும் காட்டுகிறது, `omarchy agent account remove work` ஒன்றை மறக்கிறது, மற்றும் `omarchy agent account rename primary Hey` ஒன்றை மறுபெயரிடுகிறது (அல்லது பேனலில் ஒரு கணக்கின் பெயரை click செய்யவும்). இந்தக் கட்டளைகள் உங்கள் இயல்புநிலை ஏஜென்ட்டின் கணக்குகளில் வேலை செய்கின்றன; மற்ற provider-ஐ அடைய, `omarchy agent account use codex side` என்பதில் உள்ளது போல அதை முதலில் பெயரிடவும். `~/.claude` அல்லது `~/.codex`-இல் நீங்கள் ஏற்கனவே வைத்திருந்த உள்நுழைவு _Main_ கணக்கு. Codex-இன் அது இருக்கும் இடத்திலேயே இருக்கிறது; Claude-இன் மற்றொரு கணக்கு செயலில் இருக்கும்போது அதன் சொந்த கோப்புறையில் காத்திருக்கிறது. சுமார் எட்டு மணிநேரத்திற்கும் மேலாக பயன்படுத்தப்படாமல் விடப்பட்ட ஒரு கணக்கு _Sign-in required_ என்று காட்டலாம்; அந்தக் கணக்கை பேனலிலேயே மீண்டும் உள்நுழைய அதை click செய்யவும், அல்லது அதற்கு மாறி ஒரு அமர்வைத் தொடங்கவும், அது உள்நுழைவைத் தானாகவே புதுப்பிக்கும். நீங்கள் `claude mcp add` மூலம் சேர்க்கும் MCP server-கள் ஒவ்வொரு Claude கணக்கையும் அடைகின்றன, ஏனெனில் அவை அனைத்தும் `~/.claude`-இல் இயங்குகின்றன; Codex மற்றும் Grok-க்கு, ஒரு கணக்கு சேர்க்கப்படும்போது நீங்கள் வைத்திருந்த server-கள் அதனுடன் வருகின்றன, ஆனால் பின்னர் வந்தவை நீங்கள் அவற்றைச் சேர்த்த கணக்கை மட்டுமே அடைகின்றன. Claude Desktop அதன் சொந்த உள்நுழைவை வைத்திருக்கிறது, மேலும் ஒரு CLI binary-க்கு ஒரு முழுமையான பாதையுடன் கட்டமைக்கப்பட்ட Codex அல்லது Grok கருவிகள் மாற்றத்தைப் பின்பற்றாது. ஒரு வெளிப்படையான `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, அல்லது `GROK_HOME` தேர்ந்தெடுக்கப்பட்ட கணக்கை விட முன்னுரிமை பெறுகிறது.

### செயலிழப்பு கண்டறிதல்

Omarchy செயல்முறை செயலிழப்புகளுக்காக systemd-coredump-ஐக் கண்காணிக்கிறது. நீங்கள் ஒரு இயல்புநிலை ஏஜென்ட்டைத் தேர்ந்தெடுத்த பிறகு, core dump செய்யும் உங்கள் எந்த நிரலும் ஒரு "Process crashed" அறிவிப்பைக் கொண்டுவரும் — அதை click செய்யவும், மேலும் செயலிழப்பு core dump-இலிருந்து உண்மைகளை நிறுவுவதற்கும் செயலிழப்பு upstream-இல் புகாரளிக்கத் தகுதியானதா என்பதைத் தீர்மானிப்பதற்கும் ஏஜென்ட்டை வழிநடத்தும் Omarchy-இன் omarchy-diagnose-crash திறனுடன் உங்கள் இயல்புநிலை ஏஜென்ட்டிடம் ஒப்படைக்கப்படும். நீங்கள் அதை `coredumpctl list`-இலிருந்து எந்த PID-க்கு எதிராகவும் `omarchy agent crash <pid>` மூலம் கையால் இயக்கலாம்.

கண்காணிப்பு இயல்பாகவே இயக்கத்தில் உள்ளது. _Trigger > Toggle > Crash Capture Off_ என்பதன் கீழ் (அல்லது `omarchy toggle crash-capture` மூலம்) அதை அணைக்கவும், அறிவிப்புகள் நிறுத்தப்படும்; `omarchy agent crash <pid>` இன்னும் கையால் வேலை செய்யும்.

செயலிழப்புகளை ஒரு நேரத்தில் ஒரு நிரல் வீதமும் அமைதிப்படுத்தலாம், இதைத்தான் கண்டறிதல் இறுதியில் உங்களுக்கு வழங்குகிறது. `omarchy crash mute hyprland` அந்த நிரலுக்கு மட்டும் அறிவிப்புகளை நிறுத்துகிறது, `omarchy crash mute hyprland off` அவற்றை மீண்டும் கொண்டுவருகிறது, மேலும் `omarchy crash mute` மட்டும் நீங்கள் அமைதிப்படுத்தியதை பட்டியலிடுகிறது. இது binary-இன் பாதையை அதன் பெயரைப் போலவே மகிழ்ச்சியுடன் எடுக்கிறது, எனவே `omarchy crash mute /usr/bin/hyprland` அதையே செய்கிறது. `omarchy crash mute 'Some App'` என்பதில் உள்ளது போல, இடைவெளி உள்ள ஒரு பெயரை மேற்கோள் காட்டவும். மற்ற அனைத்தும் இன்னும் அறிவிக்கின்றன, மேலும் அமைதிப்படுத்தப்பட்ட நிரல் இன்னும் செயலிழக்கிறது — இது நினைவூட்டலை மறைக்கிறது, எதையும் சரி செய்யாது.

### Desktop பயன்பாடுகள்

_Install > AI_ மெனு சில வரைகலை AI செயலிகளையும் கொண்டுள்ளது: Amp Desktop, Antigravity Desktop, ChatGPT desktop app, Claude desktop app (Chat, Cowork, மற்றும் Claude Code தாவல்களுடன் Anthropic-இன் Linux beta), xAI-இன் மாடல்களுடன் அரட்டை அடிக்க Grok Bot, Herdr Desktop, Hermes Desktop, OpenClaw, Perplexity desktop app, மற்றும் T3 Code. Grok Bot என்பது டெஸ்க்டாப் அரட்டை செயலி. குறியீட்டு ஏஜென்ட் என்பது `grok` கட்டளை.

Hermes Desktop என்பது தெரிந்து கொள்ள வேண்டிய ஒன்று, ஏனெனில் ஒரு இயந்திரத்தில் ஒரு Hermes உள்ளது, அது செயலியினுடையது: Hermes எப்போதும் செயலி வழியாக மட்டுமே நிறுவப்படுகிறது, மேலும் இயல்புநிலை ஏஜென்ட் இயக்கும் `hermes` கட்டளை செயலியினுடையது. Hermes-ஐ இயல்புநிலை ஏஜென்ட்டாகத் தேர்ந்தெடுப்பது _Install > AI_ உள்ளீடு செய்வதையே நிறுவுகிறது: package, மற்றும் Hermes-இன் சொந்த நிறுவியால் அமைக்கப்பட்ட `~/.hermes`-இன் கீழ் ஒரு Hermes runtime, இது முதல் முறை சில நிமிடங்கள் எடுக்கும். அந்த runtime என்பது terminal `hermes` கட்டளை, இயல்புநிலை ஏஜென்ட் மற்றும் செயலி அனைத்தும் பயன்படுத்தும் ஒரே Hermes, மேலும் அது Omarchy வெளியீட்டிற்காக காத்திருக்காமல் `hermes update` மூலம் தன்னைப் புதுப்பிக்கிறது. அதை நிறுவுவது Hermes-க்கு Omarchy theme-ஐ `omarchy` என்ற பெயரிடப்பட்ட ஒரு skin ஆகவும் வழங்குகிறது, நீங்கள் theme-களை மாற்றும்போது ஒவ்வொரு Hermes மேற்பரப்பும் அதைப் பின்பற்றுகிறது; நீங்கள் அது வேண்டாம் என்றால் Hermes-இன் Appearance அமைப்புகளின் கீழ் அல்லது `/skin` மூலம் வேறு ஒன்றைத் தேர்ந்தெடுக்கவும், மேலும் Omarchy அந்தத் தேர்வை தனியாக விட்டுவிடும். _Remove > AI_-இன் கீழ் செயலியை நீக்குவது முதலில் Hermes-ஐ மூடுகிறது, gateway உட்பட, அந்த runtime-ஐ அதனுடன் எடுத்துச் செல்கிறது, மேலும் நீங்கள் வேறுவிதமாகச் சொல்லாத வரை உங்கள் அரட்டைகள், நினைவுகள், மற்றும் Hermes தனக்காக எழுதிய திறன்களை வைத்திருக்கிறது: அந்தத் தரவும் உங்கள் இணைப்பு அமைப்புகளும் செல்ல வேண்டுமா என்று அது கேட்கிறது, இயல்புநிலை வேண்டாம் என்பது.

OpenClaw-இன் டெஸ்க்டாப் அனுபவம் அதன் Control UI ஆகும், இது அதன் சொந்த உள்ளூர் gateway ஆல் ஆதரிக்கப்படும் ஒரு web செயலியாகத் திறக்கிறது. OpenClaw `~/.openclaw`-இல் வாழ்கிறது மற்றும் தன்னைப் புதுப்பிக்கிறது: Control UI-இன் "Update Gateway" பொத்தானைப் பயன்படுத்தவும் அல்லது `openclaw update` என்பதை இயக்கவும், மேலும் gateway புதிய பதிப்பில் மறுதொடக்கம் செய்யும். ஒரு புதிய நிறுவல் எந்த வெளியீட்டிலிருந்து தொடங்குகிறது என்பதை மட்டுமே Omarchy தேர்ந்தெடுக்கிறது. OpenClaw உங்கள் இயல்புநிலை ஏஜென்ட்டாகவும் இருக்கலாம்: அதை `omarchy default agent openclaw` மூலம் தேர்ந்தெடுப்பது `~/.openclaw`-இல் அதே நகலை அமைக்கிறது, மேலும் ஏஜென்ட் அதன் gateway உடன் இணைக்கப்பட்ட OpenClaw-இன் terminal UI-ஐத் திறக்கிறது. _Remove > AI_-இன் கீழ் OpenClaw-ஐ நீக்குவது gateway service மற்றும் செயலியை அதனுடன் எடுத்துச் செல்கிறது, பின்னர் `~/.openclaw` செல்ல வேண்டுமா என்று கேட்கிறது, ஏனெனில் அது OpenClaw-உடன் மற்றும் அது பதிவிறக்கும் plugin runtime-களுடன் உங்கள் அரட்டைகள் மற்றும் நற்சான்றிதழ்களை வைத்திருக்கிறது; இயல்புநிலை அதை வைத்திருக்கிறது, மேலும் OpenClaw-ஐ மீண்டும் நிறுவுவது அதை மீண்டும் எடுத்துக் கொள்ளும்.

Herdr Desktop என்பது [Herdr](https://herdr.dev) டெஸ்க்டாப் செயலி: நீங்கள் சாளரத்தை மூடும்போது அதன் core-இல் தொடர்ந்து இயங்கும் terminal-கள் மற்றும் குறியீட்டு ஏஜென்ட்களின் spaces, tabs, மற்றும் panes. இது ஒரு package-ஐ விட Herdr-இன் சொந்த நிறுவியிலிருந்து வருகிறது, எனவே இது `~/.local/share/herdr-app`-இல் வாழ்கிறது, உங்களிடம் ஏற்கனவே ஒன்று இல்லை என்றால் `~/.local/bin/herdr-core`-இல் அதன் core-ஐக் கொண்டுவருகிறது, மேலும் இரண்டையும் புதுப்பிக்கிறது. இது Omarchy `Super + Ctrl + Return`-இல் வழங்கும் `herdr` கட்டளைக்கு பதிலாக அதற்கு அருகில் அமர்கிறது, மேலும் அந்தக் கட்டளையின் நேரடி key-களைப் பெறுகிறது: `Alt + Return` மற்றும் `Alt + Shift + Return` ஒரு pane-ஐ கீழே அல்லது வலதுபுறம் பிரிக்கிறது, `Alt + Escape` அதை மூடுகிறது, `Ctrl + Alt + Arrow` pane-களுக்கு இடையில் நகர்கிறது, `Alt + 1..9` மற்றும் `Alt + Left/Right` ஒரு tab-ஐத் தேர்ந்தெடுக்கிறது, மற்றும் `Alt + Up/Down` spaces-க்கு இடையில் நகர்கிறது. `Ctrl + 1..9` ஒரு space-ஐத் தேர்ந்தெடுக்கிறது மற்றும் `Alt + Shift + Up/Down` ஏஜென்ட்கள் வழியாக படிப்படியாகச் செல்கிறது. `Ctrl + Space` prefix key-கள் terminal-மட்டுமே இருக்கும், ஏனெனில் செயலி ஒரு வரிசைக்காக ஒரு எளிய Ctrl key-ஐ வைத்திருக்க முடியாது. Omarchy இவற்றை `~/.config/herdr-app/keys.json`-இல் எழுதுகிறது, மேலும் `omarchy-refresh-herdr-app` அவற்றை மீண்டும் வைக்கிறது. அதை நிறுவுவது Herdr-இன் Omarchy theme-ஐத் தேர்ந்தெடுக்கிறது, அது அப்போதிலிருந்து உங்கள் Omarchy theme-ஐப் பின்பற்றுகிறது. Herdr light mode-க்கு ஒரு theme-ஐயும் dark mode-க்கு ஒரு theme-ஐயும் வைத்திருக்கிறது, எனவே dark மற்றும் light Omarchy theme-க்கு இடையில் மாறிய பிறகு, மற்ற mode-க்காக Herdr-இன் theme picker-இல் Omarchy-ஐ மீண்டும் ஒரு முறை தேர்ந்தெடுக்கவும்.

T3 Code ஒரு package-இலிருந்து அல்லாமல் `~/.local/share/t3code`-இல் அதன் அதிகாரப்பூர்வ AppImage வெளியீட்டிலிருந்து இயங்குகிறது, எனவே அது தன்னைப் புதுப்பிக்கிறது. அதை நிறுவுவது Stable அல்லது Nightly channel-இல் தொடங்க வேண்டுமா என்று கேட்கிறது; பின்னர் T3 Code-இன் அமைப்புகளில் மாற்றவும். உங்கள் thread-கள் மற்றும் அமைப்புகள் `~/.t3`-இல் வாழ்கின்றன, மேலும் _Remove > AI_-இன் கீழ் T3 Code-ஐ நீக்குவது அவற்றை அதனுடன் எடுத்துச் செல்கிறது.

### உள்ளூர் மாடல்கள்

உங்கள் குறியீட்டு ஏஜென்ட்களுக்காக உங்கள் சொந்த இயந்திரத்தில் ஒரு திறந்த மாடலை இயக்கவும். உங்கள் prompt-கள் மற்றும் குறியீடு இயந்திரத்திலேயே இருக்கும்; மாடலுக்கு அனுப்பப்பட்ட எதுவும் அதை விட்டு வெளியேறாது. இதனுடன் தொடங்கவும்:

```bash
omarchy models use best text
```

அது இந்த இயந்திரத்திற்கான சிறந்த text மாடலை அமைக்கிறது, உங்கள் ஏஜென்ட்கள் பயன்படுத்தும் வகை. Image, video மற்றும் music மாடல்கள் அவற்றின் சொந்த சிறந்ததைக் கொண்டுள்ளன: `omarchy models use best image`, `video` அல்லது `music`. இந்த இயந்திரத்திற்கான ஒவ்வொரு வகையின் தேர்வையும் பார்க்க `omarchy models use best` என்பதை இயக்கவும்.

அல்லது ஏஜென்ட்கள் பேனலில் + ஐத் தேர்ந்தெடுக்கவும்: _Use a local model_-இன் கீழ் அது இந்த இயந்திரத்திற்கு பொருந்தும் ஒவ்வொரு குறியீட்டு மாடலையும் பட்டியலிடுகிறது, பரிந்துரைக்கப்பட்டது முதலில். மாடல்களை இயக்கும் Podman, Omarchy உடன் வருகிறது, NVIDIA இயந்திரத்தில் NVIDIA-இன் container toolkit-ம் வருகிறது, இது அவற்றுக்கு GPU-ஐ வழங்குகிறது; இரண்டில் ஒன்று காணவில்லை என்றால், முதல் அமைப்பு அதை நிறுவும். பின்னர் Omarchy இந்த இயந்திரத்திற்கான பரிந்துரைக்கப்பட்ட மாடலைத் தேர்ந்தெடுக்கிறது, அதைப் பதிவிறக்குகிறது, மற்றும் அதைத் தொடங்குகிறது. பத்து GB அளவிலான பதிவிறக்கத்தையும், மாடல் இயங்கும்போது இயந்திரத்தின் நினைவகத்தின் பெரும்பகுதி பயன்பாட்டில் இருக்கும் என்பதையும் எதிர்பார்க்கவும்: Flash Next அதன் முழு 256K context உடன் சுமார் 100 GiB பயன்படுத்துகிறது. அதற்குத் தேவையான நினைவகத்தை மற்ற மாடல்கள் வைத்திருந்தால், அது நிறுத்தப்பட்ட நிலையில் அமைக்கப்படுகிறது, நீங்கள் ஒன்றை நிறுத்தியவுடன் தொடங்க தயாராக உள்ளது. மாடல் வெளியேறும்போது நிறுத்தப்படும்; உங்களுக்கு வேறு ஏதாவதுக்கு நினைவகம் தேவைப்படும்போது அதை நீங்களே நிறுத்தவும்.

`omarchy models list` விருப்பங்களைக் காட்டுகிறது மற்றும் சில ஏன் பொருந்தாது என்பதை விளக்குகிறது. மற்றொன்றை அமைக்க, `omarchy models use <recipe>` என்பதை இயக்கவும். இன்று, 128 GB Strix Halo இயந்திரங்களுக்கு `qwen3.8-flash-next-gufo` மற்றும் `qwen3.8-27b-gufo` கிடைக்கின்றன; 27B சுமார் 40 GiB எடுக்கும், எனவே அது மற்ற வேலைக்கு இடமளிக்கிறது. Intel-இன் Arc B390 உடன் 64 GB laptop-இல், `qwen3.6-35b-a3b-llamacpp` சுமார் 30 GiB-இல் இயங்குகிறது. புதிய recipe-கள் மற்றும் பரிந்துரைகள் package வழியாக `omarchy update` உடன் வருகின்றன.

நீங்கள் சேர்க்கும் ஒரு குறியீட்டு மாடல் உங்கள் சந்தாக்களுக்கு அருகில் ஏஜென்ட்கள் பேனலில் அதன் சொந்த வரியைப் பெறுகிறது: அதைத் தொடங்க play, அதை நிறுத்த மற்றும் அதன் நினைவகத்தை விடுவிக்க pause, அது இயங்கும்போது உங்கள் tailnet-இல் உள்ள மற்ற இயந்திரங்களுடன் அதைப் பகிர Tailscale குறி, மற்றும் அதில் உங்கள் ஏஜென்ட்டைத் திறக்க terminal பொத்தான். அதன் வரி அது செல்லும்போது பதிவிறக்கம், ஏற்றம் அல்லது நிறுத்தத்தைக் காட்டுகிறது, மேலும் அதைத் தொடங்க போதுமான இலவச நினைவகம் இல்லாதபோது அதைச் சொல்கிறது, அல்லது அது ஒரு பிழையுடன் நிறுத்தப்படும்போது அதன் பதிவுகளுக்கு இணைக்கிறது. அவை நினைவகத்தில் ஒன்றாகப் பொருந்தும்போது பல ஒரே நேரத்தில் இயங்க முடியும். தேர்ந்தெடுக்கப்பட்ட வரியில் Delete அழுத்தி இந்த இயந்திரத்திலிருந்து மாடலை நீக்கவும், பதிவிறக்கமும் உட்பட; + அதை மீண்டும் அமைக்க முடியும். ஒரு terminal-இலிருந்து அமைக்கப்பட்ட ஒரு குறியீட்டு மாடல் நீங்கள் அதைச் சேர்க்கும் வரை + இன் கீழ் காத்திருக்கிறது, நீங்கள் இணைத்த ஒரு இயந்திரம் (`omarchy models pair <host>`) இயக்கும் மாடல்களும் அப்படியே.

நீங்கள் அமைக்கும் ஒவ்வொரு குறியீட்டு மாடலும் app launcher-இல் அதன் சொந்த உள்ளீட்டையும் பெறுகிறது, மாடலின் பெயரின் கீழ் மற்றும் அதன் தயாரிப்பாளரின் logo உடன், Claude, Codex அல்லது Grok-இல் உள்நுழைவது ஒன்றைச் சேர்ப்பது போல. அது அந்த மாடலில் உங்கள் ஏஜென்ட்டைத் திறக்கிறது, மேலும் அது இயங்கவில்லை என்றால் முதலில் மாடலைத் தொடங்குகிறது: terminal அது ஏற்றப்படுவதைக் காட்டுகிறது மற்றும் அது தயாரானவுடன் ஏஜென்ட்டிடம் ஒப்படைக்கிறது. ஒரு மாடலை நீக்குவது அதன் உள்ளீட்டை நீக்குகிறது.

ஒவ்வொரு மாடலும் குறியீட்டுக்காக அல்ல. Image, video மற்றும் music மாடல்கள் அதற்கு பதிலாக Fantasi-இல் திறக்கும், இந்த இயந்திரத்தில் இயங்கும் ஒரு மாடலுடன் படங்கள், video மற்றும் music உருவாக்குவதற்கான Omarchy-இன் செயலி, மேலும் அங்கு அல்லது `omarchy models` மூலம் நிர்வகிக்கப்படுகின்றன.

ஒரு மாடல் அது அமைக்கப்பட்டது போலவே தொடர்ந்து இயங்குகிறது, எனவே ஒரு Omarchy புதுப்பிப்பு உங்கள் ஏஜென்ட்களின் கீழ் ஒன்றை ஒருபோதும் மறுதொடக்கம் செய்யாது. நீங்கள் அமைத்துள்ள ஒரு மாடலுக்கு Omarchy-இல் புதிய runtime அல்லது புதிய weights இருக்கும்போது, அதன் வரி ஒரு update பொத்தானைக் காட்டுகிறது: அதை அழுத்தவும், மாடல் பின்னணியில் மீண்டும் அமைக்கப்படுகிறது, மாறியதை மட்டும் பதிவிறக்குகிறது, மேலும் புதிய பதிப்பில் மறுதொடக்கம் செய்கிறது. நிறுத்தப்பட்ட ஒரு மாடல் நிறுத்தப்பட்டதாகவே இருக்கும். `omarchy models update` ஒரு terminal-இலிருந்து ஒவ்வொரு மாடலுக்கும் அதையே செய்கிறது.

Command line-இலிருந்து, `omarchy models start <recipe>` மற்றும் `omarchy models stop <recipe>` அதையே செய்கின்றன, `omarchy models status` ஒவ்வொரு மாடலையும் காட்டுகிறது, மேலும் `omarchy agent --local-model <recipe>` உங்கள் இயல்புநிலை ஏஜென்ட் எதுவாக இருந்தாலும் அந்த மாடலை pi-இல் திறக்கிறது. உங்கள் உள்ளூர் மாடலை ஏஜென்ட் hotkey, Quake console, மற்றும் _Make something_ திறப்பதாக மாற்ற, `omarchy default agent local` என்பதை இயக்கவும் அல்லது ஏஜென்ட்கள் பேனலில் இயங்கும் ஒரு மாடலை நட்சத்திரமிடவும். pi நீங்கள் அமைத்துள்ள ஒவ்வொரு மாடலையும், மற்றும் நீங்கள் இணைத்த இயந்திரங்களில் உள்ளவற்றையும், அதன் சொந்த மாடல் picker-இல் பட்டியலிடுகிறது, எனவே எளிய `pi` அவற்றையும் அடையும். எந்த OpenAI-இணக்கமான client-ம் இணைக்க முடியும்: `status` ஒவ்வொரு மாடலின் முகவரியையும் காட்டுகிறது (முதலாவது `http://127.0.0.1:11435/v1`), recipe பெயர் மாடல், மற்றும் key `~/.config/omarchy/agent-local/key`-இல் உள்ளது.

`omarchy models remove <recipe>` ஒரு மாடலையும் வேறு எந்த மாடலும் பயன்படுத்தாத பதிவிறக்கங்களையும் நீக்குகிறது.

Third-party runtime-கள் அவற்றின் publisher உடன் லேபிளிடப்படுகின்றன. Omarchy ஒவ்வொரு மாடலையும் network அணுகல் இல்லாமல் இயக்குகிறது.

### உள்ளூர் LLMகள்

Omarchy உள்ளூர் LLM மாடல்களை இயக்க இரண்டு வழிகளைப் பரிந்துரைக்கிறது: LM Studio மற்றும் Ollama. LM Studio திறந்த-எடை மாடல்களைக் கண்டறிவதற்கும், அவற்றை நிறுவுவதற்கும், அவற்றை இயக்குவதற்கும் ஒரு GUI interface-ஐ வழங்குகிறது. எளிதாகத் தொடங்க இது ஒரு சிறந்த வழி. Ollama அதையே செய்வதற்கு ஒரு CLI-ஐ வழங்குகிறது. ஆனால் நீங்கள் உள்ளூர் மாடல்களுக்குப் புதியவர் என்றால், நான் LM Studio உடன் தொடங்குவேன். நீங்கள் Omarchy Menu-இல் _Install > AI_-இன் கீழ் இரண்டில் ஒன்றை நிறுவலாம்.

### Omarchy திறன்கள்

ஏஜென்ட் திறன்கள் AI குறிப்பிட்ட கருவிகளை ஒரு குறிப்பிட்ட வழியில் பயன்படுத்த உதவுகின்றன, மேலும் Omarchy அவற்றில் ஏழை வழங்குகிறது. omarchy திறன் உங்கள் Hyprland config-ஐ மாற்றுவது அல்லது பட்டியை சரிசெய்வது போன்ற அமைப்பை தனிப்பயனாக்குவதை உள்ளடக்குகிறது. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app, மற்றும் omarchy-make-game ஆகியவை புதிதாக ஒன்றை உருவாக்குவதை உள்ளடக்குகின்றன, omarchy-contribute ஒரு பிழையைப் புகாரளிப்பது அல்லது upstream-க்கு ஒரு திருத்தத்தை அனுப்புவதை உள்ளடக்குகிறது, மேலும் omarchy-diagnose-crash ஒரு செயலிழப்பின் core dump வழியாக வேலை செய்கிறது. அவை Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` மற்றும் ஒவ்வொரு `~/.hermes/profiles/*/skills`), மற்றும் பொதுவான `~/.agents/skills` இருப்பிடத்திற்கான திறன் கோப்பகங்களில் symlink செய்யப்படுகின்றன, எனவே பெரும்பாலான harness-கள் அவற்றை தானாகவே எடுத்துக் கொள்கின்றன. அதே பெயருடன் உங்கள் சொந்த திறன் கோப்புறை முன்னுரிமை பெறுகிறது.

ஆனால் நீங்கள் இந்தத் திறன்களை சோதனை என்று கருத வேண்டும். வெவ்வேறு மாடல்கள் அதை வெவ்வேறு விளைவுக்கு பயன்படுத்தும். முதலில் plan mode-இல் இயக்குவது சிறந்தது, எனவே ஏஜென்ட் எதை மாற்ற விரும்புகிறது என்பது பற்றி உங்களுக்கு ஒரு யோசனை இருக்கும். பின்னர் மாற்றங்களைத் திரும்பப் பெற அல்லது ஏஜென்ட் எல்லாவற்றையும் குழப்பினால் `omarchy reinstall configs` என்பதை அழைக்கவும் தயாராக இருங்கள்.
