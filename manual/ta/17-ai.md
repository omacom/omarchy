Omarchy உங்களுக்காக இயல்புநிலையைத் தேர்ந்தெடுக்காமல், கீழுள்ள குறியீட்டு முகவர்களுக்கான தொடக்கிகளை உள்ளடக்கியுள்ளது. முதல் முறை பயன்படுத்தும்போது அதன் CLI-ஐ நிறுவ ஒரு கட்டளையை இயக்கவும், பின்னர் கேட்கும்போது அங்கீகரிக்கவும். ### முகவர்களை நிறுவுதல் மற்றும் புதுப்பித்தல்

Hermes மற்றும் OpenClaw தவிர, இந்த முகவர்கள் mise-இன் சோம்பேறி நிறுவலைப் பயன்படுத்துகிறார்கள்: முதல் தொடக்கம் CLI-ஐ நிறுவும், பின்னர் வரும் தொடக்கங்கள் அதையே மீண்டும் பயன்படுத்தும். நிறுவப்பட்ட முகவருக்கு புதிய வெளியீடு உள்ளதா என mise அதிகபட்சம் நான்கு மணிநேரத்திற்கு ஒருமுறை, அது தொடங்குவதற்குச் சற்று முன்பு அல்லது ஷெல் ப்ராம்ப்டில் பின்னணியில் சரிபார்க்கிறது. அந்தப் புதுப்பிப்பு தோல்வியடைந்தால் அல்லது நீங்கள் ஆஃப்லைனில் இருந்தால், நிறுவப்பட்ட பதிப்பு இயங்கும். `omarchy update` நிறுவப்பட்ட முகவர்களை Omarchy-இன் மீதமுள்ளவற்றுடன் சேர்த்துப் புதுப்பிக்கிறது, மற்றும் `mup` mise-ஆல் நிர்வகிக்கப்படும் கருவிகளை மட்டும் புதுப்பிக்கிறது.

`claude update`, `codex update`, அல்லது ஒரு பயன்பாட்டில் உள்ள புதுப்பிப்பு பொத்தான் போன்ற முகவரின் சொந்தப் புதுப்பிப்பான், mise-ஆல் நிர்வகிக்கப்படும் நிறுவலைப் புதுப்பிக்காது. `codex update` தோல்வியடைகிறது, மற்றும் `claude update` வெற்றி என்று அறிவித்துக்கொண்டே mise கண்காணிக்காத தனி நகலை நிறுவக்கூடும். முகவரின் சொந்த நிறுவி மற்றும் புதுப்பிப்பானைப் பயன்படுத்த நீங்கள் விரும்பினால், அதை `disable_tools`-இல் சேர்க்கவும்; [முன்பே நிறுவப்பட்ட CLI கருவிகள்](18-development-tools.md#preinstalled-cli-tools) ஐப் பார்க்கவும்.

நீங்கள் அவை தேவைப்படுவதற்கு முன்பே உள்ளமைக்கப்பட்ட அனைத்து சோம்பேறி கருவிகளையும் நிறுவ, `mise install --include-lazy` ஐ இயக்கவும். இதில் முகவர்களுடன் Omarchy-இன் மற்ற இயல்புநிலை CLI கருவிகளும் அடங்கும். ஒரு தனி கருவியை நிறுவுவதற்கு அல்லது உங்கள் சொந்த நிறுவலைப் பயன்படுத்துவதற்கு [முன்பே நிறுவப்பட்ட CLI கருவிகள்](18-development-tools.md#preinstalled-cli-tools) ஐப் பார்க்கவும்.

`grok` mise-இன் முதல்-தரப்பு `grok` தொகுப்பு வழியாக, `claude` மற்றும் `codex` போலவே நிறுவப்படுகிறது. `grok` ஐ இயக்கவும், அல்லது முகவர்கள் பலகத்தில் அதை நட்சத்திரமிடவும். x.ai-இல் உள்ள `curl | bash` நிறுவியைத் தவிர்க்கவும். அந்தப் பாதை இரண்டாவது நகலை `~/.grok/bin`-இல் வைக்கிறது, அதை `PATH`-இல் முன்னால் சேர்க்கிறது, மற்றும் Omarchy-இன் ரேப்பரை மேலெழுதுகிறது.

`dsh` அதன் உலாவி UI-ஐ `127.0.0.1:3080`-இல் திறக்கிறது, தொடக்க கோப்பகத்தை அதன் இயல்புநிலை பணியிடமாகக் கொண்டு. அதன் உலாவி UI தொடக்க ப்ராம்ப்டை ஏற்காது, எனவே `omarchy agent prompt` அதை ஒட்டுவதற்காக உங்கள் கிளிப்போர்டில் ப்ராம்ப்டுடன் திறக்கிறது. Omarchy அதை DeepSeek-இன் ஒப்புதல்-தேவையில்லா அனுமதி முன்னமைவுடன் தொடங்குகிறது. நீங்கள் அதன் அதிகாரப்பூர்வ மாதிரி API-ஐப் பயன்படுத்தும்போது DeepSeek Harness அமர்வு பதிவுகளை DeepSeek-க்கு பதிவேற்றுகிறது; அதன் உலாவி UI-இல் _Settings > General > Upload Session Log_ கீழ் அதை அணைக்கவும். நீங்கள் அதற்கு அனுப்பும் கருத்தும் அமர்வுடன் சேர்த்துப் பதிவேற்றப்படும், நீங்கள் அதை `DSH_TELEMETRY_MODE=DISABLED` உடன் தொடங்கினால் தவிர.

### இயல்புநிலை முகவர்

முகவர்கள் பலகத்தில் ஒரு முகவருக்கு அருகில் உள்ள நட்சத்திரத்தால் உங்கள் இயல்புநிலை முகவரைத் தேர்ந்தெடுக்கவும், இயல்புநிலையில் அது நிரப்பப்பட்டிருக்கும், அல்லது `omarchy default agent <name>` உடன், இது அங்கு வரிசை இல்லாத எந்த ஹார்னஸையும் ஏற்கும். முகவர் இன்னும் நிறுவப்படவில்லை என்றால், அதைத் தேர்ந்தெடுப்பது முதலில் அதை நிறுவும், மற்றும் அது பயன்பாட்டு தொடக்கியில் Agent-க்கு அருகில் தனக்கென ஒரு தொடக்கியையும் பெறும். புதிய Omarchy ஒன்றை அமைக்க உங்களை ஒருமுறை மட்டுமான அறிவிப்புடன் அழைக்கிறது, அது முகவர்கள் பலகத்தைத் திறக்கும்.

Claude-ஐத் தேர்ந்தெடுப்பது Chromium, Chrome, Brave, Brave Origin, மற்றும் Edge ஆகியவற்றுக்காக அதன் உலாவி நீட்டிப்பை அமைக்கவும் முயற்சிக்கிறது. நீட்டிப்பு அமைப்பு அனைத்து பயனர்களுக்கும் பொருந்தும் மற்றும் உங்கள் கணினி கடவுச்சொல்லைக் கேட்கக்கூடும்; ரத்து செய்வது அல்லது தோல்வியடைந்த நீட்டிப்பு நிறுவல் இருந்தாலும் Claude தேர்ந்தெடுக்கப்பட்டு தொடங்கப்படும். உங்கள் உலாவியை மறுதொடக்கம் செய்யவும், கேட்டால் நீட்டிப்பை இயக்கவும், மற்றும் அதை இணைப்பதை முடிக்க Claude-இல் உள்நுழையவும். இணைப்பைச் சரிபார்க்க Claude-இல் `/chrome` ஐ இயக்கவும். Firefox மற்றும் Zen இந்த நீட்டிப்பை ஆதரிக்காது. இந்த அமைப்பு சேர்க்கப்படுவதற்கு முன்பே Claude ஏற்கனவே உங்கள் இயல்புநிலையாக இருந்தால், நீட்டிப்பை நிறுவ அதை மீண்டும் தேர்ந்தெடுக்கவும்.

நீங்கள் தேர்ந்தெடுத்த பிறகு, `Super + Shift + Ctrl + A` இயல்புநிலை முகவரை ஒரு பிரத்யேக முனைய சாளரத்தில் தொடங்கும் (அல்லது நீங்கள் இன்னும் தேர்ந்தெடுக்கவில்லை என்றால் தேர்வியைக் கொண்டுவரும்). நீங்கள் அதை `omarchy agent prompt "Review this project"` உடன் நேரடியாக ஒரு பணிக்குள் தொடங்கவும் முடியும். Freebuff மற்றும் DeepSeek Harness தொடக்க ப்ராம்ப்டை ஏற்காது, எனவே அவை அதற்கு பதிலாக ஒட்டுவதற்காக உங்கள் கிளிப்போர்டில் ப்ராம்ப்டுடன் திறக்கும். இப்படித் தொடங்கப்படும் முகவர்கள் அவரவரின் நிறுத்தி-கேட்காத முறைகளில் கவனிக்கப்படாமல் இயங்குவார்கள், எனவே அவர்கள் உண்மையில் செயல்களைச் செய்யத் தயாராக இருங்கள்! MiniMax Code-இன் ஊடாடும் அமர்வுகளுக்கு அத்தகைய முறை இல்லை, எனவே அது வழக்கம் போல அனுமதிகளைக் கேட்கும். மற்றும் முகவர்கள் உங்கள் முகப்பு கோப்பகத்திற்கான நம்பிக்கையை நினைவில் வைக்க மறுப்பதால், `$HOME`-இலிருந்து தொடங்குபவை அதற்கு பதிலாக `~/Work`-இல் தொடங்கும்.

முனைய குறுக்குவழிகளும் உள்ளன: `a` தற்போதைய முனையத்தில் இயல்புநிலை முகவரை நேரடியாக இயக்குகிறது, அதே நேரத்தில் `c`, `cx`, மற்றும் `cy` OpenCode, Claude Code, மற்றும் Codex ஐ நேரடியாகத் தொடங்குகின்றன (மீண்டும் அவற்றின் தானியங்கு-ஒப்புதல் முறைகளில்). தீம் மாற்றங்களும் முகவர்களுக்கு ஒத்திசைக்கப்படும்: நீங்கள் Omarchy தீமை மாற்றும்போது Claude Code, Pi, OpenCode, மற்றும் Hermes (Omarchy அதை நிறுவிய பிறகு) அனைத்தும் பின்தொடரும்.

### உங்கள் முகவர் வழிமுறைகள்

ஒவ்வொரு முகவருக்கான தனிப்பட்ட விதிகள் `~/.agents/skills`-இல் உள்ள பகிரப்பட்ட ஸ்கில்களுக்கு அருகில் `~/.agents/AGENTS.md`-இல் செல்லும். முகவர்கள் பலகத்தில் + க்கு அருகில் உள்ள ஆவண ஐகானால் அதைத் திறக்கவும், அல்லது `omarchy agent instructions --edit` உடன், இது ஒவ்வொரு ஹார்னஸும் தனது சொந்த உலகளாவிய கோப்பை வைத்திருக்கும் இடத்திலும் அதை இணைக்கிறது: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, Copilot-இன் `~/.copilot/copilot-instructions.md`, மற்றும் பல. Crush மற்றும் Amp `~/.config/AGENTS.md` இணைப்பைப் படிக்கும், அதே நேரத்தில் omp, Kimi, மற்றும் DeepSeek Harness `~/.agents/AGENTS.md` ஐ நேரடியாகப் படிக்கும். இயல்புநிலை முகவரைத் தேர்ந்தெடுப்பதும் அதை இணைக்கும். நீங்கள் ஏற்கனவே வைத்திருந்த வழிமுறைகள் கோப்பு, இன்னும் ஒன்று இல்லை என்றால் பகிரப்பட்டதாக மாறும்; இல்லையெனில் அது இணைப்புக்கு அருகில் `.bak` ஆக வைக்கப்படும். மற்றொரு முகவரை நிறுவிய பிறகு மீண்டும் இணைக்க `omarchy agent instructions` ஐ இயக்கவும்.

### முகவர்கள் பலகம்

மேல் பட்டியில் முகவர்கள் ஐகான் உள்ளது. நீங்கள் ஒரு முகவரை அமைப்பதற்கு முன்பு, அதன் பலகம் தொடங்க மூன்று வழிகளை வழங்குகிறது: Claude, Codex, Grok, Gemini, Muse, Cursor, அல்லது Copilot சந்தாவில் உள்நுழையவும், அல்லது More கீழ் OpenCode Go, MiniMax, Synthetic, அல்லது Z.ai குறியீட்டு திட்டம்; Fireworks, OpenCode Zen மற்றும் Go, OpenRouter உடன் பயன்பாட்டிற்கு ஏற்ப செலுத்தவும், அல்லது More கீழ் DeepSeek அல்லது OpenCode உள்நுழையும் வேறு எந்த வழங்குநரும், அனைத்தும் OpenCode-இல் இயங்கும்; அல்லது உங்கள் கணினிக்குப் பொருந்தும் ஒன்று இருக்கும்போது அதற்கான சிறந்த மாதிரியை இயக்கவும். நீங்கள் முதலில் முடிப்பது உங்கள் இயல்புநிலை முகவராக மாறும், மற்றும் பலகத்தில் உள்ள +, அல்லது Omarchy Menu-இல் _Agent > Add_ பின்னர் அதே மூன்றையும் வழங்கும். அதன் பிறகு, பலகம் ஒவ்வொரு சந்தாவையும் ஒரே பக்கத்தில் வைக்கிறது: ஒவ்வொரு முகவர் மற்றும் கணக்கு அதன் திட்டத்துடன், அதன் 5-மணிநேர அமர்வு மற்றும் வாராந்திர வரம்புகள் ஒவ்வொன்றிற்கும் ஒரு மீட்டர், அது மீட்டமைக்கப்படும் வரையிலான நேரத்துடன் (சரியான சதவீதத்திற்கு மேலே வைக்கவும்), அல்லது மீதமுள்ள முன்கூட்டியே செலுத்தப்பட்ட இருப்பு, நீங்கள் அனைத்திலும் பயன்படுத்தியதைச் சுழற்றும் ஒரு வரியின் கீழ், இந்த வார டோக்கன்கள் மற்றும் உங்கள் அதிகம் பயன்படுத்தப்பட்ட மாதிரி போல. _Make something cool_ கீழ் இது புதிய தீம், செருகுநிரல், பயன்பாடு, அல்லது விளையாட்டுக்கான தொடக்க ப்ராம்ப்டுகளை வழங்குகிறது, அவை பணியை உங்கள் இயல்புநிலை முகவரிடம் ஒப்படைக்கும். பயன்பாடுகள் Omarchy-இன் சொந்த Hype, Monologue, மற்றும் Omacut போலவே, C++ மற்றும் Qt Quick-இல், omarchy-make-app முகவர் ஸ்கில்லைப் பின்பற்றி உருவாக்கப்படுகின்றன, மற்றும் அவற்றுக்குத் தேவையான கம்பைலர் மற்றும் Qt பகுதிகள் நிறுவப்பட்டு வருகின்றன. விளையாட்டுகள் `~/Games/vibes`-இல் ஒற்றை three.js பக்கம், omarchy-make-game முகவர் ஸ்கில்லைப் பின்பற்றி, மற்றும் அனைத்தும் தற்போதைய தீமில் ஒரு Game Vibes தொடக்கியிலிருந்து திறக்கும்; அவை three.js ஐ வலையிலிருந்து ஏற்றுகின்றன, எனவே தொடங்க அவற்றுக்கு இணைப்பு தேவை. Claude Code, Codex, Grok, Kimi, Cursor மற்றும் அதன் Grok Bot ஒதுக்கீடு, GitHub Copilot, Muse, Gemini (Antigravity வழியாக), மற்றும் Devin ஆகியவை அவற்றின் வரம்புகளுடன் தொடக்கத்திலிருந்தே உள்ளடக்கப்பட்டுள்ளன, Kimchi அதன் திட்டம், முன்கூட்டியே செலுத்தப்பட்ட கிரெடிட்கள், மற்றும் செலவு பட்ஜெட்களுடன், மற்றும் Hermes, Mistral Vibe, மற்றும் Qwen Code நீங்கள் அவற்றைப் பயன்படுத்திய பிறகு அவற்றின் அமர்வுகள் மற்றும் டோக்கன்களைக் காட்டும். pi, omp, அல்லது opencode வழியாக நீங்கள் பயன்படுத்தும் வழங்குநர் திட்டங்கள் மற்றும் விசைகளும் தோன்றும்: OpenCode Zen மற்றும் Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan, மற்றும் Synthetic அவற்றின் வரம்புகளுடன்; OpenRouter மற்றும் DeepSeek அவற்றின் முன்கூட்டியே செலுத்தப்பட்ட இருப்புகளுடன்; Fireworks கடந்த 30 நாட்களில் அதன் செலவுடன். உங்கள் சொந்த வன்பொருளில் நீங்கள் இயக்கும் மாதிரிகளிலிருந்து வரும் டோக்கன்களும் மொத்தங்களில் கணக்கிடப்படும்; மாதிரிகளுக்கே தனி பலகம் உள்ளது, [உள்ளூர் மாதிரிகள்](#local-models) கீழ் விவரிக்கப்பட்டுள்ளது. ஒவ்வொரு முகவரும், நீங்கள் எத்தனை ஹார்னஸ்கள் வழியாக அதை இயக்கினாலும், அதற்கு பில் செய்பவர் கீழ் ஒருமுறை மட்டுமே கணக்கிடப்படும்.

பலகத்திற்கு பட்டி ஐகானை இடது-கிளிக் செய்யவும் அல்லது `Super + Ctrl + X` ஐ அழுத்தவும், உங்கள் இயல்புநிலை முகவரைத் தொடங்க வலது-கிளிக் செய்யவும், மற்றும் புதுப்பிக்க நடு-கிளிக் செய்யவும். அதன் பின்னால் உள்ள பயன்பாட்டு பதிவுகள் ஒவ்வொரு 15 நிமிடங்களுக்கும் `omarchy agent usage update` ஆல் மீண்டும் உருவாக்கப்படும், மற்றும் பலகம் ஒத்திசைக்கப்பட்ட கோப்புறை வழியாக உங்கள் மற்ற கணினிகளிலிருந்தும் பயன்பாட்டை இணைக்க முடியும். முழு அமைப்புகளுக்கு `$OMARCHY_PATH/shell/plugins/agents/` கீழ் உள்ள README ஐப் பார்க்கவும்.

### பல சந்தாக்கள்

நீங்கள் ஒன்றுக்கு மேற்பட்ட Claude, Codex, அல்லது Grok திட்டத்திற்கு செலுத்தினால் — தனிப்பட்ட Max மற்றும் பணி ஒன்று, என்று சொல்லலாம் — Omarchy அவை அனைத்தையும் உள்நுழைந்த நிலையில் வைத்து அவற்றுக்கிடையே நகர முடியும். முகவர்கள் பலகத்தில் உள்ள + உடன் ஒரு சந்தாவைச் சேர்க்கவும், அது அங்கேயே உங்களை அதன் வழியாக அழைத்துச் செல்லும், அல்லது `omarchy agent account add claude Work` உடன் (அல்லது `codex`, அல்லது `grok`). அதே + மற்றும் கட்டளை Gemini (`gemini`) மற்றும் OpenCode (`opencode`) இல் உள்நுழையும், மற்றும் Fireworks (`fireworks`) அல்லது OpenRouter (`openrouter`) API விசையை OpenCode-இல் சேமிக்கும்; கட்டளை Copilot (`copilot`), Cursor (`cursor`), மற்றும் Muse (`muse`) இலும் உள்நுழையும். அவை ஒவ்வொன்றும் ஒரே உள்நுழைவை வைத்திருக்கும். CLI இல்லை என்றால் அதை நிறுவும். ஒரு வழங்குநருக்கான முதல் கணக்கு உங்கள் சாதாரண உலாவி வழியாக, CLI எப்போதும் பார்க்கும் இடத்திலேயே உள்நுழையும். அதற்குப் பிறகு வரும் ஒவ்வொன்றும் தனிப்பட்ட சாளரம் வழியாக உள்நுழையும், எனவே உங்கள் உலாவி ஏற்கனவே உள்நுழைந்துள்ள கணக்கு தவறுதலாக எடுக்கப்படாது; நீங்கள் சேர்க்கும் கணக்காக அங்கு உள்நுழையவும், மற்றும் ஏற்கனவே திறந்திருந்த எந்த தனிப்பட்ட சாளரத்தையும் முதலில் மூடவும். இதைச் செய்ய CLI-இலிருந்து ஒருபோதும் வெளியேற வேண்டாம்: வெளியேறுவது சேமிக்கப்பட்ட உள்நுழைவை ரத்து செய்யும், மற்றும் அந்தக் கணக்கு மீண்டும் சேர்க்கப்பட வேண்டும்.

உங்கள் சந்தா உள்நுழைவுகளை SSH வழியாக மற்றொரு Omarchy கணினிக்கு நகலெடுக்க, `omarchy agent account copy user@laptop` ஐ இயக்கவும். இலக்கில் ஒன்று நிறுவப்படவில்லை என்றால் அனுப்புநர் தற்காலிக பெறுநரை வழங்குவார், எனவே பழைய Omarchy கணினிகள் புதுப்பிப்பு இல்லாமல் கணக்குகளைப் பெற முடியும். நிறுவப்பட்ட பெறுநர்கள் முன்னுரிமை பெறுவார்கள். இது அனைத்து Claude, Codex, மற்றும் Grok சந்தாக்களையும் நகலெடுக்கும்; அவற்றைத் தேர்ந்தெடுக்க வழங்குநர் பெயர்களைச் சேர்க்கவும், `omarchy agent account copy laptop claude` இல் உள்ளது போல. கணக்கு பெயர்கள் மற்றும் கட்டளை ID-கள் மூலத்துடன் பொருந்தும், இலக்கில் ஏற்கனவே உள்ள கணக்குகள் உட்பட. தொடர்பில்லாத இலக்கு கணக்குகள் அவற்றின் பெயர்கள் முரண்பட்டால் எண் பின்னொட்டைப் பெறும், மற்றும் அமைப்புகள், ஸ்கில்கள், செருகுநிரல்கள், மற்றும் உரையாடல் வரலாறு ஒவ்வொரு கணினிக்கும் உள்ளூராகவே இருக்கும்.

ஏற்கனவே உள்ள இலக்கு சான்றுகள் வைக்கப்படும். அங்கு ஏற்கனவே உள்நுழைந்துள்ள மூல கணக்கு அதன் சான்றுகளை மாற்றாமல் அதன் பெயர் ஒத்திசைக்கப்படும்; மற்ற கணக்குகள் அதற்கு அருகில் சேர்க்கப்படும். பொருந்தும் கணக்குகளுக்கு சேமிக்கப்பட்ட சான்றுகளை மாற்ற, இலக்கில் அந்தக் கணக்கின் அமர்வுகளை விட்டு வெளியேறிய பிறகு `omarchy agent account copy --replace laptop claude` ஐப் பயன்படுத்தவும். புதிய இலக்கு மூலத்தின் செயலில் உள்ள கணக்கு மற்றும் மாற்று விருப்பங்களையும் பெறும்; நிறுவப்பட்ட இலக்கு தனதையே வைத்திருக்கும்.

சான்றுகள் SSH வழியாக பயணித்து இலக்கில் தனிப்பட்ட கோப்புகளில் சேமிக்கப்படும், எனவே நீங்கள் நம்பும் கணினிகளுக்கு மட்டும் நகலெடுக்கவும். இது ஒருமுறை நகல், தொடர்ச்சியான ஒத்திசைவு அல்ல. Codex புதுப்பிப்பு டோக்கன்கள் மற்றொரு கணினியால் சுழற்றப்படலாம், நகலெடுக்கப்பட்ட உள்நுழைவுக்கு புதுப்பிப்பு தேவைப்படும் நிலையை விட்டுவிடும்; பல கணினிகளில் ஒரே நேரத்தில் பயன்படுத்த தனி உள்நுழைவுகளே மிகவும் நம்பகமான தேர்வாக இருக்கும். [Codex-இன் கணக்கு அங்கீகார வழிகாட்டி](https://developers.openai.com/codex/auth/ci-cd-auth) ஐப் பார்க்கவும்.

ஒரு வழங்குநருக்கு ஒரு கணக்கு செயலில் இருக்கும், மற்றும் ஒவ்வொரு புதிய அமர்வும் அதுவாகவே தொடங்கும்: `cx`, `cy`, சாதாரண `claude`, `codex`, அல்லது `grok`, `omarchy agent` வழியாக தொடங்கப்படும் எதுவும், மற்றும் `PATH`-இல் CLI-ஐக் கண்டறியும் ஸ்கிரிப்டுகள் அல்லது எடிட்டர்கள். `omarchy agent account use work` உடன் மாற்றவும் (மற்றும் `omarchy agent account use main` உடன் திரும்பவும்), அல்லது பலகத்தில் ஒரு கணக்கின் எண்ணை அழுத்தி பின்னர் `Enter` ஐ அழுத்துவதன் மூலம் (அல்லது அதன் நட்சத்திரத்தைக் கிளிக் செய்வதன் மூலம்). இயங்கும் Claude அமர்வுகளும், அவற்றின் அடுத்த செய்தியிலிருந்து மாறும்: ஒவ்வொரு Claude அமர்வும் `~/.claude`-இல் இயங்கும், அது எப்போதும் செயலில் உள்ள கணக்கின் உள்நுழைவை வைத்திருக்கும். பழைய Omarchy-ஆல் கணக்கின் சொந்த கோப்புறையில் தொடங்கப்பட்ட Claude அமர்வு அது வெளியேறும் வரை அந்த உள்நுழைவை வைத்திருக்கும், எனவே மாற்றம் அந்த அமர்வுகளைப் பெயரிட்டு அவை போன பிறகு தானாகவே முடியும். இயங்கும் Codex மற்றும் Grok அமர்வுகள் அவை தொடங்கிய கணக்கிலேயே இருக்கும். உரையாடல் வரலாறு, அமைப்புகள், ஸ்கில்கள், மற்றும் செருகுநிரல்கள் கணக்குகள் முழுவதும் பகிரப்படும், எனவே அதே கோப்புறையில் `claude --continue` நீங்கள் புதிய கணக்கில் விட்ட இடத்திலிருந்து தொடரும்.

ஒன்றுக்கு மேற்பட்ட கணக்குடன், பலகம் ஒவ்வொரு கணக்கின் வரம்புகளையும் அருகருகே காட்டும், பயன்பாட்டில் உள்ள ஒன்றில் நிரப்பப்பட்ட நட்சத்திரத்துடன். செயலில் உள்ள கணக்கு ஒரு வரம்பின் 95% ஐத் தாண்டும்போது Omarchy உங்களுக்கு அறிவிக்கும், மற்றும் அறிவிப்பைக் கிளிக் செய்வது அதிக இடவசதி உள்ள கணக்கிற்கு மாற்றும். அது ஒருபோதும் தானாக மாறாது. `omarchy agent account threshold 90` உடன் வரம்பை மாற்றவும். ஒவ்வொரு கணக்கும் வரம்புக்கு மேல் இருந்தால், எந்தக் கணக்கு முதலில் விடுபடும் என்பதுடன் ஒருமுறை அதைப் பற்றி நீங்கள் கேள்விப்படுவீர்கள். செயலில் உள்ள கணக்கு அதன் வரம்பிலிருந்து 15 புள்ளிகளுக்குள் இருக்கும்போது (இயல்புநிலையில் 80%), அதன் வரம்புகள் ஒவ்வொரு 15 நிமிடங்களுக்கு பதிலாக ஒவ்வொரு மூன்று நிமிடங்களுக்கும் சரிபார்க்கப்படும்.

`omarchy agent account list` ஒவ்வொரு கணக்கையும் அதன் சமீபத்திய வரம்புகளையும் காட்டும், `omarchy agent account remove work` ஒன்றை மறக்கும், மற்றும் `omarchy agent account rename primary Hey` ஒன்றுக்கு மறுபெயரிடும் (அல்லது பலகத்தில் ஒரு கணக்கின் பெயரைக் கிளிக் செய்யவும்). இந்தக் கட்டளைகள் உங்கள் இயல்புநிலை முகவரின் கணக்குகளில் வேலை செய்யும்; மற்ற வழங்குநரை அடைய, `omarchy agent account use codex side` இல் உள்ளது போல அதை முதலில் பெயரிடவும். `~/.claude` அல்லது `~/.codex`-இல் நீங்கள் ஏற்கனவே வைத்திருந்த உள்நுழைவு _Main_ கணக்கு. Codex-இனது அது இருக்கும் இடத்திலேயே இருக்கும்; மற்றொரு கணக்கு செயலில் இருக்கும்போது Claude-இனது தனக்கென ஒரு கோப்புறையில் காத்திருக்கும். சுமார் எட்டு மணிநேரத்திற்கும் மேலாக பயன்படுத்தப்படாமல் விடப்பட்ட கணக்கு _Sign-in required_ எனக் காட்டக்கூடும்; பலகத்திலேயே அந்தக் கணக்கில் மீண்டும் உள்நுழைய அதைக் கிளிக் செய்யவும், அல்லது அதற்கு மாறி ஒரு அமர்வைத் தொடங்கவும், அது தானாகவே உள்நுழைவைப் புதுப்பிக்கும். நீங்கள் `claude mcp add` உடன் சேர்க்கும் MCP சர்வர்கள் ஒவ்வொரு Claude கணக்கையும் அடையும், ஏனெனில் அவை அனைத்தும் `~/.claude`-இல் இயங்கும்; Codex மற்றும் Grok-க்கு, ஒரு கணக்கு சேர்க்கப்பட்டபோது நீங்கள் வைத்திருந்த சர்வர்கள் அதனுடன் வரும், ஆனால் பின்னர் வருபவை நீங்கள் அவற்றைச் சேர்த்த கணக்கை மட்டுமே அடையும். Claude Desktop தனக்கென ஒரு உள்நுழைவை வைத்திருக்கும், மற்றும் CLI பைனரிக்கான முழுமையான பாதையுடன் உள்ளமைக்கப்பட்ட Codex அல்லது Grok கருவிகள் மாற்றத்தைப் பின்தொடராது. வெளிப்படையான `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, அல்லது `GROK_HOME` தேர்ந்தெடுக்கப்பட்ட கணக்கைவிட முன்னுரிமை பெறும்.

### செயலிழப்பு கண்டறிதல்

Omarchy செயல்முறை செயலிழப்புகளுக்காக systemd-coredump ஐக் கண்காணிக்கிறது. நீங்கள் இயல்புநிலை முகவரைத் தேர்ந்தெடுத்த பிறகு, கோர் டம்ப் செய்யும் உங்கள் எந்த நிரலும் "Process crashed" அறிவிப்பைக் கொண்டுவரும் — அதைக் கிளிக் செய்யவும், மற்றும் செயலிழப்பு Omarchy-இன் omarchy-diagnose-crash ஸ்கில்லுடன் சேர்த்து உங்கள் இயல்புநிலை முகவரிடம் ஒப்படைக்கப்படும், அது கோர் டம்பிலிருந்து உண்மைகளை நிறுவுவதன் வழியாகவும் செயலிழப்பு மேல்நிலையில் அறிவிக்கத் தகுந்ததா என முடிவு செய்வதன் வழியாகவும் முகவரை அழைத்துச் செல்லும். நீங்கள் அதை `coredumpctl list`-இலிருந்து எந்த PID-க்கு எதிராகவும் `omarchy agent crash <pid>` உடன் கையாலும் இயக்க முடியும்.

கண்காணிப்பு இயல்புநிலையாக இயக்கத்தில் உள்ளது. _Trigger > Toggle > Crash Capture Off_ கீழ் (அல்லது `omarchy toggle crash-capture` உடன்) அதை அணைக்கவும், அறிவிப்புகள் நிற்கும்; `omarchy agent crash <pid>` இன்னும் கையால் வேலை செய்யும்.

செயலிழப்புகளை ஒரு நேரத்தில் ஒரு நிரல் வீதமும் அமைதிப்படுத்த முடியும், கண்டறிதல் இறுதியில் உங்களுக்கு வழங்குவது அதுதான். `omarchy crash mute hyprland` அந்த நிரலுக்கு மட்டும் அறிவிப்புகளை நிறுத்தும், `omarchy crash mute hyprland off` அவற்றைத் திரும்பக் கொண்டுவரும், மற்றும் `omarchy crash mute` தனியாக நீங்கள் அமைதிப்படுத்தியதைப் பட்டியலிடும். இது பைனரியின் பாதையை அதன் பெயரைப் போலவே மகிழ்ச்சியுடன் ஏற்கும், எனவே `omarchy crash mute /usr/bin/hyprland` அதே செயலைச் செய்யும். இடைவெளி உள்ள பெயரை, `omarchy crash mute 'Some App'` இல் உள்ளது போல மேற்கோள் காட்டவும். மற்ற அனைத்தும் இன்னும் அறிவிக்கும், மற்றும் அமைதிப்படுத்தப்பட்ட நிரல் இன்னும் செயலிழக்கும் — இது நினைவூட்டலை மறைக்கிறது, எதையும் சரிசெய்யாது.

### டெஸ்க்டாப் பயன்பாடுகள்

_Install > AI_ மெனுவும் சில வரைகலை AI பயன்பாடுகளைக் கொண்டுள்ளது: Amp Desktop, Antigravity Desktop, ChatGPT டெஸ்க்டாப் பயன்பாடு, Claude டெஸ்க்டாப் பயன்பாடு (Anthropic-இன் Linux பீட்டா, Chat, Cowork, மற்றும் Claude Code தாவல்களுடன்), xAI-இன் மாதிரிகளுடன் அரட்டை அடிக்க Grok Bot, Herdr Desktop, Hermes Desktop, OpenClaw, Perplexity டெஸ்க்டாப் பயன்பாடு, மற்றும் T3 Code. Grok Bot டெஸ்க்டாப் அரட்டை பயன்பாடு. குறியீட்டு முகவர் `grok` கட்டளை.

Hermes Desktop தெரிந்து கொள்ள வேண்டிய ஒன்று, ஏனெனில் ஒரு கணினியில் ஒரு Hermes உள்ளது, மற்றும் அது பயன்பாட்டினுடையது: Hermes எப்போதும் பயன்பாடு வழியாக மட்டுமே நிறுவப்படும், மற்றும் இயல்புநிலை முகவர் இயக்கும் `hermes` கட்டளை பயன்பாட்டினுடையது. Hermes-ஐ இயல்புநிலை முகவராகத் தேர்ந்தெடுப்பது _Install > AI_ உள்ளீடு செய்வதையே நிறுவும்: தொகுப்பு, மற்றும் Hermes-இன் சொந்த நிறுவியால் அமைக்கப்பட்ட `~/.hermes` கீழ் Hermes இயக்கநேரம், இது முதல் முறை சில நிமிடங்கள் எடுக்கும். அந்த இயக்கநேரம்தான் முனைய `hermes` கட்டளை, இயல்புநிலை முகவர் மற்றும் பயன்பாடு அனைத்தும் பயன்படுத்தும் ஒரே Hermes, மற்றும் அது Omarchy வெளியீட்டிற்காகக் காத்திராமல் `hermes update` உடன் தானாகவே புதுப்பிக்கும். அதை நிறுவுவது Hermes-க்கு Omarchy தீமை `omarchy` எனப் பெயரிடப்பட்ட ஸ்கின்னாகவும் வழங்குகிறது, நீங்கள் தீம்களை மாற்றும்போது ஒவ்வொரு Hermes மேற்பரப்பும் அதைப் பின்தொடரும்; நீங்கள் அது வேண்டாம் என்றால் Hermes-இன் Appearance அமைப்புகள் கீழ் அல்லது `/skin` உடன் மற்றொன்றைத் தேர்ந்தெடுக்கவும், மற்றும் Omarchy அந்தத் தேர்வை அப்படியே விட்டுவிடும். _Remove > AI_ கீழ் பயன்பாட்டை அகற்றுவது முதலில் Hermes-ஐ மூடும், நுழைவாயில் உட்பட, அந்த இயக்கநேரத்தை அதனுடன் எடுத்துச் செல்லும், மற்றும் நீங்கள் வேறுவிதமாகச் சொன்னால் தவிர உங்கள் அரட்டைகள், நினைவுகள், மற்றும் Hermes தனக்காக எழுதிய ஸ்கில்களை வைத்திருக்கும்: அந்தத் தரவும் உங்கள் இணைப்பு அமைப்புகளும் கூட போக வேண்டுமா என இது கேட்கும், இயல்புநிலை இல்லை என.

OpenClaw-இன் டெஸ்க்டாப் அனுபவம் அதன் Control UI, இது அதன் சொந்த உள்ளூர் நுழைவாயிலால் ஆதரிக்கப்படும் வலை பயன்பாடாகத் திறக்கும். OpenClaw `~/.openclaw`-இல் வாழ்கிறது மற்றும் தானாகவே புதுப்பிக்கிறது: Control UI-இன் "Update Gateway" பொத்தானைப் பயன்படுத்தவும் அல்லது `openclaw update` ஐ இயக்கவும், மற்றும் நுழைவாயில் புதிய பதிப்பில் மறுதொடக்கம் செய்யும். புதிய நிறுவல் எந்த வெளியீட்டிலிருந்து தொடங்க வேண்டும் என்பதை மட்டுமே Omarchy தேர்ந்தெடுக்கிறது. OpenClaw உங்கள் இயல்புநிலை முகவராகவும் இருக்க முடியும்: _Agent > Harness_ கீழ் அதைத் தேர்ந்தெடுப்பது `~/.openclaw`-இல் அதே நகலை அமைக்கிறது, மற்றும் முகவர் OpenClaw-இன் முனைய UI-ஐ அதன் நுழைவாயிலுடன் இணைத்துத் திறக்கிறது. _Remove > AI_ கீழ் OpenClaw-ஐ அகற்றுவது நுழைவாயில் சேவை மற்றும் பயன்பாட்டை அதனுடன் எடுத்துச் சென்று பின்னர் `~/.openclaw` கூட போக வேண்டுமா எனக் கேட்கும், ஏனெனில் அது OpenClaw தானே மற்றும் அது பதிவிறக்கும் செருகுநிரல் இயக்கநேரங்களுடன் உங்கள் அரட்டைகள் மற்றும் சான்றுகளை வைத்திருக்கிறது; இயல்புநிலை அதை வைத்திருக்கும், மற்றும் OpenClaw-ஐ மீண்டும் நிறுவுவது அதைத் திரும்ப எடுக்கும்.

Herdr Desktop என்பது [Herdr](https://herdr.dev) டெஸ்க்டாப் பயன்பாடு: நீங்கள் சாளரத்தை மூடும்போது அதன் மையத்தில் இயங்கிக் கொண்டிருக்கும் முனையங்கள் மற்றும் குறியீட்டு முகவர்களின் இடங்கள், தாவல்கள், மற்றும் பேன்கள். இது தொகுப்பிலிருந்து அல்லாமல் Herdr-இன் சொந்த நிறுவியிலிருந்து வருகிறது, எனவே இது `~/.local/share/herdr-app`-இல் வாழ்கிறது, உங்களிடம் ஏற்கனவே ஒன்று இல்லை என்றால் அதன் மையத்தை `~/.local/bin/herdr-core`-இல் கொண்டுவருகிறது, மற்றும் இரண்டையும் தானாகவே புதுப்பிக்கிறது. இது Omarchy `Super + Ctrl + Return`-இல் வழங்கும் `herdr` கட்டளையை மாற்றாமல் அதற்கு அருகில் அமர்கிறது, மற்றும் அந்தக் கட்டளையின் நேரடி விசைகளைப் பெறுகிறது: `Alt + Return` மற்றும் `Alt + Shift + Return` ஒரு பேனை கீழே அல்லது வலதுபுறமாகப் பிளக்கும், `Alt + Escape` அதை மூடும், `Ctrl + Alt + Arrow` பேன்களுக்கிடையே நகரும், `Alt + 1..9` மற்றும் `Alt + Left/Right` ஒரு தாவலைத் தேர்ந்தெடுக்கும், மற்றும் `Alt + Up/Down` இடங்களுக்கிடையே நகரும். `Ctrl + 1..9` ஒரு இடத்தைத் தேர்ந்தெடுக்கும் மற்றும் `Alt + Shift + Up/Down` முகவர்கள் வழியாகச் செல்லும். `Ctrl + Space` முன்னொட்டு விசைகள் முனையத்திற்கு மட்டுமே இருக்கும், ஏனெனில் பயன்பாடு ஒரு வரிசைக்காக சாதாரண Ctrl விசையை வைத்திருக்க முடியாது. Omarchy இவற்றை `~/.config/herdr-app/keys.json`-இல் எழுதும், மற்றும் `omarchy-refresh-herdr-app` அவற்றைத் திரும்ப வைக்கும். அதை நிறுவுவது Herdr-இன் Omarchy தீமைத் தேர்ந்தெடுக்கும், அது அதன் பிறகு உங்கள் Omarchy தீமைப் பின்தொடரும். Herdr ஒளி முறைக்கு ஒரு தீமையும் இருள் முறைக்கு ஒரு தீமையும் வைத்திருக்கிறது, எனவே இருள் மற்றும் ஒளி Omarchy தீமுக்கிடையே மாறிய பிறகு, மற்ற முறைக்காக Herdr-இன் தீம் தேர்வியில் Omarchy-ஐ மீண்டும் ஒருமுறை தேர்ந்தெடுக்கவும்.

T3 Code தொகுப்பிலிருந்து அல்லாமல் `~/.local/share/t3code`-இல் அதன் அதிகாரப்பூர்வ AppImage வெளியீட்டிலிருந்து இயங்குகிறது, எனவே அது தானாகவே புதுப்பிக்கிறது. அதை நிறுவுவது Stable அல்லது Nightly சேனலில் தொடங்க வேண்டுமா எனக் கேட்கும்; பின்னர் T3 Code-இன் அமைப்புகளில் மாற்றவும். உங்கள் திரிகள் மற்றும் அமைப்புகள் `~/.t3`-இல் வாழ்கின்றன, மற்றும் _Remove > AI_ கீழ் T3 Code-ஐ அகற்றுவது அவற்றை அதனுடன் எடுத்துச் செல்லும்.

### உள்ளூர் மாதிரிகள்

உங்கள் குறியீட்டு முகவர்களுக்காக உங்கள் சொந்த கணினியில் திறந்த மாதிரியை இயக்கவும். உங்கள் ப்ராம்ப்டுகள் மற்றும் குறியீடு கணினியிலேயே இருக்கும்; மாதிரிக்கு அனுப்பப்படும் எதுவும் அதை விட்டு வெளியேறாது. இதனுடன் தொடங்கவும்:

```bash
omarchy models use best text
```

இது இந்தக் கணினிக்கான சிறந்த உரை மாதிரியை அமைக்கிறது, உங்கள் முகவர்கள் பயன்படுத்தும் வகை. படம், வீடியோ மற்றும் இசை மாதிரிகளுக்கு தனித்தனியாக சிறந்தவை உள்ளன: `omarchy models use best image`, `video` அல்லது `music`. ஒவ்வொரு வகையின் இந்தக் கணினிக்கான தேர்வைப் பார்க்க `omarchy models use best` ஐ இயக்கவும்.

அல்லது மேல் பட்டியில், முகவர்கள் ஐகானுக்கு அருகில் உள்ள அதன் மினுமினுப்பு ஐகானிலிருந்து, அல்லது Super + Ctrl + Alt + X உடன் உள்ளூர் மாதிரிகள் பலகத்தைத் திறந்து, + ஐத் தேர்ந்தெடுக்கவும். ஒரு மாதிரி இந்தக் கணினிக்குப் பொருந்தும்போது ஐகான் தோன்றும். மாதிரிகளை இயக்கும் Podman, Omarchy உடன் வருகிறது, NVIDIA கணினியில் NVIDIA-இன் கொள்கலன் கருவித்தொகுப்பும் வருகிறது, அது அவற்றுக்கு GPU-ஐ வழங்குகிறது; ஏதேனும் ஒன்று இல்லை என்றால், முதல் அமைப்பு அதை நிறுவும். பின்னர் Omarchy இந்தக் கணினிக்கு பரிந்துரைக்கப்பட்ட மாதிரியைத் தேர்ந்தெடுத்து, அதைப் பதிவிறக்கி, தொடங்கும். பத்துகள் GB பதிவிறக்கத்தையும் மாதிரி இயங்கும்போது கணினியின் நினைவகத்தின் பெரும்பகுதி பயன்பாட்டில் இருப்பதையும் எதிர்பார்க்கவும்: Flash Next அதன் முழு 256K சூழலுடன் சுமார் 100 GiB ஐப் பயன்படுத்துகிறது. அதற்குத் தேவையான நினைவகத்தை மற்ற மாதிரிகள் வைத்திருந்தால், அது நிறுத்தப்பட்ட நிலையில் அமைக்கப்படும், நீங்கள் ஒன்றை நிறுத்தியவுடன் தொடங்கத் தயாராக. மாதிரி வெளியேறும்போது நிற்கும்; உங்களுக்கு வேறு ஏதாவதற்கு நினைவகம் தேவைப்படும்போது அதை நீங்களே நிறுத்தவும்.

`omarchy models list` விருப்பங்களைக் காட்டி சில ஏன் பொருந்தவில்லை என்பதை விளக்குகிறது. மற்றொன்றை அமைக்க, `omarchy models use <recipe>` ஐ இயக்கவும். இன்று, 128 GB Strix Halo கணினிகளுக்கு `qwen3.8-flash-next-gufo` மற்றும் `qwen3.8-27b-gufo` கிடைக்கின்றன; 27B சுமார் 40 GiB எடுக்கும், எனவே அது மற்ற வேலைகளுக்கு இடம் விடுகிறது. Intel-இன் Arc B390 உடன் 64 GB மடிக்கணினியில், `qwen3.6-35b-a3b-llamacpp` சுமார் 30 GiB-இல் இயங்கும். புதிய ரெசிபிகள் மற்றும் பரிந்துரைகள் `omarchy update` உடன், தொகுப்பு வழியாக வரும்.

நீங்கள் அமைக்கும் ஒவ்வொரு மாதிரியும் உள்ளூர் மாதிரிகள் பலகத்தில் தனக்கென ஒரு வரியைப் பெறும்: அதைத் தொடங்க இயக்கவும், அதை நிறுத்தி அதன் நினைவகத்தை விடுவிக்க இடைநிறுத்தவும், மற்றும் அதில் உங்கள் முகவரைத் திறக்க முனைய பொத்தான். மேலே குறுக்காக, ஒரு பட்டி கணினியின் நினைவகம் Omarchy தானே (கணினி மற்றும் உங்கள் பயன்பாடுகள்), இயங்கும் ஒவ்வொரு மாதிரி, மற்றும் காலியாக உள்ளது ஆகியவற்றுக்கிடையே எப்படி பிரிக்கப்பட்டுள்ளது என்பதைக் காட்டும். நிறுத்தப்பட்ட மாதிரியைச் சுட்டிக்காட்டவும், பட்டி அது பொருந்துமா, அல்லது எவ்வளவு குறைவாக உள்ளது என்பதைக் காட்டும். அவை நினைவகத்தில் ஒன்றாகப் பொருந்தும்போது பல ஒரே நேரத்தில் இயங்க முடியும்; ஒன்று பொருந்தவில்லை என்றால், எந்த இயங்கும் மாதிரியை நிறுத்த வேண்டும் என Omarchy சொல்லும். அவற்றை மறுவரிசைப்படுத்த அவற்றின் லோகோவால் வரிகளை இழுக்கவும், மற்றும் மாதிரியையும் அதன் பதிவிறக்கத்தையும் அகற்ற தேர்ந்தெடுக்கப்பட்ட வரியில் Delete ஐ அழுத்தவும்.

நீங்கள் அமைக்கும் ஒவ்வொரு குறியீட்டு மாதிரியும் பயன்பாட்டு தொடக்கியில், மாதிரியின் பெயரின் கீழ் மற்றும் அதன் தயாரிப்பாளரின் லோகோவுடன், Claude, Codex அல்லது Grok-இல் உள்நுழைவது ஒன்றைச் சேர்ப்பது போலவே தனக்கென ஒரு உள்ளீட்டைப் பெறும். இது அந்த மாதிரியில் உங்கள் முகவரைத் திறக்கும், மற்றும் அது இயங்கவில்லை என்றால் மாதிரியை முதலில் தொடங்கும்: முனையம் அது ஏற்றப்படுவதைக் காட்டி அது தயாரானவுடன் முகவரிடம் ஒப்படைக்கும். மாதிரியை அகற்றுவது அதன் உள்ளீட்டை அகற்றும்.

ஒவ்வொரு மாதிரியும் குறியீட்டுக்காக அல்ல. படம், வீடியோ மற்றும் இசை மாதிரிகள் அதற்கு பதிலாக Fantasi-இல் திறக்கும், இந்தக் கணினியில் இயங்கும் மாதிரியுடன் படங்கள், வீடியோ மற்றும் இசையை உருவாக்குவதற்கான Omarchy-இன் பயன்பாடு, அங்கு அல்லது உள்ளூர் மாதிரிகள் பலகத்தில் அவற்றின் வரியிலிருந்து தேர்ந்தெடுக்கப்படும்.

ஒரு மாதிரி அது அமைக்கப்பட்டது போலவே தொடர்ந்து இயங்கும், எனவே Omarchy புதுப்பிப்பு உங்கள் முகவர்களின் கீழ் ஒன்றை ஒருபோதும் மறுதொடக்கம் செய்யாது. நீங்கள் அமைத்த மாதிரிக்கு Omarchy-இடம் புதிய இயக்கநேரம் அல்லது புதிய எடைகள் இருக்கும்போது, அதன் வரி புதுப்பிப்பு பொத்தானைக் காட்டும்: அதை அழுத்தவும், மாதிரி பின்னணியில் மீண்டும் அமைக்கப்படும், மாறியதை மட்டும் பதிவிறக்கி, புதிய பதிப்பில் மறுதொடக்கம் செய்யும். நிறுத்தப்பட்டிருந்த மாதிரி நிறுத்தப்பட்டே இருக்கும். `omarchy models update` முனையத்திலிருந்து ஒவ்வொரு மாதிரிக்கும் அதையே செய்யும்.

கட்டளை வரியிலிருந்து, `omarchy models start <recipe>` மற்றும் `omarchy models stop <recipe>` அதையே செய்யும், `omarchy models status` ஒவ்வொரு மாதிரியையும் காட்டும், மற்றும் `omarchy agent --local-model <recipe>` உங்கள் இயல்புநிலை முகவர் எதுவாக இருந்தாலும் அந்த மாதிரியை pi-இல் திறக்கும். உங்கள் உள்ளூர் மாதிரியை முகவர் ஹாட்கீ, Quake கன்சோல், மற்றும் _Make something_ திறப்பதாக மாற்ற, `omarchy default agent local` ஐ இயக்கவும் அல்லது _Agent > Harness_ கீழ் _Local model_ ஐத் தேர்ந்தெடுக்கவும். pi நீங்கள் அமைத்த ஒவ்வொரு மாதிரியையும், நீங்கள் இணைத்த கணினிகளில் உள்ளவற்றையும், அதன் சொந்த மாதிரி தேர்வியில் பட்டியலிடும், எனவே சாதாரண `pi` அவற்றையும் அடையும். எந்த OpenAI-இணக்கமான கிளையண்டும் இணைக்க முடியும்: `status` ஒவ்வொரு மாதிரியின் முகவரியையும் காட்டும் (முதலாவது `http://127.0.0.1:11435/v1`), ரெசிபி பெயரே மாதிரி, மற்றும் விசை `~/.config/omarchy/agent-local/key`-இல் உள்ளது.

`omarchy models remove <recipe>` மாதிரியையும் வேறு எந்த மாதிரியும் பயன்படுத்தாத பதிவிறக்கங்களையும் நீக்கும்.

மூன்றாம்-தரப்பு இயக்கநேரங்கள் அவற்றின் வெளியீட்டாளருடன் குறிக்கப்படும். Omarchy ஒவ்வொரு மாதிரியையும் நெட்வொர்க் அணுகல் இல்லாமல் இயக்குகிறது.

### உள்ளூர் LLM-கள்

Omarchy உள்ளூர் LLM மாதிரிகளை இயக்க இரண்டு வழிகளைப் பரிந்துரைக்கிறது: LM Studio மற்றும் Ollama. LM Studio திறந்த-எடை மாதிரிகளைக் கண்டறிய, அவற்றை நிறுவ, மற்றும் அவற்றை இயக்க GUI இடைமுகத்தை வழங்குகிறது. எளிதாகத் தொடங்க இது சிறந்த வழி. Ollama அதேபோல செய்ய CLI-ஐ வழங்குகிறது. ஆனால் நீங்கள் உள்ளூர் மாதிரிகளுக்கு புதியவராக இருந்தால், நான் LM Studio-உடன் தொடங்குவேன். Omarchy Menu-இல் _Install > AI_ கீழ் நீங்கள் ஏதேனும் ஒன்றை நிறுவ முடியும்.

### Omarchy ஸ்கில்கள்

முகவர் ஸ்கில்கள் AI குறிப்பிட்ட கருவிகளை குறிப்பிட்ட வழியில் பயன்படுத்த உதவுகின்றன, மற்றும் Omarchy அவற்றில் ஏழை வழங்குகிறது. omarchy ஸ்கில் உங்கள் Hyprland உள்ளமைவை மாற்றுவது அல்லது பட்டியை சரிசெய்வது போல கணினியைத் தனிப்பயனாக்குவதை உள்ளடக்கும். omarchy-make-theme, omarchy-make-plugin, omarchy-make-app, மற்றும் omarchy-make-game புதிதாக ஏதாவது உருவாக்குவதை உள்ளடக்கும், omarchy-contribute பிழையை அறிவிப்பது அல்லது சரிசெய்தலை மேல்நிலைக்கு அனுப்புவதை உள்ளடக்கும், மற்றும் omarchy-diagnose-crash செயலிழப்பின் கோர் டம்ப் வழியாக வேலை செய்யும். அவை Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` மற்றும் ஒவ்வொரு `~/.hermes/profiles/*/skills`), மற்றும் பொதுவான `~/.agents/skills` இருப்பிடத்திற்கான ஸ்கில் கோப்பகங்களில் சிம்லிங்க் செய்யப்பட்டுள்ளன, எனவே பெரும்பாலான ஹார்னஸ்கள் அவற்றைத் தானாகவே எடுக்கும். அதே பெயருடன் உங்கள் சொந்த ஸ்கில் கோப்புறை முன்னுரிமை பெறும்.

ஆனால் நீங்கள் இந்த ஸ்கில்களை சோதனை முயற்சியாகக் கருத வேண்டும். வெவ்வேறு மாதிரிகள் அதை வெவ்வேறு விளைவுகளுக்குப் பயன்படுத்தும். முதலில் பிளான் முறையில் இயக்குவது சிறந்தது, எனவே முகவர் எதை மாற்ற விரும்புகிறது என்பது பற்றி உங்களுக்கு ஒரு யோசனை இருக்கும். மற்றும் முகவர் எல்லாவற்றையும் குழப்பினால், மாற்றங்களைத் திரும்பப் பெற அல்லது `omarchy reinstall configs` ஐ அழைக்கக் கூடத் தயாராக இருங்கள்.
