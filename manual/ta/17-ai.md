# AI

Omarchy AI coding agentகளை முதல் தர குடிமக்களாக நடத்துகிறது, ஆனால் உங்களுக்காக ஒரு விருப்பமானதை நிச்சயம் தேர்ந்தெடுப்பதில்லை. அதற்குப் பதிலாக, ஒவ்வொரு முக்கியமான coding-agent CLIயும் lazy-loaded launcher ஆக முன்கூட்டியே இணைக்கப்பட்டு வருகிறது. Launcherகள் `~/.local/bin/` இல் உள்ள சிறிய [mise](https://mise.jdx.dev/)-நிர்வகிக்கப்படும் stubகள், எனவே நீங்கள் உண்மையில் ஒன்றை முதல்முறையாக இயக்கும் வரை எதுவும் பதிவிறக்கப்படாது. Hermes இதற்கு விதிவிலக்கு: அதற்கு எதுவும் stub செய்யப்படவில்லை, அதைத் தேர்ந்தெடுப்பது Hermes Desktopஐ நிறுவுகிறது, கீழே உள்ள _டெஸ்க்டாப் ஆப்ஸ்_ விளக்குவது போல. இவற்றில் ஏதேனும் ஒன்றை இயக்கி, கேட்கப்படும் போது அங்கீகரிக்கவும்:

| கட்டளை    | ஏஜென்ட்                                                            |
|------------|------------------------------------------------------------------|
| `claude`   | [Claude Code](https://code.claude.com/docs/en/overview)          |
| `codex`    | [OpenAI Codex](https://github.com/openai/codex)                  |
| `opencode` | [OpenCode](https://opencode.ai/)                                 |
| `agy`      | [Google Antigravity CLI](https://github.com/google-antigravity/antigravity-cli) |
| `copilot`  | [GitHub Copilot CLI](https://github.com/github/copilot-cli)      |
| `crush`    | [Crush](https://github.com/charmbracelet/crush)                  |
| `grok`     | xAI இலிருந்து [Grok Build](https://x.ai/build)                        |
| `kimi`     | [Kimi Code](https://www.kimi.com/code/docs/en/)                  |
| `pi`       | [Mario Zechnerஇன் Pi](https://github.com/badlogic/pi-mono)        |
| `omp`      | [Oh My Pi](https://github.com/can1357/oh-my-pi)                  |
| `ori`      | [Ori](https://openrouter.ai/docs/guides/ori/harness), OpenRouterஇன் harness |
| `hermes`   | [Hermes](https://hermes-agent.nousresearch.com/), Nous Researchஇன் ஏஜென்ட்  |
| `muse`     | [Muse Code](https://dev.meta.ai), Metaவின் coding agent           |
| `cursor-agent` | [Cursor CLI](https://cursor.com/cli)                         |

`ori` தான் வித்தியாசமானது: இது OpenRouterஇன் முழு மாடல் பட்டியலுக்கு எதிராக மற்ற harnessகளை இயக்குகிறது, எனவே `ori claude`, `ori codex` அல்லது `ori opencode` ஆகியவை நீங்கள் சுட்டிக்காட்டும் எந்த மாடலிலும் அந்த ஏஜென்டுகளைத் தொடங்குகின்றன, மேலும் `ori code` என்பது Oriஇன் சொந்த ஏஜென்ட்.

அதே வழியில் கூடுதல் CLI ஒன்றைச் சுற்றி வைக்க, `omarchy-mise-install <package> [command-name]` ஐ இயக்கவும். நீங்கள் `omarchy update` (அல்லது `mup` alias) ஐ இயக்கும்போது mise நிர்வகிக்கும் மற்ற அனைத்துடனும் சேர்ந்து stubகளும் புதுப்பிக்கப்பட்டிருக்கும்.

`grok` என்பது `claude` மற்றும் `codex` போலவே miseஇன் first-party `grok` பேக்கேஜ் மூலம் நிறுவப்படுகிறது. `grok` ஐ இயக்கவும், அல்லது _Setup > Defaults > Agent_ இன் கீழ் அதைத் தேர்ந்தெடுக்கவும். x.ai இல் உள்ள `curl | bash` installerஐத் தவிர்க்கவும். அந்த வழி `~/.grok/bin` இல் இரண்டாவது நகலை வைத்து, அதை `PATH` இல் முன்னால் சேர்த்து, Omarchyஇன் wrapperஐ மேலெழுதும்.

### இயல்புநிலை ஏஜென்ட்

`omarchy default agent <name>` மூலமாகவோ அல்லது Omarchy Menuவில் (`Super + Space`) _Setup > Defaults > Agent_ இன் கீழோ உங்கள் இயல்புநிலை ஏஜென்டைத் தேர்ந்தெடுக்கவும். ஏஜென்ட் இன்னும் நிறுவப்படவில்லை என்றால், அதைத் தேர்ந்தெடுப்பது முதலில் அதை நிறுவும். புதிய Omarchy ஒருமுறை அறிவிப்பு மூலம் இந்தத் தேர்வைச் செய்ய உங்களை அழைக்கும்.

Claudeஐத் தேர்ந்தெடுப்பது Chromium, Chrome, Brave, Brave Origin மற்றும் Edgeக்கான அதன் உலாவி நீட்டிப்பையும் அமைக்க முயற்சிக்கும். நீட்டிப்பு அமைப்பு அனைத்து பயனர்களுக்கும் பொருந்தும், உங்கள் சிஸ்டம் கடவுச்சொல்லைக் கேட்கக்கூடும்; அதை ரத்து செய்தாலோ அல்லது நீட்டிப்பு நிறுவல் தோல்வியடைந்தாலோ கூட Claude தேர்ந்தெடுக்கப்பட்டுத் தொடங்கப்படும். உங்கள் உலாவியை மறுதொடக்கம் செய்யவும், கேட்கப்பட்டால் நீட்டிப்பை இயக்கவும், அதை இணைப்பதை முடிக்க Claudeஇல் உள்நுழையவும். இணைப்பைச் சரிபார்க்க Claudeஇல் `/chrome` ஐ இயக்கவும். Firefox மற்றும் Zen இந்த நீட்டிப்பை ஆதரிப்பதில்லை. இந்த அமைப்பு சேர்க்கப்படுவதற்கு முன்பே Claude உங்கள் இயல்புநிலையாக இருந்திருந்தால், நீட்டிப்பை நிறுவ அதை மீண்டும் தேர்ந்தெடுக்கவும்.

[Muse Code](https://dev.meta.ai) — Metaவின் `muse` — மற்ற ஏஜென்டுகளைப் போலவே முன்கூட்டியே நிறுவப்பட்ட mise stubஐப் பயன்படுத்துகிறது. அதை இயல்புநிலையாகத் தேர்ந்தெடுப்பது miseஇன் HTTP backend மூலம் Metaவின் அதிகாரப்பூர்வ launcherஐ நிறுவுகிறது. Launcher உங்கள் இயந்திரத்திற்கான native binaryஐச் சரிபார்த்துப் புதுப்பிக்கிறது.

நீங்கள் தேர்ந்தெடுத்தவுடன், `Super + Shift + Ctrl + A` இயல்புநிலை ஏஜென்டை ஒரு பிரத்யேக terminal சாளரத்தில் தொடங்கும் (அல்லது நீங்கள் இன்னும் தேர்ந்தெடுக்கவில்லை என்றால் pickerஐக் கொண்டுவரும்). `omarchy agent prompt "Review this project"` மூலம் அதை நேரடியாக ஒரு பணிக்குள்ளும் தொடங்கலாம். இப்படித் தொடங்கப்படும் ஏஜென்டுகள் அந்தந்த don't-stop-to-ask பயன்முறைகளில் கவனிக்கப்படாமல் இயங்கும், எனவே அவை உண்மையில் செயல்படத் தயாராக இருங்கள்! மேலும் ஏஜென்டுகள் உங்கள் home directoryக்கான நம்பிக்கையை நினைவில் வைத்திருக்க மறுப்பதால், `$HOME` இலிருந்து தொடங்கும் இயக்கங்கள் அதற்குப் பதிலாக `~/Work` இல் தொடங்குகின்றன.

Terminal குறுக்குவழிகளும் உள்ளன: `a` தற்போதைய terminalஇல் இயல்புநிலை ஏஜென்டை இன்லைனாக இயக்குகிறது, அதே நேரத்தில் `c`, `cx`, மற்றும் `cy` ஆகியவை OpenCode, Claude Code, மற்றும் Codexஐ நேரடியாகத் தொடங்குகின்றன (மீண்டும், அவற்றின் auto-approving பயன்முறைகளில்). Theme மாற்றங்களும் ஏஜென்டுகளுடன் ஒத்திசைகின்றன: நீங்கள் Omarchy themeஐ மாற்றும்போது Claude Code, Pi, OpenCode, மற்றும் Hermes (Omarchy அதை நிறுவியவுடன்) அனைத்தும் அதனுடன் ஒத்துச் செல்லும்.

### ஏஜென்டுகள் பேனல்

மேல் barஇல் ஒரு ஏஜென்டுகள் ஐகான் உள்ளது. நீங்கள் ஒரு ஏஜென்டை அமைப்பதற்கு முன், அதன் பேனல் Claude, Codex, அல்லது Grokஇல் உள்நுழைவதற்கு உங்களை வழிநடத்துகிறது, முதலாவது உங்கள் இயல்புநிலை ஏஜென்டாக ஆகும். அதன் பிறகு, பேனல் ஒவ்வொரு சந்தாவையும் ஒரே பக்கத்தில் வைக்கிறது: ஒவ்வொரு ஏஜென்ட் மற்றும் கணக்கும் அதன் திட்டத்துடன், அதன் ஒவ்வொரு 5 மணிநேர session மற்றும் வாராந்திர வரம்புகளுக்கும் ஒரு meter உடன், அது மீட்டமைக்கப்படும் வரையிலான நேரத்துடன் (leaf துல்லியமான சதவீதத்திற்கு hover செய்யவும்), அல்லது மீதமுள்ள முன்கட்டண இருப்பு, இந்த வார டோக்கன்கள் மற்றும் நீங்கள் அதிகம் பயன்படுத்திய மாடல் போல அவை அனைத்திலும் நீங்கள் பயன்படுத்தியதை சுழற்றிக் காட்டும் ஒரு வரியின் கீழ். _Make something_ இன் கீழ் அது ஒரு புதிய theme, plugin, அல்லது ஆப்பிற்கான starter promptகளை வழங்குகிறது, அவை பணியை உங்கள் இயல்புநிலை ஏஜென்டிடம் ஒப்படைக்கின்றன. Omarchyஇன் சொந்த Hype, Monologue, மற்றும் Omacut உருவாக்கப்படும் வழியிலேயே C++ மற்றும் Qt Quick இல், omarchy-app agent skillஐப் பின்பற்றி ஆப்ஸ் உருவாக்கப்படுகின்றன, அவற்றுக்குத் தேவையான compiler மற்றும் Qt பகுதிகள் நிறுவப்பட்டு வருகின்றன. Claude Code, Codex, Grok, Fireworks, மற்றும் Kimi ஆகியவை தொடக்கத்திலேயே உள்ளடக்கப்படுகின்றன. Kimi தற்போது உள்ளூர் டோக்கன் அல்லது prompt புள்ளிவிவரங்கள் இல்லாமல் கணக்கு ஒதுக்கீட்டு வரம்புகளைத் தெரிவிக்கிறது.

பேனலுக்கு bar ஐகானை இடத்து கிளிக் செய்யவும், உங்கள் இயல்புநிலை ஏஜென்டைத் தொடங்க வலது கிளிக் செய்யவும். அதன் பின்னணியில் உள்ள பயன்பாட்டுப் பதிவுகள் ஒவ்வொரு 15 நிமிடங்களுக்கும் `omarchy agent usage-update` மூலம் மீண்டும் உருவாக்கப்படுகின்றன, மேலும் பேனல் ஒரு ஒத்திசைக்கப்பட்ட folder மூலம் உங்கள் மற்ற இயந்திரங்களிலிருந்து வரும் பயன்பாட்டைக் கூட இணைக்க முடியும். முழு அமைப்புகளுக்கு `$OMARCHY_PATH/shell/plugins/agents/` இன் கீழ் உள்ள READMEஐப் பார்க்கவும்.

### பல சந்தாக்கள்

நீங்கள் ஒன்றுக்கு மேற்பட்ட Claude, Codex, அல்லது Grok திட்டங்களுக்குப் பணம் செலுத்தினால் — எடுத்துக்காட்டாக தனிப்பட்ட Max ஒன்றும் வேலைக்கான ஒன்றும் — Omarchy அவை அனைத்தையும் உள்நுழைந்த நிலையில் வைத்து அவற்றுக்கிடையே நகர முடியும். ஏஜென்டுகள் பேனலில் உள்ள + மூலம் ஒரு சந்தாவைச் சேர்க்கவும், அது அங்கேயே உங்களை அதில் வழிநடத்துகிறது, அல்லது `omarchy agent account add claude Work` (அல்லது `codex`, அல்லது `grok`) மூலம் சேர்க்கவும். அது இல்லையென்றால் அது CLIஐ நிறுவும். ஒரு வழங்குநருக்கான முதல் கணக்கு உங்கள் வழக்கமான உலாவி மூலம், CLI எப்போதும் பார்க்கும் இடத்திலேயே உள்நுழைகிறது. அதற்குப் பிறகான ஒவ்வொன்றும் ஒரு தனியார் சாளரம் மூலம் உள்நுழைகிறது, எனவே உங்கள் உலாவி ஏற்கனவே உள்நுழைந்திருக்கும் கணக்கு தவறுதலாக எடுக்கப்படாது; நீங்கள் சேர்க்கும் கணக்காக அங்கே உள்நுழையவும், மேலும் நீங்கள் ஏற்கனவே திறந்து வைத்திருந்த எந்த தனியார் சாளரத்தையும் முதலில் மூடவும். இதைச் செய்ய CLIஇலிருந்து ஒருபோதும் வெளியேற வேண்டாம்: வெளியேறுவது சேமிக்கப்பட்ட உள்நுழைவை ரத்து செய்கிறது, அந்தக் கணக்கை மீண்டும் சேர்க்க வேண்டியிருக்கும்.

உங்கள் சந்தா உள்நுழைவுகளை SSH மூலம் மற்றொரு Omarchy இயந்திரத்திற்கு நகலெடுக்க, `omarchy agent account copy user@laptop` ஐ இயக்கவும். இலக்கில் ஒன்று நிறுவப்படவில்லை என்றால் அனுப்புநர் ஒரு தற்காலிக receiverஐ வழங்குகிறார், எனவே பழைய Omarchy இயந்திரங்கள் புதுப்பிப்பு இல்லாமல் கணக்குகளைப் பெற முடியும். நிறுவப்பட்ட receiverகளுக்கு முன்னுரிமை. இது அனைத்து Claude, Codex, மற்றும் Grok சந்தாக்களையும் நகலெடுக்கிறது; அவற்றைத் தேர்ந்தெடுக்க வழங்குநர் பெயர்களைச் சேர்க்கவும், `omarchy agent account copy laptop claude` இல் உள்ளது போல. கணக்குப் பெயர்கள் மற்றும் கட்டளை IDகள் மூலத்துடன் பொருந்துகின்றன, இலக்கில் ஏற்கனவே உள்ள கணக்குகள் உட்பட. தொடர்பில்லாத இலக்குக் கணக்குகளின் பெயர்கள் முரண்பட்டால் அவை ஒரு எண் பின்னொட்டைப் பெறுகின்றன, மேலும் அமைப்புகள், skillகள், pluginகள், மற்றும் உரையாடல் வரலாறு ஒவ்வொரு இயந்திரத்திற்கும் உள்ளூராகவே இருக்கும்.

ஏற்கனவே உள்ள இலக்குச் சான்றுகள் வைத்திருக்கப்படுகின்றன. அங்கே ஏற்கனவே உள்நுழைந்துள்ள ஒரு மூலக் கணக்கின் பெயர் அதன் சான்றுகளை மாற்றாமல் ஒத்திசைக்கப்படுகிறது; மற்ற கணக்குகள் அதனுடன் சேர்த்து சேர்க்கப்படுகின்றன. பொருந்தும் கணக்குகளுக்கு சேமிக்கப்பட்ட சான்றுகளை மாற்ற, இலக்கில் அந்தக் கணக்கின் sessionகளை மூடிய பிறகு `omarchy agent account copy --replace laptop claude` ஐப் பயன்படுத்தவும். புதிய இலக்கு மூலத்தின் செயலில் உள்ள கணக்கு மற்றும் மாற்றும் விருப்பங்களையும் பெறுகிறது; ஏற்கனவே நிறுவப்பட்ட இலக்கு தன்னுடையதையே வைத்திருக்கிறது.

சான்றுகள் SSH மூலம் பயணித்து இலக்கில் தனியார் கோப்புகளில் சேமிக்கப்படுகின்றன, எனவே நீங்கள் நம்பும் இயந்திரங்களுக்கு மட்டும் நகலெடுக்கவும். இது ஒருமுறை நகல், தொடர்ச்சியான ஒத்திசைவு அல்ல. Codex refresh tokenகளை மற்றொரு இயந்திரம் சுழற்றக்கூடும், நகலெடுக்கப்பட்ட உள்நுழைவுக்குப் புதுப்பித்தல் தேவைப்படும்; பல இயந்திரங்களில் ஒரே நேரத்தில் பயன்படுத்துவதற்கு தனித்தனி உள்நுழைவுகளே மிகவும் நம்பகமான தேர்வாக இருக்கின்றன. [Codexஇன் கணக்கு அங்கீகார வழிகாட்டுதலைப்](https://developers.openai.com/codex/auth/ci-cd-auth) பார்க்கவும்.

ஒவ்வொரு வழங்குநருக்கும் ஒரு கணக்கு செயலில் இருக்கும், ஒவ்வொரு புதிய sessionனும் அதுவாகவே தொடங்கும்: `cx`, `cy`, ஒரு வெற்று `claude`, `codex`, அல்லது `grok`, `omarchy agent` மூலம் தொடங்கப்படும் எதுவும், மற்றும் `PATH` இல் CLIஐக் கண்டுபிடிக்கும் scriptகள் அல்லது editorகள். `omarchy agent account use work` மூலம் மாற்றவும் (மேலும் `omarchy agent account use main` மூலம் திரும்பவும்), அல்லது பேனலில் ஒரு கணக்கின் எண்ணை அழுத்தி பின்னர் `Enter` ஐ அழுத்துவதன் மூலம் (அல்லது அதன் Use பொத்தானைக் கிளிக் செய்வதன் மூலம்) மாற்றவும். ஏற்கனவே இயங்கிக் கொண்டிருக்கும் sessionகள் அவை தொடங்கிய கணக்கிலேயே இருக்கும். உரையாடல் வரலாறு, அமைப்புகள், skillகள், மற்றும் pluginகள் கணக்குகள் முழுவதும் பகிரப்படுகின்றன, எனவே அதே folderஇல் `claude --continue` நீங்கள் புதிய கணக்கில் விட்ட இடத்திலிருந்து தொடரும்.

ஒன்றுக்கு மேற்பட்ட கணக்குகளுடன், பேனல் ஒவ்வொரு கணக்கின் வரம்புகளையும் பக்கத்துப் பக்கமாகக் காட்டுகிறது, செயலில் உள்ளது குறிக்கப்பட்டிருக்கும். இயல்புநிலையாக செயலில் உள்ள கணக்கு ஒரு வரம்பின் 95% ஐக் கடக்கும் போது Omarchy உங்களுக்கு அறிவிக்கிறது, அறிவிப்பைக் கிளிக் செய்வது அதிக இடவசதி உள்ள கணக்கிற்கு மாற்றுகிறது. பேனலில் ஒரு கணக்கின் வரியின் மீது hover செய்து Use க்கு அருகில் தோன்றும் Autoswitchஐக் கிளிக் செய்யவும் (அல்லது `m` ஐ அழுத்தவும்), அல்லது அது தானாகவே மாறுவதற்கு பதிலாக `omarchy agent account mode auto` ஐ இயக்கவும்; அது இயக்கத்தில் இருக்கும் போது, Autoswitch Useஇன் இடத்தைப் பிடிக்கிறது, அதை மீண்டும் கிளிக் செய்வது அறிவிப்பதற்குத் திரும்பும். வரம்பை மாற்ற ஒரு எண்ணைச் சேர்க்கவும், `omarchy agent account mode auto 90` இல் உள்ளது போல. ஒவ்வொரு கணக்கும் வரம்பை விட அதிகமாக இருந்தால், எந்தக் கணக்கு முதலில் விடுவிக்கப்படும் என்பதுடன் சேர்த்து அதைப் பற்றி ஒருமுறை நீங்கள் கேள்விப்படுவீர்கள். செயலில் உள்ள ஒரு கணக்கு அதன் வரம்பிலிருந்து 15 புள்ளிகளுக்குள் இருக்கும் போது (இயல்புநிலையில் 80%), அதன் வரம்புகள் ஒவ்வொரு 15 நிமிடங்களுக்குப் பதிலாக ஒவ்வொரு மூன்று நிமிடங்களுக்கும் சரிபார்க்கப்படுகின்றன.

`omarchy agent account list` ஒவ்வொரு கணக்கையும் அதன் சமீபத்திய வரம்புகளையும் காட்டுகிறது, `omarchy agent account remove work` ஒன்றை மறக்கிறது, மேலும் `omarchy agent account rename primary Hey` ஒன்றிற்கு மறுபெயரிடுகிறது (அல்லது பேனலில் ஒரு கணக்கின் பெயரைக் கிளிக் செய்யவும்). இந்தக் கட்டளைகள் உங்கள் இயல்புநிலை ஏஜென்டின் கணக்குகளில் வேலை செய்கின்றன; மற்ற வழங்குநரை அடைய, முதலில் அதைப் பெயரிடவும், `omarchy agent account use codex side` இல் உள்ளது போல. `~/.claude` அல்லது `~/.codex` இல் நீங்கள் ஏற்கனவே வைத்திருந்த உள்நுழைவு _Main_ கணக்கு மற்றும் அது இருக்கும் இடத்திலேயே இருக்கும். சுமார் எட்டு மணிநேரங்களுக்கு மேல் பயன்படுத்தப்படாமல் விடப்பட்ட ஒரு கணக்கு _Sign-in required_ ஐக் காட்டக்கூடும்; அந்தக் கணக்கை மீண்டும் பேனலிலேயே உள்நுழைய அதைக் கிளிக் செய்யவும், அல்லது அதில் ஒரு sessionஐத் தொடங்கவும், அது தானாகவே உள்நுழைவைப் புதுப்பிக்கிறது. ஒரு கணக்கு சேர்க்கப்பட்டபோது நீங்கள் வைத்திருந்த MCP serverகள் அதனுடன் வருகின்றன, ஆனால் நீங்கள் பின்னர் `claude mcp add` மூலம் சேர்ப்பவை நீங்கள் அவற்றைச் சேர்த்த கணக்கை மட்டுமே அடைகின்றன. Claude Desktop மற்றும் CLI binary க்கான முழுமையான பாதையுடன் கட்டமைக்கப்பட்ட கருவிகள் மாற்றத்தைப் பின்பற்றுவதில்லை. வெளிப்படையான `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, அல்லது `GROK_HOME` தேர்ந்தெடுக்கப்பட்ட கணக்கை விட முன்னுரிமை பெறுகிறது.

### செயலிழப்பு நோயறிதல்

Omarchy செயல்முறைச் செயலிழப்புகளுக்கு systemd-coredump ஐக் கவனிக்கிறது. ஏதாவது segfault ஆகும் போது, உங்களுக்கு ஒரு "Process crashed" அறிவிப்பு கிடைக்கும் — அதைக் கிளிக் செய்யவும், செயலிழப்பு Omarchyஇன் diagnose-crash skill உடன் சேர்த்து உங்கள் இயல்புநிலை ஏஜென்டிடம் ஒப்படைக்கப்படும், அது core dump இலிருந்து உண்மைகளை நிறுவுவதிலும் செயலிழப்பு upstream இல் தெரிவிக்கத் தகுதியானதா என்று முடிவு செய்வதிலும் ஏஜென்டை வழிநடத்துகிறது. `omarchy agent crash <pid>` மூலம் `coredumpctl list` இலிருந்து எந்த PID க்கு எதிராகவும் அதை கைமுறையாக இயக்கலாம்.

கவனிப்பது இயல்புநிலையாக இயக்கத்தில் உள்ளது. அதை _Trigger > Toggle > Crash Capture_ இன் கீழோ (அல்லது `omarchy toggle crash-capture` மூலமோ) முடக்கவும், அறிவிப்புகள் நிற்கும்; `omarchy agent crash <pid>` இன்னும் கைமுறையாக வேலை செய்கிறது.

செயலிழப்புகளை ஒரு நேரத்தில் ஒரு நிரல் வீதமும் அமைதிப்படுத்தலாம், இறுதியில் நோயறிதல் உங்களுக்கு வழங்குவது அதுதான். `omarchy crash mute hyprland` அந்த நிரலுக்கு மட்டும் அறிவிப்புகளை நிறுத்துகிறது, `omarchy crash mute hyprland off` அவற்றை மீண்டும் கொண்டுவருகிறது, மேலும் தனியாக `omarchy crash mute` நீங்கள் mute செய்ததைப் பட்டியலிடுகிறது. அது binaryஇன் பெயரைப் போலவே அதன் பாதையையும் மகிழ்ச்சியுடன் எடுக்கிறது, எனவே `omarchy crash mute /usr/bin/hyprland` அதே காரியத்தைச் செய்கிறது. இடைவெளி உள்ள பெயரை மேற்கோள் காட்டவும், `omarchy crash mute 'Some App'` இல் உள்ளது போல. மற்ற அனைத்தும் இன்னும் அறிவிக்கின்றன, மேலும் mute செய்யப்பட்ட நிரல் இன்னும் செயலிழக்கிறது — இது நினைவூட்டலை மறைக்கிறது, எதையும் சரிசெய்வதில்லை.

### டெஸ்க்டாப் ஆப்ஸ்

_Install > AI_ மெனு சில வரைகலை AI ஆப்ஸையும் கொண்டுள்ளது: ChatGPT desktop app, Claude desktop app (Chat, Cowork, மற்றும் Claude Code tabs உடன் Anthropicஇன் Linux beta), xAIஇன் மாடல்களுடன் அரட்டையடிக்க Grok Bot, Hermes Desktop, OpenClaw, மற்றும் Perplexity desktop app. Grok Bot என்பது desktop chat app. Coding agent என்பது `grok` கட்டளை.

Hermes Desktop தான் தெரிந்து கொள்ள வேண்டிய ஒன்று, ஏனெனில் ஒரு இயந்திரத்தில் ஒரே ஒரு Hermes உள்ளது, அது ஆப்பினுடையது: Hermes எப்போதும் ஆப்பின் மூலமே நிறுவப்படுகிறது, இயல்புநிலை ஏஜென்ட் இயக்கும் `hermes` கட்டளையும் ஆப்பினுடையதே. Hermesஐ இயல்புநிலை ஏஜென்டாகத் தேர்ந்தெடுப்பது _Install > AI_ உள்ளீடு செய்வதையே நிறுவுகிறது: பேக்கேஜ், மற்றும் Hermesஇன் சொந்த installer மூலம் அமைக்கப்பட்ட `~/.hermes` இன் கீழ் ஒரு Hermes runtime, முதல்முறையாக இதற்கு சில நிமிடங்கள் ஆகின்றன. அந்த runtime தான் terminal `hermes` கட்டளை, இயல்புநிலை ஏஜென்ட் மற்றும் ஆப் அனைத்தும் பயன்படுத்தும் ஒரேயொரு Hermes, மேலும் அது ஒரு Omarchy வெளியீட்டிற்காகக் காத்திருப்பதை விட `hermes update` மூலம் தன்னைத்தானே புதுப்பித்துக் கொள்கிறது. அதை நிறுவுவது Hermesக்கு Omarchy themeஐ `omarchy` என்ற பெயரிடப்பட்ட skin ஆகவும் ஒப்படைக்கிறது, நீங்கள் themeகளை மாற்றும்போது ஒவ்வொரு Hermes மேற்பரப்பும் அதைப் பின்பற்றுகிறது; நீங்கள் அப்படி வேண்டாமென விரும்பினால் Hermesஇன் Appearance அமைப்புகளின் கீழ் அல்லது `/skin` மூலம் மற்றொன்றைத் தேர்ந்தெடுக்கவும், Omarchy அந்தத் தேர்வைத் தானே விட்டுவிடும். _Remove > AI_ இன் கீழ் ஆப்பை அகற்றுவது முதலில் Hermes ஐ, gateway உட்பட, மூடுகிறது, அந்த runtimeஐ அதனுடன் எடுத்துச் செல்கிறது, மேலும் நீங்கள் வேறுவிதமாகச் சொல்லாவிட்டால் உங்கள் அரட்டைகள், நினைவுகள், மற்றும் Hermes தனக்கென எழுதிய skillகளை வைத்திருக்கிறது: அந்தத் தரவு மற்றும் உங்கள் இணைப்பு அமைப்புகளும் செல்ல வேண்டுமா என்று அது கேட்கிறது, இல்லை என்பதையே இயல்புநிலையாகக் கொண்டு.

OpenClawஇன் desktop அனுபவம் அதன் Control UI, அது அதன் சொந்த உள்ளூர் gatewayஆல் ஆதரிக்கப்படும் web app ஆகத் திறக்கிறது. OpenClaw `~/.openclaw` இல் வசிக்கிறது, தன்னைத்தானே புதுப்பித்துக் கொள்கிறது: Control UIஇன் "Update Gateway" பொத்தானைப் பயன்படுத்தவும் அல்லது `openclaw update` ஐ இயக்கவும், gateway புதிய பதிப்பில் மறுதொடக்கம் செய்யப்படும். புதிய நிறுவல் எந்த வெளியீட்டில் தொடங்குகிறது என்பதை மட்டுமே Omarchy தேர்ந்தெடுக்கிறது. _Remove > AI_ இன் கீழ் OpenClaw ஐ அகற்றுவது gateway service மற்றும் ஆப்பை அதனுடன் எடுத்துச் சென்று பின்னர் `~/.openclaw` வும் செல்ல வேண்டுமா என்று கேட்கிறது, ஏனெனில் அதுதான் OpenClaw தானே மற்றும் அது பதிவிறக்கும் plugin runtimeகளுடன் சேர்த்து உங்கள் அரட்டைகள் மற்றும் சான்றுகளை வைத்திருக்கிறது; இயல்புநிலை அதை வைத்திருக்கிறது, OpenClaw ஐ மீண்டும் நிறுவுவது அதைத் திரும்ப எடுத்துக்கொள்கிறது.

### உள்ளூர் LLMகள்

Omarchy உள்ளூர் LLM மாடல்களை இயக்குவதற்கு இரண்டு வழிகளைப் பரிந்துரைக்கிறது: LM Studio மற்றும் Ollama. LM Studio open-weight மாடல்களைக் கண்டுபிடிக்கவும், அவற்றை நிறுவவும், அவற்றை இயக்கவும் ஒரு GUI இடைமுகத்தை வழங்குகிறது. எளிதாகத் தொடங்க இது ஒரு சிறந்த வழி. Ollama அதேபோலச் செய்வதற்கு ஒரு CLIஐ வழங்குகிறது. ஆனால் நீங்கள் உள்ளூர் மாடல்களுக்குப் புதியவர் என்றால், நான் LM Studio உடன் தொடங்குவேன். நீங்கள் Omarchy Menuவில் _Install > AI_ இன் கீழ் இரண்டில் ஒன்றை நிறுவலாம்.

### Omarchy Skill

Agent skillகள் AI குறிப்பிட்ட கருவிகளை ஒரு குறிப்பிட்ட வழியில் பயன்படுத்த உதவுகின்றன, Omarchy சிஸ்டத்தை வடிவமைப்பதற்கான ஒரு இயல்புநிலை skill உடன் வருகிறது. உங்கள் Hyprland configஐ மாற்றுவது, barஐச் சரிசெய்வது, அல்லது முதலிலிருந்து ஒரு புதிய themeஐ உருவாக்குவது போலவும் கூட. இது Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` மற்றும் ஒவ்வொரு `~/.hermes/profiles/*/skills`), மற்றும் பொதுவான `~/.agents/skills` இருப்பிடத்திற்கான skill directoryகளில் symlink செய்யப்பட்டுள்ளது, எனவே பெரும்பாலான harnessகள் அதைத் தானாகவே எடுத்துக்கொள்கின்றன.

ஆனால் நீங்கள் இந்த skillஐ சோதனை முறையாகவே கருத வேண்டும். வெவ்வேறு மாடல்கள் அதை வெவ்வேறு விளைவுகளுடன் பயன்படுத்தும். ஏஜென்ட் எதை மாற்ற விரும்புகிறது என்பதைப் பற்றி உங்களுக்கு ஒரு யோசனை இருப்பதற்காக, முதலில் plan modeஇல் இயக்குவது சிறந்தது. மேலும் ஏஜென்ட் எல்லாவற்றையும் குழப்பினால், பின்னர் மாற்றங்களைத் திரும்பப் பெறவோ அல்லது `omarchy reinstall configs` ஐ இயக்கவோ கூடத் தயாராக இருக்கவும்.
