Omarchy உங்களுக்காக இயல்புநிலையைத் தேர்ந்தெடுக்காமல், கீழே உள்ள கோடிங் ஏஜென்ட்களுக்கான லான்சர்களை உள்ளடக்கியுள்ளது. ஒரு கட்டளையை இயக்கினால் முதல் பயன்பாட்டில் அதன் CLI நிறுவப்படும், பின்னர் கேட்கும்போது அங்கீகரிக்கவும். Hermes இதற்கு விதிவிலக்கு: முதல் பயன்பாட்டில் அதற்கு எதுவும் நிறுவப்படாது, அதைத் தேர்ந்தெடுப்பது Hermes Desktop ஐ நிறுவும், கீழே உள்ள _Desktop apps_ விளக்குவது போல.

### ஏஜென்ட்களை நிறுவுதல் மற்றும் புதுப்பித்தல்

Hermes ஐத் தவிர, இந்த ஏஜென்ட்கள் mise இன் சோம்பேறி நிறுவலைப் பயன்படுத்துகின்றன: முதல் தொடக்கம் CLI ஐ நிறுவுகிறது, பின்னர் வரும் தொடக்கங்கள் அதையே மீண்டும் பயன்படுத்துகின்றன. mise ஒரு நிறுவப்பட்ட ஏஜென்டில் புதிய வெளியீடு உள்ளதா என்பதை அதிகபட்சம் நான்கு மணிநேரத்திற்கு ஒருமுறை, அது தொடங்குவதற்கு சற்று முன்பு அல்லது ஷெல் ப்ராம்ப்டில் பின்னணியில் சரிபார்க்கிறது. அந்தப் புதுப்பிப்பு தோல்வியடைந்தால் அல்லது நீங்கள் ஆஃப்லைனில் இருந்தால், நிறுவப்பட்ட பதிப்பு இயங்கும். `omarchy update` Omarchy இன் மற்றவற்றுடன் நிறுவப்பட்ட ஏஜென்ட்களையும் புதுப்பிக்கிறது, மேலும் `mup` mise நிர்வகிக்கும் கருவிகளை மட்டும் புதுப்பிக்கிறது.

`claude update`, `codex update`, அல்லது ஒரு பயன்பாட்டில் உள்ள புதுப்பிப்பு பொத்தான் போன்ற ஒரு ஏஜென்டின் சொந்தப் புதுப்பிப்பான், mise நிர்வகிக்கும் நிறுவலைப் புதுப்பிக்காது. `codex update` தோல்வியடையும், மேலும் `claude update` வெற்றி என்று அறிவித்துக்கொண்டே mise கண்காணிக்காத தனி நகலை நிறுவக்கூடும். நீங்கள் ஒரு ஏஜென்டின் சொந்த நிறுவி மற்றும் புதுப்பிப்பானையே பயன்படுத்த விரும்பினால், அதை `disable_tools` இல் சேர்க்கவும்; [முன்பே நிறுவப்பட்ட CLI கருவிகள்](18-development-tools.md#preinstalled-cli-tools) ஐப் பார்க்கவும்.

உங்களுக்குத் தேவைப்படுவதற்கு முன்பே கட்டமைக்கப்பட்ட அனைத்து சோம்பேறி கருவிகளையும் நிறுவ, `mise install --include-lazy` ஐ இயக்கவும். இதில் ஏஜென்ட்களுடன் Omarchy இன் மற்ற இயல்புநிலை CLI கருவிகளும் அடங்கும். ஒரு ஒற்றைக் கருவியை நிறுவுவது அல்லது உங்கள் சொந்த நிறுவலைப் பயன்படுத்துவது பற்றி [முன்பே நிறுவப்பட்ட CLI கருவிகள்](18-development-tools.md#preinstalled-cli-tools) ஐப் பார்க்கவும்.

`grok` mise இன் முதல்-தரப்பு `grok` தொகுப்பின் மூலம் நிறுவப்படுகிறது, `claude` மற்றும் `codex` போலவே அதே வழியில். `grok` ஐ இயக்கவும், அல்லது _Agent > Harness_ இன் கீழ் அதைத் தேர்ந்தெடுக்கவும். x.ai இல் உள்ள `curl | bash` நிறுவியைத் தவிர்க்கவும். அந்தப் பாதை இரண்டாவது நகலை `~/.grok/bin` இல் வைக்கிறது, அதை `PATH` இல் முன்னால் சேர்க்கிறது, மேலும் Omarchy இன் ரேப்பரை மேலெழுதுகிறது.

`dsh` அதன் உலாவி UI ஐ `127.0.0.1:3080` இல் திறக்கிறது, தொடக்க அடைவை அதன் இயல்புநிலை பணியிடமாகக் கொண்டு. அதன் உலாவி UI தொடக்க ப்ராம்ப்டை ஏற்காது, எனவே `omarchy agent prompt` அதை உங்கள் கிளிப்போர்டில் ஒட்டுவதற்கான ப்ராம்ப்டுடன் திறக்கிறது. Omarchy அதை DeepSeek இன் ஒப்புதல்-இல்லா அனுமதி முன்னமைவுடன் தொடங்குகிறது. நீங்கள் அதன் அதிகாரப்பூர்வ மாடல் API ஐப் பயன்படுத்தும்போது DeepSeek Harness அமர்வு பதிவுகளை DeepSeek க்கு பதிவேற்றுகிறது; அதன் உலாவி UI இல் _Settings > General > Upload Session Log_ இன் கீழ் அதை முடக்கவும். நீங்கள் அதற்கு அனுப்பும் கருத்தும் அமர்வுடன் சேர்த்து பதிவேற்றப்படுகிறது, நீங்கள் அதை `DSH_TELEMETRY_MODE=DISABLED` உடன் தொடங்கினால் தவிர.

### இயல்புநிலை ஏஜென்ட்

உங்கள் இயல்புநிலை ஏஜென்டை `omarchy default agent <name>` உடன் அல்லது Omarchy Menu இல் (`Super + Space`) _Agent > Harness_ இன் கீழ் தேர்ந்தெடுக்கவும். ஏஜென்ட் இன்னும் நிறுவப்படவில்லை என்றால், அதைத் தேர்ந்தெடுப்பது முதலில் அதை நிறுவும். புதிய Omarchy ஒருமுறை மட்டுமேயான அறிவிப்புடன் இந்தத் தேர்வைச் செய்ய உங்களை அழைக்கும்.

Claude ஐத் தேர்ந்தெடுப்பது Chromium, Chrome, Brave, Brave Origin, மற்றும் Edge க்கான அதன் உலாவி நீட்டிப்பை அமைக்கவும் முயற்சிக்கிறது. நீட்டிப்பு அமைப்பு அனைத்துப் பயனர்களுக்கும் பொருந்தும் மற்றும் உங்கள் கணினி கடவுச்சொல்லைக் கேட்கக்கூடும்; ரத்து செய்வது அல்லது தோல்வியுற்ற நீட்டிப்பு நிறுவல் இருந்தாலும் Claude தேர்ந்தெடுக்கப்பட்டு தொடங்கப்படும். உங்கள் உலாவியை மீண்டும் தொடங்கவும், கேட்டால் நீட்டிப்பை இயக்கவும், மேலும் அதை இணைப்பதை முடிக்க Claude இல் உள்நுழையவும். இணைப்பைச் சரிபார்க்க Claude இல் `/chrome` ஐ இயக்கவும். Firefox மற்றும் Zen இந்த நீட்டிப்பை ஆதரிக்காது. இந்த அமைப்பு சேர்க்கப்படுவதற்கு முன்பே Claude உங்கள் இயல்புநிலையாக இருந்திருந்தால், நீட்டிப்பை நிறுவ அதை மீண்டும் தேர்ந்தெடுக்கவும்.

நீங்கள் தேர்ந்தெடுத்த பிறகு, `Super + Shift + Ctrl + A` இயல்புநிலை ஏஜென்டை ஒரு பிரத்யேக டெர்மினல் சாளரத்தில் தொடங்குகிறது (அல்லது நீங்கள் இன்னும் தேர்ந்தெடுக்கவில்லை என்றால் தேர்வியைக் கொண்டுவருகிறது). நீங்கள் அதை `omarchy agent prompt "Review this project"` உடன் நேரடியாக ஒரு பணியில் தொடங்கவும் முடியும். Freebuff மற்றும் DeepSeek Harness தொடக்க ப்ராம்ப்டை ஏற்காது, எனவே அவை அதற்குப் பதிலாக உங்கள் கிளிப்போர்டில் ஒட்டுவதற்கான ப்ராம்ப்டுடன் திறக்கின்றன. இவ்வாறு தொடங்கப்படும் ஏஜென்ட்கள் அவற்றின் அந்தந்த நிறுத்தி-கேட்காத முறைகளில் கவனிக்கப்படாமல் இயங்குகின்றன, எனவே அவை உண்மையில் விஷயங்களைச் செய்யத் தயாராக இருங்கள்! MiniMax Code இன் ஊடாடும் அமர்வுகளுக்கு அத்தகைய முறை இல்லை, எனவே அது வழக்கம் போல் அனுமதிகளைக் கேட்கிறது. மேலும் ஏஜென்ட்கள் உங்கள் வீட்டு அடைவுக்கான நம்பிக்கையை நினைவில் வைக்க மறுப்பதால், `$HOME` இலிருந்து தொடங்குவது அதற்குப் பதிலாக `~/Work` இல் தொடங்குகிறது.

டெர்மினல் குறுக்குவழிகளும் உள்ளன: `a` தற்போதைய டெர்மினலில் இயல்புநிலை ஏஜென்டை இன்லைனில் இயக்குகிறது, அதே நேரத்தில் `c`, `cx`, மற்றும் `cy` OpenCode, Claude Code, மற்றும் Codex ஐ நேரடியாகத் தொடங்குகின்றன (மீண்டும் அவற்றின் தானியங்கு-ஒப்புதல் முறைகளில்). தீம் மாற்றங்களும் ஏஜென்ட்களுக்கு ஒத்திசைகின்றன: நீங்கள் Omarchy தீமை மாற்றும்போது Claude Code, Pi, OpenCode, மற்றும் Hermes (Omarchy அதை நிறுவிய பிறகு) அனைத்தும் பின்தொடர்கின்றன.

### உங்கள் ஏஜென்ட் வழிமுறைகள்

ஒவ்வொரு ஏஜென்டுக்குமான தனிப்பட்ட விதிகள் `~/.agents/AGENTS.md` இல், `~/.agents/skills` இல் உள்ள பகிரப்பட்ட திறன்களுக்கு அருகில் செல்கின்றன. அதை _Agent > Instructions_ இன் கீழ் திறக்கவும், இது அதைத் தன் சொந்த உலகளாவிய கோப்பை வைத்திருக்கும் ஒவ்வொரு ஹார்னஸிலும் இணைக்கிறது: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, Copilot இன் `~/.copilot/copilot-instructions.md`, மற்றும் பல. Crush மற்றும் Amp `~/.config/AGENTS.md` இணைப்பைப் படிக்கின்றன, அதே நேரத்தில் omp, Kimi, மற்றும் DeepSeek Harness `~/.agents/AGENTS.md` ஐ நேரடியாகப் படிக்கின்றன. இயல்புநிலை ஏஜென்டைத் தேர்ந்தெடுப்பதும் அதை இணைக்கிறது. நீங்கள் ஏற்கனவே வைத்திருந்த வழிமுறைகள் கோப்பு, இன்னும் எதுவும் இல்லை என்றால் பகிரப்பட்ட ஒன்றாக மாறுகிறது; இல்லையெனில் அது இணைப்பிற்கு அருகில் `.bak` ஆக வைக்கப்படுகிறது. மற்றொரு ஏஜென்டை நிறுவிய பிறகு மீண்டும் இணைக்க `omarchy agent instructions` ஐ இயக்கவும்.

### ஏஜென்ட்கள் பேனல்

மேல் பட்டியில் ஏஜென்ட்கள் ஐகான் உள்ளது. நீங்கள் ஒரு ஏஜென்டை அமைப்பதற்கு முன்பு, அதன் பேனல் Claude, Codex, அல்லது Grok இல் உள்நுழைவதன் மூலம் உங்களை வழிநடத்துகிறது, மேலும் முதலாவது உங்கள் இயல்புநிலை ஏஜென்டாக மாறுகிறது. அதன் பிறகு, பேனல் ஒவ்வொரு சந்தாவையும் ஒரே பக்கத்தில் வைக்கிறது: ஒவ்வொரு ஏஜென்ட் மற்றும் கணக்கு அதன் திட்டத்துடன், அதன் 5-மணிநேர அமர்வு மற்றும் வாராந்திர வரம்புகள் ஒவ்வொன்றுக்கும் அது மீட்டமைக்கப்படும் வரையிலான நேரத்துடன் ஒரு மீட்டர் (சரியான சதவீதத்திற்கு மேலே வைக்கவும்), அல்லது மீதமுள்ள முன்கூட்டியே செலுத்தப்பட்ட இருப்பு, நீங்கள் அனைத்திலும் பயன்படுத்தியதைச் சுழற்றும் ஒரு வரியின் கீழ், இந்த வார டோக்கன்கள் மற்றும் உங்கள் அதிகம் பயன்படுத்தப்பட்ட மாடல் போன்றவை. _Make something_ இன் கீழ் அது புதிய தீம், செருகுநிரல், பயன்பாடு, அல்லது விளையாட்டுக்கான தொடக்க ப்ராம்ப்டுகளை வழங்குகிறது, அவை பணியை உங்கள் இயல்புநிலை ஏஜென்டிடம் ஒப்படைக்கின்றன. பயன்பாடுகள் Omarchy இன் சொந்த Hype, Monologue, மற்றும் Omacut கட்டமைக்கப்பட்ட விதத்தில், C++ மற்றும் Qt Quick இல், omarchy-make-app ஏஜென்ட் திறனைப் பின்பற்றி கட்டமைக்கப்படுகின்றன, மேலும் அவற்றுக்குத் தேவையான கம்பைலர் மற்றும் Qt துண்டுகள் நிறுவப்பட்டு வருகின்றன. விளையாட்டுகள் `~/Games/vibes` இல் ஒரு ஒற்றை three.js பக்கம், omarchy-make-game ஏஜென்ட் திறனைப் பின்பற்றுகின்றன, மேலும் அனைத்தும் தற்போதைய தீமில் ஒரு Game Vibes லான்சரிலிருந்து திறக்கின்றன; அவை three.js ஐ வலையிலிருந்து ஏற்றுகின்றன, எனவே அவை தொடங்க ஒரு இணைப்பு தேவை. Claude Code, Codex, Grok, Kimi, Cursor மற்றும் அதன் Grok Bot ஒதுக்கீடு, GitHub Copilot, Muse, Antigravity, Kimchi, மற்றும் Devin அவற்றின் வரம்புகளுடன் உடனடியாக உள்ளடக்கப்பட்டுள்ளன, மேலும் Hermes, Mistral Vibe, மற்றும் Qwen Code நீங்கள் அவற்றைப் பயன்படுத்திய பிறகு அவற்றின் அமர்வுகள் மற்றும் டோக்கன்களைக் காட்டுகின்றன. pi, omp, அல்லது opencode மூலம் நீங்கள் பயன்படுத்தும் வழங்குநர் திட்டங்கள் மற்றும் விசைகளும் தோன்றுகின்றன: OpenCode Zen மற்றும் Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan, மற்றும் Synthetic அவற்றின் வரம்புகளுடன்; Fireworks, OpenRouter, மற்றும் DeepSeek அவற்றின் முன்கூட்டியே செலுத்தப்பட்ட இருப்புகளுடன்; மேலும் Local models இன் கீழ் உங்கள் சொந்த வன்பொருளில் நீங்கள் இயக்கும் மாடல்கள். ஒவ்வொரு ஏஜென்டும் ஒருமுறை மட்டுமே கணக்கிடப்படுகிறது, அதற்கு யார் கட்டணம் வசூலிக்கிறார்களோ அவரின் கீழ், நீங்கள் அதை எத்தனை ஹார்னஸ்கள் மூலம் இயக்கினாலும்.

பேனலுக்கு பட்டி ஐகானை இடது-கிளிக் செய்யவும், உங்கள் இயல்புநிலை ஏஜென்டைத் தொடங்க வலது-கிளிக் செய்யவும். அதன் பின்னால் உள்ள பயன்பாட்டுப் பதிவுகள் ஒவ்வொரு 15 நிமிடங்களுக்கும் `omarchy agent usage-update` மூலம் மீண்டும் உருவாக்கப்படுகின்றன, மேலும் பேனல் ஒத்திசைக்கப்பட்ட கோப்புறை வழியாக உங்கள் மற்ற இயந்திரங்களிலிருந்து பயன்பாட்டை இணைக்கவும் முடியும். முழு அமைப்புகளுக்கு `$OMARCHY_PATH/shell/plugins/agents/` இன் கீழ் உள்ள README ஐப் பார்க்கவும்.

### பல சந்தாக்கள்

நீங்கள் ஒன்றுக்கும் மேற்பட்ட Claude, Codex, அல்லது Grok திட்டத்திற்கு பணம் செலுத்தினால் — தனிப்பட்ட Max மற்றும் வேலை ஒன்று என்று சொல்லலாம் — Omarchy அவை அனைத்தையும் உள்நுழைந்த நிலையில் வைத்து அவற்றுக்கு இடையில் நகர முடியும். ஏஜென்ட்கள் பேனலில் + உடன் ஒரு சந்தாவைச் சேர்க்கவும், அது அங்கேயே உங்களை அதன் மூலம் வழிநடத்துகிறது, அல்லது `omarchy agent account add claude Work` உடன் (அல்லது `codex`, அல்லது `grok`). அது இல்லை என்றால் CLI ஐ நிறுவுகிறது. ஒரு வழங்குநருக்கான முதல் கணக்கு உங்கள் சாதாரண உலாவி மூலம் உள்நுழைகிறது, CLI எப்போதும் பார்க்கும் இடத்திலேயே. அதன் பிறகு ஒவ்வொன்றும் ஒரு தனிப்பட்ட சாளரம் மூலம் உள்நுழைகிறது, எனவே உங்கள் உலாவி ஏற்கனவே உள்நுழைந்துள்ள கணக்கு தவறுதலாக எடுக்கப்படாது; நீங்கள் சேர்க்கும் கணக்காக அங்கே உள்நுழையவும், மேலும் நீங்கள் ஏற்கனவே திறந்து வைத்திருந்த எந்த தனிப்பட்ட சாளரத்தையும் முதலில் மூடவும். இதைச் செய்ய CLI இலிருந்து ஒருபோதும் வெளியேற வேண்டாம்: வெளியேறுவது சேமிக்கப்பட்ட உள்நுழைவை ரத்து செய்கிறது, மேலும் அந்தக் கணக்கு மீண்டும் சேர்க்கப்பட வேண்டும்.

உங்கள் சந்தா உள்நுழைவுகளை SSH வழியாக மற்றொரு Omarchy இயந்திரத்திற்கு நகலெடுக்க, `omarchy agent account copy user@laptop` ஐ இயக்கவும். இலக்கில் ஒன்று நிறுவப்படவில்லை என்றால் அனுப்புநர் தற்காலிக பெறுநரை வழங்குகிறார், எனவே பழைய Omarchy இயந்திரங்கள் புதுப்பிப்பு இல்லாமல் கணக்குகளைப் பெற முடியும். நிறுவப்பட்ட பெறுநர்கள் முன்னுரிமை பெறுகின்றனர். இது அனைத்து Claude, Codex, மற்றும் Grok சந்தாக்களையும் நகலெடுக்கிறது; அவற்றைத் தேர்ந்தெடுக்க வழங்குநர் பெயர்களைச் சேர்க்கவும், `omarchy agent account copy laptop claude` இல் உள்ளது போல. கணக்குப் பெயர்கள் மற்றும் கட்டளை IDகள் மூலத்துடன் பொருந்துகின்றன, இலக்கில் ஏற்கனவே உள்ள கணக்குகள் உட்பட. தொடர்பில்லாத இலக்குக் கணக்குகளின் பெயர்கள் முரண்பட்டால் எண் பின்னொட்டைப் பெறுகின்றன, மேலும் அமைப்புகள், திறன்கள், செருகுநிரல்கள், மற்றும் உரையாடல் வரலாறு ஒவ்வொரு இயந்திரத்திற்கும் உள்ளூராகவே இருக்கும்.

ஏற்கனவே உள்ள இலக்குச் சான்றுகள் வைக்கப்படுகின்றன. அங்கே ஏற்கனவே உள்நுழைந்துள்ள ஒரு மூலக் கணக்கின் பெயர் அதன் சான்றுகளை மாற்றாமல் ஒத்திசைக்கப்படுகிறது; மற்ற கணக்குகள் அதற்கு அருகில் சேர்க்கப்படுகின்றன. பொருந்தும் கணக்குகளுக்கான சேமிக்கப்பட்ட சான்றுகளை மாற்ற, இலக்கில் அந்தக் கணக்கின் அமர்வுகளை விட்டு வெளியேறிய பிறகு `omarchy agent account copy --replace laptop claude` ஐப் பயன்படுத்தவும். புதிய இலக்கு மூலத்தின் செயலில் உள்ள கணக்கு மற்றும் மாற்றும் விருப்பங்களையும் பெறுகிறது; நிறுவப்பட்ட இலக்கு தன் சொந்தத்தை வைத்திருக்கிறது.

சான்றுகள் SSH வழியாகப் பயணித்து இலக்கில் தனிப்பட்ட கோப்புகளில் சேமிக்கப்படுகின்றன, எனவே நீங்கள் நம்பும் இயந்திரங்களுக்கு மட்டுமே நகலெடுக்கவும். இது ஒருமுறை நகல், தொடர்ந்து ஒத்திசைத்தல் அல்ல. Codex புதுப்பிப்பு டோக்கன்கள் மற்றொரு இயந்திரத்தால் சுழற்றப்படலாம், நகலெடுக்கப்பட்ட உள்நுழைவு புதுப்பிக்கப்பட வேண்டிய நிலையில் இருக்கும்; பல இயந்திரங்களில் ஒரே நேரத்தில் பயன்படுத்த தனித்தனி உள்நுழைவுகள் மிகவும் நம்பகமான தேர்வாக இருக்கின்றன. [Codex இன் கணக்கு அங்கீகார வழிகாட்டுதல்](https://developers.openai.com/codex/auth/ci-cd-auth) ஐப் பார்க்கவும்.

ஒரு வழங்குநருக்கு ஒரு கணக்கு செயலில் உள்ளது, மேலும் ஒவ்வொரு புதிய அமர்வும் அதுவாகவே தொடங்குகிறது: `cx`, `cy`, ஒரு எளிய `claude`, `codex`, அல்லது `grok`, `omarchy agent` மூலம் தொடங்கப்படும் எதுவும், மேலும் `PATH` இல் CLI ஐக் கண்டறியும் ஸ்கிரிப்டுகள் அல்லது எடிட்டர்கள். `omarchy agent account use work` உடன் மாற்றவும் (மேலும் `omarchy agent account use main` உடன் திரும்பவும்), அல்லது பேனலில் ஒரு கணக்கின் எண்ணை அழுத்தி பின்னர் `Enter` ஐ அழுத்துவதன் மூலம் (அல்லது அதன் Use பொத்தானைக் கிளிக் செய்வதன் மூலம்). இயங்கும் Claude அமர்வுகளும் மாறுகின்றன, அவற்றின் அடுத்த செய்தியிலிருந்து: ஒவ்வொரு Claude அமர்வும் `~/.claude` இல் இயங்குகிறது, இது எப்போதும் செயலில் உள்ள கணக்கின் உள்நுழைவை வைத்திருக்கிறது. பழைய Omarchy மூலம் கணக்கின் சொந்த கோப்புறையில் தொடங்கப்பட்ட Claude அமர்வு அது வெளியேறும் வரை அந்த உள்நுழைவை வைத்திருக்கிறது, எனவே மாற்றம் அந்த அமர்வுகளைப் பெயரிட்டு அவை போனவுடன் தானாகவே முடிவடைகிறது. இயங்கும் Codex மற்றும் Grok அமர்வுகள் அவை தொடங்கிய கணக்கிலேயே இருக்கின்றன. உரையாடல் வரலாறு, அமைப்புகள், திறன்கள், மற்றும் செருகுநிரல்கள் கணக்குகள் முழுவதும் பகிரப்படுகின்றன, எனவே அதே கோப்புறையில் `claude --continue` நீங்கள் புதிய கணக்கில் விட்ட இடத்திலிருந்து தொடர்கிறது.

ஒன்றுக்கும் மேற்பட்ட கணக்குகளுடன், பேனல் ஒவ்வொரு கணக்கின் வரம்புகளையும் அருகருகே காட்டுகிறது, செயலில் உள்ளது குறிக்கப்பட்டிருக்கும். இயல்பாக Omarchy செயலில் உள்ள கணக்கு ஒரு வரம்பின் 95% ஐக் கடக்கும்போது உங்களுக்கு அறிவிக்கிறது, மேலும் அறிவிப்பைக் கிளிக் செய்வது அதிக இடவசதி உள்ள கணக்கிற்கு மாறுகிறது. பேனலில் ஒரு கணக்கின் வரியின் மீது வைத்து Use க்கு அருகில் தோன்றும் Autoswitch ஐக் கிளிக் செய்யவும் (அல்லது `m` ஐ அழுத்தவும்), அல்லது அது தானாகவே மாற `omarchy agent account mode auto` ஐ இயக்கவும்; அது இயக்கத்தில் இருக்கும்போது, Autoswitch Use இன் இடத்தைப் பிடிக்கிறது, மேலும் அதை மீண்டும் கிளிக் செய்வது அறிவிப்பதற்குத் திரும்புகிறது. வாசலை மாற்ற ஒரு எண்ணைச் சேர்க்கவும், `omarchy agent account mode auto 90` இல் உள்ளது போல. ஒவ்வொரு கணக்கும் வாசலுக்கு மேல் இருந்தால், எந்தக் கணக்கு முதலில் விடுபடுகிறது என்பதுடன் ஒருமுறை அதைப் பற்றி கேட்பீர்கள். செயலில் உள்ள கணக்கு அதன் வாசலுக்கு 15 புள்ளிகளுக்குள் இருக்கும்போது (இயல்புநிலையில் 80%), அதன் வரம்புகள் ஒவ்வொரு 15 க்கும் பதிலாக ஒவ்வொரு மூன்று நிமிடங்களுக்கும் சரிபார்க்கப்படுகின்றன.

`omarchy agent account list` ஒவ்வொரு கணக்கையும் அதன் சமீபத்திய வரம்புகளையும் காட்டுகிறது, `omarchy agent account remove work` ஒன்றை மறக்கிறது, மேலும் `omarchy agent account rename primary Hey` ஒன்றை மறுபெயரிடுகிறது (அல்லது பேனலில் ஒரு கணக்கின் பெயரைக் கிளிக் செய்யவும்). இந்தக் கட்டளைகள் உங்கள் இயல்புநிலை ஏஜென்டின் கணக்குகளில் வேலை செய்கின்றன; மற்ற வழங்குநரை அடைய, முதலில் அதைப் பெயரிடவும், `omarchy agent account use codex side` இல் உள்ளது போல. நீங்கள் ஏற்கனவே `~/.claude` அல்லது `~/.codex` இல் வைத்திருந்த உள்நுழைவு _Main_ கணக்கு ஆகும். Codex இனது அது இருக்கும் இடத்திலேயே இருக்கிறது; Claude இனது மற்றொரு கணக்கு செயலில் இருக்கும்போது அதன் சொந்த கோப்புறையில் காத்திருக்கிறது. சுமார் எட்டு மணிநேரத்திற்கும் மேலாகப் பயன்படுத்தப்படாமல் விடப்பட்ட கணக்கு _Sign-in required_ ஐக் காட்டக்கூடும்; பேனலிலேயே அந்தக் கணக்கில் மீண்டும் உள்நுழைய அதைக் கிளிக் செய்யவும், அல்லது அதற்கு மாறி ஒரு அமர்வைத் தொடங்கவும், இது உள்நுழைவைத் தானாகவே புதுப்பிக்கிறது. நீங்கள் `claude mcp add` உடன் சேர்க்கும் MCP சர்வர்கள் ஒவ்வொரு Claude கணக்கையும் அடைகின்றன, ஏனெனில் அவை அனைத்தும் `~/.claude` இல் இயங்குகின்றன; Codex மற்றும் Grok க்கு, ஒரு கணக்கு சேர்க்கப்பட்டபோது நீங்கள் வைத்திருந்த சர்வர்கள் அதனுடன் வருகின்றன, ஆனால் பின்னர் வந்தவை நீங்கள் அவற்றைச் சேர்த்த கணக்கை மட்டுமே அடைகின்றன. Claude Desktop தன் சொந்த உள்நுழைவை வைத்திருக்கிறது, மேலும் CLI பைனரிக்கான முழுமையான பாதையுடன் கட்டமைக்கப்பட்ட Codex அல்லது Grok கருவிகள் மாற்றத்தைப் பின்பற்றாது. வெளிப்படையான `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, அல்லது `GROK_HOME` தேர்ந்தெடுக்கப்பட்ட கணக்கை விட முன்னுரிமை பெறுகிறது.

### செயலிழப்பு கண்டறிதல்

Omarchy செயல்முறை செயலிழப்புகளுக்கு systemd-coredump ஐக் கண்காணிக்கிறது. ஏதாவது segfault ஆகும்போது, உங்களுக்கு "Process crashed" அறிவிப்பு கிடைக்கும் — அதைக் கிளிக் செய்யவும், மேலும் செயலிழப்பு உங்கள் இயல்புநிலை ஏஜென்டிடம் Omarchy இன் diagnose-crash திறனுடன் ஒப்படைக்கப்படுகிறது, இது கோர் டம்பிலிருந்து உண்மைகளை நிறுவுவதன் மூலமும் செயலிழப்பு மேல்நிலையில் புகாரளிக்கத் தகுதியானதா என்பதைத் தீர்மானிப்பதன் மூலமும் ஏஜென்டை வழிநடத்துகிறது. நீங்கள் அதை `coredumpctl list` இலிருந்து எந்த PID க்கும் எதிராக `omarchy agent crash <pid>` உடன் கையாலும் இயக்கலாம்.

கண்காணிப்பு இயல்பாக இயக்கத்தில் உள்ளது. அதை _Trigger > Toggle > Crash Capture_ இன் கீழ் (அல்லது `omarchy toggle crash-capture` உடன்) முடக்கவும், அறிவிப்புகள் நிற்கும்; `omarchy agent crash <pid>` இன்னும் கையால் வேலை செய்கிறது.

செயலிழப்புகளை ஒரு நிரலுக்கு ஒரு முறை அமைதிப்படுத்தவும் முடியும், இதைத்தான் கண்டறிதல் இறுதியில் உங்களுக்கு வழங்குகிறது. `omarchy crash mute hyprland` அந்த நிரலுக்கு மட்டுமே அறிவிப்புகளை நிறுத்துகிறது, `omarchy crash mute hyprland off` அவற்றைத் திரும்பக் கொண்டுவருகிறது, மேலும் `omarchy crash mute` தனியாக நீங்கள் அமைதிப்படுத்தியதைப் பட்டியலிடுகிறது. அது பைனரியின் பாதையை அதன் பெயரைப் போலவே மகிழ்ச்சியுடன் ஏற்கிறது, எனவே `omarchy crash mute /usr/bin/hyprland` அதையே செய்கிறது. அதில் இடைவெளி உள்ள பெயரை மேற்கோள் காட்டவும், `omarchy crash mute 'Some App'` இல் உள்ளது போல. மற்ற அனைத்தும் இன்னும் அறிவிக்கின்றன, மேலும் அமைதிப்படுத்தப்பட்ட நிரல் இன்னும் செயலிழக்கிறது — இது நினைவூட்டலை மறைக்கிறது, இது எதையும் சரிசெய்யாது.

### டெஸ்க்டாப் பயன்பாடுகள்

_Install > AI_ மெனு சில வரைகலை AI பயன்பாடுகளையும் கொண்டுள்ளது: Antigravity Desktop, ChatGPT டெஸ்க்டாப் பயன்பாடு, Claude டெஸ்க்டாப் பயன்பாடு (Anthropic இன் Linux beta, Chat, Cowork, மற்றும் Claude Code தாவல்களுடன்), xAI இன் மாடல்களுடன் அரட்டையடிக்க Grok Bot, Herdr Desktop, Hermes Desktop, OpenClaw, Perplexity டெஸ்க்டாப் பயன்பாடு, மற்றும் T3 Code. Grok Bot என்பது டெஸ்க்டாப் அரட்டை பயன்பாடு. கோடிங் ஏஜென்ட் என்பது `grok` கட்டளை.

Hermes Desktop என்பது தெரிந்து கொள்ள வேண்டிய ஒன்றாகும், ஏனெனில் ஒரு இயந்திரத்தில் ஒரு Hermes உள்ளது, மேலும் அது பயன்பாட்டினது: Hermes எப்போதும் பயன்பாட்டின் மூலம் மட்டுமே நிறுவப்படுகிறது, மேலும் இயல்புநிலை ஏஜென்ட் இயக்கும் `hermes` கட்டளை பயன்பாட்டினது. Hermes ஐ இயல்புநிலை ஏஜென்டாகத் தேர்ந்தெடுப்பது _Install > AI_ உள்ளீடு செய்வதையே நிறுவுகிறது: தொகுப்பு, மற்றும் Hermes இன் சொந்த நிறுவியால் அமைக்கப்பட்ட `~/.hermes` இன் கீழ் ஒரு Hermes இயக்கநேரம், இது முதல் முறை சில நிமிடங்கள் எடுக்கும். அந்த இயக்கநேரம் டெர்மினல் `hermes` கட்டளை, இயல்புநிலை ஏஜென்ட் மற்றும் பயன்பாடு அனைத்தும் பயன்படுத்தும் ஒரே Hermes ஆகும், மேலும் அது Omarchy வெளியீட்டிற்காகக் காத்திருப்பதற்குப் பதிலாக `hermes update` உடன் தன்னைப் புதுப்பிக்கிறது. அதை நிறுவுவது Hermes க்கு Omarchy தீமை `omarchy` என்று பெயரிடப்பட்ட தோலாகவும் வழங்குகிறது, இது நீங்கள் தீம்களை மாற்றும்போது ஒவ்வொரு Hermes மேற்பரப்பும் பின்பற்றுகிறது; நீங்கள் அது வேண்டாம் என்றால் Hermes இன் Appearance அமைப்புகளின் கீழ் அல்லது `/skin` உடன் மற்றொன்றைத் தேர்ந்தெடுக்கவும், மேலும் Omarchy அந்தத் தேர்வை அப்படியே விட்டுவிடுகிறது. _Remove > AI_ இன் கீழ் பயன்பாட்டை அகற்றுவது முதலில் Hermes ஐ மூடுகிறது, gateway உட்பட, அந்த இயக்கநேரத்தை அதனுடன் எடுத்துச் செல்கிறது, மேலும் நீங்கள் வேறுவிதமாகச் சொன்னால் தவிர உங்கள் அரட்டைகள், நினைவுகள், மற்றும் Hermes தனக்காக எழுதிய திறன்களை வைத்திருக்கிறது: அந்தத் தரவும் உங்கள் இணைப்பு அமைப்புகளும் போக வேண்டுமா என்று, இயல்பாக இல்லை என்று கேட்கிறது.

OpenClaw இன் டெஸ்க்டாப் அனுபவம் அதன் Control UI ஆகும், இது அதன் சொந்த உள்ளூர் gateway ஆல் ஆதரிக்கப்படும் வலைப் பயன்பாடாகத் திறக்கிறது. OpenClaw `~/.openclaw` இல் வாழ்கிறது மற்றும் தன்னைப் புதுப்பிக்கிறது: Control UI இன் "Update Gateway" பொத்தானைப் பயன்படுத்தவும் அல்லது `openclaw update` ஐ இயக்கவும், மேலும் gateway புதிய பதிப்பில் மீண்டும் தொடங்குகிறது. Omarchy புதிய நிறுவல் எந்த வெளியீட்டிலிருந்து தொடங்குகிறது என்பதை மட்டுமே தேர்ந்தெடுக்கிறது. _Remove > AI_ இன் கீழ் OpenClaw ஐ அகற்றுவது gateway சேவையையும் பயன்பாட்டையும் அதனுடன் எடுத்துச் சென்று, பின்னர் `~/.openclaw` உம் போக வேண்டுமா என்று கேட்கிறது, ஏனெனில் அது OpenClaw உடன் மற்றும் அது பதிவிறக்கும் செருகுநிரல் இயக்கநேரங்களுடன் உங்கள் அரட்டைகள் மற்றும் சான்றுகளை வைத்திருக்கிறது; இயல்புநிலை அதை வைத்திருக்கிறது, மேலும் OpenClaw ஐ மீண்டும் நிறுவுவது அதை மீண்டும் எடுத்துக்கொள்கிறது.

Herdr Desktop என்பது [Herdr](https://herdr.dev) டெஸ்க்டாப் பயன்பாடு: நீங்கள் சாளரத்தை மூடும்போது அதன் மையத்தில் தொடர்ந்து இயங்கும் டெர்மினல்கள் மற்றும் கோடிங் ஏஜென்ட்களின் இடங்கள், தாவல்கள், மற்றும் பேன்கள். அது ஒரு தொகுப்பிற்குப் பதிலாக Herdr இன் சொந்த நிறுவியிலிருந்து வருகிறது, எனவே அது `~/.local/share/herdr-app` இல் வாழ்கிறது, உங்களிடம் இன்னும் ஒன்று இல்லையென்றால் அதன் மையத்தை `~/.local/bin/herdr-core` இல் கொண்டுவருகிறது, மேலும் இரண்டையும் தானே புதுப்பிக்கிறது. அது Omarchy `Super + Ctrl + Return` இல் வழங்கும் `herdr` கட்டளையை மாற்றுவதற்குப் பதிலாக அதற்கு அருகில் அமர்கிறது, மேலும் அந்தக் கட்டளையின் நேரடி விசைகளைப் பெறுகிறது: `Alt + Return` மற்றும் `Alt + Shift + Return` ஒரு பேனை கீழே அல்லது வலதுபுறம் பிரிக்கின்றன, `Alt + Escape` அதை மூடுகிறது, `Ctrl + Alt + Arrow` பேன்களுக்கு இடையில் நகர்கிறது, `Alt + 1..9` மற்றும் `Alt + Left/Right` ஒரு தாவலைத் தேர்ந்தெடுக்கின்றன, மேலும் `Alt + Up/Down` இடங்களுக்கு இடையில் நகர்கின்றன. `Ctrl + 1..9` ஒரு இடத்தைத் தேர்ந்தெடுக்கிறது மற்றும் `Alt + Shift + Up/Down` ஏஜென்ட்கள் வழியாகப் படிப்படியாகச் செல்கிறது. `Ctrl + Space` முன்னொட்டு விசைகள் டெர்மினலுக்கு மட்டுமே இருக்கின்றன, ஏனெனில் பயன்பாடு ஒரு வரிசைக்கு எளிய Ctrl விசையை வைத்திருக்க முடியாது. Omarchy இவற்றை `~/.config/herdr-app/keys.json` இல் எழுதுகிறது, மேலும் `omarchy-refresh-herdr-app` அவற்றைத் திரும்ப வைக்கிறது. அதை நிறுவுவது Herdr இன் Omarchy தீமைத் தேர்ந்தெடுக்கிறது, இது அதன் பிறகு உங்கள் Omarchy தீமைப் பின்பற்றுகிறது. Herdr ஒளி முறைக்கு ஒரு தீமையும் இருண்ட முறைக்கு ஒரு தீமையும் வைத்திருக்கிறது, எனவே இருண்ட மற்றும் ஒளி Omarchy தீமுக்கு இடையில் மாறிய பிறகு, மற்ற முறைக்கு Herdr இன் தீம் தேர்வியில் Omarchy ஐ மீண்டும் ஒருமுறை தேர்ந்தெடுக்கவும்.

T3 Code அதன் அதிகாரப்பூர்வ AppImage வெளியீட்டிலிருந்து ஒரு தொகுப்பிற்குப் பதிலாக `~/.local/share/t3code` இல் இயங்குகிறது, எனவே அது தன்னைப் புதுப்பிக்கிறது. அதை நிறுவுவது Stable அல்லது Nightly சேனலில் தொடங்க வேண்டுமா என்று கேட்கிறது; பின்னர் T3 Code இன் அமைப்புகளில் மாற்றவும். உங்கள் நூல்கள் மற்றும் அமைப்புகள் `~/.t3` இல் வாழ்கின்றன, மேலும் _Remove > AI_ இன் கீழ் T3 Code ஐ அகற்றுவது அவற்றை அதனுடன் எடுத்துச் செல்கிறது.

### உள்ளூர் மாடல்கள்

உங்கள் கோடிங் ஏஜென்ட்களுக்கு உங்கள் சொந்த இயந்திரத்தில் ஒரு திறந்த மாடலை இயக்கவும். உங்கள் ப்ராம்ப்டுகளும் குறியீடும் இயந்திரத்தில் இருக்கும்; மாடலுக்கு அனுப்பப்படும் எதுவும் அதை விட்டு வெளியேறாது. இதனுடன் தொடங்கவும்:

```bash
omarchy agent local use best
```

அல்லது, மேல் பட்டியில் உள்ள ஏஜென்ட்கள் பேனலில், + ஐத் தேர்ந்தெடுத்து பின்னர் Local AI ஐத் தேர்ந்தெடுக்கவும், இது ஒரு மாடல் இந்த இயந்திரத்திற்குப் பொருந்தும்போது தோன்றும். முதல் முறை, இது மாடல்களை இயக்கும் Podman ஐ நிறுவுகிறது, மேலும் NVIDIA இயந்திரத்தில் அவற்றுக்கு GPU ஐ வழங்கும் NVIDIA இன் கொள்கலன் கருவித்தொகுப்பை நிறுவுகிறது. பின்னர் Omarchy இந்த இயந்திரத்திற்குப் பரிந்துரைக்கப்பட்ட மாடலைத் தேர்ந்தெடுத்து, அதைப் பதிவிறக்கி, தொடங்குகிறது. பத்துகள் GB பதிவிறக்கத்தையும் மாடல் இயங்கும்போது இயந்திரத்தின் நினைவகத்தின் பெரும்பகுதி பயன்பாட்டில் இருப்பதையும் எதிர்பார்க்கவும்: Flash Next அதன் முழு 256K சூழலுடன் சுமார் 100 GiB ஐப் பயன்படுத்துகிறது. மற்ற மாடல்கள் அதற்குத் தேவையான நினைவகத்தை வைத்திருந்தால், அது நிறுத்தப்பட்ட நிலையில் அமைக்கப்படுகிறது, நீங்கள் ஒன்றை நிறுத்தியவுடன் தொடங்கத் தயாராக இருக்கும். மாடல் வெளியேறும்போது நிற்கிறது; உங்களுக்கு வேறு எதற்காவது நினைவகம் தேவைப்படும்போது அதை நீங்களே நிறுத்தவும்.

`omarchy agent local list` விருப்பங்களைக் காட்டுகிறது மற்றும் சில ஏன் பொருந்தவில்லை என்பதை விளக்குகிறது. மற்றொன்றை அமைக்க, `omarchy agent local use <recipe>` ஐ இயக்கவும். இன்று, `qwen3.8-flash-next-gufo` மற்றும் `qwen3.8-27b-gufo` 128 GB Strix Halo இயந்திரங்களுக்குக் கிடைக்கின்றன; 27B சுமார் 40 GiB எடுக்கும், எனவே அது மற்ற வேலைகளுக்கு இடம் விடுகிறது. Intel இன் Arc B390 உடன் 64 GB மடிக்கணினியில், `qwen3.6-35b-a3b-llamacpp` சுமார் 30 GiB இல் இயங்குகிறது. புதிய சமையல் குறிப்புகளும் பரிந்துரைகளும் தொகுப்பின் மூலம் `omarchy update` உடன் வருகின்றன.

நீங்கள் அமைக்கும் ஒவ்வொரு மாடலும் உங்கள் சந்தாக்களுக்கு அருகில் ஏஜென்ட்கள் பேனலில் அதன் சொந்த வரியைப் பெறுகிறது: அதைத் தொடங்க இயக்கவும், அதை நிறுத்தி அதன் நினைவகத்தை விடுவிக்க இடைநிறுத்தவும், மேலும் அதில் உங்கள் ஏஜென்டைத் திறக்க டெர்மினல் பொத்தான். அவை நினைவகத்தில் ஒன்றாகப் பொருந்தும்போது பல ஒரே நேரத்தில் இயங்க முடியும்; ஒன்று பொருந்தவில்லை என்றால், எந்த இயங்கும் மாடலை நிறுத்த வேண்டும் என்று Omarchy சொல்கிறது. அவற்றை மறுவரிசைப்படுத்த வரிகளை இழுக்கவும், மேலும் ஒரு மாடலையும் அதன் பதிவிறக்கத்தையும் அகற்ற தேர்ந்தெடுக்கப்பட்ட வரியில் Delete ஐ அழுத்தவும்.

நீங்கள் அமைக்கும் ஒவ்வொரு மாடலும் பயன்பாட்டு லான்சரில் அதன் சொந்த உள்ளீட்டையும் பெறுகிறது, மாடலின் பெயரின் கீழ் மற்றும் அதன் தயாரிப்பாளரின் லோகோவுடன், Claude, Codex அல்லது Grok இல் உள்நுழைவது ஒன்றைச் சேர்ப்பது போல. அது அந்த மாடலில் உங்கள் ஏஜென்டைத் திறக்கிறது, மேலும் அது இயங்கவில்லை என்றால் முதலில் மாடலைத் தொடங்குகிறது: டெர்மினல் அது ஏற்றுவதைக் காட்டி அது தயாரானவுடன் ஏஜென்டிடம் ஒப்படைக்கிறது. ஒரு மாடலை அகற்றுவது அதன் உள்ளீட்டை அகற்றுகிறது.

ஒரு மாடல் அது அமைக்கப்பட்ட விதத்திலேயே தொடர்ந்து இயங்குகிறது, எனவே Omarchy புதுப்பிப்பு உங்கள் ஏஜென்ட்களின் கீழ் ஒன்றை ஒருபோதும் மீண்டும் தொடங்காது. நீங்கள் அமைத்துள்ள மாடலுக்கு Omarchy இல் புதிய இயக்கநேரம் அல்லது புதிய எடைகள் இருக்கும்போது, அதன் வரி புதுப்பிப்பு பொத்தானைக் காட்டுகிறது: அதை அழுத்தவும், மாடல் பின்னணியில் மீண்டும் அமைக்கப்படுகிறது, மாறியதை மட்டும் பதிவிறக்குகிறது, மேலும் புதிய பதிப்பில் மீண்டும் தொடங்குகிறது. நிறுத்தப்பட்ட மாடல் நிறுத்தப்பட்டே இருக்கும். `omarchy agent local update` டெர்மினலிலிருந்து ஒவ்வொரு மாடலுக்கும் அதையே செய்கிறது.

கட்டளை வரியிலிருந்து, `omarchy agent local start <recipe>` மற்றும் `omarchy agent local stop <recipe>` அதையே செய்கின்றன, `omarchy agent local status` ஒவ்வொரு மாடலையும் காட்டுகிறது, மேலும் `omarchy agent --local` நீங்கள் கடைசியாகத் தொடங்கிய மாடலில் உங்கள் இயல்புநிலை ஏஜென்டைத் திறக்கிறது. pi, OpenCode மற்றும் Qwen Code ஒன்றைப் பயன்படுத்தலாம்; வேறு எந்த இயல்புநிலையுடனும் அது pi இல் திறக்கிறது. pi நீங்கள் அமைத்துள்ள ஒவ்வொரு மாடலையும், மேலும் நீங்கள் இணைத்துள்ள இயந்திரங்களில் உள்ளவற்றையும், அதன் சொந்த மாடல் தேர்வியில் பட்டியலிடுகிறது, எனவே எளிய `pi` அவற்றையும் அடைகிறது. எந்த OpenAI-இணக்கமான கிளையண்டும் இணைக்க முடியும்: `status` ஒவ்வொரு மாடலின் முகவரியையும் காட்டுகிறது (முதலாவது `http://127.0.0.1:11435/v1`), சமையல் குறிப்பு பெயர் மாடல் ஆகும், மேலும் விசை `~/.config/omarchy/agent-local/key` இல் உள்ளது.

`omarchy agent local remove <recipe>` ஒரு மாடலையும் வேறு எந்த மாடலும் பயன்படுத்தாத பதிவிறக்கங்களையும் நீக்குகிறது.

மூன்றாம் தரப்பு இயக்கநேரங்கள் அவற்றின் வெளியீட்டாளருடன் குறிக்கப்படுகின்றன. Omarchy ஒவ்வொரு மாடலையும் பிணைய அணுகல் இல்லாமல் இயக்குகிறது.

### உள்ளூர் LLMகள்

Omarchy உள்ளூர் LLM மாடல்களை இயக்க இரண்டு வழிகளைப் பரிந்துரைக்கிறது: LM Studio மற்றும் Ollama. LM Studio திறந்த-எடை மாடல்களைக் கண்டறிவதற்கும், அவற்றை நிறுவுவதற்கும், இயக்குவதற்கும் GUI இடைமுகத்தை வழங்குகிறது. எளிதாகத் தொடங்க இது ஒரு சிறந்த வழி. Ollama அதேபோல் செய்ய CLI ஐ வழங்குகிறது. ஆனால் நீங்கள் உள்ளூர் மாடல்களுக்குப் புதியவராக இருந்தால், நான் LM Studio உடன் தொடங்குவேன். Omarchy Menu இல் _Install > AI_ இன் கீழ் நீங்கள் இரண்டில் ஒன்றையும் நிறுவலாம்.

### Omarchy Skill

ஏஜென்ட் திறன்கள் AI குறிப்பிட்ட கருவிகளைக் குறிப்பிட்ட வழியில் பயன்படுத்த உதவுகின்றன, மேலும் Omarchy கணினியைத் தனிப்பயனாக்க இயல்புநிலை திறனுடன் வருகிறது. உங்கள் Hyprland config ஐ மாற்றியமைப்பது, பட்டியைச் சரிசெய்வது, அல்லது புதிதாக ஒரு புதிய தீமை உருவாக்குவது போல. இது Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` மற்றும் ஒவ்வொரு `~/.hermes/profiles/*/skills`), மற்றும் பொதுவான `~/.agents/skills` இருப்பிடத்திற்கான திறன் அடைவுகளில் சிம்லிங்க் செய்யப்பட்டுள்ளது, எனவே பெரும்பாலான ஹார்னஸ்கள் அதைத் தானாகவே எடுத்துக்கொள்கின்றன.

ஆனால் நீங்கள் இந்தத் திறனைப் பரிசோதனையாகக் கருத வேண்டும். வெவ்வேறு மாடல்கள் அதை வெவ்வேறு விளைவுகளுக்குப் பயன்படுத்தும். முதலில் திட்ட முறையில் இயக்குவது சிறந்தது, எனவே ஏஜென்ட் எதை மாற்ற விரும்புகிறது என்பது பற்றி உங்களுக்கு ஒரு யோசனை இருக்கும். மேலும் ஏஜென்ட் எல்லாவற்றையும் குழப்பினால், மாற்றங்களைத் திரும்பப் பெற அல்லது `omarchy reinstall configs` ஐக் கூட அழைக்கத் தயாராக இருங்கள்.
