### Agent-களை நிறுவுதலும் புதுப்பித்தலும்

Hermes-ஐத் தவிர, இந்த agent-கள் mise-இன் lazy installation-ஐப் பயன்படுத்துகின்றன: முதல் தொடக்கம் CLI-ஐ நிறுவும், பிந்தைய தொடக்கங்கள் அதையே மீண்டும் பயன்படுத்தும். தொடங்குவதற்குச் சற்று முன்பு அல்லது shell prompt-இல் பின்னணியில், அதிகபட்சம் நான்கு மணி நேரத்திற்கு ஒருமுறை, நிறுவப்பட்ட agent-க்கு புதிய வெளியீடு உள்ளதா என mise சரிபார்க்கிறது. அந்தப் புதுப்பிப்பு தோல்வியடைந்தாலோ நீங்கள் offline-இல் இருந்தாலோ, நிறுவப்பட்ட பதிப்பு இயங்கும். `omarchy update` நிறுவப்பட்ட agent-களை Omarchy-இன் மற்ற பகுதிகளுடன் புதுப்பிக்கிறது, மேலும் `mup` mise-நிர்வகிக்கும் கருவிகளை மட்டும் புதுப்பிக்கிறது.

`claude update`, `codex update`, அல்லது ஒரு app-இல் உள்ள update பொத்தான் போன்ற agent-இன் சொந்த updater, mise-நிர்வகிக்கும் நிறுவலைப் புதுப்பிக்காது. `codex update` தோல்வியடையும், மேலும் `claude update` வெற்றி என அறிவித்து, mise கண்காணிக்காத தனி நகலை நிறுவ கூடும். அதற்குப் பதிலாக agent-இன் native installer-ஐயும் updater-ஐயும் பயன்படுத்த விரும்பினால், அதை `disable_tools`-இல் சேர்க்கவும்; [முன்பே நிறுவப்பட்ட CLI கருவிகள்](18-development-tools.md#preinstalled-cli-tools) பார்க்கவும்.

உள்ளமைக்கப்பட்ட அனைத்து lazy கருவிகளையும் உங்களுக்குத் தேவைப்படுவதற்கு முன்பே நிறுவ, `mise install --include-lazy` இயக்கவும். இதில் agent-களுடன் Omarchy-இன் மற்ற இயல்புநிலை CLI கருவிகளும் அடங்கும். ஒரு தனிக் கருவியை நிறுவ அல்லது உங்கள் சொந்த நிறுவலைப் பயன்படுத்த [முன்பே நிறுவப்பட்ட CLI கருவிகள்](18-development-tools.md#preinstalled-cli-tools) பார்க்கவும்.

`grok`, `claude` மற்றும் `codex` போன்றே mise-இன் first-party `grok` package மூலம் நிறுவப்படுகிறது. `grok` இயக்கவும், அல்லது _Setup > Defaults > Agent_-இன் கீழ் அதைத் தேர்ந்தெடுக்கவும். x.ai-இல் உள்ள `curl | bash` installer-ஐத் தவிர்க்கவும். அந்த வழி இரண்டாவது நகலை `~/.grok/bin`-இல் வைக்கிறது, அதை `PATH`-இல் முன்னால் சேர்க்கிறது, மேலும் Omarchy-இன் wrapper-ஐ மேலெழுதுகிறது.

`dsh` அதன் browser UI-ஐ `127.0.0.1:3080`-இல் திறக்கிறது, தொடக்க directory-ஐ அதன் இயல்புநிலை workspace ஆகக் கொண்டு. அதன் browser UI தொடக்க prompt எதையும் எடுக்காது, எனவே `omarchy agent prompt` அதை prompt உங்கள் clipboard-இல் ஒட்டுவதற்காக வைத்துத் திறக்கிறது. Omarchy அதை DeepSeek-இன் no-approval permission preset-உடன் தொடங்குகிறது. நீங்கள் அதன் official model API-ஐப் பயன்படுத்தும்போது DeepSeek Harness session log-களை DeepSeek-க்கு பதிவேற்றுகிறது; அதன் browser UI-இல் _Settings > General > Upload Session Log_-இன் கீழ் அதை அணைக்கவும். நீங்கள் அதற்கு அனுப்பும் feedback-ம் session-உடன் பதிவேற்றப்படும், நீங்கள் அதை `DSH_TELEMETRY_MODE=DISABLED`-உடன் தொடங்கினால் தவிர.

### இயல்புநிலை agent

உங்கள் இயல்புநிலை agent-ஐ `omarchy default agent <name>` கொண்டு அல்லது Omarchy Menu-வில் (`Super + Space`) _Setup > Defaults > Agent_-இன் கீழ் தேர்ந்தெடுக்கவும். Agent இன்னும் நிறுவப்படவில்லை என்றால், அதைத் தேர்ந்தெடுப்பது முதலில் அதை நிறுவும். புதிய Omarchy ஒருமுறை மட்டுமான அறிவிப்புடன் இந்தத் தேர்வைச் செய்ய உங்களை அழைக்கும்.

Claude-ஐத் தேர்ந்தெடுப்பது Chromium, Chrome, Brave, Brave Origin, மற்றும் Edge-க்கு அதன் browser extension-ஐ அமைக்கவும் முயற்சிக்கிறது. Extension அமைப்பு அனைத்து பயனர்களுக்கும் பொருந்தும், உங்கள் system password-ஐக் கேட்க கூடும்; ரத்து செய்வதோ extension நிறுவல் தோல்வியடைவதோ Claude-ஐத் தேர்ந்தெடுத்துத் தொடங்குவதைத் தடுக்காது. உங்கள் browser-ஐ மறுதொடக்கம் செய்து, கேட்கப்பட்டால் extension-ஐ இயக்கி, அதை இணைப்பதை முடிக்க Claude-இல் sign in செய்யவும். இணைப்பைச் சரிபார்க்க Claude-இல் `/chrome` இயக்கவும். Firefox மற்றும் Zen இந்த extension-ஐ ஆதரிக்காது. இந்த அமைப்பு சேர்க்கப்படுவதற்கு முன்பே Claude உங்கள் இயல்புநிலையாக இருந்திருந்தால், extension-ஐ நிறுவ அதை மீண்டும் தேர்ந்தெடுக்கவும்.

நீங்கள் தேர்ந்தெடுத்ததும், `Super + Shift + Ctrl + A` இயல்புநிலை agent-ஐ ஒரு தனி terminal window-வில் தொடங்கும் (அல்லது நீங்கள் இன்னும் தேர்ந்தெடுக்கவில்லை என்றால் picker-ஐக் கொண்டு வரும்). `omarchy agent prompt "Review this project"` கொண்டு அதை நேரடியாக ஒரு பணிக்குள் தொடங்கவும் முடியும். Freebuff மற்றும் DeepSeek Harness தொடக்க prompt எதையும் எடுக்காது, எனவே அவை prompt-ஐ உங்கள் clipboard-இல் ஒட்டுவதற்காக வைத்து அதற்குப் பதிலாகத் திறக்கும். இவ்வாறு தொடங்கப்படும் Agent-கள் அவற்றின் அந்தந்த don't-stop-to-ask முறைகளில் கவனிக்கப்படாமல் இயங்கும், எனவே அவை உண்மையில் செயல்களைச் செய்யத் தயாராக இருங்கள்! MiniMax Code-க்கு அதன் interactive session-களுக்கு அத்தகைய முறை இல்லை, எனவே அது வழக்கம் போல் அனுமதிகளைக் கேட்கும். மேலும் agent-கள் உங்கள் home directory-க்கான நம்பிக்கையை நினைவில் வைக்க மறுப்பதால், `$HOME`-இலிருந்து தொடங்குபவை அதற்குப் பதிலாக `~/Work`-இல் தொடங்கும்.

Terminal shortcut-களும் உள்ளன: `a` தற்போதைய terminal-இல் இயல்புநிலை agent-ஐ inline-ஆக இயக்குகிறது, அதே நேரம் `c`, `cx`, மற்றும் `cy` OpenCode, Claude Code, மற்றும் Codex-ஐ நேரடியாகத் தொடங்கும் (மீண்டும் அவற்றின் auto-approving முறைகளில்). Theme மாற்றங்களும் agent-களுக்கு sync ஆகும்: நீங்கள் Omarchy theme-ஐ மாற்றும்போது Claude Code, Pi, OpenCode, மற்றும் Hermes (Omarchy அதை நிறுவியதும்) அனைத்தும் பின்தொடரும்.

### Agents பேனல்

Top bar-இல் ஒரு agents ஐகான் உள்ளது. நீங்கள் ஒரு agent-ஐ அமைப்பதற்கு முன்பு, அதன் பேனல் Claude, Codex, அல்லது Grok-இல் sign in செய்வதன் வழியாக உங்களை அழைத்துச் செல்லும், மேலும் முதலாவது உங்கள் இயல்புநிலை agent ஆகும். அதன் பிறகு, பேனல் ஒவ்வொரு சந்தாவையும் ஒரே பக்கத்தில் வைக்கிறது: ஒவ்வொரு agent-ம் கணக்கும் அதன் plan-உடன், அதன் 5-மணி நேர session மற்றும் வாராந்திர வரம்புகள் ஒவ்வொன்றுக்கும் ஒரு meter-ம் அது reset ஆகும் வரையிலான நேரமும் (சரியான சதவீதத்திற்கு hover செய்யவும்), அல்லது மீதமுள்ள prepaid balance, இவை அனைத்திலும் நீங்கள் பயன்படுத்தியவற்றின் வழியாகச் சுழலும் ஒரு வரியின் கீழ், இந்த வார டோக்கன்கள் மற்றும் நீங்கள் அதிகம் பயன்படுத்திய model போல. _Make something_-இன் கீழ் இது உங்கள் இயல்புநிலை agent-இடம் பணியைக் கையளிக்கும் புதிய theme, plugin, அல்லது app-க்கான starter prompt-களை வழங்குகிறது. App-கள் Omarchy-இன் சொந்த Hype, Monologue, மற்றும் Omacut கட்டமைக்கப்பட்ட விதத்தில், C++ மற்றும் Qt Quick-இல், omarchy-app agent skill-ஐப் பின்பற்றி கட்டமைக்கப்படுகின்றன, மேலும் அவற்றுக்குத் தேவையான compiler மற்றும் Qt பகுதிகள் நிறுவப்பட்டு வருகின்றன. Claude Code, Codex, Grok, Kimi, Cursor மற்றும் அதன் Grok Bot allowance, GitHub Copilot, Muse, Antigravity, Kimchi, மற்றும் Devin ஆகியவை அவற்றின் வரம்புகளுடன் out of the box உள்ளடக்கப்பட்டுள்ளன, மேலும் Hermes, Mistral Vibe, மற்றும் Qwen Code நீங்கள் அவற்றைப் பயன்படுத்தியதும் அவற்றின் session-களையும் டோக்கன்களையும் காட்டும். pi, omp, அல்லது opencode வழியாக நீங்கள் பயன்படுத்தும் Provider plan-களும் key-களும் கூடக் காட்டப்படும்: OpenCode Zen மற்றும் Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan, மற்றும் Synthetic அவற்றின் வரம்புகளுடன்; Fireworks, OpenRouter, மற்றும் DeepSeek அவற்றின் prepaid balance-களுடன்; மேலும் நீங்கள் உங்கள் சொந்த hardware-இல் இயக்கும் model-கள் Local models-இன் கீழ். ஒவ்வொரு agent-ம் ஒருமுறை மட்டுமே கணக்கிடப்படும், அதற்கு யார் bill செய்கிறார்களோ அவர்களின் கீழ், நீங்கள் எத்தனை harness-கள் வழியாக அதை இயக்கினாலும்.

பேனலுக்கு bar ஐகானை left-click செய்யவும், உங்கள் இயல்புநிலை agent-ஐத் தொடங்க right-click செய்யவும். அதன் பின்னால் உள்ள usage record-கள் ஒவ்வொரு 15 நிமிடங்களும் `omarchy agent usage-update` மூலம் மீண்டும் உருவாக்கப்படுகின்றன, மேலும் பேனல் synced folder வழியாக உங்கள் மற்ற machine-களிலிருந்து usage-ஐக் கூட இணைக்க முடியும். முழு அமைப்புகளுக்கு `$OMARCHY_PATH/shell/plugins/agents/`-இன் கீழ் உள்ள README-ஐப் பார்க்கவும்.

### பல சந்தாக்கள்

நீங்கள் ஒன்றுக்கு மேற்பட்ட Claude, Codex, அல்லது Grok plan-களுக்குப் பணம் செலுத்தினால் — தனிப்பட்ட Max ஒன்றும் வேலைக்கானது ஒன்றும் என்று வைத்துக்கொள்வோம் — Omarchy அவை அனைத்தையும் signed in ஆக வைத்து அவற்றுக்கிடையே நகர முடியும். agents பேனலில் உள்ள +-உடன் ஒரு சந்தாவைச் சேர்க்கவும், அது அங்கேயே உங்களை அதன் வழியாக அழைத்துச் செல்லும், அல்லது `omarchy agent account add claude Work` (அல்லது `codex`, அல்லது `grok`) கொண்டு சேர்க்கவும். அது இல்லை என்றால் CLI-ஐ நிறுவும். ஒரு provider-க்கான முதல் கணக்கு உங்கள் சாதாரண browser வழியாக, CLI எப்போதும் பார்க்கும் இடத்திலேயே sign in செய்யும். அதன் பிறகு வரும் ஒவ்வொன்றும் ஒரு private window வழியாக sign in செய்யும், எனவே உங்கள் browser ஏற்கனவே signed in ஆக உள்ள கணக்கு தவறுதலாக எடுக்கப்படாது; நீங்கள் சேர்க்கும் கணக்காக அங்கே sign in செய்து, நீங்கள் ஏற்கனவே திறந்து வைத்துள்ள எந்த private window-வையும் முதலில் மூடவும். இதைச் செய்ய CLI-இலிருந்து ஒருபோதும் log out செய்யாதீர்கள்: log out செய்வது சேமிக்கப்பட்ட sign-in-ஐ ரத்து செய்யும், மேலும் அந்தக் கணக்கை மீண்டும் சேர்க்க வேண்டியிருக்கும்.

உங்கள் சந்தா login-களை SSH வழியாக மற்றொரு Omarchy machine-க்கு நகலெடுக்க, `omarchy agent account copy user@laptop` இயக்கவும். இலக்கில் ஒன்று நிறுவப்படவில்லை என்றால் அனுப்புநர் ஒரு தற்காலிக receiver-ஐ வழங்குகிறது, எனவே பழைய Omarchy machine-கள் update இல்லாமல் கணக்குகளைப் பெற முடியும். நிறுவப்பட்ட receiver-களுக்கு முன்னுரிமை கிடைக்கும். இது அனைத்து Claude, Codex, மற்றும் Grok சந்தாக்களையும் நகலெடுக்கிறது; அவற்றைத் தேர்ந்தெடுக்க provider பெயர்களைச் சேர்க்கவும், `omarchy agent account copy laptop claude` போல. கணக்குப் பெயர்களும் command ID-களும் மூலத்துடன் பொருந்தும், இலக்கில் ஏற்கனவே உள்ள கணக்குகள் உட்பட. தொடர்பில்லாத இலக்குக் கணக்குகளின் பெயர்கள் முரண்பட்டால் அவை ஒரு எண் பின்னொட்டைப் பெறும், மேலும் அமைப்புகள், skill-கள், plugin-கள், மற்றும் conversation history ஒவ்வொரு machine-க்கும் உள்ளூராகவே இருக்கும்.

ஏற்கனவே உள்ள இலக்கு credential-கள் வைக்கப்படும். அங்கே ஏற்கனவே signed in ஆக உள்ள ஒரு மூலக் கணக்கின் பெயர் அதன் credential-களை மாற்றாமல் ஒத்திசைக்கப்படும்; மற்ற கணக்குகள் அதனுடன் சேர்க்கப்படும். பொருந்தும் கணக்குகளுக்கான சேமிக்கப்பட்ட credential-களை மாற்ற, இலக்கில் அந்தக் கணக்கின் session-களை விட்டு வெளியேறிய பிறகு `omarchy agent account copy --replace laptop claude` பயன்படுத்தவும். புதிய இலக்கு மூலத்தின் active கணக்கையும் switching விருப்பங்களையும் கூடப் பெறும்; நிறுவப்பட்ட இலக்கு தன்னுடையவற்றை வைத்திருக்கும்.

Credential-கள் SSH வழியாகப் பயணித்து இலக்கில் private file-களில் சேமிக்கப்படுகின்றன, எனவே நீங்கள் நம்பும் machine-களுக்கு மட்டும் நகலெடுக்கவும். இது ஒருமுறை நகல், தொடர்ச்சியான ஒத்திசைவு அல்ல. Codex refresh token-கள் மற்றொரு machine-ஆல் மாற்றப்படலாம், நகலெடுக்கப்பட்ட login-ஐ புதுப்பிக்க வேண்டிய நிலையில் விட்டு. பல machine-களில் ஒரே நேரத்தில் பயன்படுத்த தனித்தனி sign-in-களே மிகவும் நம்பகமான தேர்வாக இருக்கும். [Codex-இன் கணக்கு authentication வழிகாட்டல்](https://developers.openai.com/codex/auth/ci-cd-auth) பார்க்கவும்.

Provider ஒன்றுக்கு ஒரு கணக்கு active ஆக இருக்கும், மேலும் ஒவ்வொரு புதிய session-ம் அதுவாகவே தொடங்கும்: `cx`, `cy`, ஒரு சாதாரண `claude`, `codex`, அல்லது `grok`, `omarchy agent` வழியாகத் தொடங்கப்படும் எதுவும், மேலும் `PATH`-இல் CLI-ஐக் கண்டறியும் script-கள் அல்லது editor-கள். `omarchy agent account use work` கொண்டு மாற்றவும் (மேலும் `omarchy agent account use main` கொண்டு திரும்பவும்), அல்லது பேனலில் ஒரு கணக்கின் எண்ணை அழுத்தி பின்னர் `Enter` அழுத்துவதன் மூலம் (அல்லது அதன் Use பொத்தானை click செய்வதன் மூலம்). ஏற்கனவே இயங்கும் Session-கள் அவை தொடங்கிய கணக்கிலேயே இருக்கும். Conversation history, அமைப்புகள், skill-கள், மற்றும் plugin-கள் கணக்குகள் முழுவதும் பகிரப்படும், எனவே அதே folder-இல் `claude --continue` புதிய கணக்கில் நீங்கள் விட்ட இடத்திலிருந்து தொடரும்.

ஒன்றுக்கு மேற்பட்ட கணக்குகளுடன், பேனல் ஒவ்வொரு கணக்கின் வரம்புகளையும் பக்கத்திற்குப் பக்கம் காட்டும், active ஆனது குறிக்கப்பட்டு. இயல்பாக active கணக்கு ஒரு வரம்பின் 95%-ஐக் கடக்கும்போது Omarchy உங்களுக்கு அறிவிக்கும், மேலும் அறிவிப்பை click செய்வது அதிக headroom உள்ள கணக்கிற்கு மாறும். பேனலில் ஒரு கணக்கின் வரியின் மீது hover செய்து Use-க்கு அருகில் தோன்றும் Autoswitch-ஐ click செய்யவும் (அல்லது `m` அழுத்தவும்), அல்லது அது தானாகவே மாற `omarchy agent account mode auto` இயக்கவும்; அது on-இல் இருக்கும்போது, Autoswitch Use-இன் இடத்தை எடுக்கும், மேலும் அதை மீண்டும் click செய்வது அறிவிப்பதற்குத் திரும்பும். Threshold-ஐ மாற்ற ஒரு எண்ணைச் சேர்க்கவும், `omarchy agent account mode auto 90` போல. ஒவ்வொரு கணக்கும் threshold-க்கு மேல் இருந்தால், எந்தக் கணக்கு முதலில் விடுபடுகிறது என்பதுடன், நீங்கள் அதைப் பற்றி ஒருமுறை கேட்பீர்கள். Active கணக்கு அதன் threshold-இலிருந்து 15 புள்ளிகளுக்குள் இருக்கும்போது (இயல்புநிலையில் 80%), அதன் வரம்புகள் ஒவ்வொரு 15-க்கும் பதிலாக ஒவ்வொரு மூன்று நிமிடங்களும் சரிபார்க்கப்படும்.

`omarchy agent account list` ஒவ்வொரு கணக்கையும் அதன் சமீபத்திய வரம்புகளையும் காட்டுகிறது, `omarchy agent account remove work` ஒன்றை மறக்கிறது, மேலும் `omarchy agent account rename primary Hey` ஒன்றிற்கு மறுபெயரிடுகிறது (அல்லது பேனலில் ஒரு கணக்கின் பெயரை click செய்யவும்). இந்த command-கள் உங்கள் இயல்புநிலை agent-இன் கணக்குகளில் வேலை செய்யும்; மற்ற provider-ஐ அடைய, முதலில் அதைப் பெயரிடவும், `omarchy agent account use codex side` போல. `~/.claude` அல்லது `~/.codex`-இல் நீங்கள் ஏற்கனவே வைத்திருந்த login _Main_ கணக்கு, அது இருக்கும் இடத்திலேயே இருக்கும். சுமார் எட்டு மணி நேரத்திற்கும் மேலாகப் பயன்படுத்தப்படாத கணக்கு _Sign-in required_ எனக் காட்ட கூடும்; பேனலிலேயே அந்தக் கணக்கை மீண்டும் sign in செய்ய அதை click செய்யவும், அல்லது அதில் ஒரு session-ஐத் தொடங்கவும், அது தானாகவே sign-in-ஐப் புதுப்பிக்கும். ஒரு கணக்கு சேர்க்கப்பட்டபோது நீங்கள் வைத்திருந்த MCP server-கள் அதற்கு வரும், ஆனால் பின்னர் `claude mcp add` கொண்டு நீங்கள் சேர்ப்பவை நீங்கள் அவற்றைச் சேர்த்த கணக்கை மட்டுமே அடையும். Claude Desktop மற்றும் CLI binary-க்கான absolute path கொண்டு உள்ளமைக்கப்பட்ட கருவிகள் switch-ஐப் பின்பற்றாது. வெளிப்படையான `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, அல்லது `GROK_HOME` தேர்ந்தெடுக்கப்பட்ட கணக்கை விட முன்னுரிமை பெறும்.

### செயலிழப்பு கண்டறிதல்

Omarchy process செயலிழப்புகளுக்கு systemd-coredump-ஐக் கண்காணிக்கிறது. ஏதாவது segfault ஆகும்போது, உங்களுக்கு ஒரு "Process crashed" அறிவிப்பு கிடைக்கும் — அதை click செய்யவும், மேலும் செயலிழப்பு உங்கள் இயல்புநிலை agent-இடம் Omarchy-இன் diagnose-crash skill-உடன் கையளிக்கப்படும், அது core dump-இலிருந்து உண்மைகளை நிறுவுவதன் வழியாகவும் செயலிழப்பு upstream-இல் புகாரளிக்கத் தகுதியானதா என முடிவு செய்வதன் வழியாகவும் agent-ஐ அழைத்துச் செல்லும். `coredumpctl list`-இலிருந்து எந்த PID-க்கு எதிராகவும் `omarchy agent crash <pid>` கொண்டு அதை கையாலும் இயக்கலாம்.

கண்காணிப்பு இயல்பாக on-இல் இருக்கும். _Trigger > Toggle > Crash Capture_-இன் கீழ் (அல்லது `omarchy toggle crash-capture` கொண்டு) அதை அணைக்கவும், அறிவிப்புகள் நிற்கும்; `omarchy agent crash <pid>` இன்னும் கையால் வேலை செய்யும்.

செயலிழப்புகளை ஒரு நேரத்தில் ஒரு program வீதமும் அமைதிப்படுத்தலாம், இதைத்தான் diagnosis இறுதியில் உங்களுக்கு வழங்குகிறது. `omarchy crash mute hyprland` அந்த program-க்கு மட்டும் அறிவிப்புகளை நிறுத்துகிறது, `omarchy crash mute hyprland off` அவற்றை மீண்டும் கொண்டு வருகிறது, மேலும் `omarchy crash mute` தனியாக நீங்கள் muted செய்தவற்றைப் பட்டியலிடுகிறது. அது binary-இன் பெயரைப் போலவே அதன் path-ஐயும் மகிழ்ச்சியுடன் எடுக்கும், எனவே `omarchy crash mute /usr/bin/hyprland` அதே வேலையைச் செய்கிறது. இடைவெளி உள்ள பெயரை மேற்கோள் காட்டவும், `omarchy crash mute 'Some App'` போல. மற்ற அனைத்தும் இன்னும் அறிவிக்கும், மேலும் muted program இன்னும் செயலிழக்கும் — இது நினைவூட்டலை மறைக்கிறது, எதையும் சரிசெய்யாது.

### Desktop apps

_Install > AI_ menu சில graphical AI app-களையும் கொண்டுள்ளது: ChatGPT desktop app, Claude desktop app (Chat, Cowork, மற்றும் Claude Code tab-களுடன் Anthropic-இன் Linux beta), xAI-இன் model-களுடன் அரட்டையடிக்க Grok Bot, Hermes Desktop, OpenClaw, Perplexity desktop app, மற்றும் T3 Code. Grok Bot என்பது desktop chat app. Coding agent என்பது `grok` command.

Hermes Desktop தான் தெரிந்து கொள்ள வேண்டியது, ஏனெனில் ஒரு machine-இல் ஒரு Hermes உள்ளது, மேலும் அது app-இனுடையது: Hermes எப்போதும் app வழியாக மட்டுமே நிறுவப்படுகிறது, மேலும் இயல்புநிலை agent இயக்கும் `hermes` command app-இனுடையது. Hermes-ஐ இயல்புநிலை agent ஆகத் தேர்ந்தெடுப்பது _Install > AI_ entry செய்வதையே நிறுவுகிறது: package, மற்றும் Hermes-இன் சொந்த installer-ஆல் அமைக்கப்பட்ட `~/.hermes`-இன் கீழ் ஒரு Hermes runtime, இது முதல் முறை சில நிமிடங்கள் எடுக்கும். அந்த runtime தான் terminal `hermes` command, இயல்புநிலை agent மற்றும் app அனைத்தும் பயன்படுத்தும் ஒரே Hermes, மேலும் அது Omarchy வெளியீட்டிற்காகக் காத்திராமல் `hermes update` கொண்டு தன்னைப் புதுப்பிக்கிறது. அதை நிறுவுவது Hermes-க்கு Omarchy theme-ஐ `omarchy` என்ற பெயரிடப்பட்ட skin ஆகவும் கையளிக்கிறது, நீங்கள் theme-களை மாற்றும்போது ஒவ்வொரு Hermes surface-ம் அதைப் பின்பற்றும்; நீங்கள் அது அவ்வாறு செய்ய விரும்பவில்லை என்றால் Hermes-இன் Appearance அமைப்புகளின் கீழ் அல்லது `/skin` கொண்டு மற்றொன்றைத் தேர்ந்தெடுக்கவும், மேலும் Omarchy அந்தத் தேர்வை அப்படியே விட்டுவிடும். _Remove > AI_-இன் கீழ் app-ஐ அகற்றுவது முதலில் Hermes-ஐ மூடுகிறது, gateway உட்பட, அந்த runtime-ஐ அதனுடன் எடுத்துச் செல்கிறது, மேலும் நீங்கள் வேறுவிதமாகச் சொன்னால் தவிர உங்கள் chat-கள், நினைவுகள், மற்றும் Hermes தனக்காக எழுதிய skill-களை வைத்திருக்கிறது: அந்த data-வும் உங்கள் connection அமைப்புகளும் கூடச் செல்ல வேண்டுமா என அது கேட்கும், இயல்பாக no என.

OpenClaw-இன் desktop அனுபவம் அதன் Control UI ஆகும், அது அதன் சொந்த local gateway-ஆல் ஆதரிக்கப்படும் ஒரு web app ஆகத் திறக்கிறது. OpenClaw `~/.openclaw`-இல் வாழ்கிறது மற்றும் தன்னைப் புதுப்பிக்கிறது: Control UI-இன் "Update Gateway" பொத்தானைப் பயன்படுத்தவும் அல்லது `openclaw update` இயக்கவும், மேலும் gateway புதிய பதிப்பில் மறுதொடக்கம் ஆகும். புதிய நிறுவல் எந்த வெளியீட்டிலிருந்து தொடங்குகிறது என்பதை மட்டும் Omarchy தேர்ந்தெடுக்கிறது. _Remove > AI_-இன் கீழ் OpenClaw-ஐ அகற்றுவது gateway service-ஐயும் app-ஐயும் அதனுடன் எடுத்துச் சென்று பின்னர் `~/.openclaw` கூடச் செல்ல வேண்டுமா எனக் கேட்கும், ஏனெனில் அது OpenClaw-உடனும் அது பதிவிறக்கும் plugin runtime-களுடனும் உங்கள் chat-களையும் credential-களையும் வைத்திருக்கிறது; இயல்புநிலை அதை வைத்திருக்கும், மேலும் OpenClaw-ஐ மீண்டும் நிறுவுவது அதை மீண்டும் எடுத்துக்கொள்ளும்.

T3 Code ஒரு package-இலிருந்து அல்லாமல் `~/.local/share/t3code`-இல் அதன் official AppImage வெளியீட்டிலிருந்து இயங்குகிறது, எனவே அது தன்னைப் புதுப்பிக்கிறது. அதை நிறுவுவது Stable அல்லது Nightly channel-இல் தொடங்க வேண்டுமா எனக் கேட்கும்; பின்னர் T3 Code-இன் அமைப்புகளில் மாற்றவும். உங்கள் thread-களும் அமைப்புகளும் `~/.t3`-இல் வாழ்கின்றன, மேலும் _Remove > AI_-இன் கீழ் T3 Code-ஐ அகற்றுவது அவற்றை அதனுடன் எடுத்துச் செல்கிறது.

### உள்ளூர் LLM-கள்

Omarchy உள்ளூர் LLM model-களை இயக்க இரண்டு வழிகளைப் பரிந்துரைக்கிறது: LM Studio மற்றும் Ollama. LM Studio open-weight model-களைக் கண்டறிவதற்கும், அவற்றை நிறுவுவதற்கும், அவற்றை இயக்குவதற்கும் ஒரு GUI interface-ஐ வழங்குகிறது. எளிதாகத் தொடங்க இது ஒரு சிறந்த வழி. Ollama அதேபோல் செய்ய ஒரு CLI-ஐ வழங்குகிறது. ஆனால் நீங்கள் உள்ளூர் model-களுக்குப் புதியவர் என்றால், நான் LM Studio-வில் தொடங்குவேன். Omarchy Menu-வில் _Install > AI_-இன் கீழ் இரண்டில் ஒன்றை நிறுவலாம்.

### The Omarchy Skill

Agent skill-கள் AI குறிப்பிட்ட கருவிகளை ஒரு குறிப்பிட்ட வழியில் பயன்படுத்த உதவுகின்றன, மேலும் Omarchy system-ஐத் தனிப்பயனாக்க ஒரு இயல்புநிலை skill-உடன் வருகிறது. உங்கள் Hyprland config-ஐ மாற்றுவது, bar-ஐச் சரிசெய்வது, அல்லது புதிதாக ஒரு theme-ஐ உருவாக்குவது போல. இது Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` மற்றும் ஒவ்வொரு `~/.hermes/profiles/*/skills`), மற்றும் பொதுவான `~/.agents/skills` இடத்திற்கான skill directory-களில் symlinked செய்யப்பட்டுள்ளது, எனவே பெரும்பாலான harness-கள் அதைத் தானாகவே எடுத்துக்கொள்ளும்.

ஆனால் நீங்கள் இந்த skill-ஐ பரிசோதனை எனக் கருத வேண்டும். வெவ்வேறு model-கள் அதை வெவ்வேறு விளைவுகளுக்குப் பயன்படுத்தும். முதலில் plan mode-இல் இயக்குவது சிறந்தது, எனவே agent என்ன மாற்ற விரும்புகிறது என்பது பற்றி உங்களுக்கு ஒரு யோசனை இருக்கும். மேலும் agent எல்லாவற்றையும் குழப்பினால் மாற்றங்களை rollback செய்ய அல்லது `omarchy reinstall configs` கூட அழைக்கத் தயாராக இருங்கள்.
