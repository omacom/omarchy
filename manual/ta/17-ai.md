# AI

Omarchy உங்களுக்காக இயல்புநிலையைத் தேர்ந்தெடுக்காமல், கீழே உள்ள coding agent-களுக்கான launcher-களை உள்ளடக்கியுள்ளது. முதல் பயன்பாட்டில் அதன் CLI-ஐ நிறுவ ஒரு கட்டளையை இயக்கவும், பின்னர் கேட்கப்படும்போது அங்கீகரிக்கவும். Hermes மற்றும் OpenClaw விதிவிலக்குகள்: அவற்றுக்கு mise வழியாக எதுவும் நிறுவப்படுவதில்லை, மேலும் ஏதேனும் ஒன்றைத் தேர்ந்தெடுப்பது, கீழே _Desktop apps_ விளக்குவது போல, அதன் சொந்த தானாகப் புதுப்பிக்கும் நகலை அமைக்கிறது.

### agent-களை நிறுவுதல் மற்றும் புதுப்பித்தல்

Hermes மற்றும் OpenClaw தவிர, இந்த agent-கள் mise இன் lazy installation-ஐப் பயன்படுத்துகின்றன: முதல் தொடக்கம் CLI-ஐ நிறுவுகிறது, பிந்தைய தொடக்கங்கள் அதையே மீண்டும் பயன்படுத்துகின்றன. mise ஒரு நிறுவப்பட்ட agent-க்கு புதிய வெளியீடு உள்ளதா என நான்கு மணி நேரத்திற்கு ஒரு முறைக்கு மேல் சரிபார்க்காது, அது தொடங்குவதற்குச் சற்று முன்பு அல்லது shell prompt-இல் பின்னணியில். அந்தப் புதுப்பிப்பு தோல்வியடைந்தால் அல்லது நீங்கள் offline-இல் இருந்தால், நிறுவப்பட்ட பதிப்பு இயங்கும். `omarchy update` நிறுவப்பட்ட agent-களை Omarchy இன் மற்ற பகுதிகளுடன் புதுப்பிக்கிறது, மேலும் `mup` mise நிர்வகிக்கும் கருவிகளை மட்டும் புதுப்பிக்கிறது.

`claude update`, `codex update` போன்ற agent இன் சொந்த updater, அல்லது ஒரு app-இல் உள்ள update button, mise நிர்வகிக்கும் நிறுவலைப் புதுப்பிக்காது. `codex update` தோல்வியடையும், மேலும் `claude update` வெற்றி என அறிவித்தாலும் mise கண்காணிக்காத தனி நகலை நிறுவக்கூடும். agent இன் சொந்த installer மற்றும் updater-ஐப் பயன்படுத்த விரும்பினால், அதை `disable_tools`-இல் சேர்க்கவும்; [முன்பே நிறுவப்பட்ட CLI கருவிகள்](18-development-tools.md#preinstalled-cli-tools) பார்க்கவும்.

உங்களுக்குத் தேவைப்படும் முன்பே கட்டமைக்கப்பட்ட அனைத்து lazy கருவிகளையும் நிறுவ, `mise install --include-lazy` இயக்கவும். இதில் agent-களுடன் Omarchy இன் மற்ற இயல்புநிலை CLI கருவிகளும் அடங்கும். ஒற்றைக் கருவியை நிறுவுவது அல்லது உங்கள் சொந்த நிறுவலைப் பயன்படுத்துவது குறித்து [முன்பே நிறுவப்பட்ட CLI கருவிகள்](18-development-tools.md#preinstalled-cli-tools) பார்க்கவும்.

`grok` mise இன் first-party `grok` package வழியாக நிறுவப்படுகிறது, `claude` மற்றும் `codex` போலவே. `grok` இயக்கவும், அல்லது _Agent > Harness_ கீழ் அதைத் தேர்ந்தெடுக்கவும். x.ai-இல் `curl | bash` installer-ஐத் தவிர்க்கவும். அந்தப் பாதை `~/.grok/bin`-இல் இரண்டாவது நகலை வைக்கிறது, அதை `PATH`-இல் முன்னால் சேர்க்கிறது, மேலும் Omarchy இன் wrapper-ஐ மேலெழுதுகிறது.

`dsh` அதன் browser UI-ஐ `127.0.0.1:3080`-இல் திறக்கிறது, தொடக்கக் கோப்பகத்தை அதன் இயல்புநிலை workspace ஆகக் கொண்டு. அதன் browser UI தொடக்க prompt-ஐ ஏற்காது, எனவே `omarchy agent prompt` ஒட்டுவதற்காக prompt-ஐ உங்கள் clipboard-இல் வைத்து அதைத் திறக்கிறது. Omarchy அதை DeepSeek இன் no-approval permission preset உடன் தொடங்குகிறது. நீங்கள் அதன் அதிகாரப்பூர்வ model API-ஐப் பயன்படுத்தும்போது DeepSeek Harness session log-களை DeepSeek-க்கு பதிவேற்றுகிறது; அதன் browser UI-இல் _Settings > General > Upload Session Log_ கீழ் அதை முடக்கவும். நீங்கள் `DSH_TELEMETRY_MODE=DISABLED` உடன் தொடங்காவிட்டால், நீங்கள் அனுப்பும் கருத்தும் session உடன் பதிவேற்றப்படும்.

### இயல்புநிலை agent

`omarchy default agent <name>` உடன் அல்லது Omarchy Menu (`Super + Space`) இல் _Agent > Harness_ கீழ் உங்கள் இயல்புநிலை agent-ஐத் தேர்ந்தெடுக்கவும். agent இன்னும் நிறுவப்படவில்லை என்றால், அதைத் தேர்ந்தெடுப்பது முதலில் அதை நிறுவும், மேலும் Agent-க்கு அடுத்ததாக app launcher-இல் அதற்கென தனி launcher-ஐயும் பெறும். புதிய Omarchy ஒரு முறை மட்டும் வரும் அறிவிப்புடன் இந்தத் தேர்வைச் செய்ய உங்களை அழைக்கும்.

Claude-ஐத் தேர்ந்தெடுப்பது Chromium, Chrome, Brave, Brave Origin, மற்றும் Edge-க்கான அதன் browser extension-ஐ அமைக்கவும் முயற்சிக்கிறது. extension அமைப்பு அனைத்து பயனர்களுக்கும் பொருந்தும், உங்கள் system password-ஐக் கேட்கக்கூடும்; ரத்து செய்வது அல்லது extension நிறுவல் தோல்வியடைவது கூட Claude-ஐத் தேர்ந்தெடுத்து தொடங்கும். உங்கள் browser-ஐ மறுதொடக்கம் செய்யவும், கேட்கப்பட்டால் extension-ஐ இயக்கவும், அதை இணைப்பதை முடிக்க Claude-இல் உள்நுழையவும். இணைப்பைச் சரிபார்க்க Claude-இல் `/chrome` இயக்கவும். Firefox மற்றும் Zen இந்த extension-ஐ ஆதரிக்காது. இந்த அமைப்பு சேர்க்கப்படுவதற்கு முன்பே Claude உங்கள் இயல்புநிலையாக இருந்தால், extension-ஐ நிறுவ அதை மீண்டும் தேர்ந்தெடுக்கவும்.

நீங்கள் தேர்ந்தெடுத்த பிறகு, `Super + Shift + Ctrl + A` இயல்புநிலை agent-ஐ பிரத்யேக terminal window-இல் தொடங்கும் (அல்லது நீங்கள் இன்னும் தேர்ந்தெடுக்கவில்லை என்றால் picker-ஐக் கொண்டுவரும்). `omarchy agent prompt "Review this project"` உடன் அதை நேரடியாக ஒரு பணிக்குள் தொடங்கவும் முடியும். Freebuff மற்றும் DeepSeek Harness தொடக்க prompt-ஐ ஏற்காது, எனவே அவை ஒட்டுவதற்காக prompt-ஐ உங்கள் clipboard-இல் வைத்து திறக்கும். இவ்வாறு தொடங்கப்படும் agent-கள் அந்தந்த don't-stop-to-ask mode-களில் கவனிக்கப்படாமல் இயங்கும், எனவே அவை உண்மையில் செயல்படத் தயாராக இருங்கள்! MiniMax Code-க்கு அதன் interactive session-களுக்கு அத்தகைய mode இல்லை, எனவே அது வழக்கம் போல அனுமதிகளைக் கேட்கும். மேலும் agent-கள் உங்கள் home directory-க்கான trust-ஐ நினைவில் வைக்க மறுப்பதால், `$HOME`-இலிருந்து தொடங்குவது அதற்கு பதிலாக `~/Work`-இல் தொடங்கும்.

terminal shortcut-களும் உள்ளன: `a` தற்போதைய terminal-இல் இயல்புநிலை agent-ஐ inline ஆக இயக்குகிறது, அதே நேரம் `c`, `cx`, மற்றும் `cy` OpenCode, Claude Code, மற்றும் Codex-ஐ நேரடியாகத் தொடங்குகின்றன (மீண்டும் அவற்றின் auto-approving mode-களில்). Theme மாற்றங்கள் agent-களுக்கும் ஒத்திசைகின்றன: நீங்கள் Omarchy theme-ஐ மாற்றும்போது Claude Code, Pi, OpenCode, மற்றும் Hermes (Omarchy அதை நிறுவிய பிறகு) அனைத்தும் பின்தொடரும்.

### உங்கள் agent அறிவுறுத்தல்கள்

ஒவ்வொரு agent-க்கான தனிப்பட்ட விதிகள் `~/.agents/skills`-இல் உள்ள shared skill-களுக்கு அடுத்ததாக `~/.agents/AGENTS.md`-இல் செல்கின்றன. அதை _Agent > Instructions_ கீழ் திறக்கவும், இது ஒவ்வொரு harness-இன் சொந்த global file-உடனும் அதை இணைக்கிறது: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, Copilot இன் `~/.copilot/copilot-instructions.md`, மற்றும் பல. Crush மற்றும் Amp `~/.config/AGENTS.md` இணைப்பைப் படிக்கின்றன, அதே நேரம் omp, Kimi, மற்றும் DeepSeek Harness `~/.agents/AGENTS.md`-ஐ நேரடியாகப் படிக்கின்றன. இயல்புநிலை agent-ஐத் தேர்ந்தெடுப்பதும் அதை இணைக்கிறது. ஏற்கனவே இல்லாதிருந்தால் நீங்கள் ஏற்கனவே வைத்திருந்த instructions file shared ஆனதாக மாறும்; இல்லையெனில் அது இணைப்புக்கு அருகில் `.bak` ஆக வைக்கப்படும். மற்றொரு agent-ஐ நிறுவிய பிறகு மீண்டும் இணைக்க `omarchy agent instructions` இயக்கவும்.

### agents panel

மேல் bar-இல் agents icon உள்ளது. நீங்கள் ஒரு agent-ஐ அமைப்பதற்கு முன்பு, அதன் panel Claude, Codex, அல்லது Grok-இல் உள்நுழைவதன் வழியாக உங்களை வழிநடத்தும், முதலாவது உங்கள் இயல்புநிலை agent ஆக மாறும். அதன் பிறகு, panel ஒவ்வொரு சந்தாவையும் ஒரே பக்கத்தில் வைக்கிறது: ஒவ்வொரு agent மற்றும் account அதன் plan உடன், அதன் 5 மணி நேர session மற்றும் வாராந்திர வரம்புகள் ஒவ்வொன்றுக்கும் ஒரு meter உடன் அது reset ஆகும் வரையிலான நேரத்துடன் (சரியான சதவீதத்திற்கு hover செய்யவும்), அல்லது மீதமுள்ள prepaid balance, அவை அனைத்திலும் நீங்கள் பயன்படுத்தியதைச் சுழற்றும் ஒரு வரியின் கீழ், இந்த வாரம் token-கள் மற்றும் நீங்கள் அதிகம் பயன்படுத்திய model போன்றவை. _Make something cool_ கீழ் அது புதிய theme, plugin, app, அல்லது game-க்கான starter prompt-களை வழங்குகிறது, அவை பணியை உங்கள் இயல்புநிலை agent-இடம் ஒப்படைக்கின்றன. App-கள் Omarchy இன் சொந்த Hype, Monologue, மற்றும் Omacut போல C++ மற்றும் Qt Quick-இல், omarchy-make-app agent skill-ஐப் பின்பற்றி உருவாக்கப்படுகின்றன, மேலும் அவற்றுக்குத் தேவையான compiler மற்றும் Qt பகுதிகள் நிறுவப்பட்டு வருகின்றன. Game-கள் `~/Games/vibes`-இல் ஒற்றை three.js பக்கம், omarchy-make-game agent skill-ஐப் பின்பற்றி, அனைத்தும் தற்போதைய theme-இல் ஒரே Game Vibes launcher-இலிருந்து திறக்கும்; அவை web-இலிருந்து three.js-ஐ ஏற்றுகின்றன, எனவே தொடங்க அவற்றுக்கு இணைப்பு தேவை. Claude Code, Codex, Grok, Kimi, Cursor மற்றும் அதன் Grok Bot allowance, GitHub Copilot, Muse, Antigravity, மற்றும் Devin அவற்றின் வரம்புகளுடன் out of the box உள்ளடக்கப்படுகின்றன, Kimchi அதன் plan, prepaid credit-கள், மற்றும் spend budget-களுடன், மேலும் Hermes, Mistral Vibe, மற்றும் Qwen Code நீங்கள் அவற்றைப் பயன்படுத்திய பிறகு அவற்றின் session-கள் மற்றும் token-களைக் காட்டுகின்றன. pi, omp, அல்லது opencode வழியாக நீங்கள் பயன்படுத்தும் Provider plan-கள் மற்றும் key-களும் தோன்றும்: OpenCode Zen மற்றும் Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan, மற்றும் Synthetic அவற்றின் வரம்புகளுடன்; OpenRouter மற்றும் DeepSeek அவற்றின் prepaid balance-களுடன்; Fireworks கடந்த 30 நாட்களில் அதன் spend உடன். உங்கள் சொந்த hardware-இல் நீங்கள் இயக்கும் model-களிலிருந்து token-களும் மொத்தங்களில் கணக்கிடப்படுகின்றன; model-களுக்கு அவற்றுக்கென தனி panel உள்ளது, [Local model-கள்](#local-models) கீழ் விவரிக்கப்பட்டுள்ளது. ஒவ்வொரு agent-உம், நீங்கள் எத்தனை harness-கள் வழியாக அதை இயக்கினாலும், அதற்கு bill செய்பவர் கீழ் ஒரு முறை மட்டுமே கணக்கிடப்படுகிறது.

panel-க்கு bar icon-ஐ left-click செய்யவும் அல்லது `Super + Ctrl + X` அழுத்தவும், உங்கள் இயல்புநிலை agent-ஐத் தொடங்க right-click செய்யவும், refresh செய்ய middle-click செய்யவும். அதன் பின்னால் உள்ள usage record-கள் ஒவ்வொரு 15 நிமிடங்களுக்கும் `omarchy agent usage update` மூலம் மீண்டும் உருவாக்கப்படுகின்றன, மேலும் panel synced folder வழியாக உங்கள் மற்ற machine-களிலிருந்து usage-ஐக் கூட இணைக்க முடியும். முழு அமைப்புகளுக்கு `$OMARCHY_PATH/shell/plugins/agents/` கீழ் உள்ள README பார்க்கவும்.

### பல சந்தாக்கள்

நீங்கள் ஒன்றுக்கு மேற்பட்ட Claude, Codex, அல்லது Grok plan-க்கு பணம் செலுத்தினால் — தனிப்பட்ட Max மற்றும் வேலைக்கான ஒன்று என வைத்துக்கொள்வோம் — Omarchy அவை அனைத்தையும் உள்நுழைந்த நிலையில் வைத்து அவற்றுக்கிடையே நகர முடியும். agents panel-இல் + உடன் சந்தாவைச் சேர்க்கவும், அது அங்கேயே உங்களை வழிநடத்தும், அல்லது `omarchy agent account add claude Work` (அல்லது `codex`, அல்லது `grok`) உடன். அது இல்லாவிட்டால் CLI-ஐ நிறுவும். provider-க்கான முதல் account உங்கள் சாதாரண browser வழியாக, CLI எப்போதும் பார்க்கும் இடத்திலேயே உள்நுழையும். அதன் பிறகு ஒவ்வொன்றும் private window வழியாக உள்நுழையும், எனவே உங்கள் browser ஏற்கனவே உள்நுழைந்துள்ள account தவறுதலாகத் தேர்ந்தெடுக்கப்படாது; நீங்கள் சேர்க்கும் account ஆக அங்கே உள்நுழையவும், மேலும் ஏற்கனவே திறந்துள்ள private window-வை முதலில் மூடவும். இதற்காக CLI-இலிருந்து ஒருபோதும் log out செய்யாதீர்கள்: log out செய்வது சேமிக்கப்பட்ட sign-in-ஐ ரத்து செய்யும், அந்த account மீண்டும் சேர்க்கப்பட வேண்டும்.

உங்கள் சந்தா login-களை SSH வழியாக மற்றொரு Omarchy machine-க்கு நகலெடுக்க, `omarchy agent account copy user@laptop` இயக்கவும். destination-இல் நிறுவப்பட்ட receiver இல்லாதபோது sender தற்காலிக receiver-ஐ வழங்குகிறது, எனவே பழைய Omarchy machine-கள் update இல்லாமல் account-களைப் பெற முடியும். நிறுவப்பட்ட receiver-கள் முன்னுரிமை பெறும். இது அனைத்து Claude, Codex, மற்றும் Grok சந்தாக்களையும் நகலெடுக்கிறது; அவற்றைத் தேர்ந்தெடுக்க provider பெயர்களைச் சேர்க்கவும், `omarchy agent account copy laptop claude` போல. Account பெயர்கள் மற்றும் command ID-கள் source-உடன் பொருந்தும், destination-இல் ஏற்கனவே உள்ள account-கள் உட்பட. தொடர்பில்லாத destination account-களின் பெயர்கள் மோதினால் எண் suffix பெறும், மேலும் settings, skill-கள், plugin-கள், மற்றும் conversation history ஒவ்வொரு machine-இலும் local ஆகவே இருக்கும்.

ஏற்கனவே உள்ள destination credential-கள் வைக்கப்படும். அங்கே ஏற்கனவே உள்நுழைந்துள்ள source account அதன் credential-களை மாற்றாமல் அதன் பெயர் ஒத்திசைக்கப்படும்; மற்ற account-கள் அதனுடன் சேர்க்கப்படும். பொருந்தும் account-களுக்கான சேமிக்கப்பட்ட credential-களை மாற்ற, destination-இல் அந்த account இன் session-களை மூடிய பிறகு `omarchy agent account copy --replace laptop claude` பயன்படுத்தவும். புதிய destination source இன் active account மற்றும் switching preference-களையும் பெறும்; ஏற்கனவே உள்ள destination தனது சொந்தத்தை வைத்திருக்கும்.

Credential-கள் SSH வழியாகப் பயணித்து destination-இல் private file-களில் சேமிக்கப்படுகின்றன, எனவே நீங்கள் நம்பும் machine-களுக்கு மட்டுமே நகலெடுக்கவும். இது ஒரு முறை நகல், தொடர்ச்சியான ஒத்திசைவு அல்ல. Codex refresh token-கள் மற்றொரு machine மூலம் rotate செய்யப்படலாம், நகலெடுக்கப்பட்ட login புதுப்பிப்பு தேவைப்படும் நிலையில் விட்டுவிடும்; பல machine-களில் ஒரே நேரத்தில் பயன்படுத்த தனித்தனி sign-in-கள் மிகவும் நம்பகமான தேர்வாக இருக்கும். [Codex இன் account authentication வழிகாட்டுதல்](https://developers.openai.com/codex/auth/ci-cd-auth) பார்க்கவும்.

provider-க்கு ஒரு account active ஆக இருக்கும், ஒவ்வொரு புதிய session-உம் அதுவாகவே தொடங்கும்: `cx`, `cy`, சாதாரண `claude`, `codex`, அல்லது `grok`, `omarchy agent` வழியாகத் தொடங்கப்படும் எதுவும், மற்றும் `PATH`-இல் CLI-ஐக் கண்டறியும் script-கள் அல்லது editor-கள். `omarchy agent account use work` உடன் மாற்றவும் (மற்றும் `omarchy agent account use main` உடன் திரும்பவும்), அல்லது panel-இல் account இன் எண்ணை அழுத்தி பின்னர் `Enter` அழுத்துவதன் மூலம் (அல்லது அதன் Use button-ஐ click செய்வதன் மூலம்). இயங்கும் Claude session-களும் அவற்றின் அடுத்த message-இலிருந்து மாறும்: ஒவ்வொரு Claude session-உம் `~/.claude`-இல் இயங்கும், அது எப்போதும் active account இன் sign-in-ஐ வைத்திருக்கும். பழைய Omarchy மூலம் account இன் சொந்த folder-இல் தொடங்கப்பட்ட Claude session அது மூடும் வரை அந்த sign-in-ஐ வைத்திருக்கும், எனவே switch அந்த session-களைப் பெயரிட்டு அவை மறைந்த பிறகு தானாகவே முடியும். இயங்கும் Codex மற்றும் Grok session-கள் அவை தொடங்கிய account-இலேயே இருக்கும். Conversation history, settings, skill-கள், மற்றும் plugin-கள் account-கள் முழுவதும் பகிரப்படுகின்றன, எனவே அதே folder-இல் `claude --continue` நீங்கள் புதிய account-இல் விட்ட இடத்திலிருந்து தொடரும்.

ஒன்றுக்கு மேற்பட்ட account இருக்கும்போது, panel ஒவ்வொரு account இன் வரம்புகளையும் பக்கத்திற்கு பக்கம் காட்டும், active ஆனது குறிக்கப்பட்டிருக்கும். இயல்பாக active account வரம்பின் 95% ஐக் கடக்கும்போது Omarchy உங்களுக்கு அறிவிக்கும், அறிவிப்பை click செய்வது மிக அதிக headroom உள்ள account-க்கு மாற்றும். panel-இல் account இன் வரியின் மீது hover செய்து Use-க்கு அருகில் தோன்றும் Autoswitch-ஐ click செய்யவும் (அல்லது `m` அழுத்தவும்), அல்லது `omarchy agent account mode auto` இயக்கவும், அது தானாகவே மாற; அது on-இல் இருக்கும்போது, Autoswitch Use இன் இடத்தை எடுக்கும், அதை மீண்டும் click செய்வது அறிவிப்பதற்குத் திரும்பும். threshold-ஐ மாற்ற எண்ணைச் சேர்க்கவும், `omarchy agent account mode auto 90` போல. ஒவ்வொரு account-உம் threshold-க்கு மேல் இருந்தால், எந்த account முதலில் விடுவிக்கப்படும் என்பதுடன் ஒரு முறை அதைக் கேட்பீர்கள். active account அதன் threshold-இலிருந்து 15 புள்ளிகளுக்குள் இருக்கும்போது (இயல்புநிலையில் 80%), அதன் வரம்புகள் ஒவ்வொரு 15-க்கு பதிலாக ஒவ்வொரு மூன்று நிமிடங்களுக்கும் சரிபார்க்கப்படும்.

`omarchy agent account list` ஒவ்வொரு account-ஐயும் அதன் சமீபத்திய வரம்புகளையும் காட்டுகிறது, `omarchy agent account remove work` ஒன்றை மறக்கிறது, மற்றும் `omarchy agent account rename primary Hey` ஒன்றை மறுபெயரிடுகிறது (அல்லது panel-இல் account இன் பெயரை click செய்யவும்). இந்தக் கட்டளைகள் உங்கள் இயல்புநிலை agent இன் account-களில் செயல்படும்; மற்ற provider-ஐ அடைய, `omarchy agent account use codex side` போல முதலில் அதைப் பெயரிடவும். `~/.claude` அல்லது `~/.codex`-இல் நீங்கள் ஏற்கனவே வைத்திருந்த login _Main_ account ஆகும். Codex இனது அது இருக்கும் இடத்திலேயே இருக்கும்; மற்றொரு account active ஆக இருக்கும்போது Claude இனது அதற்கென தனி folder-இல் காத்திருக்கும். சுமார் எட்டு மணி நேரத்திற்கு மேல் பயன்படுத்தப்படாத account _Sign-in required_ எனக் காட்டக்கூடும்; panel-இலேயே அந்த account-ஐ மீண்டும் உள்நுழைய அதை click செய்யவும், அல்லது அதற்கு மாறி ஒரு session-ஐத் தொடங்கவும், அது sign-in-ஐ தானாகவே புதுப்பிக்கும். நீங்கள் `claude mcp add` உடன் சேர்க்கும் MCP server-கள் ஒவ்வொரு Claude account-ஐயும் அடையும், ஏனெனில் அவை அனைத்தும் `~/.claude`-இல் இயங்கும்; Codex மற்றும் Grok-க்கு, account சேர்க்கப்பட்டபோது உங்களிடம் இருந்த server-கள் அதற்கும் வரும், ஆனால் பின்னர் சேர்க்கப்பட்டவை நீங்கள் அவற்றைச் சேர்த்த account-ஐ மட்டுமே அடையும். Claude Desktop அதற்கென தனி sign-in-ஐ வைத்திருக்கும், மேலும் CLI binary-க்கான absolute path உடன் கட்டமைக்கப்பட்ட Codex அல்லது Grok கருவிகள் switch-ஐப் பின்பற்றாது. வெளிப்படையான `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, அல்லது `GROK_HOME` தேர்ந்தெடுக்கப்பட்ட account-ஐ விட முன்னுரிமை பெறும்.

### செயலிழப்பு கண்டறிதல்

Omarchy process crash-களுக்காக systemd-coredump-ஐக் கண்காணிக்கிறது. நீங்கள் இயல்புநிலை agent-ஐத் தேர்ந்தெடுத்த பிறகு, core dump செய்யும் உங்கள் எந்த program-உம் "Process crashed" அறிவிப்பைக் கொண்டுவரும் — அதை click செய்யவும், crash உங்கள் இயல்புநிலை agent-இடம் Omarchy இன் omarchy-diagnose-crash skill உடன் ஒப்படைக்கப்படும், அது core dump-இலிருந்து உண்மைகளை நிறுவுவதன் வழியாக agent-ஐ வழிநடத்தி crash-ஐ upstream-இல் புகாரளிக்கத் தகுதியானதா என முடிவு செய்யும். `coredumpctl list`-இலிருந்து எந்த PID-க்கு எதிராகவும் `omarchy agent crash <pid>` உடன் அதை கையால் இயக்கவும் முடியும்.

கண்காணிப்பு இயல்பாக on-இல் உள்ளது. _Trigger > Toggle > Crash Capture Off_ கீழ் (அல்லது `omarchy toggle crash-capture` உடன்) அதை முடக்கவும், அறிவிப்புகள் நின்றுவிடும்; `omarchy agent crash <pid>` கையால் இன்னும் செயல்படும்.

Crash-களை ஒரு நேரத்தில் ஒரு program வீதம் அமைதிப்படுத்தவும் முடியும், diagnosis இறுதியில் உங்களுக்கு வழங்குவது அதுதான். `omarchy crash mute hyprland` அந்த program-க்கு மட்டும் அறிவிப்புகளை நிறுத்துகிறது, `omarchy crash mute hyprland off` அவற்றைத் திரும்பக் கொண்டுவருகிறது, மேலும் `omarchy crash mute` தனியாக நீங்கள் mute செய்தவற்றைப் பட்டியலிடுகிறது. இது binary இன் path-ஐ அதன் பெயரைப் போலவே மகிழ்ச்சியுடன் ஏற்கிறது, எனவே `omarchy crash mute /usr/bin/hyprland` அதே செயலைச் செய்கிறது. இடைவெளி உள்ள பெயரை quote செய்யவும், `omarchy crash mute 'Some App'` போல. மற்ற அனைத்தும் இன்னும் அறிவிக்கும், mute செய்யப்பட்ட program இன்னும் செயலிழக்கும் — இது நினைவூட்டலை மறைக்கிறது, எதையும் சரிசெய்யாது.

### Desktop பயன்பாடுகள்

_Install > AI_ menu சில graphical AI app-களையும் கொண்டுள்ளது: Amp Desktop, Antigravity Desktop, ChatGPT desktop app, Claude desktop app (Anthropic இன் Linux beta, Chat, Cowork, மற்றும் Claude Code tab-களுடன்), xAI இன் model-களுடன் அரட்டையடிக்க Grok Bot, Herdr Desktop, Hermes Desktop, OpenClaw, Perplexity desktop app, மற்றும் T3 Code. Grok Bot என்பது desktop chat app ஆகும். coding agent என்பது `grok` கட்டளை ஆகும்.

Hermes Desktop தெரிந்து கொள்ள வேண்டிய ஒன்று, ஏனெனில் ஒரு machine-க்கு ஒரு Hermes உள்ளது, அது app இனது: Hermes எப்போதும் app வழியாக மட்டுமே நிறுவப்படும், மேலும் இயல்புநிலை agent இயக்கும் `hermes` கட்டளை app இனதே. Hermes-ஐ இயல்புநிலை agent ஆகத் தேர்ந்தெடுப்பது _Install > AI_ உள்ளீடு செய்வதையே நிறுவுகிறது: package, மற்றும் Hermes இன் சொந்த installer மூலம் அமைக்கப்பட்ட `~/.hermes` கீழ் Hermes runtime, முதல் முறை சில நிமிடங்கள் எடுக்கும். அந்த runtime தான் terminal `hermes` கட்டளை, இயல்புநிலை agent மற்றும் app அனைத்தும் பயன்படுத்தும் ஒரே Hermes, மேலும் அது Omarchy வெளியீட்டிற்காகக் காத்திராமல் `hermes update` உடன் தானாகவே புதுப்பிக்கிறது. அதை நிறுவுவது Hermes-க்கு Omarchy theme-ஐ `omarchy` என்ற skin ஆகவும் வழங்குகிறது, நீங்கள் theme-களை மாற்றும்போது ஒவ்வொரு Hermes surface-உம் அதைப் பின்பற்றும்; நீங்கள் அது வேண்டாம் என்றால் Hermes இன் Appearance settings கீழ் அல்லது `/skin` உடன் மற்றொன்றைத் தேர்ந்தெடுக்கவும், Omarchy அந்தத் தேர்வை அப்படியே விட்டுவிடும். _Remove > AI_ கீழ் app-ஐ அகற்றுவது முதலில் Hermes-ஐ மூடும், gateway உட்பட, அந்த runtime-ஐ அதனுடன் எடுத்துச் செல்லும், மேலும் நீங்கள் வேறுவிதமாகச் சொல்லாவிட்டால் உங்கள் chat-கள், நினைவுகள், மற்றும் Hermes தனக்காக எழுதிய skill-களை வைத்திருக்கும்: அந்த data மற்றும் உங்கள் connection settings-உம் செல்ல வேண்டுமா என அது கேட்கும், இயல்பாக no என.

OpenClaw இன் desktop அனுபவம் அதன் Control UI ஆகும், அது அதன் சொந்த local gateway ஆதரவுடன் web app ஆகத் திறக்கும். OpenClaw `~/.openclaw`-இல் வாழ்கிறது மற்றும் தானாகவே புதுப்பிக்கிறது: Control UI இன் "Update Gateway" button-ஐப் பயன்படுத்தவும் அல்லது `openclaw update` இயக்கவும், gateway புதிய பதிப்பில் மறுதொடக்கம் செய்யும். புதிய நிறுவல் எந்த வெளியீட்டிலிருந்து தொடங்கும் என்பதை மட்டுமே Omarchy தேர்ந்தெடுக்கிறது. OpenClaw உங்கள் இயல்புநிலை agent-ஆகவும் இருக்க முடியும்: _Agent > Harness_ கீழ் அதைத் தேர்ந்தெடுப்பது `~/.openclaw`-இல் அதே நகலை அமைக்கிறது, மேலும் agent அதன் gateway-உடன் இணைக்கப்பட்ட OpenClaw இன் terminal UI-ஐத் திறக்கிறது. _Remove > AI_ கீழ் OpenClaw-ஐ அகற்றுவது gateway service மற்றும் app-ஐ அதனுடன் எடுத்துச் செல்லும், பின்னர் `~/.openclaw` கூட செல்ல வேண்டுமா எனக் கேட்கும், ஏனெனில் அது OpenClaw மற்றும் அது download செய்யும் plugin runtime-களுடன் உங்கள் chat-கள் மற்றும் credential-களை வைத்திருக்கிறது; இயல்புநிலை அதை வைத்திருக்கும், மேலும் OpenClaw-ஐ மீண்டும் நிறுவுவது அதை மீண்டும் எடுத்துக்கொள்ளும்.

Herdr Desktop என்பது [Herdr](https://herdr.dev) desktop app ஆகும்: நீங்கள் window-வை மூடும்போது அதன் core-இல் தொடர்ந்து இயங்கும் terminal-கள் மற்றும் coding agent-களின் space-கள், tab-கள், மற்றும் pane-கள். இது package-ஐ விட Herdr இன் சொந்த installer-இலிருந்து வருகிறது, எனவே அது `~/.local/share/herdr-app`-இல் வாழ்கிறது, உங்களிடம் ஏற்கனவே ஒன்று இல்லாதபோது அதன் core-ஐ `~/.local/bin/herdr-core`-இல் கொண்டுவருகிறது, மேலும் இரண்டையும் தானாகவே புதுப்பிக்கிறது. அது Omarchy `Super + Ctrl + Return`-இல் வழங்கும் `herdr` கட்டளைக்கு அருகில் அமர்ந்திருக்கிறது, அதை மாற்றாமல், மேலும் அந்தக் கட்டளையின் direct key-களைப் பெறுகிறது: `Alt + Return` மற்றும் `Alt + Shift + Return` pane-ஐ கீழே அல்லது வலதுபுறம் பிரிக்கும், `Alt + Escape` அதை மூடும், `Ctrl + Alt + Arrow` pane-களுக்கிடையே நகரும், `Alt + 1..9` மற்றும் `Alt + Left/Right` tab-ஐத் தேர்ந்தெடுக்கும், மேலும் `Alt + Up/Down` space-களுக்கிடையே நகரும். `Ctrl + 1..9` space-ஐத் தேர்ந்தெடுக்கும் மற்றும் `Alt + Shift + Up/Down` agent-கள் வழியாகச் செல்லும். `Ctrl + Space` prefix key-கள் terminal-க்கு மட்டுமே இருக்கும், ஏனெனில் app ஒரு sequence-க்காக சாதாரண Ctrl key-ஐ வைத்திருக்க முடியாது. Omarchy இவற்றை `~/.config/herdr-app/keys.json`-இல் எழுதுகிறது, மேலும் `omarchy-refresh-herdr-app` அவற்றை மீண்டும் வைக்கிறது. அதை நிறுவுவது Herdr இன் Omarchy theme-ஐத் தேர்ந்தெடுக்கிறது, அது அதன் பிறகு உங்கள் Omarchy theme-ஐப் பின்பற்றும். Herdr light mode-க்கு ஒரு theme-ஐயும் dark-க்கு ஒன்றையும் வைத்திருக்கிறது, எனவே dark மற்றும் light Omarchy theme-களுக்கிடையே மாறிய பிறகு, மற்ற mode-க்காக Herdr இன் theme picker-இல் Omarchy-ஐ மீண்டும் ஒருமுறை தேர்ந்தெடுக்கவும்.

T3 Code package-ஐ விட `~/.local/share/t3code`-இல் அதன் அதிகாரப்பூர்வ AppImage வெளியீட்டிலிருந்து இயங்குகிறது, எனவே அது தானாகவே புதுப்பிக்கிறது. அதை நிறுவுவது Stable அல்லது Nightly channel-இல் தொடங்க வேண்டுமா எனக் கேட்கும்; பின்னர் T3 Code இன் settings-இல் மாற்றவும். உங்கள் thread-கள் மற்றும் settings `~/.t3`-இல் வாழ்கின்றன, மேலும் _Remove > AI_ கீழ் T3 Code-ஐ அகற்றுவது அவற்றை அதனுடன் எடுத்துச் செல்லும்.

### உள்ளூர் model-கள்

உங்கள் coding agent-களுக்காக உங்கள் சொந்த machine-இல் open model-ஐ இயக்கவும். உங்கள் prompt-கள் மற்றும் code machine-இலேயே இருக்கும்; model-க்கு அனுப்பப்படும் எதுவும் அதை விட்டு வெளியேறாது. இதனுடன் தொடங்கவும்:

```bash
omarchy models use best text
```

அது இந்த machine-க்கான சிறந்த text model-ஐ அமைக்கிறது, உங்கள் agent-கள் பயன்படுத்தும் வகை. Image, video மற்றும் music model-களுக்கு அவற்றுக்கென சிறந்தது உள்ளது: `omarchy models use best image`, `video` அல்லது `music`. இந்த machine-க்கான ஒவ்வொரு வகையின் தேர்வையும் பார்க்க `omarchy models use best` இயக்கவும்.

அல்லது மேல் bar-இல் agents icon-க்கு அடுத்ததாக அதன் sparkles icon-இலிருந்து, அல்லது Super + Ctrl + Alt + X உடன் local models panel-ஐத் திறந்து, + தேர்ந்தெடுக்கவும். model இந்த machine-க்குப் பொருந்தும்போது icon தோன்றும். model-களை இயக்கும் Podman Omarchy உடன் வருகிறது, NVIDIA machine-இல் NVIDIA இன் container toolkit உம், அது அவற்றுக்கு GPU-ஐ வழங்குகிறது; ஏதேனும் ஒன்று இல்லாவிட்டால், முதல் அமைப்பு அதை நிறுவும். பின்னர் Omarchy இந்த machine-க்கு பரிந்துரைக்கப்பட்ட model-ஐத் தேர்ந்தெடுத்து, அதை download செய்து, தொடங்கும். பல பத்து GB download மற்றும் model இயங்கும்போது machine இன் பெரும்பாலான நினைவகம் பயன்பாட்டில் இருக்கும் என எதிர்பார்க்கவும்: Flash Next அதன் முழு 256K context உடன் சுமார் 100 GiB பயன்படுத்துகிறது. மற்ற model-கள் அதற்குத் தேவையான நினைவகத்தை வைத்திருந்தால், அது நிறுத்தப்பட்ட நிலையில் அமைக்கப்படும், நீங்கள் ஒன்றை நிறுத்தியவுடன் தொடங்கத் தயாராக இருக்கும். model logout-இல் நிற்கும்; உங்களுக்கு வேறு ஏதாவதற்கு நினைவகம் தேவைப்படும்போது அதை நீங்களே நிறுத்தவும்.

`omarchy models list` விருப்பங்களைக் காட்டுகிறது மற்றும் சில ஏன் பொருந்தாது என விளக்குகிறது. மற்றொன்றை அமைக்க, `omarchy models use <recipe>` இயக்கவும். இன்று, 128 GB Strix Halo machine-களுக்கு `qwen3.8-flash-next-gufo` மற்றும் `qwen3.8-27b-gufo` கிடைக்கின்றன; 27B சுமார் 40 GiB எடுக்கும், எனவே அது மற்ற வேலைகளுக்கு இடம் விடுகிறது. Intel இன் Arc B390 உடன் 64 GB laptop-இல், `qwen3.6-35b-a3b-llamacpp` சுமார் 30 GiB-இல் இயங்குகிறது. புதிய recipe-கள் மற்றும் பரிந்துரைகள் package வழியாக `omarchy update` உடன் வருகின்றன.

நீங்கள் அமைக்கும் ஒவ்வொரு model-க்கும் local models panel-இல் அதற்கென தனி வரி கிடைக்கும்: அதைத் தொடங்க play, அதை நிறுத்தி அதன் நினைவகத்தை விடுவிக்க pause, மற்றும் அதில் உங்கள் agent-ஐத் திறக்க terminal button. மேலே, Omarchy-க்கே (system மற்றும் உங்கள் app-கள்), ஒவ்வொரு இயங்கும் model, மற்றும் இலவசமாக உள்ளது இடையே machine இன் நினைவகம் எவ்வாறு பிரிக்கப்பட்டுள்ளது என ஒரு bar காட்டுகிறது. நிறுத்தப்பட்ட model-ஐச் சுட்டிக்காட்டவும், bar அது பொருந்துமா, அல்லது எவ்வளவு குறைவாக உள்ளது எனக் காட்டும். நினைவகத்தில் ஒன்றாகப் பொருந்தும்போது பல ஒரே நேரத்தில் இயங்க முடியும்; ஒன்று பொருந்தவில்லை என்றால், எந்த இயங்கும் model-ஐ நிறுத்த வேண்டும் என Omarchy கூறும். அவற்றை மறுவரிசைப்படுத்த அவற்றின் logo மூலம் வரிகளை இழுக்கவும், மேலும் model மற்றும் அதன் download-ஐ அகற்ற தேர்ந்தெடுக்கப்பட்ட வரியில் Delete அழுத்தவும்.

நீங்கள் அமைக்கும் ஒவ்வொரு coding model-க்கும் app launcher-இல் அதற்கென தனி உள்ளீடு கிடைக்கும், model இன் பெயரில் மற்றும் அதன் உருவாக்குநரின் logo உடன், Claude, Codex அல்லது Grok-இல் உள்நுழைவது ஒன்றைச் சேர்ப்பது போல. அது அந்த model-இல் உங்கள் agent-ஐத் திறக்கும், மேலும் அது இயங்கவில்லை என்றால் முதலில் model-ஐத் தொடங்கும்: terminal அது load ஆவதைக் காட்டி, அது தயாரானவுடன் agent-இடம் ஒப்படைக்கும். model-ஐ அகற்றுவது அதன் உள்ளீட்டை அகற்றும்.

ஒவ்வொரு model-உம் coding-க்காக அல்ல. Image, video மற்றும் music model-கள் அதற்கு பதிலாக Fantasi-இல் திறக்கும், இந்த machine-இல் இயங்கும் model உடன் படங்கள், video மற்றும் இசையை உருவாக்க Omarchy இன் app, அங்கே அல்லது local models panel-இல் அவற்றின் வரியிலிருந்து தேர்ந்தெடுக்கப்படும்.

model அது அமைக்கப்பட்டது போலவே தொடர்ந்து இயங்கும், எனவே Omarchy update உங்கள் agent-களின் கீழ் ஒன்றை ஒருபோதும் மறுதொடக்கம் செய்யாது. நீங்கள் அமைத்துள்ள model-க்கு Omarchy-இடம் புதிய runtime அல்லது புதிய weight-கள் இருக்கும்போது, அதன் வரி update button-ஐக் காட்டும்: அதை அழுத்தவும், model பின்னணியில் மீண்டும் அமைக்கப்படும், மாறியதை மட்டும் download செய்து, புதிய பதிப்பில் மறுதொடக்கம் செய்யும். நிறுத்தப்பட்ட model நிறுத்தப்பட்டே இருக்கும். `omarchy models update` terminal-இலிருந்து ஒவ்வொரு model-க்கும் அதையே செய்கிறது.

command line-இலிருந்து, `omarchy models start <recipe>` மற்றும் `omarchy models stop <recipe>` அதையே செய்கின்றன, `omarchy models status` ஒவ்வொரு model-ஐயும் காட்டுகிறது, மேலும் `omarchy agent --local` நீங்கள் கடைசியாகத் தொடங்கிய model-இல் உங்கள் இயல்புநிலை agent-ஐத் திறக்கிறது. pi, OpenCode மற்றும் Qwen Code ஒன்றைப் பயன்படுத்த முடியும்; வேறு எந்த இயல்புநிலையுடனும் அது pi-இல் திறக்கும், அல்லது உங்களிடம் pi இல்லாவிட்டால் OpenCode-இல். pi நீங்கள் அமைத்துள்ள ஒவ்வொரு model-ஐயும், மற்றும் நீங்கள் இணைத்துள்ள machine-களில் உள்ளவற்றையும், அதன் சொந்த model picker-இல் பட்டியலிடுகிறது, எனவே சாதாரண `pi` அவற்றையும் அடையும். எந்த OpenAI-compatible client-உம் இணைக்க முடியும்: `status` ஒவ்வொரு model இன் address-ஐயும் காட்டுகிறது (முதலாவது `http://127.0.0.1:11435/v1`), recipe பெயர் model ஆகும், மேலும் key `~/.config/omarchy/agent-local/key`-இல் உள்ளது.

`omarchy models remove <recipe>` model-ஐயும் வேறு எந்த model-உம் பயன்படுத்தாத download-களையும் நீக்குகிறது.

Third-party runtime-கள் அவற்றின் publisher உடன் label செய்யப்படுகின்றன. Omarchy ஒவ்வொரு model-ஐயும் network access இல்லாமல் இயக்குகிறது.

### உள்ளூர் LLM-கள்

Omarchy local LLM model-களை இயக்க இரண்டு வழிகளைப் பரிந்துரைக்கிறது: LM Studio மற்றும் Ollama. LM Studio open-weight model-களைக் கண்டறிந்து, நிறுவி, இயக்க GUI interface-ஐ வழங்குகிறது. எளிதாகத் தொடங்க இது சிறந்த வழி. Ollama அதையே போல செய்ய CLI-ஐ வழங்குகிறது. ஆனால் நீங்கள் local model-களுக்குப் புதியவர் என்றால், நான் LM Studio-உடன் தொடங்குவேன். Omarchy Menu-இல் _Install > AI_ கீழ் ஏதேனும் ஒன்றை நிறுவ முடியும்.

### Omarchy skill-கள்

Agent skill-கள் AI குறிப்பிட்ட கருவிகளைக் குறிப்பிட்ட வழியில் பயன்படுத்த உதவுகின்றன, மேலும் Omarchy அவற்றில் ஏழை வழங்குகிறது. omarchy skill உங்கள் Hyprland config-ஐ மாற்றுவது அல்லது bar-ஐ சரிசெய்வது போல system-ஐ வடிவமைப்பதை உள்ளடக்கும். omarchy-make-theme, omarchy-make-plugin, omarchy-make-app, மற்றும் omarchy-make-game புதிதாக ஒன்றை உருவாக்குவதை உள்ளடக்கும், omarchy-contribute bug-ஐப் புகாரளிப்பது அல்லது fix-ஐ upstream-க்கு அனுப்புவதை உள்ளடக்கும், மேலும் omarchy-diagnose-crash crash இன் core dump வழியாகச் செயல்படும். அவை Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` மற்றும் ஒவ்வொரு `~/.hermes/profiles/*/skills`), மற்றும் பொதுவான `~/.agents/skills` இருப்பிடத்திற்கான skill directory-களில் symlink செய்யப்படுகின்றன, எனவே பெரும்பாலான harness-கள் அவற்றைத் தானாகவே எடுத்துக்கொள்ளும். அதே பெயரில் உங்கள் சொந்த skill folder முன்னுரிமை பெறும்.

ஆனால் நீங்கள் இந்த skill-களை பரிசோதனை எனக் கருத வேண்டும். வெவ்வேறு model-கள் அதை வெவ்வேறு விளைவுக்குப் பயன்படுத்தும். முதலில் plan mode-இல் இயக்குவது சிறந்தது, எனவே agent எதை மாற்ற விரும்புகிறது என உங்களுக்கு ஒரு யோசனை கிடைக்கும். பின்னர் மாற்றங்களை rollback செய்ய அல்லது agent எல்லாவற்றையும் குழப்பினால் `omarchy reinstall configs`-ஐக் கூட அழைக்கத் தயாராக இருங்கள்.
