# AI

Omarchy உங்களுக்கு இயல்புநிலையைத் தேர்ந்தெடுக்காமல், கீழே உள்ள குறியீட்டு முகவர்களுக்கான தொடக்கிகளை உள்ளடக்கியுள்ளது. ஒரு கட்டளையை இயக்கினால் முதல் பயன்பாட்டில் அதன் CLI நிறுவப்படும், பின்னர் கேட்கும்போது அங்கீகரிக்கவும். Hermes இதற்கு விதிவிலக்கு: முதல் பயன்பாட்டில் அதற்கு எதுவும் நிறுவப்படாது, அதைத் தேர்ந்தெடுப்பது Hermes Desktop-ஐ நிறுவும், கீழே உள்ள _Desktop apps_ விளக்குவது போல.

### முகவர்களை நிறுவுதலும் புதுப்பித்தலும்

Hermes-ஐத் தவிர, இந்த முகவர்கள் mise-இன் lazy நிறுவலைப் பயன்படுத்துகிறார்கள்: முதல் தொடக்கம் CLI-ஐ நிறுவும், பின்னர் வரும் தொடக்கங்கள் அதையே மீண்டும் பயன்படுத்தும். mise ஒரு நிறுவப்பட்ட முகவருக்கு புதிய வெளியீடு உள்ளதா என நான்கு மணி நேரத்திற்கு ஒரு முறைக்கு மேல் சரிபார்க்காது, அது தொடங்குவதற்குச் சற்று முன் அல்லது shell prompt-இல் பின்னணியில். அந்தப் புதுப்பிப்பு தோல்வியடைந்தால் அல்லது நீங்கள் offline-இல் இருந்தால், நிறுவப்பட்ட பதிப்பு இயங்கும். `omarchy update` நிறுவப்பட்ட முகவர்களை Omarchy-இன் மற்ற பகுதிகளுடன் புதுப்பிக்கிறது, மற்றும் `mup` mise-நிர்வகிக்கும் கருவிகளை மட்டும் புதுப்பிக்கிறது.

ஒரு முகவரின் சொந்தப் புதுப்பிப்பான், `claude update`, `codex update`, அல்லது ஒரு செயலியில் உள்ள புதுப்பிப்பு பொத்தான் போன்றவை, mise-நிர்வகிக்கும் நிறுவலைப் புதுப்பிக்காது. `codex update` தோல்வியடையும், மற்றும் `claude update` வெற்றி என அறிவித்துக்கொண்டே mise கண்காணிக்காத தனி நகலை நிறுவக்கூடும். நீங்கள் ஒரு முகவரின் சொந்த நிறுவி மற்றும் புதுப்பிப்பானையே பயன்படுத்த விரும்பினால், அதை `disable_tools`-இல் சேர்க்கவும்; [முன்பே நிறுவப்பட்ட CLI கருவிகள்](18-development-tools.md#preinstalled-cli-tools) பார்க்கவும்.

உங்களுக்குத் தேவைப்படுவதற்கு முன்பே உள்ளமைக்கப்பட்ட அனைத்து lazy கருவிகளையும் நிறுவ, `mise install --include-lazy` இயக்கவும். இதில் Omarchy-இன் மற்ற இயல்புநிலை CLI கருவிகளும் முகவர்களுடன் சேரும். ஒரு தனி கருவியை நிறுவ அல்லது உங்கள் சொந்த நிறுவலைப் பயன்படுத்த [முன்பே நிறுவப்பட்ட CLI கருவிகள்](18-development-tools.md#preinstalled-cli-tools) பார்க்கவும்.

`grok` mise-இன் first-party `grok` package மூலம் நிறுவப்படுகிறது, `claude` மற்றும் `codex` போலவே. `grok` இயக்கவும், அல்லது _Setup > Defaults > Agent_ கீழ் அதைத் தேர்ந்தெடுக்கவும். x.ai-இல் உள்ள `curl | bash` நிறுவியைத் தவிர்க்கவும். அந்த வழி இரண்டாவது நகலை `~/.grok/bin`-இல் வைக்கிறது, அதை `PATH`-இல் முன்னால் சேர்க்கிறது, மற்றும் Omarchy-இன் wrapper-ஐ மேலெழுதுகிறது.

`dsh` அதன் உலாவி UI-ஐ `127.0.0.1:3080`-இல் திறக்கிறது, தொடக்க அடைவை அதன் இயல்புநிலை workspace ஆகக் கொண்டு. அதன் உலாவி UI தொடக்க prompt-ஐ ஏற்காது, எனவே `omarchy agent prompt` அதை உங்கள் clipboard-இல் prompt-ஐ ஒட்டுவதற்காகக் கொண்டு திறக்கிறது. Omarchy அதை DeepSeek-இன் no-approval அனுமதி preset-உடன் தொடங்குகிறது. நீங்கள் அதன் அதிகாரப்பூர்வ மாடல் API-ஐப் பயன்படுத்தும்போது DeepSeek Harness அமர்வுப் பதிவுகளை DeepSeek-க்கு பதிவேற்றுகிறது; அதன் உலாவி UI-இல் _Settings > General > Upload Session Log_ கீழ் அதை அணைக்கவும். நீங்கள் அதற்கு அனுப்பும் கருத்தும் அமர்வுடன் பதிவேற்றப்படும், நீங்கள் அதை `DSH_TELEMETRY_MODE=DISABLED`-உடன் தொடங்கினால் தவிர.

### இயல்புநிலை முகவர்

உங்கள் இயல்புநிலை முகவரை `omarchy default agent <name>` உடன் அல்லது Omarchy Menu-வில் (`Super + Space`) _Setup > Defaults > Agent_ கீழ் தேர்ந்தெடுக்கவும். முகவர் இன்னும் நிறுவப்படவில்லை என்றால், அதைத் தேர்ந்தெடுப்பது முதலில் அதை நிறுவும். ஒரு புதிய Omarchy ஒரு முறை மட்டுமேயான அறிவிப்புடன் இந்தத் தேர்வைச் செய்ய உங்களை அழைக்கும்.

Claude-ஐத் தேர்ந்தெடுப்பது Chromium, Chrome, Brave, Brave Origin, மற்றும் Edge-க்கான அதன் உலாவி நீட்டிப்பையும் அமைக்க முயற்சிக்கிறது. நீட்டிப்பு அமைப்பு அனைத்து பயனர்களுக்கும் பொருந்தும் மற்றும் உங்கள் system password-ஐக் கேட்கக்கூடும்; ரத்து செய்வது அல்லது தோல்வியடைந்த நீட்டிப்பு நிறுவல் இருந்தாலும் Claude தேர்ந்தெடுக்கப்பட்டு தொடங்கப்படும். உங்கள் உலாவியை மறுதொடக்கம் செய்யவும், கேட்கப்பட்டால் நீட்டிப்பை இயக்கவும், மற்றும் அதை இணைப்பதை முடிக்க Claude-இல் உள்நுழையவும். இணைப்பைச் சரிபார்க்க Claude-இல் `/chrome` இயக்கவும். Firefox மற்றும் Zen இந்த நீட்டிப்பை ஆதரிக்காது. இந்த அமைப்பு சேர்க்கப்படுவதற்கு முன்பே Claude உங்கள் இயல்புநிலையாக இருந்தால், நீட்டிப்பை நிறுவ அதை மீண்டும் தேர்ந்தெடுக்கவும்.

நீங்கள் தேர்ந்தெடுத்த பிறகு, `Super + Shift + Ctrl + A` இயல்புநிலை முகவரை ஒரு பிரத்யேக terminal window-வில் தொடங்கும் (அல்லது நீங்கள் இன்னும் தேர்ந்தெடுக்கவில்லை என்றால் picker-ஐக் கொண்டுவரும்). நீங்கள் `omarchy agent prompt "Review this project"` உடன் அதை நேரடியாக ஒரு பணியிலும் தொடங்கலாம். Freebuff மற்றும் DeepSeek Harness தொடக்க prompt-ஐ ஏற்காது, எனவே அவை அதற்குப் பதிலாக உங்கள் clipboard-இல் prompt-ஐ ஒட்டுவதற்காகக் கொண்டு திறக்கும். இந்த வழியில் தொடங்கப்படும் முகவர்கள் அவரவரின் நிறுத்தி-கேட்காத முறைகளில் கவனிப்பின்றி இயங்குவார்கள், எனவே அவர்கள் உண்மையில் விஷயங்களைச் செய்யத் தயாராக இருங்கள்! MiniMax Code-க்கு அதன் ஊடாடும் அமர்வுகளுக்கு அத்தகைய முறை இல்லை, எனவே அது வழக்கம் போல அனுமதிகளைக் கேட்கும். மேலும் முகவர்கள் உங்கள் home directory-க்கு நம்பிக்கையை நினைவில் வைக்க மறுப்பதால், `$HOME`-இலிருந்து தொடங்குவது அதற்குப் பதிலாக `~/Work`-இல் தொடங்கும்.

Terminal குறுக்குவழிகளும் உள்ளன: `a` இயல்புநிலை முகவரை தற்போதைய terminal-இல் inline-ஆக இயக்குகிறது, அதே நேரத்தில் `c`, `cx`, மற்றும் `cy` OpenCode, Claude Code, மற்றும் Codex-ஐ நேரடியாகத் தொடங்கும் (மீண்டும் அவற்றின் auto-approving முறைகளில்). Theme மாற்றங்களும் முகவர்களுக்கு ஒத்திசைகின்றன: நீங்கள் Omarchy theme-ஐ மாற்றும்போது Claude Code, Pi, OpenCode, மற்றும் Hermes (Omarchy அதை நிறுவிய பிறகு) அனைத்தும் பின்தொடரும்.

### முகவர்கள் panel

மேல் பட்டையில் ஒரு முகவர்கள் icon உள்ளது. நீங்கள் ஒரு முகவரை அமைப்பதற்கு முன், அதன் panel Claude, Codex, அல்லது Grok-இல் உள்நுழைவதன் வழியாக உங்களை நடத்தும், மற்றும் முதலாவது உங்கள் இயல்புநிலை முகவராக மாறும். அதன் பிறகு, panel ஒவ்வொரு சந்தாவையும் ஒரே பக்கத்தில் வைக்கிறது: ஒவ்வொரு முகவரும் கணக்கும் அதன் திட்டத்துடன், அதன் 5-மணி நேர அமர்வு மற்றும் வாராந்திர வரம்புகள் ஒவ்வொன்றுக்கும் ஒரு meter உடன் அது மீட்டமைக்கப்படும் வரையிலான நேரத்துடன் (சரியான சதவீதத்திற்கு hover செய்யவும்), அல்லது மீதமுள்ள prepaid இருப்பு, அவை அனைத்திலும் நீங்கள் பயன்படுத்தியதைச் சுழற்றும் ஒரு வரியின் கீழ், இந்த வாரம் tokens மற்றும் நீங்கள் அதிகம் பயன்படுத்திய மாடல் போன்றவை. _Make something_ கீழ் அது புதிய theme, plugin, அல்லது செயலிக்கான தொடக்க prompt-களை வழங்குகிறது, அவை பணியை உங்கள் இயல்புநிலை முகவரிடம் ஒப்படைக்கும். செயலிகள் Omarchy-இன் சொந்த Hype, Monologue, மற்றும் Omacut போலவே, C++ மற்றும் Qt Quick-இல், omarchy-app agent skill-ஐப் பின்பற்றி உருவாக்கப்படுகின்றன, மற்றும் அவற்றுக்குத் தேவையான compiler மற்றும் Qt துண்டுகள் நிறுவப்பட்டு வரும். Claude Code, Codex, Grok, Kimi, Cursor மற்றும் அதன் Grok Bot அனுமதி, GitHub Copilot, Muse, Antigravity, Kimchi, மற்றும் Devin ஆகியவை அவற்றின் வரம்புகளுடன் தொடக்கத்திலிருந்தே உள்ளடக்கப்பட்டுள்ளன, மற்றும் Hermes, Mistral Vibe, மற்றும் Qwen Code நீங்கள் அவற்றைப் பயன்படுத்திய பிறகு அவற்றின் அமர்வுகள் மற்றும் tokens-ஐக் காட்டும். நீங்கள் pi, omp, அல்லது opencode மூலம் பயன்படுத்தும் Provider திட்டங்கள் மற்றும் key-களும் தோன்றும்: OpenCode Zen மற்றும் Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan, மற்றும் Synthetic அவற்றின் வரம்புகளுடன்; Fireworks, OpenRouter, மற்றும் DeepSeek அவற்றின் prepaid இருப்புகளுடன்; மற்றும் Local models கீழ் உங்கள் சொந்த hardware-இல் நீங்கள் இயக்கும் மாடல்கள். ஒவ்வொரு முகவரும் ஒரு முறை மட்டுமே கணக்கிடப்படுகிறது, அதற்கு யார் கட்டணம் வசூலிக்கிறார்களோ அவரின் கீழ், நீங்கள் எத்தனை harness-கள் மூலம் அதை இயக்கினாலும்.

Panel-க்கு பட்டை icon-ஐ இடது-கிளிக் செய்யவும், உங்கள் இயல்புநிலை முகவரைத் தொடங்க வலது-கிளிக் செய்யவும். அதன் பின்னால் உள்ள பயன்பாட்டுப் பதிவுகள் ஒவ்வொரு 15 நிமிடங்களுக்கும் `omarchy agent usage-update` மூலம் மீண்டும் உருவாக்கப்படுகின்றன, மற்றும் panel ஒரு ஒத்திசைக்கப்பட்ட folder வழியாக உங்கள் மற்ற இயந்திரங்களிலிருந்து பயன்பாட்டை இணைக்கவும் முடியும். முழு அமைப்புகளுக்கு `$OMARCHY_PATH/shell/plugins/agents/` கீழ் உள்ள README-ஐப் பார்க்கவும்.

### பல சந்தாக்கள்

நீங்கள் ஒன்றுக்கு மேற்பட்ட Claude, Codex, அல்லது Grok திட்டத்திற்கு பணம் செலுத்தினால் — தனிப்பட்ட Max மற்றும் பணியிடத்திற்கான ஒன்று என்று வைத்துக்கொள்வோம் — Omarchy அவை அனைத்தையும் உள்நுழைந்த நிலையில் வைத்து அவற்றுக்கிடையே நகர முடியும். முகவர்கள் panel-இல் உள்ள + உடன் ஒரு சந்தாவைச் சேர்க்கவும், அது அங்கேயே உங்களை அதன் வழியாக நடத்தும், அல்லது `omarchy agent account add claude Work` உடன் (அல்லது `codex`, அல்லது `grok`). அது இல்லையென்றால் CLI-ஐ நிறுவும். ஒரு provider-க்கான முதல் கணக்கு உங்கள் சாதாரண உலாவி மூலம் உள்நுழைகிறது, CLI எப்போதும் பார்க்கும் இடத்திலேயே. அதன் பிறகு வரும் ஒவ்வொன்றும் ஒரு private window மூலம் உள்நுழைகிறது, எனவே உங்கள் உலாவி ஏற்கனவே உள்நுழைந்துள்ள கணக்கு தவறுதலாக எடுக்கப்படாது; அங்கு நீங்கள் சேர்க்கும் கணக்காக உள்நுழையவும், மற்றும் நீங்கள் ஏற்கனவே திறந்து வைத்திருந்த எந்த private window-வையும் முதலில் மூடவும். இதைச் செய்ய CLI-இலிருந்து ஒருபோதும் வெளியேற வேண்டாம்: வெளியேறுவது சேமிக்கப்பட்ட உள்நுழைவை ரத்து செய்யும், மற்றும் அந்தக் கணக்கு மீண்டும் சேர்க்கப்பட வேண்டியிருக்கும்.

உங்கள் சந்தா உள்நுழைவுகளை SSH வழியாக மற்றொரு Omarchy இயந்திரத்திற்கு நகலெடுக்க, `omarchy agent account copy user@laptop` இயக்கவும். இலக்கில் ஒன்று நிறுவப்படவில்லை என்றால் அனுப்புபவர் ஒரு தற்காலிக receiver-ஐ வழங்குகிறார், எனவே பழைய Omarchy இயந்திரங்கள் புதுப்பிப்பு இல்லாமல் கணக்குகளைப் பெற முடியும். நிறுவப்பட்ட receiver-கள் முன்னுரிமை பெறும். இது அனைத்து Claude, Codex, மற்றும் Grok சந்தாக்களையும் நகலெடுக்கிறது; அவற்றைத் தேர்ந்தெடுக்க provider பெயர்களைச் சேர்க்கவும், `omarchy agent account copy laptop claude` போல. கணக்குப் பெயர்கள் மற்றும் கட்டளை ID-கள் மூலத்துடன் பொருந்தும், இலக்கில் ஏற்கனவே உள்ள கணக்குகள் உட்பட. தொடர்பில்லாத இலக்குக் கணக்குகள் அவற்றின் பெயர்கள் முரண்பட்டால் எண் பின்னொட்டைப் பெறும், மற்றும் அமைப்புகள், skills, plugins, மற்றும் உரையாடல் வரலாறு ஒவ்வொரு இயந்திரத்திற்கும் உள்ளூராகவே இருக்கும்.

ஏற்கனவே உள்ள இலக்கு credentials வைக்கப்படும். அங்கு ஏற்கனவே உள்நுழைந்துள்ள ஒரு மூலக் கணக்கு அதன் credentials-ஐ மாற்றாமல் அதன் பெயரை ஒத்திசைக்கிறது; மற்ற கணக்குகள் அதனுடன் சேர்க்கப்படும். பொருந்தும் கணக்குகளுக்கான சேமிக்கப்பட்ட credentials-ஐ மாற்ற, இலக்கில் அந்தக் கணக்கின் அமர்வுகளை விட்டு வெளியேறிய பிறகு `omarchy agent account copy --replace laptop claude` பயன்படுத்தவும். ஒரு புதிய இலக்கு மூலத்தின் செயலில் உள்ள கணக்கு மற்றும் மாற்றும் விருப்பங்களையும் பெறும்; ஒரு நிறுவப்பட்ட இலக்கு தன்னுடையதை வைத்துக்கொள்ளும்.

Credentials SSH வழியாகப் பயணித்து இலக்கில் private கோப்புகளில் சேமிக்கப்படும், எனவே நீங்கள் நம்பும் இயந்திரங்களுக்கு மட்டும் நகலெடுக்கவும். இது ஒரு முறை நகல், தொடர்ச்சியான ஒத்திசைவு அல்ல. Codex refresh tokens மற்றொரு இயந்திரத்தால் சுழற்றப்படலாம், நகலெடுக்கப்பட்ட உள்நுழைவுக்கு புதுப்பிப்பு தேவைப்படும் நிலையை விட்டு; பல இயந்திரங்களில் ஒரே நேரத்தில் பயன்படுத்த தனித்தனி உள்நுழைவுகளே மிகவும் நம்பகமான தேர்வாக இருக்கும். [Codex-இன் கணக்கு அங்கீகார வழிகாட்டுதல்](https://developers.openai.com/codex/auth/ci-cd-auth) பார்க்கவும்.

ஒரு provider-க்கு ஒரு கணக்கு செயலில் உள்ளது, மற்றும் ஒவ்வொரு புதிய அமர்வும் அதுவாகவே தொடங்குகிறது: `cx`, `cy`, ஒரு எளிய `claude`, `codex`, அல்லது `grok`, `omarchy agent` மூலம் தொடங்கப்படும் எதுவும், மற்றும் `PATH`-இல் CLI-ஐக் கண்டறியும் script-கள் அல்லது editor-கள். `omarchy agent account use work` உடன் மாற்றவும் (மற்றும் `omarchy agent account use main` உடன் திரும்பவும்), அல்லது panel-இல் ஒரு கணக்கின் எண்ணை அழுத்தி பின்னர் `Enter` அழுத்துவதன் மூலம் (அல்லது அதன் Use பொத்தானைக் கிளிக் செய்வதன் மூலம்). ஏற்கனவே இயங்கும் அமர்வுகள் அவை தொடங்கிய கணக்கிலேயே இருக்கும். உரையாடல் வரலாறு, அமைப்புகள், skills, மற்றும் plugins கணக்குகள் முழுவதும் பகிரப்படும், எனவே அதே folder-இல் `claude --continue` நீங்கள் புதிய கணக்கில் விட்ட இடத்திலிருந்து தொடரும்.

ஒன்றுக்கு மேற்பட்ட கணக்குடன், panel ஒவ்வொரு கணக்கின் வரம்புகளையும் அருகருகே காட்டும், செயலில் உள்ளது குறிக்கப்பட்டு. இயல்பாக Omarchy செயலில் உள்ள கணக்கு ஒரு வரம்பின் 95%-ஐக் கடக்கும்போது உங்களுக்கு அறிவிக்கும், மற்றும் அறிவிப்பைக் கிளிக் செய்வது அதிக இடவசதி உள்ள கணக்குக்கு மாறும். Panel-இல் ஒரு கணக்கின் வரியில் hover செய்து Use-க்கு அருகில் தோன்றும் Autoswitch-ஐக் கிளிக் செய்யவும் (அல்லது `m` அழுத்தவும்), அல்லது அது தானாகவே மாற `omarchy agent account mode auto` இயக்கவும்; அது இயக்கத்தில் இருக்கும்போது, Autoswitch Use-இன் இடத்தை எடுக்கும், மற்றும் அதை மீண்டும் கிளிக் செய்வது அறிவிப்பதற்குத் திரும்பும். வரம்பை மாற்ற ஒரு எண்ணைச் சேர்க்கவும், `omarchy agent account mode auto 90` போல. ஒவ்வொரு கணக்கும் வரம்புக்கு மேல் இருந்தால், எந்தக் கணக்கு முதலில் விடுபடுகிறது என்பதுடன் ஒரு முறை அதைக் கேட்பீர்கள். செயலில் உள்ள கணக்கு அதன் வரம்பிலிருந்து 15 புள்ளிகளுக்குள் இருக்கும்போது (இயல்புநிலையில் 80%), அதன் வரம்புகள் ஒவ்வொரு 15 நிமிடங்களுக்குப் பதிலாக ஒவ்வொரு மூன்று நிமிடங்களுக்கும் சரிபார்க்கப்படும்.

`omarchy agent account list` ஒவ்வொரு கணக்கையும் அதன் சமீபத்திய வரம்புகளையும் காட்டுகிறது, `omarchy agent account remove work` ஒன்றை மறக்கிறது, மற்றும் `omarchy agent account rename primary Hey` ஒன்றுக்கு மறுபெயரிடுகிறது (அல்லது panel-இல் ஒரு கணக்கின் பெயரைக் கிளிக் செய்யவும்). இந்தக் கட்டளைகள் உங்கள் இயல்புநிலை முகவரின் கணக்குகளில் செயல்படும்; மற்ற provider-ஐ அடைய, முதலில் அதன் பெயரைக் குறிப்பிடவும், `omarchy agent account use codex side` போல. நீங்கள் ஏற்கனவே `~/.claude` அல்லது `~/.codex`-இல் வைத்திருந்த உள்நுழைவு _Main_ கணக்கு மற்றும் அது இருக்கும் இடத்திலேயே இருக்கும். சுமார் எட்டு மணி நேரத்திற்கு மேல் பயன்படுத்தப்படாமல் விடப்பட்ட ஒரு கணக்கு _Sign-in required_ எனக் காட்டக்கூடும்; panel-இலேயே அந்தக் கணக்கை மீண்டும் உள்நுழைய அதைக் கிளிக் செய்யவும், அல்லது அதில் ஒரு அமர்வைத் தொடங்கவும், அது தானாகவே உள்நுழைவைப் புதுப்பிக்கும். ஒரு கணக்கு சேர்க்கப்பட்டபோது நீங்கள் வைத்திருந்த MCP server-கள் அதற்கு வரும், ஆனால் நீங்கள் பின்னர் `claude mcp add` உடன் சேர்ப்பவை நீங்கள் அவற்றைச் சேர்த்த கணக்கை மட்டுமே அடையும். Claude Desktop மற்றும் ஒரு CLI binary-க்கான absolute path உடன் உள்ளமைக்கப்பட்ட கருவிகள் மாற்றத்தைப் பின்பற்றாது. ஒரு வெளிப்படையான `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, அல்லது `GROK_HOME` தேர்ந்தெடுக்கப்பட்ட கணக்கை விட முன்னுரிமை பெறும்.

### செயலிழப்பு கண்டறிதல்

Omarchy செயல்முறை செயலிழப்புகளுக்காக systemd-coredump-ஐக் கண்காணிக்கிறது. ஏதாவது segfault ஆகும்போது, உங்களுக்கு ஒரு "Process crashed" அறிவிப்பு கிடைக்கும் — அதைக் கிளிக் செய்யவும், மற்றும் செயலிழப்பு உங்கள் இயல்புநிலை முகவரிடம் Omarchy-இன் diagnose-crash skill-உடன் ஒப்படைக்கப்படும், அது core dump-இலிருந்து உண்மைகளை நிறுவுவதன் வழியாகவும் செயலிழப்பை upstream-இல் புகாரளிப்பது மதிப்புள்ளதா என முடிவு செய்வதன் வழியாகவும் முகவரை நடத்தும். நீங்கள் `coredumpctl list`-இலிருந்து எந்த PID-க்கு எதிராகவும் `omarchy agent crash <pid>` உடன் அதைக் கையாலும் இயக்கலாம்.

கண்காணிப்பு இயல்பாக இயக்கத்தில் உள்ளது. அதை _Trigger > Toggle > Crash Capture_ கீழ் அணைக்கவும் (அல்லது `omarchy toggle crash-capture` உடன்) மற்றும் அறிவிப்புகள் நிற்கும்; `omarchy agent crash <pid>` இன்னும் கையால் செயல்படும்.

செயலிழப்புகளை ஒரு நேரத்தில் ஒரு நிரல் வீதமும் அமைதிப்படுத்தலாம், அதுவே கண்டறிதல் இறுதியில் உங்களுக்கு வழங்குவது. `omarchy crash mute hyprland` அந்த நிரலுக்கு மட்டும் அறிவிப்புகளை நிறுத்துகிறது, `omarchy crash mute hyprland off` அவற்றைத் திரும்பக் கொண்டுவருகிறது, மற்றும் `omarchy crash mute` தனியாக நீங்கள் அமைதிப்படுத்தியதைப் பட்டியலிடுகிறது. அது binary-இன் path-ஐ அதன் பெயரைப் போலவே மகிழ்ச்சியாக ஏற்கிறது, எனவே `omarchy crash mute /usr/bin/hyprland` அதே வேலையைச் செய்கிறது. இடைவெளி உள்ள பெயரை மேற்கோள் காட்டவும், `omarchy crash mute 'Some App'` போல. மற்ற அனைத்தும் இன்னும் அறிவிக்கும், மற்றும் அமைதிப்படுத்தப்பட்ட நிரல் இன்னும் செயலிழக்கும் — இது நினைவூட்டலை மறைக்கிறது, எதையும் சரிசெய்யாது.

### Desktop செயலிகள்

_Install > AI_ menu சில வரைகலை AI செயலிகளையும் கொண்டுள்ளது: ChatGPT desktop செயலி, Claude desktop செயலி (Anthropic-இன் Linux beta, Chat, Cowork, மற்றும் Claude Code tabs உடன்), xAI-இன் மாடல்களுடன் அரட்டையடிக்க Grok Bot, Hermes Desktop, OpenClaw, Perplexity desktop செயலி, மற்றும் T3 Code. Grok Bot என்பது desktop அரட்டைச் செயலி. குறியீட்டு முகவர் `grok` கட்டளை.

Hermes Desktop தான் தெரிந்து கொள்ள வேண்டிய ஒன்று, ஏனெனில் ஒரு இயந்திரத்தில் ஒரு Hermes உள்ளது, மற்றும் அது செயலியினுடையது: Hermes எப்போதும் செயலி மூலம் மட்டுமே நிறுவப்படுகிறது, மற்றும் இயல்புநிலை முகவர் இயக்கும் `hermes` கட்டளை செயலியினுடையது. Hermes-ஐ இயல்புநிலை முகவராகத் தேர்ந்தெடுப்பது _Install > AI_ உள்ளீடு செய்வதையே நிறுவுகிறது: package, மற்றும் Hermes-இன் சொந்த நிறுவியால் அமைக்கப்பட்ட `~/.hermes` கீழ் ஒரு Hermes runtime, இது முதல் முறை சில நிமிடங்கள் எடுக்கும். அந்த runtime தான் terminal `hermes` கட்டளை, இயல்புநிலை முகவர் மற்றும் செயலி அனைத்தும் பயன்படுத்தும் ஒரே Hermes, மற்றும் அது Omarchy வெளியீட்டிற்காகக் காத்திருக்காமல் `hermes update` உடன் தன்னைப் புதுப்பிக்கிறது. அதை நிறுவுவது Hermes-க்கு Omarchy theme-ஐ `omarchy` என்ற பெயரிடப்பட்ட skin ஆகவும் கொடுக்கிறது, நீங்கள் theme-களை மாற்றும்போது ஒவ்வொரு Hermes மேற்பரப்பும் அதைப் பின்பற்றும்; நீங்கள் அது வேண்டாம் என்றால் Hermes-இன் Appearance அமைப்புகளில் அல்லது `/skin` உடன் வேறொன்றைத் தேர்ந்தெடுக்கவும், மற்றும் Omarchy அந்தத் தேர்வை அப்படியே விட்டுவிடும். _Remove > AI_ கீழ் செயலியை நீக்குவது முதலில் Hermes-ஐ மூடும், gateway உட்பட, அந்த runtime-ஐ அதனுடன் எடுத்துச் செல்லும், மற்றும் உங்கள் அரட்டைகள், நினைவுகள், மற்றும் Hermes தனக்காக எழுதிய skills-ஐ வைத்துக்கொள்ளும், நீங்கள் வேறுவிதமாகச் சொன்னால் தவிர: அந்தத் தரவும் உங்கள் இணைப்பு அமைப்புகளும் செல்ல வேண்டுமா என அது கேட்கும், இயல்பாக இல்லை என.

OpenClaw-இன் desktop அனுபவம் அதன் Control UI, இது அதன் சொந்த local gateway-ஆல் ஆதரிக்கப்படும் web செயலியாகத் திறக்கிறது. OpenClaw `~/.openclaw`-இல் வாழ்கிறது மற்றும் தன்னைப் புதுப்பிக்கிறது: Control UI-இன் "Update Gateway" பொத்தானைப் பயன்படுத்தவும் அல்லது `openclaw update` இயக்கவும், மற்றும் gateway புதிய பதிப்பில் மறுதொடக்கம் செய்யும். Omarchy ஒரு புதிய நிறுவல் தொடங்கும் வெளியீட்டை மட்டும் தேர்ந்தெடுக்கிறது. _Remove > AI_ கீழ் OpenClaw-ஐ நீக்குவது gateway service மற்றும் செயலியை அதனுடன் எடுத்துச் சென்று பின்னர் `~/.openclaw` செல்ல வேண்டுமா எனக் கேட்கும், ஏனெனில் அது உங்கள் அரட்டைகள் மற்றும் credentials-ஐ OpenClaw மற்றும் அது பதிவிறக்கும் plugin runtime-களுடன் வைத்திருக்கிறது; இயல்புநிலை அதை வைத்துக்கொள்ளும், மற்றும் OpenClaw-ஐ மீண்டும் நிறுவுவது அதைத் திரும்ப எடுக்கும்.

T3 Code ஒரு package-இலிருந்து அல்லாமல் `~/.local/share/t3code`-இல் அதன் அதிகாரப்பூர்வ AppImage வெளியீட்டிலிருந்து இயங்குகிறது, எனவே அது தன்னைப் புதுப்பிக்கிறது. அதை நிறுவுவது Stable அல்லது Nightly channel-இல் தொடங்க வேண்டுமா எனக் கேட்கிறது; பின்னர் T3 Code-இன் அமைப்புகளில் மாற்றவும். உங்கள் thread-கள் மற்றும் அமைப்புகள் `~/.t3`-இல் வாழ்கின்றன, மற்றும் _Remove > AI_ கீழ் T3 Code-ஐ நீக்குவது அவற்றை அதனுடன் எடுத்துச் செல்கிறது.

### Local மாடல்கள்

உங்கள் குறியீட்டு முகவர்களுக்காக உங்கள் சொந்த இயந்திரத்தில் ஒரு திறந்த மாடலை இயக்கவும். உங்கள் prompt-கள் மற்றும் குறியீடு இயந்திரத்தில் தங்கும்; மாடலுக்கு அனுப்பப்படும் எதுவும் அதை விட்டு வெளியேறாது. இதனுடன் தொடங்கவும்:

```bash
omarchy agent local use best
```

அல்லது, மேல் பட்டையில் உள்ள முகவர்கள் panel-இல், + தேர்ந்தெடுத்து பின்னர் Local AI, இது ஒரு மாடல் இந்த இயந்திரத்திற்குப் பொருந்தும்போது தோன்றும். முதல் முறை, இது Podman-ஐ நிறுவுகிறது, இது மாடல்களை இயக்குகிறது. Omarchy பின்னர் இந்த இயந்திரத்திற்குப் பரிந்துரைக்கப்பட்ட மாடலைத் தேர்ந்தெடுத்து, அதைப் பதிவிறக்கி, தொடங்குகிறது. பத்துக்கணக்கான GB பதிவிறக்கத்தையும் மாடல் இயங்கும்போது இயந்திர நினைவகத்தின் பெரும்பகுதி பயன்பாட்டில் இருப்பதையும் எதிர்பார்க்கவும்: Flash Next அதன் முழு 256K context-உடன் சுமார் 100 GiB பயன்படுத்துகிறது. மற்ற மாடல்கள் அதற்குத் தேவையான நினைவகத்தை வைத்திருந்தால், அது நிறுத்தப்பட்ட நிலையில் அமைக்கப்படும், நீங்கள் ஒன்றை நிறுத்தியதும் தொடங்கத் தயாராக இருக்கும். மாடல் logout-இல் நிற்கும்; வேறு ஏதாவதற்கு நினைவகம் தேவைப்படும்போது அதை நீங்களே நிறுத்தவும்.

`omarchy agent local list` விருப்பங்களைக் காட்டுகிறது மற்றும் சில ஏன் பொருந்தாது என விளக்குகிறது. மற்றொன்றை அமைக்க, `omarchy agent local use <recipe>` இயக்கவும். இன்று, `qwen3.8-flash-next-halogen` மற்றும் `qwen3.8-27b-gufo` 128 GB Strix Halo இயந்திரங்களுக்குக் கிடைக்கிறது. புதிய recipe-கள் மற்றும் பரிந்துரைகள் `omarchy update` உடன், package மூலம் வருகின்றன.

நீங்கள் அமைக்கும் ஒவ்வொரு மாடலுக்கும் முகவர்கள் panel-இல், உங்கள் சந்தாக்களுக்கு அடுத்து, அதன் சொந்த வரி கிடைக்கும்: அதைத் தொடங்க play, அதை நிறுத்தி அதன் நினைவகத்தை விடுவிக்க pause, மற்றும் அதில் உங்கள் முகவரைத் திறக்க terminal பொத்தான். பல மாடல்கள் நினைவகத்தில் ஒன்றாகப் பொருந்தும்போது ஒரே நேரத்தில் இயங்கலாம்; ஒன்று பொருந்தவில்லை என்றால், எந்த இயங்கும் மாடலை நிறுத்த வேண்டும் என Omarchy சொல்லும். அவற்றை மறுவரிசைப்படுத்த வரிகளை இழுக்கவும், மற்றும் ஒரு மாடலையும் அதன் பதிவிறக்கத்தையும் நீக்க தேர்ந்தெடுக்கப்பட்ட வரியில் Delete அழுத்தவும்.

கட்டளை வரியிலிருந்து, `omarchy agent local start <recipe>` மற்றும் `omarchy agent local stop <recipe>` அதையே செய்கிறது, `omarchy agent local status` ஒவ்வொரு மாடலையும் காட்டுகிறது, மற்றும் `omarchy agent --local` உங்கள் இயல்புநிலை முகவரை நீங்கள் கடைசியாகத் தொடங்கிய மாடலில் திறக்கிறது (உங்கள் இயல்புநிலை முகவர் local மாடலைப் பயன்படுத்த முடியாவிட்டால் pi). எந்த OpenAI-இணக்கமான client-உம் இணைக்க முடியும்: `status` ஒவ்வொரு மாடலின் முகவரியையும் காட்டுகிறது (முதலாவது `http://127.0.0.1:11435/v1`), recipe பெயரே மாடல், மற்றும் key `~/.config/omarchy/agent-local/key`-இல் உள்ளது.

`omarchy agent local remove <recipe>` ஒரு மாடலையும் வேறு எந்த மாடலும் பயன்படுத்தாத பதிவிறக்கங்களையும் நீக்குகிறது.

மூன்றாம் தரப்பு runtime-கள் அவற்றின் வெளியீட்டாளருடன் குறிக்கப்பட்டுள்ளன. Omarchy ஒவ்வொரு மாடலையும் network அணுகல் இல்லாமல் இயக்குகிறது.

### Local LLM-கள்

Omarchy local LLM மாடல்களை இயக்குவதற்கான இரண்டு வழிகளைப் பரிந்துரைக்கிறது: LM Studio மற்றும் Ollama. LM Studio திறந்த-எடை மாடல்களைக் கண்டறிய, நிறுவ, மற்றும் இயக்க ஒரு GUI interface-ஐ வழங்குகிறது. எளிதாகத் தொடங்க இது ஒரு சிறந்த வழி. Ollama இதேபோல் செய்வதற்கான CLI-ஐ வழங்குகிறது. ஆனால் நீங்கள் local மாடல்களுக்கு புதியவராக இருந்தால், நான் LM Studio-உடன் தொடங்குவேன். நீங்கள் Omarchy Menu-வில் _Install > AI_ கீழ் ஏதேனும் ஒன்றை நிறுவலாம்.

### Omarchy Skill

Agent skill-கள் AI குறிப்பிட்ட கருவிகளை ஒரு குறிப்பிட்ட வழியில் பயன்படுத்த உதவுகின்றன, மற்றும் Omarchy system-ஐ வடிவமைப்பதற்கான இயல்புநிலை skill-உடன் வருகிறது. உங்கள் Hyprland config-ஐ மாற்றுவது, பட்டையைச் சரிசெய்வது, அல்லது புதிதாக ஒரு theme-ஐ உருவாக்குவது போல. இது Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` மற்றும் ஒவ்வொரு `~/.hermes/profiles/*/skills`), மற்றும் பொதுவான `~/.agents/skills` இருப்பிடத்திற்கான skill அடைவுகளில் symlinked செய்யப்பட்டுள்ளது, எனவே பெரும்பாலான harness-கள் அதைத் தானாகவே எடுக்கும்.

ஆனால் நீங்கள் இந்த skill-ஐ சோதனை முயற்சியாகக் கருத வேண்டும். வெவ்வேறு மாடல்கள் அதை வெவ்வேறு விளைவுகளுக்குப் பயன்படுத்தும். முதலில் plan mode-இல் இயக்குவது சிறந்தது, எனவே முகவர் என்ன மாற்ற விரும்புகிறது என்பதைப் பற்றிய ஒரு யோசனை உங்களுக்குக் கிடைக்கும். பின்னர் மாற்றங்களைத் திரும்பப் பெற அல்லது முகவர் எல்லாவற்றையும் குழப்பினால் `omarchy reinstall configs`-ஐயும் இயக்கத் தயாராக இருங்கள்.
