உங்களுக்கு இயல்புநிலையைத் தேர்ந்தெடுக்காமல், கீழுள்ள குறியீட்டு முகவர்களுக்கான தொடக்க நிரல்களை Omarchy கொண்டுள்ளது. முதல் பயன்பாட்டில் அதன் CLI-ஐ நிறுவ ஒரு கட்டளையை இயக்கவும், பின்னர் கேட்கும்போது அங்கீகரிக்கவும். Hermes மட்டும் விதிவிலக்கு: முதல் பயன்பாட்டில் அதற்காக எதுவும் நிறுவப்படாது, அதைத் தேர்ந்தெடுப்பது Hermes Desktop-ஐ நிறுவும், கீழே உள்ள _Desktop apps_ விளக்குவது போல.

### முகவர்களை நிறுவுதலும் புதுப்பித்தலும்

Hermes-ஐத் தவிர, இந்த முகவர்கள் mise-இன் சோம்பேறி நிறுவலைப் பயன்படுத்துகின்றன: முதல் தொடக்கம் CLI-ஐ நிறுவும், பிந்தைய தொடக்கங்கள் அதையே மீண்டும் பயன்படுத்தும். நிறுவப்பட்ட முகவருக்குப் புதிய வெளியீடு உள்ளதா என்பதை mise அதிகபட்சம் நான்கு மணி நேரத்திற்கு ஒரு முறை, அது தொடங்குவதற்குச் சற்று முன்பு அல்லது shell prompt-இல் பின்னணியில் சரிபார்க்கும். அந்தப் புதுப்பிப்பு தோல்வியடைந்தால் அல்லது நீங்கள் ஆஃப்லைனில் இருந்தால், நிறுவப்பட்ட பதிப்பு இயங்கும். `omarchy update` மீதமுள்ள Omarchy-யுடன் சேர்த்து நிறுவப்பட்ட முகவர்களையும் புதுப்பிக்கும், மேலும் `mup` mise-ஆல் நிர்வகிக்கப்படும் கருவிகளை மட்டும் புதுப்பிக்கும்.

`claude update`, `codex update`, அல்லது ஒரு செயலியில் உள்ள புதுப்பிப்பு பொத்தான் போன்ற முகவரின் சொந்தப் புதுப்பிப்பாளர், mise-ஆல் நிர்வகிக்கப்படும் நிறுவலைப் புதுப்பிக்காது. `codex update` தோல்வியடையும், மேலும் `claude update` வெற்றி என்று தெரிவித்தாலும் mise கண்காணிக்காத தனி நகலை நிறுவக்கூடும். ஒரு முகவரின் சொந்த நிறுவியையும் புதுப்பிப்பாளரையும் பயன்படுத்த விரும்பினால், அதை `disable_tools`-இல் சேர்க்கவும்; [முன்பே நிறுவப்பட்ட CLI கருவிகள்](18-development-tools.md#preinstalled-cli-tools)-ஐப் பார்க்கவும்.

நீங்கள் தேவைப்படுவதற்கு முன்பே கட்டமைக்கப்பட்ட அனைத்து சோம்பேறி கருவிகளையும் நிறுவ, `mise install --include-lazy`-ஐ இயக்கவும். இதில் முகவர்களுடன் Omarchy-இன் மற்ற இயல்புநிலை CLI கருவிகளும் அடங்கும். ஒரு தனி கருவியை நிறுவுவதற்கு அல்லது உங்கள் சொந்த நிறுவலைப் பயன்படுத்துவதற்கு [முன்பே நிறுவப்பட்ட CLI கருவிகள்](18-development-tools.md#preinstalled-cli-tools)-ஐப் பார்க்கவும்.

`grok`, `claude` மற்றும் `codex`-ஐப் போலவே mise-இன் முதல்-தரப்பு `grok` தொகுப்பின் மூலம் நிறுவப்படுகிறது. `grok`-ஐ இயக்கவும், அல்லது _Agent > Harness_ கீழ் அதைத் தேர்ந்தெடுக்கவும். x.ai-இல் உள்ள `curl | bash` நிறுவியைத் தவிர்க்கவும். அந்த வழி இரண்டாவது நகலை `~/.grok/bin`-இல் வைக்கும், அதை `PATH`-இல் முன்னால் சேர்க்கும், மேலும் Omarchy-இன் wrapper-ஐ மேலெழுதும்.

`dsh` அதன் உலாவி UI-ஐ `127.0.0.1:3080`-இல் திறக்கும், தொடக்க கோப்பகத்தை அதன் இயல்புநிலை பணியிடமாகக் கொண்டிருக்கும். அதன் உலாவி UI தொடக்க prompt-ஐ எடுக்காது, எனவே `omarchy agent prompt` ஒட்டுவதற்காக உங்கள் clipboard-இல் prompt-உடன் அதைத் திறக்கும். DeepSeek-இன் ஒப்புதல்-இல்லாத அனுமதி preset-உடன் Omarchy அதைத் தொடங்குகிறது. நீங்கள் அதன் அதிகாரப்பூர்வ மாடல் API-ஐப் பயன்படுத்தும்போது DeepSeek Harness அமர்வு பதிவுகளை DeepSeek-க்கு பதிவேற்றும்; அதன் உலாவி UI-இல் _Settings > General > Upload Session Log_ கீழ் அதை அணைக்கவும். நீங்கள் அதை `DSH_TELEMETRY_MODE=DISABLED`-உடன் தொடங்காவிட்டால், நீங்கள் அதற்கு அனுப்பும் கருத்தும் அமர்வுடன் பதிவேற்றப்படும்.

### இயல்புநிலை முகவர்

`omarchy default agent <name>`-உடன் அல்லது Omarchy Menu (`Super + Space`)-இல் _Agent > Harness_ கீழ் உங்கள் இயல்புநிலை முகவரைத் தேர்ந்தெடுக்கவும். முகவர் இன்னும் நிறுவப்படவில்லை என்றால், அதைத் தேர்ந்தெடுப்பது முதலில் அதை நிறுவும். புதிய Omarchy ஒரு முறை மட்டும் வரும் அறிவிப்புடன் இந்தத் தேர்வைச் செய்ய உங்களை அழைக்கும்.

Claude-ஐத் தேர்ந்தெடுப்பது Chromium, Chrome, Brave, Brave Origin, மற்றும் Edge-க்காக அதன் உலாவி நீட்டிப்பை அமைக்கவும் முயற்சிக்கும். நீட்டிப்பு அமைப்பு அனைத்து பயனர்களுக்கும் பொருந்தும் மற்றும் உங்கள் கணினி கடவுச்சொல்லைக் கேட்கலாம்; ரத்து செய்வது அல்லது தோல்வியடைந்த நீட்டிப்பு நிறுவல் இருந்தாலும் Claude தேர்ந்தெடுக்கப்பட்டு தொடங்கப்படும். உங்கள் உலாவியை மறுதொடக்கம் செய்யவும், கேட்கப்பட்டால் நீட்டிப்பை இயக்கவும், மேலும் அதை இணைப்பதை முடிக்க Claude-இல் உள்நுழையவும். இணைப்பைச் சரிபார்க்க Claude-இல் `/chrome`-ஐ இயக்கவும். Firefox மற்றும் Zen இந்த நீட்டிப்பை ஆதரிக்காது. இந்த அமைப்பு சேர்க்கப்படுவதற்கு முன்பே Claude உங்கள் இயல்புநிலையாக இருந்திருந்தால், நீட்டிப்பை நிறுவ அதை மீண்டும் தேர்ந்தெடுக்கவும்.

நீங்கள் தேர்ந்தெடுத்த பிறகு, `Super + Shift + Ctrl + A` இயல்புநிலை முகவரை ஒரு தனி terminal window-இல் தொடங்கும் (அல்லது நீங்கள் இன்னும் தேர்ந்தெடுக்கவில்லை என்றால் தேர்வியைக் கொண்டுவரும்). `omarchy agent prompt "Review this project"`-உடன் அதை நேரடியாக ஒரு பணிக்குள் தொடங்கவும் முடியும். Freebuff மற்றும் DeepSeek Harness தொடக்க prompt-ஐ எடுக்காது, எனவே அவை ஒட்டுவதற்காக உங்கள் clipboard-இல் prompt-உடன் திறக்கும். இப்படித் தொடங்கப்படும் முகவர்கள் தங்கள் அந்தந்த நிறுத்தி-கேட்காத முறைகளில் கவனிக்கப்படாமல் இயங்கும், எனவே அவை உண்மையில் விஷயங்களைச் செய்யத் தயாராக இருங்கள்! MiniMax Code-க்கு அதன் ஊடாடும் அமர்வுகளுக்கு அப்படிப்பட்ட முறை இல்லை, எனவே அது வழக்கம் போல் அனுமதிகளைக் கேட்கும். மேலும் முகவர்கள் உங்கள் முகப்பு கோப்பகத்திற்கான நம்பிக்கையை நினைவில் கொள்ள மறுப்பதால், `$HOME`-இலிருந்து தொடங்குவது அதற்குப் பதிலாக `~/Work`-இல் தொடங்கும்.

terminal குறுக்குவழிகளும் உள்ளன: `a` தற்போதைய terminal-இல் இயல்புநிலை முகவரை inline-ஆக இயக்கும், அதே நேரத்தில் `c`, `cx`, மற்றும் `cy` ஆகியவை OpenCode, Claude Code, மற்றும் Codex-ஐ நேரடியாகத் தொடங்கும் (மீண்டும் அவற்றின் தானியங்கு-ஒப்புதல் முறைகளில்). Theme மாற்றங்களும் முகவர்களுக்கு ஒத்திசைக்கப்படும்: நீங்கள் Omarchy theme-ஐ மாற்றும்போது Claude Code, Pi, OpenCode, மற்றும் Hermes (Omarchy அதை நிறுவிய பிறகு) அனைத்தும் பின்தொடரும்.

### உங்கள் முகவர் வழிமுறைகள்

ஒவ்வொரு முகவருக்கான தனிப்பட்ட விதிகள் `~/.agents/skills`-இல் உள்ள பகிரப்பட்ட skills-க்கு அடுத்ததாக `~/.agents/AGENTS.md`-இல் செல்லும். அதை _Agent > Instructions_ கீழ் திறக்கவும், இது ஒவ்வொரு harness-ம் தனது சொந்த உலகளாவிய கோப்பை வைத்திருக்கும் இடங்களில் அதையும் இணைக்கும்: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, Copilot-இன் `~/.copilot/copilot-instructions.md`, மற்றும் பல. Crush மற்றும் Amp ஆகியவை `~/.config/AGENTS.md` இணைப்பைப் படிக்கும், அதே நேரத்தில் omp, Kimi, மற்றும் DeepSeek Harness ஆகியவை `~/.agents/AGENTS.md`-ஐ நேரடியாகப் படிக்கும். இயல்புநிலை முகவரைத் தேர்ந்தெடுப்பதும் அதை இணைக்கும். நீங்கள் ஏற்கனவே வைத்திருந்த வழிமுறைகள் கோப்பு, இன்னும் எதுவும் இல்லை என்றால் பகிரப்பட்டதாக மாறும்; இல்லையெனில் அது இணைப்பின் அருகில் `.bak` என வைக்கப்படும். மற்றொரு முகவரை நிறுவிய பிறகு மீண்டும் இணைக்க `omarchy agent instructions`-ஐ இயக்கவும்.

### முகவர்கள் பேனல்

மேல் பட்டையில் ஒரு முகவர்கள் ஐகான் உள்ளது. நீங்கள் ஒரு முகவரை அமைப்பதற்கு முன்பு, அதன் பேனல் Claude, Codex, அல்லது Grok-இல் உள்நுழைவதன் மூலம் உங்களை வழிநடத்தும், மேலும் முதலாவது உங்கள் இயல்புநிலை முகவராக மாறும். அதன் பிறகு, பேனல் ஒவ்வொரு சந்தாவையும் ஒரே பக்கத்தில் வைக்கும்: ஒவ்வொரு முகவரும் கணக்கும் அதன் திட்டத்துடன், அதன் 5-மணி நேர அமர்வு மற்றும் வாராந்திர வரம்புகள் ஒவ்வொன்றுக்கும் ஒரு மீட்டர், அது மீட்டமைக்கப்படும் வரை உள்ள நேரத்துடன் (சரியான சதவீதத்திற்கு hover செய்யவும்), அல்லது மீதமுள்ள முன்கூட்டியே செலுத்தப்பட்ட இருப்பு, அவை அனைத்திலும் நீங்கள் பயன்படுத்தியதைச் சுழற்றும் ஒரு வரியின் கீழ், இந்த வார டோக்கன்கள் மற்றும் உங்கள் அதிகம் பயன்படுத்தப்பட்ட மாடல் போன்றவை. _Make something_ கீழ் இது உங்கள் இயல்புநிலை முகவரிடம் பணியை ஒப்படைக்கும் புதிய theme, plugin, app, அல்லது game-க்கான தொடக்க prompt-களை வழங்கும். Omarchy-இன் சொந்த Hype, Monologue, மற்றும் Omacut உருவாக்கப்படும் விதத்தில், C++ மற்றும் Qt Quick-இல், omarchy-make-app agent skill-ஐப் பின்பற்றி Apps உருவாக்கப்படுகின்றன, மேலும் அவற்றுக்குத் தேவையான compiler மற்றும் Qt துண்டுகள் நிறுவப்பட்டு வருகின்றன. Games என்பது omarchy-make-game agent skill-ஐப் பின்பற்றி `~/Games/vibes`-இல் உள்ள ஒற்றை three.js பக்கம், மேலும் அனைத்தும் தற்போதைய theme-இல் ஒரே Game Vibes launcher-இலிருந்து திறக்கும்; அவை web-இலிருந்து three.js-ஐ ஏற்றுகின்றன, எனவே அவை தொடங்க ஒரு இணைப்பு தேவை. Claude Code, Codex, Grok, Kimi, Cursor மற்றும் அதன் Grok Bot ஒதுக்கீடு, GitHub Copilot, Muse, Antigravity, Kimchi, மற்றும் Devin ஆகியவை அவற்றின் வரம்புகளுடன் உடனடியாகக் காட்டப்படும், மேலும் Hermes, Mistral Vibe, மற்றும் Qwen Code ஆகியவை நீங்கள் அவற்றைப் பயன்படுத்திய பிறகு அவற்றின் அமர்வுகளையும் டோக்கன்களையும் காட்டும். pi, omp, அல்லது opencode மூலம் நீங்கள் பயன்படுத்தும் Provider திட்டங்களும் keys-ம் தோன்றும்: OpenCode Zen மற்றும் Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan, மற்றும் Synthetic அவற்றின் வரம்புகளுடன்; Fireworks, OpenRouter, மற்றும் DeepSeek அவற்றின் முன்கூட்டியே செலுத்தப்பட்ட இருப்புகளுடன்; மேலும் Local models கீழ் உங்கள் சொந்த hardware-இல் நீங்கள் இயக்கும் மாடல்கள். ஒவ்வொரு முகவரும் ஒரு முறை மட்டுமே கணக்கிடப்படும், அதற்கு பில் செய்பவர் கீழ், நீங்கள் எத்தனை harness-கள் மூலம் அதை இயக்கினாலும்.

பேனலுக்கு பட்டை ஐகானை இடது-கிளிக் செய்யவும், உங்கள் இயல்புநிலை முகவரைத் தொடங்க வலது-கிளிக் செய்யவும். அதன் பின்னால் உள்ள பயன்பாட்டு பதிவுகள் ஒவ்வொரு 15 நிமிடங்களுக்கும் `omarchy agent usage-update`-ஆல் மீண்டும் உருவாக்கப்படும், மேலும் பேனல் ஒத்திசைக்கப்பட்ட கோப்புறை வழியாக உங்கள் மற்ற இயந்திரங்களிலிருந்து பயன்பாட்டை இணைக்கவும் முடியும். முழு அமைப்புகளுக்கு `$OMARCHY_PATH/shell/plugins/agents/` கீழ் உள்ள README-ஐப் பார்க்கவும்.

### பல சந்தாக்கள்

நீங்கள் ஒன்றுக்கு மேற்பட்ட Claude, Codex, அல்லது Grok திட்டத்திற்கு பணம் செலுத்தினால் — தனிப்பட்ட Max மற்றும் வேலைக்கான ஒன்று என்று சொல்லலாம் — Omarchy அவை அனைத்தையும் உள்நுழைந்த நிலையில் வைத்து அவற்றுக்கு இடையே நகர முடியும். முகவர்கள் பேனலில் உள்ள + உடன் ஒரு சந்தாவைச் சேர்க்கவும், அது அங்கேயே உங்களை வழிநடத்தும், அல்லது `omarchy agent account add claude Work`-உடன் (அல்லது `codex`, அல்லது `grok`). CLI காணவில்லை என்றால் அது அதை நிறுவும். ஒரு provider-க்கான முதல் கணக்கு உங்கள் சாதாரண உலாவி மூலம், CLI எப்போதும் பார்க்கும் இடத்திலேயே உள்நுழையும். அதற்குப் பிறகு ஒவ்வொன்றும் ஒரு தனிப்பட்ட window மூலம் உள்நுழையும், எனவே உங்கள் உலாவி ஏற்கனவே உள்நுழைந்துள்ள கணக்கு தவறாக எடுக்கப்படாது; நீங்கள் சேர்க்கும் கணக்காக அங்கு உள்நுழையவும், மேலும் நீங்கள் ஏற்கனவே திறந்து வைத்திருந்த எந்த தனிப்பட்ட window-வையும் முதலில் மூடவும். இதைச் செய்ய CLI-இலிருந்து ஒருபோதும் வெளியேற வேண்டாம்: வெளியேறுவது சேமிக்கப்பட்ட உள்நுழைவை ரத்து செய்யும், மேலும் அந்தக் கணக்கை மீண்டும் சேர்க்க வேண்டியிருக்கும்.

உங்கள் சந்தா உள்நுழைவுகளை SSH வழியாக மற்றொரு Omarchy இயந்திரத்திற்கு நகலெடுக்க, `omarchy agent account copy user@laptop`-ஐ இயக்கவும். இலக்கில் ஒன்று நிறுவப்படவில்லை என்றால் அனுப்புநர் ஒரு தற்காலிக பெறுநரை வழங்கும், எனவே பழைய Omarchy இயந்திரங்கள் புதுப்பிப்பு இல்லாமல் கணக்குகளைப் பெற முடியும். நிறுவப்பட்ட பெறுநர்களுக்கு முன்னுரிமை கிடைக்கும். இது அனைத்து Claude, Codex, மற்றும் Grok சந்தாக்களையும் நகலெடுக்கும்; அவற்றைத் தேர்ந்தெடுக்க provider பெயர்களைச் சேர்க்கவும், `omarchy agent account copy laptop claude` போன்றது. கணக்கு பெயர்களும் command ID-களும் மூலத்துடன் பொருந்தும், இலக்கில் ஏற்கனவே உள்ள கணக்குகள் உட்பட. தொடர்பில்லாத இலக்கு கணக்குகளின் பெயர்கள் மோதினால் அவை எண் பின்னொட்டைப் பெறும், மேலும் அமைப்புகள், skills, plugins, மற்றும் உரையாடல் வரலாறு ஒவ்வொரு இயந்திரத்திற்கும் உள்ளூராகவே இருக்கும்.

ஏற்கனவே உள்ள இலக்கு நற்சான்றிதழ்கள் வைக்கப்படும். அங்கு ஏற்கனவே உள்நுழைந்துள்ள ஒரு மூலக் கணக்கின் பெயர் அதன் நற்சான்றிதழ்களை மாற்றாமல் ஒத்திசைக்கப்படும்; மற்ற கணக்குகள் அதனுடன் சேர்க்கப்படும். பொருந்தும் கணக்குகளுக்கான சேமிக்கப்பட்ட நற்சான்றிதழ்களை மாற்ற, இலக்கில் அந்தக் கணக்கின் அமர்வுகளிலிருந்து வெளியேறிய பிறகு `omarchy agent account copy --replace laptop claude`-ஐப் பயன்படுத்தவும். புதிய இலக்கு மூலத்தின் செயலில் உள்ள கணக்கு மற்றும் மாறுதல் விருப்பங்களையும் பெறும்; நிறுவப்பட்ட இலக்கு தன்னுடையவற்றை வைத்திருக்கும்.

நற்சான்றிதழ்கள் SSH வழியாகப் பயணித்து இலக்கில் தனிப்பட்ட கோப்புகளில் சேமிக்கப்படும், எனவே நீங்கள் நம்பும் இயந்திரங்களுக்கு மட்டும் நகலெடுக்கவும். இது ஒரு முறை நகல், தொடர்ச்சியான ஒத்திசைவு அல்ல. Codex refresh டோக்கன்கள் மற்றொரு இயந்திரத்தால் சுழற்றப்படலாம், நகலெடுக்கப்பட்ட உள்நுழைவுக்கு புதுப்பித்தல் தேவைப்படும் நிலையை விட்டுச் செல்லும்; பல இயந்திரங்களில் ஒரே நேரத்தில் பயன்படுத்த தனி உள்நுழைவுகள் மிகவும் நம்பகமான தேர்வாக இருக்கும். [Codex-இன் கணக்கு அங்கீகார வழிகாட்டுதல்](https://developers.openai.com/codex/auth/ci-cd-auth)-ஐப் பார்க்கவும்.

ஒரு provider-க்கு ஒரு கணக்கு செயலில் இருக்கும், மேலும் ஒவ்வொரு புதிய அமர்வும் அதுவாகவே தொடங்கும்: `cx`, `cy`, சாதாரண `claude`, `codex`, அல்லது `grok`, `omarchy agent` மூலம் தொடங்கப்படும் எதுவும், மற்றும் `PATH`-இல் CLI-ஐக் கண்டறியும் scripts அல்லது editors. `omarchy agent account use work`-உடன் மாற்றவும் (மேலும் `omarchy agent account use main`-உடன் திரும்பவும்), அல்லது பேனலில் ஒரு கணக்கின் எண்ணை அழுத்தி பின்னர் `Enter`-ஐ அழுத்துவதன் மூலம் (அல்லது அதன் Use பொத்தானைக் கிளிக் செய்வதன் மூலம்). இயங்கும் Claude அமர்வுகளும் அவற்றின் அடுத்த செய்தியிலிருந்து மாறும்: ஒவ்வொரு Claude அமர்வும் `~/.claude`-இல் இயங்கும், அது எப்போதும் செயலில் உள்ள கணக்கின் உள்நுழைவை வைத்திருக்கும். பழைய Omarchy-ஆல் ஒரு கணக்கின் சொந்த கோப்புறையில் தொடங்கப்பட்ட Claude அமர்வு அது வெளியேறும் வரை அந்த உள்நுழைவை வைத்திருக்கும், எனவே மாற்றம் அந்த அமர்வுகளைப் பெயரிட்டு அவை போன பிறகு தானாகவே முடியும். இயங்கும் Codex மற்றும் Grok அமர்வுகள் அவை தொடங்கிய கணக்கிலேயே இருக்கும். உரையாடல் வரலாறு, அமைப்புகள், skills, மற்றும் plugins கணக்குகள் முழுவதும் பகிரப்படும், எனவே அதே கோப்புறையில் `claude --continue` நீங்கள் புதிய கணக்கில் விட்ட இடத்திலிருந்து தொடரும்.

ஒன்றுக்கு மேற்பட்ட கணக்குகளுடன், பேனல் ஒவ்வொரு கணக்கின் வரம்புகளையும் அருகருகே காட்டும், செயலில் உள்ளது குறிக்கப்பட்டிருக்கும். இயல்பாக, செயலில் உள்ள கணக்கு ஒரு வரம்பின் 95%-ஐத் தாண்டும்போது Omarchy உங்களுக்கு அறிவிக்கும், மேலும் அறிவிப்பைக் கிளிக் செய்வது அதிக இடவசதி உள்ள கணக்கிற்கு மாறும். பேனலில் ஒரு கணக்கின் வரியில் hover செய்து Use-க்கு அருகில் தோன்றும் Autoswitch-ஐக் கிளிக் செய்யவும் (அல்லது `m`-ஐ அழுத்தவும்), அல்லது அதற்குப் பதிலாக அதுவாகவே மாற `omarchy agent account mode auto`-ஐ இயக்கவும்; அது இயக்கத்தில் இருக்கும்போது, Autoswitch Use-இன் இடத்தை எடுக்கும், மேலும் அதை மீண்டும் கிளிக் செய்வது அறிவிப்பதற்குத் திரும்பும். வாசலை மாற்ற ஒரு எண்ணைச் சேர்க்கவும், `omarchy agent account mode auto 90` போன்றது. ஒவ்வொரு கணக்கும் வாசலுக்கு மேல் இருந்தால், எந்தக் கணக்கு முதலில் விடுபடுகிறது என்பதுடன் அதைப் பற்றி ஒரு முறை கேட்பீர்கள். செயலில் உள்ள கணக்கு அதன் வாசலிலிருந்து 15 புள்ளிகளுக்குள் இருக்கும்போது (இயல்புநிலையில் 80%), அதன் வரம்புகள் ஒவ்வொரு 15 நிமிடங்களுக்குப் பதிலாக ஒவ்வொரு மூன்று நிமிடங்களுக்கும் சரிபார்க்கப்படும்.

`omarchy agent account list` ஒவ்வொரு கணக்கையும் அதன் சமீபத்திய வரம்புகளையும் காட்டும், `omarchy agent account remove work` ஒன்றை மறக்கும், மேலும் `omarchy agent account rename primary Hey` ஒன்றுக்குப் பெயர் மாற்றும் (அல்லது பேனலில் ஒரு கணக்கின் பெயரைக் கிளிக் செய்யவும்). இந்தக் கட்டளைகள் உங்கள் இயல்புநிலை முகவரின் கணக்குகளில் வேலை செய்யும்; மற்ற provider-ஐ அடைய, முதலில் அதைப் பெயரிடவும், `omarchy agent account use codex side` போன்றது. நீங்கள் ஏற்கனவே `~/.claude` அல்லது `~/.codex`-இல் வைத்திருந்த உள்நுழைவு _Main_ கணக்கு. Codex-இனுடையது அது இருக்கும் இடத்திலேயே இருக்கும்; மற்றொரு கணக்கு செயலில் இருக்கும்போது Claude-இனுடையது தனது சொந்த கோப்புறையில் காத்திருக்கும். சுமார் எட்டு மணி நேரத்திற்கு மேல் பயன்படுத்தப்படாமல் விடப்பட்ட கணக்கு _Sign-in required_-ஐக் காட்டலாம்; பேனலிலேயே அந்தக் கணக்கில் மீண்டும் உள்நுழைய அதைக் கிளிக் செய்யவும், அல்லது அதற்கு மாறி ஒரு அமர்வைத் தொடங்கவும், இது உள்நுழைவைத் தானாகவே புதுப்பிக்கும். நீங்கள் `claude mcp add`-உடன் சேர்க்கும் MCP servers ஒவ்வொரு Claude கணக்கையும் அடையும், ஏனெனில் அவை அனைத்தும் `~/.claude`-இல் இயங்கும்; Codex மற்றும் Grok-க்கு, ஒரு கணக்கு சேர்க்கப்பட்டபோது நீங்கள் வைத்திருந்த servers அதனுடன் வரும், ஆனால் பிந்தையவை நீங்கள் அவற்றைச் சேர்த்த கணக்கை மட்டுமே அடையும். Claude Desktop தனது சொந்த உள்நுழைவை வைத்திருக்கும், மேலும் CLI binary-க்கான முழுமையான பாதையுடன் கட்டமைக்கப்பட்ட Codex அல்லது Grok கருவிகள் மாற்றத்தைப் பின்பற்றாது. வெளிப்படையான `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, அல்லது `GROK_HOME` தேர்ந்தெடுக்கப்பட்ட கணக்கை விட முன்னுரிமை பெறும்.

### செயலிழப்பு கண்டறிதல்

செயல்முறை செயலிழப்புகளுக்காக Omarchy systemd-coredump-ஐக் கண்காணிக்கும். ஏதாவது segfault ஆகும்போது, உங்களுக்கு ஒரு "Process crashed" அறிவிப்பு கிடைக்கும் — அதைக் கிளிக் செய்யவும், மேலும் செயலிழப்பு உங்கள் இயல்புநிலை முகவரிடம் Omarchy-இன் diagnose-crash skill-உடன் ஒப்படைக்கப்படும், இது core dump-இலிருந்து உண்மைகளை நிறுவுவதன் மூலமும் செயலிழப்பு upstream-இல் தெரிவிக்கத் தகுதியானதா என்பதைத் தீர்மானிப்பதன் மூலமும் முகவரை வழிநடத்தும். `coredumpctl list`-இலிருந்து எந்த PID-க்கு எதிராகவும் `omarchy agent crash <pid>`-உடன் அதைக் கையாலும் இயக்கலாம்.

கண்காணிப்பு இயல்பாகவே இயக்கத்தில் இருக்கும். _Trigger > Toggle > Crash Capture_ கீழ் (அல்லது `omarchy toggle crash-capture`-உடன்) அதை அணைக்கவும், அறிவிப்புகள் நிற்கும்; `omarchy agent crash <pid>` இன்னும் கையால் வேலை செய்யும்.

செயலிழப்புகளை ஒரு நேரத்தில் ஒரு நிரல் வீதமாகவும் அமைதிப்படுத்தலாம், இதைத்தான் கண்டறிதல் இறுதியில் உங்களுக்கு வழங்கும். `omarchy crash mute hyprland` அந்த நிரலுக்கு மட்டும் அறிவிப்புகளை நிறுத்தும், `omarchy crash mute hyprland off` அவற்றைத் திரும்பக் கொண்டுவரும், மேலும் `omarchy crash mute` தனியாக நீங்கள் அமைதிப்படுத்தியவற்றைப் பட்டியலிடும். இது binary-இன் பாதையை அதன் பெயரைப் போலவே மகிழ்ச்சியாக எடுக்கும், எனவே `omarchy crash mute /usr/bin/hyprland` அதே வேலையைச் செய்யும். இடைவெளி உள்ள பெயரை மேற்கோள் காட்டவும், `omarchy crash mute 'Some App'` போன்றது. மற்ற அனைத்தும் இன்னும் அறிவிக்கும், மேலும் அமைதிப்படுத்தப்பட்ட நிரல் இன்னும் செயலிழக்கும் — இது நினைவூட்டலை மறைக்கும், இது எதையும் சரிசெய்யாது.

### Desktop apps

_Install > AI_ மெனுவும் சில வரைகலை AI செயலிகளைக் கொண்டுள்ளது: ChatGPT desktop app, Claude desktop app (Anthropic-இன் Linux beta, Chat, Cowork, மற்றும் Claude Code தாவல்களுடன்), Grok Bot xAI-இன் மாடல்களுடன் அரட்டையடிக்க, Herdr Desktop, Hermes Desktop, OpenClaw, Perplexity desktop app, மற்றும் T3 Code. Grok Bot என்பது desktop chat app. குறியீட்டு முகவர் `grok` கட்டளை.

Hermes Desktop தான் தெரிந்து கொள்ள வேண்டியது, ஏனெனில் ஒரு இயந்திரத்தில் ஒரு Hermes உள்ளது, மேலும் அது செயலியினுடையது: Hermes எப்போதும் செயலி மூலமாக மட்டுமே நிறுவப்படும், மேலும் இயல்புநிலை முகவர் இயக்கும் `hermes` கட்டளை செயலியினுடையது. Hermes-ஐ இயல்புநிலை முகவராகத் தேர்ந்தெடுப்பது _Install > AI_ உள்ளீடு செய்வதையே நிறுவும்: தொகுப்பு, மற்றும் Hermes-இன் சொந்த நிறுவியால் அமைக்கப்பட்ட `~/.hermes` கீழ் ஒரு Hermes runtime, இது முதல் முறை சில நிமிடங்கள் எடுக்கும். terminal `hermes` கட்டளை, இயல்புநிலை முகவர் மற்றும் செயலி அனைத்தும் பயன்படுத்தும் ஒரே Hermes அந்த runtime தான், மேலும் அது Omarchy வெளியீட்டிற்காகக் காத்திருக்காமல் `hermes update`-உடன் தன்னைப் புதுப்பிக்கும். அதை நிறுவுவது Hermes-க்கு Omarchy theme-ஐ `omarchy` என்ற பெயரிடப்பட்ட skin-ஆகவும் வழங்கும், நீங்கள் theme-களை மாற்றும்போது ஒவ்வொரு Hermes மேற்பரப்பும் அதைப் பின்பற்றும்; நீங்கள் அது வேண்டாம் என்றால் Hermes-இன் Appearance அமைப்புகளின் கீழ் அல்லது `/skin`-உடன் மற்றொன்றைத் தேர்ந்தெடுக்கவும், மேலும் Omarchy அந்தத் தேர்வை அப்படியே விட்டுவிடும். _Remove > AI_ கீழ் செயலியை நீக்குவது முதலில் Hermes-ஐ மூடும், gateway உட்பட, அந்த runtime-ஐ அதனுடன் எடுக்கும், மேலும் நீங்கள் வேறுவிதமாகச் சொல்லாவிட்டால் உங்கள் chats, memories, மற்றும் Hermes தனக்காக எழுதிய skills-ஐ வைத்திருக்கும்: அந்தத் தரவும் உங்கள் இணைப்பு அமைப்புகளும் கூட போக வேண்டுமா என்று அது கேட்கும், இயல்புநிலை இல்லை என்பதாகும்.

OpenClaw-இன் desktop அனுபவம் அதன் Control UI, இது அதன் சொந்த உள்ளூர் gateway-ஆல் ஆதரிக்கப்படும் web app-ஆகத் திறக்கும். OpenClaw `~/.openclaw`-இல் வாழ்கிறது மற்றும் தன்னைப் புதுப்பிக்கிறது: Control UI-இன் "Update Gateway" பொத்தானைப் பயன்படுத்தவும் அல்லது `openclaw update`-ஐ இயக்கவும், மேலும் gateway புதிய பதிப்பில் மறுதொடக்கம் செய்யும். புதிய நிறுவல் தொடங்கும் வெளியீட்டை மட்டுமே Omarchy தேர்ந்தெடுக்கும். _Remove > AI_ கீழ் OpenClaw-ஐ நீக்குவது gateway service-ஐயும் செயலியையும் அதனுடன் எடுத்து, பின்னர் `~/.openclaw` கூட போக வேண்டுமா என்று கேட்கும், ஏனெனில் அது OpenClaw-வுடனும் அது பதிவிறக்கும் plugin runtime-களுடனும் உங்கள் chats மற்றும் நற்சான்றிதழ்களை வைத்திருக்கும்; இயல்புநிலை அதை வைத்திருக்கும், மேலும் OpenClaw-ஐ மீண்டும் நிறுவுவது அதைத் திரும்ப எடுக்கும்.

Herdr Desktop என்பது [Herdr](https://herdr.dev) desktop app: நீங்கள் window-வை மூடும்போது அதன் core-இல் தொடர்ந்து இயங்கும் terminals மற்றும் குறியீட்டு முகவர்களின் spaces, tabs, மற்றும் panes. இது ஒரு தொகுப்பை விட Herdr-இன் சொந்த நிறுவியிலிருந்து வருகிறது, எனவே இது `~/.local/share/herdr-app`-இல் வாழ்கிறது, உங்களிடம் ஏற்கனவே ஒன்று இல்லாதபோது அதன் core-ஐ `~/.local/bin/herdr-core`-இல் கொண்டுவருகிறது, மேலும் இரண்டையும் தானே புதுப்பிக்கிறது. இது Omarchy `Super + Ctrl + Return`-இல் வழங்கும் `herdr` கட்டளைக்குப் பதிலாக அல்லாமல் அதற்கு அருகில் அமர்கிறது, மேலும் அந்தக் கட்டளையின் நேரடி விசைகளைப் பெறுகிறது: `Alt + Return` மற்றும் `Alt + Shift + Return` ஒரு pane-ஐ கீழே அல்லது வலதுபுறமாகப் பிரிக்கும், `Alt + Escape` அதை மூடும், `Ctrl + Alt + Arrow` pane-களுக்கு இடையே நகரும், `Alt + 1..9` மற்றும் `Alt + Left/Right` ஒரு tab-ஐத் தேர்ந்தெடுக்கும், மேலும் `Alt + Up/Down` spaces-களுக்கு இடையே நகரும். `Ctrl + 1..9` ஒரு space-ஐத் தேர்ந்தெடுக்கும் மற்றும் `Alt + Shift + Up/Down` முகவர்கள் வழியாகச் செல்லும். `Ctrl + Space` prefix விசைகள் terminal-க்கு மட்டும் இருக்கும், ஏனெனில் செயலி ஒரு வரிசைக்காக சாதாரண Ctrl விசையை வைத்திருக்க முடியாது. Omarchy இவற்றை `~/.config/herdr-app/keys.json`-இல் எழுதும், மேலும் `omarchy-refresh-herdr-app` அவற்றைத் திரும்ப வைக்கும். அதை நிறுவுவது Herdr-இன் Omarchy theme-ஐத் தேர்ந்தெடுக்கும், அது அப்போதிலிருந்து உங்கள் Omarchy theme-ஐப் பின்பற்றும். Herdr light mode-க்கு ஒரு theme-ஐயும் dark mode-க்கு ஒன்றையும் வைத்திருக்கும், எனவே dark மற்றும் light Omarchy theme-க்கு இடையே மாறிய பிறகு, மற்ற mode-க்கு Herdr-இன் theme picker-இல் Omarchy-ஐ மீண்டும் ஒரு முறை தேர்ந்தெடுக்கவும்.

T3 Code ஒரு தொகுப்பிலிருந்து அல்லாமல் `~/.local/share/t3code`-இல் அதன் அதிகாரப்பூர்வ AppImage வெளியீட்டிலிருந்து இயங்கும், எனவே அது தன்னைப் புதுப்பிக்கும். அதை நிறுவுவது Stable அல்லது Nightly channel-இல் தொடங்க வேண்டுமா என்று கேட்கும்; பின்னர் T3 Code-இன் அமைப்புகளில் மாற்றவும். உங்கள் threads மற்றும் அமைப்புகள் `~/.t3`-இல் வாழ்கின்றன, மேலும் _Remove > AI_ கீழ் T3 Code-ஐ நீக்குவது அவற்றை அதனுடன் எடுக்கும்.

### உள்ளூர் மாடல்கள்

உங்கள் குறியீட்டு முகவர்களுக்காக உங்கள் சொந்த இயந்திரத்தில் ஒரு திறந்த மாடலை இயக்கவும். உங்கள் prompt-களும் code-ம் இயந்திரத்திலேயே இருக்கும்; மாடலுக்கு அனுப்பப்படும் எதுவும் அதை விட்டு வெளியேறாது. இதனுடன் தொடங்கவும்:

```bash
omarchy agent local use best
```

அல்லது, மேல் பட்டையில் உள்ள முகவர்கள் பேனலில், + ஐத் தேர்ந்தெடுத்து பின்னர் Local AI-ஐத் தேர்ந்தெடுக்கவும், இது ஒரு மாடல் இந்த இயந்திரத்திற்குப் பொருந்தும்போது தோன்றும். முதல் முறை, இது மாடல்களை இயக்கும் Podman-ஐ நிறுவும், மேலும் NVIDIA இயந்திரத்தில் NVIDIA-இன் container toolkit-ஐ நிறுவும், இது அவற்றுக்கு GPU-ஐ வழங்கும். Omarchy பின்னர் இந்த இயந்திரத்திற்கு பரிந்துரைக்கப்பட்ட மாடலைத் தேர்ந்தெடுத்து, அதைப் பதிவிறக்கி, தொடங்கும். பல பத்து GB பதிவிறக்கத்தையும் மாடல் இயங்கும்போது இயந்திரத்தின் பெரும்பாலான நினைவகம் பயன்பாட்டில் இருப்பதையும் எதிர்பார்க்கவும்: Flash Next அதன் முழு 256K context-உடன் சுமார் 100 GiB-ஐப் பயன்படுத்துகிறது. மற்ற மாடல்கள் அதற்குத் தேவையான நினைவகத்தை வைத்திருந்தால், அது நிறுத்தப்பட்ட நிலையில் அமைக்கப்படும், நீங்கள் ஒன்றை நிறுத்தியவுடன் தொடங்கத் தயாராக இருக்கும். மாடல் logout-இல் நிற்கும்; வேறு எதற்காவது நினைவகம் தேவைப்படும்போது அதை நீங்களே நிறுத்தவும்.

`omarchy agent local list` விருப்பங்களைக் காட்டும் மற்றும் சில ஏன் பொருந்தவில்லை என்பதை விளக்கும். மற்றொன்றை அமைக்க, `omarchy agent local use <recipe>`-ஐ இயக்கவும். இன்று, 128 GB Strix Halo இயந்திரங்களுக்கு `qwen3.8-flash-next-gufo` மற்றும் `qwen3.8-27b-gufo` கிடைக்கும்; 27B சுமார் 40 GiB எடுக்கும், எனவே அது மற்ற வேலைகளுக்கு இடம் விடும். Intel-இன் Arc B390 கொண்ட 64 GB laptop-இல், `qwen3.6-35b-a3b-llamacpp` சுமார் 30 GiB-இல் இயங்கும். புதிய recipes மற்றும் பரிந்துரைகள் தொகுப்பின் மூலம் `omarchy update`-உடன் வரும்.

நீங்கள் அமைக்கும் ஒவ்வொரு மாடலும் உங்கள் சந்தாக்களுக்கு அடுத்ததாக முகவர்கள் பேனலில் தனது சொந்த வரியைப் பெறும்: அதைத் தொடங்க play, அதை நிறுத்தி அதன் நினைவகத்தை விடுவிக்க pause, மேலும் அதில் உங்கள் முகவரைத் திறக்க terminal பொத்தான். அவை நினைவகத்தில் ஒன்றாகப் பொருந்தும்போது பல ஒரே நேரத்தில் இயங்க முடியும்; ஒன்று பொருந்தவில்லை என்றால், எந்த இயங்கும் மாடலை நிறுத்த வேண்டும் என்று Omarchy சொல்லும். அவற்றை மறுவரிசைப்படுத்த வரிகளை இழுக்கவும், மேலும் ஒரு மாடலையும் அதன் பதிவிறக்கத்தையும் நீக்க தேர்ந்தெடுக்கப்பட்ட வரியில் Delete-ஐ அழுத்தவும்.

நீங்கள் அமைக்கும் ஒவ்வொரு மாடலும் app launcher-இல் தனது சொந்த உள்ளீட்டையும் பெறும், மாடலின் பெயரின் கீழ் மற்றும் அதன் தயாரிப்பாளரின் logo-உடன், Claude, Codex அல்லது Grok-இல் உள்நுழைவது ஒன்றைச் சேர்ப்பது போல. இது அந்த மாடலில் உங்கள் முகவரைத் திறக்கும், மேலும் அது இயங்கவில்லை என்றால் முதலில் மாடலைத் தொடங்கும்: terminal அது ஏற்றப்படுவதைக் காட்டி அது தயாரானவுடன் முகவரிடம் ஒப்படைக்கும். ஒரு மாடலை நீக்குவது அதன் உள்ளீட்டை நீக்கும்.

ஒரு மாடல் அது அமைக்கப்பட்டபடியே சரியாகத் தொடர்ந்து இயங்கும், எனவே Omarchy update உங்கள் முகவர்களின் கீழ் ஒன்றை ஒருபோதும் மறுதொடக்கம் செய்யாது. நீங்கள் அமைத்த மாடலுக்கு Omarchy-இடம் புதிய runtime அல்லது புதிய weights இருக்கும்போது, அதன் வரி ஒரு புதுப்பிப்பு பொத்தானைக் காட்டும்: அதை அழுத்தவும், மாடல் பின்னணியில் மீண்டும் அமைக்கப்படும், மாறியதை மட்டும் பதிவிறக்கி, புதிய பதிப்பில் மறுதொடக்கம் செய்யும். நிறுத்தப்பட்ட மாடல் நிறுத்தப்பட்டபடியே இருக்கும். `omarchy agent local update` ஒரு terminal-இலிருந்து ஒவ்வொரு மாடலுக்கும் அதையே செய்யும்.

Command line-இலிருந்து, `omarchy agent local start <recipe>` மற்றும் `omarchy agent local stop <recipe>` அதையே செய்யும், `omarchy agent local status` ஒவ்வொரு மாடலையும் காட்டும், மேலும் `omarchy agent --local` நீங்கள் கடைசியாகத் தொடங்கிய மாடலில் உங்கள் இயல்புநிலை முகவரைத் திறக்கும். pi, OpenCode மற்றும் Qwen Code ஒன்றைப் பயன்படுத்த முடியும்; வேறு எந்த இயல்புநிலையுடனும் அது pi-இல் திறக்கும். pi நீங்கள் அமைத்த ஒவ்வொரு மாடலையும், மற்றும் நீங்கள் இணைத்த இயந்திரங்களில் உள்ளவற்றையும், அதன் சொந்த model picker-இல் பட்டியலிடும், எனவே சாதாரண `pi` அவற்றையும் அடையும். எந்த OpenAI-இணக்கமான client-ம் இணைக்க முடியும்: `status` ஒவ்வொரு மாடலின் முகவரியையும் காட்டும் (முதலாவது `http://127.0.0.1:11435/v1`), recipe பெயர் மாடல், மேலும் key `~/.config/omarchy/agent-local/key`-இல் உள்ளது.

`omarchy agent local remove <recipe>` ஒரு மாடலையும் வேறு எந்த மாடலும் பயன்படுத்தாத பதிவிறக்கங்களையும் நீக்கும்.

Third-party runtime-கள் அவற்றின் வெளியீட்டாளருடன் பெயரிடப்படும். Omarchy ஒவ்வொரு மாடலையும் network அணுகல் இல்லாமல் இயக்கும்.

### உள்ளூர் LLM-கள்

Omarchy உள்ளூர் LLM மாடல்களை இயக்க இரண்டு வழிகளைப் பரிந்துரைக்கிறது: LM Studio மற்றும் Ollama. LM Studio திறந்த-எடை மாடல்களைக் கண்டறிய, அவற்றை நிறுவ, மற்றும் அவற்றை இயக்க ஒரு GUI interface-ஐ வழங்குகிறது. எளிதாகத் தொடங்க இது ஒரு சிறந்த வழி. Ollama இதேபோல் செய்ய ஒரு CLI-ஐ வழங்குகிறது. ஆனால் நீங்கள் உள்ளூர் மாடல்களுக்குப் புதியவர் என்றால், நான் LM Studio-உடன் தொடங்குவேன். Omarchy Menu-இல் _Install > AI_ கீழ் இரண்டில் ஒன்றையும் நிறுவலாம்.

### Omarchy Skill

Agent skills AI குறிப்பிட்ட கருவிகளை ஒரு குறிப்பிட்ட வழியில் பயன்படுத்த உதவும், மேலும் Omarchy அமைப்பைத் தனிப்பயனாக்க ஒரு இயல்புநிலை skill-உடன் வருகிறது. உங்கள் Hyprland config-ஐ மாற்றுவது, பட்டையைச் சரிசெய்வது, அல்லது புதிதாக ஒரு theme-ஐ உருவாக்குவது போன்றது. இது Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` மற்றும் ஒவ்வொரு `~/.hermes/profiles/*/skills`), மற்றும் பொதுவான `~/.agents/skills` இருப்பிடத்திற்கான skill கோப்பகங்களில் symlinked செய்யப்பட்டுள்ளது, எனவே பெரும்பாலான harness-கள் அதைத் தானாகவே எடுக்கும்.

ஆனால் இந்த skill-ஐ நீங்கள் சோதனை நிலையில் உள்ளதாகக் கருத வேண்டும். வெவ்வேறு மாடல்கள் அதை வெவ்வேறு விளைவுகளுக்குப் பயன்படுத்தும். முதலில் plan mode-இல் இயக்குவது சிறந்தது, எனவே முகவர் எதை மாற்ற விரும்புகிறது என்பது பற்றி உங்களுக்கு ஒரு யோசனை கிடைக்கும். மேலும் முகவர் எல்லாவற்றையும் குழப்பினால், மாற்றங்களைத் திரும்பப் பெற அல்லது `omarchy reinstall configs`-ஐ அழைக்கவும் தயாராக இருங்கள்.
