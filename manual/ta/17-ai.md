Omarchy, உங்களுக்காக இயல்புநிலையைத் தேர்ந்தெடுக்காமல், கீழே உள்ள குறியீட்டு ஏஜெண்டுகளுக்கான தொடக்கிகளை உள்ளடக்கியுள்ளது. முதல் முறை பயன்படுத்தும்போது அதன் CLI-ஐ நிறுவ ஒரு கட்டளையை இயக்கவும், பின்னர் கேட்கும்போது அங்கீகரிக்கவும். Hermes மற்றும் OpenClaw ஆகியவை விதிவிலக்குகள்: mise வழியாக அவற்றுக்கு எதுவும் நிறுவப்படுவதில்லை, மேலும் அவற்றில் ஏதேனும் ஒன்றைத் தேர்ந்தெடுப்பது தானாகவே புதுப்பித்துக் கொள்ளும் அதன் சொந்த நகலை அமைக்கும், கீழே உள்ள _டெஸ்க்டாப் பயன்பாடுகள்_ விளக்குவது போல.

### ஏஜெண்டுகளை நிறுவுதல் மற்றும் புதுப்பித்தல்

Hermes மற்றும் OpenClaw தவிர, இந்த ஏஜெண்டுகள் mise இன் சோம்பேறி நிறுவலைப் பயன்படுத்துகின்றன: முதல் முறை தொடங்குவது CLI-ஐ நிறுவுகிறது, பின்னர் தொடங்குவது அதையே மீண்டும் பயன்படுத்துகிறது. mise, நிறுவப்பட்ட ஏஜெண்டிற்கு புதிய வெளியீடு உள்ளதா என்பதை நான்கு மணிநேரத்திற்கு ஒரு முறைக்கு மேல் சரிபார்ப்பதில்லை, அது தொடங்குவதற்கு சற்று முன்பு அல்லது ஷெல் ப்ராம்ப்டில் பின்னணியில். அந்தப் புதுப்பிப்பு தோல்வியடைந்தால் அல்லது நீங்கள் ஆஃப்லைனில் இருந்தால், நிறுவப்பட்ட பதிப்பு இயங்கும். `omarchy update` ஆனது Omarchy இன் மற்ற பகுதிகளுடன் சேர்த்து நிறுவப்பட்ட ஏஜெண்டுகளையும் புதுப்பிக்கிறது, மேலும் `mup` ஆனது mise நிர்வகிக்கும் கருவிகளை மட்டும் புதுப்பிக்கிறது.

`claude update`, `codex update` போன்ற ஏஜெண்டின் சொந்தப் புதுப்பிப்பான், அல்லது ஒரு செயலியில் உள்ள புதுப்பிப்பு பொத்தான், mise நிர்வகிக்கும் நிறுவலைப் புதுப்பிப்பதில்லை. `codex update` தோல்வியடைகிறது, மேலும் `claude update` வெற்றி என்று அறிவித்துக் கொண்டே mise கண்காணிக்காத தனி நகலை நிறுவக்கூடும். ஒரு ஏஜெண்டின் சொந்த நிறுவி மற்றும் புதுப்பிப்பானைப் பயன்படுத்த விரும்பினால், அதை `disable_tools` இல் சேர்க்கவும்; [முன்பே நிறுவப்பட்ட CLI கருவிகள்](18-development-tools.md#preinstalled-cli-tools) ஐப் பார்க்கவும்.

உங்களுக்குத் தேவைப்படுவதற்கு முன்பே கட்டமைக்கப்பட்ட அனைத்து சோம்பேறி கருவிகளையும் நிறுவ, `mise install --include-lazy` ஐ இயக்கவும். இதில் ஏஜெண்டுகளுடன் சேர்த்து Omarchy இன் மற்ற இயல்புநிலை CLI கருவிகளும் அடங்கும். ஒரு தனி கருவியை நிறுவுவது அல்லது உங்கள் சொந்த நிறுவலைப் பயன்படுத்துவது பற்றி [முன்பே நிறுவப்பட்ட CLI கருவிகள்](18-development-tools.md#preinstalled-cli-tools) ஐப் பார்க்கவும்.

`grok` ஆனது mise இன் முதல்-தரப்பு `grok` தொகுப்பு வழியாக நிறுவப்படுகிறது, `claude` மற்றும் `codex` போலவே. `grok` ஐ இயக்கவும், அல்லது _Agent > Harness_ இன் கீழ் அதைத் தேர்ந்தெடுக்கவும். x.ai இல் உள்ள `curl | bash` நிறுவியைத் தவிர்க்கவும். அந்த வழி `~/.grok/bin` இல் இரண்டாவது நகலை வைக்கிறது, அதை `PATH` இல் முன்னால் சேர்க்கிறது, மேலும் Omarchy இன் ரேப்பரை மேலெழுதுகிறது.

`dsh` அதன் உலாவி UI-ஐ `127.0.0.1:3080` இல் திறக்கிறது, தொடங்கிய கோப்பகத்தை அதன் இயல்புநிலை பணியிடமாகக் கொண்டு. அதன் உலாவி UI தொடக்க ப்ராம்ப்டை எடுப்பதில்லை, எனவே `omarchy agent prompt` அதை உங்கள் கிளிப்போர்டில் ப்ராம்ப்டுடன் ஒட்டுவதற்காகத் திறக்கிறது. Omarchy அதை DeepSeek இன் ஒப்புதல்-தேவையில்லாத அனுமதி முன்னமைவுடன் தொடங்குகிறது. DeepSeek Harness, நீங்கள் அதன் அதிகாரப்பூர்வ மாடல் API-ஐப் பயன்படுத்தும்போது அமர்வு பதிவுகளை DeepSeek க்கு பதிவேற்றுகிறது; அதன் உலாவி UI இல் _Settings > General > Upload Session Log_ இன் கீழ் அதை அணைக்கவும். நீங்கள் `DSH_TELEMETRY_MODE=DISABLED` உடன் அதைத் தொடங்காவிட்டால், நீங்கள் அதற்கு அனுப்பும் கருத்தும் அமர்வுடன் சேர்த்து பதிவேற்றப்படும்.

### இயல்புநிலை ஏஜெண்ட்

`omarchy default agent <name>` உடன் அல்லது Omarchy Menu (`Super + Space`) இல் _Agent > Harness_ இன் கீழ் உங்கள் இயல்புநிலை ஏஜெண்டைத் தேர்ந்தெடுக்கவும். ஏஜெண்ட் இன்னும் நிறுவப்படவில்லை என்றால், அதைத் தேர்ந்தெடுப்பது முதலில் அதை நிறுவுகிறது, மேலும் அது செயலி தொடக்கியில், Agent க்கு அருகில், தனக்கென ஒரு தொடக்கியையும் பெறுகிறது. புதிய Omarchy ஒரு முறை மட்டுமே வரும் அறிவிப்புடன் இந்தத் தேர்வைச் செய்ய உங்களை அழைக்கும்.

Claude ஐத் தேர்ந்தெடுப்பது Chromium, Chrome, Brave, Brave Origin, மற்றும் Edge க்கான அதன் உலாவி நீட்டிப்பை அமைக்கவும் முயற்சிக்கிறது. நீட்டிப்பு அமைப்பு அனைத்து பயனர்களுக்கும் பொருந்தும் மற்றும் உங்கள் கணினி கடவுச்சொல்லைக் கேட்கக்கூடும்; ரத்து செய்வது அல்லது தோல்வியடைந்த நீட்டிப்பு நிறுவல் இருந்தாலும் Claude தேர்ந்தெடுக்கப்பட்டு தொடங்கப்படும். உங்கள் உலாவியை மறுதொடக்கம் செய்யவும், கேட்கப்பட்டால் நீட்டிப்பை இயக்கவும், மேலும் அதை இணைப்பதை முடிக்க Claude இல் உள்நுழையவும். இணைப்பைச் சரிபார்க்க Claude இல் `/chrome` ஐ இயக்கவும். Firefox மற்றும் Zen இந்த நீட்டிப்பை ஆதரிப்பதில்லை. இந்த அமைப்பு சேர்க்கப்படுவதற்கு முன்பே Claude உங்கள் இயல்புநிலையாக இருந்தால், நீட்டிப்பை நிறுவ அதை மீண்டும் தேர்ந்தெடுக்கவும்.

நீங்கள் தேர்ந்தெடுத்தவுடன், `Super + Shift + Ctrl + A` இயல்புநிலை ஏஜெண்டை ஒரு பிரத்யேக டெர்மினல் சாளரத்தில் தொடங்குகிறது (அல்லது நீங்கள் இன்னும் தேர்ந்தெடுக்கவில்லை என்றால் தேர்வியைக் கொண்டு வருகிறது). `omarchy agent prompt "Review this project"` உடன் அதை நேரடியாக ஒரு பணிக்குள் தொடங்கவும் முடியும். Freebuff மற்றும் DeepSeek Harness தொடக்க ப்ராம்ப்டை எடுப்பதில்லை, எனவே அவை அதற்குப் பதிலாக உங்கள் கிளிப்போர்டில் ப்ராம்ப்டுடன் ஒட்டுவதற்காகத் திறக்கின்றன. இவ்வாறு தொடங்கப்படும் ஏஜெண்டுகள் அவற்றின் அந்தந்த நிறுத்தி-கேட்காத பயன்முறைகளில் கவனிக்கப்படாமல் இயங்குகின்றன, எனவே அவை உண்மையில் விஷயங்களைச் செய்யத் தயாராக இருங்கள்! MiniMax Code க்கு அதன் ஊடாடும் அமர்வுகளுக்கு அத்தகைய பயன்முறை இல்லை, எனவே அது வழக்கம் போல் அனுமதிகளைக் கேட்கிறது. மேலும் ஏஜெண்டுகள் உங்கள் முகப்பு கோப்பகத்திற்கான நம்பிக்கையை நினைவில் வைக்க மறுப்பதால், `$HOME` இலிருந்து தொடங்குவது அதற்குப் பதிலாக `~/Work` இல் தொடங்குகிறது.

டெர்மினல் குறுக்குவழிகளும் உள்ளன: `a` தற்போதைய டெர்மினலில் இயல்புநிலை ஏஜெண்டை உள்ளேயே இயக்குகிறது, அதே நேரத்தில் `c`, `cx`, மற்றும் `cy` ஆகியவை OpenCode, Claude Code, மற்றும் Codex ஐ நேரடியாகத் தொடங்குகின்றன (மீண்டும் அவற்றின் தானியங்கு-ஒப்புதல் பயன்முறைகளில்). தீம் மாற்றங்களும் ஏஜெண்டுகளுக்கு ஒத்திசைகின்றன: நீங்கள் Omarchy தீமை மாற்றும்போது Claude Code, Pi, OpenCode, மற்றும் Hermes (Omarchy அதை நிறுவியவுடன்) அனைத்தும் பின்தொடர்கின்றன.

### உங்கள் ஏஜெண்ட் வழிமுறைகள்

ஒவ்வொரு ஏஜெண்டிற்குமான தனிப்பட்ட விதிகள் `~/.agents/AGENTS.md` இல் செல்கின்றன, `~/.agents/skills` இல் உள்ள பகிரப்பட்ட திறன்களுக்கு அருகில். அதை _Agent > Instructions_ இன் கீழ் திறக்கவும், இது தனது சொந்த உலகளாவிய கோப்பை வைத்திருக்கும் ஒவ்வொரு ஹார்னஸிலும் அதை இணைக்கிறது: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, Copilot இன் `~/.copilot/copilot-instructions.md`, மற்றும் பல. Crush மற்றும் Amp ஆகியவை `~/.config/AGENTS.md` இணைப்பைப் படிக்கின்றன, அதே நேரத்தில் omp, Kimi, மற்றும் DeepSeek Harness ஆகியவை `~/.agents/AGENTS.md` ஐ நேரடியாகப் படிக்கின்றன. இயல்புநிலை ஏஜெண்டைத் தேர்ந்தெடுப்பதும் அதை இணைக்கிறது. உங்களிடம் ஏற்கனவே இருந்த வழிமுறைகள் கோப்பு, இன்னும் பகிரப்பட்ட ஒன்று இல்லை என்றால் பகிரப்பட்டதாக மாறுகிறது; இல்லையெனில் அது இணைப்புக்கு அருகில் `.bak` ஆக வைக்கப்படுகிறது. மற்றொரு ஏஜெண்டை நிறுவிய பிறகு மீண்டும் இணைக்க `omarchy agent instructions` ஐ இயக்கவும்.

### ஏஜெண்டுகள் பேனல்

மேல் பட்டியில் ஒரு ஏஜெண்டுகள் ஐகான் உள்ளது. நீங்கள் ஒரு ஏஜெண்டை அமைப்பதற்கு முன், அதன் பேனல் Claude, Codex, அல்லது Grok இல் உள்நுழைவதன் வழியாக உங்களை அழைத்துச் செல்கிறது, மேலும் முதலாவது உங்கள் இயல்புநிலை ஏஜெண்டாக மாறுகிறது. அதன் பிறகு, பேனல் ஒவ்வொரு சந்தாவையும் ஒரே பக்கத்தில் வைக்கிறது: ஒவ்வொரு ஏஜெண்ட் மற்றும் கணக்கும் அதன் திட்டத்துடன், அதன் 5-மணிநேர அமர்வு மற்றும் வாராந்திர வரம்புகள் ஒவ்வொன்றிற்கும் ஒரு மீட்டர், அது மீட்டமைக்கும் வரையிலான நேரத்துடன் (சரியான சதவீதத்திற்கு மேலே வைக்கவும்), அல்லது மீதமுள்ள முன்கூட்டியே செலுத்தப்பட்ட இருப்பு, அவை அனைத்திலும் நீங்கள் பயன்படுத்தியதைச் சுழற்றும் ஒரு வரியின் கீழ், இந்த வாரம் டோக்கன்கள் மற்றும் உங்கள் அதிகம் பயன்படுத்தப்பட்ட மாடல் போன்றவை. _Make something cool_ இன் கீழ் அது புதிய தீம், செருகுநிரல், செயலி, அல்லது விளையாட்டுக்கான தொடக்க ப்ராம்ப்டுகளை வழங்குகிறது, அவை பணியை உங்கள் இயல்புநிலை ஏஜெண்டிடம் ஒப்படைக்கின்றன. செயலிகள் Omarchy இன் சொந்த Hype, Monologue, மற்றும் Omacut கட்டமைக்கப்பட்ட விதத்தில், C++ மற்றும் Qt Quick இல், omarchy-make-app ஏஜெண்ட் திறனைப் பின்பற்றி கட்டமைக்கப்படுகின்றன, மேலும் அவற்றுக்குத் தேவையான கம்பைலர் மற்றும் Qt துண்டுகள் நிறுவப்பட்டு வருகின்றன. விளையாட்டுகள் `~/Games/vibes` இல் ஒரு ஒற்றை three.js பக்கம், omarchy-make-game ஏஜெண்ட் திறனைப் பின்பற்றுகின்றன, மேலும் அனைத்தும் தற்போதைய தீமில் ஒரு Game Vibes தொடக்கியிலிருந்து திறக்கின்றன; அவை வலையிலிருந்து three.js ஐ ஏற்றுகின்றன, எனவே தொடங்க அவற்றுக்கு இணைப்பு தேவை. Claude Code, Codex, Grok, Kimi, Cursor மற்றும் அதன் Grok Bot அனுமதி, GitHub Copilot, Muse, Antigravity, மற்றும் Devin ஆகியவை அவற்றின் வரம்புகளுடன் உடனடியாக உள்ளடக்கப்படுகின்றன, Kimchi அதன் திட்டம், முன்கூட்டியே செலுத்தப்பட்ட கிரெடிட்கள், மற்றும் செலவு பட்ஜெட்களுடன், மேலும் Hermes, Mistral Vibe, மற்றும் Qwen Code ஆகியவை நீங்கள் அவற்றைப் பயன்படுத்தியவுடன் அவற்றின் அமர்வுகள் மற்றும் டோக்கன்களைக் காட்டுகின்றன. நீங்கள் pi, omp, அல்லது opencode வழியாகப் பயன்படுத்தும் வழங்குநர் திட்டங்கள் மற்றும் விசைகளும் தோன்றுகின்றன: OpenCode Zen மற்றும் Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan, மற்றும் Synthetic அவற்றின் வரம்புகளுடன்; OpenRouter மற்றும் DeepSeek அவற்றின் முன்கூட்டியே செலுத்தப்பட்ட இருப்புகளுடன்; Fireworks கடந்த 30 நாட்களில் அதன் செலவுடன். உங்கள் சொந்த வன்பொருளில் நீங்கள் இயக்கும் மாடல்களிலிருந்து வரும் டோக்கன்களும் மொத்தங்களில் கணக்கிடப்படுகின்றன; மாடல்களுக்கே தனி பேனல் உள்ளது, [உள்ளூர் மாடல்கள்](#local-models) இன் கீழ் விவரிக்கப்பட்டுள்ளது. ஒவ்வொரு ஏஜெண்டும் ஒரு முறை மட்டுமே கணக்கிடப்படுகிறது, அதற்கு யார் பில் செய்கிறார்களோ அவரின் கீழ், நீங்கள் எத்தனை ஹார்னஸ்கள் வழியாக அதை இயக்கினாலும்.

பேனலுக்கு பட்டி ஐகானை இடது-கிளிக் செய்யவும் அல்லது `Super + Ctrl + X` ஐ அழுத்தவும், உங்கள் இயல்புநிலை ஏஜெண்டைத் தொடங்க வலது-கிளிக் செய்யவும், மேலும் புதுப்பிக்க நடு-கிளிக் செய்யவும். அதன் பின்னால் உள்ள பயன்பாட்டுப் பதிவுகள் ஒவ்வொரு 15 நிமிடங்களுக்கும் `omarchy agent usage update` மூலம் மீண்டும் உருவாக்கப்படுகின்றன, மேலும் பேனல் ஒத்திசைக்கப்பட்ட கோப்புறை வழியாக உங்கள் மற்ற இயந்திரங்களிலிருந்து பயன்பாட்டை இணைக்கவும் முடியும். முழு அமைப்புகளுக்கு `$OMARCHY_PATH/shell/plugins/agents/` இன் கீழ் உள்ள README ஐப் பார்க்கவும்.

### பல சந்தாக்கள்

நீங்கள் ஒன்றுக்கு மேற்பட்ட Claude, Codex, அல்லது Grok திட்டங்களுக்கு பணம் செலுத்தினால் — தனிப்பட்ட Max மற்றும் வேலைக்கான ஒன்று, என்று சொல்லலாம் — Omarchy அவை அனைத்தையும் உள்நுழைந்த நிலையில் வைத்து அவற்றுக்கு இடையே நகர முடியும். ஏஜெண்டுகள் பேனலில் + உடன் ஒரு சந்தாவைச் சேர்க்கவும், அது அங்கேயே உங்களை அதன் வழியாக அழைத்துச் செல்லும், அல்லது `omarchy agent account add claude Work` உடன் (அல்லது `codex`, அல்லது `grok`). அது இல்லை என்றால் CLI-ஐ நிறுவுகிறது. ஒரு வழங்குநருக்கான முதல் கணக்கு உங்கள் சாதாரண உலாவி வழியாக உள்நுழைகிறது, CLI எப்போதும் பார்க்கும் இடத்திலேயே. அதற்குப் பிறகு ஒவ்வொன்றும் தனிப்பட்ட சாளரம் வழியாக உள்நுழைகிறது, எனவே உங்கள் உலாவி ஏற்கனவே உள்நுழைந்துள்ள கணக்கு தவறுதலாக எடுக்கப்படுவதில்லை; நீங்கள் சேர்க்கும் கணக்காக அங்கு உள்நுழையவும், மேலும் நீங்கள் ஏற்கனவே திறந்து வைத்திருந்த தனிப்பட்ட சாளரத்தை முதலில் மூடவும். இதைச் செய்ய CLI இலிருந்து ஒருபோதும் வெளியேற வேண்டாம்: வெளியேறுவது சேமிக்கப்பட்ட உள்நுழைவை ரத்து செய்கிறது, மேலும் அந்தக் கணக்கு மீண்டும் சேர்க்கப்பட வேண்டும்.

உங்கள் சந்தா உள்நுழைவுகளை மற்றொரு Omarchy இயந்திரத்திற்கு SSH வழியாக நகலெடுக்க, `omarchy agent account copy user@laptop` ஐ இயக்கவும். இலக்கில் நிறுவப்பட்ட ஒன்று இல்லாதபோது அனுப்புநர் தற்காலிக பெறுநரை வழங்குகிறது, எனவே பழைய Omarchy இயந்திரங்கள் புதுப்பிப்பு இல்லாமல் கணக்குகளைப் பெற முடியும். நிறுவப்பட்ட பெறுநர்களுக்கு முன்னுரிமை அளிக்கப்படுகிறது. இது அனைத்து Claude, Codex, மற்றும் Grok சந்தாக்களையும் நகலெடுக்கிறது; அவற்றைத் தேர்ந்தெடுக்க வழங்குநர் பெயர்களைச் சேர்க்கவும், `omarchy agent account copy laptop claude` இல் உள்ளது போல. கணக்குப் பெயர்கள் மற்றும் கட்டளை IDகள் மூலத்துடன் பொருந்துகின்றன, இலக்கில் ஏற்கனவே உள்ள கணக்குகள் உட்பட. தொடர்பில்லாத இலக்கு கணக்குகள், அவற்றின் பெயர்கள் முரண்பட்டால் எண் பின்னொட்டைப் பெறுகின்றன, மேலும் அமைப்புகள், திறன்கள், செருகுநிரல்கள், மற்றும் உரையாடல் வரலாறு ஒவ்வொரு இயந்திரத்திற்கும் உள்ளூராகவே இருக்கும்.

ஏற்கனவே உள்ள இலக்கு நற்சான்றிதழ்கள் வைக்கப்படுகின்றன. அங்கு ஏற்கனவே உள்நுழைந்துள்ள மூலக் கணக்கு அதன் நற்சான்றிதழ்களை மாற்றாமல் அதன் பெயர் ஒத்திசைக்கப்படுகிறது; மற்ற கணக்குகள் அதனுடன் சேர்த்து சேர்க்கப்படுகின்றன. பொருந்தும் கணக்குகளுக்கான சேமிக்கப்பட்ட நற்சான்றிதழ்களை மாற்ற, இலக்கில் அந்தக் கணக்கின் அமர்வுகளை விட்டு வெளியேறிய பிறகு `omarchy agent account copy --replace laptop claude` ஐப் பயன்படுத்தவும். புதிய இலக்கு மூலத்தின் செயலில் உள்ள கணக்கு மற்றும் மாற்றும் விருப்பங்களையும் பெறுகிறது; நிறுவப்பட்ட இலக்கு தனதையே வைத்திருக்கிறது.

நற்சான்றிதழ்கள் SSH வழியாகப் பயணித்து இலக்கில் தனிப்பட்ட கோப்புகளில் சேமிக்கப்படுகின்றன, எனவே நீங்கள் நம்பும் இயந்திரங்களுக்கு மட்டும் நகலெடுக்கவும். இது ஒரு முறை நகல், தொடர்ச்சியான ஒத்திசைவு அல்ல. Codex புதுப்பிப்பு டோக்கன்கள் மற்றொரு இயந்திரத்தால் மாற்றப்படலாம், நகலெடுக்கப்பட்ட உள்நுழைவுக்கு புதுப்பிப்பு தேவைப்படும் நிலையில் விட்டுவிடும்; பல இயந்திரங்களில் ஒரே நேரத்தில் பயன்படுத்த தனித்தனி உள்நுழைவுகளே மிகவும் நம்பகமான தேர்வாக இருக்கும். [Codex's account authentication guidance](https://developers.openai.com/codex/auth/ci-cd-auth) ஐப் பார்க்கவும்.

ஒரு வழங்குநருக்கு ஒரு கணக்கு செயலில் உள்ளது, மேலும் ஒவ்வொரு புதிய அமர்வும் அதுவாகவே தொடங்குகிறது: `cx`, `cy`, ஒரு சாதாரண `claude`, `codex`, அல்லது `grok`, `omarchy agent` வழியாகத் தொடங்கப்படும் எதுவும், மற்றும் `PATH` இல் CLI-ஐக் கண்டறியும் ஸ்கிரிப்டுகள் அல்லது எடிட்டர்கள். `omarchy agent account use work` உடன் மாற்றவும் (மேலும் `omarchy agent account use main` உடன் திரும்பவும்), அல்லது பேனலில் ஒரு கணக்கின் எண்ணை அழுத்தி பின்னர் `Enter` ஐ அழுத்துவதன் மூலம் (அல்லது அதன் Use பொத்தானைக் கிளிக் செய்வதன் மூலம்). இயங்கும் Claude அமர்வுகளும் மாறுகின்றன, அவற்றின் அடுத்த செய்தியிலிருந்து: ஒவ்வொரு Claude அமர்வும் `~/.claude` இல் இயங்குகிறது, இது எப்போதும் செயலில் உள்ள கணக்கின் உள்நுழைவை வைத்திருக்கிறது. பழைய Omarchy மூலம் கணக்கின் சொந்த கோப்புறையில் தொடங்கப்பட்ட Claude அமர்வு அது வெளியேறும் வரை அந்த உள்நுழைவை வைத்திருக்கிறது, எனவே மாற்றம் அந்த அமர்வுகளைப் பெயரிட்டு அவை போனவுடன் தானாகவே முடிகிறது. இயங்கும் Codex மற்றும் Grok அமர்வுகள் அவை தொடங்கிய கணக்கிலேயே இருக்கும். உரையாடல் வரலாறு, அமைப்புகள், திறன்கள், மற்றும் செருகுநிரல்கள் கணக்குகள் முழுவதும் பகிரப்படுகின்றன, எனவே அதே கோப்புறையில் `claude --continue` நீங்கள் புதிய கணக்கில் விட்ட இடத்திலிருந்து தொடர்கிறது.

ஒன்றுக்கு மேற்பட்ட கணக்குகளுடன், பேனல் ஒவ்வொரு கணக்கின் வரம்புகளையும் அருகருகே காட்டுகிறது, செயலில் உள்ளது குறிக்கப்பட்டுள்ளது. இயல்பாக Omarchy, செயலில் உள்ள கணக்கு ஒரு வரம்பின் 95% ஐத் தாண்டும்போது உங்களுக்கு அறிவிக்கிறது, மேலும் அறிவிப்பைக் கிளிக் செய்வது அதிக இடவசதி உள்ள கணக்கிற்கு மாற்றுகிறது. பேனலில் ஒரு கணக்கின் வரியின் மேல் வைத்து Use க்கு அருகில் தோன்றும் Autoswitch ஐக் கிளிக் செய்யவும் (அல்லது `m` ஐ அழுத்தவும்), அல்லது அது தானாகவே மாற `omarchy agent account mode auto` ஐ இயக்கவும்; அது இயக்கத்தில் இருக்கும்போது, Autoswitch Use இன் இடத்தைப் பிடிக்கிறது, மேலும் அதை மீண்டும் கிளிக் செய்வது அறிவிப்பதற்குத் திரும்புகிறது. வரம்பை மாற்ற ஒரு எண்ணைச் சேர்க்கவும், `omarchy agent account mode auto 90` இல் உள்ளது போல. ஒவ்வொரு கணக்கும் வரம்புக்கு மேல் இருந்தால், எந்தக் கணக்கு முதலில் விடுபடுகிறது என்பதுடன் சேர்த்து ஒரு முறை அதைப் பற்றி நீங்கள் கேள்விப்படுவீர்கள். செயலில் உள்ள கணக்கு அதன் வரம்பிலிருந்து 15 புள்ளிகளுக்குள் இருக்கும்போது (இயல்புநிலையில் 80%), அதன் வரம்புகள் ஒவ்வொரு 15 நிமிடங்களுக்கும் பதிலாக ஒவ்வொரு மூன்று நிமிடங்களுக்கும் சரிபார்க்கப்படுகின்றன.

`omarchy agent account list` ஒவ்வொரு கணக்கையும் அதன் சமீபத்திய வரம்புகளையும் காட்டுகிறது, `omarchy agent account remove work` ஒன்றை மறக்கிறது, மேலும் `omarchy agent account rename primary Hey` ஒன்றை மறுபெயரிடுகிறது (அல்லது பேனலில் ஒரு கணக்கின் பெயரைக் கிளிக் செய்யவும்). இந்தக் கட்டளைகள் உங்கள் இயல்புநிலை ஏஜெண்டின் கணக்குகளில் வேலை செய்கின்றன; மற்ற வழங்குநரை அடைய, முதலில் அதைப் பெயரிடவும், `omarchy agent account use codex side` இல் உள்ளது போல. `~/.claude` அல்லது `~/.codex` இல் நீங்கள் ஏற்கனவே வைத்திருந்த உள்நுழைவு _Main_ கணக்கு ஆகும். Codex இனது அது இருக்கும் இடத்திலேயே இருக்கிறது; மற்றொரு கணக்கு செயலில் இருக்கும்போது Claude இனது தனது சொந்த கோப்புறையில் காத்திருக்கிறது. சுமார் எட்டு மணிநேரத்திற்கும் மேலாகப் பயன்படுத்தப்படாமல் விடப்பட்ட கணக்கு _Sign-in required_ என்று காட்டக்கூடும்; அந்தக் கணக்கை பேனலிலேயே மீண்டும் உள்நுழைய அதைக் கிளிக் செய்யவும், அல்லது அதற்கு மாறி ஒரு அமர்வைத் தொடங்கவும், இது தானாகவே உள்நுழைவைப் புதுப்பிக்கிறது. நீங்கள் `claude mcp add` உடன் சேர்க்கும் MCP சர்வர்கள் ஒவ்வொரு Claude கணக்கையும் அடைகின்றன, ஏனெனில் அவை அனைத்தும் `~/.claude` இல் இயங்குகின்றன; Codex மற்றும் Grok க்கு, ஒரு கணக்கு சேர்க்கப்பட்டபோது உங்களிடம் இருந்த சர்வர்கள் அதனுடன் வருகின்றன, ஆனால் பின்னர் வருபவை நீங்கள் அவற்றைச் சேர்த்த கணக்கை மட்டுமே அடைகின்றன. Claude Desktop தனது சொந்த உள்நுழைவை வைத்திருக்கிறது, மேலும் CLI பைனரிக்கான முழுமையான பாதையுடன் கட்டமைக்கப்பட்ட Codex அல்லது Grok கருவிகள் மாற்றத்தைப் பின்தொடர்வதில்லை. வெளிப்படையான `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, அல்லது `GROK_HOME` தேர்ந்தெடுக்கப்பட்ட கணக்கை விட முன்னுரிமை பெறுகிறது.

### செயலிழப்பு கண்டறிதல்

Omarchy செயல்முறை செயலிழப்புகளுக்காக systemd-coredump ஐக் கண்காணிக்கிறது. நீங்கள் இயல்புநிலை ஏஜெண்டைத் தேர்ந்தெடுத்தவுடன், உங்கள் நிரல்களில் ஏதேனும் ஒன்று core ஐ டம்ப் செய்தால் "Process crashed" அறிவிப்பு வரும் — அதைக் கிளிக் செய்யவும், மேலும் செயலிழப்பு உங்கள் இயல்புநிலை ஏஜெண்டிடம் Omarchy இன் omarchy-diagnose-crash திறனுடன் சேர்த்து ஒப்படைக்கப்படும், இது core dump இலிருந்து உண்மைகளை நிறுவுவதன் வழியாகவும் செயலிழப்பு மேல்நிலையில் புகாரளிக்கத் தகுந்ததா என்பதைத் தீர்மானிப்பதன் வழியாகவும் ஏஜெண்டை அழைத்துச் செல்கிறது. `coredumpctl list` இலிருந்து எந்த PID க்கு எதிராகவும் `omarchy agent crash <pid>` உடன் அதை கையாலும் இயக்கலாம்.

கண்காணிப்பு இயல்பாக இயக்கத்தில் உள்ளது. அதை _Trigger > Toggle > Crash Capture Off_ இன் கீழ் அணைக்கவும் (அல்லது `omarchy toggle crash-capture` உடன்) மற்றும் அறிவிப்புகள் நிற்கும்; `omarchy agent crash <pid>` இன்னும் கையால் வேலை செய்கிறது.

செயலிழப்புகளை ஒரு நேரத்தில் ஒரு நிரல் வீதம் அமைதிப்படுத்தவும் முடியும், இதைத்தான் கண்டறிதல் இறுதியில் உங்களுக்கு வழங்குகிறது. `omarchy crash mute hyprland` அந்த நிரலுக்கு மட்டும் அறிவிப்புகளை நிறுத்துகிறது, `omarchy crash mute hyprland off` அவற்றை மீண்டும் கொண்டு வருகிறது, மேலும் `omarchy crash mute` தானாகவே நீங்கள் அமைதிப்படுத்தியதைப் பட்டியலிடுகிறது. இது பைனரியின் பாதையையும் அதன் பெயரைப் போலவே மகிழ்ச்சியுடன் எடுக்கிறது, எனவே `omarchy crash mute /usr/bin/hyprland` அதையே செய்கிறது. இடைவெளி உள்ள பெயரை மேற்கோள் காட்டவும், `omarchy crash mute 'Some App'` இல் உள்ளது போல. மற்ற அனைத்தும் இன்னும் அறிவிக்கின்றன, மேலும் அமைதிப்படுத்தப்பட்ட நிரல் இன்னும் செயலிழக்கிறது — இது நினைவூட்டலை மறைக்கிறது, எதையும் சரிசெய்வதில்லை.

### டெஸ்க்டாப் பயன்பாடுகள்

_Install > AI_ மெனுவும் சில வரைகலை AI செயலிகளைக் கொண்டுள்ளது: Amp Desktop, Antigravity Desktop, ChatGPT டெஸ்க்டாப் செயலி, Claude டெஸ்க்டாப் செயலி (Anthropic இன் Linux பீட்டா, Chat, Cowork, மற்றும் Claude Code தாவல்களுடன்), xAI இன் மாடல்களுடன் அரட்டையடிக்க Grok Bot, Herdr Desktop, Hermes Desktop, OpenClaw, Perplexity டெஸ்க்டாப் செயலி, மற்றும் T3 Code. Grok Bot என்பது டெஸ்க்டாப் அரட்டை செயலி. குறியீட்டு ஏஜெண்ட் என்பது `grok` கட்டளை.

Hermes Desktop தான் தெரிந்து கொள்ள வேண்டியது, ஏனெனில் ஒரு இயந்திரத்தில் ஒரு Hermes உள்ளது, மேலும் அது செயலியினுடையது: Hermes எப்போதும் செயலி வழியாகவே நிறுவப்படுகிறது, மேலும் இயல்புநிலை ஏஜெண்ட் இயக்கும் `hermes` கட்டளை செயலியினுடையது. Hermes ஐ இயல்புநிலை ஏஜெண்டாகத் தேர்ந்தெடுப்பது _Install > AI_ உள்ளீடு செய்வதையே நிறுவுகிறது: தொகுப்பு, மற்றும் Hermes இன் சொந்த நிறுவியால் அமைக்கப்பட்ட `~/.hermes` இன் கீழ் ஒரு Hermes இயக்கநேரம், இது முதல் முறை சில நிமிடங்கள் எடுக்கும். அந்த இயக்கநேரம் தான் டெர்மினல் `hermes` கட்டளை, இயல்புநிலை ஏஜெண்ட் மற்றும் செயலி அனைத்தும் பயன்படுத்தும் ஒரே Hermes, மேலும் அது Omarchy வெளியீட்டிற்காகக் காத்திருப்பதற்குப் பதிலாக `hermes update` உடன் தன்னைத்தானே புதுப்பிக்கிறது. அதை நிறுவுவது Hermes க்கு Omarchy தீமை `omarchy` என்று பெயரிடப்பட்ட தோலாகவும் வழங்குகிறது, இதை நீங்கள் தீம்களை மாற்றும்போது ஒவ்வொரு Hermes மேற்பரப்பும் பின்தொடர்கிறது; நீங்கள் அது வேண்டாம் என்றால் Hermes இன் Appearance அமைப்புகளின் கீழ் அல்லது `/skin` உடன் மற்றொன்றைத் தேர்ந்தெடுக்கவும், மேலும் Omarchy அந்தத் தேர்வை அப்படியே விட்டுவிடுகிறது. _Remove > AI_ இன் கீழ் செயலியை நீக்குவது முதலில் Hermes ஐ மூடுகிறது, கேட்வே உட்பட, அந்த இயக்கநேரத்தை அதனுடன் எடுத்துச் செல்கிறது, மேலும் நீங்கள் வேறுவிதமாகச் சொல்லாவிட்டால் உங்கள் அரட்டைகள், நினைவுகள், மற்றும் Hermes தனக்காக எழுதிய திறன்களை வைத்திருக்கிறது: அந்தத் தரவும் உங்கள் இணைப்பு அமைப்புகளும் கூட போக வேண்டுமா என்று அது கேட்கிறது, இல்லை என்பதை இயல்பாகக் கொண்டு.

OpenClaw இன் டெஸ்க்டாப் அனுபவம் அதன் Control UI ஆகும், இது அதன் சொந்த உள்ளூர் கேட்வேயால் ஆதரிக்கப்படும் வலை செயலியாகத் திறக்கிறது. OpenClaw `~/.openclaw` இல் வாழ்கிறது மற்றும் தன்னைத்தானே புதுப்பிக்கிறது: Control UI இன் "Update Gateway" பொத்தானைப் பயன்படுத்தவும் அல்லது `openclaw update` ஐ இயக்கவும், மேலும் கேட்வே புதிய பதிப்பில் மறுதொடக்கம் செய்கிறது. Omarchy புதிய நிறுவல் எந்த வெளியீட்டிலிருந்து தொடங்குகிறது என்பதை மட்டுமே தேர்ந்தெடுக்கிறது. OpenClaw உங்கள் இயல்புநிலை ஏஜெண்டாகவும் இருக்க முடியும்: அதை _Agent > Harness_ இன் கீழ் தேர்ந்தெடுப்பது `~/.openclaw` இல் அதே நகலை அமைக்கிறது, மேலும் ஏஜெண்ட் OpenClaw இன் டெர்மினல் UI-ஐ அதன் கேட்வேயுடன் இணைக்கப்பட்டுத் திறக்கிறது. _Remove > AI_ இன் கீழ் OpenClaw ஐ நீக்குவது கேட்வே சேவை மற்றும் செயலியை அதனுடன் எடுத்துச் சென்று பின்னர் `~/.openclaw` கூட போக வேண்டுமா என்று கேட்கிறது, ஏனெனில் அது உங்கள் அரட்டைகள் மற்றும் நற்சான்றிதழ்களை OpenClaw உடன் சேர்த்து மற்றும் அது பதிவிறக்கும் செருகுநிரல் இயக்கநேரங்களுடன் வைத்திருக்கிறது; இயல்புநிலை அதை வைத்திருக்கிறது, மேலும் OpenClaw ஐ மீண்டும் நிறுவுவது அதை மீண்டும் எடுத்துக் கொள்கிறது.

Herdr Desktop என்பது [Herdr](https://herdr.dev) டெஸ்க்டாப் செயலி: நீங்கள் சாளரத்தை மூடும்போது அதன் மையத்தில் தொடர்ந்து இயங்கும் டெர்மினல்கள் மற்றும் குறியீட்டு ஏஜெண்டுகளின் இடங்கள், தாவல்கள், மற்றும் பேன்கள். இது ஒரு தொகுப்பிலிருந்து அல்லாமல் Herdr இன் சொந்த நிறுவியிலிருந்து வருகிறது, எனவே அது `~/.local/share/herdr-app` இல் வாழ்கிறது, உங்களிடம் ஏற்கனவே ஒன்று இல்லாதபோது அதன் மையத்தை `~/.local/bin/herdr-core` இல் கொண்டு வருகிறது, மேலும் இரண்டையும் தானே புதுப்பிக்கிறது. இது Omarchy `Super + Ctrl + Return` இல் வழங்கும் `herdr` கட்டளையை மாற்றுவதற்குப் பதிலாக அதற்கு அருகில் அமர்ந்திருக்கிறது, மேலும் அந்தக் கட்டளையின் நேரடி விசைகளைப் பெறுகிறது: `Alt + Return` மற்றும் `Alt + Shift + Return` ஒரு பேனை கீழே அல்லது வலதுபுறமாகப் பிரிக்கின்றன, `Alt + Escape` அதை மூடுகிறது, `Ctrl + Alt + Arrow` பேன்களுக்கு இடையே நகர்கிறது, `Alt + 1..9` மற்றும் `Alt + Left/Right` ஒரு தாவலைத் தேர்ந்தெடுக்கின்றன, மற்றும் `Alt + Up/Down` இடங்களுக்கு இடையே நகர்கின்றன. `Ctrl + 1..9` ஒரு இடத்தைத் தேர்ந்தெடுக்கிறது மற்றும் `Alt + Shift + Up/Down` ஏஜெண்டுகள் வழியாகச் செல்கிறது. `Ctrl + Space` முன்னொட்டு விசைகள் டெர்மினலுக்கு மட்டுமே இருக்கும், ஏனெனில் செயலி ஒரு வரிசைக்காக சாதாரண Ctrl விசையைப் பிடித்து வைத்திருக்க முடியாது. Omarchy இவற்றை `~/.config/herdr-app/keys.json` இல் எழுதுகிறது, மேலும் `omarchy-refresh-herdr-app` அவற்றை மீண்டும் வைக்கிறது. அதை நிறுவுவது Herdr இன் Omarchy தீமைத் தேர்ந்தெடுக்கிறது, இது அதிலிருந்து உங்கள் Omarchy தீமைப் பின்தொடர்கிறது. Herdr லைட் பயன்முறைக்கு ஒரு தீமையும் டார்க் பயன்முறைக்கு ஒரு தீமையும் வைத்திருக்கிறது, எனவே டார்க் மற்றும் லைட் Omarchy தீமுக்கு இடையே மாறிய பிறகு, மற்ற பயன்முறைக்காக Herdr இன் தீம் தேர்வியில் Omarchy ஐ மீண்டும் ஒரு முறை தேர்ந்தெடுக்கவும்.

T3 Code ஒரு தொகுப்பிலிருந்து அல்லாமல் `~/.local/share/t3code` இல் அதன் அதிகாரப்பூர்வ AppImage வெளியீட்டிலிருந்து இயங்குகிறது, எனவே அது தன்னைத்தானே புதுப்பிக்கிறது. அதை நிறுவுவது Stable அல்லது Nightly சேனலில் தொடங்க வேண்டுமா என்று கேட்கிறது; பின்னர் T3 Code இன் அமைப்புகளில் மாற்றவும். உங்கள் திரெடுகள் மற்றும் அமைப்புகள் `~/.t3` இல் வாழ்கின்றன, மேலும் _Remove > AI_ இன் கீழ் T3 Code ஐ நீக்குவது அவற்றை அதனுடன் எடுத்துச் செல்கிறது.

### உள்ளூர் மாடல்கள்

உங்கள் குறியீட்டு ஏஜெண்டுகளுக்காக உங்கள் சொந்த இயந்திரத்தில் ஒரு திறந்த மாடலை இயக்கவும். உங்கள் ப்ராம்ப்டுகள் மற்றும் குறியீடு இயந்திரத்திலேயே இருக்கும்; மாடலுக்கு அனுப்பப்படும் எதுவும் அதை விட்டு வெளியேறுவதில்லை. இதனுடன் தொடங்கவும்:

```bash
omarchy models use best text
```

அது இந்த இயந்திரத்திற்கான சிறந்த உரை மாடலை அமைக்கிறது, உங்கள் ஏஜெண்டுகள் பயன்படுத்தும் வகை. படம், வீடியோ மற்றும் இசை மாடல்களுக்கும் அவற்றின் சொந்த சிறந்தது உள்ளது: `omarchy models use best image`, `video` அல்லது `music`. ஒவ்வொரு வகையின் தேர்வையும் இந்த இயந்திரத்திற்காகப் பார்க்க `omarchy models use best` ஐ இயக்கவும்.

அல்லது மேல் பட்டியில் ஏஜெண்டுகள் ஐகானுக்கு அருகில் உள்ள அதன் மின்னல் ஐகானிலிருந்து, அல்லது Super + Ctrl + Alt + X உடன் உள்ளூர் மாடல்கள் பேனலைத் திறந்து, + ஐத் தேர்ந்தெடுக்கவும். ஒரு மாடல் இந்த இயந்திரத்திற்குப் பொருந்தும்போது ஐகான் தோன்றும். மாடல்களை இயக்கும் Podman, Omarchy உடன் வருகிறது, NVIDIA இயந்திரத்தில் NVIDIA இன் கொள்கலன் கருவித்தொகுப்பும் வருகிறது, இது அவற்றுக்கு GPU ஐ வழங்குகிறது; ஏதேனும் ஒன்று இல்லை என்றால், முதல் அமைப்பு அதை நிறுவுகிறது. பின்னர் Omarchy இந்த இயந்திரத்திற்கான பரிந்துரைக்கப்பட்ட மாடலைத் தேர்ந்தெடுத்து, அதைப் பதிவிறக்கி, தொடங்குகிறது. பத்துக்கணக்கான GB பதிவிறக்கத்தையும், மாடல் இயங்கும்போது இயந்திரத்தின் நினைவகத்தில் பெரும்பாலானது பயன்பாட்டில் இருப்பதையும் எதிர்பார்க்கவும்: Flash Next அதன் முழு 256K சூழலுடன் சுமார் 100 GiB ஐப் பயன்படுத்துகிறது. மற்ற மாடல்கள் அதற்குத் தேவையான நினைவகத்தை வைத்திருந்தால், அது நிறுத்தப்பட்ட நிலையில் அமைக்கப்படுகிறது, நீங்கள் ஒன்றை நிறுத்தியவுடன் தொடங்கத் தயாராக. மாடல் வெளியேறும்போது நிற்கிறது; உங்களுக்கு வேறு ஏதாவதற்காக நினைவகம் தேவைப்படும்போது அதை நீங்களே நிறுத்தவும்.

`omarchy models list` விருப்பங்களைக் காட்டுகிறது மற்றும் சில ஏன் பொருந்தவில்லை என்பதை விளக்குகிறது. மற்றொன்றை அமைக்க, `omarchy models use <recipe>` ஐ இயக்கவும். இன்று, `qwen3.8-flash-next-gufo` மற்றும் `qwen3.8-27b-gufo` ஆகியவை 128 GB Strix Halo இயந்திரங்களுக்குக் கிடைக்கின்றன; 27B சுமார் 40 GiB எடுக்கிறது, எனவே அது மற்ற வேலைகளுக்கு இடம் விடுகிறது. Intel இன் Arc B390 உடன் 64 GB மடிக்கணினியில், `qwen3.6-35b-a3b-llamacpp` சுமார் 30 GiB இல் இயங்குகிறது. புதிய சமையல் குறிப்புகள் மற்றும் பரிந்துரைகள் தொகுப்பு வழியாக `omarchy update` உடன் வருகின்றன.

நீங்கள் அமைக்கும் ஒவ்வொரு மாடலும் உள்ளூர் மாடல்கள் பேனலில் தனது சொந்த வரியைப் பெறுகிறது: அதைத் தொடங்க இயக்கவும், அதை நிறுத்தி அதன் நினைவகத்தை விடுவிக்க இடைநிறுத்தவும், மேலும் அதில் உங்கள் ஏஜெண்டைத் திறக்க டெர்மினல் பொத்தான். மேலே குறுக்காக, ஒரு பட்டி இயந்திரத்தின் நினைவகம் Omarchy க்கே (கணினி மற்றும் உங்கள் செயலிகள்), இயங்கும் ஒவ்வொரு மாடல், மற்றும் எது இலவசம் என்பதற்கு இடையே எவ்வாறு பிரிக்கப்பட்டுள்ளது என்பதைக் காட்டுகிறது. நிறுத்தப்பட்ட மாடலைச் சுட்டிக்காட்டவும், பட்டி அது பொருந்துகிறதா, அல்லது எவ்வளவு குறைவாக உள்ளது என்பதைக் காட்டுகிறது. அவை நினைவகத்தில் ஒன்றாகப் பொருந்தும்போது பல ஒரே நேரத்தில் இயங்க முடியும்; ஒன்று பொருந்தவில்லை என்றால், எந்த இயங்கும் மாடலை நிறுத்த வேண்டும் என்று Omarchy சொல்கிறது. வரிகளை அவற்றின் லோகோவால் இழுத்து மறுவரிசைப்படுத்தவும், மேலும் தேர்ந்தெடுக்கப்பட்ட வரியில் Delete ஐ அழுத்தி ஒரு மாடலையும் அதன் பதிவிறக்கத்தையும் நீக்கவும்.

நீங்கள் அமைக்கும் ஒவ்வொரு மாடலும் செயலி தொடக்கியில் தனது சொந்த உள்ளீட்டையும் பெறுகிறது, மாடலின் பெயரின் கீழ் மற்றும் அதன் தயாரிப்பாளரின் லோகோவுடன், Claude, Codex அல்லது Grok இல் உள்நுழைவது ஒன்றைச் சேர்ப்பது போல. இது அந்த மாடலில் உங்கள் ஏஜெண்டைத் திறக்கிறது, மேலும் அது இயங்கவில்லை என்றால் முதலில் மாடலைத் தொடங்குகிறது: டெர்மினல் அது ஏற்றப்படுவதைக் காட்டுகிறது மற்றும் அது தயாரானவுடன் ஏஜெண்டிடம் ஒப்படைக்கிறது. ஒரு மாடலை நீக்குவது அதன் உள்ளீட்டை நீக்குகிறது.

ஒவ்வொரு மாடலும் குறியீட்டிற்காக அல்ல. படம், வீடியோ மற்றும் இசை மாடல்கள் அதற்குப் பதிலாக Fantasi இல் திறக்கின்றன, இந்த இயந்திரத்தில் இயங்கும் மாடலுடன் படங்கள், வீடியோ மற்றும் இசையை உருவாக்குவதற்கான Omarchy இன் செயலி, அவற்றின் தொடக்கி உள்ளீட்டிலிருந்தும் உள்ளூர் மாடல்கள் பேனலில் அவற்றின் வரியிலிருந்தும்.

ஒரு மாடல் அது அமைக்கப்பட்ட விதத்திலேயே தொடர்ந்து இயங்குகிறது, எனவே Omarchy புதுப்பிப்பு உங்கள் ஏஜெண்டுகளின் கீழ் ஒன்றை ஒருபோதும் மறுதொடக்கம் செய்வதில்லை. நீங்கள் அமைத்த மாடலுக்கு Omarchy இல் புதிய இயக்கநேரம் அல்லது புதிய எடைகள் இருக்கும்போது, அதன் வரி புதுப்பிப்பு பொத்தானைக் காட்டுகிறது: அதை அழுத்தவும், மாடல் பின்னணியில் மீண்டும் அமைக்கப்படுகிறது, மாறியதை மட்டும் பதிவிறக்கி, மேலும் புதிய பதிப்பில் மறுதொடக்கம் செய்கிறது. நிறுத்தப்பட்ட மாடல் நிறுத்தப்பட்டே இருக்கிறது. `omarchy models update` டெர்மினலிலிருந்து ஒவ்வொரு மாடலுக்கும் அதையே செய்கிறது.

கட்டளை வரியிலிருந்து, `omarchy models start <recipe>` மற்றும் `omarchy models stop <recipe>` அதையே செய்கின்றன, `omarchy models status` ஒவ்வொரு மாடலையும் காட்டுகிறது, மேலும் `omarchy agent --local` நீங்கள் கடைசியாகத் தொடங்கிய மாடலில் உங்கள் இயல்புநிலை ஏஜெண்டைத் திறக்கிறது. pi, OpenCode மற்றும் Qwen Code ஒன்றைப் பயன்படுத்த முடியும்; வேறு எந்த இயல்புநிலையுடனும் அது pi இல் திறக்கிறது, அல்லது உங்களிடம் pi இல்லை என்றால் OpenCode இல். pi நீங்கள் அமைத்த ஒவ்வொரு மாடலையும், மேலும் நீங்கள் இணைத்த இயந்திரங்களில் உள்ளவற்றையும், அதன் சொந்த மாடல் தேர்வியில் பட்டியலிடுகிறது, எனவே சாதாரண `pi` அவற்றையும் அடைகிறது. எந்த OpenAI-இணக்கமான கிளையண்டும் இணைக்க முடியும்: `status` ஒவ்வொரு மாடலின் முகவரியையும் காட்டுகிறது (முதலாவது `http://127.0.0.1:11435/v1`), சமையல் குறிப்பு பெயரே மாடல், மேலும் விசை `~/.config/omarchy/agent-local/key` இல் உள்ளது.

`omarchy models remove <recipe>` ஒரு மாடலையும் வேறு எந்த மாடலும் பயன்படுத்தாத பதிவிறக்கங்களையும் நீக்குகிறது.

மூன்றாம் தரப்பு இயக்கநேரங்கள் அவற்றின் வெளியீட்டாளருடன் பெயரிடப்பட்டுள்ளன. Omarchy ஒவ்வொரு மாடலையும் நெட்வொர்க் அணுகல் இல்லாமல் இயக்குகிறது.

### உள்ளூர் LLMகள்

Omarchy உள்ளூர் LLM மாடல்களை இயக்குவதற்கான இரண்டு வழிகளைப் பரிந்துரைக்கிறது: LM Studio மற்றும் Ollama. LM Studio திறந்த-எடை மாடல்களைக் கண்டறிவதற்கும், அவற்றை நிறுவுவதற்கும், அவற்றை இயக்குவதற்கும் GUI இடைமுகத்தை வழங்குகிறது. எளிதாகத் தொடங்க இது ஒரு சிறந்த வழி. Ollama இதேபோல் செய்வதற்கு CLI ஐ வழங்குகிறது. ஆனால் நீங்கள் உள்ளூர் மாடல்களுக்குப் புதியவர் என்றால், நான் LM Studio உடன் தொடங்குவேன். Omarchy Menu இல் _Install > AI_ இன் கீழ் நீங்கள் இரண்டில் ஏதேனும் ஒன்றை நிறுவலாம்.

### Omarchy திறன்கள்

ஏஜெண்ட் திறன்கள் AI குறிப்பிட்ட கருவிகளைக் குறிப்பிட்ட விதத்தில் பயன்படுத்த உதவுகின்றன, மேலும் Omarchy அவற்றில் ஏழை வழங்குகிறது. omarchy திறன் கணினியைத் தனிப்பயனாக்குவதை உள்ளடக்குகிறது, உங்கள் Hyprland கட்டமைப்பை மாற்றுவது அல்லது பட்டியைச் சரிசெய்வது போல. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app, மற்றும் omarchy-make-game ஆகியவை புதிதாக ஏதாவது உருவாக்குவதை உள்ளடக்குகின்றன, omarchy-contribute ஒரு பிழையைப் புகாரளிப்பது அல்லது மேல்நிலைக்கு ஒரு சரிசெய்தலை அனுப்புவதை உள்ளடக்குகிறது, மேலும் omarchy-diagnose-crash ஒரு செயலிழப்பின் core dump வழியாகச் செயல்படுகிறது. அவை Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` மற்றும் ஒவ்வொரு `~/.hermes/profiles/*/skills`), மற்றும் பொதுவான `~/.agents/skills` இருப்பிடத்திற்கான திறன் கோப்பகங்களில் சிம்லிங்க் செய்யப்பட்டுள்ளன, எனவே பெரும்பாலான ஹார்னஸ்கள் அவற்றைத் தானாகவே எடுத்துக் கொள்கின்றன. அதே பெயரைக் கொண்ட உங்கள் சொந்த திறன் கோப்புறை முன்னுரிமை பெறுகிறது.

ஆனால் நீங்கள் இந்தத் திறன்களைச் சோதனை முயற்சியாகக் கருத வேண்டும். வெவ்வேறு மாடல்கள் அதை வெவ்வேறு விளைவுகளுக்குப் பயன்படுத்தும். முதலில் திட்டப் பயன்முறையில் இயக்குவது சிறந்தது, எனவே ஏஜெண்ட் என்ன மாற்ற விரும்புகிறது என்பது பற்றி உங்களுக்கு ஒரு யோசனை இருக்கும். பின்னர் ஏஜெண்ட் எல்லாவற்றையும் குழப்பினால், மாற்றங்களைத் திரும்பப் பெற அல்லது `omarchy reinstall configs` ஐ அழைக்கவும் தயாராக இருங்கள்.
