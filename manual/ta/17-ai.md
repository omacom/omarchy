# AI

Omarchy, உங்களுக்காக ஒரு இயல்புநிலையைத் தேர்ந்தெடுக்காமல், கீழே உள்ள coding agentகளுக்கான launcherகளை உள்ளடக்கியுள்ளது. முதல் முறை பயன்படுத்தும்போது அதன் CLI ஐ நிறுவ ஒரு கட்டளையை இயக்கவும், பின்னர் கேட்கும்போது அங்கீகரிக்கவும். Hermes மற்றும் OpenClaw ஆகியவை விதிவிலக்குகள்: அவற்றுக்காக mise வழியாக எதுவும் நிறுவப்படுவதில்லை, மேலும் அவற்றில் ஒன்றைத் தேர்ந்தெடுப்பது அதன் சொந்த சுயமாகப் புதுப்பிக்கும் நகலை அமைக்கிறது, கீழே உள்ள _Desktop பயன்பாடுகள்_ விளக்குவது போல.

### Agentகளை நிறுவுதலும் புதுப்பித்தலும்

Hermes மற்றும் OpenClaw தவிர, இந்த agentகள் mise இன் lazy நிறுவலைப் பயன்படுத்துகின்றன: முதல் தொடக்கம் CLI ஐ நிறுவுகிறது, பின்னர் வரும் தொடக்கங்கள் அதையே மீண்டும் பயன்படுத்துகின்றன. நிறுவப்பட்ட agent க்கு புதிய வெளியீடு உள்ளதா என்பதையும் mise அதிகபட்சம் நான்கு மணிநேரத்திற்கு ஒரு முறை சரிபார்க்கிறது, அது தொடங்குவதற்குச் சற்று முன்பு அல்லது shell prompt இல் பின்னணியில். அந்தப் புதுப்பிப்பு தோல்வியடைந்தால் அல்லது நீங்கள் offline இல் இருந்தால், நிறுவப்பட்ட பதிப்பு இயங்கும். `omarchy update` நிறுவப்பட்ட agentகளை Omarchy இன் மீதியுடன் சேர்த்துப் புதுப்பிக்கிறது, மேலும் `mup` mise ஆல் நிர்வகிக்கப்படும் கருவிகளை மட்டும் புதுப்பிக்கிறது.

`claude update`, `codex update` போன்ற agent இன் சொந்த updater, அல்லது ஒரு பயன்பாட்டில் உள்ள புதுப்பிப்பு பொத்தான், mise ஆல் நிர்வகிக்கப்படும் நிறுவலைப் புதுப்பிக்காது. `codex update` தோல்வியடைகிறது, மேலும் `claude update` வெற்றி என்று தெரிவித்தாலும் mise கண்காணிக்காத ஒரு தனி நகலை நிறுவக்கூடும். நீங்கள் agent இன் சொந்த installer மற்றும் updater ஐப் பயன்படுத்த விரும்பினால், அதை `disable_tools` இல் சேர்க்கவும்; [முன்பே நிறுவப்பட்ட CLI கருவிகள்](18-development-tools.md#preinstalled-cli-tools) ஐப் பார்க்கவும்.

உள்ளமைக்கப்பட்ட அனைத்து lazy கருவிகளையும் உங்களுக்குத் தேவைப்படுவதற்கு முன்பே நிறுவ, `mise install --include-lazy` ஐ இயக்கவும். இதில் agentகளுடன் Omarchy இன் மற்ற இயல்புநிலை CLI கருவிகளும் அடங்கும். ஒரு தனி கருவியை நிறுவுவது அல்லது உங்கள் சொந்த நிறுவலைப் பயன்படுத்துவது பற்றி [முன்பே நிறுவப்பட்ட CLI கருவிகள்](18-development-tools.md#preinstalled-cli-tools) ஐப் பார்க்கவும்.

`grok` என்பது `claude` மற்றும் `codex` போலவே mise இன் முதல்-தரப்பு `grok` package வழியாக நிறுவப்படுகிறது. `grok` ஐ இயக்கவும், அல்லது _Agent > Harness_ இன் கீழ் அதைத் தேர்ந்தெடுக்கவும். x.ai இல் உள்ள `curl | bash` installer ஐத் தவிர்க்கவும். அந்த வழி `~/.grok/bin` இல் இரண்டாவது நகலை வைக்கிறது, அதை `PATH` இல் முன்னால் சேர்க்கிறது, மேலும் Omarchy இன் wrapper ஐ மேலெழுதுகிறது.

`dsh` அதன் browser UI ஐ `127.0.0.1:3080` இல் திறக்கிறது, தொடக்க directory ஐ அதன் இயல்புநிலை workspace ஆகக் கொண்டு. அதன் browser UI தொடக்க prompt ஐ ஏற்காது, எனவே `omarchy agent prompt` அதை உங்கள் clipboard இல் உள்ள prompt உடன் ஒட்டுவதற்காகத் திறக்கிறது. Omarchy அதை DeepSeek இன் ஒப்புதல்-தேவையில்லாத permission preset உடன் தொடங்குகிறது. நீங்கள் அதன் அதிகாரப்பூர்வ model API ஐப் பயன்படுத்தும்போது DeepSeek Harness அமர்வு பதிவுகளை DeepSeek க்குப் பதிவேற்றுகிறது; அதன் browser UI இல் _அமைப்புகள் > பொது > அமர்வு பதிவைப் பதிவேற்று_ இன் கீழ் அதை அணைக்கவும். நீங்கள் அதற்கு அனுப்பும் கருத்தும் அமர்வுடன் சேர்த்துப் பதிவேற்றப்படும், நீங்கள் அதை `DSH_TELEMETRY_MODE=DISABLED` உடன் தொடங்கினால் தவிர.

### இயல்புநிலை agent

உங்கள் இயல்புநிலை agent ஐ `omarchy default agent <name>` உடன் அல்லது Omarchy Menu (`Super + Space`) இல் _Agent > Harness_ இன் கீழ் தேர்ந்தெடுக்கவும். Agent இன்னும் நிறுவப்படவில்லை என்றால், அதைத் தேர்ந்தெடுப்பது முதலில் அதை நிறுவும், மேலும் Agent க்கு அருகில், app launcher இல் அதற்கென தனி launcher ஒன்றும் கிடைக்கும். புதிய Omarchy ஒன்று இந்தத் தேர்வைச் செய்ய ஒரு முறை மட்டும் வரும் அறிவிப்புடன் உங்களை அழைக்கும்.

Claude ஐத் தேர்ந்தெடுப்பது Chromium, Chrome, Brave, Brave Origin, மற்றும் Edge க்கான அதன் browser நீட்டிப்பை அமைக்கவும் முயற்சிக்கிறது. நீட்டிப்பு அமைப்பு அனைத்து பயனர்களுக்கும் பொருந்தும், மேலும் உங்கள் system password ஐக் கேட்கக்கூடும்; ரத்து செய்வது அல்லது தோல்வியடைந்த நீட்டிப்பு நிறுவல் இருந்தாலும் Claude தேர்ந்தெடுக்கப்பட்டு தொடங்கப்படும். உங்கள் browser ஐ மறுதொடக்கம் செய்யவும், கேட்டால் நீட்டிப்பை இயக்கவும், மேலும் அதை இணைப்பதை முடிக்க Claude இல் உள்நுழையவும். இணைப்பைச் சரிபார்க்க Claude இல் `/chrome` ஐ இயக்கவும். Firefox மற்றும் Zen இந்த நீட்டிப்பை ஆதரிக்காது. இந்த அமைப்பு சேர்க்கப்படுவதற்கு முன்பே Claude ஏற்கனவே உங்கள் இயல்புநிலையாக இருந்தால், நீட்டிப்பை நிறுவ அதை மீண்டும் தேர்ந்தெடுக்கவும்.

நீங்கள் தேர்ந்தெடுத்த பிறகு, `Super + Shift + Ctrl + A` இயல்புநிலை agent ஐ ஒரு பிரத்யேக terminal சாளரத்தில் தொடங்கும் (அல்லது நீங்கள் இன்னும் தேர்ந்தெடுக்கவில்லை என்றால் picker ஐக் கொண்டு வரும்). `omarchy agent prompt "Review this project"` உடன் அதை நேரடியாக ஒரு பணிக்குள் தொடங்கவும் முடியும். Freebuff மற்றும் DeepSeek Harness தொடக்க prompt ஐ ஏற்காது, எனவே அவை உங்கள் clipboard இல் உள்ள prompt ஐ ஒட்டுவதற்காக அதற்குப் பதிலாகத் திறக்கும். இவ்வாறு தொடங்கப்படும் agentகள் அவற்றின் அந்தந்த நிறுத்தி-கேட்காத முறைகளில் கவனிக்கப்படாமல் இயங்கும், எனவே அவை உண்மையில் விஷயங்களைச் செய்யத் தயாராக இருங்கள்! MiniMax Code இன் ஊடாடும் அமர்வுகளுக்கு அத்தகைய முறை இல்லை, எனவே அது வழக்கம் போல் அனுமதிகளைக் கேட்கும். மேலும் agentகள் உங்கள் home directory க்கான நம்பிக்கையை நினைவில் வைக்க மறுப்பதால், `$HOME` இலிருந்து தொடங்குவது அதற்குப் பதிலாக `~/Work` இல் தொடங்கும்.

Terminal shortcutகளும் உள்ளன: `a` தற்போதைய terminal இல் இயல்புநிலை agent ஐ inline ஆக இயக்குகிறது, அதே நேரத்தில் `c`, `cx`, மற்றும் `cy` OpenCode, Claude Code, மற்றும் Codex ஐ நேரடியாகத் தொடங்குகின்றன (மீண்டும் அவற்றின் தானாக-ஒப்புதல் அளிக்கும் முறைகளில்). Theme மாற்றங்களும் agentகளுக்கு ஒத்திசைகின்றன: நீங்கள் Omarchy theme ஐ மாற்றும்போது Claude Code, Pi, OpenCode, மற்றும் Hermes (Omarchy அதை நிறுவிய பிறகு) அனைத்தும் அதனுடன் சேர்ந்து மாறும்.

### உங்கள் agent வழிமுறைகள்

ஒவ்வொரு agent க்கான தனிப்பட்ட விதிகள் `~/.agents/AGENTS.md` இல், `~/.agents/skills` இல் உள்ள பகிரப்பட்ட skillகளுக்கு அருகில் செல்கின்றன. அதை _Agent > வழிமுறைகள்_ இன் கீழ் திறக்கவும், இது அதைத் தன் சொந்த global கோப்பை வைத்திருக்கும் ஒவ்வொரு harness இலும் இணைக்கிறது: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, Copilot இன் `~/.copilot/copilot-instructions.md`, மற்றும் பல. Crush மற்றும் Amp `~/.config/AGENTS.md` இணைப்பைப் படிக்கின்றன, அதே நேரத்தில் omp, Kimi, மற்றும் DeepSeek Harness `~/.agents/AGENTS.md` ஐ நேரடியாகப் படிக்கின்றன. இயல்புநிலை agent ஐத் தேர்ந்தெடுப்பது அதையும் இணைக்கிறது. ஏற்கனவே உங்களிடம் இருந்த வழிமுறைகள் கோப்பு, இன்னும் ஒன்று இல்லை என்றால் பகிரப்பட்டதாக மாறும்; இல்லையெனில் அது இணைப்புக்கு அருகில் `.bak` ஆக வைக்கப்படும். மற்றொரு agent ஐ நிறுவிய பிறகு மீண்டும் இணைக்க `omarchy agent instructions` ஐ இயக்கவும்.

### Agentகள் panel

மேல் bar இல் agentகள் icon ஒன்று உள்ளது. நீங்கள் ஒரு agent ஐ அமைப்பதற்கு முன், அதன் panel Claude, Codex, அல்லது Grok இல் உள்நுழைவதன் வழியாக உங்களை அழைத்துச் செல்கிறது, மேலும் முதலாவது உங்கள் இயல்புநிலை agent ஆகிறது. அதன் பிறகு, panel ஒவ்வொரு சந்தாவையும் ஒரே பக்கத்தில் வைக்கிறது: ஒவ்வொரு agent மற்றும் கணக்கு அதன் plan உடன், அதன் 5-மணிநேர அமர்வு மற்றும் வாராந்திர வரம்புகள் ஒவ்வொன்றுக்கும் ஒரு meter உடன் அது மீட்டமைக்கும் வரையிலான நேரத்துடன் (சரியான சதவீதத்திற்கு hover செய்யவும்), அல்லது மீதமுள்ள முன்பண இருப்பு, அவை அனைத்திலும் நீங்கள் பயன்படுத்தியதைச் சுழற்றிக் காட்டும் ஒரு வரியின் கீழ், இந்த வாரத்தில் tokenகள் மற்றும் நீங்கள் அதிகம் பயன்படுத்திய model போல. _ஏதாவது சிறப்பாக உருவாக்குங்கள்_ இன் கீழ் அது புதிய theme, plugin, app, அல்லது game க்கான தொடக்க promptகளை வழங்குகிறது, அவை பணியை உங்கள் இயல்புநிலை agent இடம் ஒப்படைக்கின்றன. பயன்பாடுகள் Omarchy இன் சொந்த Hype, Monologue, மற்றும் Omacut போல, C++ மற்றும் Qt Quick இல், omarchy-make-app agent skill ஐப் பின்பற்றி உருவாக்கப்படுகின்றன, மேலும் அவற்றுக்குத் தேவையான compiler மற்றும் Qt பாகங்கள் நிறுவப்பட்டு வருகின்றன. Gameகள் `~/Games/vibes` இல் ஒரு ஒற்றை three.js பக்கம், omarchy-make-game agent skill ஐப் பின்பற்றி, மேலும் அனைத்தும் தற்போதைய theme இல் ஒரு Game Vibes launcher இலிருந்து திறக்கும்; அவை three.js ஐ web இலிருந்து ஏற்றுகின்றன, எனவே தொடங்க அவற்றுக்கு இணைப்பு தேவை. Claude Code, Codex, Grok, Kimi, Cursor மற்றும் அதன் Grok Bot ஒதுக்கீடு, GitHub Copilot, Muse, Antigravity, மற்றும் Devin ஆகியவை அவற்றின் வரம்புகளுடன் உடனடியாக உள்ளடக்கப்பட்டுள்ளன, Kimchi அதன் plan, முன்பண creditகள், மற்றும் செலவு budgetகளுடன், மேலும் Hermes, Mistral Vibe, மற்றும் Qwen Code நீங்கள் அவற்றைப் பயன்படுத்திய பிறகு அவற்றின் அமர்வுகள் மற்றும் tokenகளைக் காட்டுகின்றன. நீங்கள் pi, omp, அல்லது opencode வழியாகப் பயன்படுத்தும் Provider planகள் மற்றும் keyகளும் தோன்றும்: OpenCode Zen மற்றும் Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan, மற்றும் Synthetic அவற்றின் வரம்புகளுடன்; OpenRouter மற்றும் DeepSeek அவற்றின் முன்பண இருப்புகளுடன்; Fireworks கடந்த 30 நாட்களில் அதன் செலவுடன். உங்கள் சொந்த hardware இல் நீங்கள் இயக்கும் modelகளிலிருந்து வரும் Tokenகளும் மொத்தங்களில் கணக்கிடப்படுகின்றன; modelகளுக்குத் தனியாக ஒரு panel உள்ளது, [உள்ளூர் modelகள்](#local-models) இன் கீழ் விவரிக்கப்பட்டுள்ளது. ஒவ்வொரு agent உம் ஒரு முறை மட்டுமே கணக்கிடப்படுகிறது, அதற்கு யார் பில் செய்கிறார்களோ அவரின் கீழ், நீங்கள் எத்தனை harnessகள் வழியாக அதை இயக்கினாலும்.

Panel க்கு bar icon ஐ இடது-click செய்யவும் அல்லது `Super + Ctrl + X` ஐ அழுத்தவும், உங்கள் இயல்புநிலை agent ஐத் தொடங்க வலது-click செய்யவும், புதுப்பிக்க நடு-click செய்யவும். அதன் பின்னால் உள்ள பயன்பாட்டுப் பதிவுகள் ஒவ்வொரு 15 நிமிடங்களுக்கும் `omarchy agent usage update` ஆல் மீண்டும் உருவாக்கப்படுகின்றன, மேலும் panel ஒத்திசைக்கப்பட்ட folder வழியாக உங்கள் மற்ற இயந்திரங்களிலிருந்து பயன்பாட்டை இணைக்கவும் முடியும். முழு அமைப்புகளுக்கு `$OMARCHY_PATH/shell/plugins/agents/` இன் கீழ் உள்ள README ஐப் பார்க்கவும்.

### பல சந்தாக்கள்

நீங்கள் ஒன்றுக்கு மேற்பட்ட Claude, Codex, அல்லது Grok plan க்குப் பணம் செலுத்தினால் — தனிப்பட்ட Max ஒன்றும் பணி ஒன்றும், என்று வைத்துக்கொள்வோம் — Omarchy அவை அனைத்தையும் உள்நுழைந்த நிலையில் வைத்து அவற்றுக்கிடையே நகர முடியும். Agentகள் panel இல் + உடன் ஒரு சந்தாவைச் சேர்க்கவும், இது அங்கேயே உங்களை அதன் வழியாக அழைத்துச் செல்கிறது, அல்லது `omarchy agent account add claude Work` உடன் (அல்லது `codex`, அல்லது `grok`). CLI இல்லை என்றால் அது அதை நிறுவும். ஒரு provider க்கான முதல் கணக்கு உங்கள் வழக்கமான browser வழியாக, CLI எப்போதும் பார்க்கும் இடத்திலேயே உள்நுழைகிறது. அதன் பிறகு வரும் ஒவ்வொன்றும் ஒரு தனிப்பட்ட சாளரம் வழியாக உள்நுழைகிறது, எனவே உங்கள் browser ஏற்கனவே உள்நுழைந்துள்ள கணக்கு தவறுதலாகப் பிடிக்கப்படாது; நீங்கள் சேர்க்கும் கணக்காக அங்கே உள்நுழையவும், மேலும் ஏற்கனவே திறந்துள்ள தனிப்பட்ட சாளரத்தை முதலில் மூடவும். இதைச் செய்ய CLI இலிருந்து ஒருபோதும் வெளியேற வேண்டாம்: வெளியேறுவது சேமிக்கப்பட்ட உள்நுழைவை ரத்து செய்கிறது, மேலும் அந்தக் கணக்கு மீண்டும் சேர்க்கப்பட வேண்டும்.

உங்கள் சந்தா உள்நுழைவுகளை SSH வழியாக மற்றொரு Omarchy இயந்திரத்திற்கு நகலெடுக்க, `omarchy agent account copy user@laptop` ஐ இயக்கவும். இலக்கில் receiver நிறுவப்படவில்லை என்றால் அனுப்புபவர் தற்காலிக receiver ஒன்றை வழங்குகிறார், எனவே பழைய Omarchy இயந்திரங்கள் புதுப்பிப்பு இல்லாமல் கணக்குகளைப் பெற முடியும். நிறுவப்பட்ட receiverகளுக்கு முன்னுரிமை கிடைக்கும். இது அனைத்து Claude, Codex, மற்றும் Grok சந்தாக்களையும் நகலெடுக்கிறது; அவற்றைத் தேர்ந்தெடுக்க provider பெயர்களைச் சேர்க்கவும், `omarchy agent account copy laptop claude` இல் உள்ளது போல. கணக்குப் பெயர்கள் மற்றும் கட்டளை IDகள் மூலத்துடன் பொருந்துகின்றன, இலக்கில் ஏற்கனவே உள்ள கணக்குகள் உட்பட. தொடர்பில்லாத இலக்கு கணக்குகள் அவற்றின் பெயர்கள் முரண்பட்டால் எண் பின்னொட்டு பெறுகின்றன, மேலும் அமைப்புகள், skillகள், pluginகள், மற்றும் உரையாடல் வரலாறு ஒவ்வொரு இயந்திரத்திற்கும் உள்ளூராகவே இருக்கும்.

ஏற்கனவே உள்ள இலக்கு சான்றுகள் வைக்கப்படுகின்றன. அங்கே ஏற்கனவே உள்நுழைந்துள்ள மூல கணக்கு அதன் சான்றுகளை மாற்றாமல் அதன் பெயர் ஒத்திசைக்கப்படுகிறது; மற்ற கணக்குகள் அதனுடன் சேர்த்துச் சேர்க்கப்படுகின்றன. பொருந்தும் கணக்குகளுக்குச் சேமிக்கப்பட்ட சான்றுகளை மாற்ற, இலக்கில் அந்தக் கணக்கின் அமர்வுகளை மூடிய பிறகு `omarchy agent account copy --replace laptop claude` ஐப் பயன்படுத்தவும். புதிய இலக்கு மூலத்தின் செயலில் உள்ள கணக்கு மற்றும் மாறுதல் விருப்பங்களையும் பெறுகிறது; நிறுவப்பட்ட இலக்கு அதன் சொந்தத்தை வைத்திருக்கிறது.

சான்றுகள் SSH வழியாகப் பயணிக்கின்றன மற்றும் இலக்கில் தனிப்பட்ட கோப்புகளில் சேமிக்கப்படுகின்றன, எனவே நீங்கள் நம்பும் இயந்திரங்களுக்கு மட்டும் நகலெடுக்கவும். இது ஒரு முறை நகல், தொடர்ச்சியான ஒத்திசைவு அல்ல. Codex refresh tokenகள் மற்றொரு இயந்திரத்தால் சுழற்றப்படலாம், நகலெடுக்கப்பட்ட உள்நுழைவுக்குப் புதுப்பிப்பு தேவைப்படும் நிலையை விட்டுவிடும்; பல இயந்திரங்களில் ஒரே நேரத்தில் பயன்படுத்த தனி உள்நுழைவுகள் மிகவும் நம்பகமான தேர்வாக இருக்கும். [Codex இன் கணக்கு அங்கீகார வழிகாட்டுதல்](https://developers.openai.com/codex/auth/ci-cd-auth) ஐப் பார்க்கவும்.

ஒரு provider க்கு ஒரு கணக்கு செயலில் உள்ளது, மேலும் ஒவ்வொரு புதிய அமர்வும் அதுவாகவே தொடங்குகிறது: `cx`, `cy`, ஒரு சாதாரண `claude`, `codex`, அல்லது `grok`, `omarchy agent` வழியாகத் தொடங்கப்படும் எதுவும், மற்றும் `PATH` இல் CLI ஐக் கண்டறியும் scriptகள் அல்லது editorகள். `omarchy agent account use work` உடன் மாற்றவும் (மேலும் `omarchy agent account use main` உடன் திரும்பவும்), அல்லது panel இல் ஒரு கணக்கின் எண்ணை அழுத்தி பின்னர் `Enter` ஐ அழுத்துவதன் மூலம் (அல்லது அதன் Use பொத்தானை click செய்வதன் மூலம்). இயங்கும் Claude அமர்வுகளும் மாறுகின்றன, அவற்றின் அடுத்த செய்தியிலிருந்து: ஒவ்வொரு Claude அமர்வும் `~/.claude` இல் இயங்குகிறது, இது எப்போதும் செயலில் உள்ள கணக்கின் உள்நுழைவை வைத்திருக்கிறது. பழைய Omarchy ஆல் கணக்கின் சொந்த folder இல் தொடங்கப்பட்ட Claude அமர்வு அது மூடும் வரை அந்த உள்நுழைவை வைத்திருக்கிறது, எனவே மாற்றம் அந்த அமர்வுகளுக்குப் பெயரிட்டு அவை போன பிறகு தானாகவே முடிவடைகிறது. இயங்கும் Codex மற்றும் Grok அமர்வுகள் அவை தொடங்கிய கணக்கிலேயே இருக்கும். உரையாடல் வரலாறு, அமைப்புகள், skillகள், மற்றும் pluginகள் கணக்குகள் முழுவதும் பகிரப்படுகின்றன, எனவே அதே folder இல் `claude --continue` நீங்கள் புதிய கணக்கில் விட்ட இடத்திலிருந்து தொடர்கிறது.

ஒன்றுக்கு மேற்பட்ட கணக்குகளுடன், panel ஒவ்வொரு கணக்கின் வரம்புகளையும் அருகருகில் காட்டுகிறது, செயலில் உள்ளது குறிக்கப்பட்டு. இயல்பாக செயலில் உள்ள கணக்கு ஒரு வரம்பின் 95% ஐக் கடக்கும்போது Omarchy உங்களுக்கு அறிவிக்கிறது, மேலும் அறிவிப்பை click செய்வது அதிக இடவசதி உள்ள கணக்குக்கு மாற்றுகிறது. Panel இல் ஒரு கணக்கின் வரியில் hover செய்து Use க்கு அருகில் தோன்றும் Autoswitch ஐ click செய்யவும் (அல்லது `m` ஐ அழுத்தவும்), அல்லது அது தானாகவே மாற `omarchy agent account mode auto` ஐ இயக்கவும்; அது இயக்கத்தில் இருக்கும்போது, Autoswitch Use இன் இடத்தைப் பிடிக்கிறது, மேலும் அதை மீண்டும் click செய்வது அறிவிப்புக்குத் திரும்புகிறது. வரம்பை மாற்ற ஒரு எண்ணைச் சேர்க்கவும், `omarchy agent account mode auto 90` இல் உள்ளது போல. ஒவ்வொரு கணக்கும் வரம்புக்கு மேல் இருந்தால், எந்தக் கணக்கு முதலில் விடுபடும் என்பதுடன் ஒரு முறை நீங்கள் கேட்பீர்கள். செயலில் உள்ள கணக்கு அதன் வரம்பிலிருந்து 15 புள்ளிகளுக்குள் இருக்கும்போது (இயல்புநிலையில் 80%), அதன் வரம்புகள் ஒவ்வொரு 15 நிமிடங்களுக்குப் பதிலாக ஒவ்வொரு மூன்று நிமிடங்களுக்கும் சரிபார்க்கப்படுகின்றன.

`omarchy agent account list` ஒவ்வொரு கணக்கையும் அதன் சமீபத்திய வரம்புகளையும் காட்டுகிறது, `omarchy agent account remove work` ஒன்றை மறக்கிறது, மற்றும் `omarchy agent account rename primary Hey` ஒன்றுக்குப் பெயர் மாற்றுகிறது (அல்லது panel இல் ஒரு கணக்கின் பெயரை click செய்யவும்). இந்தக் கட்டளைகள் உங்கள் இயல்புநிலை agent இன் கணக்குகளில் வேலை செய்கின்றன; மற்ற provider ஐ அடைய, முதலில் அதற்குப் பெயரிடவும், `omarchy agent account use codex side` இல் உள்ளது போல. `~/.claude` அல்லது `~/.codex` இல் நீங்கள் ஏற்கனவே வைத்திருந்த உள்நுழைவு _Main_ கணக்கு ஆகும். Codex இனுடையது அது இருக்கும் இடத்திலேயே இருக்கும்; Claude இனுடையது மற்றொரு கணக்கு செயலில் இருக்கும்போது தன் சொந்த folder இல் காத்திருக்கிறது. சுமார் எட்டு மணிநேரத்திற்கு மேல் பயன்படுத்தப்படாமல் விடப்பட்ட கணக்கு _உள்நுழைவு தேவை_ என்று காட்டக்கூடும்; அந்தக் கணக்கை panel இலேயே மீண்டும் உள்நுழைய அதை click செய்யவும், அல்லது அதற்கு மாறி ஒரு அமர்வைத் தொடங்கவும், இது தானாகவே உள்நுழைவைப் புதுப்பிக்கிறது. நீங்கள் `claude mcp add` உடன் சேர்க்கும் MCP serverகள் ஒவ்வொரு Claude கணக்கையும் அடைகின்றன, ஏனெனில் அவை அனைத்தும் `~/.claude` இல் இயங்குகின்றன; Codex மற்றும் Grok க்கு, ஒரு கணக்கு சேர்க்கப்பட்டபோது உங்களிடம் இருந்த serverகள் அதனுடன் வருகின்றன, ஆனால் பின்னர் வருபவை நீங்கள் அவற்றைச் சேர்த்த கணக்கை மட்டுமே அடைகின்றன. Claude Desktop தன் சொந்த உள்நுழைவை வைத்திருக்கிறது, மேலும் CLI binary க்கு முழுமையான path உடன் உள்ளமைக்கப்பட்ட Codex அல்லது Grok கருவிகள் மாற்றத்தைப் பின்பற்றாது. வெளிப்படையான `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, அல்லது `GROK_HOME` தேர்ந்தெடுக்கப்பட்ட கணக்கை விட முன்னுரிமை பெறுகிறது.

### செயலிழப்பு கண்டறிதல்

Omarchy செயல்முறை செயலிழப்புகளுக்காக systemd-coredump ஐக் கண்காணிக்கிறது. நீங்கள் இயல்புநிலை agent ஐத் தேர்ந்தெடுத்த பிறகு, core dump செய்யும் உங்கள் எந்த நிரலும் "Process crashed" அறிவிப்பைக் கொண்டு வரும் — அதை click செய்யவும், மேலும் செயலிழப்பு உங்கள் இயல்புநிலை agent இடம் Omarchy இன் omarchy-diagnose-crash skill உடன் ஒப்படைக்கப்படும், இது core dump இலிருந்து உண்மைகளை நிறுவுவதற்கும் செயலிழப்பு upstream இல் புகாரளிக்கத் தகுந்ததா என்பதை முடிவு செய்வதற்கும் agent ஐ வழிநடத்துகிறது. `coredumpctl list` இலிருந்து எந்த PID க்கும் எதிராக `omarchy agent crash <pid>` உடன் அதைக் கையாலும் இயக்கலாம்.

கண்காணிப்பு இயல்பாக இயக்கத்தில் உள்ளது. அதை _தூண்டுதல் > மாற்று > செயலிழப்பு பதிவை அணை_ இன் கீழ் அணைக்கவும் (அல்லது `omarchy toggle crash-capture` உடன்) மேலும் அறிவிப்புகள் நிற்கும்; `omarchy agent crash <pid>` இன்னும் கையால் வேலை செய்கிறது.

செயலிழப்புகளை ஒரு நேரத்தில் ஒரு நிரல் வீதமும் அமைதிப்படுத்தலாம், இதைத்தான் கண்டறிதல் இறுதியில் உங்களுக்கு வழங்குகிறது. `omarchy crash mute hyprland` அந்த நிரலுக்கு மட்டும் அறிவிப்புகளை நிறுத்துகிறது, `omarchy crash mute hyprland off` அவற்றைத் திரும்பக் கொண்டு வருகிறது, மேலும் `omarchy crash mute` தனியாக நீங்கள் அமைதிப்படுத்தியதைப் பட்டியலிடுகிறது. இது binary இன் path ஐ அதன் பெயரைப் போலவே மகிழ்ச்சியுடன் ஏற்கிறது, எனவே `omarchy crash mute /usr/bin/hyprland` அதே வேலையைச் செய்கிறது. இடைவெளி உள்ள பெயரை மேற்கோள் காட்டவும், `omarchy crash mute 'Some App'` இல் உள்ளது போல. மற்ற அனைத்தும் இன்னும் அறிவிக்கும், மேலும் அமைதிப்படுத்தப்பட்ட நிரல் இன்னும் செயலிழக்கும் — இது நினைவூட்டலை மறைக்கிறது, எதையும் சரி செய்யாது.

### Desktop பயன்பாடுகள்

_நிறுவு > AI_ menu சில வரைகலை AI பயன்பாடுகளையும் கொண்டுள்ளது: Amp Desktop, Antigravity Desktop, ChatGPT desktop app, Claude desktop app (Anthropic இன் Linux beta, Chat, Cowork, மற்றும் Claude Code tabகளுடன்), xAI இன் modelகளுடன் அரட்டை அடிக்க Grok Bot, Herdr Desktop, Hermes Desktop, OpenClaw, Perplexity desktop app, மற்றும் T3 Code. Grok Bot என்பது desktop அரட்டை பயன்பாடு. Coding agent என்பது `grok` கட்டளை.

Hermes Desktop பற்றித்தான் தெரிந்து கொள்ள வேண்டும், ஏனெனில் ஒரு இயந்திரத்தில் ஒரு Hermes உள்ளது, அது பயன்பாட்டினுடையது: Hermes எப்போதும் பயன்பாடு வழியாக மட்டுமே நிறுவப்படுகிறது, மேலும் இயல்புநிலை agent இயக்கும் `hermes` கட்டளை பயன்பாட்டினுடையது. Hermes ஐ இயல்புநிலை agent ஆகத் தேர்ந்தெடுப்பது _நிறுவு > AI_ உள்ளீடு செய்வதையே நிறுவுகிறது: package, மற்றும் Hermes இன் சொந்த installer ஆல் அமைக்கப்பட்ட `~/.hermes` இன் கீழ் ஒரு Hermes runtime, இது முதல் முறை சில நிமிடங்கள் எடுக்கும். அந்த runtime தான் terminal `hermes` கட்டளை, இயல்புநிலை agent மற்றும் பயன்பாடு அனைத்தும் பயன்படுத்தும் ஒரே Hermes, மேலும் அது Omarchy வெளியீட்டிற்காகக் காத்திருப்பதற்குப் பதிலாக `hermes update` உடன் தன்னைப் புதுப்பிக்கிறது. அதை நிறுவுவது Hermes க்கு Omarchy theme ஐ `omarchy` என்ற பெயரிடப்பட்ட skin ஆகவும் வழங்குகிறது, இது நீங்கள் themeகளை மாற்றும்போது ஒவ்வொரு Hermes மேற்பரப்பும் பின்பற்றுகிறது; நீங்கள் அது வேண்டாம் என்றால் Hermes இன் தோற்ற அமைப்புகளின் கீழ் அல்லது `/skin` உடன் வேறொன்றைத் தேர்ந்தெடுக்கவும், மேலும் Omarchy அந்தத் தேர்வைத் தனியாக விட்டுவிடும். _நீக்கு > AI_ இன் கீழ் பயன்பாட்டை நீக்குவது முதலில் Hermes ஐ மூடுகிறது, gateway உட்பட, அந்த runtime ஐ அதனுடன் எடுத்துச் செல்கிறது, மேலும் உங்கள் அரட்டைகள், நினைவுகள், மற்றும் Hermes தனக்காக எழுதிய skillகளை நீங்கள் வேறுவிதமாகச் சொன்னால் தவிர வைத்திருக்கிறது: அந்தத் தரவும் உங்கள் இணைப்பு அமைப்புகளும் கூட போக வேண்டுமா என்று அது கேட்கிறது, இயல்பாக இல்லை என்று.

OpenClaw இன் desktop அனுபவம் அதன் Control UI ஆகும், இது அதன் சொந்த உள்ளூர் gateway ஆல் ஆதரிக்கப்படும் web பயன்பாடாகத் திறக்கிறது. OpenClaw `~/.openclaw` இல் வாழ்கிறது மற்றும் தன்னைப் புதுப்பிக்கிறது: Control UI இன் "Update Gateway" பொத்தானைப் பயன்படுத்தவும் அல்லது `openclaw update` ஐ இயக்கவும், மேலும் gateway புதிய பதிப்பில் மறுதொடக்கம் செய்யும். புதிய நிறுவல் எந்த வெளியீட்டிலிருந்து தொடங்குகிறது என்பதை Omarchy மட்டுமே தேர்ந்தெடுக்கிறது. OpenClaw உங்கள் இயல்புநிலை agent ஆகவும் இருக்கலாம்: அதை _Agent > Harness_ இன் கீழ் தேர்ந்தெடுப்பது `~/.openclaw` இல் அதே நகலை அமைக்கிறது, மேலும் agent அதன் gateway உடன் இணைக்கப்பட்ட OpenClaw இன் terminal UI ஐத் திறக்கிறது. _நீக்கு > AI_ இன் கீழ் OpenClaw ஐ நீக்குவது gateway service மற்றும் பயன்பாட்டை அதனுடன் எடுத்துச் செல்கிறது, பின்னர் `~/.openclaw` கூட போக வேண்டுமா என்று கேட்கிறது, ஏனெனில் அது OpenClaw உடன் மற்றும் அது பதிவிறக்கும் plugin runtimeகளுடன் உங்கள் அரட்டைகள் மற்றும் சான்றுகளை வைத்திருக்கிறது; இயல்புநிலை அதை வைத்திருக்கிறது, மேலும் OpenClaw ஐ மீண்டும் நிறுவுவது அதை மீண்டும் எடுத்துக்கொள்கிறது.

Herdr Desktop என்பது [Herdr](https://herdr.dev) desktop பயன்பாடு: நீங்கள் சாளரத்தை மூடும்போது அதன் core இல் தொடர்ந்து இயங்கும் terminalகள் மற்றும் coding agentகளின் spaceகள், tabகள், மற்றும் paneகள். இது package இலிருந்து அல்லாமல் Herdr இன் சொந்த installer இலிருந்து வருகிறது, எனவே அது `~/.local/share/herdr-app` இல் வாழ்கிறது, உங்களிடம் ஏற்கனவே ஒன்று இல்லை என்றால் `~/.local/bin/herdr-core` இல் அதன் core ஐக் கொண்டு வருகிறது, மேலும் இரண்டையும் தன்னைப் புதுப்பிக்கிறது. இது Omarchy `Super + Ctrl + Return` இல் வழங்கும் `herdr` கட்டளைக்குப் பதிலாக அல்லாமல் அதற்கு அருகில் அமர்கிறது, மேலும் அந்தக் கட்டளையின் நேரடி keyகளைப் பெறுகிறது: `Alt + Return` மற்றும் `Alt + Shift + Return` ஒரு pane ஐ கீழே அல்லது வலதுபுறமாகப் பிரிக்கிறது, `Alt + Escape` அதை மூடுகிறது, `Ctrl + Alt + Arrow` paneகளுக்கிடையே நகர்கிறது, `Alt + 1..9` மற்றும் `Alt + Left/Right` ஒரு tab ஐத் தேர்ந்தெடுக்கிறது, மேலும் `Alt + Up/Down` spaceகளுக்கிடையே நகர்கிறது. `Ctrl + 1..9` ஒரு space ஐத் தேர்ந்தெடுக்கிறது மற்றும் `Alt + Shift + Up/Down` agentகள் வழியாகச் செல்கிறது. `Ctrl + Space` prefix keyகள் terminal-மட்டுமாகவே இருக்கும், ஏனெனில் பயன்பாடு ஒரு வரிசைக்காக சாதாரண Ctrl key ஐ வைத்திருக்க முடியாது. Omarchy இவற்றை `~/.config/herdr-app/keys.json` இல் எழுதுகிறது, மேலும் `omarchy-refresh-herdr-app` அவற்றைத் திரும்ப வைக்கிறது. அதை நிறுவுவது Herdr இன் Omarchy theme ஐத் தேர்ந்தெடுக்கிறது, இது அப்போதிலிருந்து உங்கள் Omarchy theme ஐப் பின்பற்றுகிறது. Herdr light mode க்கு ஒரு theme ஐயும் dark mode க்கு ஒன்றையும் வைத்திருக்கிறது, எனவே dark மற்றும் light Omarchy themeக்கு இடையில் மாறிய பிறகு, மற்ற mode க்காக Herdr இன் theme picker இல் Omarchy ஐ மீண்டும் ஒரு முறை தேர்ந்தெடுக்கவும்.

T3 Code package இலிருந்து அல்லாமல் `~/.local/share/t3code` இல் அதன் அதிகாரப்பூர்வ AppImage வெளியீட்டிலிருந்து இயங்குகிறது, எனவே அது தன்னைப் புதுப்பிக்கிறது. அதை நிறுவுவது Stable அல்லது Nightly channel இல் தொடங்க வேண்டுமா என்று கேட்கிறது; பின்னர் T3 Code இன் அமைப்புகளில் மாற்றவும். உங்கள் threadகள் மற்றும் அமைப்புகள் `~/.t3` இல் வாழ்கின்றன, மேலும் _நீக்கு > AI_ இன் கீழ் T3 Code ஐ நீக்குவது அவற்றை அதனுடன் எடுத்துச் செல்கிறது.

### உள்ளூர் modelகள்

உங்கள் coding agentகளுக்காக உங்கள் சொந்த இயந்திரத்தில் திறந்த model ஒன்றை இயக்கவும். உங்கள் promptகள் மற்றும் code இயந்திரத்திலேயே இருக்கும்; model க்கு அனுப்பப்படும் எதுவும் அதை விட்டு வெளியேறாது. இதனுடன் தொடங்கவும்:

```bash
omarchy models use best text
```

இது இந்த இயந்திரத்திற்கான சிறந்த text model ஐ அமைக்கிறது, உங்கள் agentகள் பயன்படுத்தும் வகை. Image, video மற்றும் music modelகளுக்குத் தனித்தனியாகச் சிறந்தது உள்ளது: `omarchy models use best image`, `video` அல்லது `music`. இந்த இயந்திரத்திற்கான ஒவ்வொரு வகையின் தேர்வையும் பார்க்க `omarchy models use best` ஐ இயக்கவும்.

அல்லது மேல் bar இல், agentகள் icon க்கு அருகில் உள்ள அதன் sparkles icon இலிருந்து, அல்லது Super + Ctrl + Shift + X உடன் உள்ளூர் modelகள் panel ஐத் திறந்து, + ஐத் தேர்ந்தெடுக்கவும். ஒரு model இந்த இயந்திரத்திற்குப் பொருந்தும்போது icon தோன்றும். Modelகளை இயக்கும் Podman, Omarchy உடன் வருகிறது, NVIDIA இயந்திரத்தில் NVIDIA இன் container toolkit உம் வருகிறது, இது அவற்றுக்கு GPU ஐ வழங்குகிறது; ஏதாவது இல்லை என்றால், முதல் அமைப்பு அதை நிறுவும். Omarchy பின்னர் இந்த இயந்திரத்திற்குப் பரிந்துரைக்கப்பட்ட model ஐத் தேர்ந்தெடுத்து, அதைப் பதிவிறக்கி, அதைத் தொடங்குகிறது. பத்துகள் GB பதிவிறக்கத்தையும் model இயங்கும்போது இயந்திரத்தின் நினைவகத்தின் பெரும்பகுதி பயன்பாட்டில் இருப்பதையும் எதிர்பார்க்கவும்: Flash Next அதன் முழு 256K context உடன் சுமார் 100 GiB ஐப் பயன்படுத்துகிறது. மற்ற modelகள் அதற்குத் தேவையான நினைவகத்தை வைத்திருந்தால், அது நிறுத்தப்பட்ட நிலையில் அமைக்கப்படுகிறது, நீங்கள் ஒன்றை நிறுத்தியதும் தொடங்கத் தயாராக. Model logout இல் நிற்கும்; வேறு ஏதாவதற்கு நினைவகம் தேவைப்படும்போது அதை நீங்களே நிறுத்தவும்.

`omarchy models list` விருப்பங்களைக் காட்டுகிறது மற்றும் சில ஏன் பொருந்தாது என்பதை விளக்குகிறது. மற்றொன்றை அமைக்க, `omarchy models use <recipe>` ஐ இயக்கவும். இன்று, 128 GB Strix Halo இயந்திரங்களுக்கு `qwen3.8-flash-next-gufo` மற்றும் `qwen3.8-27b-gufo` கிடைக்கின்றன; 27B சுமார் 40 GiB எடுக்கும், எனவே அது மற்ற வேலைகளுக்கு இடம் விடுகிறது. Intel இன் Arc B390 உடன் 64 GB laptop இல், `qwen3.6-35b-a3b-llamacpp` சுமார் 30 GiB இல் இயங்குகிறது. புதிய recipeகள் மற்றும் பரிந்துரைகள் package வழியாக `omarchy update` உடன் வருகின்றன.

நீங்கள் அமைக்கும் ஒவ்வொரு model க்கும் உள்ளூர் modelகள் panel இல் தனி வரி கிடைக்கும்: அதைத் தொடங்க play, அதை நிறுத்தி அதன் நினைவகத்தை விடுவிக்க pause, மற்றும் அதில் உங்கள் agent ஐத் திறக்க terminal பொத்தான். மேலே குறுக்காக, ஒரு bar இயந்திரத்தின் நினைவகம் Omarchy க்கே (system மற்றும் உங்கள் பயன்பாடுகள்), ஒவ்வொரு இயங்கும் model, மற்றும் இலவசமாக உள்ளவை என எப்படிப் பிரிக்கப்பட்டுள்ளது என்பதைக் காட்டுகிறது. நிறுத்தப்பட்ட model ஐச் சுட்டிக்காட்டினால் bar அது பொருந்துமா, அல்லது எவ்வளவு குறைவாக உள்ளது என்பதைக் காட்டும். பல ஒன்றாக நினைவகத்தில் பொருந்தும்போது ஒரே நேரத்தில் இயங்கலாம்; ஒன்று பொருந்தவில்லை என்றால், எந்த இயங்கும் model ஐ நிறுத்த வேண்டும் என்று Omarchy சொல்கிறது. வரிகளை அவற்றின் logo ஆல் இழுத்து மறுவரிசைப்படுத்தவும், மேலும் ஒரு model ஐயும் அதன் பதிவிறக்கத்தையும் நீக்க தேர்ந்தெடுக்கப்பட்ட வரியில் Delete ஐ அழுத்தவும்.

நீங்கள் அமைக்கும் ஒவ்வொரு model க்கும் app launcher இல் தனி உள்ளீடும் கிடைக்கும், model இன் பெயரில் மற்றும் அதன் தயாரிப்பாளரின் logo உடன், Claude, Codex அல்லது Grok இல் உள்நுழைவது ஒன்றைச் சேர்ப்பது போல. அது அந்த model இல் உங்கள் agent ஐத் திறக்கிறது, மேலும் அது இயங்கவில்லை என்றால் முதலில் model ஐத் தொடங்குகிறது: terminal அது ஏற்றப்படுவதைக் காட்டுகிறது மற்றும் அது தயாரானதும் agent இடம் ஒப்படைக்கிறது. ஒரு model ஐ நீக்குவது அதன் உள்ளீட்டை நீக்குகிறது.

ஒவ்வொரு model உம் coding க்கானது அல்ல. Image, video மற்றும் music modelகள் அதற்குப் பதிலாக Fantasi இல் திறக்கும், இந்த இயந்திரத்தில் இயங்கும் model உடன் படங்கள், video மற்றும் music உருவாக்குவதற்கான Omarchy இன் பயன்பாடு, அவற்றின் launcher உள்ளீட்டிலிருந்தும் உள்ளூர் modelகள் panel இல் அவற்றின் வரியிலிருந்தும்.

ஒரு model அது அமைக்கப்பட்டபடியே சரியாகத் தொடர்ந்து இயங்கும், எனவே Omarchy புதுப்பிப்பு ஒருபோதும் உங்கள் agentகளின் கீழ் ஒன்றை மறுதொடக்கம் செய்யாது. நீங்கள் அமைத்த model க்கு Omarchy இல் புதிய runtime அல்லது புதிய weightகள் இருக்கும்போது, அதன் வரி புதுப்பிப்பு பொத்தானைக் காட்டும்: அதை அழுத்தவும், மேலும் model பின்னணியில் மீண்டும் அமைக்கப்படும், மாறியதை மட்டும் பதிவிறக்கி, புதிய பதிப்பில் மறுதொடக்கம் செய்யும். நிறுத்தப்பட்ட model நிறுத்தப்பட்டே இருக்கும். `omarchy models update` terminal இலிருந்து ஒவ்வொரு model க்கும் அதையே செய்கிறது.

Command line இலிருந்து, `omarchy models start <recipe>` மற்றும் `omarchy models stop <recipe>` அதையே செய்கின்றன, `omarchy models status` ஒவ்வொரு model ஐயும் காட்டுகிறது, மேலும் `omarchy agent --local` நீங்கள் கடைசியாகத் தொடங்கிய model இல் உங்கள் இயல்புநிலை agent ஐத் திறக்கிறது. pi, OpenCode மற்றும் Qwen Code ஒன்றைப் பயன்படுத்தலாம்; வேறு எந்த இயல்புநிலையுடனும் அது pi இல் திறக்கும், அல்லது உங்களிடம் pi இல்லை என்றால் OpenCode இல். pi நீங்கள் அமைத்த ஒவ்வொரு model ஐயும், மேலும் நீங்கள் இணைத்த இயந்திரங்களில் உள்ளவற்றையும், அதன் சொந்த model picker இல் பட்டியலிடுகிறது, எனவே சாதாரண `pi` அவற்றையும் அடையும். எந்த OpenAI-இணக்கமான client உம் இணைக்கலாம்: `status` ஒவ்வொரு model இன் முகவரியையும் காட்டுகிறது (முதலாவது `http://127.0.0.1:11435/v1`), recipe பெயர் model ஆகும், மேலும் key `~/.config/omarchy/agent-local/key` இல் உள்ளது.

`omarchy models remove <recipe>` ஒரு model ஐயும் வேறு எந்த model உம் பயன்படுத்தாத பதிவிறக்கங்களையும் நீக்குகிறது.

மூன்றாம் தரப்பு runtimeகள் அவற்றின் வெளியீட்டாளருடன் குறிக்கப்பட்டுள்ளன. Omarchy ஒவ்வொரு model ஐயும் network அணுகல் இல்லாமல் இயக்குகிறது.

### உள்ளூர் LLMகள்

Omarchy உள்ளூர் LLM modelகளை இயக்க இரண்டு வழிகளைப் பரிந்துரைக்கிறது: LM Studio மற்றும் Ollama. LM Studio திறந்த-எடை modelகளைக் கண்டறிவதற்கும், அவற்றை நிறுவுவதற்கும், அவற்றை இயக்குவதற்கும் GUI interface ஐ வழங்குகிறது. எளிதாகத் தொடங்க இது சிறந்த வழி. Ollama இதையே போலச் செய்ய CLI ஐ வழங்குகிறது. ஆனால் நீங்கள் உள்ளூர் modelகளுக்குப் புதியவர் என்றால், நான் LM Studio உடன் தொடங்குவேன். Omarchy Menu இல் _நிறுவு > AI_ இன் கீழ் ஏதாவது ஒன்றை நிறுவலாம்.

### Omarchy skillகள்

Agent skillகள் AI குறிப்பிட்ட கருவிகளைக் குறிப்பிட்ட வழியில் பயன்படுத்த உதவுகின்றன, மேலும் Omarchy அவற்றில் ஏழை வழங்குகிறது. Omarchy skill உங்கள் Hyprland config ஐ மாற்றுவது அல்லது bar ஐ சரிசெய்வது போல, system ஐத் தனிப்பயனாக்குவதை உள்ளடக்குகிறது. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app, மற்றும் omarchy-make-game புதிதாக ஏதாவது உருவாக்குவதை உள்ளடக்குகின்றன, omarchy-contribute ஒரு bug ஐப் புகாரளிப்பது அல்லது upstream க்கு ஒரு திருத்தத்தை அனுப்புவதை உள்ளடக்குகிறது, மேலும் omarchy-diagnose-crash ஒரு செயலிழப்பின் core dump வழியாக வேலை செய்கிறது. அவை Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` மற்றும் ஒவ்வொரு `~/.hermes/profiles/*/skills`), மற்றும் பொதுவான `~/.agents/skills` இடத்திற்கான skill directoryகளில் symlink செய்யப்பட்டுள்ளன, எனவே பெரும்பாலான harnessகள் அவற்றைத் தானாகவே எடுத்துக்கொள்கின்றன. அதே பெயரில் உங்கள் சொந்த skill folder இருந்தால் அதற்கு முன்னுரிமை கிடைக்கும்.

ஆனால் நீங்கள் இந்த skillகளை சோதனை முயற்சியாகக் கருத வேண்டும். வெவ்வேறு modelகள் அதை வெவ்வேறு விளைவுகளுக்குப் பயன்படுத்தும். முதலில் plan mode இல் இயக்குவது சிறந்தது, எனவே agent எதை மாற்ற விரும்புகிறது என்பது பற்றி உங்களுக்கு ஒரு யோசனை இருக்கும். மேலும் agent எல்லாவற்றையும் குழப்பினால், மாற்றங்களைத் திரும்பப் பெற அல்லது `omarchy reinstall configs` ஐ அழைக்கவும் தயாராக இருங்கள்.
