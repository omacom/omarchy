Omarchy, உங்களுக்கு இயல்புநிலையைத் தேர்ந்தெடுக்காமல், கீழே உள்ள குறியீட்டு முகவர்களுக்கான துவக்கிகளை உள்ளடக்கியுள்ளது. முதல் பயன்பாட்டில் அதன் CLI ஐ நிறுவ ஒரு கட்டளையை இயக்கவும், பின்னர் கேட்கும்போது அங்கீகரிக்கவும். Hermes மற்றும் OpenClaw விதிவிலக்குகள்: அவற்றுக்கு mise வழியாக எதுவும் நிறுவப்படுவதில்லை, மேலும் ஏதேனும் ஒன்றைத் தேர்ந்தெடுப்பது அதன் சொந்த தானாகப் புதுப்பிக்கும் நகலை அமைக்கிறது, கீழே _டெஸ்க்டாப் பயன்பாடுகள்_ விளக்குவது போல.

### முகவர்களை நிறுவுதல் மற்றும் புதுப்பித்தல்

Hermes மற்றும் OpenClaw தவிர, இந்த முகவர்கள் mise இன் lazy நிறுவலைப் பயன்படுத்துகிறார்கள்: முதல் துவக்கம் CLI ஐ நிறுவுகிறது, பின்னர் துவக்கங்கள் அதை மீண்டும் பயன்படுத்துகின்றன. நிறுவப்பட்ட முகவருக்கு புதிய வெளியீடு உள்ளதா என mise நான்கு மணி நேரத்திற்கு ஒரு முறைக்கு மேல் சரிபார்ப்பதில்லை, அது தொடங்குவதற்கு சற்று முன்பு அல்லது shell prompt இல் பின்னணியில். அந்தப் புதுப்பிப்பு தோல்வியடைந்தால் அல்லது நீங்கள் ஆஃப்லைனில் இருந்தால், நிறுவப்பட்ட பதிப்பு இயங்கும். `omarchy update` நிறுவப்பட்ட முகவர்களை Omarchy இன் மற்ற பகுதிகளுடன் புதுப்பிக்கிறது, மற்றும் `mup` mise ஆல் நிர்வகிக்கப்படும் கருவிகளை மட்டும் புதுப்பிக்கிறது.

ஒரு முகவரின் சொந்தப் புதுப்பிப்பான், எடுத்துக்காட்டாக `claude update`, `codex update`, அல்லது ஒரு பயன்பாட்டில் உள்ள புதுப்பிப்புப் பொத்தான், mise ஆல் நிர்வகிக்கப்படும் நிறுவலைப் புதுப்பிக்காது. `codex update` தோல்வியடைகிறது, மற்றும் `claude update` வெற்றி என அறிவிக்கலாம், ஆனால் mise கண்காணிக்காத தனியான நகலை நிறுவும். நீங்கள் ஒரு முகவரின் சொந்த நிறுவி மற்றும் புதுப்பிப்பானைப் பயன்படுத்த விரும்பினால், அதை `disable_tools` இல் சேர்க்கவும்; [முன்னிறுவப்பட்ட CLI கருவிகள்](18-development-tools.md#preinstalled-cli-tools) ஐப் பார்க்கவும்.

உள்ளமைக்கப்பட்ட அனைத்து lazy கருவிகளையும் உங்களுக்குத் தேவைப்படுவதற்கு முன்பே நிறுவ, `mise install --include-lazy` ஐ இயக்கவும். இதில் முகவர்களுடன் Omarchy இன் மற்ற இயல்புநிலை CLI கருவிகளும் அடங்கும். ஒரு கருவியை நிறுவ அல்லது உங்கள் சொந்த நிறுவலைப் பயன்படுத்த [முன்னிறுவப்பட்ட CLI கருவிகள்](18-development-tools.md#preinstalled-cli-tools) ஐப் பார்க்கவும்.

`grok` என்பது mise இன் first-party `grok` தொகுப்பு வழியாக நிறுவப்படுகிறது, `claude` மற்றும் `codex` போலவே. `grok` ஐ இயக்கவும், அல்லது முகவர்கள் பலகத்தில் அதை நட்சத்திரமிடவும். x.ai இல் உள்ள `curl | bash` நிறுவியைத் தவிர்க்கவும். அந்த வழி `~/.grok/bin` இல் இரண்டாவது நகலை வைக்கிறது, அதை `PATH` இல் முன்னால் சேர்க்கிறது, மற்றும் Omarchy இன் wrapper ஐ மேலெழுதுகிறது.

`dsh` அதன் உலாவி UI ஐ `127.0.0.1:3080` இல் திறக்கிறது, துவக்க கோப்பகத்தை அதன் இயல்புநிலை பணியிடமாகக் கொண்டு. அதன் உலாவி UI தொடக்க prompt ஐ ஏற்காது, எனவே `omarchy agent prompt` அதை paste செய்வதற்காக prompt உங்கள் clipboard இல் இருக்கும்படி திறக்கிறது. Omarchy அதை DeepSeek இன் no-approval அனுமதி preset உடன் தொடங்குகிறது. நீங்கள் அதன் அதிகாரப்பூர்வ model API ஐப் பயன்படுத்தும்போது DeepSeek Harness அமர்வு பதிவுகளை DeepSeek க்கு பதிவேற்றுகிறது; அதன் உலாவி UI இல் _Settings > General > Upload Session Log_ கீழ் அதை முடக்கவும். நீங்கள் அதற்கு அனுப்பும் கருத்தும் அமர்வுடன் சேர்த்து பதிவேற்றப்படும், நீங்கள் அதை `DSH_TELEMETRY_MODE=DISABLED` உடன் தொடங்காவிட்டால்.

### இயல்புநிலை முகவர்

முகவர்கள் பலகத்தில் ஒரு முகவருக்கு அருகில் உள்ள நட்சத்திரத்தைக் கொண்டு உங்கள் இயல்புநிலை முகவரைத் தேர்ந்தெடுக்கவும், அது இயல்புநிலையில் நிரப்பப்பட்டிருக்கும், அல்லது `omarchy default agent <name>` உடன், இது அங்கு வரிசை இல்லாத எந்த harness ஐயும் ஏற்கும். முகவர் இன்னும் நிறுவப்படவில்லை என்றால், அதைத் தேர்ந்தெடுப்பது முதலில் அதை நிறுவும், மேலும் அதற்கு Agent க்கு அடுத்து பயன்பாட்டு துவக்கியில் அதற்கே உரிய துவக்கியும் கிடைக்கும். புதிய Omarchy ஒரு முறை மட்டும் வரும் அறிவிப்புடன் ஒன்றை அமைக்க உங்களை அழைக்கிறது, அது முகவர்கள் பலகத்தைத் திறக்கும்.

Claude ஐத் தேர்ந்தெடுப்பது Chromium, Chrome, Brave, Brave Origin, மற்றும் Edge க்கான அதன் உலாவி நீட்டிப்பை அமைக்கவும் முயற்சிக்கிறது. நீட்டிப்பு அமைப்பு அனைத்து பயனர்களுக்கும் பொருந்தும் மற்றும் உங்கள் system password ஐக் கேட்கலாம்; ரத்து செய்தல் அல்லது தோல்வியடைந்த நீட்டிப்பு நிறுவல் இருந்தாலும் Claude தேர்ந்தெடுக்கப்பட்டு துவக்கப்படும். உங்கள் உலாவியை மறுதொடக்கம் செய்யவும், கேட்கும்போது நீட்டிப்பை இயக்கவும், மற்றும் அதை இணைப்பதை முடிக்க Claude இல் உள்நுழையவும். இணைப்பைச் சரிபார்க்க Claude இல் `/chrome` ஐ இயக்கவும். Firefox மற்றும் Zen இந்த நீட்டிப்பை ஆதரிக்காது. இந்த அமைப்பு சேர்க்கப்படுவதற்கு முன்பே Claude உங்கள் இயல்புநிலையாக இருந்தால், நீட்டிப்பை நிறுவ அதை மீண்டும் தேர்ந்தெடுக்கவும்.

நீங்கள் தேர்ந்தெடுத்த பிறகு, `Super + Shift + Ctrl + A` இயல்புநிலை முகவரை பிரத்யேக terminal சாளரத்தில் துவக்கும் (அல்லது நீங்கள் இன்னும் தேர்ந்தெடுக்கவில்லை என்றால் picker ஐக் கொண்டுவரும்). நீங்கள் அதை நேரடியாக ஒரு பணியில் `omarchy agent prompt "Review this project"` உடன் துவக்கவும் முடியும். Freebuff மற்றும் DeepSeek Harness தொடக்க prompt ஐ ஏற்காது, எனவே அவை அதற்கு பதிலாக paste செய்வதற்காக prompt உங்கள் clipboard இல் இருக்கும்படி திறக்கும். இப்படி துவக்கப்படும் முகவர்கள் அந்தந்த don't-stop-to-ask முறைகளில் கவனிக்கப்படாமல் இயங்கும், எனவே அவை உண்மையில் விஷயங்களைச் செய்யத் தயாராக இருங்கள்! MiniMax Code க்கு அதன் ஊடாடும் அமர்வுகளுக்கு அத்தகைய முறை இல்லை, எனவே அது வழக்கம் போல் அனுமதிகளைக் கேட்கும். மேலும் முகவர்கள் உங்கள் home கோப்பகத்திற்கான trust ஐ நினைவில் வைக்க மறுப்பதால், `$HOME` இலிருந்து துவக்கங்கள் அதற்கு பதிலாக `~/Work` இல் தொடங்கும்.

terminal குறுக்குவழிகளும் உள்ளன: `a` தற்போதைய terminal இல் இயல்புநிலை முகவரை inline ஆக இயக்குகிறது, அதே நேரத்தில் `c`, `cx`, மற்றும் `cy` OpenCode, Claude Code, மற்றும் Codex ஐ நேரடியாகத் தொடங்குகின்றன (மீண்டும் அவற்றின் auto-approving முறைகளில்). Theme மாற்றங்கள் முகவர்களுக்கும் ஒத்திசைகின்றன: Claude Code, Pi, OpenCode, மற்றும் Hermes (Omarchy அதை நிறுவிய பிறகு) அனைத்தும் நீங்கள் Omarchy theme ஐ மாற்றும்போது பின்தொடரும்.

### உங்கள் முகவர் வழிமுறைகள்

ஒவ்வொரு முகவருக்கான தனிப்பட்ட விதிகள் `~/.agents/AGENTS.md` இல் செல்கின்றன, `~/.agents/skills` இல் உள்ள பகிரப்பட்ட skills க்கு அடுத்து. முகவர்கள் பலகத்தில் + க்கு அருகில் உள்ள document ஐகானுடன் அதைத் திறக்கவும், அல்லது `omarchy agent instructions --edit` உடன், இது தனது சொந்த global கோப்பை வைத்திருக்கும் ஒவ்வொரு harness இலும் அதை இணைக்கிறது: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, Copilot இன் `~/.copilot/copilot-instructions.md`, மற்றும் பல. Crush மற்றும் Amp `~/.config/AGENTS.md` இணைப்பைப் படிக்கின்றன, அதே நேரத்தில் omp, Kimi, மற்றும் DeepSeek Harness `~/.agents/AGENTS.md` ஐ நேரடியாகப் படிக்கின்றன. இயல்புநிலை முகவரைத் தேர்ந்தெடுப்பதும் அதை இணைக்கிறது. உங்களிடம் ஏற்கனவே இருந்த வழிமுறைகள் கோப்பு, இன்னும் ஒன்று இல்லை என்றால் பகிரப்பட்ட ஒன்றாக மாறும்; இல்லையெனில் அது இணைப்புக்கு அருகில் `.bak` ஆக வைக்கப்படும். மற்றொரு முகவரை நிறுவிய பிறகு மீண்டும் இணைக்க `omarchy agent instructions` ஐ இயக்கவும்.

### முகவர்கள் பலகம்

மேல் பட்டியில் முகவர்கள் ஐகான் உள்ளது. நீங்கள் ஒரு முகவரை அமைக்கும் முன், அதன் பலகம் தொடங்க மூன்று வழிகளை வழங்குகிறது: Claude, Codex, Grok, Gemini, Muse, Cursor, அல்லது Copilot சந்தாவில் உள்நுழையவும், அல்லது More கீழ் OpenCode Go, MiniMax, Synthetic, அல்லது Z.ai coding plan; Fireworks, OpenCode Zen and Go, OpenRouter உடன் pay as you go செய்யவும், அல்லது More கீழ் DeepSeek அல்லது OpenCode உள்நுழையும் வேறு எந்த provider உடனும், அனைத்தும் OpenCode இல் இயங்கும்; அல்லது உங்கள் கணினிக்குப் பொருந்தும் போது, அதற்கான சிறந்த மாதிரியை இயக்கவும். நீங்கள் முதலில் முடிப்பது உங்கள் இயல்புநிலை முகவராக மாறும், மற்றும் பலகத்தில் உள்ள + பின்னர் அதே மூன்றையும் வழங்குகிறது. அதன் பிறகு, பலகம் ஒவ்வொரு சந்தாவையும் ஒரு பக்கத்தில் வைக்கிறது: ஒவ்வொரு முகவர் மற்றும் கணக்கு அதன் plan உடன், அதன் 5 மணி நேர அமர்வு மற்றும் வாராந்திர வரம்புகள் ஒவ்வொன்றுக்கும் ஒரு meter உடன் அது மீட்டமைக்கும் வரை உள்ள நேரத்துடன் (சரியான சதவீதத்திற்கு hover செய்யவும்), அல்லது மீதமுள்ள prepaid balance, அவை அனைத்திலும் நீங்கள் பயன்படுத்தியதைச் சுழற்றும் ஒரு வரியின் கீழ், இந்த வாரம் tokens மற்றும் நீங்கள் அதிகம் பயன்படுத்திய மாதிரி போன்றவை. _Make something cool_ கீழ் அது புதிய theme, plugin, app, அல்லது game க்கான starter prompt களை வழங்குகிறது, அவை பணியை உங்கள் இயல்புநிலை முகவரிடம் ஒப்படைக்கும். Apps Omarchy இன் சொந்த Hype, Monologue, மற்றும் Omacut போலவே, C++ மற்றும் Qt Quick இல், omarchy-make-app agent skill ஐப் பின்பற்றி கட்டமைக்கப்படுகின்றன, மற்றும் அவற்றுக்குத் தேவையான compiler மற்றும் Qt பகுதிகள் நிறுவப்பட்டு வருகின்றன. Games `~/Games/vibes` இல் ஒரே three.js பக்கமாக, omarchy-make-game agent skill ஐப் பின்பற்றி, மற்றும் அனைத்தும் தற்போதைய theme இல் ஒரு Game Vibes துவக்கியிலிருந்து திறக்கும்; அவை three.js ஐ web இலிருந்து ஏற்றுகின்றன, எனவே தொடங்க அவற்றுக்கு இணைப்பு தேவை. Claude Code, Codex, Grok, Kimi, Cursor மற்றும் அதன் Grok Bot allowance, GitHub Copilot, Muse, Gemini (Antigravity வழியாக), மற்றும் Devin அவற்றின் வரம்புகளுடன் out of the box உள்ளடக்கப்பட்டுள்ளன, Kimchi அதன் plan, prepaid credits, மற்றும் spend budgets உடன், மற்றும் Hermes, Mistral Vibe, மற்றும் Qwen Code நீங்கள் அவற்றைப் பயன்படுத்திய பிறகு அவற்றின் அமர்வுகள் மற்றும் tokens ஐக் காட்டுகின்றன. pi, omp, அல்லது opencode வழியாக நீங்கள் பயன்படுத்தும் Provider plans மற்றும் keys உம் தோன்றும்: OpenCode Zen and Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan, மற்றும் Synthetic அவற்றின் வரம்புகளுடன்; OpenRouter மற்றும் DeepSeek அவற்றின் prepaid balances உடன்; Fireworks கடந்த 30 நாட்களில் அதன் spend உடன். நீங்கள் உங்கள் சொந்த hardware இல் இயக்கும் மாதிரிகளிலிருந்து tokens உம் மொத்தங்களில் கணக்கிடப்படும்; மாதிரிகளுக்கு தனி பலகம் உள்ளது, [உள்ளூர் மாதிரிகள்](#local-models) கீழ் விவரிக்கப்பட்டுள்ளது. ஒவ்வொரு முகவரும் ஒரு முறை மட்டுமே கணக்கிடப்படும், அதற்கு யார் bill செய்கிறார்களோ அவர்களின் கீழ், நீங்கள் எத்தனை harness கள் வழியாக அதை இயக்கினாலும்.

பலகத்திற்கு bar ஐகானை இடது-கிளிக் செய்யவும் அல்லது `Super + Ctrl + X` ஐ அழுத்தவும், உங்கள் இயல்புநிலை முகவரைத் துவக்க வலது-கிளிக் செய்யவும், மற்றும் புதுப்பிக்க நடு-கிளிக் செய்யவும். அதன் பின்னால் உள்ள பயன்பாட்டு பதிவுகள் ஒவ்வொரு 15 நிமிடங்களுக்கும் `omarchy agent usage update` ஆல் மீண்டும் உருவாக்கப்படுகின்றன, மற்றும் பலகம் ஒத்திசைக்கப்பட்ட folder வழியாக உங்கள் மற்ற இயந்திரங்களிலிருந்து பயன்பாட்டை இணைக்கவும் முடியும். முழு அமைப்புகளுக்கு `$OMARCHY_PATH/shell/plugins/agents/` கீழ் உள்ள README ஐப் பார்க்கவும்.

### பல சந்தாக்கள்

நீங்கள் ஒன்றுக்கு மேற்பட்ட Claude, Codex, அல்லது Grok plan க்கு பணம் செலுத்தினால் — எடுத்துக்காட்டாக தனிப்பட்ட Max மற்றும் வேலை ஒன்று — Omarchy அவை அனைத்தையும் உள்நுழைந்த நிலையில் வைத்து அவற்றுக்கிடையே நகர முடியும். முகவர்கள் பலகத்தில் + உடன் சந்தாவைச் சேர்க்கவும், அது உங்களை அங்கேயே வழிநடத்தும், அல்லது `omarchy agent account add claude Work` உடன் (அல்லது `codex`, அல்லது `grok`). அதே + மற்றும் கட்டளை Gemini (`gemini`) மற்றும் OpenCode (`opencode`) இல் உள்நுழையும், மற்றும் OpenCode இல் Fireworks (`fireworks`) அல்லது OpenRouter (`openrouter`) API key ஐ சேமிக்கும்; கட்டளை Copilot (`copilot`), Cursor (`cursor`), மற்றும் Muse (`muse`) இலும் உள்நுழையும். அவை ஒவ்வொன்றும் ஒரே உள்நுழைவை வைத்திருக்கும். அது CLI காணவில்லை என்றால் அதை நிறுவும். ஒரு provider க்கான முதல் கணக்கு உங்கள் சாதாரண உலாவி வழியாக உள்நுழையும், CLI எப்போதும் பார்க்கும் இடத்திலேயே. அதற்குப் பிறகு ஒவ்வொன்றும் private சாளரம் வழியாக உள்நுழையும், எனவே உங்கள் உலாவி ஏற்கனவே உள்நுழைந்துள்ள கணக்கு தவறுதலாக எடுக்கப்படாது; நீங்கள் சேர்க்கும் கணக்காக அங்கு உள்நுழையவும், மற்றும் ஏற்கனவே திறந்திருந்த எந்த private சாளரத்தையும் முதலில் மூடவும். இதைச் செய்ய ஒருபோதும் CLI இலிருந்து வெளியேற வேண்டாம்: வெளியேறுவது சேமிக்கப்பட்ட உள்நுழைவை ரத்து செய்யும், மற்றும் அந்தக் கணக்கு மீண்டும் சேர்க்கப்பட வேண்டும்.

உங்கள் சந்தா உள்நுழைவுகளை SSH வழியாக மற்றொரு Omarchy இயந்திரத்திற்கு நகலெடுக்க, `omarchy agent account copy user@laptop` ஐ இயக்கவும். இலக்கில் ஒன்று நிறுவப்படவில்லை என்றால் அனுப்புநர் தற்காலிக receiver ஐ வழங்குகிறது, எனவே பழைய Omarchy இயந்திரங்கள் புதுப்பிப்பு இல்லாமல் கணக்குகளைப் பெற முடியும். நிறுவப்பட்ட receiver கள் முன்னுரிமை பெறும். இது அனைத்து Claude, Codex, மற்றும் Grok சந்தாக்களையும் நகலெடுக்கிறது; அவற்றைத் தேர்ந்தெடுக்க provider பெயர்களைச் சேர்க்கவும், `omarchy agent account copy laptop claude` இல் போல. கணக்குப் பெயர்கள் மற்றும் கட்டளை ID கள் மூலத்துடன் பொருந்தும், இலக்கில் ஏற்கனவே உள்ள கணக்குகள் உட்பட. தொடர்பில்லாத இலக்கு கணக்குகள் அவற்றின் பெயர்கள் முரண்பட்டால் எண் பின்னொட்டைப் பெறும், மற்றும் அமைப்புகள், skills, plugins, மற்றும் உரையாடல் வரலாறு ஒவ்வொரு இயந்திரத்திற்கும் உள்ளூராக இருக்கும்.

ஏற்கனவே உள்ள இலக்கு credentials வைக்கப்படும். அங்கு ஏற்கனவே உள்நுழைந்த மூலக் கணக்கு அதன் credentials ஐ மாற்றாமல் அதன் பெயர் ஒத்திசைக்கப்படும்; மற்ற கணக்குகள் அதற்கு அருகில் சேர்க்கப்படும். பொருந்தும் கணக்குகளுக்கு சேமிக்கப்பட்ட credentials ஐ மாற்ற, இலக்கில் அந்தக் கணக்கின் அமர்வுகளை விட்டு வெளியேறிய பிறகு `omarchy agent account copy --replace laptop claude` ஐப் பயன்படுத்தவும். ஒரு புதிய இலக்கு மூலத்தின் active கணக்கு மற்றும் switching விருப்பங்களையும் பெறும்; ஒரு நிறுவப்பட்ட இலக்கு தனதை வைத்திருக்கும்.

Credentials SSH வழியாக பயணித்து இலக்கில் private கோப்புகளில் சேமிக்கப்படுகின்றன, எனவே நீங்கள் நம்பும் இயந்திரங்களுக்கு மட்டும் நகலெடுக்கவும். இது ஒரு முறை நகல், தொடர்ந்த ஒத்திசைவு அல்ல. Codex refresh tokens மற்றொரு இயந்திரத்தால் சுழற்றப்படலாம், ஒரு நகலெடுக்கப்பட்ட உள்நுழைவுக்கு புதுப்பிப்பு தேவைப்படும் நிலையை விட்டு; பல இயந்திரங்களில் ஒரே நேரத்தில் பயன்படுத்த தனி உள்நுழைவுகள் மிகவும் நம்பகமான தேர்வாக இருக்கும். [Codex இன் கணக்கு அங்கீகார வழிகாட்டல்](https://developers.openai.com/codex/auth/ci-cd-auth) ஐப் பார்க்கவும்.

provider க்கு ஒரு கணக்கு active ஆக இருக்கும், மற்றும் ஒவ்வொரு புதிய அமர்வும் அதுவாகத் தொடங்கும்: `cx`, `cy`, ஒரு plain `claude`, `codex`, அல்லது `grok`, `omarchy agent` வழியாக துவக்கப்படும் எதுவும், மற்றும் `PATH` இல் CLI ஐக் கண்டறியும் scripts அல்லது editors. `omarchy agent account use work` உடன் மாற்றவும் (மற்றும் `omarchy agent account use main` உடன் திரும்பவும்), அல்லது பலகத்தில் கணக்கின் எண்ணை அழுத்தி பின்னர் `Enter` (அல்லது அதன் நட்சத்திரத்தைக் கிளிக் செய்து). இயங்கும் Claude அமர்வுகளும் மாறும், அவற்றின் அடுத்த செய்தியிலிருந்து: ஒவ்வொரு Claude அமர்வும் `~/.claude` இல் இயங்கும், இது எப்போதும் active கணக்கின் உள்நுழைவை வைத்திருக்கும். ஒரு கணக்கின் சொந்த folder இல் பழைய Omarchy ஆல் தொடங்கப்பட்ட Claude அமர்வு அது வெளியேறும் வரை அந்த உள்நுழைவை வைத்திருக்கும், எனவே switch அந்த அமர்வுகளைப் பெயரிட்டு அவை போன பிறகு தானாகவே முடிகிறது. இயங்கும் Codex மற்றும் Grok அமர்வுகள் அவை தொடங்கிய கணக்கிலேயே இருக்கும். உரையாடல் வரலாறு, அமைப்புகள், skills, மற்றும் plugins கணக்குகள் முழுவதும் பகிரப்படும், எனவே அதே folder இல் `claude --continue` நீங்கள் புதிய கணக்கில் விட்ட இடத்திலிருந்து தொடரும்.

ஒன்றுக்கு மேற்பட்ட கணக்குடன், பலகம் ஒவ்வொரு கணக்கின் வரம்புகளையும் அருகருகே காட்டுகிறது, பயன்பாட்டில் உள்ளதில் நிரப்பப்பட்ட நட்சத்திரத்துடன். active கணக்கு வரம்பின் 95% ஐக் கடக்கும்போது Omarchy உங்களுக்கு அறிவிக்கிறது, மற்றும் அறிவிப்பைக் கிளிக் செய்வது அதிக headroom உள்ள கணக்கிற்கு மாற்றும். அது தானாக ஒருபோதும் மாற்றாது. `omarchy agent account threshold 90` உடன் threshold ஐ மாற்றவும். ஒவ்வொரு கணக்கும் threshold க்கு மேல் இருந்தால், எந்தக் கணக்கு முதலில் விடுபடுகிறது என்பதுடன் ஒரு முறை நீங்கள் கேட்பீர்கள். ஒரு active கணக்கு அதன் threshold இலிருந்து 15 புள்ளிகளுக்குள் இருக்கும்போது (இயல்புநிலையில் 80%), அதன் வரம்புகள் ஒவ்வொரு 15 க்கு பதிலாக ஒவ்வொரு மூன்று நிமிடங்களுக்கும் சரிபார்க்கப்படும்.

`omarchy agent account list` ஒவ்வொரு கணக்கையும் அதன் சமீபத்திய வரம்புகளையும் காட்டுகிறது, `omarchy agent account remove work` ஒன்றை மறக்கிறது, மற்றும் `omarchy agent account rename primary Hey` ஒன்றை மறுபெயரிடுகிறது (அல்லது பலகத்தில் ஒரு கணக்கின் பெயரைக் கிளிக் செய்யவும்). இந்தக் கட்டளைகள் உங்கள் இயல்புநிலை முகவரின் கணக்குகளில் செயல்படும்; மற்ற provider ஐ அடைய, முதலில் அதைப் பெயரிடவும், `omarchy agent account use codex side` இல் போல. `~/.claude` அல்லது `~/.codex` இல் நீங்கள் ஏற்கனவே வைத்திருந்த உள்நுழைவு _Main_ கணக்கு. Codex இன் அது இருக்கும் இடத்திலேயே இருக்கும்; மற்றொரு கணக்கு active ஆக இருக்கும்போது Claude இன் அது தனது சொந்த folder இல் காத்திருக்கும். சுமார் எட்டு மணி நேரத்திற்கு மேல் பயன்படுத்தப்படாத கணக்கு _Sign-in required_ எனக் காட்டலாம்; அந்தக் கணக்கை பலகத்திலேயே மீண்டும் உள்நுழைய அதைக் கிளிக் செய்யவும், அல்லது அதற்கு மாறி ஒரு அமர்வைத் தொடங்கவும், இது உள்நுழைவைத் தானாகப் புதுப்பிக்கும். நீங்கள் `claude mcp add` உடன் சேர்க்கும் MCP servers ஒவ்வொரு Claude கணக்கையும் அடையும், ஏனெனில் அவை அனைத்தும் `~/.claude` இல் இயங்கும்; Codex மற்றும் Grok க்கு, ஒரு கணக்கு சேர்க்கப்பட்டபோது உங்களிடம் இருந்த servers அதற்கு வரும், ஆனால் பின்னர் உள்ளவை நீங்கள் அவற்றைச் சேர்த்த கணக்கை மட்டுமே அடையும். Claude Desktop தனது சொந்த உள்நுழைவை வைத்திருக்கும், மற்றும் CLI binary க்கு absolute path உடன் உள்ளமைக்கப்பட்ட Codex அல்லது Grok கருவிகள் switch ஐப் பின்பற்றாது. வெளிப்படையான `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, அல்லது `GROK_HOME` தேர்ந்தெடுக்கப்பட்ட கணக்கை விட முன்னுரிமை பெறும்.

### செயலிழப்பு கண்டறிதல்

Omarchy செயல்முறை செயலிழப்புகளுக்கு systemd-coredump ஐக் கண்காணிக்கிறது. நீங்கள் இயல்புநிலை முகவரைத் தேர்ந்தெடுத்த பிறகு, core dump செய்யும் உங்கள் எந்த நிரலும் "Process crashed" அறிவிப்பைக் கொண்டுவரும் — அதைக் கிளிக் செய்யவும், மற்றும் செயலிழப்பு உங்கள் இயல்புநிலை முகவரிடம் Omarchy இன் omarchy-diagnose-crash skill உடன் ஒப்படைக்கப்படும், இது core dump இலிருந்து உண்மைகளை நிறுவி செயலிழப்பு upstream இல் புகாரளிக்கத் தகுந்ததா என முடிவு செய்வதன் மூலம் முகவரை வழிநடத்துகிறது. நீங்கள் அதை `coredumpctl list` இலிருந்து எந்த PID க்கும் எதிராக கையால் `omarchy agent crash <pid>` உடன் இயக்கவும் முடியும்.

கண்காணிப்பு இயல்பாகவே இயக்கத்தில் உள்ளது. _Trigger > Toggle > Crash Capture Off_ கீழ் (அல்லது `omarchy toggle crash-capture` உடன்) அதை முடக்கவும் மற்றும் அறிவிப்புகள் நிற்கும்; `omarchy agent crash <pid>` இன்னும் கையால் செயல்படும்.

செயலிழப்புகளை ஒரு நேரத்தில் ஒரு நிரல் வீதம் அமைதிப்படுத்தவும் முடியும், இது கண்டறிதல் இறுதியில் உங்களுக்கு வழங்குவது. `omarchy crash mute hyprland` அந்த நிரலுக்கு மட்டும் அறிவிப்புகளை நிறுத்துகிறது, `omarchy crash mute hyprland off` அவற்றைத் திரும்பக் கொண்டுவருகிறது, மற்றும் `omarchy crash mute` தனியாக நீங்கள் muted செய்ததைப் பட்டியலிடுகிறது. அது binary இன் path ஐ அதன் பெயரைப் போலவே மகிழ்ச்சியுடன் ஏற்கிறது, எனவே `omarchy crash mute /usr/bin/hyprland` அதே வேலையைச் செய்கிறது. இடைவெளி உள்ள பெயரை மேற்கோள் காட்டவும், `omarchy crash mute 'Some App'` இல் போல. மற்ற அனைத்தும் இன்னும் அறிவிக்கும், மற்றும் muted நிரல் இன்னும் செயலிழக்கும் — இது நினைவூட்டலை மறைக்கிறது, இது எதையும் சரிசெய்யாது.

### டெஸ்க்டாப் பயன்பாடுகள்

_Install > AI_ menu சில graphical AI பயன்பாடுகளையும் கொண்டுள்ளது: Amp Desktop, Antigravity Desktop, ChatGPT desktop app, Claude desktop app (Anthropic இன் Linux beta, Chat, Cowork, மற்றும் Claude Code tabs உடன்), xAI இன் மாதிரிகளுடன் உரையாட Grok Bot, Herdr Desktop, Hermes Desktop, OpenClaw, Perplexity desktop app, மற்றும் T3 Code. Grok Bot என்பது desktop chat பயன்பாடு. குறியீட்டு முகவர் என்பது `grok` கட்டளை.

Hermes Desktop தெரிந்து கொள்ள வேண்டிய ஒன்று, ஏனெனில் ஒரு இயந்திரத்தில் ஒரு Hermes உள்ளது, மற்றும் அது பயன்பாட்டினுடையது: Hermes எப்போதும் பயன்பாடு வழியாக மட்டுமே நிறுவப்படும், மற்றும் இயல்புநிலை முகவர் இயக்கும் `hermes` கட்டளை பயன்பாட்டினுடையது. Hermes ஐ இயல்புநிலை முகவராகத் தேர்ந்தெடுப்பது _Install > AI_ உள்ளீடு செய்வதையே நிறுவுகிறது: தொகுப்பு, மற்றும் Hermes இன் சொந்த நிறுவியால் அமைக்கப்பட்ட `~/.hermes` கீழ் ஒரு Hermes runtime, இது முதல் முறை சில நிமிடங்கள் எடுக்கும். அந்த runtime தான் terminal `hermes` கட்டளை, இயல்புநிலை முகவர் மற்றும் பயன்பாடு அனைத்தும் பயன்படுத்தும் ஒரே Hermes, மற்றும் அது Omarchy வெளியீட்டிற்காக காத்திருக்காமல் `hermes update` உடன் தானாகவே புதுப்பிக்கிறது. அதை நிறுவுவது Hermes க்கு Omarchy theme ஐ `omarchy` என்ற பெயரில் skin ஆகவும் வழங்குகிறது, இதை ஒவ்வொரு Hermes மேற்பரப்பும் நீங்கள் theme களை மாற்றும்போது பின்பற்றும்; நீங்கள் அது வேண்டாம் என்றால் Hermes இன் Appearance அமைப்புகளில் அல்லது `/skin` உடன் மற்றொன்றைத் தேர்ந்தெடுக்கவும், மற்றும் Omarchy அந்தத் தேர்வை தனியாக விட்டுவிடும். _Remove > AI_ கீழ் பயன்பாட்டை அகற்றுவது முதலில் Hermes ஐ மூடும், gateway உட்பட, அந்த runtime ஐ அதனுடன் எடுத்துச் செல்லும், மற்றும் உங்கள் chats, memories, மற்றும் Hermes தனக்காக எழுதிய skills ஐ வைத்திருக்கும், நீங்கள் வேறுவிதமாகச் சொல்லாவிட்டால்: அந்தத் தரவும் உங்கள் இணைப்பு அமைப்புகளும் செல்ல வேண்டுமா என அது கேட்கும், இயல்புநிலை இல்லை என்பது.

OpenClaw இன் desktop அனுபவம் அதன் Control UI, இது அதன் சொந்த உள்ளூர் gateway ஆல் ஆதரிக்கப்படும் web பயன்பாடாகத் திறக்கும். OpenClaw `~/.openclaw` இல் வாழ்கிறது மற்றும் தானாகவே புதுப்பிக்கிறது: Control UI இன் "Update Gateway" பொத்தானைப் பயன்படுத்தவும் அல்லது `openclaw update` ஐ இயக்கவும், மற்றும் gateway புதிய பதிப்பில் மறுதொடக்கம் செய்யும். Omarchy புதிய நிறுவல் தொடங்கும் வெளியீட்டை மட்டுமே தேர்ந்தெடுக்கிறது. OpenClaw உங்கள் இயல்புநிலை முகவராகவும் இருக்கலாம்: `omarchy default agent openclaw` உடன் அதைத் தேர்ந்தெடுப்பது `~/.openclaw` இல் அதே நகலை அமைக்கிறது, மற்றும் முகவர் OpenClaw இன் terminal UI ஐ அதன் gateway உடன் இணைத்து திறக்கிறது. _Remove > AI_ கீழ் OpenClaw ஐ அகற்றுவது gateway service மற்றும் பயன்பாட்டை அதனுடன் எடுத்துச் செல்லும், பின்னர் `~/.openclaw` உம் செல்ல வேண்டுமா எனக் கேட்கும், ஏனெனில் அது OpenClaw தானே மற்றும் அது பதிவிறக்கும் plugin runtime களுடன் உங்கள் chats மற்றும் credentials ஐ வைத்திருக்கிறது; இயல்புநிலை அதை வைத்திருக்கும், மற்றும் OpenClaw ஐ மீண்டும் நிறுவுவது அதை மீண்டும் எடுக்கும்.

Herdr Desktop என்பது [Herdr](https://herdr.dev) desktop பயன்பாடு: நீங்கள் சாளரத்தை மூடும்போது அதன் core இல் தொடர்ந்து இயங்கும் terminals மற்றும் coding agents இன் spaces, tabs, மற்றும் panes. இது ஒரு தொகுப்பிலிருந்து அல்லாமல் Herdr இன் சொந்த நிறுவியிலிருந்து வருகிறது, எனவே அது `~/.local/share/herdr-app` இல் வாழ்கிறது, உங்களிடம் இன்னும் ஒன்று இல்லை என்றால் `~/.local/bin/herdr-core` இல் அதன் core ஐக் கொண்டுவருகிறது, மற்றும் இரண்டையும் தானாகவே புதுப்பிக்கிறது. இது Omarchy `Super + Ctrl + Return` இல் வழங்கும் `herdr` கட்டளைக்கு அருகில் அமர்ந்துள்ளது, அதை மாற்றாமல், மற்றும் அந்தக் கட்டளையின் direct keys ஐப் பெறுகிறது: `Alt + Return` மற்றும் `Alt + Shift + Return` ஒரு pane ஐ கீழே அல்லது வலமாகப் பிரிக்கிறது, `Alt + Escape` அதை மூடுகிறது, `Ctrl + Alt + Arrow` panes இடையே நகர்கிறது, `Alt + 1..9` மற்றும் `Alt + Left/Right` ஒரு tab ஐத் தேர்ந்தெடுக்கிறது, மற்றும் `Alt + Up/Down` spaces இடையே நகர்கிறது. `Ctrl + 1..9` ஒரு space ஐத் தேர்ந்தெடுக்கிறது மற்றும் `Alt + Shift + Up/Down` agents வழியாகச் செல்கிறது. `Ctrl + Space` prefix keys terminal-மட்டுமாக இருக்கும், ஏனெனில் பயன்பாடு ஒரு sequence க்கு plain Ctrl key ஐ வைத்திருக்க முடியாது. Omarchy இவற்றை `~/.config/herdr-app/keys.json` இல் எழுதுகிறது, மற்றும் `omarchy-refresh-herdr-app` அவற்றைத் திரும்ப வைக்கிறது. அதை நிறுவுவது Herdr இன் Omarchy theme ஐத் தேர்ந்தெடுக்கிறது, இது அதிலிருந்து உங்கள் Omarchy theme ஐப் பின்பற்றும். Herdr light mode க்கு ஒரு theme மற்றும் dark mode க்கு ஒன்றை வைத்திருக்கிறது, எனவே dark மற்றும் light Omarchy theme இடையே மாறிய பிறகு, மற்ற mode க்கு Herdr இன் theme picker இல் Omarchy ஐ மீண்டும் தேர்ந்தெடுக்கவும்.

T3 Code அதன் அதிகாரப்பூர்வ AppImage வெளியீட்டிலிருந்து ஒரு தொகுப்பிலிருந்து அல்லாமல் `~/.local/share/t3code` இல் இயங்குகிறது, எனவே அது தானாகவே புதுப்பிக்கிறது. அதை நிறுவுவது Stable அல்லது Nightly channel இல் தொடங்க வேண்டுமா எனக் கேட்கும்; பின்னர் T3 Code இன் அமைப்புகளில் மாற்றவும். உங்கள் threads மற்றும் அமைப்புகள் `~/.t3` இல் வாழ்கின்றன, மற்றும் _Remove > AI_ கீழ் T3 Code ஐ அகற்றுவது அவற்றை அதனுடன் எடுத்துச் செல்லும்.

### உள்ளூர் மாதிரிகள்

உங்கள் coding agents க்காக உங்கள் சொந்த இயந்திரத்தில் ஒரு open model ஐ இயக்கவும். உங்கள் prompts மற்றும் code இயந்திரத்தில் இருக்கும்; மாதிரிக்கு அனுப்பப்படும் எதுவும் அதை விட்டு வெளியேறாது. இதனுடன் தொடங்கவும்:

```bash
omarchy models use best text
```

அது இந்த இயந்திரத்திற்கான சிறந்த text மாதிரியை அமைக்கிறது, உங்கள் முகவர்கள் பயன்படுத்தும் வகை. Image, video மற்றும் music மாதிரிகளுக்கு அவற்றின் சொந்த சிறந்தது உள்ளது: `omarchy models use best image`, `video` அல்லது `music`. ஒவ்வொரு வகையின் இந்த இயந்திரத்திற்கான தேர்வைப் பார்க்க `omarchy models use best` ஐ இயக்கவும்.

அல்லது மேல் பட்டியில் முகவர்கள் ஐகானுக்கு அடுத்து அதன் sparkles ஐகானிலிருந்து உள்ளூர் மாதிரிகள் பலகத்தைத் திறக்கவும், அல்லது Super + Ctrl + Alt + X உடன், மற்றும் + ஐத் தேர்ந்தெடுக்கவும். ஒரு மாதிரி இந்த இயந்திரத்திற்குப் பொருந்தும்போது ஐகான் தோன்றும். மாதிரிகளை இயக்கும் Podman, Omarchy உடன் வருகிறது, NVIDIA இயந்திரத்தில் NVIDIA இன் container toolkit உம் வருகிறது, இது அவற்றுக்கு GPU ஐக் கொடுக்கிறது; ஏதேனும் ஒன்று காணவில்லை என்றால், முதல் அமைப்பு அதை நிறுவும். பின்னர் Omarchy இந்த இயந்திரத்திற்கு பரிந்துரைக்கப்பட்ட மாதிரியைத் தேர்ந்தெடுத்து, அதைப் பதிவிறக்கி, அதைத் தொடங்குகிறது. பத்து GB பதிவிறக்கத்தையும் மாதிரி இயங்கும்போது இயந்திரத்தின் நினைவகத்தில் பெரும்பாலானது பயன்பாட்டில் இருப்பதையும் எதிர்பார்க்கவும்: Flash Next அதன் முழு 256K context உடன் சுமார் 100 GiB ஐப் பயன்படுத்துகிறது. மற்ற மாதிரிகள் அதற்குத் தேவையான நினைவகத்தை வைத்திருந்தால், அது நிறுத்தப்பட்ட நிலையில் அமைக்கப்படும், நீங்கள் ஒன்றை நிறுத்தியவுடன் தொடங்கத் தயாராக இருக்கும். மாதிரி logout இல் நிற்கும்; வேறு ஏதாவதுக்கு நினைவகம் தேவைப்படும்போது நீங்களே அதை நிறுத்தவும்.

`omarchy models list` விருப்பங்களைக் காட்டுகிறது மற்றும் சில ஏன் பொருந்தவில்லை என்பதை விளக்குகிறது. மற்றொன்றை அமைக்க, `omarchy models use <recipe>` ஐ இயக்கவும். இன்று, `qwen3.8-flash-next-gufo` மற்றும் `qwen3.8-27b-gufo` 128 GB Strix Halo இயந்திரங்களுக்கு கிடைக்கின்றன; 27B சுமார் 40 GiB எடுக்கும், எனவே அது மற்ற வேலைகளுக்கு இடம் விட்டுவிடும். Intel இன் Arc B390 உடன் 64 GB laptop இல், `qwen3.6-35b-a3b-llamacpp` சுமார் 30 GiB இல் இயங்குகிறது. புதிய recipes மற்றும் பரிந்துரைகள் `omarchy update` உடன், தொகுப்பு வழியாக வருகின்றன.

நீங்கள் அமைக்கும் ஒவ்வொரு மாதிரியும் உள்ளூர் மாதிரிகள் பலகத்தில் அதன் சொந்த வரியைப் பெறுகிறது: அதைத் தொடங்க play, அதை நிறுத்தி அதன் நினைவகத்தை விடுவிக்க pause, மற்றும் அதில் உங்கள் முகவரைத் திறக்க terminal பொத்தான். மேலே குறுக்காக, ஒரு bar இயந்திரத்தின் நினைவகம் Omarchy தானே (system மற்றும் உங்கள் apps), ஒவ்வொரு இயங்கும் மாதிரி, மற்றும் free என்ன உள்ளது இடையே எப்படி பிரிக்கப்பட்டுள்ளது என்பதைக் காட்டுகிறது. நிறுத்தப்பட்ட மாதிரியைச் சுட்டிக்காட்டவும் மற்றும் bar அது பொருந்துகிறதா, அல்லது எவ்வளவு குறைவாக உள்ளது என்பதைக் காட்டுகிறது. பல ஒன்றாக நினைவகத்தில் பொருந்தும்போது ஒரே நேரத்தில் இயங்க முடியும்; ஒன்று பொருந்தவில்லை என்றால், எந்த இயங்கும் மாதிரியை நிறுத்த வேண்டும் என Omarchy கூறுகிறது. அவற்றை மறுவரிசைப்படுத்த அவற்றின் logo ஆல் வரிகளை இழுக்கவும், மற்றும் ஒரு மாதிரி மற்றும் அதன் பதிவிறக்கத்தை அகற்ற தேர்ந்தெடுக்கப்பட்ட வரியில் Delete ஐ அழுத்தவும்.

நீங்கள் அமைக்கும் ஒவ்வொரு coding மாதிரியும் பயன்பாட்டு துவக்கியில் அதன் சொந்த உள்ளீட்டைப் பெறுகிறது, மாதிரியின் பெயரில் மற்றும் அதன் உருவாக்கியவரின் logo உடன், Claude, Codex அல்லது Grok இல் உள்நுழைவது ஒன்றைச் சேர்ப்பது போல. அது அந்த மாதிரியில் உங்கள் முகவரைத் திறக்கும், மற்றும் அது இயங்கவில்லை என்றால் முதலில் மாதிரியைத் தொடங்கும்: terminal அது ஏற்றுவதைக் காட்டி அது தயாரானவுடன் முகவரிடம் ஒப்படைக்கிறது. ஒரு மாதிரியை அகற்றுவது அதன் உள்ளீட்டை அகற்றும்.

ஒவ்வொரு மாதிரியும் coding க்காக அல்ல. Image, video மற்றும் music மாதிரிகள் அதற்கு பதிலாக Fantasi இல் திறக்கும், Omarchy இன் இந்த இயந்திரத்தில் இயங்கும் மாதிரியுடன் படங்கள், video மற்றும் music உருவாக்கும் பயன்பாடு, அங்கு அல்லது உள்ளூர் மாதிரிகள் பலகத்தில் அவற்றின் வரியிலிருந்து தேர்ந்தெடுக்கப்படும்.

ஒரு மாதிரி அது அமைக்கப்பட்டது போலவே தொடர்ந்து இயங்கும், எனவே ஒரு Omarchy புதுப்பிப்பு உங்கள் முகவர்களின் கீழ் ஒன்றை ஒருபோதும் மறுதொடக்கம் செய்யாது. நீங்கள் அமைத்த மாதிரிக்கு Omarchy இல் புதிய runtime அல்லது புதிய weights இருக்கும்போது, அதன் வரி ஒரு update பொத்தானைக் காட்டுகிறது: அதை அழுத்தவும் மற்றும் மாதிரி பின்னணியில் மீண்டும் அமைக்கப்படும், மாறியதை மட்டும் பதிவிறக்கி, புதிய பதிப்பில் மறுதொடக்கம் செய்யும். நிறுத்தப்பட்ட மாதிரி நிறுத்தப்பட்டதாகவே இருக்கும். `omarchy models update` ஒரு terminal இலிருந்து ஒவ்வொரு மாதிரிக்கும் அதையே செய்கிறது.

கட்டளை வரியிலிருந்து, `omarchy models start <recipe>` மற்றும் `omarchy models stop <recipe>` அதையே செய்கிறது, `omarchy models status` ஒவ்வொரு மாதிரியையும் காட்டுகிறது, மற்றும் `omarchy agent --local-model <recipe>` அந்த மாதிரியை pi இல் திறக்கிறது, உங்கள் இயல்புநிலை முகவர் எதுவாக இருந்தாலும். உங்கள் உள்ளூர் மாதிரியை agent hotkey, Quake console, மற்றும் _Make something_ திறக்கும் ஒன்றாக மாற்ற, `omarchy default agent local` ஐ இயக்கவும் அல்லது முகவர்கள் பலகத்தில் இயங்கும் மாதிரியை நட்சத்திரமிடவும். pi நீங்கள் அமைத்த ஒவ்வொரு மாதிரியையும், மற்றும் நீங்கள் இணைத்த இயந்திரங்களில் உள்ளவற்றையும், அதன் சொந்த model picker இல் பட்டியலிடுகிறது, எனவே plain `pi` உம் அவற்றை அடையும். எந்த OpenAI-compatible client உம் இணைக்க முடியும்: `status` ஒவ்வொரு மாதிரியின் முகவரியையும் காட்டுகிறது (முதலாவது `http://127.0.0.1:11435/v1`), recipe பெயர் மாதிரி, மற்றும் key `~/.config/omarchy/agent-local/key` இல் உள்ளது.

`omarchy models remove <recipe>` ஒரு மாதிரியையும் மற்ற எந்த மாதிரியும் பயன்படுத்தாத பதிவிறக்கங்களையும் நீக்குகிறது.

Third-party runtime கள் அவற்றின் publisher உடன் label செய்யப்படுகின்றன. Omarchy ஒவ்வொரு மாதிரியையும் network அணுகல் இல்லாமல் இயக்குகிறது.

### உள்ளூர் LLMகள்

Omarchy உள்ளூர் LLM மாதிரிகளை இயக்க இரண்டு வழிகளைப் பரிந்துரைக்கிறது: LM Studio மற்றும் Ollama. LM Studio open-weight மாதிரிகளைக் கண்டறிந்து, அவற்றை நிறுவி, அவற்றை இயக்க ஒரு GUI interface ஐ வழங்குகிறது. எளிதாகத் தொடங்க இது ஒரு சிறந்த வழி. Ollama இதேபோல் செய்ய ஒரு CLI ஐ வழங்குகிறது. ஆனால் நீங்கள் உள்ளூர் மாதிரிகளுக்கு புதியவர் என்றால், நான் LM Studio உடன் தொடங்குவேன். Omarchy Menu இல் _Install > AI_ கீழ் ஏதேனும் ஒன்றை நிறுவலாம்.

### Omarchy skills

Agent skills AI குறிப்பிட்ட கருவிகளை ஒரு குறிப்பிட்ட வழியில் பயன்படுத்த உதவுகிறது, மற்றும் Omarchy அவற்றில் ஏழை வழங்குகிறது. omarchy skill உங்கள் Hyprland config ஐ மாற்றுவது அல்லது bar ஐ சரிசெய்வது போல system ஐ வடிவமைப்பதை உள்ளடக்குகிறது. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app, மற்றும் omarchy-make-game புதியது ஒன்றை உருவாக்குவதை உள்ளடக்குகிறது, omarchy-contribute ஒரு பிழையைப் புகாரளிப்பது அல்லது ஒரு fix ஐ upstream க்கு அனுப்புவதை உள்ளடக்குகிறது, மற்றும் omarchy-diagnose-crash ஒரு செயலிழப்பின் core dump வழியாகச் செயல்படுகிறது. அவை Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` மற்றும் ஒவ்வொரு `~/.hermes/profiles/*/skills`), மற்றும் generic `~/.agents/skills` இடத்திற்கான skill கோப்பகங்களில் symlinked செய்யப்பட்டுள்ளன, எனவே பெரும்பாலான harness கள் அவற்றைத் தானாகவே எடுக்கும். அதே பெயரில் உங்கள் சொந்த skill folder முன்னுரிமை பெறும்.

ஆனால் நீங்கள் இந்த skills ஐ சோதனை எனக் கருத வேண்டும். வெவ்வேறு மாதிரிகள் அதை வெவ்வேறு விளைவுக்குப் பயன்படுத்தும். முதலில் plan mode இல் இயக்குவது சிறந்தது, எனவே முகவர் எதை மாற்ற விரும்புகிறது என்பது பற்றி உங்களுக்கு ஒரு யோசனை இருக்கும். பின்னர் மாற்றங்களை rollback செய்ய அல்லது முகவர் எல்லாவற்றையும் குழப்பினால் `omarchy reinstall configs` ஐ கூட அழைக்கத் தயாராக இருங்கள்.
