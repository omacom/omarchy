# AI

Omarchy உங்களுக்காக இயல்புநிலையைத் தேர்ந்தெடுக்காமல், கீழே உள்ள coding agent-களுக்கான launcher-களை உள்ளடக்கியுள்ளது. முதல் பயன்பாட்டில் அதன் CLI-ஐ நிறுவ ஒரு கட்டளையை இயக்கவும், பின்னர் கேட்கப்படும்போது அங்கீகரிக்கவும். Hermes மற்றும் OpenClaw ஆகியவை விதிவிலக்குகள்: அவற்றுக்காக mise வழியாக எதுவும் நிறுவப்படாது, அவற்றில் ஒன்றைத் தேர்ந்தெடுப்பது அதன் சொந்த தானாகப் புதுப்பிக்கும் நகலை அமைக்கிறது, கீழே உள்ள _Desktop apps_ விளக்குவது போல.

### Agent-களை நிறுவுதல் மற்றும் புதுப்பித்தல்

Hermes மற்றும் OpenClaw தவிர, இந்த agent-கள் mise-இன் lazy நிறுவலைப் பயன்படுத்துகின்றன: முதல் தொடக்கம் CLI-ஐ நிறுவுகிறது, பின்னர் வரும் தொடக்கங்கள் அதையே மீண்டும் பயன்படுத்துகின்றன. mise ஒரு நிறுவப்பட்ட agent-க்கு புதிய வெளியீடு இருக்கிறதா என நான்கு மணி நேரத்திற்கு ஒரு முறைக்கு மேல் சரிபார்க்காது, அது தொடங்குவதற்கு சற்று முன்பு அல்லது shell prompt-இல் பின்னணியில். அந்தப் புதுப்பிப்பு தோல்வியடைந்தால் அல்லது நீங்கள் offline-இல் இருந்தால், நிறுவப்பட்ட பதிப்பு இயங்கும். `omarchy update` நிறுவப்பட்ட agent-களை Omarchy-இன் மற்றவற்றுடன் சேர்த்துப் புதுப்பிக்கிறது, `mup` mise-நிர்வகிக்கும் கருவிகளை மட்டும் புதுப்பிக்கிறது.

`claude update`, `codex update` போன்ற ஒரு agent-இன் சொந்த updater, அல்லது ஒரு பயன்பாட்டில் உள்ள update பொத்தான், mise-நிர்வகிக்கும் நிறுவலைப் புதுப்பிக்காது. `codex update` தோல்வியடையும், மேலும் `claude update` வெற்றி என அறிவித்து, mise கண்காணிக்காத தனி நகலை நிறுவக்கூடும். நீங்கள் ஒரு agent-இன் சொந்த நிறுவி மற்றும் updater-ஐப் பயன்படுத்த விரும்பினால், அதை `disable_tools`-இல் சேர்க்கவும்; [Preinstalled CLI tools](18-development-tools.md#preinstalled-cli-tools) பார்க்கவும்.

உங்களுக்குத் தேவைப்படுவதற்கு முன்பே கட்டமைக்கப்பட்ட அனைத்து lazy கருவிகளையும் நிறுவ, `mise install --include-lazy` ஐ இயக்கவும். இதில் agent-களுடன் Omarchy-இன் மற்ற இயல்புநிலை CLI கருவிகளும் அடங்கும். ஒரு கருவியை நிறுவுவதற்கு அல்லது உங்கள் சொந்த நிறுவலைப் பயன்படுத்துவதற்கு [Preinstalled CLI tools](18-development-tools.md#preinstalled-cli-tools) பார்க்கவும்.

`grok` mise-இன் முதல்-தரப்பு `grok` தொகுப்பு வழியாக, `claude` மற்றும் `codex` போலவே நிறுவப்படுகிறது. `grok` ஐ இயக்கவும், அல்லது _Agent > Harness_ கீழ் அதைத் தேர்ந்தெடுக்கவும். x.ai-இல் உள்ள `curl | bash` நிறுவியைத் தவிர்க்கவும். அந்த வழி `~/.grok/bin`-இல் இரண்டாவது நகலை வைக்கிறது, அதை `PATH`-இல் முன்னால் சேர்க்கிறது, மேலும் Omarchy-இன் wrapper-ஐ மேலெழுதுகிறது.

`dsh` அதன் browser UI-ஐ `127.0.0.1:3080`-இல் திறக்கிறது, தொடக்க அடைவு அதன் இயல்புநிலை workspace ஆக இருக்கும். அதன் browser UI தொடக்க prompt-ஐ எடுத்துக்கொள்ளாது, எனவே `omarchy agent prompt` அதை உங்கள் clipboard-இல் உள்ள prompt-உடன் ஒட்டுவதற்காகத் திறக்கிறது. Omarchy அதை DeepSeek-இன் no-approval அனுமதி preset-உடன் தொடங்குகிறது. DeepSeek Harness நீங்கள் அதன் அதிகாரப்பூர்வ மாடல் API-ஐப் பயன்படுத்தும்போது session log-களை DeepSeek-க்கு பதிவேற்றுகிறது; அதன் browser UI-இல் _Settings > General > Upload Session Log_ கீழ் அதை அணைக்கவும். நீங்கள் அதற்கு அனுப்பும் கருத்தும் session-உடன் பதிவேற்றப்படும், நீங்கள் அதை `DSH_TELEMETRY_MODE=DISABLED` உடன் தொடங்கினால் தவிர.

### இயல்புநிலை agent

`omarchy default agent <name>` உடன் அல்லது Omarchy Menu-வில் (`Super + Space`) _Agent > Harness_ கீழ் உங்கள் இயல்புநிலை agent-ஐத் தேர்ந்தெடுக்கவும். agent இன்னும் நிறுவப்படவில்லை என்றால், அதைத் தேர்ந்தெடுப்பது முதலில் அதை நிறுவும், மேலும் Agent-க்கு அருகில், app launcher-இல் அதற்குச் சொந்த launcher-ஐயும் பெறும். புதிய Omarchy ஒரு முறை மட்டும் வரும் அறிவிப்புடன் இந்தத் தேர்வைச் செய்ய உங்களை அழைக்கும்.

Claude-ஐத் தேர்ந்தெடுப்பது Chromium, Chrome, Brave, Brave Origin, மற்றும் Edge-க்கு அதன் browser extension-ஐ அமைக்கவும் முயற்சிக்கிறது. extension அமைப்பு அனைத்துப் பயனர்களுக்கும் பொருந்தும் மற்றும் உங்கள் system கடவுச்சொல்லைக் கேட்கக்கூடும்; ரத்து செய்தல் அல்லது தோல்வியடைந்த extension நிறுவல் இன்னும் Claude-ஐத் தேர்ந்தெடுத்துத் தொடங்கும். உங்கள் browser-ஐ மறுதொடக்கம் செய்யவும், கேட்கப்பட்டால் extension-ஐ இயக்கவும், மேலும் அதை இணைப்பதை முடிக்க Claude-இல் உள்நுழையவும். இணைப்பைச் சரிபார்க்க Claude-இல் `/chrome` ஐ இயக்கவும். Firefox மற்றும் Zen இந்த extension-ஐ ஆதரிக்காது. இந்த அமைப்பு சேர்க்கப்படுவதற்கு முன்பே Claude ஏற்கனவே உங்கள் இயல்புநிலையாக இருந்தால், extension-ஐ நிறுவ அதை மீண்டும் தேர்ந்தெடுக்கவும்.

நீங்கள் தேர்ந்தெடுத்த பிறகு, `Super + Shift + Ctrl + A` இயல்புநிலை agent-ஐ ஒரு பிரத்யேக terminal சாளரத்தில் தொடங்கும் (அல்லது நீங்கள் இன்னும் தேர்ந்தெடுக்கவில்லை என்றால் picker-ஐக் கொண்டுவரும்). `omarchy agent prompt "Review this project"` உடன் நேரடியாக ஒரு பணிக்குள் தொடங்கவும் முடியும். Freebuff மற்றும் DeepSeek Harness தொடக்க prompt-ஐ எடுத்துக்கொள்ளாது, எனவே அவை அதற்குப் பதிலாக உங்கள் clipboard-இல் உள்ள prompt-உடன் ஒட்டுவதற்காகத் திறக்கும். இப்படித் தொடங்கப்படும் agent-கள் அவற்றின் அந்தந்த don't-stop-to-ask முறைகளில் கவனிக்கப்படாமல் இயங்கும், எனவே அவை உண்மையில் விஷயங்களைச் செய்யத் தயாராக இருங்கள்! MiniMax Code-க்கு அதன் interactive session-களுக்கு அத்தகைய முறை இல்லை, எனவே அது வழக்கம் போல அனுமதிகளைக் கேட்கும். மேலும் agent-கள் உங்கள் home அடைவுக்கான trust-ஐ நினைவில் வைக்க மறுப்பதால், `$HOME`-இலிருந்து தொடங்குவது அதற்குப் பதிலாக `~/Work`-இல் தொடங்கும்.

terminal shortcut-களும் உள்ளன: `a` தற்போதைய terminal-இல் இயல்புநிலை agent-ஐ inline-ஆக இயக்கும், அதே நேரம் `c`, `cx`, மற்றும் `cy` OpenCode, Claude Code, மற்றும் Codex-ஐ நேரடியாகத் தொடங்கும் (மீண்டும் அவற்றின் auto-approving முறைகளில்). Theme மாற்றங்களும் agent-களுக்கு ஒத்திசைகின்றன: Omarchy theme-ஐ மாற்றும்போது Claude Code, Pi, OpenCode, மற்றும் Hermes (Omarchy அதை நிறுவியவுடன்) அனைத்தும் பின்தொடரும்.

### உங்கள் agent வழிமுறைகள்

ஒவ்வொரு agent-க்குமான தனிப்பட்ட விதிகள் `~/.agents/AGENTS.md`-இல், `~/.agents/skills`-இல் உள்ள பகிரப்பட்ட skill-களுக்கு அருகில் செல்லும். அதை _Agent > Instructions_ கீழ் திறக்கவும், இது ஒவ்வொரு harness-இன் சொந்த global கோப்பை வைத்திருக்கும் இடத்திலும் அதை இணைக்கிறது: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, Copilot-இன் `~/.copilot/copilot-instructions.md`, மற்றும் பல. Crush மற்றும் Amp `~/.config/AGENTS.md` இணைப்பைப் படிக்கும், omp, Kimi, மற்றும் DeepSeek Harness `~/.agents/AGENTS.md`-ஐ நேரடியாகப் படிக்கும். இயல்புநிலை agent-ஐத் தேர்ந்தெடுப்பதும் அதை இணைக்கிறது. நீங்கள் ஏற்கனவே வைத்திருந்த வழிமுறைகள் கோப்பு, இன்னும் ஒன்று இல்லை என்றால், பகிரப்பட்டதாக மாறும்; இல்லையெனில் அது இணைப்பின் அருகில் `.bak` ஆக வைக்கப்படும். மற்றொரு agent-ஐ நிறுவிய பிறகு மீண்டும் இணைக்க `omarchy agent instructions` ஐ இயக்கவும்.

### பல சந்தாக்கள்

நீங்கள் ஒன்றுக்கு மேற்பட்ட Claude, Codex, அல்லது Grok திட்டத்திற்கு பணம் செலுத்தினால் — தனிப்பட்ட Max மற்றும் வேலை ஒன்று, சொல்லலாம் — Omarchy அவை அனைத்தையும் உள்நுழைந்த நிலையில் வைத்திருக்கவும் அவற்றுக்கிடையே நகரவும் முடியும். agents panel-இல் உள்ள + உடன் ஒரு சந்தாவைச் சேர்க்கவும், அது அங்கேயே உங்களை அதன் வழியாக அழைத்துச் செல்லும், அல்லது `omarchy agent account add claude Work` உடன் (அல்லது `codex`, அல்லது `grok`). அது இல்லை என்றால் CLI-ஐ நிறுவும். ஒரு provider-க்கான முதல் கணக்கு உங்கள் சாதாரண browser வழியாக, CLI எப்போதும் பார்க்கும் இடத்திலேயே உள்நுழைகிறது. அதன் பிறகு வரும் ஒவ்வொன்றும் private சாளரம் வழியாக உள்நுழைகிறது, எனவே உங்கள் browser ஏற்கனவே உள்நுழைந்துள்ள கணக்கு தவறாக எடுக்கப்படாது; நீங்கள் சேர்க்கும் கணக்காக அங்கு உள்நுழைந்து, நீங்கள் ஏற்கனவே திறந்திருந்த எந்த private சாளரத்தையும் முதலில் மூடவும். இதைச் செய்ய CLI-இலிருந்து ஒருபோதும் வெளியேற வேண்டாம்: வெளியேறுவது சேமிக்கப்பட்ட sign-in-ஐ ரத்து செய்யும், மேலும் அந்தக் கணக்கு மீண்டும் சேர்க்கப்பட வேண்டும்.

உங்கள் சந்தா உள்நுழைவுகளை மற்றொரு Omarchy இயந்திரத்திற்கு SSH வழியாக நகலெடுக்க, `omarchy agent account copy user@laptop` ஐ இயக்கவும். இலக்கில் ஒன்று நிறுவப்படவில்லை என்றால் அனுப்புநர் தற்காலிக receiver-ஐ வழங்குகிறார், எனவே பழைய Omarchy இயந்திரங்கள் update இல்லாமல் கணக்குகளைப் பெற முடியும். நிறுவப்பட்ட receiver-கள் முன்னுரிமை பெறும். இது அனைத்து Claude, Codex, மற்றும் Grok சந்தாக்களையும் நகலெடுக்கிறது; அவற்றைத் தேர்ந்தெடுக்க provider பெயர்களைச் சேர்க்கவும், `omarchy agent account copy laptop claude` போல. கணக்குப் பெயர்கள் மற்றும் command ID-கள் மூலத்துடன் பொருந்துகின்றன, இலக்கில் ஏற்கனவே உள்ள கணக்குகள் உட்பட. தொடர்பில்லாத இலக்கு கணக்குகள் அவற்றின் பெயர்கள் முரண்பட்டால் எண் பின்னொட்டைப் பெறும், மேலும் அமைப்புகள், skills, plugins, மற்றும் உரையாடல் வரலாறு ஒவ்வொரு இயந்திரத்திற்கும் உள்ளூராக இருக்கும்.

ஏற்கனவே உள்ள இலக்கு credentials வைக்கப்படுகின்றன. அங்கு ஏற்கனவே உள்நுழைந்துள்ள மூலக் கணக்கு அதன் credentials-ஐ மாற்றாமல் அதன் பெயர் ஒத்திசைக்கப்படுகிறது; மற்ற கணக்குகள் அதனுடன் சேர்க்கப்படுகின்றன. பொருந்தும் கணக்குகளுக்கான சேமிக்கப்பட்ட credentials-ஐ மாற்ற, இலக்கில் அந்தக் கணக்கின் session-களை விட்டு வெளியேறிய பிறகு `omarchy agent account copy --replace laptop claude` ஐப் பயன்படுத்தவும். புதிய இலக்கு மூலத்தின் செயலில் உள்ள கணக்கு மற்றும் மாறுதல் விருப்பங்களையும் பெறுகிறது; நிறுவப்பட்ட இலக்கு அதன் சொந்தத்தை வைத்திருக்கிறது.

Credentials SSH வழியாகப் பயணம் செய்து இலக்கில் private கோப்புகளில் சேமிக்கப்படுகின்றன, எனவே நீங்கள் நம்பும் இயந்திரங்களுக்கு மட்டுமே நகலெடுக்கவும். இது ஒரு முறை நகல், தொடர்ச்சியான ஒத்திசைவு அல்ல. Codex refresh token-கள் மற்றொரு இயந்திரத்தால் மாற்றப்படக்கூடும், நகலெடுக்கப்பட்ட உள்நுழைவுக்கு புதுப்பித்தல் தேவைப்படும்; பல இயந்திரங்களில் ஒரே நேரத்தில் பயன்படுத்துவதற்கு தனித்தனி sign-in-கள் மிகவும் நம்பகமான தேர்வாக இருக்கின்றன. [Codex's account authentication guidance](https://developers.openai.com/codex/auth/ci-cd-auth) பார்க்கவும்.

ஒரு provider-க்கு ஒரு கணக்கு செயலில் இருக்கும், மேலும் ஒவ்வொரு புதிய session-ம் அதுவாகத் தொடங்கும்: `cx`, `cy`, சாதாரண `claude`, `codex`, அல்லது `grok`, `omarchy agent` வழியாகத் தொடங்கப்படும் எதுவும், மற்றும் `PATH`-இல் CLI-ஐக் கண்டறியும் script-கள் அல்லது editor-கள். `omarchy agent account use work` உடன் மாறவும் (மற்றும் `omarchy agent account use main` உடன் திரும்பவும்), அல்லது panel-இல் ஒரு கணக்கின் எண்ணை அழுத்தி பின்னர் `Enter` அழுத்தவும் (அல்லது அதன் Use பொத்தானை click செய்யவும்). இயங்கும் Claude session-களும், அவற்றின் அடுத்த செய்தியிலிருந்து மாறும்: ஒவ்வொரு Claude session-ம் `~/.claude`-இல் இயங்குகிறது, இது எப்போதும் செயலில் உள்ள கணக்கின் sign-in-ஐ வைத்திருக்கும். பழைய Omarchy மூலம் ஒரு கணக்கின் சொந்த folder-இல் தொடங்கப்பட்ட Claude session அது வெளியேறும் வரை அந்த sign-in-ஐ வைத்திருக்கும், எனவே மாற்றம் அந்த session-களைப் பெயரிடுகிறது மற்றும் அவை போனவுடன் தானாகவே முடிகிறது. இயங்கும் Codex மற்றும் Grok session-கள் அவை தொடங்கிய கணக்கிலேயே இருக்கும். உரையாடல் வரலாறு, அமைப்புகள், skills, மற்றும் plugins கணக்குகள் முழுவதும் பகிரப்படுகின்றன, எனவே அதே folder-இல் `claude --continue` நீங்கள் புதிய கணக்கில் விட்ட இடத்திலிருந்து தொடரும்.

ஒன்றுக்கு மேற்பட்ட கணக்குடன், panel ஒவ்வொரு கணக்கின் வரம்புகளையும் அருகருகே காட்டுகிறது, செயலில் உள்ளது குறிக்கப்பட்டுள்ளது. இயல்பாக Omarchy செயலில் உள்ள கணக்கு ஒரு வரம்பின் 95%-ஐக் கடக்கும்போது உங்களுக்கு அறிவிக்கிறது, மேலும் அறிவிப்பை click செய்வது அதிக headroom உள்ள கணக்கிற்கு மாற்றுகிறது. panel-இல் ஒரு கணக்கின் வரியை hover செய்து Use-க்கு அருகில் தோன்றும் Autoswitch-ஐ click செய்யவும் (அல்லது `m` அழுத்தவும்), அல்லது அது தானாகவே மாற `omarchy agent account mode auto` ஐ இயக்கவும்; அது இயக்கத்தில் இருக்கும்போது, Autoswitch Use-இன் இடத்தை எடுக்கும், மேலும் அதை மீண்டும் click செய்வது அறிவிப்பதற்குத் திரும்பும். threshold-ஐ மாற்ற ஒரு எண்ணைச் சேர்க்கவும், `omarchy agent account mode auto 90` போல. ஒவ்வொரு கணக்கும் threshold-க்கு மேல் இருந்தால், எந்தக் கணக்கு முதலில் விடுவிக்கப்படுகிறது என்பதுடன் ஒரு முறை அதைப் பற்றி நீங்கள் கேட்பீர்கள். செயலில் உள்ள கணக்கு அதன் threshold-இலிருந்து 15 புள்ளிகளுக்குள் இருக்கும்போது (இயல்புநிலையில் 80%), அதன் வரம்புகள் ஒவ்வொரு 15-க்கும் பதிலாக ஒவ்வொரு மூன்று நிமிடங்களுக்கும் சரிபார்க்கப்படுகின்றன.

`omarchy agent account list` ஒவ்வொரு கணக்கையும் அதன் சமீபத்திய வரம்புகளையும் காட்டுகிறது, `omarchy agent account remove work` ஒன்றை மறக்கிறது, மற்றும் `omarchy agent account rename primary Hey` ஒன்றை மறுபெயரிடுகிறது (அல்லது panel-இல் ஒரு கணக்கின் பெயரை click செய்யவும்). இந்தக் கட்டளைகள் உங்கள் இயல்புநிலை agent-இன் கணக்குகளில் வேலை செய்கின்றன; மற்ற provider-ஐ அடைய, முதலில் அதைப் பெயரிடவும், `omarchy agent account use codex side` போல. `~/.claude` அல்லது `~/.codex`-இல் நீங்கள் ஏற்கனவே வைத்திருந்த உள்நுழைவு _Main_ கணக்கு ஆகும். Codex-இனது அது இருக்கும் இடத்திலேயே இருக்கும்; Claude-இனது மற்றொரு கணக்கு செயலில் இருக்கும்போது அதன் சொந்த folder-இல் காத்திருக்கும். சுமார் எட்டு மணி நேரத்திற்கு மேல் பயன்படுத்தப்படாமல் விடப்பட்ட கணக்கு _Sign-in required_ எனக் காட்டக்கூடும்; panel-இல் உடனே அந்தக் கணக்கில் மீண்டும் உள்நுழைய அதை click செய்யவும், அல்லது அதற்கு மாறி ஒரு session-ஐத் தொடங்கவும், இது தானாகவே sign-in-ஐப் புதுப்பிக்கும். நீங்கள் `claude mcp add` உடன் சேர்க்கும் MCP server-கள் ஒவ்வொரு Claude கணக்கையும் அடையும், ஏனெனில் அவை அனைத்தும் `~/.claude`-இல் இயங்குகின்றன; Codex மற்றும் Grok-க்கு, ஒரு கணக்கு சேர்க்கப்பட்டபோது நீங்கள் வைத்திருந்த server-கள் அதற்கு வரும், ஆனால் பின்னர் வருவன நீங்கள் அவற்றைச் சேர்த்த கணக்கை மட்டுமே அடையும். Claude Desktop அதன் சொந்த sign-in-ஐ வைத்திருக்கிறது, மேலும் CLI binary-க்கு absolute path உடன் கட்டமைக்கப்பட்ட Codex அல்லது Grok கருவிகள் மாற்றத்தைப் பின்பற்றாது. வெளிப்படையான `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, அல்லது `GROK_HOME` தேர்ந்தெடுக்கப்பட்ட கணக்கை விட முன்னுரிமை பெறுகிறது.

### செயலிழப்பு கண்டறிதல்

Omarchy செயல்முறை செயலிழப்புகளுக்காக systemd-coredump-ஐக் கண்காணிக்கிறது. நீங்கள் இயல்புநிலை agent-ஐத் தேர்ந்தெடுத்தவுடன், core dump செய்யும் உங்கள் எந்த நிரலும் "Process crashed" அறிவிப்பைக் கொண்டுவரும் — அதை click செய்யவும், மேலும் செயலிழப்பு உங்கள் இயல்புநிலை agent-க்கு Omarchy-இன் omarchy-diagnose-crash skill-உடன் கொடுக்கப்படும், இது core dump-இலிருந்து உண்மைகளை நிறுவுவதன் வழியாகவும் செயலிழப்பு upstream-இல் அறிவிக்கத் தகுதியானதா எனத் தீர்மானிப்பதன் வழியாகவும் agent-ஐ அழைத்துச் செல்லும். `coredumpctl list`-இலிருந்து எந்த PID-க்கும் எதிராக `omarchy agent crash <pid>` உடன் அதை கையாலும் இயக்கலாம்.

கண்காணிப்பு இயல்பாக இயக்கத்தில் உள்ளது. அதை _Trigger > Toggle > Crash Capture Off_ கீழ் (அல்லது `omarchy toggle crash-capture` உடன்) அணைக்கவும், அறிவிப்புகள் நிற்கும்; `omarchy agent crash <pid>` இன்னும் கையால் வேலை செய்யும்.

செயலிழப்புகளை ஒரு நேரத்தில் ஒரு நிரல் வீதம் அமைதிப்படுத்தவும் முடியும், இதைத்தான் கண்டறிதல் இறுதியில் உங்களுக்கு வழங்குகிறது. `omarchy crash mute hyprland` அந்த நிரலுக்கு மட்டும் அறிவிப்புகளை நிறுத்துகிறது, `omarchy crash mute hyprland off` அவற்றை மீண்டும் கொண்டுவருகிறது, மேலும் `omarchy crash mute` தனியாக நீங்கள் என்ன mute செய்தீர்கள் என்பதைப் பட்டியலிடுகிறது. இது binary-இன் path-ஐ அதன் பெயரைப் போலவே மகிழ்ச்சியாக எடுக்கும், எனவே `omarchy crash mute /usr/bin/hyprland` அதையே செய்கிறது. இடைவெளி உள்ள பெயரை மேற்கோள் காட்டவும், `omarchy crash mute 'Some App'` போல. மற்ற அனைத்தும் இன்னும் அறிவிக்கும், மேலும் mute செய்யப்பட்ட நிரல் இன்னும் செயலிழக்கும் — இது நினைவூட்டலை மறைக்கிறது, இது எதையும் சரி செய்யாது.

### Desktop apps

_Install > AI_ மெனு சில graphical AI பயன்பாடுகளையும் கொண்டுள்ளது: Amp Desktop, Antigravity Desktop, ChatGPT desktop app, Claude desktop app (Anthropic-இன் Linux beta, Chat, Cowork, மற்றும் Claude Code tabs உடன்), xAI-இன் மாடல்களுடன் அரட்டை அடிக்க Grok Bot, Herdr Desktop, Hermes Desktop, OpenClaw, Perplexity desktop app, மற்றும் T3 Code. Grok Bot என்பது desktop chat பயன்பாடு. coding agent என்பது `grok` கட்டளை.

Hermes Desktop தான் தெரிந்து கொள்ள வேண்டியது, ஏனெனில் ஒரு இயந்திரத்திற்கு ஒரு Hermes உள்ளது, அது பயன்பாட்டினுடையது: Hermes எப்போதும் பயன்பாடு வழியாக மட்டுமே நிறுவப்படுகிறது, மேலும் இயல்புநிலை agent இயக்கும் `hermes` கட்டளை பயன்பாட்டினுடையது. Hermes-ஐ இயல்புநிலை agent ஆகத் தேர்ந்தெடுப்பது _Install > AI_ நுழைவு செய்வதையே நிறுவுகிறது: தொகுப்பு, மற்றும் Hermes-இன் சொந்த நிறுவியால் அமைக்கப்பட்ட `~/.hermes` கீழ் ஒரு Hermes runtime, இது முதல் முறை சில நிமிடங்கள் எடுக்கும். அந்த runtime தான் terminal `hermes` கட்டளை, இயல்புநிலை agent மற்றும் பயன்பாடு அனைத்தும் பயன்படுத்தும் ஒரே Hermes, மேலும் இது Omarchy வெளியீட்டிற்காகக் காத்திருக்காமல் `hermes update` உடன் தானாகவே புதுப்பிக்கிறது. அதை நிறுவுவது Hermes-க்கு Omarchy theme-ஐ `omarchy` என்ற பெயரிடப்பட்ட skin ஆகவும் கொடுக்கிறது, நீங்கள் theme-களை மாற்றும்போது ஒவ்வொரு Hermes மேற்பரப்பும் அதைப் பின்பற்றும்; நீங்கள் அது வேண்டாம் என்றால் Hermes-இன் Appearance அமைப்புகளின் கீழ் அல்லது `/skin` உடன் மற்றொன்றைத் தேர்ந்தெடுக்கவும், Omarchy அந்தத் தேர்வை அப்படியே விட்டுவிடும். _Remove > AI_ கீழ் பயன்பாட்டை நீக்குவது முதலில் Hermes-ஐ மூடுகிறது, gateway உட்பட, அந்த runtime-ஐ அதனுடன் எடுத்துச் செல்கிறது, மேலும் உங்கள் chats, memories, மற்றும் Hermes தனக்காக எழுதிய skills-ஐ வைத்திருக்கிறது, நீங்கள் வேறுவிதமாகச் சொன்னால் தவிர: அந்த data மற்றும் உங்கள் இணைப்பு அமைப்புகளும் போக வேண்டுமா என அது கேட்கிறது, இயல்புநிலை no ஆகும்.

OpenClaw-இன் desktop அனுபவம் அதன் Control UI ஆகும், இது அதன் சொந்த உள்ளூர் gateway-ஆல் ஆதரிக்கப்படும் web பயன்பாடாகத் திறக்கிறது. OpenClaw `~/.openclaw`-இல் வாழ்கிறது மற்றும் தானாகவே புதுப்பிக்கிறது: Control UI-இன் "Update Gateway" பொத்தானைப் பயன்படுத்தவும் அல்லது `openclaw update` ஐ இயக்கவும், மேலும் gateway புதிய பதிப்பில் மறுதொடக்கம் செய்யும். புதிய நிறுவல் தொடங்கும் வெளியீட்டை மட்டுமே Omarchy தேர்ந்தெடுக்கிறது. OpenClaw உங்கள் இயல்புநிலை agent-ஆகவும் இருக்க முடியும்: அதை _Agent > Harness_ கீழ் தேர்ந்தெடுப்பது `~/.openclaw`-இல் அதே நகலை அமைக்கிறது, மேலும் agent OpenClaw-இன் terminal UI-ஐ அதன் gateway-உடன் இணைத்துத் திறக்கிறது. _Remove > AI_ கீழ் OpenClaw-ஐ நீக்குவது gateway service மற்றும் பயன்பாட்டை அதனுடன் எடுத்துச் சென்று, பின்னர் `~/.openclaw` போக வேண்டுமா எனக் கேட்கிறது, ஏனெனில் அது OpenClaw மற்றும் அது பதிவிறக்கும் plugin runtime-களுடன் உங்கள் chats மற்றும் credentials-ஐ வைத்திருக்கிறது; இயல்புநிலை அதை வைத்திருக்கிறது, மேலும் OpenClaw-ஐ மீண்டும் நிறுவுவது அதை மீண்டும் எடுத்துக்கொள்ளும்.

Herdr Desktop என்பது [Herdr](https://herdr.dev) desktop பயன்பாடு: நீங்கள் சாளரத்தை மூடும்போது அதன் core-இல் தொடர்ந்து இயங்கும் terminal-கள் மற்றும் coding agent-களின் spaces, tabs, மற்றும் panes. இது ஒரு தொகுப்பிலிருந்து அல்லாமல் Herdr-இன் சொந்த நிறுவியிலிருந்து வருகிறது, எனவே இது `~/.local/share/herdr-app`-இல் வாழ்கிறது, உங்களிடம் ஏற்கனவே ஒன்று இல்லாதபோது `~/.local/bin/herdr-core`-இல் அதன் core-ஐக் கொண்டுவருகிறது, மேலும் இரண்டையும் தானாகவே புதுப்பிக்கிறது. இது Omarchy `Super + Ctrl + Return`-இல் வழங்கும் `herdr` கட்டளையை மாற்றாமல் அதன் அருகில் அமர்கிறது, மேலும் அந்தக் கட்டளையின் நேரடி key-களைப் பெறுகிறது: `Alt + Return` மற்றும் `Alt + Shift + Return` ஒரு pane-ஐ கீழே அல்லது வலதே பிரிக்கிறது, `Alt + Escape` அதை மூடுகிறது, `Ctrl + Alt + Arrow` pane-களுக்கிடையே நகர்கிறது, `Alt + 1..9` மற்றும் `Alt + Left/Right` ஒரு tab-ஐத் தேர்ந்தெடுக்கிறது, மற்றும் `Alt + Up/Down` space-களுக்கிடையே நகர்கிறது. `Ctrl + 1..9` ஒரு space-ஐத் தேர்ந்தெடுக்கிறது மற்றும் `Alt + Shift + Up/Down` agent-கள் வழியாகச் செல்கிறது. `Ctrl + Space` prefix key-கள் terminal-க்கு மட்டுமே இருக்கும், ஏனெனில் பயன்பாடு ஒரு sequence-க்கு சாதாரண Ctrl key-ஐ வைத்திருக்க முடியாது. Omarchy இவற்றை `~/.config/herdr-app/keys.json`-க்கு எழுதுகிறது, மேலும் `omarchy-refresh-herdr-app` அவற்றை மீண்டும் வைக்கிறது. அதை நிறுவுவது Herdr-இன் Omarchy theme-ஐத் தேர்ந்தெடுக்கிறது, இது அப்போதிருந்து உங்கள் Omarchy theme-ஐப் பின்பற்றுகிறது. Herdr light mode-க்கு ஒரு theme-ஐயும் dark mode-க்கு ஒன்றையும் வைத்திருக்கிறது, எனவே dark மற்றும் light Omarchy theme-க்கு இடையே மாறிய பிறகு, மற்ற mode-க்கு Herdr-இன் theme picker-இல் Omarchy-ஐ மீண்டும் ஒரு முறை தேர்ந்தெடுக்கவும்.

T3 Code ஒரு தொகுப்பிலிருந்து அல்லாமல் `~/.local/share/t3code`-இல் உள்ள அதன் அதிகாரப்பூர்வ AppImage வெளியீட்டிலிருந்து இயங்குகிறது, எனவே இது தானாகவே புதுப்பிக்கிறது. அதை நிறுவுவது Stable அல்லது Nightly channel-இல் தொடங்க வேண்டுமா எனக் கேட்கிறது; பின்னர் T3 Code-இன் அமைப்புகளில் மாறவும். உங்கள் threads மற்றும் settings `~/.t3`-இல் வாழ்கின்றன, மேலும் _Remove > AI_ கீழ் T3 Code-ஐ நீக்குவது அவற்றை அதனுடன் எடுத்துச் செல்கிறது.

### உள்ளூர் மாடல்கள்

உங்கள் coding agent-களுக்காக உங்கள் சொந்த இயந்திரத்தில் ஒரு open மாடலை இயக்கவும். உங்கள் prompt-கள் மற்றும் code இயந்திரத்திலேயே இருக்கும்; மாடலுக்கு அனுப்பப்படும் எதுவும் அதை விட்டு வெளியேறாது. இதனுடன் தொடங்கவும்:

```bash
omarchy agent local use best
```

அல்லது, மேல் bar-இல் உள்ள agents panel-இல், + மற்றும் பின்னர் Local AI-ஐத் தேர்ந்தெடுக்கவும், இது ஒரு மாடல் இந்த இயந்திரத்திற்குப் பொருந்தும்போது காட்டப்படும். மாடல்களை இயக்கும் Podman, Omarchy-உடன் வருகிறது, NVIDIA இயந்திரத்தில் NVIDIA-இன் container toolkit-ம் அவற்றுக்கு GPU-ஐக் கொடுக்கிறது; ஏதேனும் ஒன்று இல்லை என்றால், முதல் அமைப்பு அதை நிறுவும். பின்னர் Omarchy இந்த இயந்திரத்திற்கு பரிந்துரைக்கப்பட்ட மாடலைத் தேர்ந்தெடுத்து, அதைப் பதிவிறக்கி, தொடங்குகிறது. பத்து GB அளவிலான பதிவிறக்கத்தையும், மாடல் இயங்கும்போது இயந்திரத்தின் நினைவகத்தில் பெரும்பாலானது பயன்பாட்டில் இருப்பதையும் எதிர்பார்க்கவும்: Flash Next அதன் முழு 256K context-உடன் சுமார் 100 GiB பயன்படுத்துகிறது. மற்ற மாடல்கள் அதற்குத் தேவையான நினைவகத்தை வைத்திருந்தால், இது நிறுத்தப்பட்ட நிலையில் அமைக்கப்படுகிறது, நீங்கள் ஒன்றை நிறுத்தியவுடன் தொடங்கத் தயாராக இருக்கும். மாடல் logout-இல் நிற்கும்; உங்களுக்கு நினைவகம் வேறு எதற்காவது தேவைப்படும்போது அதை நீங்களே நிறுத்தவும்.

`omarchy agent local list` விருப்பங்களைக் காட்டுகிறது மற்றும் சில ஏன் பொருந்தாது என விளக்குகிறது. மற்றொன்றை அமைக்க, `omarchy agent local use <recipe>` ஐ இயக்கவும். இன்று, `qwen3.8-flash-next-gufo` மற்றும் `qwen3.8-27b-gufo` 128 GB Strix Halo இயந்திரங்களுக்குக் கிடைக்கின்றன; 27B சுமார் 40 GiB எடுக்கும், எனவே இது மற்ற வேலைகளுக்கு இடம் விடுகிறது. Intel-இன் Arc B390 உடன் 64 GB laptop-இல், `qwen3.6-35b-a3b-llamacpp` சுமார் 30 GiB-இல் இயங்குகிறது. புதிய recipe-களும் பரிந்துரைகளும் தொகுப்பு வழியாக `omarchy update` உடன் வருகின்றன.

நீங்கள் அமைக்கும் ஒவ்வொரு மாடலும் agents panel-இல், உங்கள் சந்தாக்களுக்கு அருகில், அதன் சொந்த வரியைப் பெறுகிறது: அதைத் தொடங்க play, அதை நிறுத்தி அதன் நினைவகத்தை விடுவிக்க pause, மேலும் அதில் உங்கள் agent-ஐத் திறக்க terminal பொத்தான். அவை நினைவகத்தில் ஒன்றாகப் பொருந்தும்போது பல ஒரே நேரத்தில் இயங்க முடியும்; ஒன்று பொருந்தவில்லை என்றால், எந்த இயங்கும் மாடலை நிறுத்த வேண்டும் என Omarchy சொல்கிறது. அவற்றை மறுவரிசைப்படுத்த வரிகளை இழுக்கவும், மேலும் ஒரு மாடலையும் அதன் பதிவிறக்கத்தையும் நீக்க தேர்ந்தெடுக்கப்பட்ட வரியில் Delete அழுத்தவும்.

நீங்கள் அமைக்கும் ஒவ்வொரு மாடலும் app launcher-இல் அதன் சொந்த பதிவையும் பெறுகிறது, மாடலின் பெயரின் கீழ் மற்றும் அதன் தயாரிப்பாளரின் logo-உடன், Claude, Codex அல்லது Grok-இல் உள்நுழைவது ஒன்றைச் சேர்ப்பது போல. இது அந்த மாடலில் உங்கள் agent-ஐத் திறக்கிறது, மேலும் அது இயங்கவில்லை என்றால் முதலில் மாடலைத் தொடங்குகிறது: terminal அது ஏற்றப்படுவதைக் காட்டி, அது தயாரானவுடன் agent-க்குக் கொடுக்கிறது. ஒரு மாடலை நீக்குவது அதன் பதிவை நீக்குகிறது.

ஒவ்வொரு மாடலும் coding-க்கு அல்ல. Image, video மற்றும் music மாடல்கள் அதற்குப் பதிலாக Fantasi-இல் திறக்கும், இந்த இயந்திரத்தில் இயங்கும் மாடலுடன் படங்கள், video மற்றும் music உருவாக்க Omarchy-இன் பயன்பாடு, அவற்றின் launcher பதிவிலிருந்தும் agents panel-இல் அவற்றின் வரியிலிருந்தும்.

ஒரு மாடல் அது அமைக்கப்பட்டபடியே சரியாகத் தொடர்ந்து இயங்குகிறது, எனவே Omarchy update ஒருபோதும் உங்கள் agent-களின் கீழ் ஒன்றை மறுதொடக்கம் செய்யாது. நீங்கள் அமைத்த மாடலுக்கு Omarchy-இடம் புதிய runtime அல்லது புதிய weights இருக்கும்போது, அதன் வரி update பொத்தானைக் காட்டுகிறது: அதை அழுத்தவும், மாடல் பின்னணியில் மீண்டும் அமைக்கப்படுகிறது, மாறியதை மட்டும் பதிவிறக்குகிறது, மேலும் புதிய பதிப்பில் மறுதொடக்கம் செய்கிறது. நிறுத்தப்பட்ட மாடல் நிறுத்தப்பட்டே இருக்கும். `omarchy agent local update` terminal-இலிருந்து ஒவ்வொரு மாடலுக்கும் அதையே செய்கிறது.

command line-இலிருந்து, `omarchy agent local start <recipe>` மற்றும் `omarchy agent local stop <recipe>` அதையே செய்கின்றன, `omarchy agent local status` ஒவ்வொரு மாடலையும் காட்டுகிறது, மேலும் `omarchy agent --local` நீங்கள் கடைசியாகத் தொடங்கிய மாடலில் உங்கள் இயல்புநிலை agent-ஐத் திறக்கிறது. pi, OpenCode மற்றும் Qwen Code ஒன்றைப் பயன்படுத்த முடியும்; வேறு எந்த இயல்புநிலையுடனும் இது pi-இல் திறக்கும், அல்லது உங்களிடம் pi இல்லை என்றால் OpenCode-இல். pi நீங்கள் அமைத்த ஒவ்வொரு மாடலையும், மேலும் நீங்கள் இணைத்த இயந்திரங்களில் உள்ளவற்றையும், அதன் சொந்த model picker-இல் பட்டியலிடுகிறது, எனவே சாதாரண `pi` அவற்றையும் அடையும். எந்த OpenAI-இணக்கமான client-ம் இணைக்க முடியும்: `status` ஒவ்வொரு மாடலின் முகவரியையும் காட்டுகிறது (முதலாவது `http://127.0.0.1:11435/v1`), recipe பெயர் மாடல் ஆகும், மேலும் key `~/.config/omarchy/agent-local/key`-இல் உள்ளது.

`omarchy agent local remove <recipe>` ஒரு மாடலையும் வேறு எந்த மாடலும் பயன்படுத்தாத பதிவிறக்கங்களையும் நீக்குகிறது.

மூன்றாம் தரப்பு runtime-கள் அவற்றின் publisher-உடன் பெயரிடப்பட்டுள்ளன. Omarchy ஒவ்வொரு மாடலையும் network அணுகல் இல்லாமல் இயக்குகிறது.

### Local LLMs

Omarchy உள்ளூர் LLM மாடல்களை இயக்க இரண்டு வழிகளைப் பரிந்துரைக்கிறது: LM Studio மற்றும் Ollama. LM Studio open-weight மாடல்களைக் கண்டறிய, அவற்றை நிறுவ, மற்றும் அவற்றை இயக்க GUI interface-ஐ வழங்குகிறது. எளிதாகத் தொடங்க இது ஒரு சிறந்த வழி. Ollama இதேபோல் செய்ய CLI-ஐ வழங்குகிறது. ஆனால் நீங்கள் உள்ளூர் மாடல்களுக்குப் புதியவர் என்றால், நான் LM Studio-உடன் தொடங்குவேன். Omarchy Menu-வில் _Install > AI_ கீழ் இரண்டில் ஒன்றை நிறுவலாம்.

### Omarchy skills

Agent skills AI குறிப்பிட்ட கருவிகளை ஒரு குறிப்பிட்ட வழியில் பயன்படுத்த உதவுகின்றன, மேலும் Omarchy அவற்றில் ஏழு வழங்குகிறது. omarchy skill system-ஐத் தனிப்பயனாக்குவதை உள்ளடக்குகிறது, உங்கள் Hyprland config-ஐ மாற்றுவது அல்லது bar-ஐ சரிசெய்வது போல. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app, மற்றும் omarchy-make-game புதிதாக ஒன்றை உருவாக்குவதை உள்ளடக்குகின்றன, omarchy-contribute பிழையை அறிவிப்பது அல்லது upstream-க்கு ஒரு திருத்தத்தை அனுப்புவதை உள்ளடக்குகிறது, மற்றும் omarchy-diagnose-crash ஒரு செயலிழப்பின் core dump வழியாக வேலை செய்கிறது. அவை Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` மற்றும் ஒவ்வொரு `~/.hermes/profiles/*/skills`), மற்றும் பொதுவான `~/.agents/skills` இடத்திற்கான skill அடைவுகளில் symlink செய்யப்பட்டுள்ளன, எனவே பெரும்பாலான harness-கள் அவற்றைத் தானாகவே எடுத்துக்கொள்ளும். அதே பெயருடன் உங்கள் சொந்த skill folder இருந்தால் அது முன்னுரிமை பெறும்.

ஆனால் நீங்கள் இந்த skill-களை பரிசோதனை எனக் கருத வேண்டும். வெவ்வேறு மாடல்கள் இதை வெவ்வேறு விளைவுக்குப் பயன்படுத்தும். முதலில் plan mode-இல் இயக்குவது சிறந்தது, எனவே agent என்ன மாற்ற விரும்புகிறது என்பது பற்றி உங்களுக்கு ஒரு யோசனை இருக்கும். மேலும் agent எல்லாவற்றையும் குழப்பினால், மாற்றங்களை rollback செய்ய அல்லது `omarchy reinstall configs` ஐ அழைக்கவும் தயாராக இருங்கள்.
