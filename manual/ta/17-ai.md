# AI

Omarchy உங்களுக்காக ஒரு இயல்புநிலையைத் தேர்ந்தெடுக்காமல், கீழே உள்ள கோடிங் ஏஜென்ட்களுக்கான லாஞ்சர்களை உள்ளடக்கியுள்ளது. முதல் முறை பயன்படுத்தும்போது அதன் CLI ஐ நிறுவ ஒரு கட்டளையை இயக்கவும், பின்னர் கேட்கும்போது அங்கீகரிக்கவும். Hermes விதிவிலக்கு: முதல் முறை பயன்படுத்தும்போது அதற்காக எதுவும் நிறுவப்படாது, அதைத் தேர்ந்தெடுப்பது Hermes Desktop ஐ நிறுவும், கீழே உள்ள _Desktop apps_ விளக்குவது போல.

### ஏஜென்ட்களை நிறுவுதல் மற்றும் புதுப்பித்தல்

Hermes ஐத் தவிர, இந்த ஏஜென்ட்கள் mise இன் lazy நிறுவலைப் பயன்படுத்துகின்றன: முதல் தொடக்கம் CLI ஐ நிறுவுகிறது, பிந்தைய தொடக்கங்கள் அதை மீண்டும் பயன்படுத்துகின்றன. mise மேலும் நிறுவப்பட்ட ஏஜென்டில் புதிய வெளியீடு உள்ளதா என நான்கு மணிநேரத்திற்கு ஒரு முறைக்கு மேல் சரிபார்க்காது, அது தொடங்குவதற்கு சற்று முன்பு அல்லது shell prompt இல் பின்னணியில். அந்தப் புதுப்பிப்பு தோல்வியடைந்தால் அல்லது நீங்கள் ஆஃப்லைனில் இருந்தால், நிறுவப்பட்ட பதிப்பு இயங்கும். `omarchy update` Omarchy இன் மற்ற பகுதிகளுடன் நிறுவப்பட்ட ஏஜென்ட்களையும் புதுப்பிக்கிறது, மற்றும் `mup` mise ஆல் நிர்வகிக்கப்படும் கருவிகளை மட்டும் புதுப்பிக்கிறது.

`claude update`, `codex update` போன்ற ஏஜென்டின் சொந்த updater, அல்லது ஒரு app இல் உள்ள புதுப்பிப்பு பொத்தான், mise ஆல் நிர்வகிக்கப்படும் நிறுவலைப் புதுப்பிக்காது. `codex update` தோல்வியடைகிறது, மற்றும் `claude update` வெற்றி என அறிவித்து, mise கண்காணிக்காத தனி நகலை நிறுவக்கூடும். நீங்கள் ஒரு ஏஜென்டின் சொந்த installer மற்றும் updater ஐப் பயன்படுத்த விரும்பினால், அதை `disable_tools` இல் சேர்க்கவும்; [Preinstalled CLI tools](18-development-tools.md#preinstalled-cli-tools) ஐப் பார்க்கவும்.

உங்களுக்குத் தேவைப்படுவதற்கு முன்பே கட்டமைக்கப்பட்ட அனைத்து lazy கருவிகளையும் நிறுவ, `mise install --include-lazy` ஐ இயக்கவும். இதில் ஏஜென்ட்களுடன் Omarchy இன் மற்ற இயல்புநிலை CLI கருவிகளும் அடங்கும். ஒரு கருவியை நிறுவுவது அல்லது உங்கள் சொந்த நிறுவலைப் பயன்படுத்துவது குறித்து [Preinstalled CLI tools](18-development-tools.md#preinstalled-cli-tools) ஐப் பார்க்கவும்.

`grok` mise இன் first-party `grok` package மூலம் நிறுவப்படுகிறது, `claude` மற்றும் `codex` போலவே. `grok` ஐ இயக்கவும், அல்லது _Setup > Defaults > Agent_ இன் கீழ் அதைத் தேர்ந்தெடுக்கவும். x.ai இல் உள்ள `curl | bash` installer ஐத் தவிர்க்கவும். அந்த வழி `~/.grok/bin` இல் இரண்டாவது நகலை வைக்கிறது, அதை `PATH` இல் முன்சேர்க்கிறது, மற்றும் Omarchy இன் wrapper ஐ மேலெழுதுகிறது.

`dsh` அதன் browser UI ஐ `127.0.0.1:3080` இல் திறக்கிறது, தொடக்க கோப்பகம் அதன் இயல்புநிலை workspace ஆக இருக்கும். அதன் browser UI தொடக்க prompt ஐ எடுக்காது, எனவே `omarchy agent prompt` உங்கள் clipboard இல் prompt உடன் ஒட்டுவதற்காக அதைத் திறக்கிறது. Omarchy அதை DeepSeek இன் no-approval permission preset உடன் தொடங்குகிறது. நீங்கள் அதன் அதிகாரப்பூர்வ மாடல் API ஐப் பயன்படுத்தும்போது DeepSeek Harness அமர்வு பதிவுகளை DeepSeek க்கு பதிவேற்றுகிறது; அதன் browser UI இல் _Settings > General > Upload Session Log_ இன் கீழ் அதை அணைக்கவும். நீங்கள் அதற்கு அனுப்பும் கருத்தும் அமர்வுடன் பதிவேற்றப்படும், நீங்கள் அதை `DSH_TELEMETRY_MODE=DISABLED` உடன் தொடங்கினால் தவிர.

### இயல்புநிலை ஏஜென்ட்

`omarchy default agent <name>` உடன் அல்லது Omarchy Menu (`Super + Space`) இல் _Setup > Defaults > Agent_ இன் கீழ் உங்கள் இயல்புநிலை ஏஜென்டைத் தேர்ந்தெடுக்கவும். ஏஜென்ட் இன்னும் நிறுவப்படவில்லை என்றால், அதைத் தேர்ந்தெடுப்பது முதலில் அதை நிறுவும். புதிய Omarchy ஒரு முறை அறிவிப்புடன் இந்தத் தேர்வைச் செய்ய உங்களை அழைக்கும்.

Claude ஐத் தேர்ந்தெடுப்பது Chromium, Chrome, Brave, Brave Origin, மற்றும் Edge க்கான அதன் browser extension ஐ அமைக்கவும் முயற்சிக்கிறது. Extension அமைப்பு அனைத்து பயனர்களுக்கும் பொருந்தும் மற்றும் உங்கள் system கடவுச்சொல்லைக் கேட்கலாம்; ரத்து செய்வது அல்லது extension நிறுவல் தோல்வியடைவது கூட Claude ஐத் தேர்ந்தெடுத்து தொடங்கும். உங்கள் browser ஐ மறுதொடக்கம் செய்யவும், கேட்கப்பட்டால் extension ஐ இயக்கவும், மற்றும் அதை இணைப்பதை முடிக்க Claude இல் உள்நுழையவும். இணைப்பைச் சரிபார்க்க Claude இல் `/chrome` ஐ இயக்கவும். Firefox மற்றும் Zen இந்த extension ஐ ஆதரிக்காது. இந்த அமைப்பு சேர்க்கப்படுவதற்கு முன்பே Claude ஏற்கனவே உங்கள் இயல்புநிலையாக இருந்தால், extension ஐ நிறுவ அதை மீண்டும் தேர்ந்தெடுக்கவும்.

நீங்கள் தேர்ந்தெடுத்த பிறகு, `Super + Shift + Ctrl + A` இயல்புநிலை ஏஜென்டை ஒரு பிரத்யேக terminal window இல் தொடங்குகிறது (அல்லது நீங்கள் இன்னும் தேர்ந்தெடுக்கவில்லை என்றால் picker ஐக் கொண்டு வருகிறது). நீங்கள் அதை `omarchy agent prompt "Review this project"` உடன் நேரடியாக ஒரு பணியில் தொடங்கவும் முடியும். Freebuff மற்றும் DeepSeek Harness தொடக்க prompt ஐ எடுக்காது, எனவே அவை அதற்கு பதிலாக உங்கள் clipboard இல் prompt உடன் ஒட்டுவதற்காகத் திறக்கும். இப்படித் தொடங்கப்படும் ஏஜென்ட்கள் அவற்றின் அந்தந்த don't-stop-to-ask பயன்முறைகளில் கவனிக்கப்படாமல் இயங்குகின்றன, எனவே அவை உண்மையில் விஷயங்களைச் செய்யத் தயாராக இருங்கள்! MiniMax Code அதன் ஊடாடும் அமர்வுகளுக்கு அத்தகைய பயன்முறை இல்லை, எனவே அது வழக்கம் போல் அனுமதிகளைக் கேட்கிறது. மேலும் ஏஜென்ட்கள் உங்கள் home கோப்பகத்திற்கான நம்பிக்கையை நினைவில் கொள்ள மறுப்பதால், `$HOME` இலிருந்து தொடங்குவது அதற்கு பதிலாக `~/Work` இல் தொடங்கும்.

Terminal குறுக்குவழிகளும் உள்ளன: `a` தற்போதைய terminal இல் இயல்புநிலை ஏஜென்டை inline ஆக இயக்குகிறது, அதே நேரத்தில் `c`, `cx`, மற்றும் `cy` OpenCode, Claude Code, மற்றும் Codex ஐ நேரடியாகத் தொடங்குகின்றன (மீண்டும் அவற்றின் auto-approving பயன்முறைகளில்). தீம் மாற்றங்களும் ஏஜென்ட்களுடன் ஒத்திசைகின்றன: நீங்கள் Omarchy தீமை மாற்றும்போது Claude Code, Pi, OpenCode, மற்றும் Hermes (Omarchy அதை நிறுவியவுடன்) அனைத்தும் பின்தொடர்கின்றன.

### ஏஜென்ட்கள் panel

மேல் பட்டியில் ஒரு agents ஐகான் உள்ளது. நீங்கள் ஒரு ஏஜென்டை அமைப்பதற்கு முன்பு, அதன் panel Claude, Codex, அல்லது Grok இல் உள்நுழைவதன் மூலம் உங்களை வழிநடத்துகிறது, மற்றும் முதல் ஒன்று உங்கள் இயல்புநிலை ஏஜென்ட் ஆகிறது. அதற்குப் பிறகு, panel ஒவ்வொரு சந்தாவையும் ஒரே பக்கத்தில் வைக்கிறது: ஒவ்வொரு ஏஜென்டும் கணக்கும் அதன் plan உடன், அதன் 5 மணிநேர அமர்வு மற்றும் வாராந்திர வரம்புகள் ஒவ்வொன்றிற்கும் ஒரு meter உடன் அது மீட்டமைக்கப்படும் வரையிலான நேரத்துடன் (சரியான சதவீதத்திற்கு hover செய்யவும்), அல்லது மீதமுள்ள முன்செலுத்தப்பட்ட இருப்பு, நீங்கள் அவை அனைத்திலும் பயன்படுத்தியதைச் சுழற்றும் ஒரு வரியின் கீழ், இந்த வாரம் tokens மற்றும் நீங்கள் அதிகம் பயன்படுத்திய மாடல் போன்றவை. _Make something_ இன் கீழ் இது புதிய தீம், plugin, அல்லது app க்கான starter prompt களை வழங்குகிறது, அவை பணியை உங்கள் இயல்புநிலை ஏஜென்டிடம் ஒப்படைக்கின்றன. App கள் Omarchy இன் சொந்த Hype, Monologue, மற்றும் Omacut போலவே, C++ மற்றும் Qt Quick இல், omarchy-app agent skill ஐப் பின்பற்றி உருவாக்கப்படுகின்றன, மேலும் அவற்றுக்குத் தேவையான compiler மற்றும் Qt பகுதிகள் நிறுவப்பட்டு வருகின்றன. Claude Code, Codex, Grok, Kimi, Cursor மற்றும் அதன் Grok Bot allowance, GitHub Copilot, Muse, Antigravity, Kimchi, மற்றும் Devin அவற்றின் வரம்புகளுடன் out of the box ஆக உள்ளடக்கப்பட்டுள்ளன, மற்றும் Hermes, Mistral Vibe, மற்றும் Qwen Code நீங்கள் அவற்றைப் பயன்படுத்தியவுடன் அவற்றின் அமர்வுகள் மற்றும் tokens ஐக் காட்டுகின்றன. நீங்கள் pi, omp, அல்லது opencode மூலம் பயன்படுத்தும் Provider plan கள் மற்றும் key களும் தோன்றும்: OpenCode Zen மற்றும் Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan, மற்றும் Synthetic அவற்றின் வரம்புகளுடன்; Fireworks, OpenRouter, மற்றும் DeepSeek அவற்றின் முன்செலுத்தப்பட்ட இருப்புகளுடன்; மற்றும் Local models இன் கீழ் உங்கள் சொந்த hardware இல் நீங்கள் இயக்கும் மாடல்கள். ஒவ்வொரு ஏஜென்டும் ஒரு முறை மட்டுமே கணக்கிடப்படுகிறது, அதற்கு யார் பில் செய்கிறார்களோ அவர்களின் கீழ், நீங்கள் அதை எத்தனை harness கள் மூலம் இயக்கினாலும்.

Panel க்கு bar ஐகானை இடது-கிளிக் செய்யவும், உங்கள் இயல்புநிலை ஏஜென்டைத் தொடங்க வலது-கிளிக் செய்யவும். அதன் பின்னால் உள்ள பயன்பாட்டுப் பதிவுகள் ஒவ்வொரு 15 நிமிடங்களுக்கும் `omarchy agent usage-update` ஆல் மீண்டும் உருவாக்கப்படுகின்றன, மேலும் panel ஒரு synced folder வழியாக உங்கள் மற்ற இயந்திரங்களிலிருந்து பயன்பாட்டை இணைக்கவும் முடியும். முழு அமைப்புகளுக்கு `$OMARCHY_PATH/shell/plugins/agents/` இன் கீழ் உள்ள README ஐப் பார்க்கவும்.

### பல சந்தாக்கள்

நீங்கள் ஒன்றுக்கு மேற்பட்ட Claude, Codex, அல்லது Grok plan க்கு பணம் செலுத்தினால் — தனிப்பட்ட Max மற்றும் வேலை ஒன்று என்று வைத்துக்கொள்வோம் — Omarchy அவை அனைத்தையும் உள்நுழைந்து வைத்து அவற்றுக்கிடையே நகர முடியும். agents panel இல் + உடன் ஒரு சந்தாவைச் சேர்க்கவும், அது அங்கேயே உங்களை அதன் மூலம் வழிநடத்தும், அல்லது `omarchy agent account add claude Work` (அல்லது `codex`, அல்லது `grok`) உடன். அது இல்லை என்றால் CLI ஐ நிறுவும். ஒரு provider க்கான முதல் கணக்கு உங்கள் சாதாரண browser மூலம் உள்நுழைகிறது, CLI எப்போதும் பார்க்கும் இடத்திலேயே. அதற்குப் பிறகு ஒவ்வொன்றும் ஒரு private window மூலம் உள்நுழைகிறது, எனவே உங்கள் browser ஏற்கனவே உள்நுழைந்துள்ள கணக்கு தவறுதலாக எடுக்கப்படாது; நீங்கள் சேர்க்கும் கணக்காக அங்கு உள்நுழையவும், மேலும் நீங்கள் ஏற்கனவே திறந்து வைத்திருந்த private window ஐ முதலில் மூடவும். இதைச் செய்ய CLI இலிருந்து ஒருபோதும் வெளியேற வேண்டாம்: வெளியேறுவது சேமிக்கப்பட்ட உள்நுழைவை ரத்து செய்கிறது, மற்றும் அந்தக் கணக்கை மீண்டும் சேர்க்க வேண்டியிருக்கும்.

உங்கள் சந்தா உள்நுழைவுகளை மற்றொரு Omarchy இயந்திரத்திற்கு SSH வழியாக நகலெடுக்க, `omarchy agent account copy user@laptop` ஐ இயக்கவும். இலக்கில் ஒன்று நிறுவப்படவில்லை என்றால் அனுப்புநர் தற்காலிக receiver ஐ வழங்குகிறார், எனவே பழைய Omarchy இயந்திரங்கள் புதுப்பிப்பு இல்லாமல் கணக்குகளைப் பெற முடியும். நிறுவப்பட்ட receiver கள் முன்னுரிமை பெறுகின்றன. இது அனைத்து Claude, Codex, மற்றும் Grok சந்தாக்களையும் நகலெடுக்கிறது; அவற்றைத் தேர்ந்தெடுக்க provider பெயர்களைச் சேர்க்கவும், `omarchy agent account copy laptop claude` இல் உள்ளது போல. கணக்குப் பெயர்கள் மற்றும் command ID கள் மூலத்துடன் பொருந்துகின்றன, இலக்கில் ஏற்கனவே உள்ள கணக்குகள் உட்பட. தொடர்பில்லாத இலக்குக் கணக்குகளின் பெயர்கள் முரண்பட்டால் எண் பின்னொட்டைப் பெறுகின்றன, மற்றும் அமைப்புகள், skills, plugins, மற்றும் உரையாடல் வரலாறு ஒவ்வொரு இயந்திரத்திற்கும் உள்ளூராகவே இருக்கும்.

ஏற்கனவே உள்ள இலக்கு credentials வைக்கப்படுகின்றன. அங்கு ஏற்கனவே உள்நுழைந்துள்ள ஒரு மூலக் கணக்கின் பெயர் அதன் credentials ஐ மாற்றாமல் ஒத்திசைக்கப்படுகிறது; மற்ற கணக்குகள் அதனுடன் சேர்க்கப்படுகின்றன. பொருந்தும் கணக்குகளுக்கான சேமிக்கப்பட்ட credentials ஐ மாற்ற, இலக்கில் அந்தக் கணக்கின் அமர்வுகளை விட்டு வெளியேறிய பிறகு `omarchy agent account copy --replace laptop claude` ஐப் பயன்படுத்தவும். புதிய இலக்கு மூலத்தின் செயலில் உள்ள கணக்கு மற்றும் மாற்றும் விருப்பங்களையும் பெறுகிறது; நிறுவப்பட்ட இலக்கு தன்னுடையதை வைத்திருக்கிறது.

Credentials SSH வழியாகப் பயணித்து இலக்கில் தனிப்பட்ட கோப்புகளில் சேமிக்கப்படுகின்றன, எனவே நீங்கள் நம்பும் இயந்திரங்களுக்கு மட்டும் நகலெடுக்கவும். இது ஒரு முறை நகல், தொடர்ச்சியான ஒத்திசைவு அல்ல. Codex refresh token கள் மற்றொரு இயந்திரத்தால் சுழற்றப்படலாம், நகலெடுக்கப்பட்ட உள்நுழைவுக்கு புதுப்பிப்பு தேவைப்படும்; பல இயந்திரங்களில் ஒரே நேரத்தில் பயன்படுத்த தனித்தனி உள்நுழைவுகளே மிகவும் நம்பகமான தேர்வாக இருக்கும். [Codex's account authentication guidance](https://developers.openai.com/codex/auth/ci-cd-auth) ஐப் பார்க்கவும்.

ஒரு provider க்கு ஒரு கணக்கு செயலில் உள்ளது, மேலும் ஒவ்வொரு புதிய அமர்வும் அதுவாகவே தொடங்குகிறது: `cx`, `cy`, ஒரு சாதாரண `claude`, `codex`, அல்லது `grok`, `omarchy agent` மூலம் தொடங்கப்படும் எதுவும், மற்றும் `PATH` இல் CLI ஐக் கண்டறியும் script கள் அல்லது editor கள். `omarchy agent account use work` உடன் மாற்றவும் (மற்றும் `omarchy agent account use main` உடன் திரும்பவும்), அல்லது panel இல் ஒரு கணக்கின் எண்ணை அழுத்தி பின்னர் `Enter` (அல்லது அதன் Use பொத்தானைக் கிளிக் செய்து). ஏற்கனவே இயங்கும் அமர்வுகள் அவை தொடங்கிய கணக்கிலேயே இருக்கும். உரையாடல் வரலாறு, அமைப்புகள், skills, மற்றும் plugins கணக்குகள் முழுவதும் பகிரப்படுகின்றன, எனவே அதே folder இல் `claude --continue` நீங்கள் புதிய கணக்கில் விட்ட இடத்திலிருந்து தொடர்கிறது.

ஒன்றுக்கு மேற்பட்ட கணக்குகளுடன், panel ஒவ்வொரு கணக்கின் வரம்புகளையும் அருகருகே காட்டுகிறது, செயலில் உள்ளது குறிக்கப்பட்டிருக்கும். இயல்பாக செயலில் உள்ள கணக்கு ஒரு வரம்பின் 95% ஐக் கடக்கும்போது Omarchy உங்களுக்கு அறிவிக்கிறது, மற்றும் அறிவிப்பைக் கிளிக் செய்வது அதிக headroom உள்ள கணக்கிற்கு மாற்றுகிறது. Panel இல் ஒரு கணக்கின் வரியில் hover செய்து Use இன் அருகில் தோன்றும் Autoswitch ஐக் கிளிக் செய்யவும் (அல்லது `m` ஐ அழுத்தவும்), அல்லது அது தானாகவே மாற `omarchy agent account mode auto` ஐ இயக்கவும்; அது இயக்கத்தில் இருக்கும்போது, Autoswitch Use இன் இடத்தை எடுக்கிறது, மேலும் அதை மீண்டும் கிளிக் செய்வது அறிவிப்பிற்குத் திரும்பும். வரம்பை மாற்ற ஒரு எண்ணைச் சேர்க்கவும், `omarchy agent account mode auto 90` இல் உள்ளது போல. ஒவ்வொரு கணக்கும் வரம்பை விட அதிகமாக இருந்தால், எந்தக் கணக்கு முதலில் விடுபடுகிறது என்பதுடன் ஒரு முறை உங்களுக்குத் தெரிவிக்கப்படும். செயலில் உள்ள கணக்கு அதன் வரம்பிலிருந்து 15 புள்ளிகளுக்குள் இருக்கும்போது (இயல்புநிலையில் 80%), அதன் வரம்புகள் ஒவ்வொரு 15 க்கு பதிலாக ஒவ்வொரு மூன்று நிமிடங்களுக்கும் சரிபார்க்கப்படுகின்றன.

`omarchy agent account list` ஒவ்வொரு கணக்கையும் அதன் சமீபத்திய வரம்புகளையும் காட்டுகிறது, `omarchy agent account remove work` ஒன்றை மறக்கிறது, மற்றும் `omarchy agent account rename primary Hey` ஒன்றின் பெயரை மாற்றுகிறது (அல்லது panel இல் ஒரு கணக்கின் பெயரைக் கிளிக் செய்யவும்). இந்தக் கட்டளைகள் உங்கள் இயல்புநிலை ஏஜென்டின் கணக்குகளில் வேலை செய்கின்றன; மற்ற provider ஐ அடைய, முதலில் அதைப் பெயரிடவும், `omarchy agent account use codex side` இல் உள்ளது போல. `~/.claude` அல்லது `~/.codex` இல் நீங்கள் ஏற்கனவே வைத்திருந்த உள்நுழைவு _Main_ கணக்கு மற்றும் அது இருக்கும் இடத்திலேயே இருக்கும். சுமார் எட்டு மணிநேரத்திற்கு மேல் பயன்படுத்தப்படாத கணக்கு _Sign-in required_ எனக் காட்டலாம்; panel இல் அந்தக் கணக்கில் மீண்டும் உள்நுழைய அதைக் கிளிக் செய்யவும், அல்லது அதில் ஒரு அமர்வைத் தொடங்கவும், அது தானாகவே உள்நுழைவைப் புதுப்பிக்கிறது. ஒரு கணக்கு சேர்க்கப்பட்டபோது நீங்கள் வைத்திருந்த MCP server கள் அதற்கு வருகின்றன, ஆனால் நீங்கள் பின்னர் `claude mcp add` உடன் சேர்ப்பவை நீங்கள் அவற்றைச் சேர்த்த கணக்கை மட்டுமே அடைகின்றன. Claude Desktop மற்றும் CLI binary க்கான absolute path உடன் கட்டமைக்கப்பட்ட கருவிகள் மாற்றத்தைப் பின்பற்றாது. வெளிப்படையான `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, அல்லது `GROK_HOME` தேர்ந்தெடுக்கப்பட்ட கணக்கை விட முன்னுரிமை பெறுகிறது.

### Crash கண்டறிதல்

Omarchy process crash களுக்காக systemd-coredump ஐக் கவனிக்கிறது. ஏதாவது segfault ஆகும்போது, உங்களுக்கு "Process crashed" அறிவிப்பு கிடைக்கும் — அதைக் கிளிக் செய்யவும், மற்றும் crash உங்கள் இயல்புநிலை ஏஜென்டிடம் Omarchy இன் diagnose-crash skill உடன் ஒப்படைக்கப்படுகிறது, இது core dump இலிருந்து உண்மைகளை நிறுவுவதன் மூலமும் crash upstream இல் அறிக்கையிடுவதற்கு மதிப்புள்ளதா என்பதைத் தீர்மானிப்பதன் மூலமும் ஏஜென்டை வழிநடத்துகிறது. நீங்கள் அதை `coredumpctl list` இலிருந்து எந்த PID க்கும் எதிராக `omarchy agent crash <pid>` உடன் கையாலும் இயக்கலாம்.

கவனிப்பது இயல்பாக இயக்கத்தில் உள்ளது. _Trigger > Toggle > Crash Capture_ இன் கீழ் (அல்லது `omarchy toggle crash-capture` உடன்) அதை அணைக்கவும், அறிவிப்புகள் நிற்கும்; `omarchy agent crash <pid>` இன்னும் கையால் வேலை செய்கிறது.

Crash களை ஒரு நேரத்தில் ஒரு program ஆகவும் அமைதிப்படுத்தலாம், இதைத்தான் கண்டறிதல் இறுதியில் உங்களுக்கு வழங்குகிறது. `omarchy crash mute hyprland` அந்த program க்கு மட்டும் அறிவிப்புகளை நிறுத்துகிறது, `omarchy crash mute hyprland off` அவற்றை மீண்டும் கொண்டு வருகிறது, மற்றும் `omarchy crash mute` தனியாக நீங்கள் முடக்கியதைப் பட்டியலிடுகிறது. இது binary இன் path ஐ அதன் பெயரைப் போலவே மகிழ்ச்சியுடன் எடுக்கிறது, எனவே `omarchy crash mute /usr/bin/hyprland` அதே வேலையைச் செய்கிறது. இடைவெளி உள்ள பெயரை மேற்கோள் காட்டவும், `omarchy crash mute 'Some App'` இல் உள்ளது போல. மற்ற அனைத்தும் இன்னும் அறிவிக்கின்றன, மற்றும் முடக்கப்பட்ட program இன்னும் crash ஆகிறது — இது நினைவூட்டலை மறைக்கிறது, இது எதையும் சரிசெய்யாது.

### Desktop apps

_Install > AI_ மெனு சில graphical AI app களையும் கொண்டுள்ளது: ChatGPT desktop app, Claude desktop app (Anthropic இன் Linux beta, Chat, Cowork, மற்றும் Claude Code tab களுடன்), xAI இன் மாடல்களுடன் அரட்டை அடிக்க Grok Bot, Herdr Desktop, Hermes Desktop, OpenClaw, Perplexity desktop app, மற்றும் T3 Code. Grok Bot என்பது desktop chat app. கோடிங் ஏஜென்ட் `grok` கட்டளை.

Hermes Desktop தான் தெரிந்து கொள்ள வேண்டியது, ஏனெனில் ஒரு இயந்திரத்தில் ஒரு Hermes உள்ளது, மற்றும் அது app இனுடையது: Hermes எப்போதும் app மூலம் மட்டுமே நிறுவப்படுகிறது, மற்றும் இயல்புநிலை ஏஜென்ட் இயக்கும் `hermes` கட்டளை app இனுடையது. Hermes ஐ இயல்புநிலை ஏஜென்டாகத் தேர்ந்தெடுப்பது _Install > AI_ உள்ளீடு செய்வதையே நிறுவுகிறது: package, மற்றும் Hermes இன் சொந்த installer ஆல் அமைக்கப்பட்ட `~/.hermes` இன் கீழ் ஒரு Hermes runtime, இது முதல் முறை சில நிமிடங்கள் எடுக்கும். அந்த runtime தான் terminal `hermes` கட்டளை, இயல்புநிலை ஏஜென்ட் மற்றும் app அனைத்தும் பயன்படுத்தும் ஒரே Hermes, மற்றும் இது Omarchy வெளியீட்டிற்காகக் காத்திராமல் `hermes update` உடன் தன்னைப் புதுப்பிக்கிறது. அதை நிறுவுவது Hermes க்கு Omarchy தீமை `omarchy` என்ற பெயரிடப்பட்ட skin ஆகவும் வழங்குகிறது, இதை நீங்கள் தீம்களை மாற்றும்போது ஒவ்வொரு Hermes மேற்பரப்பும் பின்பற்றுகிறது; நீங்கள் அது வேண்டாம் என்றால் Hermes இன் Appearance அமைப்புகளின் கீழ் அல்லது `/skin` உடன் மற்றொன்றைத் தேர்ந்தெடுக்கவும், மற்றும் Omarchy அந்தத் தேர்வை அப்படியே விட்டுவிடுகிறது. _Remove > AI_ இன் கீழ் app ஐ அகற்றுவது முதலில் Hermes ஐ மூடுகிறது, gateway உட்பட, அந்த runtime ஐ அதனுடன் எடுக்கிறது, மற்றும் நீங்கள் வேறுவிதமாகச் சொல்லாவிட்டால் உங்கள் அரட்டைகள், நினைவுகள், மற்றும் Hermes தனக்காக எழுதிய skills ஐ வைத்திருக்கிறது: அந்தத் தரவும் உங்கள் இணைப்பு அமைப்புகளும் போக வேண்டுமா என அது கேட்கிறது, இயல்பாக இல்லை.

OpenClaw இன் desktop அனுபவம் அதன் Control UI, இது அதன் சொந்த உள்ளூர் gateway ஆல் ஆதரிக்கப்படும் web app ஆகத் திறக்கிறது. OpenClaw `~/.openclaw` இல் வாழ்கிறது மற்றும் தன்னைப் புதுப்பிக்கிறது: Control UI இன் "Update Gateway" பொத்தானைப் பயன்படுத்தவும் அல்லது `openclaw update` ஐ இயக்கவும், மற்றும் gateway புதிய பதிப்பில் மறுதொடக்கம் செய்யும். Omarchy புதிய நிறுவல் தொடங்கும் வெளியீட்டை மட்டுமே தேர்ந்தெடுக்கிறது. _Remove > AI_ இன் கீழ் OpenClaw ஐ அகற்றுவது gateway service மற்றும் app ஐ அதனுடன் எடுக்கிறது, பின்னர் `~/.openclaw` போக வேண்டுமா எனக் கேட்கிறது, ஏனெனில் அது உங்கள் அரட்டைகள் மற்றும் credentials ஐ OpenClaw உடன் மற்றும் அது பதிவிறக்கும் plugin runtime களுடன் வைத்திருக்கிறது; இயல்புநிலை அதை வைத்திருக்கிறது, மேலும் OpenClaw ஐ மீண்டும் நிறுவுவது அதை மீண்டும் எடுக்கிறது.

Herdr Desktop என்பது [Herdr](https://herdr.dev) desktop app: நீங்கள் window ஐ மூடும்போது அதன் core இல் தொடர்ந்து இயங்கும் terminal கள் மற்றும் கோடிங் ஏஜென்ட்களின் spaces, tab கள், மற்றும் pane கள். இது ஒரு package ஐ விட Herdr இன் சொந்த installer இலிருந்து வருகிறது, எனவே இது `~/.local/share/herdr-app` இல் வாழ்கிறது, உங்களிடம் ஏற்கனவே ஒன்று இல்லாதபோது அதன் core ஐ `~/.local/bin/herdr-core` இல் கொண்டு வருகிறது, மற்றும் இரண்டையும் தன்னைப் புதுப்பிக்கிறது. இது Omarchy `Super + Ctrl + Return` இல் வழங்கும் `herdr` கட்டளையை மாற்றாமல் அதன் அருகில் அமர்கிறது, மற்றும் அந்தக் கட்டளையின் நேரடி key களைப் பெறுகிறது: `Alt + Return` மற்றும் `Alt + Shift + Return` ஒரு pane ஐ கீழே அல்லது வலதுபுறம் பிரிக்கின்றன, `Alt + Escape` அதை மூடுகிறது, `Ctrl + Alt + Arrow` pane களுக்கிடையே நகர்கிறது, `Alt + 1..9` மற்றும் `Alt + Left/Right` ஒரு tab ஐத் தேர்ந்தெடுக்கின்றன, மற்றும் `Alt + Up/Down` space களுக்கிடையே நகர்கின்றன. `Ctrl + 1..9` ஒரு space ஐத் தேர்ந்தெடுக்கிறது மற்றும் `Alt + Shift + Up/Down` ஏஜென்ட்கள் வழியாகச் செல்கிறது. `Ctrl + Space` prefix key கள் terminal க்கு மட்டுமே இருக்கும், ஏனெனில் app ஒரு வரிசைக்காக சாதாரண Ctrl key ஐ வைத்திருக்க முடியாது. Omarchy இவற்றை `~/.config/herdr-app/keys.json` இல் எழுதுகிறது, மற்றும் `omarchy-refresh-herdr-app` அவற்றை மீண்டும் வைக்கிறது. அதை நிறுவுவது Herdr இன் Omarchy தீமைத் தேர்ந்தெடுக்கிறது, இது அதன் பிறகு உங்கள் Omarchy தீமைப் பின்பற்றுகிறது. Herdr light mode க்கு ஒரு தீமையும் dark க்கு ஒன்றையும் வைத்திருக்கிறது, எனவே dark மற்றும் light Omarchy தீமுக்கிடையே மாறிய பிறகு, மற்ற பயன்முறைக்காக Herdr இன் தீம் picker இல் Omarchy ஐ மீண்டும் ஒரு முறை தேர்ந்தெடுக்கவும்.

T3 Code அதன் அதிகாரப்பூர்வ AppImage வெளியீட்டிலிருந்து ஒரு package ஐ விட `~/.local/share/t3code` இல் இயங்குகிறது, எனவே இது தன்னைப் புதுப்பிக்கிறது. அதை நிறுவுவது Stable அல்லது Nightly channel இல் தொடங்க வேண்டுமா எனக் கேட்கிறது; பின்னர் T3 Code இன் அமைப்புகளில் மாற்றவும். உங்கள் thread கள் மற்றும் அமைப்புகள் `~/.t3` இல் வாழ்கின்றன, மற்றும் _Remove > AI_ இன் கீழ் T3 Code ஐ அகற்றுவது அவற்றை அதனுடன் எடுக்கிறது.

### Local மாடல்கள்

உங்கள் கோடிங் ஏஜென்ட்களுக்காக உங்கள் சொந்த இயந்திரத்தில் ஒரு திறந்த மாடலை இயக்கவும். உங்கள் prompt கள் மற்றும் குறியீடு இயந்திரத்திலேயே இருக்கும்; மாடலுக்கு அனுப்பப்படும் எதுவும் அதை விட்டு வெளியேறாது. இதனுடன் தொடங்கவும்:

```bash
omarchy agent local use best
```

அல்லது, மேல் பட்டியில் உள்ள agents panel இல், + ஐத் தேர்ந்தெடுத்து பின்னர் Local AI ஐத் தேர்ந்தெடுக்கவும், இது ஒரு மாடல் இந்த இயந்திரத்திற்குப் பொருந்தும்போது தோன்றும். முதல் முறை, இது மாடல்களை இயக்கும் Podman ஐ நிறுவுகிறது, மற்றும் NVIDIA இயந்திரத்தில் NVIDIA இன் container toolkit ஐ நிறுவுகிறது, இது அவற்றுக்கு GPU ஐ வழங்குகிறது. Omarchy பின்னர் இந்த இயந்திரத்திற்கு பரிந்துரைக்கப்பட்ட மாடலைத் தேர்ந்தெடுத்து, அதைப் பதிவிறக்கி, தொடங்குகிறது. பத்துகள் GB பதிவிறக்கத்தையும் மாடல் இயங்கும்போது இயந்திரத்தின் பெரும்பாலான நினைவகம் பயன்பாட்டில் இருப்பதையும் எதிர்பார்க்கவும்: Flash Next அதன் முழு 256K context உடன் சுமார் 100 GiB ஐப் பயன்படுத்துகிறது. மற்ற மாடல்கள் அதற்குத் தேவையான நினைவகத்தை வைத்திருந்தால், அது நிறுத்தப்பட்டு அமைக்கப்படுகிறது, நீங்கள் ஒன்றை நிறுத்தியவுடன் தொடங்கத் தயாராக உள்ளது. மாடல் வெளியேறும்போது நிற்கிறது; உங்களுக்கு வேறு ஏதாவதுக்கு நினைவகம் தேவைப்படும்போது அதை நீங்களே நிறுத்தவும்.

`omarchy agent local list` விருப்பங்களைக் காட்டுகிறது மற்றும் சில ஏன் பொருந்தவில்லை என்பதை விளக்குகிறது. மற்றொன்றை அமைக்க, `omarchy agent local use <recipe>` ஐ இயக்கவும். இன்று, 128 GB Strix Halo இயந்திரங்களுக்கு `qwen3.8-flash-next-gufo` மற்றும் `qwen3.8-27b-gufo` கிடைக்கின்றன; 27B சுமார் 40 GiB எடுக்கிறது, எனவே இது மற்ற வேலைகளுக்கு இடம் விடுகிறது. புதிய recipe கள் மற்றும் பரிந்துரைகள் package மூலம் `omarchy update` உடன் வருகின்றன.

நீங்கள் அமைக்கும் ஒவ்வொரு மாடலுக்கும் agents panel இல், உங்கள் சந்தாக்களுக்கு அருகில், அதன் சொந்த வரி கிடைக்கிறது: அதைத் தொடங்க play, அதை நிறுத்தி அதன் நினைவகத்தை விடுவிக்க pause, மற்றும் அதில் உங்கள் ஏஜென்டைத் திறக்க terminal பொத்தான். அவை நினைவகத்தில் ஒன்றாகப் பொருந்தும்போது பல ஒரே நேரத்தில் இயங்க முடியும்; ஒன்று பொருந்தவில்லை என்றால், எந்த இயங்கும் மாடலை நிறுத்த வேண்டும் என Omarchy கூறுகிறது. அவற்றை மறுவரிசைப்படுத்த வரிகளை இழுக்கவும், மற்றும் ஒரு மாடலையும் அதன் பதிவிறக்கத்தையும் அகற்ற தேர்ந்தெடுக்கப்பட்ட வரியில் Delete ஐ அழுத்தவும்.

கட்டளை வரியிலிருந்து, `omarchy agent local start <recipe>` மற்றும் `omarchy agent local stop <recipe>` அதையே செய்கின்றன, `omarchy agent local status` ஒவ்வொரு மாடலையும் காட்டுகிறது, மற்றும் `omarchy agent --local` நீங்கள் கடைசியாகத் தொடங்கிய மாடலில் உங்கள் இயல்புநிலை ஏஜென்டைத் திறக்கிறது (உங்கள் இயல்புநிலை ஏஜென்ட் local மாடலைப் பயன்படுத்த முடியாவிட்டால் pi). எந்த OpenAI-இணக்கமான client உம் இணைக்க முடியும்: `status` ஒவ்வொரு மாடலின் முகவரியையும் காட்டுகிறது (முதல் ஒன்று `http://127.0.0.1:11435/v1`), recipe பெயர் தான் மாடல், மற்றும் key `~/.config/omarchy/agent-local/key` இல் உள்ளது.

`omarchy agent local remove <recipe>` ஒரு மாடலையும் மற்ற எந்த மாடலும் பயன்படுத்தாத பதிவிறக்கங்களையும் நீக்குகிறது.

Third-party runtime கள் அவற்றின் வெளியீட்டாளருடன் லேபிளிடப்பட்டுள்ளன. Omarchy ஒவ்வொரு மாடலையும் network அணுகல் இல்லாமல் இயக்குகிறது.

### Local LLM கள்

Omarchy local LLM மாடல்களை இயக்க இரண்டு வழிகளைப் பரிந்துரைக்கிறது: LM Studio மற்றும் Ollama. LM Studio open-weight மாடல்களைக் கண்டறிய, அவற்றை நிறுவ, மற்றும் அவற்றை இயக்க GUI interface ஐ வழங்குகிறது. இது எளிதாகத் தொடங்க ஒரு சிறந்த வழி. Ollama இதேபோல் செய்ய CLI ஐ வழங்குகிறது. ஆனால் நீங்கள் local மாடல்களுக்குப் புதியவர் என்றால், நான் LM Studio உடன் தொடங்குவேன். Omarchy Menu இல் _Install > AI_ இன் கீழ் இரண்டில் ஒன்றையும் நிறுவலாம்.

### Omarchy Skill

Agent skill கள் AI குறிப்பிட்ட கருவிகளை ஒரு குறிப்பிட்ட வழியில் பயன்படுத்த உதவுகின்றன, மற்றும் Omarchy system ஐத் தனிப்பயனாக்க ஒரு இயல்புநிலை skill உடன் வருகிறது. உங்கள் Hyprland config ஐ மாற்றுவது, பட்டியை சரிசெய்வது, அல்லது புதிதாக ஒரு புதிய தீமை உருவாக்குவது போன்றவை. இது Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` மற்றும் ஒவ்வொரு `~/.hermes/profiles/*/skills`), மற்றும் பொதுவான `~/.agents/skills` இடத்திற்கான skill கோப்பகங்களில் symlinked செய்யப்பட்டுள்ளது, எனவே பெரும்பாலான harness கள் அதைத் தானாகவே எடுக்கின்றன.

ஆனால் நீங்கள் இந்த skill ஐ சோதனை எனக் கருத வேண்டும். வெவ்வேறு மாடல்கள் அதை வெவ்வேறு விளைவுகளுக்குப் பயன்படுத்தும். முதலில் plan mode இல் இயக்குவது சிறந்தது, எனவே ஏஜென்ட் என்ன மாற்ற விரும்புகிறது என்பது பற்றிய யோசனை உங்களுக்கு இருக்கும். பின்னர் மாற்றங்களை rollback செய்ய அல்லது ஏஜென்ட் எல்லாவற்றையும் குழப்பினால் `omarchy reinstall configs` ஐ அழைக்கவும் தயாராக இருங்கள்.
