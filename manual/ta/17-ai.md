Omarchy, உங்களுக்காக ஒரு இயல்புநிலையைத் தேர்ந்தெடுக்காமல், கீழே உள்ள கோடிங் ஏஜென்ட்களுக்கான லாஞ்சர்களை உள்ளடக்கியுள்ளது. ஒரு கட்டளையை இயக்கினால் முதல் பயன்பாட்டில் அதன் CLI நிறுவப்படும், பின்னர் கேட்கப்படும்போது அங்கீகரிக்கவும். Hermes இதற்கு விதிவிலக்கு: முதல் பயன்பாட்டில் அதற்காக எதுவும் நிறுவப்படாது, அதைத் தேர்ந்தெடுப்பது Hermes Desktop ஐ நிறுவும், கீழே உள்ள _Desktop apps_ விளக்குவது போல.

### ஏஜென்ட்களை நிறுவுதல் மற்றும் புதுப்பித்தல்

Hermes தவிர, இந்த ஏஜென்ட்கள் mise இன் lazy நிறுவலைப் பயன்படுத்துகின்றன: முதல் தொடக்கம் CLI ஐ நிறுவும், பின்னர் வரும் தொடக்கங்கள் அதையே மீண்டும் பயன்படுத்தும். நிறுவப்பட்ட ஏஜென்ட்டிற்கு புதிய வெளியீடு உள்ளதா என mise அதிகபட்சம் நான்கு மணிநேரத்திற்கு ஒருமுறை சரிபார்க்கும், அது தொடங்குவதற்குச் சற்று முன்பு அல்லது shell prompt இல் பின்னணியில். அந்தப் புதுப்பிப்பு தோல்வியடைந்தால் அல்லது நீங்கள் offline இல் இருந்தால், நிறுவப்பட்ட பதிப்பு இயங்கும். `omarchy update` நிறுவப்பட்ட ஏஜென்ட்களை Omarchy இன் மற்ற பகுதிகளுடன் சேர்த்துப் புதுப்பிக்கும், மற்றும் `mup` mise நிர்வகிக்கும் கருவிகளை மட்டும் புதுப்பிக்கும்.

ஒரு ஏஜென்ட்டின் சொந்த updater, எடுத்துக்காட்டாக `claude update`, `codex update`, அல்லது ஒரு செயலியில் உள்ள update பொத்தான், mise நிர்வகிக்கும் நிறுவலைப் புதுப்பிக்காது. `codex update` தோல்வியடையும், மற்றும் `claude update` வெற்றி என அறிவித்தாலும் mise கண்காணிக்காத தனி நகலை நிறுவக்கூடும். நீங்கள் ஒரு ஏஜென்ட்டின் சொந்த நிறுவி மற்றும் updater ஐப் பயன்படுத்த விரும்பினால், அதை `disable_tools` இல் சேர்க்கவும்; [Preinstalled CLI tools](18-development-tools.md#preinstalled-cli-tools) ஐப் பார்க்கவும்.

உங்களுக்குத் தேவைப்படுவதற்கு முன்பே கட்டமைக்கப்பட்ட அனைத்து lazy கருவிகளையும் நிறுவ, `mise install --include-lazy` ஐ இயக்கவும். இதில் ஏஜென்ட்களுடன் Omarchy இன் மற்ற இயல்புநிலை CLI கருவிகளும் அடங்கும். ஒரு தனி கருவியை நிறுவ அல்லது உங்கள் சொந்த நிறுவலைப் பயன்படுத்த [Preinstalled CLI tools](18-development-tools.md#preinstalled-cli-tools) ஐப் பார்க்கவும்.

`grok` என்பது `claude` மற்றும் `codex` போலவே, mise இன் first-party `grok` package மூலம் நிறுவப்படுகிறது. `grok` ஐ இயக்கவும், அல்லது _Agent > Harness_ இன் கீழ் அதைத் தேர்ந்தெடுக்கவும். x.ai இல் உள்ள `curl | bash` நிறுவியைத் தவிர்க்கவும். அந்த வழி இரண்டாவது நகலை `~/.grok/bin` இல் வைக்கும், அதை `PATH` இல் முன்னால் சேர்க்கும், மற்றும் Omarchy இன் wrapper ஐ மேலெழுதும்.

`dsh` அதன் browser UI ஐ `127.0.0.1:3080` இல் திறக்கும், தொடக்க அடைவையே அதன் இயல்புநிலை workspace ஆகக் கொண்டு. அதன் browser UI தொடக்க prompt ஐ ஏற்காது, எனவே `omarchy agent prompt` அதை உங்கள் clipboard இல் உள்ள prompt உடன் ஒட்டுவதற்காகத் திறக்கும். Omarchy அதை DeepSeek இன் no-approval permission preset உடன் தொடங்குகிறது. நீங்கள் அதன் அதிகாரப்பூர்வ model API ஐப் பயன்படுத்தும்போது DeepSeek Harness அமர்வு பதிவுகளை DeepSeek க்குப் பதிவேற்றும்; அதன் browser UI இல் _Settings > General > Upload Session Log_ இன் கீழ் அதை அணைக்கவும். நீங்கள் அதற்கு அனுப்பும் கருத்தும் அமர்வுடன் பதிவேற்றப்படும், நீங்கள் அதை `DSH_TELEMETRY_MODE=DISABLED` உடன் தொடங்காவிட்டால்.

### இயல்புநிலை ஏஜென்ட்

`omarchy default agent <name>` மூலம் அல்லது Omarchy Menu (`Super + Space`) இல் _Agent > Harness_ இன் கீழ் உங்கள் இயல்புநிலை ஏஜென்ட்டைத் தேர்ந்தெடுக்கவும். ஏஜென்ட் இன்னும் நிறுவப்படவில்லை என்றால், அதைத் தேர்ந்தெடுப்பது முதலில் அதை நிறுவும். புதிய Omarchy ஒருமுறை மட்டும் வரும் அறிவிப்புடன் இந்தத் தேர்வைச் செய்ய உங்களை அழைக்கும்.

Claude ஐத் தேர்ந்தெடுப்பது Chromium, Chrome, Brave, Brave Origin, மற்றும் Edge க்கான அதன் browser extension ஐ அமைக்கவும் முயற்சிக்கும். Extension அமைப்பு அனைத்து பயனர்களுக்கும் பொருந்தும் மற்றும் உங்கள் system password ஐக் கேட்கக்கூடும்; ரத்து செய்தாலும் அல்லது extension நிறுவல் தோல்வியடைந்தாலும் Claude தேர்ந்தெடுக்கப்பட்டு தொடங்கப்படும். உங்கள் browser ஐ மறுதொடக்கம் செய்யவும், கேட்கப்பட்டால் extension ஐ இயக்கவும், மற்றும் அதை இணைப்பதை முடிக்க Claude இல் உள்நுழையவும். இணைப்பைச் சரிபார்க்க Claude இல் `/chrome` ஐ இயக்கவும். Firefox மற்றும் Zen இந்த extension ஐ ஆதரிக்காது. இந்த அமைப்பு சேர்க்கப்படுவதற்கு முன்பே Claude உங்கள் இயல்புநிலையாக இருந்திருந்தால், extension ஐ நிறுவ அதை மீண்டும் தேர்ந்தெடுக்கவும்.

நீங்கள் தேர்ந்தெடுத்த பிறகு, `Super + Shift + Ctrl + A` உங்கள் இயல்புநிலை ஏஜென்ட்டை ஒரு பிரத்யேக terminal window இல் தொடங்கும் (அல்லது நீங்கள் இன்னும் தேர்ந்தெடுக்கவில்லை என்றால் picker ஐக் கொண்டுவரும்). `omarchy agent prompt "Review this project"` மூலம் அதை நேரடியாக ஒரு பணியிலும் தொடங்கலாம். Freebuff மற்றும் DeepSeek Harness தொடக்க prompt ஐ ஏற்காது, எனவே அவை அதற்குப் பதிலாக உங்கள் clipboard இல் உள்ள prompt ஐ ஒட்டுவதற்காகத் திறக்கும். இவ்வாறு தொடங்கப்படும் ஏஜென்ட்கள் அவற்றின் அந்தந்த don't-stop-to-ask முறைகளில் கவனிக்கப்படாமல் இயங்கும், எனவே அவை உண்மையில் செயல்களைச் செய்யத் தயாராக இருங்கள்! MiniMax Code இன் ஊடாடும் அமர்வுகளுக்கு அத்தகைய முறை இல்லை, எனவே அது வழக்கம் போல அனுமதிகளைக் கேட்கும். மேலும் ஏஜென்ட்கள் உங்கள் home directory க்கான trust ஐ நினைவில் கொள்ள மறுப்பதால், `$HOME` இலிருந்து தொடங்குவது அதற்குப் பதிலாக `~/Work` இல் தொடங்கும்.

terminal குறுக்குவழிகளும் உள்ளன: `a` தற்போதைய terminal இல் இயல்புநிலை ஏஜென்ட்டை inline ஆக இயக்கும், அதே நேரத்தில் `c`, `cx`, மற்றும் `cy` OpenCode, Claude Code, மற்றும் Codex ஐ நேரடியாகத் தொடங்கும் (மீண்டும் அவற்றின் auto-approving முறைகளில்). Theme மாற்றங்களும் ஏஜென்ட்களுக்கு ஒத்திசைகின்றன: Claude Code, Pi, OpenCode, மற்றும் Hermes (Omarchy அதை நிறுவிய பிறகு) அனைத்தும் நீங்கள் Omarchy theme ஐ மாற்றும்போது அதைப் பின்பற்றும்.

### உங்கள் ஏஜென்ட் வழிமுறைகள்

ஒவ்வொரு ஏஜென்ட்டுக்குமான தனிப்பட்ட விதிகள் `~/.agents/AGENTS.md` இல், `~/.agents/skills` இல் உள்ள பகிரப்பட்ட skills க்கு அருகில் இருக்கும். அதை _Agent > Instructions_ இன் கீழ் திறக்கவும், இது தனது சொந்த global கோப்பை வைத்திருக்கும் ஒவ்வொரு harness இலும் அதை இணைக்கும்: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, Copilot இன் `~/.copilot/copilot-instructions.md`, மற்றும் பல. Crush மற்றும் Amp `~/.config/AGENTS.md` இணைப்பைப் படிக்கும், அதே நேரத்தில் omp, Kimi, மற்றும் DeepSeek Harness `~/.agents/AGENTS.md` ஐ நேரடியாகப் படிக்கும். இயல்புநிலை ஏஜென்ட்டைத் தேர்ந்தெடுப்பதும் அதை இணைக்கும். உங்களிடம் ஏற்கனவே இருந்த ஒரு instructions கோப்பு, இன்னும் பகிரப்பட்டது இல்லை என்றால் அதுவே பகிரப்பட்டதாக மாறும்; இல்லையெனில் அது இணைப்புக்கு அருகில் `.bak` ஆக வைக்கப்படும். மற்றொரு ஏஜென்ட்டை நிறுவிய பிறகு மீண்டும் இணைக்க `omarchy agent instructions` ஐ இயக்கவும்.

### ஏஜென்ட்கள் பேனல்

மேல் பட்டியில் ஒரு agents ஐகான் உள்ளது. நீங்கள் ஒரு ஏஜென்ட்டை அமைப்பதற்கு முன்பு, அதன் பேனல் Claude, Codex, அல்லது Grok இல் உள்நுழைவதற்கு உங்களை வழிநடத்தும், மற்றும் முதலாவது உங்கள் இயல்புநிலை ஏஜென்ட்டாக மாறும். அதன் பிறகு, பேனல் ஒவ்வொரு சந்தாவையும் ஒரே பக்கத்தில் வைக்கிறது: ஒவ்வொரு ஏஜென்ட் மற்றும் கணக்கும் அதன் திட்டத்துடன், அதன் 5 மணிநேர அமர்வு மற்றும் வாராந்திர வரம்புகள் ஒவ்வொன்றுக்கும் அது மீட்டமைக்கப்படும் வரையிலான நேரத்துடன் ஒரு மீட்டர் (சரியான சதவீதத்திற்கு hover செய்யவும்), அல்லது மீதமுள்ள prepaid இருப்பு, அவை அனைத்திலும் நீங்கள் பயன்படுத்தியதைச் சுழற்சியாகக் காட்டும் ஒரு வரியின் கீழ், இந்த வாரத்தின் tokens மற்றும் நீங்கள் அதிகம் பயன்படுத்திய மாடல் போன்றவை. _Make something_ இன் கீழ் இது உங்கள் இயல்புநிலை ஏஜென்ட்டிடம் பணியை ஒப்படைக்கும் புதிய theme, plugin, app, அல்லது game க்கான starter prompts ஐ வழங்குகிறது. Apps, Omarchy இன் சொந்த Hype, Monologue, மற்றும் Omacut போலவே, C++ மற்றும் Qt Quick இல், omarchy-app agent skill ஐப் பின்பற்றி உருவாக்கப்படுகின்றன, மற்றும் அவற்றுக்குத் தேவையான compiler மற்றும் Qt பகுதிகள் நிறுவப்பட்டு வருகின்றன. Games என்பவை `~/Games/vibes` இல் உள்ள ஒரு single three.js பக்கம், web-game agent skill ஐப் பின்பற்றி, மற்றும் அனைத்தும் தற்போதைய theme இல் ஒரு Game Vibes launcher இலிருந்து திறக்கும்; அவை three.js ஐ web இலிருந்து ஏற்றுகின்றன, எனவே தொடங்குவதற்கு அவற்றுக்கு ஒரு இணைப்பு தேவை. Claude Code, Codex, Grok, Kimi, Cursor மற்றும் அதன் Grok Bot allowance, GitHub Copilot, Muse, Antigravity, Kimchi, மற்றும் Devin ஆகியவை அவற்றின் வரம்புகளுடன் நேரடியாகவே உள்ளடக்கப்படுகின்றன, மற்றும் Hermes, Mistral Vibe, மற்றும் Qwen Code நீங்கள் அவற்றைப் பயன்படுத்திய பிறகு அவற்றின் அமர்வுகள் மற்றும் tokens ஐக் காட்டுகின்றன. pi, omp, அல்லது opencode மூலம் நீங்கள் பயன்படுத்தும் Provider திட்டங்கள் மற்றும் keys உம் தெரிகின்றன: OpenCode Zen மற்றும் Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan, மற்றும் Synthetic அவற்றின் வரம்புகளுடன்; Fireworks, OpenRouter, மற்றும் DeepSeek அவற்றின் prepaid இருப்புகளுடன்; மற்றும் Local models இன் கீழ் உங்கள் சொந்த hardware இல் நீங்கள் இயக்கும் மாடல்கள். ஒவ்வொரு ஏஜென்ட்டும் ஒருமுறை மட்டுமே கணக்கிடப்படுகிறது, அதற்கு யார் bill செய்கிறாரோ அவரின் கீழ், நீங்கள் அதை எத்தனை harness கள் மூலம் இயக்கினாலும்.

பேனலுக்கு பட்டி ஐகானை இடது-கிளிக் செய்யவும், உங்கள் இயல்புநிலை ஏஜென்ட்டைத் தொடங்க வலது-கிளிக் செய்யவும். அதன் பின்னால் உள்ள பயன்பாட்டுப் பதிவுகள் ஒவ்வொரு 15 நிமிடங்களுக்கும் `omarchy agent usage-update` மூலம் மீண்டும் உருவாக்கப்படுகின்றன, மற்றும் பேனல் ஒரு synced கோப்புறை வழியாக உங்கள் மற்ற இயந்திரங்களிலிருந்து பயன்பாட்டைக் கூட இணைக்க முடியும். முழு அமைப்புகளுக்கு `$OMARCHY_PATH/shell/plugins/agents/` இன் கீழ் உள்ள README ஐப் பார்க்கவும்.

### பல சந்தாக்கள்

நீங்கள் ஒன்றுக்கு மேற்பட்ட Claude, Codex, அல்லது Grok திட்டத்திற்குப் பணம் செலுத்தினால் — எடுத்துக்காட்டாக ஒரு தனிப்பட்ட Max மற்றும் ஒரு வேலைக்கானது எனச் சொல்லலாம் — Omarchy அவை அனைத்தையும் உள்நுழைந்த நிலையில் வைத்திருக்கவும் அவற்றுக்கிடையே நகரவும் முடியும். agents பேனலில் உள்ள + மூலம் ஒரு சந்தாவைச் சேர்க்கவும், இது அங்கேயே உங்களை அதன் வழியாக நடத்தும், அல்லது `omarchy agent account add claude Work` (அல்லது `codex`, அல்லது `grok`) மூலம். அது இல்லையென்றால் CLI ஐ நிறுவும். ஒரு provider க்கான முதல் கணக்கு உங்கள் சாதாரண browser மூலம், CLI எப்போதும் பார்க்கும் இடத்திலேயே உள்நுழைகிறது. அதற்குப் பிறகு வரும் ஒவ்வொன்றும் ஒரு private window மூலம் உள்நுழைகிறது, எனவே உங்கள் browser ஏற்கனவே உள்நுழைந்துள்ள கணக்கு தவறுதலாக எடுக்கப்படாது; நீங்கள் சேர்க்கும் கணக்காக அங்கு உள்நுழையவும், மற்றும் நீங்கள் ஏற்கனவே திறந்து வைத்திருந்த எந்த private window வையும் முதலில் மூடவும். இதைச் செய்ய ஒருபோதும் CLI இலிருந்து வெளியேற வேண்டாம்: வெளியேறுவது சேமிக்கப்பட்ட உள்நுழைவை ரத்து செய்யும், மற்றும் அந்தக் கணக்கு மீண்டும் சேர்க்கப்பட வேண்டும்.

உங்கள் சந்தா உள்நுழைவுகளை மற்றொரு Omarchy இயந்திரத்திற்கு SSH வழியாக நகலெடுக்க, `omarchy agent account copy user@laptop` ஐ இயக்கவும். இலக்கில் ஒன்று நிறுவப்படவில்லை என்றால் அனுப்புநர் ஒரு தற்காலிக receiver ஐ வழங்குகிறது, எனவே பழைய Omarchy இயந்திரங்கள் update இல்லாமல் கணக்குகளைப் பெற முடியும். நிறுவப்பட்ட receivers முன்னுரிமை பெறுகின்றன. இது அனைத்து Claude, Codex, மற்றும் Grok சந்தாக்களையும் நகலெடுக்கிறது; அவற்றைத் தேர்ந்தெடுக்க provider பெயர்களைச் சேர்க்கவும், `omarchy agent account copy laptop claude` இல் உள்ளது போல. கணக்கு பெயர்கள் மற்றும் command ID கள் மூலத்துடன் பொருந்துகின்றன, இலக்கில் ஏற்கனவே உள்ள கணக்குகள் உட்பட. தொடர்பில்லாத இலக்கு கணக்குகள் அவற்றின் பெயர்கள் முரண்பட்டால் ஒரு எண் பின்னொட்டைப் பெறுகின்றன, மற்றும் அமைப்புகள், skills, plugins, மற்றும் உரையாடல் வரலாறு ஒவ்வொரு இயந்திரத்திற்கும் உள்ளூராகவே இருக்கும்.

ஏற்கனவே உள்ள இலக்கு நற்சான்றிதழ்கள் வைக்கப்படுகின்றன. அங்கு ஏற்கனவே உள்நுழைந்துள்ள ஒரு மூல கணக்கின் பெயர் அதன் நற்சான்றிதழ்களை மாற்றாமல் ஒத்திசைக்கப்படுகிறது; மற்ற கணக்குகள் அதற்கு அருகில் சேர்க்கப்படுகின்றன. பொருந்தும் கணக்குகளுக்கான சேமிக்கப்பட்ட நற்சான்றிதழ்களை மாற்ற, இலக்கில் அந்தக் கணக்கின் அமர்வுகளை விட்டு வெளியேறிய பிறகு `omarchy agent account copy --replace laptop claude` ஐப் பயன்படுத்தவும். புதிய இலக்கு மூலத்தின் செயலில் உள்ள கணக்கு மற்றும் மாறுதல் விருப்பங்களையும் பெறுகிறது; நிறுவப்பட்ட இலக்கு அதன் சொந்தத்தை வைத்திருக்கிறது.

நற்சான்றிதழ்கள் SSH வழியாகப் பயணித்து இலக்கில் private கோப்புகளில் சேமிக்கப்படுகின்றன, எனவே நீங்கள் நம்பும் இயந்திரங்களுக்கு மட்டும் நகலெடுக்கவும். இது ஒருமுறை நகல், தொடர்ந்து ஒத்திசைவு அல்ல. Codex refresh tokens மற்றொரு இயந்திரத்தால் சுழற்றப்படலாம், இதனால் நகலெடுக்கப்பட்ட உள்நுழைவுக்குப் புதுப்பிப்பு தேவைப்படும்; பல இயந்திரங்களில் ஒரே நேரத்தில் பயன்படுத்தத் தனித்தனி உள்நுழைவுகளே மிகவும் நம்பகமான தேர்வாக இருக்கும். [Codex's account authentication guidance](https://developers.openai.com/codex/auth/ci-cd-auth) ஐப் பார்க்கவும்.

ஒரு provider க்கு ஒரு கணக்கு செயலில் இருக்கும், மற்றும் ஒவ்வொரு புதிய அமர்வும் அதுவாகவே தொடங்கும்: `cx`, `cy`, ஒரு சாதாரண `claude`, `codex`, அல்லது `grok`, `omarchy agent` மூலம் தொடங்கப்படும் எதுவும், மற்றும் `PATH` இல் CLI ஐக் கண்டறியும் scripts அல்லது editors. `omarchy agent account use work` மூலம் மாற்றவும் (மற்றும் `omarchy agent account use main` மூலம் திரும்பவும்), அல்லது பேனலில் ஒரு கணக்கின் எண்ணை அழுத்தி பின்னர் `Enter` (அல்லது அதன் Use பொத்தானைக் கிளிக் செய்வதன் மூலம்). இயங்கும் Claude அமர்வுகளும் மாறும், அவற்றின் அடுத்த செய்தியிலிருந்து: ஒவ்வொரு Claude அமர்வும் `~/.claude` இல் இயங்குகிறது, இது எப்போதும் செயலில் உள்ள கணக்கின் உள்நுழைவைக் கொண்டிருக்கும். பழைய Omarchy ஆல் ஒரு கணக்கின் சொந்த கோப்புறையில் தொடங்கப்பட்ட Claude அமர்வு அது வெளியேறும் வரை அந்த உள்நுழைவை வைத்திருக்கும், எனவே மாற்றம் அந்த அமர்வுகளைப் பெயரிட்டு அவை போன பிறகு தானாகவே முடிகிறது. இயங்கும் Codex மற்றும் Grok அமர்வுகள் அவை தொடங்கிய கணக்கிலேயே இருக்கும். உரையாடல் வரலாறு, அமைப்புகள், skills, மற்றும் plugins கணக்குகள் முழுவதும் பகிரப்படுகின்றன, எனவே அதே கோப்புறையில் `claude --continue` நீங்கள் புதிய கணக்கில் விட்ட இடத்திலிருந்து தொடரும்.

ஒன்றுக்கு மேற்பட்ட கணக்குகளுடன், பேனல் ஒவ்வொரு கணக்கின் வரம்புகளையும் அருகருகே காட்டுகிறது, செயலில் உள்ளது குறிக்கப்பட்டு. இயல்பாக செயலில் உள்ள கணக்கு ஒரு வரம்பின் 95% ஐக் கடக்கும்போது Omarchy உங்களுக்கு அறிவிக்கும், மற்றும் அறிவிப்பைக் கிளிக் செய்வது அதிக headroom உள்ள கணக்கிற்கு மாற்றும். பேனலில் ஒரு கணக்கின் வரியின் மீது hover செய்து Use க்கு அருகில் தோன்றும் Autoswitch ஐக் கிளிக் செய்யவும் (அல்லது `m` ஐ அழுத்தவும்), அல்லது அது தானாகவே மாற `omarchy agent account mode auto` ஐ இயக்கவும்; அது இயக்கத்தில் இருக்கும்போது, Autoswitch Use இன் இடத்தைப் பிடிக்கிறது, மற்றும் அதை மீண்டும் கிளிக் செய்வது அறிவிப்பதற்குத் திரும்புகிறது. வரம்பை மாற்ற ஒரு எண்ணைச் சேர்க்கவும், `omarchy agent account mode auto 90` இல் உள்ளது போல. ஒவ்வொரு கணக்கும் வரம்பிற்கு மேல் இருந்தால், எந்தக் கணக்கு முதலில் விடுபடுகிறது என்பதுடன் ஒருமுறை நீங்கள் அதைப் பற்றிக் கேள்விப்படுவீர்கள். செயலில் உள்ள கணக்கு அதன் வரம்பிலிருந்து 15 புள்ளிகளுக்குள் இருக்கும்போது (இயல்புநிலையில் 80%), அதன் வரம்புகள் ஒவ்வொரு 15 நிமிடங்களுக்கும் பதிலாக ஒவ்வொரு மூன்று நிமிடங்களுக்கும் சரிபார்க்கப்படுகின்றன.

`omarchy agent account list` ஒவ்வொரு கணக்கையும் அதன் சமீபத்திய வரம்புகளையும் காட்டுகிறது, `omarchy agent account remove work` ஒன்றை மறக்கிறது, மற்றும் `omarchy agent account rename primary Hey` ஒன்றை மறுபெயரிடுகிறது (அல்லது பேனலில் ஒரு கணக்கின் பெயரைக் கிளிக் செய்யவும்). இந்தக் கட்டளைகள் உங்கள் இயல்புநிலை ஏஜென்ட்டின் கணக்குகளில் செயல்படுகின்றன; மற்ற provider ஐ அடைய, அதை முதலில் பெயரிடவும், `omarchy agent account use codex side` இல் உள்ளது போல. நீங்கள் ஏற்கனவே `~/.claude` அல்லது `~/.codex` இல் வைத்திருந்த உள்நுழைவு _Main_ கணக்கு. Codex இனது அது இருக்கும் இடத்திலேயே இருக்கும்; மற்றொரு கணக்கு செயலில் இருக்கும்போது Claude இனது அதற்கெனத் தனி கோப்புறையில் காத்திருக்கும். சுமார் எட்டு மணிநேரத்திற்கும் மேலாகப் பயன்படுத்தப்படாமல் விடப்பட்ட ஒரு கணக்கு _Sign-in required_ எனக் காட்டக்கூடும்; பேனலிலேயே அந்தக் கணக்கை மீண்டும் உள்நுழைய அதைக் கிளிக் செய்யவும், அல்லது அதற்கு மாறி ஒரு அமர்வைத் தொடங்கவும், இது தானாகவே உள்நுழைவைப் புதுப்பிக்கும். நீங்கள் `claude mcp add` மூலம் சேர்க்கும் MCP servers ஒவ்வொரு Claude கணக்கையும் அடைகின்றன, ஏனெனில் அவை அனைத்தும் `~/.claude` இல் இயங்குகின்றன; Codex மற்றும் Grok க்கு, ஒரு கணக்கு சேர்க்கப்பட்டபோது உங்களிடம் இருந்த servers அதனுடன் வருகின்றன, ஆனால் பின்னர் வருபவை நீங்கள் அவற்றைச் சேர்த்த கணக்கை மட்டுமே அடைகின்றன. Claude Desktop அதன் சொந்த உள்நுழைவை வைத்திருக்கிறது, மற்றும் ஒரு CLI binary க்கான absolute path உடன் கட்டமைக்கப்பட்ட Codex அல்லது Grok கருவிகள் மாற்றத்தைப் பின்பற்றாது. வெளிப்படையான `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, அல்லது `GROK_HOME` தேர்ந்தெடுக்கப்பட்ட கணக்கை விட முன்னுரிமை பெறுகிறது.

### செயலிழப்பு கண்டறிதல்

Omarchy செயல்முறை செயலிழப்புகளுக்காக systemd-coredump ஐக் கண்காணிக்கிறது. ஏதாவது segfault ஆகும்போது, உங்களுக்கு ஒரு "Process crashed" அறிவிப்பு கிடைக்கும் — அதைக் கிளிக் செய்யவும், மற்றும் செயலிழப்பு உங்கள் இயல்புநிலை ஏஜென்ட்டிடம் Omarchy இன் diagnose-crash skill உடன் ஒப்படைக்கப்படும், இது core dump இலிருந்து உண்மைகளை நிறுவுவதற்கும் செயலிழப்பை upstream இல் புகாரளிக்கத் தகுந்ததா என்று முடிவு செய்வதற்கும் ஏஜென்ட்டை வழிநடத்தும். `coredumpctl list` இலிருந்து எந்த PID க்கும் எதிராக `omarchy agent crash <pid>` மூலம் அதைக் கையாலும் இயக்கலாம்.

கண்காணிப்பு இயல்பாக இயக்கத்தில் இருக்கும். அதை _Trigger > Toggle > Crash Capture_ இன் கீழ் (அல்லது `omarchy toggle crash-capture` மூலம்) அணைக்கவும் மற்றும் அறிவிப்புகள் நிற்கும்; `omarchy agent crash <pid>` இன்னும் கையால் செயல்படும்.

செயலிழப்புகளை ஒரு நேரத்தில் ஒரு program ஆகவும் அமைதிப்படுத்தலாம், இது கண்டறிதல் இறுதியில் உங்களுக்கு வழங்குவது. `omarchy crash mute hyprland` அந்த program க்கு மட்டும் அறிவிப்புகளை நிறுத்துகிறது, `omarchy crash mute hyprland off` அவற்றைத் திரும்பக் கொண்டுவருகிறது, மற்றும் `omarchy crash mute` தனியாக நீங்கள் அமைதிப்படுத்தியதைப் பட்டியலிடுகிறது. இது binary இன் பாதையை அதன் பெயரைப் போலவே மகிழ்ச்சியாக ஏற்கிறது, எனவே `omarchy crash mute /usr/bin/hyprland` அதே வேலையைச் செய்கிறது. இடைவெளி உள்ள பெயரை மேற்கோள் காட்டவும், `omarchy crash mute 'Some App'` இல் உள்ளது போல. மற்ற எல்லாமும் இன்னும் அறிவிக்கும், மற்றும் அமைதிப்படுத்தப்பட்ட program இன்னும் செயலிழக்கும் — இது நினைவூட்டலை மறைக்கிறது, இது எதையும் சரிசெய்யாது.

### Desktop செயலிகள்

_Install > AI_ மெனுவில் சில graphical AI செயலிகளும் உள்ளன: ChatGPT desktop app, Claude desktop app (Chat, Cowork, மற்றும் Claude Code tabs உடன் Anthropic இன் Linux beta), xAI இன் மாடல்களுடன் அரட்டை அடிப்பதற்கான Grok Bot, Herdr Desktop, Hermes Desktop, OpenClaw, Perplexity desktop app, மற்றும் T3 Code. Grok Bot என்பது desktop chat செயலி. கோடிங் ஏஜென்ட் என்பது `grok` கட்டளை.

Hermes Desktop தான் தெரிந்து கொள்ள வேண்டியது, ஏனெனில் ஒரு இயந்திரத்தில் ஒரு Hermes உள்ளது, மற்றும் அது செயலியினுடையது: Hermes எப்போதும் செயலி மூலம் மட்டுமே நிறுவப்படுகிறது, மற்றும் இயல்புநிலை ஏஜென்ட் இயக்கும் `hermes` கட்டளை செயலியினுடையது. Hermes ஐ இயல்புநிலை ஏஜென்ட்டாகத் தேர்ந்தெடுப்பது _Install > AI_ உள்ளீடு செய்வதையே நிறுவுகிறது: package, மற்றும் Hermes இன் சொந்த நிறுவியால் அமைக்கப்பட்ட `~/.hermes` இன் கீழ் ஒரு Hermes runtime, இது முதல் முறை சில நிமிடங்கள் எடுக்கும். அந்த runtime தான் terminal `hermes` கட்டளை, இயல்புநிலை ஏஜென்ட் மற்றும் செயலி அனைத்தும் பயன்படுத்தும் ஒரே Hermes, மற்றும் அது ஒரு Omarchy வெளியீட்டிற்காகக் காத்திராமல் `hermes update` மூலம் தன்னைப் புதுப்பித்துக் கொள்கிறது. அதை நிறுவுவது Hermes க்கு Omarchy theme ஐ `omarchy` என்ற பெயரில் ஒரு skin ஆகவும் வழங்குகிறது, இதை ஒவ்வொரு Hermes surface உம் நீங்கள் themes மாற்றும்போது பின்பற்றும்; நீங்கள் அது வேண்டாம் என்றால் Hermes இன் Appearance அமைப்புகளின் கீழ் அல்லது `/skin` மூலம் மற்றொன்றைத் தேர்ந்தெடுக்கவும், மற்றும் Omarchy அந்தத் தேர்வை அப்படியே விட்டுவிடும். _Remove > AI_ இன் கீழ் செயலியை நீக்குவது முதலில் Hermes ஐ மூடுகிறது, gateway உட்பட, அந்த runtime ஐ அதனுடன் எடுத்துச் செல்கிறது, மற்றும் நீங்கள் வேறுவிதமாகக் கூறாவிட்டால் உங்கள் chats, memories, மற்றும் Hermes தனக்காக எழுதிய skills ஐ வைத்திருக்கிறது: அந்தத் தரவும் உங்கள் இணைப்பு அமைப்புகளும் போக வேண்டுமா என்று அது கேட்கும், இயல்பாக இல்லை என்று.

OpenClaw இன் desktop அனுபவம் அதன் Control UI, இது அதன் சொந்த local gateway ஆல் ஆதரிக்கப்படும் ஒரு web app ஆகத் திறக்கும். OpenClaw `~/.openclaw` இல் வாழ்கிறது மற்றும் தன்னைப் புதுப்பித்துக் கொள்கிறது: Control UI இன் "Update Gateway" பொத்தானைப் பயன்படுத்தவும் அல்லது `openclaw update` ஐ இயக்கவும், மற்றும் gateway புதிய பதிப்பில் மறுதொடக்கம் ஆகும். Omarchy புதிய நிறுவல் தொடங்கும் வெளியீட்டை மட்டுமே தேர்ந்தெடுக்கிறது. _Remove > AI_ இன் கீழ் OpenClaw ஐ நீக்குவது gateway service மற்றும் செயலியை அதனுடன் எடுத்துச் செல்கிறது, பின்னர் `~/.openclaw` உம் போக வேண்டுமா என்று கேட்கிறது, ஏனெனில் அது OpenClaw உடன் மற்றும் அது பதிவிறக்கும் plugin runtimes உடன் உங்கள் chats மற்றும் நற்சான்றிதழ்களைக் கொண்டுள்ளது; இயல்புநிலை அதை வைத்திருக்கிறது, மற்றும் OpenClaw ஐ மீண்டும் நிறுவுவது அதை மீண்டும் எடுத்துக் கொள்கிறது.

Herdr Desktop என்பது [Herdr](https://herdr.dev) desktop செயலி: நீங்கள் window வை மூடும்போது அதன் core இல் தொடர்ந்து இயங்கும் terminals மற்றும் கோடிங் ஏஜென்ட்களின் spaces, tabs, மற்றும் panes. இது ஒரு package இலிருந்து அல்லாமல் Herdr இன் சொந்த நிறுவியிலிருந்து வருகிறது, எனவே இது `~/.local/share/herdr-app` இல் வாழ்கிறது, உங்களிடம் ஏற்கனவே ஒன்று இல்லையென்றால் `~/.local/bin/herdr-core` இல் அதன் core ஐக் கொண்டுவருகிறது, மற்றும் இரண்டையும் தானே புதுப்பித்துக் கொள்கிறது. இது Omarchy `Super + Ctrl + Return` இல் வழங்கும் `herdr` கட்டளைக்கு அருகில் அமர்ந்திருக்கிறது, அதை மாற்றாமல், மற்றும் அந்தக் கட்டளையின் direct keys ஐப் பெறுகிறது: `Alt + Return` மற்றும் `Alt + Shift + Return` ஒரு pane ஐக் கீழே அல்லது வலதுபுறம் பிரிக்கிறது, `Alt + Escape` அதை மூடுகிறது, `Ctrl + Alt + Arrow` panes க்கிடையே நகர்கிறது, `Alt + 1..9` மற்றும் `Alt + Left/Right` ஒரு tab ஐத் தேர்ந்தெடுக்கிறது, மற்றும் `Alt + Up/Down` spaces க்கிடையே நகர்கிறது. `Ctrl + 1..9` ஒரு space ஐத் தேர்ந்தெடுக்கிறது மற்றும் `Alt + Shift + Up/Down` agents வழியாகச் செல்கிறது. `Ctrl + Space` prefix keys terminal க்கு மட்டுமே இருக்கும், ஏனெனில் செயலி ஒரு வரிசைக்காக ஒரு சாதாரண Ctrl key ஐப் பிடித்து வைக்க முடியாது. Omarchy இவற்றை `~/.config/herdr-app/keys.json` இல் எழுதுகிறது, மற்றும் `omarchy-refresh-herdr-app` அவற்றை மீண்டும் வைக்கிறது. அதை நிறுவுவது Herdr இன் Omarchy theme ஐத் தேர்ந்தெடுக்கிறது, இது அதன் பிறகு உங்கள் Omarchy theme ஐப் பின்பற்றும். Herdr light mode க்கு ஒரு theme மற்றும் dark mode க்கு ஒன்றை வைத்திருக்கிறது, எனவே dark மற்றும் light Omarchy theme க்கிடையே மாறிய பிறகு, மற்ற முறைக்கு Herdr இன் theme picker இல் Omarchy ஐ மீண்டும் ஒருமுறை தேர்ந்தெடுக்கவும்.

T3 Code ஒரு package இலிருந்து அல்லாமல் `~/.local/share/t3code` இல் அதன் அதிகாரப்பூர்வ AppImage வெளியீட்டிலிருந்து இயங்குகிறது, எனவே அது தன்னைப் புதுப்பித்துக் கொள்கிறது. அதை நிறுவுவது Stable அல்லது Nightly channel இல் தொடங்க வேண்டுமா என்று கேட்கிறது; பின்னர் T3 Code இன் அமைப்புகளில் மாற்றவும். உங்கள் threads மற்றும் அமைப்புகள் `~/.t3` இல் வாழ்கின்றன, மற்றும் _Remove > AI_ இன் கீழ் T3 Code ஐ நீக்குவது அவற்றை அதனுடன் எடுத்துச் செல்கிறது.

### Local மாடல்கள்

உங்கள் கோடிங் ஏஜென்ட்களுக்காக உங்கள் சொந்த இயந்திரத்தில் ஒரு open model ஐ இயக்கவும். உங்கள் prompts மற்றும் code உங்கள் இயந்திரத்திலேயே இருக்கும்; மாடலுக்கு அனுப்பப்படும் எதுவும் அதை விட்டு வெளியேறாது. இதனுடன் தொடங்கவும்:

```bash
omarchy agent local use best
```

அல்லது, மேல் பட்டியில் உள்ள agents பேனலில், + மற்றும் பின்னர் Local AI ஐத் தேர்ந்தெடுக்கவும், இது ஒரு மாடல் இந்த இயந்திரத்திற்குப் பொருந்தும்போது தோன்றும். முதல் முறை, இது Podman ஐ நிறுவுகிறது, இது மாடல்களை இயக்குகிறது, மற்றும் ஒரு NVIDIA இயந்திரத்தில் NVIDIA இன் container toolkit, இது அவற்றுக்கு GPU ஐ வழங்குகிறது. Omarchy பின்னர் இந்த இயந்திரத்திற்கான பரிந்துரைக்கப்பட்ட மாடலைத் தேர்ந்தெடுத்து, அதைப் பதிவிறக்கி, தொடங்குகிறது. பத்துக்கணக்கான GB பதிவிறக்கத்தையும் மாடல் இயங்கும்போது இயந்திரத்தின் நினைவகத்தின் பெரும்பகுதி பயன்பாட்டில் இருப்பதையும் எதிர்பார்க்கவும்: Flash Next அதன் முழு 256K context உடன் சுமார் 100 GiB ஐப் பயன்படுத்துகிறது. மற்ற மாடல்கள் அதற்குத் தேவையான நினைவகத்தை வைத்திருந்தால், அது நிறுத்தப்பட்ட நிலையில் அமைக்கப்படுகிறது, நீங்கள் ஒன்றை நிறுத்தியவுடன் தொடங்கத் தயாராக. மாடல் logout இல் நிற்கும்; உங்களுக்கு வேறு ஏதாவதற்கு நினைவகம் தேவைப்படும்போது அதை நீங்களே நிறுத்தவும்.

`omarchy agent local list` விருப்பங்களைக் காட்டுகிறது மற்றும் சில ஏன் பொருந்தவில்லை என்று விளக்குகிறது. மற்றொன்றை அமைக்க, `omarchy agent local use <recipe>` ஐ இயக்கவும். இன்று, `qwen3.8-flash-next-gufo` மற்றும் `qwen3.8-27b-gufo` 128 GB Strix Halo இயந்திரங்களுக்குக் கிடைக்கின்றன; 27B சுமார் 40 GiB எடுக்கிறது, எனவே அது மற்ற வேலைக்கு இடம் விடுகிறது. Intel இன் Arc B390 உடன் ஒரு 64 GB laptop இல், `qwen3.6-35b-a3b-llamacpp` சுமார் 30 GiB இல் இயங்குகிறது. புதிய recipes மற்றும் பரிந்துரைகள் `omarchy update` மூலம், package வழியாக வருகின்றன.

நீங்கள் அமைக்கும் ஒவ்வொரு மாடலுக்கும் agents பேனலில், உங்கள் சந்தாக்களுக்கு அருகில் அதற்கென ஒரு வரி கிடைக்கிறது: அதைத் தொடங்க play, அதை நிறுத்தி அதன் நினைவகத்தை விடுவிக்க pause, மற்றும் அதில் உங்கள் ஏஜென்ட்டைத் திறக்க terminal பொத்தான். அவை நினைவகத்தில் ஒன்றாகப் பொருந்தும்போது பல ஒரே நேரத்தில் இயங்க முடியும்; ஒன்று பொருந்தவில்லை என்றால், எந்த இயங்கும் மாடலை நிறுத்த வேண்டும் என்று Omarchy கூறுகிறது. அவற்றை மறுவரிசைப்படுத்த வரிகளை இழுக்கவும், மற்றும் ஒரு மாடலையும் அதன் பதிவிறக்கத்தையும் நீக்கத் தேர்ந்தெடுக்கப்பட்ட வரியில் Delete ஐ அழுத்தவும்.

நீங்கள் அமைக்கும் ஒவ்வொரு மாடலுக்கும் app launcher இல் அதற்கென ஒரு உள்ளீடும் கிடைக்கிறது, மாடலின் பெயரின் கீழ் மற்றும் அதன் தயாரிப்பாளரின் logo உடன், Claude, Codex அல்லது Grok இல் உள்நுழைவது ஒன்றைச் சேர்ப்பது போல. இது அந்த மாடலில் உங்கள் ஏஜென்ட்டைத் திறக்கிறது, மற்றும் அது இயங்கவில்லை என்றால் முதலில் மாடலைத் தொடங்குகிறது: terminal அது ஏற்றப்படுவதைக் காட்டி அது தயாரானதும் ஏஜென்ட்டிடம் ஒப்படைக்கிறது. ஒரு மாடலை நீக்குவது அதன் உள்ளீட்டை நீக்குகிறது.

கட்டளை வரியிலிருந்து, `omarchy agent local start <recipe>` மற்றும் `omarchy agent local stop <recipe>` அதையே செய்கின்றன, `omarchy agent local status` ஒவ்வொரு மாடலையும் காட்டுகிறது, மற்றும் `omarchy agent --local` நீங்கள் கடைசியாகத் தொடங்கிய மாடலில் உங்கள் இயல்புநிலை ஏஜென்ட்டைத் திறக்கிறது. pi, OpenCode மற்றும் Qwen Code ஒன்றைப் பயன்படுத்த முடியும்; வேறு எந்த இயல்புநிலையுடனும் அது pi இல் திறக்கும். pi நீங்கள் அமைத்த ஒவ்வொரு மாடலையும், மற்றும் நீங்கள் இணைத்த இயந்திரங்களில் உள்ளவற்றையும், அதன் சொந்த model picker இல் பட்டியலிடுகிறது, எனவே சாதாரண `pi` உம் அவற்றை அடைய முடியும். எந்த OpenAI-compatible client உம் இணைக்க முடியும்: `status` ஒவ்வொரு மாடலின் முகவரியையும் காட்டுகிறது (முதலாவது `http://127.0.0.1:11435/v1`), recipe பெயரே மாடல், மற்றும் key `~/.config/omarchy/agent-local/key` இல் உள்ளது.

`omarchy agent local remove <recipe>` ஒரு மாடலையும் வேறு எந்த மாடலும் பயன்படுத்தாத பதிவிறக்கங்களையும் நீக்குகிறது.

மூன்றாம் தரப்பு runtimes அவற்றின் publisher உடன் பெயரிடப்படுகின்றன. Omarchy ஒவ்வொரு மாடலையும் network அணுகல் இல்லாமல் இயக்குகிறது.

### Local LLM கள்

Omarchy local LLM மாடல்களை இயக்குவதற்கான இரண்டு வழிகளைப் பரிந்துரைக்கிறது: LM Studio மற்றும் Ollama. LM Studio open-weight மாடல்களைக் கண்டறிவதற்கும், அவற்றை நிறுவுவதற்கும், அவற்றை இயக்குவதற்கும் ஒரு GUI interface ஐ வழங்குகிறது. எளிதாகத் தொடங்க இது ஒரு சிறந்த வழி. Ollama அதையே செய்வதற்கு ஒரு CLI ஐ வழங்குகிறது. ஆனால் நீங்கள் local மாடல்களுக்குப் புதியவர் என்றால், நான் LM Studio உடன் தொடங்குவேன். Omarchy Menu இல் _Install > AI_ இன் கீழ் எதையும் நிறுவலாம்.

### Omarchy Skill

Agent skills AI குறிப்பிட்ட கருவிகளை ஒரு குறிப்பிட்ட வழியில் பயன்படுத்த உதவுகிறது, மற்றும் Omarchy கணினியைத் தனிப்பயனாக்க ஒரு இயல்புநிலை skill உடன் வருகிறது. உங்கள் Hyprland config ஐ மாற்றுவது போல, பட்டியைச் சரிசெய்வது போல, அல்லது புதிதாக ஒரு புதிய theme ஐ உருவாக்குவது போல. இது Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` மற்றும் ஒவ்வொரு `~/.hermes/profiles/*/skills`), மற்றும் பொதுவான `~/.agents/skills` இடத்திற்கான skill அடைவுகளில் symlinked செய்யப்பட்டுள்ளது, எனவே பெரும்பாலான harness கள் அதைத் தானாகவே எடுத்துக்கொள்கின்றன.

ஆனால் நீங்கள் இந்த skill ஐச் சோதனை முயற்சியாகக் கருத வேண்டும். வெவ்வேறு மாடல்கள் அதை வெவ்வேறு விளைவுகளுக்குப் பயன்படுத்தும். முதலில் plan mode இல் இயக்குவது சிறந்தது, எனவே ஏஜென்ட் என்ன மாற்ற விரும்புகிறது என்பது பற்றி உங்களுக்கு ஒரு யோசனை கிடைக்கும். பின்னர் மாற்றங்களைத் திரும்பப் பெற அல்லது ஏஜென்ட் எல்லாவற்றையும் குழப்பிவிட்டால் `omarchy reinstall configs` ஐ இயக்கக் கூடத் தயாராக இருங்கள்.
