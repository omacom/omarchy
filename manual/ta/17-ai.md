# AI

Omarchy உங்களுக்காக இயல்புநிலையைத் தேர்ந்தெடுக்காமல் கீழே உள்ள கோடிங் ஏஜென்ட்களுக்கான லாஞ்சர்களைக் கொண்டுள்ளது. முதல் பயன்பாட்டில் அதன் CLI ஐ நிறுவ ஒரு கட்டளையை இயக்கவும், பின்னர் கேட்கப்படும்போது அங்கீகரிக்கவும். Hermes மற்றும் OpenClaw விதிவிலக்குகள்: அவற்றுக்காக mise வழியாக எதுவும் நிறுவப்படுவதில்லை, மேலும் அவற்றில் ஒன்றைத் தேர்ந்தெடுப்பது அதன் சொந்த சுய-புதுப்பிப்பு நகலை அமைக்கிறது, கீழே உள்ள _டெஸ்க்டாப் பயன்பாடுகள்_ விளக்குவது போல.

### ஏஜென்ட்களை நிறுவுதலும் புதுப்பித்தலும்

Hermes மற்றும் OpenClaw தவிர, இந்த ஏஜென்ட்கள் mise இன் சோம்பேறி நிறுவலைப் பயன்படுத்துகின்றன: முதல் தொடக்கம் CLI ஐ நிறுவுகிறது, பிந்தைய தொடக்கங்கள் அதை மீண்டும் பயன்படுத்துகின்றன. mise ஒரு நிறுவப்பட்ட ஏஜென்டிற்கு புதிய வெளியீடு உள்ளதா என நான்கு மணி நேரத்திற்கு ஒரு முறைக்கு மேல் சரிபார்க்காது, அது தொடங்குவதற்கு சற்று முன்பு அல்லது ஷெல் ப்ராம்ப்டில் பின்னணியில். அந்தப் புதுப்பிப்பு தோல்வியடைந்தால் அல்லது நீங்கள் ஆஃப்லைனில் இருந்தால், நிறுவப்பட்ட பதிப்பு இயங்கும். `omarchy update` Omarchy இன் மற்றவற்றுடன் நிறுவப்பட்ட ஏஜென்ட்களையும் புதுப்பிக்கிறது, மேலும் `mup` mise நிர்வகிக்கும் கருவிகளை மட்டும் புதுப்பிக்கிறது.

`claude update`, `codex update` போன்ற ஏஜென்டின் சொந்தப் புதுப்பிப்பான், அல்லது ஒரு பயன்பாட்டில் உள்ள புதுப்பிப்பு பொத்தான், mise நிர்வகிக்கும் நிறுவலைப் புதுப்பிக்காது. `codex update` தோல்வியடைகிறது, மேலும் `claude update` வெற்றி என அறிவித்தாலும் mise கண்காணிக்காத தனி நகலை நிறுவக்கூடும். நீங்கள் ஏஜென்டின் சொந்த நிறுவி மற்றும் புதுப்பிப்பானைப் பயன்படுத்த விரும்பினால், அதை `disable_tools` இல் சேர்க்கவும்; [முன்பே நிறுவப்பட்ட CLI கருவிகள்](18-development-tools.md#preinstalled-cli-tools) ஐப் பார்க்கவும்.

உங்களுக்குத் தேவைப்படுவதற்கு முன்பே உள்ளமைக்கப்பட்ட அனைத்து சோம்பேறி கருவிகளையும் நிறுவ, `mise install --include-lazy` ஐ இயக்கவும். இதில் ஏஜென்ட்களுடன் Omarchy இன் மற்ற இயல்புநிலை CLI கருவிகளும் அடங்கும். ஒரு ஒற்றைக் கருவியை நிறுவுவதற்கு அல்லது உங்கள் சொந்த நிறுவலைப் பயன்படுத்துவதற்கு [முன்பே நிறுவப்பட்ட CLI கருவிகள்](18-development-tools.md#preinstalled-cli-tools) ஐப் பார்க்கவும்.

`grok` mise இன் முதல்-தரப்பு `grok` தொகுப்பு வழியாக நிறுவப்படுகிறது, `claude` மற்றும் `codex` போலவே. `grok` ஐ இயக்கவும், அல்லது ஏஜென்ட்கள் பேனலில் அதை நட்சத்திரமிடவும். x.ai இல் உள்ள `curl | bash` நிறுவியைத் தவிர்க்கவும். அந்த வழி இரண்டாவது நகலை `~/.grok/bin` இல் வைக்கிறது, அதை `PATH` இல் முன்னால் சேர்க்கிறது, மேலும் Omarchy இன் wrapper ஐ மேலெழுதுகிறது.

`dsh` அதன் உலாவி UI ஐ `127.0.0.1:3080` இல் திறக்கிறது, தொடக்கக் கோப்பகத்தை அதன் இயல்புநிலை பணியிடமாகக் கொண்டு. அதன் உலாவி UI தொடக்க ப்ராம்ப்டை எடுக்காது, எனவே `omarchy agent prompt` அதை உங்கள் கிளிப்போர்டில் ஒட்டுவதற்கான ப்ராம்ப்டுடன் திறக்கிறது. Omarchy அதை DeepSeek இன் ஒப்புதல் தேவையில்லாத அனுமதி முன்னமைவுடன் தொடங்குகிறது. நீங்கள் அதன் அதிகாரப்பூர்வ மாடல் API ஐப் பயன்படுத்தும்போது DeepSeek Harness அமர்வு பதிவுகளை DeepSeek க்கு பதிவேற்றுகிறது; அதன் உலாவி UI இல் _Settings > General > Upload Session Log_ இன் கீழ் அதை அணைக்கவும். நீங்கள் அதற்கு அனுப்பும் கருத்தும் அமர்வுடன் பதிவேற்றப்படுகிறது, நீங்கள் அதை `DSH_TELEMETRY_MODE=DISABLED` உடன் தொடங்கினால் தவிர.

### இயல்புநிலை ஏஜென்ட்

ஏஜென்ட்கள் பேனலில் ஒரு ஏஜென்டுக்கு அருகில் உள்ள நட்சத்திரத்தைக் கொண்டு உங்கள் இயல்புநிலை ஏஜென்டைத் தேர்ந்தெடுக்கவும், அது இயல்புநிலையில் நிரப்பப்பட்டிருக்கும், அல்லது `omarchy default agent <name>` உடன், அது அங்கு ஒரு வரி இல்லாத எந்த harness ஐயும் எடுக்கும். ஏஜென்ட் இன்னும் நிறுவப்படவில்லை என்றால், அதைத் தேர்ந்தெடுப்பது முதலில் அதை நிறுவுகிறது, மேலும் அது பயன்பாட்டு லாஞ்சரில் Agent க்கு அருகில் தனக்கான லாஞ்சரையும் பெறுகிறது. புதிய Omarchy ஒரு முறை மட்டும் வரும் அறிவிப்புடன் ஒன்றை அமைக்க உங்களை அழைக்கிறது, அது ஏஜென்ட்கள் பேனலைத் திறக்கிறது.

Claude ஐத் தேர்ந்தெடுப்பது Chromium, Chrome, Brave, Brave Origin, மற்றும் Edge க்காக அதன் உலாவி நீட்டிப்பை அமைக்கவும் முயற்சிக்கிறது. நீட்டிப்பு அமைப்பு அனைத்துப் பயனர்களுக்கும் பொருந்தும் மற்றும் உங்கள் கணினி கடவுச்சொல்லைக் கேட்கக்கூடும்; நீட்டிப்பு நிறுவலை ரத்து செய்தாலும் அல்லது அது தோல்வியடைந்தாலும் Claude தேர்ந்தெடுக்கப்பட்டு தொடங்கப்படும். உங்கள் உலாவியை மறுதொடக்கம் செய்யவும், கேட்கப்பட்டால் நீட்டிப்பை இயக்கவும், மேலும் அதை இணைப்பதை முடிக்க Claude இல் உள்நுழையவும். இணைப்பைச் சரிபார்க்க Claude இல் `/chrome` ஐ இயக்கவும். Firefox மற்றும் Zen இந்த நீட்டிப்பை ஆதரிக்காது. இந்த அமைப்பு சேர்க்கப்படுவதற்கு முன்பே Claude உங்கள் இயல்புநிலையாக இருந்திருந்தால், நீட்டிப்பை நிறுவ அதை மீண்டும் தேர்ந்தெடுக்கவும்.

நீங்கள் தேர்ந்தெடுத்த பிறகு, `Super + Shift + Ctrl + A` இயல்புநிலை ஏஜென்டை ஒரு பிரத்யேக டெர்மினல் சாளரத்தில் தொடங்குகிறது (அல்லது நீங்கள் இன்னும் தேர்ந்தெடுக்கவில்லை என்றால் தேர்வியைக் கொண்டு வருகிறது). நீங்கள் அதை `omarchy agent prompt "Review this project"` உடன் நேரடியாக ஒரு பணியிலும் தொடங்கலாம். Freebuff மற்றும் DeepSeek Harness தொடக்க ப்ராம்ப்டை எடுக்காது, எனவே அவை அதற்குப் பதிலாக உங்கள் கிளிப்போர்டில் ஒட்டுவதற்கான ப்ராம்ப்டுடன் திறக்கின்றன. இவ்வாறு தொடங்கப்படும் ஏஜென்ட்கள் அவற்றின் அந்தந்த நிறுத்தி-கேட்காத முறைகளில் கவனிக்கப்படாமல் இயங்குகின்றன, எனவே அவை உண்மையில் விஷயங்களைச் செய்யத் தயாராக இருங்கள்! MiniMax Code அதன் ஊடாடும் அமர்வுகளுக்கு அத்தகைய முறையைக் கொண்டிருக்கவில்லை, எனவே அது வழக்கம் போல் அனுமதிகளைக் கேட்கிறது. மேலும் ஏஜென்ட்கள் உங்கள் முகப்புக் கோப்பகத்திற்கான நம்பிக்கையை நினைவில் கொள்ள மறுப்பதால், `$HOME` இலிருந்து தொடங்குவது அதற்குப் பதிலாக `~/Work` இல் தொடங்குகிறது.

டெர்மினல் குறுக்குவழிகளும் உள்ளன: `a` தற்போதைய டெர்மினலில் இயல்புநிலை ஏஜென்டை இன்லைனில் இயக்குகிறது, அதே நேரத்தில் `c`, `cx`, `cy`, மற்றும் `ca` OpenCode, Claude Code, Codex, மற்றும் Antigravity ஐ நேரடியாகத் தொடங்குகின்றன (மீண்டும் அவற்றின் தானியங்கு-ஒப்புதல் முறைகளில்). தீம் மாற்றங்களும் ஏஜென்ட்களுக்கு ஒத்திசைகின்றன: Claude Code, Pi, OpenCode, மற்றும் Hermes (Omarchy அதை நிறுவிய பிறகு) அனைத்தும் நீங்கள் Omarchy தீமை மாற்றும்போது பின்தொடர்கின்றன.

### உங்கள் ஏஜென்ட் வழிமுறைகள்

ஒவ்வொரு ஏஜென்டுக்கான தனிப்பட்ட விதிகள் `~/.agents/skills` இல் உள்ள பகிரப்பட்ட ஸ்கில்களுக்கு அருகில் `~/.agents/AGENTS.md` இல் செல்கின்றன. ஏஜென்ட்கள் பேனலில் + க்கு அருகில் உள்ள ஆவண ஐகானைக் கொண்டு அதைத் திறக்கவும், அல்லது `omarchy agent instructions --edit` உடன், அது அதைத் தனது சொந்த உலகளாவிய கோப்பை வைத்திருக்கும் ஒவ்வொரு harness இலும் இணைக்கிறது: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, Copilot இன் `~/.copilot/copilot-instructions.md`, மற்றும் பல. Crush மற்றும் Amp `~/.config/AGENTS.md` இணைப்பைப் படிக்கின்றன, அதே நேரத்தில் omp, Kimi, மற்றும் DeepSeek Harness `~/.agents/AGENTS.md` ஐ நேரடியாகப் படிக்கின்றன. இயல்புநிலை ஏஜென்டைத் தேர்ந்தெடுப்பதும் அதை இணைக்கிறது. உங்களிடம் ஏற்கனவே இருந்த வழிமுறைகள் கோப்பு, இன்னும் பகிரப்பட்டது எதுவும் இல்லை என்றால் பகிரப்பட்டதாக மாறுகிறது; இல்லையெனில் அது இணைப்புக்கு அருகில் `.bak` ஆக வைக்கப்படுகிறது. மற்றொரு ஏஜென்டை நிறுவிய பிறகு மீண்டும் இணைக்க `omarchy agent instructions` ஐ இயக்கவும்.

### ஏஜென்ட்கள் பேனல்

மேல் பட்டியில் ஒரு ஏஜென்ட்கள் ஐகான் உள்ளது. நீங்கள் ஒரு ஏஜென்டை அமைப்பதற்கு முன்பு, அதன் பேனல் தொடங்க மூன்று வழிகளை வழங்குகிறது: Claude, Codex, Grok, Gemini, Muse, Cursor, அல்லது Copilot சந்தாவில் உள்நுழையவும், அல்லது More இன் கீழ் OpenCode Go, MiniMax, Synthetic, அல்லது Z.ai கோடிங் திட்டம்; Fireworks, OpenCode Zen மற்றும் Go, OpenRouter உடன் பயன்பாட்டிற்கு ஏற்ப பணம் செலுத்தவும், அல்லது More இன் கீழ் DeepSeek அல்லது OpenCode உள்நுழையும் வேறு எந்த வழங்குநரும், அனைத்தும் OpenCode இல் இயங்குகின்றன; அல்லது உங்கள் கணினிக்குப் பொருந்தும்போது அதற்கான சிறந்த மாடலை இயக்கவும். நீங்கள் முதலில் முடிக்கும் ஒன்று உங்கள் இயல்புநிலை ஏஜென்டாக மாறுகிறது, மேலும் பேனலில் உள்ள + பின்னர் அதே மூன்றையும் வழங்குகிறது. அதன் பிறகு, பேனல் ஒவ்வொரு சந்தாவையும் ஒரே பக்கத்தில் வைக்கிறது: ஒவ்வொரு ஏஜென்டும் கணக்கும் அதன் திட்டத்துடன், அதன் 5-மணி நேர அமர்வு மற்றும் வாராந்திர வரம்புகள் ஒவ்வொன்றிற்கும் ஒரு மீட்டர், அது மீட்டமைக்கும் வரையிலான நேரத்துடன் (சரியான சதவீதத்திற்கு மேலே கொண்டு செல்லவும்), அல்லது மீதமுள்ள முன்கூட்டியே செலுத்தப்பட்ட இருப்பு, நீங்கள் அவை அனைத்திலும் பயன்படுத்தியதைச் சுழற்றும் ஒரு வரியின் கீழ், இந்த வார டோக்கன்கள் மற்றும் உங்கள் அதிகம் பயன்படுத்தப்பட்ட மாடல் போல. _ஏதாவது சிறப்பாக உருவாக்கவும்_ இன் கீழ் அது புதிய தீம், பிளகின், பயன்பாடு, அல்லது விளையாட்டுக்கான தொடக்க ப்ராம்ப்டுகளை வழங்குகிறது, அவை பணியை உங்கள் இயல்புநிலை ஏஜென்டிடம் ஒப்படைக்கின்றன. பயன்பாடுகள் Omarchy இன் சொந்த Hype, Monologue, மற்றும் Omacut போலவே, C++ மற்றும் Qt Quick இல், omarchy-make-app ஏஜென்ட் ஸ்கில்லைப் பின்பற்றி உருவாக்கப்படுகின்றன, மேலும் அவற்றுக்குத் தேவையான கம்பைலர் மற்றும் Qt துண்டுகள் நிறுவப்பட்டு வருகின்றன. விளையாட்டுகள் `~/Games/vibes` இல் உள்ள ஒற்றை three.js பக்கம், omarchy-make-game ஏஜென்ட் ஸ்கில்லைப் பின்பற்றி, மேலும் அனைத்தும் தற்போதைய தீமில் ஒரு Game Vibes லாஞ்சரிலிருந்து திறக்கின்றன; அவை three.js ஐ வலையிலிருந்து ஏற்றுகின்றன, எனவே தொடங்க அவற்றுக்கு இணைப்பு தேவை. Claude Code, Codex, Grok, Kimi, Cursor மற்றும் அதன் Grok Bot ஒதுக்கீடு, GitHub Copilot, Muse, Gemini (Antigravity வழியாக), மற்றும் Devin அவற்றின் வரம்புகளுடன் உடனடியாகக் கவரப்படுகின்றன, Kimchi அதன் திட்டம், முன்கூட்டியே செலுத்தப்பட்ட கிரெடிட்கள், மற்றும் செலவு பட்ஜெட்களுடன், மேலும் Hermes, Mistral Vibe, மற்றும் Qwen Code நீங்கள் அவற்றைப் பயன்படுத்திய பிறகு அவற்றின் அமர்வுகள் மற்றும் டோக்கன்களைக் காட்டுகின்றன. நீங்கள் pi, omp, அல்லது opencode வழியாகப் பயன்படுத்தும் வழங்குநர் திட்டங்கள் மற்றும் விசைகளும் தோன்றுகின்றன: OpenCode Zen மற்றும் Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan, மற்றும் Synthetic அவற்றின் வரம்புகளுடன்; OpenRouter மற்றும் DeepSeek அவற்றின் முன்கூட்டியே செலுத்தப்பட்ட இருப்புகளுடன்; Fireworks கடந்த 30 நாட்களில் அதன் செலவுடன். உங்கள் சொந்த வன்பொருளில் நீங்கள் இயக்கும் கோடிங் மாடல்கள் அவற்றுக்கான வரிகளைப் பெறுகின்றன, மேலும் அவற்றின் டோக்கன்களும் மொத்தங்களில் கணக்கிடப்படுகின்றன, [உள்ளூர் மாடல்கள்](#local-models) இன் கீழ் விவரிக்கப்பட்டுள்ளபடி. ஒவ்வொரு ஏஜென்டும் ஒரு முறை மட்டுமே கணக்கிடப்படுகிறது, அதற்கு பில் செய்பவரின் கீழ், நீங்கள் எத்தனை harness கள் வழியாக அதை இயக்கினாலும்.

பேனலுக்கு பட்டி ஐகானை இடது-கிளிக் செய்யவும் அல்லது `Super + Ctrl + X` ஐ அழுத்தவும், உங்கள் இயல்புநிலை ஏஜென்டைத் தொடங்க வலது-கிளிக் செய்யவும், மற்றும் புதுப்பிக்க நடு-கிளிக் செய்யவும். அதன் பின்னால் உள்ள பயன்பாட்டுப் பதிவுகள் ஒவ்வொரு 15 நிமிடங்களுக்கும் `omarchy agent usage update` மூலம் மீண்டும் உருவாக்கப்படுகின்றன, மேலும் பேனல் ஒத்திசைக்கப்பட்ட கோப்புறை வழியாக உங்கள் மற்ற கணினிகளிலிருந்து பயன்பாட்டையும் இணைக்க முடியும். முழு அமைப்புகளுக்கு `$OMARCHY_PATH/shell/plugins/agents/` இன் கீழ் உள்ள README ஐப் பார்க்கவும்.

### பல சந்தாக்கள்

நீங்கள் ஒன்றுக்கு மேற்பட்ட Claude, Codex, அல்லது Grok திட்டத்திற்கு பணம் செலுத்தினால் — தனிப்பட்ட Max மற்றும் வேலை ஒன்று, சொல்லுங்கள் — Omarchy அவை அனைத்தையும் உள்நுழைந்து வைத்து அவற்றுக்கு இடையில் நகர முடியும். ஏஜென்ட்கள் பேனலில் உள்ள + உடன் ஒரு சந்தாவைச் சேர்க்கவும், அது அங்கேயே உங்களை அதன் வழியாக அழைத்துச் செல்லும், அல்லது `omarchy agent account add claude Work` உடன் (அல்லது `codex`, அல்லது `grok`). அதே + மற்றும் கட்டளை Gemini (`gemini`) மற்றும் OpenCode (`opencode`) இல் உள்நுழைகின்றன, மேலும் Fireworks (`fireworks`) அல்லது OpenRouter (`openrouter`) API விசையை OpenCode இல் சேமிக்கின்றன; கட்டளை Copilot (`copilot`), Cursor (`cursor`), மற்றும் Muse (`muse`) இலும் உள்நுழைகிறது. அவை ஒவ்வொன்றும் ஒற்றை உள்நுழைவை வைத்திருக்கின்றன. அது இல்லை என்றால் CLI ஐ நிறுவுகிறது. ஒரு வழங்குநருக்கான முதல் கணக்கு உங்கள் சாதாரண உலாவி வழியாக உள்நுழைகிறது, CLI எப்போதும் பார்க்கும் இடத்திலேயே. அதன் பிறகு ஒவ்வொன்றும் ஒரு தனிப்பட்ட சாளரம் வழியாக உள்நுழைகிறது, எனவே உங்கள் உலாவி ஏற்கனவே உள்நுழைந்துள்ள கணக்கு தவறுதலாக எடுக்கப்படாது; நீங்கள் சேர்க்கும் கணக்காக அங்கு உள்நுழையவும், மேலும் நீங்கள் ஏற்கனவே திறந்து வைத்திருந்த எந்த தனிப்பட்ட சாளரத்தையும் முதலில் மூடவும். இதைச் செய்ய ஒருபோதும் CLI இலிருந்து வெளியேற வேண்டாம்: வெளியேறுவது சேமிக்கப்பட்ட உள்நுழைவை ரத்து செய்கிறது, மேலும் அந்தக் கணக்கு மீண்டும் சேர்க்கப்பட வேண்டியிருக்கும்.

உங்கள் சந்தா உள்நுழைவுகளை SSH வழியாக மற்றொரு Omarchy கணினிக்கு நகலெடுக்க, `omarchy agent account copy user@laptop` ஐ இயக்கவும். இலக்கில் ஒன்று நிறுவப்படவில்லை என்றால் அனுப்புநர் தற்காலிக பெறுநரை வழங்குகிறார், எனவே பழைய Omarchy கணினிகள் புதுப்பிப்பு இல்லாமல் கணக்குகளைப் பெற முடியும். நிறுவப்பட்ட பெறுநர்கள் முன்னுரிமை பெறுகிறார்கள். இது அனைத்து Claude, Codex, மற்றும் Grok சந்தாக்களையும் நகலெடுக்கிறது; அவற்றைத் தேர்ந்தெடுக்க வழங்குநர் பெயர்களைச் சேர்க்கவும், `omarchy agent account copy laptop claude` இல் உள்ளது போல. கணக்குப் பெயர்கள் மற்றும் கட்டளை IDகள் மூலத்துடன் பொருந்துகின்றன, இலக்கில் ஏற்கனவே உள்ள கணக்குகள் உட்பட. தொடர்பில்லாத இலக்குக் கணக்குகள் அவற்றின் பெயர்கள் முரண்பட்டால் எண் பின்னொட்டைப் பெறுகின்றன, மேலும் அமைப்புகள், ஸ்கில்கள், பிளகின்கள், மற்றும் உரையாடல் வரலாறு ஒவ்வொரு கணினிக்கும் உள்ளூராகவே இருக்கும்.

ஏற்கனவே உள்ள இலக்கு நற்சான்றுகள் வைக்கப்படுகின்றன. அங்கு ஏற்கனவே உள்நுழைந்துள்ள மூலக் கணக்கு அதன் நற்சான்றுகளை மாற்றாமல் அதன் பெயர் ஒத்திசைக்கப்படுகிறது; மற்ற கணக்குகள் அதனுடன் சேர்க்கப்படுகின்றன. பொருந்தும் கணக்குகளுக்கான சேமிக்கப்பட்ட நற்சான்றுகளை மாற்ற, இலக்கில் அந்தக் கணக்கின் அமர்வுகளை விட்டு வெளியேறிய பிறகு `omarchy agent account copy --replace laptop claude` ஐப் பயன்படுத்தவும். புதிய இலக்கு மூலத்தின் செயலில் உள்ள கணக்கு மற்றும் மாற்று விருப்பங்களையும் பெறுகிறது; நிறுவப்பட்ட இலக்கு தன்னுடையவற்றை வைத்திருக்கிறது.

நற்சான்றுகள் SSH வழியாகப் பயணித்து இலக்கில் தனிப்பட்ட கோப்புகளில் சேமிக்கப்படுகின்றன, எனவே நீங்கள் நம்பும் கணினிகளுக்கு மட்டுமே நகலெடுக்கவும். இது ஒரு முறை நகல், தொடர்ச்சியான ஒத்திசைவு அல்ல. Codex புதுப்பிப்பு டோக்கன்கள் மற்றொரு கணினியால் சுழற்றப்படலாம், நகலெடுக்கப்பட்ட உள்நுழைவுக்கு புதுப்பித்தல் தேவைப்படும்; பல கணினிகளில் ஒரே நேரத்தில் பயன்படுத்த தனி உள்நுழைவுகள் மிகவும் நம்பகமான தேர்வாக இருக்கும். [Codex இன் கணக்கு அங்கீகார வழிகாட்டுதல்](https://developers.openai.com/codex/auth/ci-cd-auth) ஐப் பார்க்கவும்.

ஒரு வழங்குநருக்கு ஒரு கணக்கு செயலில் உள்ளது, மேலும் ஒவ்வொரு புதிய அமர்வும் அதுவாகவே தொடங்குகிறது: `cx`, `cy`, ஒரு சாதாரண `claude`, `codex`, அல்லது `grok`, `omarchy agent` வழியாகத் தொடங்கப்படும் எதுவும், மற்றும் `PATH` இல் CLI ஐக் கண்டறியும் ஸ்கிரிப்ட்கள் அல்லது எடிட்டர்கள். `omarchy agent account use work` உடன் மாற்றவும் (மற்றும் `omarchy agent account use main` உடன் திரும்பவும்), அல்லது பேனலில் ஒரு கணக்கின் எண்ணை அழுத்தி பின்னர் `Enter` ஐ அழுத்துவதன் மூலம் (அல்லது அதன் நட்சத்திரத்தைக் கிளிக் செய்வதன் மூலம்). இயங்கும் Claude அமர்வுகளும் மாறுகின்றன, அவற்றின் அடுத்த செய்தியிலிருந்து: ஒவ்வொரு Claude அமர்வும் `~/.claude` இல் இயங்குகிறது, அது எப்போதும் செயலில் உள்ள கணக்கின் உள்நுழைவை வைத்திருக்கிறது. பழைய Omarchy மூலம் ஒரு கணக்கின் சொந்தக் கோப்புறையில் தொடங்கப்பட்ட Claude அமர்வு அது வெளியேறும் வரை அந்த உள்நுழைவை வைத்திருக்கிறது, எனவே மாற்றம் அந்த அமர்வுகளைப் பெயரிட்டு அவை போனவுடன் தானாகவே முடிகிறது. இயங்கும் Codex மற்றும் Grok அமர்வுகள் அவை தொடங்கிய கணக்கிலேயே இருக்கும். உரையாடல் வரலாறு, அமைப்புகள், ஸ்கில்கள், மற்றும் பிளகின்கள் கணக்குகள் முழுவதும் பகிரப்படுகின்றன, எனவே அதே கோப்புறையில் `claude --continue` நீங்கள் புதிய கணக்கில் விட்ட இடத்திலிருந்து தொடர்கிறது.

ஒன்றுக்கு மேற்பட்ட கணக்குகளுடன், பேனல் ஒவ்வொரு கணக்கின் வரம்புகளையும் அருகருகே காட்டுகிறது, பயன்பாட்டில் உள்ளதில் நிரப்பப்பட்ட நட்சத்திரத்துடன். செயலில் உள்ள கணக்கு ஒரு வரம்பில் 95% ஐக் கடக்கும்போது Omarchy உங்களுக்கு அறிவிக்கிறது, மேலும் அறிவிப்பைக் கிளிக் செய்வது அதிக இடவசதி உள்ள கணக்கிற்கு மாற்றுகிறது. அது தானாகவே ஒருபோதும் மாற்றாது. `omarchy agent account threshold 90` உடன் வரம்பை மாற்றவும். ஒவ்வொரு கணக்கும் வரம்புக்கு மேல் இருந்தால், எந்தக் கணக்கு முதலில் விடுபடுகிறது என்பதுடன் ஒரு முறை அதைப் பற்றி கேட்பீர்கள். செயலில் உள்ள கணக்கு அதன் வரம்பிலிருந்து 15 புள்ளிகளுக்குள் இருக்கும்போது (இயல்புநிலையில் 80%), அதன் வரம்புகள் ஒவ்வொரு 15 க்கும் பதிலாக ஒவ்வொரு மூன்று நிமிடங்களுக்கும் சரிபார்க்கப்படுகின்றன.

`omarchy agent account list` ஒவ்வொரு கணக்கையும் அதன் சமீபத்திய வரம்புகளையும் காட்டுகிறது, `omarchy agent account remove work` ஒன்றை மறக்கிறது, மற்றும் `omarchy agent account rename primary Hey` ஒன்றை மறுபெயரிடுகிறது (அல்லது பேனலில் ஒரு கணக்கின் பெயரைக் கிளிக் செய்யவும்). இந்த கட்டளைகள் உங்கள் இயல்புநிலை ஏஜென்டின் கணக்குகளில் வேலை செய்கின்றன; மற்ற வழங்குநரை அடைய, முதலில் அதைப் பெயரிடவும், `omarchy agent account use codex side` இல் உள்ளது போல. `~/.claude` அல்லது `~/.codex` இல் நீங்கள் ஏற்கனவே வைத்திருந்த உள்நுழைவு _Main_ கணக்கு ஆகும். Codex இனுடையது அது இருக்கும் இடத்திலேயே இருக்கும்; Claude இனுடையது மற்றொரு கணக்கு செயலில் இருக்கும்போது தனக்கான கோப்புறையில் காத்திருக்கிறது. சுமார் எட்டு மணி நேரத்திற்கும் மேலாகப் பயன்படுத்தப்படாத கணக்கு _Sign-in required_ எனக் காட்டக்கூடும்; பேனலிலேயே அந்தக் கணக்கில் மீண்டும் உள்நுழைய அதைக் கிளிக் செய்யவும், அல்லது அதற்கு மாறி ஒரு அமர்வைத் தொடங்கவும், அது தானாகவே உள்நுழைவைப் புதுப்பிக்கிறது. நீங்கள் `claude mcp add` உடன் சேர்க்கும் MCP சர்வர்கள் ஒவ்வொரு Claude கணக்கையும் அடைகின்றன, ஏனெனில் அவை அனைத்தும் `~/.claude` இல் இயங்குகின்றன; Codex மற்றும் Grok க்கு, ஒரு கணக்கு சேர்க்கப்பட்டபோது உங்களிடம் இருந்த சர்வர்கள் அதற்கு வருகின்றன, ஆனால் பிந்தையவை நீங்கள் அவற்றைச் சேர்த்த கணக்கை மட்டுமே அடைகின்றன. Claude Desktop தனக்கான உள்நுழைவை வைத்திருக்கிறது, மேலும் CLI பைனரிக்கு முழுமையான பாதையுடன் உள்ளமைக்கப்பட்ட Codex அல்லது Grok கருவிகள் மாற்றத்தைப் பின்தொடராது. வெளிப்படையான `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, அல்லது `GROK_HOME` தேர்ந்தெடுக்கப்பட்ட கணக்கை விட முன்னுரிமை பெறுகிறது.

### செயலிழப்பு கண்டறிதல்

Omarchy செயல்முறை செயலிழப்புகளுக்கு systemd-coredump ஐக் கண்காணிக்கிறது. நீங்கள் இயல்புநிலை ஏஜென்டைத் தேர்ந்தெடுத்த பிறகு, கோர் டம்ப் செய்யும் உங்கள் எந்த நிரலும் "Process crashed" அறிவிப்பைக் கொண்டு வருகிறது — அதைக் கிளிக் செய்யவும், மேலும் செயலிழப்பு உங்கள் இயல்புநிலை ஏஜென்டிடம் Omarchy இன் omarchy-diagnose-crash ஸ்கில்லுடன் ஒப்படைக்கப்படுகிறது, அது கோர் டம்பிலிருந்து உண்மைகளை நிறுவுவதிலும் செயலிழப்பு மேல்நிலையில் அறிக்கை செய்யத் தகுதியானதா என முடிவு செய்வதிலும் ஏஜென்டை வழிநடத்துகிறது. நீங்கள் அதை `coredumpctl list` இலிருந்து எந்த PID க்கும் எதிராக `omarchy agent crash <pid>` உடன் கைமுறையாகவும் இயக்கலாம்.

கண்காணிப்பு இயல்பாகவே இயக்கத்தில் உள்ளது. அதை _Trigger > Toggle > Crash Capture Off_ இன் கீழ் அணைக்கவும் (அல்லது `omarchy toggle crash-capture` உடன்) மற்றும் அறிவிப்புகள் நிற்கும்; `omarchy agent crash <pid>` இன்னும் கைமுறையாக வேலை செய்கிறது.

செயலிழப்புகளை ஒரு நேரத்தில் ஒரு நிரல் வீதமும் அமைதிப்படுத்தலாம், அதையே கண்டறிதல் இறுதியில் உங்களுக்கு வழங்குகிறது. `omarchy crash mute hyprland` அந்த நிரலுக்கு மட்டும் அறிவிப்புகளை நிறுத்துகிறது, `omarchy crash mute hyprland off` அவற்றைத் திரும்பக் கொண்டு வருகிறது, மேலும் `omarchy crash mute` தனியாக நீங்கள் அமைதிப்படுத்தியதைப் பட்டியலிடுகிறது. அது பைனரியின் பாதையை அதன் பெயரைப் போலவே மகிழ்ச்சியுடன் எடுக்கிறது, எனவே `omarchy crash mute /usr/bin/hyprland` அதே விஷயத்தைச் செய்கிறது. இடைவெளி உள்ள பெயரை மேற்கோள் காட்டவும், `omarchy crash mute 'Some App'` இல் உள்ளது போல. மற்ற அனைத்தும் இன்னும் அறிவிக்கின்றன, மேலும் அமைதிப்படுத்தப்பட்ட நிரல் இன்னும் செயலிழக்கிறது — இது நினைவூட்டலை மறைக்கிறது, அது எதையும் சரிசெய்யாது.

### டெஸ்க்டாப் பயன்பாடுகள்

_Install > AI_ மெனு சில வரைகலை AI பயன்பாடுகளையும் கொண்டுள்ளது: Amp Desktop, Antigravity Desktop, ChatGPT டெஸ்க்டாப் பயன்பாடு, Claude டெஸ்க்டாப் பயன்பாடு (Anthropic இன் Linux பீட்டா, Chat, Cowork, மற்றும் Claude Code டேப்களுடன்), xAI இன் மாடல்களுடன் அரட்டை அடிக்க Grok Bot, Herdr Desktop, Hermes Desktop, OpenClaw, Perplexity டெஸ்க்டாப் பயன்பாடு, மற்றும் T3 Code. Grok Bot டெஸ்க்டாப் அரட்டை பயன்பாடு ஆகும். கோடிங் ஏஜென்ட் `grok` கட்டளை ஆகும்.

Hermes Desktop தான் தெரிந்து கொள்ள வேண்டியது, ஏனெனில் ஒரு கணினியில் ஒரு Hermes உள்ளது, மேலும் அது பயன்பாட்டினுடையது: Hermes எப்போதும் பயன்பாடு வழியாக மட்டுமே நிறுவப்படுகிறது, மேலும் இயல்புநிலை ஏஜென்ட் இயக்கும் `hermes` கட்டளை பயன்பாட்டினுடையது. Hermes ஐ இயல்புநிலை ஏஜென்டாகத் தேர்ந்தெடுப்பது _Install > AI_ உள்ளீடு செய்வதையே நிறுவுகிறது: தொகுப்பு, மற்றும் Hermes இன் சொந்த நிறுவியால் அமைக்கப்பட்ட `~/.hermes` இன் கீழ் ஒரு Hermes இயக்கநேரம், அது முதல் முறை சில நிமிடங்கள் எடுக்கிறது. அந்த இயக்கநேரம் தான் டெர்மினல் `hermes` கட்டளை, இயல்புநிலை ஏஜென்ட் மற்றும் பயன்பாடு அனைத்தும் பயன்படுத்தும் ஒரே Hermes, மேலும் அது Omarchy வெளியீட்டிற்காகக் காத்திராமல் `hermes update` உடன் தன்னைப் புதுப்பிக்கிறது. அதை நிறுவுவது Hermes க்கு Omarchy தீமை `omarchy` என்ற பெயரிடப்பட்ட தோலாகவும் வழங்குகிறது, அதை ஒவ்வொரு Hermes மேற்பரப்பும் நீங்கள் தீம்களை மாற்றும்போது பின்தொடர்கிறது; நீங்கள் அது வேண்டாம் என்றால் Hermes இன் Appearance அமைப்புகளின் கீழ் அல்லது `/skin` உடன் மற்றொன்றைத் தேர்ந்தெடுக்கவும், மேலும் Omarchy அந்தத் தேர்வைத் தனியாக விட்டுவிடுகிறது. _Remove > AI_ இன் கீழ் பயன்பாட்டை அகற்றுவது Hermes ஐ முதலில் மூடுகிறது, கேட்வே உட்பட, அந்த இயக்கநேரத்தை அதனுடன் எடுக்கிறது, மேலும் நீங்கள் வேறுவிதமாகச் சொன்னால் தவிர உங்கள் அரட்டைகள், நினைவுகள், மற்றும் Hermes தனக்காக எழுதிய ஸ்கில்களை வைத்திருக்கிறது: அந்தத் தரவும் உங்கள் இணைப்பு அமைப்புகளும் போக வேண்டுமா என அது கேட்கிறது, இயல்புநிலை இல்லை என்பதாக.

OpenClaw இன் டெஸ்க்டாப் அனுபவம் அதன் Control UI ஆகும், அது அதன் சொந்த உள்ளூர் கேட்வேயால் ஆதரிக்கப்படும் வலைப் பயன்பாடாகத் திறக்கிறது. OpenClaw `~/.openclaw` இல் வாழ்கிறது மற்றும் தன்னைப் புதுப்பிக்கிறது: Control UI இன் "Update Gateway" பொத்தானைப் பயன்படுத்தவும் அல்லது `openclaw update` ஐ இயக்கவும், மேலும் கேட்வே புதிய பதிப்பில் மறுதொடக்கம் செய்யும். Omarchy புதிய நிறுவல் தொடங்கும் வெளியீட்டை மட்டுமே தேர்ந்தெடுக்கிறது. OpenClaw உங்கள் இயல்புநிலை ஏஜென்டாகவும் இருக்க முடியும்: அதை `omarchy default agent openclaw` உடன் தேர்ந்தெடுப்பது `~/.openclaw` இல் அதே நகலை அமைக்கிறது, மேலும் ஏஜென்ட் OpenClaw இன் டெர்மினல் UI ஐ அதன் கேட்வேயுடன் இணைத்துத் திறக்கிறது. _Remove > AI_ இன் கீழ் OpenClaw ஐ அகற்றுவது கேட்வே சேவையையும் பயன்பாட்டையும் அதனுடன் எடுக்கிறது, பின்னர் `~/.openclaw` வும் போக வேண்டுமா எனக் கேட்கிறது, ஏனெனில் அது உங்கள் அரட்டைகள் மற்றும் நற்சான்றுகளை OpenClaw உடனும் அது பதிவிறக்கும் பிளகின் இயக்கநேரங்களுடனும் வைத்திருக்கிறது; இயல்புநிலை அதை வைத்திருக்கிறது, மேலும் OpenClaw ஐ மீண்டும் நிறுவுவது அதைத் திரும்ப எடுக்கிறது.

Herdr Desktop என்பது [Herdr](https://herdr.dev) டெஸ்க்டாப் பயன்பாடு: நீங்கள் சாளரத்தை மூடும்போது அதன் மையத்தில் தொடர்ந்து இயங்கும் டெர்மினல்கள் மற்றும் கோடிங் ஏஜென்ட்களின் இடங்கள், டேப்கள், மற்றும் பேன்கள். அது ஒரு தொகுப்பை விட Herdr இன் சொந்த நிறுவியிலிருந்து வருகிறது, எனவே அது `~/.local/share/herdr-app` இல் வாழ்கிறது, உங்களிடம் இன்னும் ஒன்று இல்லை என்றால் அதன் மையத்தை `~/.local/bin/herdr-core` இல் கொண்டு வருகிறது, மேலும் இரண்டையும் தன்னைப் புதுப்பிக்கிறது. அது Omarchy `Super + Ctrl + Return` இல் வழங்கும் `herdr` கட்டளைக்கு அருகில் அமர்கிறது, அதை மாற்றாமல், மேலும் அந்தக் கட்டளையின் நேரடி விசைகளைப் பெறுகிறது: `Alt + Return` மற்றும் `Alt + Shift + Return` ஒரு பேனை கீழே அல்லது வலதுபுறம் பிரிக்கின்றன, `Alt + Escape` அதை மூடுகிறது, `Ctrl + Alt + Arrow` பேன்களுக்கு இடையில் நகர்கிறது, `Alt + 1..9` மற்றும் `Alt + Left/Right` ஒரு டேபைத் தேர்ந்தெடுக்கின்றன, மேலும் `Alt + Up/Down` இடங்களுக்கு இடையில் நகர்கின்றன. `Ctrl + 1..9` ஒரு இடத்தைத் தேர்ந்தெடுக்கிறது மற்றும் `Alt + Shift + Up/Down` ஏஜென்ட்கள் வழியாகச் செல்கிறது. `Ctrl + Space` முன்னொட்டு விசைகள் டெர்மினலுக்கு மட்டுமே இருக்கும், ஏனெனில் பயன்பாடு ஒரு வரிசைக்கு சாதாரண Ctrl விசையை வைத்திருக்க முடியாது. Omarchy இவற்றை `~/.config/herdr-app/keys.json` இல் எழுதுகிறது, மேலும் `omarchy-refresh-herdr-app` அவற்றைத் திரும்ப வைக்கிறது. அதை நிறுவுவது Herdr இன் Omarchy தீமைத் தேர்ந்தெடுக்கிறது, அது அப்போதிலிருந்து உங்கள் Omarchy தீமைப் பின்தொடர்கிறது. Herdr ஒளி முறைக்கு ஒரு தீமையும் இருள் முறைக்கு ஒரு தீமையும் வைத்திருக்கிறது, எனவே இருள் மற்றும் ஒளி Omarchy தீமுக்கு இடையில் மாறிய பிறகு, மற்ற முறைக்கு Herdr இன் தீம் தேர்வியில் Omarchy ஐ மீண்டும் ஒரு முறை தேர்ந்தெடுக்கவும்.

T3 Code ஒரு தொகுப்பிலிருந்து அல்லாமல் `~/.local/share/t3code` இல் அதன் அதிகாரப்பூர்வ AppImage வெளியீட்டிலிருந்து இயங்குகிறது, எனவே அது தன்னைப் புதுப்பிக்கிறது. அதை நிறுவுவது Stable அல்லது Nightly சேனலில் தொடங்க வேண்டுமா எனக் கேட்கிறது; பின்னர் T3 Code இன் அமைப்புகளில் மாற்றவும். உங்கள் திரெட்கள் மற்றும் அமைப்புகள் `~/.t3` இல் வாழ்கின்றன, மேலும் _Remove > AI_ இன் கீழ் T3 Code ஐ அகற்றுவது அவற்றை அதனுடன் எடுக்கிறது.

### உள்ளூர் மாடல்கள்

உங்கள் கோடிங் ஏஜென்ட்களுக்காக உங்கள் சொந்தக் கணினியில் ஒரு திறந்த மாடலை இயக்கவும். உங்கள் ப்ராம்ப்டுகளும் கோடும் கணினியிலேயே இருக்கும்; மாடலுக்கு அனுப்பப்படும் எதுவும் அதை விட்டு வெளியேறாது. இதனுடன் தொடங்கவும்:

```bash
omarchy models use best text
```

அது இந்தக் கணினிக்கான சிறந்த உரை மாடலை அமைக்கிறது, உங்கள் ஏஜென்ட்கள் பயன்படுத்தும் வகை. படம், வீடியோ மற்றும் இசை மாடல்களுக்கு அவற்றுக்கான சிறந்தது உள்ளது: `omarchy models use best image`, `video` அல்லது `music`. இந்தக் கணினிக்கான ஒவ்வொரு வகையின் தேர்வையும் பார்க்க `omarchy models use best` ஐ இயக்கவும்.

அல்லது ஏஜென்ட்கள் பேனலில் + ஐத் தேர்ந்தெடுக்கவும்: _உள்ளூர் மாடலைப் பயன்படுத்தவும்_ இன் கீழ் அது இந்தக் கணினிக்குப் பொருந்தும் ஒவ்வொரு கோடிங் மாடலையும் பட்டியலிடுகிறது, பரிந்துரைக்கப்பட்டது முதலில். மாடல்களை இயக்கும் Podman, Omarchy உடன் வருகிறது, NVIDIA கணினியில் NVIDIA இன் கண்டெய்னர் கருவித்தொகுப்பும் வருகிறது, அது அவற்றுக்கு GPU ஐ வழங்குகிறது; ஏதேனும் ஒன்று இல்லை என்றால், முதல் அமைப்பு அதை நிறுவுகிறது. பின்னர் Omarchy இந்தக் கணினிக்கான பரிந்துரைக்கப்பட்ட மாடலைத் தேர்ந்தெடுத்து, அதைப் பதிவிறக்கி, தொடங்குகிறது. பத்துகள் GB பதிவிறக்கத்தையும், மாடல் இயங்கும்போது கணினியின் நினைவகத்தின் பெரும்பகுதி பயன்பாட்டில் இருப்பதையும் எதிர்பார்க்கவும்: Flash Next அதன் முழு 256K சூழலுடன் சுமார் 100 GiB ஐப் பயன்படுத்துகிறது. மற்ற மாடல்கள் அதற்குத் தேவையான நினைவகத்தை வைத்திருந்தால், அது நிறுத்தப்பட்ட நிலையில் அமைக்கப்படுகிறது, நீங்கள் ஒன்றை நிறுத்தியவுடன் தொடங்கத் தயாராக. மாடல் வெளியேறும்போது நிற்கிறது; உங்களுக்கு வேறு ஏதாவதுக்கு நினைவகம் தேவைப்படும்போது அதை நீங்களே நிறுத்தவும்.

`omarchy models list` விருப்பங்களைக் காட்டுகிறது மற்றும் சில ஏன் பொருந்தவில்லை என்பதை விளக்குகிறது. மற்றொன்றை அமைக்க, `omarchy models use <recipe>` ஐ இயக்கவும். இன்று, `qwen3.8-flash-next-gufo` மற்றும் `qwen3.8-27b-gufo` 128 GB Strix Halo கணினிகளுக்குக் கிடைக்கின்றன; 27B சுமார் 40 GiB எடுக்கிறது, எனவே அது மற்ற வேலைகளுக்கு இடம் விடுகிறது. Intel இன் Arc B390 உடன் 64 GB மடிக்கணினியில், `qwen3.6-35b-a3b-llamacpp` சுமார் 30 GiB இல் இயங்குகிறது. புதிய சமையல் குறிப்புகளும் பரிந்துரைகளும் `omarchy update` உடன், தொகுப்பு வழியாக வருகின்றன.

நீங்கள் சேர்க்கும் கோடிங் மாடல் ஏஜென்ட்கள் பேனலில், உங்கள் சந்தாக்களுக்கு அருகில், தனக்கான வரியைப் பெறுகிறது: அதைத் தொடங்க play, அதை நிறுத்தி அதன் நினைவகத்தை விடுவிக்க pause, அது இயங்கும்போது உங்கள் tailnet இல் உள்ள மற்ற கணினிகளுடன் அதைப் பகிர Tailscale குறி, மற்றும் அதில் உங்கள் ஏஜென்டைத் திறக்க டெர்மினல் பொத்தான். அதன் வரி பதிவிறக்கம், ஏற்றம் அல்லது நிறுத்தத்தை அது செல்லும்போது காட்டுகிறது, மேலும் அதைத் தொடங்க போதுமான இலவச நினைவகம் இல்லை என்றால் அவ்வாறு கூறுகிறது, அல்லது அது பிழையுடன் நின்றால் அதன் பதிவுகளுக்கு இணைக்கிறது. நினைவகத்தில் ஒன்றாகப் பொருந்தும்போது பல ஒரே நேரத்தில் இயங்க முடியும். தேர்ந்தெடுக்கப்பட்ட வரியில் Delete ஐ அழுத்தி மாடலை இந்தக் கணினியிலிருந்து அகற்றவும், பதிவிறக்கமும் உட்பட; + அதை மீண்டும் அமைக்க முடியும். டெர்மினலிலிருந்து அமைக்கப்பட்ட கோடிங் மாடல் நீங்கள் அதைச் சேர்க்கும் வரை + இன் கீழ் காத்திருக்கிறது, மேலும் நீங்கள் இணைத்த கணினி (`omarchy models pair <host>`) இயக்கும் மாடல்களும் அவ்வாறே.

நீங்கள் அமைக்கும் ஒவ்வொரு கோடிங் மாடலும் பயன்பாட்டு லாஞ்சரில் தனக்கான உள்ளீட்டையும் பெறுகிறது, மாடலின் பெயரின் கீழ் மற்றும் அதன் தயாரிப்பாளரின் லோகோவுடன், Claude, Codex அல்லது Grok இல் உள்நுழைவது ஒன்றைச் சேர்ப்பது போல. அது அந்த மாடலில் உங்கள் ஏஜென்டைத் திறக்கிறது, மேலும் அது இயங்கவில்லை என்றால் முதலில் மாடலைத் தொடங்குகிறது: டெர்மினல் அது ஏற்றப்படுவதைக் காட்டி அது தயாரானவுடன் ஏஜென்டிடம் ஒப்படைக்கிறது. மாடலை அகற்றுவது அதன் உள்ளீட்டை அகற்றுகிறது.

ஒவ்வொரு மாடலும் கோடிங்கிற்காக அல்ல. படம், வீடியோ மற்றும் இசை மாடல்கள் அதற்குப் பதிலாக Fantasi இல் திறக்கின்றன, இந்தக் கணினியில் இயங்கும் மாடலைக் கொண்டு படங்கள், வீடியோ மற்றும் இசையை உருவாக்குவதற்கான Omarchy இன் பயன்பாடு, மேலும் அங்கே அல்லது `omarchy models` உடன் நிர்வகிக்கப்படுகின்றன.

ஒரு மாடல் அது அமைக்கப்பட்டபடியே தொடர்ந்து இயங்குகிறது, எனவே Omarchy புதுப்பிப்பு ஒருபோதும் உங்கள் ஏஜென்ட்களின் கீழ் ஒன்றை மறுதொடக்கம் செய்யாது. நீங்கள் அமைத்த மாடலுக்கு Omarchy இல் புதிய இயக்கநேரம் அல்லது புதிய எடைகள் இருக்கும்போது, அதன் வரி புதுப்பிப்பு பொத்தானைக் காட்டுகிறது: அதை அழுத்தவும், மாடல் பின்னணியில் மீண்டும் அமைக்கப்படுகிறது, மாறியதை மட்டும் பதிவிறக்கி, புதிய பதிப்பில் மறுதொடக்கம் செய்யும். நிறுத்தப்பட்ட மாடல் நிறுத்தப்பட்டே இருக்கும். `omarchy models update` டெர்மினலிலிருந்து ஒவ்வொரு மாடலுக்கும் அதையே செய்கிறது.

கட்டளை வரியிலிருந்து, `omarchy models start <recipe>` மற்றும் `omarchy models stop <recipe>` அதையே செய்கின்றன, `omarchy models status` ஒவ்வொரு மாடலையும் காட்டுகிறது, மேலும் `omarchy agent --local-model <recipe>` உங்கள் இயல்புநிலை ஏஜென்ட் எதுவாக இருந்தாலும் அந்த மாடலை pi இல் திறக்கிறது. உங்கள் உள்ளூர் மாடலை ஏஜென்ட் ஹாட்கீ, Quake கன்சோல், மற்றும் _ஏதாவது உருவாக்கவும்_ திறக்கும் விஷயமாக மாற்ற, `omarchy default agent local` ஐ இயக்கவும் அல்லது ஏஜென்ட்கள் பேனலில் இயங்கும் மாடலை நட்சத்திரமிடவும். pi நீங்கள் அமைத்த ஒவ்வொரு மாடலையும், மற்றும் நீங்கள் இணைத்த கணினிகளில் உள்ளவற்றையும், அதன் சொந்த மாடல் தேர்வியில் பட்டியலிடுகிறது, எனவே சாதாரண `pi` அவற்றையும் அடைகிறது. எந்த OpenAI-இணக்கமான கிளையண்டும் இணைக்க முடியும்: `status` ஒவ்வொரு மாடலின் முகவரியையும் காட்டுகிறது (முதலாவது `http://127.0.0.1:11435/v1`), சமையல் குறிப்பு பெயர் மாடல், மற்றும் விசை `~/.config/omarchy/agent-local/key` இல் உள்ளது.

`omarchy models remove <recipe>` ஒரு மாடலையும் வேறு எந்த மாடலும் பயன்படுத்தாத பதிவிறக்கங்களையும் நீக்குகிறது.

மூன்றாம் தரப்பு இயக்கநேரங்கள் அவற்றின் வெளியீட்டாளருடன் குறிக்கப்படுகின்றன. Omarchy ஒவ்வொரு மாடலையும் பிணைய அணுகல் இல்லாமல் இயக்குகிறது.

### உள்ளூர் LLMகள்

Omarchy உள்ளூர் LLM மாடல்களை இயக்க இரண்டு வழிகளைப் பரிந்துரைக்கிறது: LM Studio மற்றும் Ollama. LM Studio திறந்த-எடை மாடல்களைக் கண்டறிவதற்கும், நிறுவுவதற்கும், இயக்குவதற்கும் GUI இடைமுகத்தை வழங்குகிறது. எளிதாகத் தொடங்க இது ஒரு சிறந்த வழி. Ollama இதேபோல் செய்ய CLI ஐ வழங்குகிறது. ஆனால் நீங்கள் உள்ளூர் மாடல்களுக்குப் புதியவராக இருந்தால், நான் LM Studio உடன் தொடங்குவேன். Omarchy மெனுவில் _Install > AI_ இன் கீழ் இரண்டில் ஒன்றையும் நிறுவலாம்.

### Omarchy ஸ்கில்கள்

ஏஜென்ட் ஸ்கில்கள் AI குறிப்பிட்ட கருவிகளை குறிப்பிட்ட வழியில் பயன்படுத்த உதவுகின்றன, மேலும் Omarchy அவற்றில் ஏழை வழங்குகிறது. omarchy ஸ்கில் உங்கள் Hyprland உள்ளமைவை மாற்றுவது அல்லது பட்டியை சரிசெய்வது போல கணினியைத் தனிப்பயனாக்குவதை உள்ளடக்குகிறது. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app, மற்றும் omarchy-make-game புதிதாக ஏதாவது உருவாக்குவதை உள்ளடக்குகின்றன, omarchy-contribute ஒரு பிழையை அறிக்கை செய்வது அல்லது மேல்நிலைக்கு திருத்தத்தை அனுப்புவதை உள்ளடக்குகிறது, மற்றும் omarchy-diagnose-crash ஒரு செயலிழப்பின் கோர் டம்ப் வழியாக வேலை செய்கிறது. அவை Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` மற்றும் ஒவ்வொரு `~/.hermes/profiles/*/skills`), மற்றும் பொதுவான `~/.agents/skills` இருப்பிடத்திற்கான ஸ்கில் கோப்பகங்களில் சிம்லிங்க் செய்யப்பட்டுள்ளன, எனவே பெரும்பாலான harness கள் அவற்றைத் தானாகவே எடுக்கின்றன. அதே பெயரைக் கொண்ட உங்கள் சொந்த ஸ்கில் கோப்புறை முன்னுரிமை பெறுகிறது.

ஆனால் நீங்கள் இந்த ஸ்கில்களை சோதனை முயற்சியாகக் கருத வேண்டும். வெவ்வேறு மாடல்கள் அதை வெவ்வேறு விளைவுகளுக்குப் பயன்படுத்தும். முதலில் திட்ட முறையில் இயக்குவது சிறந்தது, எனவே ஏஜென்ட் எதை மாற்ற விரும்புகிறது என்பது பற்றி உங்களுக்கு ஒரு யோசனை இருக்கும். மேலும் ஏஜென்ட் எல்லாவற்றையும் குழப்பினால், மாற்றங்களைத் திரும்பப் பெற அல்லது `omarchy reinstall configs` ஐக் கூட அழைக்கத் தயாராக இருங்கள்.
