# AI

Omarchy உங்களுக்காக ஒரு இயல்புநிலையைத் தேர்ந்தெடுக்காமல், கீழே உள்ள coding agentகளுக்கான launcherகளை உள்ளடக்கியுள்ளது. அதன் CLI ஐ முதல் பயன்பாட்டில் நிறுவ ஒரு கட்டளையை இயக்கவும், பின்னர் கேட்கப்படும்போது அங்கீகரிக்கவும். Hermes மற்றும் OpenClaw விதிவிலக்குகள்: அவற்றுக்காக mise வழியாக எதுவும் நிறுவப்படுவதில்லை, மேலும் அவற்றில் ஒன்றைத் தேர்ந்தெடுப்பது அதன் சொந்த சுய-புதுப்பிப்பு நகலை அமைக்கிறது, கீழே உள்ள _Desktop apps_ விளக்குவது போல.

### Agentகளை நிறுவுதல் மற்றும் புதுப்பித்தல்

Hermes மற்றும் OpenClaw தவிர, இந்த agentகள் mise இன் lazy installation ஐப் பயன்படுத்துகின்றன: முதல் தொடக்கம் CLI ஐ நிறுவுகிறது, பிந்தைய தொடக்கங்கள் அதையே மீண்டும் பயன்படுத்துகின்றன. mise மேலும் நிறுவப்பட்ட agent க்கு ஒரு புதிய வெளியீடு உள்ளதா என நான்கு மணி நேரத்திற்கு அதிகபட்சம் ஒரு முறை, அது தொடங்குவதற்குச் சற்று முன்பு அல்லது ஒரு shell prompt இல் பின்னணியில் சரிபார்க்கிறது. அந்தப் புதுப்பிப்பு தோல்வியடைந்தால் அல்லது நீங்கள் offline இல் இருந்தால், நிறுவப்பட்ட பதிப்பு இயங்கும். `omarchy update` Omarchy இன் மற்றவற்றுடன் நிறுவப்பட்ட agentகளையும் புதுப்பிக்கிறது, மேலும் `mup` mise நிர்வகிக்கும் கருவிகளை மட்டுமே புதுப்பிக்கிறது.

`claude update`, `codex update` போன்ற ஒரு agent இன் சொந்த updater, அல்லது ஒரு பயன்பாட்டில் உள்ள ஒரு update பொத்தான், mise நிர்வகிக்கும் நிறுவலைப் புதுப்பிக்காது. `codex update` தோல்வியடைகிறது, மேலும் `claude update` mise கண்காணிக்காத ஒரு தனி நகலை நிறுவிக்கொண்டே வெற்றி என அறிவிக்கலாம். நீங்கள் ஒரு agent இன் சொந்த installer மற்றும் updater ஐப் பயன்படுத்த விரும்பினால், அதை `disable_tools` இல் சேர்க்கவும்; [முன்நிறுவப்பட்ட CLI கருவிகள்](18-development-tools.md#preinstalled-cli-tools) ஐப் பார்க்கவும்.

உங்களுக்குத் தேவைப்படுவதற்கு முன்பே உள்ளமைக்கப்பட்ட அனைத்து lazy கருவிகளையும் நிறுவ, `mise install --include-lazy` ஐ இயக்கவும். இதில் agentகளுடன் Omarchy இன் மற்ற இயல்புநிலை CLI கருவிகளும் அடங்கும். ஒரு ஒற்றைக் கருவியை நிறுவுவது அல்லது உங்கள் சொந்த நிறுவலைப் பயன்படுத்துவது பற்றி [முன்நிறுவப்பட்ட CLI கருவிகள்](18-development-tools.md#preinstalled-cli-tools) ஐப் பார்க்கவும்.

`grok` mise இன் first-party `grok` package வழியாக, `claude` மற்றும் `codex` போலவே அதே வழியில் நிறுவப்படுகிறது. `grok` ஐ இயக்கவும், அல்லது _Agent > Harness_ இன் கீழ் அதைத் தேர்ந்தெடுக்கவும். x.ai இல் உள்ள `curl | bash` installer ஐத் தவிர்க்கவும். அந்த வழி இரண்டாவது நகலை `~/.grok/bin` இல் வைக்கிறது, அதை `PATH` இல் முன்னால் சேர்க்கிறது, மேலும் Omarchy இன் wrapper ஐ மேலெழுதுகிறது.

`dsh` அதன் browser UI ஐ `127.0.0.1:3080` இல் திறக்கிறது, தொடக்க அடைவை அதன் இயல்புநிலை workspace ஆகக் கொண்டு. அதன் browser UI எந்தத் தொடக்க prompt ஐயும் எடுத்துக்கொள்ளாது, எனவே `omarchy agent prompt` அதை ஒட்டுவதற்காக உங்கள் clipboard இல் prompt உடன் திறக்கிறது. Omarchy அதை DeepSeek இன் no-approval permission preset உடன் தொடங்குகிறது. DeepSeek Harness நீங்கள் அதன் அதிகாரப்பூர்வ model API ஐப் பயன்படுத்தும்போது session logகளை DeepSeek க்கு பதிவேற்றுகிறது; அதன் browser UI இல் _Settings > General > Upload Session Log_ இன் கீழ் அதை அணைக்கவும். நீங்கள் அதற்கு அனுப்பும் கருத்தும் session உடன் சேர்த்து பதிவேற்றப்படுகிறது, நீங்கள் அதை `DSH_TELEMETRY_MODE=DISABLED` உடன் தொடங்கினால் தவிர.

### இயல்புநிலை agent

`omarchy default agent <name>` உடன் அல்லது Omarchy Menu (`Super + Space`) இல் _Agent > Harness_ இன் கீழ் உங்கள் இயல்புநிலை agent ஐத் தேர்ந்தெடுக்கவும். agent இன்னும் நிறுவப்படவில்லை என்றால், அதைத் தேர்ந்தெடுப்பது முதலில் அதை நிறுவுகிறது, மேலும் அது app launcher இல், Agent க்கு அடுத்து, அதற்கே உரிய ஒரு launcher ஐயும் பெறுகிறது. ஒரு புதிய Omarchy ஒரு முறை மட்டுமே வரும் அறிவிப்புடன் இந்தத் தேர்வைச் செய்ய உங்களை அழைக்கும்.

Claude ஐத் தேர்ந்தெடுப்பது Chromium, Chrome, Brave, Brave Origin, மற்றும் Edge க்காக அதன் browser extension ஐ அமைக்கவும் முயற்சிக்கிறது. extension அமைப்பு அனைத்து பயனர்களுக்கும் பொருந்தும் மற்றும் உங்கள் system password ஐக் கேட்கலாம்; ரத்து செய்வது அல்லது தோல்வியடைந்த extension நிறுவல் இருந்தாலும் Claude தேர்ந்தெடுக்கப்பட்டு தொடங்கப்படும். உங்கள் browser ஐ மறுதொடக்கம் செய்யவும், கேட்கப்பட்டால் extension ஐ இயக்கவும், மேலும் அதை இணைப்பதை முடிக்க Claude இல் உள்நுழையவும். இணைப்பைச் சரிபார்க்க Claude இல் `/chrome` ஐ இயக்கவும். Firefox மற்றும் Zen இந்த extension ஐ ஆதரிக்காது. இந்த அமைப்பு சேர்க்கப்படுவதற்கு முன்பே Claude ஏற்கனவே உங்கள் இயல்புநிலையாக இருந்திருந்தால், extension ஐ நிறுவ அதை மீண்டும் தேர்ந்தெடுக்கவும்.

நீங்கள் தேர்ந்தெடுத்த பிறகு, `Super + Shift + Ctrl + A` இயல்புநிலை agent ஐ ஒரு பிரத்யேக terminal window இல் தொடங்குகிறது (அல்லது நீங்கள் இன்னும் தேர்ந்தெடுக்கவில்லை என்றால் picker ஐக் கொண்டு வருகிறது). நீங்கள் அதை `omarchy agent prompt "Review this project"` உடன் நேரடியாக ஒரு பணியில் தொடங்கவும் முடியும். Freebuff மற்றும் DeepSeek Harness எந்தத் தொடக்க prompt ஐயும் எடுத்துக்கொள்ளாது, எனவே அவை அதற்குப் பதிலாக ஒட்டுவதற்காக உங்கள் clipboard இல் prompt உடன் திறக்கின்றன. இந்த வழியில் தொடங்கப்படும் Agentகள் அவற்றின் அந்தந்த don't-stop-to-ask முறைகளில் கவனிக்கப்படாமல் இயங்குகின்றன, எனவே அவை உண்மையில் விஷயங்களைச் செய்யத் தயாராக இருங்கள்! MiniMax Code அதன் interactive sessionகளுக்கு அத்தகைய முறை எதையும் கொண்டிருக்கவில்லை, எனவே அது வழக்கம் போல் அனுமதிகளைக் கேட்கிறது. மேலும் agentகள் உங்கள் home அடைவுக்கான நம்பிக்கையை நினைவில் வைக்க மறுப்பதால், `$HOME` இலிருந்து தொடங்குவது அதற்குப் பதிலாக `~/Work` இல் தொடங்குகிறது.

terminal shortcutகளும் உள்ளன: `a` தற்போதைய terminal இல் இயல்புநிலை agent ஐ inline ஆக இயக்குகிறது, அதே நேரத்தில் `c`, `cx`, மற்றும் `cy` OpenCode, Claude Code, மற்றும் Codex ஐ நேரடியாகத் தொடங்குகின்றன (மீண்டும் அவற்றின் auto-approving முறைகளில்). Theme மாற்றங்களும் agentகளுக்கு ஒத்திசைகின்றன: நீங்கள் Omarchy theme ஐ மாற்றும்போது Claude Code, Pi, OpenCode, மற்றும் Hermes (Omarchy அதை நிறுவிய பிறகு) அனைத்தும் அதனுடன் சேர்ந்து பின்தொடர்கின்றன.

### உங்கள் agent அறிவுறுத்தல்கள்

ஒவ்வொரு agent க்கான தனிப்பட்ட விதிகளும் `~/.agents/skills` இல் உள்ள பகிரப்பட்ட skillகளுக்கு அடுத்து `~/.agents/AGENTS.md` இல் செல்கின்றன. அதை _Agent > Instructions_ இன் கீழ் திறக்கவும், இது அதைத் தன் சொந்த global கோப்பை வைத்திருக்கும் ஒவ்வொரு harness இலும் இணைக்கிறது: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, Copilot இன் `~/.copilot/copilot-instructions.md`, மற்றும் பல. Crush மற்றும் Amp `~/.config/AGENTS.md` இணைப்பைப் படிக்கின்றன, அதே நேரத்தில் omp, Kimi, மற்றும் DeepSeek Harness `~/.agents/AGENTS.md` ஐ நேரடியாகப் படிக்கின்றன. ஒரு இயல்புநிலை agent ஐத் தேர்ந்தெடுப்பதும் அதை இணைக்கிறது. நீங்கள் ஏற்கனவே வைத்திருந்த ஒரு அறிவுறுத்தல் கோப்பு, இன்னும் எதுவும் இல்லை என்றால் பகிரப்பட்டதாக மாறுகிறது; இல்லையெனில் அது இணைப்புக்கு அருகில் `.bak` ஆக வைக்கப்படுகிறது. மற்றொரு agent ஐ நிறுவிய பிறகு மீண்டும் இணைக்க `omarchy agent instructions` ஐ இயக்கவும்.

### Agentகள் panel

மேல் பட்டியில் ஒரு agentகள் icon உள்ளது. நீங்கள் ஒரு agent ஐ அமைப்பதற்கு முன்பு, அதன் panel Claude, Codex, அல்லது Grok இல் உள்நுழைவதன் வழியாக உங்களை வழிநடத்துகிறது, மேலும் முதலாவது உங்கள் இயல்புநிலை agent ஆக மாறுகிறது. அதன் பிறகு, panel ஒவ்வொரு சந்தாவையும் ஒரே பக்கத்தில் வைக்கிறது: ஒவ்வொரு agent மற்றும் கணக்கும் அதன் திட்டத்துடன், அதன் 5 மணி நேர session மற்றும் வாராந்திர வரம்புகள் ஒவ்வொன்றுக்கும் ஒரு meter உடன் அது மீட்டமைக்கப்படும் வரையிலான நேரத்துடன் (சரியான சதவீதத்திற்கு hover செய்யவும்), அல்லது மீதமுள்ள prepaid இருப்பு, அவை அனைத்திலும் நீங்கள் பயன்படுத்தியதைச் சுழற்றும் ஒரு வரியின் கீழ், இந்த வாரம் பயன்படுத்திய tokenகள் மற்றும் நீங்கள் மிகவும் பயன்படுத்திய model போல. _Make something cool_ இன் கீழ் இது புதிய theme, plugin, app, அல்லது game க்கான starter promptகளை வழங்குகிறது, அவை பணியை உங்கள் இயல்புநிலை agent இடம் ஒப்படைக்கின்றன. பயன்பாடுகள் Omarchy இன் சொந்த Hype, Monologue, மற்றும் Omacut கட்டமைக்கப்பட்ட விதத்தில், C++ மற்றும் Qt Quick இல், omarchy-make-app agent skill ஐப் பின்பற்றி கட்டமைக்கப்படுகின்றன, மேலும் அவற்றுக்குத் தேவையான compiler மற்றும் Qt பகுதிகள் நிறுவப்பட்டு வருகின்றன. விளையாட்டுகள் omarchy-make-game agent skill ஐப் பின்பற்றி `~/Games/vibes` இல் உள்ள ஒரு ஒற்றை three.js பக்கம், மேலும் அனைத்தும் தற்போதைய theme இல் ஒரு Game Vibes launcher இலிருந்து திறக்கின்றன; அவை three.js ஐ web இலிருந்து ஏற்றுகின்றன, எனவே அவை தொடங்க ஒரு இணைப்பு தேவை. Claude Code, Codex, Grok, Kimi, Cursor மற்றும் அதன் Grok Bot அனுமதி, GitHub Copilot, Muse, Antigravity, மற்றும் Devin அவற்றின் வரம்புகளுடன் பெட்டியில் இருந்தே உள்ளடக்கப்பட்டுள்ளன, Kimchi அதன் திட்டம், prepaid creditகள், மற்றும் செலவு பட்ஜெட்டுகளுடன், மேலும் Hermes, Mistral Vibe, மற்றும் Qwen Code நீங்கள் அவற்றைப் பயன்படுத்திய பிறகு அவற்றின் sessionகள் மற்றும் tokenகளைக் காட்டுகின்றன. நீங்கள் pi, omp, அல்லது opencode வழியாகப் பயன்படுத்தும் Provider திட்டங்கள் மற்றும் keyகளும் தோன்றுகின்றன: OpenCode Zen மற்றும் Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan, மற்றும் Synthetic அவற்றின் வரம்புகளுடன்; OpenRouter மற்றும் DeepSeek அவற்றின் prepaid இருப்புகளுடன்; Fireworks கடந்த 30 நாட்களில் அதன் செலவுடன். நீங்கள் உங்கள் சொந்த hardware இல் இயக்கும் modelகளிலிருந்து வரும் Tokenகளும் மொத்தங்களில் கணக்கிடப்படுகின்றன; modelகளுக்கே சொந்தமாக ஒரு panel உள்ளது, [உள்ளூர் மாடல்கள்](#local-models) இன் கீழ் விவரிக்கப்பட்டுள்ளது. ஒவ்வொரு agent ம், நீங்கள் அதை எத்தனை harnessகள் வழியாக இயக்கினாலும், அதற்கு யார் bill செய்கிறார்களோ அவரின் கீழ் ஒரு முறை மட்டுமே கணக்கிடப்படுகிறது.

panel க்காக பட்டி icon ஐ இடது-கிளிக் செய்யவும் அல்லது `Super + Ctrl + X` ஐ அழுத்தவும், உங்கள் இயல்புநிலை agent ஐத் தொடங்க வலது-கிளிக் செய்யவும், மற்றும் புதுப்பிக்க நடு-கிளிக் செய்யவும். அதன் பின்னால் உள்ள பயன்பாட்டுப் பதிவுகள் ஒவ்வொரு 15 நிமிடங்களுக்கும் `omarchy agent usage update` ஆல் மீண்டும் உருவாக்கப்படுகின்றன, மேலும் panel ஒரு synced கோப்புறை வழியாக உங்கள் மற்ற இயந்திரங்களிலிருந்து பயன்பாட்டைக் கூட இணைக்க முடியும். முழு அமைப்புகளுக்கு `$OMARCHY_PATH/shell/plugins/agents/` இன் கீழ் உள்ள README ஐப் பார்க்கவும்.

### பல சந்தாக்கள்

நீங்கள் ஒன்றுக்கு மேற்பட்ட Claude, Codex, அல்லது Grok திட்டத்திற்கு பணம் செலுத்தினால் — உதாரணமாக ஒரு தனிப்பட்ட Max மற்றும் ஒரு வேலைக்கானது — Omarchy அவை அனைத்தையும் உள்நுழைந்த நிலையில் வைத்திருக்கவும் அவற்றுக்கிடையே நகரவும் முடியும். agentகள் panel இல் உள்ள + உடன் ஒரு சந்தாவைச் சேர்க்கவும், அது அங்கேயே அதன் வழியாக உங்களை வழிநடத்துகிறது, அல்லது `omarchy agent account add claude Work` உடன் (அல்லது `codex`, அல்லது `grok`). அது இல்லை என்றால் CLI ஐ நிறுவுகிறது. ஒரு provider க்கான முதல் கணக்கு உங்கள் சாதாரண browser வழியாக, CLI எப்போதும் பார்க்கும் இடத்திலேயே உள்நுழைகிறது. அதன் பிறகு உள்ள ஒவ்வொன்றும் ஒரு private window வழியாக உள்நுழைகிறது, எனவே உங்கள் browser ஏற்கனவே உள்நுழைந்துள்ள கணக்கு தவறுதலாக எடுக்கப்படாது; நீங்கள் சேர்க்கும் கணக்காக அங்கு உள்நுழையவும், மேலும் நீங்கள் ஏற்கனவே திறந்து வைத்திருந்த எந்த private window ஐயும் முதலில் மூடவும். இதைச் செய்ய CLI இலிருந்து ஒருபோதும் வெளியேற வேண்டாம்: வெளியேறுவது சேமிக்கப்பட்ட உள்நுழைவை ரத்து செய்கிறது, மேலும் அந்தக் கணக்கு மீண்டும் சேர்க்கப்பட வேண்டியிருக்கும்.

உங்கள் சந்தா உள்நுழைவுகளை SSH வழியாக மற்றொரு Omarchy இயந்திரத்திற்கு நகலெடுக்க, `omarchy agent account copy user@laptop` ஐ இயக்கவும். destination இல் ஒன்று நிறுவப்படவில்லை என்றால் அனுப்புபவர் ஒரு தற்காலிக receiver ஐ வழங்குகிறார், எனவே பழைய Omarchy இயந்திரங்கள் ஒரு புதுப்பிப்பு இல்லாமல் கணக்குகளைப் பெற முடியும். நிறுவப்பட்ட receiverகளுக்கு முன்னுரிமை அளிக்கப்படுகிறது. இது அனைத்து Claude, Codex, மற்றும் Grok சந்தாக்களையும் நகலெடுக்கிறது; அவற்றைத் தேர்ந்தெடுக்க provider பெயர்களைச் சேர்க்கவும், `omarchy agent account copy laptop claude` இல் உள்ளது போல. கணக்குப் பெயர்கள் மற்றும் command IDகள் source உடன் பொருந்துகின்றன, destination இல் ஏற்கனவே உள்ள கணக்குகள் உட்பட. தொடர்பில்லாத destination கணக்குகள் அவற்றின் பெயர்கள் முரண்பட்டால் ஒரு எண் பின்னொட்டைப் பெறுகின்றன, மேலும் settings, skillகள், pluginகள், மற்றும் உரையாடல் வரலாறு ஒவ்வொரு இயந்திரத்திற்கும் உள்ளூராகவே இருக்கும்.

ஏற்கனவே உள்ள destination நற்சான்றிதழ்கள் வைக்கப்படுகின்றன. அங்கு ஏற்கனவே உள்நுழைந்துள்ள ஒரு source கணக்கின் பெயர் அதன் நற்சான்றிதழ்களை மாற்றாமல் ஒத்திசைக்கப்படுகிறது; மற்ற கணக்குகள் அதனுடன் சேர்த்து சேர்க்கப்படுகின்றன. பொருந்தும் கணக்குகளுக்கு சேமிக்கப்பட்ட நற்சான்றிதழ்களை மாற்ற, destination இல் அந்தக் கணக்கின் sessionகளை விட்டு வெளியேறிய பிறகு `omarchy agent account copy --replace laptop claude` ஐப் பயன்படுத்தவும். ஒரு புதிய destination source இன் செயலில் உள்ள கணக்கு மற்றும் மாற்றுதல் விருப்பங்களையும் பெறுகிறது; ஒரு நிறுவப்பட்ட destination தன்னுடையவற்றை வைத்திருக்கிறது.

நற்சான்றிதழ்கள் SSH வழியாகப் பயணித்து destination இல் தனிப்பட்ட கோப்புகளில் சேமிக்கப்படுகின்றன, எனவே நீங்கள் நம்பும் இயந்திரங்களுக்கு மட்டுமே நகலெடுக்கவும். இது ஒரு முறை நகல், தொடர்ச்சியான ஒத்திசைவு அல்ல. Codex refresh tokenகள் மற்றொரு இயந்திரத்தால் சுழற்றப்படலாம், இதனால் நகலெடுக்கப்பட்ட உள்நுழைவுக்கு புதுப்பித்தல் தேவைப்படும்; பல இயந்திரங்களில் ஒரே நேரத்தில் பயன்படுத்த தனித்தனி உள்நுழைவுகள் மிகவும் நம்பகமான தேர்வாக இருக்கின்றன. [Codex இன் கணக்கு அங்கீகார வழிகாட்டி](https://developers.openai.com/codex/auth/ci-cd-auth) ஐப் பார்க்கவும்.

provider ஒன்றுக்கு ஒரு கணக்கு செயலில் உள்ளது, மேலும் ஒவ்வொரு புதிய session ம் அதுவாகவே தொடங்குகிறது: `cx`, `cy`, ஒரு எளிய `claude`, `codex`, அல்லது `grok`, `omarchy agent` வழியாகத் தொடங்கப்பட்ட எதுவும், மற்றும் `PATH` இல் CLI ஐக் கண்டறியும் scriptகள் அல்லது editorகள். `omarchy agent account use work` உடன் மாற்றவும் (மற்றும் `omarchy agent account use main` உடன் திரும்பவும்), அல்லது panel இல் ஒரு கணக்கின் எண்ணை அழுத்தி பின்னர் `Enter` ஐ அழுத்துவதன் மூலம் (அல்லது அதன் Use பொத்தானைக் கிளிக் செய்வதன் மூலம்). இயங்கும் Claude sessionகளும், அவற்றின் அடுத்த செய்தியிலிருந்து மாறுகின்றன: ஒவ்வொரு Claude session ம் `~/.claude` இல் இயங்குகிறது, இது எப்போதும் செயலில் உள்ள கணக்கின் உள்நுழைவைக் கொண்டுள்ளது. ஒரு பழைய Omarchy ஆல் ஒரு கணக்கின் சொந்த கோப்புறையில் தொடங்கப்பட்ட ஒரு Claude session அது வெளியேறும் வரை அந்த உள்நுழைவை வைத்திருக்கிறது, எனவே மாற்றம் அந்த sessionகளைப் பெயரிடுகிறது மற்றும் அவை போனவுடன் தானாகவே முடிகிறது. இயங்கும் Codex மற்றும் Grok sessionகள் அவை தொடங்கிய கணக்கிலேயே இருக்கின்றன. உரையாடல் வரலாறு, settings, skillகள், மற்றும் pluginகள் கணக்குகள் முழுவதும் பகிரப்படுகின்றன, எனவே அதே கோப்புறையில் `claude --continue` நீங்கள் புதிய கணக்கில் விட்ட இடத்திலிருந்து தொடர்கிறது.

ஒன்றுக்கு மேற்பட்ட கணக்குகளுடன், panel ஒவ்வொரு கணக்கின் வரம்புகளையும் அருகருகே காட்டுகிறது, செயலில் உள்ளது குறிக்கப்பட்டிருக்கும். இயல்பாக Omarchy செயலில் உள்ள கணக்கு ஒரு வரம்பின் 95% ஐத் தாண்டும்போது உங்களுக்கு அறிவிக்கிறது, மேலும் அறிவிப்பைக் கிளிக் செய்வது மிகவும் headroom உள்ள கணக்கிற்கு மாற்றுகிறது. panel இல் ஒரு கணக்கின் வரியின் மீது hover செய்து Use க்கு அருகில் தோன்றும் Autoswitch ஐக் கிளிக் செய்யவும் (அல்லது `m` ஐ அழுத்தவும்), அல்லது அது தானாகவே மாற `omarchy agent account mode auto` ஐ இயக்கவும்; அது இயக்கத்தில் இருக்கும்போது, Autoswitch Use இன் இடத்தை எடுக்கிறது, மேலும் அதை மீண்டும் கிளிக் செய்வது அறிவிப்பதற்குத் திரும்புகிறது. வரம்பை மாற்ற ஒரு எண்ணைச் சேர்க்கவும், `omarchy agent account mode auto 90` இல் உள்ளது போல. ஒவ்வொரு கணக்கும் வரம்புக்கு மேல் இருந்தால், எந்தக் கணக்கு முதலில் விடுபடுகிறது என்பதுடன் ஒரு முறை அதைப் பற்றி நீங்கள் கேட்பீர்கள். ஒரு செயலில் உள்ள கணக்கு அதன் வரம்பிலிருந்து 15 புள்ளிகளுக்குள் இருக்கும்போது (இயல்புநிலையில் 80%), அதன் வரம்புகள் ஒவ்வொரு 15 நிமிடங்களுக்குப் பதிலாக ஒவ்வொரு மூன்று நிமிடங்களுக்கும் சரிபார்க்கப்படுகின்றன.

`omarchy agent account list` ஒவ்வொரு கணக்கையும் அதன் சமீபத்திய வரம்புகளையும் காட்டுகிறது, `omarchy agent account remove work` ஒன்றை மறக்கிறது, மேலும் `omarchy agent account rename primary Hey` ஒன்றுக்கு மறுபெயரிடுகிறது (அல்லது panel இல் ஒரு கணக்கின் பெயரைக் கிளிக் செய்யவும்). இந்தக் கட்டளைகள் உங்கள் இயல்புநிலை agent இன் கணக்குகளில் செயல்படுகின்றன; மற்ற provider ஐ அடைய, முதலில் அதைப் பெயரிடவும், `omarchy agent account use codex side` இல் உள்ளது போல. நீங்கள் ஏற்கனவே `~/.claude` அல்லது `~/.codex` இல் வைத்திருந்த உள்நுழைவு _Main_ கணக்கு ஆகும். Codex இனுடையது அது இருக்கும் இடத்திலேயே இருக்கிறது; மற்றொரு கணக்கு செயலில் இருக்கும்போது Claude இனுடையது அதற்கே உரிய ஒரு கோப்புறையில் காத்திருக்கிறது. சுமார் எட்டு மணி நேரத்திற்கும் மேலாகப் பயன்படுத்தப்படாமல் விடப்பட்ட ஒரு கணக்கு _Sign-in required_ ஐக் காட்டலாம்; panel இலேயே அந்தக் கணக்கில் மீண்டும் உள்நுழைய அதைக் கிளிக் செய்யவும், அல்லது அதற்கு மாறி ஒரு session ஐத் தொடங்கவும், இது உள்நுழைவைத் தானாகவே புதுப்பிக்கிறது. நீங்கள் `claude mcp add` உடன் சேர்க்கும் MCP serverகள் ஒவ்வொரு Claude கணக்கையும் அடைகின்றன, ஏனெனில் அவை அனைத்தும் `~/.claude` இல் இயங்குகின்றன; Codex மற்றும் Grok க்கு, ஒரு கணக்கு சேர்க்கப்பட்டபோது நீங்கள் வைத்திருந்த serverகள் அதனுடன் வருகின்றன, ஆனால் பிந்தையவை நீங்கள் அவற்றைச் சேர்த்த கணக்கை மட்டுமே அடைகின்றன. Claude Desktop தனக்கே உரிய ஒரு உள்நுழைவை வைத்திருக்கிறது, மேலும் ஒரு CLI binary க்கான absolute path உடன் உள்ளமைக்கப்பட்ட Codex அல்லது Grok கருவிகள் மாற்றத்தைப் பின்தொடராது. ஒரு வெளிப்படையான `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, அல்லது `GROK_HOME` தேர்ந்தெடுக்கப்பட்ட கணக்கை விட முன்னுரிமை பெறுகிறது.

### செயலிழப்பு கண்டறிதல்

Omarchy process செயலிழப்புகளுக்காக systemd-coredump ஐக் கண்காணிக்கிறது. நீங்கள் ஒரு இயல்புநிலை agent ஐத் தேர்ந்தெடுத்த பிறகு, core ஐ dump செய்யும் உங்கள் எந்த நிரலும் ஒரு "Process crashed" அறிவிப்பைக் கொண்டு வருகிறது — அதைக் கிளிக் செய்யவும், மேலும் செயலிழப்பு Omarchy இன் omarchy-diagnose-crash skill உடன் உங்கள் இயல்புநிலை agent இடம் ஒப்படைக்கப்படுகிறது, இது core dump இலிருந்து உண்மைகளை நிறுவுவதன் வழியாகவும் செயலிழப்பு upstream இல் அறிக்கையிடத் தகுதியானதா என முடிவு செய்வதன் வழியாகவும் agent ஐ வழிநடத்துகிறது. நீங்கள் அதை `coredumpctl list` இலிருந்து எந்த PID க்கும் எதிராக `omarchy agent crash <pid>` உடன் கையாலும் இயக்கலாம்.

கண்காணிப்பு இயல்பாக இயக்கத்தில் உள்ளது. அதை _Trigger > Toggle > Crash Capture Off_ இன் கீழ் (அல்லது `omarchy toggle crash-capture` உடன்) அணைக்கவும், அறிவிப்புகள் நின்றுவிடும்; `omarchy agent crash <pid>` இன்னும் கையால் செயல்படுகிறது.

செயலிழப்புகளை ஒரு நேரத்தில் ஒரு நிரல் வீதமும் அமைதிப்படுத்தலாம், இதைத்தான் கண்டறிதல் இறுதியில் உங்களுக்கு வழங்குகிறது. `omarchy crash mute hyprland` அந்த நிரலுக்கு மட்டுமே அறிவிப்புகளை நிறுத்துகிறது, `omarchy crash mute hyprland off` அவற்றைத் திரும்பக் கொண்டு வருகிறது, மேலும் `omarchy crash mute` தனியாக நீங்கள் அமைதிப்படுத்தியதைப் பட்டியலிடுகிறது. இது binary இன் path ஐ அதன் பெயரைப் போலவே மகிழ்ச்சியாக எடுத்துக்கொள்கிறது, எனவே `omarchy crash mute /usr/bin/hyprland` அதே விஷயத்தைச் செய்கிறது. அதில் இடைவெளி உள்ள ஒரு பெயரை மேற்கோள் காட்டவும், `omarchy crash mute 'Some App'` இல் உள்ளது போல. மற்ற அனைத்தும் இன்னும் அறிவிக்கின்றன, மேலும் அமைதிப்படுத்தப்பட்ட நிரல் இன்னும் செயலிழக்கிறது — இது நினைவூட்டலை மறைக்கிறது, இது எதையும் சரிசெய்யாது.

### டெஸ்க்டாப் பயன்பாடுகள்

_Install > AI_ menu சில வரைகலை AI பயன்பாடுகளையும் கொண்டுள்ளது: Amp Desktop, Antigravity Desktop, ChatGPT desktop app, Claude desktop app (Chat, Cowork, மற்றும் Claude Code tabகளுடன் Anthropic இன் Linux beta), xAI இன் modelகளுடன் அரட்டை அடிக்க Grok Bot, Herdr Desktop, Hermes Desktop, OpenClaw, Perplexity desktop app, மற்றும் T3 Code. Grok Bot என்பது desktop chat app ஆகும். coding agent என்பது `grok` கட்டளை ஆகும்.

Hermes Desktop என்பது தெரிந்து கொள்ள வேண்டிய ஒன்று, ஏனெனில் ஒரு இயந்திரத்தில் ஒரு Hermes உள்ளது, மேலும் அது பயன்பாட்டினுடையது: Hermes எப்போதும் பயன்பாட்டின் வழியாக மட்டுமே நிறுவப்படுகிறது, மேலும் இயல்புநிலை agent இயக்கும் `hermes` கட்டளை பயன்பாட்டினுடையது. Hermes ஐ இயல்புநிலை agent ஆகத் தேர்ந்தெடுப்பது _Install > AI_ உள்ளீடு செய்வதையே நிறுவுகிறது: package, மற்றும் Hermes இன் சொந்த installer ஆல் அமைக்கப்பட்ட `~/.hermes` இன் கீழ் ஒரு Hermes runtime, இது முதல் முறை சில நிமிடங்கள் எடுக்கும். அந்த runtime என்பது terminal `hermes` கட்டளை, இயல்புநிலை agent மற்றும் பயன்பாடு அனைத்தும் பயன்படுத்தும் ஒரே Hermes, மேலும் அது Omarchy வெளியீட்டிற்காகக் காத்திருப்பதற்குப் பதிலாக `hermes update` உடன் தன்னைப் புதுப்பிக்கிறது. அதை நிறுவுவது Hermes க்கு Omarchy theme ஐ `omarchy` எனப் பெயரிடப்பட்ட ஒரு skin ஆகவும் வழங்குகிறது, நீங்கள் themeகளை மாற்றும்போது ஒவ்வொரு Hermes மேற்பரப்பும் அதைப் பின்தொடர்கிறது; நீங்கள் அது வேண்டாம் என விரும்பினால் Hermes இன் Appearance settings இன் கீழ் அல்லது `/skin` உடன் வேறொன்றைத் தேர்ந்தெடுக்கவும், மேலும் Omarchy அந்தத் தேர்வை அப்படியே விட்டுவிடுகிறது. _Remove > AI_ இன் கீழ் பயன்பாட்டை அகற்றுவது முதலில் Hermes ஐ மூடுகிறது, gateway உட்பட, அந்த runtime ஐ அதனுடன் எடுத்துச் செல்கிறது, மேலும் நீங்கள் வேறுவிதமாகச் சொன்னால் தவிர உங்கள் அரட்டைகள், நினைவுகள், மற்றும் Hermes தனக்காக எழுதிய skillகளை வைத்திருக்கிறது: அந்தத் தரவும் உங்கள் இணைப்பு அமைப்புகளும் கூட போக வேண்டுமா என இது கேட்கிறது, இயல்புநிலையாக இல்லை என.

OpenClaw இன் desktop அனுபவம் என்பது அதன் Control UI, இது அதன் சொந்த உள்ளூர் gateway ஆல் ஆதரிக்கப்படும் ஒரு web app ஆகத் திறக்கிறது. OpenClaw `~/.openclaw` இல் வாழ்கிறது மற்றும் தன்னைப் புதுப்பிக்கிறது: Control UI இன் "Update Gateway" பொத்தானைப் பயன்படுத்தவும் அல்லது `openclaw update` ஐ இயக்கவும், மேலும் gateway புதிய பதிப்பில் மறுதொடக்கம் செய்கிறது. ஒரு புதிய நிறுவல் எந்த வெளியீட்டிலிருந்து தொடங்குகிறது என்பதை மட்டுமே Omarchy தேர்ந்தெடுக்கிறது. OpenClaw உங்கள் இயல்புநிலை agent ஆகவும் இருக்கலாம்: _Agent > Harness_ இன் கீழ் அதைத் தேர்ந்தெடுப்பது `~/.openclaw` இல் அதே நகலை அமைக்கிறது, மேலும் agent OpenClaw இன் terminal UI ஐ அதன் gateway உடன் இணைக்கப்பட்டு திறக்கிறது. _Remove > AI_ இன் கீழ் OpenClaw ஐ அகற்றுவது gateway சேவையையும் பயன்பாட்டையும் அதனுடன் எடுத்துச் செல்கிறது, பின்னர் `~/.openclaw` ம் போக வேண்டுமா எனக் கேட்கிறது, ஏனெனில் அது OpenClaw உடன் மற்றும் அது பதிவிறக்கும் plugin runtimeகளுடன் உங்கள் அரட்டைகள் மற்றும் நற்சான்றிதழ்களை வைத்திருக்கிறது; இயல்புநிலை அதை வைத்திருக்கிறது, மேலும் OpenClaw ஐ மீண்டும் நிறுவுவது அதை மீண்டும் எடுக்கிறது.

Herdr Desktop என்பது [Herdr](https://herdr.dev) desktop app: நீங்கள் window ஐ மூடும்போது அதன் core இல் தொடர்ந்து இயங்கும் terminalகள் மற்றும் coding agentகளின் spaceகள், tabகள், மற்றும் paneகள். இது ஒரு package இலிருந்து வராமல் Herdr இன் சொந்த installer இலிருந்து வருகிறது, எனவே இது `~/.local/share/herdr-app` இல் வாழ்கிறது, உங்களிடம் இன்னும் ஒன்று இல்லை என்றால் `~/.local/bin/herdr-core` இல் அதன் core ஐக் கொண்டு வருகிறது, மேலும் இரண்டையும் தானே புதுப்பிக்கிறது. இது Omarchy `Super + Ctrl + Return` இல் வழங்கும் `herdr` கட்டளையை மாற்றுவதற்குப் பதிலாக அதற்கு அருகில் அமர்கிறது, மேலும் அந்தக் கட்டளையின் நேரடி keyகளைப் பெறுகிறது: `Alt + Return` மற்றும் `Alt + Shift + Return` ஒரு pane ஐ கீழ் அல்லது வலதுபுறமாகப் பிரிக்கின்றன, `Alt + Escape` அதை மூடுகிறது, `Ctrl + Alt + Arrow` paneகளுக்கிடையே நகர்கிறது, `Alt + 1..9` மற்றும் `Alt + Left/Right` ஒரு tab ஐத் தேர்ந்தெடுக்கின்றன, மேலும் `Alt + Up/Down` spaceகளுக்கிடையே நகர்கின்றன. `Ctrl + 1..9` ஒரு space ஐத் தேர்ந்தெடுக்கிறது மற்றும் `Alt + Shift + Up/Down` agentகள் வழியாகப் படிப்படியாகச் செல்கிறது. `Ctrl + Space` prefix keyகள் terminal க்கு மட்டுமே இருக்கின்றன, ஏனெனில் பயன்பாடு ஒரு வரிசைக்காக ஒரு எளிய Ctrl key ஐ வைத்திருக்க முடியாது. Omarchy இவற்றை `~/.config/herdr-app/keys.json` இல் எழுதுகிறது, மேலும் `omarchy-refresh-herdr-app` அவற்றைத் திரும்ப வைக்கிறது. அதை நிறுவுவது Herdr இன் Omarchy theme ஐத் தேர்ந்தெடுக்கிறது, இது அதன் பிறகு உங்கள் Omarchy theme ஐப் பின்தொடர்கிறது. Herdr light mode க்கு ஒரு theme மற்றும் dark க்கு ஒன்றை வைத்திருக்கிறது, எனவே ஒரு dark மற்றும் ஒரு light Omarchy theme க்கிடையே மாறிய பிறகு, மற்ற முறைக்காக Herdr இன் theme picker இல் Omarchy ஐ மீண்டும் ஒரு முறை தேர்ந்தெடுக்கவும்.

T3 Code ஒரு package இலிருந்து வராமல் `~/.local/share/t3code` இல் அதன் அதிகாரப்பூர்வ AppImage வெளியீட்டிலிருந்து இயங்குகிறது, எனவே இது தன்னைப் புதுப்பிக்கிறது. அதை நிறுவுவது Stable அல்லது Nightly channel இல் தொடங்க வேண்டுமா எனக் கேட்கிறது; பின்னர் T3 Code இன் settings இல் மாற்றவும். உங்கள் threadகள் மற்றும் settings `~/.t3` இல் வாழ்கின்றன, மேலும் _Remove > AI_ இன் கீழ் T3 Code ஐ அகற்றுவது அவற்றை அதனுடன் எடுத்துச் செல்கிறது.

### உள்ளூர் மாடல்கள்

உங்கள் coding agentகளுக்காக உங்கள் சொந்த இயந்திரத்தில் ஒரு open model ஐ இயக்கவும். உங்கள் promptகள் மற்றும் code இயந்திரத்திலேயே இருக்கும்; model க்கு அனுப்பப்படும் எதுவும் அதை விட்டு வெளியேறாது. இதனுடன் தொடங்கவும்:

```bash
omarchy models use best text
```

அது இந்த இயந்திரத்திற்கான சிறந்த text model ஐ அமைக்கிறது, உங்கள் agentகள் பயன்படுத்தும் வகை. Image, video மற்றும் music modelகளுக்கு அவற்றுக்கே உரிய சிறந்தவை உள்ளன: `omarchy models use best image`, `video` அல்லது `music`. இந்த இயந்திரத்திற்கான ஒவ்வொரு வகையின் தேர்வையும் பார்க்க `omarchy models use best` ஐ இயக்கவும்.

அல்லது உள்ளூர் மாடல்கள் panel ஐ அதன் sparkles icon இலிருந்து மேல் பட்டியில், agentகள் icon க்கு அடுத்து, அல்லது Super + Ctrl + Alt + X உடன் திறந்து, + ஐத் தேர்ந்தெடுக்கவும். ஒரு model இந்த இயந்திரத்திற்குப் பொருந்தும்போது icon தோன்றுகிறது. modelகளை இயக்கும் Podman, Omarchy உடன் வருகிறது, NVIDIA இயந்திரத்தில் NVIDIA இன் container toolkit ம் அப்படியே, இது அவற்றுக்கு GPU ஐக் கொடுக்கிறது; ஒன்று இல்லை என்றால், முதல் அமைப்பு அதை நிறுவுகிறது. பின்னர் Omarchy இந்த இயந்திரத்திற்கு பரிந்துரைக்கப்பட்ட model ஐத் தேர்ந்தெடுத்து, அதைப் பதிவிறக்கி, தொடங்குகிறது. பத்துகள் GB பதிவிறக்கம் மற்றும் model இயங்கும்போது இயந்திரத்தின் பெரும்பாலான நினைவகம் பயன்பாட்டில் இருக்கும் என எதிர்பார்க்கவும்: Flash Next அதன் முழு 256K context உடன் சுமார் 100 GiB ஐப் பயன்படுத்துகிறது. மற்ற modelகள் அதற்குத் தேவையான நினைவகத்தை வைத்திருந்தால், அது நிறுத்தப்பட்டு அமைக்கப்படுகிறது, நீங்கள் ஒன்றை நிறுத்தியவுடன் தொடங்கத் தயாராக உள்ளது. model வெளியேறும்போது நின்றுவிடும்; நினைவகம் உங்களுக்கு வேறு எதற்காவது தேவைப்படும்போது அதை நீங்களே நிறுத்தவும்.

`omarchy models list` விருப்பங்களைக் காட்டுகிறது மற்றும் சில ஏன் பொருந்தவில்லை என விளக்குகிறது. மற்றொன்றை அமைக்க, `omarchy models use <recipe>` ஐ இயக்கவும். இன்று, `qwen3.8-flash-next-gufo` மற்றும் `qwen3.8-27b-gufo` 128 GB Strix Halo இயந்திரங்களுக்குக் கிடைக்கின்றன; 27B சுமார் 40 GiB எடுக்கிறது, எனவே இது மற்ற வேலைகளுக்கு இடம் விடுகிறது. Intel இன் Arc B390 உடன் ஒரு 64 GB laptop இல், `qwen3.6-35b-a3b-llamacpp` சுமார் 30 GiB இல் இயங்குகிறது. புதிய recipeகள் மற்றும் பரிந்துரைகள் `omarchy update` உடன், package வழியாக வருகின்றன.

நீங்கள் அமைக்கும் ஒவ்வொரு model க்கும் உள்ளூர் மாடல்கள் panel இல் அதற்கே உரிய ஒரு வரி கிடைக்கிறது: அதைத் தொடங்க play, அதை நிறுத்தி அதன் நினைவகத்தை விடுவிக்க pause, மற்றும் அதில் உங்கள் agent ஐத் திறக்க terminal பொத்தான். மேலே குறுக்காக, ஒரு பட்டி இயந்திரத்தின் நினைவகம் Omarchy க்கே (system மற்றும் உங்கள் பயன்பாடுகள்), இயங்கும் ஒவ்வொரு model, மற்றும் இலவசமாக உள்ளதற்கு இடையே எவ்வாறு பிரிக்கப்பட்டுள்ளது எனக் காட்டுகிறது. நிறுத்தப்பட்ட ஒரு model ஐச் சுட்டிக்காட்டவும், பட்டி அது பொருந்துமா, அல்லது எவ்வளவு குறைகிறது எனக் காட்டுகிறது. பல ஒன்றாக நினைவகத்தில் பொருந்தும்போது ஒரே நேரத்தில் இயங்க முடியும்; ஒன்று பொருந்தவில்லை என்றால், எந்த இயங்கும் model ஐ நிறுத்த வேண்டும் என Omarchy கூறுகிறது. வரிகளை அவற்றின் logo ஆல் இழுத்து மறுவரிசைப்படுத்தவும், மேலும் ஒரு model மற்றும் அதன் பதிவிறக்கத்தை அகற்ற தேர்ந்தெடுக்கப்பட்ட வரியில் Delete ஐ அழுத்தவும்.

நீங்கள் அமைக்கும் ஒவ்வொரு coding model க்கும் app launcher இல் அதற்கே உரிய ஒரு உள்ளீடும் கிடைக்கிறது, model இன் பெயரின் கீழ் மற்றும் அதன் தயாரிப்பாளரின் logo உடன், Claude, Codex அல்லது Grok இல் உள்நுழைவது ஒன்றைச் சேர்ப்பது போல. இது உங்கள் agent ஐ அந்த model இல் திறக்கிறது, மேலும் அது இயங்கவில்லை என்றால் முதலில் model ஐத் தொடங்குகிறது: terminal அது ஏற்றுவதைக் காட்டுகிறது மற்றும் அது தயாரானவுடன் agent இடம் ஒப்படைக்கிறது. ஒரு model ஐ அகற்றுவது அதன் உள்ளீட்டை அகற்றுகிறது.

ஒவ்வொரு model ம் coding க்காக அல்ல. Image, video மற்றும் music modelகள் அதற்குப் பதிலாக Fantasi இல் திறக்கின்றன, இந்த இயந்திரத்தில் இயங்கும் ஒரு model உடன் படங்கள், video மற்றும் music ஐ உருவாக்குவதற்கான Omarchy இன் பயன்பாடு, அங்கு அல்லது உள்ளூர் மாடல்கள் panel இல் அவற்றின் வரியிலிருந்து தேர்ந்தெடுக்கப்படுகிறது.

ஒரு model அது அமைக்கப்பட்டபடியே தொடர்ந்து இயங்குகிறது, எனவே ஒரு Omarchy புதுப்பிப்பு உங்கள் agentகளின் கீழ் ஒன்றை ஒருபோதும் மறுதொடக்கம் செய்யாது. நீங்கள் அமைத்துள்ள ஒரு model க்கு Omarchy இடம் புதிய runtime அல்லது புதிய weightகள் இருக்கும்போது, அதன் வரி ஒரு update பொத்தானைக் காட்டுகிறது: அதை அழுத்தவும், model பின்னணியில் மீண்டும் அமைக்கப்படுகிறது, மாறியதை மட்டும் பதிவிறக்குகிறது, மேலும் புதிய பதிப்பில் மறுதொடக்கம் செய்கிறது. நிறுத்தப்பட்டிருந்த ஒரு model நிறுத்தப்பட்டே இருக்கிறது. `omarchy models update` ஒரு terminal இலிருந்து ஒவ்வொரு model க்கும் அதையே செய்கிறது.

command line இலிருந்து, `omarchy models start <recipe>` மற்றும் `omarchy models stop <recipe>` அதையே செய்கின்றன, `omarchy models status` ஒவ்வொரு model ஐயும் காட்டுகிறது, மேலும் `omarchy agent --local` உங்கள் இயல்புநிலை agent எதுவாக இருந்தாலும் நீங்கள் கடைசியாகத் தொடங்கிய model ஐ pi இல் திறக்கிறது. OpenCode மற்றும் Qwen Code ஒரு உள்ளூர் model ஐயும் பயன்படுத்தலாம்: `omarchy models harness opencode` அல்லது `omarchy models harness qwen` அவற்றை அதற்குப் பதிலாக அங்கு திறக்கிறது, மேலும் `omarchy models harness pi` திரும்பச் செல்கிறது. pi நீங்கள் அமைத்துள்ள ஒவ்வொரு model ஐயும், மற்றும் நீங்கள் இணைத்துள்ள இயந்திரங்களில் உள்ளவற்றையும், அதன் சொந்த model picker இல் பட்டியலிடுகிறது, எனவே எளிய `pi` ம் அவற்றை அடைகிறது. எந்த OpenAI-இணக்க client ம் இணைக்க முடியும்: `status` ஒவ்வொரு model இன் முகவரியையும் காட்டுகிறது (முதலாவது `http://127.0.0.1:11435/v1`), recipe பெயர் model ஆகும், மேலும் key `~/.config/omarchy/agent-local/key` இல் உள்ளது.

`omarchy models remove <recipe>` ஒரு model ஐயும் மற்ற எந்த model ம் பயன்படுத்தாத பதிவிறக்கங்களையும் நீக்குகிறது.

Third-party runtimeகள் அவற்றின் வெளியீட்டாளருடன் லேபிளிடப்படுகின்றன. Omarchy ஒவ்வொரு model ஐயும் எந்த network அணுகலும் இல்லாமல் இயக்குகிறது.

### உள்ளூர் LLMகள்

Omarchy உள்ளூர் LLM modelகளை இயக்க இரண்டு வழிகளைப் பரிந்துரைக்கிறது: LM Studio மற்றும் Ollama. LM Studio open-weight modelகளைக் கண்டறிவதற்கும், அவற்றை நிறுவுவதற்கும், அவற்றை இயக்குவதற்கும் ஒரு GUI interface ஐ வழங்குகிறது. எளிதாகத் தொடங்க இது ஒரு சிறந்த வழி. Ollama இதேபோல் செய்ய ஒரு CLI ஐ வழங்குகிறது. ஆனால் நீங்கள் உள்ளூர் modelகளுக்குப் புதியவர் என்றால், நான் LM Studio உடன் தொடங்குவேன். Omarchy Menu இல் _Install > AI_ இன் கீழ் இரண்டில் ஒன்றை நிறுவலாம்.

### Omarchy ஸ்கில்கள்

Agent ஸ்கில்கள் AI குறிப்பிட்ட கருவிகளை ஒரு குறிப்பிட்ட வழியில் பயன்படுத்த உதவுகின்றன, மேலும் Omarchy அவற்றில் ஏழை வழங்குகிறது. omarchy ஸ்கில் உங்கள் Hyprland config ஐ மாற்றுவது அல்லது பட்டியைச் சரிசெய்வது போல, system ஐத் தனிப்பயனாக்குவதை உள்ளடக்குகிறது. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app, மற்றும் omarchy-make-game புதிய ஒன்றை உருவாக்குவதை உள்ளடக்குகின்றன, omarchy-contribute ஒரு பிழையை அறிக்கையிடுவது அல்லது ஒரு திருத்தத்தை upstream க்கு அனுப்புவதை உள்ளடக்குகிறது, மேலும் omarchy-diagnose-crash ஒரு செயலிழப்பின் core dump வழியாகச் செயல்படுகிறது. அவை Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` மற்றும் ஒவ்வொரு `~/.hermes/profiles/*/skills`), மற்றும் பொதுவான `~/.agents/skills` இடத்திற்கான ஸ்கில் அடைவுகளில் symlink செய்யப்பட்டுள்ளன, எனவே பெரும்பாலான harnessகள் அவற்றைத் தானாகவே எடுக்கின்றன. அதே பெயருடன் உங்கள் சொந்த ஸ்கில் கோப்புறை முன்னுரிமை பெறுகிறது.

ஆனால் நீங்கள் இந்த ஸ்கில்களைச் சோதனை முயற்சியாகக் கருத வேண்டும். வெவ்வேறு modelகள் அதை வெவ்வேறு விளைவுக்குப் பயன்படுத்தும். முதலில் plan mode இல் இயக்குவது சிறந்தது, எனவே agent எதை மாற்ற விரும்புகிறது என உங்களுக்கு ஒரு யோசனை கிடைக்கும். மேலும் agent எல்லாவற்றையும் ஒரு குழப்பமாக்கினால், மாற்றங்களை rollback செய்ய அல்லது `omarchy reinstall configs` ஐக் கூட செயல்படுத்தத் தயாராக இருங்கள்.
