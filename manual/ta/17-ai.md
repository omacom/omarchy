### ஏஜென்டுகளை நிறுவுதல் மற்றும் புதுப்பித்தல்

Hermes மற்றும் OpenClaw தவிர, ஒவ்வொரு ஏஜென்டும் Omarchy-இன் சொந்த களஞ்சியத்திலிருந்து வரும் ஒரு தொகுப்பு ஆகும். _Install > AI > CLI_ இலிருந்து அல்லது `omarchy install ai cli <command>` கொண்டு ஒன்றை நிறுவவும், மற்றும் _Remove > AI > CLI_ இலிருந்து அதை மீண்டும் நீக்கவும், இது அதன் உள்நுழைவுகளையும் வரலாற்றையும் அப்படியே விட்டுவிடும். இன்னும் நிறுவப்படாத ஏஜென்டைத் தேர்ந்தெடுப்பதும் அதை நிறுவும்: ஏஜென்டுகள் பேனலில் அதற்கு நட்சத்திரமிடுதல், `omarchy default agent <name>` கொண்டு அதைத் தேர்ந்தெடுத்தல், அல்லது அதன் சந்தாவில் உள்நுழைதல். Omarchy ஒரு ஏஜென்டின் ஒவ்வொரு புதிய வெளியீட்டையும் ஒரு மணி நேரத்திற்குள், ஒவ்வொரு சேனலுக்கும் வெளியிடுகிறது, மற்றும் `omarchy update` அதை மீதமுள்ள அமைப்புடன் சேர்த்து நிறுவுகிறது.

pacman அவற்றைப் புதுப்பித்த நிலையில் வைத்திருப்பதால், ஏஜென்டுகளின் சொந்த புதுப்பிப்பாளர்கள் அணைக்கப்பட்டுள்ளனர்: `claude update` அல்லது ஒரு செயலியில் உள்ள புதுப்பிப்பு பொத்தானுக்கு எந்த வேலையும் இல்லை. நீங்கள் ஒரு ஏஜென்டை அதன் சொந்த நிறுவியிலிருந்து இயக்க விரும்பினால், அதைப் பயன்படுத்தி Omarchy-இன் தொகுப்பை நிறுவாமல் விடவும்; உங்கள் `PATH` இல் ஏற்கனவே உள்ள ஒரு நகல் நிறுவப்பட்டதாகக் கணக்கிடப்படும். `grok` க்கான x.ai-இன் நிறுவி போன்ற, Omarchy-இன் நகலுக்கு முன்னால் `PATH` இல் இரண்டாவது நகலை வைக்கும் `curl | bash` நிறுவிகளைத் தவிர்க்கவும்.

`dsh` அதன் உலாவி UI-ஐ `127.0.0.1:3080` இல் திறக்கிறது, தொடக்க அடைவை அதன் இயல்புநிலை பணியிடமாகக் கொண்டு. அதன் உலாவி UI தொடக்க தூண்டுதலை ஏற்காது, எனவே `omarchy agent prompt` ஒட்டுவதற்காக தூண்டுதலை உங்கள் கிளிப்போர்டில் வைத்து அதைத் திறக்கிறது. Omarchy அதை DeepSeek-இன் ஒப்புதல்-இல்லாத அனுமதி முன்னமைவுடன் தொடங்குகிறது. நீங்கள் அதன் அதிகாரப்பூர்வ மாதிரி API-ஐப் பயன்படுத்தும்போது DeepSeek Harness அமர்வு பதிவுகளை DeepSeek-க்கு பதிவேற்றுகிறது; அதன் உலாவி UI-இல் _Settings > General > Upload Session Log_ இன் கீழ் அதை அணைக்கவும். நீங்கள் அதற்கு அனுப்பும் கருத்தும் அமர்வுடன் சேர்த்து பதிவேற்றப்படும், நீங்கள் அதை `DSH_TELEMETRY_MODE=DISABLED` கொண்டு தொடங்காவிட்டால்.

### இயல்புநிலை ஏஜென்ட்

ஏஜென்டுகள் பேனலில் ஒரு ஏஜென்டுக்கு அருகில் உள்ள நட்சத்திரத்தைக் கொண்டு உங்கள் இயல்புநிலை ஏஜென்டைத் தேர்ந்தெடுக்கவும், இது இயல்புநிலையில் நிரப்பப்பட்டிருக்கும், அல்லது `omarchy default agent <name>` கொண்டு, இது அங்கு ஒரு வரி இல்லாத எந்த ஹார்னஸையும் ஏற்கும். ஏஜென்ட் இன்னும் நிறுவப்படவில்லை என்றால், அதைத் தேர்ந்தெடுப்பது முதலில் அதை நிறுவும், மற்றும் அதற்கு செயலி தொடக்கியில், Agent-க்கு அருகில், அதன் சொந்த தொடக்கியும் கிடைக்கும். புதிய Omarchy ஒரு முறை மட்டுமேயான அறிவிப்புடன் ஒன்றை அமைக்க உங்களை அழைக்கிறது, இது ஏஜென்டுகள் பேனலைத் திறக்கிறது.

Claude-ஐத் தேர்ந்தெடுப்பது Chromium, Chrome, Brave, Brave Origin, மற்றும் Edge-க்கான அதன் உலாவி நீட்டிப்பை அமைக்கவும் முயற்சிக்கிறது. நீட்டிப்பு அமைப்பு அனைத்து பயனர்களுக்கும் பொருந்தும் மற்றும் உங்கள் அமைப்பு கடவுச்சொல்லைக் கேட்கலாம்; ரத்து செய்தல் அல்லது தோல்வியடைந்த நீட்டிப்பு நிறுவல் இருந்தாலும் Claude தேர்ந்தெடுக்கப்பட்டு தொடங்கப்படும். உங்கள் உலாவியை மறுதொடக்கம் செய்யவும், கேட்கும்போது நீட்டிப்பை இயக்கவும், மற்றும் அதை இணைப்பதை முடிக்க Claude-இல் உள்நுழையவும். இணைப்பைச் சரிபார்க்க Claude-இல் `/chrome` ஐ இயக்கவும். Firefox மற்றும் Zen இந்த நீட்டிப்பை ஆதரிக்காது. இந்த அமைப்பு சேர்க்கப்படுவதற்கு முன்பே Claude ஏற்கனவே உங்கள் இயல்புநிலையாக இருந்தால், நீட்டிப்பை நிறுவ அதை மீண்டும் தேர்ந்தெடுக்கவும்.

நீங்கள் தேர்ந்தெடுத்தவுடன், `Super + Shift + Ctrl + A` இயல்புநிலை ஏஜென்டை ஒரு பிரத்யேக முனைய சாளரத்தில் தொடங்குகிறது (அல்லது நீங்கள் இன்னும் தேர்ந்தெடுக்கவில்லை என்றால் தேர்ந்தெடுப்பாளரைக் கொண்டுவருகிறது). `omarchy agent prompt "Review this project"` கொண்டு நீங்கள் அதை நேரடியாக ஒரு பணியிலும் தொடங்கலாம். Freebuff மற்றும் DeepSeek Harness தொடக்க தூண்டுதலை ஏற்காது, எனவே அவை ஒட்டுவதற்காக தூண்டுதலை உங்கள் கிளிப்போர்டில் வைத்து திறக்கின்றன. இவ்வாறு தொடங்கப்படும் ஏஜென்டுகள் அவற்றின் அந்தந்த கேட்க-நிறுத்தாத பயன்முறைகளில் கவனிக்கப்படாமல் இயங்குகின்றன, எனவே அவை உண்மையில் விஷயங்களைச் செய்யத் தயாராக இருங்கள்! MiniMax Code-க்கு அதன் ஊடாடும் அமர்வுகளுக்கு அத்தகைய பயன்முறை இல்லை, எனவே அது வழக்கம் போல் அனுமதிகளைக் கேட்கிறது. மற்றும் ஏஜென்டுகள் உங்கள் வீட்டு அடைவுக்கான நம்பிக்கையை நினைவில் கொள்ள மறுப்பதால், `$HOME` இலிருந்து தொடங்குவது அதற்கு பதிலாக `~/Work` இல் தொடங்குகிறது.

முனைய குறுக்குவழிகளும் உள்ளன: `a` தற்போதைய முனையத்தில் இயல்புநிலை ஏஜென்டை உள்ளிணைந்து இயக்குகிறது, அதே நேரத்தில் `c`, `cx`, `cy`, மற்றும் `ca` OpenCode, Claude Code, Codex, மற்றும் Antigravity-ஐ நேரடியாகத் தொடங்குகின்றன (மீண்டும் அவற்றின் தானாக-ஒப்புதல் அளிக்கும் பயன்முறைகளில்). தீம் மாற்றங்களும் ஏஜென்டுகளுக்கு ஒத்திசைகின்றன: நீங்கள் Omarchy தீமை மாற்றும்போது Claude Code, Pi, OpenCode, மற்றும் Hermes (Omarchy அதை நிறுவிய பிறகு) அனைத்தும் பின்தொடர்கின்றன.

### உங்கள் ஏஜென்ட் வழிமுறைகள்

ஒவ்வொரு ஏஜென்டுக்கான தனிப்பட்ட விதிகள் `~/.agents/AGENTS.md` இல், `~/.agents/skills` இல் உள்ள பகிரப்பட்ட திறன்களுக்கு அருகில் செல்கின்றன. ஏஜென்டுகள் பேனலில் + க்கு அருகில் உள்ள ஆவண ஐகானைக் கொண்டு, அல்லது `omarchy agent instructions --edit` கொண்டு அதைத் திறக்கவும், இது அதை அதன் சொந்த உலகளாவிய கோப்பை வைத்திருக்கும் ஒவ்வொரு ஹார்னஸிலும் இணைக்கிறது: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, Copilot-இன் `~/.copilot/copilot-instructions.md`, மற்றும் பல. Crush மற்றும் Amp `~/.config/AGENTS.md` இணைப்பைப் படிக்கின்றன, அதே நேரத்தில் omp, Kimi, மற்றும் DeepSeek Harness `~/.agents/AGENTS.md` ஐ நேரடியாகப் படிக்கின்றன. இயல்புநிலை ஏஜென்டைத் தேர்ந்தெடுப்பதும் அதை இணைக்கிறது. உங்களிடம் ஏற்கனவே இருந்த ஒரு வழிமுறைகள் கோப்பு, இன்னும் ஒன்று இல்லை என்றால் பகிரப்பட்டதாக மாறும்; இல்லையெனில் அது இணைப்புக்கு அருகில் `.bak` ஆக வைக்கப்படும். மற்றொரு ஏஜென்டை நிறுவிய பிறகு மீண்டும் இணைக்க `omarchy agent instructions` ஐ இயக்கவும்.

### ஏஜென்டுகள் பேனல்

மேல் பட்டியில் ஒரு ஏஜென்டுகள் ஐகான் உள்ளது. நீங்கள் ஒரு ஏஜென்டை அமைப்பதற்கு முன், அதன் பேனல் தொடங்க மூன்று வழிகளை வழங்குகிறது: Claude, Codex, Grok, Gemini, Muse, Cursor, அல்லது Copilot சந்தாவில் உள்நுழையவும், அல்லது More இன் கீழ் OpenCode Go, MiniMax, Synthetic, அல்லது Z.ai குறியீட்டுத் திட்டம்; Fireworks, OpenCode Zen மற்றும் Go, OpenRouter கொண்டு, அல்லது More இன் கீழ் DeepSeek அல்லது OpenCode உள்நுழையும் வேறு எந்த வழங்குநரையும் கொண்டு பயன்படுத்திய அளவுக்கு செலுத்தவும், அனைத்தும் OpenCode இல் இயங்குகின்றன; அல்லது உங்கள் கணினிக்கு பொருந்தும்போது, அதற்கான சிறந்த மாதிரியை இயக்கவும். நீங்கள் முடிக்கும் முதலாவது உங்கள் இயல்புநிலை ஏஜென்டாக மாறும், மற்றும் பேனலில் உள்ள + பின்னர் அதே மூன்றையும் வழங்குகிறது. அதற்குப் பிறகு, பேனல் ஒவ்வொரு சந்தாவையும் ஒரே பக்கத்தில் வைக்கிறது: ஒவ்வொரு ஏஜென்டும் கணக்கும் அதன் திட்டத்துடன், அதன் 5-மணிநேர அமர்வு மற்றும் வாராந்திர வரம்புகள் ஒவ்வொன்றுக்கும் ஒரு மீட்டர் மற்றும் அது மீட்டமைக்கப்படும் வரையிலான நேரத்துடன் (சரியான சதவீதத்திற்கு மேலே வைக்கவும்), அல்லது மீதமுள்ள முன்கூட்டியே செலுத்தப்பட்ட இருப்பு, அவை அனைத்திலும் நீங்கள் பயன்படுத்தியதை சுழற்றும் ஒரு வரியின் கீழ், இந்த வார டோக்கன்கள் மற்றும் உங்கள் அதிகம் பயன்படுத்தப்பட்ட மாதிரி போன்றவை. _Make something cool_ இன் கீழ் இது உங்கள் இயல்புநிலை ஏஜென்டிடம் பணியை ஒப்படைக்கும் புதிய தீம், செருகுநிரல், செயலி, அல்லது விளையாட்டுக்கான தொடக்க தூண்டுதல்களை வழங்குகிறது. செயலிகள் Omarchy-இன் சொந்த Hype, Monologue, மற்றும் Omacut போல, C++ மற்றும் Qt Quick இல், omarchy-make-app ஏஜென்ட் திறனைப் பின்பற்றி உருவாக்கப்படுகின்றன, மற்றும் அவற்றுக்குத் தேவையான தொகுப்பாளர் மற்றும் Qt பகுதிகள் நிறுவப்பட்டு வருகின்றன. விளையாட்டுகள் `~/Games/vibes` இல் ஒற்றை three.js பக்கம், omarchy-make-game ஏஜென்ட் திறனைப் பின்பற்றி, மற்றும் அனைத்தும் தற்போதைய தீமில் ஒரே Game Vibes தொடக்கியிலிருந்து திறக்கின்றன; அவை வலையிலிருந்து three.js ஐ ஏற்றுகின்றன, எனவே தொடங்க அவற்றுக்கு இணைப்பு தேவை. Claude Code, Codex, Grok, Kimi, Cursor மற்றும் அதன் Grok Bot கொடுப்பனவு, GitHub Copilot, Muse, Gemini (Antigravity வழியாக), மற்றும் Devin ஆகியவை அவற்றின் வரம்புகளுடன் உடனடியாக உள்ளடக்கப்பட்டுள்ளன, Kimchi அதன் திட்டம், முன்கூட்டியே செலுத்தப்பட்ட கிரெடிட்டுகள், மற்றும் செலவு பட்ஜெட்டுகளுடன், மற்றும் Hermes, Mistral Vibe, மற்றும் Qwen Code நீங்கள் அவற்றைப் பயன்படுத்தியவுடன் அவற்றின் அமர்வுகளையும் டோக்கன்களையும் காட்டுகின்றன. நீங்கள் pi, omp, அல்லது opencode வழியாகப் பயன்படுத்தும் வழங்குநர் திட்டங்களும் விசைகளும் கூட காட்டப்படுகின்றன: OpenCode Zen மற்றும் Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan, மற்றும் Synthetic அவற்றின் வரம்புகளுடன்; OpenRouter மற்றும் DeepSeek அவற்றின் முன்கூட்டியே செலுத்தப்பட்ட இருப்புகளுடன்; Fireworks கடந்த 30 நாட்களில் அதன் செலவுடன். உங்கள் சொந்த வன்பொருளில் நீங்கள் இயக்கும் குறியீட்டு மாதிரிகள் அவற்றின் சொந்த வரிகளைப் பெறுகின்றன, மற்றும் அவற்றின் டோக்கன்களும் மொத்தங்களில் கணக்கிடப்படுகின்றன, [உள்ளூர் மாதிரிகள்](#local-models) இன் கீழ் விவரிக்கப்பட்டுள்ளபடி. ஒவ்வொரு ஏஜென்டும் ஒரு முறை மட்டுமே கணக்கிடப்படும், அதற்கு பில் செய்பவர் யாரோ அவரின் கீழ், நீங்கள் எத்தனை ஹார்னஸ்கள் வழியாக அதை இயக்கினாலும்.

பேனலுக்கு பட்டி ஐகானை இடது-கிளிக் செய்யவும் அல்லது `Super + Ctrl + X` ஐ அழுத்தவும், உங்கள் இயல்புநிலை ஏஜென்டைத் தொடங்க வலது-கிளிக் செய்யவும், மற்றும் புதுப்பிக்க நடு-கிளிக் செய்யவும். அதன் பின்னால் உள்ள பயன்பாட்டுப் பதிவுகள் ஒவ்வொரு 15 நிமிடங்களுக்கும் `omarchy agent usage update` ஆல் மீண்டும் உருவாக்கப்படுகின்றன, மற்றும் பேனல் ஒத்திசைக்கப்பட்ட கோப்புறை வழியாக உங்கள் மற்ற இயந்திரங்களிலிருந்து பயன்பாட்டை இணைக்கவும் முடியும். முழு அமைப்புகளுக்கு `$OMARCHY_PATH/shell/plugins/agents/` இன் கீழ் உள்ள README ஐப் பார்க்கவும்.

### பல சந்தாக்கள்

நீங்கள் ஒன்றுக்கு மேற்பட்ட Claude, Codex, அல்லது Grok திட்டத்திற்கு பணம் செலுத்தினால் — தனிப்பட்ட Max மற்றும் வேலைக்கான ஒன்று, சொல்லலாம் — Omarchy அவை அனைத்தையும் உள்நுழைந்த நிலையில் வைத்து அவற்றுக்கிடையே நகர முடியும். ஏஜென்டுகள் பேனலில் உள்ள + கொண்டு ஒரு சந்தாவைச் சேர்க்கவும், இது அங்கேயே உங்களை அதன் வழியாக அழைத்துச் செல்லும், அல்லது `omarchy agent account add claude Work` (அல்லது `codex`, அல்லது `grok`) கொண்டு. அதே + மற்றும் கட்டளை Gemini (`gemini`) மற்றும் OpenCode (`opencode`) இல் உள்நுழைகிறது, மற்றும் OpenCode இல் Fireworks (`fireworks`) அல்லது OpenRouter (`openrouter`) API விசையைச் சேமிக்கிறது; கட்டளை Copilot (`copilot`), Cursor (`cursor`), மற்றும் Muse (`muse`) இலும் உள்நுழைகிறது. அவை ஒவ்வொன்றும் ஒற்றை உள்நுழைவை வைத்திருக்கின்றன. CLI காணவில்லை என்றால் அது அதை நிறுவுகிறது. ஒரு வழங்குநருக்கான முதல் கணக்கு உங்கள் சாதாரண உலாவி வழியாக, CLI எப்போதும் பார்க்கும் இடத்திலேயே உள்நுழைகிறது. அதற்குப் பிறகு ஒவ்வொன்றும் ஒரு தனிப்பட்ட சாளரம் வழியாக உள்நுழைகிறது, எனவே உங்கள் உலாவி ஏற்கனவே உள்நுழைந்துள்ள கணக்கு தவறுதலாக எடுக்கப்படாது; நீங்கள் சேர்க்கும் கணக்காக அங்கு உள்நுழையவும், மற்றும் நீங்கள் ஏற்கனவே திறந்து வைத்துள்ள எந்த தனிப்பட்ட சாளரத்தையும் முதலில் மூடவும். இதைச் செய்ய CLI இலிருந்து ஒருபோதும் வெளியேற வேண்டாம்: வெளியேறுவது சேமிக்கப்பட்ட உள்நுழைவை ரத்து செய்கிறது, மற்றும் அந்தக் கணக்கை மீண்டும் சேர்க்க வேண்டியிருக்கும்.

உங்கள் சந்தா உள்நுழைவுகளை SSH வழியாக மற்றொரு Omarchy இயந்திரத்திற்கு நகலெடுக்க, `omarchy agent account copy user@laptop` ஐ இயக்கவும். இலக்கில் நிறுவப்பட்ட ஒன்று இல்லாதபோது அனுப்புநர் ஒரு தற்காலிக பெறுநரை வழங்குகிறார், எனவே பழைய Omarchy இயந்திரங்கள் புதுப்பிப்பு இல்லாமல் கணக்குகளைப் பெற முடியும். நிறுவப்பட்ட பெறுநர்கள் முன்னுரிமை பெறுகிறார்கள். இது அனைத்து Claude, Codex, மற்றும் Grok சந்தாக்களையும் நகலெடுக்கிறது; `omarchy agent account copy laptop claude` இல் உள்ளது போல, அவற்றைத் தேர்ந்தெடுக்க வழங்குநர் பெயர்களைச் சேர்க்கவும். கணக்குப் பெயர்களும் கட்டளை ID-களும் மூலத்துடன் பொருந்துகின்றன, இலக்கில் ஏற்கனவே உள்ள கணக்குகள் உட்பட. தொடர்பில்லாத இலக்குக் கணக்குகள் அவற்றின் பெயர்கள் முரண்பட்டால் எண் பின்னொட்டைப் பெறுகின்றன, மற்றும் அமைப்புகள், திறன்கள், செருகுநிரல்கள், மற்றும் உரையாடல் வரலாறு ஒவ்வொரு இயந்திரத்திற்கும் உள்ளூராகவே இருக்கின்றன.

ஏற்கனவே உள்ள இலக்கு சான்றுகள் வைக்கப்படுகின்றன. அங்கு ஏற்கனவே உள்நுழைந்துள்ள ஒரு மூலக் கணக்கு அதன் சான்றுகளை மாற்றாமல் அதன் பெயர் ஒத்திசைக்கப்படுகிறது; மற்ற கணக்குகள் அதற்கு அருகில் சேர்க்கப்படுகின்றன. பொருந்தும் கணக்குகளுக்கான சேமிக்கப்பட்ட சான்றுகளை மாற்ற, இலக்கில் அந்தக் கணக்கின் அமர்வுகளை விட்டு வெளியேறிய பிறகு `omarchy agent account copy --replace laptop claude` ஐப் பயன்படுத்தவும். புதிய இலக்கு மூலத்தின் செயலில் உள்ள கணக்கையும் மாற்றும் விருப்பங்களையும் பெறுகிறது; நிறுவப்பட்ட இலக்கு அதன் சொந்தத்தை வைத்திருக்கிறது.

சான்றுகள் SSH வழியாகப் பயணித்து இலக்கில் தனிப்பட்ட கோப்புகளில் சேமிக்கப்படுகின்றன, எனவே நீங்கள் நம்பும் இயந்திரங்களுக்கு மட்டுமே நகலெடுக்கவும். இது ஒரு முறை நகல், தொடர்ச்சியான ஒத்திசைவு அல்ல. Codex புதுப்பிப்பு டோக்கன்கள் மற்றொரு இயந்திரத்தால் சுழற்றப்படலாம், நகலெடுக்கப்பட்ட உள்நுழைவை புதுப்பிக்க வேண்டிய நிலையில் விட்டுவிடும்; பல இயந்திரங்களில் ஒரே நேரத்தில் பயன்படுத்த தனித்தனி உள்நுழைவுகள் மிகவும் நம்பகமான தேர்வாக இருக்கின்றன. [Codex-இன் கணக்கு அங்கீகார வழிகாட்டுதலைப்](https://developers.openai.com/codex/auth/ci-cd-auth) பார்க்கவும்.

ஒரு வழங்குநருக்கு ஒரு கணக்கு செயலில் உள்ளது, மற்றும் ஒவ்வொரு புதிய அமர்வும் அதுவாகவே தொடங்குகிறது: `cx`, `cy`, ஒரு வெற்று `claude`, `codex`, அல்லது `grok`, `omarchy agent` வழியாகத் தொடங்கப்படும் எதுவும், மற்றும் `PATH` இல் CLI-ஐக் கண்டறியும் ஸ்கிரிப்டுகள் அல்லது எடிட்டர்கள். `omarchy agent account use work` கொண்டு மாற்றவும் (மற்றும் `omarchy agent account use main` கொண்டு திரும்பவும்), அல்லது பேனலில் ஒரு கணக்கின் எண்ணை அழுத்தி பின்னர் `Enter` (அல்லது அதன் நட்சத்திரத்தைக் கிளிக் செய்வதன் மூலம்). இயங்கும் Claude அமர்வுகளும் மாறுகின்றன, அவற்றின் அடுத்த செய்தியிலிருந்து: ஒவ்வொரு Claude அமர்வும் `~/.claude` இல் இயங்குகிறது, இது எப்போதும் செயலில் உள்ள கணக்கின் உள்நுழைவை வைத்திருக்கும். பழைய Omarchy ஆல் ஒரு கணக்கின் சொந்த கோப்புறையில் தொடங்கப்பட்ட Claude அமர்வு அது வெளியேறும் வரை அந்த உள்நுழைவை வைத்திருக்கும், எனவே மாற்றம் அந்த அமர்வுகளுக்குப் பெயரிட்டு அவை போனவுடன் தானாகவே முடிவடைகிறது. இயங்கும் Codex மற்றும் Grok அமர்வுகள் அவை தொடங்கிய கணக்கிலேயே இருக்கின்றன. உரையாடல் வரலாறு, அமைப்புகள், திறன்கள், மற்றும் செருகுநிரல்கள் கணக்குகள் முழுவதும் பகிரப்படுகின்றன, எனவே அதே கோப்புறையில் `claude --continue` நீங்கள் புதிய கணக்கில் விட்ட இடத்திலிருந்து தொடர்கிறது.

ஒன்றுக்கு மேற்பட்ட கணக்குடன், பேனல் ஒவ்வொரு கணக்கின் வரம்புகளையும் அருகருகே காட்டுகிறது, பயன்பாட்டில் உள்ள ஒன்றில் நிரப்பப்பட்ட நட்சத்திரத்துடன். செயலில் உள்ள கணக்கு ஒரு வரம்பின் 95% ஐ கடக்கும்போது Omarchy உங்களுக்கு அறிவிக்கிறது, மற்றும் அறிவிப்பைக் கிளிக் செய்வது அதிக இடவசதி உள்ள கணக்கிற்கு மாறுகிறது. அது ஒருபோதும் தானாக மாறாது. `omarchy agent account threshold 90` கொண்டு வரம்பை மாற்றவும். ஒவ்வொரு கணக்கும் வரம்புக்கு மேல் இருந்தால், எந்தக் கணக்கு முதலில் விடுபடுகிறது என்பதுடன், அதைப் பற்றி ஒரு முறை கேட்பீர்கள். செயலில் உள்ள கணக்கு அதன் வரம்பிலிருந்து 15 புள்ளிகளுக்குள் இருக்கும்போது (இயல்புநிலையில் 80%), அதன் வரம்புகள் ஒவ்வொரு 15 க்கும் பதிலாக ஒவ்வொரு மூன்று நிமிடங்களுக்கும் சரிபார்க்கப்படுகின்றன.

`omarchy agent account list` ஒவ்வொரு கணக்கையும் அதன் சமீபத்திய வரம்புகளையும் காட்டுகிறது, `omarchy agent account remove work` ஒன்றை மறக்கிறது, மற்றும் `omarchy agent account rename primary Hey` ஒன்றை மறுபெயரிடுகிறது (அல்லது பேனலில் ஒரு கணக்கின் பெயரைக் கிளிக் செய்யவும்). இந்தக் கட்டளைகள் உங்கள் இயல்புநிலை ஏஜென்டின் கணக்குகளில் வேலை செய்கின்றன; மற்ற வழங்குநரை அடைய, `omarchy agent account use codex side` இல் உள்ளது போல, முதலில் அதற்குப் பெயரிடவும். `~/.claude` அல்லது `~/.codex` இல் நீங்கள் ஏற்கனவே வைத்திருந்த உள்நுழைவு _Main_ கணக்கு ஆகும். Codex-இனுடையது அது இருக்கும் இடத்திலேயே இருக்கிறது; மற்றொரு கணக்கு செயலில் இருக்கும்போது Claude-இனுடையது அதன் சொந்த கோப்புறையில் காத்திருக்கிறது. சுமார் எட்டு மணி நேரத்திற்கும் மேலாகப் பயன்படுத்தப்படாமல் விடப்பட்ட ஒரு கணக்கு _Sign-in required_ ஐக் காட்டலாம்; அந்தக் கணக்கை பேனலிலேயே மீண்டும் உள்நுழைய அதைக் கிளிக் செய்யவும், அல்லது அதற்கு மாறி ஒரு அமர்வைத் தொடங்கவும், இது தானாகவே உள்நுழைவைப் புதுப்பிக்கிறது. நீங்கள் `claude mcp add` கொண்டு சேர்க்கும் MCP சேவையகங்கள் ஒவ்வொரு Claude கணக்கையும் அடைகின்றன, ஏனெனில் அவை அனைத்தும் `~/.claude` இல் இயங்குகின்றன; Codex மற்றும் Grok-க்கு, ஒரு கணக்கு சேர்க்கப்பட்டபோது உங்களிடம் இருந்த சேவையகங்கள் அதற்கு வருகின்றன, ஆனால் பின்னர் வருபவை நீங்கள் அவற்றைச் சேர்த்த கணக்கை மட்டுமே அடைகின்றன. Claude Desktop அதன் சொந்த உள்நுழைவை வைத்திருக்கிறது, மற்றும் CLI பைனரிக்கு முழுமையான பாதையுடன் கட்டமைக்கப்பட்ட Codex அல்லது Grok கருவிகள் மாற்றத்தைப் பின்பற்றாது. வெளிப்படையான `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, அல்லது `GROK_HOME` தேர்ந்தெடுக்கப்பட்ட கணக்கை விட முன்னுரிமை பெறுகிறது.

### செயலிழப்பு கண்டறிதல்

Omarchy செயல்முறை செயலிழப்புகளுக்காக systemd-coredump ஐக் கண்காணிக்கிறது. நீங்கள் ஒரு இயல்புநிலை ஏஜென்டைத் தேர்ந்தெடுத்தவுடன், கோர் டம்ப் செய்யும் உங்கள் எந்த நிரலும் "Process crashed" அறிவிப்பைக் கொண்டுவருகிறது — அதைக் கிளிக் செய்யவும், மற்றும் செயலிழப்பு உங்கள் இயல்புநிலை ஏஜென்டிடம் Omarchy-இன் omarchy-diagnose-crash திறனுடன் ஒப்படைக்கப்படுகிறது, இது கோர் டம்பிலிருந்து உண்மைகளை நிறுவுவதன் வழியாகவும் செயலிழப்பை மேல்நிலையில் புகாரளிக்கத் தகுந்ததா என்பதைத் தீர்மானிப்பதன் வழியாகவும் ஏஜென்டை அழைத்துச் செல்கிறது. `omarchy agent crash <pid>` கொண்டு `coredumpctl list` இலிருந்து எந்த PID-க்கு எதிராகவும் நீங்கள் அதை கையாலும் இயக்கலாம்.

கண்காணிப்பு இயல்பாகவே இயக்கத்தில் உள்ளது. _Trigger > Toggle > Crash Capture Off_ இன் கீழ் (அல்லது `omarchy toggle crash-capture` கொண்டு) அதை அணைக்கவும் மற்றும் அறிவிப்புகள் நிற்கின்றன; `omarchy agent crash <pid>` இன்னும் கையால் வேலை செய்கிறது.

செயலிழப்புகளை ஒரு நேரத்தில் ஒரு நிரல் வீதம் அமைதிப்படுத்தவும் முடியும், இதைத்தான் கண்டறிதல் இறுதியில் உங்களுக்கு வழங்குகிறது. `omarchy crash mute hyprland` அந்த நிரலுக்கு மட்டுமே அறிவிப்புகளை நிறுத்துகிறது, `omarchy crash mute hyprland off` அவற்றைத் திரும்பக் கொண்டுவருகிறது, மற்றும் `omarchy crash mute` தனியாக நீங்கள் அமைதிப்படுத்தியவற்றைப் பட்டியலிடுகிறது. இது பைனரியின் பாதையை அதன் பெயரைப் போலவே மகிழ்ச்சியாக ஏற்கிறது, எனவே `omarchy crash mute /usr/bin/hyprland` அதே வேலையைச் செய்கிறது. `omarchy crash mute 'Some App'` இல் உள்ளது போல, இடைவெளி உள்ள பெயரை மேற்கோள் காட்டவும். மற்ற அனைத்தும் இன்னும் அறிவிக்கின்றன, மற்றும் அமைதிப்படுத்தப்பட்ட நிரல் இன்னும் செயலிழக்கிறது — இது நினைவூட்டலை மறைக்கிறது, இது எதையும் சரிசெய்யாது.

### டெஸ்க்டாப் செயலிகள்

_Install > AI > Desktop_ வரைகலை AI செயலிகளைக் கொண்டுள்ளது: Amp Desktop, Antigravity Desktop, ChatGPT டெஸ்க்டாப் செயலி, Claude டெஸ்க்டாப் செயலி (Anthropic-இன் Linux பீட்டா, Chat, Cowork, மற்றும் Claude Code தாவல்களுடன்), xAI-இன் மாதிரிகளுடன் அரட்டையடிக்க Grok Bot, Herdr Desktop, Hermes Desktop, OpenClaw, Perplexity டெஸ்க்டாப் செயலி, மற்றும் T3 Code. Grok Bot என்பது டெஸ்க்டாப் அரட்டை செயலி. குறியீட்டு ஏஜென்ட் என்பது `grok` கட்டளை.

Hermes Desktop தெரிந்து கொள்ள வேண்டிய ஒன்று, ஏனெனில் ஒரு இயந்திரத்தில் ஒரு Hermes உள்ளது, மற்றும் அது செயலியினுடையது: Hermes எப்போதும் செயலி வழியாக மட்டுமே நிறுவப்படுகிறது, மற்றும் இயல்புநிலை ஏஜென்ட் இயக்கும் `hermes` கட்டளை செயலியினுடையது. Hermes-ஐ இயல்புநிலை ஏஜென்டாகத் தேர்ந்தெடுப்பது _Install > AI > Desktop_ உள்ளீடு செய்வதையே நிறுவுகிறது: தொகுப்பு, மற்றும் Hermes-இன் சொந்த நிறுவியால் அமைக்கப்பட்ட `~/.hermes` இன் கீழ் ஒரு Hermes இயக்க நேரம், இது முதல் முறை சில நிமிடங்கள் எடுக்கும். அந்த இயக்க நேரம்தான் முனைய `hermes` கட்டளை, இயல்புநிலை ஏஜென்ட் மற்றும் செயலி அனைத்தும் பயன்படுத்தும் ஒரே Hermes, மற்றும் இது Omarchy வெளியீட்டிற்காகக் காத்திருக்காமல் `hermes update` கொண்டு தானாகவே புதுப்பிக்கிறது. அதை நிறுவுவது Hermes-க்கு Omarchy தீமை `omarchy` என்ற பெயரிடப்பட்ட தோலாகவும் வழங்குகிறது, இதை ஒவ்வொரு Hermes மேற்பரப்பும் நீங்கள் தீம்களை மாற்றும்போது பின்பற்றுகிறது; நீங்கள் அது வேண்டாம் என்றால் Hermes-இன் Appearance அமைப்புகளின் கீழ் அல்லது `/skin` கொண்டு வேறொன்றைத் தேர்ந்தெடுக்கவும், மற்றும் Omarchy அந்தத் தேர்வை அப்படியே விட்டுவிடும். _Remove > AI > Desktop_ இன் கீழ் செயலியை நீக்குவது முதலில் Hermes-ஐ மூடுகிறது, நுழைவாயில் உட்பட, அந்த இயக்க நேரத்தை அதனுடன் எடுத்துச் செல்கிறது, மற்றும் நீங்கள் வேறுவிதமாகச் சொல்லாவிட்டால் உங்கள் அரட்டைகள், நினைவுகள், மற்றும் Hermes தனக்காக எழுதிய திறன்களை வைத்திருக்கிறது: அந்தத் தரவும் உங்கள் இணைப்பு அமைப்புகளும் கூட போக வேண்டுமா என்று, இயல்புநிலையாக இல்லை என்று, அது கேட்கிறது.

OpenClaw-இன் டெஸ்க்டாப் அனுபவம் அதன் Control UI ஆகும், இது அதன் சொந்த உள்ளூர் நுழைவாயிலால் ஆதரிக்கப்படும் வலை செயலியாகத் திறக்கிறது. OpenClaw `~/.openclaw` இல் வாழ்கிறது மற்றும் தானாகவே புதுப்பிக்கிறது: Control UI-இன் "Update Gateway" பொத்தானைப் பயன்படுத்தவும் அல்லது `openclaw update` ஐ இயக்கவும், மற்றும் நுழைவாயில் புதிய பதிப்பில் மறுதொடக்கம் செய்கிறது. புதிய நிறுவல் எந்த வெளியீட்டிலிருந்து தொடங்குகிறது என்பதை மட்டுமே Omarchy தேர்ந்தெடுக்கிறது. OpenClaw உங்கள் இயல்புநிலை ஏஜென்டாகவும் இருக்க முடியும்: `omarchy default agent openclaw` கொண்டு அதைத் தேர்ந்தெடுப்பது `~/.openclaw` இல் அதே நகலை அமைக்கிறது, மற்றும் ஏஜென்ட் அதன் நுழைவாயிலுடன் இணைக்கப்பட்ட OpenClaw-இன் முனைய UI-ஐத் திறக்கிறது. _Remove > AI > Desktop_ இன் கீழ் OpenClaw-ஐ நீக்குவது நுழைவாயில் சேவையையும் செயலியையும் அதனுடன் எடுத்துச் சென்று, பின்னர் `~/.openclaw` கூட போக வேண்டுமா என்று கேட்கிறது, ஏனெனில் அது OpenClaw-உடன் மற்றும் அது பதிவிறக்கும் செருகுநிரல் இயக்க நேரங்களுடன் உங்கள் அரட்டைகளையும் சான்றுகளையும் வைத்திருக்கிறது; இயல்புநிலை அதை வைத்திருக்கிறது, மற்றும் OpenClaw-ஐ மீண்டும் நிறுவுவது அதை மீண்டும் எடுத்துக்கொள்கிறது.

Herdr Desktop என்பது [Herdr](https://herdr.dev) டெஸ்க்டாப் செயலி: நீங்கள் சாளரத்தை மூடும்போது அதன் மையத்தில் தொடர்ந்து இயங்கும் முனையங்கள் மற்றும் குறியீட்டு ஏஜென்டுகளின் இடங்கள், தாவல்கள், மற்றும் பலகங்கள். இது ஒரு தொகுப்பை விட Herdr-இன் சொந்த நிறுவியிலிருந்து வருகிறது, எனவே இது `~/.local/share/herdr-app` இல் வாழ்கிறது, உங்களிடம் இன்னும் ஒன்று இல்லாதபோது அதன் மையத்தை `~/.local/bin/herdr-core` இல் கொண்டுவருகிறது, மற்றும் இரண்டையும் தானாகவே புதுப்பிக்கிறது. இது `Super + Ctrl + Return` இல் Omarchy வழங்கும் `herdr` கட்டளைக்கு அருகில் அமர்ந்திருக்கிறது, அதை மாற்றாமல், மற்றும் அந்தக் கட்டளையின் நேரடி விசைகளைப் பெறுகிறது: `Alt + Return` மற்றும் `Alt + Shift + Return` ஒரு பலகத்தை கீழே அல்லது வலதுபுறமாகப் பிரிக்கின்றன, `Alt + Escape` அதை மூடுகிறது, `Ctrl + Alt + Arrow` பலகங்களுக்கு இடையில் நகர்கிறது, `Alt + 1..9` மற்றும் `Alt + Left/Right` ஒரு தாவலைத் தேர்ந்தெடுக்கின்றன, மற்றும் `Alt + Up/Down` இடங்களுக்கு இடையில் நகர்கின்றன. `Ctrl + 1..9` ஒரு இடத்தைத் தேர்ந்தெடுக்கிறது மற்றும் `Alt + Shift + Up/Down` ஏஜென்டுகள் வழியாகச் செல்கிறது. `Ctrl + Space` முன்னொட்டு விசைகள் முனையத்திற்கு மட்டுமே இருக்கின்றன, ஏனெனில் செயலி ஒரு வரிசைக்காக வெற்று Ctrl விசையை வைத்திருக்க முடியாது. Omarchy இவற்றை `~/.config/herdr-app/keys.json` இல் எழுதுகிறது, மற்றும் `omarchy-refresh-herdr-app` அவற்றைத் திரும்ப வைக்கிறது. அதை நிறுவுவது Herdr-இன் Omarchy தீமைத் தேர்ந்தெடுக்கிறது, இது அதிலிருந்து உங்கள் Omarchy தீமைப் பின்பற்றுகிறது. Herdr ஒளி பயன்முறைக்கு ஒரு தீமையும் இருள் பயன்முறைக்கு ஒரு தீமையும் வைத்திருக்கிறது, எனவே இருண்ட மற்றும் ஒளி Omarchy தீமுக்கு இடையில் மாறிய பிறகு, மற்ற பயன்முறைக்காக Herdr-இன் தீம் தேர்ந்தெடுப்பாளரில் Omarchy-ஐ மீண்டும் ஒரு முறை தேர்ந்தெடுக்கவும்.

T3 Code ஒரு தொகுப்பை விட `~/.local/share/t3code` இல் அதன் அதிகாரப்பூர்வ AppImage வெளியீட்டிலிருந்து இயங்குகிறது, எனவே இது தானாகவே புதுப்பிக்கிறது. அதை நிறுவுவது Stable அல்லது Nightly சேனலில் தொடங்க வேண்டுமா என்று கேட்கிறது; பின்னர் T3 Code-இன் அமைப்புகளில் மாற்றவும். உங்கள் திரிகளும் அமைப்புகளும் `~/.t3` இல் வாழ்கின்றன, மற்றும் _Remove > AI > Desktop_ இன் கீழ் T3 Code-ஐ நீக்குவது அவற்றை அதனுடன் எடுத்துச் செல்கிறது.

### உள்ளூர் மாதிரிகள்

உங்கள் குறியீட்டு ஏஜென்டுகளுக்காக உங்கள் சொந்த இயந்திரத்தில் ஒரு திறந்த மாதிரியை இயக்கவும். உங்கள் தூண்டுதல்களும் குறியீடும் இயந்திரத்திலேயே இருக்கின்றன; மாதிரிக்கு அனுப்பப்படும் எதுவும் அதை விட்டு வெளியேறாது. இதனுடன் தொடங்கவும்:

```bash
omarchy models use best text
```

இது இந்த இயந்திரத்திற்கான சிறந்த உரை மாதிரியை அமைக்கிறது, உங்கள் ஏஜென்டுகள் பயன்படுத்தும் வகை. படம், காணொளி மற்றும் இசை மாதிரிகளுக்கு அவற்றின் சொந்த சிறந்தது உள்ளது: `omarchy models use best image`, `video` அல்லது `music`. இந்த இயந்திரத்திற்கான ஒவ்வொரு வகையின் தேர்வையும் பார்க்க `omarchy models use best` ஐ இயக்கவும்.

அல்லது ஏஜென்டுகள் பேனலில் + ஐத் தேர்ந்தெடுக்கவும்: _Use a local model_ இன் கீழ் இது இந்த இயந்திரத்திற்கு பொருந்தும் ஒவ்வொரு குறியீட்டு மாதிரியையும் பட்டியலிடுகிறது, பரிந்துரைக்கப்பட்டது முதலில். மாதிரிகளை இயக்கும் Podman, Omarchy உடன் வருகிறது, NVIDIA இயந்திரத்தில் NVIDIA-இன் கொள்கலன் கருவித்தொகுப்பும் வருகிறது, இது அவற்றுக்கு GPU-ஐ வழங்குகிறது; இரண்டில் ஒன்று காணவில்லை என்றால், முதல் அமைப்பு அதை நிறுவுகிறது. Omarchy பின்னர் இந்த இயந்திரத்திற்கான பரிந்துரைக்கப்பட்ட மாதிரியைத் தேர்ந்தெடுத்து, அதைப் பதிவிறக்கி, அதைத் தொடங்குகிறது. பத்துகள் GB பதிவிறக்கத்தையும் மாதிரி இயங்கும்போது இயந்திரத்தின் பெரும்பாலான நினைவகம் பயன்பாட்டில் இருப்பதையும் எதிர்பார்க்கவும்: Flash Next அதன் முழு 256K சூழலுடன் சுமார் 100 GiB பயன்படுத்துகிறது. அதற்குத் தேவையான நினைவகத்தை மற்ற மாதிரிகள் வைத்திருந்தால், அது நிறுத்தப்பட்ட நிலையில் அமைக்கப்படுகிறது, நீங்கள் ஒன்றை நிறுத்தியவுடன் தொடங்கத் தயாராக உள்ளது. மாதிரி வெளியேறும்போது நிற்கிறது; வேறு ஏதாவதற்கு நினைவகம் தேவைப்படும்போது அதை நீங்களே நிறுத்தவும்.

`omarchy models list` விருப்பங்களைக் காட்டுகிறது மற்றும் சில ஏன் பொருந்தவில்லை என்பதை விளக்குகிறது. மற்றொன்றை அமைக்க, `omarchy models use <recipe>` ஐ இயக்கவும். இன்று, 128 GB Strix Halo இயந்திரங்களுக்கு `qwen3.8-flash-next-gufo` மற்றும் `qwen3.8-27b-gufo` கிடைக்கின்றன; 27B சுமார் 40 GiB எடுக்கும், எனவே இது மற்ற வேலைகளுக்கு இடம் விடுகிறது. Intel-இன் Arc B390 உடன் 64 GB மடிக்கணினியில், `qwen3.6-35b-a3b-llamacpp` சுமார் 30 GiB இல் இயங்குகிறது. புதிய ரெசிபிகளும் பரிந்துரைகளும் தொகுப்பு வழியாக `omarchy update` உடன் வருகின்றன.

நீங்கள் சேர்க்கும் ஒரு குறியீட்டு மாதிரி ஏஜென்டுகள் பேனலில், உங்கள் சந்தாக்களுக்கு அருகில், அதன் சொந்த வரியைப் பெறுகிறது: அதைத் தொடங்க இயக்கவும், அதை நிறுத்தி அதன் நினைவகத்தை விடுவிக்க இடைநிறுத்தவும், அது இயங்கும்போது உங்கள் tailnet இல் உள்ள மற்ற இயந்திரங்களுடன் அதைப் பகிர Tailscale குறி, மற்றும் அதில் உங்கள் ஏஜென்டைத் திறக்க முனைய பொத்தான். அதன் வரி பதிவிறக்கம், ஏற்றம் அல்லது நிறுத்தத்தை அது செல்லும்போது காட்டுகிறது, மற்றும் அதைத் தொடங்க போதுமான இலவச நினைவகம் இல்லாதபோது அவ்வாறு கூறுகிறது, அல்லது அது பிழையுடன் நின்றபோது அதன் பதிவுகளுக்கு இணைக்கிறது. நினைவகத்தில் ஒன்றாகப் பொருந்தும்போது பல ஒரே நேரத்தில் இயங்க முடியும். தேர்ந்தெடுக்கப்பட்ட வரியில் Delete ஐ அழுத்தி மாதிரியை இந்த இயந்திரத்திலிருந்து நீக்கவும், பதிவிறக்கம் உட்பட; + அதை மீண்டும் அமைக்க முடியும். முனையத்திலிருந்து அமைக்கப்பட்ட ஒரு குறியீட்டு மாதிரி நீங்கள் அதைச் சேர்க்கும் வரை + இன் கீழ் காத்திருக்கிறது, நீங்கள் இணைத்த இயந்திரம் (`omarchy models pair <host>`) இயக்கும் மாதிரிகளும் அவ்வாறே.

நீங்கள் அமைக்கும் ஒவ்வொரு குறியீட்டு மாதிரியும் செயலி தொடக்கியில், மாதிரியின் பெயரின் கீழ் மற்றும் அதன் உருவாக்குநரின் லோகோவுடன், Claude, Codex அல்லது Grok இல் உள்நுழைவது ஒன்றைச் சேர்ப்பது போல, அதன் சொந்த உள்ளீட்டையும் பெறுகிறது. இது அந்த மாதிரியில் உங்கள் ஏஜென்டைத் திறக்கிறது, மற்றும் அது இயங்கவில்லை என்றால் முதலில் மாதிரியைத் தொடங்குகிறது: முனையம் அது ஏறுவதைக் காட்டி அது தயாரானவுடன் ஏஜென்டிடம் ஒப்படைக்கிறது. ஒரு மாதிரியை நீக்குவது அதன் உள்ளீட்டை நீக்குகிறது.

ஒவ்வொரு மாதிரியும் குறியீட்டுக்கானது அல்ல. படம், காணொளி மற்றும் இசை மாதிரிகள் அதற்கு பதிலாக Fantasi இல் திறக்கின்றன, இந்த இயந்திரத்தில் இயங்கும் மாதிரியுடன் படங்கள், காணொளி மற்றும் இசையை உருவாக்குவதற்கான Omarchy-இன் செயலி, மற்றும் அங்கே அல்லது `omarchy models` கொண்டு நிர்வகிக்கப்படுகின்றன.

ஒரு மாதிரி அது அமைக்கப்பட்டபடியே தொடர்ந்து இயங்குகிறது, எனவே Omarchy புதுப்பிப்பு ஒருபோதும் உங்கள் ஏஜென்டுகளின் கீழ் ஒன்றை மறுதொடக்கம் செய்யாது. நீங்கள் அமைத்த மாதிரிக்கு Omarchy இடம் புதிய இயக்க நேரம் அல்லது புதிய எடைகள் இருக்கும்போது, அதன் வரி ஒரு புதுப்பிப்பு பொத்தானைக் காட்டுகிறது: அதை அழுத்தவும் மற்றும் மாதிரி பின்னணியில் மீண்டும் அமைக்கப்படுகிறது, மாறியதை மட்டுமே பதிவிறக்கி, மற்றும் புதிய பதிப்பில் மறுதொடக்கம் செய்கிறது. நிறுத்தப்பட்ட மாதிரி நிறுத்தப்பட்டே இருக்கும். `omarchy models update` முனையத்திலிருந்து ஒவ்வொரு மாதிரிக்கும் அதையே செய்கிறது.

கட்டளை வரியிலிருந்து, `omarchy models start <recipe>` மற்றும் `omarchy models stop <recipe>` அதையே செய்கின்றன, `omarchy models status` ஒவ்வொரு மாதிரியையும் காட்டுகிறது, மற்றும் `omarchy agent --local-model <recipe>` உங்கள் இயல்புநிலை ஏஜென்ட் எதுவாக இருந்தாலும் அந்த மாதிரியை pi இல் திறக்கிறது. உங்கள் உள்ளூர் மாதிரியை ஏஜென்ட் ஹாட்கீ, Quake கன்சோல், மற்றும் _Make something_ திறக்கும் ஒன்றாக மாற்ற, `omarchy default agent local` ஐ இயக்கவும் அல்லது ஏஜென்டுகள் பேனலில் இயங்கும் மாதிரிக்கு நட்சத்திரமிடவும். pi நீங்கள் அமைத்த ஒவ்வொரு மாதிரியையும், மற்றும் நீங்கள் இணைத்த இயந்திரங்களில் உள்ளவற்றையும், அதன் சொந்த மாதிரி தேர்ந்தெடுப்பாளரில் பட்டியலிடுகிறது, எனவே வெற்று `pi` அவற்றையும் அடைகிறது. எந்த OpenAI-இணக்கமான கிளையண்டும் இணைக்க முடியும்: `status` ஒவ்வொரு மாதிரியின் முகவரியையும் காட்டுகிறது (முதலாவது `http://127.0.0.1:11435/v1`), ரெசிபி பெயர்தான் மாதிரி, மற்றும் விசை `~/.config/omarchy/agent-local/key` இல் உள்ளது.

`omarchy models remove <recipe>` ஒரு மாதிரியையும் வேறு எந்த மாதிரியும் பயன்படுத்தாத பதிவிறக்கங்களையும் நீக்குகிறது.

மூன்றாம் தரப்பு இயக்க நேரங்கள் அவற்றின் வெளியீட்டாளருடன் லேபிளிடப்பட்டுள்ளன. Omarchy ஒவ்வொரு மாதிரியையும் பிணைய அணுகல் இல்லாமல் இயக்குகிறது.

### உள்ளூர் LLMs

Omarchy உள்ளூர் LLM மாதிரிகளை இயக்க இரண்டு வழிகளைப் பரிந்துரைக்கிறது: LM Studio மற்றும் Ollama. LM Studio திறந்த-எடை மாதிரிகளைக் கண்டறிதல், அவற்றை நிறுவுதல், மற்றும் அவற்றை இயக்குவதற்கான GUI இடைமுகத்தை வழங்குகிறது. எளிதாகத் தொடங்க இது ஒரு சிறந்த வழி. Ollama இதேபோல் செய்வதற்கான CLI ஐ வழங்குகிறது. ஆனால் நீங்கள் உள்ளூர் மாதிரிகளுக்குப் புதியவர் என்றால், நான் LM Studio உடன் தொடங்குவேன். Omarchy Menu இல் _Install > AI > Desktop_ இலிருந்து LM Studio ஐயும் _Install > AI > CLI_ இலிருந்து Ollama ஐயும் நிறுவவும்.

### Omarchy திறன்கள்

ஏஜென்ட் திறன்கள் AI குறிப்பிட்ட கருவிகளை ஒரு குறிப்பிட்ட வழியில் பயன்படுத்த உதவுகின்றன, மற்றும் Omarchy அவற்றில் ஏழை வழங்குகிறது. omarchy திறன் அமைப்பைத் தனிப்பயனாக்குவதை உள்ளடக்குகிறது, உங்கள் Hyprland கட்டமைப்பைச் சரிசெய்தல் அல்லது பட்டியைச் சரிசெய்தல் போன்றவை. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app, மற்றும் omarchy-make-game புதிதாக ஏதாவது உருவாக்குவதை உள்ளடக்குகின்றன, omarchy-contribute ஒரு பிழையைப் புகாரளித்தல் அல்லது மேல்நிலைக்கு ஒரு திருத்தத்தை அனுப்புவதை உள்ளடக்குகிறது, மற்றும் omarchy-diagnose-crash ஒரு செயலிழப்பின் கோர் டம்ப் வழியாகச் செல்கிறது. அவை Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` மற்றும் ஒவ்வொரு `~/.hermes/profiles/*/skills`), மற்றும் பொதுவான `~/.agents/skills` இடத்திற்கான திறன் அடைவுகளில் சிம்லிங்க் செய்யப்பட்டுள்ளன, எனவே பெரும்பாலான ஹார்னஸ்கள் அவற்றைத் தானாகவே எடுத்துக்கொள்கின்றன. அதே பெயரைக் கொண்ட உங்கள் சொந்த திறன் கோப்புறை முன்னுரிமை பெறுகிறது.

ஆனால் நீங்கள் இந்தத் திறன்களை சோதனை முயற்சியாகக் கருத வேண்டும். வெவ்வேறு மாதிரிகள் அதை வெவ்வேறு விளைவுகளுக்குப் பயன்படுத்தும். முதலில் திட்டப் பயன்முறையில் இயக்குவது சிறந்தது, எனவே ஏஜென்ட் எதை மாற்ற விரும்புகிறது என்பது பற்றிய யோசனை உங்களுக்கு இருக்கும். பின்னர் மாற்றங்களைத் திரும்பப் பெற அல்லது ஏஜென்ட் எல்லாவற்றையும் குழப்பினால் `omarchy reinstall configs` ஐ அழைக்கவும் தயாராக இருங்கள்.
