# மேம்பாட்டுக் கருவிகள்

## மாற்று எடிட்டர்கள்

Omarchy முன்னிருப்பாக [Neovim](https://neovim.io/) உடன் வருகிறது, ஆனால் இன்னும் கொஞ்சம் பிரதானமானதும் பழக்கமானதுமான ஒன்றை நீங்கள் விரும்பினால், Omarchy Menu (`Super + Space`) ஐ இயக்கி, _Install > Editor_ கீழ் உள்ள விருப்பங்களைப் பார்க்கலாம். அங்கு VSCode, Cursor, Zed, Sublime Text, Helix, Vim மற்றும் Emacs ஆகியவற்றை நாங்கள் பட்டியலிட்டுள்ளோம். நீங்கள் தேடுவது கிடைக்கவில்லை என்றால், _Install > Package_ ஐப் பாருங்கள், அது ஒரு Arch தொகுப்பில் இல்லையா என்று பாருங்கள் (இல்லையென்றால், AUR ஐச் சரிபார்க்க _Install > AUR_ ஐ முயற்சிக்கவும்).

அசல் `vi` எடிட்டரும் பெட்டியிலிருந்து வெளியே வந்தவுடனேயே கிடைக்கிறது. டெர்மினலில் ஒரு கோப்பைத் திருத்த `vi filename` ஐ இயக்கவும்.

`VSCode`, `Cursor`, `VSCodium` மற்றும் `Helix` ஆகியவற்றுக்குத் தீம் பொருத்தம் வழங்கப்படுகிறது.

கணினி முழுவதற்குமான முன்னிருப்பு எடிட்டரை `Setup > Defaults > Editor` கீழ் அமைக்கலாம்.

## சூழல்

Omarchy Menu (`Super + Space`) இன் _Install > Development_ பிரிவின் மூலம் முழு அளவிலான மேம்பாட்டுச் சூழல்களை அமைப்பதை Omarchy ஆதரிக்கிறது. நிச்சயமாக _Ruby on Rails_ ஐக் காண்பீர்கள், ஆனால் JavaScript இற்கான மூன்று முக்கிய ரன்டைம்களும் (Node.js, Bun, Deno), Laravel மற்றும் Symfony போன்ற பிரபலமான PHP கட்டமைப்புகளும் உள்ளன. ஓ, அத்துடன் Go, Rust, Python, Java, Elixir (Phoenix உடன்), .NET, OCaml, Zig, Clojure மற்றும் Scala ஆகியவையும் உள்ளன. இது மிகவும் பரந்த தேர்வு!

இந்தச் சூழல்களில் பெரும்பாலானவை [Mise](https://mise.jdx.dev/) மூலம் நிர்வகிக்கப்படுகின்றன. ஒரே கணினியில் ஒரு நிரலாக்க மொழியின் பல பதிப்புகளை நிறுவி இயக்க உங்களை அனுமதிக்கும் கருவி இது. Ruby க்கான rbenv அல்லது rvm போல, அல்லது Python க்கான virtualenv போல இது, ஆனால் இது பல வேறுபட்ட சூழல்களுக்கு வேலை செய்கிறது.

எடுத்துக்காட்டாக, Ruby ஐ நிறுவ, `mise use -g ruby` ஐ இயக்குவீர்கள், இது Ruby ஐ நிறுவுவதுடன் அதை உலகளாவிய முன்னிருப்பாகவும் அமைக்கும். அல்லது, உங்கள் திட்டத்தில் .ruby-version கோப்பு இருந்தால், அந்தத் திட்டத்தின் ரூட்டில் `mise i` ஐ இயக்கினாலே போதும்.

## முன்கூட்டியே நிறுவப்பட்ட CLI கருவிகள்

[mise இன் lazy நிறுவல்](https://mise.jdx.dev/dev-tools/shims.html#lazy-tools) மூலம் `gh`, `uv` மற்றும் பெரும்பாலான [கோடிங் ஏஜெண்டுகளை](17-ai.md) Omarchy கிடைக்கச் செய்கிறது. முதல் முறை அவற்றில் ஒன்றை இயக்கும்போது, mise அதை நிறுவுகிறது. பிற்கால இயக்கங்கள் நிறுவப்பட்ட பதிப்பையே மீண்டும் பயன்படுத்துகின்றன; ஒவ்வொரு தொடக்கத்திலும் அவை புதுப்பிப்பு இருக்கிறதா என்று சரிபார்ப்பதில்லை.

முன்னிருப்புகளை நீங்கள் ஆய்வு செய்யலாம் அல்லது முன்கூட்டியே அவற்றை நிறுவலாம்:

```bash
mise ls --current              # List the tools configured for this directory
mise install gh               # Install one tool now
mise install --include-lazy    # Install all configured tools, including lazy tools
```

நிறுவப்பட்ட கருவிகளை Omarchy இன் மீதியுடன் சேர்த்துப் புதுப்பிக்க `omarchy update` ஐ இயக்கவும். `mup` என்ற மாற்றுப்பெயர் mise நிர்வகிக்கும் கருவிகளை மட்டுமே புதுப்பிக்கிறது. உங்கள் சொந்த உள்ளமைவில் மற்றொரு கருவியைச் சேர்க்க, `mise use -g <tool>` ஐப் பயன்படுத்தவும்.

Python அமைப்பும் mise மூலம் `uv` ஐ நிறுவுகிறது. Python மேம்பாட்டுச் சூழலை அகற்றுவது `uv` ஐ ஒரு தனித்த கருவியாகக் கிடைக்கவே வைத்திருக்கும்.

### உங்கள் சொந்த நிறுவலைப் பயன்படுத்துதல்

mise இன் கட்டளைகள் `PATH` இல் `~/.local/bin` க்கு முன் வருகின்றன, எனவே எடுத்துக்காட்டாக Claude Code இன் அல்லது Cursor இன் சொந்த நிறுவியைக் கொண்டு நீங்களே நிறுவிய ஒரு கருவி, இன்னும் mise இன் நகலையே இயக்கும். டெஸ்க்டாப்பிலிருந்து தொடங்கப்படும் செயலிகளும் கணினித் தொகுப்புகளுக்கு முன் mise இன் கட்டளைகளையே கண்டுபிடிக்கின்றன, எனவே `gh` ஐ இயக்கும் ஒரு செயலி, நீங்கள் pacman மூலம் `github-cli` ஐ நிறுவியிருந்தாலும் mise இன் நகலையே பெறும், முதல் முறை mise அந்த நகலை நிறுவும். அதற்குப் பதிலாக உங்களுடையதைப் பயன்படுத்த, `~/.config/mise/config.toml` இல் mise இன் நகலை முடக்கவும். எடுத்துக்காட்டாக, Cursor CLI ஐ நீங்களே நிறுவியிருந்தால்:

```toml
[settings]
disable_tools = ["cursor-agent"]
```

ஏற்கனவே `[settings]` அட்டவணை இருந்தால், உள்ளீட்டை அங்கே சேர்க்கவும்; ஏற்கனவே உள்ள `disable_tools` பட்டியலை மாற்றுவதற்குப் பதிலாக அதை நீட்டிக்கவும். உங்கள் நிறுவல் `PATH` இல் இருப்பதை உறுதிப்படுத்தவும். mise கருவியின் பெயரைப் பயன்படுத்தவும், அது அதன் கட்டளையிலிருந்து வேறுபடலாம்: எடுத்துக்காட்டாக, `oh-my-pi` ஆனது `omp` ஐ வழங்குகிறது. முன்னிருப்பு-ஏஜெண்ட் தொடக்கியும் `~/.local/bin` இல் பயனர் நிறுவிய Cursor அல்லது Muse ஐயே விரும்புகிறது.

### முன்னிருப்புகளை அகற்றுதலும் மீட்டமைத்தலும்

_Remove Preinstalls_ ஆனது, `~/.config/mise/miserc.toml` இல் `ignored_config_paths` இல் அவற்றைச் சேர்ப்பதன் மூலம், உங்கள் பயனருக்கு Omarchy இன் கருவி அறிவிப்புகளைத் தவிர்க்குமாறு mise ஐச் செய்கிறது. _Restore Preinstalls_ அந்த வரியை மீண்டும் நீக்குகிறது. உங்கள் சொந்த உள்ளமைவில் அல்லது ஒரு திட்டத்தின் `mise.toml` இல் நீங்களே அறிவிக்கும் கருவிகள், எப்படியிருந்தாலும் தொடர்ந்து வேலை செய்யும். முன்கூட்டிய நிறுவல்களை அகற்றிய பிறகு நீங்கள் ஒரு முன்னிருப்பு ஏஜெண்டைத் தேர்ந்தெடுத்தால் அல்லது Python ஐ அமைத்தால், அந்தக் கருவி உங்கள் சொந்த உள்ளமைவில் சேர்க்கப்படும். இரண்டும் உங்கள் பயனருக்கு மட்டுமே பொருந்தும்; கணினியில் உள்ள மற்ற பயனர்கள் தங்கள் சொந்தத் தேர்வை வைத்திருப்பார்கள்.

## Docker

[Docker](https://www.docker.com/) க்கு அறிமுகம் எதுவும் hardly தேவையில்லை. தனிமைப்படுத்தப்பட்ட கொள்கலன்களை இயக்க இது உங்களை அனுமதிக்கிறது, மேலும் Docker ஐயும் [Docker Compose](https://docs.docker.com/compose/) ஐயும் உள்ளடக்கி, அதை நன்றாக இயக்கத் தேவையான அனைத்தையும் Omarchy நிறுவுகிறது.

முன்னிருப்பாக உங்கள் பயனர் `docker` குழுவில் *இல்லை*. அந்தக் குழு உண்மையில் கடவுச்சொல் இல்லாத root ஆகும் — அதில் உள்ள எதுவும் `docker run -v /:/host` ஐ இயக்கி கணினியைக் கைப்பற்ற முடியும் — எனவே உங்களாக இயங்கும் ஒரே ஒரு மோசமான ஸ்கிரிப்ட் அல்லது சார்பு, இல்லையென்றால் root இலிருந்து ஒரு கட்டளை தூரத்தில் இருக்கும். எனவே கட்டளை வரியில் நீங்கள் Docker ஐ `sudo` உடன் இயக்குகிறீர்கள் (`sudo docker ps`, `sudo docker compose up`), மேலும் டீமனுடன் பேசும் வரைகலைக் கருவிகள் — Windows VM — தேவைப்படும்போது உங்களிடம் அங்கீகாரம் கேட்கும். குழு இல்லாத அமைப்பின் வசதியை மீண்டும் விரும்பி, அதன் பரிமாற்றத்தைப் புரிந்துகொண்டால், **Setup > Security > Sudoless Docker** இலிருந்து அதை இயக்கவும் (அல்லது `omarchy-setup-security-sudoless-docker` ஐ இயக்கவும்), இது ஒரு எச்சரிக்கைக்குப் பிறகு உங்களை `docker` குழுவில் சேர்க்கும்; பிறகு எளிய `docker` மற்றும் `d` மாற்றுப்பெயர் மீண்டும் `sudo` இல்லாமல் வேலை செய்யும்.

Omarchy மெனுவில் _Install > Development > Docker DB_ ஐப் பயன்படுத்தி உள்ளூர் மேம்பாட்டிற்கான பொதுவான தரவுத்தளங்களை Docker இல் அமைக்கலாம்.

## GitHub CLI

டெர்மினலிலிருந்து களஞ்சியங்கள், சிக்கல்கள் மற்றும் pull request களுடன் வேலை செய்ய [GitHub CLI](https://cli.github.com/) ஆனது `gh` ஆகக் கிடைக்கிறது. முதல் பயன்பாட்டில் அதை நிறுவி அங்கீகரிக்க `gh auth login` ஐ இயக்கவும், பிறகு ஒரு களஞ்சியத்தை நகலெடுக்க `gh repo clone org/repo` ஐ இயக்கவும். அதன் கட்டளைகளை ஆராய `gh --help` ஐ இயக்கவும்.

pull request களுக்கான டெர்மினல் இடைமுகத்திற்கு, `ghui` ஐ இயக்கவும்; mise முதல் பயன்பாட்டிலேயே அதையும் நிறுவுகிறது. Git உடனேயே வேலை செய்ய [Lazygit](https://github.com/jesseduffield/lazygit) முன்கூட்டியே நிறுவப்பட்டுள்ளது.
