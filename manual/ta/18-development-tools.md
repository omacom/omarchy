# மேம்பாட்டுக் கருவிகள்

## மாற்று எடிட்டர்கள்

புதிய நிறுவல்களில் Omarchy இயல்புநிலை எடிட்டராக Plain உடன் வருகிறது, மேலும் [Neovim](https://neovim.io/) முன்பே நிறுவப்பட்டிருக்கும், ஆனால் இன்னும் கொஞ்சம் பிரதானமான, பழக்கமான ஒன்று வேண்டுமென்றால், Omarchy Menu (`Super + Space`) ஐ இயக்கி _Install > Editor_ கீழ் உள்ள விருப்பங்களைப் பாருங்கள். அங்கே VSCode, Cursor, Zed, Sublime Text, Helix, Vim, மற்றும் Emacs பட்டியலிடப்பட்டுள்ளன. நீங்கள் தேடுவது கிடைக்கவில்லை என்றால், _Install > Package_ ஐப் பாருங்கள், அது ஒரு Arch package இல் இல்லையா என்று பாருங்கள் (இல்லையென்றால், AUR ஐச் சரிபார்க்க _Install > AUR_ ஐ முயற்சியுங்கள்).

அசல் `vi` எடிட்டரும் தொடக்கத்திலிருந்தே கிடைக்கிறது. டெர்மினலில் ஒரு கோப்பைத் திருத்த `vi filename` ஐ இயக்குங்கள்.

`VSCode`, `Cursor`, `VSCodium`, மற்றும் `Helix` ஆகியவற்றுக்கு தீம் பொருத்தம் வழங்கப்படுகிறது.

கணினி முழுவதற்குமான இயல்புநிலை எடிட்டரை `Setup > Defaults > Editor` கீழ் அமைக்கலாம்.

## சூழல்

Omarchy Menu (`Super + Space`) இன் _Install > Development_ பிரிவின் வழியாக ஏராளமான மேம்பாட்டுச் சூழல்களை அமைப்பதை Omarchy ஆதரிக்கிறது. நிச்சயமாக _Ruby on Rails_ அங்கே கிடைக்கும், ஆனால் JavaScript க்கான மூன்று முக்கிய ரன்டைம்களும் (Node.js, Bun, Deno), மேலும் Laravel மற்றும் Symfony போன்ற பிரபலமான PHP ஃபிரேம்வொர்க்குகளும் கிடைக்கும். ஓ, Go, Rust, Python, Java, Elixir (Phoenix உடன்), .NET, OCaml, Zig, Clojure, மற்றும் Scala வும் உள்ளன. இது மிகவும் பரந்த தேர்வு!

இந்தச் சூழல்களில் பெரும்பாலானவற்றை [Mise](https://mise.jdx.dev/) நிர்வகிக்கிறது. இது ஒரே கணினியில் ஒரு நிரலாக்க மொழியின் பல பதிப்புகளை நிறுவி இயக்க உங்களை அனுமதிக்கும் கருவி. இது Ruby க்கான rbenv அல்லது rvm போல, அல்லது Python க்கான virtualenv போல, ஆனால் இது பல்வேறு சூழல்களுக்கு வேலை செய்கிறது.

உதாரணமாக Ruby ஐ நிறுவ, `mise use -g ruby` ஐ இயக்குவீர்கள்; இது Ruby ஐ நிறுவுவதுடன் அதை உலகளாவிய இயல்புநிலையாகவும் அமைக்கும். அல்லது, உங்கள் திட்டத்தில் .ruby-version கோப்பு இருந்தால், அந்தத் திட்டத்தின் ரூட்டில் `mise i` ஐ இயக்கினாலே போதும்.

## முன்பே நிறுவப்பட்ட CLI கருவிகள்

`uv`, Node.js, மற்றும் `playwright-cli` (நிறுவப்பட்ட Chrome ஐப் பயன்படுத்தி உலாவியை ஏஜெண்டுகள் இயக்குவதற்கு) ஆகியவை package களாக நிறுவப்பட்டு வருகின்றன, மேலும் `omarchy update` அவற்றை மீதமுள்ள கணினியுடன் தற்போதைய நிலையில் வைத்திருக்கிறது. `ghui`, [Hunk](https://github.com/modem-dev/hunk), மற்றும் Basecamp, Cloudflare மற்றும் HEY CLI கள் _Install > CLI_ கீழ் ஒரு தேர்வு தொலைவில் உள்ளன, மேலும் [கோடிங் ஏஜெண்டுகள்](17-ai.md) _Install > AI > CLI_ கீழ் உள்ளன.

mise நீங்கள் _Install > Development_ இலிருந்து அமைக்கும் ரன்டைம்களை மட்டுமே நிர்வகிக்கிறது; Omarchy தானாக அதன் வழியாக எதையும் நிறுவாது. அவற்றை மீதமுள்ள Omarchy உடன் புதுப்பிக்க `omarchy update` ஐ இயக்குங்கள்; `mup` மாற்றுப்பெயர் mise ஆல் நிர்வகிக்கப்படும் கருவிகளை மட்டும் புதுப்பிக்கிறது. உங்கள் சொந்த உள்ளமைவில் மற்றொரு கருவியைச் சேர்க்க, `mise use -g <tool>` ஐப் பயன்படுத்துங்கள்.

## Docker

[Docker](https://www.docker.com/) க்கு அதிக அறிமுகம் தேவையில்லை. இது தனிமைப்படுத்தப்பட்ட கண்டெய்னர்களை இயக்க உங்களை அனுமதிக்கிறது, மேலும் அதை நன்றாக இயக்கத் தேவையான அனைத்தையும் Omarchy நிறுவுகிறது, Docker தானும் [Docker Compose](https://docs.docker.com/compose/) உம் உட்பட.

இயல்பாகவே உங்கள் பயனர் `docker` குழுவில் *இல்லை*. அந்தக் குழு நடைமுறையில் கடவுச்சொல் இல்லாத root — அதில் உள்ள எதுவும் `docker run -v /:/host` ஐ இயக்கி கணினியைக் கைப்பற்ற முடியும் — எனவே உங்களாக இயங்கும் ஒரே ஒரு மோசமான ஸ்கிரிப்ட் அல்லது சார்பு, இல்லையென்றால் root க்கு ஒரே ஒரு கட்டளை தொலைவில் இருக்கும். எனவே கட்டளை வரியில் நீங்கள் Docker ஐ `sudo` உடன் இயக்குகிறீர்கள் (`sudo docker ps`, `sudo docker compose up`), மேலும் டீமனுடன் பேசும் வரைகலைக் கருவிகள் — Windows VM — தேவைப்படும்போது அங்கீகாரம் கேட்கும். குழு இல்லாத அமைப்பின் வசதி மீண்டும் வேண்டும், அதற்கான சமரசமும் புரிகிறது என்றால், **Setup > Security > Sudoless Docker** இலிருந்து அதை இயக்குங்கள் (அல்லது `omarchy-setup-security-sudoless-docker` ஐ இயக்குங்கள்); இது ஒரு எச்சரிக்கைக்குப் பிறகு உங்களை `docker` குழுவில் சேர்க்கும்; பிறகு சாதாரண `docker` மற்றும் `d` மாற்றுப்பெயர் மீண்டும் `sudo` இல்லாமல் வேலை செய்யும்.

Omarchy மெனுவில் _Install > Development > Docker DB_ ஐப் பயன்படுத்தி Docker இல் உள்ளூர் மேம்பாட்டுக்கான பொதுவான தரவுத்தளங்களை அமைக்கலாம்.

## GitHub CLI

[GitHub CLI](https://cli.github.com/) என்பது `gh`, டெர்மினலில் இருந்து ரெப்போசிட்டரிகள், இஷ்யூக்கள் மற்றும் புல் ரிக்வெஸ்டுகளுடன் வேலை செய்வதற்கு. அங்கே GitHub இல் உள்நுழைய நீங்கள் தேர்ந்தெடுக்கும்போது _Setup > Git_ அதை நிறுவுகிறது, பிறகு `gh repo clone org/repo` ஒரு ரெப்போசிட்டரியை குளோன் செய்கிறது. அதன் கட்டளைகளை ஆராய `gh --help` ஐ இயக்குங்கள்.

_Install > CLI > GitHub_ GitHub CLI, `gh` ஐ, புல் ரிக்வெஸ்டுகளுக்கான டெர்மினல் இடைமுகமான `ghui` உடன் நிறுவுகிறது. Git உடனேயே வேலை செய்வதற்கு [Lazygit](https://github.com/jesseduffield/lazygit) முன்பே நிறுவப்பட்டுள்ளது.
