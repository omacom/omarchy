# மேம்பாட்டுக் கருவிகள்

## மாற்றுத் திருத்திகள்

Omarchy இயல்பாக [Neovim](https://neovim.io/) உடன் வருகிறது, ஆனால் இன்னும் பரவலான, பழக்கமான ஒன்று வேண்டுமென்றால், Omarchy மெனுவை (`Super + Space`) திறந்து _நிறுவு > Editor_ க்குக் கீழ் உள்ள விருப்பங்களைப் பார்க்கலாம். அங்கு VSCode, Cursor, Zed, Sublime Text, Helix, Vim மற்றும் Emacs உள்ளன. நீங்கள் தேடுவது கிடைக்கவில்லை என்றால், _நிறுவு > Package_ ஐப் பாருங்கள், Arch தொகுப்பில் அது இருக்கிறதா என்று பாருங்கள் (இல்லை என்றால், AUR ஐச் சரிபார்க்க _நிறுவு > AUR_ ஐ முயற்சிக்கவும்).

அசல் `vi` திருத்தியும் உடனே கிடைக்கிறது. முனையத்தில் ஒரு கோப்பைத் திருத்த `vi filename` என்று இயக்கவும்.

`VSCode`, `Cursor`, `VSCodium` மற்றும் `Helix` க்கு தீம் பொருத்தம் வழங்கப்படுகிறது.

கணினி அளவிலான இயல்புநிலைத் திருத்தியை `அமைப்பு > இயல்புநிலைகள் > Editor` க்குக் கீழ் அமைக்கலாம்.

## சூழல்

Omarchy மெனுவின் (`Super + Space`) _நிறுவு > Development_ பிரிவு மூலம் பலவிதமான மேம்பாட்டுச் சூழல்களை அமைக்க Omarchy ஆதரிக்கிறது. நிச்சயமாக _Ruby on Rails_ கிடைக்கும், அத்துடன் JavaScript க்கான மூன்று முக்கிய இயக்க நேரங்களும் (Node.js, Bun, Deno), Laravel மற்றும் Symfony போன்ற பிரபலமான PHP கட்டமைப்புகளும் உள்ளன. ஓ, Go, Rust, Python, Java, Elixir (Phoenix உடன்), .NET, OCaml, Zig, Clojure மற்றும் Scala வும் உள்ளன. மிகவும் பரந்த தேர்வு!

இந்தச் சூழல்களில் பெரும்பாலானவை [Mise](https://mise.jdx.dev/) ஆல் நிர்வகிக்கப்படுகின்றன. ஒரே இயந்திரத்தில் ஒரு நிரலாக்க மொழியின் பல பதிப்புகளை நிறுவி இயக்க உதவும் கருவி இது. Ruby க்கான rbenv அல்லது rvm போல, அல்லது Python க்கான virtualenv போல, ஆனால் பல்வேறு சூழல்களில் இது வேலை செய்கிறது.

எடுத்துக்காட்டாக Ruby ஐ நிறுவ, `mise use -g ruby` என்று இயக்கினால், Ruby நிறுவப்படுவதோடு உலகளாவிய இயல்புநிலையாகவும் அமைக்கப்படும். அல்லது, உங்கள் திட்டத்தில் .ruby-version கோப்பு இருந்தால், அந்தத் திட்டத்தின் மூலத்தில் `mise i` என்று இயக்கினாலே போதும்.

## Docker

[Docker](https://www.docker.com/) க்கு அறிமுகம் தேவையில்லை. தனிமைப்படுத்தப்பட்ட கொள்கலன்களை இயக்க இது உதவுகிறது, மேலும் Omarchy அதைச் சிறப்பாக இயக்கத் தேவையான அனைத்தையும் நிறுவுகிறது, Docker உட்பட [Docker Compose](https://docs.docker.com/compose/) உட்பட.

இயல்பாக உங்கள் பயனர் `docker` குழுவில் *இல்லை*. அந்தக் குழு நடைமுறையில் கடவுச்சொல் இல்லாத root — அதில் உள்ள எதுவும் `docker run -v /:/host` என்று இயக்கி இயந்திரத்தைக் கைப்பற்றலாம் — எனவே உங்களாக இயங்கும் ஒரு முரட்டு ஸ்கிரிப்ட் அல்லது சார்பு root இலிருந்து ஒரு கட்டளை தொலைவில் இருக்கும். எனவே கட்டளை வரியில் Docker ஐ `sudo` உடன் இயக்குகிறீர்கள் (`sudo docker ps`, `sudo docker compose up`), மேலும் டீமனுடன் பேசும் வரைகலைக் கருவிகள் — Windows VM — தேவைப்படும்போது அங்கீகாரம் கேட்கும். குழுவில்லாத அமைப்பின் வசதியை மீண்டும் விரும்பினால், பரிமாற்றத்தைப் புரிந்து கொண்டால், **அமைப்பு > Security > Sudoless Docker** இலிருந்து அதை இயக்கவும் (அல்லது `omarchy-setup-security-sudoless-docker` என்று இயக்கவும்), இது எச்சரிக்கைக்குப் பிறகு உங்களை `docker` குழுவில் சேர்க்கிறது; பின்னர் வெற்று `docker` மற்றும் `d` மாற்றுப்பெயர் `sudo` இல்லாமல் மீண்டும் வேலை செய்யும்.

Omarchy மெனுவில் _நிறுவு > Development > Docker DB_ ஐப் பயன்படுத்தி உள்ளூர் மேம்பாட்டிற்கான பொதுவான தரவுத்தளங்களை Docker இல் அமைக்கலாம்.

## GitHub CLI

[The GitHub CLI](https://cli.github.com/) உங்கள் GitHub கணக்குடன் அங்கீகரிக்கவும் அதைப் பயன்படுத்தித் தனியார் களஞ்சியங்களை நகலெடுக்கவும் உதவுகிறது. இது சோம்பேறித்தனமாக ஏற்றப்படும் mise stub களில் ஒன்றாக இணைக்கப்பட்டுள்ளது, எனவே முதல் முறை `gh` ஐ இயக்கும்போது, அது தன்னைத்தானே நிறுவும். அங்கீகரிக்க, `gh auth login` என்று இயக்கவும். பின்னர் `gh repo clone org/repo` ஐப் பயன்படுத்தித் தனியார் களஞ்சியங்களைப் பெறலாம்.

இந்தக் கட்டளையைப் பயன்படுத்தி வேறு பல GitHub செயல்பாடுகளையும் செய்யலாம். என்னென்ன சாத்தியம் என்பதைப் பார்க்க `gh` என்று இயக்கவும்.

TUI இல் உங்கள் pull request களை நிர்வகிக்க `ghui` க்கும் சோம்பேறித்தனமாக நிறுவும் stub ஒன்று உள்ளது. மேலும் [lazygit](https://github.com/jesseduffield/lazygit) முன்கூட்டியே நிறுவப்பட்டுள்ளது, git ஐயும் TUI இலிருந்தே இயக்க விரும்பினால் பயன்படுத்தலாம்.
