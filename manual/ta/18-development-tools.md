# மேம்பாட்டுக் கருவிகள்

## மாற்று எடிட்டர்கள்

Omarchy புதிய நிறுவல்களில் Plain ஐ இயல்புநிலை எடிட்டராகக் கொண்டு வருகிறது, [Neovim](https://neovim.io/) முன்னரே நிறுவப்பட்டிருக்கும், ஆனால் இன்னும் கொஞ்சம் பரவலாகப் பயன்படுத்தப்படும், பரிச்சயமான ஒன்று உங்களுக்கு வேண்டுமானால், Omarchy Menu (`Super + Space`) ஐ இயக்கி, _நிறுவு > எடிட்டர்_ என்பதன் கீழ் உள்ள விருப்பங்களைப் பார்க்கலாம். அங்கே VSCode, Cursor, Zed, Sublime Text, Helix, Vim, மற்றும் Emacs ஆகியவை பட்டியலிடப்பட்டுள்ளன. நீங்கள் தேடுவதைக் கண்டுபிடிக்க முடியவில்லை என்றால், _நிறுவு > தொகுப்பு_ ஐப் பாருங்கள், அது ஒரு Arch தொகுப்பில் இல்லையா என்று பாருங்கள் (இல்லையெனில், AUR ஐச் சரிபார்க்க _நிறுவு > AUR_ ஐ முயற்சிக்கவும்).

அசல் `vi` எடிட்டரும் தொடக்க நிலையிலேயே கிடைக்கிறது. டெர்மினலில் கோப்பைத் திருத்த `vi filename` என்று இயக்கவும்.

`VSCode`, `Cursor`, `VSCodium`, மற்றும் `Helix` ஆகியவற்றுக்கு தீம் பொருத்தம் வழங்கப்படுகிறது.

கணினி முழுவதற்கான இயல்புநிலை எடிட்டரை `அமைப்பு > இயல்புநிலைகள் > எடிட்டர்` என்பதன் கீழ் நீங்கள் அமைக்கலாம்.

## சுற்றுச்சூழல்

Omarchy Menu (`Super + Space`) இன் _நிறுவு > மேம்பாடு_ பிரிவின் மூலம் முழு அளவிலான மேம்பாட்டுச் சூழல்களை அமைப்பதை Omarchy ஆதரிக்கிறது. நிச்சயமாக நீங்கள் _Ruby on Rails_ ஐக் காண்பீர்கள், ஆனால் JavaScript க்கான மூன்று முக்கிய ரன்டைம்களும் (Node.js, Bun, Deno), Laravel மற்றும் Symfony போன்ற பிரபலமான PHP கட்டமைப்புகளும் கிடைக்கும். ஓ, மேலும் Go, Rust, Python, Java, Elixir (Phoenix உடன்), .NET, OCaml, Zig, Clojure, மற்றும் Scala கூட உள்ளன. இது மிகவும் பரந்த தேர்வு!

இந்தச் சூழல்களில் பெரும்பாலானவை [Mise](https://mise.jdx.dev/) மூலம் நிர்வகிக்கப்படுகின்றன. இது ஒரே கணினியில் ஒரு நிரலாக்க மொழியின் பல பதிப்புகளை நிறுவி இயக்க உங்களை அனுமதிக்கும் கருவி. இது Ruby க்கான rbenv அல்லது rvm அல்லது Python க்கான virtualenv போன்றது, ஆனால் இது பல வேறுபட்ட சூழல்களுக்குப் பொருந்தும்.

உதாரணமாக, Ruby ஐ நிறுவ, நீங்கள் `mise use -g ruby` என்று இயக்க வேண்டும், அது Ruby ஐ நிறுவுவதோடு, அதை உலகளாவிய இயல்புநிலையாகவும் அமைக்கும். அல்லது, உங்கள் திட்டத்தில் .ruby-version கோப்பு இருந்தால், அந்தத் திட்டத்தின் ரூட்டில் `mise i` என்று இயக்கினாலே போதும்.

## முன்னரே நிறுவப்பட்ட CLI கருவிகள்

Omarchy, `gh`, `uv`, மற்றும் பெரும்பாலான [குறியீட்டு ஏஜெண்டுகள்](17-ai.md) போன்ற கருவிகளை [mise's lazy installation](https://mise.jdx.dev/dev-tools/shims.html#lazy-tools) மூலம் கிடைக்கச் செய்கிறது. முதல் முறை நீங்கள் ஒன்றை இயக்கும்போது, mise அதை நிறுவுகிறது. குறியீட்டு ஏஜெண்டுகள் பிறகு இயங்குவதற்கு முன் ஒரு புதுப்பிப்பைச் சரிபார்க்கின்றன, அதிகபட்சம் நான்கு மணிநேரத்திற்கு ஒரு முறை; `gh` மற்றும் `uv` போன்ற பிற கருவிகள், நீங்கள் புதுப்பிக்கும் வரை நிறுவப்பட்ட பதிப்பையே மீண்டும் பயன்படுத்துகின்றன.

இயல்புநிலைகளை நீங்கள் பார்வையிடவோ அல்லது முன்கூட்டியே அவற்றை நிறுவவோ கூட முடியும்:

```bash
mise ls --current              # List the tools configured for this directory
mise install gh               # Install one tool now
mise install --include-lazy    # Install all configured tools, including lazy tools
```

நிறுவப்பட்ட கருவிகளை Omarchy இன் மீதமுள்ளவற்றுடன் புதுப்பிக்க `omarchy update` என்று இயக்கவும். `mup` மாற்றுப்பெயர் mise மூலம் நிர்வகிக்கப்படும் கருவிகளை மட்டுமே புதுப்பிக்கிறது. உங்கள் சொந்த உள்ளமைவில் மற்றொரு கருவியைச் சேர்க்க, `mise use -g <tool>` ஐப் பயன்படுத்தவும்.

Python அமைப்பும் mise மூலம் `uv` ஐ நிறுவுகிறது. Python மேம்பாட்டுச் சூழலை அகற்றுவது `uv` ஐ ஒரு சுயாதீன கருவியாகக் கிடைக்க வைக்கிறது.

### உங்கள் சொந்த நிறுவலைப் பயன்படுத்துதல்

mise இன் கட்டளைகள் `PATH` இல் `~/.local/bin` க்கு முன் வருகின்றன, எனவே நீங்களே நிறுவிய ஒரு கருவி, உதாரணமாக Claude Code அல்லது Cursor இன் சொந்த நிறுவி மூலம், அது இன்னும் mise இன் நகலையே இயக்குகிறது. டெஸ்க்டாப்பில் இருந்து தொடங்கப்படும் பயன்பாடுகளும் கணினித் தொகுப்புகளுக்கு முன் mise இன் கட்டளைகளைக் கண்டுபிடிக்கின்றன, எனவே `gh` ஐ இயக்கும் ஒரு பயன்பாடு, நீங்கள் pacman உடன் `github-cli` ஐ நிறுவியிருந்தாலும் mise இன் நகலைப் பெறுகிறது, மேலும் mise முதல் முறையில் அந்த நகலையே நிறுவுகிறது. அதற்கு பதிலாக உங்களுடையதைப் பயன்படுத்த, `~/.config/mise/config.toml` இல் mise இன் நகலை முடக்கவும். உதாரணமாக, நீங்களே Cursor CLI ஐ நிறுவியிருந்தால்:

```toml
[settings]
disable_tools = ["cursor-agent"]
```

உங்களிடம் ஏற்கனவே ஒரு `[settings]` அட்டவணை இருந்தால், உள்ளீட்டை அங்கே சேர்க்கவும்; ஏற்கனவே உள்ள `disable_tools` பட்டியலை மாற்றுவதற்கு பதிலாக அதை விரிவாக்கவும். உங்கள் நிறுவல் `PATH` இல் இருப்பதை உறுதிப்படுத்திக் கொள்ளுங்கள். mise கருவி பெயரைப் பயன்படுத்தவும், அது அதன் கட்டளையில் இருந்து வேறுபடலாம்: உதாரணமாக, `oh-my-pi` `omp` ஐ வழங்குகிறது. இயல்புநிலை ஏஜெண்டு தொடக்கக் கருவியும் `~/.local/bin` இல் பயனர் நிறுவிய Cursor அல்லது Muse ஐ விரும்புகிறது.

### இயல்புநிலைகளை அகற்றுதல் மற்றும் மீட்டமைத்தல்

_அகற்று > முன்நிறுவப்பட்டவை_ என்பது Omarchy இன் முன்னரே நிறுவப்பட்ட வலை பயன்பாடுகள், TUIகள் மற்றும் பயன்பாடுகளை அகற்றுகிறது, மேலும் உங்கள் பயனருக்காக Omarchy இன் கருவி அறிவிப்புகளை mise தவிர்க்க வைக்கிறது, அவற்றை `~/.config/mise/miserc.toml` இல் `ignored_config_paths` இல் சேர்ப்பதன் மூலம். _நிறுவு > முன்நிறுவப்பட்டவை_ அவற்றை மீண்டும் கொண்டு வருகிறது மற்றும் அந்த வரியை மீண்டும் அகற்றுகிறது. உங்கள் சொந்த உள்ளமைவில் அல்லது ஒரு திட்டத்தின் `mise.toml` இல் நீங்களே அறிவிக்கும் கருவிகள், எந்த வழியிலும் தொடர்ந்து வேலை செய்கின்றன. முன்நிறுவப்பட்டவற்றை அகற்றிய பிறகு நீங்கள் இயல்புநிலை ஏஜெண்டைத் தேர்ந்தெடுத்தால் அல்லது Python ஐ அமைத்தால், அந்தக் கருவி உங்கள் சொந்த உள்ளமைவில் சேர்க்கப்படுகிறது. mise அமைப்பு உங்கள் பயனருக்கு மட்டுமே பொருந்தும், மற்ற பயனர்கள் தங்கள் சொந்த தேர்வைத் தக்கவைத்துக் கொள்கிறார்கள்; பயன்பாடுகள் தொகுப்புகளாக இருப்பதால், அவற்றை அகற்றுவது அல்லது மீட்டமைப்பது கணினியில் உள்ள அனைவருக்கும் அவற்றை மாற்றுகிறது.

## Docker

[Docker](https://www.docker.com/) க்கு அறிமுகம் எதுவும் தேவையில்லை. இது தனிமைப்படுத்தப்பட்ட கொள்கலன்களை இயக்க உங்களை அனுமதிக்கிறது, மேலும் Omarchy அதை நன்றாக இயக்க தேவையான அனைத்தையும் நிறுவுகிறது, Docker தானே மற்றும் [Docker Compose](https://docs.docker.com/compose/) உட்பட.

இயல்புநிலையாக உங்கள் பயனர் `docker` குழுவில் *இல்லை*. அந்தக் குழு நடைமுறையில் கடவுச்சொல் இல்லாத root ஆகும் — அதில் உள்ள எதுவும் `docker run -v /:/host` என்று இயக்கி கணினியைக் கைப்பற்ற முடியும் — எனவே உங்களாக இயங்கும் ஒரு மோசமான ஸ்கிரிப்ட் அல்லது சார்பு, இல்லையெனில் root இலிருந்து ஒரு கட்டளை தூரத்தில் இருக்கும். எனவே கட்டளை வரியில் நீங்கள் Docker ஐ `sudo` உடன் இயக்குகிறீர்கள் (`sudo docker ps`, `sudo docker compose up`), மேலும் டீமானுடன் பேசும் வரைகலை கருவிகள் — Windows VM — அவற்றுக்குத் தேவைப்படும்போது அங்கீகாரத்தைக் கேட்கின்றன. குழு இல்லாத அமைப்பின் வசதியை நீங்கள் மீண்டும் விரும்பினால் மற்றும் பரிமாற்றத்தைப் புரிந்து கொண்டால், அதை **அமைப்பு > பாதுகாப்பு > Sudoless Docker** இலிருந்து இயக்கவும் (அல்லது `omarchy-setup-security-sudoless-docker` ஐ இயக்கவும்), இது ஒரு எச்சரிக்கையின் பிறகு உங்களை `docker` குழுவில் சேர்க்கிறது; பிறகு எளிய `docker` மற்றும் `d` மாற்றுப்பெயர் `sudo` இல்லாமல் மீண்டும் வேலை செய்கின்றன.

Omarchy மெனுவில் _நிறுவு > மேம்பாடு > Docker DB_ ஐப் பயன்படுத்தி உள்ளூர் மேம்பாட்டிற்கான பொதுவான தரவுத்தளங்களை Docker இல் அமைக்கலாம்.

## GitHub CLI

[GitHub CLI](https://cli.github.com/) டெர்மினலில் இருந்து ரிப்போசிட்டரிகள், சிக்கல்கள் மற்றும் இழுக்கும் கோரிக்கைகளுடன் வேலை செய்வதற்கு `gh` ஆகக் கிடைக்கிறது. முதல் பயன்பாட்டில் அதை நிறுவவும் அங்கீகரிக்கவும் `gh auth login` ஐ இயக்கவும், பிறகு ஒரு ரிப்போசிட்டரியை குளோன் செய்ய `gh repo clone org/repo` ஐ இயக்கவும். அதன் கட்டளைகளை ஆராய `gh --help` ஐ இயக்கவும்.

இழுக்கும் கோரிக்கைகளுக்கான டெர்மினல் இடைமுகத்திற்கு, `ghui` ஐ இயக்கவும்; mise அதையும் முதல் பயன்பாட்டில் நிறுவுகிறது. [Lazygit](https://github.com/jesseduffield/lazygit) Git உடன் வேலை செய்வதற்காக முன்னரே நிறுவப்பட்டுள்ளது.
