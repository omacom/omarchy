# மேம்பாட்டுக் கருவிகள்

## மாற்று எடிட்டர்கள்

புதிய நிறுவல்களில் Omarchy இயல்புநிலை எடிட்டராக Plain உடன் வருகிறது, மேலும் [Neovim](https://neovim.io/) முன்கூட்டியே நிறுவப்பட்டுள்ளது, ஆனால் இன்னும் கொஞ்சம் பிரதானமானதும் பழக்கமானதுமான ஒன்றை நீங்கள் விரும்பினால், Omarchy Menu (`Super + Space`) ஐ இயக்கி, _நிறுவு > எடிட்டர்_ என்பதன் கீழ் உள்ள விருப்பங்களைப் பார்க்கலாம். அங்கே VSCode, Cursor, Zed, Sublime Text, Helix, Vim மற்றும் Emacs ஆகியவை பட்டியலிடப்பட்டுள்ளன. நீங்கள் தேடுவது கிடைக்கவில்லை என்றால், _நிறுவு > தொகுப்பு_ என்பதைப் பார்த்து, அது ஒரு Arch தொகுப்பில் இல்லையா என்று பாருங்கள் (இல்லையென்றால், AUR ஐச் சரிபார்க்க _நிறுவு > AUR_ ஐ முயற்சிக்கவும்).

அசல் `vi` எடிட்டரும் தொடக்கத்திலிருந்தே கிடைக்கிறது. டெர்மினலில் ஒரு கோப்பைத் திருத்த `vi filename` என்று இயக்கவும்.

`VSCode`, `Cursor`, `VSCodium` மற்றும் `Helix` ஆகியவற்றுக்கு தீம் பொருத்தம் வழங்கப்படுகிறது.

கணினி முழுவதற்குமான இயல்புநிலை எடிட்டரை `Setup > Defaults > Editor` என்பதன் கீழ் அமைக்கலாம்.

## சூழல்

Omarchy Menu (`Super + Space`) இன் _நிறுவு > மேம்பாடு_ பிரிவின் மூலம் ஏராளமான மேம்பாட்டுச் சூழல்களை அமைப்பதை Omarchy ஆதரிக்கிறது. நிச்சயமாக அங்கே _Ruby on Rails_ ஐக் காண்பீர்கள், அதோடு JavaScript க்கான மூன்று முக்கிய ரன்டைம்களும் (Node.js, Bun, Deno), மேலும் Laravel மற்றும் Symfony போன்ற பிரபலமான PHP கட்டமைப்புகளும் உள்ளன. ஓ, மேலும் Go, Rust, Python, Java, Elixir (Phoenix உடன்), .NET, OCaml, Zig, Clojure மற்றும் Scala வும் உள்ளன. இது மிகவும் பரந்த தேர்வு!

இந்தச் சூழல்களில் பெரும்பாலானவை [Mise](https://mise.jdx.dev/) ஆல் நிர்வகிக்கப்படுகின்றன. இது ஒரே கணினியில் ஒரு நிரலாக்க மொழியின் பல பதிப்புகளை நிறுவி இயக்க உங்களை அனுமதிக்கும் ஒரு கருவி. இது Ruby க்கான rbenv அல்லது rvm போன்றது அல்லது Python க்கான virtualenv போன்றது, ஆனால் இது பல வேறுபட்ட சூழல்களுக்கு வேலை செய்கிறது.

எடுத்துக்காட்டாக, Ruby ஐ நிறுவ, நீங்கள் `mise use -g ruby` என்று இயக்குவீர்கள், இது Ruby ஐ நிறுவுவதுடன் அதை உலகளாவிய இயல்புநிலையாகவும் அமைக்கும். அல்லது, உங்கள் திட்டத்தில் .ruby-version கோப்பு இருந்தால், அந்தத் திட்டத்தின் ரூட்டில் `mise i` என்று இயக்கினால் போதும்.

## முன்கூட்டியே நிறுவப்பட்ட CLI கருவிகள்

`uv`, Node.js மற்றும் `playwright-cli` (நிறுவப்பட்ட Chrome ஐப் பயன்படுத்தி, ஏஜெண்டுகள் ஒரு உலாவியை இயக்குவதற்காக) ஆகியவை தொகுப்புகளாக நிறுவப்பட்டு வருகின்றன, மேலும் `omarchy update` அவற்றை கணினியின் மற்ற பகுதிகளுடன் புதுப்பித்த நிலையில் வைத்திருக்கிறது. [Hunk](https://github.com/modem-dev/hunk) மற்றும் GitHub, Basecamp, Cloudflare மற்றும் HEY CLIகள் _நிறுவு > CLI_ என்பதன் கீழ் ஒரே ஒரு தேர்வு தொலைவில் உள்ளன, மேலும் [குறியீட்டு ஏஜெண்டுகள்](17-ai.md) _நிறுவு > AI > CLI_ என்பதன் கீழ் உள்ளன.

_நிறுவு > மேம்பாடு_ என்பதிலிருந்து நீங்கள் அமைக்கும் ரன்டைம்களை மட்டுமே mise நிர்வகிக்கிறது; Omarchy தானாக அதன் மூலம் எதையும் நிறுவுவதில்லை. அவற்றை Omarchy இன் மற்ற பகுதிகளுடன் புதுப்பிக்க `omarchy update` ஐ இயக்கவும்; `mup` மாற்றுப்பெயர் mise ஆல் நிர்வகிக்கப்படும் கருவிகளை மட்டுமே புதுப்பிக்கிறது. உங்கள் சொந்த உள்ளமைவில் மற்றொரு கருவியைச் சேர்க்க, `mise use -g <tool>` ஐப் பயன்படுத்தவும்.

## Docker

[Docker](https://www.docker.com/) க்கு எந்த அறிமுகமும் தேவையில்லை என்றே சொல்லலாம். இது தனிமைப்படுத்தப்பட்ட கண்டெய்னர்களை இயக்க உங்களை அனுமதிக்கிறது, மேலும் அதைச் சிறப்பாக இயக்கத் தேவையான அனைத்தையும் Omarchy நிறுவுகிறது, Docker ஐயும் [Docker Compose](https://docs.docker.com/compose/) ஐயும் உள்ளடக்கி.

இயல்பாக உங்கள் பயனர் `docker` குழுவில் *இல்லை*. அந்தக் குழு உண்மையில் கடவுச்சொல் இல்லாத root ஆகும் — அதில் உள்ள எதுவும் `docker run -v /:/host` என்று இயக்கி கணினியைக் கைப்பற்ற முடியும் — எனவே உங்களாக இயங்கும் ஒரே ஒரு முரட்டு ஸ்கிரிப்ட் அல்லது சார்பு இல்லையென்றால் root இலிருந்து ஒரே ஒரு கட்டளை தொலைவில் இருக்கும். எனவே கட்டளை வரியில் நீங்கள் Docker ஐ `sudo` உடன் இயக்குகிறீர்கள் (`sudo docker ps`, `sudo docker compose up`), மேலும் டீமனுடன் பேசும் வரைகலைக் கருவிகள் — Windows VM — தேவைப்படும்போது அங்கீகாரத்தைக் கேட்கின்றன. குழு இல்லாத அமைப்பின் வசதியை மீண்டும் விரும்பி, அதன் சமரசத்தைப் புரிந்துகொண்டால், அதை **அமைப்பு > பாதுகாப்பு > Sudoless Docker** என்பதிலிருந்து இயக்கவும் (அல்லது `omarchy-setup-security-sudoless-docker` ஐ இயக்கவும்), இது ஒரு எச்சரிக்கைக்குப் பிறகு உங்களை `docker` குழுவில் சேர்க்கிறது; பிறகு சாதாரண `docker` மற்றும் `d` மாற்றுப்பெயர் மீண்டும் `sudo` இல்லாமல் வேலை செய்யும்.

Omarchy மெனுவில் _நிறுவு > மேம்பாடு > Docker DB_ என்பதைப் பயன்படுத்தி உள்ளூர் மேம்பாட்டுக்கான பொதுவான தரவுத்தளங்களை Docker இல் அமைக்கலாம்.

## GitHub CLI

[GitHub CLI](https://cli.github.com/) என்பது `gh`, டெர்மினலில் இருந்து ரெப்போசிட்டரிகள், இஷ்யூக்கள் மற்றும் புல் கோரிக்கைகளுடன் வேலை செய்வதற்காக. அங்கே GitHub இல் உள்நுழைய நீங்கள் தேர்ந்தெடுக்கும்போது _அமைப்பு > Git_ அதை நிறுவுகிறது, அல்லது அதைத் தனியாக _நிறுவு > CLI > GitHub_ என்பதிலிருந்து நிறுவவும். பிறகு `gh repo clone org/repo` ஒரு ரெப்போசிட்டரியை குளோன் செய்கிறது; அதன் கட்டளைகளை ஆராய `gh --help` ஐ இயக்கவும்.

Git உடனேயே வேலை செய்வதற்காக [Lazygit](https://github.com/jesseduffield/lazygit) முன்கூட்டியே நிறுவப்பட்டுள்ளது.
