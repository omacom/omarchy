# டாட்ஃபைல்கள்

Omarchy முதன்மையாக `~/.config` இல் வசிக்கும் dotfiles என்று அழைக்கப்படுவற்றின் மூலம் கட்டமைக்கப்படுகிறது. அவை உங்கள் மாற்றங்களுக்கான உங்கள் கோப்புகளாகக் கருதப்படுகின்றன. `/usr/share/omarchy` இல் வசிக்கும் கோப்புகள் Omarchy-க்கே சொந்தமானவை, அவற்றில் நீங்கள் கை வைக்கக் கூடாது. `/usr/share/omarchy` இல் எதையாவது மாற்ற வேண்டுமென்றால், அதற்குப் பதிலாக `~/.config` இல் அந்த மதிப்பை மேலெழுத வேண்டும்.

முக்கியக் கட்டமைப்புகளை Omarchy மெனுவிலிருந்தே (`Super + Space`) நேரடியாகத் திருத்தலாம், எடுத்துக்காட்டாக _Setup > Keyboard > Keybindings_, _Setup > Input_, மற்றும் _Setup > Config > [file]_. இப்படிச் செய்யும்போது, கட்டமைப்புத் திருத்தங்களுக்குப் பிறகு மறுதொடக்கம் செய்யப்பட வேண்டிய எந்தச் செயல்முறையும், நீங்கள் எடிட்டரிலிருந்து வெளியேறிய பிறகு தானாகவே மறுதொடக்கம் செய்யப்படும் (இயல்பாக Neovim — `:wq`, நினைவில் கொள்ளுங்கள்! — ஆனால் _Setup > Defaults > Editor_ வழியாக அதை மாற்றலாம்).

`~/.config` இல் உள்ள முக்கியக் கோப்புகள் மற்றும் அவை எதைக் கட்டுப்படுத்துகின்றன என்பதன் பட்டியல் இங்கே:

| File                  | Purpose              |
| ----------------------- | --------------------- |
| `~/.config/hypr/hyprland.lua` | முக்கிய Hyprland கட்டமைப்பு. Omarchy இயல்புநிலைகளையும் கீழே உள்ள உங்கள் மேலெழுதும் கோப்புகளையும் ஏற்றுகிறது. [Hyprland கட்டமைப்புகள் பற்றி மேலும் அறிக](https://wiki.hypr.land/Configuring/).  |
| `~/.config/hypr/bindings.lua` | உங்கள் சொந்த விசைப்பிணைப்புகள் மற்றும் இயல்புநிலைகளின் மேலெழுதல்கள். |
| `~/.config/hypr/monitors.lua` | சுழற்சி, கூடுதல் பயன்முறைகள், அல்லது ஒரு மானிட்டரை அணைத்து வைப்பது போன்ற, மானிட்டர் பேனல் உள்ளடக்காத மானிட்டர் அமைப்புகள். |
| `~/.config/hypr/input.lua` | உங்கள் விசைப்பலகைத் தளவமைப்பு, மவுஸ் மற்றும் டிராக்பேட் அமைப்புகளைக் கட்டுப்படுத்துகிறது. |
| `~/.config/hypr/looknfeel.lua` | இடைவெளிகள், விளிம்புகள், அனிமேஷன்கள் மற்றும் தோற்றத்தின் மற்ற அனைத்தையும் கட்டுப்படுத்துகிறது. |
| `~/.config/hypr/autostart.lua` | அமர்வுடன் தொடங்கப்படும் கூடுதல் செயல்முறைகளைக் கட்டுப்படுத்துகிறது. |
| `~/.config/omarchy/shell.json` | Omarchy shell-ஐக் கட்டுப்படுத்துகிறது: பார் நிலை, தளவமைப்பு மற்றும் விட்ஜெட்கள், மேலும் ஸ்கிரீன்சேவர், பூட்டு மற்றும் செயலற்ற நேரங்கள். |
| `~/.config/foot/foot.ini` | உங்கள் டெர்மினலைக் கட்டுப்படுத்துகிறது (foot தான் இயல்புநிலை). |
| `~/.XCompose` | உங்கள் விரைவு-அணுகல் ஈமோஜி மற்றும் பெயர்/மின்னஞ்சல் தானியங்கு நிரப்பலை வரையறுக்கிறது. மாற்றங்களைச் செய்த பிறகு `omarchy-restart-xcompose` ஐ இயக்குவதை உறுதிப்படுத்திக் கொள்ளுங்கள். |

உங்கள் சொந்த அமைப்பை மாற்றியமைக்க நிறைய மாற்றங்களைச் செய்ய நேர்ந்தால், இந்த dotfiles அனைத்தையும் காப்புப் பிரதி எடுப்பது நல்ல யோசனை. [Stow அதைச் செய்ய ஒரு சிறந்த வழி](https://www.youtube.com/watch?v=NoFiYOqnC4o).

### அமர்வுடன் உங்கள் சொந்த பயன்பாடுகளைத் தொடங்குதல்

நீங்கள் ஒவ்வொரு முறை உள்நுழையும்போதும் ஏதாவது இயங்க வேண்டுமென்றால் — ஒரு ஒத்திசைவு டீமான், ஒரு அரட்டைச் செயலி, உங்கள் சொந்த ஸ்கிரிப்ட் — அதை `~/.config/hypr/autostart.lua` இல் போடுங்கள்:

```lua
o.launch_on_start("my-service")
```

அது கட்டளையை அமர்வின் ஒரு பகுதியாகத் தொடங்குகிறது, எனவே நீங்கள் மீண்டும் வெளியேறும்போது அது முறையாகச் சுத்தம் செய்யப்படும்.

### கணினி நிகழ்வுகளில் ஸ்கிரிப்ட்களை இயக்குதல்

Omarchy ஒரு சில தருணங்களில் hooks-ஐத் தூண்டுகிறது, உங்கள் சொந்த ஸ்கிரிப்ட்களை அவற்றில் தொங்கவிடலாம். அவை `~/.config/omarchy/hooks/<event>.d/` இல் வசிக்கின்றன, ஒவ்வொரு நிகழ்வுக்கும் ஒரு கோப்பகம், அந்த நிகழ்வு நடக்கும்போது அங்குள்ள இயக்கக்கூடிய ஒவ்வொரு கோப்பும் இயங்கும்:

| Event | When it runs |
| ----- | ------------ |
| `post-boot` | டெஸ்க்டாப் தொடங்கிய உடனேயே |
| `post-update` | `omarchy update` இன் இறுதிக்கு அருகில், தொகுப்புகள், இடம்பெயர்வுகள் மற்றும் சேவை மறுதொடக்கங்களுக்குப் பிறகு, mise கருவிகள் புதுப்பிக்கப்படுவதற்கு முன்பு |
| `pre-refresh-pacman` | `omarchy refresh pacman` தொகுப்புக் கட்டமைப்பை மீண்டும் ஒத்திசைத்த பிறகு, அது தொகுப்புகளைப் புதுப்பிப்பதற்கு முன்பு; ஒரு சேனல் மாற்றம் அதே புதுப்பிப்புப் படியின்போது இதை இயக்குகிறது |
| `theme-set` | ஒரு தீம் மாற்றத்திற்குப் பிறகு (தீம் பெயர் `$1` இல்) |
| `font-set` | ஒரு எழுத்துரு மாற்றத்திற்குப் பிறகு (எழுத்துருப் பெயர் `$1` இல்) |
| `battery-low` | பேட்டரி குறையும்போது (சதவீதம் `$1` இல்) |

`pre-refresh-pacman` hook தான் தனிப்பயன் களஞ்சியங்கள் அல்லது `IgnorePkg` வரிகள் இருக்க வேண்டிய இடம், ஏனெனில் அது தொகுப்புப் பரிவர்த்தனைக்கு முன்பு இயங்குகிறது. இரண்டு புதுப்பிப்பு தொடர்பான hooks-களும் Omarchy அதன் தற்காலிகமாகச் சேமிக்கப்பட்ட sudo அங்கீகாரத்தை அழித்த பிறகு உங்கள் பயனராக இயங்குகின்றன, எனவே `sudo` ஐப் பயன்படுத்தும் ஒரு hook-க்கு அதன் சொந்த அங்கீகாரம் தேவை, அது உங்கள் கடவுச்சொல்லைக் கேட்கலாம்.

அந்தக் கோப்பகங்கள் ஒவ்வொன்றும் ஏற்கனவே ஒரு hook-இன் வடிவத்தைக் காட்டும் ஒரு `.sample` கோப்பை வைத்திருக்கிறது — அதை வேலைக்கு அமர்த்தப் பெயரிலிருந்து `.sample` ஐ நீக்குங்கள். நீங்கள் வேறு எங்காவது எழுதிய ஒரு ஸ்கிரிப்டை நிறுவ, `omarchy hook install post-boot ~/my-hook` ஐப் பயன்படுத்துங்கள், அது அதை உள்ளே நகலெடுத்து இயக்கக்கூடியதாக மாற்றுகிறது.

### உங்கள் சொந்த மெனு உள்ளீடுகளைச் சேர்த்தல்

Omarchy மெனுவை (`Super + Space`) `~/.config/omarchy/extensions/omarchy-menu.jsonc` ஐத் திருத்துவதன் மூலம் உங்கள் சொந்த வரிசைகளுடன் நீட்டிக்கலாம். உள்ளீடுகள் ஒரு புள்ளியிடப்பட்ட id-யால் விசையிடப்படுகின்றன, அந்த id தான் அவற்றை மரத்தில் வைக்கிறது, எனவே `personal` மூல மெனுவில் தோன்றும், `personal.notes` அதன் உள்ளே தோன்றும்:

```jsonc
"personal": {"icon":"","label":"Personal"},
"personal.notes": {"icon":"󰎞","label":"Notes","action":"omarchy-launch-editor ~/notes"},
```

ஏற்கனவே உள்ள id-யை மீண்டும் பயன்படுத்தினால், புதிய ஒன்றைச் சேர்ப்பதற்குப் பதிலாக அந்த வரிசையை மேலெழுதுகிறீர்கள். கிடைக்கக்கூடிய அனைத்துப் புலங்களும் கருத்துகளாக ஆவணப்படுத்தப்பட்ட நிலையில் கோப்பு வருகிறது.

### உங்கள் சொந்த shell exports, functions, மற்றும் aliases ஐச் சேர்த்தல்

Omarchy ஏராளமான பணிச்சூழலியல் aliases மற்றும் பயனுள்ள functions உடன் வருகிறது, ஆனால் உங்கள் சொந்தத்தைச் சேர்க்க விரும்புவது மிகவும் பொதுவானது. aliases, functions, மற்றும் exports அனைத்தையும் `~/.bashrc` இல் சேர்க்க வேண்டும். இந்தக் கோப்பு புதுப்பிப்புகளில் மேலெழுதப்படாது. Omarchy இயல்புநிலைகளில் எதையாவது மாற்ற விரும்பினால், அவற்றையும் இங்கே பாதுகாப்பாகச் சேர்க்கலாம்.

### டெஸ்க்டாப்பிற்கான சூழல் மாறிகளை அமைத்தல்

டெஸ்க்டாப் அமர்வு exports `~/.config/uwsm/env.d/` இல் இருக்க வேண்டும். இந்தக் கோப்புகள் உங்கள் டெஸ்க்டாப் தொடங்குவதற்கு முன்பு இயங்குகின்றன, எனவே ஒரு shell பிழை உங்களை உள்நுழைவுத் திரைக்குத் திருப்பி அனுப்பலாம். அவற்றைத் திருத்தும்போது வேலை செய்யும் ஒரு டெர்மினலைத் திறந்து வைத்திருங்கள். ஒரு மேலெழுதலை முடக்க, அதை `env.d` இலிருந்து வெளியே நகர்த்துங்கள். ஒரு மாற்றம் உள்நுழைவைத் தடுத்தால் [உள்நுழைவு மீட்பு](45-troubleshooting.md#my-password-is-accepted-but-i-return-to-the-login-screen) ஐப் பாருங்கள்.

### உள் Omarchy கோப்புகளை மாற்றுதல்

பாருங்கள், இது உங்கள் கணினி. அதில் நீங்கள் விரும்பிய எதையும் செய்யலாம், ஆனால் `/usr/share/omarchy` இல் உள்ள கோப்புகளில் நேரடியாக மாற்றங்களைச் செய்வதற்கு எதிராக நான் அறிவுறுத்துவேன். அவை Omarchy pacman தொகுப்புக்குச் சொந்தமானவை, எனவே உங்கள் மாற்றங்கள் அடுத்த புதுப்பிப்பில் வெறுமனே மேலெழுதப்படும். அதற்குப் பதிலாக உங்களுக்குப் பிடிக்காத எந்த இயல்புநிலை மதிப்புகளையும் `~/.config/*` கோப்புறையில் மேலெழுதுவதே உங்களுக்கு நல்லது.

அப்படி கிட்டத்தட்ட எல்லாவற்றையும் மாற்றலாம், இயல்புநிலை விசைப்பிணைப்புகளைப் போல. [Obsidian](https://obsidian.md/) க்குப் பதிலாக [Joplin](https://joplinapp.org/) ஐ வைக்க, `~/.config/hypr/bindings.lua` ஐத் திருத்துங்கள், எடுத்துக்காட்டாக (`omarchy-pkg-add joplin-bin` மூலம் நிறுவவும்):

```lua
o.rebind("SUPER + SHIFT + O", "Joplin", "joplin-desktop")
```

`o.rebind` அதன் மாற்றீட்டைச் சேர்ப்பதற்கு முன்பு ஏற்கனவே உள்ள பிணைப்பை நீக்குகிறது. அது ஏவுதல் உதவியாளர்கள் மற்றும் பிணைப்பு விருப்பங்கள் உட்பட, `o.bind` இன் அதே வாதங்களை எடுக்கிறது. ஒரு பிணைப்பைச் சேர்க்க `o.bind` ஐப் பயன்படுத்துங்கள், அல்லது அதை மாற்றாமல் ஒன்றை நீக்க `hl.unbind` ஐப் பயன்படுத்துங்கள்.

உள் Omarchy கோப்புகளில் ஹேக் செய்வதில் நீங்கள் வலியுறுத்தினால், _Update > Channel > Dev_ வழியாக dev சேனலுக்கு மாறுங்கள். அது Omarchy-ஐ `~/omarchy` இல் உள்ள மூலக் குறியீட்டின் ஒரு git checkout உடன் இணைக்கிறது, அதை உங்கள் மனம் நிறைய மாற்ற நீங்கள் சுதந்திரமாக இருக்கிறீர்கள். நீங்கள் என்ன செய்ய வேண்டும் என்று சொல்ல இங்கு யாரும் இல்லை!

### எந்த மாற்றங்களையும் மீட்டமைத்தல்

கட்டமைப்புகளைக் குழப்பிவிட்டால், Omarchy மெனுவில் _Update > Config_ வழியாக அவற்றை எப்போதும் இயல்புநிலைகளுக்குத் திருப்பலாம். அல்லது எல்லாவற்றையும் மீட்டமைக்க `omarchy reinstall configs` ஐ இயக்குவதன் மூலம்.
