# பாதுகாப்பு

Omarchy பாதுகாப்பை மிகவும் தீவிரமாக எடுத்துக்கொள்கிறது. இது _Real World_ இல் _Real Work_ செய்ய நீங்கள் பயன்படுத்தக்கூடிய ஓர் இயக்க முறைமையாக இருக்க வேண்டும் என்பதே நோக்கம். ஒரு laptop தொலைந்துவிட்டால் அது பாதுகாப்பு அவசரநிலையாக மாறிவிடக் கூடாது. எனவே நாங்கள் செய்வது இதுதான்:

1. *முழு வட்டு குறியாக்கம் கட்டாயம்*: உங்கள் தரவின் நேரடிப் பாதுகாப்பை உறுதி செய்வதற்கான மிக முக்கியமான படி இதுதான். உங்கள் கணினி தொலைந்துவிட்டாலோ திருடப்பட்டாலோ, தரவு நிலையான LUKS (Linux Unified Key Setup) பயன்படுத்தி முழுமையாகக் குறியாக்கம் செய்யப்பட்டிருக்கும்.
2. *Firewall இயல்பாகவே இயக்கப்பட்டிருக்கும்*: [LocalSend](https://localsend.org/) க்கான port 53317 தவிர, உள்வரும் அனைத்து traffic உம் இயல்பாகவே தடுக்கப்படும். _Setup > Security > SSHD_ வழியாக நீங்கள் அதை இயக்கும் வரை ssh கூட அணைக்கப்பட்டிருக்கும்; அந்த அமைப்பின் ஒரு பகுதியாக port 22 திறக்கப்படும் (brute force தாக்குதல்களுக்கு எதிராக வீதம் கட்டுப்படுத்தப்பட்டது). உங்கள் containers தற்செயலாக உலகிற்கு வெளிப்பட்டுவிடாமல் தடுக்க, [ufw-docker](https://github.com/chaifeng/ufw-docker) அமைப்பைப் பயன்படுத்தி Docker அணுகலையும் கூட நாங்கள் கட்டுப்படுத்துகிறோம்.
3. *Arch இல் எப்போதும் சமீபத்திய புதுப்பிப்புகள் இருக்கும்*: Omarchy கட்டமைக்கப்பட்டுள்ள அடிப்படை distro வான Arch, ஒரு rolling distribution ஆகும். அதாவது, எந்தத் தொகுப்பிலும் ஒரு பாதுகாப்புக் குறைபாடு கண்டறியப்பட்டுச் சரிசெய்யப்பட்டால், அது `omarchy-update` பயன்படுத்தி நிறுவுவதற்கு விரைவாகக் கிடைக்கும். அந்த வழியில் நீங்கள் எப்போதும் எல்லாவற்றின் சமீபத்திய, மிகவும் பாதுகாப்பான பதிப்புகளையே இயக்கிக் கொண்டிருப்பீர்கள்.
4. *Omarchy அதன் சொந்தத் தொகுப்புகளையும் mirror ஐயும் பராமரிக்கிறது*: Omarchy இயல்பாக Arch இன் சொந்த core/extra/multilib repositories மற்றும் அதன் சொந்த Omarchy Package Repository ஆகியவற்றிலிருந்து வரும் தொகுப்புகளை மட்டுமே சார்ந்திருக்கிறது. நீங்கள் AUR இலிருந்து நேரடியாக மென்பொருளை நிறுவலாம், ஆனால் அடிப்படை நிறுவல் அவ்வாறு செய்வதில்லை — third-party browsers போன்ற சில விருப்ப நிறுவல்கள் மட்டுமே AUR இலிருந்து பெறுகின்றன.
5. *Cloudflare எங்களை DDoS இலிருந்து பாதுகாக்கிறது*: Omarchy விநியோக உள்கட்டமைப்பு — ISOகள், Omarchy தொகுப்புகள், Arch mirror — Cloudflare இன் வலிமையான DDoS shield இன் பின்னால் பாதுகாக்கப்பட்டு அவர்களின் CDN இல் வழங்கப்படுகிறது. இது சிறந்த கிடைக்கும்தன்மையை வழங்குகிறது.

## உங்கள் கடவுச்சொற்களை மாற்றுதல்

குறியாக்கம் செய்யப்பட்ட நிறுவலில் உங்களிடம் இரண்டு கடவுச்சொற்கள் உள்ளன: ஒன்று boot நேரத்தில் drive ஐத் திறக்கும், மற்றொன்று நீங்கள் உள்நுழையவும் `sudo` பயன்படுத்தவும் உதவும். Setup அவை இரண்டையும் ஒன்றாகவே அமைக்கிறது. Omarchy menu இல் _Update > Password_ இன் கீழ் இரண்டையும் மாற்றலாம் — முதலாவதற்கு _Drive Encryption_, இரண்டாவதற்கு _User_. Drive கடவுச்சொல்லை மாற்றும்போது முதலில் தற்போதைய கடவுச்சொல் கேட்கப்படும், எனவே அதைக் கையில் வைத்திருங்கள். ஒரு மாற்றம் இடையில் தடைபட்டால், _Drive Encryption_ ஐ மீண்டும் இயக்குங்கள்: அது இப்போது drive ஐத் திறக்கும் கடவுச்சொல்லைக் கேட்டு மாற்றத்தை முடித்துவிடும்.

## நீங்கள் ஏற்கெனவே பயன்படுத்திய ஒரு கணினியை வேறொருவரிடம் கொடுத்தல்

உங்கள் கணினியை வேறொருவரிடம் கொடுக்கிறீர்கள் என்றால், அதை மீண்டும் நிறுவ வேண்டியதில்லை. Omarchy menu இல் _Setup > Reset Computer_ ஐ இயக்கி, உறுதிப்படுத்த `reset` எனத் தட்டச்சு செய்து, reboot செய்யுங்கள். அது ஒவ்வொரு user account ஐயும் `/home` இல் உள்ள அனைத்தையும் அழிக்கும், நிறுவலுக்குப் பிறகு நீங்கள் சேர்த்த அனைத்துத் தொகுப்புகளையும் system மாற்றங்களையும் தூக்கி எறியும், கணினியின் அடையாளத்தை — network connections, host keys, எல்லாவற்றையும் — நீக்கும். மீண்டும் எழுவது முதல் boot இல் வந்த அதே setup wizard தான்; அதன் புதிய உரிமையாளர் தங்கள் சொந்தப் பெயர், கடவுச்சொல் மற்றும் குறியாக்கக் கடவுச்சொல்லை உள்ளிட அது தயாராக இருக்கும்.

Installer எடுக்கும் baseline snapshot ஐ மீட்டமைப்பதன் மூலம் இது செயல்படுவதால், Omarchy ISO இலிருந்து நிறுவப்பட்ட கணினிகளில் மட்டுமே இது கிடைக்கும். மேலும் குறியாக்கம் இல்லாத drive இல், reset என்பது பாதுகாப்பான அழிப்பு அல்ல, வெறும் நீக்கம் மட்டுமே; எனவே தரவு முக்கியமானதாக இருந்தால், அதற்குப் பதிலாகப் புதிய நிறுவலைச் செய்யுங்கள்.

## கடவுச்சொல் இல்லாத sudo

சில நேரங்களில் `sudo` கேட்பதை நிறுத்த வேண்டும் என்று நீங்கள் விரும்புவீர்கள்; பெரும்பாலும் ஒரு AI agent உங்களுக்காக நீண்ட நேரம் system வேலை செய்து கொண்டிருக்கும்போது இது நிகழும். _Setup > Security > Passwordless Sudo_ எவ்வளவு நேரம் அணுகலை அனுமதிக்க வேண்டும் என்று கேட்கும்: **15 நிமிடங்கள்**, **1 மணி நேரம்**, **1 நாள்**, அல்லது **நிரந்தரமாக**. அணுகல் செயலில் இருக்கும்போது மற்ற menu bar குறிகாட்டிகளுக்கு அருகில் ஒரு சிவப்பு எச்சரிக்கைச் சின்னம் தோன்றும். அதை click செய்யுங்கள் அல்லது அணுகலை அணைக்க அந்த command ஐ மீண்டும் இயக்குங்கள். `omarchy-sudo-passwordless 30` மூலம் உங்கள் சொந்த நிமிடங்களின் எண்ணிக்கையையும் (1 முதல் 1440 வரை) வழங்கலாம், அல்லது `omarchy-sudo-passwordless permanent` ஐப் பயன்படுத்தலாம்.

நேரம் குறிக்கப்பட்ட அணுகல் தானாகவே காலாவதியாகும்; காலக்கெடுவைத் தாண்டிய suspend இலிருந்து மீண்டும் தொடங்கிய உடனேயும் இது பொருந்தும். கணினியை மறுதொடக்கம் செய்வது அதை முன்கூட்டியே முடித்துவிடும். நிரந்தர அணுகல் rebootகளுக்குப் பிறகும் நீடிக்கும், நீங்கள் அதை முடக்கும் வரை இயக்கப்பட்டே இருக்கும்.

Omarchy இன் settings தொகுப்பைப் புதுப்பிப்பதோ அகற்றுவதோ, அதன் காலாவதி ஆதரவு மாறுவதற்கு முன்பே எந்தவொரு தற்காலிக அனுமதியையும் முடித்துவிடும். Command ஓர் authorization அல்லது cleanup பிழையைத் தெரிவித்தால், மற்றொரு அனுமதியை இயக்க முயல்வதற்கு முன் அதைச் சரிசெய்யுங்கள்; ஒரு பிழை என்பது கடவுச்சொல் இல்லாத அணுகல் செயலற்றது என்று அர்த்தமல்ல.

இதைப் பற்றித் தெளிவாக இருங்கள்: இது இயக்கத்தில் இருக்கும்போது, உங்கள் user ஆக இயங்கும் எதுவும் கேட்கப்படாமலேயே root ஆக எதையும் செய்ய முடியும். அதுதான் இதன் முழு நோக்கமும், அதுவே இதன் முழு அபாயமும் கூட.
