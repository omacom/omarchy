# பாதுகாப்பு

Omarchy பாதுகாப்பை மிகவும் தீவிரமாக எடுத்துக்கொள்கிறது. இது _உண்மையான உலகில்_ _உண்மையான வேலையைச்_ செய்ய நீங்கள் பயன்படுத்தக்கூடிய ஒரு இயக்க முறைமையாக இருக்க வேண்டும் என்பதே இதன் நோக்கம். ஒரு laptop தொலைந்து போவது பாதுகாப்பு அவசரநிலைக்கு வழிவகுக்க முடியாத இடத்தில். எனவே நாங்கள் செய்வது இதுதான்:

1. *முழு-வட்டு குறியாக்கம் இயல்பாகவே இயக்கத்தில் இருக்கும்*: உங்கள் தரவின் நேரடிப் பாதுகாப்பை உறுதி செய்வதில் இதுவே மிக முக்கியமான படியாகும். உங்கள் கணினி தொலைந்து போனாலோ திருடப்பட்டாலோ, நிலையான LUKS (Linux Unified Key Setup) ஐப் பயன்படுத்தி தரவு முழுமையாகக் குறியாக்கம் செய்யப்பட்டிருக்கும். தூக்கி எறியக்கூடிய இயந்திரங்களுக்கு இதிலிருந்து விலகிக்கொள்ள நிறுவி உங்களை அனுமதிக்கிறது (பார்க்கவும் [தொடங்குதல்](02-getting-started.md)); குறியாக்கம் இல்லாமல் நிறுவினால் இந்தப் பாதுகாப்பு எதுவும் கிடைக்காது, வட்டைக் கையில் வைத்திருக்கும் எவரும் அதைப் படிக்க முடியும்.
2. *Firewall இயல்பாகவே இயக்கப்பட்டிருக்கும்*: சில விதிவிலக்குகளைத் தவிர, உள்வரும் அனைத்துப் போக்குவரத்தும் இயல்பாகவே தடுக்கப்படும்: [LocalSend](https://localsend.org/) க்கான port 53317; Docker தனது containers க்குக் கொடுக்கும் தனிப்பட்ட முகவரி வரம்புகளிலிருந்து ஏற்றுக்கொள்ளப்படும், Docker bridge முகவரியில் (172.17.0.1) உள்ள கணினியின் சொந்த resolver க்கான DNS வினவல்கள்; மற்றும் multicast DNS (port 5353), இது உங்கள் பிணையத்தில் உள்ள printers மற்றும் பிற சாதனங்கள் ஒன்றையொன்று கண்டறிய அனுமதிக்கிறது, மேலும் உங்கள் கணினியின் பெயரையும் அங்கே அறிவிக்கிறது. இவற்றுக்கு மேலாக, ping, உங்கள் router இடமிருந்து ஒரு முகவரியைப் பெறுதல் (DHCP), மற்றும் UPnP கண்டறிதல் ஆகியவற்றுக்கான UFW இன் நிலையான அனுமதிகளை firewall தக்க வைத்துக்கொள்கிறது. _அமைப்பு > பாதுகாப்பு > SSHD_ வழியாக நீங்கள் அதை இயக்கும் வரை ssh கூட அணைக்கப்பட்டிருக்கும்; அது உங்கள் SSH சாவியை அங்கீகரிக்கிறது, கடவுச்சொல் உள்நுழைவுகளை அணைக்கிறது, அதன் பிறகே port 22 ஐத் திறக்கிறது (முரட்டுத்தனமான தாக்குதலுக்கு எதிராக விகிதம் வரம்பிடப்பட்டது). உங்கள் containers தற்செயலாக உலகுக்கு வெளிப்படுவதைத் தடுக்க [ufw-docker](https://github.com/chaifeng/ufw-docker) அமைப்பைப் பயன்படுத்தி Docker அணுகலை நாங்கள் கூடப் பூட்டி வைக்கிறோம்.
3. *Arch எப்போதும் சமீபத்திய புதுப்பிப்புகளைக் கொண்டிருக்கும்*: Omarchy கட்டமைக்கப்பட்டுள்ள அடிப்படை distro வான Arch, ஒரு rolling distribution ஆகும். அதாவது, எந்தவொரு தொகுப்பிலும் கண்டறியப்பட்டு சரிசெய்யப்படும் எந்தவொரு பாதுகாப்பு பாதிப்பும் `omarchy-update` ஐப் பயன்படுத்தி நிறுவுவதற்கு விரைவாகக் கிடைக்கும். அந்த வகையில் நீங்கள் எப்போதும் எல்லாவற்றின் சமீபத்திய, மிகவும் பாதுகாப்பான பதிப்புகளையே இயக்கிக்கொண்டிருப்பீர்கள்.
4. *Omarchy தனது சொந்தத் தொகுப்புகளையும் mirror ஐயும் பராமரிக்கிறது*: Omarchy இயல்பாகவே Arch இன் சொந்த core/extra/multilib repositories இலிருந்து (ARM இயந்திரங்களில் Arch Linux ARM இலிருந்து, மேலும் Apple Silicon இல் Asahi ALARM) மற்றும் அதன் சொந்த Omarchy Package Repository இலிருந்து மட்டுமே தொகுப்புகளைச் சார்ந்திருக்கிறது. நீங்கள் AUR இலிருந்து நேரடியாக மென்பொருளை நிறுவ முடியும், ஆனால் அடிப்படை நிறுவல் அவ்வாறு செய்வதில்லை — மூன்றாம் தரப்பு browsers போன்ற சில விருப்ப நிறுவல்கள் மட்டுமே AUR இலிருந்து பெறுகின்றன.
5. *Cloudflare எங்களை DDoS இலிருந்து பாதுகாக்கிறது*: Omarchy விநியோக உள்கட்டமைப்பு — ISO கள், Omarchy தொகுப்புகள், Arch mirror — Cloudflare இன் வலிமையான DDoS கவசத்தின் பின்னால் பாதுகாக்கப்பட்டு, அவர்களின் CDN இல் வழங்கப்படுகிறது. இது மிகச்சிறந்த கிடைக்கும் தன்மையை வழங்குகிறது.

## உங்கள் கடவுச்சொற்களை மாற்றுதல்

குறியாக்கம் செய்யப்பட்ட நிறுவலில் உங்களிடம் இரண்டு கடவுச்சொற்கள் உள்ளன: தொடக்கத்தில் வட்டைத் திறக்கும் ஒன்று, மற்றும் நீங்கள் உள்நுழையவும் `sudo` உடன் பயன்படுத்தவும் உள்ள ஒன்று. அமைப்பு அவை இரண்டையும் ஒன்றாகவே ஆக்குகிறது. இரண்டையும் Omarchy மெனுவில் _புதுப்பிப்பு > கடவுச்சொல்_ என்பதன் கீழ் மாற்ற முடியும் — முதலாவதற்கு _வட்டு குறியாக்கம்_, இரண்டாவதற்கு _பயனர்_. வட்டுக் கடவுச்சொல்லை மாற்றுவது முதலில் தற்போதைய கடவுச்சொல்லைக் கேட்கும், எனவே அதைக் கையில் தயாராக வைத்திருங்கள். ஒரு மாற்றம் இடையில் தடைபட்டால், _வட்டு குறியாக்கம்_ ஐ மீண்டும் இயக்கவும்: அது இப்போது வட்டைத் திறக்கும் கடவுச்சொல்லைக் கேட்டு மாற்றத்தை முடித்துவிடும்.

## நீங்கள் ஏற்கனவே பயன்படுத்திய இயந்திரத்தை அடுத்தவரிடம் கொடுத்தல்

உங்கள் இயந்திரத்தை வேறு ஒருவரிடம் கொடுக்கிறீர்கள் என்றால், நீங்கள் அதை மீண்டும் நிறுவ வேண்டியதில்லை. Omarchy மெனுவில் _நீக்கு > தொழிற்சாலை மீட்டமைப்பு_ ஐ இயக்கி, உறுதிப்படுத்த `reset` எனத் தட்டச்சு செய்து, கேட்கப்பட்டால் உங்கள் வட்டு குறியாக்கக் கடவுச்சொல்லை உள்ளிட்டு, மறுதொடக்கம் செய்யவும். அது ஒவ்வொரு பயனர் கணக்கையும் `/home` இல் உள்ள அனைத்தையும் அழிக்கிறது, நிறுவிய பிறகு நீங்கள் செய்த அனைத்துத் தொகுப்புகளையும் கணினி மாற்றங்களையும் தூக்கி எறிகிறது, மேலும் இயந்திரத்தின் அடையாளத்தைத் தெளிவுபடுத்துகிறது — பிணைய இணைப்புகள், host சாவிகள், மற்றும் எல்லாம். மீண்டும் வருவது முதல் தொடக்கத்திலிருந்து வரும் அமைப்பு வழிகாட்டியாகும், அதன் புதிய உரிமையாளர் தங்கள் சொந்தப் பெயர், கடவுச்சொல் மற்றும் குறியாக்கக் கடவுச்சொல்லை உள்ளிடத் தயாராக இருக்கும்.

இது நிறுவி எடுக்கும் அடிப்படை snapshot ஐ மீட்டமைப்பதன் மூலம் செயல்படுகிறது, எனவே இது Omarchy ISO இலிருந்து நிறுவப்பட்ட இயந்திரங்களில் மட்டுமே கிடைக்கும். மேலும் குறியாக்கம் இல்லாத வட்டில், மீட்டமைப்பு என்பது பாதுகாப்பான அழிப்பு அல்ல, வெறும் நீக்கம் மட்டுமே, எனவே தரவு முக்கியமானதாக இருந்தால், அதற்குப் பதிலாக புதிதாக நிறுவவும்.

## கடவுச்சொல் இல்லாத sudo

சில நேரங்களில் `sudo` கேட்பதை நிறுத்த வேண்டும் என்று நீங்கள் விரும்புவீர்கள், பெரும்பாலும் ஒரு AI agent உங்களுக்காக நீண்ட நேரம் கணினி வேலையைச் செய்யும்போது. _அமைப்பு > பாதுகாப்பு > கடவுச்சொல் இல்லாத Sudo_ எவ்வளவு நேரம் அணுகலை அனுமதிக்க வேண்டும் என்று கேட்கிறது: **15 நிமிடங்கள்**, **1 மணி நேரம்**, **1 நாள்**, அல்லது **நிரந்தரமாக**. அணுகல் செயலில் இருக்கும்போது மற்ற மெனு பட்டை குறிகாட்டிகளுக்கு அருகில் ஒரு சிவப்பு எச்சரிக்கை சின்னம் தோன்றும். அதைக் கிளிக் செய்யவும் அல்லது அணுகலை அணைக்க கட்டளையை மீண்டும் இயக்கவும். `omarchy-sudo-passwordless 30` உடன் உங்கள் சொந்த நிமிடங்களின் எண்ணிக்கையையும் (1 முதல் 1440 வரை) நீங்கள் அனுப்பலாம், அல்லது `omarchy-sudo-passwordless permanent` ஐப் பயன்படுத்தலாம்.

காலவரையறுக்கப்பட்ட அணுகல் தானாகவே காலாவதியாகிவிடும், காலக்கெடுவைத் தாண்டிய இடைநிறுத்தத்திலிருந்து மீண்டும் தொடங்கிய உடனேயும் உட்பட. கணினியை மறுதொடக்கம் செய்வது அதை முன்கூட்டியே முடித்துவிடும். நிரந்தர அணுகல் மறுதொடக்கங்களையும் தாண்டி நிலைத்திருக்கும், நீங்கள் அதை முடக்கும் வரை இயக்கத்திலேயே இருக்கும்.

Omarchy இன் அமைப்புகள் தொகுப்பைப் புதுப்பிப்பது அல்லது நீக்குவது, அதன் காலாவதி ஆதரவு மாறுவதற்கு முன்பே எந்தவொரு தற்காலிக அனுமதியையும் முடித்துவிடும். கட்டளை அங்கீகாரம் அல்லது சுத்தப்படுத்தல் பிழையைப் புகாரளித்தால், மற்றொரு அனுமதியை இயக்க முயற்சிக்கும் முன் அதைத் தீர்க்கவும்; பிழை என்பது கடவுச்சொல் இல்லாத அணுகல் செயலில் இல்லை என்று அர்த்தமல்ல.

இதைப் பற்றித் தெளிவாக இருங்கள்: இது இயக்கத்தில் இருக்கும்போது, உங்கள் பயனராக இயங்கும் எதுவும் கேட்கப்படாமலேயே root ஆக எதையும் செய்ய முடியும். அதுவே முழு நோக்கமும், அதுவே முழு அபாயமும் கூட.
