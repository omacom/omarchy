# சிக்கல் தீர்த்தல்

### புதுப்பிப்பால் என் சிஸ்டத்தை உடைத்துவிட்டேன்!

முதலில் உங்கள் சமீபத்திய புதுப்பிப்புக்கு முந்தைய பதிப்புக்கு [உங்கள் சிஸ்டத்தைப் பின்னோக்கித் திருப்ப](47-system-snapshots.md) முயற்சிக்கவும். அது வேலை செய்யவில்லை என்றால், Discord இல் #omarchy-help இல் உங்கள் சிக்கலைப் பகிர `omarchy-debug` ஐப் பயன்படுத்தவும். அவை அனைத்தும் தோல்வியடைந்தால், `omarchy-reinstall` ஐப் பயன்படுத்தி இயல்புநிலை கான்ஃபிகுகளையும் பேக்கேஜ்களையும் மீண்டும் நிறுவலாம்.

### என் திரையில் சில ஆப்ஸ் ஏன் இவ்வளவு பெரிதாகத் தெரிகின்றன?

Omarchy 2x உயர் தெளிவுத்திறன் கொண்ட திரையை அனுமானிக்கிறது, எனவே நீங்கள் மானிட்டர் பேனலில் ஒரு அளவைத் தேர்ந்தெடுக்கும் வரை அது `GDK_SCALE` ஐ 2 ஆக அமைக்கிறது. நீங்கள் 1x திரையில் இருந்து GTK அல்லது X11 ஆப்ஸ் மிகப் பெரிதாக வந்தால், மானிட்டர் பேனலில் அதற்கு 1x ஐத் தேர்ந்தெடுக்கவும், அல்லது `~/.config/hypr/monitors.lua` இல் `hl.env("GDK_SCALE", "1")` ஐச் சேர்க்கவும் (பின்னர் மிகப் பெரிதாக உள்ள எந்த ஆப்ஸையும் மறுதொடக்கம் செய்யவும்). [மானிட்டர்கள் குறித்த கையேட்டைப்](33-monitors.md) பார்க்கவும்.

Spotify இல், UI ஐச் சுருக்க `Ctrl + Minus` ஐப் பயன்படுத்தலாம் (பெரிதாக்க `Ctrl + Plus` ஐப் பயன்படுத்தலாம்).

### என் Super கீ பைண்டுகள் அனைத்தும் ஏன் வேலை செய்வதை நிறுத்திவிட்டன?

சில ASUS ROG மற்றும் TUF லேப்டாப்களில், `Fn + Super` என்பது எளிதில் கவனிக்கத் தவறக்கூடிய ஒரு கோர்டு ஆகும், இது ஃபர்ம்வேர் Windows-key லாக்கை மாற்றுகிறது (கேமிங்கிற்காக வடிவமைக்கப்பட்டது, எனவே நீங்கள் தற்செயலாக ஒரு கேமிலிருந்து வெளியேற மாட்டீர்கள்). அது நடந்ததைத் திரையில் எதுவும் உங்களுக்குச் சொல்லாது. லாக் இயக்கத்தில் இருக்கும்போது, Super எதையும் வெளியிடாது — எனவே Super ஐப் பயன்படுத்தும் ஒவ்வொரு Omarchy பைண்டும் நின்றுவிடும், மேலும் Hyprland உடைந்துவிட்டது போல் தோன்றும்.

`~/.config/hypr/` இல் தோண்டத் தொடங்குவதற்கு முன் `Fn + Super` ஐ ஒருமுறை அழுத்தவும், அது Super ஐ மீண்டும் கொண்டு வரவில்லை என்றால், லாக்கை இயக்கத்தில் விட்டுவிடாதபடி அதை மீண்டும் அழுத்தவும். இது Fn-lock அல்ல, அது F-key வரிசை என்ன செய்கிறது என்பதை மட்டுமே மாற்றுகிறது.

### என் Wi-Fi, Bluetooth, ஆடியோ அல்லது டிராக்பேட் திடீரென வேலை செய்வதை நிறுத்திவிட்டது

நீங்கள் ரீபூட் செய்வதற்கு முன், பாதிக்கப்பட்ட துணை அமைப்பைத் தனியாக மறுதொடக்கம் செய்ய முயற்சிக்கவும். Omarchy மெனுவில் உள்ள _புதுப்பிப்பு > வன்பொருள்_ இல் Wi-Fi, Bluetooth, ஆடியோ மற்றும் டிராக்பேட் உள்ளன, மேலும் அவற்றில் ஒன்றை மீண்டும் ஏற்றுவது பெரும்பாலான "ஐந்து நிமிடங்களுக்கு முன்பு வேலை செய்தது" சூழ்நிலைகளைச் சரிசெய்கிறது — மீண்டும் இணைக்க மறுக்கும் Bluetooth ஹெட்செட், சஸ்பெண்டிற்குப் பிறகு செயலிழந்த டிராக்பேட், நீங்கள் ஒரு மானிட்டரைத் துண்டித்தபோது மறைந்த ஒலி.

### என் வெளிப்புற ஸ்பீக்கர்கள் ஏன் ஒலிக்கவில்லை?

அவை முதன்மை வெளியீடாக அமைக்கப்படாததால் இருக்கலாம். பட்டியின் வலது பக்கத்தில் உள்ள ஸ்பீக்கர் ஐகானைக் கிளிக் செய்யவும், அது ஒலியளவு பாப்அப்பைத் திறக்கும், அங்கு நீங்கள் வெளியீட்டு சாதனத்தைத் தேர்ந்தெடுக்கலாம் (மேலும் ஆப்ஸ் வாரியான ஒலியளவுகளையும் கலக்கலாம்).

### என் லேப்டாப் ஸ்பீக்கர்கள் வித்தியாசமாக ஒலிக்கின்றன

சில லேப்டாப்களில், Omarchy உள்ளமைக்கப்பட்ட ஸ்பீக்கர்களின் அதிர்வெண் பதிலைச் சரிசெய்யும் ஸ்பீக்கர் டியூனிங்கைத் தானாகவே பயன்படுத்துகிறது. `omarchy audio tuning status` உங்கள் கணினியில் ஒன்று செயலில் உள்ளதா என்பதை உங்களுக்குச் சொல்கிறது, மேலும் நீங்கள் ஸ்பீக்கர்களை அப்படியே கேட்க விரும்பினால் `omarchy audio tuning off` அதை அணைக்கிறது.

### என் கடவுச்சொல்லால் ஏன் லாகின் அல்லது sudo செய்ய முடியவில்லை?

நீங்கள் அதைப் பத்து முறை தவறாகத் தட்டச்சு செய்து லாக் அவுட் செய்யப்பட்டிருக்கலாம். லாக்அவுட் இரண்டு நிமிடங்களுக்குப் பிறகு தானாகவே நீங்கும். உங்களால் காத்திருக்க முடியவில்லை என்றால், இது லாக் திரையில் நடந்தால், நீங்கள் `CTRL + ALT + F2` ஐ அழுத்தி ஒரு புதிய TTY ஐத் தொடங்கலாம், அங்கு நீங்கள் root ஆக லாகின் செய்யலாம், பின்னர் `faillock --reset --user [your-username]` ஐ இயக்கலாம். அது லாக்அவுட்டை மீட்டமைக்கும், நீங்கள் தொடரலாம்.

### என் கடவுச்சொல் ஏற்றுக்கொள்ளப்படுகிறது, ஆனால் நான் லாகின் திரைக்கே திரும்புகிறேன்

உங்கள் கடவுச்சொல் சரியாக இருந்தாலும், உடைந்த செஷன் சூழல் கோப்பு டெஸ்க்டாப்பைத் தொடங்குவதைத் தடுக்கலாம். `~/.config/uwsm/env.d/` ஐத் திருத்திய பிறகு இதைச் சரிபார்ப்பது குறிப்பாகப் பயனுள்ளது.

`Ctrl + Alt + F2` ஐ அழுத்தி, உங்கள் சாதாரண பயனர்பெயர் மற்றும் கடவுச்சொல்லுடன் லாகின் செய்து, தற்போதைய பூட்டின் பயனர் ஜர்னலை ஆய்வு செய்யவும்:

```bash
journalctl --user -b -t uwsm_env-preloader --no-pager
```

உங்கள் சூழல் கோப்புகளில் ஒன்றைப் பெயரிடும் பிழையைத் தேடவும், எடுத்துக்காட்டாக `bad substitution`, env வெளியீட்டு அடையாளம் காணப்படவில்லை என்ற செய்திக்குச் சற்று முன்பு. மீண்டும் லாகின் செய்ய முயற்சிப்பதற்கு முன் அந்தக் கோப்பை `env.d` இலிருந்து வெளியே நகர்த்தவும். எடுத்துக்காட்டாக, பிழை `99-custom` ஐப் பெயரிட்டால்:

```bash
mkdir -p ~/.config/uwsm/disabled
mv -i ~/.config/uwsm/env.d/99-custom ~/.config/uwsm/disabled/
```

UWSM தொடரியல் பிழை உள்ள கோப்பைத் தவிர்க்கிறது, ஆனால் கோப்பு இயங்கும்போது மட்டுமே தோன்றும் `bad substitution` போன்ற ஒரு அபாயகரமான பிழை, இன்னும் டெஸ்க்டாப்பைத் தொடங்குவதைத் தடுக்கலாம். சிஸ்டம் ஸ்னாப்ஷாட் பின்னோக்கித் திருப்புதல் இந்தக் கோப்புகளைச் சரிசெய்யாது, ஏனெனில் `/home` பின்னோக்கித் திருப்பப்படாது.

நீங்கள் லாகின் செய்ய முடிந்தவுடன், சேமித்த நகலை மீண்டும் நகர்த்துவதற்கு முன் அதைச் சரிசெய்யவும். `sh -n` கோப்பை இயக்காமல் தொடரியல் பிழைகளைப் பிடிக்கிறது, ஆனால் அது சோர்ஸ் செய்யப்படும்போது ஏற்படும் ஒவ்வொரு பிழையையும் பிடிக்க முடியாது. மாற்றங்களைச் சோதிக்கும்போது வேலை செய்யும் டெர்மினலைத் திறந்து வைத்திருக்கவும்.

### 1Password SSH Agent / CLI க்கான எனது 1Password அங்கீகாரத் தூண்டல்கள் ஏன் தோன்றவில்லை?

இது 2 காரணங்களால் நடக்கலாம்:

விரிவான ஒப்புதல் தூண்டல் தோன்ற, அமைப்புகள் > மேம்பட்டது > வன்பொருள் முடுக்கத்தைப் பயன்படுத்து இயக்கப்பட்டிருக்க வேண்டும். _குறிப்பு: இது வேலை செய்யத் தொடங்க ஒரு ரீபூட் தேவை._

 ![troubleshooting-1password](images/troubleshooting-1password.webp)

அல்லது நீங்கள் பூட் செய்ததிலிருந்து 1Password ஐத் தொடங்கவில்லை என்றால், தூண்டல் தோன்றாது.
