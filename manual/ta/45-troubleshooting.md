# சிக்கல்களைத் தீர்த்தல்

### ஒரு புதுப்பிப்பால் என் கணினியை உடைத்துவிட்டேன்!

முதலில், உங்கள் சமீபத்திய புதுப்பிப்புக்கு முந்தைய பதிப்புக்கு [உங்கள் கணினியை மீட்டமைக்க](47-system-snapshots.md) முயற்சிக்கவும். அது வேலை செய்யவில்லை என்றால், Discord இல் #omarchy-help இல் உங்கள் சிக்கலைப் பகிர `omarchy-debug` ஐப் பயன்படுத்தவும். அவை அனைத்தும் தோல்வியுற்றால், `omarchy-reinstall` ஐப் பயன்படுத்தி இயல்புநிலை உள்ளமைவுகளையும் தொகுப்புகளையும் மீண்டும் நிறுவலாம்.

### என் திரையில் சில செயலிகள் ஏன் இவ்வளவு பெரிதாகத் தெரிகின்றன?

Omarchy ஒரு 2x உயர் தெளிவுத்திறன் திரையை எதிர்பார்க்கிறது, எனவே நீங்கள் மானிட்டர் பேனலில் ஒரு அளவைத் தேர்ந்தெடுக்கும் வரை அது `GDK_SCALE` ஐ 2 என அமைக்கிறது. நீங்கள் 1x திரையில் இருந்து, GTK அல்லது X11 செயலிகள் மிகப் பெரிதாக வந்தால், மானிட்டர் பேனலில் அதற்கு 1x ஐத் தேர்ந்தெடுக்கவும், அல்லது `~/.config/hypr/monitors.lua` இல் `hl.env("GDK_SCALE", "1")` ஐச் சேர்க்கவும் (பின்னர் மிகப் பெரிதாக உள்ள எந்தச் செயலியையும் மறுதொடக்கம் செய்யவும்). [மானிட்டர்கள் குறித்த கையேட்டைப்](33-monitors.md) பார்க்கவும்.

Spotify க்கு, UI ஐச் சுருக்க `Ctrl + Minus` ஐயும் (பெரிதாக்க `Ctrl + Plus` ஐயும்) பயன்படுத்தலாம்.

### என் Super விசைக் கட்டுகள் அனைத்தும் ஏன் வேலை செய்வதை நிறுத்திவிட்டன?

சில ASUS ROG மற்றும் TUF மடிக்கணினிகளில், `Fn + Super` என்பது எளிதில் கவனிக்கத் தவறக்கூடிய ஒரு கூட்டு விசை அழுத்தம்; இது ஒரு firmware Windows விசைப் பூட்டை மாற்றுகிறது (விளையாடும்போது தற்செயலாக விளையாட்டிலிருந்து வெளியேறிவிடாமல் இருக்க உருவாக்கப்பட்டது). அது நடந்ததைத் திரையில் எதுவும் உங்களுக்குச் சொல்லாது. பூட்டு இயக்கத்தில் இருக்கும்போது, Super எதையும் வெளியிடாது — எனவே Super ஐப் பயன்படுத்தும் ஒவ்வொரு Omarchy கட்டும் நின்றுவிடும், Hyprland உடைந்துவிட்டது போலத் தோன்றும்.

`~/.config/hypr/` க்குள் தேடத் தொடங்குவதற்கு முன் ஒருமுறை `Fn + Super` ஐ அழுத்தவும், அது Super ஐ மீண்டும் கொண்டுவரவில்லை என்றால், பூட்டை இயக்கத்தில் விட்டுவிடாமல் இருக்க மீண்டும் அதை அழுத்தவும். இது Fn-lock அல்ல; அது F விசை வரிசை என்ன செய்கிறது என்பதை மட்டுமே மாற்றுகிறது.

### என் Wi-Fi, Bluetooth, ஆடியோ அல்லது டிராக்பேட் திடீரென வேலை செய்வதை நிறுத்திவிட்டது

நீங்கள் மறுதொடக்கம் செய்வதற்கு முன், பிரச்சனைக்குரிய துணை அமைப்பைத் தனியாக மறுதொடக்கம் செய்து பார்க்கவும். Omarchy மெனுவில் உள்ள _Update > Hardware_ இல் Wi-Fi, Bluetooth, Audio மற்றும் Trackpad உள்ளன, அவற்றில் ஒன்றை மீண்டும் ஏற்றுவது “ஐந்து நிமிடங்களுக்கு முன் வேலை செய்தது” என்ற பெரும்பாலான சூழ்நிலைகளைச் சரிசெய்யும் — மீண்டும் இணையாத Bluetooth ஹெட்செட், இடைநிறுத்தத்திற்குப் பிறகு செயலிழந்த டிராக்பேட், மானிட்டரைத் துண்டித்தபோது மறைந்த ஒலி.

### என் வெளிப்புற ஸ்பீக்கர்கள் ஏன் ஒலிக்கவில்லை?

அவை முதன்மை வெளியீடாக அமைக்கப்படாததால் இருக்கலாம். பட்டியின் வலது பக்கத்தில் உள்ள ஸ்பீக்கர் ஐகானைக் கிளிக் செய்யவும், அது ஒலியளவு பாப்அப்பைத் திறக்கும்; அங்கு நீங்கள் வெளியீட்டு சாதனத்தைத் தேர்ந்தெடுக்கலாம் (ஒவ்வொரு செயலிக்கும் தனித்தனியாக ஒலியளவையும் கலக்கலாம்).

### என் மடிக்கணினி ஸ்பீக்கர்களின் ஒலி சரியில்லை

சில மடிக்கணினிகளில், உள்ளமைக்கப்பட்ட ஸ்பீக்கர்களின் அதிர்வெண் பதிலைச் சரிசெய்யும் ஒரு ஸ்பீக்கர் டியூனிங்கை Omarchy தானாகவே பயன்படுத்துகிறது. உங்கள் கணினியில் ஒன்று செயலில் உள்ளதா என்பதை `omarchy audio tuning status` உங்களுக்குச் சொல்லும், ஸ்பீக்கர்களை அப்படியே கேட்க விரும்பினால் `omarchy audio tuning off` அதை அணைக்கும்.

### என் கடவுச்சொல்லால் ஏன் உள்நுழையவோ sudo செய்யவோ முடியவில்லை?

நீங்கள் அதைப் பலமுறை தவறாகத் தட்டச்சு செய்து பூட்டப்பட்டிருக்கலாம். இது பூட்டுத் திரையில் நடந்தால், புதிய TTY ஐத் தொடங்க `CTRL + ALT + F2` ஐ அழுத்தலாம்; அங்கு root ஆக உள்நுழைந்து, பின்னர் `faillock --reset --user [your-username]` ஐ இயக்கவும். அது பூட்டை மீட்டமைக்கும், நீங்கள் தொடரலாம்.

### என் கடவுச்சொல் ஏற்கப்படுகிறது, ஆனால் நான் மீண்டும் உள்நுழைவுத் திரைக்கே திரும்புகிறேன்

உங்கள் கடவுச்சொல் சரியாக இருந்தாலும், உடைந்த ஒரு அமர்வு சூழல் கோப்பு டெஸ்க்டாப் தொடங்குவதைத் தடுக்கலாம். `~/.config/uwsm/env.d/` ஐத் திருத்திய பிறகு இதைச் சரிபார்ப்பது குறிப்பாக முக்கியம்.

`Ctrl + Alt + F2` ஐ அழுத்தி, உங்கள் வழக்கமான பயனர்பெயர் மற்றும் கடவுச்சொல்லால் உள்நுழைந்து, தற்போதைய தொடக்கத்தின் பயனர் பதிவை ஆய்வு செய்யவும்:

```bash
journalctl --user -b -t uwsm_env-preloader --no-pager
```

`bad substitution` போன்ற, உங்கள் சூழல் கோப்புகளில் ஒன்றைப் பெயரிடும் ஒரு பிழையைத் தேடவும்; அது env வெளியீட்டுக் குறி காணப்படவில்லை என்ற செய்திக்குச் சற்று முன் இருக்கும். மீண்டும் உள்நுழைய முயற்சிக்கும் முன் அந்தக் கோப்பை `env.d` இலிருந்து வெளியே நகர்த்தவும். எடுத்துக்காட்டாக, பிழை `99-custom` ஐப் பெயரிட்டால்:

```bash
mkdir -p ~/.config/uwsm/disabled
mv -i ~/.config/uwsm/env.d/99-custom ~/.config/uwsm/disabled/
```

தொடரியல் பிழை உள்ள ஒரு கோப்பை UWSM தவிர்க்கிறது, ஆனால் `bad substitution` போல, கோப்பு இயங்கும்போது மட்டுமே வெளிப்படும் ஒரு கொடிய பிழை, டெஸ்க்டாப் தொடங்குவதை இன்னும் தடுக்கலாம். கணினி ஸ்னாப்ஷாட் மீட்டமைப்பு இந்தக் கோப்புகளைச் சரிசெய்யாது, ஏனெனில் `/home` மீட்டமைக்கப்படுவதில்லை.

நீங்கள் உள்நுழைய முடிந்ததும், சேமிக்கப்பட்ட நகலை மீண்டும் நகர்த்துவதற்கு முன் அதைச் சரிசெய்யவும். `sh -n` கோப்பை இயக்காமல் தொடரியல் பிழைகளைப் பிடிக்கிறது, ஆனால் அது source செய்யப்படும்போது ஏற்படும் ஒவ்வொரு பிழையையும் அதால் பிடிக்க முடியாது. மாற்றங்களைச் சோதிக்கும்போது வேலை செய்யும் ஒரு டெர்மினலைத் திறந்து வைத்திருக்கவும்.

### 1Password SSH Agent / CLI க்கான என் 1Password அங்கீகார அறிவிப்புகள் ஏன் தோன்றவில்லை?

இது 2 காரணங்களால் நடக்கலாம்:

முழுமையான ஒப்புதல் அறிவிப்பு தோன்ற வேண்டுமெனில், Settings > Advanced > Use Hardware Acceleration இயக்கப்பட்டிருக்க வேண்டும். _குறிப்பு: இது வேலை செய்யத் தொடங்க ஒரு மறுதொடக்கம் தேவை._

 ![troubleshooting-1password](images/troubleshooting-1password.webp)

அல்லது கணினியைத் தொடங்கியதிலிருந்து நீங்கள் 1Password ஐத் திறக்கவில்லை என்றால், அறிவிப்பு தோன்றாது.
