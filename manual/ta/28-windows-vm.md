# Windows VM

x86_64 கணினிகளில் Docker VM வழியாக Windows-ஐ இயக்க Omarchy ஒரு எளிய வழியை வழங்குகிறது. Omarchy மெனுவிலிருந்து (`Super + Space`) _நிறுவு > Windows_ என்பதைப் பயன்படுத்தி அதை நிறுவலாம்.

இதற்கு உங்கள் கணினிக்கு KVM மெய்நிகராக்கம் தேவை; பெரும்பாலான கணினிகளில் அது உண்டு — ஆனால் சில நேரங்களில் அது BIOS-இல் அணைக்கப்பட்டிருக்கும், அப்படி இருந்தால் நிறுவி அதை உங்களுக்குச் சொல்லும். வட்டு இடமும் உங்களுக்குத் தேவைப்படும்: Windows-க்கு நீங்கள் கொடுப்பது எதுவோ அது, கூடவே படிமத்திற்கே சுமார் 10GB.

நிறுவி எவ்வளவு RAM, எத்தனை CPU மையங்கள் மற்றும் எவ்வளவு வட்டை ஒப்படைக்க வேண்டும் என்று கேட்கும் (64GB அல்லது அதற்கு மேல் என்பதே புத்திசாலித்தனமான குறைந்தபட்சம்), பிறகு ஒரு Windows பயனர்பெயரையும் கடவுச்சொல்லையும் கேட்கும். அவற்றைக் காலியாக விட்டால் `docker` / `admin` கிடைக்கும். பதிவிறக்கம் சிறிது நேரம் எடுக்கும் — 10-15 நிமிடங்கள் சாதாரணம் — மேலும் `http://127.0.0.1:8006` என்ற முகவரியில் உலாவியில் முன்னேற்றத்தைப் பின்தொடரலாம். கன்சோலைத் திறப்பதற்கு முன் உலாவி அதே பயனர்பெயரையும் கடவுச்சொல்லையும் கேட்கும்.

## அதைப் பயன்படுத்துதல்

நிறுவியதும், செயலி துவக்கியிலிருந்து _Windows_-ஐத் துவக்கவும். அது ஏற்கனவே இயங்கவில்லை என்றால் VM-ஐத் தொடங்கி, முழுத் திரையில் RDP வழியாக உங்களை இணைக்கும். குளிர் தொடக்கத்தில் அதற்கு 15-30 வினாடிகள் கொடுங்கள்.

RDP அமர்வு ஒலி, உங்கள் மைக்ரோஃபோன் மற்றும் பகிரப்பட்ட கிளிப்போர்டு ஆகியவற்றைக் கொண்டு செல்கிறது, எனவே Linux-க்கும் Windows-க்கும் இடையே உரையை நகலெடுப்பது அப்படியே வேலை செய்யும். தெளிவுத்திறன் உங்கள் சாளரத்தைப் பின்தொடரும், மேலும் Omarchy உங்கள் காட்சி அளவிடுதலை அப்படியே அனுப்புகிறது, எனவே HiDPI திரையில் அது மங்கலான குழப்பமாக இருக்காது.

RDP சாளரத்தை மூடும்போது, VM தானாகவே அணைந்துவிடும். அதைத் தொடர்ந்து இயங்க விட விரும்பினால் — உள்ளே ஏதோ ஒன்று வேலை செய்து கொண்டிருக்கிறது என்று வைத்துக்கொள்வோம் — அதற்குப் பதிலாக `omarchy windows vm launch --keep-alive` கொண்டு அதைத் துவக்கவும்.

மீதமுள்ள கட்டுப்பாடுகள் அதே கட்டளையிலேயே உள்ளன:

```bash
omarchy windows vm status    # is it running?
omarchy windows vm stop      # shut it down
omarchy windows vm launch    # start and connect
```

## கோப்புகளைப் பகிர்தல்

உங்கள் முகப்பு அடைவில் உள்ள `~/Windows` அடைவு தானாகவே VM உடன் பகிரப்படுகிறது. Windows அவற்றை அணுக வேண்டும் என்று விரும்பினால் கோப்புகளை அங்கே போடவும். உங்கள் கோப்பு முறைமையின் வேறு எந்தப் பகுதிக்கும் VM-க்கு அணுகல் இல்லை, எனவே Windows பக்கத்தில் உள்ள எந்தக் கெட்டதிலிருந்தும் நீங்கள் பாதுகாப்பாக இருப்பீர்கள். அதன் சொந்த மெய்நிகர் வட்டு `~/.windows`-இல் கிடைக்கிறது.

அந்தப் பழக்கமான முகப்புப் பாதைகள் அவற்றின் சொந்தக் கோப்பு முறைமைகளிலேயே இருக்கும். அவை நீங்கள் சொந்தமாக வைத்திருக்கும் அடைவுகளுக்கான symlinks ஆகவும் இருக்கலாம்; மெய்நிகர் வட்டு பெரிய இயக்ககத்தில் இருக்கும்போது இது பயனுள்ளதாக இருக்கும். நிறுவி உண்மையில் `~/.windows`-ஐக் கொண்டிருக்கும் கோப்பு முறைமையில் உள்ள காலி இடத்தை அளவிடுகிறது, உங்கள் முகப்பு அடைவைக் கொண்டிருக்கும் கோப்பு முறைமையில் அவசியமில்லை.

வட்டு மற்றும் பகிரப்பட்ட பாதைகளைத் தனித்தனியான, ஒன்றுடன் ஒன்று மேற்பொருந்தாத அடைவுகளாக வைத்திருக்கவும். அகற்றுதல் வேண்டுமென்றே வட்டு அடைவைக் காலியாக்கும், ஆனால் பகிரப்பட்ட அடைவைப் பாதுகாக்கும். நீக்குவதற்குச் சற்று முன், Omarchy ஒரு வரம்பிடப்பட்ட அடக்கச் சோதனையைச் செய்கிறது; அந்தச் சோதனை நேரம் முடிந்தாலோ அல்லது இரண்டு மரங்களும் தனித்தனியானவை என்று நிரூபிக்க முடியாவிட்டாலோ எதையும் அகற்ற மறுக்கிறது.

VM தொடங்குவதற்கு முன், Omarchy அந்த இரண்டு அடைவுகளையும் திறந்து பொருத்தி வைக்கிறது, பிறகு சரியான அடைவு inodes-ஐ `/var/lib/omarchy/windows/mounts`-க்குக் கீழே உள்ள தனிப்பட்ட, ஒவ்வொரு பயனருக்குமான நங்கூரங்களில் bind-mount செய்கிறது. Docker அந்த root-பாதுகாக்கப்பட்ட நங்கூரங்களை மட்டுமே பார்க்கிறது. இது தனிப்பயன் வட்டு இருப்பிடங்களைப் பாதுகாக்கிறது; அதே நேரத்தில், சிறப்புரிமை பெற்ற கொள்கலன் அதைப் பயன்படுத்துவதற்கு முன் உங்களாக இயங்கும் மற்றொரு செயல்முறை சோதிக்கப்பட்ட பாதையை மாற்றுவதைத் தடுக்கிறது. இடம்பெயர்வின்போது ஏற்கனவே உள்ள வட்டு மற்றும் பகிரப்பட்ட அடைவுகள் mode `0700`-க்கு இறுக்கப்படுகின்றன, இதனால் பிற உள்ளூர் கணக்குகள் அவற்றின் உள்ளடக்கங்களை உலாவ முடியாது.

VM-இன் போர்ட்கள் localhost-க்கு மட்டுமே பிணைக்கப்பட்டுள்ளன, எனவே உங்கள் வலையமைப்பில் உள்ள எதுவும் Windows கணினியை அடைய முடியாது. வலை கன்சோலுக்கும் கட்டமைக்கப்பட்ட Windows பயனர்பெயரும் கடவுச்சொல்லும் தேவை; இது மற்றொரு உள்ளூர் கணக்கு போர்ட் 8006 வழியாக VM-ஐ இயக்குவதைத் தடுக்கிறது.

## வரம்புகளும் உரிமமும்

இந்த அமைப்பில் GPU பாஸ்த்ரூ இல்லை, எனவே இது விளையாட்டுக்கோ வீடியோ திருத்தத்திற்கோ பொருத்தமானதல்ல. Microsoft Office-ஐ அல்லது உங்களிடம் கட்டாயம் இருக்க வேண்டிய வேறு எதையும் இயக்க இது ஒரு சிறந்த வழி.

நிறுவப்படும் பதிப்பு Windows 11 Pro, செயல்படுத்தப்படாதது. கட்டுப்படுத்தப்பட்ட அம்சங்களைப் பயன்படுத்த உங்கள் சொந்த உரிம விசை தேவைப்படும்.

இந்தக் கணினி Windows உடன் வந்திருந்தால், Omarchy-ஐ நிறுவிய பிறகும் OEM விசை இன்னும் firmware-இல் இருக்கும். `omarchy windows key` கொண்டு அதை அச்சிடவும். அந்த விசை இந்தக் கணினியுடன் பிணைக்கப்பட்டது — இந்த வன்பொருளில் மீண்டும் நிறுவப்பட்ட Windows-ஐ அது செயல்படுத்தும், ஆனால் பொதுவாக அது VM-ஐச் செயல்படுத்தாது.

பின்னர் ஒரு டெர்மினலில் `omarchy windows vm install`-ஐ இயக்குவதன் மூலம் வள ஒதுக்கீட்டை மாற்றலாம்; அது உங்கள் பதில்களிலிருந்து VM-இன் கட்டமைப்பை மீண்டும் எழுதும். compose கோப்பு இப்போது `/var/lib/omarchy/windows/docker-compose.yml`-இல் இருக்கிறது மற்றும் root-க்குச் சொந்தமானது — அது வேண்டுமென்றே செய்யப்பட்டது, இதனால் உங்களாக இயங்கும் ஒரு செயல்முறை அதை மீண்டும் எழுதி, சிறப்புரிமை பெற்ற துவக்கம் உங்கள் முழு வட்டையும் கொள்கலனுக்குள் ஏற்றும்படி செய்ய முடியாது. அதைக் கையால் திருத்த வேண்டும் என்றால் (எடுத்துக்காட்டாக ஒரு USB சாதனத்தை ஏற்ற), அதை `sudo` கொண்டு திருத்தவும், எல்லா விருப்பங்களையும் [Dockur Windows திட்டத்தில்](https://github.com/dockur/windows) பார்க்கவும்.

முழுவதையும் அகற்ற, Omarchy மெனுவிலிருந்து _அகற்று > Windows_-ஐப் பயன்படுத்தவும். அது `~/.windows`-இல் உள்ள VM-இன் வட்டையும் Windows-க்குள் நிறுவப்பட்ட எல்லாவற்றையும் நீக்கும், எனவே உங்களுக்குத் தேவையான எதையும் முதலில் VM-இலிருந்து நகலெடுத்துக் கொள்ளவும். உங்கள் பகிரப்பட்ட `~/Windows` கோப்புறை அப்படியே விடப்படும்.
