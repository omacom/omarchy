### 安装和更新智能体

除 Hermes 和 OpenClaw 外，每个智能体都是来自 Omarchy 自有仓库的一个软件包。从 _安装 > AI > CLI_ 或使用 `omarchy install ai cli <command>` 安装一个，再从 _移除 > AI > CLI_ 将其移除，移除时会保留其登录信息和历史记录。选择一个尚未安装的智能体也会将其安装：在智能体面板中为其加星、使用 `omarchy default agent <name>` 选择它，或者登录其订阅。Omarchy 会在一小时内将每个智能体的每个新版本发布到所有渠道，而 `omarchy update` 会随系统其余部分一起将其安装。

由于 pacman 会让它们保持最新，智能体自身的更新程序已被关闭：`claude update` 或应用中的更新按钮都无事可做。如果你更愿意通过智能体自身的安装程序来运行它，那就用那个，并保持 Omarchy 的软件包未安装；`PATH` 上已有的副本也算已安装。跳过那些会把第二份副本放到 `PATH` 中 Omarchy 副本之前的 `curl | bash` 安装程序，例如 x.ai 为 `grok` 提供的那个。

`dsh` 会在 `127.0.0.1:3080` 打开其浏览器界面，并以启动目录作为默认工作区。其浏览器界面不接受起始提示词，因此 `omarchy agent prompt` 打开它时，会把提示词放到你的剪贴板上供你粘贴。Omarchy 会以 DeepSeek 的无审批权限预设启动它。当你使用 DeepSeek Harness 的官方模型 API 时，它会将会话日志上传到 DeepSeek；在其浏览器界面中的 _设置 > 常规 > Upload Session Log_ 下关闭此项。你发送给它的反馈也会随会话一同上传，除非你使用 `DSH_TELEMETRY_MODE=DISABLED` 启动它。

### 默认智能体

在智能体面板中，用智能体旁边的星标来选定你的默认智能体，默认项的星标会被填充，或者使用 `omarchy default agent <name>`，该命令也接受任何在面板中没有一行的 harness。如果智能体尚未安装，选择它会先将其安装，而且它还会在应用启动器中获得自己的启动器，位于 Agent 旁边。全新安装的 Omarchy 会通过一条一次性通知邀请你设置一个，点击它会打开智能体面板。

选择 Claude 时，还会尝试为 Chromium、Chrome、Brave、Brave Origin 和 Edge 设置其浏览器扩展。扩展的设置适用于所有用户，并可能要求你输入系统密码；取消或扩展安装失败，仍然会选定并启动 Claude。重启你的浏览器，在提示时启用该扩展，并登录 Claude 以完成连接。在 Claude 中运行 `/chrome` 以检查连接。Firefox 和 Zen 不支持此扩展。如果在添加此设置之前 Claude 已经是你的默认项，请再次选择它以安装该扩展。

选定之后，`Super + Shift + Ctrl + A` 会在一个专用的终端窗口中启动默认智能体（或者，如果你尚未选定，则会打开选择器）。你也可以用 `omarchy agent prompt "Review this project"` 让它直接进入一项任务。Freebuff 和 DeepSeek Harness 不接受起始提示词，因此它们打开时会改为把提示词放到你的剪贴板上供你粘贴。以这种方式启动的智能体会以各自的不要停下来问模式无人值守地运行，所以要做好它们真的会动手的准备！MiniMax Code 的交互式会话没有这种模式，因此它会照常请求权限。另外，由于智能体拒绝记住对你的主目录的信任，从 `$HOME` 启动时，会改为在 `~/Work` 中启动。

还有终端快捷方式：`a` 会在当前终端中内联运行默认智能体，而 `c`、`cx`、`cy` 和 `ca` 则直接启动 OpenCode、Claude Code、Codex 和 Antigravity（同样处于它们的自动批准模式）。主题更改也会同步到智能体：当你切换 Omarchy 主题时，Claude Code、Pi、OpenCode 和 Hermes（一旦 Omarchy 已安装它）都会随之跟随。

### 你的智能体指令

适用于每个智能体的个人规则放在 `~/.agents/AGENTS.md` 中，紧挨着 `~/.agents/skills` 中的共享技能。用智能体面板中 + 旁边的文档图标打开它，或者使用 `omarchy agent instructions --edit`，后者还会把它链接到每个维护着自己全局文件的 harness 中：`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`~/.pi/agent/AGENTS.md`、`~/.config/opencode/AGENTS.md`、Copilot 的 `~/.copilot/copilot-instructions.md`，等等。Crush 和 Amp 读取 `~/.config/AGENTS.md` 链接，而 omp、Kimi 和 DeepSeek Harness 则直接读取 `~/.agents/AGENTS.md`。选定默认智能体时也会将其链接。如果你已有的指令文件此前还没有共享文件，它就会成为共享文件；否则，它会作为 `.bak` 保存在链接旁边。安装另一个智能体后，运行 `omarchy agent instructions` 重新链接。

### 智能体面板

顶栏有一个智能体图标。在你设置智能体之前，它的面板提供了三种入门方式：登录 Claude、Codex、Grok、Gemini、Muse、Cursor 或 Copilot 订阅，或者在更多下登录 OpenCode Go、MiniMax、Synthetic 或 Z.ai 编程套餐；使用 Fireworks、OpenCode Zen 和 Go、OpenRouter 按量付费，或者在更多下使用 DeepSeek 或 OpenCode 可登录的任何其他提供商，这些都在 OpenCode 中运行；或者，在有适合的模型时，运行最适合你电脑的模型。你完成的第一种方式会成为你的默认智能体，面板中的 + 之后也会提供同样的三种方式。在那之后，面板会把每一个订阅都放在一页上：每个智能体和账户及其套餐、其 5 小时会话限额和每周限额各自的计量条以及距离重置的时间（将鼠标悬停可查看确切百分比），或者剩余的预付余额，上面还有一行轮流显示你在所有这些项目中的使用情况，例如本周的 token 数和你最常用的模型。在 _做点酷东西_ 下，它提供了用于新主题、插件、应用或游戏的起始提示词，这些提示词会把任务交给你的默认智能体。应用的构建方式与 Omarchy 自己的 Hype、Monologue 和 Omacut 相同，使用 C++ 和 Qt Quick，遵循 omarchy-make-app 智能体技能，而且它们所需的编译器和 Qt 组件都已安装。游戏是 `~/Games/vibes` 中的单个 three.js 页面，遵循 omarchy-make-game 智能体技能，并且全都从当前主题中的一个 Game Vibes 启动器打开；它们从网络加载 three.js，因此启动时需要连接。Claude Code、Codex、Grok、Kimi、Cursor 及其 Grok Bot 额度、GitHub Copilot、Muse、Gemini（通过 Antigravity）和 Devin 开箱即用地被覆盖，并显示其限额，Kimchi 显示其套餐、预付额度和支出预算，Hermes、Mistral Vibe 和 Qwen Code 则会在你使用它们之后显示其会话和 token。你通过 pi、omp 或 opencode 使用的提供商套餐和密钥也会显示出来：OpenCode Zen 和 Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan 和 Synthetic 及其限额；OpenRouter 和 DeepSeek 及其预付余额；Fireworks 及其过去 30 天的支出。你在自己硬件上运行的编程模型会有各自的行，而且它们的 token 也会计入总计，如 [本地模型](#local-models) 所述。每个智能体只计一次，计在向你收费的那一方名下，无论你通过多少个 harness 来驱动它。

左键单击栏图标或按 `Super + Ctrl + X` 打开面板，右键单击启动你的默认智能体，中键单击刷新。其背后的使用记录每 15 分钟由 `omarchy agent usage update` 重新生成，而且面板甚至可以通过一个同步文件夹合并来自你其他机器的使用情况。完整设置请参见 `$OMARCHY_PATH/shell/plugins/agents/` 下的 README。

### 多个订阅

如果你付费购买了不止一个 Claude、Codex 或 Grok 套餐——比如一个个人 Max 和一个工作套餐——Omarchy 可以让它们全都保持登录，并在它们之间切换。用智能体面板中的 + 添加一个订阅，它会就在那里引导你完成，或者使用 `omarchy agent account add claude Work`（或 `codex`，或 `grok`）。同样的 + 和命令还可以登录 Gemini（`gemini`）和 OpenCode（`opencode`），并在 OpenCode 中保存 Fireworks（`fireworks`）或 OpenRouter（`openrouter`）API 密钥；该命令还可以登录 Copilot（`copilot`）、Cursor（`cursor`）和 Muse（`muse`）。这些各自只保留一个登录。它会在 CLI 缺失时安装它。一个提供商的第一个账户会通过你的普通浏览器登录，就在 CLI 一直查找的位置。此后的每一个账户都通过隐私窗口登录，这样你浏览器已经登录的账户就不会被误选；在那里以你要添加的账户登录，并先关闭你已打开的任何隐私窗口。切勿为此退出 CLI 的登录：退出登录会撤销已保存的登录信息，那个账户就必须重新添加。

要通过 SSH 将你的订阅登录信息复制到另一台 Omarchy 机器上，运行 `omarchy agent account copy user@laptop`。当目标机器未安装接收端时，发送方会提供一个临时接收端，因此较旧的 Omarchy 机器无需更新即可接收账户。已安装的接收端优先。这会复制所有 Claude、Codex 和 Grok 订阅；添加提供商名称可选择它们，如 `omarchy agent account copy laptop claude` 中所示。账户名称和命令 ID 与源机器保持一致，包括目标机器上已存在的账户。不相关的目标账户如果名称冲突，会获得一个数字后缀，而设置、技能、插件和对话历史则保留在每台机器本地。

目标机器现有的凭据会得到保留。一个已经在那里登录的源账户，其名称会被同步，而不会替换其凭据；其他账户会被添加在其旁边。要替换匹配账户的已保存凭据，请在退出目标机器上该账户的会话后，使用 `omarchy agent account copy --replace laptop claude`。一台全新的目标机器还会获得源机器的活动账户和切换偏好；一台已在使用中的目标机器则保留自己的。

凭据通过 SSH 传输，并存储在目标机器的私有文件中，因此只复制到你信任的机器上。这是一次性复制，不是持续同步。Codex 刷新 token 可能会被另一台机器轮换，导致复制的登录信息需要续期；对于在多台机器上同时使用，分别登录仍然是最可靠的选择。请参见 [Codex 的账户身份验证指南](https://developers.openai.com/codex/auth/ci-cd-auth)。

每个提供商有一个活动账户，每个新会话都以它开始：`cx`、`cy`、普通的 `claude`、`codex` 或 `grok`、通过 `omarchy agent` 启动的任何东西，以及在 `PATH` 上找到 CLI 的脚本或编辑器。用 `omarchy agent account use work` 切换（用 `omarchy agent account use main` 切回来），或者在面板中按一个账户的编号然后按 `Enter`（或点击它的星标）。正在运行的 Claude 会话也会切换，从它们的下一条消息开始：每个 Claude 会话都在 `~/.claude` 中运行，那里始终保存活动账户的登录信息。由较旧 Omarchy 在账户自己的文件夹中启动的 Claude 会话会一直保持那个登录，直到它退出，因此切换操作会列出那些会话的名称，并在它们消失后自行完成。正在运行的 Codex 和 Grok 会话会保持它们启动时所用的账户。对话历史、设置、技能和插件在各账户之间共享，因此在同一文件夹中运行 `claude --continue` 会在新账户上从你离开的地方继续。

有多个账户时，面板会并排显示每个账户的限额，正在使用的那个带有一个填充的星标。当活动账户超过某个限额的 95% 时，Omarchy 会通知你，点击通知会切换到余量最多的账户。它从不会自行切换。用 `omarchy agent account threshold 90` 更改阈值。如果每个账户都超过阈值，你会收到一次通知，并得知哪个账户最先释放。在活动账户距离其阈值不到 15 个百分点时（默认下为 80%），其限额会每三分钟检查一次，而不是每 15 分钟。

`omarchy agent account list` 显示每个账户及其最新限额，`omarchy agent account remove work` 删除一个，`omarchy agent account rename primary Hey` 重命名一个（或者点击面板中账户的名称）。这些命令作用于你的默认智能体的账户；要访问另一个提供商，先命名它，如 `omarchy agent account use codex side` 中所示。你在 `~/.claude` 或 `~/.codex` 中已有的登录是 _Main_ 账户。Codex 的会留在原处；Claude 的则会在另一个账户活动时，待在它自己的一个文件夹中。一个闲置超过约八小时的账户可能会显示 _需要登录_；点击它可直接在面板中再次登录该账户，或者切换到它并启动一个会话，它会自行刷新登录信息。你用 `claude mcp add` 添加的 MCP 服务器会到达每个 Claude 账户，因为它们都在 `~/.claude` 中运行；对于 Codex 和 Grok，在添加账户时你已有的服务器会随之而来，但之后添加的服务器只会到达你添加它们时所在的账户。Claude Desktop 保留它自己的登录，而使用 CLI 二进制文件的绝对路径配置的 Codex 或 Grok 工具不会跟随切换。显式的 `CLAUDE_CONFIG_DIR`、`CODEX_HOME` 或 `GROK_HOME` 优先于所选账户。

### 崩溃诊断

Omarchy 会监视 systemd-coredump 中的进程崩溃。一旦你选定了默认智能体，你任何转储了核心的程序都会带来一条进程已崩溃通知——点击它，崩溃就会连同 Omarchy 的 omarchy-diagnose-crash 技能一起交给你的默认智能体，该技能会引导智能体从核心转储中确立事实，并决定这次崩溃是否值得向上游报告。你也可以用 `omarchy agent crash <pid>` 手动对 `coredumpctl list` 中的任意 PID 运行它。

监视默认开启。在 _触发器 > 切换 > 关闭崩溃捕获_ 下关闭它（或使用 `omarchy toggle crash-capture`），通知就会停止；`omarchy agent crash <pid>` 仍然可以手动使用。

崩溃也可以一次为一个程序静默，这正是诊断在最后向你提供的选项。`omarchy crash mute hyprland` 只停止该程序的通知，`omarchy crash mute hyprland off` 将它们恢复，而单独运行 `omarchy crash mute` 会列出你已静默的内容。它接受二进制文件的路径，就像接受其名称一样方便，因此 `omarchy crash mute /usr/bin/hyprland` 起同样的作用。把含有空格的名称用引号括起来，如 `omarchy crash mute 'Some App'` 中所示。其他一切仍会通知，被静默的程序仍然会崩溃——这只是隐藏提醒，并不修复任何东西。

### 桌面应用

_安装 > AI > Desktop_ 包含图形化的 AI 应用：Amp Desktop、Antigravity Desktop、ChatGPT 桌面应用、Claude 桌面应用（Anthropic 的 Linux 测试版，带有 Chat、Cowork 和 Claude Code 标签页）、用于与 xAI 模型聊天的 Grok Bot、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexity 桌面应用和 T3 Code。Grok Bot 是桌面聊天应用。编程智能体是 `grok` 命令。

Hermes Desktop 是需要了解的那个，因为一台机器只有一个 Hermes，而且它是该应用的：Hermes 只会通过该应用安装，而默认智能体运行的 `hermes` 命令也是该应用的。选择 Hermes 作为默认智能体，安装的是与 _安装 > AI > Desktop_ 条目相同的东西：软件包，以及一个由 Hermes 自己的安装程序在 `~/.hermes` 下设置的 Hermes 运行时，首次安装需要几分钟。那个运行时就是终端 `hermes` 命令、默认智能体和应用共同使用的唯一 Hermes，它用 `hermes update` 自行更新，而不是等待 Omarchy 发布。安装它还会把 Omarchy 主题作为一个名为 `omarchy` 的皮肤交给 Hermes，每一个 Hermes 界面都会在你切换主题时随之跟随；如果你不希望这样，在 Hermes 的 Appearance 设置下或用 `/skin` 选择另一个，Omarchy 会尊重那个选择。在 _移除 > AI > Desktop_ 下移除该应用，会先关闭 Hermes，包括网关，并带走那个运行时，同时保留你的聊天、记忆以及 Hermes 为自己编写的技能，除非你另有指示：它会询问，默认回答为否，是否也应删除那些数据和你的连接设置。

OpenClaw 的桌面体验是它的 Control UI，它会作为一个由其自己的本地网关支持的 Web 应用打开。OpenClaw 位于 `~/.openclaw` 中，并会自行更新：使用 Control UI 的 Update Gateway 按钮或运行 `openclaw update`，网关就会在新版本上重启。Omarchy 只选择全新安装从哪个版本开始。OpenClaw 也可以是你的默认智能体：用 `omarchy default agent openclaw` 选择它，会在 `~/.openclaw` 中设置同一个副本，而且该智能体会打开连接到其网关的 OpenClaw 终端 UI。在 _移除 > AI > Desktop_ 下移除 OpenClaw，会带走网关服务和应用，然后询问是否也应删除 `~/.openclaw`，因为那里保存着你的聊天和凭据，以及 OpenClaw 本身和它下载的插件运行时；默认会保留它，再次安装 OpenClaw 时会重新使用它。

Herdr Desktop 是 [Herdr](https://herdr.dev) 桌面应用：由终端和编程智能体组成的空间、标签页和窗格，当你关闭窗口时，它们会在其核心中继续运行。它来自 Herdr 自己的安装程序而非软件包，因此它位于 `~/.local/share/herdr-app` 中，当你还没有核心时，会在 `~/.local/bin/herdr-core` 中带来它的核心，并会自行更新这两者。它与 Omarchy 在 `Super + Ctrl + Return` 上提供的 `herdr` 命令并存，而不是取代它，并获得该命令的直接按键：`Alt + Return` 和 `Alt + Shift + Return` 向下或向右拆分窗格，`Alt + Escape` 关闭它，`Ctrl + Alt + Arrow` 在窗格之间移动，`Alt + 1..9` 和 `Alt + Left/Right` 选择标签页，`Alt + Up/Down` 在空间之间移动。`Ctrl + 1..9` 选择空间，`Alt + Shift + Up/Down` 逐个切换智能体。`Ctrl + Space` 前缀键仍然仅供终端使用，因为该应用无法为一段按键序列按住一个普通的 Ctrl 键。Omarchy 会将这些写入 `~/.config/herdr-app/keys.json`，而 `omarchy-refresh-herdr-app` 会将它们还原。安装它会选择 Herdr 的 Omarchy 主题，从那时起它会跟随你的 Omarchy 主题。Herdr 为浅色模式保留一个主题，为深色模式保留一个主题，因此在深色和浅色 Omarchy 主题之间切换后，请为另一种模式在 Herdr 的主题选择器中再次选择 Omarchy。

T3 Code 从 `~/.local/share/t3code` 中其官方 AppImage 发布版运行，而不是从软件包运行，因此它会自行更新。安装它时会询问是从 Stable 还是 Nightly 渠道开始；稍后可在 T3 Code 的设置中切换。你的线程和设置位于 `~/.t3` 中，在 _移除 > AI > Desktop_ 下移除 T3 Code 时会将它们一起带走。

### 本地模型

在你自己的机器上为你的编程智能体运行一个开放模型。你的提示词和代码会留在机器上；发送给模型的任何东西都不会离开它。从以下命令开始：

```bash
omarchy models use best text
```

这会为这台机器设置最佳文本模型，也就是你的智能体使用的那种。图像、视频和音乐模型各有其最佳选择：`omarchy models use best image`、`video` 或 `music`。运行 `omarchy models use best` 可查看每种类型为这台机器所做的选择。

或者在智能体面板中选择 +：在 _使用本地模型_ 下，它会列出适合这台机器的每一个编程模型，推荐的排在第一位。运行模型的 Podman 随 Omarchy 附带，在 NVIDIA 机器上，NVIDIA 的容器工具包也随之附带，它为模型提供 GPU；如果其中任何一个缺失，第一次设置时会安装它。然后 Omarchy 会为这台机器挑选推荐的模型，下载它，并启动它。预计下载量为数十 GB，并且在模型运行时机器的大部分内存会被占用：Flash Next 在使用其完整的 256K 上下文时，会占用约 100 GiB。如果其他模型占用了它所需的内存，它会被设置为已停止状态，等你停止其中一个后即可启动。该模型在注销时停止；当你需要把内存用于其他事情时，请自己停止它。

`omarchy models list` 显示选项，并解释为什么有些不适合。要设置另一个，运行 `omarchy models use <recipe>`。如今，`qwen3.8-flash-next-gufo` 和 `qwen3.8-27b-gufo` 适用于 128 GB 的 Strix Halo 机器；27B 占用约 40 GiB，因此它为其他工作留出了空间。在一台带有 Intel Arc B390 的 64 GB 笔记本电脑上，`qwen3.6-35b-a3b-llamacpp` 以约 30 GiB 运行。新的配方和推荐会通过软件包随 `omarchy update` 一同到来。

你添加的编程模型会在智能体面板中获得自己的一行，位于你的订阅旁边：播放按钮用于启动它，暂停按钮用于停止它并释放其内存，Tailscale 标记用于在它运行时与你 tailnet 上的其他机器共享它，终端按钮用于在它上面打开你的智能体。它的行会实时显示下载、加载或停止，并在没有足够的可用内存来启动它时说明情况，或者在它因错误而停止时链接到其日志。当它们能同时装入内存时，多个模型可以同时运行。在选定的一行上按 Delete，可将该模型连同下载内容一起从这台机器上删除；+ 可以再次设置它。从终端设置的编程模型会等在 + 下，直到你添加它，你已配对的机器（`omarchy models pair <host>`）所运行的模型也是如此。

你设置的每一个编程模型还会在应用启动器中获得自己的条目，以该模型的名称和其制造商的标志显示，就像登录 Claude、Codex 或 Grok 会添加一个一样。它会在该模型上打开你的智能体，如果模型尚未运行，会先启动它：终端会显示它正在加载，并在它启动后交给智能体。移除一个模型会移除它的条目。

不是每个模型都是用于编程的。图像、视频和音乐模型会在 Fantasi 中打开，那是 Omarchy 用于借助在这台机器上运行的模型来制作图片、视频和音乐的应用，并在那里或用 `omarchy models` 进行管理。

一个模型会完全按照它设置时的方式继续运行，因此 Omarchy 更新从不会在你的智能体底下重启一个模型。当 Omarchy 为你已设置的模型提供了更新的运行时或更新的权重时，它的行会显示一个更新按钮：按下它，该模型会在后台重新设置，只下载已更改的内容，并在新版本上重启。一个已停止的模型会保持停止状态。`omarchy models update` 从终端对每个模型做同样的事情。

从命令行，`omarchy models start <recipe>` 和 `omarchy models stop <recipe>` 做同样的事情，`omarchy models status` 显示每一个模型，而 `omarchy agent --local-model <recipe>` 无论你的默认智能体是什么，都会在 pi 中打开那个模型。要让你的本地模型成为智能体热键、Quake 控制台和 _做点东西_ 打开的对象，运行 `omarchy default agent local` 或在智能体面板中为一个正在运行的模型加星。pi 还会在其自己的模型选择器中列出你已设置的每一个模型，以及你已配对机器上的那些模型，因此普通的 `pi` 也能访问它们。任何与 OpenAI 兼容的客户端也可以连接：`status` 显示每个模型的地址（第一个是 `http://127.0.0.1:11435/v1`），配方名称即是模型，而密钥在 `~/.config/omarchy/agent-local/key` 中。

`omarchy models remove <recipe>` 删除一个模型以及没有其他模型使用的下载内容。

第三方运行时会标有其发布者。Omarchy 运行每个模型时都不提供网络访问。

### 本地 LLM

Omarchy 推荐两种运行本地 LLM 模型的方式：LM Studio 和 Ollama。LM Studio 提供了一个 GUI 界面，用于查找开放权重模型、安装它们并运行它们。这是一个轻松上手的好方法。Ollama 则提供 CLI 来以类似方式做到这一点。但如果你刚接触本地模型，我建议从 LM Studio 开始。从 Omarchy 菜单中的 _安装 > AI > Desktop_ 安装 LM Studio，并从 _安装 > AI > CLI_ 安装 Ollama。

### Omarchy 技能

智能体技能帮助 AI 以特定方式使用特定工具，Omarchy 附带其中七个。omarchy 技能涵盖定制系统，例如调整你的 Hyprland 配置或调整栏。omarchy-make-theme、omarchy-make-plugin、omarchy-make-app 和 omarchy-make-game 涵盖制作新东西，omarchy-contribute 涵盖报告 bug 或向上游发送修复，而 omarchy-diagnose-crash 则处理崩溃的核心转储。它们被符号链接到 Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` 以及每个 `~/.hermes/profiles/*/skills`）的技能目录，以及通用的 `~/.agents/skills` 位置，因此大多数 harness 会自动拾取它们。你自己的同名技能文件夹优先。

但你应该把这些技能看作是实验性的。不同的模型使用它的效果会有所不同。最好先以计划模式运行，这样你就能了解智能体想要更改什么。然后，如果智能体把一切弄得一团糟，要做好回滚更改、甚至调用 `omarchy reinstall configs` 的准备。
