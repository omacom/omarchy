### 安装和更新智能体

除 Hermes 和 OpenClaw 外，这些智能体都使用 mise 的懒安装：首次启动时安装 CLI，之后的启动会复用它。mise 还会至多每四小时检查一次已安装智能体是否有新版本，就在它启动之前，或者在 shell 提示符下在后台检查。如果该更新失败或者你处于离线状态，就会运行已安装的版本。`omarchy update` 会随 Omarchy 的其余部分一起更新已安装的智能体，而 `mup` 只更新由 mise 管理的工具。

智能体自己的更新器，例如 `claude update`、`codex update`，或者应用中的更新按钮，不会更新由 mise 管理的安装。`codex update` 会失败，而 `claude update` 可能会报告成功，却安装了一个 mise 不跟踪的独立副本。如果你更愿意使用智能体原生的安装器和更新器，把它加入 `disable_tools`；参见[预装 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

要在需要之前安装所有已配置的懒工具，运行 `mise install --include-lazy`。这包括 Omarchy 的其他默认 CLI 工具以及这些智能体。有关安装单个工具或使用你自己的安装，参见[预装 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

`grok` 通过 mise 的第一方 `grok` 包安装，与 `claude` 和 `codex` 的方式相同。运行 `grok`，或者在智能体面板中给它加星。跳过 x.ai 上的 `curl | bash` 安装器。那条路径会在 `~/.grok/bin` 中放入第二个副本，把它前置到 `PATH` 上，并覆盖 Omarchy 的包装器。

`dsh` 会在 `127.0.0.1:3080` 上打开它的浏览器 UI，并以启动目录作为其默认工作区。它的浏览器 UI 不接受起始提示词，所以 `omarchy agent prompt` 打开它时会把提示词放在你的剪贴板上供你粘贴。Omarchy 会以 DeepSeek 的无审批权限预设启动它。当你使用 DeepSeek 的官方模型 API 时，DeepSeek Harness 会把会话日志上传到 DeepSeek；在它的浏览器 UI 中的 _Settings > General > Upload Session Log_ 下关闭这一项。你发送给它的反馈也会随会话一起上传，除非你以 `DSH_TELEMETRY_MODE=DISABLED` 启动它。

### 默认智能体

用智能体面板中某个智能体旁边的星标来挑选你的默认智能体，默认项上的星标是实心的，或者用 `omarchy default agent <name>`，它也接受任何在那里没有一行的 harness。如果该智能体尚未安装，挑选它会先安装它，并且它还会在应用启动器中获得它自己的启动器，紧挨着 Agent。全新的 Omarchy 会通过一次性通知邀请你设置一个，通知会打开智能体面板。

选择 Claude 还会尝试为 Chromium、Chrome、Brave、Brave Origin 和 Edge 设置它的浏览器扩展。该扩展设置适用于所有用户，并且可能会要求你输入系统密码；取消或扩展安装失败仍然会选择并启动 Claude。重启你的浏览器，在提示时启用该扩展，并登录 Claude 以完成连接。在 Claude 中运行 `/chrome` 来检查连接。Firefox 和 Zen 不支持此扩展。如果在加入此设置之前 Claude 就已经是你的默认项，再次选择它即可安装该扩展。

选好之后，`Super + Shift + Ctrl + A` 会在一个专用终端窗口中启动默认智能体（或者如果你还没有选择，就会调出选择器）。你也可以用 `omarchy agent prompt "Review this project"` 让它直接进入一项任务。Freebuff 和 DeepSeek Harness 不接受起始提示词，所以它们打开时会把提示词放在你的剪贴板上供你粘贴，而不是这样。 以这种方式启动的智能体会以它们各自的不要停下来询问模式无人值守地运行，所以要做好它们真的会动手做事的准备！MiniMax Code 的交互式会话没有这种模式，所以它会像往常一样请求权限。而且由于智能体拒绝记住对你的主目录的信任，从 `$HOME` 启动会转而在 `~/Work` 中开始。

也有终端快捷方式：`a` 在当前终端中内联运行默认智能体，而 `c`、`cx`、`cy` 和 `ca` 直接启动 OpenCode、Claude Code、Codex 和 Antigravity（同样是在它们的自动批准模式下）。主题变化也会同步到智能体：当你切换 Omarchy 主题时，Claude Code、Pi、OpenCode 和 Hermes（一旦 Omarchy 已安装它）都会随之跟随。

### 你的智能体指令

适用于每个智能体的个人规则放在 `~/.agents/AGENTS.md` 中，紧挨着 `~/.agents/skills` 中的共享技能。用智能体面板中 + 旁边的文档图标打开它，或者用 `omarchy agent instructions --edit`，后者还会把它链接到每个保留其自己全局文件的 harness 中：`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`~/.pi/agent/AGENTS.md`、`~/.config/opencode/AGENTS.md`、Copilot 的 `~/.copilot/copilot-instructions.md`，等等。Crush 和 Amp 读取 `~/.config/AGENTS.md` 链接，而 omp、Kimi 和 DeepSeek Harness 直接读取 `~/.agents/AGENTS.md`。挑选默认智能体也会链接它。如果你已有的某个指令文件在尚不存在共享文件时，就会成为共享文件；否则它会作为 `.bak` 保存在链接旁边。在安装另一个智能体后，运行 `omarchy agent instructions` 重新链接。

### 智能体面板

顶栏有一个智能体图标。在你设置智能体之前，它的面板提供三种开始方式：登录 Claude、Codex、Grok、Gemini、Muse、Cursor 或 Copilot 订阅，或者在 More 下选择 OpenCode Go、MiniMax、Synthetic 或 Z.ai 编码计划；使用 Fireworks、OpenCode Zen and Go、OpenRouter 按量付费，或者在 More 下使用 DeepSeek 或 OpenCode 能登录的任何其他提供商，这些都在 OpenCode 中运行；或者运行适合你计算机的最佳模型，当有适合的模型时。 你完成的第一种会成为你的默认智能体，面板中的 + 之后会提供同样的三种方式。在那之后，面板会把每个订阅都放在一页上：每个智能体和账户及其计划、它的每个 5 小时会话限额和每周限额的计量条以及距离重置的时间（悬停可查看确切百分比），或者剩余的预付余额，位于一行轮播内容之下，那一行会轮流显示你在所有这些智能体上的使用情况，例如本周的 tokens 和你最常用的模型。在 _Make something cool_ 下，它提供用于新主题、插件、应用或游戏的入门提示词，把任务交给你的默认智能体。应用的构建方式与 Omarchy 自己的 Hype、Monologue 和 Omacut 相同，用 C++ 和 Qt Quick，遵循 omarchy-make-app 智能体技能，并且它们所需的编译器和 Qt 组件都已安装。游戏是 `~/Games/vibes` 中的单个 three.js 页面，遵循 omarchy-make-game 智能体技能，并且全都从当前主题中的一个 Game Vibes 启动器打开；它们从网络加载 three.js，所以启动时需要连接。Claude Code、Codex、Grok、Kimi、Cursor 及其 Grok Bot 额度、GitHub Copilot、Muse、Gemini（通过 Antigravity）和 Devin 开箱即用地被涵盖，并带有它们的限额，Kimchi 带有它的计划、预付额度和支出预算，而 Hermes、Mistral Vibe 和 Qwen Code 会在你使用过它们后显示它们的会话和 tokens。你通过 pi、omp 或 opencode 使用的提供商计划和密钥也会显示出来：OpenCode Zen and Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan 和 Synthetic，带有它们的限额；OpenRouter 和 DeepSeek，带有它们的预付余额；Fireworks，带有它在过去 30 天的支出。在你自己的硬件上运行的编码模型有它们自己的行，它们的 tokens 也计入总计，如[本地模型](#local-models)下所述。每个智能体只计数一次，计在向它收费的一方名下，无论你通过多少个 harness 驱动它。

左键点击栏图标或按 `Super + Ctrl + X` 打开面板，右键点击启动你的默认智能体，中键点击刷新。它背后的使用记录每 15 分钟由 `omarchy agent usage update` 重新生成，并且面板甚至可以通过同步文件夹合并来自你其他机器的使用情况。有关完整设置，参见 `$OMARCHY_PATH/shell/plugins/agents/` 下的 README。

### 多个订阅

如果你为不止一个 Claude、Codex 或 Grok 计划付费——例如一个个人 Max 和一个工作用的——Omarchy 可以让它们全部保持登录状态，并在它们之间移动。用智能体面板中的 + 添加订阅，它会就在那里引导你完成，或者用 `omarchy agent account add claude Work`（或 `codex`，或 `grok`）。同样的 + 和命令可登录 Gemini（`gemini`）和 OpenCode（`opencode`），并在 OpenCode 中保存 Fireworks（`fireworks`）或 OpenRouter（`openrouter`）API 密钥；该命令还可登录 Copilot（`copilot`）、Cursor（`cursor`）和 Muse（`muse`）。这些各自只保留一次登录。如果 CLI 缺失，它会安装它。某个提供商的第一个账户会通过你的普通浏览器登录，就在 CLI 一直查找的地方。之后的每一个都通过隐私窗口登录，所以你的浏览器已登录的账户不会被误选；在那里以你要添加的账户登录，并先关闭你已打开的任何隐私窗口。千万不要为此退出 CLI 登录：退出登录会撤销已保存的登录状态，而那个账户就必须重新添加。

要通过 SSH 把你的订阅登录信息复制到另一台 Omarchy 机器，运行 `omarchy agent account copy user@laptop`。当目标机器没有安装接收器时，发送方会提供一个临时接收器，所以较旧的 Omarchy 机器无需更新也能接收账户。已安装的接收器优先。此操作复制所有 Claude、Codex 和 Grok 订阅；添加提供商名称来选择它们，如 `omarchy agent account copy laptop claude`。账户名称和命令 ID 与源机器一致，包括目标机器上已存在的账户。如果无关的目标账户名称冲突，它们会获得数字后缀，并且设置、技能、插件和对话历史都保留在每台机器本地。

现有的目标凭据会保留。已在那里登录的源账户会同步其名称，但不会替换其凭据；其他账户会被添加到它旁边。要替换匹配账户的已保存凭据，在退出目标机器上该账户的会话后，使用 `omarchy agent account copy --replace laptop claude`。全新目标机器还会获得源机器的活动账户和切换偏好；已在使用的目标机器会保留自己的。

凭据通过 SSH 传输，并存储在目标机器的私有文件中，所以只复制到你信任的机器。这是一次性复制，不是持续同步。Codex 刷新 tokens 可能会被另一台机器轮换，使复制的登录状态需要续期；对在多台机器上同时使用而言，单独登录仍然是最可靠的选择。参见 [Codex 的账户身份验证指南](https://developers.openai.com/codex/auth/ci-cd-auth)。

每个提供商有一个账户是活动的，每个新会话都会以它开始：`cx`、`cy`、普通的 `claude`、`codex` 或 `grok`、通过 `omarchy agent` 启动的任何东西，以及在 `PATH` 上找到该 CLI 的脚本或编辑器。用 `omarchy agent account use work` 切换（并用 `omarchy agent account use main` 切回来），或者在面板中按某个账户的编号然后按 `Enter`（或点击它的星标）。正在运行的 Claude 会话也会切换，从它们下一条消息开始：每个 Claude 会话都在 `~/.claude` 中运行，那里始终保存着活动账户的登录状态。由较旧 Omarchy 在某个账户自己的文件夹中启动的 Claude 会话，会一直保持该登录状态直到退出，所以切换时会点名这些会话，并在它们消失后自行完成。正在运行的 Codex 和 Grok 会话会保持在它们启动时所用的账户上。对话历史、设置、技能和插件在各账户间共享，所以在同一文件夹中的 `claude --continue` 会在新账户上从你离开的地方继续。

当有不止一个账户时，面板会并排显示每个账户的限额，正在使用的那个上面有一个实心星标。当活动账户超过某个限额的 95% 时，Omarchy 会通知你，点击通知会切换到余量最多的账户。它永远不会自行切换。用 `omarchy agent account threshold 90` 更改阈值。如果每个账户都超过了阈值，你会收到一次通知，同时得知哪个账户最先释放出来。当活动账户距离其阈值在 15 个百分点以内时（默认阈值下为 80%），它的限额会每三分钟检查一次，而不是每 15 分钟。

`omarchy agent account list` 显示每个账户及其最新限额，`omarchy agent account remove work` 遗忘一个账户，`omarchy agent account rename primary Hey` 重命名一个账户（或点击面板中的某个账户名称）。这些命令作用于你的默认智能体的账户；要触及其他提供商，先点名它，如 `omarchy agent account use codex side`。你在 `~/.claude` 或 `~/.codex` 中已有的登录是 _Main_ 账户。Codex 的保持原地不动；Claude 的在另一个账户活动时会在它自己的文件夹中等待。闲置超过约八小时的账户可能会显示 _Sign-in required_；点击它可就在面板中重新登录该账户，或者切换到它并启动会话，后者会自行刷新登录状态。你用 `claude mcp add` 添加的 MCP 服务器能触达每个 Claude 账户，因为它们都在 `~/.claude` 中运行；对于 Codex 和 Grok，你在某个账户被添加时已有的服务器会随之带到该账户，但之后的服务器只能触达你添加它们时所在的账户。Claude Desktop 保留它自己的登录状态，而以指向 CLI 二进制文件的绝对路径配置的 Codex 或 Grok 工具不会跟随切换。显式的 `CLAUDE_CONFIG_DIR`、`CODEX_HOME` 或 `GROK_HOME` 优先于所选账户。

### 崩溃诊断

Omarchy 会监视 systemd-coredump 以发现进程崩溃。一旦你挑选了默认智能体，你的任何转储核心的程序都会带来一个 "Process crashed" 通知——点击它，崩溃就会连同 Omarchy 的 omarchy-diagnose-crash 技能一起交给你的默认智能体，该技能会引导智能体从核心转储中确立事实，并决定该崩溃是否值得向上游报告。你也可以对 `coredumpctl list` 中的任何 PID 手动运行它，使用 `omarchy agent crash <pid>`。

监视默认开启。在 _Trigger > Toggle > Crash Capture Off_ 下关闭它（或使用 `omarchy toggle crash-capture`），通知就会停止；`omarchy agent crash <pid>` 手动仍然有效。

崩溃也可以一次为一个程序静默，这就是诊断在最后提供给你的选项。`omarchy crash mute hyprland` 只停止该程序的通知，`omarchy crash mute hyprland off` 把它们带回来，而单独的 `omarchy crash mute` 列出你已静默的内容。它接受二进制文件的路径和接受其名称一样愉快，所以 `omarchy crash mute /usr/bin/hyprland` 做同样的事情。给带空格的名称加上引号，如 `omarchy crash mute 'Some App'`。其他一切仍然会通知，被静默的程序仍然会崩溃——这只是隐藏提醒，它不修复任何东西。

### 桌面应用

_Install > AI_ 菜单还包含几个图形化 AI 应用：Amp Desktop、Antigravity Desktop、ChatGPT 桌面应用、Claude 桌面应用（Anthropic 的 Linux beta 版，带有 Chat、Cowork 和 Claude Code 标签页）、用于与 xAI 的模型聊天的 Grok Bot、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexity 桌面应用和 T3 Code。Grok Bot 是桌面聊天应用。编码智能体是 `grok` 命令。

Hermes Desktop 是需要了解的那个，因为一台机器只有一个 Hermes，而它属于该应用：Hermes 只能通过该应用安装，而默认智能体运行的 `hermes` 命令也是该应用的。选择 Hermes 作为默认智能体会安装与 _Install > AI_ 条目相同的东西：该软件包，以及一个由 Hermes 自己的安装器在 `~/.hermes` 下设置的 Hermes 运行时，第一次需要几分钟。该运行时就是终端 `hermes` 命令、默认智能体和该应用全都使用的那一个 Hermes，并且它会用 `hermes update` 自我更新，而不是等待 Omarchy 发布。安装它还会把 Omarchy 主题作为名为 `omarchy` 的皮肤交给 Hermes，当你切换主题时，每个 Hermes 表面都会跟随；在 Hermes 的 Appearance 设置下或使用 `/skin` 选择另一个，如果你不希望它跟随，Omarchy 会让那个选择保持不变。在 _Remove > AI_ 下移除该应用会先关闭 Hermes，包括网关，并把该运行时一并带走，同时保留你的聊天、记忆和 Hermes 为自己编写的技能，除非你另有指示：它会询问是否也应移除该数据和你的连接设置，默认为否。

OpenClaw 的桌面体验是它的 Control UI，它作为由其自己的本地网关支持的 web 应用打开。OpenClaw 位于 `~/.openclaw` 中并自我更新：使用 Control UI 的 "Update Gateway" 按钮或运行 `openclaw update`，网关会在新版本上重启。Omarchy 只选择全新安装起始的版本。OpenClaw 也可以是你的默认智能体：用 `omarchy default agent openclaw` 选择它会在 `~/.openclaw` 中设置同一个副本，并且该智能体会打开连接到其网关的 OpenClaw 终端 UI。在 _Remove > AI_ 下移除 OpenClaw 会把网关服务和该应用一并带走，然后询问 `~/.openclaw` 是否也应移除，因为那里除了 OpenClaw 本身及其下载的插件运行时外，还保存着你的聊天和凭据；默认会保留它，再次安装 OpenClaw 时会重新拾起它。

Herdr Desktop 是 [Herdr](https://herdr.dev) 桌面应用：由空格、标签页和窗格组成的终端和编码智能体，当你关闭窗口时，它们会在其核心中继续运行。它来自 Herdr 自己的安装器而不是软件包，所以它位于 `~/.local/share/herdr-app` 中，当你尚没有核心时，会把它的核心一并放在 `~/.local/bin/herdr-core` 中，并会同时更新两者。它位于 Omarchy 在 `Super + Ctrl + Return` 上提供的 `herdr` 命令旁边，而不是替换它，并获得了该命令的直接按键：`Alt + Return` 和 `Alt + Shift + Return` 向下或向右拆分窗格，`Alt + Escape` 关闭它，`Ctrl + Alt + Arrow` 在窗格间移动，`Alt + 1..9` 和 `Alt + Left/Right` 选择标签页，而 `Alt + Up/Down` 在空格间移动。`Ctrl + 1..9` 选择空格，`Alt + Shift + Up/Down` 在智能体间步进。`Ctrl + Space` 前缀按键保持仅限终端，因为该应用无法为一个序列按住一个普通 Ctrl 键。Omarchy 把这些写入 `~/.config/herdr-app/keys.json`，而 `omarchy-refresh-herdr-app` 会把它们放回去。安装它会挑选 Herdr 的 Omarchy 主题，从那时起它会跟随你的 Omarchy 主题。Herdr 为浅色模式保留一个主题，为深色模式保留一个，所以在深色和浅色 Omarchy 主题之间切换后，再在 Herdr 的主题选择器中为另一种模式选择 Omarchy 一次。

T3 Code 从它位于 `~/.local/share/t3code` 的官方 AppImage 版本运行，而不是从软件包运行，所以它会自我更新。安装它时会询问在 Stable 还是 Nightly 频道开始；之后在 T3 Code 的设置中切换。你的线程和设置位于 `~/.t3` 中，在 _Remove > AI_ 下移除 T3 Code 会把它们一并带走。

### 本地模型

在你自己的机器上为你的编码智能体运行一个开放模型。你的提示词和代码都留在机器上；发送给模型的任何东西都不会离开它。从这里开始：

```bash
omarchy models use best text
```

这会为这台机器设置最佳文本模型，就是你的智能体使用的那类。图像、视频和音乐模型也有它们自己的最佳选择：`omarchy models use best image`、`video` 或 `music`。运行 `omarchy models use best` 查看每类为这台机器挑选的选择。

或者在智能体面板中选择 +：在 _Use a local model_ 下，它列出适合这台机器的每个编码模型，推荐的排在第一。运行这些模型的 Podman 随 Omarchy 一同提供，NVIDIA 机器上的 NVIDIA 容器工具包也一样，它为它们提供 GPU；如果其中任何一项缺失，首次设置会安装它。然后 Omarchy 会挑选这台机器的推荐模型，下载它，并启动它。预计会有数十 GB 的下载，并且当模型运行时机器的大部分内存会被占用：Flash Next 以其完整的 256K 上下文运行时用约 100 GiB。如果其他模型占有所需的内存，它会被设置为已停止状态，准备在你停掉一个后启动。模型在注销时停止；当你需要内存用于其他事情时，自己停掉它。

`omarchy models list` 显示选项，并解释为什么有些不适合。要设置另一个，运行 `omarchy models use <recipe>`。如今，`qwen3.8-flash-next-gufo` 和 `qwen3.8-27b-gufo` 可用于 128 GB Strix Halo 机器；27B 用约 40 GiB，所以它为其他工作留出了空间。在一台带有 Intel 的 Arc B390 的 64 GB 笔记本上，`qwen3.6-35b-a3b-llamacpp` 在约 30 GiB 内运行。新配方和推荐随 `omarchy update` 通过该软件包到来。

你添加的编码模型在智能体面板中获得它自己的行，就在你的订阅旁边：播放以启动它，暂停以停止它并释放其内存，Tailscale 标记以在它运行时与你 tailnet 上的其他机器共享它，以及终端按钮以在它上面打开你的智能体。它的行会实时显示下载、加载或停止，并在没有足够可用内存启动它时说明，或者在它以错误停止时链接到其日志。当多个模型能同时装进内存时，它们可以同时运行。按 Delete 删除选定的行，将模型从这台机器上移除，包括下载的全部内容；+ 可以再次设置它。从终端设置的编码模型会等在 + 下，直到你添加它，你已配对机器（`omarchy models pair <host>`）运行的模型也是如此。

你设置的每个编码模型在应用启动器中也有它自己的条目，位于该模型的名称下并带有其制造商的标志，正如登录到 Claude、Codex 或 Grok 会添加一个一样。它在该模型上打开你的智能体，如果它没有运行则先启动模型：终端会显示它正在加载，并在它准备好后交给智能体。移除模型会移除其条目。

并非每个模型都是为编码而设。图像、视频和音乐模型改为在 Fantasi 中打开，Fantasi 是 Omarchy 用于利用这台机器上运行的模型制作图片、视频和音乐的应用，并在那里或用 `omarchy models` 管理。

模型保持完全按其设置方式运行，所以 Omarchy 更新永远不会在你的智能体之下重启某个模型。当 Omarchy 有更新的运行时或更新的权重可用于你已设置的模型时，它的行会显示一个更新按钮：按下它，模型会在后台重新设置，仅下载已更改的内容，并在新版本上重启。已停止的模型仍保持停止。`omarchy models update` 从终端对每个模型做同样的事情。

从命令行，`omarchy models start <recipe>` 和 `omarchy models stop <recipe>` 做同样的事情，`omarchy models status` 显示每个模型，而 `omarchy agent --local-model <recipe>` 在 pi 中打开该模型，无论你的默认智能体是什么。要使你的本地模型成为智能体热键、Quake 控制台和 _Make something_ 打开的内容，运行 `omarchy default agent local` 或者在智能体面板中给正在运行的模型加星。pi 还会在它自己的模型选择器中列出你已设置的每个模型，以及在你已配对机器上的那些模型，所以普通的 `pi` 也能触达它们。任何与 OpenAI 兼容的客户端也可以连接：`status` 显示每个模型的地址（第一个是 `http://127.0.0.1:11435/v1`），配方名称就是模型，而密钥位于 `~/.config/omarchy/agent-local/key` 中。

`omarchy models remove <recipe>` 删除一个模型以及没有其他模型使用的下载。

第三方运行时标有其发布者。Omarchy 运行每个模型时都没有网络访问权限。

### 本地 LLM

Omarchy 推荐两种运行本地 LLM 模型的方式：LM Studio 和 Ollama。LM Studio 提供一个 GUI 界面，用于查找开放权重模型、安装它们并运行它们。这是轻松入门的好方法。Ollama 提供一个 CLI，以类似方式做到这一点。但如果你是本地模型的新手，我会从 LM Studio 开始。你可以在 Omarchy 菜单的 _Install > AI_ 下安装其中任何一个。

### Omarchy 技能

智能体技能帮助 AI 以特定方式使用特定工具，Omarchy 随附了其中七个。omarchy 技能涵盖定制系统，例如调整你的 Hyprland 配置或调整栏。omarchy-make-theme、omarchy-make-plugin、omarchy-make-app 和 omarchy-make-game 涵盖制作新东西，omarchy-contribute 涵盖向上游报告错误或发送修复，而 omarchy-diagnose-crash 则处理崩溃的核心转储。它们被符号链接到 Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` 和每个 `~/.hermes/profiles/*/skills`）以及通用 `~/.agents/skills` 位置的技能目录中，所以大多数 harness 都会自动拾取它们。你自己的某个同名技能文件夹优先。

但你应该把这些技能视为实验性的。不同的模型会以不同的效果使用它。最好先在计划模式下运行，这样你就能有个概念，了解智能体想要更改什么。然后准备好回滚更改，甚至在智能体把一切搞得一团糟时，调用 `omarchy reinstall configs`。
