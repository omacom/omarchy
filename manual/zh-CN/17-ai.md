### 安装和更新智能体

Hermes 除外，这些智能体使用 mise 的延迟安装：首次启动时安装 CLI，之后启动时直接复用。mise 还会每四个小时最多检查一次已安装智能体是否有新版本，就在启动前或在 shell 提示符下于后台检查。如果更新失败或你处于离线状态，则运行已安装的版本。`omarchy update` 会随 Omarchy 的其余部分一起更新已安装的智能体，而 `mup` 只更新由 mise 管理的工具。

智能体自身的更新程序，例如 `claude update`、`codex update`，或应用中的更新按钮，不会更新由 mise 管理的安装。`codex update` 会失败，而 `claude update` 可能报告成功，却安装了一个 mise 不跟踪的独立副本。如果你更愿意使用智能体原生的安装程序和更新程序，请将其添加到 `disable_tools`；参见[预装的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

要在需要之前安装所有已配置的延迟工具，请运行 `mise install --include-lazy`。这包括 Omarchy 的其他默认 CLI 工具以及这些智能体。有关安装单个工具或使用你自己的安装，参见[预装的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

`grok` 通过 mise 的第一方 `grok` 包安装，与 `claude` 和 `codex` 相同。运行 `grok`，或在 _Setup > Defaults > Agent_ 下选择它。跳过 x.ai 上的 `curl | bash` 安装程序。那条路径会在 `~/.grok/bin` 中放入第二个副本，将其前置到 `PATH` 上，并覆盖 Omarchy 的包装器。

`dsh` 会在 `127.0.0.1:3080` 上打开其浏览器 UI，并以启动目录作为默认工作区。其浏览器 UI 不接受起始提示词，因此 `omarchy agent prompt` 会打开它，并将提示词放到你的剪贴板上以便粘贴。Omarchy 以 DeepSeek 的免审批权限预设启动它。DeepSeek Harness 在你使用其官方模型 API 时会将会话日志上传到 DeepSeek；在其浏览器 UI 的 _Settings > General > Upload Session Log_ 下关闭该功能。你发送给它的反馈也会随会话一起上传，除非你使用 `DSH_TELEMETRY_MODE=DISABLED` 启动它。

### 默认智能体

使用 `omarchy default agent <name>` 或在 Omarchy 菜单（`Super + Space`）的 _Setup > Defaults > Agent_ 下选择你的默认智能体。如果该智能体尚未安装，选择它会先安装它。全新的 Omarchy 会通过一次性通知邀请你做出此选择。

选择 Claude 还会尝试为 Chromium、Chrome、Brave、Brave Origin 和 Edge 设置其浏览器扩展。该扩展的设置适用于所有用户，可能会要求输入你的系统密码；取消或扩展安装失败仍然会选择并启动 Claude。重启你的浏览器，如有提示则启用该扩展，并登录 Claude 以完成连接。在 Claude 中运行 `/chrome` 以检查连接。Firefox 和 Zen 不支持此扩展。如果在此设置添加之前 Claude 已经是你的默认项，请再次选择它以安装该扩展。

选择之后，`Super + Shift + Ctrl + A` 会在一个专用终端窗口中启动默认智能体（如果你尚未选择，则会调出选择器）。你也可以使用 `omarchy agent prompt "Review this project"` 让它直接开始执行一项任务。Freebuff 和 DeepSeek Harness 不接受起始提示词，因此它们会打开并将提示词放到你的剪贴板上以便粘贴。以这种方式启动的智能体会以各自的“不要停下来询问”模式无人值守地运行，所以要做好它们真的会动手做事的准备！MiniMax Code 的交互式会话没有这种模式，因此它会像往常一样请求权限。而且，由于智能体拒绝记住对你的主目录的信任，从 `$HOME` 启动的会话会改为在 `~/Work` 中开始。

也有终端快捷方式：`a` 会在当前终端中内联运行默认智能体，而 `c`、`cx` 和 `cy` 则直接启动 OpenCode、Claude Code 和 Codex（同样处于自动批准模式）。主题更改也会同步到智能体：当你切换 Omarchy 主题时，Claude Code、Pi、OpenCode 和 Hermes（一旦 Omarchy 安装了它）都会跟随变化。

### 智能体面板

顶栏有一个智能体图标。在你设置智能体之前，它的面板会引导你登录 Claude、Codex 或 Grok，第一个登录的会成为你的默认智能体。之后，该面板会将每个订阅都放在一个页面上：每个智能体和账户及其套餐、其 5 小时会话限额和每周限额各自的计量条以及距离重置的时间（悬停可查看确切百分比），或剩余的预付余额，位于一行轮换显示的内容下方，该行会轮换显示你在所有智能体上的使用情况，例如本周的 tokens 和你最常用的模型。在 _Make something_ 下，它提供了用于新主题、插件或应用的起始提示词，可将任务交给你的默认智能体。应用的构建方式与 Omarchy 自己的 Hype、Monologue 和 Omacut 相同，使用 C++ 和 Qt Quick，遵循 omarchy-app 智能体技能，并且它们所需的编译器和 Qt 组件都已预装。Claude Code、Codex、Grok、Kimi、Cursor 及其 Grok Bot 额度、GitHub Copilot、Muse、Antigravity、Kimchi 和 Devin 开箱即用地涵盖在内，并带有各自的限额，而 Hermes、Mistral Vibe 和 Qwen Code 会在你使用过后显示它们的会话和 tokens。你通过 pi、omp 或 opencode 使用的提供商套餐和密钥也会显示出来：OpenCode Zen 和 Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan 和 Synthetic，带有各自的限额；Fireworks、OpenRouter 和 DeepSeek，带有各自的预付余额；以及你在自己硬件上运行的模型，位于 Local models 下。每个智能体只计数一次，归在向你收费的一方名下，无论你通过多少个 harness 来驱动它。

左键单击顶栏图标打开面板，右键单击启动你的默认智能体。其背后的使用记录每 15 分钟由 `omarchy agent usage-update` 重新生成一次，并且该面板甚至可以通过同步文件夹合并来自你其他机器的使用情况。有关完整设置，参见 `$OMARCHY_PATH/shell/plugins/agents/` 下的 README。

### 多个订阅

如果你付费订购了多个 Claude、Codex 或 Grok 套餐——比如一个个人 Max 和一个工作套餐——Omarchy 可以让它们全部保持登录状态，并在它们之间切换。使用智能体面板中的 + 添加订阅，它会当场引导你完成，或者使用 `omarchy agent account add claude Work`（或 `codex`，或 `grok`）。如果 CLI 缺失，它会安装它。某个提供商的第一个账户通过你的普通浏览器登录，就在 CLI 一直查找的位置。之后的每一个账户都通过隐私窗口登录，这样你浏览器已登录的账户就不会被误选；在那里以你要添加的账户登录，并先关闭你已打开的任何隐私窗口。千万不要为此退出 CLI 登录：退出登录会撤销已保存的登录信息，该账户将不得不重新添加。

要通过 SSH 将你的订阅登录信息复制到另一台 Omarchy 机器，请运行 `omarchy agent account copy user@laptop`。当目标机器未安装接收端时，发送方会提供一个临时接收端，因此较旧的 Omarchy 机器无需更新即可接收账户。已安装的接收端优先。此命令会复制所有 Claude、Codex 和 Grok 订阅；添加提供商名称可选择它们，例如 `omarchy agent account copy laptop claude`。账户名称和命令 ID 与源机器一致，包括目标机器上已存在的账户。如果无关的目标账户名称冲突，它们会获得数字后缀，并且设置、技能、插件和对话历史都保留在每台机器本地。

目标机器上现有的凭据会保留。已在那里登录的源账户会同步其名称，但不会替换其凭据；其他账户则会一同添加进来。要替换匹配账户的已保存凭据，请在目标机器上退出该账户的会话后，使用 `omarchy agent account copy --replace laptop claude`。全新的目标机器还会获得源机器的活动账户和切换偏好；已建立的目标机器会保留自己的。

凭据通过 SSH 传输，并存储在目标机器的私有文件中，因此只能复制到你信任的机器。这是一次性复制，不是持续同步。Codex 刷新令牌可能会被另一台机器轮换，导致复制的登录信息需要续期；对于在多台机器上同时使用，单独登录仍然是最可靠的选择。参见[Codex 的账户身份验证指南](https://developers.openai.com/codex/auth/ci-cd-auth)。

每个提供商有一个活动账户，每个新会话都会以它开始：`cx`、`cy`、普通的 `claude`、`codex` 或 `grok`、通过 `omarchy agent` 启动的任何内容，以及在 `PATH` 上找到 CLI 的脚本或编辑器。使用 `omarchy agent account use work` 切换（使用 `omarchy agent account use main` 切回），或在面板中按某个账户的数字然后按 `Enter`（或单击其 Use 按钮）。已在运行的会话会继续使用它们启动时所用的账户。对话历史、设置、技能和插件在账户之间共享，因此在同一文件夹中执行 `claude --continue` 会在新账户上从你离开的地方继续。

拥有多个账户时，面板会并排显示每个账户的限额，并标记活动账户。默认情况下，当活动账户超过某个限额的 95% 时，Omarchy 会通知你，单击通知会切换到余量最多的账户。将鼠标悬停在面板中的账户行上，然后单击 Use 旁边出现的 Autoswitch（或按 `m`），或运行 `omarchy agent account mode auto`，即可改让它自行切换；启用时，Autoswitch 会取代 Use 的位置，再次单击它会恢复为通知。添加数字以更改阈值，例如 `omarchy agent account mode auto 90`。如果每个账户都超过阈值，你会收到一次通知，并告知哪个账户最先释放额度。当活动账户距离其阈值在 15 个百分点以内（默认阈值下为 80%）时，其限额会每三分钟检查一次，而不是每 15 分钟。

`omarchy agent account list` 会显示每个账户及其最新限额，`omarchy agent account remove work` 会忘记一个账户，`omarchy agent account rename primary Hey` 会重命名一个账户（或单击面板中的账户名称）。这些命令作用于你默认智能体的账户；要访问其他提供商，请先命名它，例如 `omarchy agent account use codex side`。你原本在 `~/.claude` 或 `~/.codex` 中已有的登录是 _Main_ 账户，并保留在原处。未使用超过约八小时的账户可能会显示 _Sign-in required_；单击它可直接在面板中为该账户重新登录，或在其中启动一个会话，它会自行刷新登录。添加账户时你拥有的 MCP 服务器会随之转移到该账户，但之后使用 `claude mcp add` 添加的服务器只会到达你添加它们时所在的账户。Claude Desktop 和使用 CLI 二进制文件绝对路径配置的工具不会跟随切换。显式的 `CLAUDE_CONFIG_DIR`、`CODEX_HOME` 或 `GROK_HOME` 优先于所选账户。

### 崩溃诊断

Omarchy 监视 systemd-coredump 中的进程崩溃。当某个进程出现段错误时，你会收到一个 "Process crashed" 通知——单击它，崩溃信息便会连同 Omarchy 的 diagnose-crash 技能一同交给你的默认智能体，该技能会引导智能体从核心转储中查明事实，并决定该崩溃是否值得向上游报告。你也可以使用 `omarchy agent crash <pid>` 针对 `coredumpctl list` 中的任意 PID 手动运行它。

该监视默认开启。在 _Trigger > Toggle > Crash Capture_ 下关闭它（或使用 `omarchy toggle crash-capture`），通知便会停止；`omarchy agent crash <pid>` 仍然可以手动使用。

崩溃也可以按单个程序静默，这正是诊断最后会向你提供的选项。`omarchy crash mute hyprland` 会仅停止该程序的通知，`omarchy crash mute hyprland off` 会恢复通知，而单独执行 `omarchy crash mute` 会列出你已静默的内容。它接受二进制文件的路径，就像接受其名称一样，因此 `omarchy crash mute /usr/bin/hyprland` 效果相同。为包含空格的名称加引号，例如 `omarchy crash mute 'Some App'`。其他所有内容仍会通知，被静默的程序仍会崩溃——这会隐藏提醒，不会修复任何问题。

### 桌面应用

_Install > AI_ 菜单还包含一些图形化 AI 应用：ChatGPT 桌面应用、Claude 桌面应用（Anthropic 的 Linux beta 版，带有 Chat、Cowork 和 Claude Code 标签页）、用于与 xAI 模型聊天的 Grok Bot、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexity 桌面应用和 T3 Code。Grok Bot 是桌面聊天应用。编程智能体是 `grok` 命令。

Hermes Desktop 是需要了解的那个，因为一台机器只有一个 Hermes，而它属于该应用：Hermes 只通过该应用安装，而默认智能体运行的 `hermes` 命令也是该应用的。将 Hermes 选为默认智能体会安装与 _Install > AI_ 条目相同的内容：该软件包，以及由 Hermes 自己的安装程序在 `~/.hermes` 下设置的 Hermes 运行时，首次安装需要几分钟。该运行时是终端 `hermes` 命令、默认智能体和应用共同使用的那一个 Hermes，它通过 `hermes update` 自行更新，而不是等待 Omarchy 发布新版本。安装它还会将 Omarchy 主题作为名为 `omarchy` 的皮肤交给 Hermes，当你切换主题时，每个 Hermes 界面都会跟随；在 Hermes 的 Appearance 设置下或使用 `/skin` 选择其他皮肤，如果你不想它跟随，Omarchy 不会干涉该选择。在 _Remove > AI_ 下移除该应用会先关闭 Hermes，包括网关，并带走该运行时，并保留你的聊天、记忆和 Hermes 为自己编写的技能，除非你另有指示：它会询问是否也应删除该数据和你的连接设置，默认回答为否。

OpenClaw 的桌面体验是其 Control UI，它作为由其自己的本地网关支持的 Web 应用打开。OpenClaw 位于 `~/.openclaw` 并自行更新：使用 Control UI 的 "Update Gateway" 按钮或运行 `openclaw update`，网关便会在新版本上重启。Omarchy 只选择全新安装所起始的版本。在 _Remove > AI_ 下移除 OpenClaw 会带走网关服务和应用，然后询问是否也应删除 `~/.openclaw`，因为那里保存着你的聊天和凭据，以及 OpenClaw 本身和它下载的插件运行时；默认保留它，再次安装 OpenClaw 时会重新使用它。

Herdr Desktop 是 [Herdr](https://herdr.dev) 桌面应用：空间、标签页以及终端和编程智能体的窗格，当你关闭窗口时，它们会在其核心中继续运行。它来自 Herdr 自己的安装程序而非软件包，因此它位于 `~/.local/share/herdr-app`，当你尚无核心时，它会在 `~/.local/bin/herdr-core` 中附带其核心，并同时更新自身。它位于 Omarchy 在 `Super + Ctrl + Return` 上提供的 `herdr` 命令旁边，而不是替换它，并获得该命令的直接按键：`Alt + Return` 和 `Alt + Shift + Return` 向下或向右拆分窗格，`Alt + Escape` 关闭它，`Ctrl + Alt + Arrow` 在窗格之间移动，`Alt + 1..9` 和 `Alt + Left/Right` 选择标签页，`Alt + Up/Down` 在空间之间移动。`Ctrl + 1..9` 选择空间，`Alt + Shift + Up/Down` 在智能体之间步进。`Ctrl + Space` 前缀按键仅保留给终端，因为该应用无法为一个序列按住普通的 Ctrl 键。Omarchy 将这些写入 `~/.config/herdr-app/keys.json`，而 `omarchy-refresh-herdr-app` 会把它们放回去。安装它会选择 Herdr 的 Omarchy 主题，从那时起它会跟随你的 Omarchy 主题。Herdr 为浅色模式保留一个主题，为深色模式保留一个主题，因此在深色和浅色 Omarchy 主题之间切换后，再在 Herdr 的主题选择器中选择一次 Omarchy，以应用于另一种模式。

T3 Code 从其位于 `~/.local/share/t3code` 的官方 AppImage 发行版运行，而非从软件包运行，因此它自行更新。安装它时会询问是启动 Stable 还是 Nightly 频道；之后可在 T3 Code 的设置中切换。你的线程和设置位于 `~/.t3`，在 _Remove > AI_ 下移除 T3 Code 会带走它们。

### 本地模型

在你自己的机器上为你的编程智能体运行开放模型。你的提示词和代码保留在机器上；发送给模型的任何内容都不会离开它。从以下开始：

```bash
omarchy agent local use best
```

或者，在顶栏的智能体面板中，选择 + 然后选择 Local AI，当有适合这台机器的模型时它会显示出来。首次使用时，这会安装 Podman，它运行这些模型，而在 NVIDIA 机器上还会安装 NVIDIA 的容器工具包，它为它们提供 GPU。Omarchy 然后会为这台机器挑选推荐模型，下载它并启动它。预计下载量为数十 GB，并且在模型运行时机器的大部分内存会被占用：Flash Next 在其完整的 256K 上下文下会使用约 100 GiB。如果其他模型占用了它所需的内存，它会设置为已停止状态，一旦你停止其中一个便可启动。该模型在注销时停止；当你需要内存用于其他用途时，请自行停止它。

`omarchy agent local list` 会显示选项并解释为什么某些选项不适合。要设置另一个，请运行 `omarchy agent local use <recipe>`。如今，`qwen3.8-flash-next-gufo` 和 `qwen3.8-27b-gufo` 可用于 128 GB Strix Halo 机器；27B 需要约 40 GiB，因此它会为其他工作留出空间。新配方和推荐会随 `omarchy update` 通过该软件包到达。

你设置的每个模型在智能体面板中都拥有自己的一行，位于你的订阅旁边：播放按钮启动它，暂停按钮停止它并释放其内存，终端按钮可在它上面打开你的智能体。当它们能同时容纳于内存中时，多个模型可同时运行；如果某个模型容纳不下，Omarchy 会指出要停止哪个正在运行的模型。拖动行可重新排序，按下 Delete 可删除所选行对应的模型及其下载。

在命令行中，`omarchy agent local start <recipe>` 和 `omarchy agent local stop <recipe>` 功能相同，`omarchy agent local status` 显示每个模型，而 `omarchy agent --local` 会在你最后启动的模型上打开你的默认智能体（如果你的默认智能体无法使用本地模型，则打开 pi）。任何兼容 OpenAI 的客户端也可以连接：`status` 显示每个模型的地址（第一个是 `http://127.0.0.1:11435/v1`），配方名称即模型，密钥位于 `~/.config/omarchy/agent-local/key` 中。

`omarchy agent local remove <recipe>` 会删除一个模型以及没有其他模型使用的下载。

第三方运行时标注了其发布者。Omarchy 在无网络访问的情况下运行每个模型。

### 本地 LLM

Omarchy 推荐两种运行本地 LLM 模型的方式：LM Studio 和 Ollama。LM Studio 提供了 GUI 界面，用于查找开放权重模型、安装它们并运行它们。它是一个轻松入门的好方法。Ollama 提供了 CLI 以类似方式完成此事。但如果你是本地模型新手，我会从 LM Studio 开始。你可以在 Omarchy 菜单的 _Install > AI_ 下安装其中任何一个。

### Omarchy 技能

智能体技能帮助 AI 以特定方式使用特定工具，而 Omarchy 附带一个用于定制系统的默认技能。比如调整你的 Hyprland 配置、调整顶栏，甚至从头创建一个新主题。它被符号链接到 Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` 和每个 `~/.hermes/profiles/*/skills`）以及通用 `~/.agents/skills` 位置的技能目录中，因此大多数 harness 会自动拾取它。

但你应该将此技能视为实验性的。不同的模型会以不同的效果使用它。最好先在计划模式下运行，这样你就能了解智能体想要更改什么。然后准备好回滚更改，甚至在智能体把一切弄得一团糟时调用 `omarchy reinstall configs`。
