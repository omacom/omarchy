### 安装和更新智能体

除 Hermes 和 OpenClaw 外，这些智能体都使用 mise 的懒安装：首次启动时安装 CLI，后续启动时复用它。mise 还会至多每四小时检查一次已安装智能体是否有新版本，就在它启动之前，或者在 shell 提示符下在后台检查。如果该更新失败或者你离线，就会运行已安装的版本。`omarchy update` 会随 Omarchy 的其余部分一起更新已安装的智能体，而 `mup` 只更新由 mise 管理的工具。

智能体自己的更新程序，例如 `claude update`、`codex update`，或者应用中的更新按钮，不会更新由 mise 管理的安装。`codex update` 会失败，而 `claude update` 可能报告成功，却安装了一个 mise 不跟踪的单独副本。如果你宁愿使用智能体原生的安装程序和更新程序，把它加到 `disable_tools` 中；参见[预装的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

要在需要之前安装所有已配置的懒工具，运行 `mise install --include-lazy`。这包括 Omarchy 的其他默认 CLI 工具以及这些智能体。有关安装单个工具或使用你自己的安装，参见[预装的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

`grok` 是通过 mise 的第一方 `grok` 包安装的，和 `claude` 与 `codex` 一样。运行 `grok`，或者在 _Agent > Harness_ 下选择它。跳过 x.ai 上的 `curl | bash` 安装程序。那条路径会在 `~/.grok/bin` 中放第二个副本，把它前置到 `PATH` 上，并覆盖 Omarchy 的包装器。

`dsh` 会在 `127.0.0.1:3080` 上打开其浏览器 UI，并把启动目录作为其默认工作区。它的浏览器 UI 不接受起始提示，所以 `omarchy agent prompt` 打开它时，会把提示放在你的剪贴板上供你粘贴。Omarchy 以 DeepSeek 的无批准权限预设启动它。当你使用 DeepSeek 的官方模型 API 时，DeepSeek Harness 会把会话日志上传到 DeepSeek；在其浏览器 UI 的 _Settings > General > Upload Session Log_ 下关闭这一项。你发送给它的反馈也会随会话一起上传，除非你以 `DSH_TELEMETRY_MODE=DISABLED` 启动它。

### 默认智能体

用 `omarchy default agent <name>` 或者在 Omarchy 菜单（`Super + Space`）的 _Agent > Harness_ 下选择你的默认智能体。如果该智能体尚未安装，选择它会先安装它，而且它还会在应用启动器中获得自己的启动器，紧挨着 Agent。全新的 Omarchy 会通过一次性通知邀请你做出这个选择。

选择 Claude 还会尝试为 Chromium、Chrome、Brave、Brave Origin 和 Edge 设置其浏览器扩展。该扩展设置适用于所有用户，并且可能会要求你的系统密码；取消或者扩展安装失败，仍然会选择并启动 Claude。重启你的浏览器，在提示时启用该扩展，并登录 Claude 以完成连接。在 Claude 中运行 `/chrome` 检查连接。Firefox 和 Zen 不支持这个扩展。如果在加入此设置之前 Claude 已经是你的默认项，再次选择它以安装该扩展。

选好之后，`Super + Shift + Ctrl + A` 会在一个专用终端窗口中启动默认智能体（或者如果你还没选，就会调出选择器）。你也可以用 `omarchy agent prompt "Review this project"` 让它直接进入一项任务。Freebuff 和 DeepSeek Harness 不接受起始提示，所以它们打开时改为把提示放在你的剪贴板上供你粘贴。以这种方式启动的智能体会以它们各自的不要停下来询问模式无人值守地运行，所以要做好它们真的会动手做事的准备！MiniMax Code 的交互式会话没有这种模式，所以它会像往常一样请求权限。而且由于智能体拒绝记住对你的主目录的信任，从 `$HOME` 启动时改为在 `~/Work` 中开始。

还有终端快捷方式：`a` 在当前终端中内联运行默认智能体，而 `c`、`cx` 和 `cy` 直接启动 OpenCode、Claude Code 和 Codex（同样以它们的自动批准模式）。主题变化也会同步到智能体：当你切换 Omarchy 主题时，Claude Code、Pi、OpenCode 和 Hermes（一旦 Omarchy 已安装它）都会跟随。

### 你的智能体指令

适用于每个智能体的个人规则放在 `~/.agents/AGENTS.md` 中，紧挨着 `~/.agents/skills` 中的共享技能。在 _Agent > Instructions_ 下打开它，它还会把该文件链接到每个保留其自己全局文件的 harness 中：`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`~/.pi/agent/AGENTS.md`、`~/.config/opencode/AGENTS.md`、Copilot 的 `~/.copilot/copilot-instructions.md`，等等。Crush 和 Amp 读取 `~/.config/AGENTS.md` 链接，而 omp、Kimi 和 DeepSeek Harness 直接读取 `~/.agents/AGENTS.md`。选择一个默认智能体也会链接它。如果你已经有了一个指令文件，且尚不存在共享文件，它就会成为共享文件；否则它会作为 `.bak` 保存在链接旁边。在安装另一个智能体后，运行 `omarchy agent instructions` 重新链接。

### 智能体面板

顶栏有一个智能体图标。在你设置智能体之前，它的面板会引导你登录 Claude、Codex 或 Grok，第一个登录的会成为你的默认智能体。在那之后，该面板把每个订阅都放在一页上：每个智能体和账户及其套餐、每个 5 小时会话和每周限额的计量条以及距离重置的时间（悬停可看确切百分比），或者剩余的预付余额，在一行轮换显示你全部使用情况的内容下方，例如本周的 tokens 和你最常用的模型。在 _Make something cool_ 下，它提供用于新主题、插件、应用或游戏的入门提示，把任务交给你的默认智能体。应用的构建方式和 Omarchy 自己的 Hype、Monologue 和 Omacut 一样，使用 C++ 和 Qt Quick，遵循 omarchy-make-app 智能体技能，而且它们所需的编译器和 Qt 组件都已安装好。游戏是 `~/Games/vibes` 中的单个 three.js 页面，遵循 omarchy-make-game 智能体技能，全都从当前主题中的一个 Game Vibes 启动器打开；它们从网上加载 three.js，所以启动时需要连接。Claude Code、Codex、Grok、Kimi、Cursor 及其 Grok Bot 配额、GitHub Copilot、Muse、Antigravity 和 Devin 开箱即用地被涵盖并带有限额，Kimchi 带有其套餐、预付额度和支出预算，而 Hermes、Mistral Vibe 和 Qwen Code 一旦你使用过它们，就会显示它们的会话和 tokens。你通过 pi、omp 或 opencode 使用的提供商套餐和密钥也会出现：OpenCode Zen 和 Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan 和 Synthetic，带有限额；OpenRouter 和 DeepSeek，带有其预付余额；Fireworks，带有其过去 30 天的支出。你在自己硬件上运行的模型的 tokens 也计入总计；模型本身有自己的面板，在[本地模型](#local-models)下有说明。每个智能体只计数一次，按向它计费的一方计算，无论你通过多少个 harness 驱动它。

左键点击栏图标或按 `Super + Ctrl + X` 打开面板，右键点击启动你的默认智能体，中键点击刷新。其背后的使用记录每 15 分钟由 `omarchy agent usage update` 重新生成，而且该面板甚至可以通过同步文件夹合并来自你其他机器的使用情况。有关完整设置，参见 `$OMARCHY_PATH/shell/plugins/agents/` 下的 README。

### 多个订阅

如果你付费购买了不止一个 Claude、Codex 或 Grok 套餐——比如一个个人 Max 和一个工作套餐——Omarchy 可以让它们全部保持登录，并在它们之间切换。用智能体面板中的 + 添加订阅，它会在那里直接引导你完成，或者用 `omarchy agent account add claude Work`（或 `codex`，或 `grok`）。如果缺失，它会安装 CLI。某个提供商的第一个账户会通过你的普通浏览器登录，正是 CLI 一直查看的位置。此后的每一个都通过隐私窗口登录，这样你的浏览器已经登录的账户不会被误选；在那里登录为你要添加的账户，并且先关闭你已经打开的任何隐私窗口。切勿为此注销 CLI：注销会撤销已保存的登录，该账户将不得不重新添加。

要通过 SSH 把你的订阅登录复制到另一台 Omarchy 机器，运行 `omarchy agent account copy user@laptop`。当目的地没有安装接收器时，发送方会提供一个临时接收器，所以较旧的 Omarchy 机器无需更新就能接收账户。已安装的接收器优先。这会复制所有 Claude、Codex 和 Grok 订阅；添加提供商名称来选择它们，如 `omarchy agent account copy laptop claude`。账户名称和命令 ID 与源一致，包括目的地已存在的账户。无关的目的地账户如果名称冲突，会获得数字后缀，设置、技能、插件和对话历史则保留在每台机器本地。

已存在的目的地凭据会被保留。对于已在那里登录的源账户，其名称会被同步但不会替换其凭据；其他账户会被添加到它旁边。要替换匹配账户的已保存凭据，在退出目的地该账户的会话后，使用 `omarchy agent account copy --replace laptop claude`。全新的目的地还会获得源的活动账户和切换偏好；已有基础的目的地保留它自己的。

凭据通过 SSH 传输，并存储在目的地的私有文件中，所以只复制到你信任的机器。这是一次性复制，不是持续同步。Codex 刷新 tokens 可能被另一台机器轮换，导致复制的登录需要续期；在多台机器上同时使用时，单独登录仍是最可靠的选择。参见 [Codex 的账户身份验证指南](https://developers.openai.com/codex/auth/ci-cd-auth)。

每个提供商有一个账户是活动的，每个新会话都以它开始：`cx`、`cy`、普通的 `claude`、`codex` 或 `grok`、通过 `omarchy agent` 启动的任何东西，以及在 `PATH` 上找到 CLI 的脚本或编辑器。用 `omarchy agent account use work` 切换（用 `omarchy agent account use main` 切换回来），或者在面板中按一个账户的数字然后按 `Enter`（或点击它的 Use 按钮）。正在运行的 Claude 会话也会切换，从它们的下一条消息开始：每个 Claude 会话都在 `~/.claude` 中运行，其中始终保存着活动账户的登录。由较旧 Omarchy 在账户自己的文件夹中启动的 Claude 会话，会保留该登录直到退出，所以切换会点名那些会话，并在它们消失后自行完成。正在运行的 Codex 和 Grok 会话会一直停留在它们开始时用的账户上。对话历史、设置、技能和插件在账户之间共享，所以在同一文件夹中 `claude --continue` 会在新账户上从你离开的地方继续。

当有不止一个账户时，面板会并排显示每个账户的限额，并标记活动的那个。默认情况下，当活动账户超过限额的 95% 时，Omarchy 会通知你，点击通知会切换到余量最多的账户。把指针悬停在面板中某个账户的行上，点击出现在 Use 旁边的 Autoswitch（或按 `m`），或者运行 `omarchy agent account mode auto`，让它自行切换；启用时 Autoswitch 会取代 Use，再次点击它会回到通知。添加一个数字来更改阈值，如 `omarchy agent account mode auto 90`。如果每个账户都超过了阈值，你会听到一次，附带哪个账户最先腾出。当活动账户距离其阈值在 15 点以内（默认时为 80%）时，其限额会每三分钟检查一次，而不是每 15 分钟。

`omarchy agent account list` 显示每个账户及其最新限额，`omarchy agent account remove work` 删除一个，`omarchy agent account rename primary Hey` 重命名一个（或点击面板中某个账户的名称）。这些命令作用于你的默认智能体的账户；要访问另一个提供商，先点名它，如 `omarchy agent account use codex side`。你已经在 `~/.claude` 或 `~/.codex` 中已有的登录是 _Main_ 账户。Codex 的账户留在原处；Claude 的账户在另一个账户活动时，会等在它自己的文件夹中。一个未使用超过约八小时的账户可能会显示 _Sign-in required_；点击它直接在面板中重新登录该账户，或者切换到它并启动一个会话，它会自行刷新登录。你用 `claude mcp add` 添加的 MCP 服务器会触及每个 Claude 账户，因为它们都在 `~/.claude` 中运行；对于 Codex 和 Grok，在添加账户时你已有的服务器会随之进入该账户，但之后添加的只会触及你添加它们时所在的账户。Claude Desktop 保留它自己的登录，而且用 CLI 二进制文件的绝对路径配置的 Codex 或 Grok 工具不会跟随切换。显式的 `CLAUDE_CONFIG_DIR`、`CODEX_HOME` 或 `GROK_HOME` 优先于选定的账户。

### 崩溃诊断

Omarchy 监视 systemd-coredump 的进程崩溃。一旦你选定了默认智能体，你的任何转储了 core 的程序都会带来一个 "Process crashed" 通知——点击它，崩溃就会连同 Omarchy 的 omarchy-diagnose-crash 技能一起交给你的默认智能体，该技能会引导智能体从 core dump 查明事实，并决定该崩溃是否值得向上游报告。你也可以用 `omarchy agent crash <pid>` 手动针对 `coredumpctl list` 中的任何 PID 运行它。

监视默认开启。在 _Trigger > Toggle > Crash Capture Off_ 下关闭它（或用 `omarchy toggle crash-capture`），通知就会停止；`omarchy agent crash <pid>` 仍然可以手动工作。

崩溃也可以一次为一个程序静音，这正是诊断在最后向你提供的。`omarchy crash mute hyprland` 只停止该程序的通知，`omarchy crash mute hyprland off` 把它们带回来，而单独的 `omarchy crash mute` 会列出你已静音的内容。它既接受二进制文件路径，也同样乐意接受其名称，所以 `omarchy crash mute /usr/bin/hyprland` 做同样的事。为包含空格的名称加引号，如 `omarchy crash mute 'Some App'`。其他一切仍会通知，而且被静音的程序仍会崩溃——这只是隐藏提醒，它不修复任何东西。

### 桌面应用

_Install > AI_ 菜单还带了几个图形 AI 应用：Amp Desktop、Antigravity Desktop、ChatGPT desktop app、Claude desktop app（Anthropic 的 Linux beta 版，带有 Chat、Cowork 和 Claude Code 标签页）、用于与 xAI 的模型聊天的 Grok Bot、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexity desktop app 和 T3 Code。Grok Bot 是桌面聊天应用。编程智能体是 `grok` 命令。

Hermes Desktop 是需要了解的那一个，因为一台机器只有一个 Hermes，而它是属于该应用的：Hermes 只通过该应用安装，而默认智能体运行的 `hermes` 命令是该应用的。把 Hermes 选为默认智能体会安装 _Install > AI_ 条目安装的相同东西：该软件包，以及一个由 Hermes 自己的安装程序在 `~/.hermes` 下设置的 Hermes 运行时，第一次需要几分钟。这个运行时就是终端 `hermes` 命令、默认智能体和该应用全都使用的唯一 Hermes，并且它会用 `hermes update` 自我更新，而不是等待 Omarchy 发布。安装它还会把 Omarchy 主题作为名为 `omarchy` 的皮肤交给 Hermes，每个 Hermes 界面切换主题时都会跟随；在 Hermes 的 Appearance 设置下或用 `/skin` 选择另一个，如果你宁愿它不跟随，Omarchy 会让那个选择保持不变。在 _Remove > AI_ 下移除该应用，会先关闭 Hermes，包括网关，并把该运行时一起带走，并保留你的聊天、记忆和 Hermes 为自己编写的技能，除非你告诉它不保留：它会问，默认答否，那些数据和你的连接设置是否也应该去掉。

OpenClaw 的桌面体验是其 Control UI，它作为由其自己的本地网关支持的 web 应用打开。OpenClaw 住在 `~/.openclaw` 中，并会自我更新：使用 Control UI 的 "Update Gateway" 按钮或运行 `openclaw update`，网关会在新版本上重启。Omarchy 只选择全新安装从哪个发行版开始。OpenClaw 也可以是你的默认智能体：在 _Agent > Harness_ 下选择它会设置 `~/.openclaw` 中的同一副本，而智能体会打开连接到其网关的 OpenClaw 终端 UI。在 _Remove > AI_ 下移除 OpenClaw，会把网关服务和该应用一起带走，然后询问是否也去掉 `~/.openclaw`，因为那里保存着你的聊天和凭据，还有 OpenClaw 本身及其下载的插件运行时；默认保留它，再次安装 OpenClaw 会把它接回来。

Herdr Desktop 是 [Herdr](https://herdr.dev) 桌面应用：由终端和编程智能体组成的空间、标签页和窗格，当你关闭窗口时，它们在其核心中继续运行。它来自 Herdr 自己的安装程序而不是软件包，所以它住在 `~/.local/share/herdr-app` 中，当你还没有时，会在 `~/.local/bin/herdr-core` 中带来其核心，并自我更新两者。它位于 Omarchy 在 `Super + Ctrl + Return` 上提供的 `herdr` 命令旁边，而不是取代它，并获得该命令的直接按键：`Alt + Return` 和 `Alt + Shift + Return` 向下或向右拆分窗格，`Alt + Escape` 关闭它，`Ctrl + Alt + Arrow` 在窗格间移动，`Alt + 1..9` 和 `Alt + Left/Right` 选择标签页，`Alt + Up/Down` 在空间之间移动。`Ctrl + 1..9` 选择空间，`Alt + Shift + Up/Down` 在智能体之间步进。`Ctrl + Space` 前缀键保持仅供终端使用，因为该应用无法为一个序列按住普通的 Ctrl 键。Omarchy 把这些写入 `~/.config/herdr-app/keys.json`，而 `omarchy-refresh-herdr-app` 会把它们放回去。安装它会选择 Herdr 的 Omarchy 主题，从那时起它会跟随你的 Omarchy 主题。Herdr 为浅色模式保留一个主题，为深色模式保留一个，所以在深色和浅色 Omarchy 主题之间切换后，在 Herdr 的主题选择器中再为另一个模式选择一次 Omarchy。

T3 Code 从 `~/.local/share/t3code` 中的官方 AppImage 发行版运行，而不是从软件包运行，所以它会自我更新。安装它会询问是从 Stable 还是 Nightly 通道开始；之后在 T3 Code 的设置中切换。你的线程和设置住在 `~/.t3` 中，而在 _Remove > AI_ 下移除 T3 Code 会把它们一起带走。

### 本地模型

在你自己的机器上为你的编程智能体运行开放模型。你的提示和代码都留在机器上；发送给模型的任何东西都不会离开它。从以下开始：

```bash
omarchy models use best text
```

这为这台机器设置最佳文本模型，也就是你的智能体使用的那类。图像、视频和音乐模型各有自己的最佳：`omarchy models use best image`、`video` 或 `music`。运行 `omarchy models use best` 查看每个种类为这台机器选出的型号。

或者从顶栏中智能体图标旁边的闪光图标打开本地模型面板，或用 Super + Ctrl + Alt + X，并选择 +。当某个模型适合这台机器时，该图标会显示。运行模型的 Podman 随 Omarchy 一起来，如 NVIDIA 机器上的 NVIDIA 容器工具包，它把 GPU 给模型；如果缺少任一个，第一次设置会安装它。然后 Omarchy 为这台机器选出推荐模型，下载它，并启动它。预计下载量为数十 GB，并且在模型运行时，机器的大部分内存会被使用：Flash Next 以其完整的 256K 上下文运行时用约 100 GiB。如果其他模型占有所需的内存，它会被设置为已停止状态，一旦你停止其中一个就准备启动。该模型在注销时停止；当你需要内存做其他事情时，你自己停止它。

`omarchy models list` 显示选项，并解释为什么有些不适合。要设置另一个，运行 `omarchy models use <recipe>`。如今，`qwen3.8-flash-next-gufo` 和 `qwen3.8-27b-gufo` 适用于 128 GB Strix Halo 机器；27B 用约 40 GiB，所以它为其他工作留出空间。在配备 Intel 的 Arc B390 的 64 GB 笔记本电脑上，`qwen3.6-35b-a3b-llamacpp` 用约 30 GiB 运行。新的配方和推荐随 `omarchy update` 通过该包到来。

你设置的每个模型在本地模型面板中都有自己的一行：播放启动它，暂停停止它并释放其内存，终端按钮在它上面打开你的智能体。在顶部横贯，一条栏显示机器内存如何在 Omarchy 本身（系统和你的应用）、每个正在运行的模型和空闲部分之间分配。指向一个已停止的模型，栏会显示它是否适合，或者还差多少。几个模型在内存共同适合时可以同时运行；如果一个不适合，Omarchy 会说出要停止哪个正在运行的模型。按其标志拖拽行来重新排序它们，并在选中的行上按 Delete 删除模型及其下载。

你设置的每个编程模型还在应用启动器中获得自己的条目，位于模型名称之下并带有其制造者的标志，就像登录 Claude、Codex 或 Grok 会添加一个一样。它在该模型上打开你的智能体，如果它还没运行，先启动该模型：终端显示它正在加载，并在就绪后移交给智能体。移除模型会移除其条目。

并非每个模型都是用于编程的。图像、视频和音乐模型改为在 Fantasi 中打开，Fantasi 是 Omarchy 的应用，用于用这台机器上运行的模型制作图片、视频和音乐，在那里选出，或者从本地模型面板中的它们所在的那一行选出。

一个模型完全按其设置时的状态继续运行，所以 Omarchy 更新永远不会在你的智能体下方重启一个。当 Omarchy 有更新的运行时或你已设置模型的更新权重时，它的那一行会显示一个更新按钮：按下它，该模型在后台重新设置，只下载已变化的内容，并在新版本上重启。曾停止的模型保持停止。`omarchy models update` 对每个模型从终端做同样的事。

从命令行，`omarchy models start <recipe>` 和 `omarchy models stop <recipe>` 做同样的事，`omarchy models status` 显示每个模型，而 `omarchy agent --local` 在你最后启动的模型上打开你的默认智能体。pi、OpenCode 和 Qwen Code 可以使用一个；换作任何其他默认项，它会在 pi 中打开，或者如果你没有 pi，在 OpenCode 中打开。pi 还在其自己的模型选择器中列出你设置的每个模型，以及你在已配对机器上的那些模型，所以普通的 `pi` 也能访问它们。任何与 OpenAI 兼容的客户端也可以连接：`status` 显示每个模型的地址（第一个是 `http://127.0.0.1:11435/v1`），配方名就是模型，密钥在 `~/.config/omarchy/agent-local/key` 中。

`omarchy models remove <recipe>` 删除一个模型以及没有其他模型使用的下载。

第三方运行时标有其发布者。Omarchy 运行每个模型时都无网络访问。

### 本地 LLM

Omarchy 推荐两种运行本地 LLM 模型的方式：LM Studio 和 Ollama。LM Studio 提供 GUI 界面，用于查找开放权重模型、安装它们并运行它们。这是轻松上手的好方法。Ollama 提供 CLI 以类似方式做到这一点。但如果你是本地模型新手，我会从 LM Studio 开始。你可以在 Omarchy 菜单的 _Install > AI_ 下安装任一个。

### Omarchy 技能

智能体技能帮助 AI 以特定方式使用特定工具，Omarchy 附带了其中七个。omarchy 技能涵盖定制系统，比如调整你的 Hyprland 配置或调整栏。omarchy-make-theme、omarchy-make-plugin、omarchy-make-app 和 omarchy-make-game 涵盖制作新东西，omarchy-contribute 涵盖向上游报告错误或发送修复，而 omarchy-diagnose-crash 处理崩溃的 core dump。它们被符号链接到 Claude Code (`~/.claude/skills`)、Codex (`~/.codex/skills`)、Pi (`~/.pi/agent/skills`)、Antigravity (`~/.gemini/config/skills`)、Hermes (`~/.hermes/skills` 和每个 `~/.hermes/profiles/*/skills`)，以及通用 `~/.agents/skills` 位置的技能目录中，所以大多数 harness 会自动拾取它们。你自己的同名技能文件夹优先。

但你应该把这些技能看作实验性的。不同模型运用它的效果会不同。最好先以 plan 模式运行，这样你对智能体想要更改什么有个概念。然后准备好回滚更改，或者甚至在智能体把一切搞得一团糟时调用 `omarchy reinstall configs`。
