### 安装和更新智能体

Hermes 除外，这些智能体都使用 mise 的延迟安装：第一次启动时安装 CLI，之后的启动则复用它。mise 还会至多每四小时检查一次已安装的智能体是否有新版本，就在它启动之前，或者在 shell 提示符下在后台检查。如果更新失败或者你处于离线状态，就会运行已安装的版本。`omarchy update` 会随 Omarchy 的其他部分一起更新已安装的智能体，而 `mup` 只更新 mise 管理的工具。

智能体自己的更新器，例如 `claude update`、`codex update`，或应用中的更新按钮，不会更新 mise 管理的安装。`codex update` 会失败，而 `claude update` 可能报告成功，却安装了一个 mise 不跟踪的单独副本。如果你更想使用智能体原生的安装器和更新器，把它加到 `disable_tools` 中；参见[预装 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

要在需要之前安装所有已配置的延迟工具，运行 `mise install --include-lazy`。这既包括这些智能体，也包括 Omarchy 的其他默认 CLI 工具。关于安装单个工具或使用你自己的安装，参见[预装 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

`grok` 通过 mise 的第一方 `grok` 包安装，方式与 `claude` 和 `codex` 相同。运行 `grok`，或在 _Setup > Defaults > Agent_ 下选择它。跳过 x.ai 上的 `curl | bash` 安装器。那条路径会在 `~/.grok/bin` 中放入第二个副本，把它前置到 `PATH` 上，并覆盖 Omarchy 的包装器。

`dsh` 会在 `127.0.0.1:3080` 上打开它的浏览器 UI，并以启动目录作为其默认工作区。它的浏览器 UI 不接受起始提示词，所以 `omarchy agent prompt` 打开它时会把提示词放到你的剪贴板上供你粘贴。Omarchy 以 DeepSeek 的无审批权限预设启动它。当你使用 DeepSeek 的官方模型 API 时，DeepSeek Harness 会把会话日志上传给 DeepSeek；在其浏览器 UI 的 _Settings > General > Upload Session Log_ 下关闭这一项。你发送给它的反馈也会随会话一起上传，除非你用 `DSH_TELEMETRY_MODE=DISABLED` 启动它。

### 默认智能体

用 `omarchy default agent <name>` 或在 Omarchy 菜单（`Super + Space`）的 _Setup > Defaults > Agent_ 下选择你的默认智能体。如果该智能体尚未安装，选择它会先安装它。全新的 Omarchy 会用一条一次性的通知邀请你做出这个选择。

选择 Claude 还会尝试为 Chromium、Chrome、Brave、Brave Origin 和 Edge 设置它的浏览器扩展。该扩展的设置适用于所有用户，可能会要求输入你的系统密码；取消或扩展安装失败仍然会选择并启动 Claude。重启你的浏览器，在出现提示时启用该扩展，并登录 Claude 以完成连接。在 Claude 中运行 `/chrome` 检查连接。Firefox 和 Zen 不支持这个扩展。如果在加入这项设置之前 Claude 就已经是你的默认项，再次选择它即可安装该扩展。

选好之后，`Super + Shift + Ctrl + A` 会在一个专用的终端窗口中启动默认智能体（或者，如果你还没选，会调出选择器）。你也可以用 `omarchy agent prompt "Review this project"` 让它直接进入一项任务。Freebuff 和 DeepSeek Harness 不接受起始提示词，所以它们打开时会把提示词放到你的剪贴板上供你粘贴，而不是这样。以这种方式启动的智能体会在各自的不要停下来询问模式下无人值守地运行，所以你要做好准备，它们真的会动手做事！MiniMax Code 的交互式会话没有这种模式，所以它会像往常一样请求权限。而且，由于智能体拒绝记住对你的主目录的信任，从 `$HOME` 启动时会改为在 `~/Work` 中开始。

也有终端快捷方式：`a` 在当前终端内内联运行默认智能体，而 `c`、`cx` 和 `cy` 直接启动 OpenCode、Claude Code 和 Codex（同样是在它们的自动批准模式下）。主题变化也会同步到这些智能体：当你切换 Omarchy 主题时，Claude Code、Pi、OpenCode 和 Hermes（一旦 Omarchy 安装了它）都会随之跟随。

### 智能体面板

顶栏有一个智能体图标。在你设置好一个智能体之前，它的面板会引导你登录 Claude、Codex 或 Grok，第一个登录的会成为你的默认智能体。在那之后，面板会把每一个订阅都放到一页上：每个智能体和账户及其套餐、针对它的 5 小时会话限额和每周限额中每一项的计量条以及距离重置的时间（悬停可看确切百分比），或者剩余的预付余额，位于一行轮换显示你跨所有这些智能体的用量（例如本周的 tokens 和你最常用的模型）之下。在 _Make something_ 下，它提供用于新主题、插件或应用的入门提示词，把任务交给你的默认智能体。应用的构建方式与 Omarchy 自己的 Hype、Monologue 和 Omacut 相同，用 C++ 和 Qt Quick，遵循 omarchy-app 智能体技能，它们需要的编译器和 Qt 组件都已随系统安装。Claude Code、Codex、Grok、Kimi、Cursor 及其 Grok Bot 额度、GitHub Copilot、Muse、Antigravity、Kimchi 和 Devin 开箱即用地被覆盖，并带有它们的限额，而 Hermes、Mistral Vibe 和 Qwen Code 则在你使用过它们之后显示它们的会话和 tokens。你通过 pi、omp 或 opencode 使用的提供商套餐和密钥也会显示出来：OpenCode Zen 和 Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan 和 Synthetic 及其限额；Fireworks、OpenRouter 和 DeepSeek 及其预付余额；以及你在自己的硬件上运行的模型，位于 Local models 下。无论你通过多少个 harness 驱动它，每个智能体都只计一次，归到向你收费的那一方名下。

左键点击栏上的图标打开面板，右键点击启动你的默认智能体。它背后的用量记录由 `omarchy agent usage-update` 每 15 分钟重新生成一次，面板甚至可以通过一个同步文件夹合并来自你的其他机器的用量。完整的设置参见 `$OMARCHY_PATH/shell/plugins/agents/` 下的 README。

### 多个订阅

如果你为不止一个 Claude、Codex 或 Grok 套餐付费——比如一个个人 Max 和一个工作的——Omarchy 可以让它们全都保持登录，并在它们之间切换。用智能体面板中的 + 添加一个订阅，它会就在那里引导你完成，或者用 `omarchy agent account add claude Work`（或 `codex`，或 `grok`）。如果 CLI 缺失，它会安装它。某个提供商的第一个账户通过你的普通浏览器登录，就在 CLI 一直查找的地方。此后的每一个都通过一个隐私窗口登录，这样你浏览器中已经登录的账户就不会被误选；在那里登录为你要添加的账户，并先关掉你已经打开的任何隐私窗口。千万不要为此退出 CLI 的登录：退出会撤销已保存的登录，那个账户就必须重新添加。

要通过 SSH 把你的订阅登录复制到另一台 Omarchy 机器上，运行 `omarchy agent account copy user@laptop`。当目标机器上没有安装接收器时，发送方会提供一个临时接收器，所以较旧的 Omarchy 机器无需更新就能接收账户。已安装的接收器优先。此命令复制所有 Claude、Codex 和 Grok 订阅；添加提供商名称来选择它们，如 `omarchy agent account copy laptop claude` 中那样。账户名称和命令 ID 与来源一致，包括目标上已经存在的账户。无关的目标账户如果名称冲突，会得到一个数字后缀，而设置、技能、插件和对话历史都保留在各自的机器本地。

目标上现有的凭据会被保留。已经在那里登录的来源账户会同步其名称，但不会替换其凭据；其他账户会被添加到它旁边。要为匹配的账户替换已保存的凭据，先在目标上退出该账户的会话，再使用 `omarchy agent account copy --replace laptop claude`。全新的目标还会得到来源的活动账户和切换偏好；已有既定状态的目标则保留自己的。

凭据通过 SSH 传输，并存储在目标上的私有文件中，所以只复制到你信任的机器。这是一次性复制，不是持续同步。Codex 刷新令牌可能被另一台机器轮换，使复制的登录需要续期；对在多台机器上同时使用而言，分开登录仍然是最可靠的选择。参见 [Codex 的账户认证指南](https://developers.openai.com/codex/auth/ci-cd-auth)。

每个提供商有一个活动账户，每个新会话都以它开始：`cx`、`cy`、普通的 `claude`、`codex` 或 `grok`、通过 `omarchy agent` 启动的任何东西，以及在 `PATH` 上找到该 CLI 的脚本或编辑器。用 `omarchy agent account use work` 切换（并用 `omarchy agent account use main` 切回），或者在面板中按一个账户的编号然后按 `Enter`（或点击它的 Use 按钮）。已经在运行的会话会留在它们开始时用的账户上。对话历史、设置、技能和插件在账户之间共享，所以在同一个文件夹中的 `claude --continue` 会在新账户上从你离开的地方继续。

有多个账户时，面板会并排显示每个账户的限额，并标记活动的那一个。默认情况下，当活动账户超过某个限额的 95% 时，Omarchy 会通知你，点击该通知会切换到余量最多的账户。将鼠标悬停在面板中的某个账户行上，点击 Use 旁边出现的 Autoswitch（或按 `m`），或者运行 `omarchy agent account mode auto`，让它自行切换；它开启时，Autoswitch 会取代 Use 的位置，再次点击它会回到通知模式。添加一个数字来更改阈值，如 `omarchy agent account mode auto 90` 中那样。如果每个账户都超过了阈值，你会被告知一次，同时告知哪个账户最先释放额度。当活动账户距离其阈值在 15 个百分点以内时（默认阈值下为 80%），它的限额会每三分钟检查一次，而不是每 15 分钟。

`omarchy agent account list` 显示每个账户及其最新限额，`omarchy agent account remove work` 遗忘一个账户，而 `omarchy agent account rename primary Hey` 重命名一个账户（或在面板中点击一个账户的名称）。这些命令作用于你的默认智能体的账户；要访问另一个提供商，先点名它，如 `omarchy agent account use codex side` 中那样。你已经在 `~/.claude` 或 `~/.codex` 中拥有的登录是 _Main_ 账户，并会留在原处。闲置超过约八小时的账户可能显示 _Sign-in required_；点击它直接在面板中重新登录那个账户，或者在它下面启动一个会话，这会自动刷新登录。你在添加某个账户时拥有的 MCP 服务器会随之带到该账户，但你后来用 `claude mcp add` 添加的只会到达你添加它们时所在的那个账户。Claude Desktop 以及用 CLI 二进制文件的绝对路径配置的工具不会跟随切换。显式的 `CLAUDE_CONFIG_DIR`、`CODEX_HOME` 或 `GROK_HOME` 优先于所选账户。

### 崩溃诊断

Omarchy 会监视 systemd-coredump 的进程崩溃。当某个程序段错误时，你会收到一条“Process crashed”通知——点击它，崩溃就会连同 Omarchy 的 diagnose-crash 技能一并交给你默认的智能体，该技能会引导智能体从核心转储中确立事实，并判断该崩溃是否值得向上游报告。你也可以对着 `coredumpctl list` 中的任何 PID 手动运行它，使用 `omarchy agent crash <pid>`。

该监视默认开启。在 _Trigger > Toggle > Crash Capture_ 下关闭它（或使用 `omarchy toggle crash-capture`），通知就会停止；`omarchy agent crash <pid>` 仍然可以手动使用。

崩溃也可以一次为一个程序静默，这正是诊断在最后向你提供的。`omarchy crash mute hyprland` 只停止该程序的通知，`omarchy crash mute hyprland off` 将它们带回来，而单独运行 `omarchy crash mute` 会列出你已静默的内容。它接受二进制文件的路径就和接受其名称一样高兴，所以 `omarchy crash mute /usr/bin/hyprland` 做的是同一件事。给带空格的名称加引号，如 `omarchy crash mute 'Some App'` 中那样。其他一切仍然会通知，而且被静默的程序仍然会崩溃——这只是隐藏提醒，它不修复任何东西。

### 桌面应用

_Install > AI_ 菜单也带有一些图形 AI 应用：ChatGPT 桌面应用、Claude 桌面应用（Anthropic 的 Linux beta 版，带有 Chat、Cowork 和 Claude Code 标签页）、用于与 xAI 的模型聊天的 Grok Bot、Hermes Desktop、OpenClaw、Perplexity 桌面应用和 T3 Code。Grok Bot 是桌面聊天应用。编程智能体是 `grok` 命令。

Hermes Desktop 是需要了解的那一个，因为一台机器上只有一个 Hermes，而且它是该应用的：Hermes 永远只通过该应用安装，默认智能体运行的 `hermes` 命令就是该应用的。选择 Hermes 作为默认智能体会安装与 _Install > AI_ 条目相同的东西：该软件包，以及一个由 Hermes 自己的安装器在 `~/.hermes` 下设置的 Hermes 运行时，第一次需要几分钟时间。终端 `hermes` 命令、默认智能体和该应用都使用这一个运行时，它通过 `hermes update` 自行更新，而不是等待 Omarchy 发布版本。安装它还会把 Omarchy 主题作为一个名为 `omarchy` 的皮肤交给 Hermes，当你切换主题时，每个 Hermes 界面都会跟随它；如果你不想这样，在 Hermes 的 Appearance 设置下或用 `/skin` 选择另一个，Omarchy 不会干涉那个选择。在 _Remove > AI_ 下移除该应用会先关闭 Hermes，包括网关，并带走那个运行时，同时保留你的聊天、记忆和 Hermes 为自己编写的技能，除非你另行告诉它：它会询问，默认选否，是否也应删除那些数据和你的连接设置。

OpenClaw 的桌面体验是它的 Control UI，它作为一个 web 应用打开，由其自己的本地网关提供支持。OpenClaw 位于 `~/.openclaw` 中并自行更新：使用 Control UI 的“Update Gateway”按钮或运行 `openclaw update`，网关会在新版本上重启。Omarchy 只选择全新安装起始的发布版本。在 _Remove > AI_ 下移除 OpenClaw 会带走网关服务和该应用，然后询问 `~/.openclaw` 是否也应删除，因为那里除了 OpenClaw 本身和它下载的插件运行时，还存放着你的聊天和凭据；默认保留它，再次安装 OpenClaw 会把它重新拾起。

T3 Code 从其官方 AppImage 发布在 `~/.local/share/t3code` 中运行，而不是从软件包运行，所以它会自行更新。安装它会询问是开始于 Stable 还是 Nightly 频道；之后在 T3 Code 的设置中切换。你的线程和设置位于 `~/.t3` 中，在 _Remove > AI_ 下移除 T3 Code 会把它们一并带走。

### 本地模型

在你自己的机器上为你的编程智能体运行一个开放模型。你的提示词和代码留在机器上；发送给模型的任何东西都不会离开它。从这里开始：

```bash
omarchy agent local use best
```

或者，在顶栏的智能体面板中，选择 + 然后选择 Local AI，当有模型适合这台机器时它会出现。第一次时，这会安装 Podman，它运行这些模型，而在 NVIDIA 机器上还会安装 NVIDIA 的容器工具包，它让模型用上 GPU。然后 Omarchy 会为这台机器挑选推荐的模型，下载它，并启动它。预期会有几十 GB 的下载，并且在模型运行时机器的大部分内存会被占用：Flash Next 在其完整的 256K 上下文下使用约 100 GiB。如果其他模型占着它需要的内存，它会被设置为已停止状态，准备好在你停掉一个模型之后启动。该模型在注销时停止；当你需要内存做其他事情时，自己停掉它。

`omarchy agent local list` 显示可选项，并解释为什么有些不合适。要设置另一个，运行 `omarchy agent local use <recipe>`。如今，`qwen3.8-flash-next-gufo` 和 `qwen3.8-27b-gufo` 可用于 128 GB Strix Halo 机器；27B 占用约 40 GiB，所以它为其他工作留出了空间。新的配方和推荐通过软件包随 `omarchy update` 一同到来。

你设置的每个模型在智能体面板中都有自己的一行，挨着你的订阅：播放来启动它，暂停来停止它并释放它的内存，终端按钮来在它上面打开你的智能体。当多个模型能同时装进内存时，可以同时运行几个；如果有一个装不下，Omarchy 会说明该停掉哪个正在运行的模型。拖动行来重新排序它们，并在选中的一行上按 Delete 来移除一个模型及其下载。

在命令行上，`omarchy agent local start <recipe>` 和 `omarchy agent local stop <recipe>` 做同样的事，`omarchy agent local status` 显示每个模型，而 `omarchy agent --local` 在你上次启动的模型上打开你的默认智能体（如果你的默认智能体不能使用本地模型，则是 pi）。任何与 OpenAI 兼容的客户端也可以连接：`status` 显示每个模型的地址（第一个是 `http://127.0.0.1:11435/v1`），配方名称就是模型，密钥在 `~/.config/omarchy/agent-local/key` 中。

`omarchy agent local remove <recipe>` 删除一个模型以及没有其他模型使用的下载。

第三方运行时会标有其发布者。Omarchy 运行每个模型时都不给网络访问。

### 本地 LLM

Omarchy 推荐两种运行本地 LLM 模型的方式：LM Studio 和 Ollama。LM Studio 提供一个 GUI 界面，用于查找开放权重模型、安装它们并运行它们。它是一个轻松上手的绝佳方式。Ollama 提供一个 CLI 以类似方式做到这一点。但如果你刚接触本地模型，我建议从 LM Studio 开始。你可以在 Omarchy 菜单的 _Install > AI_ 下安装任意一个。

### Omarchy 技能

智能体技能帮助 AI 以特定的方式使用特定的工具，Omarchy 附带一个用于定制系统的默认技能。比如调整你的 Hyprland 配置、调整栏，甚至从零创建一个新主题。它被符号链接到 Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` 和每一个 `~/.hermes/profiles/*/skills`）以及通用的 `~/.agents/skills` 位置的技能目录中，所以大多数 harness 都会自动拾取它。

但你应该把这个技能视为实验性的。不同的模型使用它的效果各异。最好先在规划模式下运行，这样你能了解智能体想要更改什么。然后准备好回滚更改，甚至调用 `omarchy reinstall configs`，如果智能体把一切弄得一团糟的话。
