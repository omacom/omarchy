### 安装和更新智能体

Hermes 和 OpenClaw 除外，这些智能体使用 mise 的延迟安装：首次启动时安装 CLI，后续启动时复用它。mise 还会至多每四小时检查一次已安装智能体是否有新版本，就在它启动之前，或在 shell 提示符下于后台检查。如果更新失败或你处于离线状态，则运行已安装的版本。`omarchy update` 会随 Omarchy 的其余部分一起更新已安装的智能体，而 `mup` 仅更新由 mise 管理的工具。

智能体自身的更新器，例如 `claude update`、`codex update`，或应用中的更新按钮，不会更新由 mise 管理的安装。`codex update` 会失败，而 `claude update` 可能会报告成功，却安装了一份 mise 不跟踪的单独副本。如果你更愿意使用智能体原生的安装器和更新器，把它添加到 `disable_tools`；见[预装的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

要在需要之前安装所有已配置的延迟工具，运行 `mise install --include-lazy`。这包括 Omarchy 的其他默认 CLI 工具以及这些智能体。有关安装单个工具或使用你自己的安装，见[预装的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

`grok` 通过 mise 的第一方 `grok` 包安装，与 `claude` 和 `codex` 相同。运行 `grok`，或在智能体面板中为它加星。跳过 x.ai 上的 `curl | bash` 安装器。那条路径会在 `~/.grok/bin` 中放入第二份副本，把它前置到 `PATH` 上，并覆盖 Omarchy 的包装器。

`dsh` 在 `127.0.0.1:3080` 上打开其浏览器 UI，并以启动目录作为默认工作区。其浏览器 UI 不接受起始提示，所以 `omarchy agent prompt` 打开它时，会把提示放在你的剪贴板上供你粘贴。Omarchy 以 DeepSeek 的免审批权限预设启动它。当你使用 DeepSeek Harness 的官方模型 API 时，它会把会话日志上传到 DeepSeek；在其浏览器 UI 中的 _Settings > General > Upload Session Log_ 下将其关闭。你发送给它的反馈也会随会话一起上传，除非你使用 `DSH_TELEMETRY_MODE=DISABLED` 启动它。

### 默认智能体

使用智能体面板中智能体旁边的星标来选择你的默认智能体，默认项上的星标是实心的；也可以使用 `omarchy default agent <name>`，它还接受任何在那里没有一行的 harness。如果智能体尚未安装，选择它时会先安装它，而且它还会在应用启动器中获得自己的启动器，紧挨着 Agent。全新的 Omarchy 会通过一次性通知邀请你设置一个，通知会打开智能体面板。

选择 Claude 时还会尝试为 Chromium、Chrome、Brave、Brave Origin 和 Edge 设置其浏览器扩展。该扩展设置适用于所有用户，并且可能会要求你输入系统密码；取消或扩展安装失败仍然会选择并启动 Claude。重启你的浏览器，在提示时启用该扩展，并登录 Claude 以完成连接。运行 Claude 中的 `/chrome` 来检查连接。Firefox 和 Zen 不支持此扩展。如果在此设置被添加之前 Claude 就已经是你的默认项，请再次选择它以安装该扩展。

在你选择之后，`Super + Shift + Ctrl + A` 会在专用终端窗口中启动默认智能体（或者，如果你尚未选择，它会调出选择器）。你也可以用 `omarchy agent prompt "Review this project"` 让它直接进入一项任务。Freebuff 和 DeepSeek Harness 不接受起始提示，所以它们打开时会把提示放在你的剪贴板上供你粘贴。以这种方式启动的智能体会以它们各自无需停下来询问的无人值守模式运行，所以请准备好它们真的会做事情！MiniMax Code 的交互式会话没有这种模式，所以它会像往常一样请求权限。而且，由于智能体拒绝为你的主目录记住信任，从 `$HOME` 启动时改为在 `~/Work` 中启动。

也有终端快捷方式：`a` 在当前终端中内联运行默认智能体，而 `c`、`cx` 和 `cy` 会直接启动 OpenCode、Claude Code 和 Codex（同样处于它们的自动批准模式中）。主题变化也会同步到智能体：当你切换 Omarchy 主题时，Claude Code、Pi、OpenCode 和 Hermes（一旦 Omarchy 已安装它）都会跟随。

### 你的智能体指令

适用于每个智能体的个人规则放在 `~/.agents/AGENTS.md` 中，紧挨着 `~/.agents/skills` 中的共享技能。用智能体面板中 + 旁边的文档图标打开它，或使用 `omarchy agent instructions --edit`，后者还会把它链接到每个保留其自有全局文件的 harness 中：`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`~/.pi/agent/AGENTS.md`、`~/.config/opencode/AGENTS.md`、Copilot 的 `~/.copilot/copilot-instructions.md`，等等。Crush 和 Amp 读取 `~/.config/AGENTS.md` 链接，而 omp、Kimi 和 DeepSeek Harness 直接读取 `~/.agents/AGENTS.md`。选择默认智能体时也会链接它。如果你已有的指令文件此前不存在共享文件，它会成为共享文件；否则，它会作为 `.bak` 保留在链接旁边。安装另一个智能体后，运行 `omarchy agent instructions` 重新链接。

### 智能体面板

顶栏上有一个智能体图标。在你设置智能体之前，它的面板提供了三种开始方式：登录 Claude、Codex、Grok、Gemini、Muse、Cursor 或 Copilot 订阅，或者在 More 下登录 OpenCode Go、MiniMax、Synthetic 或 Z.ai 编程套餐；使用 Fireworks、OpenCode Zen and Go、OpenRouter 按用量付费，或者在 More 下使用 DeepSeek 或 OpenCode 能登录的任何其他提供商，这些都运行在 OpenCode 中；或者在有适合的模型时，为你的计算机运行最佳模型。你完成的第一个会成为你的默认智能体，之后面板中的 +，或者 Omarchy Menu 中的 _Agent > Add_，会提供相同的三种方式。之后，面板会把每个订阅都放在一页上：每个智能体和账户及其套餐、其 5 小时会话和每周限额各自的计量表以及距离重置的时间（悬停查看确切百分比），或剩余的预付余额，位于一行轮播内容的下方，该行会轮播你在所有这些上使用过的内容，例如本周的 tokens 和你最常用的模型。在 _Make something cool_ 下，它会为能把任务交给你的默认智能体的新主题、插件、应用或游戏提供入门提示。应用按照 Omarchy 自己的 Hype、Monologue 和 Omacut 的构建方式使用 C++ 和 Qt Quick 构建，并遵循 omarchy-make-app 智能体技能，它们所需的编译器和 Qt 组件都已安装。游戏是遵循 omarchy-make-game 智能体技能的、位于 `~/Games/vibes` 中的单个 three.js 页面，且都从当前主题中的一个 Game Vibes 启动器打开；它们从 web 加载 three.js，所以启动时需要连接。Claude Code、Codex、Grok、Kimi、Cursor 及其 Grok Bot 额度、GitHub Copilot、Muse、Gemini（通过 Antigravity）和 Devin 开箱即用，带有它们的限额；Kimchi 带有其套餐、预付额度和支出预算；而 Hermes、Mistral Vibe 和 Qwen Code 在你使用它们后会显示其会话和 tokens。通过 pi、omp 或 opencode 使用的提供商套餐和密钥也会出现：OpenCode Zen and Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan 和 Synthetic，带有它们的限额；OpenRouter 和 DeepSeek，带有它们的预付余额；Fireworks，带有其过去 30 天的支出。来自你在自有硬件上运行的模型的 Tokens 也会计入总数；这些模型本身有自己的面板，在[本地模型](#local-models)下描述。每个智能体只计一次，计入向它计费的一方，无论你通过多少个 harness 驱动它。

左键单击栏图标或按 `Super + Ctrl + X` 打开面板，右键单击以启动你的默认智能体，中键单击以刷新。其背后的使用记录由 `omarchy agent usage update` 每 15 分钟重新生成一次，面板甚至可以通过同步文件夹合并来自你其他机器的使用情况。有关完整设置，见 `$OMARCHY_PATH/shell/plugins/agents/` 下的 README。

### 多个订阅

如果你为多个 Claude、Codex 或 Grok 套餐付费——例如一个个人 Max 和一个工作套餐——Omarchy 可以保持它们全部登录并在它们之间移动。使用智能体面板中的 + 添加订阅，它会直接在那里引导你完成，或者使用 `omarchy agent account add claude Work`（或 `codex`，或 `grok`）。同样的 + 和命令能登录 Gemini（`gemini`）和 OpenCode（`opencode`），并在 OpenCode 中保存 Fireworks（`fireworks`）或 OpenRouter（`openrouter`）API 密钥；该命令也能登录 Copilot（`copilot`）、Cursor（`cursor`）和 Muse（`muse`）。它们各自只保持一次登录。如果缺少 CLI，它会安装它。一个提供商的第一个账户会通过你的普通浏览器登录，恰好在 CLI 一直查找的位置。之后的每一个账户都通过隐私窗口登录，所以你的浏览器已登录的账户不会被误选；在那里登录你要添加的账户，并先关闭你已打开的任何隐私窗口。千万不要为此退出 CLI：退出会撤销已保存的登录，该账户将必须重新添加。

要通过 SSH 把你的订阅登录复制到另一台 Omarchy 机器上，运行 `omarchy agent account copy user@laptop`。当目标机器未安装接收器时，发送方会提供一个临时接收器，所以较旧的 Omarchy 机器无需更新即可接收账户。已安装的接收器优先。这会复制所有 Claude、Codex 和 Grok 订阅；添加提供商名称以选择它们，如 `omarchy agent account copy laptop claude` 中所示。账户名称和命令 ID 与源机器匹配，包括已存在于目标机器上的账户。无关的目标账户在名称冲突时会获得数字后缀，设置、技能、插件和对话历史则保留在每台机器本地。

现有的目标凭据会被保留。已在那里登录的源账户会同步其名称，但不会替换其凭据；其他账户会被添加到它旁边。要替换匹配账户已保存的凭据，请在目标机器上退出该账户的会话后，使用 `omarchy agent account copy --replace laptop claude`。全新的目标机器还会获得源机器的活动账户和切换偏好；已建立的目标机器则保留其自己的。

凭据通过 SSH 传输并存储在目标机器的私有文件中，所以只复制到你信任的机器上。这是一次性复制，而非持续同步。Codex 刷新 tokens 可能被另一台机器轮换，导致复制的登录需要续期；对于在多台机器上同时使用，单独登录仍然是最可靠的选择。见[Codex 的账户身份验证指南](https://developers.openai.com/codex/auth/ci-cd-auth)。

每个提供商只有一个账户处于活动状态，每个新会话都以该身份开始：`cx`、`cy`、普通的 `claude`、`codex` 或 `grok`、任何通过 `omarchy agent` 启动的内容，以及在 `PATH` 上找到 CLI 的脚本或编辑器。使用 `omarchy agent account use work` 切换（并使用 `omarchy agent account use main` 切换回来），或在面板中按下账户的编号然后按 `Enter`（或点击其星标）。正在运行的 Claude 会话也会切换，从它们的下一条消息开始：每个 Claude 会话都在 `~/.claude` 中运行，那里始终保存着活动账户的登录。由较旧 Omarchy 在账户自有文件夹中启动的 Claude 会话会保持该登录直到退出，所以切换会指出这些会话，并在它们消失后自行完成。正在运行的 Codex 和 Grok 会话会保持它们启动时所使用的账户。对话历史、设置、技能和插件在账户之间共享，所以同一文件夹中的 `claude --continue` 会在新账户上从你离开的地方继续。

当有一个以上账户时，面板会并排显示每个账户的限额，正在使用的一个上面有实心星。Omarchy 会在活动账户超过限额的 95% 时通知你，点击该通知会切换到余量最多的账户。它绝不会自行切换。使用 `omarchy agent account threshold 90` 更改阈值。如果每个账户都超过阈值，你会得到一次通知，并得知哪个账户最先释放。当活动账户与阈值相差 15 个百分点以内时（默认时为 80%），其限额会每三分钟检查一次，而不是每 15 分钟一次。

`omarchy agent account list` 显示每个账户及其最新限额，`omarchy agent account remove work` 遗忘一个账户，`omarchy agent account rename primary Hey` 重命名一个账户（或者在面板中点击账户的名称）。这些命令作用于你的默认智能体的账户；要访问另一个提供商，先命名它，就像 `omarchy agent account use codex side` 中那样。你在 `~/.claude` 或 `~/.codex` 中已有的登录就是 _Main_ 账户。Codex 的会留在原处；Claude 的则在另一个账户处于活动状态时，于其自有文件夹中等待。闲置超过约八小时的账户可能会显示 _Sign-in required_；点击它可直接在面板中重新登录该账户，或切换到它并启动会话，后者会自行刷新登录。使用 `claude mcp add` 添加的 MCP 服务器能到达每个 Claude 账户，因为它们都在 `~/.claude` 中运行；对于 Codex 和 Grok，在账户被添加时你已有的服务器会随它一同前往，但之后添加的只能到达你添加它们的账户。Claude Desktop 保留其自有登录，且配置为使用指向 CLI 二进制文件的绝对路径的 Codex 或 Grok 工具不会跟随切换。明确设置的 `CLAUDE_CONFIG_DIR`、`CODEX_HOME` 或 `GROK_HOME` 优先于所选账户。

### 崩溃诊断

Omarchy 监视 systemd-coredump 以发现进程崩溃。一旦你选定了默认智能体，你的任何转储核心的程序都会带来一个 "Process crashed" 通知——点击它，崩溃就会连同 Omarchy 的 omarchy-diagnose-crash 技能一并交给你的默认智能体，该技能会引导智能体从核心转储中确立事实，并决定该崩溃是否值得向上游报告。你也可以用 `omarchy agent crash <pid>` 针对来自 `coredumpctl list` 的任何 PID 手动运行它。

监视默认开启。在 _Trigger > Toggle > Crash Capture Off_ 下将其关闭（或使用 `omarchy toggle crash-capture`）后，通知会停止；`omarchy agent crash <pid>` 仍然可以手动运行。

崩溃也可以一次为一个程序静音，这正是诊断在结束时提供给你的。`omarchy crash mute hyprland` 仅停止该程序的通知，`omarchy crash mute hyprland off` 将它们恢复，而单独使用 `omarchy crash mute` 则列出你已静音的内容。它既接受二进制文件的路径，也接受其名称，所以 `omarchy crash mute /usr/bin/hyprland` 做同样的事。为含有空格的名称加引号，就像 `omarchy crash mute 'Some App'` 中那样。其他一切仍会通知，被静音的程序也会仍然崩溃——这隐藏了提醒，它不会修复任何东西。

### 桌面应用

_Install > AI_ 菜单还包含一些图形化 AI 应用：Amp Desktop、Antigravity Desktop、ChatGPT 桌面应用、Claude 桌面应用（Anthropic 的 Linux beta 版，带有 Chat、Cowork 和 Claude Code 标签页）、用于与 xAI 的模型聊天的 Grok Bot、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexity 桌面应用和 T3 Code。Grok Bot 是桌面聊天应用。编程智能体则是 `grok` 命令。

Hermes Desktop 是需要了解的那个，因为一台机器只有一个 Hermes，而它属于该应用：Hermes 仅通过该应用安装，默认智能体运行的 `hermes` 命令也是该应用的。选择 Hermes 作为默认智能体会安装与 _Install > AI_ 条目相同的东西：软件包，以及由 Hermes 自身安装器在 `~/.hermes` 下设置的一个 Hermes 运行时，首次使用时需要几分钟。该运行时就是终端 `hermes` 命令、默认智能体和该应用都使用的那个 Hermes，它用 `hermes update` 自我更新，而不是等待 Omarchy 发布。安装它还会把 Omarchy 主题作为名为 `omarchy` 的皮肤交给 Hermes，当你切换主题时，每个 Hermes 表面都会遵循它；如果你不希望如此，可在 Hermes 的 Appearance 设置下或用 `/skin` 选择另一个，Omarchy 会让那个选择保持不变。在 _Remove > AI_ 下移除该应用时，会先关闭 Hermes（包括网关），并随它一起带走该运行时；除非你另行说明，它会保留你的聊天、记忆以及 Hermes 为自身编写的技能：它会询问，默认回答为否，询问是否也要一并移除该数据和你的连接设置。

OpenClaw 的桌面体验是它的 Control UI，它作为由其自有本地网关支持的 web 应用打开。OpenClaw 位于 `~/.openclaw` 中并自我更新：使用 Control UI 的 "Update Gateway" 按钮或运行 `openclaw update`，网关会在新版本上重启。Omarchy 只选择全新安装起始的版本。OpenClaw 也可以是你的默认智能体：在 _Agent > Harness_ 下选择它，会在 `~/.openclaw` 中设置同样的副本，智能体会打开附加到其网关的 OpenClaw 终端 UI。在 _Remove > AI_ 下移除 OpenClaw 时，会随它一起带走网关服务和该应用，然后询问 `~/.openclaw` 是否也应该移除，因为那里除了 OpenClaw 本身及其下载的插件运行时外，还保存着你的聊天和凭据；默认会保留它，再次安装 OpenClaw 时会重新使用它。

Herdr Desktop 是 [Herdr](https://herdr.dev) 桌面应用：由终端和编程智能体组成的空间、标签页和窗格，当你关闭窗口时，它们会在其核心中继续运行。它来自 Herdr 自己的安装器而非软件包，所以它位于 `~/.local/share/herdr-app` 中，当你尚没有它时，会在 `~/.local/bin/herdr-core` 中随附其核心，并自我更新两者。它位于 Omarchy 随 `Super + Ctrl + Return` 提供的 `herdr` 命令旁边，而不是替换它，并获得该命令的直接按键：`Alt + Return` 和 `Alt + Shift + Return` 向下或向右拆分窗格，`Alt + Escape` 关闭它，`Ctrl + Alt + Arrow` 在窗格之间移动，`Alt + 1..9` 和 `Alt + Left/Right` 选择标签页，`Alt + Up/Down` 在空间之间移动。`Ctrl + 1..9` 选择空间，`Alt + Shift + Up/Down` 在智能体之间步进。`Ctrl + Space` 前缀按键仅保留给终端，因为该应用无法为序列按住普通的 Ctrl 键。Omarchy 把这些写入 `~/.config/herdr-app/keys.json`，`omarchy-refresh-herdr-app` 会把它们恢复。安装它会选择 Herdr 的 Omarchy 主题，从此该主题会跟随你的 Omarchy 主题。Herdr 为浅色模式保留一个主题，为深色模式保留一个主题，所以在深色和浅色 Omarchy 主题之间切换后，再在 Herdr 的主题选择器中为另一种模式选择一次 Omarchy。

T3 Code 从位于 `~/.local/share/t3code` 中的官方 AppImage 版本运行，而非从软件包运行，所以它自我更新。安装它时会询问在 Stable 还是 Nightly 渠道上开始；稍后可在 T3 Code 的设置中切换。你的线程和设置位于 `~/.t3` 中，在 _Remove > AI_ 下移除 T3 Code 时会随它一起被移除。

### 本地模型

在你自己的机器上为你的编程智能体运行一个开放模型。你的提示和代码会留在机器上；发送给模型的任何内容都不会离开它。从此开始：

```bash
omarchy models use best text
```

这会为这台机器设置最佳文本模型，即你的智能体使用的那种。图像、视频和音乐模型也各有其最佳选择：`omarchy models use best image`、`video` 或 `music`。运行 `omarchy models use best` 以查看每种类型为这台机器做出的选择。

或者从顶栏中其智能体图标旁边的闪耀图标打开本地模型面板，或使用 Super + Ctrl + Alt + X 并选择 +。当有适合这台机器的模型时，该图标才会出现。运行模型的 Podman 随 Omarchy 一同提供，NVIDIA 机器上的 NVIDIA 容器工具包也是如此，它给这些模型提供 GPU；如果其中任何一个不存在，首次设置时会安装它。然后 Omarchy 会为这台机器选择推荐的模型，下载它，并启动它。预期下载量为数十 GB，且在模型运行时会占用机器的大部分内存：Flash Next 在其完整的 256K 上下文下使用约 100 GiB。如果其他模型占用了它所需的内存，它会被设置为已停止，准备在你停止一个模型后启动。该模型在注销时停止；当你需要内存做其他事情时，自己停止它。

`omarchy models list` 显示选项，并解释为什么某些选项不合适。要设置另一个，运行 `omarchy models use <recipe>`。今天，`qwen3.8-flash-next-gufo` 和 `qwen3.8-27b-gufo` 可用于 128 GB Strix Halo 机器；27B 约占 40 GiB，所以它为其他工作留出了空间。在一台 64 GB、配备 Intel 的 Arc B390 的笔记本电脑上，`qwen3.6-35b-a3b-llamacpp` 在约 30 GiB 中运行。新的配方和推荐随 `omarchy update` 通过软件包到达。

你设置的每个模型在本地模型面板中都有自己的一行：播放以启动它，暂停以停止它并释放其内存，以及终端按钮以在其上打开你的智能体。在顶部，一个条形图显示机器的内存如何在 Omarchy 本身（系统和你的应用）、每个正在运行的模型以及空闲部分之间划分。指向一个已停止的模型时，该栏会显示它是否适合，或还差多少。多个模型可以在内存中同时容纳时一起运行；如果某个模型不适合，Omarchy 会说应该停止哪个正在运行的模型。按其徽标拖动行来重新排序它们，并在一个选定的行上按 Delete 以移除一个模型及其下载。

你设置的每个编程模型也会在应用启动器中获得自己的条目，位于该模型的名称下，并带有其制作者的徽标，就像登录 Claude、Codex 或 Grok 会添加一个一样。它在该模型上打开你的智能体，如果它尚未运行，则先启动模型：终端会显示它正在加载，并在就绪后移交给智能体。移除一个模型会移除其条目。

并非每个模型都是用于编程的。图像、视频和音乐模型改为在 Fantasi 中打开，Fantasi 是 Omarchy 的应用，用于使用在这台机器上运行的模型制作图片、视频和音乐，你可以在那里或从它们在本地模型面板中的行来选择它们。

模型会以其设置时的样子精确地保持运行，所以 Omarchy 更新绝不会在你的智能体之下重启一个模型。当 Omarchy 有更新的运行时或更新的权重用于你已设置的模型时，其行会显示更新按钮：按下它，模型将在后台重新设置，仅下载已更改的内容，并在新版本上重启。已停止的模型仍保持停止。`omarchy models update` 从终端对每个模型做同样的事。

从命令行，`omarchy models start <recipe>` 和 `omarchy models stop <recipe>` 做同样的事，`omarchy models status` 显示每个模型，`omarchy agent --local-model <recipe>` 则无论你的默认智能体是什么，都会在 pi 中打开该模型。要让你的本地模型成为智能体快捷键、Quake 控制台和 _Make something_ 打开的内容，运行 `omarchy default agent local` 或在 _Agent > Harness_ 下选择 _Local model_。pi 还会在其自己的模型选择器中列出你已设置的每个模型，以及你已配对的机器上的模型，所以普通的 `pi` 也能访问它们。任何与 OpenAI 兼容的客户端也可以连接：`status` 显示每个模型的地址（第一个是 `http://127.0.0.1:11435/v1`），配方名称即模型，而密钥在 `~/.config/omarchy/agent-local/key` 中。

`omarchy models remove <recipe>` 删除一个模型，以及没有其他模型使用的下载。

第三方运行时标有其发布者。Omarchy 在没有网络访问的情况下运行每个模型。

### 本地 LLM

Omarchy 推荐了运行本地 LLM 模型的两种方法：LM Studio 和 Ollama。LM Studio 提供 GUI 界面，用于查找开放权重模型、安装它们并运行它们。这是一种轻松上手的好方法。Ollama 提供 CLI 以类似方式完成此事。但如果你是本地模型的新手，我会从 LM Studio 开始。你可以在 Omarchy Menu 中的 _Install > AI_ 下安装其中任何一个。

### Omarchy 技能

智能体技能帮助 AI 以特定方式使用特定工具，Omarchy 附带了其中七个。omarchy 技能涵盖定制系统，例如调整你的 Hyprland 配置或调整栏。omarchy-make-theme、omarchy-make-plugin、omarchy-make-app 和 omarchy-make-game 涵盖制作新东西，omarchy-contribute 涵盖报告 bug 或向上游发送修复，而 omarchy-diagnose-crash 则处理崩溃的核心转储。它们被符号链接到 Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` 和每个 `~/.hermes/profiles/*/skills`）的技能目录，以及通用的 `~/.agents/skills` 位置，所以大多数 harness 会自动获取它们。你自有的同名技能文件夹优先。

但你应该把这些技能视为实验性的。不同模型将以不同效果使用它。最好先在规划模式下运行，这样你就对智能体想要更改的内容有所了解。然后准备好回滚更改，甚至调用 `omarchy reinstall configs`（如果智能体把一切弄得一团糟）。
