### 安装和更新智能体

除了 Hermes 和 OpenClaw，这些智能体都使用 mise 的延迟安装：首次启动时安装 CLI，后续启动则重复使用它。mise 还会至多每四小时检查一次已安装智能体是否有新版本，就在它启动之前检查，或在 shell 提示符下在后台检查。如果更新失败或你离线，就会运行已安装的版本。`omarchy update` 会在更新 Omarchy 其他部分的同时更新已安装的智能体，而 `mup` 只更新由 mise 管理的工具。

智能体自身的更新程序，例如 `claude update`、`codex update`，或应用中的更新按钮，不会更新由 mise 管理的安装。`codex update` 会失败，而 `claude update` 可能报告成功，却安装了一个 mise 不跟踪的独立副本。如果你更愿意使用智能体原生的安装程序和更新程序，请将其添加到 `disable_tools`；请参阅[预装的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

要在需要之前安装所有已配置的延迟工具，请运行 `mise install --include-lazy`。这包括 Omarchy 的其他默认 CLI 工具以及这些智能体。有关安装单个工具或使用你自己的安装，请参阅[预装的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

`grok` 通过 mise 的第一方 `grok` 包安装，与 `claude` 和 `codex` 的方式相同。运行 `grok`，或在_智能体 > 框架_下选择它。跳过 x.ai 上的 `curl | bash` 安装程序。那条路径会在 `~/.grok/bin` 中放入第二个副本，将其提前到 `PATH` 中，并覆盖 Omarchy 的包装器。

`dsh` 会在 `127.0.0.1:3080` 上打开其浏览器 UI，并以启动目录作为其默认工作区。其浏览器 UI 不接受起始提示词，所以 `omarchy agent prompt` 会打开它，并将提示词放到你的剪贴板上供你粘贴。Omarchy 会以 DeepSeek 的免审批权限预设启动它。当你使用其官方模型 API 时，DeepSeek Harness 会将会话日志上传到 DeepSeek；在其浏览器 UI 的_设置 > 通用 > 上传会话日志_下关闭此项。你发送给它的反馈也会随会话一同上传，除非你用 `DSH_TELEMETRY_MODE=DISABLED` 启动它。

### 默认智能体

用 `omarchy default agent <name>` 或在 Omarchy 菜单（`Super + Space`）的_智能体 > 框架_下选择你的默认智能体。如果该智能体尚未安装，选择它会先安装它，而且它还会在应用启动器中获得自己的启动器，紧挨着 Agent。新安装的 Omarchy 会通过一次性通知邀请你做出这个选择。

选择 Claude 还会尝试为 Chromium、Chrome、Brave、Brave Origin 和 Edge 设置其浏览器扩展。该扩展设置适用于所有用户，并且可能要求你输入系统密码；取消或扩展安装失败仍然会选择并启动 Claude。重启你的浏览器，在提示时启用该扩展，并登录 Claude 以完成连接。在 Claude 中运行 `/chrome` 来检查连接。Firefox 和 Zen 不支持此扩展。如果在此设置添加之前 Claude 已经是你的默认项，请再次选择它以安装该扩展。

选好之后，`Super + Shift + Ctrl + A` 会在专用终端窗口中启动默认智能体（或者如果你还没有选择，就会调出选择器）。你也可以用 `omarchy agent prompt "Review this project"` 让它直接开始任务。Freebuff 和 DeepSeek Harness 不接受起始提示词，所以它们会打开并将提示词放到你的剪贴板上供你粘贴。以这种方式启动的智能体会以各自的不要停下来询问模式无人值守地运行，所以你要做好它们真的会干活的准备！MiniMax Code 的交互式会话没有这种模式，所以它会像往常一样请求权限。而且由于智能体拒绝记住对你的主目录的信任，从 `$HOME` 启动时改为在 `~/Work` 中开始。

还有终端快捷方式：`a` 在当前终端中内联运行默认智能体，而 `c`、`cx` 和 `cy` 则直接启动 OpenCode、Claude Code 和 Codex（同样处于自动批准模式）。主题更改也会同步到智能体：当你切换 Omarchy 主题时，Claude Code、Pi、OpenCode 和 Hermes（一旦 Omarchy 已安装它）都会跟随变化。

### 你的智能体指令

适用于每个智能体的个人规则放在 `~/.agents/AGENTS.md` 中，紧挨着 `~/.agents/skills` 中的共享技能。在_智能体 > 指令_下打开它，它还会链接到每个保留自己全局文件的框架中：`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`~/.pi/agent/AGENTS.md`、`~/.config/opencode/AGENTS.md`、Copilot 的 `~/.copilot/copilot-instructions.md`，等等。Crush 和 Amp 读取 `~/.config/AGENTS.md` 链接，而 omp、Kimi 和 DeepSeek Harness 直接读取 `~/.agents/AGENTS.md`。选择默认智能体时也会链接它。如果你已经有一个指令文件且尚不存在共享文件，它就会成为共享文件；否则它会作为 `.bak` 保留在链接旁边。在安装另一个智能体后，运行 `omarchy agent instructions` 重新链接。

### 智能体面板

顶栏上有一个智能体图标。在你设置智能体之前，它的面板会引导你登录 Claude、Codex 或 Grok，第一个登录的会成为你的默认智能体。在那之后，该面板将每个订阅都放在一页上：每个智能体和帐户及其套餐、每个 5 小时会话和每周限制的计量表以及距离重置的时间（悬停可查看确切百分比），或剩余的预付余额，上面还有一行轮换显示你所有智能体的使用情况，如本周的 token 数和你最常用的模型。在_做点酷东西_下，它提供用于新主题、插件、应用或游戏的起始提示词，并将任务交给你的默认智能体。应用的构建方式与 Omarchy 自己的 Hype、Monologue 和 Omacut 相同，使用 C++ 和 Qt Quick，遵循 omarchy-make-app 智能体技能，而且它们所需的编译器和 Qt 组件都已安装好。游戏是位于 `~/Games/vibes` 中的单个 three.js 页面，遵循 omarchy-make-game 智能体技能，并且全部从当前主题中的一个 Game Vibes 启动器打开；它们从网络加载 three.js，因此需要网络连接才能启动。Claude Code、Codex、Grok、Kimi、Cursor 及其 Grok Bot 额度、GitHub Copilot、Muse、Antigravity 和 Devin 开箱即用地涵盖了它们的限制，Kimchi 涵盖了其套餐、预付额度和消费预算，而 Hermes、Mistral Vibe 和 Qwen Code 在你使用过后会显示其会话和 token。你通过 pi、omp 或 opencode 使用的提供商套餐和密钥也会显示出来：OpenCode Zen 和 Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan 以及 Synthetic 及其限制；OpenRouter 和 DeepSeek 及其预付余额；Fireworks 及其过去 30 天的消费。你在自己硬件上运行的模型所用的 token 也计入总数；这些模型本身有自己的面板，详见[本地模型](#local-models)。每个智能体都只计一次，计在为其付费的一方名下，无论你通过多少个框架来驱动它。

左键单击顶栏图标或按 `Super + Ctrl + X` 打开面板，右键单击启动你的默认智能体，中键单击刷新。其背后的使用记录由 `omarchy agent usage update` 每 15 分钟重新生成，而且该面板甚至可以通过同步文件夹合并来自你其他机器的使用情况。完整设置请参阅 `$OMARCHY_PATH/shell/plugins/agents/` 下的 README。

### 多个订阅

如果你付费订阅了不止一个 Claude、Codex 或 Grok 套餐——比如一个个人 Max 和一个工作套餐——Omarchy 可以让它们全部保持登录状态，并在它们之间切换。用智能体面板中的 + 添加订阅，它会直接在那里引导你完成，或者使用 `omarchy agent account add claude Work`（或 `codex`，或 `grok`）。如果缺失，它会安装 CLI。某个提供商的第一个帐户会通过你的普通浏览器登录，就在 CLI 一直查找的位置。之后的每一个帐户都通过隐私窗口登录，因此你的浏览器已登录的帐户不会被误选；在那里登录为你要添加的帐户，并先关闭你已打开的任何隐私窗口。千万不要为此注销 CLI：注销会撤销已保存的登录状态，该帐户将不得不重新添加。

要通过 SSH 将你的订阅登录信息复制到另一台 Omarchy 机器，请运行 `omarchy agent account copy user@laptop`。当目标机器未安装接收端时，发送端会提供一个临时接收端，因此较旧的 Omarchy 机器无需更新即可接收帐户。已安装的接收端优先。这会复制所有 Claude、Codex 和 Grok 订阅；添加提供商名称可选择它们，如 `omarchy agent account copy laptop claude`。帐户名称和命令 ID 与源机器匹配，包括目标机器上已存在的帐户。如果无关的目标帐户名称冲突，它们会获得数字后缀，而设置、技能、插件和对话历史则保留在每台机器本地。

目标机器上现有的凭据会保留。已在那里登录的源帐户会同步其名称，但不会替换其凭据；其他帐户会并排添加。要替换匹配帐户已保存的凭据，请在退出目标机器上该帐户的会话后，使用 `omarchy agent account copy --replace laptop claude`。新的目标机器还会获得源机器的活动帐户和切换偏好；已建立的目标机器则保留自己的。

凭据通过 SSH 传输，并存储在目标机器的私有文件中，因此只复制到你信任的机器。这是一次性复制，不是持续同步。Codex 刷新 token 可能被另一台机器轮换，导致复制的登录需要续期；对于在多台机器上同时使用，单独登录仍是最可靠的选择。请参阅[Codex 的帐户身份验证指南](https://developers.openai.com/codex/auth/ci-cd-auth)。

每个提供商有一个帐户处于活动状态，每个新会话都以该帐户启动：`cx`、`cy`、普通的 `claude`、`codex` 或 `grok`、通过 `omarchy agent` 启动的任何内容，以及在 `PATH` 上找到 CLI 的脚本或编辑器。用 `omarchy agent account use work` 切换（用 `omarchy agent account use main` 切回），或在面板中按帐户的编号再按 `Enter`（或单击其 Use 按钮）。正在运行的 Claude 会话也会切换，从其下一条消息开始：每个 Claude 会话都在 `~/.claude` 中运行，该目录始终保存活动帐户的登录状态。由较旧 Omarchy 在帐户自己的文件夹中启动的 Claude 会话会一直保持该登录状态直到退出，因此切换时会列出那些会话，并在它们消失后自行完成。正在运行的 Codex 和 Grok 会话会保持它们启动时所用的帐户。对话历史、设置、技能和插件在帐户之间共享，因此在同一文件夹中执行 `claude --continue` 会在新帐户上从你离开的地方继续。

有多个帐户时，面板会并排显示每个帐户的限制，并标记活动帐户。默认情况下，当活动帐户超过限制的 95% 时，Omarchy 会通知你，单击通知会切换到余量最多的帐户。将鼠标悬停在面板中的帐户行上，单击 Use 旁边出现的 Autoswitch（或按 `m`），或运行 `omarchy agent account mode auto`，让它自行切换；启用时，Autoswitch 会取代 Use 的位置，再次单击它会回到通知模式。添加数字可更改阈值，如 `omarchy agent account mode auto 90`。如果每个帐户都超过阈值，你会收到一次通知，并告知哪个帐户最先释放。在活动帐户距离其阈值 15 个百分点以内时（默认阈值下为 80%），其限制会每三分钟检查一次，而不是每 15 分钟。

`omarchy agent account list` 显示每个帐户及其最新限制，`omarchy agent account remove work` 遗忘一个帐户，而 `omarchy agent account rename primary Hey` 重命名一个帐户（或单击面板中的帐户名称）。这些命令作用于你的默认智能体的帐户；要访问其他提供商，请先命名它，如 `omarchy agent account use codex side`。你在 `~/.claude` 或 `~/.codex` 中已有的登录是_Main_帐户。Codex 的帐户保持原位；Claude 的帐户在另一个帐户活动时会等待在自己的文件夹中。未使用超过约八小时的帐户可能显示_需要登录_；单击它可在面板中直接重新登录该帐户，或切换到它并启动会话，后者会自行刷新登录状态。你用 `claude mcp add` 添加的 MCP 服务器会覆盖每个 Claude 帐户，因为它们都在 `~/.claude` 中运行；对于 Codex 和 Grok，你在添加帐户时已有的服务器会跟随到该帐户，但之后的服务器只能到达你添加它们时所用的帐户。Claude Desktop 保留自己的登录状态，而用 CLI 二进制文件的绝对路径配置的 Codex 或 Grok 工具不会跟随切换。显式的 `CLAUDE_CONFIG_DIR`、`CODEX_HOME` 或 `GROK_HOME` 优先于所选帐户。

### 崩溃诊断

Omarchy 会监听 systemd-coredump 以发现进程崩溃。一旦你选定了默认智能体，你的任何程序发生核心转储都会带来一个“Process crashed”通知——单击它，崩溃就会连同 Omarchy 的 omarchy-diagnose-crash 技能一同交给你的默认智能体，该技能会引导智能体从核心转储中查明事实，并决定该崩溃是否值得向上游报告。你也可以用 `omarchy agent crash <pid>` 对 `coredumpctl list` 中的任何 PID 手动运行它。

该监听默认开启。在_触发器 > 切换 > 关闭崩溃捕获_下将其关闭（或使用 `omarchy toggle crash-capture`）后，通知就会停止；`omarchy agent crash <pid>` 仍可手动使用。

崩溃也可以一次为一个程序静音，这正是诊断结束时提供给你的选项。`omarchy crash mute hyprland` 只停止该程序的通知，`omarchy crash mute hyprland off` 会恢复它们，而单独运行 `omarchy crash mute` 会列出你已静音的程序。它接受二进制文件的路径和名称一样顺利，因此 `omarchy crash mute /usr/bin/hyprland` 的作用相同。为包含空格的名称加引号，如 `omarchy crash mute 'Some App'`。其他一切仍会通知，而且被静音的程序仍会崩溃——这只是隐藏提醒，并不会修复任何东西。

### 桌面应用

_安装 > AI_ 菜单还包含一些图形化 AI 应用：Amp Desktop、Antigravity Desktop、ChatGPT 桌面应用、Claude 桌面应用（Anthropic 的 Linux 测试版，带有 Chat、Cowork 和 Claude Code 标签页）、用于与 xAI 模型聊天的 Grok Bot、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexity 桌面应用和 T3 Code。Grok Bot 是桌面聊天应用。编程智能体是 `grok` 命令。

Hermes Desktop 是你需要了解的那个，因为一台机器只有一个 Hermes，而且它是该应用的：Hermes 只能通过该应用安装，默认智能体运行的 `hermes` 命令也是该应用的。将 Hermes 选为默认智能体所安装的与_安装 > AI_条目安装的是同一东西：该软件包，以及一个由 Hermes 自己的安装程序在 `~/.hermes` 下设置的 Hermes 运行时，首次安装需要几分钟时间。该运行时就是终端 `hermes` 命令、默认智能体和应用都使用的那一个 Hermes，而且它用 `hermes update` 自行更新，而不是等待 Omarchy 发布版本。安装它还会将 Omarchy 主题作为名为 `omarchy` 的皮肤交给 Hermes，当你切换主题时，每个 Hermes 界面都会跟随；如果你不想这样，请在 Hermes 的 Appearance 设置下或用 `/skin` 选择另一个，而 Omarchy 会尊重该选择。在_移除 > AI_下移除该应用会先关闭 Hermes（包括网关），并随之移除该运行时，同时保留你的聊天、记忆和 Hermes 为自己编写的技能，除非你另行指示：它会询问（默认为否）是否也应删除该数据和你的连接设置。

OpenClaw 的桌面体验是其 Control UI，它作为一个由自己的本地网关支持的 Web 应用打开。OpenClaw 位于 `~/.openclaw` 中并自行更新：使用 Control UI 的“Update Gateway”按钮或运行 `openclaw update`，网关就会在新版本上重启。Omarchy 只选择全新安装的起始版本。OpenClaw 也可以是你的默认智能体：在_智能体 > 框架_下选择它会设置 `~/.openclaw` 中的同一个副本，而且该智能体会打开连接到其网关的 OpenClaw 终端 UI。在_移除 > AI_下移除 OpenClaw 会随之移除网关服务和应用，然后询问是否也应删除 `~/.openclaw`，因为它保存着你的聊天和凭据，以及 OpenClaw 本身和它下载的插件运行时；默认保留它，再次安装 OpenClaw 时会重新拾起它。

Herdr Desktop 是 [Herdr](https://herdr.dev) 桌面应用：包含终端和编程智能体的空间、标签页和窗格，当你关闭窗口时它们会继续在其核心中运行。它来自 Herdr 自己的安装程序而非软件包，因此位于 `~/.local/share/herdr-app` 中，当你尚没有核心时，它会在 `~/.local/bin/herdr-core` 中附带其核心，并同时自行更新两者。它与 Omarchy 在 `Super + Ctrl + Return` 上提供的 `herdr` 命令并存而不是替换它，并获得该命令的直接按键：`Alt + Return` 和 `Alt + Shift + Return` 向下或向右拆分窗格，`Alt + Escape` 关闭窗格，`Ctrl + Alt + Arrow` 在窗格之间移动，`Alt + 1..9` 和 `Alt + Left/Right` 选择标签页，`Alt + Up/Down` 在空间之间移动。`Ctrl + 1..9` 选择一个空间，`Alt + Shift + Up/Down` 逐步切换智能体。`Ctrl + Space` 前缀按键仍只用于终端，因为该应用无法为一个序列按住一个普通 Ctrl 键。Omarchy 将这些写入 `~/.config/herdr-app/keys.json`，而 `omarchy-refresh-herdr-app` 会将它们恢复。安装它会选择 Herdr 的 Omarchy 主题，从那时起它会跟随你的 Omarchy 主题。Herdr 为浅色模式保留一个主题，为深色模式保留一个主题，因此在深色和浅色 Omarchy 主题之间切换后，请在 Herdr 的主题选择器中再为另一个模式选择一次 Omarchy。

T3 Code 从 `~/.local/share/t3code` 中的官方 AppImage 版本运行，而不是从软件包运行，因此它会自行更新。安装它时会询问是启动 Stable 还是 Nightly 频道；之后可在 T3 Code 的设置中切换。你的线程和设置位于 `~/.t3` 中，在_移除 > AI_下移除 T3 Code 会随之删除它们。

### 本地模型

在你自己的机器上为你的编程智能体运行开源模型。你的提示词和代码保留在机器上；发送给模型的内容不会离开它。从以下命令开始：

```bash
omarchy models use best text
```

这会为这台机器设置最佳的文本模型，也就是你的智能体使用的那类模型。图像、视频和音乐模型也有各自的最佳选择：`omarchy models use best image`、`video` 或 `music`。运行 `omarchy models use best` 可查看每种类型为这台机器挑选的选择。

或者从顶栏中紧挨着智能体图标的闪光图标，或者用 Super + Ctrl + Shift + X 打开本地模型面板，然后选择 +。当有适合这台机器的模型时，该图标会显示。运行模型的 Podman 随 Omarchy 提供，NVIDIA 机器上的 NVIDIA 容器工具包也是如此，它为模型提供 GPU；如果其中任何一项缺失，首次设置时会安装它。然后 Omarchy 会为这台机器挑选推荐的模型，下载并启动它。预期会下载数十 GB，而且模型运行时会占用机器的大部分内存：Flash Next 在开启完整 256K 上下文时使用约 100 GiB。如果其他模型占用了它所需的内存，它会被设置为已停止状态，一旦你停止其中一个就可启动。该模型在注销时停止；当你需要内存做其他事情时，请自己停止它。

`omarchy models list` 显示选项并解释为什么有些不适合。要设置另一个，请运行 `omarchy models use <recipe>`。如今，`qwen3.8-flash-next-gufo` 和 `qwen3.8-27b-gufo` 可用于 128 GB Strix Halo 机器；27B 使用约 40 GiB，因此为其他工作留出了空间。在一台配备 Intel Arc B390 的 64 GB 笔记本电脑上，`qwen3.6-35b-a3b-llamacpp` 以约 30 GiB 运行。新的配方和推荐会通过软件包随 `omarchy update` 一同到达。

你设置的每个模型在本地模型面板中都有自己的行：播放可启动它，暂停可停止它并释放其内存，终端按钮可在其上打开你的智能体。顶部有一条栏显示机器的内存如何在 Omarchy 本身（系统和你的应用）、每个运行中的模型以及空闲部分之间分配。指向一个已停止的模型时，该栏会显示它是否适合，或者还差多少。当多个模型能同时容纳在内存中时，它们可以同时运行；如果一个无法容纳，Omarchy 会说明应停止哪个正在运行的模型。拖动行按其徽标重新排序，然后在选中的行上按 Delete 可删除模型及其下载。

你设置的每个模型在应用启动器中也有自己的条目，位于模型名称下并带有其制造商的徽标，就像登录 Claude、Codex 或 Grok 会添加一个条目一样。它会在该模型上打开你的智能体，如果模型未运行则先启动它：终端会显示它正在加载，并在就绪后移交给智能体。移除模型会移除其条目。

并非每个模型都用于编程。图像、视频和音乐模型会在 Fantasi 中打开，Fantasi 是 Omarchy 的应用，用于用运行在这台机器上的模型制作图片、视频和音乐，可从它们的启动器条目和它们在本地模型面板中的行打开。

一个模型会完全按照设置时的方式保持运行，因此 Omarchy 更新永远不会在你的智能体下重启模型。当 Omarchy 有更新的运行时或更新的权重可用于你已设置的模型时，其行会显示更新按钮：按下它，模型会在后台重新设置，只下载已更改的内容，并以新版本重启。已停止的模型仍保持已停止。`omarchy models update` 在终端中为每个模型做同样的事情。

在命令行中，`omarchy models start <recipe>` 和 `omarchy models stop <recipe>` 做同样的事情，`omarchy models status` 显示每个模型，而 `omarchy agent --local` 会在你上次启动的模型上打开你的默认智能体。pi、OpenCode 和 Qwen Code 可以使用一个模型；对于任何其他默认智能体，它会在 pi 中打开，或者如果你没有 pi，则在 OpenCode 中打开。pi 还会在自己的模型选择器中列出你设置的每个模型，以及你在已配对机器上设置的模型，因此普通的 `pi` 也能访问它们。任何与 OpenAI 兼容的客户端也可以连接：`status` 显示每个模型的地址（第一个是 `http://127.0.0.1:11435/v1`），配方名称就是模型，密钥位于 `~/.config/omarchy/agent-local/key` 中。

`omarchy models remove <recipe>` 会删除一个模型以及其他模型未使用的下载。

第三方运行时标注了其发布者。Omarchy 在没有网络访问的情况下运行每个模型。

### 本地 LLM

Omarchy 推荐两种运行本地 LLM 模型的方式：LM Studio 和 Ollama。LM Studio 提供 GUI 界面用于查找开放权重模型、安装它们并运行它们。它是轻松上手的绝佳方式。Ollama 提供 CLI 以类似方式做到这一点。但如果你是本地模型新手，我会从 LM Studio 开始。你可以在 Omarchy 菜单的_安装 > AI_下安装任意一个。

### Omarchy 技能

智能体技能帮助 AI 以特定方式使用特定工具，Omarchy 附带其中七个。omarchy 技能涵盖定制系统，如调整你的 Hyprland 配置或调整顶栏。omarchy-make-theme、omarchy-make-plugin、omarchy-make-app 和 omarchy-make-game 涵盖制作新东西，omarchy-contribute 涵盖报告 bug 或向上游发送修复，而 omarchy-diagnose-crash 则处理崩溃的核心转储。它们被符号链接到 Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` 和每个 `~/.hermes/profiles/*/skills`）以及通用 `~/.agents/skills` 位置的技能目录中，因此大多数框架会自动拾取它们。具有相同名称的你自己的技能文件夹优先。

但你应该将这些技能视为实验性功能。不同模型将以不同效果使用它。最好先在计划模式下运行，这样你就能知道智能体想更改什么。然后准备好回滚更改，甚至调用 `omarchy reinstall configs`，如果智能体把一切都搞砸了的话。
