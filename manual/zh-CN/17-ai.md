### 安装和更新智能体

除 Hermes 外，这些智能体都使用 mise 的懒安装：首次启动会安装 CLI，后续启动则直接复用。mise 还会至多每四小时检查一次已安装智能体是否有新版本，就在它启动之前，或者在 shell 提示符下于后台检查。如果该更新失败或你处于离线状态，就会运行已安装的版本。`omarchy update` 会随 Omarchy 的其余部分一起更新已安装的智能体，而 `mup` 只更新 mise 管理的工具。

智能体自己的更新程序，例如 `claude update`、`codex update`，或者应用中的更新按钮，不会更新 mise 管理的安装。`codex update` 会失败，而 `claude update` 可能会报告成功，却安装了一个 mise 并不跟踪的独立副本。如果你更愿意使用智能体原生的安装程序和更新程序，请将其添加到 `disable_tools`；参阅 [预装 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

若要在需要之前安装所有已配置的懒加载工具，请运行 `mise install --include-lazy`。这不仅包括智能体，也包括 Omarchy 的其他默认 CLI 工具。有关安装单个工具或使用你自己的安装方式，参阅 [预装 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

`grok` 通过 mise 的第一方 `grok` 包安装，方式与 `claude` 和 `codex` 相同。运行 `grok`，或在 _Setup > Defaults > Agent_ 下选择它。跳过 x.ai 上的 `curl | bash` 安装程序。那条路径会在 `~/.grok/bin` 中放入第二个副本，将其置于 `PATH` 前部，并覆盖 Omarchy 的封装脚本。

`dsh` 会在 `127.0.0.1:3080` 打开其浏览器 UI，并以启动目录作为其默认工作区。其浏览器 UI 不接受起始提示词，因此 `omarchy agent prompt` 会打开它，并将提示词放到你的剪贴板上供你粘贴。Omarchy 会使用 DeepSeek 的无需批准权限预设来启动它。当你使用 DeepSeek 官方模型 API 时，DeepSeek Harness 会将 session 日志上传到 DeepSeek；在其浏览器 UI 的 _Settings > General > Upload Session Log_ 下关闭该功能。你发送给它的反馈也会随 session 一起上传，除非你使用 `DSH_TELEMETRY_MODE=DISABLED` 来启动它。

### 默认智能体

使用 `omarchy default agent <name>` 或在 Omarchy Menu（`Super + Space`）的 _Setup > Defaults > Agent_ 下选择你的默认智能体。如果该智能体尚未安装，选择它时会先安装它。全新的 Omarchy 会通过一次性通知邀请你做出这一选择。

选择 Claude 时，还会尝试为 Chromium、Chrome、Brave、Brave Origin 和 Edge 设置其浏览器扩展。该扩展的设置适用于所有用户，并且可能会要求输入你的系统密码；取消操作或扩展安装失败，仍会选择并启动 Claude。重启你的浏览器，在出现提示时启用该扩展，并登录 Claude 以完成连接。在 Claude 中运行 `/chrome` 来检查连接。Firefox 和 Zen 不支持此扩展。如果在添加此设置之前 Claude 就已经是你的默认智能体，请再次选择它以安装该扩展。

做出选择后，`Super + Shift + Ctrl + A` 会在专用终端窗口中启动默认智能体（如果你尚未选择，则会调出选择器）。你也可以使用 `omarchy agent prompt "Review this project"` 让它直接开始执行一项任务。Freebuff 和 DeepSeek Harness 不接受起始提示词，因此它们打开时会将提示词放到你的剪贴板上供你粘贴。以这种方式启动的智能体，会在各自无需中途询问的模式下无人值守地运行，所以请做好它们真的会动手做事的准备！MiniMax Code 的交互式会话没有这种模式，因此它会照常请求权限。而且由于智能体拒绝记住对你的主目录的信任，从 `$HOME` 启动时，会改为在 `~/Work` 中启动。

还有终端快捷方式：`a` 会在当前终端中内联运行默认智能体，而 `c`、`cx` 和 `cy` 则直接启动 OpenCode、Claude Code 和 Codex（同样处于它们的自动批准模式下）。主题更改也会同步到这些智能体：当你切换 Omarchy 主题时，Claude Code、Pi、OpenCode 和 Hermes（一旦 Omarchy 已安装它）都会随之变化。

### 智能体面板

顶栏有一个智能体图标。在你设置智能体之前，它的面板会引导你登录 Claude、Codex 或 Grok，第一个登录的会成为你的默认智能体。此后，该面板会将每个订阅都放在同一个页面上：每个智能体和账户及其套餐、每个智能体 5 小时会会话限制和每周限制的计量表以及距离重置的时间（悬停可查看确切百分比），或者剩余的预付余额，位于一行轮换显示你所有智能体使用情况的文字下方，例如本周的 tokens 和你最常用的模型。在 _Make something_ 下，它提供了用于新建主题、插件或应用的入门提示词，可将任务交给你的默认智能体。应用的构建方式与 Omarchy 自己的 Hype、Monologue 和 Omacut 相同，使用 C++ 和 Qt Quick，遵循 omarchy-app agent skill，并且它们所需的编译器和 Qt 组件都已随附安装。Claude Code、Codex、Grok、Kimi、Cursor 及其 Grok Bot 额度、GitHub Copilot、Muse、Antigravity、Kimchi 和 Devin 都开箱即用地涵盖在内，并带有它们的限制，而 Hermes、Mistral Vibe 和 Qwen Code 则会在你使用过它们后显示它们的会话和 tokens。通过 pi、omp 或 opencode 使用的提供商套餐和密钥也会显示出来：OpenCode Zen 和 Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan 以及 Synthetic，并带有它们的限制；Fireworks、OpenRouter 和 DeepSeek，并带有它们的预付余额；以及你在自己硬件上运行的模型，位于 Local models 下。每个智能体只计算一次，归到为其计费的一方名下，无论你通过多少个 harness 来驱动它。

左键点击顶栏图标打开面板，右键点击则启动你的默认智能体。其背后的使用记录由 `omarchy agent usage-update` 每 15 分钟重新生成一次，并且该面板甚至可以通过同步文件夹合并来自你其他机器的使用情况。有关完整设置，参阅 `$OMARCHY_PATH/shell/plugins/agents/` 下的 README。

### 多个订阅

如果你为不止一个 Claude、Codex 或 Grok 套餐付费——比如一个个人 Max 和一个工作套餐——Omarchy 可以让它们全部保持登录状态，并在它们之间切换。使用智能体面板中的 + 添加订阅，它会直接在那里引导你完成，或者使用 `omarchy agent account add claude Work`（或 `codex`，或 `grok`）来添加。如果缺少 CLI，它会安装它。某个提供商的第一个账户通过你的普通浏览器登录，位置正是 CLI 一直查找的位置。此后的每一个账户都通过隐私窗口登录，因此你浏览器已经登录的账户不会被误选；在那里以你正在添加的账户登录，并先关闭你已经打开的任何隐私窗口。千万不要为此退出 CLI 登录：退出会撤销已保存的登录状态，而该账户将不得不重新添加。

若要通过 SSH 将你的订阅登录信息复制到另一台 Omarchy 机器，请运行 `omarchy agent account copy user@laptop`。当目标机器没有安装接收端时，发送方会提供一个临时接收端，因此较旧的 Omarchy 机器无需更新也能接收账户。已安装的接收端优先。此命令复制所有 Claude、Codex 和 Grok 订阅；添加提供商名称可选择它们，如 `omarchy agent account copy laptop claude` 所示。账户名称和命令 ID 与源机器保持一致，包括目标机器上已经存在的账户。如果不相关的目标账户名称冲突，它们会获得数字后缀，并且设置、skills、插件和对话历史记录都保留在每台机器本地。

目标机器现有的凭据会被保留。源账户如果已经在那里登录，其名称会被同步，但不会替换其凭据；其他账户会被添加到其旁边。若要替换匹配账户已保存的凭据，请在退出目标机器上该账户的会话后，使用 `omarchy agent account copy --replace laptop claude`。全新的目标机器还会获得源机器的活动账户和切换偏好；已有配置的目标机器则保留自己的。

凭据通过 SSH 传输，并存储在目标机器的私有文件中，因此请只复制到你信任的机器。这是一次性复制，不是持续同步。Codex refresh tokens 可能会被另一台机器轮换，导致复制的登录信息需要续期；在多台机器上同时使用时，分别登录仍然是最可靠的选择。参阅 [Codex 的账户身份验证指南](https://developers.openai.com/codex/auth/ci-cd-auth)。

每个提供商有一个活动账户，每个新会话都以该账户开始：`cx`、`cy`、普通的 `claude`、`codex` 或 `grok`、通过 `omarchy agent` 启动的任何东西，以及在 `PATH` 上找到 CLI 的脚本或编辑器。使用 `omarchy agent account use work` 切换（并使用 `omarchy agent account use main` 切回），或者在面板中按某个账户的编号然后按 `Enter`（或点击其 Use 按钮）。已经运行的会话会继续使用它们开始时使用的账户。对话历史记录、设置、skills 和插件在账户之间共享，因此在同一个文件夹中运行 `claude --continue` 会在新账户上从你离开的地方继续。

当有多个账户时，面板会并排显示每个账户的限制，并标记活动账户。默认情况下，当活动账户超过某个限制的 95% 时，Omarchy 会通知你，点击该通知会切换到余量最多的账户。将鼠标悬停在面板中某个账户的行上，点击 Use 旁边出现的 Autoswitch（或按 `m`），或者运行 `omarchy agent account mode auto`，即可让它改为自行切换；开启时，Autoswitch 会取代 Use 的位置，再次点击则会恢复为通知。添加一个数字可更改阈值，如 `omarchy agent account mode auto 90` 所示。如果每个账户都超过阈值，你会收到一次通知，并告知哪个账户最先释放额度。当活动账户距离其阈值在 15 个百分点以内时（默认阈值下为 80%），其限制会每三分钟检查一次，而不是每 15 分钟检查一次。

`omarchy agent account list` 会显示每个账户及其最新限制，`omarchy agent account remove work` 会遗忘一个账户，而 `omarchy agent account rename primary Hey` 会重命名一个账户（或在面板中点击账户名称）。这些命令作用于你的默认智能体的账户；若要访问另一个提供商，请先命名它，如 `omarchy agent account use codex side` 所示。你已经在 `~/.claude` 或 `~/.codex` 中拥有的登录是 _Main_ 账户，并保留在原处。某个账户闲置超过约八小时后，可能会显示 _Sign-in required_；点击它可直接在面板中再次登录该账户，或者在其中启动一个会话，它会自行刷新登录状态。添加账户时你拥有的 MCP 服务器会随之转移到该账户，但你之后使用 `claude mcp add` 添加的服务器只会到达你添加它们时所在的账户。Claude Desktop 以及配置了指向 CLI 二进制文件的绝对路径的工具不会跟随切换。显式设置的 `CLAUDE_CONFIG_DIR`、`CODEX_HOME` 或 `GROK_HOME` 优先于所选账户。

### 崩溃诊断

Omarchy 会监视 systemd-coredump 以发现进程崩溃。当某个程序出现段错误时，你会收到一条 “Process crashed” 通知——点击它，崩溃就会连同 Omarchy 的 diagnose-crash skill 一起交给你的默认智能体，该 skill 会引导智能体从 core dump 中查明事实，并决定该崩溃是否值得向上游报告。你也可以使用 `omarchy agent crash <pid>`，针对 `coredumpctl list` 中的任何 PID 手动运行它。

此监视默认开启。在 _Trigger > Toggle > Crash Capture_ 下关闭它（或使用 `omarchy toggle crash-capture`），通知就会停止；`omarchy agent crash <pid>` 仍然可以手动使用。

崩溃也可以一次为一个程序静音，这正是诊断在最后会向你提供的选项。`omarchy crash mute hyprland` 只停止该程序的通知，`omarchy crash mute hyprland off` 会恢复它们，而单独运行 `omarchy crash mute` 则会列出你已静音的内容。它同样接受二进制文件的路径和名称，因此 `omarchy crash mute /usr/bin/hyprland` 效果相同。为带有空格的名称加上引号，如 `omarchy crash mute 'Some App'` 所示。其他一切仍会通知，而被静音的程序仍会崩溃——这只是隐藏提醒，并不会修复任何东西。

### 桌面应用

_Install > AI_ 菜单还包含一些图形化 AI 应用：ChatGPT 桌面应用、Claude 桌面应用（Anthropic 的 Linux beta 版，带有 Chat、Cowork 和 Claude Code 标签页）、用于与 xAI 模型聊天的 Grok Bot、Hermes Desktop、OpenClaw、Perplexity 桌面应用以及 T3 Code。Grok Bot 是桌面聊天应用。编程智能体则是 `grok` 命令。

Hermes Desktop 是需要了解的一个，因为一台机器只有一个 Hermes，而它属于该应用：Hermes 始终只通过该应用安装，默认智能体运行的 `hermes` 命令也是该应用的。将 Hermes 选为默认智能体，会安装与 _Install > AI_ 条目相同的内容：软件包，以及由 Hermes 自己的安装程序在 `~/.hermes` 下设置的一个 Hermes 运行时，首次安装需要几分钟。那个运行时就是终端 `hermes` 命令、默认智能体和应用共同使用的唯一 Hermes，并且它会通过 `hermes update` 自行更新，而不是等待 Omarchy 发布新版本。安装它还会将 Omarchy 主题作为名为 `omarchy` 的皮肤交给 Hermes，当你切换主题时，每个 Hermes 界面都会随之变化；如果你不希望如此，请在 Hermes 的 Appearance 设置下或使用 `/skin` 选择另一个，Omarchy 会保留那个选择不变。在 _Remove > AI_ 下删除该应用时，会先关闭 Hermes，包括 gateway，然后连同那个运行时一起删除，并保留你的聊天、记忆以及 Hermes 为自己编写的 skills，除非你另行指示：它会询问该数据和你的连接设置是否也应一并删除，默认答案为否。

OpenClaw 的桌面体验是它的 Control UI，它会作为一个由其自身本地 gateway 提供支持的 web 应用打开。OpenClaw 位于 `~/.openclaw` 中，并会自行更新：使用 Control UI 的 “Update Gateway” 按钮或运行 `openclaw update`，gateway 就会在新版本上重启。Omarchy 只选择全新安装起始的版本。在 _Remove > AI_ 下删除 OpenClaw 时，会连同 gateway 服务和应用一起删除，然后询问 `~/.openclaw` 是否也应删除，因为那里保存着你的聊天和凭据，以及 OpenClaw 本身和它下载的插件运行时；默认会保留它，再次安装 OpenClaw 时会重新使用它。

T3 Code 通过其位于 `~/.local/share/t3code` 中的官方 AppImage 版本运行，而不是通过软件包运行，因此它会自行更新。安装它时会询问是使用 Stable 还是 Nightly 渠道；之后可在 T3 Code 的设置中切换。你的线程和设置位于 `~/.t3` 中，在 _Remove > AI_ 下删除 T3 Code 时会连同它们一起删除。

### 本地模型

在你自己的机器上为你的编程智能体运行开放模型。你的提示词和代码保留在机器上；发送给模型的任何内容都不会离开它。开始方式如下：

```bash
omarchy agent local use best
```

或者，在顶栏的智能体面板中，选择 + 然后选择 Local AI，当某个模型适合此机器时它会出现。首次使用时，这会安装 Podman，由它运行模型。然后 Omarchy 会为此机器选择推荐的模型，下载它并启动它。请预期会下载数十 GB 的数据，并且在模型运行时会占用机器的大部分内存：Flash Next 在其完整的 256K context 下会使用约 100 GiB。如果其他模型占用了它所需的内存，它会被设置为已停止状态，等你停止其中一个模型后即可启动。该模型会在注销时停止；当你需要将内存用于其他用途时，请自行停止它。

`omarchy agent local list` 会显示各个选项，并解释为什么有些不适合。若要设置另一个，请运行 `omarchy agent local use <recipe>`。目前，`qwen3.8-flash-next-halogen` 和 `qwen3.8-27b-gufo` 可用于 128 GB Strix Halo 机器。新的 recipes 和推荐会随 `omarchy update` 通过软件包到来。

你设置的每个模型都会在智能体面板中拥有自己的一行，位于你的订阅旁边：点击播放可启动它，点击暂停可停止它并释放其内存，点击终端按钮可在其上打开你的智能体。当它们能同时容纳在内存中时，多个模型可以同时运行；如果某个模型容纳不下，Omarchy 会指出应停止哪个正在运行的模型。拖动各行可重新排序，并在选中某行时按 Delete 可删除模型及其下载内容。

从命令行来看，`omarchy agent local start <recipe>` 和 `omarchy agent local stop <recipe>` 作用相同，`omarchy agent local status` 会显示每个模型，而 `omarchy agent --local` 会在你上次启动的模型上打开你的默认智能体（如果你的默认智能体无法使用本地模型，则使用 pi）。任何与 OpenAI 兼容的客户端也可以连接：`status` 会显示每个模型的地址（第一个是 `http://127.0.0.1:11435/v1`），recipe 名称就是模型，密钥位于 `~/.config/omarchy/agent-local/key` 中。

`omarchy agent local remove <recipe>` 会删除一个模型以及没有其他模型使用的下载内容。

第三方运行时会标注其发布者。Omarchy 运行每个模型时都不会提供网络访问。

### 本地 LLMs

Omarchy 推荐两种运行本地 LLM 模型的方式：LM Studio 和 Ollama。LM Studio 提供 GUI 界面，用于查找开放权重模型、安装它们并运行它们。这是轻松上手的好方法。Ollama 提供 CLI 以类似方式做到这一点。但如果你是本地模型的新手，我建议从 LM Studio 开始。你可以在 Omarchy Menu 的 _Install > AI_ 下安装其中任意一个。

### Omarchy Skill

Agent skills 帮助 AI 以特定方式使用特定工具，Omarchy 随附了一个用于定制系统的默认 skill。比如调整你的 Hyprland 配置、调整顶栏，甚至从头创建一个新主题。它被符号链接到 Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` 以及每个 `~/.hermes/profiles/*/skills`）的 skill 目录，以及通用的 `~/.agents/skills` 位置，因此大多数 harness 都会自动拾取它。

但你应该把这个 skill 视为实验性的。不同的模型使用它的效果会不同。最好先在 plan mode 下运行，这样你能了解智能体想要更改什么。然后，如果智能体把一切弄得一团糟，请做好回滚更改、甚至调用 `omarchy reinstall configs` 的准备。
