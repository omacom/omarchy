### 安装和更新智能体

除 Hermes 外，这些智能体都使用 mise 的延迟安装：首次启动时安装 CLI，后续启动则重复使用已安装的版本。mise 还会至多每四小时检查一次已安装智能体是否有新版本，检查时机就在它启动之前，或者在 shell 提示符下在后台进行。如果更新失败或你处于离线状态，就会运行已安装的版本。`omarchy update` 会在更新 Omarchy 其他部分的同时更新已安装的智能体，而 `mup` 只更新由 mise 管理的工具。

智能体自己的更新器，例如 `claude update`、`codex update` 或应用中的更新按钮，不会更新由 mise 管理的安装。`codex update` 会失败，而 `claude update` 可能会报告成功，却安装了一个 mise 不跟踪的独立副本。如果你更愿意使用智能体原生的安装器和更新器，把它加入 `disable_tools`；参见 [预装 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

要在需要之前安装所有已配置的延迟工具，运行 `mise install --include-lazy`。这包括 Omarchy 的其他默认 CLI 工具以及这些智能体。有关安装单个工具或使用你自己的安装，参见 [预装 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

`grok` 通过 mise 的第一方 `grok` 包安装，方式与 `claude` 和 `codex` 相同。运行 `grok`，或在 _Agent > Harness_ 下选择它。跳过 x.ai 上的 `curl | bash` 安装器。那条路径会在 `~/.grok/bin` 中放入第二个副本，将其前置到 `PATH` 上，并覆盖 Omarchy 的包装器。

`dsh` 会在 `127.0.0.1:3080` 打开其浏览器 UI，并将启动目录作为其默认工作区。它的浏览器 UI 不接受起始提示词，因此 `omarchy agent prompt` 打开它时，会将提示词放到你的剪贴板上供你粘贴。Omarchy 使用 DeepSeek 的免审批权限预设启动它。当你使用 DeepSeek 的官方模型 API 时，DeepSeek Harness 会将会话日志上传到 DeepSeek；在其浏览器 UI 的 _Settings > General > Upload Session Log_ 下关闭这一项。你发送给它的反馈也会随会话一起上传，除非你使用 `DSH_TELEMETRY_MODE=DISABLED` 启动它。

### 默认智能体

使用 `omarchy default agent <name>` 或在 Omarchy Menu（`Super + Space`）的 _Agent > Harness_ 下选择你的默认智能体。如果该智能体尚未安装，选择它会先安装它。全新的 Omarchy 会通过一次性通知邀请你做出这一选择。

选择 Claude 还会尝试为 Chromium、Chrome、Brave、Brave Origin 和 Edge 设置其浏览器扩展。该扩展设置适用于所有用户，可能会要求输入你的系统密码；取消或扩展安装失败仍会选择并启动 Claude。重启你的浏览器，如有提示则启用该扩展，并登录 Claude 以完成连接。在 Claude 中运行 `/chrome` 检查连接。Firefox 和 Zen 不支持此扩展。如果在加入此设置之前 Claude 已经是你的默认项，再次选择它即可安装该扩展。

做出选择后，`Super + Shift + Ctrl + A` 会在专用终端窗口中启动默认智能体（如果你尚未选择，则会打开选择器）。你也可以用 `omarchy agent prompt "Review this project"` 让它直接进入一项任务。Freebuff 和 DeepSeek Harness 不接受起始提示词，因此它们打开时提示词会在你的剪贴板上供你粘贴。以这种方式启动的智能体会以各自的不要停下来询问模式无人值守地运行，所以要做好它们真的会动手做事的准备！MiniMax Code 的交互式会话没有这种模式，因此它会像往常一样请求权限。而且由于智能体拒绝记住对你的主目录的信任，从 `$HOME` 启动时改为在 `~/Work` 中启动。

终端中也有快捷方式：`a` 在当前终端中内联运行默认智能体，而 `c`、`cx` 和 `cy` 则直接启动 OpenCode、Claude Code 和 Codex（同样处于自动批准模式）。主题变化也会同步到智能体：当你切换 Omarchy 主题时，Claude Code、Pi、OpenCode 和 Hermes（一旦 Omarchy 安装了它）都会随之变化。

### 你的智能体指令

适用于每个智能体的个人规则放在 `~/.agents/AGENTS.md` 中，紧挨着 `~/.agents/skills` 中的共享技能。在 _Agent > Instructions_ 下打开它，它还会将其链接到每个保留了自己全局文件的 harness 中：`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`~/.pi/agent/AGENTS.md`、`~/.config/opencode/AGENTS.md`、Copilot 的 `~/.copilot/copilot-instructions.md`，等等。Crush 和 Amp 读取 `~/.config/AGENTS.md` 链接，而 omp、Kimi 和 DeepSeek Harness 直接读取 `~/.agents/AGENTS.md`。选择默认智能体时也会链接它。如果你已有的指令文件在尚不存在共享文件时，会成为共享文件；否则它会作为 `.bak` 保存在链接旁边。安装另一个智能体后，运行 `omarchy agent instructions` 重新链接。

### 智能体面板

顶栏有一个智能体图标。在你设置智能体之前，它的面板会引导你登录 Claude、Codex 或 Grok，第一个登录的会成为你的默认智能体。之后，该面板会将每个订阅放在同一页面上：每个智能体和帐户及其套餐、其 5 小时会话限额和每周限额各自的计量条以及距离重置的时间（悬停查看确切百分比），或剩余的预付余额，上方有一行轮流显示你在所有这些智能体上的使用情况，例如本周的 tokens 和你最常用的模型。在 _Make something_ 下，它提供用于新主题、插件、应用或游戏的起始提示词，将任务交给你的默认智能体。应用的构建方式与 Omarchy 自己的 Hype、Monologue 和 Omacut 相同，使用 C++ 和 Qt Quick，遵循 omarchy-make-app 智能体技能，它们所需的编译器和 Qt 组件都已安装。游戏是 `~/Games/vibes` 中的单个 three.js 页面，遵循 omarchy-make-game 智能体技能，所有游戏都从当前主题中的一个 Game Vibes 启动器打开；它们从网络加载 three.js，因此启动时需要网络连接。Claude Code、Codex、Grok、Kimi、Cursor 及其 Grok Bot 额度、GitHub Copilot、Muse、Antigravity、Kimchi 和 Devin 开箱即用地包含在内，并带有它们的限额，Hermes、Mistral Vibe 和 Qwen Code 则会在你使用过它们后显示其会话和 tokens。你通过 pi、omp 或 opencode 使用的提供商套餐和密钥也会显示：带有其限额的 OpenCode Zen 和 Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan 和 Synthetic；带有其预付余额的 Fireworks、OpenRouter 和 DeepSeek；以及你在自己的硬件上运行的模型，位于本地模型下。每个智能体只计算一次，归在向你收费的一方名下，无论你通过多少个 harness 使用它。

左键单击顶栏图标打开面板，右键单击启动你的默认智能体。其背后的使用记录每 15 分钟由 `omarchy agent usage-update` 重新生成，该面板甚至可以通过同步文件夹合并来自你其他机器的使用情况。完整设置参见 `$OMARCHY_PATH/shell/plugins/agents/` 下的 README。

### 多个订阅

如果你付费订阅了多个 Claude、Codex 或 Grok 套餐——例如一个个人 Max 和一个工作套餐——Omarchy 可以让它们全部保持登录状态，并在它们之间切换。使用智能体面板中的 + 添加订阅，它会在那里直接引导你完成，或者使用 `omarchy agent account add claude Work`（或 `codex`，或 `grok`）。如果缺少 CLI，它会安装它。某个提供商的第一个帐户通过你的普通浏览器登录，就在 CLI 一直查找的位置。此后的每一个帐户都通过隐私窗口登录，因此你的浏览器已登录的帐户不会被误选；在那里以你要添加的帐户登录，并先关闭你已打开的任何隐私窗口。切勿为此注销 CLI：注销会撤销已保存的登录，该帐户将不得不重新添加。

要通过 SSH 将你的订阅登录信息复制到另一台 Omarchy 机器，运行 `omarchy agent account copy user@laptop`。当目标机器未安装接收器时，发送方会提供一个临时接收器，因此较旧的 Omarchy 机器无需更新即可接收帐户。已安装的接收器优先。此命令会复制所有 Claude、Codex 和 Grok 订阅；添加提供商名称可选择它们，如 `omarchy agent account copy laptop claude`。帐户名称和命令 ID 与源机器匹配，包括目标机器上已存在的帐户。如果无关的目标帐户名称冲突，它们会获得数字后缀，设置、技能、插件和对话历史则保留在每台机器本地。

目标机器上现有的凭据会保留。已在那里登录的源帐户会同步其名称，但不替换其凭据；其他帐户会添加在其旁边。要为匹配的帐户替换已保存的凭据，请在退出目标机器上该帐户的会话后，使用 `omarchy agent account copy --replace laptop claude`。全新目标机器还会获得源机器的活动帐户和切换偏好；已建立的目标机器则保留自己的。

凭据通过 SSH 传输，并存储在目标机器的私有文件中，因此只能复制到你信任的机器。这是一次性复制，不是持续同步。Codex 刷新 tokens 可能会被另一台机器轮换，导致复制的登录需要续期；对于同时在多台机器上使用，单独登录仍是最可靠的选择。参见 [Codex 的帐户身份验证指南](https://developers.openai.com/codex/auth/ci-cd-auth)。

每个提供商有一个活动帐户，每个新会话都以该帐户启动：`cx`、`cy`、普通的 `claude`、`codex` 或 `grok`、通过 `omarchy agent` 启动的任何内容，以及在 `PATH` 上找到 CLI 的脚本或编辑器。使用 `omarchy agent account use work` 切换（并用 `omarchy agent account use main` 切回），或在面板中按帐户的编号再按 `Enter`（或单击其 Use 按钮）。正在运行的 Claude 会话也会切换，从其下一条消息开始：每个 Claude 会话都在 `~/.claude` 中运行，那里始终保存活动帐户的登录信息。由较旧 Omarchy 在帐户自己的文件夹中启动的 Claude 会话会保留该登录信息，直到它退出为止，因此切换时会列出这些会话，并在它们消失后自行完成。正在运行的 Codex 和 Grok 会话会留在它们启动时使用的帐户上。对话历史、设置、技能和插件在各帐户之间共享，因此在同一文件夹中执行 `claude --continue` 会在新帐户上从你离开的地方继续。

有多个帐户时，面板会并排显示每个帐户的限额，并标记活动帐户。默认情况下，当活动帐户超过限额的 95% 时，Omarchy 会通知你，单击通知会切换到余量最多的帐户。将鼠标悬停在面板中的帐户行上，单击 Use 旁边出现的 Autoswitch（或按 `m`），或运行 `omarchy agent account mode auto`，让它自行切换；它开启时，Autoswitch 会取代 Use 的位置，再次单击它会回到通知模式。添加数字更改阈值，如 `omarchy agent account mode auto 90`。如果每个帐户都超过阈值，你会收到一次通知，并告知哪个帐户最先释放。在活动帐户距离其阈值 15 个点以内时（默认阈值为 80%），其限额每三分钟检查一次，而不是每 15 分钟检查一次。

`omarchy agent account list` 显示每个帐户及其最新限额，`omarchy agent account remove work` 遗忘一个帐户，`omarchy agent account rename primary Hey` 重命名一个帐户（或在面板中单击帐户名称）。这些命令作用于你的默认智能体的帐户；要访问其他提供商，先命名它，如 `omarchy agent account use codex side`。你已在 `~/.claude` 或 `~/.codex` 中拥有的登录是 _Main_ 帐户。Codex 的登录保留在原处；Claude 的登录在另一个帐户活动时，会等待在它自己的文件夹中。帐户超过约八小时未使用，可能会显示 _Sign-in required_；单击它可直接在面板中重新登录该帐户，或切换到它并启动会话，这会自动刷新登录。你使用 `claude mcp add` 添加的 MCP 服务器可供每个 Claude 帐户使用，因为它们都在 `~/.claude` 中运行；对于 Codex 和 Grok，添加帐户时你已有的服务器会随之带到该帐户，但之后添加的服务器只会进入你添加它们的帐户。Claude Desktop 保留其自己的登录，使用指向 CLI 二进制文件的绝对路径配置的 Codex 或 Grok 工具不会跟随切换。显式的 `CLAUDE_CONFIG_DIR`、`CODEX_HOME` 或 `GROK_HOME` 优先于所选帐户。

### 崩溃诊断

Omarchy 监视 systemd-coredump 的进程崩溃。当某个进程发生段错误时，你会收到“Process crashed”通知——单击它，崩溃信息会与 Omarchy 的 diagnose-crash 技能一起交给你的默认智能体，该技能会引导智能体从核心转储中确立事实，并判断该崩溃是否值得向上游报告。你也可以用 `omarchy agent crash <pid>` 手动对 `coredumpctl list` 中的任何 PID 运行它。

监视默认开启。在 _Trigger > Toggle > Crash Capture_ 下（或使用 `omarchy toggle crash-capture`）将其关闭，通知便会停止；`omarchy agent crash <pid>` 仍可手动使用。

崩溃也可以一次为一个程序静默，这也是诊断在最后向你提供的选项。`omarchy crash mute hyprland` 仅停止该程序的通知，`omarchy crash mute hyprland off` 将其恢复，单独使用 `omarchy crash mute` 则列出你已静默的内容。它既接受二进制文件路径，也接受名称，因此 `omarchy crash mute /usr/bin/hyprland` 效果相同。名称中有空格时，加引号，如 `omarchy crash mute 'Some App'`。其他所有内容仍会通知，被静默的程序仍会崩溃——这只是隐藏提醒，并不能修复任何问题。

### 桌面应用

_Install > AI_ 菜单还包含一些图形化 AI 应用：ChatGPT 桌面应用、Claude 桌面应用（Anthropic 的 Linux beta，带有 Chat、Cowork 和 Claude Code 选项卡）、用于与 xAI 模型聊天的 Grok Bot、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexity 桌面应用和 T3 Code。Grok Bot 是桌面聊天应用。编码智能体是 `grok` 命令。

Hermes Desktop 是需要了解的那个，因为一台机器上只有一个 Hermes，而且它是该应用的：Hermes 只能通过该应用安装，默认智能体运行的 `hermes` 命令也是该应用的。选择 Hermes 作为默认智能体会安装 _Install > AI_ 条目安装的相同内容：软件包，以及由 Hermes 自己的安装器在 `~/.hermes` 下设置的 Hermes 运行时，首次安装需要几分钟。该运行时就是终端 `hermes` 命令、默认智能体和该应用共同使用的那一个 Hermes，它使用 `hermes update` 自行更新，而不是等待 Omarchy 发布版本。安装它还会将 Omarchy 主题作为名为 `omarchy` 的皮肤交给 Hermes，当你切换主题时，每个 Hermes 界面都会随之变化；如果你不希望如此，在 Hermes 的 Appearance 设置下或使用 `/skin` 选择另一个，Omarchy 不会干涉该选择。在 _Remove > AI_ 下移除该应用会先关闭 Hermes，包括网关，并带走该运行时，同时保留你的聊天、记忆和 Hermes 为自己编写的技能，除非你另行指示：它会询问是否也应删除该数据和你的连接设置，默认为否。

OpenClaw 的桌面体验是其 Control UI，它作为由其自己的本地网关支持的 Web 应用打开。OpenClaw 位于 `~/.openclaw` 并自行更新：使用 Control UI 的“Update Gateway”按钮或运行 `openclaw update`，网关会以新版本重启。Omarchy 只选择全新安装起始的版本。在 _Remove > AI_ 下移除 OpenClaw 会带走网关服务和应用，然后询问是否也应删除 `~/.openclaw`，因为那里保存你的聊天和凭据以及 OpenClaw 本身和它下载的插件运行时；默认保留它，再次安装 OpenClaw 时会重新使用它。

Herdr Desktop 是 [Herdr](https://herdr.dev) 桌面应用：由 spaces、tabs 和 panes 组成的终端和编码智能体，即使你关闭窗口，它们也会在其核心中继续运行。它来自 Herdr 自己的安装器而不是软件包，因此位于 `~/.local/share/herdr-app`，当你尚没有时，它会在 `~/.local/bin/herdr-core` 中带上其核心，并同时更新两者。它位于 Omarchy 在 `Super + Ctrl + Return` 上提供的 `herdr` 命令旁边，而不是取代它，并获得该命令的直接按键：`Alt + Return` 和 `Alt + Shift + Return` 向下或向右拆分 pane，`Alt + Escape` 关闭它，`Ctrl + Alt + Arrow` 在 panes 之间移动，`Alt + 1..9` 和 `Alt + Left/Right` 选择 tab，`Alt + Up/Down` 在 spaces 之间移动。`Ctrl + 1..9` 选择 space，`Alt + Shift + Up/Down` 逐步切换智能体。`Ctrl + Space` 前缀键仍仅限终端，因为该应用无法将普通 Ctrl 键保持为序列的一部分。Omarchy 将这些写入 `~/.config/herdr-app/keys.json`，`omarchy-refresh-herdr-app` 将其恢复。安装它会选择 Herdr 的 Omarchy 主题，此后会跟随你的 Omarchy 主题。Herdr 为浅色模式保留一个主题，为深色模式保留一个主题，因此在深色和浅色 Omarchy 主题之间切换后，再在 Herdr 的主题选择器中为另一种模式选择一次 Omarchy。

T3 Code 从其位于 `~/.local/share/t3code` 的官方 AppImage 版本运行，而不是从软件包运行，因此它会自行更新。安装它时会询问在 Stable 还是 Nightly 通道启动；之后可在 T3 Code 的设置中切换。你的 threads 和设置位于 `~/.t3`，在 _Remove > AI_ 下移除 T3 Code 会将它们一并带走。

### 本地模型

在你自己的机器上为你的编码智能体运行一个开放模型。你的提示词和代码留在机器上；发送给模型的内容不会离开它。从以下命令开始：

```bash
omarchy agent local use best
```

或者，在顶栏的智能体面板中，选择 + 然后选择 Local AI，当有模型适合这台机器时它会显示。首次使用时，这会安装 Podman（运行模型），在 NVIDIA 机器上还会安装 NVIDIA 的容器工具包（为它们提供 GPU）。然后 Omarchy 选择这台机器的推荐模型，下载它并启动它。预计下载量为数十 GB，且模型运行时将占用大多数机器内存：Flash Next 使用其完整的 256K 上下文时约占 100 GiB。如果其他模型占用了它所需的内存，它会被设置为已停止状态，待你停止一个模型后即可启动。该模型在注销时停止；当你需要内存用于其他事情时，自己停止它。

`omarchy agent local list` 显示选项，并解释为什么有些不适合。要设置另一个，运行 `omarchy agent local use <recipe>`。如今，`qwen3.8-flash-next-gufo` 和 `qwen3.8-27b-gufo` 可用于 128 GB Strix Halo 机器；27B 约占 40 GiB，因此为其他工作留出空间。在配备 Intel 的 Arc B390 的 64 GB 笔记本电脑上，`qwen3.6-35b-a3b-llamacpp` 以约 30 GiB 运行。新 recipe 和推荐随 `omarchy update` 通过软件包到来。

你设置的每个模型在智能体面板中都有一行，紧挨着你的订阅：播放以启动它，暂停以停止它并释放其内存，终端按钮则在其上打开你的智能体。当它们在内存中容得下时，多个模型可以同时运行；如果一个容不下，Omarchy 会指出应停止哪个正在运行的模型。拖动行重新排序，按 Delete 删除所选行以移除模型及其下载。

你设置的每个模型在应用启动器中也有其自己的条目，以模型名称和其制造商的标志显示，如登录 Claude、Codex 或 Grok 时添加的条目一样。它在该模型上打开你的智能体，如果模型尚未运行，会先启动它：终端会显示它正在加载，并在就绪后交给智能体。移除模型会移除其条目。

模型会完全按照设置时的方式持续运行，因此 Omarchy 更新永远不会在你的智能体底下重启一个模型。当 Omarchy 为你已设置的模型提供更新的运行时或更新的权重时，它的那一行会显示一个更新按钮：按下它，模型会在后台重新设置，只下载已更改的内容，并以新版本重启。已停止的模型仍保持停止。`omarchy agent local update` 从终端对每个模型执行相同操作。

在命令行中，`omarchy agent local start <recipe>` 和 `omarchy agent local stop <recipe>` 执行相同操作，`omarchy agent local status` 显示每个模型，`omarchy agent --local` 在你上次启动的模型上打开你的默认智能体。pi、OpenCode 和 Qwen Code 可以使用一个模型；使用任何其他默认项时，它会在 pi 中打开。pi 还会在其自己的模型选择器中列出你已设置的每个模型，以及你在已配对机器上设置的那些模型，因此普通的 `pi` 也能访问它们。任何与 OpenAI 兼容的客户端也可以连接：`status` 显示每个模型的地址（第一个是 `http://127.0.0.1:11435/v1`），recipe 名称即模型，密钥位于 `~/.config/omarchy/agent-local/key`。

`omarchy agent local remove <recipe>` 删除一个模型及没有其他模型使用的下载。

第三方运行时标注有其发布者。Omarchy 在无网络访问的情况下运行每个模型。

### 本地 LLM

Omarchy 推荐两种运行本地 LLM 模型的方式：LM Studio 和 Ollama。LM Studio 提供 GUI 界面，用于查找开放权重模型、安装和运行它们。它是轻松入门的好方法。Ollama 提供 CLI 以类似方式做到这一点。但如果你是本地模型的新手，我会从 LM Studio 开始。你可以在 Omarchy Menu 的 _Install > AI_ 下安装其中任一。

### Omarchy Skill

智能体技能帮助 AI 以特定方式使用特定工具，Omarchy 自带一个用于定制系统的默认技能。如调整你的 Hyprland 配置、调整顶栏，甚至从头创建一个新主题。它符号链接到 Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` 和每个 `~/.hermes/profiles/*/skills`）以及通用的 `~/.agents/skills` 位置的技能目录中，因此大多数 harness 会自动拾取它。

但你应该将此技能视为实验性的。不同模型对其的使用效果各异。最好先在计划模式下运行，这样你能了解智能体想要更改什么。然后准备好回滚更改，甚至在智能体把一切搞得一团糟时调用 `omarchy reinstall configs`。
