### 安装和更新智能体

Hermes 除外，这些智能体都使用 mise 的延迟安装：首次启动时安装 CLI，后续启动则重复使用它。mise 还会检查已安装的智能体是否有新版本，最多每四小时一次，就在它启动之前，或者在 shell 提示符下于后台进行。如果更新失败或你处于离线状态，就会运行已安装的版本。`omarchy update` 会在更新 Omarchy 其他部分的同时更新已安装的智能体，而 `mup` 则只更新 mise 管理的工具。

智能体自身的更新器，例如 `claude update`、`codex update`，或应用中的更新按钮，不会更新 mise 管理的安装。`codex update` 会失败，而 `claude update` 可能会报告成功，但实际上安装了一个 mise 并不追踪的独立副本。如果你更愿意使用智能体原生的安装器和更新器，把它加入 `disable_tools`；见[预装 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

要在需要之前安装所有已配置的延迟工具，运行 `mise install --include-lazy`。这既包括 Omarchy 的其他默认 CLI 工具，也包括这些智能体。安装单个工具或使用你自己的安装，见[预装 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

`grok` 通过 mise 的第一方 `grok` 软件包安装，方式与 `claude` 和 `codex` 一样。运行 `grok`，或在 _Agent > Harness_ 下选择它。跳过 x.ai 上的 `curl | bash` 安装器。那条路径会在 `~/.grok/bin` 中放上第二个副本，把它放在 `PATH` 前面，并覆盖 Omarchy 的包装器。

`dsh` 会在 `127.0.0.1:3080` 打开它的浏览器 UI，并把启动目录作为其默认工作区。它的浏览器 UI 不接受启动提示词，所以 `omarchy agent prompt` 打开它时，会把提示词放在你的剪贴板上供你粘贴。Omarchy 以 DeepSeek 的无需批准权限预设启动它。当你使用 DeepSeek 官方模型 API 时，DeepSeek Harness 会把会话日志上传到 DeepSeek；在其浏览器 UI 的 _Settings > General > Upload Session Log_ 下关闭这一项。你向它发送的反馈也会随会话一起上传，除非你用 `DSH_TELEMETRY_MODE=DISABLED` 启动它。

### 默认智能体

用 `omarchy default agent <name>` 或在 Omarchy 菜单（`Super + Space`）的 _Agent > Harness_ 下选择你的默认智能体。如果智能体尚未安装，选择它会先安装它。全新的 Omarchy 会用一条一次性通知邀请你做出这一选择。

选择 Claude 还会尝试为 Chromium、Chrome、Brave、Brave Origin 和 Edge 设置它的浏览器扩展。该扩展设置适用于所有用户，可能会要求你的系统密码；取消或扩展安装失败后，仍然会选择并启动 Claude。重启你的浏览器，在出现提示时启用扩展，并登录 Claude 以完成连接。在 Claude 中运行 `/chrome` 检查连接状态。Firefox 和 Zen 不支持这个扩展。如果在加入这项设置之前 Claude 就已经是你的默认项，再次选择它以安装扩展。

做出选择后，`Super + Shift + Ctrl + A` 会在一个专用终端窗口中启动默认智能体（如果你还没有选择，则会调出选择器）。你也可以让它直接进入一项任务，如 `omarchy agent prompt "Review this project"`。Freebuff 和 DeepSeek Harness 不接受启动提示词，所以它们打开时改为把提示词放在你的剪贴板上供你粘贴。以这种方式启动的智能体会以各自的不要停下来询问模式无人值守地运行，所以要做好准备，它们真的会动手做事！MiniMax Code 的交互式会话没有这种模式，所以它会像往常一样请求权限。而且由于智能体拒绝记住对你的主目录的信任，从 `$HOME` 启动时会改为从 `~/Work` 开始。

也有终端快捷方式：`a` 会在当前终端内联运行默认智能体，而 `c`、`cx` 和 `cy` 则直接启动 OpenCode、Claude Code 和 Codex（同样处于各自的自动批准模式）。主题变化也会同步到智能体：当你切换 Omarchy 主题时，Claude Code、Pi、OpenCode 和 Hermes（一旦 Omarchy 安装了它）都会随之跟随。

### 你的智能体指令

面向每个智能体的个人规则都放在 `~/.agents/AGENTS.md` 中，紧挨着位于 `~/.agents/skills` 的共享技能。在 _Agent > Instructions_ 下打开它，它还会把该文件链接到每一个维护自己全局文件的 harness 中：`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`~/.pi/agent/AGENTS.md`、`~/.config/opencode/AGENTS.md`、Copilot 的 `~/.copilot/copilot-instructions.md`，等等。Crush 和 Amp 读取 `~/.config/AGENTS.md` 链接，而 omp、Kimi 和 DeepSeek Harness 则直接读取 `~/.agents/AGENTS.md`。选择默认智能体时也会链接它。如果你已有的指令文件此前并不存在共享版本，它就会成为共享的那一个；否则它会被保留在链接旁，命名为 `.bak`。在安装另一个智能体后，运行 `omarchy agent instructions` 重新链接。

### 智能体面板

顶栏上有一个智能体图标。在你设置智能体之前，它的面板会引导你登录 Claude、Codex 或 Grok，第一个登录的就会成为你的默认智能体。此后，该面板会把每一个订阅都放在同一页上：每个智能体和帐户及其套餐、针对其 5 小时会话限制和每周限制各自的计量条以及距离重置的时间（悬停可查看确切百分比），或者剩余的预付余额，上方还有一行轮换显示你全部使用情况的内容，例如本周的 token 数和你最常用的模型。在 _Make something_ 下，它提供用于新建主题、插件、应用或游戏的入门提示词，把任务交给你的默认智能体。应用的构建方式与 Omarchy 自家的 Hype、Monologue 和 Omacut 一样，使用 C++ 和 Qt Quick，遵循 omarchy-make-app 智能体技能，它们需要的编译器和 Qt 组件都已安装。游戏是位于 `~/Games/vibes` 中的单个 three.js 页面，遵循 omarchy-make-game 智能体技能，全部从当前主题中的一个 Game Vibes 启动器打开；它们从网络加载 three.js，所以启动时需要网络连接。Claude Code、Codex、Grok、Kimi、Cursor 及其 Grok Bot 额度、GitHub Copilot、Muse、Antigravity、Kimchi 和 Devin 开箱即用地被涵盖，并带有它们的限制，而 Hermes、Mistral Vibe 和 Qwen Code 会在你使用过它们后显示其会话和 token。通过 pi、omp 或 opencode 使用的服务商套餐和密钥也会出现：OpenCode Zen 和 Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan 和 Synthetic，带有它们的限制；Fireworks、OpenRouter 和 DeepSeek，带有它们的预付余额；以及你在自己硬件上运行的模型，列在 Local models 下。每个智能体只计数一次，计入向你收费的一方名下，无论你通过多少个 harness 来驱动它。

左键单击顶栏图标打开面板，右键单击则启动你的默认智能体。其背后的使用记录每 15 分钟由 `omarchy agent usage-update` 重新生成，该面板甚至可以通过一个同步文件夹合并来自你其他机器的使用情况。完整设置见 `$OMARCHY_PATH/shell/plugins/agents/` 下的 README。

### 多个订阅

如果你付费购买了不止一个 Claude、Codex 或 Grok 套餐——比如一个个人 Max 和一个工作套餐——Omarchy 可以让它们全部保持登录状态，并在它们之间切换。用智能体面板中的 + 添加一个订阅，它会就在那里引导你完成，或者用 `omarchy agent account add claude Work`（或 `codex`，或 `grok`）。如果 CLI 缺失，它会安装它。某个服务商的第一个帐户通过你的普通浏览器登录，就在 CLI 一直查看的位置。之后的每一个帐户都通过隐私窗口登录，这样你浏览器已经登录的帐户就不会被误选；在那里以你正在添加的帐户身份登录，并先关闭你已打开的任何隐私窗口。切勿为此注销 CLI：注销会撤销已保存的登录状态，那个帐户将不得不重新添加。

要通过 SSH 把你的订阅登录信息复制到另一台 Omarchy 机器，运行 `omarchy agent account copy user@laptop`。当目标机器没有安装接收器时，发送方会提供一个临时接收器，所以较旧的 Omarchy 机器无需更新就能接收帐户。已安装的接收器优先。此命令复制所有 Claude、Codex 和 Grok 订阅；添加服务商名称以选择它们，如 `omarchy agent account copy laptop claude`。帐户名称和命令 ID 与源机器保持一致，包括目标机器上已存在的帐户。无关的目标帐户在名称冲突时会获得数字后缀，设置、技能、插件和对话历史都保留在各自机器本地。

目标机器已有的凭据会被保留。对于已在那里登录的源帐户，其名称会被同步，但不会替换其凭据；其他帐户则会添加在它旁边。要替换匹配帐户已保存的凭据，先退出目标机器上该帐户的会话，然后使用 `omarchy agent account copy --replace laptop claude`。全新的目标机器还会获得源机器的活动帐户和切换偏好；已有使用历史的目标机器则保留自己的。

凭据通过 SSH 传输，并存储在目标机器的私有文件中，所以只复制到你信任的机器。这是一次性复制，不是持续同步。Codex 刷新 token 可能会被另一台机器轮换，导致复制的登录状态需要续期；在多台机器上同时使用时，分开登录仍然是最可靠的选择。见[Codex 的帐户身份验证指南](https://developers.openai.com/codex/auth/ci-cd-auth)。

每个服务商有一个活动帐户，每个新会话都以它开始：`cx`、`cy`、普通的 `claude`、`codex` 或 `grok`、通过 `omarchy agent` 启动的任何东西，以及在 `PATH` 上找到 CLI 的脚本或编辑器。用 `omarchy agent account use work` 切换（用 `omarchy agent account use main` 切回），或者在面板中按某个帐户的编号再按 `Enter`（或点击其 Use 按钮）。正在运行的 Claude 会话也会切换，从它们的下一条消息开始：每个 Claude 会话都在 `~/.claude` 中运行，那里始终保存着活动帐户的登录状态。由较旧 Omarchy 在帐户自己的文件夹中启动的 Claude 会话会一直保持那次登录直到它退出，所以切换操作会列出那些会话的名称，并在它们消失后自行完成。正在运行的 Codex 和 Grok 会话则保持它们启动时所用的帐户。对话历史、设置、技能和插件在各帐户之间共享，所以在同一文件夹中执行 `claude --continue` 会在新帐户上从你离开的地方继续。

当帐户多于一个时，面板会并排显示每个帐户的限制，并标记活动的那一个。默认情况下，当活动帐户超过某项限制的 95% 时，Omarchy 会通知你，点击通知会切换到余量最多的帐户。将鼠标悬停在面板中某个帐户的行上，点击 Use 旁出现的 Autoswitch（或按 `m`），或运行 `omarchy agent account mode auto`，让它自行切换；开启期间，Autoswitch 会取代 Use 的位置，再次点击它则回到通知模式。添加一个数字以更改阈值，如 `omarchy agent account mode auto 90`。如果每个帐户都超过阈值，你会收到一次通知，同时得知哪个帐户最先释放额度。当活动帐户距离其阈值在 15 个百分点以内时（默认情况下为 80%），它的限制会每三分钟检查一次，而不是每 15 分钟一次。

`omarchy agent account list` 显示每个帐户及其最新限制，`omarchy agent account remove work` 遗忘一个帐户，`omarchy agent account rename primary Hey` 则重命名一个帐户（或点击面板中的帐户名）。这些命令作用于你的默认智能体的帐户；要访问其他服务商，先点名它，如 `omarchy agent account use codex side`。你已经在 `~/.claude` 或 `~/.codex` 中拥有的登录是 _Main_ 帐户。Codex 的帐户保持原位；Claude 的帐户在另一个帐户活动期间，会在它自己的文件夹中等待。闲置超过约八小时的帐户可能会显示 _Sign-in required_；点击它可以直接在面板中为该帐户重新登录，或者切换到它并启动一个会话，这会自动刷新登录状态。你用 `claude mcp add` 添加的 MCP 服务器会到达每个 Claude 帐户，因为它们都在 `~/.claude` 中运行；对于 Codex 和 Grok，你在添加帐户时已有的服务器会随之带到该帐户，但之后的服务器只能到达你添加它们的那个帐户。Claude Desktop 保留自己的一套登录，而配置为使用 CLI 二进制文件绝对路径的 Codex 或 Grok 工具不会跟随切换。显式的 `CLAUDE_CONFIG_DIR`、`CODEX_HOME` 或 `GROK_HOME` 优先于所选帐户。

### 崩溃诊断

Omarchy 监视 systemd-coredump 以发现进程崩溃。当某个程序发生段错误时，你会收到一条 "Process crashed" 通知——点击它，崩溃信息就会连同 Omarchy 的 diagnose-crash 技能一起交给你的默认智能体，该技能会引导智能体从核心转储中确立事实，并判断这次崩溃是否值得向上游报告。你也可以针对 `coredumpctl list` 中的任何 PID 手动运行它，使用 `omarchy agent crash <pid>`。

监视功能默认开启。在 _Trigger > Toggle > Crash Capture_ 下（或用 `omarchy toggle crash-capture`）关闭它，通知就会停止；`omarchy agent crash <pid>` 仍然可以手动使用。

崩溃通知也可以一次针对一个程序静默，这正是诊断在最后向你提供的选项。`omarchy crash mute hyprland` 只停止该程序的通知，`omarchy crash mute hyprland off` 使其恢复，单独执行 `omarchy crash mute` 则列出你已静默的内容。它同样乐意接受二进制文件的路径和名称，所以 `omarchy crash mute /usr/bin/hyprland` 做的是同一件事。为带有空格的名称加引号，如 `omarchy crash mute 'Some App'`。其他一切仍会通知，被静默的程序也仍会崩溃——这只是隐藏提醒，并不能修复任何东西。

### 桌面应用

_Install > AI_ 菜单还包含一些图形化 AI 应用：Antigravity Desktop、ChatGPT 桌面应用、Claude 桌面应用（Anthropic 的 Linux 测试版，带有 Chat、Cowork 和 Claude Code 标签页）、用于与 xAI 模型聊天的 Grok Bot、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexity 桌面应用和 T3 Code。Grok Bot 是桌面聊天应用。编码智能体则是 `grok` 命令。

Hermes Desktop 是需要了解的那一个，因为一台机器上只有一个 Hermes，而且它是属于这个应用的：Hermes 从来只通过该应用安装，默认智能体运行的 `hermes` 命令也是该应用的。把 Hermes 选为默认智能体安装的正是 _Install > AI_ 条目所安装的同一内容：软件包，以及一个由 Hermes 自己的安装器在 `~/.hermes` 下设置的 Hermes 运行时，首次安装需要几分钟时间。那个运行时正是终端的 `hermes` 命令、默认智能体和该应用全都使用的那一个 Hermes，它通过 `hermes update` 自行更新，而不是等待 Omarchy 发布新版本。安装它还会把 Omarchy 主题作为一个名为 `omarchy` 的皮肤交给 Hermes，每一个 Hermes 界面都会在你切换主题时随之跟随；如果你不希望如此，在 Hermes 的 Appearance 设置下或用 `/skin` 选择另一个，Omarchy 不会干涉那个选择。在 _Remove > AI_ 下移除该应用会先关闭 Hermes（包括网关），并随之带走那个运行时，同时保留你的聊天、记忆以及 Hermes 为自己编写的技能，除非你另行指示：它会询问，默认回答为否，是否也删除那些数据和你的连接设置。

OpenClaw 的桌面体验是它的 Control UI，它作为一个 Web 应用打开，由它自己的本地网关提供支持。OpenClaw 位于 `~/.openclaw` 中，并会自行更新：使用 Control UI 的 "Update Gateway" 按钮，或运行 `openclaw update`，网关就会在新版本上重启。Omarchy 只选择全新安装从哪个版本开始。在 _Remove > AI_ 下移除 OpenClaw 会随之带走网关服务和该应用，然后询问是否也应删除 `~/.openclaw`，因为那里保存着你的聊天和凭据，以及 OpenClaw 本身和它下载的插件运行时；默认会保留它，再次安装 OpenClaw 时会重新接管它。

Herdr Desktop 是 [Herdr](https://herdr.dev) 桌面应用：由空间、标签页以及终端和编码智能体的窗格构成，即使你关掉窗口，它们也会在其核心中继续运行。它来自 Herdr 自己的安装器，而不是软件包，所以它位于 `~/.local/share/herdr-app` 中，在你尚且没有时会在 `~/.local/bin/herdr-core` 中附带其核心，并同时更新自身。它与 Omarchy 在 `Super + Ctrl + Return` 上提供的 `herdr` 命令并存，而不是取代它，并获得该命令的直接按键：`Alt + Return` 和 `Alt + Shift + Return` 向下或向右拆分窗格，`Alt + Escape` 关闭它，`Ctrl + Alt + Arrow` 在窗格之间移动，`Alt + 1..9` 和 `Alt + Left/Right` 选择标签页，`Alt + Up/Down` 在空间之间移动。`Ctrl + 1..9` 选择一个空间，`Alt + Shift + Up/Down` 在智能体之间步进。`Ctrl + Space` 前缀键仅保留在终端中使用，因为该应用无法为一个连招一直按住普通的 Ctrl 键。Omarchy 将这些写入 `~/.config/herdr-app/keys.json`，`omarchy-refresh-herdr-app` 会把它们恢复。安装它会选定 Herdr 的 Omarchy 主题，从那时起它就会跟随你的 Omarchy 主题。Herdr 为浅色模式保留一个主题，为深色模式保留一个主题，所以在一个深色和一个浅色 Omarchy 主题之间切换后，再在 Herdr 的主题选择器中为另一种模式选择一次 Omarchy。

T3 Code 从其位于 `~/.local/share/t3code` 中的官方 AppImage 版本运行，而不是从软件包运行，所以它会自行更新。安装它时会询问是从 Stable 还是 Nightly 通道开始；之后可在 T3 Code 的设置中切换。你的线程和设置位于 `~/.t3` 中，在 _Remove > AI_ 下移除 T3 Code 会随之带走它们。

### 本地模型

在你自己的机器上为你的编码智能体运行一个开放模型。你的提示词和代码都停留在这台机器上；发送给模型的任何内容都不会离开它。从此开始：

```bash
omarchy agent local use best
```

或者，在顶栏的智能体面板中，选择 + 然后选择 Local AI，当有模型适合这台机器时它会出现。第一次使用时，这会安装运行这些模型的 Podman，在 NVIDIA 机器上还会安装 NVIDIA 的容器工具包，让模型使用 GPU。然后 Omarchy 选出适合这台机器的推荐模型，下载它并启动它。预计下载量为数十 GB，并且在模型运行时，机器的大部分内存会被占用：Flash Next 使用其完整的 256K 上下文时大约占用 100 GiB。如果其他模型占用了它需要的内存，它会被设置为停止状态，一待你停掉某个模型就可以启动。该模型在注销时停止；当你需要内存做其他事情时，自己停掉它。

`omarchy agent local list` 显示可选项，并解释为什么有些不适合。要再设置一个，运行 `omarchy agent local use <recipe>`。如今，`qwen3.8-flash-next-gufo` 和 `qwen3.8-27b-gufo` 可用于 128 GB Strix Halo 机器；27B 约占 40 GiB，所以会为其他工作留出空间。在配备 Intel Arc B390 的 64 GB 笔记本电脑上，`qwen3.6-35b-a3b-llamacpp` 在约 30 GiB 中运行。新的配方和推荐会随 `omarchy update` 一起通过软件包到达。

你设置的每个模型在智能体面板中都会有自己的单独一行，紧挨着你的订阅：播放按钮启动它，暂停按钮停止它并释放其内存，终端按钮则在它上面打开你的智能体。当多个模型能同时装进内存时，它们可以同时运行；如果某一个装不下，Omarchy 会说明该停止哪个正在运行的模型。拖动行可重新排序，按 Delete 选中一行即可移除一个模型及其下载。

你设置的每个模型在应用启动器中也会有自己的条目，以该模型的名称并带有其制造者的标志，就像登录 Claude、Codex 或 Grok 时会增加一个一样。它会在那个模型上打开你的智能体，如果模型尚未运行，会先启动它：终端会显示它正在加载，一旦它就绪就转交给智能体。移除一个模型会移除它的条目。

一个模型保持完全按其设置时的状态运行，所以 Omarchy 更新永远不会在你的智能体手下重启任何一个模型。当 Omarchy 拥有针对你已设置模型的更新运行时或更新权重时，那一行会显示一个更新按钮：按下它，模型就会在后台重新设置，只下载有变化的部分，并以新版本重启。原本停止的模型仍会保持停止。`omarchy agent local update` 在终端中对每个模型做同样的事情。

在命令行中，`omarchy agent local start <recipe>` 和 `omarchy agent local stop <recipe>` 做同样的事情，`omarchy agent local status` 显示每一个模型，`omarchy agent --local` 则在你上次启动的模型上打开你的默认智能体。pi、OpenCode 和 Qwen Code 可以使用一个模型；搭配任何其他默认项时则会在 pi 中打开。pi 还会在它自己的模型选择器中列出你设置的每一个模型，以及那些位于你已配对机器上的模型，所以直接运行 `pi` 也能到达它们。任何与 OpenAI 兼容的客户端也可以连接：`status` 显示每个模型的地址（第一个是 `http://127.0.0.1:11435/v1`），配方名称就是模型，密钥位于 `~/.config/omarchy/agent-local/key` 中。

`omarchy agent local remove <recipe>` 删除一个模型，以及没有其他模型使用的下载内容。

第三方运行时会标注其发布者。Omarchy 在没有网络访问的情况下运行每个模型。

### 本地 LLM

Omarchy 推荐两种运行本地 LLM 模型的方式：LM Studio 和 Ollama。LM Studio 提供一个 GUI 界面，用于查找开放权重模型、安装它们并运行它们。这是轻松上手的好方法。Ollama 则提供一个 CLI，以类似方式做同样的事情。但如果你是本地模型的新手，我会从 LM Studio 开始。你可以在 Omarchy 菜单的 _Install > AI_ 下安装其中任何一个。

### Omarchy Skill

智能体技能帮助 AI 以特定方式使用特定工具，Omarchy 附带一个默认技能，用于量身定制系统。就如调整你的 Hyprland 配置、调整顶栏，或者甚至从零开始创建一个新主题。它被符号链接到 Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` 以及每个 `~/.hermes/profiles/*/skills`）的技能目录，以及通用的 `~/.agents/skills` 位置，所以大多数 harness 会自动拾取它。

但你应该把这个技能视为实验性的。不同的模型会以不同的效果使用它。最好先在计划模式下运行，这样你就能有个概念，了解智能体想要更改什么。然后准备好回滚更改，或者甚至在智能体把一切搞得一团糟时调用 `omarchy reinstall configs`。
