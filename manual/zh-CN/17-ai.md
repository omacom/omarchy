### 安装和更新智能体

除 Hermes 和 OpenClaw 外，这些智能体使用 mise 的延迟安装：首次启动时安装 CLI，之后的启动会重复使用它。mise 还会最多每四小时检查一次已安装智能体是否有新版本，就在它启动之前，或在 shell 提示符下于后台检查。如果该更新失败或你处于离线状态，则运行已安装的版本。`omarchy update` 会在更新 Omarchy 其余部分的同时更新已安装的智能体，而 `mup` 仅更新由 mise 管理的工具。

智能体自身的更新程序，例如 `claude update`、`codex update` 或应用中的更新按钮，不会更新由 mise 管理的安装。`codex update` 会失败，而 `claude update` 可能报告成功，却安装了 mise 不跟踪的单独副本。如果你更愿意使用智能体的原生安装程序和更新程序，请将其添加到 `disable_tools`；请参阅 [预装 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

要在需要之前安装所有已配置的延迟工具，请运行 `mise install --include-lazy`。这包括 Omarchy 的其他默认 CLI 工具以及智能体。有关安装单个工具或使用你自己的安装，请参阅 [预装 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

`grok` 通过 mise 的第一方 `grok` 包安装，与 `claude` 和 `codex` 的方式相同。运行 `grok`，或在 _Agent > Harness_ 下选择它。跳过 x.ai 上的 `curl | bash` 安装程序。该路径会在 `~/.grok/bin` 中放入第二个副本，将其前置到 `PATH` 上，并覆盖 Omarchy 的包装器。

`dsh` 在 `127.0.0.1:3080` 打开其浏览器 UI，并以启动目录作为其默认工作区。其浏览器 UI 不接受起始提示词，因此 `omarchy agent prompt` 打开它时，会将提示词放在你的剪贴板上供你粘贴。Omarchy 使用 DeepSeek 的免审批权限预设启动它。当你使用 DeepSeek 的官方模型 API 时，DeepSeek Harness 会将会话日志上传到 DeepSeek；在其浏览器 UI 的 _Settings > General > Upload Session Log_ 下关闭该功能。你发送给它的反馈也会随会话一同上传，除非你使用 `DSH_TELEMETRY_MODE=DISABLED` 启动它。

### 默认智能体

使用 `omarchy default agent <name>` 或在 Omarchy Menu（`Super + Space`）的 _Agent > Harness_ 下选择你的默认智能体。如果智能体尚未安装，选择它时会先安装它，并且它还会在应用启动器中获得自己的启动器，位于 Agent 旁边。全新的 Omarchy 会通过一次性通知邀请你做出此选择。

选择 Claude 还会尝试为 Chromium、Chrome、Brave、Brave Origin 和 Edge 设置其浏览器扩展。该扩展的设置适用于所有用户，并且可能要求你输入系统密码；取消或扩展安装失败仍会选择并启动 Claude。重启你的浏览器，在提示时启用扩展，并登录 Claude 以完成连接。在 Claude 中运行 `/chrome` 检查连接。Firefox 和 Zen 不支持此扩展。如果在此设置添加之前 Claude 已经是你的默认项，请重新选择它以安装扩展。

选择后，`Super + Shift + Ctrl + A` 会在专用终端窗口中启动默认智能体（如果你尚未选择，则会调出选择器）。你还可以使用 `omarchy agent prompt "Review this project"` 让它直接开始执行任务。Freebuff 和 DeepSeek Harness 不接受起始提示词，因此它们打开时改为将提示词放在你的剪贴板上供你粘贴。以这种方式启动的智能体会在各自的不要停下来询问模式下无人值守地运行，所以要做好它们真的会做事的准备！MiniMax Code 的交互式会话没有这种模式，因此它会像往常一样请求权限。而且由于智能体拒绝记住对你主目录的信任，从 `$HOME` 启动时会在 `~/Work` 中开始。

也有终端快捷方式：`a` 在当前终端中内联运行默认智能体，而 `c`、`cx` 和 `cy` 直接启动 OpenCode、Claude Code 和 Codex（同样处于自动批准模式）。主题更改也会同步到智能体：当你切换 Omarchy 主题时，Claude Code、Pi、OpenCode 和 Hermes（一旦 Omarchy 已安装它）都会随之更改。

### 你的智能体指令

适用于每个智能体的个人规则放在 `~/.agents/AGENTS.md` 中，紧挨着 `~/.agents/skills` 中的共享技能。在 _Agent > Instructions_ 下打开它，它还会将其链接到每个保留其自有全局文件的框架中：`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`~/.pi/agent/AGENTS.md`、`~/.config/opencode/AGENTS.md`、Copilot 的 `~/.copilot/copilot-instructions.md`，依此类推。Crush 和 Amp 读取 `~/.config/AGENTS.md` 链接，而 omp、Kimi 和 DeepSeek Harness 直接读取 `~/.agents/AGENTS.md`。选择默认智能体也会链接它。如果你已有的指令文件在尚无共享文件时，就会成为共享文件；否则它会作为 `.bak` 保留在链接旁边。安装另一个智能体后，运行 `omarchy agent instructions` 重新链接。

### 智能体面板

顶部栏有一个智能体图标。在你设置智能体之前，其面板会引导你登录 Claude、Codex 或 Grok，第一个登录的会成为你的默认智能体。之后，该面板将每个订阅都放在一页上：每个智能体和账户及其套餐、每个 5 小时会话限额和每周限额的计量表以及距离重置的时间（悬停可查看确切百分比），或剩余的预付余额，位于一行内容的下方，该行会轮流显示你在所有这些智能体上的使用情况，例如本周的 tokens 和你最常用的模型。在 _Make something cool_ 下，它为新主题、插件、应用或游戏提供入门提示词，将任务交给你的默认智能体。应用按照 Omarchy 自有的 Hype、Monologue 和 Omacut 的方式构建，使用 C++ 和 Qt Quick，遵循 omarchy-make-app 智能体技能，它们所需的编译器和 Qt 组件已随附安装。游戏是位于 `~/Games/vibes` 中的单个 three.js 页面，遵循 omarchy-make-game 智能体技能，并且全部从当前主题中的一个 Game Vibes 启动器打开；它们从网络加载 three.js，因此需要连接才能启动。Claude Code、Codex、Grok、Kimi、Cursor 及其 Grok Bot 额度、GitHub Copilot、Muse、Antigravity 和 Devin 开箱即用地涵盖了它们的限额，Kimchi 涵盖了其套餐、预付额度和支出预算，而 Hermes、Mistral Vibe 和 Qwen Code 在你使用过它们后会显示其会话和 tokens。你通过 pi、omp 或 opencode 使用的提供商套餐和密钥也会显示出来：OpenCode Zen 和 Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan 以及 Synthetic，并包含它们的限额；OpenRouter 和 DeepSeek 及其预付余额；Fireworks 及其过去 30 天的支出。你在自有硬件上运行的模型的 tokens 也计入总计；模型本身有其自己的面板，在 [本地模型](#local-models) 下有说明。每个智能体只计一次，按向其收费的一方计，无论你通过多少个框架驱动它。

左键单击栏图标或按 `Super + Ctrl + X` 打开面板，右键单击启动你的默认智能体，中键单击刷新。它背后的使用记录每 15 分钟由 `omarchy agent usage update` 重新生成，并且该面板甚至可以通过同步文件夹合并来自你其他机器的使用情况。有关完整设置，请参阅 `$OMARCHY_PATH/shell/plugins/agents/` 下的 README。

### 多个订阅

如果你购买了多个 Claude、Codex 或 Grok 套餐——例如一个个人 Max 和一个工作套餐——Omarchy 可以让它们全部保持登录状态，并在它们之间切换。使用智能体面板中的 + 添加订阅，它会直接在那里引导你完成，或者使用 `omarchy agent account add claude Work`（或 `codex`，或 `grok`）。如果 CLI 缺失，它会安装它。某个提供商的第一个账户通过你的普通浏览器登录，就在 CLI 一直查找的位置。之后的每个账户都通过隐私窗口登录，因此你的浏览器已登录的账户不会被错误地选中；在那里登录你要添加的账户，并先关闭你已打开的任何隐私窗口。切勿为此退出 CLI：退出会撤销已保存的登录，该账户将不得不重新添加。

要通过 SSH 将你的订阅登录信息复制到另一台 Omarchy 机器，请运行 `omarchy agent account copy user@laptop`。当目标机器未安装接收器时，发送方会提供一个临时接收器，因此较旧的 Omarchy 机器无需更新即可接收账户。已安装的接收器优先。此命令会复制所有 Claude、Codex 和 Grok 订阅；添加提供商名称可选择它们，如 `omarchy agent account copy laptop claude`。账户名称和命令 ID 与源机器匹配，包括目标机器上已存在的账户。无关的目标账户如果名称冲突，会获得数字后缀，设置、技能、插件和对话历史则保留在每台机器本地。

现有的目标凭据会保留。已在那里登录的源账户会同步其名称，而不替换其凭据；其他账户会添加到其旁边。要替换匹配账户已保存的凭据，请在目标机器上退出该账户的会话后，使用 `omarchy agent account copy --replace laptop claude`。全新的目标机器还会获得源机器的活动账户和切换偏好；已建立的目标机器则保留其自己的。

凭据通过 SSH 传输，并存储在目标机器的私有文件中，因此仅复制到你信任的机器。这是一次性复制，而非持续同步。Codex 刷新 tokens 可能会被另一台机器轮换，导致复制的登录需要续订；在多台机器上同时使用时，单独登录仍是最可靠的选择。请参阅 [Codex 的账户身份验证指南](https://developers.openai.com/codex/auth/ci-cd-auth)。

每个提供商有一个活动账户，每个新会话都以该账户开始：`cx`、`cy`、普通的 `claude`、`codex` 或 `grok`、通过 `omarchy agent` 启动的任何内容，以及在 `PATH` 上找到 CLI 的脚本或编辑器。使用 `omarchy agent account use work` 切换（并使用 `omarchy agent account use main` 切换回来），或在面板中按账户的编号然后按 `Enter`（或单击其 Use 按钮）。正在运行的 Claude 会话也会从下一条消息起切换：每个 Claude 会话都在 `~/.claude` 中运行，该目录始终持有活动账户的登录信息。由旧版 Omarchy 在账户自有文件夹中启动的 Claude 会话会保留该登录信息直到它退出，因此切换时会列出这些会话，并会在它们消失后自行完成。正在运行的 Codex 和 Grok 会话会留在它们启动时所用的账户上。对话历史、设置、技能和插件在账户之间共享，因此在同一文件夹中的 `claude --continue` 会在新账户上从你离开的地方继续。

有多个账户时，面板会并排显示每个账户的限额，并标记活动账户。默认情况下，当活动账户超过限额的 95% 时，Omarchy 会通知你，单击通知会切换到余量最多的账户。将鼠标悬停在面板中的账户行上，然后单击 Use 旁边出现的 Autoswitch（或按 `m`），或运行 `omarchy agent account mode auto`，让它自行切换；启用后，Autoswitch 会取代 Use，再次单击它会回到通知模式。添加数字可更改阈值，如 `omarchy agent account mode auto 90`。如果每个账户都超过阈值，你只会收到一次通知，同时会告知哪个账户最先释放。当活动账户距离其阈值在 15 个百分点以内（默认值为 80%）时，其限额每三分钟检查一次，而不是每 15 分钟一次。

`omarchy agent account list` 显示每个账户及其最新限额，`omarchy agent account remove work` 遗忘一个账户，而 `omarchy agent account rename primary Hey` 重命名一个账户（或在面板中单击账户的名称）。这些命令适用于你的默认智能体的账户；要访问其他提供商，请先命名它，如 `omarchy agent account use codex side`。你已在 `~/.claude` 或 `~/.codex` 中拥有的登录是 _Main_ 账户。Codex 的保留在原处；Claude 的在另一个账户活动时，会等待在它自己的文件夹中。闲置超过约八小时的账户可能会显示 _Sign-in required_；单击它可直接在面板中重新登录该账户，或切换到它并启动会话，后者会自行刷新登录。使用 `claude mcp add` 添加的 MCP 服务器可到达每个 Claude 账户，因为它们都在 `~/.claude` 中运行；对于 Codex 和 Grok，你在添加账户时已有的服务器会随之进入该账户，但之后的服务器仅能到达你添加它们时所在的账户。Claude Desktop 保留其自己的登录，使用指向 CLI 二进制文件的绝对路径配置的 Codex 或 Grok 工具不会跟随切换。显式的 `CLAUDE_CONFIG_DIR`、`CODEX_HOME` 或 `GROK_HOME` 优先于所选账户。

### 崩溃诊断

Omarchy 通过 systemd-coredump 监视进程崩溃。一旦你选择了默认智能体，你的任何转储核心的程序都会带来 “Process crashed” 通知——单击它，崩溃就会连同 Omarchy 的 omarchy-diagnose-crash 技能一同交给你的默认智能体，该技能会引导智能体从核心转储中查明事实，并决定该崩溃是否值得向上游报告。你还可以用 `omarchy agent crash <pid>` 针对 `coredumpctl list` 中的任何 PID 手动运行它。

监视默认开启。在 _Trigger > Toggle > Crash Capture Off_ 下将其关闭（或使用 `omarchy toggle crash-capture`），通知就会停止；`omarchy agent crash <pid>` 仍可手动使用。

崩溃还可以逐个程序地静默，这正是诊断在最后向你提供的功能。`omarchy crash mute hyprland` 仅停止该程序的通知，`omarchy crash mute hyprland off` 将其恢复，而单独的 `omarchy crash mute` 会列出你已静默的内容。它接受二进制文件的路径如同接受其名称一样，因此 `omarchy crash mute /usr/bin/hyprland` 也具有相同的效果。用引号括起带有空格的名称，如 `omarchy crash mute 'Some App'`。其他一切仍会通知，被静默的程序仍会崩溃——这隐藏了提醒，它并不能修复任何问题。

### 桌面应用

_Install > AI_ 菜单还包含一些图形化 AI 应用：Amp Desktop、Antigravity Desktop、ChatGPT 桌面应用、Claude 桌面应用（Anthropic 的 Linux 测试版，包含 Chat、Cowork 和 Claude Code 标签页）、用于与 xAI 的模型聊天的 Grok Bot、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexity 桌面应用和 T3 Code。Grok Bot 是桌面聊天应用。编程智能体是 `grok` 命令。

Hermes Desktop 是需要了解的一个，因为一台机器只有一个 Hermes，而它是该应用的：Hermes 始终仅通过该应用安装，默认智能体运行的 `hermes` 命令也是该应用的。将 Hermes 选为默认智能体会安装与 _Install > AI_ 条目相同的内容：该软件包，以及由 Hermes 自有安装程序在 `~/.hermes` 下设置的 Hermes 运行时，第一次需要几分钟时间。终端 `hermes` 命令、默认智能体和该应用都使用这一个 Hermes 运行时，它通过 `hermes update` 自行更新，而不是等待 Omarchy 发布新版本。安装它还会将 Omarchy 主题作为名为 `omarchy` 的皮肤交给 Hermes，每个 Hermes 界面都会在你切换主题时随之更改；如果你不希望如此，请在 Hermes 的 Appearance 设置下或使用 `/skin` 选择另一个，Omarchy 会保留该选择不动。在 _Remove > AI_ 下删除该应用时，会先关闭 Hermes，包括网关，并将其运行时一并删除，并保留你的聊天、记忆和 Hermes 为自己编写的技能，除非你另有指示：它会询问，默认为否，是否也应删除该数据和你的连接设置。

OpenClaw 的桌面体验是其 Control UI，它以 Web 应用形式打开，由其自有的本地网关提供支持。OpenClaw 位于 `~/.openclaw` 中并自行更新：使用 Control UI 的 “Update Gateway” 按钮或运行 `openclaw update`，网关会在新版本上重启。Omarchy 仅选择全新安装的起始版本。OpenClaw 也可以成为你的默认智能体：在 _Agent > Harness_ 下选择它，会在 `~/.openclaw` 中设置同一个副本，智能体会打开连接到其网关的 OpenClaw 终端 UI。在 _Remove > AI_ 下删除 OpenClaw 会将网关服务和应用一并删除，然后询问是否也应删除 `~/.openclaw`，因为它保存了你的聊天和凭据以及 OpenClaw 本身和它下载的插件运行时；默认会保留它，再次安装 OpenClaw 时会重新使用它。

Herdr Desktop 是 [Herdr](https://herdr.dev) 桌面应用：包含终端和编程智能体的空间、标签页和窗格，当你关闭窗口时，它们会在其核心中继续运行。它来自 Herdr 自有的安装程序而非软件包，因此位于 `~/.local/share/herdr-app` 中，当你尚没有时，它会在 `~/.local/bin/herdr-core` 中附带其核心，并自行更新两者。它位于 Omarchy 在 `Super + Ctrl + Return` 上提供的 `herdr` 命令旁边，而不是取代它，并获得该命令的直接按键：`Alt + Return` 和 `Alt + Shift + Return` 向下或向右拆分窗格，`Alt + Escape` 关闭窗格，`Ctrl + Alt + Arrow` 在窗格之间移动，`Alt + 1..9` 和 `Alt + Left/Right` 选择标签页，而 `Alt + Up/Down` 在空间之间移动。`Ctrl + 1..9` 选择空间，`Alt + Shift + Up/Down` 在智能体之间步进。`Ctrl + Space` 前缀按键仍仅适用于终端，因为该应用无法为序列按住普通的 Ctrl 键。Omarchy 将这些写入 `~/.config/herdr-app/keys.json`，而 `omarchy-refresh-herdr-app` 会将它们放回。安装它会选择 Herdr 的 Omarchy 主题，从那时起它会跟随你的 Omarchy 主题。Herdr 为浅色模式保留一个主题，为深色模式保留一个主题，因此在深色和浅色 Omarchy 主题之间切换后，请在 Herdr 的主题选择器中再次为另一种模式选择 Omarchy。

T3 Code 从其位于 `~/.local/share/t3code` 中的官方 AppImage 版本运行，而不是从软件包运行，因此它会自行更新。安装它时会询问在 Stable 还是 Nightly 频道开始；之后在 T3 Code 的设置中切换。你的线程和设置位于 `~/.t3` 中，在 _Remove > AI_ 下删除 T3 Code 会将它们一并删除。

### 本地模型

在你自己的机器上为你的编程智能体运行开放模型。你的提示词和代码保留在机器上；发送给模型的任何内容都不会离开它。从以下开始：

```bash
omarchy models use best text
```

这会为此机器设置最佳文本模型，即你的智能体使用的类型。图像、视频和音乐模型也有各自的最佳选择：`omarchy models use best image`、`video` 或 `music`。运行 `omarchy models use best` 查看每种类型对此机器的选择。

或者从顶部栏中其闪光图标打开本地模型面板，该图标位于智能体图标旁边，或使用 Super + Ctrl + Alt + X，然后选择 +。当有适合此机器的模型时，该图标就会显示。运行模型的 Podman 随 Omarchy 附带，在 NVIDIA 机器上 NVIDIA 的容器工具包也随附，它为它们提供 GPU；如果其中任何一项缺失，首次设置会安装它。然后 Omarchy 会为此机器挑选推荐模型，下载它并启动它。预计会有数十 GB 的下载，并且在模型运行时机器的大部分内存会被占用：Flash Next 在其完整的 256K 上下文下使用约 100 GiB。如果其他模型占用了它所需的内存，它会被设置为已停止状态，准备好在你停止一个模型后启动。模型在注销时停止；当你需要内存用于其他事情时，请自行停止它。

`omarchy models list` 显示选项并解释为什么某些选项不适合。要设置另一个，请运行 `omarchy models use <recipe>`。如今，`qwen3.8-flash-next-gufo` 和 `qwen3.8-27b-gufo` 可用于 128 GB Strix Halo 机器；27B 占用约 40 GiB，因此它为其他工作留出了空间。在一台配备 Intel 的 Arc B390 的 64 GB 笔记本电脑上，`qwen3.6-35b-a3b-llamacpp` 在约 30 GiB 中运行。新的配方和推荐随 `omarchy update` 通过该软件包提供。

你设置的每个模型都在本地模型面板中获得自己的一行：播放可启动它，暂停可停止它并释放其内存，终端按钮可在其上打开你的智能体。顶部有一条横栏，显示机器内存如何在 Omarchy 本身（系统和你的应用）、每个正在运行的模型和空闲部分之间分配。指向已停止的模型时，该横栏会显示它是否适合，或还差多少。多个模型可以在内存中同时运行时一起运行；如果一个不适合，Omarchy 会说明要停止哪个正在运行的模型。通过其徽标拖动行可重新排序它们，并按 Delete 删除选定的行以删除模型及其下载。

你设置的每个模型还会在应用启动器中获得自己的条目，位于模型名称下并带有其制造商的徽标，就像登录 Claude、Codex 或 Grok 时添加一个一样。它会在该模型上打开你的智能体，如果模型未运行，则先启动它：终端会显示它正在加载，并在就绪后移交给智能体。删除模型也会删除其条目。

并非每个模型都用于编程。图像、视频和音乐模型改为在 Fantasi 中打开，Fantasi 是 Omarchy 用于通过在此机器上运行的模型制作图片、视频和音乐的应用，可从它们的启动器条目和本地模型面板中的那一行打开。

模型会完全按照设置时的方式继续运行，因此 Omarchy 更新永远不会在你的智能体下重启模型。当 Omarchy 为你已设置的模型提供了更新的运行时或更新的权重时，其行会显示更新按钮：按下它，模型会在后台重新设置，仅下载已更改的内容，并在新版本上重启。已停止的模型保持停止状态。`omarchy models update` 在终端中对每个模型执行相同操作。

从命令行，`omarchy models start <recipe>` 和 `omarchy models stop <recipe>` 执行相同操作，`omarchy models status` 显示每个模型，而 `omarchy agent --local` 在你上次启动的模型上打开你的默认智能体。pi、OpenCode 和 Qwen Code 可以使用一个；使用任何其他默认项时，它会在 pi 中打开，如果你没有 pi，则在 OpenCode 中打开。pi 还会在其自己的模型选择器中列出你已设置的每个模型，以及你在已配对机器上的模型，因此普通的 `pi` 也可以访问它们。任何与 OpenAI 兼容的客户端也可以连接：`status` 会显示每个模型的地址（第一个是 `http://127.0.0.1:11435/v1`），配方名称就是模型，密钥位于 `~/.config/omarchy/agent-local/key` 中。

`omarchy models remove <recipe>` 删除模型以及没有其他模型使用的下载。

第三方运行时的标签标有其发布者。Omarchy 在没有网络访问的情况下运行每个模型。

### 本地 LLMs

Omarchy 推荐两种运行本地 LLM 模型的方式：LM Studio 和 Ollama。LM Studio 提供 GUI 界面，用于查找开放权重模型、安装它们并运行它们。这是轻松上手的好方法。Ollama 提供 CLI 以类似方式做到这一点。但如果你是本地模型的新手，我会从 LM Studio 开始。你可以在 Omarchy Menu 的 _Install > AI_ 下安装其中任何一个。

### Omarchy 技能

智能体技能帮助 AI 以特定方式使用特定工具，Omarchy 随附了其中七个。omarchy 技能涵盖定制系统，例如调整你的 Hyprland 配置或调整栏。omarchy-make-theme、omarchy-make-plugin、omarchy-make-app 和 omarchy-make-game 涵盖制作新事物，omarchy-contribute 涵盖报告 bug 或向上游发送修复，而 omarchy-diagnose-crash 则处理崩溃的核心转储。它们被符号链接到 Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` 和每个 `~/.hermes/profiles/*/skills`）以及通用 `~/.agents/skills` 位置的技能目录中，因此大多数框架都会自动拾取它们。你自己的同名技能文件夹优先。

但你应该将这些技能视为实验性的。不同的模型会以不同的效果使用它。最好先在计划模式下运行，这样你就能了解智能体想要更改什么。然后准备好回滚更改，甚至调用 `omarchy reinstall configs`，如果智能体把一切搞得一团糟的话。
