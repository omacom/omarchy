# AI

Omarchy 包含了下列编程 agent 的启动器，但不会替你选定默认项。运行命令即可在首次使用时安装其 CLI，然后在提示时完成身份验证。Hermes 是个例外：首次使用时不会为它安装任何东西，选中它会安装 Hermes Desktop，正如下面_桌面应用_一节所述。

### 安装和更新 agent

除 Hermes 外，这些 agent 都使用 mise 的延迟安装：首次启动时安装 CLI，后续启动则复用它。mise 还最多每四小时检查一次已安装 agent 是否有新版本，就在它启动之前，或在 shell 提示符下于后台检查。如果该更新失败或你处于离线状态，则运行已安装的版本。`omarchy update` 会随 Omarchy 的其余部分一起更新已安装的 agent，而 `mup` 只更新由 mise 管理的工具。

agent 自带的更新程序，例如 `claude update`、`codex update`，或应用中的更新按钮，不会更新由 mise 管理的安装。`codex update` 会失败，而 `claude update` 可能会报告成功，却安装了 mise 并不跟踪的另一份副本。如果你更想使用 agent 原生的安装程序和更新程序，将它添加到 `disable_tools`；请参阅[预装的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

要在你需要之前安装所有已配置的延迟工具，运行 `mise install --include-lazy`。这既包括 Omarchy 的其他默认 CLI 工具，也包括这些 agent。关于安装单个工具或使用你自己的安装，请参阅[预装的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

`grok` 通过 mise 的第一方 `grok` 包安装，与 `claude` 和 `codex` 的方式相同。运行 `grok`，或在 _Agent > Harness_ 下选择它。跳过 x.ai 上的 `curl | bash` 安装程序。那条路径会在 `~/.grok/bin` 中放入第二份副本，将其前置到 `PATH` 上，并覆盖 Omarchy 的包装器。

`dsh` 在 `127.0.0.1:3080` 上打开其浏览器 UI，并以启动目录作为其默认工作区。其浏览器 UI 不接受起始提示词，因此 `omarchy agent prompt` 打开它时会把提示词放在你的剪贴板上供你粘贴。Omarchy 使用 DeepSeek 的无需批准权限预设来启动它。当你使用 DeepSeek 的官方模型 API 时，DeepSeek Harness 会将它把会话日志上传到 DeepSeek；在其浏览器 UI 的 _Settings > General > Upload Session Log_ 下将其关闭。你发送给它的反馈也会随会话一同上传，除非你使用 `DSH_TELEMETRY_MODE=DISABLED` 启动它。

### 默认 agent

使用 `omarchy default agent <name>` 或在 Omarchy Menu（`Super + Space`）的 _Agent > Harness_ 下选择你的默认 agent。如果该 agent 尚未安装，选中它会先将其安装。全新的 Omarchy 会通过一次性通知邀请你作出这一选择。

选择 Claude 还会尝试为 Chromium、Chrome、Brave、Brave Origin 和 Edge 设置其浏览器扩展。该扩展设置适用于所有用户，可能会要求输入你的系统密码；取消或扩展安装失败仍会选中并启动 Claude。重启你的浏览器，如有提示则启用该扩展，并登录 Claude 以完成连接。在 Claude 中运行 `/chrome` 以检查连接。Firefox 和 Zen 不支持此扩展。如果在添加此设置之前 Claude 就已经是你的默认项，请再次选择它以安装该扩展。

选好之后，`Super + Shift + Ctrl + A` 会在一个专用终端窗口中启动默认 agent（或者，如果你尚未选择，则调出选择器）。你也可以用 `omarchy agent prompt "Review this project"` 让它直接进入一项任务。Freebuff 和 DeepSeek Harness 不接受起始提示词，因此它们打开时会把提示词放在你的剪贴板上供你粘贴。以这种方式启动的 agent 会在各自的不停下来询问的模式下无人值守地运行，所以要做好它们真的会动手做事的准备！MiniMax Code 的交互式会话没有这种模式，因此它会像往常一样请求权限。而且，由于 agent 拒绝记住对你主目录的信任，从 `$HOME` 启动时会改为在 `~/Work` 中启动。

还有终端快捷方式：`a` 在当前终端中内联运行默认 agent，而 `c`、`cx` 和 `cy` 则直接启动 OpenCode、Claude Code 和 Codex（同样处于它们的自动批准模式）。主题变化也会同步到 agent：当你切换 Omarchy 主题时，Claude Code、Pi、OpenCode 和 Hermes（一旦 Omarchy 已安装它）都会随之跟随。

### 你的 agent 指令

适用于每个 agent 的个人规则放在 `~/.agents/AGENTS.md` 中，紧挨着 `~/.agents/skills` 中的共享技能。在 _Agent > Instructions_ 下打开它，它还会将其链接到每个维护自己全局文件的 harness 中：`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`~/.pi/agent/AGENTS.md`、`~/.config/opencode/AGENTS.md`、Copilot 的 `~/.copilot/copilot-instructions.md`，等等。Crush 和 Amp 读取 `~/.config/AGENTS.md` 链接，而 omp、Kimi 和 DeepSeek Harness 直接读取 `~/.agents/AGENTS.md`。选择默认 agent 时也会将其链接。如果你已经有一个指令文件，且此前尚不存在共享文件，它就会成为共享文件；否则它会以 `.bak` 的形式保留在链接旁。安装另一个 agent 后，运行 `omarchy agent instructions` 以重新链接。

### agent 面板

顶栏有一个 agent 图标。在你设置 agent 之前，它的面板会引导你登录 Claude、Codex 或 Grok，第一个登录的会成为你的默认 agent。此后，该面板会将每个订阅放在一个页面上：每个 agent 和账户连同其套餐、其 5 小时会话限额和每周限额各自的计量条及距离重置的时间（悬停查看确切百分比），或者剩余的预付余额，都位于一行轮播文字之下，该行会轮流显示你在所有这些 agent 上用过的内容，例如本周的 token 和你最常用的模型。在 _Make something_ 下，它提供用于新建主题、插件或应用的起始提示词，并将任务交给你的默认 agent。应用的构建方式与 Omarchy 自己的 Hype、Monologue 和 Omacut 相同，使用 C++ 和 Qt Quick，遵循 omarchy-app agent 技能，并且它们所需的编译器和 Qt 组件都已预装。Claude Code、Codex、Grok、Kimi、Cursor 及其 Grok Bot 额度、GitHub Copilot、Muse、Antigravity、Kimchi 和 Devin 开箱即用地被覆盖，并显示其限额，Hermes、Mistral Vibe 和 Qwen Code 则会在你使用它们后显示其会话和 token。你通过 pi、omp 或 opencode 使用的提供商套餐和密钥也会显示出来：OpenCode Zen 和 Go、Z.ai 的 GLM Coding Plan、Ollama Cloud、MiniMax Token Plan 和 Synthetic，连同其限额；Fireworks、OpenRouter 和 DeepSeek，连同其预付余额；以及你在自有硬件上运行的模型，归在 Local models 下。每个 agent 只计算一次，归在向你收费的那一家名下，无论你通过多少个 harness 来驱动它。

左键点击顶栏图标打开面板，右键点击启动你的默认 agent。其背后的使用记录每 15 分钟由 `omarchy agent usage-update` 重新生成，该面板甚至可以通过一个同步文件夹合并来自你其他机器的使用情况。完整设置请参阅 `$OMARCHY_PATH/shell/plugins/agents/` 下的 README。

### 多个订阅

如果你付费订阅了不止一个 Claude、Codex 或 Grok 套餐——比如一个个人 Max 和一个工作套餐——Omarchy 可以让它们全部保持登录状态，并在它们之间切换。在 agent 面板中用 + 添加一个订阅，它会就在那里引导你完成，或者使用 `omarchy agent account add claude Work`（或 `codex`，或 `grok`）。如果 CLI 缺失，它会安装它。某个提供商的第一个账户通过你的普通浏览器登录，就在 CLI 一直查找的位置。此后的每一个账户都通过隐私窗口登录，因此你浏览器已经登录的账户不会被误选；在那里以你要添加的账户登录，并先关闭你已经打开的任何隐私窗口。千万不要为此退出 CLI 登录：退出登录会撤销已保存的登录状态，该账户将不得不重新添加。

要通过 SSH 将你的订阅登录信息复制到另一台 Omarchy 机器上，运行 `omarchy agent account copy user@laptop`。当目标机器未安装接收器时，发送方会提供一个临时接收器，因此较旧的 Omarchy 机器无需更新即可接收账户。已安装的接收器优先。此命令会复制所有 Claude、Codex 和 Grok 订阅；添加提供商名称以选择它们，例如 `omarchy agent account copy laptop claude`。账户名称和命令 ID 与源机器保持一致，包括目标机器上已经存在的账户。如果名称冲突，无关的目标账户会获得数字后缀，而设置、技能、插件和对话历史则保留在各自机器本地。

目标机器现有的凭据会保留。已在那里登录的源账户会同步其名称，但不会替换其凭据；其他账户会添加到它旁边。要替换匹配账户的已保存凭据，请在退出目标机器上该账户的会话后，使用 `omarchy agent account copy --replace laptop claude`。全新的目标机器还会获得源机器的活动账户和切换偏好；已建立的目标机器则保留自己的。

凭据通过 SSH 传输，并存储在目标机器的私有文件中，因此只应复制到你信任的机器。这是一次性复制，不是持续同步。Codex 的刷新 token 可能会被另一台机器轮换，导致复制的登录需要续期；对于在多台机器上同时使用，单独登录仍是最可靠的选择。请参阅 [Codex 的账户身份验证指南](https://developers.openai.com/codex/auth/ci-cd-auth)。

每个提供商只有一个活动账户，每个新会话都会以它开始：`cx`、`cy`、普通的 `claude`、`codex` 或 `grok`、通过 `omarchy agent` 启动的任何东西，以及在 `PATH` 上找到该 CLI 的脚本或编辑器。用 `omarchy agent account use work` 切换（用 `omarchy agent account use main` 切回），或者在面板中按下某个账户的数字然后按 `Enter`（或点击其 Use 按钮）。已经运行的会话会继续使用它们启动时的账户。对话历史、设置、技能和插件在账户之间共享，因此在同一文件夹中运行 `claude --continue` 会在新账户上从你离开的地方继续。

当有多个账户时，面板会并排显示每个账户的限额，并标记活动账户。默认情况下，当活动账户超过某个限额的 95% 时，Omarchy 会通知你，点击该通知会切换到余量最多的账户。将鼠标悬停在面板中某个账户的行上，点击 Use 旁出现的 Autoswitch（或按 `m`），或者运行 `omarchy agent account mode auto`，让它自行切换；开启时，Autoswitch 会取代 Use 的位置，再次点击它则恢复为通知。添加一个数字以更改阈值，例如 `omarchy agent account mode auto 90`。如果每个账户都超过阈值，你会收到一次通知，并告知哪个账户最先释放额度。当活动账户距离其阈值在 15 个百分点以内时（默认阈值下为 80%），其限额会每三分钟检查一次，而不是每 15 分钟。

`omarchy agent account list` 显示每个账户及其最新限额，`omarchy agent account remove work` 移除一个账户，`omarchy agent account rename primary Hey` 重命名一个账户（或者在面板中点击账户的名称）。这些命令作用于你的默认 agent 的账户；要访问其他提供商，先命名它，例如 `omarchy agent account use codex side`。你已经在 `~/.claude` 或 `~/.codex` 中拥有的登录是 _Main_ 账户，并保留在原处。一个超过约八小时未使用的账户可能会显示 _Sign-in required_；点击它可直接在面板中重新登录该账户，或者在其中启动一个会话，它会自行刷新登录。添加账户时你拥有的 MCP 服务器会随之带到该账户，但之后用 `claude mcp add` 添加的服务器只会到达你添加它们时所在的账户。Claude Desktop 和配置了 CLI 二进制绝对路径的工具不会跟随切换。显式的 `CLAUDE_CONFIG_DIR`、`CODEX_HOME` 或 `GROK_HOME` 优先于所选账户。

### 崩溃诊断

Omarchy 会监视 systemd-coredump 以发现进程崩溃。当某个进程出现段错误时，你会收到一个 "Process crashed" 通知——点击它，崩溃就会连同 Omarchy 的 diagnose-crash 技能一起交给你的默认 agent，该技能会引导 agent 从核心转储中查明事实，并决定该崩溃是否值得向上游报告。你也可以用 `omarchy agent crash <pid>` 针对 `coredumpctl list` 中的任意 PID 手动运行它。

该监视默认开启。在 _Trigger > Toggle > Crash Capture_ 下将其关闭（或使用 `omarchy toggle crash-capture`），通知就会停止；`omarchy agent crash <pid>` 仍可手动使用。

崩溃也可以一次为一个程序静默，这正是诊断在结束时向你提供的选项。`omarchy crash mute hyprland` 只停止该程序的通知，`omarchy crash mute hyprland off` 将其恢复，而单独运行 `omarchy crash mute` 则列出你已静默的内容。它既接受二进制文件的路径，也接受其名称，因此 `omarchy crash mute /usr/bin/hyprland` 效果相同。为含有空格的名称加引号，例如 `omarchy crash mute 'Some App'`。其他一切仍会发出通知，被静默的程序也仍会崩溃——这只是隐藏提醒，并不会修复任何东西。

### 桌面应用

_Install > AI_ 菜单还包含一些图形化 AI 应用：ChatGPT 桌面应用、Claude 桌面应用（Anthropic 的 Linux 测试版，带有 Chat、Cowork 和 Claude Code 标签页）、用于与 xAI 模型聊天的 Grok Bot、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexity 桌面应用和 T3 Code。Grok Bot 是桌面聊天应用。编程 agent 则是 `grok` 命令。

Hermes Desktop 是需要了解的那个，因为一台机器只有一个 Hermes，而且它属于该应用：Hermes 只能通过该应用安装，默认 agent 运行的 `hermes` 命令也是该应用的。将 Hermes 选为默认 agent 会安装与 _Install > AI_ 条目相同的东西：软件包，以及一个由 Hermes 自己的安装程序设置、位于 `~/.hermes` 下的 Hermes 运行时，首次安装需要几分钟。该运行时是终端 `hermes` 命令、默认 agent 和应用共同使用的唯一 Hermes，它使用 `hermes update` 自行更新，而不是等待 Omarchy 发布新版本。安装它还会将 Omarchy 主题作为名为 `omarchy` 的皮肤提供给 Hermes，每当你切换主题时，每个 Hermes 界面都会随之跟随；如果你不希望这样，可在 Hermes 的 Appearance 设置下或使用 `/skin` 选择另一个，Omarchy 不会干涉该选择。在 _Remove > AI_ 下删除该应用会先关闭 Hermes，包括网关，把该运行时一并删除，并保留你的聊天、记忆以及 Hermes 为自己编写的技能，除非你另行指示：它会询问，默认回答为否，是否也删除那些数据和你的连接设置。

OpenClaw 的桌面体验是其 Control UI，它以 Web 应用的形式打开，后端是其自己的本地网关。OpenClaw 位于 `~/.openclaw` 并会自行更新：使用 Control UI 的 "Update Gateway" 按钮或运行 `openclaw update`，网关就会在新版本上重启。Omarchy 只选择全新安装从哪个发行版开始。在 _Remove > AI_ 下删除 OpenClaw 会一并删除网关服务和应用，然后询问是否也应删除 `~/.openclaw`，因为那里保存着你的聊天和凭据，以及 OpenClaw 本身和它下载的插件运行时；默认保留它，再次安装 OpenClaw 时会重新使用它。

Herdr Desktop 是 [Herdr](https://herdr.dev) 桌面应用：由终端和编程 agent 组成的 spaces、标签页和窗格，在你关闭窗口时它们仍在其核心中继续运行。它来自 Herdr 自己的安装程序而非软件包，因此位于 `~/.local/share/herdr-app` 中，当你尚没有其核心时，它会把核心一并带到 `~/.local/bin/herdr-core`，并会自行更新这两者。它与 Omarchy 附带、绑定到 `Super + Ctrl + Return` 的 `herdr` 命令并存而不是替换它，并获得该命令的直接按键：`Alt + Return` 和 `Alt + Shift + Return` 向下或向右拆分窗格，`Alt + Escape` 关闭它，`Ctrl + Alt + Arrow` 在窗格之间移动，`Alt + 1..9` 和 `Alt + Left/Right` 选择一个标签页，`Alt + Up/Down` 在 spaces 之间移动。`Ctrl + 1..9` 选择一个 space，`Alt + Shift + Up/Down` 在 agent 之间步进。`Ctrl + Space` 前缀按键仍只适用于终端，因为该应用无法为一个按键序列保持按住普通的 Ctrl 键。Omarchy 将这些写入 `~/.config/herdr-app/keys.json`，而 `omarchy-refresh-herdr-app` 会将其恢复。安装它会选择 Herdr 的 Omarchy 主题，此后它会跟随你的 Omarchy 主题。Herdr 为浅色模式保留一个主题，为深色模式保留一个主题，因此在深色和浅色 Omarchy 主题之间切换后，在 Herdr 的主题选择器中为另一种模式再选择一次 Omarchy。

T3 Code 运行其官方 AppImage 发行版，位于 `~/.local/share/t3code`，而不是来自软件包，因此它会自行更新。安装它时会询问是先从 Stable 还是 Nightly 频道开始；之后在 T3 Code 的设置中切换。你的线程和设置位于 `~/.t3`，在 _Remove > AI_ 下删除 T3 Code 会将它们一并删除。

### 本地模型

在你自己的机器上为你的编程 agent 运行一个开放模型。你的提示词和代码都留在机器上；发送给模型的任何内容都不会离开它。从以下命令开始：

```bash
omarchy agent local use best
```

或者，在顶栏的 agent 面板中，选择 + 然后选择 Local AI，当有模型适合这台机器时它会出现。首次使用时，这会安装 Podman（它运行模型），在 NVIDIA 机器上还会安装 NVIDIA 的容器工具包（它让模型能够使用 GPU）。然后 Omarchy 会为这台机器挑选推荐模型，下载它并启动它。预计会有几十 GB 的下载，且在模型运行期间，机器的大部分内存都会被占用：Flash Next 在使用其完整 256K 上下文时约使用 100 GiB。如果其他模型占用了它所需的内存，它会被设置为停止状态，一等你停止一个其他模型就可以启动。该模型在注销时停止；当你需要内存做其他事情时，请自己把它停掉。

`omarchy agent local list` 显示选项并解释为什么有些不适合。要设置另一个，运行 `omarchy agent local use <recipe>`。目前，`qwen3.8-flash-next-gufo` 和 `qwen3.8-27b-gufo` 可用于 128 GB 的 Strix Halo 机器；27B 约占用 40 GiB，因此会为其他工作留出空间。新的配方和推荐会通过软件包随 `omarchy update` 到来。

你设置的每个模型都在 agent 面板中获得自己的一行，位于你的订阅旁边：播放按钮启动它，暂停按钮停止它并释放其内存，终端按钮在它上面打开你的 agent。当多个模型能同时装进内存时，它们可以同时运行；如果一个装不下，Omarchy 会说明应该停止哪个正在运行的模型。拖动行以重新排列，选中某行时按 Delete 可删除一个模型及其下载。

在命令行中，`omarchy agent local start <recipe>` 和 `omarchy agent local stop <recipe>` 做同样的事情，`omarchy agent local status` 显示每个模型，而 `omarchy agent --local` 在你上次启动的模型上打开你的默认 agent（如果你的默认 agent 不能使用本地模型，则使用 pi）。任何兼容 OpenAI 的客户端也可以连接：`status` 显示每个模型的地址（第一个是 `http://127.0.0.1:11435/v1`），配方名称就是模型，密钥位于 `~/.config/omarchy/agent-local/key` 中。

`omarchy agent local remove <recipe>` 删除一个模型，以及没有其他模型使用的下载。

第三方运行时会标注其发布者。Omarchy 在没有网络访问的情况下运行每个模型。

### 本地 LLM

Omarchy 推荐两种运行本地 LLM 模型的方式：LM Studio 和 Ollama。LM Studio 提供了一个 GUI 界面，用于查找开放权重模型、安装它们并运行它们。它是轻松入门的好方法。Ollama 提供了类似功能的 CLI。但如果你是本地模型新手，我会从 LM Studio 开始。你可以在 Omarchy Menu 的 _Install > AI_ 下安装其中任何一个。

### Omarchy 技能

Agent 技能帮助 AI 以特定方式使用特定工具，而 Omarchy 附带了一个用于定制系统的默认技能。例如调整你的 Hyprland 配置、调整顶栏，甚至从零开始创建一个新主题。它被符号链接到以下技能目录：Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` 和每个 `~/.hermes/profiles/*/skills`），以及通用的 `~/.agents/skills` 位置，因此大多数 harness 会自动识别它。

但你应该把这个技能视为实验性的。不同模型使用它的效果会有所不同。最好先在计划模式下运行，以便你了解 agent 想要更改什么。然后，如果 agent 把一切搞得一团糟，要做好回滚更改，甚至调用 `omarchy reinstall configs` 的准备。
