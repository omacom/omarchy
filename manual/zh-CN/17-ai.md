### 安装和更新智能体

除 Hermes 和 OpenClaw 外，这些智能体使用 mise 的懒安装：首次启动会安装 CLI，后续启动会复用它。mise 还会至多每四小时检查一次已安装智能体是否有新版本，就在它启动之前，或在 shell 提示符下在后台检查。如果该更新失败或你处于离线状态，就会运行已安装的版本。`omarchy update` 会在更新 Omarchy 其余部分的同时更新已安装的智能体，而 `mup` 只更新 mise 管理的工具。

智能体自己的更新程序，例如 `claude update`、`codex update`，或应用中的更新按钮，不会更新 mise 管理的安装。`codex update` 会失败，而 `claude update` 可能会报告成功，却安装了一个 mise 不跟踪的独立副本。如果你更愿意使用智能体原生的安装程序和更新程序，请将它加入 `disable_tools`；请参阅 [预装的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

要在需要之前安装所有已配置的懒加载工具，请运行 `mise install --include-lazy`。这包括 Omarchy 的其他默认 CLI 工具以及这些智能体。有关安装单个工具或使用你自己的安装，请参阅 [预装的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

`grok` 通过 mise 的第一方 `grok` 包安装，方式与 `claude` 和 `codex` 相同。运行 `grok`，或在 _Agent > Harness_ 下选择它。跳过 x.ai 上的 `curl | bash` 安装程序。那条路径会在 `~/.grok/bin` 中放入第二个副本，将它置于 `PATH` 的最前面，并覆盖 Omarchy 的包装器。

`dsh` 会在 `127.0.0.1:3080` 上打开其浏览器 UI，并以启动目录作为其默认工作区。其浏览器 UI 不接受起始提示词，因此 `omarchy agent prompt` 打开它时，会将提示词放在你的剪贴板上以便粘贴。Omarchy 使用 DeepSeek 的无批准权限预设启动它。当你使用 DeepSeek 的官方模型 API 时，DeepSeek Harness 会将 session 日志上传到 DeepSeek；在其浏览器 UI 的 _Settings > General > Upload Session Log_ 下关闭这一功能。你发送给它的反馈也会随 session 一起上传，除非你使用 `DSH_TELEMETRY_MODE=DISABLED` 启动它。

### 默认智能体

使用 `omarchy default agent <name>` 或在 Omarchy Menu（`Super + Space`）的 _Agent > Harness_ 下选择你的默认智能体。如果该智能体尚未安装，选择它会先安装它，而且它还会在应用启动器中获得一个自己的启动器，位于 Agent 旁边。全新的 Omarchy 会通过一次性通知邀请你做出这一选择。

选择 Claude 还会尝试为 Chromium、Chrome、Brave、Brave Origin 和 Edge 设置其浏览器扩展。该扩展设置适用于所有用户，可能会要求输入你的系统密码；取消或扩展安装失败仍然会选择并启动 Claude。重启你的浏览器，如有提示则启用该扩展，并登录 Claude 以完成连接。在 Claude 中运行 `/chrome` 以检查连接。Firefox 和 Zen 不支持此扩展。如果在此设置加入之前 Claude 已经是你的默认项，请再次选择它以安装该扩展。

选好之后，`Super + Shift + Ctrl + A` 会在专用终端窗口中启动默认智能体（或者如果你尚未选择，则调出选择器）。你也可以用 `omarchy agent prompt "Review this project"` 让它直接进入一项任务。Freebuff 和 DeepSeek Harness 不接受起始提示词，因此它们打开时改为将提示词放在你的剪贴板上以便粘贴。以这种方式启动的智能体会以各自的“不要停下来询问”模式无人值守地运行，所以要做好它们真的会动手做事的准备！MiniMax Code 的交互式 session 没有这种模式，因此它会像往常一样请求权限。而且由于智能体拒绝为你的主目录记住信任，从 `$HOME` 启动时改为在 `~/Work` 中启动。

还有终端快捷方式：`a` 会在当前终端中内联运行默认智能体，而 `c`、`cx` 和 `cy` 则直接启动 OpenCode、Claude Code 和 Codex（同样处于其自动批准模式）。主题更改也会同步到这些智能体：当你切换 Omarchy 主题时，Claude Code、Pi、OpenCode 和 Hermes（一旦 Omarchy 已安装它）都会随之跟随。

### 你的智能体指令

每个智能体的个人规则都放在 `~/.agents/AGENTS.md` 中，紧挨着 `~/.agents/skills` 中的共享 skills。在 _Agent > Instructions_ 下打开它，它还会将它链接到每个保留其自己全局文件的 harness 中：`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`~/.pi/agent/AGENTS.md`、`~/.config/opencode/AGENTS.md`、Copilot 的 `~/.copilot/copilot-instructions.md`，等等。Crush 和 Amp 读取 `~/.config/AGENTS.md` 链接，而 omp、Kimi 和 DeepSeek Harness 直接读取 `~/.agents/AGENTS.md`。选择默认智能体时也会链接它。如果你已有的指令文件在尚不存在共享文件时，就会成为共享的那一份；否则它会作为 `.bak` 保存在链接旁边。安装另一个智能体后，运行 `omarchy agent instructions` 以重新链接。

### 智能体面板

顶栏有一个智能体图标。在你设置智能体之前，其面板会引导你登录 Claude、Codex 或 Grok，而第一个会成为你的默认智能体。之后，该面板将每个订阅都放在同一页面上：每个智能体和账户及其套餐、每个 5 小时 session 限额和每周限额的计量条及距离重置的时间（悬停可查看确切百分比），或剩余的预付余额，位于一行轮播文字之下，该行会轮流显示你在所有这些智能体上的使用情况，例如本周的 tokens 以及你最常用的模型。在 _Make something cool_ 下，它提供用于新主题、插件、应用或游戏的入门提示词，并将任务交给你的默认智能体。应用的构建方式与 Omarchy 自己的 Hype、Monologue 和 Omacut 相同，使用 C++ 和 Qt Quick，遵循 omarchy-make-app agent skill，并且它们所需的编译器和 Qt 组件都已安装。游戏是位于 `~/Games/vibes` 中的单个 three.js 页面，遵循 omarchy-make-game agent skill，并且全部从当前主题中的一个 Game Vibes 启动器打开；它们从网络加载 three.js，因此启动时需要网络连接。Claude Code、Codex、Grok、Kimi、Cursor 及其 Grok Bot 配额、GitHub Copilot、Muse、Antigravity 和 Devin 开箱即用地被覆盖并显示其限额，Kimchi 显示其套餐、预付额度和支出预算，而 Hermes、Mistral Vibe 和 Qwen Code 在你使用过它们后会显示其 session 和 tokens。通过 pi、omp 或 opencode 使用的 Provider 套餐和密钥也会显示：OpenCode Zen 和 Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan 和 Synthetic 及其限额；OpenRouter 和 DeepSeek 及其预付余额；Fireworks 及其过去 30 天的支出。在你自己硬件上运行的模型的 tokens 也计入总数；这些模型本身有它们自己的面板，在 [本地模型](#local-models) 下有说明。每个智能体只计数一次，按向其收费的一方计算，无论你通过多少个 harness 来驱动它。

左键单击顶栏图标或按 `Super + Ctrl + X` 打开面板，右键单击以启动你的默认智能体，中键单击以刷新。它背后的使用记录由 `omarchy agent usage update` 每 15 分钟重新生成一次，并且该面板甚至可以通过同步文件夹合并来自你其他机器的使用情况。有关完整设置，请参阅 `$OMARCHY_PATH/shell/plugins/agents/` 下的 README。

### 多个订阅

如果你为多个 Claude、Codex 或 Grok 套餐付费——比如一个个人 Max 和一个工作套餐——Omarchy 可以让它们全部保持登录状态，并在它们之间切换。使用智能体面板中的 + 添加一个订阅，它会在那里引导你完成，或者使用 `omarchy agent account add claude Work`（或 `codex`，或 `grok`）。如果 CLI 缺失，它会安装它。某个 provider 的第一个账户会通过你正常的浏览器登录，就在 CLI 一直查找的位置。之后每一个都会通过隐私窗口登录，因此你的浏览器已登录的账户不会被误选；在那里以你正在添加的账户登录，并先关闭你已打开的任何隐私窗口。千万不要为此退出 CLI：退出会撤销已保存的登录，而该账户将不得不再次添加。

要通过 SSH 将你的订阅登录信息复制到另一台 Omarchy 机器，请运行 `omarchy agent account copy user@laptop`。当目标机器未安装接收端时，发送方会提供一个临时接收端，因此较旧的 Omarchy 机器无需更新即可接收账户。已安装的接收端优先。此命令会复制所有 Claude、Codex 和 Grok 订阅；添加 provider 名称以选择它们，例如 `omarchy agent account copy laptop claude`。账户名称和命令 ID 与源保持一致，包括目标上已存在的账户。如果名称冲突，无关的目标账户会收到数字后缀，并且设置、skills、插件和对话历史仍保留在每台机器本地。

目标上现有的凭据会被保留。源账户如果已在那里登录，其名称会被同步，但不会替换其凭据；其他账户会被添加到它旁边。要替换匹配账户已保存的凭据，请在退出目标上该账户的 session 后，使用 `omarchy agent account copy --replace laptop claude`。全新的目标还会获得源的活动账户和切换偏好；已建立的目标会保留其自己的。

凭据通过 SSH 传输，并存储在目标上的私有文件中，因此只能复制到你信任的机器。这是一次性复制，而不是持续同步。Codex 的 refresh tokens 可能被另一台机器轮换，导致复制的登录需要续期；对于在多台机器上同时使用，单独登录仍是最可靠的选择。请参阅 [Codex 的账户身份验证指南](https://developers.openai.com/codex/auth/ci-cd-auth)。

每个 provider 有一个活动账户，每个新 session 都以它开始：`cx`、`cy`、普通的 `claude`、`codex` 或 `grok`、通过 `omarchy agent` 启动的任何东西，以及在 `PATH` 上找到 CLI 的脚本或编辑器。使用 `omarchy agent account use work` 切换（并用 `omarchy agent account use main` 切回），或者在面板中按某个账户的数字然后按 `Enter`（或单击其 Use 按钮）。正在运行的 Claude session 也会切换，从它们下一条消息开始：每个 Claude session 都在 `~/.claude` 中运行，该目录始终保存活动账户的登录。由较旧 Omarchy 在某个账户自己的文件夹中启动的 Claude session 会保留该登录直到它退出，因此切换时会列出那些 session，并在它们消失后自行完成。正在运行的 Codex 和 Grok session 会保持在它们启动时所用的账户。对话历史、设置、skills 和插件在账户之间共享，因此在同一文件夹中的 `claude --continue` 会在新账户上从你离开的地方继续。

当有多个账户时，面板会并排显示每个账户的限额，并标记活动的那一个。当活动账户超过某个限额的 95% 时，Omarchy 会通知你，单击通知会切换到余量最多的账户。它永远不会自行切换。使用 `omarchy agent account threshold 90` 更改阈值。如果每个账户都超过阈值，你只会听到一次，并会获知哪个账户最先释放。当活动账户距离其阈值在 15 个百分点以内时（默认值为 80%），其限额会每三分钟检查一次，而不是每 15 分钟一次。

`omarchy agent account list` 显示每个账户及其最新限额，`omarchy agent account remove work` 遗忘一个账户，而 `omarchy agent account rename primary Hey` 重命名一个账户（或在面板中单击某个账户的名称）。这些命令作用于你的默认智能体的账户；要访问另一个 provider，请先点名它，例如 `omarchy agent account use codex side`。你已经在 `~/.claude` 或 `~/.codex` 中拥有的登录是 _Main_ 账户。Codex 的保留在原处；Claude 的在另一个账户处于活动状态时，会在它自己的文件夹中等待。某个账户超过约八小时未使用，可能会显示 _Sign-in required_；在面板中直接单击它以再次登录该账户，或切换到它并启动一个 session，它会自行刷新登录。你使用 `claude mcp add` 添加的 MCP 服务器会到达每个 Claude 账户，因为它们都在 `~/.claude` 中运行；对于 Codex 和 Grok，你在添加某个账户时已有的服务器会随之到达该账户，但之后添加的只会到达你添加它们时所在的账户。Claude Desktop 保留它自己的登录，而使用 CLI 二进制文件的绝对路径配置的 Codex 或 Grok 工具不会跟随切换。显式的 `CLAUDE_CONFIG_DIR`、`CODEX_HOME` 或 `GROK_HOME` 优先于所选账户。

### 崩溃诊断

Omarchy 会监视 systemd-coredump 中的进程崩溃。一旦你选择了默认智能体，你的任何转储核心的程序都会带来一个“Process crashed”通知——单击它，崩溃就会连同 Omarchy 的 omarchy-diagnose-crash skill 一起交给你的默认智能体，该 skill 会引导智能体从 core dump 中确立事实，并决定该崩溃是否值得向上游报告。你也可以使用 `omarchy agent crash <pid>` 手动对 `coredumpctl list` 中的任意 PID 运行它。

这项监视默认开启。在 _Trigger > Toggle > Crash Capture Off_ 下关闭它（或使用 `omarchy toggle crash-capture`），通知就会停止；`omarchy agent crash <pid>` 仍然可以手动工作。

崩溃也可以一次为一个程序静默，这正是诊断在结束时向你提供的。`omarchy crash mute hyprland` 仅停止该程序的通知，`omarchy crash mute hyprland off` 将它们恢复，而单独使用 `omarchy crash mute` 会列出你已静默的内容。它既接受二进制文件的路径，也接受其名称，因此 `omarchy crash mute /usr/bin/hyprland` 效果相同。为带有空格的名称加引号，例如 `omarchy crash mute 'Some App'`。其他一切仍会通知，被静默的程序仍会崩溃——这隐藏了提醒，它并不会修复任何东西。

### 桌面应用

_Install > AI_ 菜单还包含一些图形化 AI 应用：Amp Desktop、Antigravity Desktop、ChatGPT desktop app、Claude desktop app（Anthropic 的 Linux beta 版，带有 Chat、Cowork 和 Claude Code 标签页）、用于与 xAI 的模型聊天的 Grok Bot、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexity desktop app 和 T3 Code。Grok Bot 是桌面聊天应用。编程智能体是 `grok` 命令。

Hermes Desktop 是需要了解的那一个，因为一台机器只有一个 Hermes，而它是该应用的：Hermes 始终只能通过该应用安装，而默认智能体运行的 `hermes` 命令也是该应用的。将 Hermes 选为默认智能体会安装与 _Install > AI_ 条目相同的东西：软件包，以及由 Hermes 自己的安装程序在 `~/.hermes` 下设置的 Hermes runtime，第一次需要几分钟。该 runtime 是终端 `hermes` 命令、默认智能体和应用都使用的那一个 Hermes，并且它会使用 `hermes update` 自行更新，而不是等待 Omarchy 发布新版本。安装它还会将 Omarchy 主题作为名为 `omarchy` 的皮肤交给 Hermes，当你切换主题时，每个 Hermes 界面都会随之跟随；如果你不愿意这样，在 Hermes 的 Appearance 设置下或使用 `/skin` 选择另一个，而 Omarchy 会尊重该选择。在 _Remove > AI_ 下删除该应用时，会先关闭 Hermes（包括 gateway），并带走该 runtime，并保留你的聊天、记忆和 Hermes 为自己编写的 skills，除非你另有指示：它会询问是否也应删除该数据和你的连接设置，默认为否。

OpenClaw 的桌面体验是其 Control UI，它作为由其自己的本地 gateway 支持的 web app 打开。OpenClaw 位于 `~/.openclaw` 中，并会自行更新：使用 Control UI 的“Update Gateway”按钮或运行 `openclaw update`，gateway 会在新版本上重启。Omarchy 只选择全新安装从哪个版本开始。OpenClaw 也可以是你的默认智能体：在 _Agent > Harness_ 下选择它会设置位于 `~/.openclaw` 中的同一个副本，而该智能体会打开连接到其 gateway 的 OpenClaw 终端 UI。在 _Remove > AI_ 下删除 OpenClaw 会带走 gateway 服务和应用，然后询问 `~/.openclaw` 是否也应删除，因为其中保存着你的聊天和凭据，以及 OpenClaw 本身和它下载的插件 runtime；默认保留它，再次安装 OpenClaw 时会将其重新拾起。

Herdr Desktop 是 [Herdr](https://herdr.dev) 桌面应用：spaces、tabs 以及终端和编程智能体的 panes，即使你关闭窗口，它们仍会在其核心中运行。它来自 Herdr 自己的安装程序而非软件包，因此位于 `~/.local/share/herdr-app` 中，当你尚没有时，它会在 `~/.local/bin/herdr-core` 中带来其核心，并会自行更新这两者。它与 Omarchy 在 `Super + Ctrl + Return` 上提供的 `herdr` 命令并存，而不是取代它，并且获得该命令的直接按键：`Alt + Return` 和 `Alt + Shift + Return` 向下或向右拆分 pane，`Alt + Escape` 关闭它，`Ctrl + Alt + Arrow` 在 panes 之间移动，`Alt + 1..9` 和 `Alt + Left/Right` 选择 tab，而 `Alt + Up/Down` 在 spaces 之间移动。`Ctrl + 1..9` 选择 space，而 `Alt + Shift + Up/Down` 在智能体之间步进。`Ctrl + Space` 前缀按键仍仅限终端，因为应用无法为一个序列按住普通的 Ctrl 键。Omarchy 将这些写入 `~/.config/herdr-app/keys.json`，而 `omarchy-refresh-herdr-app` 会将它们恢复。安装它会选择 Herdr 的 Omarchy 主题，从那时起它会跟随你的 Omarchy 主题。Herdr 为浅色模式保留一个主题，为深色模式保留一个，因此在深色和浅色 Omarchy 主题之间切换后，再在 Herdr 的主题选择器中为另一种模式选择一次 Omarchy。

T3 Code 从位于 `~/.local/share/t3code` 中的其官方 AppImage 发布运行，而不是从软件包运行，因此它会自行更新。安装它时会询问是从 Stable 还是 Nightly 频道开始；之后在 T3 Code 的设置中切换。你的 threads 和设置位于 `~/.t3` 中，在 _Remove > AI_ 下删除 T3 Code 会将它们一并带走。

### 本地模型

在你自己的机器上为你的编程智能体运行一个开放模型。你的提示词和代码留在机器上；发送给模型的内容不会离开它。开始于：

```bash
omarchy models use best text
```

这为本机设置了最好的 text 模型，即你的智能体使用的那类。Image、video 和 music 模型各有其最好的：`omarchy models use best image`、`video` 或 `music`。运行 `omarchy models use best` 查看每种类型为本机挑选的结果。

或者从顶栏中其紧挨智能体图标的 sparkles 图标打开本地模型面板，或使用 Super + Ctrl + Alt + X，然后选择 +。当某个模型适合本机时，该图标会出现。运行这些模型的 Podman 随 Omarchy 提供，NVIDIA 机器上的 NVIDIA container toolkit 也是如此，它为它们提供 GPU；如果任何一个缺失，首次设置会安装它。然后 Omarchy 为本机挑选推荐的模型，下载它，并启动它。预计下载量为数十 GB，并且在模型运行时会占用机器的大部分内存：Flash Next 在使用其完整的 256K 上下文时会使用约 100 GiB。如果其他模型占用了它所需的内存，它会被设置为已停止状态，准备在你停止一个后启动。该模型在注销时停止；当你需要内存做其他事情时，请自行停止它。

`omarchy models list` 显示选项并解释为什么有些不适合。要设置另一个，请运行 `omarchy models use <recipe>`。如今，`qwen3.8-flash-next-gufo` 和 `qwen3.8-27b-gufo` 可用于 128 GB Strix Halo 机器；27B 占用约 40 GiB，因此它为其他工作留出了空间。在一台配备 Intel Arc B390 的 64 GB 笔记本上，`qwen3.6-35b-a3b-llamacpp` 在约 30 GiB 中运行。新的配方和推荐会通过软件包随 `omarchy update` 到来。

你设置的每个模型都会在本地模型面板中获得自己的一行：play 以启动它，pause 以停止它并释放其内存，terminal 按钮以在它上面打开你的智能体。顶部有一条栏显示机器内存如何在 Omarchy 本身（系统和你的应用）、每个正在运行的模型以及空闲部分之间划分。指向一个已停止的模型时，该栏会显示它是否适合，或还差多少。多个模型可以在它们一起适合内存时同时运行；如果一个不适合，Omarchy 会说应停止哪个正在运行的模型。按其 logo 拖动行以重新排序它们，并在一个选定的行上按 Delete 以删除一个模型及其下载。

你设置的每个编程模型还会在应用启动器中获得自己的条目，位于该模型的名称之下并带有其制造者的 logo，就像登录 Claude、Codex 或 Grok 时会添加一个一样。它在该模型上打开你的智能体，并且如果它未运行，会先启动该模型：终端会显示它正在加载，并在它启动后交给智能体。删除一个模型会删除其条目。

并非每个模型都是用于编程的。Image、video 和 music 模型改在 Fantasi 中打开，Fantasi 是 Omarchy 的应用，用于使用在这台机器上运行的模型制作图片、视频和音乐，可在那里或从它们在本地模型面板中的行选择。

模型会完全按照设置时的样子继续运行，因此 Omarchy 更新永远不会在你的智能体之下重启一个。当 Omarchy 有更新的 runtime 或更新的 weights 用于你已设置的模型时，其行会显示一个更新按钮：按下它，该模型会在后台重新设置，只下载已更改的部分，并在新版本上重启。之前已停止的模型仍保持停止。`omarchy models update` 对每个模型从终端执行同样的操作。

从命令行，`omarchy models start <recipe>` 和 `omarchy models stop <recipe>` 执行同样的操作，`omarchy models status` 显示每个模型，而 `omarchy agent --local` 会在 pi 中打开你上次启动的模型，无论你的默认智能体是什么。OpenCode 和 Qwen Code 也可以使用本地模型：`omarchy models harness opencode` 或 `omarchy models harness qwen` 改为在那里打开它们，而 `omarchy models harness pi` 则返回。pi 还会在其自己的模型选择器中列出你已设置的每个模型，以及在你已配对的机器上的那些模型，因此普通的 `pi` 也可以访问它们。任何与 OpenAI 兼容的客户端也可以连接：`status` 显示每个模型的地址（第一个是 `http://127.0.0.1:11435/v1`），recipe 名称就是模型，而密钥位于 `~/.config/omarchy/agent-local/key` 中。

`omarchy models remove <recipe>` 删除一个模型以及没有其他模型使用的下载。

第三方 runtimes 会标注其发布者。Omarchy 在没有网络访问的情况下运行每个模型。

### 本地 LLMs

Omarchy 推荐两种运行本地 LLM 模型的方式：LM Studio 和 Ollama。LM Studio 提供一个 GUI 界面用于查找开放权重模型、安装它们并运行它们。这是一种轻松入门的好方法。Ollama 提供 CLI 以类似方式完成此事。但如果你是本地模型新手，我会从 LM Studio 开始。你可以在 Omarchy Menu 的 _Install > AI_ 下安装任意一个。

### Omarchy skills

Agent skills 帮助 AI 以特定方式使用特定工具，而 Omarchy 附带了其中七个。omarchy skill 涵盖定制系统，例如调整你的 Hyprland 配置或调整顶栏。omarchy-make-theme、omarchy-make-plugin、omarchy-make-app 和 omarchy-make-game 涵盖制作新东西，omarchy-contribute 涵盖报告 bug 或向 upstream 发送修复，而 omarchy-diagnose-crash 则处理崩溃的 core dump。它们被符号链接到 Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` 和每个 `~/.hermes/profiles/*/skills`）的 skill 目录以及通用的 `~/.agents/skills` 位置，因此大多数 harness 会自动拾取它们。具有相同名称的你自己的 skill 文件夹优先。

但你应该将这些 skills 视为实验性的。不同模型将以不同效果使用它。最好先在 plan mode 下运行，这样你就能了解智能体想要更改什么。然后准备好回滚更改，甚至调用 `omarchy reinstall configs`，如果智能体把一切弄得一团糟的话。
