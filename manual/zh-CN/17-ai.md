### 安装和更新智能体

除 Hermes 和 OpenClaw 外，这些智能体都使用 mise 的懒安装：首次启动时安装 CLI，之后的启动会重复使用它。mise 还会至多每四小时检查一次已安装智能体是否有新版本，就在它启动前，或在 shell 提示符下在后台检查。如果更新失败或你处于离线状态，就会运行已安装的版本。`omarchy update` 会随 Omarchy 的其余部分一起更新已安装的智能体，而 `mup` 只更新由 mise 管理的工具。

智能体自带的更新程序，例如 `claude update`、`codex update` 或应用中的更新按钮，不会更新由 mise 管理的安装。`codex update` 会失败，而 `claude update` 可能会报告成功，却安装了 mise 不跟踪的单独副本。如果你更愿意使用智能体原生的安装程序和更新程序，请将其加入 `disable_tools`；请参阅 [预装 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

要提前安装所有已配置的懒工具，在需要之前运行 `mise install --include-lazy`。这包括 Omarchy 的其他默认 CLI 工具以及这些智能体。有关安装单个工具或使用你自己的安装，请参阅 [预装 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

`grok` 通过 mise 的第一方 `grok` 包安装，与 `claude` 和 `codex` 相同。运行 `grok`，或在 _Agent > Harness_ 下选择它。跳过 x.ai 上的 `curl | bash` 安装程序。那条路径会在 `~/.grok/bin` 中放入第二个副本，将其前置到 `PATH`，并覆盖 Omarchy 的包装器。

`dsh` 会在 `127.0.0.1:3080` 打开其浏览器 UI，并以启动目录作为默认工作区。其浏览器 UI 不接受起始提示，因此 `omarchy agent prompt` 打开它时会将提示放在你的剪贴板上以便粘贴。Omarchy 以 DeepSeek 的免批准权限预设启动它。当你使用 DeepSeek 的官方模型 API 时，DeepSeek Harness 会将会话日志上传到 DeepSeek；在其浏览器 UI 的 _Settings > General > Upload Session Log_ 下关闭此功能。你发送给它的反馈也会随会话一起上传，除非你使用 `DSH_TELEMETRY_MODE=DISABLED` 启动它。

### 默认智能体

使用 `omarchy default agent <name>` 或在 Omarchy 菜单（`Super + Space`）的 _Agent > Harness_ 下选择你的默认智能体。如果智能体尚未安装，选择它会先安装它，并且它还会在应用启动器中获得自己的启动器，位于 Agent 旁边。全新的 Omarchy 会通过一次性通知邀请你做出此选择。

选择 Claude 时还会尝试为 Chromium、Chrome、Brave、Brave Origin 和 Edge 设置其浏览器扩展。此扩展设置适用于所有用户，可能会要求输入你的系统密码；取消或扩展安装失败仍会选择并启动 Claude。重启你的浏览器，如有提示则启用该扩展，并登录 Claude 以完成连接。在 Claude 中运行 `/chrome` 检查连接。Firefox 和 Zen 不支持此扩展。如果在此设置添加之前 Claude 已经是你的默认智能体，请再次选择它以安装该扩展。

一旦你做出选择，`Super + Shift + Ctrl + A` 会在专用终端窗口中启动默认智能体（如果你尚未选择，则会打开选择器）。你也可以用 `omarchy agent prompt "Review this project"` 直接让它执行任务。Freebuff 和 DeepSeek Harness 不接受起始提示，因此它们打开时会将提示放在你的剪贴板上以便粘贴。以这种方式启动的智能体会以各自的不要停下来询问模式无人值守运行，所以请做好它们真的会做事的准备！MiniMax Code 的交互式会话没有这种模式，因此它会照常请求权限。并且由于智能体拒绝记住对你的主目录的信任，从 `$HOME` 启动时会在 `~/Work` 中启动。

还有终端快捷方式：`a` 在当前终端中内联运行默认智能体，而 `c`、`cx` 和 `cy` 则直接启动 OpenCode、Claude Code 和 Codex（同样以其自动批准模式）。主题更改也会同步到智能体：当你切换 Omarchy 主题时，Claude Code、Pi、OpenCode 和 Hermes（一旦 Omarchy 已安装它）都会跟随。

### 你的智能体指令

每个智能体的个人规则位于 `~/.agents/AGENTS.md`，与共享技能一起位于 `~/.agents/skills` 中。在 _Agent > Instructions_ 下打开它，它还会将其链接到每个保留自己全局文件的 harness 中：`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`~/.pi/agent/AGENTS.md`、`~/.config/opencode/AGENTS.md`、Copilot 的 `~/.copilot/copilot-instructions.md`，依此类推。Crush 和 Amp 读取 `~/.config/AGENTS.md` 链接，而 omp、Kimi 和 DeepSeek Harness 则直接读取 `~/.agents/AGENTS.md`。选择默认智能体也会链接它。如果你已有的指令文件在尚无共享文件时，会成为共享文件；否则它会作为 `.bak` 保留在链接旁边。安装另一个智能体后，运行 `omarchy agent instructions` 重新链接。

### 智能体面板

顶部栏有一个智能体图标。在你设置智能体之前，其面板会引导你登录 Claude、Codex 或 Grok，第一个将成为你的默认智能体。之后，面板将每个订阅放在一个页面上：每个智能体和帐户及其套餐、每个 5 小时会话和每周限额的计量表及重置前的剩余时间（悬停可查看确切百分比），或剩余的预付余额，位于一行轮播内容之下，该行会轮流显示你在所有这些服务上的使用情况，例如本周的 token 数和你最常用的模型。在 _Make something cool_ 下，它提供了用于新主题、插件、应用或游戏的入门提示，并将任务交给你的默认智能体。应用的构建方式与 Omarchy 自家的 Hype、Monologue 和 Omacut 相同，使用 C++ 和 Qt Quick，遵循 omarchy-make-app 智能体技能，所需的编译器和 Qt 组件都已安装。游戏是位于 `~/Games/vibes` 中的单个 three.js 页面，遵循 omarchy-make-game 智能体技能，并且全部从当前主题中的一个 Game Vibes 启动器打开；它们从网络加载 three.js，因此需要网络连接才能启动。Claude Code、Codex、Grok、Kimi、Cursor 及其 Grok Bot 额度、GitHub Copilot、Muse、Antigravity 和 Devin 开箱即用地覆盖其限额，Kimchi 覆盖其套餐、预付额度和支出预算，而 Hermes、Mistral Vibe 和 Qwen Code 则在你使用过后显示其会话和 token。你通过 pi、omp 或 opencode 使用的服务商套餐和密钥也会显示：OpenCode Zen 和 Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan 和 Synthetic 及其限额；OpenRouter 和 DeepSeek 及其预付余额；Fireworks 及其过去 30 天的支出。你在自己硬件上运行的模型的 token 也计入总计；模型本身有自己的面板，在 [本地模型](#local-models) 下描述。每个智能体只计一次，按向其收费的一方计算，无论你通过多少个 harness 驱动它。

左键单击栏图标或按 `Super + Ctrl + X` 打开面板，右键单击启动你的默认智能体，中键单击刷新。其后的使用记录每 15 分钟由 `omarchy agent usage update` 重新生成，并且面板甚至可以通过同步文件夹合并来自你其他机器的使用情况。有关完整设置，请参阅位于 `$OMARCHY_PATH/shell/plugins/agents/` 下的 README。

### 多个订阅

如果你为多个 Claude、Codex 或 Grok 套餐付费，例如一个个人 Max 和一个工作套餐，Omarchy 可以让它们全部保持登录状态，并在它们之间切换。使用智能体面板中的 + 添加订阅，它会直接在那里引导你完成，或者使用 `omarchy agent account add claude Work`（或 `codex`，或 `grok`）。如果缺失，它会安装 CLI。每个服务商的第一个帐户通过你的普通浏览器登录，就在 CLI 一直查找的位置。之后的每个帐户都通过隐私窗口登录，因此你的浏览器已登录的帐户不会被误选；在那里登录为你要添加的帐户，并先关闭你已打开的任何隐私窗口。切勿为此注销 CLI：注销会撤销已保存的登录，该帐户将不得不重新添加。

要通过 SSH 将你的订阅登录信息复制到另一台 Omarchy 机器，请运行 `omarchy agent account copy user@laptop`。当目标机器没有安装接收器时，发送方会提供临时接收器，因此较旧的 Omarchy 机器无需更新即可接收帐户。已安装的接收器优先。此命令会复制所有 Claude、Codex 和 Grok 订阅；添加服务商名称以选择它们，如 `omarchy agent account copy laptop claude`。帐户名称和命令 ID 与源机器匹配，包括目标机器上已存在的帐户。无关的目标帐户如果名称冲突，会收到数字后缀，并且设置、技能、插件和对话历史都保留在每台机器本地。

目标机器上现有的凭据会保留。已在那里登录的源帐户，其名称会被同步，而不会替换其凭据；其他帐户则会添加在其旁边。要替换匹配帐户的已保存凭据，请在退出目标机器上该帐户的会话后，使用 `omarchy agent account copy --replace laptop claude`。全新的目标机器还会获得源机器的活动帐户和切换偏好；已建立的目标机器则保留自己的。

凭据通过 SSH 传输，并存储在目标机器的私有文件中，因此仅复制到你信任的机器。这是一次性复制，而非持续同步。Codex 刷新 token 可能会被另一台机器轮换，导致复制的登录需要续期；单独登录仍是多台机器同时使用最可靠的选择。请参阅 [Codex 的帐户身份验证指南](https://developers.openai.com/codex/auth/ci-cd-auth)。

每个服务商有一个帐户处于活动状态，每个新会话都以它开始：`cx`、`cy`、普通的 `claude`、`codex` 或 `grok`、通过 `omarchy agent` 启动的任何内容，以及在 `PATH` 上找到 CLI 的脚本或编辑器。使用 `omarchy agent account use work` 切换（并使用 `omarchy agent account use main` 切换回来），或在面板中按帐户编号然后按 `Enter`（或单击其 Use 按钮）。正在运行的 Claude 会话也会切换，从其下一条消息开始：每个 Claude 会话都在 `~/.claude` 中运行，该目录始终保存活动帐户的登录信息。由较旧 Omarchy 在帐户自己的文件夹中启动的 Claude 会话会保留该登录信息，直到退出，因此切换时会列出这些会话，并会在它们消失后自行完成。正在运行的 Codex 和 Grok 会话会保持在其启动时使用的帐户上。对话历史、设置、技能和插件在帐户间共享，因此同一文件夹中的 `claude --continue` 会在新帐户上从你离开的地方继续。

有多个帐户时，面板会并排显示每个帐户的限额，并标记活动帐户。默认情况下，Omarchy 会在活动帐户超过限额的 95% 时通知你，单击通知会切换到余量最多的帐户。将鼠标悬停在面板中的帐户行上，然后单击 Use 旁边出现的 Autoswitch（或按 `m`），或运行 `omarchy agent account mode auto`，让它自动切换；启用后，Autoswitch 会取代 Use 的位置，再次单击它则恢复为通知。添加数字可更改阈值，如 `omarchy agent account mode auto 90`。如果每个帐户都超过阈值，你会收到一次通知，并告知哪个帐户最先释放。在活动帐户距其阈值 15 个百分点以内时（默认值为 80%），其限额会每三分钟检查一次，而不是每 15 分钟一次。

`omarchy agent account list` 显示每个帐户及其最新限额，`omarchy agent account remove work` 会忘记一个帐户，`omarchy agent account rename primary Hey` 则重命名一个帐户（或单击面板中的帐户名称）。这些命令作用于你的默认智能体的帐户；要访问其他服务商，请先命名它，如 `omarchy agent account use codex side`。你在 `~/.claude` 或 `~/.codex` 中已有的登录是 _Main_ 帐户。Codex 的保持原位；Claude 的则在另一个帐户活动时等待在其自己的文件夹中。帐户超过约八小时未使用，可能会显示 _Sign-in required_；单击它直接在面板中重新登录该帐户，或切换到它并启动会话，后者会自动刷新登录信息。你使用 `claude mcp add` 添加的 MCP 服务器会到达每个 Claude 帐户，因为它们都在 `~/.claude` 中运行；对于 Codex 和 Grok，在帐户添加时你已有的服务器会随之而来，但之后的服务器仅会到达你添加它们的帐户。Claude Desktop 保留自己的登录，而使用 CLI 二进制文件绝对路径配置的 Codex 或 Grok 工具不会跟随切换。显式的 `CLAUDE_CONFIG_DIR`、`CODEX_HOME` 或 `GROK_HOME` 优先于所选帐户。

### 崩溃诊断

Omarchy 会监视 systemd-coredump 以发现进程崩溃。一旦你选择了默认智能体，你的任何程序发生核心转储都会带来 "Process crashed" 通知，单击它，崩溃就会连同 Omarchy 的 omarchy-diagnose-crash 技能一并交给你的默认智能体，该技能会引导智能体从核心转储中查明事实，并决定该崩溃是否值得向上游报告。你也可以使用 `omarchy agent crash <pid>`，根据 `coredumpctl list` 中的任何 PID 手动运行它。

此监视默认开启。在 _Trigger > Toggle > Crash Capture Off_ 下关闭它（或使用 `omarchy toggle crash-capture`），通知就会停止；`omarchy agent crash <pid>` 仍可手动使用。

也可以逐个程序静默崩溃，这正是诊断在最后向你提供的功能。`omarchy crash mute hyprland` 仅停止该程序的通知，`omarchy crash mute hyprland off` 将其带回来，而单独运行 `omarchy crash mute` 则列出你已静默的内容。它接受二进制文件的路径如同接受其名称一样，因此 `omarchy crash mute /usr/bin/hyprland` 效果相同。对带空格的名称使用引号，如 `omarchy crash mute 'Some App'`。其他一切仍会通知，被静默的程序仍会崩溃，这隐藏了提醒，并没有修复任何问题。

### 桌面应用

_Install > AI_ 菜单还包含一些图形化 AI 应用：Amp Desktop、Antigravity Desktop、ChatGPT 桌面应用、Claude 桌面应用（Anthropic 的 Linux beta 版，具有 Chat、Cowork 和 Claude Code 标签页）、用于与 xAI 模型聊天的 Grok Bot、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexity 桌面应用和 T3 Code。Grok Bot 是桌面聊天应用。编程智能体是 `grok` 命令。

Hermes Desktop 是你需要了解的，因为一台机器只有一个 Hermes，而它属于该应用：Hermes 只能通过该应用安装，默认智能体运行的 `hermes` 命令也是该应用的。选择 Hermes 作为默认智能体会安装与 _Install > AI_ 条目相同的内容：该软件包，以及由 Hermes 自己的安装程序在 `~/.hermes` 下设置的 Hermes 运行时，首次使用需要几分钟。该运行时是终端 `hermes` 命令、默认智能体和该应用都使用的唯一的 Hermes，它通过 `hermes update` 自我更新，而不是等待 Omarchy 发布。安装它还会将 Omarchy 主题作为名为 `omarchy` 的皮肤交给 Hermes，每个 Hermes 界面切换主题时都会跟随；如果你不希望这样，请在 Hermes 的 Appearance 设置下或使用 `/skin` 选择其他皮肤，Omarchy 会保留该选择。在 _Remove > AI_ 下移除该应用会先关闭 Hermes，包括网关，并随之带走该运行时，并保留你的聊天、记忆和 Hermes 为自己编写的技能，除非你另行指示：它会询问你的数据和连接设置是否也应该一并删除，默认为否。

OpenClaw 的桌面体验是其 Control UI，它作为由其自己的本地网关支持的 Web 应用打开。OpenClaw 位于 `~/.openclaw` 并自我更新：使用 Control UI 的 "Update Gateway" 按钮或运行 `openclaw update`，网关将在新版本上重启。Omarchy 仅选择全新安装的起始版本。OpenClaw 也可以是你的默认智能体：在 _Agent > Harness_ 下选择它会设置位于 `~/.openclaw` 的同一副本，智能体会打开附加到其网关的 OpenClaw 终端 UI。在 _Remove > AI_ 下移除 OpenClaw 会随之带走网关服务和该应用，然后询问 `~/.openclaw` 是否也应该删除，因为那里保存着你的聊天和凭据，以及 OpenClaw 本身和它下载的插件运行时；默认保留它，再次安装 OpenClaw 时会重新使用它。

Herdr Desktop 是 [Herdr](https://herdr.dev) 桌面应用：包含终端和编程智能体的空间、标签页和窗格，当你关闭窗口时，它们在其核心中继续运行。它来自 Herdr 自己的安装程序而不是软件包，因此位于 `~/.local/share/herdr-app`，当你还没有时，会在 `~/.local/bin/herdr-core` 中附带其核心，并自我更新两者。它位于 Omarchy 在 `Super + Ctrl + Return` 上提供的 `herdr` 命令旁边，而不是取代它，并获得该命令的直接按键：`Alt + Return` 和 `Alt + Shift + Return` 向下或向右拆分窗格，`Alt + Escape` 关闭它，`Ctrl + Alt + Arrow` 在窗格之间移动，`Alt + 1..9` 和 `Alt + Left/Right` 选择标签页，`Alt + Up/Down` 在空间之间移动。`Ctrl + 1..9` 选择空间，`Alt + Shift + Up/Down` 在智能体之间步进。`Ctrl + Space` 前缀键仅保留给终端，因为应用无法为序列按住普通的 Ctrl 键。Omarchy 将这些写入 `~/.config/herdr-app/keys.json`，`omarchy-refresh-herdr-app` 会将其恢复。安装它会选择 Herdr 的 Omarchy 主题，从此跟随你的 Omarchy 主题。Herdr 为浅色模式保留一个主题，为深色模式保留一个主题，因此在深色和浅色 Omarchy 主题之间切换后，请在 Herdr 的主题选择器中再次选择 Omarchy 以用于另一种模式。

T3 Code 从其位于 `~/.local/share/t3code` 的官方 AppImage 版本运行，而不是从软件包运行，因此它会自我更新。安装它时会询问在 Stable 还是 Nightly 频道开始；之后在 T3 Code 的设置中切换。你的线程和设置位于 `~/.t3`，在 _Remove > AI_ 下移除 T3 Code 会随之带走它们。

### 本地模型

在你自己的机器上为你的编程智能体运行开放模型。你的提示和代码保留在机器上；发送给模型的内容不会离开它。从以下开始：

```bash
omarchy models use best text
```

这会为这台机器设置最佳的文本模型，也就是你的智能体使用的类型。图像、视频和音乐模型也有各自的最佳选择：`omarchy models use best image`、`video` 或 `music`。运行 `omarchy models use best` 查看每种类型为这台机器挑选的选择。

或从顶部栏的星光图标，位于智能体图标旁边，打开本地模型面板，或使用 Super + Ctrl + Alt + X，然后选择 +。当有适合这台机器的模型时，该图标会显示。运行模型的 Podman 随 Omarchy 提供，NVIDIA 机器上的 NVIDIA 容器工具包也是如此，它为模型提供 GPU；如果其中任何一项缺失，首次设置时会安装它。然后 Omarchy 为这台机器挑选推荐的模型，下载并启动它。预计会有数十 GB 的下载，并且在模型运行时会占用大部分机器内存：Flash Next 使用其完整 256K 上下文时约占 100 GiB。如果其他模型占用了它所需的内存，它会被设置为已停止状态，准备在你停止一个后启动。模型在注销时停止；当你需要内存做其他事情时，请自己停止它。

`omarchy models list` 显示选项，并解释为什么有些不适合。要设置另一个，请运行 `omarchy models use <recipe>`。如今，`qwen3.8-flash-next-gufo` 和 `qwen3.8-27b-gufo` 适用于 128 GB Strix Halo 机器；27B 约占 40 GiB，因此为其他工作留出了空间。在配备 Intel Arc B390 的 64 GB 笔记本电脑上，`qwen3.6-35b-a3b-llamacpp` 约在 30 GiB 中运行。新配方和推荐通过软件包随 `omarchy update` 抵达。

你设置的每个模型在本地模型面板中都有一行：播放以启动它，暂停以停止它并释放其内存，以及终端按钮以在其上打开你的智能体。横跨顶部，一个条形图显示机器内存如何在 Omarchy 本身（系统和你的应用）、每个正在运行的模型和空闲部分之间分配。指向已停止的模型时，该条形图显示它是否适合，或差多少。多个模型可以在内存足够时同时运行；如果一个不适合，Omarchy 会说明要停止哪个正在运行的模型。拖动行按其徽标重新排序，然后按 Delete 删除选定的行以移除模型及其下载。

你设置的每个编程模型也会在应用启动器中获得其自己的条目，位于模型名称下，并带有其制造商的徽标，就像登录 Claude、Codex 或 Grok 会添加一个一样。它在该模型上打开你的智能体，如果模型未运行，则先启动它：终端会显示它正在加载，并在就绪后交给智能体。移除模型会移除其条目。

并非每个模型都用于编程。图像、视频和音乐模型则在 Fantasi 中打开，Fantasi 是 Omarchy 用于使用本机运行的模型制作图片、视频和音乐的应用，在那里或从它们在本地模型面板中的行选择。

模型会完全按照设置时的方式继续运行，因此 Omarchy 更新永远不会在你的智能体下重启模型。当 Omarchy 有更新的运行时或更新的权重可用于你已设置的模型时，其行会显示更新按钮：按下它，模型会在后台重新设置，仅下载已更改的内容，并在新版本上重启。已停止的模型会保持停止。`omarchy models update` 从终端对每个模型执行相同操作。

从命令行，`omarchy models start <recipe>` 和 `omarchy models stop <recipe>` 执行相同操作，`omarchy models status` 显示每个模型，`omarchy agent --local` 在 pi 中打开你最后启动的模型，无论你的默认智能体是什么。OpenCode 和 Qwen Code 也可以使用本地模型：`omarchy models harness opencode` 或 `omarchy models harness qwen` 会在那里打开它们，`omarchy models harness pi` 则返回。pi 还会在其自己的模型选择器中列出你已设置的每个模型，以及你在已配对机器上的模型，因此普通的 `pi` 也能访问它们。任何与 OpenAI 兼容的客户端也可以连接：`status` 显示每个模型的地址（第一个是 `http://127.0.0.1:11435/v1`），配方名称就是模型，密钥位于 `~/.config/omarchy/agent-local/key` 中。

`omarchy models remove <recipe>` 删除模型和其他模型未使用的下载。

第三方运行时标有其发布者。Omarchy 在无网络访问的情况下运行每个模型。

### 本地 LLM

Omarchy 推荐两种运行本地 LLM 模型的方式：LM Studio 和 Ollama。LM Studio 提供 GUI 界面，用于查找开放权重模型、安装它们并运行它们。这是轻松入门的好方法。Ollama 提供 CLI 以类似方式做到这一点。但如果你刚接触本地模型，我建议从 LM Studio 开始。你可以在 Omarchy 菜单的 _Install > AI_ 下安装其中任何一个。

### Omarchy 技能

智能体技能帮助 AI 以特定方式使用特定工具，Omarchy 提供了七个这样的技能。omarchy 技能涵盖定制系统，例如调整你的 Hyprland 配置或调整栏。omarchy-make-theme、omarchy-make-plugin、omarchy-make-app 和 omarchy-make-game 涵盖制作新事物，omarchy-contribute 涵盖报告 bug 或向上游发送修复，而 omarchy-diagnose-crash 则处理崩溃的核心转储。它们被符号链接到 Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` 和每个 `~/.hermes/profiles/*/skills`）以及通用的 `~/.agents/skills` 位置的技能目录中，因此大多数 harness 会自动选取它们。具有相同名称的你自己的技能文件夹优先。

但你应该将这些技能视为实验性的。不同的模型会以不同效果使用它。最好先在 plan mode 下运行，这样你就能了解智能体想要更改什么。然后准备好回滚更改，甚至调用 `omarchy reinstall configs`，以防智能体把一切搞得一团糟。
