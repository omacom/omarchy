### 安装和更新智能体

除 Hermes 和 OpenClaw 外，这些智能体都使用 mise 的惰性安装：首次启动时安装 CLI，之后的启动会重复使用它。mise 还会至多每四小时检查一次已安装的智能体是否有新版本，检查时机就在它启动之前，或者在 shell 提示符下于后台进行。如果更新失败或你处于离线状态，就会运行已安装的版本。`omarchy update` 会连同 Omarchy 的其余部分一起更新已安装的智能体，而 `mup` 只更新由 mise 管理的工具。

智能体自己的更新器，例如 `claude update`、`codex update`，或应用中的更新按钮，不会更新由 mise 管理的安装。`codex update` 会失败，而 `claude update` 可能报告成功，却安装了一份 mise 并不跟踪的独立副本。如果你更愿意使用智能体原生的安装器和更新器，把它加入 `disable_tools`；参见[预装 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

要在需要它们之前安装所有已配置的惰性工具，运行 `mise install --include-lazy`。这既包括智能体，也包括 Omarchy 的其他默认 CLI 工具。关于安装单个工具或使用你自己的安装，参见[预装 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

`grok` 通过 mise 的第一方 `grok` 包安装，与 `claude` 和 `codex` 的方式相同。运行 `grok`，或在 _Agent > Harness_ 下选择它。跳过 x.ai 上的 `curl | bash` 安装器。那条路径会在 `~/.grok/bin` 中放入第二份副本、把它加到 `PATH` 的最前面，并覆盖 Omarchy 的包装器。

`dsh` 会在 `127.0.0.1:3080` 打开它的浏览器 UI，并以启动目录作为它的默认工作区。它的浏览器 UI 不接受起始提示词，所以 `omarchy agent prompt` 打开它时会把提示词放在你的剪贴板上供你粘贴。Omarchy 以 DeepSeek 的免审批权限预设启动它。当你使用 DeepSeek 的官方模型 API 时，DeepSeek Harness 会把会话日志上传到 DeepSeek；在它的浏览器 UI 中于 _Settings > General > Upload Session Log_ 下关闭这一项。你发送给它的反馈也会连同会话一起上传，除非你用 `DSH_TELEMETRY_MODE=DISABLED` 启动它。

### 默认智能体

用 `omarchy default agent <name>` 或在 Omarchy 菜单（`Super + Space`）的 _Agent > Harness_ 下挑选你的默认智能体。如果该智能体尚未安装，挑选它会先安装它，它还会在应用启动器中获得一个属于自己的启动器，紧挨着 Agent。全新安装的 Omarchy 会通过一条一次性通知邀请你作出这一选择。

选择 Claude 时还会尝试为 Chromium、Chrome、Brave、Brave Origin 和 Edge 设置它的浏览器扩展。该扩展的设置适用于所有用户，并可能要求你输入系统密码；取消操作或扩展安装失败，仍会选择并启动 Claude。重启你的浏览器，在出现提示时启用该扩展，并登录 Claude 以完成连接。在 Claude 中运行 `/chrome` 来检查连接。Firefox 和 Zen 不支持此扩展。如果在加入此设置之前 Claude 已经是你的默认项，再次选择它以安装该扩展。

选择完成后，`Super + Shift + Ctrl + A` 会在一个专用的终端窗口中启动默认智能体（如果你尚未选择，则会调出选择器）。你也可以用 `omarchy agent prompt "Review this project"` 让它直接进入一项任务。Freebuff 和 DeepSeek Harness 不接受起始提示词，所以它们打开时会改为把提示词放在你的剪贴板上供你粘贴。以这种方式启动的智能体会以它们各自无需停下来询问的模式无人值守地运行，所以你要做好准备，它们真的会动手做事！MiniMax Code 的交互式会话没有这种模式，所以它会照常请求权限。而且由于智能体拒绝记住对你的主目录的信任，从 `$HOME` 启动时会在 `~/Work` 中开始。

也有终端快捷方式：`a` 在当前终端中内联运行默认智能体，而 `c`、`cx` 和 `cy` 则直接启动 OpenCode、Claude Code 和 Codex（同样处于它们的自动批准模式）。主题变化也会同步到智能体：当你切换 Omarchy 主题时，Claude Code、Pi、OpenCode 以及 Hermes（一旦 Omarchy 已安装它）都会随之变化。

### 你的智能体指令

适用于每个智能体的个人规则放在 `~/.agents/AGENTS.md` 中，紧挨着位于 `~/.agents/skills` 的共享技能。在 _Agent > Instructions_ 下打开它，它还会把该文件链接到每个保留其自有全局文件的 harness 中：`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`~/.pi/agent/AGENTS.md`、`~/.config/opencode/AGENTS.md`、Copilot 的 `~/.copilot/copilot-instructions.md`，等等。Crush 和 Amp 读取 `~/.config/AGENTS.md` 链接，而 omp、Kimi 和 DeepSeek Harness 则直接读取 `~/.agents/AGENTS.md`。选择默认智能体时也会链接它。如果你已有的指令文件在尚无共享文件时，它会成为共享文件；否则，它会作为 `.bak` 保留在链接旁边。安装另一个智能体后，运行 `omarchy agent instructions` 以重新链接。

### 智能体面板

顶栏有一个智能体图标。在你设置智能体之前，它的面板会引导你登录 Claude、Codex 或 Grok，第一个登录的会成为你的默认智能体。此后，该面板把每个订阅都放在同一页面上：每个智能体和账户及其套餐、每个智能体的 5 小时会话限额和每周限额的计量条以及距离重置的时间（悬停以查看确切百分比），或者剩余的预付余额，上方还有一行轮换展示你在所有智能体上的使用情况，例如本周的 tokens 用量和你最常用的模型。在 _Make something cool_ 下，它提供用于新建主题、插件、应用或游戏的入门提示词，把任务交给你的默认智能体。应用的构建方式与 Omarchy 自家的 Hype、Monologue 和 Omacut 相同，用 C++ 和 Qt Quick，并遵循 omarchy-make-app 智能体技能，它们所需的编译器和 Qt 组件都已安装。游戏是位于 `~/Games/vibes` 中的单个 three.js 页面，遵循 omarchy-make-game 智能体技能，全部从当前主题下的一个 Game Vibes 启动器打开；它们从网络加载 three.js，所以启动时需要网络连接。Claude Code、Codex、Grok、Kimi、Cursor 及其 Grok Bot 额度、GitHub Copilot、Muse、Antigravity 和 Devin 开箱即用地被覆盖，并显示其限额；Kimchi 显示其套餐、预付额度和消费预算；Hermes、Mistral Vibe 和 Qwen Code 则在你使用过它们之后显示其会话和 tokens。你通过 pi、omp 或 opencode 使用的提供商套餐和密钥也会显示：OpenCode Zen 和 Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan 以及 Synthetic，并显示其限额；OpenRouter 和 DeepSeek 显示其预付余额；Fireworks 显示其过去 30 天的消费；还有你在自己硬件上运行的模型，列在 Local models 下。每个智能体只计数一次，归在为它收费的一方之下，无论你通过多少个 harness 使用它。

左键点击顶栏图标或按 `Super + Ctrl + X` 打开面板，右键点击启动你的默认智能体，中键点击刷新。它背后的用量记录由 `omarchy agent usage update` 每 15 分钟重新生成一次，该面板甚至可以通过一个同步文件夹合并你其他机器的用量。完整设置参见 `$OMARCHY_PATH/shell/plugins/agents/` 下的 README。

### 多个订阅

如果你购买了不止一个 Claude、Codex 或 Grok 套餐——比如一个个人 Max 和一个工作套餐——Omarchy 可以让它们都保持登录并在它们之间切换。用智能体面板中的 + 添加订阅，它会在那里引导你完成；或用 `omarchy agent account add claude Work`（或 `codex`，或 `grok`）。如果缺失，它会安装 CLI。某个提供商的第一个账户通过你平常的浏览器登录，就在 CLI 一直查找的位置。此后的每一个账户都通过隐私窗口登录，因此你的浏览器已登录的账户不会被误选；在那里登录为你要添加的账户，并先关闭你已打开的任何隐私窗口。切勿为此退出 CLI 登录：退出登录会撤销已保存的登录，而该账户将不得不重新添加。

要通过 SSH 把你的订阅登录复制到另一台 Omarchy 机器，运行 `omarchy agent account copy user@laptop`。当目标机器未安装接收端时，发送方会提供一个临时接收端，因此较旧的 Omarchy 机器无需更新也能接收账户。已安装的接收端优先。此命令复制所有 Claude、Codex 和 Grok 订阅；加上提供商名称可选择它们，如 `omarchy agent account copy laptop claude`。账户名称和命令 ID 与源端保持一致，包括目标端已存在的账户。无关的目标账户在名称冲突时获得数字后缀，设置、技能、插件和对话历史则在每台机器上保持本地状态。

目标端已有的凭证会保留。对于目标端已有源账户登录的情况，会同步其名称而不替换其凭证；其他账户会在其旁边添加。要替换匹配账户的已保存凭证，在目标端退出该账户的会话后使用 `omarchy agent account copy --replace laptop claude`。新的目标端还会获得源端的活动账户和切换偏好；已有设置的目标端则保留自己的。

凭证经 SSH 传输，并存储在目标端的私有文件中，所以只复制到你信任的机器。这是 一次性复制，不是持续同步。Codex 的刷新令牌可能被另一台机器轮换，导致复制的登录需要续期；在多台机器上同时使用时，分别登录仍是最可靠的选择。参见 [Codex 的账户认证指南](https://developers.openai.com/codex/auth/ci-cd-auth)。

每个提供商有一个活动账户，每个新会话都以该账户开始：`cx`、`cy`、普通的 `claude`、`codex` 或 `grok`、任何通过 `omarchy agent` 启动的内容，以及在 `PATH` 上找到 CLI 的脚本或编辑器。用 `omarchy agent account use work` 切换（用 `omarchy agent account use main` 切换回去），或者在面板中按某账户的编号然后按 `Enter`（或点击它的 Use 按钮）。正在运行的 Claude 会话也会从它的下一条消息起切换：每个 Claude 会话都运行在 `~/.claude` 中，那里始终保存活动账户的登录。一个由旧版 Omarchy 在某账户自己的文件夹中启动的 Claude 会话，会保留该登录直至退出，因此切换时会指出那些会话，并在它们消失后自行完成。正在运行的 Codex 和 Grok 会话仍保留它们启动时的账户。对话历史、设置、技能和插件在账户之间共享，因此在同一文件夹中执行 `claude --continue` 会在新账户上从你离开的地方继续。

有多个账户时，面板会并排显示每个账户的限额，并标记活动账户。默认情况下，当活动账户超过某个限额的 95% 时，Omarchy 会通知你，点击该通知会切换到余量最多的账户。悬停面板中某账户的行，点击 Use 旁边出现的 Autoswitch（或按 `m`），或者运行 `omarchy agent account mode auto`，让它自行切换；开启期间，Autoswitch 会取代 Use 的位置，再次点击它会回到通知模式。加上数字可变更阈值，例如 `omarchy agent account mode auto 90`。如果每个账户都超过阈值，你会收到一次说明，以及哪个账户最早释放容量。当活动账户距离其阈值在 15 个百分点以内（默认时为 80%）时，它的限额每三分钟检查一次，而不是每 15 分钟检查一次。

`omarchy agent account list` 显示每个账户及其最新限额，`omarchy agent account remove work` 忘记一个账户，`omarchy agent account rename primary Hey` 重命名一个账户（或者点击面板中某个账户的名称）。这些命令作用于你的默认智能体的账户；要访问另一个提供商，先命名它，例如 `omarchy agent account use codex side`。你先前已存在于 `~/.claude` 或 `~/.codex` 中的登录是 _Main_ 账户。Codex 的仍保留在原处；当另一个账户处于活动状态时，Claude 的则保留在它自己的文件夹中。一个未使用超过约八小时的账户可能显示 _Sign-in required_；点击它可直接在面板中重新登录该账户，或者切换到该账户并启动一个会话，这会自动刷新登录。用 `claude mcp add` 添加的 MCP 服务器可到达每个 Claude 账户，因为它们都在 `~/.claude` 中运行；对于 Codex 和 Grok，在添加某个账户时你拥有的服务器会随之带到该账户，但之后添加的只会到达你添加它们的那个账户。Claude Desktop 有它自己的登录，配置为使用某个 CLI 二进制文件绝对路径的 Codex 或 Grok 工具不会跟随切换。显式的 `CLAUDE_CONFIG_DIR`、`CODEX_HOME` 或 `GROK_HOME` 优先于所选账户。

### 崩溃诊断

Omarchy 监视 systemd-coredump 的进程崩溃。一旦你选择了默认智能体，你的任何程序发生 core dump 都会带来一条 "Process crashed" 通知——点击它，崩溃就会连同 Omarchy 的 omarchy-diagnose-crash 技能交给你的默认智能体，该技能会带着智能体从 core dump 中查明事实，并决定该崩溃是否值得向上游报告。你也可以针对 `coredumpctl list` 中的任何 PID 手动运行它：`omarchy agent crash <pid>`。

监视默认开启。在 _Trigger > Toggle > Crash Capture Off_ 下关闭它（或使用 `omarchy toggle crash-capture`）后通知会停止；`omarchy agent crash <pid>` 仍可手动使用。

也可以逐个程序静音崩溃，这正是诊断在最后向你提供的选项。`omarchy crash mute hyprland` 仅停止该程序的通知，`omarchy crash mute hyprland off` 会恢复它们，单独执行 `omarchy crash mute` 会列出你已静音的内容。它既接受二进制文件的路径，也同样接受它的名称，所以 `omarchy crash mute /usr/bin/hyprland` 的效果相同。给带有空格的名称加引号，例如 `omarchy crash mute 'Some App'`。其他一切仍会通知，且被静音的程序仍然会崩溃——这只是隐藏提醒，并不能修复任何东西。

### 桌面应用

_Install > AI_ 菜单还提供一些图形 AI 应用：Amp Desktop、Antigravity Desktop、ChatGPT desktop app、Claude desktop app（Anthropic 的 Linux beta，带有 Chat、Cowork 和 Claude Code 标签页）、用于与 xAI 的模型聊天的 Grok Bot、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexity desktop app 和 T3 Code。Grok Bot 是桌面聊天应用。编程智能体则是 `grok` 命令。

Hermes Desktop 是需要了解的那一个，因为一台机器只有一个 Hermes，而它就是这个应用的：Hermes 始终只能通过该应用安装，而默认智能体运行的 `hermes` 命令也是该应用的。选择 Hermes 作为默认智能体会安装与 _Install > AI_ 条目相同的东西：该软件包，以及一个由 Hermes 自己的安装器在 `~/.hermes` 下设置的 Hermes 运行时，首次需要几分钟。这个运行时就是终端 `hermes` 命令、默认智能体和应用都使用的那一个 Hermes，它通过 `hermes update` 自我更新，而不是等待 Omarchy 发布更新。安装它还会把 Omarchy 主题作为名为 `omarchy` 的皮肤交给 Hermes，每当你切换主题时，每个 Hermes 界面都会随之变化；如果你不希望如此，在 Hermes 的 Appearance 设置下或使用 `/skin` 选择另一个，Omarchy 不会改动那个选择。在 _Remove > AI_ 下移除该应用会先关闭 Hermes，包括网关，并随之移除该运行时，同时保留你的聊天、记忆和 Hermes 为自己编写的技能，除非你另行指示：它会询问是否也应删除那些数据和你的连接设置，默认回答为否。

OpenClaw 的桌面体验是它的 Control UI，它作为一个由它自己的本地网关支持的 web app 打开。OpenClaw 位于 `~/.openclaw` 并自我更新：使用 Control UI 的 "Update Gateway" 按钮或运行 `openclaw update`，网关会在新版本上重启。Omarchy 只选择全新安装从哪个发行版开始。OpenClaw 也可以是你的默认智能体：在 _Agent > Harness_ 下选择它，会在 `~/.openclaw` 中设置同一个副本，该智能体打开连接到它的网关的 OpenClaw 终端 UI。在 _Remove > AI_ 下移除 OpenClaw 会移除网关服务和应用，随后询问是否也应删除 `~/.openclaw`，因为那里包含你的聊天和凭证，以及 OpenClaw 本身和它下载的插件运行时；默认保留它，再次安装 OpenClaw 时会重新使用它。

Herdr Desktop 是 [Herdr](https://herdr.dev) 桌面应用：由空间、标签页和窗格组成的终端和编程智能体，当你关闭窗口时它们会继续在它的核心中运行。它来自 Herdr 自己的安装器而不是某个软件包，所以它位于 `~/.local/share/herdr-app`，在你尚未拥有一个核心时还会随之把核心带入 `~/.local/bin/herdr-core`，并对二者进行自我更新。它与 Omarchy 以 `Super + Ctrl + Return` 提供的 `herdr` 命令并存，而不是替换它，并获得该命令的直接按键：`Alt + Return` 和 `Alt + Shift + Return` 向下或向右拆分窗格，`Alt + Escape` 关闭窗格，`Ctrl + Alt + Arrow` 在窗格之间移动，`Alt + 1..9` 和 `Alt + Left/Right` 选择标签页，`Alt + Up/Down` 在空间之间移动。`Ctrl + 1..9` 选择一个空间，`Alt + Shift + Up/Down` 在智能体之间逐步切换。前缀键 `Ctrl + Space` 仍仅在终端中可用，因为该应用无法为了一个按键序列按住普通的 Ctrl 键。Omarchy 把这些写入 `~/.config/herdr-app/keys.json`，`omarchy-refresh-herdr-app` 会把它们放回。安装它会选择 Herdr 的 Omarchy 主题，从此它会跟随你的 Omarchy 主题。Herdr 为浅色模式保留一个主题、为深色模式保留一个主题，因此在深色和浅色 Omarchy 主题之间切换后，再在 Herdr 的主题选择器中为另一个模式选择一次 Omarchy。

T3 Code 从位于 `~/.local/share/t3code` 中的官方 AppImage 发行版运行，而不是从软件包运行，因此它会自我更新。安装它时会询问是在 Stable 还是 Nightly channel 上开始；之后在 T3 Code 的设置中切换。你的线程和设置位于 `~/.t3`，在 _Remove > AI_ 下移除 T3 Code 会随之删除它们。

### 本地模型

在你自己的机器上为你的编程智能体运行一个开放模型。你的提示词和代码保留在这台机器上；发送给模型的任何东西都不会离开它。从这里开始：

```bash
omarchy agent local use best
```

或者，在顶栏的智能体面板中，选择 + 然后选择 Local AI，当有适合这台机器的模型时它会出现。运行模型的 Podman 随 Omarchy 提供，NVIDIA 机器上的 NVIDIA container toolkit 也是如此，它为模型提供 GPU；如果其中任何一个缺失，首次设置会安装它。然后 Omarchy 会挑选为这台机器推荐的模型、下载它并启动它。预计会下载数十 GB，并且在模型运行时会占用这台机器的大部分内存：Flash Next 启用它完整的 256K 上下文时使用约 100 GiB。如果其他模型占用了它所需的内存，它会被设置为停止状态，等你停止其中一个后就可启动。该模型在注销时停止；当你需要内存用于其他事情时，你自己停止它。

`omarchy agent local list` 显示选项，并解释为什么有些不适合。要设置另一个，运行 `omarchy agent local use <recipe>`。如今，`qwen3.8-flash-next-gufo` 和 `qwen3.8-27b-gufo` 可用于 128 GB Strix Halo 机器；27B 约占 40 GiB，因此它能为其他工作留出空间。在配备 Intel's Arc B390 的 64 GB 笔记本电脑上，`qwen3.6-35b-a3b-llamacpp` 在约 30 GiB 内运行。新的配方和建议通过 `omarchy update` 随软件包到达。

你设置的每个模型在智能体面板中都会有它自己的一行，紧挨着你的订阅：按播放启动它，按暂停停止它并释放它的内存，按终端按钮在该模型上打开你的智能体。当多个模型能同时容纳在内存中时，它们可以同时运行；如果某个容纳不下，Omarchy 会指出该停止哪个正在运行的模型。拖动各行以重新排列它们，在选中的一行上按 Delete 删除某个模型及其下载。

你设置的每个模型还会在应用启动器中获得它自己的条目，位于该模型的名称下，并带有其制造商的徽标，就像登录 Claude、Codex 或 Grok 会添加一个一样。它在该模型上打开你的智能体，如果模型尚未运行，会先启动它：终端会显示它正在加载，一旦就绪就会交给智能体。删除一个模型会删除它的条目。

并非每个模型都用于编程。图像、视频和音乐模型则在 Fantasi 中打开，Fantasi 是 Omarchy 用于以运行在这台机器上的模型创作图片、视频和音乐的应用，可从它们的启动器条目和它们在智能体面板中的行打开。

一个模型会按它设置时的状态确切地继续运行，因此 Omarchy 更新永远不会在你的智能体之下重启某个模型。当 Omarchy 拥有你已设置模型的更新运行时或更新权重时，它的那一行会显示一个更新按钮：按下它，模型会在后台重新设置，只下载发生变化的内容，并在新版本上重启。曾处于停止状态的模型会保持停止。`omarchy agent local update` 在终端中对每个模型做同样的事情。

从命令行看，`omarchy agent local start <recipe>` 和 `omarchy agent local stop <recipe>` 做同样的事情，`omarchy agent local status` 显示每个模型，`omarchy agent --local` 在你最后启动的模型上打开你的默认智能体。pi、OpenCode 和 Qwen Code 可以使用其中一个；如果是任何其他默认项，它会在 pi 中打开，或在你没有 pi 时在 OpenCode 中打开。pi 还会在它自己的模型选择器中列出你已设置的每个模型，以及在你与之配对的机器上的那些模型，所以直接运行 `pi` 也可以访问它们。任何兼容 OpenAI 的客户端也可以连接：`status` 显示每个模型的地址（第一个是 `http://127.0.0.1:11435/v1`），recipe 名称即是模型，密钥位于 `~/.config/omarchy/agent-local/key`。

`omarchy agent local remove <recipe>` 删除一个模型以及其他任何模型都没有在使用的下载。

第三方运行时标有它们的发布者。Omarchy 在没有网络访问的情况下运行每个模型。

### 本地 LLM

Omarchy 推荐两种运行本地 LLM 模型的方式：LM Studio 和 Ollama。LM Studio 提供一个 GUI 界面，用于查找开放权重模型、安装它们并运行它们。它是轻松上手的好方法。Ollama 提供一个 CLI 以类似方式做到这一点。但如果你是本地模型的新手，我会从 LM Studio 开始。你可以在 Omarchy 菜单的 _Install > AI_ 下安装其中任何一个。

### Omarchy 技能

智能体技能帮助 AI 以特定方式使用特定工具，Omarchy 随附了其中七个。omarchy 技能涵盖定制系统，比如调整你的 Hyprland 配置或调整顶栏。omarchy-make-theme、omarchy-make-plugin、omarchy-make-app 和 omarchy-make-game 涵盖制作新东西，omarchy-contribute 涵盖报告 bug 或向上游发送修复，omarchy-diagnose-crash 则深入分析一次崩溃的 core dump。它们以符号链接加入 Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` 以及每个 `~/.hermes/profiles/*/skills`）和通用的 `~/.agents/skills` 位置的技能目录，所以大多数 harness 会自动获取它们。一个与之同名的你自己的技能文件夹优先。

但你应该把这些技能看作实验性的。不同的模型使用它的效果会不同。最好先在 plan mode 下运行，这样你就能了解智能体想要改变什么。然后准备好回滚变更，甚至在智能体把一切弄得一团糟时调用 `omarchy reinstall configs`。
