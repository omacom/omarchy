### 安装和更新智能体

除 Hermes 和 OpenClaw 外，这些智能体使用 mise 的惰性安装：首次启动时安装 CLI，之后的启动会复用它。mise 还会至多每四小时检查一次已安装的智能体是否有新版本，就在它启动之前或在 shell 提示符下于后台检查。如果该更新失败或你处于离线状态，则运行已安装的版本。`omarchy update` 会随着 Omarchy 的其余部分一起更新已安装的智能体，而 `mup` 仅更新由 mise 管理的工具。

智能体自带的更新程序，例如 `claude update`、`codex update`，或应用中的更新按钮，不会更新由 mise 管理的安装。`codex update` 会失败，而 `claude update` 可能报告成功，却安装了一份 mise 并不追踪的独立副本。如果你更愿意使用智能体原生的安装程序和更新程序，请将其添加到 `disable_tools`；请参阅[预装的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

要在需要之前安装所有已配置的惰性工具，请运行 `mise install --include-lazy`。这既包括 Omarchy 的其他默认 CLI 工具，也包括这些智能体。关于安装单个工具或使用你自己的安装，请参阅[预装的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

`grok` 通过 mise 的第一方 `grok` 软件包安装，方式与 `claude` 和 `codex` 相同。运行 `grok`，或在智能体面板中为它加星标。请跳过 x.ai 上的 `curl | bash` 安装程序。那条路径会在 `~/.grok/bin` 中放入第二份副本，将其置于 `PATH` 的最前面，并覆盖 Omarchy 的包装器。

`dsh` 会在 `127.0.0.1:3080` 打开其浏览器 UI，并以启动目录作为其默认工作区。它的浏览器 UI 不接受起始提示，因此 `omarchy agent prompt` 打开它时会把提示放在你的剪贴板上供你粘贴。Omarchy 会以 DeepSeek 的无需批准权限预设来启动它。当你使用其官方模型 API 时，DeepSeek Harness 会将它会将向你发送反馈。将其关闭的位置是在其浏览器 UI 中的 _Settings > General > Upload Session Log_。除非你以 `DSH_TELEMETRY_MODE=DISABLED` 启动它，否则你发送给它的反馈也会随会话一并上传。

### 默认智能体

使用智能体面板中某个智能体旁边的星标来选择你的默认智能体，默认智能体上的星标是实心的；或使用 `omarchy default agent <name>`，它也接受面板中没有对应行的任何框架。如果该智能体尚未安装，选择它时会先安装它，并且它还会在应用启动器中获得它自己的启动器，就在 Agent 旁边。一套全新的 Omarchy 会通过一次性通知邀请你设置一个默认智能体，该通知会打开智能体面板。

选择 Claude 还会尝试为 Chromium、Chrome、Brave、Brave Origin 和 Edge 设置其浏览器扩展。该扩展设置适用于所有用户，并且可能需要你的系统密码；取消或扩展安装失败仍然会选择并启动 Claude。重启你的浏览器，如有提示则启用该扩展，并登录 Claude 以完成连接。在 Claude 中运行 `/chrome` 以检查连接。Firefox 和 Zen 不支持此扩展。如果你在此设置被添加之前 Claude 已经是你的默认智能体，请再次选择它以安装该扩展。

选好之后，`Super + Shift + Ctrl + A` 会在一个专用终端窗口中启动默认智能体（或者如果你尚未选择，则会调出选择器）。你也可以用 `omarchy agent prompt "Review this project"` 让它直接进入一项任务。Freebuff 和 DeepSeek Harness 不接受起始提示，因此它们打开时会改为把提示放在你的剪贴板上供你粘贴。以这种方式启动的智能体会以各自不需停下来询问的模式无人值守地运行，所以要做好它们真的会动手做事的准备！MiniMax Code 的交互式会话没有这种模式，因此它会像往常一样请求权限。而且由于智能体拒绝记住对你主目录的信任，从 `$HOME` 启动时改为在 `~/Work` 中启动。

还有一些终端快捷方式：`a` 会在当前终端中内联运行默认智能体，而 `c`、`cx` 和 `cy` 会直接启动 OpenCode、Claude Code 和 Codex（同样处于它们的自动批准模式）。主题更改也会同步到智能体：当你切换 Omarchy 主题时，Claude Code、Pi、OpenCode 和 Hermes（一旦 Omarchy 已安装它）都会随之跟随。

### 你的智能体指令

适用于每个智能体的个人规则放在 `~/.agents/AGENTS.md` 中，紧挨着位于 `~/.agents/skills` 中的共享技能。使用智能体面板中 + 旁边的文档图标打开它，或使用 `omarchy agent instructions --edit`，该命令还会将它链接到每个保留有自有全局文件的框架中：`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`~/.pi/agent/AGENTS.md`、`~/.config/opencode/AGENTS.md`、Copilot 的 `~/.copilot/copilot-instructions.md`，等等。Crush 和 Amp 读取 `~/.config/AGENTS.md` 链接，而 omp、Kimi 和 DeepSeek Harness 直接读取 `~/.agents/AGENTS.md`。选择默认智能体时也会链接它。如果尚不存在共享文件，你已有的指令文件就会成为共享文件；否则它会以 `.bak` 的形式保留在链接旁边。在安装另一个智能体后，运行 `omarchy agent instructions` 以重新链接。

### 智能体面板

顶栏上有一个智能体图标。在你设置智能体之前，其面板提供三种开始方式：登录 Claude、Codex、Grok、Gemini、Muse、Cursor 或 Copilot 订阅，或者在 More 下使用 OpenCode Go、MiniMax、Synthetic 或 Z.ai 的编程套餐；按用量付费使用 Fireworks、OpenCode Zen and Go、OpenRouter，或者在 More 下使用 DeepSeek 或 OpenCode 可登录的任何其他提供商，它们全部都在 OpenCode 中运行；或者运行最适合你计算机的模型（当有能适配的模型时）。你完成的第一个就会成为你的默认智能体，面板中的 + 之后会提供同样的三种方式。之后，面板会把每个订阅都放在同一页上：每个智能体和账户及其套餐，每个 5 小时会话限额和每周限额的计量表以及距离其重置的时间（悬停可查看精确百分比），或者剩余的预付余额，位于一行轮播内容的下方，该行轮换显示你跨所有智能体的使用情况，例如本周的 token 以及你使用最多的模型。在 _Make something cool_ 之下，它提供入门提示，用于新建主题、插件、应用或游戏，并将任务交给你的默认智能体。应用的构建方式与 Omarchy 自身的 Hype、Monologue 和 Omacut 相同，使用 C++ 和 Qt Quick，遵循 omarchy-make-app 智能体技能，而它们所需的编译器和 Qt 组件都已安装。游戏是位于 `~/Games/vibes` 中的单个 three.js 页面，遵循 omarchy-make-game 智能体技能，并且全部从当前主题中的一个 Game Vibes 启动器打开；它们从网络加载 three.js，因此启动时需要连接。Claude Code、Codex、Grok、Kimi、Cursor 及其 Grok Bot 额度、GitHub Copilot、Muse、Gemini（通过 Antigravity）和 Devin 开箱即用地连同其限额一并涵盖，Kimchi 则连同其套餐、预付额度以及支出预算一并涵盖，而 Hermes、Mistral Vibe 和 Qwen Code 会在你使用它们后显示其会话和 token。你通过 pi、omp 或 opencode 使用的提供商套餐和密钥也会显示出来：OpenCode Zen and Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan 和 Synthetic 及其限额；OpenRouter 和 DeepSeek 及其预付余额；Fireworks 及其过去 30 天的支出。你在自己的硬件上运行的编程模型拥有各自独立的行，而且它们的 token 也会计入总数，如[本地模型](#local-models)所述。每个智能体只计一次，按对其收费的一方计算，无论你通过多少个框架来驱动它。

左键单击顶栏图标或按 `Super + Ctrl + X` 打开面板，右键单击以启动你的默认智能体，中键单击以刷新。其背后的使用记录由 `omarchy agent usage update` 每 15 分钟重新生成，而且该面板甚至可以通过一个已同步的文件夹合并来自你其他机器的使用情况。完整设置请参见 `$OMARCHY_PATH/shell/plugins/agents/` 下的 README。

### 多个订阅

如果你为多个 Claude、Codex 或 Grok 套餐付费——例如一个个人 Max 套餐和一个工作套餐——Omarchy 可以让它们全部保持登录状态，并在它们之间切换。使用智能体面板中的 + 添加一个订阅，它会就在那里引导你完成整个过程；或使用 `omarchy agent account add claude Work`（或 `codex`，或 `grok`）。同一个 + 和同一个命令也可登录 Gemini（`gemini`）和 OpenCode（`opencode`），并在 OpenCode 中保存 Fireworks（`fireworks`）或 OpenRouter（`openrouter`）API 密钥；该命令还可登录 Copilot（`copilot`）、Cursor（`cursor`）和 Muse（`muse`）。它们各自只保留单个登录状态。如果 CLI 缺失，它会安装该 CLI。某个提供商的第一个账户通过你的常规浏览器登录，就在 CLI 一直查找的位置。之后的每一个账户都通过隐私窗口登录，这样你浏览器已登录的账户就不会被误选；在其中以你正在添加的账户登录，并先关闭任何已打开的隐私窗口。切勿为此而退出 CLI：退出会撤销已保存的登录状态，该账户将不得不重新添加。

要通过 SSH 将你的订阅登录信息复制到另一台 Omarchy 机器上，请运行 `omarchy agent account copy user@laptop`。当目标机器上未安装接收端时，发送方会提供一个临时接收端，因此较旧的 Omarchy 机器无需更新即可接收账户。已安装的接收端优先。此命令会复制所有 Claude、Codex 和 Grok 订阅；添加提供商名称以选择它们，例如 `omarchy agent account copy laptop claude`。账户名称和命令 ID 与来源一致，包括目标上已经存在的账户。若无关的目标账户名称冲突，它们会获得数字后缀，而设置、技能、插件和对话历史则保留在各自机器上。

目标上已有的凭据会被保留。对于已在那里登录的来源账户，其名称会被同步但不会替换其凭据；其他账户会被添加到它旁边。若要替换匹配账户的已保存凭据，请在目标上退出该账户的会话后，使用 `omarchy agent account copy --replace laptop claude`。全新目标还会获得来源的活动账户和切换首选项；已经长期使用的目标则保留自己的设置。

凭据通过 SSH 传输，并存储在目标机器的私有文件中，因此请只复制到你信任的机器上。这是一次性复制，而不是持续同步。Codex 的刷新 token 可能被另一台机器轮换，从而使复制的登录状态需要续期；为多台机器同时使用而各自单独登录，仍是最可靠的选择。请参阅 [Codex 的账户认证指南](https://developers.openai.com/codex/auth/ci-cd-auth)。

每个提供商只有一个账户处于活动状态，并且每个新会话都会以该账户开始：`cx`、`cy`、普通的 `claude`、`codex` 或 `grok`，通过 `omarchy agent` 启动的任何内容，以及在 `PATH` 上找到该 CLI 的脚本或编辑器。使用 `omarchy agent account use work` 进行切换（并使用 `omarchy agent account use main` 切回来），或者在面板中按某个账户的编号然后按 `Enter`（或单击其星标）。正在运行的 Claude 会话也会切换，从其下一条消息开始：每个 Claude 会话都在 `~/.claude` 中运行，该目录始终保存活动账户的登录状态。由较旧的 Omarchy 在账户自己的文件夹中启动的 Claude 会话，会保留该登录状态直至退出，因此切换操作会点出这些会话的名称，并在它们消失后自行结束。正在运行的 Codex 和 Grok 会话会保持在其启动时所用的账户上。对话历史、设置、技能和插件在各个账户之间共享，因此，在同一文件夹中使用 `claude --continue` 会在新账户上从你离开的地方继续。

拥有多个账户时，面板会并排显示每个账户的限额，正在使用的那个带有一颗实心星。当活动账户超过某个限额的 95% 时，Omarchy 会通知你，点击该通知会切换到余量最多的账户。它永远不会自行切换。使用 `omarchy agent account threshold 90` 来更改阈值。如果每个账户都超过了阈值，你会收到一次通知，并得知哪个账户最先恢复。当活动账户处于阈值 15 个百分点以内（默认值为 80%）时，其限额每三分钟检查一次，而不是每 15 分钟。

`omarchy agent account list` 显示每个账户及其最新限额，`omarchy agent account remove work` 遗忘一个账户，`omarchy agent account rename primary Hey` 重命名一个账户（或者在面板中单击账户名称）。这些命令作用于你的默认智能体的账户；若要访问其他提供商，请先说出它的名字，如 `omarchy agent account use codex side`。你在 `~/.claude` 或 `~/.codex` 中已经拥有的登录是 _Main_ 账户。Codex 的账户留在原处；Claude 的账户在另一个账户处于活动状态时会待在它自己的文件夹中。一个超过大约八小时未使用的账户可能会显示 _Sign-in required_；点击它即可直接在面板中重新登录该账户，或者切换到它并启动一个会话，这会自动刷新登录状态。你使用 `claude mcp add` 添加的 MCP 服务器会覆盖到每一个 Claude 账户，因为它们全部都在 `~/.claude` 中运行；对于 Codex 和 Grok，在添加账户时你已经拥有的服务器会一同进入该账户，但之后添加的服务器只会进入你添加它们的那个账户。Claude Desktop 保留其自己的登录状态，并且使用指向某个 CLI 二进制文件的绝对路径配置的 Codex 或 Grok 工具不会跟随切换。显式的 `CLAUDE_CONFIG_DIR`、`CODEX_HOME` 或 `GROK_HOME` 优先于所选账户。

### 崩溃诊断

Omarchy 会监控 systemd-coredump 以检测进程崩溃。一旦你选定了默认智能体，你的任何发生核心转储的程序都会带来一条 “Process crashed” 通知——点击它，该崩溃就会连同 Omarchy 的 omarchy-diagnose-crash 技能一同交给你的默认智能体，该技能会引导智能体从核心转储中查清事实，并判断该崩溃是否值得向上游报告。你也可以使用 `omarchy agent crash <pid>` 针对 `coredumpctl list` 中的任何 PID 手动运行它。

该监控默认开启。在 _Trigger > Toggle > Crash Capture Off_ 下将其关闭（或使用 `omarchy toggle crash-capture`），通知就会停止；`omarchy agent crash <pid>` 仍可手动使用。

崩溃也可以逐个程序地静默，这正是诊断最终会向你提供的选项。`omarchy crash mute hyprland` 仅停止那个程序的通知，`omarchy crash mute hyprland off` 将其恢复，而单独使用 `omarchy crash mute` 则会列出你已静默的内容。它接受二进制文件的路径正如接受其名称一样，因此 `omarchy crash mute /usr/bin/hyprland` 会做同样的事情。对含有空格的名称加引号，例如 `omarchy crash mute 'Some App'`。其他所有内容仍会通知，而且被静默的程序仍会崩溃——这只是隐藏提醒，并不能修复任何问题。

### 桌面应用

_Install > AI_ 菜单还带有一些图形 AI 应用：Amp Desktop、Antigravity Desktop、ChatGPT 桌面应用、Claude 桌面应用（Anthropic 的 Linux beta 版，具有 Chat、Cowork 和 Claude Code 标签页）、用于与 xAI 的模型聊天的 Grok Bot、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexity 桌面应用和 T3 Code。Grok Bot 是桌面聊天应用。而编程智能体是 `grok` 命令。

Hermes Desktop 是需要了解的一个，因为一台机器上只有一个 Hermes，而且它是该应用的 Hermes：Hermes 只能通过该应用安装，而默认智能体运行的 `hermes` 命令也是该应用的。选择 Hermes 作为默认智能体会安装与 _Install > AI_ 条目相同的东西：该软件包，以及一个位于 `~/.hermes` 之下、由 Hermes 自己的安装程序设置的 Hermes 运行时，第一次需要几分钟的时间。这一运行时就是终端的 `hermes` 命令、默认智能体以及该应用全都使用的那唯一 Hermes，而且它会用 `hermes update` 自我更新，而不是等待 Omarchy 发布新版。安装它还会把 Omarchy 主题作为名为 `omarchy` 的皮肤交给 Hermes，当你切换主题时，每个 Hermes 界面都会跟随；如果不想这样，就在 Hermes 的 Appearance 设置中或使用 `/skin` 选择另一个，而 Omarchy 不干涉那个选择。在 _Remove > AI_ 下删除该应用会先关闭 Hermes（包括网关），随之带走该运行时，并保留你的聊天记录、记忆以及 Hermes 为自己编写的技能，除非你要求不这样做：它会询问那些数据以及你的连接设置是否也应该一并删除，默认为否。

OpenClaw 的桌面体验是其 Control UI，它会以一个配备其自有本地网关的 Web 应用打开。OpenClaw 位于 `~/.openclaw` 并会自我更新：使用 Control UI 的 “Update Gateway” 按钮或运行 `openclaw update`，网关就会重启至新版本。Omarchy 仅选择全新安装所用的起始版本。OpenClaw 也可以是你的默认智能体：使用 `omarchy default agent openclaw` 选择它，会在 `~/.openclaw` 中设置同样的副本，并且智能体会打开连接到其网关的 OpenClaw 终端 UI。在 _Remove > AI_ 下删除 OpenClaw 会连同网关服务和该应用一起删除，然后询问 `~/.openclaw` 是否也应该删除，因为那里除了保存 OpenClaw 本身及其下载的插件运行时之外，还保存着你的聊天记录和凭据；默认为保留它，再次安装 OpenClaw 会重新接上它。

Herdr Desktop 是 [Herdr](https://herdr.dev) 桌面应用：由终端和编程智能体组成的空间、标签页和窗格，即使你关闭窗口，它们也会在它的核心中继续运行。它来自 Herdr 自己的安装程序而非软件包，因此位于 `~/.local/share/herdr-app` 中，当你尚未拥有它时，它把它的核心一并带来，放在 `~/.local/bin/herdr-core`，而且它会自我更新这两者。它与 Omarchy 在 `Super + Ctrl + Return` 上提供的 `herdr` 命令并存而不是替换它，并获得那个命令的直接按键：`Alt + Return` 和 `Alt + Shift + Return` 向下或向右拆分窗格，`Alt + Escape` 关闭窗格，`Ctrl + Alt + Arrow` 在窗格之间移动，`Alt + 1..9` 和 `Alt + Left/Right` 选择标签页，`Alt + Up/Down` 在空间之间移动。`Ctrl + 1..9` 选择空间，`Alt + Shift + Up/Down` 逐个浏览智能体。`Ctrl + Space` 前缀按键仍只用于终端，因为该应用无法为序批量保留普通的 Ctrl 键。Omarchy 将这些按键写入 `~/.config/herdr-app/keys.json`，而 `omarchy-refresh-herdr-app` 会把它们放回去。安装它会选择 Herdr 的 Omarchy 主题，从此它便跟随你的 Omarchy 主题。Herdr 为浅色模式保留一份主题，也为深色模式保留一份，因此在深色与浅色的 Omarchy 主题之间切换之后，要为另一模式再在 Herdr 的主题选择器中选一次 Omarchy。

T3 Code 从 `~/.local/share/t3code` 中的官方 AppImage 版本运行而非从软件包，因此它会自我更新。安装它会询问是使用 Stable 还是 Nightly 频道；之后可以在 T3 Code 的设置中切换。你的话题和设置位于 `~/.t3`，而在 _Remove > AI_ 下删除 T3 Code 时，删除者会把它们一并带走。

### 本地模型

在你自己的机器上为你的编程智能体运行开放模型。你的提示和代码都留在机器上；发送给模型的任何内容都不会离开机器。从这里开始：

```bash
omarchy models use best text
```

这样会为这台机器设置最佳文本模型，也就是你的智能体所使用的那一类。图像、视频和音乐模型也各有其最佳选择：`omarchy models use best image`、`video` 或 `music`。运行 `omarchy models use best` 可查看每一种类型为这台机器所选的模型。

或者在智能体面板中选择 +：在 _Use a local model_ 下，它列出了适配这台机器的每一个编程模型，推荐的排在第一。运行這些模型的 Podman 随 Omarchy 一同提供，配备 NVIDIA 机器上提供 GPU 的 NVIDIA 容器工具包也随之提供；如果其中一样缺失，首次设置会安装它。然后 Omarchy 挑选这台机器的推荐模型，下载它并启动它。预计下载量达数十 GB，且在模型运行期间，机器的大部分内存会被占用：Flash Next 使用其完整的 256K 上下文时约占 100 GiB。如果其他模型占去了所需的内存，它会被设置成已停止状态，等你停止一个模型后就可启动。模型在注销时停止；当你需要把内存用于其他事情时，请自己停止它。

`omarchy models list` 显示可选项，并说明某些模型为何不适配。要设置另一个模型，请运行 `omarchy models use <recipe>`。如今，`qwen3.8-flash-next-gufo` 和 `qwen3.8-27b-gufo` 适用于 128 GB 的 Strix Halo 机器；27B 约占用 40 GiB，因此会留出空间给其他工作。在一台 64 GB、配备 Intel Arc B390 的笔记本电脑上，`qwen3.6-35b-a3b-llamacpp` 约在 30 GiB 中运行。新的配方和推荐会通过软件包随着 `omarchy update` 到来。

你添加的编程模型会在智能体面板中获得自己的一行，位于订阅旁边：播放按钮启动它，暂停按钮停止它并释放其内存，Tailscale 标记在它运行期间将其与 tailnet 上的其他机器共享，终端按钮则在该模型上打开你的智能体。它的这一行会随着进行显示下载、加载或停止，且当可用内存不足以启动时会说明此事，或当它因错误停下来时链接到其日志。内存能够同时装下它们时，可同时运行多个。在选中的一行上按 Delete 即可从这台机器上移除该模型，连下载一并删除；+ 可以再次设置它。从终端设置的编程模型会一直待在 + 下直到你添加它，你已配对的机器（`omarchy models pair <host>`）所运行的模型亦然。

每个你设置的编程模型还在应用启动器中获得自己的条目，条目位于模型名称之下并带有其制造者的标志，就像登录 Claude、Codex 或 Grok 时会添加条目一样。它会在该模型上打开你的智能体，而且如果模型未运行，它会先启动模型：终端会显示它正在加载，并在就绪后将控制交给你智能体。移除模型会移除其条目。

并非每个模型都是用于编程。图像、视频和音乐模型改为在 Fantasi 中打开，Fantasi 是 Omarchy 用于利用在该机器上运行的模型制作图片、视频和音乐的应用，而它们可以在那里或使用 `omarchy models` 进行管理。

模型会严格按照其设置时的样子持续运行，因此 Omarchy 的更新永远不会在你的智能体下方重启模型。当 Omarchy 有更新的运行时或你要更新的新权重时，它的那一行会显示更新按钮：按下它，模型就会在后台重新设置，仅下载发生更改的部分，并在新版本上重启。曾被停止的模型仍会保持停止。`omarchy models update` 会在终端里对每个模型做同样的事情。

从命令行来看，`omarchy models start <recipe>` 和 `omarchy models stop <recipe>` 作用相同，`omarchy models status` 显示每个模型，而 `omarchy agent --local-model <recipe>` 无论你的默认智能体是什么，都会在 pi 中打开该模型。若要让你的本地模型成为智能体热键、Quake 控制台以及 _Make something_ 所打开的内容，请运行 `omarchy default agent local` 或在智能体面板中为一个正在运行的模型加星标。pi 也会其自有模型选择器中列出你设置的每一个模型，以及已配对的机器上的模型，因此普通的 `pi` 也能访问它们。任何兼容 OpenAI 的客户端也可以连接：`status` 显示每个模型的地址（第一个是 `http://127.0.0.1:11435/v1`），模型就是该配方的名称，而密钥位于 `~/.config/omarchy/agent-local/key` 中。

`omarchy models remove <recipe>` 删除一个模型，以及没有其他模型使用的那些下载内容。

第三方运行时会被标有其发布者的标签。Omarchy 在没有网络访问的条件下运行每一个模型。

### 本地 LLM

Omarchy 推荐两种运行本地 LLM 模型的方式：LM Studio 和 Ollama。LM Studio 提供了一个 GUI 界面，用于查找开放权重模型、安装它们并运行它们。这是轻松上手的好方法。Ollama 提供了一个 CLI 以类似方式做到这一点。但如果你是本地模型的新手，我会从 LM Studio 开始。你可以在 Omarchy 菜单的 _Install > AI_ 下安裝其中任一。

### Omarchy 技能

智能体技能帮助 AI 以特定的方式使用特定的工具，而 Omarchy 自带了七个这样的技能。omarchy 技能涵盖定制系统，比如调整你的 Hyprland 配置或调整顶栏。omarchy-make-theme、omarchy-make-plugin、omarchy-make-app 和 omarchy-make-game 涵盖制作新事物，omarchy-contribute 涵盖报告错误或向上游发出修复，而 omarchy-diagnose-crash 处理崩溃的核心转储。它们被符号链接到 Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` 和每个 `~/.hermes/profiles/*/skills`）以及通用 `~/.agents/skills` 位置的技能目录中，因此大多数框架会自动拾取它们。一个同名的自有技能文件夹会优先。

但你应该把这些技能看作是实验性的。不同的模型对它的使用效果也各不相同。最好先以 plan 模式运行，这样你就能知道智能体想改什么。然后准备回滚更改，甚至调用 `omarchy reinstall configs`，如果智能体把一切弄得一团糟的话。
