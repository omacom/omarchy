### 安装和更新智能体

除了 Hermes，这些智能体使用 mise 的懒安装：首次启动时安装 CLI，后续启动则复用它。mise 还至多每四小时检查一次已安装的智能体是否有新版本，就在它启动之前，或者在 shell 提示符下于后台检查。如果更新失败或者你离线，就会运行已安装的版本。`omarchy update` 会在更新 Omarchy 其余部分的同时更新已安装的智能体，而 `mup` 仅更新由 mise 管理的工具。

智能体自带的更新程序，例如 `claude update`、`codex update`，或者应用中的更新按钮，不会更新由 mise 管理的安装。`codex update` 会失败，而 `claude update` 可能报告成功，却安装了一个 mise 不跟踪的单独副本。如果你更愿意使用智能体原生的安装程序和更新程序，请将其添加到 `disable_tools`；请参阅 [预装的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

要在需要之前安装所有已配置的懒加载工具，请运行 `mise install --include-lazy`。这包括 Omarchy 的其他默认 CLI 工具以及这些智能体。有关安装单个工具或使用你自己的安装，请参阅 [预装的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

`grok` 通过 mise 的第一方 `grok` 包安装，方式与 `claude` 和 `codex` 相同。运行 `grok`，或者在 _Setup > Defaults > Agent_ 下选择它。跳过 x.ai 上的 `curl | bash` 安装程序。那个路径会在 `~/.grok/bin` 中放入第二个副本，将其前置到 `PATH` 上，并覆盖 Omarchy 的包装器。

`dsh` 会在 `127.0.0.1:3080` 打开其浏览器 UI，并将启动目录作为其默认工作区。其浏览器 UI 不接受启动提示词，因此 `omarchy agent prompt` 打开它时会将提示词放在你的剪贴板上供你粘贴。Omarchy 使用 DeepSeek 的无需批准权限预设来启动它。当你使用 DeepSeek 的官方模型 API 时，DeepSeek Harness 会将 session 日志上传给 DeepSeek；在其浏览器 UI 的 _Settings > General > Upload Session Log_ 下关闭这一功能。你向它发送的反馈也会随 session 一起上传，除非你使用 `DSH_TELEMETRY_MODE=DISABLED` 启动它。

### 默认智能体

使用 `omarchy default agent <name>` 或在 Omarchy 菜单（`Super + Space`）的 _Setup > Defaults > Agent_ 下，选择你的默认智能体。如果该智能体尚未安装，选择它会先将其安装。全新的 Omarchy 会通过一次性通知邀请你做出这一选择。

选择 Claude 还会尝试为 Chromium、Chrome、Brave、Brave Origin 和 Edge 设置其浏览器扩展。该扩展设置适用于所有用户，并且可能要求你输入系统密码；取消或扩展安装失败仍然会选择并启动 Claude。重启你的浏览器，如果出现提示则启用该扩展，并登录 Claude 以完成连接。在 Claude 中运行 `/chrome` 来检查连接。Firefox 和 Zen 不支持此扩展。如果在添加此设置之前 Claude 已经是你的默认项，请再次选择它以安装该扩展。

一旦你做出了选择，`Super + Shift + Ctrl + A` 会在一个专用终端窗口中启动默认智能体（或者，如果你尚未选择，则调出选择器）。你也可以使用 `omarchy agent prompt "Review this project"` 让它直接开始处理一项任务。Freebuff 和 DeepSeek Harness 不接受启动提示词，因此它们打开时会将提示词放在你的剪贴板上供你粘贴，而不是直接接收。以这种方式启动的智能体会以各自的“不要停下来询问”模式无人值守地运行，所以要做好它们真的会动手做事的准备！MiniMax Code 的交互式会话没有这种模式，因此它会像往常一样请求权限。而且，由于智能体拒绝记住对你的主目录的信任，从 `$HOME` 启动时会在 `~/Work` 中开始。

还有终端快捷方式：`a` 会在当前终端中内联运行默认智能体，而 `c`、`cx` 和 `cy` 则直接启动 OpenCode、Claude Code 和 Codex（同样处于其自动批准模式）。主题更改也会同步到这些智能体：当你切换 Omarchy 主题时，Claude Code、Pi、OpenCode 和 Hermes（一旦 Omarchy 安装了它）都会随之跟随。

### 智能体面板

顶栏有一个智能体图标。在你设置智能体之前，其面板会引导你登录 Claude、Codex 或 Grok，而第一个登录的会成为你的默认智能体。之后，该面板将每个订阅都放在同一个页面上：每个智能体和帐户及其套餐、每个 5 小时 session 和每周限额的计量条以及距离重置的时间（悬停查看确切百分比），或者剩余的预付余额，全部位于一行轮播内容的下方，该行会轮流显示你在所有这些智能体上的使用情况，例如本周的 tokens 和你最常用的模型。在 _Make something_ 下，它提供用于新建主题、插件或应用的入门提示词，并将任务交给你的默认智能体。应用的构建方式与 Omarchy 自己的 Hype、Monologue 和 Omacut 相同，使用 C++ 和 Qt Quick，遵循 omarchy-app 智能体技能，并且它们所需的编译器和 Qt 组件都已安装。Claude Code、Codex、Grok、Kimi、Cursor 及其 Grok Bot 额度、GitHub Copilot、Muse、Antigravity、Kimchi 和 Devin 开箱即用地涵盖了它们的限额，而 Hermes、Mistral Vibe 和 Qwen Code 则会在你使用过它们后显示其会话和 tokens。你通过 pi、omp 或 opencode 使用的提供商套餐和密钥也会显示：OpenCode Zen 和 Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan 以及 Synthetic，并带有它们的限额；Fireworks、OpenRouter 和 DeepSeek，并带有它们的预付余额；以及你在自己的硬件上运行的，位于 Local models 下的模型。每个智能体只计数一次，归到向你收费的一方名下，无论你通过多少个 harness 来驱动它。

左键单击顶栏图标打开面板，右键单击启动你的默认智能体。它背后的使用记录每 15 分钟由 `omarchy agent usage-update` 重新生成一次，并且该面板甚至可以通过一个同步文件夹来合并来自你其他机器的使用情况。有关完整设置，请参阅 `$OMARCHY_PATH/shell/plugins/agents/` 下的 README。

### 多个订阅

如果你付费购买了不止一个 Claude、Codex 或 Grok 套餐——比如一个个人 Max 和一个工作用的——Omarchy 可以让它们全部保持登录状态，并在它们之间切换。使用智能体面板中的 + 添加一个订阅，它会直接在那里引导你完成，或者使用 `omarchy agent account add claude Work`（或者 `codex`，或者 `grok`）。如果 CLI 缺失，它会安装它。某个提供商的第一个帐户通过你的普通浏览器登录，就在 CLI 一直查找的位置。之后的每一个帐户都通过隐私窗口登录，因此你的浏览器已经登录的帐户不会被误选；在那里登录你要添加的帐户，并先关闭你已打开的任何隐私窗口。切勿为此退出 CLI：退出登录会吊销已保存的登录状态，并且该帐户将不得不重新添加。

要通过 SSH 将你的订阅登录信息复制到另一台 Omarchy 机器，请运行 `omarchy agent account copy user@laptop`。当目标机器未安装接收器时，发送方会提供一个临时接收器，因此较旧的 Omarchy 机器无需更新即可接收帐户。已安装的接收器优先。此命令复制所有 Claude、Codex 和 Grok 订阅；添加提供商名称来选择它们，如 `omarchy agent account copy laptop claude` 中所示。帐户名称和命令 ID 与源机器一致，包括目标机器上已存在的帐户。如果无关的目标帐户名称冲突，它们会收到一个数字后缀，并且设置、技能、插件和对话历史都保留在各自机器本地。

已有的目标凭据会保留。如果源帐户已在那里登录，其名称会被同步，但不会替换其凭据；其他帐户则会被添加到它旁边。要替换匹配帐户的已保存凭据，请在目标机器上退出该帐户的会话后，使用 `omarchy agent account copy --replace laptop claude`。全新目标机器还会获得源机器的活动帐户和切换偏好；已有数据的目标机器则保留自己的。

凭据通过 SSH 传输，并存储在目标机器上的私有文件中，因此仅复制到你信任的机器。这是一次性复制，而不是持续同步。Codex 刷新 tokens 可能被另一台机器轮换，导致复制的登录状态需要续订；对于同时在多台机器上使用，单独登录仍然是最可靠的选择。请参阅 [Codex 的帐户身份验证指南](https://developers.openai.com/codex/auth/ci-cd-auth)。

每个提供商有一个活动帐户，并且每个新会话都会以该帐户开始：`cx`、`cy`、普通的 `claude`、`codex` 或 `grok`、通过 `omarchy agent` 启动的任何东西，以及在 `PATH` 上找到 CLI 的脚本或编辑器。使用 `omarchy agent account use work` 切换（并使用 `omarchy agent account use main` 切回），或者在面板中按下某个帐户的编号然后按 `Enter`（或单击其 Use 按钮）。已在运行的会话会继续使用其启动时的帐户。对话历史、设置、技能和插件在所有帐户之间共享，因此在同一文件夹中执行 `claude --continue` 会在新帐户上从你离开的地方继续。

当有多个帐户时，面板会并排显示每个帐户的限额，并标记活动帐户。默认情况下，当活动帐户超过某个限额的 95% 时，Omarchy 会通知你，单击该通知会切换到余量最多的帐户。将鼠标悬停在面板中的某行帐户上，单击 Use 旁边出现的 Autoswitch（或按 `m`），或者运行 `omarchy agent account mode auto`，让它自行切换；它打开时，Autoswitch 会取代 Use 的位置，再次单击它则恢复为通知。添加一个数字来更改阈值，如 `omarchy agent account mode auto 90` 中所示。如果每个帐户都超过阈值，你会收到一次通知，同时得知哪个帐户最先释放额度。当活动帐户距离其阈值在 15 个百分点以内（默认情况下为 80%）时，其限额会每三分钟检查一次，而不是每 15 分钟检查一次。

`omarchy agent account list` 显示每个帐户及其最新限额，`omarchy agent account remove work` 忘记一个帐户，而 `omarchy agent account rename primary Hey` 重命名一个帐户（或单击面板中的帐户名称）。这些命令适用于你的默认智能体的帐户；要访问另一个提供商，请先命名它，如 `omarchy agent account use codex side` 中所示。你早先在 `~/.claude` 或 `~/.codex` 中已有的登录是 _Main_ 帐户，并保持在原处。一个超过大约八小时未使用的帐户可能会显示 _Sign-in required_；单击它可以直接在面板中重新登录该帐户，或者在其中启动一个会话，它会自行刷新登录状态。当添加帐户时你已有的 MCP 服务器会随之一起过去，但你后来使用 `claude mcp add` 添加的那些只会到达你添加它们的帐户。Claude Desktop 和使用 CLI 二进制文件的绝对路径配置的工具不会跟随切换。显式指定的 `CLAUDE_CONFIG_DIR`、`CODEX_HOME` 或 `GROK_HOME` 优先于所选帐户。

### 崩溃诊断

Omarchy 监视 systemd-coredump 以发现进程崩溃。当某物发生段错误时，你会收到一个 “Process crashed” 通知——单击它，崩溃就会连同 Omarchy 的 diagnose-crash 技能一起交给你的默认智能体，该技能会引导智能体从核心转储中查明事实，并决定该崩溃是否值得向上游报告。你也可以使用 `omarchy agent crash <pid>`，针对 `coredumpctl list` 中的任何 PID 手动运行它。

默认开启监视。在 _Trigger > Toggle > Crash Capture_ 下（或使用 `omarchy toggle crash-capture`）关闭它，通知就会停止；`omarchy agent crash <pid>` 仍然可以手动使用。

也可以一次静默一个程序的崩溃，这正是诊断在最后向你提供的选项。`omarchy crash mute hyprland` 仅停止该程序的通知，`omarchy crash mute hyprland off` 将其恢复，而单独使用 `omarchy crash mute` 则列出你已静默的内容。它接受二进制文件的路径就像接受其名称一样方便，因此 `omarchy crash mute /usr/bin/hyprland` 做同样的事情。对带有空格的名称加引号，如 `omarchy crash mute 'Some App'` 中所示。其他一切仍会通知，而被静默的程序仍会崩溃——这隐藏了提醒，并没有修复任何东西。

### 桌面应用

_Install > AI_ 菜单还包含一些图形化 AI 应用：ChatGPT 桌面应用、Claude 桌面应用（Anthropic 的 Linux beta 版，带有 Chat、Cowork 和 Claude Code 选项卡）、用于与 xAI 的模型聊天的 Grok Bot、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexity 桌面应用和 T3 Code。Grok Bot 是桌面聊天应用。编码智能体是 `grok` 命令。

Hermes Desktop 是需要了解的那个，因为一台机器只有一个 Hermes，并且它属于该应用：Hermes 只能通过该应用安装，而默认智能体运行的 `hermes` 命令正是该应用的。选择 Hermes 作为默认智能体会安装 _Install > AI_ 条目安装的相同内容：该软件包，以及一个由 Hermes 自己的安装程序在 `~/.hermes` 下设置的 Hermes 运行时，首次使用时需要几分钟。该运行时是终端 `hermes` 命令、默认智能体和应用都使用的那唯一一个 Hermes，并且它使用 `hermes update` 自行更新，而不是等待 Omarchy 发布。安装它还会将 Omarchy 主题作为名为 `omarchy` 的皮肤交给 Hermes，每个 Hermes 界面都会随着你切换主题而跟随它；如果你不想这样，请在 Hermes 的 Appearance 设置下或使用 `/skin` 选择另一个，而 Omarchy 会让那个选择保持不变。在 _Remove > AI_ 下删除该应用会先关闭 Hermes，包括网关，并随之带走该运行时，并保留你的聊天、记忆以及 Hermes 为自己编写的技能，除非你另行告诉它：它会询问，默认为否，是否也应删除那些数据和你的连接设置。

OpenClaw 的桌面体验是其 Control UI，它作为一个 web 应用打开，由其自己的本地网关提供后端支持。OpenClaw 位于 `~/.openclaw` 并自行更新：使用 Control UI 的 “Update Gateway” 按钮或运行 `openclaw update`，网关就会在新版本上重启。Omarchy 仅选择全新安装起始的发布版本。在 _Remove > AI_ 下删除 OpenClaw 会随之带走网关服务和应用，然后询问是否也应删除 `~/.openclaw`，因为那里保存了你的聊天和凭据，以及 OpenClaw 本身及其下载的插件运行时；默认保留它，再次安装 OpenClaw 会将其重新拾起。

Herdr Desktop 是 [Herdr](https://herdr.dev) 桌面应用：由 spaces、tabs 和 panes 组成的终端和编码智能体，当你关闭窗口时，它们在其核心中继续运行。它来自 Herdr 自己的安装程序而不是一个软件包，因此它位于 `~/.local/share/herdr-app`，当你还没有时，它会在 `~/.local/bin/herdr-core` 中随身带来其核心，并自行更新两者。它位于 Omarchy 在 `Super + Ctrl + Return` 上提供的 `herdr` 命令旁边，而不是替换它。安装它会选择 Herdr 的 Omarchy 主题，从那时起它会跟随你的 Omarchy 主题。Herdr 为浅色模式保留一个主题，为深色模式保留一个主题，因此在深色和浅色 Omarchy 主题之间切换后，在 Herdr 的主题选择器中再选择一次 Omarchy 以用于另一种模式。

T3 Code 从位于 `~/.local/share/t3code` 中的其官方 AppImage 版本运行，而不是从软件包运行，因此它自行更新。安装它时会询问是启动 Stable 还是 Nightly 频道；之后可以在 T3 Code 的设置中切换。你的线程和设置位于 `~/.t3`，而在 _Remove > AI_ 下删除 T3 Code 会随之将它们带走。

### 本地模型

在你自己的机器上为你的编码智能体运行一个开放模型。你的提示词和代码保留在机器上；发送给模型的任何东西都不会离开它。从以下命令开始：

```bash
omarchy agent local use best
```

或者，在顶栏的智能体面板中，选择 + 然后选择 Local AI，当有模型适合这台机器时它会出现。第一次使用时，这会安装 Podman，它运行这些模型，而在 NVIDIA 机器上，还会安装 NVIDIA 的容器工具包，它为它们提供 GPU。然后 Omarchy 为这台机器挑选推荐模型，下载它，并启动它。预计下载量达数十 GB，并且模型运行时机器的大部分内存都会被占用：Flash Next 在其完整的 256K 上下文下使用约 100 GiB。如果其他模型占用了它所需的内存，它会被设置为已停止状态，准备在你停止一个后启动。该模型在注销时停止；当你需要内存用于其他事情时，请自行停止它。

`omarchy agent local list` 显示选项并解释为什么某些不适合。要设置另一个，请运行 `omarchy agent local use <recipe>`。如今，`qwen3.8-flash-next-gufo` 和 `qwen3.8-27b-gufo` 可用于 128 GB Strix Halo 机器；27B 占用约 40 GiB，因此它为其他工作留出了空间。新的 recipe 和推荐随 `omarchy update` 通过该软件包到达。

你设置的每个模型在智能体面板中都有自己的行，紧挨着你的订阅：play 启动它，pause 停止它并释放其内存，terminal 按钮则在其上打开你的智能体。当它们在内存中同时适合时，几个可以同时运行；如果一个不适合，Omarchy 会说明要停止哪个正在运行的模型。拖动行来重新排序它们，并在一个选定的行上按 Delete 删除一个模型及其下载。

从命令行，`omarchy agent local start <recipe>` 和 `omarchy agent local stop <recipe>` 做相同的事情，`omarchy agent local status` 显示每个模型，而 `omarchy agent --local` 在你上次启动的模型上打开你的默认智能体（如果你的默认智能体不能使用本地模型，则打开 pi）。任何与 OpenAI 兼容的客户端也可以连接：`status` 显示每个模型的地址（第一个是 `http://127.0.0.1:11435/v1`），recipe 名称即是模型，而密钥位于 `~/.config/omarchy/agent-local/key`。

`omarchy agent local remove <recipe>` 删除一个模型，以及没有其他模型使用的下载。

第三方运行时标注了它们的发布者。Omarchy 运行每个模型时都没有网络访问。

### 本地 LLMs

Omarchy 推荐两种运行本地 LLM 模型的方式：LM Studio 和 Ollama。LM Studio 提供一个 GUI 界面，用于查找开放权重模型、安装它们并运行它们。这是轻松上手的好方法。Ollama 提供一个 CLI，以类似方式做到这一点。但如果你是本地模型的新手，我会从 LM Studio 开始。你可以在 Omarchy 菜单的 _Install > AI_ 下安装任意一个。

### Omarchy Skill

智能体技能帮助 AI 以特定方式使用特定工具，而 Omarchy 附带一个用于定制系统的默认技能。就像调整你的 Hyprland 配置、调整顶栏，甚至从头创建一个新主题。它被符号链接到 Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` 和每个 `~/.hermes/profiles/*/skills`）以及通用的 `~/.agents/skills` 位置的技能目录中，因此大多数 harness 会自动拾取它。

但你应将此技能视为实验性的。不同模型将以不同效果使用它。最好先在计划模式下运行，以便你了解该智能体想要更改什么。然后准备好回滚更改，甚至调用 `omarchy reinstall configs`，如果该智能体把一切搞得一团糟。
