### 安装和更新智能体

除 Hermes 和 OpenClaw 外，这些智能体都使用 mise 的延迟安装：首次启动时安装 CLI，之后的启动会复用它。mise 还会至多每四小时检查一次已安装智能体是否有新版本，就在它启动之前检查，或在 shell 提示符时在后台检查。如果该更新失败或你处于离线状态，则运行已安装的版本。`omarchy update` 会随 Omarchy 的其余部分一起更新已安装的智能体，而 `mup` 只更新由 mise 管理的工具。

智能体自身的更新器，例如 `claude update`、`codex update`，或应用中的更新按钮，不会更新由 mise 管理的安装。`codex update` 会失败，而 `claude update` 可能报告成功，却安装了一份 mise 不跟踪的单独副本。如果你宁愿使用智能体原生的安装器和更新器，把它加入 `disable_tools`；参见 [预装的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

要在需要之前安装所有已配置的延迟工具，运行 `mise install --include-lazy`。这包括 Omarchy 的其他默认 CLI 工具以及这些智能体。有关安装单个工具或使用你自己的安装，参见 [预装的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

`grok` 通过 mise 的第一方 `grok` 包安装，与 `claude` 和 `codex` 的方式相同。运行 `grok`，或在智能体面板中给它加星。跳过 x.ai 上的 `curl | bash` 安装器。那个路径会在 `~/.grok/bin` 中放入第二份副本，把它前置到 `PATH` 上，并覆盖 Omarchy 的包装器。

`dsh` 在 `127.0.0.1:3080` 上打开其浏览器 UI，并以启动目录作为其默认工作区。它的浏览器 UI 不接受起始提示词，所以 `omarchy agent prompt` 打开它时，会把提示词放在你的剪贴板上供你粘贴。Omarchy 以 DeepSeek 的无批准权限预设启动它。当你使用 DeepSeek 的官方模型 API 时，DeepSeek Harness 会把会话日志上传到 DeepSeek；在其浏览器 UI 的 _设置 > 通用 > 上传会话日志_ 下关闭它。你发送给它的反馈也会随会话一起上传，除非你用 `DSH_TELEMETRY_MODE=DISABLED` 启动它。

### 默认智能体

用智能体面板中某个智能体旁边的星标来挑选你的默认智能体，默认项上的星标是填充的，或者用 `omarchy default agent <name>`，它也接受任何在那里没有一行的 harness。如果该智能体尚未安装，挑选它会先安装它，并且它还会在应用启动器中获得自己的一个启动器，紧挨着 Agent。一个全新的 Omarchy 会用一条一次性通知邀请你设置一个，通知会打开智能体面板。

选择 Claude 还会尝试为 Chromium、Chrome、Brave、Brave Origin 和 Edge 设置其浏览器扩展。该扩展设置适用于所有用户，并且可能要求你的系统密码；取消或扩展安装失败仍然会选择并启动 Claude。重启你的浏览器，如有提示则启用该扩展，然后登录 Claude 以完成连接。在 Claude 中运行 `/chrome` 来检查连接。Firefox 和 Zen 不支持这个扩展。如果在加入这个设置之前 Claude 已经是你的默认项，再次选择它以安装该扩展。

一旦你完成了选择，`Super + Shift + Ctrl + A` 会在一个专用终端窗口中启动默认智能体（或者，如果你尚未选择，则调出选择器）。你也可以用 `omarchy agent prompt "Review this project"` 让它直接进入一项任务。Freebuff 和 DeepSeek Harness 不接受起始提示词，所以它们打开时改为把提示词放在你的剪贴板上供你粘贴。以这种方式启动的智能体，会在各自的不停下来询问的模式下无人值守地运行，所以做好准备，它们真的会动手做事！MiniMax Code 的交互式会话没有这种模式，所以它照常请求权限。而且，由于智能体拒绝为你的主目录记住信任，从 `$HOME` 启动的会话改为在 `~/Work` 中开始。

还有终端快捷方式：`a` 在当前终端中内联运行默认智能体，而 `c`、`cx` 和 `cy` 直接启动 OpenCode、Claude Code 和 Codex（同样是在它们的自动批准模式下）。主题更改也会同步到智能体：当你切换 Omarchy 主题时，Claude Code、Pi、OpenCode 和 Hermes（一旦 Omarchy 已安装它）都会跟随。

### 你的智能体指令

给每个智能体的个人规则放在 `~/.agents/AGENTS.md`，紧挨着 `~/.agents/skills` 中的共享技能。用智能体面板中 + 旁边的文档图标打开它，或者用 `omarchy agent instructions --edit`，它还会把它链接到每个保留其自有全局文件的 harness 中：`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`~/.pi/agent/AGENTS.md`、`~/.config/opencode/AGENTS.md`、Copilot 的 `~/.copilot/copilot-instructions.md`，等等。Crush 和 Amp 读取 `~/.config/AGENTS.md` 链接，而 omp、Kimi 和 DeepSeek Harness 直接读取 `~/.agents/AGENTS.md`。挑选一个默认智能体也会链接它。如果你已有的指令文件在尚无共享文件时，会成为共享的那份；否则它会作为 `.bak` 保留在链接旁边。安装另一个智能体后，运行 `omarchy agent instructions` 重新链接。

### 智能体面板

顶栏有一个智能体图标。在你设置智能体之前，它的面板提供三种开始方式：登录一个 Claude、Codex、Grok、Gemini、Muse、Cursor 或 Copilot 订阅，或者在更多项下选一个 OpenCode Go、MiniMax、Synthetic 或 Z.ai 编码套餐；按量付费用 Fireworks、OpenCode Zen 和 Go、OpenRouter，或者在更多项下用 DeepSeek 或任何其他 OpenCode 可登录的提供商，它们全都在 OpenCode 中运行；或者，当有一款适合你的计算机时，运行最适合它的模型。你完成的第一个会成为你的默认智能体，而面板中的 +，或 Omarchy 菜单中的 _Agent > Add_，之后提供同样的三种方式。在那之后，该面板把每个订阅都放在同一页上：每个智能体和账户及其套餐，每个智能体的 5 小时会话限额和每周限额各有一条计量条，并显示距离重置的时间（悬停可查看确切百分比），或者剩余的预付余额，在它们上方还有一行轮播显示你全部的使用情况，例如本周的 token 数和你最常用的模型。在 _Make something cool_ 下，它提供用于新主题、插件、应用或游戏的起始提示词，把任务交给你的默认智能体。应用的构建方式与 Omarchy 自家的 Hype、Monologue 和 Omacut 相同，用 C++ 和 Qt Quick，遵循 omarchy-make-app 智能体技能，而且它们所需的编译器和 Qt 组件都已随之安装。游戏是 `~/Games/vibes` 中单个的 three.js 页面，遵循 omarchy-make-game 智能体技能，并且全都从当前主题中的一个 Game Vibes 启动器打开；它们从网络加载 three.js，所以启动时需要连接。Claude Code、Codex、Grok、Kimi、Cursor 及其 Grok Bot 额度、GitHub Copilot、Muse、Gemini（通过 Antigravity）和 Devin 开箱即用地被覆盖，并带有它们的限额，Kimchi 带有其套餐、预付额度和支出预算，而 Hermes、Mistral Vibe 和 Qwen Code 会在你使用过它们后显示其会话和 token。你通过 pi、omp 或 opencode 使用的提供商套餐和密钥也会显示出来：OpenCode Zen 和 Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan 和 Synthetic，带有它们的限额；OpenRouter 和 DeepSeek，带有它们的预付余额；Fireworks，带有其过去 30 天的支出。你在自己的硬件上运行的模型的 token 也计入总计；模型本身有其自己的面板，在 [本地模型](#local-models) 下描述。每个智能体只计一次，按向它计费的一方计，无论你通过多少个 harness 驱动它。

左键单击栏图标或按 `Super + Ctrl + X` 打开面板，右键单击启动你的默认智能体，中键单击刷新。它背后的使用记录每 15 分钟由 `omarchy agent usage update` 重新生成，并且该面板甚至可以通过一个同步文件夹合并来自你其他机器的使用情况。有关完整设置，参见 `$OMARCHY_PATH/shell/plugins/agents/` 下的 README。

### 多个订阅

如果你付费购买了多个 Claude、Codex 或 Grok 套餐——比如一个个人的 Max 和一个工作的——Omarchy 可以让它们全部保持登录状态，并在它们之间切换。用智能体面板中的 + 添加一个订阅，它会在那里引导你完成，或者用 `omarchy agent account add claude Work`（或 `codex`，或 `grok`）。同一个 + 和命令可登录 Gemini（`gemini`）和 OpenCode（`opencode`），并在 OpenCode 中保存一个 Fireworks（`fireworks`）或 OpenRouter（`openrouter`）API 密钥；该命令还可登录 Copilot（`copilot`）、Cursor（`cursor`）和 Muse（`muse`）。那些各自只保留一个登录。它会在 CLI 缺失时安装它。某个提供商的第一个账户通过你平常的浏览器登录，就在该 CLI 一直查找的地方。此后的每一个都通过一个隐私窗口登录，所以你浏览器已经登录的账户不会被误拾取；在那里以你要添加的账户登录，并先关闭你已打开的任何隐私窗口。切勿为此注销 CLI：注销会撤销已保存的登录，而那个账户将不得不重新添加。

要通过 SSH 把你的订阅登录复制到另一台 Omarchy 机器上，运行 `omarchy agent account copy user@laptop`。当目标机器未安装接收方时，发送方会提供一个临时接收方，所以较旧的 Omarchy 机器无需更新就能接收账户。已安装的接收方优先。这会复制所有 Claude、Codex 和 Grok 订阅；添加提供商名称来选择它们，如 `omarchy agent account copy laptop claude`。账户名称和命令 ID 与源一致，包括目标上已经存在的账户。无关的目标账户如果名称冲突，会收到一个数字后缀，而且设置、技能、插件和对话历史都保留在每台机器本地。

已有的目标凭据会被保留。一个已经在那里登录的源账户会同步其名称，但不替换其凭据；其他账户会被添加在它旁边。要为匹配的账户替换已保存的凭据，在退出目标上那个账户的会话后，使用 `omarchy agent account copy --replace laptop claude`。一个全新的目标还会获得源的活动账户和切换偏好；一个已确立的目标会保留它自己的。

凭据通过 SSH 传输，并存储在目标上的私有文件中，所以只复制到你信任的机器上。这是一次性复制，不是持续同步。Codex 刷新 token 可能被另一台机器轮换，使复制的登录需要续期；在多台机器上同时使用时，单独登录仍是最可靠的选择。参见 [Codex 的账户身份验证指南](https://developers.openai.com/codex/auth/ci-cd-auth)。

每个提供商有一个活动账户，每个新会话都以它开始：`cx`、`cy`，平常的 `claude`、`codex` 或 `grok`，通过 `omarchy agent` 启动的任何东西，以及在 `PATH` 上找到该 CLI 的脚本或编辑器。用 `omarchy agent account use work` 切换（并用 `omarchy agent account use main` 切回），或者在面板中按一个账户的编号然后按 `Enter`（或单击它的星标）。正在运行的 Claude 会话也会切换，从它们下一条消息起：每个 Claude 会话都在 `~/.claude` 中运行，它始终持有活动账户的登录。一个由较旧 Omarchy 在某个账户自己的文件夹中启动的 Claude 会话，在退出之前都会持有那个登录，所以切换时会点名那些会话，并在它们消失后自行完成。正在运行的 Codex 和 Grok 会话会停留在它们开始时用的账户上。对话历史、设置、技能和插件在账户之间共享，所以在同一个文件夹中 `claude --continue` 会在新账户上从你离开的地方继续。

有多个账户时，面板并排显示每个账户的限额，正在使用的那个上面有一颗填充的星标。当活动账户超过某个限额的 95% 时，Omarchy 会通知你，单击该通知会切换到余量最多的账户。它从不自行切换。用 `omarchy agent account threshold 90` 更改阈值。如果每个账户都超过了阈值，你会听到一次，并得知哪个账户最先释放出来。当活动账户距离其阈值在 15 个点以内时（默认下为 80%），它的限额每三分钟检查一次，而不是每 15 分钟。

`omarchy agent account list` 显示每个账户及其最新的限额，`omarchy agent account remove work` 忘掉一个，`omarchy agent account rename primary Hey` 重命名一个（或在面板中单击一个账户的名称）。这些命令作用于你的默认智能体的账户；要到达另一个提供商，先点名它，如 `omarchy agent account use codex side`。你已经在 `~/.claude` 或 `~/.codex` 中拥有的登录是 _Main_ 账户。Codex 的留在它所在的地方；Claude 的在另一个账户活动时，等待在它自己的文件夹中。一个超过约八小时未使用的账户可能显示 _需要登录_；单击它可直接在面板中重新登录那个账户，或者切换到它并启动一个会话，它会自行刷新登录。你用 `claude mcp add` 添加的 MCP 服务器会到达每个 Claude 账户，因为它们全都在 `~/.claude` 中运行；对于 Codex 和 Grok，你在添加某个账户时已有的服务器会跟着到它那里，但之后的服务器只能到达你添加它们时所在的账户。Claude Desktop 保留它自己的登录，而用指向某个 CLI 二进制文件的绝对路径配置的 Codex 或 Grok 工具不会跟随切换。显式的 `CLAUDE_CONFIG_DIR`、`CODEX_HOME` 或 `GROK_HOME` 优先于所选账户。

### 崩溃诊断

Omarchy 监视 systemd-coredump 中的进程崩溃。一旦你挑选了一个默认智能体，你的任何倾倒核心的程序都会带来一个“Process crashed”通知——单击它，崩溃就会连同 Omarchy 的 omarchy-diagnose-crash 技能一起交给你的默认智能体，该技能会引导智能体从核心转储中查清事实，并决定该崩溃是否值得向上游报告。你也可以用 `omarchy agent crash <pid>`，针对 `coredumpctl list` 中的任何 PID 手动运行它。

该监视默认开启。在 _Trigger > Toggle > Crash Capture Off_ 下关闭它（或用 `omarchy toggle crash-capture`），通知就会停止；`omarchy agent crash <pid>` 仍然可以手动使用。

崩溃也可以逐个程序地静音，这正是诊断最后向你提供的。`omarchy crash mute hyprland` 只停止该程序的通知，`omarchy crash mute hyprland off` 把它们带回来，而单独的 `omarchy crash mute` 会列出你已静音的内容。它接受二进制文件的路径和接受它的名称一样愉快，所以 `omarchy crash mute /usr/bin/hyprland` 做的是同一件事。给带空格的名称加上引号，如 `omarchy crash mute 'Some App'`。其他一切仍会通知，而被静音的程序仍会崩溃——这隐藏了提醒，它不修复任何东西。

### 桌面应用

_Install > AI_ 菜单还带有几个图形 AI 应用：Amp Desktop、Antigravity Desktop、ChatGPT desktop app、Claude desktop app（Anthropic 的 Linux beta，带有 Chat、Cowork 和 Claude Code 标签页）、Grok Bot（用于与 xAI 的模型聊天）、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexity desktop app 和 T3 Code。Grok Bot 是桌面聊天应用。编码智能体是 `grok` 命令。

Hermes Desktop 是需要了解的那个，因为一台机器只有一个 Hermes，而且它是该应用的：Hermes 只通过该应用安装，而默认智能体运行的 `hermes` 命令也是该应用的。选择 Hermes 作为默认智能体会安装与 _Install > AI_ 条目相同的东西：该软件包，以及一个由 Hermes 自己的安装器在 `~/.hermes` 下设置的 Hermes 运行时，第一次需要几分钟。那个运行时是终端 `hermes` 命令、默认智能体和该应用全都使用的唯一 Hermes，而且它用 `hermes update` 自我更新，而不是等 Omarchy 发布。安装它还会把 Omarchy 主题作为一个名为 `omarchy` 的皮肤交给 Hermes，当你切换主题时，每个 Hermes 界面都会跟随它；如果你宁愿它不这样，在 Hermes 的 Appearance 设置下或用 `/skin` 选择另一个，Omarchy 会保留那个选择不动。在 _Remove > AI_ 下移除该应用会先关闭 Hermes，包括网关，带上那个运行时一起移除，并保留你的聊天、记忆和 Hermes 为自己编写的技能，除非你另行告诉它：它会询问，默认为否，是否也一并移除那些数据和你的连接设置。

OpenClaw 的桌面体验是其 Control UI，它作为一个由其自有本地网关支持的 Web 应用打开。OpenClaw 位于 `~/.openclaw` 并自我更新：使用 Control UI 的“Update Gateway”按钮或运行 `openclaw update`，网关会在新版本上重启。Omarchy 只选择全新安装起始的版本。OpenClaw 也可以是你的默认智能体：在 _Agent > Harness_ 下选择它，会在 `~/.openclaw` 中设置同一个副本，该智能体会打开连接到其网关的 OpenClaw 终端 UI。在 _Remove > AI_ 下移除 OpenClaw 会带上网关服务和应用一起移除，然后询问 `~/.openclaw` 是否也应该移除，因为那里存放着你的聊天和凭据，以及 OpenClaw 本身和它下载的插件运行时；默认保留它，再次安装 OpenClaw 会把它拾回来。

Herdr Desktop 是 [Herdr](https://herdr.dev) 桌面应用：由终端和编码智能体组成的 spaces、标签页和窗格，当你关闭窗口时它们在它的核心中继续运行。它来自 Herdr 自己的安装器而不是一个软件包，所以它位于 `~/.local/share/herdr-app`，在你尚没有时在 `~/.local/bin/herdr-core` 中带上它的核心，并自我更新两者。它位于 Omarchy 在 `Super + Ctrl + Return` 上随附的 `herdr` 命令旁边，而不是替换它，并获得该命令的直接按键：`Alt + Return` 和 `Alt + Shift + Return` 向下或向右拆分窗格，`Alt + Escape` 关闭它，`Ctrl + Alt + Arrow` 在窗格之间移动，`Alt + 1..9` 和 `Alt + Left/Right` 选择标签页，`Alt + Up/Down` 在 spaces 之间移动。`Ctrl + 1..9` 选择一个 space，`Alt + Shift + Up/Down` 在智能体之间步进。`Ctrl + Space` 前缀键保持仅供终端使用，因为该应用无法为一个序列按住一个平常的 Ctrl 键。Omarchy 把这些写入 `~/.config/herdr-app/keys.json`，而 `omarchy-refresh-herdr-app` 把它们放回来。安装它会挑选 Herdr 的 Omarchy 主题，从那时起它会跟随你的 Omarchy 主题。Herdr 为浅色模式保留一个主题，为深色模式保留一个，所以在深色和浅色 Omarchy 主题之间切换后，再在 Herdr 的主题选择器中为另一种模式选择一次 Omarchy。

T3 Code 从其位于 `~/.local/share/t3code` 的官方 AppImage 版本运行，而不是从一个软件包运行，所以它自我更新。安装它会询问是从 Stable 还是 Nightly 通道开始；之后在 T3 Code 的设置中切换。你的 threads 和设置位于 `~/.t3`，在 _Remove > AI_ 下移除 T3 Code 会把它们一起移除。

### 本地模型

在你自己的机器上为你的编码智能体运行一个开放模型。你的提示词和代码留在机器上；发送给模型的任何东西都不会离开它。从这里开始：

```bash
omarchy models use best text
```

这会为这台机器设置最佳文本模型，就是你的智能体使用的那种。图像、视频和音乐模型各有其最佳者：`omarchy models use best image`、`video` 或 `music`。运行 `omarchy models use best` 查看每种类型为这台机器挑选的那个。

或者从顶栏中其紧挨着智能体图标的闪光图标打开本地模型面板，或用 Super + Ctrl + Alt + X，然后选择 +。当有一款模型适合这台机器时，该图标就会出现。运行这些模型的 Podman 随 Omarchy 一同提供，在 NVIDIA 机器上 NVIDIA 的容器工具包也一同提供，它为它们提供 GPU；如果其中任何一个缺失，首次设置会安装它。然后 Omarchy 为这台机器挑选推荐的模型，下载它，并启动它。预计会有数十 GB 的下载，并且在模型运行时机器的大部分内存会被使用：Flash Next 以其完整的 256K 上下文使用约 100 GiB。如果其他模型占有所需的内存，它会被设置为已停止，准备在你停止一个后启动。该模型在注销时停止；当你需要内存做其他事情时，自己停止它。

`omarchy models list` 显示这些选项，并解释为什么有些不适合。要设置另一个，运行 `omarchy models use <recipe>`。今天，`qwen3.8-flash-next-gufo` 和 `qwen3.8-27b-gufo` 可用于 128 GB Strix Halo 机器；27B 占用约 40 GiB，所以它为其他工作留出了空间。在一台 64 GB、带 Intel 的 Arc B390 的笔记本电脑上，`qwen3.6-35b-a3b-llamacpp` 以约 30 GiB 运行。新的配方和推荐通过软件包随 `omarchy update` 到来。

你设置的每个模型在本地模型面板中都有其自己的一行：播放以启动它，暂停以停止它并释放其内存，以及终端按钮以在其上打开你的智能体。在顶部横贯，一条栏显示机器的内存如何在 Omarchy 本身（系统和你的应用）、每个正在运行的模型和空闲部分之间划分。指向一个已停止的模型，该栏显示它是否适合，或者还差多少。多个模型可以在它们一起适合内存时同时运行；如果一个不适合，Omarchy 会说明要停止哪个正在运行的模型。按它们的徽标拖动行以重新排序，并按 Delete 删除选定的行以移除一个模型及其下载。

你设置的每个编码模型在应用启动器中也都有其自己的条目，以该模型的名称并带有其制作者的徽标，就像登录 Claude、Codex 或 Grok 添加一个那样。它在该模型上打开你的智能体，如果它没有运行则先启动该模型：终端显示它正在加载，并在它就绪后交给该智能体。移除一个模型会移除其条目。

不是每个模型都是用于编码的。图像、视频和音乐模型改为在 Fantasi 中打开，那是 Omarchy 用在本机运行的模型制作图片、视频和音乐的应用，在那里或从它们在本地模型面板中的行挑选。

一个模型完全按其设置时的样子保持运行，所以 Omarchy 更新从不在你的智能体底下重启一个。当 Omarchy 为你已设置的一个模型提供了更新的运行时或更新的权重时，它的行显示一个更新按钮：按下它，该模型会在后台重新设置，只下载已更改的部分，并在新版本上重启。一个已停止的模型会保持停止。`omarchy models update` 从终端对每个模型做同样的事。

在命令行中，`omarchy models start <recipe>` 和 `omarchy models stop <recipe>` 做同样的事，`omarchy models status` 显示每个模型，而 `omarchy agent --local` 无论你的默认智能体是什么，都会在 pi 中打开你最后启动的模型。要让该模型成为智能体热键、Quake 控制台和 _Make something_ 打开的那个，运行 `omarchy default agent local` 或在 _Agent > Harness_ 下挑选 _本地模型_。pi 还在其自己的模型选择器中列出你已设置的每个模型，以及你已配对机器上的那些，所以平常的 `pi` 也能到达它们。任何与 OpenAI 兼容的客户端也可以连接：`status` 显示每个模型的地址（第一个是 `http://127.0.0.1:11435/v1`），配方名称就是模型，密钥在 `~/.config/omarchy/agent-local/key` 中。

`omarchy models remove <recipe>` 删除一个模型以及没有其他模型使用的下载。

第三方运行时标有其发布者。Omarchy 以无网络访问的方式运行每个模型。

### 本地 LLM

Omarchy 推荐两种运行本地 LLM 模型的方式：LM Studio 和 Ollama。LM Studio 提供一个 GUI 界面，用于查找开放权重模型、安装它们并运行它们。它是轻松起步的好方法。Ollama 提供一个 CLI 以类似方式做这件事。但如果你是本地模型新手，我会从 LM Studio 开始。你可以在 Omarchy 菜单的 _Install > AI_ 下安装任何一个。

### Omarchy 技能

智能体技能帮助 AI 以特定方式使用特定工具，Omarchy 附带其中七个。omarchy 技能涵盖定制系统，例如调整你的 Hyprland 配置或调整栏。omarchy-make-theme、omarchy-make-plugin、omarchy-make-app 和 omarchy-make-game 涵盖制作新东西，omarchy-contribute 涵盖报告 bug 或向上游发送修复，而 omarchy-diagnose-crash 处理一个崩溃的核心转储。它们被符号链接到 Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` 和每个 `~/.hermes/profiles/*/skills`）的技能目录以及通用的 `~/.agents/skills` 位置，所以大多数 harness 自动拾取它们。你自己的同名技能文件夹优先。

但你应该把这些技能看作实验性的。不同的模型使用它们的效果会不同。最好先在 plan 模式下运行，这样你对智能体想要更改什么有个概念。然后做好准备，回滚更改，甚至调用 `omarchy reinstall configs`，如果智能体把一切搞得一团糟的话。
