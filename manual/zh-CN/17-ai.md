### 安装和更新代理

除了 Hermes，这些代理都使用 mise 的懒安装：首次启动会安装 CLI，后续启动则复用已安装的版本。mise 还会至多每四小时检查一次已安装代理是否有新版本，就在它启动之前，或者在后台的 shell 提示符下进行。如果那次更新失败或你处于离线状态，就会运行已安装的版本。`omarchy update` 会随 Omarchy 的其余部分一起更新已安装的代理，而 `mup` 只更新由 mise 管理的工具。

代理自己的更新器，例如 `claude update`、`codex update`，或者应用中的更新按钮，不会更新由 mise 管理的安装。`codex update` 会失败，而 `claude update` 可能报告成功，却安装了一个 mise 不跟踪的单独副本。如果你更愿意使用某个代理的原生安装器和更新器，把它加入 `disable_tools`；见 [预装的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

若要提前安装所有已配置的懒工具，以免到需要时才装，运行 `mise install --include-lazy`。这既包括 Omarchy 的其他默认 CLI 工具，也包括这些代理。有关安装单个工具或使用你自己的安装，见 [预装的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

`grok` 通过 mise 的第一方 `grok` 包安装，与 `claude` 和 `codex` 的方式相同。运行 `grok`，或者在 _Agent > Harness_ 下选择它。跳过 x.ai 上的 `curl | bash` 安装器。那条路径会在 `~/.grok/bin` 中放入第二个副本，将它置于 `PATH` 的前面，并覆盖 Omarchy 的包装器。

`dsh` 会在 `127.0.0.1:3080` 打开它的浏览器 UI，并以启动目录作为其默认工作区。它的浏览器 UI 不接受起始提示词，所以 `omarchy agent prompt` 打开它时会把提示词放到你的剪贴板上供你粘贴。Omarchy 会使用 DeepSeek 的无审批权限预设来启动它。当你使用 DeepSeek 的官方模型 API 时，DeepSeek Harness 会把会话日志上传到 DeepSeek；在它的浏览器 UI 中的 _Settings > General > Upload Session Log_ 下关闭这一项。你发送给它的反馈也会随会话一起上传，除非你用 `DSH_TELEMETRY_MODE=DISABLED` 启动它。

### 默认代理

使用 `omarchy default agent <name>` 选择你的默认代理，或者在 Omarchy Menu（`Super + Space`）的 _Agent > Harness_ 下选择。如果该代理还没安装，选择它时会先安装它。全新的 Omarchy 会通过一次性通知邀请你做出这个选择。

选择 Claude 还会尝试为 Chromium、Chrome、Brave、Brave Origin 和 Edge 设置它的浏览器扩展。这个扩展设置适用于所有用户，可能会要求你输入系统密码；取消或者扩展安装失败，仍然会选中并启动 Claude。重启你的浏览器，在出现提示时启用该扩展，并登录 Claude 以完成连接。在 Claude 中运行 `/chrome` 检查连接。Firefox 和 Zen 不支持这个扩展。如果在加入这项设置之前 Claude 就已经是你的默认代理了，再次选择它即可安装该扩展。

一旦你选定了，`Super + Shift + Ctrl + A` 就会在一个专用的终端窗口中启动默认代理（或者，如果你还没有选择，就会调起选择器）。你也可以用 `omarchy agent prompt "Review this project"` 让它直接进入一项任务。Freebuff 和 DeepSeek Harness 不接受起始提示词，所以它们打开时会改为把提示词放到你的剪贴板上供你粘贴。以这种方式启动的代理会在它们各自的“不要停下来询问”模式下无人值守地运行，所以做好它们真的会动手做事的准备！MiniMax Code 的交互式会话没有这种模式，所以它会像往常一样请求权限。而且，由于代理拒绝为你的主目录记住信任，从 `$HOME` 启动时改为在 `~/Work` 中开始。

终端里也有快捷方式：`a` 会在当前终端中内联运行默认代理，而 `c`、`cx` 和 `cy` 则会直接启动 OpenCode、Claude Code 和 Codex（同样处于它们的自动批准模式）。主题变化也会同步到这些代理：当你切换 Omarchy 主题时，Claude Code、Pi、OpenCode 和 Hermes（一旦 Omarchy 安装了它）都会随之变化。

### 你的代理指令

适用于每个代理的个人规则都放在 `~/.agents/AGENTS.md` 中，旁边就是 `~/.agents/skills` 中的共享技能。在 _Agent > Instructions_ 下打开它，它还会把该文件链接到每个拥有自己全局文件的 harness 中：`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`~/.pi/agent/AGENTS.md`、`~/.config/opencode/AGENTS.md`、Copilot 的 `~/.copilot/copilot-instructions.md`，等等。Crush 和 Amp 读取 `~/.config/AGENTS.md` 链接，而 omp、Kimi 和 DeepSeek Harness 直接读取 `~/.agents/AGENTS.md`。选择默认代理时也会把它链接好。如果你已有的某个指令文件在尚不存在共享文件时，就会成为那个共享文件；否则，它会作为 `.bak` 保留在该链接旁边。安装了另一个代理后，运行 `omarchy agent instructions` 重新建立链接。

### 代理面板

顶部栏有一个代理图标。在你尚未设置代理之前，它的面板会引导你登录 Claude、Codex 或 Grok，其中第一个会成为你的默认代理。之后，这个面板会把每一项订阅都放在同一页面上：每个代理和账号及其套餐、每个 5 小时会话限额和每周限额的计量条以及距离重置还剩多少时间（把鼠标悬停在上面可看到确切的百分比），或者剩余的预付余额，上面还有一行轮流显示你在所有这些代理上一共用过什么的内容，例如本周的 tokens 和你最常用的模型。在 _Make something_ 下，它会提供用于新主题、插件、应用或游戏的入门提示词，把任务交给你的默认代理。应用的构建方式与 Omarchy 自家的 Hype、Monologue 和 Omacut 一样，使用 C++ 和 Qt Quick，遵循 omarchy-app 代理技能，而且它们需要的编译器和 Qt 组件都已安装。游戏是位于 `~/Games/vibes` 中的单个 three.js 页面，遵循 web-game 代理技能，并且全都从当前主题中的一个 Game Vibes 启动器打开；它们会从网上加载 three.js，所以启动时需要网络连接。Claude Code、Codex、Grok、Kimi、Cursor 及其 Grok Bot 额度、GitHub Copilot、Muse、Antigravity、Kimchi 和 Devin 开箱即用地包含在内，并带有它们的限额，Hermes、Mistral Vibe 和 Qwen Code 则会在你使用过它们之后显示它们的会话和 tokens。你通过 pi、omp 或 opencode 使用的提供商套餐和密钥也会显示出来：OpenCode Zen 和 Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan 以及 Synthetic 及其限额；Fireworks、OpenRouter 和 DeepSeek 及其预付余额；以及你在自己的硬件上运行的模型，列在 Local models 下。每个代理只计算一次，按照向它收费的一方计算，不管你通过多少个 harness 来驱动它。

左键单击栏图标打开面板，右键单击则启动你的默认代理。它背后的用量记录由 `omarchy agent usage-update` 每 15 分钟重新生成一次，而且该面板甚至可以通过一个同步文件夹合并来自你其他机器的用量。完整的设置见 `$OMARCHY_PATH/shell/plugins/agents/` 下的 README。

### 多个订阅

如果你付费购买了不止一个 Claude、Codex 或 Grok 套餐——例如一个个人 Max 和一个工作用的——Omarchy 可以让它们全都保持登录并在它们之间切换。用代理面板中的 + 添加一个订阅，它会直接在那里引导你完成，或者用 `omarchy agent account add claude Work`（或 `codex`，或 `grok`）。如果缺失，它会安装 CLI。某个提供商的第一个账号会通过你平常的浏览器登录，就在 CLI 一直会去查找的地方。之后的每一个账号都会通过一个隐私窗口登录，这样你浏览器已经登录的账号就不会被误认为是这个账号；在那里登录你要添加的账号，并且先关闭你已经打开的任何隐私窗口。千万不要为了做这件事而退出 CLI：退出会撤销已保存的登录状态，那个账号就必须重新添加。

要通过 SSH 把你的订阅登录信息复制到另一台 Omarchy 机器上，运行 `omarchy agent account copy user@laptop`。当目标机器没有安装接收器时，发送方会提供一个临时的接收器，所以较旧的 Omarchy 机器无需更新也能接收账号。已安装的接收器优先。这个命令会复制所有的 Claude、Codex 和 Grok 订阅；添加提供商名称可只选它们，如 `omarchy agent account copy laptop claude`。账号名称和命令 ID 与源机器保持一致，包括目标机器上已经存在的账号。如果不相关的目标账号名称冲突，它们会收到一个数字后缀，而设置、技能、插件和对话历史都保留在各自的机器上、互不影响。

目标机器上现有的凭据会被保留。已经在那里登录的源账号，其名称会同步，但不会替换它的凭据；其他账号则会并排添加进去。若要替换匹配账号已保存的凭据，先在目标机器上退出那个账号的会话，再使用 `omarchy agent account copy --replace laptop claude`。全新的目标机器还会获得源机器当前活动的账号和切换偏好；已经用过的目标机器则保留它自己的。

凭据通过 SSH 传输，并存储在目标机器的私有文件中，所以只往你信任的机器上复制。这是一次性复制，不是持续同步。Codex 的刷新 tokens 可能被另一台机器轮换，导致复制过去的登录状态需要续期；为同时在多台机器上使用，单独登录仍然是最可靠的选择。见 [Codex 的账号身份验证指南](https://developers.openai.com/codex/auth/ci-cd-auth)。

每个提供商同时只有一个活动账号，每个新会话开始时都会是它：`cx`、`cy`、普通的 `claude`、`codex` 或 `grok`、任何通过 `omarchy agent` 启动的东西，以及在 `PATH` 上找到该 CLI 的脚本或编辑器。用 `omarchy agent account use work` 切换（用 `omarchy agent account use main` 切回来），或者在面板中按下一个账号的数字再按 `Enter`（或点击它的 Use 按钮）。正在运行的 Claude 会话也会切换，从它们下一条消息起：每个 Claude 会话都在 `~/.claude` 中运行，那里始终保存着活动账号的登录状态。由较旧 Omarchy 在某个账号自己的文件夹中启动的 Claude 会话会一直持有那个登录状态，直到它退出为止，所以切换时会点名这些会话，并在它们消失后自行完成。正在运行的 Codex 和 Grok 会话则会一直留在它们启动时所用的账号上。对话历史、设置、技能和插件在账号之间共享，所以在同一个文件夹中运行 `claude --continue` 会在新账号上从你离开的地方继续。

有不止一个账号时，面板会把每个账号的限额并排显示，并标出活动的那个。默认情况下，当活动账号超过某个限额的 95% 时，Omarchy 会通知你，点击该通知会切换到余量最多的账号。把鼠标悬停在面板中某个账号的行上，点击 Use 旁边出现的 Autoswitch（或按 `m`），或者运行 `omarchy agent account mode auto`，让它自行切换；它开启时，Autoswitch 会取代 Use 的位置，再次点击它就会回到只通知。用一个数字改变阈值，如 `omarchy agent account mode auto 90`。如果每个账号都超过了阈值，你会收到一次通知，同时告诉你哪个账号最先释放额度。当活动账号距离其阈值在 15 个百分点以内（默认阈值下即 80%）时，它的限额会每三分钟检查一次，而不是每 15 分钟一次。

`omarchy agent account list` 会显示每个账号及其最新限额，`omarchy agent account remove work` 会忘记其中一个，`omarchy agent account rename primary Hey` 会重命名一个（或者点击面板中某个账号的名称）。这些命令作用于你的默认代理的账号；若要触及另一个提供商，先点名它，如 `omarchy agent account use codex side`。你已经在 `~/.claude` 或 `~/.codex` 中拥有的登录就是 _Main_ 账号。Codex 的账号留在原地；Claude 的账号在另一个账号活动时，会等待在它自己专属的文件夹中。某个账号超过约八小时未使用，可能会显示 _Sign-in required_；点击它可直接在面板中重新登录那个账号，或者切换到它并启动一个会话，它就会自行刷新登录状态。你用 `claude mcp add` 添加的 MCP 服务器能到达每个 Claude 账号，因为它们全都在 `~/.claude` 中运行；对于 Codex 和 Grok，你在某个账号被添加时就已经有的服务器会跟着到那个账号，但之后添加的只能到达你添加它们时所在的那个账号。Claude Desktop 有它自己的登录状态，而用 CLI 二进制文件的绝对路径配置的 Codex 或 Grok 工具不会跟随切换。显式指定的 `CLAUDE_CONFIG_DIR`、`CODEX_HOME` 或 `GROK_HOME` 优先于所选账号。

### 崩溃诊断

Omarchy 会监视 systemd-coredump 中的进程崩溃。当某个进程发生段错误时，你会收到一条 “Process crashed” 通知——点击它，崩溃就会连同 Omarchy 的 diagnose-crash 技能一同交给你的默认代理，这个技能会引导代理从核心转储中查清事实，并判断这次崩溃是否值得向上游报告。你也可以对照 `coredumpctl list` 中的任何 PID 手动运行它，用 `omarchy agent crash <pid>`。

监视默认开启。在 _Trigger > Toggle > Crash Capture_ 下关闭它（或者用 `omarchy toggle crash-capture`）后，通知就会停止；`omarchy agent crash <pid>` 仍然可以手动使用。

崩溃也可以按单个程序逐个静默，这正是诊断最后会提供给你的选项。`omarchy crash mute hyprland` 只停止该程序的通知，`omarchy crash mute hyprland off` 把它们恢复，`omarchy crash mute` 单独运行时会列出你已静默的内容。它接受二进制文件的路径和接受名称一样爽快，所以 `omarchy crash mute /usr/bin/hyprland` 做的事完全一样。给带有空格的名称加引号，如 `omarchy crash mute 'Some App'`。其他一切都仍然会通知，而且被静默的程序仍然会崩溃——这只是隐藏提醒，它不修复任何东西。

### 桌面应用

_Install > AI_ 菜单还包含一些图形化 AI 应用：ChatGPT 桌面应用、Claude 桌面应用（Anthropic 的 Linux beta 版，带有 Chat、Cowork 和 Claude Code 标签页）、用于与 xAI 的模型聊天的 Grok Bot、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexity 桌面应用，以及 T3 Code。Grok Bot 是桌面聊天应用。编程代理是 `grok` 命令。

Hermes Desktop 是你需要了解的那个，因为一台机器上只有一个 Hermes，而且它是属于这个应用的：Hermes 永远只能通过该应用安装，而默认代理运行的 `hermes` 命令也是该应用的。选择 Hermes 作为默认代理，安装的东西与 _Install > AI_ 入口安装的完全相同：该软件包，以及一个由 Hermes 自己的安装器在 `~/.hermes` 下设置的 Hermes 运行时，第一次需要几分钟的时间。终端的 `hermes` 命令、默认代理和这个应用全都使用那同一个 Hermes 运行时，而且它用 `hermes update` 自行更新，而不是等着 Omarchy 发新版。安装它还会把 Omarchy 主题作为一个名为 `omarchy` 的皮肤交给 Hermes，每当你切换主题时，每个 Hermes 界面都会随之变；如果你不想这样，可在 Hermes 的 Appearance 设置下选择另一个，或者用 `/skin`，Omarchy 不会改动那个选择。在 _Remove > AI_ 下移除该应用时，会先关闭 Hermes，包括网关，把那个运行时一并带走，并保留你的聊天、记忆以及 Hermes 为自己编写的技能，除非你另行说明：它会询问是否也应删掉那些数据和你的连接设置，默认回答为否。

OpenClaw 的桌面体验是它的 Control UI，它作为一个 web 应用打开，背后是它自己的本地网关。OpenClaw 位于 `~/.openclaw` 中，并会自行更新：使用 Control UI 的 “Update Gateway” 按钮，或者运行 `openclaw update`，网关就会在新版本上重启。Omarchy 只选择全新安装起始时所用的版本。在 _Remove > AI_ 下移除 OpenClaw 会把网关服务和该应用一并带走，然后询问是否也应删掉 `~/.openclaw`，因为那里保存着你的聊天和凭据，还有 OpenClaw 本身以及它下载的插件运行时；默认是保留它，再次安装 OpenClaw 时还会重新拾起它。

Herdr Desktop 是 [Herdr](https://herdr.dev) 桌面应用：由 spaces、tabs 和 panes 组成的终端和编程代理，即使你关掉窗口，它们也会在它的核心中继续运行。它来自 Herdr 自己的安装器而不是某个软件包，所以它位于 `~/.local/share/herdr-app` 中，当你还没有时，它会在 `~/.local/bin/herdr-core` 中一并带来它的核心，并自行更新这两者。它与 Omarchy 在 `Super + Ctrl + Return` 上自带的 `herdr` 命令并存，而不是取代它，而且它获得了该命令的直接按键：`Alt + Return` 和 `Alt + Shift + Return` 向下或向右拆分一个 pane，`Alt + Escape` 关闭它，`Ctrl + Alt + Arrow` 在 panes 之间移动，`Alt + 1..9` 和 `Alt + Left/Right` 选择一个 tab，`Alt + Up/Down` 在 spaces 之间移动。`Ctrl + 1..9` 选择一个 space，`Alt + Shift + Up/Down` 在代理之间步进。`Ctrl + Space` 前缀键仍然只在终端里可用，因为该应用无法为一个序列按住一个普通的 Ctrl 键。Omarchy 会把这些写入 `~/.config/herdr-app/keys.json`，而 `omarchy-refresh-herdr-app` 会把它们恢复回来。安装它会选择 Herdr 的 Omarchy 主题，从此该主题会跟随你的 Omarchy 主题。Herdr 为浅色模式保留一个主题，为深色模式保留一个主题，所以在深色和浅色的 Omarchy 主题之间切换之后，再在 Herdr 的主题选择器中选一次 Omarchy，用于另一个模式。

T3 Code 从其位于 `~/.local/share/t3code` 中的官方 AppImage 版本运行，而不是从某个软件包运行，所以它会自行更新。安装它时会询问要从 Stable 还是 Nightly 频道开始；之后在 T3 Code 的设置中切换。你的 threads 和设置位于 `~/.t3` 中，在 _Remove > AI_ 下移除 T3 Code 时会把它们一并带走。

### 本地模型

为你的编程代理在自己的机器上运行一个开放模型。你的提示词和代码都留在机器上；发送给模型的任何东西都不会离开它。从这里开始：

```bash
omarchy agent local use best
```

或者，在顶部栏的代理面板中，选择 + 然后选择 Local AI，当有模型适合这台机器时它就会出现。第一次时，这会安装 Podman，它负责运行这些模型，在 NVIDIA 机器上还会安装 NVIDIA 的容器工具包，它让这些模型能用上 GPU。然后 Omarchy 会为这台机器挑选推荐的模型，下载它并启动它。预期要下载几十 GB，而且模型运行时机器的大部分内存都会被占用：Flash Next 在使用其完整的 256K 上下文时大约要用 100 GiB。如果其他模型占着它需要的内存，它会被设置为已停止的状态，等你停掉某个模型后即可启动。该模型在注销登录时停止；当你需要把内存用于别的事情时，自己停掉它。

`omarchy agent local list` 会显示选项，并解释为什么有些不适合。若要设置另一个，运行 `omarchy agent local use <recipe>`。如今，`qwen3.8-flash-next-gufo` 和 `qwen3.8-27b-gufo` 适用于 128 GB 的 Strix Halo 机器；27B 大约需要 40 GiB，所以它会为其他工作留出空间。在一台带有 Intel Arc B390 的 64 GB 笔记本上，`qwen3.6-35b-a3b-llamacpp` 在大约 30 GiB 内运行。新的 recipes 和推荐会通过软件包随 `omarchy update` 一同到来。

你设置的每个模型都在代理面板中拥有自己的一行，挨着你的订阅：点播放启动它，点暂停停止它并释放它的内存，点终端按钮在它上面打开你的代理。有内存能一起装下时，几个模型可以同时运行；如果某个装不下，Omarchy 会说应该停掉哪个正在运行的模型。拖动行可重新排序，按 Delete 选中一行即可移除一个模型及其下载。

你设置的每个模型还会在应用启动器中拥有自己的条目，以该模型的名称命名，并带有其制造商的标志，就像登录 Claude、Codex 或 Grok 会添加一个条目那样。它会在那个模型上打开你的代理，如果该模型没有运行，它会先启动它：终端会显示它正在加载，并在它准备好后交给代理。移除一个模型也会移除它的条目。

从命令行看，`omarchy agent local start <recipe>` 和 `omarchy agent local stop <recipe>` 做的事相同，`omarchy agent local status` 显示每个模型，而 `omarchy agent --local` 会在你最后启动的模型上打开你的默认代理。pi、OpenCode 和 Qwen Code 可以使用其中一个；若是任何其他默认代理，它会在 pi 中打开。pi 还会在它自己的模型选择器中列出你设置过的每个模型，以及在你已经配对过的机器上的那些模型，所以普通的 `pi` 也能触及它们。任何与 OpenAI 兼容的客户端也可以连接：`status` 会显示每个模型的地址（第一个是 `http://127.0.0.1:11435/v1`），recipe 名称就是模型，密钥位于 `~/.config/omarchy/agent-local/key`。

`omarchy agent local remove <recipe>` 会删除一个模型以及没有其他模型使用的那些下载。

第三方运行时会标有它们的发布者。Omarchy 在没有网络访问的条件下运行每一个模型。

### 本地 LLM

Omarchy 推荐两种运行本地 LLM 模型的方式：LM Studio 和 Ollama。LM Studio 提供一个 GUI 界面，用于查找开放权重模型、安装它们并运行它们。它是轻松入门的好方式。Ollama 提供一个 CLI，以类似方式做到这点。但如果你是本地模型新手，我会从 LM Studio 开始。你可以在 Omarchy Menu 的 _Install > AI_ 下安装其中任何一个。

### Omarchy Skill

代理技能帮助 AI 以特定方式使用特定工具，而 Omarchy 附带一个用于量身定制系统的默认技能。就像调整你的 Hyprland 配置、调整栏，或者甚至从头创建一个新主题。它被符号链接到 Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` 以及每个 `~/.hermes/profiles/*/skills`）的技能目录，以及通用的 `~/.agents/skills` 位置，所以大多数 harness 都会自动拾取它。

但你应该把这个技能视为实验性的。不同的模型使用它的效果各不相同。最好先在规划模式下运行，这样你就能有个概念，知道代理想改什么。然后准备好回滚更改，甚至调用 `omarchy reinstall configs`，如果代理把一切都搞得一团糟的话。
