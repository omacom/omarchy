# AI

Omarchy 把 AI 编程智能体当作一等公民，但它不会替你挑一个最喜欢的。相反，每个主流的编程智能体 CLI 都预先接好了懒加载启动器。这些启动器是 `~/.local/bin/` 中由 [mise](https://mise.jdx.dev/) 管理的小型存根，所以在你第一次真正运行某个智能体之前，什么都不会下载。Hermes 是个例外：它没有存根，选择它会安装 Hermes Desktop，正如下面的_桌面应用_所解释的。调用其中任何一个，并在提示时进行身份验证：

| 命令    | 智能体                                                            |
|------------|------------------------------------------------------------------|
| `claude`   | [Claude Code](https://code.claude.com/docs/en/overview)          |
| `codex`    | [OpenAI Codex](https://github.com/openai/codex)                  |
| `opencode` | [OpenCode](https://opencode.ai/)                                 |
| `agy`      | [Google Antigravity CLI](https://github.com/google-antigravity/antigravity-cli) |
| `copilot`  | [GitHub Copilot CLI](https://github.com/github/copilot-cli)      |
| `crush`    | [Crush](https://github.com/charmbracelet/crush)                  |
| `grok`     | 来自 xAI 的 [Grok Build](https://x.ai/build)                        |
| `kimi`     | [Kimi Code](https://www.kimi.com/code/docs/en/)                  |
| `pi`       | [Mario Zechner 的 Pi](https://github.com/badlogic/pi-mono)        |
| `omp`      | [Oh My Pi](https://github.com/can1357/oh-my-pi)                  |
| `ori`      | [Ori](https://openrouter.ai/docs/guides/ori/harness)，OpenRouter 的 harness |
| `hermes`   | [Hermes](https://hermes-agent.nousresearch.com/)，Nous Research 的智能体  |
| `muse`     | [Muse Code](https://dev.meta.ai)，Meta 的编程智能体           |
| `cursor-agent` | [Cursor CLI](https://cursor.com/cli)                         |

`ori` 是其中与众不同的一个：它让其他 harness 对着 OpenRouter 的整个模型目录运行，所以 `ori claude`、`ori codex` 或 `ori opencode` 会在你指向的任何模型上启动那些智能体，而 `ori code` 是 Ori 自己的智能体。

要以同样的方式包装一个额外的 CLI，请运行 `omarchy-mise-install <package> [command-name]`。当你运行 `omarchy update`（或 `mup` 别名）时，这些存根会与 mise 管理的其他一切一起保持最新。

`grok` 通过 mise 的第一方 `grok` 包安装，与 `claude` 和 `codex` 的方式相同。运行 `grok`，或在_设置 > 默认项 > 智能体_下选择它。跳过 x.ai 上的 `curl | bash` 安装程序。那条路径会在 `~/.grok/bin` 中放入第二份副本，把它前置到 `PATH` 上，并覆盖 Omarchy 的包装器。

### 默认智能体

用 `omarchy default agent <name>` 选择你的默认智能体，或者在 Omarchy Menu（`Super + Space`）的_设置 > 默认项 > 智能体_下选择。如果该智能体尚未安装，选择它会先安装它。全新的 Omarchy 会通过一次性通知邀请你做出这个选择。

选择 Claude 还会尝试为 Chromium、Chrome、Brave、Brave Origin 和 Edge 设置它的浏览器扩展。该扩展设置适用于所有用户，可能会要求你输入系统密码；取消或扩展安装失败仍会选择并启动 Claude。重启你的浏览器，在提示时启用该扩展，并登录 Claude 以完成连接。在 Claude 中运行 `/chrome` 来检查连接。Firefox 和 Zen 不支持这个扩展。如果在这个设置功能添加之前 Claude 已经是你的默认智能体，请再次选择它来安装该扩展。

[Muse Code](https://dev.meta.ai) —— Meta 的 `muse` —— 像其他智能体一样使用预安装的 mise 存根。选择它作为默认智能体会通过 mise 的 HTTP 后端安装 Meta 的官方启动器。该启动器会验证并更新适合你机器的原生二进制文件。

一旦你做出选择，`Super + Shift + Ctrl + A` 就会在一个专用的终端窗口中启动默认智能体（或者如果你还没有选择，就会弹出选择器）。你也可以用 `omarchy agent prompt "Review this project"` 让它直接进入一个任务。以这种方式启动的智能体会各自在不中途停下来询问的模式下无人值守地运行，所以要做好它们真的会做事的准备！而且由于智能体拒绝记住对你主目录的信任，从 `$HOME` 启动时改为从 `~/Work` 开始。

也有终端快捷方式：`a` 在当前终端中内联运行默认智能体，而 `c`、`cx` 和 `cy` 则直接启动 OpenCode、Claude Code 和 Codex（同样是在它们的自动批准模式下）。主题更改也会同步到智能体：当你切换 Omarchy 主题时，Claude Code、Pi、OpenCode 和 Hermes（一旦 Omarchy 安装了它）都会跟随变化。

### 智能体面板

顶部栏有一个智能体图标。在你设置好一个智能体之前，它的面板会引导你登录 Claude、Codex 或 Grok，第一个就会成为你的默认智能体。在那之后，面板会把每个订阅都放在一页上：每个智能体和账户及其套餐、每个 5 小时会话限额和每周限额的计量条及距离重置的时间（悬停可查看确切百分比），或者剩余的预付余额，上方还有一行轮播显示你在所有这些智能体上的使用情况，比如本周的 tokens 和你用得最多的模型。在_做点什么_下面，它提供用于新主题、插件或应用的入门提示词，把任务交给你的默认智能体。应用的构建方式与 Omarchy 自己的 Hype、Monologue 和 Omacut 相同，用 C++ 和 Qt Quick，遵循 omarchy-app 智能体技能，它们需要的编译器和 Qt 组件都已安装好。Claude Code、Codex、Grok、Fireworks 和 Kimi 开箱即用地受支持。Kimi 目前报告账户配额限制，但不提供本地 token 或提示词统计数据。

左键单击栏图标打开面板，右键单击启动你的默认智能体。其背后的使用记录每 15 分钟由 `omarchy agent usage-update` 重新生成一次，而且面板甚至可以通过一个同步文件夹合并你其他机器上的使用情况。完整的设置请参阅 `$OMARCHY_PATH/shell/plugins/agents/` 下的 README。

### 多个订阅

如果你为不止一个 Claude、Codex 或 Grok 套餐付费 —— 比如一个个人 Max 和一个工作用的 —— Omarchy 可以让它们都保持登录状态，并在它们之间切换。用智能体面板中的 + 添加一个订阅，它会就在那里引导你完成，或者用 `omarchy agent account add claude Work`（或 `codex`，或 `grok`）添加。如果 CLI 缺失，它会安装该 CLI。一个提供商的第一个账户通过你平常的浏览器登录，就在 CLI 一直查找的地方。在那之后的每一个都通过一个隐私窗口登录，这样你的浏览器已经登录的那个账户就不会被误选；在那里以你要添加的账户身份登录，并先关闭你已经打开的任何隐私窗口。千万不要为此退出 CLI 的登录：退出登录会撤销已保存的登录状态，那个账户就必须重新添加。

要通过 SSH 把你的订阅登录信息复制到另一台 Omarchy 机器上，请运行 `omarchy agent account copy user@laptop`。当目标机器没有安装接收器时，发送方会提供一个临时接收器，所以较旧的 Omarchy 机器无需更新也可以接收账户。已安装的接收器优先。这会复制所有的 Claude、Codex 和 Grok 订阅；加上提供商名称可选择它们，如 `omarchy agent account copy laptop claude`。账户名称和命令 ID 与来源一致，包括目标机器上已经存在的账户。如果不相关的目标账户名称冲突，它们会收到一个数字后缀，而设置、技能、插件和对话历史则保留在每台机器本地。

已有的目标凭据会被保留。一个已经在那里登录的来源账户，其名称会被同步，但不会替换其凭据；其他账户会被添加到它旁边。要替换匹配账户已保存的凭据，请在退出目标机器上那个账户的会话后，使用 `omarchy agent account copy --replace laptop claude`。一个全新的目标机器还会获得来源的活动账户和切换偏好设置；一个已经在使用的目标机器则保留它自己的。

凭据通过 SSH 传输，并存储在目标机器的私有文件中，所以只复制到你信任的机器上。这是一次性复制，不是持续同步。Codex 刷新令牌可能会被另一台机器轮换，使得复制过来的登录需要续期；对于在多台机器上同时使用，分开的登录仍然是最可靠的选择。请参阅 [Codex 的账户身份验证指南](https://developers.openai.com/codex/auth/ci-cd-auth)。

每个提供商有一个活动账户，每个新会话都以它开始：`cx`、`cy`、普通的 `claude`、`codex` 或 `grok`、通过 `omarchy agent` 启动的任何东西，以及在 `PATH` 上找到该 CLI 的脚本或编辑器。用 `omarchy agent account use work` 切换（并用 `omarchy agent account use main` 切回来），或者在面板中按下某个账户的编号然后按 `Enter`（或单击它的 Use 按钮）。已经在运行的会话会留在它们开始时所用的账户上。对话历史、设置、技能和插件在账户之间共享，所以在同一文件夹中的 `claude --continue` 会在新账户上从你离开的地方继续。

当有多个账户时，面板会并排显示每个账户的限额，并标记活动的那一个。默认情况下，当活动账户超过某个限额的 95% 时，Omarchy 会通知你，单击该通知会切换到余量最多的账户。把鼠标悬停在面板中某个账户的行上，单击 Use 旁边出现的 Autoswitch（或按 `m`），或者运行 `omarchy agent account mode auto`，可以让它自动切换；开启时，Autoswitch 会取代 Use 的位置，再次单击它会回到通知模式。加上一个数字可更改阈值，如 `omarchy agent account mode auto 90`。如果每个账户都超过了阈值，你会收到一次通知，同时告知哪个账户最先释放额度。当活动账户距离其阈值在 15 个百分点以内时（默认情况下为 80%），它的限额会每三分钟检查一次，而不是每 15 分钟。

`omarchy agent account list` 显示每个账户及其最新限额，`omarchy agent account remove work` 忘记一个账户，`omarchy agent account rename primary Hey` 重命名一个账户（或者单击面板中某个账户的名称）。这些命令作用于你默认智能体的账户；要到达另一个提供商，请先写出它的名字，如 `omarchy agent account use codex side`。你已经在 `~/.claude` 或 `~/.codex` 中拥有的登录就是 _Main_ 账户，它会留在原地。一个闲置超过大约八个小时的账户可能会显示_需要登录_；单击它即可直接在面板中重新登录那个账户，或者在它里面开始一个会话，这会自动刷新登录状态。你在添加某个账户时已经拥有的 MCP 服务器会随之带到那个账户，但你后来用 `claude mcp add` 添加的那些只会到达你添加它们时所在的账户。Claude Desktop 以及用指向 CLI 二进制文件的绝对路径配置的工具不会跟随切换。显式的 `CLAUDE_CONFIG_DIR`、`CODEX_HOME` 或 `GROK_HOME` 优先于所选账户。

### 崩溃诊断

Omarchy 会监视 systemd-coredump 以发现进程崩溃。当某个进程发生段错误时，你会收到一个“Process crashed”通知 —— 单击它，这次崩溃就会连同 Omarchy 的 diagnose-crash 技能一起交给你的默认智能体，该技能会引导智能体从核心转储中确定事实，并决定这次崩溃是否值得向 upstream 报告。你也可以用 `omarchy agent crash <pid>` 针对 `coredumpctl list` 中的任何 PID 手动运行它。

监视默认是开启的。在_触发器 > 切换 > 崩溃捕获_下关闭它（或用 `omarchy toggle crash-capture`），通知就会停止；`omarchy agent crash <pid>` 仍然可以手动使用。

崩溃也可以逐个程序地静默，这正是诊断最后会向你提供的选项。`omarchy crash mute hyprland` 只停止那个程序的通知，`omarchy crash mute hyprland off` 把它们带回来，而单独运行 `omarchy crash mute` 则列出你已经静默的内容。它接受二进制文件的路径如同接受其名称一样顺畅，所以 `omarchy crash mute /usr/bin/hyprland` 做的是同一件事。给带有空格的名称加引号，如 `omarchy crash mute 'Some App'`。其他一切仍然会通知，而被静默的程序仍然会崩溃 —— 这隐藏了提醒，它不会修复任何东西。

### 桌面应用

_安装 > AI_ 菜单还带有几个图形化的 AI 应用：ChatGPT 桌面应用、Claude 桌面应用（Anthropic 的 Linux 测试版，带有 Chat、Cowork 和 Claude Code 标签页）、用于与 xAI 的模型聊天的 Grok Bot、Hermes Desktop、OpenClaw，以及 Perplexity 桌面应用。Grok Bot 是桌面聊天应用。编程智能体是 `grok` 命令。

Hermes Desktop 是值得了解的那一个，因为一台机器只有一个 Hermes，而且它属于这个应用：Hermes 只通过这个应用安装，而默认智能体运行的 `hermes` 命令也是这个应用的。选择 Hermes 作为默认智能体会安装与_安装 > AI_条目相同的东西：软件包，以及由 Hermes 自己的安装程序在 `~/.hermes` 下设置的一个 Hermes 运行时，第一次需要几分钟。那个运行时是终端 `hermes` 命令、默认智能体和应用全都使用的那一个 Hermes，它用 `hermes update` 自我更新，而不是等待 Omarchy 发布新版本。安装它还会把 Omarchy 主题作为一个名为 `omarchy` 的皮肤交给 Hermes，当你切换主题时，每个 Hermes 界面都会跟随它；如果你不想如此，在 Hermes 的 Appearance 设置下或用 `/skin` 选择另一个，Omarchy 不会干涉那个选择。在_移除 > AI_下移除该应用会先关闭 Hermes，包括网关，带走那个运行时，并保留你的聊天、记忆以及 Hermes 为自己编写的技能，除非你告诉它不要保留：它会询问那些数据和你的连接设置是否也应该去掉，默认为不去掉。

OpenClaw 的桌面体验是它的 Control UI，它作为一个由它自己的本地网关支持的 Web 应用打开。OpenClaw 位于 `~/.openclaw`，并自我更新：使用 Control UI 的“Update Gateway”按钮或运行 `openclaw update`，网关就会在新版本上重启。Omarchy 只选择全新安装从哪个版本开始。在_移除 > AI_下移除 OpenClaw 会一并带走网关服务和应用，然后询问 `~/.openclaw` 是否也应该去掉，因为那里存放着你的聊天和凭据，以及 OpenClaw 本身和它下载的插件运行时；默认是保留它，再次安装 OpenClaw 会把它重新捡起来。

### 本地 LLM

Omarchy 推荐两种运行本地 LLM 模型的方式：LM Studio 和 Ollama。LM Studio 提供一个 GUI 界面，用于查找开放权重模型、安装它们并运行它们。这是一个轻松上手的绝佳方式。Ollama 提供一个 CLI 以类似的方式做这件事。但如果你是本地模型的新手，我会从 LM Studio 开始。你可以在 Omarchy Menu 的_安装 > AI_下安装任意一个。

### Omarchy 技能

智能体技能帮助 AI 以特定的方式使用特定的工具，Omarchy 自带一个用于定制系统的默认技能。比如调整你的 Hyprland 配置、调整顶部栏，甚至从零创建一个新主题。它被符号链接到 Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` 和每个 `~/.hermes/profiles/*/skills`）的技能目录，以及通用的 `~/.agents/skills` 位置，所以大多数 harness 都会自动捡起它。

但你应该把这个技能当作实验性的。不同的模型会以不同的效果使用它。最好先在计划模式下运行，这样你对智能体想要更改什么心里有数。然后要做好回滚更改的准备，如果智能体把一切都搞得一团糟，甚至要做好调用 `omarchy reinstall configs` 的准备。
