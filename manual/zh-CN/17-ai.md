### 安装和更新智能体

除 Hermes 外，这些智能体使用 mise 的延迟安装：首次启动时安装 CLI，之后的启动会重复使用它。mise 还会检查已安装的智能体是否有新版本，最多每四小时检查一次，就在它启动之前，或在 shell 提示符下于后台检查。如果该更新失败或你处于离线状态，则运行已安装的版本。`omarchy update` 会随 Omarchy 的其余部分一起更新已安装的智能体，而 `mup` 只更新由 mise 管理的工具。

智能体自带的更新程序，例如 `claude update`、`codex update` 或应用中的更新按钮，不会更新由 mise 管理的安装。`codex update` 会失败，而 `claude update` 可能会报告成功，却安装了一个 mise 不跟踪的独立副本。如果你更愿意使用智能体原生的安装程序和更新程序，请将其添加到 `disable_tools`；请参阅[预装的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

要提前安装所有已配置的延迟工具，请运行 `mise install --include-lazy`。这包括 Omarchy 的其他默认 CLI 工具以及这些智能体。有关安装单个工具或使用你自己的安装，请参阅[预装的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

`grok` 通过 mise 的第一方 `grok` 软件包安装，与 `claude` 和 `codex` 的方式相同。运行 `grok`，或在_智能体 > Harness_下选择它。跳过 x.ai 上的 `curl | bash` 安装程序。那条路径会在 `~/.grok/bin` 中放入第二个副本，将其前置到 `PATH` 上，并覆盖 Omarchy 的包装器。

`dsh` 会在 `127.0.0.1:3080` 上打开其浏览器 UI，并以启动目录作为其默认工作区。其浏览器 UI 不接受起始提示，因此 `omarchy agent prompt` 会打开它，并将提示放到你的剪贴板中供你粘贴。Omarchy 会以 DeepSeek 的无批准权限预设启动它。当你使用 DeepSeek Harness 的官方模型 API 时，它会将遭受会话日志上传到 DeepSeek；在其浏览器 UI 的_设置 > 常规 > 上传会话日志_下关闭该功能。你发送给它的反馈也会随会话一起上传，除非你使用 `DSH_TELEMETRY_MODE=DISABLED` 启动它。

### 默认智能体

使用 `omarchy default agent <name>` 选择你的默认智能体，或在 Omarchy 菜单（`Super + Space`）的_智能体 > Harness_下选择。如果该智能体尚未安装，选择它会先安装它。全新的 Omarchy 会通过一次性通知邀请你做出这一选择。

选择 Claude 还会尝试为 Chromium、Chrome、Brave、Brave Origin 和 Edge 设置其浏览器扩展。该扩展设置适用于所有用户，可能会要求输入你的系统密码；取消或扩展安装失败仍然会选择并启动 Claude。重启你的浏览器，在提示时启用该扩展，并登录 Claude 以完成连接。在 Claude 中运行 `/chrome` 检查连接。Firefox 和 Zen 不支持此扩展。如果在添加此设置之前 Claude 已经是你的默认项，请再次选择它以安装该扩展。

一旦你做出了选择，`Super + Shift + Ctrl + A` 会在一个专用终端窗口中启动默认智能体（如果你还没有选择，则会打开选择器）。你也可以使用 `omarchy agent prompt "Review this project"` 让它直接开始执行一项任务。Freebuff 和 DeepSeek Harness 不接受起始提示，因此它们会打开并将提示放到你的剪贴板中供你粘贴。以这种方式启动的智能体会以各自的不要停下来询问模式无人值守地运行，所以要做好它们真的会动手做事的准备！MiniMax Code 的交互式会话没有这种模式，因此它会像往常一样请求权限。而且，由于智能体拒绝记住对你的主目录的信任，从 `$HOME` 启动时会改为在 `~/Work` 中启动。

还有终端快捷方式：`a` 在当前终端中内联运行默认智能体，而 `c`、`cx` 和 `cy` 则直接启动 OpenCode、Claude Code 和 Codex（同样以它们的自动批准模式运行）。主题更改也会同步到这些智能体：当你切换 Omarchy 主题时，Claude Code、Pi、OpenCode 和 Hermes（一旦 Omarchy 已安装它）都会随之变化。

### 你的智能体指令

适用于每个智能体的个人规则位于 `~/.agents/AGENTS.md`，紧邻 `~/.agents/skills` 中的共享技能。在_智能体 > 指令_下打开它，它还会将其链接到每个拥有自己全局文件的 harness 中：`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`~/.pi/agent/AGENTS.md`、`~/.config/opencode/AGENTS.md`、Copilot 的 `~/.copilot/copilot-instructions.md`，等等。Crush 和 Amp 读取 `~/.config/AGENTS.md` 链接，而 omp、Kimi 和 DeepSeek Harness 则直接读取 `~/.agents/AGENTS.md`。选择默认智能体也会链接它。如果你已有的指令文件在尚不存在共享文件时，就会成为共享文件；否则，它会作为 `.bak` 保留在链接旁边。在安装另一个智能体后，运行 `omarchy agent instructions` 重新链接。

### 智能体面板

顶栏有一个智能体图标。在你设置智能体之前，它的面板会引导你登录 Claude、Codex 或 Grok，其中第一个会成为你的默认智能体。之后，该面板会将每个订阅都放在一个页面上：每个智能体和帐户及其套餐，每个智能体的 5 小时会话限额和每周限额的计量表以及距离重置的时间（将鼠标悬停可查看确切百分比），或剩余的预付余额，上方有一行文字轮换显示你在所有这些智能体中的使用情况，例如本周的 token 数和你最常用的模型。在_做点东西_下，它为新主题、插件或应用提供起始提示，并将任务交给你的默认智能体。应用的构建方式与 Omarchy 自己的 Hype、Monologue 和 Omacut 相同，使用 C++ 和 Qt Quick，遵循 omarchy-app 智能体技能，它们所需的编译器和 Qt 组件都已预装。Claude Code、Codex、Grok、Kimi、Cursor 及其 Grok Bot 额度、GitHub Copilot、Muse、Antigravity、Kimchi 和 Devin 都开箱即用地涵盖在内并显示其限额，而 Hermes、Mistral Vibe 和 Qwen Code 则会在你使用它们后显示其会话和 token。你通过 pi、omp 或 opencode 使用的提供商套餐和密钥也会显示：OpenCode Zen 和 Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan 和 Synthetic 及其限额；Fireworks、OpenRouter 和 DeepSeek 及其预付余额；以及你在自己的硬件上运行的模型，位于 Local models 下。每个智能体只计算一次，按向它收费的一方归类，无论你通过多少个 harness 来驱动它。

左键单击顶栏图标打开面板，右键单击启动你的默认智能体。其背后的使用记录每 15 分钟由 `omarchy agent usage-update` 重新生成，并且该面板甚至可以通过同步文件夹合并来自你的其他机器的使用情况。有关完整设置，请参阅 `$OMARCHY_PATH/shell/plugins/agents/` 下的 README。

### 多个订阅

如果你付费订阅了不止一个 Claude、Codex 或 Grok 套餐——比如一个个人 Max 和一个工作套餐——Omarchy 可以让它们全部保持登录状态，并在它们之间切换。使用智能体面板中的 + 添加一个订阅，它会直接在那里引导你完成，或者使用 `omarchy agent account add claude Work`（或 `codex`，或 `grok`）。如果缺少 CLI，它会安装它。某个提供商的第一个帐户通过你平常的浏览器登录，就在 CLI 一直查找的位置。此后的每一个帐户都通过隐私窗口登录，因此你的浏览器已登录的帐户不会被误选；在那里以你要添加的帐户身份登录，并先关闭你已打开的任何隐私窗口。切勿为此退出 CLI 登录：退出登录会吊销已保存的登录信息，该帐户将不得不重新添加。

要通过 SSH 将你的订阅登录信息复制到另一台 Omarchy 机器，请运行 `omarchy agent account copy user@laptop`。当目标机器没有安装接收器时，发送方会提供一个临时接收器，因此较旧的 Omarchy 机器无需更新即可接收帐户。已安装的接收器优先。此命令会复制所有 Claude、Codex 和 Grok 订阅；添加提供商名称可选择它们，如 `omarchy agent account copy laptop claude`。帐户名称和命令 ID 与源机器保持一致，包括目标机器上已存在的帐户。如果名称冲突，无关的目标帐户会获得数字后缀，设置、技能、插件和对话历史则保留在每台机器本地。

目标机器上现有的凭据会保留。已在那里登录的源帐户会同步其名称，但不会替换其凭据；其他帐户会添加到它旁边。要替换匹配帐户的已保存凭据，请在目标机器上退出该帐户的会话后，使用 `omarchy agent account copy --replace laptop claude`。全新的目标机器还会获得源机器的活动帐户和切换偏好；已建立的目标机器则保留自己的。

凭据通过 SSH 传输，并存储在目标机器的私有文件中，因此只能复制到你信任的机器。这是一次性复制，而不是持续同步。Codex 刷新 token 可能会被另一台机器轮换，导致复制的登录信息需要续期；对于在多台机器上同时使用，单独登录仍然是最可靠的选择。请参阅 [Codex 的帐户身份验证指南](https://developers.openai.com/codex/auth/ci-cd-auth)。

每个提供商有一个活动帐户，每个新会话都以它开始：`cx`、`cy`、普通的 `claude`、`codex` 或 `grok`、通过 `omarchy agent` 启动的任何内容，以及在 `PATH` 上找到 CLI 的脚本或编辑器。使用 `omarchy agent account use work` 切换（使用 `omarchy agent account use main` 切回），或在面板中按某个帐户的数字然后按 `Enter`（或单击其 Use 按钮）。已在运行的会话会继续使用它们启动时所用的帐户。对话历史、设置、技能和插件在帐户之间共享，因此在同一文件夹中的 `claude --continue` 会在新帐户上从你离开的地方继续。

当有多个帐户时，面板会并排显示每个帐户的限额，并标记活动帐户。默认情况下，当活动帐户超过某个限额的 95% 时，Omarchy 会通知你，单击该通知会切换到余量最多的帐户。将鼠标悬停在面板中某个帐户的行上，单击 Use 旁边出现的 Autoswitch（或按 `m`），或运行 `omarchy agent account mode auto`，让它自行切换；启用时，Autoswitch 会取代 Use 的位置，再次单击它会恢复为通知。添加数字可更改阈值，如 `omarchy agent account mode auto 90`。如果每个帐户都超过了阈值，你只会收到一次通知，并告知哪个帐户最先释放额度。当活动帐户距离其阈值在 15 个点以内时（默认值下为 80%），其限额会每三分钟检查一次，而不是每 15 分钟。

`omarchy agent account list` 显示每个帐户及其最新限额，`omarchy agent account remove work` 忘记一个帐户，`omarchy agent account rename primary Hey` 重命名一个帐户（或单击面板中某个帐户的名称）。这些命令适用于你的默认智能体的帐户；要访问另一个提供商，请先命名它，如 `omarchy agent account use codex side`。你在 `~/.claude` 或 `~/.codex` 中已有的登录是 _Main_ 帐户，并保留在原处。超过约八小时未使用的帐户可能会显示_需要登录_；单击它可直接在面板中重新登录该帐户，或在其中启动一个会话，它会自行刷新登录。你在添加某个帐户时拥有的 MCP 服务器会随之转移到该帐户，但你后来使用 `claude mcp add` 添加的服务器只会进入你添加它们时所在的帐户。Claude Desktop 以及使用 CLI 二进制文件的绝对路径配置的工具不会跟随切换。显式的 `CLAUDE_CONFIG_DIR`、`CODEX_HOME` 或 `GROK_HOME` 优先于所选帐户。

### 崩溃诊断

Omarchy 监视 systemd-coredump 以检测进程崩溃。当某个进程发生段错误时，你会收到一条“Process crashed”通知——单击它，崩溃就会连同 Omarchy 的 diagnose-crash 技能一起交给你的默认智能体，该技能会引导智能体从核心转储中查明事实，并决定该崩溃是否值得向上游报告。你也可以使用 `omarchy agent crash <pid>` 对 `coredumpctl list` 中的任何 PID 手动运行它。

该监视默认开启。在_触发器 > 切换 > 崩溃捕获_下将其关闭（或使用 `omarchy toggle crash-capture`），通知就会停止；`omarchy agent crash <pid>` 仍然可以手动使用。

还可以一次静默一个程序的崩溃，这正是诊断最后向你提供的选项。`omarchy crash mute hyprland` 只停止该程序的通知，`omarchy crash mute hyprland off` 将其恢复，单独使用 `omarchy crash mute` 则列出你已静默的内容。它接受二进制文件的路径就像接受其名称一样乐意，因此 `omarchy crash mute /usr/bin/hyprland` 的效果相同。为带有空格的名称加引号，如 `omarchy crash mute 'Some App'`。其他一切仍会通知，被静默的程序仍会崩溃——这只是隐藏了提醒，并不会修复任何问题。

### 桌面应用

_安装 > AI_ 菜单还包含一些图形化 AI 应用：ChatGPT 桌面应用、Claude 桌面应用（Anthropic 的 Linux 测试版，带有 Chat、Cowork 和 Claude Code 标签页）、用于与 xAI 的模型聊天的 Grok Bot、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexity 桌面应用和 T3 Code。Grok Bot 是桌面聊天应用。编程智能体是 `grok` 命令。

Hermes Desktop 是你需要了解的那个，因为一台机器只有一个 Hermes，而它是属于该应用的：Hermes 始终只能通过该应用安装，默认智能体运行的 `hermes` 命令就是该应用的。选择 Hermes 作为默认智能体会安装与_安装 > AI_条目相同的东西：软件包，以及由 Hermes 自己的安装程序在 `~/.hermes` 下设置的 Hermes 运行时，首次安装需要几分钟。该运行时就是终端 `hermes` 命令、默认智能体和应用共同使用的那一个 Hermes，它通过 `hermes update` 自行更新，而不是等待 Omarchy 发布新版本。安装它还会将 Omarchy 主题作为名为 `omarchy` 的皮肤交给 Hermes，当你切换主题时，每个 Hermes 界面都会随之变化；如果你不希望这样，请在 Hermes 的 Appearance 设置下或使用 `/skin` 选择另一个，Omarchy 不会干涉这一选择。在_移除 > AI_下移除该应用会先关闭 Hermes（包括网关在内），把该运行时一同带走，并保留你的聊天、记忆以及 Hermes 为自己编写的技能，除非你另行指示：它会询问，默认为否，是否也要删除这些数据和你的连接设置。

OpenClaw 的桌面体验是其 Control UI，它作为由其自己的本地网关支持的 Web 应用打开。OpenClaw 位于 `~/.openclaw` 并自行更新：使用 Control UI 的“Update Gateway”按钮或运行 `openclaw update`，网关会在新版本上重启。Omarchy 只选择全新安装的起始版本。在_移除 > AI_下移除 OpenClaw 会将其网关服务和应用一同删除，然后询问是否也要删除 `~/.openclaw`，因为那里保存着你的聊天和凭据，以及 OpenClaw 本身和它下载的插件运行时；默认保留它，重新安装 OpenClaw 会将其重新拾起。

Herdr Desktop 是 [Herdr](https://herdr.dev) 桌面应用：由空间、标签页和窗格组成的终端和编程智能体，即使你关闭窗口，它们也会在其核心中继续运行。它来自 Herdr 自己的安装程序而不是软件包，因此它位于 `~/.local/share/herdr-app`，当你还没有核心时，它会带来位于 `~/.local/bin/herdr-core` 的核心，并自行更新这两者。它位于 Omarchy 在 `Super + Ctrl + Return` 上提供的 `herdr` 命令旁边，而不是替换它，并获得该命令的直接按键：`Alt + Return` 和 `Alt + Shift + Return` 向下或向右拆分窗格，`Alt + Escape` 关闭窗格，`Ctrl + Alt + Arrow` 在窗格之间移动，`Alt + 1..9` 和 `Alt + Left/Right` 选择标签页，`Alt + Up/Down` 在空间之间移动。`Ctrl + 1..9` 选择空间，`Alt + Shift + Up/Down` 逐步切换智能体。`Ctrl + Space` 前缀按键仅保留在终端中，因为应用无法为一个序列按住普通的 Ctrl 键。Omarchy 将这些写入 `~/.config/herdr-app/keys.json`，`omarchy-refresh-herdr-app` 会将其恢复。安装它会选择 Herdr 的 Omarchy 主题，从那时起它会跟随你的 Omarchy 主题。Herdr 为浅色模式保留一个主题，为深色模式保留一个，因此在深色和浅色 Omarchy 主题之间切换后，请在 Herdr 的主题选择器中再次为另一种模式选择 Omarchy。

T3 Code 从其位于 `~/.local/share/t3code` 的官方 AppImage 版本运行，而不是从软件包运行，因此它会自行更新。安装它时会询问是启动 Stable 频道还是 Nightly 频道；稍后可在 T3 Code 的设置中切换。你的线程和设置位于 `~/.t3`，在_移除 > AI_下移除 T3 Code 会将其一同删除。

### 本地模型

在你自己的机器上为你的编程智能体运行开放模型。你的提示和代码保留在机器上；发送给模型的任何内容都不会离开它。从以下命令开始：

```bash
omarchy agent local use best
```

或者，在顶栏的智能体面板中，选择 + 然后选择 Local AI，当有模型适合这台机器时，它就会出现。首次使用时，这会安装 Podman，Podman 负责运行模型，在 NVIDIA 机器上还会安装 NVIDIA 的容器工具包，为模型提供 GPU。然后 Omarchy 会为这台机器挑选推荐模型，下载它，并启动它。预计下载量为数十 GB，并且在模型运行时机器的大部分内存会被占用：Flash Next 在其完整的 256K 上下文下使用约 100 GiB。如果其他模型占用了它所需的内存，它会被设置为已停止状态，准备在你停止一个模型后启动。该模型在注销时停止；当你需要内存用于其他用途时，请自行停止它。

`omarchy agent local list` 显示选项，并解释为什么有些不适合。要设置另一个，请运行 `omarchy agent local use <recipe>`。如今，`qwen3.8-flash-next-gufo` 和 `qwen3.8-27b-gufo` 可用于 128 GB Strix Halo 机器；27B 约占用 40 GiB，因此它为其他工作留出了空间。新的配方和推荐会通过软件包随 `omarchy update` 到来。

你设置的每个模型在智能体面板中都会有自己的一行，紧邻你的订阅：播放以启动它，暂停以停止它并释放其内存，终端按钮可在其上打开你的智能体。当它们能一起装入内存时，多个模型可以同时运行；如果一个放不下，Omarchy 会说明要停止哪个正在运行的模型。拖动行可重新排序，按 Delete 删除选定的行可移除一个模型及其下载。

从命令行，`omarchy agent local start <recipe>` 和 `omarchy agent local stop <recipe>` 做同样的事，`omarchy agent local status` 显示每个模型，`omarchy agent --local` 在你上次启动的模型上打开你的默认智能体。pi、OpenCode 和 Qwen Code 可以使用其中一个；使用任何其他默认智能体时，它会在 pi 中打开。pi 还会在其自己的模型选择器中列出你设置的每个模型，以及在你已配对的机器上的模型，因此普通的 `pi` 也可以访问它们。任何与 OpenAI 兼容的客户端也可以连接：`status` 显示每个模型的地址（第一个是 `http://127.0.0.1:11435/v1`），配方名称就是模型，密钥位于 `~/.config/omarchy/agent-local/key`。

`omarchy agent local remove <recipe>` 删除一个模型以及没有其他模型使用的下载。

第三方运行时会标有其发布者。Omarchy 在无网络访问的情况下运行每个模型。

### 本地 LLM

Omarchy 推荐两种运行本地 LLM 模型的方式：LM Studio 和 Ollama。LM Studio 提供 GUI 界面，用于查找开放权重模型、安装它们并运行它们。这是轻松入门的好方法。Ollama 提供 CLI 以类似方式做到这一点。但如果你是本地模型的新手，我会从 LM Studio 开始。你可以在 Omarchy 菜单的_安装 > AI_下安装其中任何一个。

### Omarchy 技能

智能体技能帮助 AI 以特定方式使用特定工具，Omarchy 自带一个用于定制系统的默认技能。比如调整你的 Hyprland 配置、调整顶栏，甚至从头创建一个新主题。它被符号链接到 Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` 和每个 `~/.hermes/profiles/*/skills`）以及通用的 `~/.agents/skills` 位置的技能目录中，因此大多数 harness 都会自动拾取它。

但你应该把这项技能视为实验性的。不同的模型对它的使用效果会有所不同。最好先在计划模式下运行，这样你就能了解智能体想要更改什么。然后准备好回滚更改，甚至调用 `omarchy reinstall configs`，如果智能体把一切弄得一团糟。
