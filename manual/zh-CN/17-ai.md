### 安装和更新智能体

Hermes 和 OpenClaw 除外，这些智能体使用 mise 的延迟安装：首次启动时安装 CLI，之后的启动会重复使用它。mise 还最多每四小时检查一次已安装智能体是否有新版本，就在它启动之前，或在 shell 提示符下在后台检查。如果该更新失败或你处于离线状态，则运行已安装的版本。`omarchy update` 会随 Omarchy 的其余部分一起更新已安装的智能体，而 `mup` 只更新由 mise 管理的工具。

智能体自己的更新程序，例如 `claude update`、`codex update`，或应用中的更新按钮，不会更新由 mise 管理的安装。`codex update` 会失败，而 `claude update` 可能会报告成功，却安装了一个 mise 不跟踪的单独副本。如果你更愿意使用智能体原生的安装程序和更新程序，请将其添加到 `disable_tools`；请参阅[预装的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

要在需要之前安装所有已配置的延迟工具，请运行 `mise install --include-lazy`。这包括 Omarchy 的其他默认 CLI 工具以及这些智能体。有关安装单个工具或使用你自己的安装，请参阅[预装的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

`grok` 通过 mise 的第一方 `grok` 包安装，与 `claude` 和 `codex` 的方式相同。运行 `grok`，或在智能体面板中为它加星标。跳过 x.ai 上的 `curl | bash` 安装程序。那条路径会在 `~/.grok/bin` 中放入第二个副本，将其前置到 `PATH` 上，并覆盖 Omarchy 的包装器。

`dsh` 在 `127.0.0.1:3080` 上打开其浏览器 UI，并以启动目录作为其默认工作区。它的浏览器 UI 不接受起始提示词，所以 `omarchy agent prompt` 打开它时，会把提示词放在你的剪贴板上供你粘贴。Omarchy 以 DeepSeek 的无批准权限预设启动它。当你使用 DeepSeek 的官方模型 API 时，DeepSeek Harness 会将会话日志上传到 DeepSeek；在其浏览器 UI 的 _Settings > General > Upload Session Log_ 下关闭此项。你发送给它的反馈也会随会话一起上传，除非你以 `DSH_TELEMETRY_MODE=DISABLED` 启动它。

### 默认智能体

用智能体面板中某个智能体旁边的星标来选择你的默认智能体，默认智能体上的星标是实心的；或者用 `omarchy default agent <name>`，它也接受那里没有单独一行的任何 harness。如果该智能体尚未安装，选择它会先安装它，而且它还会在应用启动器中获得自己的启动器，位于 Agent 旁边。全新的 Omarchy 会通过一次性通知邀请你设置一个，该通知会打开智能体面板。

选择 Claude 还会尝试为 Chromium、Chrome、Brave、Brave Origin 和 Edge 设置它的浏览器扩展。该扩展设置适用于所有用户，并且可能会要求你输入系统密码；取消或扩展安装失败仍然会选择并启动 Claude。重启你的浏览器，如有提示则启用该扩展，并登录 Claude 以完成连接。在 Claude 中运行 `/chrome` 来检查连接。Firefox 和 Zen 不支持此扩展。如果在此设置被添加之前 Claude 已经是你的默认项，请再次选择它以安装该扩展。

选择之后，`Super + Shift + Ctrl + A` 会在专用终端窗口中启动默认智能体（或者，如果你尚未选择，则调出选择器）。你也可以用 `omarchy agent prompt "Review this project"` 直接让它进入一项任务。Freebuff 和 DeepSeek Harness 不接受起始提示词，所以它们打开时改为把提示词放在你的剪贴板上供你粘贴。以这种方式启动的智能体会在各自的不停下来询问的模式下无人值守地运行，所以要做好它们真的会动手做事的准备！MiniMax Code 的交互式会话没有这种模式，所以它会照常请求权限。而且，由于智能体会拒绝记住对你主目录的信任，从 `$HOME` 启动时改为在 `~/Work` 中开始。

还有终端快捷方式：`a` 在当前终端中内联运行默认智能体，而 `c`、`cx` 和 `cy` 直接启动 OpenCode、Claude Code 和 Codex（同样是在它们的自动批准模式下）。主题更改也会同步到智能体：当你切换 Omarchy 主题时，Claude Code、Pi、OpenCode 和 Hermes（一旦 Omarchy 已安装它）都会随之跟随。

### 你的智能体指令

适用于每个智能体的个人规则放在 `~/.agents/AGENTS.md` 中，紧挨着 `~/.agents/skills` 中的共享技能。用智能体面板中 + 旁边的文档图标打开它，或者用 `omarchy agent instructions --edit`，它还会将其链接到每个保留自己全局文件的 harness 中：`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`~/.pi/agent/AGENTS.md`、`~/.config/opencode/AGENTS.md`、Copilot 的 `~/.copilot/copilot-instructions.md`，等等。Crush 和 Amp 读取 `~/.config/AGENTS.md` 链接，而 omp、Kimi 和 DeepSeek Harness 直接读取 `~/.agents/AGENTS.md`。选择默认智能体时也会链接它。如果你已有的指令文件在尚没有共享文件时，会成为共享文件；否则它会以 `.bak` 的形式保留在链接旁边。安装另一个智能体后，运行 `omarchy agent instructions` 重新链接。

### 智能体面板

顶栏有一个智能体图标。在你设置智能体之前，它的面板提供了三种开始方式：登录 Claude、Codex、Grok、Gemini、Muse、Cursor 或 Copilot 订阅，或者在“更多”下登录 OpenCode Go、MiniMax、Synthetic 或 Z.ai 编程套餐；通过 Fireworks、OpenCode Zen and Go、OpenRouter 按用量付费，或者在“更多”下通过 DeepSeek 或 OpenCode 可登录的任何其他提供商，它们都在 OpenCode 中运行；或者在有一款适合你的计算机时，运行最适合它的模型。你完成的第一个会成为你的默认智能体，面板中的 + 之后会提供同样的三种方式。之后，该面板会把每个订阅都放在一页上：每个智能体和账户及其套餐，每个智能体的 5 小时会话限额和每周限额各有一个计量条，并显示距离重置的时间（悬停查看确切百分比），或剩余的预付余额，上面还有一行轮流显示你在所有这些智能体上的使用情况，例如本周的 token 数和你最常用的模型。在 _Make something cool_ 下，它为新主题、插件、应用或游戏提供起始提示词，把任务交给你的默认智能体。应用的构建方式与 Omarchy 自己的 Hype、Monologue 和 Omacut 相同，用 C++ 和 Qt Quick，遵循 omarchy-make-app 智能体技能，它们需要的编译器和 Qt 组件都已安装。游戏是 `~/Games/vibes` 中单个的 three.js 页面，遵循 omarchy-make-game 智能体技能，并且全都从当前主题中的一个 Game Vibes 启动器打开；它们从网络加载 three.js，所以开始时需要网络连接。Claude Code、Codex、Grok、Kimi、Cursor 及其 Grok Bot 额度、GitHub Copilot、Muse、Gemini（通过 Antigravity）和 Devin 都开箱即用地涵盖了它们的限额，Kimchi 涵盖其套餐、预付额度和支出预算，Hermes、Mistral Vibe 和 Qwen Code 则会在你使用过它们后显示其会话和 token。你通过 pi、omp 或 opencode 使用的提供商套餐和密钥也会显示：OpenCode Zen and Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan 和 Synthetic 及其限额；OpenRouter 和 DeepSeek 及其预付余额；Fireworks 及其过去 30 天的支出。你在自己的硬件上运行的模型的 token 也计入总计；模型本身有自己的面板，在[本地模型](#local-models)下有说明。每个智能体只计一次，归到向它收费的一方名下，无论你通过多少个 harness 来驱动它。

左键单击栏图标或按 `Super + Ctrl + X` 打开面板，右键单击启动你的默认智能体，中键单击刷新。它背后的使用记录每 15 分钟由 `omarchy agent usage update` 重新生成，并且该面板甚至可以通过同步文件夹合并来自你其他机器的使用情况。有关完整设置，请参阅 `$OMARCHY_PATH/shell/plugins/agents/` 下的 README。

### 多个订阅

如果你付费购买了不止一个 Claude、Codex 或 Grok 套餐——比如一个个人 Max 和一个工作套餐——Omarchy 可以让它们全部保持登录状态，并在它们之间切换。用智能体面板中的 + 添加订阅，它会直接在那里引导你完成，或者用 `omarchy agent account add claude Work`（或 `codex`，或 `grok`）。同样的 + 和命令可登录 Gemini（`gemini`）和 OpenCode（`opencode`），并在 OpenCode 中保存 Fireworks（`fireworks`）或 OpenRouter（`openrouter`）API 密钥；该命令还可登录 Copilot（`copilot`）、Cursor（`cursor`）和 Muse（`muse`）。这些各自只保留一个登录。它会在 CLI 缺失时安装它。提供商的第一个账户通过你的普通浏览器登录，就在 CLI 一直查找的地方。之后的每一个都通过隐私窗口登录，所以你浏览器已经登录的账户不会被误选；在那里以你要添加的账户登录，并先关闭你已打开的任何隐私窗口。千万不要为此退出 CLI：退出登录会撤销已保存的登录，该账户将不得不重新添加。

要通过 SSH 将你的订阅登录复制到另一台 Omarchy 机器，请运行 `omarchy agent account copy user@laptop`。当目标机器没有安装接收器时，发送方会提供一个临时接收器，所以较旧的 Omarchy 机器无需更新即可接收账户。已安装的接收器优先。此命令会复制所有 Claude、Codex 和 Grok 订阅；添加提供商名称来选择它们，如 `omarchy agent account copy laptop claude`。账户名称和命令 ID 与源机器一致，包括目标机器上已存在的账户。如果名称冲突，无关的目标账户会获得数字后缀，设置、技能、插件和对话历史则保留在每台机器本地。

目标机器上现有的凭据会保留。已在那里登录的源账户会同步其名称，但不会替换其凭据；其他账户会添加在它旁边。要替换匹配账户的已保存凭据，请在退出目标机器上该账户的会话后，使用 `omarchy agent account copy --replace laptop claude`。全新的目标机器还会获得源机器的活动账户和切换偏好；已建立的目标机器则保留自己的。

凭据通过 SSH 传输，并存储在目标机器的私有文件中，所以只复制到你信任的机器。这是一次性复制，不是持续同步。Codex 刷新 token 可能会被另一台机器轮换，导致复制的登录需要续期；在多台机器上同时使用时，单独登录仍然是最可靠的选择。请参阅 [Codex 的账户身份验证指南](https://developers.openai.com/codex/auth/ci-cd-auth)。

每个提供商只有一个账户处于活动状态，每个新会话都以它开始：`cx`、`cy`、普通的 `claude`、`codex` 或 `grok`、通过 `omarchy agent` 启动的任何东西，以及在 `PATH` 上找到 CLI 的脚本或编辑器。用 `omarchy agent account use work` 切换（用 `omarchy agent account use main` 切回），或者在面板中按某个账户的数字然后按 `Enter`（或单击它的星标）。正在运行的 Claude 会话也会切换，从它们的下一条消息开始：每个 Claude 会话都在 `~/.claude` 中运行，该目录始终保存活动账户的登录。由较旧 Omarchy 在账户自己的文件夹中启动的 Claude 会话会保留该登录直到退出，所以切换时会列出这些会话，并在它们消失后自行完成。正在运行的 Codex 和 Grok 会话会停留在它们启动时使用的账户上。对话历史、设置、技能和插件在账户之间共享，所以在同一文件夹中 `claude --continue` 会在新账户上从你离开的地方继续。

当有多个账户时，面板会并排显示每个账户的限额，正在使用的那个上面有实心星标。当活动账户超过某个限额的 95% 时，Omarchy 会通知你，单击该通知会切换到余量最多的账户。它永远不会自行切换。用 `omarchy agent account threshold 90` 更改阈值。如果每个账户都超过了阈值，你会收到一次通知，并告知哪个账户最先释放。当活动账户距离其阈值在 15 个百分点以内时（默认值为 80%），它的限额会每三分钟检查一次，而不是每 15 分钟。

`omarchy agent account list` 显示每个账户及其最新限额，`omarchy agent account remove work` 忘记一个账户，`omarchy agent account rename primary Hey` 重命名一个账户（或在面板中单击某个账户的名称）。这些命令作用于你的默认智能体的账户；要访问另一个提供商，请先命名它，如 `omarchy agent account use codex side`。你已经在 `~/.claude` 或 `~/.codex` 中拥有的登录是 _Main_ 账户。Codex 的账户留在原处；Claude 的账户在另一个账户活动时会等待在它自己的文件夹中。闲置超过约八小时的账户可能会显示 _Sign-in required_；单击它可直接在面板中重新登录该账户，或者切换到它并启动一个会话，这会自动刷新登录。用 `claude mcp add` 添加的 MCP 服务器可到达每个 Claude 账户，因为它们都在 `~/.claude` 中运行；对于 Codex 和 Grok，你在添加某个账户时拥有的服务器会随它一起过去，但后来的服务器只能到达你添加它们时所在的账户。Claude Desktop 保留自己的登录，而配置了指向某个 CLI 二进制文件的绝对路径的 Codex 或 Grok 工具不会跟随切换。显式的 `CLAUDE_CONFIG_DIR`、`CODEX_HOME` 或 `GROK_HOME` 优先于所选账户。

### 崩溃诊断

Omarchy 监视 systemd-coredump 以发现进程崩溃。一旦你选择了默认智能体，你的任何程序发生核心转储时都会带来一个“进程已崩溃”通知——单击它，崩溃就会连同 Omarchy 的 omarchy-diagnose-crash 技能一并交给你的默认智能体，该技能会引导智能体从核心转储中查明事实，并决定该崩溃是否值得向上游报告。你也可以用 `omarchy agent crash <pid>` 对 `coredumpctl list` 中的任何 PID 手动运行它。

此监视默认开启。在 _Trigger > Toggle > Crash Capture Off_ 下关闭它（或用 `omarchy toggle crash-capture`），通知就会停止；`omarchy agent crash <pid>` 仍然可以手动使用。

也可以一次静默一个程序的崩溃，诊断结束时就会向你提供这一选项。`omarchy crash mute hyprland` 只停止该程序的通知，`omarchy crash mute hyprland off` 将它们恢复，单独使用 `omarchy crash mute` 则列出你已静默的内容。它接受二进制文件的路径就像接受其名称一样高兴，所以 `omarchy crash mute /usr/bin/hyprland` 做的是同样的事情。给带空格的名称加引号，如 `omarchy crash mute 'Some App'`。其他一切仍会通知，被静默的程序仍会崩溃——这只是隐藏提醒，并不能修复任何东西。

### 桌面应用

_Install > AI_ 菜单还包含一些图形化 AI 应用：Amp Desktop、Antigravity Desktop、ChatGPT 桌面应用、Claude 桌面应用（Anthropic 的 Linux 测试版，带有 Chat、Cowork 和 Claude Code 选项卡）、用于与 xAI 的模型聊天的 Grok Bot、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexity 桌面应用和 T3 Code。Grok Bot 是桌面聊天应用。编程智能体是 `grok` 命令。

Hermes Desktop 是需要了解的那个，因为一台机器上只有一个 Hermes，而且它属于该应用：Hermes 只通过该应用安装，默认智能体运行的 `hermes` 命令也是该应用的。选择 Hermes 作为默认智能体会安装与 _Install > AI_ 条目相同的东西：该软件包，以及一个由 Hermes 自己的安装程序在 `~/.hermes` 下设置的 Hermes 运行时，首次安装需要几分钟。这个运行时就是终端 `hermes` 命令、默认智能体和该应用全都使用的那一个 Hermes，它用 `hermes update` 自行更新，而不是等待 Omarchy 发布新版本。安装它还会把 Omarchy 主题作为名为 `omarchy` 的皮肤交给 Hermes，当你切换主题时，每个 Hermes 界面都会跟随；在 Hermes 的 Appearance 设置下或用 `/skin` 选择另一个，如果你不想让它这样，Omarchy 会让那个选择保持不变。在 _Remove > AI_ 下删除该应用时，会先关闭 Hermes，包括网关，并把该运行时一并带走，同时保留你的聊天、记忆和 Hermes 为自己编写的技能，除非你另行告知：它会询问，默认为否，是否也删除该数据和你的连接设置。

OpenClaw 的桌面体验是它的 Control UI，它以由自己的本地网关支持的 Web 应用形式打开。OpenClaw 位于 `~/.openclaw` 中并自行更新：使用 Control UI 的“Update Gateway”按钮或运行 `openclaw update`，网关就会在新版本上重启。Omarchy 只选择全新安装从哪个版本开始。OpenClaw 也可以是你的默认智能体：用 `omarchy default agent openclaw` 选择它，会在 `~/.openclaw` 中设置同一个副本，智能体会打开连接到其网关的 OpenClaw 终端 UI。在 _Remove > AI_ 下删除 OpenClaw 会把网关服务和该应用一并带走，然后询问是否也删除 `~/.openclaw`，因为那里保存着你的聊天和凭据，以及 OpenClaw 本身和它下载的插件运行时；默认会保留它，再次安装 OpenClaw 时会重新拾起它。

Herdr Desktop 是 [Herdr](https://herdr.dev) 桌面应用：由空间、选项卡以及终端和编程智能体的窗格组成，当你关闭窗口时，它们在它的核心中继续运行。它来自 Herdr 自己的安装程序而不是软件包，所以它位于 `~/.local/share/herdr-app` 中，当你还没有时，会在 `~/.local/bin/herdr-core` 中带来它的核心，并自行更新这两者。它与 Omarchy 在 `Super + Ctrl + Return` 上提供的 `herdr` 命令并存，而不是替换它，并获得该命令的直接按键：`Alt + Return` 和 `Alt + Shift + Return` 向下或向右拆分窗格，`Alt + Escape` 关闭窗格，`Ctrl + Alt + Arrow` 在窗格之间移动，`Alt + 1..9` 和 `Alt + Left/Right` 选择选项卡，`Alt + Up/Down` 在空间之间移动。`Ctrl + 1..9` 选择空间，`Alt + Shift + Up/Down` 在智能体之间步进。`Ctrl + Space` 前缀按键保持只在终端中使用，因为该应用不能用一个普通的 Ctrl 键来保持一个序列。Omarchy 将这些写入 `~/.config/herdr-app/keys.json`，而 `omarchy-refresh-herdr-app` 会把它们放回去。安装它会选择 Herdr 的 Omarchy 主题，从那时起它会跟随你的 Omarchy 主题。Herdr 为浅色模式保留一个主题，为深色模式保留一个，所以在深色和浅色 Omarchy 主题之间切换后，请在 Herdr 的主题选择器中为另一种模式再选择一次 Omarchy。

T3 Code 从它在 `~/.local/share/t3code` 中的官方 AppImage 版本运行，而不是从软件包运行，所以它自行更新。安装它时会询问是从 Stable 还是 Nightly 频道开始；之后在 T3 Code 的设置中切换。你的线程和设置位于 `~/.t3` 中，在 _Remove > AI_ 下删除 T3 Code 会把它们一并带走。

### 本地模型

在你自己的机器上为你的编程智能体运行一个开放模型。你的提示词和代码留在机器上；发送给模型的任何东西都不会离开它。从以下命令开始：

```bash
omarchy models use best text
```

这会为这台机器设置最佳的文本模型，就是你的智能体使用的那种。图像、视频和音乐模型各有自己的最佳选择：`omarchy models use best image`、`video` 或 `music`。运行 `omarchy models use best` 查看每种类型为这台机器选择的那一个。

或者从顶栏中智能体图标旁边的闪烁图标打开本地模型面板，或用 Super + Ctrl + Alt + X，然后选择 +。当有一款模型适合这台机器时，该图标会出现。运行这些模型的 Podman 随 Omarchy 一同提供，NVIDIA 机器上的 NVIDIA 容器工具包也是如此，它为它们提供 GPU；如果其中任何一个缺失，首次设置会安装它。然后 Omarchy 会为这台机器选择推荐的模型，下载它，并启动它。预计下载量为数十 GB，并且模型运行时机器的大部分内存都会被占用：Flash Next 在其完整的 256K 上下文下使用约 100 GiB。如果其他模型占用了它需要的内存，它会被设置为停止状态，准备在你停止一个模型后开始。该模型在注销时停止；当你需要内存做别的事情时，请自行停止它。

`omarchy models list` 显示这些选项，并解释为什么有些不适合。要设置另一个，请运行 `omarchy models use <recipe>`。如今，`qwen3.8-flash-next-gufo` 和 `qwen3.8-27b-gufo` 可用于 128 GB Strix Halo 机器；27B 占用约 40 GiB，所以它为其他工作留出了空间。在配备 Intel Arc B390 的 64 GB 笔记本电脑上，`qwen3.6-35b-a3b-llamacpp` 在约 30 GiB 中运行。新的配方和推荐通过软件包随 `omarchy update` 一同到来。

你设置的每个模型都会在本地模型面板中获得自己的一行：播放可启动它，暂停可停止它并释放其内存，终端按钮可在它上面打开你的智能体。顶部有一条横条，显示机器的内存如何在 Omarchy 本身（系统和你的应用）、每个运行中的模型和空闲部分之间分配。指向一个已停止的模型，横条会显示它是否适合，或者还差多少。几个模型可以在它们同时适合内存时一起运行；如果一个不适合，Omarchy 会告诉你应停止哪个运行中的模型。拖动行上的标志可重新排序，按 Delete 键在所选行上可删除一个模型及其下载内容。

你设置的每个编程模型还会在应用启动器中获得自己的条目，位于该模型的名称下并带有其制造者的标志，就像登录 Claude、Codex 或 Grok 会添加一个一样。它在该模型上打开你的智能体，如果它没有运行，会先启动该模型：终端会显示它正在加载，并在它就绪后交给智能体。删除一个模型会删除它的条目。

并非每个模型都是为编程而设的。图像、视频和音乐模型改为在 Fantasi 中打开，Fantasi 是 Omarchy 用于在该机器上运行的模型制作图片、视频和音乐的应用，在那里或从它们在本地模型面板中的那一行选择。

模型会完全按照它被设置的方式继续运行，所以 Omarchy 更新永远不会在你的智能体之下重启一个模型。当 Omarchy 为你已设置的模型提供了更新的运行时或更新的权重时，它的那一行会显示一个更新按钮：按下它，该模型会在后台重新设置，只下载已更改的内容，并在新版本上重启。已停止的模型会保持停止状态。`omarchy models update` 从终端对每个模型做同样的事情。

从命令行，`omarchy models start <recipe>` 和 `omarchy models stop <recipe>` 做同样的事情，`omarchy models status` 显示每个模型，而 `omarchy agent --local-model <recipe>` 在 pi 中打开该模型，无论你的默认智能体是什么。要让你的本地模型成为智能体快捷键、Quake 控制台和 _Make something_ 打开的对象，请运行 `omarchy default agent local`，或在智能体面板中为一个运行中的模型加星标。pi 还会在它自己的模型选择器中列出你已设置的每个模型，以及你已配对的机器上的模型，所以普通的 `pi` 也能访问它们。任何与 OpenAI 兼容的客户端也可以连接：`status` 显示每个模型的地址（第一个是 `http://127.0.0.1:11435/v1`），配方名称就是模型，密钥在 `~/.config/omarchy/agent-local/key` 中。

`omarchy models remove <recipe>` 删除一个模型以及没有其他模型使用的下载内容。

第三​​方运行时标有它们的发布者。Omarchy 在没有网络访问的情况下运行每个模型。

### 本地 LLM

Omarchy 推荐两种运行本地 LLM 模型的方式：LM Studio 和 Ollama。LM Studio 提供了用于查找开放权重模型、安装它们并运行它们的 GUI 界面。这是个轻松上手的好方法。Ollama 提供了类似的 CLI。但如果你是本地模型新手，我会从 LM Studio 开始。你可以在 Omarchy 菜单的 _Install > AI_ 下安装其中任何一个。

### Omarchy 技能

智能体技能帮助 AI 以特定方式使用特定工具，Omarchy 附带了其中七个。omarchy 技能涵盖定制系统，例如调整你的 Hyprland 配置或调整栏。omarchy-make-theme、omarchy-make-plugin、omarchy-make-app 和 omarchy-make-game 涵盖制作新东西，omarchy-contribute 涵盖报告 bug 或向上游发送修复，而 omarchy-diagnose-crash 则处理崩溃的核心转储。它们被符号链接到 Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` 和每个 `~/.hermes/profiles/*/skills`）的技能目录，以及通用的 `~/.agents/skills` 位置，所以大多数 harness 都会自动拾起它们。你自己的同名技能文件夹优先。

但你应该把这些技能视为实验性的。不同的模型使用它的效果会有所不同。最好先在规划模式下运行，这样你就能知道智能体想改什么。然后准备好回滚更改，甚至调用 `omarchy reinstall configs`，如果智能体把一切都搞得一团糟的话。
