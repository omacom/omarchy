### 安装和更新 agent

除 Hermes 外，这些 agent 都使用 mise 的延迟安装：首次启动时安装 CLI，后续启动则复用已安装版本。mise 还会至多每四小时检查一次已安装 agent 是否有新版本，检查时机就在它启动之前，或在 shell 提示符下于后台进行。如果更新失败或你处于离线状态，就会运行已安装的版本。`omarchy update` 会随 Omarchy 的其余部分一起更新已安装的 agent，而 `mup` 仅更新由 mise 管理的工具。

某个 agent 自带的更新器，例如 `claude update`、`codex update`，或应用中的更新按钮，不会更新由 mise 管理的安装。`codex update` 会失败，而 `claude update` 可能报告成功，却安装了一个 mise 并不追踪的独立副本。如果你更想使用某个 agent 的原生安装器和更新器，请将其加入 `disable_tools`；参见[预装 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

要在需要之前安装所有已配置的延迟工具，请运行 `mise install --include-lazy`。这包括 Omarchy 的其他默认 CLI 工具以及这些 agent。有关安装单个工具或使用你自己的安装方式，请参见[预装 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

`grok` 通过 mise 的第一方 `grok` 包安装，与 `claude` 和 `codex` 的方式相同。运行 `grok`，或在 _Setup > Defaults > Agent_ 下选择它。跳过 x.ai 上的 `curl | bash` 安装器。那条路径会在 `~/.grok/bin` 中放置第二个副本，将其前置到 `PATH` 上，并覆盖 Omarchy 的包装器。

`dsh` 会在 `127.0.0.1:3080` 打开其浏览器 UI，并将启动目录作为其默认工作区。其浏览器 UI 不接受起始提示词，因此 `omarchy agent prompt` 打开它时，会将提示词放到你的剪贴板上以便粘贴。Omarchy 以 DeepSeek 的无审批权限预设启动它。DeepSeek Harness 在你使用其官方模型 API 时会将会话日志上传到 DeepSeek；在其浏览器 UI 的 _Settings > General > Upload Session Log_ 下可关闭此功能。你发送给它的反馈也会随会话一同上传，除非你以 `DSH_TELEMETRY_MODE=DISABLED` 启动它。

### 默认 agent

使用 `omarchy default agent <name>` 或在 Omarchy Menu（`Super + Space`）的 _Setup > Defaults > Agent_ 下选择你的默认 agent。如果该 agent 尚未安装，选择它时会先进行安装。全新安装的 Omarchy 会通过一次性通知邀请你作出这一选择。

选择 Claude 还会尝试为 Chromium、Chrome、Brave、Brave Origin 和 Edge 设置其浏览器扩展。该扩展的设置适用于所有用户，且可能要求输入你的系统密码；取消或扩展安装失败仍会选定并启动 Claude。重启你的浏览器，在提示时启用该扩展，并登录 Claude 以完成连接。在 Claude 中运行 `/chrome` 检查连接状态。Firefox 和 Zen 不支持此扩展。如果在此设置功能加入之前 Claude 就已经是你的默认项，请重新选择它以安装该扩展。

选定之后，`Super + Shift + Ctrl + A` 会在一个专用终端窗口中启动默认 agent（如果你尚未选择，则会调出选择器）。你也可以用 `omarchy agent prompt "Review this project"` 让它直接着手一项任务。Freebuff 和 DeepSeek Harness 不接受起始提示词，因此它们打开时改为将提示词放到你的剪贴板上以便粘贴。以这种方式启动的 agent 会在各自的不停下来询问的模式下无人值守地运行，所以请做好准备，它们真的会动手做事！MiniMax Code 的交互式会话没有这种模式，因此它会照常请求权限。另外，由于 agent 拒绝记住对你的主目录的信任，从 `$HOME` 启动时会改为在 `~/Work` 中启动。

还有终端快捷方式：`a` 在当前终端中内联运行默认 agent，而 `c`、`cx` 和 `cy` 则直接启动 OpenCode、Claude Code 和 Codex（同样处于各自的自动批准模式）。主题变更也会同步到这些 agent：当你切换 Omarchy 主题时，Claude Code、Pi、OpenCode 和 Hermes（一旦 Omarchy 已安装它）都会随之变化。

### agent 面板

顶栏有一个 agent 图标。在你设置好某个 agent 之前，它的面板会引导你登录 Claude、Codex 或 Grok，第一个登录的会成为你的默认 agent。在那之后，该面板会将每个订阅都放在同一页面上：每个 agent 和账户及其套餐、其 5 小时会话限额和每周限额各自的计量条以及距离重置的时间（悬停可查看确切百分比），或剩余的预付余额，上方还有一行轮流显示你在所有这些服务上的使用情况，例如本周的 token 用量和你最常用的模型。在 _Make something_ 下，它提供用于新主题、插件或应用的起始提示词，将任务交给你的默认 agent。应用的构建方式与 Omarchy 自家的 Hype、Monologue 和 Omacut 相同，使用 C++ 和 Qt Quick，遵循 omarchy-app agent skill，并且它们所需的编译器和 Qt 组件都已预装。Claude Code、Codex、Grok、Kimi、Cursor 及其 Grok Bot 额度、GitHub Copilot、Muse、Antigravity、Kimchi 和 Devin 开箱即用地涵盖了它们的限额信息，而 Hermes、Mistral Vibe 和 Qwen Code 会在你使用过它们之后显示其会话和 token 用量。你通过 pi、omp 或 opencode 使用的提供商套餐和密钥也会显示出来：OpenCode Zen 和 Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan 以及 Synthetic，连同它们的限额；Fireworks、OpenRouter 和 DeepSeek，连同它们的预付余额；以及你在自有硬件上运行的模型，归在 Local models 下。每个 agent 只计数一次，归到向你收费的那一家名下，无论你通过多少个 harness 来驱动它。

左键点击顶栏图标打开面板，右键点击启动你的默认 agent。其背后的用量记录由 `omarchy agent usage-update` 每 15 分钟重新生成一次，并且该面板甚至可以通过一个同步文件夹合并来自你的其他机器的用量。完整设置请参见 `$OMARCHY_PATH/shell/plugins/agents/` 下的 README。

### 多个订阅

如果你为不止一个 Claude、Codex 或 Grok 套餐付费——比如一个个人 Max 和一个工作套餐——Omarchy 可以让它们全部保持登录状态并在它们之间切换。用 agent 面板中的 + 添加订阅，它会就在那里引导你完成全过程，或者用 `omarchy agent account add claude Work`（或 `codex`，或 `grok`）。如果 CLI 缺失，它会先安装。某个提供商的第一个账户通过你的普通浏览器登录，正是 CLI 一直查看的位置。此后的每一个账户都通过隐私窗口登录，这样你浏览器中已登录的账户就不会被误选；在那里以你正在添加的账户身份登录，并先关闭你已经打开的任何隐私窗口。千万不要为了做这件事而退出 CLI 登录：退出登录会吊销已保存的登录信息，那个账户将不得不重新添加。

要通过 SSH 将你的订阅登录信息复制到另一台 Omarchy 机器，请运行 `omarchy agent account copy user@laptop`。当目标机器未安装接收器时，发送方会提供一个临时接收器，因此较旧的 Omarchy 机器无需更新也能接收账户。已安装的接收器优先。此操作复制所有 Claude、Codex 和 Grok 订阅；添加提供商名称可选择其中一部分，例如 `omarchy agent account copy laptop claude`。账户名称和命令 ID 与源机器保持一致，包括已存在于目标机器上的账户。若目标机器上不相关的账户出现名称冲突，它们会获得一个数字后缀，而设置、skill、插件和对话历史则保留在各自机器本地。

目标机器现有的凭据会被保留。对于已在那里登录的源账户，其名称会被同步但不会替换其凭据；其他账户则被添加在其旁边。要替换匹配账户的已保存凭据，请先在目标机器上退出该账户的会话，然后使用 `omarchy agent account copy --replace laptop claude`。全新的目标机器还会获得源机器的活动账户和切换偏好；已有配置的目标机器则保留自己的。

凭据通过 SSH 传输，并存储在目标机器的私有文件中，因此只能复制到你信任的机器。这是一次性复制，而非持续同步。Codex 刷新令牌可能会被另一台机器轮换，导致复制的登录信息需要续期；对几台机器上的同时使用而言，各自独立登录仍然是最可靠的选择。参见 [Codex 的账户身份验证指南](https://developers.openai.com/codex/auth/ci-cd-auth)。

每个提供商有一个活动账户，每个新会话都以该账户身份启动：`cx`、`cy`、普通的 `claude`、`codex` 或 `grok`、任何通过 `omarchy agent` 启动的内容，以及在 `PATH` 上找到该 CLI 的脚本或编辑器。使用 `omarchy agent account use work` 切换（用 `omarchy agent account use main` 切回），或在面板中按某个账户的数字键然后按 `Enter`（或点击其 Use 按钮）。已经在运行的会话仍保持在其启动时的账户上。对话历史、设置、skill 和插件在各账户之间共享，因此在同一文件夹中运行 `claude --continue` 会在新账户上从你离开的地方继续。

当有多个账户时，面板会并排显示每个账户的限额，并标记出活动账户。默认情况下，当活动账户超过某个限额的 95% 时，Omarchy 会通知你，点击该通知会切换到余量最多的账户。把指针悬停在面板中某个账户的行上，点击 Use 旁边出现的 Autoswitch（或按 `m`），或运行 `omarchy agent account mode auto`，可让它改为自动切换；开启期间，Autoswitch 会取代 Use 的位置，再次点击则回到仅通知。添加一个数字可更改阈值，例如 `omarchy agent account mode auto 90`。如果每个账户都超过了阈值，你会收到一次通知，并告知哪个账户最先释放额度。当活动账户距离其阈值在 15 个百分点以内时（默认情况下为 80%），其限额会每三分钟检查一次，而不是每 15 分钟一次。

`omarchy agent account list` 显示每个账户及其最新限额，`omarchy agent account remove work` 遗忘一个账户，`omarchy agent account rename primary Hey` 重命名一个账户（或在面板中点击某个账户的名称）。这些命令作用于你的默认 agent 的账户；要触及其他提供商，请先点名它，例如 `omarchy agent account use codex side`。你原本在 `~/.claude` 或 `~/.codex` 中的登录是 _Main_ 账户，会留在原处。一个账户超过约八小时未使用后可能显示 _Sign-in required_；点击它可直接在面板中重新登录该账户，或者在其中启动一个会话，它会自动刷新登录状态。添加某个账户时你已有的 MCP 服务器会随之而来，但之后用 `claude mcp add` 添加的服务器只会到达你添加它们时所在的账户。Claude Desktop 以及用 CLI 二进制的绝对路径配置的工具不会跟随切换。显式设置的 `CLAUDE_CONFIG_DIR`、`CODEX_HOME` 或 `GROK_HOME` 优先于所选账户。

### 崩溃诊断

Omarchy 监视 systemd-coredump 中的进程崩溃。当某个进程出现段错误时，你会收到一个“Process crashed”通知——点击它，崩溃就会连同 Omarchy 的 diagnose-crash skill 一起交给你的默认 agent，该 skill 会引导 agent 从核心转储中查明事实，并决定这次崩溃是否值得向上游报告。你也可以用 `omarchy agent crash <pid>` 手动对 `coredumpctl list` 中的任意 PID 运行它。

该监视默认开启。在 _Trigger > Toggle > Crash Capture_ 下将其关闭（或使用 `omarchy toggle crash-capture`）后，通知就会停止；`omarchy agent crash <pid>` 仍可手动使用。

崩溃也可以按单个程序逐个静默，这正是诊断在最后向你提供的选项。`omarchy crash mute hyprland` 只停止该程序的通知，`omarchy crash mute hyprland off` 恢复通知，而单独的 `omarchy crash mute` 会列出你已静默的内容。它接受二进制文件的路径就像接受其名称一样方便，因此 `omarchy crash mute /usr/bin/hyprland` 效果相同。为包含空格的名称加引号，例如 `omarchy crash mute 'Some App'`。其他一切仍会发通知，而且被静默的程序仍会崩溃——这只是隐藏提醒，并不能修复任何问题。

### 桌面应用

_Install > AI_ 菜单还包含一些图形化 AI 应用：ChatGPT 桌面应用、Claude 桌面应用（Anthropic 的 Linux beta 版，带有 Chat、Cowork 和 Claude Code 标签页）、用于与 xAI 模型聊天的 Grok Bot、Hermes Desktop、OpenClaw、Perplexity 桌面应用，以及 T3 Code。Grok Bot 是桌面聊天应用。编码 agent 则是 `grok` 命令。

Hermes Desktop 是你需要了解的那一个，因为一台机器只有一个 Hermes，而且它属于这个应用：Hermes 只会通过该应用安装，而默认 agent 运行的 `hermes` 命令正是该应用的。选择 Hermes 作为默认 agent 所安装的内容与 _Install > AI_ 条目相同：这个软件包，以及一个由 Hermes 自家安装器在 `~/.hermes` 下设置的 Hermes 运行时，首次安装需要几分钟时间。那个运行时是唯一的 Hermes，终端的 `hermes` 命令、默认 agent 和该应用都使用它，它通过 `hermes update` 自行更新，而不等待 Omarchy 发布新版本。安装它还会把 Omarchy 主题作为一款名为 `omarchy` 的皮肤交给 Hermes，当你切换主题时，Hermes 的每个界面都会随之变化；如果你不希望如此，可在 Hermes 的 Appearance 设置下或使用 `/skin` 选择另一款，Omarchy 不会干涉那个选择。在 _Remove > AI_ 下移除该应用会先关闭 Hermes（包括 gateway），并带走那个运行时，同时保留你的聊天、记忆，以及 Hermes 为自己编写的 skill，除非你另有指示：它会询问（默认为否）那些数据和你的连接设置是否也应该一并删除。

OpenClaw 的桌面体验是其 Control UI，它作为一个 web 应用打开，背后是它自己的本地 gateway。OpenClaw 存放在 `~/.openclaw` 中并自行更新：使用 Control UI 的“Update Gateway”按钮或运行 `openclaw update`，gateway 就会以新版本重启。Omarchy 只决定全新安装从哪个版本开始。在 _Remove > AI_ 下移除 OpenClaw 会带走 gateway 服务和该应用，然后询问 `~/.openclaw` 是否也应该一并删除，因为其中存放着你的聊天和凭据，以及 OpenClaw 本身和它下载的插件运行时；默认会保留它，再次安装 OpenClaw 时会重新接手它。

T3 Code 从其官方 AppImage 版本运行，位于 `~/.local/share/t3code` 中，而非来自某个软件包，因此它自行更新。安装时会询问从 Stable 还是 Nightly 频道开始；之后可在 T3 Code 的设置中切换。你的线程和设置存放在 `~/.t3` 中，在 _Remove > AI_ 下移除 T3 Code 会将它们一并带走。

### 本地模型

在你自己的机器上为你的编码 agent 运行一个开放模型。你的提示词和代码留在机器上；发送给模型的任何东西都不会离开它。从以下命令开始：

```bash
omarchy agent local use best
```

或者，在顶栏的 agent 面板中，选择 + 然后选择 Local AI；当某个模型适合这台机器时它就会出现。首次执行时，这会安装运行模型的 Podman，在 NVIDIA 机器上还会安装 NVIDIA 的容器工具包，让模型能使用 GPU。然后 Omarchy 会为这台机器挑选推荐模型，下载并启动它。预计会有几十 GB 的下载，并且在模型运行时机器的大部分内存会被占用：Flash Next 在其完整的 256K 上下文下使用约 100 GiB。如果其他模型占用了它所需的内存，它会被设置成停止状态，等你停掉某个模型后即可启动。该模型在注销时停止；当你需要把内存用于其他事情时，请自行停止它。

`omarchy agent local list` 显示各个选项，并解释有些为什么不适合。要设置另一个，请运行 `omarchy agent local use <recipe>`。目前，面向 128 GB Strix Halo 机器的有 `qwen3.8-flash-next-halogen` 和 `qwen3.8-27b-gufo` 可用。新的 recipe 和推荐会随 `omarchy update` 通过软件包到来。

你设置的每个模型都会在 agent 面板中拥有自己的一行，紧邻你的订阅：点击播放来启动它，点击暂停来停止它并释放其内存，点击终端按钮在其上打开你的 agent。当它们能同时装进内存时，几个模型可以一起运行；如果某个装不下，Omarchy 会告诉你应停止哪个正在运行的模型。拖动行可重新排序，在选中的一行上按 Delete 可移除某个模型及其下载内容。

在命令行上，`omarchy agent local start <recipe>` 和 `omarchy agent local stop <recipe>` 起同样的作用，`omarchy agent local status` 显示每个模型，`omarchy agent --local` 则在你上次启动的模型上打开你的默认 agent（如果你的默认 agent 无法使用本地模型，则打开 pi）。任何兼容 OpenAI 的客户端也可以连接：`status` 显示每个模型的地址（第一个是 `http://127.0.0.1:11435/v1`），recipe 名称即是模型，密钥则位于 `~/.config/omarchy/agent-local/key` 中。

`omarchy agent local remove <recipe>` 删除某个模型以及没有其他模型使用的下载内容。

第三方运行时会标注其发布者。Omarchy 在没有网络访问的情况下运行每个模型。

### 本地 LLM

Omarchy 推荐两种运行本地 LLM 模型的方式：LM Studio 和 Ollama。LM Studio 提供了一个 GUI 界面，用于查找开放权重模型、安装并运行它们。这是轻松上手的好方法。Ollama 提供的 CLI 也能做类似的事。但如果你是本地模型的新手，我建议从 LM Studio 开始。你可以在 Omarchy Menu 的 _Install > AI_ 下安装其中任何一个。

### Omarchy Skill

Agent skill 帮助 AI 以特定方式使用特定工具，而 Omarchy 随附了一个用于定制系统的默认 skill。比如调整你的 Hyprland 配置、调整顶栏，甚至从零创建一个新主题。它被符号链接到 Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` 以及每个 `~/.hermes/profiles/*/skills`）的 skill 目录，以及通用的 `~/.agents/skills` 位置，因此大多数 harness 会自动拾取它。

但你应该将这个 skill 视为实验性的。不同模型运用它的效果各不相同。最好先在 plan mode 下运行，这样你能对 agent 想改动什么有个概念。然后，如果 agent 把一切都弄得一团糟，要准备好回滚更改，甚至调用 `omarchy reinstall configs`。
