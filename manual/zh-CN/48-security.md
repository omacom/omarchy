# 安全性

Omarchy 极其重视安全。这是要成为一个你可以在_真实世界_里做_真实工作_的操作系统。在那里，丢失笔记本电脑也不能引发安全紧急事件。所以我们是这样做的：

1. *全盘加密默认开启*：这是保护你的数据物理安全的最重要一步。如果你的电脑丢失或被盗，数据会使用标准 LUKS (Linux Unified Key Setup) 完全加密。安装程序允许你为一次性机器选择退出（参见[入门指南](02-getting-started.md)）；没有加密的安装则没有这种保护，任何拿到硬盘的人都可以读取它。
2. *防火墙默认启用*：默认阻止所有传入流量，只有少数例外：用于 [LocalSend](https://localsend.org/) 的 53317 端口；向位于 Docker 网桥地址（172.17.0.1）的本机解析器发送的 DNS 查询，接受来自 Docker 给其容器的私有地址范围；以及多播 DNS（5353 端口），它让打印机和你网络上的其他设备互相发现，也会在那里公布你的电脑名称。除此之外，防火墙还保留了 UFW 对 ping、从路由器获取地址 (DHCP) 以及 UPnP 发现的标准放行。甚至 ssh 在你通过 _设置 > 安全 > SSHD_ 开启它之前都是关闭的，该操作会授权你的 SSH 密钥、关闭密码登录，然后才打开 22 端口（有速率限制以防暴力破解）。我们甚至使用 [ufw-docker](https://github.com/chaifeng/ufw-docker) 配置锁定 Docker 访问，防止你的容器意外暴露给全世界。
3. *Arch 始终拥有最新更新*：Arch 是 Omarchy 所基于的底层发行版，是滚动发行版。这意味着在任何软件包中发现并修复的任何安全漏洞，都可以很快用 `omarchy-update` 安装。你因此总是运行一切软件的最新、最安全版本。
4. *Omarchy 维护自己的软件包和镜像*：Omarchy 默认仅依赖来自 Arch 自身的 core/extra/multilib 仓库（在 ARM 机器上是 Arch Linux ARM，再加上 Apple Silicon 上的 Asahi ALARM）和它自己的 Omarchy 软件包仓库。你可以直接从 AUR 安装软件，但基本安装不会这样做——只有少数可选安装，比如第三方浏览器，会从 AUR 拉取。
5. *Cloudflare 保护我们免受 DDoS 攻击*：Omarchy 分发基础设施——ISO、Omarchy 软件包、Arch 镜像——都受到 Cloudflare 强大的 DDoS 盾保护，并托管在他们的 CDN 上。这提供了出色的可用性。

## 更改你的密码

你在一台加密安装上有两个密码：开机时解锁硬盘的那个，以及你登录和 `sudo` 时用的那个。设置过程将它们设为相同。Omarchy 菜单中的 _更新 > 密码_ 会同时更改两者，所以它们保持相同：它会询问当前的硬盘密码，然后是新密码，先更改硬盘的，再将你的登录密码设为与其匹配。没有硬盘加密时，它只更改你的登录密码。如果更改被中断，再次运行 _更新 > 密码_：它会询问当前解锁硬盘的密码，完成更改，并将你的登录密码设为它。要更改另一块加密硬盘的密码，在终端中运行 `omarchy-drive-password`。

## 转让你已经用过的机器

如果你要把机器交给其他人，你不必重装它。在 Omarchy 菜单中运行 _移除 > 恢复出厂设置_，输入 `reset` 确认，如果被询问则输入你的硬盘加密密码，然后重启。这会清除每个用户账户和 `/home` 中的一切，丢弃你自安装以来所做的所有软件包和系统更改，并清除机器的身份——网络连接、主机密钥，全都清除。回来的是首次开机时的设置向导，它已准备好让新主人输入自己的名字、密码和加密密码。

它通过恢复安装程序拍摄的基线快照工作，所以只在从 Omarchy ISO 安装的机器上可用。而且在没有加密的硬盘上，重置是删除而非安全擦除，所以如果数据敏感，改用全新安装。

## 无密码 sudo

有时你想让 `sudo` 不再询问，最常见的是当一个 AI 代理在为你做一长段系统工作时。_设置 > 安全 > 无密码 Sudo_ 会询问允许访问多久：**15 分钟**、**1 小时**、**1 天**或**永久**。当访问激活时，一个红色警告图标会出现在其他菜单栏指示器旁边。点击它或者再次运行命令以关闭访问。你也可以用 `omarchy-sudo-passwordless 30` 传入你自己的分钟数（从 1 到 1440），或使用 `omarchy-sudo-passwordless permanent`。

定时访问自动到期，包括在跨越截止时间的挂起恢复后立即到期。重启电脑会提前结束它。永久访问会在重启后存活，并保持启用，直到你禁用为止。

更新或移除 Omarchy 的设置软件包会在其到期支持变更之前结束任何临时授权。如果命令报告授权或清理错误，请在尝试启用另一个授权之前解决它；出错并不意味着无密码访问未处于启用状态。

对这一点要有清醒认识：当它打开时，以你的用户身份运行的任何东西都可以无需被询问地以 root 做任何事情。这就是全部目的，也正是全部风险所在。

## 签名密钥

所有 ISO 签名和 Omarchy 仓库包的公钥是 `40DFB630FF42BCFFB047046CF0134EE680CAC571` ([在 openpgp.org 上验证](https://keys.openpgp.org/search?q=pkgs%40omarchy.org))。`omarchy/omarchy-keyring` 软件包也包含它，并将用于无缝推出任何潜在更新。

你可以通过给任何 ISO 发布 URL 添加 `.sig` 来找到它的签名，比如 `https://iso.omarchy.org/omarchy-x.x.x.iso.sig`。
