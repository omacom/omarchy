# 安全

Omarchy 对安全极其重视。这是一个让你能在_真实世界_中做_真正的工作_的操作系统。丢了笔记本电脑，也不能演变成一场安全紧急事件。所以我们是这样做的：

1. *默认开启全盘加密*：这是保护你数据物理安全最重要的一步。如果你的电脑丢失或被盗，数据会使用标准的 LUKS (Linux Unified Key Setup) 完全加密。安装程序允许你为用完即弃的机器选择退出（参见[入门指南](02-getting-started.md)）；没有加密的安装则完全没有这层保护，任何拿到驱动器的人都能读取其中的内容。
2. *默认启用防火墙*：默认阻止所有传入流量，只有少数例外：用于 [LocalSend](https://localsend.org/) 的 53317 端口；发往位于 Docker 网桥地址 (172.17.0.1) 的计算机自身解析器的 DNS 查询，这类查询接受来自 Docker 分配给其容器的私有地址范围；以及多播 DNS（5353 端口），它让打印机和网络上的其他设备能相互发现，也会在那里公布你的计算机名称。在此之外，防火墙还保留了 UFW 的标准放行规则：ping、从路由器获取地址 (DHCP)，以及 UPnP 发现。连 ssh 默认都是关闭的，直到你通过 _Setup > Security > SSHD_ 将其开启，这会作为设置的一部分开放 22 端口（并限制速率以防暴力破解）。我们甚至使用 [ufw-docker](https://github.com/chaifeng/ufw-docker) 设置来锁定 Docker 访问，防止你的容器意外暴露到全世界面前。
3. *Arch 始终拥有最新更新*：Arch 是 Omarchy 所基于的底层发行版，它是一个滚动发行版。这意味着，任何软件包中发现并修复的安全漏洞，都能很快通过 `omarchy-update` 安装。用这种方式，你始终运行着所有软件的最新、最安全版本。
4. *Omarchy 维护自己的软件包和镜像*：Omarchy 默认只依赖来自 Arch 自家的 core/extra/multilib 仓库以及它自己的 Omarchy Package Repository 的软件包。你可以直接从 AUR 安装软件，但基础安装不会这样做——只有少数可选安装，比如第三方浏览器，才会从 AUR 拉取。
5. *Cloudflare 保护我们免受 DDoS 攻击*：Omarchy 的分发基础设施——ISO、Omarchy 软件包、Arch 镜像——都受到 Cloudflare 强大的 DDoS 防护盾保护，并托管在他们的 CDN 上。这提供了出色的可用性。

## 更改你的密码

在加密安装中你有两个密码：一个是在启动时解锁驱动器的，另一个是你登录和 `sudo` 时使用的。初始设置会将它们设为相同。两者都可以在 Omarchy 菜单的 _Update > Password_ 下更改——第一个选 _Drive Encryption_，第二个选 _User_。更改驱动器密码会先要求你输入当前密码，所以请提前准备好。如果更改被中断，请再次运行 _Drive Encryption_：它会要求你输入现在能解锁驱动器的密码，并完成更改。

## 转交一台你已经用过的机器

如果你要把机器交给其他人，你不必重新安装它。在 Omarchy 菜单中运行 _Remove > Factory Reset_，输入 `reset` 确认，然后重启。这会擦除每一个用户账户以及 `/home` 中的所有内容，丢弃你自安装以来添加的所有软件包和系统更改，并清除机器的身份信息——网络连接、主机密钥，全部清除。重新启动后出现的是首次启动时的设置向导，新主人可以输入他们自己的姓名、密码和加密密码。

它的工作原理是恢复安装程序创建的基线快照，所以只有从 Omarchy ISO 安装的机器才能使用。而且在没有加密的驱动器上，重置只是删除而不是安全擦除，所以如果数据敏感，请改为全新安装。

## 免密码 sudo

有时你希望 `sudo` 不再反复询问，最常见的情况是 AI agent 正在为你长时间执行系统工作。_Setup > Security > Passwordless Sudo_ 会询问你允许多长时间的访问：**15 分钟**、**1 小时**、**1 天**或**永久**。访问处于活动状态时，菜单栏其他指示器旁会出现一个红色警告图标。点击它或再次运行该命令即可关闭访问。你也可以使用 `omarchy-sudo-passwordless 30` 传入你自己的分钟数（从 1 到 1440），或使用 `omarchy-sudo-passwordless permanent`。

定时访问会自动过期，包括从跨越截止时间的挂起中恢复后立即过期。重启电脑会提前终止它。永久访问在重启后依然保留，并会一直保持启用，直到你将其禁用。

更新或删除 Omarchy 的设置软件包，会在其过期支持发生变化之前结束任何临时授权。如果该命令报告授权或清理错误，请先解决它，再尝试启用另一项授权；出现错误并不意味着免密码访问处于非活动状态。

对这一点要有清醒认识：开启期间，任何以你的用户身份运行的程序都可以以 root 身份做任何事，且不会被询问。这正是它的全部意义所在，也正是它的全部风险所在。

## 签名密钥

所有 ISO 签名和 Omarchy 仓库软件包的公钥是 `40DFB630FF42BCFFB047046CF0134EE680CAC571`（[在 openpgp.org 上验证](https://keys.openpgp.org/search?q=pkgs%40omarchy.org)）。`omarchy/omarchy-keyring` 软件包也包含此公钥，并将用于无缝推出任何可能的更新。

你可以通过在其 URL 后添加 `.sig` 来找到任何 ISO 版本的签名，例如 `https://iso.omarchy.org/omarchy-x.x.x.iso.sig`。
