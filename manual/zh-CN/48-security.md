# 安全

Omarchy 极其重视安全。这理应是一个你可以在_现实世界_中用来做_真正工作_的操作系统。在这里，丢失一台笔记本电脑不应该导致一场安全紧急事件。所以我们是这样做的：

1. *默认启用全盘加密*：这是保护你的数据物理安全的最重要一步。如果你的计算机丢失或被盗，数据会使用标准的 LUKS (Linux Unified Key Setup) 完全加密。安装程序允许你为用完即弃的机器选择退出（参见[入门](02-getting-started.md)）；没有加密的安装完全没有这种保护，任何拿到硬盘的人都能读取其中的内容。
2. *默认启用防火墙*：默认阻止所有传入流量，只有少数例外：用于 [LocalSend](https://localsend.org/) 的 53317 端口；向位于 Docker 网桥地址 (172.17.0.1) 的计算机自身解析器发出的 DNS 查询，这些查询仅接受来自 Docker 分配给其容器的私有地址范围；以及多播 DNS（端口 5353），它让打印机和你网络上的其他设备能够互相发现，也会在那里宣告你计算机的名称。在此之外，防火墙保留了 UFW 的标准放行项：ping、从你的路由器获取地址 (DHCP)，以及 UPnP 发现。就连 ssh 也处于关闭状态，直到你通过_设置 > 安全 > SSHD_ 将其开启，这会作为设置的一部分开放 22 端口（并针对暴力破解进行速率限制）。我们甚至使用 [ufw-docker](https://github.com/chaifeng/ufw-docker) 设置锁定了 Docker 访问，防止你的容器意外暴露给全世界。
3. *Arch 始终提供最新更新*：Arch 是 Omarchy 所基于的底层发行版，它是一个滚动发行版。这意味着，任何软件包中发现并已修补的安全漏洞，都很快就能使用 `omarchy-update` 安装。这样你始终运行着一切软件的最新、最安全版本。
4. *Omarchy 维护自己的软件包和镜像*：Omarchy 默认只依赖来自 Arch 自身的 core/extra/multilib 仓库以及其自身的 Omarchy Package Repository 的软件包。你可以直接从 AUR 安装软件，但基础安装不会这样做——只有少数可选安装，例如第三方浏览器，才会从 AUR 拉取。
5. *Cloudflare 保护我们免受 DDoS 攻击*：Omarchy 的分发基础设施——ISO、Omarchy 软件包、Arch 镜像——都受到 Cloudflare 强大的 DDoS 防护盾保护，并托管在他们的 CDN 上。这提供了出色的可用性。

## 更改你的密码

在加密安装中你有两个密码：一个在启动时解锁驱动器，另一个用于登录和 `sudo`。设置时会将它们设为相同的。两者都可以在 Omarchy 菜单的_更新 > 密码_下更改——第一个选_驱动器加密_，第二个选_用户_。更改驱动器密码时会先要求输入当前密码，所以请提前准备好。如果更改被中断，请再次运行_驱动器加密_：它会要求输入当前能解锁驱动器的密码，并完成更改。

## 将你已经用过的机器转交他人

如果你要将机器交给其他人，你不必重新安装它。在 Omarchy 菜单中运行_设置 > 重置计算机_，输入 `reset` 确认，然后重启。这会清除每一个用户账户以及 `/home` 中的一切，丢弃自安装以来你所做的所有软件包和系统更改，并清除机器的身份——网络连接、主机密钥，全部清除。重新启动后出现的是首次启动时的设置向导，新主人可以输入他们自己的姓名、密码和加密密码。

它通过恢复安装程序拍摄的基线快照来工作，因此仅在从 Omarchy ISO 安装的机器上可用。而且在未加密的驱动器上，重置是删除而不是安全擦除，因此如果数据敏感，请改为进行全新安装。

## 免密码 sudo

有时你希望 `sudo` 不再询问，最常见的情况是 AI agent 正在为你完成一段长时间的系统工作。_设置 > 安全 > 免密码 Sudo_ 会询问允许访问的时长：**15 分钟**、**1 小时**、**1 天**或**永久**。访问处于活动状态时，菜单栏其他指示器旁会出现一个红色警告图标。点击它或再次运行该命令即可关闭访问。你也可以使用 `omarchy-sudo-passwordless 30` 传入你自己的分钟数（从 1 到 1440），或使用 `omarchy-sudo-passwordless permanent`。

定时访问会自动过期，包括在跨越截止时间的挂起恢复后立即过期。重启计算机会提前结束它。永久访问在重启后仍然保留，并保持启用，直到你将其禁用。

更新或删除 Omarchy 的设置软件包会在其到期支持变更之前结束任何临时授权。如果该命令报告授权或清理错误，请在尝试启用另一个授权之前解决它；出现错误并不意味着免密码访问处于非活动状态。

对此要清醒地认识：当它开启时，任何以你的用户身份运行的东西都可以无需询问就以 root 身份做任何事。这正是它的全部意义所在，也是它的全部风险所在。

## 签名密钥

所有 ISO 签名和 Omarchy 仓库软件包的公钥是 `40DFB630FF42BCFFB047046CF0134EE680CAC571`（[在 openpgp.org 上验证](https://keys.openpgp.org/search?q=pkgs%40omarchy.org)）。`omarchy/omarchy-keyring` 软件包也包含此密钥，并将用于无缝推出任何潜在的更新。

你可以通过在其 URL 后添加 `.sig` 来找到任何 ISO 版本的签名，例如 `https://iso.omarchy.org/omarchy-x.x.x.iso.sig`。
