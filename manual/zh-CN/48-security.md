# 安全

Omarchy 对安全极为认真。这应该是一个你可以在_现实世界_中用来做_真正的工作_的操作系统。在这样的系统上，丢失一台笔记本电脑绝不能演变成一场安全紧急事件。所以我们是这样做的：

1. *默认启用全盘加密*：这是保护你的数据物理安全的最重要一步。如果你的电脑丢失或被盗，数据会使用标准 LUKS (Linux Unified Key Setup) 完全加密。安装程序允许你在一次性使用的机器上选择退出（参见[开始使用](02-getting-started.md)）；未加密的安装没有任何这种保护，任何拿到该驱动器的人都可以读取它。
2. *默认启用防火墙*：默认阻止所有传入流量，只有几个例外：[LocalSend](https://localsend.org/) 使用的 53317 端口；对计算机自身解析器的 DNS 查询，地址为 Docker 网桥地址 (172.17.0.1)，接受来自 Docker 分配给其容器的私有地址范围的查询；以及多播 DNS（端口 5353），它让打印机和你网络上的其他设备能够相互发现，也会在那里公布你的计算机名称。在此之外，防火墙保留了 UFW 对 ping、从你的路由器获取地址 (DHCP) 以及 UPnP 发现的标准放行。甚至 ssh 也是关闭的，直到你通过_设置 > 安全 > SSHD_ 将其打开，该操作会授权你的 SSH 密钥、关闭密码登录，然后才打开 22 端口（已做速率限制以防暴力破解）。我们甚至使用 [ufw-docker](https://github.com/chaifeng/ufw-docker) 配置锁定了 Docker 访问，以防你的容器意外暴露到全世界面前。
3. *Arch 始终拥有最新更新*：Arch 是 Omarchy 所基于的底层发行版，它是一个滚动发行版。这意味着，任何软件包中发现并已修补的任何安全漏洞，都可以很快通过 `omarchy-update` 安装。这样，你始终运行着所有软件的最新、最安全的版本。
4. *Omarchy 维护自己的软件包和镜像*：Omarchy 默认只依赖来自 Arch 自身 core/extra/multilib 仓库（在 ARM 机器上是 Arch Linux ARM 的仓库，在 Apple Silicon 上则再加上 Asahi ALARM）以及其自己的 Omarchy Package Repository 的软件包。你可以直接从 AUR 安装软件，但基础安装不会这样做——只有少数可选安装，例如第三方浏览器，才会从 AUR 拉取。
5. *Cloudflare 保护我们免受 DDoS 攻击*：Omarchy 的分发基础设施——ISO、Omarchy 软件包、Arch 镜像——都受到 Cloudflare 强大的 DDoS 防护盾保护，并托管在他们的 CDN 上。这提供了出色的可用性。

## 修改你的密码

在加密安装中你有两个密码：一个在启动时解锁驱动器，另一个用于登录和 `sudo`。设置时会将它们设为相同。两者都可以在 Omarchy 菜单的_更新 > 密码_下修改——第一个选_驱动器加密_，第二个选_用户_。修改驱动器密码时会先要求输入当前密码，所以请备好它。如果修改被中断，请再次运行_驱动器加密_：它会询问现在能解锁驱动器的密码，并完成修改。

## 转交一台你已经用过的机器

如果你要把机器交给其他人，你不必重新安装它。在 Omarchy 菜单中运行_移除 > 恢复出厂设置_，输入 `reset` 以确认，如果有提示则输入你的驱动器加密密码，然后重启。这会清除每一个用户账户以及 `/home` 中的一切，丢弃你自安装以来所做的所有软件包和系统更改，并清除机器的身份——网络连接、主机密钥，全部清除。重新启动后出现的将是首次启动时的设置向导，它已准备好让新主人输入他们自己的姓名、密码和加密密码。

它通过恢复安装程序拍摄的基线快照来工作，所以它仅适用于从 Omarchy ISO 安装的机器。而且在没有加密的驱动器上，重置是删除而不是安全擦除，所以如果数据是敏感的，请改为进行全新安装。

## 免密码 sudo

有时你希望 `sudo` 不再询问密码，最常见的情况是 AI 智能体正在替你长时间做系统工作时。_设置 > 安全 > 免密码 sudo_ 会询问允许访问多长时间：**15 分钟**、**1 小时**、**1 天**或**永久**。访问处于活动状态时，其他菜单栏指示器旁边会出现一个红色警告图标。点击它或再次运行该命令即可关闭访问。你还可以使用 `omarchy-sudo-passwordless 30` 传入你自己的分钟数（从 1 到 1440），或使用 `omarchy-sudo-passwordless permanent`。

定时访问会自动过期，包括从一次跨过截止时间的挂起中恢复后立即过期。重启计算机将提前结束它。永久访问在重启后依然有效，并保持启用，直到你将其禁用。

更新或移除 Omarchy 的设置软件包会在其过期支持发生变化之前结束任何临时授权。如果该命令报告授权或清理错误，请在尝试启用另一项授权之前解决它；出现错误并不意味着免密码访问未处于活动状态。

对这一点要有清醒的认识：它开启时，任何以你的用户身份运行的东西都可以以 root 身份做任何事，无需被询问。这正是它的全部意义，也正是它的全部风险。

## 签名密钥

所有 ISO 签名和 Omarchy 仓库软件包的公钥是 `40DFB630FF42BCFFB047046CF0134EE680CAC571`（[在 openpgp.org 上验证](https://keys.openpgp.org/search?q=pkgs%40omarchy.org)）。`omarchy/omarchy-keyring` 软件包同样包含此密钥，并将用于无缝推出任何潜在更新。

你可以通过在其 URL 后添加 `.sig` 来找到任何 ISO 发行版的签名，例如 `https://iso.omarchy.org/omarchy-x.x.x.iso.sig`。
