# IA

Omarchy incluye lanzadores para los agentes de programación siguientes sin elegir uno predeterminado por ti. Ejecuta un comando para instalar su CLI la primera vez que lo uses y luego autentícate cuando se te pida. Hermes es la excepción: no se instala nada para él en el primer uso y, al elegirlo, se instala Hermes Desktop, como se explica en _Aplicaciones de escritorio_ más abajo.

### Instalar y actualizar agentes

Excepto Hermes, estos agentes usan la instalación diferida de mise: el primer inicio instala el CLI y los inicios posteriores lo reutilizan. mise también comprueba si hay una versión nueva de un agente instalado como máximo una vez cada cuatro horas, justo antes de iniciarlo o en segundo plano en un mensaje de la terminal. Si esa actualización falla o no tienes conexión, se ejecuta la versión instalada. `omarchy update` actualiza los agentes instalados junto con el resto de Omarchy, y `mup` actualiza solo las herramientas administradas con mise.

El actualizador propio de un agente, como `claude update`, `codex update` o un botón de actualización en una app, no actualiza la instalación administrada con mise. `codex update` falla, y `claude update` puede reportar éxito mientras instala una copia aparte que mise no rastrea. Si prefieres usar el instalador y el actualizador nativos de un agente, agrégalo a `disable_tools`; consulta [Herramientas CLI preinstaladas](18-development-tools.md#preinstalled-cli-tools).

Para instalar todas las herramientas diferidas configuradas antes de necesitarlas, ejecuta `mise install --include-lazy`. Esto incluye las demás herramientas CLI predeterminadas de Omarchy, además de los agentes. Consulta [Herramientas CLI preinstaladas](18-development-tools.md#preinstalled-cli-tools) para instalar una sola herramienta o usar tu propia instalación.

`grok` se instala mediante el paquete propio `grok` de mise, de la misma forma que `claude` y `codex`. Ejecuta `grok`, o elígelo en _Setup > Defaults > Agent_. Omite el instalador `curl | bash` de x.ai. Esa ruta coloca una segunda copia en `~/.grok/bin`, la antepone en `PATH` y sobrescribe el contenedor de Omarchy.

`dsh` abre su interfaz web en `127.0.0.1:3080`, con el directorio de inicio como su espacio de trabajo predeterminado. Su interfaz web no acepta un prompt inicial, así que `omarchy agent prompt` la abre con el prompt en tu portapapeles para que lo pegues. Omarchy lo inicia con el ajuste predefinido de permisos sin aprobación de DeepSeek. DeepSeek Harness sube los registros de sesión a DeepSeek cuando usas su API oficial de modelos; desactívalo en _Settings > General > Upload Session Log_ en su interfaz web. Los comentarios que le envíes también se suben con la sesión, a menos que lo inicies con `DSH_TELEMETRY_MODE=DISABLED`.

### El agente predeterminado

Elige tu agente predeterminado con `omarchy default agent <name>` o en _Setup > Defaults > Agent_ en el menú de Omarchy (`Super + Space`). Si el agente aún no está instalado, al elegirlo se instala primero. Una instalación nueva de Omarchy te invitará a hacer esta elección con una notificación única.

Al elegir Claude también se intenta configurar su extensión de navegador para Chromium, Chrome, Brave, Brave Origin y Edge. La configuración de la extensión se aplica a todos los usuarios y puede pedirte tu contraseña del sistema; cancelar o que falle la instalación de la extensión aún selecciona e inicia Claude. Reinicia tu navegador, activa la extensión si se te pide e inicia sesión en Claude para terminar de conectarla. Ejecuta `/chrome` en Claude para comprobar la conexión. Firefox y Zen no son compatibles con esta extensión. Si Claude ya era tu predeterminado antes de que se agregara esta configuración, selecciónalo de nuevo para instalar la extensión.

Una vez que hayas elegido, `Super + Shift + Ctrl + A` inicia el agente predeterminado en una ventana de terminal dedicada (o abre el selector si aún no has elegido). También puedes iniciarlo directamente en una tarea con `omarchy agent prompt "Review this project"`. Freebuff y DeepSeek Harness no aceptan un prompt inicial, así que se abren con el prompt en tu portapapeles para que lo pegues. Los agentes iniciados así se ejecutan sin supervisión en sus respectivos modos de no detenerse a preguntar, así que prepárate para que realmente hagan cosas. MiniMax Code no tiene un modo así para sus sesiones interactivas, así que pide permisos como de costumbre. Y como los agentes se niegan a recordar la confianza para tu directorio personal, los inicios desde `$HOME` empiezan en `~/Work` en su lugar.

También hay atajos de terminal: `a` ejecuta el agente predeterminado en línea en la terminal actual, mientras que `c`, `cx` y `cy` inician OpenCode, Claude Code y Codex directamente (también en sus modos de aprobación automática). Los cambios de tema también se sincronizan con los agentes: Claude Code, Pi, OpenCode y Hermes (una vez que Omarchy lo haya instalado) te siguen cuando cambias el tema de Omarchy.

### El panel de agentes

La barra superior tiene un ícono de agentes. Antes de que hayas configurado un agente, su panel te guía para iniciar sesión en Claude, Codex o Grok, y el primero se convierte en tu agente predeterminado. Después de eso, el panel reúne todas las suscripciones en una página: cada agente y cuenta con su plan, un medidor para cada uno de sus límites de sesión de 5 horas y semanal con el tiempo hasta que se restablezca (pasa el cursor para ver el porcentaje exacto), o el saldo prepagado restante, bajo una línea que rota por lo que has usado en todos ellos, como los tokens de esta semana y tu modelo más usado. En _Make something_ ofrece prompts iniciales para un tema, plugin o app nuevos que le entregan la tarea a tu agente predeterminado. Las apps se construyen como las propias Hype, Monologue y Omacut de Omarchy, en C++ y Qt Quick, siguiendo la skill de agente omarchy-app, y el compilador y las piezas de Qt que necesitan vienen instalados. Claude Code, Codex, Grok, Kimi, Cursor y su asignación de Grok Bot, GitHub Copilot, Muse, Antigravity, Kimchi y Devin están cubiertos desde el inicio con sus límites, y Hermes, Mistral Vibe y Qwen Code muestran sus sesiones y tokens una vez que los hayas usado. Los planes y claves de proveedores que uses mediante pi, omp u opencode también aparecen: OpenCode Zen y Go, el Z.ai GLM Coding Plan, Ollama Cloud, el MiniMax Token Plan y Synthetic con sus límites; Fireworks, OpenRouter y DeepSeek con sus saldos prepagados; y los modelos que ejecutas en tu propio hardware en Local models. Cada agente se cuenta una vez, bajo quien lo factura, sin importar por cuántos harnesses lo manejes.

Haz clic izquierdo en el ícono de la barra para ver el panel y clic derecho para iniciar tu agente predeterminado. Los registros de uso detrás de él se regeneran cada 15 minutos con `omarchy agent usage-update`, y el panel incluso puede combinar el uso de tus otras máquinas mediante una carpeta sincronizada. Consulta el README en `$OMARCHY_PATH/shell/plugins/agents/` para ver toda la configuración.

### Varias suscripciones

Si pagas más de un plan de Claude, Codex o Grok —uno personal Max y uno del trabajo, por ejemplo—, Omarchy puede mantenerlos todos con la sesión iniciada y moverse entre ellos. Agrega una suscripción con el + en el panel de agentes, que te guía ahí mismo, o con `omarchy agent account add claude Work` (o `codex`, o `grok`). Instala el CLI si falta. La primera cuenta de un proveedor inicia sesión mediante tu navegador normal, justo donde el CLI siempre busca. Cada una después de esa inicia sesión mediante una ventana privada, para que la cuenta en la que tu navegador ya inició sesión no se tome por error; inicia sesión ahí como la cuenta que estás agregando y cierra primero cualquier ventana privada que ya tuvieras abierta. Nunca cierres sesión en el CLI para hacer esto: cerrar sesión revoca el inicio de sesión guardado y habría que agregar esa cuenta de nuevo.

Para copiar tus inicios de sesión de suscripción a otra máquina Omarchy por SSH, ejecuta `omarchy agent account copy user@laptop`. El emisor proporciona un receptor temporal cuando el destino no tiene uno instalado, así que las máquinas Omarchy más viejas pueden recibir cuentas sin una actualización. Los receptores instalados tienen precedencia. Esto copia todas las suscripciones de Claude, Codex y Grok; agrega nombres de proveedores para seleccionarlas, como en `omarchy agent account copy laptop claude`. Los nombres de cuenta y los ID de comando coinciden con el origen, incluidas las cuentas que ya estén presentes en el destino. Las cuentas de destino no relacionadas reciben un sufijo numérico si sus nombres entran en conflicto, y la configuración, las skills, los plugins y el historial de conversaciones permanecen locales en cada máquina.

Las credenciales de destino existentes se conservan. Una cuenta de origen que ya haya iniciado sesión ahí sincroniza su nombre sin reemplazar sus credenciales; las demás cuentas se agregan junto a ella. Para reemplazar las credenciales guardadas de las cuentas coincidentes, usa `omarchy agent account copy --replace laptop claude` después de salir de las sesiones de esa cuenta en el destino. Un destino nuevo también recibe la cuenta activa y las preferencias de cambio del origen; un destino ya establecido conserva las suyas.

Las credenciales viajan por SSH y se guardan en archivos privados en el destino, así que cópialas solo a máquinas en las que confíes. Esto es una copia única, no una sincronización continua. Los tokens de actualización de Codex pueden ser rotados por otra máquina, lo que deja un inicio de sesión copiado con necesidad de renovación; los inicios de sesión separados siguen siendo la opción más confiable para uso simultáneo en varias máquinas. Consulta la [guía de autenticación de cuentas de Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Una cuenta por proveedor está activa, y cada sesión nueva empieza como ella: `cx`, `cy`, un `claude`, `codex` o `grok` simple, cualquier cosa iniciada mediante `omarchy agent`, y los scripts o editores que encuentren el CLI en `PATH`. Cambia con `omarchy agent account use work` (y vuelve con `omarchy agent account use main`), o en el panel presionando el número de una cuenta y luego `Enter` (o haciendo clic en su botón Use). Las sesiones que ya se están ejecutando permanecen en la cuenta con la que empezaron. El historial de conversaciones, la configuración, las skills y los plugins se comparten entre cuentas, así que `claude --continue` en la misma carpeta continúa donde lo dejaste en la cuenta nueva.

Con más de una cuenta, el panel muestra los límites de cada cuenta lado a lado, con la activa marcada. Por defecto, Omarchy te avisa cuando la cuenta activa supera el 95% de un límite, y al hacer clic en la notificación cambia a la cuenta con más margen. Pasa el cursor sobre la línea de una cuenta en el panel y haz clic en el Autoswitch que aparece junto a Use (o presiona `m`), o ejecuta `omarchy agent account mode auto`, para que cambie por sí solo; mientras está activado, Autoswitch ocupa el lugar de Use, y al hacer clic de nuevo vuelve a avisar. Agrega un número para cambiar el umbral, como en `omarchy agent account mode auto 90`. Si todas las cuentas superan el umbral, te enterarás una vez, junto con qué cuenta se libera primero. Mientras una cuenta activa esté a menos de 15 puntos de su umbral (80% con el valor predeterminado), sus límites se comprueban cada tres minutos en lugar de cada 15.

`omarchy agent account list` muestra todas las cuentas y sus límites más recientes, `omarchy agent account remove work` olvida una, y `omarchy agent account rename primary Hey` cambia el nombre de una (o haz clic en el nombre de una cuenta en el panel). Estos comandos funcionan en las cuentas de tu agente predeterminado; para llegar al otro proveedor, nómbralo primero, como en `omarchy agent account use codex side`. El inicio de sesión que ya tenías en `~/.claude` o `~/.codex` es la cuenta _Main_ y se queda donde está. Una cuenta que no se use por más de unas ocho horas puede mostrar _Sign-in required_; haz clic en ella para iniciar sesión en esa cuenta de nuevo directamente en el panel, o inicia una sesión en ella, lo que renueva el inicio de sesión por sí solo. Los servidores MCP que tenías cuando se agregó una cuenta la acompañan, pero los que agregues después con `claude mcp add` solo llegan a la cuenta en la que los agregaste. Claude Desktop y las herramientas configuradas con una ruta absoluta a un binario CLI no siguen el cambio. Un `CLAUDE_CONFIG_DIR`, `CODEX_HOME` o `GROK_HOME` explícito tiene precedencia sobre la cuenta seleccionada.

### Diagnóstico de fallos

Omarchy vigila systemd-coredump en busca de fallos de procesos. Cuando algo hace segfault, recibirás una notificación "Process crashed": haz clic en ella y el fallo se entrega a tu agente predeterminado junto con la skill diagnose-crash de Omarchy, que guía al agente para establecer los hechos a partir del core dump y decidir si vale la pena reportar el fallo al proyecto original. También puedes ejecutarlo a mano contra cualquier PID de `coredumpctl list` con `omarchy agent crash <pid>`.

La vigilancia está activada por defecto. Desactívala en _Trigger > Toggle > Crash Capture_ (o con `omarchy toggle crash-capture`) y las notificaciones se detienen; `omarchy agent crash <pid>` sigue funcionando a mano.

Los fallos también se pueden silenciar un programa a la vez, que es lo que el diagnóstico te ofrece al final. `omarchy crash mute hyprland` detiene las notificaciones solo para ese programa, `omarchy crash mute hyprland off` las trae de vuelta, y `omarchy crash mute` por sí solo lista lo que has silenciado. Acepta la ruta del binario con la misma facilidad que su nombre, así que `omarchy crash mute /usr/bin/hyprland` hace lo mismo. Pon entre comillas un nombre con un espacio, como en `omarchy crash mute 'Some App'`. Todo lo demás sigue avisando, y el programa silenciado sigue fallando: esto oculta el recordatorio, no arregla nada.

### Aplicaciones de escritorio

El menú _Install > AI_ también lleva algunas apps gráficas de IA: la app de escritorio de ChatGPT, la app de escritorio de Claude (la beta para Linux de Anthropic, con pestañas Chat, Cowork y Claude Code), Grok Bot para chatear con los modelos de xAI, Hermes Desktop, OpenClaw, la app de escritorio de Perplexity y T3 Code. Grok Bot es la app de chat de escritorio. El agente de programación es el comando `grok`.

Hermes Desktop es la que hay que conocer, porque una máquina tiene un solo Hermes, y es el de la app: Hermes solo se instala mediante la app, y el comando `hermes` que ejecuta el agente predeterminado es el de la app. Elegir Hermes como agente predeterminado instala lo mismo que la entrada _Install > AI_: el paquete y un entorno de ejecución de Hermes en `~/.hermes` configurado por el propio instalador de Hermes, lo que toma unos minutos la primera vez. Ese entorno es el único Hermes que usan el comando `hermes` de la terminal, el agente predeterminado y la app, y se actualiza solo con `hermes update` en lugar de esperar una versión de Omarchy. Al instalarlo también le entrega a Hermes el tema de Omarchy como una skin llamada `omarchy`, que todas las superficies de Hermes siguen cuando cambias de tema; elige otra en la configuración Appearance de Hermes o con `/skin` si prefieres que no lo haga, y Omarchy deja esa elección en paz. Quitar la app en _Remove > AI_ cierra Hermes primero, gateway incluido, se lleva ese entorno con ella y conserva tus chats, recuerdos y las skills que Hermes escribió para sí mismo a menos que le digas lo contrario: te pregunta, con no como predeterminado, si esos datos y tu configuración de conexión también deben irse.

La experiencia de escritorio de OpenClaw es su Control UI, que se abre como una app web respaldada por su propio gateway local. OpenClaw vive en `~/.openclaw` y se actualiza solo: usa el botón "Update Gateway" de la Control UI o ejecuta `openclaw update`, y el gateway se reinicia en la versión nueva. Omarchy solo elige la versión con la que empieza una instalación nueva. Quitar OpenClaw en _Remove > AI_ se lleva el servicio del gateway y la app con él y luego pregunta si `~/.openclaw` también debe irse, ya que ahí guarda tus chats y credenciales junto con el propio OpenClaw y los entornos de ejecución de plugins que descarga; el valor predeterminado lo conserva, e instalar OpenClaw de nuevo lo recupera.

T3 Code se ejecuta desde su lanzamiento oficial en AppImage en `~/.local/share/t3code` en lugar de desde un paquete, así que se actualiza solo. Al instalarlo se te pregunta si quieres empezar en el canal Stable o Nightly; cámbialo después en la configuración de T3 Code. Tus hilos y configuración viven en `~/.t3`, y quitar T3 Code en _Remove > AI_ se los lleva con él.

### Modelos locales

Ejecuta un modelo abierto en tu propia máquina para tus agentes de programación. Tus prompts y tu código permanecen en la máquina; nada de lo enviado al modelo sale de ella. Empieza con:

```bash
omarchy agent local use best
```

O, en el panel de agentes en la barra superior, elige + y luego Local AI, que aparece cuando un modelo cabe en esta máquina. La primera vez, esto instala Podman, que ejecuta los modelos. Luego Omarchy elige el modelo recomendado para esta máquina, lo descarga y lo inicia. Espera una descarga de decenas de GB y que la mayor parte de la memoria de la máquina esté en uso mientras el modelo se ejecuta: Flash Next usa unos 100 GiB con su contexto completo de 256K. Si otros modelos ocupan la memoria que necesita, queda configurado detenido, listo para iniciarse una vez que detengas uno. El modelo se detiene al cerrar sesión; detenlo tú mismo cuando necesites la memoria para otra cosa.

`omarchy agent local list` muestra las opciones y explica por qué algunas no caben. Para configurar otro, ejecuta `omarchy agent local use <recipe>`. Hoy, `qwen3.8-flash-next-halogen` y `qwen3.8-27b-gufo` están disponibles para máquinas Strix Halo de 128 GB. Las recetas y recomendaciones nuevas llegan con `omarchy update`, mediante el paquete.

Cada modelo que configures obtiene su propia línea en el panel de agentes, junto a tus suscripciones: reproducir para iniciarlo, pausar para detenerlo y liberar su memoria, y el botón de terminal para abrir tu agente en él. Varios pueden ejecutarse a la vez cuando caben juntos en memoria; si uno no cabe, Omarchy dice qué modelo en ejecución hay que detener. Arrastra las líneas para reordenarlas y presiona Delete en una línea seleccionada para quitar un modelo y su descarga.

Desde la línea de comandos, `omarchy agent local start <recipe>` y `omarchy agent local stop <recipe>` hacen lo mismo, `omarchy agent local status` muestra todos los modelos, y `omarchy agent --local` abre tu agente predeterminado en el último modelo que iniciaste (pi si tu agente predeterminado no puede usar un modelo local). Cualquier cliente compatible con OpenAI también puede conectarse: `status` muestra la dirección de cada modelo (la primera es `http://127.0.0.1:11435/v1`), el nombre de la receta es el modelo, y la clave está en `~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` elimina un modelo y las descargas que ningún otro modelo use.

Los entornos de ejecución de terceros están etiquetados con su editor. Omarchy ejecuta todos los modelos sin acceso a la red.

### LLM locales

Omarchy recomienda dos formas de ejecutar modelos LLM locales: LM Studio y Ollama. LM Studio proporciona una interfaz GUI para encontrar modelos de pesos abiertos, instalarlos y ejecutarlos. Es una gran manera de empezar con facilidad. Ollama ofrece un CLI para hacer algo parecido. Pero si eres nuevo en los modelos locales, yo empezaría con LM Studio. Puedes instalar cualquiera de los dos en _Install > AI_ en el menú de Omarchy.

### La skill de Omarchy

Las skills para agentes ayudan a la IA a usar herramientas específicas de una manera específica, y Omarchy incluye una skill predeterminada para ajustar el sistema. Como retocar tu configuración de Hyprland, ajustar la barra o incluso crear un tema nuevo desde cero. Está enlazada simbólicamente en los directorios de skills de Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` y cada `~/.hermes/profiles/*/skills`), y la ubicación genérica `~/.agents/skills`, así que la mayoría de los harnesses la recogen automáticamente.

Pero debes tratar esta skill como experimental. Los distintos modelos la usarán con efectos distintos. Es mejor ejecutarla primero en modo de plan, para que tengas una idea de lo que al agente le gustaría cambiar. Y luego prepárate para revertir los cambios o incluso invocar `omarchy reinstall configs`, si el agente hace un desastre con todo.
