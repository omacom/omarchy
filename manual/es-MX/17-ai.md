# IA

Omarchy trata a los agentes de programación con IA como ciudadanos de primera clase, pero no elige un favorito por ti. En su lugar, cada CLI importante de agente de programación viene precableada como un lanzador de carga diferida. Los lanzadores son pequeños stubs administrados por [mise](https://mise.jdx.dev/) en `~/.local/bin/`, así que no se descarga nada hasta la primera vez que realmente ejecutas uno. Hermes es la excepción: no hay ningún stub para él, y elegirlo instala Hermes Desktop, como se explica abajo en _Aplicaciones de escritorio_. Invoca cualquiera de estos y autentícate cuando se te pida:

| Comando    | Agente                                                            |
|------------|------------------------------------------------------------------|
| `claude`   | [Claude Code](https://code.claude.com/docs/en/overview)          |
| `codex`    | [OpenAI Codex](https://github.com/openai/codex)                  |
| `opencode` | [OpenCode](https://opencode.ai/)                                 |
| `agy`      | [Google Antigravity CLI](https://github.com/google-antigravity/antigravity-cli) |
| `copilot`  | [GitHub Copilot CLI](https://github.com/github/copilot-cli)      |
| `crush`    | [Crush](https://github.com/charmbracelet/crush)                  |
| `grok`     | [Grok Build](https://x.ai/build) de xAI                        |
| `kimi`     | [Kimi Code](https://www.kimi.com/code/docs/en/)                  |
| `pi`       | [Pi de Mario Zechner](https://github.com/badlogic/pi-mono)        |
| `omp`      | [Oh My Pi](https://github.com/can1357/oh-my-pi)                  |
| `ori`      | [Ori](https://openrouter.ai/docs/guides/ori/harness), el harness de OpenRouter |
| `hermes`   | [Hermes](https://hermes-agent.nousresearch.com/), el agente de Nous Research  |
| `muse`     | [Muse Code](https://dev.meta.ai), el agente de programación de Meta           |
| `cursor-agent` | [Cursor CLI](https://cursor.com/cli)                         |

`ori` es el raro del grupo: ejecuta los demás harnesses contra todo el catálogo de modelos de OpenRouter, así que `ori claude`, `ori codex` u `ori opencode` inician esos agentes con el modelo al que los apuntes, y `ori code` es el agente propio de Ori.

Para envolver una CLI adicional de la misma manera, ejecuta `omarchy-mise-install <package> [command-name]`. Los stubs se mantienen actualizados junto con todo lo demás que administra mise cuando ejecutas `omarchy update` (o el alias `mup`).

`grok` se instala a través del paquete propio `grok` de mise, de la misma manera que `claude` y `codex`. Ejecuta `grok`, o elígelo en _Setup > Defaults > Agent_. Sáltate el instalador `curl | bash` de x.ai. Esa ruta pone una segunda copia en `~/.grok/bin`, la antepone en `PATH` y sobrescribe el wrapper de Omarchy.

### El agente predeterminado

Elige tu agente predeterminado con `omarchy default agent <name>` o en _Setup > Defaults > Agent_ en el menú de Omarchy (`Super + Space`). Si el agente todavía no está instalado, elegirlo lo instala primero. Un Omarchy recién instalado te invitará a hacer esta elección con una notificación única.

Elegir Claude también intenta configurar su extensión de navegador para Chromium, Chrome, Brave, Brave Origin y Edge. La configuración de la extensión se aplica a todos los usuarios y puede pedirte tu contraseña del sistema; cancelar o que falle la instalación de la extensión aun así selecciona e inicia Claude. Reinicia tu navegador, habilita la extensión si se te pide e inicia sesión en Claude para terminar de conectarla. Ejecuta `/chrome` en Claude para verificar la conexión. Firefox y Zen no son compatibles con esta extensión. Si Claude ya era tu predeterminado antes de que se agregara esta configuración, selecciónalo de nuevo para instalar la extensión.

[Muse Code](https://dev.meta.ai) — el `muse` de Meta — usa un stub de mise preinstalado como los demás agentes. Elegirlo como predeterminado instala el lanzador oficial de Meta a través del backend HTTP de mise. El lanzador verifica y actualiza el binario nativo para tu máquina.

Una vez que hayas elegido, `Super + Shift + Ctrl + A` inicia el agente predeterminado en una ventana de terminal dedicada (o abre el selector si todavía no has elegido). También puedes iniciarlo directo en una tarea con `omarchy agent prompt "Review this project"`. Los agentes iniciados así se ejecutan sin supervisión en sus respectivos modos de no detenerse a preguntar, así que prepárate para que de verdad hagan cosas. Y como los agentes se niegan a recordar la confianza para tu directorio home, los inicios desde `$HOME` empiezan en `~/Work` en su lugar.

También hay atajos de terminal: `a` ejecuta el agente predeterminado en línea en la terminal actual, mientras que `c`, `cx` y `cy` inician OpenCode, Claude Code y Codex directamente (de nuevo en sus modos de aprobación automática). Los cambios de tema también se sincronizan con los agentes: Claude Code, Pi, OpenCode y Hermes (una vez que Omarchy lo haya instalado) siguen el cambio cuando cambias el tema de Omarchy.

### El panel de agentes

La barra superior tiene un icono de agentes. Antes de que hayas configurado un agente, su panel te guía para iniciar sesión en Claude, Codex o Grok, y el primero se convierte en tu agente predeterminado. Después de eso, el panel pone cada suscripción en una sola página: cada agente y cuenta con su plan, un medidor para cada uno de sus límites de sesión de 5 horas y semanales con el tiempo hasta que se restablezca (pasa el cursor para ver el porcentaje exacto), o el saldo prepagado restante, bajo una línea que rota por lo que has usado en todos ellos, como los tokens de esta semana y tu modelo más usado. En _Make something_ ofrece prompts iniciales para un tema, plugin o app nuevos que le entregan la tarea a tu agente predeterminado. Las apps se construyen como se construyen Hype, Monologue y Omacut, las propias de Omarchy, en C++ y Qt Quick, siguiendo la skill de agente omarchy-app, y el compilador y las piezas de Qt que necesitan vienen instalados. Claude Code, Codex, Grok, Fireworks y Kimi están cubiertos desde el inicio. Kimi actualmente reporta los límites de cuota de la cuenta sin estadísticas locales de tokens ni de prompts.

Haz clic izquierdo en el icono de la barra para abrir el panel, clic derecho para iniciar tu agente predeterminado. Los registros de uso detrás de él se regeneran cada 15 minutos con `omarchy agent usage-update`, y el panel incluso puede fusionar el uso de tus otras máquinas mediante una carpeta sincronizada. Consulta el README en `$OMARCHY_PATH/shell/plugins/agents/` para ver todos los ajustes.

### Varias suscripciones

Si pagas más de un plan de Claude, Codex o Grok — un Max personal y uno del trabajo, por ejemplo — Omarchy puede mantenerlos todos con sesión iniciada y moverse entre ellos. Agrega una suscripción con el + en el panel de agentes, que te guía ahí mismo, o con `omarchy agent account add claude Work` (o `codex`, o `grok`). Instala la CLI si falta. La primera cuenta de un proveedor inicia sesión a través de tu navegador normal, justo donde la CLI siempre busca. Cada una después de esa inicia sesión a través de una ventana privada, para que la cuenta en la que tu navegador ya tiene sesión iniciada no se tome por error; inicia sesión ahí como la cuenta que estás agregando, y cierra antes cualquier ventana privada que ya tuvieras abierta. Nunca cierres sesión en la CLI para hacer esto: cerrar sesión revoca el inicio de sesión guardado, y esa cuenta tendría que agregarse de nuevo.

Para copiar tus inicios de sesión de suscripción a otra máquina con Omarchy por SSH, ejecuta `omarchy agent account copy user@laptop`. El emisor proporciona un receptor temporal cuando el destino no tiene uno instalado, así que las máquinas con Omarchy más viejas pueden recibir cuentas sin una actualización. Los receptores instalados tienen precedencia. Esto copia todas las suscripciones de Claude, Codex y Grok; agrega nombres de proveedor para seleccionarlas, como en `omarchy agent account copy laptop claude`. Los nombres de cuenta y los ID de comando coinciden con el origen, incluidas las cuentas ya presentes en el destino. Las cuentas del destino no relacionadas reciben un sufijo numérico si sus nombres entran en conflicto, y los ajustes, las skills, los plugins y el historial de conversaciones se quedan locales en cada máquina.

Las credenciales existentes del destino se conservan. Una cuenta de origen que ya tiene sesión iniciada ahí tiene su nombre sincronizado sin reemplazar sus credenciales; las demás cuentas se agregan junto a ella. Para reemplazar las credenciales guardadas de las cuentas coincidentes, usa `omarchy agent account copy --replace laptop claude` después de salir de las sesiones de esa cuenta en el destino. Un destino nuevo también recibe la cuenta activa y las preferencias de cambio del origen; un destino ya establecido conserva las suyas.

Las credenciales viajan por SSH y se almacenan en archivos privados en el destino, así que copia solo a máquinas en las que confíes. Esta es una copia única, no una sincronización continua. Otra máquina puede rotar los tokens de actualización de Codex, dejando un inicio de sesión copiado con necesidad de renovación; los inicios de sesión separados siguen siendo la opción más confiable para uso simultáneo en varias máquinas. Consulta la [guía de autenticación de cuentas de Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Una cuenta por proveedor está activa, y cada sesión nueva empieza como ella: `cx`, `cy`, un simple `claude`, `codex` o `grok`, cualquier cosa iniciada a través de `omarchy agent`, y scripts o editores que encuentren la CLI en `PATH`. Cambia con `omarchy agent account use work` (y regresa con `omarchy agent account use main`), o en el panel presionando el número de una cuenta y luego `Enter` (o haciendo clic en su botón Use). Las sesiones que ya están corriendo se quedan en la cuenta con la que empezaron. El historial de conversaciones, los ajustes, las skills y los plugins se comparten entre cuentas, así que `claude --continue` en la misma carpeta retoma donde te quedaste en la cuenta nueva.

Con más de una cuenta, el panel muestra los límites de cada cuenta lado a lado, con la activa marcada. Por defecto, Omarchy te notifica cuando la cuenta activa supera el 95% de un límite, y hacer clic en la notificación cambia a la cuenta con más margen. Pasa el cursor sobre la línea de una cuenta en el panel y haz clic en Autoswitch que aparece junto a Use (o presiona `m`), o ejecuta `omarchy agent account mode auto`, para que cambie por su cuenta en su lugar; mientras está activado, Autoswitch toma el lugar de Use, y hacer clic de nuevo regresa a notificar. Agrega un número para cambiar el umbral, como en `omarchy agent account mode auto 90`. Si cada cuenta está por encima del umbral, te enterarás una vez, junto con qué cuenta se libera primero. Mientras una cuenta activa esté dentro de los 15 puntos de su umbral (80% en el valor predeterminado), sus límites se verifican cada tres minutos en lugar de cada 15.

`omarchy agent account list` muestra cada cuenta y sus límites más recientes, `omarchy agent account remove work` olvida una, y `omarchy agent account rename primary Hey` renombra una (o haz clic en el nombre de una cuenta en el panel). Estos comandos funcionan en las cuentas de tu agente predeterminado; para llegar al otro proveedor, nómbralo primero, como en `omarchy agent account use codex side`. El inicio de sesión que ya tenías en `~/.claude` o `~/.codex` es la cuenta _Main_ y se queda donde está. Una cuenta que se deja sin usar por más de unas ocho horas puede mostrar _Sign-in required_; haz clic en ella para iniciar sesión en esa cuenta de nuevo justo en el panel, o inicia una sesión en ella, lo que refresca el inicio de sesión por su cuenta. Los servidores MCP que tenías cuando se agregó una cuenta vienen con ella, pero los que agregues después con `claude mcp add` solo llegan a la cuenta en la que los agregaste. Claude Desktop y las herramientas configuradas con una ruta absoluta a un binario de CLI no siguen el cambio. Un `CLAUDE_CONFIG_DIR`, `CODEX_HOME` o `GROK_HOME` explícito tiene precedencia sobre la cuenta seleccionada.

### Diagnóstico de fallos

Omarchy vigila systemd-coredump en busca de fallos de procesos. Cuando algo hace segfault, recibirás una notificación de "Process crashed" — haz clic en ella, y el fallo se le entrega a tu agente predeterminado junto con la skill diagnose-crash de Omarchy, que guía al agente para establecer los hechos a partir del core dump y decidir si vale la pena reportar el fallo upstream. También puedes ejecutarlo a mano contra cualquier PID de `coredumpctl list` con `omarchy agent crash <pid>`.

La vigilancia está activada por defecto. Desactívala en _Trigger > Toggle > Crash Capture_ (o con `omarchy toggle crash-capture`) y las notificaciones se detienen; `omarchy agent crash <pid>` sigue funcionando a mano.

Los fallos también se pueden silenciar de un programa a la vez, que es lo que el diagnóstico te ofrece al final. `omarchy crash mute hyprland` detiene las notificaciones solo para ese programa, `omarchy crash mute hyprland off` las trae de vuelta, y `omarchy crash mute` por sí solo lista lo que has silenciado. Acepta la ruta del binario tan felizmente como su nombre, así que `omarchy crash mute /usr/bin/hyprland` hace lo mismo. Pon entre comillas un nombre con un espacio, como en `omarchy crash mute 'Some App'`. Todo lo demás sigue notificando, y el programa silenciado sigue fallando — esto oculta el recordatorio, no arregla nada.

### Aplicaciones de escritorio

El menú _Install > AI_ también trae algunas apps gráficas de IA: la app de escritorio de ChatGPT, la app de escritorio de Claude (la beta para Linux de Anthropic, con pestañas de Chat, Cowork y Claude Code), Grok Bot para chatear con los modelos de xAI, Hermes Desktop, OpenClaw y la app de escritorio de Perplexity. Grok Bot es la app de chat de escritorio. El agente de programación es el comando `grok`.

Hermes Desktop es la que hay que conocer, porque una máquina tiene un solo Hermes, y es el de la app: Hermes solo se instala a través de la app, y el comando `hermes` que ejecuta el agente predeterminado es el de la app. Elegir Hermes como agente predeterminado instala lo mismo que hace la entrada de _Install > AI_: el paquete, y un runtime de Hermes bajo `~/.hermes` configurado por el instalador propio de Hermes, que tarda unos minutos la primera vez. Ese runtime es el único Hermes que usan el comando `hermes` de la terminal, el agente predeterminado y la app, y se actualiza solo con `hermes update` en lugar de esperar una versión de Omarchy. Instalarlo también le entrega a Hermes el tema de Omarchy como una skin llamada `omarchy`, que cada superficie de Hermes sigue conforme cambias de tema; elige otra en los ajustes de Appearance de Hermes o con `/skin` si prefieres que no lo haga, y Omarchy deja esa elección en paz. Quitar la app en _Remove > AI_ cierra Hermes primero, gateway incluido, se lleva ese runtime con ella, y conserva tus chats, memorias y las skills que Hermes escribió para sí mismo a menos que le digas lo contrario: te pregunta, con no como predeterminado, si esos datos y tus ajustes de conexión también deben irse.

La experiencia de escritorio de OpenClaw es su Control UI, que se abre como una web app respaldada por su propio gateway local. OpenClaw vive en `~/.openclaw` y se actualiza solo: usa el botón "Update Gateway" de la Control UI o ejecuta `openclaw update`, y el gateway se reinicia en la versión nueva. Omarchy solo elige la versión desde la que empieza una instalación nueva. Quitar OpenClaw en _Remove > AI_ se lleva el servicio del gateway y la app con él y luego pregunta si `~/.openclaw` también debe irse, ya que eso guarda tus chats y credenciales junto con OpenClaw mismo y los runtimes de plugins que descarga; el valor predeterminado lo conserva, e instalar OpenClaw de nuevo lo retoma.

### LLM locales

Omarchy recomienda dos maneras de ejecutar modelos LLM locales: LM Studio y Ollama. LM Studio proporciona una interfaz GUI para encontrar modelos de pesos abiertos, instalarlos y ejecutarlos. Es una gran manera de empezar fácilmente. Ollama ofrece una CLI para hacer lo mismo de manera similar. Pero si eres nuevo en los modelos locales, yo empezaría con LM Studio. Puedes instalar cualquiera de los dos en _Install > AI_ en el menú de Omarchy.

### La skill de Omarchy

Las skills de agente ayudan a la IA a usar herramientas específicas de una manera específica, y Omarchy viene con una skill predeterminada para personalizar el sistema. Como ajustar tu configuración de Hyprland, ajustar la barra o incluso crear un tema nuevo desde cero. Está enlazada con symlink en los directorios de skills de Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` y cada `~/.hermes/profiles/*/skills`) y la ubicación genérica `~/.agents/skills`, así que la mayoría de los harnesses la toman automáticamente.

Pero deberías tratar esta skill como experimental. Distintos modelos la usarán con distinto efecto. Es mejor ejecutar primero en modo de plan, para que tengas una idea de lo que al agente le gustaría cambiar. Y luego prepárate para revertir cambios o incluso invocar `omarchy reinstall configs`, si el agente hace un desastre con todo.
