# IA

Omarchy incluye lanzadores para los agentes de programación siguientes sin elegir un predeterminado por ti. Ejecuta un comando para instalar su CLI en el primer uso y luego autentícate cuando se te pida. Hermes y OpenClaw son las excepciones: no se instala nada para ellos a través de mise, y elegir cualquiera de los dos configura su propia copia con actualización automática, como explica _Aplicaciones de escritorio_ más abajo.

### Instalar y actualizar agentes

Excepto Hermes y OpenClaw, estos agentes usan la instalación diferida de mise: el primer inicio instala la CLI y los siguientes la reutilizan. mise también comprueba si hay una nueva versión de un agente instalado como máximo una vez cada cuatro horas, justo antes de iniciarlo o en segundo plano en un prompt de shell. Si esa actualización falla o no tienes conexión, se ejecuta la versión instalada. `omarchy update` actualiza los agentes instalados junto con el resto de Omarchy, y `mup` actualiza solo las herramientas gestionadas por mise.

El actualizador propio de un agente, como `claude update`, `codex update` o un botón de actualización en una aplicación, no actualiza la instalación gestionada por mise. `codex update` falla, y `claude update` puede reportar éxito mientras instala una copia separada que mise no sigue. Si prefieres usar el instalador y actualizador nativos de un agente, añádelo a `disable_tools`; consulta [Herramientas CLI preinstaladas](18-development-tools.md#preinstalled-cli-tools).

Para instalar todas las herramientas diferidas configuradas antes de necesitarlas, ejecuta `mise install --include-lazy`. Esto incluye las demás herramientas CLI predeterminadas de Omarchy además de los agentes. Consulta [Herramientas CLI preinstaladas](18-development-tools.md#preinstalled-cli-tools) para instalar una sola herramienta o usar tu propia instalación.

`grok` se instala a través del paquete propio `grok` de mise, igual que `claude` y `codex`. Ejecuta `grok`, o elígelo en _Agente > Harness_. Sáltate el instalador `curl | bash` de x.ai. Esa ruta pone una segunda copia en `~/.grok/bin`, la antepone en `PATH` y sobrescribe el wrapper de Omarchy.

`dsh` abre su interfaz de navegador en `127.0.0.1:3080`, con el directorio de inicio como su espacio de trabajo predeterminado. Su interfaz de navegador no acepta un prompt inicial, así que `omarchy agent prompt` lo abre con el prompt en tu portapapeles para pegarlo. Omarchy lo inicia con el preset de permisos sin aprobación de DeepSeek. DeepSeek Harness sube los registros de sesión a DeepSeek cuando usas su API oficial de modelos; desactívalo en _Settings > General > Upload Session Log_ en su interfaz de navegador. Los comentarios que le envíes también se suben con la sesión, a menos que lo inicies con `DSH_TELEMETRY_MODE=DISABLED`.

### El agente predeterminado

Elige tu agente predeterminado con `omarchy default agent <name>` o en _Agente > Harness_ en el Menú de Omarchy (`Super + Space`). Si el agente aún no está instalado, al elegirlo se instala primero, y también obtiene su propio lanzador en el lanzador de aplicaciones, junto a Agent. Un Omarchy recién instalado te invitará a hacer esta elección con una notificación única.

Elegir Claude también intenta configurar su extensión de navegador para Chromium, Chrome, Brave, Brave Origin y Edge. La configuración de la extensión se aplica a todos los usuarios y puede pedir tu contraseña del sistema; cancelar o que falle la instalación de la extensión no impide seleccionar e iniciar Claude. Reinicia tu navegador, activa la extensión si se te pide e inicia sesión en Claude para terminar de conectarla. Ejecuta `/chrome` en Claude para comprobar la conexión. Firefox y Zen no son compatibles con esta extensión. Si Claude ya era tu predeterminado antes de que se añadiera esta configuración, selecciónalo de nuevo para instalar la extensión.

Una vez que hayas elegido, `Super + Shift + Ctrl + A` inicia el agente predeterminado en una ventana de terminal dedicada (o abre el selector si aún no has elegido). También puedes iniciarlo directamente en una tarea con `omarchy agent prompt "Review this project"`. Freebuff y DeepSeek Harness no aceptan un prompt inicial, así que se abren con el prompt en tu portapapeles para pegarlo. Los agentes iniciados así se ejecutan sin supervisión en sus respectivos modos de no detenerse a preguntar, ¡así que prepárate para que hagan cosas de verdad! MiniMax Code no tiene un modo así para sus sesiones interactivas, así que pide permisos como de costumbre. Y como los agentes se niegan a recordar la confianza para tu directorio personal, los inicios desde `$HOME` arrancan en `~/Work`.

También hay atajos de terminal: `a` ejecuta el agente predeterminado en línea en la terminal actual, mientras que `c`, `cx` y `cy` inician OpenCode, Claude Code y Codex directamente (también en sus modos de aprobación automática). Los cambios de tema también se sincronizan con los agentes: Claude Code, Pi, OpenCode y Hermes (una vez que Omarchy lo haya instalado) siguen el cambio cuando cambias el tema de Omarchy.

### Las instrucciones de tu agente

Las reglas personales para cada agente van en `~/.agents/AGENTS.md`, junto a las skills compartidas en `~/.agents/skills`. Ábrelo en _Agente > Instrucciones_, que también lo enlaza en cada harness que mantiene su propio archivo global: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` de Copilot, y así sucesivamente. Crush y Amp leen el enlace `~/.config/AGENTS.md`, mientras que omp, Kimi y DeepSeek Harness leen `~/.agents/AGENTS.md` directamente. Elegir un agente predeterminado también lo enlaza. Un archivo de instrucciones que ya tenías se convierte en el compartido si aún no había ninguno; en caso contrario se conserva junto al enlace como `.bak`. Ejecuta `omarchy agent instructions` para volver a enlazarlo después de instalar otro agente.

### El panel de agentes

La barra superior tiene un icono de agentes. Antes de que hayas configurado un agente, su panel te guía para iniciar sesión en Claude, Codex o Grok, y el primero se convierte en tu agente predeterminado. Después, el panel pone cada suscripción en una sola página: cada agente y cuenta con su plan, un medidor para cada uno de sus límites de sesión de 5 horas y semanal con el tiempo hasta que se restablece (pasa el cursor para ver el porcentaje exacto), o el saldo prepago restante, bajo una línea que rota por lo que has usado en todos ellos, como tokens esta semana y tu modelo más usado. En _Make something cool_ ofrece prompts iniciales para un tema, plugin, aplicación o juego nuevo que entregan la tarea a tu agente predeterminado. Las aplicaciones se construyen como las propias Hype, Monologue y Omacut de Omarchy, en C++ y Qt Quick, siguiendo la skill de agente omarchy-make-app, y el compilador y las piezas de Qt que necesitan vienen instalados. Los juegos son una sola página de three.js en `~/Games/vibes`, siguiendo la skill de agente omarchy-make-game, y todos se abren desde un único lanzador Game Vibes en el tema actual; cargan three.js desde la web, así que necesitan conexión para iniciar. Claude Code, Codex, Grok, Kimi, Cursor y su asignación Grok Bot, GitHub Copilot, Muse, Antigravity y Devin están cubiertos desde el primer momento con sus límites, Kimchi con su plan, créditos prepago y presupuestos de gasto, y Hermes, Mistral Vibe y Qwen Code muestran sus sesiones y tokens una vez que los hayas usado. Los planes y claves de proveedores que usas a través de pi, omp u opencode también aparecen: OpenCode Zen y Go, el Z.ai GLM Coding Plan, Ollama Cloud, el MiniMax Token Plan y Synthetic con sus límites; OpenRouter y DeepSeek con sus saldos prepago; Fireworks con su gasto en los últimos 30 días. Los tokens de modelos que ejecutas en tu propio hardware también cuentan para los totales; los modelos mismos tienen su propio panel, descrito en [Modelos locales](#local-models). Cada agente se cuenta una sola vez, bajo quien lo factura, sin importar por cuántos harnesses lo uses.

Haz clic izquierdo en el icono de la barra o pulsa `Super + Ctrl + X` para el panel, clic derecho para iniciar tu agente predeterminado y clic central para actualizar. Los registros de uso que lo alimentan se regeneran cada 15 minutos con `omarchy agent usage update`, y el panel incluso puede combinar el uso de tus otras máquinas mediante una carpeta sincronizada. Consulta el README en `$OMARCHY_PATH/shell/plugins/agents/` para ver todos los ajustes.

### Varias suscripciones

Si pagas más de un plan de Claude, Codex o Grok —uno personal Max y uno del trabajo, por ejemplo— Omarchy puede mantenerlos todos con sesión iniciada y moverse entre ellos. Añade una suscripción con el + en el panel de agentes, que te guía ahí mismo, o con `omarchy agent account add claude Work` (o `codex`, o `grok`). Instala la CLI si falta. La primera cuenta de un proveedor inicia sesión a través de tu navegador normal, justo donde la CLI siempre busca. Cada una después de esa inicia sesión a través de una ventana privada, para que la cuenta en la que tu navegador ya inició sesión no se tome por error; inicia sesión ahí como la cuenta que estás añadiendo y cierra antes cualquier ventana privada que ya tuvieras abierta. Nunca cierres sesión en la CLI para hacer esto: cerrar sesión revoca el inicio de sesión guardado y esa cuenta tendría que añadirse de nuevo.

Para copiar tus inicios de sesión de suscripción a otra máquina Omarchy por SSH, ejecuta `omarchy agent account copy user@laptop`. El remitente proporciona un receptor temporal cuando el destino no tiene uno instalado, así que las máquinas Omarchy más antiguas pueden recibir cuentas sin una actualización. Los receptores instalados tienen prioridad. Esto copia todas las suscripciones de Claude, Codex y Grok; añade nombres de proveedor para seleccionarlas, como en `omarchy agent account copy laptop claude`. Los nombres de cuenta y los ID de comando coinciden con el origen, incluidas las cuentas ya presentes en el destino. Las cuentas de destino no relacionadas reciben un sufijo numérico si sus nombres entran en conflicto, y los ajustes, skills, plugins y el historial de conversaciones permanecen locales en cada máquina.

Las credenciales de destino existentes se conservan. Una cuenta de origen que ya inició sesión allí ve sincronizado su nombre sin reemplazar sus credenciales; las demás cuentas se añaden junto a ella. Para reemplazar las credenciales guardadas de cuentas coincidentes, usa `omarchy agent account copy --replace laptop claude` después de cerrar las sesiones de esa cuenta en el destino. Un destino nuevo también obtiene la cuenta activa y las preferencias de cambio del origen; un destino establecido conserva las suyas.

Las credenciales viajan por SSH y se guardan en archivos privados en el destino, así que copia solo a máquinas en las que confíes. Esto es una copia única, no una sincronización continua. Los tokens de actualización de Codex pueden ser rotados por otra máquina, dejando un inicio de sesión copiado necesitado de renovación; los inicios de sesión separados siguen siendo la opción más fiable para uso simultáneo en varias máquinas. Consulta [la guía de autenticación de cuentas de Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Una cuenta por proveedor está activa, y cada sesión nueva empieza como ella: `cx`, `cy`, un simple `claude`, `codex` o `grok`, cualquier cosa iniciada a través de `omarchy agent`, y scripts o editores que encuentren la CLI en `PATH`. Cambia con `omarchy agent account use work` (y vuelve con `omarchy agent account use main`), o en el panel pulsando el número de una cuenta y luego `Enter` (o haciendo clic en su botón Use). Las sesiones de Claude en ejecución también cambian, desde su siguiente mensaje: cada sesión de Claude se ejecuta en `~/.claude`, que siempre contiene el inicio de sesión de la cuenta activa. Una sesión de Claude iniciada en la carpeta propia de una cuenta por un Omarchy anterior conserva ese inicio de sesión hasta que sale, así que el cambio nombra esas sesiones y termina por sí solo una vez que desaparezcan. Las sesiones de Codex y Grok en ejecución permanecen en la cuenta con la que empezaron. El historial de conversaciones, los ajustes, las skills y los plugins se comparten entre cuentas, así que `claude --continue` en la misma carpeta continúa donde lo dejaste en la cuenta nueva.

Con más de una cuenta, el panel muestra los límites de cada cuenta lado a lado, con la activa marcada. Por defecto Omarchy te avisa cuando la cuenta activa supera el 95% de un límite, y hacer clic en la notificación cambia a la cuenta con más margen. Pasa el cursor sobre la línea de una cuenta en el panel y haz clic en Autoswitch que aparece junto a Use (o pulsa `m`), o ejecuta `omarchy agent account mode auto`, para que cambie por sí solo; mientras está activado, Autoswitch ocupa el lugar de Use, y hacer clic de nuevo vuelve a avisar. Añade un número para cambiar el umbral, como en `omarchy agent account mode auto 90`. Si cada cuenta supera el umbral, te enterarás una vez, junto con qué cuenta se libera primero. Mientras una cuenta activa esté a menos de 15 puntos de su umbral (80% con el predeterminado), sus límites se comprueban cada tres minutos en lugar de cada 15.

`omarchy agent account list` muestra cada cuenta y sus límites más recientes, `omarchy agent account remove work` olvida una, y `omarchy agent account rename primary Hey` renombra una (o haz clic en el nombre de una cuenta en el panel). Estos comandos funcionan en las cuentas de tu agente predeterminado; para llegar al otro proveedor, nómbralo primero, como en `omarchy agent account use codex side`. El inicio de sesión que ya tenías en `~/.claude` o `~/.codex` es la cuenta _Main_. El de Codex permanece donde está; el de Claude espera en su propia carpeta mientras otra cuenta está activa. Una cuenta sin usar por más de unas ocho horas puede mostrar _Sign-in required_; haz clic en ella para volver a iniciar sesión en esa cuenta justo en el panel, o cambia a ella e inicia una sesión, que refresca el inicio de sesión por sí sola. Los servidores MCP que añades con `claude mcp add` llegan a cada cuenta de Claude, ya que todas se ejecutan en `~/.claude`; para Codex y Grok, los servidores que tenías cuando se añadió una cuenta la acompañan, pero los posteriores solo llegan a la cuenta en la que los añadiste. Claude Desktop mantiene su propio inicio de sesión, y las herramientas de Codex o Grok configuradas con una ruta absoluta a un binario de CLI no siguen el cambio. Un `CLAUDE_CONFIG_DIR`, `CODEX_HOME` o `GROK_HOME` explícito tiene prioridad sobre la cuenta seleccionada.

### Diagnóstico de fallos

Omarchy vigila systemd-coredump en busca de fallos de procesos. Una vez que hayas elegido un agente predeterminado, cualquier programa tuyo que haga un volcado de memoria trae una notificación "Process crashed" —haz clic en ella y el fallo se entrega a tu agente predeterminado junto con la skill omarchy-diagnose-crash de Omarchy, que guía al agente para establecer los hechos a partir del volcado de memoria y decidir si vale la pena reportar el fallo upstream. También puedes ejecutarlo a mano contra cualquier PID de `coredumpctl list` con `omarchy agent crash <pid>`.

La vigilancia está activada por defecto. Desactívala en _Trigger > Toggle > Crash Capture Off_ (o con `omarchy toggle crash-capture`) y las notificaciones se detienen; `omarchy agent crash <pid>` sigue funcionando a mano.

Los fallos también pueden silenciarse programa por programa, que es lo que el diagnóstico te ofrece al final. `omarchy crash mute hyprland` detiene las notificaciones solo para ese programa, `omarchy crash mute hyprland off` las trae de vuelta, y `omarchy crash mute` por sí solo lista lo que has silenciado. Acepta la ruta del binario tan bien como su nombre, así que `omarchy crash mute /usr/bin/hyprland` hace lo mismo. Pon entre comillas un nombre con un espacio, como en `omarchy crash mute 'Some App'`. Todo lo demás sigue avisando, y el programa silenciado sigue fallando —esto oculta el recordatorio, no arregla nada.

### Aplicaciones de escritorio

El menú _Instalar > IA_ también incluye algunas aplicaciones gráficas de IA: Amp Desktop, Antigravity Desktop, la aplicación de escritorio de ChatGPT, la aplicación de escritorio de Claude (la beta para Linux de Anthropic, con pestañas Chat, Cowork y Claude Code), Grok Bot para chatear con los modelos de xAI, Herdr Desktop, Hermes Desktop, OpenClaw, la aplicación de escritorio de Perplexity y T3 Code. Grok Bot es la aplicación de chat de escritorio. El agente de programación es el comando `grok`.

Hermes Desktop es la que debes conocer, porque una máquina tiene un solo Hermes, y es el de la aplicación: Hermes solo se instala a través de la aplicación, y el comando `hermes` que ejecuta el agente predeterminado es el de la aplicación. Elegir Hermes como agente predeterminado instala lo mismo que la entrada _Instalar > IA_: el paquete y un runtime de Hermes en `~/.hermes` configurado por el propio instalador de Hermes, que tarda unos minutos la primera vez. Ese runtime es el único Hermes que usan el comando `hermes` de terminal, el agente predeterminado y la aplicación, y se actualiza a sí mismo con `hermes update` en lugar de esperar una versión de Omarchy. Instalarlo también le da a Hermes el tema de Omarchy como un skin llamado `omarchy`, que cada superficie de Hermes sigue cuando cambias temas; elige otro en los ajustes de Appearance de Hermes o con `/skin` si prefieres que no lo haga, y Omarchy respeta esa elección. Eliminar la aplicación en _Eliminar > IA_ cierra Hermes primero, gateway incluido, se lleva ese runtime con ella y conserva tus chats, recuerdos y las skills que Hermes escribió para sí mismo a menos que le digas lo contrario: pregunta, con no por defecto, si esos datos y tus ajustes de conexión también deben irse.

La experiencia de escritorio de OpenClaw es su Control UI, que se abre como una aplicación web respaldada por su propio gateway local. OpenClaw vive en `~/.openclaw` y se actualiza a sí mismo: usa el botón "Update Gateway" de la Control UI o ejecuta `openclaw update`, y el gateway se reinicia en la nueva versión. Omarchy solo elige la versión desde la que empieza una instalación nueva. OpenClaw también puede ser tu agente predeterminado: elegirlo en _Agente > Harness_ configura esa misma copia en `~/.openclaw`, y el agente abre la interfaz de terminal de OpenClaw conectada a su gateway. Eliminar OpenClaw en _Eliminar > IA_ se lleva el servicio del gateway y la aplicación con él y luego pregunta si `~/.openclaw` también debe irse, ya que ahí están tus chats y credenciales junto con el propio OpenClaw y los runtimes de plugins que descarga; por defecto lo conserva, e instalar OpenClaw de nuevo lo recupera.

Herdr Desktop es la aplicación de escritorio de [Herdr](https://herdr.dev): espacios, pestañas y paneles de terminales y agentes de programación que siguen ejecutándose en su núcleo cuando cierras la ventana. Viene del propio instalador de Herdr en lugar de un paquete, así que vive en `~/.local/share/herdr-app`, trae su núcleo en `~/.local/bin/herdr-core` cuando aún no tienes uno, y se actualiza a sí mismo en ambos. Se sitúa junto al comando `herdr` que Omarchy incluye en `Super + Ctrl + Return` en lugar de reemplazarlo, y obtiene las teclas directas de ese comando: `Alt + Return` y `Alt + Shift + Return` dividen un panel hacia abajo o a la derecha, `Alt + Escape` lo cierra, `Ctrl + Alt + Arrow` se mueve entre paneles, `Alt + 1..9` y `Alt + Left/Right` eligen una pestaña, y `Alt + Up/Down` se mueven entre espacios. `Ctrl + 1..9` elige un espacio y `Alt + Shift + Up/Down` recorre los agentes. Las teclas de prefijo `Ctrl + Space` permanecen solo en terminal, ya que la aplicación no puede mantener una tecla Ctrl simple para una secuencia. Omarchy escribe estas en `~/.config/herdr-app/keys.json`, y `omarchy-refresh-herdr-app` las restablece. Instalarlo elige el tema Omarchy de Herdr, que sigue tu tema de Omarchy desde entonces. Herdr mantiene un tema para modo claro y uno para modo oscuro, así que después de cambiar entre un tema Omarchy oscuro y uno claro, elige Omarchy en el selector de temas de Herdr una vez más para el otro modo.

T3 Code se ejecuta desde su AppImage oficial en `~/.local/share/t3code` en lugar de desde un paquete, así que se actualiza a sí mismo. Instalarlo pregunta si empezar en el canal Stable o Nightly; cambia después en los ajustes de T3 Code. Tus hilos y ajustes viven en `~/.t3`, y eliminar T3 Code en _Eliminar > IA_ se los lleva con él.

### Modelos locales

Ejecuta un modelo abierto en tu propia máquina para tus agentes de programación. Tus prompts y código permanecen en la máquina; nada enviado al modelo sale de ella. Empieza con:

```bash
omarchy models use best text
```

Eso configura el mejor modelo de texto para esta máquina, el tipo que usan tus agentes. Los modelos de imagen, video y música tienen su propio mejor: `omarchy models use best image`, `video` o `music`. Ejecuta `omarchy models use best` para ver la elección de cada tipo para esta máquina.

O abre el panel de modelos locales desde su icono de destellos en la barra superior, junto al icono de agentes, o con Super + Ctrl + Alt + X, y elige +. El icono aparece cuando un modelo encaja en esta máquina. Podman, que ejecuta los modelos, viene con Omarchy, igual que el kit de herramientas de contenedores de NVIDIA en una máquina NVIDIA, que les da la GPU; si falta alguno, la primera configuración lo instala. Omarchy luego elige el modelo recomendado para esta máquina, lo descarga y lo inicia. Espera una descarga de decenas de GB y que la mayor parte de la memoria de la máquina esté en uso mientras el modelo se ejecuta: Flash Next usa unos 100 GiB con su contexto completo de 256K. Si otros modelos ocupan la memoria que necesita, se configura detenido, listo para iniciar una vez que detengas uno. El modelo se detiene al cerrar sesión; detenlo tú mismo cuando necesites la memoria para otra cosa.

`omarchy models list` muestra las opciones y explica por qué algunas no encajan. Para configurar otro, ejecuta `omarchy models use <recipe>`. Hoy, `qwen3.8-flash-next-gufo` y `qwen3.8-27b-gufo` están disponibles para máquinas Strix Halo de 128 GB; el de 27B ocupa unos 40 GiB, así que deja espacio para otro trabajo. En una laptop de 64 GB con Arc B390 de Intel, `qwen3.6-35b-a3b-llamacpp` se ejecuta en unos 30 GiB. Las nuevas recetas y recomendaciones llegan con `omarchy update`, a través del paquete.

Cada modelo que configuras obtiene su propia línea en el panel de modelos locales: play para iniciarlo, pause para detenerlo y liberar su memoria, y el botón de terminal para abrir tu agente en él. En la parte superior, una barra muestra cómo se divide la memoria de la máquina entre el propio Omarchy (el sistema y tus aplicaciones), cada modelo en ejecución y lo que está libre. Apunta a un modelo detenido y la barra muestra si encaja, o cuánto le falta. Varios pueden ejecutarse a la vez cuando encajan juntos en memoria; si uno no encaja, Omarchy dice qué modelo en ejecución detener. Arrastra las líneas por su logo para reordenarlas, y pulsa Delete en una línea seleccionada para eliminar un modelo y su descarga.

Cada modelo que configuras también obtiene su propia entrada en el lanzador de aplicaciones, bajo el nombre del modelo y con el logo de su creador, igual que iniciar sesión en Claude, Codex o Grok añade una. Abre tu agente en ese modelo y lo inicia primero si no está en ejecución: la terminal lo muestra cargando y entrega al agente una vez que está listo. Eliminar un modelo elimina su entrada.

No todos los modelos son para programar. Los modelos de imagen, video y música se abren en Fantasi en su lugar, la aplicación de Omarchy para hacer imágenes, video y música con un modelo ejecutándose en esta máquina, desde su entrada en el lanzador y desde su línea en el panel de modelos locales.

Un modelo sigue ejecutándose exactamente como se configuró, así que una actualización de Omarchy nunca reinicia uno bajo tus agentes. Cuando Omarchy tiene un runtime más nuevo o pesos más nuevos para un modelo que configuraste, su línea muestra un botón de actualización: púlsalo y el modelo se configura de nuevo en segundo plano, descargando solo lo que cambió, y se reinicia en la nueva versión. Un modelo que estaba detenido permanece detenido. `omarchy models update` hace lo mismo para cada modelo desde una terminal.

Desde la línea de comandos, `omarchy models start <recipe>` y `omarchy models stop <recipe>` hacen lo mismo, `omarchy models status` muestra cada modelo, y `omarchy agent --local` abre tu agente predeterminado en el último modelo que iniciaste. pi, OpenCode y Qwen Code pueden usar uno; con cualquier otro predeterminado se abre en pi, o en OpenCode si no tienes pi. pi también lista cada modelo que configuraste, y los de máquinas con las que te emparejaste, en su propio selector de modelos, así que un simple `pi` también llega a ellos. Cualquier cliente compatible con OpenAI también puede conectarse: `status` muestra la dirección de cada modelo (la primera es `http://127.0.0.1:11435/v1`), el nombre de la receta es el modelo, y la clave está en `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` elimina un modelo y las descargas que ningún otro modelo usa.

Los runtimes de terceros están etiquetados con su editor. Omarchy ejecuta cada modelo sin acceso a la red.

### LLM locales

Omarchy recomienda dos formas de ejecutar modelos LLM locales: LM Studio y Ollama. LM Studio proporciona una interfaz GUI para encontrar modelos de pesos abiertos, instalarlos y ejecutarlos. Es una gran forma de empezar fácilmente. Ollama ofrece una CLI para hacer lo mismo. Pero si eres nuevo en modelos locales, yo empezaría con LM Studio. Puedes instalar cualquiera en _Instalar > IA_ en el Menú de Omarchy.

### Las skills de Omarchy

Las skills de agente ayudan a la IA a usar herramientas específicas de una forma específica, y Omarchy incluye siete de ellas. La skill omarchy cubre personalizar el sistema, como ajustar tu configuración de Hyprland o ajustar la barra. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app y omarchy-make-game cubren hacer algo nuevo, omarchy-contribute cubre reportar un error o enviar una corrección upstream, y omarchy-diagnose-crash trabaja a través del volcado de memoria de un fallo. Están enlazadas mediante symlink en los directorios de skills para Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` y cada `~/.hermes/profiles/*/skills`), y la ubicación genérica `~/.agents/skills`, así que la mayoría de los harnesses las recogen automáticamente. Una carpeta de skill propia con el mismo nombre tiene prioridad.

Pero debes tratar estas skills como experimentales. Distintos modelos las usarán con distinto efecto. Es mejor ejecutar primero en modo plan, para que tengas una idea de lo que el agente querría cambiar. Y luego prepárate para revertir cambios o incluso invocar `omarchy reinstall configs`, si el agente hace un desastre con todo.
