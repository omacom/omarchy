# IA

Omarchy incluye lanzadores para los agentes de programación siguientes sin elegir uno predeterminado por ti. Ejecuta un comando para instalar su CLI la primera vez que lo uses y luego autentícate cuando se te pida. Hermes es la excepción: no se instala nada para él en el primer uso, y al elegirlo se instala Hermes Desktop, como explica _Aplicaciones de escritorio_ más abajo.

### Instalación y actualización de agentes

Salvo Hermes, estos agentes usan la instalación diferida de mise: el primer inicio instala el CLI, y los inicios posteriores lo reutilizan. mise también comprueba si hay una versión nueva de un agente instalado como máximo una vez cada cuatro horas, justo antes de que inicie o en segundo plano en un prompt del shell. Si esa actualización falla o no tienes conexión, se ejecuta la versión instalada. `omarchy update` actualiza los agentes instalados junto con el resto de Omarchy, y `mup` actualiza solo las herramientas administradas por mise.

El actualizador propio de un agente, como `claude update`, `codex update` o un botón de actualización en una app, no actualiza la instalación administrada por mise. `codex update` falla, y `claude update` puede indicar que todo salió bien mientras instala una copia aparte que mise no sigue. Si prefieres usar el instalador y el actualizador nativos de un agente, agrégalo a `disable_tools`; consulta [Herramientas CLI preinstaladas](18-development-tools.md#preinstalled-cli-tools).

Para instalar todas las herramientas diferidas configuradas antes de que las necesites, ejecuta `mise install --include-lazy`. Esto incluye las demás herramientas CLI predeterminadas de Omarchy, además de los agentes. Consulta [Herramientas CLI preinstaladas](18-development-tools.md#preinstalled-cli-tools) para instalar una sola herramienta o usar tu propia instalación.

`grok` se instala mediante el paquete `grok` oficial de mise, igual que `claude` y `codex`. Ejecuta `grok`, o elígelo en _Agente > Harness_. Sáltate el instalador con `curl | bash` de x.ai. Esa ruta pone una segunda copia en `~/.grok/bin`, la antepone en `PATH` y sobrescribe el wrapper de Omarchy.

`dsh` abre su interfaz de navegador en `127.0.0.1:3080`, con el directorio de lanzamiento como su espacio de trabajo predeterminado. Su interfaz de navegador no acepta un prompt inicial, así que `omarchy agent prompt` lo abre con el prompt en tu portapapeles para que lo pegues. Omarchy lo inicia con el preajuste de permisos sin aprobación de DeepSeek. DeepSeek Harness sube los registros de sesión a DeepSeek cuando usas su API oficial de modelos; desactívalo en _Settings > General > Upload Session Log_ en su interfaz de navegador. Los comentarios que le envíes también se suben con la sesión, a menos que lo inicies con `DSH_TELEMETRY_MODE=DISABLED`.

### El agente predeterminado

Elige tu agente predeterminado con `omarchy default agent <name>` o en _Agente > Harness_ en el Menú de Omarchy (`Super + Space`). Si el agente aún no está instalado, al elegirlo se instala primero. Un Omarchy recién instalado te invitará a hacer esta elección con una notificación única.

Elegir Claude también intenta configurar su extensión de navegador para Chromium, Chrome, Brave, Brave Origin y Edge. La configuración de la extensión se aplica a todos los usuarios y puede pedir tu contraseña del sistema; cancelar o que falle la instalación de la extensión no impide que Claude quede seleccionado y se inicie. Reinicia tu navegador, activa la extensión si se te pide e inicia sesión en Claude para terminar de conectarla. Ejecuta `/chrome` en Claude para comprobar la conexión. Firefox y Zen no son compatibles con esta extensión. Si Claude ya era tu predeterminado antes de que se agregara esta configuración, selecciónalo de nuevo para instalar la extensión.

Una vez que hayas elegido, `Super + Shift + Ctrl + A` inicia el agente predeterminado en una ventana de terminal dedicada (o muestra el selector si aún no has elegido). También puedes iniciarlo directamente en una tarea con `omarchy agent prompt "Review this project"`. Freebuff y DeepSeek Harness no aceptan un prompt inicial, así que se abren con el prompt en tu portapapeles para que lo pegues. Los agentes iniciados así se ejecutan sin supervisión en sus respectivos modos de no detenerse a preguntar, ¡así que prepárate para que de verdad hagan cosas! MiniMax Code no tiene un modo así para sus sesiones interactivas, así que pide permisos como de costumbre. Y como los agentes se niegan a recordar la confianza para tu directorio personal, los inicios desde `$HOME` arrancan en `~/Work`.

También hay atajos de terminal: `a` ejecuta el agente predeterminado en línea en la terminal actual, mientras que `c`, `cx` y `cy` inician OpenCode, Claude Code y Codex directamente (también en sus modos de aprobación automática). Los cambios de tema también se sincronizan con los agentes: Claude Code, Pi, OpenCode y Hermes (una vez que Omarchy lo haya instalado) siguen el cambio cuando cambias el tema de Omarchy.

### Las instrucciones de tu agente

Las reglas personales para cada agente van en `~/.agents/AGENTS.md`, junto a las skills compartidas en `~/.agents/skills`. Ábrelo en _Agente > Instrucciones_, que también lo enlaza en cada harness que mantiene su propio archivo global: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, el `~/.copilot/copilot-instructions.md` de Copilot, etcétera. Crush y Amp leen el enlace `~/.config/AGENTS.md`, mientras que omp, Kimi y DeepSeek Harness leen `~/.agents/AGENTS.md` directamente. Elegir un agente predeterminado también lo enlaza. Un archivo de instrucciones que ya tenías se convierte en el compartido si aún no había ninguno; en caso contrario, se conserva junto al enlace como `.bak`. Ejecuta `omarchy agent instructions` para volver a enlazarlo después de instalar otro agente.

### El panel de agentes

La barra superior tiene un icono de agentes. Antes de que hayas configurado un agente, su panel te guía para iniciar sesión en Claude, Codex o Grok, y el primero se convierte en tu agente predeterminado. Después de eso, el panel pone cada suscripción en una sola página: cada agente y cuenta con su plan, un medidor para cada uno de sus límites de sesión de 5 horas y semanales con el tiempo que falta para que se restablezca (pasa el cursor por encima para ver el porcentaje exacto), o el saldo de prepago restante, bajo una línea que va rotando por lo que has usado en todos ellos, como los tokens de esta semana y tu modelo más usado. En _Crea algo_ ofrece prompts iniciales para un tema, plugin o app nuevos que entregan la tarea a tu agente predeterminado. Las apps se crean como se crean Hype, Monologue y Omacut, las propias de Omarchy, en C++ y Qt Quick, siguiendo la skill de agente omarchy-app, y el compilador y las piezas de Qt que necesitan ya vienen instalados. Claude Code, Codex, Grok, Kimi, Cursor y su asignación de Grok Bot, GitHub Copilot, Muse, Antigravity, Kimchi y Devin están cubiertos desde el inicio con sus límites, y Hermes, Mistral Vibe y Qwen Code muestran sus sesiones y tokens una vez que los has usado. Los planes y claves de proveedores que usas mediante pi, omp u opencode también aparecen: OpenCode Zen y Go, el Z.ai GLM Coding Plan, Ollama Cloud, el MiniMax Token Plan y Synthetic con sus límites; Fireworks, OpenRouter y DeepSeek con sus saldos de prepago; y los modelos que ejecutas en tu propio hardware en Modelos locales. Cada agente se cuenta una sola vez, bajo quien lo factura, sin importar por cuántos harnesses lo uses.

Haz clic izquierdo en el icono de la barra para abrir el panel y clic derecho para iniciar tu agente predeterminado. Los registros de uso detrás de él se regeneran cada 15 minutos con `omarchy agent usage-update`, y el panel incluso puede combinar el uso de tus otras máquinas mediante una carpeta sincronizada. Consulta el README en `$OMARCHY_PATH/shell/plugins/agents/` para ver toda la configuración.

### Varias suscripciones

Si pagas más de un plan de Claude, Codex o Grok —un Max personal y uno del trabajo, por ejemplo—, Omarchy puede mantenerlos todos con la sesión iniciada y moverse entre ellos. Agrega una suscripción con el + en el panel de agentes, que te guía ahí mismo, o con `omarchy agent account add claude Work` (o `codex`, o `grok`). Instala el CLI si falta. La primera cuenta de un proveedor inicia sesión mediante tu navegador normal, justo donde el CLI siempre busca. Cada una después de esa inicia sesión mediante una ventana privada, para que la cuenta en la que tu navegador ya tiene la sesión iniciada no se tome por error; inicia sesión ahí como la cuenta que estás agregando y cierra antes cualquier ventana privada que ya tuvieras abierta. Nunca cierres la sesión del CLI para hacer esto: cerrar la sesión revoca el inicio de sesión guardado, y esa cuenta tendría que agregarse de nuevo.

Para copiar tus inicios de sesión de suscripción a otra máquina con Omarchy por SSH, ejecuta `omarchy agent account copy user@laptop`. El emisor proporciona un receptor temporal cuando el destino no tiene uno instalado, así que las máquinas con Omarchy más antiguas pueden recibir cuentas sin una actualización. Los receptores instalados tienen prioridad. Esto copia todas las suscripciones de Claude, Codex y Grok; agrega nombres de proveedores para seleccionarlas, como en `omarchy agent account copy laptop claude`. Los nombres de cuenta y los ID de comando coinciden con el origen, incluidas las cuentas que ya están presentes en el destino. Las cuentas de destino no relacionadas reciben un sufijo numérico si sus nombres entran en conflicto, y la configuración, las skills, los plugins y el historial de conversaciones permanecen locales en cada máquina.

Las credenciales existentes en el destino se conservan. Una cuenta de origen que ya tiene la sesión iniciada ahí sincroniza su nombre sin reemplazar sus credenciales; las demás cuentas se agregan junto a ella. Para reemplazar las credenciales guardadas de las cuentas coincidentes, usa `omarchy agent account copy --replace laptop claude` después de salir de las sesiones de esa cuenta en el destino. Un destino nuevo también recibe la cuenta activa y las preferencias de cambio del origen; un destino ya establecido conserva las suyas.

Las credenciales viajan por SSH y se almacenan en archivos privados en el destino, así que copia solo a máquinas en las que confíes. Es una copia única, no una sincronización continua. Otra máquina puede rotar los tokens de actualización de Codex, lo que deja un inicio de sesión copiado necesitado de renovación; los inicios de sesión por separado siguen siendo la opción más confiable para usarlo simultáneamente en varias máquinas. Consulta la [guía de autenticación de cuentas de Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Una cuenta por proveedor está activa, y cada sesión nueva empieza como ella: `cx`, `cy`, un `claude`, `codex` o `grok` a secas, cualquier cosa iniciada mediante `omarchy agent`, y los scripts o editores que encuentran el CLI en `PATH`. Cambia con `omarchy agent account use work` (y vuelve con `omarchy agent account use main`), o en el panel presionando el número de una cuenta y luego `Enter` (o haciendo clic en su botón Use). Las sesiones que ya están en ejecución permanecen en la cuenta con la que empezaron. El historial de conversaciones, la configuración, las skills y los plugins se comparten entre cuentas, así que `claude --continue` en la misma carpeta retoma donde lo dejaste en la cuenta nueva.

Con más de una cuenta, el panel muestra los límites de cada cuenta uno al lado del otro, con la activa marcada. Por defecto, Omarchy te avisa cuando la cuenta activa supera el 95% de un límite, y al hacer clic en la notificación cambia a la cuenta con más margen. Pasa el cursor por encima de la línea de una cuenta en el panel y haz clic en el Autoswitch que aparece junto a Use (o presiona `m`), o ejecuta `omarchy agent account mode auto`, para que cambie por sí solo; mientras está activado, Autoswitch ocupa el lugar de Use, y al hacer clic de nuevo vuelve a avisar. Agrega un número para cambiar el umbral, como en `omarchy agent account mode auto 90`. Si todas las cuentas superan el umbral, te enterarás una vez, junto con qué cuenta se libera primero. Mientras una cuenta activa esté a menos de 15 puntos de su umbral (80% con el valor predeterminado), sus límites se comprueban cada tres minutos en lugar de cada 15.

`omarchy agent account list` muestra cada cuenta y sus límites más recientes, `omarchy agent account remove work` olvida una, y `omarchy agent account rename primary Hey` cambia el nombre de una (o haz clic en el nombre de una cuenta en el panel). Estos comandos funcionan en las cuentas de tu agente predeterminado; para llegar al otro proveedor, nómbralo primero, como en `omarchy agent account use codex side`. El inicio de sesión que ya tenías en `~/.claude` o `~/.codex` es la cuenta _Main_ y se queda donde está. Una cuenta que no se usa durante más de unas ocho horas puede mostrar _Sign-in required_; haz clic en ella para volver a iniciar sesión con esa cuenta ahí mismo en el panel, o inicia una sesión en ella, lo que actualiza el inicio de sesión por sí solo. Los servidores MCP que tenías cuando se agregó una cuenta pasan a ella, pero los que agregues después con `claude mcp add` solo llegan a la cuenta en la que los agregaste. Claude Desktop y las herramientas configuradas con una ruta absoluta a un binario del CLI no siguen el cambio. Un `CLAUDE_CONFIG_DIR`, `CODEX_HOME` o `GROK_HOME` explícito tiene prioridad sobre la cuenta seleccionada.

### Diagnóstico de fallos

Omarchy vigila systemd-coredump en busca de fallos de procesos. Cuando algo falla con un segfault, recibirás una notificación de "Process crashed": haz clic en ella, y el fallo se entrega a tu agente predeterminado junto con la skill diagnose-crash de Omarchy, que guía al agente para establecer los hechos a partir del volcado de memoria y decidir si vale la pena reportar el fallo al proyecto original. También puedes ejecutarlo a mano contra cualquier PID de `coredumpctl list` con `omarchy agent crash <pid>`.

La vigilancia está activada por defecto. Desactívala en _Trigger > Toggle > Crash Capture_ (o con `omarchy toggle crash-capture`) y las notificaciones se detienen; `omarchy agent crash <pid>` sigue funcionando a mano.

Los fallos también se pueden silenciar programa por programa, que es lo que el diagnóstico te ofrece al final. `omarchy crash mute hyprland` detiene las notificaciones solo para ese programa, `omarchy crash mute hyprland off` las trae de vuelta, y `omarchy crash mute` por sí solo enumera lo que has silenciado. Acepta la ruta del binario con la misma facilidad que su nombre, así que `omarchy crash mute /usr/bin/hyprland` hace lo mismo. Pon entre comillas un nombre que tenga un espacio, como en `omarchy crash mute 'Some App'`. Todo lo demás sigue avisando, y el programa silenciado sigue fallando: esto oculta el recordatorio, no arregla nada.

### Aplicaciones de escritorio

El menú _Instalar > IA_ también incluye algunas apps gráficas de IA: la app de escritorio de ChatGPT, la app de escritorio de Claude (la beta para Linux de Anthropic, con pestañas de Chat, Cowork y Claude Code), Grok Bot para chatear con los modelos de xAI, Herdr Desktop, Hermes Desktop, OpenClaw, la app de escritorio de Perplexity y T3 Code. Grok Bot es la app de chat de escritorio. El agente de programación es el comando `grok`.

Hermes Desktop es la que debes conocer, porque una máquina tiene un solo Hermes, y es el de la app: Hermes solo se instala mediante la app, y el comando `hermes` que ejecuta el agente predeterminado es el de la app. Elegir Hermes como el agente predeterminado instala lo mismo que la entrada _Instalar > IA_: el paquete y un entorno de ejecución de Hermes en `~/.hermes` configurado por el propio instalador de Hermes, lo que tarda unos minutos la primera vez. Ese entorno de ejecución es el único Hermes que usan el comando `hermes` de la terminal, el agente predeterminado y la app, y se actualiza solo con `hermes update` en lugar de esperar a una versión de Omarchy. Al instalarlo también se entrega a Hermes el tema de Omarchy como una skin llamada `omarchy`, que cada superficie de Hermes sigue cuando cambias de tema; elige otra en los ajustes de Apariencia de Hermes o con `/skin` si prefieres que no lo haga, y Omarchy respeta esa elección. Eliminar la app en _Eliminar > IA_ cierra Hermes primero, gateway incluido, se lleva ese entorno de ejecución con ella y conserva tus chats, memorias y las skills que Hermes escribió para sí mismo a menos que le digas lo contrario: pregunta, con «no» como respuesta predeterminada, si esos datos y tu configuración de conexión también deben irse.

La experiencia de escritorio de OpenClaw es su Control UI, que se abre como una app web respaldada por su propio gateway local. OpenClaw vive en `~/.openclaw` y se actualiza solo: usa el botón "Update Gateway" de la Control UI o ejecuta `openclaw update`, y el gateway se reinicia con la versión nueva. Omarchy solo elige la versión con la que empieza una instalación nueva. Eliminar OpenClaw en _Eliminar > IA_ se lleva el servicio del gateway y la app con él y luego pregunta si `~/.openclaw` también debe irse, ya que ahí están tus chats y credenciales junto con el propio OpenClaw y los entornos de ejecución de plugins que descarga; la opción predeterminada lo conserva, e instalar OpenClaw de nuevo lo retoma.

Herdr Desktop es la app de escritorio de [Herdr](https://herdr.dev): espacios, pestañas y paneles de terminales y agentes de programación que siguen ejecutándose en su núcleo cuando cierras la ventana. Viene del propio instalador de Herdr y no de un paquete, así que vive en `~/.local/share/herdr-app`, trae su núcleo en `~/.local/bin/herdr-core` cuando aún no tienes uno, y actualiza ambos por sí mismo. Está junto al comando `herdr` que Omarchy incluye asignado a `Super + Ctrl + Return`, en lugar de reemplazarlo, y recibe las teclas directas de ese comando: `Alt + Return` y `Alt + Shift + Return` dividen un panel hacia abajo o hacia la derecha, `Alt + Escape` lo cierra, `Ctrl + Alt + Arrow` se mueve entre paneles, `Alt + 1..9` y `Alt + Left/Right` eligen una pestaña, y `Alt + Up/Down` se mueven entre espacios. `Ctrl + 1..9` elige un espacio y `Alt + Shift + Up/Down` recorre los agentes. Las teclas con el prefijo `Ctrl + Space` se quedan solo en la terminal, ya que la app no puede mantener presionada una tecla Ctrl simple para una secuencia. Omarchy escribe estas en `~/.config/herdr-app/keys.json`, y `omarchy-refresh-herdr-app` las restablece. Al instalarlo se elige el tema Omarchy de Herdr, que sigue tu tema de Omarchy a partir de entonces. Herdr mantiene un tema para el modo claro y uno para el oscuro, así que después de cambiar entre un tema de Omarchy oscuro y uno claro, elige Omarchy en el selector de temas de Herdr una vez más para el otro modo.

T3 Code se ejecuta desde su versión oficial en AppImage en `~/.local/share/t3code` y no desde un paquete, así que se actualiza solo. Al instalarlo se te pregunta si quieres empezar en el canal Stable o Nightly; cámbialo después en los ajustes de T3 Code. Tus hilos y ajustes viven en `~/.t3`, y eliminar T3 Code en _Eliminar > IA_ se los lleva con él.

### Modelos locales

Ejecuta un modelo abierto en tu propia máquina para tus agentes de programación. Tus prompts y tu código se quedan en la máquina; nada de lo que se envía al modelo sale de ella. Empieza con:

```bash
omarchy agent local use best
```

O, en el panel de agentes de la barra superior, elige + y luego IA local, que aparece cuando un modelo cabe en esta máquina. La primera vez, esto instala Podman, que ejecuta los modelos, y en una máquina NVIDIA el kit de herramientas de contenedores de NVIDIA, que les da la GPU. Luego Omarchy elige el modelo recomendado para esta máquina, lo descarga y lo inicia. Espera una descarga de decenas de GB y que la mayor parte de la memoria de la máquina esté en uso mientras el modelo se ejecuta: Flash Next usa unos 100 GiB con su contexto completo de 256K. Si otros modelos ocupan la memoria que necesita, queda configurado detenido, listo para iniciarse en cuanto detengas uno. El modelo se detiene al cerrar sesión; deténlo tú mismo cuando necesites la memoria para otra cosa.

`omarchy agent local list` muestra las opciones y explica por qué algunas no caben. Para configurar otro, ejecuta `omarchy agent local use <recipe>`. Hoy, `qwen3.8-flash-next-gufo` y `qwen3.8-27b-gufo` están disponibles para máquinas Strix Halo de 128 GB; el de 27B ocupa unos 40 GiB, así que deja espacio para otro trabajo. Las recetas y recomendaciones nuevas llegan con `omarchy update`, mediante el paquete.

Cada modelo que configuras tiene su propia línea en el panel de agentes, junto a tus suscripciones: reproducir para iniciarlo, pausar para detenerlo y liberar su memoria, y el botón de terminal para abrir tu agente en él. Varios pueden ejecutarse a la vez cuando caben juntos en la memoria; si uno no cabe, Omarchy dice qué modelo en ejecución debes detener. Arrastra las líneas para reordenarlas y presiona Delete en una línea seleccionada para eliminar un modelo y su descarga.

Desde la línea de comandos, `omarchy agent local start <recipe>` y `omarchy agent local stop <recipe>` hacen lo mismo, `omarchy agent local status` muestra cada modelo, y `omarchy agent --local` abre tu agente predeterminado en el último modelo que iniciaste. pi, OpenCode y Qwen Code pueden usar uno; con cualquier otro predeterminado se abre en pi. pi también enumera cada modelo que has configurado, y los de las máquinas con las que te has emparejado, en su propio selector de modelos, así que un `pi` a secas también llega a ellos. Cualquier cliente compatible con OpenAI también puede conectarse: `status` muestra la dirección de cada modelo (la primera es `http://127.0.0.1:11435/v1`), el nombre de la receta es el modelo y la clave está en `~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` elimina un modelo y las descargas que ningún otro modelo usa.

Los entornos de ejecución de terceros están etiquetados con su editor. Omarchy ejecuta cada modelo sin acceso a la red.

### LLM locales

Omarchy recomienda dos formas de ejecutar modelos LLM locales: LM Studio y Ollama. LM Studio proporciona una interfaz GUI para encontrar modelos de pesos abiertos, instalarlos y ejecutarlos. Es una forma excelente de empezar fácilmente. Ollama ofrece un CLI para hacer lo mismo de forma similar. Pero si eres nuevo en los modelos locales, yo empezaría con LM Studio. Puedes instalar cualquiera de los dos en _Instalar > IA_ en el Menú de Omarchy.

### La skill de Omarchy

Las skills de agente ayudan a la IA a usar herramientas específicas de una forma específica, y Omarchy incluye una skill predeterminada para ajustar el sistema a tu medida. Como retocar tu configuración de Hyprland, ajustar la barra o incluso crear un tema nuevo desde cero. Está enlazada mediante enlaces simbólicos en los directorios de skills de Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` y cada `~/.hermes/profiles/*/skills`), y la ubicación genérica `~/.agents/skills`, así que la mayoría de los harnesses la detectan automáticamente.

Pero debes tratar esta skill como experimental. Los distintos modelos la usarán con efectos diferentes. Es mejor ejecutarla primero en modo de planificación, para que tengas una idea de lo que el agente querría cambiar. Y luego prepárate para revertir los cambios o incluso invocar `omarchy reinstall configs`, si el agente hace un desastre con todo.
