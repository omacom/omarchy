# IA

Omarchy incluye lanzadores para los agentes de programación siguientes sin elegir uno predeterminado por ti. Ejecuta un comando para instalar su CLI la primera vez que lo uses y luego autentícate cuando se te pida. Hermes es la excepción: no se instala nada para él en el primer uso, y al elegirlo se instala Hermes Desktop, como explica _Aplicaciones de escritorio_ más abajo.

### Instalación y actualización de agentes

Excepto Hermes, estos agentes utilizan la instalación diferida de mise: el primer inicio instala el CLI, y los inicios posteriores lo reutilizan. mise también verifica si hay una versión nueva de un agente instalado como máximo una vez cada cuatro horas, justo antes de que inicie o en segundo plano en un prompt del shell. Si esa actualización falla o no tienes conexión, se ejecuta la versión instalada. `omarchy update` actualiza los agentes instalados junto con el resto de Omarchy, y `mup` actualiza únicamente las herramientas gestionadas por mise.

El actualizador propio de un agente, como `claude update`, `codex update` o un botón de actualización en una aplicación, no actualiza la instalación gestionada por mise. `codex update` falla, y `claude update` puede informar que tuvo éxito mientras instala una copia aparte que mise no rastrea. Si prefieres utilizar el instalador y actualizador nativos de un agente, agrégalo a `disable_tools`; consulta [Herramientas CLI preinstaladas](18-development-tools.md#preinstalled-cli-tools).

Para instalar todas las herramientas diferidas configuradas antes de que las necesites, ejecuta `mise install --include-lazy`. Esto incluye las demás herramientas CLI predeterminadas de Omarchy, además de los agentes. Consulta [Herramientas CLI preinstaladas](18-development-tools.md#preinstalled-cli-tools) para instalar una sola herramienta o utilizar tu propia instalación.

`grok` se instala mediante el paquete propio `grok` de mise, de la misma manera que `claude` y `codex`. Ejecuta `grok`, o elígelo en _Agent > Harness_. Evita el instalador `curl | bash` de x.ai. Esa ruta coloca una segunda copia en `~/.grok/bin`, la antepone en `PATH` y sobrescribe el wrapper de Omarchy.

`dsh` abre su interfaz de navegador en `127.0.0.1:3080`, con el directorio de inicio como su espacio de trabajo predeterminado. Su interfaz de navegador no acepta un prompt inicial, así que `omarchy agent prompt` lo abre con el prompt en tu portapapeles para pegarlo. Omarchy lo inicia con el preajuste de permisos sin aprobación de DeepSeek. DeepSeek Harness sube los registros de sesión a DeepSeek cuando utilizas su API oficial de modelo; desactívalo en _Settings > General > Upload Session Log_ en su interfaz de navegador. Los comentarios que le envíes también se suben con la sesión, a menos que lo inicies con `DSH_TELEMETRY_MODE=DISABLED`.

### El agente predeterminado

Elige tu agente predeterminado con `omarchy default agent <name>` o en _Agent > Harness_ en el Menú de Omarchy (`Super + Space`). Si el agente aún no está instalado, al elegirlo se instala primero. Un Omarchy recién instalado te invitará a tomar esta decisión con una notificación única.

Al elegir Claude también se intenta configurar su extensión de navegador para Chromium, Chrome, Brave, Brave Origin y Edge. La configuración de la extensión se aplica a todos los usuarios y puede pedirte tu contraseña del sistema; cancelar o que falle la instalación de la extensión no impide seleccionar e iniciar Claude. Reinicia tu navegador, habilita la extensión si se te pide e inicia sesión en Claude para terminar de conectarla. Ejecuta `/chrome` en Claude para verificar la conexión. Firefox y Zen no son compatibles con esta extensión. Si Claude ya era tu predeterminado antes de que se agregara esta configuración, selecciónalo de nuevo para instalar la extensión.

Una vez que hayas elegido, `Super + Shift + Ctrl + A` inicia el agente predeterminado en una ventana de terminal dedicada (o abre el selector si aún no has elegido). También puedes iniciarlo directamente en una tarea con `omarchy agent prompt "Review this project"`. Freebuff y DeepSeek Harness no aceptan un prompt inicial, así que se abren con el prompt en tu portapapeles para pegarlo en su lugar. Los agentes iniciados de esta manera funcionan sin supervisión en sus respectivos modos de no detenerse a preguntar, ¡así que prepárate para que hagan cosas de verdad! MiniMax Code no tiene un modo así para sus sesiones interactivas, así que pide permisos como de costumbre. Y como los agentes se niegan a recordar la confianza para tu directorio principal, los inicios desde `$HOME` comienzan en `~/Work` en su lugar.

También hay atajos de terminal: `a` ejecuta el agente predeterminado en línea en la terminal actual, mientras que `c`, `cx` y `cy` inician OpenCode, Claude Code y Codex directamente (también en sus modos de aprobación automática). Los cambios de tema también se sincronizan con los agentes: Claude Code, Pi, OpenCode y Hermes (una vez que Omarchy lo ha instalado) te siguen cuando cambias el tema de Omarchy.

### Las instrucciones de tu agente

Las reglas personales para cada agente van en `~/.agents/AGENTS.md`, junto a las skills compartidas en `~/.agents/skills`. Ábrelo en _Agent > Instructions_, que también lo enlaza en cada harness que mantiene su propio archivo global: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, el `~/.copilot/copilot-instructions.md` de Copilot, y así sucesivamente. Crush y Amp leen el enlace `~/.config/AGENTS.md`, mientras que omp, Kimi y DeepSeek Harness leen `~/.agents/AGENTS.md` directamente. Elegir un agente predeterminado también lo enlaza. Un archivo de instrucciones que ya tenías se convierte en el compartido si aún no había ninguno; en caso contrario, se conserva junto al enlace como `.bak`. Ejecuta `omarchy agent instructions` para volver a enlazarlo después de instalar otro agente.

### El panel de agentes

La barra superior tiene un ícono de agentes. Antes de que hayas configurado un agente, su panel te guía para iniciar sesión en Claude, Codex o Grok, y el primero se convierte en tu agente predeterminado. Después de eso, el panel reúne cada suscripción en una sola página: cada agente y cuenta con su plan, un medidor para cada uno de sus límites de sesión de 5 horas y semanal con el tiempo hasta que se restablezca (pasa el cursor para ver el porcentaje exacto), o el saldo prepagado restante, bajo una línea que rota por lo que has utilizado en todos ellos, como tokens esta semana y tu modelo más usado. En _Make something_ ofrece prompts iniciales para un tema, plugin, aplicación o juego nuevos que le encargan la tarea a tu agente predeterminado. Las aplicaciones se construyen como se construyen las propias Hype, Monologue y Omacut de Omarchy, en C++ y Qt Quick, siguiendo la skill de agente omarchy-make-app, y el compilador y los componentes de Qt que necesitan vienen instalados. Los juegos son una sola página de three.js en `~/Games/vibes`, siguiendo la skill de agente omarchy-make-game, y todos se abren desde un solo lanzador Game Vibes en el tema actual; cargan three.js desde la web, así que necesitan conexión para iniciar. Claude Code, Codex, Grok, Kimi, Cursor y su asignación de Grok Bot, GitHub Copilot, Muse, Antigravity, Kimchi y Devin están cubiertos desde el inicio con sus límites, y Hermes, Mistral Vibe y Qwen Code muestran sus sesiones y tokens una vez que los has usado. Los planes y claves de proveedores que utilizas mediante pi, omp u opencode también aparecen: OpenCode Zen y Go, el Z.ai GLM Coding Plan, Ollama Cloud, el MiniMax Token Plan y Synthetic con sus límites; Fireworks, OpenRouter y DeepSeek con sus saldos prepagados; y los modelos que ejecutas en tu propio hardware en Local models. Cada agente se cuenta una sola vez, bajo quien lo factura, sin importar por cuántos harnesses lo utilices.

Haz clic izquierdo en el ícono de la barra para abrir el panel, clic derecho para iniciar tu agente predeterminado. Los registros de uso que lo respaldan se regeneran cada 15 minutos con `omarchy agent usage-update`, y el panel incluso puede combinar el uso de tus otras máquinas mediante una carpeta sincronizada. Consulta el README en `$OMARCHY_PATH/shell/plugins/agents/` para ver la configuración completa.

### Varias suscripciones

Si pagas más de un plan de Claude, Codex o Grok —por ejemplo, un Max personal y uno del trabajo— Omarchy puede mantenerlos todos con sesión iniciada y moverse entre ellos. Agrega una suscripción con el + en el panel de agentes, que te guía ahí mismo, o con `omarchy agent account add claude Work` (o `codex`, o `grok`). Instala el CLI si falta. La primera cuenta de un proveedor inicia sesión a través de tu navegador normal, justo donde el CLI siempre busca. Cada una después de esa inicia sesión a través de una ventana privada, para que la cuenta en la que tu navegador ya inició sesión no se tome por error; inicia sesión ahí como la cuenta que estás agregando, y cierra primero cualquier ventana privada que ya tuvieras abierta. Nunca cierres sesión en el CLI para hacer esto: cerrar sesión revoca el inicio de sesión guardado, y esa cuenta tendría que agregarse de nuevo.

Para copiar tus inicios de sesión de suscripción a otra máquina Omarchy por SSH, ejecuta `omarchy agent account copy user@laptop`. El remitente proporciona un receptor temporal cuando el destino no tiene uno instalado, así que las máquinas Omarchy más antiguas pueden recibir cuentas sin una actualización. Los receptores instalados tienen prioridad. Esto copia todas las suscripciones de Claude, Codex y Grok; agrega nombres de proveedores para seleccionarlas, como en `omarchy agent account copy laptop claude`. Los nombres de cuenta y los ID de comando coinciden con el origen, incluidas las cuentas ya presentes en el destino. Las cuentas de destino no relacionadas reciben un sufijo numérico si sus nombres entran en conflicto, y la configuración, las skills, los plugins y el historial de conversaciones permanecen locales en cada máquina.

Las credenciales existentes del destino se conservan. Una cuenta de origen que ya inició sesión ahí ve su nombre sincronizado sin reemplazar sus credenciales; las demás cuentas se agregan junto a ella. Para reemplazar las credenciales guardadas de cuentas coincidentes, utiliza `omarchy agent account copy --replace laptop claude` después de cerrar las sesiones de esa cuenta en el destino. Un destino nuevo también recibe la cuenta activa y las preferencias de cambio del origen; un destino ya establecido conserva las suyas.

Las credenciales viajan por SSH y se almacenan en archivos privados en el destino, así que copia únicamente a máquinas en las que confíes. Esto es una copia única, no una sincronización continua. Los tokens de actualización de Codex pueden ser rotados por otra máquina, dejando un inicio de sesión copiado necesitado de renovación; los inicios de sesión separados siguen siendo la opción más confiable para el uso simultáneo en varias máquinas. Consulta la [guía de autenticación de cuentas de Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Una cuenta por proveedor está activa, y cada sesión nueva inicia como ella: `cx`, `cy`, un simple `claude`, `codex` o `grok`, cualquier cosa iniciada mediante `omarchy agent`, y scripts o editores que encuentran el CLI en `PATH`. Cambia con `omarchy agent account use work` (y vuelve con `omarchy agent account use main`), o en el panel presionando el número de una cuenta y luego `Enter` (o haciendo clic en su botón Use). Las sesiones de Claude en ejecución también cambian, desde su siguiente mensaje: cada sesión de Claude se ejecuta en `~/.claude`, que siempre contiene el inicio de sesión de la cuenta activa. Una sesión de Claude iniciada en la carpeta propia de una cuenta por un Omarchy más antiguo conserva ese inicio de sesión hasta que se cierra, así que el cambio nombra esas sesiones y termina por sí solo una vez que hayan desaparecido. Las sesiones de Codex y Grok en ejecución permanecen en la cuenta con la que iniciaron. El historial de conversaciones, la configuración, las skills y los plugins se comparten entre cuentas, así que `claude --continue` en la misma carpeta continúa donde lo dejaste en la cuenta nueva.

Con más de una cuenta, el panel muestra los límites de cada cuenta lado a lado, con la activa marcada. Por defecto, Omarchy te notifica cuando la cuenta activa supera el 95% de un límite, y al hacer clic en la notificación cambia a la cuenta con más margen. Pasa el cursor sobre la línea de una cuenta en el panel y haz clic en el Autoswitch que aparece junto a Use (o presiona `m`), o ejecuta `omarchy agent account mode auto`, para que cambie por sí solo en su lugar; mientras está activado, Autoswitch ocupa el lugar de Use, y al hacer clic en él de nuevo se vuelve a notificar. Agrega un número para cambiar el umbral, como en `omarchy agent account mode auto 90`. Si cada cuenta supera el umbral, te enterarás una vez, junto con qué cuenta se libera primero. Mientras una cuenta activa está dentro de 15 puntos de su umbral (80% en el valor predeterminado), sus límites se verifican cada tres minutos en lugar de cada 15.

`omarchy agent account list` muestra cada cuenta y sus límites más recientes, `omarchy agent account remove work` olvida una, y `omarchy agent account rename primary Hey` cambia el nombre de una (o haz clic en el nombre de una cuenta en el panel). Estos comandos funcionan en las cuentas de tu agente predeterminado; para llegar al otro proveedor, nómbralo primero, como en `omarchy agent account use codex side`. El inicio de sesión que ya tenías en `~/.claude` o `~/.codex` es la cuenta _Main_. La de Codex permanece donde está; la de Claude espera en una carpeta propia mientras otra cuenta está activa. Una cuenta que no se usa durante más de unas ocho horas puede mostrar _Sign-in required_; haz clic en ella para iniciar sesión en esa cuenta de nuevo justo en el panel, o cambia a ella e inicia una sesión, lo que actualiza el inicio de sesión por sí solo. Los servidores MCP que agregas con `claude mcp add` llegan a cada cuenta de Claude, ya que todas se ejecutan en `~/.claude`; para Codex y Grok, los servidores que tenías cuando se agregó una cuenta la acompañan, pero los posteriores solo llegan a la cuenta en la que los agregaste. Claude Desktop mantiene su propio inicio de sesión, y las herramientas de Codex o Grok configuradas con una ruta absoluta a un binario CLI no siguen el cambio. Un `CLAUDE_CONFIG_DIR`, `CODEX_HOME` o `GROK_HOME` explícito tiene prioridad sobre la cuenta seleccionada.

### Diagnóstico de fallas

Omarchy vigila systemd-coredump en busca de fallas de procesos. Cuando algo hace segfault, recibirás una notificación "Process crashed" —haz clic en ella, y la falla se entrega a tu agente predeterminado junto con la skill diagnose-crash de Omarchy, que guía al agente para establecer los hechos a partir del core dump y decidir si vale la pena reportar la falla upstream. También puedes ejecutarla manualmente contra cualquier PID de `coredumpctl list` con `omarchy agent crash <pid>`.

La vigilancia está activada por defecto. Desactívala en _Trigger > Toggle > Crash Capture_ (o con `omarchy toggle crash-capture`) y las notificaciones se detienen; `omarchy agent crash <pid>` sigue funcionando manualmente.

Las fallas también se pueden silenciar programa por programa, que es lo que el diagnóstico te ofrece al final. `omarchy crash mute hyprland` detiene las notificaciones solo para ese programa, `omarchy crash mute hyprland off` las trae de vuelta, y `omarchy crash mute` por sí solo enumera lo que has silenciado. Acepta la ruta del binario con la misma facilidad que su nombre, así que `omarchy crash mute /usr/bin/hyprland` hace lo mismo. Pon entre comillas un nombre con un espacio, como en `omarchy crash mute 'Some App'`. Todo lo demás sigue notificando, y el programa silenciado sigue fallando: esto oculta el recordatorio, no arregla nada.

### Aplicaciones de escritorio

El menú _Install > AI_ también incluye algunas aplicaciones gráficas de IA: Antigravity Desktop, la aplicación de escritorio de ChatGPT, la aplicación de escritorio de Claude (la beta para Linux de Anthropic, con pestañas Chat, Cowork y Claude Code), Grok Bot para chatear con los modelos de xAI, Herdr Desktop, Hermes Desktop, OpenClaw, la aplicación de escritorio de Perplexity y T3 Code. Grok Bot es la aplicación de chat de escritorio. El agente de programación es el comando `grok`.

Hermes Desktop es el que debes conocer, porque una máquina tiene un solo Hermes, y es el de la aplicación: Hermes solo se instala a través de la aplicación, y el comando `hermes` que ejecuta el agente predeterminado es el de la aplicación. Elegir Hermes como agente predeterminado instala lo mismo que instala la entrada _Install > AI_: el paquete, y un runtime de Hermes en `~/.hermes` configurado por el propio instalador de Hermes, que tarda unos minutos la primera vez. Ese runtime es el único Hermes que utilizan el comando `hermes` de terminal, el agente predeterminado y la aplicación, y se actualiza solo con `hermes update` en lugar de esperar una versión de Omarchy. Al instalarlo también se le entrega a Hermes el tema de Omarchy como una skin llamada `omarchy`, que cada superficie de Hermes sigue cuando cambias de tema; elige otra en la configuración de Appearance de Hermes o con `/skin` si prefieres que no lo haga, y Omarchy respeta esa elección. Eliminar la aplicación en _Remove > AI_ cierra Hermes primero, incluida la gateway, se lleva ese runtime con ella, y conserva tus chats, recuerdos y las skills que Hermes escribió para sí mismo a menos que le digas lo contrario: te pregunta, con no por defecto, si esos datos y tu configuración de conexión también deben irse.

La experiencia de escritorio de OpenClaw es su Control UI, que se abre como una aplicación web respaldada por su propia gateway local. OpenClaw vive en `~/.openclaw` y se actualiza solo: utiliza el botón "Update Gateway" de la Control UI o ejecuta `openclaw update`, y la gateway se reinicia en la versión nueva. Omarchy solo elige la versión con la que comienza una instalación nueva. Eliminar OpenClaw en _Remove > AI_ se lleva el servicio de gateway y la aplicación con ella y luego te pregunta si `~/.openclaw` también debe irse, ya que eso guarda tus chats y credenciales junto con OpenClaw mismo y los runtimes de plugins que descarga; el valor predeterminado lo conserva, e instalar OpenClaw de nuevo lo recupera.

Herdr Desktop es la aplicación de escritorio de [Herdr](https://herdr.dev): espacios, pestañas y paneles de terminales y agentes de programación que siguen ejecutándose en su núcleo cuando cierras la ventana. Viene del propio instalador de Herdr y no de un paquete, así que vive en `~/.local/share/herdr-app`, trae su núcleo en `~/.local/bin/herdr-core` cuando aún no tienes uno, y se actualiza a sí misma en ambos. Se sitúa junto al comando `herdr` que Omarchy incluye en `Super + Ctrl + Return` en lugar de reemplazarlo, y obtiene las teclas directas de ese comando: `Alt + Return` y `Alt + Shift + Return` dividen un panel hacia abajo o hacia la derecha, `Alt + Escape` lo cierra, `Ctrl + Alt + Arrow` se mueve entre paneles, `Alt + 1..9` y `Alt + Left/Right` eligen una pestaña, y `Alt + Up/Down` se mueven entre espacios. `Ctrl + 1..9` elige un espacio y `Alt + Shift + Up/Down` recorre los agentes. Las teclas de prefijo `Ctrl + Space` permanecen solo en terminal, ya que la aplicación no puede retener una tecla Ctrl simple para una secuencia. Omarchy escribe esto en `~/.config/herdr-app/keys.json`, y `omarchy-refresh-herdr-app` lo vuelve a colocar. Al instalarla se elige el tema Omarchy de Herdr, que sigue tu tema de Omarchy a partir de entonces. Herdr conserva un tema para el modo claro y uno para el oscuro, así que después de cambiar entre un tema Omarchy oscuro y uno claro, elige Omarchy en el selector de temas de Herdr una vez más para el otro modo.

T3 Code se ejecuta desde su AppImage oficial en `~/.local/share/t3code` en lugar de desde un paquete, así que se actualiza solo. Al instalarlo se te pregunta si empezar en el canal Stable o Nightly; cambias después en la configuración de T3 Code. Tus hilos y configuración viven en `~/.t3`, y eliminar T3 Code en _Remove > AI_ se los lleva con él.

### Modelos locales

Ejecuta un modelo abierto en tu propia máquina para tus agentes de programación. Tus prompts y tu código permanecen en la máquina; nada de lo enviado al modelo sale de ella. Empieza con:

```bash
omarchy agent local use best
```

O, en el panel de agentes de la barra superior, elige + y luego Local AI, que aparece cuando un modelo cabe en esta máquina. La primera vez, esto instala Podman, que ejecuta los modelos, y en una máquina NVIDIA el kit de herramientas de contenedores de NVIDIA, que les da la GPU. Omarchy luego elige el modelo recomendado para esta máquina, lo descarga y lo inicia. Espera una descarga de decenas de GB y que la mayor parte de la memoria de la máquina esté en uso mientras el modelo se ejecuta: Flash Next utiliza unos 100 GiB con su contexto completo de 256K. Si otros modelos ocupan la memoria que necesita, se configura detenido, listo para iniciar una vez que detengas uno. El modelo se detiene al cerrar sesión; detenlo tú mismo cuando necesites la memoria para otra cosa.

`omarchy agent local list` muestra las opciones y explica por qué algunas no caben. Para configurar otro, ejecuta `omarchy agent local use <recipe>`. Hoy, `qwen3.8-flash-next-gufo` y `qwen3.8-27b-gufo` están disponibles para máquinas Strix Halo de 128 GB; el 27B ocupa unos 40 GiB, así que deja espacio para otro trabajo. En una laptop de 64 GB con Arc B390 de Intel, `qwen3.6-35b-a3b-llamacpp` se ejecuta en unos 30 GiB. Las recetas y recomendaciones nuevas llegan con `omarchy update`, a través del paquete.

Cada modelo que configuras obtiene su propia línea en el panel de agentes, junto a tus suscripciones: reproducir para iniciarlo, pausar para detenerlo y liberar su memoria, y el botón de terminal para abrir tu agente en él. Varios pueden ejecutarse a la vez cuando caben juntos en memoria; si uno no cabe, Omarchy dice qué modelo en ejecución debes detener. Arrastra las líneas para reordenarlas, y presiona Delete en una línea seleccionada para eliminar un modelo y su descarga.

Cada modelo que configuras también obtiene su propia entrada en el lanzador de aplicaciones, bajo el nombre del modelo y con el logo de su creador, de la manera en que iniciar sesión en Claude, Codex o Grok agrega una. Abre tu agente en ese modelo, y primero inicia el modelo si no está en ejecución: la terminal lo muestra cargando y entrega el control al agente una vez que está listo. Eliminar un modelo elimina su entrada.

Un modelo sigue ejecutándose exactamente como fue configurado, así que una actualización de Omarchy nunca reinicia uno bajo tus agentes. Cuando Omarchy tiene un runtime más nuevo o pesos más nuevos para un modelo que has configurado, su línea muestra un botón de actualización: presiónalo y el modelo se configura de nuevo en segundo plano, descargando únicamente lo que cambió, y se reinicia en la versión nueva. Un modelo que estaba detenido permanece detenido. `omarchy agent local update` hace lo mismo para cada modelo desde una terminal.

Desde la línea de comandos, `omarchy agent local start <recipe>` y `omarchy agent local stop <recipe>` hacen lo mismo, `omarchy agent local status` muestra cada modelo, y `omarchy agent --local` abre tu agente predeterminado en el último modelo que iniciaste. pi, OpenCode y Qwen Code pueden utilizar uno; con cualquier otro predeterminado se abre en pi. pi también enumera cada modelo que has configurado, y los de máquinas con las que te has emparejado, en su propio selector de modelos, así que un simple `pi` también llega a ellos. Cualquier cliente compatible con OpenAI también puede conectarse: `status` muestra la dirección de cada modelo (la primera es `http://127.0.0.1:11435/v1`), el nombre de la receta es el modelo, y la clave está en `~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` elimina un modelo y las descargas que ningún otro modelo utiliza.

Los runtimes de terceros están etiquetados con su editor. Omarchy ejecuta cada modelo sin acceso a la red.

### LLM locales

Omarchy recomienda dos maneras de ejecutar modelos LLM locales: LM Studio y Ollama. LM Studio proporciona una interfaz GUI para encontrar modelos de pesos abiertos, instalarlos y ejecutarlos. Es una gran manera de empezar fácilmente. Ollama ofrece un CLI para hacerlo de manera similar. Pero si eres nuevo en los modelos locales, yo empezaría con LM Studio. Puedes instalar cualquiera de los dos en _Install > AI_ en el Menú de Omarchy.

### La Skill de Omarchy

Las skills de agente ayudan a la IA a utilizar herramientas específicas de una manera específica, y Omarchy incluye una skill predeterminada para adaptar el sistema. Como modificar tu configuración de Hyprland, ajustar la barra, o incluso crear un tema nuevo desde cero. Está enlazada mediante symlink en los directorios de skills para Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` y cada `~/.hermes/profiles/*/skills`) y la ubicación genérica `~/.agents/skills`, así que la mayoría de los harnesses la recogen automáticamente.

Pero debes tratar esta skill como experimental. Diferentes modelos la utilizarán con distinto efecto. Es mejor ejecutarla primero en modo plan, para que tengas una idea de lo que al agente le gustaría cambiar. Y luego prepárate para revertir cambios o incluso invocar `omarchy reinstall configs`, si el agente hace un desastre con todo.
