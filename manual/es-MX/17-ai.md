# IA

Omarchy incluye lanzadores para los agentes de programación siguientes sin elegir uno predeterminado por ti. Ejecuta un comando para instalar su CLI en el primer uso y luego autentícate cuando se te solicite. Hermes es la excepción: no se instala nada para él en el primer uso, y elegirlo instala Hermes Desktop, como explica _Aplicaciones de escritorio_ más adelante.

### Instalar y actualizar agentes

Excepto Hermes, estos agentes usan la instalación diferida de mise: el primer inicio instala el CLI, y los inicios posteriores lo reutilizan. mise también comprueba si un agente instalado tiene una nueva versión como máximo una vez cada cuatro horas, justo antes de iniciarlo o en segundo plano en un prompt de la shell. Si esa actualización falla o no tienes conexión, se ejecuta la versión instalada. `omarchy update` actualiza los agentes instalados con el resto de Omarchy, y `mup` actualiza solo las herramientas gestionadas por mise.

El actualizador propio de un agente, como `claude update`, `codex update` o un botón de actualización en una aplicación, no actualiza la instalación gestionada por mise. `codex update` falla, y `claude update` puede reportar éxito mientras instala una copia separada que mise no rastrea. Si prefieres usar el instalador y el actualizador nativos de un agente, agrégalo a `disable_tools`; consulta [Herramientas CLI preinstaladas](18-development-tools.md#preinstalled-cli-tools).

Para instalar todas las herramientas diferidas configuradas antes de necesitarlas, ejecuta `mise install --include-lazy`. Esto incluye las demás herramientas CLI predeterminadas de Omarchy además de los agentes. Consulta [Herramientas CLI preinstaladas](18-development-tools.md#preinstalled-cli-tools) para instalar una sola herramienta o usar tu propia instalación.

`grok` se instala a través del paquete propio `grok` de mise, de la misma manera que `claude` y `codex`. Ejecuta `grok`, o elígelo en _Setup > Defaults > Agent_. Omite el instalador `curl | bash` de x.ai. Esa ruta coloca una segunda copia en `~/.grok/bin`, la antepone en `PATH` y sobrescribe el wrapper de Omarchy.

`dsh` abre su interfaz de navegador en `127.0.0.1:3080`, con el directorio de inicio como su espacio de trabajo predeterminado. Su interfaz de navegador no acepta un prompt inicial, así que `omarchy agent prompt` lo abre con el prompt en tu portapapeles para pegarlo. Omarchy lo inicia con el preset de permisos sin aprobación de DeepSeek. DeepSeek Harness sube los registros de sesión a DeepSeek cuando usas su API oficial de modelos; desactívalo en _Settings > General > Upload Session Log_ en su interfaz de navegador. Los comentarios que le envíes también se suben con la sesión, a menos que lo inicies con `DSH_TELEMETRY_MODE=DISABLED`.

### El agente predeterminado

Elige tu agente predeterminado con `omarchy default agent <name>` o en _Setup > Defaults > Agent_ en el menú de Omarchy (`Super + Space`). Si el agente aún no está instalado, elegirlo lo instala primero. Una instalación nueva de Omarchy te invitará a hacer esta elección con una notificación única.

Elegir Claude también intenta configurar su extensión de navegador para Chromium, Chrome, Brave, Brave Origin y Edge. La configuración de la extensión se aplica a todos los usuarios y puede pedir tu contraseña del sistema; cancelar o que falle la instalación de la extensión no impide que Claude se seleccione e inicie. Reinicia tu navegador, habilita la extensión si se te solicita e inicia sesión en Claude para terminar de conectarla. Ejecuta `/chrome` en Claude para comprobar la conexión. Firefox y Zen no son compatibles con esta extensión. Si Claude ya era tu predeterminado antes de que se agregara esta configuración, selecciónalo de nuevo para instalar la extensión.

Una vez que hayas elegido, `Super + Shift + Ctrl + A` inicia el agente predeterminado en una ventana de terminal dedicada (o muestra el selector si aún no has elegido). También puedes iniciarlo directamente en una tarea con `omarchy agent prompt "Review this project"`. Freebuff y DeepSeek Harness no aceptan un prompt inicial, así que se abren con el prompt en tu portapapeles para pegarlo en su lugar. Los agentes iniciados de esta manera se ejecutan sin supervisión en sus respectivos modos de no detenerse a preguntar, ¡así que prepárate para que realmente hagan cosas! MiniMax Code no tiene un modo así para sus sesiones interactivas, así que pide permisos como de costumbre. Y como los agentes se niegan a recordar la confianza para tu directorio home, los inicios desde `$HOME` empiezan en `~/Work` en su lugar.

También hay atajos de terminal: `a` ejecuta el agente predeterminado en línea en la terminal actual, mientras que `c`, `cx` y `cy` inician OpenCode, Claude Code y Codex directamente (también en sus modos de aprobación automática). Los cambios de tema también se sincronizan con los agentes: Claude Code, Pi, OpenCode y Hermes (una vez que Omarchy lo ha instalado) siguen el cambio cuando cambias el tema de Omarchy.

### El panel de agentes

La barra superior tiene un icono de agentes. Antes de que hayas configurado un agente, su panel te guía para iniciar sesión en Claude, Codex o Grok, y el primero se convierte en tu agente predeterminado. Después de eso, el panel reúne todas las suscripciones en una página: cada agente y cuenta con su plan, un medidor para cada uno de sus límites de sesión de 5 horas y semanales con el tiempo hasta que se restablece (pasa el cursor para ver el porcentaje exacto), o el saldo prepagado restante, bajo una línea que rota a través de lo que has usado entre todos ellos, como los tokens de esta semana y tu modelo más usado. En _Make something_ ofrece prompts iniciales para un nuevo tema, plugin o aplicación que entregan la tarea a tu agente predeterminado. Las aplicaciones se construyen como se construyen las propias Hype, Monologue y Omacut de Omarchy, en C++ y Qt Quick, siguiendo la skill de agente omarchy-app, y el compilador y las piezas de Qt que necesitan vienen instalados. Claude Code, Codex, Grok, Kimi, Cursor y su asignación de Grok Bot, GitHub Copilot, Muse, Antigravity, Kimchi y Devin están cubiertos desde el primer momento con sus límites, y Hermes, Mistral Vibe y Qwen Code muestran sus sesiones y tokens una vez que los has usado. Los planes y claves de proveedores que usas a través de pi, omp u opencode también aparecen: OpenCode Zen y Go, el Z.ai GLM Coding Plan, Ollama Cloud, el MiniMax Token Plan y Synthetic con sus límites; Fireworks, OpenRouter y DeepSeek con sus saldos prepagados; y los modelos que ejecutas en tu propio hardware en Local models. Cada agente se cuenta una vez, bajo quien lo facture, sin importar a través de cuántos harnesses lo uses.

Haz clic izquierdo en el icono de la barra para abrir el panel, clic derecho para iniciar tu agente predeterminado. Los registros de uso detrás de él se regeneran cada 15 minutos con `omarchy agent usage-update`, y el panel incluso puede fusionar el uso de tus otras máquinas mediante una carpeta sincronizada. Consulta el README en `$OMARCHY_PATH/shell/plugins/agents/` para ver la configuración completa.

### Varias suscripciones

Si pagas más de un plan de Claude, Codex o Grok —uno personal Max y uno del trabajo, por ejemplo— Omarchy puede mantenerlos todos con sesión iniciada y moverse entre ellos. Agrega una suscripción con el + en el panel de agentes, que te guía ahí mismo, o con `omarchy agent account add claude Work` (o `codex`, o `grok`). Instala el CLI si falta. La primera cuenta de un proveedor inicia sesión a través de tu navegador normal, justo donde el CLI siempre busca. Cada una después de esa inicia sesión a través de una ventana privada, para que la cuenta en la que tu navegador ya tiene sesión iniciada no se tome por error; inicia sesión ahí como la cuenta que estás agregando y cierra primero cualquier ventana privada que ya tuvieras abierta. Nunca cierres sesión en el CLI para hacer esto: cerrar sesión revoca el inicio de sesión guardado, y esa cuenta tendría que agregarse de nuevo.

Para copiar tus inicios de sesión de suscripción a otra máquina Omarchy por SSH, ejecuta `omarchy agent account copy user@laptop`. El remitente proporciona un receptor temporal cuando el destino no tiene uno instalado, así que las máquinas Omarchy más antiguas pueden recibir cuentas sin una actualización. Los receptores instalados tienen prioridad. Esto copia todas las suscripciones de Claude, Codex y Grok; agrega nombres de proveedores para seleccionarlas, como en `omarchy agent account copy laptop claude`. Los nombres de cuenta y los ID de comando coinciden con el origen, incluidas las cuentas ya presentes en el destino. Las cuentas de destino no relacionadas reciben un sufijo numérico si sus nombres entran en conflicto, y la configuración, las skills, los plugins y el historial de conversaciones permanecen locales en cada máquina.

Las credenciales existentes del destino se conservan. Una cuenta del origen que ya tiene sesión iniciada ahí ve sincronizado su nombre sin reemplazar sus credenciales; las demás cuentas se agregan junto a ella. Para reemplazar las credenciales guardadas de las cuentas coincidentes, usa `omarchy agent account copy --replace laptop claude` después de cerrar las sesiones de esa cuenta en el destino. Un destino nuevo también obtiene la cuenta activa y las preferencias de cambio del origen; un destino ya establecido conserva las suyas.

Las credenciales viajan a través de SSH y se almacenan en archivos privados en el destino, así que copia solo a máquinas en las que confíes. Esto es una copia única, no una sincronización continua. Los tokens de actualización de Codex pueden ser rotados por otra máquina, lo que deja un inicio de sesión copiado con necesidad de renovación; los inicios de sesión separados siguen siendo la opción más confiable para el uso simultáneo en varias máquinas. Consulta la [guía de autenticación de cuentas de Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Una cuenta por proveedor está activa, y cada nueva sesión empieza como ella: `cx`, `cy`, un `claude`, `codex` o `grok` simple, cualquier cosa iniciada a través de `omarchy agent`, y scripts o editores que encuentran el CLI en `PATH`. Cambia con `omarchy agent account use work` (y vuelve con `omarchy agent account use main`), o en el panel presionando el número de una cuenta y luego `Enter` (o haciendo clic en su botón Use). Las sesiones que ya se están ejecutando permanecen en la cuenta con la que empezaron. El historial de conversaciones, la configuración, las skills y los plugins se comparten entre cuentas, así que `claude --continue` en la misma carpeta continúa donde lo dejaste en la cuenta nueva.

Con más de una cuenta, el panel muestra los límites de cada cuenta lado a lado, con la activa marcada. Por defecto, Omarchy te notifica cuando la cuenta activa supera el 95% de un límite, y hacer clic en la notificación cambia a la cuenta con más margen. Pasa el cursor sobre la línea de una cuenta en el panel y haz clic en Autoswitch que aparece junto a Use (o presiona `m`), o ejecuta `omarchy agent account mode auto`, para que cambie por sí solo en su lugar; mientras está activado, Autoswitch ocupa el lugar de Use, y hacer clic en él de nuevo vuelve a notificar. Agrega un número para cambiar el umbral, como en `omarchy agent account mode auto 90`. Si todas las cuentas superan el umbral, te enterarás una vez, junto con qué cuenta se libera primero. Mientras una cuenta activa está dentro de los 15 puntos de su umbral (80% en el valor predeterminado), sus límites se comprueban cada tres minutos en lugar de cada 15.

`omarchy agent account list` muestra cada cuenta y sus límites más recientes, `omarchy agent account remove work` olvida una, y `omarchy agent account rename primary Hey` renombra una (o haz clic en el nombre de una cuenta en el panel). Estos comandos funcionan en las cuentas de tu agente predeterminado; para llegar al otro proveedor, nómbralo primero, como en `omarchy agent account use codex side`. El inicio de sesión que ya tenías en `~/.claude` o `~/.codex` es la cuenta _Main_ y se queda donde está. Una cuenta sin uso durante más de unas ocho horas puede mostrar _Sign-in required_; haz clic en ella para iniciar sesión en esa cuenta de nuevo justo en el panel, o inicia una sesión en ella, lo que actualiza el inicio de sesión por sí solo. Los servidores MCP que tenías cuando se agregó una cuenta vienen con ella, pero los que agregues después con `claude mcp add` solo llegan a la cuenta en la que los agregaste. Claude Desktop y las herramientas configuradas con una ruta absoluta a un binario del CLI no siguen el cambio. Un `CLAUDE_CONFIG_DIR`, `CODEX_HOME` o `GROK_HOME` explícito tiene prioridad sobre la cuenta seleccionada.

### Diagnóstico de fallos

Omarchy vigila systemd-coredump en busca de fallos de procesos. Cuando algo hace segfault, recibirás una notificación "Process crashed": haz clic en ella y el fallo se entrega a tu agente predeterminado junto con la skill diagnose-crash de Omarchy, que guía al agente para establecer los hechos a partir del core dump y decidir si vale la pena reportar el fallo upstream. También puedes ejecutarlo a mano contra cualquier PID de `coredumpctl list` con `omarchy agent crash <pid>`.

La vigilancia está activada por defecto. Desactívala en _Trigger > Toggle > Crash Capture_ (o con `omarchy toggle crash-capture`) y las notificaciones se detienen; `omarchy agent crash <pid>` sigue funcionando a mano.

Los fallos también pueden silenciarse programa por programa, que es lo que el diagnóstico te ofrece al final. `omarchy crash mute hyprland` detiene las notificaciones solo para ese programa, `omarchy crash mute hyprland off` las trae de vuelta, y `omarchy crash mute` por sí solo lista lo que has silenciado. Acepta la ruta del binario con la misma facilidad que su nombre, así que `omarchy crash mute /usr/bin/hyprland` hace lo mismo. Pon entre comillas un nombre con un espacio, como en `omarchy crash mute 'Some App'`. Todo lo demás sigue notificando, y el programa silenciado sigue fallando: esto oculta el recordatorio, no arregla nada.

### Aplicaciones de escritorio

El menú _Install > AI_ también incluye algunas aplicaciones gráficas de IA: la aplicación de escritorio de ChatGPT, la aplicación de escritorio de Claude (la beta para Linux de Anthropic, con pestañas Chat, Cowork y Claude Code), Grok Bot para chatear con los modelos de xAI, Hermes Desktop, OpenClaw, la aplicación de escritorio de Perplexity y T3 Code. Grok Bot es la aplicación de chat de escritorio. El agente de programación es el comando `grok`.

Hermes Desktop es la que debes conocer, porque una máquina tiene un solo Hermes, y es el de la aplicación: Hermes solo se instala a través de la aplicación, y el comando `hermes` que ejecuta el agente predeterminado es el de la aplicación. Elegir Hermes como agente predeterminado instala lo mismo que la entrada _Install > AI_: el paquete y un runtime de Hermes en `~/.hermes` configurado por el propio instalador de Hermes, lo que toma unos minutos la primera vez. Ese runtime es el único Hermes que usan el comando `hermes` de la terminal, el agente predeterminado y la aplicación, y se actualiza solo con `hermes update` en lugar de esperar una versión de Omarchy. Instalarlo también entrega a Hermes el tema de Omarchy como un skin llamado `omarchy`, que cada superficie de Hermes sigue cuando cambias de tema; elige otro en la configuración de Appearance de Hermes o con `/skin` si prefieres que no lo haga, y Omarchy deja esa elección en paz. Quitar la aplicación en _Remove > AI_ cierra Hermes primero, gateway incluido, se lleva ese runtime con ella y conserva tus chats, recuerdos y las skills que Hermes escribió para sí mismo a menos que le digas lo contrario: te pregunta, con no como predeterminado, si esos datos y tu configuración de conexión también deben irse.

La experiencia de escritorio de OpenClaw es su Control UI, que se abre como una aplicación web respaldada por su propio gateway local. OpenClaw vive en `~/.openclaw` y se actualiza solo: usa el botón "Update Gateway" de la Control UI o ejecuta `openclaw update`, y el gateway se reinicia en la nueva versión. Omarchy solo elige la versión con la que empieza una instalación nueva. Quitar OpenClaw en _Remove > AI_ se lleva el servicio del gateway y la aplicación con él y luego pregunta si `~/.openclaw` también debe irse, ya que eso guarda tus chats y credenciales junto con el propio OpenClaw y los runtimes de plugins que descarga; el valor predeterminado lo conserva, e instalar OpenClaw de nuevo lo recupera.

T3 Code se ejecuta desde su versión oficial en AppImage en `~/.local/share/t3code` en lugar de desde un paquete, así que se actualiza solo. Instalarlo pregunta si empezar en el canal Stable o Nightly; cámbialo después en la configuración de T3 Code. Tus hilos y configuración viven en `~/.t3`, y quitar T3 Code en _Remove > AI_ se los lleva con él.

### LLM locales

Omarchy recomienda dos maneras de ejecutar modelos LLM locales: LM Studio y Ollama. LM Studio proporciona una interfaz GUI para encontrar modelos de pesos abiertos, instalarlos y ejecutarlos. Es una gran manera de empezar fácilmente. Ollama ofrece un CLI para hacer algo similar. Pero si eres nuevo en los modelos locales, yo empezaría con LM Studio. Puedes instalar cualquiera de los dos en _Install > AI_ en el menú de Omarchy.

### La skill de Omarchy

Las skills de agente ayudan a la IA a usar herramientas específicas de una manera específica, y Omarchy incluye una skill predeterminada para adaptar el sistema. Como retocar tu configuración de Hyprland, ajustar la barra o incluso crear un tema nuevo desde cero. Está enlazada mediante symlink en los directorios de skills de Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` y cada `~/.hermes/profiles/*/skills`) y la ubicación genérica `~/.agents/skills`, así que la mayoría de los harnesses la recogen automáticamente.

Pero debes tratar esta skill como experimental. Los distintos modelos la usarán con efectos distintos. Es mejor ejecutarla primero en modo de planificación, para que tengas una idea de lo que al agente le gustaría cambiar. Y luego prepárate para revertir los cambios o incluso invocar `omarchy reinstall configs`, si el agente hace un desastre con todo.
