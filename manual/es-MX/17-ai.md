# IA

Omarchy incluye lanzadores para los agentes de código siguientes sin elegir uno predeterminado por ti. Ejecuta un comando para instalar su CLI la primera vez que lo uses y luego autentícate cuando te lo pida. Hermes y OpenClaw son las excepciones: no se instala nada para ellos a través de mise, y elegir cualquiera de los dos configura su propia copia con actualización automática, como explica _Aplicaciones de escritorio_ más abajo.

### Instalación y actualización de agentes

Excepto Hermes y OpenClaw, estos agentes usan la instalación diferida de mise: el primer inicio instala la CLI y los inicios posteriores la reutilizan. mise también comprueba si un agente instalado tiene una versión nueva como máximo una vez cada cuatro horas, justo antes de iniciarlo o en segundo plano en un prompt de shell. Si esa actualización falla o no tienes conexión, se ejecuta la versión instalada. `omarchy update` actualiza los agentes instalados junto con el resto de Omarchy, y `mup` actualiza únicamente las herramientas gestionadas por mise.

El actualizador propio de un agente, como `claude update`, `codex update` o un botón de actualización en una app, no actualiza la instalación gestionada por mise. `codex update` falla, y `claude update` puede informar que tuvo éxito mientras instala una copia aparte que mise no rastrea. Si prefieres usar el instalador y el actualizador nativos de un agente, agrégalo a `disable_tools`; consulta [Herramientas CLI preinstaladas](18-development-tools.md#preinstalled-cli-tools).

Para instalar todas las herramientas diferidas configuradas antes de que las necesites, ejecuta `mise install --include-lazy`. Esto incluye las demás herramientas CLI predeterminadas de Omarchy, además de los agentes. Consulta [Herramientas CLI preinstaladas](18-development-tools.md#preinstalled-cli-tools) para instalar una sola herramienta o usar tu propia instalación.

`grok` se instala a través del paquete propio `grok` de mise, de la misma manera que `claude` y `codex`. Ejecuta `grok`, o elígelo en _Agente > Harness_. Omite el instalador `curl | bash` de x.ai. Esa ruta coloca una segunda copia en `~/.grok/bin`, la antepone en `PATH` y sobrescribe el contenedor de Omarchy.

`dsh` abre su interfaz de usuario en el navegador en `127.0.0.1:3080`, con el directorio de inicio como su espacio de trabajo predeterminado. Su interfaz de usuario en el navegador no acepta un prompt inicial, así que `omarchy agent prompt` la abre con el prompt en tu portapapeles para que lo pegues. Omarchy la inicia con el ajuste preestablecido de permisos sin aprobación de DeepSeek. DeepSeek Harness sube los registros de sesión a DeepSeek cuando usas su API oficial de modelos; desactívalo en _Ajustes > General > Subir registro de sesión_ en su interfaz de usuario en el navegador. Los comentarios que le envíes también se suben con la sesión, a menos que la inicies con `DSH_TELEMETRY_MODE=DISABLED`.

### El agente predeterminado

Elige tu agente predeterminado con `omarchy default agent <name>` o en _Agente > Harness_ en el menú de Omarchy (`Super + Space`). Si el agente aún no está instalado, al elegirlo se instala primero, y también recibe su propio lanzador en el lanzador de aplicaciones, junto a Agent. Un Omarchy recién instalado te invitará a hacer esta elección con una notificación única.

Elegir Claude también intenta configurar su extensión para navegador para Chromium, Chrome, Brave, Brave Origin y Edge. La configuración de la extensión se aplica a todos los usuarios y puede pedirte tu contraseña del sistema; cancelar la instalación de la extensión o que esta falle no impide seleccionar e iniciar Claude. Reinicia tu navegador, habilita la extensión si te lo pide e inicia sesión en Claude para terminar de conectarla. Ejecuta `/chrome` en Claude para comprobar la conexión. Firefox y Zen no son compatibles con esta extensión. Si Claude ya era tu predeterminado antes de que se agregara esta configuración, vuelve a seleccionarlo para instalar la extensión.

Una vez que hayas elegido, `Super + Shift + Ctrl + A` inicia el agente predeterminado en una ventana de terminal dedicada (o abre el selector si aún no has elegido). También puedes iniciarlo directamente en una tarea con `omarchy agent prompt "Review this project"`. Freebuff y DeepSeek Harness no aceptan un prompt inicial, así que en su lugar se abren con el prompt en tu portapapeles para que lo pegues. Los agentes iniciados de esta manera se ejecutan sin supervisión en sus respectivos modos de no detenerse a preguntar, ¡así que prepárate para que de verdad hagan cosas! MiniMax Code no tiene un modo así para sus sesiones interactivas, así que pide permisos como de costumbre. Y como los agentes se niegan a recordar la confianza para tu directorio personal, los inicios desde `$HOME` comienzan en `~/Work`.

También hay atajos de terminal: `a` ejecuta el agente predeterminado en línea en la terminal actual, mientras que `c`, `cx` y `cy` inician OpenCode, Claude Code y Codex directamente (también en sus modos de aprobación automática). Los cambios de tema también se sincronizan con los agentes: Claude Code, Pi, OpenCode y Hermes (una vez que Omarchy lo ha instalado) te siguen cuando cambias el tema de Omarchy.

### Las instrucciones de tu agente

Las reglas personales para cada agente van en `~/.agents/AGENTS.md`, junto a las skills compartidas en `~/.agents/skills`. Ábrelo en _Agente > Instrucciones_, que también lo enlaza en cada harness que mantiene su propio archivo global: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, el `~/.copilot/copilot-instructions.md` de Copilot, etcétera. Crush y Amp leen el enlace `~/.config/AGENTS.md`, mientras que omp, Kimi y DeepSeek Harness leen `~/.agents/AGENTS.md` directamente. Elegir un agente predeterminado también lo enlaza. Un archivo de instrucciones que ya tenías se convierte en el compartido si aún no había ninguno; en caso contrario, se conserva junto al enlace como `.bak`. Ejecuta `omarchy agent instructions` para volver a enlazarlo después de instalar otro agente.

### El panel de agentes

La barra superior tiene un ícono de agentes. Antes de que hayas configurado un agente, su panel te guía para iniciar sesión en Claude, Codex o Grok, y el primero se convierte en tu agente predeterminado. Después de eso, el panel pone cada suscripción en una sola página: cada agente y cuenta con su plan, un medidor para cada uno de sus límites de sesión de 5 horas y semanal con el tiempo que falta para que se restablezca (pasa el cursor por encima para ver el porcentaje exacto), o el saldo prepagado restante, bajo una línea que rota por lo que has usado en todos ellos, como los tokens de esta semana y tu modelo más usado. En _Crea algo genial_ ofrece prompts iniciales para un tema, plugin, app o juego nuevo que entregan la tarea a tu agente predeterminado. Las apps se crean como se crean las propias Hype, Monologue y Omacut de Omarchy, en C++ y Qt Quick, siguiendo la skill de agente omarchy-make-app, y el compilador y los componentes de Qt que necesitan vienen instalados. Los juegos son una sola página de three.js en `~/Games/vibes`, siguiendo la skill de agente omarchy-make-game, y todos se abren desde un solo lanzador Game Vibes con el tema actual; cargan three.js desde la web, así que necesitan una conexión para iniciar. Claude Code, Codex, Grok, Kimi, Cursor y su asignación de Grok Bot, GitHub Copilot, Muse, Antigravity y Devin están cubiertos desde el inicio con sus límites, Kimchi con su plan, créditos prepagados y presupuestos de gasto, y Hermes, Mistral Vibe y Qwen Code muestran sus sesiones y tokens una vez que los has usado. Los planes y claves de proveedores que usas a través de pi, omp u opencode también aparecen: OpenCode Zen y Go, el Z.ai GLM Coding Plan, Ollama Cloud, el MiniMax Token Plan y Synthetic con sus límites; OpenRouter y DeepSeek con sus saldos prepagados; Fireworks con su gasto de los últimos 30 días. Los tokens de los modelos que ejecutas en tu propio hardware también cuentan para los totales; los modelos en sí tienen su propio panel, descrito en [Modelos locales](#local-models). Cada agente se cuenta una vez, bajo quien lo facture, sin importar a través de cuántos harnesses lo manejes.

Haz clic izquierdo en el ícono de la barra o presiona `Super + Ctrl + X` para abrir el panel, clic derecho para iniciar tu agente predeterminado y clic central para actualizar. Los registros de uso que lo respaldan se regeneran cada 15 minutos con `omarchy agent usage update`, y el panel incluso puede combinar el uso de tus otros equipos mediante una carpeta sincronizada. Consulta el README en `$OMARCHY_PATH/shell/plugins/agents/` para ver toda la configuración.

### Varias suscripciones

Si pagas más de un plan de Claude, Codex o Grok —uno personal Max y uno de trabajo, por ejemplo—, Omarchy puede mantenerlos a todos con la sesión iniciada y moverse entre ellos. Agrega una suscripción con el + en el panel de agentes, que te guía ahí mismo, o con `omarchy agent account add claude Work` (o `codex`, o `grok`). Instala la CLI si falta. La primera cuenta de un proveedor inicia sesión a través de tu navegador normal, justo donde la CLI siempre busca. Cada una después de esa inicia sesión a través de una ventana privada, para que la cuenta en la que tu navegador ya inició sesión no se seleccione por error; inicia sesión ahí como la cuenta que estás agregando y cierra primero cualquier ventana privada que ya tuvieras abierta. Nunca cierres sesión en la CLI para hacer esto: cerrar sesión revoca el inicio de sesión guardado, y esa cuenta tendría que agregarse de nuevo.

Para copiar tus inicios de sesión de suscripción a otro equipo Omarchy por SSH, ejecuta `omarchy agent account copy user@laptop`. El remitente proporciona un receptor temporal cuando el destino no tiene uno instalado, así que los equipos Omarchy más antiguos pueden recibir cuentas sin una actualización. Los receptores instalados tienen prioridad. Esto copia todas las suscripciones de Claude, Codex y Grok; agrega nombres de proveedores para seleccionarlas, como en `omarchy agent account copy laptop claude`. Los nombres de cuenta y los ID de comando coinciden con el origen, incluidas las cuentas ya presentes en el destino. Las cuentas de destino no relacionadas reciben un sufijo numérico si sus nombres entran en conflicto, y la configuración, las skills, los plugins y el historial de conversaciones permanecen locales en cada equipo.

Las credenciales existentes del destino se conservan. Una cuenta de origen que ya inició sesión ahí ve sincronizado su nombre sin reemplazar sus credenciales; las demás cuentas se agregan junto a ella. Para reemplazar las credenciales guardadas de las cuentas coincidentes, usa `omarchy agent account copy --replace laptop claude` después de salir de las sesiones de esa cuenta en el destino. Un destino nuevo también recibe la cuenta activa y las preferencias de cambio del origen; un destino ya establecido conserva las suyas.

Las credenciales viajan por SSH y se guardan en archivos privados en el destino, así que copia solo a equipos en los que confíes. Esto es una copia única, no una sincronización continua. Los tokens de actualización de Codex pueden ser rotados por otro equipo, lo que deja un inicio de sesión copiado necesitando renovación; los inicios de sesión separados siguen siendo la opción más confiable para el uso simultáneo en varios equipos. Consulta la [guía de autenticación de cuentas de Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Una cuenta por proveedor está activa, y cada sesión nueva comienza como ella: `cx`, `cy`, un simple `claude`, `codex` o `grok`, cualquier cosa iniciada a través de `omarchy agent`, y los scripts o editores que encuentran la CLI en `PATH`. Cambia con `omarchy agent account use work` (y vuelve con `omarchy agent account use main`), o en el panel presionando el número de una cuenta y luego `Enter` (o haciendo clic en su botón Use). Las sesiones de Claude en ejecución también cambian, a partir de su siguiente mensaje: cada sesión de Claude se ejecuta en `~/.claude`, que siempre contiene el inicio de sesión de la cuenta activa. Una sesión de Claude iniciada en la propia carpeta de una cuenta por un Omarchy más antiguo conserva ese inicio de sesión hasta que sale, así que el cambio nombra esas sesiones y termina por sí solo una vez que desaparecen. Las sesiones de Codex y Grok en ejecución permanecen en la cuenta con la que comenzaron. El historial de conversaciones, la configuración, las skills y los plugins se comparten entre cuentas, así que `claude --continue` en la misma carpeta continúa donde lo dejaste en la cuenta nueva.

Con más de una cuenta, el panel muestra los límites de cada cuenta lado a lado, con la activa marcada. Omarchy te notifica cuando la cuenta activa supera el 95 % de un límite, y al hacer clic en la notificación cambia a la cuenta con más margen. Nunca cambia por sí solo. Cambia el umbral con `omarchy agent account threshold 90`. Si cada cuenta supera el umbral, te enterarás una vez, junto con qué cuenta se libera primero. Mientras una cuenta activa esté a menos de 15 puntos de su umbral (80 % en el valor predeterminado), sus límites se comprueban cada tres minutos en lugar de cada 15.

`omarchy agent account list` muestra cada cuenta y sus límites más recientes, `omarchy agent account remove work` olvida una, y `omarchy agent account rename primary Hey` cambia el nombre de una (o haz clic en el nombre de una cuenta en el panel). Estos comandos funcionan en las cuentas de tu agente predeterminado; para llegar al otro proveedor, nómbralo primero, como en `omarchy agent account use codex side`. El inicio de sesión que ya tenías en `~/.claude` o `~/.codex` es la cuenta _Main_. El de Codex se queda donde está; el de Claude espera en su propia carpeta mientras otra cuenta está activa. Una cuenta que no se usa durante más de unas ocho horas puede mostrar _Sign-in required_; haz clic en ella para volver a iniciar sesión en esa cuenta justo en el panel, o cambia a ella e inicia una sesión, lo que actualiza el inicio de sesión por sí solo. Los servidores MCP que agregas con `claude mcp add` llegan a cada cuenta de Claude, ya que todas se ejecutan en `~/.claude`; para Codex y Grok, los servidores que tenías cuando se agregó una cuenta la acompañan, pero los posteriores solo llegan a la cuenta en la que los agregaste. Claude Desktop mantiene su propio inicio de sesión, y las herramientas de Codex o Grok configuradas con una ruta absoluta a un binario de CLI no siguen el cambio. Un `CLAUDE_CONFIG_DIR`, `CODEX_HOME` o `GROK_HOME` explícito tiene prioridad sobre la cuenta seleccionada.

### Diagnóstico de fallas

Omarchy observa systemd-coredump en busca de fallas de procesos. Una vez que hayas elegido un agente predeterminado, cualquier programa tuyo que genere un volcado de memoria trae una notificación "Process crashed": haz clic en ella y la falla se entrega a tu agente predeterminado junto con la skill omarchy-diagnose-crash de Omarchy, que guía al agente para establecer los hechos a partir del volcado de memoria y decidir si vale la pena informar la falla al proyecto original. También puedes ejecutarlo manualmente contra cualquier PID de `coredumpctl list` con `omarchy agent crash <pid>`.

La observación está activada de forma predeterminada. Desactívala en _Disparador > Alternar > Desactivar captura de fallas_ (o con `omarchy toggle crash-capture`) y las notificaciones se detienen; `omarchy agent crash <pid>` sigue funcionando manualmente.

Las fallas también pueden silenciarse programa por programa, que es lo que el diagnóstico te ofrece al final. `omarchy crash mute hyprland` detiene las notificaciones solo para ese programa, `omarchy crash mute hyprland off` las trae de vuelta, y `omarchy crash mute` por sí solo enumera lo que has silenciado. Acepta la ruta del binario con la misma facilidad que su nombre, así que `omarchy crash mute /usr/bin/hyprland` hace lo mismo. Escribe entre comillas un nombre con un espacio, como en `omarchy crash mute 'Some App'`. Todo lo demás sigue notificando, y el programa silenciado sigue fallando: esto oculta el recordatorio, no arregla nada.

### Aplicaciones de escritorio

El menú _Instalar > IA_ también incluye algunas apps gráficas de IA: Amp Desktop, Antigravity Desktop, la app de escritorio de ChatGPT, la app de escritorio de Claude (la beta para Linux de Anthropic, con las pestañas Chat, Cowork y Claude Code), Grok Bot para chatear con los modelos de xAI, Herdr Desktop, Hermes Desktop, OpenClaw, la app de escritorio de Perplexity y T3 Code. Grok Bot es la app de escritorio para chatear. El agente de código es el comando `grok`.

Hermes Desktop es la que debes conocer, porque un equipo tiene un solo Hermes, y es el de la app: Hermes solo se instala a través de la app, y el comando `hermes` que ejecuta el agente predeterminado es el de la app. Elegir Hermes como agente predeterminado instala lo mismo que instala la entrada _Instalar > IA_: el paquete, y un entorno de ejecución de Hermes en `~/.hermes` configurado por el propio instalador de Hermes, lo que tarda unos minutos la primera vez. Ese entorno de ejecución es el único Hermes que usan el comando `hermes` de la terminal, el agente predeterminado y la app, y se actualiza a sí mismo con `hermes update` en lugar de esperar una versión de Omarchy. Instalarlo también le entrega a Hermes el tema de Omarchy como una apariencia llamada `omarchy`, que cada superficie de Hermes sigue cuando cambias de tema; elige otra en los ajustes de Apariencia de Hermes o con `/skin` si prefieres que no lo haga, y Omarchy respeta esa elección. Eliminar la app en _Eliminar > IA_ cierra primero Hermes, puerta de enlace incluida, se lleva ese entorno de ejecución con ella y conserva tus chats, recuerdos y las skills que Hermes escribió para sí mismo, a menos que le digas lo contrario: te pregunta, con «no» como respuesta predeterminada, si esos datos y tu configuración de conexión también deben irse.

La experiencia de escritorio de OpenClaw es su Control UI, que se abre como una app web respaldada por su propia puerta de enlace local. OpenClaw vive en `~/.openclaw` y se actualiza a sí mismo: usa el botón "Update Gateway" de la Control UI o ejecuta `openclaw update`, y la puerta de enlace se reinicia en la versión nueva. Omarchy solo elige la versión con la que comienza una instalación nueva. OpenClaw también puede ser tu agente predeterminado: elegirlo en _Agente > Harness_ configura esa misma copia en `~/.openclaw`, y el agente abre la interfaz de usuario de terminal de OpenClaw conectada a su puerta de enlace. Eliminar OpenClaw en _Eliminar > IA_ se lleva el servicio de puerta de enlace y la app con él y luego pregunta si `~/.openclaw` también debe irse, ya que ahí se guardan tus chats y credenciales junto con el propio OpenClaw y los entornos de ejecución de plugins que descarga; el valor predeterminado lo conserva, e instalar OpenClaw de nuevo lo recupera.

Herdr Desktop es la app de escritorio de [Herdr](https://herdr.dev): espacios, pestañas y paneles de terminales y agentes de código que siguen ejecutándose en su núcleo cuando cierras la ventana. Proviene del propio instalador de Herdr en lugar de un paquete, así que vive en `~/.local/share/herdr-app`, trae su núcleo en `~/.local/bin/herdr-core` cuando aún no tienes uno, y actualiza ambos por sí misma. Se ubica junto al comando `herdr` que Omarchy incluye en `Super + Ctrl + Return` en lugar de reemplazarlo, y recibe las teclas directas de ese comando: `Alt + Return` y `Alt + Shift + Return` dividen un panel hacia abajo o hacia la derecha, `Alt + Escape` lo cierra, `Ctrl + Alt + Arrow` se mueve entre paneles, `Alt + 1..9` y `Alt + Left/Right` eligen una pestaña, y `Alt + Up/Down` se mueven entre espacios. `Ctrl + 1..9` elige un espacio y `Alt + Shift + Up/Down` recorre los agentes. Las teclas con el prefijo `Ctrl + Space` se quedan solo en la terminal, ya que la app no puede mantener una tecla Ctrl simple para una secuencia. Omarchy las escribe en `~/.config/herdr-app/keys.json`, y `omarchy-refresh-herdr-app` las restablece. Al instalarla se elige el tema Omarchy de Herdr, que sigue tu tema de Omarchy desde entonces. Herdr conserva un tema para el modo claro y uno para el modo oscuro, así que después de cambiar entre un tema oscuro y uno claro de Omarchy, elige Omarchy una vez más en el selector de temas de Herdr para el otro modo.

T3 Code se ejecuta desde su versión oficial AppImage en `~/.local/share/t3code` en lugar de desde un paquete, así que se actualiza a sí mismo. Al instalarlo se pregunta si comenzar en el canal Stable o Nightly; cámbialo después en los ajustes de T3 Code. Tus hilos y ajustes viven en `~/.t3`, y eliminar T3 Code en _Eliminar > IA_ se los lleva con él.

### Modelos locales

Ejecuta un modelo abierto en tu propio equipo para tus agentes de código. Tus prompts y tu código se quedan en el equipo; nada de lo que se envía al modelo sale de él. Comienza con:

```bash
omarchy models use best text
```

Eso configura el mejor modelo de texto para este equipo, el tipo que usan tus agentes. Los modelos de imagen, video y música tienen su propio mejor modelo: `omarchy models use best image`, `video` o `music`. Ejecuta `omarchy models use best` para ver la elección de cada tipo para este equipo.

O abre el panel de modelos locales desde su ícono de destellos en la barra superior, junto al ícono de agentes, o con Super + Ctrl + Alt + X, y elige +. El ícono aparece cuando un modelo cabe en este equipo. Podman, que ejecuta los modelos, viene con Omarchy, al igual que el kit de herramientas de contenedores de NVIDIA en un equipo NVIDIA, que les da la GPU; si falta alguno de los dos, la primera configuración lo instala. Omarchy luego elige el modelo recomendado para este equipo, lo descarga y lo inicia. Espera una descarga de decenas de GB y que la mayor parte de la memoria del equipo esté en uso mientras el modelo se ejecuta: Flash Next usa unos 100 GiB con su contexto completo de 256K. Si otros modelos ocupan la memoria que necesita, se configura detenido, listo para iniciar una vez que detengas uno. El modelo se detiene al cerrar sesión; detenlo tú mismo cuando necesites la memoria para otra cosa.

`omarchy models list` muestra las opciones y explica por qué algunas no caben. Para configurar otro, ejecuta `omarchy models use <recipe>`. Hoy, `qwen3.8-flash-next-gufo` y `qwen3.8-27b-gufo` están disponibles para equipos Strix Halo de 128 GB; el de 27B ocupa unos 40 GiB, así que deja espacio para otro trabajo. En una laptop de 64 GB con Arc B390 de Intel, `qwen3.6-35b-a3b-llamacpp` se ejecuta en unos 30 GiB. Las recetas y recomendaciones nuevas llegan con `omarchy update`, a través del paquete.

Cada modelo que configuras recibe su propia línea en el panel de modelos locales: reproducir para iniciarlo, pausar para detenerlo y liberar su memoria, y el botón de terminal para abrir tu agente en él. En la parte superior, una barra muestra cómo se divide la memoria del equipo entre el propio Omarchy (el sistema y tus apps), cada modelo en ejecución y lo que está libre. Apunta a un modelo detenido y la barra muestra si cabe, o cuánto le falta. Varios pueden ejecutarse a la vez cuando caben juntos en la memoria; si uno no cabe, Omarchy dice qué modelo en ejecución detener. Arrastra las líneas por su logotipo para reordenarlas, y presiona Delete en una línea seleccionada para eliminar un modelo y su descarga.

Cada modelo de código que configuras también recibe su propia entrada en el lanzador de aplicaciones, bajo el nombre del modelo y con el logotipo de su creador, de la misma manera que iniciar sesión en Claude, Codex o Grok agrega una. Abre tu agente en ese modelo, e inicia primero el modelo si no se está ejecutando: la terminal muestra cómo se carga y entrega el control al agente una vez que está listo. Eliminar un modelo elimina su entrada.

No todos los modelos son para código. Los modelos de imagen, video y música se abren en Fantasi en su lugar, la app de Omarchy para crear imágenes, video y música con un modelo que se ejecuta en este equipo, elegido ahí o desde su línea en el panel de modelos locales.

Un modelo sigue ejecutándose exactamente como se configuró, así que una actualización de Omarchy nunca reinicia uno bajo tus agentes. Cuando Omarchy tiene un entorno de ejecución más nuevo o pesos más nuevos para un modelo que has configurado, su línea muestra un botón de actualización: presiónalo y el modelo se configura de nuevo en segundo plano, descargando solo lo que cambió, y se reinicia en la versión nueva. Un modelo que estaba detenido permanece detenido. `omarchy models update` hace lo mismo para cada modelo desde una terminal.

Desde la línea de comandos, `omarchy models start <recipe>` y `omarchy models stop <recipe>` hacen lo mismo, `omarchy models status` muestra cada modelo, y `omarchy agent --local` abre el último modelo que iniciaste en pi, sea cual sea tu agente predeterminado. OpenCode y Qwen Code también pueden usar un modelo local: `omarchy models harness opencode` u `omarchy models harness qwen` los abre ahí en su lugar, y `omarchy models harness pi` vuelve. pi también enumera cada modelo que has configurado, y los de los equipos con los que te has emparejado, en su propio selector de modelos, así que un simple `pi` también llega a ellos. Cualquier cliente compatible con OpenAI también puede conectarse: `status` muestra la dirección de cada modelo (la primera es `http://127.0.0.1:11435/v1`), el nombre de la receta es el modelo, y la clave está en `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` elimina un modelo y las descargas que ningún otro modelo usa.

Los entornos de ejecución de terceros están etiquetados con su editor. Omarchy ejecuta cada modelo sin acceso a la red.

### LLM locales

Omarchy recomienda dos maneras de ejecutar modelos LLM locales: LM Studio y Ollama. LM Studio proporciona una interfaz GUI para encontrar modelos de pesos abiertos, instalarlos y ejecutarlos. Es una gran manera de empezar con facilidad. Ollama ofrece una CLI para hacer lo mismo de manera similar. Pero si eres nuevo en los modelos locales, yo empezaría con LM Studio. Puedes instalar cualquiera de los dos en _Instalar > IA_ en el menú de Omarchy.

### Las skills de Omarchy

Las skills de agente ayudan a la IA a usar herramientas específicas de una manera específica, y Omarchy incluye siete. La skill omarchy cubre la personalización del sistema, como ajustar tu configuración de Hyprland o ajustar la barra. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app y omarchy-make-game cubren la creación de algo nuevo, omarchy-contribute cubre informar un error o enviar una corrección al proyecto original, y omarchy-diagnose-crash trabaja a partir del volcado de memoria de una falla. Están enlazadas mediante enlaces simbólicos en los directorios de skills de Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` y cada `~/.hermes/profiles/*/skills`), y la ubicación genérica `~/.agents/skills`, así que la mayoría de los harnesses las recogen automáticamente. Una carpeta de skill propia con el mismo nombre tiene prioridad.

Pero deberías tratar estas skills como experimentales. Los distintos modelos las usarán con resultados diferentes. Es mejor ejecutar primero en modo de plan, para que tengas una idea de lo que al agente le gustaría cambiar. Y luego prepárate para revertir los cambios o incluso invocar `omarchy reinstall configs`, si el agente hace un desastre con todo.
