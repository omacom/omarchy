# IA

O Omarchy inclui lançadores para os agentes de programação abaixo sem escolher um padrão para você. Execute um comando para instalar sua CLI no primeiro uso e depois autentique-se quando solicitado. Hermes é a exceção: nada é instalado para ele no primeiro uso, e escolhê-lo instala o Hermes Desktop, como _Aplicativos desktop_ abaixo explica.

### Instalando e atualizando agentes

Com exceção do Hermes, esses agentes usam a instalação preguiçosa do mise: a primeira execução instala a CLI, e as execuções seguintes a reutilizam. O mise também verifica se há uma nova versão de um agente instalado no máximo uma vez a cada quatro horas, logo antes de ele iniciar ou em segundo plano em um prompt do shell. Se essa atualização falhar ou você estiver offline, a versão instalada é executada. `omarchy update` atualiza os agentes instalados junto com o restante do Omarchy, e `mup` atualiza apenas as ferramentas gerenciadas pelo mise.

O atualizador próprio de um agente, como `claude update`, `codex update` ou um botão de atualização em um aplicativo, não atualiza a instalação gerenciada pelo mise. `codex update` falha, e `claude update` pode relatar sucesso enquanto instala uma cópia separada que o mise não acompanha. Se você preferir usar o instalador e o atualizador nativos de um agente, adicione-o a `disable_tools`; consulte [Ferramentas CLI pré-instaladas](18-development-tools.md#preinstalled-cli-tools).

Para instalar todas as ferramentas preguiçosas configuradas antes de precisar delas, execute `mise install --include-lazy`. Isso inclui as outras ferramentas CLI padrão do Omarchy, além dos agentes. Consulte [Ferramentas CLI pré-instaladas](18-development-tools.md#preinstalled-cli-tools) para instalar uma única ferramenta ou usar sua própria instalação.

O `grok` é instalado por meio do pacote `grok` oficial do mise, da mesma forma que `claude` e `codex`. Execute `grok` ou escolha-o em _Configuração > Padrões > Agente_. Pule o instalador `curl | bash` em x.ai. Esse caminho coloca uma segunda cópia em `~/.grok/bin`, a coloca no início do `PATH` e sobrescreve o wrapper do Omarchy.

O `dsh` abre sua interface no navegador em `127.0.0.1:3080`, com o diretório de lançamento como workspace padrão. Sua interface no navegador não aceita um prompt inicial, então `omarchy agent prompt` a abre com o prompt na sua área de transferência para você colar. O Omarchy o inicia com a predefinição de permissões sem aprovação da DeepSeek. O DeepSeek Harness envia logs de sessão para a DeepSeek quando você usa sua API oficial de modelo; desative isso em _Configurações > Geral > Upload Session Log_ na interface no navegador dele. O feedback que você envia também é enviado junto com a sessão, a menos que você o inicie com `DSH_TELEMETRY_MODE=DISABLED`.

### O agente padrão

Escolha seu agente padrão com `omarchy default agent <name>` ou em _Configuração > Padrões > Agente_ no Menu do Omarchy (`Super + Space`). Se o agente ainda não estiver instalado, escolhê-lo o instala primeiro. Um Omarchy recém-instalado vai convidar você a fazer essa escolha com uma notificação única.

Escolher o Claude também tenta configurar sua extensão de navegador para Chromium, Chrome, Brave, Brave Origin e Edge. A configuração da extensão se aplica a todos os usuários e pode pedir sua senha do sistema; cancelar ou uma falha na instalação da extensão ainda seleciona e inicia o Claude. Reinicie seu navegador, ative a extensão se solicitado e entre no Claude para concluir a conexão. Execute `/chrome` no Claude para verificar a conexão. Firefox e Zen não oferecem suporte a essa extensão. Se o Claude já era seu padrão antes de essa configuração ser adicionada, selecione-o novamente para instalar a extensão.

Depois de escolher, `Super + Shift + Ctrl + A` inicia o agente padrão em uma janela de terminal dedicada (ou abre o seletor, se você ainda não escolheu). Você também pode iniciá-lo direto em uma tarefa com `omarchy agent prompt "Review this project"`. Freebuff e DeepSeek Harness não aceitam um prompt inicial, então eles abrem com o prompt na sua área de transferência para você colar. Agentes iniciados dessa forma são executados sem supervisão, em seus respectivos modos de não parar para perguntar, então esteja pronto para eles realmente fazerem coisas! O MiniMax Code não tem um modo assim para suas sessões interativas, então ele pede permissões como de costume. E, como os agentes se recusam a lembrar a confiança para o seu diretório home, as execuções a partir de `$HOME` começam em `~/Work`.

Também há atalhos de terminal: `a` executa o agente padrão inline no terminal atual, enquanto `c`, `cx` e `cy` iniciam OpenCode, Claude Code e Codex diretamente (também em seus modos de aprovação automática). As mudanças de tema também são sincronizadas com os agentes: Claude Code, Pi, OpenCode e Hermes (depois que o Omarchy o instala) acompanham quando você troca o tema do Omarchy.

### O painel de agentes

A barra superior tem um ícone de agentes. Antes de você configurar um agente, o painel dele orienta você a entrar no Claude, Codex ou Grok, e o primeiro deles se torna seu agente padrão. Depois disso, o painel coloca todas as assinaturas em uma única página: cada agente e conta com seu plano, um medidor para cada um de seus limites de sessão de 5 horas e semanais com o tempo até a redefinição (passe o mouse para ver a porcentagem exata), ou o saldo pré-pago restante, sob uma linha que alterna pelo que você usou em todos eles, como tokens nesta semana e seu modelo mais usado. Em _Crie alguma coisa_, ele oferece prompts iniciais para um novo tema, plugin ou aplicativo que entregam a tarefa ao seu agente padrão. Os aplicativos são construídos da mesma forma que os próprios Hype, Monologue e Omacut do Omarchy, em C++ e Qt Quick, seguindo a skill de agente omarchy-app, e o compilador e os componentes do Qt de que eles precisam já vêm instalados. Claude Code, Codex, Grok, Kimi, Cursor e sua cota do Grok Bot, GitHub Copilot, Muse, Antigravity, Kimchi e Devin são cobertos de fábrica com seus limites, e Hermes, Mistral Vibe e Qwen Code mostram suas sessões e tokens depois que você os usa. Planos de provedores e chaves que você usa por meio de pi, omp ou opencode também aparecem: OpenCode Zen e Go, o Z.ai GLM Coding Plan, Ollama Cloud, o MiniMax Token Plan e Synthetic com seus limites; Fireworks, OpenRouter e DeepSeek com seus saldos pré-pagos; e os modelos que você executa no seu próprio hardware em Modelos locais. Cada agente é contado uma vez, sob quem o fatura, não importa por quantos harnesses você o conduza.

Clique com o botão esquerdo no ícone da barra para abrir o painel, clique com o botão direito para iniciar seu agente padrão. Os registros de uso por trás dele são regenerados a cada 15 minutos por `omarchy agent usage-update`, e o painel pode até mesclar o uso das suas outras máquinas por meio de uma pasta sincronizada. Consulte o README em `$OMARCHY_PATH/shell/plugins/agents/` para ver as configurações completas.

### Várias assinaturas

Se você paga por mais de um plano do Claude, Codex ou Grok — um Max pessoal e um de trabalho, por exemplo — o Omarchy pode manter todos eles conectados e alternar entre eles. Adicione uma assinatura com o + no painel de agentes, que orienta você ali mesmo, ou com `omarchy agent account add claude Work` (ou `codex`, ou `grok`). Ele instala a CLI se ela estiver faltando. A primeira conta de um provedor entra pelo seu navegador normal, bem onde a CLI sempre procura. Todas as seguintes entram por uma janela privativa, para que a conta em que seu navegador já está conectado não seja escolhida por engano; entre ali como a conta que você está adicionando e feche antes qualquer janela privativa que já estiver aberta. Nunca saia da CLI para fazer isso: sair revoga o login salvo, e essa conta teria de ser adicionada novamente.

Para copiar seus logins de assinatura para outra máquina Omarchy via SSH, execute `omarchy agent account copy user@laptop`. O remetente fornece um receptor temporário quando o destino não tem um instalado, para que máquinas Omarchy mais antigas possam receber contas sem uma atualização. Receptores instalados têm precedência. Isso copia todas as assinaturas do Claude, Codex e Grok; adicione nomes de provedores para selecioná-las, como em `omarchy agent account copy laptop claude`. Os nomes das contas e os IDs de comando correspondem à origem, incluindo contas já presentes no destino. Contas de destino não relacionadas recebem um sufixo numérico se seus nomes entrarem em conflito, e configurações, skills, plugins e histórico de conversas permanecem locais em cada máquina.

As credenciais existentes no destino são mantidas. Uma conta de origem que já está conectada lá tem seu nome sincronizado sem substituir suas credenciais; as outras contas são adicionadas ao lado dela. Para substituir as credenciais salvas de contas correspondentes, use `omarchy agent account copy --replace laptop claude` depois de encerrar as sessões dessa conta no destino. Um destino novo também recebe a conta ativa e as preferências de alternância da origem; um destino já estabelecido mantém as suas próprias.

As credenciais trafegam via SSH e são armazenadas em arquivos privados no destino, então copie apenas para máquinas em que você confia. Isso é uma cópia única, não uma sincronização contínua. Os tokens de atualização do Codex podem ser rotacionados por outra máquina, deixando um login copiado precisando de renovação; logins separados continuam sendo a escolha mais confiável para uso simultâneo em várias máquinas. Consulte o [guia de autenticação de contas do Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Uma conta por provedor fica ativa, e toda nova sessão começa como ela: `cx`, `cy`, um simples `claude`, `codex` ou `grok`, qualquer coisa iniciada por meio de `omarchy agent`, e scripts ou editores que encontram a CLI no `PATH`. Alterne com `omarchy agent account use work` (e volte com `omarchy agent account use main`), ou no painel pressionando o número de uma conta e depois `Enter` (ou clicando no botão Usar dela). Sessões que já estão em execução permanecem na conta com que começaram. Histórico de conversas, configurações, skills e plugins são compartilhados entre as contas, então `claude --continue` na mesma pasta continua de onde você parou na nova conta.

Com mais de uma conta, o painel mostra os limites de cada conta lado a lado, com a ativa marcada. Por padrão, o Omarchy avisa você quando a conta ativa passa de 95% de um limite, e clicar na notificação alterna para a conta com mais folga. Passe o mouse sobre a linha de uma conta no painel e clique em Autoswitch, que aparece ao lado de Usar (ou pressione `m`), ou execute `omarchy agent account mode auto`, para que ela alterne sozinha; enquanto estiver ativado, Autoswitch ocupa o lugar de Usar, e clicar nele novamente volta a apenas notificar. Adicione um número para mudar o limite, como em `omarchy agent account mode auto 90`. Se todas as contas estiverem acima do limite, você será avisado uma vez, junto com qual conta libera primeiro. Enquanto uma conta ativa estiver a até 15 pontos do seu limite (80% no padrão), seus limites são verificados a cada três minutos, em vez de a cada 15.

`omarchy agent account list` mostra todas as contas e seus limites mais recentes, `omarchy agent account remove work` esquece uma, e `omarchy agent account rename primary Hey` renomeia uma (ou clique no nome de uma conta no painel). Esses comandos funcionam nas contas do seu agente padrão; para alcançar o outro provedor, nomeie-o primeiro, como em `omarchy agent account use codex side`. O login que você já tinha em `~/.claude` ou `~/.codex` é a conta _Main_ e permanece onde está. Uma conta deixada sem uso por mais de cerca de oito horas pode mostrar _Login necessário_; clique nela para entrar novamente nessa conta direto no painel, ou inicie uma sessão nela, o que atualiza o login por conta própria. Os servidores MCP que você tinha quando uma conta foi adicionada acompanham essa conta, mas os que você adiciona depois com `claude mcp add` só alcançam a conta em que você os adicionou. O Claude Desktop e ferramentas configuradas com um caminho absoluto para um binário da CLI não acompanham a alternância. Um `CLAUDE_CONFIG_DIR`, `CODEX_HOME` ou `GROK_HOME` explícito tem precedência sobre a conta selecionada.

### Diagnóstico de falhas

O Omarchy observa o systemd-coredump em busca de falhas de processos. Quando algo sofre um segfault, você recebe uma notificação "Processo falhou" — clique nela, e a falha é entregue ao seu agente padrão junto com a skill diagnose-crash do Omarchy, que orienta o agente a estabelecer os fatos a partir do core dump e decidir se vale a pena relatar a falha upstream. Você também pode executá-la manualmente contra qualquer PID de `coredumpctl list` com `omarchy agent crash <pid>`.

A observação está ativada por padrão. Desative-a em _Acionador > Alternar > Captura de Falhas_ (ou com `omarchy toggle crash-capture`) e as notificações param; `omarchy agent crash <pid>` ainda funciona manualmente.

As falhas também podem ser silenciadas um programa por vez, que é o que o diagnóstico oferece a você no final. `omarchy crash mute hyprland` interrompe as notificações apenas para esse programa, `omarchy crash mute hyprland off` as traz de volta, e `omarchy crash mute` sozinho lista o que você silenciou. Ele aceita o caminho do binário tão bem quanto seu nome, então `omarchy crash mute /usr/bin/hyprland` faz a mesma coisa. Coloque entre aspas um nome com espaço, como em `omarchy crash mute 'Some App'`. Todo o resto ainda notifica, e o programa silenciado ainda falha — isso esconde o lembrete, não corrige nada.

### Aplicativos desktop

O menu _Instalar > IA_ também traz alguns aplicativos gráficos de IA: o aplicativo desktop do ChatGPT, o aplicativo desktop do Claude (o beta para Linux da Anthropic, com abas Chat, Cowork e Claude Code), Grok Bot para conversar com os modelos da xAI, Herdr Desktop, Hermes Desktop, OpenClaw, o aplicativo desktop do Perplexity e T3 Code. O Grok Bot é o aplicativo desktop de chat. O agente de programação é o comando `grok`.

O Hermes Desktop é aquele que você precisa conhecer, porque uma máquina tem um único Hermes, e ele é o do aplicativo: o Hermes só é instalado por meio do aplicativo, e o comando `hermes` que o agente padrão executa é o do aplicativo. Escolher o Hermes como agente padrão instala a mesma coisa que a entrada _Instalar > IA_ instala: o pacote, e um runtime do Hermes em `~/.hermes` configurado pelo próprio instalador do Hermes, o que leva alguns minutos na primeira vez. Esse runtime é o único Hermes que o comando `hermes` no terminal, o agente padrão e o aplicativo usam, e ele se atualiza com `hermes update`, em vez de esperar por uma versão do Omarchy. Instalá-lo também entrega ao Hermes o tema do Omarchy como uma skin chamada `omarchy`, que todas as superfícies do Hermes acompanham quando você troca de tema; escolha outra nas configurações de Aparência do Hermes ou com `/skin` se preferir que ele não faça isso, e o Omarchy deixa essa escolha em paz. Remover o aplicativo em _Remover > IA_ fecha o Hermes primeiro, gateway incluído, leva esse runtime junto, e mantém suas conversas, memórias e as skills que o Hermes escreveu para si mesmo, a menos que você diga o contrário: ele pergunta, com "não" como padrão, se esses dados e suas configurações de conexão também devem ser removidos.

A experiência desktop do OpenClaw é sua Control UI, que abre como um aplicativo web apoiado por seu próprio gateway local. O OpenClaw vive em `~/.openclaw` e se atualiza sozinho: use o botão "Update Gateway" da Control UI ou execute `openclaw update`, e o gateway reinicia na nova versão. O Omarchy só escolhe a versão a partir da qual uma instalação nova começa. Remover o OpenClaw em _Remover > IA_ leva o serviço do gateway e o aplicativo junto e depois pergunta se `~/.openclaw` também deve ser removido, já que ele guarda suas conversas e credenciais junto com o próprio OpenClaw e os runtimes de plugins que ele baixa; o padrão é mantê-lo, e instalar o OpenClaw novamente o retoma.

O Herdr Desktop é o aplicativo desktop do [Herdr](https://herdr.dev): espaços, abas e painéis de terminais e agentes de programação que continuam em execução em seu núcleo quando você fecha a janela. Ele vem do próprio instalador do Herdr, e não de um pacote, então vive em `~/.local/share/herdr-app`, traz seu núcleo junto em `~/.local/bin/herdr-core` quando você ainda não tem um, e atualiza a si mesmo e a ele. Ele fica ao lado do comando `herdr` que o Omarchy distribui em `Super + Ctrl + Return`, em vez de substituí-lo. Instalá-lo escolhe o tema Omarchy do Herdr, que acompanha seu tema do Omarchy a partir de então. O Herdr mantém um tema para o modo claro e um para o escuro, então, depois de alternar entre um tema escuro e um claro do Omarchy, escolha Omarchy no seletor de temas do Herdr mais uma vez para o outro modo.

O T3 Code é executado a partir de sua versão oficial em AppImage em `~/.local/share/t3code`, e não de um pacote, então ele se atualiza sozinho. Instalá-lo pergunta se você quer começar no canal Stable ou Nightly; altere depois nas configurações do T3 Code. Suas threads e configurações vivem em `~/.t3`, e remover o T3 Code em _Remover > IA_ as leva junto.

### Modelos locais

Execute um modelo aberto na sua própria máquina para seus agentes de programação. Seus prompts e seu código permanecem na máquina; nada do que é enviado ao modelo sai dela. Comece com:

```bash
omarchy agent local use best
```

Ou, no painel de agentes na barra superior, escolha + e depois IA Local, que aparece quando um modelo cabe nesta máquina. Na primeira vez, isso instala o Podman, que executa os modelos, e, em uma máquina NVIDIA, o kit de ferramentas de contêineres da NVIDIA, que dá a eles acesso à GPU. O Omarchy então escolhe o modelo recomendado para esta máquina, o baixa e o inicia. Espere um download de dezenas de GB e a maior parte da memória da máquina em uso enquanto o modelo estiver em execução: o Flash Next usa cerca de 100 GiB com seu contexto completo de 256K. Se outros modelos estiverem ocupando a memória de que ele precisa, ele é configurado parado, pronto para iniciar assim que você parar um deles. O modelo para ao sair da sessão; pare-o você mesmo quando precisar da memória para outra coisa.

`omarchy agent local list` mostra as opções e explica por que algumas não cabem. Para configurar outro, execute `omarchy agent local use <recipe>`. Hoje, `qwen3.8-flash-next-gufo` e `qwen3.8-27b-gufo` estão disponíveis para máquinas Strix Halo de 128 GB; o 27B usa cerca de 40 GiB, então deixa espaço para outro trabalho. Novas receitas e recomendações chegam com `omarchy update`, por meio do pacote.

Cada modelo que você configura ganha sua própria linha no painel de agentes, ao lado das suas assinaturas: play para iniciá-lo, pause para pará-lo e liberar sua memória, e o botão de terminal para abrir seu agente nele. Vários podem ser executados ao mesmo tempo quando cabem juntos na memória; se um não couber, o Omarchy diz qual modelo em execução parar. Arraste as linhas para reordená-las e pressione Delete em uma linha selecionada para remover um modelo e seu download.

Na linha de comando, `omarchy agent local start <recipe>` e `omarchy agent local stop <recipe>` fazem o mesmo, `omarchy agent local status` mostra todos os modelos, e `omarchy agent --local` abre seu agente padrão no último modelo que você iniciou (pi, se seu agente padrão não puder usar um modelo local). Qualquer cliente compatível com a OpenAI também pode se conectar: `status` mostra o endereço de cada modelo (o primeiro é `http://127.0.0.1:11435/v1`), o nome da receita é o modelo, e a chave está em `~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` exclui um modelo e os downloads que nenhum outro modelo usa.

Runtimes de terceiros são rotulados com seu editor. O Omarchy executa todos os modelos sem acesso à rede.

### LLMs locais

O Omarchy recomenda duas formas de executar modelos LLM locais: LM Studio e Ollama. O LM Studio oferece uma interface gráfica para encontrar modelos de pesos abertos, instalá-los e executá-los. É uma ótima forma de começar com facilidade. O Ollama oferece uma CLI para fazer o mesmo. Mas, se você é novo em modelos locais, eu começaria pelo LM Studio. Você pode instalar qualquer um dos dois em _Instalar > IA_ no Menu do Omarchy.

### A Skill do Omarchy

As skills de agente ajudam a IA a usar ferramentas específicas de uma forma específica, e o Omarchy vem com uma skill padrão para personalizar o sistema. Como ajustar sua configuração do Hyprland, ajustar a barra ou até criar um novo tema do zero. Ela é vinculada por symlink aos diretórios de skills do Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` e cada `~/.hermes/profiles/*/skills`) e ao local genérico `~/.agents/skills`, então a maioria dos harnesses a detecta automaticamente.

Mas você deve tratar essa skill como experimental. Modelos diferentes vão usá-la com efeitos diferentes. É melhor executá-la primeiro no modo de planejamento, para você ter uma ideia do que o agente gostaria de mudar. E depois esteja pronto para reverter as mudanças ou até invocar `omarchy reinstall configs`, se o agente fizer uma bagunça em tudo.
