### Instalando e atualizando agentes

Exceto por Hermes e OpenClaw, esses agentes usam a instalação preguiçosa do mise: a primeira inicialização instala a CLI, e as inicializações posteriores a reutilizam. O mise também verifica se um agente instalado tem uma nova versão no máximo uma vez a cada quatro horas, logo antes de ele iniciar ou em segundo plano em um prompt do shell. Se essa atualização falhar ou você estiver offline, a versão instalada é executada. `omarchy update` atualiza os agentes instalados com o restante do Omarchy, e `mup` atualiza apenas as ferramentas gerenciadas pelo mise.

O atualizador próprio de um agente, como `claude update`, `codex update` ou um botão de atualização em um aplicativo, não atualiza a instalação gerenciada pelo mise. `codex update` falha, e `claude update` pode relatar sucesso enquanto instala uma cópia separada que o mise não rastreia. Se você preferir usar o instalador e o atualizador nativos de um agente, adicione-o a `disable_tools`; veja [Ferramentas de CLI pré-instaladas](18-development-tools.md#preinstalled-cli-tools).

Para instalar todas as ferramentas preguiçosas configuradas antes de precisar delas, execute `mise install --include-lazy`. Isso inclui as outras ferramentas de CLI padrão do Omarchy, além dos agentes. Veja [Ferramentas de CLI pré-instaladas](18-development-tools.md#preinstalled-cli-tools) para instalar uma única ferramenta ou usar sua própria instalação.

`grok` é instalado através do pacote primário `grok` do mise, da mesma forma que `claude` e `codex`. Execute `grok`, ou marque-o com uma estrela no painel de agentes. Pule o instalador `curl | bash` em x.ai. Esse caminho coloca uma segunda cópia em `~/.grok/bin`, a coloca no início do `PATH` e sobrescreve o wrapper do Omarchy.

`dsh` abre sua interface de navegador em `127.0.0.1:3080`, com o diretório de inicialização como seu workspace padrão. Sua interface de navegador não aceita um prompt inicial, então `omarchy agent prompt` a abre com o prompt na sua área de transferência para colar. O Omarchy a inicia com a predefinição de permissão sem aprovação da DeepSeek. O DeepSeek Harness envia logs de sessão para a DeepSeek quando você usa sua API oficial de modelo; desative isso em _Settings > General > Upload Session Log_ na sua interface de navegador. O feedback que você envia a ele também é enviado com a sessão, a menos que você o inicie com `DSH_TELEMETRY_MODE=DISABLED`.

### O agente padrão

Escolha seu agente padrão com a estrela ao lado de um agente no painel de agentes, que fica preenchida no padrão, ou com `omarchy default agent <name>`, que também aceita qualquer harness sem uma linha lá. Se o agente ainda não estiver instalado, escolhê-lo o instala primeiro, e ele também ganha um lançador próprio no lançador de aplicativos, ao lado de Agent. Um Omarchy novo convida você a configurar um com uma notificação única, que abre o painel de agentes.

Escolher o Claude também tenta configurar sua extensão de navegador para Chromium, Chrome, Brave, Brave Origin e Edge. A configuração da extensão se aplica a todos os usuários e pode pedir sua senha do sistema; cancelar ou uma instalação de extensão com falha ainda seleciona e inicia o Claude. Reinicie seu navegador, ative a extensão se solicitado e entre no Claude para concluir a conexão. Execute `/chrome` no Claude para verificar a conexão. Firefox e Zen não suportam essa extensão. Se o Claude já era seu padrão antes de essa configuração ser adicionada, selecione-o novamente para instalar a extensão.

Depois de escolher, `Super + Shift + Ctrl + A` inicia o agente padrão em uma janela de terminal dedicada (ou abre o seletor se você ainda não escolheu). Você também pode iniciá-lo direto em uma tarefa com `omarchy agent prompt "Review this project"`. Freebuff e DeepSeek Harness não aceitam um prompt inicial, então eles abrem com o prompt na sua área de transferência para colar. Agentes iniciados dessa forma executam sem supervisão em seus respectivos modos de não parar para perguntar, então esteja pronto para eles realmente fazerem coisas! O MiniMax Code não tem esse modo para suas sessões interativas, então ele pede permissões como de costume. E como os agentes se recusam a lembrar a confiança no seu diretório home, as inicializações a partir de `$HOME` começam em `~/Work`.

Também há atalhos de terminal: `a` executa o agente padrão inline no terminal atual, enquanto `c`, `cx` e `cy` iniciam OpenCode, Claude Code e Codex diretamente (novamente em seus modos de aprovação automática). Mudanças de tema também sincronizam para os agentes: Claude Code, Pi, OpenCode e Hermes (depois que o Omarchy o instalou) acompanham quando você troca o tema do Omarchy.

### Suas instruções para agentes

Regras pessoais para cada agente vão em `~/.agents/AGENTS.md`, ao lado das skills compartilhadas em `~/.agents/skills`. Abra-o com o ícone de documento ao lado do + no painel de agentes, ou com `omarchy agent instructions --edit`, que também o vincula a cada harness que mantém seu próprio arquivo global: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` do Copilot, e assim por diante. Crush e Amp leem o link `~/.config/AGENTS.md`, enquanto omp, Kimi e DeepSeek Harness leem `~/.agents/AGENTS.md` diretamente. Escolher um agente padrão também o vincula. Um arquivo de instruções que você já tinha se torna o compartilhado se ainda não havia nenhum; caso contrário, ele é mantido ao lado do link como `.bak`. Execute `omarchy agent instructions` para vincular novamente após instalar outro agente.

### O painel de agentes

A barra superior tem um ícone de agentes. Antes de você configurar um agente, seu painel oferece três formas de começar: entrar com uma assinatura Claude, Codex, Grok, Gemini, Muse, Cursor ou Copilot, ou em More um plano de programação OpenCode Go, MiniMax, Synthetic ou Z.ai; pagar conforme o uso com Fireworks, OpenCode Zen and Go, OpenRouter, ou em More DeepSeek ou qualquer outro provedor ao qual o OpenCode se conecte, todos executados no OpenCode; ou executar o melhor modelo para o seu computador, quando um couber nele. O primeiro que você concluir se torna seu agente padrão, e o + no painel oferece os mesmos três depois. Depois disso, o painel coloca cada assinatura em uma página: cada agente e conta com seu plano, um medidor para cada um de seus limites de sessão de 5 horas e semanal com o tempo até ele reiniciar (passe o mouse para ver a porcentagem exata), ou o saldo pré-pago restante, sob uma linha que alterna pelo que você usou em todos eles, como tokens nesta semana e seu modelo mais usado. Em _Make something cool_, ele oferece prompts iniciais para um novo tema, plugin, aplicativo ou jogo que entregam a tarefa ao seu agente padrão. Aplicativos são construídos da forma como os próprios Hype, Monologue e Omacut do Omarchy são, em C++ e Qt Quick, seguindo a skill de agente omarchy-make-app, e o compilador e as peças do Qt de que eles precisam vêm instalados. Jogos são uma única página three.js em `~/Games/vibes`, seguindo a skill de agente omarchy-make-game, e todos abrem a partir de um lançador Game Vibes no tema atual; eles carregam three.js da web, então precisam de uma conexão para iniciar. Claude Code, Codex, Grok, Kimi, Cursor e sua cota Grok Bot, GitHub Copilot, Muse, Gemini (através do Antigravity) e Devin são cobertos de fábrica com seus limites, Kimchi com seu plano, créditos pré-pagos e orçamentos de gastos, e Hermes, Mistral Vibe e Qwen Code mostram suas sessões e tokens depois que você os usou. Planos de provedores e chaves que você usa através de pi, omp ou opencode também aparecem: OpenCode Zen and Go, o Z.ai GLM Coding Plan, Ollama Cloud, o MiniMax Token Plan e Synthetic com seus limites; OpenRouter e DeepSeek com seus saldos pré-pagos; Fireworks com seus gastos nos últimos 30 dias. Tokens de modelos que você executa no seu próprio hardware também contam para os totais; os modelos em si têm um painel próprio, descrito em [Modelos locais](#local-models). Cada agente é contado uma vez, sob quem o fatura, por quantos harnesses você o conduza.

Clique com o botão esquerdo no ícone da barra ou pressione `Super + Ctrl + X` para o painel, clique com o botão direito para iniciar seu agente padrão e clique com o botão do meio para atualizar. Os registros de uso por trás dele são regenerados a cada 15 minutos por `omarchy agent usage update`, e o painel pode até mesclar o uso das suas outras máquinas através de uma pasta sincronizada. Veja o README em `$OMARCHY_PATH/shell/plugins/agents/` para as configurações completas.

### Várias assinaturas

Se você paga por mais de um plano Claude, Codex ou Grok — um Max pessoal e um de trabalho, por exemplo — o Omarchy pode manter todos conectados e alternar entre eles. Adicione uma assinatura com o + no painel de agentes, que o guia ali mesmo, ou com `omarchy agent account add claude Work` (ou `codex`, ou `grok`). O mesmo + e comando entram no Gemini (`gemini`) e no OpenCode (`opencode`), e salvam uma chave de API do Fireworks (`fireworks`) ou da OpenRouter (`openrouter`) no OpenCode; o comando também entra no Copilot (`copilot`), no Cursor (`cursor`) e no Muse (`muse`). Esses mantêm um único login cada. Ele instala a CLI se ela estiver faltando. A primeira conta de um provedor entra através do seu navegador normal, exatamente onde a CLI sempre procura. Cada uma depois disso entra através de uma janela privada, para que a conta em que seu navegador já está conectado não seja capturada por engano; entre lá como a conta que você está adicionando e feche qualquer janela privada que você já tinha aberto antes. Nunca saia da CLI para fazer isso: sair revoga o login salvo, e essa conta teria que ser adicionada novamente.

Para copiar seus logins de assinatura para outra máquina Omarchy por SSH, execute `omarchy agent account copy user@laptop`. O remetente fornece um receptor temporário quando o destino não tem um instalado, para que máquinas Omarchy mais antigas possam receber contas sem uma atualização. Receptores instalados têm precedência. Isso copia todas as assinaturas Claude, Codex e Grok; adicione nomes de provedores para selecioná-las, como em `omarchy agent account copy laptop claude`. Nomes de contas e IDs de comando coincidem com a origem, incluindo contas já presentes no destino. Contas de destino não relacionadas recebem um sufixo numérico se seus nomes conflitarem, e configurações, skills, plugins e histórico de conversas permanecem locais em cada máquina.

Credenciais existentes no destino são mantidas. Uma conta de origem já conectada lá tem seu nome sincronizado sem substituir suas credenciais; outras contas são adicionadas ao lado dela. Para substituir credenciais salvas de contas correspondentes, use `omarchy agent account copy --replace laptop claude` depois de encerrar as sessões dessa conta no destino. Um destino novo também recebe a conta ativa e as preferências de alternância da origem; um destino estabelecido mantém as suas próprias.

Credenciais viajam através do SSH e são armazenadas em arquivos privados no destino, então copie apenas para máquinas em que você confia. Isso é uma cópia única, não uma sincronização contínua. Tokens de atualização do Codex podem ser rotacionados por outra máquina, deixando um login copiado precisando de renovação; logins separados continuam sendo a escolha mais confiável para uso simultâneo em várias máquinas. Veja as [orientações de autenticação de conta do Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Uma conta por provedor fica ativa, e cada nova sessão começa como ela: `cx`, `cy`, um `claude`, `codex` ou `grok` simples, qualquer coisa iniciada através de `omarchy agent`, e scripts ou editores que encontram a CLI no `PATH`. Alterne com `omarchy agent account use work` (e volte com `omarchy agent account use main`), ou no painel pressionando o número de uma conta e depois `Enter` (ou clicando na sua estrela). Sessões Claude em execução também alternam, a partir da próxima mensagem: cada sessão Claude executa em `~/.claude`, que sempre mantém o login da conta ativa. Uma sessão Claude iniciada na pasta própria de uma conta por um Omarchy mais antigo mantém esse login até encerrar, então a alternância nomeia essas sessões e conclui sozinha quando elas se forem. Sessões Codex e Grok em execução permanecem na conta com que começaram. Histórico de conversas, configurações, skills e plugins são compartilhados entre contas, então `claude --continue` na mesma pasta continua de onde você parou na nova conta.

Com mais de uma conta, o painel mostra os limites de cada conta lado a lado, com uma estrela preenchida na que está em uso. O Omarchy notifica você quando a conta ativa passa de 95% de um limite, e clicar na notificação alterna para a conta com mais folga. Ele nunca alterna sozinho. Altere o limiar com `omarchy agent account threshold 90`. Se cada conta estiver acima do limiar, você saberá disso uma vez, junto com qual conta libera primeiro. Enquanto uma conta ativa estiver dentro de 15 pontos do seu limiar (80% no padrão), seus limites são verificados a cada três minutos, em vez de a cada 15.

`omarchy agent account list` mostra cada conta e seus limites mais recentes, `omarchy agent account remove work` esquece uma, e `omarchy agent account rename primary Hey` renomeia uma (ou clique no nome de uma conta no painel). Esses comandos funcionam nas contas do seu agente padrão; para alcançar o outro provedor, nomeie-o primeiro, como em `omarchy agent account use codex side`. O login que você já tinha em `~/.claude` ou `~/.codex` é a conta _Main_. A do Codex fica onde está; a do Claude aguarda em uma pasta própria enquanto outra conta está ativa. Uma conta deixada sem uso por mais de cerca de oito horas pode mostrar _Sign-in required_; clique nela para entrar novamente nessa conta direto no painel, ou alterne para ela e inicie uma sessão, que atualiza o login sozinha. Servidores MCP que você adiciona com `claude mcp add` alcançam cada conta Claude, já que todos executam em `~/.claude`; para Codex e Grok, servidores que você tinha quando uma conta foi adicionada vêm junto para ela, mas os posteriores só alcançam a conta em que você os adicionou. O Claude Desktop mantém um login próprio, e ferramentas Codex ou Grok configuradas com um caminho absoluto para um binário de CLI não acompanham a alternância. Um `CLAUDE_CONFIG_DIR`, `CODEX_HOME` ou `GROK_HOME` explícito tem precedência sobre a conta selecionada.

### Diagnóstico de falhas

O Omarchy observa o systemd-coredump em busca de falhas de processos. Depois que você escolhe um agente padrão, qualquer programa seu que despeje core traz uma notificação "Process crashed" — clique nela, e a falha é entregue ao seu agente padrão junto com a skill omarchy-diagnose-crash do Omarchy, que guia o agente para estabelecer os fatos a partir do core dump e decidir se a falha vale ser relatada upstream. Você também pode executá-la manualmente contra qualquer PID de `coredumpctl list` com `omarchy agent crash <pid>`.

A observação está ativada por padrão. Desative-a em _Trigger > Toggle > Crash Capture Off_ (ou com `omarchy toggle crash-capture`) e as notificações param; `omarchy agent crash <pid>` ainda funciona manualmente.

Falhas também podem ser silenciadas um programa por vez, que é o que o diagnóstico oferece a você no final. `omarchy crash mute hyprland` para as notificações apenas para esse programa, `omarchy crash mute hyprland off` as traz de volta, e `omarchy crash mute` sozinho lista o que você silenciou. Ele aceita o caminho do binário tão bem quanto seu nome, então `omarchy crash mute /usr/bin/hyprland` faz a mesma coisa. Coloque entre aspas um nome com um espaço, como em `omarchy crash mute 'Some App'`. Todo o resto ainda notifica, e o programa silenciado ainda falha — isso esconde o lembrete, não corrige nada.

### Aplicativos de desktop

O menu _Install > AI_ também traz alguns aplicativos gráficos de IA: Amp Desktop, Antigravity Desktop, o aplicativo de desktop do ChatGPT, o aplicativo de desktop do Claude (o beta para Linux da Anthropic, com abas Chat, Cowork e Claude Code), Grok Bot para conversar com os modelos da xAI, Herdr Desktop, Hermes Desktop, OpenClaw, o aplicativo de desktop do Perplexity e T3 Code. Grok Bot é o aplicativo de chat de desktop. O agente de programação é o comando `grok`.

O Hermes Desktop é o que você precisa conhecer, porque uma máquina tem um Hermes, e ele é o do aplicativo: o Hermes só é instalado através do aplicativo, e o comando `hermes` que o agente padrão executa é o do aplicativo. Escolher o Hermes como agente padrão instala a mesma coisa que a entrada _Install > AI_: o pacote, e um runtime Hermes em `~/.hermes` configurado pelo próprio instalador do Hermes, que leva alguns minutos na primeira vez. Esse runtime é o único Hermes que o comando `hermes` do terminal, o agente padrão e o aplicativo usam, e ele se atualiza com `hermes update` em vez de esperar por uma versão do Omarchy. Instalá-lo também entrega ao Hermes o tema do Omarchy como uma skin chamada `omarchy`, que cada superfície do Hermes acompanha conforme você troca de temas; escolha outra nas configurações de Appearance do Hermes ou com `/skin` se você preferir que não, e o Omarchy deixa essa escolha em paz. Remover o aplicativo em _Remove > AI_ fecha o Hermes primeiro, gateway incluído, leva esse runtime junto e mantém seus chats, memórias e as skills que o Hermes escreveu para si mesmo, a menos que você diga o contrário: ele pergunta, com padrão não, se esses dados e suas configurações de conexão também devem ir.

A experiência de desktop do OpenClaw é sua Control UI, que abre como um aplicativo web apoiado por seu próprio gateway local. O OpenClaw vive em `~/.openclaw` e se atualiza sozinho: use o botão "Update Gateway" da Control UI ou execute `openclaw update`, e o gateway reinicia na nova versão. O Omarchy só escolhe a versão com que uma instalação nova começa. O OpenClaw também pode ser seu agente padrão: escolhê-lo com `omarchy default agent openclaw` configura essa mesma cópia em `~/.openclaw`, e o agente abre a interface de terminal do OpenClaw conectada ao seu gateway. Remover o OpenClaw em _Remove > AI_ leva o serviço gateway e o aplicativo junto e depois pergunta se `~/.openclaw` também deve ir, já que isso mantém seus chats e credenciais ao lado do próprio OpenClaw e dos runtimes de plugins que ele baixa; o padrão o mantém, e instalar o OpenClaw novamente o recupera.

O Herdr Desktop é o aplicativo de desktop do [Herdr](https://herdr.dev): espaços, abas e painéis de terminais e agentes de programação que continuam executando em seu núcleo quando você fecha a janela. Ele vem do próprio instalador do Herdr em vez de um pacote, então vive em `~/.local/share/herdr-app`, traz seu núcleo junto em `~/.local/bin/herdr-core` quando você ainda não tem um, e atualiza ambos sozinho. Ele fica ao lado do comando `herdr` que o Omarchy traz em `Super + Ctrl + Return`, em vez de substituí-lo, e recebe as teclas diretas desse comando: `Alt + Return` e `Alt + Shift + Return` dividem um painel para baixo ou para a direita, `Alt + Escape` o fecha, `Ctrl + Alt + Arrow` move entre painéis, `Alt + 1..9` e `Alt + Left/Right` escolhem uma aba, e `Alt + Up/Down` move entre espaços. `Ctrl + 1..9` escolhe um espaço e `Alt + Shift + Up/Down` percorre os agentes. As teclas de prefixo `Ctrl + Space` permanecem apenas no terminal, já que o aplicativo não pode manter uma tecla Ctrl simples para uma sequência. O Omarchy escreve essas em `~/.config/herdr-app/keys.json`, e `omarchy-refresh-herdr-app` as coloca de volta. Instalá-lo escolhe o tema Omarchy do Herdr, que acompanha seu tema Omarchy a partir de então. O Herdr mantém um tema para o modo claro e um para o modo escuro, então, depois de alternar entre um tema Omarchy escuro e um claro, escolha Omarchy no seletor de temas do Herdr mais uma vez para o outro modo.

O T3 Code executa a partir de seu lançamento oficial AppImage em `~/.local/share/t3code`, em vez de um pacote, então ele se atualiza sozinho. Instalá-lo pergunta se deve começar no canal Stable ou Nightly; altere depois nas configurações do T3 Code. Seus threads e configurações vivem em `~/.t3`, e remover o T3 Code em _Remove > AI_ os leva junto.

### Modelos locais

Execute um modelo aberto na sua própria máquina para seus agentes de programação. Seus prompts e código ficam na máquina; nada enviado ao modelo sai dela. Comece com:

```bash
omarchy models use best text
```

Isso configura o melhor modelo de texto para esta máquina, o tipo que seus agentes usam. Modelos de imagem, vídeo e música têm um melhor próprio: `omarchy models use best image`, `video` ou `music`. Execute `omarchy models use best` para ver a escolha de cada tipo para esta máquina.

Ou abra o painel de modelos locais a partir do seu ícone de brilhos na barra superior, ao lado do ícone de agentes, ou com Super + Ctrl + Alt + X, e escolha +. O ícone aparece quando um modelo cabe nesta máquina. O Podman, que executa os modelos, vem com o Omarchy, assim como o kit de ferramentas de contêiner da NVIDIA em uma máquina NVIDIA, que lhes dá a GPU; se algum deles estiver faltando, a primeira configuração o instala. O Omarchy então escolhe o modelo recomendado para esta máquina, o baixa e o inicia. Espere um download de dezenas de GB e a maior parte da memória da máquina em uso enquanto o modelo executa: o Flash Next usa cerca de 100 GiB com seu contexto completo de 256K. Se outros modelos ocuparem a memória de que ele precisa, ele é configurado parado, pronto para iniciar quando você parar um. O modelo para no logout; pare-o você mesmo quando precisar da memória para outra coisa.

`omarchy models list` mostra as opções e explica por que algumas não cabem. Para configurar outro, execute `omarchy models use <recipe>`. Hoje, `qwen3.8-flash-next-gufo` e `qwen3.8-27b-gufo` estão disponíveis para máquinas Strix Halo de 128 GB; o 27B usa cerca de 40 GiB, então deixa espaço para outro trabalho. Em um laptop de 64 GB com Arc B390 da Intel, `qwen3.6-35b-a3b-llamacpp` executa em cerca de 30 GiB. Novas receitas e recomendações chegam com `omarchy update`, através do pacote.

Cada modelo que você configura ganha sua própria linha no painel de modelos locais: play para iniciá-lo, pause para pará-lo e liberar sua memória, e o botão de terminal para abrir seu agente nele. No topo, uma barra mostra como a memória da máquina é dividida entre o próprio Omarchy (o sistema e seus aplicativos), cada modelo em execução e o que está livre. Aponte para um modelo parado e a barra mostra se ele cabe, ou quanto falta. Vários podem executar ao mesmo tempo quando cabem juntos na memória; se um não couber, o Omarchy diz qual modelo em execução parar. Arraste linhas pelo seu logo para reordená-las e pressione Delete em uma linha selecionada para remover um modelo e seu download.

Cada modelo de programação que você configura também ganha sua própria entrada no lançador de aplicativos, sob o nome do modelo e com o logo do seu criador, da forma como entrar no Claude, Codex ou Grok adiciona uma. Ele abre seu agente nesse modelo e inicia o modelo primeiro se ele não estiver executando: o terminal mostra ele carregando e entrega ao agente quando estiver pronto. Remover um modelo remove sua entrada.

Nem todo modelo é para programação. Modelos de imagem, vídeo e música abrem no Fantasi, o aplicativo do Omarchy para fazer imagens, vídeo e música com um modelo executando nesta máquina, escolhido lá ou a partir da sua linha no painel de modelos locais.

Um modelo continua executando exatamente como foi configurado, então uma atualização do Omarchy nunca reinicia um sob seus agentes. Quando o Omarchy tem um runtime mais novo ou pesos mais novos para um modelo que você configurou, sua linha mostra um botão de atualização: pressione-o e o modelo é configurado novamente em segundo plano, baixando apenas o que mudou, e reinicia na nova versão. Um modelo que estava parado permanece parado. `omarchy models update` faz o mesmo para cada modelo a partir de um terminal.

A partir da linha de comando, `omarchy models start <recipe>` e `omarchy models stop <recipe>` fazem o mesmo, `omarchy models status` mostra cada modelo, e `omarchy agent --local-model <recipe>` abre esse modelo no pi, qualquer que seja seu agente padrão. Para tornar seu modelo local o que a tecla de atalho do agente, o console Quake e _Make something_ abrem, execute `omarchy default agent local` ou marque com uma estrela um modelo em execução no painel de agentes. O pi também lista cada modelo que você configurou, e os de máquinas com as quais você pareou, em seu próprio seletor de modelos, então um `pi` simples também os alcança. Qualquer cliente compatível com OpenAI também pode se conectar: `status` mostra o endereço de cada modelo (o primeiro é `http://127.0.0.1:11435/v1`), o nome da receita é o modelo, e a chave está em `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` exclui um modelo e os downloads que nenhum outro modelo usa.

Runtimes de terceiros são rotulados com seu editor. O Omarchy executa cada modelo sem acesso à rede.

### LLMs locais

O Omarchy recomenda duas formas de executar modelos LLM locais: LM Studio e Ollama. O LM Studio fornece uma interface GUI para encontrar modelos de pesos abertos, instalá-los e executá-los. É uma ótima forma de começar facilmente. O Ollama oferece uma CLI para fazer isso de forma semelhante. Mas se você é novo em modelos locais, eu começaria com o LM Studio. Você pode instalar qualquer um deles em _Install > AI_ no Menu Omarchy.

### As skills do Omarchy

Skills de agente ajudam a IA a usar ferramentas específicas de uma forma específica, e o Omarchy traz sete delas. A skill omarchy cobre personalizar o sistema, como ajustar sua configuração do Hyprland ou ajustar a barra. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app e omarchy-make-game cobrem fazer algo novo, omarchy-contribute cobre relatar um bug ou enviar uma correção upstream, e omarchy-diagnose-crash trabalha sobre o core dump de uma falha. Elas são vinculadas por symlink aos diretórios de skills para Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` e cada `~/.hermes/profiles/*/skills`) e o local genérico `~/.agents/skills`, então a maioria dos harnesses as captura automaticamente. Uma pasta de skill sua com o mesmo nome tem precedência.

Mas você deve tratar essas skills como experimentais. Modelos diferentes a usarão com efeito diferente. É melhor executar no modo de planejamento primeiro, para você ter uma ideia do que o agente gostaria de mudar. E depois esteja pronto para reverter mudanças ou até invocar `omarchy reinstall configs`, se o agente fizer uma bagunça de tudo.
