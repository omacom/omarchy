# IA

O Omarchy inclui lançadores para os agentes de programação abaixo sem escolher um padrão para você. Execute um comando para instalar sua CLI no primeiro uso e, em seguida, autentique-se quando solicitado. Hermes é a exceção: nada é instalado para ele no primeiro uso, e escolhê-lo instala o Hermes Desktop, como _Desktop apps_ abaixo explica.

### Instalando e atualizando agentes

Exceto o Hermes, esses agentes usam a instalação preguiçosa do mise: a primeira inicialização instala a CLI, e as inicializações seguintes a reutilizam. O mise também verifica se há uma nova versão de um agente instalado no máximo uma vez a cada quatro horas, logo antes de iniciá-lo ou em segundo plano em um prompt do shell. Se essa atualização falhar ou você estiver offline, a versão instalada é executada. `omarchy update` atualiza os agentes instalados junto com o restante do Omarchy, e `mup` atualiza apenas as ferramentas gerenciadas pelo mise.

O atualizador próprio de um agente, como `claude update`, `codex update` ou um botão de atualização em um aplicativo, não atualiza a instalação gerenciada pelo mise. `codex update` falha, e `claude update` pode relatar sucesso enquanto instala uma cópia separada que o mise não rastreia. Se você preferir usar o instalador e o atualizador nativos de um agente, adicione-o a `disable_tools`; veja [Ferramentas CLI pré-instaladas](18-development-tools.md#preinstalled-cli-tools).

Para instalar todas as ferramentas preguiçosas configuradas antes de precisar delas, execute `mise install --include-lazy`. Isso inclui as outras ferramentas CLI padrão do Omarchy, além dos agentes. Veja [Ferramentas CLI pré-instaladas](18-development-tools.md#preinstalled-cli-tools) para instalar uma única ferramenta ou usar sua própria instalação.

`grok` é instalado pelo pacote primário `grok` do mise, da mesma forma que `claude` e `codex`. Execute `grok` ou escolha-o em _Setup > Defaults > Agent_. Pule o instalador `curl | bash` em x.ai. Esse caminho coloca uma segunda cópia em `~/.grok/bin`, a coloca na frente no `PATH` e sobrescreve o wrapper do Omarchy.

`dsh` abre sua interface de navegador em `127.0.0.1:3080`, com o diretório de inicialização como workspace padrão. Sua interface de navegador não aceita um prompt inicial, então `omarchy agent prompt` a abre com o prompt na área de transferência para você colar. O Omarchy o inicia com a predefinição de permissão sem aprovação do DeepSeek. O DeepSeek Harness envia logs de sessão para o DeepSeek quando você usa a API oficial de modelos dele; desative isso em _Settings > General > Upload Session Log_ na interface de navegador dele. O feedback que você envia também é enviado junto com a sessão, a menos que você o inicie com `DSH_TELEMETRY_MODE=DISABLED`.

### O agente padrão

Escolha seu agente padrão com `omarchy default agent <name>` ou em _Setup > Defaults > Agent_ no Menu do Omarchy (`Super + Space`). Se o agente ainda não estiver instalado, escolhê-lo o instala primeiro. Um Omarchy recém-instalado o convidará a fazer essa escolha com uma notificação única.

Escolher Claude também tenta configurar sua extensão de navegador para Chromium, Chrome, Brave, Brave Origin e Edge. A configuração da extensão se aplica a todos os usuários e pode pedir sua senha do sistema; cancelar ou uma instalação da extensão com falha ainda seleciona e inicia Claude. Reinicie seu navegador, ative a extensão se solicitado e entre no Claude para concluir a conexão. Execute `/chrome` no Claude para verificar a conexão. Firefox e Zen não são compatíveis com essa extensão. Se Claude já era seu padrão antes de essa configuração ser adicionada, selecione-o novamente para instalar a extensão.

Depois de escolher, `Super + Shift + Ctrl + A` inicia o agente padrão em uma janela de terminal dedicada (ou abre o seletor se você ainda não tiver escolhido). Você também pode iniciá-lo direto em uma tarefa com `omarchy agent prompt "Review this project"`. Freebuff e DeepSeek Harness não aceitam prompt inicial, então eles abrem com o prompt na área de transferência para você colar. Agentes iniciados dessa forma são executados sem supervisão em seus respectivos modos de não parar para perguntar, então esteja preparado para que eles realmente façam coisas! O MiniMax Code não tem esse modo para suas sessões interativas, então ele pede permissões normalmente. E como os agentes se recusam a lembrar da confiança no seu diretório home, inicializações a partir de `$HOME` começam em `~/Work`.

Também há atalhos de terminal: `a` executa o agente padrão inline no terminal atual, enquanto `c`, `cx` e `cy` iniciam OpenCode, Claude Code e Codex diretamente (também em seus modos de aprovação automática). Mudanças de tema também são sincronizadas com os agentes: Claude Code, Pi, OpenCode e Hermes (depois que o Omarchy o instala) acompanham quando você troca o tema do Omarchy.

### O painel de agentes

A barra superior tem um ícone de agentes. Antes de você configurar um agente, o painel dele o orienta a entrar no Claude, Codex ou Grok, e o primeiro deles se torna seu agente padrão. Depois disso, o painel coloca todas as assinaturas em uma página: cada agente e conta com seu plano, um medidor para cada um de seus limites de sessão de 5 horas e semanais com o tempo até a redefinição (passe o mouse para ver a porcentagem exata), ou o saldo pré-pago restante, sob uma linha que alterna pelo que você usou em todos eles, como tokens nesta semana e seu modelo mais usado. Em _Make something_, ele oferece prompts iniciais para um novo tema, plugin ou aplicativo que entregam a tarefa ao seu agente padrão. Os aplicativos são construídos da forma como os próprios Hype, Monologue e Omacut do Omarchy são, em C++ e Qt Quick, seguindo a skill de agente omarchy-app, e o compilador e as peças do Qt de que eles precisam já vêm instalados. Claude Code, Codex, Grok, Kimi, Cursor e sua cota do Grok Bot, GitHub Copilot, Muse, Antigravity, Kimchi e Devin são cobertos de fábrica com seus limites, e Hermes, Mistral Vibe e Qwen Code mostram suas sessões e tokens depois que você os usa. Planos de provedores e chaves que você usa por meio de pi, omp ou opencode também aparecem: OpenCode Zen e Go, o Z.ai GLM Coding Plan, Ollama Cloud, o MiniMax Token Plan e Synthetic com seus limites; Fireworks, OpenRouter e DeepSeek com seus saldos pré-pagos; e os modelos que você executa no seu próprio hardware em Local models. Cada agente é contado uma vez, sob quem o fatura, não importa por quantos harnesses você o acione.

Clique com o botão esquerdo no ícone da barra para o painel, clique com o botão direito para iniciar seu agente padrão. Os registros de uso por trás dele são regenerados a cada 15 minutos por `omarchy agent usage-update`, e o painel pode até mesclar o uso das suas outras máquinas por meio de uma pasta sincronizada. Veja o README em `$OMARCHY_PATH/shell/plugins/agents/` para as configurações completas.

### Várias assinaturas

Se você paga por mais de um plano Claude, Codex ou Grok — um Max pessoal e um de trabalho, digamos — o Omarchy pode manter todos conectados e alternar entre eles. Adicione uma assinatura com o + no painel de agentes, que o orienta ali mesmo, ou com `omarchy agent account add claude Work` (ou `codex`, ou `grok`). Ele instala a CLI se ela estiver faltando. A primeira conta de um provedor entra pelo seu navegador normal, bem onde a CLI sempre procura. Todas as seguintes entram por uma janela privada, para que a conta em que seu navegador já está conectado não seja captada por engano; entre ali como a conta que você está adicionando e feche antes qualquer janela privada que você já tenha aberta. Nunca saia da CLI para fazer isso: sair revoga o login salvo, e essa conta teria que ser adicionada novamente.

Para copiar seus logins de assinatura para outra máquina Omarchy por SSH, execute `omarchy agent account copy user@laptop`. O remetente fornece um receptor temporário quando o destino não tem um instalado, então máquinas Omarchy mais antigas podem receber contas sem uma atualização. Receptores instalados têm precedência. Isso copia todas as assinaturas Claude, Codex e Grok; adicione nomes de provedores para selecioná-las, como em `omarchy agent account copy laptop claude`. Nomes de contas e IDs de comandos correspondem à origem, incluindo contas já presentes no destino. Contas de destino não relacionadas recebem um sufixo numérico se seus nomes conflitarem, e configurações, skills, plugins e histórico de conversas permanecem locais em cada máquina.

Credenciais de destino existentes são mantidas. Uma conta de origem já conectada lá tem seu nome sincronizado sem substituir suas credenciais; outras contas são adicionadas ao lado dela. Para substituir credenciais salvas de contas correspondentes, use `omarchy agent account copy --replace laptop claude` depois de encerrar as sessões dessa conta no destino. Um destino novo também recebe a conta ativa e as preferências de alternância da origem; um destino já estabelecido mantém as suas próprias.

As credenciais viajam por SSH e são armazenadas em arquivos privados no destino, então copie apenas para máquinas em que você confia. Isso é uma cópia única, não uma sincronização contínua. Tokens de atualização do Codex podem ser rotacionados por outra máquina, deixando um login copiado precisando de renovação; logins separados continuam sendo a escolha mais confiável para uso simultâneo em várias máquinas. Veja a [orientação de autenticação de contas do Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Uma conta por provedor fica ativa, e cada nova sessão começa como ela: `cx`, `cy`, um `claude`, `codex` ou `grok` simples, qualquer coisa iniciada por meio de `omarchy agent`, e scripts ou editores que encontram a CLI no `PATH`. Alterne com `omarchy agent account use work` (e volte com `omarchy agent account use main`), ou no painel pressionando o número de uma conta e depois `Enter` (ou clicando no botão Use dela). Sessões já em execução permanecem na conta com a qual começaram. Histórico de conversas, configurações, skills e plugins são compartilhados entre contas, então `claude --continue` na mesma pasta continua de onde você parou na nova conta.

Com mais de uma conta, o painel mostra os limites de cada conta lado a lado, com a ativa marcada. Por padrão, o Omarchy avisa você quando a conta ativa passa de 95% de um limite, e clicar na notificação alterna para a conta com mais folga. Passe o mouse sobre a linha de uma conta no painel e clique no Autoswitch que aparece ao lado de Use (ou pressione `m`), ou execute `omarchy agent account mode auto`, para que ele alterne sozinho; enquanto estiver ativado, Autoswitch toma o lugar de Use, e clicar nele novamente volta a avisar. Adicione um número para mudar o limite, como em `omarchy agent account mode auto 90`. Se todas as contas estiverem acima do limite, você ficará sabendo uma vez, junto com qual conta libera primeiro. Enquanto uma conta ativa estiver dentro de 15 pontos do seu limite (80% no padrão), seus limites são verificados a cada três minutos, em vez de a cada 15.

`omarchy agent account list` mostra todas as contas e seus limites mais recentes, `omarchy agent account remove work` esquece uma, e `omarchy agent account rename primary Hey` renomeia uma (ou clique no nome de uma conta no painel). Esses comandos funcionam nas contas do seu agente padrão; para alcançar o outro provedor, nomeie-o primeiro, como em `omarchy agent account use codex side`. O login que você já tinha em `~/.claude` ou `~/.codex` é a conta _Main_ e permanece onde está. Uma conta deixada sem uso por mais de cerca de oito horas pode mostrar _Sign-in required_; clique nela para entrar nessa conta novamente direto no painel, ou inicie uma sessão nela, o que atualiza o login por conta própria. Servidores MCP que você tinha quando uma conta foi adicionada a acompanham, mas os que você adiciona depois com `claude mcp add` só alcançam a conta em que você os adicionou. Claude Desktop e ferramentas configuradas com um caminho absoluto para um binário da CLI não acompanham a alternância. Um `CLAUDE_CONFIG_DIR`, `CODEX_HOME` ou `GROK_HOME` explícito tem precedência sobre a conta selecionada.

### Diagnóstico de falhas

O Omarchy observa o systemd-coredump em busca de falhas de processos. Quando algo sofre segfault, você receberá uma notificação "Process crashed" — clique nela, e a falha é entregue ao seu agente padrão junto com a skill diagnose-crash do Omarchy, que orienta o agente a estabelecer os fatos a partir do core dump e decidir se a falha vale ser relatada upstream. Você também pode executá-la manualmente contra qualquer PID de `coredumpctl list` com `omarchy agent crash <pid>`.

A observação fica ativada por padrão. Desative-a em _Trigger > Toggle > Crash Capture_ (ou com `omarchy toggle crash-capture`) e as notificações param; `omarchy agent crash <pid>` ainda funciona manualmente.

As falhas também podem ser silenciadas um programa de cada vez, que é o que o diagnóstico oferece a você no final. `omarchy crash mute hyprland` interrompe as notificações apenas para esse programa, `omarchy crash mute hyprland off` as traz de volta, e `omarchy crash mute` sozinho lista o que você silenciou. Ele aceita o caminho do binário tão bem quanto seu nome, então `omarchy crash mute /usr/bin/hyprland` faz a mesma coisa. Coloque entre aspas um nome com espaço, como em `omarchy crash mute 'Some App'`. Todo o resto continua avisando, e o programa silenciado continua falhando — isso esconde o lembrete, não conserta nada.

### Aplicativos de desktop

O menu _Install > AI_ também traz alguns aplicativos gráficos de IA: o aplicativo de desktop do ChatGPT, o aplicativo de desktop do Claude (o beta para Linux da Anthropic, com abas Chat, Cowork e Claude Code), Grok Bot para conversar com os modelos da xAI, Hermes Desktop, OpenClaw, o aplicativo de desktop do Perplexity e T3 Code. Grok Bot é o aplicativo de chat de desktop. O agente de programação é o comando `grok`.

Hermes Desktop é o que você precisa conhecer, porque uma máquina tem um Hermes, e ele é o do aplicativo: o Hermes só é instalado pelo aplicativo, e o comando `hermes` que o agente padrão executa é o do aplicativo. Escolher Hermes como agente padrão instala a mesma coisa que a entrada _Install > AI_: o pacote, e um runtime do Hermes em `~/.hermes` configurado pelo instalador próprio do Hermes, o que leva alguns minutos na primeira vez. Esse runtime é o único Hermes que o comando `hermes` do terminal, o agente padrão e o aplicativo usam, e ele se atualiza com `hermes update` em vez de esperar por uma versão do Omarchy. Instalá-lo também entrega ao Hermes o tema do Omarchy como uma skin chamada `omarchy`, que todas as superfícies do Hermes seguem conforme você troca de temas; escolha outra nas configurações de Appearance do Hermes ou com `/skin` se preferir que ele não faça isso, e o Omarchy deixa essa escolha em paz. Remover o aplicativo em _Remove > AI_ fecha o Hermes primeiro, gateway incluído, leva esse runtime junto e mantém seus chats, memórias e as skills que o Hermes escreveu para si mesmo, a menos que você diga o contrário: ele pergunta, com padrão não, se esses dados e suas configurações de conexão também devem ir embora.

A experiência de desktop do OpenClaw é sua Control UI, que abre como um aplicativo web apoiado por seu próprio gateway local. O OpenClaw vive em `~/.openclaw` e se atualiza sozinho: use o botão "Update Gateway" da Control UI ou execute `openclaw update`, e o gateway reinicia na nova versão. O Omarchy só escolhe a versão da qual uma instalação nova parte. Remover o OpenClaw em _Remove > AI_ leva o serviço do gateway e o aplicativo junto e depois pergunta se `~/.openclaw` também deve ir embora, já que isso guarda seus chats e credenciais junto do próprio OpenClaw e dos runtimes de plugins que ele baixa; o padrão o mantém, e instalar o OpenClaw novamente o recupera.

O T3 Code é executado a partir de sua versão oficial em AppImage em `~/.local/share/t3code` em vez de um pacote, então ele se atualiza sozinho. Instalá-lo pergunta se deve começar no canal Stable ou Nightly; altere depois nas configurações do T3 Code. Suas threads e configurações vivem em `~/.t3`, e remover o T3 Code em _Remove > AI_ as leva junto.

### LLMs locais

O Omarchy recomenda duas formas de executar modelos LLM locais: LM Studio e Ollama. O LM Studio oferece uma interface gráfica para encontrar modelos de pesos abertos, instalá-los e executá-los. É uma ótima forma de começar facilmente. O Ollama oferece uma CLI para fazer isso de forma semelhante. Mas se você é novo em modelos locais, eu começaria pelo LM Studio. Você pode instalar qualquer um deles em _Install > AI_ no Menu do Omarchy.

### A Skill do Omarchy

Skills de agente ajudam a IA a usar ferramentas específicas de uma forma específica, e o Omarchy vem com uma skill padrão para personalizar o sistema. Como ajustar sua configuração do Hyprland, ajustar a barra, ou até criar um novo tema do zero. Ela é vinculada por symlink aos diretórios de skills de Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` e cada `~/.hermes/profiles/*/skills`), e ao local genérico `~/.agents/skills`, então a maioria dos harnesses a capta automaticamente.

Mas você deve tratar essa skill como experimental. Modelos diferentes a usarão com efeitos diferentes. É melhor executar primeiro em modo de planejamento, para você ter uma ideia do que o agente gostaria de mudar. E depois esteja pronto para reverter mudanças ou até invocar `omarchy reinstall configs`, se o agente fizer uma bagunça em tudo.
