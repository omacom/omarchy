# AI

Omarchy 內含下列程式編寫 agent 的啟動器，但不會幫你挑選預設值。執行某個指令即可在第一次使用時安裝其 CLI，然後依提示進行驗證。Hermes 與 OpenClaw 是例外：它們不會透過 mise 安裝任何東西，選擇其中任何一個都會設定一份專屬的、可自行更新的副本，詳見下方的 _桌面應用程式_。

### 安裝與更新 agent

除 Hermes 與 OpenClaw 外，這些 agent 都使用 mise 的延遲安裝：第一次啟動時安裝 CLI，後續啟動時則重複使用它。mise 也會在已安裝的 agent 啟動前，或在 shell 提示符下於背景中，最多每四小時檢查一次是否有新版本。如果該更新失敗或你處於離線狀態，就會執行已安裝的版本。`omarchy update` 會連同 Omarchy 的其他部分一起更新已安裝的 agent，而 `mup` 只更新由 mise 管理的工具。

agent 自己的更新程式，例如 `claude update`、`codex update`，或應用程式中的更新按鈕，不會更新由 mise 管理的安裝。`codex update` 會失敗，而 `claude update` 可能會在安裝一份 mise 未追蹤的獨立副本時，仍回報成功。如果你寧願使用 agent 原生的安裝程式與更新程式，請將它加入 `disable_tools`；請參閱 [預先安裝的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

若要在需要之前安裝所有已設定的延遲工具，請執行 `mise install --include-lazy`。這包含 Omarchy 的其他預設 CLI 工具以及這些 agent。關於安裝單一工具或使用你自己的安裝，請參閱 [預先安裝的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

`grok` 是透過 mise 的第一方 `grok` 套件安裝的，方式與 `claude` 和 `codex` 相同。請執行 `grok`，或在 agent 面板中為它加上星號。請跳過 x.ai 上 `curl | bash` 的安裝程式。那個方式會在 `~/.grok/bin` 放第二份副本，將它加到 `PATH` 的最前面，並覆寫 Omarchy 的包裝程式。

`dsh` 會在 `127.0.0.1:3080` 開啟其瀏覽器 UI，並以啟動目錄作為其預設工作區。它的瀏覽器 UI 不接受起始提示，所以 `omarchy agent prompt` 會在開啟它時把提示放在你的剪貼簿中供你貼上。Omarchy 會以 DeepSeek 的無需核准權限預設集來啟動它。當你使用其官方模型 API 時，DeepSeek Harness 會將工作階段記錄上傳到 DeepSeek；請在其瀏覽器 UI 中的 _Settings > General > Upload Session Log_ 下關閉該功能。你傳送給它的意見回饋也會連同工作階段一起上傳，除非你以 `DSH_TELEMETRY_MODE=DISABLED` 啟動它。

### 預設 agent

你可以用 agent 面板中 agent 旁邊的星號來挑選你的預設 agent，該星號在預設 agent 上會被填滿，或使用 `omarchy default agent <name>`，它也接受任何在那裡沒有一行的 harness。如果該 agent 尚未安裝，挑選它會先安裝它，而且它也會在應用程式啟動器中 Agent 旁邊，得到一個專屬的啟動器。全新的 Omarchy 會以一次性的通知邀請你設定一個，該通知會開啟 agent 面板。

選擇 Claude 也會嘗試為 Chromium、Chrome、Brave、Brave Origin 與 Edge 設定其瀏覽器擴充功能。該擴充功能的設定適用於所有使用者，且可能會要求你輸入系統密碼；取消或擴充功能安裝失敗時，仍會選擇並啟動 Claude。請重新啟動你的瀏覽器，在出現提示時啟用該擴充功能，並登入 Claude 以完成連線。請在 Claude 中執行 `/chrome` 以檢查連線。Firefox 與 Zen 不支援此擴充功能。如果在此設定加入之前 Claude 就已經是你的預設值，請再次選擇它以安裝擴充功能。

一旦你完成了選擇，`Super + Shift + Ctrl + A` 會在專屬的終端機視窗中啟動預設 agent（或者如果你還沒選擇，就會開啟選擇器）。你也可以用 `omarchy agent prompt "Review this project"` 讓它直接進入一項任務。Freebuff 與 DeepSeek Harness 不接受起始提示，所以它們會改為在開啟時把提示放在你的剪貼簿中供你貼上。以這種方式啟動的 agent 會在各自的「不要停下來詢問」模式下無人監督地執行，所以請做好它們真的會去做事的準備！MiniMax Code 的互動式工作階段沒有這種模式，所以它會照常要求權限。而且由於 agent 拒絕對你的家目錄記住信任，從 `$HOME` 啟動時會改為在 `~/Work` 中開始。

也有終端機快捷鍵：`a` 會在目前的終端機中內嵌執行預設 agent，而 `c`、`cx` 與 `cy` 則會直接啟動 OpenCode、Claude Code 與 Codex（同樣在其自動核准模式下）。主題變更也會同步到這些 agent：當你切換 Omarchy 主題時，Claude Code、Pi、OpenCode 與 Hermes（一旦 Omarchy 已安裝它）都會跟著變更。

### 你的 agent 指示

給每個 agent 的個人規則都放在 `~/.agents/AGENTS.md` 中，旁邊就是位於 `~/.agents/skills` 中的共用 skills。你可以用 agent 面板中 + 旁邊的文件圖示開啟它，或使用 `omarchy agent instructions --edit`，它也會將它連結到每個保有自己全域檔案的 harness 中：`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`~/.pi/agent/AGENTS.md`、`~/.config/opencode/AGENTS.md`、Copilot 的 `~/.copilot/copilot-instructions.md`，依此類推。Crush 與 Amp 會讀取 `~/.config/AGENTS.md` 連結，而 omp、Kimi 與 DeepSeek Harness 則直接讀取 `~/.agents/AGENTS.md`。挑選預設 agent 也會連結它。如果你已經有一個指示檔案，且尚無共用檔案，它就會成為共用檔案；否則它會以 `.bak` 的形式保留在連結旁邊。在安裝另一個 agent 後，請執行 `omarchy agent instructions` 來重新連結。

### agent 面板

頂部列有一個 agent 圖示。在你設定 agent 之前，其面板提供三種開始方式：登入 Claude、Codex、Grok、Gemini、Muse、Cursor 或 Copilot 訂閱，或在 More 下使用 OpenCode Go、MiniMax、Synthetic 或 Z.ai 程式編寫方案；使用 Fireworks、OpenCode Zen and Go、OpenRouter 以隨用隨付的方式付費，或在 More 下使用 DeepSeek 或 OpenCode 可登入的任何其他供應商，這些全都在 OpenCode 中執行；或者在有適合的模型時，在你的電腦上執行最適合它的模型。你完成的第一個就會成為你的預設 agent，而面板中的 + 之後也會提供同樣的三種方式。在那之後，該面板會把每個訂閱都放在同一頁上：每個 agent 與帳戶及其方案、其 5 小時工作階段限制與每週限制各自的儀表及距離重置的時間（將滑鼠懸停以查看確切百分比），或剩餘的預付餘額，上方則有一行會輪流顯示你在所有這些帳戶中已使用的內容，例如本週的 tokens 與你最常使用的模型。在 _做一些很酷的東西_ 下，它提供新主題、plugin、應用程式或遊戲的起始提示，將任務交給你的預設 agent。應用程式是以 Omarchy 自己的 Hype、Monologue 與 Omacut 相同的方式，使用 C++ 與 Qt Quick 並遵循 omarchy-make-app agent skill 而建構的，而它們需要的 compiler 與 Qt 元件都會隨附安裝。遊戲是位於 `~/Games/vibes` 中的單一 three.js 頁面，遵循 omarchy-make-game agent skill，而且全部都會從目前主題中的同一個 Game Vibes 啟動器開啟；它們會從網路載入 three.js，所以它們需要連線才能啟動。Claude Code、Codex、Grok、Kimi、Cursor 及其 Grok Bot 額度、GitHub Copilot、Muse、Gemini（透過 Antigravity）與 Devin 開箱即涵蓋其限制，Kimchi 涵蓋其方案、預付點數與支出預算，而 Hermes、Mistral Vibe 與 Qwen Code 則會在你使用它們後顯示其工作階段與 tokens。你透過 pi、omp 或 opencode 使用的供應商方案與金鑰也會顯示：OpenCode Zen and Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan 與 Synthetic 及其限制；OpenRouter 與 DeepSeek 及其預付餘額；Fireworks 及其過去 30 天的支出。你在自己的硬體上執行的程式編寫模型也有其專屬的行，而且它們的 tokens 也會計入總數，如 [本機模型](#local-models) 下所述。每個 agent 只會計算一次，以向它收費的一方為準，不論你是透過多少個 harness 來驅動它。

左鍵按一下列上的圖示或按 `Super + Ctrl + X` 來開啟面板，右鍵按一下來啟動你的預設 agent，中鍵按一下來重新整理。其背後的使用記錄每 15 分鐘由 `omarchy agent usage update` 重新產生一次，而且該面板甚至可以透過已同步的資料夾合併來自你其他機器的使用量。完整設定請參閱 `$OMARCHY_PATH/shell/plugins/agents/` 下的 README。

### 多個訂閱

如果你付費購買了不只一個 Claude、Codex 或 Grok 方案——例如一個個人的 Max 和一個工作用的——Omarchy 可以讓它們全部保持登入狀態並在它們之間移動。請用 agent 面板中的 + 新增訂閱，它會直接在那裡一步步引導你完成，或使用 `omarchy agent account add claude Work`（或 `codex`，或 `grok`）。同一個 + 與指令也可登入 Gemini（`gemini`）與 OpenCode（`opencode`），並在 OpenCode 中儲存 Fireworks（`fireworks`）或 OpenRouter（`openrouter`）API 金鑰；該指令同樣可登入 Copilot（`copilot`）、Cursor（`cursor`）與 Muse（`muse`）。那些都各自只保留一個登入。缺少時它會安裝 CLI。某個供應商的第一個帳戶會透過你的一般瀏覽器登入，就在 CLI 一直查看的位置。在那之後的每一個帳戶都會透過隱私視窗登入，所以你瀏覽器已登入的帳戶就不會被誤選；在那裡以你要新增的帳戶登入，並先關閉任何你已開啟的隱私視窗。絕對不要為了做這件事而登出 CLI：登出會撤銷已儲存的登入，而且該帳戶將必須重新新增。

若要透過 SSH 將你的訂閱登入複製到另一台 Omarchy 機器，請執行 `omarchy agent account copy user@laptop`。當目的地未安裝接收器時，傳送方會提供一個暫時接收器，所以較舊的 Omarchy 機器無需更新即可接收帳戶。已安裝的接收器會優先使用。這會複製所有 Claude、Codex 與 Grok 訂閱；請加入供應商名稱以選取它們，例如 `omarchy agent account copy laptop claude`。帳戶名稱與指令 ID 都與來源相符，包括目的地已存在的帳戶。若名稱衝突，不相關的目的地帳戶會收到一個數字後綴，而設定、skills、plugins 與對話記錄則會保留在每一台機器本機。

目的地現有的認證會被保留。已在那裡登入的來源帳戶，其名稱會被同步，但不會取代其認證；其他帳戶則會加在它旁邊。若要取代相符帳戶已儲存的認證，請在結束目的地上該帳戶的工作階段後，使用 `omarchy agent account copy --replace laptop claude`。全新的目的地也會取得來源的作用中帳戶與切換偏好設定；已建立的目的地則會保留自己的。

認證會透過 SSH 傳輸，並被儲存在目的地上的私人檔案中，所以請只複製到你信任的機器。這是一次性複製，不是持續同步。Codex 的重新整理 token 可能會被另一台機器輪替，導致複製的登入需要續訂；在多台機器上同時使用時，分開登入仍是最可靠的選擇。請參閱 [Codex 的帳戶驗證指南](https://developers.openai.com/codex/auth/ci-cd-auth)。

每個供應商只有一個帳戶是作用中的，而且每個新工作階段都會以它開始：`cx`、`cy`、普通的 `claude`、`codex` 或 `grok`、透過 `omarchy agent` 啟動的任何東西，以及在 `PATH` 上找到 CLI 的 script 或編輯器。請以 `omarchy agent account use work` 切換（並以 `omarchy agent account use main` 切換回來），或在面板中按某個帳戶的數字再按 `Enter`（或點擊它的星號）。正在執行的 Claude 工作階段也會切換，從它們的下一則訊息開始：每個 Claude 工作階段都在 `~/.claude` 中執行，該目錄永遠保有作用中帳戶的登入。由較舊 Omarchy 在某個帳戶專屬資料夾中啟動的 Claude 工作階段會保有該登入，直到它結束為止，所以該切換會點名那些工作階段，並在它們消失後自行完成。正在執行的 Codex 與 Grok 工作階段會停留在它們開始時所用的帳戶上。對話記錄、設定、skills 與 plugins 在帳戶之間共用，所以在同一個資料夾中的 `claude --continue` 會在新帳戶上從你上次中斷的地方繼續。

當有一個以上的帳戶時，面板會並排顯示每個帳戶的限制，並在使用中的那一個上標示填滿的星號。當作用中帳戶超過某個限制的 95% 時，Omarchy 會通知你，而點擊該通知會切換到餘裕最多的帳戶。它絕不會自行切換。請以 `omarchy agent account threshold 90` 變更該門檻。如果每個帳戶都超過該門檻，你會收到一次通知，並告知哪個帳戶會最先釋放出來。當作用中帳戶距離其門檻在 15 個百分點以內（預設情況下為 80%）時，其限制會每三分鐘而非每 15 分鐘檢查一次。

`omarchy agent account list` 會顯示每個帳戶及其最新限制，`omarchy agent account remove work` 會忘記一個帳戶，而 `omarchy agent account rename primary Hey` 會重新命名一個帳戶（或在面板中點擊某個帳戶的名稱）。這些指令作用於你預設 agent 的帳戶；若要到達另一個供應商，請先指名它，例如 `omarchy agent account use codex side`。你在 `~/.claude` 或 `~/.codex` 中已經有的登入就是 _Main_ 帳戶。Codex 的會留在原處；在另一個帳戶作用中時，Claude 的會在它自己的資料夾中等待。閒置超過約八小時的帳戶可能會顯示 _Sign-in required_；請點擊它，直接在面板中重新登入該帳戶，或切換到它並啟動一個工作階段，它就會自行重新整理登入。你以 `claude mcp add` 新增的 MCP 伺服器會到達每個 Claude 帳戶，因為它們都在 `~/.claude` 中執行；對於 Codex 與 Grok，你在新增某個帳戶時已有的伺服器會跟著到該帳戶，但之後的伺服器只會到達你新增它們的那個帳戶。Claude Desktop 保有其專屬的登入，而以指向 CLI 二進位檔案的絕對路徑設定的 Codex 或 Grok 工具不會跟著切換。明確的 `CLAUDE_CONFIG_DIR`、`CODEX_HOME` 或 `GROK_HOME` 優先於所選的帳戶。

### 當機診斷

Omarchy 會監視 systemd-coredump 是否有程序當機。一旦你挑選了預設 agent，你任何傾印出 core 的程式都會帶來一個 "Process crashed" 通知——點擊它，當機就會連同 Omarchy 的 omarchy-diagnose-crash skill 一起交給你的預設 agent，該 skill 會引導 agent 從 core dump 建立事實，並判斷該當機是否值得向上游回報。你也可以以 `coredumpctl list` 中的任何 PID 手動執行它，指令為 `omarchy agent crash <pid>`。

該監視預設開啟。請在 _Trigger > Toggle > Crash Capture Off_ 下將它關閉（或使用 `omarchy toggle crash-capture`），通知就會停止；`omarchy agent crash <pid>` 仍可用手動方式執行。

當機也可以一次靜音一個程式，這正是診斷在最後提供給你的選項。`omarchy crash mute hyprland` 只會停止該程式的通知，`omarchy crash mute hyprland off` 會讓它們恢復，而單獨使用 `omarchy crash mute` 會列出你已靜音的內容。它同樣高興地接受二進位檔案的路徑作為它的名稱，所以 `omarchy crash mute /usr/bin/hyprland` 做的事相同。請為含有空格的名稱加上引號，例如 `omarchy crash mute 'Some App'`。其他一切仍會通知，而且被靜音的程式仍會當機——這隱藏的是提醒，並不能修復任何東西。

### 桌面應用程式

_Install > AI_ 選單也提供一些圖形化 AI 應用程式：Amp Desktop、Antigravity Desktop、ChatGPT desktop app、Claude desktop app（Anthropic 的 Linux beta，包含 Chat、Cowork 與 Claude Code 分頁）、用於與 xAI 的模型聊天的 Grok Bot、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexity desktop app，以及 T3 Code。Grok Bot 是桌面聊天應用程式。程式編寫 agent 則是 `grok` 指令。

Hermes Desktop 是你需要瞭解的一個，因為一台機器只有一個 Hermes，且它屬於該應用程式：Hermes 永遠只能透過該應用程式安裝，而且預設 agent 執行的 `hermes` 指令也是該應用程式的。選擇 Hermes 作為預設 agent 時，安裝的東西與 _Install > AI_ 項目安裝的相同：該套件，以及一個由 Hermes 自己的安裝程式設定、位於 `~/.hermes` 下的 Hermes 執行階段，第一次需要幾分鐘的時間。該執行階段就是終端機 `hermes` 指令、預設 agent 與該應用程式全都使用的那一個 Hermes，而且它會以 `hermes update` 自行更新，而不等待 Omarchy 發行。安裝它也會把 Omarchy 主題作為一個名為 `omarchy` 的 skin 交給 Hermes，每個 Hermes 介面都會在你切換主題時跟著變；如果你不想如此，請在 Hermes 的 Appearance 設定下或用 `/skin` 挑選另一個，Omarchy 會讓該選擇維持不變。在 _Remove > AI_ 下移除該應用程式會先關閉 Hermes，包含閘道，並將該執行階段一併移除，而且會保留你的聊天、記憶，以及 Hermes 為自己寫入的 skills，除非你另行指示：它會詢問那些資料與你的連線設定是否也該一併移除，預設答案為否。

OpenClaw 的桌面體驗是其 Control UI，它會作為一個由其專屬本機閘道支援的 web app 開啟。OpenClaw 存在於 `~/.openclaw` 並會自行更新：請使用 Control UI 的 "Update Gateway" 按鈕，或執行 `openclaw update`，閘道就會以新版本重新啟動。Omarchy 只選擇全新安裝一開始使用的版本。OpenClaw 也可以是你的預設 agent：以 `omarchy default agent openclaw` 選擇它會在 `~/.openclaw` 中設定同一份副本，而且該 agent 會開啟連接到其閘道的 OpenClaw 終端機 UI。在 _Remove > AI_ 下移除 OpenClaw 會將閘道服務與該應用程式一併移除，然後詢問 `~/.openclaw` 是否也該移除，因為其中存放了你的聊天與認證，以及 OpenClaw 本身及其下載的 plugin 執行階段；預設會保留它，而再次安裝 OpenClaw 會把它接回來。

Herdr Desktop 是 [Herdr](https://herdr.dev) 桌面應用程式：其核心會在你關閉視窗後讓空間、標籤頁，以及終端機與程式編寫 agent 的窗格繼續執行。它不是來自某個套件，而是來自 Herdr 自己的安裝程式，所以它位於 `~/.local/share/herdr-app`，當你尚沒有一個時，會把其核心一併放在 `~/.local/bin/herdr-core`，並且兩者都會自行更新。它位於 Omarchy 隨附於 `Super + Ctrl + Return` 的 `herdr` 指令旁邊而非取代它，並承襲了該指令的直接按鍵：`Alt + Return` 與 `Alt + Shift + Return` 可將窗格向下或向右分割，`Alt + Escape` 可關閉它，`Ctrl + Alt + Arrow` 可在窗格間移動，`Alt + 1..9` 與 `Alt + Left/Right` 可挑選標籤頁，而 `Alt + Up/Down` 可在空間間移動。`Ctrl + 1..9` 可挑選空間，而 `Alt + Shift + Up/Down` 可逐步檢視 agent。`Ctrl + Space` 前綴鍵仍只用於終端機，因為該應用程式無法為一個序列按住一個普通的 Ctrl 鍵。Omarchy 會將這些寫入 `~/.config/herdr-app/keys.json`，而 `omarchy-refresh-herdr-app` 會把它們放回來。安裝它時會選取 Herdr 的 Omarchy 主題，該主題從此會跟隨你的 Omarchy 主題。Herdr 會為淺色模式保存一個主題，為深色模式保存一個主題，所以在深色及淺色的 Omarchy 主題之間切換後，請在 Herdr 的主題選取器中為另一種模式再選取一次 Omarchy。

T3 Code 是從 `~/.local/share/t3code` 中的官方 AppImage 版本執行，而非從某個套件執行，所以它會自行更新。安裝它時會詢問要從 Stable 通道開始，還是 Nightly 通道；之後請在 T3 Code 的設定中切換。你的討論串與設定存在於 `~/.t3`，而在 _Remove > AI_ 下移除 T3 Code 會將它們一併移除。

### 本機模型

在你自己的機器上，為你的程式編寫 agent 執行一個開放模型。你的提示與程式碼會留在機器上；送給模型的東西不會離開它。首先：

```bash
omarchy models use best text
```

這會為這台機器設定最適合的文字模型，也就是你的 agent 使用的種類。圖像、影片與音樂模型也各有其最適合的：`omarchy models use best image`、`video` 或 `music`。請執行 `omarchy models use best` 以查看每一種類在這台機器上的首選。

或在 agent 面板中選擇 +：在 _使用本機模型_ 下，它會列出每個適合這台機器的程式編寫模型，推薦的那個排在最前面。執行模型的 Podman 隨 Omarchy 附帶，NVIDIA 機器上的 NVIDIA container toolkit 亦然，它會將 GPU 提供給它們；若缺少其中任何一個，第一次設定會安裝它。然後，Omarchy 會為這台機器挑選推薦的模型，下載它並啟動它。請預期下載量會達數十 GB，且在模型運行時，會用掉機器的大部分記憶體：Flash Next 在其完整的 256K 上下文下約使用 100 GiB。如果其他模型佔用了它所需的記憶體，它會以已停止的狀態設定，待你停止其中一個時即可啟動。模型會在登出時停止；當你需要將記憶體用於其他用途時，請自行停止它。

`omarchy models list` 會顯示選項並說明為何有些不適合。若要設定另一個，請執行 `omarchy models use <recipe>`。如今，`qwen3.8-flash-next-gufo` 與 `qwen3.8-27b-gufo` 可用於 128 GB Strix Halo 機器；27B 大約佔 40 GiB，所以會為其他工作留出空間。在一台配有 Intel 的 Arc B390 的 64 GB 筆記型電腦上，`qwen3.6-35b-a3b-llamacpp` 大約在 30 GiB 內即可執行。新的 recipe 與推薦會透過套件隨 `omarchy update` 一同到來。

你新增的程式編寫模型會在 agent 面板中取得它自己的那一行，旁邊就是你的訂閱：播放可啟動它，暫停可停止它並釋放其記憶體，Tailscale 標記可讓它在執行時與你的 tailnet 上其他機器共用，終端機按鈕則可讓你以你的 agent 在它上面開啟。它的那一行會隨著過程顯示下載、載入或停止，並會在沒有足夠的可用記憶體啟動它時告知，或者在它以錯誤停止時連結到其記錄。多個模型可以在它們都能一同放入記憶體時同時執行。在已選取的行上按 Delete 即可將該模型從此台機器移除，包括下載在內；+ 可以再次設定它。從終端機設定的程式編寫模型會在 + 下等待，直到你將它加入，你配對的機器（`omarchy models pair <host>`）所執行的模型亦然。

每個你設定的程式編寫模型也會在應用程式啟動器中取得它自己的項目，以該模型的名稱命名並附有其製造商的標誌，正如登入 Claude、Codex 或 Grok 會加入一個一樣。它會在該模型上開啟你的 agent，而且若模型尚未執行，會先啟動它：終端機將顯示它載入，並在它就緒後交接給 agent。移除模型也會移除其項目。

並非每種模型都是為了程式編寫。圖像、影片與音樂模型會改在 Fantasi 中開啟，也就是 Omarchy 用於使用在此台機器上運行的模型製作圖片、影片和音樂的應用程式，並在那裡或以 `omarchy models` 進行管理。

模型會完全按照其設置時的方式保持運行，所以 Omarchy 更新永遠不會在你的 agent 之下重新啟動模型。當 Omarchy 為你已設定的某個模型提供更新的執行階段或更新的權重時，它的那一行會顯示更新按鈕：按下它，該模型便會在背景中再次設定，只下載已變更的部份，並以新版本重新啟動。已停止的模型會保持停止。`omarchy models update` 對每個模型從終端機做同樣的事。

從命令列，`omarchy models start <recipe>` 與 `omarchy models stop <recipe>` 做同樣的事，`omarchy models status` 會顯示每個模型，而 `omarchy agent --local-model <recipe>` 可將該模型在 pi 中開啟，無論你的預設 agent 是什麼。若要讓你的本機模型成為 agent 熱鍵、Quake console 與 _做一些東西_ 開啟的對象，請執行 `omarchy default agent local` 或為 agent 面板中一個正在執行的模型加上星號。pi 也會在自己的模型選取器中列出每個你已設定的模型，以及你已配對的機器上的模型，所以普通的 `pi` 也可以使用它們。任何相容於 OpenAI 的客戶端也可以連接：`status` 會顯示每個模型的位址（第一個是 `http://127.0.0.1:11435/v1`），recipe 名稱即該模型，而金鑰位於 `~/.config/omarchy/agent-local/key`。

`omarchy models remove <recipe>` 會刪除某個模型以及沒有其他模型使用的下載。

第三方執行階段會以其發布者標籤。Omarchy 以禁止網路存取的方式運行每個模型。

### 本機 LLM

Omarchy 推薦兩種運行本機 LLM 模型的方式：LM Studio 與 Ollama。LM Studio 提供一個 GUI 介面，供尋找開放權重模型、安裝並運行它們。這是輕鬆上手的絕佳方式。Ollama 則提供了 CLI 以類似的方式做相同的事情。但如果你剛接觸本機模型，我會從 LM Studio 開始。你可以在 Omarchy 選單的 _Install > AI_ 下安裝其中任何一個。

### Omarchy skills

Agent skills 可協助 AI 以特定的方式使用特定的工具，而 Omarchy 附帶了其中七個。omarchy skill 涵蓋如何量身打造系統，例如調整你的 Hyprland 設置或調整該列。omarchy-make-theme、omarchy-make-plugin、omarchy-make-app 與 omarchy-make-game 涵蓋製作新的東西，omarchy-contribute 涵蓋回報錯誤或將修復傳送到上游，而 omarchy-diagnose-crash 則會處理當機的 core dump。它們被符號連結到 Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` 以及每個 `~/.hermes/profiles/*/skills`），以及通用的 `~/.agents/skills` 位置的 skill 目錄中，所以大多數 harness 會自動取得它們。你自己的同名 skill 資料夾會優先使用。

但你應該將這些 skills 視為實驗性質的。不同的模型運用它們的效果各不相同。最好先在 plan mode下運行，這樣你就能知道 agent 想更改什麼。然後就準備回滾更改，甚至在 agent 把一切搞得一團糟時，執行 `omarchy reinstall configs`。
