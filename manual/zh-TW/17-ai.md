# AI

Omarchy 將 AI 程式設計 agent 視為一等公民，但不會替你選定最愛。相反地，每個主流的程式設計 agent CLI 都預先接好了延遲載入的啟動器。這些啟動器是位於 `~/.local/bin/` 中，由 [mise](https://mise.jdx.dev/) 管理的小型 stub，所以在你第一次真正執行某個 agent 之前，不會下載任何東西。Hermes 是例外：它沒有 stub，選擇它會安裝 Hermes Desktop，如下方「桌面應用程式」所述。執行以下任一指令，並在系統提示時完成驗證：

| 指令    | Agent                                                            |
|------------|------------------------------------------------------------------|
| `claude`   | [Claude Code](https://code.claude.com/docs/en/overview)          |
| `codex`    | [OpenAI Codex](https://github.com/openai/codex)                  |
| `opencode` | [OpenCode](https://opencode.ai/)                                 |
| `agy`      | [Google Antigravity CLI](https://github.com/google-antigravity/antigravity-cli) |
| `copilot`  | [GitHub Copilot CLI](https://github.com/github/copilot-cli)      |
| `crush`    | [Crush](https://github.com/charmbracelet/crush)                  |
| `grok`     | 來自 xAI 的 [Grok Build](https://x.ai/build)                        |
| `kimi`     | [Kimi Code](https://www.kimi.com/code/docs/en/)                  |
| `pi`       | [Mario Zechner 的 Pi](https://github.com/badlogic/pi-mono)        |
| `omp`      | [Oh My Pi](https://github.com/can1357/oh-my-pi)                  |
| `ori`      | [Ori](https://openrouter.ai/docs/guides/ori/harness)，OpenRouter 的 harness |
| `hermes`   | [Hermes](https://hermes-agent.nousresearch.com/)，Nous Research 的 agent  |
| `muse`     | [Muse Code](https://dev.meta.ai)，Meta 的程式設計 agent           |
| `cursor-agent` | [Cursor CLI](https://cursor.com/cli)                         |

`ori` 是其中比較特別的一個：它讓其他 harness 對著 OpenRouter 的整個模型目錄執行，所以 `ori claude`、`ori codex` 或 `ori opencode` 會以你指定的任何模型啟動那些 agent，而 `ori code` 則是 Ori 自己的 agent。

若要以相同方式包裝額外的 CLI，請執行 `omarchy-mise-install <package> [command-name]`。當你執行 `omarchy update`（或 `mup` 別名）時，這些 stub 會和 mise 管理的其他一切一起保持最新。

`grok` 是透過 mise 的第一方 `grok` 套件安裝，方式和 `claude` 與 `codex` 相同。執行 `grok`，或在 _Setup > Defaults > Agent_ 下選取它。跳過 x.ai 上的 `curl | bash` 安裝程式。那條路會在 `~/.grok/bin` 放第二份複本、把它置於 `PATH` 前面，並覆寫 Omarchy 的 wrapper。

### 預設 agent

使用 `omarchy default agent <name>` 或在 Omarchy Menu（`Super + Space`）的 _Setup > Defaults > Agent_ 下，選取你的預設 agent。如果該 agent 尚未安裝，選取它會先將它安裝好。全新的 Omarchy 會以一次性通知邀請你做出這個選擇。

選擇 Claude 也會嘗試為 Chromium、Chrome、Brave、Brave Origin 和 Edge 設定它的瀏覽器擴充功能。擴充功能設定適用於所有使用者，且可能要求你輸入系統密碼；取消或擴充功能安裝失敗，仍會選取並啟動 Claude。重新啟動瀏覽器、在提示時啟用擴充功能，並登入 Claude 以完成連線。在 Claude 中執行 `/chrome` 檢查連線。Firefox 和 Zen 不支援這個擴充功能。如果在加入此設定之前，Claude 就已經是你的預設 agent，請再次選取它以安裝擴充功能。

[Muse Code](https://dev.meta.ai) — Meta 的 `muse` — 像其他 agent 一樣使用預先安裝的 mise stub。將它選為預設 agent 會透過 mise 的 HTTP 後端安裝 Meta 的官方啟動器。該啟動器會驗證並更新適合你機器的原生執行檔。

選好之後，`Super + Shift + Ctrl + A` 會在專用的終端機視窗中啟動預設 agent（如果你還沒選，則會開啟選取器）。你也可以用 `omarchy agent prompt "Review this project"` 直接讓它開始執行一項工作。以這種方式啟動的 agent 會在各自「不停下來發問」的模式中無人值守地執行，所以請做好它們真的會動手做事的準備！而且由於 agent 拒絕記住對你家目錄的信任，從 `$HOME` 啟動時會改在 `~/Work` 中開始。

也有終端機捷徑：`a` 會在目前終端機中內嵌執行預設 agent，而 `c`、`cx` 和 `cy` 則直接啟動 OpenCode、Claude Code 和 Codex（同樣處於自動核准模式）。主題變更也會同步到 agent：當你切換 Omarchy 主題時，Claude Code、Pi、OpenCode 和 Hermes（一旦 Omarchy 已安裝它）都會跟著變。

### agent 面板

頂部列上有一個 agent 圖示。在你設定好 agent 之前，它的面板會引導你登入 Claude、Codex 或 Grok，而第一個登入的會成為你的預設 agent。在那之後，面板會將每個訂閱都放在同一頁上：每個 agent 和帳戶連同它的方案、其 5 小時 session 和每週限制各自的用量計量條及距離重設的時間（將滑鼠懸停可查看確切百分比），或剩餘的預付餘額，上方還有一行文字會輪流顯示你在所有這些 agent 中的使用情況，例如本週的 token 數量和你最常使用的模型。在 _Make something_ 底下，它提供用於新主題、外掛或應用程式的入門 prompt，將工作交給你的預設 agent。應用程式的建置方式和 Omarchy 自己的 Hype、Monologue 和 Omacut 相同，使用 C++ 和 Qt Quick，遵循 omarchy-app agent skill，而它們所需的編譯器和 Qt 元件都已預先安裝。Claude Code、Codex、Grok、Fireworks 和 Kimi 都開箱即用。Kimi 目前回報帳戶配額限制，但不提供本機 token 或 prompt 統計資料。

以滑鼠左鍵按一下列上的圖示開啟面板，以右鍵按一下啟動你的預設 agent。它背後的使用記錄會由 `omarchy agent usage-update` 每 15 分鐘重新產生一次，面板甚至可以透過同步的資料夾合併你其他機器上的使用情況。完整設定請參閱 `$OMARCHY_PATH/shell/plugins/agents/` 底下的 README。

### 多個訂閱

如果你付費訂閱了不只一個 Claude、Codex 或 Grok 方案——例如一個個人 Max 和一個工作用的——Omarchy 可以讓它們全部保持登入，並在它們之間切換。使用 agent 面板中的 + 新增訂閱，它會直接在那裡引導你完成；或使用 `omarchy agent account add claude Work`（或 `codex`，或 `grok`）。如果缺少 CLI，它會將其安裝好。某個供應商的第一個帳戶會透過你平常的瀏覽器登入，就在 CLI 一向查找的位置。之後的每個帳戶都透過隱私視窗登入，所以你瀏覽器已登入的帳戶不會被誤選；在那裡以你正在新增的帳戶身分登入，並先關閉你已經開啟的任何隱私視窗。永遠不要為了做這件事而登出 CLI：登出會撤銷已儲存的登入狀態，該帳戶就必須重新新增一次。

若要透過 SSH 將你的訂閱登入資料複製到另一台 Omarchy 機器，請執行 `omarchy agent account copy user@laptop`。當目的地沒有安裝接收器時，傳送方會提供臨時接收器，讓較舊的 Omarchy 機器無需更新也能接收帳戶。已安裝的接收器優先。這會複製所有 Claude、Codex 和 Grok 訂閱；加入供應商名稱可選取特定供應商，例如 `omarchy agent account copy laptop claude`。帳戶名稱和指令 ID 都與來源端相符，包括目的地已存在的帳戶。若名稱衝突，不相關的目的地帳戶會收到數字後綴，而設定、技能、外掛和對話歷史記錄則各自保留在本機。

目的地現有的憑證會保留。來源帳戶若已經在該處登入，它的名稱會同步，但不會取代它的憑證；其他帳戶則會新增在它旁邊。若要取代相符帳戶已儲存的憑證，請在目的地結束該帳戶的 session 後，使用 `omarchy agent account copy --replace laptop claude`。全新目的地也會得到來源端目前使用中的帳戶和切換偏好設定；已建立好的目的地則保留自己的。

憑證透過 SSH 傳輸，並儲存在目的地的私密檔案中，所以只複製到你信任的機器。這是一次性複製，不是持續同步。Codex 重新整理 token 可能被另一台機器輪替，讓複製的登入狀態需要重新更新；在多台機器上同時使用時，分別登入仍是最可靠的選擇。請參閱 [Codex 的帳戶驗證指南](https://developers.openai.com/codex/auth/ci-cd-auth)。

每個供應商有一個目前使用中的帳戶，而且每個新 session 都以它開始：`cx`、`cy`、普通的 `claude`、`codex` 或 `grok`、任何透過 `omarchy agent` 啟動的項目，以及在 `PATH` 上找到 CLI 的指令碼或編輯器。使用 `omarchy agent account use work` 切換（使用 `omarchy agent account use main` 切回），或在面板中按下某個帳戶的號碼再按 `Enter`（或按一下它的 Use 按鈕）。已經在執行的 session 會維持它們開始時的帳戶。對話歷史記錄、設定、技能和外掛會在帳戶之間共享，所以在同一個資料夾中執行 `claude --continue`，會在新帳戶上從你上次離開的地方接續。

有多個帳戶時，面板會並排顯示每個帳戶的限制，並標記目前使用中的那個。依預設，當目前使用中的帳戶超過某個限制的 95% 時，Omarchy 會通知你，按一下通知就會切換到餘裕最多的帳戶。將滑鼠懸停在面板中某個帳戶的那一行，按一下 Use 旁邊出現的 Autoswitch（或按 `m`），或執行 `omarchy agent account mode auto`，便可讓它改為自行切換；開啟後，Autoswitch 會取代 Use 的位置，再按一次就會回到通知模式。加入數字可變更門檻，例如 `omarchy agent account mode auto 90`。如果每個帳戶都超過門檻，你會收到一次通知，以及哪個帳戶最先釋放額度。當目前使用中的帳戶距離其門檻在 15 個百分點之內時（預設為 80%），它的限制會每 3 分鐘檢查一次，而不是每 15 分鐘。

`omarchy agent account list` 顯示每個帳戶及其最新限制，`omarchy agent account remove work` 忘記一個帳戶，`omarchy agent account rename primary Hey` 重新命名一個帳戶（或按一下面板中某個帳戶的名稱）。這些指令作用在你預設 agent 的帳戶上；若要觸及另一個供應商，請先命名它，例如 `omarchy agent account use codex side`。你原本在 `~/.claude` 或 `~/.codex` 中的登入就是 _Main_ 帳戶，並且會留在原處。帳戶若閒置超過約 8 小時，可能會顯示 _Sign-in required_；按一下它，在面板中直接將該帳戶重新登入，或在其中啟動 session，它便會自行重新整理登入狀態。新增帳戶時你擁有的 MCP 伺服器會跟著它一起過去，但你之後使用 `claude mcp add` 新增的，只會到達你加入它們的那個帳戶。Claude Desktop 以及以絕對路徑設定到某個 CLI 執行檔的工具，不會跟著切換。明示的 `CLAUDE_CONFIG_DIR`、`CODEX_HOME` 或 `GROK_HOME` 的優先順序高於選定的帳戶。

### 崩潰診斷

Omarchy 會監看 systemd-coredump 是否有行程崩潰。當某個程序發生 segmentation fault 時，你會收到「Process crashed」通知——按一下它，這次崩潰就會連同 Omarchy 的 diagnose-crash skill 一起交給你的預設 agent；該 skill 會引導 agent 從 core dump 建立事實，並判斷這次崩潰是否值得回報給上游。你也可以使用 `omarchy agent crash <pid>`，手動針對 `coredumpctl list` 中的任何 PID 執行它。

此監看功能預設開啟。在 _Trigger > Toggle > Crash Capture_ 下將其關閉（或使用 `omarchy toggle crash-capture`），通知便會停止；`omarchy agent crash <pid>` 仍可手動運作。

也可以逐個程式地將崩潰通知靜音，這正是診斷最後會提供你的選項。`omarchy crash mute hyprland` 只停止該程式的通知，`omarchy crash mute hyprland off` 將它們帶回，而單獨執行 `omarchy crash mute` 會列出你已靜音的項目。它接受執行檔的路徑就和接受名稱一樣開心，所以 `omarchy crash mute /usr/bin/hyprland` 效果相同。名稱中有空格時請加上引號，例如 `omarchy crash mute 'Some App'`。其他一切仍會通知，而且被靜音的程式仍然會崩潰——這只是藏起提醒，並沒有修復任何東西。

### 桌面應用程式

_Install > AI_ 選單也提供一些圖形化 AI 應用程式：ChatGPT 桌面應用程式、Claude 桌面應用程式（Anthropic 的 Linux beta，具備 Chat、Cowork 和 Claude Code 分頁）、用於與 xAI 的模型聊天的 Grok Bot、Hermes Desktop、OpenClaw，以及 Perplexity 桌面應用程式。Grok Bot 是桌面聊天應用程式。程式設計 agent 則是 `grok` 指令。

Hermes Desktop 是需要了解的那一個，因為一台機器上只有一個 Hermes，而且它是這個應用程式的：Hermes 只能透過該應用程式安裝，而預設 agent 執行的 `hermes` 指令就是該應用程式的。選擇 Hermes 作為預設 agent，安裝的東西與 _Install > AI_ 項目相同：套件，以及由 Hermes 自家安裝程式在 `~/.hermes` 底下設定好的 Hermes runtime，第一次需要幾分鐘。該 runtime 就是終端機 `hermes` 指令、預設 agent 和應用程式三者共用的那個唯一 Hermes，並使用 `hermes update` 自行更新，而不是等待 Omarchy 發布新版本。安裝它還會把 Omarchy 主題作為名為 `omarchy` 的 skin 交給 Hermes，當你切換主題，每個 Hermes 介面都會跟隨；如果你不想這樣，可在 Hermes 的 Appearance 設定下或使用 `/skin` 選其他 skin，Omarchy 會尊重該選擇並不干涉。在 _Remove > AI_ 下移除該應用程式時，會先關閉 Hermes（包括 gateway），連同該 runtime 一起移除，並保留你的聊天、記憶，以及 Hermes 為自己撰寫的技能，除非你另有指示：它會詢問這些資料和你的連線設定是否也要一併刪除，預設為否。

OpenClaw 的桌面體驗就是它的 Control UI，它會以其自己本機 gateway 為後端的 web 應用程式開啟。OpenClaw 位於 `~/.openclaw` 並會自行更新：使用 Control UI 的「Update Gateway」按鈕或執行 `openclaw update`，gateway 便會以新版本重新啟動。Omarchy 只選擇全新安裝的起始發行版。在 _Remove > AI_ 下移除 OpenClaw 時，會一併移除 gateway 服務和應用程式，然後詢問 `~/.openclaw` 是否也要刪除，因為那裡放了你的聊天和憑證，連同 OpenClaw 本身以及它下載的外掛 runtime；預設會保留它，往後再次安裝 OpenClaw 時會重新接管它。

### 本機 LLM

Omarchy 推薦兩種執行本機 LLM 模型的方式：LM Studio 和 Ollama。LM Studio 提供 GUI 介面，來尋找開放權重模型、安裝並執行它們。這是輕鬆上手的好方法。Ollama 則提供 CLI 來做類似的事。但如果你剛接觸本機模型，我會從 LM Studio 開始。你可以在 Omarchy Menu 的 _Install > AI_ 下安裝任何一個。

### Omarchy Skill

Agent skill 能幫助 AI 以特定方式使用特定工具，而 Omarchy 隨附了一項用於調整系統的預設 skill。例如微調你的 Hyprland 設定、調整列，或甚至從頭建立新主題。它會以符號連結放到 Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` 以及每個 `~/.hermes/profiles/*/skills`）的 skill 目錄，以及通用的 `~/.agents/skills` 位置，所以大部分 harness 都會自動抓到它。

但你應該將這項 skill 視為實驗性功能。不同模型使用它的效果會不一樣。最好先在 plan 模式下執行，如此你就可以瞭解 agent 想改些什麼。然後，如果 agent 把一切搞得一團亂，請準備好回退變更，甚至呼叫 `omarchy reinstall configs`。
