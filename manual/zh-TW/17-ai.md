### 安裝與更新 agent

除了 Hermes 之外，這些 agent 都使用 mise 的延遲安裝：首次啟動會安裝 CLI，後續啟動則重複使用它。mise 也會在啟動前或在 shell 提示字元處於背景檢查已安裝的 agent 是否有新版本，最多每四小時一次。如果更新失敗或你處於離線狀態，就會執行已安裝的版本。`omarchy update` 會連同 Omarchy 的其他部分一起更新已安裝的 agent，而 `mup` 則只更新由 mise 管理的工具。

agent 自己的更新程式，例如 `claude update`、`codex update` 或應用程式中的更新按鈕，不會更新由 mise 管理的安裝。`codex update` 會失敗，而 `claude update` 可能回報成功，卻安裝了 mise 沒有追蹤的另一份副本。如果你寧願使用 agent 原生的安裝程式與更新程式，請將它加入 `disable_tools`；請參閱 [預先安裝的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

要在需要之前安裝所有已設定的延遲工具，請執行 `mise install --include-lazy`。這包括 Omarchy 的其他預設 CLI 工具以及這些 agent。如需安裝單一工具或使用你自己的安裝，請參閱 [預先安裝的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

`grok` 是透過 mise 的第一方 `grok` 套件安裝，方式與 `claude` 和 `codex` 相同。執行 `grok`，或在 _Agent > Harness_ 下選擇它。不要用 x.ai 上的 `curl | bash` 安裝程式。那條路徑會在 `~/.grok/bin` 放第二份副本、把它加到 `PATH` 的前面，並覆寫 Omarchy 的包裝程式。

`dsh` 會在 `127.0.0.1:3080` 開啟其瀏覽器 UI，以啟動目錄作為預設工作區。其瀏覽器 UI 不接受起始提示，所以 `omarchy agent prompt` 會開啟它，並將提示放在你的剪貼簿中供你貼上。Omarchy 會以 DeepSeek 的無需批准權限預設集啟動它。當你使用 DeepSeek 官方模型 API 時，DeepSeek Harness 會將工作階段記錄上傳到 DeepSeek；在其瀏覽器 UI 的 _Settings > General > Upload Session Log_ 下將其關閉。你傳送給它的意見回饋也會連同工作階段一起上傳，除非你以 `DSH_TELEMETRY_MODE=DISABLED` 啟動它。

### 預設 agent

以 `omarchy default agent <name>` 或在 Omarchy 選單（`Super + Space`）的 _Agent > Harness_ 下挑選你的預設 agent。如果 agent 尚未安裝，選取它會先安裝它。全新的 Omarchy 會以一次性通知邀請你做這個選擇。

選擇 Claude 也會嘗試為 Chromium、Chrome、Brave、Brave Origin 和 Edge 設定其瀏覽器擴充功能。擴充功能設定適用於所有使用者，且可能要求輸入你的系統密碼；取消或擴充功能安裝失敗，仍然會選取並啟動 Claude。重新啟動瀏覽器、依提示啟用擴充功能，並登入 Claude 以完成連接。在 Claude 中執行 `/chrome` 檢查連接。Firefox 和 Zen 不支援此擴充功能。如果在加入此設定之前 Claude 就已經是你的預設值，請再次選取它以安裝擴充功能。

選定後，`Super + Shift + Ctrl + A` 會在專用終端機視窗中啟動預設 agent（若尚未選定，則會開啟選擇器）。你也可以用 `omarchy agent prompt "Review this project"` 直接讓它進入任務。Freebuff 和 DeepSeek Harness 不接受起始提示，所以它們會開啟並將提示放在你的剪貼簿中供你貼上。以這種方式啟動的 agent 會在各自不要停下來詢問的模式下無人看管地執行，所以要做好它們真的會動手的心理準備！MiniMax Code 的互動式工作階段沒有這種模式，所以它會照常要求權限。而且由於 agent 拒絕對你的家目錄記住信任，從 `$HOME` 啟動時會改在 `~/Work` 中開始。

終端機也有捷徑：`a` 會在目前終端機中以行內方式執行預設 agent，而 `c`、`cx` 和 `cy` 則會直接啟動 OpenCode、Claude Code 和 Codex（同樣處於自動批准模式）。主題變更也會同步到 agent：當你切換 Omarchy 主題時，Claude Code、Pi、OpenCode 和 Hermes（一旦 Omarchy 已安裝它）都會跟著變。

### 你的 agent 指示

給每個 agent 的個人規則都放在 `~/.agents/AGENTS.md`，旁邊就是放在 `~/.agents/skills` 的共用技能。在 _Agent > Instructions_ 下開啟它，它也會將其連結到每個擁有自己全域檔案的 harness：`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`~/.pi/agent/AGENTS.md`、`~/.config/opencode/AGENTS.md`、Copilot 的 `~/.copilot/copilot-instructions.md`，依此類推。Crush 和 Amp 讀取 `~/.config/AGENTS.md` 連結，而 omp、Kimi 和 DeepSeek Harness 則直接讀取 `~/.agents/AGENTS.md`。挑選預設 agent 也會連結它。如果你已經有指示檔案，且尚無共用檔案，它就會成為共用檔案；否則它會以 `.bak` 的形式保留在連結旁邊。安裝另一個 agent 後，執行 `omarchy agent instructions` 重新連結。

### agent 面板

頂部列有一個 agent 圖示。在你設定 agent 之前，其面板會引導你登入 Claude、Codex 或 Grok，而第一個會成為你的預設 agent。之後，面板會將每個訂閱放在同一頁：每個 agent 和帳號及其方案、每個 5 小時工作階段和每週限制的儀表及距離重置的時間（將滑鼠懸停可查看確切百分比），或剩餘的預付餘額，上方有一行輪流顯示你在所有這些服務中的使用量，例如本週的 token 數量和你最常使用的模型。在 _Make something_ 下，它會為新主題、外掛、應用程式或遊戲提供起始提示，並將任務交給你的預設 agent。應用程式是以 Omarchy 自己的 Hype、Monologue 和 Omacut 相同的方式打造，使用 C++ 和 Qt Quick，遵循 omarchy-make-app agent 技能，且它們需要的編譯器和 Qt 元件都已安裝。遊戲是放在 `~/Games/vibes` 中的單一 three.js 頁面，遵循 omarchy-make-game agent 技能，且全部從目前主題中的同一個 Game Vibes 啟動器開啟；它們會從網路載入 three.js，所以啟動時需要連線。Claude Code、Codex、Grok、Kimi、Cursor 及其 Grok Bot 額度、GitHub Copilot、Muse、Antigravity、Kimchi 和 Devin 皆開箱即用地涵蓋其限制，而 Hermes、Mistral Vibe 和 Qwen Code 會在你使用過後顯示其工作階段和 token。你透過 pi、omp 或 opencode 使用的供應商方案和金鑰也會顯示：OpenCode Zen 和 Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan 和 Synthetic 及其限制；Fireworks、OpenRouter 和 DeepSeek 及其預付餘額；以及你在自己硬體上執行的模型，列在 Local models 下。每個 agent 只計算一次，列在向你收費的一方名下，無論你透過多少個 harness 驅動它。

左鍵點擊列圖示開啟面板，右鍵點擊則啟動你的預設 agent。其背後的使用記錄每 15 分鐘由 `omarchy agent usage-update` 重新產生，且面板甚至可以透過同步資料夾合併來自你其他機器的使用量。完整設定請參閱 `$OMARCHY_PATH/shell/plugins/agents/` 下的 README。

### 多個訂閱

如果你付費訂閱了多個 Claude、Codex 或 Grok 方案——例如個人 Max 和工作用的一個——Omarchy 可以讓它們全部保持登入，並在之間切換。用 agent 面板中的 + 新增訂閱，它會直接在那裡引導你完成，或使用 `omarchy agent account add claude Work`（或 `codex`，或 `grok`）。如果缺少 CLI，它會安裝它。供應商的第一個帳號會透過你一般的瀏覽器登入，就在 CLI 一直查找的位置。之後的每一個帳號都會透過隱私視窗登入，所以你瀏覽器已登入的帳號不會被誤選；在那裡登入你要新增的帳號，並先關閉你已開啟的任何隱私視窗。永遠不要為此登出 CLI：登出會撤銷已儲存的登入，該帳號就必須重新新增。

要透過 SSH 將你的訂閱登入複製到另一台 Omarchy 機器，請執行 `omarchy agent account copy user@laptop`。當目的地未安裝接收器時，傳送方會提供一個臨時接收器，所以較舊的 Omarchy 機器無需更新即可接收帳號。已安裝的接收器優先。此操作會複製所有 Claude、Codex 和 Grok 訂閱；加入供應商名稱以選取它們，例如 `omarchy agent account copy laptop claude`。帳號名稱和指令 ID 與來源相符，包括目的地已存在的帳號。無關的目的地帳號若名稱衝突，會收到數字後綴，而設定、技能、外掛和對話歷史則各台機器各自保留。

目的地現有的憑證會保留。來源帳號若已在那裡登入，其名稱會同步，但不會取代其憑證；其他帳號則會新增在其旁邊。要取代相符帳號已儲存的憑證，請先在目的地結束該帳號的工作階段，再使用 `omarchy agent account copy --replace laptop claude`。全新的目的地也會取得來源的作用中帳號和切換偏好；已建立的目的地則保留自己的。

憑證透過 SSH 傳輸，並儲存在目的地上的私人檔案中，所以只複製到你信任的機器。這是一次性複製，不是持續同步。Codex 重新整理 token 可能被另一台機器輪換，導致複製過去的登入需要續期；在多台機器上同時使用時，分別登入仍然是最可靠的選擇。請參閱 [Codex 的帳號驗證指南](https://developers.openai.com/codex/auth/ci-cd-auth)。

每個供應商有一個作用中的帳號，且每個新工作階段都以它開始：`cx`、`cy`、普通的 `claude`、`codex` 或 `grok`、透過 `omarchy agent` 啟動的任何東西，以及在 `PATH` 上找到 CLI 的腳本或編輯器。用 `omarchy agent account use work` 切換（並以 `omarchy agent account use main` 切換回來），或在面板中按下帳號的數字再按 `Enter`（或點擊其 Use 按鈕）。執行中的 Claude 工作階段也會切換，從其下一則訊息開始：每個 Claude 工作階段都在 `~/.claude` 中執行，那裡永遠保存作用中帳號的登入。由舊版 Omarchy 在帳號自己的資料夾中啟動的 Claude 工作階段，會保留該登入直到它結束，所以切換會列出這些工作階段，並在它們消失後自動完成。執行中的 Codex 和 Grok 工作階段會留在它們開始時使用的帳號上。對話歷史、設定、技能和外掛在帳號之間共用，所以在同一個資料夾中的 `claude --continue` 會在新帳號上從你上次中斷的地方繼續。

有多個帳號時，面板會並排顯示每個帳號的限制，並標記作用中的那個。預設情況下，當作用中帳號超過限制的 95% 時，Omarchy 會通知你，點擊通知會切換到餘裕最多的帳號。將滑鼠懸停在面板中的帳號行上，點擊 Use 旁邊出現的 Autoswitch（或按 `m`），或執行 `omarchy agent account mode auto`，讓它自動切換；在開啟時，Autoswitch 會取代 Use 的位置，再次點擊它會恢復為通知。加入數字以變更門檻，例如 `omarchy agent account mode auto 90`。如果每個帳號都超過門檻，你會收到一次通知，並告知哪個帳號最先釋放。當作用中帳號距離其門檻在 15 個百分點內時（預設值為 80%），其限制會每三分鐘檢查一次，而不是每 15 分鐘。

`omarchy agent account list` 顯示每個帳號及其最新限制，`omarchy agent account remove work` 會忘記一個帳號，而 `omarchy agent account rename primary Hey` 會重新命名一個帳號（或點擊面板中的帳號名稱）。這些指令作用於你的預設 agent 的帳號；要存取另一個供應商，請先命名它，例如 `omarchy agent account use codex side`。你已經在 `~/.claude` 或 `~/.codex` 中擁有的登入是 _Main_ 帳號。Codex 的登入保持原位；Claude 的登入在另一個帳號作用時，會在自己的資料夾中等待。一個帳號若超過約八小時未使用，可能會顯示 _Sign-in required_；點擊它以直接在面板中再次登入該帳號，或切換到它並啟動工作階段，它會自行重新整理登入。你用 `claude mcp add` 新增的 MCP 伺服器會到達每個 Claude 帳號，因為它們都在 `~/.claude` 中執行；對於 Codex 和 Grok，在新增帳號時你已有的伺服器會隨之而來，但之後的伺服器只會到達你新增它們的那個帳號。Claude Desktop 保留自己的登入，而以 CLI 二進位檔的絕對路徑設定的 Codex 或 Grok 工具不會跟隨切換。明確的 `CLAUDE_CONFIG_DIR`、`CODEX_HOME` 或 `GROK_HOME` 優先於所選帳號。

### 當機診斷

Omarchy 會監看 systemd-coredump 以偵測處理程序當機。當某個程式發生 segfault 時，你會收到「Process crashed」通知——點擊它，當機就會連同 Omarchy 的 diagnose-crash 技能交給你的預設 agent，該技能會引導 agent 從核心傾印中建立事實，並判斷當機是否值得向 upstream 回報。你也可以用 `omarchy agent crash <pid>` 對 `coredumpctl list` 中的任何 PID 手動執行它。

監看預設開啟。在 _Trigger > Toggle > Crash Capture_ 下將其關閉（或使用 `omarchy toggle crash-capture`），通知就會停止；`omarchy agent crash <pid>` 仍然可以手動運作。

當機也可以逐個程式靜音，這是診斷在最後會提供給你的選項。`omarchy crash mute hyprland` 只停止該程式的通知，`omarchy crash mute hyprland off` 會將其恢復，而單獨使用 `omarchy crash mute` 會列出你已靜音的項目。它接受二進位檔的路徑，也接受其名稱，所以 `omarchy crash mute /usr/bin/hyprland` 效果相同。為包含空格的名稱加上引號，例如 `omarchy crash mute 'Some App'`。其他所有東西仍然會通知，且被靜音的程式仍然會當機——這只是隱藏提醒，並不能修復任何東西。

### 桌面應用程式

_Install > AI_ 選單也包含一些圖形化 AI 應用程式：Antigravity Desktop、ChatGPT 桌面應用程式、Claude 桌面應用程式（Anthropic 的 Linux beta，包含 Chat、Cowork 和 Claude Code 分頁）、用於與 xAI 模型聊天的 Grok Bot、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexity 桌面應用程式和 T3 Code。Grok Bot 是桌面聊天應用程式。程式開發 agent 是 `grok` 指令。

Hermes Desktop 是需要知道的那個，因為一台機器只有一個 Hermes，且它是該應用程式的：Hermes 只能透過該應用程式安裝，而預設 agent 執行的 `hermes` 指令是該應用程式的。選擇 Hermes 作為預設 agent，會安裝與 _Install > AI_ 項目相同的東西：該套件，以及一個由 Hermes 自己的安裝程式在 `~/.hermes` 下設定的 Hermes 執行環境，第一次需要幾分鐘。該執行環境是終端機 `hermes` 指令、預設 agent 和應用程式全部使用的一個 Hermes，且它用 `hermes update` 自行更新，而不是等待 Omarchy 發行新版本。安裝它也會將 Omarchy 主題作為名為 `omarchy` 的外皮交給 Hermes，當你切換主題時，每個 Hermes 介面都會跟著變；如果你不想這樣，在 Hermes 的 Appearance 設定下或用 `/skin` 選擇另一個，Omarchy 不會干涉該選擇。在 _Remove > AI_ 下移除該應用程式，會先關閉 Hermes（包括 gateway），並將該執行環境一起移除，且保留你的聊天、記憶和 Hermes 為自己編寫的技能，除非你另有指示：它會詢問該資料和你的連接設定是否也要一併移除，預設為否。

OpenClaw 的桌面體驗是其 Control UI，它會以其自己的本地 gateway 為後端，以網頁應用程式的形式開啟。OpenClaw 存在於 `~/.openclaw` 中並自行更新：使用 Control UI 的「Update Gateway」按鈕或執行 `openclaw update`，gateway 會在新版本上重新啟動。Omarchy 只選擇全新安裝的起始版本。在 _Remove > AI_ 下移除 OpenClaw，會將 gateway 服務和該應用程式一起移除，然後詢問是否也要移除 `~/.openclaw`，因為那裡保存你的聊天和憑證，以及 OpenClaw 本身和它下載的外掛執行環境；預設會保留它，而再次安裝 OpenClaw 會將其取回。

Herdr Desktop 是 [Herdr](https://herdr.dev) 桌面應用程式：spaces、tabs 和 panes 終端機與程式開發 agent，當你關閉視窗時，它們會在其核心中持續執行。它來自 Herdr 自己的安裝程式而非套件，所以它存放在 `~/.local/share/herdr-app`，當你尚無其核心時，會在 `~/.local/bin/herdr-core` 帶來其核心，且兩者都會自行更新。它位於 Omarchy 在 `Super + Ctrl + Return` 上提供的 `herdr` 指令旁邊，而不是取代它，且取得該指令的直接按鍵：`Alt + Return` 和 `Alt + Shift + Return` 向下或向右分割窗格，`Alt + Escape` 關閉它，`Ctrl + Alt + Arrow` 在窗格間移動，`Alt + 1..9` 和 `Alt + Left/Right` 選擇分頁，而 `Alt + Up/Down` 在 spaces 間移動。`Ctrl + 1..9` 選擇 space，而 `Alt + Shift + Up/Down` 在 agent 間逐步切換。`Ctrl + Space` 前綴按鍵仍然只屬於終端機，因為該應用程式無法為序列保留一個普通的 Ctrl 鍵。Omarchy 將這些寫入 `~/.config/herdr-app/keys.json`，且 `omarchy-refresh-herdr-app` 會將其放回。安裝它會選擇 Herdr 的 Omarchy 主題，從那時起跟隨你的 Omarchy 主題。Herdr 為淺色模式保留一個主題，為深色模式保留一個，所以在深色和淺色 Omarchy 主題之間切換後，請在 Herdr 的主題選擇器中再選擇一次 Omarchy 以用於另一個模式。

T3 Code 從其官方 AppImage 版本在 `~/.local/share/t3code` 中執行，而非從套件執行，所以它會自行更新。安裝它會詢問是否從 Stable 或 Nightly 頻道開始；之後在 T3 Code 的設定中切換。你的執行緒和設定存放在 `~/.t3` 中，在 _Remove > AI_ 下移除 T3 Code 會將它們一起移除。

### 本地模型

在你的機器上為你的程式開發 agent 執行開放模型。你的提示和程式碼留在機器上；傳送給模型的內容不會離開它。從以下指令開始：

```bash
omarchy agent local use best
```

或者，在頂部列的 agent 面板中，選擇 + 然後選擇 Local AI，當有模型適合這台機器時，它會出現。第一次，這會安裝 Podman（用來執行模型），且在 NVIDIA 機器上安裝 NVIDIA 的容器工具包（讓它們能夠使用 GPU）。然後 Omarchy 會挑選這台機器的推薦模型、下載它並啟動它。預期會有數十 GB 的下載，且模型執行期間會用掉機器的大部分記憶體：Flash Next 以其完整的 256K 上下文使用約 100 GiB。如果其他模型佔用了它需要的記憶體，它會設定為停止狀態，當你停止其中一個時即可啟動。模型在登出時停止；當你需要記憶體做其他事情時，請自行停止它。

`omarchy agent local list` 顯示選項並解釋為什麼有些不適合。要設定另一個，請執行 `omarchy agent local use <recipe>`。目前，`qwen3.8-flash-next-gufo` 和 `qwen3.8-27b-gufo` 可用於 128 GB Strix Halo 機器；27B 約佔 40 GiB，所以會留出空間給其他工作。在配備 Intel Arc B390 的 64 GB 筆記型電腦上，`qwen3.6-35b-a3b-llamacpp` 約在 30 GiB 中執行。新的 recipe 和推薦會透過套件隨 `omarchy update` 一起推出。

你設定的每個模型在 agent 面板中都有自己的一行，位於你的訂閱旁邊：播放以啟動它，暫停以停止它並釋放記憶體，而終端機按鈕則在其上開啟你的 agent。當它們能同時容納於記憶體中時，多個可以同時執行；如果有一個無法容納，Omarchy 會說明要停止哪個執行中的模型。拖曳行來重新排序它們，並在選取的行上按 Delete 以移除模型及其下載。

你設定的每個模型在應用程式啟動器中也有自己的條目，以模型名稱和其製造商的標誌顯示，就像登入 Claude、Codex 或 Grok 會新增一個一樣。它會在該模型上開啟你的 agent，若尚未執行則先啟動模型：終端機會顯示它正在載入，並在就緒後交給 agent。移除模型也會移除其條目。

模型會完全按照設定時的樣子持續執行，所以 Omarchy 更新永遠不會在你的 agent 底下重新啟動一個模型。當 Omarchy 有更新的執行環境或更新的權重可供你已設定的模型使用時，其行會顯示更新按鈕：按下它，模型會在背景重新設定，只下載變更的部分，並在新版本上重新啟動。已停止的模型會保持停止。`omarchy agent local update` 在終端機中對每個模型做同樣的事。

從指令列，`omarchy agent local start <recipe>` 和 `omarchy agent local stop <recipe>` 做同樣的事，`omarchy agent local status` 顯示每個模型，而 `omarchy agent --local` 在你最後啟動的模型上開啟你的預設 agent。pi、OpenCode 和 Qwen Code 可以使用它；使用任何其他預設值時，它會在 pi 中開啟。pi 也會在其自己的模型選擇器中列出你已設定的每個模型，以及你在已配對機器上的模型，所以普通的 `pi` 也能存取它們。任何與 OpenAI 相容的客戶端也可以連接：`status` 顯示每個模型的位址（第一個是 `http://127.0.0.1:11435/v1`），recipe 名稱就是模型，而金鑰在 `~/.config/omarchy/agent-local/key` 中。

`omarchy agent local remove <recipe>` 刪除模型以及沒有其他模型使用的下載。

第三方執行環境會標記其發行者。Omarchy 執行每個模型時不提供網路存取。

### 本地 LLM

Omarchy 推薦兩種執行本地 LLM 模型的方式：LM Studio 和 Ollama。LM Studio 提供 GUI 介面，用於尋找開放權重模型、安裝它們並執行它們。這是輕鬆入門的好方法。Ollama 提供 CLI 以類似方式完成。但如果你對本地模型不熟悉，我會從 LM Studio 開始。你可以在 Omarchy 選單的 _Install > AI_ 下安裝任一個。

### Omarchy Skill

Agent 技能幫助 AI 以特定方式使用特定工具，且 Omarchy 附帶一個用於定制系統的預設技能。例如調整你的 Hyprland 設定、調整列，或甚至從零開始建立新主題。它被符號連結到 Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` 和每個 `~/.hermes/profiles/*/skills`），以及通用的 `~/.agents/skills` 位置的技能目錄中，所以大多數 harness 會自動取得它。

但你應該將此技能視為實驗性質。不同模型使用它的效果也會不同。最好先在計畫模式中執行，這樣你能了解 agent 想要變更什麼。然後準備好回復變更，甚至在 agent 把一切搞得一團糟時，呼叫 `omarchy reinstall configs`。
