### 安裝與更新代理

除了 Hermes 和 OpenClaw 之外，這些代理都使用 mise 的懶安裝：首次啟動會安裝 CLI，後續啟動則重複使用。mise 也會在已安裝代理啟動前，或在 shell 提示字元處於背景中，最多每四小時檢查一次是否有新版本釋出。如果更新失敗或你離線，就會執行已安裝的版本。`omarchy update` 會連同 Omarchy 其餘部分一起更新已安裝的代理，而 `mup` 則只更新由 mise 管理的工具。

代理自己的更新程式，例如 `claude update`、`codex update`，或應用程式中的更新按鈕，都不會更新由 mise 管理的安裝。`codex update` 會失敗，而 `claude update` 可能回報成功，卻安裝了一個 mise 不追蹤的獨立副本。如果你比較想使用代理原生的安裝程式與更新程式，請將它加入 `disable_tools`；參見 [預先安裝的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

若要在需要之前安裝所有已設定的懶工具，請執行 `mise install --include-lazy`。這包括 Omarchy 的其他預設 CLI 工具以及這些代理。如需安裝單一工具或使用你自己的安裝，請參見 [預先安裝的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

`grok` 是透過 mise 的第一方 `grok` 套件安裝，方式與 `claude` 和 `codex` 相同。執行 `grok`，或在 _Agent > Harness_ 下選擇它。跳過 x.ai 上的 `curl | bash` 安裝程式。那條路徑會在 `~/.grok/bin` 放第二份副本、將它加到 `PATH` 最前面，並覆寫 Omarchy 的包裝程式。

`dsh` 會在 `127.0.0.1:3080` 開啟它的瀏覽器 UI，並以啟動目錄作為預設工作區。它的瀏覽器 UI 不接受起始提示，所以 `omarchy agent prompt` 會將提示放在你的剪貼簿上讓你貼上來開啟它。Omarchy 會以 DeepSeek 的無需核准權限預設集啟動它。當你使用 DeepSeek 官方模型 API 時，DeepSeek Harness 會將工作階段記錄上傳給 DeepSeek；在它的瀏覽器 UI 中，於 _Settings > General > Upload Session Log_ 下將其關閉。你傳送給它的回饋也會連同工作階段一起上傳，除非你以 `DSH_TELEMETRY_MODE=DISABLED` 啟動它。

### 預設代理

使用 `omarchy default agent <name>` 或在 Omarchy Menu（`Super + Space`）的 _Agent > Harness_ 下挑選你的預設代理。如果代理尚未安裝，選取它會先進行安裝，而且它還會在應用程式啟動器中、在 Agent 旁邊，獲得一個專屬的啟動器。全新的 Omarchy 會以一次性通知邀請你做這個選擇。

選擇 Claude 也會嘗試為 Chromium、Chrome、Brave、Brave Origin 和 Edge 設定它的瀏覽器擴充功能。擴充功能設定適用於所有使用者，而且可能會要求輸入你的系統密碼；取消或擴充功能安裝失敗，仍然會選取並啟動 Claude。重新啟動你的瀏覽器、依提示啟用擴充功能，並登入 Claude 以完成連接。在 Claude 中執行 `/chrome` 檢查連線。Firefox 和 Zen 不支援這個擴充功能。如果在加入這項設定之前 Claude 就已經是你的預設，請再選取它一次來安裝擴充功能。

一旦你選好了，`Super + Shift + Ctrl + A` 會在專屬終端機視窗中啟動預設代理（如果你還沒選，則會開啟選擇器）。你也可以用 `omarchy agent prompt "Review this project"` 讓它直接進入一項任務。Freebuff 和 DeepSeek Harness 不接受起始提示，所以它們會改將提示放在你的剪貼簿上讓你貼上。這樣啟動的代理會在各自「不要停下來問」的模式下無人值守地執行，所以要做好它們真的會動手做事的準備！MiniMax Code 的互動式工作階段沒有這種模式，所以它會照常要求權限。而且由於代理拒絕記住對你家目錄的信任，從 `$HOME` 啟動時會改在 `~/Work` 中開始。

也有終端機快速鍵：`a` 會在目前終端機中內嵌執行預設代理，而 `c`、`cx` 和 `cy` 則會直接啟動 OpenCode、Claude Code 和 Codex（同樣處於自動核准模式）。主題變更也會同步給代理：當你切換 Omarchy 主題時，Claude Code、Pi、OpenCode 和 Hermes（一旦 Omarchy 已安裝它）都會跟著變。

### 你的代理指示

給每個代理的個人規則放在 `~/.agents/AGENTS.md`，就在 `~/.agents/skills` 中的共用技能旁邊。在 _Agent > Instructions_ 下開啟它，它也會將它連結到每個維護自己全域檔案的 harness：`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`~/.pi/agent/AGENTS.md`、`~/.config/opencode/AGENTS.md`、Copilot 的 `~/.copilot/copilot-instructions.md`，依此類推。Crush 和 Amp 讀取 `~/.config/AGENTS.md` 連結，而 omp、Kimi 和 DeepSeek Harness 則直接讀取 `~/.agents/AGENTS.md`。挑選預設代理也會連結它。如果你已經有一個指示檔案，而且還沒有共用的，它就會成為共用檔案；否則它會以 `.bak` 的形式保留在連結旁邊。在安裝另一個代理後，執行 `omarchy agent instructions` 重新連結。

### 代理面板

頂部列有一個代理圖示。在你設定代理之前，它的面板會引導你登入 Claude、Codex 或 Grok，而第一個登入的會成為你的預設代理。在那之後，面板會把每個訂閱放在同一頁：每個代理和帳號及其方案、每個 5 小時工作階段和每週限額的用量計量表以及距離重置的時間（懸停可看確切百分比），或剩餘的預付餘額，全都位於一條會輪播你所有用量概況的文字下方，例如本週的 tokens 和你最常用的模型。在 _Make something cool_ 下，它會提供入門提示，用於新主題、外掛、應用程式或遊戲，並將任務交給你的預設代理。應用程式的建構方式與 Omarchy 自己的 Hype、Monologue 和 Omacut 相同，使用 C++ 和 Qt Quick，遵循 omarchy-make-app 代理技能，而且它們需要的編譯器和 Qt 元件都已安裝好。遊戲是位於 `~/Games/vibes` 中的單一 three.js 頁面，遵循 omarchy-make-game 代理技能，而且全都從一個目前主題下的 Game Vibes 啟動器開啟；它們會從網路載入 three.js，所以啟動時需要連線。Claude Code、Codex、Grok、Kimi、Cursor 及其 Grok Bot 額度、GitHub Copilot、Muse、Antigravity 和 Devin 開箱即涵蓋其限額，Kimchi 涵蓋其方案、預付點數和支出預算，而 Hermes、Mistral Vibe 和 Qwen Code 則在你使用過它們後顯示其工作階段和 tokens。你透過 pi、omp 或 opencode 使用的供應商方案和金鑰也會顯示：OpenCode Zen 和 Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan 和 Synthetic 及其限額；OpenRouter 和 DeepSeek 及其預付餘額；Fireworks 及其過去 30 天的支出。你在自己硬體上執行的模型的 tokens 也會計入總計；這些模型本身有自己的面板，詳見 [本機模型](#local-models) 下的說明。每個代理只會計數一次，歸在向你收費的一方名下，不管你透過多少個 harness 使用它。

左鍵按一下列上的圖示或按 `Super + Ctrl + X` 開啟面板，右鍵按一下啟動你的預設代理，中鍵按一下重新整理。它背後的用量記錄每 15 分鐘由 `omarchy agent usage update` 重新產生，而且面板甚至可以透過同步資料夾合併來自你其他機器的用量。完整設定請參見 `$OMARCHY_PATH/shell/plugins/agents/` 下的 README。

### 多個訂閱

如果你付費訂閱了不止一個 Claude、Codex 或 Grok 方案——例如一個個人 Max 和一個工作的——Omarchy 可以讓它們全部保持登入，並在它們之間切換。用代理面板中的 + 新增一個訂閱，它會在那裡直接引導你完成，或使用 `omarchy agent account add claude Work`（或 `codex`，或 `grok`）。如果缺少 CLI，它會安裝它。某個供應商的第一個帳號會透過你的一般瀏覽器登入，就在 CLI 一直查看的那個位置。之後的每個帳號都會透過私密視窗登入，所以你瀏覽器已經登入的帳號不會被誤選；在那裡登入你要新增的帳號，並先關閉你已經開啟的任何私密視窗。絕不要為了這樣做而登出 CLI：登出會撤銷已儲存的登入，而且那個帳號就必須重新新增。

若要透過 SSH 將你的訂閱登入複製到另一台 Omarchy 機器，請執行 `omarchy agent account copy user@laptop`。當目的地沒有安裝接收端時，傳送端會提供一個暫時接收端，所以較舊的 Omarchy 機器無需更新就能接收帳號。已安裝的接收端優先。這會複製所有 Claude、Codex 和 Grok 訂閱；加入供應商名稱來選取它們，例如 `omarchy agent account copy laptop claude`。帳號名稱和指令 ID 與來源相符，包括目的地已經存在的帳號。無關的目的地帳號如果名稱衝突，會獲得數字後綴，而且設定、技能、外掛和對話記錄都會保留在每台機器本機。

目的地現有的憑證會保留。已經在那裡登入的來源帳號，會同步其名稱而不取代其憑證；其他帳號則會加在它旁邊。若要取代相符帳號已儲存的憑證，請在目的地結束該帳號的工作階段後，使用 `omarchy agent account copy --replace laptop claude`。全新目的地還會獲得來源的啟用帳號和切換偏好；已建立好的目的地則保留它自己的。

憑證會透過 SSH 傳輸，並儲存在目的地的私密檔案中，所以只複製到你信任的機器。這是一次性複製，不是持續同步。Codex 的重新整理 tokens 可以被另一台機器輪替，導致複製過去的登入需要更新；若要在多台機器上同時使用，各自獨立登入仍然是最可靠的選擇。參見 [Codex 的帳號驗證指南](https://developers.openai.com/codex/auth/ci-cd-auth)。

每個供應商有一個啟用中的帳號，而且每個新工作階段都會以它開始：`cx`、`cy`、普通的 `claude`、`codex` 或 `grok`、透過 `omarchy agent` 啟動的任何東西，以及在 `PATH` 上找到 CLI 的指令稿或編輯器。使用 `omarchy agent account use work` 切換（並用 `omarchy agent account use main` 切回），或在面板中按一個帳號的數字然後按 `Enter`（或按一下它的 Use 按鈕）。執行中的 Claude 工作階段也會切換，從它們的下一則訊息開始：每個 Claude 工作階段都在 `~/.claude` 中執行，那裡永遠保存啟用帳號的登入。由較舊 Omarchy 於帳號自己資料夾中啟動的 Claude 工作階段，會一直保留那個登入直到結束，所以切換會列出那些工作階段，並在它們消失後自行完成。執行中的 Codex 和 Grok 工作階段會留在它們啟動時所用的帳號上。對話記錄、設定、技能和外掛在帳號間共用，所以在同一資料夾中的 `claude --continue` 會在新帳號上接續你上次離開的地方。

有不止一個帳號時，面板會並排顯示每個帳號的限額，並標示啟用中的那個。依預設，當啟用帳號超過某個限額的 95% 時，Omarchy 會通知你，而按一下通知會切換到餘裕最多的帳號。將滑鼠懸停在面板中某個帳號的那一行，按一下 Use 旁邊出現的 Autoswitch（或按 `m`），或執行 `omarchy agent account mode auto`，讓它自行切換；開啟時，Autoswitch 會取代 Use，再按一下它就會回到通知模式。加入數字來變更門檻，例如 `omarchy agent account mode auto 90`。如果每個帳號都超過門檻，你只會收到一次通知，同時會告訴你哪個帳號最先釋出額度。當啟用帳號距離其門檻在 15 個百分點以內（預設時為 80%），它的限額會每三分鐘檢查一次，而不是每 15 分鐘。

`omarchy agent account list` 會顯示每個帳號及其最新限額，`omarchy agent account remove work` 會忘記一個帳號，而 `omarchy agent account rename primary Hey` 會重新命名一個帳號（或按一下面板中的帳號名稱）。這些指令作用於你預設代理的帳號；若要觸及另一個供應商，請先點名它，例如 `omarchy agent account use codex side`。你原本在 `~/.claude` 或 `~/.codex` 中的登入就是 _Main_ 帳號。Codex 的會留在原處；Claude 的在另一個帳號啟用時，會待在它自己的資料夾中。閒置超過約八小時的帳號可能會顯示 _Sign-in required_；按一下它即可直接在面板中重新登入該帳號，或切換到它並啟動一個工作階段，它就會自行更新登入。你用 `claude mcp add` 加入的 MCP 伺服器會到達每個 Claude 帳號，因為它們全都在 `~/.claude` 中執行；對於 Codex 和 Grok，在帳號新增時你已有的伺服器會跟著到它那裡，但之後的伺服器只會到達你加入它們時的那個帳號。Claude Desktop 保留它自己的登入，而以絕對路徑指向 CLI 二進位檔所設定的 Codex 或 Grok 工具不會跟著切換。明確的 `CLAUDE_CONFIG_DIR`、`CODEX_HOME` 或 `GROK_HOME` 優先於所選帳號。

### 崩潰診斷

Omarchy 會監看 systemd-coredump 以偵測處理程序崩潰。一旦你挑選了預設代理，你的任何程式傾印核心時都會帶來「Process crashed」通知——按一下它，崩潰就會連同 Omarchy 的 omarchy-diagnose-crash 技能一併交給你的預設代理，該技能會引導代理從核心傾印中建立事實，並判定這個崩潰是否值得向上游回報。你也可以用 `omarchy agent crash <pid>` 手動對 `coredumpctl list` 中的任何 PID 執行它。

監看依預設開啟。在 _Trigger > Toggle > Crash Capture Off_ 下將其關閉（或用 `omarchy toggle crash-capture`），通知就會停止；`omarchy agent crash <pid>` 手動仍然能用。

崩潰也可以一次靜音一個程式，這正是診斷最後會提供給你的。`omarchy crash mute hyprland` 會只停止那個程式的通知，`omarchy crash mute hyprland off` 會將它們恢復，而單獨使用 `omarchy crash mute` 會列出你已靜音的項目。它同樣高興地接受二進位檔的路徑，也接受名稱，所以 `omarchy crash mute /usr/bin/hyprland` 做的事一樣。名稱中有空格時請將它引用起來，例如 `omarchy crash mute 'Some App'`。其他一切仍會通知，而且被靜音的程式仍會崩潰——這只是隱藏提醒，並不會修好任何東西。

### 桌面應用程式

_Install > AI_ 選單還載有幾個圖形化 AI 應用程式：Amp Desktop、Antigravity Desktop、ChatGPT 桌面應用程式、Claude 桌面應用程式（Anthropic 的 Linux beta 版，具有 Chat、Cowork 和 Claude Code 分頁）、Grok Bot（用於與 xAI 的模型聊天）、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexity 桌面應用程式，以及 T3 Code。Grok Bot 是桌面聊天應用程式。程式碼代理則是 `grok` 指令。

Hermes Desktop 是你該知道的那個，因為一台機器只有一個 Hermes，而且它屬於這個應用程式：Hermes 永遠只透過這個應用程式安裝，你的預設代理執行的 `hermes` 指令就是這個應用程式的。選擇 Hermes 作為預設代理，安裝的東西與 _Install > AI_ 項目安裝的相同：套件，以及一個位於 `~/.hermes` 下、由 Hermes 自己的安裝程式建立的 Hermes 執行環境，第一次需要幾分鐘時間。那個執行環境就是終端機 `hermes` 指令、預設代理和應用程式全都使用的那一個 Hermes，而且它會用 `hermes update` 自我更新，而不是等待 Omarchy 發行新版。安裝它還會將 Omarchy 主題以名為 `omarchy` 的外觀交給 Hermes，當你切換主題時，每個 Hermes 介面都會跟著變；如果你不想這樣，請在 Hermes 的 Appearance 設定下或用 `/skin` 挑選另一個，而 Omarchy 會尊重那個選擇不管。在 _Remove > AI_ 下移除這個應用程式會先關閉 Hermes，包括閘道，並將那個執行環境一併帶走，而且會保留你的聊天、記憶，以及 Hermes 為自己撰寫的技能，除非你另有指示：它會詢問，預設為否，是否連那份資料和你的連線設定也要一併移除。

OpenClaw 的桌面體驗是它的 Control UI，它會以網頁應用程式形式開啟，由它自己的本機閘道在背後支援。OpenClaw 位於 `~/.openclaw` 並自我更新：使用 Control UI 的「Update Gateway」按鈕或執行 `openclaw update`，閘道就會在新版本上重新啟動。Omarchy 只選擇全新安裝從哪個發行版開始。OpenClaw 也可以是你的預設代理：在 _Agent > Harness_ 下選擇它，會在 `~/.openclaw` 中建立同一份副本，而代理會開啟連接至其閘道的 OpenClaw 終端機 UI。在 _Remove > AI_ 下移除 OpenClaw 會將閘道服務和應用程式一併帶走，然後詢問 `~/.openclaw` 是否也要一併移除，因為那裡放著你的聊天和憑證，以及 OpenClaw 本身和它下載的外掛執行環境；預設會保留它，而再次安裝 OpenClaw 時會將它重新拾起。

Herdr Desktop 是 [Herdr](https://herdr.dev) 桌面應用程式：spaces、tabs，以及終端機和程式碼代理的 panes，當你關閉視窗時，它們會在其核心中繼續執行。它來自 Herdr 自己的安裝程式而不是套件，所以它位於 `~/.local/share/herdr-app`，當你還沒有時，會在 `~/.local/bin/herdr-core` 一併帶來它的核心，並且兩者都會自我更新。它與 Omarchy 在 `Super + Ctrl + Return` 上隨附的 `herdr` 指令並肩而坐，而不是取代它，而且會取得那個指令的直接按鍵：`Alt + Return` 和 `Alt + Shift + Return` 會向下或向右分割 pane，`Alt + Escape` 關閉它，`Ctrl + Alt + Arrow` 在 panes 之間移動，`Alt + 1..9` 和 `Alt + Left/Right` 選擇 tab，而 `Alt + Up/Down` 在 spaces 之間移動。`Ctrl + 1..9` 選擇 space，而 `Alt + Shift + Up/Down` 會逐步瀏覽代理。`Ctrl + Space` 前綴按鍵仍然只屬於終端機，因為應用程式無法為了序列保留普通的 Ctrl 按鍵。Omarchy 會將這些寫入 `~/.config/herdr-app/keys.json`，而 `omarchy-refresh-herdr-app` 會將它們放回來。安裝它會挑選 Herdr 的 Omarchy 主題，從那時起它會跟著你的 Omarchy 主題。Herdr 會為淺色模式保留一個主題、為深色模式保留一個，所以在深色與淺色 Omarchy 主題之間切換後，請在 Herdr 的主題選擇器中再挑選一次 Omarchy 用於另一個模式。

T3 Code 會從位於 `~/.local/share/t3code` 的官方 AppImage 發行版執行，而不是從套件執行，所以它會自我更新。安裝它時會詢問要從 Stable 通道還是 Nightly 通道開始；之後可在 T3 Code 的設定中切換。你的 threads 和設定位於 `~/.t3`，在 _Remove > AI_ 下移除 T3 Code 會將它們一併帶走。

### 本機模型

在你自己的機器上為你的程式碼代理執行一個開放模型。你的提示和程式碼會留在機器上；傳送給模型的東西不會離開它。從以下開始：

```bash
omarchy models use best text
```

這會為這台機器設定最佳的文字模型，也就是你的代理所用的那種。圖片、影片和音樂模型各有最佳選擇：`omarchy models use best image`、`video` 或 `music`。執行 `omarchy models use best` 可查看每種在本機上的選擇。

或者從頂部列中、代理圖示旁邊的閃耀圖示，或用 Super + Ctrl + Alt + X 開啟本機模型面板，並選擇 +。當有模型適合這台機器時，這個圖示就會出現。Podman（負責執行模型）隨 Omarchy 附帶，NVIDIA 機器上的 NVIDIA 容器工具包也一樣，它會為它們提供 GPU；如果其中任一缺失，首次設定會安裝它。接著 Omarchy 會挑選這台機器的推薦模型、下載它，並啟動它。預期會有數十 GB 的下載，而且模型執行時會使用大部分機器記憶體：Flash Next 在其完整的 256K 上下文下約使用 100 GiB。如果其他模型占著它需要的記憶體，它會設定成停止狀態，等你停止一個後就準備好啟動。模型會在登出時停止；當你需要記憶體做其他事時，請自己停止它。

`omarchy models list` 會顯示選項並解釋為何有些不適合。若要設定另一個，請執行 `omarchy models use <recipe>`。今天，`qwen3.8-flash-next-gufo` 和 `qwen3.8-27b-gufo` 適用於 128 GB Strix Halo 機器；27B 約占 40 GiB，所以它會留下空間給其他工作。在配備 Intel 的 Arc B390 的 64 GB 筆電上，`qwen3.6-35b-a3b-llamacpp` 約在 30 GiB 內執行。新的配方和推薦會隨 `omarchy update` 透過套件到來。

你設定的每個模型在本機模型面板中都有自己的一行：play 開始它，pause 停止它並釋放其記憶體，而終端機按鈕會在它上面開啟你的代理。橫跨頂部，一條列會顯示機器記憶體如何在 Omarchy 本身（系統和你的應用程式）、每個執行中的模型，以及剩餘空間之間分配。指向一個已停止的模型時，該列會顯示它是否適合，或還差多少。多個可以同時執行，當它們能一起放進記憶體時；如果有一個放不下，Omarchy 會說該停止哪個執行中的模型。依它們的標誌拖曳各行來重新排序它們，並在選取的行上按 Delete 來移除模型及其下載。

你設定的每個程式碼模型在應用程式啟動器中也都有自己的項目，位於模型名稱下並帶有其製作者的標誌，就像登入 Claude、Codex 或 Grok 會加入一個一樣。它會在該模型上開啟你的代理，而且如果模型還沒執行，會先啟動它：終端機會顯示它正在載入，並在就緒後交給代理。移除模型也會移除其項目。

不是每個模型都是為寫程式而來。圖片、影片和音樂模型會改在 Fantasi 中開啟，Fantasi 是 Omarchy 用於以在本機上執行的模型製作圖片、影片和音樂的應用程式，可以在那裡或從本機模型面板中的它們那一行挑選。

模型會完全按照它設定好的樣子繼續執行，所以 Omarchy 更新永遠不會在你的代理底下重新啟動它。當 Omarchy 有你已設定之模型的新版執行環境或新版權重時，它的那一行會顯示更新按鈕：按一下它，模型就會在背景中重新設定，只下載有變更的部分，並在新版本上重新啟動。原本停止的模型會保持停止。`omarchy models update` 會在終端機中為每個模型做相同的事。

從命令列，`omarchy models start <recipe>` 和 `omarchy models stop <recipe>` 做相同的事，`omarchy models status` 會顯示每個模型，而 `omarchy agent --local` 會在你最後啟動的模型上開啟你的預設代理。pi、OpenCode 和 Qwen Code 可以使用其中之一；配合任何其他預設，它會在 pi 中開啟，或在你沒有 pi 時在 OpenCode 中開啟。pi 也會在自己的模型選擇器中列出你設定的每個模型，以及你在已配對機器上的模型，所以普通的 `pi` 也能觸及它們。任何與 OpenAI 相容的用戶端也能連接：`status` 會顯示每個模型的位址（第一個是 `http://127.0.0.1:11435/v1`），配方名稱就是模型，而金鑰在 `~/.config/omarchy/agent-local/key` 中。

`omarchy models remove <recipe>` 會刪除模型以及沒有其他模型使用的下載。

第三方執行環境會標示其發行者。Omarchy 在沒有網路存取的情況下執行每個模型。

### 本機 LLM

Omarchy 推薦兩種執行本機 LLM 模型的方式：LM Studio 和 Ollama。LM Studio 提供圖形化介面，用於尋找開放權重模型、安裝它們，並執行它們。這是輕鬆上手的絕佳方式。Ollama 提供 CLI 以類似方式完成。不過如果你是本機模型的新手，我會從 LM Studio 開始。你可以在 Omarchy Menu 的 _Install > AI_ 下安裝任一者。

### Omarchy 技能

代理技能幫助 AI 以特定方式使用特定工具，而 Omarchy 隨附了七個。omarchy 技能涵蓋量身打造系統，例如調整你的 Hyprland 設定或調整列。omarchy-make-theme、omarchy-make-plugin、omarchy-make-app 和 omarchy-make-game 涵蓋製作新東西，omarchy-contribute 涵蓋回報錯誤或將修正傳送到上游，而 omarchy-diagnose-crash 則處理崩潰的核心傾印。它們會以符號連結進入 Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` 和每個 `~/.hermes/profiles/*/skills`）的技能目錄，以及通用的 `~/.agents/skills` 位置，所以大多數 harness 會自動拾取它們。你自己的同名技能資料夾優先。

但你應該將這些技能視為實驗性質。不同的模型會以不同程度的效果使用它。最好先在計畫模式下執行，這樣你就會了解代理想要變更什麼。然後，如果代理把一切搞得一團亂，要做好回復變更、甚至援用 `omarchy reinstall configs` 的準備。
