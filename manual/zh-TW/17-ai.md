### 安裝與更新 Agent

除了 Hermes 之外，這些 Agent 都使用 mise 的延遲安裝：第一次啟動時安裝 CLI，之後的啟動則重複使用它。mise 也會檢查已安裝的 Agent 是否有新版本，最多每四小時一次，就在它啟動之前，或在 shell 提示字元處於背景檢查。如果該更新失敗，或你處於離線狀態，就會執行已安裝的版本。`omarchy update` 會連同 Omarchy 的其他部分一起更新已安裝的 Agent，而 `mup` 只更新由 mise 管理的工具。

Agent 自己的更新程式，例如 `claude update`、`codex update`，或應用程式中的更新按鈕，不會更新由 mise 管理的安裝。`codex update` 會失敗，而 `claude update` 可能回報成功，卻安裝了 mise 沒有追蹤的另一份副本。如果你比較想使用 Agent 原生的安裝程式與更新程式，請將它加入 `disable_tools`；請參閱 [預先安裝的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

若要在需要之前安裝所有已設定的延遲工具，請執行 `mise install --include-lazy`。這包括 Omarchy 的其他預設 CLI 工具，以及這些 Agent。如需安裝單一工具或使用你自己的安裝，請參閱 [預先安裝的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

`grok` 是透過 mise 的第一方 `grok` 套件安裝的，方式與 `claude` 和 `codex` 相同。執行 `grok`，或在 _Setup > Defaults > Agent_ 下選擇它。不要使用 x.ai 上的 `curl | bash` 安裝程式。那條路徑會在 `~/.grok/bin` 放第二份副本、把它加到 `PATH` 最前面，並覆寫 Omarchy 的包裝程式。

`dsh` 會在 `127.0.0.1:3080` 開啟其瀏覽器 UI，並以啟動目錄作為預設工作區。它的瀏覽器 UI 不接受起始提示詞，所以 `omarchy agent prompt` 開啟它時，會將提示詞放在你的剪貼簿中讓你貼上。Omarchy 會以 DeepSeek 的免核准權限預設集啟動它。當你使用 DeepSeek Harness 的官方模型 API 時，它會將工作階段記錄上傳到 DeepSeek；在其瀏覽器 UI 的 _Settings > General > Upload Session Log_ 下將其關閉。你傳送給它的意見回饋也會連同工作階段一起上傳，除非你以 `DSH_TELEMETRY_MODE=DISABLED` 啟動它。

### 預設 Agent

使用 `omarchy default agent <name>`，或在 Omarchy Menu（`Super + Space`）的 _Setup > Defaults > Agent_ 下，選擇你的預設 Agent。如果該 Agent 尚未安裝，選擇它會先將它安裝。全新安裝的 Omarchy 會以一次性的通知邀請你做這個選擇。

選擇 Claude 也會嘗試為 Chromium、Chrome、Brave、Brave Origin 和 Edge 設定其瀏覽器擴充功能。擴充功能設定適用於所有使用者，且可能要求輸入你的系統密碼；取消或擴充功能安裝失敗，仍然會選取並啟動 Claude。重新啟動你的瀏覽器，依提示啟用擴充功能，並登入 Claude 以完成連接。在 Claude 中執行 `/chrome` 以檢查連線。Firefox 和 Zen 不支援這個擴充功能。如果在加入這項設定之前，Claude 就已經是你的預設值，請再次選取它以安裝擴充功能。

一旦你選定，`Super + Shift + Ctrl + A` 會在專用的終端機視窗中啟動預設 Agent（或者，如果你尚未選定，則會開啟選擇器）。你也可以用 `omarchy agent prompt "Review this project"` 讓它直接進入一項任務。Freebuff 和 DeepSeek Harness 不接受起始提示詞，所以它們開啟時會改將提示詞放在你的剪貼簿中讓你貼上。以這種方式啟動的 Agent 會在各自的「不要停下來詢問」模式中無人看管地執行，所以要準備好它們真的會去做事！MiniMax Code 的互動式工作階段沒有這種模式，所以它會照常要求權限。而且，由於 Agent 拒絕記住對你家目錄的信任，從 `$HOME` 啟動時會改在 `~/Work` 中開始。

也有終端機快捷方式：`a` 會在目前的終端機中內嵌執行預設 Agent，而 `c`、`cx` 和 `cy` 則直接啟動 OpenCode、Claude Code 和 Codex（同樣是在它們的自動核准模式中）。主題變更也會同步到這些 Agent：當你切換 Omarchy 主題時，Claude Code、Pi、OpenCode 和 Hermes（一旦 Omarchy 已安裝它）都會跟著變更。

### Agent 面板

頂部列有一個 Agent 圖示。在你設定 Agent 之前，它的面板會引導你登入 Claude、Codex 或 Grok，而第一個登入的會成為你的預設 Agent。之後，該面板會將每個訂閱放在同一頁上：每個 Agent 和帳戶及其方案、每個 5 小時工作階段和每週額度的量表，以及距離重置的時間（將滑鼠懸停以查看確切百分比），或剩餘的預付餘額，位在一行輪替顯示你全部使用情況的文字下方，例如本週的 token 數和你最常使用的模型。在 _Make something_ 下，它提供用於新主題、外掛程式或應用程式的入門提示詞，並將任務交給你的預設 Agent。應用程式的建置方式與 Omarchy 自己的 Hype、Monologue 和 Omacut 相同，使用 C++ 和 Qt Quick，遵循 omarchy-app Agent skill，而且它們所需的編譯器和 Qt 元件都已隨附安裝。Claude Code、Codex、Grok、Kimi、Cursor 及其 Grok Bot 額度、GitHub Copilot、Muse、Antigravity、Kimchi 和 Devin 都開箱即用地涵蓋其額度，而 Hermes、Mistral Vibe 和 Qwen Code 則會在你使用過它們之後顯示其工作階段和 token。你透過 pi、omp 或 opencode 使用的供應商方案和金鑰也會顯示：OpenCode Zen 和 Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan 和 Synthetic 及其額度；Fireworks、OpenRouter 和 DeepSeek 及其預付餘額；以及你在自己硬體上執行的模型，位於 Local models 下。每個 Agent 只計算一次，歸在向它收費的一方名下，不論你透過多少個 harness 驅動它。

左鍵按一下列上的圖示開啟面板，右鍵按一下則啟動你的預設 Agent。其背後的使用記錄每 15 分鐘由 `omarchy agent usage-update` 重新產生，而且該面板甚至可以透過同步資料夾合併來自你其他機器的使用情況。如需完整設定，請參閱 `$OMARCHY_PATH/shell/plugins/agents/` 下的 README。

### 多個訂閱

如果你付費訂閱了一個以上的 Claude、Codex 或 Grok 方案，例如一個個人的 Max 和一個工作的，Omarchy 可以讓它們全部保持登入，並在它們之間移動。在 Agent 面板中使用 + 新增訂閱，它會就在那裡引導你完成，或使用 `omarchy agent account add claude Work`（或 `codex`，或 `grok`）。如果缺少 CLI，它會將其安裝。某個供應商的第一個帳戶會透過你平常的瀏覽器登入，就在 CLI 一直查看的位置。之後的每一個都會透過私人視窗登入，所以你瀏覽器已經登入的帳戶不會被誤選；在那裡以你要新增的帳戶登入，並先關閉你已經開啟的任何私人視窗。絕不要為此登出 CLI：登出會撤銷已儲存的登入狀態，而該帳戶將必須重新新增。

若要透過 SSH 將你的訂閱登入資訊複製到另一台 Omarchy 機器，請執行 `omarchy agent account copy user@laptop`。當目的地尚未安裝接收器時，傳送方會提供一個臨時接收器，所以較舊的 Omarchy 機器無需更新也能接收帳戶。已安裝的接收器優先。此指令會複製所有 Claude、Codex 和 Grok 訂閱；加入供應商名稱以選取它們，例如 `omarchy agent account copy laptop claude`。帳戶名稱和指令 ID 與來源相符，包括目的地已存在的帳戶。無關的目的地帳戶如果名稱衝突，將收到數字後綴，而設定、skill、外掛程式和對話記錄則各自保留在本機。

現有的目的地憑證會被保留。已經在那裡登入的來源帳戶，其名稱會被同步，但不會取代其憑證；其他帳戶則會新增在其旁邊。若要取代相符帳戶已儲存的憑證，請在結束該帳戶在目的地上的工作階段之後，使用 `omarchy agent account copy --replace laptop claude`。全新的目的地也會取得來源的使用中帳戶和切換偏好；已建立的目的地則保留自己的。

憑證會透過 SSH 傳送，並儲存在目的地上的私人檔案中，所以只能複製到你信任的機器。這是一次性的複製，不是持續同步。Codex 的刷新 token 可能會被另一台機器輪替，使複製的登入狀態需要續期；對於同時在多台機器上使用，個別登入仍是最可靠的選擇。請參閱 [Codex 的帳戶驗證指南](https://developers.openai.com/codex/auth/ci-cd-auth)。

每個供應商有一個使用中的帳戶，而且每個新工作階段都以它開始：`cx`、`cy`、普通的 `claude`、`codex` 或 `grok`、任何透過 `omarchy agent` 啟動的東西，以及在 `PATH` 上找到 CLI 的指令碼或編輯器。使用 `omarchy agent account use work` 切換（並以 `omarchy agent account use main` 切換回來），或在面板中按下帳戶的數字然後按 `Enter`（或按一下其 Use 按鈕）。已經在執行中的工作階段會停留在它們開始時所用的帳戶。對話記錄、設定、skill 和外掛程式會在帳戶之間共享，所以在同一個資料夾中的 `claude --continue` 會在新帳戶上接續你上次離開的地方。

當有多個帳戶時，面板會並排顯示每個帳戶的額度，並標記使用中的那個。依預設，當使用中帳戶超過額度的 95% 時，Omarchy 會通知你，而按一下通知會切換到餘裕最多的帳戶。將滑鼠懸停在面板中的帳戶行上，並按一下出現在 Use 旁邊的 Autoswitch（或按 `m`），或執行 `omarchy agent account mode auto`，讓它改為自行切換；當它開啟時，Autoswitch 會取代 Use 的位置，再按一下它就會回到通知模式。加入一個數字以變更門檻，例如 `omarchy agent account mode auto 90`。如果每個帳戶都超過門檻，你會收到一次通知，同時告知哪個帳戶最先釋出。當使用中帳戶距離其門檻在 15 個百分點以內時（預設為 80%），其額度會每三分鐘檢查一次，而不是每 15 分鐘一次。

`omarchy agent account list` 會顯示每個帳戶及其最新額度，`omarchy agent account remove work` 會忘記一個帳戶，而 `omarchy agent account rename primary Hey` 會重新命名一個帳戶（或在面板中按一下帳戶名稱）。這些指令作用於你的預設 Agent 的帳戶；若要到達另一個供應商，請先命名它，例如 `omarchy agent account use codex side`。你已經在 `~/.claude` 或 `~/.codex` 中擁有的登入是 _Main_ 帳戶，並且會留在原處。閒置超過約八小時的帳戶可能會顯示 _Sign-in required_；按一下它即可直接在面板中重新登入該帳戶，或在其中啟動一個工作階段，它會自行刷新登入狀態。當帳戶被新增時你擁有的 MCP 伺服器會隨之而來，但你之後以 `claude mcp add` 新增的伺服器只會到達你新增它們的那個帳戶。Claude Desktop 和以 CLI 二進位檔的絕對路徑設定的工具不會跟隨切換。明確的 `CLAUDE_CONFIG_DIR`、`CODEX_HOME` 或 `GROK_HOME` 優先於所選帳戶。

### 當機診斷

Omarchy 會監看 systemd-coredump 是否有處理程序當機。當某個東西發生 segfault 時，你會收到一個 "Process crashed" 通知，按一下它，當機就會連同 Omarchy 的 diagnose-crash skill 一起交給你的預設 Agent，該 skill 會引導 Agent 從核心傾印中建立事實，並判斷該當機是否值得向 upstream 回報。你也可以使用 `omarchy agent crash <pid>`，以手動方式對 `coredumpctl list` 中的任何 PID 執行它。

監看依預設開啟。在 _Trigger > Toggle > Crash Capture_ 下將其關閉（或使用 `omarchy toggle crash-capture`），通知就會停止；`omarchy agent crash <pid>` 仍可用手動方式運作。

也可以一次靜音一個程式的當機，這正是診斷在最後提供的。`omarchy crash mute hyprland` 只停止該程式的通知，`omarchy crash mute hyprland off` 會將它們帶回來，而單獨的 `omarchy crash mute` 會列出你已靜音的內容。它同樣樂意接受二進位檔的路徑和名稱，所以 `omarchy crash mute /usr/bin/hyprland` 會做同樣的事。將含有空格的名稱加上引號，例如 `omarchy crash mute 'Some App'`。其他一切仍會通知，而被靜音的程式仍會當機，這只是隱藏提醒，不會修復任何東西。

### 桌面應用程式

_Install > AI_ 選單還包含一些圖形化 AI 應用程式：ChatGPT 桌面應用程式、Claude 桌面應用程式（Anthropic 的 Linux beta，含有 Chat、Cowork 和 Claude Code 分頁）、用於與 xAI 模型聊天的 Grok Bot、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexity 桌面應用程式和 T3 Code。Grok Bot 是桌面聊天應用程式。程式碼 Agent 則是 `grok` 指令。

Hermes Desktop 是你需要了解的那一個，因為一台機器只有一個 Hermes，而且它是該應用程式的：Hermes 只能透過該應用程式安裝，而且預設 Agent 執行的 `hermes` 指令就是該應用程式的。選擇 Hermes 作為預設 Agent 會安裝與 _Install > AI_ 項目相同的東西：該套件，以及一個由 Hermes 自己的安裝程式在 `~/.hermes` 下設定的 Hermes runtime，第一次需要幾分鐘。終端機的 `hermes` 指令、預設 Agent 和該應用程式全都使用那個 runtime，而且它會以 `hermes update` 自行更新，而不是等待 Omarchy 發行。那項安裝也會將 Omarchy 主題作為名為 `omarchy` 的 skin 交給 Hermes，當你切換主題時，每個 Hermes 介面都會跟隨；如果你不想如此，請在 Hermes 的 Appearance 設定下或使用 `/skin` 選擇另一個，而 Omarchy 會讓那個選擇保持不變。在 _Remove > AI_ 下移除該應用程式會先關閉 Hermes，包括 gateway，並將該 runtime 一併移除，而且除非你另有指示，它會保留你的聊天、記憶，以及 Hermes 為自己編寫的 skill：它會詢問，預設為否，該資料和你的連接設定是否也應該一併刪除。

OpenClaw 的桌面體驗是其 Control UI，它會以由其自身本機 gateway 支援的網頁應用程式形式開啟。OpenClaw 存在於 `~/.openclaw` 並自行更新：使用 Control UI 的 "Update Gateway" 按鈕，或執行 `openclaw update`，gateway 就會在新版本上重新啟動。Omarchy 只選擇全新安裝從哪個版本開始。在 _Remove > AI_ 下移除 OpenClaw 會將 gateway 服務和該應用程式一併移除，然後詢問 `~/.openclaw` 是否也應該刪除，因為那裡存放著你的聊天和憑證，以及 OpenClaw 本身和它下載的外掛程式 runtime；預設會保留它，而再次安裝 OpenClaw 會將它接回來。

Herdr Desktop 是 [Herdr](https://herdr.dev) 桌面應用程式：由終端機和程式碼 Agent 組成的 spaces、tabs 和 panes，當你關閉視窗時，它們會繼續在其 core 中執行。它來自 Herdr 自己的安裝程式而不是套件，所以它存在於 `~/.local/share/herdr-app`，當你還沒有 Herdr 時，它會在 `~/.local/bin/herdr-core` 一併帶來其 core，而且兩者都會自行更新。它與 Omarchy 在 `Super + Ctrl + Return` 上提供的 `herdr` 指令並存，而不是取代它。安裝它會選取 Herdr 的 Omarchy 主題，從此它會跟隨你的 Omarchy 主題。Herdr 為淺色模式保留一個主題，為深色模式保留一個，所以在深色和淺色的 Omarchy 主題之間切換之後，請在 Herdr 的主題選擇器中再為另一種模式選取一次 Omarchy。

T3 Code 從其官方 AppImage 發行版本在 `~/.local/share/t3code` 中執行，而不是從套件，所以它會自行更新。安裝它時會詢問要從 Stable 還是 Nightly 通道開始；之後可在 T3 Code 的設定中切換。你的討論串和設定存放在 `~/.t3`，在 _Remove > AI_ 下移除 T3 Code 會將它們一併移除。

### 本機模型

在你自己的機器上為你的程式碼 Agent 執行開放模型。你的提示詞和程式碼會留在機器上；傳送給模型的任何東西都不會離開它。以下列指令開始：

```bash
omarchy agent local use best
```

或者，在頂部列的 Agent 面板中，選擇 +，然後選擇 Local AI，當有模型適合這台機器時它就會出現。第一次，這會安裝 Podman，它負責執行模型，而在 NVIDIA 機器上，還會安裝 NVIDIA 的容器工具包，它讓模型能使用 GPU。然後 Omarchy 會為這台機器挑選建議的模型、下載它並啟動它。預期會有數十 GB 的下載量，而且當模型執行時，機器的大部分記憶體都會被使用：Flash Next 在其完整的 256K 上下文下使用約 100 GiB。如果其他模型佔用了它需要的記憶體，它會被設定為已停止，準備好在你停止一個模型之後啟動。該模型會在登出時停止；當你需要將記憶體用於其他用途時，請自行停止它。

`omarchy agent local list` 會顯示選項，並解釋為什麼有些不適合。若要設定另一個，請執行 `omarchy agent local use <recipe>`。今天，`qwen3.8-flash-next-gufo` 和 `qwen3.8-27b-gufo` 可用於 128 GB 的 Strix Halo 機器；27B 佔用約 40 GiB，所以它會為其他工作留下空間。新的 recipe 和建議會透透過套件隨 `omarchy update` 一起送達。

你設定的每個模型在 Agent 面板中都會有自己的一行，位於你的訂閱旁邊：按播放以啟動它，按暫停以停止它並釋放其記憶體，以及終端機按鈕以在它上面開啟你的 Agent。當它們能同時裝進記憶體時，多個可以同時執行；如果有一個裝不下，Omarchy 會說明要停止哪個執行中的模型。拖曳各行以重新排序它們，並在選取的行上按 Delete 以移除模型及其下載。

從指令行來看，`omarchy agent local start <recipe>` 和 `omarchy agent local stop <recipe>` 做同樣的事，`omarchy agent local status` 顯示每個模型，而 `omarchy agent --local` 會在你最後啟動的模型上開啟你的預設 Agent（如果你的預設 Agent 無法使用本機模型，則為 pi）。任何與 OpenAI 相容的用戶端也可以連接：`status` 會顯示每個模型的位址（第一個是 `http://127.0.0.1:11435/v1`），recipe 名稱就是模型，而金鑰位於 `~/.config/omarchy/agent-local/key`。

`omarchy agent local remove <recipe>` 會刪除一個模型，以及沒有其他模型使用的下載。

第三方 runtime 會標示其發行者。Omarchy 執行每個模型時都不提供網路存取。

### 本機 LLM

Omarchy 建議兩種執行本機 LLM 模型的方式：LM Studio 和 Ollama。LM Studio 提供一個 GUI 介面，用於尋找開放權重的模型、安裝它們並執行它們。這是輕鬆入門的好方法。Ollama 提供一個 CLI 以類似方式完成。 但如果你是本機模型的新手，我會從 LM Studio 開始。你可以在 Omarchy Menu 的 _Install > AI_ 下安裝其中任何一個。

### Omarchy Skill

Agent skill 幫助 AI 以特定方式使用特定工具，而 Omarchy 隨附一個用於調整系統的預設 skill。就像調整你的 Hyprland 設定、調整列，甚至從頭建立一個新主題。它被 symlink 到 Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` 和每個 `~/.hermes/profiles/*/skills`），以及通用的 `~/.agents/skills` 位置的 skill 目錄中，所以大多數 harness 都會自動取得它。

但你應該將這個 skill 視為實驗性的。不同的模型會以不同的效果使用它。最好先在 plan 模式中執行，這樣你能了解 Agent 想要更改什麼。然後準備好回復變更，甚至在 Agent 把一切搞得一團糟時，執行 `omarchy reinstall configs`。
