# AI

Omarchy 內含下列程式設計 agent 的啟動器，但不會替你選定預設的 agent。執行指令即可在第一次使用時安裝其 CLI，之後依提示進行驗證。Hermes 和 OpenClaw 是例外：它們不會透過 mise 安裝任何東西，選擇任一者都會設置其專屬的自我更新副本，如下文的 _桌面應用程式_ 所述。

### 安裝與更新 agent

除了 Hermes 和 OpenClaw 之外，這些 agent 都使用 mise 的延遲安裝：第一次啟動時安裝 CLI，之後的啟動則重複使用它。mise 也會最多每四小時檢查一次已安裝的 agent 是否有新版本，就在它啟動之前檢查，或在 shell 提示字元處於背景檢查。如果該更新失敗或你離線，就會運行已安裝的版本。`omarchy update` 會連同 Omarchy 其餘部分一起更新已安裝的 agent，而 `mup` 只更新由 mise 管理的工具。

agent 自己的更新程式，例如 `claude update`、`codex update`，或應用程式中的更新按鈕，並不會更新由 mise 管理的安裝。`codex update` 會失敗，而 `claude update` 可能回報成功，卻同時安裝了 mise 沒有追蹤的另一份副本。如果你寧願使用 agent 原生的安裝程式和更新程式，請將它加入 `disable_tools`；請參閱[預先安裝的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

若要在需要之前安裝所有已設定的延遲工具，請執行 `mise install --include-lazy`。這除了包含 agent 之外，也包含 Omarchy 的其他預設 CLI 工具。如需安裝單一工具或使用你自己的安裝，請參閱[預先安裝的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

`grok` 透過 mise 的第一方 `grok` 套件安裝，方式和 `claude` 與 `codex` 相同。執行 `grok`，或在 agent 面板中為它標星。跳過 x.ai 上的 `curl | bash` 安裝程式。那條路徑會把第二份副本放在 `~/.grok/bin`，把它加到 `PATH` 的最前面，並覆寫 Omarchy 的 wrapper。

`dsh` 會在 `127.0.0.1:3080` 開啟其瀏覽器 UI，並以啟動目錄作為其預設工作區。它的瀏覽器 UI 不接受起始提示，所以 `omarchy agent prompt` 開啟它時，會將提示放到你的剪貼簿上讓你貼上。Omarchy 會以 DeepSeek 的無需核准權限預設集啟動它。當你使用其官方模型 API 時，DeepSeek Harness 會將工作階段記錄上傳到 DeepSeek；在其瀏覽器 UI 的 _Settings > General > Upload Session Log_ 下將其關閉。你傳送給它的意見回饋也會連同工作階段一起上傳，除非你以 `DSH_TELEMETRY_MODE=DISABLED` 啟動它。

### 預設 agent

在 agent 面板中，以 agent 旁邊的星號來挑選你的預設 agent，預設 agent 上的星號會填滿，或使用 `omarchy default agent <name>`，該指令也接受在那裡沒有列出的一行資料的任何 harness。如果該 agent 還沒有安裝，挑選它會先將其安裝，而且它還會在應用程式啟動器中，Agent 旁邊，獲得自己的啟動器。全新的 Omarchy 會以一次性通知邀請你設置一個，通知開啟後會開啟 agent 面板。

選擇 Claude 也會嘗試為 Chromium、Chrome、Brave、Brave Origin 以及 Edge 設置其瀏覽器擴充功能。擴充功能的設置適用於所有使用者，而且可能要求你輸入系統密碼；取消或擴充功能安裝失敗，仍然會選定並啟動 Claude。重新啟動你的瀏覽器，若有提示則啟用擴充功能，並登入 Claude 以完成連接。 在 Claude 中執行 `/chrome` 以檢查連接。Firefox 和 Zen 不支援此擴充功能。如果在新增此設置之前 Claude 就已經是你的預設，請再次選取它以安裝擴充功能。

選好之後，`Super + Shift + Ctrl + A` 會在專用的終端機視窗中啟動預設 agent（或如果你還沒有選擇，則開啟挑選器）。你也可以用 `omarchy agent prompt "Review this project"` 直接讓它進入一項任務。Freebuff 和 DeepSeek Harness 不接受起始提示，所以它們開啟時會改為將提示放到你的剪貼簿上讓你貼上。以此方式啟動的 agent 會在各自的不要停下來詢問模式中無人看管地運行，所以要準備好它們真的會動手做事！MiniMax Code 的互動工作階段沒有這種模式，所以它會照常要求權限。而且由於 agent 拒絕記住對你家目錄的信任，所以從 `$HOME` 啟動時會改在 `~/Work` 中開始。

也有終端機快捷鍵：`a` 會在目前終端機中內嵌運行預設 agent，而 `c`、`cx`、`cy` 和 `ca` 則直接啟動 OpenCode、Claude Code、Codex 和 Antigravity（同樣以其自動核准模式運行）。主題變化也會同步到 agent：當你切換 Omarchy 主題時，Claude Code、Pi、OpenCode 和 Hermes（一旦 Omarchy 已安裝它）都會跟著變更。

### 你的 agent 指示

每個 agent 的個人規則都放在 `~/.agents/AGENTS.md` 中，位於 `~/.agents/skills` 的共用 skills 旁邊。用 agent 面板中 + 旁邊的文件圖示開啟它，或使用 `omarchy agent instructions --edit` 開啟，它也會將其連結到每個保有自己全域檔案的 harness 中：`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`~/.pi/agent/AGENTS.md`、`~/.config/opencode/AGENTS.md`、Copilot 的 `~/.copilot/copilot-instructions.md`，等。Crush 和 Amp 讀取 `~/.config/AGENTS.md` 連結，而 omp、Kimi 和 DeepSeek Harness 直接讀取 `~/.agents/AGENTS.md`。挑選預設 agent 也會連結它。如果你已經有指示檔案且還沒有共用的，則那份檔案會成為共用的檔案；否則它會以 `.bak` 的形式保留在連結旁邊。在安裝另一個 agent 之後執行 `omarchy agent instructions` 以重新連結。

### agent 面板

頂部欄有一個 agent 圖示。在你設置 agent 之前，其面板提供三種開始的方式：登入 Claude、Codex、Grok、Gemini、Muse、Cursor 或 Copilot 訂閱，或在 More 下登入 OpenCode Go、MiniMax、Synthetic 或 Z.ai 程式設計方案；以隨用隨付方式使用 Fireworks、OpenCode Zen 和 Go、OpenRouter，或在 More 下使用 DeepSeek 或 OpenCode 可登入的任何其他供應商，這些都在 OpenCode 中運行；或在有適合的模型時為你的電腦運行最佳模型。你完成的第一個會成為你的預設 agent，而面板中的 + 之後也會提供同樣的三種方式。在那之後，面板會把每個訂閱都放在同一頁上：每個 agent 和帳戶連同其方案、各自的 5 小時工作階段和每週限額的量表以及重設前的剩餘時間（將滑鼠懸停以查看確切百分比）、或剩餘的預付餘額，全部列在一行輪替顯示你在所有帳戶上的使用情況之下，例如本週的 token 以及你最常使用的模型。在 _Make something cool_ 之下，它提供新主題、plugin、應用程式或遊戲的入門提示，並將任務交給你的預設 agent。應用程式的建立方式就和 Omarchy 自己的 Hype、Monologue 和 Omacut 一樣，使用 C++ 和 Qt Quick，並遵循 omarchy-make-app agent skill，而且它們需要的編譯器和 Qt 元件會隨之安裝。遊戲是位於 `~/Games/vibes` 中的單一 three.js 頁面，遵循 omarchy-make-game agent skill，而且都是從目前主題中的一個 Game Vibes 啟動器開啟；它們從網路載入 three.js，所以啟動時需要連線。Claude Code、Codex、Grok、Kimi、Cursor 及其 Grok Bot 額度、GitHub Copilot、Muse、Gemini（透過 Antigravity）和 Devin 一開箱就涵蓋其限額，Kimchi 涵蓋其方案、預付點數和支出預算，而 Hermes、Mistral Vibe 和 Qwen Code 會在你使用過它們之後顯示其工作階段和 token。透過 pi、omp 或 opencode 使用的供應商方案和金鑰也會出現：OpenCode Zen 和 Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan，以及 Synthetic 連同其限額；OpenRouter 和 DeepSeek 連同其預付餘額；Fireworks 連同其過去 30 天的支出。你在自己的硬體上運行的程式設計模型會獲得自己的列，而且它們的 token 也會算進總數，如[本機模型](#local-models)所述。每個 agent 只計算一次，歸在向你計費的一方之下，無論你透過多少個 harness 驅動它。

左鍵按一下欄圖示或按 `Super + Ctrl + X` 可開啟面板，右鍵按一下可啟動你的預設 agent，中鍵按一下可重新整理。其背後的用量記錄每 15 分鐘由 `omarchy agent usage update` 重新產生，而且面板甚至可以透過已同步的資料夾合併來自你其他機器的用量。完整的設定請參閱 `$OMARCHY_PATH/shell/plugins/agents/` 之下的 README。

### 多個訂閱

如果你付費購買了不只一個 Claude、Codex 或 Grok 方案——例如一個個人的 Max 方案和一個工作用的——Omarchy 可以讓它們全部保持登入狀態，並在它們之間移動。用 agent 面板中的 + 新增訂閱，它會就在那裡帶著你完成，或使用 `omarchy agent account add claude Work`（或 `codex`，或 `grok`）。同樣的 + 和指令也能登入 Gemini（`gemini`）和 OpenCode（`opencode`），並將 Fireworks（`fireworks`）或 OpenRouter（`openrouter`）API 金鑰儲存在 OpenCode 中；該指令同樣能登入 Copilot（`copilot`）、Cursor（`cursor`）和 Muse（`muse`）。那些每個都只保留一個登入。 如果 CLI 不存在，它會進行安裝。某個供應商的第一個帳戶會透過你一般的瀏覽器登入，就在 CLI 一直查看的那個地方。之後的每個帳戶都會透過私人視窗登入，所以你瀏覽器已經登入的帳戶就不會被誤挑中；在那裡以你要新增的帳戶登入，並先關閉你已經開啟的任何私人視窗。永遠不要為了這樣做而登出 CLI：登出會撤銷已儲存的登入，而且該帳戶將必須再次新增。

若要透過 SSH 將你的訂閱登入複製到另一台 Omarchy 機器上，請執行 `omarchy agent account copy user@laptop`。當目的地沒有安裝接收器時，寄送方會提供一個暫時的接收器，所以較舊的 Omarchy 機器不需要更新就能接收帳戶。已安裝的接收器優先。這會複製所有 Claude、Codex 和 Grok 訂閱；加入供應商名稱來挑選它們，例如 `omarchy agent account copy laptop claude`。帳戶名稱和指令 ID 會與來源相符，包括目的地已經存在的帳戶。無關的目的地帳戶如果名稱衝突，會獲得一個數字尾碼，而設定、skills、plugins 和對話記錄則會保留在本機。

現有的目的地憑證會保留下來。已經在那裡登入的來源帳戶會同步其名稱而不會取代其憑證；其他帳戶則會加在它的旁邊。若要取代相符帳戶已儲存的憑證，請在結束目的地該帳戶的工作階段之後使用 `omarchy agent account copy --replace laptop claude`。全新的目的地還會獲得來源作用中的帳戶和切換偏好設定；已經建立的目的地則保留自己的設定。

憑證透過 SSH 傳輸，並儲存在目的地的私人檔案中，所以只複製到你信任的機器上。這是一次性複製，不是持續同步。Codex 重新整理 token 可能會被另一台機器輪替，導致複製的登入需要更新；分開的登入仍然是在數台機器上同時使用的最可靠選擇。請參閱 [Codex 的帳戶驗證指南](https://developers.openai.com/codex/auth/ci-cd-auth)。

每個供應商只有一個帳戶是作用中的，而且每個新的工作階段都會以該帳戶開始：`cx`、`cy`、一個普通的 `claude`、`codex` 或 `grok`、透過 `omarchy agent` 啟動的任何東西，以及在 `PATH` 上找到 CLI 的腳本或編輯器。用 `omarchy agent account use work` 切換（並用 `omarchy agent account use main` 切換回來），或在面板中按一個帳戶的號碼接著按 `Enter`（或按一下它的星號）。正在運行的 Claude 工作階段也會切換，從其下一則訊息開始：每個 Claude 工作階段都在 `~/.claude` 中運行，其中永遠保存著作用中帳戶的登入。一個由舊版 Omarchy 在某個帳戶自己的資料夾中啟動的 Claude 工作階段，會一直保有該登入直到它結束，所以切換時會點名那些工作階段，並在它們消失之後自行完成。正在運行的 Codex 和 Grok 工作階段會留在它們開始時使用的帳戶上。對話記錄、設定、skills 和 plugins 在所有帳戶間共用，所以在同個資料夾中執行 `claude --continue` 會在新帳戶上從你上次離開的地方接續。

當有多個帳戶時，面板會並排顯示每個帳戶的限額，正在使用的上面有一個填滿的星號。當作用中帳戶超過限額的 95% 時，Omarchy 會通知你，按一下通知就會切換到餘裕最大的帳戶。它永遠不會自己切換。用 `omarchy agent account threshold 90` 變更門檻。如果每個帳戶都超過門檻，你只會收到一次通知，同時告訴你哪個帳戶會最先釋放。當作用中帳戶在距離其門檻 15 個百分點以內（預設為 80%）時，其限額會每三分鐘檢查一次，而不是每 15 分鐘。

`omarchy agent account list` 顯示每個帳戶及其最新限額，`omarchy agent account remove work` 會忘記一個帳戶，而 `omarchy agent account rename primary Hey` 會為一個帳戶重新命名（或在面板中按一下一個帳戶的名稱）。這些指令作用於你的預設 agent 的帳戶；若要到達其他供應商，請先寫它的名稱，例如 `omarchy agent account use codex side`。你已經在 `~/.claude` 或 `~/.codex` 中持有的登入，就是 _Main_ 帳戶。Codex 的會留在它原來的位置；Claude 的會等待在自己的資料夾中，而同時有另一個作用中的帳戶。一個帳戶超過大約八小時未使用，可能會顯示 _Sign-in required_；按一下它就能直接在面板中再次登入該帳戶，或切換至它並開始一個工作階段，那會自行重新整理登入。你用 `claude mcp add` 新增的 MCP 伺服器會到達每個 Claude 帳戶，因為它們都在 `~/.claude` 中運行；對於 Codex 和 Grok，你在某個帳戶新增時已有的伺服器會隨之一起到達，但之後的伺服器只會到達你新增它們的那個帳戶。Claude Desktop 擁有自己的登入，而設定為使用 CLI 二進位檔絕對路徑的 Codex 或 Grok 工具不會跟隨切換。一個明確的 `CLAUDE_CONFIG_DIR`、`CODEX_HOME` 或 `GROK_HOME` 優先於所選的帳戶。

### 當機診斷

Omarchy 會監看 systemd-coredump 的進程當機事件。一旦你選了預設 agent，你任何傾印核心的程式都會帶來一則「Process crashed」通知——按一下它，而當機連同 Omarchy 的 omarchy-diagnose-crash skill 一起交給你的預設 agent，該 skill 帶著 agent 從核心傾印中建立事實並決定此當機是否值得向 upstream 回報。你也可以使用 `omarchy agent crash <pid>` 針對來自 `coredumpctl list` 的任何 PID 手動執行它。

監看預設開啟。在 _Trigger > Toggle > Crash Capture Off_ 下將其關閉（或使用 `omarchy toggle crash-capture`），通知即停止；`omarchy agent crash <pid>` 仍可用手動執行。

當機也可以逐個程式地靜音，這正是診斷最後提供的你能做的事。`omarchy crash mute hyprland` 只停止該程式的通知，`omarchy crash mute hyprland off` 則讓它們回來，而單獨的 `omarchy crash mute` 則列出你已經靜音的內容。它接受二進位檔的路徑的程度和接受相同，它的名稱一樣高興，所以 `omarchy crash mute /usr/bin/hyprland` 會做同樣的事情。為含有空格的名稱加上引號，例如 `omarchy crash mute 'Some App'`。其他一切仍會通知，而且靜音的程式仍然會當機——這只是隱藏提醒，不會修正任何東西。

### 桌面應用程式

_Install > AI_ 選單也包含一些圖形化 AI 應用程式：Amp Desktop、Antigravity Desktop、ChatGPT 桌面應用程式、Claude 桌面應用程式（Anthropic 的 Linux beta，含有 Chat、Cowork 和 Claude Code 分頁）、用於與 xAI 模型聊天的 Grok Bot、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexity 桌面應用程式，以及 T3 Code。Grok Bot 是桌面聊天應用程式。程式設計 agent 是 `grok` 指令。

Hermes Desktop 是應該要了解的，因為一台機器只有一個 Hermes，且它是這個應用程式的：Hermes 永遠只能透過該應用程式安裝，而預設 agent 運行的 `hermes` 指令就是該應用程式的。選擇 Hermes 作為預設 agent 所安裝的與 _Install > AI_ 項目安裝的相同：這個套件，以及 Hermes 自己的安裝程式在 `~/.hermes` 之下設置的 Hermes 執行環境，第一次需要幾分鐘的時間。那個執行環境就是終端機 `hermes` 指令、預設 agent 以及應用程式全部都在使用的唯一的 Hermes，而且它會用 `hermes update` 自我更新，而不是等待 Omarchy 發行版本。安裝它也會將 Omarchy 主題作為一個名為 `omarchy` 的 skin 交給 Hermes，每個 Hermes 的介面都會在你切換主題時跟隨它；如果你不想要這樣，在 Hermes 的 Appearance 設定下或用 `/skin` 挑選另一個，Omarchy 會保留那個選擇。在 _Remove > AI_ 下移除該應用程式，會先關閉 Hermes（包括閘道），並一併帶走該執行環境，而且除非你另有說明，否則會保留你的聊天、記憶和 Hermes 為自己編寫的 skills：它會詢問該資料和你的連線設定是否也該刪除，預設為否。

OpenClaw 的桌面體驗是其 Control UI，它會以自己的本機閘道支援的 web 應用程式形式開啟。OpenClaw 存在於 `~/.openclaw` 中，並會自我更新：用 Control UI 的「Update Gateway」按鈕或執行 `openclaw update`，閘道就會在新版本上重新啟動。Omarchy 只選擇全新安裝初始的版本。OpenClaw 也可以是你的預設 agent：用 `omarchy default agent openclaw` 選擇它，就會在 `~/.openclaw` 中設置同一份副本，而該 agent 會開啟 OpenClaw 的終端機 UI 並連接到其閘道。在 _Remove > AI_ 下移除 OpenClaw 會帶走閘道服務和應用程式，然後詢問 `~/.openclaw` 是否也應該刪除，因為它和 OpenClaw 本身與其下載的 plugin 執行環境一起保存著你的聊天和憑證；將保留它為預設，再次安裝 OpenClaw 就會將它接回來。

Herdr Desktop 是 [Herdr](https://herdr.dev) 桌面應用程式：當你關閉視窗時，在其核心中繼續運行的終端機和程式設計 agent 的空間、分頁和窗格。它來自 Herdr 自己的安裝程式而不是套件，所以它位於 `~/.local/share/herdr-app`，當你還沒有 Herdr core 時，它會在 `~/.local/bin/herdr-core` 中帶來它，並會同時自我更新。它與 Omarchy 在 `Super + Ctrl + Return` 上隨附的 `herdr` 指令並列，而非取代它，並獲得了該指令的直接按鍵：`Alt + Return` 和 `Alt + Shift + Return` 向下或向右分割窗格，`Alt + Escape` 關閉它，`Ctrl + Alt + Arrow` 在窗格之間移動，`Alt + 1..9` 和 `Alt + Left/Right` 挑選分頁，而 `Alt + Up/Down` 則在空間之間移動。`Ctrl + 1..9` 挑選一個空間，而 `Alt + Shift + Up/Down` 會逐步瀏覽 agent。`Ctrl + Space` 前綴鍵仍只用於終端機，因為該應用程式無法為一個序列按住一個普通的 Ctrl 鍵。Omarchy 會把這些寫到 `~/.config/herdr-app/keys.json`，而且 `omarchy-refresh-herdr-app` 會將它們寫回。安裝它會挑選 Herdr 的 Omarchy 主題，從此它會跟隨你的 Omarchy 主題。Herdr 為亮色模式保留一個主題而暗色模式保留另一個，所以在切換暗色與亮色 Omarchy 主題後，在 Herdr 的主題挑選器中再次為另一個模式選擇 Omarchy。

T3 Code 會從 `~/.local/share/t3code` 中的其官方 AppImage 版本運行，而不是從套件，所以它會自我更新。安裝它時會詢問是否從 Stable 還是 Nightly 頻道開始；往後在 T3 Code 的設定中切換。你的 discussions 和設定位於 `~/.t3`，而在 _Remove > AI_ 下按移除 T3 Code 會隨之將它們刪除。

### 本機模型

在你自己的機器上為你的程式設計 agent 運行開放模型。你的提示和程式碼保留在機器上；傳給模型的東西都不會離開它。以下列指令開始：

```bash
omarchy models use best text
```

那會為這台機器設置最佳的文字模型，是你的 agent 使用的種類。圖像、影片和音樂模型各有其最佳：`omarchy models use best image`、`video` 或 `music`。執行 `omarchy models use best` 可查看每種種類在此機器的選擇。

或選 agent 面板中的 +：在 _Use a local model_ 之下，它列出適合此機器的每一個程式設計模型，推薦的那個放在第一位。運行這些模型的 Podman 隨 Omarchy 附帶，NVIDIA 機器上的 NVIDIA 容器工具包也是，這給予了它們 GPU；如果其中任一缺失，則第一次設置時會安裝它。Omarchy 隨後會挑選此機器的推薦模型，下載它，並開始它。預期下載數十 GB，而且在模型運行時，會用掉大部分的機器記憶體：Flash Next 使用其完整 256K 背景文本時約使用 100 GiB。 如果其他模型佔用了它所需的記憶體，它會被設置為停止狀態，隨時便於在你停止一個之後開始使用。模型在登出時停止；當你需要將記憶體用在其他事情時，自己停止它。

`omarchy models list` 顯示選項並解釋為何一些不適合。要設置另一個，請執行 `omarchy models use <recipe>`。今日，`qwen3.8-flash-next-gufo` 和 `qwen3.8-27b-gufo` 可用於 128 GB Strix Halo 機器；27B 約需要 40 GiB，所以它為其他工作保留空間。在一部帶有 Intel 的 Arc B390 的 64 GB 筆電上，`qwen3.6-35b-a3b-llamacpp` 運行約需 30 GiB。新的配方和推薦會透過套件隨 `omarchy update` 而來。

你新增的程式設計模型會在 agent 面板中獲得自己的一行，緊鄰你的訂閱：播放按鈕啟動它，暫停按鈕停止它並釋放其記憶體，Tailscale 標誌在運行期間分享它給 tailnet 上的其他機器，以及終端機按鈕在該模型上開啟你的 agent。它的那行會隨著進展顯示下載、載入或停止，而且在沒有足夠的可用記憶體啟動它時會表明，或在它因錯誤而停止時連結到其記錄。幾個模型可以在記憶體裝得下時同時運行。按 Delete 於選定的一行上，將模型從此機器上移除，連同下載的內容一起；+ 可以再次設置它。從終端機設置的程式設計模型，在 + 之下等待直到你新增它，而你曾配對過的機器（`omarchy models pair <host>`）所運行的模型也是如此。

每個你設置的程式設計模型也會在應用程式啟動器中，獲得其專屬項目以模型名稱並以其製造商標誌顯示，就像登入 Claude、Codex 或 Grok 便新增一個。它會在該模型上開啟你的 agent，而且如果它未運行，會先啟動模型：終端機會顯示它正在載入，並在其啟動後移交 agent。移除模型也會移除其項目。

並非每種模型都是為了寫程式。圖像、影片和音樂模型會改在 Fantasi 中開啟，Omarchy 中用於以本機運行的模型製作圖片、影片和音樂的應用程式，並在那裡或用 `omarchy models` 進行管理。

模型運行完全照著被設置的它一樣，所以 Omarchy 更新永遠不會在你的 agent 之下重新啟動它。當 Omarchy 擁有你已設置的新版執行環境或新權重時，它的那一行會顯示更新按鈕：按它模型會在背景中重新設置，只下載變動過的並且在新版本上重新啟動。被停止的模型仍會保持停止。`omarchy models update` 會對來自終端機的每個模型做同樣事情。

從指令列來看，`omarchy models start <recipe>` 和 `omarchy models stop <recipe>` 作用相同，`omarchy models status` 顯示每個模型，而 `omarchy agent --local-model <recipe>` 會在 pi 中開啟那個模型，不論你的預設 agent 是什麼。若想讓本地模型成為 agent 快捷鍵、Quake 主控台以及 _Make something_ 開啟的對象，執行 `omarchy default agent local` 或在 agent 面板中為運行中的模型標星。pi 還會在其自身的模型挑選器中列出你所設置的每個模型，以及那在已配對的機器上設置的，所以普通的 `pi` 也能使用它們。任何與 OpenAI 相容的用戶端也能連接：`status` 顯示每個模型的位址（第一個是 `http://127.0.0.1:11435/v1`），配方名稱就是模型，而金鑰位於 `~/.config/omarchy/agent-local/key` 中。

`omarchy models remove <recipe>` 會刪去一個模型和沒有其他任何模型用到的下載內容。

第三方執行環境以其出版者標示。Omarchy 運行每個模型時不具備網路存取。

### 本機 LLM

Omarchy 建議兩種運行本機 LLM 模型的方式：LM Studio 和 Ollama。LM Studio 提供 GUI 介面用於尋找開放權重的模型、安裝它們並運行它們。這是一個容易開始的絕佳方式。Ollama 提供一個 CLI 以類似方式完成。但如果你是新手本機模型，我會建議從 LM Studio 開始。你可以在 Omarchy 選單的 _Install > AI_ 下安裝任一者。

### The Omarchy skills

Agent skills 幫助 AI 以特定方式使用特定工具，且 Omarchy 隨附了其中七個。omarchy skill 涵蓋了量身訂製系統，像調整你的 Hyprland 設置或更動工具列。omarchy-make-theme、omarchy-make-plugin、omarchy-make-app 及 omarchy-make-game 涵蓋了新事物的製作，omarchy-contribute 涵蓋了報告錯誤或將修復傳送到 upstream，而 omarchy-diagnose-crash 則深入分析當機的核心傾印。它們被符號連結到 Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` 以及每個 `~/.hermes/profiles/*/skills`）的 skill 目錄中，以及通用的 `~/.agents/skills` 位置，所以大多數 harness 會自動採用它們。你自有的同名 skill 資料夾擁有優先權。

但你應該將這些 skills 視為實驗性質的。不同的模型使用它的成效不同。最好先在 plan 模式下運行，這樣你就能對 agent 想要更動的東西心中有個概念。並準備好要 rollback 變更，或者甚至呼叫 `omarchy reinstall configs`，如果 agent 把一切都弄得一團糟。
