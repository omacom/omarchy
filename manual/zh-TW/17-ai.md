# AI

Omarchy 為下列程式設計 agent 內含啟動器，但不會幫你挑選預設的 agent。執行指令即可在首次使用時安裝其 CLI，然後在出現提示時進行驗證。Hermes 是例外：首次使用時不會為它安裝任何東西，選擇它則會安裝 Hermes Desktop，如下方 _桌面應用程式_ 一節所述。

### 安裝與更新 agent

Hermes 除外，這些 agent 都使用 mise 的延遲安裝：第一次啟動時安裝 CLI，後續啟動則重複使用它。mise 也會檢查已安裝的 agent 是否有新版本，最多每四小時一次，就在它啟動之前，或在 shell 提示字元下於背景檢查。如果該次更新失敗或你處於離線狀態，就會執行已安裝的版本。`omarchy update` 會連同 Omarchy 的其他部分一起更新已安裝的 agent，而 `mup` 只更新由 mise 管理的工具。

agent 自己的更新程式，例如 `claude update`、`codex update`，或應用程式中的更新按鈕，都不會更新由 mise 管理的安裝。`codex update` 會失敗，而 `claude update` 可能回報成功，卻安裝了一個 mise 沒有追蹤的獨立副本。如果你寧願使用 agent 原生的安裝程式與更新程式，請將它加入 `disable_tools`；請參閱 [預先安裝的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

若要在需要之前安裝所有已設定的延遲工具，請執行 `mise install --include-lazy`。這包含 Omarchy 的其他預設 CLI 工具以及這些 agent。關於安裝單一工具或使用你自己的安裝，請參閱 [預先安裝的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

`grok` 是透過 mise 的第一方 `grok` 套件安裝，與 `claude` 和 `codex` 的方式相同。執行 `grok`，或在 _Agent > Harness_ 下選擇它。跳過 x.ai 上的 `curl | bash` 安裝程式。那條路徑會在 `~/.grok/bin` 放第二份副本、把它加到 `PATH` 最前面，並覆寫 Omarchy 的 wrapper。

`dsh` 會在 `127.0.0.1:3080` 開啟其瀏覽器 UI，並以啟動目錄作為預設工作區。其瀏覽器 UI 不接受起始提示，所以 `omarchy agent prompt` 開啟它時會把提示放在你的剪貼簿中讓你貼上。Omarchy 會以 DeepSeek 的無需核准權限預設集啟動它。當你使用 DeepSeek 的官方模型 API 時，DeepSeek Harness 會將工作階段記錄上傳到 DeepSeek；在其瀏覽器 UI 的 _Settings > General > Upload Session Log_ 下將它關閉。你傳送給它的意見回饋也會連同工作階段一起上傳，除非你以 `DSH_TELEMETRY_MODE=DISABLED` 啟動它。

### 預設 agent

使用 `omarchy default agent <name>`，或在 Omarchy Menu（`Super + Space`）的 _Agent > Harness_ 下，挑選你的預設 agent。如果該 agent 尚未安裝，選擇它時會先安裝它。全新的 Omarchy 會以一次性的通知邀請你做出這個選擇。

選擇 Claude 時，也會嘗試為 Chromium、Chrome、Brave、Brave Origin 和 Edge 設定其瀏覽器擴充功能。擴充功能設定適用於所有使用者，且可能要求你輸入系統密碼；取消或擴充功能安裝失敗，仍會選取並啟動 Claude。重新啟動你的瀏覽器，在出現提示時啟用擴充功能，並登入 Claude 以完成連接。在 Claude 中執行 `/chrome` 以檢查連線。Firefox 和 Zen 不支援這個擴充功能。如果在加入這項設定之前 Claude 就已經是你的預設，請再次選取它以安裝擴充功能。

一旦你選好，`Super + Shift + Ctrl + A` 會在專用的終端機視窗中啟動預設 agent（或者如果你還沒選，就會叫出選擇器）。你也可以用 `omarchy agent prompt "Review this project"` 直接讓它進入一項任務。Freebuff 和 DeepSeek Harness 不接受起始提示，所以它們開啟時會改為把提示放在你的剪貼簿中讓你貼上。以這種方式啟動的 agent 會在各自「不停下來詢問」的模式下無人監管地執行，所以要做好它們真的會動手做事的準備！MiniMax Code 的互動式工作階段沒有這種模式，所以它會照常要求權限。而且由於 agent 拒絕記住對你家目錄的信任，從 `$HOME` 啟動時會改在 `~/Work` 中開始。

也有終端機捷徑：`a` 會在目前的終端機內直接執行預設 agent，而 `c`、`cx` 和 `cy` 則直接啟動 OpenCode、Claude Code 和 Codex（同樣是在它們的自動核准模式下）。主題變更也會同步給 agent：當你切換 Omarchy 主題時，Claude Code、Pi、OpenCode 和 Hermes（一旦 Omarchy 已安裝它）都會跟著變更。

### 你的 agent 指示

給每個 agent 的個人規則都放在 `~/.agents/AGENTS.md`，就在 `~/.agents/skills` 中的共用 skills 旁邊。在 _Agent > Instructions_ 下開啟它，它也會把它連結到每個保有自己全域檔案的 harness 中：`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`~/.pi/agent/AGENTS.md`、`~/.config/opencode/AGENTS.md`、Copilot 的 `~/.copilot/copilot-instructions.md`，等等。Crush 和 Amp 讀取 `~/.config/AGENTS.md` 連結，而 omp、Kimi 和 DeepSeek Harness 則直接讀取 `~/.agents/AGENTS.md`。挑選預設 agent 時也會連結它。如果你已經有一個指示檔案，而且尚未有共用檔案，它就會成為共用檔案；否則它會以 `.bak` 的形式保留在連結旁邊。安裝另一個 agent 後，執行 `omarchy agent instructions` 以重新連結。

### agent 面板

頂部列有一個 agent 圖示。在你設定好 agent 之前，它的面板會引導你登入 Claude、Codex 或 Grok，而第一個登入的就會成為你的預設 agent。之後，面板會把每個訂閱都放在同一頁：每個 agent 及其帳號連同其方案，針對其 5 小時工作階段額度與每週額度的每一個都有一個計量表，並顯示距離重置還有多久（將滑鼠懸停可查看確切百分比），或者剩餘的預付餘額，全都排在一行輪播文字下方，輪流顯示你在所有這些服務中用過什麼，例如本週的 tokens 和你最常用的模型。在 _Make something_ 下，它提供用於新主題、外掛、應用程式或遊戲的入門提示，把任務交給你的預設 agent。應用程式的打造方式與 Omarchy 自己的 Hype、Monologue 和 Omacut 相同，用 C++ 和 Qt Quick，遵循 omarchy-app agent skill，而且它們需要的編譯器和 Qt 元件都已安裝。遊戲是放在 `~/Games/vibes` 中的單一 three.js 頁面，遵循 web-game agent skill，而且全部都從目前主題中的同一個 Game Vibes 啟動器開啟；它們從網路載入 three.js，所以啟動時需要連線。Claude Code、Codex、Grok、Kimi、Cursor 及其 Grok Bot 額度、GitHub Copilot、Muse、Antigravity、Kimchi 和 Devin 都開箱即用地涵蓋在內並附帶其額度，而 Hermes、Mistral Vibe 和 Qwen Code 則會在你用過之後顯示其工作階段和 tokens。你透過 pi、omp 或 opencode 使用的供應商方案和金鑰也會出現：OpenCode Zen 和 Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan 和 Synthetic 及其額度；Fireworks、OpenRouter 和 DeepSeek 及其預付餘額；以及你在自己硬體上執行的模型，列在 Local models 下。每個 agent 只計算一次，歸在向你收費的一方名下，不論你透過多少個 harness 驅動它。

左鍵按一下列上的圖示開啟面板，右鍵按一下則啟動你的預設 agent。其背後的使用記錄每 15 分鐘由 `omarchy agent usage-update` 重新產生一次，而且面板甚至可以透過同步資料夾合併來自你其他機器的使用量。完整設定請參閱 `$OMARCHY_PATH/shell/plugins/agents/` 下的 README。

### 多個訂閱

如果你付費訂閱了一個以上的 Claude、Codex 或 Grok 方案——比方說一個個人的 Max 和一個工作的——Omarchy 可以讓它們全部保持登入，並在它們之間切換。用 agent 面板中的 + 新增訂閱，它會就在那裡引導你完成，或者用 `omarchy agent account add claude Work`（或 `codex`，或 `grok`）。如果缺少 CLI，它會安裝它。某個供應商的第一個帳號會透過你的一般瀏覽器登入，就在 CLI 一直查看的位置。之後的每一個都會透過私密視窗登入，所以你的瀏覽器已經登入的帳號不會被誤選；在那裡以你要新增的帳號登入，並先關閉你已經開啟的任何私密視窗。絕不要為了這樣做而登出 CLI：登出會撤銷已儲存的登入狀態，而且該帳號得重新新增一次。

若要透過 SSH 將你的訂閱登入資訊複製到另一台 Omarchy 機器，請執行 `omarchy agent account copy user@laptop`。當目的地沒有安裝接收端時，傳送端會提供一個臨時接收端，所以較舊的 Omarchy 機器不需更新就能接收帳號。已安裝的接收端優先。這會複製所有 Claude、Codex 和 Grok 訂閱；加入供應商名稱以選取它們，例如 `omarchy agent account copy laptop claude`。帳號名稱和指令 ID 與來源相符，包括目的地上已經存在的帳號。無關的目的地帳號在名稱衝突時會收到數字後綴，而且設定、skills、外掛和對話歷史都各自保留在本機。

目的地上現有的憑證會被保留。已經在那裡登入的來源帳號，其名稱會被同步但不會取代其憑證；其他帳號則會加在它旁邊。若要取代相符帳號已儲存的憑證，請在目的地結束該帳號的工作階段後使用 `omarchy agent account copy --replace laptop claude`。全新的目的地還會取得來源的現用帳號和切換偏好；已經建立好的目的地則保留自己的。

憑證透過 SSH 傳輸，並儲存在目的地上的私人檔案中，所以只複製到你信任的機器。這是一次性的複製，不是持續同步。Codex 的 refresh token 可能被另一台機器輪替，讓複製的登入需要續期；在好幾台機器上同時使用時，個別登入仍然是最可靠的選擇。請參閱 [Codex 的帳號驗證指南](https://developers.openai.com/codex/auth/ci-cd-auth)。

每個供應商只有一個帳號是現用的，而且每個新工作階段都會以它開始：`cx`、`cy`、普通的 `claude`、`codex` 或 `grok`、任何透過 `omarchy agent` 啟動的東西，以及在 `PATH` 上找到 CLI 的腳本或編輯器。用 `omarchy agent account use work` 切換（再用 `omarchy agent account use main` 切回去），或者在面板中按下帳號的數字然後按 `Enter`（或按一下它的 Use 按鈕）。正在執行的 Claude 工作階段也會切換，從它們的下一則訊息開始：每個 Claude 工作階段都在 `~/.claude` 中執行，該處永遠保有現用帳號的登入狀態。由較舊的 Omarchy 在帳號自己資料夾中啟動的 Claude 工作階段，在結束前會一直保有該登入狀態，所以切換時會點名那些工作階段，並在它們消失後自行完成。正在執行的 Codex 和 Grok 工作階段會留在它們開始時所用的帳號上。對話歷史、設定、skills 和外掛在各帳號之間共用，所以在同一個資料夾中執行 `claude --continue`，會在新帳號上接續你離開時的位置。

有多個帳號時，面板會並排顯示每個帳號的額度，並標示出現用的那一個。預設情況下，當現用帳號超過額度的 95% 時 Omarchy 會通知你，而按一下通知就會切換到餘裕最多的帳號。將滑鼠懸停在面板中帳號的那一行，按一下 Use 旁邊出現的 Autoswitch（或按 `m`），或者執行 `omarchy agent account mode auto`，讓它改為自行切換；在它開啟期間，Autoswitch 會取代 Use 的位置，而且再次按一下它就會回到通知模式。加入數字以變更門檻，例如 `omarchy agent account mode auto 90`。如果每個帳號都超過門檻，你會收到一次通知，同時告訴你哪個帳號最先釋出額度。當現用帳號距離其門檻在 15 個百分點內時（預設值下為 80%），它的額度會改為每三分鐘檢查一次，而不是每 15 分鐘。

`omarchy agent account list` 顯示每個帳號及其最新額度，`omarchy agent account remove work` 會忘記一個帳號，而 `omarchy agent account rename primary Hey` 則重新命名一個帳號（或按一下面板中帳號的名稱）。這些指令作用於你的預設 agent 的帳號；若要接觸另一個供應商，請先點名它，例如 `omarchy agent account use codex side`。你已經在 `~/.claude` 或 `~/.codex` 中持有的登入是 _Main_ 帳號。Codex 的帳號會留在原處；Claude 的帳號則在另一個帳號使用期間待在它自己的資料夾中。閒置超過約八小時的帳號可能顯示 _Sign-in required_；按一下它就在面板中直接重新登入該帳號，或者切換到它並啟動一個工作階段，它就會自行更新登入狀態。你用 `claude mcp add` 加入的 MCP 伺服器會到達每個 Claude 帳號，因為它們全都在 `~/.claude` 中執行；對於 Codex 和 Grok，在新增帳號時你已有的伺服器會跟著過去，但後來加入的只會到達你當時新增它們的那個帳號。Claude Desktop 保持它自己的登入狀態，而且用絕對路徑指向某個 CLI 二進位檔來設定的 Codex 或 Grok 工具不會跟著切換。明確指定的 `CLAUDE_CONFIG_DIR`、`CODEX_HOME` 或 `GROK_HOME` 優先於所選的帳號。

### 當機診斷

Omarchy 會監視 systemd-coredump 中的處理程序當機。當某個東西發生 segfault，你會收到一個 "Process crashed" 通知——按一下它，當機就會連同 Omarchy 的 diagnose-crash skill 一起交給你的預設 agent，該 skill 會引導 agent 從 core dump 建立事實，並判斷這次當機是否值得向 upstream 回報。你也可以用 `omarchy agent crash <pid>`，針對從 `coredumpctl list` 得到的任何 PID 手動執行它。

這項監視預設開啟。在 _Trigger > Toggle > Crash Capture_ 下將它關閉（或用 `omarchy toggle crash-capture`），通知就會停止；`omarchy agent crash <pid>` 仍可用手動方式運作。

當機也可以一次靜音一個程式，這正是診斷最後會向你提議的。`omarchy crash mute hyprland` 只停止該程式的通知，`omarchy crash mute hyprland off` 會把它們帶回來，而單獨執行 `omarchy crash mute` 則會列出你已靜音的項目。它同樣接受二進位檔的路徑和名稱，所以 `omarchy crash mute /usr/bin/hyprland` 效果相同。把帶有空格的名稱括起來，例如 `omarchy crash mute 'Some App'`。其他所有東西仍會通知，而且被靜音的程式仍然會當機——這只是隱藏提醒，並不會修好任何東西。

### 桌面應用程式

_Install > AI_ 選單還收錄了幾個圖形化 AI 應用程式：ChatGPT 桌面應用程式、Claude 桌面應用程式（Anthropic 的 Linux beta，帶有 Chat、Cowork 和 Claude Code 分頁）、用於與 xAI 模型聊天的 Grok Bot、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexity 桌面應用程式，以及 T3 Code。Grok Bot 是桌面聊天應用程式。程式設計 agent 則是 `grok` 指令。

Hermes Desktop 是需要知道的那一個，因為一台機器只有一個 Hermes，而且它是屬於該應用程式的：Hermes 只透過這個應用程式安裝，而且預設 agent 執行的 `hermes` 指令就是該應用程式的。選擇 Hermes 作為預設 agent 安裝的，就是 _Install > AI_ 項目安裝的同一樣東西：套件，以及由 Hermes 自己的安裝程式在 `~/.hermes` 下設定好的 Hermes runtime，第一次需要幾分鐘時間。這個 runtime 就是終端機 `hermes` 指令、預設 agent 和應用程式全都共用的那唯一一個 Hermes，而且它會用 `hermes update` 自行更新，而不是等 Omarchy 發行新版。安裝它還會把 Omarchy 主題作為一個名為 `omarchy` 的 skin 交給 Hermes，每個 Hermes 介面在你切換主題時都會跟著變更；如果你不希望如此，請在 Hermes 的 Appearance 設定下或用 `/skin` 挑選另一個，而 Omarchy 會尊重那個選擇。在 _Remove > AI_ 下移除該應用程式會先關閉 Hermes，包括 gateway 在內，連同該 runtime 一起帶走，並保留你的聊天、記憶以及 Hermes 為自己寫的 skills，除非你另有指示：它會以預設為否的方式詢問，那些資料和你的連線設定是否也要一併刪除。

OpenClaw 的桌面體驗是其 Control UI，它會以自己的本機 gateway 作後端開啟為網頁應用程式。OpenClaw 住在 `~/.openclaw` 並會自行更新：使用 Control UI 的 "Update Gateway" 按鈕或執行 `openclaw update`，gateway 就會在新版本上重新啟動。Omarchy 只挑選全新安裝的起始版本。在 _Remove > AI_ 下移除 OpenClaw 會連同 gateway 服務和應用程式一起帶走，然後詢問 `~/.openclaw` 是否也要一併刪除，因為那裡放著你的聊天和憑證，以及 OpenClaw 本身和它下載的外掛 runtime；預設會保留它，而再次安裝 OpenClaw 就會重新接上它。

Herdr Desktop 是 [Herdr](https://herdr.dev) 桌面應用程式：當你關閉視窗後，其核心中仍持續執行的終端機與程式設計 agent 的 spaces、tabs 和 panes。它來自 Herdr 自己的安裝程式而非套件，所以它住在 `~/.local/share/herdr-app`，當你還沒有 Herdr 核心時會在 `~/.local/bin/herdr-core` 一併帶來一個，而且兩者都會自我更新。它與 Omarchy 在 `Super + Ctrl + Return` 上隨附的 `herdr` 指令並列存在而不是取代它，而且取得了那個指令的直接按鍵：`Alt + Return` 和 `Alt + Shift + Return` 向下或向右分割 pane，`Alt + Escape` 關閉它，`Ctrl + Alt + Arrow` 在 panes 之間移動，`Alt + 1..9` 和 `Alt + Left/Right` 挑選 tab，而 `Alt + Up/Down` 在 spaces 之間移動。`Ctrl + 1..9` 挑選 space，而 `Alt + Shift + Up/Down` 在 agent 之間逐一移動。`Ctrl + Space` 前綴按鍵仍然只屬於終端機，因為該應用程式無法為一個序列按住普通的 Ctrl 鍵。Omarchy 將這些寫入 `~/.config/herdr-app/keys.json`，而 `omarchy-refresh-herdr-app` 會把它們放回去。安裝它會挑選 Herdr 的 Omarchy 主題，從此跟隨你的 Omarchy 主題。Herdr 為亮色模式保留一個主題、為深色模式保留一個，所以在深色與淺色 Omarchy 主題之間切換後，請在 Herdr 的主題選擇器中再挑選一次 Omarchy 以套用到另一個模式。

T3 Code 從其位於 `~/.local/share/t3code` 的官方 AppImage 發行版本執行而非來自套件，所以它會自行更新。安裝它時會詢問要在 Stable 還是 Nightly 頻道開始；稍後在 T3 Code 的設定中切換。你的 threads 和設定住在 `~/.t3`，而且在 _Remove > AI_ 下移除 T3 Code 會把它們一併帶走。

### 本機模型

在你自己的機器上為你的程式設計 agent 執行一個開放模型。你的提示和程式碼會留在機器上；送給模型的任何東西都不會離開它。從以下指令開始：

```bash
omarchy agent local use best
```

或者，在頂部列的 agent 面板中，先選擇 + 再選擇 Local AI，當有模型適合這台機器時它就會出現。第一次這樣做時，會安裝 Podman，它負責執行模型；而且在 NVIDIA 機器上會安裝 NVIDIA 的容器工具包，讓模型能使用 GPU。接著 Omarchy 會為這台機器挑選建議的模型、下載它並啟動它。預期下載量會有數十 GB，而且模型執行期間機器的大部分記憶體都會被佔用：Flash Next 在其完整的 256K context 下大約使用 100 GiB。如果其他模型佔著它需要的記憶體，它會以停止狀態設定好，等你停掉其中一個就能隨時啟動。模型在登出時停止；當你需要記憶體做其他事時，請自己停掉它。

`omarchy agent local list` 顯示各個選項，並說明為什麼有些不適合。若要設定另一個，請執行 `omarchy agent local use <recipe>`。目前，`qwen3.8-flash-next-gufo` 和 `qwen3.8-27b-gufo` 適用於 128 GB Strix Halo 機器；27B 大約佔 40 GiB，所以會留出空間給其他工作。在配備 Intel 的 Arc B390 的 64 GB 筆記型電腦上，`qwen3.6-35b-a3b-llamacpp` 大約以 30 GiB 執行。新的 recipes 和建議會隨著 `omarchy update` 透過套件送達。

你設定的每個模型在 agent 面板中都會有自己的一行，就在你的訂閱旁邊：按播放以啟動它，按暫停以停止它並釋放其記憶體，按終端機按鈕則在其上開啟你的 agent。當記憶體裝得下時，好幾個可以同時執行；如果裝不下，Omarchy 會說該停掉哪個正在執行的模型。拖曳各行以重新排列它們，並在選取的一行上按 Delete 以移除模型及其下載。

你設定的每個模型還會在應用程式啟動器中取得自己的項目，以模型的名稱並帶著其製造商的 logo，就像登入 Claude、Codex 或 Grok 會加入一個一樣。它會在該模型上開啟你的 agent，如果模型還沒執行，就會先啟動模型：終端機會顯示它載入中，並在它就緒後交給 agent。移除模型也會移除其項目。

從命令列來看，`omarchy agent local start <recipe>` 和 `omarchy agent local stop <recipe>` 做的是同一件事，`omarchy agent local status` 顯示每個模型，而 `omarchy agent --local` 則在你上次啟動的模型上開啟你的預設 agent。pi、OpenCode 和 Qwen Code 可以使用其中一個；如果預設是其他任何 agent，它會在 pi 中開啟。pi 也會在其自己的模型選擇器中列出你設定過的每個模型，以及那些在你已配對的機器上的模型，所以普通的 `pi` 也能連到它們。任何與 OpenAI 相容的用戶端也可以連線：`status` 會顯示每個模型的位址（第一個是 `http://127.0.0.1:11435/v1`），recipe 名稱就是模型，而金鑰在 `~/.config/omarchy/agent-local/key` 中。

`omarchy agent local remove <recipe>` 會刪除一個模型，以及沒有其他模型使用的下載。

第三方 runtime 會標示其發布者。Omarchy 在沒有網路存取的情況下執行每個模型。

### 本機 LLM

Omarchy 推薦兩種執行本機 LLM 模型的方式：LM Studio 和 Ollama。LM Studio 提供一個 GUI 介面，用於尋找開放權重模型、安裝它們並執行它們。它是輕鬆上手的好方法。Ollama 則提供做類似事情的 CLI。但如果你是本機模型的新手，我會從 LM Studio 開始。你可以在 Omarchy Menu 的 _Install > AI_ 下安裝任一個。

### Omarchy Skill

Agent skills 協助 AI 以特定方式使用特定工具，而且 Omarchy 隨附了一個用於調整系統的預設 skill。像是調整你的 Hyprland 設定、調整列，甚至從零打造新主題。它被 symlink 進 Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` 以及每一個 `~/.hermes/profiles/*/skills`）的 skill 目錄，還有通用的 `~/.agents/skills` 位置，所以大多數 harness 都會自動接上它。

但你應該把這個 skill 當作實驗性的。不同的模型會以不同程度發揮它。最好先在計畫模式下執行，這樣你能了解 agent 想要變更什麼。然後做好回復變更、甚至在 agent 把一切搞得一團糟時調用 `omarchy reinstall configs` 的準備。
