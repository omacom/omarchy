### 安裝與更新代理工具

除了 Hermes 之外，這些代理工具都使用 mise 的延遲安裝：首次啟動會安裝 CLI，後續啟動則重複使用它。mise 也會在啟動前或在 shell 提示字元處於背景時，檢查已安裝的代理工具是否有新版本，最多每四小時一次。如果該更新失敗或你處於離線狀態，就執行已安裝的版本。`omarchy update` 會連同 Omarchy 的其他部分一起更新已安裝的代理工具，而 `mup` 則只更新 mise 管理的工具。

代理工具自己的更新程式，例如 `claude update`、`codex update`，或應用程式中的更新按鈕，不會更新 mise 管理的安裝。`codex update` 會失敗，而 `claude update` 可能回報成功，卻安裝了一份 mise 沒有追蹤的獨立副本。如果你寧願使用代理工具原生的安裝程式與更新程式，把它加入 `disable_tools`；詳見[預先安裝的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

若要在需要之前安裝所有已設定的延遲工具，執行 `mise install --include-lazy`。這包含 Omarchy 的其他預設 CLI 工具以及這些代理工具。關於安裝單一工具或使用你自己的安裝方式，詳見[預先安裝的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

`grok` 是透過 mise 的第一方 `grok` 套件安裝，方式與 `claude` 和 `codex` 相同。執行 `grok`，或在 _Setup > Defaults > Agent_ 底下選取它。跳過 x.ai 上的 `curl | bash` 安裝程式。那條路徑會在 `~/.grok/bin` 放入第二份副本、把它加在 `PATH` 最前面，並覆寫 Omarchy 的包裝程式。

`dsh` 會在 `127.0.0.1:3080` 開啟它的瀏覽器 UI，並以啟動目錄作為它的預設工作區。它的瀏覽器 UI 不接受起始提示，所以 `omarchy agent prompt` 會開啟它，並把提示放在你的剪貼簿讓你貼上。Omarchy 以 DeepSeek 的不需核准權限預設集啟動它。當你使用 DeepSeek 官方的模型 API 時，DeepSeek Harness 會把工作階段記錄上傳到 DeepSeek；在它的瀏覽器 UI 中，在 _Settings > General > Upload Session Log_ 底下關閉這個功能。你送出的意見回饋也會連同工作階段一起上傳，除非你以 `DSH_TELEMETRY_MODE=DISABLED` 啟動它。

### 預設代理工具

用 `omarchy default agent <name>` 選取你的預設代理工具，或在 Omarchy Menu（`Super + Space`）的 _Setup > Defaults > Agent_ 底下選取。如果該代理工具尚未安裝，選取它會先安裝它。全新安裝的 Omarchy 會用一次性的通知邀請你做這個選擇。

選擇 Claude 也會嘗試為 Chromium、Chrome、Brave、Brave Origin 和 Edge 設定它的瀏覽器擴充功能。擴充功能的設定適用於所有使用者，可能會要求你輸入系統密碼；取消或擴充功能安裝失敗，仍然會選取並啟動 Claude。重新啟動你的瀏覽器，出現提示時啟用擴充功能，並登入 Claude 以完成連接。在 Claude 中執行 `/chrome` 來檢查連接。Firefox 和 Zen 不支援這個擴充功能。如果在加入這項設定之前 Claude 就已經是你的預設工具，再選取一次即可安裝擴充功能。

一旦你選好了，`Super + Shift + Ctrl + A` 會在專用的終端機視窗中啟動預設代理工具（如果你還沒選，就會顯示選擇器）。你也可以用 `omarchy agent prompt "Review this project"` 直接讓它進入一項任務。Freebuff 和 DeepSeek Harness 不接受起始提示，所以它們會改為開啟並把提示放在你的剪貼簿讓你貼上。以這種方式啟動的代理工具，會在各自不要停下來問的模式下無人看管地執行，所以準備好它們真的會動手做事吧！MiniMax Code 的互動式工作階段沒有這種模式，所以它會照常詢問權限。而且由於代理工具拒絕記住對你家目錄的信任，從 `$HOME` 啟動時會改在 `~/Work` 中開始。

也有終端機捷徑：`a` 會在目前的終端機中內嵌執行預設代理工具，而 `c`、`cx` 和 `cy` 則直接啟動 OpenCode、Claude Code 和 Codex（同樣是在它們的自動核准模式下）。主題變更也會同步到這些代理工具：當你切換 Omarchy 主題時，Claude Code、Pi、OpenCode 和 Hermes（在 Omarchy 已安裝它之後）都會跟著變。

### 代理工具面板

頂部列有一個代理工具圖示。在你設定代理工具之前，它的面板會引導你登入 Claude、Codex 或 Grok，而第一個登入的會成為你的預設代理工具。在那之後，面板把每一個訂閱都放在同一個頁面上：每一個代理工具和帳號連同它的方案，每一個 5 小時工作階段和每週限制的用量計量條以及距離重設還剩的時間（把滑鼠停在上面可看到確切百分比），或是剩餘的預付餘額，都列在一行輪播你跨所有代理工具的使用量的文字底下，像是本週的 token 數量和你最常使用的模型。在 _Make something_ 底下，它提供用於新主題、新外掛或新應用程式的起始提示，並把任務交給你的預設代理工具。應用程式是用和 Omarchy 自家的 Hype、Monologue 和 Omacut 相同的方式打造的，使用 C++ 和 Qt Quick，遵循 omarchy-app 代理技能，而它們所需的編譯器和 Qt 組件都已隨附安裝。Claude Code、Codex、Grok、Kimi、Cursor 及其 Grok Bot 額度、GitHub Copilot、Muse、Antigravity、Kimchi 和 Devin 都已開箱即用地涵蓋並附其限制，而 Hermes、Mistral Vibe 和 Qwen Code 則在你用過它們之後顯示它們的工作階段和 token。你透過 pi、omp 或 opencode 使用的供應商方案和金鑰也會出現：附其限制的 OpenCode Zen 和 Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan 和 Synthetic；附其預付餘額的 Fireworks、OpenRouter 和 DeepSeek；以及你在自己的硬體上執行的模型，列在 Local models 底下。每一個代理工具只計算一次，歸在向它收費的那一方名下，不論你透過多少個 harness 來驅動它。

左鍵按一下列上的圖示開啟面板，右鍵按一下則啟動你的預設代理工具。它背後的用量記錄每 15 分鐘由 `omarchy agent usage-update` 重新產生，而面板甚至可以透過一個已同步的資料夾合併來自你其他機器的用量。完整的設定詳見 `$OMARCHY_PATH/shell/plugins/agents/` 底下的 README。

### 多個訂閱

如果你付費購買了不只一個 Claude、Codex 或 Grok 方案 — 比如說一個個人的 Max 和一個工作的 — Omarchy 可以讓它們全都保持登入，並在它們之間切換。用代理工具面板中的 + 新增一個訂閱，它會就在那裡引導你完成，或者用 `omarchy agent account add claude Work`（或 `codex`，或 `grok`）。如果 CLI 不見了，它會安裝它。某個供應商的第一個帳號會透過你平常的瀏覽器登入，就在 CLI 一向查看的那個地方。之後的每一個帳號都透過私密視窗登入，所以你瀏覽器已經登入的那個帳號不會被誤選；在那裡以你正在新增的那個帳號登入，並先關掉你已經開著的任何私密視窗。絕對不要為了做這件事而登出 CLI：登出會撤銷已儲存的登入，而那個帳號就必須重新新增。

若要透過 SSH 把你的訂閱登入複製到另一台 Omarchy 機器，執行 `omarchy agent account copy user@laptop`。當目的地沒有安裝接收端時，傳送端會提供一個臨時接收端，所以較舊的 Omarchy 機器不需更新也能接收帳號。已安裝的接收端優先。這會複製所有的 Claude、Codex 和 Grok 訂閱；加上供應商名稱來選取它們，例如 `omarchy agent account copy laptop claude`。帳號名稱和指令 ID 與來源相符，包括目的地已經存在的帳號。無關的目的地帳號如果名稱衝突，會得到一個數字後綴，而設定、技能、外掛和對話記錄都保留在各自的機器上。

目的地現有的憑證會被保留。某個來源帳號如果已經在那裡登入，它的名稱會被同步，但不會取代它的憑證；其他帳號會被新增到它旁邊。若要取代相符帳號已儲存的憑證，在結束目的地該帳號的工作階段之後，使用 `omarchy agent account copy --replace laptop claude`。一個全新的目的地也會取得來源目前使用的帳號和切換偏好；一個已經建立好的目的地則保留它自己的。

憑證透過 SSH 傳輸，並儲存在目的地上的私密檔案中，所以只複製到你信任的機器。這是一次性的複製，不是持續的同步。Codex 的 refresh token 可能被另一台機器輪換，導致一份複製的登入需要重新更新；要在數台機器上同時使用，分別登入仍然是最可靠的選擇。詳見 [Codex 的帳號驗證指南](https://developers.openai.com/codex/auth/ci-cd-auth)。

每一個供應商有一個使用中的帳號，而每一個新工作階段都以它開始：`cx`、`cy`、普通的 `claude`、`codex` 或 `grok`、透過 `omarchy agent` 啟動的任何東西，以及在 `PATH` 上找到 CLI 的指令稿或編輯器。用 `omarchy agent account use work` 切換（並用 `omarchy agent account use main` 切回來），或在面板中按下某個帳號的數字再按 `Enter`（或按一下它的 Use 按鈕）。已經在執行的工作階段會留在它們開始時的那個帳號。對話記錄、設定、技能和外掛在帳號之間共用，所以在同一個資料夾中執行 `claude --continue` 會在新帳號上接續你上次離開的地方。

當你有多個帳號時，面板會並排顯示每個帳號的限制，並標記使用中的那一個。依預設，當使用中的帳號超過某個限制的 95% 時 Omarchy 會通知你，而按一下該通知會切換到餘裕最多的帳號。把滑鼠停在面板中某個帳號的那一行上，按一下在 Use 旁邊出現的 Autoswitch（或按 `m`），或執行 `omarchy agent account mode auto`，即可讓它自己切換；當它開啟時，Autoswitch 會取代 Use 的位置，而再按一次它就會回到通知模式。加上一個數字來變更門檻，例如 `omarchy agent account mode auto 90`。如果每一個帳號都超過門檻，你會被通知一次，並被告知哪個帳號最先釋出額度。當使用中的帳號距離它的門檻在 15 個百分點以內（預設值為 80%）時，它的限制會每三分鐘檢查一次，而不是每 15 分鐘。

`omarchy agent account list` 顯示每一個帳號及其最新限制，`omarchy agent account remove work` 遺忘一個帳號，而 `omarchy agent account rename primary Hey` 為一個帳號重新命名（或在面板中按一下某個帳號的名稱）。這些指令作用在你預設代理工具的帳號上；若要觸及另一個供應商，先寫出它的名稱，例如 `omarchy agent account use codex side`。你原本在 `~/.claude` 或 `~/.codex` 中的登入是 _Main_ 帳號，而且會留在原處。一個閒置超過約八小時的帳號可能會顯示 _Sign-in required_；按一下它就能直接在面板中為該帳號重新登入，或在該帳號中啟動一個工作階段，它自己就會更新登入。在新增某個帳號時你已有的 MCP 伺服器會跟著過去到該帳號，但你之後用 `claude mcp add` 新增的那些，只會到達你新增它們時的那個帳號。Claude Desktop 以及以 CLI 執行檔的絕對路徑設定的工具，不會跟著切換。一個明確指定的 `CLAUDE_CONFIG_DIR`、`CODEX_HOME` 或 `GROK_HOME` 優先於所選的帳號。

### 當機診斷

Omarchy 監看 systemd-coredump 的處理程序當機。當有東西發生段錯誤時，你會收到一個「Process crashed」通知 — 按一下它，當機資訊就會連同 Omarchy 的 diagnose-crash 技能一起交給你的預設代理工具，該技能會引導代理工具從核心傾印中確立事實，並判斷這次當機是否值得向上游回報。你也可以用 `omarchy agent crash <pid>`，針對 `coredumpctl list` 中的任何 PID 手動執行它。

監看功能依預設開啟。在 _Trigger > Toggle > Crash Capture_ 底下關閉它（或用 `omarchy toggle crash-capture`），通知就會停止；`omarchy agent crash <pid>` 仍然可以手動使用。

當機也可以一次只讓一個程式靜音，這正是診斷在最後會提供你的功能。`omarchy crash mute hyprland` 只會停止該程式的通知，`omarchy crash mute hyprland off` 會把它們帶回來，而單獨執行 `omarchy crash mute` 則會列出你已靜音的項目。它接受執行檔的路徑就和接受名稱一樣樂意，所以 `omarchy crash mute /usr/bin/hyprland` 做的是同一件事。用引號把含有空格的名稱括起來，例如 `omarchy crash mute 'Some App'`。其他所有東西仍然會通知，而被靜音的程式也仍然會當機 — 這只是隱藏提醒，不會修好任何東西。

### 桌面應用程式

_Install > AI_ 選單還包含幾個圖形化的 AI 應用程式：ChatGPT 桌面應用程式、Claude 桌面應用程式（Anthropic 的 Linux beta 版，附有 Chat、Cowork 和 Claude Code 分頁）、用於和 xAI 的模型聊天的 Grok Bot、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexity 桌面應用程式，以及 T3 Code。Grok Bot 是桌面聊天應用程式。程式設計代理工具則是 `grok` 指令。

Hermes Desktop 是你需要認識的那一個，因為一台機器只有一個 Hermes，而它是屬於這個應用程式的：Hermes 只會透過這個應用程式安裝，而預設代理工具執行的 `hermes` 指令也是這個應用程式的。選擇 Hermes 作為預設代理工具，安裝的是和 _Install > AI_ 項目同樣的東西：套件，以及由 Hermes 自己的安裝程式在 `~/.hermes` 底下設定的一個 Hermes 執行環境，第一次需要幾分鐘的時間。那個執行環境就是終端機的 `hermes` 指令、預設代理工具和應用程式全都在用的那同一個 Hermes，而且它用 `hermes update` 自行更新，而不是等 Omarchy 發布新版本。安裝它也會把 Omarchy 主題以名為 `omarchy` 的 skin 交給 Hermes，而每一個 Hermes 介面都會在你切換主題時跟著變；如果你不想要這樣，在 Hermes 的 Appearance 設定中或用 `/skin` 選另一個，Omarchy 就會尊重那個選擇不再干涉。在 _Remove > AI_ 底下移除該應用程式會先關閉 Hermes，包括 gateway 在內，並把那個執行環境一起帶走，同時保留你的聊天、記憶以及 Hermes 為自己寫的技能，除非你另有交代：它會詢問，預設為否，詢問那些資料和你的連接設定是否也要一併移除。

OpenClaw 的桌面體驗是它的 Control UI，它作為一個網頁應用程式開啟，背後是它自己本機的 gateway。OpenClaw 住在 `~/.openclaw` 並自行更新：使用 Control UI 的「Update Gateway」按鈕或執行 `openclaw update`，gateway 就會以新版本重新啟動。Omarchy 只決定全新安裝從哪個版本開始。在 _Remove > AI_ 底下移除 OpenClaw，會把 gateway 服務和應用程式一起帶走，然後詢問 `~/.openclaw` 是否也要一併移除，因為那裡除了 OpenClaw 本身和它下載的外掛執行環境之外，還存放著你的聊天和憑證；預設會保留它，而再次安裝 OpenClaw 時會把它接回來。

Herdr Desktop 是 [Herdr](https://herdr.dev) 桌面應用程式：由終端機和程式設計代理工具構成的 spaces、tabs 和 panes，當你關閉視窗時，它們會在它的 core 中持續執行。它來自 Herdr 自己的安裝程式而不是一個套件，所以它住在 `~/.local/share/herdr-app`，在你還沒有的時候把它的 core 放在 `~/.local/bin/herdr-core`，並且自行更新這兩者。它和 Omarchy 隨附在 `Super + Ctrl + Return` 上的 `herdr` 指令並存，而不是取代它，而且它也得到了該指令的直接按鍵：`Alt + Return` 和 `Alt + Shift + Return` 向下或向右分割一個窗格，`Alt + Escape` 關閉它，`Ctrl + Alt + Arrow` 在窗格之間移動，`Alt + 1..9` 和 `Alt + Left/Right` 選取一個分頁，而 `Alt + Up/Down` 在 spaces 之間移動。`Ctrl + 1..9` 選取一個 space 而 `Alt + Shift + Up/Down` 在代理工具之間逐個切換。`Ctrl + Space` 前綴鍵仍然是終端機專用，因為這個應用程式無法為一個序列按住一個普通的 Ctrl 鍵。Omarchy 把這些寫入 `~/.config/herdr-app/keys.json`，而 `omarchy-refresh-herdr-app` 會把它們放回去。安裝它會選取 Herdr 的 Omarchy 主題，從此之後它會跟隨你的 Omarchy 主題。Herdr 為淺色模式保留一個主題、為深色模式保留一個主題，所以在深色和淺色 Omarchy 主題之間切換之後，再在 Herdr 的主題選擇器中選一次 Omarchy 給另一種模式用。

T3 Code 從它在 `~/.local/share/t3code` 中的官方 AppImage 版本執行，而不是從一個套件，所以它自行更新。安裝它時會詢問你要從 Stable 還是 Nightly 頻道開始；日後可在 T3 Code 的設定中切換。你的討論串和設定存放在 `~/.t3`，而在 _Remove > AI_ 底下移除 T3 Code 會把它們一起帶走。

### 本機模型

在你自己的機器上為你的程式設計代理工具執行一個開放模型。你的提示和程式碼會留在機器上；送到模型的任何東西都不會離開它。從這裡開始：

```bash
omarchy agent local use best
```

或者，在頂部列的代理工具面板中，選擇 + 然後選擇 Local AI，當有模型適合這台機器時它就會出現。第一次執行時，這會安裝負責執行模型的 Podman，而在 NVIDIA 機器上還會安裝 NVIDIA 的容器工具包，讓它們能使用 GPU。然後 Omarchy 會為這台機器挑選推薦的模型，下載它並啟動它。請預期下載量會達數十 GB，而且模型執行時機器的大部分記憶體都會被占用：Flash Next 在其完整的 256K 上下文下約使用 100 GiB。如果其他模型占用了它需要的記憶體，它會被設定為停止狀態，準備在你停止其中一個模型後啟動。模型會在登出時停止；當你需要把記憶體用在其他事情上時，自行停止它。

`omarchy agent local list` 顯示這些選項，並解釋有些為什麼不適合。若要設定另一個，執行 `omarchy agent local use <recipe>`。目前，`qwen3.8-flash-next-gufo` 和 `qwen3.8-27b-gufo` 可用於 128 GB 的 Strix Halo 機器；27B 約占用 40 GiB，所以它給其他工作留了空間。新的 recipe 和推薦會透過套件隨 `omarchy update` 送達。

你設定的每一個模型在代理工具面板中都有自己的一行，緊鄰著你的訂閱：播放可啟動它，暫停可停止它並釋放它的記憶體，終端機按鈕可在該模型上開啟你的代理工具。當它們能一起裝進記憶體時，好幾個可以同時執行；如果有一個裝不下，Omarchy 會告訴你該停止哪個正在執行的模型。拖曳這些行來重新排序，並在選取的一行上按 Delete 來移除一個模型及其下載。

從指令列，`omarchy agent local start <recipe>` 和 `omarchy agent local stop <recipe>` 做同樣的事，`omarchy agent local status` 顯示每一個模型，而 `omarchy agent --local` 會在你最後啟動的那個模型上開啟你的預設代理工具（如果你的預設代理工具無法使用本機模型，則為 pi）。任何與 OpenAI 相容的用戶端也可以連接：`status` 會顯示每一個模型的位址（第一個是 `http://127.0.0.1:11435/v1`），recipe 名稱就是模型，而金鑰位在 `~/.config/omarchy/agent-local/key`。

`omarchy agent local remove <recipe>` 刪除一個模型以及沒有其他模型使用的下載。

第三方執行環境會標示出它們的發行者。Omarchy 在沒有網路存取的情況下執行每一個模型。

### 本機 LLM

Omarchy 推薦兩種執行本機 LLM 模型的方式：LM Studio 和 Ollama。LM Studio 提供一個 GUI 介面，用於尋找開放權重模型、安裝它們並執行它們。這是一個輕鬆上手的好方法。Ollama 提供一個 CLI 以類似的方式做到這一點。但如果你是本機模型的新手，我會建議從 LM Studio 開始。你可以在 Omarchy Menu 的 _Install > AI_ 底下安裝其中任一個。

### Omarchy 技能

代理技能幫助 AI 以特定的方式使用特定的工具，而 Omarchy 隨附了一項預設的技能用於量身打造系統。像是微調你的 Hyprland 設定、調整頂部列，或甚至從頭打造一個新主題。它被以符號連結的方式連結到 Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` 以及每一個 `~/.hermes/profiles/*/skills`）的技能目錄，以及通用的 `~/.agents/skills` 位置，所以大多數 harness 都會自動取得它。

但你應該把這項技能當作實驗性的來看待。不同的模型運用它的成效也會不同。最好先在規劃模式下執行，這樣你能對代理工具想要改變什麼有個概念。然後準備好回復變更，甚至在代理工具把一切都弄得一團糟時，呼叫 `omarchy reinstall configs`。
