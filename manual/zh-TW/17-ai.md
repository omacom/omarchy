### 安裝與更新 agent

Hermes 除外，這些 agent 都採用 mise 的延遲安裝：首次啟動時安裝 CLI，後續啟動則重複使用它。mise 也會至多每四小時檢查一次已安裝的 agent 是否有新版本，時間點就在它啟動之前，或在 shell 提示符下於背景檢查。如果更新失敗或你處於離線狀態，就會執行已安裝的版本。`omarchy update` 會連同 Omarchy 的其他部分一起更新已安裝的 agent，而 `mup` 只更新由 mise 管理的工具。

agent 自己的更新程式，例如 `claude update`、`codex update` 或應用程式中的更新按鈕，並不會更新由 mise 管理的安裝。`codex update` 會失敗，而 `claude update` 可能回報成功，卻安裝了 mise 沒有追蹤的另一份副本。如果你寧願使用 agent 原生的安裝程式與更新程式，請將它加入 `disable_tools`；參見 [預先安裝的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

若要在需要之前安裝所有已設定的延遲工具，請執行 `mise install --include-lazy`。這包括 Omarchy 的其他預設 CLI 工具以及這些 agent。關於安裝單一工具或使用你自己的安裝，請參見 [預先安裝的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

`grok` 透過 mise 的第一方 `grok` 套件安裝，方式與 `claude` 和 `codex` 相同。執行 `grok`，或在 _Agent > Harness_ 下選擇它。跳過 x.ai 上的 `curl | bash` 安裝程式。那條路徑會在 `~/.grok/bin` 放第二份副本，把它加到 `PATH` 最前面，並覆寫 Omarchy 的包裝程式。

`dsh` 在 `127.0.0.1:3080` 開啟其瀏覽器 UI，並以啟動目錄作為預設工作區。其瀏覽器 UI 不接受起始提示，所以 `omarchy agent prompt` 開啟它時會把提示放在你的剪貼簿中讓你貼上。Omarchy 以 DeepSeek 的無需核准權限預設集啟動它。當你使用 DeepSeek 官方的模型 API 時，DeepSeek Harness 會將工作階段紀錄上傳到 DeepSeek；在其瀏覽器 UI 的 _Settings > General > Upload Session Log_ 下將其關閉。你傳送給它的意見回饋也會連同工作階段一起上傳，除非你以 `DSH_TELEMETRY_MODE=DISABLED` 啟動它。

### 預設 agent

使用 `omarchy default agent <name>`，或在 Omarchy Menu（`Super + Space`）的 _Agent > Harness_ 下，選取你的預設 agent。如果 agent 尚未安裝，選取它會先將其安裝。全新的 Omarchy 會以一次性的通知邀請你做出這個選擇。

選擇 Claude 時，也會嘗試為 Chromium、Chrome、Brave、Brave Origin 和 Edge 設定它的瀏覽器擴充功能。擴充功能的設定適用於所有使用者，且可能要求輸入你的系統密碼；取消或擴充功能安裝失敗，仍會選取並啟動 Claude。重新啟動瀏覽器，依提示啟用擴充功能，並登入 Claude 以完成連接。在 Claude 中執行 `/chrome` 檢查連線。Firefox 和 Zen 不支援此擴充功能。如果在加入此設定之前 Claude 就已經是你的預設值，請再次選取它以安裝擴充功能。

選定之後，`Super + Shift + Ctrl + A` 會在專用的終端機視窗中啟動預設 agent（或者，如果你尚未選擇，就叫出選取器）。你也可以用 `omarchy agent prompt "Review this project"` 讓它直接進入工作。Freebuff 和 DeepSeek Harness 不接受起始提示，因此它們開啟時會把提示放在你的剪貼簿中讓你貼上。以這種方式啟動的 agent 會在各自不要停下來問的模式下無人看管地執行，所以要做好它們真的會動手做事的心理準備！MiniMax Code 的互動式工作階段沒有這種模式，所以它會照常詢問權限。而且由於 agent 拒絕記住對你家目錄的信任，從 `$HOME` 啟動時會改在 `~/Work` 中開始。

也有終端機捷徑：`a` 在目前的終端機內直接執行預設 agent，而 `c`、`cx` 和 `cy` 則直接啟動 OpenCode、Claude Code 和 Codex（同樣是在它們的自動核准模式下）。主題變更也會同步到這些 agent：當你切換 Omarchy 主題時，Claude Code、Pi、OpenCode 和 Hermes（在 Omarchy 已安裝它之後）都會跟著變。

### 你的 agent 指示

給每個 agent 的個人規則放在 `~/.agents/AGENTS.md`，就在 `~/.agents/skills` 中的共用技能旁邊。在 _Agent > Instructions_ 下開啟它；它也會將該檔案連結到每個保有自己全域檔案的 harness：`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`~/.pi/agent/AGENTS.md`、`~/.config/opencode/AGENTS.md`、Copilot 的 `~/.copilot/copilot-instructions.md`，依此類推。Crush 和 Amp 讀取 `~/.config/AGENTS.md` 連結，而 omp、Kimi 和 DeepSeek Harness 則直接讀取 `~/.agents/AGENTS.md`。選取預設 agent 時也會連結它。如果你已經有指示檔案，且尚無共用檔案，它就會成為共用檔案；否則它會以 `.bak` 保留在連結旁邊。安裝另一個 agent 後，執行 `omarchy agent instructions` 重新連結。

### agent 面板

頂部欄有一個 agent 圖示。在你設定好 agent 之前，它的面板會引導你登入 Claude、Codex 或 Grok，第一個登入的就會成為你的預設 agent。之後，面板會把每個訂閱放在同一頁：每個 agent 與帳戶及其方案、其 5 小時工作階段與每週限額各自的量表及距離重置的時間（將游標停在上面可看確切百分比），或剩餘的預付餘額，上方還有一行輪流顯示你在所有 agent 上的使用情況，例如本週的 token 和你最常用的模型。在 _Make something_ 下，它提供新主題、插件、應用程式或遊戲的起始提示，將工作交給你的預設 agent。應用程式的建置方式與 Omarchy 自己的 Hype、Monologue 和 Omacut 相同，使用 C++ 和 Qt Quick，遵循 omarchy-make-app agent 技能，而它們需要的編譯器和 Qt 元件都已安裝。遊戲是位於 `~/Games/vibes` 的單一 three.js 頁面，遵循 omarchy-make-game agent 技能，且全部從目前主題中的同一個 Game Vibes 啟動器開啟；它們從網路載入 three.js，所以啟動時需要連線。Claude Code、Codex、Grok、Kimi、Cursor 及其 Grok Bot 額度、GitHub Copilot、Muse、Antigravity、Kimchi 和 Devin 開箱即涵蓋其限額，而 Hermes、Mistral Vibe 和 Qwen Code 會在你使用過後顯示其工作階段和 token。透過 pi、omp 或 opencode 使用的供應商方案和金鑰也會顯示：OpenCode Zen 和 Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan 以及 Synthetic 及其限額；Fireworks、OpenRouter 和 DeepSeek 及其預付餘額；以及你在自己硬體上執行的模型，位於 Local models 下。每個 agent 只計算一次，歸在向你收費的一方名下，無論你透過多少個 harness 使用它。

左鍵點擊頂部欄圖示開啟面板，右鍵點擊則啟動你的預設 agent。其背後的使用紀錄由 `omarchy agent usage-update` 每 15 分鐘重新產生，且面板甚至可以透過同步資料夾合併你其他機器的使用情況。完整設定請參見 `$OMARCHY_PATH/shell/plugins/agents/` 下的 README。

### 多個訂閱

如果你付費訂閱了不只一個 Claude、Codex 或 Grok 方案——例如一個個人 Max 和一個工作用的——Omarchy 可以讓它們全部保持登入，並在它們之間切換。使用 agent 面板中的 + 新增訂閱，它會直接在那裡引導你完成，或使用 `omarchy agent account add claude Work`（或 `codex`、或 `grok`）。如果缺少 CLI，它會將其安裝。某個供應商的第一個帳戶透過你的一般瀏覽器登入，就在 CLI 一直查看的位置。之後的每個帳戶都透過隱私視窗登入，所以你瀏覽器已登入的帳戶不會被誤選；在那裡以你要新增的帳戶登入，並先關閉任何你已經開啟的隱私視窗。永遠不要為了這樣做而從 CLI 登出：登出會撤銷已儲存的登入，而該帳戶將必須重新新增。

若要透過 SSH 將你的訂閱登入資訊複製到另一台 Omarchy 機器，請執行 `omarchy agent account copy user@laptop`。當目的地未安裝接收端時，傳送端會提供臨時接收端，所以較舊的 Omarchy 機器無需更新即可接收帳戶。已安裝的接收端優先。此操作會複製所有 Claude、Codex 和 Grok 訂閱；加入供應商名稱可選取它們，例如 `omarchy agent account copy laptop claude`。帳戶名稱和指令 ID 與來源相符，包括目的地已存在的帳戶。不相關的目的地帳戶若名稱衝突，會收到數字後綴，而設定、技能、插件和對話紀錄則保留在各台機器本地。

目的地現有的憑證會保留。已在那裡登入的來源帳戶，其名稱會同步，但不會取代其憑證；其他帳戶會加在它旁邊。若要取代相符帳戶的已儲存憑證，請在結束目的地上該帳戶的工作階段後，使用 `omarchy agent account copy --replace laptop claude`。全新的目的地也會取得來源的使用中帳戶和切換偏好；已建立好的目的地則保留自己的。

憑證透過 SSH 傳輸，並儲存在目的地的私人檔案中，所以只複製到你信任的機器。這是一次性複製，不是持續同步。Codex 的 refresh token 可能被另一台機器輪替，使複製的登入資訊需要更新；若要在多台機器上同時使用，分開登入仍是最可靠的選擇。參見 [Codex 的帳戶驗證指南](https://developers.openai.com/codex/auth/ci-cd-auth)。

每個供應商有一個使用中的帳戶，且每個新工作階段都以它開始：`cx`、`cy`、普通的 `claude`、`codex` 或 `grok`，透過 `omarchy agent` 啟動的任何東西，以及在 `PATH` 上找到 CLI 的腳本或編輯器。使用 `omarchy agent account use work` 切換（再用 `omarchy agent account use main` 切回），或在面板中按下帳戶的數字再按 `Enter`（或點擊其 Use 按鈕）。執行中的 Claude 工作階段也會切換，從它們的下一則訊息開始：每個 Claude 工作階段都在 `~/.claude` 中執行，該目錄永遠持有使用中帳戶的登入資訊。由較舊 Omarchy 在帳戶自己的資料夾中啟動的 Claude 工作階段會保留該登入資訊直到退出，所以切換時會列出那些工作階段，並在它們消失後自行完成。執行中的 Codex 和 Grok 工作階段會留在它們啟動時的帳戶上。對話紀錄、設定、技能和插件在帳戶之間共用，所以在相同資料夾中執行 `claude --continue` 會在新帳戶上從你上次離開的地方接續。

有多個帳戶時，面板會並排顯示每個帳戶的限額，並標示使用中的一個。依預設，當使用中的帳戶超過限額的 95% 時，Omarchy 會通知你，點擊通知會切換到餘裕最多的帳戶。將游標停在面板中帳戶的那一行，點擊 Use 旁出現的 Autoswitch（或按 `m`），或執行 `omarchy agent account mode auto`，讓它改為自行切換；開啟時，Autoswitch 會取代 Use 的位置，再次點擊它會恢復為通知。加入數字可變更閾值，例如 `omarchy agent account mode auto 90`。如果每個帳戶都超過閾值，你會收到一次通知，並告知哪個帳戶最先釋出額度。當使用中帳戶距離其閾值在 15 個百分點以內時（預設為 80%），其限額會每三分鐘檢查一次，而非每 15 分鐘。

`omarchy agent account list` 顯示每個帳戶及其最新限額，`omarchy agent account remove work` 忘記一個帳戶，而 `omarchy agent account rename primary Hey` 重新命名一個帳戶（或在面板中點擊帳戶名稱）。這些指令作用於你預設 agent 的帳戶；若要存取其他供應商，請先指名它，例如 `omarchy agent account use codex side`。你已在 `~/.claude` 或 `~/.codex` 中的登入是 _Main_ 帳戶。Codex 的會留在原地；Claude 的在另一個帳戶使用時，會在它自己的資料夾中等候。閒置超過約八小時的帳戶可能顯示 _Sign-in required_；點擊它可直接在面板中重新登入該帳戶，或切換到它並啟動一個工作階段，這會自行更新登入資訊。你用 `claude mcp add` 加入的 MCP 伺服器會到達每個 Claude 帳戶，因為它們都在 `~/.claude` 中執行；對於 Codex 和 Grok，新增帳戶時你已有的伺服器會跟著過去，但之後加入的只會到達你加入它們的那個帳戶。Claude Desktop 保有它自己的登入，而以 CLI 二進位檔絕對路徑設定的 Codex 或 Grok 工具不會跟隨切換。明確的 `CLAUDE_CONFIG_DIR`、`CODEX_HOME` 或 `GROK_HOME` 優先於所選帳戶。

### 當機診斷

Omarchy 會透過 systemd-coredump 監看行程當機。當某個東西發生 segfault 時，你會收到 "Process crashed" 通知——點擊它，當機資訊會連同 Omarchy 的 diagnose-crash 技能交給你的預設 agent，該技能會引導 agent 從 core dump 確立事實，並判斷該當機是否值得向上游回報。你也可以用 `omarchy agent crash <pid>` 手動對 `coredumpctl list` 中的任何 PID 執行它。

此監看依預設開啟。在 _Trigger > Toggle > Crash Capture_ 下將其關閉（或使用 `omarchy toggle crash-capture`），通知就會停止；`omarchy agent crash <pid>` 仍可手動運作。

當機也可以一次針對一個程式靜音，這是診斷最後提供給你的選項。`omarchy crash mute hyprland` 只停止該程式的通知，`omarchy crash mute hyprland off` 將它們恢復，而單獨執行 `omarchy crash mute` 會列出你已靜音的項目。它接受二進位檔的路徑就跟接受名稱一樣樂意，所以 `omarchy crash mute /usr/bin/hyprland` 做的是同一件事。將含有空格的名稱用引號括起，例如 `omarchy crash mute 'Some App'`。其他一切仍會通知，且被靜音的程式仍會當機——這只是隱藏提醒，它不會修復任何東西。

### 桌面應用程式

_Install > AI_ 選單也包含幾個圖形化 AI 應用程式：ChatGPT 桌面應用程式、Claude 桌面應用程式（Anthropic 的 Linux beta，具備 Chat、Cowork 和 Claude Code 分頁）、用於與 xAI 模型聊天的 Grok Bot、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexity 桌面應用程式和 T3 Code。Grok Bot 是桌面聊天應用程式。程式設計 agent 則是 `grok` 指令。

Hermes Desktop 是你需要知道的那一個，因為一台機器只有一個 Hermes，而且它是該應用程式的：Hermes 只透過該應用程式安裝，而預設 agent 執行的 `hermes` 指令就是該應用程式的。選擇 Hermes 作為預設 agent，安裝的東西與 _Install > AI_ 項目安裝的相同：套件，以及由 Hermes 自己的安裝程式在 `~/.hermes` 下設定的 Hermes 執行環境，第一次需要幾分鐘。該執行環境就是終端機的 `hermes` 指令、預設 agent 和應用程式全都使用的那一個 Hermes，且它用 `hermes update` 自行更新，而非等待 Omarchy 發行。安裝它也會將 Omarchy 主題以名為 `omarchy` 的 skin 交給 Hermes，每個 Hermes 介面都會在你切換主題時跟著變；如果你不想這樣，在 Hermes 的 Appearance 設定下或用 `/skin` 選擇另一個，Omarchy 會尊重那個選擇。在 _Remove > AI_ 下移除該應用程式會先關閉 Hermes，包括 gateway，並將該執行環境一併帶走，且除非你另有指示，否則會保留你的聊天、記憶以及 Hermes 為自己撰寫的技能：它會詢問，預設為否，是否也要一併移除那些資料和你的連線設定。

OpenClaw 的桌面體驗是其 Control UI，它以網頁應用程式形式開啟，由自己的本機 gateway 支援。OpenClaw 住在 `~/.openclaw` 中並自行更新：使用 Control UI 的 "Update Gateway" 按鈕或執行 `openclaw update`，gateway 就會以新版本重新啟動。Omarchy 只選擇全新安裝從哪個版本開始。在 _Remove > AI_ 下移除 OpenClaw 會將 gateway 服務和應用程式一併帶走，然後詢問 `~/.openclaw` 是否也要移除，因為它存放了你的聊天和憑證，以及 OpenClaw 本身和它下載的插件執行環境；預設為保留它，再次安裝 OpenClaw 時會重新取用它。

Herdr Desktop 是 [Herdr](https://herdr.dev) 桌面應用程式：spaces、tabs 和 panes 中裝著終端機和程式設計 agent，當你關閉視窗時，它們會在其核心中持續執行。它來自 Herdr 自己的安裝程式而非套件，所以它住在 `~/.local/share/herdr-app`，當你尚沒有時，會在 `~/.local/bin/herdr-core` 一併帶來其核心，並自行更新兩者。它與 Omarchy 隨附在 `Super + Ctrl + Return` 上的 `herdr` 指令並存而非取代它，且取得該指令的直接按鍵：`Alt + Return` 和 `Alt + Shift + Return` 向下或向右分割 pane，`Alt + Escape` 關閉它，`Ctrl + Alt + Arrow` 在 pane 之間移動，`Alt + 1..9` 和 `Alt + Left/Right` 選擇 tab，而 `Alt + Up/Down` 在 space 之間移動。`Ctrl + 1..9` 選擇 space，而 `Alt + Shift + Up/Down` 逐個切換 agent。`Ctrl + Space` 前綴按鍵仍為終端機專用，因為該應用程式無法為了序列操作按住一個單純的 Ctrl 鍵。Omarchy 將這些寫入 `~/.config/herdr-app/keys.json`，而 `omarchy-refresh-herdr-app` 會將它們寫回。安裝它會選取 Herdr 的 Omarchy 主題，從此跟隨你的 Omarchy 主題。Herdr 為淺色模式保留一個主題、為深色模式保留一個，所以在深色和淺色 Omarchy 主題之間切換後，請在 Herdr 的主題選取器中再次為另一個模式選擇 Omarchy。

T3 Code 從位於 `~/.local/share/t3code` 的官方 AppImage 發行版本執行，而非從套件，所以它會自行更新。安裝時會詢問要從 Stable 還是 Nightly 頻道開始；之後可在 T3 Code 的設定中切換。你的討論串和設定住在 `~/.t3`，在 _Remove > AI_ 下移除 T3 Code 會將它們一併帶走。

### 本機模型

在你自己的機器上為你的程式設計 agent 執行開放模型。你的提示和程式碼留在機器上；送給模型的任何東西都不會離開它。從以下開始：

```bash
omarchy agent local use best
```

或者，在頂部欄的 agent 面板中，選擇 + 然後選 Local AI，當有模型適合這台機器時它會出現。第一次，這會安裝 Podman，它負責執行模型，在 NVIDIA 機器上還會安裝 NVIDIA 的 container toolkit，讓模型能使用 GPU。接著 Omarchy 會為這台機器挑選建議的模型、下載它並啟動它。預期下載數十 GB，且模型執行時機器的多數記憶體會被使用：Flash Next 在其完整的 256K context 下使用約 100 GiB。如果其他模型佔用了它需要的記憶體，它會以停止狀態完成設定，準備好在你停止其中一個後啟動。模型會在登出時停止；當你需要記憶體做其他事時，請自行停止它。

`omarchy agent local list` 顯示選項，並解釋為何有些不適合。若要設定另一個，請執行 `omarchy agent local use <recipe>`。目前，`qwen3.8-flash-next-gufo` 和 `qwen3.8-27b-gufo` 可用於 128 GB Strix Halo 機器；27B 佔約 40 GiB，所以會留出空間給其他工作。在配備 Intel 的 Arc B390 的 64 GB 筆記型電腦上，`qwen3.6-35b-a3b-llamacpp` 以約 30 GiB 執行。新 recipes 和建議會透過 `omarchy update` 以套件形式送達。

你設定的每個模型在 agent 面板中都有自己的一行，就在你的訂閱旁邊：play 用於啟動它，pause 用於停止它並釋放其記憶體，而終端機按鈕用於在它上面開啟你的 agent。當它們能一起放入記憶體時，多個可以同時執行；如果有一個放不下，Omarchy 會說明要停止哪個執行中的模型。拖曳各行重新排序，並在選取的一行上按 Delete 以移除模型及其下載。

你設定的每個模型在應用程式啟動器中也有自己的項目，位於模型名稱下並帶有其製造商的標誌，就像登入 Claude、Codex 或 Grok 會新增一個一樣。它會在該模型上開啟你的 agent，如果模型尚未執行，會先啟動模型：終端機會顯示它載入中，並在它就緒後交給 agent。移除模型會移除其項目。

模型會完全按照設定時的樣子持續執行，所以 Omarchy 更新永遠不會在你的 agent 底下重新啟動它。當 Omarchy 有更新的執行環境或更新的 weights 給你已設定的模型時，它的那一行會顯示更新按鈕：按下它，模型會在背景重新設定，只下載有變動的部分，並以新版本重新啟動。已停止的模型會保持停止。`omarchy agent local update` 從終端機對每個模型做同樣的事。

從命令列，`omarchy agent local start <recipe>` 和 `omarchy agent local stop <recipe>` 做同樣的事，`omarchy agent local status` 顯示每個模型，而 `omarchy agent --local` 在你最後啟動的模型上開啟你的預設 agent。pi、OpenCode 和 Qwen Code 可以使用其中一個；若預設是其他任何 agent，則會在 pi 中開啟。pi 也會在其自己的模型選取器中列出你設定的每個模型，以及在你已配對機器上的那些，所以普通的 `pi` 也能存取它們。任何與 OpenAI 相容的用戶端也能連接：`status` 顯示每個模型的位址（第一個是 `http://127.0.0.1:11435/v1`），recipe 名稱就是模型，而金鑰在 `~/.config/omarchy/agent-local/key` 中。

`omarchy agent local remove <recipe>` 會刪除模型以及沒有其他模型使用的下載。

第三方執行環境會標示其發行者。Omarchy 在沒有網路存取的情況下執行每個模型。

### 本機 LLM

Omarchy 推薦兩種執行本機 LLM 模型的方式：LM Studio 和 Ollama。LM Studio 提供 GUI 介面來尋找 open-weight 模型、安裝它們並執行它們。這是輕鬆上手的絕佳方式。Ollama 提供 CLI 以類似方式做到這一點。但如果你是本機模型新手，我會從 LM Studio 開始。你可以在 Omarchy Menu 的 _Install > AI_ 下安裝任一個。

### Omarchy Skill

Agent 技能幫助 AI 以特定方式使用特定工具，而 Omarchy 隨附一個預設技能用於量身打造系統。就像調整你的 Hyprland 設定、調整頂部欄，甚至從頭建立新主題。它已符號連結至 Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` 以及每個 `~/.hermes/profiles/*/skills`）的技能目錄，以及通用的 `~/.agents/skills` 位置，所以大多數 harness 會自動取用它。

但你應將此技能視為實驗性。不同模型使用它會有不同效果。最好先在 plan mode 中執行，這樣你能了解 agent 想要變更什麼。然後準備好回復變更，甚至執行 `omarchy reinstall configs`，如果 agent 把一切搞得一團糟。
