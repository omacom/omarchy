### 安裝與更新 Agent

除了 Hermes 與 OpenClaw 之外，這些 Agent 都使用 mise 的延遲安裝：首次啟動時安裝 CLI，後續啟動則重複使用它。mise 也會最多每四小時檢查一次已安裝的 Agent 是否有新版本，檢查時機就在它啟動之前，或在 shell 提示符下於背景執行。如果該更新失敗或你離線，就會執行已安裝的版本。`omarchy update` 會將已安裝的 Agent 與 Omarchy 的其餘部分一併更新，而 `mup` 僅更新由 mise 管理的工具。

Agent 自己的更新程式，例如 `claude update`、`codex update`，或應用程式中的更新按鈕，不會更新由 mise 管理的安裝。`codex update` 會失敗，而 `claude update` 可能會回報成功，卻安裝了 mise 未追蹤的另一份副本。如果你寧願使用 Agent 原生的安裝程式與更新程式，請將它加入 `disable_tools`；詳見 [預先安裝的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

若要在需要之前安裝所有已設定的延遲工具，請執行 `mise install --include-lazy`。這包括 Omarchy 的其他預設 CLI 工具以及這些 Agent。關於安裝單一工具或使用你自己的安裝，請參閱 [預先安裝的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

`grok` 是透過 mise 的第一方 `grok` 套件安裝，與 `claude` 和 `codex` 的方式相同。執行 `grok`，或在 Agents 面板中為它加上星號。跳過 x.ai 上的 `curl | bash` 安裝程式。那條路徑會在 `~/.grok/bin` 放入第二份副本、將它前置於 `PATH`，並覆寫 Omarchy 的包裝器。

`dsh` 會在 `127.0.0.1:3080` 開啟其瀏覽器 UI，並以啟動目錄作為其預設工作區。其瀏覽器 UI 不接受起始提示，因此 `omarchy agent prompt` 開啟它時會將提示放在你的剪貼簿中供你貼上。Omarchy 會以 DeepSeek 的無需核准權限預設集啟動它。當你使用其官方模型 API 時，DeepSeek Harness 會將工作階段記錄上傳至 DeepSeek；請在其瀏覽器 UI 的 _Settings > General > Upload Session Log_ 下將其關閉。你傳送給它的意見回饋也會連同工作階段一併上傳，除非你以 `DSH_TELEMETRY_MODE=DISABLED` 啟動它。

### 預設 Agent

你可以使用 Agents 面板中 Agent 旁邊的星號來選擇你的預設 Agent，預設者上的星號會填滿，或使用 `omarchy default agent <name>`，後者也可接受任何在那裡沒有一列的 harness。如果該 Agent 尚未安裝，選擇它會先將其安裝，而且它還會在應用程式啟動器中取得自己的啟動器，位於 Agent 旁邊。全新的 Omarchy 會以一次性通知邀請你設定一個，該通知會開啟 Agents 面板。

選擇 Claude 也會嘗試為 Chromium、Chrome、Brave、Brave Origin 以及 Edge 設定其瀏覽器擴充功能。該擴充功能設定適用於所有使用者，且可能會要求你的系統密碼；取消或擴充功能安裝失敗，仍會選取並啟動 Claude。重新啟動你的瀏覽器，如有提示請啟用該擴充功能，並登入 Claude 以完成連接。在 Claude 中執行 `/chrome` 以檢查連接。Firefox 與 Zen 不支援此擴充功能。如果在加入此設定之前 Claude 已是你的預設值，請再次選取它以安裝該擴充功能。

一旦你已選擇，`Super + Shift + Ctrl + A` 就會在專用的終端機視窗中啟動預設 Agent（或者如果你尚未選擇，則會開啟選擇器）。你也可以用 `omarchy agent prompt "Review this project"` 直接讓它進入一項任務。Freebuff 與 DeepSeek Harness 不接受起始提示，因此它們會改為將提示放在你的剪貼簿中開啟，供你貼上。以這種方式啟動的 Agent 會在各自「不要停下來詢問」的模式下無人看管地執行，所以請做好它們真的會動手做事的準備！MiniMax Code 的互動式工作階段沒有這種模式，因此它會照常要求權限。而且由於 Agent 拒絕記住對你家目錄的信任，因此從 `$HOME` 啟動時會改為在 `~/Work` 中開始。

還有終端機快捷方式：`a` 會在目前的終端機中內嵌執行預設 Agent，而 `c`、`cx` 和 `cy` 則會直接啟動 OpenCode、Claude Code 與 Codex（同樣在其自動核准模式下）。主題變更也會同步至 Agent：當你切換 Omarchy 主題時，Claude Code、Pi、OpenCode 以及 Hermes（一旦 Omarchy 已安裝它）都會一同跟隨。

### 你的 Agent 指示

適用於每個 Agent 的個人規則放在 `~/.agents/AGENTS.md`，位於 `~/.agents/skills` 中共享技能的旁邊。你可以使用 Agents 面板中 + 旁邊的文件圖示開啟它，或使用 `omarchy agent instructions --edit`，後者也會將它連結至每個保留其專屬全域檔案的 harness：`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`~/.pi/agent/AGENTS.md`、`~/.config/opencode/AGENTS.md`、Copilot 的 `~/.copilot/copilot-instructions.md`，依此類推。Crush 與 Amp 讀取 `~/.config/AGENTS.md` 連結，而 omp、Kimi 與 DeepSeek Harness 則直接讀取 `~/.agents/AGENTS.md`。選擇預設 Agent 也會連結它。如果你已有指示檔案且尚無共享檔案，它就會成為共享檔案；否則它會以 `.bak` 形式保留在連結旁邊。安裝另一個 Agent 後，請執行 `omarchy agent instructions` 以重新連結。

### Agents 面板

頂部列有一個 Agents 圖示。在你設定 Agent 之前，其面板提供三種開始方式：登入 Claude、Codex、Grok、Gemini、Muse、Cursor 或 Copilot 訂閱，或在 More 下登入 OpenCode Go、MiniMax、Synthetic 或 Z.ai 程式編寫方案；使用 Fireworks、OpenCode Zen 與 Go、OpenRouter 用多少付多少，或在 More 下使用 DeepSeek 或 OpenCode 可登入的任何其他供應商，全部都在 OpenCode 中執行；或在有適合的模型時，執行最適合你電腦的模型。你完成的第一個會成為你的預設 Agent，而面板中的 +，或 Omarchy Menu 中的 _Agent > Add_，之後也會提供同樣的三種方式。之後，該面板會將每個訂閱放在同一頁上：每個 Agent 與帳號連同其方案、其 5 小時工作階段與每週限制各自的計量表與距離重設的時間（將滑鼠懸停以查看確切百分比），或剩餘的預付餘額，都位於一行輪替文字下方，該行會輪替顯示你在所有這些項目中的使用情況，例如本週的 token 以及你最常使用的模型。在 _Make something cool_ 下，它提供新主題、外掛程式、應用程式或遊戲的起始提示，將任務交給你的預設 Agent。應用程式的建構方式與 Omarchy 自己的 Hype、Monologue 與 Omacut 相同，使用 C++ 與 Qt Quick，遵循 omarchy-make-app Agent 技能，而且它們所需的編譯器與 Qt 元件都已隨附安裝。遊戲是位於 `~/Games/vibes` 的單一 three.js 頁面，遵循 omarchy-make-game Agent 技能，而且全部都從目前主題中的同一個 Game Vibes 啟動器開啟；它們會從網路載入 three.js，因此啟動時需要連線。Claude Code、Codex、Grok、Kimi、Cursor 及其 Grok Bot 額度、GitHub Copilot、Muse、Gemini（透過 Antigravity）以及 Devin 開箱即涵蓋其限制，Kimchi 則涵蓋其方案、預付點數與支出預算，而 Hermes、Mistral Vibe 與 Qwen Code 會在你使用它們後顯示其工作階段與 token。你透過 pi、omp 或 opencode 使用的供應商方案與金鑰也會顯示：OpenCode Zen 與 Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan 以及 Synthetic 連同其限制；OpenRouter 與 DeepSeek 連同其預付餘額；Fireworks 連同其過去 30 天的支出。你在自己硬體上執行的模型所產生的 token 也會計入總數；模型本身有其專屬面板，詳述於 [本機模型](#local-models)。每個 Agent 都只計算一次，歸於向你收費的一方，無論你透過多少個 harness 驅動它。

以左鍵按一下列上的圖示或按下 `Super + Ctrl + X` 可開啟面板，以右鍵按一下可啟動你的預設 Agent，以中鍵按一下可重新整理。其背後的使用記錄會由 `omarchy agent usage update` 每 15 分鐘重新產生，而且該面板甚至可以透過已同步的資料夾合併來自你其他機器的使用情況。完整的設定請參閱 `$OMARCHY_PATH/shell/plugins/agents/` 下的 README。

### 多個訂閱

如果你付費訂閱了不只一個 Claude、Codex 或 Grok 方案——例如一個個人 Max 與一個工作用的——Omarchy 可以讓它們全部保持登入，並在它們之間切換。使用 Agents 面板中的 + 新增訂閱，它會直接在那裡引導你完成，或使用 `omarchy agent account add claude Work`（或 `codex`，或 `grok`）。同樣的 + 與指令可登入 Gemini（`gemini`）與 OpenCode（`opencode`），並在 OpenCode 中儲存 Fireworks（`fireworks`）或 OpenRouter（`openrouter`）API 金鑰；該指令也可登入 Copilot（`copilot`）、Cursor（`cursor`）以及 Muse（`muse`）。那些各自只保留一個登入。如果缺少 CLI，它會將其安裝。某個供應商的第一個帳號會透過你的一般瀏覽器登入，就在 CLI 一直查看的位置。此後的每一個都會透過隱私視窗登入，因此你瀏覽器已登入的帳號就不會被誤選；在那裡以你要新增的帳號登入，並先關閉你已開啟的任何隱私視窗。切勿為此登出 CLI：登出會撤銷已儲存的登入，而該帳號將必須重新新增。

若要透過 SSH 將你的訂閱登入複製到另一台 Omarchy 機器，請執行 `omarchy agent account copy user@laptop`。當目的地未安裝接收器時，傳送方會提供一個暫時接收器，因此較舊的 Omarchy 機器無需更新即可接收帳號。已安裝的接收器優先。這會複製所有 Claude、Codex 與 Grok 訂閱；加入供應商名稱以選取它們，例如 `omarchy agent account copy laptop claude`。帳號名稱與指令 ID 會與來源相符，包括目的地已存在的帳號。無關的目的地帳號如果名稱衝突，會收到數字後綴，而設定、技能、外掛程式與對話記錄則保留在每台機器的本機。

目的地現有的憑證會保留。已在那裡登入的來源帳號會同步其名稱，但不會取代其憑證；其他帳號則會新增在其旁邊。若要取代相符帳號已儲存的憑證，請在結束目的地上的該帳號工作階段後，使用 `omarchy agent account copy --replace laptop claude`。全新的目的地還會取得來源的使用中帳號與切換偏好設定；已建立的目的地則保留自己的。

憑證會透過 SSH 傳送，並儲存在目的地上的私有檔案中，因此請僅複製到你信任的機器。這是一次性複製，而非持續同步。Codex 的重新整理 token 可能會被另一台機器輪替，導致複製的登入需要更新；在多台機器上同時使用時，分開登入仍是最可靠的選擇。請參閱 [Codex 的帳號驗證指南](https://developers.openai.com/codex/auth/ci-cd-auth)。

每個供應商有一個使用中的帳號，而且每個新工作階段都以它開始：`cx`、`cy`、普通的 `claude`、`codex` 或 `grok`、透過 `omarchy agent` 啟動的任何東西，以及在 `PATH` 上找到 CLI 的指令碼或編輯器。使用 `omarchy agent account use work` 切換（並以 `omarchy agent account use main` 切換回來），或在面板中按下帳號的數字然後按下 `Enter`（或按一下其星號）。正在執行的 Claude 工作階段也會切換，從它們的下一則訊息開始：每個 Claude 工作階段都在 `~/.claude` 中執行，該處永遠保存使用中帳號的登入。由較舊的 Omarchy 在帳號專屬資料夾中啟動的 Claude 工作階段會保留該登入，直到它結束為止，因此切換會列出那些工作階段的名稱，並在它們消失後自行完成。正在執行的 Codex 與 Grok 工作階段會停留在它們開始時所用的帳號上。對話記錄、設定、技能與外掛程式在帳號之間共享，因此在同一個資料夾中的 `claude --continue` 會以新帳號接續你離開的地方。

有不只一個帳號時，面板會並排顯示每個帳號的限制，使用中的那個會有填滿的星號。當使用中帳號超過限制的 95% 時，Omarchy 會通知你，而按一下該通知會切換至餘裕最大的帳號。它永遠不會自行切換。使用 `omarchy agent account threshold 90` 變更閾值。如果每個帳號都超過閾值，你會收到一次通知，同時得知哪個帳號最先釋出。當使用中帳號距離其閾值在 15 個百分點以內（預設為 80%）時，其限制會每三分鐘檢查一次，而非每 15 分鐘。

`omarchy agent account list` 會顯示每個帳號及其最新限制，`omarchy agent account remove work` 會忘記一個帳號，而 `omarchy agent account rename primary Hey` 會重新命名一個帳號（或在面板中按一下帳號的名稱）。這些指令作用於你的預設 Agent 的帳號；若要存取其他供應商，請先命名它，例如 `omarchy agent account use codex side`。你已在 `~/.claude` 或 `~/.codex` 中擁有的登入是 _Main_ 帳號。Codex 的會留在原處；Claude 的則在另一個帳號使用期間，等待在其專屬的資料夾中。閒置超過約八小時的帳號可能會顯示 _Sign-in required_；按一下它即可直接在面板中再次登入該帳號，或切換至它並開始一個工作階段，這會自行重新整理登入。你以 `claude mcp add` 新增的 MCP 伺服器可供每個 Claude 帳號使用，因為它們全都在 `~/.claude` 中執行；對於 Codex 與 Grok，在新增帳號時你已有的伺服器會隨之而來，但之後的伺服器僅可供你新增它們的那個帳號使用。Claude Desktop 保留其專屬的登入，而以 CLI 二進位檔的絕對路徑設定的 Codex 或 Grok 工具不會跟隨切換。明確的 `CLAUDE_CONFIG_DIR`、`CODEX_HOME` 或 `GROK_HOME` 優先於所選的帳號。

### 崩潰診斷

Omarchy 會監看 systemd-coredump 以偵測程序崩潰。一旦你已選擇預設 Agent，你的任何程式傾印核心時都會帶來一個 "Process crashed" 通知——按一下它，崩潰就會連同 Omarchy 的 omarchy-diagnose-crash 技能一併交給你的預設 Agent，該技能會引導 Agent 從核心傾印中確立事實，並決定該崩潰是否值得向上游回報。你也可以使用 `omarchy agent crash <pid>`，手動針對 `coredumpctl list` 中的任何 PID 執行它。

此監看預設開啟。在 _Trigger > Toggle > Crash Capture Off_ 下將其關閉（或使用 `omarchy toggle crash-capture`），通知就會停止；`omarchy agent crash <pid>` 仍可手動運作。

崩潰也可以一次靜音一個程式，這正是診斷在最後提供給你的功能。`omarchy crash mute hyprland` 僅停止該程式的通知，`omarchy crash mute hyprland off` 會將它們恢復，而單獨的 `omarchy crash mute` 會列出你已靜音的項目。它接受二進位檔的路徑就如同接受其名稱一樣自在，因此 `omarchy crash mute /usr/bin/hyprland` 會做同樣的事情。將含有空格的名稱加上引號，例如 `omarchy crash mute 'Some App'`。其他一切仍會通知，而被靜音的程式仍會崩潰——這只是隱藏提醒，並不會修復任何東西。

### 桌面應用程式

_Install > AI_ 選單也包含一些圖形化 AI 應用程式：Amp Desktop、Antigravity Desktop、ChatGPT 桌面應用程式、Claude 桌面應用程式（Anthropic 的 Linux beta，含有 Chat、Cowork 與 Claude Code 分頁）、用於與 xAI 模型聊天的 Grok Bot、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexity 桌面應用程式，以及 T3 Code。Grok Bot 是桌面聊天應用程式。程式編寫 Agent 則是 `grok` 指令。

Hermes Desktop 是需要了解的那一個，因為一台機器只有一個 Hermes，而且它是屬於該應用程式的：Hermes 永遠僅透過該應用程式安裝，而預設 Agent 執行的 `hermes` 指令也是該應用程式的。選擇 Hermes 作為預設 Agent 會安裝與 _Install > AI_ 項目相同的東西：該套件，以及由 Hermes 自己的安裝程式設定、位於 `~/.hermes` 下的 Hermes 執行環境，首次需花費幾分鐘。該執行環境就是終端機 `hermes` 指令、預設 Agent 與該應用程式全都使用的那一個 Hermes，而且它會以 `hermes update` 自行更新，而非等待 Omarchy 發行。安裝它也會將 Omarchy 主題作為名為 `omarchy` 的外觀交給 Hermes，每個 Hermes 介面都會在你切換主題時跟隨；如果你寧願它不要跟隨，請在 Hermes 的 Appearance 設定下或以 `/skin` 選取另一個，而 Omarchy 會尊重那個選擇，不加干預。在 _Remove > AI_ 下移除該應用程式會先關閉 Hermes（包括閘道）、將該執行環境一併移除，並保留你的聊天、記憶以及 Hermes 為自己編寫的技能，除非你另有指示：它會詢問該資料與你的連接設定是否也應一併移除，預設為否。

OpenClaw 的桌面體驗是其 Control UI，它會以由其專屬本機閘道支援的網頁應用程式形式開啟。OpenClaw 位於 `~/.openclaw` 並會自行更新：使用 Control UI 的「Update Gateway」按鈕或執行 `openclaw update`，閘道就會以新版本重新啟動。Omarchy 僅選擇全新安裝從哪個版本開始。OpenClaw 也可以是你的預設 Agent：在 _Agent > Harness_ 下選擇它會在 `~/.openclaw` 中設定同一份副本，而且該 Agent 會開啟連接至其閘道的 OpenClaw 終端機 UI。在 _Remove > AI_ 下移除 OpenClaw 會將閘道服務與該應用程式一併移除，然後詢問 `~/.openclaw` 是否也應移除，因為那裡保存著你的聊天與憑證，以及 OpenClaw 本身與它下載的外掛程式執行環境；預設會保留它，而再次安裝 OpenClaw 會將它重新接回。

Herdr Desktop 是 [Herdr](https://herdr.dev) 桌面應用程式：由空間、分頁與窗格組成的終端機與程式編寫 Agent，即使你關閉視窗，它們仍會在其核心中持續執行。它來自 Herdr 自己的安裝程式而非套件，因此它位於 `~/.local/share/herdr-app`，當你尚無其核心時會將核心一併帶來放在 `~/.local/bin/herdr-core`，並且兩者都會自行更新。它位於 Omarchy 隨附於 `Super + Ctrl + Return` 的 `herdr` 指令旁邊，而非取代它，並取得該指令的直接按鍵：`Alt + Return` 與 `Alt + Shift + Return` 會向下或向右分割窗格，`Alt + Escape` 會關閉它，`Ctrl + Alt + Arrow` 會在窗格之間移動，`Alt + 1..9` 與 `Alt + Left/Right` 會選取分頁，而 `Alt + Up/Down` 會在空間之間移動。`Ctrl + 1..9` 會選取空間，而 `Alt + Shift + Up/Down` 會依序切換 Agent。`Ctrl + Space` 前綴按鍵仍僅供終端機使用，因為該應用程式無法按住一個普通的 Ctrl 鍵來組成序列。Omarchy 會將這些寫入 `~/.config/herdr-app/keys.json`，而 `omarchy-refresh-herdr-app` 會將它們放回。安裝它會選取 Herdr 的 Omarchy 主題，從那時起它會跟隨你的 Omarchy 主題。Herdr 為淺色模式保留一個主題、為深色模式保留另一個，因此在深色與淺色 Omarchy 主題之間切換後，請在 Herdr 的主題選擇器中再次為另一個模式選取 Omarchy。

T3 Code 從位於 `~/.local/share/t3code` 的其官方 AppImage 發行版本執行，而非從套件執行，因此它會自行更新。安裝它會詢問要從 Stable 還是 Nightly 通道開始；之後可在 T3 Code 的設定中切換。你的討論串與設定位於 `~/.t3`，而在 _Remove > AI_ 下移除 T3 Code 會將它們一併移除。

### 本機模型

在你自己的機器上為你的程式編寫 Agent 執行開放模型。你的提示與程式碼會保留在機器上；傳送給模型的任何東西都不會離開它。從以下開始：

```bash
omarchy models use best text
```

這會為這台機器設定最佳的文字模型，也就是你的 Agent 所使用的那種。影像、影片與音樂模型各自有其最佳選擇：`omarchy models use best image`、`video` 或 `music`。執行 `omarchy models use best` 以查看每種種類為這台機器所選的模型。

或者從頂部列中 Agents 圖示旁邊的閃耀圖示開啟本機模型面板，或使用 Super + Ctrl + Alt + X，然後選擇 +。當有模型適合這台機器時，該圖示就會出現。執行模型的 Podman 隨 Omarchy 附帶，在 NVIDIA 機器上 NVIDIA 的容器工具包亦然，它讓模型能使用 GPU；如果其中任一缺少，首次設定會將其安裝。然後 Omarchy 會為這台機器選取推薦的模型、下載它並啟動它。請預期會有數十 GB 的下載，而且在模型執行期間機器的多數記憶體都會被使用：Flash Next 在其完整的 256K 上下文下會使用約 100 GiB。如果其他模型佔用了它所需的記憶體，它會以停止狀態完成設定，等你停止其中一個後即可啟動。該模型會在登出時停止；當你需要將記憶體用於其他用途時，請自行停止它。

`omarchy models list` 會顯示選項並解釋為何有些不適合。若要設定另一個，請執行 `omarchy models use <recipe>`。目前，`qwen3.8-flash-next-gufo` 與 `qwen3.8-27b-gufo` 可用於 128 GB 的 Strix Halo 機器；27B 會佔用約 40 GiB，因此會留下空間給其他工作。在配備 Intel 的 Arc B390 的 64 GB 筆記型電腦上，`qwen3.6-35b-a3b-llamacpp` 會在約 30 GiB 下執行。新的配方與建議會透過套件隨 `omarchy update` 送達。

你設定的每個模型在本機模型面板中都有其專屬的一列：播放可啟動它，暫停可停止它並釋放其記憶體，而終端機按鈕可在它上面開啟你的 Agent。頂部有一條列顯示機器的記憶體如何在 Omarchy 本身（系統與你的應用程式）、每個執行中的模型以及可用空間之間分配。指向一個已停止的模型，該列就會顯示它是否適合，或還差多少。多個模型可以在記憶體能同時容納它們時一同執行；如果有一個不適合，Omarchy 會說明要停止哪個執行中的模型。拖曳各列的標誌以重新排序，並在選取的一列上按下 Delete 以移除模型及其下載。

你設定的每個程式編寫模型也都會在應用程式啟動器中取得其專屬項目，位於該模型的名稱下並帶有其製作者的標誌，就如同登入 Claude、Codex 或 Grok 會新增一個一樣。它會在該模型上開啟你的 Agent，而且如果模型尚未執行，會先啟動模型：終端機會顯示它正在載入，並在它就緒後交給 Agent。移除模型會移除其項目。

並非每個模型都是用於程式編寫。影像、影片與音樂模型改為在 Fantasi 中開啟，那是 Omarchy 用於以在這台機器上執行的模型製作圖片、影片與音樂的應用程式，可在那裡選取，或從它們在本機模型面板中的那一列選取。

模型會完全按照其設定方式持續執行，因此 Omarchy 更新永遠不會在你的 Agent 底下重新啟動它。當 Omarchy 為你已設定的模型提供較新的執行環境或較新的權重時，它的那一列會顯示更新按鈕：按下它，該模型就會在背景重新設定，僅下載已變更的部分，並以新版本重新啟動。已停止的模型會保持停止。`omarchy models update` 會從終端機對每個模型做同樣的事情。

從指令行，`omarchy models start <recipe>` 與 `omarchy models stop <recipe>` 會做同樣的事情，`omarchy models status` 會顯示每個模型，而 `omarchy agent --local` 會在 pi 中開啟你最後啟動的模型，無論你的預設 Agent 是什麼。若要讓該模型成為 Agent 快捷鍵、Quake 主控台與 _Make something_ 所開啟的對象，請執行 `omarchy default agent local` 或在 _Agent > Harness_ 下選取 _Local model_。pi 也會在其自己的模型選擇器中列出你已設定的每個模型，以及你已配對的機器上的模型，因此普通的 `pi` 也可以存取它們。任何與 OpenAI 相容的用戶端也可以連接：`status` 會顯示每個模型的位址（第一個是 `http://127.0.0.1:11435/v1`），配方名稱即是模型，而金鑰位於 `~/.config/omarchy/agent-local/key`。

`omarchy models remove <recipe>` 會刪除模型以及沒有其他模型使用的下載。

第三方執行環境會標示其發行者。Omarchy 執行每個模型時都不提供網路存取。

### 本機 LLM

Omarchy 推薦兩種執行本機 LLM 模型的方式：LM Studio 與 Ollama。LM Studio 提供 GUI 介面，用於尋找開放權重模型、安裝它們並執行它們。這是輕鬆上手的好方法。Ollama 提供 CLI 以類似方式做到這一點。但如果你是本機模型的新手，我會從 LM Studio 開始。你可以在 Omarchy Menu 的 _Install > AI_ 下安裝其中任一者。

### Omarchy 技能

Agent 技能可協助 AI 以特定方式使用特定工具，而 Omarchy 隨附其中七個。omarchy 技能涵蓋量身打造系統，例如調整你的 Hyprland 設定或調整列。omarchy-make-theme、omarchy-make-plugin、omarchy-make-app 以及 omarchy-make-game 涵蓋製作新事物，omarchy-contribute 涵蓋回報錯誤或向上游傳送修正，而 omarchy-diagnose-crash 則處理崩潰的核心傾印。它們已以符號連結放入 Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` 與每個 `~/.hermes/profiles/*/skills`）的技能目錄，以及通用的 `~/.agents/skills` 位置，因此多數 harness 都會自動選取它們。你自己擁有的同名技能資料夾優先。

但你應該將這些技能視為實驗性質。不同的模型會以不同的效果使用它。最好先在規劃模式下執行，這樣你能了解 Agent 想要變更什麼。然後，如果 Agent 把一切搞得一團糟，請做好回滾變更、甚至執行 `omarchy reinstall configs` 的準備。
