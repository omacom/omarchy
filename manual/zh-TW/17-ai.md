### 安裝與更新代理

Hermes 除外，這些代理使用 mise 的延遲安裝：首次啟動時安裝 CLI，之後的啟動則重複使用它。mise 也會檢查已安裝的代理是否有新版本，最多每四小時一次，就在它啟動之前，或在背景於 shell 提示字元處進行。如果該更新失敗或你處於離線狀態，就會運行已安裝的版本。`omarchy update` 會連同 Omarchy 的其他部分一起更新已安裝的代理，而 `mup` 只更新由 mise 管理的工具。

代理自己的更新程式，例如 `claude update`、`codex update`，或應用程式中的更新按鈕，不會更新由 mise 管理的安裝。`codex update` 會失敗，而 `claude update` 可能回報成功，卻安裝了一個 mise 不追蹤的獨立副本。如果你寧願使用代理原生的安裝程式和更新程式，請將它加入 `disable_tools`；請參閱 [Preinstalled CLI tools](18-development-tools.md#preinstalled-cli-tools)。

若要在需要之前安裝所有已設定的延遲工具，請執行 `mise install --include-lazy`。這包括 Omarchy 的其他預設 CLI 工具以及這些代理。關於安裝單一工具或使用你自己的安裝方式，請參閱 [Preinstalled CLI tools](18-development-tools.md#preinstalled-cli-tools)。

`grok` 是透過 mise 官方的 `grok` 套件安裝的，與 `claude` 和 `codex` 相同。請執行 `grok`，或在 _Setup > Defaults > Agent_ 下選取它。跳過 x.ai 上的 `curl | bash` 安裝程式。那條路徑會在 `~/.grok/bin` 放入第二個副本，將它加到 `PATH` 的最前面，並覆寫 Omarchy 的包裝程式。

`dsh` 會在 `127.0.0.1:3080` 開啟其瀏覽器 UI，並以啟動目錄作為其預設工作區。它的瀏覽器 UI 不接受起始提示，所以 `omarchy agent prompt` 會開啟它，並將提示放在你的剪貼簿上供你貼上。Omarchy 會以 DeepSeek 的免核准權限預設集啟動它。當你使用 DeepSeek 官方的模型 API 時，DeepSeek Harness 會將工作階段記錄上傳至 DeepSeek；在其瀏覽器 UI 的 _Settings > General > Upload Session Log_ 下關閉該功能。你傳送給它的意見回饋也會連同工作階段一起上傳，除非你以 `DSH_TELEMETRY_MODE=DISABLED` 啟動它。

### 預設代理

使用 `omarchy default agent <name>`，或在 Omarchy Menu（`Super + Space`）的 _Setup > Defaults > Agent_ 下，選取你的預設代理。如果該代理尚未安裝，選取它會先將其安裝。全新的 Omarchy 會以一次性通知邀請你做出這個選擇。

選擇 Claude 也會嘗試為 Chromium、Chrome、Brave、Brave Origin 和 Edge 設定其瀏覽器擴充功能。擴充功能設定適用於所有使用者，且可能要求你的系統密碼；取消或擴充功能安裝失敗，仍然會選取並啟動 Claude。重新啟動你的瀏覽器，如有提示則啟用該擴充功能，並登入 Claude 以完成連接。在 Claude 中執行 `/chrome` 來檢查連線。Firefox 和 Zen 不支援這個擴充功能。如果在加入這項設定之前 Claude 就已經是你的預設值，請再次選取它以安裝該擴充功能。

一旦你做出選擇，`Super + Shift + Ctrl + A` 會在專用的終端機視窗中啟動預設代理（或者如果你尚未選擇，則會開啟選取器）。你也可以使用 `omarchy agent prompt "Review this project"` 直接讓它進入一項任務。Freebuff 和 DeepSeek Harness 不接受起始提示，所以它們會改為開啟並將提示放在你的剪貼簿上供你貼上。以這種方式啟動的代理會在各自「不要停下來詢問」的模式下無人值守地運行，所以請做好它們真的會動手做事的準備！MiniMax Code 的互動式工作階段沒有這種模式，所以它會照常要求權限。而且由於代理拒絕記住對你家目錄的信任，從 `$HOME` 啟動時會改在 `~/Work` 中開始。

也有終端機捷徑：`a` 會在目前的終端機中內嵌運行預設代理，而 `c`、`cx` 和 `cy` 則直接啟動 OpenCode、Claude Code 和 Codex（同樣在其自動核准模式下）。主題變更也會同步到代理：Claude Code、Pi、OpenCode 和 Hermes（一旦 Omarchy 已安裝它）在你切換 Omarchy 主題時都會跟著變更。

### 代理面板

頂端列有一個代理圖示。在你設定代理之前，其面板會引導你登入 Claude、Codex 或 Grok，而第一個會成為你的預設代理。之後，該面板會將每個訂閱放在同一頁上：每個代理和帳戶連同其方案、其 5 小時工作階段和每週上限各自的計量表以及距離重設的時間（將滑鼠懸停以查看確切百分比），或剩餘的預付餘額，位於一行會輪流顯示你所有代理使用情況的文字下方，例如本週的 token 和你最常用的模型。在 _Make something_ 下，它會提供用於新主題、外掛程式或應用程式的起始提示，並將任務交給你的預設代理。應用程式的建置方式與 Omarchy 自己的 Hype、Monologue 和 Omacut 相同，使用 C++ 和 Qt Quick，遵循 omarchy-app 代理技能，而它們所需的編譯器和 Qt 元件都會隨附安裝。Claude Code、Codex、Grok、Kimi、Cursor 及其 Grok Bot 額度、GitHub Copilot、Muse、Antigravity、Kimchi 和 Devin 開箱即用就涵蓋其上限，而 Hermes、Mistral Vibe 和 Qwen Code 一旦你使用過它們，就會顯示其工作階段和 token。你透過 pi、omp 或 opencode 使用的供應商方案和金鑰也會顯示：OpenCode Zen 和 Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan 和 Synthetic 連同其上限；Fireworks、OpenRouter 和 DeepSeek 連同其預付餘額；以及你在自己的硬體上運行、位於「本機模型」下的模型。每個代理只計算一次，歸於向其收費的一方，無論你透過多少個 harness 驅動它。

左鍵點擊列圖示開啟面板，右鍵點擊則啟動你的預設代理。其背後的使用記錄每 15 分鐘由 `omarchy agent usage-update` 重新產生，而該面板甚至可以透過已同步的資料夾合併你其他機器上的使用情況。完整的設定請參閱 `$OMARCHY_PATH/shell/plugins/agents/` 下的 README。

### 多個訂閱

如果你付費購買了不止一個 Claude、Codex 或 Grok 方案——例如一個個人 Max 和一個工作用的——Omarchy 可以讓它們全部保持登入狀態，並在它們之間移動。使用代理面板中的 + 新增訂閱，它會直接在那裡引導你完成，或使用 `omarchy agent account add claude Work`（或 `codex`，或 `grok`）。如果缺少 CLI，它會將其安裝。某個供應商的第一個帳戶會透過你的一般瀏覽器登入，就在 CLI 一直查看的位置。之後的每一個都會透過私人視窗登入，所以你的瀏覽器已經登入的帳戶不會被誤選；在那裡以你正在新增的帳戶登入，並且先關閉你已開啟的任何私人視窗。絕不要為此登出 CLI：登出會撤銷已儲存的登入，而該帳戶將必須再次新增。

若要透過 SSH 將你的訂閱登入複製到另一台 Omarchy 機器，請執行 `omarchy agent account copy user@laptop`。當目的地未安裝接收器時，傳送方會提供一個臨時接收器，所以較舊的 Omarchy 機器無需更新即可接收帳戶。已安裝的接收器優先。這會複製所有 Claude、Codex 和 Grok 訂閱；加入供應商名稱以選取它們，如在 `omarchy agent account copy laptop claude` 中。帳戶名稱和指令 ID 與來源相符，包括目的地已存在的帳戶。無關的目的地帳戶如果名稱衝突，會收到數字後綴，而設定、技能、外掛程式和對話歷史會保留在每台機器本機。

現有的目的地憑證會保留。已經在那裡登入的來源帳戶會同步其名稱，但不取代其憑證；其他帳戶會新增在其旁邊。若要取代相符帳戶已儲存的憑證，請在結束目的地該帳戶的工作階段後，使用 `omarchy agent account copy --replace laptop claude`。全新目的地也會取得來源的作用中帳戶和切換偏好；已建立的目的地則保留其自己的。

憑證透過 SSH 傳輸，並儲存在目的地上的私人檔案中，所以只複製到你信任的機器。這是一次性複製，不是持續同步。Codex 更新權杖可能由另一台機器輪替，使複製的登入需要續訂；在多台機器上同時使用時，個別登入仍是最可靠的選擇。請參閱 [Codex 的帳戶驗證指引](https://developers.openai.com/codex/auth/ci-cd-auth)。

每個供應商有一個作用中的帳戶，而每個新的工作階段都以它開始：`cx`、`cy`、一個普通的 `claude`、`codex` 或 `grok`、透過 `omarchy agent` 啟動的任何東西，以及在 `PATH` 上找到 CLI 的指令碼或編輯器。使用 `omarchy agent account use work` 切換（並使用 `omarchy agent account use main` 切換回來），或在面板中按下帳戶的數字然後按 `Enter`（或點擊其 Use 按鈕）。已在運行的工作階段會保持在其開始時所用的帳戶。對話歷史、設定、技能和外掛程式在各帳戶間共用，所以在同一個資料夾中的 `claude --continue` 會在新帳戶上接續你之前中斷的地方。

擁有多個帳戶時，該面板會並排顯示每個帳戶的上限，並標記作用中的一個。預設情況下，當作用中帳戶超過某個上限的 95% 時，Omarchy 會通知你，點擊該通知會切換到剩餘額度最多的帳戶。將滑鼠懸停在面板中帳戶的那一行上，並點擊出現在 Use 旁邊的 Autoswitch（或按 `m`），或執行 `omarchy agent account mode auto`，讓它自行切換；當它開啟時，Autoswitch 會取代 Use 的位置，再次點擊它會回到通知模式。加入數字以變更門檻，如在 `omarchy agent account mode auto 90` 中。如果每個帳戶都超過門檻，你會收到一次通知，並告知哪個帳戶最先釋放額度。當作用中帳戶距離其門檻在 15 個百分點內時（預設為 80%），其上限會每三分鐘而非每 15 分鐘檢查一次。

`omarchy agent account list` 會顯示每個帳戶及其最新上限，`omarchy agent account remove work` 會忘記一個帳戶，而 `omarchy agent account rename primary Hey` 會重新命名一個帳戶（或點擊面板中的帳戶名稱）。這些指令作用於你預設代理的帳戶；若要接觸其他供應商，請先指名它，如在 `omarchy agent account use codex side` 中。你已在 `~/.claude` 或 `~/.codex` 中擁有的登入是 _Main_ 帳戶，並會留在原處。帳戶若超過約八小時未使用，可能會顯示 _Sign-in required_；點擊它以直接在面板中再次登入該帳戶，或在其中開始一個工作階段，它會自行重新整理登入。你在新增帳戶時擁有的 MCP 伺服器會隨之帶入，但你之後使用 `claude mcp add` 新增的伺服器只會到達你新增它們時所在的帳戶。Claude Desktop 以及以絕對路徑設定指向 CLI 二進位檔的工具，不會跟著切換。明確的 `CLAUDE_CONFIG_DIR`、`CODEX_HOME` 或 `GROK_HOME` 優先於所選帳戶。

### 當機診斷

Omarchy 會監看 systemd-coredump 以找出程序當機。當某個程序發生區段錯誤時，你會收到一個「Process crashed」通知——點擊它，當機就會連同 Omarchy 的 diagnose-crash 技能一起交給你的預設代理，該技能會引導代理從核心傾印中確立事實，並決定該當機是否值得向 upstream 回報。你也可以使用 `omarchy agent crash <pid>`，針對來自 `coredumpctl list` 的任何 PID 手動執行它。

監看預設為開啟。在 _Trigger > Toggle > Crash Capture_ 下將其關閉（或使用 `omarchy toggle crash-capture`），通知就會停止；`omarchy agent crash <pid>` 仍可手動運作。

當機也可以一次針對一個程序靜音，這正是診斷最後會向你提供的選項。`omarchy crash mute hyprland` 只停止該程序的通知，`omarchy crash mute hyprland off` 會將它們恢復，而單獨的 `omarchy crash mute` 會列出你已靜音的內容。它同樣高興地接受二進位檔的路徑如同其名稱，所以 `omarchy crash mute /usr/bin/hyprland` 做的是同一件事。為含有空格的名稱加上引號，如在 `omarchy crash mute 'Some App'` 中。其他一切仍會通知，而被靜音的程序仍會當機——這隱藏的是提醒，它並不修復任何東西。

### 桌面應用程式

_Install > AI_ 選單還包含一些圖形化 AI 應用程式：ChatGPT 桌面應用程式、Claude 桌面應用程式（Anthropic 的 Linux beta 版，具有 Chat、Cowork 和 Claude Code 分頁）、用於與 xAI 模型聊天的 Grok Bot、Hermes Desktop、OpenClaw、Perplexity 桌面應用程式和 T3 Code。Grok Bot 是桌面聊天應用程式。程式設計代理是 `grok` 指令。

Hermes Desktop 是你需要知道的一個，因為一台機器有一個 Hermes，而它是屬於該應用程式的：Hermes 只會透過該應用程式安裝，而預設代理運行的 `hermes` 指令也是該應用程式的。選擇 Hermes 作為預設代理，安裝的是與 _Install > AI_ 項目相同的東西：該套件，以及一個由 Hermes 自己的安裝程式設定的、位於 `~/.hermes` 下的 Hermes 執行環境，第一次需要幾分鐘。該執行環境就是終端機的 `hermes` 指令、預設代理和該應用程式全都使用的一個 Hermes，而它會使用 `hermes update` 自行更新，而非等待 Omarchy 發行新版。安裝它也會將 Omarchy 主題以名為 `omarchy` 的外觀交給 Hermes，每個 Hermes 介面都會在你切換主題時跟著變更；如果你不希望如此，請在 Hermes 的 Appearance 設定下或使用 `/skin` 選取另一個，而 Omarchy 會尊重該選擇，不去動它。在 _Remove > AI_ 下移除該應用程式會先關閉 Hermes（包括閘道），連同該執行環境一起移除，並保留你的聊天、記憶以及 Hermes 為自己編寫的技能，除非你另行指示：它會詢問（預設為否）該資料和你的連線設定是否也應一併移除。

OpenClaw 的桌面體驗是其 Control UI，它會作為一個由其自己的本機閘道支援的網頁應用程式開啟。OpenClaw 存在於 `~/.openclaw` 中並自行更新：使用 Control UI 的「Update Gateway」按鈕或執行 `openclaw update`，閘道就會在新版本上重新啟動。Omarchy 只選擇全新安裝從哪個版本開始。在 _Remove > AI_ 下移除 OpenClaw 會連同閘道服務和該應用程式一起移除，然後詢問 `~/.openclaw` 是否也應一併移除，因為其中存放了你的聊天和憑證，以及 OpenClaw 本身和它下載的外掛程式執行環境；預設會保留它，而再次安裝 OpenClaw 會將它接回。

T3 Code 是從其位於 `~/.local/share/t3code` 的官方 AppImage 發行版運行的，而非從套件安裝，所以它會自行更新。安裝它時會詢問要從 Stable 還是 Nightly 頻道開始；之後在 T3 Code 的設定中切換。你的對話串和設定存在於 `~/.t3` 中，在 _Remove > AI_ 下移除 T3 Code 會連同它們一起移除。

### 本機模型

在你自己的機器上為你的程式設計代理運行一個開放模型。你的提示和程式碼保留在機器上；傳送給模型的任何東西都不會離開它。開始方式如下：

```bash
omarchy agent local use best
```

或者，在頂端列的代理面板中，選擇 + 然後選擇 Local AI，當有一個適合這台機器的模型時它就會出現。第一次這樣做時，會安裝 Podman，它負責運行這些模型。接著 Omarchy 會選出為這台機器推薦的模型，下載它，並啟動它。預計下載會有數十 GB，而在模型運行時，會使用這台機器的大部分記憶體：Flash Next 以其完整的 256K 上下文使用約 100 GiB。如果其他模型佔用了它需要的記憶體，它會被設定為停止狀態，準備在你停止其中一個之後啟動。模型會在登出時停止；當你需要記憶體做其他事時，請自行將它停止。

`omarchy agent local list` 會顯示各個選項，並解釋為何有些不適合。若要設定另一個，請執行 `omarchy agent local use <recipe>`。今天，`qwen3.8-flash-next-halogen` 和 `qwen3.8-27b-gufo` 可用於 128 GB Strix Halo 機器。新的配方和推薦會隨 `omarchy update` 透過套件到來。

你設定的每個模型在代理面板中都會有自己的一行，位於你的訂閱旁邊：播放以啟動它，暫停以停止它並釋放其記憶體，以及終端機按鈕以在它上面開啟你的代理。當多個模型一起放得進記憶體時，它們可以同時運行；如果有一個放不進去，Omarchy 會說明該停止哪個運行中的模型。拖曳各行以重新排序它們，並在選取的一行上按 Delete 來移除模型及其下載。

從命令列來看，`omarchy agent local start <recipe>` 和 `omarchy agent local stop <recipe>` 做的是同一件事，`omarchy agent local status` 會顯示每個模型，而 `omarchy agent --local` 會在你最後啟動的模型上開啟你的預設代理（如果你的預設代理不能使用本機模型，則為 pi）。任何與 OpenAI 相容的用戶端也可以連接：`status` 會顯示每個模型的位址（第一個是 `http://127.0.0.1:11435/v1`），配方名稱即為模型，而金鑰位於 `~/.config/omarchy/agent-local/key`。

`omarchy agent local remove <recipe>` 會刪除模型以及沒有其他模型使用的下載。

第三方執行環境以其發布者標示。Omarchy 運行每個模型時皆不連接網路。

### 本機 LLM

Omarchy 推薦兩種運行本機 LLM 模型的方式：LM Studio 和 Ollama。LM Studio 提供一個 GUI 介面，用於尋找開放權重模型、安裝它們並運行它們。這是一個容易上手的絕佳方式。Ollama 則提供 CLI 以類似方式進行。但如果你是本機模型的新手，我會從 LM Studio 開始。你可以在 Omarchy Menu 的 _Install > AI_ 下安裝任一者。

### Omarchy 技能

代理技能幫助 AI 以特定方式使用特定工具，而 Omarchy 隨附了一個預設技能，用於量身打造系統。就像調整你的 Hyprland 設定、調整列，或甚至從頭建立一個新主題。它被符號連結到 Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` 和每個 `~/.hermes/profiles/*/skills`）的技能目錄，以及通用的 `~/.agents/skills` 位置，所以大多數 harness 都會自動拾取它。

但你應將這項技能視為實驗性質。不同的模型會以不同的效果使用它。最好先在計畫模式下運行，這樣你就會對代理想要變更什麼有概念。然後準備好還原變更，或甚至呼叫 `omarchy reinstall configs`，如果代理把一切弄得一團糟的話。
