### 安裝與更新代理程式

除了 Hermes 和 OpenClaw 之外，這些代理程式都使用 mise 的延遲安裝：首次啟動時安裝 CLI，後續啟動則重複使用它。mise 也會至多每四小時檢查一次已安裝的代理程式是否有新版本，就在它啟動前，或在 shell 提示字元處於背景檢查。如果該次更新失敗或你離線，就會執行已安裝的版本。`omarchy update` 會連同 Omarchy 的其餘部分一起更新已安裝的代理程式，`mup` 則只更新 mise 管理的工具。

代理程式自己的更新程式，例如 `claude update`、`codex update` 或應用程式中的更新按鈕，不會更新 mise 管理的安裝。`codex update` 會失敗，`claude update` 則可能報告成功，卻安裝了一個 mise 不追蹤的獨立副本。如果你偏好使用代理程式原生的安裝程式與更新程式，請將它加入 `disable_tools`；請參閱 [預先安裝的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

若要在需要之前安裝所有已設定的延遲工具，請執行 `mise install --include-lazy`。這包括 Omarchy 的其他預設 CLI 工具以及代理程式。如需安裝單一工具或使用你自己的安裝，請參閱 [預先安裝的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

`grok` 是透過 mise 的第一方 `grok` 套件安裝，方式與 `claude` 和 `codex` 相同。執行 `grok`，或在 _Agent > Harness_ 下選擇它。跳過 x.ai 上的 `curl | bash` 安裝程式。那條路徑會在 `~/.grok/bin` 放入第二個副本，將其前置於 `PATH`，並覆寫 Omarchy 的包裝程式。

`dsh` 會在 `127.0.0.1:3080` 開啟其瀏覽器 UI，並以啟動目錄作為其預設工作區。它的瀏覽器 UI 不接受起始提示詞，因此 `omarchy agent prompt` 開啟它時，會將提示詞放在你的剪貼簿中讓你貼上。Omarchy 會以 DeepSeek 的免核准權限預設集啟動它。當你使用其官方模型 API 時，DeepSeek Harness 會將工作階段記錄上傳至 DeepSeek；在其瀏覽器 UI 的 _Settings > General > Upload Session Log_ 下將其關閉。你向它傳送的意見回饋也會連同工作階段一起上傳，除非你以 `DSH_TELEMETRY_MODE=DISABLED` 啟動它。

### 預設代理程式

使用 `omarchy default agent <name>` 或在 Omarchy Menu（`Super + Space`）的 _Agent > Harness_ 下，挑選你的預設代理程式。如果該代理程式尚未安裝，選擇它時會先安裝它，而且它還會在應用程式啟動器中取得自己的啟動器，就在 Agent 旁邊。全新的 Omarchy 會以一次性通知邀請你作出這個選擇。

選擇 Claude 時，也會嘗試為 Chromium、Chrome、Brave、Brave Origin 和 Edge 設定其瀏覽器擴充功能。此擴充功能設定適用於所有使用者，且可能要求你的系統密碼；取消或擴充功能安裝失敗，仍然會選取並啟動 Claude。重新啟動你的瀏覽器，在出現提示時啟用擴充功能，並登入 Claude 以完成連接。在 Claude 中執行 `/chrome` 以檢查連接。Firefox 和 Zen 不支援此擴充功能。如果在新增此設定之前 Claude 就已經是你的預設值，請再次選取它以安裝擴充功能。

作出選擇後，`Super + Shift + Ctrl + A` 會在專屬的終端機視窗中啟動預設代理程式（或者如果你尚未選擇，則會開啟挑選器）。你也可以用 `omarchy agent prompt "Review this project"` 讓它直接啟動並進入一項任務。Freebuff 和 DeepSeek Harness 不接受起始提示詞，因此它們開啟時會改將提示詞放在你的剪貼簿中讓你貼上。以這種方式啟動的代理程式，會在各自的「不要停下來詢問」模式中無人看管地執行，因此請做好它們真的會動手做事的準備！MiniMax Code 的互動式工作階段沒有這種模式，因此它會照常要求權限。而且由於代理程式拒絕記住對你家目錄的信任，從 `$HOME` 啟動時會改在 `~/Work` 中啟動。

也有終端機快捷鍵：`a` 會在目前的終端機中內嵌執行預設代理程式，而 `c`、`cx` 和 `cy` 則會直接啟動 OpenCode、Claude Code 和 Codex（同樣在其自動核准模式中）。主題變更也會同步至代理程式：當你切換 Omarchy 主題時，Claude Code、Pi、OpenCode 和 Hermes（一旦 Omarchy 已安裝它）都會跟著變更。

### 你的代理程式指示

適用於每個代理程式的個人規則放在 `~/.agents/AGENTS.md`，就在 `~/.agents/skills` 中的共用技能旁邊。在 _Agent > Instructions_ 下開啟它，它也會將其連結至每個保留自己全域檔案的 harness：`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`~/.pi/agent/AGENTS.md`、`~/.config/opencode/AGENTS.md`、Copilot 的 `~/.copilot/copilot-instructions.md`，等等。Crush 和 Amp 讀取 `~/.config/AGENTS.md` 連結，而 omp、Kimi 和 DeepSeek Harness 則直接讀取 `~/.agents/AGENTS.md`。挑選預設代理程式時也會連結它。如果先前並沒有共用檔案，你已有的指示檔案就會成為共用檔案；否則它會以 `.bak` 形式保留在連結旁邊。安裝另一個代理程式後，執行 `omarchy agent instructions` 以重新連結。

### 代理程式面板

頂部列有一個代理程式圖示。在你設定代理程式之前，其面板會引導你登入 Claude、Codex 或 Grok，而第一個登入的就會成為你的預設代理程式。在那之後，面板會將每個訂閱都放在同一頁上：每個代理程式和帳號及其方案、其 5 小時工作階段額度和每週額度各自的量表及距離重置的時間（將滑鼠游標停在其上可查看確切百分比），或剩餘的預付餘額，全都列在一行會輪番呈現你跨所有代理程式使用情況的文字下方，例如本週的 token 以及你最常使用的模型。在 _Make something cool_ 下，它會提供新主題、插件、應用程式或遊戲的入門提示詞，將任務交給你的預設代理程式。應用程式是以 Omarchy 自己的 Hype、Monologue 和 Omacut 相同的方式打造，使用 C++ 和 Qt Quick，遵循 omarchy-make-app 代理程式技能，而它們需要的編譯器和 Qt 元件都會隨附安裝。遊戲是位於 `~/Games/vibes` 中的單一 three.js 頁面，遵循 omarchy-make-game 代理程式技能，而且全都從目前主題中的同一個 Game Vibes 啟動器開啟；它們會從網路載入 three.js，因此需要連線才能啟動。Claude Code、Codex、Grok、Kimi、Cursor 及其 Grok Bot 額度、GitHub Copilot、Muse、Antigravity 和 Devin 開箱即涵蓋其額度，Kimchi 涵蓋其方案、預付點數和支出預算，而 Hermes、Mistral Vibe 和 Qwen Code 則會在你使用過它們後顯示其工作階段和 token。你透過 pi、omp 或 opencode 使用的供應商方案和金鑰也會顯示：OpenCode Zen 和 Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan 和 Synthetic 及其額度；OpenRouter 和 DeepSeek 及其預付餘額；Fireworks 及其過去 30 天的支出。來自你在自己的硬體上執行的模型的 token 也會計入總計；模型本身則有其專屬面板，詳見 [本地模型](#local-models) 一節。每個代理程式都只會計算一次，歸屬於向它收費的一方，無論你透過多少個 harness 驅動它。

以左鍵按一下列上的圖示或按下 `Super + Ctrl + X` 可開啟面板，以右鍵按一下可啟動你的預設代理程式，以中鍵按一下可重新整理。其背後的使用記錄每 15 分鐘由 `omarchy agent usage update` 重新產生，而且面板甚至可以透過已同步的資料夾合併來自你其他機器的使用情況。完整設定請參閱 `$OMARCHY_PATH/shell/plugins/agents/` 下的 README。

### 多個訂閱

如果你付費購買了不只一個 Claude、Codex 或 Grok 方案——例如一個個人 Max 和一個工作用的——Omarchy 可以讓它們全都保持登入，並在它們之間切換。使用代理程式面板中的 + 新增訂閱，它會就在那裡引導你完成，或使用 `omarchy agent account add claude Work`（或 `codex`、或 `grok`）。如果缺少 CLI，它會安裝它。某個供應商的第一個帳號會透過你平常的瀏覽器登入，就在 CLI 一直查看的位置。在那之後的每一個帳號，都會透過私密視窗登入，因此你瀏覽器已登入的帳號就不會被誤選；在那裡以你要新增的帳號登入，並先關閉你已開啟的任何私密視窗。永遠不要為了這樣做而登出 CLI：登出會撤銷已儲存的登入狀態，而該帳號將必須重新新增。

若要透過 SSH 將你的訂閱登入資訊複製到另一台 Omarchy 機器，請執行 `omarchy agent account copy user@laptop`。當目的地未安裝接收器時，傳送方會提供一個暫時接收器，因此較舊的 Omarchy 機器無需更新即可接收帳號。已安裝的接收器具有優先權。這會複製所有 Claude、Codex 和 Grok 訂閱；加入供應商名稱即可選取它們，如 `omarchy agent account copy laptop claude`。帳號名稱和指令 ID 會與來源相符，包括目的地已存在的帳號。如果名稱衝突，不相關的目的地帳號會收到數字後綴，而設定、技能、插件和對話記錄則各自保留在每台機器上。

現有的目的地憑證會保留。已經在那裡登入的來源帳號，其名稱會同步，但不會取代其憑證；其他帳號則會新增至其旁邊。若要取代相符帳號已儲存的憑證，請在目的地退出該帳號的工作階段後，使用 `omarchy agent account copy --replace laptop claude`。全新的目的地還會取得來源使用中的帳號和切換偏好；已建立的目的地則保留自己的偏好。

憑證會透過 SSH 傳輸，並儲存在目的地的私人檔案中，因此請只複製到你信任的機器。這是一次性複製，並非持續同步。Codex 重新整理 token 可能會被另一台機器輪替，使複製的登入資訊需要續期；在多台機器上同時使用時，各自獨立登入仍是最可靠的選擇。請參閱 [Codex 的帳號驗證指南](https://developers.openai.com/codex/auth/ci-cd-auth)。

每個供應商會有一個使用中的帳號，而且每個新的工作階段都會以它啟動：`cx`、`cy`、普通的 `claude`、`codex` 或 `grok`、透過 `omarchy agent` 啟動的任何東西，以及在 `PATH` 上找到 CLI 的指令碼或編輯器。使用 `omarchy agent account use work` 切換（並以 `omarchy agent account use main` 切換回來），或在面板中按下帳號的編號然後按 `Enter`（或按其 Use 按鈕）。正在執行的 Claude 工作階段也會切換，從它們的下一則訊息開始：每個 Claude 工作階段都在 `~/.claude` 中執行，該處永遠保存著使用中帳號的登入資訊。由較舊的 Omarchy 在帳號自己的資料夾中啟動的 Claude 工作階段，會保留該登入資訊直到它退出，因此切換時會列出那些工作階段的名稱，並在它們消失後自行完成。正在執行的 Codex 和 Grok 工作階段會留在它們啟動時所用的帳號上。對話記錄、設定、技能和插件在帳號之間共用，因此在相同資料夾中的 `claude --continue` 會在新帳號上接續你離開的地方。

當有多個帳號時，面板會並排顯示每個帳號的額度，並標記使用中的帳號。依預設，當使用中的帳號超過額度的 95% 時，Omarchy 會通知你，而按一下通知就會切換到餘裕最多的帳號。將滑鼠游標停在面板中帳號的那一行，按一下 Use 旁邊出現的 Autoswitch（或按下 `m`），或執行 `omarchy agent account mode auto`，即可讓它改為自行切換；當它開啟時，Autoswitch 會取代 Use 的位置，再按一下它就會回到通知模式。加入數字即可變更閾值，如 `omarchy agent account mode auto 90`。如果每個帳號都超過閾值，你會收到一次通知，同時告知哪個帳號最先釋出額度。雖然使用中的帳號距離其閾值在 15 個百分點以內（預設值為 80%），其額度會每三分鐘檢查一次，而非每 15 分鐘。

`omarchy agent account list` 會顯示每個帳號及其最新額度，`omarchy agent account remove work` 會忘記一個帳號，`omarchy agent account rename primary Hey` 會重新命名一個帳號（或在面板中按一下帳號的名稱）。這些指令作用於你預設代理程式的帳號；若要存取另一個供應商，請先指名它，如 `omarchy agent account use codex side`。你原本在 `~/.claude` 或 `~/.codex` 中已有的登入是 _Main_ 帳號。Codex 的會留在原處；當另一個帳號正在使用時，Claude 的會在它自己的資料夾中等待。一個超過約八小時未使用的帳號可能會顯示 _Sign-in required_；按一下它即可直接在面板中重新登入該帳號，或切換至它並啟動工作階段，它就會自行重新整理登入資訊。你用 `claude mcp add` 新增的 MCP 伺服器會到達每個 Claude 帳號，因為它們都在 `~/.claude` 中執行；對於 Codex 和 Grok，你在帳號新增時已有的伺服器會跟著到該帳號，但之後新增的只會到達你新增它們時所在的帳號。Claude Desktop 保留它自己的登入，而以指向 CLI 二進位檔案的絕對路徑設定的 Codex 或 Grok 工具不會跟著切換。明確的 `CLAUDE_CONFIG_DIR`、`CODEX_HOME` 或 `GROK_HOME` 會優先於所選的帳號。

### 崩潰診斷

Omarchy 會監看 systemd-coredump 是否有處理程序崩潰。一旦你挑選了預設代理程式，你任何傾印核心的程式都會帶來一個「Process crashed」通知——按一下它，崩潰就會連同 Omarchy 的 omarchy-diagnose-crash 技能一同交給你的預設代理程式，該技能會引導代理程式從核心轉儲建立事實，並判定該崩潰是否值得向上游報告。你也可以針對 `coredumpctl list` 中的任何 PID，使用 `omarchy agent crash <pid>` 手動執行它。

監看依預設開啟。在 _Trigger > Toggle > Crash Capture Off_ 下將其關閉（或使用 `omarchy toggle crash-capture`），通知就會停止；`omarchy agent crash <pid>` 仍然可以手動運作。

崩潰也可以逐個程式靜音，這正是診斷在最後提供給你的選項。`omarchy crash mute hyprland` 只會停止該程式的通知，`omarchy crash mute hyprland off` 會將它們帶回來，而單獨的 `omarchy crash mute` 會列出你已靜音的內容。它接受二進位檔案的路徑就如同接受其名稱一樣爽快，因此 `omarchy crash mute /usr/bin/hyprland` 做的是同樣的事情。為含有空格的名稱加上引號，如 `omarchy crash mute 'Some App'`。其他一切仍會通知，而且已靜音的程式仍然會崩潰——這只是隱藏提醒，並不會修好任何東西。

### 桌面應用程式

_Install > AI_ 選單也包含幾個圖形化 AI 應用程式：Amp Desktop、Antigravity Desktop、ChatGPT 桌面應用程式、Claude 桌面應用程式（Anthropic 的 Linux beta 版，具有 Chat、Cowork 和 Claude Code 分頁）、用於與 xAI 模型聊天的 Grok Bot、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexity 桌面應用程式和 T3 Code。Grok Bot 是桌面聊天應用程式。程式設計代理程式則是 `grok` 指令。

Hermes Desktop 是需要知道的那一個，因為一台機器只有一個 Hermes，而它是屬於該應用程式的：Hermes 僅能透過該應用程式安裝，而且預設代理程式執行的 `hermes` 指令就是該應用程式的。選擇 Hermes 作為預設代理程式，安裝的與 _Install > AI_ 項目安裝的是同樣的東西：該套件，以及一個由 Hermes 自己的安裝程式設定、位於 `~/.hermes` 下的 Hermes 執行環境，第一次需要幾分鐘時間。該執行環境就是終端機 `hermes` 指令、預設代理程式和應用程式全都使用的那一個 Hermes，而且它會以 `hermes update` 自行更新，而非等待 Omarchy 發行新版。安裝它時，還會將 Omarchy 主題以名為 `omarchy` 的外觀交給 Hermes，當你切換主題時，每個 Hermes 介面都會跟著變更；如果你不希望如此，請在 Hermes 的 Appearance 設定下或使用 `/skin` 挑選另一個，而 Omarchy 會尊重該選擇，不去動它。在 _Remove > AI_ 下移除該應用程式時，會先關閉 Hermes（包括閘道），一併帶走該執行環境，並保留你的聊天、記憶以及 Hermes 為自己撰寫的技能，除非你另行指示：它會詢問你的這些資料和你的連線設定是否也應一併移除，預設為否。

OpenClaw 的桌面體驗是其 Control UI，它會以一個由其專屬本地閘道支援的網頁應用程式形式開啟。OpenClaw 位於 `~/.openclaw` 並自行更新：使用 Control UI 的「Update Gateway」按鈕或執行 `openclaw update`，閘道就會在新版本上重新啟動。Omarchy 只選擇全新安裝所起始的發行版本。OpenClaw 也可以是你的預設代理程式：在 _Agent > Harness_ 下選擇它，會在 `~/.openclaw` 中設定同一個副本，而且該代理程式會開啟附加至其閘道的 OpenClaw 終端機 UI。在 _Remove > AI_ 下移除 OpenClaw，會一併帶走閘道服務和應用程式，然後詢問 `~/.openclaw` 是否也應移除，因為其中保存著你的聊天和憑證，以及 OpenClaw 本身和它下載的插件執行環境；預設會保留它，而再次安裝 OpenClaw 會將它重新接回來。

Herdr Desktop 是 [Herdr](https://herdr.dev) 桌面應用程式：由終端機和程式設計代理程式組成的空間、分頁和窗格，當你關閉視窗時，它們仍會在其核心中持續執行。它來自 Herdr 自己的安裝程式而非套件，因此它位於 `~/.local/share/herdr-app`，當你尚沒有時，會在 `~/.local/bin/herdr-core` 中帶來其核心，而且兩者都會自行更新。它位於 Omarchy 隨附在 `Super + Ctrl + Return` 上的 `herdr` 指令旁邊，而非取代它，而且它獲得了該指令的直接鍵：`Alt + Return` 和 `Alt + Shift + Return` 向下或向右分割窗格，`Alt + Escape` 關閉它，`Ctrl + Alt + Arrow` 在窗格之間移動，`Alt + 1..9` 和 `Alt + Left/Right` 挑選分頁，而 `Alt + Up/Down` 在空間之間移動。`Ctrl + 1..9` 挑選一個空間，`Alt + Shift + Up/Down` 在代理程式之間逐步切換。`Ctrl + Space` 前綴鍵僅在終端機中保留，因為該應用程式無法為了序列而按住一個普通的 Ctrl 鍵。Omarchy 將這些寫入 `~/.config/herdr-app/keys.json`，而 `omarchy-refresh-herdr-app` 會將它們放回去。安裝它時會挑選 Herdr 的 Omarchy 主題，從那時起它會跟隨你的 Omarchy 主題。Herdr 會保留一個淺色模式主題和一個深色模式主題，因此在深色與淺色 Omarchy 主題之間切換後，請在 Herdr 的主題挑選器中再挑選一次 Omarchy 以使用另一個模式。

T3 Code 從其位於 `~/.local/share/t3code` 的官方 AppImage 發行版執行，而非從套件執行，因此它會自行更新。安裝它時會詢問要從 Stable 還是 Nightly 頻道開始；之後可在 T3 Code 的設定中切換。你的討論串和設定位於 `~/.t3`，而在 _Remove > AI_ 下移除 T3 Code 會將它們一併帶走。

### 本地模型

在你自己的機器上執行開放模型，供你的程式設計代理程式使用。你的提示詞和程式碼會留在機器上；傳送給模型的任何東西都不會離開它。以下列指令開始：

```bash
omarchy models use best text
```

這會為此機器設定最佳的文字模型，也就是你的代理程式使用的那一類。圖片、影片和音樂模型各有其最佳選擇：`omarchy models use best image`、`video` 或 `music`。執行 `omarchy models use best` 以查看每一種類為此機器挑選的模型。

或者，從頂部列中其位於代理程式圖示旁邊的閃爍圖示，或以 Super + Ctrl + Alt + X 開啟本地模型面板，並選擇 +。當有模型適合此機器時，該圖示就會顯示。負責執行模型的 Podman 會隨 Omarchy 附帶，在 NVIDIA 機器上 NVIDIA 的容器工具包也一樣，它會為它們提供 GPU；如果其中任何一個缺失，第一次設定就會安裝它。接著 Omarchy 會為此機器挑選建議的模型，下載它並啟動它。預期下載量會有數十 GB，而且在模型執行時，機器的大部分記憶體都會在使用中：Flash Next 在其完整的 256K 上下文下使用約 100 GiB。如果其他模型佔用了它所需的記憶體，它會以停止狀態完成設定，等你停止其中一個時即可啟動。模型會在登出時停止；當你需要記憶體做其他事情時，請自行停止它。

`omarchy models list` 會顯示選項並說明為什麼有些不適合。若要設定另一個，請執行 `omarchy models use <recipe>`。目前，`qwen3.8-flash-next-gufo` 和 `qwen3.8-27b-gufo` 可用於 128 GB Strix Halo 機器；27B 約使用 40 GiB，因此它會留下空間進行其他工作。在一台具有 Intel Arc B390 的 64 GB 筆記型電腦上，`qwen3.6-35b-a3b-llamacpp` 約在 30 GiB 內執行。新的配方和建議會透過套件隨 `omarchy update` 送達。

你設定的每個模型在本地模型面板中都有其專屬的一行：播放鍵可啟動它，暫停鍵可停止它並釋放其記憶體，而終端機按鈕可在其上開啟你的代理程式。橫跨頂部的列會顯示機器的記憶體如何在 Omarchy 本身（系統和你的應用程式）、每個正在執行的模型和剩餘空閒空間之間分配。指向一個已停止的模型時，該列會顯示它是否適合，或還差多少。數個模型在共同適合記憶體時可以同時執行；如果有一個不適合，Omarchy 會說明要停止哪個正在執行的模型。按住它們的標誌拖曳各行即可重新排序它們，並在選取一行時按 Delete 可移除模型及其下載。

你設定的每個程式設計模型還會在應用程式啟動器中取得其專屬項目，位於模型的名稱下並帶有其製造商的標誌，就像登入 Claude、Codex 或 Grok 時會新增一個一樣。它會在該模型上開啟你的代理程式，而且如果模型尚未執行，會先啟動它：終端機會顯示它正在載入，並在它準備就緒後交給代理程式。移除模型也會移除其項目。

並非每個模型都是用於程式設計。圖片、影片和音樂模型改在 Fantasi 中開啟，Fantasi 是 Omarchy 用於使用在此機器上執行的模型製作圖片、影片和音樂的應用程式，可在那裡或從它們在本地模型面板中的行挑選。

模型會完全按照其設定時的方式持續執行，因此 Omarchy 更新永遠不會在你的代理程式之下重新啟動它。當 Omarchy 為你已設定的模型提供了較新的執行環境或較新的權重時，其那一行會顯示更新按鈕：按下它，模型就會在背景中重新設定，只下載已變更的部分，並在新版本上重新啟動。已停止的模型會保持停止。`omarchy models update` 會從終端機為每個模型做同樣的事情。

從命令列來看，`omarchy models start <recipe>` 和 `omarchy models stop <recipe>` 做同樣的事情，`omarchy models status` 顯示每個模型，而 `omarchy agent --local` 則會不論你的預設代理程式為何，都在 pi 中開啟你最後啟動的模型。OpenCode 和 Qwen Code 也可以使用本地模型：`omarchy models harness opencode` 或 `omarchy models harness qwen` 會改在那裡開啟它們，而 `omarchy models harness pi` 則會回到 pi。pi 還會在其自己的模型挑選器中列出你已設定的每個模型，以及在你已配對的機器上的模型，因此普通的 `pi` 也能存取它們。任何與 OpenAI 相容的用戶端也能連線：`status` 會顯示每個模型的位址（第一個是 `http://127.0.0.1:11435/v1`），配方名稱就是模型，而金鑰位於 `~/.config/omarchy/agent-local/key`。

`omarchy models remove <recipe>` 會刪除一個模型以及沒有其他模型使用的下載。

第三方執行環境會以其發布者標示。Omarchy 在沒有網路存取的情況下執行每個模型。

### 本地 LLM

Omarchy 建議兩種執行本地 LLM 模型的方式：LM Studio 和 Ollama。LM Studio 提供一個 GUI 介面用於尋找開放權重模型、安裝它們並執行它們。這是輕鬆上手的好方法。Ollama 提供一個 CLI 以類似方式完成。 但如果你是本地模型新手，我會建議從 LM Studio 開始。你可以在 Omarchy Menu 的 _Install > AI_ 下安裝任一者。

### Omarchy 技能

代理程式技能會協助 AI 以特定的方式使用特定的工具，而 Omarchy 隨附七個這樣的技能。omarchy 技能涵蓋量身打造系統，如調整你的 Hyprland 設定或調整該列。omarchy-make-theme、omarchy-make-plugin、omarchy-make-app 和 omarchy-make-game 涵蓋製作新東西，omarchy-contribute 涵蓋報告錯誤或向上游傳送修復，而 omarchy-diagnose-crash 則處理崩潰的核心轉儲。它們會以符號連結放入 Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` 以及每個 `~/.hermes/profiles/*/skills`）的技能目錄，以及通用的 `~/.agents/skills` 位置，因此大多數 harness 會自動取得它們。你自己同名的技能資料夾具有優先權。

但你應該將這些技能視為實驗性質。不同的模型會以不同程度發揮其效果。最好先在計畫模式中執行，這樣你就能了解代理程式想變更什麼。然後準備好回復變更，甚至在代理程式把一切搞得一團糟時，準備好叫用 `omarchy reinstall configs`。
