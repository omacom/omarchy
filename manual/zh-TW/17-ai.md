### 安裝與更新代理

除 Hermes 外，這些代理都使用 mise 的延遲安裝：首次啟動會安裝 CLI，之後的啟動會重複使用它。mise 也會在啟動前，或在 shell 提示字元下的背景中，最多每四小時檢查一次已安裝的代理是否有新版本。如果該更新失敗或你處於離線狀態，便會執行已安裝的版本。`omarchy update` 會連同 Omarchy 的其他部分一起更新已安裝的代理，而 `mup` 則只更新由 mise 管理的工具。

代理自己的更新程式，例如 `claude update`、`codex update`，或應用程式中的更新按鈕，不會更新由 mise 管理的安裝。`codex update` 會失敗，而 `claude update` 可能回報成功，卻安裝了一份 mise 不追蹤的獨立副本。如果你寧願使用代理原生的安裝程式與更新程式，請將它加入 `disable_tools`；請參閱[預先安裝的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

若要在需要之前先安裝所有已設定的延遲工具，請執行 `mise install --include-lazy`。這包括 Omarchy 的其他預設 CLI 工具，以及這些代理。安裝單一工具或使用你自己的安裝方式，請參閱[預先安裝的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

`grok` 是透過 mise 的第一方 `grok` 套件安裝，和 `claude` 與 `codex` 相同。執行 `grok`，或在 _Agent > Harness_ 下選取它。不要用 x.ai 上的 `curl | bash` 安裝程式。那條路徑會在 `~/.grok/bin` 放第二份副本、將它排在 `PATH` 最前面，並覆寫 Omarchy 的包裝程式。

`dsh` 會在 `127.0.0.1:3080` 開啟它的瀏覽器 UI，並以啟動目錄作為預設工作區。它的瀏覽器 UI 不接受起始提示，所以 `omarchy agent prompt` 開啟它時會把提示放在你的剪貼簿上讓你貼上。Omarchy 會以 DeepSeek 的無需核准權限預設集來啟動它。當你使用 DeepSeek 的官方模型 API 時，DeepSeek Harness 會將工作階段記錄上傳到 DeepSeek；在它的瀏覽器 UI 的 _Settings > General > Upload Session Log_ 下將其關閉。你傳送給它的回饋也會連同工作階段一起上傳，除非你以 `DSH_TELEMETRY_MODE=DISABLED` 啟動它。

### 預設代理

用 `omarchy default agent <name>` 挑選你的預設代理，或在 Omarchy Menu（`Super + Space`）的 _Agent > Harness_ 下挑選。如果該代理尚未安裝，選它會先將它安裝。全新安裝的 Omarchy 會以一次性的通知邀請你做這個選擇。

選擇 Claude 也會嘗試為 Chromium、Chrome、Brave、Brave Origin 和 Edge 設定它的瀏覽器擴充功能。擴充功能的設定適用於所有使用者，且可能會要求你輸入系統密碼；取消或擴充功能安裝失敗，仍然會選取並啟動 Claude。重新啟動你的瀏覽器、依提示啟用擴充功能，並登入 Claude 以完成連接。在 Claude 中執行 `/chrome` 來檢查連接狀態。Firefox 和 Zen 不支援這個擴充功能。如果在加入這項設定之前，Claude 就已經是你的預設，請再選它一次來安裝擴充功能。

選定後，`Super + Shift + Ctrl + A` 會在專用的終端機視窗中啟動預設代理（如果你還沒選，則會開啟選擇器）。你也可以用 `omarchy agent prompt "Review this project"` 讓它直接進入一項任務。Freebuff 和 DeepSeek Harness 不接受起始提示，所以它們開啟時會把提示放在你的剪貼簿上讓你貼上。以這種方式啟動的代理會以各自的「不要停下來詢問」模式無人值守地執行，所以要做好它們真的會動手做事的準備！MiniMax Code 的互動式工作階段沒有這種模式，所以它會照常詢問權限。而且由於代理拒絕記住對你家目錄的信任，從 `$HOME` 啟動時會改從 `~/Work` 開始。

也有終端機捷徑：`a` 會在目前的終端機內直接執行預設代理，而 `c`、`cx` 和 `cy` 則會直接啟動 OpenCode、Claude Code 和 Codex（同樣是它們的自動核准模式）。主題變更也會同步給代理：當你切換 Omarchy 主題時，Claude Code、Pi、OpenCode 和 Hermes（一旦 Omarchy 已安裝它）都會跟著變更。

### 你的代理指示

每個代理的個人規則都放在 `~/.agents/AGENTS.md`，就在共用技能所在的 `~/.agents/skills` 旁邊。在 _Agent > Instructions_ 下開啟它，它也會被連結到每個有自己全域檔案的 harness：`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`~/.pi/agent/AGENTS.md`、`~/.config/opencode/AGENTS.md`、Copilot 的 `~/.copilot/copilot-instructions.md`，依此類推。Crush 和 Amp 讀取 `~/.config/AGENTS.md` 連結，而 omp、Kimi 和 DeepSeek Harness 則直接讀取 `~/.agents/AGENTS.md`。挑選預設代理也會連結它。如果你已經有一份指示檔案，而還沒有共用的那份，它就會成為共用檔案；否則它會以 `.bak` 的形式保留在連結旁邊。安裝另一個代理後，執行 `omarchy agent instructions` 來重新連結。

### 代理面板

頂部欄有一個代理圖示。在你設定好代理之前，它的面板會引導你登入 Claude、Codex 或 Grok，第一個登入的會成為你的預設代理。之後，面板會把每一個訂閱都放在同一頁上：每個代理和帳戶及其方案、其 5 小時工作階段與每週限制各自的用量表和距離重置的時間（將滑鼠懸停可查看確切百分比），或剩餘的預付餘額，上方有一行會輪播顯示你在所有代理上的總用量，例如本週的 token 以及你最常用的模型。在 _Make something_ 之下，它會提供用於新主題、外掛程式或應用程式的起始提示，將任務交給你的預設代理。應用程式是按照 Omarchy 自己的 Hype、Monologue 和 Omacut 的方式打造，使用 C++ 和 Qt Quick，遵循 omarchy-app 代理技能，且它們所需的編譯器和 Qt 組件都已隨附安裝。Claude Code、Codex、Grok、Kimi、Cursor 及其 Grok Bot 額度、GitHub Copilot、Muse、Antigravity、Kimchi 和 Devin 在開箱時即涵蓋其限制，而 Hermes、Mistral Vibe 和 Qwen Code 則會在你使用過後顯示其工作階段和 token。你透過 pi、omp 或 opencode 使用的供應商方案和金鑰也會顯示出來：OpenCode Zen 和 Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan 和 Synthetic，連同它們的限制；Fireworks、OpenRouter 和 DeepSeek 則顯示其預付餘額；還有你在自己硬體上執行的模型，位於 Local models 之下。每個代理只會計算一次，以向其收費的一方為準，不論你透過多少個 harness 來驅動它。

左鍵點擊欄圖示開啟面板，右鍵點擊則啟動你的預設代理。它背後的用量記錄每 15 分鐘由 `omarchy agent usage-update` 重新產生，而且面板甚至能透過已同步的資料夾合併你其他機器的用量。完整設定請參閱 `$OMARCHY_PATH/shell/plugins/agents/` 下的 README。

### 多個訂閱

如果你付費訂閱了一個以上的 Claude、Codex 或 Grok 方案——例如一個個人 Max 和一個工作用的——Omarchy 可以讓它們全都保持登入，並在它們之間切換。用代理面板中的 + 新增一個訂閱，它會就在那裡引導你完成，或用 `omarchy agent account add claude Work`（或 `codex`，或 `grok`）。如果缺少 CLI，它會將它安裝。某個供應商的第一個帳戶會透過你平常的瀏覽器登入，就在 CLI 一直以來查找的位置。之後的每一個都會透過私密視窗登入，所以你瀏覽器已登入的帳戶不會被誤選；在那裡以你要新增的帳戶登入，並先關閉你已開啟的任何私密視窗。絕對不要為了做這件事而登出 CLI：登出會撤銷已儲存的登入，那個帳戶就必須重新新增。

若要透過 SSH 將你的訂閱登入複製到另一台 Omarchy 機器，請執行 `omarchy agent account copy user@laptop`。當目的地沒有安裝接收端時，傳送端會提供一個臨時接收端，所以較舊的 Omarchy 機器無需更新就能接收帳戶。已安裝的接收端優先。這會複製所有 Claude、Codex 和 Grok 訂閱；加上供應商名稱即可加以選擇，例如 `omarchy agent account copy laptop claude`。帳戶名稱和指令 ID 與來源相符，包括目的地已存在的帳戶。無關的目的地帳戶若名稱衝突，會被加上數字後綴，而設定、技能、外掛程式和對話記錄則保留在各自的機器本機。

現有的目的地憑證會予以保留。已經在那裡登入的來源帳戶會同步其名稱，但不會取代其憑證；其他帳戶則會新增在其旁邊。若要取代相符帳戶已儲存的憑證，請在結束目的地該帳戶的工作階段後，使用 `omarchy agent account copy --replace laptop claude`。全新的目的地還會取得來源的作用中帳戶和切換偏好設定；已建立的目的地則保留自己的。

憑證會透過 SSH 傳輸，並以私人檔案儲存在目的地，所以只複製到你信任的機器。這是一次性複製，不是持續同步。Codex 重新整理 token 可能會被另一台機器輪替，導致複製的登入需要續期；在多台機器上同時使用時，個別登入仍是最可靠的選擇。請參閱 [Codex 的帳戶驗證指南](https://developers.openai.com/codex/auth/ci-cd-auth)。

每個供應商有一個帳戶處於使用中，每個新工作階段都會以它開始：`cx`、`cy`、普通的 `claude`、`codex` 或 `grok`、透過 `omarchy agent` 啟動的任何東西，以及在 `PATH` 上找到 CLI 的指令碼或編輯器。用 `omarchy agent account use work` 切換（並用 `omarchy agent account use main` 切回），或在面板中按下帳戶的編號再按 `Enter`（或點擊它的 Use 按鈕）。已經在執行的工作階段會維持在它們開始時所用的帳戶。對話記錄、設定、技能和外掛程式在各帳戶之間共用，所以在同一個資料夾中的 `claude --continue` 會在新帳戶上從你離開的地方接續。

有多個帳戶時，面板會並排顯示每個帳戶的限制，並標記作用中的那個。依預設，當作用中的帳戶超過某個限制的 95% 時，Omarchy 會通知你，點擊通知會切換到餘裕最多的帳戶。將滑鼠懸停在面板中的帳戶那一行上，點擊 Use 旁邊出現的 Autoswitch（或按 `m`），或執行 `omarchy agent account mode auto`，讓它自行切換；開啟時，Autoswitch 會取代 Use 的位置，再次點擊它便會恢復為通知。加上數字可變更門檻，例如 `omarchy agent account mode auto 90`。如果每個帳戶都超過門檻，你會收到一次通知，並得知哪個帳戶最先釋放額度。當作用中的帳戶距離其門檻在 15 個百分點以內（預設為 80%）時，其限制會每三分鐘檢查一次，而不是每 15 分鐘。

`omarchy agent account list` 會顯示每個帳戶及其最新限制，`omarchy agent account remove work` 會忘記一個帳戶，而 `omarchy agent account rename primary Hey` 會重新命名一個帳戶（或在面板中點擊帳戶名稱）。這些指令作用於你的預設代理的帳戶；若要觸及另一個供應商，請先命名它，例如 `omarchy agent account use codex side`。你原本在 `~/.claude` 或 `~/.codex` 中已有的登入是 _Main_ 帳戶，並會留在原處。閒置超過約八小時的帳戶可能會顯示 _Sign-in required_；點擊它就能直接在面板中重新登入該帳戶，或在其中啟動一個工作階段，它會自行重新整理登入。新增帳戶時你已有的 MCP 伺服器會跟著過去，但你之後用 `claude mcp add` 新增的只會到達你新增它們時所在的那個帳戶。Claude Desktop 和以 CLI 二進位檔絕對路徑設定的工具不會跟隨切換。明確指定的 `CLAUDE_CONFIG_DIR`、`CODEX_HOME` 或 `GROK_HOME` 優先於所選的帳戶。

### 崩潰診斷

Omarchy 會監看 systemd-coredump 以偵測程序崩潰。當某個東西出現 segfault 時，你會收到一個 "Process crashed" 通知——點擊它，崩潰就會連同 Omarchy 的 diagnose-crash 技能交給你的預設代理，該技能會引導代理從核心傾印中建立事實，並決定該崩潰是否值得向 upstream 回報。你也可以用 `coredumpctl list` 中的任何 PID 手動對它執行 `omarchy agent crash <pid>`。

監看依預設為開啟。在 _Trigger > Toggle > Crash Capture_ 下將其關閉（或用 `omarchy toggle crash-capture`），通知就會停止；`omarchy agent crash <pid>` 仍可手動使用。

崩潰也可以一次按一個程式來靜音，這是診斷在結尾會提供給你的選項。`omarchy crash mute hyprland` 只會停止該程式的通知，`omarchy crash mute hyprland off` 會將它們恢復，而單獨的 `omarchy crash mute` 會列出你已靜音的項目。它接受二進位檔的路徑就像接受其名稱一樣，所以 `omarchy crash mute /usr/bin/hyprland` 效果相同。名稱中有空格的請用引號括起來，例如 `omarchy crash mute 'Some App'`。其他一切仍會發出通知，被靜音的程式也仍會崩潰——這只是隱藏提醒，不會修好任何東西。

### 桌面應用程式

_Install > AI_ 選單還包含一些圖形化 AI 應用程式：ChatGPT 桌面應用程式、Claude 桌面應用程式（Anthropic 的 Linux beta 版，帶有 Chat、Cowork 和 Claude Code 分頁）、用於與 xAI 模型聊天的 Grok Bot、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexity 桌面應用程式，以及 T3 Code。Grok Bot 是桌面聊天應用程式。程式碼代理則是 `grok` 指令。

Hermes Desktop 是你需要了解的那個，因為一台機器只有一個 Hermes，而且它是屬於該應用程式的：Hermes 只能透過該應用程式安裝，預設代理執行的 `hermes` 指令就是該應用程式的。選擇 Hermes 作為預設代理會安裝和 _Install > AI_ 項目相同的東西：該套件，以及一個位於 `~/.hermes` 之下、由 Hermes 自己的安裝程式設定的 Hermes 執行環境，第一次需要花幾分鐘時間。該執行環境是終端機 `hermes` 指令、預設代理和應用程式全都共用的那一個 Hermes，且它會用 `hermes update` 自行更新，而非等待 Omarchy 發布新版本。安裝它還會將 Omarchy 主題以名為 `omarchy` 的外觀交給 Hermes，每個 Hermes 介面都會隨著你切換主題而跟隨；如果你不想如此，請在 Hermes 的 Appearance 設定下或用 `/skin` 選另一個，Omarchy 不會干涉那個選擇。在 _Remove > AI_ 下移除該應用程式會先關閉 Hermes，gateway 也包括在內，並連同該執行環境一起移除，同時保留你的聊天、記憶，以及 Hermes 為自己撰寫的技能，除非你另有指示：它會詢問你，預設為否，是否也應一併移除那些資料和你的連線設定。

OpenClaw 的桌面體驗是它的 Control UI，會以一個由其自身本機 gateway 支援的網頁應用程式開啟。OpenClaw 住在 `~/.openclaw` 並會自行更新：使用 Control UI 的 "Update Gateway" 按鈕或執行 `openclaw update`，gateway 就會以新版本重新啟動。Omarchy 只選擇全新安裝的起始版本。在 _Remove > AI_ 下移除 OpenClaw 會連同 gateway 服務和應用程式一起移除，然後詢問 `~/.openclaw` 是否也應一併刪除，因為它存放了你的聊天和憑證，以及 OpenClaw 本身和它下載的外掛程式執行環境；預設是保留它，再次安裝 OpenClaw 時會重新取回它。

Herdr Desktop 是 [Herdr](https://herdr.dev) 桌面應用程式：由空間、分頁，以及終端機和程式碼代理的窗格組成，即使你關閉視窗，它們仍會在其核心中持續執行。它來自 Herdr 自己的安裝程式而非套件，所以它住在 `~/.local/share/herdr-app`，當你還沒有核心時會在 `~/.local/bin/herdr-core` 附帶其核心，並會自行更新兩者。它與 Omarchy 透過 `Super + Ctrl + Return` 提供的 `herdr` 指令並存，而非取而代之，並取得該指令的直接按鍵：`Alt + Return` 和 `Alt + Shift + Return` 會向下或向右分割窗格，`Alt + Escape` 會關閉它，`Ctrl + Alt + Arrow` 會在窗格之間移動，`Alt + 1..9` 和 `Alt + Left/Right` 會選取分頁，`Alt + Up/Down` 會在空間之間移動。`Ctrl + 1..9` 會選取空間，`Alt + Shift + Up/Down` 會在代理之間逐步切換。`Ctrl + Space` 前置按鍵仍僅限終端機使用，因為應用程式無法為一個按鍵序列 удерживать 普通的 Ctrl 鍵。Omarchy 會將這些寫入 `~/.config/herdr-app/keys.json`，而 `omarchy-refresh-herdr-app` 會將它們還原。安裝它會選取 Herdr 的 Omarchy 主題，從那之後它便會跟隨你的 Omarchy 主題。Herdr 會為淺色模式保留一個主題、為深色模式保留一個，所以在深色與淺色 Omarchy 主題之間切換後，請在 Herdr 的主題選擇器中再選一次 Omarchy 給另一種模式使用。

T3 Code 從其官方 AppImage 版本在 `~/.local/share/t3code` 中執行，而非從套件安裝，所以它會自行更新。安裝它會詢問要從 Stable 還是 Nightly 頻道開始；之後可在 T3 Code 的設定中切換。你的對話串和設定住在 `~/.t3`，在 _Remove > AI_ 下移除 T3 Code 會連同它們一起移除。

### 本機模型

在你自己的機器上為你的程式碼代理執行開放模型。你的提示和程式碼都留在機器上；傳送給模型的東西不會離開它。從這裡開始：

```bash
omarchy agent local use best
```

或者，在頂部欄的代理面板中，選擇 + 然後 Local AI，它會在有模型適合這台機器時出現。第一次，這會安裝負責執行模型的 Podman，以及在 NVIDIA 機器上安裝 NVIDIA 的容器工具包，讓模型能使用 GPU。Omarchy 接著會為這台機器挑選建議的模型、下載它並啟動它。請預期下載量達數十 GB，且模型執行時會佔用機器的大部分記憶體：Flash Next 以其完整的 256K context 使用約 100 GiB。如果其他模型佔用了它所需的記憶體，它會被設定為停止狀態，等你停止其中一個後便可啟動。模型會在登出時停止；當你需要把記憶體用在其他事情上時，請自行停止它。

`omarchy agent local list` 會顯示這些選項，並解釋為什麼有些不適合。若要設定另一個，請執行 `omarchy agent local use <recipe>`。目前，`qwen3.8-flash-next-gufo` 和 `qwen3.8-27b-gufo` 可用於 128 GB Strix Halo 機器；27B 佔約 40 GiB，所以它會為其他工作留下空間。新的配方和建議會隨 `omarchy update` 透過套件送達。

你設定的每個模型都會在代理面板中擁有自己的一行，緊鄰你的訂閱：按播放來啟動它，按暫停來停止它並釋放其記憶體，終端機按鈕則是在它上面開啟你的代理。當多個模型能同時容納在記憶體中時，它們可同時執行；如果有一個容不下，Omarchy 會告訴你該停止哪個正在執行的模型。拖曳各行來重新排序，並對選取的行按 Delete 來移除模型及其下載。

從命令列來看，`omarchy agent local start <recipe>` 和 `omarchy agent local stop <recipe>` 做的事相同，`omarchy agent local status` 會顯示每個模型，而 `omarchy agent --local` 會在你最後啟動的模型上開啟你的預設代理（如果你的預設代理無法使用本機模型，則為 pi）。任何與 OpenAI 相容的用戶端也能連接：`status` 會顯示每個模型的位址（第一個是 `http://127.0.0.1:11435/v1`），配方名稱即為模型，金鑰位於 `~/.config/omarchy/agent-local/key`。

`omarchy agent local remove <recipe>` 會刪除一個模型和沒有其他模型在使用的下載。

第三方執行環境會標示其發行者。Omarchy 執行每個模型時都不提供網路存取。

### 本機 LLM

Omarchy 推薦兩種執行本機 LLM 模型的方式：LM Studio 和 Ollama。LM Studio 提供 GUI 介面來尋找開放權重模型、安裝它們並執行它們。這是輕鬆入門的好方法。Ollama 則提供 CLI 以類似方式執行。但如果你是本機模型的新手，我會從 LM Studio 開始。你可以在 Omarchy Menu 的 _Install > AI_ 下安裝任一個。

### Omarchy 技能

代理技能協助 AI 以特定方式使用特定工具，Omarchy 附帶了一個用於量身打造系統的預設技能。就像調整你的 Hyprland 設定、調整列，甚至從零開始建立一個新主題。它已被符號連結到 Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` 以及每個 `~/.hermes/profiles/*/skills`）的技能目錄，以及通用的 `~/.agents/skills` 位置，所以大多數 harness 會自動取得它。

但你應該將這個技能視為實驗性質。不同的模型運用它的效果各異。最好先以 plan 模式執行，讓你對代理想做什麼變更有個概念。然後，万一代理把一切弄得一團糟，請準備好復原變更，甚至呼叫 `omarchy reinstall configs`。
