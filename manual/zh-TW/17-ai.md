### 安裝與更新代理

除了 Hermes 和 OpenClaw 之外，這些代理都使用 mise 的延遲安裝：第一次啟動時安裝 CLI，之後的啟動則重複使用它。mise 也最多每四小時檢查一次已安裝代理是否有新版本，就在它啟動之前，或在背景於 shell 提示符下檢查。如果更新失敗或你處於離線狀態，就會執行已安裝的版本。`omarchy update` 會連同 Omarchy 的其餘部分一起更新已安裝的代理，而 `mup` 則只更新由 mise 管理的工具。

代理自己的更新程式，例如 `claude update`、`codex update`，或應用程式中的更新按鈕，並不會更新由 mise 管理的安裝。`codex update` 會失敗，而 `claude update` 可能回報成功，卻安裝了一個 mise 沒有追蹤的獨立副本。如果你寧願使用代理原生的安裝程式和更新程式，請將它加入 `disable_tools`；請參閱 [Preinstalled CLI tools](18-development-tools.md#preinstalled-cli-tools)。

若要在需要之前安裝所有已設定的延遲工具，請執行 `mise install --include-lazy`。這除了代理之外，還包括 Omarchy 的其他預設 CLI 工具。若要安裝單一工具或使用你自己的安裝，請參閱 [Preinstalled CLI tools](18-development-tools.md#preinstalled-cli-tools)。

`grok` 是透過 mise 的第一方 `grok` 套件安裝的，方式與 `claude` 和 `codex` 相同。執行 `grok`，或在代理面板中為它標上星號。跳過 x.ai 上的 `curl | bash` 安裝程式。那個方式會在 `~/.grok/bin` 放第二份副本、把它加到 `PATH` 的最前面，並覆寫 Omarchy 的包裝程式。

`dsh` 會在 `127.0.0.1:3080` 開啟它的瀏覽器 UI，並以啟動目錄作為預設工作區。它的瀏覽器 UI 不接受起始提示，所以 `omarchy agent prompt` 開啟它時會把提示放在你的剪貼簿中讓你貼上。Omarchy 會以 DeepSeek 的免核准權限預設集啟動它。當你使用 DeepSeek 官方的模型 API 時，DeepSeek Harness 會將工作階段記錄上傳給 DeepSeek；在它的瀏覽器 UI 中於 _Settings > General > Upload Session Log_ 下將其關閉。你傳送給它的意見回饋也會連同工作階段一起上傳，除非你用 `DSH_TELEMETRY_MODE=DISABLED` 啟動它。

### 預設代理

用代理面板中代理旁邊的星號來挑選你的預設代理，預設代理上的星號會是填滿的，或者用 `omarchy default agent <name>`，它也接受任何沒有列在那裡的 harness。如果代理尚未安裝，挑選它會先安裝它，而且它也會在應用程式啟動器中、在 Agent 旁邊，得到一個專屬的啟動器。全新的 Omarchy 會用一次性的通知邀請你設定一個，點開它就會開啟代理面板。

選擇 Claude 也會嘗試為 Chromium、Chrome、Brave、Brave Origin 和 Edge 設定它的瀏覽器擴充功能。擴充功能的設定適用於所有使用者，而且可能會要求你輸入系統密碼；取消或擴充功能安裝失敗，仍然會選取並啟動 Claude。重新啟動你的瀏覽器，如果出現提示就啟用擴充功能，然後登入 Claude 來完成與它的連線。在 Claude 中執行 `/chrome` 來檢查連線。Firefox 和 Zen 不支援這個擴充功能。如果在加入這項設定之前 Claude 就已經是你的預設值，請重新選取它一次來安裝擴充功能。

一旦你選好了，`Super + Shift + Ctrl + A` 會在專用的終端機視窗中啟動預設代理（或者如果你還沒選，就會叫出挑選器）。你也可以用 `omarchy agent prompt "Review this project"` 讓它直接進入工作。Freebuff 和 DeepSeek Harness 不接受起始提示，所以它們開啟時會改把提示放在你的剪貼簿中讓你貼上。以這種方式啟動的代理會各自以「不用停下來詢問」的模式無人值守地執行，所以要做好它們真的會動手做事的準備！MiniMax Code 的互動式工作階段沒有這種模式，所以它會照常要求權限。而且由於代理拒絕記住對你家目錄的信任，從 `$HOME` 啟動時會改在 `~/Work` 中開始。

還有終端機捷徑：`a` 會在目前的終端機中內嵌執行預設代理，而 `c`、`cx` 和 `cy` 則會直接啟動 OpenCode、Claude Code 和 Codex（一樣是在它們的自動核准模式中）。主題變更也會同步到代理：Claude Code、Pi、OpenCode 和 Hermes（一旦 Omarchy 已安裝它）在你切換 Omarchy 主題時都會跟著變。

### 你的代理指示

給每個代理的個人規則放在 `~/.agents/AGENTS.md`，就在 `~/.agents/skills` 中共用技能的旁邊。用代理面板中 + 旁邊的文件圖示開啟它，或者用 `omarchy agent instructions --edit`，它也會把該檔案連結進每個保留自己全域檔案的 harness 中：`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`~/.pi/agent/AGENTS.md`、`~/.config/opencode/AGENTS.md`、Copilot 的 `~/.copilot/copilot-instructions.md`，依此類推。Crush 和 Amp 讀取的是 `~/.config/AGENTS.md` 連結，而 omp、Kimi 和 DeepSeek Harness 則直接讀取 `~/.agents/AGENTS.md`。挑選預設代理也會連結它。如果你已經有一個指示檔案，而且還沒有共用的那一份，它就會成為共用的那一份；否則它會以 `.bak` 的形式保留在連結旁邊。安裝另一個代理後，請執行 `omarchy agent instructions` 來重新連結。

### 代理面板

頂部欄有一個代理圖示。在你設定代理之前，它的面板會提供三種開始方式：登入 Claude、Codex、Grok、Gemini、Muse、Cursor 或 Copilot 訂閱，或者在 More 之下選一個 OpenCode Go、MiniMax、Synthetic 或 Z.ai 編碼方案；用 Fireworks、OpenCode Zen and Go、OpenRouter 以量計費，或者在 More 之下用 DeepSeek 或 OpenCode 能登入的任何其他供應商，全部都在 OpenCode 中執行；或者在你的電腦裝得下的情況下，執行最適合它的最佳模型。你第一個完成的那一個就會成為你的預設代理，之後面板中的 +，或者 Omarchy Menu 中的 _Agent > Add_，會再次提供同樣的三種方式。之後，面板會把每個訂閱都放在同一頁上：每個代理和帳戶連同它的方案、每個 5 小時工作階段與每週額度的用量表與其重設前的剩餘時間（將滑鼠游標停在上面可看到確切百分比），或者剩餘的預付餘額，全都在一行輪流顯示你所有代理總共用量的文字之下，像是本週的 tokens 和你最常用到的模型。在 _Make something cool_ 之下，它會提供新主題、plugin、app 或遊戲的起始提示，將工作交給你的預設代理。Apps 的建置方式與 Omarchy 自己的 Hype、Monologue 和 Omacut 相同，都是用 C++ 和 Qt Quick，並遵循 omarchy-make-app 代理技能，而且它們需要的編譯器和 Qt 元件都已安裝好。Games 是位於 `~/Games/vibes` 中的單一 three.js 頁面，遵循 omarchy-make-game 代理技能，而且全都從目前主題中的一個 Game Vibes 啟動器開啟；它們會從網路載入 three.js，所以需要連線才能開始。Claude Code、Codex、Grok、Kimi、Cursor 及其 Grok Bot 額度、GitHub Copilot、Muse、Gemini（透過 Antigravity）和 Devin 開箱即涵蓋其額度，Kimchi 涵蓋其方案、預付點數和支出預算，而 Hermes、Mistral Vibe 和 Qwen Code 會在你用過它們之後顯示其工作階段和 tokens。你透過 pi、omp 或 opencode 使用的供應商方案和金鑰也會顯示出來：OpenCode Zen and Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan 和 Synthetic 連同其額度；OpenRouter 和 DeepSeek 連同其預付餘額；Fireworks 連同它在過去 30 天的支出。你在自己硬體上執行的模型所產生的 tokens 也計入總數；模型本身有它們專屬的面板，詳見 [Local models](#local-models) 一節所述。每個代理只計一次，計在向它收費的那一方名下，無論你透過多少個 harness 驅動它。

左鍵點擊欄圖示或按下 `Super + Ctrl + X` 叫出面板，右鍵點擊啟動你的預設代理，中鍵點擊則重新整理。它背後的使用記錄每 15 分鐘由 `omarchy agent usage update` 重新產生，而且面板甚至可以透過同步資料夾合併來自你其他機器的用量。完整的設定請參閱 `$OMARCHY_PATH/shell/plugins/agents/` 之下的 README。

### 多個訂閱

如果你付費購買了不只一個 Claude、Codex 或 Grok 方案——例如一個個人的 Max 和一個工作的——Omarchy 可以讓它們全都保持登入狀態，並在它們之間移動。用代理面板中的 + 新增訂閱，它會直接在那裡引導你完成，或者用 `omarchy agent account add claude Work`（或者 `codex`，或者 `grok`）。同一個 + 和指令也能登入 Gemini（`gemini`）和 OpenCode（`opencode`），並在 OpenCode 中儲存 Fireworks（`fireworks`）或 OpenRouter（`openrouter`）API 金鑰；這個指令還能登入 Copilot（`copilot`）、Cursor（`cursor`）和 Muse（`muse`）。那些每一個只保留一個登入。缺少 CLI 時它會安裝它。供應商的第一個帳戶會透過你一般的瀏覽器登入，就在 CLI 一直在找的地方。之後的每一個都會透過隱私視窗登入，所以你瀏覽器已經登入的那個帳戶就不會被誤挑；請在那裡登入你要新增的帳戶，而且先關閉你已經開啟的任何隱私視窗。千萬不要為了做這件事而登出 CLI：登出會註銷已儲存的登入，那個帳戶就必須重新新增。

若要透過 SSH 將你的訂閱登入複製到另一台 Omarchy 機器，請執行 `omarchy agent account copy user@laptop`。當目的地沒有安裝接收端時，傳送端會提供一個暫時接收端，所以較舊的 Omarchy 機器不用更新也能接收帳戶。已安裝的接收端優先。這會複製所有 Claude、Codex 和 Grok 訂閱；加入供應商名稱來選取它們，例如 `omarchy agent account copy laptop claude`。帳戶名稱和指令 ID 會與來源相符，包括目的地上已經存在的帳戶。無關的目的地帳戶如果名稱衝突，會被加上數字尾碼，而設定、技能、plugins 和對話記錄則各自留在各台機器上。

目的地已有的憑證會被保留。已經在那裡登入的來源帳戶，其名稱會被同步但不會取代其憑證；其他帳戶則會加在它旁邊。若要取代相符帳戶已儲存的憑證，請先在目的地結束該帳戶的工作階段，然後使用 `omarchy agent account copy --replace laptop claude`。全新的目的地也會取得來源目前使用的帳戶和切換偏好；已經建立好的目的地則會保留它自己的。

憑證會透過 SSH 傳輸，並儲存在目的地的私人檔案中，所以只複製到你信任的機器。這是一次性的複製，不是持續的同步。Codex 的重新整理 tokens 可能被另一台機器輪替，導致複製過去的登入需要續期；在多台機器上同時使用時，各自獨立登入仍然是最可靠的選擇。請參閱 [Codex's account authentication guidance](https://developers.openai.com/codex/auth/ci-cd-auth)。

每個供應商一次只有一個帳戶是使用中的，而且每個新工作階段都會以它開始：`cx`、`cy`、普通的 `claude`、`codex` 或 `grok`、任何透過 `omarchy agent` 啟動的東西，以及在 `PATH` 上找到 CLI 的腳本或編輯器。用 `omarchy agent account use work` 切換（再用 `omarchy agent account use main` 切回去），或者在面板中按下帳戶的數字再按 `Enter`（或點擊它的星號）。正在執行的 Claude 工作階段也會切換，從它們的下一則訊息起生效：每個 Claude 工作階段都在 `~/.claude` 中執行，那裡永遠保留使用中帳戶的登入。由較舊的 Omarchy 在帳戶自己的資料夾中啟動的 Claude 工作階段，會一直保留該登入直到結束為止，所以切換時會點名那些工作階段，並在它們消失後自行完成。正在執行的 Codex 和 Grok 工作階段會留在它們開始時的那個帳戶上。對話記錄、設定、技能和 plugins 在各帳戶間共用，所以在同一個資料夾中執行 `claude --continue` 就會在新帳戶上接著你上次離開的地方繼續。

在有多個帳戶的情況下，面板會並排顯示每個帳戶的額度，並在使用中的那個帳戶上標示填滿的星號。當使用中的帳戶超過某個額度的 95% 時，Omarchy 會通知你，點擊通知就會切換到剩餘空間最多的帳戶。它絕不會自行切換。用 `omarchy agent account threshold 90` 變更門檻。如果每個帳戶都超過門檻，你會收到一次通知，連同哪個帳戶最先釋出額度。當使用中的帳戶距離其門檻在 15 個百分點以內（預設時是 80%）時，其額度每三分鐘檢查一次，而不是每 15 分鐘。

`omarchy agent account list` 顯示每個帳戶及其最新額度，`omarchy agent account remove work` 會忘掉一個帳戶，而 `omarchy agent account rename primary Hey` 會重新命名一個帳戶（或在面板中點擊帳戶的名稱）。這些指令作用於你預設代理的帳戶；若要觸及另一個供應商，請先點名它，例如 `omarchy agent account use codex side`。你已經在 `~/.claude` 或 `~/.codex` 中已有的登入是 _Main_ 帳戶。Codex 的會留在原處；Claude 的則會在另一個帳戶使用期間，待在它自己的資料夾中。閒置超過大約八小時的帳戶可能會顯示 _Sign-in required_；點擊它就能直接在面板中重新登入該帳戶，或者切換到它並啟動一個工作階段，它就會自行重新整理登入。你用 `claude mcp add` 新增的 MCP 伺服器會觸及每個 Claude 帳戶，因為它們都在 `~/.claude` 中執行；對於 Codex 和 Grok，你在加入某個帳戶時已有的伺服器會跟著到那個帳戶，但之後新增的只會到你加入它們時所在的帳戶。Claude Desktop 保留它自己的登入，而且用 CLI 二進位檔絕對路徑設定的 Codex 或 Grok 工具不會跟著切換。明確的 `CLAUDE_CONFIG_DIR`、`CODEX_HOME` 或 `GROK_HOME` 會優先於所選的帳戶。

### 崩潰診斷

Omarchy 會監看 systemd-coredump 以找出程序崩潰。一旦你挑選了預設代理，你任何傾印核心的程式都會帶來一個 "Process crashed" 通知——點擊它，崩潰就會連同 Omarchy 的 omarchy-diagnose-crash 技能一併交給你的預設代理，該技能會引導代理從核心傾印中建立事實，並判斷該崩潰是否值得向上游回報。你也可以用 `omarchy agent crash <pid>` 手動對 `coredumpctl list` 中的任何 PID 執行它。

監看預設是開啟的。在 _Trigger > Toggle > Crash Capture Off_ 之下把它關掉（或用 `omarchy toggle crash-capture`），通知就會停止；`omarchy agent crash <pid>` 手動執行仍然有效。

崩潰也可以一次按一個程式來靜音，這正是診斷最後會提供給你的選項。`omarchy crash mute hyprland` 只停止該程式的通知，`omarchy crash mute hyprland off` 會把它們帶回來，而單獨執行 `omarchy crash mute` 則會列出你已靜音的項目。它同樣高興地接受二進位檔的路徑和它的名稱，所以 `omarchy crash mute /usr/bin/hyprland` 做的是同一件事。為名稱中有空格者加上引號，例如 `omarchy crash mute 'Some App'`。其他一切都仍然會通知，而且被靜音的程式仍然會崩潰——這只是隱藏提醒，它不修復任何東西。

### 桌面應用程式

_Install > AI_ 選單還備有一些圖形化 AI 應用程式：Amp Desktop、Antigravity Desktop、ChatGPT desktop app、Claude desktop app（Anthropic 的 Linux beta 版，有 Chat、Cowork 和 Claude Code 分頁）、用來與 xAI 模型聊天的 Grok Bot、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexity desktop app 和 T3 Code。Grok Bot 是桌面聊天應用程式。編碼代理則是 `grok` 指令。

Hermes Desktop 是需要知道的那一個，因為一台機器只有一個 Hermes，而那個 Hermes 是屬於這個應用程式的：Hermes 永遠只能透過該應用程式安裝，而預設代理執行的 `hermes` 指令也是該應用程式的。選擇 Hermes 作為預設代理，安裝的東西與 _Install > AI_ 那個項目相同：套件，以及由 Hermes 自己的安裝程式在 `~/.hermes` 之下設定好的 Hermes runtime，第一次需要幾分鐘。終端機的 `hermes` 指令、預設代理和應用程式全都使用那一個 runtime，而且它會用 `hermes update` 自行更新，而不是等 Omarchy 發布新版。安裝它還會把 Omarchy 主題作為名為 `omarchy` 的外觀交給 Hermes，每個 Hermes 介面在你切換主題時都會跟著變；如果你不想讓它這樣，請在 Hermes 的 Appearance 設定中或用 `/skin` 挑另一個，而 Omarchy 不會干涉那個選擇。在 _Remove > AI_ 之下移除該應用程式會先關閉 Hermes，連閘道一併關閉，把那個 runtime 跟著帶走，並保留你的聊天、記憶，和 Hermes 為自己寫的技能，除非你另外指示：它會詢問那些資料和你的連線設定是否也該一併移除，預設為否。

OpenClaw 的桌面體驗是它的 Control UI，它會以自己的本機閘道為後盾，以 web app 的形式開啟。OpenClaw 存在 `~/.openclaw` 中，並會自我更新：使用 Control UI 的 "Update Gateway" 按鈕或執行 `openclaw update`，閘道就會在新版本上重新啟動。Omarchy 只挑選全新安裝的起始版本。OpenClaw 也可以是你的預設代理：在 _Agent > Harness_ 之下選擇它會設定 `~/.openclaw` 中同一份副本，而代理會開啟連接到其閘道的 OpenClaw 終端機 UI。在 _Remove > AI_ 之下移除 OpenClaw，會把閘道服務和應用程式跟著帶走，然後詢問 `~/.openclaw` 是否也該一併移除，因為那裡放著你的聊天和憑證，連同 OpenClaw 本身和它下載的 plugin runtimes；預設會保留它，而且重新安裝 OpenClaw 會把它接回來。

Herdr Desktop 是 [Herdr](https://herdr.dev) 桌面應用程式：spaces、tabs，以及 panes of terminals 和編碼代理，即使你關閉視窗，它們也持續在其核心中執行。它來自 Herdr 自己的安裝程式而不是套件，所以它住在 `~/.local/share/herdr-app`，當你還沒有的時候，它會在 `~/.local/bin/herdr-core` 帶來它的核心，並會兩者都自我更新。它位於 Omarchy 在 `Super + Ctrl + Return` 上隨附的 `herdr` 指令旁邊，而不是取代它，而且得到那個指令的直接按鍵：`Alt + Return` 和 `Alt + Shift + Return` 會向下或向右分割 pane，`Alt + Escape` 關閉它，`Ctrl + Alt + Arrow` 在 panes 之間移動，`Alt + 1..9` 和 `Alt + Left/Right` 挑選 tab，以及 `Alt + Up/Down` 在 spaces 之間移動。`Ctrl + 1..9` 挑選 space，`Alt + Shift + Up/Down` 逐個切換代理。`Ctrl + Space` 前綴鍵仍然只用於終端機，因為應用程式無法為序列保留一個普通的 Ctrl 鍵。Omarchy 會把這些寫入 `~/.config/herdr-app/keys.json`，而 `omarchy-refresh-herdr-app` 會把它們放回去。安裝它會挑選 Herdr 的 Omarchy 主題，從此它會跟著你的 Omarchy 主題。在淺色模式和深色模式下 Herdr 各保留一個主題，所以在深色和淺色 Omarchy 主題之間切換後，請在 Herdr 的主題挑選器中再為另一種模式挑選一次 Omarchy。

T3 Code 從位於 `~/.local/share/t3code` 的官方 AppImage 版本執行，而不是從套件執行，所以它會自我更新。安裝它時會詢問要從 Stable 通道還是 Nightly 通道開始；日後在 T3 Code 的設定中切換。你的討論串和設定住在 `~/.t3`，而在 _Remove > AI_ 之下移除 T3 Code 會把它們跟著帶走。

### 本機模型

在你自己的機器上為你的編碼代理執行開放模型。你的提示和程式碼都留在機器上；傳送給模型的任何東西都不會離開它。從以下開始：

```bash
omarchy models use best text
```

那會為這台機器設定最佳的文字模型，也就是你的代理會用到的那種。圖像、影片和音樂模型也各有自己的最佳選擇：`omarchy models use best image`、`video` 或 `music`。執行 `omarchy models use best` 來查看這台機器對每一種的挑選。

或者從頂部欄中 agents 圖示旁邊的 sparkles 圖示開啟本機模型面板，或用 Super + Ctrl + Alt + X，然後選 +。當有模型適合這台機器時，這個圖示就會出現。Podman，也就是執行模型的程式，隨 Omarchy 附帶，NVIDIA 機器上的 NVIDIA container toolkit 也一樣，那讓它們可以使用 GPU；如果其中任何一個遺失，第一次設定就會安裝它。接著 Omarchy 會挑選這台機器的推薦模型、下載它並啟動它。預期下載量會有數十 GB，而且模型執行期間機器的大部分記憶體都會在使用中：Flash Next 在其完整的 256K 上下文下使用約 100 GiB。如果其他模型佔著它需要的記憶體，它會以停止的狀態設定好，等你停止其中一個時就能啟動。模型會在登出時停止；當你需要記憶體做其他事時，請自己停掉它。

`omarchy models list` 顯示選項，並解釋為什麼有些不適合。若要設定另一個，請執行 `omarchy models use <recipe>`。今天，`qwen3.8-flash-next-gufo` 和 `qwen3.8-27b-gufo` 可用於 128 GB Strix Halo 機器；27B 大約需要 40 GiB，所以它為其他工作留下了空間。在配備 Intel Arc B390 的 64 GB 筆電上，`qwen3.6-35b-a3b-llamacpp` 大約以 30 GiB 執行。新的 recipes 和推薦會透過套件隨著 `omarchy update` 送達。

你設定的每個模型都會在本機模型面板中擁有自己的一列：按播放來啟動它，按暫停來停止它並釋放其記憶體，以及按終端機按鈕在它上面開啟你的代理。頂部有一條長條，顯示機器的記憶體如何在 Omarchy 本身（系統和你的應用程式）、每個正在執行的模型，以及空閒的空間之間分配。指向一個已停止的模型，該長條會顯示它是否裝得下，或者還差多少。多個模型在能一起裝進記憶體時可以同時執行；如果有一個裝不下，Omarchy 會說該停止哪個正在執行的模型。拖曳各列的標誌來重新排序，並在所選的列上按 Delete 來移除模型及其下載。

你設定的每個編碼模型也都會在應用程式啟動器中擁有自己的項目，以模型名稱並配上其製造商的標誌，就像登入 Claude、Codex 或 Grok 所增加的那樣。它會在那個模型上開啟你的代理，而且如果模型尚未執行，會先啟動它：終端機會顯示它載入中，並在它就緒後交給代理。移除模型也會移除它的項目。

不是每個模型都是用來編碼的。圖像、影片和音樂模型反而會在 Fantasi 中開啟，那是 Omarchy 用來以這台機器上執行的模型製作圖片、影片和音樂的應用程式，可以在那裡挑選，或者從它們在本機模型面板中的那一列挑選。

模型會完全按照它設定好的樣子持續執行，所以 Omarchy 更新永遠不會在你的代理之下重新啟動它。當 Omarchy 有你已設定模型的較新 runtime 或較新 weights 時，它的那一列會顯示一個更新按鈕：按下它，模型會在背景中重新設定、只下載已變更的部分，並在新版本上重新啟動。原本停止的模型會保持停止。`omarchy models update` 會從終端機對每個模型做同樣的事。

從指令列，`omarchy models start <recipe>` 和 `omarchy models stop <recipe>` 做的也相同，`omarchy models status` 顯示每個模型，而 `omarchy agent --local-model <recipe>` 會在 pi 中開啟那個模型，無論你的預設代理是誰。若要讓你的本機模型成為代理快速鍵、Quake console 和 _Make something_ 所開啟的對象，請執行 `omarchy default agent local` 或在 _Agent > Harness_ 之下挑選 _Local model_。pi 也會在它自己的模型挑選器中列出你設定的每個模型，以及你已與其配對的機器上的模型，所以普通的 `pi` 也能觸及它們。任何與 OpenAI 相容的用戶端也能連接：`status` 顯示每個模型的位址（第一個是 `http://127.0.0.1:11435/v1`），recipe 名稱就是模型，而金鑰在 `~/.config/omarchy/agent-local/key` 中。

`omarchy models remove <recipe>` 會刪除模型以及沒有其他模型使用的下載內容。

第三方 runtimes 會以其發布者標示。Omarchy 執行每個模型時都不提供網路存取。

### 本機 LLM

Omarchy 推薦兩種執行本機 LLM 模型的方式：LM Studio 和 Ollama。LM Studio 提供了 GUI 介面，用來尋找開放權重的模型、安裝它們並執行它們。這是輕鬆上手的好方法。Ollama 提供 CLI 以類似方式完成。可是如果你是本機模型的新手，我會從 LM Studio 開始。你可以在 Omarchy Menu 的 _Install > AI_ 之下安裝其中任一種。

### Omarchy 技能

代理技能幫助 AI 以特定方式使用特定工具，而 Omarchy 隨附了七個這樣的技能。omarchy 技能涵蓋量身打造系統，像是調整你的 Hyprland 設定或調整欄位。omarchy-make-theme、omarchy-make-plugin、omarchy-make-app 和 omarchy-make-game 涵蓋製作新東西，omarchy-contribute 涵蓋回報 bug 或向 upstream 傳送修復，而 omarchy-diagnose-crash 則會逐步處理崩潰的核心傾印。它們被符號連結進 Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` 和每個 `~/.hermes/profiles/*/skills`）的技能目錄，以及通用的 `~/.agents/skills` 位置，所以大多數 harnesses 都會自動挑到它們。你自己的同名技能資料夾會優先。

不過你應該把這些技能當作實驗性的。不同的模型運用它的成效會有所不同。最好先在 plan mode 中執行，這樣你就能大概知道代理想要變更什麼。然後做好回復變更、甚至在代理把一切搞得一團糟時調用 `omarchy reinstall configs` 的準備。
