Omarchy 隨附下列程式設計 agent 的啟動器，但不會替你決定預設使用哪一個。從 _Install > AI > CLI_ 安裝其中一個，接著依提示進行驗證。Hermes 與 OpenClaw 是例外：選擇其中任一個都會安裝一份可自行更新的專屬副本，詳見下方的 _桌面應用程式_。

### 安裝與更新 agent

除了 Hermes 與 OpenClaw 之外，每個 agent 都是來自 Omarchy 自家儲存庫的套件。從 _Install > AI > CLI_ 或使用 `omarchy install ai cli <command>` 安裝其中一個，並從 _Remove > AI > CLI_ 再次移除，移除時會保留其登入狀態與歷史紀錄。選擇一個尚未安裝的 agent 時也會一併安裝：在 agent 面板中將其標記星號、使用 `omarchy default agent <name>` 選擇它，或登入其訂閱。Omarchy 會在 agent 發布每個新版本的一小時內，將其發布到所有頻道，而 `omarchy update` 會連同系統其他部分一起安裝它。

由於 pacman 會讓它們保持在最新狀態，agent 自己的更新程式已停用：`claude update` 或應用程式中的更新按鈕無事可做。如果你寧願使用 agent 自己的安裝程式來執行它，就使用那個安裝程式，並不要安裝 Omarchy 的套件；你的 `PATH` 上已有的副本會被視為已安裝。請避開會將第二份副本放在 Omarchy 之前於 `PATH` 上的 `curl | bash` 安裝程式，例如 x.ai 為 `grok` 提供的那個。

`dsh` 會在 `127.0.0.1:3080` 開啟其瀏覽器 UI，並以啟動目錄作為預設工作區。它的瀏覽器 UI 不接受起始提示，因此 `omarchy agent prompt` 會開啟它，並將提示放在你的剪貼簿中供你貼上。Omarchy 會以 DeepSeek 的無需核准權限預設集啟動它。當你使用 DeepSeek 官方模型 API 時，DeepSeek Harness 會將工作階段記錄上傳給 DeepSeek；在其瀏覽器 UI 的 _Settings > General > Upload Session Log_ 下將其關閉。你傳送給它的意見回饋也會連同工作階段一起上傳，除非你以 `DSH_TELEMETRY_MODE=DISABLED` 啟動它。

### 預設 agent

使用 agent 面板中 agent 旁的星號來選擇你的預設 agent，預設的那個星號會被填滿，或使用 `omarchy default agent <name>`，它也接受面板上沒有列出的任何 harness。如果 agent 尚未安裝，選擇它會先安裝它，它也會在應用程式啟動器中獲得自己的一個啟動器，緊鄰 Agent。全新安裝的 Omarchy 會透過一次性通知邀請你設定一個，點擊後會開啟 agent 面板。

選擇 Claude 也會嘗試為 Chromium、Chrome、Brave、Brave Origin 與 Edge 設定其瀏覽器擴充功能。擴充功能設定適用於所有使用者，且可能要求你輸入系統密碼；取消或擴充功能安裝失敗，仍會選擇並啟動 Claude。重新啟動你的瀏覽器，在出現提示時啟用擴充功能，並登入 Claude 以完成連接。在 Claude 中執行 `/chrome` 來檢查連線。Firefox 與 Zen 不支援此擴充功能。如果在新增此設定之前 Claude 就已經是你的預設，請再次選擇它以安裝擴充功能。

選好之後，`Super + Shift + Ctrl + A` 會在專屬終端機視窗中啟動預設 agent（若你尚未選擇，則會開啟選擇器）。你也可以用 `omarchy agent prompt "Review this project"` 讓它直接進入任務。Freebuff 與 DeepSeek Harness 不接受起始提示，因此它們會開啟並將提示放在你的剪貼簿中供你貼上。以這種方式啟動的 agent 會在各自的不要停下來詢問模式下無人看管地執行，所以請做好它們真的會動手做事的準備！MiniMax Code 的互動式工作階段沒有這種模式，因此它會照常要求權限。而且由於 agent 拒絕記住對你家目錄的信任，從 `$HOME` 啟動時會改為在 `~/Work` 中開始。

也有終端機捷徑：`a` 會在目前終端機中內嵌執行預設 agent，而 `c`、`cx`、`cy` 與 `ca` 會直接啟動 OpenCode、Claude Code、Codex 與 Antigravity（同樣以其自動核准模式）。主題變更也會同步給 agent：當你切換 Omarchy 主題時，Claude Code、Pi、OpenCode 與 Hermes（一旦 Omarchy 已安裝它）都會跟著變更。

### 你的 agent 指示

給每個 agent 的個人規則都放在 `~/.agents/AGENTS.md`，就在 `~/.agents/skills` 中的共用 skills 旁邊。用 agent 面板中 + 旁的文件圖示開啟它，或使用 `omarchy agent instructions --edit`，它也會將其連結到每個保有自己全域檔案的 harness 中：`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`~/.pi/agent/AGENTS.md`、`~/.config/opencode/AGENTS.md`、Copilot 的 `~/.copilot/copilot-instructions.md`，依此類推。Crush 與 Amp 會讀取 `~/.config/AGENTS.md` 連結，而 omp、Kimi 與 DeepSeek Harness 會直接讀取 `~/.agents/AGENTS.md`。選擇預設 agent 時也會連結它。如果你已經有一個指示檔案，且尚無共用檔案，它就會成為共用檔案；否則它會以 `.bak` 的形式保留在連結旁。安裝另一個 agent 後，執行 `omarchy agent instructions` 重新連結。

### agent 面板

頂部列有一個 agent 圖示。在你設定 agent 之前，其面板提供三種開始方式：登入 Claude、Codex、Grok、Gemini、Muse、Cursor 或 Copilot 訂閱，或在 More 之下登入 OpenCode Go、MiniMax、Synthetic 或 Z.ai 程式設計方案；使用 Fireworks、OpenCode Zen and Go、OpenRouter 以按用量付費，或在 More 之下使用 DeepSeek 或 OpenCode 可登入的任何其他提供者，這些全都在 OpenCode 中執行；或在你的電腦適合時，執行最適合它的最佳模型。你完成的第一個會成為你的預設 agent，而面板中的 + 之後也會提供相同的三種方式。之後，面板會將每個訂閱放在同一頁上：每個 agent 與帳戶及其方案、其 5 小時工作階段與每週限制各自的用量計量表及距離重置的時間（將滑鼠懸停以查看確切百分比），或剩餘的預付餘額，上方有一行會輪流顯示你在所有這些服務中的使用情況，例如本週的 tokens 與你最常使用的模型。在 _Make something cool_ 之下，它提供用於新主題、plugin、app 或遊戲的入門提示，並將任務交給你的預設 agent。Apps 的建置方式與 Omarchy 自己的 Hype、Monologue 與 Omacut 相同，使用 C++ 與 Qt Quick，遵循 omarchy-make-app agent skill，而且它們所需的編譯器與 Qt 元件都已安裝。Games 是位於 `~/Games/vibes` 中的單一 three.js 頁面，遵循 omarchy-make-game agent skill，且全都從目前主題中的一個 Game Vibes 啟動器開啟；它們會從網路載入 three.js，因此需要連線才能開始。Claude Code、Codex、Grok、Kimi、Cursor 及其 Grok Bot 額度、GitHub Copilot、Muse、Gemini（透過 Antigravity）與 Devin 都已開箱即用地涵蓋其限制，Kimchi 則涵蓋其方案、預付點數與支出預算，而 Hermes、Mistral Vibe 與 Qwen Code 會在你使用過後顯示其工作階段與 tokens。你透過 pi、omp 或 opencode 使用的提供者方案與金鑰也會顯示：OpenCode Zen and Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan 與 Synthetic 及其限制；OpenRouter 與 DeepSeek 及其預付餘額；Fireworks 則顯示過去 30 天的支出。你在自己硬體上執行的程式設計模型也有自己的專屬行列，且其 tokens 也會計入總計，如 [本機模型](#local-models) 下所述。每個 agent 只會在其計費者名下計算一次，無論你透過多少個 harness 驅動它。

以左鍵點按列圖示或按下 `Super + Ctrl + X` 開啟面板，以右鍵點按啟動你的預設 agent，並以中鍵點按重新整理。其背後的使用紀錄每 15 分鐘由 `omarchy agent usage update` 重新產生，且面板甚至可以透過同步資料夾合併來自你其他機器的使用情況。請參閱 `$OMARCHY_PATH/shell/plugins/agents/` 下的 README 以了解完整設定。

### 多個訂閱

如果你付費訂閱了多個 Claude、Codex 或 Grok 方案——例如個人 Max 與工作用的——Omarchy 可以讓它們全都保持登入，並在它們之間切換。透過 agent 面板中的 + 新增訂閱，它會直接在那裡引導你完成，或使用 `omarchy agent account add claude Work`（或 `codex`，或 `grok`）。同樣的 + 與指令也可登入 Gemini（`gemini`）與 OpenCode（`opencode`），並在 OpenCode 中儲存 Fireworks（`fireworks`）或 OpenRouter（`openrouter`）API 金鑰；該指令也可登入 Copilot（`copilot`）、Cursor（`cursor`）與 Muse（`muse`）。這些每個都只保留一個登入。缺少時它會安裝 CLI。提供者的第一個帳戶會透過你平常的瀏覽器登入，就在 CLI 一直尋找的地方。之後的每個帳戶都會透過私人視窗登入，因此你的瀏覽器已登入的帳戶不會被誤選；在該處登入你要新增的帳戶，並先關閉你已開啟的任何私人視窗。切勿為此登出 CLI：登出會撤銷已儲存的登入，且該帳戶將必須重新新增。

若要透過 SSH 將你的訂閱登入資訊複製到另一台 Omarchy 機器，請執行 `omarchy agent account copy user@laptop`。當目的地沒有安裝接收程式時，傳送方會提供一個臨時接收程式，因此較舊的 Omarchy 機器無需更新即可接收帳戶。已安裝的接收程式優先。此操作會複製所有 Claude、Codex 與 Grok 訂閱；新增提供者名稱以選取它們，例如 `omarchy agent account copy laptop claude`。帳戶名稱與指令 ID 與來源相符，包括目的地已存在的帳戶。若名稱衝突，無關的目的地帳戶會獲得數字後綴，而設定、skills、plugins 與對話歷史則各機器各自保留。

現有的目的地憑證會保留。已在那裡登入的來源帳戶會同步其名稱，但不會取代其憑證；其他帳戶則會新增在其旁邊。若要取代相符帳戶已儲存的憑證，請在結束目的地該帳戶的工作階段後，使用 `omarchy agent account copy --replace laptop claude`。全新的目的地也會獲得來源使用中的帳戶與切換偏好設定；已建立的目的地則保留自己的。

憑證會透過 SSH 傳輸，並儲存在目的地的私人檔案中，因此只能複製到你信任的機器。這是一次性複製，而非持續同步。Codex 更新權杖可能會被另一台機器輪換，使複製的登入需要續訂；若要在多台機器上同時使用，各自獨立登入仍是最可靠的選擇。請參閱 [Codex 的帳戶驗證指南](https://developers.openai.com/codex/auth/ci-cd-auth)。

每個提供者一次只有一個帳戶啟用，且每個新的工作階段都會以該帳戶開始：`cx`、`cy`、普通的 `claude`、`codex` 或 `grok`、透過 `omarchy agent` 啟動的任何東西，以及在 `PATH` 上找到 CLI 的腳本或編輯器。使用 `omarchy agent account use work` 切換（並以 `omarchy agent account use main` 切換回來），或在面板中按下帳戶的號碼然後按 `Enter`（或點擊其星號）。執行中的 Claude 工作階段也會切換，從其下一則訊息開始：每個 Claude 工作階段都在 `~/.claude` 中執行，該處始終保有使用中帳戶的登入資訊。由較舊的 Omarchy 在帳戶自己的資料夾中開始的 Claude 工作階段，會保留該登入資訊直到它結束，因此切換操作會列出那些工作階段的名稱，並在它們消失後自行完成。執行中的 Codex 與 Grok 工作階段會留在它們開始時所用的帳戶。對話歷史、設定、skills 與 plugins 在帳戶間共用，因此在同一資料夾中的 `claude --continue` 會在新帳戶上從你上次中斷的地方接續。

擁有多個帳戶時，面板會並排顯示每個帳戶的限制，並在使用中的帳戶上以填滿的星號標記。當使用中帳戶超過限制的 95% 時，Omarchy 會通知你，點擊通知會切換到餘裕最多的帳戶。它永遠不會自行切換。使用 `omarchy agent account threshold 90` 變更門檻。如果每個帳戶都超過門檻，你會收到一次通知，並告知哪個帳戶最先釋出。當使用中帳戶距離其門檻在 15 個百分點以內（預設為 80%）時，其限制會每三分鐘檢查一次，而非每 15 分鐘。

`omarchy agent account list` 會顯示每個帳戶及其最新限制，`omarchy agent account remove work` 會忘記一個帳戶，而 `omarchy agent account rename primary Hey` 會重新命名一個帳戶（或在面板中點擊帳戶名稱）。這些指令作用於你預設 agent 的帳戶；若要存取其他提供者，先指定其名稱，例如 `omarchy agent account use codex side`。你已經在 `~/.claude` 或 `~/.codex` 中持有的登入是 _Main_ 帳戶。Codex 的會留在原地；Claude 的則在另一個帳戶啟用時，等待在自己專屬的資料夾中。閒置超過約八小時未使用的帳戶可能會顯示 _Sign-in required_；點擊它即可直接在面板中重新登入該帳戶，或切換到它並開始工作階段，這會自行重新整理登入資訊。你用 `claude mcp add` 新增的 MCP 伺服器會到達每個 Claude 帳戶，因為它們都在 `~/.claude` 中執行；對於 Codex 與 Grok，你在新增帳戶當時已有的伺服器會一併跟隨到該帳戶，但之後新增的只會到達你新增它們時所在的帳戶。Claude Desktop 保有自己專屬的登入，而以 CLI 二進位檔絕對路徑設定的 Codex 或 Grok 工具不會跟隨切換。明確的 `CLAUDE_CONFIG_DIR`、`CODEX_HOME` 或 `GROK_HOME` 優先於所選帳戶。

### 崩潰診斷

Omarchy 會監看 systemd-coredump 以偵測程式崩潰。一旦你選了預設 agent，你的任何程式傾印核心時都會出現「Process crashed」通知——點擊它，崩潰就會連同 Omarchy 的 omarchy-diagnose-crash skill 一起交給你的預設 agent，該 skill 會引導 agent 從核心傾印中建立事實，並判斷該崩潰是否值得向上游回報。你也可以用 `omarchy agent crash <pid>`，針對 `coredumpctl list` 中的任何 PID 手動執行它。

監看預設開啟。在 _Trigger > Toggle > Crash Capture Off_ 下將其關閉（或使用 `omarchy toggle crash-capture`），通知即停止；`omarchy agent crash <pid>` 仍可手動使用。

崩潰也可以一次針對一個程式靜音，這正是診斷在最後提供給你的選項。`omarchy crash mute hyprland` 只停止該程式的通知，`omarchy crash mute hyprland off` 使其恢復，而單獨的 `omarchy crash mute` 會列出你已靜音的項目。它接受二進位檔的路徑與名稱一樣順手，因此 `omarchy crash mute /usr/bin/hyprland` 也做同樣的事。將含有空格的名稱加上引號，例如 `omarchy crash mute 'Some App'`。其他一切仍會通知，且被靜音的程式仍會崩潰——這只是隱藏提醒，並不會修好任何東西。

### 桌面應用程式

_Install > AI > Desktop_ 提供圖形化 AI 應用程式：Amp Desktop、Antigravity Desktop、ChatGPT 桌面應用程式、Claude 桌面應用程式（Anthropic 的 Linux beta 版，具有 Chat、Cowork 與 Claude Code 分頁）、用於與 xAI 模型聊天的 Grok Bot、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexity 桌面應用程式與 T3 Code。Grok Bot 是桌面聊天應用程式。程式設計 agent 則是 `grok` 指令。

Hermes Desktop 是需要特別了解的那個，因為一台機器只有一個 Hermes，且它是屬於該應用程式的：Hermes 只能透過該應用程式安裝，而預設 agent 執行的 `hermes` 指令就是該應用程式的。選擇 Hermes 作為預設 agent 會安裝與 _Install > AI > Desktop_ 項目相同的東西：套件，以及由 Hermes 自家安裝程式在 `~/.hermes` 下設定的 Hermes 執行環境，第一次需要幾分鐘。該執行環境是終端機 `hermes` 指令、預設 agent 與應用程式全都使用的那一個 Hermes，且它會以 `hermes update` 自行更新，而非等待 Omarchy 發行版。安裝它也會將 Omarchy 主題以名為 `omarchy` 的 skin 交給 Hermes，每個 Hermes 介面都會在你切換主題時跟隨；如果你不希望如此，請在 Hermes 的 Appearance 設定下或用 `/skin` 選擇另一個，Omarchy 會尊重該選擇，不去動它。在 _Remove > AI > Desktop_ 下移除該應用程式會先關閉 Hermes，包括 gateway 在內，並將該執行環境一併帶走，且會保留你的聊天、記憶，以及 Hermes 為自己撰寫的 skills，除非你另有指示：它會詢問，預設為否，詢問該資料與你的連線設定是否也應一併移除。

OpenClaw 的桌面體驗是其 Control UI，它以網頁應用程式開啟，後端是其自己的本機 gateway。OpenClaw 位於 `~/.openclaw` 並自行更新：使用 Control UI 的「Update Gateway」按鈕或執行 `openclaw update`，gateway 會以新版本重啟。Omarchy 只決定全新安裝從哪個發行版本開始。OpenClaw 也可以是你的預設 agent：使用 `omarchy default agent openclaw` 選擇它，會在 `~/.openclaw` 中設定相同的副本，且該 agent 會開啟連接到其 gateway 的 OpenClaw 終端機 UI。在 _Remove > AI > Desktop_ 下移除 OpenClaw 會將 gateway 服務與應用程式一併帶走，然後詢問是否也應移除 `~/.openclaw`，因為那裡除了 OpenClaw 本身及其下載的 plugin 執行環境外，還保存了你的聊天與憑證；預設會保留它，而再次安裝 OpenClaw 時會重新取用它。

Herdr Desktop 是 [Herdr](https://herdr.dev) 桌面應用程式：spaces、tabs 與 panes 中有終端機與程式設計 agent，即使你關閉視窗，它們仍會在其核心中持續執行。它來自 Herdr 自家的安裝程式而非套件，因此位於 `~/.local/share/herdr-app`，當你尚無其核心時，會將核心一併放在 `~/.local/bin/herdr-core`，且兩者都會自行更新。它與 Omarchy 在 `Super + Ctrl + Return` 上隨附的 `herdr` 指令並存，而非取而代之，且取得該指令的直接按鍵：`Alt + Return` 與 `Alt + Shift + Return` 會向下或向右分割 pane，`Alt + Escape` 關閉它，`Ctrl + Alt + Arrow` 在 panes 間移動，`Alt + 1..9` 與 `Alt + Left/Right` 選擇分頁，而 `Alt + Up/Down` 在 spaces 間移動。`Ctrl + 1..9` 選擇一個 space，而 `Alt + Shift + Up/Down` 會逐步切換 agent。`Ctrl + Space` 前綴鍵僅限終端機，因為該應用程式無法為序列保留普通的 Ctrl 鍵。Omarchy 將這些寫入 `~/.config/herdr-app/keys.json`，而 `omarchy-refresh-herdr-app` 會將其恢復。安裝它會選取 Herdr 的 Omarchy 主題，自此遵循你的 Omarchy 主題。Herdr 為淺色模式保留一個主題，為深色模式保留一個，因此在深色與淺色 Omarchy 主題之間切換後，請在 Herdr 的主題選擇器中再為另一種模式選擇一次 Omarchy。

T3 Code 在 `~/.local/share/t3code` 中從其官方 AppImage 發行版執行，而非從套件，因此它會自行更新。安裝它會詢問要在 Stable 還是 Nightly 頻道開始；之後可在 T3 Code 的設定中切換。你的討論串與設定位於 `~/.t3` 中，在 _Remove > AI > Desktop_ 下移除 T3 Code 會將它們一併帶走。

### 本機模型

在你的電腦上為你的程式設計 agent 執行開放模型。你的提示與程式碼都留在機器上；送給模型的東西都不會離開它。從以下開始：

```bash
omarchy models use best text
```

那會為此機器設定最適合的文字模型，也就是你的 agent 使用的那種。Image、video 與 music 模型各有其最佳選擇：`omarchy models use best image`、`video` 或 `music`。執行 `omarchy models use best` 查看每種在此機器上的選擇。

或在 agent 面板中選擇 +：在 _Use a local model_ 之下，它會列出每個適合此機器的程式設計模型，推薦的那個排第一。執行模型的 Podman 隨 Omarchy 附帶，NVIDIA 機器上的 NVIDIA 容器工具包也一樣，它讓模型能使用 GPU；若其中任一個缺失，第一次設定時會安裝。Omarchy 接著會選擇此機器推薦的模型、下載它並啟動它。預期會有數十 GB 的下載，且模型執行時機器的大部分記憶體都會被用掉：Flash Next 在完整的 256K 上下文下會使用約 100 GiB。如果其他模型佔用了它所需的記憶體，它會設定為已停止狀態，等你停止一個模型後即可啟動。模型在登出時停止；當你需要記憶體作其他用途時，請自行停止它。

`omarchy models list` 顯示選項並說明為何有些不適合。若要設定另一個，請執行 `omarchy models use <recipe>`。目前，`qwen3.8-flash-next-gufo` 與 `qwen3.8-27b-gufo` 可用於 128 GB Strix Halo 機器；27B 約需 40 GiB，因此會留有空間供其他工作。在配備 Intel Arc B390 的 64 GB 筆記型電腦上，`qwen3.6-35b-a3b-llamacpp` 以約 30 GiB 執行。新配方與建議會透過套件隨 `omarchy update` 一起提供。

你新增的程式設計模型在 agent 面板中會有自己的一行，位於你的訂閱旁：播放以啟動它，暫停以停止它並釋放其記憶體，Tailscale 標記可在它執行時與你 tailnet 上的其他機器共享它，終端機按鈕則可在其上開啟你的 agent。它的那行會隨著進展顯示下載、載入或停止，並在記憶體不足無法啟動時如此說明，或在它以錯誤停止時連結到其記錄。多個可同時執行，只要它們一起能裝入記憶體中。在選取的行上按 Delete 以從此機器移除模型，包括下載內容；+ 可再次設定它。從終端機設定的程式設計模型會等在 + 之下，直到你新增它，你所配對機器執行的模型也是如此（`omarchy models pair <host>`）。

你設定的每個程式設計模型也會在應用程式啟動器中獲得自己的項目，位於模型名稱之下並帶有其製造商的標誌，就像登入 Claude、Codex 或 Grok 時會新增一個一樣。它會在該模型上開啟你的 agent，且若模型未執行，會先啟動它：終端機顯示其載入過程，並在就緒後交給 agent。移除模型會移除其項目。

並非每個模型都用於程式設計。Image、video 與 music 模型會改在 Fantasi 中開啟，Fantasi 是 Omarchy 用於使用在此機器上執行的模型製作圖片、影片與音樂的應用程式，且它們在那裡或以 `omarchy models` 管理。

模型會完全保持其設定時的執行方式，因此 Omarchy 更新永遠不會在你的 agent 使用期間重啟模型。當 Omarchy 有你所設定模型的新版執行環境或新版權重時，它的那一行會顯示更新按鈕：按下它，模型會在背景中重新設定，只下載變更的部分，並以新版本重啟。已停止的模型仍會保持停止。`omarchy models update` 從終端機對每個模型都做同樣的事情。

從命令列，`omarchy models start <recipe>` 與 `omarchy models stop <recipe>` 做同樣的事情，`omarchy models status` 顯示每個模型，而 `omarchy agent --local-model <recipe>` 會在 pi 中開啟該模型，無論你的預設 agent 是什麼。若要讓本機模型成為 agent 快捷鍵、Quake 主控台與 _Make something_ 開啟的對象，請執行 `omarchy default agent local` 或在 agent 面板中將正在執行的模型標記星號。pi 也在其自己的模型選擇器中列出你設定的每個模型，以及你所配對機器上的模型，因此普通的 `pi` 也能存取它們。任何與 OpenAI 相容的用戶端也可以連線：`status` 顯示每個模型的地址（第一個是 `http://127.0.0.1:11435/v1`），配方名稱就是模型，而金鑰在 `~/.config/omarchy/agent-local/key` 中。

`omarchy models remove <recipe>` 刪除模型，以及沒有其他模型使用的下載內容。

第三方執行環境會標示其發行者。Omarchy 執行每個模型時都不提供網路存取。

### 本機 LLM

Omarchy 建議兩種執行本機 LLM 模型的方式：LM Studio 與 Ollama。LM Studio 提供 GUI 介面來尋找開放權重模型、安裝並執行它們。這是輕鬆入門的好方法。Ollama 提供 CLI 以類似方式完成。但如果你是本機模型新手，我會從 LM Studio 開始。從 Omarchy Menu 的 _Install > AI > Desktop_ 安裝 LM Studio，並從 _Install > AI > CLI_ 安裝 Ollama。

### Omarchy skills

Agent skills 幫助 AI 以特定方式使用特定工具，Omarchy 隨附其中七個。omarchy skill 涵蓋量身訂做系統，例如調整你的 Hyprland 設定或調整工具列。omarchy-make-theme、omarchy-make-plugin、omarchy-make-app 與 omarchy-make-game 涵蓋製作新東西，omarchy-contribute 涵蓋回報錯誤或向上游送出修復，而 omarchy-diagnose-crash 則處理崩潰的核心傾印。它們被 symlink 到 Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` 與每個 `~/.hermes/profiles/*/skills`）以及通用的 `~/.agents/skills` 位置的 skill 目錄中，因此大多數 harness 會自動拾取它們。與你自己的同名 skill 資料夾優先。

但你應將這些 skills 視為實驗性質。不同模型使用它的效果也會不同。最好先在 plan mode 中執行，這樣你能了解 agent 想要變更什麼。接著準備好回復變更，甚至在 agent 把一切搞得一團亂時調用 `omarchy reinstall configs`。
