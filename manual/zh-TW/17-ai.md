### 安裝與更新代理工具

除了 Hermes 與 OpenClaw 之外，這些代理工具都使用 mise 的延遲安裝：首次啟動時安裝 CLI，後續啟動則重複使用它。mise 也會最多每四小時檢查一次已安裝代理工具是否有新版本，檢查時機就在它啟動之前，或是在 shell 提示字元處於背景檢查。若該更新失敗或你處於離線狀態，就會執行已安裝的版本。`omarchy update` 會連同 Omarchy 的其餘部分一起更新已安裝的代理工具，而 `mup` 則僅更新 mise 管理的工具。

代理工具自有的更新程式，例如 `claude update`、`codex update`，或是應用程式中的更新按鈕，並不會更新 mise 管理的安裝。`codex update` 會失敗，而 `claude update` 可能回報成功，卻安裝了一個 mise 不追蹤的獨立副本。如果你寧願使用代理工具原生的安裝程式與更新程式，請將它加入 `disable_tools`；參見[預先安裝的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

若要在需要之前安裝所有已設定的延遲工具，請執行 `mise install --include-lazy`。這包含 Omarchy 的其他預設 CLI 工具以及代理工具。參見[預先安裝的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)，以瞭解如何安裝單一工具或使用你自己的安裝。

`grok` 是透過 mise 的第一方 `grok` 套件安裝，方式與 `claude` 及 `codex` 相同。執行 `grok`，或在 _Agent > Harness_ 之下選擇它。跳過 x.ai 上的 `curl | bash` 安裝程式。那條路徑會在 `~/.grok/bin` 放入第二個副本，將它加到 `PATH` 的最前面，並覆寫 Omarchy 的包裝程式。

`dsh` 會在 `127.0.0.1:3080` 開啟其瀏覽器 UI，並以啟動目錄作為其預設工作區。其瀏覽器 UI 不接受起始提示詞，因此 `omarchy agent prompt` 會開啟它，並將提示詞放在你的剪貼簿中供你貼上。Omarchy 會以 DeepSeek 的免核准權限預設集啟動它。當你使用其官方模型 API 時，DeepSeek Harness 會將工作階段記錄上傳至 DeepSeek；請在其瀏覽器 UI 的 _Settings > General > Upload Session Log_ 之下關閉此功能。你傳送給它的回饋也會連同工作階段一併上傳，除非你以 `DSH_TELEMETRY_MODE=DISABLED` 啟動它。

### 預設代理工具

使用 `omarchy default agent <name>`，或在 Omarchy Menu（`Super + Space`）的 _Agent > Harness_ 之下，挑選你的預設代理工具。若該代理工具尚未安裝，選擇它會先安裝它，而且它也會在應用程式啟動器中獲得屬於自己的啟動器，緊鄰 Agent。全新安裝的 Omarchy 會以一次性通知邀請你做此選擇。

選擇 Claude 也會嘗試為 Chromium、Chrome、Brave、Brave Origin 與 Edge 設定其瀏覽器擴充功能。擴充功能的設定適用於所有使用者，且可能要求輸入你的系統密碼；取消或擴充功能安裝失敗，仍會選取並啟動 Claude。重新啟動你的瀏覽器，若有提示則啟用擴充功能，並登入 Claude 以完成連接。在 Claude 中執行 `/chrome` 以檢查連線。Firefox 與 Zen 不支援此擴充功能。若在加入此設定之前 Claude 就已經是你的預設值，請再次選擇它以安裝擴充功能。

一旦你做出選擇，`Super + Shift + Ctrl + A` 會在專用的終端機視窗中啟動預設代理工具（或者，若你尚未選擇，則會開啟選擇器）。你也可以用 `omarchy agent prompt "Review this project"` 讓它直接進入任務。Freebuff 與 DeepSeek Harness 不接受起始提示詞，因此它們會改為開啟，並將提示詞放在你的剪貼簿中供你貼上。以這種方式啟動的代理工具會在各自的不要停下來詢問模式中以無人看管的方式執行，所以請做好準備，它們真的會動手做事！MiniMax Code 的互動式工作階段沒有這種模式，因此它會照常要求權限。而且，由於代理工具拒絕記住對你家目錄的信任，從 `$HOME` 啟動的執行會改為在 `~/Work` 中開始。

也有終端機捷徑：`a` 會在目前的終端機中直接執行預設代理工具，而 `c`、`cx` 與 `cy` 則會直接啟動 OpenCode、Claude Code 與 Codex（同樣是在它們的自動核准模式中）。主題變更也會同步至代理工具：當你切換 Omarchy 主題時，Claude Code、Pi、OpenCode 與 Hermes（一旦 Omarchy 已安裝它）都會一併跟隨。

### 你的代理工具指示

給每個代理工具的個人規則放在 `~/.agents/AGENTS.md`，就在 `~/.agents/skills` 中的共享技能旁邊。在 _Agent > Instructions_ 之下開啟它，它也會將它連結進每個維護其自有全域檔案的 harness：`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`~/.pi/agent/AGENTS.md`、`~/.config/opencode/AGENTS.md`、Copilot 的 `~/.copilot/copilot-instructions.md`，依此類推。Crush 與 Amp 會讀取 `~/.config/AGENTS.md` 連結，而 omp、Kimi 與 DeepSeek Harness 則直接讀取 `~/.agents/AGENTS.md`。挑選預設代理工具也會連結它。若你已有指示檔案，且尚無共享檔案，該檔案就會成為共享檔案；否則它會以 `.bak` 的形式保留在連結旁邊。安裝另一個代理工具後，請執行 `omarchy agent instructions` 以重新連結。

### 代理工具面板

頂部列有一個代理工具圖示。在你設定代理工具之前，其面板會引導你登入 Claude、Codex 或 Grok，而第一個登入的會成為你的預設代理工具。之後，面板會將每個訂閱都放在同一頁：每個代理工具與帳戶連同其方案、每個 5 小時工作階段與每週限額的用量表及距離重置的時間（將滑鼠懸停以查看確切百分比），或是剩餘的預付餘額，都位於一行會輪換顯示你在所有代理工具上使用情況的文字之下，例如本週的 token 數與你最常使用的模型。在 _Make something cool_ 之下，它會提供用於新主題、外掛、應用程式或遊戲的入門提示詞，並將任務交給你的預設代理工具。應用程式是以 Omarchy 自家的 Hype、Monologue 與 Omacut 相同的方式，使用 C++ 與 Qt Quick 並遵循 omarchy-make-app 代理工具技能來打造，而且它們所需的編譯器與 Qt 組件都已隨附安裝。遊戲是位於 `~/Games/vibes` 的單一 three.js 頁面，遵循 omarchy-make-game 代理工具技能，且全都從目前主題中的同一個 Game Vibes 啟動器開啟；它們會從網路載入 three.js，因此需要連線才能啟動。Claude Code、Codex、Grok、Kimi、Cursor 及其 Grok Bot 額度、GitHub Copilot、Muse、Antigravity 與 Devin 都已開箱涵蓋並附其限額，Kimchi 附其方案、預付點數與支出預算，而 Hermes、Mistral Vibe 與 Qwen Code 則會在你使用過它們之後顯示其工作階段與 token。你透過 pi、omp 或 opencode 使用的供應商方案與金鑰也會出現：OpenCode Zen 與 Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan 與 Synthetic 並附其限額；OpenRouter 與 DeepSeek 並附其預付餘額；Fireworks 並附其過去 30 天的支出。你在自有硬體上執行的模型所產生的 token 也會計入總計；模型本身有其專屬面板，如[本機模型](#local-models)所述。每個代理工具只會計數一次，歸屬於向其收費的一方，不論你透過多少個 harness 驅動它。

左鍵按一下該列圖示或按 `Super + Ctrl + X` 可開啟面板，右鍵按一下可啟動你的預設代理工具，中鍵按一下可重新整理。其背後的用量記錄每 15 分鐘由 `omarchy agent usage update` 重新產生，而且面板甚至可以透過同步資料夾合併來自你其他機器的用量。完整設定請參見 `$OMARCHY_PATH/shell/plugins/agents/` 之下的 README。

### 多個訂閱

若你付費購買了不止一個 Claude、Codex 或 Grok 方案，例如一個個人 Max 與一個工作用的，Omarchy 可以讓它們全都保持登入，並在它們之間切換。使用代理工具面板中的 + 新增訂閱，它會直接在該處引導你完成，或使用 `omarchy agent account add claude Work`（或 `codex`，或 `grok`）。若 CLI 缺失，它會安裝它。某個供應商的第一個帳戶會透過你的一般瀏覽器登入，就在 CLI 一直以來查找的位置。之後的每個帳戶則會透過私密視窗登入，因此你瀏覽器已登入的帳戶不會被誤選；在該處登入你要新增的帳戶，並先關閉你已開啟的任何私密視窗。絕對不要為了此事登出 CLI：登出會撤銷已儲存的登入資訊，該帳戶就必須重新新增。

若要透過 SSH 將你的訂閱登入資訊複製到另一台 Omarchy 機器，請執行 `omarchy agent account copy user@laptop`。當目的地未安裝接收端時，傳送端會提供一個暫時的接收端，因此較舊的 Omarchy 機器無需更新即可接收帳戶。已安裝的接收端優先。此操作會複製所有 Claude、Codex 與 Grok 訂閱；加入供應商名稱可選取它們，例如 `omarchy agent account copy laptop claude`。帳戶名稱與指令 ID 與來源端一致，包括目的地已存在的帳戶。無關的目的地帳戶若名稱衝突，會獲得數字後綴，而設定、技能、外掛與對話記錄則各自保留在每台機器本機。

目的地現有的認證會被保留。已在該處登入的來源帳戶，其名稱會同步而不取代其認證；其他帳戶則會新增在其旁邊。若要取代相符帳戶的已儲存認證，請在目的地上結束該帳戶的工作階段後，使用 `omarchy agent account copy --replace laptop claude`。全新的目的地也會取得來源的作用中帳戶與切換偏好設定；已建立的目的地則保留其自有的設定。

認證會透過 SSH 傳輸，並儲存在目的地的私密檔案中，因此請僅複製到你信任的機器。這是一次性的複製，而非持續同步。Codex 的 refresh token 可能會被另一台機器輪換，導致複製的登入資訊需要重新更新；要在多台機器上同時使用，分開登入仍是最可靠的選擇。參見 [Codex 的帳戶驗證指南](https://developers.openai.com/codex/auth/ci-cd-auth)。

每個供應商同時只有一個作用中的帳戶，而且每個新工作階段都會以該帳戶開始：`cx`、`cy`、一般的 `claude`、`codex` 或 `grok`、任何透過 `omarchy agent` 啟動的內容，以及在 `PATH` 上找到 CLI 的指令碼或編輯器。使用 `omarchy agent account use work` 切換（並用 `omarchy agent account use main` 切換回來），或在面板中按帳戶的編號然後按 `Enter`（或按一下其 Use 按鈕）。執行中的 Claude 工作階段也會切換，從它們的下一則訊息開始：每個 Claude 工作階段都在 `~/.claude` 中執行，那裡永遠保存作用中帳戶的登入資訊。由較舊 Omarchy 在帳戶自有資料夾中啟動的 Claude 工作階段會保留該登入資訊直到結束，因此切換操作會列名那些工作階段，並在它們消失後自行完成。執行中的 Codex 與 Grok 工作階段會留在它們啟動時所用的帳戶上。對話記錄、設定、技能與外掛會在帳戶之間共享，因此在同一個資料夾中執行 `claude --continue` 會在新帳戶上接續你之前中斷的地方。

擁有超過一個帳戶時，面板會並排顯示每個帳戶的限額，並標示作用中的那個。依預設，當作用中帳戶超過其限額的 95% 時 Omarchy 會通知你，而按一下通知會切換到剩餘空間最多的帳戶。在面板中將滑鼠懸停在某個帳戶的行上，並按一下 Use 旁邊出現的 Autoswitch（或按 `m`），或執行 `omarchy agent account mode auto`，即可讓它自行切換；開啟時，Autoswitch 會取代 Use 的位置，再按一下它就會回到通知模式。加入數字可變更門檻，例如 `omarchy agent account mode auto 90`。若每個帳戶都超過門檻，你會收到一次通知，並告知哪個帳戶最先釋放。當作用中帳戶距離其門檻在 15 個百分點以內（預設情況下為 80%）時，其限額會每三分鐘檢查一次，而非每 15 分鐘。

`omarchy agent account list` 會顯示每個帳戶及其最新限額，`omarchy agent account remove work` 會忘記一個帳戶，而 `omarchy agent account rename primary Hey` 會重新命名一個帳戶（或在面板中按一下帳戶名稱）。這些指令作用於你預設代理工具的帳戶；若要存取另一個供應商，請先指名它，例如 `omarchy agent account use codex side`。你原本在 `~/.claude` 或 `~/.codex` 中的登入資訊即為 _Main_ 帳戶。Codex 的會留在原處；Claude 的則會在另一個帳戶作用中時，待在屬於它自己的資料夾中。閒置超過約八小時的帳戶可能會顯示 _Sign-in required_；按一下它即可直接在面板中重新登入該帳戶，或切換至它並開始一個工作階段，它就會自行更新登入資訊。你以 `claude mcp add` 新增的 MCP 伺服器會觸及每個 Claude 帳戶，因為它們都在 `~/.claude` 中執行；對於 Codex 與 Grok，在新增帳戶時你所擁有的伺服器會隨之帶入，但之後新增的只會觸及你新增它們時所用的帳戶。Claude Desktop 保留其自有的登入資訊，而以 CLI 二進位檔絕對路徑設定的 Codex 或 Grok 工具不會跟隨切換。明確的 `CLAUDE_CONFIG_DIR`、`CODEX_HOME` 或 `GROK_HOME` 會優先於選定的帳戶。

### 崩潰診斷

Omarchy 會監看 systemd-coredump 以偵測程序崩潰。一旦你選定預設代理工具，你任何傾印核心的程式都會帶來「Process crashed」通知，按一下它，崩潰就會連同 Omarchy 的 omarchy-diagnose-crash 技能交給你的預設代理工具，該技能會引導代理工具從核心傾印建立事實，並決定該崩潰是否值得向 upstream 回報。你也可以用 `omarchy agent crash <pid>`，針對 `coredumpctl list` 中的任何 PID 手動執行它。

監看功能依預設為開啟。在 _Trigger > Toggle > Crash Capture Off_ 之下關閉它（或使用 `omarchy toggle crash-capture`），通知就會停止；`omarchy agent crash <pid>` 仍可手動運作。

崩潰也可以一次靜音一個程式，這正是診斷會在最後提供給你的選項。`omarchy crash mute hyprland` 只會停止該程式的通知，`omarchy crash mute hyprland off` 會讓它們恢復，而單獨的 `omarchy crash mute` 則會列出你已靜音的內容。它同樣高興地接受二進位檔路徑與其名稱，因此 `omarchy crash mute /usr/bin/hyprland` 做的是同一件事。請為含有空格的名稱加上引號，例如 `omarchy crash mute 'Some App'`。其他所有程式仍會通知，而被靜音的程式仍會崩潰，這只是隱藏提醒，並不會修復任何問題。

### 桌面應用程式

_Install > AI_ 功能表也包含幾個圖形化 AI 應用程式：Amp Desktop、Antigravity Desktop、ChatGPT 桌面應用程式、Claude 桌面應用程式（Anthropic 的 Linux beta，附 Chat、Cowork 與 Claude Code 分頁）、用於與 xAI 模型聊天的 Grok Bot、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexity 桌面應用程式，以及 T3 Code。Grok Bot 是桌面聊天應用程式。編碼代理工具則是 `grok` 指令。

Hermes Desktop 是需要特別了解的那個，因為一台機器只有一個 Hermes，而且它屬於該應用程式：Hermes 僅會透過應用程式安裝，而預設代理工具執行的 `hermes` 指令就是該應用程式的。選擇 Hermes 作為預設代理工具會安裝與 _Install > AI_ 項目相同的東西：該套件，以及由 Hermes 自有安裝程式在 `~/.hermes` 之下設定的 Hermes 執行環境，首次需花幾分鐘。該執行環境就是唯一的 Hermes，終端機的 `hermes` 指令、預設代理工具與應用程式全都使用它，而且它會以 `hermes update` 自行更新，而非等待 Omarchy 發布新版本。安裝它也會將 Omarchy 主題交給 Hermes，作為名為 `omarchy` 的外觀，每個 Hermes 介面都會在你切換主題時跟隨；若你不想要如此，請在 Hermes 的 Appearance 設定中，或用 `/skin` 選擇另一個，Omarchy 會保留那個選擇不去動它。在 _Remove > AI_ 之下移除該應用程式會先關閉 Hermes，包括 gateway，並連同它一併帶走該執行環境，同時保留你的聊天、記憶以及 Hermes 為自己撰寫的技能，除非你另有指示：它會詢問是否連同該資料與你的連線設定一併移除，預設為否。

OpenClaw 的桌面體驗是其 Control UI，它會以網頁應用程式開啟，後端為其自有的本機 gateway。OpenClaw 位於 `~/.openclaw` 並會自行更新：使用 Control UI 的「Update Gateway」按鈕，或執行 `openclaw update`，gateway 就會在新版本上重新啟動。Omarchy 僅選擇全新安裝的起始版本。OpenClaw 也可以是你的預設代理工具：在 _Agent > Harness_ 之下選擇它會在 `~/.openclaw` 中設定同樣的副本，而該代理工具會開啟連接到其 gateway 的 OpenClaw 終端機 UI。在 _Remove > AI_ 之下移除 OpenClaw 會連同 gateway 服務與應用程式一併帶走，然後詢問 `~/.openclaw` 是否也應一併移除，因為其中保存了你的聊天與認證，以及 OpenClaw 本身與其下載的外掛執行環境；預設會保留它，再次安裝 OpenClaw 時會重新取得它。

Herdr Desktop 是 [Herdr](https://herdr.dev) 桌面應用程式：包含空間、標籤頁，以及終端機與編碼代理工具的窗格，當你關閉視窗時它們會在其核心中持續執行。它來自 Herdr 自有的安裝程式而非套件，因此它位於 `~/.local/share/herdr-app`，當你尚無核心時會將其核心一併帶入 `~/.local/bin/herdr-core`，而且兩者都會自行更新。它是與 Omarchy 隨附在 `Super + Ctrl + Return` 上的 `herdr` 指令並列，而非取代它，並且擁有該指令的直接按鍵：`Alt + Return` 與 `Alt + Shift + Return` 會向下或向右分割窗格，`Alt + Escape` 會關閉它，`Ctrl + Alt + Arrow` 會在窗格之間移動，`Alt + 1..9` 與 `Alt + Left/Right` 會選擇標籤頁，而 `Alt + Up/Down` 會在空間之間移動。`Ctrl + 1..9` 會選擇空間，`Alt + Shift + Up/Down` 會逐一巡覽代理工具。`Ctrl + Space` 前綴鍵維持終端機專屬，因為應用程式無法為一串按鍵序列按住一個普通的 Ctrl 鍵。Omarchy 將這些寫入 `~/.config/herdr-app/keys.json`，而 `omarchy-refresh-herdr-app` 會將它們恢復。安裝它會挑選 Herdr 的 Omarchy 主題，從此它會跟隨你的 Omarchy 主題。Herdr 為淺色模式與深色模式各保留一個主題，因此在深色與淺色的 Omarchy 主題之間切換後，請在 Herdr 的主題選擇器中再次為另一個模式選擇 Omarchy。

T3 Code 從其官方 AppImage 發布版本在 `~/.local/share/t3code` 中執行，而非從套件安裝，因此它會自行更新。安裝它時會詢問要從 Stable 還是 Nightly 通道開始；稍後可在 T3 Code 的設定中切換。你的對話串與設定位於 `~/.t3`，在 _Remove > AI_ 之下移除 T3 Code 會連同它們一併帶走。

### 本機模型

在你自己的機器上，為你的編碼代理工具執行開放模型。你的提示詞與程式碼會留在機器上；任何傳送給模型的內容都不會離開機器。從以下開始：

```bash
omarchy models use best text
```

這會為這台機器設定最佳的文字模型，也就是你的代理工具所使用的那種。圖像、影片與音樂模型各有其最佳選擇：`omarchy models use best image`、`video` 或 `music`。執行 `omarchy models use best` 以查看每個種類針對這台機器的選擇。

或者，從頂部列中代理工具圖示旁邊的閃光圖示開啟本機模型面板，或使用 Super + Ctrl + Alt + X，然後選擇 +。當有適合這台機器的模型時，該圖示就會出現。Podman，也就是執行模型的程式，隨 Omarchy 附帶，NVIDIA 機器上的 NVIDIA 容器工具組也一樣，它讓模型能使用 GPU；若任一缺失，首次設定時會安裝它。然後 Omarchy 會挑選這台機器的推薦模型，下載並啟動它。請預期會有數十 GB 的下載量，而且模型執行時會使用機器的大部分記憶體：Flash Next 在其完整的 256K 上下文下會使用約 100 GiB。若其他模型佔用了它需要的記憶體，它會設定為已停止的狀態，等你停止其中一個時即可啟動。模型在登出時會停止；當你需要將記憶體用於其他用途時，請自行停止它。

`omarchy models list` 會顯示選項，並解釋為何某些選項不適合。若要設定另一個，請執行 `omarchy models use <recipe>`。目前，`qwen3.8-flash-next-gufo` 與 `qwen3.8-27b-gufo` 可用於 128 GB Strix Halo 機器；27B 佔約 40 GiB，因此它能為其他工作留出空間。在配備 Intel Arc B390 的 64 GB 筆記型電腦上，`qwen3.6-35b-a3b-llamacpp` 以約 30 GiB 執行。新的配方與建議會透過套件隨 `omarchy update` 送達。

你設定的每個模型在本機模型面板中都會獲得屬於自己的行：播放可啟動它，暫停可停止它並釋放其記憶體，而終端機按鈕可在它之上開啟你的代理工具。橫跨頂部的一條長條，顯示機器的記憶體如何在 Omarchy 本身（系統與你的應用程式）、每個執行中的模型，以及空閒部分之間分配。將滑鼠指向一個已停止的模型，該長條會顯示它是否放得下，或還差多少。多個模型可以在記憶體同時容納它們時一併執行；若有一個放不下，Omarchy 會指出該停止哪個執行中的模型。依其標誌拖曳各行可重新排序，而對選取的行按 Delete 可移除模型及其下載。

你設定的每個模型也會在應用程式啟動器中獲得屬於自己的項目，位於模型名稱之下並附上其製造商的標誌，就像登入 Claude、Codex 或 Grok 會新增一個一樣。它會在該模型上開啟你的代理工具，若模型尚未執行，會先啟動模型：終端機會顯示它正在載入，並在就緒後交給代理工具。移除模型會移除其項目。

並非每個模型都是用於編碼。圖像、影片與音樂模型反而會在 Fantasi 中開啟，這是 Omarchy 用於以在本機上執行的模型製作圖片、影片與音樂的應用程式，可從它們的啟動器項目及本機模型面板中的那一行開啟。

模型會完全依其設定方式持續執行，因此 Omarchy 更新絕不會在你的代理工具之下重新啟動它。當 Omarchy 為你已設定的模型提供了較新的執行環境或較新的權重時，它的那一行會顯示更新按鈕：按下它，模型會在背景中重新設定，僅下載已變更的部分，並以新版本重新啟動。已停止的模型仍會保持停止。`omarchy models update` 會從終端機對每個模型做同樣的事。

從指令列，`omarchy models start <recipe>` 與 `omarchy models stop <recipe>` 做的是同樣的事，`omarchy models status` 顯示每個模型，而 `omarchy agent --local` 會在你最後啟動的模型上開啟你的預設代理工具。pi、OpenCode 與 Qwen Code 可以使用它；若是任何其他預設值，則會在 pi 中開啟，若你未安裝 pi，則在 OpenCode 中開啟。pi 也會在其自有的模型選擇器中，列出你已設定的每個模型，以及在你已配對的機器上的模型，因此一般的 `pi` 也能使用它們。任何與 OpenAI 相容的用戶端也可以連線：`status` 會顯示每個模型的位址（第一個是 `http://127.0.0.1:11435/v1`），配方名稱即為模型，而金鑰位於 `~/.config/omarchy/agent-local/key`。

`omarchy models remove <recipe>` 會刪除一個模型，以及其下載中沒有其他模型使用的部分。

第三方執行環境會標示其發布者。Omarchy 在無網路存取的情況下執行每個模型。

### 本機 LLMs

Omarchy 建議兩種執行本機 LLM 模型的方式：LM Studio 與 Ollama。LM Studio 提供 GUI 介面，用於尋找開放權重模型、安裝並執行它們。這是能輕鬆上手的絕佳方式。Ollama 提供 CLI 以類似方式做到這一點。但如果你對本機模型還不熟悉，我會從 LM Studio 開始。你可以在 Omarchy Menu 的 _Install > AI_ 之下安裝任一者。

### Omarchy 技能

代理工具技能幫助 AI 以特定方式使用特定工具，而 Omarchy 隨附了七個。omarchy 技能涵蓋系統的客製化，例如調整你的 Hyprland 設定或調整該列。omarchy-make-theme、omarchy-make-plugin、omarchy-make-app 與 omarchy-make-game 涵蓋製作新事物，omarchy-contribute 涵蓋回報 bug 或向 upstream 傳送修復，而 omarchy-diagnose-crash 則會處理崩潰的核心傾印。它們會被符號連結進 Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` 以及每個 `~/.hermes/profiles/*/skills`）以及通用的 `~/.agents/skills` 位置的技能目錄，因此大多數 harness 會自動取得它們。你自有的同名技能資料夾會優先使用。

但你應將這些技能視為實驗性質。不同的模型使用它的效果也會不同。最好先在計畫模式中執行，讓你了解代理工具想要變更什麼。然後準備好回滾變更，甚至呼叫 `omarchy reinstall configs`，以防代理工具把一切搞得一團糟。
