# AI

Omarchy 內含下列程式編寫代理的啟動器，但不會幫你選預設值。執行指令即可在首次使用時安裝其 CLI，然後依提示進行驗證。Hermes 與 OpenClaw 是例外：它們不會透過 mise 安裝任何東西，選擇任一者都會設定它自己會自動更新的副本，如下方的 _桌面應用程式_ 一節所述。

### 安裝與更新代理

除了 Hermes 與 OpenClaw 之外，這些代理都使用 mise 的延遲安裝：首次啟動時安裝 CLI，之後的啟動則重複使用它。mise 也會至多每四小時檢查一次已安裝代理是否有新版本，就在它啟動之前，或在 shell 提示符下於背景檢查。如果該更新失敗或你處於離線狀態，就會執行已安裝的版本。`omarchy update` 會連同 Omarchy 的其他部分一起更新已安裝的代理，而 `mup` 只更新由 mise 管理的工具。

代理自己的更新程式，例如 `claude update`、`codex update`，或應用程式中的更新按鈕，不會更新由 mise 管理的安裝。`codex update` 會失敗，而 `claude update` 可能會回報成功，卻安裝了一個 mise 沒有追蹤的獨立副本。如果你寧願使用代理原生的安裝程式與更新程式，把它加入 `disable_tools`；請參閱 [預先安裝的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

若要在需要之前安裝所有已設定的延遲工具，執行 `mise install --include-lazy`。這包括 Omarchy 的其他預設 CLI 工具以及這些代理。關於安裝單一工具或使用你自己的安裝，請參閱 [預先安裝的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

`grok` 是透過 mise 的第一方 `grok` 套件安裝，方式與 `claude` 和 `codex` 相同。執行 `grok`，或在代理面板中為它加上星號。跳過 x.ai 上的 `curl | bash` 安裝程式。那條路徑會在 `~/.grok/bin` 放第二份副本、把它加到 `PATH` 最前面，並覆寫 Omarchy 的包裝程式。

`dsh` 會在 `127.0.0.1:3080` 開啟其瀏覽器 UI，並以啟動目錄作為其預設工作區。它的瀏覽器 UI 不接受起始提示，所以 `omarchy agent prompt` 開啟它時，會把提示放在你的剪貼簿中讓你貼上。Omarchy 會以 DeepSeek 的無需核准權限預設集啟動它。當你使用 DeepSeek Harness 的官方模型 API 時，它會把工作階段記錄上傳到 DeepSeek；在其瀏覽器 UI 的 _Settings > General > Upload Session Log_ 下將其關閉。你傳送給它的意見回饋也會連同工作階段一起上傳，除非你以 `DSH_TELEMETRY_MODE=DISABLED` 啟動它。

### 預設代理

用代理面板中代理旁邊的星號來挑選你的預設代理，預設代理上的星號是填滿的；或用 `omarchy default agent <name>`，它也接受任何在那裡沒有一行的 harness。如果代理尚未安裝，挑選它會先安裝它，而且它還會在應用程式啟動器中，Agent 旁邊，得到一個專屬的啟動器。全新的 Omarchy 會以一次性的通知邀請你設定一個，該通知會開啟代理面板。

選擇 Claude 也會嘗試為 Chromium、Chrome、Brave、Brave Origin 與 Edge 設定其瀏覽器擴充功能。擴充功能的設定適用於所有使用者，可能會要求你的系統密碼；取消或擴充功能安裝失敗，仍會選取並啟動 Claude。重新啟動你的瀏覽器，依提示啟用擴充功能，並登入 Claude 以完成連接。在 Claude 中執行 `/chrome` 以檢查連線。Firefox 與 Zen 不支援此擴充功能。如果在加入此設定之前 Claude 已經是你的預設值，請再次選取它以安裝擴充功能。

一旦你選好了，`Super + Shift + Ctrl + A` 會在專用的終端機視窗中啟動預設代理（或者如果你尚未選擇，則叫出挑選器）。你也可以用 `omarchy agent prompt "Review this project"` 直接讓它進入一項任務。Freebuff 與 DeepSeek Harness 不接受起始提示，所以它們開啟時會把提示放在你的剪貼簿中讓你貼上。以這種方式啟動的代理會在各自「不要停下來問」的模式中無人看管地執行，所以要做好它們真的會動手做事的準備！MiniMax Code 的互動式工作階段沒有這種模式，所以它會照常要求權限。而且由於代理拒絕記住對你家目錄的信任，從 `$HOME` 啟動時改為在 `~/Work` 中開始。

也有終端機捷徑：`a` 會在目前的終端機中就地執行預設代理，而 `c`、`cx` 與 `cy` 則直接啟動 OpenCode、Claude Code 與 Codex（同樣以其自動核准模式）。主題變更也會同步到代理：Claude Code、Pi、OpenCode 與 Hermes（一旦 Omarchy 已安裝它）在你切換 Omarchy 主題時都會一併跟隨。

### 你的代理指示

給每個代理的個人規則放在 `~/.agents/AGENTS.md`，就在 `~/.agents/skills` 中共用技能的旁邊。用代理面板中 + 旁邊的文件圖示開啟它，或用 `omarchy agent instructions --edit`，它也會把該檔案連結進每個保留其自有全域檔案的 harness：`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`~/.pi/agent/AGENTS.md`、`~/.config/opencode/AGENTS.md`、Copilot 的 `~/.copilot/copilot-instructions.md`，依此類推。Crush 與 Amp 讀取 `~/.config/AGENTS.md` 連結，而 omp、Kimi 與 DeepSeek Harness 則直接讀取 `~/.agents/AGENTS.md`。挑選預設代理也會連結它。如果你已經有一個指示檔案，而尚無共用的，它就會成為共用的那個；否則它會以 `.bak` 的形式保留在連結旁邊。安裝另一個代理後，執行 `omarchy agent instructions` 以重新連結。

### 代理面板

頂部列有一個代理圖示。在你設定代理之前，其面板提供三種開始方式：登入 Claude、Codex、Grok、Gemini、Muse、Cursor 或 Copilot 訂閱，或在 More 之下選 OpenCode Go、MiniMax、Synthetic 或 Z.ai 程式編寫方案；以 Fireworks、OpenCode Zen 與 Go、OpenRouter 按用量付費，或在 More 之下選 DeepSeek 或 OpenCode 能登入的任何其他供應商，全都在 OpenCode 中執行；或者在有一款適合你的電腦時，執行最適合它的模型。你完成的第一個會成為你的預設代理，之後面板中的 + 仍提供同樣三種。之後，面板會把每個訂閱放在同一頁上：每個代理與帳號連同其方案、各有一個其 5 小時工作階段與每週限制的計量表，並顯示距離重置的時間（將滑鼠游標停在其上以查看確切百分比），或剩餘的預付餘額，上方還有一行輪流顯示你在所有這些之上使用過什麼，例如本週的 token 以及你最常使用的模型。在 _Make something cool_ 之下，它提供新主題、插件、應用程式或遊戲的入門提示，把任務交給你的預設代理。應用程式是以 Omarchy 自己的 Hype、Monologue 與 Omacut 相同的方式打造的，用 C++ 與 Qt Quick，遵循 omarchy-make-app 代理技能，且它們所需的編譯器與 Qt 組件會預先安裝。遊戲是位於 `~/Games/vibes` 的單一 three.js 頁面，遵循 omarchy-make-game 代理技能，全都從目前主題中的一個 Game Vibes 啟動器開啟；它們從網路載入 three.js，所以啟動時需要連線。Claude Code、Codex、Grok、Kimi、Cursor 及其 Grok Bot 額度、GitHub Copilot、Muse、Gemini（透過 Antigravity）與 Devin 一開箱就涵蓋在內並有其限制，Kimchi 則有其方案、預付點數與花費預算，而 Hermes、Mistral Vibe 與 Qwen Code 則在你使用過之後顯示其工作階段與 token。透過 pi、omp 或 opencode 使用的供應商方案與金鑰也會顯示：OpenCode Zen 與 Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan 與 Synthetic 及其限制；OpenRouter 與 DeepSeek 及其預付餘額；Fireworks 及其過去 30 天的花費。你在自己的硬體上執行的模型的 token 也會計入總計；模型本身有自己的面板，如 [本機模型](#local-models) 所述。無論你透過多少 harness 來驅動它，每個代理都只計算一次，並歸在其向你收費的那一方之下。

左鍵按一下列上的圖示或按下 `Super + Ctrl + X` 可開啟面板，右鍵按一下可啟動你的預設代理，以中鍵按一下可重新整理。其背後的使用記錄每 15 分鐘由 `omarchy agent usage update` 重新產生，且該面板甚至可以透過已同步的資料夾合併來自你其他機器的使用量。完整設定請參閱 `$OMARCHY_PATH/shell/plugins/agents/` 之下的 README。

### 多個訂閱

如果你付費訂閱了不止一個 Claude、Codex 或 Grok 方案，例如一個個人的 Max 和一個工作的，Omarchy 可以讓它們全都保持登入狀態，並在它們之間切換。用代理面板中的 + 新增一個訂閱，它會就在那裡一步步引導你；或用 `omarchy agent account add claude Work`（或 `codex`，或 `grok`）。同樣的 + 與指令可登入 Gemini（`gemini`）與 OpenCode（`opencode`），並在 OpenCode 中儲存 Fireworks（`fireworks`）或 OpenRouter（`openrouter`）API 金鑰；該指令也可登入 Copilot（`copilot`）、Cursor（`cursor`）與 Muse（`muse`）。那幾者各自只保留單一登入。若缺少 CLI 它會安裝它。某供應商的第一個帳號會透過你的一般瀏覽器登入，就在 CLI 一直查看的地方。之後的每一個帳號都透過隱私視窗登入，所以你的瀏覽器已登入的帳號就不會被誤挑中；在那裡以你要新增的帳號登入，且先關閉你已開啟的任何隱私視窗。絕對不要為了做這件事而登出 CLI：登出會撤銷已儲存的登入，而該帳號將必須重新新增。

要透過 SSH 將你的訂閱登入複製到另一台 Omarchy 機器，執行 `omarchy agent account copy user@laptop`。當目的地尚未安裝接收端時，傳送端會提供一個暫時接收端，所以較舊的 Omarchy 機器無需更新即可接收帳號。已安裝的接收端優先。這會複製所有 Claude、Codex 與 Grok 訂閱；加入供應商名稱來選取它們，例如 `omarchy agent account copy laptop claude`。帳號名稱與指令 ID 與來源相符，包括目的地已存在的帳號。目的地不相關的帳號若名稱衝突，會獲得一個數字尾碼，而設定、技能、插件與對話歷史則各自保留在本機。

目的地現有的憑證會保留。已經在那裡登入的來源帳號，其名稱會被同步但不替換其憑證；其他帳號則會加在它旁邊。要替換相符合帳號已儲存的憑證，請在結束目的地該帳號的工作階段後使用 `omarchy agent account copy --replace laptop claude`。全新的目的地也會獲得來源的作用中帳號與切換偏好設定；已有設定的目的地則保留它自己的。

憑證透過 SSH 傳送，並儲存在目的地的私密檔案中，所以只複製到你信任的機器。這是一次性的複製，不是持續的同步。Codex 的重新整理 token 可能會被另一台機器輪替，導致複製過去的登入需要續期；在多台機器上同時使用時，分別登入仍是最可靠的選擇。請參閱 [Codex 的帳號驗證指南](https://developers.openai.com/codex/auth/ci-cd-auth)。

每個供應商有一個作用中的帳號，且每個新工作階段都以它開始：`cx`、`cy`、一個普通的 `claude`、`codex` 或 `grok`，任何透過 `omarchy agent` 啟動的東西，以及在 `PATH` 上找到該 CLI 的指令稿或編輯器。用 `omarchy agent account use work` 切換（並用 `omarchy agent account use main` 切換回來），或在面板中按下帳號的編號然後按 `Enter`（或點按其星號）。執行中的 Claude 工作階段也會切換，自其下一則訊息開始：每個 Claude 工作階段都在 `~/.claude` 中執行，該處永遠持有作用中帳號的登入。由較舊的 Omarchy 在帳號自己的資料夾中啟動的 Claude 工作階段，會持有該登入直到退出為止，所以切換會點名那些工作階段，並在它們消失後自行完成。執行中的 Codex 與 Grok 工作階段會停留在它們開始時的帳號。對話歷史、設定、技能與插件在帳號之間共用，所以在相同資料夾中執行 `claude --continue` 會在新帳號上接續你離開的地方。

當有一個以上的帳號時，面板會並排顯示每個帳號的限制，使用中的那個有填滿的星號。當作用中帳號超過某限制的 95% 時，Omarchy 會通知你，點按通知就會切換到餘裕最大的帳號。它絕不會自行切換。用 `omarchy agent account threshold 90` 變更門檻。如果每個帳號都超過門檻，你會收到一次通知，並同時得知哪個帳號會最先釋出。當作用中帳號距其門檻在 15 個百分點以內（預設為 80%）時，其限制會每三分鐘檢查一次，而非每 15 分鐘。

`omarchy agent account list` 顯示每個帳號與其最新限制，`omarchy agent account remove work` 會忘記一個，`omarchy agent account rename primary Hey` 則會重新命名一個（或在面板中點按帳號的名稱）。這些指令作用於你的預設代理的帳號；要接觸其他供應商，先點名它，例如 `omarchy agent account use codex side`。你已在 `~/.claude` 或 `~/.codex` 中已有的登入是 _Main_ 帳號。Codex 的會停留在原處；Claude 的則在另一個帳號作用中時，待在它自己的資料夾中。閒置超過約八小時的帳號可能會顯示 _Sign-in required_；點按它就直接在面板中再次登入該帳號，或切換到它並開始一個工作階段，它會自行重新整理登入。你用 `claude mcp add` 新增的 MCP 伺服器會到達每個 Claude 帳號，因為它們全都在 `~/.claude` 中執行；對於 Codex 與 Grok，你在新增帳號時已有的伺服器會隨之而來，但之後新增的只會到達你新增它們時的那個帳號。Claude Desktop 保留它自己的登入，而以 CLI 二進位檔的絕對路徑設定的 Codex 或 Grok 工具不會跟隨切換。明確的 `CLAUDE_CONFIG_DIR`、`CODEX_HOME` 或 `GROK_HOME` 優先於所選帳號。

### 當機診斷

Omarchy 會監看 systemd-coredump 以偵測處理程序當機。一旦你挑選了預設代理，你的任何程式傾印核心時都會帶來一個 "Process crashed" 通知 — 點按它，當機就會連同 Omarchy 的 omarchy-diagnose-crash 技能一起交給你的預設代理，該技能會帶領代理從核心傾印中確立事實，並判定該當機是否值得向上游回報。你也可以用 `omarchy agent crash <pid>` 手動針對 `coredumpctl list` 中的任何 PID 執行它。

此監看預設開啟。在 _Trigger > Toggle > Crash Capture Off_ 之下關閉它（或用 `omarchy toggle crash-capture`），通知就會停止；`omarchy agent crash <pid>` 仍可手動運作。

也可以一次讓一個程式的當機靜音，這正是診斷最後提供給你的選項。`omarchy crash mute hyprland` 只停止該程式的通知，`omarchy crash mute hyprland off` 會將其恢復，而單獨執行 `omarchy crash mute` 則列出你已靜音的項目。它同樣樂意接受二進位檔的路徑和名稱，所以 `omarchy crash mute /usr/bin/hyprland` 效果相同。將含有空格的名稱引號包起來，例如 `omarchy crash mute 'Some App'`。其他一切仍會通知，且被靜音的程式仍會當機 — 這只是隱藏提醒，它不修復任何東西。

### 桌面應用程式

_Install > AI_ 選單還收錄了幾個圖形化 AI 應用程式：Amp Desktop、Antigravity Desktop、ChatGPT 桌面應用程式、Claude 桌面應用程式（Anthropic 的 Linux beta，具備 Chat、Cowork 與 Claude Code 分頁）、用於與 xAI 模型聊天的 Grok Bot、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexity 桌面應用程式，以及 T3 Code。Grok Bot 是桌面聊天應用程式。程式編寫代理則是 `grok` 指令。

Hermes Desktop 是你需要知道的那一個，因為一台機器只有一個 Hermes，且它屬於該應用程式：Hermes 僅能透過該應用程式安裝，而預設代理執行的 `hermes` 指令也是該應用程式的。選擇 Hermes 作為預設代理，所安裝的與 _Install > AI_ 項目相同：該套件，以及一個由 Hermes 自己的安裝程式設定、位於 `~/.hermes` 之下的 Hermes 執行階段，第一次需時幾分鐘。該執行階段是終端機 `hermes` 指令、預設代理與該應用程式全都使用的那一個 Hermes，且它會以 `hermes update` 自行更新，而非等待 Omarchy 發行。它安裝時還會把 Omarchy 主題作為名為 `omarchy` 的外觀交給 Hermes，每個 Hermes 介面都會在你切換主題時跟隨它；若你寧願它不要這麼做，在 Hermes 的 Appearance 設定之下或用 `/skin` 選另一個，Omarchy 就不會干涉該選擇。在 _Remove > AI_ 之下移除該應用程式會先關閉 Hermes（包括閘道），一併帶走該執行階段，並保留你的聊天、記憶以及 Hermes 為自己寫的技能，除非你另行指示：它會詢問，預設為否，是否也該一併移除那些資料以及你的連線設定。

OpenClaw 的桌面體驗是其 Control UI，它以其自己的本機閘道為後端，以網頁應用程式形式開啟。OpenClaw 位於 `~/.openclaw` 並會自我更新：使用 Control UI 的 "Update Gateway" 按鈕或執行 `openclaw update`，閘道就會以新版本重新啟動。Omarchy 只選擇全新安裝所起始的版本。OpenClaw 也可以是你的預設代理：以 `omarchy default agent openclaw` 選擇它會在 `~/.openclaw` 中設定相同的那一份副本，且該代理會開啟連接至其閘道的 OpenClaw 終端機 UI。在 _Remove > AI_ 之下移除 OpenClaw 會一併帶走閘道服務與該應用程式，然後詢問 `~/.openclaw` 是否也該移除，因為那裡放著你的聊天與憑證，以及 OpenClaw 本身與它下載的插件執行階段；預設會保留它，再次安裝 OpenClaw 時會重新取用它。

Herdr Desktop 是 [Herdr](https://herdr.dev) 桌面應用程式：由終端機與程式編寫代理組成的空間、分頁與窗格，在你關閉視窗後仍在其核心中持續執行。它來自 Herdr 自己的安裝程式而非套件，所以它位於 `~/.local/share/herdr-app`，當你尚未擁有時，會在 `~/.local/bin/herdr-core` 附帶其核心，並自行更新這兩者。它與 Omarchy 隨附於 `Super + Ctrl + Return` 的 `herdr` 指令並列，而非取代它，並承襲了該指令的直接按鍵：`Alt + Return` 與 `Alt + Shift + Return` 向下或向右分割窗格，`Alt + Escape` 關閉它，`Ctrl + Alt + Arrow` 在窗格之間移動，`Alt + 1..9` 與 `Alt + Left/Right` 選擇分頁，而 `Alt + Up/Down` 在空間之間移動。`Ctrl + 1..9` 選擇空間，`Alt + Shift + Up/Down` 則逐一遍歷代理。`Ctrl + Space` 前綴按鍵仍僅供終端機使用，因為該應用程式無法為一個序列按住一個單純的 Ctrl 鍵。Omarchy 將這些寫入 `~/.config/herdr-app/keys.json`，而 `omarchy-refresh-herdr-app` 會把它們恢復。安裝它會選取 Herdr 的 Omarchy 主題，從此跟隨你的 Omarchy 主題。Herdr 會為淺色模式保留一款主題、為深色模式保留另一款，所以在深色與淺色 Omarchy 主題之間切換後，請在 Herdr 的主題挑選器中再次選取 Omarchy 以套用另一種模式。

T3 Code 從位於 `~/.local/share/t3code` 的官方 AppImage 版本執行，而非從套件執行，所以它會自我更新。安裝它時會詢問要從 Stable 或 Nightly 頻道開始；之後可在 T3 Code 的設定中切換。你的討論串與設定位於 `~/.t3`，在 _Remove > AI_ 之下移除 T3 Code 會一併帶走它們。

### 本機模型

在你自己的機器上為你的程式編寫代理執行一個開放模型。你的提示與程式碼都留在機器上；傳送給模型的任何東西都不會離開它。以下列指令開始：

```bash
omarchy models use best text
```

那會設定最適合這台機器的文字模型，也就是你的代理所使用的那種。圖像、影片與音樂模型各有其最佳選擇：`omarchy models use best image`、`video` 或 `music`。執行 `omarchy models use best` 查看每一種類為這台機器所挑選的項目。

或者從頂部列中，代理圖示旁邊的閃亮圖示開啟本機模型面板，或用 Super + Ctrl + Alt + X，並選擇 +。當有模型適合這台機器時，該圖示就會出現。執行模型的 Podman 隨 Omarchy 附帶，NVIDIA 機器上的 NVIDIA 容器工具組也是，它為模型提供 GPU；若缺少任一者，首次設定會安裝它。然後 Omarchy 會為這台機器挑選推薦的模型、下載它並啟動它。預期會有數十 GB 的下載，且模型執行期間機器的多數記憶體會被使用：Flash Next 以其完整的 256K 上下文使用約 100 GiB。如果其他模型佔著它所需的記憶體，它會以已停止的狀態設定好，隨時可在你停止其中一個後啟動。模型會在登出時停止；當你需要將記憶體用於其他用途時，請自行停止它。

`omarchy models list` 顯示選項並解釋為何有些不適合。要設定另一個，執行 `omarchy models use <recipe>`。今日，`qwen3.8-flash-next-gufo` 與 `qwen3.8-27b-gufo` 可用於 128 GB Strix Halo 機器；27B 佔用約 40 GiB，所以會留下空間進行其他工作。在一台配備 Intel 的 Arc B390 的 64 GB 筆記型電腦上，`qwen3.6-35b-a3b-llamacpp` 以約 30 GiB 執行。新的配方與推薦會隨 `omarchy update` 透過套件到達。

你設定的每個模型在本機模型面板中都有自己的一行：播放可啟動它，暫停可停止它並釋放其記憶體，終端機按鈕可在它之上開啟你的代理。橫跨頂端，有一條列顯示機器的記憶體如何在 Omarchy 本身（系統與你的應用程式）、每個執行中的模型以及剩餘空間之間分配。指向一個已停止的模型，該列會顯示它是否適合，或它差多少。當多個模型可以一起放入記憶體時，可以同時執行多個；如果有一個放不下，Omarchy 會說明要停止哪個執行中的模型。拖曳其標誌以重新排列各行，並在所選行上按 Delete 以移除模型及其下載。

你設定的每個程式編寫模型也會在應用程式啟動器中得到自己的條目，以該模型的名稱並附其製造者的標誌，就像登入 Claude、Codex 或 Grok 時會新增一個一樣。它會在該模型上開啟你的代理，若它尚未執行，則先啟動該模型：終端機顯示它正在載入，並在它啟動後移交給代理。移除模型會移除其條目。

並非每個模型都是用於程式編寫的。圖像、影片與音樂模型則在 Fantasi 中開啟，那是 Omarchy 用以利用在這台機器上執行的模型製作圖片、影片與音樂的應用程式，可在那裡或從它們在本機模型面板中的那一行來挑選。

模型會完全按照它設定時的樣子持續執行，所以 Omarchy 更新絕不會在你的代理之下重新啟動一個。當 Omarchy 擁有你已設定的模型之較新的執行階段或較新的權重時，它的那一行會顯示更新按鈕：按一下，模型就會在背景重新設定，只下載有變更的部分，並以新版本重新啟動。已停止的模型仍會保持停止。`omarchy models update` 從終端機對每個模型做同樣的事。

從命令列，`omarchy models start <recipe>` 與 `omarchy models stop <recipe>` 做同樣的事，`omarchy models status` 顯示每一個模型，而 `omarchy agent --local-model <recipe>` 無論你的預設代理是什麼，都會在 pi 中開啟該模型。要讓你的本機模型成為代理快速鍵、Quake 主控台與 _Make something_ 所開啟的對象，執行 `omarchy default agent local` 或在代理面板中為執行中的模型加上星號。pi 也會在其自己的模型挑選器中列出你設定的每個模型，以及位於你已配對機器上的那些，所以普通的 `pi` 也能觸及它們。任何與 OpenAI 相容的客戶端也能連接：`status` 顯示每個模型的位址（第一個是 `http://127.0.0.1:11435/v1`），配方名稱就是模型，而金鑰位於 `~/.config/omarchy/agent-local/key`。

`omarchy models remove <recipe>` 刪除一個模型以及沒有其他模型使用的那些下載。

第三方執行階段標有其發行者。Omarchy 在無網路存取的情況下執行每一個模型。

### 本機 LLM

Omarchy 推薦兩種執行本機 LLM 模型的方式：LM Studio 與 Ollama。LM Studio 提供了一個 GUI 介面，用於尋找開放權重模型、安裝它們並執行它們。這是輕鬆上手的絕佳方式。Ollama 提供了一個 CLI 來同樣做到這一點。但如果你是本機模型的新手，我會從 LM Studio 開始。你可以在 Omarchy 選單的 _Install > AI_ 之下安裝任一者。

### Omarchy 技能

代理技能協助 AI 以特定的方式使用特定的工具，而 Omarchy 隨附了七個。omarchy 技能涵蓋量身打造系統，如微調你的 Hyprland 設定或調整該列。omarchy-make-theme、omarchy-make-plugin、omarchy-make-app 與 omarchy-make-game 涵蓋製作新的東西，omarchy-contribute 涵蓋回報錯誤或向上游送出修復，而 omarchy-diagnose-crash 則處理當機的核心傾印。它們被符號連結到 Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` 以及每個 `~/.hermes/profiles/*/skills`）的技能目錄，以及通用的 `~/.agents/skills` 位置，所以大多數 harness 會自動拾取它們。你自己擁有、名稱相同的技能資料夾優先。

但你應該將這些技能視為實驗性質。不同的模型使用它的效果會不同。最好先在計畫模式中執行，這樣你就會知道代理想變更什麼。然後做好復原變更的準備，甚至在代理把一切弄得一團糟時，呼叫 `omarchy reinstall configs`。
