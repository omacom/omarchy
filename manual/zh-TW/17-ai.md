### 安裝與更新 Agent

除了 Hermes 與 OpenClaw 之外，這些 Agent 都使用 mise 的延遲安裝：首次啟動會安裝 CLI，後續啟動則重複使用它。mise 也會在啟動前或在 shell 提示字元處於背景中，最多每四小時檢查一次已安裝 Agent 是否有新版本。如果該更新失敗或你處於離線狀態，就會執行已安裝的版本。`omarchy update` 會連同 Omarchy 其餘部分一起更新已安裝的 Agent，而 `mup` 則僅更新由 mise 管理的工具。

Agent 專屬的更新程式，例如 `claude update`、`codex update`，或應用程式中的更新按鈕，都不會更新由 mise 管理的安裝。`codex update` 會失敗，而 `claude update` 可能回報成功，卻安裝了一份 mise 未追蹤的獨立副本。如果你寧願使用 Agent 原生的安裝程式與更新程式，請將其加入 `disable_tools`；請參閱 [預先安裝的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

若要在需要之前安裝所有已設定的 lazy tools，請執行 `mise install --include-lazy`。這包括 Omarchy 的其他預設 CLI 工具以及這些 Agent。有關安裝單一工具或使用你自己的安裝方式，請參閱 [預先安裝的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

`grok` 透過 mise 的第一方 `grok` 套件安裝，方式與 `claude` 和 `codex` 相同。執行 `grok`，或在 _Agent > Harness_ 下選擇它。跳過 x.ai 上的 `curl | bash` 安裝程式。那條路徑會在 `~/.grok/bin` 放第二份副本、把它加到 `PATH` 前面，並覆寫 Omarchy 的包裝程式。

`dsh` 會在 `127.0.0.1:3080` 開啟其瀏覽器 UI，並以啟動目錄作為其預設工作區。它的瀏覽器 UI 不接受起始提示，因此 `omarchy agent prompt` 會開啟它，並將提示放在你的剪貼簿中供你貼上。Omarchy 會以 DeepSeek 的 no-approval 權限預設集啟動它。當你使用其官方模型 API 時，DeepSeek Harness 會將工作階段記錄上傳至 DeepSeek；請在其瀏覽器 UI 的 _Settings > General > Upload Session Log_ 下關閉此功能。你傳送給它的意見回饋也會連同工作階段一起上傳，除非你以 `DSH_TELEMETRY_MODE=DISABLED` 啟動它。

### 預設 Agent

使用 `omarchy default agent <name>` 或在 Omarchy Menu (`Super + Space`) 的 _Agent > Harness_ 下挑選你的預設 Agent。如果該 Agent 尚未安裝，選擇它會先進行安裝，而且它還會在應用程式啟動器中 Agent 旁邊獲得專屬的啟動器。全新的 Omarchy 會透過一次性通知邀請你做此選擇。

選擇 Claude 也會嘗試為 Chromium、Chrome、Brave、Brave Origin 以及 Edge 設定其瀏覽器擴充功能。擴充功能設定適用於所有使用者，而且可能要求你輸入系統密碼；取消或擴充功能安裝失敗，仍會選擇並啟動 Claude。重新啟動你的瀏覽器，如果出現提示就啟用該擴充功能，並登入 Claude 以完成連線。在 Claude 中執行 `/chrome` 以檢查連線。Firefox 與 Zen 不支援此擴充功能。如果在加入此設定之前 Claude 就已經是你的預設值，請再次選擇它以安裝擴充功能。

一旦你做出選擇，`Super + Shift + Ctrl + A` 會在專用的終端機視窗中啟動預設 Agent (或者如果你尚未選擇，則會顯示選擇器)。你也可以使用 `omarchy agent prompt "Review this project"` 讓它直接進入任務。Freebuff 與 DeepSeek Harness 不接受起始提示，因此它們會開啟並將提示放在你的剪貼簿中供你貼上。以這種方式啟動的 Agent 會在其各自的不要停下來問模式下無人看管地執行，所以要做好它們真的會動手做事的準備！MiniMax Code 的互動式工作階段沒有這種模式，因此它會照常要求權限。而且由於 Agent 拒絕記住對你家目錄的信任，因此從 `$HOME` 啟動時會改在 `~/Work` 中開始。

也有終端機快捷鍵：`a` 會在目前的終端機中內嵌執行預設 Agent，而 `c`、`cx` 和 `cy` 則會直接啟動 OpenCode、Claude Code 與 Codex (同樣是在其自動核准模式下)。主題變更也會同步至這些 Agent：當你切換 Omarchy 主題時，Claude Code、Pi、OpenCode 以及 Hermes (一旦 Omarchy 已安裝它) 都會跟著變。

### 你的 Agent 指示

適用於每個 Agent 的個人規則放在 `~/.agents/AGENTS.md`，就在 `~/.agents/skills` 中的共享技能旁邊。在 _Agent > Instructions_ 下開啟它，它也會將其連結至每個保有自己全域檔案的 harness：`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`~/.pi/agent/AGENTS.md`、`~/.config/opencode/AGENTS.md`、Copilot 的 `~/.copilot/copilot-instructions.md`，以此類推。Crush 與 Amp 讀取 `~/.config/AGENTS.md` 連結，而 omp、Kimi 與 DeepSeek Harness 則直接讀取 `~/.agents/AGENTS.md`。挑選預設 Agent 也會連結它。如果你已經有一個指示檔案，而目前還沒有共享檔案，它就會成為共享檔案；否則它會以 `.bak` 形式保留在連結旁邊。在安裝另一個 Agent 之後，執行 `omarchy agent instructions` 以重新連結。

### Agent 面板

頂部列有一個 Agent 圖示。在你設定 Agent 之前，其面板會引導你登入 Claude、Codex 或 Grok，而第一個會成為你的預設 Agent。在此之後，面板會將每個訂閱都放在同一頁面上：在一行輪替顯示你跨所有訂閱的使用量 (例如本週的 token 以及你最常使用的模型) 之下，列出每個 Agent 與帳戶及其方案、其 5 小時工作階段與每週限制各自的儀表及距離重置的時間 (將滑鼠懸停以查看確切百分比)，或剩餘的預付餘額。在 _Make something cool_ 下，它提供用於新主題、外掛程式、應用程式或遊戲的入門提示，並將任務交給你的預設 Agent。應用程式的建置方式與 Omarchy 專屬的 Hype、Monologue 與 Omacut 相同，都是以 C++ 與 Qt Quick 打造，遵循 omarchy-make-app Agent 技能，而且它們所需的編譯器與 Qt 元件都已安裝。遊戲是位於 `~/Games/vibes` 中的單一 three.js 頁面，遵循 omarchy-make-game Agent 技能，而且全都從目前主題中的一個 Game Vibes 啟動器開啟；它們會從網路載入 three.js，因此需要連線才能開始。Claude Code、Codex、Grok、Kimi、Cursor 及其 Grok Bot 額度、GitHub Copilot、Muse、Antigravity 以及 Devin 開箱即可涵蓋，並附其限制，Kimchi 則附其方案、預付點數與支出預算，而 Hermes、Mistral Vibe 與 Qwen Code 則會在你使用過它們後顯示其工作階段與 token。你透過 pi、omp 或 opencode 使用的供應商方案與金鑰也會顯示：OpenCode Zen 與 Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan 以及 Synthetic，並附其限制；OpenRouter 與 DeepSeek 則附其預付餘額；Fireworks 則附其過去 30 天的支出；以及你在自己的硬體上執行的模型，列在 Local models 下。每個 Agent 只會計算一次，以向其收費的一方為準，無論你透過多少 harness 來驅動它。

左鍵按一下列圖示或按下 `Super + Ctrl + X` 以開啟面板，右鍵按一下以啟動你的預設 Agent，中鍵按一下以重新整理。其背後的用量記錄每 15 分鐘由 `omarchy agent usage update` 重新產生，而且面板甚至可以透過同步資料夾合併來自你其他機器的用量。完整設定請參閱 `$OMARCHY_PATH/shell/plugins/agents/` 下的 README。

### 多個訂閱

如果你付費訂閱了不只一個 Claude、Codex 或 Grok 方案 — 例如一個個人 Max 和一個工作用的 — Omarchy 可以讓它們全都保持登入，並在它們之間移動。使用 Agent 面板中的 + 新增訂閱，它會直接在那裡引導你完成，或使用 `omarchy agent account add claude Work` (或 `codex`，或 `grok`)。如果缺少 CLI，它會進行安裝。每個供應商的第一個帳戶會透過你的一般瀏覽器登入，就在 CLI 一直查找的位置。在此之後的每個帳戶都會透過隱私視窗登入，因此你瀏覽器已經登入的帳戶就不會被誤挑；請在那裡以你要新增的帳戶登入，並先關閉你已經開啟的任何隱私視窗。永遠不要為了做這件事而登出 CLI：登出會撤銷已儲存的登入，而該帳戶就必須重新新增。

若要透過 SSH 將你的訂閱登入複製到另一台 Omarchy 機器，請執行 `omarchy agent account copy user@laptop`。當目的地沒有安裝接收端時，傳送方會提供一個暫時接收端，因此較舊的 Omarchy 機器無需更新即可接收帳戶。已安裝的接收端優先。此功能會複製所有 Claude、Codex 與 Grok 訂閱；加入供應商名稱以選擇它們，例如 `omarchy agent account copy laptop claude`。帳戶名稱與指令 ID 與來源相符，包括目的地已經存在的帳戶。無關的目的地帳戶如果名稱衝突，會獲得數字後綴，而設定、技能、外掛程式與對話記錄則各自保留在每台機器本機。

目的地現有的憑證會保留。已經在那裡登入的來源帳戶，其名稱會同步，但不會取代其憑證；其他帳戶則會加在它旁邊。若要取代相符帳戶已儲存的憑證，請在結束目的地該帳戶的工作階段後，使用 `omarchy agent account copy --replace laptop claude`。全新目的地還會獲得來源目前使用中的帳戶與切換偏好；已建立的目的地則保留自己的。

憑證會透過 SSH 傳輸，並儲存在目的地的私人檔案中，因此只能複製到你信任的機器。這是一次性複製，不是持續同步。Codex 的重新整理 token 可能會被另一台機器輪替，導致複製過去的登入需要續期；在多台機器上同時使用時，個別登入仍然是最可靠的選擇。請參閱 [Codex 的帳戶驗證指南](https://developers.openai.com/codex/auth/ci-cd-auth)。

每個供應商只有一個帳戶是目前使用中的，而每個新工作階段都會以它開始：`cx`、`cy`、普通的 `claude`、`codex` 或 `grok`、透過 `omarchy agent` 啟動的任何東西，以及在 `PATH` 上找到 CLI 的指令稿或編輯器。使用 `omarchy agent account use work` 切換 (並使用 `omarchy agent account use main` 切換回來)，或在面板中按下帳戶的號碼再按 `Enter` (或按一下其 Use 按鈕)。執行中的 Claude 工作階段也會切換，從其下一則訊息開始：每個 Claude 工作階段都在 `~/.claude` 中執行，該目錄永遠保存著目前使用中帳戶的登入資訊。由較舊 Omarchy 在帳戶專屬資料夾中啟動的 Claude 工作階段會保留該登入，直到它結束為止，因此切換會列出這些工作階段，並在它們消失後自行完成。執行中的 Codex 與 Grok 工作階段會留在它們開始時所用的帳戶上。對話記錄、設定、技能與外掛程式會在帳戶之間共享，因此在同一個資料夾中的 `claude --continue` 會在新帳戶上從你上次中斷的地方繼續。

擁有多個帳戶時，面板會並排顯示每個帳戶的限制，並標記目前使用中的帳戶。預設情況下，當目前使用中的帳戶超過某個限制的 95% 時，Omarchy 會通知你，而按下通知會切換到餘裕最多的帳戶。將滑鼠懸停在面板中帳戶的那一行上，並按一下出現在 Use 旁邊的 Autoswitch (或按下 `m`)，或執行 `omarchy agent account mode auto`，即可讓它自行切換；而當它開啟時，Autoswitch 會取代 Use 的位置，再按一下它就會回到通知模式。加入數字以變更門檻，例如 `omarchy agent account mode auto 90`。如果每個帳戶都超過門檻，你會收到一次通知，並告知哪個帳戶最先釋出。當目前使用中的帳戶距離其門檻在 15 個百分點以內 (預設為 80%) 時，其限制會每三分鐘檢查一次，而不是每 15 分鐘一次。

`omarchy agent account list` 會顯示每個帳戶及其最新限制，`omarchy agent account remove work` 會忘記一個帳戶，而 `omarchy agent account rename primary Hey` 會重新命名一個帳戶 (或在面板中按一下帳戶名稱)。這些指令對你預設 Agent 的帳戶起作用；若要到達其他供應商，請先指名它，例如 `omarchy agent account use codex side`。你已經在 `~/.claude` 或 `~/.codex` 中擁有的登入是 _Main_ 帳戶。Codex 的會留在原處；Claude 的則在另一個帳戶使用中時，會在專屬的資料夾中等待。一個帳戶超過約八小時未使用，可能會顯示 _Sign-in required_；按一下它即可直接在面板中重新登入該帳戶，或切換到它並啟動一個工作階段，這會自行重新整理登入。你使用 `claude mcp add` 新增的 MCP 伺服器會到達每個 Claude 帳戶，因為它們都在 `~/.claude` 中執行；對於 Codex 與 Grok，你在新增帳戶時已有的伺服器會隨之而來，但之後的伺服器只會到達你新增它們時所在的帳戶。Claude Desktop 會保留專屬的登入，而使用 CLI 二進位檔絕對路徑設定的 Codex 或 Grok 工具不會跟隨切換。明確的 `CLAUDE_CONFIG_DIR`、`CODEX_HOME` 或 `GROK_HOME` 優先於所選的帳戶。

### 當機診斷

Omarchy 會監看 systemd-coredump 以找出程序當機。一旦你挑選了預設 Agent，你的任何程式一旦傾印核心，就會帶來一個 "Process crashed" 通知 — 按一下它，當機就會連同 Omarchy 的 omarchy-diagnose-crash 技能一同交給你的預設 Agent，該技能會引導 Agent 從核心傾印中確立事實，並判定該當機是否值得向上游回報。你也可以使用來自 `coredumpctl list` 的任何 PID，透過 `omarchy agent crash <pid>` 手動執行它。

監看預設開啟。在 _Trigger > Toggle > Crash Capture Off_ 下將其關閉 (或使用 `omarchy toggle crash-capture`) 後，通知就會停止；`omarchy agent crash <pid>` 仍可用手動方式運作。

當機也可以一次針對一個程式靜音，這正是診斷最後會提供給你的選項。`omarchy crash mute hyprland` 僅會停止該程式的通知，`omarchy crash mute hyprland off` 會將其恢復，而單獨的 `omarchy crash mute` 則會列出你已靜音的項目。它接受二進位檔的路徑就跟接受其名稱同樣樂意，因此 `omarchy crash mute /usr/bin/hyprland` 會做同樣的事。將含有空格的名稱用引號圍住，例如 `omarchy crash mute 'Some App'`。其他一切仍會通知，而被靜音的程式仍會當機 — 這隱藏的是提醒，並不修復任何東西。

### 桌上型應用程式

_Install > AI_ 選單還包含了一些圖形化 AI 應用程式：Amp Desktop、Antigravity Desktop、ChatGPT desktop app、Claude desktop app (Anthropic 的 Linux beta 版，附有 Chat、Cowork 與 Claude Code 分頁)、Grok Bot 用於與 xAI 的模型聊天、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexity desktop app 以及 T3 Code。Grok Bot 是桌上型聊天應用程式。程式設計 Agent 是 `grok` 指令。

Hermes Desktop 是你需要知道的那一個，因為一台機器只有一個 Hermes，而它屬於該應用程式：Hermes 一律只透過該應用程式安裝，而預設 Agent 執行的 `hermes` 指令就是該應用程式的。選擇 Hermes 作為預設 Agent，會安裝與 _Install > AI_ 項目安裝的相同東西：該套件，以及由 Hermes 自己的安裝程式在 `~/.hermes` 下設定的一個 Hermes 執行環境，第一次需要幾分鐘的時間。該執行環境就是終端機 `hermes` 指令、預設 Agent 與應用程式全都使用的那一個 Hermes，而且它會以 `hermes update` 自行更新，而不是等待 Omarchy 發行新版本。安裝它還會將 Omarchy 主題交給 Hermes，作為一個名為 `omarchy` 的外觀，隨著你切換主題，每個 Hermes 介面都會跟隨；如果你寧願它不要這樣，請在 Hermes 的 Appearance 設定下或以 `/skin` 選擇另一個，而 Omarchy 會讓該選擇保持原樣。在 _Remove > AI_ 下移除該應用程式，會先關閉 Hermes，包括閘道，將該執行環境一併帶走，並保留你的聊天、記憶，以及 Hermes 為自己編寫的技能，除非你另有指示：它會詢問，預設為否，該資料以及你的連線設定是否也應該一併刪除。

OpenClaw 的桌上型體驗是它的 Control UI，它會作為一個由其專屬本機閘道支援的網頁應用程式開啟。OpenClaw 居住在 `~/.openclaw` 並會自行更新：使用 Control UI 的 "Update Gateway" 按鈕，或執行 `openclaw update`，閘道便會在新版本上重新啟動。Omarchy 只會選擇全新安裝的起始版本。OpenClaw 也可以是你的預設 Agent：在 _Agent > Harness_ 下選擇它，會在 `~/.openclaw` 設定同樣的副本，而該 Agent 會開啟連接至其閘道的 OpenClaw 終端機 UI。在 _Remove > AI_ 下移除 OpenClaw，會將閘道服務與應用程式一併帶走，然後詢問 `~/.openclaw` 是否也應該一併刪除，因為那裡除了 OpenClaw 本身以及它下載的外掛程式執行環境之外，還保存著你的聊天與憑證；預設會保留它，而再次安裝 OpenClaw 會將它重新接回。

Herdr Desktop 是 [Herdr](https://herdr.dev) 桌上型應用程式：當你關閉視窗時，終端機與程式設計 Agent 的 spaces、tabs 與 panes 會在其核心中持續執行。它來自 Herdr 自己的安裝程式而不是套件，因此它居住在 `~/.local/share/herdr-app`，當你尚未擁有時，它會在 `~/.local/bin/herdr-core` 一併帶來其核心，而且兩者都會自行更新。它位於 Omarchy 在 `Super + Ctrl + Return` 上隨附的 `herdr` 指令旁邊，而不是取代它，而且會獲得該指令的直接按鍵：`Alt + Return` 與 `Alt + Shift + Return` 會向下或向右分割窗格，`Alt + Escape` 會關閉它，`Ctrl + Alt + Arrow` 會在窗格間移動，`Alt + 1..9` 與 `Alt + Left/Right` 會選擇分頁，而 `Alt + Up/Down` 會在 spaces 之間移動。`Ctrl + 1..9` 會選擇一個 space，而 `Alt + Shift + Up/Down` 會逐步切換 Agent。`Ctrl + Space` 前綴按鍵仍然是終端機專用，因為該應用程式無法為了序列而按住一個普通的 Ctrl 鍵。Omarchy 會將這些寫入 `~/.config/herdr-app/keys.json`，而 `omarchy-refresh-herdr-app` 會將它們放回。安裝它會挑選 Herdr 的 Omarchy 主題，從此它會跟隨你的 Omarchy 主題。Herdr 會為淺色模式保留一個主題，並為深色模式保留一個，因此在深色與淺色 Omarchy 主題之間切換後，請在 Herdr 的主題選擇器中再挑選一次 Omarchy 以用於另一種模式。

T3 Code 從其位於 `~/.local/share/t3code` 的官方 AppImage 版本執行，而不是從套件執行，因此它會自行更新。安裝它會詢問是要從 Stable 還是 Nightly 頻道開始；稍後可在 T3 Code 的設定中切換。你的執行緒與設定居住在 `~/.t3`，而在 _Remove > AI_ 下移除 T3 Code 會將它們一併帶走。

### 本機模型

在你自己的機器上為你的程式設計 Agent 執行開放模型。你的提示與程式碼會留在機器上；傳送給模型的任何東西都不會離開它。從以下開始：

```bash
omarchy models use best text
```

或者，在頂部列的 Agent 面板中，選擇 + 然後選擇 Local AI，當有模型適合這台機器時它就會顯示。用來執行模型的 Podman 隨 Omarchy 附帶，NVIDIA 機器上的 NVIDIA container toolkit 也一樣，它會為它們提供 GPU；如果缺少任一項，第一次設定會安裝它。然後 Omarchy 會挑選這台機器的推薦模型、下載它並啟動它。預期下載量會達到數十 GB，而且模型執行時機器的大部分記憶體都會被使用：Flash Next 在其完整的 256K 上下文下會使用約 100 GiB。如果其他模型佔用了它需要的記憶體，它會設定為停止狀態，準備好在你停止一個模型後啟動。該模型會在登出時停止；當你需要將記憶體用於其他事情時，請自行停止它。

`omarchy models list` 會顯示選項，並解釋為什麼有些不適合。若要設定另一個，請執行 `omarchy models use <recipe>`。如今，`qwen3.8-flash-next-gufo` 與 `qwen3.8-27b-gufo` 可用於 128 GB Strix Halo 機器；27B 會用掉約 40 GiB，因此它會為其他工作留下空間。在配備 Intel 的 Arc B390 的 64 GB 筆記型電腦上，`qwen3.6-35b-a3b-llamacpp` 會在約 30 GiB 中執行。新的配方與建議會透過套件隨 `omarchy update` 一起到來。

你設定的每個模型都會在 Agent 面板中獲得專屬的一行，緊鄰你的訂閱：播放以啟動它，暫停以停止它並釋放其記憶體，而終端機按鈕則會在其上開啟你的 Agent。當它們能一起塞進記憶體時，數個可以同時執行；如果有一個塞不下，Omarchy 會說明該停止哪個正在執行的模型。拖曳各行以重新排序它們，並在選取的行上按 Delete 以移除模型及其下載。

你設定的每個模型也都會在應用程式啟動器中獲得專屬的條目，位於該模型的名稱下並附有其製造商的標誌，就像登入 Claude、Codex 或 Grok 會新增一個一樣。它會在該模型上開啟你的 Agent，而且如果它尚未執行，會先啟動該模型：終端機會顯示它正在載入，並在它就緒後交給 Agent。移除模型也會移除其條目。

並非每個模型都是為了寫程式。圖像、影片與音樂模型會改在 Fantasi 中開啟，Fantasi 是 Omarchy 用於以在這台機器上執行的模型製作圖片、影片與音樂的應用程式，從它們的啟動器條目以及它們在 Agent 面板中的那一行開啟。

模型會完全按照其設定方式持續執行，因此 Omarchy 更新永遠不會在你的 Agent 下方重新啟動它。當 Omarchy 為你已設定的模型提供了更新的執行環境或更新的權重時，它的那一行會顯示一個更新按鈕：按下它，該模型就會在背景中重新設定、僅下載已變更的部分，並在新版本上重新啟動。已停止的模型會保持停止。`omarchy models update` 會從終端機對每個模型做同樣的事。

從命令列來看，`omarchy models start <recipe>` 與 `omarchy models stop <recipe>` 會做同樣的事，`omarchy models status` 會顯示每個模型，而 `omarchy agent --local` 會在你上次啟動的模型上開啟你的預設 Agent。pi、OpenCode 與 Qwen Code 可以使用一個；對於任何其他預設值，它會在 pi 中開啟，如果你沒有 pi，則在 OpenCode 中開啟。pi 也會在其自己的模型選擇器中列出你已設定的每個模型，以及在你已配對的機器上的模型，因此普通的 `pi` 也能到達它們。任何與 OpenAI 相容的用戶端也可以連線：`status` 會顯示每個模型的位址 (第一個是 `http://127.0.0.1:11435/v1`)，配方名稱就是模型，而金鑰在 `~/.config/omarchy/agent-local/key` 中。

`omarchy models remove <recipe>` 會刪除一個模型以及沒有其他模型使用的下載。

第三方執行環境會標有其發行者。Omarchy 執行每個模型時都不會連接網路。

### 本機 LLM

Omarchy 推薦兩種執行本機 LLM 模型的方式：LM Studio 與 Ollama。LM Studio 提供一個 GUI 介面，用於尋找開放權重模型、安裝它們並執行它們。這是輕鬆上手的絕佳方式。Ollama 提供了一個 CLI，以類似的方式做到這一點。但如果你是本機模型的新手，我會從 LM Studio 開始。你可以在 Omarchy Menu 的 _Install > AI_ 下安裝任一項。

### Omarchy 技能

Agent 技能協助 AI 以特定方式使用特定工具，而 Omarchy 隨附了其中七個。omarchy 技能涵蓋了量身訂製系統，例如調整你的 Hyprland 設定或調整該列。omarchy-make-theme、omarchy-make-plugin、omarchy-make-app 與 omarchy-make-game 涵蓋了製作新東西，omarchy-contribute 涵蓋了回報錯誤或將修復傳送至上游，而 omarchy-diagnose-crash 則會處理當機的核心傾印。它們會以符號連結進入 Claude Code (`~/.claude/skills`)、Codex (`~/.codex/skills`)、Pi (`~/.pi/agent/skills`)、Antigravity (`~/.gemini/config/skills`)、Hermes (`~/.hermes/skills` 以及每個 `~/.hermes/profiles/*/skills`) 以及通用的 `~/.agents/skills` 位置的技能目錄，因此大多數 harness 都會自動挑選它們。具有相同名稱的你自己的技能資料夾優先。

但你應該將這些技能視為實驗性質。不同的模型會以不同的效果使用它。最好先在 plan mode 中執行，這樣你就能了解 Agent 想要變更什麼。然後準備好回復變更，甚至在 Agent 把一切搞得一團糟時，呼叫 `omarchy reinstall configs`。
