Omarchy 內含以下編程 agents 的啟動器，但不會替你選預設值。執行指令來在首次使用時安裝其 CLI，然後在收到提示時進行驗證。Hermes 是例外：首次使用時不會為它安裝任何東西，選擇它會安裝 Hermes Desktop，如下文 _桌面應用程式_ 一節所述。

### 安裝與更新 agents

Hermes 除外，這些 agents 都使用 mise 的延遲安裝：首次啟動會安裝 CLI，後續啟動則重用它。mise 也會最多每四小時檢查一次已安裝的 agent 是否有新版本，檢查時機是在它啟動之前，或在 shell 提示字元處於背景進行。如果該更新失敗或你處於離線狀態，就會執行已安裝的版本。`omarchy update` 會連同 Omarchy 的其他部分一起更新已安裝的 agents，而 `mup` 則只更新由 mise 管理的工具。

Agent 本身的更新程式，例如 `claude update`、`codex update`，或 app 中的更新按鈕，都不會更新由 mise 管理的安裝。`codex update` 會失敗，而 `claude update` 可能會回報成功，卻安裝了一份 mise 並未追蹤的另一份副本。如果你寧願使用 agent 的原生安裝程式與更新程式，請將它加入 `disable_tools`；請參閱[預先安裝的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

若要在需要使用之前就安裝所有已設定的延遲工具，請執行 `mise install --include-lazy`。這包含 Omarchy 的其他預設 CLI 工具以及這些 agents。如需安裝單一工具或使用你自己的安裝方式，請參閱[預先安裝的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

`grok` 是透過 mise 的第一方 `grok` 套件安裝的，方式和 `claude` 與 `codex` 相同。執行 `grok`，或在 _Setup > Defaults > Agent_ 底下選取它。跳過 x.ai 上的 `curl | bash` 安裝程式。那種方式會把第二份副本放進 `~/.grok/bin`，將它排到 `PATH` 的最前面，並覆寫 Omarchy 的 wrapper。

`dsh` 會在 `127.0.0.1:3080` 開啟它的瀏覽器 UI，並以啟動目錄作為預設工作區。它的瀏覽器 UI 不接受起始提示，因此 `omarchy agent prompt` 會將提示放在你的剪貼簿中，讓你貼上來開啟它。Omarchy 會使用 DeepSeek 的不需核准權限預設集來啟動它。當你使用它官方的模型 API 時，DeepSeek Harness 會將工作階段記錄上傳給 DeepSeek；在它的瀏覽器 UI 中的 _Settings > General > Upload Session Log_ 底下關閉該選項。你傳送的意見回饋也會隨工作階段一同上傳，除非你使用 `DSH_TELEMETRY_MODE=DISABLED` 來啟動它。

### 預設 agent

使用 `omarchy default agent <name>`，或在 Omarchy Menu（`Super + Space`）中的 _Setup > Defaults > Agent_ 底下，選取你的預設 agent。如果該 agent 還沒安裝，選取它時會先進行安裝。全新的 Omarchy 會用一則一次性通知邀請你做出這個選擇。

選擇 Claude 時，也會嘗試為 Chromium、Chrome、Brave、Brave Origin 和 Edge 設定它的瀏覽器擴充功能。擴充功能設定適用於所有使用者，而且可能會要求你的系統密碼；取消或擴充功能安裝失敗，仍會選取並啟動 Claude。請重新啟動你的瀏覽器，如有提示請啟用擴充功能，並登入 Claude 以完成連線。在 Claude 中執行 `/chrome` 來檢查連線。Firefox 和 Zen 不支援這個擴充功能。如果在這套設定加入之前 Claude 就已經是你的預設 agent，請再次選取它來安裝擴充功能。

做出選擇之後，`Super + Shift + Ctrl + A` 會在專用終端機視窗中啟動預設 agent（或者如果你還沒選取，就會開啟選取器）。你也可以使用 `omarchy agent prompt "Review this project"`，直接讓它進入一項任務。Freebuff 和 DeepSeek Harness 不接受起始提示，因此它們會改將提示放在你的剪貼簿中，讓你貼上。透過這種方式啟動的 agents，會以各自不用停下來詢問的模式無人值守地執行，因此請做好它們真的會動手做事的準備！MiniMax Code 的互動式工作階段沒有這種模式，因此它會照常要求權限。而且由於 agents 拒絕記住對你家目錄的信任，從 `$HOME` 啟動時會改從 `~/Work` 開始。

也有終端機快捷方式：`a` 會在目前的終端機內行內執行預設 agent，而 `c`、`cx` 和 `cy` 則會直接啟動 OpenCode、Claude Code 和 Codex（同樣是在它們的自動核准模式下）。主題變更也會同步給這些 agents：當你切換 Omarchy 主題時，Claude Code、Pi、OpenCode 和 Hermes（一旦 Omarchy 已安裝它）都會跟著變更。

### Agents 面板

頂部欄上有一個 agents 圖示。在你設定 agent 之前，它的面板會引導你登入 Claude、Codex 或 Grok，而第一個就會成為你的預設 agent。在那之後，面板會將每一個訂閱放在同一頁上：每個 agent 和帳號連同它的方案、每個 5 小時工作階段與每週限制的用量計量表以及距離重置的時間（將滑鼠懸停可查看確切百分比），或是剩餘的預付餘額，頂端有一行會輪流顯示你使用全部 agents 的整體用量，例如本週的 token 數量以及你最常使用的模型。在 _Make something_ 底下，它提供了新主題、plugin 或 app 的入門提示，可把任務交給你的預設 agent。Apps 就如同 Omarchy 自己的 Hype、Monologue 和 Omacut 一樣，使用 C++ 和 Qt Quick 建構而成，遵循 omarchy-app agent skill，而且它們所需的編譯器和 Qt 組件都已經安裝好了。Claude Code、Codex、Grok、Kimi、Cursor 及其 Grok Bot 額度、GitHub Copilot、Muse、Antigravity、Kimchi 和 Devin 開箱就能涵蓋，連同它們的限制，而 Hermes、Mistral Vibe 和 Qwen Code 則會在你使用過它們之後顯示它們的工作階段和 token。你透過 pi、omp 或 opencode 使用的提供者方案與金鑰也會顯示：OpenCode Zen 和 Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan 與 Synthetic，連同它們的限制；Fireworks、OpenRouter 和 DeepSeek，連同它們的預付餘額；以及你在自己硬體上執行的模型，位於 Local models 底下。每個 agent 只會計算一次，以向你收費的人來計，不論你透過多少個 harness 來驅動它。

以滑鼠左鍵按一下欄上的圖示開啟面板，右鍵則會啟動你的預設 agent。其背後的使用記錄會每 15 分鐘由 `omarchy agent usage-update` 重新產生，面板甚至還能透過已同步的資料夾，將你其他機器的用量合併進來。完整設定請參閱 `$OMARCHY_PATH/shell/plugins/agents/` 底下的 README。

### 多個訂閱

如果你付費購買了不止一個 Claude、Codex 或 Grok 方案——例如一個個人 Max 和一個工作的方案——Omarchy 可以讓它們全部保持登入狀態，並在它們之間切換。透過 agents 面板中的 + 新增一個訂閱，它會直接在那裡引導你完成，或使用 `omarchy agent account add claude Work`（或 `codex`，或 `grok`）。如果 CLI 缺失，它會安裝它。某個提供者的第一個帳號會透過你一般的瀏覽器登入，就在 CLI 一直查看的位置。那之後的每一個，都會透過一個私密視窗登入，因此你瀏覽器已經登入的那個帳號就不會被誤選；在那裡以你正在新增的那個帳號登入，並且要先關閉任何你已經開啟的私密視窗。切勿為了做這件事而登出 CLI：登出會撤銷已儲存的登入資訊，那個帳號就必須重新新增。

若要透過 SSH 將你的訂閱登入資訊複製到另一台 Omarchy 機器，請執行 `omarchy agent account copy user@laptop`。當目的地尚未安裝接收端時，傳送端會提供一個暫時的接收端，因此較舊的 Omarchy 機器無需更新就能接收帳號。已安裝的接收端會較優先。這會複製全部的 Claude、Codex 和 Grok 訂閱；如要選取它們，請加上提供者名稱，如 `omarchy agent account copy laptop claude` 中所示。帳號名稱和指令 ID 會與來源保持一致，包括那些目的地已經存在的帳號。若不相關的目的地帳號名稱有衝突，就會給予數字後綴，而設定、skills、plugins 以及對話記錄則會保留在本機。

目的地既有的憑證會予以保留。已經在那裡登入的來源帳號，會同步它的名稱而不取代它的憑證；其他的帳號則會加入在旁邊。若要取代符合帳號的已儲存憑證，在目的地結束該帳號的工作階段之後，使用 `omarchy agent account copy --replace laptop claude`。一個全新的目的地還會取得來源使用中的帳號以及切換偏好；已經建立的目的地則會保留它自己的。

憑證透過 SSH 傳遞並儲存在目的地上的私密檔案中，因此只能複製到你信任的機器。這是一次性的複製，不是持續的同步。Codex 的刷新 token 可能會由另一台機器輪換，而使複製過去的登入需要重新整理；要在多台機器上同時使用，個別分開登入仍是最可靠的選擇。請參閱 [Codex 的帳號驗證指南](https://developers.openai.com/codex/auth/ci-cd-auth)。

每個提供者一次只有一個帳號是使用中的，而且每個新工作階段都會以該帳號開始：`cx`、`cy`、一個普通的 `claude`、`codex` 或 `grok`、透過 `omarchy agent` 啟動的任何東西，以及在 `PATH` 上找到 CLI 的 script 或編輯器。使用 `omarchy agent account use work` 進行切換（並使用 `omarchy agent account use main` 切換回來），或者在面板中按下某個帳號的編號然後按 `Enter`（或按一下它的 Use 按鈕）。已經在執行的工作階段，會繼續使用它們開始時的帳號。對話記錄、設定、skills 和 plugins 會在各帳號間共享，因此在同一個資料夾中的 `claude --continue` 就會在新帳號上從你離開的地方接續下去。

擁有多個帳號時，面板會並排顯示每個帳號的限制，並標示使用中的那一個。預設情況下，當使用中的帳號超過某項限制的 95% 時，Omarchy 會通知你，按一下該通知就會切換到餘裕最多的帳號。若要改為自動切換，請將滑鼠懸停在面板中某個帳號的行上，然後按下出現在 Use 旁邊的 Autoswitch（或按下 `m`），或者執行 `omarchy agent account mode auto`；在開啟時，Autoswitch 會取代 Use 的位置，再按一次它就會回到通知模式。若要變更門檻，請加上數字，如 `omarchy agent account mode auto 90` 所示。如果每個帳號都超過門檻了，你只會收到一次通知，並且會一併告知是哪個帳號最先釋出额度。當使用中的帳號距離它的門檻在 15 個百分點以內時（預設情況下是 80%），就會每三分鐘檢查一次它的限制，而不是每 15 分鐘。

`omarchy agent account list` 會顯示每個帳號及其最新限制，`omarchy agent account remove work` 會忘記一個帳號，而 `omarchy agent account rename primary Hey` 則會為一個帳號重新命名（或者按一下面板中的帳號名稱）。這些指令作用於你的預設 agent 的帳號；如要到達其他提供者，請先命名再使用，如 `omarchy agent account use codex side` 中所示。你已經在 `~/.claude` 或 `~/.codex` 中持有的登入，就是 _Main_ 帳號，而且會保留原處不動。一個閒置超過約八小時的帳號可能顯示 _Sign-in required_；按一下它就能直接在面板中再次登入那個帳號，或是在它裡面啟動一個工作階段，這會自動更新登入狀態。在新增帳號時你所擁有的 MCP 伺服器會隨之而來，但之後使用 `claude mcp add` 新增的伺服器，只會傳到你新增它們的那個帳號。Claude Desktop 以及以 CLI 執行檔絕對路徑設定的工具，不會跟隨切換。明確指定 `CLAUDE_CONFIG_DIR`、`CODEX_HOME` 或 `GROK_HOME`，其優先權高於選取的帳號。

### 當機診斷

Omarchy 會透過 systemd-coredump 監視處理程序當機。當某個東西發生 segmentation fault 時，你會收到「Process crashed」通知——按一下它，當機資訊就會連同 Omarchy 的 diagnose-crash skill 一起交給你的預設 agent，它會引導 agent 根據 core dump 釐清事實，並判斷這次當機是否值得向 upstream 回報。你還可以使用 `omarchy agent crash <pid>`，針對 `coredumpctl list` 的任何一個 PID 手動執行它。

這項監看功能預設開啟。在 _Trigger > Toggle > Crash Capture_ 底下（或使用 `omarchy toggle crash-capture`）關閉它，通知就會停止；`omarchy agent crash <pid>` 仍然可以手動使用。

當機還可以一次針對一個程式靜音，這正是診斷最後會提供給你的選項。`omarchy crash mute hyprland` 只會停止該程式的通知，`omarchy crash mute hyprland off` 會將它們恢復，而單獨的 `omarchy crash mute` 則會列出你已經靜音的項目。它接受執行檔的路徑，如同接受名稱一般輕鬆，因此 `omarchy crash mute /usr/bin/hyprland` 有相同的效果。對於含有空格的名稱要加上引號，如 `omarchy crash mute 'Some App'` 所示。其他所有東西仍然會發出通知，而且被靜音的程式仍會當機——這只是隱藏提醒而已，它並不能修復任何問題。

### 桌面應用程式

_Install > AI_ 選單中也提供了幾個圖形化 AI app：ChatGPT 桌面 app、Claude 桌面 app（Anthropic 的 Linux beta 版，具備 Chat、Cowork 與 Claude Code 分頁）、用來與 xAI 模型聊天的 Grok Bot、Hermes Desktop、OpenClaw、Perplexity 桌面 app，以及 T3 Code。Grok Bot 是桌面聊天 app。編程 agent 則是 `grok` 指令。

Hermes Desktop 是你需要瞭解的一個，因為一台機器只有一個 Hermes，而它屬於這個 app：Hermes 始終只能透過該 app 安裝，而預設 agent 所執行的 `hermes` 指令就是這個 app 的。將 Hermes 選為預設 agent，安裝的內容和 _Install > AI_ 項目相同：那個套件，以及由 Hermes 自己的安裝程式在 `~/.hermes` 底下建立的 Hermes runtime，第一次需時數分鐘。這個 runtime 就是終端機 `hermes` 指令、預設 agent 與該 app 全都使用的一套 Hermes，而且它會使用 `hermes update` 自行更新，而非等待 Omarchy 發行。它安裝時還會把 Omarchy 主題以名為 `omarchy` 的 skin 交給 Hermes，每個 Hermes 介面都會隨你切換主題而跟隨；如果你不希望如此，請在 Hermes 的 Appearance 設定底下或使用 `/skin` 選另一個，Omarchy 就不會再動這個選擇。在 _Remove > AI_ 底下移除該 app 會先關閉 Hermes，包括 gateway，並且將執行環境一併移除，而且會保留你的聊天、記憶，以及 Hermes 為它自己所撰寫的 skills，除非你另行指示：它會詢問那些資料以及你的連線設定是否也該一併移除，預設為否。

OpenClaw 的桌面體驗是其 Control UI，會以一個 web app 的方式開啟，並以自己本機的 gateway 為後盾。OpenClaw 存在 `~/.openclaw` 中，而且會自行更新：使用 Control UI 的 "Update Gateway" 按鈕，或執行 `openclaw update`，gateway 就會以新版重新啟動。Omarchy 只會選擇一個全新安裝從哪一個版本開始。在 _Remove > AI_ 底下移除 OpenClaw 會將 gateway 服務和該 app 一併移除，然後會詢問 `~/.openclaw` 是否也該一併刪除，因為那裡收納著你的聊天與憑證，以及 OpenClaw 本身和它下載的 plugin runtime；預設會保留它，而且再次安裝 OpenClaw 就能再次取用。

T3 Code 是從 `~/.local/share/t3code` 中的官方 AppImage 發行版本運行，而非從套件運行，因此它會自行更新。安裝時會詢問你要從 Stable 或 Nightly 頻道開始；之後可以在 T3 Code 的設定中切換。你的 discussions 和設定存在 `~/.t3` 中，而在 _Remove > AI_ 底下移除 T3 Code 將會把它們一併刪除。

### 本機模型

讓一個開放模型在你自己的機器上執行，供你的編程 agents 使用。你的提示與程式碼會留在機器上；傳送給模型的任何東西都不會離開它。以下列指令開始：

```bash
omarchy agent local use best
```

或是，在頂部欄的 agents 面板中，先選擇 + 然後是 Local AI，它會在此機器能容納某個模型時出現。第一次這樣做時，它會安裝 Podman（負責運行模型），而在 NVIDIA 機器上，還會安裝 NVIDIA 的容器工具包，這能讓模型使用 GPU。然後 Omarchy 會為這台機器挑選建議的模型、下載它並啟動它。可以預期下載的資料量會達到數十 GB，而且模型執行時機器的記憶體大部分都會被使用：Flash Next 在其完整的 256K 上下文下，大約會使用 100 GiB。若其他模型占用了它所需的記憶體，它就會被設定為已停止狀態，等你停下其中一個就能啟動。模型會在登出時停止；當你需要將記憶體供其他用途時，請自行將它停下。

`omarchy agent local list` 會顯示各個選項，並說明為何有些不合適。若要設定另一個，請執行 `omarchy agent local use <recipe>`。目前 `qwen3.8-flash-next-gufo` 與 `qwen3.8-27b-gufo` 可用於 128 GB Strix Halo 機器；27B 模型約占用 40 GiB，因此它會留下空間給其他工作。新的 recipe 與建議會透過套件隨著 `omarchy update` 一同到達。

你設定的每個模型在 agents 面板中都會有自己的一行，緊鄰你的訂閱：play 開始它，pause 停下它並釋出它的記憶體，而終端機按鈕則會在它上面開啟你的 agent。當記憶體足以承載時，多個模型可同時運行；如果有一個放不下，Omarchy 會告訴你應該停止哪個正在運行的模型。拖曳各行可以重新排序，而按下所選行上的 Delete 則會刪除該模型及其下載檔案。

在指令列，`omarchy agent local start <recipe>` 以及 `omarchy agent local stop <recipe>` 能做相同的事情，`omarchy agent local status` 會顯示所有模型，而 `omarchy agent --local` 則會在你最近啟動的模型上開啟你的預設 agent（若你的預設 agent 無法使用本機模型，則為 pi）。任何相容於 OpenAI 的用戶端也都可以連線：`status` 會顯示每個模型的位址（第一個是 `http://127.0.0.1:11435/v1`），recipe 名稱即是模型，而金鑰則在 `~/.config/omarchy/agent-local/key` 中。

`omarchy agent local remove <recipe>` 會刪除模型以及沒有其他模型使用的下載檔案。

第三方 runtime 會標示其發佈者。Omarchy 運行每個模型時都不使用網路存取。

### 本機 LLM

Omarchy 推薦兩種運行本機 LLM 模型的方式：LM Studio 與 Ollama。LM Studio 提供 GUI 介面，以尋找開放權重模型、安裝它們並運行。對於快速上手來說，它是一個很棒的方式。Ollama 則提供 CLI 來以類似的方式完成。若你是本地模型新手，我建議從 LM Studio 開始。你可以在 Omarchy Menu 中的 _Install > AI_ 下安裝其中一個。

### Omarchy Skill

Agent skills 能幫助 AI 以特定方式使用特定工具，而 Omarchy 附帶了一個預設 skill，用以量身打造系統。就如同調整你的 Hyprland  config、調整 bar，或者甚至從頭打造一個全新的主題。它已經以符號連結的方式連進 Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` 以及每個 `~/.hermes/profiles/*/skills`）的 skill 目錄，還有通用的 `~/.agents/skills` 位置，因此大多數 harness 都會自動取用。

但是你應該將這個 skill 視為實驗性質。不同的模型運用它會有不同的效果。先在計畫模式下運行是最佳作法，這樣你就能大致知道 agent 想要改變什麼。然後若 agent 把一切搞得一團亂，要準備好還原變更，甚至執行 `omarchy reinstall configs`。
