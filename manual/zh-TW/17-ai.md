# AI

Omarchy 內含下列程式設計代理的啟動器，但不會幫你選預設值。執行指令即可在首次使用時安裝其 CLI，然後在提示時完成驗證。Hermes 和 OpenClaw 是例外：它們不會透過 mise 安裝任何東西，選擇其中任何一個都會設定其專屬的自我更新副本，如下方的 _桌面應用程式_ 所說明。

### 安裝與更新代理

除了 Hermes 和 OpenClaw 之外，這些代理使用 mise 的延遲安裝：首次啟動會安裝 CLI，之後的啟動則重複使用它。mise 也會在已安裝的代理啟動前，或在 shell 提示字元處於背景，最多每四小時檢查一次是否有新版本。如果該更新失敗或你處於離線狀態，就會執行已安裝的版本。`omarchy update` 會連同 Omarchy 的其他部分一起更新已安裝的代理，而 `mup` 則只更新由 mise 管理的工具。

代理自己的更新程式，例如 `claude update`、`codex update`，或應用程式中的更新按鈕，不會更新由 mise 管理的安裝。`codex update` 會失敗，而 `claude update` 可能回報成功，卻安裝了一個 mise 未追蹤的獨立副本。如果你寧願使用代理原生的安裝程式與更新程式，請將它加入 `disable_tools`；請參閱 [預先安裝的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

若要在需要之前安裝所有已設定的延遲工具，請執行 `mise install --include-lazy`。這包括 Omarchy 的其他預設 CLI 工具以及代理。關於安裝單一工具或使用你自己的安裝，請參閱 [預先安裝的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

`grok` 透過 mise 的第一方 `grok` 套件安裝，方式與 `claude` 和 `codex` 相同。執行 `grok`，或在 _Agent > Harness_ 下選擇它。不要使用 x.ai 上的 `curl | bash` 安裝程式。那個路徑會在 `~/.grok/bin` 放第二個副本、將它加到 `PATH` 最前面，並覆寫 Omarchy 的包裝程式。

`dsh` 會在 `127.0.0.1:3080` 開啟其瀏覽器 UI，並以啟動目錄作為預設工作區。它的瀏覽器 UI 不接受起始提示，所以 `omarchy agent prompt` 會開啟它，並將提示放在你的剪貼簿中供你貼上。Omarchy 以 DeepSeek 的無需核准權限預設集啟動它。當你使用 DeepSeek 官方模型 API 時，DeepSeek Harness 會將工作階段記錄上傳到 DeepSeek；在其瀏覽器 UI 的 _Settings > General > Upload Session Log_ 下將它關閉。你傳送給它的意見回饋也會連同工作階段一起上傳，除非你以 `DSH_TELEMETRY_MODE=DISABLED` 啟動它。

### 預設代理

使用 `omarchy default agent <name>` 或在 Omarchy Menu (`Super + Space`) 的 _Agent > Harness_ 下選擇你的預設代理。如果代理尚未安裝，選擇它會先安裝它，而且它也會在應用程式啟動器中 Agent 旁邊獲得自己的啟動器。全新的 Omarchy 會透過一次性的通知邀請你做這個選擇。

選擇 Claude 也會嘗試為 Chromium、Chrome、Brave、Brave Origin 和 Edge 設定其瀏覽器擴充功能。擴充功能設定適用於所有使用者，而且可能要求你輸入系統密碼；取消或擴充功能安裝失敗，仍然會選取並啟動 Claude。重新啟動你的瀏覽器，在提示時啟用擴充功能，並登入 Claude 以完成連接。在 Claude 中執行 `/chrome` 檢查連接。Firefox 和 Zen 不支援這個擴充功能。如果在加入這個設定之前 Claude 就已經是你的預設，請再次選取它以安裝擴充功能。

一旦你選好了，`Super + Shift + Ctrl + A` 會在專用的終端機視窗中啟動預設代理（或者如果你還沒選，就會叫出選擇器）。你也可以用 `omarchy agent prompt "Review this project"` 直接讓它進入一項任務。Freebuff 和 DeepSeek Harness 不接受起始提示，所以它們會開啟並將提示放在你的剪貼簿中供你貼上。以這種方式啟動的代理會在各自的不要停下來詢問模式下無人看管地執行，所以要做好它們真的會動手做事的準備！MiniMax Code 的互動式工作階段沒有這種模式，所以它會照常要求權限。而且由於代理拒絕記住對你家目錄的信任，從 `$HOME` 啟動的會改在 `~/Work` 中開始。

也有終端機快捷方式：`a` 會在目前的終端機中內嵌執行預設代理，而 `c`、`cx` 和 `cy` 則直接啟動 OpenCode、Claude Code 和 Codex（同樣以它們的自動核准模式）。主題變更也會同步到代理：當你切換 Omarchy 主題時，Claude Code、Pi、OpenCode 和 Hermes（一旦 Omarchy 已安裝它）都會跟著變。

### 你的代理指示

每個代理的個人規則放在 `~/.agents/AGENTS.md`，就在 `~/.agents/skills` 中共享技能的旁邊。在 _Agent > Instructions_ 下開啟它，它也會將它連結到每個保有自己全域檔案的 harness 中：`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`~/.pi/agent/AGENTS.md`、`~/.config/opencode/AGENTS.md`、Copilot 的 `~/.copilot/copilot-instructions.md` 等等。Crush 和 Amp 讀取 `~/.config/AGENTS.md` 連結，而 omp、Kimi 和 DeepSeek Harness 則直接讀取 `~/.agents/AGENTS.md`。挑選預設代理也會連結它。如果你已經有指示檔案，而且還沒有共享的，它會成為共享的那個；否則它會以 `.bak` 的形式保留在連結旁邊。安裝另一個代理後，執行 `omarchy agent instructions` 以重新連結。

### 代理面板

頂部列有一個代理圖示。在你設定代理之前，它的面板會引導你登入 Claude、Codex 或 Grok，而第一個會成為你的預設代理。在那之後，面板會把每個訂閱放在同一頁上：每個代理和帳戶及其方案、每個 5 小時工作階段和每週限額的計量表以及距離重置的時間（將滑鼠懸停以查看確切百分比），或者剩餘的預付餘額，都在會輪替顯示你所有使用情況的一行之下，例如本週的 token 和你最常使用的模型。在 _Make something cool_ 下，它提供用於新主題、外掛、應用程式或遊戲的入門提示，並將任務交給你的預設代理。應用程式是以 Omarchy 自己的 Hype、Monologue 和 Omacut 相同的方式打造，用 C++ 和 Qt Quick，遵循 omarchy-make-app 代理技能，而且它們需要的編譯器和 Qt 元件都會安裝好。遊戲是在 `~/Games/vibes` 中的單一 three.js 頁面，遵循 omarchy-make-game 代理技能，而且全部從目前主題中的一個 Game Vibes 啟動器開啟；它們從網路載入 three.js，所以啟動時需要連線。Claude Code、Codex、Grok、Kimi、Cursor 及其 Grok Bot 額度、GitHub Copilot、Muse、Antigravity 和 Devin 開箱就能涵蓋及其限額，Kimchi 則有其方案、預付點數和支出預算，而 Hermes、Mistral Vibe 和 Qwen Code 一旦你使用它們就會顯示它們的工作階段和 token。你透過 pi、omp 或 opencode 使用的供應商方案和金鑰也會顯示：OpenCode Zen 和 Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan，以及 Synthetic 及其限額；OpenRouter 和 DeepSeek 及其預付餘額；Fireworks 及其過去 30 天的支出。在你自己的硬體上執行的模型的 token 也會計入總計；模型本身有它們自己的面板，在 [本機模型](#local-models) 下有說明。每個代理只會計一次，歸在向你收費的那一方之下，無論你透過多少 harness 來使用它。

左鍵按一下列圖示或按下 `Super + Ctrl + X` 開啟面板，右鍵按一下啟動你的預設代理，中鍵按一下重新整理。它背後的使用記錄每 15 分鐘由 `omarchy agent usage update` 重新產生，而且面板甚至可以透過同步資料夾合併來自你其他機器的使用情況。完整的設定請參閱 `$OMARCHY_PATH/shell/plugins/agents/` 下的 README。

### 多個訂閱

如果你付費使用不只一個 Claude、Codex 或 Grok 方案——比如說個人 Max 和工作用的——Omarchy 可以讓它們全部保持登入，並在它們之間切換。用代理面板中的 + 新增訂閱，它會直接在那裡引導你完成，或者用 `omarchy agent account add claude Work`（或 `codex`，或 `grok`）。如果遺失，它會安裝 CLI。供應商的第一個帳戶會透過你一般的瀏覽器登入，就在 CLI 一直查看的地方。之後的每個帳戶都會透過私人視窗登入，所以你瀏覽器已經登入的帳戶不會被誤選；在那裡以你要新增的帳戶登入，並先關閉你已經開啟的任何私人視窗。絕對不要為了做這件事而登出 CLI：登出會撤銷已儲存的登入，而該帳戶就必須重新新增。

若要透過 SSH 將你的訂閱登入複製到另一台 Omarchy 機器，請執行 `omarchy agent account copy user@laptop`。當目的地沒有安裝接收程式時，傳送方會提供一個暫時接收程式，所以較舊的 Omarchy 機器不用更新也能接收帳戶。已安裝的接收程式優先。這會複製所有 Claude、Codex 和 Grok 訂閱；加入供應商名稱來選取它們，如 `omarchy agent account copy laptop claude` 中所示。帳戶名稱和指令 ID 與來源相符，包括目的地已經存在的帳戶。無關的目的地帳戶如果名稱衝突，會獲得數字後綴，而且設定、技能、外掛和對話記錄都會留在每台機器本地。

會保留目的地現有的憑證。已經在那裡登入的來源帳戶會同步其名稱，但不會取代其憑證；其他帳戶則會加在它的旁邊。若要取代符合帳戶的已儲存憑證，請在目的地結束該帳戶的工作階段後，使用 `omarchy agent account copy --replace laptop claude`。全新的目的地也會獲得來源的啟用中帳戶和切換偏好設定；已經建立的目的地則保留自己的。

憑證會透過 SSH 傳輸，並儲存在目的地上的私人檔案中，所以只複製到你信任的機器。這是一次性複製，不是持續同步。Codex 更新 token 可能會被另一台機器輪替，使複製的登入需要更新；為了在多台機器上同時使用，分開登入仍然是最可靠的選擇。請參閱 [Codex 的帳戶驗證指南](https://developers.openai.com/codex/auth/ci-cd-auth)。

每個供應商有一個啟用中的帳戶，而且每個新工作階段一開始都是它：`cx`、`cy`、普通的 `claude`、`codex` 或 `grok`、透過 `omarchy agent` 啟動的任何東西，以及在 `PATH` 上找到 CLI 的腳本或編輯器。用 `omarchy agent account use work` 切換（並用 `omarchy agent account use main` 切換回來），或者在面板中按下帳戶的數字再按 `Enter`（或按一下它的 Use 按鈕）。執行中的 Claude 工作階段也會切換，從它們的下一條訊息開始：每個 Claude 工作階段都在 `~/.claude` 中執行，那裡永遠保有啟用中帳戶的登入。由較舊的 Omarchy 在帳戶自己的資料夾中啟動的 Claude 工作階段，會保有該登入直到它結束，所以切換會命名那些工作階段，並在它們消失後自行完成。執行中的 Codex 和 Grok 工作階段會留在它們開始時的帳戶上。對話記錄、設定、技能和外掛在帳戶之間共享，所以在同一個資料夾中的 `claude --continue` 會在新帳戶上接續你之前離開的地方。

有不只一個帳戶時，面板會並排顯示每個帳戶的限額，並標示啟用中的那個。當啟用中帳戶超過限額的 95% 時，Omarchy 會通知你，按一下通知就會切換到餘裕最多的帳戶。它絕對不會自行切換。用 `omarchy agent account threshold 90` 更改門檻。如果每個帳戶都超過門檻，你只會聽到一次，同時會知道哪個帳戶最快釋出。當啟用中帳戶距離門檻在 15 個百分點以內（預設為 80%）時，其限額會每三分鐘檢查一次，而不是每 15 分鐘。

`omarchy agent account list` 會顯示每個帳戶及其最新限額，`omarchy agent account remove work` 會忘記一個，`omarchy agent account rename primary Hey` 會重新命名一個（或在面板中按一下帳戶名稱）。這些指令作用於你預設代理的帳戶；若要到達另一個供應商，請先命名它，如 `omarchy agent account use codex side` 所示。你已經在 `~/.claude` 或 `~/.codex` 中有的登入是 _Main_ 帳戶。Codex 的會留在原地；Claude 的則在另一個帳戶啟用時等在自己的資料夾中。閒置超過約八小時的帳戶可能會顯示 _Sign-in required_；按一下它直接在面板中重新登入該帳戶，或切換到它並開始一個工作階段，它就會自行更新登入。你用 `claude mcp add` 新增的 MCP 伺服器會到達每個 Claude 帳戶，因為它們都在 `~/.claude` 中執行；對於 Codex 和 Grok，你在新增帳戶時已有的伺服器會跟著到它那裡，但之後的只會到達你新增它們的那個帳戶。Claude Desktop 保留自己的登入，而且以絕對路徑配置到 CLI 二進位檔的 Codex 或 Grok 工具不會跟著切換。明確的 `CLAUDE_CONFIG_DIR`、`CODEX_HOME` 或 `GROK_HOME` 會優先於選定的帳戶。

### 崩潰診斷

Omarchy 會看著 systemd-coredump 是否有處理程序崩潰。一旦你挑選了預設代理，你任何傾印核心的程式都會帶來一個「Process crashed」通知——按一下它，崩潰就會連同 Omarchy 的 omarchy-diagnose-crash 技能一起交給你的預設代理，該技能會引導代理從核心傾印中建立事實，並決定崩潰是否值得向上游回報。你也可以用 `omarchy agent crash <pid>` 針對 `coredumpctl list` 中的任何 PID 手動執行它。

監看預設開啟。在 _Trigger > Toggle > Crash Capture Off_ 下將它關閉（或用 `omarchy toggle crash-capture`），通知就會停止；`omarchy agent crash <pid>` 仍然可以手動使用。

崩潰也可以一次靜音一個程式，這正是診斷最後會提供給你的。`omarchy crash mute hyprland` 只停止該程式的通知，`omarchy crash mute hyprland off` 會把它們帶回來，而單獨的 `omarchy crash mute` 會列出你已靜音的。它樂於接受二進位檔的路徑，也接受其名稱，所以 `omarchy crash mute /usr/bin/hyprland` 做同樣的事。將有空格的名稱引號起來，如 `omarchy crash mute 'Some App'`。其他一切仍會通知，而且被靜音的程式仍然會崩潰——這只是隱藏提醒，它沒有修好任何東西。

### 桌面應用程式

_Install > AI_ 選單也帶有幾個圖形化 AI 應用程式：Amp Desktop、Antigravity Desktop、ChatGPT 桌面應用程式、Claude 桌面應用程式（Anthropic 的 Linux beta，帶有 Chat、Cowork 和 Claude Code 分頁）、用於與 xAI 模型聊天的 Grok Bot、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexity 桌面應用程式，以及 T3 Code。Grok Bot 是桌面聊天應用程式。程式設計代理則是 `grok` 指令。

Hermes Desktop 是你需要知道的那個，因為一台機器有一個 Hermes，而且它屬於這個應用程式：Hermes 只能透過這個應用程式安裝，而且預設代理執行的 `hermes` 指令就是這個應用程式的。選擇 Hermes 作為預設代理會安裝與 _Install > AI_ 項目相同的東西：套件，以及一個由 Hermes 自己的安裝程式設定在 `~/.hermes` 下的 Hermes 執行階段，第一次需要幾分鐘。該執行階段就是終端機 `hermes` 指令、預設代理和應用程式全部使用的那一個 Hermes，而且它用 `hermes update` 自我更新，而不是等待 Omarchy 發行版。安裝它也會將 Omarchy 主題作為一個名為 `omarchy` 的外觀交給 Hermes，每個 Hermes 介面都會在你切換主題時跟著它；如果你不希望如此，在 Hermes 的 Appearance 設定下或用 `/skin` 挑選另一個，而 Omarchy 會任由這個選擇。從 _Remove > AI_ 下移除這個應用程式會先關閉 Hermes（包括閘道）、連同帶走該執行階段，並保留你的聊天、記憶以及 Hermes 為自己寫的技能，除非你告訴它不要：它會詢問，預設為否，這些資料和你的連接設定是否也要一併移除。

OpenClaw 的桌面體驗是其 Control UI，它以網頁應用程式的形式開啟，後端是其自己的本機閘道。OpenClaw 存在於 `~/.openclaw` 中並自我更新：使用 Control UI 的「Update Gateway」按鈕或執行 `openclaw update`，閘道就會在新版本上重新啟動。Omarchy 只選擇全新安裝一開始的版本。OpenClaw 也可以是你的預設代理：在 _Agent > Harness_ 下選擇它會在 `~/.openclaw` 中設定那同一個副本，而且代理會開啟附加到其閘道的 OpenClaw 終端機 UI。從 _Remove > AI_ 下移除 OpenClaw 會帶走閘道服務和應用程式，然後詢問 `~/.openclaw` 是否也要一併移除，因為那裡放著你的聊天和憑證，以及 OpenClaw 本身和它下載的外掛執行階段；預設會保留它，而再次安裝 OpenClaw 會把它撿回來。

Herdr Desktop 是 [Herdr](https://herdr.dev) 桌面應用程式：當你關閉視窗時，終端機和程式設計代理的 spaces、tabs 和 panes 會在其核心中持續執行。它來自 Herdr 自己的安裝程式而不是套件，所以它存放在 `~/.local/share/herdr-app`，在你還沒有時會在 `~/.local/bin/herdr-core` 帶來它的核心，並自我更新兩者。它與 Omarchy 在 `Super + Ctrl + Return` 上提供的 `herdr` 指令並列，而不是取代它，並獲得該指令的直接按鍵：`Alt + Return` 和 `Alt + Shift + Return` 會向下或向右分割窗格，`Alt + Escape` 關閉它，`Ctrl + Alt + Arrow` 在窗格之間移動，`Alt + 1..9` 和 `Alt + Left/Right` 挑選分頁，而 `Alt + Up/Down` 在 spaces 之間移動。`Ctrl + 1..9` 挑選一個 space，而 `Alt + Shift + Up/Down` 會在代理之間逐個切換。`Ctrl + Space` 前綴按鍵仍然只用於終端機，因為應用程式無法為一個序列按住一個普通的 Ctrl 鍵。Omarchy 將這些寫入 `~/.config/herdr-app/keys.json`，而 `omarchy-refresh-herdr-app` 會把它們放回去。安裝它會挑選 Herdr 的 Omarchy 主題，從那時起就會跟隨你的 Omarchy 主題。Herdr 為淺色模式保留一個主題，為深色模式保留一個，所以在深色和淺色 Omarchy 主題之間切換後，請在 Herdr 的主題選擇器中再挑選一次 Omarchy 以用於另一個模式。

T3 Code 由其官方 AppImage 發行版在 `~/.local/share/t3code` 下執行，而不是由套件，所以它會自我更新。安裝它會詢問要從 Stable 還是 Nightly 通道開始；之後在 T3 Code 的設定中切換。你的討論串和設定存放在 `~/.t3`，在 _Remove > AI_ 下移除 T3 Code 會連同帶走它們。

### 本機模型

在你自己的機器上為你的程式設計代理執行開放模型。你的提示和程式碼留在機器上；送給模型的東西不會離開它。從以下開始：

```bash
omarchy models use best text
```

這會為這台機器設定最佳的文字模型，也就是你的代理使用的那種。影像、影片和音樂模型都有自己最佳的：`omarchy models use best image`、`video` 或 `music`。執行 `omarchy models use best` 來查看每一種在這台機器上的選擇。

或者從頂部列中 agents 圖示旁邊的閃光圖示開啟本機模型面板，或以 Super + Ctrl + Alt + X，並選擇 +。當有模型適合這台機器時，這個圖示就會顯示。執行模型的 Podman 隨 Omarchy 附帶，NVIDIA 機器上的 NVIDIA 容器工具包也一樣，它讓模型可以使用 GPU；如果缺少任何一個，第一次設定會安裝它。然後 Omarchy 會為這台機器挑選推薦的模型，下載它並啟動它。預期下載會是數十 GB，而且模型執行時會使用機器的大部分記憶體：Flash Next 在完整的 256K 上下文下使用約 100 GiB。如果其他模型佔著它需要的記憶體，它會被設定為停止狀態，一旦你停止一個就可以隨時啟動。模型會在登出時停止；當你需要記憶體做其他事時，請自己停止它。

`omarchy models list` 會顯示選項並解釋為什麼有些不適合。若要設定另一個，請執行 `omarchy models use <recipe>`。今天，`qwen3.8-flash-next-gufo` 和 `qwen3.8-27b-gufo` 適用於 128 GB Strix Halo 機器；27B 約需 40 GiB，所以它會留出空間給其他工作。在配備 Intel 的 Arc B390 的 64 GB 筆記型電腦上，`qwen3.6-35b-a3b-llamacpp` 在約 30 GiB 中執行。新的配方和推薦會透過套件隨著 `omarchy update` 抵達。

你設定的每個模型在本機模型面板中都有自己的一行：播放來啟動它，暫停來停止它並釋放其記憶體，以及終端機按鈕在它上面開啟你的代理。跨頂部，一個列會顯示機器記憶體如何分配給 Omarchy 本身（系統和你的應用程式）、每個執行中的模型，以及空閒的部分。指向一個已停止的模型，這個列會顯示它是否適合，或還差多少。幾個可以同時執行，當它們一起適合記憶體時；如果一個不適合，Omarchy 會說明要停止哪個執行中的模型。拖曳它們的 logo 來重新排列各行，並在選定的行上按下 Delete 來移除一個模型及其下載。

你設定的每個程式設計模型在應用程式啟動器中也有自己的項目，以模型名稱和其製造商的 logo，就像登入 Claude、Codex 或 Grok 會加入一個一樣。它會在該模型上開啟你的代理，如果模型還沒執行，會先啟動它：終端機會顯示它載入，並在它就緒後交給代理。移除模型也會移除其項目。

不是每個模型都是用於程式設計。影像、影片和音樂模型會改在 Fantasi 中開啟，Omarchy 的應用程式，用在這台機器上執行的模型製作圖片、影片和音樂，在那裡或從它們在本機模型面板中的那一行挑選。

模型會完全按照設定的方式持續執行，所以 Omarchy 更新絕對不會在你的代理底下重新啟動一個。當 Omarchy 有你所設定模型的較新執行階段或較新權重時，它的那一行會顯示更新按鈕：按下它，模型會在背景中重新設定，只下載有變更的部分，並在新版本上重新啟動。已停止的模型會保持停止。`omarchy models update` 會在終端機中對每個模型做同樣的事。

從命令列，`omarchy models start <recipe>` 和 `omarchy models stop <recipe>` 做同樣的事，`omarchy models status` 顯示每個模型，而 `omarchy agent --local` 會在 pi 中開啟你最後啟動的模型，無論你的預設代理是什麼。OpenCode 和 Qwen Code 也可以使用本機模型：`omarchy models harness opencode` 或 `omarchy models harness qwen` 改在那裡開啟它們，而 `omarchy models harness pi` 則返回。pi 也會在自己的模型選擇器中列出你已設定的每個模型，以及你已配對的機器上的模型，所以普通的 `pi` 也能使用它們。任何與 OpenAI 相容的客戶端也可以連接：`status` 顯示每個模型的地址（第一個是 `http://127.0.0.1:11435/v1`），配方名稱就是模型，而金鑰在 `~/.config/omarchy/agent-local/key`。

`omarchy models remove <recipe>` 刪除一個模型以及沒有其他模型使用的下載。

第三方執行階段會標示其出版商。Omarchy 執行每個模型時都沒有網路存取。

### 本機 LLM

Omarchy 推薦兩種執行本機 LLM 模型的方式：LM Studio 和 Ollama。LM Studio 提供 GUI 介面來查找開放權重模型、安裝它們並執行它們。這是輕鬆入門的好方法。Ollama 提供 CLI 以類似方式做這件事。但如果你對本機模型還不熟悉，我會從 LM Studio 開始。你可以在 Omarchy Menu 的 _Install > AI_ 下安裝任一個。

### Omarchy 技能

代理技能幫助 AI 以特定方式使用特定工具，Omarchy 附帶七個。omarchy 技能涵蓋量身訂製系統，例如微調你的 Hyprland 設定或調整列。omarchy-make-theme、omarchy-make-plugin、omarchy-make-app 和 omarchy-make-game 涵蓋製作新東西，omarchy-contribute 涵蓋回報 bug 或將修復傳送到上游，而 omarchy-diagnose-crash 則處理崩潰的核心傾印。它們被符號連結到 Claude Code (`~/.claude/skills`)、Codex (`~/.codex/skills`)、Pi (`~/.pi/agent/skills`)、Antigravity (`~/.gemini/config/skills`)、Hermes (`~/.hermes/skills` 和每個 `~/.hermes/profiles/*/skills`)，以及通用的 `~/.agents/skills` 位置的技能目錄，所以大多數 harness 會自動拾取它們。你自己的同名技能資料夾會優先。

但你應該將這些技能看作是實驗性的。不同模型會以不同程度發揮它的作用。最好先在 plan mode 中執行，這樣你對代理想改變什麼會有個概念。然後準備回滾變更，甚至呼叫 `omarchy reinstall configs`，如果代理把一切弄得一團糟的話。
