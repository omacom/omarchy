### 安裝與更新代理程式

除了 Hermes 之外，這些代理程式都使用 mise 的延遲安裝：首次啟動時安裝 CLI，之後的啟動則重複使用它。mise 也會至多每四小時檢查一次已安裝的代理程式是否有新版本，就在它啟動之前，或在 shell 提示字元處於背景檢查。如果該更新失敗或你處於離線狀態，就會執行已安裝的版本。`omarchy update` 會連同 Omarchy 的其他部分一起更新已安裝的代理程式，而 `mup` 只更新由 mise 管理的工具。

代理程式自己的更新程式，例如 `claude update`、`codex update`，或應用程式中的更新按鈕，不會更新由 mise 管理的安裝。`codex update` 會失敗，而 `claude update` 可能會回報成功，卻安裝了一份 mise 沒有追蹤的獨立副本。如果你寧願使用代理程式原生的安裝程式和更新程式，請將它加入 `disable_tools`；請參閱[預先安裝的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

若要在需要之前安裝所有已設定的延遲工具，請執行 `mise install --include-lazy`。這包括 Omarchy 的其他預設 CLI 工具以及這些代理程式。關於安裝單一工具或使用你自己的安裝，請參閱[預先安裝的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

`grok` 是透過 mise 的第一方 `grok` 套件安裝的，方式與 `claude` 和 `codex` 相同。執行 `grok`，或在 _Agent > Harness_ 之下選取它。跳過 x.ai 上的 `curl | bash` 安裝程式。那條路徑會在 `~/.grok/bin` 放一份第二副本、將它加到 `PATH` 的最前面，並覆寫 Omarchy 的包裝程式。

`dsh` 會在 `127.0.0.1:3080` 開啟它的瀏覽器 UI，並以啟動目錄作為它的預設工作區。它的瀏覽器 UI 不接受起始提示，所以 `omarchy agent prompt` 開啟它時會把提示放在你的剪貼簿中讓你貼上。Omarchy 會以 DeepSeek 的免核准權限預設集來啟動它。當你使用 DeepSeek 官方的模型 API 時，DeepSeek Harness 會將工作階段記錄上傳到 DeepSeek；你可以在它的瀏覽器 UI 中，於 _Settings > General > Upload Session Log_ 之下關閉這個功能。你傳送給它的意見回饋也會連同工作階段一起上傳，除非你以 `DSH_TELEMETRY_MODE=DISABLED` 啟動它。

### 預設代理程式

使用 `omarchy default agent <name>`，或在 Omarchy Menu（`Super + Space`）的 _Agent > Harness_ 之下，選取你的預設代理程式。如果該代理程式尚未安裝，選取它時會先安裝它。全新的 Omarchy 會以一次性的通知邀請你做出這個選擇。

選擇 Claude 時，也會嘗試為 Chromium、Chrome、Brave、Brave Origin 和 Edge 設定它的瀏覽器擴充功能。擴充功能的設定會套用到所有使用者，且可能會要求你輸入系統密碼；取消或擴充功能安裝失敗，仍然會選取並啟動 Claude。重新啟動你的瀏覽器、如果出現提示就啟用該擴充功能，並登入 Claude 以完成連接。在 Claude 中執行 `/chrome` 來檢查連線。Firefox 和 Zen 不支援這個擴充功能。如果在加入這項設定之前 Claude 就已經是你的預設值，請再次選取它來安裝擴充功能。

一旦你做出了選擇，`Super + Shift + Ctrl + A` 會在一個專用的終端機視窗中啟動預設代理程式（或者，如果你還沒有選擇，就會顯示選取器）。你也可以用 `omarchy agent prompt "Review this project"` 讓它直接進入一項任務。Freebuff 和 DeepSeek Harness 不接受起始提示，所以它們開啟時會改為把提示放在你的剪貼簿中讓你貼上。以這種方式啟動的代理程式會在各自「不中途詢問」的模式下無人監管地執行，所以請做好它們真的會動手做事的準備！MiniMax Code 的互動式工作階段沒有這種模式，所以它會照常要求權限。而且由於代理程式拒絕記住對你家目錄的信任，從 `$HOME` 啟動時會改為在 `~/Work` 中開始。

也有終端機快速鍵：`a` 會在目前的終端機中以行內方式執行預設代理程式，而 `c`、`cx` 和 `cy` 則直接啟動 OpenCode、Claude Code 和 Codex（同樣是在它們的自動核准模式下）。主題變更也會同步到這些代理程式：當你切換 Omarchy 主題時，Claude Code、Pi、OpenCode 和 Hermes（一旦 Omarchy 已安裝它）全都會跟著變更。

### 你的代理程式指示

適用於每一個代理程式的個人規則都放在 `~/.agents/AGENTS.md` 中，旁邊就是位於 `~/.agents/skills` 的共享技能。在 _Agent > Instructions_ 之下開啟它，它也會將它連結到每一個保有自己全域檔案的 harness 中：`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`~/.pi/agent/AGENTS.md`、`~/.config/opencode/AGENTS.md`、Copilot 的 `~/.copilot/copilot-instructions.md`，依此類推。Crush 和 Amp 讀取 `~/.config/AGENTS.md` 連結，而 omp、Kimi 和 DeepSeek Harness 則直接讀取 `~/.agents/AGENTS.md`。選取預設代理程式時也會連結它。如果你已經有一個指示檔案，且之前還沒有共享檔案，它就會成為共享檔案；否則它會以 `.bak` 的形式保留在連結旁邊。在安裝另一個代理程式後，執行 `omarchy agent instructions` 來重新連結。

### 代理程式面板

頂部列有一個代理程式圖示。在你設定好代理程式之前，它的面板會引導你登入 Claude、Codex 或 Grok，而第一個就會成為你的預設代理程式。在那之後，面板會把每一項訂閱都放在同一頁上：每一個代理程式和帳戶連同它的方案、其 5 小時工作階段和每週限額各自的量表以及距離重置還剩的時間（將游標停留在上面可看到確切的百分比），或剩餘的預付餘額，全都位於一行輪替顯示你在所有代理程式上用量的文字之下，例如本週的 token 以及你最常使用的模型。在 _Make something_ 之下，它會為新的主題、外掛程式或應用程式提供起始提示，將任務交給你的預設代理程式。應用程式的打造方式就和 Omarchy 自己的 Hype、Monologue 和 Omacut 一樣，使用 C++ 和 Qt Quick，並遵循 omarchy-app 代理程式技能，而它們需要的編譯器和 Qt 元件都會一併安裝。Claude Code、Codex、Grok、Kimi、Cursor 及其 Grok Bot 額度、GitHub Copilot、Muse、Antigravity、Kimchi 和 Devin 開箱即涵蓋在內並附有它們的限額，而 Hermes、Mistral Vibe 和 Qwen Code 則會在你用過它們之後顯示它們的工作階段和 token。你透過 pi、omp 或 opencode 使用的供應商方案和金鑰也會顯示出來：OpenCode Zen 和 Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan 以及 Synthetic，連同它們的限額；Fireworks、OpenRouter 和 DeepSeek，連同它們的預付餘額；以及你在自己硬體上執行的模型，位於 Local models 之下。每一個代理程式都只會被計算一次，歸在向你收費的那一方之下，無論你透過多少個 harness 來驅動它。

以左鍵按一下列上的圖示來開啟面板，以右鍵按一下來啟動你的預設代理程式。它背後的使用記錄每 15 分鐘由 `omarchy agent usage-update` 重新產生一次，而面板甚至可以透過一個同步資料夾合併來自你其他機器的用量。完整的設定請參閱 `$OMARCHY_PATH/shell/plugins/agents/` 之下的 README。

### 多個訂閱

如果你付費購買了不止一個 Claude、Codex 或 Grok 方案——例如一個個人的 Max 和一個工作的方案——Omarchy 可以讓它們全都保持登入狀態，並在它們之間切換。用代理程式面板中的 + 新增一項訂閱，它會就在那裡引導你完成，或者使用 `omarchy agent account add claude Work`（或 `codex`，或 `grok`）。如果缺少 CLI，它會安裝它。某個供應商的第一個帳戶會透過你平常的瀏覽器登入，就在 CLI 一直查看的那個地方。在那之後的每一個帳戶則會透過一個私密視窗登入，所以你瀏覽器已經登入的那個帳戶不會被誤選；在那裡以你要新增的帳戶登入，並先關閉你已經開啟的任何私密視窗。絕對不要為了做這件事而登出 CLI：登出會撤銷已儲存的登入，而那個帳戶將必須重新新增。

若要透過 SSH 將你的訂閱登入複製到另一台 Omarchy 機器，請執行 `omarchy agent account copy user@laptop`。當目的地沒有安裝接收端時，傳送端會提供一個臨時的接收端，所以較舊的 Omarchy 機器無需更新就能接收帳戶。已安裝的接收端會優先使用。這會複製所有的 Claude、Codex 和 Grok 訂閱；加入供應商名稱來選取它們，例如 `omarchy agent account copy laptop claude`。帳戶名稱和指令 ID 會與來源相符，包括目的地已經存在的帳戶。如果名稱衝突，無關的目的地帳戶會獲得一個數字後綴，而設定、技能、外掛程式和對話記錄則會各自保留在本機。

目的地現有的憑證會被保留。一個已經在那裡登入的來源帳戶，其名稱會被同步，但不會取代它的憑證；其他帳戶則會加在它旁邊。若要取代相符帳戶已儲存的憑證，請在結束目的地該帳戶的工作階段後，使用 `omarchy agent account copy --replace laptop claude`。一個全新的目的地也會獲得來源使用中的帳戶和切換偏好；一個已經建立好的目的地則會保留它自己的。

憑證會透過 SSH 傳輸，並以私密檔案儲存在目的地，所以只複製到你信任的機器。這是一次性的複製，不是持續的同步。Codex 的重新整理 token 可能會被另一台機器輪替，導致複製過去的登入需要續期；在好幾台機器上同時使用時，各自獨立登入仍然是最可靠的選擇。請參閱 [Codex 的帳戶驗證指引](https://developers.openai.com/codex/auth/ci-cd-auth)。

每個供應商會有一個使用中的帳戶，而每一個新的工作階段都會以它開始：`cx`、`cy`、一個普通的 `claude`、`codex` 或 `grok`、任何透過 `omarchy agent` 啟動的東西，以及在 `PATH` 上找到 CLI 的指令稿或編輯器。用 `omarchy agent account use work` 切換（並用 `omarchy agent account use main` 切換回來），或在面板中按一個帳戶的編號然後按 `Enter`（或按一下它的 Use 按鈕）。已經在執行的工作階段會停留在它們開始時的那個帳戶上。對話記錄、設定、技能和外掛程式在帳戶之間共享，所以在同一個資料夾中的 `claude --continue` 會在新帳戶上從你上次離開的地方接續。

當你有多個帳戶時，面板會並排顯示每個帳戶的限額，並標記使用中的那一個。依預設，當使用中的帳戶超過某個限額的 95% 時，Omarchy 會通知你，而按一下通知會切換到餘裕最多的帳戶。將游標停留在面板中某個帳戶的那一行，按一下 Use 旁邊出現的 Autoswitch（或按 `m`），或執行 `omarchy agent account mode auto`，讓它改為自行切換；當它開啟時，Autoswitch 會取代 Use 的位置，再按一下它就會回到通知模式。加入一個數字來變更閾值，例如 `omarchy agent account mode auto 90`。如果每一個帳戶都超過閾值，你會收到一次通知，並得知哪個帳戶會最先釋出。當使用中的帳戶距離它的閾值在 15 個百分點以內時（預設情況下是 80%），它的限額會每三分鐘檢查一次，而不是每 15 分鐘。

`omarchy agent account list` 顯示每一個帳戶及其最新限額，`omarchy agent account remove work` 會忘掉一個帳戶，而 `omarchy agent account rename primary Hey` 會重新命名一個帳戶（或在面板中按一下一個帳戶的名稱）。這些指令作用於你預設代理程式的帳戶；若要觸及另一個供應商，請先點名它，例如 `omarchy agent account use codex side`。你已經在 `~/.claude` 或 `~/.codex` 中的登入就是 _Main_ 帳戶，並會留在原地。一個閒置超過約八小時的帳戶可能會顯示 _Sign-in required_；按一下它就能直接在面板中重新登入該帳戶，或在它之中開始一個工作階段，那也會自行重新整理登入。你在新增一個帳戶時所擁有的 MCP 伺服器會跟著它過去，但你之後用 `claude mcp add` 新增的伺服器只會到達你新增它們時的那個帳戶。Claude Desktop 以及以絕對路徑設定到 CLI 執行檔的工具不會跟著切換。明確的 `CLAUDE_CONFIG_DIR`、`CODEX_HOME` 或 `GROK_HOME` 的優先權高於選定的帳戶。

### 當機診斷

Omarchy 會監看 systemd-coredump 以找出處理程序當機。當某個東西發生 segfault 時，你會收到一個「Process crashed」通知——按一下它，當機就會連同 Omarchy 的 diagnose-crash 技能一併交給你的預設代理程式，該技能會引導代理程式從 core dump 建立事實，並判斷這次當機是否值得向 upstream 回報。你也可以用 `omarchy agent crash <pid>`，針對來自 `coredumpctl list` 的任何 PID 手動執行它。

監看功能依預設開啟。在 _Trigger > Toggle > Crash Capture_ 之下（或用 `omarchy toggle crash-capture`）將它關閉，通知就會停止；`omarchy agent crash <pid>` 仍然可以手動運作。

當機也可以一次針對一個程式靜音，這正是診斷在最後會向你提供的選項。`omarchy crash mute hyprland` 只會停止該程式的通知，`omarchy crash mute hyprland off` 會讓它們恢復，而單獨的 `omarchy crash mute` 會列出你已經靜音了什麼。它接受執行檔的路徑就和接受它的名稱一樣樂意，所以 `omarchy crash mute /usr/bin/hyprland` 做的是同樣的事。將含有空格的名稱加上引號，例如 `omarchy crash mute 'Some App'`。其他一切都仍然會通知，而被靜音的程式也仍然會當機——這只是藏起提醒，它並沒有修好任何東西。

### 桌面應用程式

_Install > AI_ 功能表還包含了一些圖形化的 AI 應用程式：ChatGPT 桌面應用程式、Claude 桌面應用程式（Anthropic 的 Linux beta 版，附有 Chat、Cowork 和 Claude Code 分頁）、用來與 xAI 的模型聊天的 Grok Bot、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexity 桌面應用程式，以及 T3 Code。Grok Bot 是桌面聊天應用程式。程式碼代理程式是 `grok` 指令。

Hermes Desktop 是你需要了解的那一個，因為一台機器上會有一個 Hermes，而它就是應用程式的 Hermes：Hermes 只會透過該應用程式安裝，而預設代理程式執行的 `hermes` 指令就是該應用程式的。選擇 Hermes 作為預設代理程式，安裝的就是 _Install > AI_ 那個項目所安裝的同樣的東西：該套件，以及一個位在 `~/.hermes` 之下、由 Hermes 自己的安裝程式設定好的 Hermes 執行環境，第一次會花幾分鐘時間。終端機的 `hermes` 指令、預設代理程式和該應用程式全都使用的就是那一個執行環境，而它會用 `hermes update` 自行更新，而不是等 Omarchy 發布新版。安裝它還會把 Omarchy 主題交給 Hermes，作為一個名為 `omarchy` 的外觀，而當你切換主題時，每一個 Hermes 介面都會跟著走；如果你不想這樣，請在 Hermes 的 Appearance 設定中或用 `/skin` 選另一個，而 Omarchy 會尊重那個選擇。在 _Remove > AI_ 之下移除該應用程式會先關閉 Hermes，包括 gateway 在內，把那個執行環境一併帶走，並保留你的聊天、記憶，以及 Hermes 為自己寫的技能，除非你另有指示：它會詢問，預設為否，那些資料和你的連線設定是否也要一併移除。

OpenClaw 的桌面體驗是它的 Control UI，它會以一個由它自己的本機 gateway 支撐的 web app 開啟。OpenClaw 住在 `~/.openclaw` 中並會自行更新：使用 Control UI 的「Update Gateway」按鈕或執行 `openclaw update`，gateway 就會在新版本上重新啟動。Omarchy 只決定一次全新安裝會從哪個版本開始。在 _Remove > AI_ 之下移除 OpenClaw 會將 gateway 服務和應用程式一併帶走，然後詢問 `~/.openclaw` 是否也要移除，因為那裡存放著你的聊天和憑證，連同 OpenClaw 本身以及它下載的外掛程式執行環境；預設會保留它，而再次安裝 OpenClaw 會將它重新接回去。

Herdr Desktop 是 [Herdr](https://herdr.dev) 桌面應用程式：終端機和程式碼代理程式的 spaces、tabs 和 panes，即使你關閉視窗，它們也仍會在它的核心中繼續執行。它不是來自套件，而是來自 Herdr 自己的安裝程式，所以它住在 `~/.local/share/herdr-app` 中，當你還沒有的時候，它會在 `~/.local/bin/herdr-core` 中一併帶來它的核心，並且它會自行更新兩者。它位於 Omarchy 隨附在 `Super + Ctrl + Return` 上的 `herdr` 指令旁邊，而不是取代它，並且擁有該指令的直接按鍵：`Alt + Return` 和 `Alt + Shift + Return` 會向下或向右分割一個 pane，`Alt + Escape` 會關閉它，`Ctrl + Alt + Arrow` 會在 panes 之間移動，`Alt + 1..9` 和 `Alt + Left/Right` 會選取一個 tab，而 `Alt + Up/Down` 會在 spaces 之間移動。`Ctrl + 1..9` 選取一個 space，而 `Alt + Shift + Up/Down` 則是在代理程式之間逐步切換。`Ctrl + Space` 前綴鍵仍然只屬於終端機，因為該應用程式無法為一個序列按住一個單純的 Ctrl 鍵。Omarchy 會將這些寫入 `~/.config/herdr-app/keys.json`，而 `omarchy-refresh-herdr-app` 會將它們恢復。安裝它會挑選 Herdr 的 Omarchy 主題，從那時起它就會跟著你的 Omarchy 主題走。Herdr 為淺色模式保留一個主題，為深色模式保留另一個，所以在深色和淺色的 Omarchy 主題之間切換之後，再在 Herdr 的主題選取器中為另一個模式選一次 Omarchy。

T3 Code 不是從套件，而是從它位於 `~/.local/share/t3code` 中的官方 AppImage 版本來執行，所以它會自行更新。安裝它時會詢問你要從 Stable 還是 Nightly 通道開始；之後可在 T3 Code 的設定中切換。你的討論串和設定住在 `~/.t3` 中，而在 _Remove > AI_ 之下移除 T3 Code 會將它們一併帶走。

### 本機模型

在你自己的機器上為你的程式碼代理程式執行一個開放模型。你的提示和程式碼都留在機器上；傳送給模型的東西沒有任何一項會離開它。從以下開始：

```bash
omarchy agent local use best
```

或者，在頂部列的代理程式面板中，選擇 + 然後選 Local AI，當有模型適合這台機器時它就會出現。第一次這樣做時，會安裝 Podman，它負責執行模型，而在 NVIDIA 機器上還會安裝 NVIDIA 的 container toolkit，讓它們能使用 GPU。然後 Omarchy 會為這台機器挑選建議的模型、下載它並啟動它。當模型執行時，預期會有數十 GB 的下載，且機器的絕大部分記憶體都會被用上：Flash Next 在其完整的 256K context 下會使用約 100 GiB。如果其他模型佔住了它需要的記憶體，它會被設定為停止狀態，等你停掉其中一個就能隨時啟動。模型會在登出時停止；當你為了其他事情需要記憶體時，就自己停掉它。

`omarchy agent local list` 會顯示各個選項，並解釋為何有些不適合。若要設定另一個，請執行 `omarchy agent local use <recipe>`。今天，`qwen3.8-flash-next-gufo` 和 `qwen3.8-27b-gufo` 可用於 128 GB 的 Strix Halo 機器；27B 會用掉約 40 GiB，所以它會留下空間給其他工作。新的 recipes 和建議會透過該套件隨著 `omarchy update` 送達。

你設定的每一個模型在代理程式面板中都會有自己的一行，就在你的訂閱旁邊：播放就能啟動它，暫停就能停掉它並釋放它的記憶體，而終端機按鈕則能在它上面開啟你的代理程式。當它們能在記憶體中同時放得下時，好幾個可以同時執行；如果有一個放不下，Omarchy 會告訴你該停掉哪個正在執行的模型。拖曳各行來重新排序它們，並在選定的行上按 Delete 來移除一個模型及其下載內容。

從命令列來看，`omarchy agent local start <recipe>` 和 `omarchy agent local stop <recipe>` 做的是同樣的事，`omarchy agent local status` 顯示每一個模型，而 `omarchy agent --local` 會在你最後啟動的那個模型上開啟你的預設代理程式。pi、OpenCode 和 Qwen Code 可以使用其中一個；換作任何其他預設值時，它會以 pi 開啟。pi 也會在它自己的模型選取器中列出你設定過的每一個模型，以及那些在你已配對的機器上的模型，所以普通的 `pi` 也能觸及它們。任何與 OpenAI 相容的用戶端也能連接：`status` 會顯示每個模型的位址（第一個是 `http://127.0.0.1:11435/v1`），recipe 名稱就是該模型，而金鑰位於 `~/.config/omarchy/agent-local/key`。

`omarchy agent local remove <recipe>` 會刪除一個模型，以及沒有其他模型使用的下載內容。

第三方執行環境會以其發布者標示。Omarchy 執行每一個模型時都不開放網路存取。

### 本機 LLM

Omarchy 建議兩種執行本機 LLM 模型的方式：LM Studio 和 Ollama。LM Studio 提供了一個 GUI 介面，用於尋找開放權重模型、安裝它們並執行它們。這是一個能輕鬆上手的好方法。Ollama 則提供了一個 CLI 以類似的方式做到這一點。但如果你是本機模型的新手，我會從 LM Studio 開始。你可以在 Omarchy Menu 的 _Install > AI_ 之下安裝其中任何一個。

### Omarchy Skill

代理程式技能幫助 AI 以特定方式使用特定工具，而 Omarchy 隨附了一個用於調整系統的預設技能。就像調整你的 Hyprland 設定、調整列，甚至從頭打造一個新主題一樣。它被以 symlink 連結到 Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` 和每一個 `~/.hermes/profiles/*/skills`）的技能目錄，以及通用的 `~/.agents/skills` 位置，所以大部分 harness 都會自動將它撿起來。

但你應該將這項技能視為實驗性的。不同的模型運用它會有不同的效果。最好先在 plan mode 中執行它，這樣你就會對代理程式想變更什麼有個概念。然後準備好回復變更，甚至在代理程式把一切搞得一團亂時調用 `omarchy reinstall configs`。
