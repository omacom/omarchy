### 安裝與更新 agent

除 Hermes 和 OpenClaw 之外，這些 agent 使用 mise 的延遲安裝：第一次啟動會安裝 CLI，之後的啟動會重複使用它。mise 也會最多每四小時檢查一次已安裝的 agent 有沒有新版本，就在它啟動之前，或在 shell 提示字元處於背景檢查。如果該更新失敗或你離線，就會執行已安裝的版本。`omarchy update` 會連同 Omarchy 其餘部分一起更新已安裝的 agent，而 `mup` 只更新 mise 管理的工具。

一個 agent 自己的更新程式，例如 `claude update`、`codex update`，或 app 中的更新按鈕，不會更新 mise 管理的安裝。`codex update` 會失敗，而 `claude update` 可能回報成功，卻安裝了一個 mise 沒有追蹤的獨立副本。如果你寧願使用 agent 原生的安裝程式和更新程式，把它加入 `disable_tools`；請參閱 [預先安裝的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

若要在需要之前安裝所有已設定的延遲工具，執行 `mise install --include-lazy`。這包括 Omarchy 的其他預設 CLI 工具以及這些 agent。關於安裝單一工具或使用你自己的安裝，請參閱 [預先安裝的 CLI 工具](18-development-tools.md#preinstalled-cli-tools)。

`grok` 透過 mise 的第一方 `grok` 套件安裝，方式和 `claude` 與 `codex` 相同。執行 `grok`，或在 _Agent > Harness_ 下選擇它。跳過 x.ai 上的 `curl | bash` 安裝程式。那條路徑會在 `~/.grok/bin` 放第二份副本，把它加到 `PATH` 最前面，並覆寫 Omarchy 的 wrapper。

`dsh` 會在 `127.0.0.1:3080` 開啟它的瀏覽器 UI，並以啟動目錄作為預設工作區。它的瀏覽器 UI 不接受起始提示，所以 `omarchy agent prompt` 會開啟它，並把提示放在你的剪貼簿讓你貼上。Omarchy 以 DeepSeek 的無需核准權限預設集啟動它。當你使用 DeepSeek 官方模型 API 時，DeepSeek Harness 會把工作階段記錄上傳到 DeepSeek；在它的瀏覽器 UI 中，於 _Settings > General > Upload Session Log_ 下關閉它。你寄給它的意見回饋也會連同工作階段一起上傳，除非你以 `DSH_TELEMETRY_MODE=DISABLED` 啟動它。

### 預設 agent

使用 `omarchy default agent <name>` 或在 Omarchy Menu（`Super + Space`）的 _Agent > Harness_ 下選擇你的預設 agent。如果該 agent 尚未安裝，選擇它會先安裝它，而且它也會在 app 啟動器中、Agent 旁邊，得到一個自己的啟動器。全新的 Omarchy 會以一次性的通知邀請你做這個選擇。

選擇 Claude 也會嘗試為 Chromium、Chrome、Brave、Brave Origin 和 Edge 設定它的瀏覽器擴充功能。擴充功能設定適用於所有使用者，而且可能會要求你的系統密碼；取消或擴充功能安裝失敗，仍然會選擇並啟動 Claude。重新啟動你的瀏覽器，若出現提示就啟用擴充功能，並登入 Claude 以完成連接。在 Claude 中執行 `/chrome` 檢查連線。Firefox 和 Zen 不支援這個擴充功能。如果在加入這項設定之前 Claude 就已經是你的預設值，再選擇它一次即可安裝擴充功能。

選好之後，`Super + Shift + Ctrl + A` 會在專用終端機視窗中啟動預設 agent（若你尚未選擇，則會開啟選擇器）。你也可以用 `omarchy agent prompt "Review this project"` 讓它直接進入任務。Freebuff 和 DeepSeek Harness 不接受起始提示，所以它們會改為把提示放在你的剪貼簿開啟，讓你貼上。以這種方式啟動的 agent 會在各自「不要停下來問」的模式下無人看管地執行，所以準備好它們真的會動手做事！MiniMax Code 的互動式工作階段沒有這種模式，所以它會照常要求權限。而且由於 agent 拒絕記住對你家目錄的信任，從 `$HOME` 啟動的會改在 `~/Work` 開始。

也有終端機快捷方式：`a` 會在目前終端機中內嵌執行預設 agent，而 `c`、`cx` 和 `cy` 會直接啟動 OpenCode、Claude Code 和 Codex（同樣以它們的自動核准模式）。主題變更也會同步到 agent：當你切換 Omarchy 主題時，Claude Code、Pi、OpenCode 和 Hermes（一旦 Omarchy 已安裝它）都會跟著變。

### 你的 agent 指示

給每個 agent 的個人規則放在 `~/.agents/AGENTS.md`，就在 `~/.agents/skills` 中的共用技能旁邊。在 _Agent > Instructions_ 下開啟它，它也會把它連結進每個保留自己全域檔案的 harness：`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`~/.pi/agent/AGENTS.md`、`~/.config/opencode/AGENTS.md`、Copilot 的 `~/.copilot/copilot-instructions.md`，諸如此類。Crush 和 Amp 讀取 `~/.config/AGENTS.md` 連結，而 omp、Kimi 和 DeepSeek Harness 直接讀取 `~/.agents/AGENTS.md`。選擇預設 agent 也會連結它。如果你已經有一個指示檔案，而且還沒有共用檔案，它就會成為共用檔案；否則它會以 `.bak` 形式保留在連結旁邊。在安裝另一個 agent 後，執行 `omarchy agent instructions` 重新連結。

### Agents 面板

頂部列有一個 agents 圖示。在你設定 agent 之前，它的面板會引導你登入 Claude、Codex 或 Grok，而第一個會成為你的預設 agent。之後，面板會把每個訂閱放在同一頁：每個 agent 和帳戶及其方案、其 5 小時工作階段和每週限制各自的計量表以及距離重置的時間（將滑鼠懸停可看確切百分比），或剩餘的預付餘額，上方有一行輪播顯示你跨全部帳戶的使用情況，例如本週的 token 和你最常用的模型。在 _Make something cool_ 下，它提供製作新主題、plugin、app 或遊戲的起始提示，並把任務交給你的預設 agent。Apps 依照 omarchy-make-app agent 技能，以 C++ 和 Qt Quick 建構，就像 Omarchy 自己的 Hype、Monologue 和 Omacut 一樣，而且它們需要的 compiler 和 Qt 元件都已安裝。Games 是 `~/Games/vibes` 中的單一 three.js 頁面，依照 omarchy-make-game agent 技能，而且全都從一個以目前主題呈現的 Game Vibes 啟動器開啟；它們從網路載入 three.js，所以啟動時需要連線。Claude Code、Codex、Grok、Kimi、Cursor 及其 Grok Bot 額度、GitHub Copilot、Muse、Antigravity 和 Devin 開箱即涵蓋其限制，Kimchi 涵蓋其方案、預付點數和支出預算，而 Hermes、Mistral Vibe 和 Qwen Code 一旦你使用過，就會顯示它們的工作階段和 token。透過 pi、omp 或 opencode 使用的供應商方案和金鑰也會顯示：OpenCode Zen 和 Go、Z.ai GLM Coding Plan、Ollama Cloud、MiniMax Token Plan 和 Synthetic 及其限制；OpenRouter 和 DeepSeek 及其預付餘額；Fireworks 及其過去 30 天的支出。在你自己硬體上執行的模型的 token 也計入總數；模型本身有自己的面板，說明於 [本機模型](#local-models) 下。每個 agent 只計算一次，歸在向它收費的一方名下，無論你透過多少 harness 駕駛它。

左鍵點擊列圖示或按 `Super + Ctrl + X` 開啟面板，右鍵點擊啟動你的預設 agent，中鍵點擊重新整理。它背後的使用記錄每 15 分鐘由 `omarchy agent usage update` 重新產生，而且面板甚至可以透過同步資料夾合併來自你其他機器的使用情況。完整設定請參閱 `$OMARCHY_PATH/shell/plugins/agents/` 下的 README。

### 多個訂閱

如果你付費訂閱不止一個 Claude、Codex 或 Grok 方案——例如一個個人 Max 和一個工作用的——Omarchy 可以讓它們全部保持登入，並在它們之間切換。用 agents 面板中的 + 新增一個訂閱，它會就在那裡引導你完成，或用 `omarchy agent account add claude Work`（或 `codex`，或 `grok`）。若缺少 CLI，它會安裝它。每個供應商的第一個帳戶會透過你平常的瀏覽器登入，就在 CLI 一直查看的地方。之後的每個帳戶都會透過隱私視窗登入，所以你瀏覽器已經登入的帳戶不會被誤選；在那裡以你要新增的帳戶登入，並先關閉你已經開啟的任何隱私視窗。永遠不要為此登出 CLI：登出會撤銷已儲存的登入，而該帳戶就必須重新新增。

若要透過 SSH 將你的訂閱登入複製到另一台 Omarchy 機器，執行 `omarchy agent account copy user@laptop`。當目的地沒有安裝接收端時，寄件端會提供一個暫時接收端，所以較舊的 Omarchy 機器無需更新就能接收帳戶。已安裝的接收端優先。這會複製所有 Claude、Codex 和 Grok 訂閱；加入供應商名稱來選取它們，例如 `omarchy agent account copy laptop claude`。帳戶名稱和指令 ID 與來源相符，包括目的地已存在的帳戶。無關的目的地帳戶若名稱衝突，會得到數字後綴，而設定、技能、plugin 和對話記錄則保留在各台機器本機。

目的地現有的憑證會保留。已經在那裡登入的來源帳戶，其名稱會同步，但不會取代其憑證；其他帳戶會加在它旁邊。若要取代相符帳戶已儲存的憑證，先在目的地結束該帳戶的工作階段，再使用 `omarchy agent account copy --replace laptop claude`。全新目的地也會得到來源使用中的帳戶和切換偏好；已建立的目的地則保留自己的。

憑證透過 SSH 傳送，並儲存在目的地上的私有檔案中，所以只複製到你信任的機器。這是一次性複製，不是持續同步。Codex refresh token 可能被另一台機器輪替，導致複製的登入需要續期；在多台機器上同時使用時，個別登入仍是最可靠的選擇。請參閱 [Codex 的帳戶驗證指引](https://developers.openai.com/codex/auth/ci-cd-auth)。

每個供應商有一個使用中的帳戶，而且每個新工作階段一開始就是它：`cx`、`cy`、一個普通的 `claude`、`codex` 或 `grok`、任何透過 `omarchy agent` 啟動的東西，以及在 `PATH` 上找到該 CLI 的 script 或編輯器。用 `omarchy agent account use work` 切換（再用 `omarchy agent account use main` 切回來），或在面板中按帳戶的號碼然後按 `Enter`（或點擊它的 Use 按鈕）。執行中的 Claude 工作階段也會切換，從它們下一則訊息開始：每個 Claude 工作階段都在 `~/.claude` 中執行，那裡永遠保存使用中帳戶的登入。由較舊 Omarchy 在帳戶自己的資料夾中啟動的 Claude 工作階段會保留該登入，直到它結束，所以切換會點名那些工作階段，並在它們消失後自行完成。執行中的 Codex 和 Grok 工作階段會留在它們啟動時所用的帳戶上。對話記錄、設定、技能和 plugin 在帳戶間共用，所以在同一個資料夾中的 `claude --continue` 會在新帳戶上從你中斷的地方繼續。

有多個帳戶時，面板會並排顯示每個帳戶的限制，並標記使用中的那個。預設情況下，當使用中帳戶超過限制的 95% 時，Omarchy 會通知你，點擊通知會切換到餘裕最多的帳戶。將滑鼠懸停在面板中的帳戶行上，點擊 Use 旁出現的 Autoswitch（或按 `m`），或執行 `omarchy agent account mode auto`，讓它自行切換；開啟時，Autoswitch 會取代 Use 的位置，再點擊一次會回到通知。加入數字來更改門檻，例如 `omarchy agent account mode auto 90`。如果每個帳戶都超過門檻，你會收到一次通知，並告知哪個帳戶最先釋放。當使用中帳戶距離門檻在 15 個百分點以內（預設為 80%）時，它的限制會每三分鐘檢查一次，而不是每 15 分鐘。

`omarchy agent account list` 顯示每個帳戶及其最新限制，`omarchy agent account remove work` 忘記一個，而 `omarchy agent account rename primary Hey` 重新命名一個（或點擊面板中的帳戶名稱）。這些指令作用在你的預設 agent 的帳戶上；若要到達其他供應商，先命名它，例如 `omarchy agent account use codex side`。你在 `~/.claude` 或 `~/.codex` 中已經有的登入就是 _Main_ 帳戶。Codex 的會留在原處；Claude 的在另一個帳戶使用中時，會待在它自己的資料夾中。閒置超過約八小時的帳戶可能會顯示 _Sign-in required_；點擊它就能在面板中直接重新登入該帳戶，或切換到它並啟動工作階段，它會自行重新整理登入。你用 `claude mcp add` 新增的 MCP server 會到達每個 Claude 帳戶，因為它們都在 `~/.claude` 中執行；對於 Codex 和 Grok，新增帳戶時你已有的 server 會跟著它，但之後的只會到達你新增它們的帳戶。Claude Desktop 保留它自己的登入，而以絕對路徑指向 CLI 二進位檔設定的 Codex 或 Grok 工具不會跟隨切換。明確的 `CLAUDE_CONFIG_DIR`、`CODEX_HOME` 或 `GROK_HOME` 優先於所選帳戶。

### 當機診斷

Omarchy 監看 systemd-coredump 的處理程序當機。一旦你選擇了預設 agent，任何你的程式傾印核心都會帶來 "Process crashed" 通知——點擊它，當機就會連同 Omarchy 的 omarchy-diagnose-crash 技能一起交給你的預設 agent，該技能會引導 agent 從核心傾印建立事實，並決定當機是否值得向 upstream 回報。你也可以用 `omarchy agent crash <pid>` 手動對 `coredumpctl list` 中的任何 PID 執行它。

監看預設開啟。在 _Trigger > Toggle > Crash Capture Off_ 下關閉它（或用 `omarchy toggle crash-capture`）通知就會停止；`omarchy agent crash <pid>` 仍可手動運作。

當機也可以一次靜音一個程式，這正是診斷最後提供給你的。`omarchy crash mute hyprland` 只停止該程式的通知，`omarchy crash mute hyprland off` 讓它們回來，而單獨的 `omarchy crash mute` 列出你已靜音的項目。它接受二進位檔的路徑和名稱一樣欣然，所以 `omarchy crash mute /usr/bin/hyprland` 做同樣的事。將含有空格的名稱引號括起來，例如 `omarchy crash mute 'Some App'`。其他一切仍會通知，而且被靜音的程式仍然會當機——這藏起提醒，不會修任何東西。

### 桌面應用程式

_Install > AI_ 選單還包含一些圖形化 AI app：Amp Desktop、Antigravity Desktop、ChatGPT desktop app、Claude desktop app（Anthropic 的 Linux beta，具備 Chat、Cowork 和 Claude Code 分頁）、Grok Bot 用來與 xAI 的模型聊天、Herdr Desktop、Hermes Desktop、OpenClaw、Perplexity desktop app，以及 T3 Code。Grok Bot 是桌面聊天 app。編碼 agent 是 `grok` 指令。

Hermes Desktop 是要知道的一個，因為一台機器有一個 Hermes，而且它是 app 的：Hermes 永遠只透過該 app 安裝，而且預設 agent 執行的 `hermes` 指令就是該 app 的。選擇 Hermes 作為預設 agent 會安裝與 _Install > AI_ 項目相同的東西：該套件，以及一個由 Hermes 自己安裝程式在 `~/.hermes` 下設定的 Hermes runtime，第一次需要幾分鐘。該 runtime 是終端機 `hermes` 指令、預設 agent 和 app 全都使用的那一個 Hermes，而且它會用 `hermes update` 自我更新，而不是等待 Omarchy 發行。安裝它也會把 Omarchy 主題交給 Hermes 作為名為 `omarchy` 的 skin，每個 Hermes 介面都會在你切換主題時跟著變；如果你不想，在 Hermes 的 Appearance 設定下或用 `/skin` 選擇另一個，Omarchy 會讓那個選擇維持原樣。在 _Remove > AI_ 下移除該 app 會先關閉 Hermes（包括 gateway），把該 runtime 一起帶走，並保留你的聊天、記憶，以及 Hermes 為自己寫的技能，除非你另有指示：它會問你是否也要把那些資料和你的連線設定一併移除，預設為否。

OpenClaw 的桌面體驗是它的 Control UI，它會作為由自己本機 gateway 支援的 web app 開啟。OpenClaw 住在 `~/.openclaw` 並自我更新：使用 Control UI 的 "Update Gateway" 按鈕或執行 `openclaw update`，gateway 就會在新版本上重新啟動。Omarchy 只選擇全新安裝的起始發行版本。OpenClaw 也可以是你的預設 agent：在 _Agent > Harness_ 下選擇它會在 `~/.openclaw` 中設定那同一份副本，而且該 agent 會開啟連接到其 gateway 的 OpenClaw 終端機 UI。在 _Remove > AI_ 下移除 OpenClaw 會把 gateway 服務和 app 一起帶走，然後問 `~/.openclaw` 是否也要一併移除，因為那裡放著你的聊天和憑證，以及 OpenClaw 本身和它下載的 plugin runtime；預設會保留它，而且再次安裝 OpenClaw 會重新接上它。

Herdr Desktop 是 [Herdr](https://herdr.dev) 桌面 app：當你關閉視窗時，其核心中持續執行的終端機和編碼 agent 的 spaces、tabs 和 panes。它來自 Herdr 自己的安裝程式而不是套件，所以它住在 `~/.local/share/herdr-app`，當你還沒有時，會在 `~/.local/bin/herdr-core` 帶來它的核心，而且兩者都會自我更新。它位於 Omarchy 在 `Super + Ctrl + Return` 上隨附的 `herdr` 指令旁邊，而不是取代它，而且得到該指令的直接按鍵：`Alt + Return` 和 `Alt + Shift + Return` 向下或向右分割 pane，`Alt + Escape` 關閉它，`Ctrl + Alt + Arrow` 在 pane 之間移動，`Alt + 1..9` 和 `Alt + Left/Right` 選擇 tab，而 `Alt + Up/Down` 在 space 之間移動。`Ctrl + 1..9` 選擇 space，`Alt + Shift + Up/Down` 逐步切換 agent。`Ctrl + Space` 前綴鍵仍只限終端機，因為該 app 無法按住單純的 Ctrl 鍵來組成序列。Omarchy 把這些寫入 `~/.config/herdr-app/keys.json`，而 `omarchy-refresh-herdr-app` 會把它們恢復。安裝它會選用 Herdr 的 Omarchy 主題，從此跟隨你的 Omarchy 主題。Herdr 為淺色模式保留一個主題、為深色保留一個，所以在深色及淺色 Omarchy 主題之間切換後，再在 Herdr 的主題選擇器中選一次 Omarchy 以套用到另一個模式。

T3 Code 從 `~/.local/share/t3code` 中的官方 AppImage 發行版本執行，而不是從套件執行，所以它會自我更新。安裝它會問要從 Stable 還是 Nightly 通道開始；之後在 T3 Code 的設定中切換。你的執行緒和設定住在 `~/.t3`，在 _Remove > AI_ 下移除 T3 Code 會把它們一起帶走。

### 本機模型

在你自己的機器上為你的編碼 agent 執行一個開放模型。你的提示和程式碼留在機器上；送給模型的東西不會離開它。從以下開始：

```bash
omarchy models use best text
```

這會為這台機器設定最佳的文字模型，也就是你的 agent 使用的類型。Image、video 和 music 模型有各自的最佳選擇：`omarchy models use best image`、`video` 或 `music`。執行 `omarchy models use best` 以查看每種類型為這台機器挑選的選擇。

或從頂部列的星光圖示（agents 圖示旁邊）開啟本機模型面板，或用 Super + Ctrl + Shift + X，並選擇 +。當有模型適合這台機器時，該圖示會出現。執行模型的 Podman 隨 Omarchy 附帶，NVIDIA 機器上的 NVIDIA container toolkit 也一樣，它給予它們 GPU；如果缺少任何一個，第一次設定會安裝它。Omarchy 然後挑選為這台機器推薦的模型，下載它，並啟動它。預期下載數十 GB，而且當模型執行時，機器的大部分記憶體將被使用：Flash Next 以其完整的 256K context 使用約 100 GiB。如果其他模型占據它需要的記憶體，它會設定成停止狀態，一旦你停止其中一個就可啟動。模型在登出時停止；當你需要記憶體做其他事時，自行停止它。

`omarchy models list` 顯示選項並解釋為何一些不適合。若要設定另一個，執行 `omarchy models use <recipe>`。今日，`qwen3.8-flash-next-gufo` 和 `qwen3.8-27b-gufo` 適用於 128 GB Strix Halo 機器；27B 約需 40 GiB，所以它為其他工作留出空間。在配備 Intel 的 Arc B390 的 64 GB 筆記型電腦上，`qwen3.6-35b-a3b-llamacpp` 約以 30 GiB 執行。新 recipes 和推薦隨 `omarchy update` 透過套件到達。

你設定的每個模型在本機模型面板中都有自己的行：播放來啟動它，暫停來停止它並釋放它的記憶體，以及終端機按鈕在它上面開啟你的 agent。頂部橫跨一個列，顯示機器記憶體如何在 Omarchy 本身（系統和你的 app）、每個執行中的模型，以及空餘之間分割。指向一個已停止的模型，該列顯示它是否適合，或差多少。幾個能同時執行，當它們一起適合記憶體時；如果一個不適合，Omarchy 說明要停止哪個執行中的模型。拖曳行以其標誌來重新排序它們，並按 Delete 在所選行上刪除一個模型及其下載。

你設定的每個模型也在 app 啟動器中獲得自己的項目，位於模型名稱下並帶其製作者標誌，就像登入 Claude、Codex 或 Grok 增加一個的一樣。它在該模型上開啟你的 agent，並且如果尚未執行會先啟動模型：終端機顯示它載入，並在它就緒後交給 agent。移除模型也會移除其項目。

不是每個模型都是用來寫程式的。Image、video 和 music 模型改在 Fantasi 開啟，那是 Omarchy 用以在這台機器上執行模型製作圖片、video 和 music 的 app，從它們的啟動器項目和本機模型面板的行開啟。

模型保持完全如其設定般執行，所以 Omarchy 更新永遠不會在你的 agent 底下重新啟動一個。當 Omarchy 有更新的 runtime 或更新的 weights 適用於你已設定的模型時，其行會顯示更新按鈕：按它，模型會在背景重新設定，只下載變更，並在新版本上重啟。已停止的模型仍保持停止。`omarchy models update` 在終端機對每個模型做同樣的事。

從指令行，`omarchy models start <recipe>` 和 `omarchy models stop <recipe>` 做同樣事，`omarchy models status` 顯示每個模型，而 `omarchy agent --local` 在你最後啟動的模型上開啟你的預設 agent。pi、OpenCode 和 Qwen Code 能使用一個；與任何其他預設一起，它會在 pi 開啟，或如果你沒有 pi，則在 OpenCode 開啟。pi 也在其自己的模型選擇器中列出你設定的每個模型，以及在你配對的機器上的，所以普通的 `pi` 也能觸及它們。任何 OpenAI-compatible client 也能連接：`status` 顯示每個模型的地址（第一個是 `http://127.0.0.1:11435/v1`），recipe name 是模型，而 key 在 `~/.config/omarchy/agent-local/key`。

`omarchy models remove <recipe>` 刪除一個模型及沒有其他模型使用的下載。

第三方 runtime 標示其出版者。Omarchy 在無網路存取下執行每個模型。

### 本機 LLM

Omarchy 推薦兩種運行本機 LLM 模型的方式：LM Studio 和 Ollama。LM Studio 提供 GUI 介面尋找開放權重模型、安裝它們並運行它們。這是輕鬆起步的好方法。Ollama 提供 CLI 以類似方式做。但如果你是本機模型新手，我會從 LM Studio 開始。你可以在 Omarchy Menu 的 _Install > AI_ 下安裝任一個。

### Omarchy 技能

Agent 技能幫助 AI 以特定方式使用特定工具，Omarchy 附帶七個。omarchy 技能涵蓋量身定制系統，像調整你的 Hyprland config 或調整 bar。omarchy-make-theme、omarchy-make-plugin、omarchy-make-app 和 omarchy-make-game 涵蓋製作新東西，omarchy-contribute 涵蓋回報 bug 或向 upstream 寄送 fix，而 omarchy-diagnose-crash 遍歷當機的 core dump。它們以 symlink 連結進 Claude Code（`~/.claude/skills`）、Codex（`~/.codex/skills`）、Pi（`~/.pi/agent/skills`）、Antigravity（`~/.gemini/config/skills`）、Hermes（`~/.hermes/skills` 及每個 `~/.hermes/profiles/*/skills`），以及通用 `~/.agents/skills` 位置的技能目錄，所以大多數 harness 自動撿起它們。同名的你自己的技能資料夾優先。

但你應視這些技能為實驗性。不同模型將以不同效果使用它。最好先在 plan mode 執行，讓你知道 agent 想更改什麼。然後準備好 rollback 變更，甚至 invoke `omarchy reinstall configs`，如果 agent 把一切搞得一團糟。
