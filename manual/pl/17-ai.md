# AI

Omarchy zawiera launchery dla poniższych agentów do kodowania, nie wybierając za Ciebie domyślnego. Uruchom polecenie, aby przy pierwszym użyciu zainstalować jego CLI, a następnie uwierzytelnij się, gdy pojawi się prośba. Hermes jest wyjątkiem: przy pierwszym użyciu nic dla niego nie jest instalowane, a wybranie go instaluje Hermes Desktop, jak wyjaśnia sekcja _Aplikacje desktopowe_ poniżej.

### Instalowanie i aktualizowanie agentów

Z wyjątkiem Hermes, agenci ci korzystają z leniwej instalacji mise: pierwsze uruchomienie instaluje CLI, a kolejne uruchomienia używają go ponownie. mise sprawdza też, co najwyżej raz na cztery godziny, czy zainstalowany agent ma nową wersję, tuż przed jego uruchomieniem lub w tle przy znaku zachęty powłoki. Jeśli ta aktualizacja się nie powiedzie lub jesteś offline, uruchamia się zainstalowana wersja. `omarchy update` aktualizuje zainstalowanych agentów wraz z resztą Omarchy, a `mup` aktualizuje wyłącznie narzędzia zarządzane przez mise.

Własny aktualizator agenta, taki jak `claude update`, `codex update` lub przycisk aktualizacji w aplikacji, nie aktualizuje instalacji zarządzanej przez mise. `codex update` kończy się niepowodzeniem, a `claude update` może zgłosić sukces, instalując przy tym osobną kopię, której mise nie śledzi. Jeśli wolisz korzystać z natywnego instalatora i aktualizatora agenta, dodaj go do `disable_tools`; zobacz [Preinstalowane narzędzia CLI](18-development-tools.md#preinstalled-cli-tools).

Aby zainstalować wszystkie skonfigurowane leniwe narzędzia, zanim będą Ci potrzebne, uruchom `mise install --include-lazy`. Obejmuje to zarówno agentów, jak i pozostałe domyślne narzędzia CLI Omarchy. Zobacz [Preinstalowane narzędzia CLI](18-development-tools.md#preinstalled-cli-tools), aby dowiedzieć się, jak zainstalować pojedyncze narzędzie lub użyć własnej instalacji.

`grok` jest instalowany przez oficjalny pakiet `grok` mise, tak samo jak `claude` i `codex`. Uruchom `grok` lub wybierz go w _Setup > Defaults > Agent_. Pomiń instalator `curl | bash` na x.ai. Ta ścieżka umieszcza drugą kopię w `~/.grok/bin`, stawia ją na początku `PATH` i nadpisuje wrapper Omarchy.

`dsh` otwiera swój interfejs przeglądarkowy pod adresem `127.0.0.1:3080`, z katalogiem uruchomienia jako domyślnym obszarem roboczym. Jego interfejs przeglądarkowy nie przyjmuje promptu startowego, więc `omarchy agent prompt` otwiera go z promptem w schowku do wklejenia. Omarchy uruchamia go ze zestawem uprawnień bez zatwierdzania od DeepSeek. DeepSeek Harness przesyła dzienniki sesji do DeepSeek, gdy korzystasz z jego oficjalnego API modeli; wyłącz to w _Settings > General > Upload Session Log_ w jego interfejsie przeglądarkowym. Opinie, które mu wysyłasz, również są przesyłane wraz z sesją, chyba że uruchomisz go z `DSH_TELEMETRY_MODE=DISABLED`.

### Domyślny agent

Wybierz domyślnego agenta za pomocą `omarchy default agent <name>` lub w _Setup > Defaults > Agent_ w menu Omarchy (`Super + Space`). Jeśli agent nie jest jeszcze zainstalowany, wybranie go najpierw go instaluje. Świeża instalacja Omarchy zaprosi Cię do dokonania tego wyboru jednorazowym powiadomieniem.

Wybranie Claude próbuje również skonfigurować jego rozszerzenie przeglądarki dla Chromium, Chrome, Brave, Brave Origin i Edge. Konfiguracja rozszerzenia dotyczy wszystkich użytkowników i może poprosić o hasło systemowe; anulowanie lub nieudana instalacja rozszerzenia nadal wybiera i uruchamia Claude. Uruchom ponownie przeglądarkę, włącz rozszerzenie, jeśli pojawi się prośba, i zaloguj się do Claude, aby dokończyć łączenie. Uruchom `/chrome` w Claude, aby sprawdzić połączenie. Firefox i Zen nie obsługują tego rozszerzenia. Jeśli Claude był już Twoim domyślnym agentem, zanim dodano tę konfigurację, wybierz go ponownie, aby zainstalować rozszerzenie.

Po dokonaniu wyboru `Super + Shift + Ctrl + A` uruchamia domyślnego agenta w dedykowanym oknie terminala (lub przywołuje selektor, jeśli jeszcze nie dokonałeś wyboru). Możesz też uruchomić go od razu do zadania za pomocą `omarchy agent prompt "Review this project"`. Freebuff i DeepSeek Harness nie przyjmują promptu startowego, więc zamiast tego otwierają się z promptem w schowku do wklejenia. Agenci uruchamiani w ten sposób działają bez nadzoru, w swoich trybach „nie zatrzymuj się, żeby pytać”, więc bądź gotowy na to, że naprawdę będą coś robić! MiniMax Code nie ma takiego trybu dla swoich interaktywnych sesji, więc pyta o uprawnienia jak zwykle. A ponieważ agenci odmawiają zapamiętywania zaufania dla Twojego katalogu domowego, uruchomienia z `$HOME` zaczynają się zamiast tego w `~/Work`.

Istnieją też skróty terminalowe: `a` uruchamia domyślnego agenta bezpośrednio w bieżącym terminalu, natomiast `c`, `cx` i `cy` uruchamiają bezpośrednio OpenCode, Claude Code i Codex (również w trybach automatycznego zatwierdzania). Zmiany motywu synchronizują się również z agentami: Claude Code, Pi, OpenCode i Hermes (gdy już Omarchy go zainstaluje) podążają za Tobą, gdy zmieniasz motyw Omarchy.

### Panel agentów

Na górnym pasku znajduje się ikona agentów. Zanim skonfigurujesz agenta, jego panel przeprowadzi Cię przez logowanie do Claude, Codex lub Grok, a pierwszy z nich stanie się Twoim domyślnym agentem. Potem panel umieszcza każdą subskrypcję na jednej stronie: każdego agenta i konto wraz z jego planem, wskaźnik dla każdego z jego limitów 5-godzinnej sesji i tygodniowych wraz z czasem do ich resetu (najedź, aby zobaczyć dokładną wartość procentową) lub pozostałe saldo prepaid, pod linią, która rotuje przez to, czego zużyłeś we wszystkich z nich, na przykład tokeny w tym tygodniu i Twój najczęściej używany model. W sekcji _Make something_ oferuje prompty startowe dla nowego motywu, wtyczki lub aplikacji, które przekazują zadanie Twojemu domyślnemu agentowi. Aplikacje są budowane tak, jak własne Hype, Monologue i Omacut Omarchy, w C++ i Qt Quick, zgodnie z skillem agenta omarchy-app, a kompilator i potrzebne im elementy Qt są zainstalowane. Claude Code, Codex, Grok, Kimi, Cursor oraz jego pula Grok Bot, GitHub Copilot, Muse, Antigravity, Kimchi i Devin są obsługiwane od razu wraz ze swoimi limitami, a Hermes, Mistral Vibe i Qwen Code pokazują swoje sesje i tokeny, gdy już ich użyjesz. Pojawiają się też plany i klucze dostawców, których używasz przez pi, omp lub opencode: OpenCode Zen i Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan oraz Synthetic wraz z ich limitami; Fireworks, OpenRouter i DeepSeek wraz z ich saldami prepaid; oraz modele, które uruchamiasz na własnym sprzęcie, w sekcji Local models. Każdy agent jest liczony raz, pod tym, kto go rozlicza, niezależnie od tego, przez ile harnessów go obsługujesz.

Kliknij ikonę na pasku lewym przyciskiem, aby otworzyć panel, prawym przyciskiem, aby uruchomić domyślnego agenta. Zapisy zużycia, na których opiera się panel, są regenerowane co 15 minut przez `omarchy agent usage-update`, a panel może nawet łączyć zużycie z innych Twoich maszyn za pośrednictwem zsynchronizowanego folderu. Zobacz README w `$OMARCHY_PATH/shell/plugins/agents/`, aby poznać pełne ustawienia.

### Kilka subskrypcji

Jeśli płacisz za więcej niż jeden plan Claude, Codex lub Grok — na przykład osobisty Max i służbowy — Omarchy może utrzymywać wszystkie zalogowane i przechodzić między nimi. Dodaj subskrypcję za pomocą + w panelu agentów, który przeprowadzi Cię przez to na miejscu, lub za pomocą `omarchy agent account add claude Work` (lub `codex`, lub `grok`). Instaluje CLI, jeśli go brakuje. Pierwsze konto u danego dostawcy loguje się przez Twoją normalną przeglądarkę, dokładnie tam, gdzie CLI zawsze zagląda. Każde kolejne loguje się przez okno prywatne, aby konto, do którego Twoja przeglądarka jest już zalogowana, nie zostało wybrane przez pomyłkę; zaloguj się tam jako konto, które dodajesz, i najpierw zamknij wszystkie okna prywatne, które masz już otwarte. Nigdy w tym celu nie wylogowuj się z CLI: wylogowanie unieważnia zapisane logowanie, a to konto trzeba by dodać ponownie.

Aby skopiować logowania subskrypcji na inną maszynę z Omarchy przez SSH, uruchom `omarchy agent account copy user@laptop`. Nadawca dostarcza tymczasowy odbiornik, gdy maszyna docelowa nie ma zainstalowanego żadnego, więc starsze maszyny z Omarchy mogą odbierać konta bez aktualizacji. Zainstalowane odbiorniki mają pierwszeństwo. Kopiuje to wszystkie subskrypcje Claude, Codex i Grok; dodaj nazwy dostawców, aby je wybrać, jak w `omarchy agent account copy laptop claude`. Nazwy kont i identyfikatory poleceń zgadzają się ze źródłem, w tym konta już obecne na maszynie docelowej. Niepowiązane konta docelowe otrzymują sufiks numeryczny, jeśli ich nazwy są w konflikcie, a ustawienia, skille, wtyczki i historia rozmów pozostają lokalne dla każdej maszyny.

Istniejące dane uwierzytelniające na maszynie docelowej są zachowywane. Konto źródłowe już tam zalogowane ma zsynchronizowaną nazwę bez zastępowania jego danych uwierzytelniających; pozostałe konta są dodawane obok niego. Aby zastąpić zapisane dane uwierzytelniające dla pasujących kont, użyj `omarchy agent account copy --replace laptop claude` po zamknięciu sesji tego konta na maszynie docelowej. Świeża maszyna docelowa otrzymuje też aktywne konto źródłowe i preferencje przełączania; ugruntowana maszyna docelowa zachowuje własne.

Dane uwierzytelniające podróżują przez SSH i są przechowywane w prywatnych plikach na maszynie docelowej, więc kopiuj je tylko na maszyny, którym ufasz. Jest to jednorazowe kopiowanie, a nie bieżąca synchronizacja. Tokeny odświeżania Codex mogą zostać zrotowane przez inną maszynę, co pozostawi skopiowane logowanie wymagające odnowienia; osobne logowania pozostają najbardziej niezawodnym wyborem przy jednoczesnym użytkowaniu na kilku maszynach. Zobacz [przewodnik Codex na temat uwierzytelniania kont](https://developers.openai.com/codex/auth/ci-cd-auth).

Aktywne jest jedno konto na dostawcę i każda nowa sesja zaczyna się jako ono: `cx`, `cy`, zwykły `claude`, `codex` lub `grok`, wszystko uruchamiane przez `omarchy agent` oraz skrypty lub edytory, które znajdują CLI w `PATH`. Przełączaj za pomocą `omarchy agent account use work` (i z powrotem za pomocą `omarchy agent account use main`) lub w panelu, naciskając numer konta, a następnie `Enter` (lub klikając jego przycisk Use). Sesje, które już działają, pozostają na koncie, na którym się zaczęły. Historia rozmów, ustawienia, skille i wtyczki są współdzielone między kontami, więc `claude --continue` w tym samym folderze podejmuje pracę tam, gdzie ją przerwałeś na nowym koncie.

Przy więcej niż jednym koncie panel pokazuje limity każdego konta obok siebie, z zaznaczonym aktywnym. Domyślnie Omarchy powiadamia Cię, gdy aktywne konto przekroczy 95% limitu, a kliknięcie powiadomienia przełącza na konto z największym zapasem. Najedź na linię konta w panelu i kliknij Autoswitch, który pojawia się obok Use (lub naciśnij `m`), albo uruchom `omarchy agent account mode auto`, aby przełączało się samo; gdy jest włączone, Autoswitch zajmuje miejsce Use, a kliknięcie go ponownie wraca do powiadamiania. Dodaj liczbę, aby zmienić próg, jak w `omarchy agent account mode auto 90`. Jeśli każde konto przekracza próg, usłyszysz o tym raz, wraz z informacją, które konto zwolni się jako pierwsze. Gdy aktywne konto znajduje się w odległości 15 punktów od swojego progu (80% przy ustawieniu domyślnym), jego limity są sprawdzane co trzy minuty, a nie co 15.

`omarchy agent account list` pokazuje każde konto i jego najnowsze limity, `omarchy agent account remove work` zapomina jedno, a `omarchy agent account rename primary Hey` zmienia nazwę jednego (lub kliknij nazwę konta w panelu). Polecenia te działają na kontach Twojego domyślnego agenta; aby sięgnąć innego dostawcy, najpierw go nazwij, jak w `omarchy agent account use codex side`. Logowanie, które już miałeś w `~/.claude` lub `~/.codex`, to konto _Main_ i pozostaje tam, gdzie jest. Konto nieużywane przez więcej niż około osiem godzin może pokazywać _Sign-in required_; kliknij je, aby ponownie zalogować to konto bezpośrednio w panelu, lub rozpocznij w nim sesję, co samo odświeży logowanie. Serwery MCP, które miałeś, gdy konto zostało dodane, przechodzą wraz z nim, ale te, które dodasz później za pomocą `claude mcp add`, docierają tylko do konta, w którym je dodałeś. Claude Desktop i narzędzia skonfigurowane bezwzględną ścieżką do pliku binarnego CLI nie podążają za przełączeniem. Jawne `CLAUDE_CONFIG_DIR`, `CODEX_HOME` lub `GROK_HOME` ma pierwszeństwo przed wybranym kontem.

### Diagnozowanie awarii

Omarchy obserwuje systemd-coredump pod kątem awarii procesów. Gdy coś ulegnie segfaultowi, otrzymasz powiadomienie „Process crashed” — kliknij je, a awaria zostanie przekazana Twojemu domyślnemu agentowi wraz ze skillem diagnose-crash Omarchy, który przeprowadza agenta przez ustalenie faktów na podstawie zrzutu pamięci i podjęcie decyzji, czy awarię warto zgłosić upstream. Możesz też uruchomić go ręcznie względem dowolnego PID z `coredumpctl list` za pomocą `omarchy agent crash <pid>`.

Obserwowanie jest domyślnie włączone. Wyłącz je w _Trigger > Toggle > Crash Capture_ (lub za pomocą `omarchy toggle crash-capture`), a powiadomienia ustaną; `omarchy agent crash <pid>` nadal działa ręcznie.

Awarie można też wyciszać po jednym programie naraz, co diagnoza oferuje Ci na końcu. `omarchy crash mute hyprland` zatrzymuje powiadomienia tylko dla tego programu, `omarchy crash mute hyprland off` przywraca je, a samo `omarchy crash mute` wypisuje to, co wyciszyłeś. Tak samo chętnie przyjmuje ścieżkę pliku binarnego jak jego nazwę, więc `omarchy crash mute /usr/bin/hyprland` robi to samo. Ujmij w cudzysłów nazwę ze spacją, jak w `omarchy crash mute 'Some App'`. Wszystko inne nadal powiadamia, a wyciszony program nadal ulega awarii — ukrywa to przypomnienie, nie naprawia niczego.

### Aplikacje desktopowe

Menu _Install > AI_ zawiera też kilka graficznych aplikacji AI: aplikację desktopową ChatGPT, aplikację desktopową Claude (beta Anthropic na Linuksa, z kartami Chat, Cowork i Claude Code), Grok Bot do czatowania z modelami xAI, Hermes Desktop, OpenClaw, aplikację desktopową Perplexity oraz T3 Code. Grok Bot to desktopowa aplikacja do czatu. Agentem do kodowania jest polecenie `grok`.

Hermes Desktop to ta, o której warto wiedzieć, ponieważ maszyna ma jeden Hermes i należy on do aplikacji: Hermes jest instalowany wyłącznie przez aplikację, a polecenie `hermes`, które uruchamia domyślny agent, należy do aplikacji. Wybranie Hermes jako domyślnego agenta instaluje to samo, co pozycja _Install > AI_: pakiet oraz środowisko uruchomieniowe Hermes w `~/.hermes`, skonfigurowane przez własny instalator Hermes, co za pierwszym razem zajmuje kilka minut. To środowisko uruchomieniowe jest tym jedynym Hermes, którego używają terminalowe polecenie `hermes`, domyślny agent i aplikacja, i aktualizuje się samo za pomocą `hermes update`, zamiast czekać na wydanie Omarchy. Zainstalowanie go przekazuje też Hermes motyw Omarchy jako skórkę o nazwie `omarchy`, za którą podąża każda powierzchnia Hermes, gdy zmieniasz motywy; wybierz inną w ustawieniach Appearance Hermes lub za pomocą `/skin`, jeśli wolisz, żeby tak nie było, a Omarchy zostawi ten wybór w spokoju. Usunięcie aplikacji w _Remove > AI_ najpierw zamyka Hermes, wraz z bramą, zabiera ze sobą to środowisko uruchomieniowe i zachowuje Twoje czaty, wspomnienia oraz skille, które Hermes napisał dla siebie, chyba że powiesz inaczej: pyta, z domyślną odpowiedzią nie, czy te dane i Twoje ustawienia połączeń też powinny zniknąć.

Doświadczeniem desktopowym OpenClaw jest jego Control UI, które otwiera się jako aplikacja webowa wspierana przez własną lokalną bramę. OpenClaw mieszka w `~/.openclaw` i aktualizuje się samo: użyj przycisku „Update Gateway” w Control UI lub uruchom `openclaw update`, a brama uruchomi się ponownie na nowej wersji. Omarchy wybiera jedynie wydanie, od którego zaczyna świeża instalacja. Usunięcie OpenClaw w _Remove > AI_ zabiera ze sobą usługę bramy i aplikację, a następnie pyta, czy `~/.openclaw` też powinno zniknąć, ponieważ przechowuje Twoje czaty i dane uwierzytelniające wraz z samym OpenClaw i pobieranymi przez niego środowiskami uruchomieniowymi wtyczek; domyślnie je zachowuje, a ponowna instalacja OpenClaw podejmuje je z powrotem.

T3 Code działa z oficjalnego wydania AppImage w `~/.local/share/t3code`, a nie z pakietu, więc aktualizuje się samo. Zainstalowanie go pyta, czy zacząć na kanale Stable czy Nightly; przełącz później w ustawieniach T3 Code. Twoje wątki i ustawienia mieszkają w `~/.t3`, a usunięcie T3 Code w _Remove > AI_ zabiera je ze sobą.

### Modele lokalne

Uruchom otwarty model na własnej maszynie dla swoich agentów do kodowania. Twoje prompty i kod pozostają na maszynie; nic wysyłanego do modelu jej nie opuszcza. Zacznij od:

```bash
omarchy agent local use best
```

Albo w panelu agentów na górnym pasku wybierz + a następnie Local AI, które pojawia się, gdy model pasuje do tej maszyny. Za pierwszym razem instaluje to Podman, który uruchamia modele, a na maszynie NVIDIA — zestaw narzędzi kontenerowych NVIDIA, który daje im GPU. Następnie Omarchy wybiera zalecany model dla tej maszyny, pobiera go i uruchamia. Spodziewaj się pobrania dziesiątek GB oraz tego, że większość pamięci maszyny będzie w użyciu, gdy model działa: Flash Next używa około 100 GiB przy pełnym kontekście 256K. Jeśli inne modele zajmują potrzebną mu pamięć, jest konfigurowany jako zatrzymany, gotowy do uruchomienia, gdy zatrzymasz jeden z nich. Model zatrzymuje się przy wylogowaniu; zatrzymaj go sam, gdy potrzebujesz pamięci do czegoś innego.

`omarchy agent local list` pokazuje opcje i wyjaśnia, dlaczego niektóre nie pasują. Aby skonfigurować inny, uruchom `omarchy agent local use <recipe>`. Dziś `qwen3.8-flash-next-gufo` i `qwen3.8-27b-gufo` są dostępne dla maszyn Strix Halo ze 128 GB; 27B zajmuje około 40 GiB, więc zostawia miejsce na inną pracę. Nowe receptury i zalecenia przychodzą wraz z `omarchy update`, przez pakiet.

Każdy skonfigurowany przez Ciebie model otrzymuje własną linię w panelu agentów, obok Twoich subskrypcji: play, aby go uruchomić, pause, aby go zatrzymać i zwolnić jego pamięć, oraz przycisk terminala, aby otworzyć na nim swojego agenta. Kilka może działać naraz, gdy razem mieszczą się w pamięci; jeśli jeden się nie mieści, Omarchy mówi, który działający model zatrzymać. Przeciągaj linie, aby zmienić ich kolejność, i naciśnij Delete na wybranej linii, aby usunąć model i jego pobrane pliki.

Z linii poleceń `omarchy agent local start <recipe>` i `omarchy agent local stop <recipe>` robią to samo, `omarchy agent local status` pokazuje każdy model, a `omarchy agent --local` otwiera Twojego domyślnego agenta na ostatnim uruchomionym przez Ciebie modelu (pi, jeśli Twój domyślny agent nie może używać modelu lokalnego). Każdy klient zgodny z OpenAI również może się połączyć: `status` pokazuje adres każdego modelu (pierwszy to `http://127.0.0.1:11435/v1`), nazwa receptury jest modelem, a klucz znajduje się w `~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` usuwa model oraz pobrane pliki, których nie używa żaden inny model.

Środowiska uruchomieniowe firm trzecich są oznaczane ich wydawcą. Omarchy uruchamia każdy model bez dostępu do sieci.

### Lokalne LLM-y

Omarchy zaleca dwa sposoby uruchamiania lokalnych modeli LLM: LM Studio i Ollama. LM Studio zapewnia interfejs GUI do znajdowania modeli o otwartych wagach, instalowania ich i uruchamiania. To świetny sposób, aby łatwo zacząć. Ollama oferuje CLI do robienia tego w podobny sposób. Ale jeśli dopiero zaczynasz przygodę z modelami lokalnymi, zacząłbym od LM Studio. Możesz zainstalować którekolwiek z nich w _Install > AI_ w menu Omarchy.

### Skill Omarchy

Skille agentów pomagają AI używać określonych narzędzi w określony sposób, a Omarchy jest dostarczane z domyślnym skillem do dostosowywania systemu. Takim jak poprawianie konfiguracji Hyprland, dostosowywanie paska czy nawet tworzenie nowego motywu od zera. Jest dowiązany symbolicznie do katalogów skilli dla Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` oraz każdego `~/.hermes/profiles/*/skills`) i ogólnej lokalizacji `~/.agents/skills`, więc większość harnessów wychwytuje go automatycznie.

Ale powinieneś traktować ten skill jako eksperymentalny. Różne modele będą używać go z różnym skutkiem. Najlepiej najpierw uruchomić go w trybie planu, abyś miał pojęcie, co agent chciałby zmienić. A potem bądź gotowy do wycofania zmian, a nawet wywołania `omarchy reinstall configs`, jeśli agent narobi bałaganu we wszystkim.
