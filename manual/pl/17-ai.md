# AI

Omarchy zawiera launchery dla poniższych agentów do kodowania, nie wybierając za Ciebie domyślnego. Uruchom polecenie, aby przy pierwszym użyciu zainstalować jego CLI, a następnie uwierzytelnij się, gdy pojawi się monit. Hermes i OpenClaw są wyjątkami: nic nie jest dla nich instalowane przez mise, a wybranie któregoś z nich konfiguruje jego własną, samouaktualniającą się kopię, jak wyjaśnia sekcja _Desktop apps_ poniżej.

### Instalowanie i aktualizowanie agentów

Z wyjątkiem Hermes i OpenClaw, ci agenci korzystają z leniwej instalacji mise: pierwsze uruchomienie instaluje CLI, a kolejne uruchomienia używają go ponownie. mise sprawdza również, czy zainstalowany agent ma nową wersję, nie częściej niż raz na cztery godziny, tuż przed jego uruchomieniem lub w tle przy promptcie powłoki. Jeśli ta aktualizacja się nie powiedzie lub jesteś offline, uruchamia się zainstalowana wersja. `omarchy update` aktualizuje zainstalowanych agentów wraz z resztą Omarchy, a `mup` aktualizuje tylko narzędzia zarządzane przez mise.

Własny aktualizator agenta, taki jak `claude update`, `codex update` lub przycisk aktualizacji w aplikacji, nie aktualizuje instalacji zarządzanej przez mise. `codex update` kończy się niepowodzeniem, a `claude update` może zgłosić sukces, instalując przy tym osobną kopię, której mise nie śledzi. Jeśli wolisz używać natywnego instalatora i aktualizatora agenta, dodaj go do `disable_tools`; zobacz [Wstępnie zainstalowane narzędzia CLI](18-development-tools.md#preinstalled-cli-tools).

Aby zainstalować wszystkie skonfigurowane leniwe narzędzia, zanim będą Ci potrzebne, uruchom `mise install --include-lazy`. Obejmuje to także pozostałe domyślne narzędzia CLI Omarchy, jak i agentów. Zobacz [Wstępnie zainstalowane narzędzia CLI](18-development-tools.md#preinstalled-cli-tools), aby dowiedzieć się o instalowaniu pojedynczego narzędzia lub używaniu własnej instalacji.

`grok` jest instalowany przez pakiet `grok` pierwszej strony mise, w ten sam sposób co `claude` i `codex`. Uruchom `grok` lub oznacz go gwiazdką w panelu agentów. Pomiń instalator `curl | bash` na x.ai. Ta ścieżka umieszcza drugą kopię w `~/.grok/bin`, dodaje ją na początku `PATH` i nadpisuje wrapper Omarchy.

`dsh` otwiera swój interfejs przeglądarkowy pod adresem `127.0.0.1:3080`, z katalogiem uruchomienia jako domyślnym obszarem roboczym. Jego interfejs przeglądarkowy nie przyjmuje początkowego promptu, więc `omarchy agent prompt` otwiera go z promptem w schowku do wklejenia. Omarchy uruchamia go z presetem uprawnień bez zatwierdzania DeepSeek. DeepSeek Harness przesyła logi sesji do DeepSeek, gdy korzystasz z jego oficjalnego API modeli; wyłącz to w jego interfejsie przeglądarkowym w _Settings > General > Upload Session Log_. Opinie, które mu wysyłasz, są również przesyłane wraz z sesją, chyba że uruchomisz go z `DSH_TELEMETRY_MODE=DISABLED`.

### Domyślny agent

Wybierz swojego domyślnego agenta gwiazdką obok agenta w panelu agentów, która jest wypełniona przy domyślnym, lub poleceniem `omarchy default agent <name>`, które przyjmuje także dowolny harness bez wiersza w tym miejscu. Jeśli agent nie jest jeszcze zainstalowany, wybranie go najpierw go instaluje, a także otrzymuje własny launcher w launcherze aplikacji, obok Agent. Świeże Omarchy zaprasza Cię do skonfigurowania jednego z nich jednorazowym powiadomieniem, które otwiera panel agentów.

Wybranie Claude próbuje również skonfigurować jego rozszerzenie przeglądarkowe dla Chromium, Chrome, Brave, Brave Origin i Edge. Konfiguracja rozszerzenia dotyczy wszystkich użytkowników i może poprosić o hasło systemowe; anulowanie lub nieudana instalacja rozszerzenia nadal wybiera i uruchamia Claude. Uruchom ponownie przeglądarkę, włącz rozszerzenie, jeśli pojawi się monit, i zaloguj się do Claude, aby dokończyć łączenie. Uruchom `/chrome` w Claude, aby sprawdzić połączenie. Firefox i Zen nie obsługują tego rozszerzenia. Jeśli Claude był już Twoim domyślnym agentem, zanim dodano tę konfigurację, wybierz go ponownie, aby zainstalować rozszerzenie.

Gdy już wybierzesz, `Super + Shift + Ctrl + A` uruchamia domyślnego agenta w dedykowanym oknie terminala (lub wywołuje selektor, jeśli jeszcze nie wybrałeś). Możesz też uruchomić go od razu do zadania poleceniem `omarchy agent prompt "Review this project"`. Freebuff i DeepSeek Harness nie przyjmują początkowego promptu, więc otwierają się z promptem w schowku do wklejenia. Agenci uruchamiani w ten sposób działają bez nadzoru w swoich trybach „nie zatrzymuj się, aby pytać”, więc bądź gotowy, że naprawdę będą coś robić! MiniMax Code nie ma takiego trybu dla swoich interaktywnych sesji, więc pyta o uprawnienia jak zwykle. A ponieważ agenci odmawiają zapamiętania zaufania dla Twojego katalogu domowego, uruchomienia z `$HOME` rozpoczynają się zamiast tego w `~/Work`.

Istnieją też skróty terminalowe: `a` uruchamia domyślnego agenta inline w bieżącym terminalu, a `c`, `cx` i `cy` uruchamiają bezpośrednio OpenCode, Claude Code i Codex (ponownie w ich trybach automatycznego zatwierdzania). Zmiany motywu synchronizują się również z agentami: Claude Code, Pi, OpenCode i Hermes (gdy Omarchy go zainstaluje) podążają za Tobą, gdy przełączasz motyw Omarchy.

### Twoje instrukcje dla agentów

Osobiste reguły dla każdego agenta znajdują się w `~/.agents/AGENTS.md`, obok współdzielonych umiejętności w `~/.agents/skills`. Otwórz je ikoną dokumentu obok + w panelu agentów lub poleceniem `omarchy agent instructions --edit`, które linkuje je również do każdego harnessu, który przechowuje własny plik globalny: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` Copilot i tak dalej. Crush i Amp odczytują link `~/.config/AGENTS.md`, a omp, Kimi i DeepSeek Harness odczytują bezpośrednio `~/.agents/AGENTS.md`. Wybranie domyślnego agenta również je linkuje. Plik instrukcji, który już miałeś, staje się współdzielonym, jeśli jeszcze go nie było; w przeciwnym razie jest przechowywany obok linku jako `.bak`. Uruchom `omarchy agent instructions`, aby ponownie zlinkować po zainstalowaniu kolejnego agenta.

### Panel agentów

Górny pasek ma ikonę agentów. Zanim skonfigurujesz agenta, jego panel oferuje trzy sposoby rozpoczęcia: zaloguj się do subskrypcji Claude, Codex, Grok, Gemini, Muse, Cursor lub Copilot, albo w sekcji More do planu kodowania OpenCode Go, MiniMax, Synthetic lub Z.ai; płać na bieżąco z Fireworks, OpenCode Zen i Go, OpenRouter, albo w sekcji More z DeepSeek lub dowolnym innym dostawcą, do którego loguje się OpenCode — wszystkie działają w OpenCode; albo uruchom najlepszy model dla swojego komputera, gdy jakiś do niego pasuje. Pierwszy, który ukończysz, staje się Twoim domyślnym agentem, a + w panelu lub _Agent > Add_ w Omarchy Menu oferuje te same trzy opcje później. Potem panel umieszcza każdą subskrypcję na jednej stronie: każdego agenta i konto wraz z jego planem, wskaźnik dla każdego z jego limitów 5-godzinnej sesji i tygodniowego wraz z czasem do resetu (najedź, aby zobaczyć dokładną wartość procentową) lub pozostałe saldo przedpłacone, pod wierszem, który rotuje przez to, czego użyłeś we wszystkich z nich, jak tokeny w tym tygodniu i Twój najczęściej używany model. W sekcji _Make something cool_ oferuje prompty startowe dla nowego motywu, wtyczki, aplikacji lub gry, które przekazują zadanie Twojemu domyślnemu agentowi. Aplikacje są budowane tak, jak własne Hype, Monologue i Omacut Omarchy, w C++ i Qt Quick, zgodnie z umiejętnością agenta omarchy-make-app, a kompilator i elementy Qt, których potrzebują, są zainstalowane. Gry to pojedyncza strona three.js w `~/Games/vibes`, zgodna z umiejętnością agenta omarchy-make-game, a wszystkie otwierają się z jednego launchera Game Vibes w bieżącym motywie; ładują three.js z sieci, więc do uruchomienia potrzebują połączenia. Claude Code, Codex, Grok, Kimi, Cursor i jego przydział Grok Bot, GitHub Copilot, Muse, Gemini (przez Antigravity) i Devin są obsługiwane od razu wraz z ich limitami, Kimchi ze swoim planem, kredytami przedpłaconymi i budżetami wydatków, a Hermes, Mistral Vibe i Qwen Code pokazują swoje sesje i tokeny, gdy już ich użyjesz. Plany i klucze dostawców, których używasz przez pi, omp lub opencode, również się pojawiają: OpenCode Zen i Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan i Synthetic wraz z ich limitami; OpenRouter i DeepSeek wraz z ich saldami przedpłaconymi; Fireworks wraz z wydatkami z ostatnich 30 dni. Tokeny z modeli, które uruchamiasz na własnym sprzęcie, również wliczają się do sum; same modele mają własny panel, opisany w sekcji [Modele lokalne](#local-models). Każdy agent jest liczony raz, pod tym, kto go rozlicza, niezależnie od tego, przez ile harnessów go prowadzisz.

Kliknij lewym przyciskiem ikonę na pasku lub naciśnij `Super + Ctrl + X`, aby otworzyć panel, kliknij prawym, aby uruchomić domyślnego agenta, a środkowym, aby odświeżyć. Rekordy użycia za nim stojące są regenerowane co 15 minut przez `omarchy agent usage update`, a panel może nawet łączyć użycie z innych Twoich maszyn przez zsynchronizowany folder. Zobacz README w `$OMARCHY_PATH/shell/plugins/agents/`, aby poznać pełne ustawienia.

### Kilka subskrypcji

Jeśli płacisz za więcej niż jeden plan Claude, Codex lub Grok — na przykład osobisty Max i służbowy — Omarchy może utrzymywać je wszystkie zalogowane i przełączać się między nimi. Dodaj subskrypcję za pomocą + w panelu agentów, który przeprowadzi Cię przez to na miejscu, lub poleceniem `omarchy agent account add claude Work` (lub `codex`, lub `grok`). Ten sam + i polecenie logują do Gemini (`gemini`) i OpenCode (`opencode`) oraz zapisują klucz API Fireworks (`fireworks`) lub OpenRouter (`openrouter`) w OpenCode; polecenie loguje również do Copilot (`copilot`), Cursor (`cursor`) i Muse (`muse`). Te zachowują po jednym zalogowaniu każde. Instaluje CLI, jeśli go brakuje. Pierwsze konto dostawcy loguje się przez Twoją normalną przeglądarkę, dokładnie tam, gdzie CLI zawsze patrzy. Każde kolejne loguje się przez okno prywatne, aby konto, do którego Twoja przeglądarka jest już zalogowana, nie zostało wybrane przez pomyłkę; zaloguj się tam jako konto, które dodajesz, i najpierw zamknij każde okno prywatne, które już miałeś otwarte. Nigdy nie wylogowuj się z CLI, aby to zrobić: wylogowanie unieważnia zapisane logowanie, a to konto trzeba by dodać ponownie.

Aby skopiować logowania subskrypcji na inną maszynę Omarchy przez SSH, uruchom `omarchy agent account copy user@laptop`. Nadawca dostarcza tymczasowy odbiornik, gdy miejsce docelowe nie ma zainstalowanego, więc starsze maszyny Omarchy mogą odbierać konta bez aktualizacji. Zainstalowane odbiorniki mają pierwszeństwo. Kopiuje to wszystkie subskrypcje Claude, Codex i Grok; dodaj nazwy dostawców, aby je wybrać, jak w `omarchy agent account copy laptop claude`. Nazwy kont i identyfikatory poleceń odpowiadają źródłu, w tym konta już obecne w miejscu docelowym. Niepowiązane konta docelowe otrzymują przyrostek numeryczny, jeśli ich nazwy są w konflikcie, a ustawienia, umiejętności, wtyczki i historia rozmów pozostają lokalne dla każdej maszyny.

Istniejące dane uwierzytelniające w miejscu docelowym są zachowywane. Konto źródłowe już tam zalogowane ma zsynchronizowaną nazwę bez zastępowania jego danych uwierzytelniających; inne konta są dodawane obok niego. Aby zastąpić zapisane dane uwierzytelniające dla pasujących kont, użyj `omarchy agent account copy --replace laptop claude` po zakończeniu sesji tego konta w miejscu docelowym. Świeże miejsce docelowe otrzymuje również aktywne konto źródłowe i preferencje przełączania; ustalone miejsce docelowe zachowuje własne.

Dane uwierzytelniające podróżują przez SSH i są przechowywane w prywatnych plikach w miejscu docelowym, więc kopiuj tylko na maszyny, którym ufasz. To jednorazowa kopia, nie ciągła synchronizacja. Tokeny odświeżania Codex mogą zostać zrotowane przez inną maszynę, pozostawiając skopiowane logowanie wymagające odnowienia; osobne logowania pozostają najbardziej niezawodnym wyborem do jednoczesnego użycia na kilku maszynach. Zobacz [wskazówki Codex dotyczące uwierzytelniania konta](https://developers.openai.com/codex/auth/ci-cd-auth).

Jedno konto na dostawcę jest aktywne, a każda nowa sesja zaczyna się jako ono: `cx`, `cy`, zwykłe `claude`, `codex` lub `grok`, wszystko uruchomione przez `omarchy agent` oraz skrypty lub edytory, które znajdują CLI na `PATH`. Przełączaj poleceniem `omarchy agent account use work` (i z powrotem poleceniem `omarchy agent account use main`) lub w panelu, naciskając numer konta, a następnie `Enter` (lub klikając jego gwiazdkę). Działające sesje Claude również się przełączają, od ich następnej wiadomości: każda sesja Claude działa w `~/.claude`, które zawsze przechowuje logowanie aktywnego konta. Sesja Claude uruchomiona we własnym folderze konta przez starsze Omarchy przechowuje to logowanie, dopóki się nie zakończy, więc przełączenie nazywa te sesje i kończy się samo, gdy znikną. Działające sesje Codex i Grok pozostają na koncie, z którym się rozpoczęły. Historia rozmów, ustawienia, umiejętności i wtyczki są współdzielone między kontami, więc `claude --continue` w tym samym folderze podejmuje pracę tam, gdzie ją zostawiłeś na nowym koncie.

Przy więcej niż jednym koncie panel pokazuje limity każdego konta obok siebie, z wypełnioną gwiazdką przy używanym. Omarchy powiadamia Cię, gdy aktywne konto przekroczy 95% limitu, a kliknięcie powiadomienia przełącza na konto z największym zapasem. Nigdy nie przełącza się samo. Zmień próg poleceniem `omarchy agent account threshold 90`. Jeśli każde konto przekracza próg, usłyszysz o tym raz, wraz z informacją, które konto zwolni się jako pierwsze. Gdy aktywne konto znajduje się w granicach 15 punktów od swojego progu (80% przy ustawieniu domyślnym), jego limity są sprawdzane co trzy minuty, a nie co 15.

`omarchy agent account list` pokazuje każde konto i jego najnowsze limity, `omarchy agent account remove work` zapomina jedno, a `omarchy agent account rename primary Hey` zmienia nazwę jednego (lub kliknij nazwę konta w panelu). Te polecenia działają na kontach Twojego domyślnego agenta; aby dotrzeć do innego dostawcy, najpierw go nazwij, jak w `omarchy agent account use codex side`. Logowanie, które już miałeś w `~/.claude` lub `~/.codex`, to konto _Main_. Konto Codex pozostaje tam, gdzie jest; konto Claude czeka we własnym folderze, gdy inne konto jest aktywne. Konto nieużywane przez ponad około osiem godzin może pokazywać _Sign-in required_; kliknij je, aby ponownie zalogować to konto bezpośrednio w panelu, lub przełącz się na nie i rozpocznij sesję, co samo odświeża logowanie. Serwery MCP, które dodajesz poleceniem `claude mcp add`, docierają do każdego konta Claude, ponieważ wszystkie działają w `~/.claude`; w przypadku Codex i Grok serwery, które miałeś, gdy konto zostało dodane, przechodzą wraz z nim, ale późniejsze docierają tylko do konta, w którym je dodałeś. Claude Desktop przechowuje własne logowanie, a narzędzia Codex lub Grok skonfigurowane bezwzględną ścieżką do pliku binarnego CLI nie podążają za przełączeniem. Jawne `CLAUDE_CONFIG_DIR`, `CODEX_HOME` lub `GROK_HOME` ma pierwszeństwo przed wybranym kontem.

### Diagnostyka awarii

Omarchy obserwuje systemd-coredump pod kątem awarii procesów. Gdy wybierzesz domyślnego agenta, każdy Twój program, który zrzuca core, wywołuje powiadomienie "Process crashed" — kliknij je, a awaria zostanie przekazana Twojemu domyślnemu agentowi wraz z umiejętnością omarchy-diagnose-crash Omarchy, która prowadzi agenta przez ustalenie faktów ze zrzutu core i zdecydowanie, czy awarię warto zgłosić upstream. Możesz też uruchomić ją ręcznie przeciwko dowolnemu PID z `coredumpctl list` poleceniem `omarchy agent crash <pid>`.

Obserwowanie jest domyślnie włączone. Wyłącz je w _Trigger > Toggle > Crash Capture Off_ (lub poleceniem `omarchy toggle crash-capture`), a powiadomienia ustaną; `omarchy agent crash <pid>` nadal działa ręcznie.

Awarie można również wyciszać program po programie, co diagnoza oferuje Ci na końcu. `omarchy crash mute hyprland` zatrzymuje powiadomienia tylko dla tego programu, `omarchy crash mute hyprland off` przywraca je, a samo `omarchy crash mute` listuje to, co wyciszyłeś. Przyjmuje ścieżkę pliku binarnego równie chętnie jak jego nazwę, więc `omarchy crash mute /usr/bin/hyprland` robi to samo. Ujmij nazwę ze spacją w cudzysłów, jak w `omarchy crash mute 'Some App'`. Wszystko inne nadal powiadamia, a wyciszony program nadal ulega awarii — to ukrywa przypomnienie, niczego nie naprawia.

### Aplikacje desktopowe

Menu _Install > AI_ zawiera również kilka graficznych aplikacji AI: Amp Desktop, Antigravity Desktop, aplikację desktopową ChatGPT, aplikację desktopową Claude (beta Anthropic na Linux, z kartami Chat, Cowork i Claude Code), Grok Bot do czatowania z modelami xAI, Herdr Desktop, Hermes Desktop, OpenClaw, aplikację desktopową Perplexity i T3 Code. Grok Bot to desktopowa aplikacja do czatu. Agentem do kodowania jest polecenie `grok`.

Hermes Desktop to ta, o której warto wiedzieć, ponieważ maszyna ma jeden Hermes i należy on do aplikacji: Hermes jest instalowany wyłącznie przez aplikację, a polecenie `hermes`, które uruchamia domyślny agent, należy do aplikacji. Wybranie Hermes jako domyślnego agenta instaluje to samo, co wpis _Install > AI_: pakiet oraz środowisko uruchomieniowe Hermes w `~/.hermes` skonfigurowane przez własny instalator Hermes, co za pierwszym razem zajmuje kilka minut. To środowisko uruchomieniowe to ten jeden Hermes, którego używają polecenie terminalowe `hermes`, domyślny agent i aplikacja, i aktualizuje się samo poleceniem `hermes update`, zamiast czekać na wydanie Omarchy. Zainstalowanie go daje również Hermes motyw Omarchy jako skórkę o nazwie `omarchy`, za którą podąża każda powierzchnia Hermes, gdy przełączasz motywy; wybierz inną w ustawieniach Appearance Hermes lub poleceniem `/skin`, jeśli wolisz, aby tak nie było, a Omarchy zostawi ten wybór w spokoju. Usunięcie aplikacji w _Remove > AI_ najpierw zamyka Hermes, w tym bramkę, zabiera ze sobą to środowisko uruchomieniowe i zachowuje Twoje czaty, wspomnienia oraz umiejętności, które Hermes napisał dla siebie, chyba że powiesz inaczej: pyta, domyślnie odpowiadając nie, czy te dane i Twoje ustawienia połączenia również mają zniknąć.

Doświadczeniem desktopowym OpenClaw jest jego Control UI, które otwiera się jako aplikacja internetowa wspierana przez własną lokalną bramkę. OpenClaw mieszka w `~/.openclaw` i aktualizuje się sam: użyj przycisku "Update Gateway" Control UI lub uruchom `openclaw update`, a bramka uruchomi się ponownie na nowej wersji. Omarchy wybiera jedynie wydanie, od którego zaczyna świeża instalacja. OpenClaw może być również Twoim domyślnym agentem: wybranie go w _Agent > Harness_ konfiguruje tę samą kopię w `~/.openclaw`, a agent otwiera interfejs terminala OpenClaw podłączony do jego bramki. Usunięcie OpenClaw w _Remove > AI_ zabiera ze sobą usługę bramki i aplikację, a następnie pyta, czy `~/.openclaw` również ma zniknąć, ponieważ przechowuje Twoje czaty i dane uwierzytelniające obok samego OpenClaw i środowisk uruchomieniowych wtyczek, które pobiera; domyślnie je zachowuje, a ponowne zainstalowanie OpenClaw je przywraca.

Herdr Desktop to aplikacja desktopowa [Herdr](https://herdr.dev): przestrzenie, karty i panele terminali i agentów do kodowania, które nadal działają w jego rdzeniu, gdy zamkniesz okno. Pochodzi z własnego instalatora Herdr, a nie z pakietu, więc mieszka w `~/.local/share/herdr-app`, przynosi ze sobą swój rdzeń w `~/.local/bin/herdr-core`, gdy jeszcze go nie masz, i aktualizuje oba sama. Siedzi obok polecenia `herdr`, które Omarchy dostarcza na `Super + Ctrl + Return`, zamiast je zastępować, i otrzymuje bezpośrednie klawisze tego polecenia: `Alt + Return` i `Alt + Shift + Return` dzielą panel w dół lub w prawo, `Alt + Escape` go zamyka, `Ctrl + Alt + Arrow` porusza się między panelami, `Alt + 1..9` i `Alt + Left/Right` wybierają kartę, a `Alt + Up/Down` poruszają się między przestrzeniami. `Ctrl + 1..9` wybiera przestrzeń, a `Alt + Shift + Up/Down` przechodzi przez agentów. Klawisze prefiksu `Ctrl + Space` pozostają tylko dla terminala, ponieważ aplikacja nie może przytrzymać zwykłego klawisza Ctrl dla sekwencji. Omarchy zapisuje je do `~/.config/herdr-app/keys.json`, a `omarchy-refresh-herdr-app` je przywraca. Zainstalowanie go wybiera motyw Omarchy Herdr, który od tej pory podąża za Twoim motywem Omarchy. Herdr przechowuje jeden motyw dla trybu jasnego i jeden dla ciemnego, więc po przełączeniu między ciemnym a jasnym motywem Omarchy ponownie wybierz Omarchy w selektorze motywów Herdr dla drugiego trybu.

T3 Code działa ze swojego oficjalnego wydania AppImage w `~/.local/share/t3code`, a nie z pakietu, więc aktualizuje się sam. Zainstalowanie go pyta, czy zacząć na kanale Stable czy Nightly; przełącz później w ustawieniach T3 Code. Twoje wątki i ustawienia mieszkają w `~/.t3`, a usunięcie T3 Code w _Remove > AI_ zabiera je ze sobą.

### Modele lokalne

Uruchom otwarty model na własnej maszynie dla swoich agentów do kodowania. Twoje prompty i kod pozostają na maszynie; nic wysłanego do modelu jej nie opuszcza. Zacznij od:

```bash
omarchy models use best text
```

To konfiguruje najlepszy model tekstowy dla tej maszyny, taki, jakiego używają Twoi agenci. Modele obrazów, wideo i muzyki mają swoje własne najlepsze: `omarchy models use best image`, `video` lub `music`. Uruchom `omarchy models use best`, aby zobaczyć wybór każdego rodzaju dla tej maszyny.

Albo otwórz panel modeli lokalnych z jego ikony iskier na górnym pasku, obok ikony agentów, lub za pomocą Super + Ctrl + Alt + X, i wybierz +. Ikona pojawia się, gdy model pasuje do tej maszyny. Podman, który uruchamia modele, jest dostarczany z Omarchy, podobnie jak zestaw narzędzi kontenerowych NVIDIA na maszynie NVIDIA, który daje im GPU; jeśli któregoś brakuje, pierwsza konfiguracja go instaluje. Omarchy następnie wybiera zalecany model dla tej maszyny, pobiera go i uruchamia. Spodziewaj się pobrania dziesiątek GB i zajęcia większości pamięci maszyny podczas działania modelu: Flash Next używa około 100 GiB przy pełnym kontekście 256K. Jeśli inne modele zajmują potrzebną mu pamięć, jest konfigurowany jako zatrzymany, gotowy do uruchomienia, gdy zatrzymasz jeden z nich. Model zatrzymuje się przy wylogowaniu; zatrzymaj go sam, gdy potrzebujesz pamięci do czegoś innego.

`omarchy models list` pokazuje opcje i wyjaśnia, dlaczego niektóre nie pasują. Aby skonfigurować inny, uruchom `omarchy models use <recipe>`. Dziś `qwen3.8-flash-next-gufo` i `qwen3.8-27b-gufo` są dostępne dla maszyn Strix Halo 128 GB; 27B zajmuje około 40 GiB, więc zostawia miejsce na inną pracę. Na laptopie 64 GB z Intel Arc B390, `qwen3.6-35b-a3b-llamacpp` działa w około 30 GiB. Nowe przepisy i rekomendacje przychodzą z `omarchy update`, przez pakiet.

Każdy model, który skonfigurujesz, otrzymuje własny wiersz w panelu modeli lokalnych: play, aby go uruchomić, pause, aby go zatrzymać i zwolnić jego pamięć, oraz przycisk terminala, aby otworzyć na nim swojego agenta. U góry pasek pokazuje, jak pamięć maszyny jest podzielona między samo Omarchy (system i Twoje aplikacje), każdy działający model i to, co jest wolne. Wskaż zatrzymany model, a pasek pokaże, czy pasuje, czy o ile mu brakuje. Kilka może działać jednocześnie, gdy razem mieszczą się w pamięci; jeśli jeden nie pasuje, Omarchy mówi, który działający model zatrzymać. Przeciągaj wiersze za ich logo, aby zmienić ich kolejność, i naciśnij Delete na wybranym wierszu, aby usunąć model i jego pobrane pliki.

Każdy model do kodowania, który skonfigurujesz, otrzymuje również własny wpis w launcherze aplikacji, pod nazwą modelu i z logo jego twórcy, tak jak zalogowanie się do Claude, Codex lub Grok dodaje taki wpis. Otwiera Twojego agenta na tym modelu i najpierw uruchamia model, jeśli nie działa: terminal pokazuje jego ładowanie i przekazuje kontrolę agentowi, gdy już działa. Usunięcie modelu usuwa jego wpis.

Nie każdy model jest do kodowania. Modele obrazów, wideo i muzyki otwierają się zamiast tego w Fantasi, aplikacji Omarchy do tworzenia obrazów, wideo i muzyki za pomocą modelu działającego na tej maszynie, wybranego tam lub z ich wiersza w panelu modeli lokalnych.

Model nadal działa dokładnie tak, jak został skonfigurowany, więc aktualizacja Omarchy nigdy nie uruchamia go ponownie pod Twoimi agentami. Gdy Omarchy ma nowsze środowisko uruchomieniowe lub nowsze wagi dla modelu, który skonfigurowałeś, jego wiersz pokazuje przycisk aktualizacji: naciśnij go, a model zostanie ponownie skonfigurowany w tle, pobierając tylko to, co się zmieniło, i uruchomi się ponownie na nowej wersji. Model, który był zatrzymany, pozostaje zatrzymany. `omarchy models update` robi to samo dla każdego modelu z terminala.

Z wiersza poleceń `omarchy models start <recipe>` i `omarchy models stop <recipe>` robią to samo, `omarchy models status` pokazuje każdy model, a `omarchy agent --local-model <recipe>` otwiera ten model w pi, niezależnie od tego, jaki jest Twój domyślny agent. Aby uczynić swój model lokalny tym, co otwierają skrót klawiszowy agenta, konsola Quake i _Make something_, uruchom `omarchy default agent local` lub wybierz _Local model_ w _Agent > Harness_. pi wymienia również każdy model, który skonfigurowałeś, oraz te na maszynach, z którymi się sparowałeś, we własnym selektorze modeli, więc zwykłe `pi` również do nich dociera. Każdy klient zgodny z OpenAI również może się połączyć: `status` pokazuje adres każdego modelu (pierwszy to `http://127.0.0.1:11435/v1`), nazwa przepisu to model, a klucz znajduje się w `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` usuwa model i pobrane pliki, których żaden inny model nie używa.

Środowiska uruchomieniowe stron trzecich są oznaczone ich wydawcą. Omarchy uruchamia każdy model bez dostępu do sieci.

### Lokalne modele LLM

Omarchy poleca dwa sposoby uruchamiania lokalnych modeli LLM: LM Studio i Ollama. LM Studio zapewnia interfejs GUI do znajdowania modeli o otwartych wagach, instalowania ich i uruchamiania. To świetny sposób, aby łatwo zacząć. Ollama oferuje CLI do robienia tego w podobny sposób. Ale jeśli dopiero zaczynasz z modelami lokalnymi, zacząłbym od LM Studio. Możesz zainstalować którykolwiek z nich w _Install > AI_ w Omarchy Menu.

### Umiejętności Omarchy

Umiejętności agentów pomagają AI używać konkretnych narzędzi w konkretny sposób, a Omarchy dostarcza siedem z nich. Umiejętność omarchy obejmuje dostosowywanie systemu, jak modyfikowanie konfiguracji Hyprland lub dostosowywanie paska. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app i omarchy-make-game obejmują tworzenie czegoś nowego, omarchy-contribute obejmuje zgłaszanie błędu lub wysyłanie poprawki upstream, a omarchy-diagnose-crash przechodzi przez zrzut core awarii. Są one linkowane symbolicznie do katalogów umiejętności dla Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` i każdego `~/.hermes/profiles/*/skills`) oraz ogólnej lokalizacji `~/.agents/skills`, więc większość harnessów wykrywa je automatycznie. Twój własny folder umiejętności o tej samej nazwie ma pierwszeństwo.

Ale powinieneś traktować te umiejętności jako eksperymentalne. Różne modele będą z nich korzystać z różnym skutkiem. Najlepiej najpierw działać w trybie planowania, aby mieć pojęcie, co agent chciałby zmienić. A potem bądź gotowy wycofać zmiany lub nawet wywołać `omarchy reinstall configs`, jeśli agent narobi bałaganu we wszystkim.
