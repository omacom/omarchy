# AI

Omarchy zawiera programy uruchamiające dla poniższych agentów kodujących, ale nie wybiera za ciebie domyślnego. Uruchom polecenie, aby przy pierwszym użyciu zainstalować jego CLI, a potem uwierzytelnij się, gdy pojawi się taki monit. Hermes jest wyjątkiem: przy pierwszym użyciu nic nie jest dla niego instalowane, a wybranie go instaluje Hermes Desktop, jak wyjaśnia sekcja _Aplikacje desktopowe_ poniżej.

### Instalowanie i aktualizowanie agentów

Z wyjątkiem Hermesa ci agenci korzystają z leniwej instalacji mise: pierwsze uruchomienie instaluje CLI, a późniejsze uruchomienia używają go ponownie. mise sprawdza też, co najwyżej raz na cztery godziny, czy zainstalowany agent ma nowe wydanie, tuż przed jego uruchomieniem albo w tle przy znaku zachęty powłoki. Jeśli ta aktualizacja się nie powiedzie albo jesteś offline, działa zainstalowana wersja. `omarchy update` aktualizuje zainstalowanych agentów wraz z resztą Omarchy, a `mup` aktualizuje tylko narzędzia zarządzane przez mise.

Własny aktualizator agenta, taki jak `claude update`, `codex update` albo przycisk aktualizacji w aplikacji, nie aktualizuje instalacji zarządzanej przez mise. `codex update` kończy się niepowodzeniem, a `claude update` może zgłosić sukces, instalując jednocześnie osobną kopię, której mise nie śledzi. Jeśli wolisz używać natywnego instalatora i aktualizatora agenta, dodaj go do `disable_tools`; zobacz [Preinstalowane narzędzia CLI](18-development-tools.md#preinstalled-cli-tools).

Aby zainstalować wszystkie skonfigurowane leniwe narzędzia, zanim będą ci potrzebne, uruchom `mise install --include-lazy`. Obejmuje to także inne domyślne narzędzia CLI Omarchy oraz agentów. Zobacz [Preinstalowane narzędzia CLI](18-development-tools.md#preinstalled-cli-tools), aby dowiedzieć się, jak zainstalować jedno narzędzie albo używać własnej instalacji.

`grok` jest instalowany przez pierwszoosobowy pakiet `grok` mise, w taki sam sposób jak `claude` i `codex`. Uruchom `grok` albo wybierz go w _Setup > Defaults > Agent_. Pomiń instalator `curl | bash` na x.ai. Ta ścieżka umieszcza drugą kopię w `~/.grok/bin`, dopisuje ją na początku `PATH` i nadpisuje wrapper Omarchy.

`dsh` otwiera swój interfejs przeglądarkowy pod `127.0.0.1:3080`, z katalogiem uruchomienia jako domyślnym obszarem roboczym. Jego interfejs przeglądarkowy nie przyjmuje początkowego promptu, więc `omarchy agent prompt` otwiera go z promptem w schowku, gotowym do wklejenia. Omarchy uruchamia go z presetem uprawnień bez zatwierdzania od DeepSeek. DeepSeek Harness przesyła logi sesji do DeepSeek, gdy używasz jego oficjalnego API modeli; wyłącz to w jego interfejsie przeglądarkowym w _Settings > General > Upload Session Log_. Opinie, które mu wysyłasz, też są przesyłane wraz z sesją, chyba że uruchomisz go z `DSH_TELEMETRY_MODE=DISABLED`.

### Domyślny agent

Wybierz domyślnego agenta poleceniem `omarchy default agent <name>` albo w _Setup > Defaults > Agent_ w menu Omarchy (`Super + Space`). Jeśli agent nie jest jeszcze zainstalowany, wybranie go najpierw go zainstaluje. Świeże Omarchy zaprosi cię do dokonania tego wyboru jednorazowym powiadomieniem.

Wybranie Claude próbuje też skonfigurować jego rozszerzenie przeglądarkowe dla Chromium, Chrome, Brave, Brave Origin i Edge. Konfiguracja rozszerzenia dotyczy wszystkich użytkowników i może poprosić o twoje hasło systemowe; anulowanie albo nieudana instalacja rozszerzenia nadal wybiera i uruchamia Claude. Uruchom ponownie przeglądarkę, włącz rozszerzenie, jeśli pojawi się taki monit, i zaloguj się do Claude, aby dokończyć łączenie. Uruchom `/chrome` w Claude, aby sprawdzić połączenie. Firefox i Zen nie obsługują tego rozszerzenia. Jeśli Claude był już twoim domyślnym agentem, zanim dodano tę konfigurację, wybierz go ponownie, aby zainstalować rozszerzenie.

Gdy już wybierzesz, `Super + Shift + Ctrl + A` uruchamia domyślnego agenta w dedykowanym oknie terminala (albo przywołuje selektor, jeśli jeszcze nie wybrałeś). Możesz też uruchomić go od razu do zadania poleceniem `omarchy agent prompt "Review this project"`. Freebuff i DeepSeek Harness nie przyjmują początkowego promptu, więc zamiast tego otwierają się z promptem w schowku, gotowym do wklejenia. Tak uruchomieni agenci działają bez nadzoru w swoich trybach, w których nie zatrzymują się, aby pytać, więc bądź gotowy na to, że naprawdę zaczną działać! MiniMax Code nie ma takiego trybu dla swoich interaktywnych sesji, więc pyta o uprawnienia jak zwykle. A ponieważ agenci odmawiają zapamiętania zaufania dla twojego katalogu domowego, uruchomienia z `$HOME` startują zamiast tego w `~/Work`.

Są też skróty terminalowe: `a` uruchamia domyślnego agenta w bieżącym terminalu, a `c`, `cx` i `cy` uruchamiają bezpośrednio OpenCode, Claude Code i Codex (ponownie w ich trybach automatycznego zatwierdzania). Zmiany motywu synchronizują się też z agentami: Claude Code, Pi, OpenCode i Hermes (gdy Omarchy go zainstaluje) podążają za tobą, gdy przełączasz motyw Omarchy.

### Panel agentów

Górny pasek ma ikonę agentów. Zanim skonfigurujesz agenta, jej panel przeprowadzi cię przez logowanie do Claude, Codex lub Grok, a pierwszy z nich stanie się twoim domyślnym agentem. Potem panel umieszcza każdą subskrypcję na jednej stronie: każdy agent i konto ze swoim planem, miernik dla każdego z jego 5-godzinnych limitów sesji i limitów tygodniowych wraz z czasem do resetu (najedź, aby zobaczyć dokładną wartość procentową) albo pozostałe przedpłacone saldo, pod wierszem, który rotuje przez to, czego użyłeś u nich wszystkich, jak tokeny w tym tygodniu i twój najczęściej używany model. W sekcji _Make something_ oferuje prompty startowe dla nowego motywu, wtyczki lub aplikacji, które przekazują zadanie twojemu domyślnemu agentowi. Aplikacje są budowane tak, jak własne aplikacje Omarchy Hype, Monologue i Omacut, w C++ i Qt Quick, zgodnie z umiejętnością agenta omarchy-app, a kompilator i elementy Qt, których potrzebują, są zainstalowane. Claude Code, Codex, Grok, Kimi, Cursor i jego pula Grok Bot, GitHub Copilot, Muse, Antigravity, Kimchi i Devin są obsługiwane od razu wraz ze swoimi limitami, a Hermes, Mistral Vibe i Qwen Code pokazują swoje sesje i tokeny, gdy już ich użyjesz. Plany dostawców i klucze, których używasz przez pi, omp lub opencode, też się pojawiają: OpenCode Zen i Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan i Synthetic wraz ze swoimi limitami; Fireworks, OpenRouter i DeepSeek wraz ze swoimi przedpłaconymi saldami; oraz modele, które uruchamiasz na własnym sprzęcie, w sekcji Local models. Każdy agent jest liczony raz, u tego, kto go rozlicza, bez względu na to, przez ile harnessów go prowadzisz.

Kliknij ikonę na pasku lewym przyciskiem myszy, aby otworzyć panel, prawym przyciskiem, aby uruchomić domyślnego agenta. Rekordy użycia stojące za panelem są regenerowane co 15 minut przez `omarchy agent usage-update`, a panel potrafi nawet łączyć użycie z twoich innych maszyn przez zsynchronizowany folder. Zobacz README w `$OMARCHY_PATH/shell/plugins/agents/`, aby poznać pełne ustawienia.

### Kilka subskrypcji

Jeśli płacisz za więcej niż jeden plan Claude, Codex lub Grok — na przykład osobisty Max i służbowy — Omarchy może utrzymywać je wszystkie zalogowane i przechodzić między nimi. Dodaj subskrypcję przyciskiem + w panelu agentów, który przeprowadzi cię przez to na miejscu, albo poleceniem `omarchy agent account add claude Work` (lub `codex`, lub `grok`). Zainstaluje CLI, jeśli go brakuje. Pierwsze konto dla dostawcy loguje się przez twoją normalną przeglądarkę, dokładnie tam, gdzie CLI zawsze patrzy. Każde kolejne loguje się przez okno prywatne, więc konto, do którego twoja przeglądarka jest już zalogowana, nie zostanie omyłkowo przechwycone; zaloguj się tam jako konto, które dodajesz, i najpierw zamknij każde okno prywatne, które masz już otwarte. Nigdy nie wylogowuj się z CLI, aby to zrobić: wylogowanie unieważnia zapisane logowanie, a to konto trzeba by dodać ponownie.

Aby skopiować logowania subskrypcji na inną maszynę Omarchy przez SSH, uruchom `omarchy agent account copy user@laptop`. Nadawca dostarcza tymczasowy odbiornik, gdy maszyna docelowa nie ma zainstalowanego żadnego, więc starsze maszyny Omarchy mogą odbierać konta bez aktualizacji. Zainstalowane odbiorniki mają pierwszeństwo. Kopiuje to wszystkie subskrypcje Claude, Codex i Grok; dodaj nazwy dostawców, aby je wybrać, jak w `omarchy agent account copy laptop claude`. Nazwy kont i identyfikatory poleceń zgadzają się ze źródłem, łącznie z kontami już obecnymi na maszynie docelowej. Niepowiązane konta docelowe dostają liczbowy przyrostek, jeśli ich nazwy kolidują, a ustawienia, umiejętności, wtyczki i historia rozmów pozostają lokalne dla każdej maszyny.

Istniejące dane uwierzytelniające na maszynie docelowej są zachowywane. Konto źródłowe już tam zalogowane ma zsynchronizowaną nazwę bez zastępowania swoich danych uwierzytelniających; inne konta są dodawane obok niego. Aby zastąpić zapisane dane uwierzytelniające dla pasujących kont, użyj `omarchy agent account copy --replace laptop claude` po zamknięciu sesji tego konta na maszynie docelowej. Świeża maszyna docelowa dostaje też aktywne konto i preferencje przełączania ze źródła; ugruntowana maszyna docelowa zachowuje własne.

Dane uwierzytelniające podróżują przez SSH i są przechowywane w prywatnych plikach na maszynie docelowej, więc kopiuj tylko na maszyny, którym ufasz. To jednorazowa kopia, nie bieżąca synchronizacja. Tokeny odświeżania Codex mogą zostać zrotowane przez inną maszynę, przez co skopiowane logowanie będzie wymagało odnowienia; osobne logowania pozostają najbardziej niezawodnym wyborem przy jednoczesnym użyciu na kilku maszynach. Zobacz [przewodnik Codex dotyczący uwierzytelniania kont](https://developers.openai.com/codex/auth/ci-cd-auth).

Jedno konto na dostawcę jest aktywne, a każda nowa sesja zaczyna jako ono: `cx`, `cy`, zwykłe `claude`, `codex` lub `grok`, wszystko uruchomione przez `omarchy agent` oraz skrypty i edytory, które znajdują CLI na `PATH`. Przełączaj poleceniem `omarchy agent account use work` (i z powrotem poleceniem `omarchy agent account use main`) albo w panelu, naciskając numer konta, a potem `Enter` (lub klikając jego przycisk Use). Sesje, które już działają, pozostają na koncie, z którym wystartowały. Historia rozmów, ustawienia, umiejętności i wtyczki są współdzielone między kontami, więc `claude --continue` w tym samym folderze podejmuje pracę tam, gdzie ją zostawiłeś na nowym koncie.

Gdy masz więcej niż jedno konto, panel pokazuje limity każdego konta obok siebie, z zaznaczonym aktywnym. Domyślnie Omarchy powiadamia cię, gdy aktywne konto przekroczy 95% limitu, a kliknięcie powiadomienia przełącza na konto z największą rezerwą. Najedź na wiersz konta w panelu i kliknij Autoswitch, który pojawia się obok Use (lub naciśnij `m`), albo uruchom `omarchy agent account mode auto`, aby przełączało się samo; gdy jest włączone, Autoswitch zajmuje miejsce Use, a ponowne kliknięcie wraca do powiadamiania. Dodaj liczbę, aby zmienić próg, jak w `omarchy agent account mode auto 90`. Jeśli każde konto przekracza próg, usłyszysz o tym raz, wraz z informacją, które konto zwolni się jako pierwsze. Gdy aktywne konto znajduje się w granicach 15 punktów od swojego progu (80% przy ustawieniu domyślnym), jego limity są sprawdzane co trzy minuty zamiast co 15.

`omarchy agent account list` pokazuje każde konto i jego najnowsze limity, `omarchy agent account remove work` zapomina jedno, a `omarchy agent account rename primary Hey` zmienia nazwę jednego (lub kliknij nazwę konta w panelu). Te polecenia działają na kontach twojego domyślnego agenta; aby dotrzeć do innego dostawcy, najpierw go nazwij, jak w `omarchy agent account use codex side`. Logowanie, które już miałeś w `~/.claude` lub `~/.codex`, jest kontem _Main_ i pozostaje tam, gdzie jest. Konto nieużywane przez więcej niż około osiem godzin może pokazać _Sign-in required_; kliknij je, aby zalogować to konto ponownie bezpośrednio w panelu, albo rozpocznij w nim sesję, co samo odświeża logowanie. Serwery MCP, które miałeś, gdy konto zostało dodane, przechodzą do niego, ale te, które dodasz później poleceniem `claude mcp add`, docierają tylko do konta, w którym je dodałeś. Claude Desktop i narzędzia skonfigurowane bezwzględną ścieżką do pliku binarnego CLI nie podążają za przełączeniem. Jawne `CLAUDE_CONFIG_DIR`, `CODEX_HOME` lub `GROK_HOME` ma pierwszeństwo przed wybranym kontem.

### Diagnoza awarii

Omarchy obserwuje systemd-coredump pod kątem awarii procesów. Gdy coś ulegnie błędowi segmentacji, dostaniesz powiadomienie „Process crashed” — kliknij je, a awaria zostanie przekazana twojemu domyślnemu agentowi wraz z umiejętnością diagnose-crash Omarchy, która prowadzi agenta przez ustalenie faktów ze zrzutu pamięci i podjęcie decyzji, czy awarię warto zgłosić upstream. Możesz też uruchomić ją ręcznie dla dowolnego PID z `coredumpctl list` poleceniem `omarchy agent crash <pid>`.

Obserwowanie jest domyślnie włączone. Wyłącz je w _Trigger > Toggle > Crash Capture_ (albo poleceniem `omarchy toggle crash-capture`), a powiadomienia ustaną; `omarchy agent crash <pid>` nadal działa ręcznie.

Awarie można też wyciszać po jednym programie naraz, co diagnoza oferuje ci na końcu. `omarchy crash mute hyprland` zatrzymuje powiadomienia tylko dla tego programu, `omarchy crash mute hyprland off` przywraca je, a samo `omarchy crash mute` wypisuje to, co wyciszyłeś. Przyjmuje ścieżkę pliku binarnego równie chętnie jak jego nazwę, więc `omarchy crash mute /usr/bin/hyprland` robi to samo. Ujmij nazwę ze spacją w cudzysłów, jak w `omarchy crash mute 'Some App'`. Wszystko inne nadal powiadamia, a wyciszony program nadal ulega awarii — to ukrywa przypomnienie, niczego nie naprawia.

### Aplikacje desktopowe

Menu _Install > AI_ zawiera też kilka graficznych aplikacji AI: aplikację desktopową ChatGPT, aplikację desktopową Claude (beta Anthropic na Linux, z kartami Chat, Cowork i Claude Code), Grok Bot do czatowania z modelami xAI, Hermes Desktop, OpenClaw, aplikację desktopową Perplexity i T3 Code. Grok Bot jest aplikacją desktopową do czatu. Agent kodujący to polecenie `grok`.

Hermes Desktop jest tą aplikacją, o której warto wiedzieć, bo maszyna ma jednego Hermesa i należy on do aplikacji: Hermes jest instalowany wyłącznie przez aplikację, a polecenie `hermes`, które uruchamia domyślny agent, należy do aplikacji. Wybranie Hermesa jako domyślnego agenta instaluje to samo, co pozycja _Install > AI_: pakiet oraz środowisko uruchomieniowe Hermes w `~/.hermes` skonfigurowane przez własny instalator Hermesa, co za pierwszym razem zajmuje kilka minut. To środowisko uruchomieniowe jest tym jedynym Hermesem, którego używają terminalowe polecenie `hermes`, domyślny agent i aplikacja, i aktualizuje się samo poleceniem `hermes update`, zamiast czekać na wydanie Omarchy. Zainstalowanie go przekazuje też Hermesowi motyw Omarchy jako skórkę o nazwie `omarchy`, za którą podąża każda powierzchnia Hermesa, gdy przełączasz motywy; wybierz inną w ustawieniach Appearance Hermesa albo poleceniem `/skin`, jeśli wolisz, aby tak nie było, a Omarchy zostawi ten wybór w spokoju. Usunięcie aplikacji w _Remove > AI_ najpierw zamyka Hermesa, łącznie z bramką, zabiera ze sobą to środowisko uruchomieniowe i zachowuje twoje czaty, wspomnienia oraz umiejętności, które Hermes napisał dla siebie, chyba że powiesz mu inaczej: pyta, domyślnie odpowiadając nie, czy te dane i twoje ustawienia połączeń też mają zniknąć.

Doświadczeniem desktopowym OpenClaw jest jego Control UI, które otwiera się jako aplikacja internetowa wspierana przez własną lokalną bramkę. OpenClaw mieszka w `~/.openclaw` i aktualizuje się samo: użyj przycisku „Update Gateway” w Control UI albo uruchom `openclaw update`, a bramka uruchomi się ponownie na nowej wersji. Omarchy wybiera tylko wydanie, od którego zaczyna świeża instalacja. Usunięcie OpenClaw w _Remove > AI_ zabiera ze sobą usługę bramki i aplikację, a potem pyta, czy `~/.openclaw` też ma zniknąć, ponieważ przechowuje twoje czaty i dane uwierzytelniające obok samego OpenClaw i środowisk uruchomieniowych wtyczek, które pobiera; domyślnie je zachowuje, a ponowne zainstalowanie OpenClaw podejmuje je z powrotem.

T3 Code działa z oficjalnego wydania AppImage w `~/.local/share/t3code`, a nie z pakietu, więc aktualizuje się samo. Zainstalowanie go pyta, czy zacząć na kanale Stable czy Nightly; przełącz później w ustawieniach T3 Code. Twoje wątki i ustawienia mieszkają w `~/.t3`, a usunięcie T3 Code w _Remove > AI_ zabiera je ze sobą.

### Lokalne LLM-y

Omarchy poleca dwa sposoby uruchamiania lokalnych modeli LLM: LM Studio i Ollama. LM Studio zapewnia interfejs GUI do znajdowania modeli o otwartych wagach, instalowania ich i uruchamiania. To świetny sposób, aby łatwo zacząć. Ollama oferuje CLI do robienia tego podobnie. Ale jeśli dopiero zaczynasz z lokalnymi modelami, zacząłbym od LM Studio. Możesz zainstalować każde z nich w _Install > AI_ w menu Omarchy.

### Skill Omarchy

Umiejętności agentów pomagają AI używać konkretnych narzędzi w konkretny sposób, a Omarchy jest dostarczane z domyślną umiejętnością do dostosowywania systemu. Taką jak poprawianie konfiguracji Hyprland, regulowanie paska czy nawet tworzenie nowego motywu od zera. Jest dowiązana symbolicznie do katalogów umiejętności dla Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` i każdego `~/.hermes/profiles/*/skills`) oraz ogólnej lokalizacji `~/.agents/skills`, więc większość harnessów wychwytuje ją automatycznie.

Ale powinieneś traktować tę umiejętność jako eksperymentalną. Różne modele będą jej używać z różnym skutkiem. Najlepiej najpierw uruchomić ją w trybie planowania, abyś miał pojęcie, co agent chciałby zmienić. A potem bądź gotowy wycofać zmiany albo nawet wywołać `omarchy reinstall configs`, jeśli agent narobi we wszystkim bałaganu.
