# AI

Omarchy zawiera programy uruchamiające dla poniższych agentów kodujących, ale nie wybiera za ciebie domyślnego. Uruchom polecenie, aby przy pierwszym użyciu zainstalować jego CLI, a potem uwierzytelnij się, gdy pojawi się stosowny monit. Hermes jest wyjątkiem: przy pierwszym użyciu nic nie jest dla niego instalowane, a wybranie go instaluje Hermes Desktop, co wyjaśnia sekcja _Aplikacje pulpitu_ poniżej.

### Instalowanie i aktualizowanie agentów

Z wyjątkiem Hermes wszyscy ci agenci korzystają z leniwej instalacji mise: pierwsze uruchomienie instaluje CLI, a kolejne uruchomienia używają go ponownie. mise sprawdza też zainstalowanego agenta pod kątem nowej wersji co najwyżej raz na cztery godziny, tuż przed jego uruchomieniem lub w tle przy wierszu poleceń powłoki. Jeśli ta aktualizacja się nie powiedzie lub jesteś offline, uruchamia się zainstalowana wersja. `omarchy update` aktualizuje zainstalowanych agentów wraz z resztą Omarchy, a `mup` aktualizuje tylko narzędzia zarządzane przez mise.

Własny program aktualizujący agenta, taki jak `claude update`, `codex update` lub przycisk aktualizacji w aplikacji, nie aktualizuje instalacji zarządzanej przez mise. `codex update` kończy się niepowodzeniem, a `claude update` może zgłosić sukces, instalując przy tym osobną kopię, której mise nie śledzi. Jeśli wolisz używać natywnego instalatora i programu aktualizującego agenta, dodaj go do `disable_tools`; zobacz [Preinstalowane narzędzia CLI](18-development-tools.md#preinstalled-cli-tools).

Aby zainstalować wszystkie skonfigurowane leniwe narzędzia, zanim będą ci potrzebne, uruchom `mise install --include-lazy`. Obejmuje to pozostałe domyślne narzędzia CLI Omarchy, a także agentów. Zobacz [Preinstalowane narzędzia CLI](18-development-tools.md#preinstalled-cli-tools), aby dowiedzieć się, jak zainstalować pojedyncze narzędzie lub użyć własnej instalacji.

`grok` jest instalowany za pośrednictwem własnego pakietu `grok` mise, w ten sam sposób co `claude` i `codex`. Uruchom `grok` lub wybierz go w _Setup > Defaults > Agent_. Pomiń instalator `curl | bash` na x.ai. Ta ścieżka umieszcza drugą kopię w `~/.grok/bin`, dopisuje ją na początek `PATH` i nadpisuje wrapper Omarchy.

`dsh` otwiera swój interfejs w przeglądarce pod adresem `127.0.0.1:3080`, z katalogiem uruchomienia jako domyślnym obszarem roboczym. Jego interfejs w przeglądarce nie przyjmuje promptu startowego, więc `omarchy agent prompt` otwiera go z promptem w schowku, gotowym do wklejenia. Omarchy uruchamia go z presetem uprawnień DeepSeek bez zatwierdzania. DeepSeek Harness przesyła dzienniki sesji do DeepSeek, gdy korzystasz z jego oficjalnego API modeli; wyłącz to w jego interfejsie w przeglądarce w sekcji _Settings > General > Upload Session Log_. Informacje zwrotne, które mu wysyłasz, są przesyłane razem z sesją, chyba że uruchomisz go z `DSH_TELEMETRY_MODE=DISABLED`.

### Domyślny agent

Wybierz domyślnego agenta za pomocą `omarchy default agent <name>` lub w sekcji _Setup > Defaults > Agent_ w Menu Omarchy (`Super + Space`). Jeśli agent nie jest jeszcze zainstalowany, wybranie go najpierw go zainstaluje. Świeże Omarchy zaprosi cię do dokonania tego wyboru jednorazowym powiadomieniem.

Wybranie Claude próbuje również skonfigurować jego rozszerzenie przeglądarki dla Chromium, Chrome, Brave, Brave Origin i Edge. Konfiguracja rozszerzenia dotyczy wszystkich użytkowników i może poprosić o hasło systemowe; anulowanie lub nieudana instalacja rozszerzenia i tak wybiera i uruchamia Claude. Uruchom ponownie przeglądarkę, włącz rozszerzenie, jeśli pojawi się taki monit, i zaloguj się do Claude, aby dokończyć łączenie. Uruchom `/chrome` w Claude, aby sprawdzić połączenie. Firefox i Zen nie obsługują tego rozszerzenia. Jeśli Claude był już twoim domyślnym agentem, zanim dodano tę konfigurację, wybierz go ponownie, aby zainstalować rozszerzenie.

Po dokonaniu wyboru `Super + Shift + Ctrl + A` uruchamia domyślnego agenta w dedykowanym oknie terminala (lub wyświetla selektor, jeśli jeszcze nie dokonałeś wyboru). Możesz też uruchomić go od razu do zadania za pomocą `omarchy agent prompt "Review this project"`. Freebuff i DeepSeek Harness nie przyjmują promptu startowego, więc otwierają się z promptem w schowku, gotowym do wklejenia. Agenci uruchamiani w ten sposób działają bez nadzoru w swoich trybach „nie zatrzymuj się, żeby pytać”, więc bądź gotów na to, że naprawdę będą coś robić! MiniMax Code nie ma takiego trybu dla swoich sesji interaktywnych, więc pyta o uprawnienia jak zwykle. A ponieważ agenci odmawiają zapamiętania zaufania dla twojego katalogu domowego, uruchomienia z `$HOME` startują zamiast tego w `~/Work`.

Są też skróty terminalowe: `a` uruchamia domyślnego agenta w bieżącym terminalu, a `c`, `cx` i `cy` uruchamiają bezpośrednio OpenCode, Claude Code i Codex (ponownie w ich trybach automatycznego zatwierdzania). Zmiany motywu synchronizują się również z agentami: Claude Code, Pi, OpenCode i Hermes (gdy Omarchy go zainstaluje) podążają za tobą, gdy przełączasz motyw Omarchy.

### Panel agentów

Górny pasek ma ikonę agentów. Zanim skonfigurujesz agenta, jego panel prowadzi cię przez logowanie do Claude, Codex lub Grok, a pierwszy z nich staje się twoim domyślnym agentem. Potem panel umieszcza każdą subskrypcję na jednej stronie: każdego agenta i konto wraz z jego planem, wskaźnik dla każdego z jego limitów sesji 5-godzinnej i tygodniowego wraz z czasem do resetu (najedź, aby zobaczyć dokładny procent) lub pozostałe saldo przedpłacone, pod wierszem, który rotuje przez to, czego użyłeś we wszystkich z nich, na przykład tokeny w tym tygodniu i najczęściej używany model. W sekcji _Make something_ oferuje prompty startowe dla nowego motywu, wtyczki lub aplikacji, które przekazują zadanie twojemu domyślnemu agentowi. Aplikacje są budowane tak, jak własne aplikacje Omarchy Hype, Monologue i Omacut, w C++ i Qt Quick, zgodnie z umiejętnością agenta omarchy-app, a potrzebne im kompilator i elementy Qt są zainstalowane. Claude Code, Codex, Grok, Kimi, Cursor wraz z jego limitem Grok Bot, GitHub Copilot, Muse, Antigravity, Kimchi i Devin są obsługiwane od razu wraz ze swoimi limitami, a Hermes, Mistral Vibe i Qwen Code pokazują swoje sesje i tokeny, gdy już ich użyjesz. Plany i klucze dostawców, których używasz za pośrednictwem pi, omp lub opencode, również się pojawiają: OpenCode Zen i Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan i Synthetic wraz ze swoimi limitami; Fireworks, OpenRouter i DeepSeek ze swoimi saldami przedpłaconymi; oraz modele, które uruchamiasz na własnym sprzęcie, w sekcji Local models. Każdy agent jest liczony raz, u tego, kto go rozlicza, niezależnie od tego, przez ile harnessów go prowadzisz.

Kliknij lewym przyciskiem ikonę na pasku, aby otworzyć panel, a prawym, aby uruchomić domyślnego agenta. Rekordy użycia stojące za nim są regenerowane co 15 minut przez `omarchy agent usage-update`, a panel może nawet łączyć użycie z innych twoich maszyn za pośrednictwem zsynchronizowanego folderu. Zobacz README w `$OMARCHY_PATH/shell/plugins/agents/`, aby poznać pełne ustawienia.

### Wiele subskrypcji

Jeśli płacisz za więcej niż jeden plan Claude, Codex lub Grok — na przykład osobisty Max i służbowy — Omarchy może utrzymywać wszystkie zalogowane i przełączać się między nimi. Dodaj subskrypcję za pomocą + w panelu agentów, który prowadzi cię przez to na miejscu, lub za pomocą `omarchy agent account add claude Work` (lub `codex`, lub `grok`). Instaluje to CLI, jeśli go brakuje. Pierwsze konto dla dostawcy loguje się przez twoją normalną przeglądarkę, dokładnie tam, gdzie CLI zawsze szuka. Każde kolejne loguje się przez okno prywatne, aby konto, na które twoja przeglądarka jest już zalogowana, nie zostało wybrane przez pomyłkę; zaloguj się tam jako konto, które dodajesz, i najpierw zamknij każde okno prywatne, które miałeś już otwarte. Nigdy nie wylogowuj się z CLI, aby to zrobić: wylogowanie unieważnia zapisane logowanie, a to konto trzeba byłoby dodać ponownie.

Aby skopiować logowania subskrypcji na inną maszynę z Omarchy przez SSH, uruchom `omarchy agent account copy user@laptop`. Nadawca dostarcza tymczasowego odbiorcę, gdy miejsce docelowe nie ma zainstalowanego żadnego, więc starsze maszyny z Omarchy mogą przyjmować konta bez aktualizacji. Zainstalowani odbiorcy mają pierwszeństwo. Kopiuje to wszystkie subskrypcje Claude, Codex i Grok; dodaj nazwy dostawców, aby je wybrać, jak w `omarchy agent account copy laptop claude`. Nazwy kont i identyfikatory poleceń pasują do źródła, w tym konta już obecne w miejscu docelowym. Niepowiązane konta docelowe otrzymują przyrostek liczbowy, jeśli ich nazwy są sprzeczne, a ustawienia, umiejętności, wtyczki i historia rozmów pozostają lokalne dla każdej maszyny.

Istniejące poświadczenia docelowe są zachowywane. Konto źródłowe już zalogowane tam ma zsynchronizowaną nazwę bez zastępowania jego poświadczeń; inne konta są dodawane obok niego. Aby zastąpić zapisane poświadczenia dla pasujących kont, użyj `omarchy agent account copy --replace laptop claude` po zakończeniu sesji tego konta w miejscu docelowym. Świeże miejsce docelowe otrzymuje również aktywne konto źródłowe i preferencje przełączania; ustalone miejsce docelowe zachowuje własne.

Poświadczenia podróżują przez SSH i są przechowywane w prywatnych plikach w miejscu docelowym, więc kopiuj tylko na maszyny, którym ufasz. Jest to jednorazowa kopia, a nie bieżąca synchronizacja. Tokeny odświeżania Codex mogą zostać zrotowane przez inną maszynę, pozostawiając skopiowane logowanie wymagające odnowienia; osobne logowania pozostają najbardziej niezawodnym wyborem do jednoczesnego używania na kilku maszynach. Zobacz [Przewodnik Codex dotyczący uwierzytelniania konta](https://developers.openai.com/codex/auth/ci-cd-auth).

Jedno konto na dostawcę jest aktywne, a każda nowa sesja zaczyna się jako ono: `cx`, `cy`, zwykłe `claude`, `codex` lub `grok`, wszystko uruchamiane przez `omarchy agent` oraz skrypty lub edytory, które znajdują CLI w `PATH`. Przełączaj za pomocą `omarchy agent account use work` (i z powrotem za pomocą `omarchy agent account use main`) lub w panelu, naciskając numer konta, a następnie `Enter` (lub klikając jego przycisk Use). Sesje już działające pozostają na koncie, z którym się rozpoczęły. Historia rozmów, ustawienia, umiejętności i wtyczki są współdzielone między kontami, więc `claude --continue` w tym samym folderze podejmuje pracę tam, gdzie ją przerwałeś, na nowym koncie.

Przy więcej niż jednym koncie panel pokazuje limity każdego konta obok siebie, z zaznaczonym aktywnym. Domyślnie Omarchy powiadamia cię, gdy aktywne konto przekroczy 95% limitu, a kliknięcie powiadomienia przełącza na konto z największym zapasem. Najedź na wiersz konta w panelu i kliknij Autoswitch, które pojawia się obok Use (lub naciśnij `m`), albo uruchom `omarchy agent account mode auto`, aby przełączało się samodzielnie; gdy jest włączone, Autoswitch zajmuje miejsce Use, a ponowne kliknięcie wraca do powiadamiania. Dodaj liczbę, aby zmienić próg, jak w `omarchy agent account mode auto 90`. Jeśli każde konto przekroczy próg, usłyszysz o tym raz, wraz z informacją, które konto zwolni się pierwsze. Gdy aktywne konto jest w odległości 15 punktów od swojego progu (80% przy ustawieniu domyślnym), jego limity są sprawdzane co trzy minuty, a nie co 15.

`omarchy agent account list` pokazuje każde konto i jego najnowsze limity, `omarchy agent account remove work` zapomina jedno, a `omarchy agent account rename primary Hey` zmienia nazwę jednego (lub kliknij nazwę konta w panelu). Te polecenia działają na kontach twojego domyślnego agenta; aby dotrzeć do innego dostawcy, najpierw go nazwij, jak w `omarchy agent account use codex side`. Logowanie, które miałeś już w `~/.claude` lub `~/.codex`, to konto _Main_ i pozostaje tam, gdzie jest. Konto nieużywane przez ponad około osiem godzin może pokazywać _Sign-in required_; kliknij je, aby zalogować to konto ponownie bezpośrednio w panelu, lub rozpocznij w nim sesję, co samo odświeża logowanie. Serwery MCP, które miałeś, gdy konto zostało dodane, przechodzą wraz z nim, ale te dodane później za pomocą `claude mcp add` docierają tylko do konta, w którym je dodałeś. Claude Desktop i narzędzia skonfigurowane bezwzględną ścieżką do pliku binarnego CLI nie podążają za przełączeniem. Jawne `CLAUDE_CONFIG_DIR`, `CODEX_HOME` lub `GROK_HOME` ma pierwszeństwo przed wybranym kontem.

### Diagnostyka awarii

Omarchy obserwuje systemd-coredump pod kątem awarii procesów. Gdy coś ulegnie błędowi segmentacji, otrzymasz powiadomienie „Process crashed” — kliknij je, a awaria zostanie przekazana twojemu domyślnemu agentowi wraz z umiejętnością diagnose-crash Omarchy, która prowadzi agenta przez ustalenie faktów ze zrzutu pamięci i podjęcie decyzji, czy awarię warto zgłosić twórcom. Możesz też uruchomić to ręcznie dla dowolnego PID z `coredumpctl list` za pomocą `omarchy agent crash <pid>`.

Obserwowanie jest domyślnie włączone. Wyłącz je w _Trigger > Toggle > Crash Capture_ (lub za pomocą `omarchy toggle crash-capture`), a powiadomienia ustaną; `omarchy agent crash <pid>` nadal działa ręcznie.

Awarie można też wyciszać po jednym programie na raz, co właśnie oferuje ci diagnostyka na końcu. `omarchy crash mute hyprland` zatrzymuje powiadomienia tylko dla tego programu, `omarchy crash mute hyprland off` przywraca je, a samo `omarchy crash mute` wypisuje, co wyciszyłeś. Przyjmuje ścieżkę pliku binarnego równie chętnie jak jego nazwę, więc `omarchy crash mute /usr/bin/hyprland` robi to samo. Ujmij w cudzysłów nazwę zawierającą spację, jak w `omarchy crash mute 'Some App'`. Wszystko inne nadal powiadamia, a wyciszony program nadal ulega awarii — to ukrywa przypomnienie, niczego nie naprawia.

### Aplikacje pulpitu

Menu _Install > AI_ zawiera również kilka graficznych aplikacji AI: aplikację pulpitu ChatGPT, aplikację pulpitu Claude (beta Anthropic na Linuksa, z kartami Chat, Cowork i Claude Code), Grok Bot do czatowania z modelami xAI, Herdr Desktop, Hermes Desktop, OpenClaw, aplikację pulpitu Perplexity i T3 Code. Grok Bot to aplikacja czatu na pulpit. Agentem kodującym jest polecenie `grok`.

Hermes Desktop to ta, o której trzeba wiedzieć, ponieważ maszyna ma jednego Hermesa i należy on do aplikacji: Hermes jest instalowany wyłącznie przez aplikację, a polecenie `hermes`, które uruchamia domyślny agent, jest poleceniem aplikacji. Wybranie Hermesa jako domyślnego agenta instaluje to samo, co pozycja _Install > AI_: pakiet oraz środowisko uruchomieniowe Hermes w `~/.hermes` skonfigurowane przez własny instalator Hermesa, co za pierwszym razem zajmuje kilka minut. To środowisko uruchomieniowe jest tym jedynym Hermesem, którego używają terminalowe polecenie `hermes`, domyślny agent i aplikacja, i aktualizuje się samo za pomocą `hermes update`, zamiast czekać na wydanie Omarchy. Zainstalowanie go daje też Hermesowi motyw Omarchy jako skórkę o nazwie `omarchy`, za którą podąża każda powierzchnia Hermesa, gdy przełączasz motywy; wybierz inną w ustawieniach Appearance Hermesa lub za pomocą `/skin`, jeśli wolisz, aby tak nie było, a Omarchy zostawi ten wybór w spokoju. Usunięcie aplikacji w _Remove > AI_ najpierw zamyka Hermesa, w tym bramę, zabiera ze sobą to środowisko uruchomieniowe i zachowuje twoje czaty, wspomnienia oraz umiejętności, które Hermes napisał dla siebie, chyba że powiesz inaczej: pyta, przy domyślnej odpowiedzi „nie”, czy te dane i twoje ustawienia połączenia również mają zniknąć.

Doświadczeniem pulpitu OpenClaw jest jego Control UI, które otwiera się jako aplikacja internetowa wspierana przez własną lokalną bramę. OpenClaw mieszka w `~/.openclaw` i aktualizuje się sam: użyj przycisku „Update Gateway” w Control UI lub uruchom `openclaw update`, a brama uruchomi się ponownie na nowej wersji. Omarchy wybiera jedynie wydanie, od którego zaczyna świeża instalacja. Usunięcie OpenClaw w _Remove > AI_ zabiera ze sobą usługę bramy i aplikację, a następnie pyta, czy `~/.openclaw` również ma zniknąć, ponieważ przechowuje twoje czaty i poświadczenia obok samego OpenClaw i środowisk uruchomieniowych wtyczek, które pobiera; ustawienie domyślne zachowuje je, a ponowna instalacja OpenClaw podnosi je z powrotem.

Herdr Desktop to aplikacja pulpitu [Herdr](https://herdr.dev): przestrzenie, karty i panele terminali i agentów kodujących, które działają dalej w jej rdzeniu, gdy zamkniesz okno. Pochodzi z własnego instalatora Herdr, a nie z pakietu, więc mieszka w `~/.local/share/herdr-app`, przynosi ze sobą swój rdzeń w `~/.local/bin/herdr-core`, gdy nie masz jeszcze żadnego, i aktualizuje zarówno siebie, jak i jego. Znajduje się obok polecenia `herdr`, które Omarchy dostarcza na `Super + Ctrl + Return`, a nie je zastępuje, i otrzymuje bezpośrednie klawisze tego polecenia: `Alt + Return` i `Alt + Shift + Return` dzielą panel w dół lub w prawo, `Alt + Escape` zamyka go, `Ctrl + Alt + Arrow` porusza się między panelami, `Alt + 1..9` i `Alt + Left/Right` wybierają kartę, a `Alt + Up/Down` poruszają się między przestrzeniami. `Ctrl + 1..9` wybiera przestrzeń, a `Alt + Shift + Up/Down` przemieszcza się po agentach. Klawisze prefiksu `Ctrl + Space` pozostają tylko dla terminala, ponieważ aplikacja nie może przytrzymać zwykłego klawisza Ctrl dla sekwencji. Omarchy zapisuje je do `~/.config/herdr-app/keys.json`, a `omarchy-refresh-herdr-app` przywraca je. Zainstalowanie go wybiera motyw Omarchy Herdr, który od tego momentu podąża za twoim motywem Omarchy. Herdr przechowuje jeden motyw dla trybu jasnego i jeden dla ciemnego, więc po przełączeniu między ciemnym a jasnym motywem Omarchy wybierz Omarchy w selektorze motywów Herdr jeszcze raz dla drugiego trybu.

T3 Code działa z oficjalnego wydania AppImage w `~/.local/share/t3code`, a nie z pakietu, więc aktualizuje się sam. Instalowanie go pyta, czy zacząć od kanału Stable czy Nightly; przełącz później w ustawieniach T3 Code. Twoje wątki i ustawienia mieszkają w `~/.t3`, a usunięcie T3 Code w _Remove > AI_ zabiera je ze sobą.

### Modele lokalne

Uruchom otwarty model na własnej maszynie dla swoich agentów kodujących. Twoje prompty i kod pozostają na maszynie; nic wysłanego do modelu jej nie opuszcza. Zacznij od:

```bash
omarchy agent local use best
```

Albo w panelu agentów na górnym pasku wybierz +, a następnie Local AI, które pojawia się, gdy model pasuje do tej maszyny. Za pierwszym razem instaluje to Podman, który uruchamia modele, a na maszynie NVIDIA zestaw narzędzi kontenerowych NVIDIA, który daje im GPU. Omarchy następnie wybiera zalecany model dla tej maszyny, pobiera go i uruchamia. Spodziewaj się pobrania dziesiątek GB i zajęcia większości pamięci maszyny podczas działania modelu: Flash Next używa około 100 GiB przy pełnym kontekście 256K. Jeśli inne modele zajmują potrzebną mu pamięć, jest skonfigurowany jako zatrzymany, gotowy do uruchomienia, gdy zatrzymasz jeden z nich. Model zatrzymuje się przy wylogowaniu; zatrzymaj go sam, gdy potrzebujesz pamięci do czegoś innego.

`omarchy agent local list` pokazuje opcje i wyjaśnia, dlaczego niektóre nie pasują. Aby skonfigurować inny, uruchom `omarchy agent local use <recipe>`. Obecnie `qwen3.8-flash-next-gufo` i `qwen3.8-27b-gufo` są dostępne dla maszyn Strix Halo ze 128 GB; 27B zajmuje około 40 GiB, więc zostawia miejsce na inną pracę. Nowe przepisy i zalecenia przybywają wraz z `omarchy update`, za pośrednictwem pakietu.

Każdy skonfigurowany model otrzymuje własny wiersz w panelu agentów, obok twoich subskrypcji: przycisk odtwarzania, aby go uruchomić, przycisk pauzy, aby go zatrzymać i zwolnić jego pamięć, oraz przycisk terminala, aby otworzyć na nim swojego agenta. Kilka może działać jednocześnie, gdy razem mieszczą się w pamięci; jeśli jeden się nie mieści, Omarchy mówi, który działający model zatrzymać. Przeciągaj wiersze, aby zmieniać ich kolejność, i naciśnij Delete na wybranym wierszu, aby usunąć model i jego pobrane pliki.

Z wiersza poleceń `omarchy agent local start <recipe>` i `omarchy agent local stop <recipe>` robią to samo, `omarchy agent local status` pokazuje każdy model, a `omarchy agent --local` otwiera twojego domyślnego agenta na ostatnim uruchomionym modelu (pi, jeśli twój domyślny agent nie może używać lokalnego modelu). Każdy klient zgodny z OpenAI również może się połączyć: `status` pokazuje adres każdego modelu (pierwszy to `http://127.0.0.1:11435/v1`), nazwa przepisu jest modelem, a klucz znajduje się w `~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` usuwa model i pobrane pliki, których nie używa żaden inny model.

Środowiska uruchomieniowe firm trzecich są oznaczane swoim wydawcą. Omarchy uruchamia każdy model bez dostępu do sieci.

### Lokalne LLM

Omarchy zaleca dwa sposoby uruchamiania lokalnych modeli LLM: LM Studio i Ollama. LM Studio zapewnia interfejs GUI do znajdowania modeli o otwartych wagach, instalowania ich i uruchamiania. To świetny sposób, aby łatwo zacząć. Ollama oferuje CLI do robienia tego w podobny sposób. Ale jeśli dopiero zaczynasz z lokalnymi modelami, zacząłbym od LM Studio. Możesz zainstalować każde z nich w _Install > AI_ w Menu Omarchy.

### Umiejętność Omarchy

Umiejętności agentów pomagają AI używać konkretnych narzędzi w konkretny sposób, a Omarchy jest dostarczane z domyślną umiejętnością do dostosowywania systemu. Taką jak dostrajanie konfiguracji Hyprland, dostosowywanie paska czy nawet tworzenie nowego motywu od zera. Jest podlinkowana symbolicznie do katalogów umiejętności dla Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` i każdego `~/.hermes/profiles/*/skills`) oraz ogólnej lokalizacji `~/.agents/skills`, więc większość harnessów podnosi ją automatycznie.

Ale powinieneś traktować tę umiejętność jako eksperymentalną. Różne modele będą jej używać z różnym skutkiem. Najlepiej najpierw uruchomić ją w trybie planowania, abyś miał pojęcie, co agent chciałby zmienić. A potem bądź gotów wycofać zmiany lub nawet wywołać `omarchy reinstall configs`, jeśli agent narobi bałaganu we wszystkim.
