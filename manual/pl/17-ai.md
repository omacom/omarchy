# AI

Omarchy zawiera programy uruchamiające dla poniższych agentów do kodowania, nie wybierając za Ciebie domyślnego. Uruchom polecenie, aby przy pierwszym użyciu zainstalować jego CLI, a następnie uwierzytelnij się, gdy pojawi się monit. Hermes i OpenClaw są wyjątkami: w ich przypadku nic nie jest instalowane przez mise, a wybranie któregokolwiek z nich instaluje jego własną, samouaktualniającą się kopię, jak wyjaśnia sekcja _Aplikacje desktopowe_ poniżej.

### Instalowanie i aktualizowanie agentów

Z wyjątkiem Hermes i OpenClaw, ci agenci korzystają z leniwej instalacji mise: pierwsze uruchomienie instaluje CLI, a kolejne uruchomienia używają go ponownie. mise sprawdza też zainstalowanego agenta pod kątem nowej wersji co najwyżej raz na cztery godziny, tuż przed jego uruchomieniem lub w tle przy znaku zachęty powłoki. Jeśli ta aktualizacja się nie powiedzie lub jesteś offline, działa zainstalowana wersja. `omarchy update` aktualizuje zainstalowanych agentów wraz z resztą Omarchy, a `mup` aktualizuje tylko narzędzia zarządzane przez mise.

Własny aktualizator agenta, taki jak `claude update`, `codex update` lub przycisk aktualizacji w aplikacji, nie aktualizuje instalacji zarządzanej przez mise. `codex update` kończy się niepowodzeniem, a `claude update` może zgłosić sukces, instalując jednocześnie osobną kopię, której mise nie śledzi. Jeśli wolisz używać natywnego instalatora i aktualizatora agenta, dodaj go do `disable_tools`; zobacz [Preinstalowane narzędzia CLI](18-development-tools.md#preinstalled-cli-tools).

Aby zainstalować wszystkie skonfigurowane narzędzia lazy, zanim będą Ci potrzebne, uruchom `mise install --include-lazy`. Obejmuje to także inne domyślne narzędzia CLI Omarchy oraz agentów. Zobacz [Preinstalowane narzędzia CLI](18-development-tools.md#preinstalled-cli-tools), aby dowiedzieć się, jak zainstalować pojedyncze narzędzie lub użyć własnej instalacji.

`grok` jest instalowany przez autorski pakiet `grok` mise, w ten sam sposób co `claude` i `codex`. Uruchom `grok` lub oznacz go gwiazdką w panelu agentów. Pomiń instalator `curl | bash` na x.ai. Ta ścieżka umieszcza drugą kopię w `~/.grok/bin`, dodaje ją na początku `PATH` i nadpisuje wrapper Omarchy.

`dsh` otwiera swój interfejs przeglądarkowy pod `127.0.0.1:3080`, z katalogiem uruchomienia jako domyślnym obszarem roboczym. Jego interfejs przeglądarkowy nie przyjmuje promptu startowego, więc `omarchy agent prompt` otwiera go z promptem w schowku do wklejenia. Omarchy uruchamia go z presetem uprawnień DeepSeek bez zatwierdzania. DeepSeek Harness przesyła dzienniki sesji do DeepSeek, gdy korzystasz z jego oficjalnego API modeli; wyłącz to w jego interfejsie przeglądarkowym w _Settings > General > Upload Session Log_. Opinie, które mu wysyłasz, są również przesyłane wraz z sesją, chyba że uruchomisz go z `DSH_TELEMETRY_MODE=DISABLED`.

### Domyślny agent

Wybierz domyślnego agenta gwiazdką obok agenta w panelu agentów, która jest wypełniona przy domyślnym, albo poleceniem `omarchy default agent <name>`, które przyjmuje też dowolny harness bez wiersza w panelu. Jeśli agent nie jest jeszcze zainstalowany, wybranie go najpierw go instaluje, a także otrzymuje on własny program uruchamiający w launcherze aplikacji, obok Agent. Świeże Omarchy zaprasza Cię do skonfigurowania jednego jednorazowym powiadomieniem, które otwiera panel agentów.

Wybranie Claude próbuje także skonfigurować jego rozszerzenie przeglądarkowe dla Chromium, Chrome, Brave, Brave Origin i Edge. Konfiguracja rozszerzenia dotyczy wszystkich użytkowników i może poprosić o hasło systemowe; anulowanie lub nieudana instalacja rozszerzenia nadal wybiera i uruchamia Claude. Uruchom ponownie przeglądarkę, włącz rozszerzenie, jeśli pojawi się monit, i zaloguj się do Claude, aby dokończyć łączenie. Uruchom `/chrome` w Claude, aby sprawdzić połączenie. Firefox i Zen nie obsługują tego rozszerzenia. Jeśli Claude był już Twoim domyślnym agentem, zanim dodano tę konfigurację, wybierz go ponownie, aby zainstalować rozszerzenie.

Gdy już wybierzesz, `Super + Shift + Ctrl + A` uruchamia domyślnego agenta w dedykowanym oknie terminala (lub wywołuje selektor, jeśli jeszcze nie wybrałeś). Możesz też uruchomić go od razu do zadania poleceniem `omarchy agent prompt "Review this project"`. Freebuff i DeepSeek Harness nie przyjmują promptu startowego, więc zamiast tego otwierają się z promptem w schowku do wklejenia. Agenci uruchamiani w ten sposób działają bez nadzoru w swoich trybach „nie zatrzymuj się, żeby pytać”, więc bądź gotowy na to, że naprawdę będą coś robić! MiniMax Code nie ma takiego trybu dla swoich sesji interaktywnych, więc pyta o uprawnienia jak zwykle. A ponieważ agenci odmawiają zapamiętywania zaufania dla katalogu domowego, uruchomienia z `$HOME` startują zamiast tego w `~/Work`.

Istnieją też skróty terminalowe: `a` uruchamia domyślnego agenta bezpośrednio w bieżącym terminalu, natomiast `c`, `cx`, `cy` i `ca` uruchamiają bezpośrednio OpenCode, Claude Code, Codex i Antigravity (ponownie w ich trybach automatycznego zatwierdzania). Zmiany motywu synchronizują się także z agentami: Claude Code, Pi, OpenCode i Hermes (po zainstalowaniu go przez Omarchy) podążają za zmianą motywu Omarchy.

### Twoje instrukcje dla agenta

Osobiste reguły dla każdego agenta znajdują się w `~/.agents/AGENTS.md`, obok współdzielonych umiejętności w `~/.agents/skills`. Otwórz je ikoną dokumentu obok + w panelu agentów albo poleceniem `omarchy agent instructions --edit`, które linkuje je także do każdego harnessu przechowującego własny plik globalny: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` Copilot itd. Crush i Amp odczytują link `~/.config/AGENTS.md`, natomiast omp, Kimi i DeepSeek Harness odczytują bezpośrednio `~/.agents/AGENTS.md`. Wybranie domyślnego agenta również je linkuje. Plik instrukcji, który już miałeś, staje się współdzielonym, jeśli jeszcze takiego nie było; w przeciwnym razie jest zachowywany obok linku jako `.bak`. Uruchom `omarchy agent instructions`, aby ponownie zlinkować po zainstalowaniu kolejnego agenta.

### Panel agentów

Górny pasek ma ikonę agentów. Zanim skonfigurujesz agenta, jego panel oferuje trzy sposoby rozpoczęcia: zaloguj się do subskrypcji Claude, Codex, Grok, Gemini, Muse, Cursor lub Copilot, albo w sekcji More do planu kodowania OpenCode Go, MiniMax, Synthetic lub Z.ai; płać na bieżąco za pomocą Fireworks, OpenCode Zen i Go, OpenRouter, albo w sekcji More DeepSeek lub dowolnego innego dostawcy, do którego loguje się OpenCode — wszystkie działają w OpenCode; albo uruchom najlepszy model dla swojego komputera, gdy jakiś do niego pasuje. Pierwszy sposób, który ukończysz, staje się Twoim domyślnym agentem, a przycisk + w panelu oferuje później te same trzy opcje. Potem panel umieszcza każdą subskrypcję na jednej stronie: każdego agenta i konto wraz z jego planem, wskaźnik dla każdego z jego limitów sesji 5-godzinnej i limitów tygodniowych wraz z czasem do ich zresetowania (najedź, aby zobaczyć dokładną wartość procentową) lub pozostałe saldo przedpłacone, pod wierszem, który rotacyjnie pokazuje, co zużyłeś we wszystkich z nich, na przykład tokeny w tym tygodniu i Twój najczęściej używany model. W sekcji _Make something cool_ oferuje starterowe prompty dla nowego motywu, wtyczki, aplikacji lub gry, które przekazują zadanie Twojemu domyślnemu agentowi. Aplikacje są budowane w taki sam sposób jak własne aplikacje Omarchy Hype, Monologue i Omacut, w C++ i Qt Quick, zgodnie z umiejętnością agenta omarchy-make-app, a potrzebne im kompilator i elementy Qt są zainstalowane. Gry to pojedyncza strona three.js w `~/Games/vibes`, zgodna z umiejętnością agenta omarchy-make-game, i wszystkie otwierają się z jednego launchera Game Vibes w bieżącym motywie; ładują three.js z sieci, więc do uruchomienia potrzebują połączenia. Claude Code, Codex, Grok, Kimi, Cursor wraz z jego przydziałem Grok Bot, GitHub Copilot, Muse, Gemini (przez Antigravity) i Devin są obsługiwane od razu wraz ze swoimi limitami, Kimchi ze swoim planem, kredytami przedpłaconymi i budżetami wydatków, a Hermes, Mistral Vibe i Qwen Code pokazują swoje sesje i tokeny, gdy już ich użyjesz. Pojawiają się także plany dostawców i klucze, których używasz przez pi, omp lub opencode: OpenCode Zen i Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan i Synthetic wraz ze swoimi limitami; OpenRouter i DeepSeek ze swoimi saldami przedpłaconymi; Fireworks ze swoimi wydatkami z ostatnich 30 dni. Modele do kodowania, które uruchamiasz na własnym sprzęcie, otrzymują własne wiersze, a ich tokeny również wliczają się do sum, jak opisano w sekcji [Modele lokalne](#local-models). Każdy agent jest liczony raz, pod podmiotem, który go rozlicza, niezależnie od tego, przez ile harnessów go prowadzisz.

Kliknij lewym przyciskiem myszy ikonę na pasku lub naciśnij `Super + Ctrl + X`, aby otworzyć panel, kliknij prawym, aby uruchomić domyślnego agenta, a środkowym, aby odświeżyć. Rekordy użycia stojące za panelem są regenerowane co 15 minut przez `omarchy agent usage update`, a panel może nawet łączyć użycie z innych Twoich maszyn za pośrednictwem zsynchronizowanego folderu. Zobacz README w `$OMARCHY_PATH/shell/plugins/agents/`, aby poznać pełne ustawienia.

### Kilka subskrypcji

Jeśli płacisz za więcej niż jeden plan Claude, Codex lub Grok — na przykład osobisty Max i służbowy — Omarchy może utrzymywać je wszystkie zalogowane i przełączać się między nimi. Dodaj subskrypcję przyciskiem + w panelu agentów, który od razu Cię przez to przeprowadzi, albo poleceniem `omarchy agent account add claude Work` (lub `codex`, lub `grok`). Ten sam przycisk + i polecenie logują do Gemini (`gemini`) i OpenCode (`opencode`) oraz zapisują klucz API Fireworks (`fireworks`) lub OpenRouter (`openrouter`) w OpenCode; polecenie loguje także do Copilot (`copilot`), Cursor (`cursor`) i Muse (`muse`). Te usługi zachowują po jednym zalogowaniu dla każdej. Instaluje CLI, jeśli go brakuje. Pierwsze konto u dostawcy loguje się przez Twoją normalną przeglądarkę, dokładnie tam, gdzie CLI zawsze go szuka. Każde kolejne loguje się przez okno prywatne, aby konto, do którego przeglądarka jest już zalogowana, nie zostało wybrane przez pomyłkę; zaloguj się tam jako konto, które dodajesz, i najpierw zamknij każde okno prywatne, które masz już otwarte. Nigdy nie wylogowuj się z CLI, aby to zrobić: wylogowanie unieważnia zapisane logowanie, a to konto trzeba by dodać ponownie.

Aby skopiować logowania subskrypcji na inną maszynę Omarchy przez SSH, uruchom `omarchy agent account copy user@laptop`. Nadawca dostarcza tymczasowy odbiornik, gdy docelowa maszyna nie ma zainstalowanego żadnego, dzięki czemu starsze maszyny Omarchy mogą odbierać konta bez aktualizacji. Zainstalowane odbiorniki mają pierwszeństwo. Kopiuje to wszystkie subskrypcje Claude, Codex i Grok; dodaj nazwy dostawców, aby je wybrać, na przykład `omarchy agent account copy laptop claude`. Nazwy kont i identyfikatory poleceń zgadzają się ze źródłem, w tym konta już obecne na maszynie docelowej. Niepowiązane konta docelowe otrzymują sufiks numeryczny, jeśli ich nazwy kolidują, a ustawienia, umiejętności, wtyczki i historia rozmów pozostają lokalne dla każdej maszyny.

Istniejące dane uwierzytelniające na maszynie docelowej są zachowywane. Konto źródłowe już zalogowane na niej ma zsynchronizowaną nazwę bez zastępowania jego danych uwierzytelniających; pozostałe konta są dodawane obok niego. Aby zastąpić zapisane dane uwierzytelniające dla pasujących kont, użyj `omarchy agent account copy --replace laptop claude` po zakończeniu sesji tego konta na maszynie docelowej. Świeża maszyna docelowa otrzymuje także aktywne konto źródłowe i preferencje przełączania; ugruntowana maszyna docelowa zachowuje własne.

Dane uwierzytelniające podróżują przez SSH i są przechowywane w prywatnych plikach na maszynie docelowej, więc kopiuj tylko na maszyny, którym ufasz. Jest to jednorazowe kopiowanie, a nie ciągła synchronizacja. Tokeny odświeżania Codex mogą zostać zrotowane przez inną maszynę, co pozostawi skopiowane logowanie wymagające odnowienia; osobne logowania pozostają najbardziej niezawodnym wyborem przy jednoczesnym używaniu na kilku maszynach. Zobacz [wskazówki Codex dotyczące uwierzytelniania kont](https://developers.openai.com/codex/auth/ci-cd-auth).

Jedno konto na dostawcę jest aktywne, a każda nowa sesja zaczyna jako ono: `cx`, `cy`, zwykłe `claude`, `codex` lub `grok`, wszystko uruchamiane przez `omarchy agent` oraz skrypty lub edytory, które znajdują CLI w `PATH`. Przełączaj poleceniem `omarchy agent account use work` (i z powrotem poleceniem `omarchy agent account use main`) lub w panelu, naciskając numer konta, a następnie `Enter` (lub klikając jego gwiazdkę). Działające sesje Claude również się przełączają, od następnej wiadomości: każda sesja Claude działa w `~/.claude`, które zawsze przechowuje logowanie aktywnego konta. Sesja Claude uruchomiona w folderze własnym konta przez starsze Omarchy przechowuje to logowanie do momentu zakończenia, więc przełączenie wymienia te sesje z nazwy i kończy się samo, gdy one znikną. Działające sesje Codex i Grok pozostają na koncie, z którym wystartowały. Historia rozmów, ustawienia, umiejętności i wtyczki są współdzielone między kontami, więc `claude --continue` w tym samym folderze kontynuuje tam, gdzie skończyłeś na nowym koncie.

Przy więcej niż jednym koncie panel pokazuje limity każdego konta obok siebie, z wypełnioną gwiazdką przy używanym. Omarchy powiadamia Cię, gdy aktywne konto przekroczy 95% limitu, a kliknięcie powiadomienia przełącza na konto z największą rezerwą. Nigdy nie przełącza samo. Zmień próg poleceniem `omarchy agent account threshold 90`. Jeśli każde konto przekracza próg, usłyszysz o tym raz, wraz z informacją, które konto zwolni się jako pierwsze. Gdy aktywne konto znajduje się w granicach 15 punktów od swojego progu (80% przy ustawieniu domyślnym), jego limity są sprawdzane co trzy minuty, a nie co 15.

`omarchy agent account list` pokazuje każde konto i jego najnowsze limity, `omarchy agent account remove work` zapomina jedno, a `omarchy agent account rename primary Hey` zmienia nazwę jednego (lub kliknij nazwę konta w panelu). Te polecenia działają na kontach Twojego domyślnego agenta; aby dotrzeć do innego dostawcy, najpierw go nazwij, na przykład `omarchy agent account use codex side`. Logowanie, które już miałeś w `~/.claude` lub `~/.codex`, to konto _Main_. Konto Codex pozostaje tam, gdzie jest; konto Claude oczekuje we własnym folderze, gdy aktywne jest inne konto. Konto nieużywane przez ponad około osiem godzin może pokazywać _Sign-in required_; kliknij je, aby ponownie zalogować to konto bezpośrednio w panelu, albo przełącz się na nie i rozpocznij sesję, co samo odświeży logowanie. Serwery MCP, które dodajesz poleceniem `claude mcp add`, docierają do każdego konta Claude, ponieważ wszystkie działają w `~/.claude`; w przypadku Codex i Grok serwery, które miałeś, gdy konto było dodawane, przechodzą wraz z nim, ale późniejsze docierają tylko do konta, w którym je dodałeś. Claude Desktop zachowuje własne logowanie, a narzędzia Codex lub Grok skonfigurowane bezwzględną ścieżką do pliku binarnego CLI nie podążają za przełączeniem. Jawne `CLAUDE_CONFIG_DIR`, `CODEX_HOME` lub `GROK_HOME` mają pierwszeństwo przed wybranym kontem.

### Diagnostyka awarii

Omarchy obserwuje systemd-coredump pod kątem awarii procesów. Gdy wybierzesz domyślnego agenta, każdy Twój program, który zrzuci core, wywoła powiadomienie „Process crashed” — kliknij je, a awaria zostanie przekazana Twojemu domyślnemu agentowi wraz z umiejętnością omarchy-diagnose-crash Omarchy, która prowadzi agenta przez ustalenie faktów ze zrzutu core i podjęcie decyzji, czy awarię warto zgłosić upstream. Możesz też uruchomić to ręcznie dla dowolnego PID z `coredumpctl list` poleceniem `omarchy agent crash <pid>`.

Obserwowanie jest domyślnie włączone. Wyłącz je w _Trigger > Toggle > Crash Capture Off_ (lub poleceniem `omarchy toggle crash-capture`), a powiadomienia ustaną; `omarchy agent crash <pid>` nadal działa ręcznie.

Awarie można też wyciszać pojedynczo dla każdego programu, co diagnostyka oferuje na końcu. `omarchy crash mute hyprland` zatrzymuje powiadomienia tylko dla tego programu, `omarchy crash mute hyprland off` przywraca je, a samo `omarchy crash mute` wyświetla listę tego, co wyciszyłeś. Przyjmuje ścieżkę pliku binarnego równie chętnie jak jego nazwę, więc `omarchy crash mute /usr/bin/hyprland` robi to samo. Nazwę ze spacją ujmij w cudzysłów, na przykład `omarchy crash mute 'Some App'`. Wszystko inne nadal powiadamia, a wyciszony program nadal się awaryjnie kończy — ukrywa to przypomnienie, niczego nie naprawia.

### Aplikacje desktopowe

Menu _Install > AI_ zawiera także kilka graficznych aplikacji AI: Amp Desktop, Antigravity Desktop, aplikację desktopową ChatGPT, aplikację desktopową Claude (beta Anthropic na Linuksa, z zakładkami Chat, Cowork i Claude Code), Grok Bot do czatowania z modelami xAI, Herdr Desktop, Hermes Desktop, OpenClaw, aplikację desktopową Perplexity oraz T3 Code. Grok Bot to desktopowa aplikacja do czatu. Agentem do kodowania jest polecenie `grok`.

Hermes Desktop to ten, o którym warto wiedzieć, ponieważ maszyna ma jednego Hermesa i jest to Hermes aplikacji: Hermes jest instalowany wyłącznie przez aplikację, a polecenie `hermes`, które uruchamia domyślny agent, jest poleceniem aplikacji. Wybranie Hermesa jako domyślnego agenta instaluje to samo, co pozycja _Install > AI_: pakiet oraz środowisko uruchomieniowe Hermes w `~/.hermes` skonfigurowane przez własny instalator Hermesa, co przy pierwszym razie zajmuje kilka minut. To środowisko uruchomieniowe jest jedynym Hermesem, którego używają terminalowe polecenie `hermes`, domyślny agent i aplikacja, i aktualizuje się samo poleceniem `hermes update`, zamiast czekać na wydanie Omarchy. Zainstalowanie go przekazuje też Hermesowi motyw Omarchy jako skórkę o nazwie `omarchy`, za którą podąża każda powierzchnia Hermesa, gdy przełączasz motywy; wybierz inną w ustawieniach wyglądu Hermesa lub poleceniem `/skin`, jeśli wolisz, żeby tak nie było, a Omarchy zostawi ten wybór w spokoju. Usunięcie aplikacji w _Remove > AI_ najpierw zamyka Hermesa, w tym bramkę, zabiera wraz z nim to środowisko uruchomieniowe i zachowuje Twoje czaty, wspomnienia oraz umiejętności, które Hermes napisał dla siebie, chyba że powiesz inaczej: pyta, domyślnie odpowiadając nie, czy te dane i Twoje ustawienia połączeń również powinny zniknąć.

Doświadczeniem desktopowym OpenClaw jest jego interfejs Control UI, który otwiera się jako aplikacja internetowa wspierana przez własną lokalną bramkę. OpenClaw mieszka w `~/.openclaw` i aktualizuje się samo: użyj przycisku „Update Gateway” w Control UI lub uruchom `openclaw update`, a bramka uruchomi się ponownie na nowej wersji. Omarchy wybiera jedynie wydanie, od którego zaczyna świeża instalacja. OpenClaw może też być Twoim domyślnym agentem: wybranie go poleceniem `omarchy default agent openclaw` konfiguruje tę samą kopię w `~/.openclaw`, a agent otwiera interfejs terminalowy OpenClaw podłączony do jego bramki. Usunięcie OpenClaw w _Remove > AI_ zabiera wraz z nim usługę bramki i aplikację, a potem pyta, czy `~/.openclaw` również powinno zniknąć, ponieważ przechowuje Twoje czaty i dane uwierzytelniające obok samego OpenClaw i środowisk uruchomieniowych wtyczek, które pobiera; ustawienie domyślne zachowuje je, a ponowne zainstalowanie OpenClaw je odzyska.

Herdr Desktop to aplikacja desktopowa [Herdr](https://herdr.dev): przestrzenie, karty i panele terminali oraz agentów do kodowania, które nadal działają w jej rdzeniu, gdy zamkniesz okno. Pochodzi z własnego instalatora Herdr zamiast z pakietu, więc mieszka w `~/.local/share/herdr-app`, przywozi swój rdzeń do `~/.local/bin/herdr-core`, gdy jeszcze go nie masz, i aktualizują się oboje. Stoi obok polecenia `herdr`, które Omarchy dostarcza na `Super + Ctrl + Return`, zamiast je zastępować, i otrzymuje bezpośrednie klawisze tego polecenia: `Alt + Return` i `Alt + Shift + Return` dzielą panel w dół lub w prawo, `Alt + Escape` zamyka go, `Ctrl + Alt + Arrow` porusza się między panelami, `Alt + 1..9` i `Alt + Left/Right` wybierają kartę, a `Alt + Up/Down` poruszają się między przestrzeniami. `Ctrl + 1..9` wybiera przestrzeń, a `Alt + Shift + Up/Down` przechodzi kolejno po agentach. Klawisze z prefiksem `Ctrl + Space` pozostają wyłącznie terminalowe, ponieważ aplikacja nie może przytrzymać zwykłego klawisza Ctrl dla sekwencji. Omarchy zapisuje je do `~/.config/herdr-app/keys.json`, a `omarchy-refresh-herdr-app` przywraca je. Zainstalowanie go wybiera motyw Omarchy Herdr, który od tego momentu podąża za Twoim motywem Omarchy. Herdr przechowuje jeden motyw dla trybu jasnego i jeden dla trybu ciemnego, więc po przełączeniu między ciemnym a jasnym motywem Omarchy wybierz Omarchy jeszcze raz w selektorze motywów Herdr dla drugiego trybu.

T3 Code działa z oficjalnego wydania AppImage w `~/.local/share/t3code` zamiast z pakietu, więc aktualizuje się samo. Zainstalowanie go pyta, czy zacząć na kanale Stable czy Nightly; zmień później w ustawieniach T3 Code. Twoje wątki i ustawienia znajdują się w `~/.t3`, a usunięcie T3 Code w _Remove > AI_ zabiera je wraz z nim.

### Modele lokalne

Uruchom otwarty model na własnej maszynie dla swoich agentów do kodowania. Twoje prompty i kod pozostają na maszynie; nic wysyłanego do modelu jej nie opuszcza. Zacznij od:

```bash
omarchy models use best text
```

Konfiguruje to najlepszy model tekstowy dla tej maszyny, taki, którego używają Twoi agenci. Modele obrazów, wideo i muzyki mają swoje najlepsze modele: `omarchy models use best image`, `video` lub `music`. Uruchom `omarchy models use best`, aby zobaczyć wybór dla tej maszyny dla każdego rodzaju.

Albo wybierz + w panelu agentów: w sekcji _Use a local model_ wymienia każdy model do kodowania, który pasuje do tej maszyny, z zalecanym na pierwszym miejscu. Podman, który uruchamia modele, jest dostarczany z Omarchy, podobnie jak zestaw narzędzi kontenerowych NVIDIA na maszynie NVIDIA, który daje im GPU; jeśli któregoś brakuje, pierwsza konfiguracja go instaluje. Omarchy następnie wybiera zalecany model dla tej maszyny, pobiera go i uruchamia. Spodziewaj się pobrania dziesiątek GB i zajęcia większości pamięci maszyny, gdy model działa: Flash Next używa około 100 GiB przy pełnym kontekście 256K. Jeśli inne modele zajmują potrzebną mu pamięć, jest konfigurowany jako zatrzymany, gotowy do uruchomienia, gdy zatrzymasz któryś z nich. Model zatrzymuje się przy wylogowaniu; zatrzymaj go sam, gdy potrzebujesz pamięci do czegoś innego.

`omarchy models list` pokazuje opcje i wyjaśnia, dlaczego niektóre nie pasują. Aby skonfigurować inny, uruchom `omarchy models use <recipe>`. Dziś dla maszyn Strix Halo ze 128 GB dostępne są `qwen3.8-flash-next-gufo` i `qwen3.8-27b-gufo`; 27B zajmuje około 40 GiB, więc zostawia miejsce na inną pracę. Na laptopie 64 GB z Intel Arc B390 `qwen3.6-35b-a3b-llamacpp` działa w około 30 GiB. Nowe receptury i rekomendacje przychodzą wraz z `omarchy update`, przez pakiet.

Model do kodowania, który dodasz, otrzymuje własny wiersz w panelu agentów, obok Twoich subskrypcji: ikona odtwarzania, aby go uruchomić, ikona pauzy, aby go zatrzymać i zwolnić jego pamięć, znak Tailscale, aby udostępnić go innym maszynom w Twoim tailnecie, gdy działa, oraz przycisk terminala, aby otworzyć na nim swojego agenta. Jego wiersz pokazuje na bieżąco pobieranie, ładowanie lub zatrzymywanie i informuje, gdy brakuje wolnej pamięci, aby go uruchomić, lub linkuje do jego dzienników, gdy zatrzymał się z błędem. Kilka może działać jednocześnie, gdy razem mieszczą się w pamięci. Naciśnij Delete na wybranym wierszu, aby usunąć model z tej maszyny, wraz z pobraniem; + może skonfigurować go ponownie. Model do kodowania skonfigurowany z terminala czeka pod przyciskiem + do momentu, aż go dodasz, podobnie jak modele, które uruchamia maszyna, z którą się sparowałeś (`omarchy models pair <host>`).

Każdy skonfigurowany model do kodowania otrzymuje też własny wpis w launcherze aplikacji, pod nazwą modelu i z logo jego twórcy, w taki sposób, w jaki zalogowanie się do Claude, Codex lub Grok dodaje taki wpis. Otwiera Twojego agenta na tym modelu i najpierw uruchamia model, jeśli nie działa: terminal pokazuje jego ładowanie i przekazuje kontrolę agentowi, gdy model jest gotowy. Usunięcie modelu usuwa jego wpis.

Nie każdy model służy do kodowania. Modele obrazów, wideo i muzyki otwierają się zamiast tego w Fantasi, aplikacji Omarchy do tworzenia obrazów, wideo i muzyki za pomocą modelu działającego na tej maszynie, i są zarządzane tam lub poleceniem `omarchy models`.

Model nadal działa dokładnie tak, jak został skonfigurowany, więc aktualizacja Omarchy nigdy nie restartuje żadnego modelu pod Twoimi agentami. Gdy Omarchy ma nowsze środowisko uruchomieniowe lub nowsze wagi dla modelu, który skonfigurowałeś, jego wiersz pokazuje przycisk aktualizacji: naciśnij go, a model zostanie ponownie skonfigurowany w tle, pobierając tylko to, co się zmieniło, i uruchomi się ponownie na nowej wersji. Model, który był zatrzymany, pozostaje zatrzymany. `omarchy models update` robi to samo dla każdego modelu z terminala.

Z wiersza poleceń `omarchy models start <recipe>` i `omarchy models stop <recipe>` robią to samo, `omarchy models status` pokazuje każdy model, a `omarchy agent --local-model <recipe>` otwiera ten model w pi, niezależnie od tego, jaki jest Twój domyślny agent. Aby uczynić model lokalny tym, co otwierają skrót agenta, konsola Quake i _Make something_, uruchom `omarchy default agent local` lub oznacz gwiazdką działający model w panelu agentów. pi wymienia także każdy skonfigurowany przez Ciebie model oraz te na maszynach, z którymi się sparowałeś, we własnym selektorze modeli, więc zwykłe `pi` również do nich dociera. Może połączyć się także dowolny klient zgodny z OpenAI: `status` pokazuje adres każdego modelu (pierwszy to `http://127.0.0.1:11435/v1`), nazwą modelu jest nazwa receptury, a klucz znajduje się w `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` usuwa model oraz pobrania, których nie używa żaden inny model.

Środowiska uruchomieniowe firm trzecich są oznaczane ich wydawcą. Omarchy uruchamia każdy model bez dostępu do sieci.

### Lokalne modele LLM

Omarchy poleca dwa sposoby uruchamiania lokalnych modeli LLM: LM Studio i Ollama. LM Studio oferuje interfejs GUI do znajdowania modeli o otwartych wagach, instalowania ich i uruchamiania. To świetny sposób, aby łatwo zacząć. Ollama oferuje CLI do robienia tego w podobny sposób. Ale jeśli jesteś nowy w modelach lokalnych, zacząłbym od LM Studio. Możesz zainstalować którekolwiek z nich w _Install > AI_ w menu Omarchy.

### Umiejętności Omarchy

Umiejętności agenta pomagają AI używać konkretnych narzędzi w konkretny sposób, a Omarchy dostarcza siedem z nich. Umiejętność omarchy obejmuje dostosowywanie systemu, na przykład poprawianie konfiguracji Hyprland lub dostosowywanie paska. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app i omarchy-make-game obejmują tworzenie czegoś nowego, omarchy-contribute obejmuje zgłaszanie błędu lub wysyłanie poprawki upstream, a omarchy-diagnose-crash pracuje nad zrzutem core awarii. Są one linkowane symbolicznie do katalogów umiejętności dla Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` oraz każdego `~/.hermes/profiles/*/skills`) i ogólnej lokalizacji `~/.agents/skills`, więc większość harnessów wykrywa je automatycznie. Twój własny folder umiejętności o tej samej nazwie ma pierwszeństwo.

Ale traktuj te umiejętności jako eksperymentalne. Różne modele będą używać ich z różnym skutkiem. Najlepiej najpierw działać w trybie planowania, aby mieć pojęcie, co agent chciałby zmienić. A potem bądź gotowy do wycofania zmian lub nawet wywołania `omarchy reinstall configs`, jeśli agent narobi bałaganu we wszystkim.
