# AI

Omarchy zawiera programy uruchamiające dla poniższych agentów kodujących, ale nie wybiera za Ciebie domyślnego. Uruchom polecenie, aby przy pierwszym użyciu zainstalować jego CLI, a następnie uwierzytelnij się, gdy pojawi się monit. Hermes jest wyjątkiem: przy pierwszym użyciu nic nie jest dla niego instalowane, a wybranie go instaluje Hermes Desktop, jak wyjaśnia sekcja _Aplikacje desktopowe_ poniżej.

### Instalowanie i aktualizowanie agentów

Poza Hermes, agenci ci korzystają z leniwej instalacji mise: pierwsze uruchomienie instaluje CLI, a kolejne uruchomienia używają go ponownie. mise sprawdza również, czy zainstalowany agent ma nową wersję, co najwyżej raz na cztery godziny, tuż przed jego uruchomieniem lub w tle przy wierszu polecenia powłoki. Jeśli ta aktualizacja się nie powiedzie lub jesteś offline, uruchomi się zainstalowana wersja. `omarchy update` aktualizuje zainstalowanych agentów wraz z resztą Omarchy, a `mup` aktualizuje tylko narzędzia zarządzane przez mise.

Własny aktualizator agenta, taki jak `claude update`, `codex update` lub przycisk aktualizacji w aplikacji, nie aktualizuje instalacji zarządzanej przez mise. `codex update` kończy się niepowodzeniem, a `claude update` może zgłosić sukces, instalując jednocześnie osobną kopię, której mise nie śledzi. Jeśli wolisz używać natywnego instalatora i aktualizatora agenta, dodaj go do `disable_tools`; zobacz [Preinstalowane narzędzia CLI](18-development-tools.md#preinstalled-cli-tools).

Aby zainstalować wszystkie skonfigurowane narzędzia lazy, zanim będą Ci potrzebne, uruchom `mise install --include-lazy`. Obejmuje to pozostałe domyślne narzędzia CLI Omarchy, a także agentów. Zobacz [Preinstalowane narzędzia CLI](18-development-tools.md#preinstalled-cli-tools), aby dowiedzieć się, jak zainstalować pojedyncze narzędzie lub użyć własnej instalacji.

`grok` jest instalowany za pośrednictwem własnego pakietu `grok` mise, w ten sam sposób co `claude` i `codex`. Uruchom `grok` lub wybierz go w _Agent > Harness_. Pomiń instalator `curl | bash` na x.ai. Ta ścieżka umieszcza drugą kopię w `~/.grok/bin`, dodaje ją na początku `PATH` i nadpisuje wrapper Omarchy.

`dsh` otwiera swój interfejs przeglądarkowy pod adresem `127.0.0.1:3080`, z katalogiem uruchomienia jako domyślnym obszarem roboczym. Jego interfejs przeglądarkowy nie przyjmuje promptu startowego, więc `omarchy agent prompt` otwiera go z promptem w schowku do wklejenia. Omarchy uruchamia go z presetem uprawnień DeepSeek bez zatwierdzania. DeepSeek Harness przesyła dzienniki sesji do DeepSeek, gdy używasz jego oficjalnego API modelu; wyłącz to w _Settings > General > Upload Session Log_ w jego interfejsie przeglądarkowym. Informacje zwrotne, które mu wysyłasz, są również przesyłane wraz z sesją, chyba że uruchomisz go z `DSH_TELEMETRY_MODE=DISABLED`.

### Domyślny agent

Wybierz swojego domyślnego agenta za pomocą `omarchy default agent <name>` lub w _Agent > Harness_ w Omarchy Menu (`Super + Space`). Jeśli agent nie jest jeszcze zainstalowany, wybranie go najpierw go zainstaluje. Świeże Omarchy zaprosi Cię do dokonania tego wyboru jednorazowym powiadomieniem.

Wybranie Claude próbuje również skonfigurować jego rozszerzenie przeglądarki dla Chromium, Chrome, Brave, Brave Origin i Edge. Konfiguracja rozszerzenia dotyczy wszystkich użytkowników i może poprosić o hasło systemowe; anulowanie lub nieudana instalacja rozszerzenia nadal wybiera i uruchamia Claude. Uruchom ponownie przeglądarkę, włącz rozszerzenie, jeśli pojawi się monit, i zaloguj się do Claude, aby dokończyć łączenie. Uruchom `/chrome` w Claude, aby sprawdzić połączenie. Firefox i Zen nie obsługują tego rozszerzenia. Jeśli Claude był już Twoim domyślnym agentem, zanim dodano tę konfigurację, wybierz go ponownie, aby zainstalować rozszerzenie.

Po dokonaniu wyboru `Super + Shift + Ctrl + A` uruchamia domyślnego agenta w dedykowanym oknie terminala (lub wywołuje selektor, jeśli jeszcze nie wybrałeś). Możesz też uruchomić go od razu do zadania za pomocą `omarchy agent prompt "Review this project"`. Freebuff i DeepSeek Harness nie przyjmują promptu startowego, więc otwierają się z promptem w schowku do wklejenia. Agenci uruchomieni w ten sposób działają bez nadzoru w swoich odpowiednich trybach „nie zatrzymuj się, aby pytać”, więc bądź gotowy na to, że naprawdę będą coś robić! MiniMax Code nie ma takiego trybu dla swoich sesji interaktywnych, więc pyta o uprawnienia jak zwykle. A ponieważ agenci odmawiają zapamiętania zaufania dla Twojego katalogu domowego, uruchomienia z `$HOME` rozpoczynają się zamiast tego w `~/Work`.

Są też skróty terminalowe: `a` uruchamia domyślnego agenta w bieżącym terminalu, a `c`, `cx` i `cy` uruchamiają bezpośrednio OpenCode, Claude Code i Codex (ponownie w ich trybach automatycznego zatwierdzania). Zmiany motywu synchronizują się również z agentami: Claude Code, Pi, OpenCode i Hermes (gdy Omarchy go zainstaluje) podążają za zmianą motywu Omarchy.

### Instrukcje Twojego agenta

Osobiste zasady dla każdego agenta znajdują się w `~/.agents/AGENTS.md`, obok współdzielonych umiejętności w `~/.agents/skills`. Otwórz go w _Agent > Instructions_, co również łączy go z każdym harnessem, który przechowuje własny plik globalny: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` Copilot i tak dalej. Crush i Amp odczytują link `~/.config/AGENTS.md`, natomiast omp, Kimi i DeepSeek Harness odczytują bezpośrednio `~/.agents/AGENTS.md`. Wybranie domyślnego agenta również go łączy. Plik instrukcji, który już miałeś, staje się współdzielonym, jeśli jeszcze go nie było; w przeciwnym razie jest przechowywany obok linku jako `.bak`. Uruchom `omarchy agent instructions`, aby ponownie połączyć po zainstalowaniu kolejnego agenta.

### Panel agentów

Górny pasek ma ikonę agentów. Zanim skonfigurujesz agenta, jego panel przeprowadzi Cię przez logowanie do Claude, Codex lub Grok, a pierwszy z nich stanie się Twoim domyślnym agentem. Potem panel umieszcza każdą subskrypcję na jednej stronie: każdego agenta i konto wraz z jego planem, wskaźnik dla każdego z jego limitów sesji 5-godzinnej i tygodniowego wraz z czasem do resetu (najedź, aby zobaczyć dokładną wartość procentową) lub pozostałe saldo przedpłacone, pod linią, która rotuje przez to, co wykorzystałeś u nich wszystkich, np. tokeny w tym tygodniu i najczęściej używany model. W sekcji _Make something_ oferuje prompty startowe dla nowego motywu, wtyczki, aplikacji lub gry, które przekazują zadanie Twojemu domyślnemu agentowi. Aplikacje są budowane w taki sposób, jak własne Hype, Monologue i Omacut Omarchy, w C++ i Qt Quick, zgodnie z umiejętnością agenta omarchy-make-app, a kompilator i potrzebne im elementy Qt są zainstalowane. Gry to pojedyncza strona three.js w `~/Games/vibes`, zgodnie z umiejętnością agenta omarchy-make-game, a wszystkie otwierają się z jednego launchera Game Vibes w bieżącym motywie; ładują three.js z sieci, więc do uruchomienia potrzebują połączenia. Claude Code, Codex, Grok, Kimi, Cursor i jego przydział Grok Bot, GitHub Copilot, Muse, Antigravity, Kimchi i Devin są obsługiwane od razu wraz z ich limitami, a Hermes, Mistral Vibe i Qwen Code pokazują swoje sesje i tokeny, gdy już ich użyjesz. Pojawiają się również plany dostawców i klucze, których używasz za pośrednictwem pi, omp lub opencode: OpenCode Zen i Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan i Synthetic wraz z ich limitami; Fireworks, OpenRouter i DeepSeek wraz z ich saldami przedpłaconymi; oraz modele, które uruchamiasz na własnym sprzęcie, w sekcji Modele lokalne. Każdy agent jest liczony raz, u tego, kto go rozlicza, niezależnie od tego, przez ile harnessów go prowadzisz.

Kliknij lewym przyciskiem myszy ikonę na pasku, aby otworzyć panel, prawym przyciskiem, aby uruchomić domyślnego agenta. Rekordy użycia, które za tym stoją, są regenerowane co 15 minut przez `omarchy agent usage-update`, a panel może nawet scalać użycie z innych Twoich maszyn za pośrednictwem zsynchronizowanego folderu. Zobacz README w `$OMARCHY_PATH/shell/plugins/agents/`, aby poznać pełne ustawienia.

### Kilka subskrypcji

Jeśli płacisz za więcej niż jeden plan Claude, Codex lub Grok — na przykład osobisty Max i służbowy — Omarchy może utrzymywać je wszystkie zalogowane i przełączać się między nimi. Dodaj subskrypcję za pomocą + w panelu agentów, który przeprowadzi Cię przez to na miejscu, lub za pomocą `omarchy agent account add claude Work` (lub `codex`, lub `grok`). Zainstaluje CLI, jeśli go brakuje. Pierwsze konto dla dostawcy loguje się przez Twoją normalną przeglądarkę, dokładnie tam, gdzie CLI zawsze szuka. Każde kolejne loguje się przez okno prywatne, aby konto, na które Twoja przeglądarka jest już zalogowana, nie zostało wybrane przez pomyłkę; zaloguj się tam jako konto, które dodajesz, i najpierw zamknij każde okno prywatne, które już miałeś otwarte. Nigdy nie wylogowuj się z CLI, aby to zrobić: wylogowanie unieważnia zapisane logowanie, a to konto trzeba byłoby dodać ponownie.

Aby skopiować logowania subskrypcji na inną maszynę Omarchy przez SSH, uruchom `omarchy agent account copy user@laptop`. Nadawca dostarcza tymczasowego odbiorcę, gdy miejsce docelowe nie ma zainstalowanego, więc starsze maszyny Omarchy mogą odbierać konta bez aktualizacji. Zainstalowani odbiorcy mają pierwszeństwo. Kopiuje to wszystkie subskrypcje Claude, Codex i Grok; dodaj nazwy dostawców, aby je wybrać, jak w `omarchy agent account copy laptop claude`. Nazwy kont i identyfikatory poleceń odpowiadają źródłu, w tym konta już obecne w miejscu docelowym. Niepowiązane konta docelowe otrzymują przyrostek numeryczny, jeśli ich nazwy są w konflikcie, a ustawienia, umiejętności, wtyczki i historia konwersacji pozostają lokalne dla każdej maszyny.

Istniejące dane uwierzytelniające w miejscu docelowym są zachowywane. Konto źródłowe już zalogowane tam ma zsynchronizowaną nazwę bez zastępowania jego danych uwierzytelniających; pozostałe konta są dodawane obok niego. Aby zastąpić zapisane dane uwierzytelniające dla pasujących kont, użyj `omarchy agent account copy --replace laptop claude` po zamknięciu sesji tego konta w miejscu docelowym. Świeże miejsce docelowe otrzymuje również aktywne konto źródłowe i preferencje przełączania; ustalone miejsce docelowe zachowuje własne.

Dane uwierzytelniające podróżują przez SSH i są przechowywane w plikach prywatnych w miejscu docelowym, więc kopiuj tylko na maszyny, którym ufasz. Jest to jednorazowa kopia, a nie bieżąca synchronizacja. Tokeny odświeżania Codex mogą zostać obrócone przez inną maszynę, pozostawiając skopiowane logowanie wymagające odnowienia; osobne logowania pozostają najbardziej niezawodnym wyborem do jednoczesnego użycia na kilku maszynach. Zobacz [przewodnik Codex dotyczący uwierzytelniania kont](https://developers.openai.com/codex/auth/ci-cd-auth).

Jedno konto na dostawcę jest aktywne, a każda nowa sesja rozpoczyna się jako ono: `cx`, `cy`, zwykłe `claude`, `codex` lub `grok`, wszystko uruchamiane przez `omarchy agent` oraz skrypty lub edytory, które znajdują CLI w `PATH`. Przełączaj za pomocą `omarchy agent account use work` (i z powrotem za pomocą `omarchy agent account use main`) lub w panelu, naciskając numer konta, a następnie `Enter` (lub klikając jego przycisk Use). Działające sesje Claude również się przełączają, od następnej wiadomości: każda sesja Claude działa w `~/.claude`, który zawsze przechowuje logowanie aktywnego konta. Sesja Claude uruchomiona we własnym folderze konta przez starsze Omarchy przechowuje to logowanie do momentu zakończenia, więc przełączenie wymienia te sesje i kończy się samo, gdy ich nie będzie. Działające sesje Codex i Grok pozostają na koncie, na którym się rozpoczęły. Historia konwersacji, ustawienia, umiejętności i wtyczki są współdzielone między kontami, więc `claude --continue` w tym samym folderze podejmuje pracę tam, gdzie ją przerwałeś na nowym koncie.

Gdy masz więcej niż jedno konto, panel pokazuje limity każdego konta obok siebie, z zaznaczonym aktywnym. Domyślnie Omarchy powiadamia Cię, gdy aktywne konto przekroczy 95% limitu, a kliknięcie powiadomienia przełącza na konto z największym zapasem. Najedź na linię konta w panelu i kliknij Autoswitch, który pojawia się obok Use (lub naciśnij `m`), lub uruchom `omarchy agent account mode auto`, aby przełączało się samo; gdy jest włączone, Autoswitch zajmuje miejsce Use, a ponowne kliknięcie wraca do powiadamiania. Dodaj liczbę, aby zmienić próg, jak w `omarchy agent account mode auto 90`. Jeśli każde konto przekroczy próg, usłyszysz o tym raz, wraz z informacją, które konto zwolni się jako pierwsze. Gdy aktywne konto znajduje się w granicach 15 punktów od swojego progu (80% przy ustawieniu domyślnym), jego limity są sprawdzane co trzy minuty, a nie co 15.

`omarchy agent account list` pokazuje każde konto i jego najnowsze limity, `omarchy agent account remove work` zapomina jedno, a `omarchy agent account rename primary Hey` zmienia nazwę jednego (lub kliknij nazwę konta w panelu). Te polecenia działają na kontach Twojego domyślnego agenta; aby dotrzeć do innego dostawcy, najpierw go nazwij, jak w `omarchy agent account use codex side`. Logowanie, które już miałeś w `~/.claude` lub `~/.codex`, to konto _Main_. Konto Codex pozostaje tam, gdzie jest; konto Claude czeka we własnym folderze, gdy inne konto jest aktywne. Konto nieużywane przez ponad około osiem godzin może pokazywać _Sign-in required_; kliknij je, aby ponownie zalogować to konto bezpośrednio w panelu, lub przełącz się na nie i rozpocznij sesję, co samo odświeży logowanie. Serwery MCP, które dodajesz za pomocą `claude mcp add`, docierają do każdego konta Claude, ponieważ wszystkie działają w `~/.claude`; w przypadku Codex i Grok serwery, które miałeś, gdy konto zostało dodane, przechodzą wraz z nim, ale późniejsze docierają tylko do konta, w którym je dodałeś. Claude Desktop przechowuje własne logowanie, a narzędzia Codex lub Grok skonfigurowane bezwzględną ścieżką do pliku binarnego CLI nie podążają za przełączeniem. Jawne `CLAUDE_CONFIG_DIR`, `CODEX_HOME` lub `GROK_HOME` ma pierwszeństwo przed wybranym kontem.

### Diagnoza awarii

Omarchy obserwuje systemd-coredump w poszukiwaniu awarii procesów. Gdy coś spowoduje segfault, otrzymasz powiadomienie "Process crashed" — kliknij je, a awaria zostanie przekazana Twojemu domyślnemu agentowi wraz z umiejętnością diagnose-crash Omarchy, która prowadzi agenta przez ustalenie faktów z core dump i podjęcie decyzji, czy awarię warto zgłosić upstream. Możesz też uruchomić ją ręcznie dla dowolnego PID z `coredumpctl list` za pomocą `omarchy agent crash <pid>`.

Obserwowanie jest domyślnie włączone. Wyłącz je w _Trigger > Toggle > Crash Capture_ (lub za pomocą `omarchy toggle crash-capture`), a powiadomienia ustaną; `omarchy agent crash <pid>` nadal działa ręcznie.

Awarie można również wyciszać po jednym programie na raz, co diagnoza oferuje Ci na końcu. `omarchy crash mute hyprland` zatrzymuje powiadomienia tylko dla tego programu, `omarchy crash mute hyprland off` przywraca je, a samo `omarchy crash mute` wyświetla listę tego, co wyciszyłeś. Przyjmuje ścieżkę pliku binarnego równie chętnie jak jego nazwę, więc `omarchy crash mute /usr/bin/hyprland` robi to samo. Ujmij w cudzysłów nazwę ze spacją, jak w `omarchy crash mute 'Some App'`. Wszystko inne nadal powiadamia, a wyciszony program nadal się zawiesza — ukrywa to przypomnienie, niczego nie naprawia.

### Aplikacje desktopowe

Menu _Install > AI_ zawiera również kilka graficznych aplikacji AI: Antigravity Desktop, aplikację desktopową ChatGPT, aplikację desktopową Claude (beta Anthropic na Linux, z kartami Chat, Cowork i Claude Code), Grok Bot do czatowania z modelami xAI, Herdr Desktop, Hermes Desktop, OpenClaw, aplikację desktopową Perplexity oraz T3 Code. Grok Bot to desktopowa aplikacja do czatu. Agentem kodującym jest polecenie `grok`.

Hermes Desktop to ten, o którym warto wiedzieć, ponieważ maszyna ma jednego Hermes i należy on do aplikacji: Hermes jest instalowany wyłącznie za pośrednictwem aplikacji, a polecenie `hermes`, które uruchamia domyślny agent, należy do aplikacji. Wybranie Hermes jako domyślnego agenta instaluje to samo, co pozycja _Install > AI_: pakiet oraz środowisko uruchomieniowe Hermes w `~/.hermes` skonfigurowane przez własny instalator Hermes, co za pierwszym razem zajmuje kilka minut. To środowisko uruchomieniowe to jedyny Hermes, którego używają polecenie terminalowe `hermes`, domyślny agent i aplikacja, i aktualizuje się samo za pomocą `hermes update`, zamiast czekać na wydanie Omarchy. Zainstalowanie go daje również Hermes motyw Omarchy jako skórkę o nazwie `omarchy`, za którą podąża każda powierzchnia Hermes, gdy przełączasz motywy; wybierz inną w ustawieniach Appearance Hermes lub za pomocą `/skin`, jeśli wolisz, aby tak nie było, a Omarchy pozostawi ten wybór w spokoju. Usunięcie aplikacji w _Remove > AI_ najpierw zamyka Hermes, w tym gateway, zabiera ze sobą to środowisko uruchomieniowe i zachowuje Twoje czaty, wspomnienia oraz umiejętności, które Hermes napisał dla siebie, chyba że powiesz inaczej: pyta, domyślnie na nie, czy te dane i Twoje ustawienia połączenia również powinny zniknąć.

Doświadczeniem desktopowym OpenClaw jest jego Control UI, które otwiera się jako aplikacja internetowa wspierana przez własny lokalny gateway. OpenClaw mieszka w `~/.openclaw` i aktualizuje się sam: użyj przycisku "Update Gateway" w Control UI lub uruchom `openclaw update`, a gateway uruchomi się ponownie w nowej wersji. Omarchy wybiera jedynie wydanie, od którego zaczyna świeża instalacja. Usunięcie OpenClaw w _Remove > AI_ zabiera ze sobą usługę gateway i aplikację, a następnie pyta, czy `~/.openclaw` również powinno zniknąć, ponieważ przechowuje Twoje czaty i dane uwierzytelniające obok samego OpenClaw oraz środowisk uruchomieniowych wtyczek, które pobiera; domyślnie je zachowuje, a ponowne zainstalowanie OpenClaw je odzyska.

Herdr Desktop to aplikacja desktopowa [Herdr](https://herdr.dev): przestrzenie, karty i panele terminali oraz agentów kodujących, które nadal działają w jej rdzeniu, gdy zamkniesz okno. Pochodzi z własnego instalatora Herdr, a nie z pakietu, więc mieszka w `~/.local/share/herdr-app`, przynosi ze sobą swój rdzeń w `~/.local/bin/herdr-core`, gdy jeszcze go nie masz, i aktualizuje oba sama. Znajduje się obok polecenia `herdr`, które Omarchy dostarcza na `Super + Ctrl + Return`, a nie je zastępuje, i otrzymuje bezpośrednie klawisze tego polecenia: `Alt + Return` i `Alt + Shift + Return` dzielą panel w dół lub w prawo, `Alt + Escape` go zamyka, `Ctrl + Alt + Arrow` przechodzi między panelami, `Alt + 1..9` i `Alt + Left/Right` wybierają kartę, a `Alt + Up/Down` przechodzą między przestrzeniami. `Ctrl + 1..9` wybiera przestrzeń, a `Alt + Shift + Up/Down` przechodzi przez agentów. Klawisze prefiksu `Ctrl + Space` pozostają tylko dla terminala, ponieważ aplikacja nie może przytrzymać zwykłego klawisza Ctrl dla sekwencji. Omarchy zapisuje je w `~/.config/herdr-app/keys.json`, a `omarchy-refresh-herdr-app` je przywraca. Zainstalowanie go wybiera motyw Omarchy Herdr, który od tego momentu podąża za Twoim motywem Omarchy. Herdr przechowuje jeden motyw dla trybu jasnego i jeden dla ciemnego, więc po przełączeniu między ciemnym a jasnym motywem Omarchy wybierz Omarchy w selektorze motywów Herdr jeszcze raz dla drugiego trybu.

T3 Code działa z oficjalnego wydania AppImage w `~/.local/share/t3code`, a nie z pakietu, więc aktualizuje się sam. Zainstalowanie go pyta, czy zacząć na kanale Stable czy Nightly; przełącz później w ustawieniach T3 Code. Twoje wątki i ustawienia znajdują się w `~/.t3`, a usunięcie T3 Code w _Remove > AI_ zabiera je ze sobą.

### Modele lokalne

Uruchom otwarty model na własnej maszynie dla swoich agentów kodujących. Twoje prompty i kod pozostają na maszynie; nic wysłanego do modelu jej nie opuszcza. Zacznij od:

```bash
omarchy agent local use best
```

Lub w panelu agentów na górnym pasku wybierz +, a następnie Local AI, które pojawia się, gdy model pasuje do tej maszyny. Za pierwszym razem instaluje to Podman, który uruchamia modele, a na maszynie NVIDIA zestaw narzędzi kontenerowych NVIDIA, który daje im GPU. Następnie Omarchy wybiera zalecany model dla tej maszyny, pobiera go i uruchamia. Spodziewaj się pobrania dziesiątek GB i zajęcia większości pamięci maszyny podczas działania modelu: Flash Next używa około 100 GiB przy pełnym kontekście 256K. Jeśli inne modele zajmują potrzebną mu pamięć, jest konfigurowany jako zatrzymany, gotowy do uruchomienia, gdy zatrzymasz jeden z nich. Model zatrzymuje się przy wylogowaniu; zatrzymaj go sam, gdy potrzebujesz pamięci do czegoś innego.

`omarchy agent local list` pokazuje opcje i wyjaśnia, dlaczego niektóre nie pasują. Aby skonfigurować inny, uruchom `omarchy agent local use <recipe>`. Obecnie `qwen3.8-flash-next-gufo` i `qwen3.8-27b-gufo` są dostępne dla maszyn Strix Halo 128 GB; 27B zajmuje około 40 GiB, więc zostawia miejsce na inną pracę. Na laptopie 64 GB z Intel Arc B390 `qwen3.6-35b-a3b-llamacpp` działa w około 30 GiB. Nowe receptury i zalecenia przychodzą wraz z `omarchy update`, za pośrednictwem pakietu.

Każdy skonfigurowany model otrzymuje własną linię w panelu agentów, obok Twoich subskrypcji: play, aby go uruchomić, pauza, aby go zatrzymać i zwolnić jego pamięć, oraz przycisk terminala, aby otworzyć na nim swojego agenta. Kilka może działać jednocześnie, gdy razem mieszczą się w pamięci; jeśli jeden się nie mieści, Omarchy mówi, który działający model zatrzymać. Przeciągaj linie, aby zmienić ich kolejność, i naciśnij Delete na wybranej linii, aby usunąć model i jego pobrane pliki.

Każdy skonfigurowany model otrzymuje również własną pozycję w launcherze aplikacji, pod nazwą modelu i z logo jego twórcy, w taki sposób, w jaki logowanie do Claude, Codex lub Grok dodaje jedną. Otwiera Twojego agenta na tym modelu i najpierw uruchamia model, jeśli nie działa: terminal pokazuje jego ładowanie i przekazuje sterowanie agentowi, gdy będzie gotowy. Usunięcie modelu usuwa jego pozycję.

Model nadal działa dokładnie tak, jak został skonfigurowany, więc aktualizacja Omarchy nigdy nie uruchamia ponownie żadnego pod Twoimi agentami. Gdy Omarchy ma nowsze środowisko uruchomieniowe lub nowsze wagi dla skonfigurowanego przez Ciebie modelu, jego linia pokazuje przycisk aktualizacji: naciśnij go, a model zostanie ponownie skonfigurowany w tle, pobierając tylko to, co się zmieniło, i uruchomi się ponownie w nowej wersji. Model, który był zatrzymany, pozostaje zatrzymany. `omarchy agent local update` robi to samo dla każdego modelu z terminala.

Z wiersza poleceń `omarchy agent local start <recipe>` i `omarchy agent local stop <recipe>` robią to samo, `omarchy agent local status` pokazuje każdy model, a `omarchy agent --local` otwiera Twojego domyślnego agenta na ostatnim uruchomionym przez Ciebie modelu. pi, OpenCode i Qwen Code mogą z niego korzystać; przy każdym innym domyślnym otwiera się w pi. pi wyświetla również każdy skonfigurowany przez Ciebie model oraz te na maszynach, z którymi się sparowałeś, we własnym selektorze modeli, więc zwykłe `pi` również do nich dociera. Może połączyć się także każdy klient zgodny z OpenAI: `status` pokazuje adres każdego modelu (pierwszy to `http://127.0.0.1:11435/v1`), nazwa receptury to model, a klucz znajduje się w `~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` usuwa model oraz pobrane pliki, których nie używa żaden inny model.

Środowiska uruchomieniowe firm trzecich są oznaczone ich wydawcą. Omarchy uruchamia każdy model bez dostępu do sieci.

### Lokalne LLM-y

Omarchy zaleca dwa sposoby uruchamiania lokalnych modeli LLM: LM Studio i Ollama. LM Studio zapewnia interfejs GUI do znajdowania modeli o otwartych wagach, instalowania ich i uruchamiania. To świetny sposób, aby łatwo zacząć. Ollama oferuje CLI do robienia tego w podobny sposób. Ale jeśli dopiero zaczynasz z modelami lokalnymi, zacząłbym od LM Studio. Możesz zainstalować każde z nich w _Install > AI_ w Omarchy Menu.

### Umiejętność Omarchy

Umiejętności agentów pomagają AI używać konkretnych narzędzi w konkretny sposób, a Omarchy jest dostarczane z domyślną umiejętnością do dostosowywania systemu. Taką jak podkręcanie konfiguracji Hyprland, dostosowywanie paska, a nawet tworzenie nowego motywu od zera. Jest ona dowiązana symbolicznie do katalogów umiejętności dla Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` i każdego `~/.hermes/profiles/*/skills`) oraz ogólnej lokalizacji `~/.agents/skills`, więc większość harnessów wykrywa ją automatycznie.

Ale powinieneś traktować tę umiejętność jako eksperymentalną. Różne modele będą jej używać z różnym skutkiem. Najlepiej najpierw uruchomić ją w trybie planowania, aby mieć pojęcie, co agent chciałby zmienić. A potem bądź gotowy wycofać zmiany, a nawet wywołać `omarchy reinstall configs`, jeśli agent narobi bałaganu we wszystkim.
