# AI

Omarchy zawiera programy uruchamiające dla poniższych agentów kodujących, ale nie wybiera za ciebie domyślnego. Uruchom polecenie, aby przy pierwszym użyciu zainstalować jego CLI, a następnie uwierzytelnij się, gdy pojawi się monit. Hermes jest wyjątkiem: nic nie jest dla niego instalowane przy pierwszym użyciu, a wybranie go instaluje Hermes Desktop, jak wyjaśnia sekcja _Desktop apps_ poniżej.

### Instalowanie i aktualizowanie agentów

Z wyjątkiem Hermesa, ci agenci korzystają z leniwej instalacji mise: pierwsze uruchomienie instaluje CLI, a kolejne uruchomienia używają go ponownie. mise sprawdza też, czy zainstalowany agent ma nowe wydanie, nie częściej niż raz na cztery godziny, tuż przed jego uruchomieniem lub w tle przy wierszu poleceń powłoki. Jeśli ta aktualizacja się nie powiedzie albo jesteś offline, uruchomi się zainstalowana wersja. `omarchy update` aktualizuje zainstalowanych agentów wraz z resztą Omarchy, a `mup` aktualizuje tylko narzędzia zarządzane przez mise.

Własny program aktualizujący agenta, taki jak `claude update`, `codex update` albo przycisk aktualizacji w aplikacji, nie aktualizuje instalacji zarządzanej przez mise. `codex update` kończy się niepowodzeniem, a `claude update` może zgłosić sukces, instalując przy tym osobną kopię, której mise nie śledzi. Jeśli wolisz używać natywnego instalatora i aktualizatora agenta, dodaj go do `disable_tools`; zobacz [Wstępnie zainstalowane narzędzia CLI](18-development-tools.md#preinstalled-cli-tools).

Aby zainstalować wszystkie skonfigurowane leniwe narzędzia, zanim będą ci potrzebne, uruchom `mise install --include-lazy`. Obejmuje to także pozostałe domyślne narzędzia CLI Omarchy, jak i agentów. Zobacz [Wstępnie zainstalowane narzędzia CLI](18-development-tools.md#preinstalled-cli-tools), aby dowiedzieć się, jak zainstalować pojedyncze narzędzie lub użyć własnej instalacji.

`grok` jest instalowany przez oficjalny pakiet `grok` mise, w ten sam sposób co `claude` i `codex`. Uruchom `grok` albo wybierz go w _Setup > Defaults > Agent_. Pomiń instalator `curl | bash` ze strony x.ai. Ta ścieżka umieszcza drugą kopię w `~/.grok/bin`, dodaje ją na początek `PATH` i nadpisuje wrapper Omarchy.

`dsh` otwiera swój interfejs w przeglądarce pod adresem `127.0.0.1:3080`, z katalogiem uruchomienia jako domyślnym obszarem roboczym. Jego interfejs w przeglądarce nie przyjmuje początkowego promptu, więc `omarchy agent prompt` otwiera go z promptem w schowku do wklejenia. Omarchy uruchamia go z presetem uprawnień bez zatwierdzania od DeepSeek. DeepSeek Harness przesyła logi sesji do DeepSeek, gdy używasz jego oficjalnego API modelu; wyłącz to w jego interfejsie w przeglądarce w _Settings > General > Upload Session Log_. Opinie, które mu wyślesz, są również przesyłane wraz z sesją, chyba że uruchomisz go z `DSH_TELEMETRY_MODE=DISABLED`.

### Domyślny agent

Wybierz domyślnego agenta poleceniem `omarchy default agent <name>` lub w _Setup > Defaults > Agent_ w Menu Omarchy (`Super + Space`). Jeśli agent nie jest jeszcze zainstalowany, wybranie go najpierw go zainstaluje. Świeże Omarchy zaprosi cię do dokonania tego wyboru jednorazowym powiadomieniem.

Wybranie Claude próbuje także skonfigurować jego rozszerzenie przeglądarki dla Chromium, Chrome, Brave, Brave Origin i Edge. Konfiguracja rozszerzenia dotyczy wszystkich użytkowników i może poprosić o hasło systemowe; anulowanie lub nieudana instalacja rozszerzenia nadal wybiera i uruchamia Claude. Uruchom ponownie przeglądarkę, włącz rozszerzenie, jeśli pojawi się monit, i zaloguj się do Claude, aby dokończyć łączenie. Uruchom `/chrome` w Claude, aby sprawdzić połączenie. Firefox i Zen nie obsługują tego rozszerzenia. Jeśli Claude był już twoim domyślnym agentem, zanim dodano tę konfigurację, wybierz go ponownie, aby zainstalować rozszerzenie.

Gdy już wybierzesz, `Super + Shift + Ctrl + A` uruchamia domyślnego agenta w dedykowanym oknie terminala (lub wywołuje selektor, jeśli jeszcze nie wybrałeś). Możesz też uruchomić go od razu do zadania poleceniem `omarchy agent prompt "Review this project"`. Freebuff i DeepSeek Harness nie przyjmują początkowego promptu, więc zamiast tego otwierają się z promptem w schowku do wklejenia. Agenci uruchomieni w ten sposób działają bez nadzoru w swoich odpowiednich trybach „nie zatrzymuj się, żeby pytać”, więc bądź gotowy na to, że naprawdę będą coś robić! MiniMax Code nie ma takiego trybu dla swoich interaktywnych sesji, więc pyta o uprawnienia jak zwykle. A ponieważ agenci odmawiają zapamiętywania zaufania dla twojego katalogu domowego, uruchomienia z `$HOME` startują zamiast tego w `~/Work`.

Są też skróty terminalowe: `a` uruchamia domyślnego agenta bezpośrednio w bieżącym terminalu, a `c`, `cx` i `cy` uruchamiają bezpośrednio OpenCode, Claude Code i Codex (ponownie w ich trybach automatycznego zatwierdzania). Zmiany motywu synchronizują się także z agentami: Claude Code, Pi, OpenCode i Hermes (gdy Omarchy go już zainstaluje) podążają za tobą, gdy przełączysz motyw Omarchy.

### Panel agentów

Górny pasek ma ikonę agentów. Zanim skonfigurujesz agenta, jego panel prowadzi cię przez logowanie do Claude, Codex lub Grok, a pierwszy z nich staje się twoim domyślnym agentem. Potem panel umieszcza każdą subskrypcję na jednej stronie: każdego agenta i konto wraz z jego planem, wskaźnik dla każdego z jego limitów sesji 5-godzinnej i tygodniowego wraz z czasem do jego zresetowania (najedź, aby zobaczyć dokładny procent) albo pozostałe saldo prepaid, pod wierszem, który rotacyjnie pokazuje, ile zużyłeś we wszystkich z nich, na przykład tokeny w tym tygodniu i najczęściej używany model. W sekcji _Make something_ oferuje startowe prompty dla nowego motywu, wtyczki lub aplikacji, które przekazują zadanie twojemu domyślnemu agentowi. Aplikacje są budowane tak, jak własne aplikacje Omarchy: Hype, Monologue i Omacut, w C++ i Qt Quick, zgodnie ze skillem agenta omarchy-app, a kompilator i elementy Qt, których potrzebują, są zainstalowane. Claude Code, Codex, Grok, Kimi, Cursor wraz z jego przydziałem Grok Bot, GitHub Copilot, Muse, Antigravity, Kimchi i Devin są obsługiwane od razu wraz z ich limitami, a Hermes, Mistral Vibe i Qwen Code pokazują swoje sesje i tokeny, gdy już ich użyjesz. Pojawiają się też plany i klucze dostawców, których używasz przez pi, omp lub opencode: OpenCode Zen i Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan i Synthetic wraz z ich limitami; Fireworks, OpenRouter i DeepSeek wraz z ich saldami prepaid; oraz modele, które uruchamiasz na własnym sprzęcie, w sekcji Local models. Każdy agent jest liczony raz, pod tym, kto go rozlicza, niezależnie od tego, przez ile harnessów go prowadzisz.

Kliknij lewym przyciskiem ikonę na pasku, aby otworzyć panel, a prawym, aby uruchomić domyślnego agenta. Rekordy użycia stojące za nim są regenerowane co 15 minut przez `omarchy agent usage-update`, a panel może nawet łączyć użycie z innych twoich maszyn przez zsynchronizowany folder. Pełne ustawienia znajdziesz w README w `$OMARCHY_PATH/shell/plugins/agents/`.

### Kilka subskrypcji

Jeśli płacisz za więcej niż jeden plan Claude, Codex lub Grok — na przykład osobisty Max i służbowy — Omarchy może utrzymywać je wszystkie zalogowane i przełączać się między nimi. Dodaj subskrypcję przyciskiem + w panelu agentów, który prowadzi cię przez to na miejscu, albo poleceniem `omarchy agent account add claude Work` (lub `codex`, albo `grok`). Instaluje CLI, jeśli go brakuje. Pierwsze konto u dostawcy loguje się przez twoją normalną przeglądarkę, dokładnie tam, gdzie CLI zawsze zagląda. Każde kolejne loguje się przez okno prywatne, aby konto, do którego twoja przeglądarka jest już zalogowana, nie zostało wybrane przez pomyłkę; zaloguj się tam jako konto, które dodajesz, i najpierw zamknij każde okno prywatne, które masz już otwarte. Nigdy nie wylogowuj się z CLI, aby to zrobić: wylogowanie unieważnia zapisane logowanie, a to konto trzeba by dodać ponownie.

Aby skopiować logowania subskrypcji na inną maszynę z Omarchy przez SSH, uruchom `omarchy agent account copy user@laptop`. Nadawca dostarcza tymczasowy odbiornik, gdy miejsce docelowe nie ma zainstalowanego żadnego, więc starsze maszyny z Omarchy mogą odbierać konta bez aktualizacji. Zainstalowane odbiorniki mają pierwszeństwo. Kopiuje to wszystkie subskrypcje Claude, Codex i Grok; dodaj nazwy dostawców, aby je wybrać, jak w `omarchy agent account copy laptop claude`. Nazwy kont i identyfikatory poleceń odpowiadają źródłu, w tym konta już obecne w miejscu docelowym. Niepowiązane konta docelowe otrzymują przyrostek liczbowy, jeśli ich nazwy są w konflikcie, a ustawienia, skille, wtyczki i historia rozmów pozostają lokalne dla każdej maszyny.

Istniejące poświadczenia w miejscu docelowym są zachowywane. Konto źródłowe już tam zalogowane ma zsynchronizowaną nazwę bez zastępowania jego poświadczeń; pozostałe konta są dodawane obok niego. Aby zastąpić zapisane poświadczenia dla pasujących kont, użyj `omarchy agent account copy --replace laptop claude` po zamknięciu sesji tego konta w miejscu docelowym. Świeże miejsce docelowe otrzymuje też aktywne konto i preferencje przełączania źródła; ugruntowane miejsce docelowe zachowuje własne.

Poświadczenia podróżują przez SSH i są przechowywane w prywatnych plikach w miejscu docelowym, więc kopiuj tylko na maszyny, którym ufasz. Jest to jednorazowa kopia, a nie bieżąca synchronizacja. Tokeny odświeżania Codex mogą zostać zrotowane przez inną maszynę, pozostawiając skopiowane logowanie w potrzebie odnowienia; osobne logowania pozostają najbardziej niezawodnym wyborem do jednoczesnego używania na kilku maszynach. Zobacz [wskazówki Codex dotyczące uwierzytelniania kont](https://developers.openai.com/codex/auth/ci-cd-auth).

Jedno konto na dostawcę jest aktywne, a każda nowa sesja zaczyna jako ono: `cx`, `cy`, zwykłe `claude`, `codex` lub `grok`, wszystko uruchomione przez `omarchy agent` oraz skrypty lub edytory, które znajdują CLI w `PATH`. Przełącz poleceniem `omarchy agent account use work` (i z powrotem poleceniem `omarchy agent account use main`) albo w panelu, naciskając numer konta, a potem `Enter` (lub klikając jego przycisk Use). Sesje, które już działają, pozostają na koncie, z którym wystartowały. Historia rozmów, ustawienia, skille i wtyczki są współdzielone między kontami, więc `claude --continue` w tym samym folderze podejmuje pracę tam, gdzie ją zostawiłeś na nowym koncie.

Przy więcej niż jednym koncie panel pokazuje limity każdego konta obok siebie, z zaznaczonym aktywnym. Domyślnie Omarchy powiadamia cię, gdy aktywne konto przekroczy 95% limitu, a kliknięcie powiadomienia przełącza na konto z największym zapasem. Najedź na wiersz konta w panelu i kliknij Autoswitch, który pojawia się obok Use (lub naciśnij `m`), albo uruchom `omarchy agent account mode auto`, aby przełączało się samo; gdy jest włączone, Autoswitch zajmuje miejsce Use, a ponowne kliknięcie wraca do powiadamiania. Dodaj liczbę, aby zmienić próg, jak w `omarchy agent account mode auto 90`. Jeśli każde konto jest powyżej progu, usłyszysz o tym raz, wraz z informacją, które konto zwolni się jako pierwsze. Gdy aktywne konto jest w granicach 15 punktów od swojego progu (80% przy domyślnym ustawieniu), jego limity są sprawdzane co trzy minuty, a nie co 15.

`omarchy agent account list` pokazuje każde konto i jego najnowsze limity, `omarchy agent account remove work` zapomina jedno, a `omarchy agent account rename primary Hey` zmienia nazwę jednego (lub kliknij nazwę konta w panelu). Te polecenia działają na kontach twojego domyślnego agenta; aby sięgnąć drugiego dostawcy, najpierw go nazwij, jak w `omarchy agent account use codex side`. Logowanie, które już miałeś w `~/.claude` lub `~/.codex`, jest kontem _Main_ i zostaje tam, gdzie jest. Konto nieużywane przez ponad około osiem godzin może pokazywać _Sign-in required_; kliknij je, aby zalogować to konto ponownie bezpośrednio w panelu, albo uruchom w nim sesję, która sama odświeży logowanie. Serwery MCP, które miałeś, gdy konto zostało dodane, przechodzą wraz z nim, ale te, które dodasz później poleceniem `claude mcp add`, trafiają tylko do konta, w którym je dodałeś. Claude Desktop i narzędzia skonfigurowane bezwzględną ścieżką do pliku binarnego CLI nie podążają za przełączeniem. Jawne `CLAUDE_CONFIG_DIR`, `CODEX_HOME` lub `GROK_HOME` ma pierwszeństwo przed wybranym kontem.

### Diagnozowanie awarii

Omarchy obserwuje systemd-coredump pod kątem awarii procesów. Gdy coś ulegnie błędowi segmentacji, otrzymasz powiadomienie „Process crashed” — kliknij je, a awaria zostanie przekazana twojemu domyślnemu agentowi wraz ze skillem diagnose-crash Omarchy, który prowadzi agenta przez ustalenie faktów ze zrzutu pamięci i podjęcie decyzji, czy awarię warto zgłosić upstream. Możesz też uruchomić to ręcznie dla dowolnego PID z `coredumpctl list` poleceniem `omarchy agent crash <pid>`.

Obserwowanie jest domyślnie włączone. Wyłącz je w _Trigger > Toggle > Crash Capture_ (lub poleceniem `omarchy toggle crash-capture`), a powiadomienia ustaną; `omarchy agent crash <pid>` nadal działa ręcznie.

Awarie można też wyciszać po jednym programie naraz, co właśnie oferuje ci diagnoza na końcu. `omarchy crash mute hyprland` zatrzymuje powiadomienia tylko dla tego programu, `omarchy crash mute hyprland off` przywraca je, a samo `omarchy crash mute` wypisuje, co wyciszyłeś. Przyjmuje ścieżkę pliku binarnego równie chętnie jak jego nazwę, więc `omarchy crash mute /usr/bin/hyprland` robi to samo. Nazwę ze spacją ujmij w cudzysłów, jak w `omarchy crash mute 'Some App'`. Wszystko inne nadal powiadamia, a wyciszony program nadal ulega awarii — to ukrywa przypomnienie, niczego nie naprawia.

### Aplikacje desktopowe

Menu _Install > AI_ zawiera też kilka graficznych aplikacji AI: aplikację desktopową ChatGPT, aplikację desktopową Claude (betę Anthropic na Linuksa, z zakładkami Chat, Cowork i Claude Code), Grok Bot do czatowania z modelami xAI, Herdr Desktop, Hermes Desktop, OpenClaw, aplikację desktopową Perplexity i T3 Code. Grok Bot jest desktopową aplikacją do czatu. Agentem kodującym jest polecenie `grok`.

Hermes Desktop jest tą, o której trzeba wiedzieć, ponieważ maszyna ma jednego Hermesa i należy on do aplikacji: Hermes jest instalowany wyłącznie przez aplikację, a polecenie `hermes`, które uruchamia domyślny agent, należy do aplikacji. Wybranie Hermesa jako domyślnego agenta instaluje to samo, co pozycja _Install > AI_: pakiet oraz środowisko uruchomieniowe Hermesa w `~/.hermes` skonfigurowane przez własny instalator Hermesa, co za pierwszym razem zajmuje kilka minut. To środowisko uruchomieniowe jest tym jedynym Hermesem, którego używają terminalowe polecenie `hermes`, domyślny agent i aplikacja, i aktualizuje się samo poleceniem `hermes update`, zamiast czekać na wydanie Omarchy. Zainstalowanie go przekazuje też Hermesowi motyw Omarchy jako skórkę o nazwie `omarchy`, za którą podąża każda powierzchnia Hermesa, gdy przełączasz motywy; wybierz inną w ustawieniach Appearance Hermesa lub poleceniem `/skin`, jeśli wolisz, żeby tak nie było, a Omarchy zostawi ten wybór w spokoju. Usunięcie aplikacji w _Remove > AI_ najpierw zamyka Hermesa, w tym bramkę, zabiera ze sobą to środowisko uruchomieniowe i zachowuje twoje czaty, wspomnienia oraz skille, które Hermes napisał dla siebie, chyba że powiesz inaczej: pyta, domyślnie odpowiadając nie, czy te dane i twoje ustawienia połączeń też powinny zniknąć.

Doświadczeniem desktopowym OpenClaw jest jego Control UI, które otwiera się jako aplikacja internetowa wspierana przez własną lokalną bramkę. OpenClaw mieszka w `~/.openclaw` i aktualizuje się sam: użyj przycisku „Update Gateway” w Control UI lub uruchom `openclaw update`, a bramka uruchomi się ponownie na nowej wersji. Omarchy wybiera jedynie wydanie, od którego zaczyna świeża instalacja. Usunięcie OpenClaw w _Remove > AI_ zabiera ze sobą usługę bramki i aplikację, a potem pyta, czy `~/.openclaw` też powinno zniknąć, ponieważ przechowuje twoje czaty i poświadczenia obok samego OpenClaw i środowisk uruchomieniowych wtyczek, które pobiera; domyślnie je zachowuje, a ponowne zainstalowanie OpenClaw je odzyska.

Herdr Desktop jest aplikacją desktopową [Herdr](https://herdr.dev): przestrzenie, karty i panele terminali oraz agentów kodujących, które nadal działają w jego rdzeniu, gdy zamkniesz okno. Pochodzi z własnego instalatora Herdr, a nie z pakietu, więc mieszka w `~/.local/share/herdr-app`, przynosi swój rdzeń w `~/.local/bin/herdr-core`, gdy jeszcze go nie masz, i aktualizuje oba samodzielnie. Stoi obok polecenia `herdr`, które Omarchy dostarcza na `Super + Ctrl + Return`, zamiast je zastępować. Zainstalowanie go wybiera motyw Omarchy dla Herdr, który od tej pory podąża za twoim motywem Omarchy. Herdr przechowuje jeden motyw dla trybu jasnego i jeden dla ciemnego, więc po przełączeniu między ciemnym a jasnym motywem Omarchy wybierz Omarchy jeszcze raz w selektorze motywów Herdr dla drugiego trybu.

T3 Code działa z oficjalnego wydania AppImage w `~/.local/share/t3code`, a nie z pakietu, więc aktualizuje się sam. Zainstalowanie go pyta, czy zacząć na kanale Stable czy Nightly; przełącz później w ustawieniach T3 Code. Twoje wątki i ustawienia mieszkają w `~/.t3`, a usunięcie T3 Code w _Remove > AI_ zabiera je ze sobą.

### Modele lokalne

Uruchom otwarty model na własnej maszynie dla swoich agentów kodujących. Twoje prompty i kod pozostają na maszynie; nic wysłanego do modelu jej nie opuszcza. Zacznij od:

```bash
omarchy agent local use best
```

Albo w panelu agentów na górnym pasku wybierz + , a potem Local AI, które pojawia się, gdy model pasuje do tej maszyny. Za pierwszym razem instaluje to Podman, który uruchamia modele, a na maszynie NVIDIA zestaw narzędzi kontenerowych NVIDIA, który daje im GPU. Następnie Omarchy wybiera zalecany model dla tej maszyny, pobiera go i uruchamia. Spodziewaj się pobrania dziesiątek GB i tego, że większość pamięci maszyny będzie używana, gdy model działa: Flash Next używa około 100 GiB przy pełnym kontekście 256K. Jeśli inne modele zajmują potrzebną mu pamięć, jest konfigurowany jako zatrzymany, gotowy do uruchomienia, gdy któryś zatrzymasz. Model zatrzymuje się przy wylogowaniu; zatrzymaj go sam, gdy potrzebujesz pamięci do czegoś innego.

`omarchy agent local list` pokazuje opcje i wyjaśnia, dlaczego niektóre nie pasują. Aby skonfigurować inny, uruchom `omarchy agent local use <recipe>`. Dziś `qwen3.8-flash-next-gufo` i `qwen3.8-27b-gufo` są dostępne dla maszyn Strix Halo ze 128 GB; 27B zajmuje około 40 GiB, więc zostawia miejsce na inną pracę. Nowe przepisy i zalecenia przychodzą z `omarchy update`, przez pakiet.

Każdy skonfigurowany model otrzymuje własny wiersz w panelu agentów, obok twoich subskrypcji: przycisk odtwarzania, aby go uruchomić, przycisk pauzy, aby go zatrzymać i zwolnić jego pamięć, oraz przycisk terminala, aby otworzyć na nim swojego agenta. Kilka może działać jednocześnie, gdy mieszczą się razem w pamięci; jeśli któryś się nie mieści, Omarchy mówi, który działający model zatrzymać. Przeciągaj wiersze, aby zmienić ich kolejność, i naciśnij Delete na wybranym wierszu, aby usunąć model i jego pobrane pliki.

Z wiersza poleceń `omarchy agent local start <recipe>` i `omarchy agent local stop <recipe>` robią to samo, `omarchy agent local status` pokazuje każdy model, a `omarchy agent --local` otwiera twojego domyślnego agenta na ostatnim modelu, który uruchomiłeś (pi, jeśli twój domyślny agent nie może używać modelu lokalnego). Może połączyć się też każdy klient zgodny z OpenAI: `status` pokazuje adres każdego modelu (pierwszy to `http://127.0.0.1:11435/v1`), nazwą modelu jest nazwa przepisu, a klucz znajduje się w `~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` usuwa model oraz pobrane pliki, których nie używa żaden inny model.

Środowiska uruchomieniowe firm trzecich są oznaczone swoim wydawcą. Omarchy uruchamia każdy model bez dostępu do sieci.

### Lokalne LLM-y

Omarchy zaleca dwa sposoby uruchamiania lokalnych modeli LLM: LM Studio i Ollama. LM Studio zapewnia interfejs GUI do znajdowania modeli o otwartych wagach, instalowania ich i uruchamiania. To świetny sposób, aby łatwo zacząć. Ollama oferuje CLI do robienia tego podobnie. Ale jeśli jesteś nowy w modelach lokalnych, zacząłbym od LM Studio. Możesz zainstalować każde z nich w _Install > AI_ w Menu Omarchy.

### Skill Omarchy

Skille agentów pomagają AI używać konkretnych narzędzi w konkretny sposób, a Omarchy dostarcza domyślny skill do dostosowywania systemu. Na przykład poprawianie konfiguracji Hyprland, regulowanie paska, a nawet tworzenie nowego motywu od zera. Jest dowiązany symbolicznie do katalogów skilli dla Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` oraz każdego `~/.hermes/profiles/*/skills`) oraz ogólnej lokalizacji `~/.agents/skills`, więc większość harnessów podchwytuje go automatycznie.

Ale powinieneś traktować ten skill jako eksperymentalny. Różne modele będą go używać z różnym skutkiem. Najlepiej najpierw uruchomić go w trybie planowania, abyś miał pojęcie, co agent chciałby zmienić. A potem bądź gotowy wycofać zmiany, a nawet wywołać `omarchy reinstall configs`, jeśli agent narobi bałaganu we wszystkim.
