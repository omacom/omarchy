# AI

Omarchy zawiera launchery dla poniższych agentów kodowania, nie wybierając za ciebie domyślnego. Uruchom polecenie, aby przy pierwszym użyciu zainstalować jego CLI, a następnie uwierzytelnij się, gdy pojawi się monit. Hermes i OpenClaw są wyjątkami: nic nie jest dla nich instalowane przez mise, a wybranie któregokolwiek z nich instaluje własną, samouaktualniającą się kopię, co wyjaśnia sekcja _Aplikacje desktopowe_ poniżej.

### Instalowanie i aktualizowanie agentów

Z wyjątkiem Hermes i OpenClaw, agenci ci korzystają z leniwej instalacji mise: pierwsze uruchomienie instaluje CLI, a kolejne uruchomienia używają go ponownie. mise sprawdza też zainstalowanego agenta pod kątem nowej wersji co najwyżej raz na cztery godziny, tuż przed jego uruchomieniem lub w tle przy prompcie powłoki. Jeśli ta aktualizacja się nie powiedzie lub jesteś offline, uruchomi się zainstalowana wersja. `omarchy update` aktualizuje zainstalowanych agentów wraz z resztą Omarchy, a `mup` aktualizuje tylko narzędzia zarządzane przez mise.

Własny aktualizator agenta, taki jak `claude update`, `codex update` lub przycisk aktualizacji w aplikacji, nie aktualizuje instalacji zarządzanej przez mise. `codex update` kończy się niepowodzeniem, a `claude update` może zgłosić sukces, instalując jednocześnie osobną kopię, której mise nie śledzi. Jeśli wolisz używać natywnego instalatora i aktualizatora agenta, dodaj go do `disable_tools`; zobacz [Wstępnie zainstalowane narzędzia CLI](18-development-tools.md#preinstalled-cli-tools).

Aby zainstalować wszystkie skonfigurowane leniwe narzędzia, zanim będą potrzebne, uruchom `mise install --include-lazy`. Obejmuje to także pozostałe domyślne narzędzia CLI Omarchy, jak również agentów. Zobacz [Wstępnie zainstalowane narzędzia CLI](18-development-tools.md#preinstalled-cli-tools), aby dowiedzieć się, jak zainstalować pojedyncze narzędzie lub użyć własnej instalacji.

`grok` jest instalowany przez oficjalny pakiet mise `grok`, w ten sam sposób co `claude` i `codex`. Uruchom `grok` lub wybierz go w _Agent > Harness_. Pomiń instalator `curl | bash` ze strony x.ai. Ta ścieżka umieszcza drugą kopię w `~/.grok/bin`, dodaje ją na początku `PATH` i nadpisuje wrapper Omarchy.

`dsh` otwiera swój interfejs przeglądarkowy pod adresem `127.0.0.1:3080`, z katalogiem uruchomienia jako domyślnym obszarem roboczym. Jego interfejs przeglądarkowy nie przyjmuje początkowego promptu, więc `omarchy agent prompt` otwiera go z promptem w schowku do wklejenia. Omarchy uruchamia go z presetem uprawnień DeepSeek bez zatwierdzania. DeepSeek Harness przesyła logi sesji do DeepSeek, gdy używasz jego oficjalnego API modeli; wyłącz to w _Settings > General > Upload Session Log_ w jego interfejsie przeglądarkowym. Opinie, które mu wysyłasz, są również przesyłane wraz z sesją, chyba że uruchomisz go z `DSH_TELEMETRY_MODE=DISABLED`.

### Domyślny agent

Wybierz domyślnego agenta poleceniem `omarchy default agent <name>` lub w _Agent > Harness_ w Omarchy Menu (`Super + Space`). Jeśli agent nie jest jeszcze zainstalowany, wybranie go najpierw go instaluje, a także otrzymuje własny launcher w launcherze aplikacji, obok Agent. Świeża instalacja Omarchy zaprosi cię do dokonania tego wyboru jednorazowym powiadomieniem.

Wybranie Claude próbuje również skonfigurować jego rozszerzenie przeglądarkowe dla Chromium, Chrome, Brave, Brave Origin i Edge. Konfiguracja rozszerzenia dotyczy wszystkich użytkowników i może poprosić o hasło systemowe; anulowanie lub nieudana instalacja rozszerzenia nadal wybiera i uruchamia Claude. Uruchom ponownie przeglądarkę, włącz rozszerzenie, jeśli pojawi się monit, i zaloguj się do Claude, aby dokończyć łączenie. Uruchom `/chrome` w Claude, aby sprawdzić połączenie. Firefox i Zen nie obsługują tego rozszerzenia. Jeśli Claude był już twoim domyślnym agentem, zanim dodano tę konfigurację, wybierz go ponownie, aby zainstalować rozszerzenie.

Po dokonaniu wyboru `Super + Shift + Ctrl + A` uruchamia domyślnego agenta w dedykowanym oknie terminala (lub wywołuje selektor, jeśli jeszcze nie wybrałeś). Możesz też uruchomić go od razu do zadania poleceniem `omarchy agent prompt "Review this project"`. Freebuff i DeepSeek Harness nie przyjmują początkowego promptu, więc otwierają się z promptem w schowku do wklejenia. Agenci uruchamiani w ten sposób działają bez nadzoru w swoich odpowiednich trybach „nie zatrzymuj się, aby pytać”, więc bądź gotowy, że naprawdę będą coś robić! MiniMax Code nie ma takiego trybu dla swoich sesji interaktywnych, więc pyta o uprawnienia jak zwykle. A ponieważ agenci odmawiają zapamiętania zaufania dla twojego katalogu domowego, uruchomienia z `$HOME` rozpoczynają się zamiast tego w `~/Work`.

Są też skróty terminalowe: `a` uruchamia domyślnego agenta w bieżącym terminalu, podczas gdy `c`, `cx` i `cy` uruchamiają bezpośrednio OpenCode, Claude Code i Codex (ponownie w ich trybach automatycznego zatwierdzania). Zmiany motywu synchronizują się również z agentami: Claude Code, Pi, OpenCode i Hermes (gdy Omarchy go zainstaluje) podążają za zmianą motywu Omarchy.

### Instrukcje dla twojego agenta

Osobiste zasady dla każdego agenta znajdują się w `~/.agents/AGENTS.md`, obok współdzielonych umiejętności w `~/.agents/skills`. Otwórz go w _Agent > Instructions_, co również tworzy dowiązanie do każdego harnessu, który przechowuje własny plik globalny: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` Copilot i tak dalej. Crush i Amp odczytują dowiązanie `~/.config/AGENTS.md`, podczas gdy omp, Kimi i DeepSeek Harness odczytują bezpośrednio `~/.agents/AGENTS.md`. Wybranie domyślnego agenta również tworzy dla niego dowiązanie. Plik instrukcji, który już miałeś, staje się współdzielonym, jeśli jeszcze go nie było; w przeciwnym razie jest przechowywany obok dowiązania jako `.bak`. Uruchom `omarchy agent instructions`, aby ponownie utworzyć dowiązania po zainstalowaniu kolejnego agenta.

### Panel agentów

Górny pasek ma ikonę agentów. Zanim skonfigurujesz agenta, jego panel przeprowadzi cię przez logowanie do Claude, Codex lub Grok, a pierwszy z nich stanie się twoim domyślnym agentem. Potem panel umieszcza każdą subskrypcję na jednej stronie: każdy agent i konto wraz z jego planem, wskaźnik dla każdego z jego 5-godzinnych limitów sesji i limitów tygodniowych wraz z czasem do resetu (najedź, aby zobaczyć dokładny procent) lub pozostałe przedpłacone saldo, pod linią, która rotuje przez to, czego użyłeś we wszystkich z nich, jak tokeny w tym tygodniu i najczęściej używany model. W sekcji _Make something cool_ oferuje prompty startowe dla nowego motywu, pluginu, aplikacji lub gry, które przekazują zadanie twojemu domyślnemu agentowi. Aplikacje są budowane tak, jak własne aplikacje Omarchy Hype, Monologue i Omacut, w C++ i Qt Quick, zgodnie z umiejętnością agenta omarchy-make-app, a kompilator i elementy Qt, których potrzebują, są zainstalowane. Gry to pojedyncza strona three.js w `~/Games/vibes`, zgodnie z umiejętnością agenta omarchy-make-game, i wszystkie otwierają się z jednego launchera Game Vibes w bieżącym motywie; ładują three.js z sieci, więc potrzebują połączenia, aby się uruchomić. Claude Code, Codex, Grok, Kimi, Cursor i jego pula Grok Bot, GitHub Copilot, Muse, Antigravity i Devin są obsługiwane od razu wraz ze swoimi limitami, Kimchi ze swoim planem, kredytami przedpłaconymi i budżetami wydatków, a Hermes, Mistral Vibe i Qwen Code pokazują swoje sesje i tokeny, gdy już ich użyjesz. Plany dostawców i klucze, których używasz przez pi, omp lub opencode, również się pojawiają: OpenCode Zen i Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan i Synthetic wraz ze swoimi limitami; OpenRouter i DeepSeek ze swoimi saldami przedpłaconymi; Fireworks ze swoimi wydatkami z ostatnich 30 dni. Tokeny z modeli, które uruchamiasz na własnym sprzęcie, również wliczają się do sum; same modele mają własny panel, opisany w sekcji [Modele lokalne](#local-models). Każdy agent jest liczony raz, u tego, kto go rozlicza, niezależnie od tego, przez ile harnessów go prowadzisz.

Kliknij lewym przyciskiem ikonę paska lub naciśnij `Super + Ctrl + X`, aby otworzyć panel, kliknij prawym, aby uruchomić domyślnego agenta, a środkowym, aby odświeżyć. Rekordy użycia stojące za nim są regenerowane co 15 minut przez `omarchy agent usage update`, a panel może nawet scalać użycie z innych twoich maszyn przez zsynchronizowany folder. Zobacz README w `$OMARCHY_PATH/shell/plugins/agents/` po pełne ustawienia.

### Kilka subskrypcji

Jeśli płacisz za więcej niż jeden plan Claude, Codex lub Grok — na przykład osobisty Max i służbowy — Omarchy może utrzymywać je wszystkie zalogowane i przełączać się między nimi. Dodaj subskrypcję przyciskiem + w panelu agentów, który od razu cię przez to przeprowadzi, lub poleceniem `omarchy agent account add claude Work` (lub `codex`, lub `grok`). Instaluje CLI, jeśli go brakuje. Pierwsze konto dla dostawcy loguje się przez twoją normalną przeglądarkę, dokładnie tam, gdzie CLI zawsze szuka. Każde kolejne loguje się przez okno prywatne, więc konto, do którego twoja przeglądarka jest już zalogowana, nie zostanie wybrane przez pomyłkę; zaloguj się tam jako konto, które dodajesz, i najpierw zamknij każde okno prywatne, które masz już otwarte. Nigdy nie wylogowuj się z CLI, aby to zrobić: wylogowanie unieważnia zapisane logowanie, a to konto trzeba byłoby dodać ponownie.

Aby skopiować logowania subskrypcji na inną maszynę Omarchy przez SSH, uruchom `omarchy agent account copy user@laptop`. Nadawca dostarcza tymczasowego odbiorcę, gdy miejsce docelowe nie ma zainstalowanego, więc starsze maszyny Omarchy mogą odbierać konta bez aktualizacji. Zainstalowani odbiorcy mają pierwszeństwo. Kopiuje to wszystkie subskrypcje Claude, Codex i Grok; dodaj nazwy dostawców, aby je wybrać, jak w `omarchy agent account copy laptop claude`. Nazwy kont i identyfikatory poleceń zgadzają się ze źródłem, w tym konta już obecne w miejscu docelowym. Niepowiązane konta docelowe otrzymują sufiks numeryczny, jeśli ich nazwy kolidują, a ustawienia, umiejętności, pluginy i historia konwersacji pozostają lokalne dla każdej maszyny.

Istniejące poświadczenia docelowe są zachowywane. Konto źródłowe już zalogowane tam ma zsynchronizowaną nazwę bez zastępowania jego poświadczeń; inne konta są dodawane obok niego. Aby zastąpić zapisane poświadczenia dla pasujących kont, użyj `omarchy agent account copy --replace laptop claude` po zakończeniu sesji tego konta w miejscu docelowym. Świeże miejsce docelowe otrzymuje również aktywne konto źródłowe i preferencje przełączania; ustalone miejsce docelowe zachowuje własne.

Poświadczenia podróżują przez SSH i są przechowywane w prywatnych plikach w miejscu docelowym, więc kopiuj tylko na maszyny, którym ufasz. To jednorazowa kopia, nie bieżąca synchronizacja. Tokeny odświeżania Codex mogą zostać zrotowane przez inną maszynę, pozostawiając skopiowane logowanie wymagające odnowienia; osobne logowania pozostają najbardziej niezawodnym wyborem do jednoczesnego użycia na kilku maszynach. Zobacz [wskazówki Codex dotyczące uwierzytelniania kont](https://developers.openai.com/codex/auth/ci-cd-auth).

Jedno konto na dostawcę jest aktywne, a każda nowa sesja zaczyna jako ono: `cx`, `cy`, zwykłe `claude`, `codex` lub `grok`, cokolwiek uruchomione przez `omarchy agent` oraz skrypty lub edytory, które znajdują CLI w `PATH`. Przełącz poleceniem `omarchy agent account use work` (i z powrotem poleceniem `omarchy agent account use main`) lub w panelu, naciskając numer konta, a następnie `Enter` (lub klikając jego przycisk Use). Działające sesje Claude również się przełączają, od następnej wiadomości: każda sesja Claude działa w `~/.claude`, które zawsze przechowuje logowanie aktywnego konta. Sesja Claude uruchomiona w folderze własnym konta przez starsze Omarchy przechowuje to logowanie do momentu zakończenia, więc przełączenie nazywa te sesje i kończy się samo, gdy znikną. Działające sesje Codex i Grok pozostają na koncie, z którym się rozpoczęły. Historia konwersacji, ustawienia, umiejętności i pluginy są współdzielone między kontami, więc `claude --continue` w tym samym folderze kontynuuje tam, gdzie skończyłeś na nowym koncie.

Mając więcej niż jedno konto, panel pokazuje limity każdego konta obok siebie, z zaznaczonym aktywnym. Domyślnie Omarchy powiadamia cię, gdy aktywne konto przekroczy 95% limitu, a kliknięcie powiadomienia przełącza na konto z największym zapasem. Najedź na linię konta w panelu i kliknij Autoswitch, które pojawia się obok Use (lub naciśnij `m`), albo uruchom `omarchy agent account mode auto`, aby przełączało się samo; gdy jest włączone, Autoswitch zajmuje miejsce Use, a ponowne kliknięcie wraca do powiadamiania. Dodaj liczbę, aby zmienić próg, jak w `omarchy agent account mode auto 90`. Jeśli każde konto przekracza próg, usłyszysz o tym raz, wraz z tym, które konto zwolni się jako pierwsze. Gdy aktywne konto jest w obrębie 15 punktów od swojego progu (80% przy domyślnym), jego limity są sprawdzane co trzy minuty, a nie co 15.

`omarchy agent account list` pokazuje każde konto i jego najnowsze limity, `omarchy agent account remove work` zapomina jedno, a `omarchy agent account rename primary Hey` zmienia nazwę jednego (lub kliknij nazwę konta w panelu). Polecenia te działają na kontach twojego domyślnego agenta; aby dotrzeć do innego dostawcy, najpierw go nazwij, jak w `omarchy agent account use codex side`. Logowanie, które już miałeś w `~/.claude` lub `~/.codex`, to konto _Main_. Konto Codex zostaje tam, gdzie jest; konto Claude czeka we własnym folderze, gdy inne konto jest aktywne. Konto nieużywane przez ponad około osiem godzin może pokazać _Sign-in required_; kliknij je, aby zalogować to konto ponownie bezpośrednio w panelu, lub przełącz się na nie i rozpocznij sesję, co samo odświeża logowanie. Serwery MCP, które dodajesz poleceniem `claude mcp add`, docierają do każdego konta Claude, ponieważ wszystkie działają w `~/.claude`; dla Codex i Grok serwery, które miałeś, gdy konto zostało dodane, trafiają do niego, ale późniejsze docierają tylko do konta, w którym je dodałeś. Claude Desktop przechowuje własne logowanie, a narzędzia Codex lub Grok skonfigurowane z bezwzględną ścieżką do binarki CLI nie podążają za przełączeniem. Wyraźne `CLAUDE_CONFIG_DIR`, `CODEX_HOME` lub `GROK_HOME` ma pierwszeństwo przed wybranym kontem.

### Diagnostyka awarii

Omarchy obserwuje systemd-coredump pod kątem awarii procesów. Gdy wybierzesz domyślnego agenta, każdy twój program, który zrzuca core, wywoła powiadomienie „Process crashed” — kliknij je, a awaria zostanie przekazana twojemu domyślnemu agentowi wraz z umiejętnością Omarchy omarchy-diagnose-crash, która prowadzi agenta przez ustalenie faktów ze zrzutu core i podjęcie decyzji, czy awarię warto zgłosić upstream. Możesz też uruchomić ją ręcznie dla dowolnego PID z `coredumpctl list` poleceniem `omarchy agent crash <pid>`.

Obserwowanie jest domyślnie włączone. Wyłącz je w _Trigger > Toggle > Crash Capture Off_ (lub poleceniem `omarchy toggle crash-capture`), a powiadomienia ustaną; `omarchy agent crash <pid>` nadal działa ręcznie.

Awarie można też wyciszać po jednym programie naraz, co diagnostyka oferuje na końcu. `omarchy crash mute hyprland` zatrzymuje powiadomienia tylko dla tego programu, `omarchy crash mute hyprland off` przywraca je, a samo `omarchy crash mute` listuje, co wyciszyłeś. Przyjmuje ścieżkę binarki równie chętnie jak jej nazwę, więc `omarchy crash mute /usr/bin/hyprland` robi to samo. Cytuj nazwę ze spacją, jak w `omarchy crash mute 'Some App'`. Wszystko inne nadal powiadamia, a wyciszony program nadal się awaryjnie kończy — to ukrywa przypomnienie, niczego nie naprawia.

### Aplikacje desktopowe

Menu _Install > AI_ zawiera też kilka graficznych aplikacji AI: Amp Desktop, Antigravity Desktop, aplikację desktopową ChatGPT, aplikację desktopową Claude (betę Anthropic na Linuksa, z zakładkami Chat, Cowork i Claude Code), Grok Bot do czatowania z modelami xAI, Herdr Desktop, Hermes Desktop, OpenClaw, aplikację desktopową Perplexity i T3 Code. Grok Bot to desktopowa aplikacja czatu. Agentem kodowania jest polecenie `grok`.

Hermes Desktop jest tą, o której warto wiedzieć, ponieważ maszyna ma jednego Hermesa i należy on do aplikacji: Hermes jest instalowany wyłącznie przez aplikację, a polecenie `hermes`, które uruchamia domyślny agent, jest poleceniem aplikacji. Wybranie Hermesa jako domyślnego agenta instaluje to samo, co pozycja _Install > AI_: pakiet oraz runtime Hermes w `~/.hermes` skonfigurowany przez własny instalator Hermesa, co za pierwszym razem zajmuje kilka minut. Ten runtime to ten jedyny Hermes, którego używają terminalowe polecenie `hermes`, domyślny agent i aplikacja, i aktualizuje się sam poleceniem `hermes update`, zamiast czekać na wydanie Omarchy. Zainstalowanie go przekazuje też Hermes motyw Omarchy jako skórkę o nazwie `omarchy`, za którą podąża każda powierzchnia Hermes, gdy przełączasz motywy; wybierz inną w ustawieniach Appearance Hermes lub poleceniem `/skin`, jeśli wolisz, aby tak nie było, a Omarchy pozostawi ten wybór w spokoju. Usunięcie aplikacji w _Remove > AI_ najpierw zamyka Hermes, w tym gateway, zabiera ten runtime ze sobą i zachowuje twoje czaty, wspomnienia i umiejętności, które Hermes napisał dla siebie, chyba że powiesz inaczej: pyta, domyślnie na nie, czy te dane i twoje ustawienia połączeń też powinny zniknąć.

Doświadczenie desktopowe OpenClaw to jego Control UI, które otwiera się jako aplikacja webowa wspierana przez własny lokalny gateway. OpenClaw mieszka w `~/.openclaw` i aktualizuje się sam: użyj przycisku „Update Gateway” w Control UI lub uruchom `openclaw update`, a gateway uruchomi się ponownie na nowej wersji. Omarchy wybiera jedynie wydanie, od którego zaczyna świeża instalacja. OpenClaw może też być twoim domyślnym agentem: wybranie go w _Agent > Harness_ konfiguruje tę samą kopię w `~/.openclaw`, a agent otwiera terminalowy interfejs OpenClaw podłączony do jego gateway. Usunięcie OpenClaw w _Remove > AI_ zabiera usługę gateway i aplikację ze sobą, a następnie pyta, czy `~/.openclaw` też powinno zniknąć, ponieważ przechowuje twoje czaty i poświadczenia obok samego OpenClaw i runtime'ów pluginów, które pobiera; domyślnie je zachowuje, a ponowne zainstalowanie OpenClaw je odzyska.

Herdr Desktop to aplikacja desktopowa [Herdr](https://herdr.dev): przestrzenie, karty i panele terminali i agentów kodowania, które nadal działają w jego rdzeniu, gdy zamkniesz okno. Pochodzi z własnego instalatora Herdr, a nie z pakietu, więc mieszka w `~/.local/share/herdr-app`, przynosi swój rdzeń w `~/.local/bin/herdr-core`, gdy jeszcze go nie masz, i aktualizuje oba sama. Siedzi obok polecenia `herdr`, które Omarchy dostarcza na `Super + Ctrl + Return`, zamiast je zastępować, i otrzymuje bezpośrednie klawisze tego polecenia: `Alt + Return` i `Alt + Shift + Return` dzielą panel w dół lub w prawo, `Alt + Escape` go zamyka, `Ctrl + Alt + Arrow` przemieszcza między panelami, `Alt + 1..9` i `Alt + Left/Right` wybierają kartę, a `Alt + Up/Down` przemieszczają między przestrzeniami. `Ctrl + 1..9` wybiera przestrzeń, a `Alt + Shift + Up/Down` przechodzi przez agentów. Klawisze prefiksowe `Ctrl + Space` pozostają tylko terminalowe, ponieważ aplikacja nie może przytrzymać zwykłego klawisza Ctrl dla sekwencji. Omarchy zapisuje je do `~/.config/herdr-app/keys.json`, a `omarchy-refresh-herdr-app` je przywraca. Zainstalowanie go wybiera motyw Omarchy Herdr, który od tego czasu podąża za twoim motywem Omarchy. Herdr przechowuje jeden motyw dla trybu jasnego i jeden dla ciemnego, więc po przełączeniu między ciemnym a jasnym motywem Omarchy wybierz Omarchy w selektorze motywów Herdr jeszcze raz dla drugiego trybu.

T3 Code działa z oficjalnego wydania AppImage w `~/.local/share/t3code`, a nie z pakietu, więc aktualizuje się sam. Zainstalowanie go pyta, czy zacząć na kanale Stable czy Nightly; przełącz później w ustawieniach T3 Code. Twoje wątki i ustawienia mieszkają w `~/.t3`, a usunięcie T3 Code w _Remove > AI_ zabiera je ze sobą.

### Modele lokalne

Uruchom otwarty model na własnej maszynie dla swoich agentów kodowania. Twoje prompty i kod pozostają na maszynie; nic wysłanego do modelu jej nie opuszcza. Zacznij od:

```bash
omarchy models use best text
```

To konfiguruje najlepszy model tekstowy dla tej maszyny, ten rodzaj, którego używają twoi agenci. Modele obrazów, wideo i muzyki mają swój własny najlepszy: `omarchy models use best image`, `video` lub `music`. Uruchom `omarchy models use best`, aby zobaczyć wybór dla każdego rodzaju na tej maszynie.

Albo otwórz panel modeli lokalnych z jego ikony błysków na górnym pasku, obok ikony agentów, lub za pomocą Super + Ctrl + Alt + X, i wybierz +. Ikona pojawia się, gdy model pasuje do tej maszyny. Podman, który uruchamia modele, jest dostarczany z Omarchy, podobnie jak zestaw narzędzi kontenerowych NVIDIA na maszynie NVIDIA, który daje im GPU; jeśli któregoś brakuje, pierwsza konfiguracja go instaluje. Omarchy następnie wybiera zalecany model dla tej maszyny, pobiera go i uruchamia. Spodziewaj się pobrania dziesiątek GB i większości pamięci maszyny w użyciu, gdy model działa: Flash Next używa około 100 GiB przy pełnym kontekście 256K. Jeśli inne modele zajmują potrzebną mu pamięć, jest konfigurowany jako zatrzymany, gotowy do uruchomienia, gdy jeden zatrzymasz. Model zatrzymuje się przy wylogowaniu; zatrzymaj go sam, gdy potrzebujesz pamięci do czegoś innego.

`omarchy models list` pokazuje opcje i wyjaśnia, dlaczego niektóre nie pasują. Aby skonfigurować inny, uruchom `omarchy models use <recipe>`. Dziś `qwen3.8-flash-next-gufo` i `qwen3.8-27b-gufo` są dostępne dla maszyn Strix Halo 128 GB; 27B zajmuje około 40 GiB, więc zostawia miejsce na inną pracę. Na laptopie 64 GB z Intel Arc B390 `qwen3.6-35b-a3b-llamacpp` działa w około 30 GiB. Nowe receptury i zalecenia przychodzą z `omarchy update`, przez pakiet.

Każdy skonfigurowany model otrzymuje własną linię w panelu modeli lokalnych: play, aby go uruchomić, pause, aby go zatrzymać i zwolnić jego pamięć, oraz przycisk terminala, aby otworzyć na nim swojego agenta. Na górze pasek pokazuje, jak pamięć maszyny jest podzielona między samo Omarchy (system i twoje aplikacje), każdy działający model i to, co jest wolne. Wskaż zatrzymany model, a pasek pokaże, czy pasuje, lub ile mu brakuje. Kilka może działać naraz, gdy mieszczą się razem w pamięci; jeśli jeden nie pasuje, Omarchy powie, który działający model zatrzymać. Przeciągaj linie za ich logo, aby zmienić ich kolejność, i naciśnij Delete na wybranej linii, aby usunąć model i jego pobranie.

Każdy model kodowania, który skonfigurujesz, otrzymuje też własny wpis w launcherze aplikacji, pod nazwą modelu i z logo jego twórcy, tak jak zalogowanie się do Claude, Codex lub Grok dodaje taki wpis. Otwiera twojego agenta na tym modelu i najpierw uruchamia model, jeśli nie działa: terminal pokazuje jego ładowanie i przekazuje kontrolę agentowi, gdy jest gotowy. Usunięcie modelu usuwa jego wpis.

Nie każdy model służy do kodowania. Modele obrazów, wideo i muzyki otwierają się zamiast tego w Fantasi, aplikacji Omarchy do tworzenia obrazów, wideo i muzyki przy użyciu modelu działającego na tej maszynie, wybrane tam lub z ich linii w panelu modeli lokalnych.

Model nadal działa dokładnie tak, jak został skonfigurowany, więc aktualizacja Omarchy nigdy nie uruchamia go ponownie pod twoimi agentami. Gdy Omarchy ma nowszy runtime lub nowsze wagi dla modelu, który skonfigurowałeś, jego linia pokazuje przycisk aktualizacji: naciśnij go, a model zostanie ponownie skonfigurowany w tle, pobierając tylko to, co się zmieniło, i uruchomi się ponownie na nowej wersji. Model, który był zatrzymany, pozostaje zatrzymany. `omarchy models update` robi to samo dla każdego modelu z terminala.

Z linii poleceń `omarchy models start <recipe>` i `omarchy models stop <recipe>` robią to samo, `omarchy models status` pokazuje każdy model, a `omarchy agent --local` otwiera twojego domyślnego agenta na ostatnim uruchomionym modelu. pi, OpenCode i Qwen Code mogą używać jednego; przy każdym innym domyślnym otwiera się w pi lub w OpenCode, jeśli nie masz pi. pi listuje też każdy skonfigurowany model oraz te na maszynach, z którymi jesteś sparowany, we własnym selektorze modeli, więc zwykłe `pi` też do nich dociera. Każdy klient kompatybilny z OpenAI też może się połączyć: `status` pokazuje adres każdego modelu (pierwszy to `http://127.0.0.1:11435/v1`), nazwa receptury jest modelem, a klucz znajduje się w `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` usuwa model i pobrania, których żaden inny model nie używa.

Runtime'y firm trzecich są oznaczone ich wydawcą. Omarchy uruchamia każdy model bez dostępu do sieci.

### Lokalne LLM-y

Omarchy zaleca dwa sposoby uruchamiania lokalnych modeli LLM: LM Studio i Ollama. LM Studio zapewnia interfejs GUI do znajdowania modeli o otwartych wagach, instalowania ich i uruchamiania. To świetny sposób, aby łatwo zacząć. Ollama oferuje CLI do robienia tego w podobny sposób. Ale jeśli jesteś nowy w modelach lokalnych, zacząłbym od LM Studio. Możesz zainstalować każde z nich w _Install > AI_ w Omarchy Menu.

### Umiejętności Omarchy

Umiejętności agentów pomagają AI używać konkretnych narzędzi w konkretny sposób, a Omarchy dostarcza siedem z nich. Umiejętność omarchy obejmuje dostosowywanie systemu, jak poprawianie konfiguracji Hyprland lub dostosowywanie paska. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app i omarchy-make-game obejmują tworzenie czegoś nowego, omarchy-contribute obejmuje zgłaszanie błędu lub wysyłanie poprawki upstream, a omarchy-diagnose-crash analizuje zrzut core awarii. Są dowiązane do katalogów umiejętności dla Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` i każdy `~/.hermes/profiles/*/skills`) oraz ogólnej lokalizacji `~/.agents/skills`, więc większość harnessów odbiera je automatycznie. Własny folder umiejętności o tej samej nazwie ma pierwszeństwo.

Ale powinieneś traktować te umiejętności jako eksperymentalne. Różne modele będą je wykorzystywać z różnym skutkiem. Najlepiej najpierw działać w trybie planu, abyś miał pojęcie, co agent chciałby zmienić. A potem bądź gotowy cofnąć zmiany lub nawet wywołać `omarchy reinstall configs`, jeśli agent narobi bałaganu we wszystkim.
