# AI

Omarchy zawiera programy uruchamiające poniższych agentów kodujących, ale nie wybiera za Ciebie domyślnego. Uruchom polecenie, aby przy pierwszym użyciu zainstalować jego CLI, a następnie uwierzytelnij się, gdy pojawi się monit. Hermes i OpenClaw są wyjątkami: nic nie jest dla nich instalowane przez mise, a wybranie któregoś z nich instaluje jego własną, samoczynnie aktualizującą się kopię, jak wyjaśnia sekcja _Aplikacje desktopowe_ poniżej.

### Instalowanie i aktualizowanie agentów

Z wyjątkiem Hermes i OpenClaw, agenci ci korzystają z leniwej instalacji mise: pierwsze uruchomienie instaluje CLI, a kolejne uruchomienia używają go ponownie. mise sprawdza również, czy dla zainstalowanego agenta dostępna jest nowa wersja, co najwyżej raz na cztery godziny, tuż przed jego uruchomieniem lub w tle przy znaku zachęty powłoki. Jeśli ta aktualizacja się nie powiedzie lub jesteś offline, uruchomi się zainstalowana wersja. `omarchy update` aktualizuje zainstalowanych agentów wraz z resztą Omarchy, a `mup` aktualizuje tylko narzędzia zarządzane przez mise.

Własny aktualizator agenta, taki jak `claude update`, `codex update` lub przycisk aktualizacji w aplikacji, nie aktualizuje instalacji zarządzanej przez mise. `codex update` kończy się niepowodzeniem, a `claude update` może zgłosić sukces, instalując jednocześnie osobną kopię, której mise nie śledzi. Jeśli wolisz używać natywnego instalatora i aktualizatora agenta, dodaj go do `disable_tools`; zobacz [Wstępnie zainstalowane narzędzia CLI](18-development-tools.md#preinstalled-cli-tools).

Aby zainstalować wszystkie skonfigurowane narzędzia lazy, zanim będą Ci potrzebne, uruchom `mise install --include-lazy`. Obejmuje to również inne domyślne narzędzia CLI Omarchy, a także agentów. Zobacz [Wstępnie zainstalowane narzędzia CLI](18-development-tools.md#preinstalled-cli-tools), aby dowiedzieć się, jak zainstalować pojedyncze narzędzie lub używać własnej instalacji.

`grok` jest instalowany przez oficjalny pakiet `grok` mise, w ten sam sposób co `claude` i `codex`. Uruchom `grok` lub oznacz go gwiazdką w panelu agentów. Pomiń instalator `curl | bash` ze strony x.ai. Ta ścieżka umieszcza drugą kopię w `~/.grok/bin`, stawia ją na początku `PATH` i nadpisuje wrapper Omarchy.

`dsh` otwiera swój interfejs przeglądarkowy pod adresem `127.0.0.1:3080`, z katalogiem uruchomienia jako domyślnym obszarem roboczym. Jego interfejs przeglądarkowy nie przyjmuje początkowego promptu, więc `omarchy agent prompt` otwiera go z promptem w schowku do wklejenia. Omarchy uruchamia go z presetem uprawnień bez zatwierdzania DeepSeek. DeepSeek Harness przesyła dzienniki sesji do DeepSeek, gdy korzystasz z jego oficjalnego API modeli; wyłącz to w jego interfejsie przeglądarkowym w _Settings > General > Upload Session Log_. Opinie, które mu wysyłasz, są również przesyłane wraz z sesją, chyba że uruchomisz go z `DSH_TELEMETRY_MODE=DISABLED`.

### Domyślny agent

Wybierz domyślnego agenta za pomocą gwiazdki obok agenta w panelu agentów, która jest wypełniona przy domyślnym, lub za pomocą `omarchy default agent <name>`, które przyjmuje również dowolny harness niemający tam swojego wiersza. Jeśli agent nie jest jeszcze zainstalowany, wybranie go najpierw go zainstaluje, a otrzyma on również własny program uruchamiający w launcherze aplikacji, obok Agent. Świeża instalacja Omarchy zaprasza Cię do skonfigurowania jednego za pomocą jednorazowego powiadomienia, które otwiera panel agentów.

Wybranie Claude próbuje również skonfigurować jego rozszerzenie przeglądarkowe dla Chromium, Chrome, Brave, Brave Origin i Edge. Konfiguracja rozszerzenia dotyczy wszystkich użytkowników i może poprosić o hasło systemowe; anulowanie lub nieudana instalacja rozszerzenia nadal wybiera i uruchamia Claude. Uruchom ponownie przeglądarkę, włącz rozszerzenie, jeśli pojawi się monit, i zaloguj się do Claude, aby dokończyć łączenie. Uruchom `/chrome` w Claude, aby sprawdzić połączenie. Firefox i Zen nie obsługują tego rozszerzenia. Jeśli Claude był już Twoim domyślnym agentem, zanim dodano tę konfigurację, wybierz go ponownie, aby zainstalować rozszerzenie.

Po dokonaniu wyboru `Super + Shift + Ctrl + A` uruchamia domyślnego agenta w dedykowanym oknie terminala (lub wywołuje selektor, jeśli jeszcze go nie wybrałeś). Możesz też uruchomić go od razu do zadania za pomocą `omarchy agent prompt "Review this project"`. Freebuff i DeepSeek Harness nie przyjmują początkowego promptu, więc zamiast tego otwierają się z promptem w schowku do wklejenia. Agenci uruchamiani w ten sposób działają bez nadzoru w swoich odpowiednich trybach „nie zatrzymuj się, aby pytać”, więc bądź gotów na to, że naprawdę będą coś robić! MiniMax Code nie ma takiego trybu dla swoich sesji interaktywnych, więc pyta o uprawnienia jak zwykle. A ponieważ agenci odmawiają zapamiętania zaufania dla Twojego katalogu domowego, uruchomienia z `$HOME` zaczynają się zamiast tego w `~/Work`.

Istnieją też skróty terminalowe: `a` uruchamia domyślnego agenta bezpośrednio w bieżącym terminalu, natomiast `c`, `cx` i `cy` uruchamiają bezpośrednio OpenCode, Claude Code i Codex (ponownie w ich trybach automatycznego zatwierdzania). Zmiany motywu synchronizują się również z agentami: Claude Code, Pi, OpenCode i Hermes (gdy Omarchy go zainstaluje) podążają za Tobą, gdy przełączasz motyw Omarchy.

### Twoje instrukcje dla agentów

Osobiste reguły dla każdego agenta znajdują się w `~/.agents/AGENTS.md`, obok współdzielonych umiejętności w `~/.agents/skills`. Otwórz go za pomocą ikony dokumentu obok + w panelu agentów lub `omarchy agent instructions --edit`, które linkuje go również do każdego harnessu przechowującego własny plik globalny: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` Copilot itd. Crush i Amp odczytują link `~/.config/AGENTS.md`, natomiast omp, Kimi i DeepSeek Harness odczytują bezpośrednio `~/.agents/AGENTS.md`. Wybranie domyślnego agenta również go linkuje. Plik instrukcji, który już miałeś, staje się współdzielonym, jeśli jeszcze go nie było; w przeciwnym razie jest przechowywany obok linku jako `.bak`. Uruchom `omarchy agent instructions`, aby ponownie połączyć po zainstalowaniu kolejnego agenta.

### Panel agentów

Na górnym pasku znajduje się ikona agentów. Zanim skonfigurujesz agenta, jego panel oferuje trzy sposoby rozpoczęcia: zaloguj się do subskrypcji Claude, Codex, Grok, Gemini, Muse, Cursor lub Copilot, albo w sekcji More wybierz plan kodowania OpenCode Go, MiniMax, Synthetic lub Z.ai; płać na bieżąco z Fireworks, OpenCode Zen i Go, OpenRouter, albo w sekcji More z DeepSeek lub dowolnym innym dostawcą, do którego loguje się OpenCode — wszystko działa w OpenCode; albo uruchom najlepszy model dla swojego komputera, gdy jakiś do niego pasuje. Pierwszy, który ukończysz, staje się Twoim domyślnym agentem, a przycisk + w panelu lub _Agent > Add_ w Menu Omarchy oferuje później te same trzy opcje. Po tym panel umieszcza każdą subskrypcję na jednej stronie: każdy agent i konto wraz z jego planem, wskaźnik dla każdego z jego 5-godzinnych limitów sesji i tygodniowych limitów wraz z czasem do ich zresetowania (najedź kursorem, aby zobaczyć dokładny procent) lub pozostałe przedpłacone saldo, pod wierszem, który rotuje przez to, czego użyłeś we wszystkich z nich, np. tokeny w tym tygodniu i Twój najczęściej używany model. W sekcji _Make something cool_ oferuje prompty startowe dla nowego motywu, wtyczki, aplikacji lub gry, które przekazują zadanie Twojemu domyślnemu agentowi. Aplikacje są budowane tak, jak własne Hype, Monologue i Omacut Omarchy, w C++ i Qt Quick, zgodnie z umiejętnością agenta omarchy-make-app, a kompilator i potrzebne im elementy Qt są zainstalowane. Gry to pojedyncza strona three.js w `~/Games/vibes`, zgodna z umiejętnością agenta omarchy-make-game, a wszystkie otwierają się z jednego launchera Game Vibes w bieżącym motywie; ładują three.js z sieci, więc do uruchomienia potrzebują połączenia. Claude Code, Codex, Grok, Kimi, Cursor i jego pula Grok Bot, GitHub Copilot, Muse, Gemini (przez Antigravity) i Devin są obsługiwane od razu wraz ze swoimi limitami, Kimchi ze swoim planem, przedpłaconymi kredytami i budżetami wydatków, a Hermes, Mistral Vibe i Qwen Code pokazują swoje sesje i tokeny, gdy już ich użyjesz. Plany dostawców i klucze, których używasz przez pi, omp lub opencode, również się pojawiają: OpenCode Zen i Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan i Synthetic wraz z ich limitami; OpenRouter i DeepSeek z ich przedpłaconymi saldami; Fireworks z wydatkami z ostatnich 30 dni. Tokeny z modeli, które uruchamiasz na własnym sprzęcie, również wliczają się do sum; same modele mają własny panel, opisany w sekcji [Modele lokalne](#local-models). Każdy agent jest liczony raz, u tego, kto go rozlicza, niezależnie od tego, przez ile harnessów go prowadzisz.

Kliknij lewym przyciskiem myszy ikonę paska lub naciśnij `Super + Ctrl + X`, aby otworzyć panel, kliknij prawym przyciskiem, aby uruchomić domyślnego agenta, a środkowym, aby odświeżyć. Rekordy użycia stojące za nim są regenerowane co 15 minut przez `omarchy agent usage update`, a panel może nawet łączyć użycie z innych Twoich maszyn za pośrednictwem zsynchronizowanego folderu. Zobacz README w `$OMARCHY_PATH/shell/plugins/agents/`, aby poznać pełne ustawienia.

### Kilka subskrypcji

Jeśli płacisz za więcej niż jeden plan Claude, Codex lub Grok — na przykład osobisty Max i służbowy — Omarchy może utrzymać je wszystkie zalogowane i przełączać się między nimi. Dodaj subskrypcję za pomocą + w panelu agentów, który przeprowadzi Cię przez to od razu tam, lub za pomocą `omarchy agent account add claude Work` (lub `codex`, lub `grok`). Ten sam + i polecenie logują do Gemini (`gemini`) i OpenCode (`opencode`) oraz zapisują klucz API Fireworks (`fireworks`) lub OpenRouter (`openrouter`) w OpenCode; polecenie loguje również do Copilot (`copilot`), Cursor (`cursor`) i Muse (`muse`). Te zachowują po jednym zalogowaniu każde. Instaluje CLI, jeśli go brakuje. Pierwsze konto dla dostawcy loguje się przez Twoją normalną przeglądarkę, dokładnie tam, gdzie CLI zawsze szuka. Każde kolejne loguje się przez okno prywatne, więc konto, do którego Twoja przeglądarka jest już zalogowana, nie zostanie pomyłkowo przechwycone; zaloguj się tam jako konto, które dodajesz, i najpierw zamknij każde okno prywatne, które już masz otwarte. Nigdy nie wylogowuj się z CLI, aby to zrobić: wylogowanie unieważnia zapisane logowanie, a to konto musiałoby zostać dodane ponownie.

Aby skopiować logowania do subskrypcji na inną maszynę Omarchy przez SSH, uruchom `omarchy agent account copy user@laptop`. Nadawca dostarcza tymczasowy odbiornik, gdy maszyna docelowa nie ma zainstalowanego, więc starsze maszyny Omarchy mogą odbierać konta bez aktualizacji. Zainstalowane odbiorniki mają pierwszeństwo. Kopiuje to wszystkie subskrypcje Claude, Codex i Grok; dodaj nazwy dostawców, aby je wybrać, np. `omarchy agent account copy laptop claude`. Nazwy kont i identyfikatory poleceń odpowiadają źródłu, w tym konta już obecne na maszynie docelowej. Niepowiązane konta docelowe otrzymują sufiks numeryczny, jeśli ich nazwy kolidują, a ustawienia, umiejętności, wtyczki i historia rozmów pozostają lokalne dla każdej maszyny.

Istniejące dane uwierzytelniające na maszynie docelowej są zachowywane. Konto źródłowe już zalogowane tam ma zsynchronizowaną nazwę bez zastępowania jego danych uwierzytelniających; pozostałe konta są dodawane obok niego. Aby zastąpić zapisane dane uwierzytelniające dla pasujących kont, użyj `omarchy agent account copy --replace laptop claude` po zamknięciu sesji tego konta na maszynie docelowej. Świeża maszyna docelowa otrzymuje również aktywne konto źródłowe i preferencje przełączania; ugruntowana maszyna docelowa zachowuje własne.

Dane uwierzytelniające podróżują przez SSH i są przechowywane w prywatnych plikach na maszynie docelowej, więc kopiuj tylko na maszyny, którym ufasz. Jest to jednorazowa kopia, a nie bieżąca synchronizacja. Tokeny odświeżania Codex mogą zostać zrotowane przez inną maszynę, pozostawiając skopiowane logowanie wymagające odnowienia; osobne logowania pozostają najbardziej niezawodnym wyborem do jednoczesnego używania na kilku maszynach. Zobacz [wskazówki Codex dotyczące uwierzytelniania konta](https://developers.openai.com/codex/auth/ci-cd-auth).

Jedno konto na dostawcę jest aktywne, a każda nowa sesja zaczyna się jako ono: `cx`, `cy`, zwykłe `claude`, `codex` lub `grok`, wszystko uruchamiane przez `omarchy agent` oraz skrypty lub edytory, które znajdują CLI w `PATH`. Przełączaj za pomocą `omarchy agent account use work` (i z powrotem za pomocą `omarchy agent account use main`) lub w panelu, naciskając numer konta, a następnie `Enter` (lub klikając jego gwiazdkę). Działające sesje Claude również się przełączają, od następnej wiadomości: każda sesja Claude działa w `~/.claude`, który zawsze przechowuje logowanie aktywnego konta. Sesja Claude uruchomiona we własnym folderze konta przez starszą wersję Omarchy zachowuje to logowanie do momentu zakończenia, więc przełączenie nazywa te sesje i kończy się samo, gdy znikną. Działające sesje Codex i Grok pozostają przy koncie, z którym się rozpoczęły. Historia rozmów, ustawienia, umiejętności i wtyczki są współdzielone między kontami, więc `claude --continue` w tym samym folderze kontynuuje tam, gdzie skończyłeś na nowym koncie.

Przy więcej niż jednym koncie panel pokazuje limity każdego konta obok siebie, z wypełnioną gwiazdką przy używanym. Omarchy powiadamia Cię, gdy aktywne konto przekroczy 95% limitu, a kliknięcie powiadomienia przełącza na konto z największym zapasem. Nigdy nie przełącza się samo. Zmień próg za pomocą `omarchy agent account threshold 90`. Jeśli każde konto przekracza próg, usłyszysz o tym raz, wraz z informacją, które konto zwolni się jako pierwsze. Gdy aktywne konto znajduje się w granicach 15 punktów od swojego progu (80% przy ustawieniu domyślnym), jego limity są sprawdzane co trzy minuty, a nie co 15.

`omarchy agent account list` pokazuje każde konto i jego najnowsze limity, `omarchy agent account remove work` zapomina jedno, a `omarchy agent account rename primary Hey` zmienia nazwę jednego (lub kliknij nazwę konta w panelu). Polecenia te działają na kontach Twojego domyślnego agenta; aby dotrzeć do innego dostawcy, najpierw go nazwij, np. `omarchy agent account use codex side`. Logowanie, które już miałeś w `~/.claude` lub `~/.codex`, to konto _Main_. Konto Codex pozostaje tam, gdzie jest; konto Claude czeka we własnym folderze, gdy inne konto jest aktywne. Konto nieużywane przez ponad około osiem godzin może pokazywać _Sign-in required_; kliknij je, aby zalogować się ponownie do tego konta bezpośrednio w panelu, lub przełącz się na nie i rozpocznij sesję, co samo odświeży logowanie. Serwery MCP, które dodajesz za pomocą `claude mcp add`, docierają do każdego konta Claude, ponieważ wszystkie działają w `~/.claude`; w przypadku Codex i Grok serwery, które miałeś, gdy konto zostało dodane, towarzyszą mu, ale późniejsze docierają tylko do konta, w którym je dodałeś. Claude Desktop zachowuje własne logowanie, a narzędzia Codex lub Grok skonfigurowane z bezwzględną ścieżką do pliku binarnego CLI nie podążają za przełączeniem. Jawne `CLAUDE_CONFIG_DIR`, `CODEX_HOME` lub `GROK_HOME` ma pierwszeństwo przed wybranym kontem.

### Diagnoza awarii

Omarchy obserwuje systemd-coredump pod kątem awarii procesów. Gdy wybierzesz domyślnego agenta, każdy Twój program, który zrzuci core, wywoła powiadomienie „Process crashed” — kliknij je, a awaria zostanie przekazana Twojemu domyślnemu agentowi wraz z umiejętnością omarchy-diagnose-crash Omarchy, która prowadzi agenta przez ustalenie faktów na podstawie zrzutu core i zdecydowanie, czy awaria jest warta zgłoszenia upstream. Możesz też uruchomić ją ręcznie dla dowolnego PID z `coredumpctl list` za pomocą `omarchy agent crash <pid>`.

Obserwowanie jest domyślnie włączone. Wyłącz je w _Trigger > Toggle > Crash Capture Off_ (lub za pomocą `omarchy toggle crash-capture`), a powiadomienia ustaną; `omarchy agent crash <pid>` nadal działa ręcznie.

Awarie można też wyciszać po jednym programie na raz, co diagnoza oferuje Ci na końcu. `omarchy crash mute hyprland` zatrzymuje powiadomienia tylko dla tego programu, `omarchy crash mute hyprland off` przywraca je, a samo `omarchy crash mute` wypisuje, co wyciszyłeś. Przyjmuje ścieżkę pliku binarnego równie chętnie jak jego nazwę, więc `omarchy crash mute /usr/bin/hyprland` robi to samo. Nazwę ze spacją ujmij w cudzysłów, np. `omarchy crash mute 'Some App'`. Wszystko inne nadal powiadamia, a wyciszony program nadal ulega awarii — ukrywa to przypomnienie, niczego nie naprawia.

### Aplikacje desktopowe

Menu _Install > AI_ zawiera również kilka graficznych aplikacji AI: Amp Desktop, Antigravity Desktop, aplikację desktopową ChatGPT, aplikację desktopową Claude (beta Anthropic na Linuksa, z kartami Chat, Cowork i Claude Code), Grok Bot do czatowania z modelami xAI, Herdr Desktop, Hermes Desktop, OpenClaw, aplikację desktopową Perplexity oraz T3 Code. Grok Bot to desktopowa aplikacja do czatu. Agent kodujący to polecenie `grok`.

Hermes Desktop to ta, o której warto wiedzieć, ponieważ maszyna ma jednego Hermesa i należy on do aplikacji: Hermes jest instalowany wyłącznie przez aplikację, a polecenie `hermes`, które uruchamia domyślny agent, należy do aplikacji. Wybranie Hermes jako domyślnego agenta instaluje to samo, co pozycja _Install > AI_: pakiet oraz środowisko uruchomieniowe Hermes w `~/.hermes` skonfigurowane przez własny instalator Hermes, co za pierwszym razem zajmuje kilka minut. To środowisko uruchomieniowe jest tym jedynym Hermesem, którego używają polecenie terminalowe `hermes`, domyślny agent i aplikacja, i aktualizuje się samo za pomocą `hermes update`, zamiast czekać na wydanie Omarchy. Zainstalowanie go przekazuje również Hermes motyw Omarchy jako skórkę o nazwie `omarchy`, za którą podąża każda powierzchnia Hermes, gdy przełączasz motywy; wybierz inną w ustawieniach Appearance Hermes lub za pomocą `/skin`, jeśli wolisz, aby tak nie było, a Omarchy zostawi ten wybór w spokoju. Usunięcie aplikacji w _Remove > AI_ najpierw zamyka Hermes, wraz z bramą, zabiera ze sobą to środowisko uruchomieniowe i zachowuje Twoje czaty, wspomnienia oraz umiejętności, które Hermes napisał dla siebie, chyba że powiesz inaczej: pyta, domyślnie na nie, czy te dane i Twoje ustawienia połączenia również powinny zniknąć.

Doświadczenie desktopowe OpenClaw to jego Control UI, które otwiera się jako aplikacja webowa wspierana przez własną lokalną bramę. OpenClaw mieszka w `~/.openclaw` i aktualizuje się samo: użyj przycisku „Update Gateway” w Control UI lub uruchom `openclaw update`, a brama uruchomi się ponownie w nowej wersji. Omarchy wybiera jedynie wydanie, od którego zaczyna świeża instalacja. OpenClaw może być również Twoim domyślnym agentem: wybranie go w _Agent > Harness_ konfiguruje tę samą kopię w `~/.openclaw`, a agent otwiera terminalowy interfejs użytkownika OpenClaw podłączony do jego bramy. Usunięcie OpenClaw w _Remove > AI_ zabiera ze sobą usługę bramy i aplikację, a następnie pyta, czy `~/.openclaw` również powinno zniknąć, ponieważ przechowuje Twoje czaty i dane uwierzytelniające wraz z samym OpenClaw i środowiskami uruchomieniowymi wtyczek, które pobiera; domyślnie je zachowuje, a ponowne zainstalowanie OpenClaw je odzyska.

Herdr Desktop to aplikacja desktopowa [Herdr](https://herdr.dev): przestrzenie, karty i panele terminali oraz agentów kodujących, które nadal działają w jego rdzeniu, gdy zamkniesz okno. Pochodzi z własnego instalatora Herdr, a nie z pakietu, więc mieszka w `~/.local/share/herdr-app`, przynosi ze sobą swój rdzeń w `~/.local/bin/herdr-core`, gdy jeszcze go nie masz, i aktualizuje jedno i drugie samo. Stoi obok polecenia `herdr`, które Omarchy dostarcza na `Super + Ctrl + Return`, zamiast je zastępować, i otrzymuje bezpośrednie klawisze tego polecenia: `Alt + Return` i `Alt + Shift + Return` dzielą panel w dół lub w prawo, `Alt + Escape` go zamyka, `Ctrl + Alt + Arrow` przemieszcza między panelami, `Alt + 1..9` i `Alt + Left/Right` wybierają kartę, a `Alt + Up/Down` przemieszczają między przestrzeniami. `Ctrl + 1..9` wybiera przestrzeń, a `Alt + Shift + Up/Down` przechodzi po agentach. Klawisze z prefiksem `Ctrl + Space` pozostają tylko dla terminala, ponieważ aplikacja nie może przytrzymać zwykłego klawisza Ctrl dla sekwencji. Omarchy zapisuje je do `~/.config/herdr-app/keys.json`, a `omarchy-refresh-herdr-app` przywraca je. Zainstalowanie go wybiera motyw Omarchy Herdr, który od tego momentu podąża za Twoim motywem Omarchy. Herdr przechowuje jeden motyw dla trybu jasnego i jeden dla trybu ciemnego, więc po przełączeniu między ciemnym a jasnym motywem Omarchy wybierz Omarchy jeszcze raz w selektorze motywów Herdr dla drugiego trybu.

T3 Code działa z oficjalnego wydania AppImage w `~/.local/share/t3code`, a nie z pakietu, więc aktualizuje się samo. Zainstalowanie go pyta, czy zacząć na kanale Stable czy Nightly; przełącz później w ustawieniach T3 Code. Twoje wątki i ustawienia mieszkają w `~/.t3`, a usunięcie T3 Code w _Remove > AI_ zabiera je ze sobą.

### Modele lokalne

Uruchamiaj otwarty model na własnej maszynie dla swoich agentów kodujących. Twoje prompty i kod pozostają na maszynie; nic wysłanego do modelu jej nie opuszcza. Zacznij od:

```bash
omarchy models use best text
```

Konfiguruje to najlepszy model tekstowy dla tej maszyny, ten rodzaj, którego używają Twoi agenci. Modele obrazu, wideo i muzyki mają swój własny najlepszy: `omarchy models use best image`, `video` lub `music`. Uruchom `omarchy models use best`, aby zobaczyć wybór dla każdego rodzaju dla tej maszyny.

Albo otwórz panel modeli lokalnych za pomocą jego ikony iskier w górnym pasku, obok ikony agentów, lub za pomocą Super + Ctrl + Alt + X, i wybierz +. Ikona pojawia się, gdy model pasuje do tej maszyny. Podman, który uruchamia modele, jest dostarczany z Omarchy, podobnie jak zestaw narzędzi kontenerowych NVIDIA na maszynie NVIDIA, który daje im GPU; jeśli któregoś brakuje, pierwsza konfiguracja go instaluje. Omarchy wybiera następnie zalecany model dla tej maszyny, pobiera go i uruchamia. Spodziewaj się pobrania dziesiątek GB i zajęcia większości pamięci maszyny podczas działania modelu: Flash Next używa około 100 GiB przy pełnym kontekście 256K. Jeśli inne modele zajmują potrzebną mu pamięć, jest konfigurowany jako zatrzymany, gotowy do uruchomienia, gdy zatrzymasz jeden z nich. Model zatrzymuje się przy wylogowaniu; zatrzymaj go sam, gdy potrzebujesz pamięci do czegoś innego.

`omarchy models list` pokazuje opcje i wyjaśnia, dlaczego niektóre nie pasują. Aby skonfigurować inny, uruchom `omarchy models use <recipe>`. Dziś dla maszyn Strix Halo ze 128 GB dostępne są `qwen3.8-flash-next-gufo` i `qwen3.8-27b-gufo`; model 27B zajmuje około 40 GiB, więc zostawia miejsce na inną pracę. Na laptopie 64 GB z Intel Arc B390 `qwen3.6-35b-a3b-llamacpp` działa w około 30 GiB. Nowe receptury i zalecenia przychodzą wraz z `omarchy update`, przez pakiet.

Każdy skonfigurowany model otrzymuje własny wiersz w panelu modeli lokalnych: play, aby go uruchomić, pause, aby go zatrzymać i zwolnić jego pamięć, oraz przycisk terminala, aby otworzyć na nim swojego agenta. Na górze pasek pokazuje, jak pamięć maszyny jest podzielona między samo Omarchy (system i Twoje aplikacje), każdy działający model i to, co jest wolne. Wskaż zatrzymany model, a pasek pokaże, czy pasuje, lub ile mu brakuje. Kilka może działać jednocześnie, gdy razem mieszczą się w pamięci; jeśli jeden nie pasuje, Omarchy powie, który działający model zatrzymać. Przeciągaj wiersze za ich logo, aby zmienić ich kolejność, i naciśnij Delete na wybranym wierszu, aby usunąć model i jego pobrane pliki.

Każdy skonfigurowany model kodujący otrzymuje również własny wpis w launcherze aplikacji, pod nazwą modelu i z logo jego twórcy, w sposób, w jaki zalogowanie się do Claude, Codex lub Grok dodaje taki wpis. Otwiera Twojego agenta na tym modelu i najpierw uruchamia model, jeśli nie działa: terminal pokazuje jego ładowanie i przekazuje kontrolę agentowi, gdy już działa. Usunięcie modelu usuwa jego wpis.

Nie każdy model służy do kodowania. Modele obrazu, wideo i muzyki otwierają się natomiast w Fantasi, aplikacji Omarchy do tworzenia obrazów, wideo i muzyki przy użyciu modelu działającego na tej maszynie, wybrane tam lub z ich wiersza w panelu modeli lokalnych.

Model nadal działa dokładnie tak, jak został skonfigurowany, więc aktualizacja Omarchy nigdy nie uruchamia go ponownie pod Twoimi agentami. Gdy Omarchy ma nowsze środowisko uruchomieniowe lub nowsze wagi dla modelu, który skonfigurowałeś, jego wiersz pokazuje przycisk aktualizacji: naciśnij go, a model zostanie ponownie skonfigurowany w tle, pobierając tylko to, co się zmieniło, i uruchomi się ponownie w nowej wersji. Model, który był zatrzymany, pozostaje zatrzymany. `omarchy models update` robi to samo dla każdego modelu z terminala.

Z wiersza poleceń `omarchy models start <recipe>` i `omarchy models stop <recipe>` robią to samo, `omarchy models status` pokazuje każdy model, a `omarchy agent --local` otwiera ostatni model, który uruchomiłeś, w pi, niezależnie od tego, jaki jest Twój domyślny agent. Aby uczynić ten model tym, co otwierają skrót klawiszowy agenta, konsola Quake i _Make something_, uruchom `omarchy default agent local` lub wybierz _Local model_ w _Agent > Harness_. pi również wypisuje każdy skonfigurowany przez Ciebie model oraz te na maszynach, z którymi się sparowałeś, we własnym selektorze modeli, więc zwykłe `pi` również do nich dociera. Dowolny klient kompatybilny z OpenAI również może się połączyć: `status` pokazuje adres każdego modelu (pierwszy to `http://127.0.0.1:11435/v1`), nazwa receptury jest modelem, a klucz znajduje się w `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` usuwa model i pobrane pliki, których nie używa żaden inny model.

Środowiska uruchomieniowe stron trzecich są oznaczone nazwą ich wydawcy. Omarchy uruchamia każdy model bez dostępu do sieci.

### Lokalne LLM

Omarchy zaleca dwa sposoby uruchamiania lokalnych modeli LLM: LM Studio i Ollama. LM Studio zapewnia interfejs GUI do znajdowania modeli o otwartych wagach, instalowania ich i uruchamiania. To świetny sposób, aby łatwo zacząć. Ollama oferuje CLI do robienia tego w podobny sposób. Ale jeśli dopiero zaczynasz przygodę z modelami lokalnymi, zacząłbym od LM Studio. Możesz zainstalować każde z nich w _Install > AI_ w Menu Omarchy.

### Umiejętności Omarchy

Umiejętności agentów pomagają AI używać określonych narzędzi w określony sposób, a Omarchy dostarcza ich siedem. Umiejętność omarchy obejmuje dostosowywanie systemu, np. poprawianie konfiguracji Hyprland lub dostosowywanie paska. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app i omarchy-make-game obejmują tworzenie czegoś nowego, omarchy-contribute obejmuje zgłaszanie błędu lub wysyłanie poprawki upstream, a omarchy-diagnose-crash pracuje nad zrzutem core awarii. Są one podlinkowane symbolicznie do katalogów umiejętności dla Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` i każdy `~/.hermes/profiles/*/skills`) oraz ogólnej lokalizacji `~/.agents/skills`, więc większość harnessów podchwytuje je automatycznie. Folder umiejętności o tej samej nazwie, który sam utworzysz, ma pierwszeństwo.

Powinieneś jednak traktować te umiejętności jako eksperymentalne. Różne modele będą ich używać z różnym skutkiem. Najlepiej najpierw działać w trybie planowania, aby mieć pojęcie, co agent chciałby zmienić. A potem bądź gotów wycofać zmiany lub nawet wywołać `omarchy reinstall configs`, jeśli agent zrobi ze wszystkiego bałagan.
