# AI

Omarchy zawiera programy uruchamiające dla poniższych agentów kodujących, ale nie wybiera za ciebie domyślnego. Uruchom polecenie, aby przy pierwszym użyciu zainstalować jego CLI, a potem uwierzytelnij się, gdy pojawi się monit. Hermes i OpenClaw to wyjątki: nic nie jest dla nich instalowane przez mise, a wybranie któregokolwiek z nich instaluje własną, samouaktualniającą się kopię, jak poniżej wyjaśnia sekcja _Aplikacje desktopowe_.

### Instalowanie i aktualizowanie agentów

Z wyjątkiem Hermes i OpenClaw ci agenci używają leniwej instalacji mise: pierwsze uruchomienie instaluje CLI, a kolejne uruchomienia używają go ponownie. mise sprawdza też, co najwyżej raz na cztery godziny, czy zainstalowany agent ma nową wersję, tuż przed jego uruchomieniem albo w tle przy znaku zachęty powłoki. Jeśli ta aktualizacja się nie powiedzie albo jesteś offline, uruchamia się zainstalowana wersja. `omarchy update` aktualizuje zainstalowanych agentów wraz z resztą Omarchy, a `mup` aktualizuje tylko narzędzia zarządzane przez mise.

Własny aktualizator agenta, taki jak `claude update`, `codex update` lub przycisk aktualizacji w aplikacji, nie aktualizuje instalacji zarządzanej przez mise. `codex update` kończy się niepowodzeniem, a `claude update` może zgłosić sukces, instalując przy tym osobną kopię, której mise nie śledzi. Jeśli wolisz używać natywnego instalatora i aktualizatora agenta, dodaj go do `disable_tools`; zobacz [Preinstalowane narzędzia CLI](18-development-tools.md#preinstalled-cli-tools).

Aby zainstalować wszystkie skonfigurowane narzędzia leniwe, zanim będą ci potrzebne, uruchom `mise install --include-lazy`. Obejmuje to także inne domyślne narzędzia CLI Omarchy, a nie tylko agentów. Zobacz [Preinstalowane narzędzia CLI](18-development-tools.md#preinstalled-cli-tools), aby dowiedzieć się, jak zainstalować pojedyncze narzędzie lub użyć własnej instalacji.

`grok` jest instalowany przez oficjalny pakiet `grok` w mise, w ten sam sposób co `claude` i `codex`. Uruchom `grok` albo wybierz go w _Agent > Harness_. Pomiń instalator `curl | bash` na x.ai. Ta ścieżka umieszcza drugą kopię w `~/.grok/bin`, dopisuje ją na początku `PATH` i nadpisuje wrapper Omarchy.

`dsh` otwiera swój interfejs przeglądarkowy pod adresem `127.0.0.1:3080`, z katalogiem uruchomienia jako domyślnym obszarem roboczym. Jego interfejs przeglądarkowy nie przyjmuje początkowego promptu, więc `omarchy agent prompt` otwiera go z promptem w schowku, gotowym do wklejenia. Omarchy uruchamia go z presetem uprawnień DeepSeek bez zatwierdzania. DeepSeek Harness przesyła logi sesji do DeepSeek, gdy używasz jego oficjalnego API modeli; wyłącz to w jego interfejsie przeglądarkowym w _Settings > General > Upload Session Log_. Opinie, które mu wysyłasz, są przesyłane wraz z sesją, chyba że uruchomisz go z `DSH_TELEMETRY_MODE=DISABLED`.

### Domyślny agent

Wybierz domyślnego agenta poleceniem `omarchy default agent <name>` albo w _Agent > Harness_ w Omarchy Menu (`Super + Space`). Jeśli agent nie jest jeszcze zainstalowany, wybranie go najpierw go zainstaluje, a w programie uruchamiającym aplikacje dostanie też własny program uruchamiający, obok pozycji Agent. Świeże Omarchy zaprosi cię do dokonania tego wyboru jednorazowym powiadomieniem.

Wybranie Claude próbuje też skonfigurować jego rozszerzenie przeglądarkowe dla Chromium, Chrome, Brave, Brave Origin i Edge. Konfiguracja rozszerzenia dotyczy wszystkich użytkowników i może poprosić o hasło systemowe; anulowanie lub niepowodzenie instalacji rozszerzenia i tak wybiera i uruchamia Claude. Uruchom przeglądarkę ponownie, włącz rozszerzenie, jeśli pojawi się monit, i zaloguj się do Claude, aby dokończyć łączenie. Uruchom `/chrome` w Claude, aby sprawdzić połączenie. Firefox i Zen nie obsługują tego rozszerzenia. Jeśli Claude był twoim domyślnym agentem, zanim dodano tę konfigurację, wybierz go ponownie, aby zainstalować rozszerzenie.

Po dokonaniu wyboru `Super + Shift + Ctrl + A` uruchamia domyślnego agenta w dedykowanym oknie terminala (albo przywołuje selektor, jeśli jeszcze nie wybrałeś). Możesz też uruchomić go bezpośrednio do zadania poleceniem `omarchy agent prompt "Review this project"`. Freebuff i DeepSeek Harness nie przyjmują początkowego promptu, więc otwierają się z promptem w schowku, gotowym do wklejenia. Agenci uruchamiani w ten sposób działają bez nadzoru w swoich trybach „nie zatrzymuj się, żeby pytać”, więc bądź gotowy na to, że naprawdę będą coś robić! MiniMax Code nie ma takiego trybu dla swoich sesji interaktywnych, więc pyta o uprawnienia jak zwykle. A ponieważ agenci odmawiają zapamiętywania zaufania dla katalogu domowego, uruchomienia z `$HOME` startują zamiast tego w `~/Work`.

Są też skróty terminalowe: `a` uruchamia domyślnego agenta bezpośrednio w bieżącym terminalu, a `c`, `cx` i `cy` uruchamiają bezpośrednio OpenCode, Claude Code i Codex (ponownie w ich trybach automatycznego zatwierdzania). Zmiany motywu synchronizują się też z agentami: Claude Code, Pi, OpenCode i Hermes (gdy Omarchy go zainstaluje) podążają za tobą, gdy przełączysz motyw Omarchy.

### Twoje instrukcje dla agentów

Osobiste zasady dla każdego agenta trafiają do `~/.agents/AGENTS.md`, obok współdzielonych umiejętności w `~/.agents/skills`. Otwórz go w _Agent > Instructions_, co łączy go też z każdym harnessem, który przechowuje własny plik globalny: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` od Copilot i tak dalej. Crush i Amp odczytują łącze `~/.config/AGENTS.md`, a omp, Kimi i DeepSeek Harness odczytują bezpośrednio `~/.agents/AGENTS.md`. Wybranie domyślnego agenta też je łączy. Plik instrukcji, który już miałeś, staje się współdzielonym, jeśli jeszcze go nie było; w przeciwnym razie jest przechowywany obok łącza jako `.bak`. Uruchom `omarchy agent instructions`, aby ponownie połączyć po zainstalowaniu kolejnego agenta.

### Panel agentów

Górny pasek ma ikonę agentów. Zanim skonfigurujesz agenta, jego panel przeprowadzi cię przez logowanie do Claude, Codex lub Grok, a pierwszy z nich stanie się twoim domyślnym agentem. Potem panel umieszcza każdą subskrypcję na jednej stronie: każdego agenta i konto wraz z jego planem, wskaźnik dla każdego z jego limitów 5-godzinnej sesji i limitów tygodniowych wraz z czasem do ich zresetowania (najedź, aby zobaczyć dokładną wartość procentową) albo pozostałe saldo przedpłacone, pod wierszem, który rotacyjnie pokazuje, ile zużyłeś we wszystkich z nich, na przykład tokeny w tym tygodniu i najczęściej używany model. W sekcji _Make something cool_ oferuje prompty startowe dla nowego motywu, wtyczki, aplikacji lub gry, które przekazują zadanie twojemu domyślnemu agentowi. Aplikacje są budowane w taki sposób, jak własne aplikacje Omarchy Hype, Monologue i Omacut, w C++ i Qt Quick, zgodnie z umiejętnością agenta omarchy-make-app, a kompilator i elementy Qt, których potrzebują, są zainstalowane. Gry to pojedyncza strona three.js w `~/Games/vibes`, zgodna z umiejętnością agenta omarchy-make-game, a wszystkie otwierają się z jednego programu uruchamiającego Game Vibes w bieżącym motywie; ładują three.js z sieci, więc do uruchomienia potrzebują połączenia. Claude Code, Codex, Grok, Kimi, Cursor i jego limit Grok Bot, GitHub Copilot, Muse, Antigravity i Devin są obsługiwane od razu wraz z ich limitami, Kimchi wraz z jego planem, kredytami przedpłaconymi i budżetami wydatków, a Hermes, Mistral Vibe i Qwen Code pokazują swoje sesje i tokeny, gdy już ich użyjesz. Pojawiają się też plany i klucze dostawców, których używasz przez pi, omp lub opencode: OpenCode Zen i Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan i Synthetic wraz z ich limitami; OpenRouter i DeepSeek wraz z ich saldami przedpłaconymi; Fireworks wraz z wydatkami z ostatnich 30 dni. Tokeny z modeli, które uruchamiasz na własnym sprzęcie, też wliczają się do sum; same modele mają własny panel, opisany w sekcji [Lokalne modele](#local-models). Każdy agent jest liczony raz, u tego, kto go rozlicza, niezależnie od tego, przez ile harnessów go prowadzisz.

Kliknij lewym przyciskiem myszy ikonę na pasku albo naciśnij `Super + Ctrl + X`, aby otworzyć panel, kliknij prawym przyciskiem, aby uruchomić domyślnego agenta, a środkowym, aby odświeżyć. Rekordy użycia, na których się opiera, są regenerowane co 15 minut przez `omarchy agent usage update`, a panel może nawet łączyć użycie z innych twoich maszyn przez zsynchronizowany folder. Zobacz README w `$OMARCHY_PATH/shell/plugins/agents/`, aby poznać pełne ustawienia.

### Kilka subskrypcji

Jeśli płacisz za więcej niż jeden plan Claude, Codex lub Grok — na przykład osobisty Max i służbowy — Omarchy może utrzymywać je wszystkie zalogowane i przełączać się między nimi. Dodaj subskrypcję przyciskiem + w panelu agentów, który od razu cię przez to przeprowadzi, albo poleceniem `omarchy agent account add claude Work` (albo `codex`, albo `grok`). Instaluje CLI, jeśli go brakuje. Pierwsze konto dla dostawcy loguje się przez twoją normalną przeglądarkę, dokładnie tam, gdzie CLI zawsze zagląda. Każde kolejne loguje się przez okno prywatne, więc konto, do którego twoja przeglądarka jest już zalogowana, nie zostanie wybrane przez pomyłkę; zaloguj się tam jako konto, które dodajesz, i najpierw zamknij każde okno prywatne, które masz już otwarte. Nigdy w tym celu nie wylogowuj się z CLI: wylogowanie unieważnia zapisane logowanie, a to konto trzeba by dodać ponownie.

Aby skopiować logowania subskrypcji na inną maszynę Omarchy przez SSH, uruchom `omarchy agent account copy user@laptop`. Nadawca dostarcza tymczasowy odbiornik, gdy maszyna docelowa nie ma zainstalowanego, więc starsze maszyny Omarchy mogą odbierać konta bez aktualizacji. Zainstalowane odbiorniki mają pierwszeństwo. Kopiuje to wszystkie subskrypcje Claude, Codex i Grok; dodaj nazwy dostawców, aby je wybrać, na przykład `omarchy agent account copy laptop claude`. Nazwy kont i identyfikatory poleceń zgadzają się ze źródłem, w tym konta już obecne na maszynie docelowej. Niepowiązane konta docelowe otrzymują przyrostek liczbowy, jeśli ich nazwy kolidują, a ustawienia, umiejętności, wtyczki i historia rozmów pozostają lokalne dla każdej maszyny.

Istniejące dane uwierzytelniające na maszynie docelowej są zachowywane. Konto źródłowe już tam zalogowane ma synchronizowaną nazwę bez zastępowania jego danych uwierzytelniających; inne konta są dodawane obok niego. Aby zastąpić zapisane dane uwierzytelniające dla pasujących kont, użyj `omarchy agent account copy --replace laptop claude` po zamknięciu sesji tego konta na maszynie docelowej. Świeża maszyna docelowa otrzymuje też aktywne konto źródła i preferencje przełączania; ustalona maszyna docelowa zachowuje własne.

Dane uwierzytelniające podróżują przez SSH i są przechowywane w prywatnych plikach na maszynie docelowej, więc kopiuj tylko na maszyny, którym ufasz. To jednorazowa kopia, a nie bieżąca synchronizacja. Tokeny odświeżania Codex mogą zostać zrotowane przez inną maszynę, przez co skopiowane logowanie będzie wymagało odnowienia; osobne logowania pozostają najbardziej niezawodnym wyborem przy jednoczesnym użyciu na kilku maszynach. Zobacz [wskazówki Codex dotyczące uwierzytelniania kont](https://developers.openai.com/codex/auth/ci-cd-auth).

Jedno konto na dostawcę jest aktywne, a każda nowa sesja zaczyna jako ono: `cx`, `cy`, zwykłe `claude`, `codex` lub `grok`, wszystko uruchamiane przez `omarchy agent` oraz skrypty i edytory, które znajdują CLI na `PATH`. Przełącz poleceniem `omarchy agent account use work` (i z powrotem poleceniem `omarchy agent account use main`) albo w panelu, naciskając numer konta, a potem `Enter` (albo klikając jego przycisk Use). Działające sesje Claude też się przełączają, od następnej wiadomości: każda sesja Claude działa w `~/.claude`, który zawsze przechowuje logowanie aktywnego konta. Sesja Claude uruchomiona we własnym folderze konta przez starsze Omarchy przechowuje to logowanie do momentu zakończenia, więc przełączenie wymienia te sesje z nazwy i kończy się samo, gdy ich już nie ma. Działające sesje Codex i Grok pozostają na koncie, na którym się rozpoczęły. Historia rozmów, ustawienia, umiejętności i wtyczki są współdzielone między kontami, więc `claude --continue` w tym samym folderze podejmuje pracę tam, gdzie ją przerwałeś na nowym koncie.

Przy więcej niż jednym koncie panel pokazuje limity każdego konta obok siebie, z zaznaczonym aktywnym. Omarchy powiadamia cię, gdy aktywne konto przekroczy 95% limitu, a kliknięcie powiadomienia przełącza na konto z największym zapasem. Nigdy nie przełącza samo. Zmień próg poleceniem `omarchy agent account threshold 90`. Jeśli każde konto przekracza próg, usłyszysz o tym raz, wraz z informacją, które konto zwolni się jako pierwsze. Gdy aktywne konto jest w odległości 15 punktów od swojego progu (80% przy ustawieniu domyślnym), jego limity są sprawdzane co trzy minuty, a nie co 15.

`omarchy agent account list` pokazuje każde konto i jego najnowsze limity, `omarchy agent account remove work` zapomina jedno, a `omarchy agent account rename primary Hey` zmienia nazwę jednego (albo kliknij nazwę konta w panelu). Te polecenia działają na kontach twojego domyślnego agenta; aby sięgnąć innego dostawcy, najpierw go nazwij, na przykład `omarchy agent account use codex side`. Logowanie, które już miałeś w `~/.claude` lub `~/.codex`, to konto _Main_. Konto Codex pozostaje tam, gdzie jest; konto Claude czeka we własnym folderze, gdy aktywne jest inne konto. Konto nieużywane przez ponad około osiem godzin może pokazywać _Sign-in required_; kliknij je, aby ponownie zalogować to konto bezpośrednio w panelu, albo przełącz się na nie i rozpocznij sesję, co samo odświeża logowanie. Serwery MCP, które dodajesz poleceniem `claude mcp add`, docierają do każdego konta Claude, ponieważ wszystkie działają w `~/.claude`; w przypadku Codex i Grok serwery, które miałeś, gdy konto było dodawane, przechodzą do niego, ale późniejsze docierają tylko do konta, w którym je dodałeś. Claude Desktop przechowuje własne logowanie, a narzędzia Codex lub Grok skonfigurowane bezwzględną ścieżką do pliku binarnego CLI nie podążają za przełączeniem. Jawne `CLAUDE_CONFIG_DIR`, `CODEX_HOME` lub `GROK_HOME` ma pierwszeństwo przed wybranym kontem.

### Diagnostyka awarii

Omarchy obserwuje systemd-coredump pod kątem awarii procesów. Gdy wybierzesz domyślnego agenta, każdy twój program, który zrzuci core, wywoła powiadomienie "Process crashed" — kliknij je, a awaria zostanie przekazana twojemu domyślnemu agentowi wraz z umiejętnością omarchy-diagnose-crash Omarchy, która prowadzi agenta przez ustalenie faktów ze zrzutu core i zdecydowanie, czy awarię warto zgłosić upstream. Możesz też uruchomić ją ręcznie dla dowolnego PID z `coredumpctl list` poleceniem `omarchy agent crash <pid>`.

Obserwowanie jest domyślnie włączone. Wyłącz je w _Trigger > Toggle > Crash Capture Off_ (albo poleceniem `omarchy toggle crash-capture`), a powiadomienia ustaną; `omarchy agent crash <pid>` nadal działa ręcznie.

Awarie można też wyciszać po jednym programie naraz, co diagnostyka oferuje ci na końcu. `omarchy crash mute hyprland` zatrzymuje powiadomienia tylko dla tego programu, `omarchy crash mute hyprland off` przywraca je, a samo `omarchy crash mute` wypisuje, co wyciszyłeś. Przyjmuje ścieżkę pliku binarnego równie chętnie jak jego nazwę, więc `omarchy crash mute /usr/bin/hyprland` robi to samo. Nazwę ze spacją ujmij w cudzysłów, na przykład `omarchy crash mute 'Some App'`. Wszystko inne nadal powiadamia, a wyciszony program nadal się wywraca — to ukrywa przypomnienie, niczego nie naprawia.

### Aplikacje desktopowe

Menu _Install > AI_ zawiera też kilka graficznych aplikacji AI: Amp Desktop, Antigravity Desktop, aplikację desktopową ChatGPT, aplikację desktopową Claude (linuxową betę Anthropic, z kartami Chat, Cowork i Claude Code), Grok Bot do rozmów z modelami xAI, Herdr Desktop, Hermes Desktop, OpenClaw, aplikację desktopową Perplexity i T3 Code. Grok Bot to desktopowa aplikacja do czatu. Agent kodujący to polecenie `grok`.

Hermes Desktop to ta, o której trzeba wiedzieć, ponieważ maszyna ma jednego Hermesa i należy on do aplikacji: Hermes jest instalowany wyłącznie przez aplikację, a polecenie `hermes`, które uruchamia domyślny agent, należy do aplikacji. Wybranie Hermes jako domyślnego agenta instaluje to samo, co pozycja _Install > AI_: pakiet oraz środowisko uruchomieniowe Hermes w `~/.hermes`, skonfigurowane przez własny instalator Hermes, co za pierwszym razem zajmuje kilka minut. To środowisko uruchomieniowe jest tym jedynym Hermesem, którego używają terminalowe polecenie `hermes`, domyślny agent i aplikacja, i aktualizuje się samo poleceniem `hermes update`, zamiast czekać na wydanie Omarchy. Zainstalowanie go przekazuje też Hermes motyw Omarchy jako skórkę o nazwie `omarchy`, za którą podąża każda powierzchnia Hermes, gdy przełączasz motywy; wybierz inną w ustawieniach Appearance Hermes albo poleceniem `/skin`, jeśli wolisz, żeby tak nie było, a Omarchy zostawi ten wybór w spokoju. Usunięcie aplikacji w _Remove > AI_ najpierw zamyka Hermes, wraz z bramką, zabiera ze sobą to środowisko uruchomieniowe i zachowuje twoje czaty, wspomnienia oraz umiejętności, które Hermes napisał dla siebie, chyba że powiesz inaczej: pyta, czy te dane i twoje ustawienia połączeń też powinny zniknąć, z domyślną odpowiedzią „nie”.

Doświadczeniem desktopowym OpenClaw jest jego Control UI, który otwiera się jako aplikacja webowa wspierana przez własną lokalną bramkę. OpenClaw mieszka w `~/.openclaw` i aktualizuje się sam: użyj przycisku "Update Gateway" w Control UI albo uruchom `openclaw update`, a bramka uruchomi się ponownie na nowej wersji. Omarchy wybiera tylko wydanie, od którego zaczyna świeża instalacja. OpenClaw może też być twoim domyślnym agentem: wybranie go w _Agent > Harness_ konfiguruje tę samą kopię w `~/.openclaw`, a agent otwiera terminalowy interfejs użytkownika OpenClaw podłączony do jego bramki. Usunięcie OpenClaw w _Remove > AI_ zabiera ze sobą usługę bramki i aplikację, a potem pyta, czy `~/.openclaw` też powinno zniknąć, ponieważ przechowuje twoje czaty i dane uwierzytelniające obok samego OpenClaw i środowisk uruchomieniowych wtyczek, które pobiera; domyślnie je zachowuje, a ponowne zainstalowanie OpenClaw znowu je podejmie.

Herdr Desktop to aplikacja desktopowa [Herdr](https://herdr.dev): przestrzenie, karty i panele terminali oraz agentów kodujących, które nadal działają w jego rdzeniu, gdy zamkniesz okno. Pochodzi z własnego instalatora Herdr, a nie z pakietu, więc mieszka w `~/.local/share/herdr-app`, przyprowadza swój rdzeń w `~/.local/bin/herdr-core`, gdy jeszcze go nie masz, i aktualizuje się sama wraz z nim. Siedzi obok polecenia `herdr`, które Omarchy dostarcza na `Super + Ctrl + Return`, zamiast je zastępować, i otrzymuje bezpośrednie klawisze tego polecenia: `Alt + Return` i `Alt + Shift + Return` dzielą panel w dół lub w prawo, `Alt + Escape` go zamyka, `Ctrl + Alt + Arrow` porusza się między panelami, `Alt + 1..9` i `Alt + Left/Right` wybierają kartę, a `Alt + Up/Down` poruszają się między przestrzeniami. `Ctrl + 1..9` wybiera przestrzeń, a `Alt + Shift + Up/Down` przechodzi po agentach. Klawisze z prefiksem `Ctrl + Space` pozostają tylko dla terminala, ponieważ aplikacja nie może przytrzymać zwykłego klawisza Ctrl dla sekwencji. Omarchy zapisuje je do `~/.config/herdr-app/keys.json`, a `omarchy-refresh-herdr-app` przywraca je. Zainstalowanie jej wybiera motyw Omarchy w Herdr, który od tej pory podąża za twoim motywem Omarchy. Herdr przechowuje jeden motyw dla trybu jasnego i jeden dla ciemnego, więc po przełączeniu między ciemnym a jasnym motywem Omarchy wybierz jeszcze raz Omarchy w selektorze motywów Herdr dla drugiego trybu.

T3 Code działa z oficjalnego wydania AppImage w `~/.local/share/t3code`, a nie z pakietu, więc aktualizuje się sam. Zainstalowanie go pyta, czy zacząć na kanale Stable czy Nightly; przełącz później w ustawieniach T3 Code. Twoje wątki i ustawienia mieszkają w `~/.t3`, a usunięcie T3 Code w _Remove > AI_ zabiera je ze sobą.

### Lokalne modele

Uruchom otwarty model na własnej maszynie dla swoich agentów kodujących. Twoje prompty i kod pozostają na maszynie; nic wysłanego do modelu jej nie opuszcza. Zacznij od:

```bash
omarchy models use best text
```

Konfiguruje to najlepszy model tekstowy dla tej maszyny, ten rodzaj, którego używają twoi agenci. Modele obrazów, wideo i muzyki mają swój własny najlepszy: `omarchy models use best image`, `video` lub `music`. Uruchom `omarchy models use best`, aby zobaczyć wybór dla tej maszyny dla każdego rodzaju.

Albo otwórz panel lokalnych modeli z jego ikony błysków na górnym pasku, obok ikony agentów, albo poleceniem Super + Ctrl + Alt + X, i wybierz +. Ikona pojawia się, gdy model pasuje do tej maszyny. Podman, który uruchamia modele, jest dostarczany z Omarchy, podobnie jak zestaw narzędzi kontenerowych NVIDIA na maszynie NVIDIA, który daje im GPU; jeśli któregoś brakuje, pierwsza konfiguracja go instaluje. Omarchy wybiera potem zalecany model dla tej maszyny, pobiera go i uruchamia. Spodziewaj się pobrania dziesiątek GB i zajęcia większości pamięci maszyny, gdy model działa: Flash Next używa około 100 GiB przy pełnym kontekście 256K. Jeśli inne modele zajmują potrzebną mu pamięć, jest konfigurowany jako zatrzymany, gotowy do uruchomienia, gdy jeden zatrzymasz. Model zatrzymuje się przy wylogowaniu; zatrzymaj go sam, gdy potrzebujesz pamięci do czegoś innego.

`omarchy models list` pokazuje opcje i wyjaśnia, dlaczego niektóre nie pasują. Aby skonfigurować inny, uruchom `omarchy models use <recipe>`. Dziś dla maszyn Strix Halo ze 128 GB dostępne są `qwen3.8-flash-next-gufo` i `qwen3.8-27b-gufo`; 27B zajmuje około 40 GiB, więc zostawia miejsce na inną pracę. Na laptopie z 64 GB i Intel Arc B390, `qwen3.6-35b-a3b-llamacpp` działa w około 30 GiB. Nowe przepisy i zalecenia przychodzą z `omarchy update`, przez pakiet.

Każdy skonfigurowany model dostaje własny wiersz w panelu lokalnych modeli: przycisk play, aby go uruchomić, przycisk pause, aby go zatrzymać i zwolnić jego pamięć, oraz przycisk terminala, aby otworzyć na nim agenta. U góry pasek pokazuje, jak pamięć maszyny jest podzielona między samo Omarchy (system i twoje aplikacje), każdy działający model i to, co jest wolne. Wskaż zatrzymany model, a pasek pokaże, czy pasuje, albo ile mu brakuje. Kilka może działać naraz, gdy razem mieszczą się w pamięci; jeśli jeden się nie mieści, Omarchy mówi, który działający model zatrzymać. Przeciągaj wiersze za ich logo, aby zmienić ich kolejność, i naciśnij Delete na wybranym wierszu, aby usunąć model i jego pobranie.

Każdy skonfigurowany model kodujący dostaje też własną pozycję w programie uruchamiającym aplikacje, pod nazwą modelu i z logo jego twórcy, w ten sam sposób, w jaki zalogowanie do Claude, Codex lub Grok dodaje jedną. Otwiera twojego agenta na tym modelu i najpierw uruchamia model, jeśli nie działa: terminal pokazuje jego ładowanie i przekazuje sterowanie agentowi, gdy jest gotowy. Usunięcie modelu usuwa jego pozycję.

Nie każdy model służy do kodowania. Modele obrazów, wideo i muzyki otwierają się zamiast tego w Fantasi, aplikacji Omarchy do tworzenia obrazów, wideo i muzyki przy użyciu modelu działającego na tej maszynie, wybranego tam albo z ich wiersza w panelu lokalnych modeli.

Model nadal działa dokładnie tak, jak został skonfigurowany, więc aktualizacja Omarchy nigdy nie uruchamia ponownie żadnego pod twoimi agentami. Gdy Omarchy ma nowsze środowisko uruchomieniowe lub nowsze wagi dla modelu, który skonfigurowałeś, jego wiersz pokazuje przycisk aktualizacji: naciśnij go, a model zostanie skonfigurowany ponownie w tle, pobierając tylko to, co się zmieniło, i uruchomi się ponownie na nowej wersji. Model, który był zatrzymany, pozostaje zatrzymany. `omarchy models update` robi to samo dla każdego modelu z terminala.

Z wiersza poleceń `omarchy models start <recipe>` i `omarchy models stop <recipe>` robią to samo, `omarchy models status` pokazuje każdy model, a `omarchy agent --local` otwiera ostatni model, który uruchomiłeś, w pi, niezależnie od tego, jaki jest twój domyślny agent. OpenCode i Qwen Code też mogą używać lokalnego modelu: `omarchy models harness opencode` lub `omarchy models harness qwen` otwiera je tam zamiast tego, a `omarchy models harness pi` wraca. pi wypisuje też każdy skonfigurowany model oraz te na maszynach, z którymi jesteś sparowany, we własnym selektorze modeli, więc zwykłe `pi` też do nich dociera. Każdy klient zgodny z OpenAI też może się połączyć: `status` pokazuje adres każdego modelu (pierwszy to `http://127.0.0.1:11435/v1`), nazwa przepisu jest modelem, a klucz jest w `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` usuwa model i pobrania, których nie używa żaden inny model.

Środowiska uruchomieniowe firm trzecich są oznaczane ich wydawcą. Omarchy uruchamia każdy model bez dostępu do sieci.

### Lokalne LLM-y

Omarchy zaleca dwa sposoby uruchamiania lokalnych modeli LLM: LM Studio i Ollama. LM Studio zapewnia interfejs GUI do znajdowania modeli o otwartych wagach, instalowania ich i uruchamiania. To świetny sposób, aby łatwo zacząć. Ollama oferuje CLI do robienia tego w podobny sposób. Ale jeśli dopiero zaczynasz z lokalnymi modelami, zacząłbym od LM Studio. Możesz zainstalować każde z nich w _Install > AI_ w Omarchy Menu.

### Umiejętności Omarchy

Umiejętności agentów pomagają AI używać określonych narzędzi w określony sposób, a Omarchy dostarcza siedem z nich. Umiejętność omarchy obejmuje dostosowywanie systemu, takie jak poprawianie konfiguracji Hyprland lub dostosowywanie paska. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app i omarchy-make-game obejmują tworzenie czegoś nowego, omarchy-contribute obejmuje zgłaszanie błędu lub wysyłanie poprawki upstream, a omarchy-diagnose-crash przechodzi przez zrzut core awarii. Są dowiązane symbolicznie do katalogów umiejętności dla Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` i każdego `~/.hermes/profiles/*/skills`) oraz ogólnej lokalizacji `~/.agents/skills`, więc większość harnessów podejmuje je automatycznie. Własny folder umiejętności o tej samej nazwie ma pierwszeństwo.

Ale powinieneś traktować te umiejętności jako eksperymentalne. Różne modele będą ich używać z różnym skutkiem. Najlepiej najpierw działać w trybie planowania, aby mieć pojęcie, co agent chciałby zmienić. A potem bądź gotowy na wycofanie zmian albo nawet wywołanie `omarchy reinstall configs`, jeśli agent narobi bałaganu we wszystkim.
