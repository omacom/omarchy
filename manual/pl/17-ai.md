# AI

Omarchy zawiera launchery dla poniższych agentów kodujących, ale nie wybiera za ciebie domyślnego. Uruchom polecenie, aby przy pierwszym użyciu zainstalować jego CLI, a następnie uwierzytelnij się, gdy pojawi się monit. Hermes jest wyjątkiem: przy pierwszym użyciu nic nie jest dla niego instalowane, a wybranie go instaluje Hermes Desktop, jak wyjaśnia poniżej sekcja _Desktop apps_.

### Instalowanie i aktualizowanie agentów

Poza Hermesem agenci ci korzystają z leniwej instalacji mise: pierwsze uruchomienie instaluje CLI, a kolejne uruchomienia używają go ponownie. mise sprawdza też, co najwyżej raz na cztery godziny, czy zainstalowany agent ma nową wersję, tuż przed jego uruchomieniem lub w tle przy znaku zachęty powłoki. Jeśli ta aktualizacja się nie powiedzie lub jesteś offline, uruchomi się zainstalowana wersja. `omarchy update` aktualizuje zainstalowanych agentów wraz z resztą Omarchy, a `mup` aktualizuje tylko narzędzia zarządzane przez mise.

Własny aktualizator agenta, taki jak `claude update`, `codex update` lub przycisk aktualizacji w aplikacji, nie aktualizuje instalacji zarządzanej przez mise. `codex update` kończy się niepowodzeniem, a `claude update` może zgłosić sukces, instalując przy tym osobną kopię, której mise nie śledzi. Jeśli wolisz używać natywnego instalatora i aktualizatora agenta, dodaj go do `disable_tools`; zobacz [Wstępnie zainstalowane narzędzia CLI](18-development-tools.md#preinstalled-cli-tools).

Aby zainstalować wszystkie skonfigurowane narzędzia lazy, zanim będą ci potrzebne, uruchom `mise install --include-lazy`. Obejmuje to pozostałe domyślne narzędzia CLI Omarchy, jak również agentów. Zobacz [Wstępnie zainstalowane narzędzia CLI](18-development-tools.md#preinstalled-cli-tools), aby dowiedzieć się, jak zainstalować pojedyncze narzędzie lub użyć własnej instalacji.

`grok` jest instalowany przez pierwszoosobowy pakiet `grok` mise, w taki sam sposób jak `claude` i `codex`. Uruchom `grok` lub wybierz go w _Agent > Harness_. Pomiń instalator `curl | bash` na x.ai. Ta ścieżka umieszcza drugą kopię w `~/.grok/bin`, dodaje ją na początek `PATH` i nadpisuje wrapper Omarchy.

`dsh` otwiera swój interfejs przeglądarkowy pod adresem `127.0.0.1:3080`, z katalogiem uruchomienia jako domyślnym obszarem roboczym. Jego interfejs przeglądarkowy nie przyjmuje początkowego promptu, więc `omarchy agent prompt` otwiera go z promptem w schowku, do wklejenia. Omarchy uruchamia go z presetem uprawnień DeepSeek bez zatwierdzania. DeepSeek Harness przesyła logi sesji do DeepSeek, gdy korzystasz z jego oficjalnego API modeli; wyłącz to w jego interfejsie przeglądarkowym w _Settings > General > Upload Session Log_. Opinie, które mu wysyłasz, są przesyłane wraz z sesją, chyba że uruchomisz go z `DSH_TELEMETRY_MODE=DISABLED`.

### Domyślny agent

Wybierz swojego domyślnego agenta za pomocą `omarchy default agent <name>` lub w _Agent > Harness_ w Omarchy Menu (`Super + Space`). Jeśli agent nie jest jeszcze zainstalowany, wybranie go najpierw go zainstaluje. Świeże Omarchy zaprosi cię do dokonania tego wyboru jednorazowym powiadomieniem.

Wybranie Claude próbuje również skonfigurować jego rozszerzenie przeglądarkowe dla Chromium, Chrome, Brave, Brave Origin i Edge. Konfiguracja rozszerzenia dotyczy wszystkich użytkowników i może poprosić o hasło systemowe; anulowanie lub nieudana instalacja rozszerzenia nadal wybiera i uruchamia Claude. Uruchom ponownie przeglądarkę, włącz rozszerzenie, jeśli pojawi się monit, i zaloguj się do Claude, aby dokończyć łączenie. Uruchom `/chrome` w Claude, aby sprawdzić połączenie. Firefox i Zen nie obsługują tego rozszerzenia. Jeśli Claude był już twoim domyślnym agentem, zanim dodano tę konfigurację, wybierz go ponownie, aby zainstalować rozszerzenie.

Gdy już wybierzesz, `Super + Shift + Ctrl + A` uruchamia domyślnego agenta w dedykowanym oknie terminala (lub wywołuje selektor, jeśli jeszcze nie wybrałeś). Możesz też uruchomić go od razu do zadania za pomocą `omarchy agent prompt "Review this project"`. Freebuff i DeepSeek Harness nie przyjmują początkowego promptu, więc zamiast tego otwierają się z promptem w schowku, do wklejenia. Agenci uruchamiani w ten sposób działają bez nadzoru w swoich trybach niezatrzymywania się, aby pytać, więc bądź gotowy na to, że naprawdę będą coś robić! MiniMax Code nie ma takiego trybu dla swoich sesji interaktywnych, więc pyta o uprawnienia jak zwykle. A ponieważ agenci odmawiają zapamiętywania zaufania dla twojego katalogu domowego, uruchomienia z `$HOME` startują zamiast tego w `~/Work`.

Istnieją też skróty terminalowe: `a` uruchamia domyślnego agenta inline w bieżącym terminalu, natomiast `c`, `cx` i `cy` uruchamiają bezpośrednio OpenCode, Claude Code i Codex (ponownie w ich trybach automatycznego zatwierdzania). Zmiany motywu synchronizują się również z agentami: Claude Code, Pi, OpenCode i Hermes (po zainstalowaniu go przez Omarchy) podążają za tobą, gdy przełączasz motyw Omarchy.

### Twoje instrukcje dla agentów

Osobiste reguły dla każdego agenta trafiają do `~/.agents/AGENTS.md`, obok współdzielonych skilli w `~/.agents/skills`. Otwórz go w _Agent > Instructions_, które łączy go również do każdego harnessa przechowującego własny plik globalny: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` Copilota i tak dalej. Crush i Amp odczytują link `~/.config/AGENTS.md`, natomiast omp, Kimi i DeepSeek Harness odczytują bezpośrednio `~/.agents/AGENTS.md`. Wybranie domyślnego agenta również go podlinkowuje. Plik instrukcji, który już miałeś, staje się tym współdzielonym, jeśli jeszcze żadnego nie było; w przeciwnym razie jest przechowywany obok linku jako `.bak`. Uruchom `omarchy agent instructions`, aby ponownie podlinkować po zainstalowaniu kolejnego agenta.

### Panel agentów

Na górnym pasku znajduje się ikona agentów. Zanim skonfigurujesz agenta, jej panel przeprowadzi cię przez logowanie do Claude, Codex lub Grok, a pierwszy z nich stanie się twoim domyślnym agentem. Potem panel umieszcza każdą subskrypcję na jednej stronie: każdy agent i konto wraz ze swoim planem, wskaźnik dla każdego z jego limitów sesji 5-godzinnej i tygodniowego wraz z czasem do resetu (najedź, aby zobaczyć dokładny procent) lub pozostałe przedpłacone saldo, pod wierszem, który rotuje przez to, czego użyłeś we wszystkich z nich, na przykład tokeny w tym tygodniu i twój najczęściej używany model. W sekcji _Make something_ oferuje prompty startowe dla nowego motywu, pluginu, aplikacji lub gry, które przekazują zadanie twojemu domyślnemu agentowi. Aplikacje są budowane w taki sam sposób jak własne Hype, Monologue i Omacut Omarchy, w C++ i Qt Quick, zgodnie ze skillem agenta omarchy-app, a kompilator i elementy Qt, których potrzebują, są już zainstalowane. Gry to pojedyncza strona three.js w `~/Games/vibes`, zgodna ze skillem agenta web-game, i wszystkie otwierają się z jednego launchera Game Vibes w bieżącym motywie; ładują three.js z sieci, więc do uruchomienia potrzebują połączenia. Claude Code, Codex, Grok, Kimi, Cursor i jego pula Grok Bot, GitHub Copilot, Muse, Antigravity, Kimchi i Devin są obsługiwane od razu wraz ze swoimi limitami, a Hermes, Mistral Vibe i Qwen Code pokazują swoje sesje i tokeny, gdy już ich użyjesz. Plany dostawców i klucze, których używasz przez pi, omp lub opencode, również się pojawiają: OpenCode Zen i Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan i Synthetic wraz ze swoimi limitami; Fireworks, OpenRouter i DeepSeek wraz ze swoimi przedpłaconymi saldami; oraz modele, które uruchamiasz na własnym sprzęcie w sekcji Local models. Każdy agent jest liczony raz, u tego, kto go rozlicza, niezależnie od tego, przez ile harnessów go obsługujesz.

Kliknij lewym przyciskiem myszy ikonę na pasku, aby otworzyć panel, kliknij prawym, aby uruchomić domyślnego agenta. Rekordy użycia stojące za nim są regenerowane co 15 minut przez `omarchy agent usage-update`, a panel może nawet łączyć użycie z innych twoich maszyn za pośrednictwem zsynchronizowanego folderu. Zobacz README w `$OMARCHY_PATH/shell/plugins/agents/`, aby poznać pełne ustawienia.

### Kilka subskrypcji

Jeśli płacisz za więcej niż jeden plan Claude, Codex lub Grok — na przykład osobisty Max i służbowy — Omarchy może utrzymać je wszystkie zalogowane i przechodzić między nimi. Dodaj subskrypcję za pomocą + w panelu agentów, który przeprowadzi cię przez to na miejscu, lub za pomocą `omarchy agent account add claude Work` (albo `codex`, albo `grok`). Instaluje CLI, jeśli go brakuje. Pierwsze konto dla dostawcy loguje się przez twoją normalną przeglądarkę, dokładnie tam, gdzie CLI zawsze patrzy. Każde kolejne loguje się przez okno prywatne, aby konto, na które twoja przeglądarka jest już zalogowana, nie zostało wybrane przez pomyłkę; zaloguj się tam jako konto, które dodajesz, i najpierw zamknij każde okno prywatne, które już miałeś otwarte. Nigdy w tym celu nie wylogowuj się z CLI: wylogowanie unieważnia zapisane logowanie i to konto trzeba by dodać ponownie.

Aby skopiować logowania subskrypcji na inną maszynę Omarchy przez SSH, uruchom `omarchy agent account copy user@laptop`. Nadawca dostarcza tymczasowy odbiornik, gdy maszyna docelowa nie ma żadnego zainstalowanego, więc starsze maszyny Omarchy mogą odbierać konta bez aktualizacji. Zainstalowani odbiorniki mają pierwszeństwo. Kopiuje to wszystkie subskrypcje Claude, Codex i Grok; dodaj nazwy dostawców, aby je wybrać, na przykład `omarchy agent account copy laptop claude`. Nazwy kont i identyfikatory poleceń zgadzają się ze źródłem, w tym konta już obecne na maszynie docelowej. Niezwiązane konta docelowe otrzymują sufiks numeryczny, jeśli ich nazwy są sprzeczne, a ustawienia, skille, pluginy i historia rozmów pozostają lokalne dla każdej maszyny.

Istniejące dane uwierzytelniające na maszynie docelowej są zachowywane. Konto źródłowe już zalogowane tam ma swoją nazwę zsynchronizowaną bez zastępowania jego danych uwierzytelniających; pozostałe konta są dodawane obok niego. Aby zastąpić zapisane dane uwierzytelniające dla pasujących kont, użyj `omarchy agent account copy --replace laptop claude` po zamknięciu sesji tego konta na maszynie docelowej. Świeża maszyna docelowa otrzymuje również aktywne konto źródłowe i preferencje przełączania; ugruntowana maszyna docelowa zachowuje własne.

Dane uwierzytelniające podróżują przez SSH i są przechowywane w plikach prywatnych na maszynie docelowej, więc kopiuj tylko na maszyny, którym ufasz. Jest to jednorazowe kopiowanie, a nie bieżąca synchronizacja. Tokeny odświeżania Codex mogą zostać zrotowane przez inną maszynę, pozostawiając skopiowane logowanie wymagające odnowienia; osobne logowania pozostają najbardziej niezawodnym wyborem do jednoczesnego użycia na kilku maszynach. Zobacz [wskazówki Codex dotyczące uwierzytelniania kont](https://developers.openai.com/codex/auth/ci-cd-auth).

Jedno konto na dostawcę jest aktywne i każda nowa sesja zaczyna jako ono: `cx`, `cy`, zwykłe `claude`, `codex` lub `grok`, wszystko uruchamiane przez `omarchy agent` oraz skrypty lub edytory, które znajdują CLI w `PATH`. Przełącz za pomocą `omarchy agent account use work` (i z powrotem za pomocą `omarchy agent account use main`) lub w panelu, naciskając numer konta, a następnie `Enter` (lub klikając jego przycisk Use). Uruchomione sesje Claude też się przełączają, od następnej wiadomości: każda sesja Claude działa w `~/.claude`, który zawsze przechowuje logowanie aktywnego konta. Sesja Claude uruchomiona w folderze własnym konta przez starsze Omarchy przechowuje to logowanie, dopóki się nie zakończy, więc przełączenie wymienia te sesje i samo kończy się, gdy ich nie będzie. Uruchomione sesje Codex i Grok pozostają na koncie, na którym się rozpoczęły. Historia rozmów, ustawienia, skille i pluginy są współdzielone między kontami, więc `claude --continue` w tym samym folderze podejmuje pracę tam, gdzie ją zostawiłeś na nowym koncie.

Mając więcej niż jedno konto, panel pokazuje limity każdego konta obok siebie, z zaznaczonym aktywnym. Domyślnie Omarchy powiadamia cię, gdy aktywne konto przekroczy 95% limitu, a kliknięcie powiadomienia przełącza na konto z największym zapasem. Najedź na wiersz konta w panelu i kliknij Autoswitch, które pojawi się obok Use (lub naciśnij `m`), albo uruchom `omarchy agent account mode auto`, aby przełączało się samo; gdy jest włączone, Autoswitch zajmuje miejsce Use, a ponowne kliknięcie wraca do powiadamiania. Dodaj liczbę, aby zmienić próg, na przykład `omarchy agent account mode auto 90`. Jeśli każde konto przekracza próg, usłyszysz o tym raz, wraz z informacją, które konto zwolni się jako pierwsze. Gdy aktywne konto jest w odległości 15 punktów od swojego progu (80% przy ustawieniu domyślnym), jego limity są sprawdzane co trzy minuty, a nie co 15.

`omarchy agent account list` pokazuje każde konto i jego najnowsze limity, `omarchy agent account remove work` zapomina jedno, a `omarchy agent account rename primary Hey` zmienia nazwę jednego (lub kliknij nazwę konta w panelu). Polecenia te działają na kontach twojego domyślnego agenta; aby dotrzeć do innego dostawcy, najpierw go nazwij, na przykład `omarchy agent account use codex side`. Logowanie, które już miałeś w `~/.claude` lub `~/.codex`, to konto _Main_. Konto Codex zostaje tam, gdzie jest; konto Claude czeka we własnym folderze, podczas gdy inne konto jest aktywne. Konto pozostawione nieużywane przez ponad około osiem godzin może pokazywać _Sign-in required_; kliknij je, aby zalogować to konto ponownie bezpośrednio w panelu, lub przełącz się na nie i rozpocznij sesję, co odświeży logowanie samo. Serwery MCP, które dodasz za pomocą `claude mcp add`, docierają do każdego konta Claude, ponieważ wszystkie działają w `~/.claude`; w przypadku Codex i Grok serwery, które miałeś, gdy konto było dodawane, idą wraz z nim, ale późniejsze docierają jedynie do konta, w którym je dodałeś. Claude Desktop przechowuje własne logowanie, a narzędzia Codex lub Grok skonfigurowane bezwzględną ścieżką do binarki CLI nie podążają za przełączeniem. Jawne `CLAUDE_CONFIG_DIR`, `CODEX_HOME` lub `GROK_HOME` ma pierwszeństwo przed wybranym kontem.

### Diagnostyka awarii

Omarchy obserwuje systemd-coredump pod kątem awarii procesów. Gdy coś ulegnie błędowi segmentacji, otrzymasz powiadomienie "Process crashed" — kliknij je, a awaria zostanie przekazana twojemu domyślnemu agentowi wraz ze skillem diagnose-crash Omarchy, który przeprowadza agenta przez ustalenie faktów ze zrzutu pamięci i zdecydowanie, czy awaria jest warta zgłoszenia upstream. Możesz też uruchomić go ręcznie względem dowolnego PID z `coredumpctl list` za pomocą `omarchy agent crash <pid>`.

Obserwowanie jest domyślnie włączone. Wyłącz je w _Trigger > Toggle > Crash Capture_ (lub za pomocą `omarchy toggle crash-capture`), a powiadomienia ustaną; `omarchy agent crash <pid>` nadal działa ręcznie.

Awarie można też wyciszać po jednym programie naraz, co właśnie diagnoza proponuje ci na końcu. `omarchy crash mute hyprland` zatrzymuje powiadomienia tylko dla tego programu, `omarchy crash mute hyprland off` je przywraca, a samo `omarchy crash mute` wypisuje to, co wyciszyłeś. Przyjmuje ścieżkę binarki równie chętnie jak jej nazwę, więc `omarchy crash mute /usr/bin/hyprland` robi to samo. Nazwę ze spacją ujmij w cudzysłów, na przykład `omarchy crash mute 'Some App'`. Wszystko inne nadal powiadamia, a wyciszony program nadal ulega awarii — to ukrywa przypomnienie, niczego nie naprawia.

### Aplikacje desktopowe

Menu _Install > AI_ zawiera również kilka graficznych aplikacji AI: aplikację desktopową ChatGPT, aplikację desktopową Claude (betę Anthropic na Linuxa, z kartami Chat, Cowork i Claude Code), Grok Bot do czatowania z modelami xAI, Herdr Desktop, Hermes Desktop, OpenClaw, aplikację desktopową Perplexity i T3 Code. Grok Bot to desktopowa aplikacja do czatu. Agentem kodującym jest polecenie `grok`.

Hermes Desktop to ta, o której trzeba wiedzieć, ponieważ maszyna ma jednego Hermesa i należy on do aplikacji: Hermes jest instalowany wyłącznie przez aplikację, a polecenie `hermes`, które uruchamia domyślny agent, należy do aplikacji. Wybranie Hermesa jako domyślnego agenta instaluje to samo, co pozycja _Install > AI_: pakiet oraz runtime Hermes w `~/.hermes` skonfigurowany przez własny instalator Hermesa, co za pierwszym razem zajmuje kilka minut. Ten runtime to ten jeden Hermes, którego używają terminalowe polecenie `hermes`, domyślny agent i aplikacja, i aktualizuje się sam za pomocą `hermes update`, zamiast czekać na wydanie Omarchy. Zainstalowanie go przekazuje również Hermesowi motyw Omarchy jako skórkę o nazwie `omarchy`, za którą podąża każda powierzchnia Hermesa, gdy przełączasz motywy; wybierz inną w ustawieniach Appearance Hermesa lub za pomocą `/skin`, jeśli wolisz, aby tak nie było, a Omarchy zostawi ten wybór w spokoju. Usunięcie aplikacji w _Remove > AI_ najpierw zamyka Hermesa, w tym bramkę, zabiera ze sobą ten runtime i zachowuje twoje czaty, wspomnienia oraz skille, które Hermes napisał dla siebie, chyba że powiesz inaczej: pyta, domyślnie na nie, czy te dane i twoje ustawienia połączeń też powinny zniknąć.

Doświadczeniem desktopowym OpenClaw jest jego Control UI, które otwiera się jako aplikacja webowa wspierana przez własną lokalną bramkę. OpenClaw mieszka w `~/.openclaw` i aktualizuje się sam: użyj przycisku "Update Gateway" w Control UI lub uruchom `openclaw update`, a bramka uruchomi się ponownie na nowej wersji. Omarchy wybiera jedynie wydanie, od którego zaczyna świeża instalacja. Usunięcie OpenClaw w _Remove > AI_ zabiera ze sobą usługę bramki i aplikację, a następnie pyta, czy `~/.openclaw` też powinien zniknąć, ponieważ przechowuje twoje czaty i dane uwierzytelniające obok samego OpenClaw i runtime'ów pluginów, które pobiera; domyślnie go zachowuje, a ponowne zainstalowanie OpenClaw go odzyska.

Herdr Desktop to aplikacja desktopowa [Herdr](https://herdr.dev): przestrzenie, karty i panele terminali oraz agentów kodujących, które nadal działają w jej rdzeniu, gdy zamkniesz okno. Pochodzi z własnego instalatora Herdr zamiast z pakietu, więc mieszka w `~/.local/share/herdr-app`, przynosi ze sobą swój rdzeń w `~/.local/bin/herdr-core`, gdy jeszcze żadnego nie masz, i aktualizuje obie te rzeczy sama. Siedzi obok polecenia `herdr`, które Omarchy dostarcza na `Super + Ctrl + Return`, zamiast go zastępować, i otrzymuje bezpośrednie klawisze tego polecenia: `Alt + Return` i `Alt + Shift + Return` dzielą panel w dół lub w prawo, `Alt + Escape` go zamyka, `Ctrl + Alt + Arrow` przemieszcza między panelami, `Alt + 1..9` i `Alt + Left/Right` wybierają kartę, a `Alt + Up/Down` przemieszczają między przestrzeniami. `Ctrl + 1..9` wybiera przestrzeń, a `Alt + Shift + Up/Down` przechodzi przez agentów. Klawisze prefiksu `Ctrl + Space` pozostają wyłącznie terminalowe, ponieważ aplikacja nie może przytrzymać zwykłego klawisza Ctrl dla sekwencji. Omarchy zapisuje je do `~/.config/herdr-app/keys.json`, a `omarchy-refresh-herdr-app` je przywraca. Zainstalowanie jej wybiera motyw Omarchy w Herdr, który od tej pory podąża za twoim motywem Omarchy. Herdr przechowuje jeden motyw dla trybu jasnego i jeden dla ciemnego, więc po przełączeniu między ciemnym a jasnym motywem Omarchy wybierz Omarchy w selektorze motywów Herdr jeszcze raz dla drugiego trybu.

T3 Code działa z oficjalnego wydania AppImage w `~/.local/share/t3code` zamiast z pakietu, więc aktualizuje się sam. Zainstalowanie go pyta, czy zacząć na kanale Stable czy Nightly; przełącz później w ustawieniach T3 Code. Twoje wątki i ustawienia mieszkają w `~/.t3`, a usunięcie T3 Code w _Remove > AI_ zabiera je ze sobą.

### Modele lokalne

Uruchom otwarty model na własnej maszynie dla swoich agentów kodujących. Twoje prompty i kod pozostają na maszynie; nic wysłanego do modelu jej nie opuszcza. Zacznij od:

```bash
omarchy agent local use best
```

Lub, w panelu agentów na górnym pasku, wybierz + a następnie Local AI, które pojawia się, gdy model pasuje do tej maszyny. Za pierwszym razem instaluje to Podman, który uruchamia modele, a na maszynie NVIDIA zestaw narzędzi kontenerowych NVIDIA, który daje im GPU. Omarchy następnie wybiera zalecany model dla tej maszyny, pobiera go i uruchamia. Spodziewaj się pobrania dziesiątek GB i zajęcia większości pamięci maszyny, gdy model działa: Flash Next używa około 100 GiB przy swoim pełnym kontekście 256K. Jeśli inne modele zajmują pamięć, której potrzebuje, jest konfigurowany jako zatrzymany, gotowy do uruchomienia, gdy jeden zatrzymasz. Model zatrzymuje się przy wylogowaniu; zatrzymaj go sam, gdy potrzebujesz pamięci do czegoś innego.

`omarchy agent local list` pokazuje opcje i wyjaśnia, dlaczego niektóre nie pasują. Aby skonfigurować kolejny, uruchom `omarchy agent local use <recipe>`. Dziś `qwen3.8-flash-next-gufo` i `qwen3.8-27b-gufo` są dostępne dla maszyn Strix Halo ze 128 GB; 27B zajmuje około 40 GiB, więc zostawia miejsce na inną pracę. Na laptopie 64 GB z Intel Arc B390 `qwen3.6-35b-a3b-llamacpp` działa w około 30 GiB. Nowe recipe i zalecenia przychodzą wraz z `omarchy update`, przez pakiet.

Każdy skonfigurowany model otrzymuje własny wiersz w panelu agentów, obok twoich subskrypcji: play, aby go uruchomić, pause, aby go zatrzymać i zwolnić jego pamięć, oraz przycisk terminala, aby otworzyć na nim swojego agenta. Kilka może działać jednocześnie, gdy razem mieszczą się w pamięci; jeśli jeden się nie mieści, Omarchy mówi, który uruchomiony model zatrzymać. Przeciągaj wiersze, aby zmienić ich kolejność, i naciśnij Delete na wybranym wierszu, aby usunąć model i jego pobrane pliki.

Każdy skonfigurowany model otrzymuje również własny wpis w launcherze aplikacji, pod nazwą modelu i z logo jego twórcy, tak jak zalogowanie się do Claude, Codex lub Grok dodaje taki wpis. Otwiera twojego agenta na tym modelu i najpierw uruchamia model, jeśli nie działa: terminal pokazuje jego ładowanie i przekazuje kontrolę agentowi, gdy już działa. Usunięcie modelu usuwa jego wpis.

Z wiersza poleceń `omarchy agent local start <recipe>` i `omarchy agent local stop <recipe>` robią to samo, `omarchy agent local status` pokazuje każdy model, a `omarchy agent --local` otwiera twojego domyślnego agenta na ostatnim modelu, który uruchomiłeś. pi, OpenCode i Qwen Code mogą używać jednego; przy każdym innym domyślnym otwiera się w pi. pi wypisuje również każdy skonfigurowany przez ciebie model oraz te na maszynach, z którymi się sparowałeś, we własnym selektorze modeli, więc zwykłe `pi` też do nich dociera. Każdy klient zgodny z OpenAI też może się połączyć: `status` pokazuje adres każdego modelu (pierwszy to `http://127.0.0.1:11435/v1`), nazwa recipe to model, a klucz znajduje się w `~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` usuwa model oraz pobrane pliki, których nie używa żaden inny model.

Runtime'y firm trzecich są oznaczone swoim wydawcą. Omarchy uruchamia każdy model bez dostępu do sieci.

### Lokalne LLM-y

Omarchy zaleca dwa sposoby uruchamiania lokalnych modeli LLM: LM Studio i Ollama. LM Studio zapewnia interfejs GUI do znajdowania modeli o otwartych wagach, instalowania ich i uruchamiania. To świetny sposób, aby łatwo zacząć. Ollama oferuje CLI do robienia tego w podobny sposób. Ale jeśli dopiero zaczynasz z modelami lokalnymi, zacząłbym od LM Studio. Możesz zainstalować każde z nich w _Install > AI_ w Omarchy Menu.

### Skill Omarchy

Skille agentów pomagają AI używać konkretnych narzędzi w konkretny sposób, a Omarchy dostarcza domyślny skill do dostosowywania systemu. Jak dostosowywanie konfiguracji Hyprland, regulowanie paska czy nawet tworzenie nowego motywu od zera. Jest podlinkowany symbolicznie do katalogów skilli dla Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` oraz każdego `~/.hermes/profiles/*/skills`) oraz ogólnej lokalizacji `~/.agents/skills`, więc większość harnessów wykrywa go automatycznie.

Ale powinieneś traktować ten skill jako eksperymentalny. Różne modele będą go używać z różnym skutkiem. Najlepiej najpierw uruchomić go w trybie planowania, aby mieć pojęcie, co agent chciałby zmienić. A potem bądź gotowy, aby cofnąć zmiany lub nawet wywołać `omarchy reinstall configs`, jeśli agent narobi bałaganu we wszystkim.
