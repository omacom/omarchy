# AI

Omarchy traktuje agentów kodujących AI jak obywateli pierwszej kategorii, ale nie wybiera za Ciebie faworyta. Zamiast tego każde ważne CLI agenta kodującego jest wstępnie podpięte jako leniwie ładowany launcher. Launchery to maleńkie fragmenty zarządzane przez [mise](https://mise.jdx.dev/) w `~/.local/bin/`, więc nic nie jest pobierane, dopóki faktycznie po raz pierwszy któregoś nie uruchomisz. Hermes jest wyjątkiem: nic nie jest dla niego zastępowane fragmentem, a jego wybór instaluje Hermes Desktop, jak wyjaśnia sekcja _Aplikacje desktopowe_ poniżej. Wywołaj dowolnego z nich i uwierzytelnij się, gdy pojawi się monit:

| Polecenie    | Agent                                                            |
|------------|------------------------------------------------------------------|
| `claude`   | [Claude Code](https://code.claude.com/docs/en/overview)          |
| `codex`    | [OpenAI Codex](https://github.com/openai/codex)                  |
| `opencode` | [OpenCode](https://opencode.ai/)                                 |
| `agy`      | [Google Antigravity CLI](https://github.com/google-antigravity/antigravity-cli) |
| `copilot`  | [GitHub Copilot CLI](https://github.com/github/copilot-cli)      |
| `crush`    | [Crush](https://github.com/charmbracelet/crush)                  |
| `grok`     | [Grok Build](https://x.ai/build) od xAI                        |
| `kimi`     | [Kimi Code](https://www.kimi.com/code/docs/en/)                  |
| `pi`       | [Pi Mario Zechnera](https://github.com/badlogic/pi-mono)        |
| `omp`      | [Oh My Pi](https://github.com/can1357/oh-my-pi)                  |
| `ori`      | [Ori](https://openrouter.ai/docs/guides/ori/harness), harness OpenRouter |
| `hermes`   | [Hermes](https://hermes-agent.nousresearch.com/), agent Nous Research  |
| `muse`     | [Muse Code](https://dev.meta.ai), agent kodujący Meta           |
| `cursor-agent` | [Cursor CLI](https://cursor.com/cli)                         |

`ori` jest tu wyjątkiem: uruchamia inne harnessy przeciwko całemu katalogowi modeli OpenRouter, więc `ori claude`, `ori codex` czy `ori opencode` uruchamiają tych agentów na dowolnym modelu, na który ich skierujesz, a `ori code` jest własnym agentem Ori.

Aby opakować dodatkowe CLI w ten sam sposób, uruchom `omarchy-mise-install <package> [command-name]`. Fragmenty są utrzymywane w aktualności wraz ze wszystkim innym, czym zarządza mise, gdy uruchamiasz `omarchy update` (lub alias `mup`).

`grok` jest instalowany przez pierwszorządny pakiet `grok` z mise, w ten sam sposób co `claude` i `codex`. Uruchom `grok` lub wybierz go w _Konfiguracja > Domyślne > Agent_. Pomiń instalator `curl | bash` z x.ai. Ta ścieżka umieszcza drugą kopię w `~/.grok/bin`, dopisuje ją na początku `PATH` i nadpisuje wrapper Omarchy.

### Domyślny agent

Wybierz domyślnego agenta za pomocą `omarchy default agent <name>` lub w _Konfiguracja > Domyślne > Agent_ w Menu Omarchy (`Super + Space`). Jeśli agent nie jest jeszcze zainstalowany, jego wybór najpierw go zainstaluje. Świeży Omarchy zaprosi Cię do dokonania tego wyboru jednorazowym powiadomieniem.

Wybór Claude podejmuje także próbę skonfigurowania jego rozszerzenia przeglądarki dla Chromium, Chrome, Brave, Brave Origin i Edge. Konfiguracja rozszerzenia dotyczy wszystkich użytkowników i może poprosić o hasło systemowe; anulowanie lub nieudana instalacja rozszerzenia nadal wybiera i uruchamia Claude. Uruchom ponownie przeglądarkę, włącz rozszerzenie, jeśli pojawi się monit, i zaloguj się do Claude, aby zakończyć jego łączenie. Uruchom `/chrome` w Claude, aby sprawdzić połączenie. Firefox i Zen nie obsługują tego rozszerzenia. Jeśli Claude był już Twoim domyślnym agentem przed dodaniem tej konfiguracji, wybierz go ponownie, aby zainstalować rozszerzenie.

[Muse Code](https://dev.meta.ai) — `muse` od Meta — używa preinstalowanego fragmentu mise, jak pozostali agenci. Wybór go jako domyślnego instaluje oficjalny launcher Meta przez backend HTTP mise. Launcher weryfikuje i aktualizuje natywny plik binarny dla Twojego komputera.

Po dokonaniu wyboru `Super + Shift + Ctrl + A` uruchamia domyślnego agenta w dedykowanym oknie terminala (lub otwiera selektor, jeśli jeszcze nie wybrałeś). Możesz także uruchomić go wprost do zadania za pomocą `omarchy agent prompt "Review this project"`. Agenci uruchomieni w ten sposób działają bez nadzoru w swoich trybach niezatrzymywania się, by pytać, więc bądź gotowy na to, że faktycznie będą coś robić! A ponieważ agenci odmawiają zapamiętywania zaufania dla katalogu domowego, uruchomienia z `$HOME` startują zamiast tego w `~/Work`.

Istnieją też skróty terminala: `a` uruchamia domyślnego agenta w bieżącym terminalu, a `c`, `cx` i `cy` uruchamiają bezpośrednio OpenCode, Claude Code i Codex (znowu w ich trybach automatycznego zatwierdzania). Zmiany motywu synchronizują się też z agentami: Claude Code, Pi, OpenCode i Hermes (gdy Omarchy go zainstaluje) podążają za Tobą, gdy zmieniasz motyw Omarchy.

### Panel agentów

Górny pasek ma ikonę agentów. Zanim skonfigurujesz agenta, jego panel przeprowadza Cię przez logowanie do Claude, Codex lub Grok, a pierwszy z nich staje się Twoim domyślnym agentem. Potem panel umieszcza każdą subskrypcję na jednej stronie: każdego agenta i konto wraz z jego planem, wskaźnik dla każdego z jego 5-godzinnych limitów sesji i limitów tygodniowych z czasem do resetu (najedź, aby zobaczyć dokładny procent) lub pozostałe przedpłacone saldo, pod linią, która przewija to, co zużyłeś u wszystkich z nich, na przykład tokeny w tym tygodniu i Twój najczęściej używany model. W sekcji _Zrób coś_ oferuje prompty startowe dla nowego motywu, wtyczki lub aplikacji, które przekazują zadanie Twojemu domyślnemu agentowi. Aplikacje są budowane w ten sposób, w jaki budowane są własne Hype, Monologue i Omacut z Omarchy, w C++ i Qt Quick, zgodnie ze skillem agenta omarchy-app, a kompilator i elementy Qt, których potrzebują, są zainstalowane. Claude Code, Codex, Grok, Fireworks i Kimi są obsługiwane po wyjęciu z pudełka. Kimi raportuje obecnie limity kwoty konta bez lokalnych statystyk tokenów lub promptów.

Kliknij lewym przyciskiem ikonę paska, aby otworzyć panel, prawym przyciskiem, aby uruchomić domyślnego agenta. Rekordy zużycia stojące za tym są regenerowane co 15 minut przez `omarchy agent usage-update`, a panel może nawet łączyć zużycie z innych Twoich komputerów przez zsynchronizowany folder. Zobacz README w `$OMARCHY_PATH/shell/plugins/agents/`, aby poznać pełne ustawienia.

### Wiele subskrypcji

Jeśli płacisz za więcej niż jeden plan Claude, Codex lub Grok — na przykład osobisty Max i jeden firmowy — Omarchy może utrzymać je wszystkie zalogowane i przechodzić między nimi. Dodaj subskrypcję za pomocą + w panelu agentów, który przeprowadzi Cię przez to na miejscu, lub za pomocą `omarchy agent account add claude Work` (lub `codex`, lub `grok`). Instaluje CLI, jeśli go brakuje. Pierwsze konto dla dostawcy loguje się przez normalną przeglądarkę, dokładnie tam, gdzie CLI zawsze patrzy. Każde kolejne loguje się przez okno prywatne, więc konto, na które przeglądarka jest już zalogowana, nie zostanie podchwycone przez pomyłkę; zaloguj się tam jako konto, które dodajesz, i najpierw zamknij wszelkie okno prywatne, które już miałeś otwarte. Nigdy nie wylogowuj się z CLI, aby to zrobić: wylogowanie odwołuje zapisane logowanie, a to konto musiałoby zostać dodane ponownie.

Aby skopiować logowania subskrypcji na inny komputer z Omarchy przez SSH, uruchom `omarchy agent account copy user@laptop`. Nadawca dostarcza tymczasowy odbiornik, gdy miejsce docelowe nie ma zainstalowanego, więc starsze komputery z Omarchy mogą odbierać konta bez aktualizacji. Zainstalowane odbiorniki mają pierwszeństwo. To kopiuje wszystkie subskrypcje Claude, Codex i Grok; dodaj nazwy dostawców, aby je wybrać, jak w `omarchy agent account copy laptop claude`. Nazwy kont i identyfikatory poleceń odpowiadają źródłu, w tym konta już obecne w miejscu docelowym. Niepowiązane konta docelowe otrzymują sufiks numeryczny, jeśli ich nazwy są w konflikcie, a ustawienia, skille, wtyczki i historia rozmów pozostają lokalne na każdym komputerze.

Istniejące poświadczenia docelowe są zachowywane. Konto źródłowe już tam zalogowane ma zsynchronizowaną nazwę bez zastępowania jego poświadczeń; inne konta są dodawane obok niego. Aby zastąpić zapisane poświadczenia dla pasujących kont, użyj `omarchy agent account copy --replace laptop claude` po zamknięciu sesji tego konta w miejscu docelowym. Świeże miejsce docelowe otrzymuje też aktywne konto źródła i preferencje przełączania; ustalone miejsce docelowe zachowuje własne.

Poświadczenia podróżują przez SSH i są przechowywane w prywatnych plikach w miejscu docelowym, więc kopiuj tylko na komputery, którym ufasz. To jest jednorazowa kopia, a nie ciągła synchronizacja. Tokeny odświeżania Codex mogą zostać zrotowane przez inny komputer, pozostawiając skopiowane logowanie wymagające odnowienia; osobne logowania pozostają najbardziej niezawodnym wyborem do jednoczesnego używania na kilku komputerach. Zobacz [wskazówki dotyczące uwierzytelniania kont w Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Jedno konto na dostawcę jest aktywne, a każda nowa sesja zaczyna się jako ono: `cx`, `cy`, proste `claude`, `codex` lub `grok`, wszystko uruchomione przez `omarchy agent` oraz skrypty lub edytory, które znajdują CLI w `PATH`. Przełącz za pomocą `omarchy agent account use work` (i z powrotem za pomocą `omarchy agent account use main`) lub w panelu, naciskając numer konta, a potem `Enter` (lub klikając jego przycisk Użyj). Sesje już uruchomione pozostają na koncie, z którym zaczęły. Historia rozmów, ustawienia, skille i wtyczki są współdzielone między kontami, więc `claude --continue` w tym samym folderze podejmuje, gdzie skończyłeś na nowym koncie.

Przy więcej niż jednym koncie panel pokazuje limity każdego konta obok siebie, z oznaczonym aktywnym. Domyślnie Omarchy powiadamia Cię, gdy aktywne konto przekracza 95% limitu, a kliknięcie powiadomienia przełącza na konto z największym zapasem. Najedź na wiersz konta w panelu i kliknij Autoswitch, który pojawia się obok Użyj (lub naciśnij `m`), lub uruchom `omarchy agent account mode auto`, aby przełączał się sam; gdy jest włączony, Autoswitch zajmuje miejsce Użyj, a kliknięcie go ponownie wraca do powiadamiania. Dodaj liczbę, aby zmienić próg, jak w `omarchy agent account mode auto 90`. Jeśli każde konto przekracza próg, usłyszysz o tym raz, wraz z tym, które konto zwalnia się pierwsze. Gdy aktywne konto znajduje się w пределах 15 punktów od swojego progu (80% przy domyślnym ustawieniu), jego limity są sprawdzane co trzy minuty, a nie co 15.

`omarchy agent account list` pokazuje każde konto i jego najnowsze limity, `omarchy agent account remove work` zapomina jedno, a `omarchy agent account rename primary Hey` zmienia nazwę jednego (lub kliknij nazwę konta w panelu). Te polecenia działają na kontach domyślnego agenta; aby sięgnąć drugiego dostawcy, najpierw go nazwij, jak w `omarchy agent account use codex side`. Logowanie, które już miałeś w `~/.claude` lub `~/.codex`, jest kontem _Main_ i zostaje tam, gdzie jest. Konto pozostawione nieużywane dłużej niż około osiem godzin może pokazywać _Wymagane logowanie_; kliknij je, aby zalogować to konto ponownie wprost w panelu lub uruchom w nim sesję, co samo odświeży logowanie. Serwery MCP, które miałeś, gdy konto było dodawane, przechodzą do niego, ale te dodane później za pomocą `claude mcp add` docierają tylko do konta, w którym je dodałeś. Claude Desktop i narzędzia skonfigurowane z bezwzględną ścieżką do binarki CLI nie podążają za przełączeniem. Jawne `CLAUDE_CONFIG_DIR`, `CODEX_HOME` lub `GROK_HOME` ma pierwszeństwo przed wybranym kontem.

### Diagnoza awarii

Omarchy obserwuje systemd-coredump pod kątem awarii procesów. Gdy coś segfaultuje, otrzymasz powiadomienie „Proces uległ awarii” — kliknij je, a awaria zostanie przekazana Twojemu domyślnemu agentowi wraz ze skillem diagnose-crash z Omarchy, który prowadzi agenta przez ustalenie faktów ze zrzutu pamięci i zdecydowanie, czy awarię warto zgłosić upstream. Możesz też uruchomić to ręcznie przeciwko dowolnemu PID z `coredumpctl list` za pomocą `omarchy agent crash <pid>`.

Obserwowanie jest domyślnie włączone. Wyłącz je w _Wyzwalacz > Przełącz > Przechwytywanie awarii_ (lub za pomocą `omarchy toggle crash-capture`), a powiadomienia ustaną; `omarchy agent crash <pid>` nadal działa ręcznie.

Awarie można też wyciszać jeden program na raz, co diagnoza oferuje Ci na końcu. `omarchy crash mute hyprland` zatrzymuje powiadomienia tylko dla tego programu, `omarchy crash mute hyprland off` je przywraca, a samo `omarchy crash mute` wypisuje to, co wyciszyłeś. Przyjmuje ścieżkę binarki równie chętnie jak jej nazwę, więc `omarchy crash mute /usr/bin/hyprland` robi to samo. Ujmij nazwę ze spacją w cudzysłów, jak w `omarchy crash mute 'Some App'`. Wszystko inne nadal powiadamia, a wyciszony program nadal ulega awarii — to ukrywa przypomnienie, nie naprawia niczego.

### Aplikacje desktopowe

Menu _Zainstaluj > AI_ niesie też kilka graficznych aplikacji AI: aplikację desktopową ChatGPT, aplikację desktopową Claude (linuksowa beta Anthropic, z kartami Chat, Cowork i Claude Code), Grok Bot do czatowania z modelami xAI, Hermes Desktop, OpenClaw i aplikację desktopową Perplexity. Grok Bot jest aplikacją desktopową do czatu. Agent kodujący to polecenie `grok`.

Hermes Desktop jest tym, o którym warto wiedzieć, bo komputer ma jednego Hermesa i należy on do aplikacji: Hermes jest zawsze instalowany tylko przez aplikację, a polecenie `hermes`, które uruchamia domyślny agent, należy do aplikacji. Wybór Hermes jako domyślnego agenta instaluje to samo, co wpis _Zainstaluj > AI_: pakiet oraz środowisko wykonawcze Hermes w `~/.hermes` skonfigurowane przez własny instalator Hermes, co za pierwszym razem zajmuje kilka minut. To środowisko wykonawcze jest tym jedynym Hermes, którego używają terminalowe polecenie `hermes`, domyślny agent i aplikacja, i aktualizuje się samo za pomocą `hermes update`, zamiast czekać na wydanie Omarchy. Jego instalacja przekazuje też Hermes motyw Omarchy jako skórkę o nazwie `omarchy`, za którą podąża każda powierzchnia Hermes, gdy zmieniasz motywy; wybierz inną w ustawieniach Wyglądu Hermes lub za pomocą `/skin`, jeśli wolisz, by tak nie było, a Omarchy zostawi ten wybór w spokoju. Usunięcie aplikacji w _Usuń > AI_ najpierw zamyka Hermes, w tym bramę, zabiera z nią to środowisko wykonawcze i zachowuje czaty, wspomnienia i skille, które Hermes napisał dla siebie, chyba że powiesz inaczej: pyta, domyślnie na nie, czy te dane i Twoje ustawienia połączeń też mają zniknąć.

Doświadczenie desktopowe OpenClaw to jego Control UI, które otwiera się jako aplikacja webowa wspierana przez własną lokalną bramę. OpenClaw żyje w `~/.openclaw` i aktualizuje się sam: użyj przycisku „Update Gateway” w Control UI lub uruchom `openclaw update`, a brama uruchomi się ponownie na nowej wersji. Omarchy wybiera tylko wydanie, od którego zaczyna świeża instalacja. Usunięcie OpenClaw w _Usuń > AI_ zabiera z nim usługę bramy i aplikację, a potem pyta, czy `~/.openclaw` też ma zniknąć, ponieważ trzyma czaty i poświadczenia obok samego OpenClaw i środowisk wykonawczych wtyczek, które pobiera; domyślnie je zachowuje, a ponowna instalacja OpenClaw je podejmuje.

### Lokalne modele LLM

Omarchy poleca dwa sposoby uruchamiania lokalnych modeli LLM: LM Studio i Ollama. LM Studio dostarcza interfejs GUI do znajdowania modeli o otwartych wagach, ich instalowania i uruchamiania. To świetny sposób, aby łatwo zacząć. Ollama oferuje CLI do robienia tego podobnie. Ale jeśli jesteś nowy w modelach lokalnych, zacząłbym od LM Studio. Możesz zainstalować każde z nich w _Zainstaluj > AI_ w Menu Omarchy.

### Skill Omarchy

Skille agentów pomagają AI używać określonych narzędzi w określony sposób, a Omarchy jest dostarczany z domyślnym skillem do dostosowywania systemu. Na przykład poprawianie konfiguracji Hyprland, dopasowywanie paska czy nawet tworzenie nowego motywu od zera. Jest podlinkowany symbolicznie do katalogów skilli dla Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` oraz każdy `~/.hermes/profiles/*/skills`) i ogólnej lokalizacji `~/.agents/skills`, więc większość harnessów podchwytuje go automatycznie.

Ale powinieneś traktować ten skill jako eksperymentalny. Różne modele będą z niego korzystać z różnym efektem. Najlepiej najpierw działać w trybie planu, abyś miał wyobrażenie o tym, co agent chciałby zmienić. A potem bądź gotowy wycofać zmiany lub nawet wywołać `omarchy reinstall configs`, jeśli agent zrobi ze wszystkiego bałagan.
