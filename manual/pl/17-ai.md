# AI

Omarchy zawiera launchery dla poniższych agentów kodujących, nie wybierając za Ciebie domyślnego. Uruchom polecenie, aby zainstalować jego CLI przy pierwszym użyciu, a następnie uwierzytelnij się, gdy pojawi się monit. Hermes i OpenClaw są wyjątkami: nic nie jest dla nich instalowane przez mise, a wybranie któregokolwiek z nich konfiguruje jego własną, samoczynnie aktualizującą się kopię, jak wyjaśnia poniżej sekcja _Aplikacje desktopowe_.

### Instalowanie i aktualizowanie agentów

Z wyjątkiem Hermes i OpenClaw ci agenci używają leniwej instalacji mise: pierwsze uruchomienie instaluje CLI, a kolejne uruchomienia używają go ponownie. mise sprawdza też, co najwyżej raz na cztery godziny, czy dla zainstalowanego agenta jest nowa wersja, tuż przed jego uruchomieniem lub w tle przy znaku zachęty powłoki. Jeśli ta aktualizacja się nie powiedzie lub jesteś offline, uruchamia się zainstalowana wersja. `omarchy update` aktualizuje zainstalowanych agentów wraz z resztą Omarchy, a `mup` aktualizuje tylko narzędzia zarządzane przez mise.

Własny aktualizator agenta, taki jak `claude update`, `codex update` lub przycisk aktualizacji w aplikacji, nie aktualizuje instalacji zarządzanej przez mise. `codex update` kończy się niepowodzeniem, a `claude update` może zgłosić sukces, instalując oddzielną kopię, której mise nie śledzi. Jeśli wolisz używać natywnego instalatora i aktualizatora agenta, dodaj go do `disable_tools`; zobacz [Wstępnie zainstalowane narzędzia CLI](18-development-tools.md#preinstalled-cli-tools).

Aby zainstalować wszystkie skonfigurowane narzędzia lazy, zanim będą Ci potrzebne, uruchom `mise install --include-lazy`. Obejmuje to również inne domyślne narzędzia CLI Omarchy, a także agentów. Zobacz [Wstępnie zainstalowane narzędzia CLI](18-development-tools.md#preinstalled-cli-tools), aby dowiedzieć się, jak zainstalować pojedyncze narzędzie lub użyć własnej instalacji.

`grok` jest instalowany przez oficjalny pakiet `grok` mise, w ten sam sposób co `claude` i `codex`. Uruchom `grok` lub oznacz go gwiazdką w panelu agentów. Pomiń instalator `curl | bash` na x.ai. Ta ścieżka umieszcza drugą kopię w `~/.grok/bin`, dodaje ją na początku `PATH` i nadpisuje wrapper Omarchy.

`dsh` otwiera swój interfejs przeglądarkowy pod adresem `127.0.0.1:3080`, z katalogiem uruchomienia jako domyślnym obszarem roboczym. Jego interfejs przeglądarkowy nie przyjmuje promptu startowego, więc `omarchy agent prompt` otwiera go z promptem w Twoim schowku do wklejenia. Omarchy uruchamia go z presetem uprawnień DeepSeek bez zatwierdzania. DeepSeek Harness wysyła dzienniki sesji do DeepSeek, gdy używasz jego oficjalnego API modelu; wyłącz to w _Settings > General > Upload Session Log_ w jego interfejsie przeglądarkowym. Opinie, które mu wysyłasz, są również wysyłane wraz z sesją, chyba że uruchomisz go z `DSH_TELEMETRY_MODE=DISABLED`.

### Domyślny agent

Wybierz domyślnego agenta gwiazdką obok agenta w panelu agentów, która jest wypełniona przy domyślnym, lub poleceniem `omarchy default agent <name>`, które przyjmuje również dowolny harness bez wiersza w tym miejscu. Jeśli agent nie jest jeszcze zainstalowany, wybranie go najpierw go instaluje, a agent otrzymuje też własny launcher w launcherze aplikacji, obok Agent. Świeża instalacja Omarchy zaprasza do skonfigurowania agenta jednorazowym powiadomieniem, które otwiera panel agentów.

Wybranie Claude próbuje również skonfigurować jego rozszerzenie przeglądarki dla Chromium, Chrome, Brave, Brave Origin i Edge. Konfiguracja rozszerzenia dotyczy wszystkich użytkowników i może poprosić o Twoje hasło systemowe; anulowanie lub nieudana instalacja rozszerzenia nadal wybiera i uruchamia Claude. Uruchom ponownie przeglądarkę, włącz rozszerzenie, jeśli pojawi się monit, i zaloguj się do Claude, aby dokończyć jego łączenie. Uruchom `/chrome` w Claude, aby sprawdzić połączenie. Firefox i Zen nie obsługują tego rozszerzenia. Jeśli Claude był już Twoim domyślnym agentem, zanim dodano tę konfigurację, wybierz go ponownie, aby zainstalować rozszerzenie.

Po dokonaniu wyboru `Super + Shift + Ctrl + A` uruchamia domyślnego agenta w dedykowanym oknie terminala (lub wyświetla selektor, jeśli jeszcze nie dokonałeś wyboru). Możesz też uruchomić go od razu do zadania poleceniem `omarchy agent prompt "Review this project"`. Freebuff i DeepSeek Harness nie przyjmują promptu startowego, więc zamiast tego otwierają się z promptem w Twoim schowku do wklejenia. Agenci uruchamiani w ten sposób działają bez nadzoru w swoich odpowiednich trybach „nie zatrzymuj się, aby pytać”, więc bądź gotowy na to, że naprawdę będą coś robić! MiniMax Code nie ma takiego trybu dla swoich sesji interaktywnych, więc pyta o uprawnienia jak zwykle. A ponieważ agenci odmawiają zapamiętania zaufania dla Twojego katalogu domowego, uruchomienia z `$HOME` startują zamiast tego w `~/Work`.

Są też skróty terminalowe: `a` uruchamia domyślnego agenta inline w bieżącym terminalu, a `c`, `cx` i `cy` uruchamiają bezpośrednio OpenCode, Claude Code i Codex (ponownie w ich trybach automatycznego zatwierdzania). Zmiany motywu synchronizują się również z agentami: Claude Code, Pi, OpenCode i Hermes (gdy Omarchy go zainstaluje) podążają za Tobą, gdy przełączasz motyw Omarchy.

### Twoje instrukcje dla agentów

Osobiste reguły dla każdego agenta znajdują się w `~/.agents/AGENTS.md`, obok współdzielonych umiejętności w `~/.agents/skills`. Otwórz je ikoną dokumentu obok + w panelu agentów lub poleceniem `omarchy agent instructions --edit`, które linkuje je również do każdego harnessu przechowującego własny plik globalny: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` Copilot itd. Crush i Amp odczytują link `~/.config/AGENTS.md`, a omp, Kimi i DeepSeek Harness odczytują bezpośrednio `~/.agents/AGENTS.md`. Wybranie domyślnego agenta również go linkuje. Plik instrukcji, który już miałeś, staje się współdzielonym, jeśli jeszcze żadnego nie było; w przeciwnym razie jest przechowywany obok linku jako `.bak`. Uruchom `omarchy agent instructions`, aby ponownie połączyć po zainstalowaniu kolejnego agenta.

### Panel agentów

Górny pasek ma ikonę agentów. Zanim skonfigurujesz agenta, jego panel oferuje trzy sposoby rozpoczęcia: zaloguj się do subskrypcji Claude, Codex, Grok, Gemini, Muse, Cursor lub Copilot albo, w sekcji More, do planu kodowania OpenCode Go, MiniMax, Synthetic lub Z.ai; płać na bieżąco z Fireworks, OpenCode Zen i Go, OpenRouter albo, w sekcji More, z DeepSeek lub dowolnym innym dostawcą, do którego loguje się OpenCode, a wszystko to działa w OpenCode; albo uruchom najlepszy model dla swojego komputera, gdy jakiś do niego pasuje. Pierwszy z nich, który dokończysz, staje się Twoim domyślnym agentem, a + w panelu oferuje później te same trzy opcje. Potem panel umieszcza każdą subskrypcję na jednej stronie: każdy agent i konto wraz ze swoim planem, wskaźnik dla każdego z jego limitów sesji 5-godzinnej i tygodniowego wraz z czasem do jego resetu (najedź, aby zobaczyć dokładny procent) lub pozostałe saldo przedpłacone, pod wierszem, który rotacyjnie pokazuje, co wykorzystałeś we wszystkich z nich, np. tokeny w tym tygodniu i Twój najczęściej używany model. W sekcji _Make something cool_ oferuje prompty startowe dla nowego motywu, wtyczki, aplikacji lub gry, które przekazują zadanie Twojemu domyślnemu agentowi. Aplikacje są budowane w taki sposób, jak własne Hype, Monologue i Omacut Omarchy, w C++ i Qt Quick, zgodnie z umiejętnością agenta omarchy-make-app, a potrzebne im kompilator i elementy Qt są zainstalowane. Gry to pojedyncza strona three.js w `~/Games/vibes`, zgodna z umiejętnością agenta omarchy-make-game, i wszystkie otwierają się z jednego launchera Game Vibes w bieżącym motywie; ładują three.js z sieci, więc do uruchomienia potrzebują połączenia. Claude Code, Codex, Grok, Kimi, Cursor wraz z jego przydziałem Grok Bot, GitHub Copilot, Muse, Gemini (przez Antigravity) i Devin są obsługiwane od razu wraz ze swoimi limitami, Kimchi ze swoim planem, kredytami przedpłaconymi i budżetami wydatków, a Hermes, Mistral Vibe i Qwen Code pokazują swoje sesje i tokeny, gdy już ich użyjesz. Plany i klucze dostawców, których używasz przez pi, omp lub opencode, również się pojawiają: OpenCode Zen i Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan i Synthetic wraz ze swoimi limitami; OpenRouter i DeepSeek ze swoimi saldami przedpłaconymi; Fireworks ze swoimi wydatkami z ostatnich 30 dni. Tokeny z modeli, które uruchamiasz na własnym sprzęcie, również wliczają się do sum; same modele mają własny panel, opisany w sekcji [Modele lokalne](#local-models). Każdy agent jest liczony raz, u tego, kto go rozlicza, niezależnie od tego, przez ile harnessów go prowadzisz.

Kliknij lewym przyciskiem ikonę na pasku lub naciśnij `Super + Ctrl + X`, aby otworzyć panel, kliknij prawym przyciskiem, aby uruchomić domyślnego agenta, a środkowym, aby odświeżyć. Rekordy użycia stojące za panelem są regenerowane co 15 minut przez `omarchy agent usage update`, a panel może nawet łączyć użycie z innych Twoich maszyn za pośrednictwem zsynchronizowanego folderu. Zobacz README w `$OMARCHY_PATH/shell/plugins/agents/`, aby poznać pełne ustawienia.

### Kilka subskrypcji

Jeśli płacisz za więcej niż jeden plan Claude, Codex lub Grok — na przykład osobisty Max i służbowy — Omarchy może utrzymywać wszystkie zalogowane i przełączać się między nimi. Dodaj subskrypcję za pomocą + w panelu agentów, który przeprowadzi Cię przez to na miejscu, lub poleceniem `omarchy agent account add claude Work` (lub `codex`, lub `grok`). Ten sam + i to samo polecenie logują do Gemini (`gemini`) i OpenCode (`opencode`) oraz zapisują klucz API Fireworks (`fireworks`) lub OpenRouter (`openrouter`) w OpenCode; polecenie loguje też do Copilot (`copilot`), Cursor (`cursor`) i Muse (`muse`). Te zachowują po jednym zalogowaniu. Instaluje CLI, jeśli go brakuje. Pierwsze konto dostawcy loguje się przez Twoją normalną przeglądarkę, dokładnie tam, gdzie CLI zawsze szuka. Każde kolejne loguje się przez okno prywatne, aby konto, do którego Twoja przeglądarka jest już zalogowana, nie zostało wybrane przez pomyłkę; zaloguj się tam jako konto, które dodajesz, i najpierw zamknij każde okno prywatne, które masz już otwarte. Nigdy nie wylogowuj się z CLI, aby to zrobić: wylogowanie unieważnia zapisane logowanie, a to konto trzeba by dodać ponownie.

Aby skopiować logowania subskrypcji na inną maszynę Omarchy przez SSH, uruchom `omarchy agent account copy user@laptop`. Nadawca dostarcza tymczasowy odbiornik, gdy maszyna docelowa nie ma zainstalowanego, więc starsze maszyny Omarchy mogą odbierać konta bez aktualizacji. Zainstalowane odbiorniki mają pierwszeństwo. Kopiuje to wszystkie subskrypcje Claude, Codex i Grok; dodaj nazwy dostawców, aby je wybrać, np. `omarchy agent account copy laptop claude`. Nazwy kont i identyfikatory poleceń odpowiadają źródłu, w tym konta już obecne na maszynie docelowej. Niepowiązane konta docelowe otrzymują sufiks numeryczny, jeśli ich nazwy kolidują, a ustawienia, umiejętności, wtyczki i historia konwersacji pozostają lokalne dla każdej maszyny.

Istniejące dane uwierzytelniające na maszynie docelowej są zachowywane. Konto źródłowe już tam zalogowane ma zsynchronizowaną nazwę bez zastępowania jego danych uwierzytelniających; inne konta są dodawane obok niego. Aby zastąpić zapisane dane uwierzytelniające dla pasujących kont, użyj `omarchy agent account copy --replace laptop claude` po zakończeniu sesji tego konta na maszynie docelowej. Świeża maszyna docelowa otrzymuje też aktywne konto źródła i jego preferencje przełączania; ugruntowana maszyna docelowa zachowuje własne.

Dane uwierzytelniające podróżują przez SSH i są przechowywane w prywatnych plikach na maszynie docelowej, więc kopiuj tylko na maszyny, którym ufasz. To jednorazowa kopia, nie bieżąca synchronizacja. Tokeny odświeżania Codex mogą zostać zrotowane przez inną maszynę, pozostawiając skopiowane logowanie wymagające odnowienia; oddzielne logowania pozostają najbardziej niezawodnym wyborem przy jednoczesnym użyciu na kilku maszynach. Zobacz [przewodnik Codex dotyczący uwierzytelniania kont](https://developers.openai.com/codex/auth/ci-cd-auth).

Jedno konto na dostawcę jest aktywne, a każda nowa sesja zaczyna jako ono: `cx`, `cy`, zwykłe `claude`, `codex` lub `grok`, wszystko uruchamiane przez `omarchy agent` oraz skrypty lub edytory, które znajdują CLI w `PATH`. Przełączaj poleceniem `omarchy agent account use work` (i z powrotem poleceniem `omarchy agent account use main`) lub w panelu, naciskając numer konta, a następnie `Enter` (lub klikając jego gwiazdkę). Działające sesje Claude również się przełączają, od ich następnej wiadomości: każda sesja Claude działa w `~/.claude`, które zawsze przechowuje logowanie aktywnego konta. Sesja Claude uruchomiona we własnym folderze konta przez starsze Omarchy przechowuje to logowanie do momentu zakończenia, więc przełączenie wymienia te sesje i kończy się samo, gdy znikną. Działające sesje Codex i Grok pozostają na koncie, z którym wystartowały. Historia konwersacji, ustawienia, umiejętności i wtyczki są współdzielone między kontami, więc `claude --continue` w tym samym folderze kontynuuje w miejscu, w którym skończyłeś na nowym koncie.

Przy więcej niż jednym koncie panel pokazuje limity każdego konta obok siebie, z wypełnioną gwiazdką na używanym. Omarchy powiadamia Cię, gdy aktywne konto przekroczy 95% limitu, a kliknięcie powiadomienia przełącza na konto z największym zapasem. Nigdy nie przełącza samo. Zmień próg poleceniem `omarchy agent account threshold 90`. Jeśli każde konto przekracza próg, usłyszysz o tym raz, wraz z informacją, które konto zwolni się jako pierwsze. Gdy aktywne konto jest w granicach 15 punktów od swojego progu (80% przy ustawieniu domyślnym), jego limity są sprawdzane co trzy minuty, a nie co 15.

`omarchy agent account list` pokazuje każde konto i jego najnowsze limity, `omarchy agent account remove work` zapomina jedno, a `omarchy agent account rename primary Hey` zmienia nazwę jednego (lub kliknij nazwę konta w panelu). Te polecenia działają na kontach Twojego domyślnego agenta; aby dotrzeć do innego dostawcy, najpierw go wskaż, np. `omarchy agent account use codex side`. Logowanie, które już miałeś w `~/.claude` lub `~/.codex`, to konto _Main_. Konto Codex pozostaje tam, gdzie jest; konto Claude czeka we własnym folderze, gdy aktywne jest inne konto. Konto nieużywane przez ponad około osiem godzin może pokazywać _Sign-in required_; kliknij je, aby ponownie zalogować to konto bezpośrednio w panelu, lub przełącz się na nie i rozpocznij sesję, co samo odświeża logowanie. Serwery MCP, które dodajesz poleceniem `claude mcp add`, docierają do każdego konta Claude, ponieważ wszystkie działają w `~/.claude`; w przypadku Codex i Grok serwery, które miałeś, gdy konto było dodawane, przechodzą do niego, ale późniejsze docierają tylko do konta, w którym je dodałeś. Claude Desktop zachowuje własne logowanie, a narzędzia Codex lub Grok skonfigurowane z bezwzględną ścieżką do pliku binarnego CLI nie podążają za przełączeniem. Jawne `CLAUDE_CONFIG_DIR`, `CODEX_HOME` lub `GROK_HOME` ma pierwszeństwo przed wybranym kontem.

### Diagnostyka awarii

Omarchy obserwuje systemd-coredump pod kątem awarii procesów. Gdy wybierzesz domyślnego agenta, każdy Twój program, który zrzuci core, wywoła powiadomienie "Process crashed" — kliknij je, a awaria zostanie przekazana Twojemu domyślnemu agentowi wraz z umiejętnością omarchy-diagnose-crash Omarchy, która prowadzi agenta przez ustalenie faktów ze zrzutu core i podjęcie decyzji, czy awarię warto zgłosić upstream. Możesz też uruchomić je ręcznie dla dowolnego PID z `coredumpctl list` poleceniem `omarchy agent crash <pid>`.

Obserwowanie jest domyślnie włączone. Wyłącz je w _Trigger > Toggle > Crash Capture Off_ (lub poleceniem `omarchy toggle crash-capture`), a powiadomienia ustaną; `omarchy agent crash <pid>` nadal działa ręcznie.

Awarie można też wyciszać pojedynczo dla każdego programu, co diagnostyka oferuje Ci na końcu. `omarchy crash mute hyprland` zatrzymuje powiadomienia tylko dla tego programu, `omarchy crash mute hyprland off` je przywraca, a samo `omarchy crash mute` wypisuje, co wyciszyłeś. Przyjmuje ścieżkę pliku binarnego równie chętnie jak jego nazwę, więc `omarchy crash mute /usr/bin/hyprland` robi to samo. Nazwę ze spacją ujmij w cudzysłów, np. `omarchy crash mute 'Some App'`. Wszystko inne nadal powiadamia, a wyciszony program nadal się wywala — to ukrywa przypomnienie, niczego nie naprawia.

### Aplikacje desktopowe

Menu _Install > AI_ zawiera też kilka graficznych aplikacji AI: Amp Desktop, Antigravity Desktop, aplikację desktopową ChatGPT, aplikację desktopową Claude (beta Anthropic na Linux, z kartami Chat, Cowork i Claude Code), Grok Bot do czatowania z modelami xAI, Herdr Desktop, Hermes Desktop, OpenClaw, aplikację desktopową Perplexity i T3 Code. Grok Bot to desktopowa aplikacja do czatu. Agentem kodującym jest polecenie `grok`.

Hermes Desktop to ta, którą warto znać, ponieważ maszyna ma jednego Hermesa i należy on do aplikacji: Hermes jest instalowany wyłącznie przez aplikację, a polecenie `hermes`, które uruchamia domyślny agent, należy do aplikacji. Wybranie Hermes jako domyślnego agenta instaluje to samo, co pozycja _Install > AI_: pakiet oraz środowisko uruchomieniowe Hermes w `~/.hermes` skonfigurowane przez własny instalator Hermes, co za pierwszym razem zajmuje kilka minut. To środowisko uruchomieniowe to ten jeden Hermes, którego używają polecenie terminalowe `hermes`, domyślny agent i aplikacja, i aktualizuje się samo poleceniem `hermes update`, zamiast czekać na wydanie Omarchy. Zainstalowanie go przekazuje też Hermes motyw Omarchy jako skórkę o nazwie `omarchy`, za którą podąża każda powierzchnia Hermes, gdy przełączasz motywy; wybierz inną w ustawieniach Appearance Hermes lub poleceniem `/skin`, jeśli wolisz, aby tak nie było, a Omarchy pozostawi ten wybór w spokoju. Usunięcie aplikacji w _Remove > AI_ najpierw zamyka Hermes, wraz z bramką, zabiera ze sobą to środowisko uruchomieniowe i zachowuje Twoje czaty, wspomnienia oraz umiejętności, które Hermes napisał dla siebie, chyba że powiesz inaczej: pyta, domyślnie odpowiadając nie, czy te dane i Twoje ustawienia połączenia również mają zniknąć.

Doświadczeniem desktopowym OpenClaw jest jego Control UI, które otwiera się jako aplikacja webowa wspierana przez jego własną lokalną bramkę. OpenClaw mieszka w `~/.openclaw` i aktualizuje się samo: użyj przycisku "Update Gateway" w Control UI lub uruchom `openclaw update`, a bramka uruchomi się ponownie na nowej wersji. Omarchy wybiera jedynie wersję, od której zaczyna świeża instalacja. OpenClaw może być też Twoim domyślnym agentem: wybranie go poleceniem `omarchy default agent openclaw` konfiguruje tę samą kopię w `~/.openclaw`, a agent otwiera terminal UI OpenClaw podłączony do jego bramki. Usunięcie OpenClaw w _Remove > AI_ zabiera usługę bramki i aplikację, a następnie pyta, czy `~/.openclaw` również ma zniknąć, ponieważ przechowuje Twoje czaty i dane uwierzytelniające wraz z samym OpenClaw i środowiskami uruchomieniowymi wtyczek, które pobiera; domyślnie je zachowuje, a ponowna instalacja OpenClaw je odzyska.

Herdr Desktop to aplikacja desktopowa [Herdr](https://herdr.dev): przestrzenie, karty i panele terminali i agentów kodujących, które nadal działają w jej rdzeniu, gdy zamkniesz okno. Pochodzi z własnego instalatora Herdr, a nie z pakietu, więc mieszka w `~/.local/share/herdr-app`, przynosi swój rdzeń w `~/.local/bin/herdr-core`, gdy jeszcze go nie masz, i aktualizuje oba samodzielnie. Stoi obok polecenia `herdr`, które Omarchy dostarcza na `Super + Ctrl + Return`, zamiast je zastępować, i otrzymuje bezpośrednie klawisze tego polecenia: `Alt + Return` i `Alt + Shift + Return` dzielą panel w dół lub w prawo, `Alt + Escape` go zamyka, `Ctrl + Alt + Arrow` przemieszcza między panelami, `Alt + 1..9` i `Alt + Left/Right` wybierają kartę, a `Alt + Up/Down` przemieszczają między przestrzeniami. `Ctrl + 1..9` wybiera przestrzeń, a `Alt + Shift + Up/Down` przechodzi przez agentów. Klawisze prefiksu `Ctrl + Space` pozostają tylko dla terminala, ponieważ aplikacja nie może przytrzymać zwykłego klawisza Ctrl dla sekwencji. Omarchy zapisuje je do `~/.config/herdr-app/keys.json`, a `omarchy-refresh-herdr-app` je przywraca. Zainstalowanie go wybiera motyw Omarchy Herdr, który od tej pory podąża za Twoim motywem Omarchy. Herdr przechowuje jeden motyw dla trybu jasnego i jeden dla ciemnego, więc po przełączeniu między ciemnym a jasnym motywem Omarchy wybierz ponownie Omarchy w selektorze motywów Herdr dla drugiego trybu.

T3 Code działa z jego oficjalnego wydania AppImage w `~/.local/share/t3code`, a nie z pakietu, więc aktualizuje się samo. Instalacja pyta, czy zacząć na kanale Stable czy Nightly; przełącz później w ustawieniach T3 Code. Twoje wątki i ustawienia mieszkają w `~/.t3`, a usunięcie T3 Code w _Remove > AI_ zabiera je ze sobą.

### Modele lokalne

Uruchom otwarty model na własnej maszynie dla swoich agentów kodujących. Twoje prompty i kod pozostają na maszynie; nic wysłanego do modelu jej nie opuszcza. Zacznij od:

```bash
omarchy models use best text
```

To konfiguruje najlepszy model tekstowy dla tej maszyny, ten, którego używają Twoi agenci. Modele obrazu, wideo i muzyki mają swój własny najlepszy: `omarchy models use best image`, `video` lub `music`. Uruchom `omarchy models use best`, aby zobaczyć wybór dla każdego rodzaju na tej maszynie.

Albo otwórz panel modeli lokalnych z jego ikony iskier na górnym pasku, obok ikony agentów, lub za pomocą Super + Ctrl + Alt + X, i wybierz +. Ikona pojawia się, gdy model pasuje do tej maszyny. Podman, który uruchamia modele, jest dostarczany z Omarchy, podobnie jak zestaw narzędzi kontenerowych NVIDIA na maszynie NVIDIA, który daje im GPU; jeśli któregoś z nich brakuje, pierwsza konfiguracja go instaluje. Omarchy następnie wybiera zalecany model dla tej maszyny, pobiera go i uruchamia. Spodziewaj się pobrania dziesiątek GB i większości pamięci maszyny używanej podczas działania modelu: Flash Next używa około 100 GiB przy swoim pełnym kontekście 256K. Jeśli inne modele zajmują potrzebną mu pamięć, jest konfigurowany jako zatrzymany, gotowy do uruchomienia, gdy zatrzymasz jeden z nich. Model zatrzymuje się przy wylogowaniu; zatrzymaj go sam, gdy potrzebujesz pamięci do czegoś innego.

`omarchy models list` pokazuje opcje i wyjaśnia, dlaczego niektóre nie pasują. Aby skonfigurować inny, uruchom `omarchy models use <recipe>`. Obecnie `qwen3.8-flash-next-gufo` i `qwen3.8-27b-gufo` są dostępne dla maszyn Strix Halo 128 GB; 27B zajmuje około 40 GiB, więc zostawia miejsce na inną pracę. Na laptopie 64 GB z Intel Arc B390 `qwen3.6-35b-a3b-llamacpp` działa w około 30 GiB. Nowe przepisy i rekomendacje przychodzą z `omarchy update`, przez pakiet.

Każdy skonfigurowany model otrzymuje własny wiersz w panelu modeli lokalnych: play, aby go uruchomić, pause, aby go zatrzymać i zwolnić jego pamięć, oraz przycisk terminala, aby otworzyć na nim swojego agenta. Na górze pasek pokazuje, jak pamięć maszyny jest podzielona między samo Omarchy (system i Twoje aplikacje), każdy działający model i to, co jest wolne. Wskaż zatrzymany model, a pasek pokaże, czy pasuje, lub ile mu brakuje. Kilka może działać jednocześnie, gdy razem mieszczą się w pamięci; jeśli jeden nie pasuje, Omarchy powie, który działający model zatrzymać. Przeciągaj wiersze za ich logo, aby zmienić ich kolejność, i naciśnij Delete na wybranym wierszu, aby usunąć model i jego pobrane pliki.

Każdy skonfigurowany model kodujący otrzymuje też własny wpis w launcherze aplikacji, pod nazwą modelu i z logo jego twórcy, tak jak zalogowanie do Claude, Codex lub Grok dodaje taki wpis. Otwiera Twojego agenta na tym modelu i najpierw uruchamia model, jeśli nie działa: terminal pokazuje jego ładowanie i przekazuje kontrolę agentowi, gdy model jest gotowy. Usunięcie modelu usuwa jego wpis.

Nie każdy model służy do kodowania. Modele obrazu, wideo i muzyki otwierają się zamiast tego w Fantasi, aplikacji Omarchy do tworzenia obrazów, wideo i muzyki przy użyciu modelu działającego na tej maszynie, wybranego tam lub z ich wiersza w panelu modeli lokalnych.

Model nadal działa dokładnie tak, jak został skonfigurowany, więc aktualizacja Omarchy nigdy nie uruchamia go ponownie pod Twoimi agentami. Gdy Omarchy ma nowsze środowisko uruchomieniowe lub nowsze wagi dla skonfigurowanego przez Ciebie modelu, jego wiersz pokazuje przycisk aktualizacji: naciśnij go, a model zostanie ponownie skonfigurowany w tle, pobierając tylko to, co się zmieniło, i uruchomi się ponownie na nowej wersji. Model, który był zatrzymany, pozostaje zatrzymany. `omarchy models update` robi to samo dla każdego modelu z terminala.

Z wiersza poleceń `omarchy models start <recipe>` i `omarchy models stop <recipe>` robią to samo, `omarchy models status` pokazuje każdy model, a `omarchy agent --local-model <recipe>` otwiera ten model w pi, niezależnie od Twojego domyślnego agenta. Aby uczynić Twój model lokalny tym, co otwierają skrót klawiszowy agenta, konsola Quake i _Make something_, uruchom `omarchy default agent local` lub oznacz gwiazdką działający model w panelu agentów. pi wypisuje też każdy skonfigurowany przez Ciebie model oraz te na maszynach, z którymi się sparowałeś, we własnym selektorze modeli, więc zwykłe `pi` też do nich dociera. Każdy klient zgodny z OpenAI również może się połączyć: `status` pokazuje adres każdego modelu (pierwszy to `http://127.0.0.1:11435/v1`), nazwa przepisu jest modelem, a klucz znajduje się w `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` usuwa model i pobrane pliki, których nie używa żaden inny model.

Środowiska uruchomieniowe firm trzecich są oznaczone swoim wydawcą. Omarchy uruchamia każdy model bez dostępu do sieci.

### Lokalne LLM-y

Omarchy poleca dwa sposoby uruchamiania lokalnych modeli LLM: LM Studio i Ollama. LM Studio zapewnia interfejs GUI do znajdowania modeli o otwartych wagach, instalowania ich i uruchamiania. To świetny sposób, aby łatwo zacząć. Ollama oferuje CLI do robienia tego w podobny sposób. Ale jeśli dopiero zaczynasz z modelami lokalnymi, zacząłbym od LM Studio. Możesz zainstalować każde z nich w _Install > AI_ w Menu Omarchy.

### Umiejętności Omarchy

Umiejętności agentów pomagają AI używać konkretnych narzędzi w konkretny sposób, a Omarchy dostarcza siedem z nich. Umiejętność omarchy obejmuje dostosowywanie systemu, np. poprawianie Twojej konfiguracji Hyprland lub dostosowywanie paska. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app i omarchy-make-game obejmują tworzenie czegoś nowego, omarchy-contribute obejmuje zgłaszanie błędu lub wysyłanie poprawki upstream, a omarchy-diagnose-crash przechodzi przez zrzut core awarii. Są one dowiązane symbolicznie do katalogów umiejętności dla Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` oraz każdego `~/.hermes/profiles/*/skills`) i ogólnej lokalizacji `~/.agents/skills`, więc większość harnessów wykrywa je automatycznie. Własny folder umiejętności o tej samej nazwie ma pierwszeństwo.

Ale powinieneś traktować te umiejętności jako eksperymentalne. Różne modele będą ich używać z różnym skutkiem. Najlepiej najpierw działać w trybie planowania, aby mieć pojęcie, co agent chciałby zmienić. A potem bądź gotowy wycofać zmiany lub nawet wywołać `omarchy reinstall configs`, jeśli agent narobi bałaganu we wszystkim.
