# AI

Omarchy zawiera launchery dla poniższych agentów kodujących, nie wybierając za Ciebie domyślnego. Uruchom polecenie, aby przy pierwszym użyciu zainstalować jego CLI, a następnie uwierzytelnij się, gdy pojawi się monit. Hermes i OpenClaw są wyjątkami: nic nie jest dla nich instalowane przez mise, a wybranie któregokolwiek z nich konfiguruje własną, samouaktualniającą się kopię, jak wyjaśniono poniżej w części _Desktop apps_.

### Instalowanie i aktualizowanie agentów

Z wyjątkiem Hermes i OpenClaw, agenci ci korzystają z leniwej instalacji mise: pierwsze uruchomienie instaluje CLI, a kolejne uruchomienia używają go ponownie. mise sprawdza też, czy dla zainstalowanego agenta jest nowa wersja, najwyżej raz na cztery godziny, tuż przed jego uruchomieniem lub w tle przy promptcie powłoki. Jeśli ta aktualizacja się nie powiedzie lub jesteś offline, uruchomi się zainstalowana wersja. `omarchy update` aktualizuje zainstalowanych agentów wraz z resztą Omarchy, a `mup` aktualizuje tylko narzędzia zarządzane przez mise.

Własny aktualizator agenta, taki jak `claude update`, `codex update` lub przycisk aktualizacji w aplikacji, nie aktualizuje instalacji zarządzanej przez mise. `codex update` kończy się niepowodzeniem, a `claude update` może zgłosić sukces, instalując przy tym osobną kopię, której mise nie śledzi. Jeśli wolisz używać natywnego instalatora i aktualizatora agenta, dodaj go do `disable_tools`; zobacz [Preinstalowane narzędzia CLI](18-development-tools.md#preinstalled-cli-tools).

Aby zainstalować wszystkie skonfigurowane narzędzia lazy, zanim będą Ci potrzebne, uruchom `mise install --include-lazy`. Obejmuje to także pozostałe domyślne narzędzia CLI Omarchy, oprócz agentów. Zobacz [Preinstalowane narzędzia CLI](18-development-tools.md#preinstalled-cli-tools), aby dowiedzieć się, jak zainstalować pojedyncze narzędzie lub użyć własnej instalacji.

`grok` jest instalowany przez oficjalny pakiet `grok` mise, w ten sam sposób co `claude` i `codex`. Uruchom `grok` lub wybierz go w _Agent > Harness_. Pomiń instalator `curl | bash` na x.ai. Ta ścieżka umieszcza drugą kopię w `~/.grok/bin`, dodaje ją na początku `PATH` i nadpisuje wrapper Omarchy.

`dsh` otwiera swój interfejs w przeglądarce pod `127.0.0.1:3080`, z katalogiem uruchomienia jako domyślnym obszarem roboczym. Jego interfejs w przeglądarce nie przyjmuje promptu startowego, więc `omarchy agent prompt` otwiera go z promptem w schowku, gotowym do wklejenia. Omarchy uruchamia go z presetem uprawnień DeepSeek bez zatwierdzania. DeepSeek Harness przesyła logi sesji do DeepSeek, gdy używasz jego oficjalnego API modeli; wyłącz to w _Settings > General > Upload Session Log_ w jego interfejsie przeglądarkowym. Opinie, które mu wysyłasz, są również przesyłane wraz z sesją, chyba że uruchomisz go z `DSH_TELEMETRY_MODE=DISABLED`.

### Domyślny agent

Wybierz domyślnego agenta poleceniem `omarchy default agent <name>` lub w _Agent > Harness_ w Omarchy Menu (`Super + Space`). Jeśli agent nie jest jeszcze zainstalowany, wybranie go najpierw go zainstaluje, a także otrzyma własny launcher w launcherze aplikacji, obok Agent. Świeże Omarchy zaprosi Cię do dokonania tego wyboru jednorazowym powiadomieniem.

Wybranie Claude próbuje również skonfigurować jego rozszerzenie przeglądarkowe dla Chromium, Chrome, Brave, Brave Origin i Edge. Konfiguracja rozszerzenia dotyczy wszystkich użytkowników i może poprosić o hasło systemowe; anulowanie lub nieudana instalacja rozszerzenia nadal wybiera i uruchamia Claude. Uruchom ponownie przeglądarkę, włącz rozszerzenie, jeśli pojawi się monit, i zaloguj się do Claude, aby dokończyć łączenie. Uruchom `/chrome` w Claude, aby sprawdzić połączenie. Firefox i Zen nie obsługują tego rozszerzenia. Jeśli Claude był już Twoim domyślnym agentem, zanim dodano tę konfigurację, wybierz go ponownie, aby zainstalować rozszerzenie.

Po dokonaniu wyboru `Super + Shift + Ctrl + A` uruchamia domyślnego agenta w dedykowanym oknie terminala (lub wywołuje selektor, jeśli jeszcze nie wybrałeś). Możesz też uruchomić go od razu do zadania poleceniem `omarchy agent prompt "Review this project"`. Freebuff i DeepSeek Harness nie przyjmują promptu startowego, więc otwierają się z promptem w schowku do wklejenia. Agenci uruchamiani w ten sposób działają bez nadzoru w swoich trybach „nie zatrzymuj się, żeby pytać”, więc bądź gotowy na to, że naprawdę będą coś robić! MiniMax Code nie ma takiego trybu dla swoich sesji interaktywnych, więc pyta o uprawnienia jak zwykle. A ponieważ agenci odmawiają zapamiętania zaufania dla Twojego katalogu domowego, uruchomienia z `$HOME` startują zamiast tego w `~/Work`.

Są też skróty terminalowe: `a` uruchamia domyślnego agenta inline w bieżącym terminalu, natomiast `c`, `cx` i `cy` uruchamiają bezpośrednio OpenCode, Claude Code i Codex (ponownie w ich trybach automatycznego zatwierdzania). Zmiany motywu synchronizują się też z agentami: Claude Code, Pi, OpenCode i Hermes (gdy Omarchy go zainstaluje) podążają za Tobą, gdy przełączysz motyw Omarchy.

### Twoje instrukcje dla agentów

Osobiste reguły dla każdego agenta znajdują się w `~/.agents/AGENTS.md`, obok współdzielonych skilli w `~/.agents/skills`. Otwórz go w _Agent > Instructions_, które łączy go też z każdym harnessem, który przechowuje własny plik globalny: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` Copilot i tak dalej. Crush i Amp czytają link `~/.config/AGENTS.md`, natomiast omp, Kimi i DeepSeek Harness czytają `~/.agents/AGENTS.md` bezpośrednio. Wybranie domyślnego agenta też tworzy dla niego link. Plik instrukcji, który już miałeś, staje się współdzielonym, jeśli jeszcze go nie było; w przeciwnym razie jest zachowywany obok linku jako `.bak`. Uruchom `omarchy agent instructions`, aby ponownie utworzyć linki po zainstalowaniu kolejnego agenta.

### Panel agentów

Na górnym pasku znajduje się ikona agentów. Zanim skonfigurujesz agenta, jej panel przeprowadzi Cię przez logowanie do Claude, Codex lub Grok, a pierwszy z nich stanie się Twoim domyślnym agentem. Potem panel umieszcza każdą subskrypcję na jednej stronie: każdy agent i konto wraz ze swoim planem, wskaźnik dla każdego z limitów: 5-godzinnej sesji i tygodniowego, wraz z czasem do resetu (najedź, aby zobaczyć dokładny procent), lub pozostałe przedpłacone saldo, pod linią, która rotuje przez to, czego użyłeś we wszystkich z nich, np. tokeny w tym tygodniu i Twój najczęściej używany model. W sekcji _Make something cool_ oferuje prompty startowe dla nowego motywu, pluginu, aplikacji lub gry, które przekazują zadanie Twojemu domyślnemu agentowi. Aplikacje są budowane tak, jak własne aplikacje Omarchy: Hype, Monologue i Omacut, w C++ i Qt Quick, zgodnie ze skillem agenta omarchy-make-app, a potrzebne im kompilator i elementy Qt są zainstalowane. Gry to pojedyncza strona three.js w `~/Games/vibes`, zgodnie ze skillem agenta omarchy-make-game, a wszystkie otwierają się z jednego launchera Game Vibes w bieżącym motywie; ładują three.js z sieci, więc do uruchomienia potrzebują połączenia. Claude Code, Codex, Grok, Kimi, Cursor wraz z jego limitem Grok Bot, GitHub Copilot, Muse, Antigravity i Devin są obsługiwane od razu wraz ze swoimi limitami, Kimchi wraz ze swoim planem, przedpłaconymi kredytami i budżetami wydatków, a Hermes, Mistral Vibe i Qwen Code pokazują swoje sesje i tokeny, gdy już ich użyjesz. Plany dostawców i klucze, których używasz przez pi, omp lub opencode, również się pojawiają: OpenCode Zen i Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan i Synthetic wraz ze swoimi limitami; OpenRouter i DeepSeek ze swoimi przedpłaconymi saldami; Fireworks ze swoimi wydatkami z ostatnich 30 dni. Tokeny z modeli, które uruchamiasz na własnym sprzęcie, również wliczają się do sum; same modele mają własny panel, opisany w sekcji [Modele lokalne](#local-models). Każdy agent jest liczony raz, u tego, kto go rozlicza, niezależnie od tego, przez ile harnessów go prowadzisz.

Kliknij lewym przyciskiem ikonę paska lub naciśnij `Super + Ctrl + X`, aby otworzyć panel, kliknij prawym, aby uruchomić domyślnego agenta, a środkowym, aby odświeżyć. Rekordy użycia za nim stojące są regenerowane co 15 minut przez `omarchy agent usage update`, a panel może nawet łączyć użycie z innych Twoich maszyn przez zsynchronizowany folder. Zobacz README w `$OMARCHY_PATH/shell/plugins/agents/`, aby poznać pełne ustawienia.

### Kilka subskrypcji

Jeśli płacisz za więcej niż jeden plan Claude, Codex lub Grok — na przykład osobisty Max i służbowy — Omarchy może utrzymywać je wszystkie zalogowane i przełączać się między nimi. Dodaj subskrypcję przyciskiem + w panelu agentów, który od razu przeprowadzi Cię przez proces, lub poleceniem `omarchy agent account add claude Work` (lub `codex`, lub `grok`). Zainstaluje CLI, jeśli go brakuje. Pierwsze konto dla dostawcy loguje się przez Twoją normalną przeglądarkę, dokładnie tam, gdzie CLI zawsze szuka. Każde kolejne loguje się przez okno prywatne, aby konto, do którego Twoja przeglądarka jest już zalogowana, nie zostało wybrane przez pomyłkę; zaloguj się tam jako konto, które dodajesz, i najpierw zamknij każde okno prywatne, które już miałeś otwarte. Nigdy w tym celu nie wylogowuj się z CLI: wylogowanie unieważnia zapisane logowanie, a to konto trzeba by dodać ponownie.

Aby skopiować logowania subskrypcji na inną maszynę Omarchy przez SSH, uruchom `omarchy agent account copy user@laptop`. Nadawca dostarcza tymczasowy odbiornik, gdy maszyna docelowa nie ma zainstalowanego, więc starsze maszyny Omarchy mogą odbierać konta bez aktualizacji. Zainstalowane odbiorniki mają pierwszeństwo. Kopiuje to wszystkie subskrypcje Claude, Codex i Grok; dodaj nazwy dostawców, aby je wybrać, jak w `omarchy agent account copy laptop claude`. Nazwy kont i ID poleceń odpowiadają źródłu, w tym konta już obecne na maszynie docelowej. Niepowiązane konta docelowe otrzymują sufiks numeryczny, jeśli ich nazwy kolidują, a ustawienia, skille, pluginy i historia konwersacji pozostają lokalne dla każdej maszyny.

Istniejące dane uwierzytelniające na maszynie docelowej są zachowywane. Konto źródłowe już tam zalogowane ma zsynchronizowaną nazwę bez zastępowania jego danych uwierzytelniających; pozostałe konta są dodawane obok niego. Aby zastąpić zapisane dane uwierzytelniające dla pasujących kont, użyj `omarchy agent account copy --replace laptop claude` po zakończeniu sesji tego konta na maszynie docelowej. Świeża maszyna docelowa otrzymuje też aktywne konto źródłowe i preferencje przełączania; maszyna docelowa z istniejącą konfiguracją zachowuje własne.

Dane uwierzytelniające podróżują przez SSH i są przechowywane w prywatnych plikach na maszynie docelowej, więc kopiuj tylko na maszyny, którym ufasz. To jednorazowa kopia, nie ciągła synchronizacja. Tokeny odświeżania Codex mogą być rotowane przez inną maszynę, pozostawiając skopiowane logowanie wymagające odnowienia; osobne logowania pozostają najbardziej niezawodnym wyborem do jednoczesnego użycia na kilku maszynach. Zobacz [przewodnik Codex dotyczący uwierzytelniania kont](https://developers.openai.com/codex/auth/ci-cd-auth).

Jedno konto na dostawcę jest aktywne, a każda nowa sesja zaczyna jako ono: `cx`, `cy`, zwykłe `claude`, `codex` lub `grok`, wszystko uruchamiane przez `omarchy agent` oraz skrypty lub edytory, które znajdują CLI w `PATH`. Przełączaj poleceniem `omarchy agent account use work` (i z powrotem poleceniem `omarchy agent account use main`) lub w panelu, naciskając numer konta, a potem `Enter` (lub klikając jego przycisk Use). Działające sesje Claude też się przełączają, od następnej wiadomości: każda sesja Claude działa w `~/.claude`, które zawsze przechowuje logowanie aktywnego konta. Sesja Claude uruchomiona we własnym folderze konta przez starsze Omarchy zachowuje to logowanie do momentu zakończenia, więc przełączenie nazywa te sesje i kończy się samo, gdy znikną. Działające sesje Codex i Grok pozostają na koncie, z którym wystartowały. Historia konwersacji, ustawienia, skille i pluginy są współdzielone między kontami, więc `claude --continue` w tym samym folderze podejmuje pracę tam, gdzie ją zostawiłeś na nowym koncie.

Przy więcej niż jednym koncie panel pokazuje limity każdego konta obok siebie, z aktywnym oznaczonym. Domyślnie Omarchy powiadamia Cię, gdy aktywne konto przekroczy 95% limitu, a kliknięcie powiadomienia przełącza na konto z największym zapasem. Najedź na linię konta w panelu i kliknij Autoswitch, które pojawia się obok Use (lub naciśnij `m`), albo uruchom `omarchy agent account mode auto`, aby przełączało się samo; gdy jest włączone, Autoswitch zajmuje miejsce Use, a ponowne kliknięcie wraca do powiadamiania. Dodaj liczbę, aby zmienić próg, jak w `omarchy agent account mode auto 90`. Jeśli każde konto jest powyżej progu, usłyszysz o tym raz, wraz z informacją, które konto zwolni się jako pierwsze. Gdy aktywne konto jest w odległości 15 punktów od swojego progu (80% przy ustawieniu domyślnym), jego limity są sprawdzane co trzy minuty zamiast co 15.

`omarchy agent account list` pokazuje każde konto i jego najnowsze limity, `omarchy agent account remove work` zapomina jedno, a `omarchy agent account rename primary Hey` zmienia nazwę jednego (lub kliknij nazwę konta w panelu). Te polecenia działają na kontach Twojego domyślnego agenta; aby dotrzeć do innego dostawcy, najpierw go nazwij, jak w `omarchy agent account use codex side`. Logowanie, które już miałeś w `~/.claude` lub `~/.codex`, to konto _Main_. Konto Codex pozostaje tam, gdzie jest; konto Claude czeka we własnym folderze, gdy inne konto jest aktywne. Konto nieużywane przez ponad około osiem godzin może pokazywać _Sign-in required_; kliknij je, aby zalogować to konto ponownie bezpośrednio w panelu, lub przełącz się na nie i rozpocznij sesję, co samo odświeży logowanie. Serwery MCP, które dodajesz poleceniem `claude mcp add`, docierają do każdego konta Claude, ponieważ wszystkie działają w `~/.claude`; w przypadku Codex i Grok serwery, które miałeś, gdy konto było dodawane, przechodzą do niego, ale późniejsze docierają tylko do konta, w którym je dodałeś. Claude Desktop zachowuje własne logowanie, a narzędzia Codex lub Grok skonfigurowane bezwzględną ścieżką do pliku binarnego CLI nie podążają za przełączeniem. Jawne `CLAUDE_CONFIG_DIR`, `CODEX_HOME` lub `GROK_HOME` ma pierwszeństwo przed wybranym kontem.

### Diagnostyka awarii

Omarchy obserwuje systemd-coredump pod kątem awarii procesów. Gdy wybierzesz domyślnego agenta, każdy Twój program, który zrzuci core, wywoła powiadomienie "Process crashed" — kliknij je, a awaria zostanie przekazana Twojemu domyślnemu agentowi wraz ze skillem omarchy-diagnose-crash Omarchy, który prowadzi agenta przez ustalenie faktów ze zrzutu core i decyzję, czy awarię warto zgłosić upstream. Możesz też uruchomić go ręcznie dla dowolnego PID z `coredumpctl list` poleceniem `omarchy agent crash <pid>`.

Obserwowanie jest domyślnie włączone. Wyłącz je w _Trigger > Toggle > Crash Capture Off_ (lub poleceniem `omarchy toggle crash-capture`), a powiadomienia ustaną; `omarchy agent crash <pid>` nadal działa ręcznie.

Awarie można też wyciszać po jednym programie, co diagnoza oferuje Ci na końcu. `omarchy crash mute hyprland` zatrzymuje powiadomienia tylko dla tego programu, `omarchy crash mute hyprland off` przywraca je, a samo `omarchy crash mute` listuje to, co wyciszyłeś. Przyjmuje ścieżkę pliku binarnego równie chętnie jak jego nazwę, więc `omarchy crash mute /usr/bin/hyprland` robi to samo. Ujmij nazwę ze spacją w cudzysłów, jak w `omarchy crash mute 'Some App'`. Wszystko inne nadal powiadamia, a wyciszony program nadal się wywala — to ukrywa przypomnienie, niczego nie naprawia.

### Aplikacje desktopowe

Menu _Install > AI_ zawiera też kilka graficznych aplikacji AI: Amp Desktop, Antigravity Desktop, aplikację desktopową ChatGPT, aplikację desktopową Claude (linuxową betę Anthropic, z zakładkami Chat, Cowork i Claude Code), Grok Bot do czatowania z modelami xAI, Herdr Desktop, Hermes Desktop, OpenClaw, aplikację desktopową Perplexity oraz T3 Code. Grok Bot to desktopowa aplikacja czatowa. Agentem kodującym jest polecenie `grok`.

Hermes Desktop to ta, o której warto wiedzieć, ponieważ maszyna ma jednego Hermesa i należy on do aplikacji: Hermes jest instalowany wyłącznie przez aplikację, a polecenie `hermes`, które uruchamia domyślny agent, należy do aplikacji. Wybór Hermesa jako domyślnego agenta instaluje to samo, co pozycja _Install > AI_: pakiet oraz środowisko uruchomieniowe Hermes w `~/.hermes` skonfigurowane przez własny instalator Hermesa, co za pierwszym razem zajmuje kilka minut. To środowisko to ten jeden Hermes, którego używają polecenie terminalowe `hermes`, domyślny agent i aplikacja, i aktualizuje się samo poleceniem `hermes update`, zamiast czekać na wydanie Omarchy. Zainstalowanie go daje też Hermesowi motyw Omarchy jako skórkę o nazwie `omarchy`, za którą podąża każda powierzchnia Hermesa, gdy przełączasz motywy; wybierz inną w ustawieniach Appearance Hermesa lub poleceniem `/skin`, jeśli wolisz, żeby tak nie było, a Omarchy pozostawi ten wybór w spokoju. Usunięcie aplikacji w _Remove > AI_ najpierw zamyka Hermesa, w tym bramkę, zabiera ze sobą to środowisko i zachowuje Twoje czaty, wspomnienia oraz skille, które Hermes napisał dla siebie, chyba że każesz inaczej: pyta, domyślnie odpowiadając nie, czy te dane i Twoje ustawienia połączeń też mają zniknąć.

Doświadczeniem desktopowym OpenClaw jest jego Control UI, które otwiera się jako aplikacja webowa wspierana przez własną lokalną bramkę. OpenClaw mieszka w `~/.openclaw` i aktualizuje się sam: użyj przycisku "Update Gateway" w Control UI lub uruchom `openclaw update`, a bramka uruchomi się ponownie na nowej wersji. Omarchy wybiera jedynie wydanie, od którego zaczyna świeża instalacja. OpenClaw może też być Twoim domyślnym agentem: wybranie go w _Agent > Harness_ konfiguruje tę samą kopię w `~/.openclaw`, a agent otwiera interfejs terminalowy OpenClaw podłączony do jego bramki. Usunięcie OpenClaw w _Remove > AI_ zabiera ze sobą usługę bramki i aplikację, a potem pyta, czy `~/.openclaw` też ma zniknąć, ponieważ przechowuje Twoje czaty i dane uwierzytelniające obok samego OpenClaw i środowisk pluginów, które pobiera; domyślnie je zachowuje, a ponowne zainstalowanie OpenClaw podejmie je z powrotem.

Herdr Desktop to aplikacja desktopowa [Herdr](https://herdr.dev): przestrzenie, karty i panele terminali oraz agentów kodujących, które nadal działają w jej rdzeniu, gdy zamkniesz okno. Pochodzi z własnego instalatora Herdr, a nie z pakietu, więc mieszka w `~/.local/share/herdr-app`, przynosi ze sobą swój rdzeń w `~/.local/bin/herdr-core`, gdy jeszcze go nie masz, i aktualizuje oba sama. Stoi obok polecenia `herdr`, które Omarchy dostarcza na `Super + Ctrl + Return`, zamiast je zastępować, i otrzymuje bezpośrednie klawisze tego polecenia: `Alt + Return` i `Alt + Shift + Return` dzielą panel w dół lub w prawo, `Alt + Escape` zamyka go, `Ctrl + Alt + Arrow` porusza się między panelami, `Alt + 1..9` i `Alt + Left/Right` wybierają kartę, a `Alt + Up/Down` poruszają się między przestrzeniami. `Ctrl + 1..9` wybiera przestrzeń, a `Alt + Shift + Up/Down` przechodzi przez agentów. Klawisze prefiksu `Ctrl + Space` pozostają tylko terminalowe, ponieważ aplikacja nie może przytrzymać zwykłego klawisza Ctrl dla sekwencji. Omarchy zapisuje je do `~/.config/herdr-app/keys.json`, a `omarchy-refresh-herdr-app` przywraca je. Zainstalowanie go wybiera motyw Omarchy dla Herdr, który od tej pory podąża za Twoim motywem Omarchy. Herdr trzyma jeden motyw dla trybu jasnego i jeden dla ciemnego, więc po przełączeniu między ciemnym a jasnym motywem Omarchy wybierz Omarchy w selektorze motywów Herdr jeszcze raz dla drugiego trybu.

T3 Code działa z oficjalnego wydania AppImage w `~/.local/share/t3code`, a nie z pakietu, więc aktualizuje się sam. Zainstalowanie go pyta, czy zacząć na kanale Stable czy Nightly; przełącz później w ustawieniach T3 Code. Twoje wątki i ustawienia mieszkają w `~/.t3`, a usunięcie T3 Code w _Remove > AI_ zabiera je ze sobą.

### Modele lokalne

Uruchom otwarty model na własnej maszynie dla swoich agentów kodujących. Twoje prompty i kod pozostają na maszynie; nic wysłanego do modelu jej nie opuszcza. Zacznij od:

```bash
omarchy models use best text
```

To konfiguruje najlepszy model tekstowy dla tej maszyny, ten rodzaj, którego używają Twoi agenci. Modele obrazów, wideo i muzyki mają swój własny najlepszy: `omarchy models use best image`, `video` lub `music`. Uruchom `omarchy models use best`, aby zobaczyć wybór każdego rodzaju dla tej maszyny.

Albo otwórz panel modeli lokalnych z jego ikony iskierek na górnym pasku, obok ikony agentów, lub za pomocą Super + Ctrl + Alt + X, i wybierz +. Ikona pojawia się, gdy model pasuje do tej maszyny. Podman, który uruchamia modele, jest dostarczany z Omarchy, podobnie jak zestaw narzędzi kontenerowych NVIDIA na maszynie NVIDIA, który daje im GPU; jeśli któregoś z nich brakuje, pierwsza konfiguracja go instaluje. Omarchy następnie wybiera zalecany model dla tej maszyny, pobiera go i uruchamia. Spodziewaj się pobrania dziesiątek GB i większości pamięci maszyny zajętej podczas działania modelu: Flash Next używa około 100 GiB przy pełnym kontekście 256K. Jeśli inne modele zajmują pamięć, której potrzebuje, jest konfigurowany jako zatrzymany, gotowy do uruchomienia, gdy zatrzymasz jeden z nich. Model zatrzymuje się przy wylogowaniu; zatrzymaj go sam, gdy potrzebujesz pamięci do czegoś innego.

`omarchy models list` pokazuje opcje i wyjaśnia, dlaczego niektóre nie pasują. Aby skonfigurować inny, uruchom `omarchy models use <recipe>`. Dziś dla maszyn Strix Halo 128 GB dostępne są `qwen3.8-flash-next-gufo` i `qwen3.8-27b-gufo`; 27B zajmuje około 40 GiB, więc zostawia miejsce na inną pracę. Na laptopie 64 GB z Intel Arc B390 `qwen3.6-35b-a3b-llamacpp` działa w około 30 GiB. Nowe receptury i zalecenia przychodzą z `omarchy update`, przez pakiet.

Każdy skonfigurowany model otrzymuje własną linię w panelu modeli lokalnych: play, aby go uruchomić, pause, aby go zatrzymać i zwolnić jego pamięć, oraz przycisk terminala, aby otworzyć na nim swojego agenta. Na górze pasek pokazuje, jak pamięć maszyny jest podzielona między samo Omarchy (system i Twoje aplikacje), każdy działający model i to, co wolne. Wskaż zatrzymany model, a pasek pokaże, czy pasuje, lub ile mu brakuje. Kilka może działać naraz, gdy mieszczą się razem w pamięci; jeśli jeden nie pasuje, Omarchy mówi, który działający model zatrzymać. Przeciągaj linie za ich logo, aby zmienić ich kolejność, i naciśnij Delete na wybranej linii, aby usunąć model i jego pobrane pliki.

Każdy skonfigurowany model kodujący otrzymuje też własny wpis w launcherze aplikacji, pod nazwą modelu i z logo jego twórcy, w sposób, w jaki zalogowanie się do Claude, Codex lub Grok dodaje taki wpis. Otwiera Twojego agenta na tym modelu i najpierw uruchamia model, jeśli nie działa: terminal pokazuje jego ładowanie i przekazuje kontrolę agentowi, gdy będzie gotowy. Usunięcie modelu usuwa jego wpis.

Nie każdy model jest do kodowania. Modele obrazów, wideo i muzyki otwierają się zamiast tego w Fantasi, aplikacji Omarchy do tworzenia obrazów, wideo i muzyki modelem działającym na tej maszynie, wybranym tam lub z ich linii w panelu modeli lokalnych.

Model nadal działa dokładnie tak, jak został skonfigurowany, więc aktualizacja Omarchy nigdy nie restartuje go pod Twoimi agentami. Gdy Omarchy ma nowsze środowisko uruchomieniowe lub nowsze wagi dla modelu, który skonfigurowałeś, jego linia pokazuje przycisk aktualizacji: naciśnij go, a model zostanie ponownie skonfigurowany w tle, pobierając tylko to, co się zmieniło, i uruchomi się ponownie na nowej wersji. Model, który był zatrzymany, pozostaje zatrzymany. `omarchy models update` robi to samo dla każdego modelu z terminala.

Z linii poleceń `omarchy models start <recipe>` i `omarchy models stop <recipe>` robią to samo, `omarchy models status` pokazuje każdy model, a `omarchy agent --local` otwiera ostatni model, który uruchomiłeś, w pi, niezależnie od tego, jaki jest Twój domyślny agent. OpenCode i Qwen Code też mogą używać modelu lokalnego: `omarchy models harness opencode` lub `omarchy models harness qwen` otwiera je tam zamiast tego, a `omarchy models harness pi` wraca. pi listuje też każdy model, który skonfigurowałeś, oraz te na maszynach, z którymi jesteś sparowany, we własnym selektorze modeli, więc zwykłe `pi` też do nich dociera. Każdy klient kompatybilny z OpenAI też może się połączyć: `status` pokazuje adres każdego modelu (pierwszy to `http://127.0.0.1:11435/v1`), nazwą modelu jest nazwa receptury, a klucz znajduje się w `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` usuwa model i pobrane pliki, których żaden inny model nie używa.

Środowiska uruchomieniowe firm trzecich są oznaczone swoim wydawcą. Omarchy uruchamia każdy model bez dostępu do sieci.

### Lokalne modele LLM

Omarchy poleca dwa sposoby uruchamiania lokalnych modeli LLM: LM Studio i Ollama. LM Studio zapewnia interfejs GUI do znajdowania modeli o otwartych wagach, instalowania ich i uruchamiania. To świetny sposób, aby łatwo zacząć. Ollama oferuje CLI do robienia tego podobnie. Ale jeśli jesteś nowy w modelach lokalnych, zacząłbym od LM Studio. Możesz zainstalować każde z nich w _Install > AI_ w Omarchy Menu.

### Skille Omarchy

Skille agentów pomagają AI używać konkretnych narzędzi w konkretny sposób, a Omarchy dostarcza siedem z nich. Skill omarchy obejmuje dostosowywanie systemu, np. poprawianie konfiguracji Hyprland lub dostosowywanie paska. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app i omarchy-make-game obejmują tworzenie czegoś nowego, omarchy-contribute obejmuje zgłaszanie błędu lub wysyłanie poprawki upstream, a omarchy-diagnose-crash pracuje nad zrzutem core awarii. Są one dowiązane symbolicznie do katalogów skilli dla Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` i każdy `~/.hermes/profiles/*/skills`) oraz ogólnej lokalizacji `~/.agents/skills`, więc większość harnessów odbiera je automatycznie. Własny folder skilla o tej samej nazwie ma pierwszeństwo.

Ale powinieneś traktować te skille jako eksperymentalne. Różne modele będą ich używać z różnym skutkiem. Najlepiej najpierw działać w trybie planu, abyś miał pojęcie, co agent chciałby zmienić. A potem bądź gotowy wycofać zmiany lub nawet wywołać `omarchy reinstall configs`, jeśli agent zrobi ze wszystkiego bałagan.
