# AI

Omarchy zawiera launchery dla poniższych agentów do kodowania, bez wybierania za Ciebie domyślnego. Uruchom polecenie, aby zainstalować jego CLI przy pierwszym użyciu, a następnie uwierzytelnij się, gdy pojawi się monit. Hermes jest wyjątkiem: przy pierwszym użyciu nic nie jest dla niego instalowane, a wybranie go instaluje Hermes Desktop, jak wyjaśnia sekcja _Aplikacje desktopowe_ poniżej.

### Instalowanie i aktualizowanie agentów

Z wyjątkiem Hermes, agenci ci korzystają z leniwej instalacji mise: pierwsze uruchomienie instaluje CLI, a późniejsze uruchomienia używają go ponownie. mise sprawdza też zainstalowanego agenta pod kątem nowej wersji co najwyżej raz na cztery godziny, tuż przed jego uruchomieniem lub w tle przy znaku zachęty powłoki. Jeśli ta aktualizacja się nie powiedzie lub jesteś offline, uruchamia się zainstalowana wersja. `omarchy update` aktualizuje zainstalowanych agentów wraz z resztą Omarchy, a `mup` aktualizuje tylko narzędzia zarządzane przez mise.

Własny aktualizator agenta, taki jak `claude update`, `codex update` lub przycisk aktualizacji w aplikacji, nie aktualizuje instalacji zarządzanej przez mise. `codex update` kończy się niepowodzeniem, a `claude update` może zgłosić sukces, instalując przy tym osobną kopię, której mise nie śledzi. Jeśli wolisz używać natywnego instalatora i aktualizatora agenta, dodaj go do `disable_tools`; zobacz [Preinstalowane narzędzia CLI](18-development-tools.md#preinstalled-cli-tools).

Aby zainstalować wszystkie skonfigurowane narzędzia leniwe, zanim będziesz ich potrzebować, uruchom `mise install --include-lazy`. Obejmuje to pozostałe domyślne narzędzia CLI Omarchy, jak również agentów. Zobacz [Preinstalowane narzędzia CLI](18-development-tools.md#preinstalled-cli-tools), aby dowiedzieć się, jak zainstalować pojedyncze narzędzie lub użyć własnej instalacji.

`grok` jest instalowany przez pierwszoosobowy pakiet `grok` mise, w ten sam sposób co `claude` i `codex`. Uruchom `grok` lub wybierz go w _Setup > Defaults > Agent_. Pomiń instalator `curl | bash` na x.ai. Ta ścieżka umieszcza drugą kopię w `~/.grok/bin`, dodaje ją na początku `PATH` i nadpisuje wrapper Omarchy.

`dsh` otwiera swój interfejs przeglądarkowy pod `127.0.0.1:3080`, z katalogiem uruchomienia jako domyślnym obszarem roboczym. Jego interfejs przeglądarkowy nie przyjmuje promptu startowego, więc `omarchy agent prompt` otwiera go z promptem w schowku do wklejenia. Omarchy uruchamia go z presetem uprawnień DeepSeek bez zatwierdzania. DeepSeek Harness przesyła logi sesji do DeepSeek, gdy używasz jego oficjalnego API modelu; wyłącz to w _Settings > General > Upload Session Log_ w jego interfejsie przeglądarkowym. Opinie, które mu wysyłasz, są również przesyłane wraz z sesją, chyba że uruchomisz go z `DSH_TELEMETRY_MODE=DISABLED`.

### Domyślny agent

Wybierz swojego domyślnego agenta za pomocą `omarchy default agent <name>` lub w _Setup > Defaults > Agent_ w Omarchy Menu (`Super + Space`). Jeśli agent nie jest jeszcze zainstalowany, wybranie go najpierw go instaluje. Świeże Omarchy zaprosi Cię do dokonania tego wyboru jednorazowym powiadomieniem.

Wybranie Claude próbuje również skonfigurować jego rozszerzenie przeglądarki dla Chromium, Chrome, Brave, Brave Origin i Edge. Konfiguracja rozszerzenia dotyczy wszystkich użytkowników i może poprosić o hasło systemowe; anulowanie lub nieudana instalacja rozszerzenia nadal wybiera i uruchamia Claude. Uruchom ponownie przeglądarkę, włącz rozszerzenie, jeśli pojawi się monit, i zaloguj się do Claude, aby dokończyć łączenie. Uruchom `/chrome` w Claude, aby sprawdzić połączenie. Firefox i Zen nie obsługują tego rozszerzenia. Jeśli Claude był już Twoim domyślnym agentem, zanim dodano tę konfigurację, wybierz go ponownie, aby zainstalować rozszerzenie.

Po dokonaniu wyboru `Super + Shift + Ctrl + A` uruchamia domyślnego agenta w dedykowanym oknie terminala (lub wywołuje selektor, jeśli jeszcze nie wybrałeś). Możesz też uruchomić go od razu do zadania za pomocą `omarchy agent prompt "Review this project"`. Freebuff i DeepSeek Harness nie przyjmują promptu startowego, więc zamiast tego otwierają się z promptem w schowku do wklejenia. Agenci uruchamiani w ten sposób działają bez nadzoru w swoich odpowiednich trybach nieprzerywania-z-pytaniami, więc bądź gotów na to, że naprawdę będą coś robić! MiniMax Code nie ma takiego trybu dla swoich sesji interaktywnych, więc pyta o uprawnienia jak zwykle. A ponieważ agenci odmawiają zapamiętywania zaufania dla Twojego katalogu domowego, uruchomienia z `$HOME` startują zamiast tego w `~/Work`.

Są też skróty terminalowe: `a` uruchamia domyślnego agenta bezpośrednio w bieżącym terminalu, natomiast `c`, `cx` i `cy` uruchamiają bezpośrednio OpenCode, Claude Code i Codex (ponownie w ich trybach automatycznego zatwierdzania). Zmiany motywu synchronizują się również z agentami: Claude Code, Pi, OpenCode i Hermes (po zainstalowaniu go przez Omarchy) podążają za Tobą, gdy przełączasz motyw Omarchy.

### Panel agentów

Górny pasek ma ikonę agentów. Zanim skonfigurujesz agenta, jego panel przeprowadzi Cię przez logowanie do Claude, Codex lub Grok, a pierwszy z nich stanie się Twoim domyślnym agentem. Potem panel umieszcza każdą subskrypcję na jednej stronie: każdego agenta i konto wraz z jego planem, miernik dla każdego z jego limitów sesji 5-godzinnej i tygodniowego wraz z czasem do resetu (najedź, aby zobaczyć dokładny procent) lub pozostałe saldo przedpłacone, pod linią, która rotuje przez to, czego użyłeś we wszystkich z nich, jak tokeny w tym tygodniu i Twój najczęściej używany model. W sekcji _Make something_ oferuje prompty startowe dla nowego motywu, wtyczki lub aplikacji, które przekazują zadanie Twojemu domyślnemu agentowi. Aplikacje są budowane w taki sam sposób jak własne Hype, Monologue i Omacut Omarchy, w C++ i Qt Quick, zgodnie ze skillem agenta omarchy-app, a kompilator i elementy Qt, których potrzebują, są zainstalowane. Claude Code, Codex, Grok, Kimi, Cursor wraz z jego przydziałem Grok Bot, GitHub Copilot, Muse, Antigravity, Kimchi i Devin są obsługiwane od razu wraz z ich limitami, a Hermes, Mistral Vibe i Qwen Code pokazują swoje sesje i tokeny, gdy już ich użyjesz. Plany dostawców i klucze, których używasz przez pi, omp lub opencode, również się pojawiają: OpenCode Zen i Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan i Synthetic wraz z ich limitami; Fireworks, OpenRouter i DeepSeek wraz z ich saldami przedpłaconymi; oraz modele, które uruchamiasz na własnym sprzęcie, w sekcji Local models. Każdy agent jest liczony raz, u tego, kto go rozlicza, niezależnie od tego, przez ile harnessów go prowadzisz.

Kliknij lewym przyciskiem ikonę na pasku, aby otworzyć panel, prawym przyciskiem, aby uruchomić domyślnego agenta. Rekordy użycia stojące za nim są regenerowane co 15 minut przez `omarchy agent usage-update`, a panel może nawet łączyć użycie z innych Twoich maszyn za pośrednictwem zsynchronizowanego folderu. Zobacz README w `$OMARCHY_PATH/shell/plugins/agents/`, aby poznać pełne ustawienia.

### Kilka subskrypcji

Jeśli płacisz za więcej niż jeden plan Claude, Codex lub Grok — na przykład osobisty Max i służbowy — Omarchy może utrzymywać je wszystkie zalogowane i przełączać się między nimi. Dodaj subskrypcję przyciskiem + w panelu agentów, który przeprowadzi Cię przez to na miejscu, lub za pomocą `omarchy agent account add claude Work` (lub `codex`, lub `grok`). Instaluje CLI, jeśli go brakuje. Pierwsze konto dla dostawcy loguje się przez Twoją normalną przeglądarkę, dokładnie tam, gdzie CLI zawsze patrzy. Każde kolejne loguje się przez okno prywatne, więc konto, do którego Twoja przeglądarka jest już zalogowana, nie zostanie wybrane przez pomyłkę; zaloguj się tam jako konto, które dodajesz, i najpierw zamknij każde okno prywatne, które już masz otwarte. Nigdy nie wylogowuj się z CLI, aby to zrobić: wylogowanie unieważnia zapisane logowanie, a to konto trzeba byłoby dodać ponownie.

Aby skopiować loginy subskrypcji na inną maszynę Omarchy przez SSH, uruchom `omarchy agent account copy user@laptop`. Nadawca dostarcza tymczasowy odbiornik, gdy maszyna docelowa nie ma zainstalowanego żadnego, więc starsze maszyny Omarchy mogą odbierać konta bez aktualizacji. Zainstalowane odbiorniki mają pierwszeństwo. Kopiuje to wszystkie subskrypcje Claude, Codex i Grok; dodaj nazwy dostawców, aby je wybrać, na przykład `omarchy agent account copy laptop claude`. Nazwy kont i identyfikatory poleceń zgadzają się ze źródłem, w tym konta już obecne na maszynie docelowej. Niepowiązane konta docelowe otrzymują sufiks numeryczny, jeśli ich nazwy kolidują, a ustawienia, skille, wtyczki i historia konwersacji pozostają lokalne dla każdej maszyny.

Istniejące dane uwierzytelniające na maszynie docelowej są zachowywane. Konto źródłowe już tam zalogowane ma zsynchronizowaną nazwę bez zastępowania jego danych uwierzytelniających; pozostałe konta są dodawane obok niego. Aby zastąpić zapisane dane uwierzytelniające dla pasujących kont, użyj `omarchy agent account copy --replace laptop claude` po zamknięciu sesji tego konta na maszynie docelowej. Świeża maszyna docelowa otrzymuje również aktywne konto i preferencje przełączania źródła; ugruntowana maszyna docelowa zachowuje własne.

Dane uwierzytelniające podróżują przez SSH i są przechowywane w prywatnych plikach na maszynie docelowej, więc kopiuj tylko na maszyny, którym ufasz. To jednorazowa kopia, a nie bieżąca synchronizacja. Tokeny odświeżania Codex mogą zostać zrotowane przez inną maszynę, pozostawiając skopiowany login w potrzebie odnowienia; osobne logowania pozostają najbardziej niezawodnym wyborem do jednoczesnego używania na kilku maszynach. Zobacz [Przewodnik Codex dotyczący uwierzytelniania kont](https://developers.openai.com/codex/auth/ci-cd-auth).

Jedno konto na dostawcę jest aktywne i każda nowa sesja zaczyna jako ono: `cx`, `cy`, zwykłe `claude`, `codex` lub `grok`, wszystko uruchamiane przez `omarchy agent` oraz skrypty lub edytory, które znajdują CLI w `PATH`. Przełącz za pomocą `omarchy agent account use work` (i z powrotem za pomocą `omarchy agent account use main`) lub w panelu, naciskając numer konta, a następnie `Enter` (lub klikając jego przycisk Use). Sesje, które już działają, pozostają na koncie, na którym się rozpoczęły. Historia konwersacji, ustawienia, skille i wtyczki są współdzielone między kontami, więc `claude --continue` w tym samym folderze podejmuje, gdzie skończyłeś na nowym koncie.

Przy więcej niż jednym koncie panel pokazuje limity każdego konta obok siebie, z zaznaczonym aktywnym. Domyślnie Omarchy powiadamia Cię, gdy aktywne konto przekroczy 95% limitu, a kliknięcie powiadomienia przełącza na konto z największym zapasem. Najedź na linię konta w panelu i kliknij Autoswitch, które pojawia się obok Use (lub naciśnij `m`), albo uruchom `omarchy agent account mode auto`, aby przełączało się samo; gdy jest włączone, Autoswitch zajmuje miejsce Use, a ponowne kliknięcie wraca do powiadamiania. Dodaj liczbę, aby zmienić próg, na przykład `omarchy agent account mode auto 90`. Jeśli każde konto przekracza próg, usłyszysz o tym raz, wraz z informacją, które konto zwolni się jako pierwsze. Gdy aktywne konto znajduje się w granicach 15 punktów swojego progu (80% przy ustawieniu domyślnym), jego limity są sprawdzane co trzy minuty, a nie co 15.

`omarchy agent account list` pokazuje każde konto i jego najnowsze limity, `omarchy agent account remove work` zapomina jedno, a `omarchy agent account rename primary Hey` zmienia nazwę jednego (lub kliknij nazwę konta w panelu). Te polecenia działają na kontach Twojego domyślnego agenta; aby sięgnąć innego dostawcy, najpierw go nazwij, na przykład `omarchy agent account use codex side`. Login, który już miałeś w `~/.claude` lub `~/.codex`, to konto _Main_ i zostaje tam, gdzie jest. Konto nieużywane przez ponad około osiem godzin może pokazywać _Sign-in required_; kliknij je, aby zalogować to konto ponownie bezpośrednio w panelu, lub rozpocznij w nim sesję, która odświeża logowanie sama. Serwery MCP, które miałeś, gdy konto było dodawane, przechodzą do niego, ale te, które dodasz później za pomocą `claude mcp add`, trafiają tylko do konta, w którym je dodałeś. Claude Desktop i narzędzia skonfigurowane bezwzględną ścieżką do binarki CLI nie podążają za przełączeniem. Jawne `CLAUDE_CONFIG_DIR`, `CODEX_HOME` lub `GROK_HOME` ma pierwszeństwo przed wybranym kontem.

### Diagnozowanie awarii

Omarchy obserwuje systemd-coredump pod kątem awarii procesów. Gdy coś wywoła segfault, otrzymasz powiadomienie "Process crashed" — kliknij je, a awaria zostanie przekazana Twojemu domyślnemu agentowi wraz ze skillem diagnose-crash Omarchy, który prowadzi agenta przez ustalenie faktów ze zrzutu pamięci i podjęcie decyzji, czy awarię warto zgłosić upstream. Możesz też uruchomić to ręcznie dla dowolnego PID z `coredumpctl list` za pomocą `omarchy agent crash <pid>`.

Obserwowanie jest domyślnie włączone. Wyłącz je w _Trigger > Toggle > Crash Capture_ (lub za pomocą `omarchy toggle crash-capture`), a powiadomienia ustaną; `omarchy agent crash <pid>` nadal działa ręcznie.

Awarie można też wyciszać po jednym programie naraz, co diagnoza oferuje Ci na końcu. `omarchy crash mute hyprland` zatrzymuje powiadomienia tylko dla tego programu, `omarchy crash mute hyprland off` je przywraca, a samo `omarchy crash mute` wyświetla, co wyciszyłeś. Przyjmuje ścieżkę binarki równie chętnie jak jej nazwę, więc `omarchy crash mute /usr/bin/hyprland` robi to samo. Ujmij nazwę ze spacją w cudzysłów, na przykład `omarchy crash mute 'Some App'`. Wszystko inne nadal powiadamia, a wyciszony program nadal się wywraca — to ukrywa przypomnienie, niczego nie naprawia.

### Aplikacje desktopowe

Menu _Install > AI_ zawiera również kilka graficznych aplikacji AI: aplikację desktopową ChatGPT, aplikację desktopową Claude (beta Anthropic dla Linuksa, z zakładkami Chat, Cowork i Claude Code), Grok Bot do czatowania z modelami xAI, Hermes Desktop, OpenClaw, aplikację desktopową Perplexity i T3 Code. Grok Bot to desktopowa aplikacja czatu. Agentem do kodowania jest polecenie `grok`.

Hermes Desktop to ta, o której trzeba wiedzieć, bo maszyna ma jednego Hermes i należy on do aplikacji: Hermes jest instalowany wyłącznie przez aplikację, a polecenie `hermes`, które uruchamia domyślny agent, należy do aplikacji. Wybranie Hermes jako domyślnego agenta instaluje to samo, co wpis _Install > AI_: pakiet oraz środowisko uruchomieniowe Hermes w `~/.hermes` skonfigurowane przez własny instalator Hermes, co za pierwszym razem zajmuje kilka minut. To środowisko uruchomieniowe jest tym jedynym Hermes, z którego korzystają terminalowe polecenie `hermes`, domyślny agent i aplikacja, i aktualizuje się samo za pomocą `hermes update`, zamiast czekać na wydanie Omarchy. Instalacja przekazuje też Hermes motyw Omarchy jako skórkę o nazwie `omarchy`, za którą podąża każda powierzchnia Hermes, gdy przełączasz motywy; wybierz inną w ustawieniach Appearance Hermes lub za pomocą `/skin`, jeśli wolisz, aby tak nie było, a Omarchy zostawi ten wybór w spokoju. Usunięcie aplikacji w _Remove > AI_ najpierw zamyka Hermes, w tym gateway, zabiera ze sobą to środowisko uruchomieniowe i zachowuje Twoje czaty, wspomnienia oraz skille, które Hermes napisał dla siebie, chyba że powiesz inaczej: pyta, domyślnie odpowiadając nie, czy te dane i Twoje ustawienia połączeń też powinny zniknąć.

Doświadczenie desktopowe OpenClaw to jego Control UI, które otwiera się jako aplikacja webowa wspierana przez własny lokalny gateway. OpenClaw mieszka w `~/.openclaw` i aktualizuje się sam: użyj przycisku "Update Gateway" Control UI lub uruchom `openclaw update`, a gateway uruchomi się ponownie na nowej wersji. Omarchy wybiera jedynie wydanie, od którego zaczyna świeża instalacja. Usunięcie OpenClaw w _Remove > AI_ zabiera ze sobą usługę gateway i aplikację, a następnie pyta, czy `~/.openclaw` też powinno zniknąć, ponieważ przechowuje Twoje czaty i dane uwierzytelniające obok samego OpenClaw i środowisk uruchomieniowych wtyczek, które pobiera; domyślnie je zachowuje, a ponowna instalacja OpenClaw je podejmuje.

T3 Code działa z oficjalnego wydania AppImage w `~/.local/share/t3code`, a nie z pakietu, więc aktualizuje się sam. Instalacja pyta, czy zacząć na kanale Stable czy Nightly; przełącz później w ustawieniach T3 Code. Twoje wątki i ustawienia mieszkają w `~/.t3`, a usunięcie T3 Code w _Remove > AI_ zabiera je ze sobą.

### Modele lokalne

Uruchom otwarty model na własnej maszynie dla swoich agentów do kodowania. Twoje prompty i kod zostają na maszynie; nic wysłanego do modelu jej nie opuszcza. Zacznij od:

```bash
omarchy agent local use best
```

Lub w panelu agentów na górnym pasku wybierz + a następnie Local AI, które pojawia się, gdy model pasuje do tej maszyny. Za pierwszym razem instaluje to Podman, który uruchamia modele, a na maszynie NVIDIA zestaw narzędzi kontenerowych NVIDIA, który daje im GPU. Omarchy następnie wybiera zalecany model dla tej maszyny, pobiera go i uruchamia. Spodziewaj się pobrania dziesiątek GB i większości pamięci maszyny w użyciu, gdy model działa: Flash Next używa około 100 GiB przy pełnym kontekście 256K. Jeśli inne modele zajmują pamięć, której potrzebuje, jest skonfigurowany jako zatrzymany, gotowy do startu, gdy zatrzymasz jeden z nich. Model zatrzymuje się przy wylogowaniu; zatrzymaj go sam, gdy potrzebujesz pamięci do czegoś innego.

`omarchy agent local list` pokazuje opcje i wyjaśnia, dlaczego niektóre nie pasują. Aby skonfigurować kolejny, uruchom `omarchy agent local use <recipe>`. Dziś `qwen3.8-flash-next-halogen` i `qwen3.8-27b-gufo` są dostępne dla maszyn Strix Halo 128 GB. Nowe receptury i zalecenia przychodzą z `omarchy update`, przez pakiet.

Każdy skonfigurowany model otrzymuje własną linię w panelu agentów, obok Twoich subskrypcji: play, aby go uruchomić, pause, aby go zatrzymać i zwolnić jego pamięć, oraz przycisk terminala, aby otworzyć na nim swojego agenta. Kilka może działać naraz, gdy razem mieszczą się w pamięci; jeśli jeden się nie mieści, Omarchy mówi, który działający model zatrzymać. Przeciągaj linie, aby zmienić ich kolejność, i naciśnij Delete na wybranej linii, aby usunąć model i jego pobranie.

Z linii poleceń `omarchy agent local start <recipe>` i `omarchy agent local stop <recipe>` robią to samo, `omarchy agent local status` pokazuje każdy model, a `omarchy agent --local` otwiera Twojego domyślnego agenta na ostatnim uruchomionym modelu (pi, jeśli Twój domyślny agent nie może używać modelu lokalnego). Każdy klient kompatybilny z OpenAI też może się połączyć: `status` pokazuje adres każdego modelu (pierwszy to `http://127.0.0.1:11435/v1`), nazwa receptury jest modelem, a klucz znajduje się w `~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` usuwa model i pobrania, których nie używa żaden inny model.

Środowiska uruchomieniowe stron trzecich są oznaczane swoim wydawcą. Omarchy uruchamia każdy model bez dostępu do sieci.

### Lokalne modele LLM

Omarchy zaleca dwa sposoby uruchamiania lokalnych modeli LLM: LM Studio i Ollama. LM Studio zapewnia interfejs GUI do znajdowania modeli o otwartych wagach, instalowania ich i uruchamiania. To świetny sposób, aby łatwo zacząć. Ollama oferuje CLI do robienia tego w podobny sposób. Ale jeśli dopiero zaczynasz z modelami lokalnymi, zacząłbym od LM Studio. Możesz zainstalować każde z nich w _Install > AI_ w Omarchy Menu.

### Skill Omarchy

Skille agentów pomagają AI używać konkretnych narzędzi w konkretny sposób, a Omarchy jest dostarczane z domyślnym skillem do dostosowywania systemu. Takim jak poprawianie konfiguracji Hyprland, dostosowywanie paska, a nawet tworzenie nowego motywu od zera. Jest dowiązany symbolicznie do katalogów skilli dla Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` i każdego `~/.hermes/profiles/*/skills`) oraz ogólnej lokalizacji `~/.agents/skills`, więc większość harnessów podchwytuje go automatycznie.

Ale powinieneś traktować ten skill jako eksperymentalny. Różne modele będą go używać z różnym skutkiem. Najlepiej najpierw uruchomić w trybie planu, aby mieć pojęcie, co agent chciałby zmienić. A potem bądź gotów wycofać zmiany, a nawet wywołać `omarchy reinstall configs`, jeśli agent narobi bałaganu we wszystkim.
