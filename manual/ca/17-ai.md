# IA

Omarchy inclou llançadors per als agents de programació següents sense triar-ne un de predeterminat per a tu. Executa una ordre per instal·lar el seu CLI al primer ús i després autentica't quan se't demani. Hermes i OpenClaw són les excepcions: no s'instal·la res per a ells a través de mise, i triar-ne qualsevol dels dos configura la seva pròpia còpia autoactualitzable, com explica _Aplicacions d'escriptori_ més avall.

### Instal·lació i actualització d'agents

Excepte Hermes i OpenClaw, aquests agents fan servir la instal·lació diferida de mise: el primer llançament instal·la el CLI, i els llançaments posteriors el reutilitzen. mise també comprova si un agent instal·lat té una nova versió com a màxim una vegada cada quatre hores, just abans d'iniciar-lo o en segon pla en un indicador de l'intèrpret d'ordres. Si aquesta actualització falla o no tens connexió, s'executa la versió instal·lada. `omarchy update` actualitza els agents instal·lats amb la resta d'Omarchy, i `mup` actualitza només les eines gestionades per mise.

L'actualitzador propi d'un agent, com ara `claude update`, `codex update` o un botó d'actualització en una aplicació, no actualitza la instal·lació gestionada per mise. `codex update` falla, i `claude update` pot informar d'èxit mentre instal·la una còpia separada que mise no segueix. Si prefereixes fer servir l'instal·lador i l'actualitzador natius d'un agent, afegeix-lo a `disable_tools`; vegeu [Eines CLI preinstal·lades](18-development-tools.md#preinstalled-cli-tools).

Per instal·lar totes les eines diferides configurades abans de necessitar-les, executa `mise install --include-lazy`. Això inclou les altres eines CLI predeterminades d'Omarchy, a més dels agents. Vegeu [Eines CLI preinstal·lades](18-development-tools.md#preinstalled-cli-tools) per instal·lar una sola eina o fer servir la teva pròpia instal·lació.

`grok` s'instal·la a través del paquet propi `grok` de mise, de la mateixa manera que `claude` i `codex`. Executa `grok`, o marca'l amb una estrella al panell d'agents. Salta't l'instal·lador `curl | bash` de x.ai. Aquesta via posa una segona còpia a `~/.grok/bin`, la anteposa a `PATH` i sobreescriu l'embolcall d'Omarchy.

`dsh` obre la seva interfície d'usuari de navegador a `127.0.0.1:3080`, amb el directori de llançament com a espai de treball predeterminat. La seva interfície de navegador no accepta cap indicació inicial, de manera que `omarchy agent prompt` l'obre amb la indicació al porta-retalls per enganxar-la. Omarchy l'inicia amb el preajust de permisos sense aprovació de DeepSeek. DeepSeek Harness puja els registres de sessió a DeepSeek quan fas servir la seva API oficial de models; desactiva-ho a _Settings > General > Upload Session Log_ a la seva interfície de navegador. Els comentaris que li envies també es pugen amb la sessió, llevat que l'iniciïs amb `DSH_TELEMETRY_MODE=DISABLED`.

### L'agent predeterminat

Tria el teu agent predeterminat amb l'estrella al costat d'un agent al panell d'agents, que està plena en el predeterminat, o amb `omarchy default agent <name>`, que també accepta qualsevol harness sense una línia allà. Si l'agent encara no està instal·lat, triar-lo l'instal·la primer, i també rep un llançador propi al llançador d'aplicacions, al costat d'Agent. Un Omarchy nou t'invita a configurar-ne un amb una notificació única, que obre el panell d'agents.

Triar Claude també intenta configurar la seva extensió de navegador per a Chromium, Chrome, Brave, Brave Origin i Edge. La configuració de l'extensió s'aplica a tots els usuaris i pot demanar-te la contrasenya del sistema; cancel·lar o que falli la instal·lació de l'extensió encara selecciona i llança Claude. Reinicia el navegador, activa l'extensió si se't demana i inicia sessió a Claude per acabar de connectar-la. Executa `/chrome` a Claude per comprovar la connexió. Firefox i Zen no admeten aquesta extensió. Si Claude ja era el teu predeterminat abans que s'afegís aquesta configuració, torna a seleccionar-lo per instal·lar l'extensió.

Un cop hagis triat, `Super + Shift + Ctrl + A` llança l'agent predeterminat en una finestra de terminal dedicada (o obre el selector si encara no n'has triat cap). També pots llançar-lo directament en una tasca amb `omarchy agent prompt "Review this project"`. Freebuff i DeepSeek Harness no accepten cap indicació inicial, de manera que s'obren amb la indicació al porta-retalls per enganxar-la. Els agents llançats d'aquesta manera s'executen sense supervisió en els seus respectius modes de no aturar-se a preguntar, així que prepara't perquè realment facin coses! MiniMax Code no té un mode així per a les seves sessions interactives, de manera que demana permisos com de costum. I com que els agents es neguen a recordar la confiança per al teu directori personal, els llançaments des de `$HOME` comencen a `~/Work`.

També hi ha dreceres de terminal: `a` executa l'agent predeterminat en línia al terminal actual, mentre que `c`, `cx` i `cy` inicien OpenCode, Claude Code i Codex directament (també en els seus modes d'aprovació automàtica). Els canvis de tema també se sincronitzen amb els agents: Claude Code, Pi, OpenCode i Hermes (un cop Omarchy l'ha instal·lat) segueixen quan canvies el tema d'Omarchy.

### Les instruccions del teu agent

Les regles personals per a cada agent van a `~/.agents/AGENTS.md`, al costat de les habilitats compartides a `~/.agents/skills`. Obre'l amb la icona de document al costat del + al panell d'agents, o amb `omarchy agent instructions --edit`, que també l'enllaça a cada harness que manté el seu propi fitxer global: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, el `~/.copilot/copilot-instructions.md` de Copilot, i així successivament. Crush i Amp llegeixen l'enllaç `~/.config/AGENTS.md`, mentre que omp, Kimi i DeepSeek Harness llegeixen `~/.agents/AGENTS.md` directament. Triar un agent predeterminat també l'enllaça. Un fitxer d'instruccions que ja tenies es converteix en el compartit si encara no n'hi havia cap; en cas contrari es conserva al costat de l'enllaç com a `.bak`. Executa `omarchy agent instructions` per tornar a enllaçar després d'instal·lar un altre agent.

### El panell d'agents

La barra superior té una icona d'agents. Abans que hagis configurat un agent, el seu panell ofereix tres maneres de començar: inicia sessió en una subscripció de Claude, Codex, Grok, Gemini, Muse, Cursor o Copilot, o a Més un pla de programació d'OpenCode Go, MiniMax, Synthetic o Z.ai; paga per ús amb Fireworks, OpenCode Zen and Go, OpenRouter, o a Més DeepSeek o qualsevol altre proveïdor al qual OpenCode iniciï sessió, tots executats a OpenCode; o executa el millor model per al teu ordinador, quan n'hi hagi un que li càpiga. El primer que acabis es converteix en el teu agent predeterminat, i el + del panell, o _Agent > Add_ al Menú d'Omarchy, ofereix els mateixos tres més tard. Després d'això, el panell posa cada subscripció en una pàgina: cada agent i compte amb el seu pla, un mesurador per a cadascun dels seus límits de sessió de 5 hores i setmanals amb el temps fins que es restableixi (passa el cursor per sobre per veure el percentatge exacte), o el saldo prepagat restant, sota una línia que rota pel que has fet servir en tots ells, com ara els tokens d'aquesta setmana i el teu model més utilitzat. A _Make something cool_ ofereix indicacions inicials per a un tema, connector, aplicació o joc nous que passen la tasca al teu agent predeterminat. Les aplicacions es construeixen de la manera com ho fan les pròpies Hype, Monologue i Omacut d'Omarchy, en C++ i Qt Quick, seguint l'habilitat d'agent omarchy-make-app, i el compilador i les peces de Qt que necessiten venen instal·lats. Els jocs són una sola pàgina three.js a `~/Games/vibes`, seguint l'habilitat d'agent omarchy-make-game, i tots s'obren des d'un únic llançador Game Vibes en el tema actual; carreguen three.js des del web, de manera que necessiten una connexió per iniciar-se. Claude Code, Codex, Grok, Kimi, Cursor i la seva assignació de Grok Bot, GitHub Copilot, Muse, Gemini (a través d'Antigravity) i Devin estan coberts de sèrie amb els seus límits, Kimchi amb el seu pla, crèdits prepagats i pressupostos de despesa, i Hermes, Mistral Vibe i Qwen Code mostren les seves sessions i tokens un cop els has fet servir. També hi apareixen els plans i claus de proveïdors que fas servir a través de pi, omp o opencode: OpenCode Zen and Go, el Z.ai GLM Coding Plan, Ollama Cloud, el MiniMax Token Plan i Synthetic amb els seus límits; OpenRouter i DeepSeek amb els seus saldos prepagats; Fireworks amb la seva despesa dels darrers 30 dies. Els tokens dels models que executes al teu propi maquinari també compten per als totals; els models mateixos tenen un panell propi, descrit a [Models locals](#local-models). Cada agent es compta una vegada, sota qui el facturi, per molts harness a través dels quals el facis servir.

Fes clic amb el botó esquerre a la icona de la barra o prem `Super + Ctrl + X` per al panell, fes clic amb el botó dret per llançar el teu agent predeterminat i fes clic amb el botó central per actualitzar. Els registres d'ús que hi ha darrere es regeneren cada 15 minuts amb `omarchy agent usage update`, i el panell fins i tot pot fusionar l'ús de les teves altres màquines a través d'una carpeta sincronitzada. Consulta el README a `$OMARCHY_PATH/shell/plugins/agents/` per a la configuració completa.

### Diverses subscripcions

Si pagues per més d'un pla de Claude, Codex o Grok — un Max personal i un de feina, per exemple — Omarchy pot mantenir-los tots amb la sessió iniciada i moure's entre ells. Afegeix una subscripció amb el + del panell d'agents, que et guia allà mateix, o amb `omarchy agent account add claude Work` (o `codex`, o `grok`). El mateix + i la mateixa ordre inicien sessió a Gemini (`gemini`) i OpenCode (`opencode`), i desen una clau API de Fireworks (`fireworks`) o OpenRouter (`openrouter`) a OpenCode; l'ordre també inicia sessió a Copilot (`copilot`), Cursor (`cursor`) i Muse (`muse`). Aquests mantenen una sola sessió iniciada cadascun. Instal·la el CLI si falta. El primer compte d'un proveïdor inicia sessió a través del teu navegador normal, just on el CLI sempre mira. Cada un després d'aquest inicia sessió a través d'una finestra privada, de manera que el compte en què el teu navegador ja ha iniciat sessió no es reculli per error; inicia sessió allà com el compte que estàs afegint, i tanca primer qualsevol finestra privada que ja tinguessis oberta. No tanquis mai la sessió del CLI per fer això: tancar la sessió revoca l'inici de sessió desat, i aquest compte s'hauria d'afegir de nou.

Per copiar els teus inicis de sessió de subscripció a una altra màquina Omarchy per SSH, executa `omarchy agent account copy user@laptop`. L'emissor proporciona un receptor temporal quan la destinació no en té cap d'instal·lat, de manera que les màquines Omarchy més antigues poden rebre comptes sense una actualització. Els receptors instal·lats tenen precedència. Això copia totes les subscripcions de Claude, Codex i Grok; afegeix noms de proveïdors per seleccionar-les, com a `omarchy agent account copy laptop claude`. Els noms de compte i els ID d'ordre coincideixen amb l'origen, inclosos els comptes ja presents a la destinació. Els comptes de destinació no relacionats reben un sufix numèric si els seus noms entren en conflicte, i la configuració, les habilitats, els connectors i l'historial de converses romanen locals a cada màquina.

Les credencials de destinació existents es conserven. Un compte d'origen que ja ha iniciat sessió allà té el seu nom sincronitzat sense reemplaçar les seves credencials; els altres comptes s'afegeixen al seu costat. Per reemplaçar les credencials desades per als comptes coincidents, fes servir `omarchy agent account copy --replace laptop claude` després de sortir de les sessions d'aquest compte a la destinació. Una destinació nova també rep el compte actiu i les preferències de canvi de l'origen; una destinació establerta conserva els seus.

Les credencials viatgen per SSH i s'emmagatzemen en fitxers privats a la destinació, així que copia només a màquines en què confiïs. Això és una còpia única, no una sincronització contínua. Els tokens d'actualització de Codex poden ser rotats per una altra màquina, i deixar un inici de sessió copiat amb necessitat de renovació; els inicis de sessió separats continuen sent l'opció més fiable per a l'ús simultani en diverses màquines. Vegeu [la guia d'autenticació de comptes de Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Un compte per proveïdor està actiu, i cada sessió nova comença com a tal: `cx`, `cy`, un `claude`, `codex` o `grok` sense més, qualsevol cosa llançada a través d'`omarchy agent`, i els scripts o editors que troben el CLI a `PATH`. Canvia amb `omarchy agent account use work` (i torna amb `omarchy agent account use main`), o al panell prement el número d'un compte i després `Enter` (o fent clic a la seva estrella). Les sessions de Claude en execució també canvien, a partir del seu missatge següent: cada sessió de Claude s'executa a `~/.claude`, que sempre conté l'inici de sessió del compte actiu. Una sessió de Claude iniciada a la carpeta pròpia d'un compte per un Omarchy més antic manté aquest inici de sessió fins que surt, de manera que el canvi anomena aquestes sessions i acaba per si mateix un cop han desaparegut. Les sessions de Codex i Grok en execució romanen al compte amb què han començat. L'historial de converses, la configuració, les habilitats i els connectors es comparteixen entre comptes, de manera que `claude --continue` a la mateixa carpeta continua on ho havies deixat amb el compte nou.

Amb més d'un compte, el panell mostra els límits de cada compte un al costat de l'altre, amb una estrella plena en el que està en ús. Omarchy t'avisa quan el compte actiu supera el 95% d'un límit, i fer clic a la notificació canvia al compte amb més marge. Mai canvia per si mateix. Canvia el llindar amb `omarchy agent account threshold 90`. Si cada compte supera el llindar, en sentiràs parlar una vegada, juntament amb quin compte s'allibera primer. Mentre un compte actiu estigui a menys de 15 punts del seu llindar (80% per defecte), els seus límits es comproven cada tres minuts en lloc de cada 15.

`omarchy agent account list` mostra cada compte i els seus límits més recents, `omarchy agent account remove work` oblida un compte, i `omarchy agent account rename primary Hey` en reanomena un (o fes clic al nom d'un compte al panell). Aquestes ordres funcionen amb els comptes del teu agent predeterminat; per arribar a l'altre proveïdor, anomena'l primer, com a `omarchy agent account use codex side`. L'inici de sessió que ja tenies a `~/.claude` o `~/.codex` és el compte _Main_. El de Codex roman on és; el de Claude espera en una carpeta pròpia mentre un altre compte està actiu. Un compte que no s'ha fet servir durant més d'unes vuit hores pot mostrar _Sign-in required_; fes-hi clic per iniciar sessió de nou en aquest compte directament al panell, o canvia-hi i inicia una sessió, que actualitza l'inici de sessió per si mateixa. Els servidors MCP que afegeixes amb `claude mcp add` arriben a cada compte de Claude, ja que tots s'executen a `~/.claude`; per a Codex i Grok, els servidors que tenies quan es va afegir un compte l'acompanyen, però els posteriors només arriben al compte en què els vas afegir. Claude Desktop manté un inici de sessió propi, i les eines de Codex o Grok configurades amb una ruta absoluta a un binari CLI no segueixen el canvi. Un `CLAUDE_CONFIG_DIR`, `CODEX_HOME` o `GROK_HOME` explícit té precedència sobre el compte seleccionat.

### Diagnòstic d'errors

Omarchy vigila systemd-coredump per detectar bloquejos de processos. Un cop hagis triat un agent predeterminat, qualsevol programa teu que faci un bolcat de memòria mostra una notificació "Process crashed" — fes-hi clic, i el bloqueig es passa al teu agent predeterminat juntament amb l'habilitat omarchy-diagnose-crash d'Omarchy, que guia l'agent per establir els fets a partir del bolcat de memòria i decidir si val la pena informar del bloqueig a l'equip original. També pots executar-ho manualment contra qualsevol PID de `coredumpctl list` amb `omarchy agent crash <pid>`.

La vigilància està activada per defecte. Desactiva-la a _Trigger > Toggle > Crash Capture Off_ (o amb `omarchy toggle crash-capture`) i les notificacions s'aturen; `omarchy agent crash <pid>` continua funcionant manualment.

Els bloquejos també es poden silenciar programa a programa, que és el que el diagnòstic t'ofereix al final. `omarchy crash mute hyprland` atura les notificacions només per a aquest programa, `omarchy crash mute hyprland off` les torna a activar, i `omarchy crash mute` per si sol llista el que has silenciat. Accepta la ruta del binari amb la mateixa facilitat que el seu nom, de manera que `omarchy crash mute /usr/bin/hyprland` fa el mateix. Posa entre cometes un nom amb un espai, com a `omarchy crash mute 'Some App'`. Tota la resta continua notificant, i el programa silenciat continua bloquejant-se — això amaga el recordatori, no arregla res.

### Aplicacions d'escriptori

El menú _Install > AI_ també inclou unes quantes aplicacions gràfiques d'IA: Amp Desktop, Antigravity Desktop, l'aplicació d'escriptori de ChatGPT, l'aplicació d'escriptori de Claude (la beta per a Linux d'Anthropic, amb pestanyes Chat, Cowork i Claude Code), Grok Bot per xatejar amb els models de xAI, Herdr Desktop, Hermes Desktop, OpenClaw, l'aplicació d'escriptori de Perplexity i T3 Code. Grok Bot és l'aplicació de xat d'escriptori. L'agent de programació és l'ordre `grok`.

Hermes Desktop és la que cal conèixer, perquè una màquina té un Hermes, i és el de l'aplicació: Hermes només s'instal·la mai a través de l'aplicació, i l'ordre `hermes` que executa l'agent predeterminat és la de l'aplicació. Triar Hermes com a agent predeterminat instal·la el mateix que l'entrada _Install > AI_: el paquet, i un entorn d'execució d'Hermes a `~/.hermes` configurat per l'instal·lador propi d'Hermes, que triga uns minuts la primera vegada. Aquest entorn d'execució és l'únic Hermes que fan servir l'ordre de terminal `hermes`, l'agent predeterminat i l'aplicació, i s'actualitza amb `hermes update` en lloc d'esperar una versió d'Omarchy. Instal·lar-lo també dona a Hermes el tema d'Omarchy com una aparença anomenada `omarchy`, que cada superfície d'Hermes segueix quan canvies de tema; tria'n una altra a la configuració Appearance d'Hermes o amb `/skin` si prefereixes que no ho faci, i Omarchy deixa aquesta tria en pau. Eliminar l'aplicació a _Remove > AI_ tanca Hermes primer, passarel·la inclosa, s'emporta aquest entorn d'execució amb ella, i conserva els teus xats, records i les habilitats que Hermes va escriure per a si mateix llevat que li diguis el contrari: pregunta, per defecte no, si aquestes dades i la teva configuració de connexió també haurien d'anar-se'n.

L'experiència d'escriptori d'OpenClaw és la seva Control UI, que s'obre com una aplicació web recolzada per la seva pròpia passarel·la local. OpenClaw viu a `~/.openclaw` i s'actualitza sol: fes servir el botó "Update Gateway" de la Control UI o executa `openclaw update`, i la passarel·la es reinicia amb la nova versió. Omarchy només tria la versió amb què comença una instal·lació nova. OpenClaw també pot ser el teu agent predeterminat: triar-lo a _Agent > Harness_ configura aquesta mateixa còpia a `~/.openclaw`, i l'agent obre la interfície d'usuari de terminal d'OpenClaw connectada a la seva passarel·la. Eliminar OpenClaw a _Remove > AI_ s'emporta el servei de passarel·la i l'aplicació amb ell i després pregunta si `~/.openclaw` també hauria d'anar-se'n, ja que allò conserva els teus xats i credencials juntament amb el mateix OpenClaw i els entorns d'execució de connectors que descarrega; per defecte es conserva, i instal·lar OpenClaw de nou el recupera.

Herdr Desktop és l'aplicació d'escriptori [Herdr](https://herdr.dev): espais, pestanyes i panells de terminals i agents de programació que continuen executant-se al seu nucli quan tanques la finestra. Ve de l'instal·lador propi de Herdr en lloc d'un paquet, de manera que viu a `~/.local/share/herdr-app`, porta el seu nucli a `~/.local/bin/herdr-core` quan encara no en tens cap, i s'actualitza tant a si mateix com a ell. Està al costat de l'ordre `herdr` que Omarchy inclou a `Super + Ctrl + Return` en lloc de reemplaçar-la, i rep les tecles directes d'aquesta ordre: `Alt + Return` i `Alt + Shift + Return` divideixen un panell cap avall o cap a la dreta, `Alt + Escape` el tanca, `Ctrl + Alt + Arrow` es mou entre panells, `Alt + 1..9` i `Alt + Left/Right` trien una pestanya, i `Alt + Up/Down` es mouen entre espais. `Ctrl + 1..9` tria un espai i `Alt + Shift + Up/Down` passa pels agents. Les tecles de prefix `Ctrl + Space` romanen només per al terminal, ja que l'aplicació no pot mantenir una tecla Ctrl simple per a una seqüència. Omarchy escriu aquestes a `~/.config/herdr-app/keys.json`, i `omarchy-refresh-herdr-app` les restaura. Instal·lar-lo tria el tema Omarchy de Herdr, que segueix el teu tema d'Omarchy a partir d'aleshores. Herdr manté un tema per al mode clar i un per al fosc, de manera que després de canviar entre un tema fosc i un de clar d'Omarchy, torna a triar Omarchy al selector de temes de Herdr una vegada més per a l'altre mode.

T3 Code s'executa des de la seva versió oficial AppImage a `~/.local/share/t3code` en lloc de des d'un paquet, de manera que s'actualitza sol. Instal·lar-lo pregunta si vols començar al canal Stable o Nightly; canvia-ho més tard a la configuració de T3 Code. Els teus fils i la teva configuració viuen a `~/.t3`, i eliminar T3 Code a _Remove > AI_ se'ls emporta amb ell.

### Models locals

Executa un model obert a la teva pròpia màquina per als teus agents de programació. Les teves indicacions i el teu codi romanen a la màquina; res del que s'envia al model en surt. Comença amb:

```bash
omarchy models use best text
```

Això configura el millor model de text per a aquesta màquina, el tipus que fan servir els teus agents. Els models d'imatge, vídeo i música tenen el seu propi millor: `omarchy models use best image`, `video` o `music`. Executa `omarchy models use best` per veure la tria de cada tipus per a aquesta màquina.

O obre el panell de models locals des de la seva icona d'espurnes a la barra superior, al costat de la icona d'agents, o amb Super + Ctrl + Alt + X, i tria +. La icona apareix quan un model cap en aquesta màquina. Podman, que executa els models, ve amb Omarchy, igual que el kit d'eines de contenidors de NVIDIA en una màquina NVIDIA, que els dona la GPU; si falta qualsevol dels dos, la primera configuració l'instal·la. Llavors Omarchy tria el model recomanat per a aquesta màquina, el descarrega i l'inicia. Espera una descàrrega de desenes de GB i que la major part de la memòria de la màquina estigui en ús mentre el model s'executa: Flash Next fa servir uns 100 GiB amb el seu context complet de 256K. Si altres models ocupen la memòria que necessita, es configura aturat, preparat per iniciar-se un cop n'aturis un. El model s'atura en tancar la sessió; atura'l tu mateix quan necessitis la memòria per a una altra cosa.

`omarchy models list` mostra les opcions i explica per què algunes no hi caben. Per configurar-ne un altre, executa `omarchy models use <recipe>`. Avui, `qwen3.8-flash-next-gufo` i `qwen3.8-27b-gufo` estan disponibles per a màquines Strix Halo de 128 GB; el 27B ocupa uns 40 GiB, de manera que deixa espai per a altres feines. En un portàtil de 64 GB amb l'Arc B390 d'Intel, `qwen3.6-35b-a3b-llamacpp` s'executa en uns 30 GiB. Les receptes i recomanacions noves arriben amb `omarchy update`, a través del paquet.

Cada model que configures rep la seva pròpia línia al panell de models locals: reprodueix per iniciar-lo, pausa per aturar-lo i alliberar la seva memòria, i el botó de terminal per obrir el teu agent en ell. A la part superior, una barra mostra com es reparteix la memòria de la màquina entre el mateix Omarchy (el sistema i les teves aplicacions), cada model en execució i el que queda lliure. Apunta a un model aturat i la barra mostra si hi cap, o quant li falta. Diversos poden executar-se alhora quan caben junts a la memòria; si un no hi cap, Omarchy diu quin model en execució has d'aturar. Arrossega les línies pel seu logotip per reordenar-les, i prem Delete en una línia seleccionada per eliminar un model i la seva descàrrega.

Cada model de programació que configures també rep la seva pròpia entrada al llançador d'aplicacions, amb el nom del model i el logotip del seu fabricant, de la manera com iniciar sessió a Claude, Codex o Grok n'afegeix una. Obre el teu agent en aquest model, i inicia el model primer si no s'està executant: el terminal mostra com es carrega i passa el relleu a l'agent un cop està en marxa. Eliminar un model elimina la seva entrada.

No tots els models són per programar. Els models d'imatge, vídeo i música s'obren a Fantasi, l'aplicació d'Omarchy per fer imatges, vídeo i música amb un model que s'executa en aquesta màquina, triats allà o des de la seva línia al panell de models locals.

Un model continua executant-se exactament com es va configurar, de manera que una actualització d'Omarchy mai en reinicia un sota els teus agents. Quan Omarchy té un entorn d'execució més nou o pesos més nous per a un model que has configurat, la seva línia mostra un botó d'actualització: prem-lo i el model es torna a configurar en segon pla, descarregant només el que ha canviat, i es reinicia amb la nova versió. Un model que estava aturat roman aturat. `omarchy models update` fa el mateix per a cada model des d'un terminal.

Des de la línia d'ordres, `omarchy models start <recipe>` i `omarchy models stop <recipe>` fan el mateix, `omarchy models status` mostra cada model, i `omarchy agent --local` obre l'últim model que vas iniciar a pi, sigui quin sigui el teu agent predeterminat. Per fer que aquest model sigui el que obren la drecera de teclat de l'agent, la consola Quake i _Make something_, executa `omarchy default agent local` o tria _Local model_ a _Agent > Harness_. pi també llista cada model que has configurat, i els de les màquines amb què t'has aparellat, al seu propi selector de models, de manera que un `pi` simple també els arriba. Qualsevol client compatible amb OpenAI també es pot connectar: `status` mostra l'adreça de cada model (la primera és `http://127.0.0.1:11435/v1`), el nom de la recepta és el model, i la clau és a `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` elimina un model i les descàrregues que cap altre model no fa servir.

Els entorns d'execució de tercers estan etiquetats amb el seu editor. Omarchy executa cada model sense accés a la xarxa.

### LLM locals

Omarchy recomana dues maneres d'executar models LLM locals: LM Studio i Ollama. LM Studio proporciona una interfície gràfica per trobar models de pesos oberts, instal·lar-los i executar-los. És una bona manera de començar fàcilment. Ollama ofereix un CLI per fer-ho de manera semblant. Però si ets nou en els models locals, jo començaria amb LM Studio. Pots instal·lar qualsevol dels dos a _Install > AI_ en el Menú d'Omarchy.

### Les habilitats d'Omarchy

Les habilitats d'agent ajuden la IA a fer servir eines específiques d'una manera específica, i Omarchy en inclou set. L'habilitat omarchy cobreix personalitzar el sistema, com ara ajustar la teva configuració de Hyprland o ajustar la barra. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app i omarchy-make-game cobreixen fer alguna cosa nova, omarchy-contribute cobreix informar d'un error o enviar una correcció a l'equip original, i omarchy-diagnose-crash treballa sobre el bolcat de memòria d'un bloqueig. Estan enllaçades simbòlicament als directoris d'habilitats per a Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` i cada `~/.hermes/profiles/*/skills`), i la ubicació genèrica `~/.agents/skills`, de manera que la majoria de harness les recullen automàticament. Una carpeta d'habilitats teva amb el mateix nom té precedència.

Però hauries de tractar aquestes habilitats com a experimentals. Diferents models les faran servir amb efectes diferents. El millor és executar primer en mode de planificació, perquè tinguis una idea del que l'agent voldria canviar. I després prepara't per revertir els canvis o fins i tot invocar `omarchy reinstall configs`, si l'agent fa un embolic amb tot.
