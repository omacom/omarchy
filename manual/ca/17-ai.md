### Instal·lació i actualització d'agents

Llevat d'Hermes, aquests agents utilitzen la instal·lació diferida de mise: la primera execució instal·la el CLI, i les execucions posteriors el reutilitzen. mise també comprova si hi ha una versió nova d'un agent instal·lat com a màxim un cop cada quatre hores, just abans que s'iniciï o en segon pla en un indicador de l'intèrpret d'ordres. Si aquesta actualització falla o no tens connexió, s'executa la versió instal·lada. `omarchy update` actualitza els agents instal·lats amb la resta d'Omarchy, i `mup` actualitza només les eines gestionades per mise.

L'actualitzador propi d'un agent, com ara `claude update`, `codex update` o un botó d'actualització en una aplicació, no actualitza la instal·lació gestionada per mise. `codex update` falla, i `claude update` pot indicar que ha tingut èxit mentre instal·la una còpia separada que mise no controla. Si prefereixes utilitzar l'instal·lador i l'actualitzador natius d'un agent, afegeix-lo a `disable_tools`; consulta [Eines de CLI preinstal·lades](18-development-tools.md#preinstalled-cli-tools).

Per instal·lar totes les eines diferides configurades abans que les necessitis, executa `mise install --include-lazy`. Això inclou les altres eines de CLI predeterminades d'Omarchy, a més dels agents. Consulta [Eines de CLI preinstal·lades](18-development-tools.md#preinstalled-cli-tools) per instal·lar una sola eina o utilitzar la teva pròpia instal·lació.

`grok` s'instal·la a través del paquet `grok` de primera mà de mise, de la mateixa manera que `claude` i `codex`. Executa `grok`, o tria'l a _Setup > Defaults > Agent_. Omet l'instal·lador `curl | bash` de x.ai. Aquest camí posa una segona còpia a `~/.grok/bin`, la anteposa a `PATH` i sobreescriu l'embolcall d'Omarchy.

`dsh` obre la seva interfície de navegador a `127.0.0.1:3080`, amb el directori d'execució com a espai de treball predeterminat. La seva interfície de navegador no accepta cap instrucció inicial, de manera que `omarchy agent prompt` l'obre amb la instrucció al porta-retalls perquè l'enganxis. Omarchy l'inicia amb el conjunt de permisos sense aprovació de DeepSeek. DeepSeek Harness puja els registres de sessió a DeepSeek quan utilitzes la seva API oficial de models; desactiva-ho a _Settings > General > Upload Session Log_ a la seva interfície de navegador. Els comentaris que li enviïs també es pugen amb la sessió, llevat que l'iniciïs amb `DSH_TELEMETRY_MODE=DISABLED`.

### L'agent predeterminat

Tria el teu agent predeterminat amb `omarchy default agent <name>` o a _Setup > Defaults > Agent_ al Menú d'Omarchy (`Super + Space`). Si l'agent encara no està instal·lat, triar-lo l'instal·la primer. Un Omarchy acabat d'instal·lar t'invitarà a fer aquesta tria amb una notificació única.

Triar Claude també intenta configurar la seva extensió de navegador per a Chromium, Chrome, Brave, Brave Origin i Edge. La configuració de l'extensió s'aplica a tots els usuaris i pot demanar-te la contrasenya del sistema; cancel·lar-la o que la instal·lació de l'extensió falli no impedeix que Claude se seleccioni i s'iniciï. Reinicia el navegador, activa l'extensió si se't demana i inicia sessió a Claude per acabar de connectar-la. Executa `/chrome` a Claude per comprovar la connexió. Firefox i Zen no admeten aquesta extensió. Si Claude ja era el teu predeterminat abans que s'afegís aquesta configuració, selecciona'l de nou per instal·lar l'extensió.

Un cop hagis triat, `Super + Shift + Ctrl + A` inicia l'agent predeterminat en una finestra de terminal dedicada (o obre el selector si encara no n'has triat cap). També el pots iniciar directament amb una tasca amb `omarchy agent prompt "Review this project"`. Freebuff i DeepSeek Harness no accepten cap instrucció inicial, de manera que s'obren amb la instrucció al porta-retalls perquè l'enganxis. Els agents iniciats d'aquesta manera funcionen sense supervisió en els seus modes respectius de no aturar-se a preguntar, així que estigues preparat perquè realment facin coses! MiniMax Code no té cap mode així per a les seves sessions interactives, de manera que demana permisos com de costum. I com que els agents es neguen a recordar la confiança per al teu directori d'inici, les execucions des de `$HOME` s'inicien a `~/Work`.

També hi ha dreceres de terminal: `a` executa l'agent predeterminat en línia al terminal actual, mentre que `c`, `cx` i `cy` inicien OpenCode, Claude Code i Codex directament (també en els seus modes d'aprovació automàtica). Els canvis de tema també se sincronitzen amb els agents: Claude Code, Pi, OpenCode i Hermes (un cop Omarchy l'ha instal·lat) segueixen el canvi quan canvies el tema d'Omarchy.

### El panell d'agents

La barra superior té una icona d'agents. Abans que hagis configurat un agent, el seu panell et guia per iniciar sessió a Claude, Codex o Grok, i el primer es converteix en el teu agent predeterminat. Després d'això, el panell posa totes les subscripcions en una sola pàgina: cada agent i compte amb el seu pla, un mesurador per a cadascun dels seus límits de sessió de 5 hores i setmanals amb el temps que falta perquè es restableixi (passa el cursor per sobre per veure el percentatge exacte), o el saldo de prepagament restant, sota una línia que va rotant pel que has utilitzat en tots ells, com ara els tokens d'aquesta setmana i el model que més utilitzes. A _Make something_ ofereix instruccions inicials per a un tema, un complement o una aplicació nous que passen la tasca al teu agent predeterminat. Les aplicacions es creen de la mateixa manera que les pròpies Hype, Monologue i Omacut d'Omarchy, en C++ i Qt Quick, seguint l'habilitat d'agent omarchy-app, i el compilador i les peces de Qt que necessiten ja venen instal·lats. Claude Code, Codex, Grok, Kimi, Cursor i la seva assignació de Grok Bot, GitHub Copilot, Muse, Antigravity, Kimchi i Devin estan coberts de sèrie amb els seus límits, i Hermes, Mistral Vibe i Qwen Code mostren les seves sessions i tokens un cop els has utilitzat. També hi apareixen els plans i les claus de proveïdors que utilitzes a través de pi, omp o opencode: OpenCode Zen i Go, el Z.ai GLM Coding Plan, Ollama Cloud, el MiniMax Token Plan i Synthetic amb els seus límits; Fireworks, OpenRouter i DeepSeek amb els seus saldos de prepagament; i els models que executes al teu propi maquinari a Models locals. Cada agent es compta un sol cop, sota qui el facturi, independentment de quants harness facis servir per fer-lo funcionar.

Fes clic amb el botó esquerre a la icona de la barra per obrir el panell i amb el botó dret per iniciar el teu agent predeterminat. Els registres d'ús que hi ha al darrere es regeneren cada 15 minuts amb `omarchy agent usage-update`, i el panell fins i tot pot fusionar l'ús de les teves altres màquines mitjançant una carpeta sincronitzada. Consulta el README a `$OMARCHY_PATH/shell/plugins/agents/` per veure la configuració completa.

### Diverses subscripcions

Si pagues més d'un pla de Claude, Codex o Grok — un Max personal i un de feina, per exemple — Omarchy pot mantenir-los tots amb la sessió iniciada i moure's entre ells. Afegeix una subscripció amb el + al panell d'agents, que et guia durant el procés allà mateix, o amb `omarchy agent account add claude Work` (o `codex`, o `grok`). Instal·la el CLI si falta. El primer compte d'un proveïdor inicia sessió a través del teu navegador normal, just on el CLI sempre busca. Tots els següents inicien sessió a través d'una finestra privada, perquè el compte amb el qual el navegador ja té la sessió iniciada no s'agafi per error; inicia-hi sessió com el compte que estàs afegint i tanca primer qualsevol finestra privada que ja tinguessis oberta. No tanquis mai la sessió del CLI per fer això: tancar la sessió revoca l'inici de sessió desat, i aquell compte s'hauria d'afegir de nou.

Per copiar els teus inicis de sessió de subscripció a una altra màquina Omarchy per SSH, executa `omarchy agent account copy user@laptop`. L'emissor proporciona un receptor temporal quan la destinació no en té cap d'instal·lat, de manera que les màquines Omarchy més antigues poden rebre comptes sense una actualització. Els receptors instal·lats tenen prioritat. Això copia totes les subscripcions de Claude, Codex i Grok; afegeix noms de proveïdors per seleccionar-les, com a `omarchy agent account copy laptop claude`. Els noms de compte i els ID d'ordre coincideixen amb l'origen, inclosos els comptes que ja hi ha a la destinació. Els comptes de destinació no relacionats reben un sufix numèric si els seus noms entren en conflicte, i la configuració, les habilitats, els complements i l'historial de converses romanen locals a cada màquina.

Les credencials de destinació existents es conserven. Un compte d'origen que ja té la sessió iniciada allà té el seu nom sincronitzat sense substituir les seves credencials; els altres comptes s'hi afegeixen al costat. Per substituir les credencials desades dels comptes coincidents, utilitza `omarchy agent account copy --replace laptop claude` després de tancar les sessions d'aquell compte a la destinació. Una destinació nova també rep el compte actiu i les preferències de canvi de l'origen; una destinació ja establerta conserva els seus.

Les credencials viatgen per SSH i s'emmagatzemen en fitxers privats a la destinació, així que copia-les només a màquines en què confiïs. Això és una còpia única, no una sincronització contínua. Una altra màquina pot rotar els tokens d'actualització de Codex, i deixar un inici de sessió copiat amb necessitat de renovació; els inicis de sessió separats continuen sent l'opció més fiable per a l'ús simultani en diverses màquines. Consulta la [guia d'autenticació de comptes de Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Un compte per proveïdor està actiu, i cada sessió nova comença com a tal: `cx`, `cy`, un `claude`, `codex` o `grok` sense més, qualsevol cosa iniciada a través d'`omarchy agent`, i els scripts o editors que troben el CLI a `PATH`. Canvia amb `omarchy agent account use work` (i torna amb `omarchy agent account use main`), o al panell prement el número d'un compte i després `Enter` (o fent clic al seu botó Use). Les sessions que ja estan en execució romanen al compte amb el qual van començar. L'historial de converses, la configuració, les habilitats i els complements es comparteixen entre comptes, de manera que `claude --continue` a la mateixa carpeta reprèn on ho vas deixar al compte nou.

Amb més d'un compte, el panell mostra els límits de cada compte un al costat de l'altre, amb l'actiu marcat. Per defecte, Omarchy t'avisa quan el compte actiu supera el 95% d'un límit, i fer clic a la notificació canvia al compte amb més marge. Passa el cursor per sobre de la línia d'un compte al panell i fes clic a l'Autoswitch que apareix al costat d'Use (o prem `m`), o executa `omarchy agent account mode auto`, perquè canviï automàticament; mentre està activat, Autoswitch ocupa el lloc d'Use, i tornar-hi a fer clic torna a les notificacions. Afegeix un número per canviar el llindar, com a `omarchy agent account mode auto 90`. Si tots els comptes superen el llindar, se t'avisarà un cop, juntament amb quin compte s'allibera primer. Mentre un compte actiu estigui a 15 punts del seu llindar (80% amb el valor predeterminat), els seus límits es comproven cada tres minuts en lloc de cada 15.

`omarchy agent account list` mostra tots els comptes i els seus límits més recents, `omarchy agent account remove work` n'oblida un, i `omarchy agent account rename primary Hey` en canvia el nom d'un (o fes clic al nom d'un compte al panell). Aquestes ordres funcionen amb els comptes del teu agent predeterminat; per arribar a l'altre proveïdor, anomena'l primer, com a `omarchy agent account use codex side`. L'inici de sessió que ja tenies a `~/.claude` o `~/.codex` és el compte _Main_ i roman on és. Un compte que no s'utilitza durant més d'unes vuit hores pot mostrar _Sign-in required_; fes-hi clic per iniciar sessió de nou amb aquell compte directament al panell, o inicia-hi una sessió, que actualitza l'inici de sessió per si sola. Els servidors MCP que tenies quan es va afegir un compte l'acompanyen, però els que afegeixis després amb `claude mcp add` només arriben al compte en què els has afegit. Claude Desktop i les eines configurades amb un camí absolut a un binari de CLI no segueixen el canvi. Un `CLAUDE_CONFIG_DIR`, `CODEX_HOME` o `GROK_HOME` explícit té prioritat sobre el compte seleccionat.

### Diagnòstic d'errors

Omarchy vigila systemd-coredump per detectar errors de processos. Quan alguna cosa fa un segfault, rebràs una notificació "Process crashed": fes-hi clic i l'error es passa al teu agent predeterminat juntament amb l'habilitat diagnose-crash d'Omarchy, que guia l'agent per establir els fets a partir del bolcat de memòria i decidir si val la pena informar de l'error al projecte original. També el pots executar manualment contra qualsevol PID de `coredumpctl list` amb `omarchy agent crash <pid>`.

La vigilància està activada per defecte. Desactiva-la a _Trigger > Toggle > Crash Capture_ (o amb `omarchy toggle crash-capture`) i les notificacions s'aturaran; `omarchy agent crash <pid>` continua funcionant manualment.

Els errors també es poden silenciar programa a programa, que és el que t'ofereix el diagnòstic al final. `omarchy crash mute hyprland` atura les notificacions només per a aquell programa, `omarchy crash mute hyprland off` les restableix, i `omarchy crash mute` per si sol enumera el que has silenciat. Accepta el camí del binari amb la mateixa facilitat que el seu nom, de manera que `omarchy crash mute /usr/bin/hyprland` fa el mateix. Posa entre cometes un nom que contingui un espai, com a `omarchy crash mute 'Some App'`. Tota la resta continua notificant, i el programa silenciat continua fallant: això amaga l'avís, no soluciona res.

### Aplicacions d'escriptori

El menú _Install > AI_ també inclou unes quantes aplicacions gràfiques d'IA: l'aplicació d'escriptori de ChatGPT, l'aplicació d'escriptori de Claude (la beta per a Linux d'Anthropic, amb pestanyes Chat, Cowork i Claude Code), Grok Bot per xatejar amb els models de xAI, Herdr Desktop, Hermes Desktop, OpenClaw, l'aplicació d'escriptori de Perplexity i T3 Code. Grok Bot és l'aplicació de xat d'escriptori. L'agent de programació és l'ordre `grok`.

Hermes Desktop és la que cal conèixer, perquè una màquina té un sol Hermes, i és el de l'aplicació: Hermes només s'instal·la mai a través de l'aplicació, i l'ordre `hermes` que executa l'agent predeterminat és la de l'aplicació. Triar Hermes com a agent predeterminat instal·la el mateix que instal·la l'entrada _Install > AI_: el paquet i un entorn d'execució d'Hermes a `~/.hermes` configurat per l'instal·lador propi d'Hermes, que triga uns minuts el primer cop. Aquest entorn d'execució és l'únic Hermes que utilitzen l'ordre `hermes` del terminal, l'agent predeterminat i l'aplicació, i s'actualitza per si mateix amb `hermes update` en lloc d'esperar una versió d'Omarchy. Instal·lar-lo també dona a Hermes el tema d'Omarchy com una aparença anomenada `omarchy`, que totes les superfícies d'Hermes segueixen quan canvies de tema; tria'n una altra a la configuració Appearance d'Hermes o amb `/skin` si prefereixes que no ho faci, i Omarchy respectarà aquesta tria. Eliminar l'aplicació a _Remove > AI_ tanca primer Hermes, passarel·la inclosa, s'endú aquell entorn d'execució i conserva els teus xats, les memòries i les habilitats que Hermes ha escrit per a si mateix, llevat que li diguis el contrari: pregunta, amb no com a resposta predeterminada, si aquestes dades i la teva configuració de connexió també s'han d'eliminar.

L'experiència d'escriptori d'OpenClaw és la seva Control UI, que s'obre com una aplicació web recolzada per la seva pròpia passarel·la local. OpenClaw viu a `~/.openclaw` i s'actualitza per si mateix: utilitza el botó "Update Gateway" de la Control UI o executa `openclaw update`, i la passarel·la es reinicia amb la versió nova. Omarchy només tria la versió amb la qual comença una instal·lació nova. Eliminar OpenClaw a _Remove > AI_ s'endú el servei de passarel·la i l'aplicació i després pregunta si `~/.openclaw` també s'ha d'eliminar, ja que allà hi ha els teus xats i les credencials juntament amb el mateix OpenClaw i els entorns d'execució de complements que descarrega; per defecte es conserva, i tornar a instal·lar OpenClaw el recupera.

Herdr Desktop és l'aplicació d'escriptori [Herdr](https://herdr.dev): espais, pestanyes i subfinestres de terminals i agents de programació que continuen funcionant al seu nucli quan tanques la finestra. Ve de l'instal·lador propi de Herdr en lloc d'un paquet, de manera que viu a `~/.local/share/herdr-app`, porta el seu nucli a `~/.local/bin/herdr-core` quan encara no en tens cap, i actualitza tots dos. Se situa al costat de l'ordre `herdr` que Omarchy proporciona a `Super + Ctrl + Return`, en lloc de substituir-la. Instal·lar-lo tria el tema Omarchy de Herdr, que a partir d'aleshores segueix el teu tema d'Omarchy. Herdr conserva un tema per al mode clar i un per al fosc, de manera que, després de canviar entre un tema fosc i un de clar d'Omarchy, tria Omarchy al selector de temes de Herdr un cop més per a l'altre mode.

T3 Code s'executa des de la seva versió oficial AppImage a `~/.local/share/t3code` en lloc de des d'un paquet, de manera que s'actualitza per si mateix. Instal·lar-lo pregunta si vols començar al canal Stable o Nightly; canvia-ho després a la configuració de T3 Code. Els teus fils i la teva configuració viuen a `~/.t3`, i eliminar T3 Code a _Remove > AI_ se'ls endú.

### Models locals

Executa un model obert a la teva pròpia màquina per als teus agents de programació. Les teves instruccions i el teu codi romanen a la màquina; res del que s'envia al model no en surt. Comença amb:

```bash
omarchy agent local use best
```

O, al panell d'agents de la barra superior, tria + i després Local AI, que apareix quan un model cap en aquesta màquina. El primer cop, això instal·la Podman, que executa els models, i en una màquina NVIDIA el kit d'eines de contenidors de NVIDIA, que els dona accés a la GPU. Aleshores Omarchy tria el model recomanat per a aquesta màquina, el descarrega i l'inicia. Espera't una descàrrega de desenes de GB i que la major part de la memòria de la màquina estigui en ús mentre el model s'executa: Flash Next utilitza uns 100 GiB amb el seu context complet de 256K. Si altres models ocupen la memòria que necessita, es configura aturat, a punt per iniciar-se un cop n'aturis un. El model s'atura en tancar la sessió; atura'l tu mateix quan necessitis la memòria per a una altra cosa.

`omarchy agent local list` mostra les opcions i explica per què algunes no hi caben. Per configurar-ne un altre, executa `omarchy agent local use <recipe>`. Avui, `qwen3.8-flash-next-gufo` i `qwen3.8-27b-gufo` estan disponibles per a màquines Strix Halo de 128 GB; el de 27B ocupa uns 40 GiB, de manera que deixa espai per a altres feines. Les receptes i recomanacions noves arriben amb `omarchy update`, a través del paquet.

Cada model que configuris té la seva pròpia línia al panell d'agents, al costat de les teves subscripcions: reproducció per iniciar-lo, pausa per aturar-lo i alliberar la seva memòria, i el botó de terminal per obrir el teu agent en ell. Diversos poden funcionar alhora quan caben junts a la memòria; si un no hi cap, Omarchy diu quin model en execució has d'aturar. Arrossega les línies per reordenar-les i prem Delete en una línia seleccionada per eliminar un model i la seva descàrrega.

Des de la línia d'ordres, `omarchy agent local start <recipe>` i `omarchy agent local stop <recipe>` fan el mateix, `omarchy agent local status` mostra tots els models, i `omarchy agent --local` obre el teu agent predeterminat en l'últim model que has iniciat (pi si el teu agent predeterminat no pot utilitzar un model local). Qualsevol client compatible amb OpenAI també s'hi pot connectar: `status` mostra l'adreça de cada model (la primera és `http://127.0.0.1:11435/v1`), el nom de la recepta és el model, i la clau és a `~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` elimina un model i les descàrregues que cap altre model no utilitza.

Els entorns d'execució de tercers estan etiquetats amb el seu editor. Omarchy executa tots els models sense accés a la xarxa.

### LLM locals

Omarchy recomana dues maneres d'executar models LLM locals: LM Studio i Ollama. LM Studio proporciona una interfície GUI per trobar models de pesos oberts, instal·lar-los i executar-los. És una manera excel·lent de començar fàcilment. Ollama ofereix un CLI per fer-ho de manera similar. Però si ets nou en els models locals, jo començaria amb LM Studio. Pots instal·lar qualsevol dels dos a _Install > AI_ al Menú d'Omarchy.

### L'habilitat d'Omarchy

Les habilitats d'agent ajuden la IA a utilitzar eines específiques d'una manera específica, i Omarchy inclou una habilitat predeterminada per adaptar el sistema a mida. Com ara retocar la configuració de Hyprland, ajustar la barra o fins i tot crear un tema nou des de zero. Està enllaçada simbòlicament als directoris d'habilitats de Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` i cada `~/.hermes/profiles/*/skills`), i a la ubicació genèrica `~/.agents/skills`, de manera que la majoria de harness la recullen automàticament.

Però hauries de tractar aquesta habilitat com a experimental. Models diferents la utilitzaran amb efectes diferents. És millor executar primer en mode de planificació, perquè tinguis una idea del que l'agent voldria canviar. I després estigues preparat per revertir els canvis o fins i tot per invocar `omarchy reinstall configs`, si l'agent ho embolica tot.
