### Instal·lació i actualització dels agents

Excepte Hermes, aquests agents fan servir la instal·lació diferida de mise: el primer llançament instal·la la CLI, i els llançaments posteriors la reutilitzen. mise també comprova si hi ha una nova versió d'un agent instal·lat com a molt un cop cada quatre hores, just abans que s'iniciï o en segon pla en un indicador de l'intèrpret d'ordres. Si aquesta actualització falla o no tens connexió, s'executa la versió instal·lada. `omarchy update` actualitza els agents instal·lats amb la resta d'Omarchy, i `mup` actualitza només les eines gestionades per mise.

L'actualitzador propi d'un agent, com ara `claude update`, `codex update` o un botó d'actualització en una aplicació, no actualitza la instal·lació gestionada per mise. `codex update` falla, i `claude update` pot dir que ha tingut èxit mentre instal·la una còpia separada que mise no controla. Si prefereixes fer servir l'instal·lador i l'actualitzador natius d'un agent, afegeix-lo a `disable_tools`; vegeu [Eines de CLI preinstal·lades](18-development-tools.md#preinstalled-cli-tools).

Per instal·lar totes les eines diferides configurades abans que les necessitis, executa `mise install --include-lazy`. Això inclou les altres eines de CLI predeterminades d'Omarchy, a més dels agents. Vegeu [Eines de CLI preinstal·lades](18-development-tools.md#preinstalled-cli-tools) per instal·lar una sola eina o fer servir la teva pròpia instal·lació.

`grok` s'instal·la mitjançant el paquet de primera mà `grok` de mise, de la mateixa manera que `claude` i `codex`. Executa `grok`, o tria'l a _Agent > Harness_. Omet l'instal·lador `curl | bash` de x.ai. Aquesta via posa una segona còpia a `~/.grok/bin`, la posa al davant a `PATH` i sobreescriu l'embolcall d'Omarchy.

`dsh` obre la seva interfície de navegador a `127.0.0.1:3080`, amb el directori de llançament com a espai de treball predeterminat. La seva interfície de navegador no accepta cap missatge inicial, de manera que `omarchy agent prompt` l'obre amb el missatge al porta-retalls perquè l'enganxis. Omarchy l'inicia amb la configuració de permisos sense aprovació de DeepSeek. DeepSeek Harness puja els registres de sessió a DeepSeek quan fas servir la seva API oficial de models; desactiva-ho a _Settings > General > Upload Session Log_ a la seva interfície de navegador. Els comentaris que li enviïs també es pugen amb la sessió, llevat que l'iniciïs amb `DSH_TELEMETRY_MODE=DISABLED`.

### L'agent predeterminat

Tria el teu agent predeterminat amb `omarchy default agent <name>` o a _Agent > Harness_ al menú d'Omarchy (`Super + Space`). Si l'agent encara no està instal·lat, triar-lo l'instal·la primer. Un Omarchy acabat d'instal·lar t'invitarà a fer aquesta tria amb una notificació única.

Triar Claude també intenta configurar la seva extensió de navegador per a Chromium, Chrome, Brave, Brave Origin i Edge. La configuració de l'extensió s'aplica a tots els usuaris i pot demanar-te la contrasenya del sistema; cancel·lar-la o que la instal·lació de l'extensió falli no impedeix que Claude quedi seleccionat i s'iniciï. Reinicia el navegador, activa l'extensió si t'ho demana i inicia sessió a Claude per acabar de connectar-la. Executa `/chrome` a Claude per comprovar la connexió. Firefox i Zen no admeten aquesta extensió. Si Claude ja era el teu predeterminat abans que s'afegís aquesta configuració, torna'l a seleccionar per instal·lar l'extensió.

Un cop hagis triat, `Super + Shift + Ctrl + A` inicia l'agent predeterminat en una finestra de terminal dedicada (o obre el selector si encara no n'has triat cap). També el pots iniciar directament amb una tasca amb `omarchy agent prompt "Review this project"`. Freebuff i DeepSeek Harness no accepten cap missatge inicial, de manera que s'obren amb el missatge al porta-retalls perquè l'enganxis. Els agents iniciats d'aquesta manera funcionen sense supervisió en els seus respectius modes de no aturar-se a demanar, així que prepara't perquè realment facin coses! MiniMax Code no té un mode així per a les seves sessions interactives, de manera que demana permisos com de costum. I com que els agents es neguen a recordar la confiança per al teu directori d'inici, els llançaments des de `$HOME` s'inicien a `~/Work`.

També hi ha dreceres de terminal: `a` executa l'agent predeterminat en línia al terminal actual, mentre que `c`, `cx` i `cy` inicien OpenCode, Claude Code i Codex directament (també en els seus modes d'aprovació automàtica). Els canvis de tema també es sincronitzen amb els agents: Claude Code, Pi, OpenCode i Hermes (un cop Omarchy l'ha instal·lat) segueixen el canvi quan canvies el tema d'Omarchy.

### Les instruccions del teu agent

Les regles personals per a cada agent van a `~/.agents/AGENTS.md`, al costat de les habilitats compartides a `~/.agents/skills`. Obre'l a _Agent > Instructions_, que també l'enllaça a cada harness que manté el seu propi fitxer global: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, el `~/.copilot/copilot-instructions.md` de Copilot, etc. Crush i Amp llegeixen l'enllaç `~/.config/AGENTS.md`, mentre que omp, Kimi i DeepSeek Harness llegeixen `~/.agents/AGENTS.md` directament. Triar un agent predeterminat també l'enllaça. Un fitxer d'instruccions que ja tenies es converteix en el compartit si encara no n'hi havia cap; en cas contrari, es conserva al costat de l'enllaç com a `.bak`. Executa `omarchy agent instructions` per tornar a enllaçar després d'instal·lar un altre agent.

### El tauler d'agents

La barra superior té una icona d'agents. Abans que hagis configurat un agent, el seu tauler et guia per iniciar sessió a Claude, Codex o Grok, i el primer es converteix en el teu agent predeterminat. Després, el tauler posa cada subscripció en una sola pàgina: cada agent i compte amb el seu pla, un mesurador per a cadascun dels seus límits de sessió de 5 hores i setmanal amb el temps que falta perquè es restableixi (passa-hi el cursor per sobre per veure el percentatge exacte), o el saldo prepagat restant, sota una línia que va rotant per allò que has fet servir entre tots ells, com ara els tokens d'aquesta setmana i el teu model més utilitzat. A _Make something_ ofereix missatges inicials per a un nou tema, connector o aplicació que passen la tasca al teu agent predeterminat. Les aplicacions es construeixen de la manera com es fan les mateixes Hype, Monologue i Omacut d'Omarchy, en C++ i Qt Quick, seguint l'habilitat d'agent omarchy-app, i el compilador i les peces de Qt que necessiten ja venen instal·lats. Claude Code, Codex, Grok, Kimi, Cursor i la seva assignació de Grok Bot, GitHub Copilot, Muse, Antigravity, Kimchi i Devin estan coberts de fàbrica amb els seus límits, i Hermes, Mistral Vibe i Qwen Code mostren les seves sessions i tokens un cop els has fet servir. Els plans i les claus de proveïdors que facis servir mitjançant pi, omp o opencode també hi apareixen: OpenCode Zen i Go, el Z.ai GLM Coding Plan, Ollama Cloud, el MiniMax Token Plan i Synthetic amb els seus límits; Fireworks, OpenRouter i DeepSeek amb els seus saldos prepagats; i els models que executes amb el teu propi maquinari a Local models. Cada agent es compta un sol cop, a nom de qui el facturi, independentment de quants harnesses facis servir per conduir-lo.

Fes clic amb el botó esquerre a la icona de la barra per obrir el tauler, fes clic amb el botó dret per iniciar el teu agent predeterminat. Els registres d'ús que hi ha al darrere es regeneren cada 15 minuts amb `omarchy agent usage-update`, i el tauler pot fins i tot fusionar l'ús de les teves altres màquines mitjançant una carpeta sincronitzada. Consulta el README a `$OMARCHY_PATH/shell/plugins/agents/` per a tota la configuració.

### Diverses subscripcions

Si pagues més d'un pla de Claude, Codex o Grok — un Max personal i un de feina, per exemple — Omarchy pot mantenir-los tots amb la sessió iniciada i moure's entre ells. Afegeix una subscripció amb el + al tauler d'agents, que et guia allà mateix, o amb `omarchy agent account add claude Work` (o `codex`, o `grok`). Instal·la la CLI si falta. El primer compte d'un proveïdor inicia sessió mitjançant el teu navegador normal, allà on la CLI sempre mira. Cadascun dels següents inicia sessió mitjançant una finestra privada, de manera que el compte amb el qual el teu navegador ja ha iniciat sessió no sigui recollit per error; inicia-hi sessió com el compte que estàs afegint, i tanca primer qualsevol finestra privada que ja tinguessis oberta. No tanquis mai la sessió de la CLI per fer això: tancar la sessió revoca l'inici de sessió desat, i aquest compte s'hauria d'afegir de nou.

Per copiar els teus inicis de sessió de subscripció a una altra màquina Omarchy per SSH, executa `omarchy agent account copy user@laptop`. L'emissor proporciona un receptor temporal quan la destinació no en té cap d'instal·lat, de manera que les màquines Omarchy més antigues poden rebre comptes sense una actualització. Els receptors instal·lats tenen prioritat. Això copia totes les subscripcions de Claude, Codex i Grok; afegeix noms de proveïdors per seleccionar-les, com a `omarchy agent account copy laptop claude`. Els noms de compte i els ID d'ordre coincideixen amb els de l'origen, inclosos els comptes ja presents a la destinació. Els comptes de destinació no relacionats reben un sufix numèric si els seus noms entren en conflicte, i la configuració, les habilitats, els connectors i l'historial de converses es queden locals a cada màquina.

Les credencials de destinació existents es conserven. Un compte d'origen que ja té la sessió iniciada allà hi veu sincronitzat el seu nom sense substituir-ne les credencials; els altres comptes s'hi afegeixen al costat. Per substituir les credencials desades dels comptes coincidents, fes servir `omarchy agent account copy --replace laptop claude` després de sortir de les sessions d'aquest compte a la destinació. Una destinació nova també rep el compte actiu i les preferències de canvi de l'origen; una destinació ja establerta conserva els seus.

Les credencials viatgen per SSH i es desen en fitxers privats a la destinació, així que copia-les només a màquines en què confiïs. Això és una còpia única, no una sincronització contínua. Els tokens d'actualització de Codex poden ser rotats per una altra màquina, i això deixaria un inici de sessió copiat amb necessitat de renovació; els inicis de sessió separats continuen sent l'opció més fiable per a un ús simultani en diverses màquines. Vegeu [guia d'autenticació de comptes de Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Un compte per proveïdor està actiu, i cada sessió nova comença com a tal: `cx`, `cy`, un `claude`, `codex` o `grok` simple, qualsevol cosa iniciada mitjançant `omarchy agent`, i els scripts o editors que trobin la CLI a `PATH`. Canvia amb `omarchy agent account use work` (i torna amb `omarchy agent account use main`), o al tauler prement el número d'un compte i després `Enter` (o fent clic al seu botó Use). Les sessions que ja estan en marxa es queden amb el compte amb el qual van començar. L'historial de converses, la configuració, les habilitats i els connectors es comparteixen entre comptes, de manera que `claude --continue` a la mateixa carpeta reprèn on ho vas deixar amb el compte nou.

Amb més d'un compte, el tauler mostra els límits de cada compte l'un al costat de l'altre, amb l'actiu marcat. Per defecte, Omarchy t'avisa quan el compte actiu supera el 95% d'un límit, i fer clic a la notificació canvia al compte amb més marge. Passa el cursor per sobre de la línia d'un compte al tauler i fes clic a Autoswitch que apareix al costat de Use (o prem `m`), o executa `omarchy agent account mode auto`, perquè canviï per si sol; mentre està activat, Autoswitch ocupa el lloc de Use, i tornar-hi a fer clic torna a avisar. Afegeix un número per canviar el llindar, com a `omarchy agent account mode auto 90`. Si tots els comptes superen el llindar, t'ho farà saber un sol cop, juntament amb quin compte es libera primer. Mentre un compte actiu estigui a 15 punts del seu llindar (80% amb el valor per defecte), els seus límits es comproven cada tres minuts en lloc de cada 15.

`omarchy agent account list` mostra cada compte i els seus límits més recents, `omarchy agent account remove work` n'oblida un i `omarchy agent account rename primary Hey` en reanomena un (o fes clic al nom d'un compte al tauler). Aquestes ordres funcionen amb els comptes del teu agent predeterminat; per arribar a l'altre proveïdor, anomena'l primer, com a `omarchy agent account use codex side`. L'inici de sessió que ja tenies a `~/.claude` o `~/.codex` és el compte _Main_ i es queda on és. Un compte que no s'ha fet servir durant més d'unes vuit hores pot mostrar _Sign-in required_; fes-hi clic per iniciar sessió amb aquest compte de nou allà mateix al tauler, o inicia una sessió amb ell, que actualitza l'inici de sessió per si sol. Els servidors MCP que tenies quan es va afegir un compte l'acompanyen, però els que afegeixis més endavant amb `claude mcp add` només arriben al compte en què els vas afegir. Claude Desktop i les eines configurades amb un camí absolut a un binari de CLI no segueixen el canvi. Un `CLAUDE_CONFIG_DIR`, `CODEX_HOME` o `GROK_HOME` explícit té prioritat sobre el compte seleccionat.

### Diagnòstic de fallades

Omarchy vigila systemd-coredump per detectar fallades de processos. Quan alguna cosa fa un segfault, rebràs una notificació "Process crashed" — fes-hi clic i la fallada es passa al teu agent predeterminat juntament amb l'habilitat diagnose-crash d'Omarchy, que guia l'agent per establir els fets a partir del bolcat de memòria i decidir si val la pena informar de la fallada amunt. També la pots executar manualment contra qualsevol PID de `coredumpctl list` amb `omarchy agent crash <pid>`.

La vigilància està activada per defecte. Desactiva-la a _Trigger > Toggle > Crash Capture_ (o amb `omarchy toggle crash-capture`) i les notificacions s'aturaran; `omarchy agent crash <pid>` continuarà funcionant manualment.

Les fallades també es poden silenciar programa a programa, que és el que el diagnòstic t'ofereix al final. `omarchy crash mute hyprland` atura les notificacions només per a aquest programa, `omarchy crash mute hyprland off` les torna a activar i `omarchy crash mute` sol llista allò que has silenciat. Accepta el camí del binari tan bé com el seu nom, de manera que `omarchy crash mute /usr/bin/hyprland` fa el mateix. Posa entre cometes un nom amb un espai, com a `omarchy crash mute 'Some App'`. Tota la resta continua avisant, i el programa silenciat continua fallant — això amaga el recordatori, no arregla res.

### Aplicacions d'escriptori

El menú _Install > AI_ també porta unes quantes aplicacions gràfiques d'IA: l'aplicació d'escriptori de ChatGPT, l'aplicació d'escriptori de Claude (la beta de Linux d'Anthropic, amb pestanyes Chat, Cowork i Claude Code), Grok Bot per xatejar amb els models de xAI, Herdr Desktop, Hermes Desktop, OpenClaw, l'aplicació d'escriptori de Perplexity i T3 Code. Grok Bot és l'aplicació de xat d'escriptori. L'agent de programació és l'ordre `grok`.

Hermes Desktop és la que cal conèixer, perquè una màquina té un sol Hermes, i és el de l'aplicació: Hermes només s'instal·la mai mitjançant l'aplicació, i l'ordre `hermes` que executa l'agent predeterminat és la de l'aplicació. Triar Hermes com a agent predeterminat instal·la el mateix que instal·la l'entrada _Install > AI_: el paquet, i un entorn d'execució de Hermes a `~/.hermes` configurat per l'instal·lador propi de Hermes, que triga uns minuts la primera vegada. Aquest entorn d'execució és l'únic Hermes que fan servir l'ordre de terminal `hermes`, l'agent predeterminat i l'aplicació, i s'actualitza per si sol amb `hermes update` en lloc d'esperar una versió d'Omarchy. Instal·lar-lo també dona a Hermes el tema d'Omarchy com una aparença anomenada `omarchy`, que cada superfície de Hermes segueix quan canvies de tema; tria'n una altra a la configuració Appearance de Hermes o amb `/skin` si prefereixes que no ho faci, i Omarchy deixarà aquesta tria tranquil·la. Eliminar l'aplicació a _Remove > AI_ tanca primer Hermes, passarel·la inclosa, s'endú aquest entorn d'execució amb ella i conserva els teus xats, memòries i les habilitats que Hermes va escriure per a si mateix, llevat que li diguis el contrari: et pregunta, amb no per defecte, si aquestes dades i la teva configuració de connexió també haurien de desaparèixer.

L'experiència d'escriptori d'OpenClaw és la seva Control UI, que s'obre com una aplicació web recolzada per la seva pròpia passarel·la local. OpenClaw viu a `~/.openclaw` i s'actualitza per si sol: fes servir el botó "Update Gateway" de la Control UI o executa `openclaw update`, i la passarel·la es reinicia amb la versió nova. Omarchy només tria la versió amb què comença una instal·lació nova. Eliminar OpenClaw a _Remove > AI_ s'endú el servei de passarel·la i l'aplicació amb ell i després pregunta si `~/.openclaw` també hauria de desaparèixer, ja que això conté els teus xats i credencials al costat del mateix OpenClaw i els entorns d'execució de connectors que descarrega; per defecte es conserva, i tornar a instal·lar OpenClaw el recupera.

Herdr Desktop és l'aplicació d'escriptori de [Herdr](https://herdr.dev): espais, pestanyes i subfinestres de terminals i agents de programació que continuen funcionant en el seu nucli quan tanques la finestra. Ve de l'instal·lador propi de Herdr en lloc d'un paquet, de manera que viu a `~/.local/share/herdr-app`, porta el seu nucli a `~/.local/bin/herdr-core` quan encara no en tens cap, i actualitza tots dos per si sol. Se situa al costat de l'ordre `herdr` que Omarchy porta a `Super + Ctrl + Return` en lloc de substituir-la, i rep les tecles directes d'aquesta ordre: `Alt + Return` i `Alt + Shift + Return` divideixen una subfinestra cap avall o cap a la dreta, `Alt + Escape` la tanca, `Ctrl + Alt + Arrow` es mou entre subfinestres, `Alt + 1..9` i `Alt + Left/Right` trien una pestanya, i `Alt + Up/Down` es mouen entre espais. `Ctrl + 1..9` tria un espai i `Alt + Shift + Up/Down` recorre els agents. Les tecles amb prefix `Ctrl + Space` es queden només per al terminal, ja que l'aplicació no pot mantenir una tecla Ctrl simple per a una seqüència. Omarchy escriu això a `~/.config/herdr-app/keys.json`, i `omarchy-refresh-herdr-app` ho torna a posar. Instal·lar-lo tria el tema Omarchy de Herdr, que a partir d'aleshores segueix el teu tema d'Omarchy. Herdr manté un tema per al mode clar i un per al mode fosc, de manera que, després de canviar entre un tema fosc i un de clar d'Omarchy, torna a triar Omarchy al selector de temes de Herdr una vegada més per a l'altre mode.

T3 Code s'executa des de la seva versió oficial en AppImage a `~/.local/share/t3code` en lloc de des d'un paquet, de manera que s'actualitza per si sol. Instal·lar-lo pregunta si vols començar al canal Stable o Nightly; canvia-ho més endavant a la configuració de T3 Code. Els teus fils i la teva configuració viuen a `~/.t3`, i eliminar T3 Code a _Remove > AI_ se'ls endú amb ell.

### Models locals

Executa un model obert a la teva pròpia màquina per als teus agents de programació. Els teus missatges i el teu codi es queden a la màquina; res del que s'envia al model en surt. Comença amb:

```bash
omarchy agent local use best
```

O, al tauler d'agents de la barra superior, tria + i després Local AI, que apareix quan un model cap en aquesta màquina. La primera vegada, això instal·la Podman, que executa els models, i en una màquina NVIDIA el conjunt d'eines de contenidors de NVIDIA, que els dona la GPU. Després Omarchy tria el model recomanat per a aquesta màquina, el descarrega i l'inicia. Espera una descàrrega de desenes de GB i que la major part de la memòria de la màquina estigui en ús mentre el model s'executa: Flash Next fa servir uns 100 GiB amb el seu context complet de 256K. Si altres models ocupen la memòria que necessita, queda configurat aturat, llest per iniciar-se un cop n'aturis un. El model s'atura en tancar la sessió; atura'l tu mateix quan necessitis la memòria per a una altra cosa.

`omarchy agent local list` mostra les opcions i explica per què algunes no hi caben. Per configurar-ne un altre, executa `omarchy agent local use <recipe>`. Avui, `qwen3.8-flash-next-gufo` i `qwen3.8-27b-gufo` estan disponibles per a màquines Strix Halo de 128 GB; el de 27B ocupa uns 40 GiB, de manera que deixa espai per a una altra feina. Les receptes i recomanacions noves arriben amb `omarchy update`, mitjançant el paquet.

Cada model que configuris rep la seva pròpia línia al tauler d'agents, al costat de les teves subscripcions: reproduir per iniciar-lo, pausar per aturar-lo i alliberar-ne la memòria, i el botó de terminal per obrir el teu agent amb ell. Se'n poden executar diversos alhora quan caben junts a la memòria; si un no hi cap, Omarchy diu quin model en execució cal aturar. Arrossega les línies per reordenar-les i prem Delete en una línia seleccionada per eliminar un model i la seva descàrrega.

Des de la línia d'ordres, `omarchy agent local start <recipe>` i `omarchy agent local stop <recipe>` fan el mateix, `omarchy agent local status` mostra cada model, i `omarchy agent --local` obre el teu agent predeterminat amb l'últim model que vas iniciar. pi, OpenCode i Qwen Code en poden fer servir un; amb qualsevol altre predeterminat s'obre a pi. pi també llista cada model que has configurat, i els de les màquines amb què t'has aparellat, al seu propi selector de models, de manera que un `pi` simple també els pot arribar. Qualsevol client compatible amb OpenAI també s'hi pot connectar: `status` mostra l'adreça de cada model (la primera és `http://127.0.0.1:11435/v1`), el nom de la recepta és el model, i la clau és a `~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` elimina un model i les descàrregues que cap altre model fa servir.

Els entorns d'execució de tercers estan etiquetats amb el seu editor. Omarchy executa cada model sense accés a la xarxa.

### LLM locals

Omarchy recomana dues maneres d'executar models LLM locals: LM Studio i Ollama. LM Studio proporciona una interfície gràfica per trobar models de pesos oberts, instal·lar-los i executar-los. És una manera excel·lent de començar fàcilment. Ollama ofereix una CLI per fer una cosa semblant. Però si ets nou amb els models locals, jo començaria amb LM Studio. Pots instal·lar-ne qualsevol dels dos a _Install > AI_ al menú d'Omarchy.

### L'habilitat d'Omarchy

Les habilitats d'agent ajuden la IA a fer servir eines específiques d'una manera específica, i Omarchy porta de fàbrica una habilitat predeterminada per adaptar el sistema. Com ara retocar la teva configuració de Hyprland, ajustar la barra, o fins i tot crear un tema nou des de zero. Està enllaçada simbòlicament als directoris d'habilitats de Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` i cada `~/.hermes/profiles/*/skills`), i la ubicació genèrica `~/.agents/skills`, de manera que la majoria de harnesses la recullen automàticament.

Però hauries de tractar aquesta habilitat com a experimental. Models diferents la faran servir amb efectes diferents. És millor executar-la primer en mode de planificació, perquè tinguis una idea del que l'agent voldria canviar. I després prepara't per revertir els canvis o fins i tot invocar `omarchy reinstall configs`, si l'agent ho embolica tot.
