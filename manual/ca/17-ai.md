Omarchy inclou llançadors per als agents de programació següents sense triar-ne un de predeterminat per a tu. Instal·la'n un des de _Instal·la > AI > CLI_, i després autentica't quan se't demani. Hermes i OpenClaw són les excepcions: triar qualsevol dels dos configura la seva pròpia còpia que s'actualitza sola, tal com explica _Aplicacions d'escriptori_ més avall.

### Instal·lació i actualització d'agents

Excepte Hermes i OpenClaw, cada agent és un paquet del repositori propi d'Omarchy. Instal·la'n un des de _Instal·la > AI > CLI_ o amb `omarchy install ai cli <command>`, i elimina'l de nou des de _Elimina > AI > CLI_, cosa que manté intactes les seves sessions iniciades i el seu historial. Triar un agent que encara no està instal·lat també l'instal·la: marcar-lo amb una estrella al panell d'agents, triar-lo amb `omarchy default agent <name>` o iniciar sessió a la seva subscripció. Omarchy publica cada nova versió d'un agent en menys d'una hora, a tots els canals, i `omarchy update` l'instal·la amb la resta del sistema.

Com que pacman els manté actualitzats, els actualitzadors propis dels agents estan desactivats: `claude update` o un botó d'actualització en una app no té res a fer. Si prefereixes executar un agent des del seu propi instal·lador, utilitza'l i deixa el paquet d'Omarchy sense instal·lar; una còpia que ja sigui al teu `PATH` compta com a instal·lada. Evita els instal·ladors `curl | bash` que posen una segona còpia per davant de la d'Omarchy al `PATH`, com el de x.ai per a `grok`.

`dsh` obre la seva interfície d'usuari al navegador a `127.0.0.1:3080`, amb el directori d'inici com a espai de treball predeterminat. La seva interfície al navegador no admet cap prompt inicial, de manera que `omarchy agent prompt` l'obre amb el prompt al porta-retalls perquè l'enganxis. Omarchy l'inicia amb el conjunt de permisos sense aprovació de DeepSeek. DeepSeek Harness puja els registres de sessió a DeepSeek quan utilitzes la seva API oficial de models; desactiva-ho a _Settings > General > Upload Session Log_ a la seva interfície al navegador. Els comentaris que li enviïs també es pugen amb la sessió, tret que l'iniciïs amb `DSH_TELEMETRY_MODE=DISABLED`.

### L'agent predeterminat

Tria el teu agent predeterminat amb l'estrella que hi ha al costat d'un agent al panell d'agents, que apareix plena en el predeterminat, o amb `omarchy default agent <name>`, que també accepta qualsevol harness que no tingui una línia allà. Si l'agent encara no està instal·lat, triar-lo l'instal·la primer, i també rep un llançador propi al llançador d'aplicacions, al costat d'Agent. Un Omarchy acabat d'instal·lar t'invita a configurar-ne un amb una notificació única, que obre el panell d'agents.

Triar Claude també intenta configurar la seva extensió de navegador per a Chromium, Chrome, Brave, Brave Origin i Edge. La configuració de l'extensió s'aplica a tots els usuaris i pot demanar-te la contrasenya del sistema; cancel·lar-la o que la instal·lació de l'extensió falli no impedeix que Claude quedi seleccionat i es llanci. Reinicia el navegador, activa l'extensió si se't demana i inicia sessió a Claude per acabar de connectar-lo. Executa `/chrome` a Claude per comprovar la connexió. Firefox i Zen no admeten aquesta extensió. Si Claude ja era el teu agent predeterminat abans que s'afegís aquesta configuració, torna a seleccionar-lo per instal·lar l'extensió.

Un cop l'hagis triat, `Super + Shift + Ctrl + A` llança l'agent predeterminat en una finestra de terminal dedicada (o obre el selector si encara no n'has triat cap). També el pots llançar directament en una tasca amb `omarchy agent prompt "Review this project"`. Freebuff i DeepSeek Harness no admeten cap prompt inicial, de manera que s'obren amb el prompt al porta-retalls perquè l'enganxis. Els agents llançats d'aquesta manera funcionen sense supervisió en els seus respectius modes de no aturar-se a demanar, així que estigues preparat perquè realment facin coses! MiniMax Code no té un mode així per a les seves sessions interactives, de manera que demana permisos com de costum. I com que els agents es neguen a recordar la confiança per al teu directori personal, els llançaments des de `$HOME` comencen a `~/Work`.

També hi ha dreceres de terminal: `a` executa l'agent predeterminat en línia al terminal actual, mentre que `c`, `cx`, `cy` i `ca` inicien OpenCode, Claude Code, Codex i Antigravity directament (de nou en els seus modes d'aprovació automàtica). Els canvis de tema també se sincronitzen amb els agents: Claude Code, Pi, OpenCode i Hermes (un cop Omarchy l'hagi instal·lat) segueixen el canvi quan canvies el tema d'Omarchy.

### Les instruccions del teu agent

Les regles personals per a cada agent van a `~/.agents/AGENTS.md`, al costat de les skills compartides a `~/.agents/skills`. Obre'l amb la icona de document que hi ha al costat del + al panell d'agents, o `omarchy agent instructions --edit`, que també l'enllaça a cada harness que manté el seu propi fitxer global: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, el `~/.copilot/copilot-instructions.md` de Copilot, i així successivament. Crush i Amp llegeixen l'enllaç `~/.config/AGENTS.md`, mentre que omp, Kimi i DeepSeek Harness llegeixen `~/.agents/AGENTS.md` directament. Triar un agent predeterminat també l'enllaça. Un fitxer d'instruccions que ja tenies es converteix en el compartit si encara no n'hi havia cap; en cas contrari, es manté al costat de l'enllaç com a `.bak`. Executa `omarchy agent instructions` per tornar a enllaçar-lo després d'instal·lar un altre agent.

### El panell d'agents

La barra superior té una icona d'agents. Abans d'haver configurat un agent, el seu panell ofereix tres maneres de començar: iniciar sessió a una subscripció de Claude, Codex, Grok, Gemini, Muse, Cursor o Copilot, o, a _More_, un pla de programació d'OpenCode Go, MiniMax, Synthetic o Z.ai; pagar per ús amb Fireworks, OpenCode Zen and Go, OpenRouter, o, a _More_, DeepSeek o qualsevol altre proveïdor al qual OpenCode iniciï sessió, tots executats a OpenCode; o executar el millor model per al teu ordinador, quan n'hi ha un que hi cap. El primer que acabis es converteix en el teu agent predeterminat, i el + del panell ofereix les mateixes tres opcions més tard. Després d'això, el panell posa cada subscripció en una sola pàgina: cada agent i compte amb el seu pla, un mesurador per a cadascun dels seus límits de sessió de 5 hores i setmanal amb el temps que falta fins que es restableixi (passa el cursor per sobre per veure el percentatge exacte), o el saldo prepagat restant, sota una línia que va rotant pel que has utilitzat entre tots ells, com els tokens d'aquesta setmana i el model que més has utilitzat. A _Make something cool_ ofereix prompts inicials per a un tema, un complement, una app o un joc nous que passen la tasca al teu agent predeterminat. Les apps es construeixen de la manera com ho són Hype, Monologue i Omacut, les pròpies d'Omarchy, en C++ i Qt Quick, seguint la skill d'agent omarchy-make-app, i el compilador i les peces de Qt que necessiten venen instal·lats. Els jocs són una sola pàgina three.js a `~/Games/vibes`, seguint la skill d'agent omarchy-make-game, i tots s'obren des d'un únic llançador Game Vibes amb el tema actual; carreguen three.js des del web, de manera que necessiten connexió per començar. Claude Code, Codex, Grok, Kimi, Cursor i la seva assignació Grok Bot, GitHub Copilot, Muse, Gemini (mitjançant Antigravity) i Devin estan coberts de fàbrica amb els seus límits, Kimchi amb el seu pla, crèdits prepagats i pressupostos de despesa, i Hermes, Mistral Vibe i Qwen Code mostren les seves sessions i tokens un cop els hagis utilitzat. Els plans i les claus de proveïdor que utilitzis mitjançant pi, omp o opencode també hi apareixen: OpenCode Zen and Go, el Z.ai GLM Coding Plan, Ollama Cloud, el MiniMax Token Plan i Synthetic amb els seus límits; OpenRouter i DeepSeek amb els seus saldos prepagats; Fireworks amb la seva despesa dels darrers 30 dies. Els models de programació que executis al teu propi maquinari tenen línies pròpies, i els seus tokens també compten per als totals, tal com es descriu a [Models locals](#local-models). Cada agent es compta una vegada, sota qui el factura, per molts harness mitjançant els quals l'utilitzis.

Fes clic amb el botó esquerre a la icona de la barra o prem `Super + Ctrl + X` per al panell, clic amb el botó dret per llançar el teu agent predeterminat i clic amb el botó del mig per actualitzar. Els registres d'ús que hi ha al darrere es regeneren cada 15 minuts amb `omarchy agent usage update`, i el panell fins i tot pot fusionar l'ús d'altres màquines teves mitjançant una carpeta sincronitzada. Consulta el README a `$OMARCHY_PATH/shell/plugins/agents/` per a tota la configuració.

### Diverses subscripcions

Si pagues per més d'un pla de Claude, Codex o Grok — un Max personal i un de feina, per exemple — Omarchy pot mantenir-los tots amb la sessió iniciada i moure's entre ells. Afegeix una subscripció amb el + del panell d'agents, que et guia allà mateix, o amb `omarchy agent account add claude Work` (o `codex`, o `grok`). El mateix + i la mateixa ordre inicien sessió a Gemini (`gemini`) i OpenCode (`opencode`), i desen una clau d'API de Fireworks (`fireworks`) o OpenRouter (`openrouter`) a OpenCode; l'ordre també inicia sessió a Copilot (`copilot`), Cursor (`cursor`) i Muse (`muse`). Aquests mantenen una única sessió iniciada cadascun. Instal·la el CLI si falta. El primer compte d'un proveïdor inicia sessió mitjançant el teu navegador normal, just on el CLI sempre mira. Cadascun dels següents inicia sessió mitjançant una finestra privada, de manera que el compte en què el teu navegador ja ha iniciat sessió no es reculli per error; inicia sessió allà com el compte que estàs afegint, i primer tanca qualsevol finestra privada que ja tinguessis oberta. No tanquis mai la sessió del CLI per fer això: tancar la sessió revoca la sessió desada, i aquell compte s'hauria d'afegir de nou.

Per copiar les sessions iniciades de subscripció a una altra màquina Omarchy per SSH, executa `omarchy agent account copy user@laptop`. L'emissor proporciona un receptor temporal quan la destinació no en té cap d'instal·lat, de manera que les màquines Omarchy més antigues poden rebre comptes sense una actualització. Els receptors instal·lats tenen preferència. Això copia totes les subscripcions de Claude, Codex i Grok; afegeix noms de proveïdor per seleccionar-les, com a `omarchy agent account copy laptop claude`. Els noms de compte i els ID d'ordre coincideixen amb l'origen, inclosos els comptes ja presents a la destinació. Els comptes de destinació no relacionats reben un sufix numèric si els seus noms entren en conflicte, i la configuració, les skills, els complements i l'historial de converses es mantenen locals a cada màquina.

Les credencials existents de la destinació es mantenen. Un compte d'origen que ja ha iniciat sessió allà té el seu nom sincronitzat sense substituir les seves credencials; els altres comptes s'hi afegeixen al costat. Per substituir les credencials desades dels comptes coincidents, utilitza `omarchy agent account copy --replace laptop claude` després de sortir de les sessions d'aquell compte a la destinació. Una destinació nova també rep el compte actiu i les preferències de canvi de l'origen; una destinació ja establerta manté les seves.

Les credencials viatgen mitjançant SSH i es desen en fitxers privats a la destinació, de manera que copia només a màquines de confiança. Això és una còpia única, no una sincronització contínua. Els tokens d'actualització de Codex poden ser rotats per una altra màquina, fet que deixa una sessió copiada amb necessitat de renovació; les sessions iniciades per separat continuen sent l'opció més fiable per a un ús simultani en diverses màquines. Consulta [la guia d'autenticació de comptes de Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Un compte per proveïdor està actiu, i cada sessió nova comença com a ell: `cx`, `cy`, un `claude`, `codex` o `grok` sense més, qualsevol cosa llançada mitjançant `omarchy agent`, i scripts o editors que trobin el CLI al `PATH`. Canvia amb `omarchy agent account use work` (i torna amb `omarchy agent account use main`), o al panell prement el número d'un compte i després `Enter` (o fent clic a la seva estrella). Les sessions de Claude en execució també canvien, a partir del seu missatge següent: cada sessió de Claude s'executa a `~/.claude`, que sempre conté la sessió iniciada del compte actiu. Una sessió de Claude iniciada a la carpeta pròpia d'un compte per un Omarchy més antic manté aquella sessió iniciada fins que surt, de manera que el canvi nomena aquelles sessions i acaba per si sol un cop hagin desaparegut. Les sessions de Codex i Grok en execució es mantenen al compte amb què van començar. L'historial de converses, la configuració, les skills i els complements es comparteixen entre comptes, de manera que `claude --continue` a la mateixa carpeta reprèn on ho vas deixar amb el compte nou.

Amb més d'un compte, el panell mostra els límits de cada compte un al costat de l'altre, amb una estrella plena en el que s'està utilitzant. Omarchy t'avisa quan el compte actiu supera el 95% d'un límit, i fer clic a la notificació canvia al compte amb més marge. Mai no canvia per si sol. Canvia el llindar amb `omarchy agent account threshold 90`. Si cada compte supera el llindar, se t'informarà una vegada, juntament amb quin compte s'allibera primer. Mentre un compte actiu estigui a menys de 15 punts del seu llindar (80% per defecte), els seus límits es comproven cada tres minuts en lloc de cada 15.

`omarchy agent account list` mostra cada compte i els seus límits més recents, `omarchy agent account remove work` n'oblida un, i `omarchy agent account rename primary Hey` en reanomena un (o fes clic al nom d'un compte al panell). Aquestes ordres funcionen amb els comptes del teu agent predeterminat; per arribar a l'altre proveïdor, nomena'l primer, com a `omarchy agent account use codex side`. La sessió que ja tenies a `~/.claude` o `~/.codex` és el compte _Main_. La de Codex es queda on és; la de Claude espera en una carpeta pròpia mentre un altre compte està actiu. Un compte que no s'hagi utilitzat durant més d'unes vuit hores pot mostrar _Sign-in required_; fes-hi clic per iniciar sessió de nou en aquell compte directament al panell, o canvia-hi i inicia una sessió, cosa que actualitza la sessió iniciada per si sola. Els servidors MCP que afegeixis amb `claude mcp add` arriben a cada compte de Claude, ja que tots s'executen a `~/.claude`; per a Codex i Grok, els servidors que tenies quan es va afegir un compte l'acompanyen, però els posteriors només arriben al compte en què els vas afegir. Claude Desktop manté una sessió iniciada pròpia, i les eines de Codex o Grok configurades amb un camí absolut a un binari del CLI no segueixen el canvi. Un `CLAUDE_CONFIG_DIR`, `CODEX_HOME` o `GROK_HOME` explícit té preferència sobre el compte seleccionat.

### Diagnòstic de fallades

Omarchy vigila systemd-coredump per detectar fallades de processos. Un cop hagis triat un agent predeterminat, qualsevol programa teu que generi un bolcat de memòria provoca una notificació "Process crashed" — fes-hi clic, i la fallada es passa al teu agent predeterminat juntament amb la skill omarchy-diagnose-crash d'Omarchy, que guia l'agent per establir els fets a partir del bolcat de memòria i decidir si la fallada val la pena d'informar-la a upstream. També la pots executar manualment contra qualsevol PID de `coredumpctl list` amb `omarchy agent crash <pid>`.

La vigilància està activada per defecte. Desactiva-la a _Trigger > Toggle > Crash Capture Off_ (o amb `omarchy toggle crash-capture`) i les notificacions s'aturaran; `omarchy agent crash <pid>` continua funcionant manualment.

Les fallades també es poden silenciar programa a programa, que és el que el diagnòstic t'ofereix al final. `omarchy crash mute hyprland` atura les notificacions només per a aquell programa, `omarchy crash mute hyprland off` les torna a activar, i `omarchy crash mute` per si sol enumera el que has silenciat. Accepta el camí del binari tan bé com el seu nom, de manera que `omarchy crash mute /usr/bin/hyprland` fa el mateix. Posa entre cometes un nom amb un espai, com a `omarchy crash mute 'Some App'`. Tota la resta continua notificant, i el programa silenciat continua fallant — això amaga el recordatori, no arregla res.

### Aplicacions d'escriptori

_Instal·la > AI > Desktop_ conté les apps gràfiques d'IA: Amp Desktop, Antigravity Desktop, l'app d'escriptori de ChatGPT, l'app d'escriptori de Claude (la beta per a Linux d'Anthropic, amb pestanyes Chat, Cowork i Claude Code), Grok Bot per xatejar amb els models de xAI, Herdr Desktop, Hermes Desktop, OpenClaw, l'app d'escriptori de Perplexity i T3 Code. Grok Bot és l'app de xat d'escriptori. L'agent de programació és l'ordre `grok`.

Hermes Desktop és la que cal conèixer, perquè una màquina té un sol Hermes, i és el de l'app: Hermes només s'instal·la mai mitjançant l'app, i l'ordre `hermes` que executa l'agent predeterminat és la de l'app. Triar Hermes com a agent predeterminat instal·la el mateix que instal·la l'entrada _Instal·la > AI > Desktop_: el paquet, i un entorn d'execució de Hermes a `~/.hermes` configurat per l'instal·lador propi de Hermes, que triga uns minuts la primera vegada. Aquell entorn d'execució és l'únic Hermes que utilitzen l'ordre `hermes` de terminal, l'agent predeterminat i l'app, i s'actualitza per si sol amb `hermes update` en lloc d'esperar una versió d'Omarchy. Instal·lar-lo també dona a Hermes el tema d'Omarchy com una aparença anomenada `omarchy`, que cada superfície de Hermes segueix quan canvies de tema; tria'n una altra a la configuració d'Appearance de Hermes o amb `/skin` si prefereixes que no ho faci, i Omarchy respecta aquella tria. Eliminar l'app a _Elimina > AI > Desktop_ primer tanca Hermes, passarel·la inclosa, s'endú aquell entorn d'execució amb ella, i manté els teus xats, records i les skills que Hermes ha escrit per a si mateix tret que li diguis el contrari: et demana, amb «no» per defecte, si aquelles dades i la teva configuració de connexió també haurien de desaparèixer.

L'experiència d'escriptori d'OpenClaw és la seva Control UI, que s'obre com una app web recolzada per la seva pròpia passarel·la local. OpenClaw viu a `~/.openclaw` i s'actualitza per si sol: utilitza el botó "Update Gateway" de la Control UI o executa `openclaw update`, i la passarel·la es reinicia amb la versió nova. Omarchy només tria la versió amb què comença una instal·lació nova. OpenClaw també pot ser el teu agent predeterminat: triar-lo amb `omarchy default agent openclaw` configura aquella mateixa còpia a `~/.openclaw`, i l'agent obre la interfície d'usuari de terminal d'OpenClaw connectada a la seva passarel·la. Eliminar OpenClaw a _Elimina > AI > Desktop_ s'endú el servei de passarel·la i l'app amb ell i després demana si `~/.openclaw` també hauria de desaparèixer, ja que allò conté els teus xats i credencials juntament amb OpenClaw mateix i els entorns d'execució de complements que descarrega; per defecte es manté, i instal·lar OpenClaw de nou el recupera.

Herdr Desktop és l'app d'escriptori [Herdr](https://herdr.dev): espais, pestanyes i panells de terminals i agents de programació que continuen funcionant al seu nucli quan tanques la finestra. Prové de l'instal·lador propi de Herdr en lloc d'un paquet, de manera que viu a `~/.local/share/herdr-app`, porta el seu nucli a `~/.local/bin/herdr-core` quan encara no en tens un, i s'actualitza tant a si mateix com a ell. Es troba al costat de l'ordre `herdr` que Omarchy proporciona amb `Super + Ctrl + Return` en lloc de substituir-la, i rep les tecles directes d'aquella ordre: `Alt + Return` i `Alt + Shift + Return` divideixen un panell cap avall o cap a la dreta, `Alt + Escape` el tanca, `Ctrl + Alt + Arrow` es mou entre panells, `Alt + 1..9` i `Alt + Left/Right` trien una pestanya, i `Alt + Up/Down` es mouen entre espais. `Ctrl + 1..9` tria un espai i `Alt + Shift + Up/Down` recorre els agents. Les tecles amb prefix `Ctrl + Space` es mantenen només per al terminal, ja que l'app no pot mantenir una tecla Ctrl simple per a una seqüència. Omarchy escriu aquestes a `~/.config/herdr-app/keys.json`, i `omarchy-refresh-herdr-app` les restaura. Instal·lar-lo tria el tema Omarchy de Herdr, que a partir d'aleshores segueix el teu tema d'Omarchy. Herdr manté un tema per al mode clar i un per al mode fosc, de manera que després de canviar entre un tema fosc i un de clar d'Omarchy, torna a triar Omarchy al selector de temes de Herdr una vegada més per a l'altre mode.

T3 Code s'executa des de la seva versió oficial AppImage a `~/.local/share/t3code` en lloc de des d'un paquet, de manera que s'actualitza per si sol. Instal·lar-lo demana si començar al canal Stable o Nightly; canvia-ho més tard a la configuració de T3 Code. Els teus fils i la teva configuració viuen a `~/.t3`, i eliminar T3 Code a _Elimina > AI > Desktop_ els s'endú amb ell.

### Models locals

Executa un model obert a la teva pròpia màquina per als teus agents de programació. Els teus prompts i el teu codi es queden a la màquina; res del que s'envia al model no en surt. Comença amb:

```bash
omarchy models use best text
```

Això configura el millor model de text per a aquesta màquina, del tipus que utilitzen els teus agents. Els models d'imatge, vídeo i música tenen el seu propi millor: `omarchy models use best image`, `video` o `music`. Executa `omarchy models use best` per veure la tria de cada tipus per a aquesta màquina.

O tria + al panell d'agents: a _Use a local model_ enumera cada model de programació que cap en aquesta màquina, el recomanat primer. Podman, que executa els models, ve amb Omarchy, igual que el kit d'eines de contenidors de NVIDIA en una màquina NVIDIA, que els dona la GPU; si falta qualsevol dels dos, la primera configuració l'instal·la. A continuació, Omarchy tria el model recomanat per a aquesta màquina, el descarrega i l'inicia. Espera una descàrrega de desenes de GB i que la major part de la memòria de la màquina estigui en ús mentre el model s'executa: Flash Next utilitza uns 100 GiB amb el seu context complet de 256K. Si altres models ocupen la memòria que necessita, es configura aturat, preparat per iniciar-se un cop n'aturis un. El model s'atura en tancar la sessió; atura'l tu mateix quan necessitis la memòria per a una altra cosa.

`omarchy models list` mostra les opcions i explica per què algunes no hi caben. Per configurar-ne un altre, executa `omarchy models use <recipe>`. Avui, `qwen3.8-flash-next-gufo` i `qwen3.8-27b-gufo` estan disponibles per a màquines Strix Halo de 128 GB; el 27B ocupa uns 40 GiB, de manera que deixa espai per a altra feina. En un portàtil de 64 GB amb l'Arc B390 d'Intel, `qwen3.6-35b-a3b-llamacpp` s'executa en uns 30 GiB. Les receptes i recomanacions noves arriben amb `omarchy update`, mitjançant el paquet.

Un model de programació que afegeixis rep la seva pròpia línia al panell d'agents, al costat de les teves subscripcions: reprodueix per iniciar-lo, pausa per aturar-lo i alliberar la seva memòria, la marca de Tailscale per compartir-lo amb les altres màquines de la teva tailnet mentre s'executa, i el botó de terminal per obrir el teu agent en ell. La seva línia mostra la descàrrega, la càrrega o l'aturada a mesura que avança, i ho diu quan no hi ha prou memòria lliure per iniciar-lo, o enllaça als seus registres quan s'ha aturat amb un error. Diversos poden executar-se alhora quan caben junts a la memòria. Prem Delete en una línia seleccionada per eliminar el model d'aquesta màquina, descàrrega i tot; + el pot configurar de nou. Un model de programació configurat des d'un terminal espera a + fins que l'afegeixis, i també ho fan els models que executa una màquina amb què t'hagis emparellat (`omarchy models pair <host>`).

Cada model de programació que configuris també rep la seva pròpia entrada al llançador d'aplicacions, amb el nom del model i amb el logotip del seu creador, de la manera com iniciar sessió a Claude, Codex o Grok n'afegeix una. Obre el teu agent en aquell model, i primer inicia el model si no s'està executant: el terminal mostra com es carrega i passa el relleu a l'agent un cop està en marxa. Eliminar un model elimina la seva entrada.

No tots els models són per programar. Els models d'imatge, vídeo i música s'obren a Fantasi, l'app d'Omarchy per fer imatges, vídeo i música amb un model que s'executa en aquesta màquina, i es gestionen allà o amb `omarchy models`.

Un model continua executant-se exactament com es va configurar, de manera que una actualització d'Omarchy mai no en reinicia un sota els teus agents. Quan Omarchy té un entorn d'execució més nou o pesos més nous per a un model que hagis configurat, la seva línia mostra un botó d'actualització: prem-lo i el model es configura de nou en segon pla, descarregant només el que ha canviat, i es reinicia amb la versió nova. Un model que estava aturat es manté aturat. `omarchy models update` fa el mateix per a cada model des d'un terminal.

Des de la línia d'ordres, `omarchy models start <recipe>` i `omarchy models stop <recipe>` fan el mateix, `omarchy models status` mostra cada model, i `omarchy agent --local-model <recipe>` obre aquell model a pi, sigui quin sigui el teu agent predeterminat. Per fer que el teu model local sigui el que obren la tecla ràpida d'agent, la consola Quake i _Make something_ , executa `omarchy default agent local` o marca amb una estrella un model en execució al panell d'agents. pi també enumera cada model que hagis configurat, i els de les màquines amb què t'hagis emparellat, al seu propi selector de models, de manera que un `pi` sense més també hi arriba. Qualsevol client compatible amb OpenAI també s'hi pot connectar: `status` mostra l'adreça de cada model (la primera és `http://127.0.0.1:11435/v1`), el nom de la recepta és el model, i la clau és a `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` elimina un model i les descàrregues que cap altre model no utilitza.

Els entorns d'execució de tercers s'etiqueten amb el seu editor. Omarchy executa cada model sense accés a la xarxa.

### LLM locals

Omarchy recomana dues maneres d'executar models LLM locals: LM Studio i Ollama. LM Studio proporciona una interfície gràfica per trobar models de pesos oberts, instal·lar-los i executar-los. És una bona manera de començar fàcilment. Ollama ofereix un CLI per fer-ho de manera similar. Però si ets nou en els models locals, jo començaria amb LM Studio. Instal·la LM Studio des de _Instal·la > AI > Desktop_ i Ollama des de _Instal·la > AI > CLI_ al menú d'Omarchy.

### Les skills d'Omarchy

Les skills d'agent ajuden la IA a utilitzar eines específiques d'una manera específica, i Omarchy en proporciona set. La skill omarchy cobreix adaptar el sistema a mida, com ajustar la teva configuració de Hyprland o ajustar la barra. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app i omarchy-make-game cobreixen fer alguna cosa nova, omarchy-contribute cobreix informar d'un error o enviar una correcció a upstream, i omarchy-diagnose-crash treballa amb el bolcat de memòria d'una fallada. Estan enllaçades simbòlicament als directoris de skills per a Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` i cada `~/.hermes/profiles/*/skills`), i la ubicació genèrica `~/.agents/skills`, de manera que la majoria de harness les recullen automàticament. Una carpeta de skill pròpia amb el mateix nom té preferència.

Però hauries de tractar aquestes skills com a experimentals. Diferents models la utilitzaran amb efectes diferents. El millor és executar primer en mode de pla, perquè tinguis una idea del que l'agent voldria canviar. I després estigues preparat per revertir els canvis o fins i tot invocar `omarchy reinstall configs`, si l'agent ho embolica tot.
