# IA

Omarchy inclou llançadors per als agents de programació següents sense triar-ne un de predeterminat per a tu. Executa una ordre per instal·lar-ne la CLI el primer cop que la facis servir, i després autentica't quan t'ho demani. Hermes és l'excepció: no s'instal·la res per a ell el primer cop, i triar-lo instal·la Hermes Desktop, com explica _Aplicacions d'escriptori_ més avall.

### Instal·lació i actualització d'agents

Excepte Hermes, aquests agents fan servir la instal·lació diferida de mise: el primer llançament instal·la la CLI, i els llançaments posteriors la reutilitzen. mise també comprova si hi ha una nova versió d'un agent instal·lat com a màxim un cop cada quatre hores, just abans d'iniciar-lo o en segon pla en un indicador de l'intèrpret d'ordres. Si aquesta actualització falla o no tens connexió, s'executa la versió instal·lada. `omarchy update` actualitza els agents instal·lats amb la resta d'Omarchy, i `mup` actualitza només les eines gestionades per mise.

L'actualitzador propi d'un agent, com ara `claude update`, `codex update` o un botó d'actualització en una aplicació, no actualitza la instal·lació gestionada per mise. `codex update` falla, i `claude update` pot informar que ha tingut èxit mentre instal·la una còpia separada que mise no segueix. Si prefereixes fer servir l'instal·lador i l'actualitzador natius d'un agent, afegeix-lo a `disable_tools`; vegeu [Eines de CLI preinstal·lades](18-development-tools.md#preinstalled-cli-tools).

Per instal·lar totes les eines diferides configurades abans que les necessitis, executa `mise install --include-lazy`. Això inclou les altres eines de CLI predeterminades d'Omarchy, a més dels agents. Vegeu [Eines de CLI preinstal·lades](18-development-tools.md#preinstalled-cli-tools) per instal·lar una sola eina o fer servir la teva pròpia instal·lació.

`grok` s'instal·la mitjançant el paquet de primera mà `grok` de mise, de la mateixa manera que `claude` i `codex`. Executa `grok`, o tria'l a _Agent > Harness_. Salta't l'instal·lador `curl | bash` de x.ai. Aquesta ruta posa una segona còpia a `~/.grok/bin`, l'avantposa a `PATH` i sobreescriu l'embolcall d'Omarchy.

`dsh` obre la seva interfície d'usuari al navegador a `127.0.0.1:3080`, amb el directori de llançament com a espai de treball predeterminat. La seva interfície al navegador no accepta cap instrucció inicial, de manera que `omarchy agent prompt` l'obre amb la instrucció al porta-retalls perquè l'enganxis. Omarchy l'inicia amb el predefinit de permisos sense aprovació de DeepSeek. DeepSeek Harness puja els registres de sessió a DeepSeek quan fas servir la seva API oficial de models; desactiva-ho a _Settings > General > Upload Session Log_ a la seva interfície al navegador. Els comentaris que li enviïs també es pugen amb la sessió, llevat que l'iniciïs amb `DSH_TELEMETRY_MODE=DISABLED`.

### L'agent predeterminat

Tria el teu agent predeterminat amb `omarchy default agent <name>` o a _Agent > Harness_ al menú d'Omarchy (`Super + Space`). Si l'agent encara no està instal·lat, triar-lo l'instal·la primer. Un Omarchy acabat d'instal·lar t'invitarà a fer aquesta tria amb una notificació única.

Triar Claude també intenta configurar la seva extensió de navegador per a Chromium, Chrome, Brave, Brave Origin i Edge. La configuració de l'extensió s'aplica a tots els usuaris i pot demanar la teva contrasenya del sistema; cancel·lar-la o que falli la instal·lació de l'extensió no impedeix seleccionar i llançar Claude. Reinicia el navegador, activa l'extensió si t'ho demana, i inicia sessió a Claude per acabar de connectar-la. Executa `/chrome` a Claude per comprovar la connexió. Firefox i Zen no admeten aquesta extensió. Si Claude ja era el teu predeterminat abans que s'afegís aquesta configuració, selecciona'l de nou per instal·lar l'extensió.

Un cop hagis triat, `Super + Shift + Ctrl + A` llança l'agent predeterminat en una finestra de terminal dedicada (o obre el selector si encara no n'has triat cap). També el pots llançar directament en una tasca amb `omarchy agent prompt "Review this project"`. Freebuff i DeepSeek Harness no accepten cap instrucció inicial, de manera que s'obren amb la instrucció al porta-retalls perquè l'enganxis. Els agents llançats així funcionen sense supervisió en els seus respectius modes de no aturar-se a demanar, així que estigues preparat perquè realment facin coses! MiniMax Code no té un mode així per a les seves sessions interactives, de manera que demana permisos com de costum. I com que els agents es neguen a recordar la confiança per al teu directori d'inici, els llançaments des de `$HOME` s'inicien a `~/Work`.

També hi ha dreceres de terminal: `a` executa l'agent predeterminat en línia al terminal actual, mentre que `c`, `cx` i `cy` inicien OpenCode, Claude Code i Codex directament (també en els seus modes d'aprovació automàtica). Els canvis de tema també se sincronitzen amb els agents: Claude Code, Pi, OpenCode i Hermes (un cop Omarchy l'ha instal·lat) segueixen el canvi quan canvies el tema d'Omarchy.

### Les instruccions del teu agent

Les regles personals per a cada agent van a `~/.agents/AGENTS.md`, al costat de les habilitats compartides a `~/.agents/skills`. Obre'l a _Agent > Instructions_, que també l'enllaça a cada arnès que manté el seu propi fitxer global: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, el `~/.copilot/copilot-instructions.md` de Copilot, i així successivament. Crush i Amp llegeixen l'enllaç `~/.config/AGENTS.md`, mentre que omp, Kimi i DeepSeek Harness llegeixen `~/.agents/AGENTS.md` directament. Triar un agent predeterminat també l'enllaça. Un fitxer d'instruccions que ja tenies es converteix en el compartit si encara no n'hi havia cap; en cas contrari es conserva al costat de l'enllaç com a `.bak`. Executa `omarchy agent instructions` per tornar a enllaçar després d'instal·lar un altre agent.

### El panell d'agents

La barra superior té una icona d'agents. Abans que hagis configurat un agent, el seu panell et guia per iniciar sessió a Claude, Codex o Grok, i el primer es converteix en el teu agent predeterminat. Després d'això, el panell posa cada subscripció en una sola pàgina: cada agent i compte amb el seu pla, un mesurador per a cadascun dels seus límits de sessió de 5 hores i setmanal amb el temps que falta perquè es restableixi (passa el cursor per sobre per veure el percentatge exacte), o el saldo prepagat restant, sota una línia que rota pel que has fet servir entre tots ells, com ara els tokens d'aquesta setmana i el teu model més utilitzat. A _Make something_ ofereix instruccions inicials per a un tema, un connector, una aplicació o un joc nous que lliuren la tasca al teu agent predeterminat. Les aplicacions es construeixen de la manera com es fan les pròpies Hype, Monologue i Omacut d'Omarchy, en C++ i Qt Quick, seguint l'habilitat d'agent omarchy-app, i el compilador i les peces de Qt que necessiten ja venen instal·lats. Els jocs són una sola pàgina de three.js a `~/Games/vibes`, seguint l'habilitat d'agent web-game, i tots s'obren des d'un únic llançador Game Vibes amb el tema actual; carreguen three.js des del web, de manera que necessiten connexió per iniciar-se. Claude Code, Codex, Grok, Kimi, Cursor i la seva assignació de Grok Bot, GitHub Copilot, Muse, Antigravity, Kimchi i Devin estan coberts de sèrie amb els seus límits, i Hermes, Mistral Vibe i Qwen Code mostren les seves sessions i tokens un cop els has fet servir. Els plans i les claus de proveïdors que fas servir mitjançant pi, omp o opencode també hi apareixen: OpenCode Zen i Go, el Z.ai GLM Coding Plan, Ollama Cloud, el MiniMax Token Plan i Synthetic amb els seus límits; Fireworks, OpenRouter i DeepSeek amb els seus saldos prepagats; i els models que executes amb el teu propi maquinari a Models locals. Cada agent es compta un sol cop, sota qui el facturi, independentment de quants arnesos facis servir per conduir-lo.

Fes clic amb el botó esquerre a la icona de la barra per al panell, clic amb el botó dret per llançar el teu agent predeterminat. Els registres d'ús que hi ha darrere es regeneren cada 15 minuts amb `omarchy agent usage-update`, i el panell fins i tot pot fusionar l'ús d'altres màquines teves mitjançant una carpeta sincronitzada. Consulta el README a `$OMARCHY_PATH/shell/plugins/agents/` per a tota la configuració.

### Diverses subscripcions

Si pagues més d'un pla de Claude, Codex o Grok — un Max personal i un de la feina, per exemple — Omarchy els pot mantenir tots amb la sessió iniciada i moure's entre ells. Afegeix una subscripció amb el + al panell d'agents, que et guia allà mateix, o amb `omarchy agent account add claude Work` (o `codex`, o `grok`). Instal·la la CLI si falta. El primer compte d'un proveïdor inicia sessió mitjançant el teu navegador normal, allà on la CLI sempre busca. Cada un dels següents inicia sessió mitjançant una finestra privada, de manera que el compte en què el teu navegador ja ha iniciat sessió no es reculli per error; inicia sessió allà com el compte que estàs afegint, i tanca primer qualsevol finestra privada que ja tinguessis oberta. No tanquis mai la sessió de la CLI per fer això: tancar la sessió revoca l'inici de sessió desat, i aquell compte s'hauria d'afegir de nou.

Per copiar els teus inicis de sessió de subscripció a una altra màquina Omarchy per SSH, executa `omarchy agent account copy user@laptop`. L'emissor proporciona un receptor temporal quan la destinació no en té cap d'instal·lat, de manera que les màquines Omarchy més antigues poden rebre comptes sense una actualització. Els receptors instal·lats tenen precedència. Això copia totes les subscripcions de Claude, Codex i Grok; afegeix noms de proveïdor per seleccionar-les, com a `omarchy agent account copy laptop claude`. Els noms de compte i els ID d'ordres coincideixen amb l'origen, inclosos els comptes ja presents a la destinació. Els comptes de destinació no relacionats reben un sufix numèric si els seus noms entren en conflicte, i la configuració, les habilitats, els connectors i l'historial de converses es queden locals a cada màquina.

Les credencials de destinació existents es conserven. Un compte d'origen que ja ha iniciat sessió allà veu el seu nom sincronitzat sense substituir les seves credencials; els altres comptes s'hi afegeixen al costat. Per substituir les credencials desades dels comptes coincidents, fes servir `omarchy agent account copy --replace laptop claude` després de tancar les sessions d'aquell compte a la destinació. Una destinació nova també rep el compte actiu i les preferències de canvi de l'origen; una destinació establerta conserva els seus.

Les credencials viatgen per SSH i s'emmagatzemen en fitxers privats a la destinació, de manera que copia només a màquines de confiança. Això és una còpia única, no una sincronització contínua. Els tokens d'actualització de Codex poden ser rotats per una altra màquina, deixant un inici de sessió copiat amb necessitat de renovació; els inicis de sessió separats continuen sent l'opció més fiable per a l'ús simultani en diverses màquines. Vegeu [la guia d'autenticació de comptes de Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Un compte per proveïdor està actiu, i cada sessió nova comença com a ell: `cx`, `cy`, un simple `claude`, `codex` o `grok`, qualsevol cosa llançada mitjançant `omarchy agent`, i scripts o editors que troben la CLI a `PATH`. Canvia amb `omarchy agent account use work` (i torna amb `omarchy agent account use main`), o al panell prement el número d'un compte i després `Enter` (o fent clic al seu botó Use). Les sessions de Claude en execució també canvien, des del seu missatge següent: cada sessió de Claude s'executa a `~/.claude`, que sempre conté l'inici de sessió del compte actiu. Una sessió de Claude iniciada a la carpeta pròpia d'un compte per un Omarchy més antic conserva aquell inici de sessió fins que surt, de manera que el canvi anomena aquestes sessions i acaba per si sol un cop han desaparegut. Les sessions de Codex i Grok en execució es queden amb el compte amb què van començar. L'historial de converses, la configuració, les habilitats i els connectors es comparteixen entre comptes, de manera que `claude --continue` a la mateixa carpeta reprèn on ho vas deixar amb el compte nou.

Amb més d'un compte, el panell mostra els límits de cada compte un al costat de l'altre, amb l'actiu marcat. Per defecte, Omarchy t'avisa quan el compte actiu supera el 95% d'un límit, i fer clic a la notificació canvia al compte amb més marge. Passa el cursor per sobre de la línia d'un compte al panell i fes clic a l'Autoswitch que apareix al costat de Use (o prem `m`), o executa `omarchy agent account mode auto`, perquè canviï per si sol; mentre està activat, Autoswitch ocupa el lloc de Use, i tornar a fer-hi clic torna a avisar. Afegeix un número per canviar el llindar, com a `omarchy agent account mode auto 90`. Si cada compte supera el llindar, te n'assabentaràs un cop, juntament amb quin compte s'allibera primer. Mentre un compte actiu és a menys de 15 punts del seu llindar (80% per defecte), els seus límits es comproven cada tres minuts en lloc de cada 15.

`omarchy agent account list` mostra cada compte i els seus límits més recents, `omarchy agent account remove work` n'oblida un, i `omarchy agent account rename primary Hey` en reanomena un (o fes clic al nom d'un compte al panell). Aquestes ordres funcionen amb els comptes del teu agent predeterminat; per arribar a l'altre proveïdor, anomena'l primer, com a `omarchy agent account use codex side`. L'inici de sessió que ja tenies a `~/.claude` o `~/.codex` és el compte _Main_. El de Codex es queda on és; el de Claude espera en una carpeta pròpia mentre un altre compte està actiu. Un compte que no s'ha fet servir durant més d'unes vuit hores pot mostrar _Sign-in required_; fes-hi clic per iniciar sessió de nou amb aquell compte directament al panell, o canvia a ell i inicia una sessió, que refresca l'inici de sessió per si sola. Els servidors MCP que afegeixes amb `claude mcp add` arriben a cada compte de Claude, ja que tots s'executen a `~/.claude`; per a Codex i Grok, els servidors que tenies quan es va afegir un compte l'acompanyen, però els posteriors només arriben al compte en què els vas afegir. Claude Desktop conserva un inici de sessió propi, i les eines de Codex o Grok configurades amb una ruta absoluta a un binari de CLI no segueixen el canvi. Un `CLAUDE_CONFIG_DIR`, `CODEX_HOME` o `GROK_HOME` explícit té precedència sobre el compte seleccionat.

### Diagnòstic de bloquejos

Omarchy vigila systemd-coredump per detectar bloquejos de processos. Quan alguna cosa fa una violació de segment, rebràs una notificació "Process crashed" — fes-hi clic, i el bloqueig es lliura al teu agent predeterminat juntament amb l'habilitat diagnose-crash d'Omarchy, que guia l'agent per establir els fets a partir del bolcat de memòria i decidir si val la pena informar del bloqueig al projecte original. També el pots executar a mà contra qualsevol PID de `coredumpctl list` amb `omarchy agent crash <pid>`.

La vigilància està activada per defecte. Desactiva-la a _Trigger > Toggle > Crash Capture_ (o amb `omarchy toggle crash-capture`) i les notificacions s'aturen; `omarchy agent crash <pid>` continua funcionant a mà.

Els bloquejos també es poden silenciar un programa cada cop, que és el que el diagnòstic t'ofereix al final. `omarchy crash mute hyprland` atura les notificacions només per a aquell programa, `omarchy crash mute hyprland off` les restableix, i `omarchy crash mute` per si sol enumera el que has silenciat. Accepta la ruta del binari tan bé com el seu nom, de manera que `omarchy crash mute /usr/bin/hyprland` fa el mateix. Posa entre cometes un nom amb un espai, com a `omarchy crash mute 'Some App'`. Tota la resta continua avisant, i el programa silenciat continua bloquejant-se — això amaga el recordatori, no soluciona res.

### Aplicacions d'escriptori

El menú _Install > AI_ també inclou unes quantes aplicacions gràfiques d'IA: l'aplicació d'escriptori de ChatGPT, l'aplicació d'escriptori de Claude (la beta de Linux d'Anthropic, amb pestanyes de Chat, Cowork i Claude Code), Grok Bot per xatejar amb els models de xAI, Herdr Desktop, Hermes Desktop, OpenClaw, l'aplicació d'escriptori de Perplexity i T3 Code. Grok Bot és l'aplicació de xat d'escriptori. L'agent de programació és l'ordre `grok`.

Hermes Desktop és la que cal conèixer, perquè una màquina té un sol Hermes, i és el de l'aplicació: Hermes només s'instal·la mai mitjançant l'aplicació, i l'ordre `hermes` que executa l'agent predeterminat és la de l'aplicació. Triar Hermes com a agent predeterminat instal·la el mateix que instal·la l'entrada _Install > AI_: el paquet, i un entorn d'execució de Hermes a `~/.hermes` configurat pel propi instal·lador de Hermes, que triga uns minuts el primer cop. Aquest entorn d'execució és l'únic Hermes que fan servir l'ordre `hermes` del terminal, l'agent predeterminat i l'aplicació, i s'actualitza per si mateix amb `hermes update` en lloc d'esperar una versió d'Omarchy. Instal·lar-lo també lliura a Hermes el tema d'Omarchy com una aparença anomenada `omarchy`, que cada superfície de Hermes segueix quan canvies de tema; tria'n una altra a la configuració d'Appearance de Hermes o amb `/skin` si prefereixes que no ho faci, i Omarchy respecta aquesta tria. Eliminar l'aplicació a _Remove > AI_ tanca primer Hermes, inclosa la passarel·la, s'endú aquell entorn d'execució, i conserva els teus xats, records i les habilitats que Hermes ha escrit per a si mateix llevat que li diguis el contrari: pregunta, amb no per defecte, si aquestes dades i la teva configuració de connexió també han de desaparèixer.

L'experiència d'escriptori d'OpenClaw és la seva Control UI, que s'obre com una aplicació web recolzada per la seva pròpia passarel·la local. OpenClaw viu a `~/.openclaw` i s'actualitza per si mateix: fes servir el botó "Update Gateway" de la Control UI o executa `openclaw update`, i la passarel·la es reinicia amb la nova versió. Omarchy només tria la versió amb què comença una instal·lació nova. Eliminar OpenClaw a _Remove > AI_ s'endú el servei de passarel·la i l'aplicació i després pregunta si `~/.openclaw` també ha de desaparèixer, ja que conté els teus xats i credencials juntament amb el propi OpenClaw i els entorns d'execució de connectors que descarrega; per defecte el conserva, i instal·lar OpenClaw de nou el recupera.

Herdr Desktop és l'aplicació d'escriptori [Herdr](https://herdr.dev): espais, pestanyes i panells de terminals i agents de programació que continuen executant-se al seu nucli quan tanques la finestra. Prové del propi instal·lador de Herdr en lloc d'un paquet, de manera que viu a `~/.local/share/herdr-app`, porta el seu nucli a `~/.local/bin/herdr-core` quan encara no en tens cap, i s'actualitzen tots dos per si mateixos. S'assenta al costat de l'ordre `herdr` que Omarchy proporciona amb `Super + Ctrl + Return` en lloc de substituir-la, i rep les tecles directes d'aquesta ordre: `Alt + Return` i `Alt + Shift + Return` divideixen un panell cap avall o cap a la dreta, `Alt + Escape` el tanca, `Ctrl + Alt + Arrow` es mou entre panells, `Alt + 1..9` i `Alt + Left/Right` trien una pestanya, i `Alt + Up/Down` es mouen entre espais. `Ctrl + 1..9` tria un espai i `Alt + Shift + Up/Down` recorre els agents. Les tecles de prefix `Ctrl + Space` es queden només per al terminal, ja que l'aplicació no pot mantenir una tecla Ctrl simple per a una seqüència. Omarchy escriu aquestes a `~/.config/herdr-app/keys.json`, i `omarchy-refresh-herdr-app` les restableix. Instal·lar-lo tria el tema Omarchy de Herdr, que segueix el teu tema d'Omarchy a partir d'aleshores. Herdr conserva un tema per al mode clar i un per al mode fosc, de manera que després de canviar entre un tema fosc i un de clar d'Omarchy, tria Omarchy una vegada més al selector de temes de Herdr per a l'altre mode.

T3 Code s'executa des de la seva versió oficial d'AppImage a `~/.local/share/t3code` en lloc de des d'un paquet, de manera que s'actualitza per si mateix. Instal·lar-lo pregunta si vols començar al canal Stable o Nightly; canvia-ho més tard a la configuració de T3 Code. Els teus fils i la teva configuració viuen a `~/.t3`, i eliminar T3 Code a _Remove > AI_ se'ls endú.

### Models locals

Executa un model obert a la teva pròpia màquina per als teus agents de programació. Les teves instruccions i el teu codi es queden a la màquina; res del que s'envia al model en surt. Comença amb:

```bash
omarchy agent local use best
```

O, al panell d'agents de la barra superior, tria + i després Local AI, que apareix quan un model cap en aquesta màquina. El primer cop, això instal·la Podman, que executa els models, i en una màquina NVIDIA el conjunt d'eines de contenidors de NVIDIA, que els dona la GPU. Aleshores Omarchy tria el model recomanat per a aquesta màquina, el descarrega i l'inicia. Espera una descàrrega de desenes de GB i que la major part de la memòria de la màquina estigui en ús mentre el model s'executa: Flash Next fa servir uns 100 GiB amb el seu context complet de 256K. Si altres models ocupen la memòria que necessita, es configura aturat, llest per iniciar-se un cop n'aturis un. El model s'atura en tancar la sessió; atura'l tu mateix quan necessitis la memòria per a una altra cosa.

`omarchy agent local list` mostra les opcions i explica per què algunes no hi caben. Per configurar-ne un altre, executa `omarchy agent local use <recipe>`. Avui, `qwen3.8-flash-next-gufo` i `qwen3.8-27b-gufo` estan disponibles per a màquines Strix Halo de 128 GB; el de 27B ocupa uns 40 GiB, de manera que deixa espai per a altra feina. En un portàtil de 64 GB amb l'Arc B390 d'Intel, `qwen3.6-35b-a3b-llamacpp` s'executa en uns 30 GiB. Les receptes i recomanacions noves arriben amb `omarchy update`, mitjançant el paquet.

Cada model que configures rep la seva pròpia línia al panell d'agents, al costat de les teves subscripcions: reprodueix per iniciar-lo, pausa per aturar-lo i alliberar la seva memòria, i el botó de terminal per obrir el teu agent en ell. Diversos poden executar-se alhora quan caben junts a la memòria; si un no hi cap, Omarchy diu quin model en execució cal aturar. Arrossega línies per reordenar-les, i prem Delete en una línia seleccionada per eliminar un model i la seva descàrrega.

Cada model que configures també rep la seva pròpia entrada al llançador d'aplicacions, amb el nom del model i el logotip del seu creador, de la manera com iniciar sessió a Claude, Codex o Grok n'afegeix una. Obre el teu agent en aquell model, i inicia el model primer si no s'està executant: el terminal el mostra carregant-se i lliura el control a l'agent un cop està llest. Eliminar un model elimina la seva entrada.

Des de la línia d'ordres, `omarchy agent local start <recipe>` i `omarchy agent local stop <recipe>` fan el mateix, `omarchy agent local status` mostra cada model, i `omarchy agent --local` obre el teu agent predeterminat en l'últim model que vas iniciar. pi, OpenCode i Qwen Code en poden fer servir un; amb qualsevol altre predeterminat s'obre en pi. pi també enumera cada model que has configurat, i els de les màquines amb què t'has emparellat, en el seu propi selector de models, de manera que un simple `pi` també hi arriba. Qualsevol client compatible amb OpenAI també s'hi pot connectar: `status` mostra l'adreça de cada model (la primera és `http://127.0.0.1:11435/v1`), el nom de la recepta és el model, i la clau és a `~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` elimina un model i les descàrregues que cap altre model fa servir.

Els entorns d'execució de tercers estan etiquetats amb el seu editor. Omarchy executa cada model sense accés a la xarxa.

### LLM locals

Omarchy recomana dues maneres d'executar models LLM locals: LM Studio i Ollama. LM Studio proporciona una interfície gràfica d'usuari per trobar models de pesos oberts, instal·lar-los i executar-los. És una manera excel·lent de començar fàcilment. Ollama ofereix una CLI per fer-ho de manera similar. Però si ets nou en els models locals, jo començaria amb LM Studio. Pots instal·lar qualsevol dels dos a _Install > AI_ al menú d'Omarchy.

### L'habilitat d'Omarchy

Les habilitats d'agent ajuden la IA a fer servir eines específiques d'una manera específica, i Omarchy inclou una habilitat predeterminada per adaptar el sistema. Com ara retocar la teva configuració de Hyprland, ajustar la barra, o fins i tot crear un tema nou des de zero. Està enllaçada simbòlicament als directoris d'habilitats de Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` i cada `~/.hermes/profiles/*/skills`), i la ubicació genèrica `~/.agents/skills`, de manera que la majoria d'arnesos la recullen automàticament.

Però hauries de tractar aquesta habilitat com a experimental. Els diferents models la faran servir amb efectes diferents. És millor executar-la primer en mode de planificació, perquè tinguis una idea del que l'agent voldria canviar. I després estigues preparat per revertir els canvis o fins i tot invocar `omarchy reinstall configs`, si l'agent ho embolica tot.
