# IA

Omarchy inclou llançadors per als agents de programació següents sense triar-ne un de predeterminat per tu. Executa una ordre per instal·lar-ne la CLI el primer cop que l'utilitzis i, després, autentica't quan t'ho demani. Hermes és l'excepció: no s'instal·la res per a ell el primer cop que l'utilitzis i, si el tries, s'instal·la Hermes Desktop, tal com s'explica a _Aplicacions d'escriptori_ més avall.

### Instal·lació i actualització d'agents

Excepte Hermes, aquests agents fan servir la instal·lació diferida de mise: el primer llançament instal·la la CLI, i els llançaments posteriors la reutilitzen. mise també comprova si hi ha una nova versió d'un agent instal·lat com a màxim un cop cada quatre hores, just abans que arrenqui o en segon pla en un indicador de l'intèrpret d'ordres. Si aquesta actualització falla o no tens connexió, s'executa la versió instal·lada. `omarchy update` actualitza els agents instal·lats amb la resta d'Omarchy, i `mup` actualitza només les eines gestionades per mise.

Un actualitzador propi d'un agent, com ara `claude update`, `codex update` o un botó d'actualització en una aplicació, no actualitza la instal·lació gestionada per mise. `codex update` falla, i `claude update` pot dir que ha tingut èxit mentre instal·la una còpia separada que mise no segueix. Si prefereixes fer servir l'instal·lador i l'actualitzador natius d'un agent, afegeix-lo a `disable_tools`; consulta [Eines CLI preinstal·lades](18-development-tools.md#preinstalled-cli-tools).

Per instal·lar totes les eines diferides configurades abans de necessitar-les, executa `mise install --include-lazy`. Això inclou tant les altres eines CLI predeterminades d'Omarchy com els agents. Consulta [Eines CLI preinstal·lades](18-development-tools.md#preinstalled-cli-tools) per instal·lar una sola eina o fer servir la teva pròpia instal·lació.

`grok` s'instal·la mitjançant el paquet oficial `grok` de mise, de la mateixa manera que `claude` i `codex`. Executa `grok`, o tria'l a _Configuració > Valors predeterminats > Agent_. Omet l'instal·lador `curl | bash` de x.ai. Aquesta via posa una segona còpia a `~/.grok/bin`, l'afegeix al principi de `PATH` i sobreescriu el wrapper d'Omarchy.

`dsh` obre la seva interfície d'usuari del navegador a `127.0.0.1:3080`, amb el directori de llançament com a espai de treball predeterminat. La seva interfície del navegador no accepta cap indicació inicial, de manera que `omarchy agent prompt` l'obre amb la indicació al porta-retalls perquè l'enganxis. Omarchy l'engega amb el conjunt de permisos sense aprovació de DeepSeek. DeepSeek Harness puja els registres de sessió a DeepSeek quan fas servir la seva API oficial de models; desactiva-ho a _Settings > General > Upload Session Log_ a la seva interfície del navegador. Els comentaris que li enviïs també es pugen amb la sessió, tret que l'engeguis amb `DSH_TELEMETRY_MODE=DISABLED`.

### L'agent predeterminat

Tria el teu agent predeterminat amb `omarchy default agent <name>` o a _Configuració > Valors predeterminats > Agent_ al Menú d'Omarchy (`Super + Space`). Si l'agent encara no està instal·lat, en triar-lo s'instal·la primer. Un Omarchy acabat d'instal·lar t'invitarà a fer aquesta tria amb una notificació única.

Triar Claude també intenta configurar la seva extensió de navegador per a Chromium, Chrome, Brave, Brave Origin i Edge. La configuració de l'extensió s'aplica a tots els usuaris i pot demanar-te la contrasenya del sistema; cancel·lar-la o que la instal·lació de l'extensió falli no impedeix que Claude se seleccioni i s'engegui. Reinicia el navegador, activa l'extensió si t'ho demana i inicia sessió a Claude per acabar de connectar-la. Executa `/chrome` a Claude per comprovar la connexió. Firefox i Zen no admeten aquesta extensió. Si Claude ja era el teu predeterminat abans que s'afegís aquesta configuració, torna a seleccionar-lo per instal·lar l'extensió.

Un cop l'hagis triat, `Super + Shift + Ctrl + A` engega l'agent predeterminat en una finestra de terminal dedicada (o obre el selector si encara no n'has triat cap). També el pots engegar directament en una tasca amb `omarchy agent prompt "Review this project"`. Freebuff i DeepSeek Harness no accepten cap indicació inicial, de manera que s'obren amb la indicació al porta-retalls perquè l'enganxis. Els agents engegats d'aquesta manera funcionen sense supervisió en els seus respectius modes de no aturar-se a demanar, així que estigues preparat perquè realment facin coses! MiniMax Code no té un mode així per a les seves sessions interactives, de manera que demana permisos com de costum. I com que els agents es neguen a recordar la confiança per al teu directori personal, els llançaments des de `$HOME` arrenquen a `~/Work`.

També hi ha dreceres de terminal: `a` executa l'agent predeterminat en línia al terminal actual, mentre que `c`, `cx` i `cy` engeguen OpenCode, Claude Code i Codex directament (també en els seus modes d'aprovació automàtica). Els canvis de tema també se sincronitzen amb els agents: Claude Code, Pi, OpenCode i Hermes (un cop Omarchy l'ha instal·lat) segueixen el canvi quan canvies el tema d'Omarchy.

### El panell d'agents

La barra superior té una icona d'agents. Abans d'haver configurat un agent, el seu panell et guia per iniciar sessió a Claude, Codex o Grok, i el primer esdevé el teu agent predeterminat. Després d'això, el panell posa totes les subscripcions en una sola pàgina: cada agent i compte amb el seu pla, un mesurador per a cadascun dels seus límits de sessió de 5 hores i setmanal amb el temps que falta perquè es reiniciï (passa-hi el cursor per veure el percentatge exacte), o el saldo prepagat restant, sota una línia que va alternant entre el que has utilitzat en tots ells, com ara els tokens d'aquesta setmana i el teu model més utilitzat. A _Fes alguna cosa_ ofereix indicacions inicials per a un tema, un connector o una aplicació nous que passen la tasca al teu agent predeterminat. Les aplicacions es construeixen com les pròpies Hype, Monologue i Omacut d'Omarchy, en C++ i Qt Quick, seguint l'habilitat d'agent omarchy-app, i el compilador i les peces de Qt que necessiten venen instal·lats. Claude Code, Codex, Grok, Kimi, Cursor i la seva assignació de Grok Bot, GitHub Copilot, Muse, Antigravity, Kimchi i Devin estan coberts de sèrie amb els seus límits, i Hermes, Mistral Vibe i Qwen Code mostren les seves sessions i tokens un cop els has utilitzat. També hi apareixen els plans i les claus de proveïdors que fas servir mitjançant pi, omp o opencode: OpenCode Zen i Go, el Z.ai GLM Coding Plan, Ollama Cloud, el MiniMax Token Plan i Synthetic amb els seus límits; Fireworks, OpenRouter i DeepSeek amb els seus saldos prepagats; i els models que executes al teu propi maquinari a Local models. Cada agent es compta un sol cop, sota qui el facturi, independentment de quants harnesses facis servir per conduir-lo.

Fes clic amb el botó esquerre a la icona de la barra per obrir el panell, fes-hi clic amb el botó dret per engegar el teu agent predeterminat. Els registres d'ús que hi ha al darrere es regeneren cada 15 minuts amb `omarchy agent usage-update`, i el panell fins i tot pot fusionar l'ús de les teves altres màquines mitjançant una carpeta sincronitzada. Consulta el README a `$OMARCHY_PATH/shell/plugins/agents/` per veure tots els ajustaments.

### Diverses subscripcions

Si pagues més d'un pla de Claude, Codex o Grok —un Max personal i un de la feina, per exemple— Omarchy pot mantenir-los tots amb la sessió iniciada i moure's entre ells. Afegeix una subscripció amb el + al panell d'agents, que et guia allà mateix, o amb `omarchy agent account add claude Work` (o `codex`, o `grok`). Instal·la la CLI si falta. El primer compte d'un proveïdor inicia sessió mitjançant el teu navegador normal, just on la CLI sempre busca. Cada un dels següents inicia sessió mitjançant una finestra privada, de manera que el compte en què el teu navegador ja ha iniciat sessió no es reculli per error; inicia sessió allà com el compte que estàs afegint i tanca abans qualsevol finestra privada que ja tinguessis oberta. No tanquis mai la sessió de la CLI per fer això: tancar la sessió revoca l'inici de sessió desat, i aquell compte s'hauria d'afegir de nou.

Per copiar els teus inicis de sessió de subscripció a una altra màquina Omarchy per SSH, executa `omarchy agent account copy user@laptop`. L'emissor proporciona un receptor temporal quan la destinació no en té cap d'instal·lat, de manera que les màquines Omarchy més antigues poden rebre comptes sense una actualització. Els receptors instal·lats tenen precedència. Això copia totes les subscripcions de Claude, Codex i Grok; afegeix noms de proveïdors per seleccionar-les, com a `omarchy agent account copy laptop claude`. Els noms de compte i els ID d'ordre coincideixen amb l'origen, inclosos els comptes que ja hi ha a la destinació. Els comptes de destinació no relacionats reben un sufix numèric si els seus noms entren en conflicte, i els ajustaments, les habilitats, els connectors i l'historial de converses es queden locals a cada màquina.

Les credencials existents de la destinació es conserven. Un compte d'origen que ja ha iniciat sessió allà veu sincronitzat el seu nom sense que se substitueixin les seves credencials; els altres comptes s'hi afegeixen al costat. Per substituir les credencials desades dels comptes coincidents, fes servir `omarchy agent account copy --replace laptop claude` després de tancar les sessions d'aquell compte a la destinació. Una destinació nova també rep el compte actiu i les preferències de canvi de l'origen; una destinació establerta conserva els seus propis.

Les credencials viatgen per SSH i s'emmagatzemen en fitxers privats a la destinació, de manera que copia-les només a màquines en què confiïs. Això és una còpia única, no una sincronització contínua. Els tokens d'actualització de Codex poden ser rotats per una altra màquina, i això deixa un inici de sessió copiat amb necessitat de renovació; els inicis de sessió separats continuen sent l'opció més fiable per a un ús simultani en diverses màquines. Consulta la [guia d'autenticació de comptes de Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Un compte per proveïdor està actiu, i cada sessió nova comença com a tal: `cx`, `cy`, un `claude`, `codex` o `grok` sense més, qualsevol cosa engegada mitjançant `omarchy agent`, i els scripts o editors que troben la CLI a `PATH`. Canvia amb `omarchy agent account use work` (i torna amb `omarchy agent account use main`), o al panell prement el número d'un compte i després `Enter` (o fent clic al seu botó Use). Les sessions que ja estan en execució es queden amb el compte amb què van començar. L'historial de converses, els ajustaments, les habilitats i els connectors es comparteixen entre comptes, de manera que `claude --continue` a la mateixa carpeta continua on ho vas deixar amb el compte nou.

Amb més d'un compte, el panell mostra els límits de cada compte l'un al costat de l'altre, amb l'actiu marcat. Per defecte, Omarchy t'avisa quan el compte actiu supera el 95% d'un límit, i en fer clic a la notificació es canvia al compte amb més marge. Passa el cursor per sobre de la línia d'un compte al panell i fes clic a l'Autoswitch que apareix al costat de Use (o prem `m`), o executa `omarchy agent account mode auto`, perquè canviï pel seu compte; mentre està activat, Autoswitch ocupa el lloc de Use, i en fer-hi clic de nou es torna a l'avís. Afegeix un número per canviar el llindar, com a `omarchy agent account mode auto 90`. Si tots els comptes superen el llindar, te n'assabentaràs un sol cop, juntament amb quin compte s'allibera primer. Mentre un compte actiu és a menys de 15 punts del seu llindar (80% amb el valor predeterminat), els seus límits es comproven cada tres minuts en lloc de cada 15.

`omarchy agent account list` mostra tots els comptes i els seus últims límits, `omarchy agent account remove work` n'oblida un, i `omarchy agent account rename primary Hey` en reanomena un (o fes clic al nom d'un compte al panell). Aquestes ordres funcionen amb els comptes del teu agent predeterminat; per arribar a l'altre proveïdor, nomena'l primer, com a `omarchy agent account use codex side`. L'inici de sessió que ja tenies a `~/.claude` o `~/.codex` és el compte _Main_ i es queda on és. Un compte que no s'ha utilitzat durant més d'unes vuit hores pot mostrar _Sign-in required_; fes-hi clic per tornar a iniciar sessió en aquell compte directament al panell, o engega una sessió en ell, que actualitza l'inici de sessió pel seu compte. Els servidors MCP que tenies quan es va afegir un compte l'acompanyen, però els que afegeixis més tard amb `claude mcp add` només arriben al compte en què els vas afegir. Claude Desktop i les eines configurades amb una ruta absoluta a un binari de CLI no segueixen el canvi. Un `CLAUDE_CONFIG_DIR`, `CODEX_HOME` o `GROK_HOME` explícit té precedència sobre el compte seleccionat.

### Diagnòstic de fallades

Omarchy vigila systemd-coredump per detectar fallades de processos. Quan alguna cosa fa una fallada de segmentació, rebràs una notificació «Process crashed» —fes-hi clic i la fallada es lliura al teu agent predeterminat juntament amb l'habilitat diagnose-crash d'Omarchy, que guia l'agent per establir els fets a partir del bolcat de memòria i decidir si val la pena informar de la fallada a upstream. També la pots executar manualment contra qualsevol PID de `coredumpctl list` amb `omarchy agent crash <pid>`.

La vigilància està activada per defecte. Desactiva-la a _Disparador > Commuta > Captura de fallades_ (o amb `omarchy toggle crash-capture`) i les notificacions s'aturen; `omarchy agent crash <pid>` continua funcionant manualment.

Les fallades també es poden silenciar programa a programa, que és el que el diagnòstic t'ofereix al final. `omarchy crash mute hyprland` atura les notificacions només per a aquell programa, `omarchy crash mute hyprland off` les recupera, i `omarchy crash mute` tot sol enumera el que has silenciat. Accepta la ruta del binari tan bé com el seu nom, de manera que `omarchy crash mute /usr/bin/hyprland` fa el mateix. Posa entre cometes un nom amb un espai, com a `omarchy crash mute 'Some App'`. Tota la resta continua notificant, i el programa silenciat continua fallant —això amaga el recordatori, no arregla res.

### Aplicacions d'escriptori

El menú _Instal·la > IA_ també inclou algunes aplicacions gràfiques d'IA: l'aplicació d'escriptori de ChatGPT, l'aplicació d'escriptori de Claude (la beta per a Linux d'Anthropic, amb pestanyes Chat, Cowork i Claude Code), Grok Bot per xatejar amb els models de xAI, Hermes Desktop, OpenClaw, l'aplicació d'escriptori de Perplexity i T3 Code. Grok Bot és l'aplicació de xat d'escriptori. L'agent de programació és l'ordre `grok`.

Hermes Desktop és la que cal conèixer, perquè una màquina té un sol Hermes, i és el de l'aplicació: Hermes només s'instal·la mai mitjançant l'aplicació, i l'ordre `hermes` que executa l'agent predeterminat és la de l'aplicació. Triar Hermes com a agent predeterminat instal·la el mateix que instal·la l'entrada _Instal·la > IA_: el paquet i un entorn d'execució de Hermes a `~/.hermes` configurat pel propi instal·lador de Hermes, que triga uns minuts el primer cop. Aquell entorn d'execució és l'únic Hermes que fan servir l'ordre `hermes` del terminal, l'agent predeterminat i l'aplicació, i s'actualitza amb `hermes update` en lloc d'esperar una versió d'Omarchy. En instal·lar-lo també es lliura a Hermes el tema d'Omarchy com una aparença anomenada `omarchy`, que totes les superfícies de Hermes segueixen quan canvies de tema; tria'n una altra als ajustaments d'Appearance de Hermes o amb `/skin` si prefereixes que no ho faci, i Omarchy respecta aquesta tria. Eliminar l'aplicació a _Elimina > IA_ tanca Hermes primer, gateway inclòs, s'emporta aquell entorn d'execució i conserva els teus xats, records i les habilitats que Hermes va escriure per a si mateix tret que li diguis el contrari: et pregunta, amb no com a resposta predeterminada, si aquestes dades i els teus ajustaments de connexió també han de desaparèixer.

L'experiència d'escriptori d'OpenClaw és la seva Control UI, que s'obre com una aplicació web amb el suport del seu propi gateway local. OpenClaw viu a `~/.openclaw` i s'actualitza sol: fes servir el botó "Update Gateway" de la Control UI o executa `openclaw update`, i el gateway es reinicia amb la versió nova. Omarchy només tria la versió amb què comença una instal·lació nova. Eliminar OpenClaw a _Elimina > IA_ s'emporta el servei de gateway i l'aplicació i després et pregunta si `~/.openclaw` també ha de desaparèixer, ja que allà hi ha els teus xats i credencials juntament amb el propi OpenClaw i els entorns d'execució de connectors que descarrega; el valor predeterminat el conserva, i si tornes a instal·lar OpenClaw el recupera.

T3 Code s'executa des de la seva versió oficial en AppImage a `~/.local/share/t3code` en lloc de des d'un paquet, de manera que s'actualitza sol. En instal·lar-lo et pregunta si vols començar al canal Stable o Nightly; canvia-ho més tard als ajustaments de T3 Code. Els teus fils i ajustaments viuen a `~/.t3`, i eliminar T3 Code a _Elimina > IA_ se'ls emporta.

### LLM locals

Omarchy recomana dues maneres d'executar models LLM locals: LM Studio i Ollama. LM Studio proporciona una interfície gràfica per trobar models de pesos oberts, instal·lar-los i executar-los. És una bona manera de començar fàcilment. Ollama ofereix una CLI per fer-ho de manera similar. Però si ets nou en els models locals, jo començaria amb LM Studio. Pots instal·lar qualsevol dels dos a _Instal·la > IA_ al Menú d'Omarchy.

### L'habilitat d'Omarchy

Les habilitats d'agent ajuden la IA a fer servir eines específiques d'una manera específica, i Omarchy inclou una habilitat predeterminada per adaptar el sistema a mida. Com ara retocar la teva configuració de Hyprland, ajustar la barra o fins i tot crear un tema nou des de zero. Està enllaçada simbòlicament als directoris d'habilitats de Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` i cada `~/.hermes/profiles/*/skills`) i la ubicació genèrica `~/.agents/skills`, de manera que la majoria de harnesses la recullen automàticament.

Però hauries de tractar aquesta habilitat com a experimental. Els diferents models la faran servir amb efectes diferents. És millor executar-la primer en mode de planificació, perquè tinguis una idea del que l'agent voldria canviar. I després estigues preparat per revertir els canvis o fins i tot invocar `omarchy reinstall configs`, si l'agent ho espatlla tot.
