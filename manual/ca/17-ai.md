# IA

Omarchy tracta els agents de codificació d'IA com a ciutadans de primera classe, però no en tria un favorit per tu. En lloc d'això, cada CLI important d'agent de codificació ve precablejat com a llançador de càrrega diferida. Els llançadors són petits stubs gestionats per [mise](https://mise.jdx.dev/) a `~/.local/bin/`, de manera que no es descarrega res fins la primera vegada que n'executes un de debò. Hermes n'és l'excepció: no se'n crea cap stub, i triar-lo instal·la Hermes Desktop, com explica _Aplicacions d'escriptori_ més avall. Invoca'n qualsevol i autentica't quan t'ho demani:

| Ordre    | Agent                                                            |
|------------|------------------------------------------------------------------|
| `claude`   | [Claude Code](https://code.claude.com/docs/en/overview)          |
| `codex`    | [OpenAI Codex](https://github.com/openai/codex)                  |
| `opencode` | [OpenCode](https://opencode.ai/)                                 |
| `agy`      | [Google Antigravity CLI](https://github.com/google-antigravity/antigravity-cli) |
| `copilot`  | [GitHub Copilot CLI](https://github.com/github/copilot-cli)      |
| `crush`    | [Crush](https://github.com/charmbracelet/crush)                  |
| `grok`     | [Grok Build](https://x.ai/build) de xAI                        |
| `kimi`     | [Kimi Code](https://www.kimi.com/code/docs/en/)                  |
| `pi`       | [Pi de Mario Zechner](https://github.com/badlogic/pi-mono)        |
| `omp`      | [Oh My Pi](https://github.com/can1357/oh-my-pi)                  |
| `ori`      | [Ori](https://openrouter.ai/docs/guides/ori/harness), el harness d'OpenRouter |
| `hermes`   | [Hermes](https://hermes-agent.nousresearch.com/), l'agent de Nous Research  |
| `muse`     | [Muse Code](https://dev.meta.ai), l'agent de codificació de Meta           |
| `cursor-agent` | [Cursor CLI](https://cursor.com/cli)                         |

`ori` és el rar de la colla: executa els altres harnesses contra tot el catàleg de models d'OpenRouter, de manera que `ori claude`, `ori codex` o `ori opencode` inicien aquests agents amb el model que els indiquis, i `ori code` és l'agent propi d'Ori.

Per embolcallar una CLI addicional de la mateixa manera, executa `omarchy-mise-install <package> [command-name]`. Els stubs es mantenen al dia juntament amb tot el que gestiona mise quan executes `omarchy update` (o l'àlies `mup`).

`grok` s'instal·la mitjançant el paquet `grok` de primera part de mise, de la mateixa manera que `claude` i `codex`. Executa `grok`, o tria'l a _Configuració > Valors per defecte > Agent_. Salta't l'instal·lador `curl | bash` de x.ai. Aquest camí posa una segona còpia a `~/.grok/bin`, la anteposa a `PATH` i sobreescriu l'embolcallador d'Omarchy.

### L'agent per defecte

Tria l'agent per defecte amb `omarchy default agent <name>` o a _Configuració > Valors per defecte > Agent_ al menú d'Omarchy (`Super + Space`). Si l'agent encara no està instal·lat, triar-lo l'instal·la primer. Un Omarchy acabat d'instal·lar t'invitarà a fer aquesta tria amb una notificació única.

Triar Claude també intenta configurar la seva extensió de navegador per a Chromium, Chrome, Brave, Brave Origin i Edge. La configuració de l'extensió s'aplica a tots els usuaris i pot demanar-te la contrasenya del sistema; cancel·lar o que falli la instal·lació de l'extensió igualment selecciona i llança Claude. Reinicia el navegador, activa l'extensió si t'ho demana i inicia sessió a Claude per acabar de connectar-la. Executa `/chrome` a Claude per comprovar la connexió. Firefox i Zen no admeten aquesta extensió. Si Claude ja era el teu agent per defecte abans que s'afegís aquesta configuració, torna'l a seleccionar per instal·lar l'extensió.

[Muse Code](https://dev.meta.ai) — el `muse` de Meta — utilitza un stub de mise preinstal·lat com els altres agents. Triar-lo com a agent per defecte instal·la el llançador oficial de Meta mitjançant el backend HTTP de mise. El llançador verifica i actualitza el binari natiu per a la teva màquina.

Un cop hagis triat, `Super + Shift + Ctrl + A` llança l'agent per defecte en una finestra de terminal dedicada (o obre el selector si encara no n'has triat cap). També el pots llançar directament a fer una tasca amb `omarchy agent prompt "Review this project"`. Els agents llançats així funcionen sense supervisió en els seus respectius modes de no aturar-se a preguntar, així que estigues preparat perquè realment facin coses! I com que els agents es neguen a recordar la confiança per al teu directori personal, els llançaments des de `$HOME` s'inicien a `~/Work` en lloc d'allà.

També hi ha dreceres de terminal: `a` executa l'agent per defecte en línia al terminal actual, mentre que `c`, `cx` i `cy` inicien OpenCode, Claude Code i Codex directament (també en els seus modes d'aprovació automàtica). Els canvis de tema també se sincronitzen amb els agents: Claude Code, Pi, OpenCode i Hermes (un cop Omarchy l'ha instal·lat) segueixen el canvi quan canvies el tema d'Omarchy.

### El panell d'agents

La barra superior té una icona d'agents. Abans d'haver configurat un agent, el seu panell et guia per iniciar sessió a Claude, Codex o Grok, i el primer esdevé el teu agent per defecte. Després d'això, el panell posa cada subscripció en una sola pàgina: cada agent i compte amb el seu pla, un mesurador per a cadascun dels seus límits de sessió de 5 hores i setmanals amb el temps restant fins que es restableixi (passa-hi el cursor per veure el percentatge exacte), o el saldo de prepagament restant, sota una línia que rota pel que has utilitzat en tots ells, com els tokens d'aquesta setmana i el model que més utilitzes. A _Crea alguna cosa_ ofereix prompts inicials per a un tema, connector o aplicació nous que passen la tasca al teu agent per defecte. Les aplicacions es construeixen de la manera com es construeixen Hype, Monologue i Omacut d'Omarchy, en C++ i Qt Quick, seguint la skill d'agent omarchy-app, i el compilador i les peces de Qt que necessiten vénen instal·lats. Claude Code, Codex, Grok, Fireworks i Kimi estan coberts de sèrie. Actualment Kimi informa dels límits de quota del compte sense estadístiques locals de tokens ni de prompts.

Fes clic amb el botó esquerre a la icona de la barra per al panell, i amb el botó dret per llançar l'agent per defecte. Els registres d'ús que hi ha al darrere es regeneren cada 15 minuts amb `omarchy agent usage-update`, i el panell fins i tot pot fusionar l'ús de les teves altres màquines mitjançant una carpeta sincronitzada. Consulta el README a `$OMARCHY_PATH/shell/plugins/agents/` per veure tots els ajusts.

### Diverses subscripcions

Si pagues més d'un pla de Claude, Codex o Grok — un Max personal i un de la feina, posem per cas — Omarchy pot mantenir-los tots amb la sessió iniciada i moure's entre ells. Afegeix una subscripció amb el + del panell d'agents, que et guia allà mateix, o amb `omarchy agent account add claude Work` (o `codex`, o `grok`). Instal·la la CLI si falta. El primer compte d'un proveïdor inicia sessió mitjançant el teu navegador normal, just on la CLI sempre mira. Tots els següents inicien sessió mitjançant una finestra privada, perquè el compte amb el qual el navegador ja ha iniciat sessió no es reculli per error; inicia-hi sessió com el compte que estàs afegint, i tanca primer qualsevol finestra privada que ja tinguessis oberta. No tanquis mai la sessió de la CLI per fer això: tancar la sessió revoca l'inici de sessió desat, i caldria tornar a afegir aquell compte.

Per copiar els inicis de sessió de les teves subscripcions a una altra màquina Omarchy mitjançant SSH, executa `omarchy agent account copy user@laptop`. L'emissor proporciona un receptor temporal quan la destinació no en té cap d'instal·lat, de manera que les màquines Omarchy més antigues poden rebre comptes sense una actualització. Els receptors instal·lats tenen precedència. Això copia totes les subscripcions de Claude, Codex i Grok; afegeix noms de proveïdor per seleccionar-les, com a `omarchy agent account copy laptop claude`. Els noms de compte i els ID d'ordre coincideixen amb l'origen, inclosos els comptes ja presents a la destinació. Els comptes de destinació no relacionats reben un sufix numèric si els seus noms entren en conflicte, i els ajusts, les skills, els connectors i l'historial de converses es queden locals a cada màquina.

Les credencials de destinació existents es conserven. Un compte d'origen que ja ha iniciat sessió allà veu sincronitzat el seu nom sense substituir les seves credencials; els altres comptes s'afegeixen al seu costat. Per substituir les credencials desades dels comptes coincidents, utilitza `omarchy agent account copy --replace laptop claude` després de tancar les sessions d'aquell compte a la destinació. Una destinació nova també rep el compte actiu i les preferències de canvi de l'origen; una destinació ja establerta conserva les seves.

Les credencials viatgen mitjançant SSH i s'emmagatzemen en fitxers privats a la destinació, així que copia-les només a màquines de confiança. Això és una còpia única, no una sincronització contínua. Els tokens d'actualització de Codex poden ser rotats per una altra màquina, i deixar un inici de sessió copiat amb necessitat de renovació; els inicis de sessió separats continuen sent l'opció més fiable per a l'ús simultani en diverses màquines. Consulta la [guia d'autenticació de comptes de Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Un compte per proveïdor està actiu, i cada sessió nova comença com a tal: `cx`, `cy`, un `claude`, `codex` o `grok` sense més, qualsevol cosa llançada mitjançant `omarchy agent`, i scripts o editors que troben la CLI a `PATH`. Canvia'l amb `omarchy agent account use work` (i torna enrere amb `omarchy agent account use main`), o al panell prement el número d'un compte i després `Enter` (o fent clic al seu botó Usa). Les sessions que ja s'estan executant romanen amb el compte amb el qual van començar. L'historial de converses, els ajusts, les skills i els connectors es comparteixen entre comptes, de manera que `claude --continue` a la mateixa carpeta reprèn on ho havies deixat amb el compte nou.

Amb més d'un compte, el panell mostra els límits de cada compte l'un al costat de l'altre, amb l'actiu marcat. Per defecte, Omarchy t'avisa quan el compte actiu supera el 95% d'un límit, i fer clic a la notificació canvia al compte amb més marge. Passa el cursor per sobre la línia d'un compte al panell i fes clic al Canvi automàtic que apareix al costat d'Usa (o prem `m`), o executa `omarchy agent account mode auto`, perquè canviï tot sol; mentre està activat, el Canvi automàtic ocupa el lloc d'Usa, i tornar-hi a fer clic torna a avisar. Afegeix un número per canviar el llindar, com a `omarchy agent account mode auto 90`. Si tots els comptes superen el llindar, te n'avisarà un cop, juntament amb quin compte s'allibera primer. Mentre un compte actiu està a 15 punts del seu llindar (80% per defecte), els seus límits es comproven cada tres minuts en lloc de cada 15.

`omarchy agent account list` mostra cada compte i els seus límits més recents, `omarchy agent account remove work` n'oblida un, i `omarchy agent account rename primary Hey` en reanomena un (o fes clic al nom d'un compte al panell). Aquestes ordres funcionen amb els comptes del teu agent per defecte; per arribar a l'altre proveïdor, anomena'l primer, com a `omarchy agent account use codex side`. L'inici de sessió que ja tenies a `~/.claude` o `~/.codex` és el compte _Principal_ i es queda on és. Un compte que fa més d'unes vuit hores que no s'utilitza pot mostrar _Cal iniciar sessió_; fes-hi clic per tornar a iniciar sessió amb aquell compte allà mateix al panell, o inicia-hi una sessió, cosa que renova l'inici de sessió tot sol. Els servidors MCP que tenies quan es va afegir un compte l'acompanyen, però els que afegeixes més tard amb `claude mcp add` només arriben al compte en què els has afegit. Claude Desktop i les eines configurades amb una ruta absoluta a un binari de CLI no segueixen el canvi. Un `CLAUDE_CONFIG_DIR`, `CODEX_HOME` o `GROK_HOME` explícit té precedència sobre el compte seleccionat.

### Diagnòstic de fallades

Omarchy vigila systemd-coredump per detectar fallades de processos. Quan alguna cosa fa segfault, rebràs una notificació "Un procés ha fallat" — fes-hi clic, i la fallada es passa al teu agent per defecte juntament amb la skill diagnose-crash d'Omarchy, que guia l'agent per establir els fets a partir del core dump i decidir si val la pena informar de la fallada upstream. També la pots executar manualment contra qualsevol PID de `coredumpctl list` amb `omarchy agent crash <pid>`.

La vigilància està activada per defecte. Desactiva-la a _Activa > Commuta > Captura de fallades_ (o amb `omarchy toggle crash-capture`) i les notificacions s'aturaran; `omarchy agent crash <pid>` encara funciona manualment.

Les fallades també es poden silenciar programa a programa, que és el que t'ofereix el diagnòstic al final. `omarchy crash mute hyprland` atura les notificacions només per a aquell programa, `omarchy crash mute hyprland off` les restableix, i `omarchy crash mute` per si sol llista el que has silenciat. Accepta la ruta del binari tan de bon grat com el seu nom, de manera que `omarchy crash mute /usr/bin/hyprland` fa el mateix. Posa entre cometes un nom amb un espai, com a `omarchy crash mute 'Some App'`. Tot la resta encara avisa, i el programa silenciat encara falla — això amaga el recordatori, no arregla res.

### Aplicacions d'escriptori

El menú _Instal·la > IA_ també inclou unes quantes aplicacions gràfiques d'IA: l'aplicació d'escriptori de ChatGPT, l'aplicació d'escriptori de Claude (la beta per a Linux d'Anthropic, amb pestanyes de Chat, Cowork i Claude Code), Grok Bot per xatejar amb els models de xAI, Hermes Desktop, OpenClaw i l'aplicació d'escriptori de Perplexity. Grok Bot és l'aplicació de xat d'escriptori. L'agent de codificació és l'ordre `grok`.

Hermes Desktop és la que cal conèixer, perquè una màquina té un Hermes, i és el de l'aplicació: Hermes només s'instal·la mai mitjançant l'aplicació, i l'ordre `hermes` que executa l'agent per defecte és la de l'aplicació. Triar Hermes com a agent per defecte instal·la el mateix que instal·la l'entrada _Instal·la > IA_: el paquet, i un runtime d'Hermes a `~/.hermes` configurat pel propi instal·lador d'Hermes, que triga uns minuts la primera vegada. Aquest runtime és l'únic Hermes que utilitzen l'ordre `hermes` del terminal, l'agent per defecte i l'aplicació, i s'actualitza tot sol amb `hermes update` en lloc d'esperar una versió d'Omarchy. Instal·lar-lo també dona a Hermes el tema d'Omarchy com una skin anomenada `omarchy`, que cada superfície d'Hermes segueix a mesura que canvies de tema; tria'n una altra als ajusts d'Aparença d'Hermes o amb `/skin` si prefereixes que no ho faci, i Omarchy deixarà aquesta tria en pau. Eliminar l'aplicació a _Elimina > IA_ tanca Hermes primer, gateway inclosa, s'emporta aquell runtime amb ell, i conserva els teus xats, records i les skills que Hermes s'ha escrit per a si mateix llevat que li diguis el contrari: pregunta, amb el no per defecte, si aquestes dades i els teus ajusts de connexió també han d'anar-se'n.

L'experiència d'escriptori d'OpenClaw és la seva Control UI, que s'obre com a aplicació web recolzada per la seva pròpia gateway local. OpenClaw viu a `~/.openclaw` i s'actualitza tot sol: utilitza el botó "Update Gateway" de la Control UI o executa `openclaw update`, i la gateway es reinicia amb la versió nova. Omarchy només tria la versió amb la qual comença una instal·lació nova. Eliminar OpenClaw a _Elimina > IA_ s'emporta el servei de gateway i l'aplicació amb ell i després pregunta si `~/.openclaw` també ha d'anar-se'n, ja que això conté els teus xats i credencials juntament amb el propi OpenClaw i els runtimes de connectors que descarrega; per defecte es conserva, i tornar a instal·lar OpenClaw el torna a recollir.

### LLM locals

Omarchy recomana dues maneres d'executar models LLM locals: LM Studio i Ollama. LM Studio proporciona una interfície GUI per trobar models de pesos oberts, instal·lar-los i executar-los. És una bona manera de començar fàcilment. Ollama ofereix una CLI per fer-ho de manera similar. Però si ets nou en models locals, jo començaria amb LM Studio. Pots instal·lar qualsevol dels dos a _Instal·la > IA_ al menú d'Omarchy.

### La skill d'Omarchy

Les skills d'agent ajuden la IA a utilitzar eines específiques d'una manera específica, i Omarchy inclou una skill per defecte per personalitzar el sistema. Com retocar la configuració de Hyprland, ajustar la barra o fins i tot crear un tema nou des de zero. Està enllaçada simbòlicament als directoris de skills de Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` i cada `~/.hermes/profiles/*/skills`), i la ubicació genèrica `~/.agents/skills`, de manera que la majoria de harnesses la recullen automàticament.

Però has de tractar aquesta skill com a experimental. Models diferents la utilitzaran amb efectes diferents. Val més executar primer en mode de planificació, perquè tinguis una idea del que l'agent voldria canviar. I després estigues preparat per revertir canvis o fins i tot invocar `omarchy reinstall configs`, si l'agent ho fa tot un embolic.
