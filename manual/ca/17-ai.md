Executa una ordre per instal·lar-ne la CLI el primer cop que l'utilitzis i autentica't quan se't demani. ### Instal·lació i actualització d'agents

Llevat d'Hermes i OpenClaw, aquests agents utilitzen la instal·lació diferida de mise: el primer llançament instal·la la CLI i els llançaments posteriors la reutilitzen. mise també comprova si hi ha una versió nova d'un agent instal·lat com a molt un cop cada quatre hores, just abans que s'iniciï o en segon pla en un indicador de l'intèrpret d'ordres. Si aquesta actualització falla o no tens connexió, s'executa la versió instal·lada. `omarchy update` actualitza els agents instal·lats amb la resta d'Omarchy, i `mup` actualitza només les eines gestionades per mise.

L'actualitzador propi d'un agent, com ara `claude update`, `codex update` o un botó d'actualització en una aplicació, no actualitza la instal·lació gestionada per mise. `codex update` falla, i `claude update` pot informar que ha tingut èxit mentre instal·la una còpia separada que mise no segueix. Si prefereixes utilitzar l'instal·lador i l'actualitzador natius d'un agent, afegeix-lo a `disable_tools`; vegeu [Eines de CLI preinstal·lades](18-development-tools.md#preinstalled-cli-tools).

Per instal·lar totes les eines diferides configurades abans que les necessitis, executa `mise install --include-lazy`. Això inclou les altres eines de CLI predeterminades d'Omarchy, a més dels agents. Vegeu [Eines de CLI preinstal·lades](18-development-tools.md#preinstalled-cli-tools) per instal·lar una sola eina o utilitzar la teva pròpia instal·lació.

`grok` s'instal·la mitjançant el paquet de primera mà `grok` de mise, de la mateixa manera que `claude` i `codex`. Executa `grok`, o tria'l a _Agent > Harness_. Omet l'instal·lador `curl | bash` de x.ai. Aquesta via posa una segona còpia a `~/.grok/bin`, la posa al davant a `PATH` i sobreescriu l'embolcall d'Omarchy.

`dsh` obre la seva interfície de navegador a `127.0.0.1:3080`, amb el directori de llançament com a espai de treball predeterminat. La seva interfície de navegador no accepta cap indicació inicial, de manera que `omarchy agent prompt` l'obre amb la indicació al porta-retalls perquè l'enganxis. Omarchy l'inicia amb el predefinit de permisos sense aprovació de DeepSeek. DeepSeek Harness puja els registres de sessió a DeepSeek quan utilitzes la seva API oficial de models; desactiva-ho a _Settings > General > Upload Session Log_ a la seva interfície de navegador. Els comentaris que li enviïs també es pugen amb la sessió, llevat que l'iniciïs amb `DSH_TELEMETRY_MODE=DISABLED`.

### L'agent predeterminat

Tria el teu agent predeterminat amb `omarchy default agent <name>` o a _Agent > Harness_ al Menú d'Omarchy (`Super + Space`). Si l'agent encara no està instal·lat, triar-lo l'instal·la primer, i també rep el seu propi llançador al llançador d'aplicacions, al costat d'Agent. Un Omarchy acabat d'instal·lar t'invitarà a fer aquesta tria amb una notificació única.

Triar Claude també intenta configurar la seva extensió de navegador per a Chromium, Chrome, Brave, Brave Origin i Edge. La configuració de l'extensió s'aplica a tots els usuaris i pot demanar-te la contrasenya del sistema; cancel·lar o que la instal·lació de l'extensió falli no impedeix que Claude sigui seleccionat i llançat. Reinicia el navegador, activa l'extensió si se't demana i inicia sessió a Claude per acabar de connectar-la. Executa `/chrome` a Claude per comprovar la connexió. Firefox i Zen no admeten aquesta extensió. Si Claude ja era el teu predeterminat abans que s'afegís aquesta configuració, selecciona'l de nou per instal·lar l'extensió.

Un cop l'hagis triat, `Super + Shift + Ctrl + A` llança l'agent predeterminat en una finestra de terminal dedicada (o obre el selector si encara no n'has triat cap). També el pots llançar directament en una tasca amb `omarchy agent prompt "Review this project"`. Freebuff i DeepSeek Harness no accepten cap indicació inicial, de manera que s'obren amb la indicació al porta-retalls perquè l'enganxis. Els agents llançats d'aquesta manera s'executen sense supervisió en els seus respectius modes de no aturar-se a demanar, així que estigues preparat perquè realment facin coses! MiniMax Code no té cap mode així per a les seves sessions interactives, de manera que demana permisos com de costum. I com que els agents es neguen a recordar la confiança per al teu directori d'inici, els llançaments des de `$HOME` comencen a `~/Work`.

També hi ha dreceres de terminal: `a` executa l'agent predeterminat en línia al terminal actual, mentre que `c`, `cx` i `cy` inicien OpenCode, Claude Code i Codex directament (també en els seus modes d'aprovació automàtica). Els canvis de tema també se sincronitzen amb els agents: Claude Code, Pi, OpenCode i Hermes (un cop Omarchy l'ha instal·lat) segueixen el canvi quan canvies el tema d'Omarchy.

### Les teves instruccions per a l'agent

Les regles personals per a cada agent van a `~/.agents/AGENTS.md`, al costat de les habilitats compartides a `~/.agents/skills`. Obre'l a _Agent > Instructions_, que també l'enllaça a cada harness que manté el seu propi fitxer global: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, el `~/.copilot/copilot-instructions.md` de Copilot, i així successivament. Crush i Amp llegeixen l'enllaç `~/.config/AGENTS.md`, mentre que omp, Kimi i DeepSeek Harness llegeixen directament `~/.agents/AGENTS.md`. Triar un agent predeterminat també l'enllaça. Un fitxer d'instruccions que ja tenies es converteix en el compartit si encara no n'hi havia cap; en cas contrari, es conserva al costat de l'enllaç com a `.bak`. Executa `omarchy agent instructions` per tornar a enllaçar després d'instal·lar un altre agent.

### El panell d'agents

La barra superior té una icona d'agents. Abans d'haver configurat un agent, el seu panell et guia per iniciar sessió a Claude, Codex o Grok, i el primer es converteix en el teu agent predeterminat. Després d'això, el panell posa cada subscripció en una sola pàgina: cada agent i compte amb el seu pla, un mesurador per a cadascun dels seus límits de sessió de 5 hores i setmanal amb el temps que falta perquè es restableixi (passa el cursor per sobre per veure el percentatge exacte), o el saldo prepagat restant, sota una línia que rota per allò que has utilitzat entre tots ells, com ara els tokens d'aquesta setmana i el teu model més utilitzat. A _Make something cool_ ofereix indicacions inicials per a un tema, un connector, una aplicació o un joc nous que passen la tasca al teu agent predeterminat. Les aplicacions es construeixen com les pròpies Hype, Monologue i Omacut d'Omarchy, en C++ i Qt Quick, seguint l'habilitat d'agent omarchy-make-app, i el compilador i les peces de Qt que necessiten ja venen instal·lats. Els jocs són una sola pàgina de three.js a `~/Games/vibes`, seguint l'habilitat d'agent omarchy-make-game, i tots s'obren des d'un únic llançador Game Vibes amb el tema actual; carreguen three.js des del web, de manera que necessiten connexió per arrencar. Claude Code, Codex, Grok, Kimi, Cursor i la seva assignació Grok Bot, GitHub Copilot, Muse, Antigravity i Devin estan coberts de fàbrica amb els seus límits, Kimchi amb el seu pla, crèdits prepagats i pressupostos de despesa, i Hermes, Mistral Vibe i Qwen Code mostren les seves sessions i tokens un cop els has utilitzat. Els plans i les claus de proveïdors que utilitzes mitjançant pi, omp o opencode també hi apareixen: OpenCode Zen i Go, el Z.ai GLM Coding Plan, Ollama Cloud, el MiniMax Token Plan i Synthetic amb els seus límits; OpenRouter i DeepSeek amb els seus saldos prepagats; Fireworks amb la seva despesa dels darrers 30 dies. Els tokens dels models que executes al teu propi maquinari també compten per als totals; els models mateixos tenen un panell propi, descrit a [Models locals](#local-models). Cada agent es compta una sola vegada, sota qui el factura, per molts harnesses a través dels quals l'utilitzis.

Fes clic amb el botó esquerre a la icona de la barra o prem `Super + Ctrl + X` per al panell, fes clic amb el botó dret per llançar el teu agent predeterminat i fes clic amb el botó del mig per actualitzar-lo. Els registres d'ús que hi ha al darrere es regeneren cada 15 minuts amb `omarchy agent usage update`, i el panell fins i tot pot fusionar l'ús d'altres màquines teves mitjançant una carpeta sincronitzada. Vegeu el README a `$OMARCHY_PATH/shell/plugins/agents/` per a tota la configuració.

### Diverses subscripcions

Si pagues més d'un pla de Claude, Codex o Grok — un Max personal i un de feina, per exemple — Omarchy pot mantenir-los tots amb la sessió iniciada i moure's entre ells. Afegeix una subscripció amb el + del panell d'agents, que t'hi guia allà mateix, o amb `omarchy agent account add claude Work` (o `codex`, o `grok`). Instal·la la CLI si falta. El primer compte d'un proveïdor inicia sessió mitjançant el teu navegador normal, allà mateix on la CLI sempre mira. Cada un dels següents inicia sessió mitjançant una finestra privada, de manera que el compte en què el teu navegador ja ha iniciat sessió no s'agafi per error; inicia-hi sessió com el compte que estàs afegint i tanca abans qualsevol finestra privada que ja tinguessis oberta. No tanquis mai la sessió de la CLI per fer això: tancar la sessió revoca l'inici de sessió desat, i aquest compte s'hauria d'afegir de nou.

Per copiar els teus inicis de sessió de subscripció a una altra màquina Omarchy per SSH, executa `omarchy agent account copy user@laptop`. L'emissor proporciona un receptor temporal quan la destinació no en té cap d'instal·lat, de manera que les màquines Omarchy més antigues poden rebre comptes sense una actualització. Els receptors instal·lats tenen precedència. Això copia totes les subscripcions de Claude, Codex i Grok; afegeix noms de proveïdor per seleccionar-les, com a `omarchy agent account copy laptop claude`. Els noms de compte i els ID d'ordre coincideixen amb l'origen, inclosos els comptes ja presents a la destinació. Els comptes de destinació no relacionats reben un sufix numèric si els seus noms entren en conflicte, i la configuració, les habilitats, els connectors i l'historial de converses romanen locals de cada màquina.

Les credencials de destinació existents es conserven. Un compte d'origen que ja ha iniciat sessió allà veu el seu nom sincronitzat sense que se'n substitueixin les credencials; la resta de comptes s'hi afegeixen al costat. Per substituir les credencials desades dels comptes coincidents, utilitza `omarchy agent account copy --replace laptop claude` després de tancar les sessions d'aquest compte a la destinació. Una destinació nova també rep el compte actiu i les preferències de canvi de l'origen; una destinació ja establerta conserva les seves.

Les credencials viatgen per SSH i es desen en fitxers privats a la destinació, de manera que copia només a màquines de confiança. Això és una còpia única, no una sincronització contínua. Els tokens d'actualització de Codex poden ser rotats per una altra màquina, i un inici de sessió copiat pot quedar necessitat de renovació; els inicis de sessió separats continuen sent l'opció més fiable per a un ús simultani en diverses màquines. Vegeu la [guia d'autenticació de comptes de Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Un compte per proveïdor està actiu, i cada sessió nova comença com a ell: `cx`, `cy`, un simple `claude`, `codex` o `grok`, qualsevol cosa llançada mitjançant `omarchy agent`, i scripts o editors que troben la CLI a `PATH`. Canvia amb `omarchy agent account use work` (i torna amb `omarchy agent account use main`), o al panell prement el número d'un compte i després `Enter` (o fent clic al seu botó Use). Les sessions de Claude en execució també canvien, a partir del seu missatge següent: cada sessió de Claude s'executa a `~/.claude`, que sempre conté l'inici de sessió del compte actiu. Una sessió de Claude iniciada a la carpeta pròpia d'un compte per un Omarchy més antic conserva aquest inici de sessió fins que surt, de manera que el canvi anomena aquestes sessions i acaba tot sol quan han desaparegut. Les sessions de Codex i Grok en execució es queden amb el compte amb què van començar. L'historial de converses, la configuració, les habilitats i els connectors es comparteixen entre comptes, de manera que `claude --continue` a la mateixa carpeta continua on ho havies deixat amb el compte nou.

Amb més d'un compte, el panell mostra els límits de cada compte l'un al costat de l'altre, amb l'actiu marcat. Per defecte, Omarchy t'avisa quan el compte actiu supera el 95% d'un límit, i fer clic a la notificació canvia al compte amb més marge. Passa el cursor per sobre de la línia d'un compte al panell i fes clic a l'Autoswitch que apareix al costat d'Use (o prem `m`), o executa `omarchy agent account mode auto`, perquè canviï tot sol; mentre està activat, Autoswitch pren el lloc d'Use, i tornar-hi a fer clic torna a avisar. Afegeix un número per canviar el llindar, com a `omarchy agent account mode auto 90`. Si cada compte supera el llindar, t'ho farà saber un cop, juntament amb quin compte s'allibera primer. Mentre un compte actiu està a menys de 15 punts del seu llindar (80% per defecte), els seus límits es comproven cada tres minuts en comptes de cada 15.

`omarchy agent account list` mostra cada compte i els seus límits més recents, `omarchy agent account remove work` en oblida un, i `omarchy agent account rename primary Hey` en canvia el nom d'un (o fes clic al nom d'un compte al panell). Aquestes ordres funcionen amb els comptes del teu agent predeterminat; per arribar a l'altre proveïdor, anomena'l primer, com a `omarchy agent account use codex side`. L'inici de sessió que ja tenies a `~/.claude` o `~/.codex` és el compte _Main_. El de Codex es queda on és; el de Claude espera en una carpeta pròpia mentre un altre compte està actiu. Un compte que no s'ha utilitzat durant més d'unes vuit hores pot mostrar _Sign-in required_; fes-hi clic per tornar a iniciar sessió en aquest compte allà mateix al panell, o canvia a ell i inicia una sessió, cosa que actualitza l'inici de sessió tot sol. Els servidors MCP que afegeixes amb `claude mcp add` arriben a cada compte de Claude, ja que tots s'executen a `~/.claude`; per a Codex i Grok, els servidors que tenies quan es va afegir un compte l'acompanyen, però els posteriors només arriben al compte en què els vas afegir. Claude Desktop manté un inici de sessió propi, i les eines de Codex o Grok configurades amb un camí absolut a un binari de CLI no segueixen el canvi. Un `CLAUDE_CONFIG_DIR`, `CODEX_HOME` o `GROK_HOME` explícit té precedència sobre el compte seleccionat.

### Diagnòstic de fallades

Omarchy vigila systemd-coredump per detectar caigudes de processos. Un cop hagis triat un agent predeterminat, qualsevol programa teu que generi un abocament de memòria mostra una notificació "Process crashed": fes-hi clic i la caiguda es passa al teu agent predeterminat juntament amb l'habilitat omarchy-diagnose-crash d'Omarchy, que guia l'agent per establir els fets a partir de l'abocament de memòria i decidir si val la pena informar de la caiguda als desenvolupadors originals. També el pots executar manualment contra qualsevol PID de `coredumpctl list` amb `omarchy agent crash <pid>`.

La vigilància està activada per defecte. Desactiva-la a _Trigger > Toggle > Crash Capture Off_ (o amb `omarchy toggle crash-capture`) i les notificacions s'aturaran; `omarchy agent crash <pid>` encara funciona manualment.

Les caigudes també es poden silenciar programa a programa, que és el que el diagnòstic t'ofereix al final. `omarchy crash mute hyprland` atura les notificacions només per a aquest programa, `omarchy crash mute hyprland off` les torna a activar, i `omarchy crash mute` tot sol enumera el que has silenciat. Accepta el camí del binari amb la mateixa alegria que el seu nom, de manera que `omarchy crash mute /usr/bin/hyprland` fa el mateix. Posa entre cometes un nom amb un espai, com a `omarchy crash mute 'Some App'`. Tota la resta continua notificant, i el programa silenciat continua caient: això amaga el recordatori, no arregla res.

### Aplicacions d'escriptori

El menú _Install > AI_ també inclou unes quantes aplicacions gràfiques d'IA: Amp Desktop, Antigravity Desktop, l'aplicació d'escriptori de ChatGPT, l'aplicació d'escriptori de Claude (la beta de Linux d'Anthropic, amb pestanyes Chat, Cowork i Claude Code), Grok Bot per xatejar amb els models de xAI, Herdr Desktop, Hermes Desktop, OpenClaw, l'aplicació d'escriptori de Perplexity i T3 Code. Grok Bot és l'aplicació de xat d'escriptori. L'agent de programació és l'ordre `grok`.

Hermes Desktop és la que cal conèixer, perquè una màquina té un sol Hermes, i és el de l'aplicació: Hermes només s'instal·la mai mitjançant l'aplicació, i l'ordre `hermes` que executa l'agent predeterminat és la de l'aplicació. Triar Hermes com a agent predeterminat instal·la el mateix que instal·la l'entrada _Install > AI_: el paquet i un entorn d'execució d'Hermes a `~/.hermes` configurat per l'instal·lador propi d'Hermes, que triga uns minuts el primer cop. Aquest entorn d'execució és l'únic Hermes que utilitzen l'ordre `hermes` del terminal, l'agent predeterminat i l'aplicació, i s'actualitza sol amb `hermes update` en comptes d'esperar una versió d'Omarchy. Instal·lar-lo també dona a Hermes el tema d'Omarchy com una aparença anomenada `omarchy`, que cada superfície d'Hermes segueix quan canvies de tema; tria'n una altra a la configuració d'Appearance d'Hermes o amb `/skin` si prefereixes que no ho faci, i Omarchy respectarà aquesta tria. Eliminar l'aplicació a _Remove > AI_ tanca primer Hermes, passarel·la inclosa, s'endú aquest entorn d'execució i conserva els teus xats, records i les habilitats que Hermes va escriure per a si mateix llevat que li diguis el contrari: et demana, amb no per defecte, si aquestes dades i la teva configuració de connexió també han de desaparèixer.

L'experiència d'escriptori d'OpenClaw és la seva Control UI, que s'obre com una aplicació web recolzada per la seva pròpia passarel·la local. OpenClaw viu a `~/.openclaw` i s'actualitza sol: utilitza el botó "Update Gateway" de la Control UI o executa `openclaw update`, i la passarel·la es reinicia amb la versió nova. Omarchy només tria la versió des de la qual comença una instal·lació nova. OpenClaw també pot ser el teu agent predeterminat: triar-lo a _Agent > Harness_ configura aquesta mateixa còpia a `~/.openclaw`, i l'agent obre la interfície de terminal d'OpenClaw connectada a la seva passarel·la. Eliminar OpenClaw a _Remove > AI_ s'endú el servei de passarel·la i l'aplicació i després et demana si `~/.openclaw` també ha de desaparèixer, ja que allà hi ha els teus xats i credencials juntament amb el mateix OpenClaw i els entorns d'execució de connectors que descarrega; per defecte es conserva, i tornar a instal·lar OpenClaw el recupera.

Herdr Desktop és l'aplicació d'escriptori [Herdr](https://herdr.dev): espais, pestanyes i panells de terminals i agents de programació que continuen executant-se en el seu nucli quan tanques la finestra. Prové de l'instal·lador propi de Herdr en comptes d'un paquet, de manera que viu a `~/.local/share/herdr-app`, porta el seu nucli a `~/.local/bin/herdr-core` quan encara no en tens cap, i s'actualitza els dos tots sols. S'asseu al costat de l'ordre `herdr` que Omarchy proporciona amb `Super + Ctrl + Return` en comptes de substituir-la, i rep les tecles directes d'aquesta ordre: `Alt + Return` i `Alt + Shift + Return` divideixen un panell cap avall o cap a la dreta, `Alt + Escape` el tanca, `Ctrl + Alt + Arrow` es mou entre panells, `Alt + 1..9` i `Alt + Left/Right` trien una pestanya, i `Alt + Up/Down` es mouen entre espais. `Ctrl + 1..9` tria un espai i `Alt + Shift + Up/Down` recorre els agents. Les tecles de prefix `Ctrl + Space` continuen sent només del terminal, ja que l'aplicació no pot mantenir una tecla Ctrl simple per a una seqüència. Omarchy escriu això a `~/.config/herdr-app/keys.json`, i `omarchy-refresh-herdr-app` ho restaura. Instal·lar-lo tria el tema Omarchy de Herdr, que a partir d'aleshores segueix el teu tema d'Omarchy. Herdr manté un tema per al mode clar i un per al mode fosc, de manera que després de canviar entre un tema Omarchy fosc i un de clar, torna a triar Omarchy al selector de temes de Herdr un cop més per a l'altre mode.

T3 Code s'executa des de la seva versió oficial AppImage a `~/.local/share/t3code` en comptes de des d'un paquet, de manera que s'actualitza sol. Instal·lar-lo et demana si vols començar al canal Stable o Nightly; canvia-ho més tard a la configuració de T3 Code. Els teus fils i la teva configuració viuen a `~/.t3`, i eliminar T3 Code a _Remove > AI_ se'ls endú.

### Models locals

Executa un model obert a la teva pròpia màquina per als teus agents de programació. Les teves indicacions i el teu codi romanen a la màquina; res del que s'envia al model no en surt. Comença amb:

```bash
omarchy models use best text
```

Això configura el millor model de text per a aquesta màquina, el tipus que utilitzen els teus agents. Els models d'imatge, vídeo i música tenen el seu propi millor: `omarchy models use best image`, `video` o `music`. Executa `omarchy models use best` per veure la tria de cada tipus per a aquesta màquina.

O obre el panell de models locals des de la seva icona d'espurnes a la barra superior, al costat de la icona d'agents, o amb Super + Ctrl + Alt + X, i tria +. La icona apareix quan un model cap en aquesta màquina. Podman, que executa els models, ve amb Omarchy, igual que el kit d'eines de contenidors de NVIDIA en una màquina NVIDIA, que els dona la GPU; si falta qualsevol dels dos, la primera configuració l'instal·la. A continuació, Omarchy tria el model recomanat per a aquesta màquina, el descarrega i l'inicia. Espera una descàrrega de desenes de GB i que la major part de la memòria de la màquina estigui en ús mentre el model s'executa: Flash Next utilitza uns 100 GiB amb el seu context complet de 256K. Si altres models ocupen la memòria que necessita, es configura aturat, llest per iniciar-se un cop n'aturis un. El model s'atura en tancar la sessió; atura'l tu mateix quan necessitis la memòria per a una altra cosa.

`omarchy models list` mostra les opcions i explica per què algunes no hi caben. Per configurar-ne una altra, executa `omarchy models use <recipe>`. Avui, `qwen3.8-flash-next-gufo` i `qwen3.8-27b-gufo` estan disponibles per a màquines Strix Halo de 128 GB; el de 27B ocupa uns 40 GiB, de manera que deixa espai per a una altra feina. En un portàtil de 64 GB amb l'Arc B390 d'Intel, `qwen3.6-35b-a3b-llamacpp` s'executa en uns 30 GiB. Les receptes i recomanacions noves arriben amb `omarchy update`, mitjançant el paquet.

Cada model que configures rep la seva pròpia línia al panell de models locals: reprodueix per iniciar-lo, pausa per aturar-lo i alliberar la seva memòria, i el botó de terminal per obrir el teu agent amb ell. A la part superior, una barra mostra com es reparteix la memòria de la màquina entre el mateix Omarchy (el sistema i les teves aplicacions), cada model en execució i el que queda lliure. Apunta a un model aturat i la barra mostra si hi cap, o quant li falta. Diversos poden executar-se alhora quan caben junts a la memòria; si un no hi cap, Omarchy diu quin model en execució cal aturar. Arrossega les línies pel seu logotip per reordenar-les i prem Delete en una línia seleccionada per eliminar un model i la seva descàrrega.

Cada model que configures també rep la seva pròpia entrada al llançador d'aplicacions, amb el nom del model i el logotip del seu fabricant, de la manera com iniciar sessió a Claude, Codex o Grok en afegeix una. Obre el teu agent amb aquest model i inicia primer el model si no està en execució: el terminal el mostra carregant-se i passa el relleu a l'agent un cop està en marxa. Eliminar un model elimina la seva entrada.

No tots els models són per programar. Els models d'imatge, vídeo i música s'obren a Fantasi, l'aplicació d'Omarchy per fer imatges, vídeo i música amb un model que s'executa en aquesta màquina, des de la seva entrada al llançador i des de la seva línia al panell de models locals.

Un model continua executant-se exactament com es va configurar, de manera que una actualització d'Omarchy mai no en reinicia cap sota els teus agents. Quan Omarchy té un entorn d'execució més nou o pesos més nous per a un model que has configurat, la seva línia mostra un botó d'actualització: prem-lo i el model es torna a configurar en segon pla, descarregant només el que ha canviat, i es reinicia amb la versió nova. Un model que estava aturat continua aturat. `omarchy models update` fa el mateix per a cada model des d'un terminal.

Des de la línia d'ordres, `omarchy models start <recipe>` i `omarchy models stop <recipe>` fan el mateix, `omarchy models status` mostra cada model, i `omarchy agent --local` obre el teu agent predeterminat amb l'últim model que has iniciat. pi, OpenCode i Qwen Code en poden utilitzar un; amb qualsevol altre predeterminat s'obre a pi, o a OpenCode si no tens pi. pi també enumera cada model que has configurat, i els de les màquines amb què t'has vinculat, al seu propi selector de models, de manera que un simple `pi` també hi arriba. Qualsevol client compatible amb OpenAI també es pot connectar: `status` mostra l'adreça de cada model (la primera és `http://127.0.0.1:11435/v1`), el nom de la recepta és el model, i la clau és a `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` elimina un model i les descàrregues que cap altre model no utilitza.

Els entorns d'execució de tercers estan etiquetats amb el seu editor. Omarchy executa cada model sense accés a la xarxa.

### LLM locals

Omarchy recomana dues maneres d'executar models LLM locals: LM Studio i Ollama. LM Studio proporciona una interfície gràfica d'usuari per trobar models de pesos oberts, instal·lar-los i executar-los. És una manera fantàstica de començar fàcilment. Ollama ofereix una CLI per fer-ho de manera similar. Però si ets nou en els models locals, jo començaria amb LM Studio. Pots instal·lar qualsevol dels dos a _Install > AI_ al Menú d'Omarchy.

### Les habilitats d'Omarchy

Les habilitats d'agent ajuden la IA a utilitzar eines específiques d'una manera específica, i Omarchy en proporciona set. L'habilitat omarchy cobreix l'adaptació del sistema, com ara retocar la teva configuració de Hyprland o ajustar la barra. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app i omarchy-make-game cobreixen fer alguna cosa nova, omarchy-contribute cobreix informar d'un error o enviar una correcció als desenvolupadors originals, i omarchy-diagnose-crash treballa amb l'abocament de memòria d'una caiguda. Estan enllaçades simbòlicament als directoris d'habilitats de Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` i cada `~/.hermes/profiles/*/skills`), i la ubicació genèrica `~/.agents/skills`, de manera que la majoria de harnesses les recullen automàticament. Una carpeta d'habilitats pròpia amb el mateix nom té precedència.

Però hauries de tractar aquestes habilitats com a experimentals. Models diferents la utilitzaran amb efectes diferents. És millor executar primer en mode de pla, perquè tinguis una idea del que l'agent voldria canviar. I després estigues preparat per revertir els canvis o fins i tot invocar `omarchy reinstall configs`, si l'agent ho espatlla tot.
