# IA

Omarchy inclou llançadors per als agents de programació següents sense triar-ne un de predeterminat per a tu. Executa una ordre per instal·lar el seu CLI en el primer ús i després autentica't quan se't demani. Hermes i OpenClaw són les excepcions: no s'instal·la res per a ells a través de mise, i triar-ne qualsevol configura la seva pròpia còpia que s'actualitza sola, com explica _Aplicacions d'escriptori_ més avall.

### Instal·lació i actualització d'agents

Excepte Hermes i OpenClaw, aquests agents utilitzen la instal·lació diferida de mise: el primer llançament instal·la el CLI i els llançaments posteriors el reutilitzen. mise també comprova si un agent instal·lat té una nova versió com a màxim una vegada cada quatre hores, just abans d'iniciar-se o en segon pla en un indicador de l'intèrpret d'ordres. Si aquesta actualització falla o estàs fora de línia, s'executa la versió instal·lada. `omarchy update` actualitza els agents instal·lats amb la resta d'Omarchy, i `mup` actualitza només les eines gestionades per mise.

L'actualitzador propi d'un agent, com ara `claude update`, `codex update` o un botó d'actualització en una aplicació, no actualitza la instal·lació gestionada per mise. `codex update` falla, i `claude update` pot informar d'èxit mentre instal·la una còpia separada que mise no segueix. Si prefereixes utilitzar l'instal·lador i l'actualitzador natius d'un agent, afegeix-lo a `disable_tools`; vegeu [Eines de CLI preinstal·lades](18-development-tools.md#preinstalled-cli-tools).

Per instal·lar totes les eines diferides configurades abans que les necessitis, executa `mise install --include-lazy`. Això inclou les altres eines de CLI predeterminades d'Omarchy, a més dels agents. Vegeu [Eines de CLI preinstal·lades](18-development-tools.md#preinstalled-cli-tools) per instal·lar una sola eina o utilitzar la teva pròpia instal·lació.

`grok` s'instal·la mitjançant el paquet oficial `grok` de mise, de la mateixa manera que `claude` i `codex`. Executa `grok` o marca'l amb una estrella al panell d'agents. Salta't l'instal·lador `curl | bash` de x.ai. Aquesta via posa una segona còpia a `~/.grok/bin`, la anteposa a `PATH` i sobreescriu l'embolcall d'Omarchy.

`dsh` obre la seva interfície d'usuari del navegador a `127.0.0.1:3080`, amb el directori de llançament com a espai de treball predeterminat. La seva interfície d'usuari del navegador no accepta cap prompt inicial, de manera que `omarchy agent prompt` l'obre amb el prompt al porta-retalls perquè l'enganxis. Omarchy l'inicia amb el preset de permisos sense aprovació de DeepSeek. DeepSeek Harness puja els registres de sessió a DeepSeek quan utilitzes la seva API oficial de models; desactiva-ho a _Settings > General > Upload Session Log_ a la seva interfície d'usuari del navegador. Els comentaris que li enviïs també es pugen amb la sessió, tret que l'iniciïs amb `DSH_TELEMETRY_MODE=DISABLED`.

### L'agent predeterminat

Tria el teu agent predeterminat amb l'estrella al costat d'un agent al panell d'agents, que està plena en el predeterminat, o amb `omarchy default agent <name>`, que també accepta qualsevol harness sense una línia allà. Si l'agent encara no està instal·lat, triar-lo l'instal·la primer, i també obté un llançador propi al llançador d'aplicacions, al costat d'Agent. Un Omarchy nou t'invita a configurar-ne un amb una notificació única, que obre el panell d'agents.

Triar Claude també intenta configurar la seva extensió del navegador per a Chromium, Chrome, Brave, Brave Origin i Edge. La configuració de l'extensió s'aplica a tots els usuaris i pot demanar-te la contrasenya del sistema; cancel·lar-la o que falli la instal·lació de l'extensió igualment selecciona i llança Claude. Reinicia el navegador, activa l'extensió si se't demana i inicia sessió a Claude per acabar de connectar-lo. Executa `/chrome` a Claude per comprovar la connexió. Firefox i Zen no admeten aquesta extensió. Si Claude ja era el teu predeterminat abans que s'afegís aquesta configuració, selecciona'l de nou per instal·lar l'extensió.

Un cop hagis triat, `Super + Shift + Ctrl + A` llança l'agent predeterminat en una finestra de terminal dedicada (o obre el selector si encara no n'has triat cap). També pots llançar-lo directament en una tasca amb `omarchy agent prompt "Review this project"`. Freebuff i DeepSeek Harness no accepten cap prompt inicial, de manera que s'obren amb el prompt al porta-retalls perquè l'enganxis. Els agents llançats d'aquesta manera s'executen sense supervisió en els seus respectius modes de no aturar-se a demanar, així que estigues preparat perquè realment facin coses! MiniMax Code no té un mode així per a les seves sessions interactives, de manera que demana permisos com de costum. I com que els agents es neguen a recordar la confiança per al teu directori d'inici, els llançaments des de `$HOME` comencen a `~/Work`.

També hi ha dreceres de terminal: `a` executa l'agent predeterminat en línia al terminal actual, mentre que `c`, `cx` i `cy` inicien OpenCode, Claude Code i Codex directament (també en els seus modes d'aprovació automàtica). Els canvis de tema també se sincronitzen amb els agents: Claude Code, Pi, OpenCode i Hermes (un cop Omarchy l'ha instal·lat) segueixen quan canvies el tema d'Omarchy.

### Les teves instruccions per als agents

Les regles personals per a cada agent van a `~/.agents/AGENTS.md`, al costat de les habilitats compartides a `~/.agents/skills`. Obre'l amb la icona de document al costat del + al panell d'agents, o amb `omarchy agent instructions --edit`, que també l'enllaça a cada harness que manté el seu propi fitxer global: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, el `~/.copilot/copilot-instructions.md` de Copilot, i així successivament. Crush i Amp llegeixen l'enllaç `~/.config/AGENTS.md`, mentre que omp, Kimi i DeepSeek Harness llegeixen `~/.agents/AGENTS.md` directament. Triar un agent predeterminat també l'enllaça. Un fitxer d'instruccions que ja tenies es converteix en el compartit si encara no n'hi havia cap; en cas contrari, es conserva al costat de l'enllaç com a `.bak`. Executa `omarchy agent instructions` per tornar a enllaçar després d'instal·lar un altre agent.

### El panell d'agents

La barra superior té una icona d'agents. Abans que hagis configurat un agent, el seu panell ofereix tres maneres de començar: iniciar sessió en una subscripció de Claude, Codex, Grok, Gemini, Muse, Cursor o Copilot, o a More un pla de programació d'OpenCode Go, MiniMax, Synthetic o Z.ai; pagar per ús amb Fireworks, OpenCode Zen and Go, OpenRouter, o a More DeepSeek o qualsevol altre proveïdor al qual OpenCode iniciï sessió, tot executat a OpenCode; o executar el millor model per al teu ordinador, quan n'hi ha un que hi cap. El primer que acabis es converteix en el teu agent predeterminat, i el + del panell ofereix les mateixes tres opcions més tard. Després d'això, el panell posa cada subscripció en una pàgina: cada agent i compte amb el seu pla, un mesurador per a cadascun dels seus límits de sessió de 5 hores i setmanal amb el temps fins que es restableixi (passa el cursor per sobre per veure el percentatge exacte), o el saldo prepagat restant, sota una línia que rota pel que has utilitzat en tots ells, com ara tokens aquesta setmana i el teu model més utilitzat. A _Make something cool_ ofereix prompts inicials per a un tema, complement, aplicació o joc nous que lliuren la tasca al teu agent predeterminat. Les aplicacions es creen de la manera com es creen les pròpies Hype, Monologue i Omacut d'Omarchy, en C++ i Qt Quick, seguint l'habilitat d'agent omarchy-make-app, i el compilador i les peces de Qt que necessiten venen instal·lats. Els jocs són una sola pàgina three.js a `~/Games/vibes`, seguint l'habilitat d'agent omarchy-make-game, i tots s'obren des d'un llançador Game Vibes en el tema actual; carreguen three.js des del web, de manera que necessiten una connexió per iniciar-se. Claude Code, Codex, Grok, Kimi, Cursor i la seva assignació de Grok Bot, GitHub Copilot, Muse, Gemini (a través d'Antigravity) i Devin estan coberts des del primer moment amb els seus límits, Kimchi amb el seu pla, crèdits prepagats i pressupostos de despesa, i Hermes, Mistral Vibe i Qwen Code mostren les seves sessions i tokens un cop els has utilitzat. Els plans i les claus de proveïdor que utilitzes a través de pi, omp o opencode també hi apareixen: OpenCode Zen and Go, el Z.ai GLM Coding Plan, Ollama Cloud, el MiniMax Token Plan i Synthetic amb els seus límits; OpenRouter i DeepSeek amb els seus saldos prepagats; Fireworks amb la seva despesa dels últims 30 dies. Els models de programació que executes en el teu propi maquinari tenen línies pròpies, i els seus tokens també compten per als totals, com es descriu a [Models locals](#local-models). Cada agent es compta una vegada, sota qui el facturi, per molts harness a través dels quals l'utilitzis.

Fes clic amb el botó esquerre a la icona de la barra o prem `Super + Ctrl + X` per al panell, fes clic amb el botó dret per llançar el teu agent predeterminat i fes clic amb el botó del mig per actualitzar. Els registres d'ús que hi ha darrere es regeneren cada 15 minuts amb `omarchy agent usage update`, i el panell fins i tot pot fusionar l'ús de les teves altres màquines mitjançant una carpeta sincronitzada. Vegeu el README a `$OMARCHY_PATH/shell/plugins/agents/` per a la configuració completa.

### Diverses subscripcions

Si pagues més d'un pla de Claude, Codex o Grok — un Max personal i un de feina, per exemple — Omarchy pot mantenir-los tots amb la sessió iniciada i moure's entre ells. Afegeix una subscripció amb el + del panell d'agents, que et guia allà mateix, o amb `omarchy agent account add claude Work` (o `codex`, o `grok`). El mateix + i ordre inicien sessió a Gemini (`gemini`) i OpenCode (`opencode`), i desen una clau d'API de Fireworks (`fireworks`) o OpenRouter (`openrouter`) a OpenCode; l'ordre també inicia sessió a Copilot (`copilot`), Cursor (`cursor`) i Muse (`muse`). Aquests mantenen una sola sessió iniciada cadascun. Instal·la el CLI si falta. El primer compte d'un proveïdor inicia sessió a través del teu navegador normal, just on el CLI sempre busca. Cada un després d'aquest inicia sessió a través d'una finestra privada, de manera que el compte al qual el teu navegador ja ha iniciat sessió no es reculli per error; inicia sessió allà com el compte que estàs afegint i tanca primer qualsevol finestra privada que ja tinguessis oberta. No tanquis mai la sessió del CLI per fer això: tancar la sessió revoca l'inici de sessió desat, i aquest compte s'hauria d'afegir de nou.

Per copiar les teves sessions de subscripció a una altra màquina Omarchy per SSH, executa `omarchy agent account copy user@laptop`. L'emissor proporciona un receptor temporal quan la destinació no en té un d'instal·lat, de manera que màquines Omarchy més antigues poden rebre comptes sense una actualització. Els receptors instal·lats tenen precedència. Això copia totes les subscripcions de Claude, Codex i Grok; afegeix noms de proveïdor per seleccionar-les, com a `omarchy agent account copy laptop claude`. Els noms de compte i els ID d'ordre coincideixen amb l'origen, inclosos els comptes ja presents a la destinació. Els comptes de destinació no relacionats reben un sufix numèric si els seus noms entren en conflicte, i la configuració, les habilitats, els complements i l'historial de converses es queden locals a cada màquina.

Les credencials de destinació existents es conserven. Un compte d'origen que ja ha iniciat sessió allà té el seu nom sincronitzat sense substituir les seves credencials; els altres comptes s'afegeixen al seu costat. Per substituir les credencials desades dels comptes coincidents, utilitza `omarchy agent account copy --replace laptop claude` després de tancar les sessions d'aquest compte a la destinació. Una destinació nova també rep el compte actiu i les preferències de canvi de l'origen; una destinació establerta conserva les seves.

Les credencials viatgen per SSH i s'emmagatzemen en fitxers privats a la destinació, així que copia només a màquines en què confiïs. Això és una còpia única, no una sincronització contínua. Els tokens d'actualització de Codex poden ser rotats per una altra màquina, deixant un inici de sessió copiat amb necessitat de renovació; els inicis de sessió separats continuen sent l'opció més fiable per a un ús simultani en diverses màquines. Vegeu la [guia d'autenticació de comptes de Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Un compte per proveïdor està actiu, i cada sessió nova comença com ell: `cx`, `cy`, un `claude`, `codex` o `grok` simple, qualsevol cosa llançada mitjançant `omarchy agent`, i scripts o editors que troben el CLI a `PATH`. Canvia amb `omarchy agent account use work` (i torna amb `omarchy agent account use main`), o al panell prement el número d'un compte i després `Enter` (o fent clic a la seva estrella). Les sessions de Claude en execució també canvien, a partir del seu missatge següent: cada sessió de Claude s'executa a `~/.claude`, que sempre conté l'inici de sessió del compte actiu. Una sessió de Claude iniciada a la carpeta pròpia d'un compte per un Omarchy més antic conserva aquest inici de sessió fins que surt, de manera que el canvi nomena aquestes sessions i acaba per si sol un cop han desaparegut. Les sessions de Codex i Grok en execució es queden amb el compte amb què van començar. L'historial de converses, la configuració, les habilitats i els complements es comparteixen entre comptes, de manera que `claude --continue` a la mateixa carpeta continua on ho vas deixar amb el compte nou.

Amb més d'un compte, el panell mostra els límits de cada compte un al costat de l'altre, amb una estrella plena en el que s'utilitza. Omarchy t'avisa quan el compte actiu supera el 95% d'un límit, i fer clic a la notificació canvia al compte amb més marge. Mai no canvia per si sol. Canvia el llindar amb `omarchy agent account threshold 90`. Si cada compte supera el llindar, ho sabràs una vegada, juntament amb quin compte s'allibera primer. Mentre un compte actiu estigui a menys de 15 punts del seu llindar (80% per defecte), els seus límits es comproven cada tres minuts en lloc de cada 15.

`omarchy agent account list` mostra cada compte i els seus límits més recents, `omarchy agent account remove work` n'oblida un, i `omarchy agent account rename primary Hey` en reanomena un (o fes clic al nom d'un compte al panell). Aquestes ordres funcionen en els comptes del teu agent predeterminat; per arribar a l'altre proveïdor, nomena'l primer, com a `omarchy agent account use codex side`. L'inici de sessió que ja tenies a `~/.claude` o `~/.codex` és el compte _Main_. El de Codex es queda on és; el de Claude espera en una carpeta pròpia mentre un altre compte està actiu. Un compte deixat sense utilitzar durant més d'unes vuit hores pot mostrar _Sign-in required_; fes-hi clic per iniciar sessió de nou en aquest compte directament al panell, o canvia a ell i inicia una sessió, que actualitza l'inici de sessió per si sol. Els servidors MCP que afegeixes amb `claude mcp add` arriben a cada compte de Claude, ja que tots s'executen a `~/.claude`; per a Codex i Grok, els servidors que tenies quan es va afegir un compte l'acompanyen, però els posteriors només arriben al compte en què els vas afegir. Claude Desktop manté un inici de sessió propi, i les eines de Codex o Grok configurades amb una ruta absoluta a un binari de CLI no segueixen el canvi. Un `CLAUDE_CONFIG_DIR`, `CODEX_HOME` o `GROK_HOME` explícit té precedència sobre el compte seleccionat.

### Diagnòstic de fallades

Omarchy vigila systemd-coredump per detectar fallades de processos. Un cop hagis triat un agent predeterminat, qualsevol programa teu que faci un bolcat de memòria principal mostra una notificació "Process crashed" — fes-hi clic, i la fallada es lliura al teu agent predeterminat juntament amb l'habilitat omarchy-diagnose-crash d'Omarchy, que guia l'agent per establir els fets a partir del bolcat de memòria principal i decidir si val la pena informar de la fallada aigües amunt. També pots executar-ho manualment contra qualsevol PID de `coredumpctl list` amb `omarchy agent crash <pid>`.

La vigilància està activada per defecte. Desactiva-la a _Trigger > Toggle > Crash Capture Off_ (o amb `omarchy toggle crash-capture`) i les notificacions s'aturen; `omarchy agent crash <pid>` continua funcionant manualment.

Les fallades també es poden silenciar un programa a la vegada, que és el que el diagnòstic t'ofereix al final. `omarchy crash mute hyprland` atura les notificacions només per a aquest programa, `omarchy crash mute hyprland off` les torna a activar, i `omarchy crash mute` per si sol llista el que has silenciat. Accepta la ruta del binari amb la mateixa facilitat que el seu nom, de manera que `omarchy crash mute /usr/bin/hyprland` fa el mateix. Posa entre cometes un nom amb un espai, com a `omarchy crash mute 'Some App'`. Tota la resta continua notificant, i el programa silenciat continua fallant — això amaga el recordatori, no arregla res.

### Aplicacions d'escriptori

El menú _Install > AI_ també inclou unes quantes aplicacions gràfiques d'IA: Amp Desktop, Antigravity Desktop, l'aplicació d'escriptori de ChatGPT, l'aplicació d'escriptori de Claude (la beta de Linux d'Anthropic, amb pestanyes Chat, Cowork i Claude Code), Grok Bot per xatejar amb els models de xAI, Herdr Desktop, Hermes Desktop, OpenClaw, l'aplicació d'escriptori de Perplexity i T3 Code. Grok Bot és l'aplicació de xat d'escriptori. L'agent de programació és l'ordre `grok`.

Hermes Desktop és la que cal conèixer, perquè una màquina té un Hermes, i és el de l'aplicació: Hermes només s'instal·la mai a través de l'aplicació, i l'ordre `hermes` que executa l'agent predeterminat és la de l'aplicació. Triar Hermes com a agent predeterminat instal·la el mateix que instal·la l'entrada _Install > AI_: el paquet, i un entorn d'execució de Hermes a `~/.hermes` configurat pel propi instal·lador de Hermes, que triga uns minuts la primera vegada. Aquest entorn d'execució és l'únic Hermes que utilitzen l'ordre `hermes` del terminal, l'agent predeterminat i l'aplicació, i s'actualitza sol amb `hermes update` en lloc d'esperar una versió d'Omarchy. Instal·lar-lo també lliura a Hermes el tema d'Omarchy com una aparença anomenada `omarchy`, que cada superfície de Hermes segueix quan canvies de tema; tria'n una altra a la configuració d'Appearance de Hermes o amb `/skin` si prefereixes que no ho faci, i Omarchy deixa aquesta tria en pau. Eliminar l'aplicació a _Remove > AI_ tanca primer Hermes, passarel·la inclosa, s'emporta aquest entorn d'execució i conserva els teus xats, memòries i les habilitats que Hermes va escriure per a si mateix tret que li diguis el contrari: pregunta, amb no per defecte, si aquestes dades i la teva configuració de connexió també haurien de desaparèixer.

L'experiència d'escriptori d'OpenClaw és la seva Control UI, que s'obre com una aplicació web recolzada per la seva pròpia passarel·la local. OpenClaw viu a `~/.openclaw` i s'actualitza sol: utilitza el botó "Update Gateway" de la Control UI o executa `openclaw update`, i la passarel·la es reinicia amb la nova versió. Omarchy només tria la versió amb què comença una instal·lació nova. OpenClaw també pot ser el teu agent predeterminat: triar-lo amb `omarchy default agent openclaw` configura aquesta mateixa còpia a `~/.openclaw`, i l'agent obre la interfície d'usuari de terminal d'OpenClaw connectada a la seva passarel·la. Eliminar OpenClaw a _Remove > AI_ s'emporta el servei de passarel·la i l'aplicació i després pregunta si `~/.openclaw` també hauria de desaparèixer, ja que allò conté els teus xats i credencials juntament amb el propi OpenClaw i els entorns d'execució de complements que descarrega; per defecte el conserva, i instal·lar OpenClaw de nou el recupera.

Herdr Desktop és l'aplicació d'escriptori de [Herdr](https://herdr.dev): espais, pestanyes i panells de terminals i agents de programació que continuen executant-se en el seu nucli quan tanques la finestra. Prové del propi instal·lador de Herdr en lloc d'un paquet, de manera que viu a `~/.local/share/herdr-app`, porta el seu nucli a `~/.local/bin/herdr-core` quan encara no en tens un, i s'actualitza tant a si mateixa com a ell. S'asseu al costat de l'ordre `herdr` que Omarchy proporciona amb `Super + Ctrl + Return` en lloc de substituir-la, i obté les tecles directes d'aquesta ordre: `Alt + Return` i `Alt + Shift + Return` divideixen un panell cap avall o cap a la dreta, `Alt + Escape` el tanca, `Ctrl + Alt + Arrow` es mou entre panells, `Alt + 1..9` i `Alt + Left/Right` trien una pestanya, i `Alt + Up/Down` es mouen entre espais. `Ctrl + 1..9` tria un espai i `Alt + Shift + Up/Down` passa pels agents. Les tecles de prefix `Ctrl + Space` es queden només per al terminal, ja que l'aplicació no pot mantenir una tecla Ctrl simple per a una seqüència. Omarchy escriu aquestes a `~/.config/herdr-app/keys.json`, i `omarchy-refresh-herdr-app` les restableix. Instal·lar-la tria el tema Omarchy de Herdr, que segueix el teu tema d'Omarchy a partir d'aleshores. Herdr manté un tema per al mode clar i un per al mode fosc, de manera que després de canviar entre un tema Omarchy fosc i un de clar, tria Omarchy una vegada més al selector de temes de Herdr per a l'altre mode.

T3 Code s'executa des de la seva versió oficial AppImage a `~/.local/share/t3code` en lloc de des d'un paquet, de manera que s'actualitza sol. Instal·lar-lo pregunta si vols començar al canal Stable o Nightly; canvia-ho més tard a la configuració de T3 Code. Els teus fils i la teva configuració viuen a `~/.t3`, i eliminar T3 Code a _Remove > AI_ se'ls emporta.

### Models locals

Executa un model obert a la teva pròpia màquina per als teus agents de programació. Els teus prompts i el teu codi es queden a la màquina; res del que s'envia al model no en surt. Comença amb:

```bash
omarchy models use best text
```

Això configura el millor model de text per a aquesta màquina, el tipus que utilitzen els teus agents. Els models d'imatge, vídeo i música tenen un millor propi: `omarchy models use best image`, `video` o `music`. Executa `omarchy models use best` per veure la tria de cada tipus per a aquesta màquina.

O tria + al panell d'agents: a _Use a local model_ llista cada model de programació que cap en aquesta màquina, el recomanat primer. Podman, que executa els models, ve amb Omarchy, igual que el kit d'eines de contenidors de NVIDIA en una màquina NVIDIA, que els dona la GPU; si falta qualsevol dels dos, la primera configuració l'instal·la. Llavors Omarchy tria el model recomanat per a aquesta màquina, el descarrega i l'inicia. Espera una descàrrega de desenes de GB i que la major part de la memòria de la màquina estigui en ús mentre el model s'executa: Flash Next utilitza uns 100 GiB amb el seu context complet de 256K. Si altres models ocupen la memòria que necessita, es configura aturat, preparat per iniciar-se un cop n'aturis un. El model s'atura en tancar la sessió; atura'l tu mateix quan necessitis la memòria per a una altra cosa.

`omarchy models list` mostra les opcions i explica per què alguns no hi caben. Per configurar-ne un altre, executa `omarchy models use <recipe>`. Avui, `qwen3.8-flash-next-gufo` i `qwen3.8-27b-gufo` estan disponibles per a màquines Strix Halo de 128 GB; el de 27B ocupa uns 40 GiB, de manera que deixa espai per a altra feina. En un portàtil de 64 GB amb l'Arc B390 d'Intel, `qwen3.6-35b-a3b-llamacpp` s'executa en uns 30 GiB. Les noves receptes i recomanacions arriben amb `omarchy update`, a través del paquet.

Un model de programació que afegeixes obté la seva pròpia línia al panell d'agents, al costat de les teves subscripcions: reproduir per iniciar-lo, pausar per aturar-lo i alliberar la seva memòria, la marca de Tailscale per compartir-lo amb les altres màquines de la teva tailnet mentre s'executa, i el botó de terminal per obrir el teu agent en ell. La seva línia mostra la descàrrega, càrrega o aturada a mesura que avança, i ho diu quan no hi ha prou memòria lliure per iniciar-lo, o enllaça als seus registres quan s'ha aturat amb un error. Diversos poden executar-se alhora quan caben junts a la memòria. Prem Delete en una línia seleccionada per eliminar el model d'aquesta màquina, descàrrega inclosa; + pot tornar a configurar-lo. Un model de programació configurat des d'un terminal espera sota + fins que l'afegeixes, i també ho fan els models que executa una màquina amb què t'has emparellat (`omarchy models pair <host>`).

Cada model de programació que configures també obté la seva pròpia entrada al llançador d'aplicacions, sota el nom del model i amb el logotip del seu creador, de la manera com iniciar sessió a Claude, Codex o Grok n'afegeix una. Obre el teu agent en aquest model, i inicia primer el model si no s'està executant: el terminal el mostra carregant-se i lliura el relleu a l'agent un cop està en marxa. Eliminar un model elimina la seva entrada.

No tots els models són per programar. Els models d'imatge, vídeo i música s'obren en canvi a Fantasi, l'aplicació d'Omarchy per fer imatges, vídeo i música amb un model que s'executa en aquesta màquina, i es gestionen allà o amb `omarchy models`.

Un model continua executant-se exactament com es va configurar, de manera que una actualització d'Omarchy mai no en reinicia un sota els teus agents. Quan Omarchy té un entorn d'execució més nou o pesos més nous per a un model que has configurat, la seva línia mostra un botó d'actualització: prem-lo i el model es torna a configurar en segon pla, descarregant només el que ha canviat, i es reinicia amb la nova versió. Un model que estava aturat continua aturat. `omarchy models update` fa el mateix per a cada model des d'un terminal.

Des de la línia d'ordres, `omarchy models start <recipe>` i `omarchy models stop <recipe>` fan el mateix, `omarchy models status` mostra cada model, i `omarchy agent --local-model <recipe>` obre aquest model a pi, sigui quin sigui el teu agent predeterminat. Per fer que el teu model local sigui el que obren la drecera de tecles de l'agent, la consola Quake i _Make something_, executa `omarchy default agent local` o marca amb una estrella un model en execució al panell d'agents. pi també llista cada model que has configurat, i els de les màquines amb què t'has emparellat, al seu propi selector de models, de manera que un `pi` simple també els arriba. Qualsevol client compatible amb OpenAI també es pot connectar: `status` mostra l'adreça de cada model (la primera és `http://127.0.0.1:11435/v1`), el nom de la recepta és el model, i la clau és a `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` elimina un model i les descàrregues que cap altre model no utilitza.

Els entorns d'execució de tercers estan etiquetats amb el seu editor. Omarchy executa cada model sense accés a la xarxa.

### LLM locals

Omarchy recomana dues maneres d'executar models LLM locals: LM Studio i Ollama. LM Studio proporciona una interfície gràfica d'usuari per trobar models de pesos oberts, instal·lar-los i executar-los. És una bona manera de començar fàcilment. Ollama ofereix un CLI per fer-ho de manera similar. Però si ets nou en models locals, jo començaria amb LM Studio. Pots instal·lar qualsevol dels dos a _Install > AI_ al menú d'Omarchy.

### Les habilitats d'Omarchy

Les habilitats d'agent ajuden la IA a utilitzar eines específiques d'una manera específica, i Omarchy en proporciona set. L'habilitat omarchy cobreix adaptar el sistema, com ara retocar la teva configuració de Hyprland o ajustar la barra. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app i omarchy-make-game cobreixen fer alguna cosa nova, omarchy-contribute cobreix informar d'un error o enviar una correcció aigües amunt, i omarchy-diagnose-crash treballa a través del bolcat de memòria principal d'una fallada. Estan enllaçades simbòlicament als directoris d'habilitats de Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` i cada `~/.hermes/profiles/*/skills`), i la ubicació genèrica `~/.agents/skills`, de manera que la majoria de harness les recullen automàticament. Una carpeta d'habilitat teva amb el mateix nom té precedència.

Però hauries de tractar aquestes habilitats com a experimentals. Diferents models la utilitzaran amb efectes diferents. És millor executar primer en mode de planificació, perquè tinguis una idea del que l'agent voldria canviar. I després estigues preparat per revertir els canvis o fins i tot invocar `omarchy reinstall configs`, si l'agent ho embolica tot.
