# Развојни алати

## Алтернативни уређивачи

Omarchy се на новим инсталацијама испоручује са Plain као подразумеваним уређивачем и већ инсталираним [Neovim](https://neovim.io/), али ако желите нешто мало више мејнстрим и познато, можете покренути Omarchy мени (`Super + Space`) и погледати опције под _Инсталирај > Уређивач_. Тамо су наведени VSCode, Cursor, Zed, Sublime Text, Helix, Vim и Emacs. Ако не пронађете оно што тражите, погледајте _Инсталирај > Пакет_ и видите да ли се налази у неком Arch пакету (а ако не, пробајте _Инсталирај > AUR_ да проверите AUR).

Оригинални уређивач `vi` такође је доступан одмах по инсталацији. Покрените `vi filename` да бисте уредили датотеку у терминалу.

Усклађивање теме нуди се за `VSCode`, `Cursor`, `VSCodium` и `Helix`.

Подразумевани уређивач за цео систем можете подесити под `Setup > Defaults > Editor`.

## Окружење

Omarchy подржава подешавање читавог низа развојних окружења кроз одељак _Инсталирај > Развој_ у Omarchy менију (`Super + Space`). Наравно да ћете тамо пронаћи _Ruby on Rails_, али и сва три главна извршна окружења за JavaScript (Node.js, Bun, Deno), као и популарне PHP оквире као што су Laravel и Symfony. Ох, а ту су и Go, Rust, Python, Java, Elixir (са Phoenix), .NET, OCaml, Zig, Clojure и Scala. То је веома широк избор!

Већином ових окружења управља [Mise](https://mise.jdx.dev/). То је алат који вам омогућава да инсталирате и покрећете више верзија програмског језика на истој машини. Сличан је алатима rbenv или rvm за Ruby или virtualenv за Python, али ради за гомилу различитих окружења.

Да бисте инсталирали, рецимо, Ruby, покренули бисте `mise use -g ruby`, чиме се Ruby и инсталира и поставља као глобална подразумевана верзија. Или, ако ваш пројекат има датотеку .ruby-version, можете једноставно покренути `mise i` у корену тог пројекта.

## Прединсталирани CLI алати

Omarchy чини алате као што су `gh`, `uv` и већина [агената за програмирање](17-ai.md) доступним кроз [лењу инсталацију mise-а](https://mise.jdx.dev/dev-tools/shims.html#lazy-tools). Први пут када покренете неки од њих, mise га инсталира. Агенти за програмирање затим пре покретања проверавају да ли постоји ажурирање, највише једном у четири сата; други алати, као што су `gh` и `uv`, поново користе инсталирану верзију док је не ажурирате.

Такође можете прегледати подразумеване вредности или их инсталирати унапред:

```bash
mise ls --current              # List the tools configured for this directory
mise install gh               # Install one tool now
mise install --include-lazy    # Install all configured tools, including lazy tools
```

Покрените `omarchy update` да бисте ажурирали инсталиране алате заједно са остатком Omarchy-ја. Алиас `mup` ажурира само алате којима управља mise. Да бисте додали још један алат у сопствену конфигурацију, користите `mise use -g <tool>`.

Подешавање Python-а такође инсталира `uv` кроз mise. Уклањање Python развојног окружења оставља `uv` доступан као независтан алат.

### Коришћење сопствене инсталације

Команде mise-а долазе пре `~/.local/bin` на `PATH`, па алат који сте сами инсталирали, на пример помоћу сопственог инсталера Claude Code-а или Cursor-а, и даље покреће копију mise-а. Апликације покренуте са радне површине такође проналазе команде mise-а пре системских пакета, па апликација која покреће `gh` добија копију mise-а чак и ако сте `github-cli` инсталирали помоћу pacman-а, а mise ту копију инсталира први пут. Да бисте уместо тога користили своју, онемогућите копију mise-а у `~/.config/mise/config.toml`. На пример, ако сте сами инсталирали Cursor CLI:

```toml
[settings]
disable_tools = ["cursor-agent"]
```

Ако већ имате табелу `[settings]`, додајте ставку тамо; проширите постојећу листу `disable_tools` уместо да је замењујете. Уверите се да је ваша инсталација на `PATH`. Користите име алата mise, које се може разликовати од његове команде: `oh-my-pi`, на пример, пружа `omp`. Покретач подразумеваног агента такође даје предност Cursor-у или Muse-у који је корисник инсталирао у `~/.local/bin`.

### Уклањање и враћање подразумеваних вредности

_Уклони > Прединсталације_ уклања Omarchy прединсталиране веб апликације, TUI-је и апликације и наводи mise да прескочи Omarchy декларације алата за вашег корисника, додајући их у `ignored_config_paths` у `~/.config/mise/miserc.toml`. _Инсталирај > Прединсталације_ их враћа и поново уклања тај ред. Алати које сами декларишете, у сопственој конфигурацији или у `mise.toml` пројекта, настављају да раде у оба случаја. Ако изаберете подразумеваног агента или подесите Python након уклањања прединсталација, тај алат се додаје у вашу сопствену конфигурацију. Подешавање mise-а важи само за вашег корисника, а други корисници задржавају сопствени избор; апликације су, међутим, пакети, па њихово уклањање или враћање мења их за све на машини.

## Docker

[Docker](https://www.docker.com/) једва да треба представљање. Омогућава вам да покрећете изоловане контејнере, а Omarchy инсталира све што је потребно да би добро радио, укључујући сам Docker и [Docker Compose](https://docs.docker.com/compose/).

Подразумевано ваш корисник *није* у групи `docker`. Та група је у суштини root без лозинке — све у њој може да покрене `docker run -v /:/host` и преузме машину — па би једна злонамерна скрипта или зависност која се покреће као ви у супротном била једну команду удаљена од root-а. Зато на командној линији Docker покрећете помоћу `sudo` (`sudo docker ps`, `sudo docker compose up`), а графички алати који разговарају са демоном — Windows VM — траже ауторизацију када им је потребна. Ако желите назад погодност подешавања без групе и разумете компромис, омогућите је из **Подешавање > Безбедност > Sudoless Docker** (или покрените `omarchy-setup-security-sudoless-docker`), што вас након упозорења додаје у групу `docker`; тада обичан `docker` и алиас `d` поново раде без `sudo`.

Уобичајене базе података за локални развој у Docker-у можете подесити помоћу _Инсталирај > Развој > Docker DB_ у Omarchy менију.

## GitHub CLI

[GitHub CLI](https://cli.github.com/) доступан је као `gh` за рад са репозиторијумима, проблемима и захтевима за спајање из терминала. Покрените `gh auth login` да бисте га инсталирали при првој употреби и аутентификовали се, затим `gh repo clone org/repo` да бисте клонирали репозиторијум. Покрените `gh --help` да бисте истражили његове команде.

За терминалски интерфејс за захтеве за спајање покрените `ghui`; mise га такође инсталира при првој употреби. [Lazygit](https://github.com/jesseduffield/lazygit) је прединсталиран за рад са самим Git-ом.
