# Развојни алати

## Алтернативни уређивачи

Omarchy подразумевано долази са уређивачем [Neovim](https://neovim.io/), али ако желите нешто мало уобичајеније и познатије, можете да покренете Omarchy Menu (`Super + Space`) и погледате опције под _Инсталирање > Уређивач_. Тамо су наведени VSCode, Cursor, Zed, Sublime Text, Helix, Vim и Emacs. Ако не пронађете оно што тражите, погледајте _Инсталирање > Пакет_ и проверите да ли се налази у неком Arch пакету, а ако се не налази, покушајте преко _Инсталирање > AUR_ да проверите AUR.

Оригинални уређивач `vi` такође је доступан одмах по инсталацији. Покрените `vi filename` да бисте уредили датотеку у терминалу.

Усклађивање теме понуђено је за `VSCode`, `Cursor`, `VSCodium` и `Helix`.

Подразумевани уређивач за цео систем можете да подесите под `Подешавање > Подразумевано > Уређивач`.

## Окружење

Omarchy подржава подешавање читавог низа развојних окружења кроз одељак _Инсталирање > Развој_ у Omarchy Menu (`Super + Space`). Наравно, тамо ћете пронаћи _Ruby on Rails_, али и сва три главна извршна окружења за JavaScript (Node.js, Bun, Deno), као и популарне PHP оквире као што су Laravel и Symfony. А ту су и Go, Rust, Python, Java, Elixir (са оквиром Phoenix), .NET, OCaml, Zig, Clojure и Scala. Избор је заиста веома широк!

Већином ових окружења управља [Mise](https://mise.jdx.dev/). То је алат који вам омогућава да инсталирате и покрећете више верзија неког програмског језика на истој машини. Сличан је алатима rbenv или rvm за Ruby или virtualenv за Python, али ради за читав низ различитих окружења.

Да бисте инсталирали, на пример, Ruby, покренули бисте `mise use -g ruby`, што ће и инсталирати Ruby и поставити га као глобално подразумевани. Или, ако ваш пројекат има датотеку .ruby-version, можете једноставно да покренете `mise i` у корену тог пројекта.

## Унапред инсталирани CLI алати

Omarchy алате као што су `gh`, `uv` и већину [агената за програмирање](17-ai.md) чини доступним кроз [лењу инсталацију алата mise](https://mise.jdx.dev/dev-tools/shims.html#lazy-tools). Први пут када покренете неки од њих, mise га инсталира. Каснија покретања користе инсталирану верзију; не проверавају ажурирање при сваком покретању.

Такође можете да прегледате подразумеване алате или да их инсталирате унапред:

```bash
mise ls --current              # List the tools configured for this directory
mise install gh               # Install one tool now
mise install --include-lazy    # Install all configured tools, including lazy tools
```

Покрените `omarchy update` да бисте ажурирали инсталиране алате заједно са остатком система Omarchy. Псеудоним `mup` ажурира само алате којима управља mise. Да бисте додали још један алат у сопствену конфигурацију, користите `mise use -g <tool>`.

Подешавање језика Python такође инсталира `uv` кроз mise. Уклањањем развојног окружења за Python, `uv` остаје доступан као самосталан алат.

### Коришћење сопствене инсталације

Команде алата mise долазе пре `~/.local/bin` у променљивој `PATH`, па алат који сте сами инсталирали, на пример помоћу инсталатера за Claude Code или Cursor, и даље покреће копију алата mise. Апликације покренуте са радне површине такође проналазе команде алата mise пре системских пакета, па апликација која покрене `gh` добија копију алата mise чак и ако сте инсталирали `github-cli` помоћу програма pacman, а mise ту копију инсталира при првом покретању. Да бисте уместо ње користили своју, онемогућите копију алата mise у датотеци `~/.config/mise/config.toml`. На пример, ако сте сами инсталирали Cursor CLI:

```toml
[settings]
disable_tools = ["cursor-agent"]
```

Ако већ имате табелу `[settings]`, додајте ставку у њу; проширите постојећу листу `disable_tools`, уместо да је замењујете. Уверите се да се ваша инсталација налази у променљивој `PATH`. Користите назив алата у систему mise, који се може разликовати од његове команде: `oh-my-pi` пружа `omp`, на пример. Покретач подразумеваног агента такође даје предност кориснички инсталираном алату Cursor или Muse у директоријуму `~/.local/bin`.

### Уклањање и враћање подразумеваних алата

_Уклони унапред инсталиране алате_ наводи mise да прескочи Omarchy декларације алата за вашег корисника, тако што их додаје у `ignored_config_paths` у датотеци `~/.config/mise/miserc.toml`. _Врати унапред инсталиране алате_ поново уклања ту линију. Алати које сами декларишете, у сопственој конфигурацији или у датотеци `mise.toml` неког пројекта, настављају да раде у оба случаја. Ако изаберете подразумеваног агента или подесите Python након уклањања унапред инсталираних алата, тај алат се додаје у вашу сопствену конфигурацију. Обе опције примењују се само на вашег корисника; други корисници на машини задржавају сопствени избор.

## Docker

[Docker](https://www.docker.com/) једва да треба представљати. Омогућава вам да покрећете изоловане контејнере, а Omarchy инсталира све што је потребно да би добро радио, укључујући сам Docker и [Docker Compose](https://docs.docker.com/compose/).

Ваш корисник подразумевано *није* у групи `docker`. Та група је у суштини root без лозинке — све што се у њој налази може да покрене `docker run -v /:/host` и преузме машину — па би један једини одметнути скрипт или зависност која се извршава под вашим налогом иначе био на једну команду од root приступа. Зато на командној линији Docker покрећете са `sudo` (`sudo docker ps`, `sudo docker compose up`), а графички алати који комуницирају са демоном — Windows VM — траже ауторизацију када им је потребна. Ако желите да вратите погодност рада без `sudo` команде и разумете компромис, омогућите je из **Подешавање > Безбедност > Docker без sudo команде** (или покрените `omarchy-setup-security-sudoless-docker`), што вас након упозорења додаје у групу `docker`; тада обичан `docker` и псеудоним `d` поново раде без `sudo`.

Уобичајене базе података за локални развој у Docker-у можете да подесите помоћу _Инсталирање > Развој > Docker DB_ у Omarchy менију.

## GitHub CLI

[GitHub CLI](https://cli.github.com/) доступан је као `gh` за рад са репозиторијумима, проблемима и захтевима за повлачење из терминала. Покрените `gh auth login` да бисте га инсталирали при првој употреби и аутентификовали се, а затим `gh repo clone org/repo` да бисте клонирали репозиторијум. Покрените `gh --help` да бисте истражили његове команде.

За терминалски интерфејс за захтеве за повлачење покрените `ghui`; mise га такође инсталира при првој употреби. [Lazygit](https://github.com/jesseduffield/lazygit) је унапред инсталиран за рад са самим системом Git.
