# Инсталације без надзора

Omarchy ISO може сам да се инсталира, без икога за тастатуром. Ако инсталер пронађе други диск са ознаком `cidata` који носи његове конфигурационе датотеке, копира их, у потпуности прескаче чаробњак за подешавање и сам се поново покреће у готов систем. Није потребна посебна верзија ISO-а, нема додатне ставке у менију за покретање — ако такав диск није прикључен, ништа се не мења и добијате уобичајени чаробњак.

Зато је Omarchy одличан као основна слика за једнократна развојна окружења: направите VM у окружењу Proxmox или помоћу алата Packer, покренете га, одете и касније се повежете преко SSH-а. `cidata` је ознака cloud-init `NoCloud`, па сви уобичајени алати за виртуализацију већ знају како да прикључе такав диск.

## Конфигурационе датотеке

Датотеке су тачно оне које записује чаробњак самог инсталера, па је најлакши начин да добијете почетни скуп да обавите једну интерактивну инсталацију (у VM-у, рецимо) и копирате оно што је записао у `/root`:

| Датотека | Обавезна | Намена |
|------|----------|---------|
| `user_configuration.json` | Да | Диск, име хоста, временска зона, тастатура |
| `user_credentials.json` | Да | Корисничко име и хеш лозинке, као и LUKS лозинка за шифровану инсталацију |
| `user_encrypt_installation.txt` | Не | `true` када конфигурација садржи блок `disk_encryption` |
| `authorized_keys` | Не | SSH јавни кључеви, по један у сваком реду |
| `tailscale_authkey` | Не | Tailscale кључ за аутентификацију за прикључивање вашем tailnet-у при првом покретању |

Хеш лозинке за `user_credentials.json` генеришите помоћу `openssl passwd -6 "yourpassword"`.

Име и имејл за git комитове нису део инсталације. Подесите их када машина буде подигнута, преко SSH-а на пример, помоћу `omarchy setup git --name "Jane Doe" --email jane@example.com`.

Уместо `user_credentials.json` можете убацити и празну датотеку под именом `defer-provisioning`. Тиме се покреће иста [инсталација припреме за другог власника](02-getting-started.md) коју можете да покренете интерактивно: машина се инсталира без личних података, а ко је први покрене бира своју тастатуру и прави свог корисника. То је режим за уређаје за прављење слика, где диск уопште не треба да носи ничије акредитиве.

## SSH приступ

Када је присутна датотека `authorized_keys`, инсталација поставља кључеве као корисничку датотеку `~/.ssh/authorized_keys`, омогућава `sshd` и отвара га у заштитном зиду. (Стандардна Omarchy инсталација долази са пакетом openssh са онемогућеном услугом и затвореним портом, па машина без надзора иначе не би била достижна.) Инсталација само додаје ваше кључеве — не попушта ниједно друго подешавање аутентификације SSH демона.

Када је присутна датотека `tailscale_authkey`, машина се уместо тога при првом покретању прикључује вашем tailnet-у: Tailscale се инсталира из пакета приложених уз ISO, заштитни зид дозвољава tailnet интерфејс, а позадински посао покреће прикључивање чим машина заиста добије мрежу и покушава поново док не успе. Користите кључ за вишекратну употребу са унапред датим овлашћењем, да једна слика диска може да послужи за много машина.

## Прављење cidata диска

Ради било који систем датотека са правом ознаком. Мајушни ISO је лак начин:

```bash
mkdir cidata
cp user_configuration.json user_credentials.json authorized_keys cidata/
genisoimage -output cidata.iso -volid cidata -joliet -rock cidata/
```

Затим га прикључите на VM уз Omarchy ISO. Ево потпуног примера за Proxmox:

```bash
qm create 101 --name my-omarchy \
  --bios ovmf --machine q35 --cpu host --cores 4 --memory 8192 \
  --ostype l26 --scsihw virtio-scsi-single \
  --efidisk0 local-lvm:0,efitype=4m,pre-enrolled-keys=0 \
  --scsi0 local-lvm:40,discard=on,iothread=1 \
  --net0 virtio,bridge=vmbr0 --vga virtio --serial0 socket \
  --ide2 local:iso/omarchy.iso,media=cdrom \
  --ide3 local:iso/cidata.iso,media=cdrom \
  --boot order='scsi0;ide2'

qm start 101
```

Редослед покретања намерно ставља диск на прво место: празан диск при првом покретању пролази даље до ISO-а, а инсталирани систем се после тога заувек покреће са диска.

## Две напомене

Шифроване инсталације без надзора нису у потпуности без надзора — неко и даље мора да укуца LUKS лозинку при првом покретању. И та лозинка иде на највиши ниво датотеке `user_credentials.json` као `encryption_password` — archinstall је чита одатле, а не из блока `disk_encryption` у датотеци `user_configuration.json` — па cidata диск направљен на основу шифроване инсталације третирајте као тајну каква и јесте.
