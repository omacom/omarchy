# Инсталације без надзора

Omarchy ISO може сам да се инсталира, без икога за тастатуром. Ако програм за инсталацију пронађе други диск са ознаком `cidata` који садржи његове датотеке за конфигурацију, копира их, у потпуности прескаче чаробњак за подешавање и сам се поново покреће у готов систем. Није потребна посебна верзија ISO датотеке, нити додатна ставка у менију за покретање — ако такав диск није прикључен, ништа се не мења и добијате уобичајени чаробњак.

Због тога је Omarchy одличан као основна слика за једнократна развојна окружења: направите VM у Proxmox-у или помоћу Packer-а, покренете је, удаљите се и повежете се преко SSH-а. `cidata` је ознака cloud-init `NoCloud`, па сви уобичајени алати за виртуелизацију већ знају како да прикључе такав диск.

## Датотеке за конфигурацију

Датотеке су управо оне које пише чаробњак самог програма за инсталацију, па је најлакши начин да добијете почетни скуп да обавите једну интерактивну инсталацију (у VM-у, рецимо) и копирате оно што је записао у `/root`:

| Датотека | Обавезно | Намена |
|------|----------|---------|
| `user_configuration.json` | Да | Диск, име домаћина, временска зона, тастатура |
| `user_credentials.json` | Да | Корисничко име и хеш лозинке |
| `user_encrypt_installation.txt` | Не | `true` када конфигурација садржи блок `disk_encryption` |
| `authorized_keys` | Не | SSH јавни кључеви, по један у сваком реду |
| `tailscale_authkey` | Не | Tailscale кључ за аутентификацију за придруживање вашем tailnet-у при првом покретању |

Генеришите хеш лозинке за `user_credentials.json` помоћу `openssl passwd -6 "yourpassword"`.

Име и имејл за git уписе нису део инсталације. Подесите их када машина проради, преко SSH-а на пример, помоћу `omarchy setup git --name "Jane Doe" --email jane@example.com`.

Можете и да убаците празну датотеку под називом `defer-provisioning` уместо `user_credentials.json`. То покреће исту [инсталацију припремљену за другог власника](02-getting-started.md) коју можете да покренете и интерактивно: машина се инсталира без личних података, а ко је први покрене бира своју тастатуру и прави свог корисника. То је режим за уређаје за израду слика, где диск уопште не би требало да садржи ичије акредитиве.

## SSH приступ

Када је `authorized_keys` присутан, инсталација подешава кључеве као кориснички `~/.ssh/authorized_keys`, омогућава `sshd` и отвара заштитни зид за њега. (Стандардна Omarchy инсталација испоручује openssh са онемогућеном услугом и затвореним портом, па би машина без надзора иначе била недоступна.) Инсталација само додаје ваше кључеве — не олабављује ниједно друго подешавање аутентификације SSH демона.

Када је `tailscale_authkey` присутан, машина се уместо тога при првом покретању придружује вашем tailnet-у: Tailscale се инсталира из пакета приложених уз ISO, заштитни зид дозвољава интерфејс tailnet-а, а посао у позадини извршава придруживање чим машина заиста добије мрежу, понављајући покушаје док не успе. Користите кључ за вишекратну употребу, унапред овлашћен, како би једна слика диска могла да послужи многим машинама.

## Израда cidata диска

Било који систем датотека са правом ознаком ради. Мала ISO датотека је једноставан начин:

```bash
mkdir cidata
cp user_configuration.json user_credentials.json authorized_keys cidata/
genisoimage -output cidata.iso -volid cidata -joliet -rock cidata/
```

Затим га прикључите VM-у заједно са Omarchy ISO датотеком. Ево целог примера за Proxmox:

```bash
qm create 101 --name my-omarchy \
  --bios ovmf --machine q35 --cpu host --cores 4 --memory 8192 \
  --ostype l26 --scsihw virtio-scsi-single \
  --efidisk0 local-lvm:0,efitype=4m,pre-enrolled-keys=0 \
  --scsi0 local-lvm:40,discard=on,iothread=1 \
  --net0 virtio,bridge=vmbr0 --vga virtio --serial0 socket \
  --ide2 local:iso/omarchy.iso,media=cdrom \
  --ide3 local:iso/cidata.iso,media=cdrom \
  --boot order='scsi0;ide2'

qm start 101
```

Редослед покретања намерно наводи диск на првом месту: празан диск при првом покретању прелази на ISO, а инсталирани систем се после тога увек покреће са диска.

## Два упозорења

Шифроване инсталације без надзора нису у потпуности без надзора — неко и даље мора да укуца LUKS лозинку при првом покретању. А блок `disk_encryption` у `user_configuration.json` садржи ту лозинку у отвореном тексту, па cidata диск направљен од шифроване инсталације третирајте као тајну каква јесте.
