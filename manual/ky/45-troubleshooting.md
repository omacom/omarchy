# Көйгөйлөрдү чечүү

### Жаңыртуу тутумумду бузуп салды!

Адегенде [тутумуңузду](47-system-snapshots.md) акыркы жаңыртууга чейинки версияга кайтарып көрүңүз. Эгер бул жардам бербесе, `omarchy-debug` колдонуп, көйгөйүңүздү Discord'догу #omarchy-help каналында бөлүшүңүз. Ал эми баары эле майнап чыкпаса, `omarchy-reinstall` менен демейки конфигурацияларды жана пакеттерди кайра орното аласыз.

### Эмне үчүн экранымда кээ бир тиркемелер ушунчалык чоң?

Omarchy 2x жогорку чечилиштеги экранды болжолдойт, ошондуктан мониторлор панелинде масштаб тандамайынча `GDK_SCALE` маанисин 2 кылып коёт. Эгер 1x экраныңыз болсо жана GTK же X11 тиркемелери өтө чоң чыкса, мониторлор панелинде ал экран үчүн 1x тандаңыз же `~/.config/hypr/monitors.lua` файлына `hl.env("GDK_SCALE", "1")` кошуңуз (андан кийин өтө чоң болуп жаткан тиркемени кайра иштетиңиз). [Мониторлор боюнча колдонмону](33-monitors.md) караңыз.

Spotify үчүн интерфейсти кичирейтүүгө `Ctrl + Minus` (чоңойтууга `Ctrl + Plus`) колдонсоңуз болот.

### Эмне үчүн Super баскычы менен болгон бардык айкалыштарым иштебей калды?

Кээ бир ASUS ROG жана TUF ноутбуктарында `Fn + Super` — байкалбай калышы оңой айкалыш, ал микропрограммадагы Windows баскычынын кулпусун күйгүзүп-өчүрөт (оюн учурунда кокусунан оюндан чыгып кетпөө үчүн жасалган). Экранда мунун болгону тууралуу эч нерсе айтылбайт. Кулпу күйүп турганда Super таптакыр эч нерсе жибербейт — ошондуктан Super колдонгон Omarchy'нин ар бир айкалышы жөн эле токтоп калат жана Hyprland бузулуп калгандай көрүнөт.

`~/.config/hypr/` ичин казып баштаардан мурун `Fn + Super` бир жолу басыңыз, эгер ал Super'ди кайтарбаса, кулпу күйүк бойдон калбашы үчүн аны дагы бир жолу басыңыз. Бул Fn-кулпу эмес, ал F баскычтарынын катары эмне кыларын гана өзгөртөт.

### Wi-Fi, Bluetooth, үн же сенсордук такта жөн эле иштебей калды

Кайра жүктөөдөн мурун көйгөй жараткан бөлүктү өзүнчө кайра иштетип көрүңүз. Omarchy менюсундагы _Жаңыртуу > Жабдуулар_ ичинде Wi-Fi, Bluetooth, Үн жана Сенсордук такта бар, жана алардын бирин кайра жүктөө «беш мүнөт мурун эле иштеп жаткан» кырдаалдардын көпчүлүгүн чечет — кайра туташпаган Bluetooth гарнитурасы, уйку режиминен кийин иштебей калган сенсордук такта, мониторду ажыратканда жоголгон үн.

### Эмне үчүн тышкы колонкаларым үн чыгарбайт?

Балким, алар негизги чыгаруу түзмөгү катары коюлган эмес. Панелдин оң жагындагы динамик сүрөтчөсүн басыңыз, ошондо үн калкыма терезеси ачылат, анда чыгаруу түзмөгүн тандай аласыз (жана ар бир тиркеменин үнүн өзүнчө жөндөсөңүз да болот).

### Ноутбугумдун динамиктери туура эмес угулат

Кээ бир ноутбуктарда Omarchy камтылган динамиктердин жыштык мүнөздөмөсүн оңдогон динамик тууралоосун автоматтык түрдө колдонот. `omarchy audio tuning status` машинаңызда андай тууралоо иштеп жатабы же жокпу, айтып берет, ал эми динамиктерди оңдоосуз уккуңуз келсе, `omarchy audio tuning off` аны өчүрөт.

### Эмне үчүн сырсөзүм менен кире албай же sudo колдоно албай жатам?

Балким, аны он жолу туура эмес терип, бөгөттөлүп калгандырсыз. Бөгөт эки мүнөттөн кийин өзү эле алынат. Күтө албасаңыз жана бул кулпу экранында болуп жатса, `CTRL + ALT + F2` басып жаңы TTY ачсаңыз болот, анда root катары кирип, `faillock --reset --user [your-username]` иштетиңиз. Ошону менен бөгөт алынат жана ишиңизди уланта бересиз.

### Сырсөзүм кабыл алынат, бирок кайра кирүү экранына кайтып келем

Сеанстын бузулган чөйрө файлы сырсөзүңүз туура болсо да иш тактанын ачылышына тоскоол болушу мүмкүн. Муну айрыкча `~/.config/uwsm/env.d/` түзөткөндөн кийин текшерип көрүү керек.

`Ctrl + Alt + F2` басып, кадимки колдонуучу атыңыз жана сырсөзүңүз менен кириңиз да, учурдагы жүктөлүүнүн колдонуучу журналын карап чыгыңыз:

```bash
journalctl --user -b -t uwsm_env-preloader --no-pager
```

Чөйрө файлдарыңыздын бирин атаган катаны, мисалы `bad substitution`, env чыгаруусунун белгиси табылган жок деген билдирүүнүн алдынан издеңиз. Кайра кирүүгө аракет кылардан мурун ошол файлды `env.d` ичинен чыгарып коюңуз. Мисалы, ката `99-custom` файлын атаса:

```bash
mkdir -p ~/.config/uwsm/disabled
mv -i ~/.config/uwsm/env.d/99-custom ~/.config/uwsm/disabled/
```

UWSM синтаксистик катасы бар файлды өткөрүп жиберет, бирок файл иштеп жатканда гана чыга турган олуттуу ката, мисалы `bad substitution`, баары бир иш тактанын ачылышына тоскоол болушу мүмкүн. Тутумдун снапшотун кайтаруу бул файлдарды оңдобойт, анткени `/home` кайтарылбайт.

Кире алганыңыздан кийин, файлды ордуна кайтарардан мурун сакталган нускасын оңдоп алыңыз. `sh -n` файлды иштетпей эле синтаксистик каталарды табат, бирок ал source кылынганда чыга турган ар бир катаны кармай албайт. Өзгөртүүлөрдү сынап жатканда иштеп турган терминалды ачык калтырыңыз.

### Эмне үчүн 1Password SSH Agent / CLI үчүн 1Password уруксат суроолору чыкпай жатат?

Мунун 2 себеби болушу мүмкүн:

Кеңири ырастоо терезеси чыгышы үчүн Settings > Advanced > Use Hardware Acceleration күйгүзүлгөн болушу керек. _Эскертүү: Бул иштей баштоо үчүн кайра жүктөөнү талап кылат._

 ![troubleshooting-1password](images/troubleshooting-1password.webp)

Же болбосо, компьютерди күйгүзгөндөн бери 1Password'ду ачпаган болсоңуз, суроо терезеси чыкпайт.
