# Көзөмөлсүз орнотуулар

Omarchy ISO баскычтоптун алдында эч ким жок болсо да өзүн өзү орното алат. Эгер орноткуч конфигурация файлдарын камтыган `cidata` деп белгиленген экинчи дискти тапса, ал аларды көчүрүп алып, жөндөө устасын толугу менен өткөрүп жиберет жана даяр тутумга өзү кайра жүктөлөт. Атайын ISO курамасы да, жүктөө менюсундагы кошумча пункт да керек эмес — андай диск туташтырылбаса, эч нерсе өзгөрбөйт жана кадимки устаны аласыз.

Бул Omarchy'ни бир жолку иштеп чыгуу чөйрөлөрү үчүн сонун базалык образ кылат: Proxmox'то же Packer менен VM түзүп, аны жүктөп, кетип калыңыз, кийин SSH аркылуу кириңиз. `cidata` — cloud-init'тин `NoCloud` белгиси, ошондуктан кеңири таралган виртуалдаштыруу куралдарынын баары андай дискти кантип туташтырууну мурунтан эле билет.

## Конфигурация файлдары

Файлдар так ошол орноткучтун өз устасы жазгандар, ошондуктан баштапкы топтомду алуунун эң оңой жолу — бир жолу интерактивдүү орнотуу жасап (мисалы, VM ичинде), анын `/root` ичине жазганын көчүрүп алуу:

| Файл | Милдеттүү | Максаты |
|------|----------|---------|
| `user_configuration.json` | Ооба | Диск, хосттун аты, убакыт алкагы, баскычтоп |
| `user_credentials.json` | Ооба | Колдонуучунун аты жана сырсөздүн хеши, ошондой эле шифрленген орнотуу үчүн LUKS купуя фразасы |
| `user_encrypt_installation.txt` | Жок | Конфигурацияда `disk_encryption` блогу болгондо `true` |
| `authorized_keys` | Жок | SSH ачык ачкычтары, ар бир сапка бирден |
| `tailscale_authkey` | Жок | Биринчи жүктөлгөндө tailnet'иңизге кошулуу үчүн Tailscale аутентификация ачкычы |

`user_credentials.json` үчүн сырсөздүн хешин `openssl passwd -6 "yourpassword"` менен түзүңүз.

Git коммиттери үчүн аты жана электрондук почта орнотуунун бөлүгү эмес. Машина иштей баштагандан кийин, мисалы SSH аркылуу, аларды `omarchy setup git --name "Jane Doe" --email jane@example.com` менен коюңуз.

`user_credentials.json` ордуна `defer-provisioning` аттуу бош файлды да салсаңыз болот. Бул интерактивдүү түрдө да баштоого боло турган ошол эле [башка ээ үчүн даярдоо орнотуусун](02-getting-started.md) иштетет: машина эч кандай жеке маалыматсыз орнотулат, ал эми аны биринчи жүктөгөн адам өз баскычтобун тандап, өз колдонуучусун түзөт. Бул образ даярдоочу стенддер үчүн режим, анда дискте эч кимдин кирүү маалыматтары болбошу керек.

## SSH аркылуу кирүү

`authorized_keys` бар болгондо, орнотуу ачкычтарды колдонуучунун `~/.ssh/authorized_keys` файлы катары коюп, `sshd` иштетет жана ал үчүн брандмауэрди ачат. (Кадимки Omarchy орнотуусу openssh менен келет, бирок кызматы өчүрүлгөн жана порту жабык болот, ошондуктан болбосо көзөмөлсүз машинага жетүү мүмкүн болбой калмак.) Орнотуу ачкычтарыңызды гана кошот — SSH демонунун башка аутентификация жөндөөлөрүнүн бирин да бошотпойт.

`tailscale_authkey` бар болгондо, анын ордуна машина биринчи жүктөлгөндө tailnet'иңизге кошулат: Tailscale ISO'го камтылган пакеттерден орнотулат, брандмауэр tailnet интерфейсине уруксат берет, ал эми фондук тапшырма машинада чындап тармак пайда болоору менен кошулууну иштетет жана ийгиликтүү болгонго чейин кайра-кайра аракет кылат. Бир диск образы көп машинага кызмат кылышы үчүн кайра колдонула турган, алдын ала уруксат берилген ачкычты колдонуңуз.

## cidata дискин түзүү

Туура белгиси бар каалаган файл тутуму иштейт. Кичинекей ISO — эң оңой жол:

```bash
mkdir cidata
cp user_configuration.json user_credentials.json authorized_keys cidata/
genisoimage -output cidata.iso -volid cidata -joliet -rock cidata/
```

Андан кийин аны VM'ге Omarchy ISO менен катар туташтырыңыз. Мына Proxmox үчүн толук мисал:

```bash
qm create 101 --name my-omarchy \
  --bios ovmf --machine q35 --cpu host --cores 4 --memory 8192 \
  --ostype l26 --scsihw virtio-scsi-single \
  --efidisk0 local-lvm:0,efitype=4m,pre-enrolled-keys=0 \
  --scsi0 local-lvm:40,discard=on,iothread=1 \
  --net0 virtio,bridge=vmbr0 --vga virtio --serial0 socket \
  --ide2 local:iso/omarchy.iso,media=cdrom \
  --ide3 local:iso/cidata.iso,media=cdrom \
  --boot order='scsi0;ide2'

qm start 101
```

Жүктөө тартибинде диск атайын биринчи турат: биринчи жүктөлүүдө бош диск ISO'го өтүп кетет, ал эми андан кийин орнотулган тутум дайыма дисктен жүктөлөт.

## Эки эскертүү

Шифрленген көзөмөлсүз орнотуулар толугу менен көзөмөлсүз эмес — биринчи жүктөлгөндө кимдир бирөө баары бир LUKS купуя фразасын териши керек. Ошондой эле ал купуя фраза `user_credentials.json` файлынын жогорку деңгээлине `encryption_password` катары жазылат — archinstall аны `user_configuration.json` ичиндеги `disk_encryption` блогунан эмес, ошол жерден окуйт — ошондуктан шифрленген орнотуудан курулган cidata дискин чыныгы сыр катары сактаңыз.
