# ابزارهای توسعه

## ویرایشگرهای جایگزین

Omarchy در نصب‌های جدید Plain را به‌عنوان ویرایشگر پیش‌فرض دارد و [Neovim](https://neovim.io/) از پیش نصب شده است، اما اگر چیزی کمی جریان‌اصلی‌تر و آشناتر می‌خواهید، می‌توانید منوی Omarchy (`Super + Space`) را اجرا کنید و گزینه‌های زیر _نصب > ویرایشگر_ را ببینید. آنجا VSCode، Cursor، Zed، Sublime Text، Helix، Vim و Emacs را فهرست کرده‌ایم. اگر آنچه دنبالش هستید را پیدا نکردید، _نصب > بسته_ را بررسی کنید و ببینید آیا در یک بسته Arch نیست (و اگر نبود، _نصب > AUR_ را امتحان کنید تا AUR را بررسی کنید).

ویرایشگر اصلی `vi` هم از همان ابتدا در دسترس است. برای ویرایش یک فایل در ترمینال `vi filename` را اجرا کنید.

تطبیق تم برای `VSCode`، `Cursor`، `VSCodium` و `Helix` ارائه می‌شود.

می‌توانید ویرایشگر پیش‌فرض سراسری سیستم را در _تنظیمات > پیش‌فرض‌ها > ویرایشگر_ تنظیم کنید.

## محیط

Omarchy از راه‌اندازی خیل عظیمی از محیط‌های توسعه از طریق بخش _نصب > توسعه_ در منوی Omarchy (`Super + Space`) پشتیبانی می‌کند. البته _Ruby on Rails_ را پیدا خواهید کرد، اما هر سه ران‌تایم اصلی JavaScript (Node.js، Bun، Deno) و همچنین فریم‌ورک‌های محبوب PHP مانند Laravel و Symfony را هم پیدا می‌کنید. اوه، و Go، Rust، Python، Java، Elixir (با Phoenix)، .NET، OCaml، Zig، Clojure و Scala هم هستند. انتخاب بسیار گسترده‌ای است!

اکثریت این محیط‌ها توسط [Mise](https://mise.jdx.dev/) مدیریت می‌شوند. این ابزاری است که به شما امکان می‌دهد چندین نسخه از یک زبان برنامه‌نویسی را روی یک ماشین نصب و اجرا کنید. مثل rbenv یا rvm برای Ruby یا virtualenv برای Python است، اما برای کلی محیط مختلف کار می‌کند.

برای نصب، مثلاً، Ruby، `mise use -g ruby` را اجرا می‌کنید، که هم Ruby را نصب می‌کند و هم آن را به‌عنوان پیش‌فرض سراسری تنظیم می‌کند. یا، اگر پروژه‌تان فایل .ruby-version دارد، می‌توانید فقط `mise i` را در ریشه آن پروژه اجرا کنید.

## ابزارهای CLI از پیش نصب‌شده

Omarchy ابزارهایی مانند `gh`، `uv` و بیشتر [ایجنت‌های کدنویسی](17-ai.md) را از طریق [نصب تنبل mise](https://mise.jdx.dev/dev-tools/shims.html#lazy-tools) در دسترس قرار می‌دهد. اولین باری که یکی را اجرا می‌کنید، mise آن را نصب می‌کند. ایجنت‌های کدنویسی سپس قبل از اجرا، حداکثر یک بار در هر چهار ساعت، به‌روزرسانی را بررسی می‌کنند؛ ابزارهای دیگر، مانند `gh` و `uv`، از نسخه نصب‌شده دوباره استفاده می‌کنند تا زمانی که به‌روزرسانی کنید.

همچنین می‌توانید پیش‌فرض‌ها را بررسی کنید یا آنها را از پیش نصب کنید:

```bash
mise ls --current              # List the tools configured for this directory
mise install gh               # Install one tool now
mise install --include-lazy    # Install all configured tools, including lazy tools
```

برای به‌روزرسانی ابزارهای نصب‌شده همراه با بقیه Omarchy، `omarchy update` را اجرا کنید. نام مستعار `mup` فقط ابزارهای مدیریت‌شده توسط mise را به‌روزرسانی می‌کند. برای افزودن ابزار دیگری به پیکربندی خودتان، از `mise use -g <tool>` استفاده کنید.

راه‌اندازی Python همچنین `uv` را از طریق mise نصب می‌کند. حذف محیط توسعه Python، `uv` را به‌عنوان ابزاری مستقل در دسترس باقی می‌گذارد.

### استفاده از نصب خودتان

دستورهای mise قبل از `~/.local/bin` در `PATH` قرار می‌گیرند، بنابراین ابزاری که خودتان نصب کرده‌اید، مثلاً با نصب‌کننده خود Claude Code یا Cursor، همچنان نسخه mise را اجرا می‌کند. برنامه‌هایی که از دسکتاپ اجرا می‌شوند هم دستورهای mise را قبل از بسته‌های سیستم پیدا می‌کنند، بنابراین برنامه‌ای که `gh` را اجرا می‌کند نسخه mise را می‌گیرد حتی اگر `github-cli` را با pacman نصب کرده باشید، و mise آن نسخه را اولین بار نصب می‌کند. برای استفاده از نسخه خودتان به‌جای آن، نسخه mise را در `~/.config/mise/config.toml` غیرفعال کنید. برای مثال، اگر Cursor CLI را خودتان نصب کرده‌اید:

```toml
[settings]
disable_tools = ["cursor-agent"]
```

اگر از قبل یک جدول `[settings]` دارید، ورودی را همانجا اضافه کنید؛ فهرست موجود `disable_tools` را گسترش دهید به‌جای اینکه آن را جایگزین کنید. مطمئن شوید نصب شما روی `PATH` است. از نام ابزار mise استفاده کنید، که می‌تواند با دستورش متفاوت باشد: برای مثال `oh-my-pi`، `omp` را ارائه می‌دهد. لانچر ایجنت پیش‌فرض هم Cursor یا Muse نصب‌شده توسط کاربر در `~/.local/bin` را ترجیح می‌دهد.

### حذف و بازیابی پیش‌فرض‌ها

_حذف > پیش‌نصب‌ها_ وب‌اپ‌ها، TUIها و برنامه‌های از پیش نصب‌شده Omarchy را حذف می‌کند، و کاری می‌کند mise اعلان‌های ابزار Omarchy را برای کاربر شما نادیده بگیرد، با افزودن آنها به `ignored_config_paths` در `~/.config/mise/miserc.toml`. _نصب > پیش‌نصب‌ها_ آنها را برمی‌گرداند و دوباره آن خط را حذف می‌کند. ابزارهایی که خودتان اعلان می‌کنید، در پیکربندی خودتان یا در `mise.toml` یک پروژه، در هر صورت به کار ادامه می‌دهند. اگر پس از حذف پیش‌نصب‌ها یک ایجنت پیش‌فرض انتخاب کنید یا Python را راه‌اندازی کنید، آن ابزار به پیکربندی خودتان اضافه می‌شود. تنظیم mise فقط برای کاربر شما اعمال می‌شود، و کاربران دیگر انتخاب خودشان را حفظ می‌کنند؛ هرچند برنامه‌ها بسته هستند، بنابراین حذف یا بازیابی آنها آنها را برای همه افراد روی ماشین تغییر می‌دهد.

## Docker

[Docker](https://www.docker.com/) تقریباً نیازی به معرفی ندارد. به شما امکان می‌دهد کانتینرهای ایزوله اجرا کنید، و Omarchy هر آنچه برای اجرای خوب آن لازم است نصب می‌کند، از جمله خود Docker و [Docker Compose](https://docs.docker.com/compose/).

به‌صورت پیش‌فرض کاربر شما در گروه `docker` *نیست*. آن گروه عملاً root بدون رمز عبور است — هر چیزی در آن می‌تواند `docker run -v /:/host` را اجرا کند و ماشین را تصاحب کند — بنابراین در غیر این صورت یک اسکریپت یا وابستگی سرکش که به‌عنوان شما اجرا شود، یک دستور با root فاصله خواهد داشت. بنابراین در خط فرمان Docker را با `sudo` اجرا می‌کنید (`sudo docker ps`، `sudo docker compose up`)، و ابزارهای گرافیکی که با دیمون صحبت می‌کنند — VM ویندوز — وقتی به آن نیاز دارند درخواست مجوز می‌کنند. اگر راحتی راه‌اندازی بدون گروه را می‌خواهید و بده‌بستان را درک می‌کنید، آن را از **تنظیمات > امنیت > Docker بدون sudo** (یا `omarchy-setup-security-sudoless-docker` را اجرا کنید) فعال کنید، که پس از یک هشدار شما را به گروه `docker` اضافه می‌کند؛ سپس `docker` ساده و نام مستعار `d` دوباره بدون `sudo` کار می‌کنند.

می‌توانید پایگاه‌داده‌های رایج برای توسعه محلی در Docker را با استفاده از _نصب > توسعه > Docker DB_ در منوی Omarchy راه‌اندازی کنید.

## GitHub CLI

[GitHub CLI](https://cli.github.com/) به‌عنوان `gh` برای کار با مخازن، issueها و pull requestها از ترمینال در دسترس است. برای نصب آن در اولین استفاده و احراز هویت `gh auth login` را اجرا کنید، سپس برای کلون کردن یک مخزن `gh repo clone org/repo` را اجرا کنید. برای کاوش دستورهای آن `gh --help` را اجرا کنید.

برای یک رابط ترمینالی برای pull requestها، `ghui` را اجرا کنید؛ mise آن را هم در اولین استفاده نصب می‌کند. [Lazygit](https://github.com/jesseduffield/lazygit) برای کار با خود Git از پیش نصب شده است.
