# ابزارهای توسعه

## ویرایشگرهای جایگزین

Omarchy به‌طور پیش‌فرض با [Neovim](https://neovim.io/) ارائه می‌شود، اما اگر چیزی رایج‌تر و آشناتر می‌خواهید، می‌توانید منوی Omarchy (`Super + Space`) را اجرا کنید و گزینه‌های زیر _نصب > Editor_ را ببینید. در آنجا VSCode، Cursor، Zed، Sublime Text، Helix، Vim و Emacs فهرست شده‌اند. اگر آنچه را که دنبالش هستید پیدا نکردید، به _نصب > Package_ سر بزنید و ببینید آیا در یک بسته Arch هست یا نه (و اگر نبود، _نصب > AUR_ را امتحان کنید تا AUR را بررسی کنید).

ویرایشگر اصلی `vi` هم از همان ابتدا در دسترس است. برای ویرایش یک فایل در ترمینال، `vi filename` را اجرا کنید.

تطبیق تم برای `VSCode`، `Cursor`، `VSCodium` و `Helix` ارائه می‌شود.

می‌توانید ویرایشگر پیش‌فرض کل سیستم را در `تنظیمات > Defaults > Editor` تنظیم کنید.

## محیط

Omarchy از راه‌اندازی انواع و اقسام محیط‌های توسعه از طریق بخش _نصب > Development_ در منوی Omarchy (`Super + Space`) پشتیبانی می‌کند. البته _Ruby on Rails_ را آنجا پیدا می‌کنید، اما هر سه زمان‌اجرای اصلی JavaScript (Node.js، Bun، Deno) و همچنین چارچوب‌های محبوب PHP مانند Laravel و Symfony را هم پیدا می‌کنید. آه، و Go، Rust، Python، Java، Elixir (همراه با Phoenix)، .NET، OCaml، Zig، Clojure و Scala هم هستند. گزینش بسیار گسترده‌ای است!

اکثر این محیط‌ها توسط [Mise](https://mise.jdx.dev/) مدیریت می‌شوند. این ابزاری است که به شما اجازه می‌دهد چندین نسخه از یک زبان برنامه‌نویسی را روی یک دستگاه نصب و اجرا کنید. مانند rbenv یا rvm برای Ruby یا virtualenv برای Python است، اما برای کلی محیط مختلف کار می‌کند.

برای نصب، مثلاً، Ruby، باید `mise use -g ruby` را اجرا کنید، که هم Ruby را نصب می‌کند و هم آن را به‌عنوان پیش‌فرض سراسری تنظیم می‌کند. یا، اگر پروژه شما یک فایل .ruby-version دارد، می‌توانید فقط `mise i` را در ریشه آن پروژه اجرا کنید.

## Docker

[Docker](https://www.docker.com/) به‌سختی نیازی به معرفی دارد. به شما اجازه می‌دهد کانتینرهای ایزوله اجرا کنید، و Omarchy هر آنچه برای اجرای خوب آن لازم است نصب می‌کند، از جمله خود Docker و [Docker Compose](https://docs.docker.com/compose/).

به‌طور پیش‌فرض کاربر شما در گروه `docker` *نیست*. آن گروه در واقع root بدون گذرواژه است — هر چیزی در آن می‌تواند `docker run -v /:/host` را اجرا کند و دستگاه را تصاحب کند — پس یک اسکریپت یا وابستگی سرکش که به‌عنوان شما اجرا شود، در غیر این صورت فقط یک دستور با root فاصله خواهد داشت. پس در خط فرمان، Docker را با `sudo` اجرا می‌کنید (`sudo docker ps`، `sudo docker compose up`)، و ابزارهای گرافیکی که با دیمون صحبت می‌کنند — ماشین مجازی Windows — وقتی به آن نیاز دارند، درخواست مجوز می‌کنند. اگر راحتی راه‌اندازی بدون گروه را می‌خواهید و بده‌بستان آن را درک می‌کنید، آن را از **تنظیمات > Security > Sudoless Docker** فعال کنید (یا `omarchy-setup-security-sudoless-docker` را اجرا کنید)، که پس از یک هشدار شما را به گروه `docker` اضافه می‌کند؛ آنگاه `docker` ساده و نام مستعار `d` دوباره بدون `sudo` کار می‌کنند.

می‌توانید پایگاه‌های داده رایج برای توسعه محلی در Docker را با استفاده از _نصب > Development > Docker DB_ در منوی Omarchy راه‌اندازی کنید.

## GitHub CLI

[GitHub CLI](https://cli.github.com/) به شما اجازه می‌دهد با حساب GitHub خود احراز هویت کنید و با استفاده از آن مخازن خصوصی را کلون کنید. این ابزار به‌عنوان یکی از استاب‌های mise با بارگذاری تنبل سیم‌کشی شده است، پس اولین باری که `gh` را اجرا می‌کنید، خودش نصب می‌شود. برای احراز هویت، `gh auth login` را اجرا کنید. آنگاه می‌توانید مخازن خصوصی را با استفاده از `gh repo clone org/repo` چک‌اوت کنید.

همچنین می‌توانید کلی عملیات GitHub دیگر را با استفاده از این دستور انجام دهید. فقط `gh` را اجرا کنید تا هر آنچه ممکن است ببینید.

یک استاب با نصب تنبل برای `ghui` هم برای مدیریت pull requestهای شما در یک TUI وجود دارد. و [lazygit](https://github.com/jesseduffield/lazygit) از پیش نصب شده است، اگر دوست دارید خود git را هم از یک TUI برانید.
