# ابزارهای توسعه

## ویرایشگرهای جایگزین

Omarchy به‌صورت پیش‌فرض با [Neovim](https://neovim.io/) عرضه می‌شود، اما اگر چیزی کمی رایج‌تر و آشناتر می‌خواهید، می‌توانید منوی Omarchy (`Super + Space`) را اجرا کنید و گزینه‌های زیر _نصب > ویرایشگر_ را ببینید. در آنجا VSCode، Cursor، Zed، Sublime Text، Helix، Vim و Emacs را فهرست کرده‌ایم. اگر چیزی را که دنبالش هستید پیدا نکردید، _نصب > بسته_ را بررسی کنید و ببینید در یک بسته Arch وجود ندارد یا نه (و اگر نبود، _نصب > AUR_ را امتحان کنید تا AUR را بررسی کنید).

ویرایشگر اصلی `vi` نیز از همان ابتدا در دسترس است. برای ویرایش یک فایل در ترمینال، `vi filename` را اجرا کنید.

تطبیق تم برای `VSCode`، `Cursor`، `VSCodium` و `Helix` ارائه می‌شود.

می‌توانید ویرایشگر پیش‌فرض کل سیستم را در `Setup > Defaults > Editor` تنظیم کنید.

## محیط

Omarchy از راه‌اندازی مجموعه کاملی از محیط‌های توسعه از طریق بخش _نصب > توسعه_ در منوی Omarchy (`Super + Space`) پشتیبانی می‌کند. البته _Ruby on Rails_ را پیدا خواهید کرد، اما هر سه ران‌تایم اصلی JavaScript (Node.js، Bun، Deno) و همچنین فریم‌ورک‌های محبوب PHP مانند Laravel و Symfony را نیز خواهید یافت. اوه، و Go، Rust، Python، Java، Elixir (با Phoenix)، .NET، OCaml، Zig، Clojure و Scala هم هستند. انتخاب بسیار گسترده‌ای است!

بیشتر این محیط‌ها توسط [Mise](https://mise.jdx.dev/) مدیریت می‌شوند. این ابزاری است که به شما امکان می‌دهد چندین نسخه از یک زبان برنامه‌نویسی را روی یک ماشین نصب و اجرا کنید. مانند rbenv یا rvm برای Ruby یا virtualenv برای Python است، اما برای کلی محیط مختلف کار می‌کند.

برای نصب، مثلاً، Ruby، باید `mise use -g ruby` را اجرا کنید، که هم Ruby را نصب می‌کند و هم آن را به‌عنوان پیش‌فرض سراسری تنظیم می‌کند. یا، اگر پروژه شما یک فایل .ruby-version دارد، می‌توانید فقط `mise i` را در ریشه آن پروژه اجرا کنید.

## ابزارهای CLI از پیش نصب‌شده

Omarchy ابزارهایی مانند `gh`، `uv` و بیشتر [ایجنت‌های کدنویسی](17-ai.md) را از طریق [نصب تنبل mise](https://mise.jdx.dev/dev-tools/shims.html#lazy-tools) در دسترس قرار می‌دهد. اولین باری که یکی از آن‌ها را اجرا می‌کنید، mise آن را نصب می‌کند. اجراهای بعدی از نسخه نصب‌شده دوباره استفاده می‌کنند؛ آن‌ها در هر بار اجرا بررسی نمی‌کنند که به‌روزرسانی‌ای وجود دارد یا نه.

همچنین می‌توانید پیش‌فرض‌ها را بررسی کنید یا آن‌ها را از قبل نصب کنید:

```bash
mise ls --current              # List the tools configured for this directory
mise install gh               # Install one tool now
mise install --include-lazy    # Install all configured tools, including lazy tools
```

برای به‌روزرسانی ابزارهای نصب‌شده همراه با بقیه Omarchy، `omarchy update` را اجرا کنید. نام مستعار `mup` فقط ابزارهای مدیریت‌شده توسط mise را به‌روزرسانی می‌کند. برای افزودن ابزار دیگری به پیکربندی خودتان، از `mise use -g <tool>` استفاده کنید.

راه‌اندازی Python همچنین `uv` را از طریق mise نصب می‌کند. حذف محیط توسعه Python، `uv` را به‌عنوان ابزاری مستقل در دسترس باقی می‌گذارد.

### استفاده از نصب خودتان

دستورات mise قبل از `~/.local/bin` در `PATH` قرار می‌گیرند، بنابراین ابزاری که خودتان نصب کرده‌اید، مثلاً با نصب‌کننده خود Claude Code یا Cursor، همچنان نسخه mise را اجرا می‌کند. برنامه‌هایی که از دسکتاپ اجرا می‌شوند نیز دستورات mise را قبل از بسته‌های سیستم پیدا می‌کنند، بنابراین برنامه‌ای که `gh` را اجرا می‌کند نسخه mise را دریافت می‌کند، حتی اگر `github-cli` را با pacman نصب کرده باشید، و mise آن نسخه را در اولین بار نصب می‌کند. برای اینکه به‌جای آن از نسخه خودتان استفاده کنید، نسخه mise را در `~/.config/mise/config.toml` غیرفعال کنید. برای مثال، اگر خودتان Cursor CLI را نصب کرده‌اید:

```toml
[settings]
disable_tools = ["cursor-agent"]
```

اگر از قبل یک جدول `[settings]` دارید، ورودی را در همانجا اضافه کنید؛ یک فهرست `disable_tools` موجود را گسترش دهید، نه اینکه آن را جایگزین کنید. مطمئن شوید نصب شما در `PATH` قرار دارد. از نام ابزار mise استفاده کنید، که می‌تواند با دستور آن متفاوت باشد: برای مثال، `oh-my-pi`، `omp` را ارائه می‌دهد. اجراکننده ایجنت پیش‌فرض نیز Cursor یا Muse نصب‌شده توسط کاربر در `~/.local/bin` را ترجیح می‌دهد.

### حذف و بازگردانی پیش‌فرض‌ها

_حذف پیش‌نصب‌ها_ باعث می‌شود mise از اعلان‌های ابزار Omarchy برای کاربر شما صرف‌نظر کند، با افزودن آن‌ها به `ignored_config_paths` در `~/.config/mise/miserc.toml`. _بازگردانی پیش‌نصب‌ها_ دوباره آن خط را حذف می‌کند. ابزارهایی که خودتان اعلان می‌کنید، در پیکربندی خودتان یا در `mise.toml` یک پروژه، در هر صورت به کار خود ادامه می‌دهند. اگر پس از حذف پیش‌نصب‌ها یک ایجنت پیش‌فرض انتخاب کنید یا Python را راه‌اندازی کنید، آن ابزار به پیکربندی خودتان اضافه می‌شود. هر دو فقط برای کاربر شما اعمال می‌شوند؛ کاربران دیگر روی ماشین انتخاب خودشان را حفظ می‌کنند.

## Docker

[Docker](https://www.docker.com/) به‌سختی به هیچ معرفی‌ای نیاز دارد. به شما امکان می‌دهد کانتینرهای ایزوله اجرا کنید، و Omarchy همه چیزهای لازم برای اجرای خوب آن را نصب می‌کند، از جمله خود Docker و [Docker Compose](https://docs.docker.com/compose/).

به‌صورت پیش‌فرض کاربر شما در گروه `docker` *نیست*. آن گروه عملاً root بدون گذرواژه است — هر چیزی در آن می‌تواند `docker run -v /:/host` را اجرا کند و کنترل ماشین را به دست بگیرد — بنابراین یک اسکریپت یا وابستگی سرکش که به‌عنوان شما اجرا شود، در غیر این صورت فقط یک دستور با root فاصله خواهد داشت. بنابراین در خط فرمان Docker را با `sudo` اجرا می‌کنید (`sudo docker ps`، `sudo docker compose up`)، و ابزارهای گرافیکی که با دیمون صحبت می‌کنند — VM ویندوز — وقتی به آن نیاز دارند درخواست مجوز می‌کنند. اگر راحتی راه‌اندازی بدون گروه را می‌خواهید و بده‌بستان آن را درک می‌کنید، آن را از **راه‌اندازی > امنیت > Docker بدون sudo** فعال کنید (یا `omarchy-setup-security-sudoless-docker` را اجرا کنید)، که پس از یک هشدار شما را به گروه `docker` اضافه می‌کند؛ سپس `docker` ساده و نام مستعار `d` دوباره بدون `sudo` کار می‌کنند.

می‌توانید پایگاه‌های داده رایج برای توسعه محلی در Docker را با استفاده از _نصب > توسعه > Docker DB_ در منوی Omarchy راه‌اندازی کنید.

## GitHub CLI

[GitHub CLI](https://cli.github.com/) به‌عنوان `gh` برای کار با مخزن‌ها، issueها و pull requestها از ترمینال در دسترس است. `gh auth login` را اجرا کنید تا در اولین استفاده آن را نصب و احراز هویت کنید، سپس `gh repo clone org/repo` را برای کلون کردن یک مخزن اجرا کنید. برای کاوش دستورات آن `gh --help` را اجرا کنید.

برای یک رابط ترمینالی برای pull requestها، `ghui` را اجرا کنید؛ mise آن را نیز در اولین استفاده نصب می‌کند. [Lazygit](https://github.com/jesseduffield/lazygit) برای کار با خود Git از پیش نصب شده است.
