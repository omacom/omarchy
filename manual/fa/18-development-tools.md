# ابزارهای توسعه

## ویرایشگرهای جایگزین

Omarchy در نصب‌های جدید با Plain به‌عنوان ویرایشگر پیش‌فرض و [Neovim](https://neovim.io/) از پیش نصب‌شده عرضه می‌شود، اما اگر چیزی کمی متعارف‌تر و آشناتر می‌خواهید، می‌توانید Omarchy Menu (`Super + Space`) را اجرا کنید و گزینه‌های زیر _Install > Editor_ را ببینید. VSCode و Cursor و Zed و Sublime Text و Helix و Vim و Emacs را آنجا فهرست کرده‌ایم. اگر آنچه را دنبالش هستید پیدا نکردید، _Install > Package_ را بررسی کنید و ببینید در یک بسته‌ی Arch نیست (و اگر نبود، _Install > AUR_ را امتحان کنید تا AUR را بررسی کنید).

ویرایشگر اصلی `vi` هم از همان اول در دسترس است. برای ویرایش یک فایل در ترمینال، `vi filename` را اجرا کنید.

تطبیق تم برای `VSCode` و `Cursor` و `VSCodium` و `Helix` ارائه می‌شود.

می‌توانید ویرایشگر پیش‌فرض سراسر سیستم را زیر `Setup > Defaults > Editor` تنظیم کنید.

## محیط

Omarchy از راه‌اندازی خیل عظیمی از محیط‌های توسعه از طریق بخش _Install > Development_ در Omarchy Menu (`Super + Space`) پشتیبانی می‌کند. البته _Ruby on Rails_ را پیدا خواهید کرد، اما هر سه ران‌تایم اصلی JavaScript (Node.js، Bun، Deno) و همچنین فریم‌ورک‌های محبوب PHP مثل Laravel و Symfony را هم خواهید یافت. اوه، و Go و Rust و Python و Java و Elixir (همراه با Phoenix) و .NET و OCaml و Zig و Clojure و Scala هم هستند. گزینش خیلی گسترده‌ای است!

اکثر این محیط‌ها توسط [Mise](https://mise.jdx.dev/) مدیریت می‌شوند. ابزاری است که به شما اجازه می‌دهد چند نسخه از یک زبان برنامه‌نویسی را روی یک ماشین نصب و اجرا کنید. مثل rbenv یا rvm برای Ruby یا virtualenv برای Python است، اما برای کلی محیط مختلف کار می‌کند.

برای نصب، بگوییم، Ruby، `mise use -g ruby` را اجرا می‌کنید که هم Ruby را نصب می‌کند و هم آن را به‌عنوان پیش‌فرض سراسری تنظیم می‌کند. یا، اگر پروژه‌تان یک فایل .ruby-version دارد، می‌توانید فقط `mise i` را در ریشه‌ی آن پروژه اجرا کنید.

## ابزارهای CLI از پیش نصب‌شده

`uv` و Node.js و `playwright-cli` (برای اینکه عامل‌ها با استفاده از Chrome نصب‌شده یک مرورگر را هدایت کنند) به‌صورت بسته نصب‌شده می‌آیند، و `omarchy update` آن‌ها را همراه با بقیه‌ی سیستم به‌روز نگه می‌دارد. [Hunk](https://github.com/modem-dev/hunk) و CLIهای GitHub و Basecamp و Cloudflare و HEY فقط یک انتخاب دورتر زیر _Install > CLI_ هستند، و [عامل‌های کدنویسی](17-ai.md) زیر _Install > AI > CLI_ قرار دارند.

mise فقط ران‌تایم‌هایی را مدیریت می‌کند که از _Install > Development_ راه‌اندازی می‌کنید؛ Omarchy به‌خودی‌خود چیزی از طریق آن نصب نمی‌کند. برای به‌روزرسانی آن‌ها همراه با بقیه‌ی Omarchy، `omarchy update` را اجرا کنید؛ نام مستعار `mup` فقط ابزارهای مدیریت‌شده با mise را به‌روزرسانی می‌کند. برای افزودن ابزار دیگری به پیکربندی خودتان، از `mise use -g <tool>` استفاده کنید.

## Docker

[Docker](https://www.docker.com/) تقریباً نیازی به معرفی ندارد. به شما اجازه می‌دهد کانتینرهای ایزوله اجرا کنید، و Omarchy هر آنچه را برای خوب اجرا کردنش لازم است نصب می‌کند، از جمله خود Docker و [Docker Compose](https://docs.docker.com/compose/).

به‌طور پیش‌فرض کاربر شما در گروه `docker` *نیست*. آن گروه عملاً root بدون رمز عبور است — هر چیزی در آن می‌تواند `docker run -v /:/host` را اجرا کند و ماشین را تصاحب کند — بنابراین یک اسکریپت یا وابستگی سرکش که به‌جای شما اجرا شود، در غیر این صورت فقط یک فرمان با root فاصله داشت. پس در خط فرمان Docker را با `sudo` اجرا می‌کنید (`sudo docker ps`، `sudo docker compose up`)، و ابزارهای گرافیکی که با دیمون صحبت می‌کنند — Windows VM — وقتی به آن نیاز داشته باشند درخواست مجوز می‌کنند. اگر راحتی یک راه‌اندازی بدون گروه را دوباره می‌خواهید و بده‌بستانش را درک می‌کنید، آن را از **Setup > Security > Sudoless Docker** فعال کنید (یا `omarchy-setup-security-sudoless-docker` را اجرا کنید)، که پس از یک هشدار شما را به گروه `docker` اضافه می‌کند؛ آن‌وقت `docker` ساده و نام مستعار `d` دوباره بدون `sudo` کار می‌کنند.

می‌توانید پایگاه‌داده‌های رایج برای توسعه‌ی محلی در Docker را با استفاده از _Install > Development > Docker DB_ در منوی Omarchy راه‌اندازی کنید.

## GitHub CLI

[GitHub CLI](https://cli.github.com/) همان `gh` است، برای کار با مخزن‌ها، issueها و pull requestها از ترمینال. وقتی انتخاب می‌کنید آنجا وارد GitHub شوید، _Setup > Git_ آن را نصب می‌کند، یا آن را جداگانه از _Install > CLI > GitHub_ نصب کنید. سپس `gh repo clone org/repo` یک مخزن را clone می‌کند؛ برای کاوش فرمان‌هایش `gh --help` را اجرا کنید.

[Lazygit](https://github.com/jesseduffield/lazygit) برای کار با خود Git از پیش نصب شده است.
