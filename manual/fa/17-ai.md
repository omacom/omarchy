# هوش مصنوعی

Omarchy لانچرهای ایجنت‌های کدنویسی زیر را بدون انتخاب یک پیش‌فرض برای شما شامل می‌شود. یک دستور را اجرا کنید تا CLI آن در اولین استفاده نصب شود، سپس وقتی از شما خواسته شد احراز هویت کنید. Hermes استثناست: در اولین استفاده چیزی برای آن نصب نمی‌شود، و انتخاب آن Hermes Desktop را نصب می‌کند، همان‌طور که _اپ‌های دسکتاپ_ در ادامه توضیح می‌دهد.

### نصب و به‌روزرسانی ایجنت‌ها

به‌جز Hermes، این ایجنت‌ها از نصب تنبل mise استفاده می‌کنند: اولین اجرا CLI را نصب می‌کند، و اجراهای بعدی از آن دوباره استفاده می‌کنند. mise همچنین حداکثر هر چهار ساعت یک بار، درست قبل از شروع یا در پس‌زمینه در پرامپت شل، یک ایجنت نصب‌شده را برای نسخه جدید بررسی می‌کند. اگر آن به‌روزرسانی شکست بخورد یا آفلاین باشید، نسخه نصب‌شده اجرا می‌شود. `omarchy update` ایجنت‌های نصب‌شده را همراه با بقیه Omarchy به‌روز می‌کند، و `mup` فقط ابزارهای مدیریت‌شده توسط mise را به‌روز می‌کند.

به‌روزرسان خود یک ایجنت، مثل `claude update`، `codex update`، یا یک دکمه به‌روزرسانی در یک اپ، نصب مدیریت‌شده توسط mise را به‌روز نمی‌کند. `codex update` شکست می‌خورد، و `claude update` می‌تواند موفقیت را گزارش کند در حالی که یک کپی جداگانه نصب می‌کند که mise آن را ردیابی نمی‌کند. اگر ترجیح می‌دهید از نصب‌کننده و به‌روزرسان بومی یک ایجنت استفاده کنید، آن را به `disable_tools` اضافه کنید؛ [ابزارهای CLI از پیش نصب‌شده](18-development-tools.md#preinstalled-cli-tools) را ببینید.

برای نصب همه ابزارهای تنبل پیکربندی‌شده قبل از اینکه به آنها نیاز پیدا کنید، `mise install --include-lazy` را اجرا کنید. این شامل سایر ابزارهای CLI پیش‌فرض Omarchy و همچنین ایجنت‌ها می‌شود. برای نصب یک ابزار تکی یا استفاده از نصب خودتان، [ابزارهای CLI از پیش نصب‌شده](18-development-tools.md#preinstalled-cli-tools) را ببینید.

`grok` از طریق پکیج first-party مربوط به `grok` در mise نصب می‌شود، به همان روشی که `claude` و `codex` نصب می‌شوند. `grok` را اجرا کنید، یا آن را زیر _Setup > Defaults > Agent_ انتخاب کنید. نصب‌کننده `curl | bash` در x.ai را رد کنید. آن مسیر یک کپی دوم در `~/.grok/bin` قرار می‌دهد، آن را در `PATH` پیش می‌اندازد، و رپر Omarchy را بازنویسی می‌کند.

`dsh` رابط کاربری مرورگر خود را روی `127.0.0.1:3080` باز می‌کند، با دایرکتوری اجرا به‌عنوان فضای کاری پیش‌فرض آن. رابط کاربری مرورگر آن هیچ پرامپت شروعی نمی‌گیرد، بنابراین `omarchy agent prompt` آن را با پرامپت روی کلیپ‌بورد شما برای چسباندن باز می‌کند. Omarchy آن را با پریست مجوز بدون نیاز به تأیید DeepSeek شروع می‌کند. DeepSeek Harness وقتی از API رسمی مدل آن استفاده می‌کنید، لاگ‌های نشست را به DeepSeek آپلود می‌کند؛ آن را در رابط کاربری مرورگر آن زیر _Settings > General > Upload Session Log_ خاموش کنید. بازخوردی که برای آن می‌فرستید نیز همراه با نشست آپلود می‌شود، مگر اینکه آن را با `DSH_TELEMETRY_MODE=DISABLED` شروع کنید.

### ایجنت پیش‌فرض

ایجنت پیش‌فرض خود را با `omarchy default agent <name>` یا زیر _Setup > Defaults > Agent_ در منوی Omarchy (`Super + Space`) انتخاب کنید. اگر ایجنت هنوز نصب نشده باشد، انتخاب آن ابتدا آن را نصب می‌کند. یک Omarchy تازه با یک اعلان یک‌بارمصرف از شما دعوت می‌کند این انتخاب را انجام دهید.

انتخاب Claude همچنین تلاش می‌کند افزونه مرورگر آن را برای Chromium، Chrome، Brave، Brave Origin، و Edge راه‌اندازی کند. راه‌اندازی افزونه برای همه کاربران اعمال می‌شود و ممکن است رمز عبور سیستم شما را بخواهد؛ لغو کردن یا نصب ناموفق افزونه همچنان Claude را انتخاب و اجرا می‌کند. مرورگر خود را ری‌استارت کنید، اگر از شما خواسته شد افزونه را فعال کنید، و برای تکمیل اتصال آن وارد Claude شوید. برای بررسی اتصال، `/chrome` را در Claude اجرا کنید. Firefox و Zen از این افزونه پشتیبانی نمی‌کنند. اگر Claude قبل از اضافه شدن این راه‌اندازی، پیش‌فرض شما بود، آن را دوباره انتخاب کنید تا افزونه نصب شود.

پس از انتخاب، `Super + Shift + Ctrl + A` ایجنت پیش‌فرض را در یک پنجره ترمینال اختصاصی اجرا می‌کند (یا اگر هنوز انتخاب نکرده‌اید، انتخاب‌گر را بالا می‌آورد). همچنین می‌توانید آن را مستقیماً وارد یک کار کنید با `omarchy agent prompt "Review this project"`. Freebuff و DeepSeek Harness هیچ پرامپت شروعی نمی‌گیرند، بنابراین در عوض با پرامپت روی کلیپ‌بورد شما برای چسباندن باز می‌شوند. ایجنت‌هایی که به این روش اجرا می‌شوند بدون مراقبت در حالت‌های مربوطه «توقف نکن و نپرس» خود اجرا می‌شوند، پس آماده باشید که واقعاً کارهایی انجام دهند! MiniMax Code چنین حالتی برای نشست‌های تعاملی خود ندارد، بنابراین مثل معمول برای مجوزها سؤال می‌کند. و از آنجا که ایجنت‌ها از به خاطر سپردن اعتماد برای دایرکتوری خانه شما خودداری می‌کنند، اجراها از `$HOME` در عوض در `~/Work` شروع می‌شوند.

میانبرهای ترمینال هم وجود دارد: `a` ایجنت پیش‌فرض را به‌صورت درون‌خطی در ترمینال فعلی اجرا می‌کند، در حالی که `c`، `cx`، و `cy`، OpenCode، Claude Code، و Codex را مستقیماً شروع می‌کنند (باز هم در حالت‌های تأیید خودکار خود). تغییرات تم نیز با ایجنت‌ها همگام می‌شود: Claude Code، Pi، OpenCode، و Hermes (پس از اینکه Omarchy آن را نصب کرد) همه وقتی تم Omarchy را عوض می‌کنید همراهی می‌کنند.

### پنل ایجنت‌ها

نوار بالا یک آیکون ایجنت‌ها دارد. قبل از اینکه یک ایجنت راه‌اندازی کرده باشید، پنل آن شما را در ورود به Claude، Codex، یا Grok راهنمایی می‌کند، و اولین مورد به ایجنت پیش‌فرض شما تبدیل می‌شود. پس از آن، پنل هر اشتراک را در یک صفحه قرار می‌دهد: هر ایجنت و حساب با طرح آن، یک متر برای هر یک از محدودیت‌های نشست 5 ساعته و هفتگی آن همراه با زمان تا ریست شدن (برای درصد دقیق هاور کنید)، یا موجودی پیش‌پرداخت باقی‌مانده، زیر خطی که در آنچه در همه آنها استفاده کرده‌اید می‌چرخد، مثل توکن‌های این هفته و پراستفاده‌ترین مدل شما. زیر _Make something_ پرامپت‌های شروعی برای یک تم، پلاگین، یا اپ جدید ارائه می‌دهد که کار را به ایجنت پیش‌فرض شما می‌سپارد. اپ‌ها به همان روشی ساخته می‌شوند که Hype، Monologue، و Omacut خود Omarchy ساخته شده‌اند، با C++ و Qt Quick، با پیروی از اسکیل ایجنت omarchy-app، و کامپایلر و قطعات Qt مورد نیاز آنها نصب‌شده می‌آیند. Claude Code، Codex، Grok، Kimi، Cursor و سهمیه Grok Bot آن، GitHub Copilot، Muse، Antigravity، Kimchi، و Devin از همان ابتدا با محدودیت‌هایشان پوشش داده می‌شوند، و Hermes، Mistral Vibe، و Qwen Code نشست‌ها و توکن‌های خود را پس از اینکه از آنها استفاده کردید نشان می‌دهند. طرح‌ها و کلیدهای ارائه‌دهنده‌ای که از طریق pi، omp، یا opencode استفاده می‌کنید نیز ظاهر می‌شوند: OpenCode Zen و Go، طرح Z.ai GLM Coding Plan، Ollama Cloud، طرح MiniMax Token Plan، و Synthetic با محدودیت‌هایشان؛ Fireworks، OpenRouter، و DeepSeek با موجودی‌های پیش‌پرداخت‌شان؛ و مدل‌هایی که روی سخت‌افزار خودتان اجرا می‌کنید زیر Local models. هر ایجنت یک بار شمرده می‌شود، زیر هر کسی که صورتحساب آن را صادر می‌کند، صرف‌نظر از اینکه از چند هارنس آن را هدایت می‌کنید.

روی آیکون نوار برای پنل کلیک چپ کنید، برای اجرای ایجنت پیش‌فرض خود کلیک راست کنید. رکوردهای مصرف پشت آن هر 15 دقیقه توسط `omarchy agent usage-update` بازتولید می‌شوند، و پنل حتی می‌تواند مصرف از ماشین‌های دیگر شما را از طریق یک پوشه همگام‌شده ادغام کند. برای تنظیمات کامل، README زیر `$OMARCHY_PATH/shell/plugins/agents/` را ببینید.

### چند اشتراک

اگر برای بیش از یک طرح Claude، Codex، یا Grok پول می‌دهید — مثلاً یک Max شخصی و یک کاری — Omarchy می‌تواند همه آنها را وارد نگه دارد و بین آنها جابه‌جا شود. یک اشتراک را با + در پنل ایجنت‌ها اضافه کنید، که همان‌جا شما را در انجام آن راهنمایی می‌کند، یا با `omarchy agent account add claude Work` (یا `codex`، یا `grok`). اگر CLI گم شده باشد آن را نصب می‌کند. اولین حساب برای یک ارائه‌دهنده از طریق مرورگر عادی شما وارد می‌شود، دقیقاً همان‌جایی که CLI همیشه نگاه می‌کند. هر حساب بعد از آن از طریق یک پنجره خصوصی وارد می‌شود، تا حسابی که مرورگر شما از قبل وارد آن شده به اشتباه انتخاب نشود؛ در آنجا به‌عنوان حسابی که اضافه می‌کنید وارد شوید، و ابتدا هر پنجره خصوصی که از قبل باز داشتید ببندید. هرگز برای این کار از CLI خارج نشوید: خروج، ورود ذخیره‌شده را باطل می‌کند، و آن حساب باید دوباره اضافه شود.

برای کپی کردن ورودهای اشتراک خود به یک ماشین Omarchy دیگر از طریق SSH، `omarchy agent account copy user@laptop` را اجرا کنید. فرستنده وقتی مقصد یکی نصب‌شده ندارد، یک گیرنده موقت تأمین می‌کند، بنابراین ماشین‌های قدیمی‌تر Omarchy می‌توانند بدون به‌روزرسانی حساب‌ها را دریافت کنند. گیرنده‌های نصب‌شده اولویت دارند. این همه اشتراک‌های Claude، Codex، و Grok را کپی می‌کند؛ نام ارائه‌دهنده‌ها را اضافه کنید تا آنها را انتخاب کنید، مثل `omarchy agent account copy laptop claude`. نام حساب‌ها و IDهای دستور با منبع مطابقت دارند، از جمله حساب‌هایی که از قبل در مقصد حضور دارند. حساب‌های نامرتبط مقصد اگر نام‌هایشان تداخل پیدا کند یک پسوند عددی دریافت می‌کنند، و تنظیمات، اسکیل‌ها، پلاگین‌ها، و تاریخچه مکالمات محلی برای هر ماشین باقی می‌مانند.

اعتبارنامه‌های موجود مقصد نگه داشته می‌شوند. یک حساب منبع که از قبل در آنجا وارد شده است، نامش بدون جایگزین کردن اعتبارنامه‌هایش همگام می‌شود؛ حساب‌های دیگر در کنار آن اضافه می‌شوند. برای جایگزین کردن اعتبارنامه‌های ذخیره‌شده برای حساب‌های منطبق، پس از بستن نشست‌های آن حساب در مقصد، از `omarchy agent account copy --replace laptop claude` استفاده کنید. یک مقصد تازه همچنین حساب فعال و ترجیحات سوئیچ کردن منبع را دریافت می‌کند؛ یک مقصد تثبیت‌شده مال خود را نگه می‌دارد.

اعتبارنامه‌ها از طریق SSH سفر می‌کنند و در فایل‌های خصوصی در مقصد ذخیره می‌شوند، بنابراین فقط به ماشین‌هایی که به آنها اعتماد دارید کپی کنید. این یک کپی یک‌بارمصرف است، نه همگام‌سازی مداوم. توکن‌های رفرش Codex می‌توانند توسط یک ماشین دیگر چرخانده شوند، و یک ورود کپی‌شده را نیازمند تمدید باقی بگذارند؛ ورودهای جداگانه مطمئن‌ترین انتخاب برای استفاده همزمان روی چند ماشین باقی می‌مانند. [راهنمای احراز هویت حساب Codex](https://developers.openai.com/codex/auth/ci-cd-auth) را ببینید.

یک حساب به ازای هر ارائه‌دهنده فعال است، و هر نشست جدید به‌عنوان آن شروع می‌شود: `cx`، `cy`، یک `claude`، `codex`، یا `grok` ساده، هر چیزی که از طریق `omarchy agent` اجرا شود، و اسکریپت‌ها یا ویرایشگرهایی که CLI را روی `PATH` پیدا می‌کنند. با `omarchy agent account use work` سوئیچ کنید (و با `omarchy agent account use main` برگردید)، یا در پنل با فشردن شماره یک حساب و سپس `Enter` (یا کلیک روی دکمه Use آن). نشست‌هایی که از قبل در حال اجرا هستند روی حسابی که با آن شروع شدند باقی می‌مانند. تاریخچه مکالمات، تنظیمات، اسکیل‌ها، و پلاگین‌ها بین حساب‌ها به اشتراک گذاشته می‌شوند، بنابراین `claude --continue` در همان پوشه از جایی که در حساب جدید رها کردید ادامه می‌دهد.

با بیش از یک حساب، پنل محدودیت‌های هر حساب را کنار هم نشان می‌دهد، با حساب فعال علامت‌گذاری شده. به‌طور پیش‌فرض Omarchy وقتی حساب فعال از 95% یک محدودیت عبور می‌کند به شما اطلاع می‌دهد، و کلیک روی اعلان به حسابی با بیشترین فضای خالی سوئیچ می‌کند. روی خط یک حساب در پنل هاور کنید و روی Autoswitch که کنار Use ظاهر می‌شود کلیک کنید (یا `m` را فشار دهید)، یا `omarchy agent account mode auto` را اجرا کنید، تا به‌جای آن خودش سوئیچ کند؛ وقتی روشن است، Autoswitch جای Use را می‌گیرد، و کلیک دوباره روی آن به اطلاع‌رسانی برمی‌گردد. یک عدد اضافه کنید تا آستانه را تغییر دهید، مثل `omarchy agent account mode auto 90`. اگر هر حسابی بالای آستانه باشد، یک بار از آن مطلع خواهید شد، همراه با اینکه کدام حساب اول آزاد می‌شود. وقتی یک حساب فعال در فاصله 15 امتیاز از آستانه‌اش باشد (80% در حالت پیش‌فرض)، محدودیت‌های آن هر سه دقیقه به‌جای هر 15 دقیقه بررسی می‌شوند.

`omarchy agent account list` هر حساب و آخرین محدودیت‌های آن را نشان می‌دهد، `omarchy agent account remove work` یکی را فراموش می‌کند، و `omarchy agent account rename primary Hey` نام یکی را تغییر می‌دهد (یا روی نام یک حساب در پنل کلیک کنید). این دستورات روی حساب‌های ایجنت پیش‌فرض شما کار می‌کنند؛ برای رسیدن به ارائه‌دهنده دیگر، ابتدا نام آن را بیاورید، مثل `omarchy agent account use codex side`. ورودی که از قبل در `~/.claude` یا `~/.codex` داشتید حساب _Main_ است و همان‌جا که هست باقی می‌ماند. حسابی که بیش از حدود هشت ساعت بلااستفاده مانده باشد ممکن است _Sign-in required_ نشان دهد؛ روی آن کلیک کنید تا آن حساب را دوباره دقیقاً در پنل وارد کنید، یا یک نشست در آن شروع کنید، که ورود را به‌خودی‌خود تازه می‌کند. سرورهای MCP که وقتی یک حساب اضافه شد داشتید همراه آن می‌آیند، اما آنهایی که بعداً با `claude mcp add` اضافه می‌کنید فقط به حسابی می‌رسند که آنها را در آن اضافه کردید. Claude Desktop و ابزارهایی که با یک مسیر مطلق به یک باینری CLI پیکربندی شده‌اند از سوئیچ پیروی نمی‌کنند. یک `CLAUDE_CONFIG_DIR`، `CODEX_HOME`، یا `GROK_HOME` صریح بر حساب انتخاب‌شده اولویت دارد.

### تشخیص کرش

Omarchy، systemd-coredump را برای کرش‌های پروسس زیر نظر دارد. وقتی چیزی سگفالت می‌کند، یک اعلان "Process crashed" دریافت خواهید کرد — روی آن کلیک کنید، و کرش همراه با اسکیل diagnose-crash مربوط به Omarchy به ایجنت پیش‌فرض شما سپرده می‌شود، که ایجنت را از طریق احراز حقایق از روی کور دامپ و تصمیم‌گیری درباره اینکه آیا کرش ارزش گزارش به بالادست را دارد یا نه، راهنمایی می‌کند. همچنین می‌توانید آن را به‌صورت دستی در برابر هر PID از `coredumpctl list` با `omarchy agent crash <pid>` اجرا کنید.

این زیرنظرگیری به‌طور پیش‌فرض روشن است. آن را زیر _Trigger > Toggle > Crash Capture_ خاموش کنید (یا با `omarchy toggle crash-capture`) و اعلان‌ها متوقف می‌شوند؛ `omarchy agent crash <pid>` همچنان به‌صورت دستی کار می‌کند.

کرش‌ها همچنین می‌توانند یک برنامه در هر زمان ساکت شوند، که همان چیزی است که تشخیص در پایان به شما پیشنهاد می‌دهد. `omarchy crash mute hyprland` اعلان‌ها را فقط برای آن برنامه متوقف می‌کند، `omarchy crash mute hyprland off` آنها را برمی‌گرداند، و `omarchy crash mute` به‌تنهایی فهرست می‌کند چه چیزی را بی‌صدا کرده‌اید. مسیر باینری را به همان راحتی نام آن می‌پذیرد، بنابراین `omarchy crash mute /usr/bin/hyprland` همان کار را می‌کند. نامی با یک فاصله در آن را کوتیشن بگذارید، مثل `omarchy crash mute 'Some App'`. هر چیز دیگری همچنان اطلاع می‌دهد، و برنامه بی‌صدا شده همچنان کرش می‌کند — این یادآور را پنهان می‌کند، چیزی را درست نمی‌کند.

### اپ‌های دسکتاپ

منوی _Install > AI_ همچنین چند اپ گرافیکی هوش مصنوعی دارد: اپ دسکتاپ ChatGPT، اپ دسکتاپ Claude (بتای لینوکس Anthropic، با تب‌های Chat، Cowork، و Claude Code)، Grok Bot برای چت با مدل‌های xAI، Hermes Desktop، OpenClaw، اپ دسکتاپ Perplexity، و T3 Code. Grok Bot اپ چت دسکتاپ است. ایجنت کدنویسی دستور `grok` است.

Hermes Desktop همان است که باید درباره‌اش بدانید، چون یک ماشین یک Hermes دارد، و آن متعلق به اپ است: Hermes فقط همیشه از طریق اپ نصب می‌شود، و دستور `hermes` که ایجنت پیش‌فرض اجرا می‌کند متعلق به اپ است. انتخاب Hermes به‌عنوان ایجنت پیش‌فرض همان چیزی را نصب می‌کند که ورودی _Install > AI_ نصب می‌کند: پکیج، و یک رانتایم Hermes زیر `~/.hermes` که توسط نصب‌کننده خود Hermes راه‌اندازی شده، که بار اول چند دقیقه طول می‌کشد. آن رانتایم همان یک Hermes است که دستور ترمینال `hermes`، ایجنت پیش‌فرض و اپ همه از آن استفاده می‌کنند، و خودش را با `hermes update` به‌روز می‌کند نه اینکه منتظر یک ریلیز Omarchy بماند. نصب آن همچنین تم Omarchy را به‌عنوان یک پوسته به نام `omarchy` به Hermes می‌دهد، که هر سطح Hermes وقتی تم‌ها را عوض می‌کنید از آن پیروی می‌کند؛ اگر ترجیح می‌دهید این‌طور نباشد، یکی دیگر را زیر تنظیمات Appearance مربوط به Hermes یا با `/skin` انتخاب کنید، و Omarchy آن انتخاب را به حال خود می‌گذارد. حذف اپ زیر _Remove > AI_ ابتدا Hermes را می‌بندد، گیت‌وی شامل، آن رانتایم را با خود می‌برد، و چت‌ها، خاطرات، و اسکیل‌هایی که Hermes برای خودش نوشته نگه می‌دارد مگر اینکه خلاف آن را بگویید: می‌پرسد، با پیش‌فرض نه، که آیا آن داده و تنظیمات اتصال شما نیز باید بروند یا نه.

تجربه دسکتاپ OpenClaw رابط Control UI آن است، که به‌عنوان یک وب‌اپ پشتیبانی‌شده توسط گیت‌وی محلی خودش باز می‌شود. OpenClaw در `~/.openclaw` زندگی می‌کند و خودش را به‌روز می‌کند: از دکمه "Update Gateway" در Control UI استفاده کنید یا `openclaw update` را اجرا کنید، و گیت‌وی روی نسخه جدید ری‌استارت می‌شود. Omarchy فقط ریلیزی را انتخاب می‌کند که یک نصب تازه از آن شروع شود. حذف OpenClaw زیر _Remove > AI_ سرویس گیت‌وی و اپ را با خود می‌برد و سپس می‌پرسد آیا `~/.openclaw` نیز باید برود یا نه، چون آن چت‌ها و اعتبارنامه‌های شما را در کنار خود OpenClaw و رانتایم‌های پلاگینی که دانلود می‌کند نگه می‌دارد؛ پیش‌فرض آن را نگه می‌دارد، و نصب دوباره OpenClaw آن را دوباره برمی‌دارد.

T3 Code از ریلیز رسمی AppImage خود در `~/.local/share/t3code` اجرا می‌شود نه از یک پکیج، بنابراین خودش را به‌روز می‌کند. نصب آن می‌پرسد آیا روی کانال Stable یا Nightly شروع شود؛ بعداً در تنظیمات T3 Code عوض کنید. تردها و تنظیمات شما در `~/.t3` زندگی می‌کنند، و حذف T3 Code زیر _Remove > AI_ آنها را با خود می‌برد.

### مدل‌های محلی

یک مدل باز را روی ماشین خودتان برای ایجنت‌های کدنویسی‌تان اجرا کنید. پرامپت‌ها و کد شما روی ماشین می‌مانند؛ هیچ چیزی که به مدل فرستاده شود آن را ترک نمی‌کند. با این شروع کنید:

```bash
omarchy agent local use best
```

یا، در پنل ایجنت‌ها در نوار بالا، + و سپس Local AI را انتخاب کنید، که وقتی یک مدل با این ماشین جور است ظاهر می‌شود. بار اول، این Podman را نصب می‌کند، که مدل‌ها را اجرا می‌کند، و روی یک ماشین NVIDIA تولکیت کانتینر NVIDIA را، که GPU را به آنها می‌دهد. سپس Omarchy مدل توصیه‌شده برای این ماشین را انتخاب می‌کند، آن را دانلود می‌کند، و شروع می‌کند. انتظار دانلودی ده‌ها GB داشته باشید و اینکه بیشتر حافظه ماشین در حالی که مدل اجرا می‌شود در حال استفاده باشد: Flash Next با کانتکست کامل 256K خود حدود 100 GiB استفاده می‌کند. اگر مدل‌های دیگر حافظه مورد نیاز آن را نگه داشته باشند، متوقف راه‌اندازی می‌شود، آماده شروع پس از اینکه یکی را متوقف کردید. مدل هنگام خروج متوقف می‌شود؛ وقتی برای چیز دیگری به حافظه نیاز دارید خودتان آن را متوقف کنید.

`omarchy agent local list` گزینه‌ها را نشان می‌دهد و توضیح می‌دهد چرا بعضی جور نیستند. برای راه‌اندازی یکی دیگر، `omarchy agent local use <recipe>` را اجرا کنید. امروز، `qwen3.8-flash-next-gufo` و `qwen3.8-27b-gufo` برای ماشین‌های 128 GB Strix Halo در دسترس هستند؛ مدل 27B حدود 40 GiB می‌گیرد، بنابراین برای کارهای دیگر جا می‌گذارد. دستورالعمل‌ها و توصیه‌های جدید با `omarchy update`، از طریق پکیج، می‌رسند.

هر مدلی که راه‌اندازی می‌کنید خط خودش را در پنل ایجنت‌ها، کنار اشتراک‌های شما، می‌گیرد: پخش برای شروع آن، مکث برای متوقف کردن آن و آزاد کردن حافظه‌اش، و دکمه ترمینال برای باز کردن ایجنت شما روی آن. چندتا می‌توانند همزمان وقتی با هم در حافظه جا می‌شوند اجرا شوند؛ اگر یکی جا نشود، Omarchy می‌گوید کدام مدل در حال اجرا را متوقف کنید. خطوط را بکشید تا دوباره مرتب شوند، و Delete را روی یک خط انتخاب‌شده فشار دهید تا یک مدل و دانلود آن حذف شود.

از خط فرمان، `omarchy agent local start <recipe>` و `omarchy agent local stop <recipe>` همین کار را می‌کنند، `omarchy agent local status` هر مدل را نشان می‌دهد، و `omarchy agent --local` ایجنت پیش‌فرض شما را روی آخرین مدلی که شروع کردید باز می‌کند (pi اگر ایجنت پیش‌فرض شما نمی‌تواند از یک مدل محلی استفاده کند). هر کلاینت سازگار با OpenAI نیز می‌تواند متصل شود: `status` آدرس هر مدل را نشان می‌دهد (اولی `http://127.0.0.1:11435/v1` است)، نام دستورالعمل نام مدل است، و کلید در `~/.config/omarchy/agent-local/key` است.

`omarchy agent local remove <recipe>` یک مدل و دانلودهایی که هیچ مدل دیگری استفاده نمی‌کند را حذف می‌کند.

رانتایم‌های شخص ثالث با ناشرشان برچسب‌گذاری می‌شوند. Omarchy هر مدل را بدون دسترسی به شبکه اجرا می‌کند.

### LLMهای محلی

Omarchy دو روش برای اجرای مدل‌های LLM محلی توصیه می‌کند: LM Studio و Ollama. LM Studio یک رابط کاربری گرافیکی برای پیدا کردن مدل‌های با وزن باز، نصب آنها، و اجرای آنها فراهم می‌کند. راهی عالی برای شروع آسان است. Ollama یک CLI برای انجام مشابه آن ارائه می‌دهد. اما اگر در مدل‌های محلی تازه‌کار هستید، من با LM Studio شروع می‌کردم. می‌توانید هر کدام را زیر _Install > AI_ در منوی Omarchy نصب کنید.

### اسکیل Omarchy

اسکیل‌های ایجنت به هوش مصنوعی کمک می‌کنند ابزارهای خاص را به روشی خاص استفاده کند، و Omarchy با یک اسکیل پیش‌فرض برای تنظیم سیستم عرضه می‌شود. مثل دستکاری کانفیگ Hyprland شما، تنظیم نوار، یا حتی ساختن یک تم جدید از صفر. آن به‌صورت سیم‌لینک در دایرکتوری‌های اسکیل برای Claude Code (`~/.claude/skills`)، Codex (`~/.codex/skills`)، Pi (`~/.pi/agent/skills`)، Antigravity (`~/.gemini/config/skills`)، Hermes (`~/.hermes/skills` و هر `~/.hermes/profiles/*/skills`)، و مکان عمومی `~/.agents/skills` قرار گرفته، بنابراین بیشتر هارنس‌ها آن را به‌طور خودکار برمی‌دارند.

اما باید این اسکیل را آزمایشی در نظر بگیرید. مدل‌های مختلف آن را به اثرات متفاوتی استفاده خواهند کرد. بهتر است اول در حالت برنامه‌ریزی اجرا کنید، تا ایده‌ای از آنچه ایجنت می‌خواهد تغییر دهد داشته باشید. و سپس آماده باشید تغییرات را برگردانید یا حتی `omarchy reinstall configs` را فراخوانی کنید، اگر ایجنت همه چیز را به هم ریخت.
