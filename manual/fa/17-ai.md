# هوش مصنوعی

Omarchy لانچرهای مربوط به عامل‌های کدنویسی زیر را بدون انتخاب یک گزینه پیش‌فرض به جای شما در بر می‌گیرد. یک دستور را اجرا کنید تا CLI آن در اولین استفاده نصب شود، سپس وقتی از شما خواسته شد احراز هویت کنید. Hermes استثناست: در اولین استفاده هیچ چیزی برای آن نصب نمی‌شود، و انتخاب آن Hermes Desktop را نصب می‌کند، همان‌طور که _Desktop apps_ در ادامه توضیح می‌دهد.

### نصب و به‌روزرسانی عامل‌ها

به‌جز Hermes، این عامل‌ها از نصب تنبل mise استفاده می‌کنند: اولین اجرا CLI را نصب می‌کند، و اجراهای بعدی از همان استفاده می‌کنند. mise همچنین حداکثر هر چهار ساعت یک بار، درست قبل از شروع یک عامل نصب‌شده یا در پس‌زمینه هنگام نمایش پرامپت شل، نسخه جدید آن را بررسی می‌کند. اگر آن به‌روزرسانی ناموفق باشد یا آفلاین باشید، نسخه نصب‌شده اجرا می‌شود. `omarchy update` عامل‌های نصب‌شده را همراه با بقیه Omarchy به‌روز می‌کند، و `mup` فقط ابزارهای مدیریت‌شده با mise را به‌روز می‌کند.

به‌روزرسان خود یک عامل، مانند `claude update`، `codex update` یا دکمه به‌روزرسانی در یک برنامه، نسخه نصب‌شده مدیریت‌شده با mise را به‌روز نمی‌کند. `codex update` شکست می‌خورد، و `claude update` می‌تواند موفقیت را گزارش کند در حالی که یک نسخه جداگانه نصب کرده است که mise آن را ردیابی نمی‌کند. اگر ترجیح می‌دهید از نصب‌کننده و به‌روزرسان بومی یک عامل استفاده کنید، آن را به `disable_tools` اضافه کنید؛ به [ابزارهای CLI از پیش نصب‌شده](18-development-tools.md#preinstalled-cli-tools) مراجعه کنید.

برای نصب همه ابزارهای تنبل پیکربندی‌شده قبل از آنکه به آن‌ها نیاز پیدا کنید، `mise install --include-lazy` را اجرا کنید. این شامل دیگر ابزارهای CLI پیش‌فرض Omarchy و همچنین عامل‌ها می‌شود. برای نصب یک ابزار منفرد یا استفاده از نصب خودتان، به [ابزارهای CLI از پیش نصب‌شده](18-development-tools.md#preinstalled-cli-tools) مراجعه کنید.

`grok` از طریق بسته first-party مربوط به `grok` در mise نصب می‌شود، به همان شیوه `claude` و `codex`. `grok` را اجرا کنید، یا آن را زیر _Agent > Harness_ انتخاب کنید. نصب‌کننده `curl | bash` در x.ai را کنار بگذارید. آن مسیر یک نسخه دوم در `~/.grok/bin` قرار می‌دهد، آن را در ابتدای `PATH` می‌گذارد، و wrapper مربوط به Omarchy را بازنویسی می‌کند.

`dsh` رابط کاربری مرورگر خود را روی `127.0.0.1:3080` باز می‌کند، و دایرکتوری اجرا به‌عنوان فضای کاری پیش‌فرض آن است. رابط کاربری مرورگر آن هیچ پرامپت شروعی نمی‌گیرد، بنابراین `omarchy agent prompt` آن را با پرامپت موجود روی کلیپ‌بوردتان برای paste کردن باز می‌کند. Omarchy آن را با preset دسترسی no-approval مربوط به DeepSeek راه‌اندازی می‌کند. DeepSeek Harness هنگام استفاده از API رسمی مدل آن، لاگ‌های نشست را برای DeepSeek آپلود می‌کند؛ آن را زیر _Settings > General > Upload Session Log_ در رابط کاربری مرورگر آن خاموش کنید. بازخوردی که برای آن ارسال می‌کنید نیز همراه با نشست آپلود می‌شود، مگر آنکه آن را با `DSH_TELEMETRY_MODE=DISABLED` راه‌اندازی کنید.

### عامل پیش‌فرض

عامل پیش‌فرض خود را با `omarchy default agent <name>` یا زیر _Agent > Harness_ در منوی Omarchy (`Super + Space`) انتخاب کنید. اگر عامل هنوز نصب نشده باشد، انتخاب آن ابتدا آن را نصب می‌کند. یک Omarchy تازه با یک اعلان یک‌باره از شما دعوت می‌کند این انتخاب را انجام دهید.

انتخاب Claude همچنین تلاش می‌کند افزونه مرورگر آن را برای Chromium، Chrome، Brave، Brave Origin و Edge راه‌اندازی کند. راه‌اندازی افزونه برای همه کاربران اعمال می‌شود و ممکن است رمز عبور سیستم شما را بخواهد؛ لغو یا ناموفق بودن نصب افزونه همچنان Claude را انتخاب و اجرا می‌کند. مرورگر خود را راه‌اندازی مجدد کنید، اگر از شما خواسته شد افزونه را فعال کنید، و برای تکمیل اتصال آن وارد Claude شوید. برای بررسی اتصال، `/chrome` را در Claude اجرا کنید. Firefox و Zen از این افزونه پشتیبانی نمی‌کنند. اگر Claude پیش از افزوده شدن این راه‌اندازی از قبل پیش‌فرض شما بود، آن را دوباره انتخاب کنید تا افزونه نصب شود.

پس از انتخاب، `Super + Shift + Ctrl + A` عامل پیش‌فرض را در یک پنجره ترمینال اختصاصی اجرا می‌کند (یا اگر هنوز انتخابی نکرده‌اید picker را نشان می‌دهد). همچنین می‌توانید آن را مستقیماً وارد یک کار کنید با `omarchy agent prompt "Review this project"`. Freebuff و DeepSeek Harness هیچ پرامپت شروعی نمی‌گیرند، بنابراین به جای آن با پرامپت موجود روی کلیپ‌بوردتان برای paste کردن باز می‌شوند. عامل‌هایی که به این شیوه اجرا می‌شوند بدون نیاز به دخالت شما در حالت‌های مربوطه خودشان که برای پرسیدن متوقف نمی‌شوند اجرا می‌شوند، پس آماده باشید که واقعاً کارهایی انجام دهند! MiniMax Code برای نشست‌های تعاملی خود چنین حالتی ندارد، بنابراین طبق معمول برای دسترسی‌ها اجازه می‌پرسد. و از آنجا که عامل‌ها از به خاطر سپردن اعتماد برای دایرکتوری home شما خودداری می‌کنند، اجراها از `$HOME` در عوض در `~/Work` شروع می‌شوند.

میانبرهای ترمینال هم وجود دارند: `a` عامل پیش‌فرض را به‌صورت inline در ترمینال فعلی اجرا می‌کند، در حالی که `c`، `cx` و `cy` به‌ترتیب OpenCode، Claude Code و Codex را مستقیماً شروع می‌کنند (باز هم در حالت‌های auto-approving خودشان). تغییر تم‌ها نیز با عامل‌ها همگام می‌شود: Claude Code، Pi، OpenCode و Hermes (پس از آنکه Omarchy آن را نصب کرد) همگی هنگام تغییر تم Omarchy همراهی می‌کنند.

### دستورالعمل‌های عامل شما

قوانین شخصی برای هر عامل در `~/.agents/AGENTS.md` قرار می‌گیرد، در کنار مهارت‌های مشترک در `~/.agents/skills`. آن را زیر _Agent > Instructions_ باز کنید، که همچنین آن را به هر harness که فایل سراسری خودش را نگه می‌دارد پیوند می‌دهد: `~/.claude/CLAUDE.md`، `~/.codex/AGENTS.md`، `~/.pi/agent/AGENTS.md`، `~/.config/opencode/AGENTS.md`، `~/.copilot/copilot-instructions.md` مربوط به Copilot، و مانند این‌ها. Crush و Amp پیوند `~/.config/AGENTS.md` را می‌خوانند، در حالی که omp، Kimi و DeepSeek Harness مستقیماً `~/.agents/AGENTS.md` را می‌خوانند. انتخاب یک عامل پیش‌فرض آن را نیز پیوند می‌دهد. یک فایل دستورالعملی که از قبل داشته‌اید، اگر هنوز فایل مشترکی وجود نداشته باشد، به فایل مشترک تبدیل می‌شود؛ در غیر این صورت در کنار پیوند به‌عنوان `.bak` نگه داشته می‌شود. پس از نصب یک عامل دیگر، `omarchy agent instructions` را برای پیوند دادن دوباره اجرا کنید.

### پنل عامل‌ها

نوار بالایی یک آیکون عامل‌ها دارد. قبل از آنکه یک عامل راه‌اندازی کرده باشید، پنل آن شما را در ورود به Claude، Codex یا Grok راهنمایی می‌کند، و اولین مورد به عامل پیش‌فرض شما تبدیل می‌شود. پس از آن، پنل همه اشتراک‌ها را در یک صفحه قرار می‌دهد: هر عامل و حساب با plan آن، یک سنجشگر برای هر یک از محدودیت‌های نشست 5 ساعته و هفتگی آن همراه با زمان باقی‌مانده تا reset شدن آن (برای درصد دقیق نگه دارید)، یا موجودی پیش‌پرداخت باقی‌مانده، زیر خطی که در میان آنچه در همه آن‌ها استفاده کرده‌اید می‌چرخد، مانند توکن‌های این هفته و پرکاربردترین مدل شما. زیر _Make something_ پرامپت‌های شروعی برای یک تم، افزونه یا برنامه جدید ارائه می‌کند که کار را به عامل پیش‌فرض شما می‌سپارند. برنامه‌ها به شیوه ساخته شدن Hype، Monologue و Omacut خود Omarchy ساخته می‌شوند، در C++ و Qt Quick، با پیروی از مهارت عامل omarchy-app، و کامپایلر و قطعات Qt مورد نیاز آن‌ها نصب‌شده ارائه می‌شوند. Claude Code، Codex، Grok، Kimi، Cursor و سهمیه Grok Bot آن، GitHub Copilot، Muse، Antigravity، Kimchi و Devin از همان ابتدا با محدودیت‌هایشان پوشش داده می‌شوند، و Hermes، Mistral Vibe و Qwen Code پس از استفاده شما نشست‌ها و توکن‌هایشان را نشان می‌دهند. planها و کلیدهای ارائه‌دهندگانی که از طریق pi، omp یا opencode استفاده می‌کنید نیز ظاهر می‌شوند: OpenCode Zen و Go، Z.ai GLM Coding Plan، Ollama Cloud، MiniMax Token Plan و Synthetic با محدودیت‌هایشان؛ Fireworks، OpenRouter و DeepSeek با موجودی‌های پیش‌پرداختشان؛ و مدل‌هایی که روی سخت‌افزار خودتان اجرا می‌کنید زیر Local models. هر عامل یک بار شمرده می‌شود، زیر هر کسی که صورت‌حساب آن را صادر می‌کند، صرف‌نظر از اینکه آن را از طریق چند harness هدایت می‌کنید.

برای پنل روی آیکون نوار چپ‌کلیک کنید، برای اجرای عامل پیش‌فرضتان راست‌کلیک کنید. سوابق مصرف پشت آن هر 15 دقیقه توسط `omarchy agent usage-update` بازتولید می‌شوند، و پنل حتی می‌تواند مصرف ماشین‌های دیگر شما را از طریق یک پوشه همگام‌شده ادغام کند. برای تنظیمات کامل، README زیر `$OMARCHY_PATH/shell/plugins/agents/` را ببینید.

### چند اشتراک

اگر برای بیش از یک plan مربوط به Claude، Codex یا Grok پرداخت می‌کنید — مثلاً یک Max شخصی و یک کاری — Omarchy می‌تواند همه آن‌ها را وارد نگه دارد و بین آن‌ها جابه‌جا شود. یک اشتراک را با + در پنل عامل‌ها اضافه کنید، که همان‌جا شما را در این فرایند راهنمایی می‌کند، یا با `omarchy agent account add claude Work` (یا `codex`، یا `grok`). اگر CLI وجود نداشته باشد آن را نصب می‌کند. اولین حساب برای یک ارائه‌دهنده از طریق مرورگر عادی شما وارد می‌شود، درست همان‌جایی که CLI همیشه به آن نگاه می‌کند. هر حساب بعد از آن از طریق یک پنجره خصوصی وارد می‌شود، تا حسابی که مرورگر شما از قبل وارد آن شده است به اشتباه انتخاب نشود؛ در آنجا به‌عنوان حسابی که اضافه می‌کنید وارد شوید، و ابتدا هر پنجره خصوصی‌ای را که از قبل باز داشته‌اید ببندید. هرگز برای این کار از CLI خارج نشوید: خروج ورود ذخیره‌شده را باطل می‌کند، و آن حساب باید دوباره اضافه شود.

برای کپی کردن ورودهای اشتراکتان به یک ماشین Omarchy دیگر از طریق SSH، `omarchy agent account copy user@laptop` را اجرا کنید. وقتی مقصد receiver نصب‌شده‌ای ندارد، فرستنده یک receiver موقت تأمین می‌کند، بنابراین ماشین‌های قدیمی‌تر Omarchy می‌توانند بدون به‌روزرسانی حساب‌ها را دریافت کنند. receiverهای نصب‌شده اولویت دارند. این کار همه اشتراک‌های Claude، Codex و Grok را کپی می‌کند؛ نام ارائه‌دهندگان را برای انتخاب آن‌ها اضافه کنید، مانند `omarchy agent account copy laptop claude`. نام حساب‌ها و شناسه‌های دستور با منبع مطابقت دارند، از جمله حساب‌هایی که از قبل در مقصد وجود دارند. حساب‌های نامرتبط مقصد در صورت تعارض نام‌هایشان یک پسوند عددی دریافت می‌کنند، و تنظیمات، مهارت‌ها، افزونه‌ها و سابقه مکالمه در هر ماشین محلی باقی می‌مانند.

اعتبارنامه‌های موجود مقصد نگه داشته می‌شوند. یک حساب منبع که از قبل در آنجا وارد شده است نامش بدون جایگزین کردن اعتبارنامه‌هایش همگام می‌شود؛ حساب‌های دیگر در کنار آن اضافه می‌شوند. برای جایگزین کردن اعتبارنامه‌های ذخیره‌شده برای حساب‌های منطبق، پس از بستن نشست‌های آن حساب در مقصد از `omarchy agent account copy --replace laptop claude` استفاده کنید. یک مقصد تازه همچنین حساب فعال و ترجیحات جابه‌جایی منبع را دریافت می‌کند؛ یک مقصد تثبیت‌شده حساب‌های خودش را نگه می‌دارد.

اعتبارنامه‌ها از طریق SSH جابه‌جا می‌شوند و در فایل‌های خصوصی در مقصد ذخیره می‌شوند، بنابراین فقط به ماشین‌هایی که به آن‌ها اعتماد دارید کپی کنید. این یک کپی یک‌باره است، نه همگام‌سازی مداوم. توکن‌های refresh مربوط به Codex می‌توانند توسط ماشین دیگری rotate شوند، و یک ورود کپی‌شده را نیازمند تمدید باقی بگذارند؛ ورودهای جداگانه برای استفاده همزمان در چند ماشین همچنان مطمئن‌ترین انتخاب هستند. به [راهنمای احراز هویت حساب Codex](https://developers.openai.com/codex/auth/ci-cd-auth) مراجعه کنید.

در هر ارائه‌دهنده یک حساب فعال است، و هر نشست جدید با همان شروع می‌شود: `cx`، `cy`، یک `claude`، `codex` یا `grok` ساده، هر چیزی که از طریق `omarchy agent` اجرا شود، و اسکریپت‌ها یا ویرایشگرهایی که CLI را روی `PATH` پیدا می‌کنند. با `omarchy agent account use work` جابه‌جا شوید (و با `omarchy agent account use main` برگردید)، یا در پنل با فشردن شماره یک حساب و سپس `Enter` (یا کلیک کردن روی دکمه Use آن). نشست‌هایی که از قبل در حال اجرا هستند روی حسابی که با آن شروع کرده‌اند باقی می‌مانند. سابقه مکالمه، تنظیمات، مهارت‌ها و افزونه‌ها بین حساب‌ها به اشتراک گذاشته می‌شوند، بنابراین `claude --continue` در همان پوشه کار را در حساب جدید از جایی که رها کرده‌اید ادامه می‌دهد.

با بیش از یک حساب، پنل محدودیت‌های هر حساب را کنار هم نشان می‌دهد، و حساب فعال علامت‌گذاری شده است. به‌طور پیش‌فرض Omarchy وقتی حساب فعال از 95% یک محدودیت عبور می‌کند به شما اطلاع می‌دهد، و کلیک کردن روی اعلان به حسابی با بیشترین فضای آزاد جابه‌جا می‌شود. روی خط یک حساب در پنل نگه دارید و روی Autoswitch که در کنار Use ظاهر می‌شود کلیک کنید (یا `m` را فشار دهید)، یا `omarchy agent account mode auto` را اجرا کنید، تا به جای آن خودش جابه‌جا شود؛ وقتی روشن است، Autoswitch جای Use را می‌گیرد، و کلیک دوباره روی آن به اطلاع‌رسانی برمی‌گردد. یک عدد اضافه کنید تا آستانه را تغییر دهید، مانند `omarchy agent account mode auto 90`. اگر همه حساب‌ها از آستانه بالاتر باشند، یک بار از آن باخبر می‌شوید، همراه با اینکه کدام حساب اول آزاد می‌شود. وقتی یک حساب فعال در فاصله 15 امتیازی از آستانه‌اش باشد (80% در حالت پیش‌فرض)، محدودیت‌های آن به جای هر 15 دقیقه، هر سه دقیقه بررسی می‌شوند.

`omarchy agent account list` هر حساب و آخرین محدودیت‌های آن را نشان می‌دهد، `omarchy agent account remove work` یکی را فراموش می‌کند، و `omarchy agent account rename primary Hey` نام یکی را تغییر می‌دهد (یا در پنل روی نام یک حساب کلیک کنید). این دستورها روی حساب‌های عامل پیش‌فرض شما کار می‌کنند؛ برای رسیدن به ارائه‌دهنده دیگر، ابتدا نام آن را بیاورید، مانند `omarchy agent account use codex side`. ورودی که از قبل در `~/.claude` یا `~/.codex` داشته‌اید حساب _Main_ است و همان‌جا که هست باقی می‌ماند. حسابی که بیش از حدود هشت ساعت بدون استفاده رها شده باشد می‌تواند _Sign-in required_ را نشان دهد؛ روی آن کلیک کنید تا همان حساب مستقیماً در پنل دوباره وارد شود، یا یک نشست در آن شروع کنید، که ورود را خودبه‌خود تازه می‌کند. سرورهای MCP که هنگام اضافه شدن یک حساب داشته‌اید همراه آن می‌آیند، اما سرورهایی که بعداً با `claude mcp add` اضافه می‌کنید فقط به حسابی می‌رسند که آن‌ها را در آن اضافه کرده‌اید. Claude Desktop و ابزارهایی که با یک مسیر مطلق به یک باینری CLI پیکربندی شده‌اند از این جابه‌جایی پیروی نمی‌کنند. یک `CLAUDE_CONFIG_DIR`، `CODEX_HOME` یا `GROK_HOME` صریح بر حساب انتخاب‌شده اولویت دارد.

### تشخیص کرش

Omarchy برای کرش‌های فرایند systemd-coredump را زیر نظر دارد. وقتی چیزی segfault می‌کند، یک اعلان «Process crashed» دریافت می‌کنید — روی آن کلیک کنید، و کرش همراه با مهارت diagnose-crash مربوط به Omarchy به عامل پیش‌فرض شما سپرده می‌شود، که عامل را در احراز واقعیت‌ها از core dump و تصمیم‌گیری درباره اینکه آیا کرش ارزش گزارش کردن به upstream را دارد راهنمایی می‌کند. همچنین می‌توانید آن را به‌صورت دستی در برابر هر PID از `coredumpctl list` با `omarchy agent crash <pid>` اجرا کنید.

این زیر نظر داشتن به‌طور پیش‌فرض روشن است. آن را زیر _Trigger > Toggle > Crash Capture_ (یا با `omarchy toggle crash-capture`) خاموش کنید و اعلان‌ها متوقف می‌شوند؛ `omarchy agent crash <pid>` همچنان به‌صورت دستی کار می‌کند.

کرش‌ها همچنین می‌توانند هر بار برای یک برنامه بی‌صدا شوند، که همان چیزی است که تشخیص در پایان به شما پیشنهاد می‌کند. `omarchy crash mute hyprland` اعلان‌ها را فقط برای آن برنامه متوقف می‌کند، `omarchy crash mute hyprland off` آن‌ها را برمی‌گرداند، و `omarchy crash mute` به‌تنهایی آنچه را بی‌صدا کرده‌اید فهرست می‌کند. مسیر باینری را به همان خوشی نام آن می‌گیرد، بنابراین `omarchy crash mute /usr/bin/hyprland` همان کار را می‌کند. نامی با فاصله در آن را در نقل‌قول بگذارید، مانند `omarchy crash mute 'Some App'`. همه چیزهای دیگر همچنان اطلاع‌رسانی می‌کنند، و برنامه بی‌صداشده همچنان کرش می‌کند — این یادآوری را پنهان می‌کند، چیزی را درست نمی‌کند.

### برنامه‌های دسکتاپ

منوی _Install > AI_ همچنین چند برنامه گرافیکی هوش مصنوعی را در بر می‌گیرد: برنامه دسکتاپ ChatGPT، برنامه دسکتاپ Claude (نسخه بتای Linux از Anthropic، با تب‌های Chat، Cowork و Claude Code)، Grok Bot برای چت کردن با مدل‌های xAI، Herdr Desktop، Hermes Desktop، OpenClaw، برنامه دسکتاپ Perplexity و T3 Code. Grok Bot برنامه چت دسکتاپ است. عامل کدنویسی دستور `grok` است.

Hermes Desktop همان موردی است که باید درباره‌اش بدانید، چون یک ماشین یک Hermes دارد، و آن متعلق به برنامه است: Hermes فقط و فقط از طریق برنامه نصب می‌شود، و دستور `hermes` که عامل پیش‌فرض اجرا می‌کند متعلق به برنامه است. انتخاب Hermes به‌عنوان عامل پیش‌فرض همان چیزی را نصب می‌کند که ورودی _Install > AI_ نصب می‌کند: بسته، و یک runtime مربوط به Hermes زیر `~/.hermes` که توسط نصب‌کننده خود Hermes راه‌اندازی شده است، که اولین بار چند دقیقه طول می‌کشد. آن runtime همان Hermes واحدی است که دستور ترمینال `hermes`، عامل پیش‌فرض و برنامه همگی از آن استفاده می‌کنند، و خودش را با `hermes update` به‌روز می‌کند به جای آنکه منتظر یک انتشار Omarchy بماند. نصب آن همچنین تم Omarchy را به‌عنوان یک skin با نام `omarchy` به Hermes می‌دهد، که هر سطح Hermes هنگام تغییر تم‌ها از آن پیروی می‌کند؛ اگر ترجیح می‌دهید این‌طور نباشد، مورد دیگری را زیر تنظیمات Appearance مربوط به Hermes یا با `/skin` انتخاب کنید، و Omarchy آن انتخاب را به حال خودش می‌گذارد. حذف برنامه زیر _Remove > AI_ ابتدا Hermes را می‌بندد، gateway هم شامل آن، آن runtime را همراه خود می‌برد، و چت‌ها، حافظه‌ها و مهارت‌هایی را که Hermes برای خودش نوشته نگه می‌دارد مگر آنکه خلافش را بگویید: می‌پرسد، با پیش‌فرض نه، که آیا آن داده‌ها و تنظیمات اتصال شما نیز باید حذف شوند یا نه.

تجربه دسکتاپ OpenClaw همان Control UI آن است، که به‌عنوان یک برنامه وب باز می‌شود که توسط gateway محلی خودش پشتیبانی می‌شود. OpenClaw در `~/.openclaw` زندگی می‌کند و خودش را به‌روز می‌کند: از دکمه «Update Gateway» در Control UI استفاده کنید یا `openclaw update` را اجرا کنید، و gateway روی نسخه جدید راه‌اندازی مجدد می‌شود. Omarchy فقط نسخه‌ای را انتخاب می‌کند که یک نصب تازه از آن شروع شود. حذف OpenClaw زیر _Remove > AI_ سرویس gateway و برنامه را همراه خود می‌برد و سپس می‌پرسد که آیا `~/.openclaw` هم باید حذف شود یا نه، چون آن چت‌ها و اعتبارنامه‌های شما را در کنار خود OpenClaw و runtimeهای افزونه‌ای که دانلود می‌کند نگه می‌دارد؛ پیش‌فرض آن را نگه می‌دارد، و نصب دوباره OpenClaw آن را بازمی‌یابد.

Herdr Desktop برنامه دسکتاپ [Herdr](https://herdr.dev) است: فضاها، تب‌ها و paneهایی از ترمینال‌ها و عامل‌های کدنویسی که وقتی پنجره را می‌بندید در هسته آن به اجرا ادامه می‌دهند. از نصب‌کننده خود Herdr می‌آید نه از یک بسته، بنابراین در `~/.local/share/herdr-app` زندگی می‌کند، وقتی هنوز یکی ندارید هسته‌اش را همراه خود در `~/.local/bin/herdr-core` می‌آورد، و هر دو خودش را به‌روز می‌کند. در کنار دستور `herdr` می‌نشیند که Omarchy روی `Super + Ctrl + Return` ارائه می‌کند نه اینکه جایگزین آن شود، و کلیدهای مستقیم آن دستور را می‌گیرد: `Alt + Return` و `Alt + Shift + Return` یک pane را به پایین یا راست تقسیم می‌کنند، `Alt + Escape` آن را می‌بندد، `Ctrl + Alt + Arrow` بین paneها حرکت می‌کند، `Alt + 1..9` و `Alt + Left/Right` یک تب انتخاب می‌کنند، و `Alt + Up/Down` بین فضاها حرکت می‌کنند. `Ctrl + 1..9` یک فضا انتخاب می‌کند و `Alt + Shift + Up/Down` در میان عامل‌ها قدم برمی‌دارد. کلیدهای پیشوند `Ctrl + Space` فقط مخصوص ترمینال باقی می‌مانند، چون برنامه نمی‌تواند یک کلید Ctrl ساده را برای یک دنباله نگه دارد. Omarchy این‌ها را در `~/.config/herdr-app/keys.json` می‌نویسد، و `omarchy-refresh-herdr-app` آن‌ها را برمی‌گرداند. نصب آن تم Omarchy مربوط به Herdr را انتخاب می‌کند، که از آن به بعد از تم Omarchy شما پیروی می‌کند. Herdr یک تم برای حالت روشن و یکی برای حالت تیره نگه می‌دارد، بنابراین پس از جابه‌جایی بین یک تم تیره و روشن Omarchy، Omarchy را یک بار دیگر در انتخاب‌گر تم Herdr برای حالت دیگر انتخاب کنید.

T3 Code از انتشار رسمی AppImage آن در `~/.local/share/t3code` اجرا می‌شود نه از یک بسته، بنابراین خودش را به‌روز می‌کند. نصب آن می‌پرسد که آیا روی کانال Stable یا Nightly شروع شود؛ بعداً در تنظیمات T3 Code جابه‌جا شوید. threadها و تنظیمات شما در `~/.t3` زندگی می‌کنند، و حذف T3 Code زیر _Remove > AI_ آن‌ها را همراه خود می‌برد.

### مدل‌های محلی

یک مدل باز را روی ماشین خودتان برای عامل‌های کدنویسی‌تان اجرا کنید. پرامپت‌ها و کد شما روی ماشین باقی می‌مانند؛ هیچ چیزی که برای مدل فرستاده شود از آن خارج نمی‌شود. با این شروع کنید:

```bash
omarchy agent local use best
```

یا، در پنل عامل‌ها در نوار بالایی، + و سپس Local AI را انتخاب کنید، که وقتی مدلی با این ماشین سازگار باشد ظاهر می‌شود. اولین بار، این Podman را نصب می‌کند، که مدل‌ها را اجرا می‌کند، و روی یک ماشین NVIDIA ابزار NVIDIA container toolkit را، که GPU را در اختیار آن‌ها می‌گذارد. سپس Omarchy مدل توصیه‌شده برای این ماشین را انتخاب می‌کند، آن را دانلود می‌کند و شروع می‌کند. منتظر دانلودی در حد ده‌ها GB و استفاده از بیشتر حافظه ماشین هنگام اجرای مدل باشید: Flash Next با context کامل 256K خود حدود 100 GiB استفاده می‌کند. اگر مدل‌های دیگری حافظه مورد نیاز آن را در اختیار داشته باشند، متوقف‌شده راه‌اندازی می‌شود، آماده شروع پس از آنکه یکی را متوقف کنید. مدل هنگام خروج از سیستم متوقف می‌شود؛ وقتی برای کار دیگری به حافظه نیاز دارید خودتان آن را متوقف کنید.

`omarchy agent local list` گزینه‌ها را نشان می‌دهد و توضیح می‌دهد چرا بعضی سازگار نیستند. برای راه‌اندازی یکی دیگر، `omarchy agent local use <recipe>` را اجرا کنید. امروزه، `qwen3.8-flash-next-gufo` و `qwen3.8-27b-gufo` برای ماشین‌های 128 GB Strix Halo در دسترس هستند؛ 27B حدود 40 GiB می‌گیرد، بنابراین برای کارهای دیگر جا باقی می‌گذارد. recipeها و توصیه‌های جدید با `omarchy update`، از طریق بسته، می‌رسند.

هر مدلی که راه‌اندازی می‌کنید خط خودش را در پنل عامل‌ها می‌گیرد، در کنار اشتراک‌های شما: play برای شروع آن، pause برای متوقف کردن آن و آزاد کردن حافظه‌اش، و دکمه ترمینال برای باز کردن عاملتان روی آن. وقتی با هم در حافظه جا شوند چند مدل می‌توانند همزمان اجرا شوند؛ اگر یکی جا نشود، Omarchy می‌گوید کدام مدل در حال اجرا را متوقف کنید. خط‌ها را برای مرتب کردن دوباره بکشید، و روی یک خط انتخاب‌شده Delete را فشار دهید تا یک مدل و دانلود آن حذف شود.

از خط فرمان، `omarchy agent local start <recipe>` و `omarchy agent local stop <recipe>` همان کار را می‌کنند، `omarchy agent local status` هر مدل را نشان می‌دهد، و `omarchy agent --local` عامل پیش‌فرض شما را روی آخرین مدلی که شروع کرده‌اید باز می‌کند (اگر عامل پیش‌فرض شما نمی‌تواند از یک مدل محلی استفاده کند pi). هر کلاینت سازگار با OpenAI نیز می‌تواند متصل شود: `status` نشانی هر مدل را نشان می‌دهد (اولی `http://127.0.0.1:11435/v1` است)، نام recipe همان مدل است، و کلید در `~/.config/omarchy/agent-local/key` است.

`omarchy agent local remove <recipe>` یک مدل و دانلودهایی را که هیچ مدل دیگری استفاده نمی‌کند حذف می‌کند.

runtimeهای third-party با ناشرشان برچسب‌گذاری می‌شوند. Omarchy هر مدل را بدون دسترسی به شبکه اجرا می‌کند.

### مدل‌های زبانی بزرگ محلی

Omarchy دو راه برای اجرای مدل‌های LLM محلی توصیه می‌کند: LM Studio و Ollama. LM Studio یک رابط GUI برای پیدا کردن مدل‌های open-weight، نصب آن‌ها و اجرای آن‌ها فراهم می‌کند. راهی عالی برای شروع آسان است. Ollama یک CLI برای انجام مشابه آن ارائه می‌کند. اما اگر در مدل‌های محلی تازه‌کار هستید، من با LM Studio شروع می‌کنم. می‌توانید هر یک را زیر _Install > AI_ در منوی Omarchy نصب کنید.

### مهارت Omarchy

مهارت‌های عامل به هوش مصنوعی کمک می‌کنند از ابزارهای خاص به شیوه‌ای خاص استفاده کند، و Omarchy با یک مهارت پیش‌فرض برای متناسب‌سازی سیستم ارائه می‌شود. مانند دستکاری کانفیگ Hyprland شما، تنظیم نوار، یا حتی ساختن یک تم جدید از صفر. به دایرکتوری‌های مهارت برای Claude Code (`~/.claude/skills`)، Codex (`~/.codex/skills`)، Pi (`~/.pi/agent/skills`)، Antigravity (`~/.gemini/config/skills`)، Hermes (`~/.hermes/skills` و هر `~/.hermes/profiles/*/skills`) و مکان عمومی `~/.agents/skills` symlink شده است، بنابراین بیشتر harnessها آن را به‌طور خودکار برمی‌دارند.

اما باید این مهارت را آزمایشی در نظر بگیرید. مدل‌های مختلف از آن با تأثیر متفاوتی استفاده خواهند کرد. بهتر است ابتدا در حالت plan اجرا کنید، تا ایده‌ای از آنچه عامل می‌خواهد تغییر دهد داشته باشید. و سپس آماده باشید تغییرات را برگردانید یا حتی `omarchy reinstall configs` را فراخوانی کنید، اگر عامل همه چیز را به هم ریخت.
