# هوش مصنوعی

Omarchy برای عامل‌های کدنویسی زیر لانچرهایی دارد، بدون اینکه پیش‌فرضی را برایتان انتخاب کند. یک دستور را اجرا کنید تا CLI آن در اولین استفاده نصب شود، سپس وقتی از شما خواسته شد احراز هویت کنید. Hermes استثناست: در اولین استفاده چیزی برای آن نصب نمی‌شود، و انتخاب آن Hermes Desktop را نصب می‌کند، همان‌طور که بخش _برنامه‌های دسکتاپ_ در پایین توضیح می‌دهد.

### نصب و به‌روزرسانی عامل‌ها

به‌جز Hermes، این عامل‌ها از نصب تنبل mise استفاده می‌کنند: اولین اجرا CLI را نصب می‌کند، و اجراهای بعدی از همان استفاده می‌کنند. mise همچنین حداکثر هر چهار ساعت یک بار، درست پیش از شروع یا در پس‌زمینه هنگام نمایش پرامپت شل، عامل نصب‌شده را برای انتشار نسخه‌ای جدید بررسی می‌کند. اگر آن به‌روزرسانی شکست بخورد یا آفلاین باشید، نسخه نصب‌شده اجرا می‌شود. `omarchy update` عامل‌های نصب‌شده را همراه با بقیه Omarchy به‌روز می‌کند، و `mup` فقط ابزارهای مدیریت‌شده با mise را به‌روز می‌کند.

به‌روزرسان خود یک عامل، مثل `claude update`، `codex update` یا یک دکمه به‌روزرسانی در یک برنامه، نمونه نصب‌شده مدیریت‌شده با mise را به‌روز نمی‌کند. `codex update` شکست می‌خورد، و `claude update` می‌تواند موفقیت را گزارش کند در حالی که نسخه‌ای جداگانه نصب می‌کند که mise آن را ردیابی نمی‌کند. اگر ترجیح می‌دهید از نصب‌کننده و به‌روزرسان بومی یک عامل استفاده کنید، آن را به `disable_tools` اضافه کنید؛ [ابزارهای CLI از پیش نصب‌شده](18-development-tools.md#preinstalled-cli-tools) را ببینید.

برای اینکه همه ابزارهای تنبل پیکربندی‌شده را پیش از نیازتان نصب کنید، `mise install --include-lazy` را اجرا کنید. این شامل سایر ابزارهای CLI پیش‌فرض Omarchy و همچنین عامل‌ها می‌شود. برای نصب یک ابزار منفرد یا استفاده از نصب خودتان، [ابزارهای CLI از پیش نصب‌شده](18-development-tools.md#preinstalled-cli-tools) را ببینید.

`grok` از طریق بسته first-party به نام `grok` در mise نصب می‌شود، درست همان‌طور که `claude` و `codex` نصب می‌شوند. `grok` را اجرا کنید، یا آن را در _Setup > Defaults > Agent_ انتخاب کنید. نصب‌کننده `curl | bash` در x.ai را کنار بگذارید. آن مسیر نسخه دومی را در `~/.grok/bin` می‌گذارد، آن را در ابتدای `PATH` قرار می‌دهد، و wrapper مربوط به Omarchy را بازنویسی می‌کند.

`dsh` رابط کاربری مرورگری خود را روی `127.0.0.1:3080` باز می‌کند، و دایرکتوری اجرا فضای کاری پیش‌فرض آن است. رابط کاربری مرورگری آن پرامپت آغازین نمی‌گیرد، پس `omarchy agent prompt` آن را طوری باز می‌کند که پرامپت روی کلیپ‌بورد شما باشد تا آن را بچسبانید. Omarchy آن را با پیش‌تنظیم مجوز بدون تأیید DeepSeek شروع می‌کند. DeepSeek Harness وقتی از API رسمی مدل آن استفاده می‌کنید، لاگ‌های نشست را به DeepSeek آپلود می‌کند؛ این را در رابط کاربری مرورگری آن زیر _Settings > General > Upload Session Log_ خاموش کنید. بازخوردی که برای آن می‌فرستید هم همراه با نشست آپلود می‌شود، مگر اینکه آن را با `DSH_TELEMETRY_MODE=DISABLED` شروع کنید.

### عامل پیش‌فرض

عامل پیش‌فرض خود را با `omarchy default agent <name>` یا زیر _Setup > Defaults > Agent_ در منوی Omarchy (یعنی `Super + Space`) انتخاب کنید. اگر عامل هنوز نصب نشده باشد، انتخاب آن ابتدا آن را نصب می‌کند. یک Omarchy تازه با یک اعلان یک‌باره از شما دعوت می‌کند این انتخاب را انجام دهید.

انتخاب Claude همچنین تلاش می‌کند افزونه مرورگر آن را برای Chromium، Chrome، Brave، Brave Origin و Edge راه‌اندازی کند. راه‌اندازی افزونه برای همه کاربران اعمال می‌شود و ممکن است رمز عبور سیستم شما را بخواهد؛ لغو کردن یا شکست نصب افزونه هنوز Claude را انتخاب و اجرا می‌کند. مرورگرتان را دوباره راه بیندازید، اگر خواسته شد افزونه را فعال کنید، و برای کامل کردن اتصال آن وارد Claude شوید. برای بررسی اتصال، `/chrome` را در Claude اجرا کنید. Firefox و Zen از این افزونه پشتیبانی نمی‌کنند. اگر Claude پیش از اضافه شدن این راه‌اندازی هم عامل پیش‌فرض شما بود، آن را دوباره انتخاب کنید تا افزونه نصب شود.

وقتی انتخاب کردید، `Super + Shift + Ctrl + A` عامل پیش‌فرض را در یک پنجره ترمینال اختصاصی اجرا می‌کند (یا اگر هنوز انتخابی نکرده باشید، انتخاب‌گر را بالا می‌آورد). همچنین می‌توانید آن را مستقیماً در یک کار اجرا کنید با `omarchy agent prompt "Review this project"`. Freebuff و DeepSeek Harness پرامپت آغازین نمی‌گیرند، پس به جای آن طوری باز می‌شوند که پرامپت روی کلیپ‌بورد شما باشد تا آن را بچسبانید. عامل‌هایی که این‌طور اجرا می‌شوند بدون مراقبت و در حالت‌های مربوط به خودشان یعنی «برای سؤال کردن توقف نکن» کار می‌کنند، پس آماده باشید که واقعاً دست به کار شوند! MiniMax Code برای نشست‌های تعاملی‌اش چنین حالتی ندارد، پس مثل معمول برای مجوزها سؤال می‌کند. و چون عامل‌ها حاضر نیستند اعتماد را برای دایرکتوری خانگی شما به خاطر بسپارند، اجراها از `$HOME` به جای آن در `~/Work` شروع می‌شوند.

میانبرهای ترمینال هم وجود دارند: `a` عامل پیش‌فرض را به صورت درون‌خطی در ترمینال فعلی اجرا می‌کند، در حالی که `c`، `cx` و `cy` به ترتیب OpenCode، Claude Code و Codex را مستقیماً شروع می‌کنند (باز هم در حالت‌های تأیید خودکارشان). تغییر تم با عامل‌ها هم همگام می‌شود: Claude Code، Pi، OpenCode و Hermes (وقتی Omarchy آن را نصب کرده باشد) همگی وقتی تم Omarchy را عوض می‌کنید همراهی می‌کنند.

### پنل عامل‌ها

نوار بالایی یک آیکون عامل‌ها دارد. پیش از اینکه یک عامل را راه بیندازید، پنل آن شما را در وارد شدن به Claude، Codex یا Grok راهنمایی می‌کند، و اولین مورد عامل پیش‌فرض شما می‌شود. پس از آن، پنل هر اشتراک را روی یک صفحه قرار می‌دهد: هر عامل و حساب با طرحش، یک متر برای هر کدام از محدودیت‌های نشست ۵ ساعته و هفتگی‌اش با زمان باقی‌مانده تا ریست آن (برای درصد دقیق نگه دارید)، یا موجودی پیش‌پرداخت باقی‌مانده، زیر خطی که در آنچه در همه آن‌ها استفاده کرده‌اید می‌چرخد، مثل توکن‌های این هفته و پراستفاده‌ترین مدل شما. زیر _Make something_ پرامپت‌های آغازینی برای یک تم، افزونه یا برنامه جدید پیشنهاد می‌دهد که کار را به عامل پیش‌فرض شما می‌سپارند. برنامه‌ها همان‌طور ساخته می‌شوند که برنامه‌های خود Omarchy یعنی Hype، Monologue و Omacut ساخته شده‌اند، در C++ و Qt Quick، با پیروی از مهارت عامل omarchy-app، و کامپایلر و قطعات Qt مورد نیازشان نصب‌شده می‌آیند. Claude Code، Codex، Grok، Kimi، Cursor و سهمیه Grok Bot آن، GitHub Copilot، Muse، Antigravity، Kimchi و Devin از همان ابتدا با محدودیت‌هایشان پوشش داده می‌شوند، و Hermes، Mistral Vibe و Qwen Code وقتی از آن‌ها استفاده کرده باشید نشست‌ها و توکن‌هایشان را نشان می‌دهند. طرح‌ها و کلیدهای ارائه‌دهندگانی که از طریق pi، omp یا opencode استفاده می‌کنید هم ظاهر می‌شوند: OpenCode Zen و Go، Z.ai GLM Coding Plan، Ollama Cloud، MiniMax Token Plan و Synthetic با محدودیت‌هایشان؛ Fireworks، OpenRouter و DeepSeek با موجودی‌های پیش‌پرداختشان؛ و مدل‌هایی که روی سخت‌افزار خودتان اجرا می‌کنید زیر Local models. هر عامل فقط یک بار شمرده می‌شود، زیر نام هر کسی که صورت‌حسابش را صادر می‌کند، هر چند هارنس را که از طریق آن به کارش می‌گیرید.

برای پنل روی آیکون نوار کلیک چپ کنید، برای اجرای عامل پیش‌فرضتان کلیک راست کنید. رکوردهای مصرف پشت آن هر ۱۵ دقیقه با `omarchy agent usage-update` دوباره تولید می‌شوند، و پنل حتی می‌تواند مصرف ماشین‌های دیگر شما را از طریق یک پوشه همگام‌شده ادغام کند. برای تنظیمات کامل، README زیر `$OMARCHY_PATH/shell/plugins/agents/` را ببینید.

### چند اشتراک

اگر برای بیش از یک طرح Claude، Codex یا Grok پول می‌دهید — مثلاً یک Max شخصی و یک کاری — Omarchy می‌تواند همه آن‌ها را وارد نگه دارد و بینشان جابه‌جا شود. یک اشتراک را با + در پنل عامل‌ها اضافه کنید، که همان‌جا شما را در انجام آن راهنمایی می‌کند، یا با `omarchy agent account add claude Work` (یا `codex`، یا `grok`). اگر CLI نباشد آن را نصب می‌کند. اولین حساب برای یک ارائه‌دهنده از طریق مرورگر معمولی شما وارد می‌شود، درست همان‌جا که CLI همیشه نگاه می‌کند. هر حساب بعدی از طریق یک پنجره خصوصی وارد می‌شود، تا حسابی که مرورگرتان از قبل به آن وارد شده است اشتباهی انتخاب نشود؛ آنجا به عنوان حسابی که دارید اضافه می‌کنید وارد شوید، و ابتدا هر پنجره خصوصی‌ای را که از قبل باز داشته‌اید ببندید. هرگز برای انجام این کار از CLI خارج نشوید: خروج ورود ذخیره‌شده را لغو می‌کند، و آن حساب باید دوباره اضافه شود.

برای کپی کردن ورودهای اشتراکتان به یک ماشین Omarchy دیگر از طریق SSH، `omarchy agent account copy user@laptop` را اجرا کنید. وقتی مقصد گیرنده‌ای نصب‌شده ندارد، فرستنده یک گیرنده موقت تأمین می‌کند، پس ماشین‌های قدیمی‌تر Omarchy می‌توانند بدون به‌روزرسانی حساب‌ها را دریافت کنند. گیرنده‌های نصب‌شده اولویت دارند. این همه اشتراک‌های Claude، Codex و Grok را کپی می‌کند؛ برای انتخابشان نام ارائه‌دهنده‌ها را اضافه کنید، مثل `omarchy agent account copy laptop claude`. نام حساب‌ها و شناسه‌های دستور با منبع مطابقت دارند، از جمله حساب‌هایی که از قبل روی مقصد حضور دارند. حساب‌های نامرتبط مقصد اگر نامشان تداخل داشته باشد پسوند عددی می‌گیرند، و تنظیمات، مهارت‌ها، افزونه‌ها و تاریخچه گفتگو برای هر ماشین محلی می‌ماند.

اعتبارنامه‌های موجود مقصد نگه داشته می‌شوند. یک حساب مبدأ که از قبل آنجا وارد شده است نامش بدون جایگزین کردن اعتبارنامه‌هایش همگام می‌شود؛ حساب‌های دیگر در کنار آن اضافه می‌شوند. برای جایگزین کردن اعتبارنامه‌های ذخیره‌شده برای حساب‌های منطبق، بعد از بستن نشست‌های آن حساب روی مقصد از `omarchy agent account copy --replace laptop claude` استفاده کنید. یک مقصد تازه همچنین حساب فعال و ترجیحات جابه‌جایی مبدأ را می‌گیرد؛ یک مقصد تثبیت‌شده مال خودش را نگه می‌دارد.

اعتبارنامه‌ها از طریق SSH سفر می‌کنند و روی مقصد در فایل‌های خصوصی ذخیره می‌شوند، پس فقط به ماشین‌هایی کپی کنید که به آن‌ها اعتماد دارید. این یک کپی یک‌باره است، نه همگام‌سازی مداوم. توکن‌های تازه‌سازی Codex می‌توانند توسط ماشین دیگری چرخانده شوند، و ورود کپی‌شده را نیازمند تمدید کنند؛ ورودهای جداگانه قابل‌اعتمادترین انتخاب برای استفاده همزمان روی چند ماشین باقی می‌مانند. [راهنمای احراز هویت حساب Codex](https://developers.openai.com/codex/auth/ci-cd-auth) را ببینید.

برای هر ارائه‌دهنده یک حساب فعال است، و هر نشست جدید به عنوان آن شروع می‌شود: `cx`، `cy`، یک `claude`، `codex` یا `grok` ساده، هر چیزی که از طریق `omarchy agent` اجرا شود، و اسکریپت‌ها یا ویرایشگرهایی که CLI را روی `PATH` پیدا می‌کنند. با `omarchy agent account use work` جابه‌جا شوید (و با `omarchy agent account use main` برگردید)، یا در پنل با فشار دادن شماره یک حساب و سپس `Enter` (یا کلیک روی دکمه Use آن). نشست‌هایی که از قبل در حال اجرا هستند روی حسابی که با آن شروع شده‌اند می‌مانند. تاریخچه گفتگو، تنظیمات، مهارت‌ها و افزونه‌ها بین حساب‌ها به اشتراک گذاشته می‌شوند، پس `claude --continue` در همان پوشه روی حساب جدید از همان‌جایی که رها کرده بودید ادامه می‌دهد.

با بیش از یک حساب، پنل محدودیت‌های هر حساب را کنار هم نشان می‌دهد، و حساب فعال علامت‌گذاری شده است. به طور پیش‌فرض Omarchy وقتی حساب فعال از ۹۵٪ یک محدودیت عبور کند به شما خبر می‌دهد، و کلیک روی اعلان به حسابی با بیشترین فضای خالی جابه‌جا می‌شود. خط یک حساب را در پنل نگه دارید و روی Autoswitch که کنار Use ظاهر می‌شود کلیک کنید (یا `m` را فشار دهید)، یا `omarchy agent account mode auto` را اجرا کنید، تا به جای آن خودش جابه‌جا شود؛ وقتی روشن است، Autoswitch جای Use را می‌گیرد، و کلیک دوباره روی آن به خبر دادن برمی‌گردد. عددی اضافه کنید تا آستانه را تغییر دهید، مثل `omarchy agent account mode auto 90`. اگر هر حسابی از آستانه بالاتر باشد، یک بار از آن باخبر می‌شوید، همراه با اینکه کدام حساب اول آزاد می‌شود. وقتی یک حساب فعال در فاصله ۱۵ امتیازی از آستانه‌اش باشد (۸۰٪ در حالت پیش‌فرض)، محدودیت‌هایش هر سه دقیقه به جای هر ۱۵ دقیقه بررسی می‌شوند.

`omarchy agent account list` هر حساب و آخرین محدودیت‌هایش را نشان می‌دهد، `omarchy agent account remove work` یکی را فراموش می‌کند، و `omarchy agent account rename primary Hey` نام یکی را تغییر می‌دهد (یا در پنل روی نام یک حساب کلیک کنید). این دستورات روی حساب‌های عامل پیش‌فرض شما کار می‌کنند؛ برای رسیدن به ارائه‌دهنده دیگر، اول نام آن را بیاورید، مثل `omarchy agent account use codex side`. ورودی که از قبل در `~/.claude` یا `~/.codex` داشتید حساب _Main_ است و همان‌جا که هست می‌ماند. حسابی که بیش از حدود هشت ساعت استفاده نشده باشد می‌تواند _Sign-in required_ نشان دهد؛ روی آن کلیک کنید تا همان حساب را درست در پنل دوباره وارد کنید، یا یک نشست در آن شروع کنید، که ورود را خودش تازه می‌کند. سرورهای MCP که وقتی حسابی اضافه شد داشتید همراه آن می‌آیند، اما آن‌هایی که بعداً با `claude mcp add` اضافه می‌کنید فقط به حسابی می‌رسند که آن‌ها را در آن اضافه کرده‌اید. Claude Desktop و ابزارهایی که با یک مسیر مطلق به یک باینری CLI پیکربندی شده‌اند از جابه‌جایی پیروی نمی‌کنند. یک `CLAUDE_CONFIG_DIR`، `CODEX_HOME` یا `GROK_HOME` صریح بر حساب انتخاب‌شده اولویت دارد.

### تشخیص خرابی

Omarchy برای خرابی‌های پردازش systemd-coredump را زیر نظر می‌گیرد. وقتی چیزی segfault می‌کند، یک اعلان "Process crashed" می‌گیرید — روی آن کلیک کنید، و خرابی همراه با مهارت diagnose-crash مربوط به Omarchy به عامل پیش‌فرض شما سپرده می‌شود، که عامل را در تثبیت حقایق از core dump و تصمیم‌گیری درباره اینکه آیا خرابی ارزش گزارش دادن به بالادستی را دارد راهنمایی می‌کند. همچنین می‌توانید آن را به صورت دستی در برابر هر PID از `coredumpctl list` با `omarchy agent crash <pid>` اجرا کنید.

زیر نظر گرفتن به طور پیش‌فرض روشن است. آن را زیر _Trigger > Toggle > Crash Capture_ خاموش کنید (یا با `omarchy toggle crash-capture`) و اعلان‌ها متوقف می‌شوند؛ `omarchy agent crash <pid>` هنوز به صورت دستی کار می‌کند.

خرابی‌ها را همچنین می‌توان هر بار یک برنامه بی‌صدا کرد، که همان چیزی است که تشخیص در پایان به شما پیشنهاد می‌دهد. `omarchy crash mute hyprland` اعلان‌ها را فقط برای آن برنامه متوقف می‌کند، `omarchy crash mute hyprland off` آن‌ها را برمی‌گرداند، و `omarchy crash mute` به تنهایی فهرست می‌کند چه چیزی را بی‌صدا کرده‌اید. مسیر باینری را همان‌قدر خوشحال می‌پذیرد که نام آن را، پس `omarchy crash mute /usr/bin/hyprland` همان کار را می‌کند. نامی با فاصله را در گیومه بگذارید، مثل `omarchy crash mute 'Some App'`. همه چیز دیگر هنوز اعلان می‌دهد، و برنامه بی‌صداشده هنوز خراب می‌شود — این یادآوری را پنهان می‌کند، چیزی را درست نمی‌کند.

### برنامه‌های دسکتاپ

منوی _Install > AI_ همچنین چند برنامه هوش مصنوعی گرافیکی دارد: برنامه دسکتاپ ChatGPT، برنامه دسکتاپ Claude (بتای لینوکس Anthropic، با زبانه‌های Chat، Cowork و Claude Code)، Grok Bot برای گفتگو با مدل‌های xAI، Hermes Desktop، OpenClaw، برنامه دسکتاپ Perplexity و T3 Code. Grok Bot برنامه گفتگوی دسکتاپ است. عامل کدنویسی دستور `grok` است.

Hermes Desktop همان یکی است که باید درباره‌اش بدانید، چون یک ماشین یک Hermes دارد، و آن مال برنامه است: Hermes فقط و فقط از طریق برنامه نصب می‌شود، و دستور `hermes` که عامل پیش‌فرض اجرا می‌کند مال برنامه است. انتخاب Hermes به عنوان عامل پیش‌فرض همان چیزی را نصب می‌کند که ورودی _Install > AI_ نصب می‌کند: بسته، و یک runtime از Hermes زیر `~/.hermes` که توسط نصب‌کننده خود Hermes راه‌اندازی شده است، که دفعه اول چند دقیقه طول می‌کشد. آن runtime همان یک Hermes است که دستور `hermes` ترمینال، عامل پیش‌فرض و برنامه همه از آن استفاده می‌کنند، و خودش را با `hermes update` به‌روز می‌کند به جای اینکه منتظر یک انتشار Omarchy بماند. نصب آن همچنین تم Omarchy را به عنوان یک پوسته با نام `omarchy` به Hermes می‌دهد، که هر سطح Hermes وقتی تم‌ها را عوض می‌کنید از آن پیروی می‌کند؛ اگر ترجیح می‌دهید این‌طور نباشد، یکی دیگر را زیر تنظیمات Appearance مربوط به Hermes یا با `/skin` انتخاب کنید، و Omarchy آن انتخاب را به حال خودش می‌گذارد. حذف برنامه زیر _Remove > AI_ ابتدا Hermes را می‌بندد، gateway هم شامل آن، و آن runtime را با خودش می‌برد، و گفتگوها، خاطرات و مهارت‌هایی را که Hermes برای خودش نوشته نگه می‌دارد مگر اینکه خلافش را بگویید: می‌پرسد، با پیش‌فرض نه، که آیا آن داده و تنظیمات اتصال شما هم باید بروند یا نه.

تجربه دسکتاپ OpenClaw همان Control UI آن است، که به عنوان یک برنامه وب با پشتیبانی gateway محلی خودش باز می‌شود. OpenClaw در `~/.openclaw` زندگی می‌کند و خودش را به‌روز می‌کند: از دکمه "Update Gateway" در Control UI استفاده کنید یا `openclaw update` را اجرا کنید، و gateway روی نسخه جدید دوباره راه می‌افتد. Omarchy فقط انتشاری را انتخاب می‌کند که یک نصب تازه از آن شروع می‌شود. حذف OpenClaw زیر _Remove > AI_ سرویس gateway و برنامه را با خودش می‌برد و سپس می‌پرسد آیا `~/.openclaw` هم باید برود یا نه، چون آن گفتگوها و اعتبارنامه‌های شما را در کنار خود OpenClaw و runtimeهای افزونه‌ای که دانلود می‌کند نگه می‌دارد؛ پیش‌فرض آن را نگه می‌دارد، و نصب دوباره OpenClaw آن را دوباره برمی‌دارد.

T3 Code از انتشار رسمی AppImage آن در `~/.local/share/t3code` اجرا می‌شود نه از یک بسته، پس خودش را به‌روز می‌کند. نصب آن می‌پرسد آیا روی کانال Stable شروع کنید یا Nightly؛ بعداً در تنظیمات T3 Code جابه‌جا شوید. رشته‌ها و تنظیمات شما در `~/.t3` زندگی می‌کنند، و حذف T3 Code زیر _Remove > AI_ آن‌ها را با خودش می‌برد.

### مدل‌های محلی

یک مدل باز را روی ماشین خودتان برای عامل‌های کدنویسی‌تان اجرا کنید. پرامپت‌ها و کد شما روی ماشین می‌مانند؛ هیچ چیز فرستاده‌شده به مدل از آن بیرون نمی‌رود. با این شروع کنید:

```bash
omarchy agent local use best
```

یا، در پنل عامل‌ها در نوار بالایی، + و سپس Local AI را انتخاب کنید، که وقتی مدلی برای این ماشین مناسب باشد ظاهر می‌شود. دفعه اول، این Podman را نصب می‌کند، که مدل‌ها را اجرا می‌کند، و روی یک ماشین NVIDIA تول‌کیت کانتینر NVIDIA را، که GPU را به آن‌ها می‌دهد. سپس Omarchy مدل توصیه‌شده برای این ماشین را انتخاب می‌کند، آن را دانلود می‌کند، و آن را شروع می‌کند. انتظار دانلودی چندده GB و استفاده از بیشتر حافظه ماشین هنگام اجرای مدل را داشته باشید: Flash Next با کانتکست کامل 256K خود از حدود 100 GiB استفاده می‌کند. اگر مدل‌های دیگر حافظه مورد نیاز آن را گرفته باشند، متوقف راه‌اندازی می‌شود، آماده شروع وقتی یکی را متوقف کنید. مدل هنگام خروج متوقف می‌شود؛ وقتی حافظه را برای کار دیگری نیاز دارید خودتان آن را متوقف کنید.

`omarchy agent local list` گزینه‌ها را نشان می‌دهد و توضیح می‌دهد چرا بعضی‌ها مناسب نیستند. برای راه‌اندازی یکی دیگر، `omarchy agent local use <recipe>` را اجرا کنید. امروز، `qwen3.8-flash-next-halogen` و `qwen3.8-27b-gufo` برای ماشین‌های 128 GB Strix Halo در دسترس هستند. دستور پخت‌ها و توصیه‌های جدید با `omarchy update`، از طریق بسته، می‌آیند.

هر مدلی که راه بیندازید خط خودش را در پنل عامل‌ها می‌گیرد، کنار اشتراک‌های شما: پخش برای شروع آن، مکث برای متوقف کردن آن و آزاد کردن حافظه‌اش، و دکمه ترمینال برای باز کردن عاملتان روی آن. چند تا می‌توانند همزمان اجرا شوند وقتی با هم در حافظه جا شوند؛ اگر یکی جا نشود، Omarchy می‌گوید کدام مدل در حال اجرا را متوقف کنید. خط‌ها را برای مرتب کردن دوباره بکشید، و روی یک خط انتخاب‌شده Delete را فشار دهید تا یک مدل و دانلود آن حذف شود.

از خط فرمان، `omarchy agent local start <recipe>` و `omarchy agent local stop <recipe>` همان کار را می‌کنند، `omarchy agent local status` هر مدل را نشان می‌دهد، و `omarchy agent --local` عامل پیش‌فرض شما را روی آخرین مدلی که شروع کرده‌اید باز می‌کند (اگر عامل پیش‌فرض شما نتواند از یک مدل محلی استفاده کند pi). هر کلاینت سازگار با OpenAI هم می‌تواند متصل شود: `status` آدرس هر مدل را نشان می‌دهد (اولی `http://127.0.0.1:11435/v1` است)، نام دستور پخت مدل است، و کلید در `~/.config/omarchy/agent-local/key` است.

`omarchy agent local remove <recipe>` یک مدل و دانلودهایی را که هیچ مدل دیگری استفاده نمی‌کند حذف می‌کند.

Runtimeهای شخص ثالث با ناشرشان برچسب‌گذاری شده‌اند. Omarchy هر مدل را بدون دسترسی به شبکه اجرا می‌کند.

### LLMهای محلی

Omarchy دو راه برای اجرای مدل‌های LLM محلی توصیه می‌کند: LM Studio و Ollama. LM Studio یک رابط کاربری گرافیکی برای پیدا کردن مدل‌های با وزن باز، نصب آن‌ها، و اجرای آن‌ها فراهم می‌کند. راهی عالی برای شروع آسان است. Ollama یک CLI برای انجام همین کار به طور مشابه ارائه می‌دهد. اما اگر تازه با مدل‌های محلی آشنا شده‌اید، من با LM Studio شروع می‌کردم. هر کدام را می‌توانید زیر _Install > AI_ در منوی Omarchy نصب کنید.

### مهارت Omarchy

مهارت‌های عامل به هوش مصنوعی کمک می‌کنند از ابزارهای خاص به روشی خاص استفاده کند، و Omarchy با یک مهارت پیش‌فرض برای متناسب‌سازی سیستم عرضه می‌شود. مثل دستکاری کانفیگ Hyprland شما، تنظیم نوار، یا حتی ساختن یک تم جدید از صفر. این به دایرکتوری‌های مهارت برای Claude Code (یعنی `~/.claude/skills`)، Codex (یعنی `~/.codex/skills`)، Pi (یعنی `~/.pi/agent/skills`)، Antigravity (یعنی `~/.gemini/config/skills`)، Hermes (یعنی `~/.hermes/skills` و هر `~/.hermes/profiles/*/skills`)، و مکان عمومی `~/.agents/skills` سیم‌لینک شده است، پس بیشتر هارنس‌ها آن را به طور خودکار برمی‌دارند.

اما باید این مهارت را آزمایشی در نظر بگیرید. مدل‌های مختلف آن را با تأثیر متفاوت استفاده خواهند کرد. بهترین کار این است که اول در حالت برنامه‌ریزی اجرا کنید، تا ایده‌ای داشته باشید عامل دوست دارد چه چیزی را تغییر دهد. و سپس آماده باشید تغییرات را برگردانید یا حتی `omarchy reinstall configs` را صدا بزنید، اگر عامل همه چیز را به هم ریخت.
