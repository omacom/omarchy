# هوش مصنوعی

Omarchy راه‌اندازهای عامل‌های کدنویسی زیر را بدون انتخاب یک پیش‌فرض برای شما شامل می‌شود. یک فرمان را اجرا کنید تا CLI آن در نخستین استفاده نصب شود، سپس وقتی از شما خواسته شد احراز هویت کنید. Hermes استثناست: در نخستین استفاده چیزی برای آن نصب نمی‌شود، و انتخاب آن Hermes Desktop را نصب می‌کند، همان‌طور که _Desktop apps_ در ادامه توضیح می‌دهد.

### نصب و به‌روزرسانی عامل‌ها

به‌جز Hermes، این عامل‌ها از نصب تنبل mise استفاده می‌کنند: نخستین اجرا CLI را نصب می‌کند و اجراهای بعدی از همان استفاده می‌کنند. mise همچنین حداکثر هر چهار ساعت یک‌بار، درست پیش از شروع آن یا در پس‌زمینه در یک پرامپت شل، عامل نصب‌شده را برای یک انتشار جدید بررسی می‌کند. اگر آن به‌روزرسانی شکست بخورد یا آفلاین باشید، نسخه نصب‌شده اجرا می‌شود. `omarchy update` عامل‌های نصب‌شده را همراه با بقیه Omarchy به‌روزرسانی می‌کند، و `mup` فقط ابزارهای مدیریت‌شده با mise را به‌روزرسانی می‌کند.

به‌روزرسان خود عامل، مانند `claude update`، `codex update` یا یک دکمه به‌روزرسانی در یک برنامه، نصب مدیریت‌شده با mise را به‌روزرسانی نمی‌کند. `codex update` شکست می‌خورد، و `claude update` می‌تواند موفقیت را گزارش کند در حالی که یک نسخه جداگانه نصب می‌کند که mise آن را ردیابی نمی‌کند. اگر ترجیح می‌دهید از نصب‌کننده و به‌روزرسان بومی یک عامل استفاده کنید، آن را به `disable_tools` اضافه کنید؛ به [ابزارهای CLI از پیش نصب‌شده](18-development-tools.md#preinstalled-cli-tools) مراجعه کنید.

برای نصب همه ابزارهای تنبل پیکربندی‌شده پیش از آن‌که به آن‌ها نیاز پیدا کنید، `mise install --include-lazy` را اجرا کنید. این شامل سایر ابزارهای CLI پیش‌فرض Omarchy و همچنین عامل‌ها می‌شود. برای نصب یک ابزار منفرد یا استفاده از نصب خودتان به [ابزارهای CLI از پیش نصب‌شده](18-development-tools.md#preinstalled-cli-tools) مراجعه کنید.

`grok` از طریق بسته first-party مربوط به mise به نام `grok` نصب می‌شود، به همان شیوه `claude` و `codex`. `grok` را اجرا کنید، یا آن را از مسیر _Setup > Defaults > Agent_ انتخاب کنید. از نصب‌کننده `curl | bash` در x.ai صرف‌نظر کنید. آن مسیر یک نسخه دوم در `~/.grok/bin` قرار می‌دهد، آن را در ابتدای `PATH` می‌گذارد و wrapper مربوط به Omarchy را بازنویسی می‌کند.

`dsh` رابط کاربری مرورگر خود را روی `127.0.0.1:3080` باز می‌کند، و پوشه راه‌اندازی به‌عنوان فضای کاری پیش‌فرض آن است. رابط کاربری مرورگر آن هیچ پرامپت شروعی نمی‌گیرد، بنابراین `omarchy agent prompt` آن را با پرامپت موجود در کلیپ‌بورد شما باز می‌کند تا جای‌گذاری کنید. Omarchy آن را با پیش‌تنظیم مجوز DeepSeek مبنی بر عدم نیاز به تأیید راه می‌اندازد. DeepSeek Harness هنگام استفاده از API رسمی مدل آن، لاگ‌های نشست را برای DeepSeek بارگذاری می‌کند؛ این گزینه را از مسیر _Settings > General > Upload Session Log_ در رابط کاربری مرورگر آن خاموش کنید. بازخوردی که برای آن می‌فرستید نیز همراه نشست بارگذاری می‌شود، مگر این‌که آن را با `DSH_TELEMETRY_MODE=DISABLED` راه بیندازید.

### عامل پیش‌فرض

عامل پیش‌فرض خود را با `omarchy default agent <name>` یا از مسیر _Setup > Defaults > Agent_ در منوی Omarchy (`Super + Space`) انتخاب کنید. اگر عامل هنوز نصب نشده باشد، انتخاب آن ابتدا آن را نصب می‌کند. یک Omarchy تازه با یک اعلان یک‌بارمصرف از شما دعوت می‌کند این انتخاب را انجام دهید.

انتخاب Claude همچنین تلاش می‌کند افزونه مرورگر آن را برای Chromium، Chrome، Brave، Brave Origin و Edge راه بیندازد. راه‌اندازی افزونه برای همه کاربران اعمال می‌شود و ممکن است گذرواژه سیستم شما را بخواهد؛ لغو کردن یا شکست نصب افزونه همچنان Claude را انتخاب و اجرا می‌کند. مرورگر خود را دوباره راه بیندازید، در صورت درخواست افزونه را فعال کنید، و برای تکمیل اتصال آن وارد Claude شوید. برای بررسی اتصال، `/chrome` را در Claude اجرا کنید. Firefox و Zen از این افزونه پشتیبانی نمی‌کنند. اگر Claude پیش از افزوده‌شدن این راه‌اندازی عامل پیش‌فرض شما بوده است، آن را دوباره انتخاب کنید تا افزونه نصب شود.

وقتی انتخاب کردید، `Super + Shift + Ctrl + A` عامل پیش‌فرض را در یک پنجره ترمینال اختصاصی اجرا می‌کند (یا اگر هنوز انتخابی نکرده‌اید، انتخاب‌گر را بالا می‌آورد). همچنین می‌توانید آن را مستقیماً برای انجام یک کار با `omarchy agent prompt "Review this project"` اجرا کنید. Freebuff و DeepSeek Harness هیچ پرامپت شروعی نمی‌گیرند، بنابراین در عوض با پرامپت موجود در کلیپ‌بورد شما باز می‌شوند تا جای‌گذاری کنید. عامل‌هایی که به این شیوه اجرا می‌شوند بدون مراقبت در حالت‌های مربوط به خودشان که برای پرسیدن متوقف نمی‌شوند کار می‌کنند، پس آماده باشید که واقعاً دست به کار شوند! MiniMax Code برای نشست‌های تعاملی خود چنین حالتی ندارد، بنابراین طبق معمول برای مجوزها سؤال می‌کند. و از آن‌جا که عامل‌ها از به‌خاطر سپردن اعتماد برای پوشه خانه شما خودداری می‌کنند، اجراها از `$HOME` در عوض در `~/Work` شروع می‌شوند.

میانبرهای ترمینال هم وجود دارند: `a` عامل پیش‌فرض را به‌صورت درون‌خطی در ترمینال فعلی اجرا می‌کند، در حالی که `c`، `cx` و `cy` به‌ترتیب OpenCode، Claude Code و Codex را مستقیماً شروع می‌کنند (باز هم در حالت‌های تأیید خودکارشان). تغییر تم نیز با عامل‌ها همگام می‌شود: Claude Code، Pi، OpenCode و Hermes (وقتی Omarchy آن را نصب کرده باشد) همگی هنگام جابه‌جایی تم Omarchy همراهی می‌کنند.

### پنل عامل‌ها

نوار بالا یک نماد عامل‌ها دارد. پیش از آن‌که عاملی را راه بیندازید، پنل آن شما را در مراحل ورود به Claude، Codex یا Grok راهنمایی می‌کند، و اولین مورد عامل پیش‌فرض شما می‌شود. پس از آن، پنل همه اشتراک‌ها را در یک صفحه قرار می‌دهد: هر عامل و حساب با طرح آن، یک نوار سنجش برای هر یک از محدودیت‌های نشست 5 ساعته و هفتگی آن همراه با زمان باقی‌مانده تا بازنشانی آن (برای درصد دقیق موشواره را نگه دارید)، یا مانده پیش‌پرداخت‌شده باقی‌مانده، زیر خطی که به‌صورت چرخشی آن‌چه را در همه آن‌ها استفاده کرده‌اید نمایش می‌دهد، مانند توکن‌های این هفته و پرکاربردترین مدل شما. در بخش _Make something_ پرامپت‌های آغازینی برای یک تم، افزونه یا برنامه جدید پیشنهاد می‌کند که کار را به عامل پیش‌فرض شما می‌سپارند. برنامه‌ها به همان شیوه‌ای ساخته می‌شوند که برنامه‌های خود Omarchy یعنی Hype، Monologue و Omacut ساخته شده‌اند، با C++ و Qt Quick، با پیروی از مهارت عامل omarchy-app، و کامپایلر و قطعات Qt مورد نیاز آن‌ها به‌صورت نصب‌شده ارائه می‌شوند. Claude Code، Codex، Grok، Kimi، Cursor و سهمیه Grok Bot آن، GitHub Copilot، Muse، Antigravity، Kimchi و Devin از همان ابتدا با محدودیت‌هایشان پوشش داده می‌شوند، و Hermes، Mistral Vibe و Qwen Code وقتی از آن‌ها استفاده کرده باشید نشست‌ها و توکن‌هایشان را نشان می‌دهند. طرح‌ها و کلیدهای ارائه‌دهندگانی که از طریق pi، omp یا opencode استفاده می‌کنید نیز ظاهر می‌شوند: OpenCode Zen و Go، طرح Z.ai GLM Coding Plan، Ollama Cloud، طرح MiniMax Token Plan و Synthetic با محدودیت‌هایشان؛ Fireworks، OpenRouter و DeepSeek با مانده‌های پیش‌پرداخت‌شده‌شان؛ و مدل‌هایی که روی سخت‌افزار خودتان اجرا می‌کنید در بخش Local models. هر عامل یک بار شمرده می‌شود، زیر مجموعه هر کسی که صورت‌حساب آن را صادر می‌کند، صرف‌نظر از این‌که از چند harness آن را هدایت می‌کنید.

روی نماد نوار چپ‌کلیک کنید تا پنل باز شود، راست‌کلیک کنید تا عامل پیش‌فرض شما اجرا شود. رکوردهای مصرف پشت آن هر 15 دقیقه توسط `omarchy agent usage-update` دوباره تولید می‌شوند، و پنل حتی می‌تواند مصرف ماشین‌های دیگر شما را از طریق یک پوشه همگام‌شده ادغام کند. برای تنظیمات کامل به README در مسیر `$OMARCHY_PATH/shell/plugins/agents/` مراجعه کنید.

### چند اشتراک

اگر برای بیش از یک طرح Claude، Codex یا Grok پول می‌پردازید — مثلاً یک Max شخصی و یک کاری — Omarchy می‌تواند همه آن‌ها را در حالت ورود نگه دارد و میان آن‌ها جابه‌جا شود. یک اشتراک را با + در پنل عامل‌ها اضافه کنید، که همان‌جا شما را در مراحل آن راهنمایی می‌کند، یا با `omarchy agent account add claude Work` (یا `codex` یا `grok`). اگر CLI موجود نباشد آن را نصب می‌کند. اولین حساب برای یک ارائه‌دهنده از طریق مرورگر معمولی شما وارد می‌شود، درست همان‌جایی که CLI همیشه به آن نگاه می‌کند. هر حساب بعد از آن از طریق یک پنجره خصوصی وارد می‌شود، تا حسابی که مرورگر شما از قبل وارد آن شده است به‌اشتباه انتخاب نشود؛ در آن‌جا به‌عنوان حسابی که اضافه می‌کنید وارد شوید، و ابتدا هر پنجره خصوصی‌ای را که از قبل باز دارید ببندید. برای انجام این کار هرگز از CLI خارج نشوید: خروج از سیستم ورود ذخیره‌شده را باطل می‌کند، و آن حساب باید دوباره اضافه شود.

برای کپی‌کردن ورودهای اشتراک خود به یک ماشین Omarchy دیگر از طریق SSH، `omarchy agent account copy user@laptop` را اجرا کنید. فرستنده وقتی مقصد گیرنده‌ای نصب‌شده ندارد یک گیرنده موقت فراهم می‌کند، بنابراین ماشین‌های قدیمی‌تر Omarchy می‌توانند بدون به‌روزرسانی حساب‌ها را دریافت کنند. گیرنده‌های نصب‌شده اولویت دارند. این کار همه اشتراک‌های Claude، Codex و Grok را کپی می‌کند؛ نام ارائه‌دهندگان را اضافه کنید تا آن‌ها را انتخاب کنید، مانند `omarchy agent account copy laptop claude`. نام حساب‌ها و شناسه‌های فرمان با منبع مطابقت دارند، از جمله حساب‌هایی که از قبل در مقصد وجود دارند. حساب‌های نامرتبط مقصد در صورت تداخل نام‌هایشان یک پسوند عددی دریافت می‌کنند، و تنظیمات، مهارت‌ها، افزونه‌ها و سابقه مکالمه در هر ماشین محلی باقی می‌مانند.

اعتبارنامه‌های موجود مقصد حفظ می‌شوند. یک حساب منبع که از قبل در آن‌جا وارد شده است نامش بدون جایگزینی اعتبارنامه‌هایش همگام می‌شود؛ حساب‌های دیگر در کنار آن اضافه می‌شوند. برای جایگزینی اعتبارنامه‌های ذخیره‌شده برای حساب‌های منطبق، پس از بستن نشست‌های آن حساب در مقصد از `omarchy agent account copy --replace laptop claude` استفاده کنید. یک مقصد تازه همچنین حساب فعال و ترجیحات جابه‌جایی منبع را دریافت می‌کند؛ یک مقصد تثبیت‌شده موارد خودش را حفظ می‌کند.

اعتبارنامه‌ها از طریق SSH سفر می‌کنند و در فایل‌های خصوصی در مقصد ذخیره می‌شوند، پس فقط به ماشین‌هایی کپی کنید که به آن‌ها اعتماد دارید. این یک کپی یک‌بارمصرف است، نه همگام‌سازی مداوم. توکن‌های تازه‌سازی Codex می‌توانند توسط ماشین دیگری چرخانده شوند و یک ورود کپی‌شده را نیازمند تمدید کنند؛ ورودهای جداگانه برای استفاده هم‌زمان روی چند ماشین مطمئن‌ترین انتخاب باقی می‌مانند. به [راهنمای احراز هویت حساب Codex](https://developers.openai.com/codex/auth/ci-cd-auth) مراجعه کنید.

برای هر ارائه‌دهنده یک حساب فعال است، و هر نشست جدید با آن شروع می‌شود: `cx`، `cy`، یک `claude`، `codex` یا `grok` ساده، هر چیزی که از طریق `omarchy agent` اجرا شود، و اسکریپت‌ها یا ویرایشگرهایی که CLI را روی `PATH` پیدا می‌کنند. با `omarchy agent account use work` جابه‌جا شوید (و با `omarchy agent account use main` برگردید)، یا در پنل با فشردن شماره یک حساب و سپس `Enter` (یا کلیک روی دکمه Use آن). نشست‌هایی که از قبل در حال اجرا هستند روی حسابی که با آن شروع شده‌اند باقی می‌مانند. سابقه مکالمه، تنظیمات، مهارت‌ها و افزونه‌ها میان حساب‌ها به اشتراک گذاشته می‌شوند، بنابراین `claude --continue` در همان پوشه کار را از همان‌جایی که در حساب جدید رها کرده بودید ادامه می‌دهد.

با بیش از یک حساب، پنل محدودیت‌های هر حساب را کنار هم نشان می‌دهد، و حساب فعال علامت‌گذاری شده است. به‌طور پیش‌فرض Omarchy وقتی حساب فعال از 95% یک محدودیت عبور کند به شما اطلاع می‌دهد، و کلیک روی اعلان به حسابی با بیشترین فضای خالی جابه‌جا می‌شود. موشواره را روی خط یک حساب در پنل نگه دارید و روی Autoswitch که کنار Use ظاهر می‌شود کلیک کنید (یا `m` را فشار دهید)، یا `omarchy agent account mode auto` را اجرا کنید، تا در عوض خودش جابه‌جا شود؛ وقتی روشن است، Autoswitch جای Use را می‌گیرد، و کلیک دوباره روی آن به حالت اطلاع‌رسانی برمی‌گردد. یک عدد اضافه کنید تا آستانه تغییر کند، مانند `omarchy agent account mode auto 90`. اگر همه حساب‌ها از آستانه گذشته باشند، یک بار از آن مطلع می‌شوید، همراه با این‌که کدام حساب زودتر آزاد می‌شود. وقتی یک حساب فعال در فاصله 15 واحدی از آستانه‌اش باشد (80% در حالت پیش‌فرض)، محدودیت‌های آن به‌جای هر 15 دقیقه هر سه دقیقه بررسی می‌شوند.

`omarchy agent account list` همه حساب‌ها و آخرین محدودیت‌های آن‌ها را نشان می‌دهد، `omarchy agent account remove work` یکی را فراموش می‌کند، و `omarchy agent account rename primary Hey` نام یکی را تغییر می‌دهد (یا در پنل روی نام یک حساب کلیک کنید). این فرمان‌ها روی حساب‌های عامل پیش‌فرض شما کار می‌کنند؛ برای رسیدن به ارائه‌دهنده دیگر، ابتدا نام آن را بیاورید، مانند `omarchy agent account use codex side`. ورودی که از قبل در `~/.claude` یا `~/.codex` داشتید حساب _Main_ است و همان‌جا می‌ماند. حسابی که بیش از حدود هشت ساعت استفاده نشده باشد می‌تواند _Sign-in required_ را نشان دهد؛ روی آن کلیک کنید تا همان حساب را درست در پنل دوباره وارد کنید، یا نشستی را در آن شروع کنید، که ورود را خودبه‌خود تازه می‌کند. سرورهای MCP که هنگام اضافه‌شدن یک حساب داشتید همراه آن می‌آیند، اما آن‌هایی که بعداً با `claude mcp add` اضافه می‌کنید فقط به حسابی می‌رسند که آن‌ها را در آن اضافه کرده‌اید. Claude Desktop و ابزارهایی که با یک مسیر مطلق به یک باینری CLI پیکربندی شده‌اند از این جابه‌جایی پیروی نمی‌کنند. یک `CLAUDE_CONFIG_DIR`، `CODEX_HOME` یا `GROK_HOME` صریح بر حساب انتخاب‌شده اولویت دارد.

### تشخیص خرابی

Omarchy برای خرابی‌های فرایند systemd-coredump را زیر نظر می‌گیرد. وقتی چیزی segfault می‌کند، یک اعلان «Process crashed» دریافت می‌کنید — روی آن کلیک کنید، و خرابی همراه با مهارت diagnose-crash مربوط به Omarchy به عامل پیش‌فرض شما سپرده می‌شود، که عامل را در مراحل احراز واقعیت‌ها از روی core dump و تصمیم‌گیری درباره این‌که آیا خرابی ارزش گزارش به بالادست را دارد یا نه راهنمایی می‌کند. همچنین می‌توانید آن را به‌صورت دستی در برابر هر PID از `coredumpctl list` با `omarchy agent crash <pid>` اجرا کنید.

این زیر نظر گرفتن به‌طور پیش‌فرض روشن است. آن را از مسیر _Trigger > Toggle > Crash Capture_ خاموش کنید (یا با `omarchy toggle crash-capture`) تا اعلان‌ها متوقف شوند؛ `omarchy agent crash <pid>` همچنان به‌صورت دستی کار می‌کند.

خرابی‌ها را همچنین می‌توان برای هر برنامه به‌صورت جداگانه بی‌صدا کرد، که همان چیزی است که تشخیص در پایان به شما پیشنهاد می‌کند. `omarchy crash mute hyprland` اعلان‌ها را فقط برای آن برنامه متوقف می‌کند، `omarchy crash mute hyprland off` آن‌ها را برمی‌گرداند، و `omarchy crash mute` به‌تنهایی فهرست می‌کند چه چیزهایی را بی‌صدا کرده‌اید. این فرمان مسیر باینری را به همان راحتی نام آن می‌پذیرد، بنابراین `omarchy crash mute /usr/bin/hyprland` همان کار را می‌کند. نامی را که در آن فاصله وجود دارد در گیومه بگذارید، مانند `omarchy crash mute 'Some App'`. همه چیزهای دیگر همچنان اطلاع‌رسانی می‌کنند، و برنامه بی‌صداشده همچنان خراب می‌شود — این کار یادآور را پنهان می‌کند، چیزی را درست نمی‌کند.

### برنامه‌های دسکتاپ

منوی _Install > AI_ همچنین چند برنامه گرافیکی هوش مصنوعی را در خود دارد: برنامه دسکتاپ ChatGPT، برنامه دسکتاپ Claude (بتای لینوکس Anthropic، با زبانه‌های Chat، Cowork و Claude Code)، Grok Bot برای گفت‌وگو با مدل‌های xAI، Herdr Desktop، Hermes Desktop، OpenClaw، برنامه دسکتاپ Perplexity و T3 Code. Grok Bot برنامه گفت‌وگوی دسکتاپ است. عامل کدنویسی فرمان `grok` است.

Hermes Desktop همان موردی است که باید درباره‌اش بدانید، زیرا یک ماشین یک Hermes دارد، و آن متعلق به برنامه است: Hermes فقط و فقط از طریق برنامه نصب می‌شود، و فرمان `hermes` که عامل پیش‌فرض اجرا می‌کند متعلق به برنامه است. انتخاب Hermes به‌عنوان عامل پیش‌فرض همان چیزی را نصب می‌کند که ورودی _Install > AI_ نصب می‌کند: بسته، و یک زمان‌اجرای Hermes در مسیر `~/.hermes` که توسط نصب‌کننده خود Hermes راه‌اندازی شده است، که نخستین بار چند دقیقه طول می‌کشد. آن زمان‌اجرا همان یک Hermes است که فرمان ترمینال `hermes`، عامل پیش‌فرض و برنامه همگی از آن استفاده می‌کنند، و خود را با `hermes update` به‌روزرسانی می‌کند نه این‌که منتظر یک انتشار Omarchy بماند. نصب آن همچنین تم Omarchy را به‌عنوان یک پوسته با نام `omarchy` به Hermes می‌دهد، که هر سطح Hermes هنگام جابه‌جایی تم‌ها از آن پیروی می‌کند؛ اگر ترجیح می‌دهید این‌طور نباشد، مورد دیگری را از تنظیمات Appearance در Hermes یا با `/skin` انتخاب کنید، و Omarchy آن انتخاب را به حال خود رها می‌کند. حذف برنامه از مسیر _Remove > AI_ ابتدا Hermes را می‌بندد، از جمله gateway آن، آن زمان‌اجرا را با خود می‌برد، و گفت‌وگوها، حافظه‌ها و مهارت‌هایی را که Hermes برای خودش نوشته است حفظ می‌کند مگر این‌که خلاف آن را بگویید: از شما می‌پرسد، با پیش‌فرض نه، که آیا آن داده‌ها و تنظیمات اتصال شما نیز باید بروند یا نه.

تجربه دسکتاپ OpenClaw همان Control UI آن است، که به‌عنوان یک برنامه وب باز می‌شود که توسط gateway محلی خودش پشتیبانی می‌شود. OpenClaw در `~/.openclaw` زندگی می‌کند و خود را به‌روزرسانی می‌کند: از دکمه «Update Gateway» در Control UI استفاده کنید یا `openclaw update` را اجرا کنید، و gateway روی نسخه جدید دوباره راه می‌افتد. Omarchy فقط انتشاری را انتخاب می‌کند که یک نصب تازه با آن شروع می‌شود. حذف OpenClaw از مسیر _Remove > AI_ سرویس gateway و برنامه را با خود می‌برد و سپس می‌پرسد که آیا `~/.openclaw` نیز باید برود یا نه، چون آن‌جا گفت‌وگوها و اعتبارنامه‌های شما را در کنار خود OpenClaw و زمان‌اجراهای افزونه‌ای که دانلود می‌کند نگه می‌دارد؛ پیش‌فرض آن را نگه می‌دارد، و نصب دوباره OpenClaw آن را دوباره برمی‌دارد.

Herdr Desktop برنامه دسکتاپ [Herdr](https://herdr.dev) است: فضاها، زبانه‌ها و قاب‌هایی از ترمینال‌ها و عامل‌های کدنویسی که وقتی پنجره را می‌بندید در هسته آن به کار خود ادامه می‌دهند. این برنامه از نصب‌کننده خود Herdr می‌آید نه از یک بسته، بنابراین در `~/.local/share/herdr-app` زندگی می‌کند، وقتی هنوز هسته‌ای ندارید هسته‌اش را در `~/.local/bin/herdr-core` همراه می‌آورد، و هر دو را خود به‌روزرسانی می‌کند. این برنامه در کنار فرمان `herdr` که Omarchy روی `Super + Ctrl + Return` عرضه می‌کند قرار می‌گیرد نه این‌که جایگزین آن شود. نصب آن تم Omarchy مربوط به Herdr را انتخاب می‌کند، که از آن پس از تم Omarchy شما پیروی می‌کند. Herdr یک تم برای حالت روشن و یکی برای حالت تیره نگه می‌دارد، بنابراین پس از جابه‌جایی میان یک تم تیره و یک تم روشن Omarchy، یک بار دیگر Omarchy را در انتخاب‌گر تم Herdr برای حالت دیگر انتخاب کنید.

T3 Code از انتشار رسمی AppImage خود در `~/.local/share/t3code` اجرا می‌شود نه از یک بسته، بنابراین خود را به‌روزرسانی می‌کند. نصب آن می‌پرسد که آیا روی کانال Stable شروع شود یا Nightly؛ بعداً در تنظیمات T3 Code جابه‌جا شوید. نخ‌ها و تنظیمات شما در `~/.t3` زندگی می‌کنند، و حذف T3 Code از مسیر _Remove > AI_ آن‌ها را با خود می‌برد.

### مدل‌های محلی

یک مدل باز را روی ماشین خودتان برای عامل‌های کدنویسی‌تان اجرا کنید. پرامپت‌ها و کد شما روی ماشین می‌مانند؛ هیچ چیزی که برای مدل فرستاده شود از آن خارج نمی‌شود. با این شروع کنید:

```bash
omarchy agent local use best
```

یا، در پنل عامل‌ها در نوار بالا، + و سپس Local AI را انتخاب کنید، که وقتی مدلی با این ماشین جور باشد ظاهر می‌شود. نخستین بار، این کار Podman را نصب می‌کند، که مدل‌ها را اجرا می‌کند، و روی یک ماشین NVIDIA جعبه‌ابزار کانتینر NVIDIA را نصب می‌کند، که GPU را در اختیار آن‌ها می‌گذارد. سپس Omarchy مدل توصیه‌شده برای این ماشین را انتخاب می‌کند، آن را دانلود می‌کند و راه می‌اندازد. انتظار دانلودی چند ده GB و استفاده از بیشتر حافظه ماشین هنگام اجرای مدل را داشته باشید: Flash Next با بستر کامل 256K خود حدود 100 GiB استفاده می‌کند. اگر مدل‌های دیگر حافظه مورد نیاز آن را در اختیار داشته باشند، این مدل به‌صورت متوقف راه‌اندازی می‌شود، آماده شروع وقتی یکی را متوقف کنید. مدل هنگام خروج از سیستم متوقف می‌شود؛ وقتی برای کار دیگری به حافظه نیاز دارید خودتان آن را متوقف کنید.

`omarchy agent local list` گزینه‌ها را نشان می‌دهد و توضیح می‌دهد چرا بعضی‌ها جور نیستند. برای راه‌اندازی مورد دیگری، `omarchy agent local use <recipe>` را اجرا کنید. امروز، `qwen3.8-flash-next-gufo` و `qwen3.8-27b-gufo` برای ماشین‌های 128 GB Strix Halo در دسترس هستند؛ مدل 27B حدود 40 GiB می‌گیرد، بنابراین برای کارهای دیگر جا می‌گذارد. دستورالعمل‌ها و توصیه‌های جدید با `omarchy update`، از طریق بسته، می‌رسند.

هر مدلی که راه می‌اندازید خط خودش را در پنل عامل‌ها، کنار اشتراک‌هایتان، می‌گیرد: play برای شروع آن، pause برای متوقف‌کردن آن و آزادکردن حافظه‌اش، و دکمه ترمینال برای بازکردن عامل شما روی آن. چند مدل وقتی با هم در حافظه جا شوند می‌توانند هم‌زمان اجرا شوند؛ اگر یکی جا نشود، Omarchy می‌گوید کدام مدل در حال اجرا را متوقف کنید. خط‌ها را بکشید تا دوباره مرتب شوند، و روی یک خط انتخاب‌شده Delete را فشار دهید تا یک مدل و دانلود آن حذف شود.

از خط فرمان، `omarchy agent local start <recipe>` و `omarchy agent local stop <recipe>` همان کار را می‌کنند، `omarchy agent local status` هر مدل را نشان می‌دهد، و `omarchy agent --local` عامل پیش‌فرض شما را روی آخرین مدلی که شروع کرده‌اید باز می‌کند (pi اگر عامل پیش‌فرض شما نتواند از یک مدل محلی استفاده کند). هر کلاینت سازگار با OpenAI نیز می‌تواند متصل شود: `status` نشانی هر مدل را نشان می‌دهد (اولی `http://127.0.0.1:11435/v1` است)، نام دستورالعمل همان مدل است، و کلید در `~/.config/omarchy/agent-local/key` قرار دارد.

`omarchy agent local remove <recipe>` یک مدل و دانلودهایی را که هیچ مدل دیگری استفاده نمی‌کند حذف می‌کند.

زمان‌اجراهای شخص ثالث با ناشرشان برچسب‌گذاری می‌شوند. Omarchy هر مدل را بدون دسترسی به شبکه اجرا می‌کند.

### LLMهای محلی

Omarchy دو راه برای اجرای مدل‌های LLM محلی توصیه می‌کند: LM Studio و Ollama. LM Studio یک رابط کاربری گرافیکی برای یافتن مدل‌های با وزن باز، نصب آن‌ها و اجرای آن‌ها فراهم می‌کند. این راهی عالی برای شروع آسان است. Ollama یک CLI برای انجام همین کار به شیوه‌ای مشابه ارائه می‌کند. اما اگر در مدل‌های محلی تازه‌کار هستید، من با LM Studio شروع می‌کنم. می‌توانید هر یک را از مسیر _Install > AI_ در منوی Omarchy نصب کنید.

### مهارت Omarchy

مهارت‌های عامل به هوش مصنوعی کمک می‌کنند از ابزارهای خاص به شیوه‌ای خاص استفاده کند، و Omarchy با یک مهارت پیش‌فرض برای سفارشی‌سازی سیستم عرضه می‌شود. مانند دست‌کاری پیکربندی Hyprland، تنظیم نوار، یا حتی ساختن یک تم جدید از صفر. این مهارت به‌صورت symlink در پوشه‌های مهارت Claude Code (`~/.claude/skills`)، Codex (`~/.codex/skills`)، Pi (`~/.pi/agent/skills`)، Antigravity (`~/.gemini/config/skills`)، Hermes (`~/.hermes/skills` و هر `~/.hermes/profiles/*/skills`)، و مکان عمومی `~/.agents/skills` قرار گرفته است، بنابراین بیشتر harnessها آن را به‌طور خودکار برمی‌دارند.

اما باید این مهارت را آزمایشی در نظر بگیرید. مدل‌های مختلف از آن به شکل‌های متفاوتی استفاده خواهند کرد. بهتر است ابتدا در حالت برنامه‌ریزی اجرا کنید، تا ایده‌ای از آن‌چه عامل می‌خواهد تغییر دهد داشته باشید. و سپس آماده باشید تغییرات را برگردانید یا حتی `omarchy reinstall configs` را فراخوانی کنید، اگر عامل همه چیز را به هم ریخت.
