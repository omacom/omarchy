# هوش مصنوعی

Omarchy راه‌اندازهایی برای ایجنت‌های کدنویسی زیر دربر دارد، بدون اینکه به‌جای شما پیش‌فرضی انتخاب کند. یک فرمان را اجرا کنید تا CLI آن در اولین استفاده نصب شود، سپس وقتی از شما خواسته شد احراز هویت کنید. Hermes استثناست: در اولین استفاده هیچ چیزی برای آن نصب نمی‌شود و انتخاب آن Hermes Desktop را نصب می‌کند، همان‌طور که _Desktop apps_ در زیر توضیح می‌دهد.

### نصب و به‌روزرسانی ایجنت‌ها

به‌جز Hermes، این ایجنت‌ها از نصب تنبل mise استفاده می‌کنند: اولین اجرا CLI را نصب می‌کند و اجراهای بعدی از آن دوباره استفاده می‌کنند. mise همچنین حداکثر هر چهار ساعت یک بار، درست پیش از شروع یا در پس‌زمینه هنگام نمایش پرامپت شل، ایجنت نصب‌شده را برای یافتن نسخه‌ای جدید بررسی می‌کند. اگر آن به‌روزرسانی ناموفق باشد یا آفلاین باشید، نسخه‌ی نصب‌شده اجرا می‌شود. `omarchy update` ایجنت‌های نصب‌شده را همراه با بقیه‌ی Omarchy به‌روزرسانی می‌کند و `mup` فقط ابزارهای مدیریت‌شده با mise را به‌روزرسانی می‌کند.

به‌روزرسان خود ایجنت، مانند `claude update`، `codex update` یا دکمه‌ی به‌روزرسانی در یک برنامه، نصب مدیریت‌شده با mise را به‌روزرسانی نمی‌کند. `codex update` ناموفق است و `claude update` ممکن است موفقیت را گزارش کند درحالی‌که نسخه‌ی جداگانه‌ای نصب می‌کند که mise آن را ردیابی نمی‌کند. اگر ترجیح می‌دهید از نصب‌کننده و به‌روزرسان بومی یک ایجنت استفاده کنید، آن را به `disable_tools` اضافه کنید؛ [ابزارهای CLI از پیش نصب‌شده](18-development-tools.md#preinstalled-cli-tools) را ببینید.

برای اینکه همه‌ی ابزارهای تنبل پیکربندی‌شده را پیش از نیازتان نصب کنید، `mise install --include-lazy` را اجرا کنید. این کار هم ابزارهای CLI پیش‌فرض دیگر Omarchy و هم ایجنت‌ها را دربر می‌گیرد. برای نصب یک ابزار منفرد یا استفاده از نصب خودتان، [ابزارهای CLI از پیش نصب‌شده](18-development-tools.md#preinstalled-cli-tools) را ببینید.

`grok` از طریق بسته‌ی درجه‌یک `grok` در mise نصب می‌شود، به همان شیوه‌ی `claude` و `codex`. `grok` را اجرا کنید یا آن را از _Setup > Defaults > Agent_ انتخاب کنید. نصب‌کننده‌ی `curl | bash` در x.ai را رد کنید. آن مسیر نسخه‌ی دومی را در `~/.grok/bin` می‌گذارد، آن را در ابتدای `PATH` قرار می‌دهد و پوشش Omarchy را بازنویسی می‌کند.

`dsh` رابط کاربری مرورگر خود را روی `127.0.0.1:3080` باز می‌کند و دایرکتوری اجرا، فضای کاری پیش‌فرض آن است. رابط کاربری مرورگر آن پرامپت آغازینی نمی‌گیرد، پس `omarchy agent prompt` آن را باز می‌کند درحالی‌که پرامپت روی کلیپ‌بورد شماست تا پیست کنید. Omarchy آن را با پیش‌تنظیم مجوز بدون تأیید DeepSeek راه می‌اندازد. DeepSeek Harness وقتی از API رسمی مدل آن استفاده می‌کنید، لاگ‌های نشست را برای DeepSeek آپلود می‌کند؛ این کار را در رابط کاربری مرورگر آن از _Settings > General > Upload Session Log_ خاموش کنید. بازخوردی که برای آن می‌فرستید هم همراه نشست آپلود می‌شود، مگر اینکه آن را با `DSH_TELEMETRY_MODE=DISABLED` راه بیندازید.

### ایجنت پیش‌فرض

ایجنت پیش‌فرض خود را با `omarchy default agent <name>` یا از _Setup > Defaults > Agent_ در منوی Omarchy (`Super + Space`) انتخاب کنید. اگر ایجنت هنوز نصب نشده باشد، انتخاب آن ابتدا آن را نصب می‌کند. یک Omarchy تازه با یک اعلان یک‌باره از شما دعوت می‌کند این انتخاب را انجام دهید.

انتخاب Claude همچنین تلاش می‌کند افزونه‌ی مرورگر آن را برای Chromium، Chrome، Brave، Brave Origin و Edge راه بیندازد. راه‌اندازی افزونه برای همه‌ی کاربران اعمال می‌شود و ممکن است رمز عبور سیستم شما را بخواهد؛ لغو کردن یا ناموفق بودن نصب افزونه همچنان Claude را انتخاب و راه‌اندازی می‌کند. مرورگر خود را ری‌استارت کنید، اگر از شما خواسته شد افزونه را فعال کنید و برای تکمیل اتصال آن وارد Claude شوید. برای بررسی اتصال، `/chrome` را در Claude اجرا کنید. Firefox و Zen از این افزونه پشتیبانی نمی‌کنند. اگر Claude پیش از افزوده‌شدن این راه‌اندازی از قبل پیش‌فرض شما بود، برای نصب افزونه آن را دوباره انتخاب کنید.

وقتی انتخاب کردید، `Super + Shift + Ctrl + A` ایجنت پیش‌فرض را در یک پنجره‌ی ترمینال اختصاصی راه می‌اندازد (یا اگر هنوز انتخابی نکرده باشید، انتخاب‌گر را بالا می‌آورد). همچنین می‌توانید آن را مستقیم با یک وظیفه راه بیندازید: `omarchy agent prompt "Review this project"`. Freebuff و DeepSeek Harness پرامپت آغازینی نمی‌گیرند، پس در عوض با پرامپت روی کلیپ‌بورد شما باز می‌شوند تا پیست کنید. ایجنت‌هایی که این‌گونه راه می‌افتند بدون مراقبت و در حالت‌های مربوطه‌ی «برای پرسیدن متوقف نشو» خود اجرا می‌شوند، پس آماده باشید که واقعاً کارهایی انجام دهند! MiniMax Code برای نشست‌های تعاملی خود چنین حالتی ندارد، پس طبق معمول مجوز می‌خواهد. و چون ایجنت‌ها از به‌خاطر سپردن اعتماد برای دایرکتوری خانه‌ی شما خودداری می‌کنند، اجراها از `$HOME` در عوض در `~/Work` شروع می‌شوند.

میانبرهای ترمینال هم وجود دارد: `a` ایجنت پیش‌فرض را به‌صورت درون‌خطی در ترمینال فعلی اجرا می‌کند، درحالی‌که `c`، `cx` و `cy` OpenCode، Claude Code و Codex را مستقیم راه می‌اندازند (باز هم در حالت‌های تأیید خودکار خود). تغییرهای تم هم با ایجنت‌ها همگام می‌شوند: Claude Code، Pi، OpenCode و Hermes (وقتی Omarchy آن را نصب کرده باشد) همگی وقتی تم Omarchy را عوض می‌کنید همراهی می‌کنند.

### پنل ایجنت‌ها

نوار بالا یک آیکون ایجنت‌ها دارد. پیش از آنکه ایجنتی را راه بیندازید، پنل آن شما را در ورود به Claude، Codex یا Grok راهنمایی می‌کند و اولین مورد، ایجنت پیش‌فرض شما می‌شود. پس از آن، پنل هر اشتراک را روی یک صفحه می‌گذارد: هر ایجنت و حساب با طرح آن، یک سنجش برای هر یک از محدودیت‌های نشست ۵ ساعته و هفتگی آن همراه با زمان باقی‌مانده تا ریست‌شدنش (برای درصد دقیق روی آن نگه دارید)، یا موجودی پیش‌پرداخت باقی‌مانده، زیر خطی که در میان آنچه در همه‌ی آن‌ها استفاده کرده‌اید می‌چرخد، مانند توکن‌های این هفته و پرکاربردترین مدل شما. زیر _Make something_ پرامپت‌های آغازی برای یک تم، افزونه یا برنامه‌ی جدید پیشنهاد می‌کند که وظیفه را به ایجنت پیش‌فرض شما می‌سپارند. برنامه‌ها به همان شیوه‌ای ساخته می‌شوند که برنامه‌های خود Omarchy یعنی Hype، Monologue و Omacut ساخته شده‌اند، با C++ و Qt Quick و با دنبال‌کردن مهارت ایجنت omarchy-app، و کامپایلر و قطعات Qt مورد نیازشان نصب‌شده ارائه می‌شوند. Claude Code، Codex، Grok، Kimi، Cursor و سهمیه‌ی Grok Bot آن، GitHub Copilot، Muse، Antigravity، Kimchi و Devin با محدودیت‌هایشان بی‌درنگ پوشش داده می‌شوند و Hermes، Mistral Vibe و Qwen Code وقتی از آن‌ها استفاده کرده باشید، نشست‌ها و توکن‌هایشان را نشان می‌دهند. طرح‌ها و کلیدهای ارائه‌دهندگانی که از طریق pi، omp یا opencode استفاده می‌کنید هم ظاهر می‌شوند: OpenCode Zen و Go، Z.ai GLM Coding Plan، Ollama Cloud، MiniMax Token Plan و Synthetic با محدودیت‌هایشان؛ Fireworks، OpenRouter و DeepSeek با موجودی‌های پیش‌پرداختشان؛ و مدل‌هایی که روی سخت‌افزار خودتان اجرا می‌کنید زیر Local models. هر ایجنت یک بار شمرده می‌شود، زیر نام هر کسی که صورت‌حسابش را صادر می‌کند، هرقدر هم که آن را از چارچوب‌های مختلف برانید.

برای پنل روی آیکون نوار چپ‌کلیک کنید و برای راه‌انداختن ایجنت پیش‌فرض خود راست‌کلیک کنید. رکوردهای استفاده‌ی پشت آن هر ۱۵ دقیقه با `omarchy agent usage-update` بازتولید می‌شوند و پنل حتی می‌تواند استفاده را از ماشین‌های دیگر شما از طریق یک پوشه‌ی همگام‌شده ادغام کند. برای تنظیمات کامل، README زیر `$OMARCHY_PATH/shell/plugins/agents/` را ببینید.

### چند اشتراک

اگر برای بیش از یک طرح Claude، Codex یا Grok پول می‌دهید — مثلاً یک Max شخصی و یک کاری — Omarchy می‌تواند همه‌ی آن‌ها را وارد نگه دارد و میانشان جابه‌جا شود. یک اشتراک را با + در پنل ایجنت‌ها اضافه کنید، که همان‌جا شما را در این کار راهنمایی می‌کند، یا با `omarchy agent account add claude Work` (یا `codex` یا `grok`). اگر CLI موجود نباشد آن را نصب می‌کند. اولین حساب برای یک ارائه‌دهنده از طریق مرورگر معمولی شما وارد می‌شود، درست همان‌جایی که CLI همیشه نگاه می‌کند. هر حساب پس از آن از طریق یک پنجره‌ی خصوصی وارد می‌شود تا حسابی که مرورگر شما از قبل با آن وارد شده به‌اشتباه انتخاب نشود؛ آنجا به‌عنوان حسابی که اضافه می‌کنید وارد شوید و اول هر پنجره‌ی خصوصی‌ای که از قبل باز داشته‌اید ببندید. هرگز برای این کار از CLI خارج نشوید: خروج، ورود ذخیره‌شده را باطل می‌کند و آن حساب باید دوباره اضافه شود.

برای کپی‌کردن ورودهای اشتراک خود به یک ماشین Omarchy دیگر روی SSH، `omarchy agent account copy user@laptop` را اجرا کنید. وقتی مقصد گیرنده‌ی نصب‌شده‌ای ندارد، فرستنده یک گیرنده‌ی موقت فراهم می‌کند، پس ماشین‌های قدیمی‌تر Omarchy می‌توانند بدون به‌روزرسانی حساب‌ها را دریافت کنند. گیرنده‌های نصب‌شده اولویت دارند. این کار همه‌ی اشتراک‌های Claude، Codex و Grok را کپی می‌کند؛ برای انتخاب آن‌ها نام ارائه‌دهنده‌ها را اضافه کنید، مانند `omarchy agent account copy laptop claude`. نام حساب‌ها و شناسه‌های فرمان با مبدأ مطابقت دارند، از جمله حساب‌هایی که از قبل در مقصد حاضرند. حساب‌های نامرتبط مقصد اگر نامشان تعارض داشته باشد پسوند عددی می‌گیرند و تنظیمات، مهارت‌ها، افزونه‌ها و تاریخچه‌ی مکالمه برای هر ماشین محلی می‌مانند.

اعتبارنامه‌های موجود مقصد نگه داشته می‌شوند. حسابی از مبدأ که از قبل آنجا وارد شده باشد، نامش بدون جایگزین‌کردن اعتبارنامه‌هایش همگام می‌شود؛ حساب‌های دیگر در کنار آن اضافه می‌شوند. برای جایگزین‌کردن اعتبارنامه‌های ذخیره‌شده برای حساب‌های مطابق، پس از بستن نشست‌های آن حساب در مقصد از `omarchy agent account copy --replace laptop claude` استفاده کنید. یک مقصد تازه همچنین حساب فعال و ترجیحات جابه‌جایی مبدأ را می‌گیرد؛ یک مقصد جاافتاده مال خودش را نگه می‌دارد.

اعتبارنامه‌ها از طریق SSH سفر می‌کنند و در فایل‌های خصوصی روی مقصد ذخیره می‌شوند، پس فقط به ماشین‌هایی کپی کنید که به آن‌ها اعتماد دارید. این یک کپی یک‌باره است، نه همگام‌سازی مداوم. توکن‌های بازخوانی Codex ممکن است توسط ماشین دیگری چرخانده شوند و یک ورود کپی‌شده را نیازمند تمدید بگذارند؛ ورودهای جداگانه همچنان مطمئن‌ترین انتخاب برای استفاده‌ی هم‌زمان روی چند ماشین هستند. [راهنمای احراز هویت حساب Codex](https://developers.openai.com/codex/auth/ci-cd-auth) را ببینید.

برای هر ارائه‌دهنده یک حساب فعال است و هر نشست جدید با آن شروع می‌شود: `cx`، `cy`، یک `claude`، `codex` یا `grok` ساده، هر چیزی که از طریق `omarchy agent` راه بیفتد و اسکریپت‌ها یا ویرایشگرهایی که CLI را روی `PATH` پیدا می‌کنند. با `omarchy agent account use work` جابه‌جا شوید (و با `omarchy agent account use main` برگردید)، یا در پنل با فشردن شماره‌ی یک حساب و سپس `Enter` (یا کلیک‌کردن روی دکمه‌ی Use آن). نشست‌هایی که از قبل در حال اجرا هستند روی حسابی که با آن شروع شده‌اند می‌مانند. تاریخچه‌ی مکالمه، تنظیمات، مهارت‌ها و افزونه‌ها میان حساب‌ها به‌اشتراک گذاشته می‌شوند، پس `claude --continue` در همان پوشه روی حساب جدید از همان‌جایی که مانده بودید ادامه می‌دهد.

با بیش از یک حساب، پنل محدودیت‌های هر حساب را کنار هم نشان می‌دهد و حساب فعال را علامت می‌زند. به‌طور پیش‌فرض Omarchy وقتی حساب فعال از ۹۵٪ یک محدودیت می‌گذرد به شما اعلان می‌دهد و کلیک‌کردن روی اعلان به حسابی با بیشترین فضای خالی جابه‌جا می‌شود. روی خط یک حساب در پنل نگه دارید و روی Autoswitch که کنار Use ظاهر می‌شود کلیک کنید (یا `m` را فشار دهید)، یا `omarchy agent account mode auto` را اجرا کنید تا به‌جای آن خودش جابه‌جا شود؛ وقتی روشن است، Autoswitch جای Use را می‌گیرد و کلیک دوباره روی آن به اعلان‌دادن برمی‌گردد. برای تغییر آستانه عددی اضافه کنید، مانند `omarchy agent account mode auto 90`. اگر هر حسابی بالای آستانه باشد، یک بار از آن باخبر می‌شوید، همراه با اینکه کدام حساب اول آزاد می‌شود. وقتی یک حساب فعال در فاصله‌ی ۱۵ واحدی از آستانه‌ی خود باشد (۸۰٪ در حالت پیش‌فرض)، محدودیت‌هایش هر سه دقیقه بررسی می‌شوند نه هر ۱۵ دقیقه.

`omarchy agent account list` هر حساب و آخرین محدودیت‌هایش را نشان می‌دهد، `omarchy agent account remove work` یکی را فراموش می‌کند و `omarchy agent account rename primary Hey` نام یکی را عوض می‌کند (یا روی نام یک حساب در پنل کلیک کنید). این فرمان‌ها روی حساب‌های ایجنت پیش‌فرض شما کار می‌کنند؛ برای رسیدن به ارائه‌دهنده‌ی دیگر، اول نام آن را بیاورید، مانند `omarchy agent account use codex side`. ورودی که از قبل در `~/.claude` یا `~/.codex` داشته‌اید حساب _Main_ است و همان‌جا که هست می‌ماند. حسابی که بیش از حدود هشت ساعت بلااستفاده مانده باشد ممکن است _Sign-in required_ نشان دهد؛ برای اینکه آن حساب را درست در پنل دوباره وارد کنید روی آن کلیک کنید، یا نشستی در آن شروع کنید، که ورود را خودش تازه می‌کند. سرورهای MCP که هنگام اضافه‌شدن یک حساب داشته‌اید همراه آن می‌آیند، اما آن‌هایی که بعداً با `claude mcp add` اضافه می‌کنید فقط به حسابی می‌رسند که آن‌ها را در آن اضافه کرده‌اید. Claude Desktop و ابزارهایی که با مسیر مطلق به یک باینری CLI پیکربندی شده‌اند از جابه‌جایی پیروی نمی‌کنند. یک `CLAUDE_CONFIG_DIR`، `CODEX_HOME` یا `GROK_HOME` صریح بر حساب انتخاب‌شده اولویت دارد.

### تشخیص خرابی

Omarchy برای خرابی‌های فرایند، systemd-coredump را زیر نظر دارد. وقتی چیزی سگفالت می‌کند، یک اعلان «Process crashed» می‌گیرید — روی آن کلیک کنید و خرابی همراه با مهارت diagnose-crash در Omarchy به ایجنت پیش‌فرض شما سپرده می‌شود؛ این مهارت ایجنت را در اثبات واقعیت‌ها از روی core dump و تصمیم‌گیری درباره‌ی اینکه آیا خرابی ارزش گزارش‌دادن به بالادست را دارد راهنمایی می‌کند. همچنین می‌توانید آن را دستی در برابر هر PID از `coredumpctl list` با `omarchy agent crash <pid>` اجرا کنید.

این زیر نظر داشتن به‌طور پیش‌فرض روشن است. آن را از _Trigger > Toggle > Crash Capture_ خاموش کنید (یا با `omarchy toggle crash-capture`) و اعلان‌ها متوقف می‌شوند؛ `omarchy agent crash <pid>` همچنان دستی کار می‌کند.

خرابی‌ها را همچنین می‌توان هر بار یک برنامه ساکت کرد، که همان چیزی است که تشخیص در پایان به شما پیشنهاد می‌کند. `omarchy crash mute hyprland` اعلان‌ها را فقط برای آن برنامه متوقف می‌کند، `omarchy crash mute hyprland off` آن‌ها را برمی‌گرداند و `omarchy crash mute` به‌تنهایی فهرست می‌کند چه چیزی را ساکت کرده‌اید. مسیر باینری را به همان خوشی نامش می‌گیرد، پس `omarchy crash mute /usr/bin/hyprland` همان کار را می‌کند. نامی را که در آن فاصله هست در نقل‌قول بگذارید، مانند `omarchy crash mute 'Some App'`. هر چیز دیگری همچنان اعلان می‌دهد و برنامه‌ی ساکت‌شده همچنان خراب می‌شود — این کار یادآور را پنهان می‌کند، چیزی را درست نمی‌کند.

### برنامه‌های دسکتاپ

منوی _Install > AI_ چند برنامه‌ی گرافیکی هوش مصنوعی هم دارد: برنامه‌ی دسکتاپ ChatGPT، برنامه‌ی دسکتاپ Claude (بتای Linux شرکت Anthropic، با زبانه‌های Chat، Cowork و Claude Code)، Grok Bot برای گپ‌زدن با مدل‌های xAI، Herdr Desktop، Hermes Desktop، OpenClaw، برنامه‌ی دسکتاپ Perplexity و T3 Code. Grok Bot برنامه‌ی گپ دسکتاپ است. ایجنت کدنویسی فرمان `grok` است.

Hermes Desktop همان موردی است که باید درباره‌اش بدانید، چون یک ماشین یک Hermes دارد و آن مال برنامه است: Hermes فقط و فقط از طریق برنامه نصب می‌شود و فرمان `hermes` که ایجنت پیش‌فرض اجرا می‌کند مال برنامه است. انتخاب Hermes به‌عنوان ایجنت پیش‌فرض همان چیزی را نصب می‌کند که مدخل _Install > AI_ نصب می‌کند: بسته و یک زمان‌اجرای Hermes زیر `~/.hermes` که نصب‌کننده‌ی خود Hermes آن را راه می‌اندازد و بار اول چند دقیقه طول می‌کشد. آن زمان‌اجرا همان یک Hermes است که فرمان `hermes` در ترمینال، ایجنت پیش‌فرض و برنامه همگی از آن استفاده می‌کنند و خودش را با `hermes update` به‌روزرسانی می‌کند نه اینکه منتظر یک انتشار Omarchy بماند. نصب آن همچنین تم Omarchy را به‌عنوان پوسته‌ای با نام `omarchy` به Hermes می‌دهد که هر سطح Hermes وقتی تم‌ها را عوض می‌کنید از آن پیروی می‌کند؛ اگر ترجیح می‌دهید این‌طور نباشد، مورد دیگری را از تنظیمات Appearance در Hermes یا با `/skin` انتخاب کنید و Omarchy آن انتخاب را به حال خود می‌گذارد. حذف برنامه از _Remove > AI_ اول Hermes را می‌بندد، از جمله درگاه آن را، آن زمان‌اجرا را با خود می‌برد و گپ‌ها، خاطرات و مهارت‌هایی را که Hermes برای خودش نوشته نگه می‌دارد مگر اینکه خلافش را بگویید: می‌پرسد، با پیش‌فرض نه، که آیا آن داده‌ها و تنظیمات اتصال شما هم باید بروند یا نه.

تجربه‌ی دسکتاپ OpenClaw همان Control UI آن است، که به‌صورت یک برنامه‌ی وب باز می‌شود و یک درگاه محلی خودش پشت آن است. OpenClaw در `~/.openclaw` زندگی می‌کند و خودش را به‌روزرسانی می‌کند: از دکمه‌ی «Update Gateway» در Control UI استفاده کنید یا `openclaw update` را اجرا کنید و درگاه روی نسخه‌ی جدید ری‌استارت می‌شود. Omarchy فقط انتشاری را انتخاب می‌کند که یک نصب تازه با آن شروع می‌شود. حذف OpenClaw از _Remove > AI_ سرویس درگاه و برنامه را با خود می‌برد و سپس می‌پرسد آیا `~/.openclaw` هم باید برود یا نه، چون آنجا گپ‌ها و اعتبارنامه‌های شما را در کنار خود OpenClaw و زمان‌اجراهای افزونه‌ای که دانلود می‌کند نگه می‌دارد؛ پیش‌فرض آن را نگه می‌دارد و نصب دوباره‌ی OpenClaw آن را دوباره برمی‌دارد.

Herdr Desktop برنامه‌ی دسکتاپ [Herdr](https://herdr.dev) است: فضاها، زبانه‌ها و پن‌هایی از ترمینال‌ها و ایجنت‌های کدنویسی که وقتی پنجره را می‌بندید در هسته‌ی آن در حال اجرا می‌مانند. از نصب‌کننده‌ی خود Herdr می‌آید نه از یک بسته، پس در `~/.local/share/herdr-app` زندگی می‌کند، وقتی هنوز هسته‌ای ندارید هسته‌اش را در `~/.local/bin/herdr-core` همراه می‌آورد و هر دو را خودش به‌روزرسانی می‌کند. کنار فرمان `herdr` می‌نشیند که Omarchy روی `Super + Ctrl + Return` ارائه می‌کند نه اینکه جای آن را بگیرد، و کلیدهای مستقیم آن فرمان را می‌گیرد: `Alt + Return` و `Alt + Shift + Return` یک پن را به پایین یا راست تقسیم می‌کنند، `Alt + Escape` آن را می‌بندد، `Ctrl + Alt + Arrow` میان پن‌ها جابه‌جا می‌شود، `Alt + 1..9` و `Alt + Left/Right` یک زبانه انتخاب می‌کنند و `Alt + Up/Down` میان فضاها جابه‌جا می‌شود. `Ctrl + 1..9` یک فضا انتخاب می‌کند و `Alt + Shift + Up/Down` میان ایجنت‌ها گام برمی‌دارد. کلیدهای پیشوند `Ctrl + Space` فقط برای ترمینال می‌مانند، چون برنامه نمی‌تواند یک کلید Ctrl ساده را برای یک دنباله نگه دارد. Omarchy این‌ها را در `~/.config/herdr-app/keys.json` می‌نویسد و `omarchy-refresh-herdr-app` آن‌ها را برمی‌گرداند. نصب آن تم Omarchy در Herdr را انتخاب می‌کند که از آن پس از تم Omarchy شما پیروی می‌کند. Herdr یک تم برای حالت روشن و یکی برای حالت تیره نگه می‌دارد، پس پس از جابه‌جایی میان یک تم تیره و یک تم روشن Omarchy، برای حالت دیگر یک بار دیگر Omarchy را در انتخاب‌گر تم Herdr انتخاب کنید.

T3 Code از انتشار رسمی AppImage خود در `~/.local/share/t3code` اجرا می‌شود نه از یک بسته، پس خودش را به‌روزرسانی می‌کند. نصب آن می‌پرسد روی کانال Stable شروع کنید یا Nightly؛ بعداً در تنظیمات T3 Code جابه‌جا شوید. رشته‌ها و تنظیمات شما در `~/.t3` زندگی می‌کنند و حذف T3 Code از _Remove > AI_ آن‌ها را با خود می‌برد.

### مدل‌های محلی

یک مدل باز را روی ماشین خودتان برای ایجنت‌های کدنویسی‌تان اجرا کنید. پرامپت‌ها و کد شما روی ماشین می‌مانند؛ هیچ چیزی که برای مدل فرستاده شود آن را ترک نمی‌کند. با این شروع کنید:

```bash
omarchy agent local use best
```

یا در پنل ایجنت‌ها در نوار بالا، + و سپس Local AI را انتخاب کنید، که وقتی مدلی برازنده‌ی این ماشین باشد ظاهر می‌شود. بار اول، این کار Podman را نصب می‌کند که مدل‌ها را اجرا می‌کند و روی یک ماشین NVIDIA، جعبه‌ابزار کانتینر NVIDIA را نصب می‌کند که GPU را به آن‌ها می‌دهد. سپس Omarchy مدل توصیه‌شده برای این ماشین را انتخاب می‌کند، آن را دانلود می‌کند و راه می‌اندازد. انتظار دانلودی چند ده GB و درگیر بودن بیشتر حافظه‌ی ماشین را وقتی مدل اجرا می‌شود داشته باشید: Flash Next با بستر کامل 256K خود حدود 100 GiB استفاده می‌کند. اگر مدل‌های دیگری حافظه‌ی مورد نیاز آن را گرفته باشند، متوقف راه‌اندازی می‌شود و آماده است وقتی یکی را متوقف کردید شروع شود. مدل هنگام خروج متوقف می‌شود؛ وقتی برای کار دیگری به حافظه نیاز دارید خودتان آن را متوقف کنید.

`omarchy agent local list` گزینه‌ها را نشان می‌دهد و توضیح می‌دهد چرا بعضی برازنده نیستند. برای راه‌انداختن مورد دیگری، `omarchy agent local use <recipe>` را اجرا کنید. امروز `qwen3.8-flash-next-gufo` و `qwen3.8-27b-gufo` برای ماشین‌های Strix Halo با 128 GB در دسترس‌اند؛ مدل 27B حدود 40 GiB می‌گیرد، پس برای کارهای دیگر جا می‌گذارد. دستورها و توصیه‌های جدید با `omarchy update` و از طریق بسته می‌رسند.

هر مدلی که راه بیندازید خط خودش را در پنل ایجنت‌ها، کنار اشتراک‌های شما، می‌گیرد: پخش برای راه‌انداختن آن، مکث برای متوقف‌کردنش و آزادکردن حافظه‌اش و دکمه‌ی ترمینال برای بازکردن ایجنت شما روی آن. چند مدل وقتی با هم در حافظه جا شوند می‌توانند هم‌زمان اجرا شوند؛ اگر یکی جا نشود، Omarchy می‌گوید کدام مدل در حال اجرا را متوقف کنید. خط‌ها را برای مرتب‌کردن دوباره بکشید و روی یک خط انتخاب‌شده Delete را فشار دهید تا یک مدل و دانلود آن حذف شود.

از خط فرمان، `omarchy agent local start <recipe>` و `omarchy agent local stop <recipe>` همان کار را می‌کنند، `omarchy agent local status` هر مدل را نشان می‌دهد و `omarchy agent --local` ایجنت پیش‌فرض شما را روی آخرین مدلی که راه انداخته‌اید باز می‌کند (اگر ایجنت پیش‌فرض شما نتواند از یک مدل محلی استفاده کند، pi). هر کلاینت سازگار با OpenAI هم می‌تواند متصل شود: `status` نشانی هر مدل را نشان می‌دهد (اولی `http://127.0.0.1:11435/v1` است)، نام دستور همان مدل است و کلید در `~/.config/omarchy/agent-local/key` است.

`omarchy agent local remove <recipe>` یک مدل و دانلودهایی را که هیچ مدل دیگری استفاده نمی‌کند حذف می‌کند.

زمان‌اجراهای طرف سوم با ناشرشان برچسب خورده‌اند. Omarchy هر مدل را بدون دسترسی به شبکه اجرا می‌کند.

### LLMهای محلی

Omarchy دو شیوه برای اجرای مدل‌های LLM محلی توصیه می‌کند: LM Studio و Ollama. LM Studio یک واسط GUI برای یافتن مدل‌های با وزن باز، نصب آن‌ها و اجرایشان فراهم می‌کند. راهی عالی برای شروع آسان است. Ollama یک CLI برای انجام مشابه همین کار پیشنهاد می‌کند. اما اگر در مدل‌های محلی تازه‌کارید، من با LM Studio شروع می‌کردم. هرکدام را می‌توانید از _Install > AI_ در منوی Omarchy نصب کنید.

### مهارت Omarchy

مهارت‌های ایجنت به هوش مصنوعی کمک می‌کنند از ابزارهای خاص به شیوه‌ای خاص استفاده کند و Omarchy با یک مهارت پیش‌فرض برای سفارشی‌کردن سیستم ارائه می‌شود. مانند دستکاری کانفیگ Hyprland، تنظیم نوار یا حتی ساختن یک تم از صفر. این مهارت به دایرکتوری‌های مهارت برای Claude Code (`~/.claude/skills`)، Codex (`~/.codex/skills`)، Pi (`~/.pi/agent/skills`)، Antigravity (`~/.gemini/config/skills`)، Hermes (`~/.hermes/skills` و هر `~/.hermes/profiles/*/skills`) و مکان عمومی `~/.agents/skills` سیم‌لینک شده است، پس بیشتر چارچوب‌ها آن را خودکار برمی‌دارند.

اما باید با این مهارت به‌صورت آزمایشی رفتار کنید. مدل‌های مختلف آن را با اثرهای متفاوت به کار می‌گیرند. بهتر است اول در حالت برنامه‌ریزی اجرا کنید تا ایده‌ای داشته باشید ایجنت دوست دارد چه چیزی را تغییر دهد. و بعد آماده باشید تغییرها را برگردانید یا حتی `omarchy reinstall configs` را فراخوانی کنید، اگر ایجنت همه‌چیز را به هم ریخت.
