# Windows VM

Omarchy راه آسانی برای اجرای Windows از طریق یک Docker VM روی ماشین‌های x86_64 ارائه می‌دهد. می‌توانید آن را با استفاده از _نصب > Windows_ از منوی Omarchy (`Super + Space`) نصب کنید.

ماشین شما برای این کار به مجازی‌سازی KVM نیاز دارد، که بیشتر ماشین‌ها دارند — اما گاهی در BIOS خاموش است، و اگر چنین باشد نصب‌کننده به شما اطلاع خواهد داد. همچنین به فضای دیسک نیاز خواهید داشت: هر مقداری که به Windows می‌دهید، به‌علاوه حدود 10GB برای خود ایمیج.

نصب‌کننده می‌پرسد چه مقدار RAM، چند هسته CPU و چه مقدار دیسک اختصاص دهید (64GB یا بیشتر کف منطقی است)، سپس یک نام کاربری و گذرواژه Windows می‌خواهد. آن‌ها را خالی بگذارید و `docker` / `admin` را دریافت می‌کنید. دانلود مدتی طول می‌کشد — 10-15 دقیقه عادی است — و می‌توانید پیشرفت را در مرورگر در `http://127.0.0.1:8006` دنبال کنید. مرورگر پیش از باز کردن کنسول، همان نام کاربری و گذرواژه را از شما می‌خواهد.

## استفاده از آن

پس از نصب، _Windows_ را از اجراکننده برنامه‌ها اجرا کنید. این کار VM را اگر از قبل در حال اجرا نباشد روشن می‌کند و شما را از طریق RDP، به‌صورت تمام‌صفحه، متصل می‌کند. در شروع سرد به آن 15-30 ثانیه فرصت دهید.

نشست RDP صدا، میکروفون شما و یک کلیپ‌بورد مشترک را منتقل می‌کند، بنابراین کپی کردن متن بین Linux و Windows به‌سادگی کار می‌کند. وضوح تصویر از پنجره شما پیروی می‌کند، و Omarchy مقیاس‌بندی نمایشگر شما را عبور می‌دهد، بنابراین روی یک صفحه‌نمایش HiDPI یک افتضاح تار نیست.

وقتی پنجره RDP را می‌بندید، VM به‌طور خودکار خاموش می‌شود. اگر ترجیح می‌دهید آن را روشن نگه دارید — مثلاً چیزی در آنجا در حال کار است — در عوض آن را با `omarchy windows vm launch --keep-alive` اجرا کنید.

بقیه کنترل‌ها روی همان دستور هستند:

```bash
omarchy windows vm status    # is it running?
omarchy windows vm stop      # shut it down
omarchy windows vm launch    # start and connect
```

## اشتراک‌گذاری فایل‌ها

دایرکتوری `~/Windows` در دایرکتوری خانه شما به‌طور خودکار با VM به اشتراک گذاشته می‌شود. اگر می‌خواهید فایل‌ها برای Windows قابل دسترس باشند، آن‌ها را آنجا قرار دهید. VM به هیچ بخش دیگری از سیستم فایل شما دسترسی ندارد، بنابراین از هر چیز ناخوشایندی در سمت Windows در امان هستید. دیسک مجازی خودش در `~/.windows` در دسترس است.

آن مسیرهای آشنا در خانه روی سیستم‌فایل‌های خودشان باقی می‌مانند. آن‌ها همچنین می‌توانند symlink به دایرکتوری‌هایی باشند که مال شما هستند، که وقتی دیسک مجازی روی یک درایو بزرگ‌تر قرار دارد مفید است. نصب‌کننده فضای آزاد را روی سیستم‌فایلی اندازه می‌گیرد که واقعاً حاوی `~/.windows` است، نه لزوماً سیستم‌فایلی که دایرکتوری خانه شما را در خود دارد.

دیسک و مسیرهای مشترک را به‌صورت دایرکتوری‌های جداگانه و بدون هم‌پوشانی نگه دارید. حذف عمداً دایرکتوری دیسک را خالی می‌کند اما دایرکتوری مشترک را حفظ می‌کند. بلافاصله پیش از حذف، Omarchy یک بررسی مهار محدود انجام می‌دهد و اگر آن بررسی زمانش تمام شود یا نتواند ثابت کند که دو درخت جدا هستند، از حذف هر چیزی خودداری می‌کند.

پیش از شروع VM، Omarchy آن دو دایرکتوری را باز می‌کند و پین می‌کند، سپس دقیقاً همان inodeهای دایرکتوری را روی لنگرهای خصوصی به‌ازای هر کاربر در زیر `/var/lib/omarchy/windows/mounts` به‌صورت bind-mount سوار می‌کند. Docker فقط آن لنگرهای محافظت‌شده توسط root را می‌بیند. این کار مکان‌های سفارشی دیسک را حفظ می‌کند و در عین حال مانع از آن می‌شود که فرایند دیگری که به‌عنوان شما اجرا می‌شود، یک مسیر بررسی‌شده را پیش از مصرف آن توسط کانتینر ممتاز جابه‌جا کند. دایرکتوری‌های موجود دیسک و مشترک در طول مهاجرت به حالت `0700` محدود می‌شوند تا سایر حساب‌های محلی نتوانند محتویات آن‌ها را مرور کنند.

پورت‌های VM فقط به localhost متصل هستند، بنابراین هیچ چیزی در شبکه شما نمی‌تواند به ماشین Windows دسترسی پیدا کند. کنسول وب نیز به نام کاربری و گذرواژه Windows پیکربندی‌شده نیاز دارد، که مانع از آن می‌شود که حساب محلی دیگری VM را از طریق پورت 8006 هدایت کند.

## محدودیت‌ها و مجوز

با این تنظیمات هیچ GPU passthrough وجود ندارد، بنابراین برای بازی یا ویرایش ویدیو مناسب نیست. این راهی عالی برای اجرای Microsoft Office یا هر چیز دیگری است که حتماً باید داشته باشید.

نسخه نصب‌شده Windows 11 Pro است، فعال‌نشده. برای استفاده از ویژگی‌های قفل‌شده به کلید مجوز خودتان نیاز خواهید داشت.

اگر این رایانه با Windows عرضه شده باشد، کلید OEM حتی پس از نصب Omarchy همچنان در firmware موجود است. آن را با `omarchy windows key` چاپ کنید. آن کلید به این ماشین وابسته است — Windows نصب‌شده مجدد روی همین سخت‌افزار را فعال خواهد کرد، اما معمولاً VM را فعال نخواهد کرد.

می‌توانید بعداً تخصیص منابع را با اجرای `omarchy windows vm install` در یک ترمینال تغییر دهید، که پیکربندی VM را بر اساس پاسخ‌های شما بازنویسی می‌کند. خود فایل compose اکنون در `/var/lib/omarchy/windows/docker-compose.yml` قرار دارد و مالک آن root است — این عمدی است، تا فرایندی که به‌عنوان شما اجرا می‌شود نتواند آن را بازنویسی کند و باعث شود راه‌اندازی ممتاز کل دیسک شما را در کانتینر سوار کند. اگر نیاز دارید آن را دستی ویرایش کنید (برای مثال برای سوار کردن یک دستگاه USB)، آن را با `sudo` ویرایش کنید و همه گزینه‌ها را در [پروژه Dockur Windows](https://github.com/dockur/windows) ببینید.

برای خلاص شدن از شر کل ماجرا، از _حذف > Windows_ از منوی Omarchy استفاده کنید. این کار دیسک VM در `~/.windows` و هر چیزی نصب‌شده در داخل Windows را حذف می‌کند، بنابراین ابتدا هر چیزی را که نیاز دارید از VM کپی کنید. پوشه مشترک `~/Windows` شما دست‌نخورده باقی می‌ماند.
