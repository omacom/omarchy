# AI

Omarchy-তে নিচের কোডিং এজেন্টগুলোর জন্য লঞ্চার অন্তর্ভুক্ত আছে, আপনার জন্য কোনো ডিফল্ট বেছে না দিয়েই। প্রথমবার ব্যবহারের সময় একটি কমান্ড চালালে এর CLI ইনস্টল হয়ে যাবে, তারপর প্রম্পট এলে প্রমাণীকরণ করুন। Hermes হলো ব্যতিক্রম: প্রথমবার ব্যবহারে এর জন্য কিছুই ইনস্টল হয় না, এবং এটি বেছে নিলে Hermes Desktop ইনস্টল হয়, যেমনটি নিচে _Desktop apps_-এ ব্যাখ্যা করা হয়েছে।

### এজেন্ট ইনস্টল ও আপডেট করা

Hermes ছাড়া, এই এজেন্টগুলো mise-এর lazy ইনস্টলেশন ব্যবহার করে: প্রথমবার চালু করলেই CLI ইনস্টল হয়, এবং পরের বারগুলোতে সেটিই পুনরায় ব্যবহার হয়। mise একটি ইনস্টল করা এজেন্টের নতুন রিলিজ আছে কিনা সর্বোচ্চ প্রতি চার ঘণ্টায় একবার পরীক্ষা করে, হয় এটি শুরু হওয়ার ঠিক আগে অথবা ব্যাকগ্রাউন্ডে একটি shell প্রম্পটে। সেই আপডেট ব্যর্থ হলে বা আপনি অফলাইনে থাকলে, ইনস্টল করা সংস্করণটিই চলে। `omarchy update` Omarchy-এর বাকি অংশের সঙ্গে ইনস্টল করা এজেন্টগুলো আপডেট করে, এবং `mup` শুধু mise-পরিচালিত টুলগুলো আপডেট করে।

কোনো এজেন্টের নিজস্ব আপডেটার, যেমন `claude update`, `codex update`, বা কোনো অ্যাপের একটি আপডেট বোতাম, mise-পরিচালিত ইনস্টলটি আপডেট করে না। `codex update` ব্যর্থ হয়, এবং `claude update` সফল হয়েছে বলে জানাতে পারে, অথচ এমন একটি আলাদা কপি ইনস্টল করে যা mise ট্র্যাক করে না। আপনি যদি বরং কোনো এজেন্টের নেটিভ ইনস্টলার ও আপডেটার ব্যবহার করতে চান, তাহলে সেটিকে `disable_tools`-এ যোগ করুন; দেখুন [আগে থেকে ইনস্টল করা CLI টুল](18-development-tools.md#preinstalled-cli-tools)।

আপনার প্রয়োজন হওয়ার আগেই সব কনফিগার করা lazy টুল ইনস্টল করতে, `mise install --include-lazy` চালান। এতে এজেন্টগুলোর পাশাপাশি Omarchy-এর অন্যান্য ডিফল্ট CLI টুলও অন্তর্ভুক্ত থাকে। একটি একক টুল ইনস্টল করতে বা আপনার নিজের ইনস্টলেশন ব্যবহার করতে দেখুন [আগে থেকে ইনস্টল করা CLI টুল](18-development-tools.md#preinstalled-cli-tools)।

`grok` mise-এর ফার্স্ট-পার্টি `grok` প্যাকেজের মাধ্যমে ইনস্টল হয়, ঠিক যেভাবে `claude` এবং `codex` হয়। `grok` চালান, অথবা _Setup > Defaults > Agent_-এর অধীনে এটি বেছে নিন। x.ai-তে থাকা `curl | bash` ইনস্টলারটি এড়িয়ে যান। সেই পথটি `~/.grok/bin`-এ একটি দ্বিতীয় কপি রাখে, সেটিকে `PATH`-এ আগে বসিয়ে দেয়, এবং Omarchy-এর wrapper-কে ওভাররাইট করে।

`dsh` তার ব্রাউজার UI `127.0.0.1:3080`-তে খোলে, লঞ্চ ডিরেক্টরিকে তার ডিফল্ট workspace হিসেবে নিয়ে। এর ব্রাউজার UI কোনো শুরুর প্রম্পট নেয় না, তাই `omarchy agent prompt` এটিকে খোলে প্রম্পটটি আপনার ক্লিপবোর্ডে রেখে, যাতে আপনি পেস্ট করতে পারেন। Omarchy এটিকে DeepSeek-এর no-approval permission প্রিসেট দিয়ে শুরু করে। আপনি যখন DeepSeek Harness-এর অফিসিয়াল মডেল API ব্যবহার করেন, তখন DeepSeek Harness DeepSeek-এ সেশন লগ আপলোড করে; এর ব্রাউজার UI-তে _Settings > General > Upload Session Log_-এর অধীনে সেটি বন্ধ করুন। আপনি এতে যে ফিডব্যাক পাঠান, সেটিও সেশনের সঙ্গে আপলোড হয়, যদি না আপনি এটিকে `DSH_TELEMETRY_MODE=DISABLED` দিয়ে শুরু করেন।

### ডিফল্ট এজেন্ট

Omarchy Menu-তে (`Super + Space`) `omarchy default agent <name>` দিয়ে অথবা _Setup > Defaults > Agent_-এর অধীনে আপনার ডিফল্ট এজেন্ট বেছে নিন। এজেন্টটি এখনও ইনস্টল করা না থাকলে, সেটিকে বেছে নিলেই প্রথমে ইনস্টল হয়ে যায়। একটি নতুন Omarchy একবারের একটি নোটিফিকেশন দিয়ে আপনাকে এই পছন্দটি করতে আমন্ত্রণ জানাবে।

Claude বেছে নিলে Chromium, Chrome, Brave, Brave Origin, এবং Edge-এর জন্য এর ব্রাউজার এক্সটেনশন সেট আপ করার চেষ্টাও করা হয়। এক্সটেনশন সেটআপটি সব ব্যবহারকারীর জন্য প্রযোজ্য হয় এবং আপনার সিস্টেম পাসওয়ার্ড চাইতে পারে; বাতিল করা বা এক্সটেনশন ইনস্টল ব্যর্থ হওয়া সত্ত্বেও Claude বেছে নেওয়া ও চালু করা হয়। আপনার ব্রাউজার রিস্টার্ট করুন, প্রম্পট এলে এক্সটেনশনটি সক্রিয় করুন, এবং এটিকে সংযুক্ত করা শেষ করতে Claude-এ সাইন ইন করুন। সংযোগটি পরীক্ষা করতে Claude-এ `/chrome` চালান। Firefox এবং Zen এই এক্সটেনশন সমর্থন করে না। এই সেটআপ যোগ হওয়ার আগেই Claude যদি ইতিমধ্যে আপনার ডিফল্ট হয়ে থাকে, তাহলে এক্সটেনশনটি ইনস্টল করতে সেটিকে আবার বেছে নিন।

একবার বেছে নিলে, `Super + Shift + Ctrl + A` ডিফল্ট এজেন্টটিকে একটি নিবেদিত টার্মিনাল উইন্ডোতে চালু করে (অথবা আপনি এখনও না বেছে থাকলে picker-টি নিয়ে আসে)। আপনি `omarchy agent prompt "Review this project"` দিয়ে এটিকে সরাসরি একটি কাজেও লাগিয়ে দিতে পারেন। Freebuff এবং DeepSeek Harness কোনো শুরুর প্রম্পট নেয় না, তাই সেগুলো বদলে প্রম্পটটি আপনার ক্লিপবোর্ডে রেখে খোলে, যাতে আপনি পেস্ট করতে পারেন। এইভাবে চালু করা এজেন্টগুলো তাদের নিজ নিজ don't-stop-to-ask মোডে কারো তত্ত্বাবধান ছাড়াই চলে, তাই তারা সত্যিই কিছু করে ফেলবে—এর জন্য প্রস্তুত থাকুন! MiniMax Code-এর ইন্টারঅ্যাক্টিভ সেশনগুলোর জন্য এমন কোনো মোড নেই, তাই এটি যথারীতি অনুমতি চায়। এবং যেহেতু এজেন্টগুলো আপনার হোম ডিরেক্টরির জন্য trust মনে রাখতে অস্বীকার করে, তাই `$HOME` থেকে চালু করলে সেগুলো বদলে `~/Work`-এ শুরু হয়।

টার্মিনাল শর্টকাটও আছে: `a` বর্তমান টার্মিনালে ইনলাইনে ডিফল্ট এজেন্ট চালায়, আর `c`, `cx`, এবং `cy` সরাসরি OpenCode, Claude Code, এবং Codex শুরু করে (আবারও তাদের auto-approving মোডে)। থিম পরিবর্তনও এজেন্টগুলোর সঙ্গে সিঙ্ক হয়: আপনি Omarchy থিম বদলালে Claude Code, Pi, OpenCode, এবং Hermes (Omarchy একবার এটিকে ইনস্টল করার পর) সবাই সঙ্গে সঙ্গে বদলে যায়।

### এজেন্ট প্যানেল

টপ বারে একটি এজেন্ট আইকন আছে। আপনি কোনো এজেন্ট সেট আপ করার আগে, এর প্যানেল আপনাকে Claude, Codex, বা Grok-এ সাইন ইন করার ধাপগুলো দিয়ে নিয়ে যায়, এবং প্রথমটিই আপনার ডিফল্ট এজেন্ট হয়ে যায়। এরপর, প্যানেলটি প্রতিটি সাবস্ক্রিপশনকে এক পৃষ্ঠায় নিয়ে আসে: প্রতিটি এজেন্ট ও অ্যাকাউন্ট তার প্ল্যানসহ, এর 5-ঘণ্টার সেশন ও সাপ্তাহিক সীমার প্রতিটির জন্য একটি মিটার, রিসেট হতে বাকি সময়সহ (ঠিক শতাংশের জন্য হোভার করুন), অথবা অবশিষ্ট প্রিপেইড ব্যালেন্স, এমন একটি লাইনের অধীনে যা সেগুলো জুড়ে আপনি যা ব্যবহার করেছেন তা ঘুরিয়ে ঘুরিয়ে দেখায়, যেমন এই সপ্তাহের টোকেন এবং আপনার সবচেয়ে বেশি ব্যবহৃত মডেল। _Make something_-এর অধীনে এটি একটি নতুন থিম, প্লাগইন, বা অ্যাপের জন্য স্টার্টার প্রম্পট দেয়, যা কাজটি আপনার ডিফল্ট এজেন্টের হাতে তুলে দেয়। অ্যাপগুলো তৈরি হয় ঠিক যেভাবে Omarchy-এর নিজস্ব Hype, Monologue, এবং Omacut তৈরি, C++ এবং Qt Quick-এ, omarchy-app এজেন্ট স্কিল অনুসরণ করে, এবং তাদের প্রয়োজনীয় কম্পাইলার ও Qt অংশগুলো ইনস্টল করাই থাকে। Claude Code, Codex, Grok, Kimi, Cursor এবং এর Grok Bot ভাতা, GitHub Copilot, Muse, Antigravity, Kimchi, এবং Devin তাদের সীমাসহ একদম শুরু থেকেই অন্তর্ভুক্ত থাকে, এবং Hermes, Mistral Vibe, এবং Qwen Code আপনি সেগুলো ব্যবহার করার পর তাদের সেশন ও টোকেন দেখায়। pi, omp, বা opencode-এর মাধ্যমে আপনি যে প্রোভাইডার প্ল্যান ও কী ব্যবহার করেন, সেগুলোও দেখা যায়: OpenCode Zen এবং Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan, এবং Synthetic তাদের সীমাসহ; Fireworks, OpenRouter, এবং DeepSeek তাদের প্রিপেইড ব্যালেন্সসহ; এবং Local models-এর অধীনে আপনার নিজের হার্ডওয়্যারে চালানো মডেলগুলো। প্রতিটি এজেন্টকে একবারই গণনা করা হয়, যেই তাকে বিল করুক না কেন তার অধীনে, আপনি যতগুলো harness দিয়েই তাকে চালান না কেন।

প্যানেলের জন্য বার আইকনে বাম-ক্লিক করুন, আপনার ডিফল্ট এজেন্ট চালু করতে ডান-ক্লিক করুন। এর পেছনের ব্যবহারের রেকর্ডগুলো প্রতি 15 মিনিটে `omarchy agent usage-update` দিয়ে পুনরায় তৈরি হয়, এবং প্যানেলটি একটি সিঙ্ক করা ফোল্ডারের মাধ্যমে আপনার অন্যান্য মেশিনের ব্যবহারও একত্র করতে পারে। সম্পূর্ণ সেটিংসের জন্য `$OMARCHY_PATH/shell/plugins/agents/`-এর অধীনে README দেখুন।

### একাধিক সাবস্ক্রিপশন

আপনি যদি একাধিক Claude, Codex, বা Grok প্ল্যানের জন্য অর্থ প্রদান করেন — ধরুন একটি ব্যক্তিগত Max এবং একটি কাজের — Omarchy সেগুলো সবগুলোকে সাইন ইন রাখতে পারে এবং সেগুলোর মধ্যে যাতায়াত করতে পারে। এজেন্ট প্যানেলে + দিয়ে একটি সাবস্ক্রিপশন যোগ করুন, যা আপনাকে সেখানেই ধাপে ধাপে নিয়ে যায়, অথবা `omarchy agent account add claude Work` দিয়ে (অথবা `codex`, অথবা `grok`)। CLI অনুপস্থিত থাকলে এটি সেটি ইনস্টল করে। একটি প্রোভাইডারের জন্য প্রথম অ্যাকাউন্টটি আপনার স্বাভাবিক ব্রাউজার দিয়ে সাইন ইন করে, ঠিক যেখানে CLI সবসময় খোঁজে। এরপরের প্রতিটি একটি প্রাইভেট উইন্ডো দিয়ে সাইন ইন করে, যাতে আপনার ব্রাউজার ইতিমধ্যে যে অ্যাকাউন্টে সাইন ইন করা আছে সেটি ভুল করে ধরা না পড়ে; সেখানে আপনি যে অ্যাকাউন্টটি যোগ করছেন সেটি হিসেবে সাইন ইন করুন, এবং আগেই খোলা থাকা যেকোনো প্রাইভেট উইন্ডো প্রথমে বন্ধ করুন। এটি করতে কখনো CLI থেকে লগ আউট করবেন না: লগ আউট করলে সংরক্ষিত সাইন-ইন বাতিল হয়ে যায়, এবং সেই অ্যাকাউন্টটিকে আবার যোগ করতে হবে।

আপনার সাবস্ক্রিপশন লগইনগুলো SSH-এর মাধ্যমে অন্য একটি Omarchy মেশিনে কপি করতে, `omarchy agent account copy user@laptop` চালান। গন্তব্যে একটি ইনস্টল করা না থাকলে প্রেরক একটি অস্থায়ী রিসিভার সরবরাহ করে, তাই পুরোনো Omarchy মেশিনগুলো আপডেট ছাড়াই অ্যাকাউন্ট পেতে পারে। ইনস্টল করা রিসিভারগুলো অগ্রাধিকার পায়। এটি সব Claude, Codex, এবং Grok সাবস্ক্রিপশন কপি করে; সেগুলো বেছে নিতে প্রোভাইডারের নাম যোগ করুন, যেমন `omarchy agent account copy laptop claude`। অ্যাকাউন্টের নাম ও কমান্ড ID উৎসের সঙ্গে মেলে, গন্তব্যে ইতিমধ্যে থাকা অ্যাকাউন্টগুলোসহ। সম্পর্কহীন গন্তব্য অ্যাকাউন্টগুলোর নামে দ্বন্দ্ব হলে একটি সংখ্যাসূচক প্রত্যয় পায়, এবং সেটিংস, স্কিল, প্লাগইন, এবং কথোপকথনের ইতিহাস প্রতিটি মেশিনে স্থানীয়ই থাকে।

বিদ্যমান গন্তব্য ক্রেডেনশিয়াল রাখা হয়। সেখানে ইতিমধ্যে সাইন ইন করা একটি উৎস অ্যাকাউন্টের নাম তার ক্রেডেনশিয়াল প্রতিস্থাপন না করেই সিঙ্ক্রোনাইজ করা হয়; অন্য অ্যাকাউন্টগুলো এর পাশাপাশি যোগ করা হয়। মিলে যাওয়া অ্যাকাউন্টগুলোর জন্য সংরক্ষিত ক্রেডেনশিয়াল প্রতিস্থাপন করতে, গন্তব্যে সেই অ্যাকাউন্টের সেশনগুলো বন্ধ করার পর `omarchy agent account copy --replace laptop claude` ব্যবহার করুন। একটি নতুন গন্তব্য উৎসের সক্রিয় অ্যাকাউন্ট ও সুইচিং পছন্দগুলোও পায়; একটি প্রতিষ্ঠিত গন্তব্য তার নিজেরগুলোই রাখে।

ক্রেডেনশিয়াল SSH-এর মাধ্যমে যায় এবং গন্তব্যে প্রাইভেট ফাইলে সংরক্ষিত হয়, তাই শুধু আপনার বিশ্বাসের মেশিনগুলোতেই কপি করুন। এটি একবারের কপি, চলমান সিঙ্ক্রোনাইজেশন নয়। Codex রিফ্রেশ টোকেন অন্য একটি মেশিন দ্বারা রোটেট করা হতে পারে, যার ফলে একটি কপি করা লগইনের নবায়নের প্রয়োজন হতে পারে; একাধিক মেশিনে একসঙ্গে ব্যবহারের জন্য আলাদা সাইন-ইনই সবচেয়ে নির্ভরযোগ্য পছন্দ। দেখুন [Codex-এর অ্যাকাউন্ট প্রমাণীকরণ নির্দেশিকা](https://developers.openai.com/codex/auth/ci-cd-auth)।

প্রতি প্রোভাইডারে একটি অ্যাকাউন্ট সক্রিয় থাকে, এবং প্রতিটি নতুন সেশন সেটি হিসেবেই শুরু হয়: `cx`, `cy`, একটি সাধারণ `claude`, `codex`, বা `grok`, `omarchy agent`-এর মাধ্যমে চালু করা যেকোনো কিছু, এবং স্ক্রিপ্ট বা এডিটর যা `PATH`-এ CLI খুঁজে পায়। `omarchy agent account use work` দিয়ে সুইচ করুন (এবং `omarchy agent account use main` দিয়ে ফিরে আসুন), অথবা প্যানেলে একটি অ্যাকাউন্টের নম্বর চেপে তারপর `Enter` চেপে (অথবা এর Use বোতামে ক্লিক করে)। ইতিমধ্যে চলমান সেশনগুলো তারা যে অ্যাকাউন্ট দিয়ে শুরু হয়েছিল সেটিতেই থাকে। কথোপকথনের ইতিহাস, সেটিংস, স্কিল, এবং প্লাগইন অ্যাকাউন্টগুলো জুড়ে শেয়ার করা হয়, তাই একই ফোল্ডারে `claude --continue` নতুন অ্যাকাউন্টে আপনি যেখানে ছেড়েছিলেন সেখান থেকেই শুরু করে।

একাধিক অ্যাকাউন্ট থাকলে, প্যানেল প্রতিটি অ্যাকাউন্টের সীমা পাশাপাশি দেখায়, সক্রিয়টিকে চিহ্নিত করে। ডিফল্টভাবে Omarchy আপনাকে জানায় যখন সক্রিয় অ্যাকাউন্টটি একটি সীমার 95% অতিক্রম করে, এবং নোটিফিকেশনে ক্লিক করলে সবচেয়ে বেশি অবকাশ আছে এমন অ্যাকাউন্টে সুইচ করে। প্যানেলে একটি অ্যাকাউন্টের লাইনের ওপর হোভার করুন এবং Use-এর পাশে আসা Autoswitch-এ ক্লিক করুন (অথবা `m` চাপুন), অথবা `omarchy agent account mode auto` চালান, যাতে এটি নিজে থেকেই সুইচ করে; এটি চালু থাকাকালীন, Autoswitch Use-এর জায়গা নেয়, এবং এতে আবার ক্লিক করলে জানানোর অবস্থায় ফিরে যায়। থ্রেশহোল্ড বদলাতে একটি সংখ্যা যোগ করুন, যেমন `omarchy agent account mode auto 90`। প্রতিটি অ্যাকাউন্টই থ্রেশহোল্ডের ওপরে থাকলে, আপনি একবারই সে কথা শুনবেন, কোন অ্যাকাউন্টটি প্রথমে মুক্ত হবে তা-সহ। একটি সক্রিয় অ্যাকাউন্ট তার থ্রেশহোল্ডের 15 পয়েন্টের মধ্যে থাকলে (ডিফল্টে 80%), এর সীমাগুলো প্রতি 15 মিনিটের বদলে প্রতি তিন মিনিটে পরীক্ষা করা হয়।

`omarchy agent account list` প্রতিটি অ্যাকাউন্ট ও এর সর্বশেষ সীমা দেখায়, `omarchy agent account remove work` একটিকে সরিয়ে দেয়, এবং `omarchy agent account rename primary Hey` একটির নাম বদলায় (অথবা প্যানেলে একটি অ্যাকাউন্টের নামে ক্লিক করুন)। এই কমান্ডগুলো আপনার ডিফল্ট এজেন্টের অ্যাকাউন্টগুলোর ওপর কাজ করে; অন্য প্রোভাইডারের কাছে পৌঁছতে, প্রথমে সেটির নাম দিন, যেমন `omarchy agent account use codex side`। `~/.claude` বা `~/.codex`-এ আপনার ইতিমধ্যে থাকা লগইনটি হলো _Main_ অ্যাকাউন্ট এবং এটি যেখানে আছে সেখানেই থাকে। প্রায় আট ঘণ্টার বেশি সময় ধরে অব্যবহৃত থাকা একটি অ্যাকাউন্ট _Sign-in required_ দেখাতে পারে; প্যানেলেই সেই অ্যাকাউন্টে আবার সাইন ইন করতে এতে ক্লিক করুন, অথবা এতে একটি সেশন শুরু করুন, যা নিজে থেকেই সাইন-ইন রিফ্রেশ করে। একটি অ্যাকাউন্ট যোগ করার সময় আপনার থাকা MCP সার্ভারগুলো সেটিতে চলে আসে, কিন্তু পরে `claude mcp add` দিয়ে আপনি যেগুলো যোগ করেন সেগুলো শুধু আপনি যে অ্যাকাউন্টে সেগুলো যোগ করেছিলেন সেটিতেই পৌঁছায়। Claude Desktop এবং একটি CLI বাইনারির absolute path দিয়ে কনফিগার করা টুলগুলো সুইচটি অনুসরণ করে না। একটি স্পষ্ট `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, বা `GROK_HOME` নির্বাচিত অ্যাকাউন্টের ওপর অগ্রাধিকার পায়।

### ক্র্যাশ নির্ণয়

Omarchy প্রক্রিয়ার ক্র্যাশের জন্য systemd-coredump পর্যবেক্ষণ করে। কোনো কিছু segfault করলে, আপনি একটি "Process crashed" নোটিফিকেশন পাবেন — এতে ক্লিক করুন, এবং ক্র্যাশটি আপনার ডিফল্ট এজেন্টের হাতে Omarchy-এর diagnose-crash স্কিলসহ তুলে দেওয়া হয়, যা এজেন্টকে core dump থেকে তথ্য প্রতিষ্ঠা করা এবং ক্র্যাশটি আপস্ট্রিমে রিপোর্ট করার মতো কিনা তা সিদ্ধান্ত নেওয়ার মধ্য দিয়ে নিয়ে যায়। আপনি `coredumpctl list` থেকে যেকোনো PID-এর বিপরীতে `omarchy agent crash <pid>` দিয়ে হাতে করেও এটি চালাতে পারেন।

পর্যবেক্ষণটি ডিফল্টভাবে চালু থাকে। _Trigger > Toggle > Crash Capture_-এর অধীনে (অথবা `omarchy toggle crash-capture` দিয়ে) এটি বন্ধ করুন এবং নোটিফিকেশন বন্ধ হয়ে যাবে; `omarchy agent crash <pid>` হাতে তখনও কাজ করে।

ক্র্যাশগুলোকে একবারে একটি প্রোগ্রাম ধরে নীরবও করা যায়, যা নির্ণয়টি শেষে আপনাকে দেয়। `omarchy crash mute hyprland` শুধু সেই প্রোগ্রামের জন্য নোটিফিকেশন বন্ধ করে, `omarchy crash mute hyprland off` সেগুলো ফিরিয়ে আনে, এবং `omarchy crash mute` নিজে থেকে চালালে আপনি কী mute করেছেন তা তালিকাভুক্ত করে। এটি বাইনারির path-কেও এর নামের মতোই সানন্দে নেয়, তাই `omarchy crash mute /usr/bin/hyprland` একই কাজ করে। নামে স্পেস থাকলে সেটিকে উদ্ধৃত করুন, যেমন `omarchy crash mute 'Some App'`। বাকি সবকিছু তখনও জানায়, এবং mute করা প্রোগ্রামটি তখনও ক্র্যাশ করে — এটি অনুস্মারকটি লুকায়, এটি কিছু ঠিক করে না।

### ডেস্কটপ অ্যাপ

_Install > AI_ মেনুতে কয়েকটি গ্রাফিক্যাল AI অ্যাপও আছে: ChatGPT ডেস্কটপ অ্যাপ, Claude ডেস্কটপ অ্যাপ (Anthropic-এর Linux beta, Chat, Cowork, এবং Claude Code ট্যাবসহ), Grok Bot xAI-এর মডেলগুলোর সঙ্গে চ্যাট করার জন্য, Herdr Desktop, Hermes Desktop, OpenClaw, Perplexity ডেস্কটপ অ্যাপ, এবং T3 Code। Grok Bot হলো ডেস্কটপ চ্যাট অ্যাপ। কোডিং এজেন্ট হলো `grok` কমান্ড।

Hermes Desktop সম্পর্কে জানা জরুরি, কারণ একটি মেশিনে একটি Hermes থাকে, এবং সেটি অ্যাপেরই: Hermes শুধুমাত্র অ্যাপের মাধ্যমেই ইনস্টল হয়, এবং ডিফল্ট এজেন্ট যে `hermes` কমান্ড চালায় সেটি অ্যাপেরই। Hermes-কে ডিফল্ট এজেন্ট হিসেবে বেছে নিলে _Install > AI_ এন্ট্রিটি যা করে ঠিক তা-ই ইনস্টল হয়: প্যাকেজটি, এবং Hermes-এর নিজস্ব ইনস্টলার দিয়ে সেট আপ করা `~/.hermes`-এর অধীনে একটি Hermes runtime, যা প্রথমবার কয়েক মিনিট সময় নেয়। সেই runtime-টিই হলো সেই একমাত্র Hermes যা টার্মিনালের `hermes` কমান্ড, ডিফল্ট এজেন্ট এবং অ্যাপ সবাই ব্যবহার করে, এবং এটি Omarchy রিলিজের অপেক্ষা না করে `hermes update` দিয়ে নিজেকে আপডেট করে। এটি ইনস্টল করলে Hermes-কে Omarchy থিমটিও `omarchy` নামে একটি স্কিন হিসেবে দেওয়া হয়, যা আপনি থিম বদলালে প্রতিটি Hermes সারফেস অনুসরণ করে; আপনি না চাইলে Hermes-এর Appearance সেটিংসের অধীনে অথবা `/skin` দিয়ে আরেকটি বেছে নিন, এবং Omarchy সেই পছন্দটিকে তার মতো থাকতে দেয়। _Remove > AI_-এর অধীনে অ্যাপটি সরালে প্রথমে Hermes বন্ধ হয়, gateway-সহ, সেই runtime-টিকে সঙ্গে নিয়ে যায়, এবং আপনার চ্যাট, স্মৃতি, এবং Hermes নিজের জন্য লেখা স্কিলগুলো রেখে দেয়, যদি না আপনি অন্যথা বলেন: এটি জিজ্ঞাসা করে, ডিফল্টভাবে না ধরে, সেই ডেটা এবং আপনার সংযোগ সেটিংসও যাবে কিনা।

OpenClaw-এর ডেস্কটপ অভিজ্ঞতা হলো এর Control UI, যা এর নিজস্ব স্থানীয় gateway দ্বারা সমর্থিত একটি ওয়েব অ্যাপ হিসেবে খোলে। OpenClaw `~/.openclaw`-তে থাকে এবং নিজেকে আপডেট করে: Control UI-এর "Update Gateway" বোতাম ব্যবহার করুন অথবা `openclaw update` চালান, এবং gateway নতুন সংস্করণে রিস্টার্ট হয়। Omarchy শুধু বেছে দেয় একটি নতুন ইনস্টল কোন রিলিজ থেকে শুরু হবে। _Remove > AI_-এর অধীনে OpenClaw সরালে gateway সার্ভিস ও অ্যাপটিকে সঙ্গে নিয়ে যায় এবং তারপর জিজ্ঞাসা করে `~/.openclaw`-ও যাবে কিনা, যেহেতু সেখানে OpenClaw নিজে এবং এটি ডাউনলোড করা প্লাগইন runtime-গুলোর পাশাপাশি আপনার চ্যাট ও ক্রেডেনশিয়াল থাকে; ডিফল্টভাবে এটি রাখা হয়, এবং OpenClaw আবার ইনস্টল করলে সেটিকে আবার তুলে নেয়।

Herdr Desktop হলো [Herdr](https://herdr.dev) ডেস্কটপ অ্যাপ: টার্মিনাল ও কোডিং এজেন্টের স্পেস, ট্যাব, এবং পেন, যা আপনি উইন্ডো বন্ধ করলেও এর কোরে চলতে থাকে। এটি একটি প্যাকেজের বদলে Herdr-এর নিজস্ব ইনস্টলার থেকে আসে, তাই এটি `~/.local/share/herdr-app`-এ থাকে, আপনার ইতিমধ্যে একটি না থাকলে `~/.local/bin/herdr-core`-এ এর কোর সঙ্গে নিয়ে আসে, এবং দুটোকেই নিজে আপডেট করে। এটি Omarchy `Super + Ctrl + Return`-এ যে `herdr` কমান্ড সরবরাহ করে সেটির পাশে বসে, সেটিকে প্রতিস্থাপন না করে, এবং সেই কমান্ডের সরাসরি কীগুলো পায়: `Alt + Return` এবং `Alt + Shift + Return` একটি পেনকে নিচে বা ডানে ভাগ করে, `Alt + Escape` সেটি বন্ধ করে, `Ctrl + Alt + Arrow` পেনগুলোর মধ্যে যাতায়াত করে, `Alt + 1..9` এবং `Alt + Left/Right` একটি ট্যাব বেছে নেয়, এবং `Alt + Up/Down` স্পেসগুলোর মধ্যে যাতায়াত করে। `Ctrl + 1..9` একটি স্পেস বেছে নেয় এবং `Alt + Shift + Up/Down` এজেন্টগুলোর মধ্য দিয়ে যায়। `Ctrl + Space` প্রিফিক্স কীগুলো শুধু টার্মিনালেই থাকে, যেহেতু অ্যাপটি একটি অনুক্রমের জন্য একটি সাধারণ Ctrl কী ধরে রাখতে পারে না। Omarchy এগুলো `~/.config/herdr-app/keys.json`-এ লেখে, এবং `omarchy-refresh-herdr-app` সেগুলো ফিরিয়ে দেয়। এটি ইনস্টল করলে Herdr-এর Omarchy থিম বেছে নেওয়া হয়, যা এরপর থেকে আপনার Omarchy থিম অনুসরণ করে। Herdr হালকা মোডের জন্য একটি থিম এবং গাঢ় মোডের জন্য একটি থিম রাখে, তাই একটি গাঢ় ও একটি হালকা Omarchy থিমের মধ্যে বদলানোর পর, অন্য মোডের জন্য Herdr-এর থিম picker-এ Omarchy আবার একবার বেছে নিন।

T3 Code একটি প্যাকেজের বদলে `~/.local/share/t3code`-এ এর অফিসিয়াল AppImage রিলিজ থেকে চলে, তাই এটি নিজেকে আপডেট করে। এটি ইনস্টল করলে জিজ্ঞাসা করা হয় Stable নাকি Nightly চ্যানেলে শুরু করবেন; পরে T3 Code-এর সেটিংসে বদলান। আপনার থ্রেড ও সেটিংস `~/.t3`-তে থাকে, এবং _Remove > AI_-এর অধীনে T3 Code সরালে সেগুলো সঙ্গে নিয়ে যায়।

### স্থানীয় মডেল

আপনার কোডিং এজেন্টগুলোর জন্য আপনার নিজের মেশিনে একটি ওপেন মডেল চালান। আপনার প্রম্পট ও কোড মেশিনেই থাকে; মডেলে পাঠানো কিছুই এটি ছেড়ে যায় না। শুরু করুন এভাবে:

```bash
omarchy agent local use best
```

অথবা, টপ বারে এজেন্ট প্যানেলে, + এবং তারপর Local AI বেছে নিন, যা একটি মডেল এই মেশিনে মানানসই হলে দেখা যায়। প্রথমবার, এটি Podman ইনস্টল করে, যা মডেলগুলো চালায়, এবং একটি NVIDIA মেশিনে NVIDIA-এর কন্টেইনার টুলকিট, যা সেগুলোকে GPU দেয়। Omarchy তারপর এই মেশিনের জন্য সুপারিশকৃত মডেলটি বেছে নেয়, সেটি ডাউনলোড করে, এবং শুরু করে। কয়েক দশ GB ডাউনলোড এবং মডেল চলার সময় মেশিনের বেশিরভাগ মেমরি ব্যবহারে থাকা আশা করুন: Flash Next এর সম্পূর্ণ 256K কনটেক্সটসহ প্রায় 100 GiB ব্যবহার করে। অন্য মডেলগুলো এর প্রয়োজনীয় মেমরি ধরে রাখলে, এটি বন্ধ অবস্থায় সেট আপ হয়, আপনি একটি বন্ধ করলেই শুরু হওয়ার জন্য প্রস্তুত। মডেলটি লগআউটে বন্ধ হয়; অন্য কিছুর জন্য মেমরি প্রয়োজন হলে নিজে সেটি বন্ধ করুন।

`omarchy agent local list` বিকল্পগুলো দেখায় এবং ব্যাখ্যা করে কেন কিছু মানায় না। আরেকটি সেট আপ করতে, `omarchy agent local use <recipe>` চালান। আজ, 128 GB Strix Halo মেশিনের জন্য `qwen3.8-flash-next-gufo` এবং `qwen3.8-27b-gufo` উপলব্ধ; 27B প্রায় 40 GiB নেয়, তাই এটি অন্য কাজের জন্য জায়গা ছেড়ে দেয়। নতুন রেসিপি ও সুপারিশ `omarchy update`-এর মাধ্যমে, প্যাকেজের মধ্য দিয়ে আসে।

আপনি সেট আপ করা প্রতিটি মডেল এজেন্ট প্যানেলে তার নিজস্ব লাইন পায়, আপনার সাবস্ক্রিপশনগুলোর পাশে: শুরু করতে play, বন্ধ করে এর মেমরি মুক্ত করতে pause, এবং এতে আপনার এজেন্ট খুলতে টার্মিনাল বোতাম। একাধিক একসঙ্গে চলতে পারে যখন সেগুলো মেমরিতে একসঙ্গে মানায়; একটি না মানালে, Omarchy বলে কোন চলমান মডেলটি বন্ধ করতে হবে। সেগুলো পুনর্বিন্যাস করতে লাইনগুলো টেনে নিন, এবং একটি নির্বাচিত লাইনে Delete চেপে একটি মডেল ও এর ডাউনলোড সরান।

কমান্ড লাইন থেকে, `omarchy agent local start <recipe>` এবং `omarchy agent local stop <recipe>` একই কাজ করে, `omarchy agent local status` প্রতিটি মডেল দেখায়, এবং `omarchy agent --local` আপনার ডিফল্ট এজেন্টকে আপনি সর্বশেষ শুরু করা মডেলে খোলে (আপনার ডিফল্ট এজেন্ট একটি স্থানীয় মডেল ব্যবহার করতে না পারলে pi)। যেকোনো OpenAI-সামঞ্জস্যপূর্ণ ক্লায়েন্টও সংযুক্ত হতে পারে: `status` প্রতিটি মডেলের ঠিকানা দেখায় (প্রথমটি হলো `http://127.0.0.1:11435/v1`), রেসিপির নামই মডেল, এবং কী-টি `~/.config/omarchy/agent-local/key`-তে আছে।

`omarchy agent local remove <recipe>` একটি মডেল এবং অন্য কোনো মডেল ব্যবহার করে না এমন ডাউনলোডগুলো মুছে দেয়।

তৃতীয়-পক্ষের runtime-গুলো তাদের প্রকাশক দিয়ে লেবেল করা হয়। Omarchy প্রতিটি মডেল কোনো নেটওয়ার্ক অ্যাক্সেস ছাড়াই চালায়।

### স্থানীয় LLM

Omarchy স্থানীয় LLM মডেল চালানোর দুটি উপায় সুপারিশ করে: LM Studio এবং Ollama। LM Studio ওপেন-ওয়েট মডেল খোঁজা, ইনস্টল করা, এবং চালানোর জন্য একটি GUI ইন্টারফেস দেয়। সহজে শুরু করার এটি একটি দারুণ উপায়। Ollama একইভাবে করার জন্য একটি CLI দেয়। কিন্তু আপনি স্থানীয় মডেলে নতুন হলে, আমি LM Studio দিয়ে শুরু করতাম। আপনি Omarchy Menu-তে _Install > AI_-এর অধীনে যেকোনো একটি ইনস্টল করতে পারেন।

### Omarchy স্কিল

এজেন্ট স্কিল AI-কে নির্দিষ্ট টুল একটি নির্দিষ্ট উপায়ে ব্যবহার করতে সাহায্য করে, এবং Omarchy সিস্টেমটি নিজের মতো করে সাজানোর জন্য একটি ডিফল্ট স্কিলসহ আসে। যেমন আপনার Hyprland কনফিগ টুইক করা, বার ঠিক করা, অথবা এমনকি একদম শুরু থেকে একটি নতুন থিম তৈরি করা। এটি Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` এবং প্রতিটি `~/.hermes/profiles/*/skills`), এবং জেনেরিক `~/.agents/skills` অবস্থানের স্কিল ডিরেক্টরিগুলোতে সিমলিঙ্ক করা আছে, তাই বেশিরভাগ harness এটি স্বয়ংক্রিয়ভাবে তুলে নেয়।

কিন্তু আপনার এই স্কিলটিকে পরীক্ষামূলক হিসেবে ধরা উচিত। বিভিন্ন মডেল এটিকে বিভিন্ন কার্যকারিতায় ব্যবহার করবে। প্রথমে plan মোডে চালানোই সবচেয়ে ভালো, যাতে এজেন্ট কী বদলাতে চায় সে সম্পর্কে আপনার ধারণা থাকে। এবং তারপর পরিবর্তনগুলো রোলব্যাক করতে অথবা এমনকি `omarchy reinstall configs` আহ্বান করতে প্রস্তুত থাকুন, যদি এজেন্ট সবকিছুর জগাখিচুড়ি করে ফেলে।
