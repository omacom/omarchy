# AI

Omarchy-তে নিচের coding agent-গুলোর জন্য launcher রয়েছে, কিন্তু আপনার জন্য কোনো default বেছে দেওয়া হয় না। প্রথমবার ব্যবহারের সময় এর CLI install করতে একটি command চালান, তারপর prompt এলে authenticate করুন। Hermes হলো ব্যতিক্রম: প্রথমবার ব্যবহারে এর জন্য কিছুই install হয় না, এবং এটি বেছে নিলে Hermes Desktop install হয়, যেমনটা নিচের _Desktop apps_-এ ব্যাখ্যা করা হয়েছে।

### Agent install ও update করা

Hermes ছাড়া, এই agent-গুলো mise-এর lazy installation ব্যবহার করে: প্রথম launch-এ CLI install হয়, এবং পরের launch-গুলো সেটিই পুনরায় ব্যবহার করে। mise একটি installed agent-এর নতুন release আছে কিনা সর্বোচ্চ প্রতি চার ঘণ্টায় একবার পরীক্ষা করে, সেটি শুরু হওয়ার ঠিক আগে অথবা background-এ একটি shell prompt-এ। সেই update ব্যর্থ হলে বা আপনি offline থাকলে, installed version-টিই চলে। `omarchy update` বাকি Omarchy-র সঙ্গে installed agent-গুলো update করে, আর `mup` শুধু mise-managed tool-গুলো update করে।

একটি agent-এর নিজের updater, যেমন `claude update`, `codex update`, বা কোনো app-এর মধ্যে থাকা একটি update button, mise-managed install-টি update করে না। `codex update` ব্যর্থ হয়, আর `claude update` সফল হয়েছে বলে জানাতে পারে, অথচ একটি আলাদা copy install করে যা mise track করে না। আপনি যদি বরং একটি agent-এর native installer ও updater ব্যবহার করতে চান, সেটিকে `disable_tools`-এ যোগ করুন; দেখুন [Preinstalled CLI tools](18-development-tools.md#preinstalled-cli-tools)।

প্রয়োজন হওয়ার আগেই সব configured lazy tool install করতে `mise install --include-lazy` চালান। এতে agent-গুলোর পাশাপাশি Omarchy-র অন্যান্য default CLI tool-ও অন্তর্ভুক্ত থাকে। একটি মাত্র tool install করা বা নিজের installation ব্যবহার করার জন্য দেখুন [Preinstalled CLI tools](18-development-tools.md#preinstalled-cli-tools)।

`grok` mise-এর first-party `grok` package-এর মাধ্যমে install হয়, ঠিক যেভাবে `claude` ও `codex` হয়। `grok` চালান, অথবা _Setup > Defaults > Agent_-এর অধীনে এটি বেছে নিন। x.ai-তে থাকা `curl | bash` installer-টি এড়িয়ে যান। সেই পথে `~/.grok/bin`-এ একটি দ্বিতীয় copy বসে, `PATH`-এর সামনে সেটি যোগ হয়, এবং Omarchy-র wrapper-টি overwrite হয়ে যায়।

`dsh` তার browser UI খোলে `127.0.0.1:3080`-এ, যেখানে launch directory-টি তার default workspace হিসেবে থাকে। এর browser UI কোনো starting prompt নেয় না, তাই `omarchy agent prompt` এটি খোলে prompt-টি আপনার clipboard-এ রেখে, যাতে আপনি paste করতে পারেন। Omarchy এটি DeepSeek-এর no-approval permission preset দিয়ে শুরু করে। আপনি যখন এর official model API ব্যবহার করেন, DeepSeek Harness session log DeepSeek-এ upload করে; এর browser UI-তে _Settings > General > Upload Session Log_-এর অধীনে সেটি বন্ধ করুন। আপনি এতে যে feedback পাঠান তাও session-এর সঙ্গে upload হয়, যদি না আপনি এটি `DSH_TELEMETRY_MODE=DISABLED` দিয়ে শুরু করেন।

### Default agent

`omarchy default agent <name>` দিয়ে অথবা Omarchy Menu-তে (`Super + Space`) _Setup > Defaults > Agent_-এর অধীনে আপনার default agent বেছে নিন। Agent-টি এখনো install না হয়ে থাকলে, এটি বেছে নিলে প্রথমে সেটি install হয়। একটি নতুন Omarchy একবারের একটি notification দিয়ে আপনাকে এই পছন্দটি করতে আমন্ত্রণ জানাবে।

Claude বেছে নিলে Chromium, Chrome, Brave, Brave Origin, এবং Edge-এর জন্য এর browser extension সেট আপ করার চেষ্টাও করা হয়। Extension setup-টি সব user-এর ক্ষেত্রে প্রযোজ্য হয় এবং আপনার system password চাইতে পারে; বাতিল করলে বা extension install ব্যর্থ হলেও Claude নির্বাচিত ও launch হয়। আপনার browser restart করুন, prompt এলে extension-টি enable করুন, এবং এটির সংযোগ সম্পূর্ণ করতে Claude-এ sign in করুন। সংযোগ পরীক্ষা করতে Claude-এ `/chrome` চালান। Firefox ও Zen এই extension সমর্থন করে না। এই setup যোগ হওয়ার আগে থেকেই Claude যদি আপনার default হয়ে থাকে, extension-টি install করতে সেটিকে আবার নির্বাচন করুন।

বেছে নেওয়ার পর, `Super + Shift + Ctrl + A` একটি dedicated terminal window-তে default agent launch করে (অথবা আপনি এখনো বেছে না নিয়ে থাকলে picker-টি নিয়ে আসে)। আপনি `omarchy agent prompt "Review this project"` দিয়ে এটিকে সরাসরি একটি কাজেও launch করতে পারেন। Freebuff ও DeepSeek Harness কোনো starting prompt নেয় না, তাই সেগুলো তার বদলে prompt-টি আপনার clipboard-এ রেখে খোলে, যাতে আপনি paste করতে পারেন। এভাবে launch করা agent-গুলো তাদের নিজ নিজ don't-stop-to-ask mode-এ unattended চলে, তাই সেগুলো সত্যিই কিছু করে ফেলার জন্য প্রস্তুত থাকুন! MiniMax Code-এর interactive session-গুলোর জন্য এমন কোনো mode নেই, তাই এটি যথারীতি permission চায়। আর যেহেতু agent-গুলো আপনার home directory-র জন্য trust মনে রাখতে অস্বীকার করে, `$HOME` থেকে launch-গুলো তার বদলে `~/Work`-এ শুরু হয়।

Terminal shortcut-ও আছে: `a` বর্তমান terminal-এ inline default agent চালায়, আর `c`, `cx`, এবং `cy` সরাসরি OpenCode, Claude Code, এবং Codex শুরু করে (আবারও তাদের auto-approving mode-এ)। Theme পরিবর্তন agent-গুলোতেও sync হয়: আপনি Omarchy theme বদলালে Claude Code, Pi, OpenCode, এবং Hermes (Omarchy এটি install করার পর) সবাই অনুসরণ করে।

### Agents panel

Top bar-এ একটি agents icon আছে। আপনি একটি agent সেট আপ করার আগে, এর panel আপনাকে Claude, Codex, বা Grok-এ sign in করার ধাপগুলো দেখিয়ে দেয়, এবং প্রথমটিই আপনার default agent হয়ে যায়। এরপর, panel-টি প্রতিটি subscription-কে এক পৃষ্ঠায় রাখে: প্রতিটি agent ও account তার plan সহ, এর প্রতিটি 5-hour session ও weekly limit-এর জন্য একটি করে meter যেখানে reset হতে কত সময় বাকি তা দেখানো হয় (সঠিক শতাংশের জন্য hover করুন), অথবা অবশিষ্ট prepaid balance, একটি লাইনের নিচে যা আপনি সেগুলোর সবগুলো মিলিয়ে কী ব্যবহার করেছেন তা ঘুরিয়ে ঘুরিয়ে দেখায়, যেমন এই সপ্তাহে tokens এবং আপনার সবচেয়ে বেশি ব্যবহৃত model। _Make something_-এর অধীনে এটি একটি নতুন theme, plugin, বা app-এর জন্য starter prompt দেয় যা কাজটি আপনার default agent-এর হাতে তুলে দেয়। Omarchy-র নিজের Hype, Monologue, এবং Omacut যেভাবে তৈরি, সেভাবেই C++ ও Qt Quick-এ app তৈরি হয়, omarchy-app agent skill অনুসরণ করে, এবং তাদের প্রয়োজনীয় compiler ও Qt অংশগুলো installed অবস্থায় আসে। Claude Code, Codex, Grok, Kimi, Cursor ও এর Grok Bot allowance, GitHub Copilot, Muse, Antigravity, Kimchi, এবং Devin তাদের limit সহ out of the box অন্তর্ভুক্ত থাকে, আর Hermes, Mistral Vibe, এবং Qwen Code আপনি সেগুলো ব্যবহার করার পর তাদের session ও token দেখায়। pi, omp, বা opencode-এর মাধ্যমে আপনি যে provider plan ও key ব্যবহার করেন সেগুলোও দেখা যায়: OpenCode Zen ও Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan, এবং Synthetic তাদের limit সহ; Fireworks, OpenRouter, এবং DeepSeek তাদের prepaid balance সহ; এবং Local models-এর অধীনে আপনি নিজের hardware-এ যে model-গুলো চালান। প্রতিটি agent একবারই গণনা করা হয়, যেই তাকে bill করুক তার অধীনে, আপনি যতগুলো harness দিয়েই তাকে চালান না কেন।

Panel-এর জন্য bar icon-এ left-click করুন, আপনার default agent launch করতে right-click করুন। এর পেছনের usage record-গুলো প্রতি 15 মিনিটে `omarchy agent usage-update` দিয়ে পুনরায় তৈরি হয়, এবং panel-টি একটি synced folder-এর মাধ্যমে আপনার অন্য machine-গুলো থেকে usage merge-ও করতে পারে। সম্পূর্ণ settings-এর জন্য `$OMARCHY_PATH/shell/plugins/agents/`-এর অধীনে README দেখুন।

### একাধিক subscription

আপনি যদি একাধিক Claude, Codex, বা Grok plan-এর জন্য অর্থ দেন — যেমন একটি personal Max ও একটি work-এর — Omarchy সেগুলো সবগুলোকে signed in রাখতে পারে এবং সেগুলোর মধ্যে যাতায়াত করতে পারে। Agents panel-এ + দিয়ে একটি subscription যোগ করুন, যা ঠিক সেখানেই আপনাকে ধাপগুলো দেখিয়ে দেয়, অথবা `omarchy agent account add claude Work` দিয়ে (অথবা `codex`, বা `grok`)। CLI অনুপস্থিত থাকলে এটি সেটি install করে। একটি provider-এর প্রথম account আপনার স্বাভাবিক browser দিয়ে sign in করে, ঠিক যেখানে CLI সবসময় খোঁজে। এরপরের প্রতিটিই একটি private window দিয়ে sign in করে, যাতে আপনার browser ইতিমধ্যে যে account-এ signed in আছে তা ভুল করে ধরা না পড়ে; সেখানে আপনি যে account যোগ করছেন সেটি হিসেবে sign in করুন, এবং আগে থেকে খোলা থাকা যেকোনো private window প্রথমে বন্ধ করুন। এটি করতে কখনো CLI থেকে log out করবেন না: log out করলে saved sign-in বাতিল হয়ে যায়, এবং সেই account-টি আবার যোগ করতে হবে।

আপনার subscription login-গুলো SSH-এর মাধ্যমে অন্য একটি Omarchy machine-এ copy করতে `omarchy agent account copy user@laptop` চালান। Destination-এ একটি installed না থাকলে sender একটি temporary receiver সরবরাহ করে, তাই পুরোনো Omarchy machine-গুলো update ছাড়াই account গ্রহণ করতে পারে। Installed receiver-গুলো অগ্রাধিকার পায়। এটি সব Claude, Codex, এবং Grok subscription copy করে; সেগুলো নির্বাচন করতে provider-এর নাম যোগ করুন, যেমন `omarchy agent account copy laptop claude`। Account-এর নাম ও command ID source-এর সঙ্গে মেলে, destination-এ ইতিমধ্যে থাকা account সহ। সম্পর্কহীন destination account-গুলোর নামে সংঘাত হলে একটি numeric suffix পায়, এবং settings, skills, plugins, ও conversation history প্রতিটি machine-এ local-ই থাকে।

বিদ্যমান destination credential রাখা হয়। সেখানে ইতিমধ্যে signed in থাকা একটি source account-এর credential প্রতিস্থাপন না করে তার নাম synchronize করা হয়; অন্য account-গুলো এর পাশাপাশি যোগ হয়। Matching account-গুলোর জন্য saved credential প্রতিস্থাপন করতে, destination-এ সেই account-এর session-গুলো quit করার পর `omarchy agent account copy --replace laptop claude` ব্যবহার করুন। একটি নতুন destination source-এর active account ও switching preference-ও পায়; একটি প্রতিষ্ঠিত destination নিজেরগুলোই রাখে।

Credential SSH-এর মাধ্যমে যায় এবং destination-এ private file-এ সংরক্ষিত হয়, তাই শুধু আপনার বিশ্বাসের machine-গুলোতেই copy করুন। এটি একবারের copy, চলমান synchronization নয়। Codex refresh token অন্য একটি machine ঘুরিয়ে দিতে পারে, ফলে একটি copied login-এর renewal প্রয়োজন হয়ে পড়ে; একাধিক machine-এ একসঙ্গে ব্যবহারের জন্য আলাদা sign-in-ই সবচেয়ে নির্ভরযোগ্য পছন্দ। দেখুন [Codex's account authentication guidance](https://developers.openai.com/codex/auth/ci-cd-auth)।

প্রতি provider-এ একটি account সক্রিয় থাকে, এবং প্রতিটি নতুন session সেটি হিসেবেই শুরু হয়: `cx`, `cy`, একটি সাধারণ `claude`, `codex`, বা `grok`, `omarchy agent`-এর মাধ্যমে launch করা যেকোনো কিছু, এবং script বা editor যা `PATH`-এ CLI খুঁজে পায়। `omarchy agent account use work` দিয়ে বদলান (এবং `omarchy agent account use main` দিয়ে ফিরে আসুন), অথবা panel-এ একটি account-এর নম্বর চেপে তারপর `Enter` চেপে (অথবা এর Use button-এ click করে)। ইতিমধ্যে চলমান session-গুলো তারা যে account দিয়ে শুরু হয়েছিল সেটিতেই থাকে। Conversation history, settings, skills, এবং plugins account-গুলোর মধ্যে shared থাকে, তাই একই folder-এ `claude --continue` নতুন account-এ আপনি যেখানে থেমেছিলেন সেখান থেকেই শুরু করে।

একাধিক account থাকলে, panel প্রতিটি account-এর limit পাশাপাশি দেখায়, যেখানে সক্রিয়টি চিহ্নিত থাকে। Default হিসেবে সক্রিয় account একটি limit-এর 95% পার হলে Omarchy আপনাকে notify করে, এবং notification-এ click করলে সবচেয়ে বেশি headroom থাকা account-এ চলে যায়। Panel-এ একটি account-এর লাইনে hover করে Use-এর পাশে আসা Autoswitch-এ click করে (অথবা `m` চেপে), অথবা `omarchy agent account mode auto` চালিয়ে, এটিকে নিজে নিজে বদলাতে দিন; এটি চালু থাকাকালীন, Autoswitch Use-এর জায়গা নেয়, এবং এতে আবার click করলে notify করায় ফিরে যায়। Threshold বদলাতে একটি সংখ্যা যোগ করুন, যেমন `omarchy agent account mode auto 90`। প্রতিটি account threshold-এর উপরে থাকলে, আপনি একবারই জানতে পারবেন, কোন account-টি প্রথমে মুক্ত হবে তা সহ। একটি সক্রিয় account তার threshold-এর 15 point-এর মধ্যে থাকলে (default-এ 80%), এর limit প্রতি 15 মিনিটের বদলে প্রতি তিন মিনিটে পরীক্ষা করা হয়।

`omarchy agent account list` প্রতিটি account ও এর সর্বশেষ limit দেখায়, `omarchy agent account remove work` একটিকে ভুলে যায়, এবং `omarchy agent account rename primary Hey` একটির নাম বদলায় (অথবা panel-এ একটি account-এর নামে click করুন)। এই command-গুলো আপনার default agent-এর account-গুলোর উপর কাজ করে; অন্য provider-এ পৌঁছাতে, প্রথমে তার নাম দিন, যেমন `omarchy agent account use codex side`। `~/.claude` বা `~/.codex`-এ আপনার ইতিমধ্যে থাকা login-টি হলো _Main_ account এবং সেটি যেখানে আছে সেখানেই থাকে। প্রায় আট ঘণ্টার বেশি সময় অব্যবহৃত থাকা একটি account _Sign-in required_ দেখাতে পারে; panel-এই সেই account-এ আবার sign in করতে এতে click করুন, অথবা এতে একটি session শুরু করুন, যা নিজে নিজেই sign-in refresh করে। একটি account যোগ করার সময় আপনার থাকা MCP server-গুলো এতে আসে, কিন্তু পরে `claude mcp add` দিয়ে আপনি যেগুলো যোগ করেন সেগুলো শুধু আপনি যে account-এ সেগুলো যোগ করেছিলেন সেটিতেই পৌঁছায়। Claude Desktop এবং একটি CLI binary-র absolute path দিয়ে configured tool-গুলো এই switch অনুসরণ করে না। একটি explicit `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, বা `GROK_HOME` নির্বাচিত account-এর উপর অগ্রাধিকার পায়।

### Crash diagnosis

Process crash-এর জন্য Omarchy systemd-coredump পর্যবেক্ষণ করে। কোনো কিছু segfault করলে, আপনি একটি "Process crashed" notification পাবেন — এতে click করুন, এবং crash-টি আপনার default agent-এর হাতে তুলে দেওয়া হয় Omarchy-র diagnose-crash skill সহ, যা agent-কে core dump থেকে তথ্য প্রতিষ্ঠা করা এবং crash-টি upstream-এ report করার যোগ্য কিনা তা সিদ্ধান্ত নেওয়ার ধাপগুলো দেখিয়ে দেয়। আপনি `coredumpctl list` থেকে যেকোনো PID-এর বিপরীতে `omarchy agent crash <pid>` দিয়ে হাতেও এটি চালাতে পারেন।

এই পর্যবেক্ষণ default হিসেবে চালু থাকে। _Trigger > Toggle > Crash Capture_-এর অধীনে (অথবা `omarchy toggle crash-capture` দিয়ে) এটি বন্ধ করুন এবং notification বন্ধ হয়ে যায়; `omarchy agent crash <pid>` হাতে তখনো কাজ করে।

Crash একবারে একটি program হিসেবেও নীরব করা যায়, যা diagnosis শেষে আপনাকে প্রস্তাব করে। `omarchy crash mute hyprland` শুধু সেই program-টির জন্য notification বন্ধ করে, `omarchy crash mute hyprland off` সেগুলো ফিরিয়ে আনে, এবং `omarchy crash mute` একা চালালে আপনি কী mute করেছেন তা তালিকাভুক্ত করে। এটি binary-র path-কে তার নামের মতোই সানন্দে নেয়, তাই `omarchy crash mute /usr/bin/hyprland` একই কাজ করে। নামে space থাকলে তা quote করুন, যেমন `omarchy crash mute 'Some App'`। বাকি সবকিছু তখনো notify করে, এবং muted program-টি তখনো crash করে — এটি reminder-টি লুকায়, কোনো কিছু ঠিক করে না।

### Desktop apps

_Install > AI_ menu-তে কয়েকটি graphical AI app-ও থাকে: ChatGPT desktop app, Claude desktop app (Anthropic-র Linux beta, Chat, Cowork, এবং Claude Code tab সহ), xAI-এর model-গুলোর সঙ্গে chat করার জন্য Grok Bot, Hermes Desktop, OpenClaw, Perplexity desktop app, এবং T3 Code। Grok Bot হলো desktop chat app। Coding agent হলো `grok` command।

Hermes Desktop সম্পর্কে জানা জরুরি, কারণ একটি machine-এ একটি Hermes থাকে, এবং সেটি app-টির: Hermes সবসময় শুধু app-এর মাধ্যমেই install হয়, এবং default agent যে `hermes` command চালায় সেটি app-টিরই। Default agent হিসেবে Hermes বেছে নেওয়া _Install > AI_ entry যা install করে ঠিক তাই install করে: package-টি, এবং Hermes-এর নিজের installer দিয়ে সেট আপ করা `~/.hermes`-এর অধীনে একটি Hermes runtime, যা প্রথমবার কয়েক মিনিট সময় নেয়। সেই runtime-টিই সেই এক Hermes যা terminal-এর `hermes` command, default agent ও app সবাই ব্যবহার করে, এবং এটি Omarchy release-এর জন্য অপেক্ষা না করে `hermes update` দিয়ে নিজেকে update করে। এটি install করলে Hermes-এর হাতে Omarchy theme-টি `omarchy` নামের একটি skin হিসেবেও তুলে দেওয়া হয়, যা আপনি theme বদলালে প্রতিটি Hermes surface অনুসরণ করে; আপনি তা না চাইলে Hermes-এর Appearance settings-এর অধীনে বা `/skin` দিয়ে অন্য একটি বেছে নিন, এবং Omarchy সেই পছন্দকে তার মতো থাকতে দেয়। _Remove > AI_-এর অধীনে app-টি সরালে প্রথমে Hermes বন্ধ হয়, gateway সহ, সেই runtime-টিকে সঙ্গে নিয়ে যায়, এবং আপনার chat, memory, এবং Hermes নিজের জন্য লেখা skill-গুলো রেখে দেয় যদি না আপনি অন্যথা বলেন: এটি জিজ্ঞাসা করে, default হিসেবে না রেখে, সেই data ও আপনার connection settings-ও যাওয়া উচিত কিনা।

OpenClaw-র desktop experience হলো এর Control UI, যা এর নিজের local gateway দ্বারা backed একটি web app হিসেবে খোলে। OpenClaw `~/.openclaw`-এ থাকে এবং নিজেকে update করে: Control UI-র "Update Gateway" button ব্যবহার করুন অথবা `openclaw update` চালান, এবং gateway নতুন version-এ restart হয়। Omarchy শুধু একটি fresh install কোন release থেকে শুরু হবে তা বেছে নেয়। _Remove > AI_-এর অধীনে OpenClaw সরালে gateway service ও app-টিকে সঙ্গে নিয়ে যায় এবং তারপর জিজ্ঞাসা করে `~/.openclaw`-ও যাওয়া উচিত কিনা, যেহেতু সেখানে OpenClaw নিজে ও এটি download করা plugin runtime-গুলোর পাশাপাশি আপনার chat ও credential থাকে; default হিসেবে এটি রাখা হয়, এবং OpenClaw আবার install করলে সেটি আবার তুলে নেওয়া হয়।

T3 Code একটি package থেকে নয়, `~/.local/share/t3code`-এ এর official AppImage release থেকে চলে, তাই এটি নিজেকে update করে। এটি install করলে জিজ্ঞাসা করা হয় Stable নাকি Nightly channel-এ শুরু করবেন; পরে T3 Code-এর settings-এ বদলান। আপনার thread ও settings `~/.t3`-এ থাকে, এবং _Remove > AI_-এর অধীনে T3 Code সরালে সেগুলো সঙ্গে নিয়ে যায়।

### Local models

আপনার coding agent-গুলোর জন্য নিজের machine-এ একটি open model চালান। আপনার prompt ও code machine-এই থাকে; model-এ পাঠানো কোনো কিছুই এটি ছেড়ে যায় না। শুরু করুন এভাবে:

```bash
omarchy agent local use best
```

অথবা, top bar-এর agents panel-এ + বেছে নিয়ে তারপর Local AI বেছে নিন, যা এই machine-এ একটি model মানানসই হলে দেখা যায়। প্রথমবার, এটি Podman install করে, যা model-গুলো চালায়। এরপর Omarchy এই machine-এর জন্য recommended model বেছে নেয়, সেটি download করে, এবং শুরু করে। Tens of GB-এর একটি download এবং model চলার সময় machine-এর বেশিরভাগ memory ব্যবহৃত হওয়ার প্রত্যাশা করুন: Flash Next তার পুরো 256K context সহ প্রায় 100 GiB ব্যবহার করে। অন্য model-গুলো এর প্রয়োজনীয় memory ধরে রাখলে, এটি stopped অবস্থায় সেট আপ হয়, আপনি একটি বন্ধ করলেই শুরু হওয়ার জন্য প্রস্তুত থাকে। Model-টি logout-এ বন্ধ হয়; অন্য কিছুর জন্য memory প্রয়োজন হলে নিজে এটি বন্ধ করুন।

`omarchy agent local list` বিকল্পগুলো দেখায় এবং ব্যাখ্যা করে কেন কিছু মানানসই নয়। আরেকটি সেট আপ করতে `omarchy agent local use <recipe>` চালান। আজ, 128 GB Strix Halo machine-গুলোর জন্য `qwen3.8-flash-next-halogen` ও `qwen3.8-27b-gufo` পাওয়া যাচ্ছে। নতুন recipe ও recommendation package-এর মাধ্যমে `omarchy update`-এর সঙ্গে আসে।

আপনি সেট আপ করা প্রতিটি model agents panel-এ নিজের একটি লাইন পায়, আপনার subscription-গুলোর পাশে: এটি শুরু করতে play, এটি বন্ধ করে এর memory মুক্ত করতে pause, এবং এতে আপনার agent খুলতে terminal button। Memory-তে একসঙ্গে মানানসই হলে একাধিক একসঙ্গে চলতে পারে; একটি মানানসই না হলে, Omarchy বলে কোন চলমান model-টি বন্ধ করতে হবে। সেগুলো পুনর্বিন্যাস করতে লাইন drag করুন, এবং একটি model ও এর download সরাতে একটি নির্বাচিত লাইনে Delete চাপুন।

Command line থেকে, `omarchy agent local start <recipe>` ও `omarchy agent local stop <recipe>` একই কাজ করে, `omarchy agent local status` প্রতিটি model দেখায়, এবং `omarchy agent --local` আপনার সর্বশেষ শুরু করা model-এ আপনার default agent খোলে (আপনার default agent একটি local model ব্যবহার করতে না পারলে pi)। যেকোনো OpenAI-compatible client-ও সংযোগ করতে পারে: `status` প্রতিটি model-এর address দেখায় (প্রথমটি `http://127.0.0.1:11435/v1`), recipe-র নামই model, এবং key-টি `~/.config/omarchy/agent-local/key`-তে থাকে।

`omarchy agent local remove <recipe>` একটি model এবং অন্য কোনো model ব্যবহার করে না এমন download-গুলো delete করে।

Third-party runtime-গুলো তাদের publisher দিয়ে labeled থাকে। Omarchy প্রতিটি model কোনো network access ছাড়াই চালায়।

### Local LLMs

Local LLM model চালানোর দুটি উপায় Omarchy সুপারিশ করে: LM Studio ও Ollama। LM Studio open-weight model খোঁজা, সেগুলো install করা, এবং চালানোর জন্য একটি GUI interface দেয়। সহজে শুরু করার এটি একটি দারুণ উপায়। Ollama একইভাবে করার জন্য একটি CLI দেয়। কিন্তু আপনি local model-এ নতুন হলে, আমি LM Studio দিয়ে শুরু করতাম। Omarchy Menu-তে _Install > AI_-এর অধীনে যেকোনো একটি install করতে পারেন।

### The Omarchy Skill

Agent skill AI-কে নির্দিষ্ট tool নির্দিষ্ট উপায়ে ব্যবহার করতে সাহায্য করে, এবং system-টি tailor করার জন্য Omarchy একটি default skill সহ আসে। যেমন আপনার Hyprland config tweak করা, bar adjust করা, বা এমনকি একদম শুরু থেকে একটি নতুন theme তৈরি করা। এটি Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` এবং প্রতিটি `~/.hermes/profiles/*/skills`), এবং generic `~/.agents/skills` location-এর skill directory-গুলোতে symlink করা থাকে, তাই বেশিরভাগ harness এটি স্বয়ংক্রিয়ভাবে তুলে নেয়।

কিন্তু এই skill-টিকে আপনার experimental হিসেবে বিবেচনা করা উচিত। বিভিন্ন model এটিকে বিভিন্ন মাত্রায় কাজে লাগাবে। প্রথমে plan mode-এ চালানোই সবচেয়ে ভালো, যাতে agent কী বদলাতে চায় সে সম্পর্কে আপনার ধারণা থাকে। এবং তারপর পরিবর্তন rollback করতে বা এমনকি `omarchy reinstall configs` invoke করতেও প্রস্তুত থাকুন, যদি agent সবকিছু এলোমেলো করে ফেলে।
