# AI

Omarchy আপনার জন্য ডিফল্ট বেছে না দিয়েই নিচের কোডিং এজেন্টগুলোর লঞ্চার অন্তর্ভুক্ত করে। প্রথমবার ব্যবহারের সময় এর CLI ইনস্টল করতে একটি কমান্ড চালান, তারপর জিজ্ঞাসা করা হলে প্রমাণীকরণ করুন। Hermes এবং OpenClaw ব্যতিক্রম: mise-এর মাধ্যমে এদের জন্য কিছুই ইনস্টল করা হয় না, এবং যেকোনো একটিকে বেছে নিলে এটি নিজস্ব স্ব-আপডেট হওয়া কপি সেট আপ করে, যেমনটা নিচে _Desktop apps_ ব্যাখ্যা করে।

### এজেন্ট ইনস্টল ও আপডেট করা

Hermes এবং OpenClaw ছাড়া, এই এজেন্টগুলো mise-এর lazy ইনস্টলেশন ব্যবহার করে: প্রথম চালু হওয়ায় CLI ইনস্টল হয়, এবং পরবর্তী চালু হওয়াগুলো সেটিই পুনরায় ব্যবহার করে। mise একটি ইনস্টল করা এজেন্টের নতুন রিলিজের জন্য সর্বোচ্চ প্রতি চার ঘণ্টায় একবার পরীক্ষা করে, এটি শুরু হওয়ার ঠিক আগে বা shell prompt-এ ব্যাকগ্রাউন্ডে। সেই আপডেট ব্যর্থ হলে বা আপনি অফলাইনে থাকলে, ইনস্টল করা সংস্করণটি চলে। `omarchy update` বাকি Omarchy-এর সঙ্গে ইনস্টল করা এজেন্টগুলো আপডেট করে, এবং `mup` শুধু mise-পরিচালিত টুলগুলো আপডেট করে।

একটি এজেন্টের নিজস্ব আপডেটার, যেমন `claude update`, `codex update`, বা কোনো অ্যাপের আপডেট বোতাম, mise-পরিচালিত ইনস্টলটি আপডেট করে না। `codex update` ব্যর্থ হয়, এবং `claude update` সফল হয়েছে বলে জানাতে পারে, অথচ এমন একটি আলাদা কপি ইনস্টল করে যা mise ট্র্যাক করে না। আপনি যদি বরং কোনো এজেন্টের নিজস্ব ইনস্টলার ও আপডেটার ব্যবহার করতে চান, সেটিকে `disable_tools`-এ যোগ করুন; দেখুন [Preinstalled CLI tools](18-development-tools.md#preinstalled-cli-tools)।

আপনার প্রয়োজন হওয়ার আগেই সব কনফিগার করা lazy টুল ইনস্টল করতে, `mise install --include-lazy` চালান। এতে এজেন্টগুলোর পাশাপাশি Omarchy-এর অন্যান্য ডিফল্ট CLI টুলও অন্তর্ভুক্ত থাকে। একটি একক টুল ইনস্টল করা বা নিজস্ব ইনস্টলেশন ব্যবহার করার জন্য দেখুন [Preinstalled CLI tools](18-development-tools.md#preinstalled-cli-tools)।

`grok` mise-এর ফার্স্ট-পার্টি `grok` প্যাকেজের মাধ্যমে ইনস্টল করা হয়, `claude` এবং `codex`-এর মতোই। `grok` চালান, বা এজেন্ট প্যানেলে এটিকে স্টার করুন। x.ai-তে থাকা `curl | bash` ইনস্টলারটি এড়িয়ে যান। সেই পথটি `~/.grok/bin`-এ দ্বিতীয় একটি কপি রাখে, সেটিকে `PATH`-এর সামনে যোগ করে, এবং Omarchy-এর wrapper-কে ওভাররাইট করে।

`dsh` তার browser UI `127.0.0.1:3080`-এ খোলে, যেখানে লঞ্চ ডিরেক্টরিটি তার ডিফল্ট workspace হিসেবে থাকে। এর browser UI কোনো শুরুর prompt নেয় না, তাই `omarchy agent prompt` এটিকে আপনার clipboard-এ থাকা prompt সহ খোলে, যাতে আপনি পেস্ট করতে পারেন। Omarchy এটিকে DeepSeek-এর no-approval permission preset দিয়ে শুরু করে। আপনি যখন এর অফিসিয়াল মডেল API ব্যবহার করেন, DeepSeek Harness সেশন লগ DeepSeek-এ আপলোড করে; এর browser UI-তে _Settings > General > Upload Session Log_-এর অধীনে সেটি বন্ধ করুন। আপনি এতে যে ফিডব্যাক পাঠান তাও সেশনের সঙ্গে আপলোড হয়, যদি না আপনি এটিকে `DSH_TELEMETRY_MODE=DISABLED` দিয়ে শুরু করেন।

### ডিফল্ট এজেন্ট

এজেন্ট প্যানেলে কোনো এজেন্টের পাশের স্টার দিয়ে আপনার ডিফল্ট এজেন্ট বেছে নিন, যা ডিফল্টের ক্ষেত্রে পূর্ণ থাকে, অথবা `omarchy default agent <name>` দিয়ে, যা সেখানে লাইন নেই এমন যেকোনো harness-ও নেয়। এজেন্টটি এখনো ইনস্টল করা না থাকলে, সেটি বেছে নিলে প্রথমে সেটি ইনস্টল হয়, এবং এটি app launcher-এ Agent-এর পাশে নিজস্ব একটি লঞ্চারও পায়। একটি নতুন Omarchy আপনাকে একবারের বিজ্ঞপ্তি দিয়ে একটি সেট আপ করার আমন্ত্রণ জানায়, যা এজেন্ট প্যানেল খোলে।

Claude বেছে নিলে Chromium, Chrome, Brave, Brave Origin, এবং Edge-এর জন্য এর browser extension সেট আপ করারও চেষ্টা করা হয়। extension সেটআপটি সব ব্যবহারকারীর জন্য প্রযোজ্য হয় এবং আপনার system password চাইতে পারে; বাতিল করা বা extension ইনস্টল ব্যর্থ হলেও Claude নির্বাচিত হয় এবং চালু হয়। আপনার ব্রাউজার পুনরায় চালু করুন, জিজ্ঞাসা করা হলে extensionটি সক্রিয় করুন, এবং সংযোগটি সম্পূর্ণ করতে Claude-এ সাইন ইন করুন। সংযোগ পরীক্ষা করতে Claude-এ `/chrome` চালান। Firefox এবং Zen এই extension সমর্থন করে না। এই সেটআপ যোগ হওয়ার আগেই Claude যদি ইতিমধ্যে আপনার ডিফল্ট হয়ে থাকে, extension ইনস্টল করতে সেটিকে আবার নির্বাচন করুন।

আপনি বেছে নেওয়ার পর, `Super + Shift + Ctrl + A` একটি নির্দিষ্ট terminal window-তে ডিফল্ট এজেন্ট চালু করে (অথবা আপনি এখনো বেছে না নিয়ে থাকলে pickerটি নিয়ে আসে)। আপনি `omarchy agent prompt "Review this project"` দিয়ে এটিকে সরাসরি একটি কাজেও চালু করতে পারেন। Freebuff এবং DeepSeek Harness কোনো শুরুর prompt নেয় না, তাই সেগুলো এর পরিবর্তে আপনার clipboard-এ থাকা prompt সহ খোলে, যাতে আপনি পেস্ট করতে পারেন। এভাবে চালু করা এজেন্টগুলো তাদের নিজ নিজ don't-stop-to-ask মোডে অমনোযোগে চলে, তাই তারা সত্যিই কিছু করে ফেলবে—এর জন্য প্রস্তুত থাকুন! MiniMax Code-এর ইন্টারঅ্যাক্টিভ সেশনগুলোর জন্য এমন কোনো মোড নেই, তাই এটি যথারীতি অনুমতি চায়। এবং যেহেতু এজেন্টগুলো আপনার home directory-এর জন্য trust মনে রাখতে অস্বীকার করে, `$HOME` থেকে চালু হওয়াগুলো এর পরিবর্তে `~/Work`-এ শুরু হয়।

terminal shortcut-ও আছে: `a` বর্তমান terminal-এ ডিফল্ট এজেন্টকে inline চালায়, আর `c`, `cx`, এবং `cy` সরাসরি OpenCode, Claude Code, এবং Codex শুরু করে (আবারও তাদের auto-approving মোডে)। থিম পরিবর্তনও এজেন্টগুলোর সঙ্গে সিঙ্ক হয়: আপনি Omarchy থিম বদলালে Claude Code, Pi, OpenCode, এবং Hermes (Omarchy একবার এটি ইনস্টল করার পর) সবাই অনুসরণ করে।

### আপনার এজেন্ট নির্দেশাবলী

প্রতিটি এজেন্টের জন্য ব্যক্তিগত নিয়ম `~/.agents/AGENTS.md`-তে যায়, `~/.agents/skills`-এ থাকা শেয়ার করা skills-এর পাশে। এজেন্ট প্যানেলে +-এর পাশের document আইকন দিয়ে এটি খুলুন, অথবা `omarchy agent instructions --edit` দিয়ে, যা এটিকে প্রতিটি harness-এর সঙ্গে লিঙ্কও করে, যারা নিজস্ব global ফাইল রাখে: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, Copilot-এর `~/.copilot/copilot-instructions.md`, এবং আরও অনেক কিছু। Crush এবং Amp `~/.config/AGENTS.md` লিঙ্কটি পড়ে, আর omp, Kimi, এবং DeepSeek Harness সরাসরি `~/.agents/AGENTS.md` পড়ে। একটি ডিফল্ট এজেন্ট বেছে নিলে সেটিও লিঙ্ক হয়। আপনার আগে থেকে থাকা একটি instructions ফাইল, যদি এখনো কোনো শেয়ার করা ফাইল না থাকে, তাহলে শেয়ার করা ফাইলটিতে পরিণত হয়; অন্যথায় সেটিকে লিঙ্কের পাশে `.bak` হিসেবে রাখা হয়। আরেকটি এজেন্ট ইনস্টল করার পর পুনরায় লিঙ্ক করতে `omarchy agent instructions` চালান।

### এজেন্ট প্যানেল

শীর্ষ বারে একটি এজেন্ট আইকন আছে। আপনি কোনো এজেন্ট সেট আপ করার আগে, এর প্যানেল শুরু করার তিনটি উপায় দেয়: একটি Claude, Codex, Grok, Gemini, Muse, Cursor, বা Copilot সাবস্ক্রিপশনে সাইন ইন করুন, অথবা More-এর অধীনে একটি OpenCode Go, MiniMax, Synthetic, বা Z.ai কোডিং প্ল্যানে; Fireworks, OpenCode Zen and Go, OpenRouter দিয়ে, অথবা More-এর অধীনে DeepSeek বা OpenCode যেসব provider-এ সাইন ইন করে তাদের অন্য যেকোনোটি দিয়ে pay as you go করুন, সবই OpenCode-এ চলে; অথবা আপনার কম্পিউটারের জন্য সেরা মডেলটি চালান, যখন কোনোটি এতে মানানসই হয়। আপনি যেটি প্রথম শেষ করবেন সেটি আপনার ডিফল্ট এজেন্ট হয়ে যায়, এবং প্যানেলের + পরে একই তিনটি উপায় দেয়। এরপর, প্যানেল প্রতিটি সাবস্ক্রিপশনকে এক পৃষ্ঠায় রাখে: প্রতিটি এজেন্ট ও অ্যাকাউন্ট তার প্ল্যানসহ, এর 5-hour session এবং weekly সীমার প্রতিটির জন্য একটি মিটার, রিসেট হওয়া পর্যন্ত বাকি সময়সহ (সঠিক শতাংশের জন্য hover করুন), অথবা বাকি prepaid ব্যালেন্স, একটি লাইনের অধীনে যা আপনি সবগুলো মিলিয়ে যা ব্যবহার করেছেন তার মধ্য দিয়ে ঘুরতে থাকে, যেমন এই সপ্তাহের টোকেন এবং আপনার সবচেয়ে বেশি ব্যবহৃত মডেল। _Make something cool_-এর অধীনে এটি একটি নতুন থিম, plugin, app, বা game-এর জন্য starter prompt দেয়, যা কাজটি আপনার ডিফল্ট এজেন্টের হাতে তুলে দেয়। অ্যাপগুলো Omarchy-এর নিজস্ব Hype, Monologue, এবং Omacut যেভাবে তৈরি, সেভাবেই C++ এবং Qt Quick-এ তৈরি হয়, omarchy-make-app agent skill অনুসরণ করে, এবং তাদের প্রয়োজনীয় compiler ও Qt অংশগুলো ইনস্টল করা অবস্থায় আসে। গেমগুলো `~/Games/vibes`-এ থাকা একটি একক three.js পৃষ্ঠা, omarchy-make-game agent skill অনুসরণ করে, এবং সবগুলো বর্তমান থিমে একটি Game Vibes লঞ্চার থেকে খোলে; তারা ওয়েব থেকে three.js লোড করে, তাই শুরু হতে তাদের সংযোগ প্রয়োজন। Claude Code, Codex, Grok, Kimi, Cursor এবং এর Grok Bot ভাতা, GitHub Copilot, Muse, Gemini (Antigravity-এর মাধ্যমে), এবং Devin তাদের সীমাসহ বাক্স থেকে বেরিয়েই কভার করা হয়, Kimchi তার প্ল্যান, prepaid credits, এবং spend budgetsসহ, এবং Hermes, Mistral Vibe, এবং Qwen Code আপনি সেগুলো ব্যবহার করার পর তাদের সেশন ও টোকেন দেখায়। pi, omp, বা opencode-এর মাধ্যমে আপনি যেসব provider প্ল্যান ও কী ব্যবহার করেন সেগুলোও দেখা যায়: OpenCode Zen and Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan, এবং Synthetic তাদের সীমাসহ; OpenRouter এবং DeepSeek তাদের prepaid ব্যালেন্সসহ; Fireworks গত 30 দিনে এর খরচসহ। আপনি নিজস্ব হার্ডওয়্যারে যেসব মডেল চালান সেগুলোর টোকেনও মোটের দিকে গণনা করা হয়; মডেলগুলোর নিজস্ব একটি প্যানেল আছে, যা [Local models](#local-models)-এর অধীনে বর্ণনা করা হয়েছে। প্রতিটি এজেন্ট একবারই গণনা করা হয়, যে-ই তাকে বিল করুক না কেন, আপনি যতগুলো harness দিয়েই তাকে চালান না কেন।

প্যানেলের জন্য বার আইকনে বাম-ক্লিক করুন বা `Super + Ctrl + X` চাপুন, আপনার ডিফল্ট এজেন্ট চালু করতে ডান-ক্লিক করুন, এবং রিফ্রেশ করতে মাঝখানে-ক্লিক করুন। এর পেছনের usage রেকর্ডগুলো প্রতি 15 মিনিটে `omarchy agent usage update` দ্বারা পুনরায় তৈরি হয়, এবং প্যানেল একটি সিঙ্ক করা ফোল্ডারের মাধ্যমে আপনার অন্য মেশিনগুলো থেকে usage মার্জও করতে পারে। সম্পূর্ণ সেটিংসের জন্য `$OMARCHY_PATH/shell/plugins/agents/`-এর অধীনে README দেখুন।

### একাধিক সাবস্ক্রিপশন

আপনি যদি একাধিক Claude, Codex, বা Grok প্ল্যানের জন্য অর্থ প্রদান করেন—ধরুন একটি ব্যক্তিগত Max এবং একটি কাজের—Omarchy সেগুলো সব সাইন ইন অবস্থায় রাখতে পারে এবং তাদের মধ্যে যাতায়াত করতে পারে। এজেন্ট প্যানেলে + দিয়ে একটি সাবস্ক্রিপশন যোগ করুন, যা আপনাকে সেখানেই ধাপে ধাপে নিয়ে যায়, অথবা `omarchy agent account add claude Work` দিয়ে (অথবা `codex`, অথবা `grok`)। একই + এবং কমান্ড Gemini (`gemini`) এবং OpenCode (`opencode`)-এ সাইন ইন করে, এবং OpenCode-এ একটি Fireworks (`fireworks`) বা OpenRouter (`openrouter`) API key সংরক্ষণ করে; কমান্ডটি Copilot (`copilot`), Cursor (`cursor`), এবং Muse (`muse`)-এও সাইন ইন করে। সেগুলো প্রত্যেকে একটি করে সাইন-ইন রাখে। CLI অনুপস্থিত থাকলে এটি সেটি ইনস্টল করে। কোনো provider-এর জন্য প্রথম অ্যাকাউন্টটি আপনার সাধারণ ব্রাউজারের মাধ্যমে সাইন ইন করে, ঠিক যেখানে CLI সবসময় খোঁজে। এরপরের প্রতিটি একটি private window-এর মাধ্যমে সাইন ইন করে, যাতে আপনার ব্রাউজার ইতিমধ্যে যে অ্যাকাউন্টে সাইন ইন আছে তা ভুল করে নেওয়া না হয়; সেখানে আপনি যে অ্যাকাউন্টটি যোগ করছেন হিসাবে সাইন ইন করুন, এবং আগে থেকে খোলা থাকা যেকোনো private window প্রথমে বন্ধ করুন। এটি করতে কখনো CLI থেকে লগ আউট করবেন না: লগ আউট করলে সংরক্ষিত সাইন-ইন বাতিল হয়ে যায়, এবং সেই অ্যাকাউন্টটিকে আবার যোগ করতে হবে।

SSH-এর মাধ্যমে আপনার সাবস্ক্রিপশন লগইনগুলো অন্য একটি Omarchy মেশিনে কপি করতে, `omarchy agent account copy user@laptop` চালান। গন্তব্যে একটি ইনস্টল করা না থাকলে প্রেরক একটি অস্থায়ী receiver সরবরাহ করে, তাই পুরনো Omarchy মেশিনগুলো আপডেট ছাড়াই অ্যাকাউন্ট গ্রহণ করতে পারে। ইনস্টল করা receiverগুলো অগ্রাধিকার পায়। এটি সব Claude, Codex, এবং Grok সাবস্ক্রিপশন কপি করে; সেগুলো নির্বাচন করতে provider-এর নাম যোগ করুন, যেমন `omarchy agent account copy laptop claude`। অ্যাকাউন্টের নাম এবং কমান্ড ID উৎসের সঙ্গে মেলে, গন্তব্যে ইতিমধ্যে থাকা অ্যাকাউন্টগুলোসহ। সম্পর্কহীন গন্তব্য অ্যাকাউন্টগুলোর নামে সংঘাত হলে তারা একটি সংখ্যাসূচক suffix পায়, এবং সেটিংস, skills, plugins, এবং conversation history প্রতিটি মেশিনে স্থানীয় থাকে।

গন্তব্যের বিদ্যমান credentials রাখা হয়। সেখানে ইতিমধ্যে সাইন ইন থাকা একটি উৎস অ্যাকাউন্টের নাম তার credentials প্রতিস্থাপন না করেই সিঙ্ক্রোনাইজ করা হয়; অন্য অ্যাকাউন্টগুলো এর পাশাপাশি যোগ করা হয়। মিলে যাওয়া অ্যাকাউন্টগুলোর জন্য সংরক্ষিত credentials প্রতিস্থাপন করতে, গন্তব্যে সেই অ্যাকাউন্টের সেশনগুলো বন্ধ করার পর `omarchy agent account copy --replace laptop claude` ব্যবহার করুন। একটি নতুন গন্তব্য উৎসের সক্রিয় অ্যাকাউন্ট এবং switching পছন্দগুলোও পায়; একটি প্রতিষ্ঠিত গন্তব্য তার নিজস্বগুলো রাখে।

Credentials SSH-এর মাধ্যমে যাতায়াত করে এবং গন্তব্যে private ফাইলে সংরক্ষণ করা হয়, তাই শুধু আপনার বিশ্বাসের মেশিনগুলোতেই কপি করুন। এটি একবারের কপি, চলমান সিঙ্ক্রোনাইজেশন নয়। Codex refresh টোকেন অন্য একটি মেশিন দ্বারা rotate করা হতে পারে, যাতে একটি কপি করা লগইনের নবায়ন প্রয়োজন হয়; একাধিক মেশিনে একসঙ্গে ব্যবহারের জন্য আলাদা সাইন-ইনই সবচেয়ে নির্ভরযোগ্য পছন্দ থাকে। দেখুন [Codex's account authentication guidance](https://developers.openai.com/codex/auth/ci-cd-auth)।

প্রতি provider-এ একটি অ্যাকাউন্ট সক্রিয় থাকে, এবং প্রতিটি নতুন সেশন সেটি হিসাবেই শুরু হয়: `cx`, `cy`, একটি সাধারণ `claude`, `codex`, বা `grok`, `omarchy agent`-এর মাধ্যমে চালু হওয়া যেকোনো কিছু, এবং scripts বা editors যা `PATH`-এ CLI খুঁজে পায়। `omarchy agent account use work` দিয়ে বদলান (এবং `omarchy agent account use main` দিয়ে ফিরে আসুন), অথবা প্যানেলে একটি অ্যাকাউন্টের নম্বর চেপে তারপর `Enter` চেপে (অথবা এর স্টারে ক্লিক করে)। চালু থাকা Claude সেশনগুলোও বদলায়, তাদের পরবর্তী বার্তা থেকে: প্রতিটি Claude সেশন `~/.claude`-এ চলে, যা সবসময় সক্রিয় অ্যাকাউন্টের সাইন-ইন ধরে রাখে। পুরনো Omarchy দ্বারা কোনো অ্যাকাউন্টের নিজস্ব ফোল্ডারে শুরু করা একটি Claude সেশন, সেটি বন্ধ না হওয়া পর্যন্ত সেই সাইন-ইন ধরে রাখে, তাই switch সেই সেশনগুলোর নাম দেয় এবং সেগুলো চলে গেলে নিজে নিজেই শেষ হয়। চালু থাকা Codex এবং Grok সেশনগুলো যে অ্যাকাউন্ট দিয়ে শুরু হয়েছিল তাতেই থাকে। Conversation history, সেটিংস, skills, এবং plugins অ্যাকাউন্টগুলোর মধ্যে শেয়ার করা হয়, তাই একই ফোল্ডারে `claude --continue` নতুন অ্যাকাউন্টে যেখানে ছেড়েছিলেন সেখান থেকেই শুরু করে।

একাধিক অ্যাকাউন্ট থাকলে, প্যানেল প্রতিটি অ্যাকাউন্টের সীমা পাশাপাশি দেখায়, যেটি ব্যবহৃত হচ্ছে তাতে একটি পূর্ণ স্টারসহ। সক্রিয় অ্যাকাউন্ট কোনো সীমার 95% অতিক্রম করলে Omarchy আপনাকে জানায়, এবং বিজ্ঞপ্তিতে ক্লিক করলে সবচেয়ে বেশি headroom থাকা অ্যাকাউন্টে বদলে যায়। এটি কখনো নিজে নিজে বদলায় না। `omarchy agent account threshold 90` দিয়ে threshold বদলান। প্রতিটি অ্যাকাউন্ট threshold-এর উপরে থাকলে, আপনি একবারই তা শুনতে পাবেন, কোন অ্যাকাউন্টটি প্রথম মুক্ত হবে তার সঙ্গেই। একটি সক্রিয় অ্যাকাউন্ট তার threshold-এর 15 পয়েন্টের মধ্যে থাকলে (ডিফল্টে 80%), তার সীমাগুলো প্রতি 15 মিনিটের বদলে প্রতি তিন মিনিটে পরীক্ষা করা হয়।

`omarchy agent account list` প্রতিটি অ্যাকাউন্ট এবং তার সর্বশেষ সীমা দেখায়, `omarchy agent account remove work` একটিকে ভুলে যায়, এবং `omarchy agent account rename primary Hey` একটির নাম বদলায় (অথবা প্যানেলে একটি অ্যাকাউন্টের নামে ক্লিক করুন)। এই কমান্ডগুলো আপনার ডিফল্ট এজেন্টের অ্যাকাউন্টগুলোতে কাজ করে; অন্য provider-এর কাছে পৌঁছাতে, প্রথমে তার নাম দিন, যেমন `omarchy agent account use codex side`। `~/.claude` বা `~/.codex`-এ আপনার আগে থেকে থাকা লগইনটি হলো _Main_ অ্যাকাউন্ট। Codex-এরটি যেখানে আছে সেখানেই থাকে; অন্য একটি অ্যাকাউন্ট সক্রিয় থাকলে Claude-এরটি তার নিজস্ব একটি ফোল্ডারে অপেক্ষা করে। প্রায় আট ঘণ্টার বেশি অব্যবহৃত থাকা একটি অ্যাকাউন্ট _Sign-in required_ দেখাতে পারে; প্যানেলেই সেই অ্যাকাউন্টে আবার সাইন ইন করতে এটিতে ক্লিক করুন, অথবা এটিতে বদলে একটি সেশন শুরু করুন, যা নিজে নিজেই সাইন-ইন রিফ্রেশ করে। আপনি `claude mcp add` দিয়ে যেসব MCP server যোগ করেন তা প্রতিটি Claude অ্যাকাউন্টে পৌঁছায়, যেহেতু তারা সবাই `~/.claude`-এ চলে; Codex এবং Grok-এর জন্য, কোনো অ্যাকাউন্ট যোগ করার সময় আপনার থাকা serverগুলো তাতে আসে, কিন্তু পরেরগুলো শুধু আপনি যেই অ্যাকাউন্টে সেগুলো যোগ করেছিলেন তাতেই পৌঁছায়। Claude Desktop নিজস্ব একটি সাইন-ইন রাখে, এবং একটি CLI binary-এর absolute path দিয়ে কনফিগার করা Codex বা Grok টুলগুলো switch অনুসরণ করে না। একটি স্পষ্ট `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, বা `GROK_HOME` নির্বাচিত অ্যাকাউন্টের উপরে অগ্রাধিকার পায়।

### ক্র্যাশ নির্ণয়

Omarchy process crash-এর জন্য systemd-coredump পর্যবেক্ষণ করে। আপনি একটি ডিফল্ট এজেন্ট বেছে নেওয়ার পর, আপনার যেকোনো প্রোগ্রাম core dump করলে একটি "Process crashed" বিজ্ঞপ্তি আসে—এটিতে ক্লিক করুন, এবং ক্র্যাশটি আপনার ডিফল্ট এজেন্টের হাতে Omarchy-এর omarchy-diagnose-crash skillসহ তুলে দেওয়া হয়, যা এজেন্টকে core dump থেকে তথ্য প্রতিষ্ঠা করা এবং ক্র্যাশটি upstream-এ রিপোর্ট করার মতো কিনা তা সিদ্ধান্ত নেওয়ার মধ্য দিয়ে নিয়ে যায়। আপনি `coredumpctl list` থেকে যেকোনো PID-এর বিপরীতে `omarchy agent crash <pid>` দিয়ে এটি হাতেও চালাতে পারেন।

পর্যবেক্ষণটি ডিফল্টভাবে চালু থাকে। _Trigger > Toggle > Crash Capture Off_-এর অধীনে এটি বন্ধ করুন (অথবা `omarchy toggle crash-capture` দিয়ে) এবং বিজ্ঞপ্তি বন্ধ হয়ে যাবে; `omarchy agent crash <pid>` তখনো হাতে কাজ করে।

ক্র্যাশগুলো একবারে একটি প্রোগ্রাম করেও নীরব করা যায়, যা নির্ণয় শেষে আপনাকে দেয়। `omarchy crash mute hyprland` শুধু সেই প্রোগ্রামটির জন্য বিজ্ঞপ্তি বন্ধ করে, `omarchy crash mute hyprland off` সেগুলো ফিরিয়ে আনে, এবং `omarchy crash mute` নিজে নিজে আপনি যা mute করেছেন তা তালিকাভুক্ত করে। এটি binary-এর path নামের মতোই আনন্দের সঙ্গে নেয়, তাই `omarchy crash mute /usr/bin/hyprland` একই কাজ করে। নামে space থাকলে তা quote করুন, যেমন `omarchy crash mute 'Some App'`। বাকি সবকিছু তখনো জানায়, এবং muted প্রোগ্রামটি তখনো ক্র্যাশ করে—এটি অনুস্মারকটি লুকায়, এটি কিছু ঠিক করে না।

### ডেস্কটপ অ্যাপ

_Install > AI_ মেনুতে কয়েকটি graphical AI অ্যাপও থাকে: Amp Desktop, Antigravity Desktop, ChatGPT desktop app, Claude desktop app (Anthropic-এর Linux beta, Chat, Cowork, এবং Claude Code ট্যাবসহ), Grok Bot xAI-এর মডেলগুলোর সঙ্গে চ্যাট করার জন্য, Herdr Desktop, Hermes Desktop, OpenClaw, Perplexity desktop app, এবং T3 Code। Grok Bot হলো ডেস্কটপ চ্যাট অ্যাপ। কোডিং এজেন্ট হলো `grok` কমান্ড।

Hermes Desktop সম্পর্কে জানা দরকার, কারণ একটি মেশিনে একটি Hermes থাকে, এবং তা হলো অ্যাপেরটি: Hermes কেবল অ্যাপের মাধ্যমেই ইনস্টল হয়, এবং ডিফল্ট এজেন্ট যে `hermes` কমান্ড চালায় তা অ্যাপেরটি। Hermes-কে ডিফল্ট এজেন্ট হিসাবে বেছে নিলে _Install > AI_ এন্ট্রি যা করে ঠিক তাই ইনস্টল হয়: প্যাকেজটি, এবং Hermes-এর নিজস্ব ইনস্টলার দ্বারা সেট আপ করা `~/.hermes`-এর অধীনে একটি Hermes runtime, যা প্রথমবার কয়েক মিনিট সময় নেয়। সেই runtimeটিই হলো সেই একটি Hermes যা terminal `hermes` কমান্ড, ডিফল্ট এজেন্ট এবং অ্যাপ সবাই ব্যবহার করে, এবং এটি Omarchy রিলিজের জন্য অপেক্ষা না করে `hermes update` দিয়ে নিজেকে আপডেট করে। এটি ইনস্টল করলে Hermes-কে Omarchy থিমও `omarchy` নামের একটি skin হিসাবে দেওয়া হয়, যা আপনি থিম বদলালে প্রতিটি Hermes surface অনুসরণ করে; আপনি যদি তা না চান তাহলে Hermes-এর Appearance সেটিংসের অধীনে বা `/skin` দিয়ে অন্যটি বেছে নিন, এবং Omarchy সেই পছন্দকে একা ছেড়ে দেয়। _Remove > AI_-এর অধীনে অ্যাপটি সরালে প্রথমে Hermes বন্ধ হয়, gatewayসহ, সেই runtimeটিকে সঙ্গে নিয়ে যায়, এবং আপনার চ্যাট, স্মৃতি, এবং Hermes নিজের জন্য যেসব skill লিখেছিল তা রাখে, যদি না আপনি অন্যথা বলেন: এটি জিজ্ঞাসা করে, ডিফল্টভাবে no ধরে, সেই ডেটা এবং আপনার connection সেটিংসও যাবে কিনা।

OpenClaw-এর ডেস্কটপ অভিজ্ঞতা হলো এর Control UI, যা এর নিজস্ব স্থানীয় gateway দ্বারা সমর্থিত একটি web app হিসাবে খোলে। OpenClaw `~/.openclaw`-তে থাকে এবং নিজেকে আপডেট করে: Control UI-এর "Update Gateway" বোতাম ব্যবহার করুন বা `openclaw update` চালান, এবং gateway নতুন সংস্করণে পুনরায় চালু হয়। Omarchy কেবল একটি নতুন ইনস্টল কোন রিলিজ থেকে শুরু হবে তা বেছে দেয়। OpenClaw আপনার ডিফল্ট এজেন্টও হতে পারে: `omarchy default agent openclaw` দিয়ে এটি বেছে নিলে `~/.openclaw`-তে সেই একই কপি সেট আপ হয়, এবং এজেন্টটি তার gateway-এর সঙ্গে সংযুক্ত OpenClaw-এর terminal UI খোলে। _Remove > AI_-এর অধীনে OpenClaw সরালে gateway service এবং অ্যাপটিকে সঙ্গে নিয়ে যায় এবং তারপর জিজ্ঞাসা করে `~/.openclaw`-ও যাবে কিনা, যেহেতু তাতে OpenClaw নিজে এবং এটি যেসব plugin runtime ডাউনলোড করে তার পাশাপাশি আপনার চ্যাট ও credentials থাকে; ডিফল্টভাবে এটি রাখা হয়, এবং OpenClaw আবার ইনস্টল করলে তা আবার তুলে নেয়।

Herdr Desktop হলো [Herdr](https://herdr.dev) ডেস্কটপ অ্যাপ: spaces, tabs, এবং panes of terminals and coding agents যা আপনি window বন্ধ করলেও এর core-এ চলতে থাকে। এটি কোনো প্যাকেজের বদলে Herdr-এর নিজস্ব ইনস্টলার থেকে আসে, তাই এটি `~/.local/share/herdr-app`-তে থাকে, আপনার আগে থেকে একটি না থাকলে `~/.local/bin/herdr-core`-এ এর core সঙ্গে নিয়ে আসে, এবং দুটিকেই নিজে আপডেট করে। এটি Omarchy `Super + Ctrl + Return`-এ যেই `herdr` কমান্ড পাঠায় তার পাশে বসে, সেটিকে প্রতিস্থাপন না করে, এবং সেই কমান্ডের direct keys পায়: `Alt + Return` এবং `Alt + Shift + Return` একটি pane নিচে বা ডানে ভাগ করে, `Alt + Escape` এটি বন্ধ করে, `Ctrl + Alt + Arrow` paneগুলোর মধ্যে যাতায়াত করে, `Alt + 1..9` এবং `Alt + Left/Right` একটি tab বেছে নেয়, এবং `Alt + Up/Down` spaceগুলোর মধ্যে যাতায়াত করে। `Ctrl + 1..9` একটি space বেছে নেয় এবং `Alt + Shift + Up/Down` এজেন্টগুলোর মধ্য দিয়ে যায়। `Ctrl + Space` prefix keys কেবল terminal-এর জন্যই থাকে, যেহেতু অ্যাপটি একটি sequence-এর জন্য একটি সাধারণ Ctrl key ধরে রাখতে পারে না। Omarchy এগুলো `~/.config/herdr-app/keys.json`-এ লেখে, এবং `omarchy-refresh-herdr-app` সেগুলো ফিরিয়ে রাখে। এটি ইনস্টল করলে Herdr-এর Omarchy থিম বেছে নেওয়া হয়, যা এরপর থেকে আপনার Omarchy থিম অনুসরণ করে। Herdr light mode-এর জন্য একটি থিম এবং dark-এর জন্য একটি রাখে, তাই একটি dark এবং একটি light Omarchy থিমের মধ্যে বদলানোর পর, অন্য mode-এর জন্য Herdr-এর theme picker-এ আবার Omarchy বেছে নিন।

T3 Code কোনো প্যাকেজের বদলে `~/.local/share/t3code`-তে এর অফিসিয়াল AppImage রিলিজ থেকে চলে, তাই এটি নিজেকে আপডেট করে। এটি ইনস্টল করলে জিজ্ঞাসা করা হয় Stable নাকি Nightly channel-এ শুরু করবেন; পরে T3 Code-এর সেটিংসে বদলান। আপনার threads এবং সেটিংস `~/.t3`-তে থাকে, এবং _Remove > AI_-এর অধীনে T3 Code সরালে সেগুলো সঙ্গে নিয়ে যায়।

### স্থানীয় মডেল

আপনার কোডিং এজেন্টগুলোর জন্য নিজস্ব মেশিনে একটি open model চালান। আপনার prompts এবং কোড মেশিনেই থাকে; মডেলে পাঠানো কিছুই এটি ছেড়ে যায় না। শুরু করুন:

```bash
omarchy models use best text
```

এটি এই মেশিনের জন্য সেরা text মডেল সেট আপ করে, যেই ধরনের মডেল আপনার এজেন্টগুলো ব্যবহার করে। Image, video এবং music মডেলগুলোর নিজস্ব সেরা আছে: `omarchy models use best image`, `video` বা `music`। এই মেশিনের জন্য প্রতিটি ধরনের বাছাই দেখতে `omarchy models use best` চালান।

অথবা শীর্ষ বারে এজেন্ট আইকনের পাশে এর sparkles আইকন থেকে, অথবা Super + Ctrl + Alt + X দিয়ে স্থানীয় মডেল প্যানেল খুলুন, এবং + বেছে নিন। কোনো মডেল এই মেশিনে মানানসই হলে আইকনটি দেখা যায়। Podman, যা মডেলগুলো চালায়, Omarchy-এর সঙ্গে আসে, একটি NVIDIA মেশিনে NVIDIA-এর container toolkit-ও আসে, যা তাদের GPU দেয়; কোনোটি অনুপস্থিত থাকলে, প্রথম সেটআপ এটি ইনস্টল করে। Omarchy তারপর এই মেশিনের জন্য প্রস্তাবিত মডেলটি বেছে নেয়, এটি ডাউনলোড করে, এবং শুরু করে। কয়েক দশ GB ডাউনলোড এবং মডেল চলার সময় মেশিনের বেশিরভাগ মেমরি ব্যবহৃত হওয়ার আশা করুন: Flash Next তার পূর্ণ 256K contextসহ প্রায় 100 GiB ব্যবহার করে। অন্য মডেলগুলো এর প্রয়োজনীয় মেমরি ধরে রাখলে, এটি বন্ধ অবস্থায় সেট আপ করা হয়, আপনি একটি বন্ধ করলেই শুরু হওয়ার জন্য প্রস্তুত। মডেলটি logout-এ বন্ধ হয়; অন্য কিছুর জন্য মেমরি প্রয়োজন হলে নিজে এটি বন্ধ করুন।

`omarchy models list` বিকল্পগুলো দেখায় এবং কেন কিছু মানানসই হয় না তা ব্যাখ্যা করে। আরেকটি সেট আপ করতে, `omarchy models use <recipe>` চালান। আজ, 128 GB Strix Halo মেশিনগুলোর জন্য `qwen3.8-flash-next-gufo` এবং `qwen3.8-27b-gufo` উপলব্ধ; 27B প্রায় 40 GiB নেয়, তাই এটি অন্য কাজের জন্য জায়গা ছেড়ে দেয়। Intel-এর Arc B390 সহ একটি 64 GB ল্যাপটপে, `qwen3.6-35b-a3b-llamacpp` প্রায় 30 GiB-তে চলে। নতুন recipes এবং সুপারিশ `omarchy update`-এর মাধ্যমে, প্যাকেজের মধ্য দিয়ে আসে।

আপনি যেসব মডেল সেট আপ করেন তার প্রতিটি স্থানীয় মডেল প্যানেলে নিজস্ব লাইন পায়: শুরু করতে play, বন্ধ করে এর মেমরি মুক্ত করতে pause, এবং এতে আপনার এজেন্ট খুলতে terminal বোতাম। শীর্ষজুড়ে, একটি বার দেখায় মেশিনের মেমরি কীভাবে Omarchy নিজে (system এবং আপনার অ্যাপগুলো), প্রতিটি চলমান মডেল, এবং যা মুক্ত আছে তার মধ্যে ভাগ করা হয়েছে। একটি বন্ধ মডেলের দিকে নির্দেশ করুন এবং বার দেখায় এটি মানানসই কিনা, বা কতটা ঘাটতি আছে। একসঙ্গে মেমরিতে মানানসই হলে একাধিক একসঙ্গে চলতে পারে; একটি মানানসই না হলে, Omarchy বলে কোন চলমান মডেলটি বন্ধ করতে হবে। সেগুলো পুনর্বিন্যাস করতে লাইনগুলো তাদের লোগো ধরে টানুন, এবং একটি মডেল ও এর ডাউনলোড সরাতে একটি নির্বাচিত লাইনে Delete চাপুন।

আপনি যেসব কোডিং মডেল সেট আপ করেন তার প্রতিটি app launcher-এ নিজস্ব এন্ট্রিও পায়, মডেলের নামের অধীনে এবং এর নির্মাতার লোগোসহ, যেভাবে Claude, Codex বা Grok-এ সাইন ইন করলে একটি যোগ হয়। এটি সেই মডেলে আপনার এজেন্ট খোলে, এবং মডেলটি চলমান না থাকলে প্রথমে সেটি শুরু করে: terminal এটি লোড হওয়া দেখায় এবং এটি তৈরি হলে এজেন্টের হাতে তুলে দেয়। একটি মডেল সরালে এর এন্ট্রি সরে যায়।

প্রতিটি মডেল কোডিংয়ের জন্য নয়। Image, video এবং music মডেলগুলো এর পরিবর্তে Fantasi-তে খোলে, এই মেশিনে চলমান একটি মডেল দিয়ে ছবি, video এবং music তৈরির জন্য Omarchy-এর অ্যাপ, যা সেখানে বা স্থানীয় মডেল প্যানেলে তাদের লাইন থেকে বেছে নেওয়া হয়।

একটি মডেল ঠিক যেভাবে সেট আপ করা হয়েছিল সেভাবেই চলতে থাকে, তাই একটি Omarchy update কখনো আপনার এজেন্টগুলোর নিচে একটিকে পুনরায় চালু করে না। Omarchy-এর কাছে আপনি সেট আপ করেছেন এমন একটি মডেলের জন্য নতুন runtime বা নতুন weights থাকলে, এর লাইন একটি update বোতাম দেখায়: এটি চাপুন এবং মডেলটি ব্যাকগ্রাউন্ডে আবার সেট আপ হয়, কেবল যা বদলেছে তাই ডাউনলোড করে, এবং নতুন সংস্করণে পুনরায় চালু হয়। বন্ধ থাকা একটি মডেল বন্ধই থাকে। `omarchy models update` একটি terminal থেকে প্রতিটি মডেলের জন্য একই কাজ করে।

কমান্ড লাইন থেকে, `omarchy models start <recipe>` এবং `omarchy models stop <recipe>` একই কাজ করে, `omarchy models status` প্রতিটি মডেল দেখায়, এবং `omarchy agent --local-model <recipe>` সেই মডেলটিকে pi-তে খোলে, আপনার ডিফল্ট এজেন্ট যাই হোক না কেন। আপনার স্থানীয় মডেলকে এজেন্ট hotkey, Quake console, এবং _Make something_ যা খোলে তা বানাতে, `omarchy default agent local` চালান বা এজেন্ট প্যানেলে একটি চলমান মডেলকে স্টার করুন। pi আপনার সেট আপ করা প্রতিটি মডেল, এবং আপনি যেসব মেশিনের সঙ্গে pair করেছেন সেগুলোতে থাকা মডেলগুলোও, তার নিজস্ব model picker-এ তালিকাভুক্ত করে, তাই সাধারণ `pi`-ও সেগুলোতে পৌঁছায়। যেকোনো OpenAI-compatible client-ও সংযুক্ত হতে পারে: `status` প্রতিটি মডেলের ঠিকানা দেখায় (প্রথমটি হলো `http://127.0.0.1:11435/v1`), recipe নামটিই মডেল, এবং কীটি `~/.config/omarchy/agent-local/key`-তে থাকে।

`omarchy models remove <recipe>` একটি মডেল এবং অন্য কোনো মডেল ব্যবহার করে না এমন ডাউনলোডগুলো মুছে দেয়।

থার্ড-পার্টি runtimeগুলো তাদের publisher দিয়ে লেবেল করা হয়। Omarchy প্রতিটি মডেল কোনো network access ছাড়াই চালায়।

### স্থানীয় LLMগুলো

Omarchy স্থানীয় LLM মডেল চালানোর দুটি উপায় সুপারিশ করে: LM Studio এবং Ollama। LM Studio open-weight মডেল খোঁজা, সেগুলো ইনস্টল করা, এবং চালানোর জন্য একটি GUI interface দেয়। সহজে শুরু করার এটি একটি দারুণ উপায়। Ollama একইভাবে করার জন্য একটি CLI দেয়। কিন্তু আপনি যদি স্থানীয় মডেলে নতুন হন, আমি LM Studio দিয়ে শুরু করতাম। আপনি Omarchy Menu-তে _Install > AI_-এর অধীনে যেকোনো একটি ইনস্টল করতে পারেন।

### Omarchy skills

Agent skills AI-কে নির্দিষ্ট টুল একটি নির্দিষ্ট উপায়ে ব্যবহার করতে সাহায্য করে, এবং Omarchy তাদের সাতটি পাঠায়। omarchy skill সিস্টেমটি নিজের মতো করে সাজানো কভার করে, যেমন আপনার Hyprland config টুইক করা বা বার সামঞ্জস্য করা। omarchy-make-theme, omarchy-make-plugin, omarchy-make-app, এবং omarchy-make-game নতুন কিছু তৈরি করা কভার করে, omarchy-contribute একটি bug রিপোর্ট করা বা upstream-এ একটি fix পাঠানো কভার করে, এবং omarchy-diagnose-crash একটি ক্র্যাশের core dump নিয়ে কাজ করে। এগুলো Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` এবং প্রতিটি `~/.hermes/profiles/*/skills`), এবং generic `~/.agents/skills` অবস্থানের জন্য skill directories-তে symlinked থাকে, তাই বেশিরভাগ harness সেগুলো স্বয়ংক্রিয়ভাবে তুলে নেয়। একই নামের আপনার নিজস্ব একটি skill folder অগ্রাধিকার পায়।

কিন্তু আপনার এই skillsগুলোকে পরীক্ষামূলক হিসাবে বিবেচনা করা উচিত। বিভিন্ন মডেল এটিকে বিভিন্ন মাত্রায় ব্যবহার করবে। প্রথমে plan mode-এ চালানোই সবচেয়ে ভালো, যাতে এজেন্ট কী বদলাতে চায় তার একটি ধারণা আপনি পান। এবং তারপর পরিবর্তনগুলো rollback করতে বা এমনকি `omarchy reinstall configs` আহ্বান করতেও প্রস্তুত থাকুন, যদি এজেন্ট সবকিছু এলোমেলো করে ফেলে।
