# ডেভেলপমেন্ট সরঞ্জাম

## বিকল্প এডিটর

Omarchy নতুন ইনস্টলে ডিফল্ট এডিটর হিসেবে Plain সহ আসে এবং [Neovim](https://neovim.io/) প্রি-ইনস্টল করা থাকে, তবে আপনি যদি আরও মূলধারার ও পরিচিত কিছু চান, তাহলে Omarchy Menu (`Super + Space`) চালিয়ে _ইনস্টল > এডিটর_-এর অধীনে অপশনগুলো দেখতে পারেন। সেখানে আমাদের তালিকায় VSCode, Cursor, Zed, Sublime Text, Helix, Vim এবং Emacs রয়েছে। আপনি যা খুঁজছেন তা না পেলে _ইনস্টল > প্যাকেজ_ দেখুন, এবং দেখুন সেটি কোনো Arch প্যাকেজে আছে কি না (আর না থাকলে, AUR যাচাই করতে _ইনস্টল > AUR_ চেষ্টা করুন)।

মূল `vi` এডিটরটিও সরাসরি ব্যবহারের জন্য উপলব্ধ। টার্মিনালে কোনো ফাইল সম্পাদনা করতে `vi filename` চালান।

`VSCode`, `Cursor`, `VSCodium` এবং `Helix`-এর জন্য থিম ম্যাচিং দেওয়া হয়।

আপনি _সেটআপ > ডিফল্ট > এডিটর_-এর অধীনে সিস্টেম-জুড়ে ডিফল্ট এডিটর সেট করতে পারেন।

## পরিবেশ

Omarchy Omarchy Menu (`Super + Space`)-এর _ইনস্টল > ডেভেলপমেন্ট_ বিভাগের মাধ্যমে পুরো একগুচ্ছ ডেভেলপমেন্ট পরিবেশ সেটআপ করা সমর্থন করে। সেখানে অবশ্যই _Ruby on Rails_ পাবেন, তবে JavaScript-এর তিনটি প্রধান রানটাইমও (Node.js, Bun, Deno) পাবেন, সেই সঙ্গে Laravel ও Symfony-এর মতো জনপ্রিয় PHP ফ্রেমওয়ার্কও। ওহ, আর Go, Rust, Python, Java, Elixir (Phoenix সহ), .NET, OCaml, Zig, Clojure এবং Scala-ও আছে। এটি খুবই বিস্তৃত একটি সংগ্রহ!

এই পরিবেশগুলোর বেশিরভাগই [Mise](https://mise.jdx.dev/) দিয়ে পরিচালিত হয়। এটি এমন একটি সরঞ্জাম যা আপনাকে একই মেশিনে কোনো প্রোগ্রামিং ভাষার একাধিক সংস্করণ ইনস্টল ও চালাতে দেয়। এটি Ruby-এর জন্য rbenv বা rvm-এর মতো, অথবা Python-এর জন্য virtualenv-এর মতো, তবে এটি একগুচ্ছ ভিন্ন পরিবেশের জন্য কাজ করে।

যেমন Ruby ইনস্টল করতে, আপনি `mise use -g ruby` চালাবেন, যা Ruby ইনস্টল করবে এবং এটিকে গ্লোবাল ডিফল্ট হিসেবেও সেট করবে। অথবা, আপনার প্রকল্পে যদি একটি .ruby-version ফাইল থাকে, তাহলে সেই প্রকল্পের রুটে শুধু `mise i` চালালেই হবে।

## প্রি-ইনস্টল করা CLI সরঞ্জাম

Omarchy `gh`, `uv` এবং বেশিরভাগ [কোডিং এজেন্ট](17-ai.md)-কে [mise-এর লেজি ইনস্টলেশন](https://mise.jdx.dev/dev-tools/shims.html#lazy-tools)-এর মাধ্যমে উপলব্ধ করে। প্রথমবার আপনি এর কোনো একটি চালালে, mise সেটি ইনস্টল করে। কোডিং এজেন্টগুলো তারপর চালানোর আগে কোনো আপডেট আছে কি না যাচাই করে, সর্বোচ্চ প্রতি চার ঘণ্টায় একবার; `gh` ও `uv`-এর মতো অন্যান্য সরঞ্জামগুলো, আপনি আপডেট না করা পর্যন্ত ইনস্টল করা সংস্করণটিই পুনরায় ব্যবহার করে।

আপনি ডিফল্টগুলো দেখতেও পারেন অথবা সেগুলো আগাম ইনস্টল করেও নিতে পারেন:

```bash
mise ls --current              # List the tools configured for this directory
mise install gh               # Install one tool now
mise install --include-lazy    # Install all configured tools, including lazy tools
```

Omarchy-এর বাকি অংশের সঙ্গে ইনস্টল করা সরঞ্জামগুলো আপডেট করতে `omarchy update` চালান। `mup` অ্যালিয়াস শুধু mise-পরিচালিত সরঞ্জামগুলো আপডেট করে। নিজের কনফিগারেশনে আরেকটি সরঞ্জাম যোগ করতে `mise use -g <tool>` ব্যবহার করুন।

Python সেটআপ mise-এর মাধ্যমে `uv`-ও ইনস্টল করে। Python ডেভেলপমেন্ট পরিবেশ সরিয়ে ফেললেও `uv` একটি স্বতন্ত্র সরঞ্জাম হিসেবে উপলব্ধ থাকে।

### নিজের ইনস্টলেশন ব্যবহার করা

mise-এর কমান্ডগুলো `PATH`-এ `~/.local/bin`-এর আগে আসে, তাই আপনি নিজে ইনস্টল করা কোনো সরঞ্জাম, উদাহরণস্বরূপ Claude Code-এর বা Cursor-এর নিজস্ব ইনস্টলার দিয়ে, তবুও mise-এর কপিটিই চালায়। ডেস্কটপ থেকে চালু করা অ্যাপগুলোও সিস্টেম প্যাকেজগুলোর আগে mise-এর কমান্ডগুলো খুঁজে পায়, তাই কোনো অ্যাপ `gh` চালালে সেটি mise-এর কপিটিই পায়, এমনকি আপনি pacman দিয়ে `github-cli` ইনস্টল করে থাকলেও, এবং mise প্রথমবার সেই কপিটি ইনস্টল করে। তার বদলে নিজেরটি ব্যবহার করতে, `~/.config/mise/config.toml`-এ mise-এর কপিটি নিষ্ক্রিয় করুন। উদাহরণস্বরূপ, আপনি যদি নিজে Cursor CLI ইনস্টল করে থাকেন:

```toml
[settings]
disable_tools = ["cursor-agent"]
```

আপনার যদি ইতিমধ্যেই একটি `[settings]` টেবিল থাকে, তাহলে সেখানে এন্ট্রিটি যোগ করুন; বিদ্যমান `disable_tools` তালিকাটি প্রতিস্থাপন না করে সেটি সম্প্রসারিত করুন। নিশ্চিত করুন যে আপনার ইনস্টলেশনটি `PATH`-এ আছে। mise সরঞ্জামের নামটি ব্যবহার করুন, যা এর কমান্ডের থেকে ভিন্ন হতে পারে: উদাহরণস্বরূপ, `oh-my-pi` দেয় `omp`। ডিফল্ট-এজেন্ট লঞ্চারটিও `~/.local/bin`-এ ব্যবহারকারীর ইনস্টল করা Cursor বা Muse-কে অগ্রাধিকার দেয়।

### ডিফল্ট সরানো এবং পুনরুদ্ধার করা

_অপসারণ > প্রি-ইনস্টলসমূহ_ Omarchy-এর প্রি-ইনস্টল করা ওয়েব অ্যাপ, TUI এবং অ্যাপগুলো সরিয়ে দেয়, এবং `~/.config/mise/miserc.toml`-এ সেগুলোকে `ignored_config_paths`-এ যোগ করে mise-কে আপনার ব্যবহারকারীর জন্য Omarchy-এর সরঞ্জাম ঘোষণাগুলো এড়িয়ে যেতে দেয়। _ইনস্টল > প্রি-ইনস্টলসমূহ_ সেগুলো ফিরিয়ে আনে এবং আবার সেই লাইনটি সরিয়ে দেয়। আপনি নিজে ঘোষণা করা সরঞ্জামগুলো, আপনার নিজের কনফিগে হোক বা কোনো প্রকল্পের `mise.toml`-এ, যেকোনো ক্ষেত্রেই কাজ করতে থাকে। প্রি-ইনস্টলসমূহ সরানোর পর আপনি যদি কোনো ডিফল্ট এজেন্ট বেছে নেন বা Python সেটআপ করেন, তাহলে সেই সরঞ্জামটি আপনার নিজের কনফিগে যোগ করা হয়। mise সেটিংটি শুধু আপনার ব্যবহারকারীর ক্ষেত্রেই প্রযোজ্য, এবং অন্যান্য ব্যবহারকারীরা তাদের নিজের পছন্দ বজায় রাখেন; অ্যাপগুলো অবশ্য প্যাকেজ, তাই সেগুলো সরানো বা পুনরুদ্ধার করা মেশিনের সবার জন্য সেগুলো পরিবর্তন করে।

## Docker

[Docker](https://www.docker.com/)-এর তেমন কোনো পরিচিতির প্রয়োজন নেই। এটি আপনাকে বিচ্ছিন্ন কন্টেইনার চালাতে দেয়, এবং Omarchy এটি ভালোভাবে চালানোর জন্য প্রয়োজনীয় সবকিছু ইনস্টল করে, যার মধ্যে রয়েছে Docker নিজে এবং [Docker Compose](https://docs.docker.com/compose/)।

ডিফল্টভাবে আপনার ব্যবহারকারী `docker` গ্রুপে *নেই*। সেই গ্রুপটি কার্যত পাসওয়ার্ডহীন root — এতে থাকা যেকোনো কিছু `docker run -v /:/host` চালিয়ে মেশিনটি দখল করে নিতে পারে — তাই আপনার হিসেবে চলা একটিমাত্র দুর্বৃত্ত স্ক্রিপ্ট বা ডিপেনডেন্সি অন্যথায় root থেকে মাত্র এক কমান্ড দূরে থাকত। তাই কমান্ড লাইনে আপনি `sudo` দিয়ে Docker চালান (`sudo docker ps`, `sudo docker compose up`), এবং যেসব গ্রাফিক্যাল সরঞ্জাম ডিমনের সঙ্গে কথা বলে — Windows VM — প্রয়োজন হলে সেগুলো অনুমোদন চায়। আপনি যদি গ্রুপহীন সেটআপের সুবিধাটি ফিরে চান এবং এই বিনিময়টি বোঝেন, তাহলে **সেটআপ > নিরাপত্তা > Sudoless Docker** থেকে এটি সক্রিয় করুন (অথবা `omarchy-setup-security-sudoless-docker` চালান), যা একটি সতর্কবার্তার পর আপনাকে `docker` গ্রুপে যোগ করে; তারপর সাধারণ `docker` এবং `d` অ্যালিয়াস আবার `sudo` ছাড়াই কাজ করে।

Omarchy মেনুতে _ইনস্টল > ডেভেলপমেন্ট > Docker DB_ ব্যবহার করে আপনি Docker-এ স্থানীয় ডেভেলপমেন্টের জন্য সাধারণ ডাটাবেসগুলো সেটআপ করতে পারেন।

## GitHub CLI

[GitHub CLI](https://cli.github.com/) টার্মিনাল থেকে রিপোজিটরি, ইস্যু এবং পুল রিকোয়েস্ট নিয়ে কাজ করার জন্য `gh` হিসেবে উপলব্ধ। প্রথম ব্যবহারে এটি ইনস্টল করে প্রমাণীকরণ করতে `gh auth login` চালান, তারপর কোনো রিপোজিটরি ক্লোন করতে `gh repo clone org/repo` চালান। এর কমান্ডগুলো অন্বেষণ করতে `gh --help` চালান।

পুল রিকোয়েস্টের জন্য একটি টার্মিনাল ইন্টারফেস পেতে `ghui` চালান; mise প্রথম ব্যবহারে এটিও ইনস্টল করে। Git নিজের সঙ্গে কাজ করার জন্য [Lazygit](https://github.com/jesseduffield/lazygit) প্রি-ইনস্টল করা থাকে।
