# ডেভেলপমেন্ট টুলসমূহ

## বিকল্প এডিটরসমূহ

Omarchy ডিফল্টভাবে [Neovim](https://neovim.io/) সহ আসে, কিন্তু আপনি যদি আরও কিছুটা প্রচলিত ও পরিচিত কিছু চান, তাহলে আপনি Omarchy Menu (`Super + Space`) চালিয়ে _Install > Editor_-এর অধীনের বিকল্পগুলো দেখতে পারেন। সেখানে আমাদের VSCode, Cursor, Zed, Sublime Text, Helix, Vim এবং Emacs তালিকাভুক্ত আছে। আপনি যা খুঁজছেন তা যদি সেখানে না পান, তাহলে _Install > Package_ দেখুন, এবং দেখুন সেটি কোনো Arch প্যাকেজে আছে কিনা (আর না থাকলে, AUR যাচাই করতে _Install > AUR_ চেষ্টা করুন)।

আসল `vi` এডিটরটিও একদম শুরু থেকেই পাওয়া যায়। টার্মিনালে কোনো ফাইল সম্পাদনা করতে `vi filename` চালান।

`VSCode`, `Cursor`, `VSCodium` এবং `Helix`-এর জন্য থিম ম্যাচিং দেওয়া হয়।

আপনি `Setup > Defaults > Editor`-এর অধীনে সিস্টেম-ব্যাপী ডিফল্ট এডিটর সেট করতে পারেন।

## এনভায়রনমেন্ট

Omarchy Menu (`Super + Space`)-এর _Install > Development_ বিভাগের মাধ্যমে Omarchy একগুচ্ছ ডেভেলপমেন্ট এনভায়রনমেন্ট সেট আপ করা সমর্থন করে। অবশ্যই সেখানে _Ruby on Rails_ পাবেন, তবে JavaScript-এর তিনটি প্রধান রানটাইমও (Node.js, Bun, Deno) পাবেন, সেই সঙ্গে Laravel ও Symfony-এর মতো জনপ্রিয় PHP ফ্রেমওয়ার্কও। ওহ, আর Go, Rust, Python, Java, Elixir (Phoenix সহ), .NET, OCaml, Zig, Clojure এবং Scala-ও আছে। এটি খুবই বিস্তৃত একটি নির্বাচন!

এই এনভায়রনমেন্টগুলোর অধিকাংশই [Mise](https://mise.jdx.dev/) দ্বারা পরিচালিত হয়। এটি এমন একটি টুল যা আপনাকে একই মেশিনে একটি প্রোগ্রামিং ভাষার একাধিক সংস্করণ ইনস্টল ও চালাতে দেয়। এটি Ruby-র জন্য rbenv বা rvm-এর মতো, কিংবা Python-এর জন্য virtualenv-এর মতো, কিন্তু এটি নানা ধরনের এনভায়রনমেন্টের জন্য কাজ করে।

ধরুন, Ruby ইনস্টল করতে আপনি `mise use -g ruby` চালাবেন, যা Ruby ইনস্টলও করবে এবং এটিকে গ্লোবাল ডিফল্ট হিসেবেও সেট করবে। অথবা, আপনার প্রকল্পে যদি একটি .ruby-version ফাইল থাকে, তাহলে আপনি সেই প্রকল্পের রুটে শুধু `mise i` চালালেই হবে।

## আগে থেকে ইনস্টল করা CLI টুলসমূহ

Omarchy `gh`, `uv`-এর মতো টুলসমূহ এবং অধিকাংশ [coding agents](17-ai.md) [Mise-এর lazy installation](https://mise.jdx.dev/dev-tools/shims.html#lazy-tools)-এর মাধ্যমে উপলব্ধ করে। প্রথমবার আপনি কোনো একটি চালালে, mise সেটি ইনস্টল করে। পরবর্তী রানগুলোতে ইনস্টল করা সংস্করণটিই পুনরায় ব্যবহার করা হয়; প্রতিটি লঞ্চে তারা কোনো আপডেট আছে কিনা যাচাই করে না।

আপনি ডিফল্টগুলো পরীক্ষা করেও দেখতে পারেন অথবা আগেভাগেই সেগুলো ইনস্টল করে নিতে পারেন:

```bash
mise ls --current              # List the tools configured for this directory
mise install gh               # Install one tool now
mise install --include-lazy    # Install all configured tools, including lazy tools
```

Omarchy-র বাকি অংশের সঙ্গে ইনস্টল করা টুলসমূহ আপডেট করতে `omarchy update` চালান। `mup` alias শুধু mise-পরিচালিত টুলসমূহ আপডেট করে। আপনার নিজের কনফিগারেশনে আরেকটি টুল যোগ করতে `mise use -g <tool>` ব্যবহার করুন।

Python সেটআপ mise-এর মাধ্যমে `uv`-ও ইনস্টল করে। Python ডেভেলপমেন্ট এনভায়রনমেন্ট সরিয়ে ফেললেও `uv` একটি স্বতন্ত্র টুল হিসেবে উপলব্ধ থাকে।

### আপনার নিজের ইনস্টলেশন ব্যবহার করা

mise-এর কমান্ডসমূহ `PATH`-এ `~/.local/bin`-এর আগে আসে, তাই আপনি নিজে ইনস্টল করা কোনো টুল, যেমন Claude Code-এর বা Cursor-এর নিজস্ব ইনস্টলার দিয়ে ইনস্টল করা, তবুও mise-এর কপিটিই চালায়। ডেস্কটপ থেকে লঞ্চ করা অ্যাপগুলোও সিস্টেম প্যাকেজের আগে mise-এর কমান্ডসমূহ খুঁজে পায়, তাই কোনো অ্যাপ `gh` চালালে সেটি mise-এর কপিটিই পায়, এমনকি আপনি pacman দিয়ে `github-cli` ইনস্টল করে থাকলেও, এবং mise প্রথমবার সেই কপিটি ইনস্টল করে। এর বদলে আপনারটি ব্যবহার করতে, `~/.config/mise/config.toml`-এ mise-এর কপিটি নিষ্ক্রিয় করুন। উদাহরণস্বরূপ, আপনি যদি নিজে Cursor CLI ইনস্টল করে থাকেন:

```toml
[settings]
disable_tools = ["cursor-agent"]
```

আপনার যদি ইতিমধ্যে একটি `[settings]` টেবিল থাকে, তাহলে এন্ট্রিটি সেখানেই যোগ করুন; বিদ্যমান `disable_tools` তালিকাটি প্রতিস্থাপন না করে সেটিকে সম্প্রসারিত করুন। নিশ্চিত করুন আপনার ইনস্টলেশনটি `PATH`-এ আছে। mise টুলের নামটি ব্যবহার করুন, যা এর কমান্ড থেকে ভিন্ন হতে পারে: উদাহরণস্বরূপ, `oh-my-pi` দেয় `omp`। default-agent লঞ্চারটিও `~/.local/bin`-এ ব্যবহারকারীর ইনস্টল করা Cursor বা Muse-কে অগ্রাধিকার দেয়।

### ডিফল্ট সরানো ও পুনরুদ্ধার করা

_Remove Preinstalls_ আপনার ব্যবহারকারীর জন্য mise-কে Omarchy-র টুল ঘোষণাগুলো এড়িয়ে যেতে বলে, সেগুলোকে `~/.config/mise/miserc.toml`-এ `ignored_config_paths`-এ যোগ করার মাধ্যমে। _Restore Preinstalls_ আবার সেই লাইনটি সরিয়ে দেয়। আপনি নিজে ঘোষণা করা টুলসমূহ, আপনার নিজের কনফিগে হোক বা কোনো প্রকল্পের `mise.toml`-এ হোক, যেভাবেই হোক কাজ করতে থাকে। প্রিইনস্টলগুলো সরানোর পর আপনি যদি একটি ডিফল্ট এজেন্ট বেছে নেন বা Python সেট আপ করেন, তাহলে সেই টুলটি আপনার নিজের কনফিগে যোগ হয়ে যায়। দুটোই শুধু আপনার ব্যবহারকারীর ক্ষেত্রে প্রযোজ্য; মেশিনের অন্য ব্যবহারকারীরা তাদের নিজেদের পছন্দই বজায় রাখেন।

## Docker

[Docker](https://www.docker.com/)-এর তেমন কোনো পরিচিতির দরকার নেই বললেই চলে। এটি আপনাকে বিচ্ছিন্ন কন্টেইনার চালাতে দেয়, এবং Omarchy এটি ভালোভাবে চালানোর জন্য যা যা দরকার তার সবই ইনস্টল করে, যার মধ্যে Docker নিজে এবং [Docker Compose](https://docs.docker.com/compose/) অন্তর্ভুক্ত।

ডিফল্টভাবে আপনার ব্যবহারকারী `docker` গ্রুপে *নেই*। সেই গ্রুপটি কার্যত পাসওয়ার্ডহীন root — এর মধ্যে থাকা যেকোনো কিছু `docker run -v /:/host` চালিয়ে মেশিনটি দখল করে নিতে পারে — তাই আপনার হিসেবে চলা একটি একক দুর্বৃত্ত স্ক্রিপ্ট বা ডিপেনডেন্সি অন্যথায় root থেকে এক কমান্ড দূরেই থাকত। তাই কমান্ড লাইনে আপনি Docker `sudo` দিয়ে চালান (`sudo docker ps`, `sudo docker compose up`), এবং যেসব গ্রাফিক্যাল টুল ডিমনের সঙ্গে কথা বলে — Windows VM — সেগুলো প্রয়োজনের সময় অনুমোদন চায়। আপনি যদি গ্রুপহীন সেটআপের সুবিধাটি ফিরে পেতে চান এবং বিনিময়টি বুঝে থাকেন, তাহলে **Setup > Security > Sudoless Docker** থেকে এটি সক্রিয় করুন (অথবা `omarchy-setup-security-sudoless-docker` চালান), যা একটি সতর্কবার্তার পর আপনাকে `docker` গ্রুপে যোগ করে; তারপর সাধারণ `docker` এবং `d` alias আবার `sudo` ছাড়াই কাজ করে।

আপনি Omarchy মেনুতে _Install > Development > Docker DB_ ব্যবহার করে Docker-এ স্থানীয় ডেভেলপমেন্টের জন্য সাধারণ ডাটাবেসগুলো সেট আপ করতে পারেন।

## GitHub CLI

[GitHub CLI](https://cli.github.com/) টার্মিনাল থেকে রিপোজিটরি, ইস্যু এবং pull request নিয়ে কাজ করার জন্য `gh` হিসেবে উপলব্ধ। প্রথম ব্যবহারে এটি ইনস্টল করে প্রমাণীকরণ করতে `gh auth login` চালান, তারপর কোনো রিপোজিটরি ক্লোন করতে `gh repo clone org/repo` চালান। এর কমান্ডসমূহ অন্বেষণ করতে `gh --help` চালান।

pull request-এর জন্য একটি টার্মিনাল ইন্টারফেস পেতে `ghui` চালান; mise প্রথম ব্যবহারে এটিও ইনস্টল করে। Git নিজের সঙ্গে কাজ করার জন্য [Lazygit](https://github.com/jesseduffield/lazygit) আগে থেকেই ইনস্টল করা আছে।
