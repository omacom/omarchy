# Windows VM

Omarchy x86_64 মেশিনে Docker VM-এর মাধ্যমে Windows চালানোর একটি সহজ উপায় দেয়। আপনি Omarchy মেনু (`Super + Space`) থেকে _Install > Windows_ ব্যবহার করে এটি ইনস্টল করতে পারেন।

এর জন্য আপনার মেশিনে KVM virtualization দরকার, যা বেশিরভাগ মেশিনেই থাকে — তবে কখনো কখনো এটি BIOS-এ বন্ধ করা থাকে, এবং তেমনটা হলে ইনস্টলার আপনাকে তা জানিয়ে দেবে। আপনার ডিস্কের জায়গাও লাগবে: Windows-কে আপনি যতটুকু দেবেন, তার সঙ্গে ইমেজটির জন্যই আরও প্রায় 10GB।

ইনস্টলার জিজ্ঞেস করবে কতটা RAM, কতগুলো CPU কোর এবং কতটা ডিস্ক দিতে চান (64GB বা তার বেশি হলো যুক্তিসঙ্গত সর্বনিম্ন), তারপর Windows-এর জন্য একটি username ও password চাইবে। ওগুলো ফাঁকা রাখলে আপনি পাবেন `docker` / `admin`। ডাউনলোড হতে বেশ সময় লাগে — 10-15 মিনিট হলো স্বাভাবিক — এবং আপনি `http://127.0.0.1:8006` ঠিকানায় ব্রাউজারে অগ্রগতি অনুসরণ করতে পারেন। কনসোল খোলার আগে ব্রাউজার একই username ও password চাইবে।

## এটি ব্যবহার করা

এটি ইনস্টল হয়ে গেলে, অ্যাপ লঞ্চার থেকে _Windows_ চালু করুন। VM ইতিমধ্যে চলমান না থাকলে এটি সেটি শুরু করবে এবং RDP দিয়ে, পূর্ণ স্ক্রিনে, আপনাকে সংযুক্ত করবে। কোল্ড স্টার্টে এটিকে 15-30 সেকেন্ড সময় দিন।

RDP সেশন শব্দ, আপনার মাইক্রোফোন এবং একটি শেয়ার করা ক্লিপবোর্ড বহন করে, তাই Linux ও Windows-এর মধ্যে টেক্সট কপি করা অনায়াসেই কাজ করে। রেজোলিউশন আপনার উইন্ডো অনুসরণ করে, এবং Omarchy আপনার ডিসপ্লে স্কেলিং পাস করে দেয়, তাই HiDPI স্ক্রিনে এটি ঘোলাটে জগাখিচুড়ি হয়ে যায় না।

আপনি RDP উইন্ডো বন্ধ করলে, VM স্বয়ংক্রিয়ভাবে বন্ধ হয়ে যায়। আপনি যদি বরং এটিকে চলমান রাখতে চান — ধরুন ভেতরে আপনার কিছু একটা কাজ করে যাচ্ছে — তাহলে এর বদলে `omarchy windows vm launch --keep-alive` দিয়ে এটি চালু করুন।

বাকি নিয়ন্ত্রণগুলো একই কমান্ডেই আছে:

```bash
omarchy windows vm status    # is it running?
omarchy windows vm stop      # shut it down
omarchy windows vm launch    # start and connect
```

## ফাইল শেয়ার করা

আপনার হোম ডিরেক্টরির `~/Windows` ডিরেক্টরিটি স্বয়ংক্রিয়ভাবে VM-এর সঙ্গে শেয়ার করা হয়। Windows থেকে অ্যাক্সেসযোগ্য করতে চাইলে ফাইলগুলো সেখানে রাখুন। VM আপনার ফাইল সিস্টেমের অন্য কোনো অংশে অ্যাক্সেস পায় না, তাই Windows দিক থেকে আসা কোনো খারাপ কিছু থেকে আপনি নিরাপদ। এর নিজের ভার্চুয়াল ডিস্ক `~/.windows`-এ পাওয়া যায়।

সেই পরিচিত হোম পাথগুলো তাদের নিজ নিজ ফাইলসিস্টেমেই থাকে। সেগুলো আপনার মালিকানাধীন ডিরেক্টরির symlink-ও হতে পারে, যা কাজে লাগে যখন ভার্চুয়াল ডিস্কটি আরও বড় কোনো ড্রাইভে থাকে। ইনস্টলার সেই ফাইলসিস্টেমে ফাঁকা জায়গা পরিমাপ করে যেটিতে আসলে `~/.windows` আছে, অগত্যা আপনার হোম ডিরেক্টরি যে ফাইলসিস্টেমে আছে সেটিতে নয়।

ডিস্ক ও শেয়ার করা পাথগুলো আলাদা, পরস্পরের ওপর না-পড়া ডিরেক্টরি হিসেবে রাখুন। সরানোর সময় ইচ্ছাকৃতভাবে ডিস্ক ডিরেক্টরিটি খালি করা হয়, কিন্তু শেয়ার করা ডিরেক্টরিটি সংরক্ষণ করা হয়। মুছে ফেলার ঠিক আগে, Omarchy একটি সীমাবদ্ধ containment যাচাই করে এবং সেই যাচাই টাইম আউট হলে বা দুটি ট্রি যে আলাদা তা প্রমাণ করতে না পারলে কোনো কিছু সরাতে অস্বীকার করে।

VM শুরু হওয়ার আগে, Omarchy সেই দুটি ডিরেক্টরি খোলে ও পিন করে, তারপর `/var/lib/omarchy/windows/mounts`-এর নিচে ব্যক্তিগত, প্রতি-ব্যবহারকারী অ্যাঙ্করগুলোর ওপর হুবহু ডিরেক্টরি inode-গুলো bind-mount করে। Docker শুধু root-সুরক্ষিত সেই অ্যাঙ্করগুলোই দেখে। এটি কাস্টম ডিস্ক অবস্থানগুলো সংরক্ষণ করে, একই সঙ্গে আপনি হিসেবে চলমান অন্য কোনো প্রসেসকে বিশেষাধিকারপ্রাপ্ত কন্টেইনারটি কোনো যাচাই করা পাথ ব্যবহার করার আগেই সেটি বদলে দেওয়া থেকে আটকায়। মাইগ্রেশনের সময় বিদ্যমান ডিস্ক ও শেয়ার করা ডিরেক্টরিগুলোকে `0700` মোডে কঠোর করা হয়, যাতে অন্য স্থানীয় অ্যাকাউন্টগুলো তাদের বিষয়বস্তু ঘেঁটে দেখতে না পারে।

VM-এর পোর্টগুলো শুধু localhost-এই বাঁধা থাকে, তাই আপনার নেটওয়ার্কের কোনো কিছুই Windows মেশিনটিতে পৌঁছাতে পারে না। ওয়েব কনসোলের জন্যও কনফিগার করা Windows username ও password দরকার হয়, যা অন্য কোনো স্থানীয় অ্যাকাউন্টকে 8006 পোর্ট দিয়ে VM-টি চালানো থেকে আটকায়।

## সীমাবদ্ধতা ও লাইসেন্সিং

এই সেটআপে কোনো GPU passthrough নেই, তাই এটি গেমিং বা ভিডিও এডিটিংয়ের জন্য উপযুক্ত নয়। Microsoft Office বা আপনার যেসব জিনিস একেবারেই না হলেই নয়, সেগুলো চালানোর এটি একটি দারুণ উপায়।

ইনস্টল করা সংস্করণটি হলো Windows 11 Pro, অ্যাক্টিভেট করা নয়। গেট করা ফিচারগুলো ব্যবহার করতে আপনার নিজের লাইসেন্স কী লাগবে।

এই কম্পিউটারটি যদি Windows নিয়ে এসে থাকে, তাহলে Omarchy ইনস্টল করার পরও OEM কীটি এখনো ফার্মওয়্যারে আছে। `omarchy windows key` দিয়ে এটি প্রিন্ট করুন। সেই কীটি এই মেশিনটির সঙ্গেই বাঁধা — এটি এই হার্ডওয়্যারে পুনরায় ইনস্টল করা Windows অ্যাক্টিভেট করবে, কিন্তু সাধারণত VM-টিকে অ্যাক্টিভেট করবে না।

পরে আপনি টার্মিনালে `omarchy windows vm install` চালিয়ে রিসোর্স বরাদ্দ বদলাতে পারেন, যা আপনার উত্তরগুলো থেকে VM-এর কনফিগারেশন নতুন করে লেখে। compose ফাইলটি নিজে এখন `/var/lib/omarchy/windows/docker-compose.yml`-এ থাকে এবং root-এর মালিকানাধীন — এটি ইচ্ছাকৃত, যাতে আপনি হিসেবে চলমান কোনো প্রসেস সেটি নতুন করে লিখতে না পারে এবং বিশেষাধিকারপ্রাপ্ত bring-up দিয়ে আপনার পুরো ডিস্ক কন্টেইনারে মাউন্ট করিয়ে নিতে না পারে। আপনার যদি এটি হাতে সম্পাদনা করার দরকার হয় (উদাহরণস্বরূপ একটি USB ডিভাইস মাউন্ট করতে), `sudo` দিয়ে এটি সম্পাদনা করুন এবং সমস্ত বিকল্প [Dockur Windows প্রকল্পে](https://github.com/dockur/windows) দেখুন।

পুরো জিনিসটি থেকে মুক্তি পেতে, Omarchy মেনু থেকে _Remove > Windows_ ব্যবহার করুন। এটি `~/.windows`-এ থাকা VM-এর ডিস্ক এবং Windows-এর ভেতরে ইনস্টল করা সবকিছু মুছে ফেলে, তাই আপনার দরকারি যা কিছু আছে তা আগে VM থেকে কপি করে বের করে নিন। আপনার শেয়ার করা `~/Windows` ফোল্ডারটি অক্ষত রাখা হয়।
