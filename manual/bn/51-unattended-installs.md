# তত্ত্বাবধানহীন ইনস্টল

Omarchy ISO কেউ কীবোর্ডের সামনে না থাকলেও নিজে নিজেই ইনস্টল হতে পারে। ইনস্টলার যদি তার কনফিগারেশন ফাইল বহনকারী `cidata` লেবেলযুক্ত দ্বিতীয় কোনো ড্রাইভ খুঁজে পায়, তাহলে সেগুলো কপি করে নেয়, সেটআপ উইজার্ড পুরোপুরি এড়িয়ে যায়, এবং নিজে থেকেই সম্পূর্ণ সিস্টেমে রিবুট করে। কোনো বিশেষ ISO বিল্ড নেই, কোনো অতিরিক্ত বুট মেনু এন্ট্রি নেই — এমন কোনো ড্রাইভ সংযুক্ত না থাকলে কিছুই বদলায় না এবং আপনি স্বাভাবিক উইজার্ডই পাবেন।

ফেলে দেওয়ার মতো dev এনভায়রনমেন্টের বেস ইমেজ হিসেবে এতে Omarchy দারুণ হয়ে ওঠে: Proxmox-এ বা Packer দিয়ে একটি VM তৈরি করুন, বুট করুন, চলে যান, SSH দিয়ে ঢুকুন। `cidata` হলো cloud-init-এর `NoCloud` লেবেল, তাই প্রচলিত সব virtualization টুলিং ইতিমধ্যেই জানে কীভাবে এমন একটি ড্রাইভ সংযুক্ত করতে হয়।

## কনফিগারেশন ফাইলগুলো

ফাইলগুলো ঠিক সেগুলোই, যা ইনস্টলারের নিজের উইজার্ড লেখে, তাই একটি প্রারম্ভিক সেট পাওয়ার সবচেয়ে সহজ উপায় হলো একটি ইন্টার‌্যাক্টিভ ইনস্টল চালানো (ধরুন, একটি VM-এ) এবং সেটি `/root`-এ যা লিখেছে তা কপি করা:

| ফাইল | প্রয়োজনীয় | উদ্দেশ্য |
|------|----------|---------|
| `user_configuration.json` | হ্যাঁ | ডিস্ক, হোস্টনেম, টাইমজোন, কীবোর্ড |
| `user_credentials.json` | হ্যাঁ | ব্যবহারকারীর নাম এবং পাসওয়ার্ড হ্যাশ |
| `user_encrypt_installation.txt` | না | কনফিগারেশনে একটি `disk_encryption` ব্লক থাকলে `true` |
| `authorized_keys` | না | SSH পাবলিক কী, প্রতি লাইনে একটি করে |
| `tailscale_authkey` | না | প্রথম বুটে আপনার tailnet-এ যোগ দেওয়ার জন্য Tailscale auth key |

`user_credentials.json`-এর জন্য পাসওয়ার্ড হ্যাশ তৈরি করুন `openssl passwd -6 "yourpassword"` দিয়ে।

git কমিটের জন্য নাম এবং ইমেইল ইনস্টলের অংশ নয়। মেশিন চালু হয়ে গেলে সেগুলো সেট করুন, যেমন SSH দিয়ে, `omarchy setup git --name "Jane Doe" --email jane@example.com` দিয়ে।

আপনি `user_credentials.json`-এর জায়গায় `defer-provisioning` নামে একটি খালি ফাইলও রেখে দিতে পারেন। এতে ইন্টার‌্যাক্টিভভাবে চালু করা যায় এমন একই [অন্য মালিকের জন্য প্রস্তুত ইনস্টল](02-getting-started.md) চলবে: মেশিন কোনো ব্যক্তিগত বিবরণ ছাড়াই ইনস্টল হবে, এবং যিনি প্রথম বুট করবেন তিনি তার কীবোর্ড বেছে নেবেন এবং তার ব্যবহারকারী তৈরি করবেন। ইমেজিং রিগের জন্য এই মোড, যেখানে ড্রাইভে কারো credentials একেবারেই থাকা উচিত নয়।

## SSH অ্যাক্সেস

যখন `authorized_keys` থাকে, তখন ইনস্টল কীগুলোকে ব্যবহারকারীর `~/.ssh/authorized_keys` হিসেবে সেট আপ করে, `sshd` সক্রিয় করে, এবং তার জন্য ফায়ারওয়াল খুলে দেয়। (সাধারণ Omarchy ইনস্টলে openssh থাকে পরিষেবা নিষ্ক্রিয় এবং পোর্ট বন্ধ অবস্থায়, তাই তত্ত্বাবধানহীন একটি মেশিন অন্যথায় পৌঁছানোই যেত না।) ইনস্টল শুধু আপনার কীগুলোই যোগ করে — এটি SSH ডিমনের অন্য কোনো authentication সেটিং শিথিল করে না।

যখন `tailscale_authkey` থাকে, তখন মেশিন তার বদলে প্রথম বুটে আপনার tailnet-এ যোগ দেয়: Tailscale ISO-র বান্ডল করা প্যাকেজগুলো থেকে ইনস্টল হয়, ফায়ারওয়াল tailnet ইন্টারফেসকে অনুমতি দেয়, এবং মেশিনে আসলেই নেটওয়ার্ক এলেই একটি ব্যাকগ্রাউন্ড জব যোগ দেওয়ার কাজ চালায়, সফল না হওয়া পর্যন্ত বারবার চেষ্টা করে। একটি পুনর্ব্যবহারযোগ্য, প্রাক-অনুমোদিত কী ব্যবহার করুন, যাতে একটি ড্রাইভ ইমেজ অনেক মেশিনে কাজ করতে পারে।

## cidata ড্রাইভ তৈরি

সঠিক লেবেলযুক্ত যেকোনো ফাইলসিস্টেম চলবে। ছোট একটি ISO-ই সহজ উপায়:

```bash
mkdir cidata
cp user_configuration.json user_credentials.json authorized_keys cidata/
genisoimage -output cidata.iso -volid cidata -joliet -rock cidata/
```

তারপর Omarchy ISO-র পাশাপাশি এটি VM-এর সঙ্গে সংযুক্ত করুন। এখানে একটি সম্পূর্ণ Proxmox উদাহরণ দেওয়া হলো:

```bash
qm create 101 --name my-omarchy \
  --bios ovmf --machine q35 --cpu host --cores 4 --memory 8192 \
  --ostype l26 --scsihw virtio-scsi-single \
  --efidisk0 local-lvm:0,efitype=4m,pre-enrolled-keys=0 \
  --scsi0 local-lvm:40,discard=on,iothread=1 \
  --net0 virtio,bridge=vmbr0 --vga virtio --serial0 socket \
  --ide2 local:iso/omarchy.iso,media=cdrom \
  --ide3 local:iso/cidata.iso,media=cdrom \
  --boot order='scsi0;ide2'

qm start 101
```

বুট অর্ডারে ইচ্ছে করেই ডিস্ককে প্রথমে রাখা হয়েছে: খালি ডিস্কটি প্রথম বুটে ISO-তে চলে যায়, এবং তারপর থেকে ইনস্টল করা সিস্টেম সবসময় ডিস্ক থেকে বুট হয়।

## দুটি সতর্কতা

এনক্রিপ্ট করা তত্ত্বাবধানহীন ইনস্টল পুরোপুরি তত্ত্বাবধানহীন নয় — প্রথম বুটে কারো না কারো LUKS passphrase টাইপ করতেই হবে। আর `user_configuration.json`-এ থাকা `disk_encryption` ব্লক সেই passphrase প্লেইনটেক্সটে বহন করে, তাই এনক্রিপ্ট করা ইনস্টল থেকে তৈরি একটি cidata ড্রাইভকে সেটি যে গোপন জিনিস, সেভাবেই রাখুন।
