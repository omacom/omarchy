# AI

Omarchy menyertakan pelancar untuk ejen pengekodan di bawah tanpa memilih pilihan lalai untuk anda. Jalankan satu perintah untuk memasang CLI-nya pada kali pertama digunakan, kemudian lakukan pengesahan apabila diminta. Hermes ialah pengecualiannya: tiada apa-apa dipasang untuknya pada kali pertama digunakan, dan memilihnya akan memasang Hermes Desktop, seperti yang diterangkan oleh _Aplikasi desktop_ di bawah.

### Memasang dan mengemas kini ejen

Kecuali Hermes, ejen ini menggunakan pemasangan malas mise: pelancaran pertama memasang CLI, dan pelancaran kemudian menggunakannya semula. mise juga menyemak ejen yang telah dipasang untuk keluaran baharu paling kerap sekali setiap empat jam, sejurus sebelum ia bermula atau di latar belakang pada prompt shell. Jika kemas kini itu gagal atau anda di luar talian, versi yang telah dipasang akan dijalankan. `omarchy update` mengemas kini ejen yang telah dipasang bersama seluruh Omarchy, dan `mup` hanya mengemas kini alat yang diurus oleh mise.

Pengemas kini ejen itu sendiri, seperti `claude update`, `codex update`, atau butang kemas kini dalam aplikasi, tidak mengemas kini pemasangan yang diurus oleh mise. `codex update` gagal, dan `claude update` boleh melaporkan kejayaan sambil memasang salinan berasingan yang tidak dijejak oleh mise. Jika anda lebih suka menggunakan pemasang dan pengemas kini natif ejen, tambahkannya pada `disable_tools`; lihat [Alat CLI yang telah dipasang](18-development-tools.md#preinstalled-cli-tools).

Untuk memasang semua alat malas yang dikonfigurasikan sebelum anda memerlukannya, jalankan `mise install --include-lazy`. Ini termasuk alat CLI lalai Omarchy yang lain serta ejen. Lihat [Alat CLI yang telah dipasang](18-development-tools.md#preinstalled-cli-tools) untuk memasang satu alat atau menggunakan pemasangan anda sendiri.

`grok` dipasang melalui pakej `grok` pihak pertama mise, dengan cara yang sama seperti `claude` dan `codex`. Jalankan `grok`, atau pilihnya di bawah _Agent > Harness_. Langkau pemasang `curl | bash` di x.ai. Laluan itu meletakkan salinan kedua dalam `~/.grok/bin`, mendahulukannya pada `PATH`, dan menimpa pembalut Omarchy.

`dsh` membuka UI pelayarnya pada `127.0.0.1:3080`, dengan direktori pelancaran sebagai ruang kerja laluainya. UI pelayarnya tidak menerima prompt permulaan, jadi `omarchy agent prompt` membukanya dengan prompt pada papan keratan anda untuk ditampal. Omarchy memulakannya dengan preset kebenaran tanpa kelulusan DeepSeek. DeepSeek Harness memuat naik log sesi ke DeepSeek apabila anda menggunakan API model rasminya; matikan itu di bawah _Settings > General > Upload Session Log_ dalam UI pelayarnya. Maklum balas yang anda hantar kepadanya turut dimuat naik bersama sesi, melainkan anda memulakannya dengan `DSH_TELEMETRY_MODE=DISABLED`.

### Ejen lalai

Pilih ejen lalai anda dengan `omarchy default agent <name>` atau di bawah _Agent > Harness_ dalam Omarchy Menu (`Super + Space`). Jika ejen itu belum dipasang, memilihnya akan memasangnya terlebih dahulu. Omarchy yang baharu akan menjemput anda membuat pilihan ini dengan pemberitahuan sekali sahaja.

Memilih Claude juga cuba menyediakan sambungan pelayarnya untuk Chromium, Chrome, Brave, Brave Origin, dan Edge. Penyediaan sambungan itu terpakai kepada semua pengguna dan mungkin meminta kata laluan sistem anda; membatalkan atau pemasangan sambungan yang gagal tetap memilih dan melancarkan Claude. Mulakan semula pelayar anda, dayakan sambungan jika diminta, dan log masuk ke Claude untuk menyelesaikan sambungannya. Jalankan `/chrome` dalam Claude untuk menyemak sambungan. Firefox dan Zen tidak menyokong sambungan ini. Jika Claude sudah menjadi pilihan lalai anda sebelum penyediaan ini ditambah, pilihnya semula untuk memasang sambungan.

Sebaik sahaja anda memilih, `Super + Shift + Ctrl + A` melancarkan ejen lalai dalam tetingkap terminal khusus (atau memaparkan pemilih jika anda belum memilih). Anda juga boleh melancarkannya terus ke dalam tugasan dengan `omarchy agent prompt "Review this project"`. Freebuff dan DeepSeek Harness tidak menerima prompt permulaan, jadi ia dibuka dengan prompt pada papan keratan anda untuk ditampal sebagai ganti. Ejen yang dilancarkan dengan cara ini berjalan tanpa pengawasan dalam mod jangan-berhenti-untuk-bertanya masing-masing, jadi bersedialah kerana ia benar-benar akan melakukan sesuatu! MiniMax Code tidak mempunyai mod seperti itu untuk sesi interaktifnya, jadi ia meminta kebenaran seperti biasa. Dan memandangkan ejen enggan mengingati kepercayaan untuk direktori rumah anda, pelancaran daripada `$HOME` bermula dalam `~/Work` sebagai ganti.

Terdapat juga pintasan terminal: `a` menjalankan ejen lalai sebaris dalam terminal semasa, manakala `c`, `cx`, dan `cy` memulakan OpenCode, Claude Code, dan Codex secara langsung (sekali lagi dalam mod meluluskan secara automatik masing-masing). Perubahan tema turut disegerakkan kepada ejen: Claude Code, Pi, OpenCode, dan Hermes (sebaik sahaja Omarchy memasangnya) semuanya mengikut apabila anda menukar tema Omarchy.

### Arahan ejen anda

Peraturan peribadi untuk setiap ejen masuk ke dalam `~/.agents/AGENTS.md`, di sebelah skill yang dikongsi dalam `~/.agents/skills`. Bukanya di bawah _Agent > Instructions_, yang turut memautkannya ke dalam setiap harness yang menyimpan fail globalnya sendiri: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` Copilot, dan sebagainya. Crush dan Amp membaca pautan `~/.config/AGENTS.md`, manakala omp, Kimi, dan DeepSeek Harness membaca `~/.agents/AGENTS.md` secara langsung. Memilih ejen lalai turut memautkannya. Fail arahan yang telah anda miliki menjadi yang dikongsi jika belum ada lagi; jika tidak, ia disimpan di sebelah pautan sebagai `.bak`. Jalankan `omarchy agent instructions` untuk memaut semula selepas memasang ejen lain.

### Panel ejen

Bar atas mempunyai ikon ejen. Sebelum anda menyediakan ejen, panelnya memandu anda untuk log masuk ke Claude, Codex, atau Grok, dan yang pertama menjadi ejen lalai anda. Selepas itu, panel meletakkan setiap langganan pada satu halaman: setiap ejen dan akaun dengan pelannya, meter untuk setiap had sesi 5 jam dan had mingguannya dengan masa sehingga ia ditetapkan semula (tuding untuk peratusan tepat), atau baki prabayar yang tinggal, di bawah baris yang bergilir melalui apa yang telah anda gunakan merentas kesemuanya, seperti token minggu ini dan model yang paling kerap anda gunakan. Di bawah _Make something_ ia menawarkan prompt permulaan untuk tema, plugin, aplikasi, atau permainan baharu yang menyerahkan tugasan kepada ejen lalai anda. Aplikasi dibina dengan cara Hype, Monologue, dan Omacut Omarchy sendiri dibina, dalam C++ dan Qt Quick, mengikut skill ejen omarchy-app, dan pengkompil serta bahagian Qt yang diperlukannya dipasang sekali. Permainan ialah satu halaman three.js dalam `~/Games/vibes`, mengikut skill ejen web-game, dan semuanya dibuka daripada satu pelancar Game Vibes dalam tema semasa; ia memuatkan three.js daripada web, jadi ia memerlukan sambungan untuk bermula. Claude Code, Codex, Grok, Kimi, Cursor dan elaun Grok Botnya, GitHub Copilot, Muse, Antigravity, Kimchi, dan Devin diliputi terus dengan had masing-masing, dan Hermes, Mistral Vibe, dan Qwen Code menunjukkan sesi dan tokennya sebaik sahaja anda menggunakannya. Pelan dan kunci penyedia yang anda gunakan melalui pi, omp, atau opencode turut muncul: OpenCode Zen dan Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan, dan Synthetic dengan had masing-masing; Fireworks, OpenRouter, dan DeepSeek dengan baki prabayarnya; dan model yang anda jalankan pada perkakasan anda sendiri di bawah Local models. Setiap ejen dikira sekali, di bawah sesiapa yang mengebilnya, tidak kira berapa banyak harness yang anda gunakan untuk menjalankannya.

Klik kiri ikon bar untuk panel, klik kanan untuk melancarkan ejen lalai anda. Rekod penggunaan di belakangnya dijana semula setiap 15 minit oleh `omarchy agent usage-update`, dan panel malah boleh menggabungkan penggunaan daripada mesin anda yang lain melalui folder yang disegerakkan. Lihat README di bawah `$OMARCHY_PATH/shell/plugins/agents/` untuk tetapan penuh.

### Beberapa langganan

Jika anda membayar lebih daripada satu pelan Claude, Codex, atau Grok — pelan Max peribadi dan pelan kerja, misalnya — Omarchy boleh memastikan kesemuanya kekal log masuk dan bergerak antara mereka. Tambah langganan dengan + dalam panel ejen, yang memandu anda melaluinya di situ juga, atau dengan `omarchy agent account add claude Work` (atau `codex`, atau `grok`). Ia memasang CLI jika tiada. Akaun pertama untuk penyedia log masuk melalui pelayar biasa anda, tepat di tempat CLI sentiasa mencarinya. Setiap yang selepas itu log masuk melalui tetingkap peribadi, supaya akaun yang pelayar anda telah log masuk tidak tersilap dipilih; log masuk di situ sebagai akaun yang anda tambah, dan tutup sebarang tetingkap peribadi yang telah anda buka terlebih dahulu. Jangan sekali-kali log keluar daripada CLI untuk melakukan ini: log keluar membatalkan log masuk yang disimpan, dan akaun itu perlu ditambah semula.

Untuk menyalin log masuk langganan ke mesin Omarchy lain melalui SSH, jalankan `omarchy agent account copy user@laptop`. Pengirim membekalkan penerima sementara apabila destinasi tidak memasangnya, supaya mesin Omarchy lama boleh menerima akaun tanpa kemas kini. Penerima yang telah dipasang diutamakan. Ini menyalin semua langganan Claude, Codex, dan Grok; tambah nama penyedia untuk memilihnya, seperti dalam `omarchy agent account copy laptop claude`. Nama akaun dan ID perintah sepadan dengan sumber, termasuk akaun yang telah ada di destinasi. Akaun destinasi yang tidak berkaitan menerima akhiran angka jika namanya bercanggah, dan tetapan, skill, plugin, serta sejarah perbualan kekal setempat bagi setiap mesin.

Bukti kelayakan destinasi yang sedia ada dikekalkan. Akaun sumber yang telah log masuk di situ namanya disegerakkan tanpa menggantikan bukti kelayakannya; akaun lain ditambah di sampingnya. Untuk menggantikan bukti kelayakan yang disimpan bagi akaun yang sepadan, gunakan `omarchy agent account copy --replace laptop claude` selepas menutup sesi akaun itu di destinasi. Destinasi baharu turut mendapat akaun aktif dan keutamaan penukaran sumber; destinasi yang telah mantap mengekalkan miliknya sendiri.

Bukti kelayakan bergerak melalui SSH dan disimpan dalam fail peribadi di destinasi, jadi salin hanya ke mesin yang anda percayai. Ini ialah salinan sekali sahaja, bukan penyegerakan berterusan. Token muat semula Codex boleh diputar oleh mesin lain, menyebabkan log masuk yang disalin memerlukan pembaharuan; log masuk berasingan kekal pilihan paling boleh dipercayai untuk penggunaan serentak pada beberapa mesin. Lihat [Panduan pengesahan akaun Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Satu akaun bagi setiap penyedia aktif, dan setiap sesi baharu bermula dengannya: `cx`, `cy`, `claude`, `codex`, atau `grok` biasa, apa-apa sahaja yang dilancarkan melalui `omarchy agent`, dan skrip atau penyunting yang menemui CLI pada `PATH`. Tukar dengan `omarchy agent account use work` (dan kembali dengan `omarchy agent account use main`), atau dalam panel dengan menekan nombor akaun kemudian `Enter` (atau mengklik butang Use). Sesi Claude yang sedang berjalan turut bertukar, bermula daripada mesej seterusnya: setiap sesi Claude berjalan dalam `~/.claude`, yang sentiasa menyimpan log masuk akaun aktif. Sesi Claude yang dimulakan dalam folder akaun itu sendiri oleh Omarchy lama menyimpan log masuk itu sehingga ia ditutup, jadi penukaran menamakan sesi tersebut dan selesai dengan sendiri sebaik sahaja ia tiada. Sesi Codex dan Grok yang sedang berjalan kekal pada akaun ia bermula. Sejarah perbualan, tetapan, skill, dan plugin dikongsi merentas akaun, jadi `claude --continue` dalam folder yang sama menyambung dari tempat anda berhenti pada akaun baharu.

Dengan lebih daripada satu akaun, panel menunjukkan had setiap akaun bersebelahan, dengan yang aktif ditanda. Secara lalai Omarchy memberitahu anda apabila akaun aktif melepasi 95% daripada had, dan mengklik pemberitahuan menukar kepada akaun dengan ruang paling banyak. Tuding baris akaun dalam panel dan klik Autoswitch yang muncul di sebelah Use (atau tekan `m`), atau jalankan `omarchy agent account mode auto`, supaya ia bertukar dengan sendiri sebagai ganti; ketika ia aktif, Autoswitch mengambil tempat Use, dan mengkliknya semula kembali kepada pemberitahuan. Tambah nombor untuk menukar ambang, seperti dalam `omarchy agent account mode auto 90`. Jika setiap akaun melepasi ambang, anda akan diberitahu sekali, bersama akaun mana yang bebas terlebih dahulu. Ketika akaun aktif berada dalam 15 mata daripada ambangnya (80% pada lalai), hadnya disemak setiap tiga minit dan bukan setiap 15.

`omarchy agent account list` menunjukkan setiap akaun dan had terbaharunya, `omarchy agent account remove work` melupakan satu, dan `omarchy agent account rename primary Hey` menamakan semula satu (atau klik nama akaun dalam panel). Perintah ini berfungsi pada akaun ejen lalai anda; untuk mencapai penyedia lain, namakannya terlebih dahulu, seperti dalam `omarchy agent account use codex side`. Log masuk yang telah anda miliki dalam `~/.claude` atau `~/.codex` ialah akaun _Main_. Milik Codex kekal di tempatnya; milik Claude menunggu dalam foldernya sendiri sementara akaun lain aktif. Akaun yang tidak digunakan selama lebih daripada kira-kira lapan jam boleh menunjukkan _Sign-in required_; kliknya untuk log masuk akaun itu semula terus dalam panel, atau tukar kepadanya dan mulakan sesi, yang menyegarkan log masuk dengan sendiri. Pelayan MCP yang anda tambah dengan `claude mcp add` mencapai setiap akaun Claude, kerana kesemuanya berjalan dalam `~/.claude`; untuk Codex dan Grok, pelayan yang anda miliki ketika akaun ditambah ikut bersamanya, tetapi yang kemudian hanya mencapai akaun tempat anda menambahnya. Claude Desktop menyimpan log masuknya sendiri, dan alat Codex atau Grok yang dikonfigurasikan dengan laluan mutlak ke binari CLI tidak mengikut penukaran. `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, atau `GROK_HOME` yang eksplisit diutamakan berbanding akaun yang dipilih.

### Diagnosis ranap

Omarchy memerhati systemd-coredump untuk ranap proses. Apabila sesuatu segfault, anda akan mendapat pemberitahuan "Process crashed" — kliknya, dan ranap itu diserahkan kepada ejen lalai anda bersama skill diagnose-crash Omarchy, yang memandu ejen menetapkan fakta daripada core dump dan memutuskan sama ada ranap itu berbaloi dilaporkan ke huluan. Anda juga boleh menjalankannya secara manual terhadap mana-mana PID daripada `coredumpctl list` dengan `omarchy agent crash <pid>`.

Pemerhatian aktif secara lalai. Matikannya di bawah _Trigger > Toggle > Crash Capture_ (atau dengan `omarchy toggle crash-capture`) dan pemberitahuan berhenti; `omarchy agent crash <pid>` masih berfungsi secara manual.

Ranap juga boleh disenyapkan satu program pada satu masa, yang ditawarkan oleh diagnosis kepada anda pada penghujungnya. `omarchy crash mute hyprland` menghentikan pemberitahuan untuk program itu sahaja, `omarchy crash mute hyprland off` memulihkannya, dan `omarchy crash mute` sendiri menyenaraikan apa yang telah anda senyapkan. Ia menerima laluan binari semudah namanya, jadi `omarchy crash mute /usr/bin/hyprland` melakukan perkara yang sama. Petik nama yang mempunyai ruang di dalamnya, seperti dalam `omarchy crash mute 'Some App'`. Semua yang lain masih memberitahu, dan program yang disenyapkan masih ranap — ini menyembunyikan peringatan, ia tidak membaiki apa-apa.

### Aplikasi desktop

Menu _Install > AI_ turut membawa beberapa aplikasi AI grafik: aplikasi desktop ChatGPT, aplikasi desktop Claude (beta Linux Anthropic, dengan tab Chat, Cowork, dan Claude Code), Grok Bot untuk berbual dengan model xAI, Herdr Desktop, Hermes Desktop, OpenClaw, aplikasi desktop Perplexity, dan T3 Code. Grok Bot ialah aplikasi sembang desktop. Ejen pengekodan ialah perintah `grok`.

Hermes Desktop ialah yang perlu diketahui, kerana sesebuah mesin mempunyai satu Hermes, dan ia milik aplikasi: Hermes hanya pernah dipasang melalui aplikasi, dan perintah `hermes` yang dijalankan oleh ejen lalai ialah milik aplikasi. Memilih Hermes sebagai ejen lalai memasang perkara yang sama seperti entri _Install > AI_: pakej, dan runtime Hermes di bawah `~/.hermes` yang disediakan oleh pemasang Hermes sendiri, yang mengambil masa beberapa minit pada kali pertama. Runtime itu ialah satu-satunya Hermes yang digunakan oleh perintah terminal `hermes`, ejen lalai dan aplikasi, dan ia mengemas kini dirinya dengan `hermes update` dan tidak menunggu keluaran Omarchy. Memasangnya turut menyerahkan tema Omarchy kepada Hermes sebagai skin bernama `omarchy`, yang diikuti oleh setiap permukaan Hermes apabila anda menukar tema; pilih yang lain di bawah tetapan Appearance Hermes atau dengan `/skin` jika anda lebih suka ia tidak berbuat demikian, dan Omarchy membiarkan pilihan itu. Mengalih keluar aplikasi di bawah _Remove > AI_ menutup Hermes terlebih dahulu, termasuk gateway, mengambil runtime itu bersamanya, dan mengekalkan sembang, memori, dan skill yang ditulis Hermes untuk dirinya melainkan anda menyuruh sebaliknya: ia bertanya, dengan lalai tidak, sama ada data itu dan tetapan sambungan anda patut turut dialih keluar.

Pengalaman desktop OpenClaw ialah Control UI-nya, yang dibuka sebagai aplikasi web yang disokong oleh gateway tempatannya sendiri. OpenClaw berada dalam `~/.openclaw` dan mengemas kini dirinya: gunakan butang "Update Gateway" Control UI atau jalankan `openclaw update`, dan gateway dimulakan semula pada versi baharu. Omarchy hanya memilih keluaran yang pemasangan baharu bermula daripadanya. Mengalih keluar OpenClaw di bawah _Remove > AI_ mengambil perkhidmatan gateway dan aplikasi bersamanya kemudian bertanya sama ada `~/.openclaw` patut turut dialih keluar, kerana itu menyimpan sembang dan bukti kelayakan anda di samping OpenClaw sendiri dan runtime plugin yang dimuat turunnya; lalai mengekalkannya, dan memasang OpenClaw semula mengambilnya kembali.

Herdr Desktop ialah aplikasi desktop [Herdr](https://herdr.dev): ruang, tab, dan panel terminal serta ejen pengekodan yang terus berjalan dalam terasnya apabila anda menutup tetingkap. Ia datang daripada pemasang Herdr sendiri dan bukan pakej, jadi ia berada dalam `~/.local/share/herdr-app`, membawa terasnya bersama dalam `~/.local/bin/herdr-core` apabila anda belum memilikinya, dan mengemas kini kedua-duanya sendiri. Ia berada di sebelah perintah `herdr` yang Omarchy sediakan pada `Super + Ctrl + Return` dan tidak menggantikannya, dan mendapat kekunci langsung perintah itu: `Alt + Return` dan `Alt + Shift + Return` membahagi panel ke bawah atau ke kanan, `Alt + Escape` menutupnya, `Ctrl + Alt + Arrow` bergerak antara panel, `Alt + 1..9` dan `Alt + Left/Right` memilih tab, dan `Alt + Up/Down` bergerak antara ruang. `Ctrl + 1..9` memilih ruang dan `Alt + Shift + Up/Down` melangkah melalui ejen. Kekunci awalan `Ctrl + Space` kekal hanya untuk terminal, kerana aplikasi tidak boleh menahan kekunci Ctrl biasa untuk satu urutan. Omarchy menulis ini ke `~/.config/herdr-app/keys.json`, dan `omarchy-refresh-herdr-app` memulihkannya. Memasangnya memilih tema Omarchy Herdr, yang mengikut tema Omarchy anda selepas itu. Herdr menyimpan satu tema untuk mod cerah dan satu untuk mod gelap, jadi selepas menukar antara tema Omarchy gelap dan cerah, pilih Omarchy dalam pemilih tema Herdr sekali lagi untuk mod lain.

T3 Code berjalan daripada keluaran AppImage rasminya dalam `~/.local/share/t3code` dan bukan daripada pakej, jadi ia mengemas kini dirinya. Memasangnya bertanya sama ada untuk bermula pada saluran Stable atau Nightly; tukar kemudian dalam tetapan T3 Code. Thread dan tetapan anda berada dalam `~/.t3`, dan mengalih keluar T3 Code di bawah _Remove > AI_ mengambilnya bersama.

### Model tempatan

Jalankan model terbuka pada mesin anda sendiri untuk ejen pengekodan anda. Prompt dan kod anda kekal pada mesin; tiada apa yang dihantar kepada model meninggalkannya. Bermula dengan:

```bash
omarchy agent local use best
```

Atau, dalam panel ejen di bar atas, pilih + kemudian Local AI, yang muncul apabila model muat pada mesin ini. Kali pertama, ini memasang Podman, yang menjalankan model, dan pada mesin NVIDIA toolkit bekas NVIDIA, yang memberikannya GPU. Omarchy kemudian memilih model yang disyorkan untuk mesin ini, memuat turunnya, dan memulakannya. Jangkakan muat turun berpuluh GB dan sebahagian besar memori mesin digunakan ketika model berjalan: Flash Next menggunakan kira-kira 100 GiB dengan konteks penuh 256K. Jika model lain memegang memori yang diperlukannya, ia disediakan dalam keadaan berhenti, bersedia untuk bermula sebaik sahaja anda menghentikan satu. Model berhenti semasa log keluar; hentikannya sendiri apabila anda memerlukan memori untuk perkara lain.

`omarchy agent local list` menunjukkan pilihan dan menerangkan mengapa sesetengahnya tidak muat. Untuk menyediakan yang lain, jalankan `omarchy agent local use <recipe>`. Hari ini, `qwen3.8-flash-next-gufo` dan `qwen3.8-27b-gufo` tersedia untuk mesin Strix Halo 128 GB; 27B menggunakan kira-kira 40 GiB, jadi ia meninggalkan ruang untuk kerja lain. Pada komputer riba 64 GB dengan Intel's Arc B390, `qwen3.6-35b-a3b-llamacpp` berjalan dalam kira-kira 30 GiB. Resipi dan syor baharu tiba dengan `omarchy update`, melalui pakej.

Setiap model yang anda sediakan mendapat barisnya sendiri dalam panel ejen, di sebelah langganan anda: main untuk memulakannya, jeda untuk menghentikannya dan membebaskan memorinya, dan butang terminal untuk membuka ejen anda padanya. Beberapa boleh berjalan sekali gus apabila ia muat dalam memori bersama; jika satu tidak muat, Omarchy menyatakan model berjalan mana yang perlu dihentikan. Seret baris untuk menyusunnya semula, dan tekan Delete pada baris yang dipilih untuk mengalih keluar model dan muat turunnya.

Setiap model yang anda sediakan turut mendapat entrinya sendiri dalam pelancar aplikasi, di bawah nama model dan dengan logo pembuatnya, dengan cara log masuk ke Claude, Codex atau Grok menambah satu. Ia membuka ejen anda pada model itu, dan memulakan model terlebih dahulu jika ia tidak berjalan: terminal menunjukkannya dimuatkan dan menyerahkan kepada ejen sebaik sahaja ia siap. Mengalih keluar model mengalih keluar entrinya.

Daripada baris perintah, `omarchy agent local start <recipe>` dan `omarchy agent local stop <recipe>` melakukan perkara yang sama, `omarchy agent local status` menunjukkan setiap model, dan `omarchy agent --local` membuka ejen lalai anda pada model terakhir yang anda mulakan. pi, OpenCode dan Qwen Code boleh menggunakan satu; dengan sebarang lalai lain ia dibuka dalam pi. pi turut menyenaraikan setiap model yang anda sediakan, dan yang pada mesin yang anda pasangkan dengannya, dalam pemilih modelnya sendiri, jadi `pi` biasa turut mencapainya. Mana-mana klien serasi OpenAI juga boleh menyambung: `status` menunjukkan alamat setiap model (yang pertama ialah `http://127.0.0.1:11435/v1`), nama resipi ialah model, dan kunci berada dalam `~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` memadam model dan muat turun yang tidak digunakan oleh model lain.

Runtime pihak ketiga dilabelkan dengan penerbitnya. Omarchy menjalankan setiap model tanpa akses rangkaian.

### LLM tempatan

Omarchy mengesyorkan dua cara menjalankan model LLM tempatan: LM Studio dan Ollama. LM Studio menyediakan antara muka GUI untuk mencari model open-weight, memasangnya, dan menjalankannya. Ia cara yang bagus untuk bermula dengan mudah. Ollama menawarkan CLI untuk melakukan perkara yang serupa. Tetapi jika anda baharu kepada model tempatan, saya akan bermula dengan LM Studio. Anda boleh memasang mana-mana satu di bawah _Install > AI_ dalam Omarchy Menu.

### Skill Omarchy

Skill ejen membantu AI menggunakan alat tertentu dengan cara tertentu, dan Omarchy disertakan dengan skill lalai untuk menyesuaikan sistem. Seperti mengubah konfigurasi Hyprland anda, melaraskan bar, atau malah mencipta tema baharu dari awal. Ia dipautkan secara simbolik ke dalam direktori skill untuk Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` dan setiap `~/.hermes/profiles/*/skills`), dan lokasi generik `~/.agents/skills`, jadi kebanyakan harness mengambilnya secara automatik.

Tetapi anda patut menganggap skill ini sebagai eksperimen. Model berbeza akan menggunakannya dengan kesan berbeza. Sebaiknya jalankannya dalam mod pelan terlebih dahulu, supaya anda mempunyai idea tentang apa yang ejen ingin ubah. Kemudian bersedia untuk membuat rollback perubahan atau malah memanggil `omarchy reinstall configs`, jika ejen mengacaukan semuanya.
