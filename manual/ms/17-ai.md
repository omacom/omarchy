# AI

Omarchy menyertakan pelancar untuk ejen pengekodan di bawah tanpa memilih ejen lalai untuk anda. Jalankan arahan untuk memasang CLI ejen tersebut pada penggunaan pertama, kemudian sahkan apabila diminta. Hermes ialah pengecualian: tiada apa-apa dipasang untuknya pada penggunaan pertama, dan memilihnya akan memasang Hermes Desktop, seperti yang dijelaskan oleh _Desktop apps_ di bawah.

### Memasang dan mengemas kini ejen

Kecuali Hermes, ejen ini menggunakan pemasangan malas mise: pelancaran pertama memasang CLI, dan pelancaran kemudian menggunakannya semula. mise juga menyemak ejen yang dipasang untuk keluaran baharu paling banyak sekali setiap empat jam, sejurus sebelum ia bermula atau di latar belakang pada gesaan shell. Jika kemas kini itu gagal atau anda di luar talian, versi yang dipasang akan berjalan. `omarchy update` mengemas kini ejen yang dipasang bersama-sama seluruh Omarchy, dan `mup` mengemas kini alat yang diuruskan mise sahaja.

Pengemas kini ejen sendiri, seperti `claude update`, `codex update`, atau butang kemas kini dalam apl, tidak mengemas kini pemasangan yang diuruskan mise. `codex update` gagal, dan `claude update` boleh melaporkan kejayaan sambil memasang salinan berasingan yang tidak dijejak oleh mise. Jika anda lebih suka menggunakan pemasang dan pengemas kini natif ejen, tambahkannya ke `disable_tools`; lihat [Alat CLI prapasang](18-development-tools.md#preinstalled-cli-tools).

Untuk memasang semua alat malas yang dikonfigurasikan sebelum anda memerlukannya, jalankan `mise install --include-lazy`. Ini termasuk alat CLI lalai Omarchy yang lain serta ejen-ejen ini. Lihat [Alat CLI prapasang](18-development-tools.md#preinstalled-cli-tools) untuk memasang satu alat atau menggunakan pemasangan anda sendiri.

`grok` dipasang melalui pakej pihak pertama `grok` mise, dengan cara yang sama seperti `claude` dan `codex`. Jalankan `grok`, atau pilihnya di bawah _Setup > Defaults > Agent_. Langkau pemasang `curl | bash` di x.ai. Laluan itu meletakkan salinan kedua dalam `~/.grok/bin`, mendahulukannya pada `PATH`, dan menulis ganti pembalut Omarchy.

`dsh` membuka UI pelayarnya pada `127.0.0.1:3080`, dengan direktori pelancaran sebagai ruang kerja laluannya. UI pelayarnya tidak menerima gesaan permulaan, jadi `omarchy agent prompt` membukanya dengan gesaan pada papan keratan anda untuk ditampal. Omarchy memulakannya dengan pratetap kebenaran tanpa kelulusan DeepSeek. DeepSeek Harness memuat naik log sesi ke DeepSeek apabila anda menggunakan API model rasminya; matikan itu di bawah _Settings > General > Upload Session Log_ dalam UI pelayarnya. Maklum balas yang anda hantar kepadanya juga dimuat naik bersama-sama sesi, melainkan anda memulakannya dengan `DSH_TELEMETRY_MODE=DISABLED`.

### Ejen lalai

Pilih ejen lalai anda dengan `omarchy default agent <name>` atau di bawah _Setup > Defaults > Agent_ dalam Omarchy Menu (`Super + Space`). Jika ejen itu belum dipasang, memilihnya akan memasangnya terlebih dahulu. Omarchy baharu akan menjemput anda membuat pilihan ini dengan pemberitahuan sekali sahaja.

Memilih Claude juga cuba menyediakan sambungan pelayarnya untuk Chromium, Chrome, Brave, Brave Origin, dan Edge. Penyediaan sambungan digunakan untuk semua pengguna dan mungkin meminta kata laluan sistem anda; membatalkan atau pemasangan sambungan yang gagal masih memilih dan melancarkan Claude. Mulakan semula pelayar anda, dayakan sambungan jika diminta, dan log masuk ke Claude untuk selesai menyambungkannya. Jalankan `/chrome` dalam Claude untuk menyemak sambungan. Firefox dan Zen tidak menyokong sambungan ini. Jika Claude sudah menjadi ejen lalai anda sebelum penyediaan ini ditambah, pilihnya sekali lagi untuk memasang sambungan.

Setelah anda memilih, `Super + Shift + Ctrl + A` melancarkan ejen lalai dalam tetingkap terminal khusus (atau memaparkan pemilih jika anda belum memilih). Anda juga boleh melancarkannya terus ke dalam tugasan dengan `omarchy agent prompt "Review this project"`. Freebuff dan DeepSeek Harness tidak menerima gesaan permulaan, jadi ia dibuka dengan gesaan pada papan keratan anda untuk ditampal sebaliknya. Ejen yang dilancarkan dengan cara ini berjalan tanpa pengawasan dalam mod jangan-berhenti-untuk-bertanya masing-masing, jadi bersedialah kerana ia benar-benar akan melakukan sesuatu! MiniMax Code tidak mempunyai mod sedemikian untuk sesi interaktifnya, jadi ia meminta kebenaran seperti biasa. Dan memandangkan ejen enggan mengingati kepercayaan untuk direktori rumah anda, pelancaran daripada `$HOME` bermula dalam `~/Work` sebaliknya.

Terdapat pintasan terminal juga: `a` menjalankan ejen lalai sebaris dalam terminal semasa, manakala `c`, `cx`, dan `cy` memulakan OpenCode, Claude Code, dan Codex secara terus (sekali lagi dalam mod meluluskan secara automatik mereka). Perubahan tema juga disegerakkan kepada ejen: Claude Code, Pi, OpenCode, dan Hermes (setelah Omarchy memasangnya) semuanya mengikut apabila anda menukar tema Omarchy.

### Panel ejen

Bar atas mempunyai ikon ejen. Sebelum anda menyediakan ejen, panelnya membimbing anda untuk log masuk ke Claude, Codex, atau Grok, dan yang pertama menjadi ejen lalai anda. Selepas itu, panel meletakkan setiap langganan pada satu halaman: setiap ejen dan akaun dengan pelannya, meter untuk setiap had sesi 5 jam dan had mingguannya dengan masa sehingga ia ditetapkan semula (tuding untuk peratusan tepat), atau baki prabayar yang tinggal, di bawah baris yang berputar melalui apa yang telah anda gunakan merentas kesemuanya, seperti token minggu ini dan model yang paling kerap anda gunakan. Di bawah _Make something_ ia menawarkan gesaan permulaan untuk tema, plugin, atau apl baharu yang menyerahkan tugasan kepada ejen lalai anda. Apl dibina dengan cara Hype, Monologue, dan Omacut milik Omarchy sendiri dibina, dalam C++ dan Qt Quick, mengikuti kemahiran ejen omarchy-app, dan pengkompil serta komponen Qt yang diperlukannya dipasang sekali. Claude Code, Codex, Grok, Kimi, Cursor dan elaun Grok Botnya, GitHub Copilot, Muse, Antigravity, Kimchi, dan Devin diliputi sejak awal dengan had mereka, dan Hermes, Mistral Vibe, dan Qwen Code menunjukkan sesi dan token mereka setelah anda menggunakannya. Pelan pembekal dan kunci yang anda gunakan melalui pi, omp, atau opencode juga muncul: OpenCode Zen dan Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan, dan Synthetic dengan had mereka; Fireworks, OpenRouter, dan DeepSeek dengan baki prabayar mereka; dan model yang anda jalankan pada perkakasan anda sendiri di bawah Local models. Setiap ejen dikira sekali, di bawah sesiapa yang mengebilnya, walau berapa banyak harness yang anda gunakan untuk menjalankannya.

Klik kiri ikon bar untuk panel, klik kanan untuk melancarkan ejen lalai anda. Rekod penggunaan di sebaliknya dijana semula setiap 15 minit oleh `omarchy agent usage-update`, dan panel malah boleh menggabungkan penggunaan daripada mesin anda yang lain melalui folder yang disegerakkan. Lihat README di bawah `$OMARCHY_PATH/shell/plugins/agents/` untuk tetapan penuh.

### Beberapa langganan

Jika anda membayar lebih daripada satu pelan Claude, Codex, atau Grok — pelan Max peribadi dan pelan kerja, katakan — Omarchy boleh memastikan kesemuanya kekal log masuk dan berpindah antara mereka. Tambah langganan dengan + dalam panel ejen, yang membimbing anda di situ juga, atau dengan `omarchy agent account add claude Work` (atau `codex`, atau `grok`). Ia memasang CLI jika ia tiada. Akaun pertama untuk pembekal log masuk melalui pelayar biasa anda, tepat di tempat CLI sentiasa mencarinya. Setiap akaun selepas itu log masuk melalui tetingkap peribadi, supaya akaun yang pelayar anda sudah log masuk tidak dipilih secara tidak sengaja; log masuk di situ sebagai akaun yang anda tambah, dan tutup mana-mana tetingkap peribadi yang anda sudah buka terlebih dahulu. Jangan sekali-kali log keluar daripada CLI untuk melakukan ini: log keluar membatalkan log masuk yang disimpan, dan akaun itu perlu ditambah semula.

Untuk menyalin log masuk langganan anda ke mesin Omarchy lain melalui SSH, jalankan `omarchy agent account copy user@laptop`. Penghantar membekalkan penerima sementara apabila destinasi tidak mempunyai penerima yang dipasang, supaya mesin Omarchy yang lebih lama boleh menerima akaun tanpa kemas kini. Penerima yang dipasang diutamakan. Ini menyalin semua langganan Claude, Codex, dan Grok; tambah nama pembekal untuk memilihnya, seperti dalam `omarchy agent account copy laptop claude`. Nama akaun dan ID arahan sepadan dengan sumber, termasuk akaun yang sudah ada pada destinasi. Akaun destinasi yang tidak berkaitan menerima akhiran angka jika namanya bercanggah, dan tetapan, kemahiran, plugin, serta sejarah perbualan kekal tempatan pada setiap mesin.

Kelayakan destinasi sedia ada dikekalkan. Akaun sumber yang sudah log masuk di situ disegerakkan namanya tanpa menggantikan kelayakannya; akaun lain ditambah di sebelahnya. Untuk menggantikan kelayakan yang disimpan bagi akaun yang sepadan, gunakan `omarchy agent account copy --replace laptop claude` selepas menutup sesi akaun itu pada destinasi. Destinasi baharu juga mendapat akaun aktif sumber dan keutamaan penukaran; destinasi yang sudah mantap mengekalkan miliknya sendiri.

Kelayakan bergerak melalui SSH dan disimpan dalam fail peribadi pada destinasi, jadi salin hanya ke mesin yang anda percayai. Ini ialah salinan sekali sahaja, bukan penyegerakan berterusan. Token muat semula Codex boleh digilirkan oleh mesin lain, menyebabkan log masuk yang disalin perlu diperbaharui; log masuk berasingan kekal pilihan paling boleh dipercayai untuk penggunaan serentak pada beberapa mesin. Lihat [panduan pengesahan akaun Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Satu akaun bagi setiap pembekal aktif, dan setiap sesi baharu bermula sebegitu: `cx`, `cy`, `claude`, `codex`, atau `grok` biasa, apa-apa sahaja yang dilancarkan melalui `omarchy agent`, dan skrip atau editor yang mencari CLI pada `PATH`. Tukar dengan `omarchy agent account use work` (dan kembali dengan `omarchy agent account use main`), atau dalam panel dengan menekan nombor akaun kemudian `Enter` (atau mengklik butang Usenya). Sesi yang sudah berjalan kekal pada akaun ia bermula. Sejarah perbualan, tetapan, kemahiran, dan plugin dikongsi merentas akaun, jadi `claude --continue` dalam folder yang sama menyambung dari tempat anda berhenti pada akaun baharu.

Dengan lebih daripada satu akaun, panel menunjukkan had setiap akaun bersebelahan, dengan yang aktif ditandakan. Secara lalai Omarchy memberitahu anda apabila akaun aktif melepasi 95% daripada had, dan mengklik pemberitahuan bertukar kepada akaun dengan ruang paling banyak. Tuding baris akaun dalam panel dan klik Autoswitch yang muncul di sebelah Use (atau tekan `m`), atau jalankan `omarchy agent account mode auto`, untuk membolehkannya bertukar sendiri sebaliknya; semasa ia hidup, Autoswitch mengambil tempat Use, dan mengkliknya sekali lagi kembali kepada memberitahu. Tambah nombor untuk menukar ambang, seperti dalam `omarchy agent account mode auto 90`. Jika setiap akaun melepasi ambang, anda akan diberitahu sekali, bersama-sama akaun mana yang bebas terlebih dahulu. Semasa akaun aktif berada dalam 15 mata daripada ambangnya (80% pada lalai), hadnya disemak setiap tiga minit dan bukan setiap 15.

`omarchy agent account list` menunjukkan setiap akaun dan had terkininya, `omarchy agent account remove work` melupakan satu akaun, dan `omarchy agent account rename primary Hey` menamakan semula satu akaun (atau klik nama akaun dalam panel). Arahan ini berfungsi pada akaun ejen lalai anda; untuk mencapai pembekal lain, namakannya dahulu, seperti dalam `omarchy agent account use codex side`. Log masuk yang anda sudah ada dalam `~/.claude` atau `~/.codex` ialah akaun _Main_ dan kekal di tempatnya. Akaun yang dibiarkan tidak digunakan selama lebih daripada kira-kira lapan jam boleh menunjukkan _Sign-in required_; kliknya untuk log masuk akaun itu semula terus dalam panel, atau mulakan sesi di dalamnya, yang menyegarkan log masuk dengan sendirinya. Pelayan MCP yang anda ada apabila akaun ditambah ikut bersamanya, tetapi yang anda tambah kemudian dengan `claude mcp add` hanya sampai ke akaun tempat anda menambahnya. Claude Desktop dan alat yang dikonfigurasikan dengan laluan mutlak ke binari CLI tidak mengikuti penukaran. `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, atau `GROK_HOME` yang eksplisit diutamakan berbanding akaun yang dipilih.

### Diagnosis ranap

Omarchy memerhati systemd-coredump untuk ranap proses. Apabila sesuatu mengalami segfault, anda akan mendapat pemberitahuan "Process crashed" — kliknya, dan ranap itu diserahkan kepada ejen lalai anda bersama-sama kemahiran diagnose-crash Omarchy, yang membimbing ejen untuk menetapkan fakta daripada core dump dan memutuskan sama ada ranap itu berbaloi dilaporkan ke huluan. Anda juga boleh menjalankannya secara manual terhadap mana-mana PID daripada `coredumpctl list` dengan `omarchy agent crash <pid>`.

Pemerhatian hidup secara lalai. Matikannya di bawah _Trigger > Toggle > Crash Capture_ (atau dengan `omarchy toggle crash-capture`) dan pemberitahuan berhenti; `omarchy agent crash <pid>` masih berfungsi secara manual.

Ranap juga boleh disenyapkan satu program pada satu masa, yang merupakan apa yang ditawarkan diagnosis kepada anda pada penghujungnya. `omarchy crash mute hyprland` menghentikan pemberitahuan untuk program itu sahaja, `omarchy crash mute hyprland off` mengembalikannya, dan `omarchy crash mute` dengan sendirinya menyenaraikan apa yang telah anda senyapkan. Ia menerima laluan binari semudah namanya, jadi `omarchy crash mute /usr/bin/hyprland` melakukan perkara yang sama. Petik nama yang mempunyai ruang di dalamnya, seperti dalam `omarchy crash mute 'Some App'`. Semua yang lain masih memberitahu, dan program yang disenyapkan masih ranap — ini menyembunyikan peringatan, ia tidak membaiki apa-apa.

### Apl desktop

Menu _Install > AI_ juga membawa beberapa apl AI grafik: apl desktop ChatGPT, apl desktop Claude (beta Linux Anthropic, dengan tab Chat, Cowork, dan Claude Code), Grok Bot untuk berbual dengan model xAI, Herdr Desktop, Hermes Desktop, OpenClaw, apl desktop Perplexity, dan T3 Code. Grok Bot ialah apl sembang desktop. Ejen pengekodan ialah arahan `grok`.

Hermes Desktop ialah yang perlu diketahui, kerana sesebuah mesin mempunyai satu Hermes, dan ia milik apl itu: Hermes hanya pernah dipasang melalui apl, dan arahan `hermes` yang dijalankan ejen lalai ialah milik apl itu. Memilih Hermes sebagai ejen lalai memasang perkara yang sama seperti entri _Install > AI_: pakej, dan runtime Hermes di bawah `~/.hermes` yang disediakan oleh pemasang Hermes sendiri, yang mengambil masa beberapa minit pada kali pertama. Runtime itu ialah satu-satunya Hermes yang digunakan oleh arahan terminal `hermes`, ejen lalai dan apl, dan ia mengemas kini dirinya dengan `hermes update` dan bukan menunggu keluaran Omarchy. Memasangnya juga menyerahkan tema Omarchy kepada Hermes sebagai skin bernama `omarchy`, yang diikuti oleh setiap permukaan Hermes apabila anda menukar tema; pilih yang lain di bawah tetapan Appearance Hermes atau dengan `/skin` jika anda lebih suka ia tidak berbuat demikian, dan Omarchy membiarkan pilihan itu. Membuang apl di bawah _Remove > AI_ menutup Hermes terlebih dahulu, termasuk gateway, mengambil runtime itu bersamanya, dan mengekalkan sembang, memori, dan kemahiran yang ditulis Hermes untuk dirinya melainkan anda menyuruh sebaliknya: ia bertanya, dengan lalai tidak, sama ada data itu dan tetapan sambungan anda juga patut dibuang.

Pengalaman desktop OpenClaw ialah Control UInya, yang dibuka sebagai apl web yang disokong oleh gateway tempatannya sendiri. OpenClaw tinggal dalam `~/.openclaw` dan mengemas kini dirinya: gunakan butang "Update Gateway" Control UI atau jalankan `openclaw update`, dan gateway dimulakan semula pada versi baharu. Omarchy hanya memilih keluaran yang dimulakan pemasangan baharu. Membuang OpenClaw di bawah _Remove > AI_ mengambil perkhidmatan gateway dan apl bersamanya kemudian bertanya sama ada `~/.openclaw` juga patut dibuang, kerana itu menyimpan sembang dan kelayakan anda bersama-sama OpenClaw sendiri dan runtime plugin yang dimuat turunnya; lalai mengekalkannya, dan memasang OpenClaw sekali lagi mengambilnya semula.

Herdr Desktop ialah apl desktop [Herdr](https://herdr.dev): ruang, tab, dan panel terminal serta ejen pengekodan yang terus berjalan dalam terasnya apabila anda menutup tetingkap. Ia datang daripada pemasang Herdr sendiri dan bukan pakej, jadi ia tinggal dalam `~/.local/share/herdr-app`, membawa terasnya dalam `~/.local/bin/herdr-core` apabila anda belum memilikinya, dan mengemas kini kedua-duanya sendiri. Ia berada di sebelah arahan `herdr` yang dihantar Omarchy pada `Super + Ctrl + Return` dan bukan menggantikannya, dan mendapat kekunci terus arahan itu: `Alt + Return` dan `Alt + Shift + Return` membelah panel ke bawah atau ke kanan, `Alt + Escape` menutupnya, `Ctrl + Alt + Arrow` bergerak antara panel, `Alt + 1..9` dan `Alt + Left/Right` memilih tab, dan `Alt + Up/Down` bergerak antara ruang. `Ctrl + 1..9` memilih ruang dan `Alt + Shift + Up/Down` melangkah melalui ejen. Kekunci awalan `Ctrl + Space` kekal untuk terminal sahaja, kerana apl tidak boleh menahan kekunci Ctrl biasa untuk urutan. Omarchy menulis ini ke `~/.config/herdr-app/keys.json`, dan `omarchy-refresh-herdr-app` meletakkannya semula. Memasangnya memilih tema Omarchy Herdr, yang mengikuti tema Omarchy anda sejak itu. Herdr menyimpan satu tema untuk mod cerah dan satu untuk mod gelap, jadi selepas bertukar antara tema Omarchy gelap dan cerah, pilih Omarchy dalam pemilih tema Herdr sekali lagi untuk mod yang satu lagi.

T3 Code berjalan daripada keluaran AppImage rasminya dalam `~/.local/share/t3code` dan bukan daripada pakej, jadi ia mengemas kini dirinya. Memasangnya bertanya sama ada untuk bermula pada saluran Stable atau Nightly; tukar kemudian dalam tetapan T3 Code. Thread dan tetapan anda tinggal dalam `~/.t3`, dan membuang T3 Code di bawah _Remove > AI_ mengambilnya bersama-sama.

### Model tempatan

Jalankan model terbuka pada mesin anda sendiri untuk ejen pengekodan anda. Gesaan dan kod anda kekal pada mesin; tiada apa yang dihantar kepada model meninggalkannya. Bermula dengan:

```bash
omarchy agent local use best
```

Atau, dalam panel ejen di bar atas, pilih + kemudian Local AI, yang muncul apabila model muat pada mesin ini. Kali pertama, ini memasang Podman, yang menjalankan model, dan pada mesin NVIDIA toolkit bekas NVIDIA, yang memberikannya GPU. Omarchy kemudian memilih model yang disyorkan untuk mesin ini, memuat turunnya, dan memulakannya. Jangkakan muat turun berpuluh GB dan sebahagian besar memori mesin digunakan semasa model berjalan: Flash Next menggunakan kira-kira 100 GiB dengan konteks penuh 256Knya. Jika model lain memegang memori yang diperlukannya, ia disediakan dalam keadaan berhenti, bersedia untuk bermula setelah anda menghentikan satu. Model berhenti semasa log keluar; hentikannya sendiri apabila anda memerlukan memori untuk perkara lain.

`omarchy agent local list` menunjukkan pilihan dan menjelaskan mengapa sesetengahnya tidak muat. Untuk menyediakan yang lain, jalankan `omarchy agent local use <recipe>`. Hari ini, `qwen3.8-flash-next-gufo` dan `qwen3.8-27b-gufo` tersedia untuk mesin Strix Halo 128 GB; 27B mengambil kira-kira 40 GiB, jadi ia meninggalkan ruang untuk kerja lain. Resipi dan syor baharu tiba dengan `omarchy update`, melalui pakej.

Setiap model yang anda sediakan mendapat barisnya sendiri dalam panel ejen, di sebelah langganan anda: main untuk memulakannya, jeda untuk menghentikannya dan membebaskan memorinya, dan butang terminal untuk membuka ejen anda padanya. Beberapa boleh berjalan serentak apabila ia muat dalam memori bersama-sama; jika satu tidak muat, Omarchy memberitahu model yang sedang berjalan mana perlu dihentikan. Seret baris untuk menyusunnya semula, dan tekan Delete pada baris yang dipilih untuk membuang model dan muat turunnya.

Daripada baris arahan, `omarchy agent local start <recipe>` dan `omarchy agent local stop <recipe>` melakukan perkara yang sama, `omarchy agent local status` menunjukkan setiap model, dan `omarchy agent --local` membuka ejen lalai anda pada model terakhir yang anda mulakan (pi jika ejen lalai anda tidak boleh menggunakan model tempatan). Mana-mana klien yang serasi OpenAI juga boleh menyambung: `status` menunjukkan alamat setiap model (yang pertama ialah `http://127.0.0.1:11435/v1`), nama resipi ialah model, dan kunci berada dalam `~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` memadam model dan muat turun yang tidak digunakan model lain.

Runtime pihak ketiga dilabel dengan penerbitnya. Omarchy menjalankan setiap model tanpa akses rangkaian.

### LLM tempatan

Omarchy mengesyorkan dua cara menjalankan model LLM tempatan: LM Studio dan Ollama. LM Studio menyediakan antara muka GUI untuk mencari model open-weight, memasangnya, dan menjalankannya. Ia cara yang bagus untuk bermula dengan mudah. Ollama menawarkan CLI untuk melakukan perkara yang sama. Tetapi jika anda baharu kepada model tempatan, saya akan bermula dengan LM Studio. Anda boleh memasang mana-mana satu di bawah _Install > AI_ dalam Omarchy Menu.

### Kemahiran Omarchy

Kemahiran ejen membantu AI menggunakan alat tertentu dengan cara tertentu, dan Omarchy dihantar dengan kemahiran lalai untuk menyesuaikan sistem. Seperti mengubah suai config Hyprland anda, melaraskan bar, atau malah mencipta tema baharu dari awal. Ia dipautkan secara simbolik ke dalam direktori kemahiran untuk Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` dan setiap `~/.hermes/profiles/*/skills`), dan lokasi generik `~/.agents/skills`, jadi kebanyakan harness mengambilnya secara automatik.

Tetapi anda patut menganggap kemahiran ini sebagai eksperimen. Model berbeza akan menggunakannya dengan kesan berbeza. Sebaiknya jalankan dalam mod pelan terlebih dahulu, supaya anda mempunyai idea tentang apa yang ejen ingin ubah. Dan kemudian bersedialah untuk membuat rollback perubahan atau malah menggunakan `omarchy reinstall configs`, jika ejen mengacaukan semuanya.
