ඔබ වෙනුවෙන් පෙරනිමියක් තෝරා නොදී, පහත කේතකරණ ඒජන්තවරුන් සඳහා දියත් කරන්නන් Omarchy තුළ ඇතුළත් වේ. එහි CLI එක පළමු වර භාවිතයේදී ස්ථාපනය කිරීමට විධානයක් ධාවනය කරන්න, ඉන්පසු විමසූ විට සත්‍යාපනය කරන්න. ### ඒජන්තවරුන් ස්ථාපනය කිරීම සහ යාවත්කාලීන කිරීම

Hermes හැර, මෙම ඒජන්තවරුන් mise හි lazy ස්ථාපනය භාවිතා කරයි: පළමු දියත් කිරීමේදී CLI එක ස්ථාපනය වන අතර, පසුකාලීන දියත් කිරීම්වලදී එයම නැවත භාවිතා වේ. එසේම mise විසින් ස්ථාපිත ඒජන්තයෙකු සඳහා නව නිකුතුවක් තිබේදැයි ආරම්භ වීමට මොහොතකට පෙර හෝ shell විමසුමකදී පසුබිමේ, උපරිම වශයෙන් සෑම පැය හතරකටම වරක් පරීක්ෂා කරයි. එම යාවත්කාලීන කිරීම අසාර්ථක වුවහොත් හෝ ඔබ නොබැඳිව සිටියහොත්, ස්ථාපිත අනුවාදය ධාවනය වේ. `omarchy update` මගින් Omarchy හි සෙසු දේවල් සමඟ ස්ථාපිත ඒජන්තවරුන්ද යාවත්කාලීන කරන අතර, `mup` මගින් යාවත්කාලීන කරන්නේ mise මගින් කළමනාකරණය වන මෙවලම් පමණි.

`claude update`, `codex update` වැනි ඒජන්තයාගේම යාවත්කාලීන කරන්නා, හෝ යෙදුමක ඇති යාවත්කාලීන බොත්තම, mise මගින් කළමනාකරණය වන ස්ථාපනය යාවත්කාලීන නොකරයි. `codex update` අසාර්ථක වන අතර, `claude update` මගින් සාර්ථක බව වාර්තා කරමින් mise විසින් නිරීක්ෂණය නොකරන වෙනම පිටපතක් ස්ථාපනය කළ හැකිය. ඒජන්තයෙකුගේ ස්වදේශීය ස්ථාපකය සහ යාවත්කාලීන කරන්නා භාවිතා කිරීමට ඔබ කැමති නම්, එය `disable_tools` වෙත එක් කරන්න; [පෙර ස්ථාපිත CLI මෙවලම්](18-development-tools.md#preinstalled-cli-tools) බලන්න.

ඔබට අවශ්‍ය වීමට පෙර වින්‍යාස කර ඇති සියලුම lazy මෙවලම් ස්ථාපනය කිරීමට, `mise install --include-lazy` ධාවනය කරන්න. මෙයට ඒජන්තවරුන් මෙන්ම Omarchy හි අනෙක් පෙරනිමි CLI මෙවලම්ද ඇතුළත් වේ. තනි මෙවලමක් ස්ථාපනය කිරීම හෝ ඔබේම ස්ථාපනයක් භාවිතා කිරීම සඳහා [පෙර ස්ථාපිත CLI මෙවලම්](18-development-tools.md#preinstalled-cli-tools) බලන්න.

`grok` ස්ථාපනය වන්නේ mise හි first-party `grok` පැකේජය හරහාය, `claude` සහ `codex` ස්ථාපනය වන ආකාරයටමය. `grok` ධාවනය කරන්න, නැතහොත් _Setup > Defaults > Agent_ යටතේ එය තෝරන්න. x.ai හි ඇති `curl | bash` ස්ථාපකය මඟ හරින්න. එම මාර්ගය මගින් දෙවන පිටපතක් `~/.grok/bin` තුළ තබන අතර, එය `PATH` හි මුලට එක් කර, Omarchy හි wrapper එක උඩින් ලියයි.

`dsh` විසින් එහි බ්‍රවුසර UI එක `127.0.0.1:3080` මත විවෘත කරන අතර, දියත් කළ නාමාවලිය එහි පෙරනිමි වැඩබිම ලෙස ගනියි. එහි බ්‍රවුසර UI එක ආරම්භක විමසුමක් නොගන්නා බැවින්, `omarchy agent prompt` මගින් එය විවෘත කරන්නේ විමසුම ඔබේ පසුරුපුවරුවේ තබා ඔබට ඇලවීමට හැකි වන පරිදිය. Omarchy විසින් එය DeepSeek හි no-approval අවසර පෙරසිටුවම සමඟ ආරම්භ කරයි. ඔබ එහි නිල ආකෘති API එක භාවිතා කරන විට DeepSeek Harness විසින් සැසි ලොග DeepSeek වෙත උඩුගත කරයි; එහි බ්‍රවුසර UI එකේ _Settings > General > Upload Session Log_ යටතේ එය අක්‍රිය කරන්න. ඔබ එයට එවන ප්‍රතිපෝෂණද සැසිය සමඟම උඩුගත වේ, ඔබ එය `DSH_TELEMETRY_MODE=DISABLED` සමඟ ආරම්භ නොකළහොත් මිස.

### පෙරනිමි ඒජන්තයා

`omarchy default agent <name>` සමඟින් හෝ Omarchy Menu එකේ (`Super + Space`) _Setup > Defaults > Agent_ යටතේ ඔබේ පෙරනිමි ඒජන්තයා තෝරන්න. ඒජන්තයා තවම ස්ථාපනය කර නොමැති නම්, එය තේරීමෙන් පළමුව එය ස්ථාපනය වේ. නව Omarchy එකක් එක් වරක් පමණක් පෙන්වන දැනුම්දීමකින් මෙම තේරීම කරන ලෙස ඔබව ආරාධනා කරනු ඇත.

Claude තේරීමෙන් Chromium, Chrome, Brave, Brave Origin, සහ Edge සඳහා එහි බ්‍රවුසර දිගුව පිහිටුවීමටද උත්සාහ කරයි. දිගුව පිහිටුවීම සියලුම පරිශීලකයින්ට අදාළ වන අතර ඔබේ පද්ධති මුරපදය ඉල්ලා සිටිය හැකිය; දිගුව ස්ථාපනය අවලංගු කිරීම හෝ අසාර්ථක වීම වුවද Claude තෝරාගෙන දියත් කරයි. ඔබේ බ්‍රවුසරය නැවත ආරම්භ කරන්න, විමසුවහොත් දිගුව සක්‍රිය කරන්න, සහ එය සම්බන්ධ කිරීම අවසන් කිරීමට Claude වෙත පුරනය වන්න. සම්බන්ධතාවය පරීක්ෂා කිරීමට Claude තුළ `/chrome` ධාවනය කරන්න. Firefox සහ Zen මෙම දිගුවට සහාය නොදක්වයි. මෙම පිහිටුවීම එක් කිරීමට පෙර සිටම Claude ඔබේ පෙරනිමිය වූයේ නම්, දිගුව ස්ථාපනය කිරීමට එය නැවත තෝරන්න.

ඔබ තෝරාගත් පසු, `Super + Shift + Ctrl + A` මගින් පෙරනිමි ඒජන්තයා කැප වූ ටර්මිනල් කවුළුවක දියත් කරයි (හෝ ඔබ තවම තෝරාගෙන නොමැති නම් තේරීම්කරු ගෙන එයි). `omarchy agent prompt "Review this project"` සමඟ ඔබට එය කෙලින්ම කාර්යයකටද දියත් කළ හැකිය. Freebuff සහ DeepSeek Harness ආරම්භක විමසුමක් නොගන්නා බැවින්, ඒවා විවෘත වන්නේ ඒ වෙනුවට විමසුම ඔබේ පසුරුපුවරුවේ තබා ඔබට ඇලවීමට හැකි වන පරිදිය. මේ ආකාරයෙන් දියත් කරන ඒජන්තවරුන් ඔවුන්ගේ අදාළ don't-stop-to-ask මාදිලිවල නොසැලකිලිමත්ව ධාවනය වන බැවින්, ඔවුන් ඇත්තටම දේවල් කිරීමට සූදානම් වන්න! MiniMax Code හි එහි අන්තර්ක්‍රියාකාරී සැසි සඳහා එවැනි මාදිලියක් නොමැති බැවින්, එය සුපුරුදු පරිදි අවසර ඉල්ලයි. එසේම ඒජන්තවරුන් ඔබේ නිවසේ නාමාවලිය සඳහා විශ්වාසය මතක තබා ගැනීම ප්‍රතික්ෂේප කරන බැවින්, `$HOME` වෙතින් කරන දියත් කිරීම් ඒ වෙනුවට `~/Work` තුළ ආරම්භ වේ.

ටර්මිනල් කෙටිමංද තිබේ: `a` මගින් පෙරනිමි ඒජන්තයා වත්මන් ටර්මිනලය තුළම ධාවනය වන අතර, `c`, `cx`, සහ `cy` මගින් OpenCode, Claude Code, සහ Codex කෙලින්ම ආරම්භ කරයි (නැවතත් ඒවායේ ස්වයං-අනුමත කිරීමේ මාදිලිවල). තේමා වෙනස්කම්ද ඒජන්තවරුන් වෙත සමමුහුර්ත වේ: ඔබ Omarchy තේමාව මාරු කරන විට Claude Code, Pi, OpenCode, සහ Hermes (Omarchy විසින් එය ස්ථාපනය කළ පසු) යන සියල්ලම ඒ අනුව වෙනස් වේ.

### ඒජන්ත පැනලය

ගිණුම් එකකට වඩා ඇති විට, පැනලය සෑම ගිණුමකම සීමාවන් එක ළඟ එක පෙන්වන අතර, සක්‍රිය එක සලකුණු කරනු ලැබේ. පෙරනිමියෙන් Omarchy විසින් සක්‍රිය ගිණුමක් සීමාවකින් 95%ක් ඉක්මවූ විට ඔබට දැනුම් දෙන අතර, දැනුම්දීම ක්ලික් කිරීමෙන් වැඩිම ඉඩක් ඇති ගිණුම වෙත මාරු වේ. පැනලයේ ගිණුමක පේළිය උඩින් ගෙන ගොස් Use අසල දිස්වන Autoswitch ක්ලික් කරන්න (හෝ `m` ඔබන්න), නැතහොත් එය තනිවම මාරු වීමට සැලැස්වීමට `omarchy agent account mode auto` ධාවනය කරන්න; එය ක්‍රියාත්මකව ඇති අතර, Autoswitch විසින් Use හි ස්ථානය ගන්නා අතර, එය නැවත ක්ලික් කිරීමෙන් දැනුම් දීම වෙත ආපසු යයි. සීමාව වෙනස් කිරීමට අංකයක් එක් කරන්න, උදාහරණයක් ලෙස `omarchy agent account mode auto 90`. සෑම ගිණුමක්ම සීමාව ඉක්මවා ඇත්නම්, ඔබට ඒ ගැන එක් වරක් අසන්නට ලැබෙනු ඇත, පළමුව නිදහස් වන්නේ කුමන ගිණුමද යන්නත් සමඟය. සක්‍රිය ගිණුමක් එහි සීමාවේ ලක්ෂ්‍ය 15ක් ඇතුළත ඇති අතර (පෙරනිමියෙන් 80%), එහි සීමාවන් සෑම මිනිත්තු 15කට වරක් වෙනුවට සෑම මිනිත්තු තුනකට වරක් පරීක්ෂා කරනු ලැබේ.

`omarchy agent account list` මගින් සෑම ගිණුමක්ම සහ එහි නවතම සීමාවන් පෙන්වයි, `omarchy agent account remove work` මගින් එකක් අමතක කරයි, සහ `omarchy agent account rename primary Hey` මගින් එකක නම වෙනස් කරයි (හෝ පැනලයේ ගිණුමක නම ක්ලික් කරන්න). මෙම විධාන ඔබේ පෙරනිමි ඒජන්තයාගේ ගිණුම් මත ක්‍රියා කරයි; අනෙක් සැපයුම්කරු වෙත ළඟා වීමට, පළමුව ඔහු නම් කරන්න, උදාහරණයක් ලෙස `omarchy agent account use codex side`. ඔබ දැනටමත් `~/.claude` හෝ `~/.codex` තුළ තිබූ පුරනය වීම _Main_ ගිණුම වන අතර එය තිබූ තැනම පවතියි. පැය අටකට වඩා වැඩි කාලයක් භාවිතා නොකර තැබූ ගිණුමකට _Sign-in required_ ලෙස පෙන්විය හැකිය; පැනලය තුළම එම ගිණුමට නැවත පුරනය වීමට එය ක්ලික් කරන්න, නැතහොත් එහි සැසියක් ආරම්භ කරන්න, එය තනිවම පුරනය වීම අලුත් කරයි. ගිණුමක් එක් කරන විට ඔබ සතුව තිබූ MCP සේවාදායකයන් එයටද පැමිණෙන නමුත්, ඔබ පසුව `claude mcp add` සමඟ එක් කරන ඒවා ළඟා වන්නේ ඔබ ඒවා එක් කළ ගිණුමට පමණි. Claude Desktop සහ CLI ද්විමය ගොනුවකට නිරපේක්ෂ මාර්ගයක් සමඟ වින්‍යාස කර ඇති මෙවලම් මාරුව අනුගමනය නොකරයි. පැහැදිලි `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, හෝ `GROK_HOME` එකක් තෝරාගත් ගිණුමට වඩා ප්‍රමුඛතාව ගනියි.

### බිඳවැටීම් රෝග විනිශ්චය

Omarchy විසින් ක්‍රියාවලි බිඳවැටීම් සඳහා systemd-coredump නිරීක්ෂණය කරයි. යමක් segfault වූ විට, ඔබට "Process crashed" දැනුම්දීමක් ලැබෙනු ඇත — එය ක්ලික් කරන්න, එවිට බිඳවැටීම ඔබේ පෙරනිමි ඒජන්තයාට භාර දෙනු ලබන්නේ Omarchy හි diagnose-crash කුසලතාව සමඟිනි, එය core dump එකෙන් කරුණු තහවුරු කර ගැනීම සහ බිඳවැටීම ඉහළට වාර්තා කිරීම වටිනවාද යන්න තීරණය කිරීම හරහා ඒජන්තයාව ගෙන යයි. ඔබට එය `coredumpctl list` වෙතින් ඕනෑම PID එකකට එරෙහිව `omarchy agent crash <pid>` සමඟ අතින්ද ධාවනය කළ හැකිය.

නමුත් ඔබ මෙම කුසලතාව පර්යේෂණාත්මක ලෙස සැලකිය යුතුය. විවිධ ආකෘති එය විවිධ ප්‍රතිඵල සඳහා භාවිතා කරනු ඇත. ඒජන්තයා වෙනස් කිරීමට කැමති දේ පිළිබඳ අදහසක් ඔබට ලැබෙන පරිදි, පළමුව plan මාදිලියේ ධාවනය කිරීම වඩාත් සුදුසුය. ඉන්පසු ඒජන්තයා සියල්ල අවුල් කර දමන්නේ නම්, වෙනස්කම් ආපසු හැරවීමට හෝ `omarchy reinstall configs` ඇමතීමට පවා සූදානම් වන්න.
