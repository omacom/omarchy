# AI

Omarchy හි පහත කේතකරණ නියෝජිතයන් සඳහා දියත්කරුවන් ඇතුළත් වන අතර, ඔබට පෙරනිමියක් තෝරා දෙන්නේ නැත. එහි CLI එක පළමු භාවිතයේදීම ස්ථාපනය කිරීමට විධානයක් ධාවනය කරන්න, පසුව විමසූ විට සත්‍යාපනය කරන්න. Hermes යනු ව්‍යතිරේකයයි: පළමු භාවිතයේදී එය සඳහා කිසිවක් ස්ථාපනය නොවන අතර, එය තේරීමෙන් Hermes Desktop ස්ථාපනය වේ, පහත _ඩෙස්ක්ටොප් යෙදුම්_ හි විස්තර කර ඇති පරිදි.

### නියෝජිතයන් ස්ථාපනය කිරීම සහ යාවත්කාලීන කිරීම

Hermes හැර, මෙම නියෝජිතයන් mise හි lazy ස්ථාපනය භාවිතා කරයි: පළමු දියත් කිරීමේදී CLI එක ස්ථාපනය වන අතර, පසු දියත් කිරීම්වලදී එයම නැවත භාවිතා කරයි. mise විසින් ස්ථාපිත නියෝජිතයෙකු සඳහා නව නිකුතුවක් තිබේදැයි ද පරීක්ෂා කරන්නේ උපරිම වශයෙන් සෑම පැය හතරකට වරක්, එය ආරම්භ වීමට මොහොතකට පෙර හෝ shell prompt එකකදී පසුබිමේදීය. එම යාවත්කාලීනය අසාර්ථක වුවහොත් හෝ ඔබ නොබැඳිව සිටියහොත්, ස්ථාපිත අනුවාදය ධාවනය වේ. `omarchy update` මඟින් Omarchy හි ඉතිරිය සමඟ ස්ථාපිත නියෝජිතයන් යාවත්කාලීන කරන අතර, `mup` මඟින් යාවත්කාලීන කරන්නේ mise මඟින් කළමනාකරණය වන මෙවලම් පමණි.

`claude update`, `codex update` වැනි නියෝජිතයෙකුගේම යාවත්කාලිනකය, හෝ යෙදුමක ඇති යාවත්කාලීන බොත්තම, mise මඟින් කළමනාකරණය වන ස්ථාපනය යාවත්කාලීන නොකරයි. `codex update` අසාර්ථක වන අතර, `claude update` මඟින් mise විසින් නිරීක්ෂණය නොකරන වෙනම පිටපතක් ස්ථාපනය කරමින් සාර්ථක වූ බව වාර්තා කළ හැකිය. ඔබ නියෝජිතයෙකුගේම ස්වදේශීය ස්ථාපකය සහ යාවත්කාලිනකය භාවිතා කිරීමට කැමති නම්, එය `disable_tools` වෙත එක් කරන්න; [පෙර ස්ථාපිත CLI මෙවලම්](18-development-tools.md#preinstalled-cli-tools) බලන්න.

ඔබට අවශ්‍ය වීමට පෙර වින්‍යාස කර ඇති සියලුම lazy මෙවලම් ස්ථාපනය කිරීමට, `mise install --include-lazy` ධාවනය කරන්න. මෙයට නියෝජිතයන් මෙන්ම Omarchy හි අනෙකුත් පෙරනිමි CLI මෙවලම් ද ඇතුළත් වේ. තනි මෙවලමක් ස්ථාපනය කිරීම හෝ ඔබේම ස්ථාපනයක් භාවිතා කිරීම සඳහා [පෙර ස්ථාපිත CLI මෙවලම්](18-development-tools.md#preinstalled-cli-tools) බලන්න.

`grok` ස්ථාපනය වන්නේ mise හි first-party `grok` පැකේජය හරහා, `claude` සහ `codex` ආකාරයටමය. `grok` ධාවනය කරන්න, නැතහොත් _Agent > Harness_ යටතේ එය තෝරන්න. x.ai හි ඇති `curl | bash` ස්ථාපකය මඟ හරින්න. එම මාර්ගය `~/.grok/bin` තුළ දෙවන පිටපතක් තබයි, එය `PATH` හි මුලට එක් කරයි, සහ Omarchy හි wrapper එක උඩින් ලියයි.

`dsh` එහි browser UI එක `127.0.0.1:3080` මත විවෘත කරන අතර, දියත් කළ නාමාවලිය එහි පෙරනිමි workspace එක වේ. එහි browser UI එක ආරම්භක prompt එකක් නොගන්නා බැවින්, `omarchy agent prompt` මඟින් එය විවෘත කරන්නේ ඇලවීමට ඔබේ clipboard එකේ ඇති prompt එක සමඟය. Omarchy එය ආරම්භ කරන්නේ DeepSeek හි අනුමැතිය-අවශ්‍ය-නැති අවසර පෙරසැකසුම සමඟය. ඔබ එහි නිල ආකෘති API එක භාවිතා කරන විට DeepSeek Harness විසින් සැසි ලොග DeepSeek වෙත උඩුගත කරයි; එහි browser UI එකේ _Settings > General > Upload Session Log_ යටතේ එය අක්‍රිය කරන්න. ඔබ එයට යවන ප්‍රතිපෝෂණ ද සැසිය සමඟ උඩුගත වේ, ඔබ එය `DSH_TELEMETRY_MODE=DISABLED` සමඟ ආරම්භ කළහොත් මිස.

### පෙරනිමි නියෝජිතයා

`omarchy default agent <name>` සමඟ හෝ Omarchy Menu එකේ (`Super + Space`) _Agent > Harness_ යටතේ ඔබේ පෙරනිමි නියෝජිතයා තෝරන්න. නියෝජිතයා තවම ස්ථාපනය කර නොමැති නම්, එය තේරීමෙන් පළමුව එය ස්ථාපනය වේ. නැවුම් Omarchy එකක් එක් වරක් පමණක් පෙන්වන දැනුම්දීමකින් මෙම තේරීම කිරීමට ඔබට ආරාධනා කරයි.

Claude තේරීමෙන් Chromium, Chrome, Brave, Brave Origin, සහ Edge සඳහා එහි browser දිගුව සැකසීමට ද උත්සාහ කරයි. දිගු සැකසුම සියලුම පරිශීලකයන්ට අදාළ වන අතර ඔබේ පද්ධති මුරපදය ඉල්ලා සිටිය හැකිය; අවලංගු කිරීම හෝ අසාර්ථක දිගු ස්ථාපනයක් වුවද Claude තෝරාගෙන දියත් කරයි. ඔබේ browser එක නැවත ආරම්භ කරන්න, විමසුවහොත් දිගුව සක්‍රිය කරන්න, සහ එය සම්බන්ධ කිරීම අවසන් කිරීමට Claude වෙත පුරනය වන්න. සම්බන්ධතාවය පරීක්ෂා කිරීමට Claude තුළ `/chrome` ධාවනය කරන්න. Firefox සහ Zen මෙම දිගුවට සහාය නොදක්වයි. මෙම සැකසුම එක් කිරීමට පෙර Claude දැනටමත් ඔබේ පෙරනිමිය වී තිබුණේ නම්, දිගුව ස්ථාපනය කිරීමට එය නැවත තෝරන්න.

### නියෝජිත පැනලය

ඉහළ තීරුවේ නියෝජිත අයිකනයක් ඇත. ඔබ නියෝජිතයෙකු සකසා ගැනීමට පෙර, එහි පැනලය Claude, Codex, හෝ Grok වෙත පුරනය වීම හරහා ඔබව රැගෙන යන අතර, ඉන් පළමු එක ඔබේ පෙරනිමි නියෝජිතයා බවට පත් වේ. ඉන් පසුව, පැනලය සෑම දායකත්වයක්ම එකම පිටුවකට ගෙන එයි: සෑම නියෝජිතයෙකුම සහ ගිණුමක්ම එහි සැලැස්ම සමඟ, එහි පැය 5 සැසි සහ සතිපතා සීමා එකිනෙක සඳහා එය යළි සැකසෙන තෙක් ඇති කාලය සමඟ මීටරයක් (නිවැරදි ප්‍රතිශතය සඳහා උඩින් තබන්න), නැතහොත් ඉතිරි පෙරගෙවුම් ශේෂය, ඔබ ඒ සියල්ල හරහා භාවිතා කර ඇති දේ හරහා භ්‍රමණය වන පේළියක් යට, මෙම සතියේ tokens සහ ඔබ වැඩිපුරම භාවිතා කළ ආකෘතිය වැනි. _Make something_ යටතේ එය ඔබේ පෙරනිමි නියෝජිතයාට කාර්යය භාර දෙන නව තේමාවක්, plugin එකක්, හෝ යෙදුමක් සඳහා ආරම්භක prompts ලබා දෙයි. යෙදුම් තැනෙන්නේ Omarchy හිම Hype, Monologue, සහ Omacut තැනෙන ආකාරයට, C++ සහ Qt Quick වලින්, omarchy-app නියෝජිත කුසලතාව අනුගමනය කරමින් වන අතර, ඔවුන්ට අවශ්‍ය compiler එක සහ Qt කොටස් ස්ථාපනය වී එයි. Claude Code, Codex, Grok, Kimi, Cursor සහ එහි Grok Bot දීමනාව, GitHub Copilot, Muse, Antigravity, Kimchi, සහ Devin ඔවුන්ගේ සීමා සමඟ පෙට්ටියෙන්ම ආවරණය වන අතර, Hermes, Mistral Vibe, සහ Qwen Code ඔබ ඒවා භාවිතා කළ පසු ඔවුන්ගේ සැසි සහ tokens පෙන්වයි. ඔබ pi, omp, හෝ opencode හරහා භාවිතා කරන සැපයුම්කරු සැලසුම් සහ යතුරු ද දිස් වේ: OpenCode Zen සහ Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan, සහ Synthetic ඔවුන්ගේ සීමා සමඟ; Fireworks, OpenRouter, සහ DeepSeek ඔවුන්ගේ පෙරගෙවුම් ශේෂ සමඟ; සහ Local models යටතේ ඔබ ඔබේම දෘඩාංග මත ධාවනය කරන ආකෘති. සෑම නියෝජිතයෙකුම ගණන් ගනු ලබන්නේ එක් වරක් පමණි, ඔබ එය කොපමණ harness ගණනක් හරහා ධාවනය කළත්, එයට බිල් කරන්නේ කවුරුන් වුවද ඔවුන් යටතේය.

පැනලය සඳහා තීරු අයිකනය වම්-ක්ලික් කරන්න, ඔබේ පෙරනිමි නියෝජිතයා දියත් කිරීමට දකුණු-ක්ලික් කරන්න. එය පිටුපස ඇති භාවිත වාර්තා සෑම මිනිත්තු 15කට වරක් `omarchy agent usage-update` මඟින් යළි ජනනය වන අතර, පැනලයට සමමුහුර්ත කළ ෆෝල්ඩරයක් හරහා ඔබේ අනෙකුත් යන්ත්‍රවලින් භාවිතය ඒකාබද්ධ කිරීමට පවා හැකිය. සම්පූර්ණ සැකසුම් සඳහා `$OMARCHY_PATH/shell/plugins/agents/` යටතේ ඇති README එක බලන්න.

### දායකත්ව කිහිපයක්

`omarchy agent account list` මඟින් සෑම ගිණුමක්ම සහ එහි නවතම සීමා පෙන්වන අතර, `omarchy agent account remove work` මඟින් එකක් අමතක කරන අතර, `omarchy agent account rename primary Hey` මඟින් එකක නම වෙනස් කරයි (නැතහොත් පැනලයේ ගිණුමේ නම ක්ලික් කරන්න). මෙම විධාන ක්‍රියා කරන්නේ ඔබේ පෙරනිමි නියෝජිතයාගේ ගිණුම් මතය; අනෙක් සැපයුම්කරු වෙත ළඟා වීමට, පළමුව එය නම් කරන්න, `omarchy agent account use codex side` හි මෙන්. ඔබ දැනටමත් `~/.claude` හෝ `~/.codex` තුළ තිබූ පුරනය වීම _Main_ ගිණුම වන අතර එය ඇති තැනම පවතී. පැය අටකට වඩා වැඩි කාලයක් භාවිතා නොකර තැබූ ගිණුමක _Sign-in required_ ලෙස පෙන්විය හැකිය; පැනලයේදීම එම ගිණුමට නැවත පුරනය වීමට එය ක්ලික් කරන්න, නැතහොත් එහි සැසියක් ආරම්භ කරන්න, එය තනිවම පුරනය වීම නැවුම් කරයි. ගිණුමක් එක් කළ විට ඔබ සතුව තිබූ MCP servers එයට ද පැමිණෙන නමුත්, ඔබ පසුව `claude mcp add` සමඟ එක් කරන ඒවා ළඟා වන්නේ ඔබ ඒවා එක් කළ ගිණුමට පමණි. ### බිඳවැටීම හඳුනාගැනීම

Omarchy විසින් ක්‍රියාවලි බිඳවැටීම් සඳහා systemd-coredump නිරීක්ෂණය කරයි. යමක් segfault වූ විට, ඔබට "Process crashed" දැනුම්දීමක් ලැබේ — එය ක්ලික් කරන්න, එවිට බිඳවැටීම Omarchy හි diagnose-crash කුසලතාව සමඟ ඔබේ පෙරනිමි නියෝජිතයාට භාර දෙනු ලැබේ, එය core dump එකෙන් කරුණු තහවුරු කිරීම සහ බිඳවැටීම upstream වෙත වාර්තා කිරීම වටිනවාද යන්න තීරණය කිරීම හරහා නියෝජිතයා රැගෙන යයි. ඔබට `coredumpctl list` වෙතින් ඕනෑම PID එකකට එරෙහිව `omarchy agent crash <pid>` සමඟ එය අතින් ද ධාවනය කළ හැකිය.

නිරීක්ෂණය පෙරනිමියෙන් ක්‍රියාත්මකයි. එය _Trigger > Toggle > Crash Capture_ යටතේ අක්‍රිය කරන්න (නැතහොත් `omarchy toggle crash-capture` සමඟ) එවිට දැනුම්දීම් නතර වේ; `omarchy agent crash <pid>` තවමත් අතින් ක්‍රියා කරයි.

බිඳවැටීම් එක් වැඩසටහනකින් එක බැගින් ද නිහඬ කළ හැකි අතර, එය හඳුනාගැනීම අවසානයේ ඔබට පිරිනමන්නේ එයයි. `omarchy crash mute hyprland` මඟින් එම වැඩසටහන සඳහා පමණක් දැනුම්දීම් නවත්වන අතර, `omarchy crash mute hyprland off` මඟින් ඒවා ආපසු ගෙන එන අතර, `omarchy crash mute` තනිවම ඔබ නිහඬ කර ඇති දේ ලැයිස්තුගත කරයි. එය binary එකේ මාර්ගය එහි නම තරමටම සතුටින් ගන්නා බැවින්, `omarchy crash mute /usr/bin/hyprland` ද එම දෙයම කරයි. එහි හිස්තැනක් ඇති නමක් උපුටා දක්වන්න, `omarchy crash mute 'Some App'` හි මෙන්. අන් සියල්ල තවමත් දැනුම් දෙන අතර, නිහඬ කළ වැඩසටහන තවමත් බිඳ වැටේ — මෙය මතක් කිරීම සඟවයි, එය කිසිවක් නිවැරදි නොකරයි.

Hermes Desktop යනු දැනගත යුතු එකකි, මන්ද යන්ත්‍රයකට ඇත්තේ එක් Hermes එකක් වන අතර එය යෙදුමට අයත් එකකි: Hermes කවදාවත් ස්ථාපනය වන්නේ යෙදුම හරහා පමණක් වන අතර, පෙරනිමි නියෝජිතයා ධාවනය කරන `hermes` විධානය යෙදුමට අයත් එකකි. පෙරනිමි නියෝජිතයා ලෙස Hermes තේරීමෙන් _Install > AI_ ප්‍රවේශය කරන එම දෙයම ස්ථාපනය වේ: පැකේජය, සහ Hermes හිම ස්ථාපකය මඟින් සකසන ලද `~/.hermes` යටතේ ඇති Hermes runtime එක, පළමු වරට මිනිත්තු කිහිපයක් ගත වේ. එම runtime එක terminal `hermes` විධානය, පෙරනිමි නියෝජිතයා සහ යෙදුම යන සියල්ලම භාවිතා කරන එකම Hermes එක වන අතර, Omarchy නිකුතුවක් එනතෙක් බලා නොසිට `hermes update` සමඟ එය තනිවම යාවත්කාලීන වේ. එය ස්ථාපනය කිරීමෙන් Hermes වෙත Omarchy තේමාව `omarchy` නම් skin එකක් ලෙස ද භාර දෙන අතර, ඔබ තේමා මාරු කරන විට සෑම Hermes පෘෂ්ඨයක්ම එය අනුගමනය කරයි; ඔබ එයට කැමති නැති නම් Hermes හි Appearance සැකසුම් යටතේ හෝ `/skin` සමඟ වෙනත් එකක් තෝරන්න, එවිට Omarchy එම තේරීම එලෙසම තබයි. _Remove > AI_ යටතේ යෙදුම ඉවත් කිරීමෙන් පළමුව Hermes වසයි, gateway එක ද ඇතුළුව, එම runtime එක එය සමඟ රැගෙන යයි, සහ ඔබ වෙනත් ආකාරයකින් නොකියන්නේ නම් ඔබේ කතාබස්, මතකයන්, සහ Hermes විසින් තමාටම ලියාගත් කුසලතා තබා ගනී: එම දත්ත සහ ඔබේ සම්බන්ධතා සැකසුම් ද යා යුතුදැයි එය අසයි, පෙරනිමිය නැත යන්නයි.

නියෝජිත කුසලතා AI හට නිශ්චිත මෙවලම් නිශ්චිත ආකාරයකින් භාවිතා කිරීමට උපකාර කරන අතර, Omarchy පද්ධතිය සකස් කිරීම සඳහා පෙරනිමි කුසලතාවක් සමඟ එයි. ඔබේ Hyprland config එක වෙනස් කිරීම, තීරුව සකස් කිරීම, හෝ මුල සිටම නව තේමාවක් නිර්මාණය කිරීම වැනි. එය Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` සහ සෑම `~/.hermes/profiles/*/skills` එකක්ම), සහ සාමාන්‍ය `~/.agents/skills` ස්ථානය සඳහා කුසලතා නාමාවලිවලට symlink කර ඇති බැවින්, බොහෝ harness එය ස්වයංක්‍රීයව ලබා ගනී.

නමුත් ඔබ මෙම කුසලතාව පර්යේෂණාත්මක ලෙස සැලකිය යුතුය. විවිධ ආකෘති එය විවිධ ප්‍රතිඵල සඳහා භාවිතා කරනු ඇත. පළමුව plan ආකාරයෙන් ධාවනය කිරීම වඩාත් හොඳය, එවිට නියෝජිතයා වෙනස් කිරීමට කැමති දේ පිළිබඳ ඔබට අදහසක් ලැබේ. ඉන්පසු නියෝජිතයා සියල්ල අවුල් කළහොත්, වෙනස්කම් ආපසු හැරවීමට හෝ `omarchy reinstall configs` ඇමතීමට පවා සූදානම්ව සිටින්න.
