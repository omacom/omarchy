# දෝෂ නිරාකරණය

### යාවත්කාලීනයකින් මම මගේ පද්ධතිය කඩා දැම්මෙමි!

පළමුව ඔබේ මෑත යාවත්කාලීනයට පෙර තිබූ අනුවාදයට [ඔබේ පද්ධතිය ආපසු ගෙන යාමට](47-system-snapshots.md) උත්සාහ කරන්න. එය සාර්ථක නොවන්නේ නම්, Discord හි #omarchy-help තුළ ඔබේ ගැටලුව බෙදා ගැනීමට `omarchy-debug` භාවිතා කරන්න. ඒ සියල්ලත් අසාර්ථක වන්නේ නම්, `omarchy-reinstall` භාවිතයෙන් පෙරනිමි configs සහ packages නැවත ස්ථාපනය කළ හැකිය.

### සමහර apps මගේ තිරයේ මෙතරම් විශාලව පෙනෙන්නේ ඇයි?

Omarchy 2x අධි-විභේදන තිරයක් ඇතැයි උපකල්පනය කරන බැවින්, ඔබ monitor පැනලයේ පරිමාණයක් තෝරන තුරු එය `GDK_SCALE` 2 ලෙස සකසයි. ඔබ 1x තිරයක සිටින අතර GTK හෝ X11 apps අධික විශාලත්වයෙන් එන්නේ නම්, monitor පැනලයේ ඒ සඳහා 1x තෝරන්න, නැතහොත් `~/.config/hypr/monitors.lua` වෙත `hl.env("GDK_SCALE", "1")` එක් කරන්න (ඉන්පසු විශාලව පෙනෙන ඕනෑම app එකක් නැවත ආරම්භ කරන්න). [monitors පිළිබඳ අත්පොත](33-monitors.md) බලන්න.

Spotify සඳහා, UI එක කුඩා කිරීමට `Ctrl + Minus` භාවිතා කළ හැකිය (විශාල කිරීමට `Ctrl + Plus` භාවිතා කරන්න).

### මගේ Super key binds සියල්ලම ක්‍රියා කිරීම නතර කළේ ඇයි?

සමහර ASUS ROG සහ TUF laptops වල, `Fn + Super` යනු firmware Windows-key lock එකක් සක්‍රිය හෝ අක්‍රිය කරන, පහසුවෙන් මඟ හැරිය හැකි chord එකකි (අහම්බෙන් game එකකින් ඉවත් වීම වැළැක්වීම සඳහා gaming වෙනුවෙන් අදහස් කරන ලද්දකි). එය සිදු වූ බව තිරයේ කිසිවක් ඔබට නොකියයි. lock එක සක්‍රියව තිබෙන අතරතුර, Super කිසිවක් නිකුත් නොකරයි — එබැවින් Super භාවිතා කරන සෑම Omarchy bind එකක්ම නතර වන අතර, Hyprland කැඩුණු බවක් පෙනේ.

`~/.config/hypr/` තුළ ගැඹුරට හාරා බැලීමට පෙර `Fn + Super` වරක් ඔබන්න, එමඟින් Super ආපසු නොඑන්නේ නම්, lock එක සක්‍රියව තබා නොගැනීම සඳහා එය නැවත ඔබන්න. මෙය Fn-lock නොවේ, එය වෙනස් කරන්නේ F-key පේළිය කරන දේ පමණි.

### මගේ Wi-Fi, Bluetooth, audio, හෝ trackpad ක්‍රියා කිරීම දැන්ම නතර වී ඇත

reboot කිරීමට පෙර, අදාළ උප පද්ධතිය පමණක් නැවත ආරම්භ කිරීමට උත්සාහ කරන්න. Omarchy මෙනුවේ _Update > Hardware_ තුළ Wi-Fi, Bluetooth, Audio, සහ Trackpad ඇති අතර, ඒවායින් එකක් නැවත පූරණය කිරීම ‘මිනිත්තු පහකට පෙර එය ක්‍රියා කළේය’ වැනි තත්ත්වයන්ගෙන් බහුතරයක් නිරාකරණය කරයි — නැවත සම්බන්ධ නොවන Bluetooth headset එකක්, suspend එකකින් පසු අක්‍රිය වූ trackpad එකක්, monitor එකක් ගලවා දැමූ විට අතුරුදහන් වූ ශබ්දය.

### මගේ බාහිර speakers වලින් ශබ්දය පිටත් නොවන්නේ ඇයි?

බොහෝ විට ඒවා ප්‍රාථමික ප්‍රතිදානය ලෙස සකසා නැති නිසාය. තීරුවේ දකුණු පස ඇති speaker නිරූපකය ක්ලික් කරන්න, එවිට එය volume popup එක විවෘත කරන අතර එහිදී ඔබට ප්‍රතිදාන උපාංගය තෝරා ගත හැකිය (per-app volumes ද මිශ්‍ර කළ හැකිය).

### මගේ laptop speakers වල ශබ්දය අමුතුය

සමහර laptops වල, Omarchy විසින් built-in speakers වල frequency response එක නිවැරදි කරන speaker tuning එකක් ස්වයංක්‍රීයව යොදනු ලැබේ. `omarchy audio tuning status` මඟින් ඔබේ යන්ත්‍රයේ එවැනි එකක් සක්‍රිය දැයි කියනු ලබන අතර, speakers වල පිරිසිදු ශබ්දයම ඇසීමට ඔබ කැමති නම් `omarchy audio tuning off` මඟින් එය අක්‍රිය කරයි.

### මගේ මුරපදයෙන් login වීමට හෝ sudo කිරීමට මට නොහැකි ඇයි?

බොහෝ විට ඔබ එය දස වරක් වැරදියට type කර අගුලු වැටී ඇත. අගුලු දැමීම මිනිත්තු දෙකකින් පසු තනිවම ඉවත් වේ. ඔබට බලා සිටිය නොහැකි නම්, මෙය lock screen එකේ සිදුවන්නේ නම්, නව TTY එකක් ආරම්භ කිරීමට `CTRL + ALT + F2` ඔබා root ලෙස login වී, පසුව `faillock --reset --user [your-username]` ධාවනය කළ හැකිය. එමඟින් අගුලු දැමීම යළි සකසනු ඇති අතර, ඔබට ඉදිරියට යා හැකිය.

### මගේ මුරපදය පිළිගැනේ, නමුත් මම ආපසු login screen එකටම යමි

ඔබේ මුරපදය නිවැරදි වුවත්, කැඩුණු session environment ගොනුවක් desktop එක ආරම්භ වීම වැළැක්විය හැකිය. `~/.config/uwsm/env.d/` සංස්කරණය කිරීමෙන් පසු මෙය පරීක්ෂා කිරීම විශේෂයෙන් වටිනා වේ.

`Ctrl + Alt + F2` ඔබා, ඔබේ සාමාන්‍ය username එක සහ මුරපදය භාවිතා කර log in වී, වත්මන් boot එකේ user journal එක පරීක්ෂා කරන්න:

```bash
journalctl --user -b -t uwsm_env-preloader --no-pager
```

env output mark එක හමු නොවූ බවට පණිවිඩයකට මඳ වේලාවකට පෙර, `bad substitution` වැනි, ඔබේ environment ගොනු වලින් එකක් නම් කරන දෝෂයක් සොයන්න. නැවත log in වීමට උත්සාහ කිරීමට පෙර එම ගොනුව `env.d` වලින් පිටතට ගෙන යන්න. උදාහරණයක් ලෙස, දෝෂය `99-custom` නම් කරන්නේ නම්:

```bash
mkdir -p ~/.config/uwsm/disabled
mv -i ~/.config/uwsm/env.d/99-custom ~/.config/uwsm/disabled/
```

UWSM විසින් syntax දෝෂයක් ඇති ගොනුවක් මඟ හරිනු ලැබේ, නමුත් ගොනුව ධාවනය වන අතරතුර පමණක් පෙනෙන `bad substitution` වැනි මාරාන්තික දෝෂයක් desktop එක ආරම්භ වීම තවමත් වැළැක්විය හැකිය. `/home` ආපසු ගෙන නොයන බැවින්, system snapshot rollback එකකින් මෙම ගොනු අලුත්වැඩියා නොවේ.

ඔබට log in විය හැකි වූ පසු, සුරකින ලද පිටපත ආපසු ගෙන යාමට පෙර එය නිවැරදි කරන්න. `sh -n` මඟින් ගොනුව ධාවනය නොකර syntax දෝෂ අල්ලා ගත හැකි නමුත්, එය sourced කරන විට සිදුවන සෑම දෝෂයක්ම අල්ලා ගත නොහැකිය. වෙනස්කම් පරීක්ෂා කරන අතරතුර ක්‍රියාකාරී terminal එකක් විවෘතව තබා ගන්න.

### 1Password SSH Agent / CLI සඳහා මගේ 1Password අවසරදීමේ prompts දිස් නොවන්නේ ඇයි?

මෙය හේතු 2ක් නිසා සිදුවිය හැකිය:

සවිස්තරාත්මක approval prompt එක දිස් වීමට නම්, Settings > Advanced > Use Hardware Acceleration සක්‍රිය කළ යුතුය. _සටහන: මෙය ක්‍රියා කිරීම ආරම්භ වීමට reboot එකක් අවශ්‍ය වේ._
