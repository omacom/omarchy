# කිසිවෙකු සහභාගී නොවන ස්ථාපනයන්

Omarchy ISO එකට යතුරුපුවරුව අසල කිසිවෙකු නොමැතිවම එයම ස්ථාපනය කර ගත හැකිය. ස්ථාපකයට එහි වින්‍යාස ගොනු රැගත් `cidata` ලෙස ලේබල් කළ දෙවන ධාවකයක් හමු වුවහොත්, එය ඒවා පිටපත් කර, පිහිටුවීමේ විශාරදය සම්පූර්ණයෙන්ම මඟ හැර, තනිවම නිම කළ පද්ධතියට නැවත පණ ගන්වයි. විශේෂ ISO තැනීමක් නැත, අමතර boot මෙනු ඇතුළත් කිරීමක් නැත — එවැනි ධාවකයක් අමුණා නැත්නම්, කිසිවක් වෙනස් නොවන අතර ඔබට සාමාන්‍ය විශාරදය ලැබේ.

මේ නිසා ඉවත දැමිය හැකි dev පරිසරයන් සඳහා පාදක image එකක් ලෙස Omarchy විශිෂ්ට වේ: Proxmox තුළ හෝ Packer සමඟ VM එකක් සාදන්න, එය boot කරන්න, ඉවත්ව යන්න, SSH හරහා පිවිසෙන්න. `cidata` යනු cloud-init `NoCloud` ලේබලයයි, එබැවින් සියලුම පොදු virtualization මෙවලම් එවැනි ධාවකයක් අමුණන ආකාරය දැනටමත් දනී.

## වින්‍යාස ගොනු

මෙම ගොනු යනු හරියටම ස්ථාපකයේම විශාරදය ලියන ඒවාමය, එබැවින් ආරම්භක කට්ටලයක් ලබා ගැනීමට ඇති පහසුම ක්‍රමය වන්නේ එක් අන්තර්ක්‍රියාකාරී ස්ථාපනයක් (VM එකක වැනි) ධාවනය කර එය `/root` වෙත ලියූ දේ පිටපත් කිරීමයි:

| ගොනුව | අවශ්‍යද | අරමුණ |
|------|----------|---------|
| `user_configuration.json` | ඔව් | තැටිය, ධාරක නාමය, වේලා කලාපය, යතුරුපුවරුව |
| `user_credentials.json` | ඔව් | පරිශීලක නාමය සහ මුරපද hash එක |
| `user_encrypt_installation.txt` | නැත | වින්‍යාසය `disk_encryption` කොටසක් රැගෙන යන විට `true` |
| `authorized_keys` | නැත | SSH පොදු යතුරු, පේළියකට එක බැගින් |
| `tailscale_authkey` | නැත | පළමු boot එකේදී ඔබේ tailnet එකට සම්බන්ධ වීමට Tailscale auth key එක |

`user_credentials.json` සඳහා මුරපද hash එක `openssl passwd -6 "yourpassword"` සමඟ ජනනය කරන්න.

git commit සඳහා නම සහ email එක ස්ථාපනයේ කොටසක් නොවේ. උදාහරණයක් ලෙස SSH හරහා, යන්ත්‍රය ක්‍රියාත්මක වූ පසු `omarchy setup git --name "Jane Doe" --email jane@example.com` සමඟ ඒවා එක් වරක් සකසන්න.

ඔබට `user_credentials.json` වෙනුවට `defer-provisioning` නමැති හිස් ගොනුවක් ද දැමිය හැකිය. එය ඔබ අන්තර්ක්‍රියාකාරීව ක්‍රියාරම්භ කළ හැකි [තවත් අයිතිකරුවෙකු සඳහා සූදානම් කරන ස්ථාපනයම](02-getting-started.md) ධාවනය කරයි: යන්ත්‍රය කිසිදු පෞද්ගලික විස්තරයකින් තොරව ස්ථාපනය වන අතර, එය පළමුව boot කරන ඕනෑම අයෙකු ඔවුන්ගේ යතුරුපුවරුව තෝරා ඔවුන්ගේ පරිශීලකයා සාදයි. එය imaging rig සඳහා වන ආකාරයයි, එහිදී ධාවකය කිසිවෙකුගේ අක්තපත්‍ර කිසිසේත් රැගෙන නොයා යුතුය.

## SSH ප්‍රවේශය

`authorized_keys` පවතින විට, ස්ථාපනය යතුරු පරිශීලකයාගේ `~/.ssh/authorized_keys` ලෙස පිහිටුවයි, `sshd` සක්‍රීය කරයි, සහ ඒ සඳහා firewall එක විවෘත කරයි. (සම්මත Omarchy ස්ථාපනයක් openssh සමඟ සේවාව අක්‍රීය කර port එක වසා දමා එන බැවින්, එසේ නොවුණහොත් කිසිවෙකු සහභාගී නොවන යන්ත්‍රයකට ළඟා විය නොහැකි වනු ඇත.) ස්ථාපනය ඔබේ යතුරු පමණක් එක් කරයි — එය SSH daemon එකේ වෙනත් කිසිදු සත්‍යාපන සැකසුමක් ලිහිල් නොකරයි.

`tailscale_authkey` පවතින විට, ඒ වෙනුවට යන්ත්‍රය පළමු boot එකේදී ඔබේ tailnet එකට සම්බන්ධ වේ: Tailscale ISO එකේ බැඳ ඇති පැකේජවලින් ස්ථාපනය වේ, firewall එක tailnet අතුරුමුහුණතට ඉඩ දෙයි, සහ පසුබිම් කාර්යයක් යන්ත්‍රයට සැබවින්ම ජාලය ලැබුණු විගස සම්බන්ධ වීම ධාවනය කරයි, එය සාර්ථක වන තෙක් නැවත උත්සාහ කරයි. එක් ධාවක image එකකට බොහෝ යන්ත්‍රවලට සේවය කළ හැකි වන පරිදි නැවත භාවිත කළ හැකි, පූර්ව-අනුමත කළ යතුරක් භාවිත කරන්න.

## cidata ධාවකය තැනීම

නිවැරදි ලේබලය ඇති ඕනෑම ගොනු පද්ධතියක් ක්‍රියා කරයි. කුඩා ISO එකක් පහසු ක්‍රමයයි:

```bash
mkdir cidata
cp user_configuration.json user_credentials.json authorized_keys cidata/
genisoimage -output cidata.iso -volid cidata -joliet -rock cidata/
```

ඉන්පසු එය Omarchy ISO එක අසල VM එකට අමුණන්න. මෙන්න සම්පූර්ණ Proxmox උදාහරණයක්:

```bash
qm create 101 --name my-omarchy \
  --bios ovmf --machine q35 --cpu host --cores 4 --memory 8192 \
  --ostype l26 --scsihw virtio-scsi-single \
  --efidisk0 local-lvm:0,efitype=4m,pre-enrolled-keys=0 \
  --scsi0 local-lvm:40,discard=on,iothread=1 \
  --net0 virtio,bridge=vmbr0 --vga virtio --serial0 socket \
  --ide2 local:iso/omarchy.iso,media=cdrom \
  --ide3 local:iso/cidata.iso,media=cdrom \
  --boot order='scsi0;ide2'

qm start 101
```

boot අනුපිළිවෙල හිතාමතාම තැටිය පළමුව ලැයිස්තුගත කරයි: හිස් තැටිය පළමු boot එකේදී ISO එකට වැටෙන අතර, ස්ථාපිත පද්ධතිය ඉන්පසු සදහටම තැටියෙන් boot වේ.

## අවවාද දෙකක්

සංකේතනය කළ කිසිවෙකු සහභාගී නොවන ස්ථාපනයන් සම්පූර්ණයෙන්ම කිසිවෙකු සහභාගී නොවන ඒවා නොවේ — පළමු boot එකේදී තවමත් යමෙකු LUKS මුරවැකිය ටයිප් කළ යුතුය. තවද `user_configuration.json` හි `disk_encryption` කොටස එම මුරවැකිය සරල පෙළින් රැගෙන යන බැවින්, සංකේතනය කළ ස්ථාපනයකින් තැනූ cidata ධාවකයක් එය වන රහස ලෙසම සලකන්න.
