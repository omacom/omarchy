# අධීක්ෂණයකින් තොර ස්ථාපනයන්

Omarchy ISO එකට යතුරුපුවරුව ළඟ කිසිවෙකු නැතිව තනිවම ස්ථාපනය විය හැකිය. ස්ථාපකයට එහි වින්‍යාස ගොනු රැගත් `cidata` ලෙස ලේබල් කළ දෙවන ධාවකයක් හමු වුවහොත්, එය ඒවා පිටපත් කර ගනී, සැකසුම් විශාරදය සම්පූර්ණයෙන්ම මඟ හරියි, තනිවම නිම කළ පද්ධතියට නැවත ආරම්භ වේ. විශේෂ ISO ගොඩනැගීමක් නැත, අමතර ආරම්භ මෙනු ඇතුළත් කිරීමක් නැත — එවැනි ධාවකයක් සවි කර නැත්නම්, කිසිවක් වෙනස් නොවන අතර ඔබට සාමාන්‍ය විශාරදයම ලැබේ.

මෙය ඉවත දැමිය හැකි dev පරිසරයන් සඳහා මූලික ප්‍රතිරූපයක් ලෙස Omarchy විශිෂ්ට කරයි: Proxmox තුළ හෝ Packer සමඟ VM එකක් සාදන්න, එය ආරම්භ කරන්න, ඉවත්ව යන්න, SSH හරහා ඇතුළු වන්න. `cidata` යනු cloud-init `NoCloud` ලේබලයයි, එබැවින් පොදු අථත්‍යකරණ මෙවලම් සියල්ලම දැනටමත් එවැනි ධාවකයක් සවි කරන ආකාරය දනී.

## වින්‍යාස ගොනු

ගොනු යනු හරියටම ස්ථාපකයේම විශාරදය ලියන දේමය, එබැවින් ආරම්භක කට්ටලයක් ලබා ගැනීමට ඇති පහසුම ක්‍රමය එක් අන්තර්ක්‍රියාකාරී ස්ථාපනයක් ක්‍රියාත්මක කර (උදාහරණයක් ලෙස VM එකක) එය `/root` වෙත ලියූ දේ පිටපත් කිරීමයි:

| ගොනුව | අවශ්‍යද | අරමුණ |
|------|----------|---------|
| `user_configuration.json` | ඔව් | තැටිය, ධාරක නාමය, වේලා කලාපය, යතුරුපුවරුව |
| `user_credentials.json` | ඔව් | පරිශීලක නාමය සහ මුරපද හැෂ් එක, සහ සංකේතිත ස්ථාපනයක් සඳහා LUKS මුරවැකිය |
| `user_encrypt_installation.txt` | නැත | වින්‍යාසය තුළ `disk_encryption` කොටසක් ඇති විට `true` |
| `authorized_keys` | නැත | SSH පොදු යතුරු, පේළියකට එක බැගින් |
| `tailscale_authkey` | නැත | පළමු ආරම්භයේදී ඔබේ tailnet එකට සම්බන්ධ වීම සඳහා Tailscale auth යතුර |

`user_credentials.json` සඳහා මුරපද හැෂ් එක `openssl passwd -6 "yourpassword"` සමඟ ජනනය කරන්න.

git commit සඳහා නම සහ විද්‍යුත් තැපෑල ස්ථාපනයේ කොටසක් නොවේ. යන්ත්‍රය ක්‍රියාත්මක වූ පසු, උදාහරණයක් ලෙස SSH හරහා, `omarchy setup git --name "Jane Doe" --email jane@example.com` සමඟ ඒවා සකසන්න.

ඔබට `user_credentials.json` වෙනුවට `defer-provisioning` නමැති හිස් ගොනුවක් ද එක් කළ හැකිය. එය ඔබ අන්තර්ක්‍රියාකාරීව ක්‍රියාත්මක කළ හැකි [තවත් අයිතිකරුවෙකු සඳහා සූදානම් කිරීමේ ස්ථාපනයම](02-getting-started.md) ක්‍රියාත්මක කරයි: යන්ත්‍රය කිසිදු පෞද්ගලික විස්තරයකින් තොරව ස්ථාපනය වන අතර, එය මුලින්ම ආරම්භ කරන ඕනෑම අයෙකු තම යතුරුපුවරුව තෝරා ගෙන තම පරිශීලකයා සාදා ගනී. ධාවකය තුළ කිසිවෙකුගේ අක්තපත්‍ර කිසිසේත්ම තිබිය යුතු නැති ප්‍රතිරූපකරණ පද්ධති සඳහා ඇති ආකාරය එයයි.

## SSH ප්‍රවේශය

`authorized_keys` ඇති විට, ස්ථාපනය යතුරු පරිශීලකයාගේ `~/.ssh/authorized_keys` ලෙස සකසයි, `sshd` සක්‍රීය කරයි, සහ ඒ සඳහා ෆයර්වෝලය විවෘත කරයි. (සාමාන්‍ය Omarchy ස්ථාපනයක openssh පැමිණෙන්නේ සේවාව අක්‍රීය කර සහ පෝර්ටය වසා දමාය, එබැවින් අධීක්ෂණයකින් තොර යන්ත්‍රයකට එසේ නොකළහොත් ළඟා විය නොහැකි වනු ඇත.) ස්ථාපනය ඔබේ යතුරු පමණක් එක් කරයි — එය SSH ඩීමනයේ වෙනත් කිසිදු සත්‍යාපන සැකසුමක් ලිහිල් නොකරයි.

`tailscale_authkey` ඇති විට, යන්ත්‍රය ඒ වෙනුවට පළමු ආරම්භයේදී ඔබේ tailnet එකට සම්බන්ධ වේ: Tailscale ස්ථාපනය වන්නේ ISO එකේ ඇසුරුම් කළ පැකේජවලින්ය, ෆයර්වෝලය tailnet අතුරුමුහුණතට ඉඩ දෙයි, සහ යන්ත්‍රයට සැබවින්ම ජාලය ලැබුණු විගසම සම්බන්ධ වීම ක්‍රියාත්මක කරන පසුබිම් කාර්යයක්, එය සාර්ථක වන තෙක් නැවත උත්සාහ කරමින් පවතී. එක් ධාවක ප්‍රතිරූපයකින් බොහෝ යන්ත්‍රවලට සේවය කළ හැකි වන පරිදි නැවත භාවිත කළ හැකි, පූර්ව-අවසර ලත් යතුරක් භාවිත කරන්න.

## cidata ධාවකය තැනීම

නිවැරදි ලේබලය සහිත ඕනෑම ගොනු පද්ධතියක් ක්‍රියා කරයි. කුඩා ISO එකක් පහසුම ක්‍රමයයි:

```bash
mkdir cidata
cp user_configuration.json user_credentials.json authorized_keys cidata/
genisoimage -output cidata.iso -volid cidata -joliet -rock cidata/
```

ඉන්පසු එය Omarchy ISO එකත් සමඟම VM එකට සවි කරන්න. මෙන්න සම්පූර්ණ Proxmox උදාහරණයක්:

```bash
qm create 101 --name my-omarchy \
  --bios ovmf --machine q35 --cpu host --cores 4 --memory 8192 \
  --ostype l26 --scsihw virtio-scsi-single \
  --efidisk0 local-lvm:0,efitype=4m,pre-enrolled-keys=0 \
  --scsi0 local-lvm:40,discard=on,iothread=1 \
  --net0 virtio,bridge=vmbr0 --vga virtio --serial0 socket \
  --ide2 local:iso/omarchy.iso,media=cdrom \
  --ide3 local:iso/cidata.iso,media=cdrom \
  --boot order='scsi0;ide2'

qm start 101
```

ආරම්භ අනුපිළිවෙල තුළ තැටිය මුලින් ලැයිස්තුගත කර ඇත්තේ හිතාමතාමය: හිස් තැටිය පළමු ආරම්භයේදී ISO එක වෙත යොමු වන අතර, ස්ථාපිත පද්ධතිය ඉන්පසු සැමවිටම තැටියෙන් ආරම්භ වේ.

## අවවාද දෙකක්

සංකේතිත අධීක්ෂණයකින් තොර ස්ථාපනයන් සම්පූර්ණයෙන්ම අධීක්ෂණයකින් තොර නොවේ — පළමු ආරම්භයේදී යමෙකු තවමත් LUKS මුරවැකිය ටයිප් කළ යුතුය. තවද එම මුරවැකිය `user_credentials.json` හි ඉහළම මට්ටමේ `encryption_password` ලෙස යෙදේ — archinstall එය කියවන්නේ එතැනින්ය, `user_configuration.json` හි `disk_encryption` කොටසෙන් නොවේ — එබැවින් සංකේතිත ස්ථාපනයකින් තැනූ cidata ධාවකයක් එය වන රහස ලෙසම සලකන්න.
