# ආරක්ෂාව

Omarchy ආරක්ෂාව අතිශය බැරෑරුම් ලෙස සලකයි. මෙය _සැබෑ ලෝකයේ_ _සැබෑ වැඩ_ කිරීමට ඔබට භාවිත කළ හැකි මෙහෙයුම් පද්ධතියක් වීමට අදහස් කෙරේ. ලැප්ටොප් එකක් අහිමි වීම ආරක්ෂක හදිසි අවස්ථාවකට හේතු විය නොහැකි තැනකි. එබැවින් අපි කරන්නේ මෙයයි:

1. *සම්පූර්ණ තැටි සංකේතනය අනිවාර්යයි*: ඔබේ දත්තවල භෞතික ආරක්ෂාව සුරක්ෂිත කිරීම සඳහා ඇති වැදගත්ම පියවර මෙයයි. ඔබේ පරිගණකය අහිමි වුවහොත් හෝ සොරකම් කළහොත්, සම්මත LUKS (Linux Unified Key Setup) භාවිතයෙන් දත්ත සම්පූර්ණයෙන්ම සංකේතනය කර ඇත.
2. *Firewall එක පෙරනිමියෙන් සක්‍රීයයි*: [LocalSend](https://localsend.org/) සඳහා වන 53317 වරාය හැර, ඇතුළු වන සියලුම ගමනාගමනය පෙරනිමියෙන් අවහිර කර ඇත. _Setup > Security > SSHD_ හරහා ඔබ එය සක්‍රීය කරන තුරු ssh පවා අක්‍රීය වන අතර, එය සැකසුමේ කොටසක් ලෙස 22 වරාය (brute force වලට එරෙහිව rate limited කර ඇත) විවෘත කරයි. ඔබේ containers අහම්බෙන් ලෝකයට නිරාවරණය වීම වැළැක්වීමට [ufw-docker](https://github.com/chaifeng/ufw-docker) සැකසුම භාවිතයෙන් අපි Docker ප්‍රවේශය පවා අගුළු දමමු.
3. *Arch සතුව සැමවිටම නවතම යාවත්කාලීන තිබේ*: Omarchy ගොඩනගා ඇති පදනම් distro එක වන Arch යනු rolling distribution එකකි. මෙයින් අර්ථවත් වන්නේ, ඕනෑම package එකක සොයාගෙන පිළියම් යොදන ඕනෑම ආරක්ෂක දුර්වලතාවක් `omarchy-update` භාවිතයෙන් ස්ථාපනය කිරීමට ඉක්මනින් ලබා ගත හැකි බවයි. ඒ ආකාරයෙන් ඔබ සැමවිටම සියල්ලෙහිම නවතම, වඩාත්ම ආරක්ෂිත versions ධාවනය කරයි.
4. *Omarchy තමන්ගේම packages සහ mirror එකක් පවත්වාගෙන යයි*: Omarchy පෙරනිමියෙන් රඳා පවතින්නේ Arch හිම core/extra/multilib repositories වලින් සහ තමන්ගේම Omarchy Package Repository එකෙන් ලැබෙන packages මත පමණි. ඔබට AUR වෙතින් සෘජුවම software ස්ථාපනය කළ හැකි නමුත්, මූලික ස්ථාපනය එසේ නොකරයි — third-party browsers වැනි විකල්ප ස්ථාපන කිහිපයක් පමණක් AUR වෙතින් ලබා ගනී.
5. *Cloudflare අපව DDoS වලින් ආරක්ෂා කරයි*: Omarchy බෙදාහැරීමේ යටිතල පහසුකම් — ISOs, Omarchy packages, Arch mirror එක — Cloudflare හි ප්‍රබල DDoS පලිහ පිටුපස ආරක්ෂා කර ඔවුන්ගේ CDN එකේ host කර ඇත. මෙය විශිෂ්ට ලබාගත හැකිබවක් සපයයි.

## ඔබේ passwords වෙනස් කිරීම

සංකේතනය කළ ස්ථාපනයක ඔබ සතුව passwords දෙකක් තිබේ: එකක් boot කිරීමේදී drive එක අගුළු හරිනු ලබන අතර, අනෙක ඔබ login වීමට සහ `sudo` සමඟ භාවිතා කරන එකයි. Setup එකෙන් ඒවා දෙකම එකම බවට පත් කරයි. Omarchy menu එකේ _Update > Password_ යටතේ දෙකම වෙනස් කළ හැකිය — පළමුවැන්න සඳහා _Drive Encryption_, දෙවැන්න සඳහා _User_. Drive password එක වෙනස් කිරීමේදී පළමුව වත්මන් එක අසන බැවින්, එය අත ළඟ තබා ගන්න. වෙනසකට බාධා ඇති වුවහොත්, _Drive Encryption_ නැවත ධාවනය කරන්න: එය දැන් drive එක අගුළු හරින password එක අසා වෙනස අවසන් කරයි.

## ඔබ දැනටමත් භාවිත කළ යන්ත්‍රයක් වෙනත් අයෙකුට භාර දීම

ඔබ ඔබේ යන්ත්‍රය වෙනත් අයෙකුට භාර දෙන්නේ නම්, ඔබට එය නැවත ස්ථාපනය කිරීමට සිදු නොවේ. Omarchy menu එකේ _Setup > Reset Computer_ ධාවනය කර, තහවුරු කිරීමට `reset` යොදා, reboot කරන්න. එය සෑම user account එකක්ම සහ `/home` තුළ ඇති සියල්ලම අතුගා දමයි, ස්ථාපනයෙන් පසු ඔබ කළ සියලුම packages සහ system වෙනස්කම් ඉවත් කරයි, සහ යන්ත්‍රයේ අනන්‍යතාවය — network connections, host keys, සහ සියල්ල — ඉවත් කරයි. නැවත ආරම්භ වන විට පළමු boot එකේ setup wizard එක ඇති අතර, එහි නව හිමිකරුට තමන්ගේම නම, password එක, සහ encryption password එක ඇතුළත් කිරීමට සූදානම්ව පවතී.

එය ක්‍රියා කරන්නේ installer එක ගන්නා baseline snapshot එක ප්‍රතිස්ථාපනය කිරීමෙනි, එබැවින් එය ලබා ගත හැක්කේ Omarchy ISO එකෙන් ස්ථාපනය කළ යන්ත්‍රවල පමණි. තවද සංකේතනය නොමැති drive එකක, reset කිරීමක් යනු secure erase එකක් නොව මකා දැමීමක් වන බැවින්, දත්ත සංවේදී නම්, ඒ වෙනුවට fresh install එකක් කරන්න.

## Password රහිත sudo

සමහර විට ඔබට `sudo` විමසීම නැවැත්වීමට අවශ්‍ය විය හැකිය, බොහෝ විටම AI agent කෙනෙකු ඔබට දිගු කාලයක් system වැඩ කරමින් සිටින විට. _Setup > Security > Passwordless Sudo_ ප්‍රවේශය කොපමණ කාලයක් ඉඩ දිය යුතුදැයි අසයි: **විනාඩි 15**, **පැය 1**, **දින 1**, හෝ **ස්ථිරවම**. ප්‍රවේශය සක්‍රීයව පවතින අතරතුර අනෙකුත් menu bar indicators අසල රතු අනතුරු ඇඟවීමේ icon එකක් දිස් වේ. එය click කරන්න හෝ අක්‍රීය කිරීමට විධානය නැවත ධාවනය කරන්න. ඔබට `omarchy-sudo-passwordless 30` සමඟ ඔබේම විනාඩි ගණනක් (1 සිට 1440 දක්වා) ද ලබා දිය හැකිය, නැතහොත් `omarchy-sudo-passwordless permanent` භාවිතා කළ හැකිය.

Timed ප්‍රවේශය ස්වයංක්‍රීයව කල් ඉකුත් වන අතර, deadline එක ඉක්මවා ගිය suspend එකකින් නැවත ආරම්භ කළ වහාම ද එය එසේම වේ. පරිගණකය restart කිරීම එය කලින් අවසන් කරයි. Permanent ප්‍රවේශය reboots වලින් පසුවත් පවතින අතර, ඔබ එය අක්‍රීය කරන තුරු සක්‍රීයව පවතී.

Omarchy හි settings package එක යාවත්කාලීන කිරීම හෝ ඉවත් කිරීම, එහි expiry support එක වෙනස් වීමට පෙර ඕනෑම තාවකාලික දීමනාවක් අවසන් කරයි. විධානය authorization හෝ cleanup දෝෂයක් වාර්තා කරන්නේ නම්, තවත් දීමනාවක් සක්‍රීය කිරීමට උත්සාහ කිරීමට පෙර එය විසඳන්න; දෝෂයක් යනු password රහිත ප්‍රවේශය අක්‍රීය බව නොවේ.

මෙය ගැන පැහැදිලි ඇසකින් බලන්න: එය සක්‍රීයව පවතින විට, ඔබේ user ලෙස ධාවනය වන ඕනෑම දෙයකට විමසීමකින් තොරව root ලෙස ඕනෑම දෙයක් කළ හැකිය. එයම තමයි මුළු අරමුණ, සහ එයම තමයි මුළු අවදානම ද.
