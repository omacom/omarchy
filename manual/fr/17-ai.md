# IA

Omarchy inclut des lanceurs pour les agents de codage ci-dessous sans en choisir un par défaut à votre place. Exécutez une commande pour installer son CLI lors de la première utilisation, puis authentifiez-vous lorsque vous y êtes invité. Hermes fait exception : rien n'est installé pour lui lors de la première utilisation, et le choisir installe Hermes Desktop, comme l'explique _Applications de bureau_ ci-dessous.

### Installation et mise à jour des agents

À l'exception de Hermes, ces agents utilisent l'installation paresseuse de mise : le premier lancement installe le CLI, et les lancements suivants le réutilisent. mise vérifie aussi si un agent installé a une nouvelle version au plus une fois toutes les quatre heures, juste avant son démarrage ou en arrière-plan à une invite du shell. Si cette mise à jour échoue ou si vous êtes hors ligne, la version installée s'exécute. `omarchy update` met à jour les agents installés avec le reste d'Omarchy, et `mup` met à jour uniquement les outils gérés par mise.

Le programme de mise à jour propre à un agent, comme `claude update`, `codex update` ou un bouton de mise à jour dans une application, ne met pas à jour l'installation gérée par mise. `codex update` échoue, et `claude update` peut annoncer un succès tout en installant une copie séparée que mise ne suit pas. Si vous préférez utiliser l'installateur et le programme de mise à jour natifs d'un agent, ajoutez-le à `disable_tools` ; voir [Outils CLI préinstallés](18-development-tools.md#preinstalled-cli-tools).

Pour installer tous les outils paresseux configurés avant d'en avoir besoin, exécutez `mise install --include-lazy`. Cela inclut les autres outils CLI par défaut d'Omarchy ainsi que les agents. Voir [Outils CLI préinstallés](18-development-tools.md#preinstalled-cli-tools) pour installer un seul outil ou utiliser votre propre installation.

`grok` est installé via le paquet officiel `grok` de mise, de la même manière que `claude` et `codex`. Exécutez `grok`, ou choisissez-le sous _Configuration > Par défaut > Agent_. Évitez l'installateur `curl | bash` sur x.ai. Ce chemin place une seconde copie dans `~/.grok/bin`, l'ajoute au début de `PATH`, et écrase le wrapper d'Omarchy.

`dsh` ouvre son interface utilisateur navigateur sur `127.0.0.1:3080`, avec le répertoire de lancement comme espace de travail par défaut. Son interface navigateur n'accepte aucun prompt de départ, donc `omarchy agent prompt` l'ouvre avec le prompt dans votre presse-papiers, à coller. Omarchy le démarre avec le préréglage d'autorisation sans approbation de DeepSeek. DeepSeek Harness envoie les journaux de session à DeepSeek lorsque vous utilisez son API de modèle officielle ; désactivez cela sous _Settings > General > Upload Session Log_ dans son interface navigateur. Les commentaires que vous lui envoyez sont également envoyés avec la session, sauf si vous le démarrez avec `DSH_TELEMETRY_MODE=DISABLED`.

### L'agent par défaut

Choisissez votre agent par défaut avec `omarchy default agent <name>` ou sous _Configuration > Par défaut > Agent_ dans le menu Omarchy (`Super + Space`). Si l'agent n'est pas encore installé, le choisir l'installe d'abord. Un Omarchy fraîchement installé vous invitera à faire ce choix avec une notification unique.

Choisir Claude tente également de configurer son extension de navigateur pour Chromium, Chrome, Brave, Brave Origin et Edge. La configuration de l'extension s'applique à tous les utilisateurs et peut demander votre mot de passe système ; annuler ou échouer l'installation de l'extension sélectionne et lance quand même Claude. Redémarrez votre navigateur, activez l'extension si vous y êtes invité, et connectez-vous à Claude pour terminer la connexion. Exécutez `/chrome` dans Claude pour vérifier la connexion. Firefox et Zen ne prennent pas en charge cette extension. Si Claude était déjà votre agent par défaut avant l'ajout de cette configuration, sélectionnez-le à nouveau pour installer l'extension.

Une fois votre choix fait, `Super + Shift + Ctrl + A` lance l'agent par défaut dans une fenêtre de terminal dédiée (ou affiche le sélecteur si vous n'avez pas encore choisi). Vous pouvez aussi le lancer directement sur une tâche avec `omarchy agent prompt "Review this project"`. Freebuff et DeepSeek Harness n'acceptent aucun prompt de départ, donc ils s'ouvrent avec le prompt dans votre presse-papiers, à coller à la place. Les agents lancés ainsi fonctionnent sans surveillance dans leurs modes respectifs où ils ne s'arrêtent pas pour demander, alors soyez prêt à ce qu'ils fassent vraiment des choses ! MiniMax Code n'a pas de tel mode pour ses sessions interactives, donc il demande les autorisations comme d'habitude. Et comme les agents refusent de mémoriser la confiance pour votre répertoire personnel, les lancements depuis `$HOME` démarrent à la place dans `~/Work`.

Il existe aussi des raccourcis de terminal : `a` exécute l'agent par défaut en ligne dans le terminal actuel, tandis que `c`, `cx` et `cy` démarrent directement OpenCode, Claude Code et Codex (toujours dans leurs modes d'approbation automatique). Les changements de thème se synchronisent aussi avec les agents : Claude Code, Pi, OpenCode et Hermes (une fois qu'Omarchy l'a installé) suivent tous lorsque vous changez le thème Omarchy.

### Le panneau des agents

La barre supérieure a une icône d'agents. Avant que vous ayez configuré un agent, son panneau vous guide pour vous connecter à Claude, Codex ou Grok, et le premier devient votre agent par défaut. Ensuite, le panneau rassemble chaque abonnement sur une page : chaque agent et chaque compte avec son forfait, un indicateur pour chacune de ses limites de session de 5 heures et hebdomadaire avec le temps restant avant sa réinitialisation (survolez pour le pourcentage exact), ou le solde prépayé restant, sous une ligne qui fait défiler ce que vous avez utilisé sur l'ensemble, comme les tokens cette semaine et votre modèle le plus utilisé. Sous _Make something_, il propose des prompts de départ pour un nouveau thème, plugin ou application qui confient la tâche à votre agent par défaut. Les applications sont construites de la même manière que Hype, Monologue et Omacut d'Omarchy, en C++ et Qt Quick, en suivant le skill d'agent omarchy-app, et le compilateur ainsi que les éléments Qt dont elles ont besoin sont installés. Claude Code, Codex, Grok, Kimi, Cursor et son allocation Grok Bot, GitHub Copilot, Muse, Antigravity, Kimchi et Devin sont couverts prêts à l'emploi avec leurs limites, et Hermes, Mistral Vibe et Qwen Code affichent leurs sessions et tokens une fois que vous les avez utilisés. Les forfaits et clés de fournisseurs que vous utilisez via pi, omp ou opencode apparaissent aussi : OpenCode Zen et Go, le Z.ai GLM Coding Plan, Ollama Cloud, le MiniMax Token Plan et Synthetic avec leurs limites ; Fireworks, OpenRouter et DeepSeek avec leurs soldes prépayés ; et les modèles que vous exécutez sur votre propre matériel sous Local models. Chaque agent est compté une fois, chez celui qui le facture, peu importe le nombre de harnesses à travers lesquels vous l'utilisez.

Cliquez avec le bouton gauche sur l'icône de la barre pour le panneau, avec le bouton droit pour lancer votre agent par défaut. Les enregistrements d'utilisation qui l'alimentent sont régénérés toutes les 15 minutes par `omarchy agent usage-update`, et le panneau peut même fusionner l'utilisation de vos autres machines via un dossier synchronisé. Voir le README sous `$OMARCHY_PATH/shell/plugins/agents/` pour tous les paramètres.

### Plusieurs abonnements

Si vous payez plus d'un forfait Claude, Codex ou Grok — un Max personnel et un professionnel, par exemple — Omarchy peut les garder tous connectés et passer de l'un à l'autre. Ajoutez un abonnement avec le + dans le panneau des agents, qui vous guide sur place, ou avec `omarchy agent account add claude Work` (ou `codex`, ou `grok`). Il installe le CLI s'il est absent. Le premier compte pour un fournisseur se connecte via votre navigateur normal, exactement là où le CLI cherche toujours. Tous les suivants se connectent via une fenêtre privée, afin que le compte auquel votre navigateur est déjà connecté ne soit pas récupéré par erreur ; connectez-vous-y avec le compte que vous ajoutez, et fermez d'abord toute fenêtre privée déjà ouverte. Ne vous déconnectez jamais du CLI pour faire cela : se déconnecter révoque la connexion enregistrée, et ce compte devrait être ajouté à nouveau.

Pour copier vos connexions d'abonnement vers une autre machine Omarchy via SSH, exécutez `omarchy agent account copy user@laptop`. L'expéditeur fournit un récepteur temporaire lorsque la destination n'en a pas d'installé, afin que les machines Omarchy plus anciennes puissent recevoir des comptes sans mise à jour. Les récepteurs installés ont la priorité. Cela copie tous les abonnements Claude, Codex et Grok ; ajoutez des noms de fournisseurs pour les sélectionner, comme dans `omarchy agent account copy laptop claude`. Les noms de compte et les ID de commande correspondent à la source, y compris les comptes déjà présents sur la destination. Les comptes de destination sans rapport reçoivent un suffixe numérique si leurs noms entrent en conflit, et les paramètres, skills, plugins et l'historique de conversation restent locaux à chaque machine.

Les identifiants de destination existants sont conservés. Un compte source déjà connecté là-bas voit son nom synchronisé sans remplacer ses identifiants ; les autres comptes sont ajoutés à côté de lui. Pour remplacer les identifiants enregistrés pour les comptes correspondants, utilisez `omarchy agent account copy --replace laptop claude` après avoir quitté les sessions de ce compte sur la destination. Une destination neuve reçoit aussi le compte actif et les préférences de basculement de la source ; une destination établie conserve les siens.

Les identifiants transitent via SSH et sont stockés dans des fichiers privés sur la destination, donc ne copiez que vers des machines de confiance. Il s'agit d'une copie ponctuelle, pas d'une synchronisation continue. Les tokens d'actualisation Codex peuvent être renouvelés par une autre machine, laissant une connexion copiée ayant besoin d'un renouvellement ; des connexions séparées restent le choix le plus fiable pour une utilisation simultanée sur plusieurs machines. Voir [le guide d'authentification de compte de Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Un compte par fournisseur est actif, et chaque nouvelle session démarre avec lui : `cx`, `cy`, un simple `claude`, `codex` ou `grok`, tout ce qui est lancé via `omarchy agent`, et les scripts ou éditeurs qui trouvent le CLI sur `PATH`. Basculez avec `omarchy agent account use work` (et revenez avec `omarchy agent account use main`), ou dans le panneau en appuyant sur le numéro d'un compte puis sur `Enter` (ou en cliquant sur son bouton Use). Les sessions déjà en cours restent sur le compte avec lequel elles ont démarré. L'historique de conversation, les paramètres, les skills et les plugins sont partagés entre les comptes, donc `claude --continue` dans le même dossier reprend là où vous vous étiez arrêté sur le nouveau compte.

Avec plus d'un compte, le panneau affiche les limites de chaque compte côte à côte, avec le compte actif marqué. Par défaut, Omarchy vous avertit lorsque le compte actif dépasse 95 % d'une limite, et cliquer sur la notification bascule vers le compte disposant de la plus grande marge. Survolez la ligne d'un compte dans le panneau et cliquez sur Autoswitch qui apparaît à côté de Use (ou appuyez sur `m`), ou exécutez `omarchy agent account mode auto`, pour qu'il bascule automatiquement à la place ; pendant qu'il est activé, Autoswitch prend la place de Use, et cliquer à nouveau dessus revient à la notification. Ajoutez un nombre pour changer le seuil, comme dans `omarchy agent account mode auto 90`. Si chaque compte dépasse le seuil, vous en serez informé une fois, avec le compte qui se libérera en premier. Lorsqu'un compte actif est à moins de 15 points de son seuil (80 % par défaut), ses limites sont vérifiées toutes les trois minutes plutôt que toutes les 15.

`omarchy agent account list` affiche chaque compte et ses dernières limites, `omarchy agent account remove work` en oublie un, et `omarchy agent account rename primary Hey` en renomme un (ou cliquez sur le nom d'un compte dans le panneau). Ces commandes fonctionnent sur les comptes de votre agent par défaut ; pour atteindre l'autre fournisseur, nommez-le d'abord, comme dans `omarchy agent account use codex side`. La connexion que vous aviez déjà dans `~/.claude` ou `~/.codex` est le compte _Main_ et reste là où elle est. Un compte laissé inutilisé pendant plus d'environ huit heures peut afficher _Sign-in required_ ; cliquez dessus pour reconnecter ce compte directement dans le panneau, ou démarrez une session avec lui, ce qui actualise la connexion tout seul. Les serveurs MCP que vous aviez lorsqu'un compte a été ajouté l'accompagnent, mais ceux que vous ajoutez plus tard avec `claude mcp add` n'atteignent que le compte dans lequel vous les avez ajoutés. Claude Desktop et les outils configurés avec un chemin absolu vers un binaire CLI ne suivent pas le basculement. Un `CLAUDE_CONFIG_DIR`, `CODEX_HOME` ou `GROK_HOME` explicite a la priorité sur le compte sélectionné.

### Diagnostic de plantage

Omarchy surveille systemd-coredump pour les plantages de processus. Lorsque quelque chose provoque une erreur de segmentation, vous recevrez une notification « Process crashed » — cliquez dessus, et le plantage est transmis à votre agent par défaut avec le skill diagnose-crash d'Omarchy, qui guide l'agent pour établir les faits à partir du core dump et décider si le plantage vaut la peine d'être signalé en amont. Vous pouvez aussi l'exécuter manuellement sur n'importe quel PID de `coredumpctl list` avec `omarchy agent crash <pid>`.

La surveillance est activée par défaut. Désactivez-la sous _Trigger > Toggle > Crash Capture_ (ou avec `omarchy toggle crash-capture`) et les notifications s'arrêtent ; `omarchy agent crash <pid>` fonctionne toujours manuellement.

Les plantages peuvent aussi être réduits au silence programme par programme, ce que le diagnostic vous propose à la fin. `omarchy crash mute hyprland` arrête les notifications pour ce programme uniquement, `omarchy crash mute hyprland off` les rétablit, et `omarchy crash mute` seul liste ce que vous avez mis en sourdine. Il accepte le chemin du binaire aussi volontiers que son nom, donc `omarchy crash mute /usr/bin/hyprland` fait la même chose. Mettez entre guillemets un nom contenant un espace, comme dans `omarchy crash mute 'Some App'`. Tout le reste continue à notifier, et le programme mis en sourdine continue à planter — cela masque le rappel, cela ne répare rien.

### Applications de bureau

Le menu _Installer > IA_ propose aussi quelques applications d'IA graphiques : l'application de bureau ChatGPT, l'application de bureau Claude (la bêta Linux d'Anthropic, avec les onglets Chat, Cowork et Claude Code), Grok Bot pour discuter avec les modèles de xAI, Hermes Desktop, OpenClaw, l'application de bureau Perplexity et T3 Code. Grok Bot est l'application de chat de bureau. L'agent de codage est la commande `grok`.

Hermes Desktop est celle à connaître, parce qu'une machine a un seul Hermes, et c'est celui de l'application : Hermes n'est jamais installé que via l'application, et la commande `hermes` qu'exécute l'agent par défaut est celle de l'application. Choisir Hermes comme agent par défaut installe la même chose que l'entrée _Installer > IA_ : le paquet, et un runtime Hermes sous `~/.hermes` configuré par l'installateur propre à Hermes, ce qui prend quelques minutes la première fois. Ce runtime est l'unique Hermes que la commande `hermes` du terminal, l'agent par défaut et l'application utilisent tous, et il se met à jour lui-même avec `hermes update` plutôt que d'attendre une version d'Omarchy. L'installer confie aussi à Hermes le thème Omarchy comme skin nommé `omarchy`, que chaque surface Hermes suit lorsque vous changez de thème ; choisissez-en un autre dans les paramètres Appearance de Hermes ou avec `/skin` si vous préférez qu'il ne le fasse pas, et Omarchy laisse ce choix tranquille. Retirer l'application sous _Retirer > IA_ ferme d'abord Hermes, gateway incluse, emporte ce runtime avec elle, et conserve vos discussions, mémoires et les skills que Hermes a écrits pour lui-même, sauf si vous lui dites le contraire : elle demande, avec non par défaut, si ces données et vos paramètres de connexion doivent aussi partir.

L'expérience de bureau d'OpenClaw est son Control UI, qui s'ouvre comme une application web adossée à sa propre gateway locale. OpenClaw vit dans `~/.openclaw` et se met à jour lui-même : utilisez le bouton « Update Gateway » de la Control UI ou exécutez `openclaw update`, et la gateway redémarre sur la nouvelle version. Omarchy choisit uniquement la version à partir de laquelle une nouvelle installation démarre. Retirer OpenClaw sous _Retirer > IA_ emporte le service gateway et l'application avec lui, puis demande si `~/.openclaw` doit aussi partir, car il contient vos discussions et identifiants aux côtés d'OpenClaw lui-même et des runtimes de plugins qu'il télécharge ; le choix par défaut le conserve, et réinstaller OpenClaw le retrouve.

T3 Code s'exécute depuis sa version AppImage officielle dans `~/.local/share/t3code` plutôt que depuis un paquet, donc il se met à jour lui-même. L'installer demande s'il faut démarrer sur le canal Stable ou Nightly ; changez plus tard dans les paramètres de T3 Code. Vos fils et paramètres vivent dans `~/.t3`, et retirer T3 Code sous _Retirer > IA_ les emporte avec lui.

### LLM locaux

Omarchy recommande deux façons d'exécuter des modèles LLM locaux : LM Studio et Ollama. LM Studio fournit une interface graphique pour trouver des modèles open-weight, les installer et les exécuter. C'est un excellent moyen de démarrer facilement. Ollama propose un CLI pour faire de même. Mais si vous débutez avec les modèles locaux, je commencerais par LM Studio. Vous pouvez installer l'un ou l'autre sous _Installer > IA_ dans le menu Omarchy.

### Le Skill Omarchy

Les skills d'agent aident l'IA à utiliser des outils spécifiques d'une manière spécifique, et Omarchy est livré avec un skill par défaut pour adapter le système. Comme modifier votre configuration Hyprland, ajuster la barre, ou même créer un nouveau thème de zéro. Il est lié symboliquement dans les répertoires de skills de Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` et chaque `~/.hermes/profiles/*/skills`), et l'emplacement générique `~/.agents/skills`, donc la plupart des harnesses le récupèrent automatiquement.

Mais vous devriez traiter ce skill comme expérimental. Différents modèles l'utiliseront avec des effets différents. Il vaut mieux d'abord l'exécuter en mode plan, afin d'avoir une idée de ce que l'agent voudrait changer. Et ensuite, soyez prêt à annuler les changements ou même à invoquer `omarchy reinstall configs`, si l'agent met le bazar partout.
