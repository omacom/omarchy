Omarchy inclut des lanceurs pour les agents de codage ci-dessous sans en choisir un par défaut pour vous. Exécutez une commande pour installer son CLI lors de la première utilisation, puis authentifiez-vous lorsque vous y êtes invité. Hermes et OpenClaw sont les exceptions : rien n'est installé pour eux via mise, et choisir l'un ou l'autre installe sa propre copie à mise à jour automatique, comme l'explique la section _Applications de bureau_ ci-dessous.

### Installation et mise à jour des agents

À l'exception de Hermes et d'OpenClaw, ces agents utilisent l'installation paresseuse de mise : le premier lancement installe le CLI, et les lancements suivants le réutilisent. mise vérifie aussi si une nouvelle version d'un agent installé est disponible au maximum une fois toutes les quatre heures, juste avant son démarrage ou en arrière-plan à l'invite du shell. Si cette mise à jour échoue ou si vous êtes hors ligne, la version installée s'exécute. `omarchy update` met à jour les agents installés avec le reste d'Omarchy, et `mup` met à jour uniquement les outils gérés par mise.

Le programme de mise à jour propre à un agent, comme `claude update`, `codex update` ou un bouton de mise à jour dans une application, ne met pas à jour l'installation gérée par mise. `codex update` échoue, et `claude update` peut annoncer un succès tout en installant une copie distincte que mise ne suit pas. Si vous préférez utiliser l'installateur et le programme de mise à jour natifs d'un agent, ajoutez-le à `disable_tools` ; voir [Outils CLI préinstallés](18-development-tools.md#preinstalled-cli-tools).

Pour installer tous les outils paresseux configurés avant d'en avoir besoin, exécutez `mise install --include-lazy`. Cela inclut les autres outils CLI par défaut d'Omarchy ainsi que les agents. Voir [Outils CLI préinstallés](18-development-tools.md#preinstalled-cli-tools) pour installer un seul outil ou utiliser votre propre installation.

`grok` est installé via le paquet officiel `grok` de mise, de la même manière que `claude` et `codex`. Exécutez `grok`, ou marquez-le d'une étoile dans le panneau des agents. Évitez l'installateur `curl | bash` de x.ai. Ce chemin installe une deuxième copie dans `~/.grok/bin`, la place en tête de `PATH` et écrase le wrapper d'Omarchy.

`dsh` ouvre son interface navigateur sur `127.0.0.1:3080`, avec le répertoire de lancement comme espace de travail par défaut. Son interface navigateur n'accepte aucune invite de départ, donc `omarchy agent prompt` l'ouvre avec l'invite dans votre presse-papiers, à coller. Omarchy le démarre avec le préréglage d'autorisations sans approbation de DeepSeek. DeepSeek Harness envoie les journaux de session à DeepSeek lorsque vous utilisez son API de modèle officielle ; désactivez cela dans _Paramètres > Général > Téléverser le journal de session_ dans son interface navigateur. Les retours que vous lui envoyez sont également téléversés avec la session, sauf si vous le démarrez avec `DSH_TELEMETRY_MODE=DISABLED`.

### L'agent par défaut

Choisissez votre agent par défaut avec l'étoile à côté d'un agent dans le panneau des agents, qui est pleine sur celui par défaut, ou avec `omarchy default agent <name>`, qui accepte aussi tout harness sans ligne dédiée. Si l'agent n'est pas encore installé, le choisir l'installe d'abord, et il reçoit aussi son propre lanceur dans le lanceur d'applications, à côté d'Agent. Un Omarchy fraîchement installé vous invite à en configurer un via une notification unique, qui ouvre le panneau des agents.

Choisir Claude tente aussi de configurer son extension de navigateur pour Chromium, Chrome, Brave, Brave Origin et Edge. La configuration de l'extension s'applique à tous les utilisateurs et peut demander votre mot de passe système ; annuler l'installation de l'extension ou son échec sélectionne et lance quand même Claude. Redémarrez votre navigateur, activez l'extension si vous y êtes invité, et connectez-vous à Claude pour terminer la connexion. Exécutez `/chrome` dans Claude pour vérifier la connexion. Firefox et Zen ne prennent pas en charge cette extension. Si Claude était déjà votre agent par défaut avant l'ajout de cette configuration, sélectionnez-le à nouveau pour installer l'extension.

Une fois votre choix fait, `Super + Shift + Ctrl + A` lance l'agent par défaut dans une fenêtre de terminal dédiée (ou affiche le sélecteur si vous n'en avez pas encore choisi). Vous pouvez aussi le lancer directement sur une tâche avec `omarchy agent prompt "Review this project"`. Freebuff et DeepSeek Harness n'acceptent aucune invite de départ, donc ils s'ouvrent avec l'invite dans votre presse-papiers, à coller à la place. Les agents lancés ainsi fonctionnent sans surveillance dans leurs modes respectifs où ils ne s'arrêtent pas pour demander, alors soyez prêt à ce qu'ils fassent vraiment des choses ! MiniMax Code n'a pas de tel mode pour ses sessions interactives, donc il demande les autorisations comme d'habitude. Et comme les agents refusent de mémoriser la confiance pour votre répertoire personnel, les lancements depuis `$HOME` démarrent dans `~/Work` à la place.

Il existe aussi des raccourcis de terminal : `a` exécute l'agent par défaut directement dans le terminal actuel, tandis que `c`, `cx`, `cy` et `ca` lancent directement OpenCode, Claude Code, Codex et Antigravity (là aussi dans leurs modes d'approbation automatique). Les changements de thème se synchronisent aussi avec les agents : Claude Code, Pi, OpenCode et Hermes (une fois qu'Omarchy l'a installé) suivent tous lorsque vous changez le thème Omarchy.

### Vos instructions pour les agents

Les règles personnelles pour chaque agent vont dans `~/.agents/AGENTS.md`, à côté des skills partagés dans `~/.agents/skills`. Ouvrez-le avec l'icône de document à côté du + dans le panneau des agents, ou avec `omarchy agent instructions --edit`, qui le lie aussi dans chaque harness qui conserve son propre fichier global : `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, le `~/.copilot/copilot-instructions.md` de Copilot, et ainsi de suite. Crush et Amp lisent le lien `~/.config/AGENTS.md`, tandis que omp, Kimi et DeepSeek Harness lisent directement `~/.agents/AGENTS.md`. Choisir un agent par défaut le lie aussi. Un fichier d'instructions que vous aviez déjà devient le fichier partagé s'il n'y en avait pas encore ; sinon, il est conservé à côté du lien sous le nom `.bak`. Exécutez `omarchy agent instructions` pour refaire les liens après avoir installé un autre agent.

### Le panneau des agents

La barre supérieure comporte une icône d'agents. Avant que vous ayez configuré un agent, son panneau propose trois façons de commencer : vous connecter à un abonnement Claude, Codex, Grok, Gemini, Muse, Cursor ou Copilot, ou sous Plus à un plan de codage OpenCode Go, MiniMax, Synthetic ou Z.ai ; payer à l'usage avec Fireworks, OpenCode Zen et Go, OpenRouter, ou sous Plus DeepSeek ou tout autre fournisseur auquel OpenCode se connecte, le tout exécuté dans OpenCode ; ou exécuter le meilleur modèle pour votre ordinateur, quand l'un d'eux lui convient. Le premier que vous terminez devient votre agent par défaut, et le + dans le panneau propose les trois mêmes options par la suite. Après cela, le panneau regroupe chaque abonnement sur une seule page : chaque agent et chaque compte avec son plan, un indicateur pour chacune de ses limites de session de 5 heures et hebdomadaire avec le temps restant avant sa réinitialisation (survolez pour le pourcentage exact), ou le solde prépayé restant, sous une ligne qui fait défiler ce que vous avez utilisé sur l'ensemble, comme les tokens cette semaine et votre modèle le plus utilisé. Sous _Créez quelque chose de sympa_, il propose des invites de démarrage pour un nouveau thème, plugin, application ou jeu qui confient la tâche à votre agent par défaut. Les applications sont construites de la même manière que Hype, Monologue et Omacut d'Omarchy, en C++ et Qt Quick, en suivant le skill d'agent omarchy-make-app, et le compilateur ainsi que les éléments Qt dont elles ont besoin sont installés. Les jeux sont une seule page three.js dans `~/Games/vibes`, en suivant le skill d'agent omarchy-make-game, et tous s'ouvrent depuis un seul lanceur Game Vibes dans le thème actuel ; ils chargent three.js depuis le web, donc ils ont besoin d'une connexion pour démarrer. Claude Code, Codex, Grok, Kimi, Cursor et son quota Grok Bot, GitHub Copilot, Muse, Gemini (via Antigravity) et Devin sont couverts d'emblée avec leurs limites, Kimchi avec son plan, ses crédits prépayés et ses budgets de dépenses, et Hermes, Mistral Vibe et Qwen Code affichent leurs sessions et leurs tokens une fois que vous les avez utilisés. Les plans et clés de fournisseurs que vous utilisez via pi, omp ou opencode apparaissent aussi : OpenCode Zen et Go, le Z.ai GLM Coding Plan, Ollama Cloud, le MiniMax Token Plan et Synthetic avec leurs limites ; OpenRouter et DeepSeek avec leurs soldes prépayés ; Fireworks avec ses dépenses des 30 derniers jours. Les modèles de codage que vous exécutez sur votre propre matériel ont leurs propres lignes, et leurs tokens comptent aussi dans les totaux, comme décrit sous [Modèles locaux](#local-models). Chaque agent est compté une seule fois, sous celui qui le facture, quel que soit le nombre de harness par lesquels vous le pilotez.

Cliquez avec le bouton gauche sur l'icône de la barre ou appuyez sur `Super + Ctrl + X` pour le panneau, cliquez avec le bouton droit pour lancer votre agent par défaut, et cliquez avec le bouton du milieu pour actualiser. Les relevés d'utilisation qui l'alimentent sont régénérés toutes les 15 minutes par `omarchy agent usage update`, et le panneau peut même fusionner l'utilisation de vos autres machines via un dossier synchronisé. Voir le README sous `$OMARCHY_PATH/shell/plugins/agents/` pour tous les réglages.

### Plusieurs abonnements

Si vous payez pour plus d'un plan Claude, Codex ou Grok — un Max personnel et un professionnel, par exemple — Omarchy peut tous les garder connectés et passer de l'un à l'autre. Ajoutez un abonnement avec le + dans le panneau des agents, qui vous guide sur place, ou avec `omarchy agent account add claude Work` (ou `codex`, ou `grok`). Le même + et la même commande permettent de se connecter à Gemini (`gemini`) et OpenCode (`opencode`), et d'enregistrer une clé API Fireworks (`fireworks`) ou OpenRouter (`openrouter`) dans OpenCode ; la commande permet aussi de se connecter à Copilot (`copilot`), Cursor (`cursor`) et Muse (`muse`). Ceux-ci conservent une seule connexion chacun. Elle installe le CLI s'il est manquant. Le premier compte pour un fournisseur se connecte via votre navigateur habituel, là où le CLI le cherche toujours. Chaque compte suivant se connecte via une fenêtre privée, afin que le compte auquel votre navigateur est déjà connecté ne soit pas récupéré par erreur ; connectez-vous là en tant que compte que vous ajoutez, et fermez d'abord toute fenêtre privée déjà ouverte. Ne vous déconnectez jamais du CLI pour faire cela : se déconnecter révoque la connexion enregistrée, et ce compte devrait être ajouté à nouveau.

Pour copier vos connexions d'abonnement vers une autre machine Omarchy via SSH, exécutez `omarchy agent account copy user@laptop`. L'expéditeur fournit un récepteur temporaire lorsque la destination n'en a pas d'installé, donc les machines Omarchy plus anciennes peuvent recevoir des comptes sans mise à jour. Les récepteurs installés ont la priorité. Cela copie tous les abonnements Claude, Codex et Grok ; ajoutez des noms de fournisseurs pour les sélectionner, comme dans `omarchy agent account copy laptop claude`. Les noms de comptes et les ID de commandes correspondent à la source, y compris les comptes déjà présents sur la destination. Les comptes de destination sans rapport reçoivent un suffixe numérique si leurs noms entrent en conflit, et les réglages, skills, plugins et l'historique des conversations restent locaux à chaque machine.

Les identifiants de destination existants sont conservés. Un compte source déjà connecté là-bas voit son nom synchronisé sans remplacer ses identifiants ; les autres comptes sont ajoutés à côté. Pour remplacer les identifiants enregistrés des comptes correspondants, utilisez `omarchy agent account copy --replace laptop claude` après avoir quitté les sessions de ce compte sur la destination. Une destination fraîche reçoit aussi le compte actif et les préférences de bascule de la source ; une destination déjà établie conserve les siens.

Les identifiants transitent via SSH et sont stockés dans des fichiers privés sur la destination, donc ne copiez que vers des machines de confiance. Il s'agit d'une copie ponctuelle, pas d'une synchronisation continue. Les tokens d'actualisation de Codex peuvent être renouvelés par une autre machine, laissant une connexion copiée en besoin de renouvellement ; des connexions distinctes restent le choix le plus fiable pour une utilisation simultanée sur plusieurs machines. Voir le [guide d'authentification des comptes de Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Un compte par fournisseur est actif, et chaque nouvelle session commence avec lui : `cx`, `cy`, un simple `claude`, `codex` ou `grok`, tout ce qui est lancé via `omarchy agent`, et les scripts ou éditeurs qui trouvent le CLI sur `PATH`. Basculez avec `omarchy agent account use work` (et revenez avec `omarchy agent account use main`), ou dans le panneau en appuyant sur le numéro d'un compte puis sur `Enter` (ou en cliquant sur son étoile). Les sessions Claude en cours basculent aussi, dès leur prochain message : chaque session Claude s'exécute dans `~/.claude`, qui contient toujours la connexion du compte actif. Une session Claude démarrée dans le dossier propre d'un compte par un Omarchy plus ancien conserve cette connexion jusqu'à ce qu'elle se termine, donc la bascule nomme ces sessions et se termine d'elle-même une fois qu'elles ont disparu. Les sessions Codex et Grok en cours restent sur le compte avec lequel elles ont commencé. L'historique des conversations, les réglages, les skills et les plugins sont partagés entre les comptes, donc `claude --continue` dans le même dossier reprend là où vous vous étiez arrêté sur le nouveau compte.

Avec plus d'un compte, le panneau affiche les limites de chaque compte côte à côte, avec une étoile pleine sur celui en cours d'utilisation. Omarchy vous avertit lorsque le compte actif dépasse 95 % d'une limite, et cliquer sur la notification bascule vers le compte disposant de la plus grande marge. Il ne bascule jamais de lui-même. Modifiez le seuil avec `omarchy agent account threshold 90`. Si chaque compte est au-dessus du seuil, vous en serez informé une fois, avec le compte qui se libère en premier. Lorsqu'un compte actif est à moins de 15 points de son seuil (80 % par défaut), ses limites sont vérifiées toutes les trois minutes plutôt que toutes les 15.

`omarchy agent account list` affiche chaque compte et ses dernières limites, `omarchy agent account remove work` en oublie un, et `omarchy agent account rename primary Hey` en renomme un (ou cliquez sur le nom d'un compte dans le panneau). Ces commandes fonctionnent sur les comptes de votre agent par défaut ; pour atteindre l'autre fournisseur, nommez-le d'abord, comme dans `omarchy agent account use codex side`. La connexion que vous aviez déjà dans `~/.claude` ou `~/.codex` est le compte _Main_. Celle de Codex reste là où elle est ; celle de Claude attend dans un dossier à elle pendant qu'un autre compte est actif. Un compte laissé inutilisé pendant plus d'environ huit heures peut afficher _Connexion requise_ ; cliquez dessus pour reconnecter ce compte directement dans le panneau, ou basculez vers lui et démarrez une session, ce qui actualise la connexion d'elle-même. Les serveurs MCP que vous ajoutez avec `claude mcp add` atteignent chaque compte Claude, puisqu'ils s'exécutent tous dans `~/.claude` ; pour Codex et Grok, les serveurs que vous aviez lors de l'ajout d'un compte l'accompagnent, mais ceux ajoutés plus tard n'atteignent que le compte dans lequel vous les avez ajoutés. Claude Desktop conserve sa propre connexion, et les outils Codex ou Grok configurés avec un chemin absolu vers un binaire CLI ne suivent pas la bascule. Un `CLAUDE_CONFIG_DIR`, `CODEX_HOME` ou `GROK_HOME` explicite a la priorité sur le compte sélectionné.

### Diagnostic des plantages

Omarchy surveille systemd-coredump pour les plantages de processus. Une fois que vous avez choisi un agent par défaut, tout programme à vous qui génère un vidage mémoire affiche une notification « Processus planté » — cliquez dessus, et le plantage est confié à votre agent par défaut avec le skill omarchy-diagnose-crash d'Omarchy, qui guide l'agent pour établir les faits à partir du vidage mémoire et décider si le plantage vaut la peine d'être signalé en amont. Vous pouvez aussi l'exécuter à la main sur n'importe quel PID de `coredumpctl list` avec `omarchy agent crash <pid>`.

La surveillance est activée par défaut. Désactivez-la sous _Déclencheur > Basculer > Désactiver la capture des plantages_ (ou avec `omarchy toggle crash-capture`) et les notifications s'arrêtent ; `omarchy agent crash <pid>` fonctionne toujours à la main.

Les plantages peuvent aussi être réduits au silence un programme à la fois, ce que le diagnostic vous propose à la fin. `omarchy crash mute hyprland` arrête les notifications pour ce programme uniquement, `omarchy crash mute hyprland off` les rétablit, et `omarchy crash mute` seul liste ce que vous avez mis en sourdine. Il accepte le chemin du binaire aussi volontiers que son nom, donc `omarchy crash mute /usr/bin/hyprland` fait la même chose. Mettez entre guillemets un nom contenant un espace, comme dans `omarchy crash mute 'Some App'`. Tout le reste continue de notifier, et le programme mis en sourdine continue de planter — cela masque le rappel, cela ne répare rien.

### Applications de bureau

Le menu _Installer > IA_ propose aussi quelques applications d'IA graphiques : Amp Desktop, Antigravity Desktop, l'application de bureau ChatGPT, l'application de bureau Claude (la bêta Linux d'Anthropic, avec les onglets Chat, Cowork et Claude Code), Grok Bot pour discuter avec les modèles de xAI, Herdr Desktop, Hermes Desktop, OpenClaw, l'application de bureau Perplexity et T3 Code. Grok Bot est l'application de discussion de bureau. L'agent de codage est la commande `grok`.

Hermes Desktop est celle qu'il faut connaître, parce qu'une machine n'a qu'un seul Hermes, et c'est celui de l'application : Hermes n'est jamais installé que via l'application, et la commande `hermes` que l'agent par défaut exécute est celle de l'application. Choisir Hermes comme agent par défaut installe la même chose que l'entrée _Installer > IA_ : le paquet, et un environnement Hermes sous `~/.hermes` configuré par l'installateur propre à Hermes, ce qui prend quelques minutes la première fois. Cet environnement est l'unique Hermes qu'utilisent la commande `hermes` du terminal, l'agent par défaut et l'application, et il se met à jour lui-même avec `hermes update` plutôt que d'attendre une version d'Omarchy. L'installer confie aussi à Hermes le thème Omarchy comme skin nommé `omarchy`, que chaque surface Hermes suit lorsque vous changez de thème ; choisissez-en un autre dans les réglages Apparence de Hermes ou avec `/skin` si vous préférez qu'il ne le fasse pas, et Omarchy laisse ce choix tranquille. Supprimer l'application sous _Supprimer > IA_ ferme d'abord Hermes, passerelle incluse, emporte cet environnement avec elle, et conserve vos discussions, vos mémoires et les skills que Hermes a écrits pour lui-même sauf si vous lui dites le contraire : elle demande, avec non par défaut, si ces données et vos réglages de connexion doivent aussi partir.

L'expérience de bureau d'OpenClaw est son Control UI, qui s'ouvre comme une application web adossée à sa propre passerelle locale. OpenClaw vit dans `~/.openclaw` et se met à jour lui-même : utilisez le bouton « Mettre à jour la passerelle » du Control UI ou exécutez `openclaw update`, et la passerelle redémarre sur la nouvelle version. Omarchy choisit uniquement la version avec laquelle une installation fraîche démarre. OpenClaw peut aussi être votre agent par défaut : le choisir avec `omarchy default agent openclaw` configure cette même copie dans `~/.openclaw`, et l'agent ouvre l'interface terminal d'OpenClaw connectée à sa passerelle. Supprimer OpenClaw sous _Supprimer > IA_ emporte le service de passerelle et l'application avec lui, puis demande si `~/.openclaw` doit aussi partir, puisque ce dossier contient vos discussions et vos identifiants avec OpenClaw lui-même et les environnements de plugins qu'il télécharge ; par défaut, il est conservé, et réinstaller OpenClaw le récupère.

Herdr Desktop est l'application de bureau [Herdr](https://herdr.dev) : des espaces, des onglets et des panneaux de terminaux et d'agents de codage qui continuent de fonctionner dans son cœur lorsque vous fermez la fenêtre. Elle provient de l'installateur propre à Herdr plutôt que d'un paquet, donc elle vit dans `~/.local/share/herdr-app`, apporte son cœur dans `~/.local/bin/herdr-core` lorsque vous n'en avez pas encore, et met à jour les deux elle-même. Elle se trouve à côté de la commande `herdr` qu'Omarchy fournit sur `Super + Ctrl + Return` plutôt que de la remplacer, et elle reçoit les touches directes de cette commande : `Alt + Return` et `Alt + Shift + Return` divisent un panneau vers le bas ou vers la droite, `Alt + Escape` le ferme, `Ctrl + Alt + Arrow` déplace entre les panneaux, `Alt + 1..9` et `Alt + Left/Right` choisissent un onglet, et `Alt + Up/Down` déplacent entre les espaces. `Ctrl + 1..9` choisit un espace et `Alt + Shift + Up/Down` fait défiler les agents. Les touches préfixes `Ctrl + Space` restent réservées au terminal, puisque l'application ne peut pas retenir une simple touche Ctrl pour une séquence. Omarchy les écrit dans `~/.config/herdr-app/keys.json`, et `omarchy-refresh-herdr-app` les y remet. L'installer choisit le thème Omarchy de Herdr, qui suit votre thème Omarchy dès lors. Herdr conserve un thème pour le mode clair et un pour le mode sombre, donc après être passé d'un thème Omarchy sombre à un thème clair, choisissez Omarchy dans le sélecteur de thème de Herdr une fois de plus pour l'autre mode.

T3 Code s'exécute depuis sa version officielle AppImage dans `~/.local/share/t3code` plutôt que depuis un paquet, donc il se met à jour lui-même. L'installer demande s'il faut démarrer sur le canal Stable ou Nightly ; changez plus tard dans les réglages de T3 Code. Vos fils et vos réglages vivent dans `~/.t3`, et supprimer T3 Code sous _Supprimer > IA_ les emporte avec lui.

### Modèles locaux

Exécutez un modèle ouvert sur votre propre machine pour vos agents de codage. Vos invites et votre code restent sur la machine ; rien de ce qui est envoyé au modèle n'en sort. Commencez par :

```bash
omarchy models use best text
```

Cela configure le meilleur modèle de texte pour cette machine, le type que vos agents utilisent. Les modèles d'image, de vidéo et de musique ont chacun leur meilleur : `omarchy models use best image`, `video` ou `music`. Exécutez `omarchy models use best` pour voir le choix de chaque type pour cette machine.

Ou choisissez + dans le panneau des agents : sous _Utiliser un modèle local_, il liste chaque modèle de codage qui convient à cette machine, le recommandé en premier. Podman, qui exécute les modèles, est fourni avec Omarchy, tout comme la boîte à outils conteneur de NVIDIA sur une machine NVIDIA, qui leur donne accès au GPU ; si l'un des deux manque, la première configuration l'installe. Omarchy choisit ensuite le modèle recommandé pour cette machine, le télécharge et le démarre. Attendez-vous à un téléchargement de dizaines de Go et à ce que la majeure partie de la mémoire de la machine soit utilisée pendant que le modèle fonctionne : Flash Next utilise environ 100 Gio avec son contexte complet de 256K. Si d'autres modèles occupent la mémoire dont il a besoin, il est configuré à l'arrêt, prêt à démarrer dès que vous en arrêtez un. Le modèle s'arrête à la déconnexion ; arrêtez-le vous-même lorsque vous avez besoin de la mémoire pour autre chose.

`omarchy models list` affiche les options et explique pourquoi certaines ne conviennent pas. Pour en configurer un autre, exécutez `omarchy models use <recipe>`. Aujourd'hui, `qwen3.8-flash-next-gufo` et `qwen3.8-27b-gufo` sont disponibles pour les machines Strix Halo de 128 Go ; le 27B prend environ 40 Gio, donc il laisse de la place pour d'autres tâches. Sur un portable de 64 Go avec l'Arc B390 d'Intel, `qwen3.6-35b-a3b-llamacpp` fonctionne dans environ 30 Gio. Les nouvelles recettes et recommandations arrivent avec `omarchy update`, via le paquet.

Un modèle de codage que vous ajoutez reçoit sa propre ligne dans le panneau des agents, à côté de vos abonnements : lecture pour le démarrer, pause pour l'arrêter et libérer sa mémoire, la marque Tailscale pour le partager avec les autres machines de votre tailnet pendant qu'il fonctionne, et le bouton terminal pour ouvrir votre agent dessus. Sa ligne affiche le téléchargement, le chargement ou l'arrêt au fur et à mesure, et le signale lorsqu'il n'y a pas assez de mémoire libre pour le démarrer, ou renvoie vers ses journaux lorsqu'il s'est arrêté avec une erreur. Plusieurs peuvent fonctionner en même temps lorsqu'ils tiennent ensemble en mémoire. Appuyez sur Delete sur une ligne sélectionnée pour supprimer le modèle de cette machine, téléchargement compris ; + peut le reconfigurer. Un modèle de codage configuré depuis un terminal attend sous + jusqu'à ce que vous l'ajoutiez, et il en va de même pour les modèles qu'exécute une machine avec laquelle vous vous êtes apparié (`omarchy models pair <host>`).

Chaque modèle de codage que vous configurez reçoit aussi sa propre entrée dans le lanceur d'applications, sous le nom du modèle et avec le logo de son créateur, de la même manière que se connecter à Claude, Codex ou Grok en ajoute une. Elle ouvre votre agent sur ce modèle, et démarre d'abord le modèle s'il n'est pas en cours : le terminal le montre en train de charger et passe la main à l'agent une fois qu'il est prêt. Supprimer un modèle supprime son entrée.

Tous les modèles ne sont pas destinés au codage. Les modèles d'image, de vidéo et de musique s'ouvrent plutôt dans Fantasi, l'application d'Omarchy pour créer des images, des vidéos et de la musique avec un modèle fonctionnant sur cette machine, et sont gérés là ou avec `omarchy models`.

Un modèle continue de fonctionner exactement comme il a été configuré, donc une mise à jour d'Omarchy n'en redémarre jamais un sous vos agents. Lorsqu'Omarchy dispose d'un environnement plus récent ou de poids plus récents pour un modèle que vous avez configuré, sa ligne affiche un bouton de mise à jour : appuyez dessus et le modèle est reconfiguré en arrière-plan, en ne téléchargeant que ce qui a changé, et redémarre sur la nouvelle version. Un modèle qui était arrêté reste arrêté. `omarchy models update` fait la même chose pour chaque modèle depuis un terminal.

Depuis la ligne de commande, `omarchy models start <recipe>` et `omarchy models stop <recipe>` font la même chose, `omarchy models status` affiche chaque modèle, et `omarchy agent --local-model <recipe>` ouvre ce modèle dans pi, quel que soit votre agent par défaut. Pour faire de votre modèle local ce qu'ouvrent la touche de raccourci de l'agent, la console Quake et _Créez quelque chose_, exécutez `omarchy default agent local` ou marquez d'une étoile un modèle en cours dans le panneau des agents. pi liste aussi chaque modèle que vous avez configuré, et ceux des machines avec lesquelles vous vous êtes apparié, dans son propre sélecteur de modèle, donc un simple `pi` les atteint aussi. Tout client compatible OpenAI peut aussi se connecter : `status` affiche l'adresse de chaque modèle (la première est `http://127.0.0.1:11435/v1`), le nom de la recette est le modèle, et la clé se trouve dans `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` supprime un modèle et les téléchargements qu'aucun autre modèle n'utilise.

Les environnements tiers sont étiquetés avec leur éditeur. Omarchy exécute chaque modèle sans aucun accès réseau.

### LLM locaux

Omarchy recommande deux façons d'exécuter des modèles LLM locaux : LM Studio et Ollama. LM Studio fournit une interface graphique pour trouver des modèles à poids ouverts, les installer et les exécuter. C'est un excellent moyen de s'y mettre facilement. Ollama propose un CLI pour faire de même. Mais si vous débutez avec les modèles locaux, je commencerais par LM Studio. Vous pouvez installer l'un ou l'autre sous _Installer > IA_ dans le menu Omarchy.

### Les skills Omarchy

Les skills d'agent aident l'IA à utiliser des outils spécifiques d'une manière spécifique, et Omarchy en fournit sept. Le skill omarchy couvre l'adaptation du système, comme modifier votre configuration Hyprland ou ajuster la barre. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app et omarchy-make-game couvrent la création de quelque chose de nouveau, omarchy-contribute couvre le signalement d'un bug ou l'envoi d'un correctif en amont, et omarchy-diagnose-crash travaille sur le vidage mémoire d'un plantage. Ils sont liés par des liens symboliques dans les répertoires de skills pour Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` et chaque `~/.hermes/profiles/*/skills`), et l'emplacement générique `~/.agents/skills`, donc la plupart des harness les récupèrent automatiquement. Un dossier de skill à vous portant le même nom a la priorité.

Mais vous devriez traiter ces skills comme expérimentaux. Différents modèles l'utiliseront avec des effets différents. Il vaut mieux commencer en mode plan, afin d'avoir une idée de ce que l'agent aimerait changer. Et ensuite, soyez prêt à annuler les changements, voire à invoquer `omarchy reinstall configs`, si l'agent met le bazar partout.
