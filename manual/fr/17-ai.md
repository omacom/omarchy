# IA

Omarchy inclut des lanceurs pour les agents de codage ci-dessous sans en choisir un par défaut à votre place. Exécutez une commande pour installer son CLI lors de la première utilisation, puis authentifiez-vous lorsque vous y êtes invité. Hermes fait exception : rien n'est installé pour lui lors de la première utilisation, et le choisir installe Hermes Desktop, comme l'explique _Applications de bureau_ ci-dessous.

### Installation et mise à jour des agents

À l'exception de Hermes, ces agents utilisent l'installation paresseuse de mise : le premier lancement installe le CLI, et les lancements suivants le réutilisent. mise vérifie également si un agent installé a une nouvelle version au maximum une fois toutes les quatre heures, juste avant son démarrage ou en arrière-plan à l'invite du shell. Si cette mise à jour échoue ou si vous êtes hors ligne, la version installée s'exécute. `omarchy update` met à jour les agents installés avec le reste d'Omarchy, et `mup` met à jour uniquement les outils gérés par mise.

Le programme de mise à jour propre à un agent, comme `claude update`, `codex update` ou un bouton de mise à jour dans une application, ne met pas à jour l'installation gérée par mise. `codex update` échoue, et `claude update` peut annoncer un succès tout en installant une copie distincte que mise ne suit pas. Si vous préférez utiliser l'installateur et le programme de mise à jour natifs d'un agent, ajoutez-le à `disable_tools` ; voir [Outils CLI préinstallés](18-development-tools.md#preinstalled-cli-tools).

Pour installer tous les outils paresseux configurés avant d'en avoir besoin, exécutez `mise install --include-lazy`. Cela inclut les autres outils CLI par défaut d'Omarchy ainsi que les agents. Voir [Outils CLI préinstallés](18-development-tools.md#preinstalled-cli-tools) pour installer un seul outil ou utiliser votre propre installation.

`grok` est installé via le package `grok` propre à mise, de la même manière que `claude` et `codex`. Exécutez `grok`, ou choisissez-le sous _Agent > Harness_. Évitez l'installateur `curl | bash` sur x.ai. Ce chemin place une deuxième copie dans `~/.grok/bin`, la place en tête de `PATH` et écrase le wrapper d'Omarchy.

`dsh` ouvre son interface navigateur sur `127.0.0.1:3080`, avec le répertoire de lancement comme espace de travail par défaut. Son interface navigateur n'accepte aucune invite de départ, donc `omarchy agent prompt` l'ouvre avec l'invite dans votre presse-papiers, prête à coller. Omarchy le démarre avec le préréglage de permissions sans approbation de DeepSeek. DeepSeek Harness envoie les journaux de session à DeepSeek lorsque vous utilisez son API de modèle officielle ; désactivez cela sous _Settings > General > Upload Session Log_ dans son interface navigateur. Les retours que vous lui envoyez sont également envoyés avec la session, sauf si vous le démarrez avec `DSH_TELEMETRY_MODE=DISABLED`.

### L'agent par défaut

Choisissez votre agent par défaut avec `omarchy default agent <name>` ou sous _Agent > Harness_ dans le Omarchy Menu (`Super + Space`). Si l'agent n'est pas encore installé, le choisir l'installe d'abord. Un Omarchy fraîchement installé vous invitera à faire ce choix avec une notification unique.

Choisir Claude tente également de configurer son extension de navigateur pour Chromium, Chrome, Brave, Brave Origin et Edge. La configuration de l'extension s'applique à tous les utilisateurs et peut demander votre mot de passe système ; annuler ou un échec d'installation de l'extension sélectionne et lance quand même Claude. Redémarrez votre navigateur, activez l'extension si vous y êtes invité, et connectez-vous à Claude pour terminer sa connexion. Exécutez `/chrome` dans Claude pour vérifier la connexion. Firefox et Zen ne prennent pas en charge cette extension. Si Claude était déjà votre agent par défaut avant l'ajout de cette configuration, sélectionnez-le à nouveau pour installer l'extension.

Une fois votre choix fait, `Super + Shift + Ctrl + A` lance l'agent par défaut dans une fenêtre de terminal dédiée (ou affiche le sélecteur si vous n'avez pas encore choisi). Vous pouvez aussi le lancer directement sur une tâche avec `omarchy agent prompt "Review this project"`. Freebuff et DeepSeek Harness n'acceptent aucune invite de départ, donc ils s'ouvrent avec l'invite dans votre presse-papiers, prête à coller. Les agents lancés ainsi fonctionnent sans surveillance dans leurs modes respectifs ne-pas-s'arrêter-pour-demander, alors soyez prêt à ce qu'ils fassent réellement des choses ! MiniMax Code n'a pas de tel mode pour ses sessions interactives, donc il demande les permissions comme d'habitude. Et comme les agents refusent de mémoriser la confiance pour votre répertoire personnel, les lancements depuis `$HOME` démarrent plutôt dans `~/Work`.

Il existe aussi des raccourcis de terminal : `a` exécute l'agent par défaut en ligne dans le terminal actuel, tandis que `c`, `cx` et `cy` lancent directement OpenCode, Claude Code et Codex (là encore dans leurs modes d'approbation automatique). Les changements de thème se synchronisent aussi avec les agents : Claude Code, Pi, OpenCode et Hermes (une fois qu'Omarchy l'a installé) suivent tous lorsque vous changez le thème Omarchy.

### Vos instructions d'agent

Les règles personnelles pour chaque agent vont dans `~/.agents/AGENTS.md`, à côté des skills partagés dans `~/.agents/skills`. Ouvrez-le sous _Agent > Instructions_, qui le lie aussi dans chaque harnais qui conserve son propre fichier global : `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, le `~/.copilot/copilot-instructions.md` de Copilot, et ainsi de suite. Crush et Amp lisent le lien `~/.config/AGENTS.md`, tandis que omp, Kimi et DeepSeek Harness lisent directement `~/.agents/AGENTS.md`. Choisir un agent par défaut le lie aussi. Un fichier d'instructions que vous aviez déjà devient le fichier partagé s'il n'y en avait pas encore ; sinon il est conservé à côté du lien sous forme de `.bak`. Exécutez `omarchy agent instructions` pour relier après l'installation d'un autre agent.

### Le panneau des agents

La barre supérieure comporte une icône d'agents. Avant que vous ayez configuré un agent, son panneau vous guide pour vous connecter à Claude, Codex ou Grok, et le premier devient votre agent par défaut. Ensuite, le panneau rassemble chaque abonnement sur une seule page : chaque agent et chaque compte avec son forfait, un compteur pour chacune de ses limites de session de 5 heures et hebdomadaire avec le temps restant avant sa réinitialisation (survolez pour le pourcentage exact), ou le solde prépayé restant, sous une ligne qui fait défiler ce que vous avez utilisé parmi tous, comme les tokens cette semaine et votre modèle le plus utilisé. Sous _Make something_, il propose des invites de démarrage pour un nouveau thème, plugin, application ou jeu qui confient la tâche à votre agent par défaut. Les applications sont construites comme le sont Hype, Monologue et Omacut d'Omarchy, en C++ et Qt Quick, en suivant le skill d'agent omarchy-app, et le compilateur et les éléments Qt dont elles ont besoin sont installés. Les jeux sont une seule page three.js dans `~/Games/vibes`, suivant le skill d'agent web-game, et s'ouvrent tous depuis un seul lanceur Game Vibes dans le thème actuel ; ils chargent three.js depuis le web, donc ils ont besoin d'une connexion pour démarrer. Claude Code, Codex, Grok, Kimi, Cursor et son allocation Grok Bot, GitHub Copilot, Muse, Antigravity, Kimchi et Devin sont pris en charge dès le départ avec leurs limites, et Hermes, Mistral Vibe et Qwen Code affichent leurs sessions et tokens une fois que vous les avez utilisés. Les forfaits et clés de fournisseurs que vous utilisez via pi, omp ou opencode apparaissent aussi : OpenCode Zen et Go, le Z.ai GLM Coding Plan, Ollama Cloud, le MiniMax Token Plan et Synthetic avec leurs limites ; Fireworks, OpenRouter et DeepSeek avec leurs soldes prépayés ; et les modèles que vous exécutez sur votre propre matériel sous Local models. Chaque agent est compté une fois, sous celui qui le facture, peu importe le nombre de harnais par lesquels vous le pilotez.

Cliquez avec le bouton gauche sur l'icône de la barre pour le panneau, avec le bouton droit pour lancer votre agent par défaut. Les relevés d'utilisation qui l'alimentent sont régénérés toutes les 15 minutes par `omarchy agent usage-update`, et le panneau peut même fusionner l'utilisation de vos autres machines via un dossier synchronisé. Voir le README sous `$OMARCHY_PATH/shell/plugins/agents/` pour tous les réglages.

### Plusieurs abonnements

Si vous payez plus d'un forfait Claude, Codex ou Grok — un Max personnel et un professionnel, par exemple — Omarchy peut les garder tous connectés et passer de l'un à l'autre. Ajoutez un abonnement avec le + dans le panneau des agents, qui vous guide sur place, ou avec `omarchy agent account add claude Work` (ou `codex`, ou `grok`). Il installe le CLI s'il manque. Le premier compte pour un fournisseur se connecte via votre navigateur normal, là où le CLI cherche toujours. Chaque suivant se connecte via une fenêtre privée, pour que le compte auquel votre navigateur est déjà connecté ne soit pas récupéré par erreur ; connectez-vous là en tant que compte que vous ajoutez, et fermez d'abord toute fenêtre privée déjà ouverte. Ne vous déconnectez jamais du CLI pour faire cela : se déconnecter révoque la connexion enregistrée, et ce compte devrait être ajouté à nouveau.

Pour copier vos connexions d'abonnement vers une autre machine Omarchy via SSH, exécutez `omarchy agent account copy user@laptop`. L'expéditeur fournit un récepteur temporaire lorsque la destination n'en a pas d'installé, donc les machines Omarchy plus anciennes peuvent recevoir des comptes sans mise à jour. Les récepteurs installés ont la priorité. Cela copie tous les abonnements Claude, Codex et Grok ; ajoutez des noms de fournisseurs pour les sélectionner, comme dans `omarchy agent account copy laptop claude`. Les noms de comptes et les ID de commande correspondent à la source, y compris les comptes déjà présents sur la destination. Les comptes de destination sans rapport reçoivent un suffixe numérique si leurs noms entrent en conflit, et les réglages, skills, plugins et l'historique de conversation restent locaux à chaque machine.

Les identifiants de destination existants sont conservés. Un compte source déjà connecté là voit son nom synchronisé sans remplacer ses identifiants ; les autres comptes sont ajoutés à côté de lui. Pour remplacer les identifiants enregistrés pour les comptes correspondants, utilisez `omarchy agent account copy --replace laptop claude` après avoir quitté les sessions de ce compte sur la destination. Une destination neuve reçoit aussi le compte actif et les préférences de bascule de la source ; une destination établie conserve les siens.

Les identifiants voyagent via SSH et sont stockés dans des fichiers privés sur la destination, donc ne copiez que vers des machines de confiance. Il s'agit d'une copie ponctuelle, pas d'une synchronisation continue. Les tokens de rafraîchissement Codex peuvent être renouvelés par une autre machine, laissant une connexion copiée ayant besoin d'un renouvellement ; des connexions distinctes restent le choix le plus fiable pour une utilisation simultanée sur plusieurs machines. Voir [le guide d'authentification de compte de Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Un compte par fournisseur est actif, et chaque nouvelle session démarre sous celui-ci : `cx`, `cy`, un simple `claude`, `codex` ou `grok`, tout ce qui est lancé via `omarchy agent`, et les scripts ou éditeurs qui trouvent le CLI sur `PATH`. Basculez avec `omarchy agent account use work` (et revenez avec `omarchy agent account use main`), ou dans le panneau en appuyant sur le numéro d'un compte puis `Enter` (ou en cliquant sur son bouton Use). Les sessions Claude en cours basculent aussi, dès leur prochain message : chaque session Claude s'exécute dans `~/.claude`, qui contient toujours la connexion du compte actif. Une session Claude démarrée dans le dossier propre d'un compte par un Omarchy plus ancien conserve cette connexion jusqu'à ce qu'elle se ferme, donc la bascule nomme ces sessions et se termine d'elle-même une fois qu'elles ont disparu. Les sessions Codex et Grok en cours restent sur le compte avec lequel elles ont démarré. L'historique de conversation, les réglages, les skills et les plugins sont partagés entre les comptes, donc `claude --continue` dans le même dossier reprend là où vous vous étiez arrêté sur le nouveau compte.

Avec plus d'un compte, le panneau affiche les limites de chaque compte côte à côte, avec le compte actif marqué. Par défaut, Omarchy vous prévient lorsque le compte actif dépasse 95 % d'une limite, et cliquer sur la notification bascule vers le compte avec le plus de marge. Survolez la ligne d'un compte dans le panneau et cliquez sur Autoswitch qui apparaît à côté de Use (ou appuyez sur `m`), ou exécutez `omarchy agent account mode auto`, pour qu'il bascule de lui-même ; pendant qu'il est activé, Autoswitch prend la place de Use, et cliquer à nouveau dessus revient à la notification. Ajoutez un nombre pour changer le seuil, comme dans `omarchy agent account mode auto 90`. Si chaque compte dépasse le seuil, vous en serez informé une fois, avec le compte qui se libère en premier. Lorsqu'un compte actif est à moins de 15 points de son seuil (80 % par défaut), ses limites sont vérifiées toutes les trois minutes plutôt que toutes les 15.

`omarchy agent account list` affiche chaque compte et ses dernières limites, `omarchy agent account remove work` en oublie un, et `omarchy agent account rename primary Hey` en renomme un (ou cliquez sur le nom d'un compte dans le panneau). Ces commandes fonctionnent sur les comptes de votre agent par défaut ; pour atteindre l'autre fournisseur, nommez-le d'abord, comme dans `omarchy agent account use codex side`. La connexion que vous aviez déjà dans `~/.claude` ou `~/.codex` est le compte _Main_. Celui de Codex reste où il est ; celui de Claude attend dans un dossier propre pendant qu'un autre compte est actif. Un compte laissé inutilisé pendant plus d'environ huit heures peut afficher _Sign-in required_ ; cliquez dessus pour reconnecter ce compte directement dans le panneau, ou basculez dessus et démarrez une session, ce qui rafraîchit la connexion de lui-même. Les serveurs MCP que vous ajoutez avec `claude mcp add` atteignent chaque compte Claude, puisqu'ils s'exécutent tous dans `~/.claude` ; pour Codex et Grok, les serveurs que vous aviez lorsqu'un compte a été ajouté l'accompagnent, mais les suivants n'atteignent que le compte dans lequel vous les avez ajoutés. Claude Desktop conserve sa propre connexion, et les outils Codex ou Grok configurés avec un chemin absolu vers un binaire CLI ne suivent pas la bascule. Un `CLAUDE_CONFIG_DIR`, `CODEX_HOME` ou `GROK_HOME` explicite a la priorité sur le compte sélectionné.

### Diagnostic des plantages

Omarchy surveille systemd-coredump pour les plantages de processus. Lorsque quelque chose fait une erreur de segmentation, vous recevrez une notification « Process crashed » — cliquez dessus, et le plantage est confié à votre agent par défaut avec le skill diagnose-crash d'Omarchy, qui guide l'agent pour établir les faits à partir du core dump et décider si le plantage vaut la peine d'être signalé en amont. Vous pouvez aussi l'exécuter à la main contre n'importe quel PID de `coredumpctl list` avec `omarchy agent crash <pid>`.

La surveillance est activée par défaut. Désactivez-la sous _Trigger > Toggle > Crash Capture_ (ou avec `omarchy toggle crash-capture`) et les notifications s'arrêtent ; `omarchy agent crash <pid>` fonctionne toujours à la main.

Les plantages peuvent aussi être réduits au silence un programme à la fois, ce que le diagnostic vous propose à la fin. `omarchy crash mute hyprland` arrête les notifications pour ce programme seulement, `omarchy crash mute hyprland off` les ramène, et `omarchy crash mute` seul liste ce que vous avez mis en sourdine. Il accepte le chemin du binaire aussi volontiers que son nom, donc `omarchy crash mute /usr/bin/hyprland` fait la même chose. Mettez entre guillemets un nom contenant un espace, comme dans `omarchy crash mute 'Some App'`. Tout le reste continue de notifier, et le programme mis en sourdine continue de planter — cela cache le rappel, cela ne répare rien.

### Applications de bureau

Le menu _Install > AI_ propose aussi quelques applications d'IA graphiques : l'application de bureau ChatGPT, l'application de bureau Claude (la bêta Linux d'Anthropic, avec les onglets Chat, Cowork et Claude Code), Grok Bot pour discuter avec les modèles de xAI, Herdr Desktop, Hermes Desktop, OpenClaw, l'application de bureau Perplexity et T3 Code. Grok Bot est l'application de discussion de bureau. L'agent de codage est la commande `grok`.

Hermes Desktop est celui qu'il faut connaître, parce qu'une machine a un seul Hermes, et c'est celui de l'application : Hermes n'est jamais installé que via l'application, et la commande `hermes` que l'agent par défaut exécute est celle de l'application. Choisir Hermes comme agent par défaut installe la même chose que l'entrée _Install > AI_ : le package, et un runtime Hermes sous `~/.hermes` configuré par l'installateur propre à Hermes, ce qui prend quelques minutes la première fois. Ce runtime est le seul Hermes que la commande `hermes` du terminal, l'agent par défaut et l'application utilisent tous, et il se met à jour lui-même avec `hermes update` plutôt que d'attendre une version d'Omarchy. L'installer donne aussi à Hermes le thème Omarchy comme un skin nommé `omarchy`, que chaque surface Hermes suit lorsque vous changez de thème ; choisissez-en un autre dans les réglages Appearance de Hermes ou avec `/skin` si vous préférez qu'il ne le fasse pas, et Omarchy laisse ce choix tranquille. Retirer l'application sous _Remove > AI_ ferme d'abord Hermes, gateway incluse, emporte ce runtime avec elle, et conserve vos discussions, mémoires et les skills que Hermes a écrits pour lui-même sauf si vous lui dites le contraire : il demande, avec non par défaut, si ces données et vos réglages de connexion doivent aussi partir.

L'expérience de bureau d'OpenClaw est son Control UI, qui s'ouvre comme une application web adossée à sa propre gateway locale. OpenClaw vit dans `~/.openclaw` et se met à jour lui-même : utilisez le bouton « Update Gateway » du Control UI ou exécutez `openclaw update`, et la gateway redémarre sur la nouvelle version. Omarchy choisit seulement la version depuis laquelle une installation neuve démarre. Retirer OpenClaw sous _Remove > AI_ emporte le service gateway et l'application avec lui, puis demande si `~/.openclaw` doit aussi partir, puisque cela contient vos discussions et identifiants à côté d'OpenClaw lui-même et des runtimes de plugins qu'il télécharge ; le choix par défaut le conserve, et installer OpenClaw à nouveau le récupère.

Herdr Desktop est l'application de bureau [Herdr](https://herdr.dev) : des espaces, onglets et volets de terminaux et d'agents de codage qui continuent de fonctionner dans son cœur lorsque vous fermez la fenêtre. Elle vient de l'installateur propre à Herdr plutôt que d'un package, donc elle vit dans `~/.local/share/herdr-app`, apporte son cœur dans `~/.local/bin/herdr-core` lorsque vous n'en avez pas encore, et se met à jour elle-même ainsi que lui. Elle se tient à côté de la commande `herdr` qu'Omarchy fournit sur `Super + Ctrl + Return` plutôt que de la remplacer, et reçoit les touches directes de cette commande : `Alt + Return` et `Alt + Shift + Return` divisent un volet vers le bas ou vers la droite, `Alt + Escape` le ferme, `Ctrl + Alt + Arrow` déplace entre les volets, `Alt + 1..9` et `Alt + Left/Right` choisissent un onglet, et `Alt + Up/Down` déplacent entre les espaces. `Ctrl + 1..9` choisit un espace et `Alt + Shift + Up/Down` parcourt les agents. Les touches de préfixe `Ctrl + Space` restent réservées au terminal, puisque l'application ne peut pas retenir une touche Ctrl simple pour une séquence. Omarchy écrit celles-ci dans `~/.config/herdr-app/keys.json`, et `omarchy-refresh-herdr-app` les remet en place. L'installer choisit le thème Omarchy de Herdr, qui suit votre thème Omarchy à partir de là. Herdr conserve un thème pour le mode clair et un pour le mode sombre, donc après être passé d'un thème Omarchy sombre à un thème clair, choisissez Omarchy dans le sélecteur de thème de Herdr encore une fois pour l'autre mode.

T3 Code s'exécute depuis sa version AppImage officielle dans `~/.local/share/t3code` plutôt que depuis un package, donc il se met à jour lui-même. L'installer vous demande si vous voulez démarrer sur le canal Stable ou Nightly ; changez plus tard dans les réglages de T3 Code. Vos fils et réglages vivent dans `~/.t3`, et retirer T3 Code sous _Remove > AI_ les emporte avec lui.

### Modèles locaux

Exécutez un modèle ouvert sur votre propre machine pour vos agents de codage. Vos invites et votre code restent sur la machine ; rien de ce qui est envoyé au modèle ne la quitte. Commencez avec :

```bash
omarchy agent local use best
```

Ou, dans le panneau des agents dans la barre supérieure, choisissez + puis Local AI, qui apparaît lorsqu'un modèle tient sur cette machine. La première fois, cela installe Podman, qui exécute les modèles, et sur une machine NVIDIA la boîte à outils conteneur de NVIDIA, qui leur donne le GPU. Omarchy choisit ensuite le modèle recommandé pour cette machine, le télécharge et le démarre. Attendez-vous à un téléchargement de dizaines de Go et à ce que la majeure partie de la mémoire de la machine soit utilisée pendant que le modèle fonctionne : Flash Next utilise environ 100 Gio avec son contexte complet de 256K. Si d'autres modèles détiennent la mémoire dont il a besoin, il est configuré arrêté, prêt à démarrer une fois que vous en arrêtez un. Le modèle s'arrête à la déconnexion ; arrêtez-le vous-même lorsque vous avez besoin de la mémoire pour autre chose.

`omarchy agent local list` affiche les options et explique pourquoi certaines ne tiennent pas. Pour en configurer un autre, exécutez `omarchy agent local use <recipe>`. Aujourd'hui, `qwen3.8-flash-next-gufo` et `qwen3.8-27b-gufo` sont disponibles pour les machines Strix Halo de 128 Go ; le 27B prend environ 40 Gio, donc il laisse de la place pour d'autres travaux. Sur un portable de 64 Go avec l'Arc B390 d'Intel, `qwen3.6-35b-a3b-llamacpp` fonctionne dans environ 30 Gio. De nouvelles recettes et recommandations arrivent avec `omarchy update`, via le package.

Chaque modèle que vous configurez obtient sa propre ligne dans le panneau des agents, à côté de vos abonnements : lecture pour le démarrer, pause pour l'arrêter et libérer sa mémoire, et le bouton terminal pour ouvrir votre agent dessus. Plusieurs peuvent fonctionner en même temps lorsqu'ils tiennent ensemble en mémoire ; si l'un ne tient pas, Omarchy indique quel modèle en cours arrêter. Faites glisser les lignes pour les réordonner, et appuyez sur Delete sur une ligne sélectionnée pour retirer un modèle et son téléchargement.

Chaque modèle que vous configurez obtient aussi sa propre entrée dans le lanceur d'applications, sous le nom du modèle et avec le logo de son créateur, de la façon dont se connecter à Claude, Codex ou Grok en ajoute une. Elle ouvre votre agent sur ce modèle, et démarre d'abord le modèle s'il ne fonctionne pas : le terminal le montre en train de se charger et passe la main à l'agent une fois qu'il est prêt. Retirer un modèle retire son entrée.

Depuis la ligne de commande, `omarchy agent local start <recipe>` et `omarchy agent local stop <recipe>` font la même chose, `omarchy agent local status` affiche chaque modèle, et `omarchy agent --local` ouvre votre agent par défaut sur le dernier modèle que vous avez démarré. pi, OpenCode et Qwen Code peuvent en utiliser un ; avec tout autre agent par défaut, il s'ouvre dans pi. pi liste aussi chaque modèle que vous avez configuré, et ceux des machines avec lesquelles vous êtes appairé, dans son propre sélecteur de modèle, donc un simple `pi` les atteint aussi. Tout client compatible OpenAI peut aussi se connecter : `status` affiche l'adresse de chaque modèle (la première est `http://127.0.0.1:11435/v1`), le nom de la recette est le modèle, et la clé se trouve dans `~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` supprime un modèle et les téléchargements qu'aucun autre modèle n'utilise.

Les runtimes tiers sont étiquetés avec leur éditeur. Omarchy exécute chaque modèle sans aucun accès réseau.

### LLM locaux

Omarchy recommande deux façons d'exécuter des modèles LLM locaux : LM Studio et Ollama. LM Studio fournit une interface GUI pour trouver des modèles à poids ouverts, les installer et les exécuter. C'est un excellent moyen de démarrer facilement. Ollama propose un CLI pour faire de même. Mais si vous débutez avec les modèles locaux, je commencerais par LM Studio. Vous pouvez installer l'un ou l'autre sous _Install > AI_ dans le Omarchy Menu.

### Le skill Omarchy

Les skills d'agent aident l'IA à utiliser des outils spécifiques d'une manière spécifique, et Omarchy est livré avec un skill par défaut pour adapter le système sur mesure. Comme modifier votre configuration Hyprland, ajuster la barre, ou même créer un nouveau thème de zéro. Il est lié par lien symbolique dans les répertoires de skills pour Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` et chaque `~/.hermes/profiles/*/skills`), et l'emplacement générique `~/.agents/skills`, donc la plupart des harnais le récupèrent automatiquement.

Mais vous devriez traiter ce skill comme expérimental. Différents modèles l'utiliseront avec des effets différents. Il vaut mieux l'exécuter d'abord en mode plan, pour avoir une idée de ce que l'agent voudrait changer. Et ensuite, soyez prêt à annuler les changements ou même à invoquer `omarchy reinstall configs`, si l'agent met le bazar partout.
