# IA

Omarchy traite les agents de codage IA comme des citoyens de première classe, mais il ne choisit pas un favori à votre place. À la place, chaque grand CLI d'agent de codage est pré-câblé comme un lanceur à chargement différé. Les lanceurs sont de minuscules stubs gérés par [mise](https://mise.jdx.dev/) dans `~/.local/bin/`, donc rien n'est téléchargé avant la première fois où vous en lancez vraiment un. Hermes est l'exception : rien n'est stubbé pour lui, et le choisir installe Hermes Desktop, comme l'explique _Applications de bureau_ ci-dessous. Invoquez n'importe lequel d'entre eux et authentifiez-vous quand on vous le demande :

| Commande    | Agent                                                            |
|------------|------------------------------------------------------------------|
| `claude`   | [Claude Code](https://code.claude.com/docs/en/overview)          |
| `codex`    | [OpenAI Codex](https://github.com/openai/codex)                  |
| `opencode` | [OpenCode](https://opencode.ai/)                                 |
| `agy`      | [Google Antigravity CLI](https://github.com/google-antigravity/antigravity-cli) |
| `copilot`  | [GitHub Copilot CLI](https://github.com/github/copilot-cli)      |
| `crush`    | [Crush](https://github.com/charmbracelet/crush)                  |
| `grok`     | [Grok Build](https://x.ai/build) de xAI                        |
| `kimi`     | [Kimi Code](https://www.kimi.com/code/docs/en/)                  |
| `pi`       | [Pi de Mario Zechner](https://github.com/badlogic/pi-mono)        |
| `omp`      | [Oh My Pi](https://github.com/can1357/oh-my-pi)                  |
| `ori`      | [Ori](https://openrouter.ai/docs/guides/ori/harness), le harness d'OpenRouter |
| `hermes`   | [Hermes](https://hermes-agent.nousresearch.com/), l'agent de Nous Research  |
| `muse`     | [Muse Code](https://dev.meta.ai), l'agent de codage de Meta           |
| `cursor-agent` | [Cursor CLI](https://cursor.com/cli)                         |

`ori` est l'exception : il exécute les autres harnesses contre tout le catalogue de modèles d'OpenRouter, donc `ori claude`, `ori codex` ou `ori opencode` démarrent ces agents sur le modèle que vous leur désignez, et `ori code` est l'agent propre à Ori.

Pour envelopper un CLI supplémentaire de la même façon, lancez `omarchy-mise-install <package> [command-name]`. Les stubs sont maintenus à jour avec tout ce que mise gère quand vous lancez `omarchy update` (ou l'alias `mup`).

`grok` est installé via le paquet `grok` de première partie de mise, de la même façon que `claude` et `codex`. Lancez `grok`, ou choisissez-le sous _Setup > Defaults > Agent_. Évitez l'installeur `curl | bash` sur x.ai. Cette voie met une deuxième copie dans `~/.grok/bin`, la place en tête sur `PATH` et écrase le wrapper d'Omarchy.

### L'agent par défaut

Choisissez votre agent par défaut avec `omarchy default agent <name>` ou sous _Setup > Defaults > Agent_ dans le Omarchy Menu (`Super + Space`). Si l'agent n'est pas encore installé, le choisir l'installe d'abord. Un Omarchy tout frais vous invitera à faire ce choix avec une notification unique.

Choisir Claude tente aussi de configurer son extension de navigateur pour Chromium, Chrome, Brave, Brave Origin et Edge. La configuration de l'extension s'applique à tous les utilisateurs et peut demander votre mot de passe système ; annuler ou échouer à installer l'extension sélectionne et lance quand même Claude. Redémarrez votre navigateur, activez l'extension si on vous le demande et connectez-vous à Claude pour terminer de la connecter. Lancez `/chrome` dans Claude pour vérifier la connexion. Firefox et Zen ne prennent pas en charge cette extension. Si Claude était déjà votre agent par défaut avant l'ajout de cette configuration, sélectionnez-le à nouveau pour installer l'extension.

[Muse Code](https://dev.meta.ai) — le `muse` de Meta — utilise un stub mise préinstallé comme les autres agents. Le choisir comme agent par défaut installe le lanceur officiel de Meta via le backend HTTP de mise. Le lanceur vérifie et met à jour le binaire natif pour votre machine.

Une fois que vous avez choisi, `Super + Shift + Ctrl + A` lance l'agent par défaut dans une fenêtre de terminal dédiée (ou affiche le sélecteur si vous n'avez pas encore choisi). Vous pouvez aussi le lancer directement dans une tâche avec `omarchy agent prompt "Review this project"`. Les agents lancés ainsi fonctionnent sans surveillance dans leurs modes respectifs où ils ne s'arrêtent pas pour demander, alors soyez prêt à ce qu'ils fassent vraiment des choses ! Et puisque les agents refusent de mémoriser la confiance pour votre répertoire personnel, les lancements depuis `$HOME` démarrent à la place dans `~/Work`.

Il y a aussi des raccourcis de terminal : `a` exécute l'agent par défaut en ligne dans le terminal actuel, tandis que `c`, `cx` et `cy` démarrent directement OpenCode, Claude Code et Codex (là encore dans leurs modes d'approbation automatique). Les changements de thème se synchronisent aussi vers les agents : Claude Code, Pi, OpenCode et Hermes (une fois qu'Omarchy l'a installé) suivent tous quand vous changez de thème Omarchy.

### Le panneau des agents

La barre supérieure a une icône d'agents. Avant que vous ayez configuré un agent, son panneau vous guide pour vous connecter à Claude, Codex ou Grok, et le premier devient votre agent par défaut. Après cela, le panneau met chaque abonnement sur une seule page : chaque agent et chaque compte avec son forfait, un compteur pour chacune de ses limites de session de 5 heures et hebdomadaire avec le temps avant sa réinitialisation (survolez pour le pourcentage exact), ou le solde prépayé restant, sous une ligne qui fait défiler ce que vous avez utilisé sur l'ensemble d'entre eux, comme les tokens cette semaine et votre modèle le plus utilisé. Sous _Make something_, il propose des prompts de départ pour un nouveau thème, un plugin ou une application qui confient la tâche à votre agent par défaut. Les applications sont construites comme le sont Hype, Monologue et Omacut d'Omarchy, en C++ et Qt Quick, en suivant le skill d'agent omarchy-app, et le compilateur et les pièces Qt dont elles ont besoin sont installés. Claude Code, Codex, Grok, Fireworks et Kimi sont couverts d'emblée. Kimi signale actuellement les limites de quota de compte sans statistiques locales de tokens ou de prompts.

Cliquez avec le bouton gauche sur l'icône de la barre pour le panneau, avec le bouton droit pour lancer votre agent par défaut. Les enregistrements d'utilisation qui le soutiennent sont régénérés toutes les 15 minutes par `omarchy agent usage-update`, et le panneau peut même fusionner l'utilisation de vos autres machines via un dossier synchronisé. Voir le README sous `$OMARCHY_PATH/shell/plugins/agents/` pour tous les paramètres.

### Plusieurs abonnements

Si vous payez plus d'un forfait Claude, Codex ou Grok — un Max personnel et un professionnel, par exemple — Omarchy peut les garder tous connectés et passer de l'un à l'autre. Ajoutez un abonnement avec le + dans le panneau des agents, qui vous guide sur place, ou avec `omarchy agent account add claude Work` (ou `codex`, ou `grok`). Il installe le CLI s'il manque. Le premier compte pour un fournisseur se connecte via votre navigateur normal, là où le CLI cherche toujours. Tous les suivants se connectent via une fenêtre privée, pour que le compte auquel votre navigateur est déjà connecté ne soit pas récupéré par erreur ; connectez-vous là en tant que compte que vous ajoutez, et fermez d'abord toute fenêtre privée que vous aviez déjà ouverte. Ne vous déconnectez jamais du CLI pour faire cela : se déconnecter révoque la connexion enregistrée, et ce compte devrait être ajouté à nouveau.

Pour copier vos connexions d'abonnement vers une autre machine Omarchy via SSH, lancez `omarchy agent account copy user@laptop`. L'expéditeur fournit un récepteur temporaire quand la destination n'en a pas d'installé, donc les machines Omarchy plus anciennes peuvent recevoir des comptes sans mise à jour. Les récepteurs installés ont priorité. Cela copie tous les abonnements Claude, Codex et Grok ; ajoutez des noms de fournisseurs pour les sélectionner, comme dans `omarchy agent account copy laptop claude`. Les noms de compte et les ID de commande correspondent à la source, y compris les comptes déjà présents sur la destination. Les comptes de destination sans rapport reçoivent un suffixe numérique si leurs noms entrent en conflit, et les paramètres, skills, plugins et l'historique de conversation restent locaux à chaque machine.

Les identifiants de destination existants sont conservés. Un compte source déjà connecté là-bas voit son nom synchronisé sans remplacer ses identifiants ; les autres comptes sont ajoutés à côté de lui. Pour remplacer les identifiants enregistrés des comptes correspondants, utilisez `omarchy agent account copy --replace laptop claude` après avoir quitté les sessions de ce compte sur la destination. Une destination fraîche reçoit aussi le compte actif et les préférences de bascule de la source ; une destination établie garde les siens.

Les identifiants voyagent via SSH et sont stockés dans des fichiers privés sur la destination, donc ne copiez que vers des machines auxquelles vous faites confiance. Il s'agit d'une copie ponctuelle, pas d'une synchronisation continue. Les tokens de rafraîchissement Codex peuvent être renouvelés par rotation par une autre machine, laissant une connexion copiée ayant besoin d'un renouvellement ; des connexions séparées restent le choix le plus fiable pour une utilisation simultanée sur plusieurs machines. Voir [les conseils d'authentification de compte de Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Un compte par fournisseur est actif, et chaque nouvelle session démarre en tant que tel : `cx`, `cy`, un simple `claude`, `codex` ou `grok`, tout ce qui est lancé via `omarchy agent`, et les scripts ou éditeurs qui trouvent le CLI sur `PATH`. Basculez avec `omarchy agent account use work` (et revenez avec `omarchy agent account use main`), ou dans le panneau en appuyant sur le numéro d'un compte puis sur `Enter` (ou en cliquant sur son bouton Use). Les sessions déjà en cours restent sur le compte avec lequel elles ont démarré. L'historique de conversation, les paramètres, les skills et les plugins sont partagés entre les comptes, donc `claude --continue` dans le même dossier reprend là où vous vous étiez arrêté sur le nouveau compte.

Avec plus d'un compte, le panneau affiche les limites de chaque compte côte à côte, avec le compte actif marqué. Par défaut, Omarchy vous notifie quand le compte actif dépasse 95% d'une limite, et cliquer sur la notification bascule vers le compte avec le plus de marge. Survolez la ligne d'un compte dans le panneau et cliquez sur l'Autoswitch qui apparaît à côté de Use (ou appuyez sur `m`), ou lancez `omarchy agent account mode auto`, pour qu'il bascule tout seul à la place ; tant qu'il est activé, Autoswitch prend la place de Use, et cliquer dessus à nouveau revient aux notifications. Ajoutez un nombre pour changer le seuil, comme dans `omarchy agent account mode auto 90`. Si chaque compte dépasse le seuil, vous en entendrez parler une fois, avec quel compte se libère en premier. Tant qu'un compte actif est à moins de 15 points de son seuil (80% par défaut), ses limites sont vérifiées toutes les trois minutes plutôt que toutes les 15.

`omarchy agent account list` affiche chaque compte et ses dernières limites, `omarchy agent account remove work` en oublie un, et `omarchy agent account rename primary Hey` en renomme un (ou cliquez sur le nom d'un compte dans le panneau). Ces commandes fonctionnent sur les comptes de votre agent par défaut ; pour atteindre l'autre fournisseur, nommez-le d'abord, comme dans `omarchy agent account use codex side`. La connexion que vous aviez déjà dans `~/.claude` ou `~/.codex` est le compte _Main_ et reste où elle est. Un compte laissé inutilisé pendant plus d'environ huit heures peut afficher _Sign-in required_ ; cliquez dessus pour reconnecter ce compte directement dans le panneau, ou démarrez une session dedans, ce qui rafraîchit la connexion tout seul. Les serveurs MCP que vous aviez quand un compte a été ajouté l'accompagnent, mais ceux que vous ajoutez plus tard avec `claude mcp add` n'atteignent que le compte dans lequel vous les avez ajoutés. Claude Desktop et les outils configurés avec un chemin absolu vers un binaire CLI ne suivent pas la bascule. Un `CLAUDE_CONFIG_DIR`, `CODEX_HOME` ou `GROK_HOME` explicite a priorité sur le compte sélectionné.

### Diagnostic des plantages

Omarchy surveille systemd-coredump pour les plantages de processus. Quand quelque chose fait un segfault, vous recevrez une notification "Process crashed" — cliquez dessus, et le plantage est confié à votre agent par défaut avec le skill diagnose-crash d'Omarchy, qui guide l'agent pour établir les faits à partir du core dump et décider si le plantage vaut la peine d'être signalé en amont. Vous pouvez aussi le lancer à la main contre n'importe quel PID de `coredumpctl list` avec `omarchy agent crash <pid>`.

La surveillance est activée par défaut. Désactivez-la sous _Trigger > Toggle > Crash Capture_ (ou avec `omarchy toggle crash-capture`) et les notifications s'arrêtent ; `omarchy agent crash <pid>` fonctionne toujours à la main.

Les plantages peuvent aussi être mis en sourdine un programme à la fois, ce que le diagnostic vous propose à la fin. `omarchy crash mute hyprland` arrête les notifications pour ce programme seulement, `omarchy crash mute hyprland off` les ramène, et `omarchy crash mute` seul liste ce que vous avez mis en sourdine. Il accepte le chemin du binaire aussi volontiers que son nom, donc `omarchy crash mute /usr/bin/hyprland` fait la même chose. Mettez entre guillemets un nom comportant un espace, comme dans `omarchy crash mute 'Some App'`. Tout le reste continue de notifier, et le programme mis en sourdine continue de planter — cela cache le rappel, cela ne répare rien.

### Applications de bureau

Le menu _Install > AI_ propose aussi quelques applications IA graphiques : l'application de bureau ChatGPT, l'application de bureau Claude (la bêta Linux d'Anthropic, avec les onglets Chat, Cowork et Claude Code), Grok Bot pour discuter avec les modèles de xAI, Hermes Desktop, OpenClaw et l'application de bureau Perplexity. Grok Bot est l'application de chat de bureau. L'agent de codage est la commande `grok`.

Hermes Desktop est celle qu'il faut connaître, parce qu'une machine a un seul Hermes, et c'est celui de l'application : Hermes n'est jamais installé que via l'application, et la commande `hermes` que l'agent par défaut exécute est celle de l'application. Choisir Hermes comme agent par défaut installe la même chose que l'entrée _Install > AI_ : le paquet, et un runtime Hermes sous `~/.hermes` configuré par l'installeur propre à Hermes, ce qui prend quelques minutes la première fois. Ce runtime est l'unique Hermes que la commande `hermes` du terminal, l'agent par défaut et l'application utilisent tous, et il se met à jour lui-même avec `hermes update` plutôt que d'attendre une version d'Omarchy. L'installer confie aussi à Hermes le thème Omarchy comme un skin nommé `omarchy`, que chaque surface Hermes suit quand vous changez de thème ; choisissez-en un autre dans les paramètres Appearance de Hermes ou avec `/skin` si vous préférez qu'il ne le fasse pas, et Omarchy laisse ce choix tranquille. Supprimer l'application sous _Remove > AI_ ferme d'abord Hermes, gateway comprise, emporte ce runtime avec lui, et conserve vos chats, vos mémoires et les skills que Hermes a écrits pour lui-même, sauf si vous lui dites le contraire : il demande, avec non par défaut, si ces données et vos paramètres de connexion doivent partir aussi.

L'expérience de bureau d'OpenClaw est son Control UI, qui s'ouvre comme une application web soutenue par sa propre gateway locale. OpenClaw vit dans `~/.openclaw` et se met à jour lui-même : utilisez le bouton "Update Gateway" du Control UI ou lancez `openclaw update`, et la gateway redémarre sur la nouvelle version. Omarchy choisit seulement la version à partir de laquelle une installation fraîche démarre. Supprimer OpenClaw sous _Remove > AI_ emporte le service de gateway et l'application avec lui, puis demande si `~/.openclaw` doit partir aussi, puisque cela contient vos chats et vos identifiants à côté d'OpenClaw lui-même et des runtimes de plugin qu'il télécharge ; le défaut le conserve, et réinstaller OpenClaw le récupère.

### LLM locaux

Omarchy recommande deux façons d'exécuter des modèles LLM locaux : LM Studio et Ollama. LM Studio fournit une interface GUI pour trouver des modèles à poids ouverts, les installer et les exécuter. C'est un excellent moyen de démarrer facilement. Ollama offre un CLI pour faire de même. Mais si vous débutez avec les modèles locaux, je commencerais par LM Studio. Vous pouvez installer l'un ou l'autre sous _Install > AI_ dans le Omarchy Menu.

### Le Skill Omarchy

Les skills d'agent aident l'IA à utiliser des outils spécifiques d'une manière spécifique, et Omarchy est livré avec un skill par défaut pour adapter le système. Comme peaufiner votre config Hyprland, ajuster la barre, ou même créer un nouveau thème de zéro. Il est lié par symlink dans les répertoires de skills pour Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` et chaque `~/.hermes/profiles/*/skills`), et l'emplacement générique `~/.agents/skills`, donc la plupart des harnesses le récupèrent automatiquement.

Mais vous devez traiter ce skill comme expérimental. Différents modèles l'utiliseront avec des effets différents. Il vaut mieux l'exécuter d'abord en mode plan, pour avoir une idée de ce que l'agent voudrait changer. Et ensuite, soyez prêt à annuler les changements ou même à invoquer `omarchy reinstall configs`, si l'agent met le bazar partout.
