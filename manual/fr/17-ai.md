# IA

Omarchy inclut des lanceurs pour les agents de codage ci-dessous sans en choisir un par défaut pour vous. Exécutez une commande pour installer son CLI lors de la première utilisation, puis authentifiez-vous lorsque vous y êtes invité. Hermes fait exception : rien n'est installé pour lui lors de la première utilisation, et le choisir installe Hermes Desktop, comme l'explique _Applications de bureau_ ci-dessous.

### Installation et mise à jour des agents

À l'exception de Hermes, ces agents utilisent l'installation paresseuse de mise : le premier lancement installe le CLI, et les lancements suivants le réutilisent. mise vérifie également si un agent installé a une nouvelle version au plus une fois toutes les quatre heures, juste avant son démarrage ou en arrière-plan à l'invite du shell. Si cette mise à jour échoue ou si vous êtes hors ligne, la version installée s'exécute. `omarchy update` met à jour les agents installés avec le reste d'Omarchy, et `mup` met à jour uniquement les outils gérés par mise.

Le programme de mise à jour propre à un agent, comme `claude update`, `codex update` ou un bouton de mise à jour dans une application, ne met pas à jour l'installation gérée par mise. `codex update` échoue, et `claude update` peut annoncer un succès tout en installant une copie séparée que mise ne suit pas. Si vous préférez utiliser l'installateur et le programme de mise à jour natifs d'un agent, ajoutez-le à `disable_tools` ; voir [Outils CLI préinstallés](18-development-tools.md#preinstalled-cli-tools).

Pour installer tous les outils paresseux configurés avant d'en avoir besoin, exécutez `mise install --include-lazy`. Cela inclut aussi les autres outils CLI par défaut d'Omarchy ainsi que les agents. Voir [Outils CLI préinstallés](18-development-tools.md#preinstalled-cli-tools) pour installer un seul outil ou utiliser votre propre installation.

`grok` est installé via le package `grok` officiel de mise, de la même manière que `claude` et `codex`. Exécutez `grok`, ou choisissez-le sous _Setup > Defaults > Agent_. Évitez l'installateur `curl | bash` sur x.ai. Ce chemin place une deuxième copie dans `~/.grok/bin`, l'ajoute au début de `PATH` et écrase le wrapper d'Omarchy.

`dsh` ouvre son interface navigateur sur `127.0.0.1:3080`, avec le répertoire de lancement comme espace de travail par défaut. Son interface navigateur n'accepte aucune invite de départ, donc `omarchy agent prompt` l'ouvre avec l'invite dans votre presse-papiers, à coller. Omarchy le démarre avec le préréglage d'autorisations sans approbation de DeepSeek. DeepSeek Harness envoie les journaux de session à DeepSeek lorsque vous utilisez son API de modèle officielle ; désactivez-le sous _Settings > General > Upload Session Log_ dans son interface navigateur. Les commentaires que vous lui envoyez sont également envoyés avec la session, sauf si vous le démarrez avec `DSH_TELEMETRY_MODE=DISABLED`.

### L'agent par défaut

Choisissez votre agent par défaut avec `omarchy default agent <name>` ou sous _Setup > Defaults > Agent_ dans le menu Omarchy (`Super + Space`). Si l'agent n'est pas encore installé, le choisir l'installe d'abord. Un Omarchy fraîchement installé vous invitera à faire ce choix avec une notification unique.

Choisir Claude tente également de configurer son extension de navigateur pour Chromium, Chrome, Brave, Brave Origin et Edge. La configuration de l'extension s'applique à tous les utilisateurs et peut demander votre mot de passe système ; annuler ou un échec d'installation de l'extension sélectionne et lance quand même Claude. Redémarrez votre navigateur, activez l'extension si vous y êtes invité, et connectez-vous à Claude pour terminer la connexion. Exécutez `/chrome` dans Claude pour vérifier la connexion. Firefox et Zen ne prennent pas en charge cette extension. Si Claude était déjà votre agent par défaut avant l'ajout de cette configuration, sélectionnez-le à nouveau pour installer l'extension.

Une fois votre choix fait, `Super + Shift + Ctrl + A` lance l'agent par défaut dans une fenêtre de terminal dédiée (ou affiche le sélecteur si vous n'avez pas encore choisi). Vous pouvez aussi le lancer directement sur une tâche avec `omarchy agent prompt "Review this project"`. Freebuff et DeepSeek Harness n'acceptent aucune invite de départ, donc ils s'ouvrent à la place avec l'invite dans votre presse-papiers, à coller. Les agents lancés de cette manière fonctionnent sans surveillance dans leurs modes respectifs ne pas s'arrêter pour demander, donc soyez prêt à ce qu'ils fassent vraiment des choses ! MiniMax Code n'a pas de tel mode pour ses sessions interactives, donc il demande les autorisations comme d'habitude. Et comme les agents refusent de mémoriser la confiance pour votre répertoire personnel, les lancements depuis `$HOME` démarrent à la place dans `~/Work`.

Il existe aussi des raccourcis de terminal : `a` exécute l'agent par défaut directement dans le terminal actuel, tandis que `c`, `cx` et `cy` démarrent directement OpenCode, Claude Code et Codex (là aussi dans leurs modes d'approbation automatique). Les changements de thème se synchronisent aussi avec les agents : Claude Code, Pi, OpenCode et Hermes (une fois qu'Omarchy l'a installé) suivent tous lorsque vous changez le thème d'Omarchy.

### Le panneau des agents

La barre supérieure comporte une icône d'agents. Avant d'avoir configuré un agent, son panneau vous guide pour vous connecter à Claude, Codex ou Grok, et le premier devient votre agent par défaut. Après cela, le panneau regroupe tous les abonnements sur une seule page : chaque agent et chaque compte avec son forfait, un indicateur pour chacune de ses limites de session de 5 heures et hebdomadaire avec le temps restant avant sa réinitialisation (survolez pour le pourcentage exact), ou le solde prépayé restant, sous une ligne qui fait défiler ce que vous avez utilisé sur l'ensemble, comme les tokens cette semaine et votre modèle le plus utilisé. Sous _Make something_, il propose des invites de démarrage pour un nouveau thème, plugin ou une nouvelle application qui confient la tâche à votre agent par défaut. Les applications sont construites de la même manière que Hype, Monologue et Omacut d'Omarchy, en C++ et Qt Quick, en suivant le skill d'agent omarchy-app, et le compilateur et les éléments Qt dont elles ont besoin sont installés. Claude Code, Codex, Grok, Kimi, Cursor et son allocation Grok Bot, GitHub Copilot, Muse, Antigravity, Kimchi et Devin sont pris en charge dès le départ avec leurs limites, et Hermes, Mistral Vibe et Qwen Code affichent leurs sessions et leurs tokens une fois que vous les avez utilisés. Les forfaits et clés de fournisseurs que vous utilisez via pi, omp ou opencode apparaissent aussi : OpenCode Zen et Go, le Z.ai GLM Coding Plan, Ollama Cloud, le MiniMax Token Plan et Synthetic avec leurs limites ; Fireworks, OpenRouter et DeepSeek avec leurs soldes prépayés ; et les modèles que vous exécutez sur votre propre matériel sous Local models. Chaque agent est compté une seule fois, sous l'entité qui le facture, quel que soit le nombre de harness par lesquels vous l'utilisez.

Cliquez avec le bouton gauche sur l'icône de la barre pour le panneau, cliquez avec le bouton droit pour lancer votre agent par défaut. Les relevés d'utilisation qui l'alimentent sont régénérés toutes les 15 minutes par `omarchy agent usage-update`, et le panneau peut même fusionner l'utilisation de vos autres machines via un dossier synchronisé. Voir le README sous `$OMARCHY_PATH/shell/plugins/agents/` pour tous les paramètres.

### Plusieurs abonnements

Si vous payez plusieurs forfaits Claude, Codex ou Grok — un Max personnel et un professionnel, par exemple — Omarchy peut tous les garder connectés et passer de l'un à l'autre. Ajoutez un abonnement avec le + dans le panneau des agents, qui vous guide directement sur place, ou avec `omarchy agent account add claude Work` (ou `codex`, ou `grok`). Il installe le CLI s'il est absent. Le premier compte pour un fournisseur se connecte via votre navigateur habituel, exactement là où le CLI cherche toujours. Tous les suivants se connectent via une fenêtre privée, afin que le compte auquel votre navigateur est déjà connecté ne soit pas récupéré par erreur ; connectez-vous là avec le compte que vous ajoutez, et fermez d'abord toute fenêtre privée déjà ouverte. Ne vous déconnectez jamais du CLI pour faire cela : se déconnecter révoque la connexion enregistrée, et ce compte devrait être ajouté à nouveau.

Pour copier vos connexions d'abonnement vers une autre machine Omarchy via SSH, exécutez `omarchy agent account copy user@laptop`. L'expéditeur fournit un récepteur temporaire lorsque la destination n'en a pas d'installé, afin que les machines Omarchy plus anciennes puissent recevoir des comptes sans mise à jour. Les récepteurs installés ont la priorité. Cela copie tous les abonnements Claude, Codex et Grok ; ajoutez des noms de fournisseurs pour les sélectionner, comme dans `omarchy agent account copy laptop claude`. Les noms de comptes et les ID de commande correspondent à la source, y compris les comptes déjà présents sur la destination. Les comptes de destination sans rapport reçoivent un suffixe numérique si leurs noms entrent en conflit, et les paramètres, skills, plugins et l'historique des conversations restent locaux à chaque machine.

Les identifiants de destination existants sont conservés. Un compte source déjà connecté là-bas voit son nom synchronisé sans remplacer ses identifiants ; les autres comptes sont ajoutés à côté. Pour remplacer les identifiants enregistrés pour les comptes correspondants, utilisez `omarchy agent account copy --replace laptop claude` après avoir quitté les sessions de ce compte sur la destination. Une destination neuve reçoit aussi le compte actif et les préférences de basculement de la source ; une destination établie conserve les siens.

Les identifiants voyagent via SSH et sont stockés dans des fichiers privés sur la destination, donc ne copiez que vers des machines de confiance. Il s'agit d'une copie unique, pas d'une synchronisation continue. Les tokens d'actualisation Codex peuvent être renouvelés par une autre machine, laissant une connexion copiée ayant besoin d'un renouvellement ; des connexions séparées restent le choix le plus fiable pour une utilisation simultanée sur plusieurs machines. Voir [le guide d'authentification des comptes de Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Un seul compte par fournisseur est actif, et chaque nouvelle session démarre avec lui : `cx`, `cy`, un simple `claude`, `codex` ou `grok`, tout ce qui est lancé via `omarchy agent`, et les scripts ou éditeurs qui trouvent le CLI sur `PATH`. Basculez avec `omarchy agent account use work` (et revenez avec `omarchy agent account use main`), ou dans le panneau en appuyant sur le numéro d'un compte puis sur `Enter` (ou en cliquant sur son bouton Use). Les sessions déjà en cours restent sur le compte avec lequel elles ont démarré. L'historique des conversations, les paramètres, les skills et les plugins sont partagés entre les comptes, donc `claude --continue` dans le même dossier reprend là où vous vous étiez arrêté sur le nouveau compte.

Avec plusieurs comptes, le panneau affiche les limites de chaque compte côte à côte, avec le compte actif marqué. Par défaut, Omarchy vous avertit lorsque le compte actif dépasse 95 % d'une limite, et cliquer sur la notification bascule vers le compte ayant le plus de marge. Survolez la ligne d'un compte dans le panneau et cliquez sur Autoswitch qui apparaît à côté de Use (ou appuyez sur `m`), ou exécutez `omarchy agent account mode auto`, pour qu'il bascule automatiquement à la place ; lorsqu'il est activé, Autoswitch prend la place de Use, et cliquer à nouveau dessus revient à la notification. Ajoutez un nombre pour changer le seuil, comme dans `omarchy agent account mode auto 90`. Si tous les comptes dépassent le seuil, vous serez averti une seule fois, avec le compte qui se libérera en premier. Lorsqu'un compte actif est à moins de 15 points de son seuil (80 % au réglage par défaut), ses limites sont vérifiées toutes les trois minutes plutôt que toutes les 15.

`omarchy agent account list` affiche tous les comptes et leurs dernières limites, `omarchy agent account remove work` oublie l'un d'eux, et `omarchy agent account rename primary Hey` renomme l'un d'eux (ou cliquez sur le nom d'un compte dans le panneau). Ces commandes fonctionnent sur les comptes de votre agent par défaut ; pour atteindre l'autre fournisseur, nommez-le d'abord, comme dans `omarchy agent account use codex side`. La connexion que vous aviez déjà dans `~/.claude` ou `~/.codex` est le compte _Main_ et reste à sa place. Un compte laissé inutilisé pendant plus d'environ huit heures peut afficher _Sign-in required_ ; cliquez dessus pour reconnecter ce compte directement dans le panneau, ou démarrez une session avec lui, ce qui actualise la connexion automatiquement. Les serveurs MCP que vous aviez lorsqu'un compte a été ajouté l'accompagnent, mais ceux que vous ajoutez plus tard avec `claude mcp add` n'atteignent que le compte dans lequel vous les avez ajoutés. Claude Desktop et les outils configurés avec un chemin absolu vers un binaire CLI ne suivent pas le basculement. Un `CLAUDE_CONFIG_DIR`, `CODEX_HOME` ou `GROK_HOME` explicite a la priorité sur le compte sélectionné.

### Diagnostic des plantages

Omarchy surveille systemd-coredump pour les plantages de processus. Lorsqu'un programme fait une erreur de segmentation, vous recevrez une notification « Process crashed » — cliquez dessus, et le plantage est transmis à votre agent par défaut avec le skill diagnose-crash d'Omarchy, qui guide l'agent pour établir les faits à partir du core dump et décider si le plantage mérite d'être signalé en amont. Vous pouvez aussi l'exécuter manuellement sur n'importe quel PID de `coredumpctl list` avec `omarchy agent crash <pid>`.

La surveillance est activée par défaut. Désactivez-la sous _Trigger > Toggle > Crash Capture_ (ou avec `omarchy toggle crash-capture`) et les notifications s'arrêtent ; `omarchy agent crash <pid>` fonctionne toujours manuellement.

Les plantages peuvent aussi être réduits au silence programme par programme, ce que le diagnostic vous propose à la fin. `omarchy crash mute hyprland` arrête les notifications pour ce programme uniquement, `omarchy crash mute hyprland off` les rétablit, et `omarchy crash mute` seul liste ce que vous avez mis en sourdine. Il accepte le chemin du binaire aussi volontiers que son nom, donc `omarchy crash mute /usr/bin/hyprland` fait la même chose. Mettez entre guillemets un nom contenant une espace, comme dans `omarchy crash mute 'Some App'`. Tout le reste continue de notifier, et le programme mis en sourdine plante toujours — cela masque le rappel, cela ne répare rien.

### Applications de bureau

Le menu _Install > AI_ propose aussi quelques applications d'IA graphiques : l'application de bureau ChatGPT, l'application de bureau Claude (la bêta Linux d'Anthropic, avec les onglets Chat, Cowork et Claude Code), Grok Bot pour discuter avec les modèles de xAI, Hermes Desktop, OpenClaw, l'application de bureau Perplexity et T3 Code. Grok Bot est l'application de chat de bureau. L'agent de codage est la commande `grok`.

Hermes Desktop est celle à connaître, car une machine a un seul Hermes, et c'est celui de l'application : Hermes n'est jamais installé que via l'application, et la commande `hermes` que l'agent par défaut exécute est celle de l'application. Choisir Hermes comme agent par défaut installe la même chose que l'entrée _Install > AI_ : le package, et un runtime Hermes sous `~/.hermes` configuré par l'installateur propre à Hermes, ce qui prend quelques minutes la première fois. Ce runtime est le seul Hermes que la commande `hermes` du terminal, l'agent par défaut et l'application utilisent tous, et il se met à jour lui-même avec `hermes update` plutôt que d'attendre une version d'Omarchy. L'installer confie aussi à Hermes le thème Omarchy comme skin nommé `omarchy`, que chaque surface Hermes suit lorsque vous changez de thème ; choisissez-en un autre dans les paramètres Appearance de Hermes ou avec `/skin` si vous préférez qu'il ne le fasse pas, et Omarchy laisse ce choix tranquille. Retirer l'application sous _Remove > AI_ ferme d'abord Hermes, gateway incluse, emporte ce runtime avec elle, et conserve vos discussions, vos mémoires et les skills que Hermes a écrits pour lui-même sauf si vous lui dites le contraire : il demande, avec non par défaut, si ces données et vos paramètres de connexion doivent aussi partir.

L'expérience de bureau d'OpenClaw est son Control UI, qui s'ouvre comme une application web adossée à sa propre gateway locale. OpenClaw vit dans `~/.openclaw` et se met à jour lui-même : utilisez le bouton « Update Gateway » du Control UI ou exécutez `openclaw update`, et la gateway redémarre sur la nouvelle version. Omarchy choisit uniquement la version avec laquelle une installation neuve démarre. Retirer OpenClaw sous _Remove > AI_ emporte le service gateway et l'application avec lui, puis demande si `~/.openclaw` doit aussi partir, car il contient vos discussions et vos identifiants avec OpenClaw lui-même et les runtimes de plugins qu'il télécharge ; le réglage par défaut le conserve, et réinstaller OpenClaw le retrouve.

T3 Code s'exécute depuis sa version AppImage officielle dans `~/.local/share/t3code` plutôt que depuis un package, donc il se met à jour lui-même. L'installer demande s'il faut démarrer sur le canal Stable ou Nightly ; changez plus tard dans les paramètres de T3 Code. Vos fils et paramètres vivent dans `~/.t3`, et retirer T3 Code sous _Remove > AI_ les emporte avec lui.

### Modèles locaux

Exécutez un modèle ouvert sur votre propre machine pour vos agents de codage. Vos invites et votre code restent sur la machine ; rien de ce qui est envoyé au modèle ne la quitte. Commencez avec :

```bash
omarchy agent local use best
```

Ou, dans le panneau des agents dans la barre supérieure, choisissez + puis Local AI, qui apparaît lorsqu'un modèle tient sur cette machine. La première fois, cela installe Podman, qui exécute les modèles. Omarchy choisit ensuite le modèle recommandé pour cette machine, le télécharge et le démarre. Attendez-vous à un téléchargement de plusieurs dizaines de Go et à ce que la majeure partie de la mémoire de la machine soit utilisée pendant l'exécution du modèle : Flash Next utilise environ 100 GiB avec son contexte complet de 256K. Si d'autres modèles occupent la mémoire dont il a besoin, il est configuré arrêté, prêt à démarrer une fois que vous en arrêtez un. Le modèle s'arrête à la déconnexion ; arrêtez-le vous-même lorsque vous avez besoin de la mémoire pour autre chose.

`omarchy agent local list` affiche les options et explique pourquoi certaines ne conviennent pas. Pour en configurer un autre, exécutez `omarchy agent local use <recipe>`. Aujourd'hui, `qwen3.8-flash-next-halogen` et `qwen3.8-27b-gufo` sont disponibles pour les machines Strix Halo de 128 GB. Les nouvelles recettes et recommandations arrivent avec `omarchy update`, via le package.

Chaque modèle que vous configurez a sa propre ligne dans le panneau des agents, à côté de vos abonnements : lecture pour le démarrer, pause pour l'arrêter et libérer sa mémoire, et le bouton terminal pour ouvrir votre agent dessus. Plusieurs peuvent fonctionner en même temps lorsqu'ils tiennent ensemble en mémoire ; si l'un ne tient pas, Omarchy indique quel modèle en cours d'exécution arrêter. Faites glisser les lignes pour les réordonner, et appuyez sur Delete sur une ligne sélectionnée pour retirer un modèle et son téléchargement.

Depuis la ligne de commande, `omarchy agent local start <recipe>` et `omarchy agent local stop <recipe>` font la même chose, `omarchy agent local status` affiche chaque modèle, et `omarchy agent --local` ouvre votre agent par défaut sur le dernier modèle que vous avez démarré (pi si votre agent par défaut ne peut pas utiliser un modèle local). Tout client compatible OpenAI peut aussi se connecter : `status` affiche l'adresse de chaque modèle (le premier est `http://127.0.0.1:11435/v1`), le nom de la recette est le modèle, et la clé se trouve dans `~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` supprime un modèle et les téléchargements qu'aucun autre modèle n'utilise.

Les runtimes tiers sont étiquetés avec leur éditeur. Omarchy exécute chaque modèle sans aucun accès réseau.

### LLM locaux

Omarchy recommande deux manières d'exécuter des modèles LLM locaux : LM Studio et Ollama. LM Studio fournit une interface GUI pour trouver des modèles à poids ouverts, les installer et les exécuter. C'est un excellent moyen de démarrer facilement. Ollama offre un CLI pour faire de même. Mais si vous débutez avec les modèles locaux, je commencerais avec LM Studio. Vous pouvez installer l'un ou l'autre sous _Install > AI_ dans le menu Omarchy.

### Le skill Omarchy

Les skills d'agent aident l'IA à utiliser des outils spécifiques d'une manière spécifique, et Omarchy est livré avec un skill par défaut pour adapter le système. Comme modifier votre configuration Hyprland, ajuster la barre, ou même créer un nouveau thème de zéro. Il est lié par lien symbolique dans les répertoires de skills pour Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` et chaque `~/.hermes/profiles/*/skills`), et l'emplacement générique `~/.agents/skills`, donc la plupart des harness le récupèrent automatiquement.

Mais vous devriez considérer ce skill comme expérimental. Différents modèles l'utiliseront avec des effets différents. Il vaut mieux l'exécuter d'abord en mode plan, afin d'avoir une idée de ce que l'agent voudrait changer. Et soyez ensuite prêt à annuler les changements ou même à invoquer `omarchy reinstall configs`, si l'agent met le bazar partout.
