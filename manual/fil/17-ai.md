### Pag-install at pag-update ng mga agent

Maliban sa Hermes at OpenClaw, ginagamit ng mga agent na ito ang lazy installation ng mise: ini-install ng unang paglunsad ang CLI, at muling ginagamit ito ng mga susunod na paglunsad. Sinusuri rin ng mise ang isang naka-install na agent para sa bagong release nang hindi hihigit sa isang beses bawat apat na oras, bago ito magsimula o sa background sa isang shell prompt. Kung mabigo ang update na iyon o offline ka, tatakbo ang naka-install na bersyon. Ina-update ng `omarchy update` ang mga naka-install na agent kasama ang iba pang bahagi ng Omarchy, at ina-update ng `mup` ang mga tool na pinamamahalaan ng mise lamang.

Hindi ina-update ng sariling updater ng isang agent, tulad ng `claude update`, `codex update`, o isang update button sa isang app, ang install na pinamamahalaan ng mise. Nabibigo ang `codex update`, at maaaring mag-ulat ng tagumpay ang `claude update` habang nag-i-install ng hiwalay na kopyang hindi sinusubaybayan ng mise. Kung mas gusto mong gamitin ang native installer at updater ng isang agent, idagdag ito sa `disable_tools`; tingnan ang [Mga paunang naka-install na CLI tool](18-development-tools.md#preinstalled-cli-tools).

Para i-install ang lahat ng naka-configure na lazy tool bago mo kailanganin ang mga ito, patakbuhin ang `mise install --include-lazy`. Kasama rito ang iba pang default na CLI tool ng Omarchy pati na rin ang mga agent. Tingnan ang [Mga paunang naka-install na CLI tool](18-development-tools.md#preinstalled-cli-tools) para sa pag-install ng isang tool o paggamit ng sarili mong installation.

Ini-install ang `grok` sa pamamagitan ng first-party na `grok` package ng mise, sa parehong paraan tulad ng `claude` at `codex`. Patakbuhin ang `grok`, o piliin ito sa ilalim ng _Agent > Harness_. Laktawan ang `curl | bash` installer sa x.ai. Naglalagay ang paraang iyon ng pangalawang kopya sa `~/.grok/bin`, inuuna ito sa `PATH`, at pinapatungan ang wrapper ng Omarchy.

Binubuksan ng `dsh` ang browser UI nito sa `127.0.0.1:3080`, na ang launch directory ang default workspace nito. Hindi tumatanggap ang browser UI nito ng starting prompt, kaya binubuksan ito ng `omarchy agent prompt` na nasa clipboard mo ang prompt para i-paste. Sinisimulan ito ng Omarchy gamit ang no-approval permission preset ng DeepSeek. Nag-a-upload ang DeepSeek Harness ng mga session log sa DeepSeek kapag ginagamit mo ang opisyal nitong model API; i-off iyon sa ilalim ng _Settings > General > Upload Session Log_ sa browser UI nito. Ang feedback na ipinapadala mo rito ay ina-upload din kasama ng session, maliban kung sisimulan mo ito gamit ang `DSH_TELEMETRY_MODE=DISABLED`.

### Ang default na agent

Piliin ang default agent mo gamit ang `omarchy default agent <name>` o sa ilalim ng _Agent > Harness_ sa Omarchy Menu (`Super + Space`). Kung hindi pa naka-install ang agent, i-install muna ito ng pagpili rito, at makakakuha rin ito ng sarili nitong launcher sa app launcher, sa tabi ng Agent. Aanyayahan ka ng isang bagong Omarchy na gawin ang pagpiling ito sa pamamagitan ng isang one-time na notification.

Sinusubukan din ng pagpili sa Claude na i-setup ang browser extension nito para sa Chromium, Chrome, Brave, Brave Origin, at Edge. Nalalapat ang setup ng extension sa lahat ng user at maaaring humingi ng system password mo; ang pagkansela o ang nabigong pag-install ng extension ay pipili at maglulunsad pa rin sa Claude. I-restart ang browser mo, i-enable ang extension kung sinabihan, at mag-sign in sa Claude para tapusin ang pagkonekta rito. Patakbuhin ang `/chrome` sa Claude para suriin ang koneksyon. Hindi sinusuportahan ng Firefox at Zen ang extension na ito. Kung Claude na ang default mo bago pa idinagdag ang setup na ito, piliin ito ulit para i-install ang extension.

Kapag nakapili ka na, ilulunsad ng `Super + Shift + Ctrl + A` ang default agent sa isang nakalaang terminal window (o ilalabas ang picker kung hindi ka pa nakakapili). Maaari mo rin itong ilunsad nang diretso sa isang gawain gamit ang `omarchy agent prompt "Review this project"`. Hindi tumatanggap ang Freebuff at DeepSeek Harness ng starting prompt, kaya magbubukas sila na nasa clipboard mo ang prompt para i-paste sa halip. Ang mga agent na inilunsad sa ganitong paraan ay tumatakbo nang walang bantay sa kani-kanilang don't-stop-to-ask mode, kaya maging handa na talagang may gagawin sila! Walang ganoong mode ang MiniMax Code para sa mga interactive session nito, kaya humihingi ito ng mga pahintulot gaya ng dati. At dahil tumatanggi ang mga agent na tandaan ang tiwala para sa home directory mo, ang mga paglunsad mula sa `$HOME` ay magsisimula sa `~/Work` sa halip.

May mga terminal shortcut din: pinapatakbo ng `a` ang default agent nang inline sa kasalukuyang terminal, habang sinisimulan ng `c`, `cx`, at `cy` ang OpenCode, Claude Code, at Codex nang diretso (muli sa kanilang mga auto-approving mode). Nagsi-sync din ang mga pagbabago ng tema sa mga agent: sumusunod ang Claude Code, Pi, OpenCode, at Hermes (kapag na-install na ito ng Omarchy) kapag nagpapalit ka ng tema ng Omarchy.

### Ang mga tagubilin ng agent mo

Ang mga personal na panuntunan para sa bawat agent ay nasa `~/.agents/AGENTS.md`, sa tabi ng mga shared skill sa `~/.agents/skills`. Buksan ito sa ilalim ng _Agent > Instructions_, na nagli-link din nito sa bawat harness na nag-iingat ng sarili nitong global file: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, ang `~/.copilot/copilot-instructions.md` ng Copilot, at iba pa. Binabasa ng Crush at Amp ang link na `~/.config/AGENTS.md`, habang direktang binabasa ng omp, Kimi, at DeepSeek Harness ang `~/.agents/AGENTS.md`. Ang pagpili ng default agent ay nagli-link din nito. Ang isang instructions file na mayroon ka na ay nagiging shared na file kung wala pa noon; kung hindi, iniingatan ito sa tabi ng link bilang `.bak`. Patakbuhin ang `omarchy agent instructions` para muling mag-link pagkatapos mag-install ng isa pang agent.

### Ang panel ng mga agent

May agents icon ang top bar. Bago ka pa nakapag-setup ng agent, gagabayan ka ng panel nito sa pag-sign in sa Claude, Codex, o Grok, at ang una ay magiging default agent mo. Pagkatapos niyon, inilalagay ng panel ang bawat subscription sa isang page: bawat agent at account kasama ang plan nito, isang meter para sa bawat 5-hour session at weekly limit nito kasama ang oras hanggang mag-reset ito (i-hover para sa eksaktong porsyento), o ang natitirang prepaid balance, sa ilalim ng isang linyang umiikot sa kung ano ang nagamit mo sa lahat ng mga ito, tulad ng mga token ngayong linggo at ang pinakamadalas mong gamiting modelo. Sa ilalim ng _Make something cool_ nag-aalok ito ng mga starter prompt para sa isang bagong tema, plugin, app, o laro na nagbibigay ng gawain sa default agent mo. Ang mga app ay binubuo sa paraang binuo ang sariling Hype, Monologue, at Omacut ng Omarchy, sa C++ at Qt Quick, na sumusunod sa omarchy-make-app agent skill, at naka-install na ang compiler at mga piraso ng Qt na kailangan nila. Ang mga laro ay iisang three.js page sa `~/Games/vibes`, na sumusunod sa omarchy-make-game agent skill, at lahat ay nagbubukas mula sa iisang Game Vibes launcher sa kasalukuyang tema; nilo-load nila ang three.js mula sa web, kaya kailangan nila ng koneksyon para magsimula. Saklaw agad ang Claude Code, Codex, Grok, Kimi, Cursor at ang Grok Bot allowance nito, GitHub Copilot, Muse, Antigravity, at Devin kasama ang kanilang mga limit, ang Kimchi kasama ang plan, prepaid credits, at spend budget nito, at ipinapakita ng Hermes, Mistral Vibe, at Qwen Code ang kanilang mga session at token kapag nagamit mo na sila. Lumalabas din ang mga provider plan at key na ginagamit mo sa pamamagitan ng pi, omp, o opencode: ang OpenCode Zen at Go, ang Z.ai GLM Coding Plan, Ollama Cloud, ang MiniMax Token Plan, at Synthetic kasama ang kanilang mga limit; ang OpenRouter at DeepSeek kasama ang kanilang mga prepaid balance; ang Fireworks kasama ang gastos nito sa nakalipas na 30 araw. Ang mga token mula sa mga modelong pinapatakbo mo sa sarili mong hardware ay nabibilang din sa mga kabuuan; ang mga modelo mismo ay may sariling panel, na inilalarawan sa ilalim ng [Mga local na modelo](#local-models). Bawat agent ay binibilang nang isang beses, sa ilalim ng kung sino man ang naniningil para rito, gaano man karaming harness mo ito patakbuhin.

I-left-click ang icon sa bar o pindutin ang `Super + Ctrl + X` para sa panel, i-right-click para ilunsad ang default agent mo, at i-middle-click para mag-refresh. Ang mga usage record sa likod nito ay muling ginagawa bawat 15 minuto ng `omarchy agent usage update`, at maaari pang pagsamahin ng panel ang usage mula sa iba mo pang machine sa pamamagitan ng isang naka-sync na folder. Tingnan ang README sa ilalim ng `$OMARCHY_PATH/shell/plugins/agents/` para sa buong mga setting.

### Maraming subscription

Kung nagbabayad ka para sa higit sa isang Claude, Codex, o Grok plan — isang personal na Max at isang pang-trabaho, halimbawa — maaaring panatilihin ng Omarchy na naka-sign in silang lahat at lumipat-lipat sa pagitan nila. Magdagdag ng subscription gamit ang + sa panel ng mga agent, na gagabay sa iyo roon mismo, o gamit ang `omarchy agent account add claude Work` (o `codex`, o `grok`). Ini-install nito ang CLI kung nawawala ito. Ang unang account para sa isang provider ay nag-sign in sa pamamagitan ng normal mong browser, mismo kung saan laging tumitingin ang CLI. Bawat isa pagkatapos niyon ay nag-sign in sa pamamagitan ng isang private window, kaya ang account na naka-sign in na sa browser mo ay hindi mapipili nang hindi sinasadya; mag-sign in doon bilang ang account na idinaragdag mo, at isara muna ang anumang private window na nakabukas mo na. Huwag kailanman mag-log out sa CLI para gawin ito: binabawi ng pag-log out ang naka-save na sign-in, at kailangang idagdag ulit ang account na iyon.

Para kopyahin ang mga subscription login mo sa isa pang Omarchy machine sa pamamagitan ng SSH, patakbuhin ang `omarchy agent account copy user@laptop`. Nagbibigay ang sender ng pansamantalang receiver kapag walang naka-install ang destination, kaya makakatanggap ang mas lumang mga Omarchy machine ng mga account nang walang update. Inuuna ang mga naka-install na receiver. Kinokopya nito ang lahat ng subscription ng Claude, Codex, at Grok; magdagdag ng mga pangalan ng provider para piliin ang mga ito, gaya ng sa `omarchy agent account copy laptop claude`. Ang mga pangalan ng account at command ID ay tumutugma sa source, kabilang ang mga account na naroon na sa destination. Ang mga hindi kaugnay na destination account ay makakatanggap ng numeric suffix kung magkasalungat ang kanilang mga pangalan, at ang mga setting, skill, plugin, at kasaysayan ng pag-uusap ay mananatiling local sa bawat machine.

Pinananatili ang mga umiiral na credential sa destination. Ang isang source account na naka-sign in na roon ay isi-sync ang pangalan nang hindi pinapalitan ang mga credential nito; ang ibang mga account ay idinaragdag sa tabi nito. Para palitan ang mga naka-save na credential para sa mga tumutugmang account, gamitin ang `omarchy agent account copy --replace laptop claude` pagkatapos isara ang mga session ng account na iyon sa destination. Ang isang bagong destination ay makakakuha rin ng active account at mga kagustuhan sa paglipat ng source; pinananatili ng isang matagal nang destination ang sarili nito.

Naglalakbay ang mga credential sa pamamagitan ng SSH at iniimbak sa mga pribadong file sa destination, kaya kumopya lamang sa mga machine na pinagkakatiwalaan mo. Ito ay isang one-time na kopya, hindi patuloy na synchronization. Ang mga Codex refresh token ay maaaring i-rotate ng ibang machine, na mag-iiwan sa isang nakopyang login na nangangailangan ng pag-renew; ang hiwalay na mga sign-in ay nananatiling pinaka-maaasahang pagpipilian para sa sabay-sabay na paggamit sa maraming machine. Tingnan ang [gabay sa authentication ng account ng Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Isang account bawat provider ang active, at bawat bagong session ay nagsisimula bilang ito: `cx`, `cy`, isang karaniwang `claude`, `codex`, o `grok`, anumang inilunsad sa pamamagitan ng `omarchy agent`, at mga script o editor na nakakahanap ng CLI sa `PATH`. Lumipat gamit ang `omarchy agent account use work` (at bumalik gamit ang `omarchy agent account use main`), o sa panel sa pamamagitan ng pagpindot sa numero ng isang account at pagkatapos ay `Enter` (o pag-click sa Use button nito). Lumilipat din ang mga tumatakbong Claude session, mula sa kanilang susunod na mensahe: bawat Claude session ay tumatakbo sa `~/.claude`, na laging naglalaman ng sign-in ng active account. Ang isang Claude session na sinimulan sa sariling folder ng isang account ng isang mas lumang Omarchy ay nag-iingat ng sign-in na iyon hanggang sa umalis ito, kaya pinapangalanan ng switch ang mga session na iyon at natatapos nang mag-isa kapag wala na sila. Ang mga tumatakbong Codex at Grok session ay mananatili sa account na pinagsimulan nila. Ang kasaysayan ng pag-uusap, mga setting, skill, at plugin ay ibinabahagi sa mga account, kaya ang `claude --continue` sa parehong folder ay magpapatuloy kung saan ka tumigil sa bagong account.

Sa higit sa isang account, ipinapakita ng panel ang mga limit ng bawat account nang magkatabi, na minarkahan ang active. Bilang default, inaabisuhan ka ng Omarchy kapag lumampas ang active account sa 95% ng isang limit, at ang pag-click sa notification ay lumilipat sa account na may pinakamaraming headroom. I-hover ang linya ng isang account sa panel at i-click ang Autoswitch na lalabas sa tabi ng Use (o pindutin ang `m`), o patakbuhin ang `omarchy agent account mode auto`, para lumipat ito nang mag-isa sa halip; habang naka-on ito, pumapalit ang Autoswitch sa Use, at ang pag-click dito ulit ay babalik sa pag-abiso. Magdagdag ng numero para baguhin ang threshold, gaya ng sa `omarchy agent account mode auto 90`. Kung ang bawat account ay lumampas sa threshold, maririnig mo ito nang isang beses, kasama kung aling account ang unang magkakaroon ng puwang. Habang ang isang active account ay nasa loob ng 15 puntos ng threshold nito (80% sa default), sinusuri ang mga limit nito bawat tatlong minuto sa halip na bawat 15.

Ipinapakita ng `omarchy agent account list` ang bawat account at ang pinakabagong mga limit nito, kinakalimutan ng `omarchy agent account remove work` ang isa, at binabago ng `omarchy agent account rename primary Hey` ang pangalan ng isa (o i-click ang pangalan ng isang account sa panel). Gumagana ang mga command na ito sa mga account ng default agent mo; para maabot ang ibang provider, pangalanan muna ito, gaya ng sa `omarchy agent account use codex side`. Ang login na mayroon ka na sa `~/.claude` o `~/.codex` ay ang _Main_ account. Ang sa Codex ay mananatili kung nasaan ito; ang sa Claude ay naghihintay sa sarili nitong folder habang may ibang account na active. Ang isang account na hindi nagamit nang higit sa mga walong oras ay maaaring magpakita ng _Sign-in required_; i-click ito para muling mag-sign in sa account na iyon mismo sa panel, o lumipat dito at magsimula ng session, na nagre-refresh ng sign-in nang mag-isa. Ang mga MCP server na idinaragdag mo gamit ang `claude mcp add` ay umaabot sa bawat Claude account, dahil lahat sila ay tumatakbo sa `~/.claude`; para sa Codex at Grok, ang mga server na mayroon ka nang idagdag ang isang account ay sumasama rito, ngunit ang mga susunod ay umaabot lamang sa account kung saan mo sila idinagdag. Nag-iingat ang Claude Desktop ng sarili nitong sign-in, at ang mga Codex o Grok tool na naka-configure na may absolute path patungo sa isang CLI binary ay hindi sumusunod sa paglipat. Ang isang tahasang `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, o `GROK_HOME` ay inuuna kaysa sa napiling account.

### Diagnosis ng crash

Binabantayan ng Omarchy ang systemd-coredump para sa mga pag-crash ng proseso. Kapag nakapili ka na ng default agent, anumang programa mo na mag-dump ng core ay magdadala ng notification na "Process crashed" — i-click ito, at ibibigay ang crash sa default agent mo kasama ang omarchy-diagnose-crash skill ng Omarchy, na gagabay sa agent sa pagtatatag ng mga katotohanan mula sa core dump at pagpapasya kung sulit bang iulat ang crash upstream. Maaari mo rin itong patakbuhin nang mano-mano laban sa anumang PID mula sa `coredumpctl list` gamit ang `omarchy agent crash <pid>`.

Naka-on ang pagbabantay bilang default. I-off ito sa ilalim ng _Trigger > Toggle > Crash Capture Off_ (o gamit ang `omarchy toggle crash-capture`) at hihinto ang mga notification; gumagana pa rin nang mano-mano ang `omarchy agent crash <pid>`.

Maaari ring patahimikin ang mga crash nang paisa-isa bawat programa, na siyang iniaalok sa iyo ng diagnosis sa dulo. Pinipigilan ng `omarchy crash mute hyprland` ang mga notification para sa programang iyon lamang, ibinabalik sila ng `omarchy crash mute hyprland off`, at inililista ng `omarchy crash mute` nang mag-isa kung ano ang na-mute mo. Tumatanggap ito ng path ng binary nang kasing saya ng pangalan nito, kaya ginagawa ng `omarchy crash mute /usr/bin/hyprland` ang parehong bagay. Mag-quote ng pangalang may espasyo, gaya ng sa `omarchy crash mute 'Some App'`. Lahat ng iba pa ay mag-aabiso pa rin, at magka-crash pa rin ang na-mute na programa — itinatago nito ang paalala, hindi nito inaayos ang anuman.

### Mga desktop app

May dala ring ilang graphical AI app ang _Install > AI_ menu: Amp Desktop, Antigravity Desktop, ang ChatGPT desktop app, ang Claude desktop app (ang Linux beta ng Anthropic, na may mga tab na Chat, Cowork, at Claude Code), Grok Bot para sa pakikipag-chat sa mga modelo ng xAI, Herdr Desktop, Hermes Desktop, OpenClaw, ang Perplexity desktop app, at T3 Code. Ang Grok Bot ay ang desktop chat app. Ang coding agent ay ang `grok` command.

Ang Hermes Desktop ang dapat mong malaman, dahil iisa lang ang Hermes ng isang machine, at pag-aari ito ng app: ini-install lamang ang Hermes sa pamamagitan ng app, at ang `hermes` command na pinapatakbo ng default agent ay sa app. Ang pagpili sa Hermes bilang default agent ay nag-i-install ng parehong bagay na ini-install ng _Install > AI_ entry: ang package, at isang Hermes runtime sa ilalim ng `~/.hermes` na sine-setup ng sariling installer ng Hermes, na tumatagal ng ilang minuto sa unang pagkakataon. Ang runtime na iyon ang iisang Hermes na ginagamit ng terminal na `hermes` command, ng default agent at ng app, at ina-update nito ang sarili gamit ang `hermes update` sa halip na maghintay ng Omarchy release. Ang pag-install nito ay nagbibigay din sa Hermes ng tema ng Omarchy bilang isang skin na pinangalanang `omarchy`, na sinusunod ng bawat Hermes surface habang nagpapalit ka ng mga tema; pumili ng iba sa ilalim ng Appearance settings ng Hermes o gamit ang `/skin` kung ayaw mo niyon, at hahayaan ng Omarchy ang pagpipiliang iyon. Ang pag-alis ng app sa ilalim ng _Remove > AI_ ay nagsasara muna sa Hermes, kasama ang gateway, isinasama ang runtime na iyon, at pinananatili ang iyong mga chat, alaala, at ang mga skill na isinulat ng Hermes para sa sarili nito maliban kung sasabihin mo ang kabaligtaran: nagtatanong ito, na ang default ay hindi, kung dapat ding alisin ang data na iyon at ang iyong mga connection setting.

Ang desktop experience ng OpenClaw ay ang Control UI nito, na nagbubukas bilang isang web app na sinusuportahan ng sarili nitong local gateway. Nakatira ang OpenClaw sa `~/.openclaw` at ina-update ang sarili nito: gamitin ang "Update Gateway" button ng Control UI o patakbuhin ang `openclaw update`, at magre-restart ang gateway sa bagong bersyon. Pinipili lamang ng Omarchy ang release kung saan magsisimula ang isang bagong install. Maaari ring maging default agent mo ang OpenClaw: ang pagpili rito sa ilalim ng _Agent > Harness_ ay nagse-setup ng parehong kopya sa `~/.openclaw`, at binubuksan ng agent ang terminal UI ng OpenClaw na nakakabit sa gateway nito. Ang pag-alis ng OpenClaw sa ilalim ng _Remove > AI_ ay isinasama ang gateway service at ang app at pagkatapos ay nagtatanong kung dapat ding alisin ang `~/.openclaw`, dahil naroon ang iyong mga chat at credential kasama ang OpenClaw mismo at ang mga plugin runtime na dina-download nito; pinananatili ito ng default, at ang muling pag-install ng OpenClaw ay kukunin itong muli.

Ang Herdr Desktop ay ang [Herdr](https://herdr.dev) desktop app: mga space, tab, at pane ng mga terminal at coding agent na patuloy na tumatakbo sa core nito kapag isinara mo ang window. Nagmumula ito sa sariling installer ng Herdr sa halip na sa isang package, kaya nakatira ito sa `~/.local/share/herdr-app`, isinasama ang core nito sa `~/.local/bin/herdr-core` kapag wala ka pa nito, at ina-update ang sarili nito pareho. Nakaupo ito sa tabi ng `herdr` command na ibinibigay ng Omarchy sa `Super + Ctrl + Return` sa halip na palitan ito, at nakukuha ang mga direct key ng command na iyon: hinahati ng `Alt + Return` at `Alt + Shift + Return` ang isang pane pababa o pakanan, isinasara ito ng `Alt + Escape`, lumilipat sa pagitan ng mga pane ang `Ctrl + Alt + Arrow`, pumipili ng tab ang `Alt + 1..9` at `Alt + Left/Right`, at lumilipat sa pagitan ng mga space ang `Alt + Up/Down`. Pumipili ng space ang `Ctrl + 1..9` at humahakbang sa mga agent ang `Alt + Shift + Up/Down`. Ang mga `Ctrl + Space` prefix key ay mananatiling pang-terminal lamang, dahil hindi kayang hawakan ng app ang isang karaniwang Ctrl key para sa isang sequence. Isinusulat ito ng Omarchy sa `~/.config/herdr-app/keys.json`, at ibinabalik sila ng `omarchy-refresh-herdr-app`. Ang pag-install nito ay pumipili ng Omarchy theme ng Herdr, na susunod sa tema ng Omarchy mo mula noon. Nag-iingat ang Herdr ng isang tema para sa light mode at isa para sa dark, kaya pagkatapos lumipat sa pagitan ng dark at light na tema ng Omarchy, piliin muli ang Omarchy sa theme picker ng Herdr nang isang beses pa para sa ibang mode.

Tumatakbo ang T3 Code mula sa opisyal nitong AppImage release sa `~/.local/share/t3code` sa halip na mula sa isang package, kaya ina-update nito ang sarili. Nagtatanong ang pag-install nito kung magsisimula sa Stable o Nightly channel; lumipat mamaya sa mga setting ng T3 Code. Nakatira ang iyong mga thread at setting sa `~/.t3`, at ang pag-alis ng T3 Code sa ilalim ng _Remove > AI_ ay isinasama sila.

### Mga local na modelo

Magpatakbo ng open model sa sarili mong machine para sa iyong mga coding agent. Mananatili sa machine ang iyong mga prompt at code; walang ipinapadala sa modelo ang umaalis dito. Magsimula sa:

```bash
omarchy models use best text
```

Sine-setup niyon ang pinakamahusay na text model para sa machine na ito, ang uri na ginagamit ng iyong mga agent. Ang mga image, video at music model ay may sarili nilang pinakamahusay: `omarchy models use best image`, `video` o `music`. Patakbuhin ang `omarchy models use best` para makita ang pinili ng bawat uri para sa machine na ito.

O buksan ang local models panel mula sa sparkles icon nito sa top bar, sa tabi ng agents icon, o gamit ang Super + Ctrl + Alt + X, at piliin ang +. Lumalabas ang icon kapag may modelong kasya sa machine na ito. Ang Podman, na nagpapatakbo ng mga modelo, ay kasama ng Omarchy, gayundin ang NVIDIA's container toolkit sa isang NVIDIA machine, na nagbibigay sa kanila ng GPU; kung nawawala ang alinman, ini-install ito ng unang setup. Pagkatapos ay pipili ang Omarchy ng inirerekomendang modelo para sa machine na ito, dina-download ito, at sinisimulan ito. Asahan ang download na sampu-sampung GB at ang karamihan ng memory ng machine ay ginagamit habang tumatakbo ang modelo: gumagamit ang Flash Next ng mga 100 GiB kasama ang buong 256K context nito. Kung hawak ng ibang mga modelo ang memory na kailangan nito, sine-setup itong nakahinto, handang magsimula kapag huminto ka ng isa. Hihinto ang modelo sa pag-logout; ihinto mo ito mismo kapag kailangan mo ang memory para sa ibang bagay.

Ipinapakita ng `omarchy models list` ang mga opsyon at ipinaliliwanag kung bakit hindi kasya ang ilan. Para mag-setup ng isa pa, patakbuhin ang `omarchy models use <recipe>`. Ngayon, ang `qwen3.8-flash-next-gufo` at `qwen3.8-27b-gufo` ay available para sa mga 128 GB Strix Halo machine; ang 27B ay gumagamit ng mga 40 GiB, kaya nag-iiwan ito ng puwang para sa iba pang gawain. Sa isang 64 GB laptop na may Intel's Arc B390, tumatakbo ang `qwen3.6-35b-a3b-llamacpp` sa mga 30 GiB. Dumarating ang mga bagong recipe at rekomendasyon kasama ng `omarchy update`, sa pamamagitan ng package.

Bawat modelong sine-setup mo ay nakakakuha ng sarili nitong linya sa local models panel: i-play para simulan ito, i-pause para ihinto ito at palayain ang memory nito, at ang terminal button para buksan ang agent mo rito. Sa itaas, ipinapakita ng isang bar kung paano nahahati ang memory ng machine sa pagitan ng Omarchy mismo (ang system at iyong mga app), bawat tumatakbong modelo, at kung ano ang libre. Ituro ang isang nakahintong modelo at ipapakita ng bar kung kasya ito, o kung gaano ito kulang. Marami ang maaaring tumakbo nang sabay kapag kasya sila sa memory nang magkasama; kung hindi kasya ang isa, sasabihin ng Omarchy kung aling tumatakbong modelo ang ihihinto. I-drag ang mga linya sa kanilang logo para muling ayusin sila, at pindutin ang Delete sa isang napiling linya para alisin ang isang modelo at ang download nito.

Bawat modelong sine-setup mo ay nakakakuha rin ng sarili nitong entry sa app launcher, sa ilalim ng pangalan ng modelo at kasama ang logo ng gumawa nito, sa paraang nagdaragdag ng isa ang pag-sign in sa Claude, Codex o Grok. Binubuksan nito ang agent mo sa modelong iyon, at sinisimulan muna ang modelo kung hindi ito tumatakbo: ipinapakita ng terminal na naglo-load ito at ibibigay sa agent kapag handa na ito. Ang pag-alis ng isang modelo ay nag-aalis ng entry nito.

Hindi lahat ng modelo ay para sa coding. Ang mga image, video at music model ay nagbubukas sa Fantasi sa halip, ang app ng Omarchy para sa paggawa ng mga larawan, video at musika gamit ang isang modelong tumatakbo sa machine na ito, mula sa kanilang launcher entry at mula sa kanilang linya sa local models panel.

Patuloy na tumatakbo ang isang modelo nang eksakto kung paano ito sine-setup, kaya hindi kailanman nire-restart ng isang Omarchy update ang isa sa ilalim ng iyong mga agent. Kapag may mas bagong runtime o mas bagong weights ang Omarchy para sa isang modelong sine-setup mo, ipinapakita ng linya nito ang isang update button: pindutin ito at muling sine-setup ang modelo sa background, dina-download lamang kung ano ang nagbago, at magre-restart sa bagong bersyon. Ang isang modelong nakahinto ay mananatiling nakahinto. Ginagawa ng `omarchy models update` ang pareho para sa bawat modelo mula sa isang terminal.

Mula sa command line, ginagawa ng `omarchy models start <recipe>` at `omarchy models stop <recipe>` ang pareho, ipinapakita ng `omarchy models status` ang bawat modelo, at binubuksan ng `omarchy agent --local` ang default agent mo sa huling modelong sinimulan mo. Maaaring gumamit ng isa ang pi, OpenCode at Qwen Code; sa anumang ibang default ay nagbubukas ito sa pi, o sa OpenCode kung wala kang pi. Inililista rin ng pi ang bawat modelong sine-setup mo, at ang mga nasa machine na ipinares mo, sa sarili nitong model picker, kaya naaabot din sila ng karaniwang `pi`. Maaari ring kumonekta ang anumang OpenAI-compatible client: ipinapakita ng `status` ang address ng bawat modelo (ang una ay `http://127.0.0.1:11435/v1`), ang recipe name ang modelo, at ang key ay nasa `~/.config/omarchy/agent-local/key`.

Binubura ng `omarchy models remove <recipe>` ang isang modelo at ang mga download na hindi ginagamit ng ibang modelo.

Ang mga third-party runtime ay nilagyan ng label ng kanilang publisher. Pinapatakbo ng Omarchy ang bawat modelo nang walang network access.

### Mga local na LLM

Inirerekomenda ng Omarchy ang dalawang paraan ng pagpapatakbo ng mga local LLM model: LM Studio at Ollama. Nagbibigay ang LM Studio ng GUI interface para sa paghahanap ng mga open-weight model, pag-install sa kanila, at pagpapatakbo sa kanila. Mahusay itong paraan para madaling makapagsimula. Nag-aalok ang Ollama ng CLI para gawin din iyon. Ngunit kung bago ka sa mga local model, magsisimula ako sa LM Studio. Maaari mong i-install ang alinman sa ilalim ng _Install > AI_ sa Omarchy Menu.

### Ang mga skill ng Omarchy

Tinutulungan ng mga agent skill ang AI na gumamit ng mga partikular na tool sa isang partikular na paraan, at may pito nito ang Omarchy. Sinasaklaw ng omarchy skill ang pag-aangkop ng system, tulad ng pag-tweak ng Hyprland config mo o pag-aadjust ng bar. Sinasaklaw ng omarchy-make-theme, omarchy-make-plugin, omarchy-make-app, at omarchy-make-game ang paggawa ng bagong bagay, sinasaklaw ng omarchy-contribute ang pag-uulat ng bug o pagpapadala ng fix upstream, at ginagawa ng omarchy-diagnose-crash ang pagdaan sa core dump ng isang crash. Naka-symlink sila sa mga skill directory para sa Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` at bawat `~/.hermes/profiles/*/skills`), at ang generic na lokasyong `~/.agents/skills`, kaya awtomatikong nakukuha sila ng karamihan sa mga harness. Ang isang skill folder mo na may parehong pangalan ay inuuna.

Ngunit dapat mong ituring ang mga skill na ito bilang eksperimental. Gagamitin sila ng iba't ibang modelo sa iba't ibang epekto. Pinakamainam na tumakbo muna sa plan mode, para magkaroon ka ng ideya kung ano ang gustong baguhin ng agent. At pagkatapos ay maging handang i-rollback ang mga pagbabago o kahit tawagin ang `omarchy reinstall configs`, kung guguluhin ng agent ang lahat.
