# AI

Kasama sa Omarchy ang mga launcher para sa mga coding agent sa ibaba nang hindi pumipili ng default para sa iyo. Magpatakbo ng command para mai-install ang CLI nito sa unang paggamit, pagkatapos ay mag-authenticate kapag sinabihan. Ang Hermes at OpenClaw ang mga exception: walang ini-install para sa kanila sa pamamagitan ng mise, at ang pagpili sa alinman ay nagse-set up ng sarili nitong self-updating na kopya, gaya ng ipinapaliwanag ng _Mga desktop app_ sa ibaba.

### Pag-install at pag-update ng mga agent

Maliban sa Hermes at OpenClaw, ginagamit ng mga agent na ito ang lazy installation ng mise: ini-install ng unang paglulunsad ang CLI, at muling ginagamit ito ng mga susunod na paglulunsad. Sinusuri rin ng mise ang isang naka-install na agent para sa bagong release nang hindi hihigit sa isang beses bawat apat na oras, bago ito magsimula o sa background sa isang shell prompt. Kung mabigo ang update na iyon o offline ka, tatakbo ang naka-install na bersyon. Ina-update ng `omarchy update` ang mga naka-install na agent kasama ang natitirang bahagi ng Omarchy, at ina-update naman ng `mup` ang mga tool na pinamamahalaan ng mise lamang.

Hindi ina-update ng sariling updater ng isang agent, gaya ng `claude update`, `codex update`, o isang update button sa isang app, ang install na pinamamahalaan ng mise. Nabibigo ang `codex update`, at maaaring mag-ulat ng tagumpay ang `claude update` habang nag-i-install ng hiwalay na kopya na hindi sinusubaybayan ng mise. Kung mas gusto mong gamitin ang native installer at updater ng isang agent, idagdag ito sa `disable_tools`; tingnan ang [Mga paunang naka-install na CLI tool](18-development-tools.md#preinstalled-cli-tools).

Para mai-install ang lahat ng naka-configure na lazy tool bago mo kailanganin ang mga ito, patakbuhin ang `mise install --include-lazy`. Kasama rito ang iba pang default na CLI tool ng Omarchy pati ang mga agent. Tingnan ang [Mga paunang naka-install na CLI tool](18-development-tools.md#preinstalled-cli-tools) para sa pag-install ng isang tool o paggamit ng sarili mong installation.

Ini-install ang `grok` sa pamamagitan ng first-party `grok` package ng mise, sa parehong paraan gaya ng `claude` at `codex`. Patakbuhin ang `grok`, o piliin ito sa ilalim ng _Agent > Harness_. Laktawan ang `curl | bash` installer sa x.ai. Naglalagay ang path na iyon ng pangalawang kopya sa `~/.grok/bin`, inuuna ito sa `PATH`, at ino-overwrite ang wrapper ng Omarchy.

Binubuksan ng `dsh` ang browser UI nito sa `127.0.0.1:3080`, na ang launch directory ang default workspace nito. Walang starting prompt ang browser UI nito, kaya binubuksan ito ng `omarchy agent prompt` na nasa clipboard mo ang prompt para i-paste. Sinisimulan ito ng Omarchy gamit ang no-approval permission preset ng DeepSeek. Ina-upload ng DeepSeek Harness ang mga session log sa DeepSeek kapag ginamit mo ang official model API nito; i-off iyon sa ilalim ng _Settings > General > Upload Session Log_ sa browser UI nito. Ang feedback na ipinapadala mo rito ay ina-upload din kasama ng session, maliban kung sisimulan mo ito gamit ang `DSH_TELEMETRY_MODE=DISABLED`.

### Ang default na agent

Piliin ang default mong agent gamit ang `omarchy default agent <name>` o sa ilalim ng _Agent > Harness_ sa Omarchy Menu (`Super + Space`). Kung hindi pa naka-install ang agent, i-install muna ito ng pagpili rito, at makakakuha rin ito ng sarili nitong launcher sa app launcher, katabi ng Agent. Aanyayahan ka ng bagong Omarchy na gawin ang pagpiling ito gamit ang isang one-time na notification.

Sinusubukan din ng pagpili sa Claude na i-set up ang browser extension nito para sa Chromium, Chrome, Brave, Brave Origin, at Edge. Nalalapat ang extension setup sa lahat ng user at maaaring humingi ng system password mo; pipiliin at ilulunsad pa rin ang Claude kahit kanselahin mo o mabigo ang pag-install ng extension. I-restart ang browser mo, i-enable ang extension kung sabihan, at mag-sign in sa Claude para tapusin ang pagkonekta rito. Patakbuhin ang `/chrome` sa Claude para suriin ang koneksyon. Hindi sinusuportahan ng Firefox at Zen ang extension na ito. Kung default mo na ang Claude bago idinagdag ang setup na ito, piliin itong muli para mai-install ang extension.

Kapag nakapili ka na, ilulunsad ng `Super + Shift + Ctrl + A` ang default na agent sa isang nakalaang terminal window (o ilalabas ang picker kung hindi ka pa nakakapili). Maaari mo rin itong ilunsad diretso sa isang task gamit ang `omarchy agent prompt "Review this project"`. Walang starting prompt ang Freebuff at DeepSeek Harness, kaya magbubukas sila na nasa clipboard mo ang prompt para i-paste sa halip. Ang mga agent na inilunsad sa ganitong paraan ay tumatakbo nang walang nag-aasikaso sa kani-kanilang don't-stop-to-ask mode, kaya maghanda kang talagang may gagawin sila! Walang ganoong mode ang MiniMax Code para sa mga interactive session nito, kaya humihingi ito ng mga permission gaya ng dati. At dahil tumatanggi ang mga agent na tandaan ang trust para sa home directory mo, ang mga paglulunsad mula sa `$HOME` ay nagsisimula sa `~/Work` sa halip.

May mga terminal shortcut din: pinapatakbo ng `a` ang default na agent nang inline sa kasalukuyang terminal, habang sinisimulan naman ng `c`, `cx`, at `cy` ang OpenCode, Claude Code, at Codex nang direkta (muli sa kanilang mga auto-approving mode). Nagsi-sync din ang mga pagbabago ng theme sa mga agent: sumusunod ang Claude Code, Pi, OpenCode, at Hermes (kapag na-install na ito ng Omarchy) kapag nagpalit ka ng Omarchy theme.

### Ang mga instruction mo para sa agent

Ang mga personal na panuntunan para sa bawat agent ay nasa `~/.agents/AGENTS.md`, katabi ng mga shared skill sa `~/.agents/skills`. Buksan ito sa ilalim ng _Agent > Instructions_, na nagli-link din nito sa bawat harness na may sarili nitong global file: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, ang `~/.copilot/copilot-instructions.md` ng Copilot, at iba pa. Binabasa ng Crush at Amp ang link na `~/.config/AGENTS.md`, habang direktang binabasa ng omp, Kimi, at DeepSeek Harness ang `~/.agents/AGENTS.md`. Ang pagpili ng default na agent ay nagli-link din nito. Ang instructions file na mayroon ka na ay nagiging shared na file kung wala pa noon; kung hindi, itatago ito sa tabi ng link bilang `.bak`. Patakbuhin ang `omarchy agent instructions` para muling i-link pagkatapos mag-install ng isa pang agent.

### Ang panel ng mga agent

May agents icon ang top bar. Bago ka pa mag-set up ng agent, gagabayan ka ng panel nito sa pag-sign in sa Claude, Codex, o Grok, at ang una ay magiging default agent mo. Pagkatapos niyon, inilalagay ng panel ang bawat subscription sa isang page: bawat agent at account kasama ang plan nito, isang meter para sa bawat 5-hour session at weekly limit nito kasama ang oras hanggang mag-reset ito (i-hover para sa eksaktong porsyento), o ang natitirang prepaid balance, sa ilalim ng isang linya na umiikot sa kung ano ang nagamit mo sa lahat ng ito, gaya ng mga token ngayong linggo at ang pinakamadalas mong ginamit na model. Sa ilalim ng _Make something cool_ nag-aalok ito ng mga starter prompt para sa bagong theme, plugin, app, o game na nagbibigay ng task sa default agent mo. Ang mga app ay ginagawa sa paraang ginawa ang sariling Hype, Monologue, at Omacut ng Omarchy, sa C++ at Qt Quick, na sumusunod sa omarchy-make-app agent skill, at naka-install na ang compiler at mga piraso ng Qt na kailangan nila. Ang mga game ay isang three.js page sa `~/Games/vibes`, na sumusunod sa omarchy-make-game agent skill, at lahat ay nagbubukas mula sa isang Game Vibes launcher sa kasalukuyang theme; nilo-load nila ang three.js mula sa web, kaya kailangan nila ng koneksyon para magsimula. Saklaw agad ang Claude Code, Codex, Grok, Kimi, Cursor at ang Grok Bot allowance nito, GitHub Copilot, Muse, Antigravity, at Devin kasama ang kanilang mga limit, ang Kimchi kasama ang plan nito, prepaid credits, at spend budgets, at ipinapakita ng Hermes, Mistral Vibe, at Qwen Code ang kanilang mga session at token kapag nagamit mo na sila. Lumalabas din ang mga provider plan at key na ginagamit mo sa pamamagitan ng pi, omp, o opencode: OpenCode Zen at Go, ang Z.ai GLM Coding Plan, Ollama Cloud, ang MiniMax Token Plan, at Synthetic kasama ang kanilang mga limit; OpenRouter at DeepSeek kasama ang kanilang prepaid balances; Fireworks kasama ang gastos nito sa nakalipas na 30 araw. Nabibilang din sa mga kabuuan ang mga token mula sa mga model na pinapatakbo mo sa sarili mong hardware; ang mga model mismo ay may sarili nilang panel, na inilalarawan sa ilalim ng [Mga local na model](#local-models). Bawat agent ay binibilang nang isang beses, sa ilalim ng kung sino ang naniningil para rito, gaano man karaming harness ang pagdaanan mo rito.

I-left-click ang bar icon o pindutin ang `Super + Ctrl + X` para sa panel, i-right-click para ilunsad ang default agent mo, at i-middle-click para mag-refresh. Ang mga usage record sa likod nito ay muling ginagawa bawat 15 minuto ng `omarchy agent usage update`, at maaari pang pagsamahin ng panel ang usage mula sa iba mo pang machine sa pamamagitan ng isang synced folder. Tingnan ang README sa ilalim ng `$OMARCHY_PATH/shell/plugins/agents/` para sa buong settings.

### Maraming subscription

Kung nagbabayad ka para sa higit sa isang Claude, Codex, o Grok plan — isang personal na Max at isang pang-trabaho, halimbawa — maaaring manatiling naka-sign in ang lahat ng ito sa Omarchy at lumipat-lipat sa pagitan nila. Magdagdag ng subscription gamit ang + sa panel ng mga agent, na gagabay sa iyo roon mismo, o gamit ang `omarchy agent account add claude Work` (o `codex`, o `grok`). Ini-install nito ang CLI kung nawawala ito. Ang unang account para sa isang provider ay nagsa-sign in sa pamamagitan ng normal mong browser, mismo kung saan laging tumitingin ang CLI. Bawat kasunod ay nagsa-sign in sa pamamagitan ng private window, para hindi aksidenteng makuha ang account na naka-sign in na sa browser mo; mag-sign in doon bilang account na idinaragdag mo, at isara muna ang anumang private window na nakabukas mo na. Huwag kailanman mag-log out sa CLI para gawin ito: binabawi ng pag-log out ang naka-save na sign-in, at kailangang idagdag muli ang account na iyon.

Para kopyahin ang mga subscription login mo sa isa pang Omarchy machine sa pamamagitan ng SSH, patakbuhin ang `omarchy agent account copy user@laptop`. Nagbibigay ang sender ng pansamantalang receiver kapag walang naka-install ang destination, kaya makakatanggap ng mga account ang mas lumang Omarchy machine nang walang update. Inuuna ang mga naka-install na receiver. Kinokopya nito ang lahat ng subscription ng Claude, Codex, at Grok; magdagdag ng mga pangalan ng provider para piliin sila, gaya ng `omarchy agent account copy laptop claude`. Tumutugma ang mga pangalan ng account at command ID sa source, kabilang ang mga account na naroon na sa destination. Makakatanggap ng numeric suffix ang hindi kaugnay na destination account kung magkasalungat ang kanilang mga pangalan, at nananatiling local sa bawat machine ang settings, skills, plugins, at conversation history.

Pananatilihin ang mga umiiral na destination credential. Ang source account na naka-sign in na roon ay isi-sync ang pangalan nito nang hindi pinapalitan ang mga credential nito; ang ibang mga account ay idinaragdag sa tabi nito. Para palitan ang mga naka-save na credential para sa magkatugmang account, gamitin ang `omarchy agent account copy --replace laptop claude` pagkatapos isara ang mga session ng account na iyon sa destination. Makukuha rin ng bagong destination ang active account at switching preferences ng source; pinapanatili ng matagal nang destination ang sarili nito.

Naglalakbay ang mga credential sa pamamagitan ng SSH at nakaimbak sa mga private file sa destination, kaya kumopya lamang sa mga machine na pinagkakatiwalaan mo. Isa itong one-time na kopya, hindi patuloy na synchronization. Maaaring i-rotate ng ibang machine ang mga refresh token ng Codex, na mag-iiwan sa kinopyang login na nangangailangan ng renewal; ang magkakahiwalay na sign-in ang nananatiling pinaka-maaasahang pagpipilian para sa sabay-sabay na paggamit sa maraming machine. Tingnan ang [gabay sa account authentication ng Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Isang account bawat provider ang active, at bawat bagong session ay nagsisimula bilang ito: `cx`, `cy`, isang simpleng `claude`, `codex`, o `grok`, anumang inilunsad sa pamamagitan ng `omarchy agent`, at mga script o editor na nakakahanap ng CLI sa `PATH`. Lumipat gamit ang `omarchy agent account use work` (at bumalik gamit ang `omarchy agent account use main`), o sa panel sa pamamagitan ng pagpindot sa numero ng isang account at pagkatapos ay `Enter` (o pag-click sa Use button nito). Lumilipat din ang mga tumatakbong Claude session, mula sa kanilang susunod na mensahe: bawat Claude session ay tumatakbo sa `~/.claude`, na laging naglalaman ng sign-in ng active account. Ang Claude session na sinimulan sa sariling folder ng isang account ng mas lumang Omarchy ay may hawak ng sign-in na iyon hanggang sa magsara ito, kaya pinapangalanan ng switch ang mga session na iyon at kusang natatapos kapag wala na sila. Nananatili ang mga tumatakbong Codex at Grok session sa account na pinagsimulan nila. Ang conversation history, settings, skills, at plugins ay shared sa lahat ng account, kaya ang `claude --continue` sa parehong folder ay nagpapatuloy kung saan ka tumigil sa bagong account.

Kapag may higit sa isang account, ipinapakita ng panel ang mga limit ng bawat account nang magkatabi, na minarkahan ang active. Inaabisuhan ka ng Omarchy kapag lumampas ang active account sa 95% ng isang limit, at ang pag-click sa notification ay lumilipat sa account na may pinakamaraming headroom. Hindi ito kailanman kusang lumilipat. Palitan ang threshold gamit ang `omarchy agent account threshold 90`. Kung ang bawat account ay lumampas sa threshold, maririnig mo ito nang isang beses, kasama kung aling account ang unang magkakaroon ng puwang. Habang ang isang active account ay nasa loob ng 15 points ng threshold nito (80% sa default), sinusuri ang mga limit nito bawat tatlong minuto sa halip na bawat 15.

Ipinapakita ng `omarchy agent account list` ang bawat account at ang pinakabagong mga limit nito, kinakalimutan ng `omarchy agent account remove work` ang isa, at pinapalitan ng pangalan ng `omarchy agent account rename primary Hey` ang isa (o i-click ang pangalan ng isang account sa panel). Gumagana ang mga command na ito sa mga account ng default agent mo; para maabot ang ibang provider, pangalanan muna ito, gaya ng `omarchy agent account use codex side`. Ang login na mayroon ka na sa `~/.claude` o `~/.codex` ay ang _Main_ account. Nananatili ang sa Codex kung nasaan ito; naghihintay ang sa Claude sa sarili nitong folder habang may ibang account na active. Ang account na hindi ginamit nang higit sa halos walong oras ay maaaring magpakita ng _Sign-in required_; i-click ito para muling mag-sign in ang account na iyon mismo sa panel, o lumipat dito at magsimula ng session, na kusang nagre-refresh ng sign-in. Ang mga MCP server na idinaragdag mo gamit ang `claude mcp add` ay umaabot sa bawat Claude account, dahil lahat sila ay tumatakbo sa `~/.claude`; para sa Codex at Grok, ang mga server na mayroon ka noong idinagdag ang isang account ay sumasama rito, pero ang mga susunod ay umaabot lamang sa account kung saan mo sila idinagdag. May sarili nitong sign-in ang Claude Desktop, at ang mga Codex o Grok tool na naka-configure gamit ang absolute path patungo sa isang CLI binary ay hindi sumusunod sa switch. Inuuna ang isang tahasang `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, o `GROK_HOME` kaysa sa napiling account.

### Diagnosis ng crash

Binabantayan ng Omarchy ang systemd-coredump para sa mga process crash. Kapag nakapili ka na ng default agent, anumang programa mo na nagda-dump ng core ay magdadala ng notification na "Process crashed" — i-click ito, at ibibigay ang crash sa default agent mo kasama ang omarchy-diagnose-crash skill ng Omarchy, na gagabay sa agent sa pagtatatag ng mga katotohanan mula sa core dump at pagpapasya kung karapat-dapat bang iulat ang crash sa upstream. Maaari mo rin itong patakbuhin nang mano-mano laban sa anumang PID mula sa `coredumpctl list` gamit ang `omarchy agent crash <pid>`.

Naka-on ang pagmamatyag bilang default. I-off ito sa ilalim ng _Trigger > Toggle > Crash Capture Off_ (o gamit ang `omarchy toggle crash-capture`) at hihinto ang mga notification; gumagana pa rin nang mano-mano ang `omarchy agent crash <pid>`.

Maaari ring patahimikin ang mga crash nang paisa-isa bawat programa, na siyang iniaalok sa iyo ng diagnosis sa dulo. Pinipigilan ng `omarchy crash mute hyprland` ang mga notification para lamang sa programang iyon, ibinabalik sila ng `omarchy crash mute hyprland off`, at inililista ng `omarchy crash mute` nang mag-isa kung ano ang na-mute mo. Tinatanggap nito ang path ng binary nang kasingsaya ng pangalan nito, kaya pareho ang ginagawa ng `omarchy crash mute /usr/bin/hyprland`. I-quote ang pangalang may space, gaya ng `omarchy crash mute 'Some App'`. Nag-aabiso pa rin ang lahat ng iba pa, at nagka-crash pa rin ang na-mute na programa — itinatago nito ang paalala, hindi nito inaayos ang anuman.

### Mga desktop app

May dala rin ang menu na _I-install > AI_ ng ilang graphical AI app: Amp Desktop, Antigravity Desktop, ang ChatGPT desktop app, ang Claude desktop app (ang Linux beta ng Anthropic, na may mga tab na Chat, Cowork, at Claude Code), Grok Bot para makipag-chat sa mga model ng xAI, Herdr Desktop, Hermes Desktop, OpenClaw, ang Perplexity desktop app, at T3 Code. Ang Grok Bot ang desktop chat app. Ang coding agent ay ang command na `grok`.

Ang Hermes Desktop ang dapat mong malaman, dahil iisa lang ang Hermes ng isang machine, at pag-aari ito ng app: ini-install lamang ang Hermes sa pamamagitan ng app, at ang command na `hermes` na pinapatakbo ng default agent ay pag-aari ng app. Ang pagpili sa Hermes bilang default agent ay nag-i-install ng parehong bagay na ginagawa ng entry na _I-install > AI_: ang package, at isang Hermes runtime sa ilalim ng `~/.hermes` na sine-set up ng sariling installer ng Hermes, na tumatagal ng ilang minuto sa unang pagkakataon. Ang runtime na iyon ang iisang Hermes na ginagamit ng terminal command na `hermes`, ng default agent at ng app, at ina-update nito ang sarili gamit ang `hermes update` sa halip na maghintay sa isang Omarchy release. Ang pag-install nito ay nagbibigay din sa Hermes ng Omarchy theme bilang isang skin na pinangalanang `omarchy`, na sinusundan ng bawat Hermes surface habang nagpapalit ka ng theme; pumili ng iba sa ilalim ng Appearance settings ng Hermes o gamit ang `/skin` kung mas gusto mong hindi, at hindi pakikialaman ng Omarchy ang pagpipiliang iyon. Ang pag-alis ng app sa ilalim ng _Alisin > AI_ ay nagsasara muna ng Hermes, kasama ang gateway, isinasama ang runtime na iyon, at pinapanatili ang iyong mga chat, memories, at ang mga skill na isinulat ng Hermes para sa sarili nito maliban kung sabihin mong hindi: nagtatanong ito, na naka-default sa hindi, kung dapat ding alisin ang data na iyon at ang iyong connection settings.

Ang desktop experience ng OpenClaw ay ang Control UI nito, na nagbubukas bilang isang web app na sinusuportahan ng sarili nitong local gateway. Nakatira ang OpenClaw sa `~/.openclaw` at ina-update ang sarili: gamitin ang button na "Update Gateway" ng Control UI o patakbuhin ang `openclaw update`, at magre-restart ang gateway sa bagong bersyon. Pinipili lamang ng Omarchy ang release na pagsisimulan ng bagong install. Maaari ring maging default agent mo ang OpenClaw: ang pagpili rito sa ilalim ng _Agent > Harness_ ay nagse-set up ng parehong kopya sa `~/.openclaw`, at binubuksan ng agent ang terminal UI ng OpenClaw na nakakabit sa gateway nito. Ang pag-alis ng OpenClaw sa ilalim ng _Alisin > AI_ ay isinasama ang gateway service at ang app at pagkatapos ay nagtatanong kung dapat ding alisin ang `~/.openclaw`, dahil naroon ang iyong mga chat at credential kasama ang OpenClaw mismo at ang mga plugin runtime na dina-download nito; pinapanatili ito ng default, at ang muling pag-install ng OpenClaw ay kukunin itong muli.

Ang Herdr Desktop ay ang desktop app ng [Herdr](https://herdr.dev): mga space, tab, at pane ng mga terminal at coding agent na patuloy na tumatakbo sa core nito kapag isinara mo ang window. Nagmumula ito sa sariling installer ng Herdr sa halip na isang package, kaya nakatira ito sa `~/.local/share/herdr-app`, isinasama ang core nito sa `~/.local/bin/herdr-core` kapag wala ka pa nito, at ina-update ang sarili nitong dalawa. Nakatabi ito sa command na `herdr` na kasama ng Omarchy sa `Super + Ctrl + Return` sa halip na palitan ito, at nakukuha nito ang mga direct key ng command na iyon: hinahati ng `Alt + Return` at `Alt + Shift + Return` ang isang pane pababa o pakanan, isinasara ito ng `Alt + Escape`, ang `Ctrl + Alt + Arrow` ay gumagalaw sa pagitan ng mga pane, ang `Alt + 1..9` at `Alt + Left/Right` ay pumipili ng tab, at ang `Alt + Up/Down` ay gumagalaw sa pagitan ng mga space. Pumipili ng space ang `Ctrl + 1..9` at ang `Alt + Shift + Up/Down` ay humahakbang sa mga agent. Ang mga prefix key na `Ctrl + Space` ay nananatiling terminal-only, dahil hindi mahawakan ng app ang isang simpleng Ctrl key para sa isang sequence. Isinusulat ito ng Omarchy sa `~/.config/herdr-app/keys.json`, at ibinabalik sila ng `omarchy-refresh-herdr-app`. Pinipili ng pag-install nito ang Omarchy theme ng Herdr, na susunod sa Omarchy theme mo mula noon. May isang theme ang Herdr para sa light mode at isa para sa dark, kaya pagkatapos lumipat sa pagitan ng dark at light na Omarchy theme, piliin muli ang Omarchy sa theme picker ng Herdr nang isang beses pa para sa kabilang mode.

Tumatakbo ang T3 Code mula sa official AppImage release nito sa `~/.local/share/t3code` sa halip na mula sa isang package, kaya ina-update nito ang sarili. Nagtatanong ang pag-install nito kung magsisimula sa Stable o Nightly channel; lumipat mamaya sa settings ng T3 Code. Nakatira ang iyong mga thread at settings sa `~/.t3`, at ang pag-alis ng T3 Code sa ilalim ng _Alisin > AI_ ay isinasama sila.

### Mga local na model

Patakbuhin ang isang open model sa sarili mong machine para sa iyong mga coding agent. Nananatili sa machine ang iyong mga prompt at code; walang ipinapadala sa model ang umaalis dito. Magsimula sa:

```bash
omarchy models use best text
```

Ise-set up nito ang pinakamahusay na text model para sa machine na ito, ang uri na ginagamit ng iyong mga agent. Ang mga image, video at music model ay may sarili nilang pinakamahusay: `omarchy models use best image`, `video` o `music`. Patakbuhin ang `omarchy models use best` para makita ang pinili ng bawat uri para sa machine na ito.

O buksan ang local models panel mula sa sparkles icon nito sa top bar, katabi ng agents icon, o gamit ang Super + Ctrl + Alt + X, at piliin ang +. Lumalabas ang icon kapag may model na kasya sa machine na ito. Ang Podman, na nagpapatakbo ng mga model, ay kasama ng Omarchy, gayundin ang container toolkit ng NVIDIA sa isang NVIDIA machine, na nagbibigay sa kanila ng GPU; kung nawawala ang alinman, ini-install ito ng unang setup. Pagkatapos ay pipiliin ng Omarchy ang inirerekomendang model para sa machine na ito, ida-download ito, at sisimulan ito. Asahan ang download na sampu-sampung GB at karamihan ng memory ng machine ay gagamitin habang tumatakbo ang model: gumagamit ang Flash Next ng humigit-kumulang 100 GiB sa buong 256K context nito. Kung hawak ng ibang mga model ang memory na kailangan nito, ise-set up itong nakahinto, handang magsimula kapag huminto ka ng isa. Humihinto ang model sa pag-logout; ihinto mo ito mismo kapag kailangan mo ang memory para sa ibang bagay.

Ipinapakita ng `omarchy models list` ang mga opsyon at ipinapaliwanag kung bakit hindi kasya ang ilan. Para mag-set up ng isa pa, patakbuhin ang `omarchy models use <recipe>`. Sa ngayon, available ang `qwen3.8-flash-next-gufo` at `qwen3.8-27b-gufo` para sa mga 128 GB Strix Halo machine; ang 27B ay gumagamit ng humigit-kumulang 40 GiB, kaya nag-iiwan ito ng puwang para sa ibang trabaho. Sa isang 64 GB laptop na may Intel's Arc B390, tumatakbo ang `qwen3.6-35b-a3b-llamacpp` sa humigit-kumulang 30 GiB. Dumarating ang mga bagong recipe at rekomendasyon kasama ang `omarchy update`, sa pamamagitan ng package.

Bawat model na ise-set up mo ay may sarili nitong linya sa local models panel: i-play para simulan ito, i-pause para ihinto ito at palayain ang memory nito, at ang terminal button para buksan ang agent mo rito. Sa itaas, ipinapakita ng isang bar kung paano nahahati ang memory ng machine sa pagitan ng Omarchy mismo (ang system at ang iyong mga app), bawat tumatakbong model, at kung ano ang libre. Ituro ang isang nakahintong model at ipapakita ng bar kung kasya ito, o kung gaano ito kakulang. Maraming model ang maaaring tumakbo nang sabay kapag kasya sila sa memory nang magkasama; kung hindi kasya ang isa, sinasabi ng Omarchy kung aling tumatakbong model ang ihihinto. I-drag ang mga linya gamit ang logo nila para muling ayusin sila, at pindutin ang Delete sa isang napiling linya para alisin ang isang model at ang download nito.

Bawat coding model na ise-set up mo ay may sarili ring entry sa app launcher, sa ilalim ng pangalan ng model at kasama ang logo ng gumawa nito, sa paraang ang pag-sign in sa Claude, Codex o Grok ay nagdaragdag ng isa. Binubuksan nito ang agent mo sa model na iyon, at sinisimulan muna ang model kung hindi ito tumatakbo: ipinapakita ng terminal na naglo-load ito at ibibigay sa agent kapag handa na ito. Ang pag-alis ng isang model ay nag-aalis ng entry nito.

Hindi lahat ng model ay para sa coding. Ang mga image, video at music model ay nagbubukas sa Fantasi sa halip, ang app ng Omarchy para gumawa ng mga larawan, video at music gamit ang isang model na tumatakbo sa machine na ito, na pinili roon o mula sa kanilang linya sa local models panel.

Pinapanatili ng isang model ang pagtakbo nang eksakto kung paano ito sine-set up, kaya hindi kailanman nire-restart ng isang Omarchy update ang isa sa ilalim ng iyong mga agent. Kapag may mas bagong runtime o mas bagong weights ang Omarchy para sa isang model na na-set up mo, ipinapakita ng linya nito ang isang update button: pindutin ito at muling ise-set up ang model sa background, ida-download lamang ang nagbago, at magre-restart sa bagong bersyon. Ang model na nakahinto ay mananatiling nakahinto. Ginagawa ng `omarchy models update` ang parehong bagay para sa bawat model mula sa isang terminal.

Mula sa command line, ginagawa ng `omarchy models start <recipe>` at `omarchy models stop <recipe>` ang parehong bagay, ipinapakita ng `omarchy models status` ang bawat model, at binubuksan ng `omarchy agent --local` ang huling model na sinimulan mo sa pi, anuman ang default agent mo. Maaari ring gumamit ang OpenCode at Qwen Code ng local model: binubuksan sila roon ng `omarchy models harness opencode` o `omarchy models harness qwen` sa halip, at bumabalik ang `omarchy models harness pi`. Inililista rin ng pi ang bawat model na na-set up mo, at iyong nasa mga machine na na-pair mo, sa sarili nitong model picker, kaya naaabot din sila ng simpleng `pi`. Maaari ring kumonekta ang anumang OpenAI-compatible client: ipinapakita ng `status` ang address ng bawat model (ang una ay `http://127.0.0.1:11435/v1`), ang recipe name ang model, at ang key ay nasa `~/.config/omarchy/agent-local/key`.

Tinatanggal ng `omarchy models remove <recipe>` ang isang model at ang mga download na hindi ginagamit ng ibang model.

Ang mga third-party runtime ay may label ng kanilang publisher. Pinapatakbo ng Omarchy ang bawat model nang walang network access.

### Mga local na LLM

Inirerekomenda ng Omarchy ang dalawang paraan ng pagpapatakbo ng mga local LLM model: LM Studio at Ollama. Nagbibigay ang LM Studio ng GUI interface para sa paghahanap ng mga open-weight model, pag-install ng mga ito, at pagpapatakbo ng mga ito. Mahusay itong paraan para madaling makapagsimula. Nag-aalok ang Ollama ng CLI para gawin ito nang katulad. Pero kung bago ka sa mga local model, magsisimula ako sa LM Studio. Maaari mong i-install ang alinman sa ilalim ng _I-install > AI_ sa Omarchy Menu.

### Ang mga Omarchy skill

Tinutulungan ng mga agent skill ang AI na gumamit ng mga partikular na tool sa isang partikular na paraan, at may pito nito ang Omarchy. Sinasaklaw ng omarchy skill ang pag-aangkop ng system, gaya ng pag-tweak ng Hyprland config mo o pag-aayos ng bar. Sinasaklaw ng omarchy-make-theme, omarchy-make-plugin, omarchy-make-app, at omarchy-make-game ang paggawa ng bagong bagay, sinasaklaw ng omarchy-contribute ang pag-uulat ng bug o pagpapadala ng fix sa upstream, at ginagabayan ng omarchy-diagnose-crash ang isang crash sa core dump nito. Naka-symlink sila sa mga skill directory para sa Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` at bawat `~/.hermes/profiles/*/skills`), at ang generic na lokasyong `~/.agents/skills`, kaya awtomatikong nakukuha sila ng karamihan ng mga harness. Inuuna ang isang skill folder mo na may parehong pangalan.

Pero dapat mong ituring na experimental ang mga skill na ito. Gagamitin ito ng iba't ibang model nang may iba't ibang epekto. Pinakamainam na tumakbo muna sa plan mode, para magkaroon ka ng ideya kung ano ang gustong baguhin ng agent. At pagkatapos ay maging handang i-rollback ang mga pagbabago o kahit tawagin ang `omarchy reinstall configs`, kung guluhin ng agent ang lahat.
