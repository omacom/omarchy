# AI

Isinasama ng Omarchy ang mga launcher para sa mga coding agent sa ibaba nang hindi pumipili ng default para sa iyo. Magpatakbo ng isang command para i-install ang CLI nito sa unang paggamit, pagkatapos ay mag-authenticate kapag sinabihan. Ang Hermes at OpenClaw ang mga eksepsyon: walang ini-install para sa kanila sa pamamagitan ng mise, at ang pagpili sa alinman ay nagse-set up ng sarili nitong kopya na kusang nag-a-update, gaya ng ipinapaliwanag ng _Desktop apps_ sa ibaba.

### Pag-install at pag-update ng mga agent

Maliban sa Hermes at OpenClaw, ginagamit ng mga agent na ito ang lazy installation ng mise: ini-install ng unang paglunsad ang CLI, at muling ginagamit ito ng mga susunod na paglunsad. Sinusuri rin ng mise ang isang naka-install na agent para sa bagong release nang hindi hihigit sa isang beses kada apat na oras, bago ito magsimula o sa background sa isang shell prompt. Kung mabigo ang update na iyon o offline ka, tatakbo ang naka-install na bersyon. Ina-update ng `omarchy update` ang mga naka-install na agent kasama ng iba pang bahagi ng Omarchy, at ina-update ng `mup` ang mga tool na pinamamahalaan ng mise lamang.

Hindi ina-update ng sariling updater ng isang agent, gaya ng `claude update`, `codex update`, o isang update button sa isang app, ang install na pinamamahalaan ng mise. Nabibigo ang `codex update`, at maaaring mag-ulat ng tagumpay ang `claude update` habang nag-i-install ng hiwalay na kopya na hindi sinusubaybayan ng mise. Kung mas gusto mong gamitin ang native installer at updater ng isang agent, idagdag ito sa `disable_tools`; tingnan ang [Mga naka-preinstall na CLI tool](18-development-tools.md#preinstalled-cli-tools).

Para i-install ang lahat ng naka-configure na lazy tool bago mo kailanganin ang mga ito, patakbuhin ang `mise install --include-lazy`. Kasama rito ang iba pang default na CLI tool ng Omarchy pati na rin ang mga agent. Tingnan ang [Mga naka-preinstall na CLI tool](18-development-tools.md#preinstalled-cli-tools) para sa pag-install ng iisang tool o paggamit ng sarili mong installation.

Ini-install ang `grok` sa pamamagitan ng first-party na `grok` package ng mise, sa parehong paraan gaya ng `claude` at `codex`. Patakbuhin ang `grok`, o i-star ito sa panel ng mga agent. Laktawan ang `curl | bash` installer sa x.ai. Naglalagay ang landas na iyon ng pangalawang kopya sa `~/.grok/bin`, inuuna ito sa `PATH`, at pinapalitan ang wrapper ng Omarchy.

Binubuksan ng `dsh` ang browser UI nito sa `127.0.0.1:3080`, na ang launch directory ang default workspace nito. Walang kinukuhang panimulang prompt ang browser UI nito, kaya binubuksan ito ng `omarchy agent prompt` na nasa clipboard mo ang prompt para i-paste. Sinisimulan ito ng Omarchy gamit ang no-approval permission preset ng DeepSeek. Ina-upload ng DeepSeek Harness ang mga session log sa DeepSeek kapag ginagamit mo ang opisyal nitong model API; i-off iyon sa ilalim ng _Settings > General > Upload Session Log_ sa browser UI nito. Ina-upload din kasama ng session ang feedback na ipinapadala mo rito, maliban kung sisimulan mo ito gamit ang `DSH_TELEMETRY_MODE=DISABLED`.

### Ang default na agent

Piliin ang default mong agent gamit ang bituin sa tabi ng isang agent sa panel ng mga agent, na napupuno sa default, o gamit ang `omarchy default agent <name>`, na tumatanggap din ng anumang harness na walang linya roon. Kung hindi pa naka-install ang agent, i-install muna ito kapag pinili mo ito, at makakakuha rin ito ng sarili nitong launcher sa app launcher, sa tabi ng Agent. Inaanyayahan ka ng bagong Omarchy na mag-set up ng isa gamit ang isang beses lang na notification, na nagbubukas sa panel ng mga agent.

Sinusubukan ding i-set up ng pagpili sa Claude ang browser extension nito para sa Chromium, Chrome, Brave, Brave Origin, at Edge. Nalalapat ang pag-set up ng extension sa lahat ng user at maaaring humingi ng system password mo; pipiliin at ilulunsad pa rin ang Claude kahit kanselahin mo ito o mabigo ang pag-install ng extension. I-restart ang browser mo, i-enable ang extension kung sinabihan, at mag-sign in sa Claude para tapusin ang pagkonekta rito. Patakbuhin ang `/chrome` sa Claude para suriin ang koneksyon. Hindi sinusuportahan ng Firefox at Zen ang extension na ito. Kung default mo na ang Claude bago pa idinagdag ang setup na ito, piliin itong muli para i-install ang extension.

Kapag nakapili ka na, ilulunsad ng `Super + Shift + Ctrl + A` ang default na agent sa isang nakalaang terminal window (o ilalabas ang picker kung hindi ka pa nakakapili). Maaari mo rin itong ilunsad nang diretso sa isang gawain gamit ang `omarchy agent prompt "Review this project"`. Walang kinukuhang panimulang prompt ang Freebuff at DeepSeek Harness, kaya sa halip ay nagbubukas ang mga ito na nasa clipboard mo ang prompt para i-paste. Tumatakbo nang walang bantay ang mga agent na inilunsad sa ganitong paraan sa kani-kanilang mode na huwag huminto para magtanong, kaya maging handa na talagang may gagawin sila! Walang ganoong mode ang MiniMax Code para sa mga interactive session nito, kaya humihingi ito ng mga pahintulot gaya ng dati. At dahil tumatanggi ang mga agent na tandaan ang tiwala para sa home directory mo, sa `~/Work` sa halip nagsisimula ang mga paglunsad mula sa `$HOME`.

May mga terminal shortcut din: pinapatakbo ng `a` ang default na agent nang inline sa kasalukuyang terminal, habang direktang sinisimulan ng `c`, `cx`, `cy`, at `ca` ang OpenCode, Claude Code, Codex, at Antigravity (muli sa kanilang mga mode na kusang nag-aapruba). Nagsi-sync din ang mga pagbabago ng tema sa mga agent: sumusunod ang Claude Code, Pi, OpenCode, at Hermes (kapag na-install na ito ng Omarchy) kapag nagpapalit ka ng tema ng Omarchy.

### Mga tagubilin mo para sa agent

Mapupunta ang mga personal na panuntunan para sa bawat agent sa `~/.agents/AGENTS.md`, sa tabi ng mga shared skill sa `~/.agents/skills`. Buksan ito gamit ang document icon sa tabi ng + sa panel ng mga agent, o ang `omarchy agent instructions --edit`, na nagli-link din nito sa bawat harness na may sarili nitong global file: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, ang `~/.copilot/copilot-instructions.md` ng Copilot, at iba pa. Binabasa ng Crush at Amp ang link na `~/.config/AGENTS.md`, habang direktang binabasa ng omp, Kimi, at DeepSeek Harness ang `~/.agents/AGENTS.md`. Inili-link din ito ng pagpili ng default na agent. Nagiging shared na file ang isang instructions file na mayroon ka na kung wala pa noon; kung hindi, mananatili ito sa tabi ng link bilang `.bak`. Patakbuhin ang `omarchy agent instructions` para muling i-link pagkatapos mag-install ng isa pang agent.

### Ang panel ng mga agent

May agents icon ang top bar. Bago ka makapag-set up ng agent, nag-aalok ang panel nito ng tatlong paraan para magsimula: mag-sign in sa isang subscription ng Claude, Codex, Grok, Gemini, Muse, Cursor, o Copilot, o sa ilalim ng More sa isang coding plan ng OpenCode Go, MiniMax, Synthetic, o Z.ai; magbayad ayon sa paggamit gamit ang Fireworks, OpenCode Zen and Go, OpenRouter, o sa ilalim ng More gamit ang DeepSeek o anumang iba pang provider na pinagsa-sign in-an ng OpenCode, na lahat ay tumatakbo sa OpenCode; o patakbuhin ang pinakamahusay na modelo para sa computer mo, kapag may umaangkop dito. Ang una mong matatapos ang magiging default mong agent, at inaalok ng + sa panel ang parehong tatlo sa ibang pagkakataon. Pagkatapos niyon, inilalagay ng panel ang bawat subscription sa isang pahina: bawat agent at account kasama ang plan nito, isang meter para sa bawat limit nito sa 5-hour session at lingguhang mga limit kasama ang oras hanggang mag-reset ito (i-hover para sa eksaktong porsyento), o ang natitirang prepaid balance, sa ilalim ng isang linyang umiikot sa kung ano ang nagamit mo sa lahat ng ito, gaya ng mga token ngayong linggo at ang pinakamadalas mong gamiting modelo. Sa ilalim ng _Make something cool_ nag-aalok ito ng mga starter prompt para sa isang bagong tema, plugin, app, o game na nagbibigay ng gawain sa default mong agent. Ginagawa ang mga app sa paraang ginawa ang sariling Hype, Monologue, at Omacut ng Omarchy, sa C++ at Qt Quick, na sumusunod sa omarchy-make-app agent skill, at naka-install na ang compiler at mga piraso ng Qt na kailangan nila. Ang mga game ay iisang three.js page sa `~/Games/vibes`, na sumusunod sa omarchy-make-game agent skill, at lahat ay nagbubukas mula sa isang Game Vibes launcher sa kasalukuyang tema; nilo-load nila ang three.js mula sa web, kaya kailangan nila ng koneksyon para magsimula. Sinasaklaw agad ang Claude Code, Codex, Grok, Kimi, Cursor at ang allowance nito sa Grok Bot, GitHub Copilot, Muse, Gemini (sa pamamagitan ng Antigravity), at Devin kasama ang kanilang mga limit, ang Kimchi kasama ang plan nito, mga prepaid credit, at mga budget sa paggastos, at ipinapakita ng Hermes, Mistral Vibe, at Qwen Code ang kanilang mga session at token kapag nagamit mo na ang mga ito. Lumalabas din ang mga provider plan at key na ginagamit mo sa pamamagitan ng pi, omp, o opencode: ang OpenCode Zen and Go, ang Z.ai GLM Coding Plan, Ollama Cloud, ang MiniMax Token Plan, at Synthetic kasama ang kanilang mga limit; ang OpenRouter at DeepSeek kasama ang kanilang mga prepaid balance; ang Fireworks kasama ang paggastos nito sa nakalipas na 30 araw. Nakakakuha ng sarili nilang mga linya ang mga coding model na pinapatakbo mo sa sarili mong hardware, at binibilang din ang kanilang mga token sa mga kabuuan, gaya ng inilalarawan sa ilalim ng [Mga lokal na modelo](#local-models). Bawat agent ay binibilang nang isang beses, sa ilalim ng kung sino ang naniningil para rito, gaano man karaming harness ang patakbuhin mo rito.

I-left-click ang icon sa bar o pindutin ang `Super + Ctrl + X` para sa panel, i-right-click para ilunsad ang default mong agent, at i-middle-click para i-refresh. Nire-regenerate kada 15 minuto ng `omarchy agent usage update` ang mga usage record sa likod nito, at maaari pang pagsamahin ng panel ang usage mula sa iba mo pang machine sa pamamagitan ng isang naka-sync na folder. Tingnan ang README sa ilalim ng `$OMARCHY_PATH/shell/plugins/agents/` para sa buong mga setting.

### Maraming subscription

Kung nagbabayad ka para sa higit sa isang plan ng Claude, Codex, o Grok — halimbawa isang personal na Max at isang pangtrabaho — maaaring panatilihing naka-sign in ng Omarchy ang lahat ng ito at lumipat-lipat sa pagitan ng mga ito. Magdagdag ng subscription gamit ang + sa panel ng mga agent, na gagabay sa iyo mismo roon, o gamit ang `omarchy agent account add claude Work` (o `codex`, o `grok`). Nagsa-sign in din ang parehong + at command sa Gemini (`gemini`) at OpenCode (`opencode`), at nagse-save ng API key ng Fireworks (`fireworks`) o OpenRouter (`openrouter`) sa OpenCode; nagsa-sign in din ang command sa Copilot (`copilot`), Cursor (`cursor`), at Muse (`muse`). Nag-iisa lang ang sign-in ng bawat isa sa mga iyon. Ini-install nito ang CLI kung nawawala ito. Nagsa-sign in ang unang account para sa isang provider sa pamamagitan ng normal mong browser, mismo kung saan laging tumitingin ang CLI. Nagsa-sign in ang bawat susunod sa pamamagitan ng isang private window, para hindi aksidenteng makuha ang account na naka-sign in na sa browser mo; mag-sign in doon bilang account na idinaragdag mo, at isara muna ang anumang private window na nakabukas mo na. Huwag kailanman mag-log out sa CLI para gawin ito: binabawi ng pag-log out ang naka-save na sign-in, at kailangang idagdag muli ang account na iyon.

Para kopyahin ang mga subscription login mo sa isa pang Omarchy machine sa pamamagitan ng SSH, patakbuhin ang `omarchy agent account copy user@laptop`. Nagbibigay ang sender ng pansamantalang receiver kapag walang naka-install ang destinasyon, kaya makakatanggap ng mga account ang mas lumang Omarchy machine nang walang update. Mas nangingibabaw ang mga naka-install na receiver. Kinokopya nito ang lahat ng subscription ng Claude, Codex, at Grok; magdagdag ng mga pangalan ng provider para piliin ang mga ito, gaya ng sa `omarchy agent account copy laptop claude`. Tumutugma ang mga pangalan ng account at command ID sa source, kabilang ang mga account na mayroon na sa destinasyon. Nakakakuha ng numeric suffix ang mga hindi kaugnay na account sa destinasyon kung magkasalungat ang kanilang mga pangalan, at nananatiling lokal sa bawat machine ang mga setting, skill, plugin, at kasaysayan ng pag-uusap.

Pinapanatili ang mga umiiral na credential sa destinasyon. Ang isang source account na naka-sign in na roon ay sina-synchronize ang pangalan nang hindi pinapalitan ang mga credential nito; idinaragdag ang iba pang account sa tabi nito. Para palitan ang mga naka-save na credential para sa magkatugmang account, gamitin ang `omarchy agent account copy --replace laptop claude` pagkatapos isara ang mga session ng account na iyon sa destinasyon. Nakukuha rin ng bagong destinasyon ang aktibong account at mga kagustuhan sa paglipat ng source; pinapanatili ng isang naitatag nang destinasyon ang sarili nito.

Naglalakbay ang mga credential sa pamamagitan ng SSH at iniimbak sa mga pribadong file sa destinasyon, kaya kumopya lang sa mga machine na pinagkakatiwalaan mo. Isang beses lang itong kopya, hindi patuloy na synchronization. Maaaring i-rotate ng ibang machine ang mga refresh token ng Codex, na mag-iiwan sa isang nakopyang login na nangangailangan ng pag-renew; nananatiling pinaka-maaasahang pagpipilian ang magkakahiwalay na sign-in para sa sabay-sabay na paggamit sa maraming machine. Tingnan ang [gabay ng Codex sa authentication ng account](https://developers.openai.com/codex/auth/ci-cd-auth).

Aktibo ang isang account bawat provider, at nagsisimula ang bawat bagong session bilang ito: `cx`, `cy`, isang karaniwang `claude`, `codex`, o `grok`, anumang inilunsad sa pamamagitan ng `omarchy agent`, at mga script o editor na nakakahanap sa CLI sa `PATH`. Lumipat gamit ang `omarchy agent account use work` (at bumalik gamit ang `omarchy agent account use main`), o sa panel sa pamamagitan ng pagpindot sa numero ng isang account at pagkatapos sa `Enter` (o pag-click sa bituin nito). Lumilipat din ang mga tumatakbong Claude session, mula sa kanilang susunod na mensahe: tumatakbo ang bawat Claude session sa `~/.claude`, na palaging naglalaman ng sign-in ng aktibong account. Ang isang Claude session na sinimulan sa sariling folder ng isang account ng isang mas lumang Omarchy ay naglalaman ng sign-in na iyon hanggang umalis ito, kaya pinapangalanan ng paglipat ang mga session na iyon at kusang natatapos kapag wala na ang mga ito. Nananatili ang mga tumatakbong Codex at Grok session sa account kung saan sila nagsimula. Ibinabahagi sa lahat ng account ang kasaysayan ng pag-uusap, mga setting, skill, at plugin, kaya nagpapatuloy ang `claude --continue` sa parehong folder kung saan ka tumigil sa bagong account.

Kapag may higit sa isang account, ipinapakita ng panel ang mga limit ng bawat account nang magkatabi, na may napunong bituin sa ginagamit. Inaabisuhan ka ng Omarchy kapag lumampas ang aktibong account sa 95% ng isang limit, at inililipat ka ng pag-click sa notification sa account na may pinakamaraming headroom. Hindi ito kailanman kusang lumilipat. Baguhin ang threshold gamit ang `omarchy agent account threshold 90`. Kung lampas ang bawat account sa threshold, maririnig mo ito nang isang beses, kasama kung aling account ang unang makakalaya. Habang ang isang aktibong account ay nasa loob ng 15 puntos ng threshold nito (80% sa default), sinusuri ang mga limit nito kada tatlong minuto sa halip na kada 15.

Ipinapakita ng `omarchy agent account list` ang bawat account at ang pinakabagong mga limit nito, kinakalimutan ng `omarchy agent account remove work` ang isa, at pinapalitan ng pangalan ng `omarchy agent account rename primary Hey` ang isa (o i-click ang pangalan ng isang account sa panel). Gumagana ang mga command na ito sa mga account ng default mong agent; para maabot ang ibang provider, pangalanan muna ito, gaya ng sa `omarchy agent account use codex side`. Ang login na mayroon ka na sa `~/.claude` o `~/.codex` ay ang _Main_ na account. Nananatili ang sa Codex kung nasaan ito; naghihintay ang sa Claude sa sarili nitong folder habang may ibang account na aktibo. Ang isang account na hindi ginamit nang higit sa mga walong oras ay maaaring magpakita ng _Sign-in required_; i-click ito para muling mag-sign in sa account na iyon mismo sa panel, o lumipat dito at magsimula ng isang session, na kusang nagre-refresh sa sign-in. Naaabot ng mga MCP server na idinaragdag mo gamit ang `claude mcp add` ang bawat Claude account, dahil lahat sila ay tumatakbo sa `~/.claude`; para sa Codex at Grok, sumasama sa isang account ang mga server na mayroon ka noong idinagdag ang account na iyon, pero ang mga susunod ay umaabot lang sa account kung saan mo idinagdag ang mga iyon. May sarili nitong sign-in ang Claude Desktop, at hindi sumusunod sa paglipat ang mga tool ng Codex o Grok na naka-configure gamit ang isang absolute path papunta sa isang CLI binary. Mas nangingibabaw ang isang tahasang `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, o `GROK_HOME` kaysa sa napiling account.

### Pag-diagnose ng crash

Binabantayan ng Omarchy ang systemd-coredump para sa mga crash ng proseso. Kapag nakapili ka na ng default na agent, ang anumang programa mo na nagda-dump ng core ay nagdadala ng notification na "Process crashed" — i-click ito, at ibibigay ang crash sa default mong agent kasama ang omarchy-diagnose-crash skill ng Omarchy, na gagabay sa agent sa pagtatatag ng mga katotohanan mula sa core dump at pagpapasya kung karapat-dapat bang iulat ang crash sa upstream. Maaari mo rin itong patakbuhin nang mano-mano laban sa anumang PID mula sa `coredumpctl list` gamit ang `omarchy agent crash <pid>`.

Naka-on ang pagbabantay bilang default. I-off ito sa ilalim ng _Trigger > Toggle > Crash Capture Off_ (o gamit ang `omarchy toggle crash-capture`) at hihinto ang mga notification; gumagana pa rin nang mano-mano ang `omarchy agent crash <pid>`.

Maaari ring patahimikin ang mga crash nang paisa-isang programa, na siyang inaalok sa iyo ng diagnosis sa dulo. Pinipigilan ng `omarchy crash mute hyprland` ang mga notification para sa programang iyon lamang, ibinabalik ang mga ito ng `omarchy crash mute hyprland off`, at inililista ng `omarchy crash mute` nang mag-isa kung ano ang pinatahimik mo. Tinatanggap nito ang path ng binary nang kasingsaya ng pangalan nito, kaya ginagawa ng `omarchy crash mute /usr/bin/hyprland` ang parehong bagay. I-quote ang isang pangalang may puwang, gaya ng sa `omarchy crash mute 'Some App'`. Nag-aabiso pa rin ang lahat ng iba pa, at nagka-crash pa rin ang pinatahimik na programa — itinatago nito ang paalala, hindi nito inaayos ang anuman.

### Mga desktop app

May dala ring ilang graphical AI app ang menu na _Install > AI_: Amp Desktop, Antigravity Desktop, ang ChatGPT desktop app, ang Claude desktop app (ang Linux beta ng Anthropic, na may mga tab na Chat, Cowork, at Claude Code), Grok Bot para makipag-chat sa mga modelo ng xAI, Herdr Desktop, Hermes Desktop, OpenClaw, ang Perplexity desktop app, at T3 Code. Ang Grok Bot ang desktop chat app. Ang coding agent ay ang command na `grok`.

Ang Hermes Desktop ang dapat mong malaman, dahil iisa lang ang Hermes ng isang machine, at sa app iyon: ini-install lang kailanman ang Hermes sa pamamagitan ng app, at ang command na `hermes` na pinapatakbo ng default na agent ay sa app. Ini-install ng pagpili sa Hermes bilang default na agent ang parehong bagay na ini-install ng entry na _Install > AI_: ang package, at isang Hermes runtime sa ilalim ng `~/.hermes` na sine-set up ng sariling installer ng Hermes, na tumatagal ng ilang minuto sa unang pagkakataon. Ang runtime na iyon ang iisang Hermes na ginagamit ng terminal command na `hermes`, ng default na agent at ng app, at kusang nag-a-update ito gamit ang `hermes update` sa halip na maghintay sa isang Omarchy release. Ibinibigay din ng pag-install nito sa Hermes ang tema ng Omarchy bilang isang skin na pinangalanang `omarchy`, na sinusundan ng bawat Hermes surface habang nagpapalit ka ng mga tema; pumili ng iba sa ilalim ng mga Appearance setting ng Hermes o gamit ang `/skin` kung mas gusto mong hindi, at hindi pakikialaman ng Omarchy ang pagpipiliang iyon. Isinasara muna ng pag-alis sa app sa ilalim ng _Remove > AI_ ang Hermes, kasama ang gateway, dinadala ang runtime na iyon, at pinapanatili ang iyong mga chat, memory, at ang mga skill na isinulat ng Hermes para sa sarili nito maliban kung sasabihin mo kung hindi: nagtatanong ito, na nagde-default sa hindi, kung dapat ding mawala ang data na iyon at ang iyong mga connection setting.

Ang desktop experience ng OpenClaw ay ang Control UI nito, na nagbubukas bilang isang web app na sinusuportahan ng sarili nitong local gateway. Nakatira ang OpenClaw sa `~/.openclaw` at kusang nag-a-update: gamitin ang button na "Update Gateway" ng Control UI o patakbuhin ang `openclaw update`, at magre-restart ang gateway sa bagong bersyon. Pinipili lang ng Omarchy ang release kung saan magsisimula ang isang bagong install. Maaari ring maging default mong agent ang OpenClaw: sine-set up ng pagpili rito gamit ang `omarchy default agent openclaw` ang parehong kopya sa `~/.openclaw`, at binubuksan ng agent ang terminal UI ng OpenClaw na nakakabit sa gateway nito. Dinadala ng pag-alis sa OpenClaw sa ilalim ng _Remove > AI_ ang gateway service at ang app kasama nito at pagkatapos ay nagtatanong kung dapat ding mawala ang `~/.openclaw`, dahil naglalaman iyon ng iyong mga chat at credential kasama ng OpenClaw mismo at ng mga plugin runtime na dina-download nito; pinapanatili ito ng default, at muling kukunin ito ng pag-install muli sa OpenClaw.

Ang Herdr Desktop ay ang desktop app na [Herdr](https://herdr.dev): mga space, tab, at pane ng mga terminal at coding agent na patuloy na tumatakbo sa core nito kapag isinara mo ang window. Nagmumula ito sa sariling installer ng Herdr sa halip na sa isang package, kaya nakatira ito sa `~/.local/share/herdr-app`, dinadala ang core nito sa `~/.local/bin/herdr-core` kapag wala ka pa nito, at kusang nag-a-update sa kanilang dalawa. Nakaupo ito sa tabi ng command na `herdr` na ibinibigay ng Omarchy sa `Super + Ctrl + Return` sa halip na palitan ito, at nakukuha nito ang mga direct key ng command na iyon: hinahati ng `Alt + Return` at `Alt + Shift + Return` ang isang pane pababa o pakanan, isinasara ito ng `Alt + Escape`, gumagalaw ang `Ctrl + Alt + Arrow` sa pagitan ng mga pane, pumipili ng tab ang `Alt + 1..9` at `Alt + Left/Right`, at gumagalaw ang `Alt + Up/Down` sa pagitan ng mga space. Pumipili ng space ang `Ctrl + 1..9` at humahakbang ang `Alt + Shift + Up/Down` sa mga agent. Nananatiling pang-terminal lang ang mga prefix key na `Ctrl + Space`, dahil hindi kayang hawakan ng app ang isang karaniwang Ctrl key para sa isang sequence. Isinusulat ito ng Omarchy sa `~/.config/herdr-app/keys.json`, at ibinabalik ito ng `omarchy-refresh-herdr-app`. Pinipili ng pag-install nito ang Omarchy theme ng Herdr, na sumusunod sa tema ng Omarchy mo mula noon. Nag-iingat ang Herdr ng isang tema para sa light mode at isa para sa dark, kaya pagkatapos lumipat sa pagitan ng dark at light na tema ng Omarchy, piliing muli ang Omarchy sa theme picker ng Herdr nang isa pang beses para sa kabilang mode.

Tumatakbo ang T3 Code mula sa opisyal nitong AppImage release sa `~/.local/share/t3code` sa halip na mula sa isang package, kaya kusang nag-a-update ito. Nagtatanong ang pag-install nito kung magsisimula sa Stable o Nightly channel; lumipat sa ibang pagkakataon sa mga setting ng T3 Code. Nakatira ang iyong mga thread at setting sa `~/.t3`, at dinadala ito ng pag-alis sa T3 Code sa ilalim ng _Remove > AI_ kasama nito.

### Mga lokal na modelo

Magpatakbo ng isang open model sa sarili mong machine para sa iyong mga coding agent. Nananatili sa machine ang iyong mga prompt at code; walang ipinapadala sa modelo ang umaalis dito. Magsimula sa:

```bash
omarchy models use best text
```

Sine-set up niyon ang pinakamahusay na text model para sa machine na ito, ang uri na ginagamit ng iyong mga agent. May sarili ring pinakamahusay ang mga image, video at music model: `omarchy models use best image`, `video` o `music`. Patakbuhin ang `omarchy models use best` para makita ang pili ng bawat uri para sa machine na ito.

O pumili ng + sa panel ng mga agent: sa ilalim ng _Use a local model_ inililista nito ang bawat coding model na umaangkop sa machine na ito, na una ang inirerekomenda. Kasama ng Omarchy ang Podman, na nagpapatakbo sa mga modelo, pati na rin ang container toolkit ng NVIDIA sa isang NVIDIA machine, na nagbibigay sa kanila ng GPU; kung nawawala ang alinman, ini-install ito ng unang setup. Pagkatapos ay pipiliin ng Omarchy ang inirerekomendang modelo para sa machine na ito, ida-download ito, at sisimulan ito. Asahan ang download na sampu-sampung GB at ang karamihan sa memory ng machine ay ginagamit habang tumatakbo ang modelo: gumagamit ang Flash Next ng mga 100 GiB kasama ang buong 256K context nito. Kung hawak ng ibang mga modelo ang memory na kailangan nito, sine-set up itong nakahinto, handang magsimula kapag pinahinto mo ang isa. Humihinto ang modelo sa pag-logout; pahintuin mo ito mismo kapag kailangan mo ang memory para sa iba pang bagay.

Ipinapakita ng `omarchy models list` ang mga opsyon at ipinapaliwanag kung bakit hindi umaangkop ang ilan. Para mag-set up ng isa pa, patakbuhin ang `omarchy models use <recipe>`. Ngayon, available ang `qwen3.8-flash-next-gufo` at `qwen3.8-27b-gufo` para sa mga 128 GB Strix Halo machine; gumagamit ang 27B ng mga 40 GiB, kaya nag-iiwan ito ng puwang para sa ibang trabaho. Sa isang 64 GB laptop na may Intel's Arc B390, tumatakbo ang `qwen3.6-35b-a3b-llamacpp` sa mga 30 GiB. Dumarating ang mga bagong recipe at rekomendasyon kasama ng `omarchy update`, sa pamamagitan ng package.

Nakakakuha ang isang coding model na idinaragdag mo ng sarili nitong linya sa panel ng mga agent, sa tabi ng iyong mga subscription: play para simulan ito, pause para pahintuin ito at palayain ang memory nito, ang Tailscale mark para ibahagi ito sa iba pang machine sa tailnet mo habang tumatakbo ito, at ang terminal button para buksan ang agent mo rito. Ipinapakita ng linya nito ang download, load o stop habang nangyayari ito, at sinasabi ito kapag walang sapat na libreng memory para simulan ito, o nagli-link sa mga log nito kapag huminto ito nang may error. Maaaring tumakbo ang ilan nang sabay-sabay kapag umaangkop silang magkasama sa memory. Pindutin ang Delete sa isang napiling linya para alisin ang modelo mula sa machine na ito, kasama ang download; maaaring i-set up itong muli ng +. Naghihintay sa ilalim ng + ang isang coding model na sine-set up mula sa isang terminal hanggang idagdag mo ito, at ganoon din ang mga modelong pinapatakbo ng isang machine na ipinares mo (`omarchy models pair <host>`).

Nakakakuha rin ang bawat coding model na sine-set up mo ng sarili nitong entry sa app launcher, sa ilalim ng pangalan ng modelo at kasama ang logo ng gumawa nito, sa paraang nagdaragdag ng isa ang pag-sign in sa Claude, Codex o Grok. Binubuksan nito ang agent mo sa modelong iyon, at sinisimulan muna ang modelo kung hindi ito tumatakbo: ipinapakita ng terminal na naglo-load ito at ibibigay sa agent kapag handa na ito. Inaalis ng pag-alis sa isang modelo ang entry nito.

Hindi lahat ng modelo ay para sa coding. Sa halip ay nagbubukas ang mga image, video at music model sa Fantasi, ang app ng Omarchy para gumawa ng mga larawan, video at musika gamit ang isang modelong tumatakbo sa machine na ito, at pinamamahalaan doon o gamit ang `omarchy models`.

Patuloy na tumatakbo ang isang modelo nang eksakto kung paano ito sine-set up, kaya hindi kailanman nire-restart ng isang Omarchy update ang isa sa ilalim ng iyong mga agent. Kapag may mas bagong runtime o mas bagong mga weight ang Omarchy para sa isang modelong sine-set up mo, ipinapakita ng linya nito ang isang update button: pindutin ito at muling sine-set up ang modelo sa background, na dina-download lang kung ano ang nagbago, at magre-restart sa bagong bersyon. Nananatiling nakahinto ang isang modelong nakahinto. Ginagawa ng `omarchy models update` ang pareho para sa bawat modelo mula sa isang terminal.

Mula sa command line, ginagawa ng `omarchy models start <recipe>` at `omarchy models stop <recipe>` ang pareho, ipinapakita ng `omarchy models status` ang bawat modelo, at binubuksan ng `omarchy agent --local-model <recipe>` ang modelong iyon sa pi, anuman ang default mong agent. Para gawing ang lokal mong modelo ang binubuksan ng agent hotkey, ng Quake console, at ng _Make something_ , patakbuhin ang `omarchy default agent local` o i-star ang isang tumatakbong modelo sa panel ng mga agent. Inililista rin ng pi ang bawat modelong sine-set up mo, at ang mga nasa machine na ipinares mo, sa sarili nitong model picker, kaya naaabot din sila ng karaniwang `pi`. Maaari ring kumonekta ang anumang OpenAI-compatible client: ipinapakita ng `status` ang address ng bawat modelo (ang una ay `http://127.0.0.1:11435/v1`), ang recipe name ang modelo, at nasa `~/.config/omarchy/agent-local/key` ang key.

Tinatanggal ng `omarchy models remove <recipe>` ang isang modelo at ang mga download na hindi ginagamit ng ibang modelo.

Nilalagyan ng label ng kanilang publisher ang mga third-party runtime. Pinapatakbo ng Omarchy ang bawat modelo nang walang network access.

### Mga lokal na LLM

Inirerekomenda ng Omarchy ang dalawang paraan ng pagpapatakbo ng mga lokal na LLM model: LM Studio at Ollama. Nagbibigay ang LM Studio ng GUI interface para sa paghahanap ng mga open-weight model, pag-install sa mga ito, at pagpapatakbo sa mga ito. Mahusay itong paraan para madaling makapagsimula. Nag-aalok ang Ollama ng CLI para gawin din ito nang katulad. Pero kung bago ka sa mga lokal na modelo, magsisimula ako sa LM Studio. Maaari mong i-install ang alinman sa ilalim ng _Install > AI_ sa Omarchy Menu.

### Ang mga skill ng Omarchy

Tinutulungan ng mga agent skill ang AI na gumamit ng mga partikular na tool sa isang partikular na paraan, at nagbibigay ang Omarchy ng pito sa mga ito. Sinasaklaw ng omarchy skill ang pag-aangkop ng system, tulad ng pag-tweak ng Hyprland config mo o pag-aayos ng bar. Sinasaklaw ng omarchy-make-theme, omarchy-make-plugin, omarchy-make-app, at omarchy-make-game ang paggawa ng bagong bagay, sinasaklaw ng omarchy-contribute ang pag-uulat ng isang bug o pagpapadala ng isang fix sa upstream, at ginagabayan ng omarchy-diagnose-crash ang isang core dump ng crash. Naka-symlink ang mga ito sa mga skill directory para sa Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` at bawat `~/.hermes/profiles/*/skills`), at ang generic na lokasyon ng `~/.agents/skills`, kaya awtomatikong nakukuha ang mga ito ng karamihan sa mga harness. Mas nangingibabaw ang isang skill folder mo na may parehong pangalan.

Pero dapat mong ituring na eksperimental ang mga skill na ito. Magagamit ito ng iba't ibang modelo sa iba't ibang bisa. Pinakamabuting tumakbo muna sa plan mode, para magkaroon ka ng ideya kung ano ang gustong baguhin ng agent. At pagkatapos ay maging handang i-rollback ang mga pagbabago o tawagin pa ang `omarchy reinstall configs`, kung guluhin ng agent ang lahat.
