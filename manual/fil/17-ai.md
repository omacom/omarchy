### Pag-install at pag-update ng mga agent

Maliban sa Hermes, ginagamit ng mga agent na ito ang lazy installation ng mise: ini-install ng unang paglunsad ang CLI, at muling ginagamit ito ng mga susunod na paglunsad. Sinusuri rin ng mise ang isang naka-install na agent para sa bagong release nang hindi hihigit sa isang beses bawat apat na oras, bago ito magsimula o sa background sa isang shell prompt. Kung mabigo ang update na iyon o offline ka, tatakbo ang naka-install na bersiyon. Ina-update ng `omarchy update` ang mga naka-install na agent kasama ang iba pang bahagi ng Omarchy, at ina-update ng `mup` ang mga tool na pinamamahalaan lamang ng mise.

Hindi ina-update ng sariling updater ng isang agent, gaya ng `claude update`, `codex update`, o isang update button sa isang app, ang install na pinamamahalaan ng mise. Nabibigo ang `codex update`, at maaaring mag-ulat ng tagumpay ang `claude update` habang nag-i-install ng hiwalay na kopyang hindi sinusubaybayan ng mise. Kung mas gusto mong gamitin ang native installer at updater ng isang agent, idagdag ito sa `disable_tools`; tingnan ang [Preinstalled CLI tools](18-development-tools.md#preinstalled-cli-tools).

Para i-install ang lahat ng naka-configure na lazy tool bago mo kailanganin ang mga ito, patakbuhin ang `mise install --include-lazy`. Kasama rito ang iba pang default na CLI tool ng Omarchy pati na rin ang mga agent. Tingnan ang [Preinstalled CLI tools](18-development-tools.md#preinstalled-cli-tools) para sa pag-install ng iisang tool o paggamit ng sarili mong installation.

Ini-install ang `grok` sa pamamagitan ng first-party `grok` package ng mise, sa parehong paraan gaya ng `claude` at `codex`. Patakbuhin ang `grok`, o piliin ito sa ilalim ng _Setup > Defaults > Agent_. Laktawan ang `curl | bash` installer sa x.ai. Naglalagay ang paraang iyon ng pangalawang kopya sa `~/.grok/bin`, inuuna ito sa `PATH`, at pinapatungan ang wrapper ng Omarchy.

Binubuksan ng `dsh` ang browser UI nito sa `127.0.0.1:3080`, na ang launch directory ang default workspace nito. Walang kinukuhang panimulang prompt ang browser UI nito, kaya binubuksan ito ng `omarchy agent prompt` na nasa clipboard mo ang prompt para i-paste. Sinisimulan ito ng Omarchy gamit ang no-approval permission preset ng DeepSeek. Nag-a-upload ang DeepSeek Harness ng mga session log sa DeepSeek kapag ginagamit mo ang opisyal nitong model API; i-off iyon sa ilalim ng _Settings > General > Upload Session Log_ sa browser UI nito. Ang feedback na ipinapadala mo rito ay ina-upload din kasama ng session, maliban kung sisimulan mo ito gamit ang `DSH_TELEMETRY_MODE=DISABLED`.

### Ang default na agent

Piliin ang default agent mo gamit ang `omarchy default agent <name>` o sa ilalim ng _Setup > Defaults > Agent_ sa Omarchy Menu (`Super + Space`). Kung hindi pa naka-install ang agent, i-install muna ito ng pagpili rito. Aanyayahan ka ng isang bagong Omarchy na gawin ang pagpiling ito gamit ang isang one-time notification.

Sinusubukan ding i-set up ng pagpili sa Claude ang browser extension nito para sa Chromium, Chrome, Brave, Brave Origin, at Edge. Nalalapat ang extension setup sa lahat ng user at maaaring humingi ng system password mo; pipiliin at ilulunsad pa rin ang Claude kahit kanselahin mo o mabigo ang pag-install ng extension. I-restart ang browser mo, i-enable ang extension kung sinabihan, at mag-sign in sa Claude para tapusin ang pagkonekta rito. Patakbuhin ang `/chrome` sa Claude para suriin ang koneksiyon. Hindi sinusuportahan ng Firefox at Zen ang extension na ito. Kung Claude na ang default mo bago pa idinagdag ang setup na ito, piliin itong muli para i-install ang extension.

Kapag nakapili ka na, ilulunsad ng `Super + Shift + Ctrl + A` ang default agent sa isang nakalaang terminal window (o ilalabas ang picker kung hindi ka pa nakakapili). Maaari mo rin itong ilunsad nang diretso sa isang gawain gamit ang `omarchy agent prompt "Review this project"`. Walang kinukuhang panimulang prompt ang Freebuff at DeepSeek Harness, kaya sa halip ay bubukas ang mga ito na nasa clipboard mo ang prompt para i-paste. Tumatakbo ang mga agent na inilunsad sa ganitong paraan nang walang nag-aasikaso sa kanila sa kani-kanilang don't-stop-to-ask mode, kaya maghanda kang talagang may gagawin ang mga ito! Walang ganoong mode ang MiniMax Code para sa mga interactive session nito, kaya humihingi ito ng mga pahintulot gaya ng dati. At dahil tumatanggi ang mga agent na tandaan ang trust para sa home directory mo, sa halip ay nagsisimula sa `~/Work` ang mga paglunsad mula sa `$HOME`.

May mga terminal shortcut din: pinapatakbo ng `a` ang default agent nang inline sa kasalukuyang terminal, habang sinisimulan ng `c`, `cx`, at `cy` ang OpenCode, Claude Code, at Codex nang direkta (muli sa kanilang auto-approving mode). Nagsi-sync din ang mga pagbabago ng tema sa mga agent: sumusunod ang Claude Code, Pi, OpenCode, at Hermes (kapag na-install na ito ng Omarchy) kapag nagpapalit ka ng tema ng Omarchy.

### Ang panel ng mga agent

Ang top bar ay may icon ng mga agent. Bago ka makapag-set up ng agent, gagabayan ka ng panel nito sa pag-sign in sa Claude, Codex, o Grok, at ang unang iyon ang magiging default agent mo. Pagkatapos niyon, inilalagay ng panel ang bawat subscription sa isang pahina: bawat agent at account kasama ang plan nito, isang meter para sa bawat 5-hour session at weekly limit nito kasama ang oras hanggang mag-reset ito (i-hover para sa eksaktong porsiyento), o ang natitirang prepaid balance, sa ilalim ng isang linyang nagpapalipat-lipat sa kung ano ang nagamit mo sa lahat ng ito, gaya ng mga token ngayong linggo at ang pinakamadalas mong gamiting modelo. Sa ilalim ng _Make something_ nag-aalok ito ng mga starter prompt para sa isang bagong tema, plugin, o app na nagbibigay ng gawain sa default agent mo. Ginagawa ang mga app sa paraang ginawa ang sariling Hype, Monologue, at Omacut ng Omarchy, sa C++ at Qt Quick, na sumusunod sa omarchy-app agent skill, at kasamang naka-install ang compiler at mga piraso ng Qt na kailangan nila. Saklaw agad ang Claude Code, Codex, Grok, Kimi, Cursor at ang Grok Bot allowance nito, GitHub Copilot, Muse, Antigravity, Kimchi, at Devin kasama ang kanilang mga limit, at ipinapakita ng Hermes, Mistral Vibe, at Qwen Code ang kanilang mga session at token kapag nagamit mo na ang mga ito. Ipinapakita rin ang mga provider plan at key na ginagamit mo sa pamamagitan ng pi, omp, o opencode: OpenCode Zen at Go, ang Z.ai GLM Coding Plan, Ollama Cloud, ang MiniMax Token Plan, at Synthetic kasama ang kanilang mga limit; Fireworks, OpenRouter, at DeepSeek kasama ang kanilang prepaid balance; at ang mga modelong pinapatakbo mo sa sarili mong hardware sa ilalim ng Local models. Bawat agent ay binibilang nang isang beses, sa ilalim ng kung sino ang naniningil para dito, gaano man karaming harness ang pagdaanan mo rito.

I-left-click ang icon sa bar para sa panel, i-right-click para ilunsad ang default agent mo. Ang mga usage record sa likod nito ay muling ginagawa bawat 15 minuto ng `omarchy agent usage-update`, at maaari pang pagsamahin ng panel ang usage mula sa iba mo pang machine sa pamamagitan ng isang naka-sync na folder. Tingnan ang README sa ilalim ng `$OMARCHY_PATH/shell/plugins/agents/` para sa buong mga setting.

### Maraming subscription

Kung nagbabayad ka para sa higit sa isang Claude, Codex, o Grok plan — halimbawa isang personal na Max at isang pangtrabaho — maaaring panatilihing naka-sign in ng Omarchy ang lahat ng ito at lumipat-lipat sa pagitan nila. Magdagdag ng subscription gamit ang + sa panel ng mga agent, na gagabay sa iyo roon mismo, o gamit ang `omarchy agent account add claude Work` (o `codex`, o `grok`). Ini-install nito ang CLI kung nawawala ito. Ang unang account para sa isang provider ay nagsa-sign in sa pamamagitan ng normal mong browser, kung saan palaging tumitingin ang CLI. Bawat kasunod ay nagsa-sign in sa pamamagitan ng isang private window, kaya hindi aksidenteng makukuha ang account na naka-sign in na sa browser mo; mag-sign in doon bilang account na idinaragdag mo, at isara muna ang anumang private window na nakabukas na. Huwag kailanman mag-log out sa CLI para gawin ito: binabawi ng pag-log out ang naka-save na sign-in, at kailangang idagdag muli ang account na iyon.

Para kopyahin ang mga subscription login mo sa isa pang Omarchy machine sa pamamagitan ng SSH, patakbuhin ang `omarchy agent account copy user@laptop`. Nagbibigay ang sender ng pansamantalang receiver kapag walang naka-install ang destinasyon, kaya makakatanggap ng mga account ang mas lumang Omarchy machine nang walang update. Inuuna ang mga naka-install na receiver. Kinokopya nito ang lahat ng subscription ng Claude, Codex, at Grok; magdagdag ng mga pangalan ng provider para piliin ang mga ito, gaya ng sa `omarchy agent account copy laptop claude`. Tumutugma ang mga pangalan ng account at command ID sa pinagmulan, kasama ang mga account na mayroon na sa destinasyon. Nakatatanggap ang mga hindi kaugnay na account sa destinasyon ng numeric suffix kung magkasalungat ang kanilang mga pangalan, at nananatiling lokal sa bawat machine ang mga setting, skill, plugin, at history ng pag-uusap.

Pinapanatili ang mga umiiral na credential sa destinasyon. Ang isang source account na naka-sign in na roon ay pina-sync ang pangalan nito nang hindi pinapalitan ang mga credential nito; idinaragdag ang iba pang account sa tabi nito. Para palitan ang mga naka-save na credential para sa magkatugmang account, gamitin ang `omarchy agent account copy --replace laptop claude` pagkatapos isara ang mga session ng account na iyon sa destinasyon. Nakatatanggap din ang isang bagong destinasyon ng aktibong account at mga kagustuhan sa paglipat ng pinagmulan; pinapanatili ng isang matagal nang destinasyon ang sarili nito.

Naglalakbay ang mga credential sa pamamagitan ng SSH at nakaimbak sa mga pribadong file sa destinasyon, kaya kumopya lamang sa mga machine na pinagkakatiwalaan mo. Ito ay isang beses na pagkopya, hindi patuloy na synchronization. Maaaring i-rotate ng isa pang machine ang mga Codex refresh token, na mag-iiwan sa isang nakopyang login na nangangailangan ng pag-renew; ang magkahiwalay na pag-sign in pa rin ang pinaka-maaasahang pagpipilian para sa sabay-sabay na paggamit sa maraming machine. Tingnan ang [gabay sa account authentication ng Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Isang account bawat provider ang aktibo, at bawat bagong session ay nagsisimula bilang ito: `cx`, `cy`, isang payak na `claude`, `codex`, o `grok`, anumang inilunsad sa pamamagitan ng `omarchy agent`, at mga script o editor na nakakahanap sa CLI sa `PATH`. Lumipat gamit ang `omarchy agent account use work` (at bumalik gamit ang `omarchy agent account use main`), o sa panel sa pamamagitan ng pagpindot sa numero ng isang account at pagkatapos ay `Enter` (o pag-click sa Use button nito). Nananatili ang mga session na tumatakbo na sa account na pinagsimulan nila. Ibinabahagi sa lahat ng account ang history ng pag-uusap, mga setting, skill, at plugin, kaya nagpapatuloy ang `claude --continue` sa parehong folder kung saan ka tumigil sa bagong account.

Kapag may higit sa isang account, ipinapakita ng panel ang mga limit ng bawat account nang magkatabi, na minarkahan ang aktibo. Bilang default, inaabisuhan ka ng Omarchy kapag lumampas ang aktibong account sa 95% ng isang limit, at inililipat ka ng pag-click sa notification sa account na may pinakamaraming headroom. I-hover ang linya ng isang account sa panel at i-click ang Autoswitch na lalabas sa tabi ng Use (o pindutin ang `m`), o patakbuhin ang `omarchy agent account mode auto`, para ito na mismo ang lumipat; habang naka-on ito, pumapalit ang Autoswitch sa Use, at ibabalik ka ng pag-click dito muli sa pag-abiso. Magdagdag ng numero para baguhin ang threshold, gaya ng sa `omarchy agent account mode auto 90`. Kung lampas ang bawat account sa threshold, maririnig mo ito nang isang beses, kasama kung aling account ang unang magkakaroon ng puwang. Habang ang isang aktibong account ay nasa loob ng 15 puntos ng threshold nito (80% sa default), sinusuri ang mga limit nito bawat tatlong minuto sa halip na bawat 15.

Ipinapakita ng `omarchy agent account list` ang bawat account at ang pinakabagong mga limit nito, kinakalimutan ng `omarchy agent account remove work` ang isa, at pinapalitan ng pangalan ng `omarchy agent account rename primary Hey` ang isa (o i-click ang pangalan ng isang account sa panel). Gumagana ang mga command na ito sa mga account ng default agent mo; para maabot ang ibang provider, pangalanan muna ito, gaya ng sa `omarchy agent account use codex side`. Ang login na mayroon ka na sa `~/.claude` o `~/.codex` ay ang _Main_ account at nananatili kung nasaan ito. Ang isang account na hindi nagamit nang higit sa walong oras ay maaaring magpakita ng _Sign-in required_; i-click ito para muling i-sign in ang account na iyon mismo sa panel, o magsimula ng session dito, na nagre-refresh ng sign-in nang kusa. Ang mga MCP server na mayroon ka noong idinagdag ang isang account ay sumasama rito, ngunit ang mga idinaragdag mo mamaya gamit ang `claude mcp add` ay umaabot lamang sa account kung saan mo idinagdag ang mga ito. Hindi sumusunod sa paglipat ang Claude Desktop at mga tool na naka-configure gamit ang absolute path patungo sa isang CLI binary. Inuuna ang isang tahasang `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, o `GROK_HOME` kaysa sa napiling account.

### Pag-diagnose ng crash

Binabantayan ng Omarchy ang systemd-coredump para sa mga pag-crash ng process. Kapag may nag-segfault, makakatanggap ka ng notification na "Process crashed" — i-click ito, at ibibigay ang crash sa default agent mo kasama ang diagnose-crash skill ng Omarchy, na gagabay sa agent sa pagtatatag ng mga katotohanan mula sa core dump at pagpapasya kung sulit iulat ang crash sa upstream. Maaari mo rin itong patakbuhin nang manu-mano laban sa anumang PID mula sa `coredumpctl list` gamit ang `omarchy agent crash <pid>`.

Naka-on bilang default ang pagbabantay. I-off ito sa ilalim ng _Trigger > Toggle > Crash Capture_ (o gamit ang `omarchy toggle crash-capture`) at titigil ang mga notification; gumagana pa rin nang manu-mano ang `omarchy agent crash <pid>`.

Maaari ring patahimikin ang mga crash nang paisa-isa bawat programa, na siyang inaalok sa iyo ng diagnosis sa dulo. Pinipigilan ng `omarchy crash mute hyprland` ang mga notification para lamang sa programang iyon, ibinabalik sila ng `omarchy crash mute hyprland off`, at inililista ng `omarchy crash mute` nang mag-isa kung ano ang na-mute mo. Tinatanggap nito ang path ng binary nang kasingdali ng pangalan nito, kaya pareho ang ginagawa ng `omarchy crash mute /usr/bin/hyprland`. Mag-quote ng pangalang may espasyo, gaya ng sa `omarchy crash mute 'Some App'`. Nag-aabiso pa rin ang lahat ng iba, at nagka-crash pa rin ang na-mute na programa — itinatago nito ang paalala, hindi nito inaayos ang anuman.

### Mga desktop app

May dala ring ilang graphical AI app ang menu na _Install > AI_: ang ChatGPT desktop app, ang Claude desktop app (Linux beta ng Anthropic, na may mga tab na Chat, Cowork, at Claude Code), Grok Bot para makipag-chat sa mga modelo ng xAI, Herdr Desktop, Hermes Desktop, OpenClaw, ang Perplexity desktop app, at T3 Code. Ang Grok Bot ay ang desktop chat app. Ang coding agent ay ang command na `grok`.

Ang Hermes Desktop ang dapat mong malaman, dahil iisa lang ang Hermes ng isang machine, at pag-aari ito ng app: ini-install lang ang Hermes sa pamamagitan ng app kailanman, at ang command na `hermes` na pinapatakbo ng default agent ay pag-aari ng app. Ang pagpili sa Hermes bilang default agent ay nag-i-install ng parehong bagay na ginagawa ng entry na _Install > AI_: ang package, at isang Hermes runtime sa ilalim ng `~/.hermes` na sine-set up ng sariling installer ng Hermes, na tumatagal ng ilang minuto sa unang pagkakataon. Ang runtime na iyon ang iisang Hermes na ginagamit ng terminal command na `hermes`, ng default agent at ng app, at ina-update nito ang sarili gamit ang `hermes update` sa halip na maghintay ng Omarchy release. Binibigyan din ng pag-install nito ang Hermes ng tema ng Omarchy bilang isang skin na pinangalanang `omarchy`, na sinusundan ng bawat Hermes surface habang nagpapalit ka ng tema; pumili ng iba sa ilalim ng Appearance settings ng Hermes o gamit ang `/skin` kung mas gusto mong hindi, at hindi pakikialaman ng Omarchy ang pagpipiliang iyon. Ang pag-alis ng app sa ilalim ng _Remove > AI_ ay nagsasara muna ng Hermes, kasama ang gateway, isinasama ang runtime na iyon, at pinapanatili ang iyong mga chat, memory, at ang mga skill na isinulat ng Hermes para sa sarili nito maliban kung sasabihin mong hindi: nagtatanong ito, na ang default ay hindi, kung dapat ding alisin ang data na iyon at ang iyong connection settings.

Ang desktop experience ng OpenClaw ay ang Control UI nito, na bubukas bilang isang web app na sinusuportahan ng sarili nitong local gateway. Nakatira ang OpenClaw sa `~/.openclaw` at ina-update ang sarili: gamitin ang button na "Update Gateway" ng Control UI o patakbuhin ang `openclaw update`, at magre-restart ang gateway sa bagong bersiyon. Pinipili lang ng Omarchy ang release na pagsisimulan ng isang bagong install. Ang pag-alis ng OpenClaw sa ilalim ng _Remove > AI_ ay isinasama ang gateway service at ang app at pagkatapos ay nagtatanong kung dapat ding alisin ang `~/.openclaw`, dahil naroon ang iyong mga chat at credential kasama ang OpenClaw mismo at ang mga plugin runtime na dina-download nito; pinapanatili ito ng default, at kukunin itong muli ng pag-install ulit ng OpenClaw.

Ang Herdr Desktop ay ang desktop app na [Herdr](https://herdr.dev): mga space, tab, at pane ng mga terminal at coding agent na patuloy na tumatakbo sa core nito kapag isinara mo ang window. Nagmumula ito sa sariling installer ng Herdr sa halip na sa isang package, kaya nakatira ito sa `~/.local/share/herdr-app`, dala ang core nito sa `~/.local/bin/herdr-core` kapag wala ka pa nito, at ina-update ang sarili nito pati iyon. Nakatabi ito sa command na `herdr` na kasama ng Omarchy sa `Super + Ctrl + Return` sa halip na palitan ito. Pinipili ng pag-install nito ang Omarchy theme ng Herdr, na susundan ang tema ng Omarchy mo mula noon. Nagpapanatili ang Herdr ng isang tema para sa light mode at isa para sa dark, kaya pagkatapos lumipat sa pagitan ng dark at light na tema ng Omarchy, piliin muli ang Omarchy sa theme picker ng Herdr nang isa pang beses para sa kabilang mode.

Tumatakbo ang T3 Code mula sa opisyal nitong AppImage release sa `~/.local/share/t3code` sa halip na mula sa isang package, kaya ina-update nito ang sarili. Nagtatanong ang pag-install nito kung magsisimula sa Stable o Nightly channel; lumipat mamaya sa mga setting ng T3 Code. Nakatira ang iyong mga thread at setting sa `~/.t3`, at isinasama sila ng pag-alis ng T3 Code sa ilalim ng _Remove > AI_.

### Mga lokal na modelo

Magpatakbo ng open model sa sarili mong machine para sa iyong mga coding agent. Nananatili sa machine ang iyong mga prompt at code; walang ipinapadala sa modelo ang umaalis dito. Magsimula sa:

```bash
omarchy agent local use best
```

O, sa panel ng mga agent sa top bar, piliin ang + at pagkatapos ay Local AI, na lalabas kapag kasya ang isang modelo sa machine na ito. Sa unang pagkakataon, ini-install nito ang Podman, na nagpapatakbo ng mga modelo, at sa isang NVIDIA machine ang container toolkit ng NVIDIA, na nagbibigay sa kanila ng GPU. Pagkatapos ay pipiliin ng Omarchy ang inirerekomendang modelo para sa machine na ito, ida-download ito, at sisimulan ito. Asahan ang download na sampu-sampung GB at ang karamihan ng memory ng machine ay ginagamit habang tumatakbo ang modelo: gumagamit ang Flash Next ng humigit-kumulang 100 GiB kasama ang buong 256K context nito. Kung hawak ng ibang modelo ang memory na kailangan nito, sine-set up itong nakahinto, handang magsimula kapag pinahinto mo ang isa. Humihinto ang modelo sa pag-logout; patigilin mo ito mismo kapag kailangan mo ang memory para sa ibang bagay.

Ipinapakita ng `omarchy agent local list` ang mga opsiyon at ipinapaliwanag kung bakit hindi kasya ang ilan. Para mag-set up ng isa pa, patakbuhin ang `omarchy agent local use <recipe>`. Ngayon, available ang `qwen3.8-flash-next-gufo` at `qwen3.8-27b-gufo` para sa mga 128 GB Strix Halo machine; gumagamit ang 27B ng humigit-kumulang 40 GiB, kaya nag-iiwan ito ng puwang para sa iba pang trabaho. Dumarating ang mga bagong recipe at rekomendasyon kasama ng `omarchy update`, sa pamamagitan ng package.

Bawat modelong sine-set up mo ay nakakakuha ng sarili nitong linya sa panel ng mga agent, sa tabi ng iyong mga subscription: play para simulan ito, pause para patigilin ito at palayain ang memory nito, at ang terminal button para buksan ang agent mo rito. Marami ang maaaring tumakbo nang sabay kapag magkakasya sila sa memory nang magkasama; kung hindi kasya ang isa, sinasabi ng Omarchy kung aling tumatakbong modelo ang patitigilin. I-drag ang mga linya para baguhin ang pagkakasunod-sunod nila, at pindutin ang Delete sa isang napiling linya para alisin ang isang modelo at ang download nito.

Mula sa command line, pareho ang ginagawa ng `omarchy agent local start <recipe>` at `omarchy agent local stop <recipe>`, ipinapakita ng `omarchy agent local status` ang bawat modelo, at binubuksan ng `omarchy agent --local` ang default agent mo sa huling modelong sinimulan mo (pi kung hindi makagamit ng lokal na modelo ang default agent mo). Maaari ring kumonekta ang anumang OpenAI-compatible client: ipinapakita ng `status` ang address ng bawat modelo (ang una ay `http://127.0.0.1:11435/v1`), ang pangalan ng recipe ang modelo, at ang key ay nasa `~/.config/omarchy/agent-local/key`.

Tinatanggal ng `omarchy agent local remove <recipe>` ang isang modelo at ang mga download na hindi ginagamit ng ibang modelo.

Nilalagyan ng label ang mga third-party runtime ng publisher nila. Pinapatakbo ng Omarchy ang bawat modelo nang walang network access.

### Mga lokal na LLM

Inirerekomenda ng Omarchy ang dalawang paraan ng pagpapatakbo ng mga lokal na LLM model: LM Studio at Ollama. Nagbibigay ang LM Studio ng GUI interface para sa paghahanap ng mga open-weight model, pag-install sa kanila, at pagpapatakbo sa kanila. Mahusay itong paraan para madaling makapagsimula. Nag-aalok ang Ollama ng CLI para gawin ito nang katulad. Ngunit kung bago ka sa mga lokal na modelo, magsimula ako sa LM Studio. Maaari mong i-install ang alinman sa ilalim ng _Install > AI_ sa Omarchy Menu.

### Ang Omarchy Skill

Tumutulong ang mga agent skill sa AI na gumamit ng mga partikular na tool sa isang partikular na paraan, at may kasamang default skill ang Omarchy para sa pag-aangkop ng sistema. Gaya ng pag-tweak ng Hyprland config mo, pag-aayos ng bar, o kahit paglikha ng bagong tema mula sa simula. Naka-symlink ito sa mga skill directory para sa Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` at bawat `~/.hermes/profiles/*/skills`), at ang generic na lokasyong `~/.agents/skills`, kaya awtomatikong nakukuha ito ng karamihan ng harness.

Ngunit dapat mong ituring na eksperimental ang skill na ito. Gagamitin ito ng iba't ibang modelo nang may iba't ibang epekto. Pinakamainam na patakbuhin muna ito sa plan mode, para magkaroon ka ng ideya kung ano ang gustong baguhin ng agent. At pagkatapos ay maging handang i-rollback ang mga pagbabago o kahit tawagin ang `omarchy reinstall configs`, kung guluhin ng agent ang lahat.
