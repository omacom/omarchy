# AI

May kasamang mga launcher ang Omarchy para sa mga coding agent sa ibaba nang hindi pumipili ng default para sa iyo. Magpatakbo ng command para mai-install ang CLI nito sa unang paggamit, pagkatapos ay mag-authenticate kapag sinabihan. Ang Hermes at OpenClaw ang mga eksepsiyon: walang ini-install para sa kanila sa pamamagitan ng mise, at ang pagpili sa alinman ay magse-setup ng sarili nitong self-updating na kopya, gaya ng ipinapaliwanag ng _Desktop apps_ sa ibaba.

### Pag-install at pag-update ng mga agent

Maliban sa Hermes at OpenClaw, ginagamit ng mga agent na ito ang lazy installation ng mise: ini-install ng unang paglulunsad ang CLI, at muling ginagamit ito ng mga susunod na paglulunsad. Sinusuri rin ng mise ang isang naka-install na agent para sa bagong release nang hindi hihigit sa isang beses kada apat na oras, bago ito magsimula o sa background sa isang shell prompt. Kung mabigo ang update na iyon o offline ka, tatakbo ang naka-install na bersiyon. Ina-update ng `omarchy update` ang mga naka-install na agent kasama ng iba pang bahagi ng Omarchy, at ina-update ng `mup` ang mga tool na pinamamahalaan ng mise lamang.

Hindi ina-update ng sariling updater ng isang agent, tulad ng `claude update`, `codex update`, o isang update button sa isang app, ang install na pinamamahalaan ng mise. Nabibigo ang `codex update`, at maaaring mag-ulat ng tagumpay ang `claude update` habang nag-i-install ng hiwalay na kopya na hindi sinusubaybayan ng mise. Kung mas gusto mong gamitin ang native installer at updater ng isang agent, idagdag ito sa `disable_tools`; tingnan ang [Mga nakapre-install na CLI tool](18-development-tools.md#preinstalled-cli-tools).

Para mai-install ang lahat ng naka-configure na lazy tool bago mo kailanganin ang mga ito, patakbuhin ang `mise install --include-lazy`. Kasama rito ang iba pang default na CLI tool ng Omarchy pati na rin ang mga agent. Tingnan ang [Mga nakapre-install na CLI tool](18-development-tools.md#preinstalled-cli-tools) para sa pag-install ng isang tool o paggamit ng sarili mong installation.

Ini-install ang `grok` sa pamamagitan ng first-party na `grok` package ng mise, sa parehong paraan tulad ng `claude` at `codex`. Patakbuhin ang `grok`, o piliin ito sa ilalim ng _Agent > Harness_. Laktawan ang `curl | bash` installer sa x.ai. Naglalagay ang paraang iyon ng pangalawang kopya sa `~/.grok/bin`, inuuna ito sa `PATH`, at pinapatungan ang wrapper ng Omarchy.

Binubuksan ng `dsh` ang browser UI nito sa `127.0.0.1:3080`, na ang launch directory ang default workspace nito. Walang starting prompt na tinatanggap ang browser UI nito, kaya binubuksan ito ng `omarchy agent prompt` na nasa clipboard mo ang prompt para i-paste. Sinisimulan ito ng Omarchy gamit ang no-approval permission preset ng DeepSeek. Nag-a-upload ang DeepSeek Harness ng mga session log sa DeepSeek kapag ginagamit mo ang opisyal nitong model API; i-off iyon sa ilalim ng _Settings > General > Upload Session Log_ sa browser UI nito. Ang feedback na ipinapadala mo rito ay ina-upload din kasama ng session, maliban na lang kung sisimulan mo ito gamit ang `DSH_TELEMETRY_MODE=DISABLED`.

### Ang default na agent

Piliin ang default agent mo gamit ang `omarchy default agent <name>` o sa ilalim ng _Agent > Harness_ sa Omarchy Menu (`Super + Space`). Kung hindi pa naka-install ang agent, i-install muna ito ng pagpili rito, at makakakuha rin ito ng sarili nitong launcher sa app launcher, katabi ng Agent. Aanyayahan ka ng isang bagong Omarchy na gawin ang pagpiling ito gamit ang isang one-time na notification.

Sinusubukan din ng pagpili sa Claude na i-setup ang browser extension nito para sa Chromium, Chrome, Brave, Brave Origin, at Edge. Nalalapat ang extension setup sa lahat ng user at maaaring humingi ng password ng system mo; pipiliin at ilulunsad pa rin ang Claude kahit kanselahin o mabigo ang pag-install ng extension. I-restart ang browser mo, i-enable ang extension kung sinabihan, at mag-sign in sa Claude para tapusin ang pagkonekta rito. Patakbuhin ang `/chrome` sa Claude para suriin ang koneksiyon. Hindi sinusuportahan ng Firefox at Zen ang extension na ito. Kung Claude na ang default mo bago idagdag ang setup na ito, piliin itong muli para mai-install ang extension.

Kapag nakapili ka na, ilulunsad ng `Super + Shift + Ctrl + A` ang default agent sa isang nakalaang terminal window (o ilalabas ang picker kung hindi ka pa nakakapili). Maaari mo rin itong ilunsad nang diretso sa isang gawain gamit ang `omarchy agent prompt "Review this project"`. Walang starting prompt na tinatanggap ang Freebuff at DeepSeek Harness, kaya sa halip ay bubuksan ang mga ito na nasa clipboard mo ang prompt para i-paste. Tumatakbo nang walang bantay ang mga agent na inilunsad sa ganitong paraan sa kani-kanilang don't-stop-to-ask mode, kaya maging handa na talagang gumawa sila ng mga bagay! Walang ganoong mode ang MiniMax Code para sa mga interactive session nito, kaya humihingi ito ng mga pahintulot gaya ng dati. At dahil tumatanggi ang mga agent na tandaan ang tiwala para sa home directory mo, sa halip ay nagsisimula sa `~/Work` ang mga paglulunsad mula sa `$HOME`.

May mga terminal shortcut din: pinapatakbo ng `a` ang default agent nang inline sa kasalukuyang terminal, habang direktang sinisimulan ng `c`, `cx`, at `cy` ang OpenCode, Claude Code, at Codex (muli sa kanilang mga auto-approving mode). Nagsi-sync din ang mga pagbabago ng tema sa mga agent: sumusunod ang Claude Code, Pi, OpenCode, at Hermes (kapag na-install na ito ng Omarchy) kapag lumipat ka ng tema ng Omarchy.

### Ang mga tagubilin ng agent mo

Mapupunta ang mga personal na panuntunan para sa bawat agent sa `~/.agents/AGENTS.md`, katabi ng mga shared skill sa `~/.agents/skills`. Buksan ito sa ilalim ng _Agent > Instructions_, na nagli-link din nito sa bawat harness na nagpapanatili ng sarili nitong global file: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, ang `~/.copilot/copilot-instructions.md` ng Copilot, at iba pa. Binabasa ng Crush at Amp ang link na `~/.config/AGENTS.md`, habang direktang binabasa ng omp, Kimi, at DeepSeek Harness ang `~/.agents/AGENTS.md`. Ili-link din ito ng pagpili ng default agent. Ang isang instructions file na mayroon ka na ay magiging shared na file kung wala pa nito; kung hindi, mananatili ito katabi ng link bilang `.bak`. Patakbuhin ang `omarchy agent instructions` para muling mag-link pagkatapos mag-install ng isa pang agent.

### Ang panel ng mga agent

May icon ng mga agent ang top bar. Bago ka mag-setup ng isang agent, gagabayan ka ng panel nito sa pag-sign in sa Claude, Codex, o Grok, at ang una ay magiging default agent mo. Pagkatapos niyon, inilalagay ng panel ang bawat subscription sa isang pahina: bawat agent at account kasama ang plano nito, isang metro para sa bawat 5-hour session at weekly limit nito kasama ang oras hanggang mag-reset ito (mag-hover para sa eksaktong porsiyento), o ang natitirang prepaid balance, sa ilalim ng isang linya na umiikot sa kung ano ang nagamit mo sa lahat ng mga ito, tulad ng mga token ngayong linggo at ang pinakamadalas mong gamiting modelo. Sa ilalim ng _Make something cool_ nag-aalok ito ng mga starter prompt para sa bagong tema, plugin, app, o laro na nagbibigay ng gawain sa default agent mo. Binubuo ang mga app sa paraang binuo ang sariling Hype, Monologue, at Omacut ng Omarchy, sa C++ at Qt Quick, na sumusunod sa omarchy-make-app agent skill, at naka-install na ang compiler at mga piraso ng Qt na kailangan nila. Ang mga laro ay iisang three.js page sa `~/Games/vibes`, na sumusunod sa omarchy-make-game agent skill, at lahat ay bumubukas mula sa isang Game Vibes launcher sa kasalukuyang tema; nilo-load nila ang three.js mula sa web, kaya kailangan nila ng koneksiyon para magsimula. Saklaw agad ang Claude Code, Codex, Grok, Kimi, Cursor at ang Grok Bot allowance nito, GitHub Copilot, Muse, Antigravity, at Devin kasama ang kanilang mga limit, ang Kimchi kasama ang plano, prepaid credits, at spend budget nito, at ipinapakita ng Hermes, Mistral Vibe, at Qwen Code ang kanilang mga session at token kapag nagamit mo na ang mga ito. Ipinapakita rin ang mga provider plan at key na ginagamit mo sa pamamagitan ng pi, omp, o opencode: ang OpenCode Zen at Go, ang Z.ai GLM Coding Plan, Ollama Cloud, ang MiniMax Token Plan, at Synthetic kasama ang kanilang mga limit; ang OpenRouter at DeepSeek kasama ang kanilang prepaid balance; ang Fireworks kasama ang gastos nito sa nakalipas na 30 araw; at ang mga modelong pinapatakbo mo sa sarili mong hardware sa ilalim ng Local models. Binibilang nang isang beses ang bawat agent, sa ilalim ng kung sino ang naniningil para rito, gaano man karaming harness ang patakbuhin mo rito.

I-left-click ang icon sa bar o pindutin ang `Super + Ctrl + X` para sa panel, i-right-click para ilunsad ang default agent mo, at i-middle-click para mag-refresh. Ang mga usage record sa likod nito ay muling ginagawa kada 15 minuto ng `omarchy agent usage update`, at maaari pang pagsamahin ng panel ang usage mula sa iba mo pang machine sa pamamagitan ng isang naka-sync na folder. Tingnan ang README sa ilalim ng `$OMARCHY_PATH/shell/plugins/agents/` para sa buong mga setting.

### Maraming subscription

Kung nagbabayad ka para sa higit sa isang plano ng Claude, Codex, o Grok — isang personal na Max at isang pang-trabaho, halimbawa — maaaring panatilihin ng Omarchy na naka-sign in ang lahat ng mga ito at lumipat sa pagitan ng mga ito. Magdagdag ng subscription gamit ang + sa panel ng mga agent, na gagabay sa iyo roon mismo, o gamit ang `omarchy agent account add claude Work` (o `codex`, o `grok`). Ini-install nito ang CLI kung nawawala ito. Ang unang account para sa isang provider ay nagsa-sign in sa pamamagitan ng normal mong browser, mismo kung saan laging tumitingin ang CLI. Ang bawat isa pagkatapos niyon ay nagsa-sign in sa pamamagitan ng isang private window, kaya hindi aksidenteng makuha ang account na naka-sign in na sa browser mo; mag-sign in doon bilang account na idinaragdag mo, at isara muna ang anumang private window na nakabukas mo na. Huwag kailanman mag-log out sa CLI para gawin ito: binabawi ng pag-log out ang naka-save na sign-in, at kailangang idagdag muli ang account na iyon.

Para kopyahin ang mga subscription login mo sa isa pang Omarchy machine sa SSH, patakbuhin ang `omarchy agent account copy user@laptop`. Nagbibigay ang sender ng pansamantalang receiver kapag walang naka-install ang destination, kaya maaaring makatanggap ng mga account ang mas lumang mga Omarchy machine nang walang update. Nauuna ang mga naka-install na receiver. Kinokopya nito ang lahat ng subscription ng Claude, Codex, at Grok; magdagdag ng mga pangalan ng provider para piliin ang mga ito, gaya ng sa `omarchy agent account copy laptop claude`. Tumutugma ang mga pangalan ng account at command ID sa source, kasama ang mga account na naroroon na sa destination. Makakatanggap ng numeric suffix ang mga hindi kaugnay na account sa destination kung magkasalungat ang kanilang mga pangalan, at mananatiling local sa bawat machine ang mga setting, skill, plugin, at kasaysayan ng pag-uusap.

Pinapanatili ang mga umiiral nang kredensiyal sa destination. Ang isang source account na naka-sign in na roon ay mai-synchronize ang pangalan nang hindi pinapalitan ang mga kredensiyal nito; idinaragdag ang iba pang account katabi nito. Para palitan ang mga naka-save na kredensiyal para sa magkatugmang mga account, gamitin ang `omarchy agent account copy --replace laptop claude` pagkatapos isara ang mga session ng account na iyon sa destination. Makukuha rin ng isang bagong destination ang active account at mga kagustuhan sa paglipat ng source; pinapanatili ng isang matagal nang destination ang sarili nito.

Naglalakbay ang mga kredensiyal sa SSH at nakaimbak sa mga private file sa destination, kaya kumopya lamang sa mga machine na pinagkakatiwalaan mo. Isa itong one-time na kopya, hindi patuloy na synchronization. Maaaring i-rotate ng ibang machine ang mga Codex refresh token, na mag-iiwan sa isang nakopyang login na nangangailangan ng pag-renew; ang magkakahiwalay na sign-in ay nananatiling pinaka-maaasahang pagpipilian para sa sabay-sabay na paggamit sa maraming machine. Tingnan ang [gabay sa pagpapatotoo ng account ng Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Isang account bawat provider ang active, at bawat bagong session ay nagsisimula bilang ito: `cx`, `cy`, isang payak na `claude`, `codex`, o `grok`, anumang inilunsad sa pamamagitan ng `omarchy agent`, at mga script o editor na nakakahanap sa CLI sa `PATH`. Lumipat gamit ang `omarchy agent account use work` (at bumalik gamit ang `omarchy agent account use main`), o sa panel sa pamamagitan ng pagpindot sa numero ng isang account at pagkatapos ay `Enter` (o pag-click sa Use button nito). Lumilipat din ang mga tumatakbong Claude session, mula sa kanilang susunod na mensahe: tumatakbo ang bawat Claude session sa `~/.claude`, na laging naglalaman ng sign-in ng active account. Ang isang Claude session na sinimulan sa sariling folder ng isang account ng isang mas lumang Omarchy ay nagpapanatili ng sign-in na iyon hanggang sa umalis ito, kaya pinapangalanan ng paglipat ang mga session na iyon at matatapos nang kusa kapag wala na ang mga ito. Mananatili ang mga tumatakbong Codex at Grok session sa account na pinagsimulan nila. Ibinabahagi sa lahat ng account ang kasaysayan ng pag-uusap, mga setting, skill, at plugin, kaya ang `claude --continue` sa parehong folder ay nagpapatuloy kung saan ka tumigil sa bagong account.

Kapag may higit sa isang account, ipinapakita ng panel ang mga limit ng bawat account nang magkatabi, na minarkahan ang active. Bilang default, inaabisuhan ka ng Omarchy kapag lumampas ang active account sa 95% ng isang limit, at ang pag-click sa notification ay lumilipat sa account na may pinakamaraming headroom. Mag-hover sa linya ng isang account sa panel at i-click ang Autoswitch na lalabas katabi ng Use (o pindutin ang `m`), o patakbuhin ang `omarchy agent account mode auto`, para lumipat ito nang kusa sa halip; habang naka-on ito, pumapalit ang Autoswitch sa Use, at ang pag-click muli rito ay bumabalik sa pag-aabiso. Magdagdag ng numero para baguhin ang threshold, gaya ng sa `omarchy agent account mode auto 90`. Kung lahat ng account ay lampas sa threshold, maririnig mo ang tungkol dito nang isang beses, kasama kung aling account ang unang magkakaroon ng puwang. Habang ang isang active account ay nasa loob ng 15 puntos ng threshold nito (80% sa default), sinusuri ang mga limit nito kada tatlong minuto sa halip na kada 15.

Ipinapakita ng `omarchy agent account list` ang bawat account at ang pinakabagong mga limit nito, nakakalimutan ng `omarchy agent account remove work` ang isa, at pinapalitan ng pangalan ng `omarchy agent account rename primary Hey` ang isa (o i-click ang pangalan ng isang account sa panel). Gumagana ang mga command na ito sa mga account ng default agent mo; para maabot ang ibang provider, pangalanan muna ito, gaya ng sa `omarchy agent account use codex side`. Ang login na mayroon ka na sa `~/.claude` o `~/.codex` ay ang _Main_ account. Mananatili ang sa Codex kung saan ito naroroon; naghihintay ang sa Claude sa sarili nitong folder habang may ibang account na active. Ang isang account na hindi nagamit nang higit sa walong oras ay maaaring magpakita ng _Sign-in required_; i-click ito para muling i-sign in ang account na iyon mismo sa panel, o lumipat dito at magsimula ng session, na nagre-refresh ng sign-in nang kusa. Ang mga MCP server na idinaragdag mo gamit ang `claude mcp add` ay umaabot sa bawat Claude account, dahil lahat sila ay tumatakbo sa `~/.claude`; para sa Codex at Grok, ang mga server na mayroon ka noong idagdag ang isang account ay sumasama rito, pero ang mga susunod ay umaabot lamang sa account kung saan mo idinagdag ang mga ito. Nagpapanatili ang Claude Desktop ng sarili nitong sign-in, at ang mga Codex o Grok tool na naka-configure na may absolute path patungo sa isang CLI binary ay hindi sumusunod sa paglipat. Nauuna ang isang tahasang `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, o `GROK_HOME` kaysa sa napiling account.

### Pag-diagnose ng crash

Binabantayan ng Omarchy ang systemd-coredump para sa mga pag-crash ng proseso. Kapag nakapili ka na ng default agent, ang anumang programa mo na mag-dump ng core ay magdadala ng notification na "Process crashed" — i-click ito, at ibibigay ang crash sa default agent mo kasama ang omarchy-diagnose-crash skill ng Omarchy, na gagabay sa agent sa pagtatatag ng mga katotohanan mula sa core dump at pagpapasya kung karapat-dapat bang iulat ang crash sa upstream. Maaari mo rin itong patakbuhin nang mano-mano laban sa anumang PID mula sa `coredumpctl list` gamit ang `omarchy agent crash <pid>`.

Naka-on bilang default ang pagbabantay. I-off ito sa ilalim ng _Trigger > Toggle > Crash Capture Off_ (o gamit ang `omarchy toggle crash-capture`) at hihinto ang mga notification; gumagana pa rin nang mano-mano ang `omarchy agent crash <pid>`.

Maaari ring patahimikin ang mga crash nang paisa-isang programa, na siyang inaalok sa iyo ng diagnosis sa dulo. Pinipigilan ng `omarchy crash mute hyprland` ang mga notification para sa programang iyon lamang, ibinabalik sila ng `omarchy crash mute hyprland off`, at inililista ng `omarchy crash mute` nang mag-isa kung ano ang na-mute mo. Tinatanggap nito ang path ng binary nang kasingsaya ng pangalan nito, kaya pareho ang ginagawa ng `omarchy crash mute /usr/bin/hyprland`. Mag-quote ng pangalang may espasyo, gaya ng sa `omarchy crash mute 'Some App'`. Nag-aabiso pa rin ang lahat ng iba pa, at nagka-crash pa rin ang na-mute na programa — itinatago nito ang paalala, hindi nito inaayos ang anuman.

### Mga desktop app

May dala rin ang menu na _Install > AI_ ng ilang graphical AI app: Amp Desktop, Antigravity Desktop, ang ChatGPT desktop app, ang Claude desktop app (ang Linux beta ng Anthropic, na may mga tab na Chat, Cowork, at Claude Code), Grok Bot para sa pakikipag-chat sa mga modelo ng xAI, Herdr Desktop, Hermes Desktop, OpenClaw, ang Perplexity desktop app, at T3 Code. Ang Grok Bot ay ang desktop chat app. Ang coding agent ay ang command na `grok`.

Ang Hermes Desktop ang dapat mong malaman, dahil iisa lang ang Hermes ng isang machine, at sa app ito: ini-install lamang ang Hermes sa pamamagitan ng app, at ang command na `hermes` na pinapatakbo ng default agent ay sa app. Ang pagpili sa Hermes bilang default agent ay nag-i-install ng parehong bagay na ini-install ng entry na _Install > AI_: ang package, at isang Hermes runtime sa ilalim ng `~/.hermes` na sine-setup ng sariling installer ng Hermes, na tumatagal ng ilang minuto sa unang pagkakataon. Ang runtime na iyon ang nag-iisang Hermes na ginagamit ng terminal command na `hermes`, ng default agent at ng app, at ina-update nito ang sarili gamit ang `hermes update` sa halip na maghintay sa isang Omarchy release. Ibinibigay din ng pag-install nito sa Hermes ang tema ng Omarchy bilang isang skin na pinangalanang `omarchy`, na sinusundan ng bawat Hermes surface habang nagpapalit ka ng tema; pumili ng iba sa ilalim ng Appearance settings ng Hermes o gamit ang `/skin` kung mas gusto mong hindi, at hahayaan ng Omarchy ang pagpipiliang iyon. Ang pag-alis ng app sa ilalim ng _Remove > AI_ ay nagsasara muna sa Hermes, kasama ang gateway, isinasama ang runtime na iyon, at pinapanatili ang iyong mga chat, memory, at ang mga skill na isinulat ng Hermes para sa sarili maliban na lang kung sasabihin mo ang kabaligtaran: nagtatanong ito, na ang default ay hindi, kung dapat ding mawala ang data na iyon at ang iyong mga connection setting.

Ang desktop experience ng OpenClaw ay ang Control UI nito, na bumubukas bilang isang web app na sinusuportahan ng sarili nitong local gateway. Nakatira ang OpenClaw sa `~/.openclaw` at ina-update ang sarili: gamitin ang button na "Update Gateway" ng Control UI o patakbuhin ang `openclaw update`, at magre-restart ang gateway sa bagong bersiyon. Pinipili lamang ng Omarchy ang release na pagsisimulan ng isang bagong install. Maaari ring maging default agent mo ang OpenClaw: ang pagpili rito sa ilalim ng _Agent > Harness_ ay nagse-setup ng parehong kopya sa `~/.openclaw`, at binubuksan ng agent ang terminal UI ng OpenClaw na nakakabit sa gateway nito. Ang pag-alis ng OpenClaw sa ilalim ng _Remove > AI_ ay isinasama ang gateway service at ang app at pagkatapos ay nagtatanong kung dapat ding mawala ang `~/.openclaw`, dahil naroroon ang iyong mga chat at kredensiyal kasama ng OpenClaw mismo at ng mga plugin runtime na dina-download nito; pinapanatili ito ng default, at ang muling pag-install ng OpenClaw ay kukunin itong muli.

Ang Herdr Desktop ay ang desktop app na [Herdr](https://herdr.dev): mga space, tab, at pane ng mga terminal at coding agent na patuloy na tumatakbo sa core nito kapag isinara mo ang window. Nagmumula ito sa sariling installer ng Herdr sa halip na sa isang package, kaya nakatira ito sa `~/.local/share/herdr-app`, isinasama ang core nito sa `~/.local/bin/herdr-core` kapag wala ka pa nito, at ina-update ang sarili nitong dalawa. Nakatabi ito sa command na `herdr` na ibinibigay ng Omarchy sa `Super + Ctrl + Return` sa halip na palitan ito, at nakukuha ang mga direct key ng command na iyon: hinahati ng `Alt + Return` at `Alt + Shift + Return` ang isang pane pababa o pakanan, isinasara ito ng `Alt + Escape`, gumagalaw ang `Ctrl + Alt + Arrow` sa pagitan ng mga pane, pumipili ng tab ang `Alt + 1..9` at `Alt + Left/Right`, at gumagalaw ang `Alt + Up/Down` sa pagitan ng mga space. Pumipili ng space ang `Ctrl + 1..9` at humahakbang ang `Alt + Shift + Up/Down` sa mga agent. Mananatiling terminal-only ang mga prefix key na `Ctrl + Space`, dahil hindi kayang hawakan ng app ang isang payak na Ctrl key para sa isang sequence. Isinusulat ito ng Omarchy sa `~/.config/herdr-app/keys.json`, at ibinabalik sila ng `omarchy-refresh-herdr-app`. Pinipili ng pag-install nito ang Omarchy theme ng Herdr, na susunod sa tema ng Omarchy mo mula noon. Nagpapanatili ang Herdr ng isang tema para sa light mode at isa para sa dark, kaya pagkatapos lumipat sa pagitan ng isang dark at isang light na tema ng Omarchy, piliin muli ang Omarchy sa theme picker ng Herdr nang isang beses pa para sa kabilang mode.

Tumatakbo ang T3 Code mula sa opisyal nitong AppImage release sa `~/.local/share/t3code` sa halip na mula sa isang package, kaya ina-update nito ang sarili. Nagtatanong ang pag-install nito kung magsisimula sa Stable o Nightly channel; lumipat mamaya sa mga setting ng T3 Code. Nakatira ang iyong mga thread at setting sa `~/.t3`, at isinasama sila ng pag-alis ng T3 Code sa ilalim ng _Remove > AI_.

### Mga local model

Magpatakbo ng isang open model sa sarili mong machine para sa mga coding agent mo. Mananatili sa machine ang iyong mga prompt at code; walang ipinapadala sa modelo ang aalis dito. Magsimula sa:

```bash
omarchy models use best text
```

O, sa panel ng mga agent sa top bar, piliin ang + at pagkatapos ang Local AI, na lumilitaw kapag may modelong kasya sa machine na ito. Kasama ng Omarchy ang Podman, na nagpapatakbo ng mga modelo, gayundin ang container toolkit ng NVIDIA sa isang NVIDIA machine, na nagbibigay sa kanila ng GPU; kung nawawala ang alinman, i-install ito ng unang setup. Pagkatapos ay pipiliin ng Omarchy ang inirerekomendang modelo para sa machine na ito, ida-download ito, at sisimulan ito. Asahan ang download na sampu-sampung GB at ang karamihan ng memory ng machine ay ginagamit habang tumatakbo ang modelo: gumagamit ang Flash Next ng humigit-kumulang 100 GiB sa buong 256K context nito. Kung hawak ng iba pang modelo ang memory na kailangan nito, sine-setup itong nakahinto, handang magsimula kapag pinahinto mo ang isa. Humihinto ang modelo sa pag-logout; pahintuin mo ito mismo kapag kailangan mo ang memory para sa iba pang bagay.

Ipinapakita ng `omarchy models list` ang mga opsiyon at ipinapaliwanag kung bakit hindi kasya ang ilan. Para mag-setup ng isa pa, patakbuhin ang `omarchy models use <recipe>`. Ngayon, available ang `qwen3.8-flash-next-gufo` at `qwen3.8-27b-gufo` para sa 128 GB Strix Halo machines; gumagamit ang 27B ng humigit-kumulang 40 GiB, kaya nag-iiwan ito ng puwang para sa iba pang trabaho. Sa isang 64 GB laptop na may Intel's Arc B390, tumatakbo ang `qwen3.6-35b-a3b-llamacpp` sa humigit-kumulang 30 GiB. Dumarating ang mga bagong recipe at rekomendasyon kasama ng `omarchy update`, sa pamamagitan ng package.

Bawat modelong sine-setup mo ay nakakakuha ng sarili nitong linya sa panel ng mga agent, katabi ng iyong mga subscription: play para simulan ito, pause para pahintuin ito at palayain ang memory nito, at ang terminal button para buksan ang agent mo rito. Maaaring tumakbo ang ilan nang sabay kapag magkakasya sila sa memory nang magkasama; kung hindi kasya ang isa, sasabihin ng Omarchy kung aling tumatakbong modelo ang pahihintuin. I-drag ang mga linya para muling ayusin sila, at pindutin ang Delete sa isang napiling linya para alisin ang isang modelo at ang download nito.

Bawat modelong sine-setup mo ay nakakakuha rin ng sarili nitong entry sa app launcher, sa ilalim ng pangalan ng modelo at kasama ang logo ng gumawa nito, sa paraang nagdaragdag ng isa ang pag-sign in sa Claude, Codex o Grok. Binubuksan nito ang agent mo sa modelong iyon, at sinisimulan muna ang modelo kung hindi ito tumatakbo: ipinapakita ng terminal na naglo-load ito at ibibigay sa agent kapag handa na ito. Ang pag-alis ng isang modelo ay nag-aalis ng entry nito.

Hindi lahat ng modelo ay para sa coding. Sa halip ay bumubukas sa Fantasi ang mga image, video at music model, ang app ng Omarchy para sa paggawa ng mga larawan, video at musika gamit ang isang modelong tumatakbo sa machine na ito, mula sa kanilang launcher entry at mula sa kanilang linya sa panel ng mga agent.

Mananatiling tumatakbo ang isang modelo nang eksakto kung paano ito sine-setup, kaya hindi kailanman magre-restart ang isang Omarchy update ng isa sa ilalim ng mga agent mo. Kapag may mas bagong runtime o mas bagong weights ang Omarchy para sa isang modelong sine-setup mo, nagpapakita ang linya nito ng update button: pindutin ito at muling sine-setup ang modelo sa background, dina-download lamang ang nagbago, at magre-restart sa bagong bersiyon. Mananatiling nakahinto ang isang modelong nakahinto. Ginagawa ng `omarchy models update` ang pareho para sa bawat modelo mula sa isang terminal.

Mula sa command line, ginagawa ng `omarchy models start <recipe>` at `omarchy models stop <recipe>` ang pareho, ipinapakita ng `omarchy models status` ang bawat modelo, at binubuksan ng `omarchy agent --local` ang default agent mo sa huling modelong sinimulan mo. Maaaring gumamit ng isa ang pi, OpenCode at Qwen Code; sa anumang ibang default ay bumubukas ito sa pi, o sa OpenCode kung wala kang pi. Inililista rin ng pi ang bawat modelong sine-setup mo, at ang mga nasa machine na ipinares mo, sa sarili nitong model picker, kaya naaabot din sila ng payak na `pi`. Maaari ring kumonekta ang anumang OpenAI-compatible client: ipinapakita ng `status` ang address ng bawat modelo (ang una ay `http://127.0.0.1:11435/v1`), ang pangalan ng recipe ang modelo, at ang key ay nasa `~/.config/omarchy/agent-local/key`.

Binubura ng `omarchy models remove <recipe>` ang isang modelo at ang mga download na hindi ginagamit ng ibang modelo.

Nilalagyan ng label ng kanilang publisher ang mga third-party runtime. Pinapatakbo ng Omarchy ang bawat modelo nang walang network access.

### Mga local LLM

Inirerekomenda ng Omarchy ang dalawang paraan ng pagpapatakbo ng mga local LLM model: LM Studio at Ollama. Nagbibigay ang LM Studio ng GUI interface para sa paghahanap ng mga open-weight model, pag-install sa kanila, at pagpapatakbo sa kanila. Mahusay itong paraan para madaling makapagsimula. Nag-aalok ang Ollama ng CLI para gawin din ito. Pero kung bago ka sa mga local model, magsisimula ako sa LM Studio. Maaari mong i-install ang alinman sa ilalim ng _Install > AI_ sa Omarchy Menu.

### Ang mga Omarchy skill

Tinutulungan ng mga agent skill ang AI na gumamit ng mga partikular na tool sa isang partikular na paraan, at may pitong ganoon ang Omarchy. Sinasaklaw ng omarchy skill ang pag-aangkop ng system, tulad ng pag-tweak ng Hyprland config mo o pag-aadjust ng bar. Sinasaklaw ng omarchy-make-theme, omarchy-make-plugin, omarchy-make-app, at omarchy-make-game ang paggawa ng bagong bagay, sinasaklaw ng omarchy-contribute ang pag-uulat ng bug o pagpapadala ng fix sa upstream, at pinoproseso ng omarchy-diagnose-crash ang core dump ng isang crash. Naka-symlink sila sa mga skill directory para sa Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` at bawat `~/.hermes/profiles/*/skills`), at ang generic na lokasyong `~/.agents/skills`, kaya awtomatikong nakukuha sila ng karamihan sa mga harness. Nauuna ang isang skill folder mo na may parehong pangalan.

Pero dapat mong ituring na experimental ang mga skill na ito. Gagamitin sila ng iba't ibang modelo nang may iba't ibang epekto. Pinakamainam na tumakbo muna sa plan mode, para magkaroon ka ng ideya kung ano ang gustong baguhin ng agent. At pagkatapos ay maging handang i-rollback ang mga pagbabago o kahit tawagin ang `omarchy reinstall configs`, kung guluhin ng agent ang lahat.
