### Pag-install at pag-update ng mga agent

Maliban sa Hermes, gumagamit ang mga agent na ito ng lazy installation ng mise: ang unang paglulunsad ang nag-i-install ng CLI, at muling ginagamit ito ng mga susunod na paglulunsad. Sinusuri rin ng mise ang isang naka-install na agent para sa bagong release nang hindi hihigit sa isang beses kada apat na oras, bago pa lang ito magsimula o sa background sa isang shell prompt. Kung mabigo ang update na iyon o offline ka, tatakbo ang naka-install na bersyon. Ina-update ng `omarchy update` ang mga naka-install na agent kasama ang iba pa sa Omarchy, at ina-update lamang ng `mup` ang mga tool na pinamamahalaan ng mise.

Hindi ina-update ng sariling updater ng isang agent, gaya ng `claude update`, `codex update`, o ng update button sa isang app, ang install na pinamamahalaan ng mise. Nabibigo ang `codex update`, at maaaring mag-ulat ng tagumpay ang `claude update` habang nag-i-install ng hiwalay na kopya na hindi sinusubaybayan ng mise. Kung mas gusto mong gamitin ang native na installer at updater ng isang agent, idagdag ito sa `disable_tools`; tingnan ang [Mga paunang naka-install na CLI tool](18-development-tools.md#preinstalled-cli-tools).

Para mai-install ang lahat ng naka-configure na lazy tool bago mo kailanganin ang mga ito, patakbuhin ang `mise install --include-lazy`. Kasama rito ang iba pang default na CLI tool ng Omarchy pati na rin ang mga agent. Tingnan ang [Mga paunang naka-install na CLI tool](18-development-tools.md#preinstalled-cli-tools) para sa pag-install ng isang tool lang o paggamit ng sarili mong installation.

Ini-install ang `grok` sa pamamagitan ng first-party na `grok` package ng mise, sa parehong paraan gaya ng `claude` at `codex`. Patakbuhin ang `grok`, o piliin ito sa ilalim ng _Setup > Defaults > Agent_. Laktawan ang `curl | bash` installer sa x.ai. Naglalagay ang paraang iyon ng pangalawang kopya sa `~/.grok/bin`, inuuna ito sa `PATH`, at pinapatungan ang wrapper ng Omarchy.

Binubuksan ng `dsh` ang browser UI nito sa `127.0.0.1:3080`, na ang launch directory ang default workspace nito. Hindi tumatanggap ang browser UI nito ng panimulang prompt, kaya binubuksan ito ng `omarchy agent prompt` na nasa clipboard mo ang prompt para i-paste. Sinisimulan ito ng Omarchy gamit ang no-approval permission preset ng DeepSeek. Nag-a-upload ang DeepSeek Harness ng mga session log sa DeepSeek kapag ginagamit mo ang opisyal nitong model API; i-off iyon sa ilalim ng _Settings > General > Upload Session Log_ sa browser UI nito. Ang feedback na ipinapadala mo rito ay ina-upload din kasama ng session, maliban na lang kung sisimulan mo ito gamit ang `DSH_TELEMETRY_MODE=DISABLED`.

### Ang default na agent

Piliin ang default mong agent gamit ang `omarchy default agent <name>` o sa ilalim ng _Setup > Defaults > Agent_ sa Omarchy Menu (`Super + Space`). Kung hindi pa naka-install ang agent, ang pagpili rito ang mag-i-install muna nito. Aanyayahan ka ng isang bagong Omarchy na gawin ang pagpiling ito sa pamamagitan ng isang one-time na notification.

Sinusubukan din ng pagpili kay Claude na i-set up ang browser extension nito para sa Chromium, Chrome, Brave, Brave Origin, at Edge. Nalalapat ang extension setup sa lahat ng user at maaaring humingi ng iyong system password; pipiliin at ilulunsad pa rin si Claude kahit kanselahin mo o mabigo ang pag-install ng extension. I-restart ang iyong browser, i-enable ang extension kung sinabihan, at mag-sign in kay Claude para matapos ang pagkonekta rito. Patakbuhin ang `/chrome` sa Claude para masuri ang koneksyon. Hindi sinusuportahan ng Firefox at Zen ang extension na ito. Kung si Claude na ang default mo bago pa idinagdag ang setup na ito, piliin siyang muli para mai-install ang extension.

Kapag nakapili ka na, ilulunsad ng `Super + Shift + Ctrl + A` ang default na agent sa isang nakalaang terminal window (o ilalabas ang picker kung hindi ka pa nakakapili). Maaari mo rin itong ilunsad diretso sa isang gawain gamit ang `omarchy agent prompt "Review this project"`. Hindi tumatanggap ang Freebuff at DeepSeek Harness ng panimulang prompt, kaya bubukas sila na nasa clipboard mo ang prompt para i-paste sa halip. Ang mga agent na inilunsad sa ganitong paraan ay tumatakbo nang walang nagbabantay sa kani-kanilang don't-stop-to-ask mode, kaya maghanda kang may gagawin talaga sila! Walang ganoong mode ang MiniMax Code para sa mga interactive session nito, kaya humihingi ito ng mga pahintulot gaya ng dati. At dahil tumatanggi ang mga agent na tandaan ang trust para sa iyong home directory, ang mga paglulunsad mula sa `$HOME` ay magsisimula sa `~/Work` sa halip.

May mga terminal shortcut din: pinapatakbo ng `a` ang default na agent inline sa kasalukuyang terminal, habang sinisimulan naman ng `c`, `cx`, at `cy` nang direkta ang OpenCode, Claude Code, at Codex (muli, sa kanilang mga auto-approving mode). Nagsi-sync din ang mga pagbabago ng tema sa mga agent: ang Claude Code, Pi, OpenCode, at Hermes (kapag na-install na ito ng Omarchy) ay pawang sumusunod kapag nagpalit ka ng tema ng Omarchy.

### Ang panel ng mga agent

May agents icon ang top bar. Bago ka pa makapag-set up ng agent, gagabayan ka ng panel nito sa pag-sign in kay Claude, Codex, o Grok, at ang una ay magiging default mong agent. Pagkatapos niyon, inilalagay ng panel ang bawat subscription sa isang pahina: bawat agent at account kasama ang plan nito, isang meter para sa bawat 5-hour session at weekly limit nito kasama ang oras hanggang mag-reset ito (i-hover para sa eksaktong porsiyento), o ang natitirang prepaid balance, sa ilalim ng isang linyang umiikot sa kung ano ang nagamit mo sa lahat ng ito, gaya ng mga token ngayong linggo at ang pinakaginagamit mong modelo. Sa ilalim ng _Make something_ nag-aalok ito ng mga starter prompt para sa isang bagong tema, plugin, o app na nagbibigay ng gawain sa default mong agent. Ang mga app ay binubuo sa paraang binuo ang sariling Hype, Monologue, at Omacut ng Omarchy, sa C++ at Qt Quick, na sumusunod sa omarchy-app agent skill, at naka-install na ang compiler at mga piraso ng Qt na kailangan nila. Saklaw agad nang walang karagdagang setup ang Claude Code, Codex, Grok, Kimi, Cursor at ang Grok Bot allowance nito, GitHub Copilot, Muse, Antigravity, Kimchi, at Devin kasama ang kanilang mga limit, at ipinapakita ng Hermes, Mistral Vibe, at Qwen Code ang kanilang mga session at token kapag nagamit mo na sila. Lumalabas din ang mga provider plan at key na ginagamit mo sa pamamagitan ng pi, omp, o opencode: ang OpenCode Zen at Go, ang Z.ai GLM Coding Plan, Ollama Cloud, ang MiniMax Token Plan, at Synthetic kasama ang kanilang mga limit; ang Fireworks, OpenRouter, at DeepSeek kasama ang kanilang mga prepaid balance; at ang mga modelong pinapatakbo mo sa sarili mong hardware sa ilalim ng Local models. Bawat agent ay binibilang nang isang beses lang, sa ilalim ng kung sino ang naniningil para rito, gaano man karaming harness ang pagdaanan mo rito.

I-left-click ang icon sa bar para sa panel, i-right-click para ilunsad ang default mong agent. Ang mga usage record sa likod nito ay muling ginagawa kada 15 minuto ng `omarchy agent usage-update`, at maaari pang pagsamahin ng panel ang usage mula sa iba mo pang mga makina sa pamamagitan ng isang naka-sync na folder. Tingnan ang README sa ilalim ng `$OMARCHY_PATH/shell/plugins/agents/` para sa buong mga setting.

### Maraming subscription

Kung nagbabayad ka para sa higit sa isang Claude, Codex, o Grok plan — halimbawa, isang personal na Max at isang pangtrabaho — maaaring panatilihin silang lahat ng Omarchy na naka-sign in at lumipat-lipat sa pagitan nila. Magdagdag ng subscription gamit ang + sa panel ng mga agent, na gagabay sa iyo roon mismo, o gamit ang `omarchy agent account add claude Work` (o `codex`, o `grok`). Ini-install nito ang CLI kung nawawala ito. Ang unang account para sa isang provider ay nag-sign in sa pamamagitan ng normal mong browser, mismo kung saan laging tumitingin ang CLI. Bawat isa pagkatapos niyon ay nag-sign in sa pamamagitan ng isang private window, para hindi aksidenteng mapili ang account na naka-sign in na sa browser mo; mag-sign in doon bilang ang account na idinaragdag mo, at isara muna ang anumang private window na nakabukas na sa iyo. Huwag kailanman mag-log out sa CLI para gawin ito: binabawi ng pag-log out ang naka-save na sign-in, at kailangang idagdag muli ang account na iyon.

Para kopyahin ang iyong mga subscription login sa ibang makinang Omarchy sa pamamagitan ng SSH, patakbuhin ang `omarchy agent account copy user@laptop`. Nagbibigay ang sender ng pansamantalang receiver kapag walang naka-install ang destination, kaya makatatanggap ng mga account ang mas lumang mga makinang Omarchy nang walang update. Inuuna ang mga naka-install na receiver. Kinokopya nito ang lahat ng Claude, Codex, at Grok subscription; magdagdag ng mga pangalan ng provider para piliin ang mga ito, gaya sa `omarchy agent account copy laptop claude`. Tumutugma ang mga pangalan ng account at command ID sa pinagmulan, kasama ang mga account na mayroon na sa destination. Ang mga hindi kaugnay na destination account ay tatanggap ng numeric suffix kung magkasalungat ang kanilang mga pangalan, at ang mga setting, skill, plugin, at history ng pag-uusap ay mananatiling lokal sa bawat makina.

Pinapanatili ang mga umiiral nang destination credential. Ang isang source account na naka-sign in na roon ay masi-sync ang pangalan nang hindi pinapalitan ang mga credential nito; ang ibang mga account ay idinaragdag sa tabi nito. Para palitan ang mga naka-save na credential para sa magkatugmang mga account, gamitin ang `omarchy agent account copy --replace laptop claude` pagkatapos isara ang mga session ng account na iyon sa destination. Makukuha rin ng isang bagong destination ang active account at mga switching preference ng pinagmulan; pinapanatili ng isang matagal nang destination ang sarili nito.

Naglalakbay ang mga credential sa pamamagitan ng SSH at iniimbak sa mga pribadong file sa destination, kaya kumopya lamang sa mga makinang pinagkakatiwalaan mo. Ito ay isang beses na pagkopya, hindi patuloy na synchronization. Maaaring i-rotate ng ibang makina ang mga Codex refresh token, na mag-iiwan sa isang kinopyang login na nangangailangan ng pag-renew; ang magkahiwalay na mga sign-in pa rin ang pinaka-maaasahang pagpipilian para sa sabay-sabay na paggamit sa maraming makina. Tingnan ang [gabay sa account authentication ng Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Isang account bawat provider ang aktibo, at bawat bagong session ay nagsisimula bilang ito: `cx`, `cy`, isang payak na `claude`, `codex`, o `grok`, anumang inilunsad sa pamamagitan ng `omarchy agent`, at mga script o editor na nakakahanap sa CLI sa `PATH`. Lumipat gamit ang `omarchy agent account use work` (at bumalik gamit ang `omarchy agent account use main`), o sa panel sa pamamagitan ng pagpindot sa numero ng isang account at pagkatapos ay `Enter` (o pag-click sa Use button nito). Ang mga session na tumatakbo na ay mananatili sa account kung saan sila nagsimula. Ang history ng pag-uusap, mga setting, skill, at plugin ay ibinabahagi sa lahat ng account, kaya ang `claude --continue` sa parehong folder ay magpapatuloy kung saan ka huminto sa bagong account.

Kapag may higit sa isang account, ipinapakita ng panel ang mga limit ng bawat account nang magkatabi, na minarkahan ang aktibo. Bilang default, inaabisuhan ka ng Omarchy kapag lumampas na sa 95% ng isang limit ang aktibong account, at ang pag-click sa notification ay lilipat sa account na may pinakamaraming headroom. I-hover ang linya ng isang account sa panel at i-click ang Autoswitch na lumalabas sa tabi ng Use (o pindutin ang `m`), o patakbuhin ang `omarchy agent account mode auto`, para ito na mismo ang lumipat; habang naka-on ito, pumapalit ang Autoswitch sa Use, at ang pag-click muli rito ay babalik sa pag-abiso. Magdagdag ng numero para baguhin ang threshold, gaya sa `omarchy agent account mode auto 90`. Kung ang bawat account ay lagpas na sa threshold, maririnig mo ito nang isang beses, kasama kung aling account ang unang magkakaroon ng puwang. Habang ang isang aktibong account ay nasa loob ng 15 puntos ng threshold nito (80% sa default), sinusuri ang mga limit nito kada tatlong minuto sa halip na kada 15.

Ipinapakita ng `omarchy agent account list` ang bawat account at ang pinakabagong mga limit nito, kinakalimutan ng `omarchy agent account remove work` ang isa, at pinapalitan ng pangalan ng `omarchy agent account rename primary Hey` ang isa (o i-click ang pangalan ng isang account sa panel). Gumagana ang mga command na ito sa mga account ng default mong agent; para maabot ang ibang provider, pangalanan muna ito, gaya sa `omarchy agent account use codex side`. Ang login na mayroon ka na sa `~/.claude` o `~/.codex` ay ang _Main_ account at mananatili kung nasaan ito. Ang isang account na hindi ginamit nang mahigit walong oras o higit pa ay maaaring magpakita ng _Sign-in required_; i-click ito para muling i-sign in ang account na iyon mismo sa panel, o magsimula ng session rito, na magre-refresh ng sign-in nang kusa. Ang mga MCP server na mayroon ka noong idinagdag ang isang account ay sasama rito, pero ang mga idinagdag mo mamaya gamit ang `claude mcp add` ay aabot lamang sa account kung saan mo sila idinagdag. Hindi sumusunod sa paglipat ang Claude Desktop at mga tool na naka-configure gamit ang absolute path papunta sa isang CLI binary. Inuuna ang isang tahasang `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, o `GROK_HOME` kaysa sa napiling account.

### Diagnosis ng crash

Binabantayan ng Omarchy ang systemd-coredump para sa mga pag-crash ng process. Kapag may nag-segfault, makatatanggap ka ng notification na "Process crashed" — i-click ito, at ibibigay ang crash sa default mong agent kasama ang diagnose-crash skill ng Omarchy, na gagabay sa agent sa pagtatatag ng mga katotohanan mula sa core dump at pagpapasya kung karapat-dapat bang iulat ang crash sa upstream. Maaari mo rin itong patakbuhin nang mano-mano laban sa anumang PID mula sa `coredumpctl list` gamit ang `omarchy agent crash <pid>`.

Naka-on bilang default ang pagbabantay. I-off ito sa ilalim ng _Trigger > Toggle > Crash Capture_ (o gamit ang `omarchy toggle crash-capture`) at hihinto ang mga notification; gagana pa rin nang mano-mano ang `omarchy agent crash <pid>`.

Maaari ring patahimikin ang mga crash nang isang programa sa isang pagkakataon, na siyang inaalok sa iyo ng diagnosis sa dulo. Pinahihinto ng `omarchy crash mute hyprland` ang mga notification para sa programang iyon lamang, ibinabalik sila ng `omarchy crash mute hyprland off`, at inililista ng `omarchy crash mute` nang mag-isa kung ano ang na-mute mo na. Tumatanggap ito ng path ng binary nang kasing saya ng pangalan nito, kaya ginagawa ng `omarchy crash mute /usr/bin/hyprland` ang parehong bagay. I-quote ang isang pangalang may space, gaya sa `omarchy crash mute 'Some App'`. Nag-aabiso pa rin ang lahat ng iba, at nagka-crash pa rin ang naka-mute na programa — itinatago nito ang paalala, hindi nito inaayos ang anuman.

### Mga desktop app

May dala ring ilang graphical na AI app ang _Install > AI_ menu: ang ChatGPT desktop app, ang Claude desktop app (ang Linux beta ng Anthropic, na may mga tab na Chat, Cowork, at Claude Code), Grok Bot para makipag-chat sa mga modelo ng xAI, Herdr Desktop, Hermes Desktop, OpenClaw, ang Perplexity desktop app, at T3 Code. Ang Grok Bot ay ang desktop chat app. Ang coding agent ay ang `grok` command.

Ang Hermes Desktop ang dapat mong malaman, dahil ang isang makina ay may iisang Hermes, at pag-aari ito ng app: ini-install lang kailanman ang Hermes sa pamamagitan ng app, at ang `hermes` command na pinapatakbo ng default na agent ay pag-aari ng app. Ang pagpili kay Hermes bilang default na agent ay nag-i-install ng parehong bagay na ini-install ng entry sa _Install > AI_: ang package, at isang Hermes runtime sa ilalim ng `~/.hermes` na sine-set up ng sariling installer ng Hermes, na tumatagal ng ilang minuto sa unang pagkakataon. Ang runtime na iyon ang nag-iisang Hermes na ginagamit ng terminal `hermes` command, ng default na agent at ng app, at ina-update nito ang sarili gamit ang `hermes update` sa halip na maghintay ng Omarchy release. Ang pag-install nito ay nagbibigay din kay Hermes ng tema ng Omarchy bilang isang skin na pinangalanang `omarchy`, na sinusundan ng bawat Hermes surface habang nagpapalit ka ng mga tema; pumili ng iba sa ilalim ng mga Appearance setting ng Hermes o gamit ang `/skin` kung ayaw mo nito, at hahayaan ng Omarchy ang pagpipiliang iyon. Ang pag-alis sa app sa ilalim ng _Remove > AI_ ay nagsasara muna kay Hermes, kasama ang gateway, isinasama ang runtime na iyon, at pinapanatili ang iyong mga chat, memory, at ang mga skill na isinulat ng Hermes para sa sarili nito maliban na lang kung sasabihin mong hindi: magtatanong ito, na ang default ay hindi, kung dapat ding alisin ang data na iyon at ang iyong mga connection setting.

Ang desktop experience ng OpenClaw ay ang Control UI nito, na nagbubukas bilang isang web app na sinusuportahan ng sarili nitong local gateway. Nakatira ang OpenClaw sa `~/.openclaw` at ina-update ang sarili nito: gamitin ang "Update Gateway" button ng Control UI o patakbuhin ang `openclaw update`, at magre-restart ang gateway sa bagong bersyon. Pinipili lamang ng Omarchy ang release kung saan magsisimula ang isang bagong install. Ang pag-alis sa OpenClaw sa ilalim ng _Remove > AI_ ay isinasama ang gateway service at ang app at pagkatapos ay magtatanong kung dapat ding alisin ang `~/.openclaw`, dahil naroon ang iyong mga chat at credential kasama ang OpenClaw mismo at ang mga plugin runtime na dina-download nito; pinapanatili ito ng default, at ang muling pag-install sa OpenClaw ay kukunin itong muli.

Ang Herdr Desktop ay ang [Herdr](https://herdr.dev) desktop app: mga space, tab, at pane ng mga terminal at coding agent na patuloy na tumatakbo sa core nito kapag isinara mo ang window. Nagmumula ito sa sariling installer ng Herdr sa halip na sa isang package, kaya nakatira ito sa `~/.local/share/herdr-app`, dala ang core nito sa `~/.local/bin/herdr-core` kapag wala ka pa nito, at ina-update ang dalawa. Nakaupo ito sa tabi ng `herdr` command na ipinapadala ng Omarchy sa `Super + Ctrl + Return` sa halip na palitan ito, at nakukuha ang mga direct key ng command na iyon: hinahati ng `Alt + Return` at `Alt + Shift + Return` ang isang pane pababa o pakanan, isinasara ito ng `Alt + Escape`, lumilipat sa pagitan ng mga pane ang `Ctrl + Alt + Arrow`, pumipili ng tab ang `Alt + 1..9` at `Alt + Left/Right`, at lumilipat sa pagitan ng mga space ang `Alt + Up/Down`. Pumipili ng space ang `Ctrl + 1..9` at humahakbang sa mga agent ang `Alt + Shift + Up/Down`. Mananatiling pang-terminal lang ang mga `Ctrl + Space` prefix key, dahil hindi kayang hawakan ng app ang isang payak na Ctrl key para sa isang sequence. Isinusulat ito ng Omarchy sa `~/.config/herdr-app/keys.json`, at ibinabalik sila ng `omarchy-refresh-herdr-app`. Ang pag-install nito ay pumipili ng Omarchy theme ng Herdr, na susunod sa tema ng Omarchy mo mula noon. Nagpapanatili ang Herdr ng isang tema para sa light mode at isa para sa dark, kaya pagkatapos lumipat sa pagitan ng isang madilim at isang maliwanag na tema ng Omarchy, piliin muli ang Omarchy sa theme picker ng Herdr para sa kabilang mode.

Tumatakbo ang T3 Code mula sa opisyal nitong AppImage release sa `~/.local/share/t3code` sa halip na mula sa isang package, kaya ina-update nito ang sarili nito. Ang pag-install nito ay magtatanong kung magsisimula sa Stable o Nightly channel; lumipat mamaya sa mga setting ng T3 Code. Ang iyong mga thread at setting ay nakatira sa `~/.t3`, at ang pag-alis sa T3 Code sa ilalim ng _Remove > AI_ ay isinasama sila.

### Mga lokal na modelo

Magpatakbo ng isang open model sa sarili mong makina para sa iyong mga coding agent. Mananatili sa makina ang iyong mga prompt at code; walang anumang ipinapadala sa modelo ang umaalis dito. Magsimula sa:

```bash
omarchy agent local use best
```

O, sa panel ng mga agent sa top bar, piliin ang + at pagkatapos ay Local AI, na lumalabas kapag may modelong kasya sa makinang ito. Sa unang pagkakataon, ini-install nito ang Podman, na nagpapatakbo sa mga modelo, at sa isang makinang NVIDIA ang container toolkit ng NVIDIA, na nagbibigay sa kanila ng GPU. Pagkatapos ay pipiliin ng Omarchy ang inirerekomendang modelo para sa makinang ito, ida-download ito, at sisimulan ito. Asahan ang download na sampu-sampung GB at ang karamihan ng memory ng makina ay ginagamit habang tumatakbo ang modelo: gumagamit ang Flash Next ng mga 100 GiB kasama ang buong 256K context nito. Kung hawak ng ibang mga modelo ang memory na kailangan nito, sine-set up itong nakahinto, handang magsimula kapag huminto ka ng isa. Humihinto ang modelo sa logout; ihinto mo ito mismo kapag kailangan mo ang memory para sa ibang bagay.

Ipinapakita ng `omarchy agent local list` ang mga opsyon at ipinaliliwanag kung bakit hindi kasya ang ilan. Para mag-set up ng isa pa, patakbuhin ang `omarchy agent local use <recipe>`. Ngayon, available ang `qwen3.8-flash-next-gufo` at `qwen3.8-27b-gufo` para sa mga makinang 128 GB Strix Halo; kumukuha ang 27B ng mga 40 GiB, kaya nag-iiwan ito ng puwang para sa ibang trabaho. Dumarating ang mga bagong recipe at rekomendasyon kasama ng `omarchy update`, sa pamamagitan ng package.

Bawat modelong sine-set up mo ay nagkakaroon ng sarili nitong linya sa panel ng mga agent, sa tabi ng iyong mga subscription: play para simulan ito, pause para ihinto ito at palayain ang memory nito, at ang terminal button para buksan ang agent mo rito. Marami ang maaaring tumakbo nang sabay kapag kasya sila sa memory nang magkasama; kung hindi kasya ang isa, sasabihin ng Omarchy kung aling tumatakbong modelo ang ihinto. I-drag ang mga linya para muling ayusin sila, at pindutin ang Delete sa isang napiling linya para alisin ang isang modelo at ang download nito.

Mula sa command line, ginagawa ng `omarchy agent local start <recipe>` at `omarchy agent local stop <recipe>` ang parehong bagay, ipinapakita ng `omarchy agent local status` ang bawat modelo, at binubuksan ng `omarchy agent --local` ang default mong agent sa huling modelong sinimulan mo (pi kung hindi makagamit ng lokal na modelo ang default mong agent). Maaari ring kumonekta ang anumang OpenAI-compatible client: ipinapakita ng `status` ang address ng bawat modelo (ang una ay `http://127.0.0.1:11435/v1`), ang pangalan ng recipe ang modelo, at ang key ay nasa `~/.config/omarchy/agent-local/key`.

Tinatanggal ng `omarchy agent local remove <recipe>` ang isang modelo at ang mga download na hindi ginagamit ng ibang modelo.

Nalagyan ng label ang mga third-party runtime ng kanilang publisher. Pinapatakbo ng Omarchy ang bawat modelo nang walang network access.

### Mga lokal na LLM

Inirerekomenda ng Omarchy ang dalawang paraan ng pagpapatakbo ng mga lokal na LLM model: LM Studio at Ollama. Nagbibigay ang LM Studio ng GUI interface para sa paghahanap ng mga open-weight model, pag-install sa kanila, at pagpapatakbo sa kanila. Isa itong mahusay na paraan para makapagsimula nang madali. Nag-aalok ang Ollama ng CLI para gawin din iyon sa katulad na paraan. Pero kung bago ka sa mga lokal na modelo, magsisimula ako sa LM Studio. Maaari mong i-install ang alinman sa dalawa sa ilalim ng _Install > AI_ sa Omarchy Menu.

### Ang Omarchy Skill

Tinutulungan ng mga agent skill ang AI na gumamit ng mga partikular na tool sa isang partikular na paraan, at may kasamang default na skill ang Omarchy para sa pag-aangkop ng sistema. Gaya ng pag-tweak sa iyong Hyprland config, pag-aayos sa bar, o kahit paglikha ng bagong tema mula sa simula. Naka-symlink ito sa mga skill directory para sa Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` at bawat `~/.hermes/profiles/*/skills`), at ang generic na lokasyong `~/.agents/skills`, kaya awtomatiko itong nakukuha ng karamihan sa mga harness.

Pero dapat mong ituring ang skill na ito bilang eksperimental. Iba't ibang modelo ang gagamit nito na may iba't ibang epekto. Pinakamainam na tumakbo muna sa plan mode, para may ideya ka kung ano ang gustong baguhin ng agent. At pagkatapos ay maging handang i-rollback ang mga pagbabago o kahit tumawag ng `omarchy reinstall configs`, kung guluhin ng agent ang lahat.
