# AI

Kasama sa Omarchy ang mga launcher para sa mga coding agent sa ibaba nang hindi pumipili ng default para sa iyo. Magpatakbo ng command para i-install ang CLI nito sa unang paggamit, pagkatapos ay mag-authenticate kapag sinabihan ka. Sina Hermes at OpenClaw ang mga exception: walang ini-install para sa kanila sa pamamagitan ng mise, at ang pagpili sa alinman ay nagse-setup ng sarili nitong self-updating na kopya, gaya ng ipinaliliwanag ng _Mga desktop app_ sa ibaba.

### Pag-install at pag-update ng mga agent

Maliban kina Hermes at OpenClaw, gumagamit ang mga agent na ito ng lazy installation ng mise: ini-install ng unang paglulunsad ang CLI, at ginagamit itong muli ng mga susunod na paglulunsad. Sinusuri rin ng mise ang isang naka-install na agent para sa bagong release nang hindi hihigit sa isang beses bawat apat na oras, bago ito magsimula o sa background sa isang shell prompt. Kung mabigo ang update na iyon o offline ka, tatakbo ang naka-install na bersyon. Ina-update ng `omarchy update` ang mga naka-install na agent kasama ang iba pang bahagi ng Omarchy, at ina-update ng `mup` ang mga tool na pinamamahalaan ng mise lamang.

Ang sariling updater ng isang agent, tulad ng `claude update`, `codex update`, o isang update button sa isang app, ay hindi nag-a-update sa install na pinamamahalaan ng mise. Nabibigo ang `codex update`, at maaaring mag-ulat ng tagumpay ang `claude update` habang nag-i-install ng hiwalay na kopya na hindi sinusubaybayan ng mise. Kung mas gusto mong gamitin ang native installer at updater ng isang agent, idagdag ito sa `disable_tools`; tingnan ang [Mga paunang naka-install na CLI tool](18-development-tools.md#preinstalled-cli-tools).

Para i-install ang lahat ng naka-configure na lazy tool bago mo kailanganin ang mga ito, patakbuhin ang `mise install --include-lazy`. Kasama rito ang iba pang default na CLI tool ng Omarchy pati na rin ang mga agent. Tingnan ang [Mga paunang naka-install na CLI tool](18-development-tools.md#preinstalled-cli-tools) para sa pag-install ng iisang tool o paggamit ng sarili mong installation.

Ini-install ang `grok` sa pamamagitan ng first-party na `grok` package ng mise, sa parehong paraan tulad ng `claude` at `codex`. Patakbuhin ang `grok`, o i-star ito sa panel ng mga agent. Laktawan ang `curl | bash` installer sa x.ai. Naglalagay ang paraang iyon ng pangalawang kopya sa `~/.grok/bin`, inuuna ito sa `PATH`, at pinapalitan ang wrapper ng Omarchy.

Binubuksan ng `dsh` ang browser UI nito sa `127.0.0.1:3080`, kung saan ang launch directory ang default nitong workspace. Walang starting prompt na tinatanggap ang browser UI nito, kaya binubuksan ito ng `omarchy agent prompt` nang nasa clipboard mo ang prompt para i-paste. Sinisimulan ito ng Omarchy gamit ang no-approval permission preset ng DeepSeek. Ina-upload ng DeepSeek Harness ang mga session log sa DeepSeek kapag ginagamit mo ang opisyal nitong model API; i-off iyon sa ilalim ng _Settings > General > Upload Session Log_ sa browser UI nito. Ang feedback na ipinapadala mo rito ay ina-upload din kasama ng session, maliban kung sisimulan mo ito gamit ang `DSH_TELEMETRY_MODE=DISABLED`.

### Ang default na agent

Piliin ang iyong default na agent gamit ang star sa tabi ng isang agent sa panel ng mga agent, na napupuno sa default, o gamit ang `omarchy default agent <name>`, na tumatanggap din ng anumang harness na walang linya roon. Kung hindi pa naka-install ang agent, ini-install muna ito ng pagpili rito, at nakakakuha rin ito ng sarili nitong launcher sa app launcher, sa tabi ng Agent. Inaanyayahan ka ng isang bagong Omarchy na mag-setup ng isa gamit ang isang beses lang na notification, na nagbubukas sa panel ng mga agent.

Sinusubukan din ng pagpili kay Claude na i-setup ang browser extension nito para sa Chromium, Chrome, Brave, Brave Origin, at Edge. Nalalapat ang setup ng extension sa lahat ng user at maaaring humingi ng iyong system password; pipiliin at ilulunsad pa rin si Claude kahit kanselahin mo ito o mabigo ang pag-install ng extension. I-restart ang iyong browser, i-enable ang extension kung sinabihan ka, at mag-sign in kay Claude para tapusin ang pagkonekta rito. Patakbuhin ang `/chrome` sa Claude para suriin ang koneksyon. Hindi sinusuportahan ng Firefox at Zen ang extension na ito. Kung si Claude na ang iyong default bago pa idinagdag ang setup na ito, piliin siyang muli para i-install ang extension.

Kapag nakapili ka na, inilulunsad ng `Super + Shift + Ctrl + A` ang default na agent sa isang nakalaang terminal window (o inilalabas ang picker kung hindi ka pa nakakapili). Maaari mo rin itong ilunsad nang diretso sa isang gawain gamit ang `omarchy agent prompt "Review this project"`. Walang starting prompt na tinatanggap ang Freebuff at DeepSeek Harness, kaya nagbubukas sila nang nasa clipboard mo ang prompt para i-paste sa halip. Ang mga agent na inilunsad sa ganitong paraan ay tumatakbo nang walang bantay sa kani-kanilang don't-stop-to-ask mode, kaya maging handa na talagang gumawa sila ng mga bagay! Walang ganoong mode ang MiniMax Code para sa mga interactive session nito, kaya humihingi ito ng mga pahintulot gaya ng dati. At dahil tumatanggi ang mga agent na tandaan ang trust para sa iyong home directory, sa `~/Work` sa halip nagsisimula ang mga paglulunsad mula sa `$HOME`.

May mga terminal shortcut din: pinapatakbo ng `a` ang default na agent nang inline sa kasalukuyang terminal, habang sinisimulan ng `c`, `cx`, at `cy` ang OpenCode, Claude Code, at Codex nang diretso (muli sa kanilang mga auto-approving mode). Nagsi-sync din ang mga pagbabago ng tema sa mga agent: sumusunod ang Claude Code, Pi, OpenCode, at Hermes (kapag na-install na ito ng Omarchy) kapag nagpapalit ka ng tema ng Omarchy.

### Ang mga tagubilin mo para sa agent

Ang mga personal na panuntunan para sa bawat agent ay nasa `~/.agents/AGENTS.md`, sa tabi ng mga shared skill sa `~/.agents/skills`. Buksan ito gamit ang document icon sa tabi ng + sa panel ng mga agent, o ang `omarchy agent instructions --edit`, na nagli-link din nito sa bawat harness na nagpapanatili ng sarili nitong global file: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, ang `~/.copilot/copilot-instructions.md` ng Copilot, at iba pa. Binabasa ng Crush at Amp ang link na `~/.config/AGENTS.md`, habang direktang binabasa ng omp, Kimi, at DeepSeek Harness ang `~/.agents/AGENTS.md`. Nagli-link din nito ang pagpili ng default na agent. Ang isang instructions file na mayroon ka na ay nagiging shared na file kung wala pa nito; kung hindi, pinapanatili ito sa tabi ng link bilang `.bak`. Patakbuhin ang `omarchy agent instructions` para muling mag-link pagkatapos mag-install ng isa pang agent.

### Ang panel ng mga agent

May agents icon ang top bar. Bago ka pa mag-setup ng agent, nag-aalok ang panel nito ng tatlong paraan para magsimula: mag-sign in sa isang subscription ng Claude, Codex, Grok, Gemini, Muse, Cursor, o Copilot, o sa ilalim ng More ng isang coding plan ng OpenCode Go, MiniMax, Synthetic, o Z.ai; magbayad ayon sa paggamit gamit ang Fireworks, OpenCode Zen and Go, OpenRouter, o sa ilalim ng More ang DeepSeek o anumang iba pang provider na pinapasign-in ng OpenCode, na lahat ay tumatakbo sa OpenCode; o patakbuhin ang pinakamahusay na modelo para sa iyong computer, kapag may kasya rito. Ang una mong matatapos ay nagiging iyong default na agent, at nag-aalok ang + sa panel ng parehong tatlo sa ibang pagkakataon. Pagkatapos niyon, inilalagay ng panel ang bawat subscription sa isang pahina: bawat agent at account kasama ang plan nito, isang meter para sa bawat 5-hour session at weekly limit nito kasama ang oras hanggang mag-reset ito (i-hover para sa eksaktong porsiyento), o ang natitirang prepaid balance, sa ilalim ng isang linya na umiikot sa iyong nagamit sa lahat ng mga ito, tulad ng mga token ngayong linggo at ang pinakamadalas mong gamiting modelo. Sa ilalim ng _Make something cool_ nag-aalok ito ng mga starter prompt para sa isang bagong tema, plugin, app, o game na nagbibigay ng gawain sa iyong default na agent. Ang mga app ay binubuo sa paraang binuo ang sariling Hype, Monologue, at Omacut ng Omarchy, sa C++ at Qt Quick, na sumusunod sa omarchy-make-app agent skill, at naka-install na ang compiler at mga piraso ng Qt na kailangan nila. Ang mga game ay isang solong three.js page sa `~/Games/vibes`, na sumusunod sa omarchy-make-game agent skill, at lahat ay nagbubukas mula sa isang Game Vibes launcher sa kasalukuyang tema; nilo-load nila ang three.js mula sa web, kaya kailangan nila ng koneksyon para magsimula. Saklaw agad ang Claude Code, Codex, Grok, Kimi, Cursor at ang Grok Bot allowance nito, GitHub Copilot, Muse, Gemini (sa pamamagitan ng Antigravity), at Devin kasama ang kanilang mga limit, ang Kimchi kasama ang plan nito, mga prepaid credit, at mga spend budget, at ipinapakita ng Hermes, Mistral Vibe, at Qwen Code ang kanilang mga session at token kapag nagamit mo na sila. Ipinapakita rin ang mga provider plan at key na ginagamit mo sa pamamagitan ng pi, omp, o opencode: ang OpenCode Zen and Go, ang Z.ai GLM Coding Plan, Ollama Cloud, ang MiniMax Token Plan, at Synthetic kasama ang kanilang mga limit; ang OpenRouter at DeepSeek kasama ang kanilang mga prepaid balance; ang Fireworks kasama ang gastos nito sa nakalipas na 30 araw. Ang mga coding model na pinapatakbo mo sa sarili mong hardware ay nakakakuha ng sarili nilang mga linya, at binibilang din ang kanilang mga token sa mga kabuuan, gaya ng inilarawan sa ilalim ng [Mga lokal na modelo](#local-models). Bawat agent ay binibilang nang isang beses, sa ilalim ng kung sino ang naniningil para rito, gaano man karaming harness ang patakbuhin mo rito.

I-left-click ang bar icon o pindutin ang `Super + Ctrl + X` para sa panel, i-right-click para ilunsad ang iyong default na agent, at i-middle-click para mag-refresh. Ang mga usage record sa likod nito ay muling ginagawa bawat 15 minuto ng `omarchy agent usage update`, at maaari pang pagsamahin ng panel ang usage mula sa iba mo pang mga machine sa pamamagitan ng isang naka-sync na folder. Tingnan ang README sa ilalim ng `$OMARCHY_PATH/shell/plugins/agents/` para sa buong mga setting.

### Maraming subscription

Kung nagbabayad ka para sa higit sa isang plan ng Claude, Codex, o Grok — halimbawa isang personal na Max at isang pangtrabaho — maaaring panatilihin ng Omarchy na naka-sign in ang lahat ng mga ito at lumipat-lipat sa pagitan ng mga ito. Magdagdag ng subscription gamit ang + sa panel ng mga agent, na gagabay sa iyo roon mismo, o gamit ang `omarchy agent account add claude Work` (o `codex`, o `grok`). Ang parehong + at command ay nagsa-sign in din sa Gemini (`gemini`) at OpenCode (`opencode`), at nagse-save ng Fireworks (`fireworks`) o OpenRouter (`openrouter`) API key sa OpenCode; nagsa-sign in din ang command sa Copilot (`copilot`), Cursor (`cursor`), at Muse (`muse`). Ang mga iyon ay nagpapanatili ng tig-iisang sign-in. Ini-install nito ang CLI kung nawawala ito. Ang unang account para sa isang provider ay nagsa-sign in sa pamamagitan ng iyong normal na browser, roon mismo kung saan laging tumitingin ang CLI. Ang bawat susunod ay nagsa-sign in sa pamamagitan ng isang pribadong window, kaya hindi aksidenteng makukuha ang account na naka-sign in na sa iyong browser; mag-sign in doon bilang account na idinaragdag mo, at isara muna ang anumang pribadong window na nakabukas mo na. Huwag kailanman mag-log out sa CLI para gawin ito: binabawi ng pag-log out ang naka-save na sign-in, at kailangang idagdag muli ang account na iyon.

Para kopyahin ang iyong mga subscription login sa isa pang Omarchy machine sa pamamagitan ng SSH, patakbuhin ang `omarchy agent account copy user@laptop`. Nagbibigay ang sender ng pansamantalang receiver kapag walang naka-install ang destination, kaya makakatanggap ng mga account ang mas lumang mga Omarchy machine nang walang update. Inuuna ang mga naka-install na receiver. Kinokopya nito ang lahat ng subscription ng Claude, Codex, at Grok; magdagdag ng mga pangalan ng provider para piliin ang mga ito, gaya ng sa `omarchy agent account copy laptop claude`. Tumutugma ang mga pangalan ng account at command ID sa source, kabilang ang mga account na mayroon na sa destination. Ang mga hindi magkaugnay na destination account ay nakakatanggap ng numeric suffix kung magkasalungat ang kanilang mga pangalan, at ang mga setting, skill, plugin, at history ng pag-uusap ay nananatiling lokal sa bawat machine.

Pinapanatili ang mga umiiral na destination credential. Ang isang source account na naka-sign in na roon ay pina-sync ang pangalan nito nang hindi pinapalitan ang mga credential nito; ang ibang mga account ay idinaragdag sa tabi nito. Para palitan ang mga naka-save na credential para sa mga magkatugmang account, gamitin ang `omarchy agent account copy --replace laptop claude` pagkatapos isara ang mga session ng account na iyon sa destination. Nakukuha rin ng isang bagong destination ang active account at mga switching preference ng source; pinapanatili ng isang matagal nang destination ang sarili nito.

Ang mga credential ay bumibiyahe sa pamamagitan ng SSH at nakaimbak sa mga pribadong file sa destination, kaya kumopya lamang sa mga machine na pinagkakatiwalaan mo. Ito ay isang beses lang na kopya, hindi patuloy na pag-synchronize. Maaaring i-rotate ng ibang machine ang mga Codex refresh token, na nag-iiwan sa isang nakopyang login na nangangailangan ng renewal; ang magkahiwalay na mga sign-in ang nananatiling pinaka-maaasahang pagpipilian para sa sabay-sabay na paggamit sa maraming machine. Tingnan ang [gabay sa pagpapatotoo ng account ng Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Isang account bawat provider ang active, at bawat bagong session ay nagsisimula bilang ito: `cx`, `cy`, isang simpleng `claude`, `codex`, o `grok`, anumang inilunsad sa pamamagitan ng `omarchy agent`, at mga script o editor na nakakahanap sa CLI sa `PATH`. Lumipat gamit ang `omarchy agent account use work` (at bumalik gamit ang `omarchy agent account use main`), o sa panel sa pamamagitan ng pagpindot sa numero ng isang account at pagkatapos ay `Enter` (o pag-click sa star nito). Lumilipat din ang mga tumatakbong Claude session, mula sa kanilang susunod na mensahe: bawat Claude session ay tumatakbo sa `~/.claude`, na palaging naglalaman ng sign-in ng active account. Ang isang Claude session na sinimulan sa sariling folder ng isang account ng isang mas lumang Omarchy ay nagpapanatili ng sign-in na iyon hanggang sa magsara ito, kaya pinapangalanan ng switch ang mga session na iyon at natatapos nang kusa kapag wala na sila. Ang mga tumatakbong Codex at Grok session ay nananatili sa account na pinagsimulan nila. Ang history ng pag-uusap, mga setting, skill, at plugin ay ibinabahagi sa mga account, kaya nagpapatuloy ang `claude --continue` sa parehong folder kung saan ka tumigil sa bagong account.

Kapag may higit sa isang account, ipinapakita ng panel ang mga limit ng bawat account nang magkatabi, na may napunong star sa ginagamit. Inaabisuhan ka ng Omarchy kapag lumampas ang active account sa 95% ng isang limit, at ang pag-click sa notification ay lumilipat sa account na may pinakamaraming natitirang puwang. Hindi ito kailanman lumilipat nang kusa. Baguhin ang threshold gamit ang `omarchy agent account threshold 90`. Kung ang bawat account ay lumampas sa threshold, maririnig mo ito nang isang beses, kasama kung aling account ang unang magkakaroon ng puwang. Habang ang isang active account ay nasa loob ng 15 puntos ng threshold nito (80% sa default), sinusuri ang mga limit nito bawat tatlong minuto sa halip na bawat 15.

Ipinapakita ng `omarchy agent account list` ang bawat account at ang pinakabagong mga limit nito, kinakalimutan ng `omarchy agent account remove work` ang isa, at pinapalitan ng `omarchy agent account rename primary Hey` ang pangalan ng isa (o i-click ang pangalan ng isang account sa panel). Gumagana ang mga command na ito sa mga account ng iyong default na agent; para maabot ang ibang provider, pangalanan muna ito, gaya ng sa `omarchy agent account use codex side`. Ang login na mayroon ka na sa `~/.claude` o `~/.codex` ay ang _Main_ account. Ang sa Codex ay nananatili kung nasaan ito; ang kay Claude ay naghihintay sa sarili nitong folder habang may ibang account na active. Ang isang account na hindi nagamit nang higit sa humigit-kumulang walong oras ay maaaring magpakita ng _Sign-in required_; i-click ito para muling i-sign in ang account na iyon mismo sa panel, o lumipat rito at magsimula ng session, na nagre-refresh sa sign-in nang kusa. Ang mga MCP server na idinaragdag mo gamit ang `claude mcp add` ay umaabot sa bawat Claude account, dahil lahat sila ay tumatakbo sa `~/.claude`; para sa Codex at Grok, ang mga server na mayroon ka noong idinagdag ang isang account ay sumasama rito, ngunit ang mga susunod ay umaabot lamang sa account kung saan mo idinagdag ang mga ito. Nagpapanatili ang Claude Desktop ng sarili nitong sign-in, at ang mga Codex o Grok tool na naka-configure gamit ang isang absolute path patungo sa isang CLI binary ay hindi sumusunod sa switch. Ang isang tahasang `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, o `GROK_HOME` ay inuuna kaysa sa napiling account.

### Pagsusuri ng pag-crash

Binabantayan ng Omarchy ang systemd-coredump para sa mga pag-crash ng proseso. Kapag nakapili ka na ng default na agent, ang anumang programa mo na nagda-dump ng core ay nagdadala ng isang "Process crashed" na notification — i-click ito, at ang crash ay ibibigay sa iyong default na agent kasama ang omarchy-diagnose-crash skill ng Omarchy, na gagabay sa agent sa pagtatatag ng mga katotohanan mula sa core dump at pagpapasya kung sulit iulat ang crash sa upstream. Maaari mo rin itong patakbuhin nang mano-mano laban sa anumang PID mula sa `coredumpctl list` gamit ang `omarchy agent crash <pid>`.

Naka-on ang pagbantay bilang default. I-off ito sa ilalim ng _Trigger > Toggle > Crash Capture Off_ (o gamit ang `omarchy toggle crash-capture`) at hihinto ang mga notification; gumagana pa rin nang mano-mano ang `omarchy agent crash <pid>`.

Maaari ding patahimikin ang mga crash nang paisa-isa bawat programa, na siyang iniaalok sa iyo ng diagnosis sa dulo. Pinipigilan ng `omarchy crash mute hyprland` ang mga notification para lamang sa programang iyon, ibinabalik sila ng `omarchy crash mute hyprland off`, at inililista ng `omarchy crash mute` nang mag-isa kung ano ang iyong na-mute. Tumatanggap ito ng path ng binary nang kasing saya ng pangalan nito, kaya pareho ang ginagawa ng `omarchy crash mute /usr/bin/hyprland`. Mag-quote ng pangalan na may puwang, gaya ng sa `omarchy crash mute 'Some App'`. Nag-aabiso pa rin ang lahat ng iba, at nagka-crash pa rin ang na-mute na programa — itinatago nito ang paalala, hindi nito inaayos ang anuman.

### Mga desktop app

May dala ring ilang graphical AI app ang menu na _Install > AI_: Amp Desktop, Antigravity Desktop, ang ChatGPT desktop app, ang Claude desktop app (ang Linux beta ng Anthropic, na may mga tab na Chat, Cowork, at Claude Code), Grok Bot para makipag-chat sa mga modelo ng xAI, Herdr Desktop, Hermes Desktop, OpenClaw, ang Perplexity desktop app, at T3 Code. Ang Grok Bot ay ang desktop chat app. Ang coding agent ay ang command na `grok`.

Ang Hermes Desktop ang dapat mong malaman, dahil ang isang machine ay may isang Hermes, at pag-aari ito ng app: ang Hermes ay ini-install lamang kailanman sa pamamagitan ng app, at ang command na `hermes` na pinapatakbo ng default na agent ay pag-aari ng app. Ang pagpili kay Hermes bilang default na agent ay nag-i-install ng parehong bagay na ginagawa ng entry na _Install > AI_: ang package, at isang Hermes runtime sa ilalim ng `~/.hermes` na sine-setup ng sariling installer ng Hermes, na tumatagal ng ilang minuto sa unang pagkakataon. Ang runtime na iyon ang nag-iisang Hermes na ginagamit ng terminal command na `hermes`, ng default na agent at ng app, at ina-update nito ang sarili gamit ang `hermes update` sa halip na maghintay ng isang Omarchy release. Ang pag-install nito ay nagbibigay din kay Hermes ng tema ng Omarchy bilang isang skin na pinangalanang `omarchy`, na sinusunod ng bawat Hermes surface habang nagpapalit ka ng mga tema; pumili ng iba sa ilalim ng mga Appearance setting ng Hermes o gamit ang `/skin` kung ayaw mong ganoon, at hindi pakikialaman ng Omarchy ang pagpipiliang iyon. Ang pag-aalis ng app sa ilalim ng _Remove > AI_ ay isinasara muna ang Hermes, kasama ang gateway, isinasama ang runtime na iyon, at pinapanatili ang iyong mga chat, memory, at ang mga skill na isinulat ng Hermes para sa sarili nito maliban kung sasabihin mo ang kabaligtaran: nagtatanong ito, na naka-default sa hindi, kung dapat ding alisin ang data na iyon at ang iyong mga connection setting.

Ang desktop experience ng OpenClaw ay ang Control UI nito, na nagbubukas bilang isang web app na sinusuportahan ng sarili nitong local gateway. Nakatira ang OpenClaw sa `~/.openclaw` at ina-update ang sarili nito: gamitin ang button na "Update Gateway" ng Control UI o patakbuhin ang `openclaw update`, at magre-restart ang gateway sa bagong bersyon. Pinipili lamang ng Omarchy ang release na pagsisimulan ng isang bagong install. Maaari ding maging iyong default na agent ang OpenClaw: ang pagpili rito gamit ang `omarchy default agent openclaw` ay nagse-setup ng parehong kopya sa `~/.openclaw`, at binubuksan ng agent ang terminal UI ng OpenClaw na nakakabit sa gateway nito. Ang pag-aalis ng OpenClaw sa ilalim ng _Remove > AI_ ay isinasama ang gateway service at ang app at pagkatapos ay nagtatanong kung dapat ding alisin ang `~/.openclaw`, dahil naglalaman iyon ng iyong mga chat at credential kasama ng OpenClaw mismo at ang mga plugin runtime na dina-download nito; pinapanatili ito ng default, at ang muling pag-install ng OpenClaw ay kukunin itong muli.

Ang Herdr Desktop ay ang desktop app na [Herdr](https://herdr.dev): mga space, tab, at pane ng mga terminal at coding agent na patuloy na tumatakbo sa core nito kapag isinara mo ang window. Nagmumula ito sa sariling installer ng Herdr sa halip na sa isang package, kaya nakatira ito sa `~/.local/share/herdr-app`, isinasama ang core nito sa `~/.local/bin/herdr-core` kapag wala ka pa nito, at ina-update ang sarili nitong dalawa. Nakatabi ito sa command na `herdr` na ipinapadala ng Omarchy sa `Super + Ctrl + Return` sa halip na palitan ito, at nakukuha ang mga direct key ng command na iyon: hinahati ng `Alt + Return` at `Alt + Shift + Return` ang isang pane pababa o pakanan, isinasara ito ng `Alt + Escape`, ang `Ctrl + Alt + Arrow` ay gumagalaw sa pagitan ng mga pane, ang `Alt + 1..9` at `Alt + Left/Right` ay pumipili ng tab, at ang `Alt + Up/Down` ay gumagalaw sa pagitan ng mga space. Ang `Ctrl + 1..9` ay pumipili ng space at ang `Alt + Shift + Up/Down` ay humahakbang sa mga agent. Ang mga prefix key na `Ctrl + Space` ay nananatiling pang-terminal lamang, dahil hindi mahawakan ng app ang isang simpleng Ctrl key para sa isang sequence. Isinusulat ito ng Omarchy sa `~/.config/herdr-app/keys.json`, at ibinabalik sila ng `omarchy-refresh-herdr-app`. Pinipili ng pag-install nito ang Omarchy theme ng Herdr, na sumusunod sa iyong Omarchy theme mula noon. Nagpapanatili ang Herdr ng isang tema para sa light mode at isa para sa dark, kaya pagkatapos lumipat sa pagitan ng isang dark at isang light na Omarchy theme, piliin muli ang Omarchy sa theme picker ng Herdr nang isang beses pa para sa kabilang mode.

Ang T3 Code ay tumatakbo mula sa opisyal nitong AppImage release sa `~/.local/share/t3code` sa halip na mula sa isang package, kaya ina-update nito ang sarili nito. Nagtatanong ang pag-install nito kung magsisimula sa Stable o Nightly channel; lumipat sa ibang pagkakataon sa mga setting ng T3 Code. Ang iyong mga thread at setting ay nasa `~/.t3`, at ang pag-aalis ng T3 Code sa ilalim ng _Remove > AI_ ay isinasama sila.

### Mga lokal na modelo

Magpatakbo ng isang open model sa sarili mong machine para sa iyong mga coding agent. Ang iyong mga prompt at code ay nananatili sa machine; walang ipinapadala sa modelo ang umaalis dito. Magsimula sa:

```bash
omarchy models use best text
```

Sine-setup niyon ang pinakamahusay na text model para sa machine na ito, ang uri na ginagamit ng iyong mga agent. Ang mga image, video at music model ay may kani-kanilang pinakamahusay: `omarchy models use best image`, `video` o `music`. Patakbuhin ang `omarchy models use best` para makita ang pinili ng bawat uri para sa machine na ito.

O piliin ang + sa panel ng mga agent: sa ilalim ng _Use a local model_ inililista nito ang bawat coding model na kasya sa machine na ito, una ang inirerekomenda. Ang Podman, na nagpapatakbo sa mga modelo, ay kasama ng Omarchy, gayundin ang container toolkit ng NVIDIA sa isang NVIDIA machine, na nagbibigay sa kanila ng GPU; kung nawawala ang alinman, ini-install ito ng unang setup. Pagkatapos ay pinipili ng Omarchy ang inirerekomendang modelo para sa machine na ito, dina-download ito, at sinisimulan ito. Asahan ang isang download na sampu-sampung GB at ang karamihan ng memory ng machine ay ginagamit habang tumatakbo ang modelo: ang Flash Next ay gumagamit ng humigit-kumulang 100 GiB kasama ang buong 256K context nito. Kung hawak ng ibang mga modelo ang memory na kailangan nito, sine-setup itong nakahinto, handang magsimula kapag pinahinto mo ang isa. Humihinto ang modelo sa pag-logout; pahintuin mo ito mismo kapag kailangan mo ang memory para sa ibang bagay.

Ipinapakita ng `omarchy models list` ang mga opsyon at ipinaliliwanag kung bakit hindi kasya ang ilan. Para mag-setup ng iba, patakbuhin ang `omarchy models use <recipe>`. Ngayon, ang `qwen3.8-flash-next-gufo` at `qwen3.8-27b-gufo` ay available para sa mga 128 GB Strix Halo machine; ang 27B ay kumukuha ng humigit-kumulang 40 GiB, kaya nag-iiwan ito ng puwang para sa ibang trabaho. Sa isang 64 GB laptop na may Intel's Arc B390, ang `qwen3.6-35b-a3b-llamacpp` ay tumatakbo sa humigit-kumulang 30 GiB. Ang mga bagong recipe at rekomendasyon ay dumarating kasama ng `omarchy update`, sa pamamagitan ng package.

Ang isang coding model na idinaragdag mo ay nakakakuha ng sarili nitong linya sa panel ng mga agent, sa tabi ng iyong mga subscription: play para simulan ito, pause para pahintuin ito at palayain ang memory nito, ang Tailscale mark para ibahagi ito sa iba pang mga machine sa iyong tailnet habang tumatakbo ito, at ang terminal button para buksan ang iyong agent dito. Ipinapakita ng linya nito ang download, load o stop habang nangyayari ito, at sinasabi kapag walang sapat na libreng memory para simulan ito, o nagli-link sa mga log nito kapag huminto ito nang may error. Marami ang maaaring tumakbo nang sabay kapag kasya sila nang magkasama sa memory. Pindutin ang Delete sa isang napiling linya para alisin ang modelo mula sa machine na ito, kasama ang download; maaaring i-setup itong muli ng +. Ang isang coding model na sine-setup mula sa isang terminal ay naghihintay sa ilalim ng + hanggang idagdag mo ito, at gayundin ang mga modelo na pinapatakbo ng isang machine na ipinares mo (`omarchy models pair <host>`).

Bawat coding model na sine-setup mo ay nakakakuha rin ng sarili nitong entry sa app launcher, sa ilalim ng pangalan ng modelo at kasama ang logo ng gumawa nito, sa paraang ang pag-sign in sa Claude, Codex o Grok ay nagdaragdag ng isa. Binubuksan nito ang iyong agent sa modelong iyon, at sinisimulan muna ang modelo kung hindi ito tumatakbo: ipinapakita ng terminal na naglo-load ito at ibibigay sa agent kapag handa na ito. Ang pag-aalis ng isang modelo ay nag-aalis ng entry nito.

Hindi lahat ng modelo ay para sa coding. Ang mga image, video at music model ay nagbubukas sa Fantasi sa halip, ang app ng Omarchy para gumawa ng mga larawan, video at musika gamit ang isang modelong tumatakbo sa machine na ito, at pinamamahalaan doon o gamit ang `omarchy models`.

Ang isang modelo ay patuloy na tumatakbo nang eksakto kung paano ito sine-setup, kaya hindi kailanman nire-restart ng isang Omarchy update ang isa sa ilalim ng iyong mga agent. Kapag may mas bagong runtime o mas bagong mga weight ang Omarchy para sa isang modelong sine-setup mo, ipinapakita ng linya nito ang isang update button: pindutin ito at ang modelo ay sine-setup muli sa background, dina-download lamang ang nagbago, at magre-restart sa bagong bersyon. Ang isang modelong nakahinto ay nananatiling nakahinto. Ginagawa ng `omarchy models update` ang pareho para sa bawat modelo mula sa isang terminal.

Mula sa command line, ginagawa ng `omarchy models start <recipe>` at `omarchy models stop <recipe>` ang pareho, ipinapakita ng `omarchy models status` ang bawat modelo, at binubuksan ng `omarchy agent --local-model <recipe>` ang modelong iyon sa pi, anuman ang iyong default na agent. Para gawing ang iyong lokal na modelo ang binubuksan ng agent hotkey, ng Quake console, at ng _Make something_, patakbuhin ang `omarchy default agent local` o i-star ang isang tumatakbong modelo sa panel ng mga agent. Inililista rin ng pi ang bawat modelong sine-setup mo, at ang mga nasa machine na ipinares mo, sa sarili nitong model picker, kaya naaabot din sila ng simpleng `pi`. Maaari ding kumonekta ang anumang OpenAI-compatible client: ipinapakita ng `status` ang address ng bawat modelo (ang una ay `http://127.0.0.1:11435/v1`), ang pangalan ng recipe ang modelo, at ang key ay nasa `~/.config/omarchy/agent-local/key`.

Binubura ng `omarchy models remove <recipe>` ang isang modelo at ang mga download na hindi ginagamit ng ibang modelo.

Ang mga third-party runtime ay nilalagyan ng label ng kanilang publisher. Pinapatakbo ng Omarchy ang bawat modelo nang walang network access.

### Mga lokal na LLM

Inirerekomenda ng Omarchy ang dalawang paraan ng pagpapatakbo ng mga lokal na LLM model: LM Studio at Ollama. Nagbibigay ang LM Studio ng isang GUI interface para sa paghahanap ng mga open-weight model, pag-install sa mga ito, at pagpapatakbo sa mga ito. Ito ay isang mahusay na paraan para madaling makapagsimula. Nag-aalok ang Ollama ng isang CLI para gawin ito nang katulad. Ngunit kung bago ka sa mga lokal na modelo, magsisimula ako sa LM Studio. Maaari mong i-install ang alinman sa ilalim ng _Install > AI_ sa Omarchy Menu.

### Ang mga skill ng Omarchy

Tinutulungan ng mga agent skill ang AI na gumamit ng mga partikular na tool sa isang partikular na paraan, at nagpapadala ang Omarchy ng pito sa mga ito. Sinasaklaw ng omarchy skill ang pagpapasadya ng system, tulad ng pag-aayos ng iyong Hyprland config o pag-aadjust ng bar. Sinasaklaw ng omarchy-make-theme, omarchy-make-plugin, omarchy-make-app, at omarchy-make-game ang paggawa ng bagong bagay, sinasaklaw ng omarchy-contribute ang pag-uulat ng bug o pagpapadala ng fix sa upstream, at ginagawa ng omarchy-diagnose-crash ang pagdaan sa core dump ng isang crash. Naka-symlink sila sa mga skill directory para sa Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` at bawat `~/.hermes/profiles/*/skills`), at ang generic na lokasyon ng `~/.agents/skills`, kaya awtomatikong nakukuha sila ng karamihan sa mga harness. Ang isang skill folder mo na may parehong pangalan ay inuuna.

Ngunit dapat mong ituring na experimental ang mga skill na ito. Gagamitin sila ng iba't ibang modelo sa iba't ibang epekto. Pinakamainam na tumakbo muna sa plan mode, para magkaroon ka ng ideya kung ano ang gustong baguhin ng agent. At pagkatapos ay maging handa na i-rollback ang mga pagbabago o kahit tawagin ang `omarchy reinstall configs`, kung guguluhin ng agent ang lahat.
