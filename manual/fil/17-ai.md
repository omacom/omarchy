# AI

Kasama sa Omarchy ang mga launcher para sa mga coding agent sa ibaba nang hindi pumipili ng default para sa iyo. Magpatakbo ng isang utos para ma-install ang CLI nito sa unang paggamit, pagkatapos ay mag-authenticate kapag sinabihan ka. Ang Hermes at OpenClaw ang mga eksepsiyon: walang ini-install para sa kanila sa pamamagitan ng mise, at ang pagpili sa alinman ay nagse-setup ng sarili nitong self-updating na kopya, tulad ng ipinaliliwanag ng _Mga desktop app_ sa ibaba.

### Pag-install at pag-update ng mga agent

Maliban sa Hermes at OpenClaw, gumagamit ang mga agent na ito ng lazy installation ng mise: ini-install ng unang paglunsad ang CLI, at muling ginagamit ito ng mga susunod na paglunsad. Sinusuri rin ng mise ang isang naka-install na agent para sa bagong release nang hindi hihigit sa isang beses bawat apat na oras, bago ito magsimula o sa background sa isang shell prompt. Kung mabigo ang update na iyon o offline ka, tatakbo ang naka-install na bersyon. Ina-update ng `omarchy update` ang mga naka-install na agent kasama ang iba pang bahagi ng Omarchy, at ina-update ng `mup` ang mga tool na pinamamahalaan ng mise lamang.

Hindi ina-update ng sariling updater ng isang agent, tulad ng `claude update`, `codex update`, o isang update button sa isang app, ang install na pinamamahalaan ng mise. Nabibigo ang `codex update`, at maaaring mag-ulat ng tagumpay ang `claude update` habang nag-i-install ng hiwalay na kopyang hindi sinusubaybayan ng mise. Kung mas gusto mong gamitin ang native installer at updater ng isang agent, idagdag ito sa `disable_tools`; tingnan ang [Mga paunang naka-install na CLI tool](18-development-tools.md#preinstalled-cli-tools).

Para ma-install ang lahat ng naka-configure na lazy tool bago mo kailanganin ang mga ito, patakbuhin ang `mise install --include-lazy`. Kasama rito ang iba pang default na CLI tool ng Omarchy pati na rin ang mga agent. Tingnan ang [Mga paunang naka-install na CLI tool](18-development-tools.md#preinstalled-cli-tools) para sa pag-install ng iisang tool o paggamit ng sarili mong installation.

Ini-install ang `grok` sa pamamagitan ng first-party na `grok` package ng mise, sa parehong paraan tulad ng `claude` at `codex`. Patakbuhin ang `grok`, o piliin ito sa ilalim ng _Agent > Harness_. Laktawan ang `curl | bash` installer sa x.ai. Naglalagay ang paraang iyon ng pangalawang kopya sa `~/.grok/bin`, inuuna ito sa `PATH`, at pinapatungan ang wrapper ng Omarchy.

Binubuksan ng `dsh` ang browser UI nito sa `127.0.0.1:3080`, na ang launch directory ang default workspace nito. Walang starting prompt ang browser UI nito, kaya binubuksan ito ng `omarchy agent prompt` na nasa clipboard mo ang prompt para i-paste. Sinisimulan ito ng Omarchy gamit ang no-approval permission preset ng DeepSeek. Nag-a-upload ang DeepSeek Harness ng mga session log sa DeepSeek kapag ginamit mo ang opisyal nitong model API; i-off iyon sa ilalim ng _Settings > General > Upload Session Log_ sa browser UI nito. Ang feedback na ipinapadala mo rito ay ina-upload din kasama ng session, maliban kung simulan mo ito gamit ang `DSH_TELEMETRY_MODE=DISABLED`.

### Ang default na agent

Piliin ang default agent mo gamit ang `omarchy default agent <name>` o sa ilalim ng _Agent > Harness_ sa Omarchy Menu (`Super + Space`). Kung hindi pa naka-install ang agent, ini-install muna ito ng pagpili rito, at nakakakuha rin ito ng sarili nitong launcher sa app launcher, katabi ng Agent. Ang bagong Omarchy ay mag-aanyaya sa iyong gawin ang pagpipiliang ito gamit ang isang beses na notification.

Sinusubukan din ng pagpili sa Claude na i-setup ang browser extension nito para sa Chromium, Chrome, Brave, Brave Origin, at Edge. Nalalapat ang extension setup sa lahat ng user at maaaring humingi ng password ng system mo; ang pagkansela o nabigong pag-install ng extension ay pipili at maglulunsad pa rin sa Claude. I-restart ang browser mo, i-enable ang extension kung sinabihan ka, at mag-sign in sa Claude para tapusin ang pagkonekta nito. Patakbuhin ang `/chrome` sa Claude para suriin ang koneksiyon. Hindi sinusuportahan ng Firefox at Zen ang extension na ito. Kung si Claude na ang default mo bago idagdag ang setup na ito, piliin ito ulit para ma-install ang extension.

Kapag nakapili ka na, inilulunsad ng `Super + Shift + Ctrl + A` ang default na agent sa isang nakalaang terminal window (o inilalabas ang picker kung hindi ka pa nakakapili). Maaari mo rin itong ilunsad diretso sa isang gawain gamit ang `omarchy agent prompt "Review this project"`. Walang starting prompt ang Freebuff at DeepSeek Harness, kaya sa halip ay bubukas ang mga ito na nasa clipboard mo ang prompt para i-paste. Ang mga agent na inilunsad sa ganitong paraan ay tumatakbo nang walang bantay sa kani-kanilang don't-stop-to-ask mode, kaya maghanda kang talagang may gagawin sila! Walang ganoong mode ang MiniMax Code para sa mga interactive session nito, kaya humihingi ito ng mga pahintulot gaya ng dati. At dahil tumatanggi ang mga agent na tandaan ang trust para sa home directory mo, sa `~/Work` sa halip nagsisimula ang mga paglunsad mula sa `$HOME`.

May mga terminal shortcut din: pinapatakbo ng `a` ang default na agent nang inline sa kasalukuyang terminal, habang sinisimulan ng `c`, `cx`, at `cy` ang OpenCode, Claude Code, at Codex nang direkta (muli sa kanilang auto-approving mode). Nagsi-sync din ang mga pagbabago ng tema sa mga agent: ang Claude Code, Pi, OpenCode, at Hermes (kapag na-install na ito ng Omarchy) ay pawang sumusunod kapag nagpalit ka ng tema ng Omarchy.

### Mga tagubilin ng agent mo

Ang mga personal na panuntunan para sa bawat agent ay nasa `~/.agents/AGENTS.md`, katabi ng mga shared skill sa `~/.agents/skills`. Buksan ito sa ilalim ng _Agent > Instructions_, na nagli-link din nito sa bawat harness na may sarili nitong global file: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, ang `~/.copilot/copilot-instructions.md` ng Copilot, at iba pa. Binabasa ng Crush at Amp ang link na `~/.config/AGENTS.md`, habang direktang binabasa ng omp, Kimi, at DeepSeek Harness ang `~/.agents/AGENTS.md`. Ang pagpili ng default na agent ay nagli-link din nito. Ang instructions file na mayroon ka na ay nagiging shared na file kung wala pa; kung hindi, itatabi ito sa tabi ng link bilang `.bak`. Patakbuhin ang `omarchy agent instructions` para muling i-link pagkatapos mag-install ng isa pang agent.

### Ang panel ng mga agent

May icon ng mga agent ang top bar. Bago ka makapag-setup ng agent, gagabayan ka ng panel nito sa pag-sign in sa Claude, Codex, o Grok, at ang una ay nagiging default agent mo. Pagkatapos niyon, inilalagay ng panel ang bawat subscription sa iisang pahina: bawat agent at account kasama ang plan nito, isang meter para sa bawat 5-hour session at weekly limit nito kasama ang oras hanggang mag-reset ito (i-hover para sa eksaktong porsiyento), o ang natitirang prepaid balance, sa ilalim ng isang linyang umiikot sa kung ano ang nagamit mo sa lahat ng mga ito, tulad ng mga token ngayong linggo at ang pinakamadalas mong ginamit na modelo. Sa ilalim ng _Make something cool_ nag-aalok ito ng mga starter prompt para sa bagong tema, plugin, app, o laro na nagbibigay ng gawain sa default agent mo. Ang mga app ay binubuo sa paraan ng sariling Hype, Monologue, at Omacut ng Omarchy, sa C++ at Qt Quick, na sumusunod sa omarchy-make-app agent skill, at naka-install na ang compiler at mga piraso ng Qt na kailangan nila. Ang mga laro ay iisang three.js page sa `~/Games/vibes`, na sumusunod sa omarchy-make-game agent skill, at lahat ay bubukas mula sa iisang Game Vibes launcher sa kasalukuyang tema; naglo-load sila ng three.js mula sa web, kaya kailangan nila ng koneksiyon para magsimula. Ang Claude Code, Codex, Grok, Kimi, Cursor at ang Grok Bot allowance nito, GitHub Copilot, Muse, Antigravity, at Devin ay sakop agad kasama ang kanilang mga limit, ang Kimchi kasama ang plan nito, prepaid credits, at spend budgets, at ipinapakita ng Hermes, Mistral Vibe, at Qwen Code ang kanilang mga session at token kapag nagamit mo na sila. Lumalabas din ang mga provider plan at key na ginagamit mo sa pamamagitan ng pi, omp, o opencode: ang OpenCode Zen at Go, ang Z.ai GLM Coding Plan, Ollama Cloud, ang MiniMax Token Plan, at Synthetic kasama ang kanilang mga limit; ang OpenRouter at DeepSeek kasama ang kanilang prepaid balance; ang Fireworks kasama ang gastos nito sa nakalipas na 30 araw. Nabibilang din sa mga kabuuan ang mga token mula sa mga modelong pinapatakbo mo sa sarili mong hardware; ang mga modelo mismo ay may sarili nilang panel, na inilalarawan sa ilalim ng [Mga lokal na modelo](#local-models). Bawat agent ay binibilang nang isang beses, sa ilalim ng kung sino ang naniningil para rito, gaano man karaming harness ang patakbuhin mo rito.

I-left-click ang icon sa bar o pindutin ang `Super + Ctrl + X` para sa panel, i-right-click para ilunsad ang default agent mo, at i-middle-click para i-refresh. Ang mga usage record sa likod nito ay muling ginagawa bawat 15 minuto ng `omarchy agent usage update`, at maaari pang pagsamahin ng panel ang usage mula sa iba mo pang machine sa pamamagitan ng naka-sync na folder. Tingnan ang README sa ilalim ng `$OMARCHY_PATH/shell/plugins/agents/` para sa buong mga setting.

### Maraming subscription

Kung nagbabayad ka para sa higit sa isang Claude, Codex, o Grok plan — isang personal na Max at isang pang-trabaho, halimbawa — maaaring panatilihin ng Omarchy na naka-sign in silang lahat at lumipat sa pagitan nila. Magdagdag ng subscription gamit ang + sa agents panel, na gagabay sa iyo roon mismo, o gamit ang `omarchy agent account add claude Work` (o `codex`, o `grok`). Ini-install nito ang CLI kung kulang ito. Ang unang account para sa isang provider ay nagsa-sign in sa pamamagitan ng normal mong browser, mismo kung saan palaging tumitingin ang CLI. Ang bawat kasunod ay nagsa-sign in sa pamamagitan ng private window, kaya hindi aksidenteng makuha ang account kung saan naka-sign in na ang browser mo; mag-sign in doon bilang account na idinaragdag mo, at isara muna ang anumang private window na nakabukas mo na. Huwag kailanman mag-log out sa CLI para gawin ito: ang pag-log out ay nagre-revoke ng naka-save na sign-in, at kailangang idagdag ulit ang account na iyon.

Para kopyahin ang mga subscription login mo sa isa pang Omarchy machine sa pamamagitan ng SSH, patakbuhin ang `omarchy agent account copy user@laptop`. Ang sender ay nagbibigay ng pansamantalang receiver kapag walang naka-install ang destination, kaya ang mas lumang Omarchy machine ay maaaring tumanggap ng mga account nang walang update. Ang mga naka-install na receiver ang nangunguna. Kinokopya nito ang lahat ng Claude, Codex, at Grok subscription; magdagdag ng mga provider name para piliin sila, tulad ng sa `omarchy agent account copy laptop claude`. Ang mga pangalan ng account at command ID ay tumutugma sa source, kabilang ang mga account na mayroon na sa destination. Ang mga hindi kaugnay na destination account ay tumatanggap ng numeric suffix kung magkasalungat ang mga pangalan nila, at ang mga setting, skill, plugin, at history ng pag-uusap ay mananatiling lokal sa bawat makina.

Pananatilihin ang mga umiiral na destination credential. Ang source account na naka-sign in na roon ay isi-synchronize ang pangalan nito nang hindi pinapalitan ang mga credential nito; ang ibang mga account ay idinaragdag sa tabi nito. Para palitan ang mga naka-save na credential para sa magkatugmang account, gamitin ang `omarchy agent account copy --replace laptop claude` pagkatapos isara ang mga session ng account na iyon sa destination. Ang bagong destination ay nakakakuha rin ng aktibong account at mga switching preference ng source; ang matagal nang destination ay pinapanatili ang sarili nito.

Naglalakbay ang mga credential sa pamamagitan ng SSH at nakaimbak sa mga pribadong file sa destination, kaya kumopya lamang sa mga makinang pinagkakatiwalaan mo. Ito ay isang beses na kopya, hindi patuloy na synchronization. Ang mga Codex refresh token ay maaaring i-rotate ng ibang makina, na mag-iiwan sa kinopyang login na nangangailangan ng renewal; ang hiwalay na mga sign-in ay nananatiling pinaka-maaasahang pagpipilian para sa sabay-sabay na paggamit sa maraming makina. Tingnan ang [gabay sa account authentication ng Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Iisang account bawat provider ang aktibo, at bawat bagong session ay nagsisimula bilang ito: `cx`, `cy`, isang payak na `claude`, `codex`, o `grok`, anumang inilunsad sa pamamagitan ng `omarchy agent`, at mga script o editor na nakakahanap ng CLI sa `PATH`. Lumipat gamit ang `omarchy agent account use work` (at bumalik gamit ang `omarchy agent account use main`), o sa panel sa pamamagitan ng pagpindot sa numero ng isang account at pagkatapos ay `Enter` (o pag-click sa Use button nito). Lumilipat din ang mga tumatakbong Claude session, mula sa susunod nilang mensahe: bawat Claude session ay tumatakbo sa `~/.claude`, na palaging naglalaman ng sign-in ng aktibong account. Ang Claude session na sinimulan sa sariling folder ng isang account ng mas lumang Omarchy ay nagtataglay ng sign-in na iyon hanggang sa umalis ito, kaya pinapangalanan ng switch ang mga session na iyon at natatapos nang kusa kapag wala na sila. Ang mga tumatakbong Codex at Grok session ay nananatili sa account kung saan sila nagsimula. Ang history ng pag-uusap, mga setting, skill, at plugin ay ibinabahagi sa mga account, kaya ang `claude --continue` sa parehong folder ay nagpapatuloy kung saan ka huminto sa bagong account.

Sa higit sa isang account, ipinapakita ng panel ang mga limit ng bawat account nang magkatabi, na minarkahan ang aktibo. Bilang default, ino-notify ka ng Omarchy kapag lumampas ang aktibong account sa 95% ng isang limit, at ang pag-click sa notification ay lumilipat sa account na may pinakamaraming headroom. I-hover ang linya ng isang account sa panel at i-click ang Autoswitch na lumalabas sa tabi ng Use (o pindutin ang `m`), o patakbuhin ang `omarchy agent account mode auto`, para lumipat ito nang kusa sa halip; habang naka-on ito, pumapalit ang Autoswitch sa Use, at ang pag-click dito ulit ay bumabalik sa pag-notify. Magdagdag ng numero para baguhin ang threshold, tulad ng sa `omarchy agent account mode auto 90`. Kung ang bawat account ay lumampas sa threshold, maririnig mo ito nang isang beses, kasama kung aling account ang unang magkakaroon ng puwang. Habang ang aktibong account ay nasa loob ng 15 puntos ng threshold nito (80% sa default), sinusuri ang mga limit nito bawat tatlong minuto sa halip na bawat 15.

Ipinapakita ng `omarchy agent account list` ang bawat account at ang pinakabagong mga limit nito, nakakalimutan ng `omarchy agent account remove work` ang isa, at pinapalitan ng pangalan ng `omarchy agent account rename primary Hey` ang isa (o i-click ang pangalan ng isang account sa panel). Gumagana ang mga utos na ito sa mga account ng default agent mo; para maabot ang ibang provider, pangalanan muna ito, tulad ng sa `omarchy agent account use codex side`. Ang login na mayroon ka na sa `~/.claude` o `~/.codex` ay ang _Main_ account. Ang sa Codex ay nananatili kung nasaan ito; ang sa Claude ay naghihintay sa sarili nitong folder habang may ibang account na aktibo. Ang account na hindi nagamit nang higit sa mga walong oras ay maaaring magpakita ng _Sign-in required_; i-click ito para muling i-sign in ang account na iyon diretso sa panel, o lumipat dito at magsimula ng session, na nagre-refresh ng sign-in nang kusa. Ang mga MCP server na idinaragdag mo gamit ang `claude mcp add` ay umaabot sa bawat Claude account, dahil lahat sila ay tumatakbo sa `~/.claude`; para sa Codex at Grok, ang mga server na mayroon ka noong idinagdag ang isang account ay sumasama rito, pero ang mga susunod ay umaabot lamang sa account kung saan mo idinagdag ang mga ito. May sarili nitong sign-in ang Claude Desktop, at ang mga Codex o Grok tool na naka-configure gamit ang absolute path papunta sa isang CLI binary ay hindi sumusunod sa switch. Ang tahasang `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, o `GROK_HOME` ay nangunguna kaysa sa napiling account.

### Pag-diagnose ng crash

Binabantayan ng Omarchy ang systemd-coredump para sa mga pag-crash ng process. Kapag nakapili ka na ng default na agent, anumang programa mo na mag-dump ng core ay magdadala ng notification na "Process crashed" — i-click ito, at ibibigay ang crash sa default agent mo kasama ang omarchy-diagnose-crash skill ng Omarchy, na gagabay sa agent sa pagtatatag ng mga katotohanan mula sa core dump at pagpapasya kung karapat-dapat bang iulat ang crash sa upstream. Maaari mo rin itong patakbuhin nang mano-mano laban sa anumang PID mula sa `coredumpctl list` gamit ang `omarchy agent crash <pid>`.

Naka-on ang pagbantay bilang default. I-off ito sa ilalim ng _Trigger > Toggle > Crash Capture Off_ (o gamit ang `omarchy toggle crash-capture`) at hihinto ang mga notification; gumagana pa rin nang mano-mano ang `omarchy agent crash <pid>`.

Maaari ding patahimikin ang mga crash nang paisa-isang programa, na siyang inaalok sa iyo ng diagnosis sa dulo. Pinipigilan ng `omarchy crash mute hyprland` ang mga notification para lamang sa programang iyon, ibinabalik sila ng `omarchy crash mute hyprland off`, at inililista ng `omarchy crash mute` nang mag-isa kung ano ang na-mute mo. Tinatanggap nito ang path ng binary nang kasingdali ng pangalan nito, kaya pareho ang ginagawa ng `omarchy crash mute /usr/bin/hyprland`. I-quote ang pangalang may puwang, tulad ng sa `omarchy crash mute 'Some App'`. Nagno-notify pa rin ang lahat ng iba, at nagka-crash pa rin ang na-mute na programa — itinatago nito ang paalala, hindi nito inaayos ang anuman.

### Mga desktop app

Nagdadala rin ang menu na _Install > AI_ ng ilang graphical AI app: Amp Desktop, Antigravity Desktop, ang ChatGPT desktop app, ang Claude desktop app (Linux beta ng Anthropic, na may mga tab na Chat, Cowork, at Claude Code), Grok Bot para makipag-chat sa mga modelo ng xAI, Herdr Desktop, Hermes Desktop, OpenClaw, ang Perplexity desktop app, at T3 Code. Ang Grok Bot ang desktop chat app. Ang coding agent ay ang utos na `grok`.

Ang Hermes Desktop ang dapat mong malaman, dahil iisa lang ang Hermes ng isang makina, at sa app iyon: ang Hermes ay ini-install lamang sa pamamagitan ng app, at ang utos na `hermes` na pinapatakbo ng default agent ay sa app. Ang pagpili sa Hermes bilang default agent ay nag-i-install ng parehong bagay na ginagawa ng entry na _Install > AI_: ang package, at isang Hermes runtime sa ilalim ng `~/.hermes` na sine-setup ng sariling installer ng Hermes, na tumatagal ng ilang minuto sa unang pagkakataon. Ang runtime na iyon ang iisang Hermes na ginagamit ng terminal na utos na `hermes`, ng default agent at ng app, at ina-update nito ang sarili gamit ang `hermes update` sa halip na maghintay sa isang Omarchy release. Ang pag-install nito ay nagbibigay din sa Hermes ng tema ng Omarchy bilang skin na pinangalanang `omarchy`, na sinusundan ng bawat Hermes surface habang nagpapalit ka ng tema; pumili ng iba sa ilalim ng Appearance settings ng Hermes o gamit ang `/skin` kung mas gusto mong hindi, at hindi pakikialaman ng Omarchy ang pagpipiliang iyon. Ang pag-alis ng app sa ilalim ng _Remove > AI_ ay isinasara muna ang Hermes, kasama ang gateway, isinasama ang runtime na iyon, at pinapanatili ang iyong mga chat, memory, at ang mga skill na isinulat ng Hermes para sa sarili nito maliban kung sabihin mo ang kabaligtaran: nagtatanong ito, na ang default ay hindi, kung dapat ding alisin ang data na iyon at ang iyong connection settings.

Ang desktop experience ng OpenClaw ay ang Control UI nito, na bubukas bilang web app na sinusuportahan ng sarili nitong local gateway. Nakatira ang OpenClaw sa `~/.openclaw` at ina-update ang sarili nito: gamitin ang button na "Update Gateway" ng Control UI o patakbuhin ang `openclaw update`, at magre-restart ang gateway sa bagong bersyon. Pinipili lamang ng Omarchy ang release kung saan nagsisimula ang bagong install. Maaari ding maging default agent mo ang OpenClaw: ang pagpili nito sa ilalim ng _Agent > Harness_ ay nagse-setup ng parehong kopya sa `~/.openclaw`, at binubuksan ng agent ang terminal UI ng OpenClaw na nakakabit sa gateway nito. Ang pag-alis ng OpenClaw sa ilalim ng _Remove > AI_ ay isinasama ang gateway service at ang app at pagkatapos ay nagtatanong kung dapat ding alisin ang `~/.openclaw`, dahil naroon ang iyong mga chat at credential kasama ang OpenClaw mismo at ang mga plugin runtime na dina-download nito; pinapanatili ito ng default, at ang muling pag-install ng OpenClaw ay kukunin ito ulit.

Ang Herdr Desktop ay ang desktop app na [Herdr](https://herdr.dev): mga space, tab, at pane ng mga terminal at coding agent na patuloy na tumatakbo sa core nito kapag isinara mo ang window. Nagmumula ito sa sariling installer ng Herdr sa halip na package, kaya nakatira ito sa `~/.local/share/herdr-app`, isinasama ang core nito sa `~/.local/bin/herdr-core` kapag wala ka pa nito, at ina-update ang sarili nitong dalawa. Nakaupo ito sa tabi ng utos na `herdr` na ibinibigay ng Omarchy sa `Super + Ctrl + Return` sa halip na palitan ito, at nakukuha ang mga direct key ng utos na iyon: hinahati ng `Alt + Return` at `Alt + Shift + Return` ang isang pane pababa o pakanan, isinasara ito ng `Alt + Escape`, gumagalaw ang `Ctrl + Alt + Arrow` sa pagitan ng mga pane, pumipili ang `Alt + 1..9` at `Alt + Left/Right` ng tab, at gumagalaw ang `Alt + Up/Down` sa pagitan ng mga space. Pumipili ang `Ctrl + 1..9` ng space at humahakbang ang `Alt + Shift + Up/Down` sa mga agent. Ang mga prefix key na `Ctrl + Space` ay mananatiling terminal-only, dahil hindi kayang hawakan ng app ang payak na Ctrl key para sa isang sequence. Isinusulat ito ng Omarchy sa `~/.config/herdr-app/keys.json`, at ibinabalik sila ng `omarchy-refresh-herdr-app`. Pinipili ng pag-install nito ang Omarchy theme ng Herdr, na susunod sa Omarchy theme mo mula noon. Nag-iingat ang Herdr ng isang tema para sa light mode at isa para sa dark, kaya pagkatapos lumipat sa pagitan ng dark at light na Omarchy theme, piliin ulit ang Omarchy sa theme picker ng Herdr nang isang beses para sa kabilang mode.

Tumatakbo ang T3 Code mula sa opisyal nitong AppImage release sa `~/.local/share/t3code` sa halip na mula sa package, kaya ina-update nito ang sarili. Nagtatanong ang pag-install nito kung magsisimula sa Stable o Nightly channel; lumipat mamaya sa mga setting ng T3 Code. Nakatira ang mga thread at setting mo sa `~/.t3`, at ang pag-alis ng T3 Code sa ilalim ng _Remove > AI_ ay isinasama sila.

### Mga lokal na modelo

Magpatakbo ng open model sa sarili mong makina para sa mga coding agent mo. Nananatili sa makina ang mga prompt at code mo; walang ipinapadala sa modelo ang umaalis dito. Magsimula sa:

```bash
omarchy models use best text
```

Itinatayo niyon ang pinakamahusay na text model para sa makinang ito, ang uri na ginagamit ng mga agent mo. Ang mga image, video at music model ay may sarili nilang pinakamahusay: `omarchy models use best image`, `video` o `music`. Patakbuhin ang `omarchy models use best` para makita ang pinili ng bawat uri para sa makinang ito.

O buksan ang local models panel mula sa sparkles icon nito sa top bar, katabi ng agents icon, o gamit ang Super + Ctrl + Alt + X, at piliin ang +. Lumalabas ang icon kapag may modelong kasya sa makinang ito. Ang Podman, na nagpapatakbo ng mga modelo, ay kasama ng Omarchy, gayundin ang container toolkit ng NVIDIA sa isang NVIDIA machine, na nagbibigay sa kanila ng GPU; kung may kulang sa alinman, ini-install ito ng unang setup. Pagkatapos ay pinipili ng Omarchy ang inirerekomendang modelo para sa makinang ito, dina-download ito, at sinisimulan ito. Asahan ang download na sampu-sampung GB at ang karamihan ng memory ng makina ay ginagamit habang tumatakbo ang modelo: gumagamit ang Flash Next ng mga 100 GiB kasama ang buong 256K context nito. Kung hawak ng ibang mga modelo ang memory na kailangan nito, itinatayo itong nakahinto, handang magsimula kapag huminto ka ng isa. Humihinto ang modelo sa pag-logout; ihinto mo ito mismo kapag kailangan mo ang memory para sa iba pa.

Ipinapakita ng `omarchy models list` ang mga opsiyon at ipinapaliwanag kung bakit hindi kasya ang ilan. Para mag-setup ng isa pa, patakbuhin ang `omarchy models use <recipe>`. Ngayon, available ang `qwen3.8-flash-next-gufo` at `qwen3.8-27b-gufo` para sa 128 GB Strix Halo machines; ang 27B ay gumagamit ng mga 40 GiB, kaya nag-iiwan ito ng puwang para sa iba pang trabaho. Sa isang 64 GB laptop na may Intel's Arc B390, tumatakbo ang `qwen3.6-35b-a3b-llamacpp` sa mga 30 GiB. Dumarating ang mga bagong recipe at rekomendasyon kasama ng `omarchy update`, sa pamamagitan ng package.

Ang bawat modelong ise-setup mo ay may sarili nitong linya sa local models panel: play para simulan ito, pause para ihinto ito at palayain ang memory nito, at ang terminal button para buksan ang agent mo rito. Sa itaas, ipinapakita ng isang bar kung paano nahahati ang memory ng makina sa pagitan ng Omarchy mismo (ang system at mga app mo), bawat tumatakbong modelo, at kung ano ang libre. Ituro ang isang nakahintong modelo at ipapakita ng bar kung kasya ito, o kung gaano ito kakulang. Marami ang maaaring tumakbo nang sabay kapag magkakasya sila sa memory nang magkasama; kung hindi kasya ang isa, sasabihin ng Omarchy kung aling tumatakbong modelo ang ihihinto. I-drag ang mga linya gamit ang logo nila para muling ayusin sila, at pindutin ang Delete sa napiling linya para alisin ang isang modelo at ang download nito.

Ang bawat coding model na ise-setup mo ay nakakakuha rin ng sarili nitong entry sa app launcher, sa ilalim ng pangalan ng modelo at kasama ang logo ng gumawa nito, sa paraan na ang pag-sign in sa Claude, Codex o Grok ay nagdaragdag ng isa. Binubuksan nito ang agent mo sa modelong iyon, at sinisimulan muna ang modelo kung hindi ito tumatakbo: ipinapakita ng terminal na naglo-load ito at ibibigay sa agent kapag handa na ito. Ang pag-alis ng modelo ay nag-aalis ng entry nito.

Hindi lahat ng modelo ay para sa coding. Ang mga image, video at music model ay bubukas sa halip sa Fantasi, ang app ng Omarchy para gumawa ng mga larawan, video at musika gamit ang modelong tumatakbo sa makinang ito, pinili roon o mula sa linya nila sa local models panel.

Nananatiling tumatakbo ang isang modelo nang eksakto kung paano ito na-setup, kaya hindi kailanman nire-restart ng Omarchy update ang isa sa ilalim ng mga agent mo. Kapag may mas bagong runtime o mas bagong weights ang Omarchy para sa modelong na-setup mo, ipinapakita ng linya nito ang update button: pindutin ito at muling ise-setup ang modelo sa background, dina-download lamang kung ano ang nagbago, at magre-restart sa bagong bersyon. Ang modelong nakahinto ay mananatiling nakahinto. Pareho ang ginagawa ng `omarchy models update` para sa bawat modelo mula sa terminal.

Mula sa command line, pareho ang ginagawa ng `omarchy models start <recipe>` at `omarchy models stop <recipe>`, ipinapakita ng `omarchy models status` ang bawat modelo, at binubuksan ng `omarchy agent --local` ang huling modelong sinimulan mo sa pi, anuman ang default agent mo. Maaari ding gumamit ng lokal na modelo ang OpenCode at Qwen Code: binubuksan sila roon sa halip ng `omarchy models harness opencode` o `omarchy models harness qwen`, at bumabalik ang `omarchy models harness pi`. Inililista rin ng pi ang bawat modelong na-setup mo, at ang mga nasa machine na na-pair mo, sa sarili nitong model picker, kaya naaabot din sila ng payak na `pi`. Maaari ding kumonekta ang anumang OpenAI-compatible client: ipinapakita ng `status` ang address ng bawat modelo (ang una ay `http://127.0.0.1:11435/v1`), ang recipe name ang modelo, at ang key ay nasa `~/.config/omarchy/agent-local/key`.

Tinatanggal ng `omarchy models remove <recipe>` ang isang modelo at ang mga download na hindi ginagamit ng ibang modelo.

Ang mga third-party runtime ay may label ng publisher nila. Pinapatakbo ng Omarchy ang bawat modelo nang walang network access.

### Mga lokal na LLM

Nagrerekomenda ang Omarchy ng dalawang paraan ng pagpapatakbo ng mga lokal na LLM model: LM Studio at Ollama. Nagbibigay ang LM Studio ng GUI interface para maghanap ng mga open-weight model, i-install sila, at patakbuhin sila. Mahusay itong paraan para madaling makapagsimula. Nag-aalok ang Ollama ng CLI para gawin din iyon nang katulad. Pero kung bago ka sa mga lokal na modelo, magsisimula ako sa LM Studio. Maaari mong i-install ang alinman sa ilalim ng _Install > AI_ sa Omarchy Menu.

### Ang mga Omarchy skill

Tumutulong ang mga agent skill sa AI na gumamit ng mga partikular na tool sa partikular na paraan, at may pito nito ang Omarchy. Sinasaklaw ng omarchy skill ang pag-aangkop ng system, tulad ng pag-tweak ng Hyprland config mo o pag-aadjust ng bar. Sinasaklaw ng omarchy-make-theme, omarchy-make-plugin, omarchy-make-app, at omarchy-make-game ang paggawa ng bago, sinasaklaw ng omarchy-contribute ang pag-uulat ng bug o pagpapadala ng fix sa upstream, at pinoproseso ng omarchy-diagnose-crash ang core dump ng isang crash. Naka-symlink sila sa mga skill directory para sa Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` at bawat `~/.hermes/profiles/*/skills`), at ang generic na lokasyon ng `~/.agents/skills`, kaya karamihan ng mga harness ay awtomatikong nakukuha sila. Ang sarili mong skill folder na may parehong pangalan ay nangunguna.

Pero dapat mong ituring na eksperimental ang mga skill na ito. Iba-iba ang epekto ng paggamit nito ng iba't ibang modelo. Pinakamainam na tumakbo muna sa plan mode, para magkaroon ka ng ideya kung ano ang gustong baguhin ng agent. At pagkatapos ay maging handang i-rollback ang mga pagbabago o tumawag pa ng `omarchy reinstall configs`, kung guluhin ng agent ang lahat.
