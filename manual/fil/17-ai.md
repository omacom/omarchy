# AI

Isinasama ng Omarchy ang mga launcher para sa mga coding agent sa ibaba nang hindi pumipili ng default para sa iyo. Mag-install ng isa mula sa _Install > AI > CLI_, pagkatapos ay mag-authenticate kapag sinabihan. Ang Hermes at OpenClaw ang mga eksepsiyon: ang pagpili sa alinman ay magse-set up ng sarili nitong kopyang nag-a-update nang kusa, gaya ng ipinaliliwanag ng _Mga desktop app_ sa ibaba.

### Pag-install at pag-update ng mga agent

Maliban sa Hermes at OpenClaw, bawat agent ay isang package mula sa sariling repository ng Omarchy. Mag-install ng isa mula sa _Install > AI > CLI_ o gamit ang `omarchy install ai cli <command>`, at alisin itong muli mula sa _Remove > AI > CLI_, na nag-iiwan sa mga sign-in at history nito sa lugar. Ang pagpili ng agent na hindi pa na-i-install ay mag-i-install din nito: ang pag-star dito sa panel ng mga agent, ang pagpili dito gamit ang `omarchy default agent <name>`, o ang pag-sign in sa subscription nito. Inilalathala ng Omarchy ang bawat bagong release ng isang agent sa loob ng isang oras, sa bawat channel, at ini-install ito ng `omarchy update` kasama ng iba pa sa system.

Dahil pinapanatili silang napapanahon ng pacman, naka-off ang sariling mga updater ng mga agent: walang magagawa ang `claude update` o isang update button sa isang app. Kung mas gusto mong patakbuhin ang isang agent mula sa sarili nitong installer, gamitin iyon at iwanang hindi naka-install ang package ng Omarchy; ang kopyang nasa iyong `PATH` na ay itinuturing na naka-install. Laktawan ang mga `curl | bash` installer na naglalagay ng pangalawang kopya na inuuna kaysa sa Omarchy sa `PATH`, gaya ng sa x.ai para sa `grok`.

Binubuksan ng `dsh` ang browser UI nito sa `127.0.0.1:3080`, na ang launch directory ang default workspace nito. Walang starting prompt ang browser UI nito, kaya binubuksan ito ng `omarchy agent prompt` na nasa clipboard mo ang prompt para i-paste. Sinisimulan ito ng Omarchy gamit ang no-approval permission preset ng DeepSeek. Ina-upload ng DeepSeek Harness ang mga session log sa DeepSeek kapag ginamit mo ang opisyal nitong model API; i-off iyon sa ilalim ng _Settings > General > Upload Session Log_ sa browser UI nito. Ang feedback na ipinapadala mo rito ay ina-upload din kasama ng session, maliban kung sisimulan mo ito gamit ang `DSH_TELEMETRY_MODE=DISABLED`.

### Ang default na agent

Piliin ang iyong default na agent gamit ang star sa tabi ng isang agent sa panel ng mga agent, na napupunan sa default, o gamit ang `omarchy default agent <name>`, na tumatanggap din ng anumang harness na walang linya roon. Kung hindi pa naka-install ang agent, ii-install muna ito ng pagpili rito, at makakakuha rin ito ng sarili nitong launcher sa app launcher, sa tabi ng Agent. Inaanyayahan ka ng bagong Omarchy na mag-set up ng isa gamit ang isang beses lang na notification, na nagbubukas sa panel ng mga agent.

Sinusubukan din ng pagpili sa Claude na i-set up ang browser extension nito para sa Chromium, Chrome, Brave, Brave Origin, at Edge. Nalalapat ang pag-setup ng extension sa lahat ng user at maaaring humingi ng password ng iyong system; ang pagkansela o nabigong pag-install ng extension ay pipili at maglulunsad pa rin sa Claude. I-restart ang iyong browser, i-enable ang extension kung sinabihan, at mag-sign in sa Claude para tapusin ang pagkonekta rito. Patakbuhin ang `/chrome` sa Claude para suriin ang koneksiyon. Hindi sinusuportahan ng Firefox at Zen ang extension na ito. Kung Claude na ang iyong default bago pa idinagdag ang setup na ito, piliin itong muli para i-install ang extension.

Kapag nakapili ka na, ilulunsad ng `Super + Shift + Ctrl + A` ang default na agent sa isang nakalaang terminal window (o ilalabas ang picker kung hindi ka pa nakakapili). Maaari mo rin itong ilunsad nang diretso sa isang gawain gamit ang `omarchy agent prompt "Review this project"`. Walang starting prompt ang Freebuff at DeepSeek Harness, kaya sa halip ay bubukas ang mga iyon na nasa clipboard mo ang prompt para i-paste. Ang mga agent na inilunsad sa ganitong paraan ay tumatakbo nang walang nagbabantay sa kani-kanilang mga mode na huwag huminto para magtanong, kaya maging handa na talagang gumawa sila ng mga bagay! Walang ganoong mode ang MiniMax Code para sa mga interactive session nito, kaya humihingi ito ng mga pahintulot gaya ng dati. At dahil tumatanggi ang mga agent na tandaan ang tiwala para sa iyong home directory, ang mga paglunsad mula sa `$HOME` ay sa halip nagsisimula sa `~/Work`.

May mga terminal shortcut din: ang `a` ay nagpapatakbo ng default na agent nang inline sa kasalukuyang terminal, habang ang `c`, `cx`, `cy`, at `ca` ay direktang nagsisimula ng OpenCode, Claude Code, Codex, at Antigravity (muli sa kanilang mga auto-approving mode). Nagsi-sync din ang mga pagbabago ng theme sa mga agent: ang Claude Code, Pi, OpenCode, at Hermes (kapag na-install na ito ng Omarchy) ay pawang sumusunod kapag nagpalit ka ng Omarchy theme.

### Mga tagubilin para sa iyong agent

Ang mga personal na patakaran para sa bawat agent ay nasa `~/.agents/AGENTS.md`, sa tabi ng mga shared skill sa `~/.agents/skills`. Buksan ito gamit ang icon ng dokumento sa tabi ng + sa panel ng mga agent, o ang `omarchy agent instructions --edit`, na nagli-link din nito sa bawat harness na may sarili nitong global file: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, ang `~/.copilot/copilot-instructions.md` ng Copilot, at iba pa. Binabasa ng Crush at Amp ang link na `~/.config/AGENTS.md`, habang direktang binabasa ng omp, Kimi, at DeepSeek Harness ang `~/.agents/AGENTS.md`. Ang pagpili ng default na agent ay nagli-link din nito. Ang instructions file na mayroon ka na ay magiging shared kung wala pa noon; kung hindi, itatabi ito sa tabi ng link bilang `.bak`. Patakbuhin ang `omarchy agent instructions` para muling mag-link pagkatapos mag-install ng isa pang agent.

### Ang panel ng mga agent

May icon ng mga agent ang top bar. Bago ka mag-set up ng agent, nag-aalok ang panel nito ng tatlong paraan para magsimula: mag-sign in sa isang subscription ng Claude, Codex, Grok, Gemini, Muse, Cursor, o Copilot, o sa ilalim ng More sa isang coding plan ng OpenCode Go, MiniMax, Synthetic, o Z.ai; magbayad ayon sa paggamit gamit ang Fireworks, OpenCode Zen and Go, OpenRouter, o sa ilalim ng More ang DeepSeek o anumang iba pang provider na sine-sign in-an ng OpenCode, na lahat ay tumatakbo sa OpenCode; o patakbuhin ang pinakamahusay na modelo para sa iyong computer, kapag may kasya rito. Ang una mong matatapos ay magiging iyong default na agent, at ang + sa panel ay nag-aalok ng parehong tatlo sa ibang pagkakataon. Pagkatapos niyon, inilalagay ng panel ang bawat subscription sa isang page: bawat agent at account kasama ang plan nito, isang meter para sa bawat isa sa 5-hour session at weekly limit nito kasama ang oras hanggang mag-reset ito (mag-hover para sa eksaktong porsiyento), o ang natitirang prepaid balance, sa ilalim ng isang linyang umiikot sa iyong nagamit sa lahat ng mga iyon, gaya ng mga token ngayong linggo at ang pinakaginagamit mong modelo. Sa ilalim ng _Make something cool_ nag-aalok ito ng mga starter prompt para sa bagong theme, plugin, app, o game na nagbibigay ng gawain sa iyong default na agent. Ang mga app ay binubuo sa paraan ng sariling Hype, Monologue, at Omacut ng Omarchy, sa C++ at Qt Quick, na sumusunod sa omarchy-make-app agent skill, at naka-install na ang compiler at mga piraso ng Qt na kailangan nila. Ang mga game ay isang solong three.js page sa `~/Games/vibes`, na sumusunod sa omarchy-make-game agent skill, at lahat ay bumubukas mula sa isang Game Vibes launcher sa kasalukuyang theme; nilo-load nila ang three.js mula sa web, kaya kailangan nila ng koneksiyon para magsimula. Ang Claude Code, Codex, Grok, Kimi, Cursor at ang Grok Bot allowance nito, GitHub Copilot, Muse, Gemini (sa pamamagitan ng Antigravity), at Devin ay saklaw kaagad kasama ng kanilang mga limit, ang Kimchi kasama ang plan nito, mga prepaid credit, at mga spend budget, at ipinapakita ng Hermes, Mistral Vibe, at Qwen Code ang kanilang mga session at token kapag nagamit mo na sila. Lumalabas din ang mga provider plan at key na ginagamit mo sa pamamagitan ng pi, omp, o opencode: ang OpenCode Zen and Go, ang Z.ai GLM Coding Plan, Ollama Cloud, ang MiniMax Token Plan, at Synthetic kasama ng kanilang mga limit; ang OpenRouter at DeepSeek kasama ng kanilang mga prepaid balance; ang Fireworks kasama ng paggastos nito sa nakalipas na 30 araw. Ang mga coding model na pinapatakbo mo sa sarili mong hardware ay nakakakuha ng sarili nilang mga linya, at ang kanilang mga token ay nabibilang din sa mga kabuuan, gaya ng inilalarawan sa ilalim ng [Mga lokal na modelo](#local-models). Bawat agent ay binibilang nang isang beses, sa ilalim ng kung sino ang naniningil para rito, gaano man karaming harness ang patakbuhin mo rito.

I-left-click ang icon sa bar o pindutin ang `Super + Ctrl + X` para sa panel, i-right-click para ilunsad ang iyong default na agent, at i-middle-click para mag-refresh. Ang mga usage record sa likod nito ay muling ginagawa bawat 15 minuto ng `omarchy agent usage update`, at maaari pang pagsamahin ng panel ang usage mula sa iba mo pang machine sa pamamagitan ng isang naka-sync na folder. Tingnan ang README sa ilalim ng `$OMARCHY_PATH/shell/plugins/agents/` para sa buong mga setting.

### Maraming subscription

Kung nagbabayad ka para sa higit sa isang plan ng Claude, Codex, o Grok — isang personal na Max at isa para sa trabaho, halimbawa — maaari silang panatilihin ng Omarchy na naka-sign in lahat at lumipat-lipat sa pagitan nila. Magdagdag ng subscription gamit ang + sa panel ng mga agent, na gagabay sa iyo roon mismo, o gamit ang `omarchy agent account add claude Work` (o `codex`, o `grok`). Ang parehong + at utos ay nagsa-sign in sa Gemini (`gemini`) at OpenCode (`opencode`), at nagse-save ng Fireworks (`fireworks`) o OpenRouter (`openrouter`) API key sa OpenCode; nagsa-sign in din ang utos sa Copilot (`copilot`), Cursor (`cursor`), at Muse (`muse`). Ang mga iyon ay nagpapanatili ng tig-iisang sign-in bawat isa. Ini-install nito ang CLI kung nawawala ito. Ang unang account para sa isang provider ay nagsa-sign in sa pamamagitan ng iyong normal na browser, roon mismo kung saan laging tumitingin ang CLI. Bawat isa pagkatapos niyon ay nagsa-sign in sa pamamagitan ng private window, kaya ang account na naka-sign in na sa iyong browser ay hindi aksidenteng makukuha; mag-sign in doon bilang account na idinaragdag mo, at isara muna ang anumang private window na nakabukas mo na. Huwag kailanman mag-log out sa CLI para gawin ito: binabawi ng pag-log out ang naka-save na sign-in, at kailangang idagdag muli ang account na iyon.

Para kopyahin ang iyong mga subscription login sa isa pang Omarchy machine sa pamamagitan ng SSH, patakbuhin ang `omarchy agent account copy user@laptop`. Ang nagpadala ay nagbibigay ng pansamantalang receiver kapag ang destinasyon ay walang naka-install, kaya ang mas lumang mga Omarchy machine ay makakatanggap ng mga account nang walang update. Nauuna ang mga naka-install na receiver. Kinokopya nito ang lahat ng subscription ng Claude, Codex, at Grok; magdagdag ng mga pangalan ng provider para piliin sila, gaya ng sa `omarchy agent account copy laptop claude`. Tumutugma ang mga pangalan ng account at command ID sa pinagmulan, kabilang ang mga account na naroon na sa destinasyon. Ang mga hindi kaugnay na account sa destinasyon ay makakatanggap ng numeric suffix kung magkasalungat ang kanilang mga pangalan, at ang mga setting, skill, plugin, at history ng pag-uusap ay nananatiling lokal sa bawat machine.

Pinapanatili ang mga umiiral na credential sa destinasyon. Ang source account na naka-sign in na roon ay sina-synchronize ang pangalan nang hindi pinapalitan ang mga credential nito; ang iba pang account ay idinaragdag sa tabi nito. Para palitan ang mga naka-save na credential para sa magkatugmang mga account, gamitin ang `omarchy agent account copy --replace laptop claude` pagkatapos isara ang mga session ng account na iyon sa destinasyon. Ang bagong destinasyon ay makakakuha rin ng aktibong account at mga kagustuhan sa paglipat ng pinagmulan; pinapanatili ng naitatag nang destinasyon ang sarili nito.

Bumibiyahe ang mga credential sa pamamagitan ng SSH at nakaimbak sa mga pribadong file sa destinasyon, kaya kumopya lamang sa mga machine na pinagkakatiwalaan mo. Ito ay isang beses na kopya, hindi patuloy na synchronization. Ang mga Codex refresh token ay maaaring i-rotate ng isa pang machine, na nag-iiwan sa kinopyang login na nangangailangan ng pag-renew; ang magkahiwalay na sign-in ang nananatiling pinaka-maaasahang pagpipilian para sa sabay-sabay na paggamit sa maraming machine. Tingnan ang [gabay sa pagpapatunay ng account ng Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Isang account bawat provider ang aktibo, at bawat bagong session ay nagsisimula bilang iyon: `cx`, `cy`, isang payak na `claude`, `codex`, o `grok`, anumang inilunsad sa pamamagitan ng `omarchy agent`, at mga script o editor na nakakahanap ng CLI sa `PATH`. Lumipat gamit ang `omarchy agent account use work` (at bumalik gamit ang `omarchy agent account use main`), o sa panel sa pamamagitan ng pagpindot sa numero ng isang account at pagkatapos ay `Enter` (o pag-click sa star nito). Lumilipat din ang mga tumatakbong Claude session, mula sa kanilang susunod na mensahe: bawat Claude session ay tumatakbo sa `~/.claude`, na laging naglalaman ng sign-in ng aktibong account. Ang Claude session na sinimulan sa sariling folder ng isang account ng mas lumang Omarchy ay naglalaman ng sign-in na iyon hanggang sa umalis ito, kaya pinapangalanan ng paglipat ang mga session na iyon at natatapos nang kusa kapag wala na sila. Ang mga tumatakbong Codex at Grok session ay nananatili sa account na sinimulan nila. Ang history ng pag-uusap, mga setting, skill, at plugin ay ibinabahagi sa mga account, kaya ang `claude --continue` sa parehong folder ay nagpapatuloy kung saan ka tumigil sa bagong account.

Kapag may higit sa isang account, ipinapakita ng panel ang mga limit ng bawat account nang magkatabi, na may napunang star sa ginagamit. Aabisuhan ka ng Omarchy kapag lumampas ang aktibong account sa 95% ng isang limit, at ang pag-click sa notification ay lilipat sa account na may pinakamaraming headroom. Hindi ito kailanman lumilipat nang kusa. Baguhin ang threshold gamit ang `omarchy agent account threshold 90`. Kung ang bawat account ay lagpas sa threshold, maririnig mo ang tungkol dito nang isang beses, kasama kung aling account ang unang magkakaroon ng puwang. Habang ang aktibong account ay nasa loob ng 15 puntos ng threshold nito (80% sa default), ang mga limit nito ay sinusuri bawat tatlong minuto sa halip na bawat 15.

Ipinapakita ng `omarchy agent account list` ang bawat account at ang pinakabagong mga limit nito, ang `omarchy agent account remove work` ay nakakalimot ng isa, at ang `omarchy agent account rename primary Hey` ay nagpapalit ng pangalan ng isa (o i-click ang pangalan ng isang account sa panel). Gumagana ang mga utos na ito sa mga account ng iyong default na agent; para maabot ang iba pang provider, pangalanan muna ito, gaya ng sa `omarchy agent account use codex side`. Ang login na mayroon ka na sa `~/.claude` o `~/.codex` ay ang _Main_ account. Ang sa Codex ay nananatili kung nasaan ito; ang sa Claude ay naghihintay sa sarili nitong folder habang aktibo ang isa pang account. Ang account na hindi nagamit nang higit sa mga walong oras ay maaaring magpakita ng _Sign-in required_; i-click ito para muling i-sign in ang account na iyon roon mismo sa panel, o lumipat dito at magsimula ng session, na nagre-refresh ng sign-in nang kusa. Ang mga MCP server na idinaragdag mo gamit ang `claude mcp add` ay umaabot sa bawat Claude account, dahil lahat sila ay tumatakbo sa `~/.claude`; para sa Codex at Grok, ang mga server na mayroon ka noong idinagdag ang isang account ay sumasama rito, ngunit ang mga susunod ay umaabot lamang sa account kung saan mo sila idinagdag. Ang Claude Desktop ay nagpapanatili ng sarili nitong sign-in, at ang mga Codex o Grok tool na naka-configure na may absolute path patungo sa isang CLI binary ay hindi sumusunod sa paglipat. Ang tahasang `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, o `GROK_HOME` ay nauuna kaysa sa napiling account.

### Pag-diagnose ng crash

Binabantayan ng Omarchy ang systemd-coredump para sa mga crash ng process. Kapag nakapili ka na ng default na agent, ang anumang programa mo na nagda-dump ng core ay nagdadala ng notification na "Process crashed" — i-click ito, at ang crash ay ibibigay sa iyong default na agent kasama ng omarchy-diagnose-crash skill ng Omarchy, na gagabay sa agent sa pagtatatag ng mga katotohanan mula sa core dump at pagpapasya kung karapat-dapat bang iulat ang crash upstream. Maaari mo rin itong patakbuhin nang manu-mano laban sa anumang PID mula sa `coredumpctl list` gamit ang `omarchy agent crash <pid>`.

Naka-on ang pagbabantay bilang default. I-off ito sa ilalim ng _Trigger > Toggle > Crash Capture Off_ (o gamit ang `omarchy toggle crash-capture`) at hihinto ang mga notification; gumagana pa rin nang manu-mano ang `omarchy agent crash <pid>`.

Maaari ring patahimikin ang mga crash nang paisa-isang programa, na siyang iaalok sa iyo ng diagnosis sa dulo. Ang `omarchy crash mute hyprland` ay humihinto sa mga notification para sa programang iyon lamang, ang `omarchy crash mute hyprland off` ay nagbabalik sa kanila, at ang `omarchy crash mute` nang mag-isa ay naglilista ng iyong na-mute. Tumatanggap ito ng path ng binary nang kasing saya ng pangalan nito, kaya ang `omarchy crash mute /usr/bin/hyprland` ay gumagawa ng parehong bagay. I-quote ang pangalang may espasyo rito, gaya ng sa `omarchy crash mute 'Some App'`. Lahat ng iba pa ay nag-aabiso pa rin, at ang na-mute na programa ay nagka-crash pa rin — itinatago nito ang paalala, hindi nito inaayos ang anuman.

### Mga desktop app

Ang _Install > AI > Desktop_ ay nagdadala ng mga graphical AI app: Amp Desktop, Antigravity Desktop, ang ChatGPT desktop app, ang Claude desktop app (ang Linux beta ng Anthropic, na may mga tab na Chat, Cowork, at Claude Code), Grok Bot para sa pakikipag-chat sa mga modelo ng xAI, Herdr Desktop, Hermes Desktop, OpenClaw, ang Perplexity desktop app, at T3 Code. Ang Grok Bot ay ang desktop chat app. Ang coding agent ay ang utos na `grok`.

Ang Hermes Desktop ang dapat mong malaman, dahil ang isang machine ay may isang Hermes, at iyon ay sa app: ang Hermes ay ini-install lamang kailanman sa pamamagitan ng app, at ang utos na `hermes` na pinapatakbo ng default na agent ay sa app. Ang pagpili sa Hermes bilang default na agent ay nag-i-install ng parehong bagay na ginagawa ng entry na _Install > AI > Desktop_: ang package, at isang Hermes runtime sa ilalim ng `~/.hermes` na sine-set up ng sariling installer ng Hermes, na tumatagal ng ilang minuto sa unang pagkakataon. Ang runtime na iyon ang nag-iisang Hermes na ginagamit ng terminal na utos na `hermes`, ng default na agent at ng app, at ina-update nito ang sarili gamit ang `hermes update` sa halip na maghintay sa isang Omarchy release. Ang pag-install nito ay nagbibigay din sa Hermes ng Omarchy theme bilang isang skin na pinangalanang `omarchy`, na sinusundan ng bawat Hermes surface habang nagpalit-palit ka ng mga theme; pumili ng iba sa ilalim ng mga Appearance setting ng Hermes o gamit ang `/skin` kung mas gusto mong hindi, at hahayaan ng Omarchy ang pagpipiliang iyon. Ang pag-alis ng app sa ilalim ng _Remove > AI > Desktop_ ay nagsasara muna ng Hermes, kasama ang gateway, kinukuha ang runtime na iyon kasama nito, at pinapanatili ang iyong mga chat, memory, at ang mga skill na isinulat ng Hermes para sa sarili nito maliban kung sasabihin mo kung hindi: magtatanong ito, na ang default ay hindi, kung dapat ding mawala ang data na iyon at ang iyong mga connection setting.

Ang desktop experience ng OpenClaw ay ang Control UI nito, na bumubukas bilang isang web app na sinusuportahan ng sarili nitong local gateway. Nakatira ang OpenClaw sa `~/.openclaw` at ina-update ang sarili nito: gamitin ang button na "Update Gateway" ng Control UI o patakbuhin ang `openclaw update`, at magre-restart ang gateway sa bagong bersyon. Pinipili lamang ng Omarchy ang release na sinisimulan ng bagong install. Maaari ring maging iyong default na agent ang OpenClaw: ang pagpili rito gamit ang `omarchy default agent openclaw` ay nagse-set up ng parehong kopya sa `~/.openclaw`, at binubuksan ng agent ang terminal UI ng OpenClaw na nakakabit sa gateway nito. Ang pag-alis ng OpenClaw sa ilalim ng _Remove > AI > Desktop_ ay kinukuha ang gateway service at ang app kasama nito at pagkatapos ay magtatanong kung dapat ding mawala ang `~/.openclaw`, dahil naglalaman iyon ng iyong mga chat at credential kasama ng OpenClaw mismo at ang mga plugin runtime na dina-download nito; pinapanatili ito ng default, at ang muling pag-install ng OpenClaw ay kukunin itong muli.

Ang Herdr Desktop ay ang desktop app na [Herdr](https://herdr.dev): mga space, tab, at pane ng mga terminal at coding agent na patuloy na tumatakbo sa core nito kapag isinara mo ang window. Nagmula ito sa sariling installer ng Herdr sa halip na isang package, kaya nakatira ito sa `~/.local/share/herdr-app`, dinadala ang core nito sa `~/.local/bin/herdr-core` kapag wala ka pang isa, at ina-update ang sarili nitong dalawa. Nakaupo ito sa tabi ng utos na `herdr` na ipinapadala ng Omarchy sa `Super + Ctrl + Return` sa halip na palitan ito, at nakukuha ang mga direct key ng utos na iyon: ang `Alt + Return` at `Alt + Shift + Return` ay naghahati ng pane pababa o pakanan, ang `Alt + Escape` ay nagsasara nito, ang `Ctrl + Alt + Arrow` ay lumilipat sa pagitan ng mga pane, ang `Alt + 1..9` at `Alt + Left/Right` ay pumipili ng tab, at ang `Alt + Up/Down` ay lumilipat sa pagitan ng mga space. Ang `Ctrl + 1..9` ay pumipili ng space at ang `Alt + Shift + Up/Down` ay humahakbang sa mga agent. Ang mga prefix key na `Ctrl + Space` ay nananatiling terminal lamang, dahil hindi mahawakan ng app ang payak na Ctrl key para sa isang sequence. Isinusulat ito ng Omarchy sa `~/.config/herdr-app/keys.json`, at ibinabalik ito ng `omarchy-refresh-herdr-app`. Ang pag-install nito ay pumipili ng Omarchy theme ng Herdr, na sinusundan ang iyong Omarchy theme mula noon. Nagpapanatili ang Herdr ng isang theme para sa light mode at isa para sa dark, kaya pagkatapos lumipat sa pagitan ng dark at light na Omarchy theme, piliin muli ang Omarchy sa theme picker ng Herdr nang isang beses pa para sa ibang mode.

Tumatakbo ang T3 Code mula sa opisyal nitong AppImage release sa `~/.local/share/t3code` sa halip na mula sa isang package, kaya ina-update nito ang sarili. Ang pag-install nito ay magtatanong kung magsisimula sa Stable o Nightly channel; lumipat sa ibang pagkakataon sa mga setting ng T3 Code. Nakatira ang iyong mga thread at setting sa `~/.t3`, at ang pag-alis ng T3 Code sa ilalim ng _Remove > AI > Desktop_ ay kinukuha sila kasama nito.

### Mga lokal na modelo

Magpatakbo ng isang open model sa sarili mong machine para sa iyong mga coding agent. Ang iyong mga prompt at code ay nananatili sa machine; walang ipinapadala sa modelo ang umaalis dito. Magsimula sa:

```bash
omarchy models use best text
```

Iyon ay nagse-set up ng pinakamahusay na text model para sa machine na ito, ang uri na ginagamit ng iyong mga agent. Ang mga image, video at music model ay may sarili nilang pinakamahusay: `omarchy models use best image`, `video` o `music`. Patakbuhin ang `omarchy models use best` para makita ang pinili ng bawat uri para sa machine na ito.

O pumili ng + sa panel ng mga agent: sa ilalim ng _Use a local model_ inililista nito ang bawat coding model na kasya sa machine na ito, ang inirerekomenda muna. Ang Podman, na nagpapatakbo ng mga modelo, ay kasama ng Omarchy, gayundin ang container toolkit ng NVIDIA sa isang NVIDIA machine, na nagbibigay sa kanila ng GPU; kung nawawala ang alinman, ii-install ito ng unang setup. Pagkatapos ay pipiliin ng Omarchy ang inirerekomendang modelo para sa machine na ito, ida-download ito, at sisimulan ito. Asahan ang download na sampu-sampung GB at ang karamihan ng memory ng machine ay ginagamit habang tumatakbo ang modelo: ang Flash Next ay gumagamit ng mga 100 GiB kasama ng buong 256K context nito. Kung hawak ng ibang mga modelo ang memory na kailangan nito, sine-set up itong nakahinto, handang magsimula kapag huminto ka ng isa. Humihinto ang modelo sa pag-logout; ihinto mo ito mismo kapag kailangan mo ang memory para sa iba pang bagay.

Ipinapakita ng `omarchy models list` ang mga opsiyon at ipinaliliwanag kung bakit hindi kasya ang ilan. Para mag-set up ng isa pa, patakbuhin ang `omarchy models use <recipe>`. Ngayon, ang `qwen3.8-flash-next-gufo` at `qwen3.8-27b-gufo` ay magagamit para sa mga 128 GB Strix Halo machine; ang 27B ay kumukuha ng mga 40 GiB, kaya nag-iiwan ito ng puwang para sa ibang trabaho. Sa isang 64 GB laptop na may Arc B390 ng Intel, ang `qwen3.6-35b-a3b-llamacpp` ay tumatakbo sa mga 30 GiB. Ang mga bagong recipe at rekomendasyon ay dumarating kasama ng `omarchy update`, sa pamamagitan ng package.

Ang coding model na idinaragdag mo ay nakakakuha ng sarili nitong linya sa panel ng mga agent, sa tabi ng iyong mga subscription: play para simulan ito, pause para ihinto ito at palayain ang memory nito, ang marka ng Tailscale para ibahagi ito sa iba pang machine sa iyong tailnet habang tumatakbo ito, at ang terminal button para buksan ang iyong agent dito. Ipinapakita ng linya nito ang download, load o stop habang nangyayari, at sinasabi ito kapag walang sapat na libreng memory para simulan ito, o nagli-link sa mga log nito kapag huminto ito nang may error. Marami ang maaaring tumakbo nang sabay kapag kasya sila sa memory nang magkasama. Pindutin ang Delete sa napiling linya para alisin ang modelo mula sa machine na ito, download at lahat; maaari itong i-set up muli ng +. Ang coding model na sine-set up mula sa terminal ay naghihintay sa ilalim ng + hanggang sa idagdag mo ito, at gayundin ang mga modelo na pinapatakbo ng machine na na-pair mo (`omarchy models pair <host>`).

Bawat coding model na sine-set up mo ay nakakakuha rin ng sarili nitong entry sa app launcher, sa ilalim ng pangalan ng modelo at kasama ng logo ng gumawa nito, sa paraan na ang pag-sign in sa Claude, Codex o Grok ay nagdaragdag ng isa. Binubuksan nito ang iyong agent sa modelong iyon, at sinisimulan muna ang modelo kung hindi ito tumatakbo: ipinapakita ng terminal na naglo-load ito at ibibigay ito sa agent kapag handa na ito. Ang pag-alis ng modelo ay nag-aalis ng entry nito.

Hindi bawat modelo ay para sa coding. Ang mga image, video at music model ay sa halip bumubukas sa Fantasi, ang app ng Omarchy para sa paggawa ng mga larawan, video at music gamit ang modelong tumatakbo sa machine na ito, at pinamamahalaan doon o gamit ang `omarchy models`.

Pinapanatili ng modelo ang pagtakbo nang eksakto kung paano ito sine-set up, kaya ang isang Omarchy update ay hindi kailanman nagre-restart ng isa sa ilalim ng iyong mga agent. Kapag may mas bagong runtime o mas bagong mga weight ang Omarchy para sa modelong sine-set up mo, ipinapakita ng linya nito ang isang update button: pindutin ito at muling sine-set up ang modelo sa background, dina-download lamang ang nagbago, at magre-restart sa bagong bersyon. Ang modelong nakahinto ay nananatiling nakahinto. Ginagawa ng `omarchy models update` ang pareho para sa bawat modelo mula sa terminal.

Mula sa command line, ginagawa ng `omarchy models start <recipe>` at `omarchy models stop <recipe>` ang pareho, ipinapakita ng `omarchy models status` ang bawat modelo, at binubuksan ng `omarchy agent --local-model <recipe>` ang modelong iyon sa pi, anuman ang iyong default na agent. Para gawing iyong lokal na modelo ang binubuksan ng agent hotkey, ng Quake console, at ng _Make something_, patakbuhin ang `omarchy default agent local` o i-star ang tumatakbong modelo sa panel ng mga agent. Inililista rin ng pi ang bawat modelong sine-set up mo, at ang mga nasa machine na na-pair mo, sa sarili nitong model picker, kaya ang payak na `pi` ay umaabot din sa kanila. Maaari ring kumonekta ang anumang OpenAI-compatible client: ipinapakita ng `status` ang address ng bawat modelo (ang una ay `http://127.0.0.1:11435/v1`), ang pangalan ng recipe ay ang modelo, at ang key ay nasa `~/.config/omarchy/agent-local/key`.

Ang `omarchy models remove <recipe>` ay nagtatanggal ng modelo at ng mga download na hindi ginagamit ng ibang modelo.

Ang mga third-party runtime ay may label ng kanilang publisher. Pinapatakbo ng Omarchy ang bawat modelo nang walang network access.

### Mga lokal na LLM

Inirerekomenda ng Omarchy ang dalawang paraan ng pagpapatakbo ng mga lokal na LLM model: LM Studio at Ollama. Nagbibigay ang LM Studio ng GUI interface para sa paghahanap ng mga open-weight model, pag-install ng mga iyon, at pagpapatakbo ng mga iyon. Mahusay itong paraan para madaling makapagsimula. Nag-aalok ang Ollama ng CLI para gawin iyon nang katulad. Ngunit kung bago ka sa mga lokal na modelo, magsisimula ako sa LM Studio. I-install ang LM Studio mula sa _Install > AI > Desktop_ at ang Ollama mula sa _Install > AI > CLI_ sa Omarchy Menu.

### Ang mga skill ng Omarchy

Tinutulungan ng mga agent skill ang AI na gumamit ng mga tiyak na tool sa isang tiyak na paraan, at nagpapadala ang Omarchy ng pito sa kanila. Sinasaklaw ng omarchy skill ang pag-aangkop ng system, gaya ng pag-tweak ng iyong Hyprland config o pag-aadjust ng bar. Sinasaklaw ng omarchy-make-theme, omarchy-make-plugin, omarchy-make-app, at omarchy-make-game ang paggawa ng bagong bagay, sinasaklaw ng omarchy-contribute ang pag-uulat ng bug o pagpapadala ng fix upstream, at sinasaklaw ng omarchy-diagnose-crash ang core dump ng isang crash. Naka-symlink sila sa mga skill directory para sa Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` at bawat `~/.hermes/profiles/*/skills`), at ang generic na lokasyong `~/.agents/skills`, kaya karamihan ng mga harness ay awtomatikong kumukuha sa kanila. Nauuna ang skill folder na sarili mo na may parehong pangalan.

Ngunit dapat mong ituring ang mga skill na ito bilang eksperimental. Iba't ibang modelo ay gagamit nito nang may iba't ibang epekto. Pinakamainam na tumakbo muna sa plan mode, para magkaroon ka ng ideya kung ano ang gustong baguhin ng agent. At pagkatapos ay maging handa na i-rollback ang mga pagbabago o kahit na ipatawag ang `omarchy reinstall configs`, kung guguluhin ng agent ang lahat.
