# AI

Kasama sa Omarchy ang mga launcher para sa mga coding agent sa ibaba nang hindi pumipili ng default para sa iyo. Magpatakbo ng command para i-install ang CLI nito sa unang paggamit, pagkatapos ay mag-authenticate kapag sinabihan. Ang Hermes ang eksepsiyon: walang ini-install para dito sa unang paggamit, at ang pagpili dito ay nag-i-install ng Hermes Desktop, gaya ng ipinaliliwanag ng _Mga desktop app_ sa ibaba.

### Pag-install at pag-update ng mga agent

Maliban sa Hermes, ginagamit ng mga agent na ito ang lazy installation ng mise: ang unang paglulunsad ay nag-i-install ng CLI, at muling ginagamit ito ng mga susunod na paglulunsad. Sinusuri rin ng mise ang isang naka-install na agent para sa bagong release nang hindi hihigit sa isang beses kada apat na oras, bago ito magsimula o sa background sa isang shell prompt. Kung mabigo ang update na iyon o offline ka, tatakbo ang naka-install na bersyon. Ina-update ng `omarchy update` ang mga naka-install na agent kasama ng iba pang bahagi ng Omarchy, at ina-update ng `mup` ang mga tool na pinamamahalaan ng mise lamang.

Ang sariling updater ng isang agent, tulad ng `claude update`, `codex update`, o isang update button sa isang app, ay hindi nag-a-update ng install na pinamamahalaan ng mise. Nabibigo ang `codex update`, at maaaring mag-ulat ng tagumpay ang `claude update` habang nag-i-install ng hiwalay na kopya na hindi sinusubaybayan ng mise. Kung mas gusto mong gamitin ang native installer at updater ng isang agent, idagdag ito sa `disable_tools`; tingnan ang [Mga paunang naka-install na CLI tool](18-development-tools.md#preinstalled-cli-tools).

Para i-install ang lahat ng naka-configure na lazy tool bago mo kailanganin ang mga ito, patakbuhin ang `mise install --include-lazy`. Kasama rito ang iba pang default na CLI tool ng Omarchy pati na rin ang mga agent. Tingnan ang [Mga paunang naka-install na CLI tool](18-development-tools.md#preinstalled-cli-tools) para sa pag-install ng isang tool o paggamit ng sarili mong installation.

Ini-install ang `grok` sa pamamagitan ng first-party na `grok` package ng mise, sa parehong paraan tulad ng `claude` at `codex`. Patakbuhin ang `grok`, o piliin ito sa ilalim ng _Setup > Defaults > Agent_. Laktawan ang `curl | bash` installer sa x.ai. Naglalagay ang landas na iyon ng pangalawang kopya sa `~/.grok/bin`, inuuna ito sa `PATH`, at pinapalitan ang wrapper ng Omarchy.

Binubuksan ng `dsh` ang browser UI nito sa `127.0.0.1:3080`, na ang launch directory ang default workspace nito. Walang kinukuhang panimulang prompt ang browser UI nito, kaya binubuksan ito ng `omarchy agent prompt` na nasa clipboard mo ang prompt para i-paste. Sinisimulan ito ng Omarchy gamit ang no-approval permission preset ng DeepSeek. Nag-a-upload ang DeepSeek Harness ng mga session log sa DeepSeek kapag ginagamit mo ang opisyal nitong model API; i-off iyon sa ilalim ng _Settings > General > Upload Session Log_ sa browser UI nito. Ang feedback na ipinapadala mo dito ay ina-upload din kasama ng session, maliban kung sisimulan mo ito gamit ang `DSH_TELEMETRY_MODE=DISABLED`.

### Ang default na agent

Piliin ang iyong default na agent gamit ang `omarchy default agent <name>` o sa ilalim ng _Setup > Defaults > Agent_ sa Omarchy Menu (`Super + Space`). Kung hindi pa naka-install ang agent, i-install muna ito ng pagpili dito. Aanyayahan ka ng bagong Omarchy na gawin ang pagpipiliang ito gamit ang isang beses lang na notification.

Ang pagpili ng Claude ay sumusubok ding i-set up ang browser extension nito para sa Chromium, Chrome, Brave, Brave Origin, at Edge. Nalalapat ang setup ng extension sa lahat ng user at maaaring humingi ng password ng iyong system; ang pagkansela o nabigong pag-install ng extension ay pipili at maglulunsad pa rin ng Claude. I-restart ang iyong browser, i-enable ang extension kung sinabihan, at mag-sign in sa Claude para tapusin ang pagkonekta dito. Patakbuhin ang `/chrome` sa Claude para suriin ang koneksyon. Hindi sinusuportahan ng Firefox at Zen ang extension na ito. Kung Claude na ang iyong default bago idinagdag ang setup na ito, piliin itong muli para i-install ang extension.

Kapag nakapili ka na, ilulunsad ng `Super + Shift + Ctrl + A` ang default na agent sa isang nakalaang terminal window (o ilalabas ang picker kung hindi ka pa nakakapili). Maaari mo rin itong ilunsad nang diretso sa isang gawain gamit ang `omarchy agent prompt "Review this project"`. Walang kinukuhang panimulang prompt ang Freebuff at DeepSeek Harness, kaya sa halip ay bubukas ang mga ito na nasa clipboard mo ang prompt para i-paste. Ang mga agent na inilunsad sa ganitong paraan ay tumatakbo nang walang nagbabantay sa kani-kanilang mga mode na hindi humihinto para magtanong, kaya maging handa na talagang may gawin ang mga ito! Walang ganoong mode ang MiniMax Code para sa mga interactive session nito, kaya humihingi ito ng mga pahintulot gaya ng dati. At dahil tumatanggi ang mga agent na tandaan ang trust para sa iyong home directory, sa halip ay nagsisimula sa `~/Work` ang mga paglulunsad mula sa `$HOME`.

May mga terminal shortcut din: pinapatakbo ng `a` ang default na agent nang inline sa kasalukuyang terminal, habang direktang sinisimulan ng `c`, `cx`, at `cy` ang OpenCode, Claude Code, at Codex (muli sa kanilang mga mode na awtomatikong nag-aapruba). Nagsi-sync din ang mga pagbabago ng theme sa mga agent: ang Claude Code, Pi, OpenCode, at Hermes (kapag na-install na ito ng Omarchy) ay sumusunod lahat kapag lumipat ka ng Omarchy theme.

### Ang panel ng mga agent

May icon ng mga agent ang top bar. Bago ka makapag-set up ng agent, gagabayan ka ng panel nito sa pag-sign in sa Claude, Codex, o Grok, at ang una ay magiging iyong default na agent. Pagkatapos niyon, inilalagay ng panel ang bawat subscription sa isang page: bawat agent at account kasama ang plan nito, isang meter para sa bawat 5-hour session at weekly limit nito kasama ang oras hanggang mag-reset ito (mag-hover para sa eksaktong porsyento), o ang natitirang prepaid balance, sa ilalim ng isang linya na umiikot sa kung ano ang nagamit mo sa lahat ng mga ito, tulad ng mga token ngayong linggo at ang pinakaginagamit mong modelo. Sa ilalim ng _Make something_ nag-aalok ito ng mga starter prompt para sa bagong theme, plugin, o app na nagbibigay ng gawain sa iyong default na agent. Ginagawa ang mga app sa paraang ginawa ang sariling Hype, Monologue, at Omacut ng Omarchy, sa C++ at Qt Quick, na sumusunod sa omarchy-app agent skill, at naka-install na ang compiler at mga piraso ng Qt na kailangan ng mga ito. Saklaw agad ang Claude Code, Codex, Grok, Kimi, Cursor at ang Grok Bot allowance nito, GitHub Copilot, Muse, Antigravity, Kimchi, at Devin kasama ang kanilang mga limit, at ipinapakita ng Hermes, Mistral Vibe, at Qwen Code ang kanilang mga session at token kapag nagamit mo na ang mga ito. Lumalabas din ang mga provider plan at key na ginagamit mo sa pamamagitan ng pi, omp, o opencode: ang OpenCode Zen at Go, ang Z.ai GLM Coding Plan, Ollama Cloud, ang MiniMax Token Plan, at Synthetic kasama ang kanilang mga limit; ang Fireworks, OpenRouter, at DeepSeek kasama ang kanilang mga prepaid balance; at ang mga modelong pinapatakbo mo sa sarili mong hardware sa ilalim ng Local models. Bawat agent ay binibilang nang isang beses, sa ilalim ng kung sino ang naniningil para dito, gaano man karaming harness mo ito patakbuhin.

I-left-click ang icon sa bar para sa panel, i-right-click para ilunsad ang iyong default na agent. Ang mga usage record sa likod nito ay muling ginagawa kada 15 minuto ng `omarchy agent usage-update`, at maaari pang pagsamahin ng panel ang usage mula sa iba mo pang machine sa pamamagitan ng isang naka-sync na folder. Tingnan ang README sa ilalim ng `$OMARCHY_PATH/shell/plugins/agents/` para sa buong mga setting.

### Maramihang subscription

Kung nagbabayad ka para sa higit sa isang Claude, Codex, o Grok plan — isang personal na Max at isang pangtrabaho, halimbawa — maaaring panatilihin ng Omarchy na naka-sign in ang lahat ng mga ito at lumipat sa pagitan ng mga ito. Magdagdag ng subscription gamit ang + sa panel ng mga agent, na gagabay sa iyo mismo doon, o gamit ang `omarchy agent account add claude Work` (o `codex`, o `grok`). Ini-install nito ang CLI kung nawawala ito. Ang unang account para sa isang provider ay nag-sa-sign in sa pamamagitan ng iyong normal na browser, mismo kung saan laging tumitingin ang CLI. Ang bawat kasunod ay nag-sa-sign in sa pamamagitan ng isang private window, para hindi aksidenteng makuha ang account na naka-sign in na sa iyong browser; mag-sign in doon bilang ang account na idinaragdag mo, at isara muna ang anumang private window na nakabukas na. Huwag kailanman mag-log out sa CLI para gawin ito: binabawi ng pag-log out ang naka-save na sign-in, at kailangang idagdag muli ang account na iyon.

Para kopyahin ang iyong mga subscription login sa isa pang Omarchy machine sa pamamagitan ng SSH, patakbuhin ang `omarchy agent account copy user@laptop`. Nagbibigay ang sender ng pansamantalang receiver kapag walang naka-install ang destination, kaya makakatanggap ng mga account ang mas lumang mga Omarchy machine nang walang update. Nauuna ang mga naka-install na receiver. Kinokopya nito ang lahat ng subscription ng Claude, Codex, at Grok; magdagdag ng mga pangalan ng provider para piliin ang mga ito, gaya ng sa `omarchy agent account copy laptop claude`. Tumutugma ang mga pangalan ng account at command ID sa source, kasama ang mga account na mayroon na sa destination. Tumatanggap ng numeric suffix ang mga hindi kaugnay na destination account kung magkasalungat ang kanilang mga pangalan, at nananatiling lokal sa bawat machine ang mga setting, skill, plugin, at kasaysayan ng pag-uusap.

Pinapanatili ang mga umiiral na credential ng destination. Ang isang source account na naka-sign in na doon ay sini-sync ang pangalan nito nang hindi pinapalitan ang mga credential nito; idinaragdag ang iba pang account sa tabi nito. Para palitan ang mga naka-save na credential para sa magkatugmang mga account, gamitin ang `omarchy agent account copy --replace laptop claude` pagkatapos isara ang mga session ng account na iyon sa destination. Nakukuha rin ng bagong destination ang active account at mga kagustuhan sa paglipat ng source; pinapanatili ng isang naitatag nang destination ang sarili nito.

Naglalakbay ang mga credential sa pamamagitan ng SSH at nakaimbak sa mga private file sa destination, kaya kumopya lang sa mga machine na pinagkakatiwalaan mo. Ito ay isang beses lang na pagkopya, hindi patuloy na synchronization. Maaaring i-rotate ng isa pang machine ang mga Codex refresh token, na mag-iiwan sa isang nakopyang login na nangangailangan ng pag-renew; ang magkakahiwalay na sign-in ang nananatiling pinakamaaasahang pagpipilian para sa sabay-sabay na paggamit sa maraming machine. Tingnan ang [gabay sa account authentication ng Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Isang account bawat provider ang active, at bawat bagong session ay nagsisimula bilang ito: `cx`, `cy`, isang simpleng `claude`, `codex`, o `grok`, anumang inilunsad sa pamamagitan ng `omarchy agent`, at mga script o editor na nakakahanap ng CLI sa `PATH`. Lumipat gamit ang `omarchy agent account use work` (at bumalik gamit ang `omarchy agent account use main`), o sa panel sa pamamagitan ng pagpindot sa numero ng isang account at pagkatapos ay `Enter` (o pag-click sa Use button nito). Ang mga session na tumatakbo na ay nananatili sa account kung saan sila nagsimula. Ibinabahagi sa lahat ng account ang kasaysayan ng pag-uusap, mga setting, skill, at plugin, kaya ang `claude --continue` sa parehong folder ay nagpapatuloy kung saan ka tumigil sa bagong account.

Kapag may higit sa isang account, ipinapakita ng panel ang mga limit ng bawat account nang magkatabi, na minarkahan ang active. Bilang default, inaabisuhan ka ng Omarchy kapag lumampas ang active account sa 95% ng isang limit, at ang pag-click sa notification ay lumilipat sa account na may pinakamaraming headroom. Mag-hover sa linya ng isang account sa panel at i-click ang Autoswitch na lalabas sa tabi ng Use (o pindutin ang `m`), o patakbuhin ang `omarchy agent account mode auto`, para hayaan itong lumipat nang mag-isa sa halip; habang naka-on ito, pumapalit ang Autoswitch sa Use, at ang pag-click dito muli ay bumabalik sa pag-abiso. Magdagdag ng numero para baguhin ang threshold, gaya ng sa `omarchy agent account mode auto 90`. Kung ang bawat account ay lampas sa threshold, maririnig mo ito nang isang beses, kasama kung aling account ang unang magkakaroon ng puwang. Habang ang isang active account ay nasa loob ng 15 puntos ng threshold nito (80% sa default), sinusuri ang mga limit nito kada tatlong minuto sa halip na kada 15.

Ipinapakita ng `omarchy agent account list` ang bawat account at ang pinakabagong mga limit nito, kinakalimutan ng `omarchy agent account remove work` ang isa, at pinapalitan ng pangalan ng `omarchy agent account rename primary Hey` ang isa (o i-click ang pangalan ng isang account sa panel). Gumagana ang mga command na ito sa mga account ng iyong default na agent; para maabot ang ibang provider, pangalanan muna ito, gaya ng sa `omarchy agent account use codex side`. Ang login na mayroon ka na sa `~/.claude` o `~/.codex` ay ang _Main_ account at nananatili kung nasaan ito. Ang isang account na hindi nagamit nang higit sa humigit-kumulang walong oras ay maaaring magpakita ng _Sign-in required_; i-click ito para muling i-sign in ang account na iyon mismo sa panel, o magsimula ng session dito, na nagre-refresh ng sign-in nang mag-isa. Ang mga MCP server na mayroon ka noong idinagdag ang isang account ay sumasama dito, pero ang mga idinaragdag mo mamaya gamit ang `claude mcp add` ay umaabot lang sa account kung saan mo idinagdag ang mga ito. Hindi sumusunod sa paglipat ang Claude Desktop at mga tool na naka-configure gamit ang absolute path patungo sa isang CLI binary. Nauuna ang isang tahasang `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, o `GROK_HOME` kaysa sa napiling account.

### Pag-diagnose ng crash

Binabantayan ng Omarchy ang systemd-coredump para sa mga pag-crash ng process. Kapag may nag-segfault, makakakuha ka ng notification na "Process crashed" — i-click ito, at ibibigay ang crash sa iyong default na agent kasama ang diagnose-crash skill ng Omarchy, na gagabay sa agent sa pagtatatag ng mga katotohanan mula sa core dump at pagpapasya kung karapat-dapat bang iulat ang crash sa upstream. Maaari mo rin itong patakbuhin nang mano-mano laban sa anumang PID mula sa `coredumpctl list` gamit ang `omarchy agent crash <pid>`.

Naka-on ang pagbabantay bilang default. I-off ito sa ilalim ng _Trigger > Toggle > Crash Capture_ (o gamit ang `omarchy toggle crash-capture`) at hihinto ang mga notification; gumagana pa rin nang mano-mano ang `omarchy agent crash <pid>`.

Maaari ring patahimikin ang mga crash nang paisa-isang programa, na siyang iaalok sa iyo ng diagnosis sa dulo. Pinipigilan ng `omarchy crash mute hyprland` ang mga notification para sa programang iyon lamang, ibinabalik sila ng `omarchy crash mute hyprland off`, at inililista ng `omarchy crash mute` nang mag-isa kung ano ang na-mute mo. Tinatanggap nito ang path ng binary nang kasingdali ng pangalan nito, kaya pareho ang ginagawa ng `omarchy crash mute /usr/bin/hyprland`. Mag-quote ng pangalan na may espasyo, gaya ng sa `omarchy crash mute 'Some App'`. Nag-aabiso pa rin ang lahat ng iba pa, at nagka-crash pa rin ang na-mute na programa — itinatago nito ang paalala, hindi nito inaayos ang anuman.

### Mga desktop app

May dala rin ang _Install > AI_ menu ng ilang graphical AI app: ang ChatGPT desktop app, ang Claude desktop app (ang Linux beta ng Anthropic, na may mga tab na Chat, Cowork, at Claude Code), Grok Bot para sa pakikipag-chat sa mga modelo ng xAI, Hermes Desktop, OpenClaw, ang Perplexity desktop app, at T3 Code. Ang Grok Bot ay ang desktop chat app. Ang coding agent ay ang `grok` command.

Ang Hermes Desktop ang dapat mong malaman, dahil ang isang machine ay may isang Hermes, at pag-aari ito ng app: ini-install lang ang Hermes sa pamamagitan ng app kailanman, at ang `hermes` command na pinapatakbo ng default na agent ay pag-aari ng app. Ang pagpili ng Hermes bilang default na agent ay nag-i-install ng parehong bagay na ginagawa ng _Install > AI_ entry: ang package, at isang Hermes runtime sa ilalim ng `~/.hermes` na sine-set up ng sariling installer ng Hermes, na tumatagal ng ilang minuto sa unang pagkakataon. Ang runtime na iyon ang nag-iisang Hermes na ginagamit ng terminal `hermes` command, ng default na agent at ng app, at ina-update nito ang sarili gamit ang `hermes update` sa halip na maghintay ng Omarchy release. Ang pag-install dito ay nagbibigay din sa Hermes ng Omarchy theme bilang isang skin na pinangalanang `omarchy`, na sinusundan ng bawat Hermes surface habang nagpapalit ka ng mga theme; pumili ng iba sa ilalim ng Appearance settings ng Hermes o gamit ang `/skin` kung mas gusto mong hindi, at hindi pakikialaman ng Omarchy ang pagpipiliang iyon. Ang pag-aalis ng app sa ilalim ng _Remove > AI_ ay nagsasara muna ng Hermes, kasama ang gateway, isinasama ang runtime na iyon, at pinapanatili ang iyong mga chat, memory, at ang mga skill na isinulat ng Hermes para sa sarili nito maliban kung sasabihin mo ang kabaligtaran: nagtatanong ito, na ang default ay hindi, kung dapat ding alisin ang data na iyon at ang iyong mga connection setting.

Ang desktop experience ng OpenClaw ay ang Control UI nito, na bubukas bilang isang web app na sinusuportahan ng sarili nitong local gateway. Nakatira ang OpenClaw sa `~/.openclaw` at ina-update ang sarili: gamitin ang "Update Gateway" button ng Control UI o patakbuhin ang `openclaw update`, at magre-restart ang gateway sa bagong bersyon. Pinipili lang ng Omarchy ang release kung saan magsisimula ang bagong install. Ang pag-aalis ng OpenClaw sa ilalim ng _Remove > AI_ ay isinasama ang gateway service at ang app at pagkatapos ay nagtatanong kung dapat ding alisin ang `~/.openclaw`, dahil naroon ang iyong mga chat at credential kasama ng OpenClaw mismo at ang mga plugin runtime na dina-download nito; pinapanatili ito ng default, at ang muling pag-install ng OpenClaw ay kukunin itong muli.

Tumatakbo ang T3 Code mula sa opisyal nitong AppImage release sa `~/.local/share/t3code` sa halip na mula sa isang package, kaya ina-update nito ang sarili. Nagtatanong ang pag-install dito kung magsisimula sa Stable o Nightly channel; lumipat mamaya sa mga setting ng T3 Code. Nakatira ang iyong mga thread at setting sa `~/.t3`, at ang pag-aalis ng T3 Code sa ilalim ng _Remove > AI_ ay isinasama ang mga ito.

### Mga lokal na LLM

Inirerekomenda ng Omarchy ang dalawang paraan ng pagpapatakbo ng mga lokal na LLM model: LM Studio at Ollama. Nagbibigay ang LM Studio ng GUI interface para sa paghahanap ng mga open-weight model, pag-install ng mga ito, at pagpapatakbo ng mga ito. Mahusay itong paraan para madaling makapagsimula. Nag-aalok ang Ollama ng CLI para gawin ang katulad. Pero kung bago ka sa mga lokal na modelo, magsisimula ako sa LM Studio. Maaari mong i-install ang alinman sa ilalim ng _Install > AI_ sa Omarchy Menu.

### Ang Omarchy Skill

Tinutulungan ng mga agent skill ang AI na gumamit ng mga partikular na tool sa isang partikular na paraan, at may kasamang default skill ang Omarchy para sa pag-aangkop ng system. Tulad ng pag-aayos ng iyong Hyprland config, pag-adjust ng bar, o kahit paglikha ng bagong theme mula sa simula. Naka-symlink ito sa mga skill directory para sa Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` at bawat `~/.hermes/profiles/*/skills`), at ang generic na lokasyon ng `~/.agents/skills`, kaya awtomatiko itong nakukuha ng karamihan sa mga harness.

Pero dapat mong ituring ang skill na ito bilang eksperimental. Gagamitin ito ng iba't ibang modelo nang may iba't ibang epekto. Pinakamainam na tumakbo muna sa plan mode, para magkaroon ka ng ideya kung ano ang gustong baguhin ng agent. At pagkatapos ay maging handang i-rollback ang mga pagbabago o kahit tawagin ang `omarchy reinstall configs`, kung guluhin ng agent ang lahat.
