# AI

Itinuturing ng Omarchy ang mga AI coding agent bilang first-class citizen, pero hindi ito mamimili ng paborito para sa iyo. Sa halip, bawat pangunahing coding-agent CLI ay naka-pre-wired na bilang lazy-loaded na launcher. Ang mga launcher ay maliliit na stub na pinamamahalaan ng [mise](https://mise.jdx.dev/) sa `~/.local/bin/`, kaya wala pang dina-download hanggang sa unang beses mo talagang patakbuhin ang isa. Ang Hermes ang eksepsyon: walang stub para dito, at kapag pinili mo ito, mai-install ang Hermes Desktop, gaya ng ipinapaliwanag sa _Mga desktop app_ sa ibaba. Patakbuhin ang alinman sa mga ito at mag-authenticate kapag sinabihan:

| Command    | Agent                                                            |
|------------|------------------------------------------------------------------|
| `claude`   | [Claude Code](https://code.claude.com/docs/en/overview)          |
| `codex`    | [OpenAI Codex](https://github.com/openai/codex)                  |
| `opencode` | [OpenCode](https://opencode.ai/)                                 |
| `agy`      | [Google Antigravity CLI](https://github.com/google-antigravity/antigravity-cli) |
| `copilot`  | [GitHub Copilot CLI](https://github.com/github/copilot-cli)      |
| `crush`    | [Crush](https://github.com/charmbracelet/crush)                  |
| `grok`     | [Grok Build](https://x.ai/build) mula sa xAI                        |
| `kimi`     | [Kimi Code](https://www.kimi.com/code/docs/en/)                  |
| `pi`       | [Pi ni Mario Zechner](https://github.com/badlogic/pi-mono)        |
| `omp`      | [Oh My Pi](https://github.com/can1357/oh-my-pi)                  |
| `ori`      | [Ori](https://openrouter.ai/docs/guides/ori/harness), ang harness ng OpenRouter |
| `hermes`   | [Hermes](https://hermes-agent.nousresearch.com/), ang agent ng Nous Research  |
| `muse`     | [Muse Code](https://dev.meta.ai), ang coding agent ng Meta           |
| `cursor-agent` | [Cursor CLI](https://cursor.com/cli)                         |

Ang `ori` ang kakaiba: pinapatakbo nito ang iba pang harness laban sa buong katalogo ng modelo ng OpenRouter, kaya sinisimulan ng `ori claude`, `ori codex`, o `ori opencode` ang mga agent na iyon sa kung anong modelong ituro mo sa kanila, at ang `ori code` ay ang sariling agent ng Ori.

Para i-wrap ang isang karagdagang CLI sa parehong paraan, patakbuhin ang `omarchy-mise-install <package> [command-name]`. Pinapanatiling napapanahon ang mga stub kasama ng lahat ng iba pang pinamamahalaan ng mise kapag pinatakbo mo ang `omarchy update` (o ang alias na `mup`).

Ini-install ang `grok` sa pamamagitan ng first-party na `grok` package ng mise, sa parehong paraan gaya ng `claude` at `codex`. Patakbuhin ang `grok`, o piliin ito sa ilalim ng _Setup > Defaults > Agent_. Laktawan ang installer na `curl | bash` sa x.ai. Naglalagay ang daang iyon ng pangalawang kopya sa `~/.grok/bin`, inilalagay ito sa unahan ng `PATH`, at ino-overwrite ang wrapper ng Omarchy.

### Ang default na agent

Piliin ang iyong default na agent gamit ang `omarchy default agent <name>` o sa ilalim ng _Setup > Defaults > Agent_ sa Omarchy Menu (`Super + Space`). Kung hindi pa naka-install ang agent, ang pagpili dito ay i-install muna ito. Aanyayahan ka ng bagong Omarchy na gawin ang pagpiling ito gamit ang isang one-time na notification.

Sinusubukan din ng pagpili sa Claude na i-set up ang browser extension nito para sa Chromium, Chrome, Brave, Brave Origin, at Edge. Nalalapat ang setup ng extension sa lahat ng user at maaaring humingi ng iyong system password; pipiliin at ilulunsad pa rin ang Claude kahit magkansela ka o mabigo ang pag-install ng extension. I-restart ang iyong browser, i-enable ang extension kung sinabihan, at mag-sign in sa Claude para tapusin ang pagkonekta dito. Patakbuhin ang `/chrome` sa Claude para suriin ang koneksyon. Hindi sinusuportahan ng Firefox at Zen ang extension na ito. Kung si Claude na ang iyong default bago pa idinagdag ang setup na ito, piliin itong muli para i-install ang extension.

Ang [Muse Code](https://dev.meta.ai) — ang `muse` ng Meta — ay gumagamit ng preinstalled na mise stub gaya ng iba pang agent. Ang pagpili dito bilang default ay nag-i-install ng opisyal na launcher ng Meta sa pamamagitan ng HTTP backend ng mise. Bine-verify at ina-update ng launcher ang native binary para sa iyong makina.

Kapag nakapili ka na, inilulunsad ng `Super + Shift + Ctrl + A` ang default na agent sa isang nakalaang terminal window (o inilalabas ang picker kung hindi ka pa nakapipili). Maaari mo rin itong ilunsad nang diretso sa isang gawain gamit ang `omarchy agent prompt "Review this project"`. Ang mga agent na inilunsad sa ganitong paraan ay tumatakbo nang walang nagbabantay sa kani-kanilang mode na hindi humihinto para magtanong, kaya maging handa kang talagang may gagawin sila! At dahil tumatanggi ang mga agent na tandaan ang tiwala para sa iyong home directory, ang mga paglulunsad mula sa `$HOME` ay nagsisimula sa `~/Work` sa halip.

May mga terminal shortcut din: pinapatakbo ng `a` ang default na agent nang inline sa kasalukuyang terminal, habang direktang sinisimulan ng `c`, `cx`, at `cy` ang OpenCode, Claude Code, at Codex (muli sa kanilang mga mode na auto-approving). Nag-sy-sync din ang mga pagbabago ng tema sa mga agent: sumusunod ang Claude Code, Pi, OpenCode, at Hermes (kapag na-install na ito ng Omarchy) kapag pinalitan mo ang tema ng Omarchy.

### Ang panel ng mga agent

May icon ng mga agent ang top bar. Bago ka makapag-set up ng agent, gagabayan ka ng panel nito sa pag-sign in sa Claude, Codex, o Grok, at ang una ay magiging iyong default na agent. Pagkatapos niyan, inilalagay ng panel ang bawat subscription sa isang pahina: bawat agent at account kasama ang plano nito, isang meter para sa bawat isa sa 5-hour session at lingguhang limit nito kasama ang oras hanggang mag-reset ito (i-hover para sa eksaktong porsyento), o ang natitirang prepaid na balanse, sa ilalim ng isang linya na umiikot sa kung ano ang nagamit mo sa kanilang lahat, gaya ng mga token ngayong linggo at ang iyong pinakaginagamit na modelo. Sa ilalim ng _Make something_ nag-aalok ito ng mga starter prompt para sa bagong tema, plugin, o app na nagbibigay ng gawain sa iyong default na agent. Ginagawa ang mga app sa paraang ginawa ang sariling Hype, Monologue, at Omacut ng Omarchy, sa C++ at Qt Quick, na sumusunod sa omarchy-app agent skill, at naka-install na ang compiler at mga piraso ng Qt na kailangan nila. Saklaw na agad ang Claude Code, Codex, Grok, Fireworks, at Kimi. Kasalukuyang nag-uulat ang Kimi ng mga limit sa quota ng account nang walang lokal na istatistika ng token o prompt.

I-left-click ang icon sa bar para sa panel, i-right-click para ilunsad ang iyong default na agent. Ang mga usage record sa likod nito ay muling ginagawa bawat 15 minuto ng `omarchy agent usage-update`, at maaari pang pagsamahin ng panel ang usage mula sa iyong iba pang makina sa pamamagitan ng isang naka-sync na folder. Tingnan ang README sa ilalim ng `$OMARCHY_PATH/shell/plugins/agents/` para sa buong mga setting.

### Maraming subscription

Kung nagbabayad ka para sa mahigit isang plano ng Claude, Codex, o Grok — isang personal na Max at isa para sa trabaho, halimbawa — mapapanatili silang lahat ng Omarchy na naka-sign in at makalilipat sa pagitan nila. Magdagdag ng subscription gamit ang + sa panel ng mga agent, na gagabay sa iyo doon mismo, o gamit ang `omarchy agent account add claude Work` (o `codex`, o `grok`). Ini-install nito ang CLI kung nawawala ito. Ang unang account para sa isang provider ay nag-sa-sign in sa pamamagitan ng iyong normal na browser, doon mismo kung saan laging tumitingin ang CLI. Bawat susunod ay nag-sa-sign in sa pamamagitan ng isang private window, kaya hindi aksidenteng makukuha ang account na naka-sign in na sa iyong browser; mag-sign in doon bilang ang account na idinaragdag mo, at isara muna ang anumang private window na nabuksan mo na. Huwag na huwag kang mag-log out sa CLI para gawin ito: binabawi ng pag-log out ang naka-save na sign-in, at kakailanganing idagdag muli ang account na iyon.

Para kopyahin ang iyong mga subscription login sa isa pang makinang Omarchy sa pamamagitan ng SSH, patakbuhin ang `omarchy agent account copy user@laptop`. Nagbibigay ang nagpadala ng pansamantalang receiver kapag walang naka-install ang destinasyon, kaya makatatanggap ng mga account ang mas lumang makinang Omarchy nang walang update. Nauuna ang mga naka-install na receiver. Kinokopya nito ang lahat ng subscription ng Claude, Codex, at Grok; magdagdag ng mga pangalan ng provider para piliin sila, gaya sa `omarchy agent account copy laptop claude`. Tumutugma ang mga pangalan ng account at command ID sa pinagmulan, kabilang ang mga account na nasa destinasyon na. Tumatanggap ng numeric suffix ang mga hindi kaugnay na account sa destinasyon kung magkatunggali ang kanilang mga pangalan, at nananatiling lokal sa bawat makina ang mga setting, skill, plugin, at kasaysayan ng pag-uusap.

Pinapanatili ang mga umiiral na kredensyal sa destinasyon. Ang isang account mula sa pinagmulan na naka-sign in na doon ay sini-synchronize ang pangalan nang hindi pinapalitan ang mga kredensyal nito; idinaragdag ang iba pang account sa tabi nito. Para palitan ang mga naka-save na kredensyal para sa magkatugmang mga account, gamitin ang `omarchy agent account copy --replace laptop claude` pagkatapos isara ang mga session ng account na iyon sa destinasyon. Nakukuha rin ng bagong destinasyon ang aktibong account at mga kagustuhan sa paglipat ng pinagmulan; pinapanatili ng isang naitatag nang destinasyon ang sarili nito.

Naglalakbay ang mga kredensyal sa pamamagitan ng SSH at iniimbak sa mga private file sa destinasyon, kaya kumopya lamang sa mga makinang pinagkakatiwalaan mo. Ito ay isang one-time na pagkopya, hindi patuloy na pagsi-synchronize. Maaaring i-rotate ng isa pang makina ang mga refresh token ng Codex, na nag-iiwan sa isang kinopyang login na nangangailangan ng pag-renew; ang magkakahiwalay na sign-in ang nananatiling pinakamaasahang pagpipilian para sa sabay-sabay na paggamit sa maraming makina. Tingnan ang [gabay sa pagpapatotoo ng account ng Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Isang account bawat provider ang aktibo, at bawat bagong session ay nagsisimula bilang ito: `cx`, `cy`, isang karaniwang `claude`, `codex`, o `grok`, anuman ang inilunsad sa pamamagitan ng `omarchy agent`, at mga script o editor na nakakahanap sa CLI sa `PATH`. Lumipat gamit ang `omarchy agent account use work` (at bumalik gamit ang `omarchy agent account use main`), o sa panel sa pamamagitan ng pagpindot sa numero ng isang account at pagkatapos ay `Enter` (o pag-click sa Use button nito). Ang mga session na tumatakbo na ay nananatili sa account kung saan sila nagsimula. Ibinabahagi sa mga account ang kasaysayan ng pag-uusap, mga setting, skill, at plugin, kaya ang `claude --continue` sa parehong folder ay nagpapatuloy kung saan ka huminto sa bagong account.

Kapag may mahigit isang account, ipinapakita ng panel ang mga limit ng bawat account nang magkatabi, na may marka ang aktibo. Bilang default, aabisuhan ka ng Omarchy kapag lumampas ang aktibong account sa 95% ng isang limit, at ang pag-click sa notification ay lumilipat sa account na may pinakamaraming headroom. I-hover ang linya ng isang account sa panel at i-click ang Autoswitch na lumilitaw sa tabi ng Use (o pindutin ang `m`), o patakbuhin ang `omarchy agent account mode auto`, para lumipat ito nang kusa sa halip; habang naka-on ito, kinukuha ng Autoswitch ang lugar ng Use, at ang pag-click dito muli ay bumabalik sa pag-aabiso. Magdagdag ng numero para baguhin ang threshold, gaya sa `omarchy agent account mode auto 90`. Kung ang bawat account ay lampas sa threshold, maririnig mo ito nang isang beses, kasama kung aling account ang unang magiging libre. Habang ang isang aktibong account ay nasa loob ng 15 puntos ng threshold nito (80% sa default), sinusuri ang mga limit nito bawat tatlong minuto sa halip na bawat 15.

Ipinapakita ng `omarchy agent account list` ang bawat account at ang pinakahuling mga limit nito, nalilimutan ng `omarchy agent account remove work` ang isa, at pinapalitan ng pangalan ng `omarchy agent account rename primary Hey` ang isa (o i-click ang pangalan ng isang account sa panel). Gumagana ang mga command na ito sa mga account ng iyong default na agent; para maabot ang isa pang provider, pangalanan muna ito, gaya sa `omarchy agent account use codex side`. Ang login na mayroon ka na sa `~/.claude` o `~/.codex` ay ang _Main_ na account at nananatili kung nasaan ito. Ang isang account na hindi ginamit nang mahigit walong oras ay maaaring magpakita ng _Sign-in required_; i-click ito para i-sign in muli ang account na iyon doon mismo sa panel, o magsimula ng session dito, na kusa nitong nire-refresh ang sign-in. Ang mga MCP server na mayroon ka noong idinagdag ang isang account ay sumasama dito, pero ang mga idinaragdag mo mamaya gamit ang `claude mcp add` ay umaabot lamang sa account kung saan mo sila idinagdag. Hindi sumusunod sa paglipat ang Claude Desktop at mga tool na naka-configure gamit ang absolute path papunta sa isang CLI binary. Nauuna ang isang tahasang `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, o `GROK_HOME` kaysa sa napiling account.

### Diagnosis ng crash

Binabantayan ng Omarchy ang systemd-coredump para sa mga pag-crash ng process. Kapag may nag-segfault, makakakuha ka ng notification na "Process crashed" — i-click ito, at ibibigay ang crash sa iyong default na agent kasama ng diagnose-crash skill ng Omarchy, na gagabay sa agent sa pagtatatag ng mga katotohanan mula sa core dump at pagpapasya kung sulit bang iulat ang crash sa upstream. Maaari mo rin itong patakbuhin nang mano-mano laban sa anumang PID mula sa `coredumpctl list` gamit ang `omarchy agent crash <pid>`.

Naka-on ang pagbabantay bilang default. I-off ito sa ilalim ng _Trigger > Toggle > Crash Capture_ (o gamit ang `omarchy toggle crash-capture`) at titigil ang mga notification; gumagana pa rin nang mano-mano ang `omarchy agent crash <pid>`.

Maaari ding patahimikin ang mga crash nang isa-isa bawat programa, na siyang iaalok sa iyo ng diagnosis sa dulo. Pinahihinto ng `omarchy crash mute hyprland` ang mga notification para sa programang iyon lamang, ibinabalik sila ng `omarchy crash mute hyprland off`, at inililista ng `omarchy crash mute` nang mag-isa kung ano ang iyong na-mute. Tumatanggap ito ng path ng binary nang kasing-handa ng pangalan nito, kaya pareho ang ginagawa ng `omarchy crash mute /usr/bin/hyprland`. I-quote ang isang pangalan na may puwang dito, gaya sa `omarchy crash mute 'Some App'`. Nag-aabiso pa rin ang lahat ng iba pa, at nagka-crash pa rin ang na-mute na programa — itinatago nito ang paalala, wala itong inaayos.

### Mga desktop app

May dalang ilang graphical na AI app din ang menu na _Install > AI_: ang ChatGPT desktop app, ang Claude desktop app (ang Linux beta ng Anthropic, na may mga tab na Chat, Cowork, at Claude Code), Grok Bot para sa pakikipag-chat sa mga modelo ng xAI, Hermes Desktop, OpenClaw, at ang Perplexity desktop app. Ang Grok Bot ang desktop chat app. Ang coding agent ay ang command na `grok`.

Ang Hermes Desktop ang dapat mong malaman, dahil ang isang makina ay may isang Hermes, at ito ay sa app: ini-install lamang kailanman ang Hermes sa pamamagitan ng app, at ang command na `hermes` na pinapatakbo ng default na agent ay sa app. Ang pagpili sa Hermes bilang default na agent ay nag-i-install ng parehong bagay na ginagawa ng entry na _Install > AI_: ang package, at isang Hermes runtime sa ilalim ng `~/.hermes` na bina-set up ng sariling installer ng Hermes, na tumatagal ng ilang minuto sa unang pagkakataon. Ang runtime na iyon ang nag-iisang Hermes na ginagamit ng terminal command na `hermes`, ng default na agent at ng app, at ina-update nito ang sarili gamit ang `hermes update` sa halip na maghintay sa isang release ng Omarchy. Ibinibigay din ng pag-install dito kay Hermes ang tema ng Omarchy bilang isang skin na pinangalanang `omarchy`, na sinusundan ng bawat surface ng Hermes habang nagpapalit ka ng mga tema; pumili ng iba sa ilalim ng mga setting ng Appearance ng Hermes o gamit ang `/skin` kung mas gusto mong hindi, at hinahayaan ng Omarchy ang pagpipiliang iyon. Isinasara muna ng pag-aalis ng app sa ilalim ng _Remove > AI_ ang Hermes, kabilang ang gateway, dinadala ang runtime na iyon kasama nito, at pinapanatili ang iyong mga chat, alaala, at ang mga skill na isinulat ng Hermes para sa sarili nito maliban kung sasabihin mong hindi: magtatanong ito, na ang default ay hindi, kung dapat ding mawala ang data na iyon at ang iyong mga setting ng koneksyon.

Ang desktop experience ng OpenClaw ay ang Control UI nito, na bumubukas bilang isang web app na sinusuportahan ng sarili nitong lokal na gateway. Nakatira ang OpenClaw sa `~/.openclaw` at ina-update ang sarili nito: gamitin ang button na "Update Gateway" ng Control UI o patakbuhin ang `openclaw update`, at magre-restart ang gateway sa bagong bersyon. Pinipili lamang ng Omarchy ang release kung saan magsisimula ang isang bagong install. Dinadala ng pag-aalis ng OpenClaw sa ilalim ng _Remove > AI_ ang serbisyo ng gateway at ang app kasama nito at pagkatapos ay magtatanong kung dapat ding mawala ang `~/.openclaw`, dahil hawak niyan ang iyong mga chat at kredensyal kasama ng OpenClaw mismo at ng mga plugin runtime na dina-download nito; pinapanatili ito ng default, at ang pag-install muli ng OpenClaw ay kukunin itong muli.

### Mga lokal na LLM

Inirerekomenda ng Omarchy ang dalawang paraan ng pagpapatakbo ng mga lokal na modelo ng LLM: LM Studio at Ollama. Nagbibigay ang LM Studio ng isang GUI interface para sa paghahanap ng mga open-weight na modelo, pag-install sa kanila, at pagpapatakbo sa kanila. Ito ay isang mahusay na paraan para madaling makapagsimula. Nag-aalok ang Ollama ng isang CLI para gawin ito nang katulad. Pero kung bago ka sa mga lokal na modelo, magsisimula ako sa LM Studio. Maaari mong i-install ang alinman sa ilalim ng _Install > AI_ sa Omarchy Menu.

### Ang Omarchy Skill

Tinutulungan ng mga agent skill ang AI na gumamit ng mga partikular na tool sa isang partikular na paraan, at may kasamang default na skill ang Omarchy para sa pag-aangkop ng system. Gaya ng pag-tweak ng iyong Hyprland config, pag-aayos ng bar, o kahit paglikha ng bagong tema mula sa simula. Naka-symlink ito sa mga skill directory para sa Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` at bawat `~/.hermes/profiles/*/skills`), at ang generic na lokasyon na `~/.agents/skills`, kaya awtomatikong kinukuha ito ng karamihan ng harness.

Pero dapat mong tratuhin ang skill na ito bilang eksperimental. Gagamitin ito ng iba't ibang modelo nang may iba't ibang epekto. Pinakamainam na tumakbo muna sa plan mode, para may ideya ka kung ano ang gustong baguhin ng agent. At pagkatapos ay maging handang i-rollback ang mga pagbabago o kahit tawagin ang `omarchy reinstall configs`, kung guguluhin ng agent ang lahat.
