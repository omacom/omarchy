# AI

Kasama sa Omarchy ang mga launcher para sa mga coding agent sa ibaba nang hindi pumipili ng default para sa iyo. Magpatakbo ng command para i-install ang CLI nito sa unang paggamit, pagkatapos ay mag-authenticate kapag sinabihan. Ang Hermes at OpenClaw ang mga eksepsiyon: walang ini-install para sa kanila sa pamamagitan ng mise, at ang pagpili sa alinman ay nagse-setup ng sarili nitong self-updating na kopya, gaya ng ipinapaliwanag ng _Desktop apps_ sa ibaba.

### Pag-install at pag-update ng mga agent

Maliban sa Hermes at OpenClaw, ginagamit ng mga agent na ito ang lazy installation ng mise: ini-install ng unang paglunsad ang CLI, at muling ginagamit ito ng mga susunod na paglunsad. Sinusuri rin ng mise ang isang naka-install na agent para sa bagong release nang hindi hihigit sa isang beses bawat apat na oras, bago ito magsimula o sa background sa isang shell prompt. Kung mabigo ang update na iyon o offline ka, tatakbo ang naka-install na bersyon. Ina-update ng `omarchy update` ang mga naka-install na agent kasama ng iba pang bahagi ng Omarchy, at ina-update ng `mup` ang mga tool na pinamamahalaan ng mise lamang.

Ang sariling updater ng isang agent, tulad ng `claude update`, `codex update`, o isang update button sa isang app, ay hindi nag-a-update ng install na pinamamahalaan ng mise. Nabibigo ang `codex update`, at maaaring mag-ulat ng tagumpay ang `claude update` habang nag-i-install ng hiwalay na kopya na hindi sinusubaybayan ng mise. Kung mas gusto mong gamitin ang katutubong installer at updater ng isang agent, idagdag ito sa `disable_tools`; tingnan ang [Mga paunang naka-install na CLI tool](18-development-tools.md#preinstalled-cli-tools).

Para i-install ang lahat ng naka-configure na lazy tool bago mo kailanganin ang mga ito, patakbuhin ang `mise install --include-lazy`. Kasama rito ang iba pang default na CLI tool ng Omarchy pati na rin ang mga agent. Tingnan ang [Mga paunang naka-install na CLI tool](18-development-tools.md#preinstalled-cli-tools) para sa pag-install ng iisang tool o paggamit ng sarili mong installation.

Ini-install ang `grok` sa pamamagitan ng first-party na `grok` package ng mise, sa parehong paraan tulad ng `claude` at `codex`. Patakbuhin ang `grok`, o i-star ito sa agents panel. Laktawan ang `curl | bash` installer sa x.ai. Naglalagay ang paraang iyon ng pangalawang kopya sa `~/.grok/bin`, inuuna ito sa `PATH`, at pinapatungan ang wrapper ng Omarchy.

Binubuksan ng `dsh` ang browser UI nito sa `127.0.0.1:3080`, na ang launch directory ang default workspace nito. Walang starting prompt ang browser UI nito, kaya binubuksan ito ng `omarchy agent prompt` na nasa clipboard mo ang prompt para i-paste. Sinisimulan ito ng Omarchy gamit ang no-approval permission preset ng DeepSeek. Ina-upload ng DeepSeek Harness ang mga session log sa DeepSeek kapag ginagamit mo ang opisyal nitong model API; i-off iyon sa ilalim ng _Settings > General > Upload Session Log_ sa browser UI nito. Ang feedback na ipinapadala mo rito ay ina-upload din kasama ng session, maliban kung sisimulan mo ito gamit ang `DSH_TELEMETRY_MODE=DISABLED`.

### Ang default na agent

Piliin ang default mong agent gamit ang star sa tabi ng isang agent sa agents panel, na napupunan sa default, o gamit ang `omarchy default agent <name>`, na tumatanggap din ng anumang harness na walang linya roon. Kung hindi pa naka-install ang agent, i-install muna ito ng pagpili rito, at makakakuha rin ito ng sarili nitong launcher sa app launcher, sa tabi ng Agent. Inaanyayahan ka ng bagong Omarchy na mag-setup ng isa gamit ang isang beses na notification, na nagbubukas sa agents panel.

Sinusubukan din ng pagpili sa Claude na i-setup ang browser extension nito para sa Chromium, Chrome, Brave, Brave Origin, at Edge. Nalalapat ang extension setup sa lahat ng user at maaaring humingi ng system password mo; pipiliin at ilulunsad pa rin ang Claude kahit kanselahin mo o mabigo ang pag-install ng extension. I-restart ang browser mo, i-enable ang extension kung sinabihan, at mag-sign in sa Claude para tapusin ang pagkonekta rito. Patakbuhin ang `/chrome` sa Claude para tingnan ang koneksyon. Hindi sinusuportahan ng Firefox at Zen ang extension na ito. Kung Claude na ang default mo bago idagdag ang setup na ito, piliin itong muli para i-install ang extension.

Kapag nakapili ka na, ilulunsad ng `Super + Shift + Ctrl + A` ang default na agent sa isang nakalaang terminal window (o ilalabas ang picker kung hindi ka pa nakakapili). Maaari mo rin itong ilunsad nang diretso sa isang gawain gamit ang `omarchy agent prompt "Review this project"`. Walang starting prompt ang Freebuff at DeepSeek Harness, kaya sa halip ay binubuksan ang mga ito na nasa clipboard mo ang prompt para i-paste. Ang mga agent na inilunsad sa ganitong paraan ay tumatakbo nang walang nagbabantay sa kani-kanilang don't-stop-to-ask mode, kaya maging handa na talagang gumawa sila ng mga bagay! Walang ganoong mode ang MiniMax Code para sa mga interactive session nito, kaya humihingi ito ng mga pahintulot gaya ng dati. At dahil tumatanggi ang mga agent na tandaan ang tiwala para sa home directory mo, sa halip ay nagsisimula sa `~/Work` ang mga paglunsad mula sa `$HOME`.

May mga terminal shortcut din: pinapatakbo ng `a` ang default na agent nang inline sa kasalukuyang terminal, habang direktang sinisimulan ng `c`, `cx`, at `cy` ang OpenCode, Claude Code, at Codex (muli sa kanilang auto-approving mode). Nagsi-sync din ang mga pagbabago ng tema sa mga agent: sumusunod ang Claude Code, Pi, OpenCode, at Hermes (kapag na-install na ito ng Omarchy) kapag nagpapalit ka ng tema ng Omarchy.

### Ang mga tagubilin ng agent mo

Ang mga personal na patakaran para sa bawat agent ay nasa `~/.agents/AGENTS.md`, sa tabi ng mga shared skill sa `~/.agents/skills`. Buksan ito gamit ang document icon sa tabi ng + sa agents panel, o ang `omarchy agent instructions --edit`, na nagli-link din nito sa bawat harness na nagpapanatili ng sarili nitong global file: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, ang `~/.copilot/copilot-instructions.md` ng Copilot, at iba pa. Binabasa ng Crush at Amp ang link na `~/.config/AGENTS.md`, habang direktang binabasa ng omp, Kimi, at DeepSeek Harness ang `~/.agents/AGENTS.md`. Nagli-link din nito ang pagpili ng default na agent. Ang instructions file na mayroon ka na ay nagiging shared na file kung wala pa nito; kung hindi, pinapanatili ito sa tabi ng link bilang `.bak`. Patakbuhin ang `omarchy agent instructions` para muling mag-link pagkatapos mag-install ng isa pang agent.

### Ang agents panel

May agents icon ang top bar. Bago ka mag-setup ng agent, nag-aalok ang panel nito ng tatlong paraan para magsimula: mag-sign in sa isang subscription ng Claude, Codex, Grok, Gemini, Muse, Cursor, o Copilot, o sa ilalim ng More sa isang coding plan ng OpenCode Go, MiniMax, Synthetic, o Z.ai; magbayad ayon sa paggamit gamit ang Fireworks, OpenCode Zen and Go, OpenRouter, o sa ilalim ng More ang DeepSeek o anumang iba pang provider na pinag-sign in-an ng OpenCode, na lahat ay tumatakbo sa OpenCode; o patakbuhin ang pinakamahusay na modelo para sa computer mo, kapag may kasya rito. Ang una mong matatapos ay magiging default agent mo, at ang + sa panel, o ang _Agent > Add_ sa Omarchy Menu, ay nag-aalok ng parehong tatlo sa ibang pagkakataon. Pagkatapos niyon, inilalagay ng panel ang bawat subscription sa isang pahina: bawat agent at account kasama ang plan nito, isang meter para sa bawat 5-hour session at weekly limit nito kasama ang oras hanggang mag-reset ito (i-hover para sa eksaktong porsyento), o ang natitirang prepaid balance, sa ilalim ng isang linyang umiikot sa kung ano ang nagamit mo sa lahat ng mga ito, tulad ng mga token ngayong linggo at ang pinakamadalas mong gamiting modelo. Sa ilalim ng _Make something cool_ nag-aalok ito ng mga starter prompt para sa bagong tema, plugin, app, o laro na nagbibigay ng gawain sa default agent mo. Ginagawa ang mga app sa paraang ginawa ang sariling Hype, Monologue, at Omacut ng Omarchy, sa C++ at Qt Quick, na sumusunod sa omarchy-make-app agent skill, at naka-install na ang compiler at mga piraso ng Qt na kailangan nila. Ang mga laro ay iisang three.js page sa `~/Games/vibes`, na sumusunod sa omarchy-make-game agent skill, at lahat ay nagbubukas mula sa isang Game Vibes launcher sa kasalukuyang tema; nilo-load nila ang three.js mula sa web, kaya kailangan nila ng koneksyon para magsimula. Saklaw agad ang Claude Code, Codex, Grok, Kimi, Cursor at ang Grok Bot allowance nito, GitHub Copilot, Muse, Gemini (sa pamamagitan ng Antigravity), at Devin kasama ang kanilang mga limit, ang Kimchi kasama ang plan, prepaid credits, at spend budgets nito, at ipinapakita ng Hermes, Mistral Vibe, at Qwen Code ang kanilang mga session at token kapag nagamit mo na sila. Lumalabas din ang mga provider plan at key na ginagamit mo sa pamamagitan ng pi, omp, o opencode: ang OpenCode Zen and Go, ang Z.ai GLM Coding Plan, Ollama Cloud, ang MiniMax Token Plan, at Synthetic kasama ang kanilang mga limit; ang OpenRouter at DeepSeek kasama ang kanilang prepaid balance; ang Fireworks kasama ang gastos nito sa nakalipas na 30 araw. Nabibilang din sa mga kabuuan ang mga token mula sa mga modelong pinapatakbo mo sa sarili mong hardware; ang mga modelo mismo ay may sariling panel, na inilalarawan sa ilalim ng [Mga lokal na modelo](#local-models). Bawat agent ay binibilang nang isang beses, sa ilalim ng kung sino ang naniningil para rito, gaano man karaming harness ang pagdaanan mo rito.

I-left-click ang bar icon o pindutin ang `Super + Ctrl + X` para sa panel, i-right-click para ilunsad ang default agent mo, at i-middle-click para mag-refresh. Ang mga usage record sa likod nito ay muling ginagawa bawat 15 minuto ng `omarchy agent usage update`, at maaari pang pagsamahin ng panel ang usage mula sa iba mo pang machine sa pamamagitan ng naka-sync na folder. Tingnan ang README sa ilalim ng `$OMARCHY_PATH/shell/plugins/agents/` para sa buong settings.

### Maraming subscription

Kung nagbabayad ka para sa higit sa isang plan ng Claude, Codex, o Grok — isang personal na Max at isang pangtrabaho, halimbawa — maaaring panatilihin ng Omarchy na naka-sign in ang lahat ng mga ito at lumipat-lipat sa pagitan nila. Magdagdag ng subscription gamit ang + sa agents panel, na gagabay sa iyo roon mismo, o gamit ang `omarchy agent account add claude Work` (o `codex`, o `grok`). Ang parehong + at command ay nag-sign in sa Gemini (`gemini`) at OpenCode (`opencode`), at nagse-save ng Fireworks (`fireworks`) o OpenRouter (`openrouter`) API key sa OpenCode; nag-sign in din ang command sa Copilot (`copilot`), Cursor (`cursor`), at Muse (`muse`). Nagpapanatili ang mga iyon ng tig-iisang sign-in bawat isa. Ini-install nito ang CLI kung nawawala ito. Ang unang account para sa isang provider ay nag-sign in sa pamamagitan ng normal mong browser, mismo kung saan laging tumitingin ang CLI. Ang bawat kasunod ay nag-sign in sa pamamagitan ng private window, kaya hindi aksidenteng makukuha ang account na naka-sign in na ang browser mo; mag-sign in doon bilang account na idinaragdag mo, at isara muna ang anumang private window na nakabukas na. Huwag kailanman mag-log out sa CLI para gawin ito: binabawi ng pag-log out ang naka-save na sign-in, at kailangang idagdag muli ang account na iyon.

Para kopyahin ang mga subscription login mo sa isa pang Omarchy machine sa pamamagitan ng SSH, patakbuhin ang `omarchy agent account copy user@laptop`. Nagbibigay ang nagpadala ng pansamantalang receiver kapag walang naka-install nito ang destinasyon, kaya makakatanggap ng mga account ang mas lumang Omarchy machine nang walang update. Inuuna ang mga naka-install na receiver. Kinokopya nito ang lahat ng subscription ng Claude, Codex, at Grok; magdagdag ng mga pangalan ng provider para piliin ang mga ito, gaya ng sa `omarchy agent account copy laptop claude`. Tumutugma ang mga pangalan ng account at command ID sa pinagmulan, kabilang ang mga account na naroon na sa destinasyon. Makakatanggap ng numeric suffix ang mga hindi kaugnay na account sa destinasyon kung magkasalungat ang kanilang mga pangalan, at mananatiling lokal sa bawat machine ang settings, skills, plugins, at conversation history.

Pinapanatili ang mga umiiral na credential sa destinasyon. Ang isang source account na naka-sign in na roon ay naka-sync ang pangalan nang hindi pinapalitan ang mga credential nito; idinaragdag ang iba pang account sa tabi nito. Para palitan ang mga naka-save na credential para sa magkatugmang account, gamitin ang `omarchy agent account copy --replace laptop claude` pagkatapos isara ang mga session ng account na iyon sa destinasyon. Makukuha rin ng bagong destinasyon ang aktibong account at switching preferences ng pinagmulan; pinapanatili ng matatag nang destinasyon ang sarili nito.

Naglalakbay ang mga credential sa pamamagitan ng SSH at nakaimbak sa mga pribadong file sa destinasyon, kaya magkopya lamang sa mga machine na pinagkakatiwalaan mo. Isa itong isang beses na kopya, hindi patuloy na synchronization. Maaaring i-rotate ng ibang machine ang mga Codex refresh token, na mag-iiwan sa nakopyang login na nangangailangan ng renewal; nananatiling pinaka-maaasahang pagpipilian ang magkahiwalay na sign-in para sa sabay-sabay na paggamit sa maraming machine. Tingnan ang [Gabay sa pagpapatotoo ng account ng Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Isang account bawat provider ang aktibo, at bawat bagong session ay nagsisimula bilang ito: `cx`, `cy`, isang payak na `claude`, `codex`, o `grok`, anumang inilunsad sa pamamagitan ng `omarchy agent`, at mga script o editor na nakakahanap ng CLI sa `PATH`. Lumipat gamit ang `omarchy agent account use work` (at bumalik gamit ang `omarchy agent account use main`), o sa panel sa pamamagitan ng pagpindot sa numero ng isang account at pagkatapos ay `Enter` (o pag-click sa star nito). Lumilipat din ang mga tumatakbong Claude session, mula sa kanilang susunod na mensahe: bawat Claude session ay tumatakbo sa `~/.claude`, na laging naglalaman ng sign-in ng aktibong account. Ang isang Claude session na sinimulan sa sariling folder ng isang account ng mas lumang Omarchy ay nagpapanatili ng sign-in na iyon hanggang sa umalis ito, kaya pinapangalanan ng paglipat ang mga session na iyon at natatapos nang kusa kapag wala na sila. Nananatili ang mga tumatakbong Codex at Grok session sa account na pinagsimulan nila. Ibinabahagi sa lahat ng account ang conversation history, settings, skills, at plugins, kaya nagpapatuloy ang `claude --continue` sa parehong folder kung saan ka tumigil sa bagong account.

Kapag may higit sa isang account, ipinapakita ng panel ang mga limit ng bawat account nang magkatabi, na may napunang star sa ginagamit. Inaabisuhan ka ng Omarchy kapag lumampas ang aktibong account sa 95% ng isang limit, at inililipat ka ng pag-click sa notification sa account na may pinakamaraming headroom. Hindi ito kailanman lumilipat nang kusa. Baguhin ang threshold gamit ang `omarchy agent account threshold 90`. Kung lampas sa threshold ang bawat account, maririnig mo ang tungkol dito nang isang beses, kasama kung aling account ang unang magkakaroon ng puwang. Habang ang isang aktibong account ay nasa loob ng 15 puntos ng threshold nito (80% sa default), sinusuri ang mga limit nito bawat tatlong minuto sa halip na bawat 15.

Ipinapakita ng `omarchy agent account list` ang bawat account at ang pinakabagong limit nito, kinakalimutan ng `omarchy agent account remove work` ang isa, at pinapalitan ng pangalan ng `omarchy agent account rename primary Hey` ang isa (o i-click ang pangalan ng isang account sa panel). Gumagana ang mga command na ito sa mga account ng default agent mo; para maabot ang ibang provider, pangalanan muna ito, gaya ng sa `omarchy agent account use codex side`. Ang login na mayroon ka na sa `~/.claude` o `~/.codex` ay ang _Main_ account. Nananatili ang sa Codex kung nasaan ito; naghihintay ang sa Claude sa sarili nitong folder habang aktibo ang ibang account. Ang isang account na hindi nagamit nang higit sa mga walong oras ay maaaring magpakita ng _Sign-in required_; i-click ito para muling mag-sign in sa account na iyon mismo sa panel, o lumipat dito at magsimula ng session, na kusang nagre-refresh ng sign-in. Ang mga MCP server na idinaragdag mo gamit ang `claude mcp add` ay umaabot sa bawat Claude account, dahil lahat sila ay tumatakbo sa `~/.claude`; para sa Codex at Grok, kasama ng isang account ang mga server na mayroon ka noong idagdag ito, ngunit ang mga susunod ay umaabot lamang sa account kung saan mo sila idinagdag. Nagpapanatili ang Claude Desktop ng sarili nitong sign-in, at hindi sumusunod sa paglipat ang mga Codex o Grok tool na naka-configure gamit ang absolute path patungo sa isang CLI binary. Inuuna ang isang tahasang `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, o `GROK_HOME` kaysa sa napiling account.

### Diagnosis ng crash

Binabantayan ng Omarchy ang systemd-coredump para sa mga crash ng process. Kapag nakapili ka na ng default agent, ang anumang programa mo na nagda-dump ng core ay nagdadala ng notification na "Process crashed" — i-click ito, at ibibigay ang crash sa default agent mo kasama ang omarchy-diagnose-crash skill ng Omarchy, na gagabay sa agent sa pagtatatag ng mga katotohanan mula sa core dump at pagpapasya kung karapat-dapat iulat ang crash sa upstream. Maaari mo rin itong patakbuhin nang mano-mano laban sa anumang PID mula sa `coredumpctl list` gamit ang `omarchy agent crash <pid>`.

Naka-on ang pagbabantay bilang default. I-off ito sa ilalim ng _Trigger > Toggle > Crash Capture Off_ (o gamit ang `omarchy toggle crash-capture`) at hihinto ang mga notification; gumagana pa rin nang mano-mano ang `omarchy agent crash <pid>`.

Maaari ring patahimikin ang mga crash nang paisa-isang programa, na siyang inaalok sa iyo ng diagnosis sa dulo. Pinipigilan ng `omarchy crash mute hyprland` ang mga notification para sa programang iyon lamang, ibinabalik sila ng `omarchy crash mute hyprland off`, at inililista ng `omarchy crash mute` nang mag-isa kung ano ang na-mute mo. Tumatanggap ito ng path ng binary nang kasing saya ng pangalan nito, kaya pareho ang ginagawa ng `omarchy crash mute /usr/bin/hyprland`. Mag-quote ng pangalang may puwang, gaya ng sa `omarchy crash mute 'Some App'`. Nag-aabiso pa rin ang lahat ng iba pa, at nagka-crash pa rin ang naka-mute na programa — itinatago nito ang paalala, hindi nito inaayos ang anuman.

### Mga desktop app

May dala rin ang menu na _Install > AI_ ng ilang graphical AI app: Amp Desktop, Antigravity Desktop, ang ChatGPT desktop app, ang Claude desktop app (ang Linux beta ng Anthropic, na may mga tab na Chat, Cowork, at Claude Code), Grok Bot para makipag-chat sa mga modelo ng xAI, Herdr Desktop, Hermes Desktop, OpenClaw, ang Perplexity desktop app, at T3 Code. Ang Grok Bot ay ang desktop chat app. Ang coding agent ay ang command na `grok`.

Ang Hermes Desktop ang dapat mong malaman, dahil iisa lang ang Hermes ng isang machine, at sa app ito: ini-install lamang ang Hermes sa pamamagitan ng app, at ang command na `hermes` na pinapatakbo ng default agent ay sa app. Ang pagpili sa Hermes bilang default agent ay nag-i-install ng parehong bagay na ginagawa ng entry na _Install > AI_: ang package, at isang Hermes runtime sa ilalim ng `~/.hermes` na sine-setup ng sariling installer ng Hermes, na tumatagal ng ilang minuto sa unang pagkakataon. Ang runtime na iyon ang iisang Hermes na ginagamit ng terminal command na `hermes`, ng default agent at ng app, at ina-update nito ang sarili gamit ang `hermes update` sa halip na maghintay sa isang Omarchy release. Ibinibigay din ng pag-install nito sa Hermes ang tema ng Omarchy bilang skin na pinangalanang `omarchy`, na sinusundan ng bawat Hermes surface habang nagpapalit ka ng mga tema; pumili ng iba sa ilalim ng Appearance settings ng Hermes o gamit ang `/skin` kung mas gusto mong hindi, at iiwan ng Omarchy ang pagpipiliang iyon. Ang pag-alis ng app sa ilalim ng _Remove > AI_ ay nagsasara muna sa Hermes, kasama ang gateway, isinasama ang runtime na iyon, at pinapanatili ang iyong mga chat, memory, at ang mga skill na isinulat ng Hermes para sa sarili maliban kung sasabihin mong hindi: nagtatanong ito, na ang default ay hindi, kung dapat ding mawala ang data na iyon at ang iyong connection settings.

Ang desktop experience ng OpenClaw ay ang Control UI nito, na nagbubukas bilang web app na sinusuportahan ng sarili nitong lokal na gateway. Nakatira ang OpenClaw sa `~/.openclaw` at ina-update ang sarili: gamitin ang button na "Update Gateway" ng Control UI o patakbuhin ang `openclaw update`, at magre-restart ang gateway sa bagong bersyon. Pinipili lamang ng Omarchy ang release na pagsisimulan ng bagong install. Maaari ring maging default agent mo ang OpenClaw: ang pagpili rito sa ilalim ng _Agent > Harness_ ay nagse-setup ng parehong kopya sa `~/.openclaw`, at binubuksan ng agent ang terminal UI ng OpenClaw na nakakabit sa gateway nito. Ang pag-alis ng OpenClaw sa ilalim ng _Remove > AI_ ay isinasama ang gateway service at ang app at pagkatapos ay nagtatanong kung dapat ding mawala ang `~/.openclaw`, dahil naroon ang iyong mga chat at credential kasama ng OpenClaw mismo at ng mga plugin runtime na dina-download nito; pinapanatili ito ng default, at muling kukunin ito ng pag-install ulit ng OpenClaw.

Ang Herdr Desktop ay ang desktop app na [Herdr](https://herdr.dev): mga space, tab, at pane ng mga terminal at coding agent na patuloy na tumatakbo sa core nito kapag isinara mo ang window. Nagmumula ito sa sariling installer ng Herdr sa halip na sa isang package, kaya nakatira ito sa `~/.local/share/herdr-app`, isinasama ang core nito sa `~/.local/bin/herdr-core` kapag wala ka pa nito, at ina-update ang sarili nitong dalawa. Nakatabi ito sa command na `herdr` na ipinapadala ng Omarchy sa `Super + Ctrl + Return` sa halip na palitan ito, at nakukuha ang mga direct key ng command na iyon: hinahati ng `Alt + Return` at `Alt + Shift + Return` ang isang pane pababa o pakanan, isinasara ito ng `Alt + Escape`, gumagalaw sa pagitan ng mga pane ang `Ctrl + Alt + Arrow`, pumipili ng tab ang `Alt + 1..9` at `Alt + Left/Right`, at gumagalaw sa pagitan ng mga space ang `Alt + Up/Down`. Pumipili ng space ang `Ctrl + 1..9` at humahakbang sa mga agent ang `Alt + Shift + Up/Down`. Nananatiling terminal-only ang mga prefix key na `Ctrl + Space`, dahil hindi kayang hawakan ng app ang payak na Ctrl key para sa isang sequence. Isinusulat ito ng Omarchy sa `~/.config/herdr-app/keys.json`, at ibinabalik sila ng `omarchy-refresh-herdr-app`. Pinipili ng pag-install nito ang Omarchy theme ng Herdr, na sumusunod sa tema ng Omarchy mo mula noon. Nagpapanatili ang Herdr ng isang tema para sa light mode at isa para sa dark, kaya pagkatapos lumipat sa pagitan ng dark at light na tema ng Omarchy, piliin muli ang Omarchy sa theme picker ng Herdr nang isang beses pa para sa kabilang mode.

Tumatakbo ang T3 Code mula sa opisyal nitong AppImage release sa `~/.local/share/t3code` sa halip na mula sa isang package, kaya ina-update nito ang sarili. Nagtatanong ang pag-install nito kung magsisimula sa Stable o Nightly channel; lumipat sa ibang pagkakataon sa settings ng T3 Code. Nakatira ang iyong mga thread at setting sa `~/.t3`, at isinasama sila ng pag-alis ng T3 Code sa ilalim ng _Remove > AI_.

### Mga lokal na modelo

Magpatakbo ng open model sa sarili mong machine para sa iyong mga coding agent. Nananatili sa machine ang iyong mga prompt at code; walang ipinapadala sa modelo ang umaalis dito. Magsimula sa:

```bash
omarchy models use best text
```

Nagse-setup iyon ng pinakamahusay na text model para sa machine na ito, ang uri na ginagamit ng iyong mga agent. Ang mga image, video at music model ay may sarili nilang pinakamahusay: `omarchy models use best image`, `video` o `music`. Patakbuhin ang `omarchy models use best` para makita ang pinili ng bawat uri para sa machine na ito.

O buksan ang local models panel mula sa sparkles icon nito sa top bar, sa tabi ng agents icon, o gamit ang Super + Ctrl + Alt + X, at piliin ang +. Lumalabas ang icon kapag may kasya na modelo sa machine na ito. Kasama ng Omarchy ang Podman, na nagpapatakbo ng mga modelo, pati na rin ang NVIDIA's container toolkit sa isang NVIDIA machine, na nagbibigay sa kanila ng GPU; kung nawawala ang alinman, ini-install ito ng unang setup. Pagkatapos ay pipiliin ng Omarchy ang inirerekomendang modelo para sa machine na ito, ida-download ito, at sisimulan ito. Asahan ang download na sampu-sampung GB at ang karamihan ng memory ng machine ay ginagamit habang tumatakbo ang modelo: gumagamit ang Flash Next ng mga 100 GiB kasama ang buong 256K context nito. Kung hawak ng ibang mga modelo ang memory na kailangan nito, sine-setup itong nakahinto, handang magsimula kapag huminto ka ng isa. Humihinto ang modelo sa logout; ihinto mo ito mismo kapag kailangan mo ang memory para sa ibang bagay.

Ipinapakita ng `omarchy models list` ang mga opsyon at ipinapaliwanag kung bakit hindi kasya ang ilan. Para mag-setup ng isa pa, patakbuhin ang `omarchy models use <recipe>`. Ngayon, available ang `qwen3.8-flash-next-gufo` at `qwen3.8-27b-gufo` para sa 128 GB Strix Halo machine; gumagamit ang 27B ng mga 40 GiB, kaya nag-iiwan ito ng puwang para sa ibang trabaho. Sa isang 64 GB laptop na may Intel's Arc B390, tumatakbo ang `qwen3.6-35b-a3b-llamacpp` sa mga 30 GiB. Dumarating ang mga bagong recipe at rekomendasyon kasama ng `omarchy update`, sa pamamagitan ng package.

Bawat modelong sine-setup mo ay nakakakuha ng sarili nitong linya sa local models panel: play para simulan ito, pause para ihinto ito at palayain ang memory nito, at ang terminal button para buksan ang agent mo rito. Sa itaas, ipinapakita ng isang bar kung paano nahahati ang memory ng machine sa pagitan ng Omarchy mismo (ang system at iyong mga app), bawat tumatakbong modelo, at kung ano ang libre. Ituro ang isang nakahintong modelo at ipapakita ng bar kung kasya ito, o kung gaano ito kakulang. Marami ang maaaring tumakbo nang sabay kapag magkakasya sila sa memory nang magkasama; kung hindi kasya ang isa, sasabihin ng Omarchy kung aling tumatakbong modelo ang ihinto. I-drag ang mga linya gamit ang logo nila para muling ayusin sila, at pindutin ang Delete sa isang napiling linya para alisin ang isang modelo at ang download nito.

Bawat coding model na sine-setup mo ay nakakakuha rin ng sarili nitong entry sa app launcher, sa ilalim ng pangalan ng modelo at kasama ang logo ng gumawa nito, sa paraang nagdaragdag ng isa ang pag-sign in sa Claude, Codex o Grok. Binubuksan nito ang agent mo sa modelong iyon, at sinisimulan muna ang modelo kung hindi ito tumatakbo: ipinapakita ng terminal na naglo-load ito at ibibigay sa agent kapag handa na ito. Inaalis ng pag-alis ng modelo ang entry nito.

Hindi lahat ng modelo ay para sa coding. Sa halip ay nagbubukas sa Fantasi ang mga image, video at music model, ang app ng Omarchy para sa paggawa ng mga larawan, video at musika gamit ang modelong tumatakbo sa machine na ito, na pinili roon o mula sa kanilang linya sa local models panel.

Nananatiling tumatakbo ang isang modelo nang eksakto kung paano ito sine-setup, kaya hindi kailanman nire-restart ng isang Omarchy update ang isa sa ilalim ng iyong mga agent. Kapag may mas bagong runtime o mas bagong weights ang Omarchy para sa isang modelong sine-setup mo, nagpapakita ang linya nito ng update button: pindutin ito at muling sine-setup ang modelo sa background, dina-download lamang ang nagbago, at magre-restart sa bagong bersyon. Ang isang modelong nakahinto ay nananatiling nakahinto. Pareho ang ginagawa ng `omarchy models update` para sa bawat modelo mula sa terminal.

Mula sa command line, pareho ang ginagawa ng `omarchy models start <recipe>` at `omarchy models stop <recipe>`, ipinapakita ng `omarchy models status` ang bawat modelo, at binubuksan ng `omarchy agent --local` ang huling modelong sinimulan mo sa pi, anuman ang default agent mo. Para gawin ang modelong iyon na binubuksan ng agent hotkey, ng Quake console, at ng _Make something_, patakbuhin ang `omarchy default agent local` o piliin ang _Local model_ sa ilalim ng _Agent > Harness_. Inililista rin ng pi ang bawat modelong sine-setup mo, at ang mga nasa machine na ipinares mo, sa sarili nitong model picker, kaya naaabot din sila ng payak na `pi`. Maaari ring kumonekta ang anumang OpenAI-compatible client: ipinapakita ng `status` ang address ng bawat modelo (ang una ay `http://127.0.0.1:11435/v1`), ang recipe name ang modelo, at ang key ay nasa `~/.config/omarchy/agent-local/key`.

Tinatanggal ng `omarchy models remove <recipe>` ang isang modelo at ang mga download na hindi ginagamit ng ibang modelo.

Nilalagyan ng label ang mga third-party runtime kasama ang publisher nila. Pinapatakbo ng Omarchy ang bawat modelo nang walang network access.

### Mga lokal na LLM

Inirerekomenda ng Omarchy ang dalawang paraan ng pagpapatakbo ng mga lokal na LLM model: LM Studio at Ollama. Nagbibigay ang LM Studio ng GUI interface para sa paghahanap ng mga open-weight model, pag-install ng mga ito, at pagpapatakbo ng mga ito. Mahusay itong paraan para madaling makapagsimula. Nag-aalok ang Ollama ng CLI para gawin ito nang katulad. Ngunit kung bago ka sa mga lokal na modelo, magsisimula ako sa LM Studio. Maaari mong i-install ang alinman sa ilalim ng _Install > AI_ sa Omarchy Menu.

### Ang mga Omarchy skill

Tinutulungan ng mga agent skill ang AI na gumamit ng mga partikular na tool sa isang partikular na paraan, at nagpapadala ang Omarchy ng pito sa mga ito. Sinasaklaw ng omarchy skill ang pagsasaayos ng system, tulad ng pag-tweak ng Hyprland config mo o pag-aadjust ng bar. Sinasaklaw ng omarchy-make-theme, omarchy-make-plugin, omarchy-make-app, at omarchy-make-game ang paggawa ng bagong bagay, sinasaklaw ng omarchy-contribute ang pag-uulat ng bug o pagpapadala ng fix sa upstream, at sinasaklaw ng omarchy-diagnose-crash ang core dump ng isang crash. Naka-symlink sila sa mga skill directory para sa Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` at bawat `~/.hermes/profiles/*/skills`), at ang generic na lokasyong `~/.agents/skills`, kaya awtomatikong nakukuha sila ng karamihan sa mga harness. Inuuna ang sariling skill folder mo na may parehong pangalan.

Ngunit dapat mong ituring na eksperimental ang mga skill na ito. Gagamitin sila ng iba't ibang modelo nang may iba't ibang epekto. Pinakamainam na tumakbo muna sa plan mode, para magkaroon ka ng ideya kung ano ang gustong baguhin ng agent. At pagkatapos ay maging handang i-rollback ang mga pagbabago o kahit tawagin ang `omarchy reinstall configs`, kung guluhin ng agent ang lahat.
