Magpatakbo ng isang utos para i-install ang CLI nito sa unang paggamit, pagkatapos ay mag-authenticate kapag sinabihan. Ang Hermes ang eksepsiyon: walang ini-install para dito sa unang paggamit, at ang pagpili dito ay nag-i-install ng Hermes Desktop, gaya ng ipinapaliwanag ng _Mga desktop app_ sa ibaba.

### Pag-install at pag-update ng mga agent

Maliban sa Hermes, ginagamit ng mga agent na ito ang lazy installation ng mise: ini-install ng unang paglulunsad ang CLI, at muling ginagamit ito ng mga susunod na paglulunsad. Sinusuri rin ng mise ang isang naka-install na agent para sa isang bagong release nang hindi hihigit sa isang beses bawat apat na oras, bago pa lang ito magsimula o sa background sa isang shell prompt. Kung mabigo ang update na iyon o offline ka, tatakbo ang naka-install na bersyon. Ina-update ng `omarchy update` ang mga naka-install na agent kasama ang iba pang bahagi ng Omarchy, at ina-update naman ng `mup` ang mga tool na pinamamahalaan ng mise lamang.

Hindi ina-update ng sariling updater ng isang agent, gaya ng `claude update`, `codex update`, o isang update button sa isang app, ang install na pinamamahalaan ng mise. Nabibigo ang `codex update`, at maaaring mag-ulat ng tagumpay ang `claude update` habang nag-i-install ng isang hiwalay na kopya na hindi sinusubaybayan ng mise. Kung mas gusto mong gamitin ang native installer at updater ng isang agent, idagdag ito sa `disable_tools`; tingnan ang [Mga paunang naka-install na tool ng CLI](18-development-tools.md#preinstalled-cli-tools).

Para i-install ang lahat ng naka-configure na lazy tool bago mo kailanganin ang mga ito, patakbuhin ang `mise install --include-lazy`. Kasama rito ang iba pang mga default na CLI tool ng Omarchy pati na rin ang mga agent. Tingnan ang [Mga paunang naka-install na tool ng CLI](18-development-tools.md#preinstalled-cli-tools) para sa pag-install ng isang tool o paggamit ng sarili mong installation.

Ini-install ang `grok` sa pamamagitan ng first-party na `grok` package ng mise, sa parehong paraan tulad ng `claude` at `codex`. Patakbuhin ang `grok`, o piliin ito sa ilalim ng _Setup > Defaults > Agent_. Laktawan ang `curl | bash` installer sa x.ai. Naglalagay ang paraang iyon ng pangalawang kopya sa `~/.grok/bin`, inuuna ito sa `PATH`, at pinapalitan ang wrapper ng Omarchy.

Binubuksan ng `dsh` ang browser UI nito sa `127.0.0.1:3080`, na ang launch directory ang default nitong workspace. Walang kinukuhang panimulang prompt ang browser UI nito, kaya binubuksan ito ng `omarchy agent prompt` na nasa clipboard mo ang prompt para i-paste. Sinisimulan ito ng Omarchy gamit ang no-approval permission preset ng DeepSeek. Nag-a-upload ang DeepSeek Harness ng mga session log sa DeepSeek kapag ginagamit mo ang opisyal nitong model API; i-off iyon sa ilalim ng _Settings > General > Upload Session Log_ sa browser UI nito. Ang feedback na ipinapadala mo rito ay ina-upload din kasama ng session, maliban kung sisimulan mo ito gamit ang `DSH_TELEMETRY_MODE=DISABLED`.

### Ang default na agent

Piliin ang iyong default na agent gamit ang `omarchy default agent <name>` o sa ilalim ng _Setup > Defaults > Agent_ sa Omarchy Menu (`Super + Space`). Kung hindi pa naka-install ang agent, ang pagpili dito ay mag-i-install muna dito. Aanyayahan ka ng isang bagong Omarchy na gawin ang pagpipiliang ito gamit ang isang beses na notification.

Sinusubukan din ng pagpili sa Claude na i-set up ang browser extension nito para sa Chromium, Chrome, Brave, Brave Origin, at Edge. Nalalapat ang setup ng extension sa lahat ng user at maaaring humingi ng iyong system password; pipiliin at ilulunsad pa rin ang Claude kahit kanselahin o mabigo ang pag-install ng extension. I-restart ang iyong browser, i-enable ang extension kung sinabihan, at mag-sign in sa Claude para tapusin ang pagkonekta dito. Patakbuhin ang `/chrome` sa Claude para tingnan ang koneksyon. Hindi sinusuportahan ng Firefox at Zen ang extension na ito. Kung Claude na ang iyong default bago pa idinagdag ang setup na ito, piliin itong muli para i-install ang extension.

Kapag nakapili ka na, ilulunsad ng `Super + Shift + Ctrl + A` ang default na agent sa isang nakalaang terminal window (o ilalabas ang picker kung hindi ka pa nakakapili). Maaari mo rin itong ilunsad diretso sa isang gawain gamit ang `omarchy agent prompt "Review this project"`. Walang kinukuhang panimulang prompt ang Freebuff at DeepSeek Harness, kaya sa halip ay bubukas ang mga ito na nasa clipboard mo ang prompt para i-paste. Ang mga agent na inilunsad sa ganitong paraan ay tumatakbo nang walang bantay sa kani-kanilang don't-stop-to-ask mode, kaya maging handa na talagang gumawa sila ng mga bagay! Walang ganoong mode ang MiniMax Code para sa mga interactive session nito, kaya humihingi ito ng mga pahintulot gaya ng dati. At dahil tumatanggi ang mga agent na tandaan ang tiwala para sa iyong home directory, ang mga paglulunsad mula sa `$HOME` ay nagsisimula sa halip sa `~/Work`.

May mga terminal shortcut din: pinapatakbo ng `a` ang default na agent nang inline sa kasalukuyang terminal, habang sinisimulan naman ng `c`, `cx`, at `cy` ang OpenCode, Claude Code, at Codex nang direkta (muli sa kanilang mga auto-approving mode). Nagsi-sync din ang mga pagbabago ng tema sa mga agent: sumusunod ang Claude Code, Pi, OpenCode, at Hermes (kapag na-install na ito ng Omarchy) kapag nagpapalit ka ng tema ng Omarchy.

### Ang panel ng mga agent

May icon ng mga agent ang top bar. Bago ka pa nakapag-set up ng isang agent, gagabayan ka ng panel nito sa pag-sign in sa Claude, Codex, o Grok, at ang una ay magiging iyong default na agent. Pagkatapos niyon, inilalagay ng panel ang bawat subscription sa isang pahina: bawat agent at account kasama ang plano nito, isang metro para sa bawat isa sa 5-hour session at weekly limit nito kasama ang oras hanggang mag-reset ito (mag-hover para sa eksaktong porsiyento), o ang natitirang prepaid balance, sa ilalim ng isang linya na umiikot sa kung ano ang nagamit mo sa lahat ng mga ito, tulad ng mga token ngayong linggo at ang pinakaginagamit mong modelo. Sa ilalim ng _Make something_ nag-aalok ito ng mga starter prompt para sa isang bagong tema, plugin, o app na nagbibigay ng gawain sa iyong default na agent. Ginagawa ang mga app sa paraang ginawa ang sariling Hype, Monologue, at Omacut ng Omarchy, sa C++ at Qt Quick, na sumusunod sa omarchy-app agent skill, at naka-install na ang compiler at mga piraso ng Qt na kailangan nila. Saklaw agad ang Claude Code, Codex, Grok, Kimi, Cursor at ang Grok Bot allowance nito, GitHub Copilot, Muse, Antigravity, Kimchi, at Devin kasama ang kanilang mga limit, at ipinapakita ng Hermes, Mistral Vibe, at Qwen Code ang kanilang mga session at token kapag nagamit mo na sila. Lumalabas din ang mga provider plan at key na ginagamit mo sa pamamagitan ng pi, omp, o opencode: OpenCode Zen at Go, ang Z.ai GLM Coding Plan, Ollama Cloud, ang MiniMax Token Plan, at Synthetic kasama ang kanilang mga limit; Fireworks, OpenRouter, at DeepSeek kasama ang kanilang mga prepaid balance; at ang mga modelong pinapatakbo mo sa sarili mong hardware sa ilalim ng Local models. Bawat agent ay binibilang nang isang beses, sa ilalim ng kung sino ang naniningil para dito, gaano man karaming harness mo ito pinagana.

I-left-click ang icon sa bar para sa panel, i-right-click para ilunsad ang iyong default na agent. Ang mga usage record sa likod nito ay muling ginagawa bawat 15 minuto ng `omarchy agent usage-update`, at maaari pang pagsamahin ng panel ang usage mula sa iba mo pang mga machine sa pamamagitan ng isang naka-sync na folder. Tingnan ang README sa ilalim ng `$OMARCHY_PATH/shell/plugins/agents/` para sa buong settings.

### Maraming subscription

Kung nagbabayad ka para sa higit sa isang plano ng Claude, Codex, o Grok — isang personal na Max at isang para sa trabaho, halimbawa — maaaring panatilihin ng Omarchy ang lahat ng mga ito na naka-sign in at lumipat sa pagitan nila. Magdagdag ng subscription gamit ang + sa panel ng mga agent, na gagabay sa iyo mismo roon, o gamit ang `omarchy agent account add claude Work` (o `codex`, o `grok`). Ini-install nito ang CLI kung nawawala ito. Ang unang account para sa isang provider ay nag-sa-sign in sa pamamagitan ng iyong normal na browser, mismo kung saan laging tumitingin ang CLI. Ang bawat susunod ay nag-sa-sign in sa pamamagitan ng isang private window, kaya ang account na naka-sign in na sa iyong browser ay hindi aksidenteng makukuha; mag-sign in doon bilang ang account na idinaragdag mo, at isara muna ang anumang private window na nakabukas mo na. Huwag kailanman mag-log out sa CLI para gawin ito: kinakansela ng pag-log out ang naka-save na sign-in, at kakailanganing idagdag muli ang account na iyon.

Para kopyahin ang iyong mga subscription login sa isa pang Omarchy machine sa pamamagitan ng SSH, patakbuhin ang `omarchy agent account copy user@laptop`. Nagbibigay ang sender ng isang pansamantalang receiver kapag walang naka-install ang destination, kaya makakatanggap ng mga account ang mga mas lumang Omarchy machine nang walang update. Inuuna ang mga naka-install na receiver. Kinokopya nito ang lahat ng subscription ng Claude, Codex, at Grok; magdagdag ng mga pangalan ng provider para piliin sila, gaya ng sa `omarchy agent account copy laptop claude`. Tumutugma ang mga pangalan ng account at command ID sa source, kasama ang mga account na naroroon na sa destination. Tumatanggap ng numeric suffix ang mga hindi kaugnay na destination account kung magkasalungat ang kanilang mga pangalan, at nananatiling lokal sa bawat machine ang settings, skills, plugins, at conversation history.

Pinapanatili ang mga umiiral nang credential sa destination. Ang isang source account na naka-sign in na doon ay sini-sync ang pangalan nito nang hindi pinapalitan ang mga credential nito; idinaragdag ang iba pang mga account sa tabi nito. Para palitan ang mga naka-save na credential para sa mga tumutugmang account, gamitin ang `omarchy agent account copy --replace laptop claude` pagkatapos isara ang mga session ng account na iyon sa destination. Tumatanggap din ang isang bagong destination ng active account at switching preferences ng source; pinapanatili naman ng isang matagal nang destination ang sarili nito.

Naglalakbay ang mga credential sa pamamagitan ng SSH at nakaimbak sa mga private file sa destination, kaya kumopya lamang sa mga machine na pinagkakatiwalaan mo. Ito ay isang beses na pagkopya, hindi patuloy na synchronization. Maaaring i-rotate ng ibang machine ang mga Codex refresh token, na nag-iiwan sa isang nakopyang login na nangangailangan ng pag-renew; ang magkahiwalay na pag-sign in ang nananatiling pinaka-maaasahang pagpipilian para sa sabay-sabay na paggamit sa maraming machine. Tingnan ang [gabay ng Codex sa authentication ng account](https://developers.openai.com/codex/auth/ci-cd-auth).

Isang account bawat provider ang active, at bawat bagong session ay nagsisimula bilang ito: `cx`, `cy`, isang simpleng `claude`, `codex`, o `grok`, anumang inilunsad sa pamamagitan ng `omarchy agent`, at mga script o editor na nakakahanap sa CLI sa `PATH`. Lumipat gamit ang `omarchy agent account use work` (at bumalik gamit ang `omarchy agent account use main`), o sa panel sa pamamagitan ng pagpindot sa numero ng isang account at pagkatapos ay `Enter` (o pag-click sa Use button nito). Ang mga session na tumatakbo na ay nananatili sa account na pinagsimulan nila. Ibinabahagi ang conversation history, settings, skills, at plugins sa pagitan ng mga account, kaya ang `claude --continue` sa parehong folder ay nagpapatuloy kung saan ka huminto sa bagong account.

Sa higit sa isang account, ipinapakita ng panel ang mga limit ng bawat account nang magkatabi, na minarkahan ang active. Bilang default, aabisuhan ka ng Omarchy kapag lumampas ang active account sa 95% ng isang limit, at ang pag-click sa notification ay lumilipat sa account na may pinakamaraming headroom. Mag-hover sa linya ng isang account sa panel at i-click ang Autoswitch na lalabas sa tabi ng Use (o pindutin ang `m`), o patakbuhin ang `omarchy agent account mode auto`, para ito na mismo ang lumipat; habang naka-on ito, pumapalit ang Autoswitch sa Use, at ang pag-click muli dito ay bumabalik sa pag-abiso. Magdagdag ng numero para baguhin ang threshold, gaya ng sa `omarchy agent account mode auto 90`. Kung ang bawat account ay lagpas na sa threshold, maririnig mo ito nang isang beses, kasama kung aling account ang unang magkakaroon ng puwang. Habang ang isang active account ay nasa loob ng 15 puntos ng threshold nito (80% sa default), sinusuri ang mga limit nito bawat tatlong minuto sa halip na bawat 15.

Ipinapakita ng `omarchy agent account list` ang bawat account at ang pinakabagong mga limit nito, kinakalimutan ng `omarchy agent account remove work` ang isa, at pinapalitan ng pangalan ng `omarchy agent account rename primary Hey` ang isa (o i-click ang pangalan ng isang account sa panel). Gumagana ang mga utos na ito sa mga account ng iyong default na agent; para maabot ang ibang provider, pangalanan muna ito, gaya ng sa `omarchy agent account use codex side`. Ang login na mayroon ka na sa `~/.claude` o `~/.codex` ay ang _Main_ account at nananatili kung nasaan ito. Ang isang account na hindi nagamit nang mahigit sa walong oras o higit pa ay maaaring magpakita ng _Sign-in required_; i-click ito para muling i-sign in ang account na iyon mismo sa panel, o magsimula ng session dito, na nagre-refresh ng sign-in nang kusa. Ang mga MCP server na mayroon ka noong idinagdag ang isang account ay sumasama dito, pero ang mga idinaragdag mo mamaya gamit ang `claude mcp add` ay umaabot lamang sa account kung saan mo sila idinagdag. Hindi sumusunod sa paglipat ang Claude Desktop at mga tool na naka-configure na may absolute path patungo sa isang CLI binary. Inuuna ang isang tahasang `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, o `GROK_HOME` kaysa sa napiling account.

### Pag-diagnose ng crash

Binabantayan ng Omarchy ang systemd-coredump para sa mga pag-crash ng process. Kapag may nag-segfault, makakakuha ka ng notification na "Process crashed" — i-click ito, at ibibigay ang crash sa iyong default na agent kasama ang diagnose-crash skill ng Omarchy, na gagabay sa agent sa pagtatatag ng mga katotohanan mula sa core dump at pagpapasya kung sulit bang i-report ang crash sa upstream. Maaari mo rin itong patakbuhin nang manu-mano laban sa anumang PID mula sa `coredumpctl list` gamit ang `omarchy agent crash <pid>`.

Naka-on ang pagbabantay bilang default. I-off ito sa ilalim ng _Trigger > Toggle > Crash Capture_ (o gamit ang `omarchy toggle crash-capture`) at hihinto ang mga notification; gumagana pa rin nang manu-mano ang `omarchy agent crash <pid>`.

Maaari ding patahimikin ang mga crash nang isa-isa bawat programa, na siyang iniaalok sa iyo ng diagnosis sa huli. Pinahihinto ng `omarchy crash mute hyprland` ang mga notification para sa programang iyon lamang, ibinabalik sila ng `omarchy crash mute hyprland off`, at inililista naman ng `omarchy crash mute` nang mag-isa kung ano ang na-mute mo. Tinatanggap nito ang path ng binary nang kasing saya ng pangalan nito, kaya pareho ang ginagawa ng `omarchy crash mute /usr/bin/hyprland`. Mag-quote ng pangalan na may space, gaya ng sa `omarchy crash mute 'Some App'`. Nag-aabiso pa rin ang lahat ng iba pa, at nagka-crash pa rin ang naka-mute na programa — itinatago nito ang paalala, hindi nito inaayos ang anuman.

### Mga desktop app

May dala rin ang _Install > AI_ menu na ilang graphical AI app: ang ChatGPT desktop app, ang Claude desktop app (ang Linux beta ng Anthropic, na may mga tab na Chat, Cowork, at Claude Code), Grok Bot para makipag-chat sa mga modelo ng xAI, Hermes Desktop, OpenClaw, ang Perplexity desktop app, at T3 Code. Ang Grok Bot ay ang desktop chat app. Ang coding agent ay ang `grok` command.

Ang Hermes Desktop ang dapat mong malaman, dahil ang isang machine ay may isang Hermes, at pag-aari ito ng app: ini-install lamang ang Hermes sa pamamagitan ng app kailanman, at ang `hermes` command na pinapatakbo ng default na agent ay pag-aari ng app. Ang pagpili sa Hermes bilang default na agent ay nag-i-install ng parehong bagay na ginagawa ng _Install > AI_ entry: ang package, at isang Hermes runtime sa ilalim ng `~/.hermes` na sine-set up ng sariling installer ng Hermes, na tumatagal ng ilang minuto sa unang pagkakataon. Ang runtime na iyon ang nag-iisang Hermes na ginagamit ng terminal `hermes` command, ng default na agent at ng app, at ina-update nito ang sarili gamit ang `hermes update` sa halip na maghintay ng isang Omarchy release. Sa pag-install dito, ibinibigay din nito kay Hermes ang tema ng Omarchy bilang isang skin na pinangalanang `omarchy`, na sinusunod ng bawat Hermes surface habang nagpapalit ka ng mga tema; pumili ng iba sa ilalim ng Appearance settings ng Hermes o gamit ang `/skin` kung mas gugustuhin mong hindi ganoon, at hindi pakikialaman ng Omarchy ang pagpipiliang iyon. Ang pag-alis ng app sa ilalim ng _Remove > AI_ ay nagsasara muna ng Hermes, kasama ang gateway, dinadala ang runtime na iyon kasama nito, at pinapanatili ang iyong mga chat, memory, at ang mga skill na isinulat ng Hermes para sa sarili nito maliban kung sasabihin mong hindi: nagtatanong ito, na ang default ay hindi, kung dapat ding alisin ang data na iyon at ang iyong connection settings.

Ang desktop experience ng OpenClaw ay ang Control UI nito, na bubukas bilang isang web app na sinusuportahan ng sarili nitong local gateway. Nakatira ang OpenClaw sa `~/.openclaw` at ina-update ang sarili nito: gamitin ang "Update Gateway" button ng Control UI o patakbuhin ang `openclaw update`, at magre-restart ang gateway sa bagong bersyon. Pinipili lamang ng Omarchy ang release na pagsisimulan ng isang bagong install. Ang pag-alis ng OpenClaw sa ilalim ng _Remove > AI_ ay dinadala ang gateway service at ang app kasama nito at pagkatapos ay nagtatanong kung dapat ding alisin ang `~/.openclaw`, dahil naroroon ang iyong mga chat at credential kasama ang OpenClaw mismo at ang mga plugin runtime na dina-download nito; pinapanatili ito ng default, at ang muling pag-install ng OpenClaw ay kukunin itong muli.

Tumatakbo ang T3 Code mula sa opisyal nitong AppImage release sa `~/.local/share/t3code` sa halip na mula sa isang package, kaya ina-update nito ang sarili nito. Nagtatanong ang pag-install dito kung magsisimula sa Stable o Nightly channel; lumipat mamaya sa settings ng T3 Code. Nakatira ang iyong mga thread at setting sa `~/.t3`, at ang pag-alis ng T3 Code sa ilalim ng _Remove > AI_ ay dinadala sila kasama nito.

### Mga lokal na modelo

Magpatakbo ng isang open model sa sarili mong machine para sa iyong mga coding agent. Nananatili sa machine ang iyong mga prompt at code; walang ipinapadala sa modelo ang umaalis dito. Magsimula sa:

```bash
omarchy agent local use best
```

O, sa panel ng mga agent sa top bar, piliin ang + at pagkatapos ay Local AI, na lumalabas kapag kasya ang isang modelo sa machine na ito. Sa unang pagkakataon, ini-install nito ang Podman, na nagpapatakbo ng mga modelo, at sa isang NVIDIA machine ang container toolkit ng NVIDIA, na nagbibigay sa kanila ng GPU. Pagkatapos ay pipiliin ng Omarchy ang inirerekomendang modelo para sa machine na ito, ida-download ito, at sisimulan ito. Asahan ang isang download na sampu-sampung GB at ang karamihan ng memory ng machine ay ginagamit habang tumatakbo ang modelo: gumagamit ang Flash Next ng humigit-kumulang 100 GiB sa buong 256K context nito. Kung hawak ng ibang mga modelo ang memory na kailangan nito, sine-set up itong nakahinto, handang magsimula kapag pinahinto mo ang isa. Humihinto ang modelo sa pag-logout; pahintuin mo ito mismo kapag kailangan mo ang memory para sa ibang bagay.

Ipinapakita ng `omarchy agent local list` ang mga opsyon at ipinapaliwanag kung bakit hindi kasya ang ilan. Para mag-set up ng isa pa, patakbuhin ang `omarchy agent local use <recipe>`. Ngayon, available ang `qwen3.8-flash-next-gufo` at `qwen3.8-27b-gufo` para sa mga 128 GB Strix Halo machine; gumagamit ang 27B ng humigit-kumulang 40 GiB, kaya nag-iiwan ito ng puwang para sa iba pang trabaho. Dumarating ang mga bagong recipe at rekomendasyon kasama ang `omarchy update`, sa pamamagitan ng package.

Bawat modelong sine-set up mo ay may sariling linya sa panel ng mga agent, sa tabi ng iyong mga subscription: play para simulan ito, pause para pahintuin ito at palayain ang memory nito, at ang terminal button para buksan ang iyong agent dito. Marami ang maaaring tumakbo nang sabay kapag kasya sila sa memory nang magkasama; kung hindi kasya ang isa, sasabihin ng Omarchy kung aling tumatakbong modelo ang pahihintuin. I-drag ang mga linya para muling ayusin sila, at pindutin ang Delete sa isang napiling linya para alisin ang isang modelo at ang download nito.

Mula sa command line, pareho ang ginagawa ng `omarchy agent local start <recipe>` at `omarchy agent local stop <recipe>`, ipinapakita ng `omarchy agent local status` ang bawat modelo, at binubuksan ng `omarchy agent --local` ang iyong default na agent sa huling modelong sinimulan mo (pi kung hindi magamit ng iyong default na agent ang isang local model). Maaari ding kumonekta ang anumang OpenAI-compatible client: ipinapakita ng `status` ang address ng bawat modelo (ang una ay `http://127.0.0.1:11435/v1`), ang pangalan ng recipe ang modelo, at ang key ay nasa `~/.config/omarchy/agent-local/key`.

Tinatanggal ng `omarchy agent local remove <recipe>` ang isang modelo at ang mga download na hindi ginagamit ng ibang modelo.

May label ang mga third-party runtime ng kanilang publisher. Pinapatakbo ng Omarchy ang bawat modelo nang walang network access.

### Mga lokal na LLM

Inirerekomenda ng Omarchy ang dalawang paraan ng pagpapatakbo ng mga lokal na LLM model: LM Studio at Ollama. Nagbibigay ang LM Studio ng isang GUI interface para sa paghahanap ng mga open-weight model, pag-install sa kanila, at pagpapatakbo sa kanila. Mahusay itong paraan para madaling makapagsimula. Nag-aalok ang Ollama ng isang CLI para gawin ito nang katulad. Pero kung bago ka sa mga lokal na modelo, magsisimula ako sa LM Studio. Maaari mong i-install ang alinman sa ilalim ng _Install > AI_ sa Omarchy Menu.

### Ang Omarchy Skill

Tinutulungan ng mga agent skill ang AI na gumamit ng mga partikular na tool sa isang partikular na paraan, at may kasamang default skill ang Omarchy para sa pagsasaayos ng system. Tulad ng pag-tweak ng iyong Hyprland config, pag-aayos ng bar, o kahit paglikha ng isang bagong tema mula sa wala. Naka-symlink ito sa mga skill directory para sa Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` at bawat `~/.hermes/profiles/*/skills`), at ang generic na lokasyong `~/.agents/skills`, kaya karamihan ng mga harness ay awtomatikong nakukuha ito.

Pero dapat mong ituring na experimental ang skill na ito. Iba't ibang modelo ang gagamit dito na may iba't ibang epekto. Pinakamainam na tumakbo muna sa plan mode, para magkaroon ka ng ideya kung ano ang gustong baguhin ng agent. At pagkatapos ay maging handang i-rollback ang mga pagbabago o kahit tawagin ang `omarchy reinstall configs`, kung guluhin ng agent ang lahat.
