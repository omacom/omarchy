# AI

Kasama sa Omarchy ang mga launcher para sa mga coding agent sa ibaba nang hindi pumipili ng default para sa iyo. Patakbuhin ang isang command para mai-install ang CLI nito sa unang paggamit, pagkatapos ay mag-authenticate kapag sinabihan. Ang Hermes ang eksepsiyon: walang ini-install para dito sa unang paggamit, at ang pagpili dito ay nag-i-install ng Hermes Desktop, gaya ng ipinaliliwanag ng _Desktop apps_ sa ibaba.

### Pag-install at pag-update ng mga agent

Maliban sa Hermes, ginagamit ng mga agent na ito ang lazy installation ng mise: ang unang paglulunsad ang nag-i-install ng CLI, at muling ginagamit ito ng mga susunod na paglulunsad. Sinusuri rin ng mise ang isang naka-install na agent para sa bagong release nang hindi hihigit sa isang beses kada apat na oras, bago ito magsimula o sa background sa isang shell prompt. Kung mabigo ang update na iyon o offline ka, tatakbo ang naka-install na bersyon. Ina-update ng `omarchy update` ang mga naka-install na agent kasama ang iba pang bahagi ng Omarchy, at ina-update ng `mup` ang mga tool na pinamamahalaan ng mise lamang.

Ang sariling updater ng isang agent, tulad ng `claude update`, `codex update`, o isang update button sa isang app, ay hindi nag-a-update ng install na pinamamahalaan ng mise. Nabibigo ang `codex update`, at maaaring mag-ulat ng tagumpay ang `claude update` habang nag-i-install ng hiwalay na kopya na hindi sinusubaybayan ng mise. Kung mas gusto mong gamitin ang native installer at updater ng isang agent, idagdag ito sa `disable_tools`; tingnan ang [Preinstalled CLI tools](18-development-tools.md#preinstalled-cli-tools).

Para mai-install ang lahat ng naka-configure na lazy tool bago mo kailanganin ang mga ito, patakbuhin ang `mise install --include-lazy`. Kasama rito ang iba pang default CLI tool ng Omarchy pati ang mga agent. Tingnan ang [Preinstalled CLI tools](18-development-tools.md#preinstalled-cli-tools) para sa pag-install ng isang tool o paggamit ng sarili mong installation.

Ini-install ang `grok` sa pamamagitan ng first-party `grok` package ng mise, sa parehong paraan ng `claude` at `codex`. Patakbuhin ang `grok`, o piliin ito sa ilalim ng _Agent > Harness_. Laktawan ang installer na `curl | bash` sa x.ai. Ang landas na iyon ay naglalagay ng pangalawang kopya sa `~/.grok/bin`, inuuna ito sa `PATH`, at pinapalitan ang wrapper ng Omarchy.

Binubuksan ng `dsh` ang browser UI nito sa `127.0.0.1:3080`, na ang launch directory ang default workspace nito. Ang browser UI nito ay hindi tumatanggap ng panimulang prompt, kaya binubuksan ito ng `omarchy agent prompt` na nasa iyong clipboard ang prompt para i-paste. Sinisimulan ito ng Omarchy gamit ang no-approval permission preset ng DeepSeek. Nag-a-upload ang DeepSeek Harness ng mga session log sa DeepSeek kapag ginagamit mo ang opisyal nitong model API; i-off iyon sa ilalim ng _Settings > General > Upload Session Log_ sa browser UI nito. Ang feedback na ipinapadala mo dito ay ina-upload din kasama ng session, maliban kung sisimulan mo ito gamit ang `DSH_TELEMETRY_MODE=DISABLED`.

### Ang default na agent

Piliin ang iyong default na agent gamit ang `omarchy default agent <name>` o sa ilalim ng _Agent > Harness_ sa Omarchy Menu (`Super + Space`). Kung hindi pa naka-install ang agent, ang pagpili dito ay mag-i-install muna nito. Aanyayahan ka ng isang bagong Omarchy na gawin ang pagpipiliang ito gamit ang isang one-time na notification.

Ang pagpili sa Claude ay sumusubok ding i-set up ang browser extension nito para sa Chromium, Chrome, Brave, Brave Origin, at Edge. Ang pag-setup ng extension ay nalalapat sa lahat ng user at maaaring humingi ng iyong system password; ang pagkansela o ang nabigong pag-install ng extension ay pipili at maglulunsad pa rin kay Claude. I-restart ang iyong browser, i-enable ang extension kung sinabihan, at mag-sign in sa Claude para matapos ang pagkonekta nito. Patakbuhin ang `/chrome` sa Claude para masuri ang koneksyon. Hindi sinusuportahan ng Firefox at Zen ang extension na ito. Kung Claude na ang iyong default bago pa idinagdag ang setup na ito, piliin ito ulit para mai-install ang extension.

Kapag nakapili ka na, ilulunsad ng `Super + Shift + Ctrl + A` ang default na agent sa isang nakalaang terminal window (o ilalabas ang picker kung hindi ka pa nakakapili). Maaari mo rin itong ilunsad nang diretso sa isang gawain gamit ang `omarchy agent prompt "Review this project"`. Ang Freebuff at DeepSeek Harness ay hindi tumatanggap ng panimulang prompt, kaya sa halip ay bubukas ang mga ito na nasa iyong clipboard ang prompt para i-paste. Ang mga agent na inilunsad sa ganitong paraan ay tumatakbo nang walang nagbabantay sa kani-kanilang don't-stop-to-ask mode, kaya maghanda kang may gagawin talaga sila! Ang MiniMax Code ay walang ganoong mode para sa mga interactive session nito, kaya humihingi ito ng mga pahintulot gaya ng dati. At dahil tumatanggi ang mga agent na tandaan ang trust para sa iyong home directory, ang mga paglulunsad mula sa `$HOME` ay sa halip nagsisimula sa `~/Work`.

May mga terminal shortcut din: pinapatakbo ng `a` ang default na agent nang inline sa kasalukuyang terminal, habang sinisimulan ng `c`, `cx`, at `cy` ang OpenCode, Claude Code, at Codex nang direkta (muli sa kani-kanilang auto-approving mode). Sumasabay din ang mga pagbabago ng tema sa mga agent: ang Claude Code, Pi, OpenCode, at Hermes (kapag na-install na ito ng Omarchy) ay pawang sumusunod kapag nagpalit ka ng tema ng Omarchy.

### Ang iyong mga tagubilin sa agent

Ang mga personal na panuntunan para sa bawat agent ay nasa `~/.agents/AGENTS.md`, katabi ng mga shared skill sa `~/.agents/skills`. Buksan ito sa ilalim ng _Agent > Instructions_, na nagli-link din nito sa bawat harness na nag-iingat ng sarili nitong global file: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, ang `~/.copilot/copilot-instructions.md` ng Copilot, at iba pa. Binabasa ng Crush at Amp ang link na `~/.config/AGENTS.md`, habang direktang binabasa ng omp, Kimi, at DeepSeek Harness ang `~/.agents/AGENTS.md`. Ang pagpili ng default na agent ay nagli-link din nito. Ang isang instructions file na mayroon ka na ay nagiging shared na file kung wala pa noon; kung hindi, mananatili ito katabi ng link bilang `.bak`. Patakbuhin ang `omarchy agent instructions` para muling i-link pagkatapos mag-install ng isa pang agent.

### Ang panel ng mga agent

Ang top bar ay may icon ng mga agent. Bago ka pa nakapag-set up ng agent, gagabayan ka ng panel nito sa pag-sign in sa Claude, Codex, o Grok, at ang una ay magiging iyong default na agent. Pagkatapos niyon, inilalagay ng panel ang bawat subscription sa isang page: bawat agent at account kasama ang plan nito, isang meter para sa bawat 5-hour session at weekly limit nito kasama ang oras hanggang sa mag-reset ito (i-hover para sa eksaktong porsiyento), o ang natitirang prepaid balance, sa ilalim ng isang linya na umiikot sa kung ano na ang nagamit mo sa lahat ng mga ito, tulad ng mga token sa linggong ito at ang pinakamadalas mong gamiting modelo. Sa ilalim ng _Make something_ nag-aalok ito ng mga starter prompt para sa isang bagong tema, plugin, app, o laro na nagbibigay ng gawain sa iyong default na agent. Ang mga app ay binubuo sa paraang binuo ang sariling Hype, Monologue, at Omacut ng Omarchy, sa C++ at Qt Quick, na sumusunod sa omarchy-app agent skill, at ang compiler at mga piraso ng Qt na kailangan nila ay naka-install na. Ang mga laro ay isang solong three.js page sa `~/Games/vibes`, na sumusunod sa web-game agent skill, at lahat ay bubukas mula sa isang Game Vibes launcher sa kasalukuyang tema; nilo-load nila ang three.js mula sa web, kaya kailangan nila ng koneksyon para magsimula. Ang Claude Code, Codex, Grok, Kimi, Cursor at ang Grok Bot allowance nito, GitHub Copilot, Muse, Antigravity, Kimchi, at Devin ay saklaw na agad kasama ang kanilang mga limit, at ipinapakita ng Hermes, Mistral Vibe, at Qwen Code ang kanilang mga session at token kapag nagamit mo na ang mga ito. Ipinapakita rin ang mga provider plan at key na ginagamit mo sa pamamagitan ng pi, omp, o opencode: ang OpenCode Zen at Go, ang Z.ai GLM Coding Plan, Ollama Cloud, ang MiniMax Token Plan, at Synthetic kasama ang kanilang mga limit; ang Fireworks, OpenRouter, at DeepSeek kasama ang kanilang mga prepaid balance; at ang mga modelong pinapatakbo mo sa sarili mong hardware sa ilalim ng Local models. Bawat agent ay binibilang nang isang beses lamang, sa ilalim ng sinumang naniningil para dito, gaano man karaming harness ang patakbuhin mo dito.

I-left-click ang icon sa bar para sa panel, i-right-click para ilunsad ang iyong default na agent. Ang mga usage record sa likod nito ay muling ginagawa kada 15 minuto ng `omarchy agent usage-update`, at maaari pang pagsamahin ng panel ang usage mula sa iba mo pang machine sa pamamagitan ng isang naka-sync na folder. Tingnan ang README sa ilalim ng `$OMARCHY_PATH/shell/plugins/agents/` para sa buong mga setting.

### Maraming subscription

Kung nagbabayad ka para sa higit sa isang plan ng Claude, Codex, o Grok — isang personal na Max at isa para sa trabaho, halimbawa — maaaring panatilihin ng Omarchy ang lahat ng mga ito na naka-sign in at lumipat sa pagitan ng mga ito. Magdagdag ng subscription gamit ang + sa panel ng mga agent, na gagabay sa iyo roon mismo, o gamit ang `omarchy agent account add claude Work` (o `codex`, o `grok`). Ini-install nito ang CLI kung nawawala ito. Ang unang account para sa isang provider ay nagsa-sign in sa pamamagitan ng iyong normal na browser, roon mismo kung saan laging tumitingin ang CLI. Bawat isa pagkatapos niyon ay nagsa-sign in sa pamamagitan ng isang private window, kaya ang account na naka-sign in na ang iyong browser ay hindi aksidenteng makukuha; mag-sign in doon bilang account na idinaragdag mo, at isara muna ang anumang private window na nakabukas mo na. Huwag kailanman mag-log out sa CLI para gawin ito: ang pag-log out ay binabawi ang naka-save na sign-in, at ang account na iyon ay kailangang idagdag ulit.

Para kopyahin ang iyong mga subscription login sa isa pang Omarchy machine sa pamamagitan ng SSH, patakbuhin ang `omarchy agent account copy user@laptop`. Ang nagpadala ay nagbibigay ng pansamantalang receiver kapag ang destinasyon ay walang naka-install, kaya ang mas lumang mga Omarchy machine ay makakatanggap ng mga account nang walang update. Ang mga naka-install na receiver ang nangunguna. Kinokopya nito ang lahat ng subscription ng Claude, Codex, at Grok; magdagdag ng mga pangalan ng provider para piliin ang mga ito, gaya sa `omarchy agent account copy laptop claude`. Ang mga pangalan ng account at command ID ay tumutugma sa pinagmulan, kabilang ang mga account na mayroon na sa destinasyon. Ang mga hindi magkaugnay na account sa destinasyon ay tumatanggap ng numeric suffix kung magkasalungat ang kanilang mga pangalan, at ang mga setting, skill, plugin, at history ng pag-uusap ay nananatiling lokal sa bawat machine.

Ang mga umiiral na credential sa destinasyon ay pinapanatili. Ang isang source account na naka-sign in na roon ay pinagsasabay ang pangalan nito nang hindi pinapalitan ang mga credential nito; ang ibang mga account ay idinaragdag katabi nito. Para palitan ang mga naka-save na credential para sa mga tumutugmang account, gamitin ang `omarchy agent account copy --replace laptop claude` pagkatapos isara ang mga session ng account na iyon sa destinasyon. Ang isang bagong destinasyon ay nakakakuha rin ng active account at mga switching preference ng pinagmulan; ang isang naitatag nang destinasyon ay pinapanatili ang sarili nito.

Ang mga credential ay naglalakbay sa pamamagitan ng SSH at nakaimbak sa mga private file sa destinasyon, kaya kumopya lamang sa mga machine na pinagkakatiwalaan mo. Ito ay isang one-time na kopya, hindi patuloy na synchronization. Ang mga Codex refresh token ay maaaring i-rotate ng isa pang machine, na nag-iiwan sa isang nakopyang login na nangangailangan ng renewal; ang magkakahiwalay na sign-in ang nananatiling pinaka-maaasahang pagpipilian para sa sabay-sabay na paggamit sa maraming machine. Tingnan ang [gabay ng Codex sa authentication ng account](https://developers.openai.com/codex/auth/ci-cd-auth).

Isang account bawat provider ang active, at bawat bagong session ay nagsisimula bilang ito: `cx`, `cy`, isang payak na `claude`, `codex`, o `grok`, anumang inilunsad sa pamamagitan ng `omarchy agent`, at mga script o editor na nakakahanap ng CLI sa `PATH`. Lumipat gamit ang `omarchy agent account use work` (at bumalik gamit ang `omarchy agent account use main`), o sa panel sa pamamagitan ng pagpindot sa numero ng isang account at pagkatapos ay `Enter` (o pag-click sa Use button nito). Ang mga tumatakbong Claude session ay lumilipat din, mula sa kanilang susunod na mensahe: bawat Claude session ay tumatakbo sa `~/.claude`, na palaging naglalaman ng sign-in ng active account. Ang isang Claude session na sinimulan sa sariling folder ng isang account ng isang mas lumang Omarchy ay naglalaman ng sign-in na iyon hanggang sa ito ay huminto, kaya pinapangalanan ng switch ang mga session na iyon at natatapos nang kusa kapag wala na ang mga ito. Ang mga tumatakbong Codex at Grok session ay nananatili sa account na sinimulan nila. Ang history ng pag-uusap, mga setting, skill, at plugin ay ibinabahagi sa lahat ng account, kaya ang `claude --continue` sa parehong folder ay nagpapatuloy kung saan ka tumigil sa bagong account.

Sa higit sa isang account, ipinapakita ng panel ang mga limit ng bawat account nang magkatabi, na minarkahan ang active. Bilang default, inaabisuhan ka ng Omarchy kapag ang active account ay lumampas sa 95% ng isang limit, at ang pag-click sa notification ay lumilipat sa account na may pinakamaraming headroom. I-hover ang linya ng isang account sa panel at i-click ang Autoswitch na lumalabas katabi ng Use (o pindutin ang `m`), o patakbuhin ang `omarchy agent account mode auto`, para ito ay lumipat nang kusa; habang naka-on ito, pumapalit ang Autoswitch sa Use, at ang pag-click dito ulit ay bumabalik sa pag-abiso. Magdagdag ng numero para baguhin ang threshold, gaya sa `omarchy agent account mode auto 90`. Kung ang bawat account ay lampas sa threshold, maririnig mo ang tungkol dito nang isang beses, kasama kung aling account ang unang magkakaroon ng puwang. Habang ang isang active account ay nasa loob ng 15 puntos ng threshold nito (80% sa default), ang mga limit nito ay sinusuri kada tatlong minuto sa halip na kada 15.

Ipinapakita ng `omarchy agent account list` ang bawat account at ang pinakabagong mga limit nito, ang `omarchy agent account remove work` ay nakakalimot ng isa, at ang `omarchy agent account rename primary Hey` ay nagpapalit ng pangalan ng isa (o i-click ang pangalan ng isang account sa panel). Gumagana ang mga command na ito sa mga account ng iyong default na agent; para maabot ang ibang provider, pangalanan muna ito, gaya sa `omarchy agent account use codex side`. Ang login na mayroon ka na sa `~/.claude` o `~/.codex` ay ang _Main_ account. Ang sa Codex ay nananatili kung nasaan ito; ang sa Claude ay naghihintay sa sarili nitong folder habang ibang account ang active. Ang isang account na hindi nagamit nang higit sa mga walong oras ay maaaring magpakita ng _Sign-in required_; i-click ito para muling i-sign in ang account na iyon mismo sa panel, o lumipat dito at magsimula ng session, na nagre-refresh ng sign-in nang kusa. Ang mga MCP server na idinaragdag mo gamit ang `claude mcp add` ay umaabot sa bawat Claude account, dahil lahat sila ay tumatakbo sa `~/.claude`; para sa Codex at Grok, ang mga server na mayroon ka noong idinagdag ang isang account ay sumasama dito, ngunit ang mga susunod ay umaabot lamang sa account kung saan mo idinagdag ang mga ito. Ang Claude Desktop ay nag-iingat ng sarili nitong sign-in, at ang mga Codex o Grok tool na naka-configure na may absolute path patungo sa isang CLI binary ay hindi sumusunod sa switch. Ang isang tahasang `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, o `GROK_HOME` ay nangunguna kaysa sa napiling account.

### Diagnosis ng crash

Binabantayan ng Omarchy ang systemd-coredump para sa mga process crash. Kapag may nag-segfault, makakakuha ka ng notification na "Process crashed" — i-click ito, at ang crash ay ibibigay sa iyong default na agent kasama ang diagnose-crash skill ng Omarchy, na gagabay sa agent sa pagtatatag ng mga katotohanan mula sa core dump at pagpapasya kung ang crash ay karapat-dapat iulat sa upstream. Maaari mo rin itong patakbuhin nang mano-mano laban sa anumang PID mula sa `coredumpctl list` gamit ang `omarchy agent crash <pid>`.

Ang pagbabantay ay naka-on bilang default. I-off ito sa ilalim ng _Trigger > Toggle > Crash Capture_ (o gamit ang `omarchy toggle crash-capture`) at hihinto ang mga notification; gumagana pa rin nang mano-mano ang `omarchy agent crash <pid>`.

Maaari ring patahimikin ang mga crash nang paisa-isa bawat programa, na siyang inaalok sa iyo ng diagnosis sa dulo. Ang `omarchy crash mute hyprland` ay humihinto sa mga notification para sa programang iyon lamang, ang `omarchy crash mute hyprland off` ay nagbabalik sa mga ito, at ang `omarchy crash mute` nang mag-isa ay naglilista ng kung ano ang na-mute mo. Tumatanggap ito ng path ng binary nang kasing saya ng pangalan nito, kaya ang `omarchy crash mute /usr/bin/hyprland` ay gumagawa ng parehong bagay. I-quote ang isang pangalan na may puwang dito, gaya sa `omarchy crash mute 'Some App'`. Lahat ng iba pa ay nag-aabiso pa rin, at ang naka-mute na programa ay nagka-crash pa rin — itinatago nito ang paalala, hindi nito inaayos ang anuman.

### Mga desktop app

Ang menu na _Install > AI_ ay nagdadala rin ng ilang graphical AI app: ang ChatGPT desktop app, ang Claude desktop app (ang Linux beta ng Anthropic, na may mga tab na Chat, Cowork, at Claude Code), Grok Bot para sa pakikipag-chat sa mga modelo ng xAI, Herdr Desktop, Hermes Desktop, OpenClaw, ang Perplexity desktop app, at T3 Code. Ang Grok Bot ay ang desktop chat app. Ang coding agent ay ang command na `grok`.

Ang Hermes Desktop ang dapat mong malaman, dahil ang isang machine ay may isang Hermes, at ito ay sa app: ang Hermes ay ini-install lamang kailanman sa pamamagitan ng app, at ang command na `hermes` na pinapatakbo ng default na agent ay sa app. Ang pagpili sa Hermes bilang default na agent ay nag-i-install ng parehong bagay na ginagawa ng entry na _Install > AI_: ang package, at isang Hermes runtime sa ilalim ng `~/.hermes` na sine-set up ng sariling installer ng Hermes, na tumatagal ng ilang minuto sa unang pagkakataon. Ang runtime na iyon ang isang Hermes na ginagamit ng terminal command na `hermes`, ng default na agent at ng app, at ina-update nito ang sarili gamit ang `hermes update` sa halip na maghintay sa isang Omarchy release. Ang pag-install nito ay nagbibigay din kay Hermes ng tema ng Omarchy bilang isang skin na pinangalanang `omarchy`, na sinusundan ng bawat Hermes surface habang nagpapalit ka ng mga tema; pumili ng iba sa ilalim ng mga Appearance setting ng Hermes o gamit ang `/skin` kung mas gusto mong hindi, at hahayaan ng Omarchy ang pagpipiliang iyon. Ang pag-alis ng app sa ilalim ng _Remove > AI_ ay nagsasara muna ng Hermes, kasama ang gateway, kinukuha ang runtime na iyon kasama nito, at pinapanatili ang iyong mga chat, memory, at ang mga skill na isinulat ng Hermes para sa sarili nito maliban kung sasabihin mo ang kabaligtaran: nagtatanong ito, na nagde-default sa hindi, kung ang data na iyon at ang iyong mga connection setting ay dapat ding mawala.

Ang desktop experience ng OpenClaw ay ang Control UI nito, na bubukas bilang isang web app na sinusuportahan ng sarili nitong local gateway. Nakatira ang OpenClaw sa `~/.openclaw` at ina-update ang sarili: gamitin ang button na "Update Gateway" ng Control UI o patakbuhin ang `openclaw update`, at ang gateway ay muling magsisimula sa bagong bersyon. Pinipili lamang ng Omarchy ang release na pagsisimulan ng isang bagong install. Ang pag-alis ng OpenClaw sa ilalim ng _Remove > AI_ ay kinukuha ang gateway service at ang app kasama nito at pagkatapos ay nagtatanong kung dapat ding mawala ang `~/.openclaw`, dahil naglalaman iyon ng iyong mga chat at credential kasama ang OpenClaw mismo at ang mga plugin runtime na dina-download nito; pinapanatili ito ng default, at ang muling pag-install ng OpenClaw ay kukunin itong muli.

Ang Herdr Desktop ay ang desktop app na [Herdr](https://herdr.dev): mga space, tab, at pane ng mga terminal at coding agent na patuloy na tumatakbo sa core nito kapag isinara mo ang window. Nagmumula ito sa sariling installer ng Herdr sa halip na isang package, kaya nakatira ito sa `~/.local/share/herdr-app`, dinadala ang core nito sa `~/.local/bin/herdr-core` kapag wala ka pa nito, at ina-update ang sarili nitong dalawa. Nakatabi ito sa command na `herdr` na ibinibigay ng Omarchy sa `Super + Ctrl + Return` sa halip na palitan ito, at nakukuha ang mga direct key ng command na iyon: hinahati ng `Alt + Return` at `Alt + Shift + Return` ang isang pane pababa o pakanan, isinasara ito ng `Alt + Escape`, ang `Ctrl + Alt + Arrow` ay gumagalaw sa pagitan ng mga pane, ang `Alt + 1..9` at `Alt + Left/Right` ay pumipili ng tab, at ang `Alt + Up/Down` ay gumagalaw sa pagitan ng mga space. Ang `Ctrl + 1..9` ay pumipili ng space at ang `Alt + Shift + Up/Down` ay humahakbang sa mga agent. Ang mga prefix key na `Ctrl + Space` ay nananatiling terminal-only, dahil hindi maaaring hawakan ng app ang isang payak na Ctrl key para sa isang sequence. Isinusulat ng Omarchy ang mga ito sa `~/.config/herdr-app/keys.json`, at ibinabalik sila ng `omarchy-refresh-herdr-app`. Ang pag-install nito ay pumipili ng tema ng Omarchy ng Herdr, na sumusunod sa iyong tema ng Omarchy mula noon. Nag-iingat ang Herdr ng isang tema para sa light mode at isa para sa dark, kaya pagkatapos lumipat sa pagitan ng isang dark at isang light na tema ng Omarchy, piliin ulit ang Omarchy sa theme picker ng Herdr nang isang beses pa para sa kabilang mode.

Tumatakbo ang T3 Code mula sa opisyal nitong AppImage release sa `~/.local/share/t3code` sa halip na mula sa isang package, kaya ina-update nito ang sarili. Ang pag-install nito ay nagtatanong kung magsisimula sa Stable o Nightly channel; lumipat mamaya sa mga setting ng T3 Code. Ang iyong mga thread at setting ay nakatira sa `~/.t3`, at ang pag-alis ng T3 Code sa ilalim ng _Remove > AI_ ay kinukuha sila kasama nito.

### Mga lokal na modelo

Magpatakbo ng isang open model sa sarili mong machine para sa iyong mga coding agent. Ang iyong mga prompt at code ay nananatili sa machine; walang ipinapadala sa modelo ang umaalis dito. Magsimula sa:

```bash
omarchy agent local use best
```

O, sa panel ng mga agent sa top bar, piliin ang + at pagkatapos ang Local AI, na lumalabas kapag ang isang modelo ay kasya sa machine na ito. Sa unang pagkakataon, ini-install nito ang Podman, na nagpapatakbo ng mga modelo, at sa isang NVIDIA machine ang container toolkit ng NVIDIA, na nagbibigay sa kanila ng GPU. Pagkatapos ay pinipili ng Omarchy ang inirerekomendang modelo para sa machine na ito, dina-download ito, at sinisimulan ito. Asahan ang isang download na sampu-sampung GB at ang karamihan ng memory ng machine ay ginagamit habang tumatakbo ang modelo: ang Flash Next ay gumagamit ng mga 100 GiB kasama ang buong 256K context nito. Kung ang ibang mga modelo ang may hawak ng memory na kailangan nito, sine-set up ito nang nakahinto, handang magsimula kapag huminto ka ng isa. Humihinto ang modelo sa pag-logout; ihinto mo ito mismo kapag kailangan mo ang memory para sa ibang bagay.

Ipinapakita ng `omarchy agent local list` ang mga opsyon at ipinaliliwanag kung bakit hindi kasya ang ilan. Para mag-set up ng isa pa, patakbuhin ang `omarchy agent local use <recipe>`. Ngayon, ang `qwen3.8-flash-next-gufo` at `qwen3.8-27b-gufo` ay available para sa mga 128 GB Strix Halo machine; ang 27B ay kumukuha ng mga 40 GiB, kaya nag-iiwan ito ng puwang para sa ibang trabaho. Sa isang 64 GB laptop na may Intel's Arc B390, ang `qwen3.6-35b-a3b-llamacpp` ay tumatakbo sa mga 30 GiB. Ang mga bagong recipe at rekomendasyon ay dumarating kasama ng `omarchy update`, sa pamamagitan ng package.

Bawat modelong sine-set up mo ay nakakakuha ng sarili nitong linya sa panel ng mga agent, katabi ng iyong mga subscription: play para simulan ito, pause para ihinto ito at palayain ang memory nito, at ang terminal button para buksan ang iyong agent dito. Marami ang maaaring tumakbo nang sabay kapag kasya sila sa memory nang magkasama; kung ang isa ay hindi kasya, sinasabi ng Omarchy kung aling tumatakbong modelo ang ihinto. I-drag ang mga linya para muling ayusin sila, at pindutin ang Delete sa isang napiling linya para alisin ang isang modelo at ang download nito.

Bawat modelong sine-set up mo ay nakakakuha rin ng sarili nitong entry sa app launcher, sa ilalim ng pangalan ng modelo at kasama ang logo ng gumawa nito, sa paraang ang pag-sign in sa Claude, Codex o Grok ay nagdaragdag ng isa. Binubuksan nito ang iyong agent sa modelong iyon, at sinisimulan muna ang modelo kung hindi ito tumatakbo: ipinapakita ng terminal na naglo-load ito at ibibigay sa agent kapag handa na ito. Ang pag-alis ng isang modelo ay nag-aalis ng entry nito.

Mula sa command line, ang `omarchy agent local start <recipe>` at `omarchy agent local stop <recipe>` ay gumagawa ng pareho, ipinapakita ng `omarchy agent local status` ang bawat modelo, at binubuksan ng `omarchy agent --local` ang iyong default na agent sa huling modelong sinimulan mo. Ang pi, OpenCode at Qwen Code ay maaaring gumamit ng isa; sa anumang ibang default bubukas ito sa pi. Inililista rin ng pi ang bawat modelong sine-set up mo, at ang mga nasa machine na ipinares mo, sa sarili nitong model picker, kaya ang payak na `pi` ay umaabot din sa kanila. Maaari ring kumonekta ang anumang OpenAI-compatible client: ipinapakita ng `status` ang address ng bawat modelo (ang una ay `http://127.0.0.1:11435/v1`), ang pangalan ng recipe ay ang modelo, at ang key ay nasa `~/.config/omarchy/agent-local/key`.

Ang `omarchy agent local remove <recipe>` ay nagbubura ng isang modelo at ng mga download na hindi ginagamit ng ibang modelo.

Ang mga third-party runtime ay may label ng kanilang publisher. Pinapatakbo ng Omarchy ang bawat modelo nang walang network access.

### Mga lokal na LLM

Inirerekomenda ng Omarchy ang dalawang paraan ng pagpapatakbo ng mga lokal na LLM model: LM Studio at Ollama. Nagbibigay ang LM Studio ng isang GUI interface para sa paghahanap ng mga open-weight model, pag-install ng mga ito, at pagpapatakbo ng mga ito. Mahusay itong paraan para madaling makapagsimula. Nag-aalok ang Ollama ng isang CLI para gawin ito nang katulad. Ngunit kung bago ka sa mga lokal na modelo, magsisimula ako sa LM Studio. Maaari mong i-install ang alinman sa ilalim ng _Install > AI_ sa Omarchy Menu.

### Ang Omarchy Skill

Tinutulungan ng mga agent skill ang AI na gumamit ng mga partikular na tool sa isang partikular na paraan, at ang Omarchy ay may kasamang default skill para sa pag-aangkop ng system. Tulad ng pag-aayos ng iyong Hyprland config, pag-aadjust ng bar, o kahit paglikha ng isang bagong tema mula sa simula. Naka-symlink ito sa mga skill directory para sa Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` at bawat `~/.hermes/profiles/*/skills`), at ang generic na lokasyon na `~/.agents/skills`, kaya karamihan ng mga harness ay awtomatikong nakukuha ito.

Ngunit dapat mong ituring ang skill na ito bilang eksperimental. Iba't ibang modelo ang gagamit dito nang may iba't ibang epekto. Pinakamainam na tumakbo muna sa plan mode, para magkaroon ka ng ideya kung ano ang gustong baguhin ng agent. At pagkatapos ay maghanda na i-rollback ang mga pagbabago o kahit tawagin ang `omarchy reinstall configs`, kung guguluhin ng agent ang lahat.
