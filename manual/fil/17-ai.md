Magpatakbo ng command para i-install ang CLI nito sa unang paggamit, pagkatapos ay mag-authenticate kapag sinabihan. Ang Hermes ang eksepsiyon: walang ini-install para dito sa unang paggamit, at ang pagpili dito ay nag-i-install ng Hermes Desktop, gaya ng ipinapaliwanag ng _Desktop apps_ sa ibaba.

### Pag-install at pag-update ng mga agent

Maliban sa Hermes, ginagamit ng mga agent na ito ang lazy installation ng mise: ini-install ng unang paglunsad ang CLI, at muling ginagamit ito ng mga susunod na paglunsad. Sinusuri rin ng mise ang isang naka-install na agent para sa bagong release nang hindi hihigit sa isang beses bawat apat na oras, bago ito magsimula o sa background sa isang shell prompt. Kung mabigo ang update na iyon o offline ka, tatakbo ang naka-install na bersyon. Ina-update ng `omarchy update` ang mga naka-install na agent kasama ang iba pang bahagi ng Omarchy, at ina-update ng `mup` ang mga tool na pinamamahalaan ng mise lamang.

Hindi ina-update ng sariling updater ng isang agent, gaya ng `claude update`, `codex update`, o isang update button sa isang app, ang install na pinamamahalaan ng mise. Nabibigo ang `codex update`, at maaaring mag-ulat ng tagumpay ang `claude update` habang nag-i-install ng hiwalay na kopya na hindi sinusubaybayan ng mise. Kung mas gusto mong gamitin ang native installer at updater ng isang agent, idagdag ito sa `disable_tools`; tingnan ang [Mga paunang naka-install na CLI tool](18-development-tools.md#preinstalled-cli-tools).

Para i-install ang lahat ng naka-configure na lazy tool bago mo kailanganin ang mga ito, patakbuhin ang `mise install --include-lazy`. Kasama rito ang iba pang default na CLI tool ng Omarchy pati ang mga agent. Tingnan ang [Mga paunang naka-install na CLI tool](18-development-tools.md#preinstalled-cli-tools) para sa pag-install ng isang tool o paggamit ng sarili mong installation.

Ang `grok` ay ini-install sa pamamagitan ng first-party `grok` package ng mise, sa parehong paraan gaya ng `claude` at `codex`. Patakbuhin ang `grok`, o piliin ito sa ilalim ng _Agent > Harness_. Laktawan ang `curl | bash` installer sa x.ai. Naglalagay ang paraang iyon ng pangalawang kopya sa `~/.grok/bin`, inuuna ito sa `PATH`, at pinapatungan ang wrapper ng Omarchy.

Binubuksan ng `dsh` ang browser UI nito sa `127.0.0.1:3080`, na ang launch directory ang default workspace nito. Walang starting prompt ang browser UI nito, kaya binubuksan ito ng `omarchy agent prompt` na nasa clipboard mo ang prompt para i-paste. Sinisimulan ito ng Omarchy gamit ang no-approval permission preset ng DeepSeek. Nag-a-upload ang DeepSeek Harness ng mga session log sa DeepSeek kapag ginagamit mo ang opisyal nitong model API; i-off iyon sa ilalim ng _Settings > General > Upload Session Log_ sa browser UI nito. Ang feedback na ipinapadala mo dito ay ina-upload din kasama ng session, maliban kung sisimulan mo ito gamit ang `DSH_TELEMETRY_MODE=DISABLED`.

### Ang default na agent

Piliin ang default mong agent gamit ang `omarchy default agent <name>` o sa ilalim ng _Agent > Harness_ sa Omarchy Menu (`Super + Space`). Kung hindi pa naka-install ang agent, i-install muna ito ng pagpili dito. Aanyayahan ka ng bagong Omarchy na gawin ang pagpipiliang ito gamit ang isang beses lang na notification.

Sinusubukan din ng pagpili sa Claude na i-set up ang browser extension nito para sa Chromium, Chrome, Brave, Brave Origin, at Edge. Nalalapat ang extension setup sa lahat ng user at maaaring humingi ng password ng system mo; pipiliin at ilulunsad pa rin ang Claude kahit kanselahin o mabigo ang pag-install ng extension. I-restart ang browser mo, i-enable ang extension kung sinabihan, at mag-sign in sa Claude para tapusin ang pagkonekta dito. Patakbuhin ang `/chrome` sa Claude para suriin ang koneksyon. Hindi sinusuportahan ng Firefox at Zen ang extension na ito. Kung Claude na ang default mo bago idinagdag ang setup na ito, piliin ito ulit para i-install ang extension.

Kapag nakapili ka na, ilulunsad ng `Super + Shift + Ctrl + A` ang default na agent sa isang nakalaang terminal window (o ilalabas ang picker kung hindi ka pa nakakapili). Maaari mo rin itong ilunsad diretso sa isang gawain gamit ang `omarchy agent prompt "Review this project"`. Walang starting prompt ang Freebuff at DeepSeek Harness, kaya magbubukas sila na nasa clipboard mo ang prompt para i-paste sa halip. Ang mga agent na inilunsad sa ganitong paraan ay tumatakbo nang walang bantay sa kani-kanilang don't-stop-to-ask mode, kaya maghanda kang may gagawin talaga sila! Walang ganoong mode ang MiniMax Code para sa mga interactive session nito, kaya humihingi ito ng mga pahintulot gaya ng dati. At dahil tumatanggi ang mga agent na tandaan ang trust para sa home directory mo, ang mga paglunsad mula sa `$HOME` ay nagsisimula sa `~/Work` sa halip.

May mga terminal shortcut din: pinapatakbo ng `a` ang default na agent nang inline sa kasalukuyang terminal, habang sinisimulan ng `c`, `cx`, at `cy` ang OpenCode, Claude Code, at Codex nang direkta (muli sa kanilang auto-approving mode). Nagsi-sync din ang mga pagbabago ng tema sa mga agent: sumusunod ang Claude Code, Pi, OpenCode, at Hermes (kapag na-install na ito ng Omarchy) kapag nagpapalit ka ng tema ng Omarchy.

### Ang mga tagubilin ng agent mo

Ang mga personal na panuntunan para sa bawat agent ay nasa `~/.agents/AGENTS.md`, katabi ng mga shared skill sa `~/.agents/skills`. Buksan ito sa ilalim ng _Agent > Instructions_, na nagli-link din dito sa bawat harness na may sarili nitong global file: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, ang `~/.copilot/copilot-instructions.md` ng Copilot, at iba pa. Binabasa ng Crush at Amp ang link na `~/.config/AGENTS.md`, habang direktang binabasa ng omp, Kimi, at DeepSeek Harness ang `~/.agents/AGENTS.md`. Nagli-link din dito ang pagpili ng default na agent. Ang instructions file na mayroon ka na ay magiging shared file kung wala pa nito; kung hindi, itatabi ito katabi ng link bilang `.bak`. Patakbuhin ang `omarchy agent instructions` para muling mag-link pagkatapos mag-install ng isa pang agent.

### Ang panel ng mga agent

May icon ng mga agent ang top bar. Bago ka makapag-set up ng agent, gagabayan ka ng panel nito sa pag-sign in sa Claude, Codex, o Grok, at ang una ay magiging default mong agent. Pagkatapos niyon, inilalagay ng panel ang bawat subscription sa isang page: bawat agent at account kasama ang plan nito, isang meter para sa bawat 5-hour session at weekly limit nito kasama ang oras hanggang mag-reset ito (i-hover para sa eksaktong porsiyento), o ang natitirang prepaid balance, sa ilalim ng isang linya na umiikot sa kung ano ang nagamit mo sa lahat ng mga ito, gaya ng mga token ngayong linggo at ang pinakamadalas mong gamiting modelo. Sa ilalim ng _Make something_ nag-aalok ito ng mga starter prompt para sa bagong tema, plugin, app, o laro na nagbibigay ng gawain sa default mong agent. Binubuo ang mga app sa paraang binuo ang sariling Hype, Monologue, at Omacut ng Omarchy, sa C++ at Qt Quick, na sumusunod sa omarchy-make-app agent skill, at naka-install na ang compiler at mga piraso ng Qt na kailangan nila. Ang mga laro ay isang three.js page lang sa `~/Games/vibes`, na sumusunod sa omarchy-make-game agent skill, at lahat ay nagbubukas mula sa isang Game Vibes launcher sa kasalukuyang tema; nilo-load nila ang three.js mula sa web, kaya kailangan nila ng koneksyon para magsimula. Saklaw agad ang Claude Code, Codex, Grok, Kimi, Cursor at ang Grok Bot allowance nito, GitHub Copilot, Muse, Antigravity, Kimchi, at Devin kasama ang kanilang mga limit, at ipinapakita ng Hermes, Mistral Vibe, at Qwen Code ang kanilang mga session at token kapag nagamit mo na sila. Lumalabas din ang mga provider plan at key na ginagamit mo sa pamamagitan ng pi, omp, o opencode: OpenCode Zen at Go, ang Z.ai GLM Coding Plan, Ollama Cloud, ang MiniMax Token Plan, at Synthetic kasama ang kanilang mga limit; Fireworks, OpenRouter, at DeepSeek kasama ang kanilang prepaid balance; at ang mga modelong pinapatakbo mo sa sarili mong hardware sa ilalim ng Local models. Bawat agent ay binibilang nang isang beses, sa ilalim ng sinumang naniningil para dito, gaano man karaming harness ang pagdaanan mo dito.

I-left-click ang icon sa bar para sa panel, i-right-click para ilunsad ang default mong agent. Ang mga usage record sa likod nito ay muling ginagawa bawat 15 minuto ng `omarchy agent usage-update`, at maaari pang pagsamahin ng panel ang usage mula sa iba mong makina sa pamamagitan ng isang naka-sync na folder. Tingnan ang README sa ilalim ng `$OMARCHY_PATH/shell/plugins/agents/` para sa buong settings.

### Maraming subscription

Kung nagbabayad ka para sa higit sa isang Claude, Codex, o Grok plan — isang personal na Max at isang pang-trabaho, halimbawa — maaaring panatilihin ng Omarchy ang lahat ng ito na naka-sign in at lumipat sa pagitan nila. Magdagdag ng subscription gamit ang + sa panel ng mga agent, na gagabay sa iyo mismo roon, o gamit ang `omarchy agent account add claude Work` (o `codex`, o `grok`). Ini-install nito ang CLI kung nawawala ito. Ang unang account para sa isang provider ay nagsa-sign in sa pamamagitan ng normal mong browser, mismo kung saan laging tumitingin ang CLI. Bawat isa pagkatapos niyon ay nagsa-sign in sa pamamagitan ng private window, kaya ang account na naka-sign in na sa browser mo ay hindi aksidenteng makukuha; mag-sign in doon bilang account na idinadagdag mo, at isara muna ang anumang private window na nakabukas mo na. Huwag kailanman mag-log out sa CLI para gawin ito: binabawi ng pag-log out ang naka-save na sign-in, at kailangang idagdag ulit ang account na iyon.

Para kopyahin ang mga subscription login mo sa isa pang Omarchy machine sa pamamagitan ng SSH, patakbuhin ang `omarchy agent account copy user@laptop`. Nagbibigay ang sender ng pansamantalang receiver kapag walang naka-install ang destinasyon, kaya ang mas lumang mga Omarchy machine ay makakatanggap ng mga account nang walang update. Inuuna ang mga naka-install na receiver. Kinokopya nito ang lahat ng Claude, Codex, at Grok subscription; magdagdag ng mga pangalan ng provider para piliin sila, gaya sa `omarchy agent account copy laptop claude`. Tumutugma ang mga pangalan ng account at command ID sa pinagmulan, kabilang ang mga account na naroon na sa destinasyon. Ang mga hindi kaugnay na account sa destinasyon ay makakatanggap ng numeric suffix kung magkasalungat ang kanilang mga pangalan, at ang settings, skills, plugins, at conversation history ay nananatiling lokal sa bawat makina.

Pinapanatili ang mga umiiral na credential sa destinasyon. Ang source account na naka-sign in na roon ay isi-sync ang pangalan nito nang hindi pinapalitan ang mga credential nito; ang ibang mga account ay idinadagdag sa tabi nito. Para palitan ang mga naka-save na credential para sa magkatugmang account, gamitin ang `omarchy agent account copy --replace laptop claude` pagkatapos isara ang mga session ng account na iyon sa destinasyon. Ang bagong destinasyon ay nakakakuha rin ng aktibong account at mga switching preference ng pinagmulan; pinapanatili ng matatag nang destinasyon ang sarili nito.

Naglalakbay ang mga credential sa pamamagitan ng SSH at nakaimbak sa mga pribadong file sa destinasyon, kaya kumopya lang sa mga makinang pinagkakatiwalaan mo. Ito ay isang beses na pagkopya, hindi patuloy na synchronization. Maaaring i-rotate ng ibang makina ang mga Codex refresh token, na mag-iiwan sa kinopyang login na nangangailangan ng pag-renew; ang magkakahiwalay na sign-in ang nananatiling pinaka-maaasahang pagpipilian para sa sabay-sabay na paggamit sa maraming makina. Tingnan ang [gabay sa account authentication ng Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Isang account bawat provider ang aktibo, at bawat bagong session ay nagsisimula bilang ito: `cx`, `cy`, isang plain na `claude`, `codex`, o `grok`, anumang inilunsad sa pamamagitan ng `omarchy agent`, at mga script o editor na nakakahanap ng CLI sa `PATH`. Lumipat gamit ang `omarchy agent account use work` (at bumalik gamit ang `omarchy agent account use main`), o sa panel sa pamamagitan ng pagpindot sa numero ng isang account at pagkatapos ay `Enter` (o pag-click sa Use button nito). Lumilipat din ang mga tumatakbong Claude session, mula sa kanilang susunod na mensahe: bawat Claude session ay tumatakbo sa `~/.claude`, na laging naglalaman ng sign-in ng aktibong account. Ang isang Claude session na sinimulan sa sariling folder ng isang account ng mas lumang Omarchy ay nagpapanatili ng sign-in na iyon hanggang umalis ito, kaya pinapangalanan ng switch ang mga session na iyon at matatapos nang kusa kapag wala na sila. Ang mga tumatakbong Codex at Grok session ay nananatili sa account kung saan sila nagsimula. Ang conversation history, settings, skills, at plugins ay ibinabahagi sa lahat ng account, kaya ang `claude --continue` sa parehong folder ay nagpapatuloy kung saan ka huminto sa bagong account.

Kapag may higit sa isang account, ipinapakita ng panel ang mga limit ng bawat account nang magkatabi, na minarkahan ang aktibo. Bilang default, aabisuhan ka ng Omarchy kapag lumampas ang aktibong account sa 95% ng isang limit, at ang pag-click sa notification ay lilipat sa account na may pinakamaraming headroom. I-hover ang linya ng isang account sa panel at i-click ang Autoswitch na lumalabas katabi ng Use (o pindutin ang `m`), o patakbuhin ang `omarchy agent account mode auto`, para hayaan itong lumipat nang kusa; habang naka-on ito, pumapalit ang Autoswitch sa Use, at ang pag-click dito ulit ay babalik sa pag-abiso. Magdagdag ng numero para baguhin ang threshold, gaya sa `omarchy agent account mode auto 90`. Kung lahat ng account ay lagpas sa threshold, maririnig mo ito nang isang beses, kasama kung aling account ang unang magkakaroon ng puwang. Habang ang isang aktibong account ay nasa loob ng 15 puntos ng threshold nito (80% sa default), sinusuri ang mga limit nito bawat tatlong minuto sa halip na bawat 15.

Ipinapakita ng `omarchy agent account list` ang bawat account at ang pinakabagong mga limit nito, kinakalimutan ng `omarchy agent account remove work` ang isa, at pinapalitan ng pangalan ng `omarchy agent account rename primary Hey` ang isa (o i-click ang pangalan ng isang account sa panel). Gumagana ang mga command na ito sa mga account ng default mong agent; para maabot ang ibang provider, pangalanan muna ito, gaya sa `omarchy agent account use codex side`. Ang login na mayroon ka na sa `~/.claude` o `~/.codex` ay ang _Main_ account. Ang sa Codex ay nananatili kung nasaan ito; ang sa Claude ay naghihintay sa sarili nitong folder habang may ibang account na aktibo. Ang account na hindi nagamit nang higit sa mga walong oras ay maaaring magpakita ng _Sign-in required_; i-click ito para muling i-sign in ang account na iyon mismo sa panel, o lumipat dito at magsimula ng session, na nagre-refresh ng sign-in nang kusa. Ang mga MCP server na idinadagdag mo gamit ang `claude mcp add` ay umaabot sa bawat Claude account, dahil lahat sila ay tumatakbo sa `~/.claude`; para sa Codex at Grok, ang mga server na mayroon ka noong idinagdag ang isang account ay sumasama dito, pero ang mga susunod ay umaabot lang sa account kung saan mo sila idinagdag. Ang Claude Desktop ay may sarili nitong sign-in, at ang mga Codex o Grok tool na naka-configure gamit ang absolute path papunta sa isang CLI binary ay hindi sumusunod sa switch. Ang tahasang `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, o `GROK_HOME` ay inuuna kaysa sa napiling account.

### Diagnosis ng crash

Binabantayan ng Omarchy ang systemd-coredump para sa mga process crash. Kapag may nag-segfault, makakakuha ka ng notification na "Process crashed" — i-click ito, at ibibigay ang crash sa default mong agent kasama ang diagnose-crash skill ng Omarchy, na gagabay sa agent sa pagtatatag ng mga katotohanan mula sa core dump at pagpapasya kung karapat-dapat bang iulat ang crash sa upstream. Maaari mo rin itong patakbuhin nang mano-mano laban sa anumang PID mula sa `coredumpctl list` gamit ang `omarchy agent crash <pid>`.

Naka-on ang pagbabantay bilang default. I-off ito sa ilalim ng _Trigger > Toggle > Crash Capture_ (o gamit ang `omarchy toggle crash-capture`) at hihinto ang mga notification; gumagana pa rin nang mano-mano ang `omarchy agent crash <pid>`.

Maaari ring patahimikin ang mga crash nang isa-isa bawat programa, na siyang inaalok sa iyo ng diagnosis sa dulo. Pinipigilan ng `omarchy crash mute hyprland` ang mga notification para sa programang iyon lang, ibinabalik sila ng `omarchy crash mute hyprland off`, at inililista ng `omarchy crash mute` nang mag-isa kung ano ang na-mute mo. Tinatanggap nito ang path ng binary nang kasing saya ng pangalan nito, kaya pareho ang ginagawa ng `omarchy crash mute /usr/bin/hyprland`. I-quote ang pangalang may space, gaya sa `omarchy crash mute 'Some App'`. Aabisuhan ka pa rin ng lahat ng iba, at magka-crash pa rin ang naka-mute na programa — itinatago nito ang paalala, hindi nito inaayos ang anuman.

### Mga desktop app

May dala ring ilang graphical AI app ang _Install > AI_ menu: ang ChatGPT desktop app, ang Claude desktop app (Linux beta ng Anthropic, na may Chat, Cowork, at Claude Code tabs), Grok Bot para makipag-chat sa mga modelo ng xAI, Herdr Desktop, Hermes Desktop, OpenClaw, ang Perplexity desktop app, at T3 Code. Ang Grok Bot ay ang desktop chat app. Ang coding agent ay ang `grok` command.

Ang Hermes Desktop ang dapat mong malaman, dahil iisa lang ang Hermes ng isang makina, at pag-aari ito ng app: ang Hermes ay ini-install lang kailanman sa pamamagitan ng app, at ang `hermes` command na pinapatakbo ng default na agent ay sa app. Ang pagpili sa Hermes bilang default na agent ay nag-i-install ng parehong bagay na ginagawa ng _Install > AI_ entry: ang package, at isang Hermes runtime sa ilalim ng `~/.hermes` na sine-set up ng sariling installer ng Hermes, na tumatagal ng ilang minuto sa unang pagkakataon. Ang runtime na iyon ang iisang Hermes na ginagamit ng terminal `hermes` command, ng default na agent at ng app, at ina-update nito ang sarili gamit ang `hermes update` sa halip na maghintay sa isang Omarchy release. Ang pag-install dito ay nagbibigay din sa Hermes ng tema ng Omarchy bilang skin na pinangalanang `omarchy`, na sinusunod ng bawat Hermes surface habang nagpapalit ka ng tema; pumili ng iba sa ilalim ng Appearance settings ng Hermes o gamit ang `/skin` kung ayaw mong ganoon, at hindi pakikialaman ng Omarchy ang pagpipiliang iyon. Ang pag-alis sa app sa ilalim ng _Remove > AI_ ay nagsasara muna sa Hermes, kasama ang gateway, isinasama ang runtime na iyon, at pinapanatili ang iyong mga chat, memory, at ang mga skill na isinulat ng Hermes para sa sarili nito maliban kung sasabihin mong hindi: nagtatanong ito, na ang default ay hindi, kung dapat ding alisin ang data na iyon at ang iyong mga connection setting.

Ang desktop experience ng OpenClaw ay ang Control UI nito, na nagbubukas bilang web app na suportado ng sarili nitong local gateway. Nakatira ang OpenClaw sa `~/.openclaw` at ina-update ang sarili nito: gamitin ang "Update Gateway" button ng Control UI o patakbuhin ang `openclaw update`, at magre-restart ang gateway sa bagong bersyon. Pinipili lang ng Omarchy ang release kung saan magsisimula ang bagong install. Ang pag-alis sa OpenClaw sa ilalim ng _Remove > AI_ ay isinasama ang gateway service at ang app at pagkatapos ay nagtatanong kung dapat ding alisin ang `~/.openclaw`, dahil naroon ang iyong mga chat at credential kasama ang OpenClaw mismo at ang mga plugin runtime na dina-download nito; pinapanatili ito ng default, at ang muling pag-install ng OpenClaw ay kukunin itong muli.

Ang Herdr Desktop ay ang [Herdr](https://herdr.dev) desktop app: mga space, tab, at pane ng mga terminal at coding agent na patuloy na tumatakbo sa core nito kapag isinara mo ang window. Nagmumula ito sa sariling installer ng Herdr sa halip na sa isang package, kaya nakatira ito sa `~/.local/share/herdr-app`, isinasama ang core nito sa `~/.local/bin/herdr-core` kapag wala ka pang isa, at ina-update ang sarili nitong dalawa. Nakaupo ito katabi ng `herdr` command na kasama ng Omarchy sa `Super + Ctrl + Return` sa halip na palitan ito, at nakakakuha ng mga direct key ng command na iyon: hinahati ng `Alt + Return` at `Alt + Shift + Return` ang isang pane pababa o pakanan, isinasara ito ng `Alt + Escape`, lumilipat sa pagitan ng mga pane ang `Ctrl + Alt + Arrow`, pumipili ng tab ang `Alt + 1..9` at `Alt + Left/Right`, at lumilipat sa pagitan ng mga space ang `Alt + Up/Down`. Pumipili ng space ang `Ctrl + 1..9` at humahakbang sa mga agent ang `Alt + Shift + Up/Down`. Ang mga `Ctrl + Space` prefix key ay nananatiling pang-terminal lang, dahil hindi kayang hawakan ng app ang plain na Ctrl key para sa isang sequence. Isinusulat ito ng Omarchy sa `~/.config/herdr-app/keys.json`, at ibinabalik sila ng `omarchy-refresh-herdr-app`. Pinipili ng pag-install dito ang Omarchy theme ng Herdr, na sumusunod sa tema ng Omarchy mo mula noon. Nagpapanatili ang Herdr ng isang tema para sa light mode at isa para sa dark, kaya pagkatapos lumipat sa pagitan ng dark at light na tema ng Omarchy, piliin muli ang Omarchy sa theme picker ng Herdr nang isang beses pa para sa kabilang mode.

Tumatakbo ang T3 Code mula sa opisyal nitong AppImage release sa `~/.local/share/t3code` sa halip na mula sa isang package, kaya ina-update nito ang sarili nito. Nagtatanong ang pag-install dito kung magsisimula sa Stable o Nightly channel; lumipat mamaya sa settings ng T3 Code. Nakatira ang iyong mga thread at setting sa `~/.t3`, at ang pag-alis sa T3 Code sa ilalim ng _Remove > AI_ ay isinasama sila.

### Mga lokal na modelo

Magpatakbo ng open model sa sarili mong makina para sa iyong mga coding agent. Nananatili sa makina ang iyong mga prompt at code; walang ipinapadala sa modelo ang umaalis dito. Magsimula sa:

```bash
omarchy agent local use best
```

O, sa panel ng mga agent sa top bar, piliin ang + at pagkatapos ay Local AI, na lumalabas kapag may modelong kasya sa makinang ito. Sa unang pagkakataon, ini-install nito ang Podman, na nagpapatakbo ng mga modelo, at sa isang NVIDIA machine ang container toolkit ng NVIDIA, na nagbibigay sa kanila ng GPU. Pagkatapos ay pipiliin ng Omarchy ang inirerekomendang modelo para sa makinang ito, ida-download ito, at sisimulan ito. Asahan ang download na sampu-sampung GB at karamihan ng memory ng makina ay magagamit habang tumatakbo ang modelo: gumagamit ang Flash Next ng mga 100 GiB kasama ang buong 256K context nito. Kung hawak ng ibang mga modelo ang memoryang kailangan nito, sine-set up itong nakahinto, handang magsimula kapag huminto ka ng isa. Hihinto ang modelo sa pag-logout; patigilin mo ito mismo kapag kailangan mo ang memory para sa iba.

Ipinapakita ng `omarchy agent local list` ang mga opsyon at ipinapaliwanag kung bakit hindi kasya ang ilan. Para mag-set up ng iba, patakbuhin ang `omarchy agent local use <recipe>`. Ngayon, available ang `qwen3.8-flash-next-gufo` at `qwen3.8-27b-gufo` para sa mga 128 GB Strix Halo machine; ang 27B ay gumagamit ng mga 40 GiB, kaya nag-iiwan ito ng puwang para sa iba pang trabaho. Sa isang 64 GB laptop na may Intel's Arc B390, tumatakbo ang `qwen3.6-35b-a3b-llamacpp` sa mga 30 GiB. Dumarating ang mga bagong recipe at rekomendasyon kasama ng `omarchy update`, sa pamamagitan ng package.

Bawat modelong sine-set up mo ay nakakakuha ng sarili nitong linya sa panel ng mga agent, katabi ng iyong mga subscription: play para simulan ito, pause para patigilin ito at palayain ang memory nito, at ang terminal button para buksan ang agent mo dito. Marami ang maaaring tumakbo nang sabay kapag kasya sila sa memory nang magkasama; kung hindi kasya ang isa, sasabihin ng Omarchy kung aling tumatakbong modelo ang patitigilin. I-drag ang mga linya para muling ayusin sila, at pindutin ang Delete sa isang napiling linya para alisin ang isang modelo at ang download nito.

Bawat modelong sine-set up mo ay nakakakuha rin ng sarili nitong entry sa app launcher, sa ilalim ng pangalan ng modelo at kasama ang logo ng gumawa nito, sa paraang ang pag-sign in sa Claude, Codex o Grok ay nagdadagdag ng isa. Binubuksan nito ang agent mo sa modelong iyon, at sinisimulan muna ang modelo kung hindi ito tumatakbo: ipinapakita ng terminal na naglo-load ito at ibibigay sa agent kapag handa na ito. Ang pag-alis sa isang modelo ay nag-aalis ng entry nito.

Patuloy na tumatakbo ang isang modelo nang eksakto kung paano ito sine-set up, kaya hindi kailanman nire-restart ng isang Omarchy update ang isa sa ilalim ng iyong mga agent. Kapag may mas bagong runtime o mas bagong weights ang Omarchy para sa isang modelong sine-set up mo, nagpapakita ang linya nito ng update button: pindutin ito at muling sine-set up ang modelo sa background, dina-download lang kung ano ang nagbago, at magre-restart sa bagong bersyon. Ang modelong nakahinto ay nananatiling nakahinto. Ginagawa ng `omarchy agent local update` ang pareho para sa bawat modelo mula sa terminal.

Mula sa command line, ginagawa ng `omarchy agent local start <recipe>` at `omarchy agent local stop <recipe>` ang pareho, ipinapakita ng `omarchy agent local status` ang bawat modelo, at binubuksan ng `omarchy agent --local` ang default mong agent sa huling modelong sinimulan mo. Maaaring gumamit ng isa ang pi, OpenCode at Qwen Code; sa anumang ibang default ay nagbubukas ito sa pi. Inililista rin ng pi ang bawat modelong sine-set up mo, at ang mga nasa mga makinang na-pair mo, sa sarili nitong model picker, kaya naaabot din sila ng plain na `pi`. Maaari ring kumonekta ang anumang OpenAI-compatible client: ipinapakita ng `status` ang address ng bawat modelo (ang una ay `http://127.0.0.1:11435/v1`), ang recipe name ang modelo, at ang key ay nasa `~/.config/omarchy/agent-local/key`.

Binubura ng `omarchy agent local remove <recipe>` ang isang modelo at ang mga download na hindi ginagamit ng ibang modelo.

Ang mga third-party runtime ay may label ng kanilang publisher. Pinapatakbo ng Omarchy ang bawat modelo nang walang network access.

### Mga lokal na LLM

Inirerekomenda ng Omarchy ang dalawang paraan ng pagpapatakbo ng mga lokal na LLM model: LM Studio at Ollama. Nagbibigay ang LM Studio ng GUI interface para sa paghahanap ng mga open-weight model, pag-install sa kanila, at pagpapatakbo sa kanila. Mahusay itong paraan para madaling makapagsimula. Nag-aalok ang Ollama ng CLI para gawin ang katulad nito. Pero kung bago ka sa mga lokal na modelo, magsimula ako sa LM Studio. Maaari mong i-install ang alinman sa ilalim ng _Install > AI_ sa Omarchy Menu.

### Ang Omarchy Skill

Tinutulungan ng mga agent skill ang AI na gumamit ng mga partikular na tool sa isang partikular na paraan, at may kasamang default skill ang Omarchy para sa pag-aangkop ng system. Gaya ng pag-tweak sa Hyprland config mo, pag-aayos ng bar, o kahit paglikha ng bagong tema mula sa simula. Naka-symlink ito sa mga skill directory para sa Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` at bawat `~/.hermes/profiles/*/skills`), at ang generic na `~/.agents/skills` location, kaya karamihan ng mga harness ay awtomatikong nakukuha ito.

Pero dapat mong ituring na eksperimental ang skill na ito. Iba't ibang modelo ang gagamit dito nang may iba't ibang epekto. Pinakamainam na patakbuhin muna ito sa plan mode, para magkaroon ka ng ideya kung ano ang gustong baguhin ng agent. At pagkatapos ay maging handang i-rollback ang mga pagbabago o kahit tawagin ang `omarchy reinstall configs`, kung guluhin ng agent ang lahat.
