# AI

Kasama sa Omarchy ang mga launcher para sa mga coding agent sa ibaba nang hindi pumipili ng default para sa iyo. Magpatakbo ng command para mai-install ang CLI nito sa unang paggamit, pagkatapos ay mag-authenticate kapag sinabihan. Ang Hermes at OpenClaw ang mga exception: walang ini-install para sa kanila sa pamamagitan ng mise, at ang pagpili sa alinman ay nagse-set up ng sarili nitong self-updating na kopya, gaya ng ipinaliliwanag ng _Mga desktop app_ sa ibaba.

### Pag-install at pag-update ng mga agent

Maliban sa Hermes at OpenClaw, ginagamit ng mga agent na ito ang lazy installation ng mise: ini-install ng unang paglunsad ang CLI, at muling ginagamit ito ng mga susunod na paglunsad. Sinusuri rin ng mise ang isang naka-install na agent para sa bagong release nang hindi hihigit sa isang beses bawat apat na oras, bago ito magsimula o sa background sa isang shell prompt. Kung mabigo ang update na iyon o offline ka, tatakbo ang naka-install na bersyon. Ina-update ng `omarchy update` ang mga naka-install na agent kasama ng iba pang bahagi ng Omarchy, at ina-update ng `mup` ang mga tool na pinamamahalaan lamang ng mise.

Hindi ina-update ng sariling updater ng isang agent, tulad ng `claude update`, `codex update`, o isang update button sa isang app, ang install na pinamamahalaan ng mise. Nabibigo ang `codex update`, at maaaring mag-ulat ng tagumpay ang `claude update` habang nag-i-install ng hiwalay na kopya na hindi sinusubaybayan ng mise. Kung mas gusto mong gamitin ang native installer at updater ng isang agent, idagdag ito sa `disable_tools`; tingnan ang [Mga preinstalled na CLI tool](18-development-tools.md#preinstalled-cli-tools).

Para mai-install ang lahat ng naka-configure na lazy tool bago mo kailanganin ang mga ito, patakbuhin ang `mise install --include-lazy`. Kasama rito ang iba pang default na CLI tool ng Omarchy pati na rin ang mga agent. Tingnan ang [Mga preinstalled na CLI tool](18-development-tools.md#preinstalled-cli-tools) para sa pag-install ng iisang tool o paggamit ng sarili mong installation.

Ini-install ang `grok` sa pamamagitan ng first-party na `grok` package ng mise, sa parehong paraan tulad ng `claude` at `codex`. Patakbuhin ang `grok`, o piliin ito sa ilalim ng _Agent > Harness_. Laktawan ang `curl | bash` installer sa x.ai. Naglalagay ang paraang iyon ng pangalawang kopya sa `~/.grok/bin`, inuuna ito sa `PATH`, at pinapatungan ang wrapper ng Omarchy.

Binubuksan ng `dsh` ang browser UI nito sa `127.0.0.1:3080`, na ang launch directory ang default workspace nito. Walang starting prompt ang browser UI nito, kaya binubuksan ito ng `omarchy agent prompt` na nasa clipboard mo ang prompt para i-paste. Sinisimulan ito ng Omarchy gamit ang no-approval permission preset ng DeepSeek. Nag-a-upload ang DeepSeek Harness ng mga session log sa DeepSeek kapag ginagamit mo ang opisyal nitong model API; i-off iyon sa ilalim ng _Settings > General > Upload Session Log_ sa browser UI nito. Ang feedback na ipinapadala mo rito ay ina-upload din kasama ng session, maliban kung sisimulan mo ito gamit ang `DSH_TELEMETRY_MODE=DISABLED`.

### Ang default na agent

Piliin ang default agent mo gamit ang `omarchy default agent <name>` o sa ilalim ng _Agent > Harness_ sa Omarchy Menu (`Super + Space`). Kung hindi pa naka-install ang agent, i-install muna ito ng pagpili rito, at makakakuha rin ito ng sarili nitong launcher sa app launcher, sa tabi ng Agent. Aanyayahan ka ng isang bagong Omarchy na gawin ang pagpipiliang ito sa pamamagitan ng isang beses na notification.

Sinusubukan din ng pagpili sa Claude na i-set up ang browser extension nito para sa Chromium, Chrome, Brave, Brave Origin, at Edge. Nalalapat ang pag-setup ng extension sa lahat ng user at maaaring humingi ng password ng system mo; pipiliin at ilulunsad pa rin ang Claude kahit kanselahin o mabigo ang pag-install ng extension. I-restart ang browser mo, i-enable ang extension kung sinabihan, at mag-sign in sa Claude para tapusin ang pagkonekta nito. Patakbuhin ang `/chrome` sa Claude para suriin ang koneksyon. Hindi sinusuportahan ng Firefox at Zen ang extension na ito. Kung Claude na ang default mo bago idagdag ang setup na ito, piliin itong muli para mai-install ang extension.

Kapag nakapili ka na, ilulunsad ng `Super + Shift + Ctrl + A` ang default agent sa isang nakalaang terminal window (o ilalabas ang picker kung hindi ka pa nakakapili). Maaari mo rin itong ilunsad nang diretso sa isang gawain gamit ang `omarchy agent prompt "Review this project"`. Walang starting prompt ang Freebuff at DeepSeek Harness, kaya sa halip ay bubukas ang mga ito na nasa clipboard mo ang prompt para i-paste. Ang mga agent na inilunsad sa ganitong paraan ay tumatakbo nang unattended sa kani-kanilang don't-stop-to-ask mode, kaya maging handa na talagang gumawa ang mga ito ng mga bagay! Walang ganoong mode ang MiniMax Code para sa mga interactive session nito, kaya humihingi ito ng mga pahintulot gaya ng dati. At dahil tumatanggi ang mga agent na tandaan ang trust para sa home directory mo, sa halip ay nagsisimula sa `~/Work` ang mga paglunsad mula sa `$HOME`.

May mga terminal shortcut din: pinapatakbo ng `a` ang default agent nang inline sa kasalukuyang terminal, habang sinisimulan ng `c`, `cx`, at `cy` ang OpenCode, Claude Code, at Codex nang diretso (muli sa kani-kanilang auto-approving mode). Nagsi-sync din ang mga pagbabago ng theme sa mga agent: ang Claude Code, Pi, OpenCode, at Hermes (kapag na-install na ito ng Omarchy) ay sumusunod lahat kapag inililipat mo ang theme ng Omarchy.

### Ang iyong mga tagubilin sa agent

Ang mga personal na patakaran para sa bawat agent ay napupunta sa `~/.agents/AGENTS.md`, sa tabi ng mga shared skill sa `~/.agents/skills`. Buksan ito sa ilalim ng _Agent > Instructions_, na nagli-link din nito sa bawat harness na may sarili nitong global file: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, ang `~/.copilot/copilot-instructions.md` ng Copilot, at iba pa. Binabasa ng Crush at Amp ang link na `~/.config/AGENTS.md`, habang direktang binabasa ng omp, Kimi, at DeepSeek Harness ang `~/.agents/AGENTS.md`. Nagli-link din nito ang pagpili ng default agent. Ang isang instructions file na mayroon ka na ay nagiging shared na file kung wala pa noon; kung hindi, mananatili ito sa tabi ng link bilang `.bak`. Patakbuhin ang `omarchy agent instructions` para muling mag-link pagkatapos mag-install ng isa pang agent.

### Ang panel ng mga agent

Ang top bar ay may icon ng mga agent. Bago ka mag-set up ng agent, gagabayan ka ng panel nito sa pag-sign in sa Claude, Codex, o Grok, at ang una ay magiging default agent mo. Pagkatapos niyon, inilalagay ng panel ang bawat subscription sa isang page: bawat agent at account kasama ang plan nito, isang meter para sa bawat 5-hour session at weekly limit nito kasama ang oras hanggang mag-reset ito (mag-hover para sa eksaktong porsiyento), o ang natitirang prepaid balance, sa ilalim ng isang linya na umiikot sa kung ano ang ginamit mo sa lahat ng mga ito, tulad ng mga token ngayong linggo at ang pinakaginagamit mong model. Sa ilalim ng _Make something cool_ nag-aalok ito ng mga starter prompt para sa isang bagong theme, plugin, app, o game na nagbibigay ng gawain sa default agent mo. Ang mga app ay ginagawa sa paraang ginawa ang sariling Hype, Monologue, at Omacut ng Omarchy, sa C++ at Qt Quick, sumusunod sa omarchy-make-app agent skill, at naka-install na ang compiler at mga piraso ng Qt na kailangan nila. Ang mga game ay iisang three.js page sa `~/Games/vibes`, sumusunod sa omarchy-make-game agent skill, at lahat ay bubukas mula sa iisang Game Vibes launcher sa kasalukuyang theme; nilo-load nila ang three.js mula sa web, kaya kailangan nila ng koneksyon para magsimula. Saklaw agad ang Claude Code, Codex, Grok, Kimi, Cursor at ang Grok Bot allowance nito, GitHub Copilot, Muse, Antigravity, at Devin kasama ang mga limit nila, ang Kimchi kasama ang plan, prepaid credits, at spend budget nito, at ipinapakita ng Hermes, Mistral Vibe, at Qwen Code ang kanilang mga session at token kapag nagamit mo na sila. Lumalabas din ang mga provider plan at key na ginagamit mo sa pamamagitan ng pi, omp, o opencode: ang OpenCode Zen at Go, ang Z.ai GLM Coding Plan, Ollama Cloud, ang MiniMax Token Plan, at Synthetic kasama ang mga limit nila; ang OpenRouter at DeepSeek kasama ang mga prepaid balance nila; ang Fireworks kasama ang gastos nito sa nakalipas na 30 araw. Nabibilang din sa mga kabuuan ang mga token mula sa mga model na pinapatakbo mo sa sarili mong hardware; ang mga model mismo ay may sariling panel, na inilalarawan sa ilalim ng [Mga lokal na model](#local-models). Bawat agent ay binibilang nang isang beses, sa ilalim ng sinumang naniningil para rito, gaano man karaming harness ang patakbuhin mo rito.

I-left-click ang icon sa bar o pindutin ang `Super + Ctrl + X` para sa panel, i-right-click para ilunsad ang default agent mo, at i-middle-click para mag-refresh. Ang mga usage record sa likod nito ay muling ginagawa bawat 15 minuto ng `omarchy agent usage update`, at maaari pang pagsamahin ng panel ang usage mula sa iba mo pang machine sa pamamagitan ng isang naka-sync na folder. Tingnan ang README sa ilalim ng `$OMARCHY_PATH/shell/plugins/agents/` para sa buong mga setting.

### Maraming subscription

Kung nagbabayad ka para sa higit sa isang Claude, Codex, o Grok plan — isang personal na Max at isang pangtrabaho, halimbawa — maaaring panatilihin ng Omarchy na naka-sign in ang lahat ng mga ito at lumipat sa pagitan nila. Magdagdag ng subscription gamit ang + sa panel ng mga agent, na gagabay sa iyo roon mismo, o gamit ang `omarchy agent account add claude Work` (o `codex`, o `grok`). Ini-install nito ang CLI kung nawawala ito. Ang unang account para sa isang provider ay nagsa-sign in sa pamamagitan ng normal mong browser, mismo kung saan laging tumitingin ang CLI. Bawat susunod ay nagsa-sign in sa pamamagitan ng isang private window, kaya hindi aksidenteng makukuha ang account na naka-sign in na sa browser mo; mag-sign in doon bilang account na idinaragdag mo, at isara muna ang anumang private window na nakabukas na. Huwag kailanman mag-log out sa CLI para gawin ito: binabawi ng pag-log out ang naka-save na sign-in, at kailangang idagdag muli ang account na iyon.

Para kopyahin ang mga subscription login mo sa isa pang Omarchy machine sa pamamagitan ng SSH, patakbuhin ang `omarchy agent account copy user@laptop`. Nagbibigay ang sender ng pansamantalang receiver kapag walang naka-install ang destination, kaya makakatanggap ng mga account ang mas lumang Omarchy machine nang walang update. Inuuna ang mga naka-install na receiver. Kinokopya nito ang lahat ng Claude, Codex, at Grok subscription; magdagdag ng mga pangalan ng provider para piliin ang mga ito, gaya ng `omarchy agent account copy laptop claude`. Tumutugma sa source ang mga pangalan ng account at command ID, kabilang ang mga account na naroon na sa destination. Ang mga hindi kaugnay na destination account ay makakatanggap ng numeric suffix kung magkasalungat ang kanilang mga pangalan, at mananatiling lokal sa bawat machine ang mga setting, skill, plugin, at history ng pag-uusap.

Pinapanatili ang mga umiiral nang destination credential. Ang isang source account na naka-sign in na roon ay sini-synchronize ang pangalan nang hindi pinapalitan ang mga credential nito; ang ibang mga account ay idinaragdag sa tabi nito. Para palitan ang mga naka-save na credential para sa magkatugmang mga account, gamitin ang `omarchy agent account copy --replace laptop claude` pagkatapos isara ang mga session ng account na iyon sa destination. Makukuha rin ng isang bagong destination ang active account at mga kagustuhan sa paglipat ng source; pinapanatili ng isang matagal nang destination ang sarili nito.

Naglalakbay ang mga credential sa pamamagitan ng SSH at nakaimbak sa mga private file sa destination, kaya kumopya lamang sa mga machine na pinagkakatiwalaan mo. Ito ay isang beses na pagkopya, hindi patuloy na synchronization. Maaaring i-rotate ng ibang machine ang mga Codex refresh token, na mag-iiwan sa isang nakopyang login na nangangailangan ng pag-renew; ang magkakahiwalay na sign-in ang nananatiling pinakamaaasahang pagpipilian para sa sabay-sabay na paggamit sa maraming machine. Tingnan ang [gabay sa account authentication ng Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Isang account bawat provider ang active, at nagsisimula ang bawat bagong session bilang iyon: `cx`, `cy`, isang karaniwang `claude`, `codex`, o `grok`, anumang inilunsad sa pamamagitan ng `omarchy agent`, at mga script o editor na nakakahanap sa CLI sa `PATH`. Lumipat gamit ang `omarchy agent account use work` (at bumalik gamit ang `omarchy agent account use main`), o sa panel sa pamamagitan ng pagpindot sa numero ng isang account at pagkatapos sa `Enter` (o pag-click sa Use button nito). Lumilipat din ang mga tumatakbong Claude session, mula sa kanilang susunod na mensahe: bawat Claude session ay tumatakbo sa `~/.claude`, na laging naglalaman ng sign-in ng active account. Ang isang Claude session na sinimulan sa sariling folder ng isang account ng isang mas lumang Omarchy ay nagtataglay ng sign-in na iyon hanggang sa umalis ito, kaya pinangalanan ng paglipat ang mga session na iyon at kusang natatapos kapag wala na sila. Mananatili ang mga tumatakbong Codex at Grok session sa account na pinagsimulan nila. Ibinabahagi sa mga account ang history ng pag-uusap, mga setting, skill, at plugin, kaya ang `claude --continue` sa parehong folder ay magpapatuloy kung saan ka tumigil sa bagong account.

Kapag may higit sa isang account, ipinapakita ng panel ang mga limit ng bawat account nang magkatabi, na minarkahan ang active. Bilang default, inaabisuhan ka ng Omarchy kapag lumampas ang active account sa 95% ng isang limit, at ang pag-click sa notification ay lumilipat sa account na may pinakamaraming headroom. Mag-hover sa linya ng isang account sa panel at i-click ang Autoswitch na lalabas sa tabi ng Use (o pindutin ang `m`), o patakbuhin ang `omarchy agent account mode auto`, para kusang lumipat ito; habang naka-on ito, pumapalit ang Autoswitch sa Use, at ang pag-click muli rito ay bumabalik sa pag-abiso. Magdagdag ng numero para baguhin ang threshold, gaya ng `omarchy agent account mode auto 90`. Kung lahat ng account ay lagpas sa threshold, maririnig mo ito nang isang beses, kasama kung aling account ang unang magkakaroon ng puwang. Habang ang isang active account ay nasa loob ng 15 puntos ng threshold nito (80% sa default), sinusuri ang mga limit nito bawat tatlong minuto sa halip na bawat 15.

Ipinapakita ng `omarchy agent account list` ang bawat account at ang pinakabagong mga limit nito, nakakalimutan ng `omarchy agent account remove work` ang isa, at pinapalitan ng pangalan ng `omarchy agent account rename primary Hey` ang isa (o i-click ang pangalan ng isang account sa panel). Gumagana ang mga command na ito sa mga account ng default agent mo; para maabot ang ibang provider, pangalanan muna ito, gaya ng `omarchy agent account use codex side`. Ang login na mayroon ka na sa `~/.claude` o `~/.codex` ay ang _Main_ account. Mananatili ang sa Codex kung nasaan ito; naghihintay ang sa Claude sa sarili nitong folder habang may ibang account na active. Ang isang account na hindi ginagamit nang higit sa walong oras ay maaaring magpakita ng _Sign-in required_; i-click ito para muling mag-sign in sa account na iyon mismo sa panel, o lumipat dito at magsimula ng session, na kusang nagre-refresh ng sign-in. Ang mga MCP server na idinaragdag mo gamit ang `claude mcp add` ay umaabot sa bawat Claude account, dahil lahat sila ay tumatakbo sa `~/.claude`; para sa Codex at Grok, ang mga server na mayroon ka nang idagdag ang isang account ay kasama rito, ngunit ang mga susunod ay umaabot lamang sa account kung saan mo idinagdag ang mga ito. May sariling sign-in ang Claude Desktop, at ang mga Codex o Grok tool na naka-configure na may absolute path sa isang CLI binary ay hindi sumusunod sa paglipat. Inuuna ang isang tahasang `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, o `GROK_HOME` kaysa sa napiling account.

### Pag-diagnose ng crash

Binabantayan ng Omarchy ang systemd-coredump para sa mga pag-crash ng process. Kapag nakapili ka na ng default agent, anumang program mo na mag-dump ng core ay magdadala ng notification na "Process crashed" — i-click ito, at ibibigay ang crash sa default agent mo kasama ang omarchy-diagnose-crash skill ng Omarchy, na gagabay sa agent sa pagtatatag ng mga katotohanan mula sa core dump at pagpapasya kung sulit iulat ang crash upstream. Maaari mo rin itong patakbuhin nang mano-mano laban sa anumang PID mula sa `coredumpctl list` gamit ang `omarchy agent crash <pid>`.

Naka-on ang pagbantay bilang default. I-off ito sa ilalim ng _Trigger > Toggle > Crash Capture Off_ (o gamit ang `omarchy toggle crash-capture`) at hihinto ang mga notification; gumagana pa rin nang mano-mano ang `omarchy agent crash <pid>`.

Maaari ring patahimikin ang mga crash nang paisa-isang program, na siyang iniaalok sa iyo ng diagnosis sa dulo. Pinipigilan ng `omarchy crash mute hyprland` ang mga notification para sa program na iyon lamang, ibinabalik sila ng `omarchy crash mute hyprland off`, at inililista ng `omarchy crash mute` nang mag-isa kung ano ang na-mute mo. Tinatanggap nito ang path ng binary nang kasingdali ng pangalan nito, kaya ginagawa ng `omarchy crash mute /usr/bin/hyprland` ang parehong bagay. Mag-quote ng pangalang may puwang, gaya ng `omarchy crash mute 'Some App'`. Nag-aabiso pa rin ang lahat ng iba, at nagka-crash pa rin ang na-mute na program — itinatago nito ang paalala, hindi nito inaayos ang anuman.

### Mga desktop app

Ang menu na _Install > AI_ ay may dala ring ilang graphical AI app: Amp Desktop, Antigravity Desktop, ang ChatGPT desktop app, ang Claude desktop app (ang Linux beta ng Anthropic, na may mga tab na Chat, Cowork, at Claude Code), Grok Bot para makipag-chat sa mga model ng xAI, Herdr Desktop, Hermes Desktop, OpenClaw, ang Perplexity desktop app, at T3 Code. Ang Grok Bot ay ang desktop chat app. Ang coding agent ay ang command na `grok`.

Ang Hermes Desktop ang dapat mong malaman, dahil iisang Hermes lang ang mayroon ang isang machine, at pag-aari ito ng app: ang Hermes ay ini-install lamang kailanman sa pamamagitan ng app, at ang command na `hermes` na pinapatakbo ng default agent ay pag-aari ng app. Ang pagpili sa Hermes bilang default agent ay nag-i-install ng parehong bagay na ginagawa ng entry na _Install > AI_: ang package, at isang Hermes runtime sa ilalim ng `~/.hermes` na sine-set up ng sariling installer ng Hermes, na tumatagal ng ilang minuto sa unang pagkakataon. Ang runtime na iyon ang iisang Hermes na ginagamit ng terminal na command na `hermes`, ng default agent at ng app, at ina-update nito ang sarili gamit ang `hermes update` sa halip na maghintay sa isang Omarchy release. Binibigyan din ng pag-install nito ang Hermes ng theme ng Omarchy bilang isang skin na pinangalanang `omarchy`, na sinusunod ng bawat Hermes surface habang lumilipat ka ng mga theme; pumili ng iba sa ilalim ng mga Appearance setting ng Hermes o gamit ang `/skin` kung ayaw mo nito, at hahayaan ng Omarchy ang pagpipiliang iyon. Ang pag-alis sa app sa ilalim ng _Remove > AI_ ay nagsasara muna sa Hermes, kasama ang gateway, kasama ang runtime na iyon, at pinapanatili ang iyong mga chat, memory, at ang mga skill na isinulat ng Hermes para sa sarili nito maliban kung sasabihin mo kung hindi: nagtatanong ito, na ang default ay hindi, kung dapat ding alisin ang data na iyon at ang iyong mga connection setting.

Ang desktop experience ng OpenClaw ay ang Control UI nito, na bubukas bilang isang web app na sinusuportahan ng sarili nitong local gateway. Nakatira ang OpenClaw sa `~/.openclaw` at ina-update ang sarili nito: gamitin ang button na "Update Gateway" ng Control UI o patakbuhin ang `openclaw update`, at magre-restart ang gateway sa bagong bersyon. Pinipili lamang ng Omarchy ang release na pagsisimulan ng isang bagong install. Maaari ring maging default agent mo ang OpenClaw: ang pagpili rito sa ilalim ng _Agent > Harness_ ay nagse-set up ng parehong kopya sa `~/.openclaw`, at binubuksan ng agent ang terminal UI ng OpenClaw na nakakabit sa gateway nito. Ang pag-alis ng OpenClaw sa ilalim ng _Remove > AI_ ay kasama ang gateway service at ang app at pagkatapos ay nagtatanong kung dapat ding alisin ang `~/.openclaw`, dahil naglalaman iyon ng iyong mga chat at credential kasama ng OpenClaw mismo at ang mga plugin runtime na dina-download nito; pinapanatili ito ng default, at ang muling pag-install ng OpenClaw ay ibabalik ito.

Ang Herdr Desktop ay ang desktop app na [Herdr](https://herdr.dev): mga space, tab, at pane ng mga terminal at coding agent na patuloy na tumatakbo sa core nito kapag isinara mo ang window. Nagmumula ito sa sariling installer ng Herdr sa halip na isang package, kaya nakatira ito sa `~/.local/share/herdr-app`, dinadala ang core nito sa `~/.local/bin/herdr-core` kapag wala ka pa nito, at ina-update ang dalawa mismo. Nakatabi ito sa command na `herdr` na ibinibigay ng Omarchy sa `Super + Ctrl + Return` sa halip na palitan ito, at nakukuha ang mga direct key ng command na iyon: hinahati ng `Alt + Return` at `Alt + Shift + Return` ang isang pane pababa o pakanan, isinasara ito ng `Alt + Escape`, ang `Ctrl + Alt + Arrow` ay gumagalaw sa pagitan ng mga pane, pinipili ng `Alt + 1..9` at `Alt + Left/Right` ang isang tab, at ang `Alt + Up/Down` ay gumagalaw sa pagitan ng mga space. Pinipili ng `Ctrl + 1..9` ang isang space at ang `Alt + Shift + Up/Down` ay humahakbang sa mga agent. Ang mga `Ctrl + Space` prefix key ay nananatiling terminal lamang, dahil hindi mahawakan ng app ang isang karaniwang Ctrl key para sa isang sequence. Isinusulat ito ng Omarchy sa `~/.config/herdr-app/keys.json`, at ibinabalik sila ng `omarchy-refresh-herdr-app`. Pinipili ng pag-install nito ang Omarchy theme ng Herdr, na sumusunod sa theme ng Omarchy mo mula noon. Nagpapanatili ang Herdr ng isang theme para sa light mode at isa para sa dark, kaya pagkatapos lumipat sa pagitan ng isang dark at isang light na Omarchy theme, piliin muli ang Omarchy sa theme picker ng Herdr nang isang beses pa para sa kabilang mode.

Tumatakbo ang T3 Code mula sa opisyal nitong AppImage release sa `~/.local/share/t3code` sa halip na mula sa isang package, kaya ina-update nito ang sarili. Nagtatanong ang pag-install nito kung magsisimula sa Stable o Nightly channel; lumipat mamaya sa mga setting ng T3 Code. Nakatira ang iyong mga thread at setting sa `~/.t3`, at ang pag-alis ng T3 Code sa ilalim ng _Remove > AI_ ay kasama ang mga ito.

### Mga lokal na model

Magpatakbo ng isang open model sa sarili mong machine para sa iyong mga coding agent. Mananatili sa machine ang iyong mga prompt at code; walang ipinapadala sa model ang umaalis dito. Magsimula sa:

```bash
omarchy models use best text
```

Sine-set up nito ang pinakamahusay na text model para sa machine na ito, ang uri na ginagamit ng iyong mga agent. Ang mga image, video at music model ay may sarili nilang pinakamahusay: `omarchy models use best image`, `video` o `music`. Patakbuhin ang `omarchy models use best` para makita ang pinili ng bawat uri para sa machine na ito.

O buksan ang panel ng mga lokal na model mula sa sparkles icon nito sa top bar, sa tabi ng icon ng mga agent, o gamit ang Super + Ctrl + Shift + X, at piliin ang +. Lumalabas ang icon kapag kasya ang isang model sa machine na ito. Ang Podman, na nagpapatakbo ng mga model, ay kasama ng Omarchy, gayundin ang container toolkit ng NVIDIA sa isang NVIDIA machine, na nagbibigay sa kanila ng GPU; kung nawawala ang alinman, ini-install ito ng unang setup. Pagkatapos ay pinipili ng Omarchy ang inirerekomendang model para sa machine na ito, dina-download ito, at sinisimulan ito. Asahan ang download na sampu-sampung GB at ang karamihan sa memory ng machine ay gagamitin habang tumatakbo ang model: gumagamit ang Flash Next ng mga 100 GiB kasama ang buong 256K context nito. Kung hawak ng ibang mga model ang memory na kailangan nito, sine-set up itong nakahinto, handang magsimula kapag huminto ka ng isa. Humihinto ang model sa pag-logout; ihinto mo ito mismo kapag kailangan mo ang memory para sa iba.

Ipinapakita ng `omarchy models list` ang mga opsyon at ipinaliliwanag kung bakit hindi kasya ang ilan. Para mag-set up ng isa pa, patakbuhin ang `omarchy models use <recipe>`. Ngayon, available ang `qwen3.8-flash-next-gufo` at `qwen3.8-27b-gufo` para sa mga 128 GB Strix Halo machine; gumagamit ang 27B ng mga 40 GiB, kaya nag-iiwan ito ng puwang para sa ibang trabaho. Sa isang 64 GB laptop na may Intel's Arc B390, tumatakbo ang `qwen3.6-35b-a3b-llamacpp` sa mga 30 GiB. Dumating ang mga bagong recipe at rekomendasyon kasama ng `omarchy update`, sa pamamagitan ng package.

Bawat model na sine-set up mo ay nakakakuha ng sarili nitong linya sa panel ng mga lokal na model: play para simulan ito, pause para ihinto ito at palayain ang memory nito, at ang terminal button para buksan ang agent mo rito. Sa itaas, ipinapakita ng isang bar kung paano nahahati ang memory ng machine sa pagitan ng Omarchy mismo (ang system at iyong mga app), bawat tumatakbong model, at kung ano ang libre. Ituro ang isang nakahintong model at ipapakita ng bar kung kasya ito, o kung gaano ito kakulangan. Marami ang maaaring tumakbo nang sabay kapag magkakasya sila sa memory nang magkasama; kung hindi kasya ang isa, sasabihin ng Omarchy kung aling tumatakbong model ang ihihinto. I-drag ang mga linya sa pamamagitan ng kanilang logo para muling ayusin sila, at pindutin ang Delete sa isang napiling linya para alisin ang isang model at ang download nito.

Bawat model na sine-set up mo ay nakakakuha rin ng sarili nitong entry sa app launcher, sa ilalim ng pangalan ng model at kasama ang logo ng gumawa nito, sa paraang nagdaragdag ng isa ang pag-sign in sa Claude, Codex o Grok. Binubuksan nito ang agent mo sa model na iyon, at sinisimulan muna ang model kung hindi ito tumatakbo: ipinapakita ng terminal na nilo-load ito at ibibigay sa agent kapag handa na ito. Ang pag-alis ng isang model ay nag-aalis ng entry nito.

Hindi lahat ng model ay para sa coding. Ang mga image, video at music model ay bubukas sa halip sa Fantasi, ang app ng Omarchy para gumawa ng mga larawan, video at musika gamit ang isang model na tumatakbo sa machine na ito, mula sa kanilang launcher entry at mula sa kanilang linya sa panel ng mga lokal na model.

Patuloy na tumatakbo ang isang model nang eksakto kung paano ito sine-set up, kaya hindi kailanman nire-restart ng isang Omarchy update ang isa sa ilalim ng iyong mga agent. Kapag may mas bagong runtime o mas bagong weights ang Omarchy para sa isang model na sine-set up mo, ipinapakita ng linya nito ang isang update button: pindutin ito at sine-set up muli ang model sa background, dina-download lamang ang nagbago, at magre-restart sa bagong bersyon. Ang isang model na nakahinto ay mananatiling nakahinto. Ginagawa ng `omarchy models update` ang pareho para sa bawat model mula sa isang terminal.

Mula sa command line, ginagawa ng `omarchy models start <recipe>` at `omarchy models stop <recipe>` ang pareho, ipinapakita ng `omarchy models status` ang bawat model, at binubuksan ng `omarchy agent --local` ang default agent mo sa huling model na sinimulan mo. Maaaring gumamit nito ang pi, OpenCode at Qwen Code; sa anumang ibang default bubukas ito sa pi, o sa OpenCode kung wala kang pi. Inililista rin ng pi ang bawat model na sine-set up mo, at ang mga nasa machine na ipinares mo, sa sarili nitong model picker, kaya naaabot din sila ng karaniwang `pi`. Maaari ring kumonekta ang anumang OpenAI-compatible client: ipinapakita ng `status` ang address ng bawat model (ang una ay `http://127.0.0.1:11435/v1`), ang recipe name ang model, at ang key ay nasa `~/.config/omarchy/agent-local/key`.

Tinatanggal ng `omarchy models remove <recipe>` ang isang model at ang mga download na hindi ginagamit ng ibang model.

Ang mga third-party runtime ay nilagyan ng label ng kanilang publisher. Pinapatakbo ng Omarchy ang bawat model nang walang network access.

### Mga lokal na LLM

Inirerekomenda ng Omarchy ang dalawang paraan ng pagpapatakbo ng mga lokal na LLM model: LM Studio at Ollama. Nagbibigay ang LM Studio ng GUI interface para sa paghahanap ng mga open-weight model, pag-install sa kanila, at pagpapatakbo sa kanila. Mahusay itong paraan para madaling makapagsimula. Nag-aalok ang Ollama ng CLI para gawin din ito. Ngunit kung bago ka sa mga lokal na model, magsisimula ako sa LM Studio. Maaari mong i-install ang alinman sa ilalim ng _Install > AI_ sa Omarchy Menu.

### Ang mga skill ng Omarchy

Tumutulong ang mga agent skill sa AI na gumamit ng mga partikular na tool sa isang partikular na paraan, at nagbibigay ang Omarchy ng pito sa kanila. Saklaw ng omarchy skill ang pag-aangkop ng system, tulad ng pag-tweak ng Hyprland config mo o pag-aayos ng bar. Saklaw ng omarchy-make-theme, omarchy-make-plugin, omarchy-make-app, at omarchy-make-game ang paggawa ng bagong bagay, saklaw ng omarchy-contribute ang pag-uulat ng bug o pagpapadala ng fix upstream, at ginagawa ng omarchy-diagnose-crash ang core dump ng isang crash. Naka-symlink sila sa mga skill directory para sa Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` at bawat `~/.hermes/profiles/*/skills`), at ang generic na lokasyong `~/.agents/skills`, kaya karamihan ng mga harness ay kusang nakukuha sila. Inuuna ang isang skill folder mo na may parehong pangalan.

Ngunit dapat mong ituring na experimental ang mga skill na ito. Iba't ibang model ang gagamit nito sa iba't ibang epekto. Pinakamainam na tumakbo muna sa plan mode, para magkaroon ka ng ideya kung ano ang gustong baguhin ng agent. At pagkatapos ay maging handang i-rollback ang mga pagbabago o kahit tawagin ang `omarchy reinstall configs`, kung guguluhin ng agent ang lahat.
