Patakbuhin ang isang command para i-install ang CLI nito sa unang paggamit, pagkatapos ay mag-authenticate kapag sinabihan. ### Pag-install at pag-update ng mga agent

Maliban sa Hermes at OpenClaw, gumagamit ang mga agent na ito ng lazy installation ng mise: ini-install ng unang paglulunsad ang CLI, at muling ginagamit ito ng mga susunod na paglulunsad. Sinusuri rin ng mise ang isang naka-install na agent para sa bagong release nang hindi hihigit sa isang beses bawat apat na oras, bago ito magsimula o sa background sa isang shell prompt. Kung mabigo ang update na iyon o offline ka, tatakbo ang naka-install na bersyon. Ina-update ng `omarchy update` ang mga naka-install na agent kasama ang natitirang bahagi ng Omarchy, at ina-update ng `mup` ang mga tool na pinamamahalaan ng mise lamang.

Hindi ina-update ng sariling updater ng isang agent, gaya ng `claude update`, `codex update`, o isang update button sa isang app, ang install na pinamamahalaan ng mise. Nabibigo ang `codex update`, at maaaring mag-ulat ng tagumpay ang `claude update` habang nag-i-install ng hiwalay na kopyang hindi sinusubaybayan ng mise. Kung mas gusto mong gamitin ang katutubong installer at updater ng isang agent, idagdag ito sa `disable_tools`; tingnan ang [Mga paunang naka-install na CLI tool](18-development-tools.md#preinstalled-cli-tools).

Para i-install ang lahat ng naka-configure na lazy tool bago mo kailanganin ang mga ito, patakbuhin ang `mise install --include-lazy`. Kasama rito ang iba pang default na CLI tool ng Omarchy pati na rin ang mga agent. Tingnan ang [Mga paunang naka-install na CLI tool](18-development-tools.md#preinstalled-cli-tools) para sa pag-install ng isang tool o paggamit ng sarili mong installation.

Ini-install ang `grok` sa pamamagitan ng first-party na `grok` package ng mise, sa parehong paraan gaya ng `claude` at `codex`. Patakbuhin ang `grok`, o piliin ito sa ilalim ng _Agent > Harness_. Laktawan ang `curl | bash` installer sa x.ai. Naglalagay ang paraang iyon ng pangalawang kopya sa `~/.grok/bin`, inuuna ito sa `PATH`, at pinapatungan ang wrapper ng Omarchy.

Binubuksan ng `dsh` ang browser UI nito sa `127.0.0.1:3080`, na ang launch directory ang default nitong workspace. Hindi tumatanggap ang browser UI nito ng panimulang prompt, kaya binubuksan ito ng `omarchy agent prompt` na nasa clipboard mo ang prompt para i-paste. Sinisimulan ito ng Omarchy gamit ang no-approval na permission preset ng DeepSeek. Nag-a-upload ang DeepSeek Harness ng mga session log sa DeepSeek kapag ginagamit mo ang opisyal nitong model API; i-off iyon sa ilalim ng _Settings > General > Upload Session Log_ sa browser UI nito. Ang feedback na ipinapadala mo rito ay ina-upload din kasama ng session, maliban na lang kung sisimulan mo ito gamit ang `DSH_TELEMETRY_MODE=DISABLED`.

### Ang default na agent

Piliin ang iyong default na agent gamit ang `omarchy default agent <name>` o sa ilalim ng _Agent > Harness_ sa Omarchy Menu (`Super + Space`). Kung hindi pa naka-install ang agent, i-install muna ito ng pagpili rito, at makakakuha rin ito ng sarili nitong launcher sa app launcher, sa tabi ng Agent. Aanyayahan ka ng bagong Omarchy na gawin ang pagpipiliang ito gamit ang isang beses lang na notification.

Sinusubukan din ng pagpili sa Claude na i-setup ang browser extension nito para sa Chromium, Chrome, Brave, Brave Origin, at Edge. Nalalapat ang setup ng extension sa lahat ng user at maaaring humingi ng iyong system password; pipiliin at ilulunsad pa rin ang Claude kahit kanselahin o mabigo ang pag-install ng extension. I-restart ang iyong browser, i-enable ang extension kung sinabihan, at mag-sign in sa Claude para tapusin ang pagkonekta rito. Patakbuhin ang `/chrome` sa Claude para suriin ang koneksiyon. Hindi sinusuportahan ng Firefox at Zen ang extension na ito. Kung Claude na ang iyong default bago idinagdag ang setup na ito, piliin itong muli para i-install ang extension.

Kapag nakapili ka na, ilulunsad ng `Super + Shift + Ctrl + A` ang default na agent sa isang nakalaang terminal window (o ilalabas ang picker kung hindi ka pa nakakapili). Maaari mo rin itong ilunsad nang diretso sa isang gawain gamit ang `omarchy agent prompt "Review this project"`. Hindi tumatanggap ang Freebuff at DeepSeek Harness ng panimulang prompt, kaya sa halip ay bubukas ang mga ito na nasa clipboard mo ang prompt para i-paste. Tumatakbo nang walang bantay ang mga agent na inilunsad sa ganitong paraan sa kani-kanilang don't-stop-to-ask mode, kaya maging handa na talagang may gawin ang mga ito! Walang ganoong mode ang MiniMax Code para sa mga interactive session nito, kaya humihingi ito ng mga pahintulot gaya ng dati. At dahil tumatanggi ang mga agent na tandaan ang tiwala para sa iyong home directory, sa `~/Work` sa halip nagsisimula ang mga paglulunsad mula sa `$HOME`.

May mga terminal shortcut din: pinapatakbo ng `a` ang default na agent nang inline sa kasalukuyang terminal, habang sinisimulan ng `c`, `cx`, at `cy` ang OpenCode, Claude Code, at Codex nang direkta (muli sa kanilang mga auto-approving mode). Nagsi-sync din ang mga pagbabago ng tema sa mga agent: sumusunod ang Claude Code, Pi, OpenCode, at Hermes (kapag na-install na ito ng Omarchy) kapag lumipat ka ng tema ng Omarchy.

### Ang iyong mga tagubilin sa agent

Ang mga personal na patakaran para sa bawat agent ay nasa `~/.agents/AGENTS.md`, sa tabi ng mga shared skill sa `~/.agents/skills`. Buksan ito sa ilalim ng _Agent > Instructions_, na nagli-link din nito sa bawat harness na may sarili nitong global file: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, ang `~/.copilot/copilot-instructions.md` ng Copilot, at iba pa. Binabasa ng Crush at Amp ang link na `~/.config/AGENTS.md`, habang direktang binabasa ng omp, Kimi, at DeepSeek Harness ang `~/.agents/AGENTS.md`. Inili-link din ito ng pagpili ng default na agent. Ang file ng mga tagubilin na mayroon ka na ay magiging shared na file kung wala pa; kung hindi, itatabi ito sa tabi ng link bilang `.bak`. Patakbuhin ang `omarchy agent instructions` para muling i-link pagkatapos mag-install ng isa pang agent.

### Ang panel ng mga agent

May icon ng mga agent ang top bar. Bago ka makapag-setup ng agent, gagabayan ka ng panel nito sa pag-sign in sa Claude, Codex, o Grok, at ang una ay magiging iyong default na agent. Pagkatapos niyon, inilalagay ng panel ang bawat subscription sa isang pahina: bawat agent at account kasama ang plano nito, isang metro para sa bawat 5-oras na session at lingguhang limit nito kasama ang oras hanggang mag-reset ito (i-hover para sa eksaktong porsiyento), o ang natitirang prepaid na balanse, sa ilalim ng isang linyang umiikot sa kung ano ang nagamit mo sa lahat ng mga ito, gaya ng mga token ngayong linggo at ang pinakamadalas mong ginamit na modelo. Sa ilalim ng _Make something cool_ nag-aalok ito ng mga panimulang prompt para sa bagong tema, plugin, app, o laro na nagbibigay ng gawain sa iyong default na agent. Ginagawa ang mga app sa paraang ginawa ng Omarchy ang sarili nitong Hype, Monologue, at Omacut, sa C++ at Qt Quick, na sumusunod sa omarchy-make-app agent skill, at naka-install na ang compiler at mga piraso ng Qt na kailangan nila. Ang mga laro ay iisang three.js page sa `~/Games/vibes`, na sumusunod sa omarchy-make-game agent skill, at lahat ay bubukas mula sa isang Game Vibes launcher sa kasalukuyang tema; nilo-load nila ang three.js mula sa web, kaya kailangan nila ng koneksiyon para magsimula. Saklaw agad ang Claude Code, Codex, Grok, Kimi, Cursor at ang Grok Bot allowance nito, GitHub Copilot, Muse, Antigravity, at Devin kasama ang kanilang mga limit, ang Kimchi kasama ang plano nito, prepaid credits, at spend budgets, at ipinapakita ng Hermes, Mistral Vibe, at Qwen Code ang kanilang mga session at token kapag nagamit mo na ang mga ito. Lumalabas din ang mga provider plan at key na ginagamit mo sa pamamagitan ng pi, omp, o opencode: OpenCode Zen at Go, ang Z.ai GLM Coding Plan, Ollama Cloud, ang MiniMax Token Plan, at Synthetic kasama ang kanilang mga limit; OpenRouter at DeepSeek kasama ang kanilang mga prepaid na balanse; Fireworks kasama ang gastos nito sa nakalipas na 30 araw. Nabibilang din sa mga kabuuan ang mga token mula sa mga modelong pinapatakbo mo sa sarili mong hardware; may sariling panel ang mga modelo mismo, na inilalarawan sa ilalim ng [Mga lokal na modelo](#local-models). Bawat agent ay binibilang nang isang beses, sa ilalim ng kung sino man ang naniningil para rito, gaano man karaming harness mo ito idaan.

I-left-click ang icon sa bar o pindutin ang `Super + Ctrl + X` para sa panel, i-right-click para ilunsad ang iyong default na agent, at i-middle-click para mag-refresh. Ang mga usage record sa likod nito ay muling ginagawa bawat 15 minuto ng `omarchy agent usage update`, at maaari pang pagsamahin ng panel ang usage mula sa iba mo pang mga makina sa pamamagitan ng isang naka-sync na folder. Tingnan ang README sa ilalim ng `$OMARCHY_PATH/shell/plugins/agents/` para sa buong mga setting.

### Ilang subscription

Kung nagbabayad ka para sa higit sa isang plano ng Claude, Codex, o Grok — isang personal na Max at isang pang-trabaho, halimbawa — maaaring panatilihing naka-sign in ng Omarchy ang lahat ng mga ito at lumipat-lipat sa pagitan ng mga ito. Magdagdag ng subscription gamit ang + sa panel ng mga agent, na gagabay sa iyo roon mismo, o gamit ang `omarchy agent account add claude Work` (o `codex`, o `grok`). Ini-install nito ang CLI kung nawawala ito. Ang unang account para sa isang provider ay nag-sa-sign in sa pamamagitan ng iyong normal na browser, eksakto kung saan palaging tumitingin ang CLI. Ang bawat susunod ay nag-sa-sign in sa pamamagitan ng private window, kaya hindi aksidenteng makuha ang account na naka-sign in na sa iyong browser; mag-sign in doon bilang account na idinaragdag mo, at isara muna ang anumang private window na nakabukas mo na. Huwag kailanman mag-log out sa CLI para gawin ito: binabawi ng pag-log out ang naka-save na sign-in, at kailangang idagdag muli ang account na iyon.

Para kopyahin ang iyong mga subscription login sa isa pang Omarchy machine sa SSH, patakbuhin ang `omarchy agent account copy user@laptop`. Nagbibigay ang nagpadala ng pansamantalang receiver kapag walang naka-install ang patutunguhan, kaya maaaring makatanggap ng mga account ang mas lumang mga Omarchy machine nang walang update. Nauuna ang mga naka-install na receiver. Kinokopya nito ang lahat ng subscription ng Claude, Codex, at Grok; magdagdag ng mga pangalan ng provider para piliin ang mga ito, gaya sa `omarchy agent account copy laptop claude`. Tumutugma ang mga pangalan ng account at command ID sa pinagmulan, kasama ang mga account na mayroon na sa patutunguhan. Makakatanggap ang mga hindi magkaugnay na account sa patutunguhan ng numeric suffix kung magkasalungat ang kanilang mga pangalan, at mananatiling lokal sa bawat makina ang mga setting, skill, plugin, at history ng pag-uusap.

Pinapanatili ang mga umiiral na kredensyal sa patutunguhan. Ang isang source account na naka-sign in na roon ay isi-sync ang pangalan nito nang hindi pinapalitan ang mga kredensyal nito; idinaragdag ang iba pang mga account sa tabi nito. Para palitan ang mga naka-save na kredensyal para sa magkatugmang mga account, gamitin ang `omarchy agent account copy --replace laptop claude` pagkatapos isara ang mga session ng account na iyon sa patutunguhan. Makukuha rin ng bagong patutunguhan ang aktibong account at mga kagustuhan sa paglipat ng pinagmulan; pinapanatili ng naitatag nang patutunguhan ang sarili nito.

Naglalakbay ang mga kredensyal sa pamamagitan ng SSH at nakaimbak sa mga pribadong file sa patutunguhan, kaya kumopya lamang sa mga makinang pinagkakatiwalaan mo. Ito ay isang beses na kopya, hindi patuloy na pag-synchronize. Maaaring i-rotate ng ibang makina ang mga Codex refresh token, na mag-iiwan sa kinopyang login na nangangailangan ng pag-renew; ang magkakahiwalay na sign-in ang nananatiling pinaka-maaasahang pagpipilian para sa sabay-sabay na paggamit sa ilang makina. Tingnan ang [Gabay sa pagpapatunay ng account ng Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Isang account bawat provider ang aktibo, at bawat bagong session ay nagsisimula bilang ito: `cx`, `cy`, isang simpleng `claude`, `codex`, o `grok`, anumang inilunsad sa pamamagitan ng `omarchy agent`, at mga script o editor na nakakahanap sa CLI sa `PATH`. Lumipat gamit ang `omarchy agent account use work` (at bumalik gamit ang `omarchy agent account use main`), o sa panel sa pamamagitan ng pagpindot sa numero ng isang account at pagkatapos sa `Enter` (o pag-click sa Use button nito). Lumilipat din ang mga tumatakbong Claude session, mula sa kanilang susunod na mensahe: bawat Claude session ay tumatakbo sa `~/.claude`, na palaging naglalaman ng sign-in ng aktibong account. Ang isang Claude session na sinimulan sa sariling folder ng isang account ng mas lumang Omarchy ay nagpapanatili ng sign-in na iyon hanggang sa isara ito, kaya pinangalanan ng paglipat ang mga session na iyon at matatapos nang kusa kapag wala na ang mga ito. Mananatili ang mga tumatakbong Codex at Grok session sa account na pinagsimulan nila. Ibinabahagi ang history ng pag-uusap, mga setting, skill, at plugin sa mga account, kaya ipagpapatuloy ng `claude --continue` sa parehong folder kung saan ka tumigil sa bagong account.

Kapag may higit sa isang account, ipinapakita ng panel ang mga limit ng bawat account nang magkatabi, na minarkahan ang aktibo. Bilang default, inaabisuhan ka ng Omarchy kapag lumampas ang aktibong account sa 95% ng isang limit, at ang pag-click sa notification ay lumilipat sa account na may pinakamaraming natitirang puwang. I-hover ang linya ng isang account sa panel at i-click ang Autoswitch na lalabas sa tabi ng Use (o pindutin ang `m`), o patakbuhin ang `omarchy agent account mode auto`, para lumipat ito nang kusa sa halip; habang naka-on ito, pumapalit ang Autoswitch sa Use, at ang muling pag-click rito ay babalik sa pag-aabiso. Magdagdag ng numero para baguhin ang threshold, gaya sa `omarchy agent account mode auto 90`. Kung ang bawat account ay lampas sa threshold, maririnig mo ito nang isang beses, kasama kung aling account ang unang magkakaroon ng puwang. Habang ang isang aktibong account ay nasa loob ng 15 puntos ng threshold nito (80% sa default), sinusuri ang mga limit nito bawat tatlong minuto sa halip na bawat 15.

Ang `omarchy agent account list` ay nagpapakita ng bawat account at ang pinakabagong mga limit nito, ang `omarchy agent account remove work` ay nakakalimot ng isa, at ang `omarchy agent account rename primary Hey` ay nagpapalit ng pangalan ng isa (o i-click ang pangalan ng isang account sa panel). Gumagana ang mga command na ito sa mga account ng iyong default na agent; para maabot ang ibang provider, pangalanan muna ito, gaya sa `omarchy agent account use codex side`. Ang login na mayroon ka na sa `~/.claude` o `~/.codex` ay ang _Main_ account. Mananatili ang sa Codex kung nasaan ito; naghihintay ang sa Claude sa sarili nitong folder habang aktibo ang isa pang account. Ang isang account na hindi nagamit nang higit sa walong oras ay maaaring magpakita ng _Sign-in required_; i-click ito para muling i-sign in ang account na iyon mismo sa panel, o lumipat dito at magsimula ng session, na nagre-refresh ng sign-in nang kusa. Ang mga MCP server na idinaragdag mo gamit ang `claude mcp add` ay umaabot sa bawat Claude account, dahil lahat sila ay tumatakbo sa `~/.claude`; para sa Codex at Grok, ang mga server na mayroon ka noong idinagdag ang isang account ay sumasama rito, ngunit ang mga susunod ay umaabot lamang sa account kung saan mo idinagdag ang mga ito. May sariling sign-in ang Claude Desktop, at hindi sumusunod sa paglipat ang mga Codex o Grok tool na naka-configure gamit ang absolute path patungo sa isang CLI binary. Nauuna ang isang tahasang `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, o `GROK_HOME` kaysa sa napiling account.

### Pag-diagnose ng crash

Binabantayan ng Omarchy ang systemd-coredump para sa mga pag-crash ng proseso. Kapag nakapili ka na ng default na agent, ang anumang programa mo na nagda-dump ng core ay magdadala ng notification na "Process crashed" — i-click ito, at ibibigay ang crash sa iyong default na agent kasama ang omarchy-diagnose-crash skill ng Omarchy, na gagabay sa agent sa pagtatatag ng mga katotohanan mula sa core dump at pagpapasya kung sulit iulat ang crash sa upstream. Maaari mo rin itong patakbuhin nang mano-mano laban sa anumang PID mula sa `coredumpctl list` gamit ang `omarchy agent crash <pid>`.

Naka-on bilang default ang pagbabantay. I-off ito sa ilalim ng _Trigger > Toggle > Crash Capture Off_ (o gamit ang `omarchy toggle crash-capture`) at hihinto ang mga notification; gumagana pa rin nang mano-mano ang `omarchy agent crash <pid>`.

Maaari ring patahimikin ang mga crash nang paisa-isa bawat programa, na siyang inaalok sa iyo ng diagnosis sa dulo. Pinipigilan ng `omarchy crash mute hyprland` ang mga notification para sa programang iyon lamang, ibinabalik sila ng `omarchy crash mute hyprland off`, at inililista ng `omarchy crash mute` nang mag-isa kung ano ang iyong na-mute. Tumatanggap ito ng path ng binary nang kasing saya ng pangalan nito, kaya pareho ang ginagawa ng `omarchy crash mute /usr/bin/hyprland`. Mag-quote ng pangalan na may espasyo, gaya sa `omarchy crash mute 'Some App'`. Nag-aabiso pa rin ang lahat ng iba, at magka-crash pa rin ang na-mute na programa — itinatago nito ang paalala, hindi nito inaayos ang anuman.

### Mga desktop app

May dala ring ilang graphical AI app ang menu na _Install > AI_: Amp Desktop, Antigravity Desktop, ang ChatGPT desktop app, ang Claude desktop app (ang Linux beta ng Anthropic, na may mga tab na Chat, Cowork, at Claude Code), Grok Bot para sa pakikipag-chat sa mga modelo ng xAI, Herdr Desktop, Hermes Desktop, OpenClaw, ang Perplexity desktop app, at T3 Code. Ang Grok Bot ay ang desktop chat app. Ang coding agent ay ang `grok` command.

Ang Hermes Desktop ang dapat mong malaman, dahil iisa lang ang Hermes ng isang makina, at pag-aari ito ng app: ini-install lang kailanman ang Hermes sa pamamagitan ng app, at ang `hermes` command na pinapatakbo ng default na agent ay sa app. Ang pagpili sa Hermes bilang default na agent ay nag-i-install ng parehong bagay na ginagawa ng entry na _Install > AI_: ang package, at isang Hermes runtime sa ilalim ng `~/.hermes` na sine-setup ng sariling installer ng Hermes, na tumatagal ng ilang minuto sa unang pagkakataon. Ang runtime na iyon ang nag-iisang Hermes na ginagamit ng terminal na `hermes` command, ng default na agent at ng app, at ina-update nito ang sarili gamit ang `hermes update` sa halip na maghintay sa isang Omarchy release. Binibigyan din ng pag-install nito ang Hermes ng tema ng Omarchy bilang skin na pinangalanang `omarchy`, na sinusundan ng bawat Hermes surface habang nagpapalit ka ng tema; pumili ng iba sa ilalim ng Appearance settings ng Hermes o gamit ang `/skin` kung ayaw mo niyon, at hahayaan ng Omarchy ang pagpipiliang iyon. Ang pag-alis ng app sa ilalim ng _Remove > AI_ ay nagsasara muna sa Hermes, kasama ang gateway, isinasama ang runtime na iyon, at pinapanatili ang iyong mga chat, memory, at ang mga skill na isinulat ng Hermes para sa sarili maliban na lang kung sasabihin mong hindi: nagtatanong ito, na ang default ay hindi, kung dapat ding alisin ang data na iyon at ang iyong mga connection setting.

Ang desktop experience ng OpenClaw ay ang Control UI nito, na bubukas bilang web app na sinusuportahan ng sarili nitong lokal na gateway. Nakatira ang OpenClaw sa `~/.openclaw` at ina-update ang sarili: gamitin ang button na "Update Gateway" ng Control UI o patakbuhin ang `openclaw update`, at magre-restart ang gateway sa bagong bersyon. Pinipili lang ng Omarchy ang release na pagsisimulan ng bagong install. Maaari ding maging iyong default na agent ang OpenClaw: ang pagpili rito sa ilalim ng _Agent > Harness_ ay nagse-setup ng parehong kopyang iyon sa `~/.openclaw`, at binubuksan ng agent ang terminal UI ng OpenClaw na nakakabit sa gateway nito. Ang pag-alis ng OpenClaw sa ilalim ng _Remove > AI_ ay isinasama ang gateway service at ang app at pagkatapos ay nagtatanong kung dapat ding alisin ang `~/.openclaw`, dahil naroon ang iyong mga chat at kredensyal kasama ang OpenClaw mismo at ang mga plugin runtime na dina-download nito; pinapanatili ito ng default, at kukunin itong muli ng muling pag-install ng OpenClaw.

Ang Herdr Desktop ay ang desktop app ng [Herdr](https://herdr.dev): mga space, tab, at pane ng mga terminal at coding agent na patuloy na tumatakbo sa core nito kapag isinara mo ang window. Nagmumula ito sa sariling installer ng Herdr sa halip na sa isang package, kaya nakatira ito sa `~/.local/share/herdr-app`, isinasama ang core nito sa `~/.local/bin/herdr-core` kapag wala ka pa nito, at ina-update ang sarili nitong dalawa. Nakatabi ito sa `herdr` command na ipinapadala ng Omarchy sa `Super + Ctrl + Return` sa halip na palitan ito, at nakukuha nito ang mga direct key ng command na iyon: hinahati ng `Alt + Return` at `Alt + Shift + Return` ang isang pane pababa o pakanan, isinasara ito ng `Alt + Escape`, gumagalaw ang `Ctrl + Alt + Arrow` sa pagitan ng mga pane, pumipili ng tab ang `Alt + 1..9` at `Alt + Left/Right`, at gumagalaw ang `Alt + Up/Down` sa pagitan ng mga space. Pumipili ng space ang `Ctrl + 1..9` at ang `Alt + Shift + Up/Down` ay humahakbang sa mga agent. Mananatiling terminal-only ang mga `Ctrl + Space` prefix key, dahil hindi kayang hawakan ng app ang isang simpleng Ctrl key para sa isang sequence. Isinusulat ito ng Omarchy sa `~/.config/herdr-app/keys.json`, at ibinabalik sila ng `omarchy-refresh-herdr-app`. Pinipili ng pag-install nito ang Omarchy theme ng Herdr, na susunod sa iyong Omarchy theme mula noon. Nagpapanatili ang Herdr ng isang tema para sa light mode at isa para sa dark, kaya pagkatapos lumipat sa pagitan ng dark at light na Omarchy theme, piliin muli ang Omarchy sa theme picker ng Herdr para sa kabilang mode.

Tumatakbo ang T3 Code mula sa opisyal nitong AppImage release sa `~/.local/share/t3code` sa halip na mula sa isang package, kaya ina-update nito ang sarili. Nagtatanong ang pag-install nito kung magsisimula sa Stable o Nightly channel; lumipat mamaya sa mga setting ng T3 Code. Ang iyong mga thread at setting ay nasa `~/.t3`, at ang pag-alis ng T3 Code sa ilalim ng _Remove > AI_ ay isinasama ang mga ito.

### Mga lokal na modelo

Patakbuhin ang isang open model sa sarili mong makina para sa iyong mga coding agent. Mananatili sa makina ang iyong mga prompt at code; walang ipinapadala sa modelo ang aalis dito. Magsimula sa:

```bash
omarchy models use best text
```

Sine-setup niyon ang pinakamahusay na text model para sa makinang ito, ang uri na ginagamit ng iyong mga agent. May sarili ring pinakamahusay ang mga image, video at music model: `omarchy models use best image`, `video` o `music`. Patakbuhin ang `omarchy models use best` para makita ang pinili ng bawat uri para sa makinang ito.

O buksan ang panel ng mga lokal na modelo mula sa sparkles icon nito sa top bar, sa tabi ng icon ng mga agent, o gamit ang Super + Ctrl + Alt + X, at piliin ang +. Lumalabas ang icon kapag kasya ang isang modelo sa makinang ito. Ang Podman, na nagpapatakbo sa mga modelo, ay kasama ng Omarchy, gaya ng NVIDIA's container toolkit sa isang NVIDIA machine, na nagbibigay sa kanila ng GPU; kung nawawala ang alinman, ini-install ito ng unang setup. Pagkatapos ay pipiliin ng Omarchy ang inirerekomendang modelo para sa makinang ito, ida-download ito, at sisimulan ito. Asahan ang download na sampu-sampung GB at ang karamihan ng memory ng makina ay ginagamit habang tumatakbo ang modelo: gumagamit ang Flash Next ng humigit-kumulang 100 GiB sa buong 256K context nito. Kung hawak ng ibang mga modelo ang memory na kailangan nito, sine-setup itong nakahinto, handang magsimula kapag pinahinto mo ang isa. Humihinto ang modelo sa pag-logout; pahintuin mo ito mismo kapag kailangan mo ang memory para sa ibang bagay.

Ang `omarchy models list` ay nagpapakita ng mga opsyon at nagpapaliwanag kung bakit hindi kasya ang ilan. Para mag-setup ng isa pa, patakbuhin ang `omarchy models use <recipe>`. Ngayon, available ang `qwen3.8-flash-next-gufo` at `qwen3.8-27b-gufo` para sa mga 128 GB Strix Halo machine; gumagamit ang 27B ng humigit-kumulang 40 GiB, kaya nag-iiwan ito ng puwang para sa iba pang trabaho. Sa isang 64 GB laptop na may Intel's Arc B390, tumatakbo ang `qwen3.6-35b-a3b-llamacpp` sa humigit-kumulang 30 GiB. Dumarating ang mga bagong recipe at rekomendasyon kasama ng `omarchy update`, sa pamamagitan ng package.

Bawat modelong sine-setup mo ay may sarili nitong linya sa panel ng mga lokal na modelo: play para simulan ito, pause para pahintuin ito at palayain ang memory nito, at ang terminal button para buksan ang iyong agent dito. Sa itaas, ipinapakita ng isang bar kung paano nahahati ang memory ng makina sa pagitan ng Omarchy mismo (ang system at ang iyong mga app), bawat tumatakbong modelo, at kung ano ang libre. Ituro ang isang nakahintong modelo at ipapakita ng bar kung kasya ito, o kung gaano ito kakulangan. Marami ang maaaring tumakbo nang sabay kapag kasya sila nang magkasama sa memory; kung hindi kasya ang isa, sasabihin ng Omarchy kung aling tumatakbong modelo ang pahihintuin. I-drag ang mga linya gamit ang logo ng mga ito para muling ayusin ang mga ito, at pindutin ang Delete sa isang napiling linya para alisin ang isang modelo at ang download nito.

Bawat coding model na sine-setup mo ay may sarili ring entry sa app launcher, sa ilalim ng pangalan ng modelo at kasama ang logo ng gumawa nito, sa paraang ang pag-sign in sa Claude, Codex o Grok ay nagdaragdag ng isa. Binubuksan nito ang iyong agent sa modelong iyon, at sinisimulan muna ang modelo kung hindi ito tumatakbo: ipinapakita ng terminal na naglo-load ito at ibibigay sa agent kapag handa na ito. Ang pag-alis ng isang modelo ay nag-aalis ng entry nito.

Hindi lahat ng modelo ay para sa coding. Ang mga image, video at music model ay bubukas sa Fantasi sa halip, ang app ng Omarchy para sa paggawa ng mga larawan, video at musika gamit ang modelong tumatakbo sa makinang ito, na pinili roon o mula sa kanilang linya sa panel ng mga lokal na modelo.

Mananatiling tumatakbo ang isang modelo nang eksakto kung paano ito sine-setup, kaya hindi kailanman ire-restart ng isang Omarchy update ang isa sa ilalim ng iyong mga agent. Kapag may mas bagong runtime o mas bagong weights ang Omarchy para sa isang modelong sine-setup mo, ipapakita ng linya nito ang isang update button: pindutin ito at muling sine-setup ang modelo sa background, dina-download lang kung ano ang nagbago, at magre-restart sa bagong bersyon. Mananatiling nakahinto ang isang modelong nakahinto. Ginagawa ng `omarchy models update` ang pareho para sa bawat modelo mula sa isang terminal.

Mula sa command line, ginagawa ng `omarchy models start <recipe>` at `omarchy models stop <recipe>` ang pareho, ipinapakita ng `omarchy models status` ang bawat modelo, at binubuksan ng `omarchy agent --local` ang iyong default na agent sa huling modelong sinimulan mo. Maaaring gumamit ang pi, OpenCode at Qwen Code ng isa; sa anumang ibang default bubukas ito sa pi, o sa OpenCode kung wala kang pi. Inililista rin ng pi ang bawat modelong sine-setup mo, at ang mga nasa mga makinang ipinares mo, sa sarili nitong model picker, kaya naaabot din sila ng simpleng `pi`. Maaari ring kumonekta ang anumang OpenAI-compatible client: ipinapakita ng `status` ang address ng bawat modelo (ang una ay `http://127.0.0.1:11435/v1`), ang recipe name ang modelo, at ang key ay nasa `~/.config/omarchy/agent-local/key`.

Ang `omarchy models remove <recipe>` ay nagbubura ng isang modelo at ng mga download na hindi ginagamit ng ibang modelo.

Nalagyan ng label ng kanilang publisher ang mga third-party runtime. Pinapatakbo ng Omarchy ang bawat modelo nang walang network access.

### Mga lokal na LLM

Inirerekomenda ng Omarchy ang dalawang paraan ng pagpapatakbo ng mga lokal na LLM model: LM Studio at Ollama. Nagbibigay ang LM Studio ng GUI interface para sa paghahanap ng mga open-weight model, pag-install ng mga ito, at pagpapatakbo ng mga ito. Mahusay itong paraan para madaling makapagsimula. Nag-aalok ang Ollama ng CLI para gawin ito nang katulad. Ngunit kung bago ka sa mga lokal na modelo, magsisimula ako sa LM Studio. Maaari mong i-install ang alinman sa ilalim ng _Install > AI_ sa Omarchy Menu.

### Ang mga Omarchy skill

Tumutulong ang mga agent skill sa AI na gumamit ng mga partikular na tool sa isang partikular na paraan, at nagpapadala ang Omarchy ng pito sa mga ito. Sinasaklaw ng omarchy skill ang pag-aangkop ng system, gaya ng pag-tweak ng iyong Hyprland config o pag-aayos ng bar. Sinasaklaw ng omarchy-make-theme, omarchy-make-plugin, omarchy-make-app, at omarchy-make-game ang paggawa ng bagong bagay, sinasaklaw ng omarchy-contribute ang pag-uulat ng bug o pagpapadala ng fix sa upstream, at ginagawa ng omarchy-diagnose-crash ang core dump ng isang crash. Naka-symlink sila sa mga skill directory para sa Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` at bawat `~/.hermes/profiles/*/skills`), at ang generic na lokasyon ng `~/.agents/skills`, kaya awtomatikong nakukuha sila ng karamihan sa mga harness. Nauuna ang isang skill folder mo na may parehong pangalan.

Ngunit dapat mong ituring na eksperimental ang mga skill na ito. Iba't ibang modelo ang gagamit nito sa iba't ibang epekto. Pinakamainam na tumakbo muna sa plan mode, para magkaroon ka ng ideya kung ano ang gustong baguhin ng agent. At pagkatapos ay maging handang i-rollback ang mga pagbabago o kahit tawagin ang `omarchy reinstall configs`, kung guguluhin ng agent ang lahat.
