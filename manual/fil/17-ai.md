# AI

Kasama sa Omarchy ang mga launcher para sa mga coding agent sa ibaba nang hindi pumipili ng default para sa iyo. Magpatakbo ng utos upang i-install ang CLI nito sa unang paggamit, pagkatapos ay mag-authenticate kapag sinabihan. Ang Hermes ang eksepsiyon: walang ini-install para dito sa unang paggamit, at ang pagpili dito ang nag-i-install ng Hermes Desktop, gaya ng ipinaliliwanag ng _Mga desktop app_ sa ibaba.

### Pag-install at pag-update ng mga agent

Maliban sa Hermes, gumagamit ang mga agent na ito ng lazy installation ng mise: ini-install ng unang paglunsad ang CLI, at muling ginagamit ito ng mga susunod na paglunsad. Sinusuri rin ng mise ang isang naka-install na agent para sa bagong release nang hindi hihigit sa isang beses bawat apat na oras, bago ito magsimula o sa background sa isang shell prompt. Kung mabigo ang update na iyon o offline ka, tatakbo ang naka-install na bersyon. Ina-update ng `omarchy update` ang mga naka-install na agent kasama ng iba pa sa Omarchy, at ina-update ng `mup` ang mga tool na pinamamahalaan ng mise lamang.

Hindi ina-update ng sariling updater ng isang agent, gaya ng `claude update`, `codex update`, o ng update button sa isang app, ang install na pinamamahalaan ng mise. Nabibigo ang `codex update`, at maaaring mag-ulat ng tagumpay ang `claude update` habang nag-i-install ng hiwalay na kopya na hindi sinusubaybayan ng mise. Kung mas gusto mong gamitin ang native na installer at updater ng isang agent, idagdag ito sa `disable_tools`; tingnan ang [Mga paunang naka-install na CLI tool](18-development-tools.md#preinstalled-cli-tools).

Upang i-install ang lahat ng naka-configure na lazy tool bago mo kailanganin ang mga ito, patakbuhin ang `mise install --include-lazy`. Kasama rito ang iba pang default na CLI tool ng Omarchy pati na rin ang mga agent. Tingnan ang [Mga paunang naka-install na CLI tool](18-development-tools.md#preinstalled-cli-tools) para sa pag-install ng iisang tool o paggamit ng sarili mong installation.

Ini-install ang `grok` sa pamamagitan ng first-party na `grok` package ng mise, sa parehong paraan gaya ng `claude` at `codex`. Patakbuhin ang `grok`, o piliin ito sa ilalim ng _Agent > Harness_. Laktawan ang `curl | bash` installer sa x.ai. Naglalagay ang paraang iyon ng pangalawang kopya sa `~/.grok/bin`, inuuna ito sa `PATH`, at pinapatungan ang wrapper ng Omarchy.

Binubuksan ng `dsh` ang browser UI nito sa `127.0.0.1:3080`, na ang launch directory ang default na workspace nito. Hindi tumatanggap ang browser UI nito ng panimulang prompt, kaya binubuksan ito ng `omarchy agent prompt` na nasa iyong clipboard ang prompt upang i-paste. Sinisimulan ito ng Omarchy gamit ang no-approval na permission preset ng DeepSeek. Ina-upload ng DeepSeek Harness ang mga session log sa DeepSeek kapag ginagamit mo ang opisyal nitong model API; i-off iyon sa ilalim ng _Settings > General > Upload Session Log_ sa browser UI nito. Ang feedback na ipinapadala mo dito ay ina-upload din kasama ng session, maliban kung sisimulan mo ito gamit ang `DSH_TELEMETRY_MODE=DISABLED`.

### Ang default na agent

Piliin ang iyong default na agent gamit ang `omarchy default agent <name>` o sa ilalim ng _Agent > Harness_ sa Omarchy Menu (`Super + Space`). Kung hindi pa naka-install ang agent, ang pagpili dito ang unang mag-i-install dito. Aayain ka ng bagong Omarchy na gawin ang pagpilìng ito sa pamamagitan ng isang beses lang na notification.

Sinusubukan ding i-set up ng pagpili sa Claude ang browser extension nito para sa Chromium, Chrome, Brave, Brave Origin, at Edge. Nalalapat ang extension setup sa lahat ng user at maaaring humingi ng iyong system password; ang pagkansela o nabigong pag-install ng extension ay pipili at maglulunsad pa rin kay Claude. I-restart ang iyong browser, i-enable ang extension kung sinabihan, at mag-sign in kay Claude upang tapusin ang pagkonekta dito. Patakbuhin ang `/chrome` sa Claude upang suriin ang koneksiyon. Hindi sinusuportahan ng Firefox at Zen ang extension na ito. Kung si Claude na ang iyong default bago idinagdag ang setup na ito, piliin itong muli upang i-install ang extension.

Kapag nakapili ka na, inilulunsad ng `Super + Shift + Ctrl + A` ang default na agent sa isang nakalaang terminal window (o inilalabas ang picker kung hindi ka pa nakakapili). Maaari mo rin itong ilunsad nang diretso sa isang gawain gamit ang `omarchy agent prompt "Review this project"`. Hindi tumatanggap ng panimulang prompt ang Freebuff at DeepSeek Harness, kaya sa halip ay nagbubukas ang mga ito na nasa iyong clipboard ang prompt upang i-paste. Ang mga agent na inilunsad sa ganitong paraan ay tumatakbo nang walang nagbabantay sa kani-kanilang mga mode na hindi humihinto para magtanong, kaya maging handa na talagang may gawin ang mga ito! Walang ganoong mode ang MiniMax Code para sa mga interactive session nito, kaya humihingi ito ng mga pahintulot gaya ng dati. At dahil tumatanggi ang mga agent na tandaan ang trust para sa iyong home directory, ang mga paglunsad mula sa `$HOME` ay sa halip nagsisimula sa `~/Work`.

Mayroon ding mga terminal shortcut: pinapatakbo ng `a` ang default na agent nang inline sa kasalukuyang terminal, habang direktang sinisimulan ng `c`, `cx`, at `cy` ang OpenCode, Claude Code, at Codex (muli, sa kanilang mga auto-approving na mode). Nagsi-sync din ang mga pagbabago ng theme sa mga agent: ang Claude Code, Pi, OpenCode, at Hermes (kapag na-install na ito ng Omarchy) ay pawang sumusunod kapag nagpalit ka ng theme ng Omarchy.

### Ang iyong mga tagubilin para sa agent

Ang mga personal na patakaran para sa bawat agent ay nasa `~/.agents/AGENTS.md`, katabi ng mga shared skill sa `~/.agents/skills`. Buksan ito sa ilalim ng _Agent > Instructions_, na nagli-link din dito sa bawat harness na may sarili nitong global file: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, ang `~/.copilot/copilot-instructions.md` ng Copilot, at iba pa. Binabasa ng Crush at Amp ang link na `~/.config/AGENTS.md`, habang direktang binabasa ng omp, Kimi, at DeepSeek Harness ang `~/.agents/AGENTS.md`. Ang pagpili ng default na agent ay nagli-link din dito. Ang isang instructions file na mayroon ka na ay nagiging shared na file kung wala pa nito; kung hindi, pinapanatili ito katabi ng link bilang `.bak`. Patakbuhin ang `omarchy agent instructions` upang muling mag-link pagkatapos mag-install ng isa pang agent.

### Ang panel ng mga agent

May agents icon ang top bar. Bago ka nakapag-set up ng agent, gagabayan ka ng panel nito sa pag-sign in kay Claude, Codex, o Grok, at ang una ay magiging iyong default na agent. Pagkatapos niyon, inilalagay ng panel ang bawat subscription sa isang page: bawat agent at account kasama ang plan nito, isang meter para sa bawat 5-hour session at weekly limit nito kasama ang oras hanggang mag-reset ito (i-hover para sa eksaktong porsiyento), o ang natitirang prepaid balance, sa ilalim ng isang linya na umiikot sa iyong nagamit sa lahat ng mga ito, gaya ng mga token ngayong linggo at ang pinakaginagamit mong modelo. Sa ilalim ng _Make something_ nag-aalok ito ng mga starter prompt para sa isang bagong theme, plugin, o app na nagbibigay ng gawain sa iyong default na agent. Ang mga app ay binubuo sa paraang binuo ang sariling Hype, Monologue, at Omacut ng Omarchy, sa C++ at Qt Quick, na sumusunod sa omarchy-app agent skill, at ang compiler at mga piraso ng Qt na kailangan ng mga ito ay kasamang naka-install. Ang Claude Code, Codex, Grok, Kimi, Cursor at ang Grok Bot allowance nito, GitHub Copilot, Muse, Antigravity, Kimchi, at Devin ay sakop agad kasama ang kanilang mga limit, at ipinapakita ng Hermes, Mistral Vibe, at Qwen Code ang kanilang mga session at token kapag nagamit mo na ang mga ito. Lumalabas din ang mga provider plan at key na ginagamit mo sa pamamagitan ng pi, omp, o opencode: ang OpenCode Zen at Go, ang Z.ai GLM Coding Plan, Ollama Cloud, ang MiniMax Token Plan, at Synthetic kasama ang kanilang mga limit; ang Fireworks, OpenRouter, at DeepSeek kasama ang kanilang mga prepaid balance; at ang mga modelong pinapatakbo mo sa sarili mong hardware sa ilalim ng Local models. Bawat agent ay binibilang nang isang beses, sa ilalim ng kung sino ang naniningil dito, gaano man karaming harness ang patakbuhin mo dito.

I-left-click ang bar icon para sa panel, i-right-click upang ilunsad ang iyong default na agent. Ang mga usage record sa likod nito ay muling ginagawa bawat 15 minuto ng `omarchy agent usage-update`, at maaari pang pagsamahin ng panel ang usage mula sa iba mong machine sa pamamagitan ng isang naka-sync na folder. Tingnan ang README sa ilalim ng `$OMARCHY_PATH/shell/plugins/agents/` para sa buong mga setting.

### Maraming subscription

Kung nagbabayad ka para sa higit sa isang Claude, Codex, o Grok plan — isang personal na Max at isang pang-trabaho, halimbawa — maaaring panatilihin ng Omarchy ang lahat ng mga ito na naka-sign in at lumipat sa pagitan ng mga ito. Magdagdag ng subscription gamit ang + sa agents panel, na gagabay sa iyo mismo roon, o gamit ang `omarchy agent account add claude Work` (o `codex`, o `grok`). Ini-install nito ang CLI kung nawawala ito. Ang unang account para sa isang provider ay nagsa-sign in sa pamamagitan ng iyong normal na browser, mismo kung saan laging tumitingin ang CLI. Bawat isa pagkatapos niyon ay nagsa-sign in sa pamamagitan ng isang private window, upang ang account na naka-sign in na sa iyong browser ay hindi aksidenteng mapili; mag-sign in doon bilang account na idinaragdag mo, at isara muna ang anumang private window na nakabukas na. Huwag kailanman mag-log out sa CLI upang gawin ito: binabawi ng pag-log out ang naka-save na sign-in, at kailangang idagdag muli ang account na iyon.

Upang kopyahin ang iyong mga subscription login sa isa pang Omarchy machine sa pamamagitan ng SSH, patakbuhin ang `omarchy agent account copy user@laptop`. Nagbibigay ang sender ng pansamantalang receiver kapag walang naka-install ang destination, kaya maaaring makatanggap ng mga account ang mas lumang Omarchy machine nang walang update. Ang mga naka-install na receiver ang inuuna. Kinokopya nito ang lahat ng subscription ng Claude, Codex, at Grok; magdagdag ng mga pangalan ng provider upang piliin ang mga ito, gaya ng `omarchy agent account copy laptop claude`. Ang mga pangalan ng account at command ID ay tumutugma sa source, kabilang ang mga account na nasa destination na. Ang mga hindi kaugnay na destination account ay tumatanggap ng numeric suffix kung magkasalungat ang kanilang mga pangalan, at ang mga setting, skill, plugin, at history ng pag-uusap ay nananatiling lokal sa bawat machine.

Pinapanatili ang mga umiiral na kredensiyal sa destination. Ang isang source account na naka-sign in na roon ay pina-sync ang pangalan nang hindi pinapalitan ang mga kredensiyal nito; ang ibang account ay idinaragdag katabi nito. Upang palitan ang mga naka-save na kredensiyal para sa mga tumutugmang account, gamitin ang `omarchy agent account copy --replace laptop claude` pagkatapos isara ang mga session ng account na iyon sa destination. Ang isang bagong destination ay nakakakuha rin ng active account at mga kagustuhan sa paglipat ng source; pinapanatili ng isang matagal nang destination ang sarili nitong mga kagustuhan.

Naglalakbay ang mga kredensiyal sa pamamagitan ng SSH at nakaimbak sa mga private file sa destination, kaya kopyahin lamang sa mga machine na pinagkakatiwalaan mo. Ito ay isang beses na kopya, hindi patuloy na synchronization. Ang mga Codex refresh token ay maaaring i-rotate ng ibang machine, na nag-iiwan sa isang nakopyang login na nangangailangan ng renewal; ang magkahiwalay na pag-sign in ang nananatiling pinaka-maaasahang pagpipilian para sa sabay-sabay na paggamit sa maraming machine. Tingnan ang [gabay sa pagpapatunay ng account ng Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Isang account bawat provider ang active, at bawat bagong session ay nagsisimula bilang ito: `cx`, `cy`, isang karaniwang `claude`, `codex`, o `grok`, anumang inilunsad sa pamamagitan ng `omarchy agent`, at mga script o editor na nakakahanap sa CLI sa `PATH`. Lumipat gamit ang `omarchy agent account use work` (at bumalik gamit ang `omarchy agent account use main`), o sa panel sa pamamagitan ng pagpindot sa numero ng isang account at pagkatapos sa `Enter` (o pag-click sa Use button nito). Ang mga session na tumatakbo na ay nananatili sa account kung saan sila nagsimula. Ang history ng pag-uusap, mga setting, skill, at plugin ay shared sa lahat ng account, kaya ang `claude --continue` sa parehong folder ay nagpapatuloy kung saan ka tumigil sa bagong account.

Sa higit sa isang account, ipinapakita ng panel ang mga limit ng bawat account nang magkatabi, na minarkahan ang active. Sa default, inaabisuhan ka ng Omarchy kapag lumampas ang active account sa 95% ng isang limit, at ang pag-click sa notification ay lumilipat sa account na may pinakamaraming headroom. I-hover ang linya ng isang account sa panel at i-click ang Autoswitch na lumalabas katabi ng Use (o pindutin ang `m`), o patakbuhin ang `omarchy agent account mode auto`, upang ito mismo ang lumipat sa halip; habang naka-on ito, pumapalit ang Autoswitch sa Use, at ang pag-click dito muli ay bumabalik sa pag-abiso. Magdagdag ng numero upang baguhin ang threshold, gaya ng `omarchy agent account mode auto 90`. Kung ang bawat account ay lumampas sa threshold, maririnig mo ang tungkol dito nang isang beses, kasama kung aling account ang unang makakalaya. Habang ang isang active account ay nasa loob ng 15 puntos ng threshold nito (80% sa default), ang mga limit nito ay sinusuri bawat tatlong minuto sa halip na bawat 15.

Ipinapakita ng `omarchy agent account list` ang bawat account at ang pinakabagong mga limit nito, ang `omarchy agent account remove work` ay nakakalimot ng isa, at ang `omarchy agent account rename primary Hey` ay nagpapalit ng pangalan ng isa (o i-click ang pangalan ng isang account sa panel). Gumagana ang mga utos na ito sa mga account ng iyong default na agent; upang maabot ang ibang provider, pangalanan muna ito, gaya ng `omarchy agent account use codex side`. Ang login na mayroon ka na sa `~/.claude` o `~/.codex` ay ang _Main_ account at nananatili kung nasaan ito. Ang isang account na hindi nagamit nang higit sa humigit-kumulang walong oras ay maaaring magpakita ng _Sign-in required_; i-click ito upang muling i-sign in ang account na iyon mismo sa panel, o magsimula ng session dito, na nagre-refresh sa sign-in nang kusa. Ang mga MCP server na mayroon ka noong idinagdag ang isang account ay sumasama dito, ngunit ang mga idinaragdag mo mamaya gamit ang `claude mcp add` ay nakakarating lamang sa account kung saan mo idinagdag ang mga ito. Ang Claude Desktop at mga tool na naka-configure gamit ang absolute path patungo sa isang CLI binary ay hindi sumusunod sa paglipat. Ang isang tahasang `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, o `GROK_HOME` ay inuuna kaysa sa napiling account.

### Pag-diagnose ng crash

Binabantayan ng Omarchy ang systemd-coredump para sa mga pag-crash ng process. Kapag may nag-segfault, makakakuha ka ng notification na "Process crashed" — i-click ito, at ang crash ay ibibigay sa iyong default na agent kasama ang diagnose-crash skill ng Omarchy, na gagabay sa agent sa pagtatatag ng mga katotohanan mula sa core dump at pagpapasya kung karapat-dapat bang iulat ang crash upstream. Maaari mo rin itong patakbuhin nang mano-mano laban sa anumang PID mula sa `coredumpctl list` gamit ang `omarchy agent crash <pid>`.

Naka-on ang pagbabantay sa default. I-off ito sa ilalim ng _Trigger > Toggle > Crash Capture_ (o gamit ang `omarchy toggle crash-capture`) at hihinto ang mga notification; gumagana pa rin nang mano-mano ang `omarchy agent crash <pid>`.

Maaari ring patahimikin ang mga crash nang isa-isa bawat programa, na siyang iniaalok sa iyo ng diagnosis sa dulo. Pinipigilan ng `omarchy crash mute hyprland` ang mga notification para lamang sa programang iyon, binabalik ito ng `omarchy crash mute hyprland off`, at inililista ng `omarchy crash mute` nang mag-isa kung ano ang na-mute mo. Tumatanggap ito ng path ng binary nang kasingsaya ng pangalan nito, kaya ginagawa ng `omarchy crash mute /usr/bin/hyprland` ang parehong bagay. I-quote ang isang pangalang may space, gaya ng `omarchy crash mute 'Some App'`. Nag-aabiso pa rin ang lahat ng iba, at nagka-crash pa rin ang na-mute na programa — itinatago nito ang paalala, hindi nito inaayos ang anuman.

### Mga desktop app

Mayroon ding ilang graphical AI app ang menu na _Install > AI_: ang ChatGPT desktop app, ang Claude desktop app (ang Linux beta ng Anthropic, na may mga tab na Chat, Cowork, at Claude Code), Grok Bot para makipag-chat sa mga modelo ng xAI, Herdr Desktop, Hermes Desktop, OpenClaw, ang Perplexity desktop app, at T3 Code. Ang Grok Bot ay ang desktop chat app. Ang coding agent ay ang utos na `grok`.

Ang Hermes Desktop ang dapat mong malaman, dahil ang isang machine ay may isang Hermes, at ito ay sa app: ang Hermes ay ini-install lamang kailanman sa pamamagitan ng app, at ang utos na `hermes` na pinapatakbo ng default na agent ay sa app. Ang pagpili sa Hermes bilang default na agent ay nag-i-install ng parehong bagay na ginagawa ng entry na _Install > AI_: ang package, at isang Hermes runtime sa ilalim ng `~/.hermes` na sine-set up ng sariling installer ng Hermes, na tumatagal ng ilang minuto sa unang pagkakataon. Ang runtime na iyon ang isang Hermes na ginagamit ng terminal na utos na `hermes`, ng default na agent at ng app, at ina-update nito ang sarili gamit ang `hermes update` sa halip na maghintay sa isang Omarchy release. Ang pag-install dito ay nagbibigay din kay Hermes ng theme ng Omarchy bilang isang skin na pinangalanang `omarchy`, na sinusunod ng bawat Hermes surface habang nagpapalit ka ng theme; pumili ng iba sa ilalim ng mga Appearance setting ng Hermes o gamit ang `/skin` kung mas gusto mo itong hindi, at hindi pinapakialaman ng Omarchy ang pagpilìng iyon. Ang pag-alis sa app sa ilalim ng _Remove > AI_ ay nagsasara muna kay Hermes, kasama ang gateway, isinasama ang runtime na iyon, at pinapanatili ang iyong mga chat, alaala, at ang mga skill na isinulat ng Hermes para sa sarili nito maliban kung sasabihin mo ang kabaligtaran: nagtatanong ito, na ang default ay hindi, kung dapat ding alisin ang data na iyon at ang iyong mga connection setting.

Ang desktop experience ng OpenClaw ay ang Control UI nito, na nagbubukas bilang isang web app na sinusuportahan ng sarili nitong local gateway. Nakatira ang OpenClaw sa `~/.openclaw` at ina-update ang sarili nito: gamitin ang button na "Update Gateway" ng Control UI o patakbuhin ang `openclaw update`, at magre-restart ang gateway sa bagong bersyon. Pinipili lamang ng Omarchy ang release kung saan nagsisimula ang isang bagong install. Ang pag-alis sa OpenClaw sa ilalim ng _Remove > AI_ ay isinasama ang gateway service at ang app at pagkatapos ay nagtatanong kung dapat ding alisin ang `~/.openclaw`, dahil naroon ang iyong mga chat at kredensiyal kasama ng mismong OpenClaw at ang mga plugin runtime na dina-download nito; pinapanatili ito ng default, at ang muling pag-install sa OpenClaw ay muling kukunin ito.

Ang Herdr Desktop ay ang desktop app na [Herdr](https://herdr.dev): mga space, tab, at pane ng mga terminal at coding agent na patuloy na tumatakbo sa core nito kapag isinara mo ang window. Nagmumula ito sa sariling installer ng Herdr sa halip na sa isang package, kaya nakatira ito sa `~/.local/share/herdr-app`, isinasama ang core nito sa `~/.local/bin/herdr-core` kapag wala ka pa nito, at ina-update ang sarili nitong dalawa. Nakaupo ito katabi ng utos na `herdr` na ibinibigay ng Omarchy sa `Super + Ctrl + Return` sa halip na palitan ito, at nakukuha ang mga direct key ng utos na iyon: hinahati ng `Alt + Return` at `Alt + Shift + Return` ang isang pane pababa o pakanan, isinasara ito ng `Alt + Escape`, ang `Ctrl + Alt + Arrow` ay gumagalaw sa pagitan ng mga pane, ang `Alt + 1..9` at `Alt + Left/Right` ay pumipili ng tab, at ang `Alt + Up/Down` ay gumagalaw sa pagitan ng mga space. Ang `Ctrl + 1..9` ay pumipili ng space at ang `Alt + Shift + Up/Down` ay humahakbang sa mga agent. Ang mga prefix key na `Ctrl + Space` ay nananatiling pang-terminal lamang, dahil hindi kayang hawakan ng app ang isang karaniwang Ctrl key para sa isang sequence. Isinusulat ito ng Omarchy sa `~/.config/herdr-app/keys.json`, at ibinabalik ito ng `omarchy-refresh-herdr-app`. Ang pag-install dito ay pumipili ng Omarchy theme ng Herdr, na sumusunod sa iyong Omarchy theme mula noon. Nagpapanatili ang Herdr ng isang theme para sa light mode at isa para sa dark, kaya pagkatapos lumipat sa pagitan ng isang dark at isang light na Omarchy theme, piliin muli ang Omarchy sa theme picker ng Herdr nang isang beses pa para sa kabilang mode.

Tumatakbo ang T3 Code mula sa opisyal nitong AppImage release sa `~/.local/share/t3code` sa halip na mula sa isang package, kaya ina-update nito ang sarili. Ang pag-install dito ay nagtatanong kung magsisimula sa Stable o Nightly channel; lumipat mamaya sa mga setting ng T3 Code. Ang iyong mga thread at setting ay nasa `~/.t3`, at ang pag-alis sa T3 Code sa ilalim ng _Remove > AI_ ay isinasama ang mga ito.

### Mga lokal na modelo

Magpatakbo ng isang open model sa sarili mong machine para sa iyong mga coding agent. Ang iyong mga prompt at code ay nananatili sa machine; walang ipinapadala sa modelo ang umaalis dito. Magsimula sa:

```bash
omarchy agent local use best
```

O, sa agents panel sa top bar, piliin ang + at pagkatapos ang Local AI, na lumalabas kapag kasya ang isang modelo sa machine na ito. Sa unang pagkakataon, ini-install nito ang Podman, na nagpapatakbo ng mga modelo, at sa isang NVIDIA machine ang container toolkit ng NVIDIA, na nagbibigay sa mga ito ng GPU. Pagkatapos ay pinipili ng Omarchy ang inirerekomendang modelo para sa machine na ito, dina-download ito, at sinisimulan ito. Asahan ang download na sampu-sampung GB at ang karamihan ng memory ng machine ay ginagamit habang tumatakbo ang modelo: ang Flash Next ay gumagamit ng humigit-kumulang 100 GiB sa buong 256K context nito. Kung hawak ng ibang modelo ang memory na kailangan nito, sine-set up itong nakahinto, handang magsimula kapag huminto ka ng isa. Humihinto ang modelo sa pag-logout; ihinto mo ito mismo kapag kailangan mo ang memory para sa ibang bagay.

Ipinapakita ng `omarchy agent local list` ang mga opsiyon at ipinaliliwanag kung bakit hindi kasya ang ilan. Upang mag-set up ng isa pa, patakbuhin ang `omarchy agent local use <recipe>`. Ngayon, ang `qwen3.8-flash-next-gufo` at `qwen3.8-27b-gufo` ay available para sa mga 128 GB Strix Halo machine; ang 27B ay kumukuha ng humigit-kumulang 40 GiB, kaya nag-iiwan ito ng puwang para sa ibang trabaho. Ang mga bagong recipe at rekomendasyon ay darating kasama ng `omarchy update`, sa pamamagitan ng package.

Bawat modelong sine-set up mo ay nakakakuha ng sarili nitong linya sa agents panel, katabi ng iyong mga subscription: play upang simulan ito, pause upang ihinto ito at palayain ang memory nito, at ang terminal button upang buksan ang iyong agent dito. Marami ang maaaring tumakbo nang sabay kapag kasya ang mga ito sa memory nang magkasama; kung hindi kasya ang isa, sasabihin ng Omarchy kung aling tumatakbong modelo ang ihinto. I-drag ang mga linya upang muling ayusin ang mga ito, at pindutin ang Delete sa isang napiling linya upang alisin ang isang modelo at ang download nito.

Mula sa command line, ginagawa ng `omarchy agent local start <recipe>` at `omarchy agent local stop <recipe>` ang parehong bagay, ipinapakita ng `omarchy agent local status` ang bawat modelo, at binubuksan ng `omarchy agent --local` ang iyong default na agent sa huling modelong sinimulan mo (pi kung hindi magamit ng iyong default na agent ang isang lokal na modelo). Maaari ring kumonekta ang anumang OpenAI-compatible client: ipinapakita ng `status` ang address ng bawat modelo (ang una ay `http://127.0.0.1:11435/v1`), ang pangalan ng recipe ay ang modelo, at ang key ay nasa `~/.config/omarchy/agent-local/key`.

Tinatanggal ng `omarchy agent local remove <recipe>` ang isang modelo at ang mga download na hindi ginagamit ng ibang modelo.

Ang mga third-party runtime ay may label ng kanilang publisher. Pinapatakbo ng Omarchy ang bawat modelo nang walang network access.

### Mga lokal na LLM

Inirerekomenda ng Omarchy ang dalawang paraan ng pagpapatakbo ng mga lokal na LLM model: LM Studio at Ollama. Nagbibigay ang LM Studio ng GUI interface para sa paghahanap ng mga open-weight model, pag-install sa mga ito, at pagpapatakbo sa mga ito. Ito ay isang mahusay na paraan upang madaling makapagsimula. Nag-aalok ang Ollama ng CLI para gawin ito nang katulad. Pero kung bago ka sa mga lokal na modelo, magsisimula ako sa LM Studio. Maaari mong i-install ang alinman sa ilalim ng _Install > AI_ sa Omarchy Menu.

### Ang Omarchy Skill

Tinutulungan ng mga agent skill ang AI na gumamit ng mga partikular na tool sa isang partikular na paraan, at may kasamang default skill ang Omarchy para sa pagsasaayos ng system. Gaya ng pag-tweak sa iyong Hyprland config, pagsasaayos sa bar, o kahit paglikha ng bagong theme mula sa simula. Naka-symlink ito sa mga skill directory para sa Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` at bawat `~/.hermes/profiles/*/skills`), at ang generic na lokasyong `~/.agents/skills`, kaya karamihan ng harness ay awtomatikong nakukuha ito.

Pero dapat mong ituring ang skill na ito bilang eksperimental. Gagamitin ito ng iba't ibang modelo sa iba't ibang epekto. Pinakamabuting patakbuhin muna ito sa plan mode, upang magkaroon ka ng ideya kung ano ang gustong baguhin ng agent. At pagkatapos ay maging handang i-rollback ang mga pagbabago o kahit tawagin ang `omarchy reinstall configs`, kung guluhin ng agent ang lahat.
