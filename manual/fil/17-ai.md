### Pag-install at pag-update ng mga agent

Maliban sa Hermes at OpenClaw, ginagamit ng mga agent na ito ang lazy installation ng mise: ini-install ng unang paglunsad ang CLI, at muling ginagamit ito ng mga susunod na paglunsad. Sinusuri rin ng mise ang isang naka-install na agent para sa bagong release nang hindi hihigit sa isang beses bawat apat na oras, bago ito magsimula o sa background sa isang shell prompt. Kung nabigo ang update na iyon o offline ka, tatakbo ang naka-install na bersyon. Ina-update ng `omarchy update` ang mga naka-install na agent kasama ng iba pang bahagi ng Omarchy, at ina-update ng `mup` ang mga tool na pinamamahalaan ng mise lamang.

Hindi ina-update ng sariling updater ng isang agent, gaya ng `claude update`, `codex update`, o isang update button sa isang app, ang install na pinamamahalaan ng mise. Nabibigo ang `codex update`, at maaaring mag-ulat ng tagumpay ang `claude update` habang nag-i-install ng hiwalay na kopya na hindi sinusubaybayan ng mise. Kung mas gusto mong gamitin ang native installer at updater ng isang agent, idagdag ito sa `disable_tools`; tingnan ang [Mga paunang naka-install na CLI tool](18-development-tools.md#preinstalled-cli-tools).

Para i-install ang lahat ng naka-configure na lazy tool bago mo kailanganin ang mga ito, patakbuhin ang `mise install --include-lazy`. Kasama rito ang iba pang default na CLI tool ng Omarchy pati na rin ang mga agent. Tingnan ang [Mga paunang naka-install na CLI tool](18-development-tools.md#preinstalled-cli-tools) para sa pag-install ng isang tool o paggamit ng sarili mong installation.

Ini-install ang `grok` sa pamamagitan ng first-party na `grok` package ng mise, sa parehong paraan gaya ng `claude` at `codex`. Patakbuhin ang `grok`, o i-star ito sa panel ng mga agent. Laktawan ang `curl | bash` installer sa x.ai. Naglalagay ang path na iyon ng pangalawang kopya sa `~/.grok/bin`, inuuna ito sa `PATH`, at pinapalitan ang wrapper ng Omarchy.

Binubuksan ng `dsh` ang browser UI nito sa `127.0.0.1:3080`, na ang launch directory ang default workspace nito. Walang starting prompt ang browser UI nito, kaya binubuksan ito ng `omarchy agent prompt` na nasa clipboard mo ang prompt para i-paste. Sinisimulan ito ng Omarchy gamit ang no-approval permission preset ng DeepSeek. Ina-upload ng DeepSeek Harness ang mga session log sa DeepSeek kapag ginagamit mo ang opisyal nitong model API; i-off iyon sa ilalim ng _Settings > General > Upload Session Log_ sa browser UI nito. Ang feedback na ipinapadala mo rito ay ina-upload din kasama ng session, maliban kung sisimulan mo ito gamit ang `DSH_TELEMETRY_MODE=DISABLED`.

### Ang default na agent

Piliin ang default mong agent gamit ang star sa tabi ng isang agent sa panel ng mga agent, na napupunan sa default, o gamit ang `omarchy default agent <name>`, na tumatanggap din ng anumang harness na walang linya roon. Kung hindi pa naka-install ang agent, i-install muna ito ng pagpili rito, at makakakuha rin ito ng sarili nitong launcher sa app launcher, sa tabi ng Agent. Inaanyayahan ka ng bagong Omarchy na mag-set up ng isa gamit ang isang beses na notification, na nagbubukas sa panel ng mga agent.

Sinusubukan din ng pagpili sa Claude na i-set up ang browser extension nito para sa Chromium, Chrome, Brave, Brave Origin, at Edge. Nalalapat ang extension setup sa lahat ng user at maaaring humingi ng password ng system mo; pipiliin at ilulunsad pa rin ang Claude kahit kanselahin mo o mabigo ang pag-install ng extension. I-restart ang browser mo, i-enable ang extension kung sinabihan, at mag-sign in sa Claude para tapusin ang pagkonekta rito. Patakbuhin ang `/chrome` sa Claude para suriin ang koneksyon. Hindi sinusuportahan ng Firefox at Zen ang extension na ito. Kung Claude na ang default mo bago idagdag ang setup na ito, piliin itong muli para i-install ang extension.

Kapag nakapili ka na, ilulunsad ng `Super + Shift + Ctrl + A` ang default na agent sa isang nakalaang terminal window (o ilalabas ang picker kung hindi ka pa nakakapili). Maaari mo rin itong ilunsad nang direkta sa isang gawain gamit ang `omarchy agent prompt "Review this project"`. Walang starting prompt ang Freebuff at DeepSeek Harness, kaya nagbubukas sila na nasa clipboard mo ang prompt para i-paste sa halip. Tumatakbo nang walang nagbabantay ang mga agent na inilunsad sa ganitong paraan sa kani-kanilang don't-stop-to-ask mode, kaya maging handa na talagang gumawa sila ng mga bagay! Walang ganoong mode ang MiniMax Code para sa mga interactive session nito, kaya humihingi ito ng mga pahintulot gaya ng dati. At dahil tumatanggi ang mga agent na tandaan ang tiwala para sa home directory mo, ang mga paglunsad mula sa `$HOME` ay nagsisimula sa `~/Work` sa halip.

May mga terminal shortcut din: pinapatakbo ng `a` ang default na agent nang inline sa kasalukuyang terminal, habang sinisimulan ng `c`, `cx`, at `cy` ang OpenCode, Claude Code, at Codex nang direkta (muli sa kanilang mga auto-approving mode). Nagsi-sync din ang mga pagbabago ng tema sa mga agent: sumusunod ang Claude Code, Pi, OpenCode, at Hermes (kapag na-install na ito ng Omarchy) kapag lumipat ka ng tema ng Omarchy.

### Ang mga tagubilin ng agent mo

Ang mga personal na patakaran para sa bawat agent ay nasa `~/.agents/AGENTS.md`, sa tabi ng mga shared skill sa `~/.agents/skills`. Buksan ito gamit ang icon ng dokumento sa tabi ng + sa panel ng mga agent, o ang `omarchy agent instructions --edit`, na nagli-link din nito sa bawat harness na nag-iingat ng sarili nitong global file: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, ang `~/.copilot/copilot-instructions.md` ng Copilot, at iba pa. Binabasa ng Crush at Amp ang link na `~/.config/AGENTS.md`, habang direktang binabasa ng omp, Kimi, at DeepSeek Harness ang `~/.agents/AGENTS.md`. Nagli-link din ito ng pagpili ng default na agent. Ang isang instructions file na mayroon ka na ay nagiging shared na file kung wala pa noon; kung hindi, iniingatan ito sa tabi ng link bilang `.bak`. Patakbuhin ang `omarchy agent instructions` para muling mag-link pagkatapos mag-install ng isa pang agent.

### Ang panel ng mga agent

May icon ng mga agent ang top bar. Bago ka mag-set up ng agent, nag-aalok ang panel nito ng tatlong paraan para magsimula: mag-sign in sa isang subscription ng Claude, Codex, Grok, Gemini, Muse, Cursor, o Copilot, o sa ilalim ng More ay isang coding plan ng OpenCode Go, MiniMax, Synthetic, o Z.ai; magbayad habang ginagamit mo ito gamit ang Fireworks, OpenCode Zen at Go, OpenRouter, o sa ilalim ng More ay DeepSeek o anumang iba pang provider na sine-sign in ng OpenCode, na lahat ay tumatakbo sa OpenCode; o patakbuhin ang pinakamahusay na modelo para sa computer mo, kapag may kasya rito. Ang una mong matatapos ay magiging default mong agent, at nag-aalok ang + sa panel ng parehong tatlo sa ibang pagkakataon. Pagkatapos noon, inilalagay ng panel ang bawat subscription sa isang page: bawat agent at account kasama ang plan nito, isang meter para sa bawat 5-hour session at weekly limit nito kasama ang oras hanggang mag-reset ito (mag-hover para sa eksaktong porsyento), o ang natitirang prepaid balance, sa ilalim ng isang linyang umiikot sa kung ano ang nagamit mo sa lahat ng mga ito, gaya ng mga token ngayong linggo at ang pinakamadalas mong gamiting modelo. Sa ilalim ng _Make something cool_ nag-aalok ito ng mga starter prompt para sa bagong tema, plugin, app, o game na nagbibigay ng gawain sa default mong agent. Ginagawa ang mga app sa paraang ginagawa ang sariling Hype, Monologue, at Omacut ng Omarchy, sa C++ at Qt Quick, na sumusunod sa omarchy-make-app agent skill, at kasamang naka-install ang compiler at mga piraso ng Qt na kailangan nila. Ang mga game ay isang solong three.js page sa `~/Games/vibes`, na sumusunod sa omarchy-make-game agent skill, at lahat ay nagbubukas mula sa isang Game Vibes launcher sa kasalukuyang tema; nilo-load nila ang three.js mula sa web, kaya kailangan nila ng koneksyon para magsimula. Saklaw agad ang Claude Code, Codex, Grok, Kimi, Cursor at ang Grok Bot allowance nito, GitHub Copilot, Muse, Gemini (sa pamamagitan ng Antigravity), at Devin kasama ang mga limit nila, ang Kimchi kasama ang plan nito, mga prepaid credit, at mga spend budget, at ipinapakita ng Hermes, Mistral Vibe, at Qwen Code ang kanilang mga session at token kapag nagamit mo na sila. Lumalabas din ang mga provider plan at key na ginagamit mo sa pamamagitan ng pi, omp, o opencode: ang OpenCode Zen at Go, ang Z.ai GLM Coding Plan, Ollama Cloud, ang MiniMax Token Plan, at Synthetic kasama ang mga limit nila; ang OpenRouter at DeepSeek kasama ang kanilang mga prepaid balance; ang Fireworks kasama ang gastos nito sa nakalipas na 30 araw. Nabibilang din sa mga kabuuan ang mga token mula sa mga modelong pinapatakbo mo sa sarili mong hardware; ang mga modelo mismo ay may sariling panel, na inilalarawan sa ilalim ng [Mga lokal na modelo](#local-models). Bawat agent ay binibilang nang isang beses, sa ilalim ng kung sino ang naniningil para rito, gaano man karaming harness ang patakbuhin mo rito.

I-left-click ang icon sa bar o pindutin ang `Super + Ctrl + X` para sa panel, i-right-click para ilunsad ang default mong agent, at i-middle-click para mag-refresh. Ang mga usage record sa likod nito ay muling ginagawa bawat 15 minuto ng `omarchy agent usage update`, at maaari pang pagsamahin ng panel ang usage mula sa iba mong mga machine sa pamamagitan ng isang naka-sync na folder. Tingnan ang README sa ilalim ng `$OMARCHY_PATH/shell/plugins/agents/` para sa buong mga setting.

### Ilang subscription

Kung nagbabayad ka para sa higit sa isang plan ng Claude, Codex, o Grok — isang personal na Max at isang pangtrabaho, halimbawa — maaaring panatilihin ng Omarchy na naka-sign in ang lahat ng mga ito at lumipat sa pagitan nila. Magdagdag ng subscription gamit ang + sa panel ng mga agent, na gagabay sa iyo roon mismo, o gamit ang `omarchy agent account add claude Work` (o `codex`, o `grok`). Ang parehong + at command ay nagsa-sign in sa Gemini (`gemini`) at OpenCode (`opencode`), at nagse-save ng API key ng Fireworks (`fireworks`) o OpenRouter (`openrouter`) sa OpenCode; nagsa-sign in din ang command sa Copilot (`copilot`), Cursor (`cursor`), at Muse (`muse`). Ang mga iyon ay nag-iingat ng tig-iisang sign-in bawat isa. Ini-install nito ang CLI kung nawawala ito. Ang unang account para sa isang provider ay nagsa-sign in sa pamamagitan ng normal mong browser, mismo kung saan laging tumitingin ang CLI. Bawat isa pagkatapos noon ay nagsa-sign in sa pamamagitan ng private window, kaya hindi aksidenteng makukuha ang account na naka-sign in na ang browser mo; mag-sign in doon bilang account na idinaragdag mo, at isara muna ang anumang private window na nakabukas mo na. Huwag kailanman mag-log out sa CLI para gawin ito: binabawi ng pag-log out ang naka-save na sign-in, at kailangang idagdag muli ang account na iyon.

Para kopyahin ang mga subscription login mo sa isa pang Omarchy machine sa pamamagitan ng SSH, patakbuhin ang `omarchy agent account copy user@laptop`. Nagbibigay ang nagpadala ng pansamantalang receiver kapag walang naka-install ang destinasyon, kaya makakatanggap ng mga account ang mas lumang mga Omarchy machine nang walang update. Inuuna ang mga naka-install na receiver. Kinokopya nito ang lahat ng subscription ng Claude, Codex, at Grok; magdagdag ng mga pangalan ng provider para piliin ang mga ito, gaya ng sa `omarchy agent account copy laptop claude`. Tumutugma ang mga pangalan ng account at command ID sa pinagmulan, kabilang ang mga account na naroon na sa destinasyon. Ang mga hindi kaugnay na account sa destinasyon ay nakakatanggap ng numeric suffix kung magkasalungat ang kanilang mga pangalan, at ang mga setting, skill, plugin, at history ng pag-uusap ay nananatiling lokal sa bawat machine.

Pinananatili ang mga umiiral na credential sa destinasyon. Ang isang source account na naka-sign in na roon ay sina-sync ang pangalan nang hindi pinapalitan ang mga credential nito; ang ibang mga account ay idinaragdag sa tabi nito. Para palitan ang mga naka-save na credential para sa magkatugmang mga account, gamitin ang `omarchy agent account copy --replace laptop claude` pagkatapos isara ang mga session ng account na iyon sa destinasyon. Nakukuha rin ng bagong destinasyon ang aktibong account at mga kagustuhan sa paglipat ng pinagmulan; pinananatili ng naitatag nang destinasyon ang sarili nito.

Naglalakbay ang mga credential sa pamamagitan ng SSH at iniimbak sa mga pribadong file sa destinasyon, kaya kumopya lamang sa mga machine na pinagkakatiwalaan mo. Ito ay isang beses na kopya, hindi patuloy na pag-synchronize. Ang mga Codex refresh token ay maaaring i-rotate ng ibang machine, na nag-iiwan sa isang nakopyang login na nangangailangan ng pag-renew; ang magkakahiwalay na sign-in ay nananatiling pinaka-maaasahang pagpipilian para sa sabay-sabay na paggamit sa ilang machine. Tingnan ang [gabay sa account authentication ng Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Isang account bawat provider ang aktibo, at bawat bagong session ay nagsisimula bilang ito: `cx`, `cy`, isang payak na `claude`, `codex`, o `grok`, anumang inilunsad sa pamamagitan ng `omarchy agent`, at mga script o editor na nakakahanap sa CLI sa `PATH`. Lumipat gamit ang `omarchy agent account use work` (at bumalik gamit ang `omarchy agent account use main`), o sa panel sa pamamagitan ng pagpindot sa numero ng isang account at pagkatapos ay `Enter` (o pag-click sa star nito). Lumilipat din ang mga tumatakbong Claude session, mula sa kanilang susunod na mensahe: bawat Claude session ay tumatakbo sa `~/.claude`, na laging naglalaman ng sign-in ng aktibong account. Ang isang Claude session na sinimulan sa sariling folder ng isang account ng mas lumang Omarchy ay nag-iingat ng sign-in na iyon hanggang sa umalis ito, kaya pinapangalanan ng paglipat ang mga session na iyon at natatapos nang mag-isa kapag wala na sila. Ang mga tumatakbong Codex at Grok session ay nananatili sa account na pinagsimulan nila. Ang history ng pag-uusap, mga setting, skill, at plugin ay ibinabahagi sa mga account, kaya ang `claude --continue` sa parehong folder ay nagpapatuloy kung saan ka tumigil sa bagong account.

Sa higit sa isang account, ipinapakita ng panel ang mga limit ng bawat account nang magkatabi, na may napunang star sa ginagamit. Inaabisuhan ka ng Omarchy kapag lumampas ang aktibong account sa 95% ng isang limit, at ang pag-click sa notification ay lumilipat sa account na may pinakamaraming headroom. Hindi ito lumilipat nang mag-isa. Baguhin ang threshold gamit ang `omarchy agent account threshold 90`. Kung ang bawat account ay lumampas sa threshold, maririnig mo ang tungkol dito nang isang beses, kasama kung aling account ang unang magkakaroon ng puwang. Habang ang isang aktibong account ay nasa loob ng 15 puntos ng threshold nito (80% sa default), sinusuri ang mga limit nito bawat tatlong minuto sa halip na bawat 15.

Ipinapakita ng `omarchy agent account list` ang bawat account at ang pinakabagong mga limit nito, ang `omarchy agent account remove work` ay nakakalimot ng isa, at ang `omarchy agent account rename primary Hey` ay nagpapalit ng pangalan ng isa (o i-click ang pangalan ng isang account sa panel). Gumagana ang mga command na ito sa mga account ng default mong agent; para maabot ang ibang provider, pangalanan muna ito, gaya ng sa `omarchy agent account use codex side`. Ang login na mayroon ka na sa `~/.claude` o `~/.codex` ay ang _Main_ account. Ang sa Codex ay nananatili kung nasaan ito; ang sa Claude ay naghihintay sa sarili nitong folder habang aktibo ang ibang account. Ang isang account na hindi nagamit nang higit sa walong oras ay maaaring magpakita ng _Sign-in required_; i-click ito para muling i-sign in ang account na iyon mismo sa panel, o lumipat dito at magsimula ng session, na nagre-refresh ng sign-in nang mag-isa. Ang mga MCP server na idinaragdag mo gamit ang `claude mcp add` ay umaabot sa bawat Claude account, dahil lahat sila ay tumatakbo sa `~/.claude`; para sa Codex at Grok, ang mga server na mayroon ka noong idinagdag ang isang account ay sumasama rito, ngunit ang mga susunod ay umaabot lamang sa account kung saan mo idinagdag ang mga ito. Nag-iingat ang Claude Desktop ng sarili nitong sign-in, at ang mga Codex o Grok tool na naka-configure gamit ang absolute path patungo sa isang CLI binary ay hindi sumusunod sa paglipat. Ang isang tahasang `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, o `GROK_HOME` ay inuuna kaysa sa napiling account.

### Pag-diagnose ng crash

Binabantayan ng Omarchy ang systemd-coredump para sa mga process crash. Kapag nakapili ka na ng default na agent, ang anumang programa mo na nagda-dump ng core ay nagdadala ng notification na "Process crashed" — i-click ito, at ang crash ay ibibigay sa default mong agent kasama ang omarchy-diagnose-crash skill ng Omarchy, na gumagabay sa agent sa pagtatatag ng mga katotohanan mula sa core dump at pagpapasya kung karapat-dapat iulat ang crash sa upstream. Maaari mo rin itong patakbuhin nang mano-mano laban sa anumang PID mula sa `coredumpctl list` gamit ang `omarchy agent crash <pid>`.

Naka-on ang pagbabantay bilang default. I-off ito sa ilalim ng _Trigger > Toggle > Crash Capture Off_ (o gamit ang `omarchy toggle crash-capture`) at hihinto ang mga notification; gumagana pa rin nang mano-mano ang `omarchy agent crash <pid>`.

Maaari ring patahimikin ang mga crash nang paisa-isang programa, na siyang iniaalok sa iyo ng diagnosis sa dulo. Pinipigilan ng `omarchy crash mute hyprland` ang mga notification para sa programang iyon lamang, ibinabalik sila ng `omarchy crash mute hyprland off`, at inililista ng `omarchy crash mute` nang mag-isa kung ano ang na-mute mo. Tumatanggap ito ng path ng binary nang kasing saya ng pangalan nito, kaya ginagawa ng `omarchy crash mute /usr/bin/hyprland` ang parehong bagay. Mag-quote ng pangalang may puwang, gaya ng sa `omarchy crash mute 'Some App'`. Nag-aabiso pa rin ang lahat ng iba, at nagka-crash pa rin ang na-mute na programa — itinatago nito ang paalala, hindi nito inaayos ang anuman.

### Mga desktop app

May dala rin ang menu na _Install > AI_ ng ilang graphical AI app: Amp Desktop, Antigravity Desktop, ang ChatGPT desktop app, ang Claude desktop app (ang Linux beta ng Anthropic, na may mga tab na Chat, Cowork, at Claude Code), Grok Bot para sa pakikipag-chat sa mga modelo ng xAI, Herdr Desktop, Hermes Desktop, OpenClaw, ang Perplexity desktop app, at T3 Code. Ang Grok Bot ay ang desktop chat app. Ang coding agent ay ang command na `grok`.

Ang Hermes Desktop ang dapat mong malaman, dahil ang isang machine ay may isang Hermes, at ito ay sa app: ini-install lamang ang Hermes sa pamamagitan ng app, at ang command na `hermes` na pinapatakbo ng default na agent ay sa app. Ang pagpili sa Hermes bilang default na agent ay nag-i-install ng parehong bagay na ginagawa ng entry na _Install > AI_: ang package, at isang Hermes runtime sa ilalim ng `~/.hermes` na sine-set up ng sariling installer ng Hermes, na tumatagal ng ilang minuto sa unang pagkakataon. Ang runtime na iyon ang isang Hermes na ginagamit ng terminal command na `hermes`, ng default na agent at ng app, at ina-update nito ang sarili nito gamit ang `hermes update` sa halip na maghintay sa isang Omarchy release. Binibigyan din ng pag-install nito ang Hermes ng tema ng Omarchy bilang isang skin na pinangalanang `omarchy`, na sinusundan ng bawat Hermes surface habang nagpapalit ka ng mga tema; pumili ng iba sa ilalim ng mga Appearance setting ng Hermes o gamit ang `/skin` kung mas gugustuhin mong hindi, at hindi pakikialaman ng Omarchy ang pagpipiliang iyon. Ang pag-alis ng app sa ilalim ng _Remove > AI_ ay isinasara muna ang Hermes, kasama ang gateway, dinadala ang runtime na iyon, at iniingatan ang iyong mga chat, memory, at ang mga skill na isinulat ng Hermes para sa sarili nito maliban kung sasabihin mo kung hindi: nagtatanong ito, na nagde-default sa hindi, kung dapat ding alisin ang data na iyon at ang iyong mga connection setting.

Ang desktop experience ng OpenClaw ay ang Control UI nito, na nagbubukas bilang isang web app na sinusuportahan ng sarili nitong local gateway. Nakatira ang OpenClaw sa `~/.openclaw` at ina-update ang sarili nito: gamitin ang button na "Update Gateway" ng Control UI o patakbuhin ang `openclaw update`, at magre-restart ang gateway sa bagong bersyon. Pinipili lamang ng Omarchy ang release na pagsisimulan ng bagong install. Maaari ring maging default mong agent ang OpenClaw: ang pagpili rito gamit ang `omarchy default agent openclaw` ay nagse-set up ng parehong kopya sa `~/.openclaw`, at binubuksan ng agent ang terminal UI ng OpenClaw na nakakabit sa gateway nito. Ang pag-alis ng OpenClaw sa ilalim ng _Remove > AI_ ay dinadala ang gateway service at ang app kasama nito at pagkatapos ay nagtatanong kung dapat ding alisin ang `~/.openclaw`, dahil naglalaman iyon ng iyong mga chat at credential kasama ng OpenClaw mismo at ang mga plugin runtime na dina-download nito; pinananatili ito ng default, at ang muling pag-install ng OpenClaw ay muling kukunin ito.

Ang Herdr Desktop ay ang desktop app ng [Herdr](https://herdr.dev): mga space, tab, at pane ng mga terminal at coding agent na patuloy na tumatakbo sa core nito kapag isinara mo ang window. Nagmula ito sa sariling installer ng Herdr sa halip na isang package, kaya nakatira ito sa `~/.local/share/herdr-app`, dinadala ang core nito sa `~/.local/bin/herdr-core` kapag wala ka pang isa, at ina-update ang sarili nito kapwa. Nakaupo ito sa tabi ng command na `herdr` na ipinapadala ng Omarchy sa `Super + Ctrl + Return` sa halip na palitan ito, at nakukuha ang mga direct key ng command na iyon: hinahati ng `Alt + Return` at `Alt + Shift + Return` ang isang pane pababa o pakanan, isinasara ito ng `Alt + Escape`, ang `Ctrl + Alt + Arrow` ay gumagalaw sa pagitan ng mga pane, ang `Alt + 1..9` at `Alt + Left/Right` ay pumipili ng tab, at ang `Alt + Up/Down` ay gumagalaw sa pagitan ng mga space. Ang `Ctrl + 1..9` ay pumipili ng space at ang `Alt + Shift + Up/Down` ay humahakbang sa mga agent. Ang mga prefix key na `Ctrl + Space` ay nananatiling terminal lamang, dahil hindi kayang hawakan ng app ang isang payak na Ctrl key para sa isang sequence. Isinusulat ito ng Omarchy sa `~/.config/herdr-app/keys.json`, at ibinabalik sila ng `omarchy-refresh-herdr-app`. Pinipili ng pag-install nito ang tema ng Omarchy ng Herdr, na sumusunod sa tema ng Omarchy mo mula noon. Nag-iingat ang Herdr ng isang tema para sa light mode at isa para sa dark, kaya pagkatapos lumipat sa pagitan ng dark at light na tema ng Omarchy, piliin muli ang Omarchy sa theme picker ng Herdr nang isang beses pa para sa kabilang mode.

Tumatakbo ang T3 Code mula sa opisyal nitong AppImage release sa `~/.local/share/t3code` sa halip na mula sa isang package, kaya ina-update nito ang sarili nito. Nagtatanong ang pag-install nito kung magsisimula sa Stable o Nightly channel; lumipat sa ibang pagkakataon sa mga setting ng T3 Code. Nakatira ang iyong mga thread at setting sa `~/.t3`, at ang pag-alis ng T3 Code sa ilalim ng _Remove > AI_ ay dinadala sila kasama nito.

### Mga lokal na modelo

Magpatakbo ng isang open model sa sarili mong machine para sa iyong mga coding agent. Nananatili sa machine ang iyong mga prompt at code; walang ipinapadala sa modelo ang umaalis dito. Magsimula sa:

```bash
omarchy models use best text
```

Ise-set up nito ang pinakamahusay na text model para sa machine na ito, ang uri na ginagamit ng iyong mga agent. Ang mga image, video at music model ay may sarili nilang pinakamahusay: `omarchy models use best image`, `video` o `music`. Patakbuhin ang `omarchy models use best` para makita ang pinili ng bawat uri para sa machine na ito.

O buksan ang panel ng mga lokal na modelo mula sa sparkles icon nito sa top bar, sa tabi ng icon ng mga agent, o gamit ang Super + Ctrl + Alt + X, at piliin ang +. Lumalabas ang icon kapag may modelong kasya sa machine na ito. Ang Podman, na nagpapatakbo ng mga modelo, ay kasama ng Omarchy, pati na rin ang container toolkit ng NVIDIA sa isang NVIDIA machine, na nagbibigay sa kanila ng GPU; kung nawawala ang alinman, i-install ito ng unang setup. Pagkatapos ay pipiliin ng Omarchy ang inirerekomendang modelo para sa machine na ito, ida-download ito, at sisimulan ito. Asahan ang download na sampu-sampung GB at ang karamihan sa memory ng machine ay ginagamit habang tumatakbo ang modelo: gumagamit ang Flash Next ng humigit-kumulang 100 GiB kasama ang buong 256K context nito. Kung hawak ng ibang mga modelo ang memory na kailangan nito, ise-set up itong nakahinto, handang magsimula kapag huminto ka ng isa. Humihinto ang modelo sa logout; ihinto mo ito mismo kapag kailangan mo ang memory para sa iba pang bagay.

Ipinapakita ng `omarchy models list` ang mga opsyon at ipinaliliwanag kung bakit hindi kasya ang ilan. Para mag-set up ng isa pa, patakbuhin ang `omarchy models use <recipe>`. Ngayon, ang `qwen3.8-flash-next-gufo` at `qwen3.8-27b-gufo` ay available para sa mga 128 GB Strix Halo machine; ang 27B ay gumagamit ng humigit-kumulang 40 GiB, kaya nag-iiwan ito ng puwang para sa ibang trabaho. Sa isang 64 GB laptop na may Intel's Arc B390, ang `qwen3.6-35b-a3b-llamacpp` ay tumatakbo sa humigit-kumulang 30 GiB. Ang mga bagong recipe at rekomendasyon ay dumarating kasama ng `omarchy update`, sa pamamagitan ng package.

Bawat modelong ise-set up mo ay nakakakuha ng sarili nitong linya sa panel ng mga lokal na modelo: play para simulan ito, pause para ihinto ito at palayain ang memory nito, at ang terminal button para buksan ang agent mo rito. Sa itaas, ipinapakita ng isang bar kung paano nahahati ang memory ng machine sa pagitan ng Omarchy mismo (ang system at ang iyong mga app), bawat tumatakbong modelo, at kung ano ang libre. Ituro ang isang nakahintong modelo at ipapakita ng bar kung kasya ito, o kung gaano ito kakulangan. Marami ang maaaring tumakbo nang sabay kapag kasya sila sa memory nang magkasama; kung hindi kasya ang isa, sasabihin ng Omarchy kung aling tumatakbong modelo ang ihinto. I-drag ang mga linya gamit ang logo nila para muling ayusin sila, at pindutin ang Delete sa isang napiling linya para alisin ang isang modelo at ang download nito.

Bawat coding model na ise-set up mo ay nakakakuha rin ng sarili nitong entry sa app launcher, sa ilalim ng pangalan ng modelo at kasama ang logo ng gumawa nito, sa paraang ang pag-sign in sa Claude, Codex o Grok ay nagdaragdag ng isa. Binubuksan nito ang agent mo sa modelong iyon, at sinisimulan muna ang modelo kung hindi ito tumatakbo: ipinapakita ng terminal na naglo-load ito at ibibigay sa agent kapag handa na ito. Ang pag-alis ng isang modelo ay nag-aalis ng entry nito.

Hindi bawat modelo ay para sa coding. Ang mga image, video at music model ay nagbubukas sa Fantasi sa halip, ang app ng Omarchy para sa paggawa ng mga larawan, video at musika gamit ang isang modelong tumatakbo sa machine na ito, na pinili roon o mula sa kanilang linya sa panel ng mga lokal na modelo.

Ang isang modelo ay patuloy na tumatakbo nang eksakto kung paano ito sine-set up, kaya hindi kailanman nire-restart ng isang Omarchy update ang isa sa ilalim ng iyong mga agent. Kapag may mas bagong runtime o mas bagong mga weight ang Omarchy para sa isang modelong sine-set up mo, ipinapakita ng linya nito ang isang update button: pindutin ito at muling ise-set up ang modelo sa background, na dina-download lamang kung ano ang nagbago, at magre-restart sa bagong bersyon. Ang isang modelong nakahinto ay nananatiling nakahinto. Ginagawa ng `omarchy models update` ang pareho para sa bawat modelo mula sa isang terminal.

Mula sa command line, ginagawa ng `omarchy models start <recipe>` at `omarchy models stop <recipe>` ang pareho, ipinapakita ng `omarchy models status` ang bawat modelo, at binubuksan ng `omarchy agent --local-model <recipe>` ang modelong iyon sa pi, anuman ang default mong agent. Para gawing ang lokal mong modelo ang binubuksan ng agent hotkey, ng Quake console, at ng _Make something_, patakbuhin ang `omarchy default agent local` o i-star ang isang tumatakbong modelo sa panel ng mga agent. Inililista rin ng pi ang bawat modelong sine-set up mo, at ang mga nasa machine na ipinares mo, sa sarili nitong model picker, kaya naaabot din sila ng payak na `pi`. Maaari ring kumonekta ang anumang OpenAI-compatible client: ipinapakita ng `status` ang address ng bawat modelo (ang una ay `http://127.0.0.1:11435/v1`), ang pangalan ng recipe ay ang modelo, at ang key ay nasa `~/.config/omarchy/agent-local/key`.

Ang `omarchy models remove <recipe>` ay nagbubura ng isang modelo at ng mga download na hindi ginagamit ng ibang modelo.

Ang mga third-party runtime ay nilagyan ng label ng kanilang publisher. Pinapatakbo ng Omarchy ang bawat modelo nang walang network access.

### Mga lokal na LLM

Inirerekomenda ng Omarchy ang dalawang paraan ng pagpapatakbo ng mga lokal na LLM model: LM Studio at Ollama. Nagbibigay ang LM Studio ng GUI interface para sa paghahanap ng mga open-weight model, pag-install sa kanila, at pagpapatakbo sa kanila. Mahusay itong paraan para madaling makapagsimula. Nag-aalok ang Ollama ng CLI para sa paggawa nito nang katulad. Ngunit kung bago ka sa mga lokal na modelo, magsisimula ako sa LM Studio. Maaari mong i-install ang alinman sa ilalim ng _Install > AI_ sa Omarchy Menu.

### Ang mga Omarchy skill

Tinutulungan ng mga agent skill ang AI na gumamit ng mga partikular na tool sa isang partikular na paraan, at nagpapadala ang Omarchy ng pito sa kanila. Sinasaklaw ng omarchy skill ang pag-aangkop ng system, gaya ng pag-aayos ng Hyprland config mo o pag-aayos ng bar. Sinasaklaw ng omarchy-make-theme, omarchy-make-plugin, omarchy-make-app, at omarchy-make-game ang paggawa ng bagong bagay, sinasaklaw ng omarchy-contribute ang pag-uulat ng bug o pagpapadala ng fix sa upstream, at ginagawa ng omarchy-diagnose-crash ang pagdaan sa core dump ng isang crash. Naka-symlink sila sa mga skill directory para sa Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` at bawat `~/.hermes/profiles/*/skills`), at ang generic na lokasyon ng `~/.agents/skills`, kaya awtomatikong kinukuha sila ng karamihan sa mga harness. Ang isang skill folder na sarili mo na may parehong pangalan ay inuuna.

Ngunit dapat mong ituring ang mga skill na ito bilang experimental. Gagamitin sila ng iba't ibang modelo sa iba't ibang epekto. Pinakamainam na tumakbo muna sa plan mode, para magkaroon ka ng ideya kung ano ang gustong baguhin ng agent. At pagkatapos ay maging handa na i-rollback ang mga pagbabago o kahit na tawagan ang `omarchy reinstall configs`, kung guguluhin ng agent ang lahat.
