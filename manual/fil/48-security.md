# Seguridad

Sineseryoso nang lubos ng Omarchy ang seguridad. Ito ay ginawa upang maging isang operating system na magagamit mo sa paggawa ng _Tunay na Trabaho_ sa _Tunay na Mundo_. Kung saan ang pagkawala ng isang laptop ay hindi mauuwi sa isang emergency sa seguridad. Kaya narito ang ginagawa namin:

1. *Naka-on bilang default ang full-disk encryption*: Ito ang pinakamahalagang hakbang upang maprotektahan nang pisikal ang iyong data. Kung mawala o manakaw ang iyong computer, ganap na naka-encrypt ang data gamit ang karaniwang LUKS (Linux Unified Key Setup). Hinahayaan ka ng installer na huwag itong gamitin para sa mga makinang pansamantala lang (tingnan ang [Pagsisimula](02-getting-started.md)); ang isang install na walang encryption ay wala ng proteksyong ito, at sinumang may hawak ng drive ay makakabasa nito.
2. *Naka-enable bilang default ang firewall*: Hinaharangan bilang default ang lahat ng papasok na traffic, na may ilang eksepsiyon: port 53317 para sa [LocalSend](https://localsend.org/); mga DNS query sa sariling resolver ng computer sa Docker bridge address (172.17.0.1), na tinatanggap mula sa mga private address range na ibinibigay ng Docker sa mga container nito; at multicast DNS (port 5353), na nagpapahintulot sa mga printer at iba pang device sa iyong network na mahanap ang isa't isa at nag-aanunsyo rin ng pangalan ng iyong computer doon. Bukod sa mga iyon, pinapanatili ng firewall ang karaniwang mga allowance ng UFW para sa ping, pagkuha ng address mula sa iyong router (DHCP), at UPnP discovery. Maging ang ssh ay naka-off hanggang i-on mo ito sa pamamagitan ng _Setup > Security > SSHD_, na nag-o-authorize sa iyong SSH key, nag-o-off ng mga password login, at saka pa lamang nagbubukas ng port 22 (may rate limit laban sa brute force). Ikinakandado pa namin ang Docker access gamit ang [ufw-docker](https://github.com/chaifeng/ufw-docker) setup upang pigilan ang iyong mga container na aksidenteng malantad sa mundo.
3. *Palaging may pinakabagong mga update ang Arch*: Ang Arch, ang pinagbatayang distro ng Omarchy, ay isang rolling distribution. Ibig sabihin, ang anumang kahinaan sa seguridad na matuklasan at ma-patch sa anumang package ay mabilis na magiging available para i-install gamit ang `omarchy-update`. Sa ganoong paraan, palagi mong pinapatakbo ang pinakabago at pinakaligtas na mga bersyon ng lahat.
4. *Pinapanatili ng Omarchy ang sarili nitong mga package at mirror*: Umaasa lamang bilang default ang Omarchy sa mga package mula sa sariling core/extra/multilib repository ng Arch (sa Arch Linux ARM sa mga ARM machine, pati na rin sa Asahi ALARM sa Apple Silicon) at sa sarili nitong Omarchy Package Repository. Maaari kang mag-install ng software nang direkta mula sa AUR, pero hindi ginagawa iyon ng base install — iilan lamang na opsyonal na install, tulad ng mga third-party browser, ang kumukuha mula sa AUR.
5. *Pinoprotektahan tayo ng Cloudflare laban sa DDoS*: Ang imprastraktura ng distribusyon ng Omarchy — ang mga ISO, ang mga package ng Omarchy, ang Arch mirror — ay protektado sa likod ng mabigat na DDoS shield ng Cloudflare at naka-host sa kanilang CDN. Nagbibigay ito ng napakahusay na availability.

## Pagpapalit ng iyong mga password

May dalawang password ka sa isang naka-encrypt na install: ang isa na nag-a-unlock ng drive sa boot, at ang isa na ginagamit mo sa pag-log in at sa `sudo`. Ginagawa ng Setup na pareho ang mga ito. Binabago ng _Update > Password_ sa Omarchy menu ang dalawa nang sabay, kaya mananatili silang pareho: hihingin nito ang kasalukuyang password ng drive, pagkatapos ang bago, babaguhin ang sa drive at pagkatapos ay itatakda ang iyong login password upang tumugma. Kung walang drive encryption, ang login password mo lang ang babaguhin nito. Kung maantala ang isang pagpapalit, patakbuhin muli ang _Update > Password_: hihingin nito ang password na nag-a-unlock ng drive ngayon, tatapusin ang pagpapalit, at itatakda ang iyong login password dito. Upang baguhin ang password ng isa pang naka-encrypt na drive, patakbuhin ang `omarchy-drive-password` sa isang terminal.

## Pagpapasa ng makinang nagamit mo na

Kung ibibigay mo ang iyong makina sa ibang tao, hindi mo kailangang i-reinstall ito. Patakbuhin ang _Remove > Factory Reset_ sa Omarchy menu, i-type ang `reset` upang kumpirmahin, ilagay ang iyong drive encryption password kung hingin, at mag-reboot. Buburahin nito ang bawat user account at lahat ng nasa `/home`, itatapon ang lahat ng package at pagbabago sa system na ginawa mo mula noong installation, at lilinisin ang pagkakakilanlan ng makina — mga network connection, host key, at lahat. Ang lalabas pagbalik ay ang setup wizard mula sa unang boot, handa para ilagay ng bagong may-ari ang sarili nilang pangalan, password, at encryption password.

Gumagana ito sa pamamagitan ng pag-restore ng baseline snapshot na kinukuha ng installer, kaya available lamang ito sa mga makinang na-install mula sa Omarchy ISO. At sa isang drive na walang encryption, ang reset ay pagbura lamang sa halip na secure erase, kaya kung sensitibo ang data, gumawa na lang ng fresh install.

## Sudo na walang password

Minsan gusto mong tumigil ang `sudo` sa paghingi, kadalasan kapag ang isang AI agent ay gumagawa ng mahabang trabaho sa system para sa iyo. Itatanong ng _Setup > Security > Passwordless Sudo_ kung gaano katagal papayagan ang access: **15 minuto**, **1 Oras**, **1 Araw**, o **Permanente**. May lalabas na pulang warning icon sa tabi ng iba pang indicator sa menu bar habang aktibo ang access. I-click ito o patakbuhin muli ang command upang i-off ang access. Maaari ka ring magpasa ng sarili mong bilang ng minuto (mula 1 hanggang 1440) gamit ang `omarchy-sudo-passwordless 30`, o gamitin ang `omarchy-sudo-passwordless permanent`.

Awtomatikong mag-e-expire ang timed access, kabilang ang kaagad pagkatapos mag-resume mula sa isang suspend na lumampas sa deadline. Ang pag-restart ng computer ay maagang nagtatapos nito. Ang permanenteng access ay nabubuhay sa mga reboot at mananatiling naka-enable hanggang i-disable mo ito.

Ang pag-update o pag-alis ng settings package ng Omarchy ay nagtatapos ng anumang pansamantalang grant bago magbago ang suporta nito sa expiry. Kung mag-ulat ang command ng authorization o cleanup error, ayusin ito bago subukang mag-enable ng isa pang grant; ang isang error ay hindi nangangahulugang hindi aktibo ang passwordless access.

Maging malinaw ang mata tungkol dito: habang naka-on ito, anumang tumatakbo bilang iyong user ay makakagawa ng kahit ano bilang root nang hindi tinatanong. Iyon ang buong punto, at iyon din ang buong panganib.
