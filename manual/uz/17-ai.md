### Agentlarni o‘rnatish va yangilash

Hermes va OpenClaw dan tashqari, bu agentlar mise ning kechiktirilgan o‘rnatishidan foydalanadi: birinchi ishga tushirish CLI ni o‘rnatadi, keyingi ishga tushirishlar uni qayta ishlatadi. mise shuningdek o‘rnatilgan agent uchun yangi versiya borligini ko‘pi bilan har to‘rt soatda bir marta, u boshlanishidan sal oldin yoki fon rejimida shell so‘rovida tekshiradi. Agar o‘sha yangilanish muvaffaqiyatsiz bo‘lsa yoki siz oflayn bo‘lsangiz, o‘rnatilgan versiya ishlaydi. `omarchy update` o‘rnatilgan agentlarni Omarchy ning qolgan qismi bilan birga yangilaydi, `mup` esa faqat mise boshqaradigan vositalarni yangilaydi.

Agentning o‘z yangilovchisi, masalan `claude update`, `codex update` yoki ilovadagi yangilash tugmasi, mise boshqaradigan o‘rnatishni yangilamaydi. `codex update` muvaffaqiyatsiz tugaydi, `claude update` esa muvaffaqiyatli deb xabar berishi mumkin, biroq mise kuzatmaydigan alohida nusxani o‘rnatadi. Agar agentning o‘z o‘rnatuvchisi va yangilovchisidan foydalanishni afzal ko‘rsangiz, uni `disable_tools` ga qo‘shing; qarang [Oldindan o‘rnatilgan CLI vositalari](18-development-tools.md#preinstalled-cli-tools).

Kerak bo‘lishidan oldin barcha sozlangan lazy vositalarni o‘rnatish uchun `mise install --include-lazy` ni ishga tushiring. Bunga agentlar qatorida Omarchy ning boshqa birlamchi CLI vositalari ham kiradi. Bitta vositani o‘rnatish yoki o‘zingizning o‘rnatishingizdan foydalanish uchun [Oldindan o‘rnatilgan CLI vositalari](18-development-tools.md#preinstalled-cli-tools) ga qarang.

`grok` mise ning birinchi tomon `grok` paketi orqali, `claude` va `codex` bilan bir xil tarzda o‘rnatiladi. `grok` ni ishga tushiring yoki uni _Agent > Harness_ ostida tanlang. x.ai dagi `curl | bash` o‘rnatuvchisini o‘tkazib yuboring. O‘sha yo‘l `~/.grok/bin` ga ikkinchi nusxani qo‘yadi, uni `PATH` boshiga qo‘shadi va Omarchy ning wrapper ini ustiga yozadi.

`dsh` o‘zining brauzer UI sini `127.0.0.1:3080` da ochadi, ishga tushirilgan katalog uning birlamchi ish maydoni bo‘ladi. Uning brauzer UI si boshlang‘ich prompt qabul qilmaydi, shuning uchun `omarchy agent prompt` uni prompt clipboardingizda yopishtirish uchun tayyor holda ochadi. Omarchy uni DeepSeek ning tasdiq talab qilinmaydigan ruxsat preseti bilan boshlaydi. DeepSeek Harness uning rasmiy model API sidan foydalanganda sessiya jurnallarini DeepSeek ga yuklaydi; buni uning brauzer UI sida _Settings > General > Upload Session Log_ ostida o‘chiring. Unga yuborgan fikr-mulohazangiz ham sessiya bilan birga yuklanadi, agar uni `DSH_TELEMETRY_MODE=DISABLED` bilan boshlamasangiz, bundan mustasno.

### Birlamchi agent

Birlamchi agentingizni `omarchy default agent <name>` bilan yoki Omarchy Menu (`Super + Space`) dagi _Agent > Harness_ ostida tanlang. Agar agent hali o‘rnatilmagan bo‘lsa, uni tanlash avval uni o‘rnatadi, shuningdek unga ilova ishga tushirgichida Agent yonida o‘zining ishga tushirgichi ham beriladi. Yangi Omarchy bir martalik bildirishnoma bilan sizni ushbu tanlovni qilishga taklif qiladi.

Claude ni tanlash Chromium, Chrome, Brave, Brave Origin va Edge uchun uning brauzer kengaytmasini ham sozlashga harakat qiladi. Kengaytmani sozlash barcha foydalanuvchilarga taalluqli va tizim parolingizni so‘rashi mumkin; bekor qilish yoki kengaytma o‘rnatilishi muvaffaqiyatsiz bo‘lishi ham Claude ni tanlaydi va ishga tushiradi. Brauzeringizni qayta ishga tushiring, so‘ralsa kengaytmani yoqing va uni ulashni yakunlash uchun Claude ga kiring. Ulanishni tekshirish uchun Claude da `/chrome` ni ishga tushiring. Firefox va Zen bu kengaytmani qo‘llab-quvvatlamaydi. Agar ushbu sozlama qo‘shilishidan oldin Claude allaqachon birlamchi agentingiz bo‘lgan bo‘lsa, kengaytmani o‘rnatish uchun uni yana tanlang.

Tanlab bo‘lganingizdan so‘ng, `Super + Shift + Ctrl + A` birlamchi agentni alohida terminal oynasida ishga tushiradi (yoki hali tanlamagan bo‘lsangiz tanlovchini ochadi). Uni to‘g‘ridan-to‘g‘ri vazifaga ham boshlashingiz mumkin: `omarchy agent prompt "Review this project"`. Freebuff va DeepSeek Harness boshlang‘ich prompt qabul qilmaydi, shuning uchun ular buning o‘rniga prompt clipboardingizda yopishtirish uchun tayyor holda ochiladi. Shu tarzda ishga tushirilgan agentlar o‘zlarining so‘rash uchun to‘xtamaydigan rejimlarida nazoratsiz ishlaydi, shuning uchun ular haqiqatan ham biror narsa qilishiga tayyor bo‘ling! MiniMax Code interaktiv sessiyalari uchun bunday rejimga ega emas, shuning uchun u odatdagidek ruxsat so‘raydi. Va agentlar uy katalogingiz uchun ishonchni eslab qolishdan bosh tortganligi sababli, `$HOME` dan ishga tushirishlar uning o‘rniga `~/Work` da boshlanadi.

Terminal yorliqlari ham bor: `a` joriy terminalda birlamchi agentni inline ishga tushiradi, `c`, `cx` va `cy` esa OpenCode, Claude Code va Codex ni to‘g‘ridan-to‘g‘ri boshlaydi (yana ularning avtomatik tasdiqlaydigan rejimlarida). Tema o‘zgarishlari agentlarga ham sinxronlanadi: Claude Code, Pi, OpenCode va Hermes (Omarchy uni o‘rnatgandan so‘ng) barchasi siz Omarchy temasini almashtirganingizda unga moslashadi.

### Agent ko‘rsatmalaringiz

Har bir agent uchun shaxsiy qoidalar `~/.agents/skills` dagi umumiy skilllar yonida `~/.agents/AGENTS.md` da joylashadi. Uni _Agent > Instructions_ ostida oching, u shuningdek uni o‘zining global faylini saqlaydigan har bir harness ga bog‘laydi: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, Copilot ning `~/.copilot/copilot-instructions.md` va hokazo. Crush va Amp `~/.config/AGENTS.md` bog‘lanishini o‘qiydi, omp, Kimi va DeepSeek Harness esa `~/.agents/AGENTS.md` ni to‘g‘ridan-to‘g‘ri o‘qiydi. Birlamchi agentni tanlash ham uni bog‘laydi. Agar hali umumiy fayl bo‘lmagan bo‘lsa, sizda avvaldan bor bo‘lgan ko‘rsatmalar fayli umumiy faylga aylanadi; aks holda u bog‘lanish yonida `.bak` sifatida saqlanadi. Boshqa agentni o‘rnatgandan so‘ng qayta bog‘lash uchun `omarchy agent instructions` ni ishga tushiring.

### Agentlar paneli

Yuqori panelda agentlar belgisi bor. Agentni sozlashdan oldin, uning paneli sizni Claude, Codex yoki Grok ga kirish bo‘yicha olib boradi va birinchisi birlamchi agentingizga aylanadi. Shundan so‘ng, panel har bir obunani bitta sahifaga joylashtiradi: har bir agent va hisob uning rejasi bilan, uning 5 soatlik sessiya va haftalik limitlarining har biri uchun o‘lchagich va u tiklanishigacha qolgan vaqt bilan (aniq foiz uchun ustiga olib boring), yoki qolgan oldindan to‘langan balans bilan, barchasida siz foydalangan narsalar bo‘ylab almashib turadigan qator ostida, masalan bu haftadagi tokenlar va eng ko‘p ishlatgan modelingiz. _Make something cool_ ostida u birlamchi agentingizga vazifani topshiradigan yangi tema, plugin, ilova yoki o‘yin uchun boshlang‘ich promptlarni taklif qiladi. Ilovalar Omarchy ning o‘z Hype, Monologue va Omacut ilovalari kabi, C++ va Qt Quick da, omarchy-make-app agent skilliga amal qilib quriladi va ularga kerak bo‘lgan kompilyator va Qt qismlari o‘rnatilgan holda keladi. O‘yinlar `~/Games/vibes` dagi bitta three.js sahifasi bo‘lib, omarchy-make-game agent skilliga amal qiladi va barchasi joriy temadagi bitta Game Vibes ishga tushirgichidan ochiladi; ular three.js ni internetdan yuklaydi, shuning uchun boshlash uchun ulanish kerak. Claude Code, Codex, Grok, Kimi, Cursor va uning Grok Bot ruxsati, GitHub Copilot, Muse, Antigravity va Devin ularning limitlari bilan tayyor holda qamrab olingan, Kimchi o‘z rejasi, oldindan to‘langan kreditlari va xarajat budgetlari bilan, Hermes, Mistral Vibe va Qwen Code esa siz ulardan foydalanganingizdan so‘ng sessiyalari va tokenlarini ko‘rsatadi. pi, omp yoki opencode orqali foydalanadigan provider rejalari va kalitlari ham ko‘rinadi: OpenCode Zen va Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan va Synthetic ularning limitlari bilan; OpenRouter va DeepSeek oldindan to‘langan balanslari bilan; Fireworks so‘nggi 30 kundagi xarajati bilan. O‘z uskunangizda ishga tushiradigan modellardan tokenlar ham jami hisobga qo‘shiladi; modellarning o‘z paneli bor, [Mahalliy modellar](#local-models) ostida tasvirlangan. Har bir agent, uni nechta harness orqali boshqarmang, kim hisob yozsa o‘sha ostida bir marta hisoblanadi.

Panel uchun panel belgisini chap tugma bilan bosing yoki `Super + Ctrl + X` ni bosing, birlamchi agentingizni ishga tushirish uchun o‘ng tugma bilan bosing va yangilash uchun o‘rta tugma bilan bosing. Uning orqasidagi foydalanish yozuvlari har 15 daqiqada `omarchy agent usage update` tomonidan qayta yaratiladi va panel hatto sinxronlangan papka orqali boshqa mashinalaringizdan foydalanishni birlashtira oladi. To‘liq sozlamalar uchun `$OMARCHY_PATH/shell/plugins/agents/` ostidagi README ga qarang.

### Bir nechta obuna

Agar siz bir nechta Claude, Codex yoki Grok rejasiga to‘lasangiz — masalan shaxsiy Max va ish rejasi — Omarchy ularning barchasini kirgan holda saqlay oladi va ular orasida harakatlana oladi. Obunani agentlar panelidagi + bilan qo‘shing, u sizni shu yerning o‘zida olib boradi, yoki `omarchy agent account add claude Work` (yoki `codex`, yoki `grok`) bilan qo‘shing. Agar CLI yo‘q bo‘lsa, u uni o‘rnatadi. Provider uchun birinchi hisob oddiy brauzeringiz orqali, CLI doim qaraydigan joyda kiradi. Undan keyingi har biri shaxsiy oyna orqali kiradi, shuning uchun brauzeringiz allaqachon kirgan hisob xatolik bilan olinib qolmaydi; u yerda qo‘shayotgan hisobingiz sifatida kiring va avval ochib qo‘ygan har qanday shaxsiy oynani yoping. Buni qilish uchun CLI dan hech qachon chiqmang: chiqish saqlangan kirishni bekor qiladi va o‘sha hisob yana qo‘shilishi kerak bo‘ladi.

Obuna kirishlaringizni SSH orqali boshqa Omarchy mashinasiga nusxalash uchun `omarchy agent account copy user@laptop` ni ishga tushiring. Agar manzilda o‘rnatilgan qabul qiluvchi bo‘lmasa, jo‘natuvchi vaqtinchalik qabul qiluvchini ta’minlaydi, shuning uchun eski Omarchy mashinalari yangilanishsiz hisoblarni qabul qila oladi. O‘rnatilgan qabul qiluvchilar ustunlikka ega. Bu barcha Claude, Codex va Grok obunalarini nusxalaydi; ularni tanlash uchun provider nomlarini qo‘shing, masalan `omarchy agent account copy laptop claude`. Hisob nomlari va buyruq ID lari manbaga mos keladi, manzilda allaqachon bor hisoblar ham kiradi. Manzildagi aloqasiz hisoblar nomlari to‘qnashsa raqamli qo‘shimcha oladi, sozlamalar, skilllar, pluginlar va suhbat tarixi esa har bir mashinada mahalliy qoladi.

Mavjud manzil hisob ma’lumotlari saqlanadi. U yerda allaqachon kirilgan manba hisobining nomi uning hisob ma’lumotlarini almashtirmasdan sinxronlanadi; boshqa hisoblar uning yoniga qo‘shiladi. Mos keladigan hisoblar uchun saqlangan hisob ma’lumotlarini almashtirish uchun manzilda o‘sha hisob sessiyalarini yopgandan so‘ng `omarchy agent account copy --replace laptop claude` dan foydalaning. Yangi manzil manbaning faol hisobi va almashish afzalliklarini ham oladi; o‘rnashgan manzil o‘zinikini saqlaydi.

Hisob ma’lumotlari SSH orqali o‘tadi va manzilda shaxsiy fayllarda saqlanadi, shuning uchun faqat ishonadigan mashinalaringizga nusxalang. Bu bir martalik nusxa, davom etuvchi sinxronlash emas. Codex yangilash tokenlari boshqa mashina tomonidan aylantirilishi mumkin, bu nusxalangan kirishni yangilashga muhtoj qilib qoldiradi; bir nechta mashinada bir vaqtda foydalanish uchun alohida kirishlar eng ishonchli tanlov bo‘lib qoladi. Qarang [Codex ning hisob autentifikatsiyasi bo‘yicha qo‘llanmasi](https://developers.openai.com/codex/auth/ci-cd-auth).

Har bir provider uchun bitta hisob faol va har bir yangi sessiya o‘sha sifatida boshlanadi: `cx`, `cy`, oddiy `claude`, `codex` yoki `grok`, `omarchy agent` orqali ishga tushirilgan har qanday narsa, CLI ni `PATH` da topadigan skriptlar yoki muharrirlar. `omarchy agent account use work` bilan almashtiring (va `omarchy agent account use main` bilan qayting), yoki panelda hisob raqamini bosib keyin `Enter` ni bosish (yoki uning Use tugmasini bosish) orqali almashtiring. Ishlayotgan Claude sessiyalari ham keyingi xabardan almashtiradi: har bir Claude sessiyasi `~/.claude` da ishlaydi, u doim faol hisobning kirishini saqlaydi. Eski Omarchy tomonidan hisobning o‘z papkasida boshlangan Claude sessiyasi yopilguncha o‘sha kirishni saqlaydi, shuning uchun almashtirish o‘sha sessiyalarni nomlaydi va ular ketgach o‘z-o‘zidan tugaydi. Ishlayotgan Codex va Grok sessiyalari boshlagan hisobda qoladi. Suhbat tarixi, sozlamalar, skilllar va pluginlar hisoblar bo‘ylab umumiydir, shuning uchun bir xil papkadagi `claude --continue` yangi hisobda qoldirgan joyingizdan davom etadi.

Bir nechta hisob bo‘lsa, panel har bir hisob limitlarini yonma-yon ko‘rsatadi, foali belgilangan. Birlamchi holatda Omarchy faol hisob limitning 95% idan o‘tganda sizni xabardor qiladi va bildirishnomani bosish eng ko‘p bo‘sh joyi bor hisobga o‘tadi. Buning o‘rniga uning o‘zi almashishi uchun hisob qatorining ustiga olib boring va Use yonida paydo bo‘ladigan Autoswitch ni bosing (yoki `m` ni bosing), yoki `omarchy agent account mode auto` ni ishga tushiring; u yoqilgan paytda Autoswitch Use o‘rnini oladi va uni yana bosish xabardor qilishga qaytadi. Chegarani o‘zgartirish uchun raqam qo‘shing, masalan `omarchy agent account mode auto 90`. Agar har bir hisob chegaradan yuqori bo‘lsa, siz bu haqda bir marta eshitasiz, qaysi hisob birinchi bo‘shashi bilan birga. Faol hisob uning chegarasidan 15 ball ichida bo‘lsa (birlamchi holatda 80%), uning limitlari har 15 daqiqa emas, har uch daqiqada tekshiriladi.

`omarchy agent account list` har bir hisobni va uning eng so‘nggi limitlarini ko‘rsatadi, `omarchy agent account remove work` bittasini unutadi va `omarchy agent account rename primary Hey` bittasini qayta nomlaydi (yoki panelda hisob nomini bosing). Bu buyruqlar birlamchi agentingiz hisoblarida ishlaydi; boshqa providerga yetish uchun uni avval nomlang, masalan `omarchy agent account use codex side`. `~/.claude` yoki `~/.codex` da sizda allaqachon bor bo‘lgan kirish _Main_ hisobdir. Codex niki turgan joyida qoladi; Claude niki boshqa hisob faol bo‘lgan paytda o‘z papkasida kutadi. Taxminan sakkiz soatdan ortiq ishlatilmagan hisob _Sign-in required_ ni ko‘rsatishi mumkin; o‘sha hisobga panelning o‘zida yana kirish uchun uni bosing yoki unga almashing va sessiyani boshlang, bu kirishni o‘z-o‘zidan yangilaydi. `claude mcp add` bilan qo‘shadigan MCP serverlar har bir Claude hisobiga yetadi, chunki ularning barchasi `~/.claude` da ishlaydi; Codex va Grok uchun hisob qo‘shilgan paytda sizda bor bo‘lgan serverlar unga birga keladi, lekin keyingilari faqat ularni qo‘shgan hisobingizga yetadi. Claude Desktop o‘z kirishini saqlaydi, CLI bajariladigan fayliga mutlaq yo‘l bilan sozlangan Codex yoki Grok vositalari almashishga amal qilmaydi. Aniq `CLAUDE_CONFIG_DIR`, `CODEX_HOME` yoki `GROK_HOME` tanlangan hisobdan ustun keladi.

### Buzilishni tashxislash

Omarchy jarayon buzilishlari uchun systemd-coredump ni kuzatadi. Birlamchi agentni tanlaganingizdan so‘ng, yadro dumpini qiladigan har qanday dasturingiz "Process crashed" bildirishnomasini keltiradi — uni bosing va buzilish birlamchi agentingizga Omarchy ning omarchy-diagnose-crash skilli bilan birga topshiriladi, u agentni yadro dumpidan faktlarni aniqlash va buzilishni yuqori oqimga xabar berishga arziydimi yoki yo‘qligini hal qilish bo‘yicha olib boradi. Uni `coredumpctl list` dan har qanday PID ga qarshi `omarchy agent crash <pid>` bilan qo‘lda ham ishga tushirishingiz mumkin.

Kuzatish birlamchi holatda yoqilgan. Uni _Trigger > Toggle > Crash Capture Off_ ostida (yoki `omarchy toggle crash-capture` bilan) o‘chiring va bildirishnomalar to‘xtaydi; `omarchy agent crash <pid>` hali ham qo‘lda ishlaydi.

Buzilishlarni bir vaqtda bitta dastur bo‘yicha ham jim qilishingiz mumkin, tashxis oxirida sizga shuni taklif qiladi. `omarchy crash mute hyprland` faqat o‘sha dastur uchun bildirishnomalarni to‘xtatadi, `omarchy crash mute hyprland off` ularni qaytaradi va `omarchy crash mute` o‘zi siz jim qilgan narsalarni ro‘yxatlaydi. U bajariladigan fayl yo‘lini uning nomi kabi mamnuniyat bilan qabul qiladi, shuning uchun `omarchy crash mute /usr/bin/hyprland` xuddi shu ishni qiladi. Ichida bo‘sh joy bor nomni qo‘shtirnoqqa oling, masalan `omarchy crash mute 'Some App'`. Qolgan hamma narsa hali ham xabar beradi va jim qilingan dastur hali ham buziladi — bu eslatmani yashiradi, hech narsani tuzatmaydi.

### Ish stoli ilovalari

_Install > AI_ menyusi bir nechta grafik AI ilovalarini ham o‘z ichiga oladi: Amp Desktop, Antigravity Desktop, ChatGPT ish stoli ilovasi, Claude ish stoli ilovasi (Anthropic ning Linux beta versiyasi, Chat, Cowork va Claude Code tab lari bilan), xAI modellari bilan suhbatlashish uchun Grok Bot, Herdr Desktop, Hermes Desktop, OpenClaw, Perplexity ish stoli ilovasi va T3 Code. Grok Bot ish stoli suhbat ilovasidir. Kodlash agenti `grok` buyrug‘idir.

Hermes Desktop — bilish kerak bo‘lgani, chunki mashinada bitta Hermes bor va u ilovaniki: Hermes faqat ilova orqali o‘rnatiladi va birlamchi agent ishga tushiradigan `hermes` buyrug‘i ilovaniki. Hermes ni birlamchi agent sifatida tanlash _Install > AI_ bandi qiladigan xuddi shu narsani o‘rnatadi: paketni va Hermes ning o‘z o‘rnatuvchisi tomonidan sozlangan, birinchi marta bir necha daqiqa oladigan `~/.hermes` ostidagi Hermes runtime ni. O‘sha runtime terminaldagi `hermes` buyrug‘i, birlamchi agent va ilova hammasi foydalanadigan yagona Hermes dir va u Omarchy versiyasini kutmasdan `hermes update` bilan o‘zini yangilaydi. Uni o‘rnatish shuningdek Hermes ga Omarchy temasini `omarchy` nomli skin sifatida beradi, har bir Hermes yuzasi siz temalarni almashtirganingizda unga moslashadi; agar xohlamasangiz Hermes ning Appearance sozlamalarida yoki `/skin` bilan boshqasini tanlang va Omarchy o‘sha tanlovni o‘z holicha qoldiradi. Ilovani _Remove > AI_ ostida olib tashlash avval Hermes ni yopadi, gateway ham kiradi, o‘sha runtime ni u bilan birga olib ketadi va siz boshqacha aytmasangiz chatlaringiz, xotiralaringiz va Hermes o‘zi uchun yozgan skilllarini saqlaydi: u o‘sha ma’lumot va ulanish sozlamalaringiz ham ketishi kerakmi deb so‘raydi, birlamchi javob yo‘q.

OpenClaw ning ish stoli tajribasi uning Control UI si bo‘lib, u o‘zining mahalliy gateway i bilan qo‘llab-quvvatlanadigan veb-ilova sifatida ochiladi. OpenClaw `~/.openclaw` da yashaydi va o‘zini yangilaydi: Control UI ning "Update Gateway" tugmasidan foydalaning yoki `openclaw update` ni ishga tushiring va gateway yangi versiyada qayta boshlanadi. Omarchy faqat yangi o‘rnatish qaysi versiyadan boshlanishini tanlaydi. OpenClaw shuningdek birlamchi agentingiz bo‘lishi mumkin: uni _Agent > Harness_ ostida tanlash `~/.openclaw` da o‘sha nusxani sozlaydi va agent OpenClaw ning gateway iga ulangan terminal UI sini ochadi. OpenClaw ni _Remove > AI_ ostida olib tashlash gateway xizmatini va ilovani u bilan birga olib ketadi va keyin `~/.openclaw` ham ketishi kerakmi deb so‘raydi, chunki u chatlaringiz va hisob ma’lumotlaringizni OpenClaw ning o‘zi va u yuklab oladigan plugin runtime lari bilan birga saqlaydi; birlamchi holatda u saqlanadi va OpenClaw ni yana o‘rnatish uni qayta oladi.

Herdr Desktop [Herdr](https://herdr.dev) ish stoli ilovasidir: oynani yopganingizda uning yadrosida ishlashda davom etadigan terminallar va kodlash agentlarining spaces, tabs va panes lari. U paketdan emas, Herdr ning o‘z o‘rnatuvchisidan keladi, shuning uchun u `~/.local/share/herdr-app` da yashaydi, agar sizda hali bo‘lmasa `~/.local/bin/herdr-core` da o‘z yadrosini olib keladi va ikkalasini ham o‘zi yangilaydi. U Omarchy `Super + Ctrl + Return` bilan jo‘natadigan `herdr` buyrug‘ining o‘rnini bosmasdan uning yonida turadi va o‘sha buyruqning to‘g‘ridan-to‘g‘ri tugmalarini oladi: `Alt + Return` va `Alt + Shift + Return` panelni pastga yoki o‘ngga bo‘ladi, `Alt + Escape` uni yopadi, `Ctrl + Alt + Arrow` panellar orasida harakatlanadi, `Alt + 1..9` va `Alt + Left/Right` tab ni tanlaydi va `Alt + Up/Down` spaces orasida harakatlanadi. `Ctrl + 1..9` space ni tanlaydi va `Alt + Shift + Up/Down` agentlar bo‘ylab qadamlaydi. `Ctrl + Space` prefix tugmalari faqat terminalda qoladi, chunki ilova ketma-ketlik uchun oddiy Ctrl tugmasini ushlab turolmaydi. Omarchy bularni `~/.config/herdr-app/keys.json` ga yozadi va `omarchy-refresh-herdr-app` ularni qayta qo‘yadi. Uni o‘rnatish Herdr ning Omarchy temasini tanlaydi, u bundan buyon Omarchy temangizga moslashadi. Herdr yorug‘ rejim uchun bitta tema va qorong‘i rejim uchun bitta tema saqlaydi, shuning uchun qorong‘i va yorug‘ Omarchy temasi orasida almashgandan so‘ng, boshqa rejim uchun Herdr ning tema tanlovchisida Omarchy ni yana bir marta tanlang.

T3 Code paketdan emas, `~/.local/share/t3code` dagi rasmiy AppImage versiyasidan ishlaydi, shuning uchun u o‘zini yangilaydi. Uni o‘rnatish Stable yoki Nightly kanalida boshlashni so‘raydi; keyin T3 Code sozlamalarida almashtiring. Threadlaringiz va sozlamalaringiz `~/.t3` da yashaydi va T3 Code ni _Remove > AI_ ostida olib tashlash ularni u bilan birga olib ketadi.

### Mahalliy modellar

Kodlash agentlaringiz uchun o‘z mashinangizda ochiq modelni ishga tushiring. Promptlaringiz va kodingiz mashinada qoladi; modelga yuborilgan hech narsa uni tark etmaydi. Quyidagidan boshlang:

```bash
omarchy models use best text
```

Bu ushbu mashina uchun eng yaxshi matn modelini, agentlaringiz foydalanadigan turdagisini sozlaydi. Tasvir, video va musiqa modellari o‘zining eng yaxshisiga ega: `omarchy models use best image`, `video` yoki `music`. Har bir turning bu mashina uchun tanlovini ko‘rish uchun `omarchy models use best` ni ishga tushiring.

Yoki mahalliy modellar panelini yuqori paneldagi, agentlar belgisi yonidagi uchqunlar belgisidan yoki Super + Ctrl + Alt + X bilan oching va + ni tanlang. Belgi model bu mashinaga sig‘ganda paydo bo‘ladi. Modellarni ishga tushiradigan Podman Omarchy bilan keladi, NVIDIA mashinasida NVIDIA ning container toolkit i ham shunday, bu ularga GPU ni beradi; agar ulardan biri yo‘q bo‘lsa, birinchi sozlash uni o‘rnatadi. Keyin Omarchy ushbu mashina uchun tavsiya qilingan modelni tanlaydi, yuklab oladi va boshlaydi. O‘nlab GB yuklanishni va model ishlayotgan paytda mashina xotirasining ko‘p qismi ishlatilishini kuting: Flash Next to‘liq 256K konteksti bilan taxminan 100 GiB ishlatadi. Agar boshqa modellar unga kerak xotirani egallab tursa, u to‘xtatilgan holda sozlanadi, birini to‘xtatganingizdan so‘ng boshlashga tayyor. Model tizimdan chiqishda to‘xtaydi; xotira boshqa narsa uchun kerak bo‘lganda uni o‘zingiz to‘xtating.

`omarchy models list` variantlarni ko‘rsatadi va ba’zilari nima uchun sig‘masligini tushuntiradi. Boshqasini sozlash uchun `omarchy models use <recipe>` ni ishga tushiring. Bugun 128 GB Strix Halo mashinalari uchun `qwen3.8-flash-next-gufo` va `qwen3.8-27b-gufo` mavjud; 27B taxminan 40 GiB oladi, shuning uchun u boshqa ish uchun joy qoldiradi. Intel ning Arc B390 siga ega 64 GB noutbukda `qwen3.6-35b-a3b-llamacpp` taxminan 30 GiB da ishlaydi. Yangi recipe lar va tavsiyalar paket orqali `omarchy update` bilan keladi.

Sozlagan har bir modelingiz mahalliy modellar panelida o‘z qatoriga ega bo‘ladi: uni boshlash uchun play, uni to‘xtatish va xotirasini bo‘shatish uchun pause va unda agentingizni ochish uchun terminal tugmasi. Yuqori bo‘ylab, qator mashina xotirasi Omarchy ning o‘zi (tizim va ilovalaringiz), har bir ishlaydigan model va bo‘sh joy orasida qanday bo‘linganini ko‘rsatadi. To‘xtatilgan modelga ko‘rsating va qator u sig‘adimi yoki qancha yetishmasligini ko‘rsatadi. Bir nechtilari xotirada birga sig‘ganda bir vaqtda ishlashi mumkin; agar bittasi sig‘masa, Omarchy qaysi ishlayotgan modelni to‘xtatishni aytadi. Ularni qayta tartiblash uchun qatorlarni ularning logotipi bo‘yicha sudrang va modelni va uning yuklanishini olib tashlash uchun tanlangan qatorda Delete ni bosing.

Sozlagan har bir kodlash modelingiz ham ilova ishga tushirgichida, model nomi ostida va uning yaratuvchisi logotipi bilan o‘z yozuviga ega bo‘ladi, Claude, Codex yoki Grok ga kirish bittasini qo‘shganidek. U agentingizni o‘sha modelda ochadi va agar model ishlamayotgan bo‘lsa, uni avval boshlaydi: terminal uning yuklanishini ko‘rsatadi va u tayyor bo‘lgach agentga topshiradi. Modelni olib tashlash uning yozuvini olib tashlaydi.

Har bir model ham kodlash uchun emas. Tasvir, video va musiqa modellari buning o‘rniga Fantasi da ochiladi, Omarchy ning bu mashinada ishlaydigan model bilan rasmlar, video va musiqa yaratish ilovasi, u yerda yoki mahalliy modellar panelidagi qatoridan tanlanadi.

Model aynan sozlanganidek ishlashda davom etadi, shuning uchun Omarchy yangilanishi agentlaringiz ostidagi bittasini hech qachon qayta boshlamaydi. Omarchy da siz sozlagan model uchun yangi runtime yoki yangi weights bo‘lsa, uning qatori yangilash tugmasini ko‘rsatadi: uni bosing va model fon rejimida yana sozlanadi, faqat o‘zgarganini yuklab oladi va yangi versiyada qayta boshlaydi. To‘xtatilgan model to‘xtatilgan holda qoladi. `omarchy models update` terminaldan har bir model uchun xuddi shuni qiladi.

Buyruq qatoridan `omarchy models start <recipe>` va `omarchy models stop <recipe>` xuddi shuni qiladi, `omarchy models status` har bir modelni ko‘rsatadi va `omarchy agent --local` birlamchi agentingiz nima bo‘lishidan qat’iy nazar, oxirgi boshlagan modelingizni pi da ochadi. OpenCode va Qwen Code ham mahalliy modeldan foydalanishi mumkin: `omarchy models harness opencode` yoki `omarchy models harness qwen` ularni buning o‘rniga u yerda ochadi va `omarchy models harness pi` orqaga qaytadi. pi shuningdek siz sozlagan har bir modelni va siz bog‘langan mashinalardagilarni o‘z model tanlovchisida ro‘yxatlaydi, shuning uchun oddiy `pi` ham ularga yetadi. Har qanday OpenAI ga mos mijoz ham ulanishi mumkin: `status` har bir model manzilini ko‘rsatadi (birinchisi `http://127.0.0.1:11435/v1`), recipe nomi modeldir va kalit `~/.config/omarchy/agent-local/key` da.

`omarchy models remove <recipe>` modelni va boshqa hech bir model foydalanmaydigan yuklanishlarni o‘chiradi.

Uchinchi tomon runtime lari ularning nashriyotchisi bilan belgilanadi. Omarchy har bir modelni tarmoqqa kirishsiz ishga tushiradi.

### Mahalliy LLMlar

Omarchy mahalliy LLM modellarini ishga tushirishning ikki usulini tavsiya qiladi: LM Studio va Ollama. LM Studio ochiq vaznli modellarni topish, o‘rnatish va ishga tushirish uchun GUI interfeysini beradi. Bu oson boshlashning ajoyib usuli. Ollama xuddi shuning uchun CLI taklif qiladi. Lekin agar siz mahalliy modellarga yangi bo‘lsangiz, men LM Studio bilan boshlagan bo‘lardim. Har ikkalasini ham Omarchy Menu dagi _Install > AI_ ostida o‘rnatishingiz mumkin.

### Omarchy skilllari

Agent skilllari AI ga aniq vositalardan aniq tarzda foydalanishga yordam beradi va Omarchy ulardan yettitasini jo‘natadi. omarchy skilli tizimni moslashni qamraydi, masalan Hyprland configingizni sozlash yoki panelni to‘g‘rilash. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app va omarchy-make-game yangi narsa yaratishni qamraydi, omarchy-contribute xato haqida xabar berish yoki yuqori oqimga tuzatish yuborishni qamraydi va omarchy-diagnose-crash buzilishning yadro dumpi bo‘yicha ishlaydi. Ular Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` va har bir `~/.hermes/profiles/*/skills`) va umumiy `~/.agents/skills` joyi uchun skill kataloglariga simli bog‘langan, shuning uchun aksariyat harnesslar ularni avtomatik oladi. Xuddi shu nomdagi o‘zingizning skill papkangiz ustunlikka ega.

Lekin bu skilllarga tajribaviy deb qarashingiz kerak. Turli modellar undan turli ta’sir bilan foydalanadi. Avval plan rejimida ishga tushirish eng yaxshisi, shunda agent nima o‘zgartirmoqchiligi haqida tasavvurga ega bo‘lasiz. Keyin esa, agar agent hamma narsani chalkashtirib yuborsa, o‘zgarishlarni orqaga qaytarishga yoki hatto `omarchy reinstall configs` ni chaqirishga tayyor bo‘ling.
