### Agentlarni o‘rnatish va yangilash

Hermes va OpenClaw dan tashqari, bu agentlar mise ning dangasa o‘rnatishidan foydalanadi: birinchi ishga tushirish CLI ni o‘rnatadi, keyingi ishga tushirishlar esa uni qayta ishlatadi. mise shuningdek o‘rnatilgan agent uchun yangi reliz borligini ko‘pi bilan har to‘rt soatda bir marta, u ishga tushishidan biroz oldin yoki fon rejimida shell prompt ida tekshiradi. Agar o‘sha yangilanish muvaffaqiyatsiz bo‘lsa yoki siz oflayn bo‘lsangiz, o‘rnatilgan versiya ishlaydi. `omarchy update` o‘rnatilgan agentlarni Omarchy ning qolgan qismi bilan birga yangilaydi, `mup` esa faqat mise tomonidan boshqariladigan vositalarni yangilaydi.

Agentning o‘z yangilovchisi, masalan `claude update`, `codex update` yoki ilovadagi yangilash tugmasi, mise tomonidan boshqariladigan o‘rnatishni yangilamaydi. `codex update` muvaffaqiyatsiz bo‘ladi, va `claude update` mise kuzatmaydigan alohida nusxani o‘rnatgan holda muvaffaqiyat haqida xabar berishi mumkin. Agar agentning o‘zining o‘rnatuvchisi va yangilovchisidan foydalanishni afzal ko‘rsangiz, uni `disable_tools` ga qo‘shing; [Oldindan o‘rnatilgan CLI vositalari](18-development-tools.md#preinstalled-cli-tools) bo‘limiga qarang.

Sozlangan barcha dangasa vositalarni ular sizga kerak bo‘lishidan oldin o‘rnatish uchun `mise install --include-lazy` ni ishga tushiring. Bunga agentlar bilan bir qatorda Omarchy ning boshqa standart CLI vositalari ham kiradi. Bitta vositani o‘rnatish yoki o‘z o‘rnatishingizdan foydalanish uchun [Oldindan o‘rnatilgan CLI vositalari](18-development-tools.md#preinstalled-cli-tools) bo‘limiga qarang.

`grok` mise ning birinchi tomon `grok` paketi orqali o‘rnatiladi, xuddi `claude` va `codex` kabi. `grok` ni ishga tushiring, yoki uni _Agent > Harness_ ostida tanlang. x.ai dagi `curl | bash` o‘rnatuvchisini o‘tkazib yuboring. O‘sha yo‘l ikkinchi nusxani `~/.grok/bin` ga qo‘yadi, uni `PATH` ning boshiga qo‘shadi va Omarchy ning wrapper ini ustiga yozadi.

`dsh` o‘zining browser UI sini `127.0.0.1:3080` da ochadi, ishga tushirish katalogi uning standart workspace i sifatida bo‘ladi. Uning browser UI si boshlang‘ich prompt olmaydi, shuning uchun `omarchy agent prompt` uni prompt clipboard ingizda yopishtirish uchun tayyor holda ochadi. Omarchy uni DeepSeek ning tasdiq talab qilmaydigan permission preset i bilan ishga tushiradi. DeepSeek Harness uning rasmiy model API sidan foydalanganda session log larini DeepSeek ga yuklaydi; buni uning browser UI sidagi _Settings > General > Upload Session Log_ ostida o‘chirib qo‘ying. Unga yuborgan feedback ingiz ham session bilan birga yuklanadi, agar uni `DSH_TELEMETRY_MODE=DISABLED` bilan ishga tushirmasangiz.

### Standart agent

Standart agentingizni `omarchy default agent <name>` bilan yoki Omarchy Menu (`Super + Space`) dagi _Agent > Harness_ ostida tanlang. Agar agent hali o‘rnatilmagan bo‘lsa, uni tanlash avval uni o‘rnatadi, va u shuningdek ilova ishga tushirgichida, Agent yonida, o‘z ishga tushirgichiga ega bo‘ladi. Yangi Omarchy sizni bir martalik bildirishnoma bilan bu tanlovni qilishga taklif qiladi.

Claude ni tanlash shuningdek Chromium, Chrome, Brave, Brave Origin va Edge uchun uning browser kengaytmasini sozlashga harakat qiladi. Kengaytmani sozlash barcha foydalanuvchilarga taalluqli bo‘ladi va tizim parolingizni so‘rashi mumkin; bekor qilish yoki kengaytmani o‘rnatish muvaffaqiyatsiz bo‘lishi baribir Claude ni tanlaydi va ishga tushiradi. Browser ingizni qayta ishga tushiring, so‘ralsa kengaytmani yoqing, va uni ulashni yakunlash uchun Claude ga kiring. Ulanishni tekshirish uchun Claude da `/chrome` ni ishga tushiring. Firefox va Zen bu kengaytmani qo‘llab-quvvatlamaydi. Agar bu sozlash qo‘shilishidan oldin Claude allaqachon standartingiz bo‘lgan bo‘lsa, kengaytmani o‘rnatish uchun uni yana tanlang.

Tanlab bo‘lganingizdan so‘ng, `Super + Shift + Ctrl + A` standart agentni maxsus terminal oynasida ishga tushiradi (yoki hali tanlamagan bo‘lsangiz tanlovchini ochadi). Uni `omarchy agent prompt "Review this project"` bilan to‘g‘ridan-to‘g‘ri vazifaga ham ishga tushirishingiz mumkin. Freebuff va DeepSeek Harness boshlang‘ich prompt olmaydi, shuning uchun ular o‘rniga prompt clipboard ingizda yopishtirish uchun tayyor holda ochiladi. Shu tarzda ishga tushirilgan agentlar o‘zlarining to‘xtab so‘ramaydigan rejimlarida qarovsiz ishlaydi, shuning uchun ularning haqiqatan ham biror narsa qilishiga tayyor bo‘ling! MiniMax Code da uning interaktiv session lari uchun bunday rejim yo‘q, shuning uchun u odatdagidek permissions so‘raydi. Va agentlar home katalogingiz uchun ishonchni eslab qolishdan bosh tortganligi sababli, `$HOME` dan ishga tushirishlar o‘rniga `~/Work` da boshlanadi.

Terminal shortcut lari ham bor: `a` standart agentni joriy terminal ichida inline ishga tushiradi, `c`, `cx` va `cy` esa OpenCode, Claude Code va Codex ni to‘g‘ridan-to‘g‘ri ishga tushiradi (yana ularning avtomatik tasdiqlaydigan rejimlarida). Tema o‘zgarishlari agentlarga ham sinxronlashadi: Claude Code, Pi, OpenCode va Hermes (Omarchy uni o‘rnatganidan keyin) Omarchy temasini almashtirganda hammasi ergashadi.

### Agentingizga ko‘rsatmalar

Har bir agent uchun shaxsiy qoidalar `~/.agents/skills` dagi umumiy skill lar yonida, `~/.agents/AGENTS.md` ga joylashadi. Uni _Agent > Instructions_ ostida oching, bu uni shuningdek o‘zining global faylini saqlaydigan har bir harness ga ham bog‘laydi: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, Copilot ning `~/.copilot/copilot-instructions.md` i, va hokazo. Crush va Amp `~/.config/AGENTS.md` bog‘lanishini o‘qiydi, omp, Kimi va DeepSeek Harness esa `~/.agents/AGENTS.md` ni to‘g‘ridan-to‘g‘ri o‘qiydi. Standart agentni tanlash ham uni bog‘laydi. Sizda allaqachon bo‘lgan ko‘rsatmalar fayli, agar hali umumiysi bo‘lmagan bo‘lsa, umumiy bo‘ladi; aks holda u bog‘lanish yonida `.bak` sifatida saqlanadi. Boshqa agentni o‘rnatgandan keyin qayta bog‘lash uchun `omarchy agent instructions` ni ishga tushiring.

### Agentlar paneli

Yuqori panelda agentlar belgisi bor. Agentni sozlashdan oldin, uning paneli sizni Claude, Codex yoki Grok ga kirish jarayonidan o‘tkazadi, va birinchisi standart agentingiz bo‘ladi. Shundan so‘ng, panel har bir obunani bitta sahifaga joylashtiradi: har bir agent va hisob uning rejasi bilan, uning 5 soatlik session va haftalik limitlarining har biri uchun o‘lchagich va u qayta tiklanguncha qolgan vaqt bilan (aniq foiz uchun ustiga olib boring), yoki qolgan oldindan to‘langan balans bilan, ularning barchasi bo‘ylab foydalanganlaringiz orasida aylanib turadigan qator ostida, masalan bu haftadagi tokenlar va eng ko‘p ishlatgan modelingiz. _Make something cool_ ostida u yangi tema, plugin, ilova yoki o‘yin uchun vazifani standart agentingizga topshiradigan boshlang‘ich prompt larni taklif qiladi. Ilovalar Omarchy ning o‘zining Hype, Monologue va Omacut lari kabi, C++ va Qt Quick da, omarchy-make-app agent skill iga amal qilgan holda quriladi, va ularga kerak bo‘lgan kompilyator va Qt qismlari o‘rnatilgan holda keladi. O‘yinlar `~/Games/vibes` dagi bitta three.js sahifasi bo‘lib, omarchy-make-game agent skill iga amal qiladi, va barchasi joriy temadagi bitta Game Vibes ishga tushirgichidan ochiladi; ular three.js ni web dan yuklaydi, shuning uchun boshlash uchun ulanish kerak. Claude Code, Codex, Grok, Kimi, Cursor va uning Grok Bot allowance i, GitHub Copilot, Muse, Antigravity va Devin ularning limitlari bilan qutidan chiqishi bilanoq qamrab olingan, Kimchi uning rejasi, oldindan to‘langan kreditlari va xarajat budget lari bilan, va Hermes, Mistral Vibe va Qwen Code ularni ishlatganingizdan keyin session lari va tokenlarini ko‘rsatadi. pi, omp yoki opencode orqali ishlatadigan provider rejalari va kalitlari ham paydo bo‘ladi: OpenCode Zen va Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan va Synthetic ularning limitlari bilan; OpenRouter va DeepSeek ularning oldindan to‘langan balanslari bilan; Fireworks so‘nggi 30 kundagi xarajatlari bilan; va o‘z uskunangizda ishlatadigan modellaringiz Local models ostida. Har bir agent bitta marta, uni nechta harness orqali boshqarmang, kim unga hisob-kitob qilsa o‘sha ostida sanaladi.

Panel uchun panel belgisini chap tugma bilan bosing yoki `Super + Ctrl + X` ni bosing, standart agentingizni ishga tushirish uchun o‘ng tugma bilan bosing, va yangilash uchun o‘rta tugma bilan bosing. Uning ortidagi foydalanish yozuvlari har 15 daqiqada `omarchy agent usage update` tomonidan qayta yaratiladi, va panel hatto sinxronlangan papka orqali boshqa mashinalaringizdan foydalanishni birlashtirishi mumkin. To‘liq sozlamalar uchun `$OMARCHY_PATH/shell/plugins/agents/` ostidagi README ga qarang.

### Bir nechta obuna

Agar siz bir nechta Claude, Codex yoki Grok rejasi uchun to‘lasangiz — aytaylik shaxsiy Max va ish uchun bitta — Omarchy ularning barchasini kirgan holda saqlashi va ular orasida harakatlanishi mumkin. Obunani agentlar panelidagi + bilan qo‘shing, u sizni xuddi o‘sha yerda jarayondan o‘tkazadi, yoki `omarchy agent account add claude Work` bilan (yoki `codex`, yoki `grok`). Agar CLI yo‘q bo‘lsa, uni o‘rnatadi. Provider uchun birinchi hisob oddiy browser ingiz orqali, CLI doim qaraydigan joyda kiradi. Undan keyingi har biri private oyna orqali kiradi, shuning uchun browser ingiz allaqachon kirgan hisob xatolik bilan tanlanib qolmaydi; u yerda qo‘shayotgan hisobingiz sifatida kiring, va avval ochib bo‘lgan har qanday private oynani oldin yoping. Buni qilish uchun hech qachon CLI dan chiqmang: chiqish saqlangan kirishni bekor qiladi, va o‘sha hisobni yana qo‘shish kerak bo‘lardi.

Obuna loginlarini SSH orqali boshqa Omarchy mashinasiga nusxalash uchun `omarchy agent account copy user@laptop` ni ishga tushiring. Qabul qiluvchi o‘rnatilmagan bo‘lsa, yuboruvchi vaqtinchalik qabul qiluvchini taqdim etadi, shuning uchun eski Omarchy mashinalari yangilanishsiz hisoblarni qabul qilishi mumkin. O‘rnatilgan qabul qiluvchilar ustunlikka ega. Bu barcha Claude, Codex va Grok obunalarini nusxalaydi; ularni tanlash uchun provider nomlarini qo‘shing, masalan `omarchy agent account copy laptop claude` dagi kabi. Hisob nomlari va buyruq ID lari manbaga mos keladi, shu jumladan manzil mashinasida allaqachon mavjud bo‘lgan hisoblar ham. Agar nomlari to‘qnashsa, aloqasiz manzil hisoblari raqamli qo‘shimcha oladi, va sozlamalar, skill lar, plugin lar va suhbat tarixi har bir mashinada mahalliy qoladi.

Mavjud manzil credential lari saqlanadi. U yerda allaqachon kirilgan manba hisobining nomi uning credential larini almashtirmasdan sinxronlashtiriladi; boshqa hisoblar uning yoniga qo‘shiladi. Mos keladigan hisoblar uchun saqlangan credential larni almashtirish uchun, manzil mashinasidagi o‘sha hisobning session larini yopgandan keyin `omarchy agent account copy --replace laptop claude` dan foydalaning. Yangi manzil mashinasi shuningdek manbaning faol hisobi va almashtirish afzalliklarini oladi; o‘rnashib qolgan manzil mashinasi o‘zinikini saqlaydi.

Credential lar SSH orqali sayohat qiladi va manzil mashinasida private fayllarda saqlanadi, shuning uchun faqat ishonadigan mashinalaringizga nusxalang. Bu bir martalik nusxa, doimiy sinxronlash emas. Codex refresh token lari boshqa mashina tomonidan aylantirilishi mumkin, bu nusxalangan loginni yangilashga muhtoj holda qoldiradi; bir nechta mashinada bir vaqtning o‘zida foydalanish uchun alohida kirishlar eng ishonchli tanlov bo‘lib qoladi. [Codex's account authentication guidance](https://developers.openai.com/codex/auth/ci-cd-auth) bo‘limiga qarang.

Har bir provider uchun bitta hisob faol bo‘ladi, va har bir yangi session o‘sha sifatida boshlanadi: `cx`, `cy`, oddiy `claude`, `codex` yoki `grok`, `omarchy agent` orqali ishga tushirilgan har qanday narsa, va CLI ni `PATH` da topadigan script lar yoki editor lar. `omarchy agent account use work` bilan almashtiring (va `omarchy agent account use main` bilan orqaga), yoki panelda hisobning raqamini bosib, so‘ng `Enter` ni bosish orqali (yoki uning Use tugmasini bosish orqali). Ishlayotgan Claude session lari ham, ularning keyingi xabaridan boshlab almashtiradi: har bir Claude session `~/.claude` da ishlaydi, u doim faol hisobning kirishini saqlaydi. Eski Omarchy tomonidan hisobning o‘z papkasida boshlangan Claude session i u yopilguncha o‘sha kirishni saqlaydi, shuning uchun almashtirish o‘sha session larni nomlaydi va ular ketgach o‘z-o‘zidan tugaydi. Ishlayotgan Codex va Grok session lari boshlagan hisobida qoladi. Suhbat tarixi, sozlamalar, skill lar va plugin lar hisoblar orasida umumiy, shuning uchun xuddi shu papkadagi `claude --continue` yangi hisobda qoldirgan joyingizdan davom etadi.

Bir nechta hisob bo‘lganda, panel har bir hisobning limitlarini yonma-yon, faol biri belgilangan holda ko‘rsatadi. Standart bo‘yicha Omarchy faol hisob limitning 95% idan o‘tganda sizni xabardor qiladi, va bildirishnomani bosish eng ko‘p zaxiraga ega hisobga o‘tadi. Buning o‘rniga uning o‘z-o‘zidan almashishi uchun paneldagi hisob qatorining ustiga olib boring va Use yonida paydo bo‘ladigan Autoswitch ni bosing (yoki `m` ni bosing), yoki `omarchy agent account mode auto` ni ishga tushiring; u yoqilgan paytda Autoswitch Use ning o‘rnini oladi, va uni yana bosish xabardor qilishga qaytadi. Chegarani o‘zgartirish uchun raqam qo‘shing, masalan `omarchy agent account mode auto 90` dagi kabi. Agar har bir hisob chegaradan yuqori bo‘lsa, siz bu haqda bir marta, qaysi hisob birinchi bo‘shashi bilan birga eshitasiz. Faol hisob uning chegarasidan 15 punkt ichida bo‘lganda (standartda 80%), uning limitlari har 15 daqiqa o‘rniga har uch daqiqada tekshiriladi.

`omarchy agent account list` har bir hisobni va uning eng so‘nggi limitlarini ko‘rsatadi, `omarchy agent account remove work` bittasini unutadi, va `omarchy agent account rename primary Hey` bittasining nomini o‘zgartiradi (yoki panelda hisob nomini bosing). Bu buyruqlar standart agentingizning hisoblarida ishlaydi; boshqa provider ga yetish uchun uni avval nomlang, masalan `omarchy agent account use codex side` dagi kabi. `~/.claude` yoki `~/.codex` da allaqachon bo‘lgan loginingiz _Main_ hisobdir. Codex niki turgan joyida qoladi; Claude niki boshqa hisob faol bo‘lganda o‘z papkasida kutadi. Taxminan sakkiz soatdan ortiq ishlatilmagan hisob _Sign-in required_ ni ko‘rsatishi mumkin; o‘sha hisobga panelning o‘zida yana kirish uchun uni bosing, yoki unga o‘ting va session boshlang, bu kirishni o‘z-o‘zidan yangilaydi. `claude mcp add` bilan qo‘shadigan MCP server lari har bir Claude hisobiga yetadi, chunki ularning barchasi `~/.claude` da ishlaydi; Codex va Grok uchun, hisob qo‘shilganda sizda bo‘lgan server lar unga hamroh bo‘ladi, lekin keyingilari faqat ularni qo‘shgan hisobingizga yetadi. Claude Desktop o‘z kirishini saqlaydi, va CLI binary siga mutlaq yo‘l bilan sozlangan Codex yoki Grok vositalari almashtirishga ergashmaydi. Aniq `CLAUDE_CONFIG_DIR`, `CODEX_HOME` yoki `GROK_HOME` tanlangan hisobdan ustun turadi.

### Crash diagnostikasi

Omarchy jarayon crash larini systemd-coredump orqali kuzatadi. Standart agentni tanlaganingizdan so‘ng, core ni tashlaydigan har qanday dasturingiz "Process crashed" bildirishnomasini olib keladi — uni bosing, va crash Omarchy ning omarchy-diagnose-crash skill i bilan birga standart agentingizga topshiriladi, bu agentni core dump dan faktlarni aniqlash va crash haqida upstream ga xabar berishga arziydimi yoki yo‘qmi qaror qilish jarayonidan o‘tkazadi. Uni `coredumpctl list` dan istalgan PID ga qarshi `omarchy agent crash <pid>` bilan qo‘lda ham ishga tushirishingiz mumkin.

Kuzatish standart bo‘yicha yoqilgan. Uni _Trigger > Toggle > Crash Capture Off_ ostida o‘chiring (yoki `omarchy toggle crash-capture` bilan) va bildirishnomalar to‘xtaydi; `omarchy agent crash <pid>` hali ham qo‘lda ishlaydi.

Crash lar shuningdek bittadan dastur bo‘yicha bir vaqtda ovozini o‘chirish mumkin, bu diagnostika sizga oxirida taklif qiladigan narsa. `omarchy crash mute hyprland` faqat o‘sha dastur uchun bildirishnomalarni to‘xtatadi, `omarchy crash mute hyprland off` ularni qaytaradi, va `omarchy crash mute` o‘z-o‘zidan siz ovozsiz qilganlaringizni ro‘yxatlaydi. U binary ning yo‘lini uning nomi kabi xursandlik bilan qabul qiladi, shuning uchun `omarchy crash mute /usr/bin/hyprland` xuddi shu ishni qiladi. Ichida bo‘sh joy bo‘lgan nomni qo‘shtirnoqqa oling, masalan `omarchy crash mute 'Some App'` dagi kabi. Qolgan hamma narsa hali ham xabar beradi, va ovozsiz qilingan dastur hali ham crash bo‘ladi — bu eslatmani yashiradi, hech narsani tuzatmaydi.

### Desktop apps

_Install > AI_ menyusi shuningdek bir nechta grafik AI ilovalarini ham olib keladi: Amp Desktop, Antigravity Desktop, ChatGPT desktop ilovasi, Claude desktop ilovasi (Anthropic ning Linux beta si, Chat, Cowork va Claude Code tab lari bilan), xAI modellar bilan suhbatlashish uchun Grok Bot, Herdr Desktop, Hermes Desktop, OpenClaw, Perplexity desktop ilovasi va T3 Code. Grok Bot desktop chat ilovasidir. Kodlash agenti `grok` buyrug‘idir.

Hermes Desktop haqida bilish kerak bo‘lgani shu, chunki mashinada bitta Hermes bor, va u ilovaniki: Hermes faqat ilova orqali o‘rnatiladi, va standart agent ishlatadigan `hermes` buyrug‘i ilovaniki. Hermes ni standart agent sifatida tanlash _Install > AI_ yozuvi qiladigan xuddi shu narsani o‘rnatadi: paketni, va Hermes ning o‘z o‘rnatuvchisi tomonidan sozlangan `~/.hermes` ostidagi Hermes runtime ini, bu birinchi marta bir necha daqiqa oladi. O‘sha runtime terminal `hermes` buyrug‘i, standart agent va ilova barchasi ishlatadigan yagona Hermes dir, va u Omarchy relizini kutish o‘rniga `hermes update` bilan o‘zini o‘zi yangilaydi. Uni o‘rnatish shuningdek Hermes ga Omarchy temasini `omarchy` nomli skin sifatida topshiradi, har bir Hermes yuzasi siz temalarni almashtirganda unga ergashadi; agar uni shunday bo‘lmasligini afzal ko‘rsangiz Hermes ning Appearance sozlamalari ostida yoki `/skin` bilan boshqasini tanlang, va Omarchy o‘sha tanlovni o‘z holiga qo‘yadi. Ilovani _Remove > AI_ ostida olib tashlash avval Hermes ni, gateway ni ham qo‘shib, yopadi, o‘sha runtime ni o‘zi bilan olib ketadi, va siz boshqacha aytmasangiz chatlaringiz, xotiralaringiz va Hermes o‘zi uchun yozgan skill larni saqlaydi: u, standart bo‘yicha yo‘q deb, o‘sha ma’lumotlar va ulanish sozlamalaringiz ham ketishi kerakmi yoki yo‘qmi so‘raydi.

OpenClaw ning desktop tajribasi uning Control UI si bo‘lib, u o‘zining mahalliy gateway i tomonidan ta’minlangan web ilova sifatida ochiladi. OpenClaw `~/.openclaw` da yashaydi va o‘zini o‘zi yangilaydi: Control UI ning "Update Gateway" tugmasini ishlating yoki `openclaw update` ni ishga tushiring, va gateway yangi versiyada qayta ishga tushadi. Omarchy faqat yangi o‘rnatish qaysi relizdan boshlanishini tanlaydi. OpenClaw shuningdek standart agentingiz bo‘lishi mumkin: uni _Agent > Harness_ ostida tanlash `~/.openclaw` dagi xuddi shu nusxani sozlaydi, va agent OpenClaw ning uning gateway iga ulangan terminal UI sini ochadi. OpenClaw ni _Remove > AI_ ostida olib tashlash gateway xizmatini va ilovani o‘zi bilan olib ketadi va so‘ng `~/.openclaw` ham ketishi kerakmi yoki yo‘qmi so‘raydi, chunki u OpenClaw ning o‘zi va u yuklab oladigan plugin runtime lari bilan bir qatorda chatlaringiz va credential laringizni saqlaydi; standart uni saqlaydi, va OpenClaw ni yana o‘rnatish uni qayta oladi.

Herdr Desktop [Herdr](https://herdr.dev) desktop ilovasidir: siz oynani yopganingizda uning core ida ishlashda davom etadigan terminallar va kodlash agentlarining space lari, tab lari va pane lari. U paket o‘rniga Herdr ning o‘z o‘rnatuvchisidan keladi, shuning uchun u `~/.local/share/herdr-app` da yashaydi, sizda hali yo‘q bo‘lganda uning core ini `~/.local/bin/herdr-core` da o‘zi bilan olib keladi, va har ikkalasini ham o‘zi yangilaydi. U uni almashtirish o‘rniga Omarchy `Super + Ctrl + Return` da yetkazib beradigan `herdr` buyrug‘i yonida o‘tiradi, va o‘sha buyruqning to‘g‘ridan-to‘g‘ri tugmalarini oladi: `Alt + Return` va `Alt + Shift + Return` pane ni pastga yoki o‘ngga ajratadi, `Alt + Escape` uni yopadi, `Ctrl + Alt + Arrow` pane lar orasida harakatlanadi, `Alt + 1..9` va `Alt + Left/Right` tab ni tanlaydi, va `Alt + Up/Down` space lar orasida harakatlanadi. `Ctrl + 1..9` space ni tanlaydi va `Alt + Shift + Up/Down` agentlar bo‘ylab qadamlaydi. `Ctrl + Space` prefix tugmalari faqat terminalda qoladi, chunki ilova ketma-ketlik uchun oddiy Ctrl tugmasini ushlab tura olmaydi. Omarchy bularni `~/.config/herdr-app/keys.json` ga yozadi, va `omarchy-refresh-herdr-app` ularni qayta joyiga qo‘yadi. Uni o‘rnatish Herdr ning Omarchy temasini tanlaydi, u shundan keyin Omarchy temangizga ergashadi. Herdr yorug‘ rejim uchun bitta tema va qorong‘i uchun bitta tema saqlaydi, shuning uchun qorong‘i va yorug‘ Omarchy temasi orasida almashgandan keyin, boshqa rejim uchun Herdr ning tema tanlovchisida Omarchy ni yana bir marta tanlang.

T3 Code paket o‘rniga `~/.local/share/t3code` dagi o‘zining rasmiy AppImage relizidan ishlaydi, shuning uchun u o‘zini o‘zi yangilaydi. Uni o‘rnatish Stable yoki Nightly kanalida boshlash kerakmi yoki yo‘qmi so‘raydi; keyinroq T3 Code sozlamalarida almashtiring. Thread laringiz va sozlamalaringiz `~/.t3` da yashaydi, va T3 Code ni _Remove > AI_ ostida olib tashlash ularni o‘zi bilan olib ketadi.

### Mahalliy modellar

Kodlash agentlaringiz uchun o‘z mashinangizda ochiq modelni ishlating. Prompt laringiz va kodingiz mashinada qoladi; modelga yuborilgan hech narsa undan chiqmaydi. Quyidagidan boshlang:

```bash
omarchy models use best text
```

Yoki, yuqori paneldagi agentlar panelida, + ni va so‘ng Local AI ni tanlang, bu model bu mashinaga mos kelganda paydo bo‘ladi. Modellarni ishlatadigan Podman Omarchy bilan keladi, NVIDIA mashinasidagi NVIDIA ning container toolkit i kabi, bu ularga GPU ni beradi; agar ikkalasidan biri yo‘q bo‘lsa, birinchi sozlash uni o‘rnatadi. Keyin Omarchy bu mashina uchun tavsiya etilgan modelni tanlaydi, uni yuklab oladi va uni ishga tushiradi. Model ishlayotganda o‘nlab GB yuklab olishni va mashina xotirasining ko‘p qismi ishlatilishini kuting: Flash Next to‘liq 256K konteksti bilan taxminan 100 GiB ishlatadi. Agar boshqa modellar unga kerak bo‘lgan xotirani ushlab tursa, u to‘xtatilgan holda sozlanadi, birini to‘xtatganingizdan keyin boshlashga tayyor. Model logout da to‘xtaydi; xotira sizga boshqa narsa uchun kerak bo‘lganda uni o‘zingiz to‘xtating.

`omarchy models list` variantlarni ko‘rsatadi va ba’zilari nima uchun mos kelmasligini tushuntiradi. Boshqasini sozlash uchun `omarchy models use <recipe>` ni ishga tushiring. Bugun, 128 GB Strix Halo mashinalari uchun `qwen3.8-flash-next-gufo` va `qwen3.8-27b-gufo` mavjud; 27B taxminan 40 GiB oladi, shuning uchun u boshqa ish uchun joy qoldiradi. Intel ning Arc B390 siga ega 64 GB laptop da, `qwen3.6-35b-a3b-llamacpp` taxminan 30 GiB da ishlaydi. Yangi recipe lar va tavsiyalar `omarchy update` bilan, paket orqali keladi.

Sozlagan har bir modelingiz obunalaringiz yonida agentlar panelida o‘z qatoriga ega bo‘ladi: uni boshlash uchun play, uni to‘xtatish va xotirasini bo‘shatish uchun pause, va unda agentingizni ochish uchun terminal tugmasi. Bir nechtasi xotiraga birga sig‘ganda bir vaqtda ishlashi mumkin; agar bittasi sig‘masa, Omarchy qaysi ishlayotgan modelni to‘xtatishni aytadi. Ularning tartibini o‘zgartirish uchun qatorlarni sudrab olib boring, va modelni va uning yuklab olinishini olib tashlash uchun tanlangan qatorda Delete ni bosing.

Sozlagan har bir modelingiz shuningdek ilova ishga tushirgichida, model nomi ostida va uning ishlab chiqaruvchisining logotipi bilan, Claude, Codex yoki Grok ga kirish bittasini qo‘shgani kabi o‘z yozuviga ega bo‘ladi. U agentingizni o‘sha modelda ochadi, va agar u ishlmayotgan bo‘lsa avval modelni boshlaydi: terminal uning yuklanishini ko‘rsatadi va u tayyor bo‘lgach agentga topshiradi. Modelni olib tashlash uning yozuvini olib tashlaydi.

Har bir model ham kodlash uchun emas. Tasvir, video va musiqa modellari o‘rniga Fantasi da ochiladi, Omarchy ning bu mashinada ishlaydigan model bilan rasmlar, video va musiqa yaratish ilovasi, ularning ishga tushirgich yozuvidan va agentlar panelidagi qatoridan.

Model sozlanganidek aynan ishlashda davom etadi, shuning uchun Omarchy yangilanishi agentlaringiz ostidagi bittasini hech qachon qayta ishga tushirmaydi. Omarchy da siz sozlagan model uchun yangi runtime yoki yangi og‘irliklar bo‘lganda, uning qatori yangilash tugmasini ko‘rsatadi: uni bosing va model fon rejimida yana sozlanadi, faqat o‘zgargan narsani yuklab oladi, va yangi versiyada qayta ishga tushadi. To‘xtatilgan model to‘xtatilgan holda qoladi. `omarchy models update` terminaldan har bir model uchun xuddi shuni qiladi.

Buyruq qatoridan, `omarchy models start <recipe>` va `omarchy models stop <recipe>` xuddi shuni qiladi, `omarchy models status` har bir modelni ko‘rsatadi, va `omarchy agent --local` standart agentingizni oxirgi boshlagan modelingizda ochadi. pi, OpenCode va Qwen Code bittasini ishlatishi mumkin; boshqa har qanday standart bilan u pi da, yoki pi sizda bo‘lmasa OpenCode da ochiladi. pi shuningdek uning o‘z model tanlovchisida siz sozlagan har bir modelni, va siz ulangan mashinalardagilarni ro‘yxatlaydi, shuning uchun oddiy `pi` ham ularga yetadi. Har qanday OpenAI ga mos mijoz ham ulanishi mumkin: `status` har bir modelning manzilini ko‘rsatadi (birinchisi `http://127.0.0.1:11435/v1`), recipe nomi modeldir, va kalit `~/.config/omarchy/agent-local/key` da.

`omarchy models remove <recipe>` modelni va boshqa hech bir model ishlatmaydigan yuklab olishlarni o‘chiradi.

Uchinchi tomon runtime lari ularning nashriyotchisi bilan belgilangan. Omarchy har bir modelni tarmoqqa kirishsiz ishlatadi.

### Mahalliy LLM lar

Omarchy mahalliy LLM modellarini ishlatishning ikki yo‘lini tavsiya qiladi: LM Studio va Ollama. LM Studio ochiq og‘irlikdagi modellarni topish, ularni o‘rnatish va ularni ishlatish uchun GUI interfeysini taqdim etadi. Bu oson boshlashning ajoyib yo‘li. Ollama xuddi shunday qilish uchun CLI taklif qiladi. Lekin agar siz mahalliy modellarga yangi bo‘lsangiz, men LM Studio dan boshlagan bo‘lardim. Ikkalasidan birini Omarchy Menu dagi _Install > AI_ ostida o‘rnatishingiz mumkin.

### Omarchy skill lari

Agent skill lari AI ga muayyan vositalardan muayyan tarzda foydalanishga yordam beradi, va Omarchy ularning yettitasini yetkazib beradi. omarchy skill i tizimingizni sozlashni qamrab oladi, masalan Hyprland config ingizni sozlash yoki panelni to‘g‘rilash. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app va omarchy-make-game yangi narsa yaratishni qamrab oladi, omarchy-contribute xato haqida xabar berish yoki tuzatishni upstream ga yuborishni qamrab oladi, va omarchy-diagnose-crash crash ning core dump i bo‘ylab ishlaydi. Ular Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` va har bir `~/.hermes/profiles/*/skills`) va generic `~/.agents/skills` joylashuvi uchun skill kataloglariga symlink qilingan, shuning uchun ko‘pchilik harness lar ularni avtomatik oladi. Xuddi shu nomdagi o‘zingizning skill papkangiz ustunlikka ega.

Lekin siz bu skill larga eksperimental sifatida qarashingiz kerak. Turli modellar uni turli samaradorlik bilan ishlatadi. Avval plan rejimida ishga tushirish eng yaxshisi, shuning uchun agent nimani o‘zgartirmoqchiligi haqida tasavvurga ega bo‘lasiz. Va keyin o‘zgarishlarni orqaga qaytarishga yoki hatto, agar agent hamma narsani tartibsiz qilib yuborsa, `omarchy reinstall configs` ni chaqirishga tayyor bo‘ling.
