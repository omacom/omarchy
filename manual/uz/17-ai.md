### Agentlarni o'rnatish va yangilash

Hermes va OpenClaw bundan mustasno, bu agentlar mise ning dangasa o'rnatishidan foydalanadi: birinchi ishga tushirish CLI ni o'rnatadi, keyingi ishga tushirishlar undan qayta foydalanadi. mise shuningdek, o'rnatilgan agentning yangi versiyasi bor-yo'qligini ko'pi bilan har to'rt soatda bir marta, ishga tushishidan oldin yoki fon rejimida shell so'rovida tekshiradi. Agar yangilash muvaffaqiyatsiz bo'lsa yoki siz oflayn bo'lsangiz, o'rnatilgan versiya ishlaydi. `omarchy update` o'rnatilgan agentlarni Omarchy ning qolgan qismi bilan birga yangilaydi, `mup` esa faqat mise tomonidan boshqariladigan vositalarni yangilaydi.

Agentning o'z yangilovchisi, masalan `claude update`, `codex update` yoki ilovadagi yangilash tugmasi, mise tomonidan boshqariladigan o'rnatishni yangilamaydi. `codex update` muvaffaqiyatsiz tugaydi, `claude update` esa muvaffaqiyat haqida xabar berib, mise kuzatmaydigan alohida nusxani o'rnatishi mumkin. Agar agentning o'z o'rnatuvchisi va yangilovchisidan foydalanishni afzal ko'rsangiz, uni `disable_tools` ga qo'shing; qarang: [Oldindan o'rnatilgan CLI vositalar](18-development-tools.md#preinstalled-cli-tools).

Sozlangan barcha dangasa vositalarni kerak bo'lishidan oldin o'rnatish uchun `mise install --include-lazy` ni bajaring. Bunga Omarchy ning boshqa standart CLI vositalari ham, agentlar ham kiradi. Bitta vositani o'rnatish yoki o'zingizning o'rnatishingizdan foydalanish uchun qarang: [Oldindan o'rnatilgan CLI vositalar](18-development-tools.md#preinstalled-cli-tools).

`grok` mise ning birinchi tomon `grok` paketi orqali, xuddi `claude` va `codex` kabi o'rnatiladi. `grok` ni bajaring yoki uni _Agent > Harness_ ostidan tanlang. x.ai dagi `curl | bash` o'rnatuvchisini o'tkazib yuboring. O'sha yo'l ikkinchi nusxani `~/.grok/bin` ga qo'yadi, uni `PATH` boshiga qo'shadi va Omarchy ning wrapper ini ustiga yozadi.

`dsh` o'zining brauzer UI sini `127.0.0.1:3080` da ochadi, ishga tushirish katalogi uning standart ish maydoni bo'ladi. Uning brauzer UI si boshlang'ich so'rovni qabul qilmaydi, shuning uchun `omarchy agent prompt` uni so'rovni joylashtirish uchun clipboard ingizga qo'yib ochadi. Omarchy uni DeepSeek ning tasdiq talab qilmaydigan ruxsatlar oldindan sozlamasi bilan ishga tushiradi. DeepSeek Harness uning rasmiy model API sidan foydalanganda sessiya jurnallarini DeepSeek ga yuklaydi; buni uning brauzer UI sidagi _Settings > General > Upload Session Log_ ostida o'chiring. Unga yuboradigan fikr-mulohazangiz ham sessiya bilan birga yuklanadi, agar uni `DSH_TELEMETRY_MODE=DISABLED` bilan ishga tushirmasangiz.

### Standart agent

Standart agentingizni `omarchy default agent <name>` bilan yoki Omarchy Menu (`Super + Space`) dagi _Agent > Harness_ ostida tanlang. Agar agent hali o'rnatilmagan bo'lsa, uni tanlash avval o'rnatadi va u ilova ishga tushirgichida, Agent yonida, o'z ishga tushirgichiga ham ega bo'ladi. Yangi Omarchy sizni bir martalik bildirishnoma bilan bu tanlovni qilishga taklif qiladi.

Claude ni tanlash uning Chromium, Chrome, Brave, Brave Origin va Edge uchun brauzer kengaytmasini o'rnatishga ham harakat qiladi. Kengaytmani o'rnatish barcha foydalanuvchilarga taalluqli va tizim parolingizni so'rashi mumkin; bekor qilish yoki kengaytmani o'rnatish muvaffaqiyatsiz bo'lishi baribir Claude ni tanlaydi va ishga tushiradi. Brauzeringizni qayta ishga tushiring, so'ralsa kengaytmani yoqing va uni ulashni yakunlash uchun Claude ga kiring. Ulanishni tekshirish uchun Claude da `/chrome` ni bajaring. Firefox va Zen bu kengaytmani qo'llab-quvvatlamaydi. Agar bu o'rnatish qo'shilishidan oldin Claude allaqachon standartingiz bo'lgan bo'lsa, kengaytmani o'rnatish uchun uni yana tanlang.

Tanlab bo'lganingizdan so'ng, `Super + Shift + Ctrl + A` standart agentni alohida terminal oynasida ishga tushiradi (yoki hali tanlamagan bo'lsangiz, tanlovchini ochadi). Uni to'g'ridan-to'g'ri vazifaga ham ishga tushirishingiz mumkin: `omarchy agent prompt "Review this project"`. Freebuff va DeepSeek Harness boshlang'ich so'rovni qabul qilmaydi, shuning uchun ular buning o'rniga so'rovni joylashtirish uchun clipboard ingizga qo'yib ochiladi. Shu tarzda ishga tushirilgan agentlar nazoratsiz, o'zlarining to'xtab-so'ramaydigan rejimlarida ishlaydi, shuning uchun ular chindan ham biror narsa qilishiga tayyor bo'ling! MiniMax Code da interaktiv sessiyalari uchun bunday rejim yo'q, shuning uchun u odatdagidek ruxsat so'raydi. Va agentlar uy katalogingiz uchun ishonchni eslab qolishdan bosh tortgani sababli, `$HOME` dan ishga tushirishlar buning o'rniga `~/Work` da boshlanadi.

Terminal yorliqlari ham bor: `a` standart agentni joriy terminalda ichki rejimda ishlatadi, `c`, `cx` va `cy` esa OpenCode, Claude Code va Codex ni to'g'ridan-to'g'ri boshlaydi (yana ularning avtomatik tasdiqlaydigan rejimlarida). Tema o'zgarishlari agentlarga ham sinxronlanadi: Claude Code, Pi, OpenCode va Hermes (Omarchy uni o'rnatib bo'lgach) Omarchy temasini almashtirganda hammasi ergashadi.

### Agent ko'rsatmalaringiz

Har bir agent uchun shaxsiy qoidalar `~/.agents/AGENTS.md` ga, umumiy skill lar yoniga, `~/.agents/skills` ga yoziladi. Uni _Agent > Instructions_ ostida oching, u shuningdek uni o'z global faylini saqlaydigan har bir harness ga bog'laydi: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, Copilot ning `~/.copilot/copilot-instructions.md` va hokazo. Crush va Amp `~/.config/AGENTS.md` havolasini o'qiydi, omp, Kimi va DeepSeek Harness esa `~/.agents/AGENTS.md` ni to'g'ridan-to'g'ri o'qiydi. Standart agentni tanlash ham uni bog'laydi. Sizda allaqachon bo'lgan ko'rsatmalar fayli, hali umumiysi bo'lmasa, umumiyga aylanadi; aks holda u havola yonida `.bak` sifatida saqlanadi. Boshqa agentni o'rnatgandan keyin qayta bog'lash uchun `omarchy agent instructions` ni bajaring.

### Agentlar paneli

Yuqori panelda agentlar belgisi bor. Agentni hali sozlamagan bo'lsangiz, uning paneli sizni Claude, Codex yoki Grok ga kirish bo'yicha olib boradi va birinchisi standart agentingizga aylanadi. Shundan keyin panel har bir obunani bitta sahifaga joylaydi: har bir agent va hisob uning rejasi bilan, uning 5 soatlik sessiya va haftalik limitlarining har biri uchun o'lchov hamda u tiklanishigacha qolgan vaqt bilan (aniq foiz uchun ustiga olib boring) yoki qolgan oldindan to'langan balans bilan, ularning barchasi bo'ylab ishlatgan narsalaringizni aylantirib ko'rsatadigan satr ostida, masalan bu haftadagi tokenlar va eng ko'p ishlatgan modelingiz. _Make something cool_ ostida u yangi tema, plugin, ilova yoki o'yin uchun standart agentingizga vazifani topshiradigan boshlang'ich so'rovlarni taklif qiladi. Ilovalar Omarchy ning o'z Hype, Monologue va Omacut lari kabi, C++ va Qt Quick da, omarchy-make-app agent skill iga amal qilib quriladi va ularga kerak bo'lgan compiler hamda Qt qismlari o'rnatilgan holda keladi. O'yinlar `~/Games/vibes` dagi bitta three.js sahifasi bo'lib, omarchy-make-game agent skill iga amal qiladi va barchasi joriy temadagi bitta Game Vibes ishga tushirgichidan ochiladi; ular three.js ni internetdan yuklaydi, shuning uchun boshlash uchun ulanish kerak. Claude Code, Codex, Grok, Kimi, Cursor va uning Grok Bot imtiyozi, GitHub Copilot, Muse, Antigravity va Devin o'z limitlari bilan tayyor holda qamrab olingan, Kimchi o'z rejasi, oldindan to'langan kreditlari va xarajat budget lari bilan, Hermes, Mistral Vibe va Qwen Code esa ulardan foydalanganingizdan keyin sessiyalari va tokenlarini ko'rsatadi. pi, omp yoki opencode orqali ishlatadigan provider rejalari va kalitlari ham chiqadi: OpenCode Zen va Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan va Synthetic o'z limitlari bilan; OpenRouter va DeepSeek oldindan to'langan balanslari bilan; Fireworks oxirgi 30 kundagi xarajati bilan. O'z uskunangizda ishlatadigan modellardan tokenlar ham jamilarga qo'shiladi; modellarning o'z paneli bor, u [Mahalliy modellar](#local-models) ostida tasvirlangan. Har bir agent, uni nechta harness orqali boshqarmang, hisobni kim to'lasa o'shaning ostida bir marta sanaladi.

Panel uchun panel belgisini chap tugma bilan bosing yoki `Super + Ctrl + X` ni bosing, standart agentingizni ishga tushirish uchun o'ng tugma bilan bosing va yangilash uchun o'rta tugma bilan bosing. Uning ortidagi foydalanish yozuvlari har 15 daqiqada `omarchy agent usage update` tomonidan qayta yaratiladi va panel hatto sinxronlangan papka orqali boshqa mashinalaringizdan foydalanishni birlashtira oladi. To'liq sozlamalar uchun `$OMARCHY_PATH/shell/plugins/agents/` ostidagi README ga qarang.

### Bir nechta obuna

Agar birdan ortiq Claude, Codex yoki Grok rejasiga to'lasangiz — masalan shaxsiy Max va ish uchun bitta — Omarchy ularning barchasini kirgan holda saqlab, ular orasida harakatlana oladi. Obunani agentlar panelidagi + bilan qo'shing, u sizni o'sha yerning o'zida olib boradi, yoki `omarchy agent account add claude Work` (yoki `codex`, yoki `grok`) bilan qo'shing. Agar CLI yo'q bo'lsa, uni o'rnatadi. Provider uchun birinchi hisob oddiy brauzeringiz orqali, CLI doim qaraydigan joyda kiradi. Undan keyingilarining har biri maxfiy oyna orqali kiradi, shuning uchun brauzeringiz allaqachon kirgan hisob xatolik bilan tanlanib qolmaydi; u yerda qo'shayotgan hisobingiz sifatida kiring va avval ochib qo'ygan har qanday maxfiy oynani yoping. Buni qilish uchun hech qachon CLI dan chiqmang: chiqish saqlangan kirishni bekor qiladi va o'sha hisobni yana qo'shishga to'g'ri keladi.

Obuna kirishlarini SSH orqali boshqa Omarchy mashinasiga nusxalash uchun `omarchy agent account copy user@laptop` ni bajaring. Qabul qiluvchisi o'rnatilmagan bo'lsa, yuboruvchi vaqtinchalik qabul qiluvchini beradi, shuning uchun eski Omarchy mashinalari yangilanishsiz hisoblarni qabul qila oladi. O'rnatilgan qabul qiluvchilar ustunlikka ega. Bu barcha Claude, Codex va Grok obunalarini nusxalaydi; ularni tanlash uchun provider nomlarini qo'shing, masalan `omarchy agent account copy laptop claude`. Hisob nomlari va buyruq ID lari manba bilan bir xil bo'ladi, jumladan qabul qiluvchida allaqachon bor hisoblar ham. Nomlari ziddiyatga tushsa, aloqasi bo'lmagan qabul qiluvchi hisoblar raqamli qo'shimcha oladi va sozlamalar, skill lar, plugin lar va suhbat tarixi har bir mashinada mahalliy qoladi.

Qabul qiluvchidagi mavjud credential lar saqlanadi. U yerda allaqachon kirgan manba hisobining nomi credential larini almashtirmasdan sinxronlanadi; boshqa hisoblar uning yoniga qo'shiladi. Mos hisoblar uchun saqlangan credential larni almashtirish uchun, qabul qiluvchida o'sha hisobning sessiyalaridan chiqqandan keyin `omarchy agent account copy --replace laptop claude` dan foydalaning. Yangi qabul qiluvchi manbaning faol hisobi va almashtirish afzalliklarini ham oladi; o'rnashib bo'lgan qabul qiluvchi o'zinikini saqlaydi.

Credential lar SSH orqali o'tadi va qabul qiluvchida shaxsiy fayllarda saqlanadi, shuning uchun faqat o'zingiz ishonadigan mashinalarga nusxalang. Bu bir martalik nusxa, doimiy sinxronlash emas. Codex yangilash tokenlari boshqa mashina tomonidan aylantirilishi mumkin, bu nusxalangan kirishni yangilashga muhtoj qilib qo'yadi; bir nechta mashinada bir vaqtda foydalanish uchun alohida kirishlar eng ishonchli tanlov bo'lib qoladi. Qarang: [Codex ning hisob autentifikatsiyasi bo'yicha qo'llanmasi](https://developers.openai.com/codex/auth/ci-cd-auth).

Har bir provider uchun bitta hisob faol va har bir yangi sessiya u sifatida boshlanadi: `cx`, `cy`, oddiy `claude`, `codex` yoki `grok`, `omarchy agent` orqali ishga tushirilgan har qanday narsa hamda CLI ni `PATH` da topadigan script lar yoki editor lar. `omarchy agent account use work` bilan almashtiring (va `omarchy agent account use main` bilan orqaga), yoki panelda hisobning raqamini keyin `Enter` ni bosib (yoki uning Use tugmasini bosib). Ishlayotgan Claude sessiyalari ham keyingi xabardan boshlab almashadi: har bir Claude sessiyasi `~/.claude` da ishlaydi, u doim faol hisobning kirishini saqlaydi. Eski Omarchy tomonidan hisobning o'z papkasida boshlangan Claude sessiyasi u chiqquncha o'sha kirishni saqlaydi, shuning uchun almashtirish o'sha sessiyalarni nomlaydi va ular ketgach o'zi tugaydi. Ishlayotgan Codex va Grok sessiyalari boshlagan hisobida qoladi. Suhbat tarixi, sozlamalar, skill lar va plugin lar hisoblar orasida umumiydir, shuning uchun bir xil papkada `claude --continue` yangi hisobda qolgan joyingizdan davom etadi.

Birdan ortiq hisob bo'lsa, panel har bir hisobning limitlarini yonma-yon ko'rsatadi, faoli belgilangan holda. Standart holda Omarchy faol hisob limitning 95% idan o'tganda sizni xabardor qiladi va bildirishnomani bosish eng ko'p zaxirasi bor hisobga o'tkazadi. Panelda hisob satrining ustiga olib boring va Use yonida chiqadigan Autoswitch ni bosing (yoki `m` ni bosing), yoki uning o'rniga o'zi almashishi uchun `omarchy agent account mode auto` ni bajaring; u yoqilgan vaqtda Autoswitch Use o'rnini egallaydi va uni yana bosish xabardor qilishga qaytaradi. Chegarani o'zgartirish uchun raqam qo'shing, masalan `omarchy agent account mode auto 90`. Agar har bir hisob chegaradan yuqori bo'lsa, bu haqida bir marta eshitasiz, qaysi hisob birinchi bo'shashi bilan birga. Faol hisob o'z chegarasidan 15 punkt ichida bo'lsa (standartda 80%), uning limitlari har 15 daqiqa o'rniga har uch daqiqada tekshiriladi.

`omarchy agent account list` har bir hisob va uning eng oxirgi limitlarini ko'rsatadi, `omarchy agent account remove work` bittasini unutadi va `omarchy agent account rename primary Hey` bittasining nomini o'zgartiradi (yoki panelda hisob nomini bosing). Bu buyruqlar standart agentingizning hisoblarida ishlaydi; boshqa provider ga yetish uchun uni avval nomlang, masalan `omarchy agent account use codex side`. `~/.claude` yoki `~/.codex` da allaqachon bo'lgan kirish _Main_ hisobdir. Codex niki turgan joyida qoladi; Claude niki boshqa hisob faol bo'lganda o'zining papkasida kutadi. Taxminan sakkiz soatdan ko'proq ishlatilmagan hisob _Sign-in required_ ni ko'rsatishi mumkin; panelning o'zida o'sha hisobga yana kirish uchun uni bosing yoki unga o'tib sessiya boshlang, bu kirishni o'zi yangilaydi. `claude mcp add` bilan qo'shadigan MCP serverlar har bir Claude hisobiga yetadi, chunki ularning hammasi `~/.claude` da ishlaydi; Codex va Grok uchun hisob qo'shilganda sizda bo'lgan serverlar unga birga keladi, lekin keyingilari faqat ularni qo'shgan hisobingizga yetadi. Claude Desktop o'z kirishini saqlaydi va CLI binary siga mutlaq yo'l bilan sozlangan Codex yoki Grok vositalari almashtirishga ergashmaydi. Aniq ko'rsatilgan `CLAUDE_CONFIG_DIR`, `CODEX_HOME` yoki `GROK_HOME` tanlangan hisobdan ustun keladi.

### Nosozlik diagnostikasi

Omarchy jarayon nosozliklari uchun systemd-coredump ni kuzatadi. Standart agentni tanlab bo'lganingizdan so'ng, core tashlaydigan har qanday dasturingiz "Process crashed" bildirishnomasini keltiradi — uni bosing va nosozlik Omarchy ning omarchy-diagnose-crash skill i bilan birga standart agentingizga topshiriladi, u agentni core dump dan faktlarni aniqlash va nosozlikni yuqori tomonga xabar qilishga arziydimi yoki yo'qligini hal qilish bo'yicha olib boradi. Uni `omarchy agent crash <pid>` bilan `coredumpctl list` dagi har qanday PID ga qo'lda ham ishlatishingiz mumkin.

Kuzatish standart holda yoqilgan. Uni _Trigger > Toggle > Crash Capture Off_ ostida (yoki `omarchy toggle crash-capture` bilan) o'chiring va bildirishnomalar to'xtaydi; `omarchy agent crash <pid>` hali ham qo'lda ishlaydi.

Nosozliklarni bir vaqtda bitta dasturdan ovozini o'chirish ham mumkin, diagnostika oxirida sizga shuni taklif qiladi. `omarchy crash mute hyprland` faqat o'sha dastur uchun bildirishnomalarni to'xtatadi, `omarchy crash mute hyprland off` ularni qaytaradi va `omarchy crash mute` o'zi nimalarning ovozini o'chirganingizni ro'yxat qiladi. U binary ning yo'lini uning nomi kabi mamnuniyat bilan qabul qiladi, shuning uchun `omarchy crash mute /usr/bin/hyprland` ham xuddi shunday qiladi. Ichida bo'sh joy bor nomni qo'shtirnoqqa oling, masalan `omarchy crash mute 'Some App'`. Qolgan hamma narsa hali ham xabardor qiladi va ovozi o'chirilgan dastur hali ham nosozlanadi — bu eslatmani yashiradi, hech narsani tuzatmaydi.

### Ish stoli ilovalari

_Install > AI_ menyusi bir nechta grafik AI ilovalarini ham olib yuradi: Amp Desktop, Antigravity Desktop, ChatGPT ish stoli ilovasi, Claude ish stoli ilovasi (Anthropic ning Linux beta si, Chat, Cowork va Claude Code tab lari bilan), xAI modellari bilan suhbatlashish uchun Grok Bot, Herdr Desktop, Hermes Desktop, OpenClaw, Perplexity ish stoli ilovasi va T3 Code. Grok Bot ish stoli suhbat ilovasidir. Kodlash agenti `grok` buyrug'idir.

Hermes Desktop bilish kerak bo'lganidir, chunki mashinada bitta Hermes bor va u ilovaniki: Hermes faqat ilova orqali o'rnatiladi va standart agent ishlatadigan `hermes` buyrug'i ilovanikidir. Hermes ni standart agent sifatida tanlash _Install > AI_ yozuvi qiladigan xuddi o'sha narsani o'rnatadi: paketni va Hermes ning o'z o'rnatuvchisi tomonidan sozlangan, birinchi marta bir necha daqiqa oladigan, `~/.hermes` ostidagi Hermes runtime ini. O'sha runtime terminal `hermes` buyrug'i, standart agent va ilova barchasi ishlatadigan bitta Hermes dir va u Omarchy relizini kutmasdan `hermes update` bilan o'zini yangilaydi. Uni o'rnatish Hermes ga Omarchy temasini `omarchy` nomli skin sifatida ham beradi, har bir Hermes yuzasi siz temalarni almashtirganda unga ergashadi; agar xohlamasangiz, Hermes ning Appearance sozlamalari ostida yoki `/skin` bilan boshqasini tanlang va Omarchy o'sha tanlovni yolg'iz qoldiradi. _Remove > AI_ ostida ilovani olib tashlash avval Hermes ni, shlyuzni ham qo'shib, yopadi, o'sha runtime ni u bilan olib ketadi va siz boshqacha aytmasangiz suhbatlaringiz, xotiralaringiz hamda Hermes o'zi uchun yozgan skill larni saqlaydi: u o'sha ma'lumot va ulanish sozlamalaringiz ham ketishi kerakmi deb so'raydi, standart javob yo'q.

OpenClaw ning ish stoli tajribasi uning Control UI si bo'lib, u o'zining mahalliy shlyuzi tomonidan quvvatlanadigan web ilova sifatida ochiladi. OpenClaw `~/.openclaw` da yashaydi va o'zini yangilaydi: Control UI ning "Update Gateway" tugmasidan foydalaning yoki `openclaw update` ni bajaring va shlyuz yangi versiyada qayta ishga tushadi. Omarchy faqat yangi o'rnatish qaysi relizdan boshlanishini tanlaydi. OpenClaw standart agentingiz ham bo'lishi mumkin: uni _Agent > Harness_ ostida tanlash `~/.openclaw` dagi xuddi o'sha nusxani sozlaydi va agent OpenClaw ning shlyuziga biriktirilgan terminal UI sini ochadi. _Remove > AI_ ostida OpenClaw ni olib tashlash shlyuz xizmati va ilovani u bilan olib ketadi, keyin `~/.openclaw` ham ketishi kerakmi deb so'raydi, chunki u suhbatlaringiz va credential laringizni OpenClaw ning o'zi hamda u yuklaydigan plugin runtime lari bilan birga saqlaydi; standart uni saqlaydi va OpenClaw ni yana o'rnatish uni qayta oladi.

Herdr Desktop bu [Herdr](https://herdr.dev) ish stoli ilovasi: oynani yopganda uning yadrosida ishlashda davom etadigan terminal va kodlash agentlarining spaces, tabs va panes lari. U paketdan emas, Herdr ning o'z o'rnatuvchisidan keladi, shuning uchun u `~/.local/share/herdr-app` da yashaydi, hali sizda bo'lmasa yadrosini `~/.local/bin/herdr-core` da birga olib keladi va ikkalasini ham o'zi yangilaydi. U Omarchy `Super + Ctrl + Return` da yetkazadigan `herdr` buyrug'ining yonida turadi, uni almashtirmaydi va o'sha buyruqning to'g'ridan-to'g'ri tugmalarini oladi: `Alt + Return` va `Alt + Shift + Return` panelni pastga yoki o'ngga bo'ladi, `Alt + Escape` uni yopadi, `Ctrl + Alt + Arrow` panellar orasida harakatlanadi, `Alt + 1..9` va `Alt + Left/Right` tab ni tanlaydi va `Alt + Up/Down` spaces orasida harakatlanadi. `Ctrl + 1..9` space ni tanlaydi va `Alt + Shift + Up/Down` agentlar bo'ylab qadamlaydi. `Ctrl + Space` prefix tugmalari faqat terminalda qoladi, chunki ilova ketma-ketlik uchun oddiy Ctrl tugmasini ushlab turolmaydi. Omarchy bularni `~/.config/herdr-app/keys.json` ga yozadi va `omarchy-refresh-herdr-app` ularni qaytaradi. Uni o'rnatish Herdr ning Omarchy temasini tanlaydi, u shundan keyin Omarchy temangizga ergashadi. Herdr yorug' rejim uchun bitta tema va qorong'i rejim uchun bitta tema saqlaydi, shuning uchun qorong'i va yorug' Omarchy temasi orasida almashtirgandan keyin, boshqa rejim uchun Herdr ning tema tanlovchisida Omarchy ni yana bir marta tanlang.

T3 Code paketdan emas, `~/.local/share/t3code` dagi rasmiy AppImage relizidan ishlaydi, shuning uchun u o'zini yangilaydi. Uni o'rnatish Stable yoki Nightly kanalida boshlashni so'raydi; keyin T3 Code sozlamalarida almashtiring. Mavzularingiz va sozlamalaringiz `~/.t3` da yashaydi va _Remove > AI_ ostida T3 Code ni olib tashlash ularni u bilan olib ketadi.

### Mahalliy modellar

Kodlash agentlaringiz uchun ochiq modelni o'z mashinangizda ishlating. So'rovlaringiz va kodingiz mashinada qoladi; modelga yuborilgan hech narsa undan chiqmaydi. Bundan boshlang:

```bash
omarchy models use best text
```

Bu bu mashina uchun eng yaxshi matn modelini, agentlaringiz ishlatadigan turini sozlaydi. Tasvir, video va musiqa modellarining har birining o'z eng yaxshisi bor: `omarchy models use best image`, `video` yoki `music`. Har bir turning bu mashina uchun tanlovini ko'rish uchun `omarchy models use best` ni bajaring.

Yoki mahalliy modellar panelini yuqori paneldagi, agentlar belgisi yonidagi uchqunlar belgisidan yoki Super + Ctrl + Alt + X bilan oching va + ni tanlang. Belgi model bu mashinaga sig'ganda chiqadi. Modellarni ishlatadigan Podman Omarchy bilan keladi, NVIDIA mashinasida ularga GPU ni beradigan NVIDIA ning container toolkit i ham shunday; agar birortasi yo'q bo'lsa, birinchi sozlash uni o'rnatadi. Keyin Omarchy bu mashina uchun tavsiya qilingan modelni tanlaydi, uni yuklaydi va ishga tushiradi. Model ishlayotganda o'nlab GB yuklanish va mashina xotirasining katta qismi ishlatilishini kuting: Flash Next to'liq 256K konteksti bilan taxminan 100 GiB ishlatadi. Agar boshqa modellar unga kerak xotirani egallagan bo'lsa, u to'xtatilgan holda sozlanadi, birini to'xtatishingiz bilan boshlashga tayyor. Model chiqishda to'xtaydi; xotira boshqa narsaga kerak bo'lganda uni o'zingiz to'xtating.

`omarchy models list` variantlarni ko'rsatadi va ba'zilari nega sig'masligini tushuntiradi. Boshqasini sozlash uchun `omarchy models use <recipe>` ni bajaring. Bugun `qwen3.8-flash-next-gufo` va `qwen3.8-27b-gufo` 128 GB Strix Halo mashinalari uchun mavjud; 27B taxminan 40 GiB oladi, shuning uchun u boshqa ish uchun joy qoldiradi. Intel ning Arc B390 siga ega 64 GB laptopda `qwen3.6-35b-a3b-llamacpp` taxminan 30 GiB da ishlaydi. Yangi recipe lar va tavsiyalar `omarchy update` bilan, paket orqali keladi.

Sozlagan har bir modelingiz mahalliy modellar panelida o'z satriga ega bo'ladi: boshlash uchun play, to'xtatish va xotirasini bo'shatish uchun pause va unda agentingizni ochish uchun terminal tugmasi. Yuqori bo'ylab satr mashina xotirasi Omarchy ning o'zi (tizim va ilovalaringiz), har bir ishlayotgan model va bo'sh joy orasida qanday bo'linganini ko'rsatadi. To'xtatilgan modelga ko'rsating va satr u sig'ish-sig'masligini yoki qancha yetishmasligini ko'rsatadi. Bir nechtalari xotirada birga sig'ganda bir vaqtda ishlashi mumkin; agar biri sig'masa, Omarchy qaysi ishlayotgan modelni to'xtatishni aytadi. Ularni qayta tartiblash uchun satrlarni ularning logotipi bo'yicha torting va model hamda uning yuklanishini olib tashlash uchun tanlangan satrda Delete ni bosing.

Sozlagan har bir kodlash modeli ilova ishga tushirgichida ham, model nomi ostida va uning yaratuvchisi logotipi bilan, Claude, Codex yoki Grok ga kirish bittasini qo'shgani kabi o'z yozuviga ega bo'ladi. U agentingizni o'sha modelda ochadi va agar model ishlamayotgan bo'lsa, avval uni boshlaydi: terminal uning yuklanishini ko'rsatadi va u tayyor bo'lgach agentga topshiradi. Modelni olib tashlash uning yozuvini olib tashlaydi.

Har bir model ham kodlash uchun emas. Tasvir, video va musiqa modellari buning o'rniga Fantasi da ochiladi, Omarchy ning bu mashinada ishlaydigan model bilan rasmlar, video va musiqa yaratish ilovasi, u yerda yoki mahalliy modellar panelidagi ularning satridan tanlanadi.

Model xuddi sozlangani kabi ishlashda davom etadi, shuning uchun Omarchy yangilanishi agentlaringiz ostida hech qachon bittasini qayta ishga tushirmaydi. Omarchy da siz sozlagan model uchun yangiroq runtime yoki yangiroq og'irliklar bo'lsa, uning satri yangilash tugmasini ko'rsatadi: uni bosing va model fonda yana sozlanadi, faqat o'zgarganni yuklaydi va yangi versiyada qayta ishga tushadi. To'xtatilgan model to'xtagan holda qoladi. `omarchy models update` terminaldan har bir model uchun xuddi shunday qiladi.

Buyruq satridan `omarchy models start <recipe>` va `omarchy models stop <recipe>` xuddi shunday qiladi, `omarchy models status` har bir modelni ko'rsatadi va `omarchy agent --local` standart agentingizni oxirgi boshlagan modelingizda ochadi. pi, OpenCode va Qwen Code bittasidan foydalanishi mumkin; boshqa har qanday standart bilan u pi da ochiladi yoki pi sizda bo'lmasa OpenCode da. pi shuningdek, sozlagan har bir modelingizni va ulangan mashinalaringizdagilarini o'z model tanlovchisida ro'yxat qiladi, shuning uchun oddiy `pi` ham ularga yetadi. Har qanday OpenAI ga mos client ham ulanishi mumkin: `status` har bir modelning manzilini ko'rsatadi (birinchisi `http://127.0.0.1:11435/v1`), recipe nomi modeldir va kalit `~/.config/omarchy/agent-local/key` da.

`omarchy models remove <recipe>` modelni va boshqa hech bir model ishlatmaydigan yuklanishlarni o'chiradi.

Uchinchi tomon runtime lari ularning nashriyotchisi bilan belgilanadi. Omarchy har bir modelni tarmoqqa kirishsiz ishlatadi.

### Mahalliy LLM lar

Omarchy mahalliy LLM modellarini ishlatishning ikki usulini tavsiya qiladi: LM Studio va Ollama. LM Studio ochiq og'irlikdagi modellarni topish, ularni o'rnatish va ishlatish uchun GUI interfeysini beradi. Bu oson boshlashning ajoyib usuli. Ollama shunga o'xshash qilish uchun CLI taklif qiladi. Lekin mahalliy modellarda yangi bo'lsangiz, men LM Studio dan boshlagan bo'lardim. Ikkalasidan birini Omarchy Menu dagi _Install > AI_ ostida o'rnatishingiz mumkin.

### Omarchy skill lari

Agent skill lari AI ga muayyan vositalardan muayyan tarzda foydalanishga yordam beradi va Omarchy ularning yettitasini yetkazadi. omarchy skill i tizimni moslashni qamrab oladi, masalan Hyprland config ingizni sozlash yoki panelni moslash. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app va omarchy-make-game yangi narsa yaratishni qamrab oladi, omarchy-contribute xato haqida xabar berish yoki tuzatishni yuqori tomonga yuborishni qamrab oladi va omarchy-diagnose-crash nosozlikning core dump i bo'ylab ishlaydi. Ular Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` va har bir `~/.hermes/profiles/*/skills`) va umumiy `~/.agents/skills` joyi uchun skill kataloglariga symlink qilingan, shuning uchun ko'pchilik harness lar ularni avtomatik oladi. Xuddi shu nomdagi o'zingizning skill papkangiz ustunlikka ega.

Lekin bu skill larga eksperimental deb qarang. Turli modellar undan turli samara bilan foydalanadi. Avval plan rejimida ishlatish eng yaxshisi, shunda agent nimani o'zgartirmoqchiligi haqida tasavvurga ega bo'lasiz. Va keyin o'zgarishlarni orqaga qaytarishga yoki hatto, agent hamma narsani tartibsiz qilib tashlasa, `omarchy reinstall configs` ni chaqirishga tayyor bo'ling.
