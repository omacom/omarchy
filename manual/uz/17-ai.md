### Agentlarni o'rnatish va yangilash

Hermes bundan mustasno, bu agentlar mise ning dangasa o'rnatishidan foydalanadi: birinchi ishga tushirish CLI ni o'rnatadi, keyingi ishga tushirishlar esa undan qayta foydalanadi. mise shuningdek o'rnatilgan agent uchun yangi reliz borligini ko'pi bilan har to'rt soatda bir marta, u ishga tushishidan sal oldin yoki shell so'rovida fonda tekshiradi. Agar o'sha yangilanish muvaffaqiyatsiz bo'lsa yoki siz oflayn bo'lsangiz, o'rnatilgan versiya ishlaydi. `omarchy update` o'rnatilgan agentlarni Omarchy ning qolgan qismi bilan birga yangilaydi, `mup` esa faqat mise boshqaradigan vositalarni yangilaydi.

Agentning o'z yangilagichi, masalan `claude update`, `codex update` yoki ilovadagi yangilash tugmasi, mise boshqaradigan o'rnatmani yangilamaydi. `codex update` muvaffaqiyatsiz tugaydi, `claude update` esa mise kuzatmaydigan alohida nusxani o'rnatib, muvaffaqiyat haqida xabar berishi mumkin. Agar agentning o'z o'rnatuvchisi va yangilagichidan foydalanishni afzal ko'rsangiz, uni `disable_tools` ga qo'shing; qarang [Oldindan o'rnatilgan CLI vositalari](18-development-tools.md#preinstalled-cli-tools).

Barcha sozlangan dangasa vositalarni ular kerak bo'lishidan oldin o'rnatish uchun `mise install --include-lazy` ni ishga tushiring. Bunga agentlar bilan birga Omarchy ning boshqa standart CLI vositalari ham kiradi. Bitta vositani o'rnatish yoki o'zingizning o'rnatmangizdan foydalanish uchun qarang [Oldindan o'rnatilgan CLI vositalari](18-development-tools.md#preinstalled-cli-tools).

`grok` mise ning birinchi tomon `grok` paketi orqali, `claude` va `codex` bilan bir xil tarzda o'rnatiladi. `grok` ni ishga tushiring yoki uni _Agent > Harness_ ostida tanlang. x.ai dagi `curl | bash` o'rnatuvchisini o'tkazib yuboring. O'sha yo'l ikkinchi nusxani `~/.grok/bin` ga qo'yadi, uni `PATH` boshiga qo'shadi va Omarchy ning o'ramini ustidan yozadi.

`dsh` o'zining brauzer UI sini `127.0.0.1:3080` da ochadi, ishga tushirish katalogi uning standart ish maydoni bo'ladi. Uning brauzer UI si boshlang'ich prompt qabul qilmaydi, shuning uchun `omarchy agent prompt` uni promptni joylashtirishingiz uchun almashuv buferingizga qo'yib ochadi. Omarchy uni DeepSeek ning rozilik talab qilmaydigan ruxsatlar oldindan sozlanmasi bilan ishga tushiradi. DeepSeek Harness uning rasmiy model API sidan foydalanganingizda sessiya jurnallarini DeepSeek ga yuklaydi; buni uning brauzer UI sidagi _Settings > General > Upload Session Log_ ostida o'chiring. Unga yuborgan fikr-mulohazangiz ham sessiya bilan birga yuklanadi, uni `DSH_TELEMETRY_MODE=DISABLED` bilan ishga tushirmasangiz.

### Standart agent

Standart agentingizni `omarchy default agent <name>` bilan yoki Omarchy Menu (`Super + Space`) dagi _Agent > Harness_ ostida tanlang. Agar agent hali o'rnatilmagan bo'lsa, uni tanlash avval uni o'rnatadi. Yangi Omarchy sizni bir martalik bildirishnoma bilan bu tanlovni qilishga taklif qiladi.

Claude ni tanlash shuningdek Chromium, Chrome, Brave, Brave Origin va Edge uchun uning brauzer kengaytmasini o'rnatishga urinadi. Kengaytmani o'rnatish barcha foydalanuvchilarga tegishli bo'ladi va tizimingiz parolini so'rashi mumkin; kengaytmani o'rnatishni bekor qilish yoki uning muvaffaqiyatsiz bo'lishi baribir Claude ni tanlaydi va ishga tushiradi. Brauzeringizni qayta ishga tushiring, so'ralsa kengaytmani yoqing va uni ulashni yakunlash uchun Claude ga kiring. Ulanishni tekshirish uchun Claude da `/chrome` ni ishga tushiring. Firefox va Zen bu kengaytmani qo'llab-quvvatlamaydi. Agar bu o'rnatish qo'shilishidan oldin Claude allaqachon standart agentingiz bo'lgan bo'lsa, kengaytmani o'rnatish uchun uni yana tanlang.

Tanlab bo'lganingizdan keyin, `Super + Shift + Ctrl + A` standart agentni alohida terminal oynasida ishga tushiradi (yoki hali tanlamagan bo'lsangiz tanlagichni ochadi). Uni to'g'ridan-to'g'ri vazifaga ham `omarchy agent prompt "Review this project"` bilan ishga tushirishingiz mumkin. Freebuff va DeepSeek Harness boshlang'ich prompt qabul qilmaydi, shuning uchun ular buning o'rniga promptni joylashtirishingiz uchun almashuv buferingizga qo'yib ochiladi. Bu tarzda ishga tushirilgan agentlar o'zlarining to'xtab so'ramaydigan rejimlarida qarovsiz ishlaydi, shuning uchun ularning haqiqatan ham biror narsa qilishiga tayyor bo'ling! MiniMax Code da uning interaktiv sessiyalari uchun bunday rejim yo'q, shuning uchun u odatdagidek ruxsat so'raydi. Va agentlar uy katalogingiz uchun ishonchni eslab qolishdan bosh tortgani sababli, `$HOME` dan ishga tushirishlar buning o'rniga `~/Work` da boshlanadi.

Terminal yorliqlari ham bor: `a` standart agentni joriy terminalda ichki ishlatadi, `c`, `cx` va `cy` esa OpenCode, Claude Code va Codex ni to'g'ridan-to'g'ri ishga tushiradi (yana ularning avtomatik tasdiqlaydigan rejimlarida). Mavzu o'zgarishlari agentlarga ham sinxronlanadi: Claude Code, Pi, OpenCode va Hermes (Omarchy uni o'rnatganidan keyin) barchasi siz Omarchy mavzusini almashtirganingizda unga ergashadi.

### Agent ko'rsatmalaringiz

Har bir agent uchun shaxsiy qoidalar `~/.agents/AGENTS.md` ga, umumiy ko'nikmalar yoniga `~/.agents/skills` ga joylashadi. Uni _Agent > Instructions_ ostida oching, u shuningdek uni o'zining global faylini saqlaydigan har bir harnessga bog'laydi: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, Copilot ning `~/.copilot/copilot-instructions.md` va hokazo. Crush va Amp `~/.config/AGENTS.md` bog'lanishini o'qiydi, omp, Kimi va DeepSeek Harness esa `~/.agents/AGENTS.md` ni to'g'ridan-to'g'ri o'qiydi. Standart agentni tanlash ham uni bog'laydi. Sizda allaqachon bo'lgan ko'rsatmalar fayli, agar hali umumiysi bo'lmasa, umumiy faylga aylanadi; aks holda u bog'lanish yonida `.bak` sifatida saqlanadi. Boshqa agentni o'rnatganingizdan keyin qayta bog'lash uchun `omarchy agent instructions` ni ishga tushiring.

### Agentlar paneli

Yuqori panelda agentlar belgisi bor. Agentni hali sozlamagan bo'lsangiz, uning paneli sizni Claude, Codex yoki Grok ga kirish orqali bosqichma-bosqich olib boradi va birinchisi standart agentingizga aylanadi. Shundan keyin panel har bir obunani bitta sahifaga joylaydi: har bir agent va hisob uning rejasi bilan, uning 5 soatlik sessiya va haftalik limitlarining har biri uchun qayta o'rnatilgunigacha qolgan vaqt bilan birga o'lchagich (aniq foiz uchun ustiga olib boring) yoki qolgan oldindan to'langan balans, ularning barchasida foydalangan narsalaringiz bo'ylab aylanib turadigan satr ostida, masalan bu haftadagi tokenlar va eng ko'p foydalangan modelingiz. _Make something_ ostida u vazifani standart agentingizga topshiradigan yangi mavzu, plagin yoki ilova uchun boshlang'ich promptlarni taklif qiladi. Ilovalar Omarchy ning o'z Hype, Monologue va Omacut ilovalari kabi, C++ va Qt Quick da, omarchy-app agent ko'nikmasiga amal qilib quriladi va ularga kerak bo'lgan kompilyator va Qt qismlari o'rnatilgan holda keladi. Claude Code, Codex, Grok, Kimi, Cursor va uning Grok Bot imtiyozi, GitHub Copilot, Muse, Antigravity, Kimchi va Devin limitlari bilan qutidan chiqishi bilanoq qamrab olingan, Hermes, Mistral Vibe va Qwen Code esa ularni ishlatganingizdan keyin sessiyalari va tokenlarini ko'rsatadi. pi, omp yoki opencode orqali foydalanadigan provayder rejalari va kalitlari ham ko'rinadi: OpenCode Zen va Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan va Synthetic ularning limitlari bilan; Fireworks, OpenRouter va DeepSeek ularning oldindan to'langan balanslari bilan; va o'z uskunangizda ishlatadigan modellaringiz Local models ostida. Har bir agent, uni nechta harness orqali boshqarmang, kim unga hisob yozsa o'shaning ostida bir marta sanaladi.

Panel uchun panel belgisini chap tugma bilan bosing, standart agentingizni ishga tushirish uchun o'ng tugma bilan bosing. Uning ortidagi foydalanish yozuvlari har 15 daqiqada `omarchy agent usage-update` tomonidan qayta yaratiladi va panel hatto sinxronlangan papka orqali boshqa mashinalaringizdan foydalanishni birlashtira oladi. To'liq sozlamalar uchun `$OMARCHY_PATH/shell/plugins/agents/` ostidagi README ga qarang.

### Bir nechta obuna

Agar siz bir nechta Claude, Codex yoki Grok rejasi uchun to'lasangiz — masalan shaxsiy Max va ish rejasi — Omarchy ularning barchasini kirgan holda saqlay oladi va ular orasida harakatlana oladi. Agentlar panelidagi + bilan obuna qo'shing, u sizni o'sha yerning o'zida bosqichma-bosqich olib boradi, yoki `omarchy agent account add claude Work` (yoki `codex`, yoki `grok`) bilan. Agar CLI yo'q bo'lsa u uni o'rnatadi. Provayder uchun birinchi hisob oddiy brauzeringiz orqali, CLI doim qaraydigan joyda kiradi. Undan keyingi har biri shaxsiy oyna orqali kiradi, shuning uchun brauzeringiz allaqachon kirgan hisob xatolik bilan tanlanib qolmaydi; u yerda qo'shayotgan hisobingiz sifatida kiring va avval ochib qo'ygan har qanday shaxsiy oynani yoping. Buni qilish uchun hech qachon CLI dan chiqmang: chiqish saqlangan kirishni bekor qiladi va o'sha hisobni yana qo'shish kerak bo'lardi.

Obuna kirishlaringizni boshqa Omarchy mashinasiga SSH orqali nusxalash uchun `omarchy agent account copy user@laptop` ni ishga tushiring. Yuboruvchi, boradigan joyda o'rnatilmagan bo'lsa, vaqtinchalik qabul qiluvchini taqdim etadi, shuning uchun eski Omarchy mashinalari yangilanishsiz hisoblarni qabul qila oladi. O'rnatilgan qabul qiluvchilar ustunlikka ega. Bu barcha Claude, Codex va Grok obunalarini nusxalaydi; ularni tanlash uchun provayder nomlarini qo'shing, masalan `omarchy agent account copy laptop claude`. Hisob nomlari va buyruq ID lari manbaga mos keladi, shu jumladan boradigan joyda allaqachon mavjud hisoblar ham. Nomi to'qnashsa, aloqasi bo'lmagan boradigan joy hisoblari raqamli qo'shimcha oladi va sozlamalar, ko'nikmalar, plaginlar hamda suhbat tarixi har bir mashinada mahalliy qoladi.

Mavjud boradigan joy hisob ma'lumotlari saqlanadi. U yerda allaqachon kirilgan manba hisobi, uning hisob ma'lumotlari almashtirilmasdan, nomi sinxronlanadi; boshqa hisoblar uning yoniga qo'shiladi. Mos hisoblar uchun saqlangan hisob ma'lumotlarini almashtirish uchun, boradigan joyda o'sha hisobning sessiyalarini yopgandan keyin `omarchy agent account copy --replace laptop claude` dan foydalaning. Yangi boradigan joy shuningdek manbaning faol hisobi va almashtirish afzalliklarini oladi; o'rnashib bo'lgan boradigan joy o'zinikini saqlaydi.

Hisob ma'lumotlari SSH orqali sayohat qiladi va boradigan joyda shaxsiy fayllarda saqlanadi, shuning uchun faqat ishonadigan mashinalaringizga nusxalang. Bu bir martalik nusxa, doimiy sinxronlash emas. Codex yangilash tokenlari boshqa mashina tomonidan aylantirilishi mumkin, bu nusxalangan kirishni yangilashga muhtoj qoldiradi; bir nechta mashinada bir vaqtda foydalanish uchun alohida kirishlar eng ishonchli tanlov bo'lib qoladi. Qarang [Codex ning hisob autentifikatsiyasi bo'yicha qo'llanmasi](https://developers.openai.com/codex/auth/ci-cd-auth).

Har bir provayderga bitta hisob faol bo'ladi va har bir yangi sessiya o'sha sifatida boshlanadi: `cx`, `cy`, oddiy `claude`, `codex` yoki `grok`, `omarchy agent` orqali ishga tushirilgan har qanday narsa hamda CLI ni `PATH` da topadigan skriptlar yoki muharrirlar. `omarchy agent account use work` bilan almashtiring (va `omarchy agent account use main` bilan orqaga), yoki panelda hisobning raqamini bosib keyin `Enter` ni bosib (yoki uning Use tugmasini bosib). Allaqachon ishlayotgan sessiyalar boshlangan hisobda qoladi. Suhbat tarixi, sozlamalar, ko'nikmalar va plaginlar hisoblar bo'ylab umumiydir, shuning uchun o'sha papkadagi `claude --continue` yangi hisobda qoldirgan joyingizdan davom etadi.

Bir nechta hisob bo'lsa, panel har bir hisobning limitlarini yonma-yon, faol hisob belgilangan holda ko'rsatadi. Sukut bo'yicha Omarchy faol hisob limitning 95% idan o'tganda sizga xabar beradi va bildirishnomani bosish eng ko'p zaxirasi bo'lgan hisobga o'tadi. Panelda hisob satri ustiga olib boring va Use yonida paydo bo'ladigan Autoswitch ni bosing (yoki `m` ni bosing), yoki buning o'rniga o'z-o'zidan almashishi uchun `omarchy agent account mode auto` ni ishga tushiring; u yoqilgan vaqtda Autoswitch Use o'rnini egallaydi va uni yana bosish xabar berishga qaytadi. Chegarani o'zgartirish uchun raqam qo'shing, masalan `omarchy agent account mode auto 90`. Agar har bir hisob chegaradan yuqori bo'lsa, bu haqida bir marta eshitasiz, qaysi hisob birinchi bo'shashi bilan birga. Faol hisob chegarasidan 15 ball ichida bo'lsa (standartda 80%), uning limitlari har 15 daqiqa o'rniga har uch daqiqada tekshiriladi.

`omarchy agent account list` har bir hisobni va uning eng so'nggi limitlarini ko'rsatadi, `omarchy agent account remove work` bittasini unutadi va `omarchy agent account rename primary Hey` bittasini qayta nomlaydi (yoki panelda hisobning nomini bosing). Bu buyruqlar standart agentingiz hisoblarida ishlaydi; boshqa provayderga yetish uchun avval uni nomlang, masalan `omarchy agent account use codex side`. `~/.claude` yoki `~/.codex` da allaqachon bo'lgan kirishingiz _Main_ hisobdir va turgan joyida qoladi. Taxminan sakkiz soatdan ko'proq foydalanilmay qolgan hisob _Sign-in required_ ni ko'rsatishi mumkin; o'sha hisobga yana panelning o'zida kirish uchun uni bosing yoki unda sessiya boshlang, bu kirishni o'z-o'zidan yangilaydi. Hisob qo'shilganda sizda bo'lgan MCP serverlari unga hamroh bo'ladi, lekin keyinroq `claude mcp add` bilan qo'shadiganlaringiz faqat ularni qo'shgan hisobingizga yetadi. Claude Desktop va CLI binar fayliga mutlaq yo'l bilan sozlangan vositalar almashishga ergashmaydi. Aniq `CLAUDE_CONFIG_DIR`, `CODEX_HOME` yoki `GROK_HOME` tanlangan hisobdan ustun keladi.

### Ishdan chiqish diagnostikasi

Omarchy jarayon ishdan chiqishlari uchun systemd-coredump ni kuzatadi. Biror narsa segfault bo'lsa, siz "Process crashed" bildirishnomasini olasiz — uni bosing va ishdan chiqish Omarchy ning diagnose-crash ko'nikmasi bilan birga standart agentingizga topshiriladi, u agentni core dump dan faktlarni aniqlash va ishdan chiqish yuqoriga xabar berishga arziydimi yoki yo'qligini hal qilish orqali bosqichma-bosqich olib boradi. Uni `coredumpctl list` dan istalgan PID ga qarshi `omarchy agent crash <pid>` bilan qo'lda ham ishga tushirishingiz mumkin.

Kuzatuv sukut bo'yicha yoqilgan. Uni _Trigger > Toggle > Crash Capture_ ostida (yoki `omarchy toggle crash-capture` bilan) o'chiring va bildirishnomalar to'xtaydi; `omarchy agent crash <pid>` qo'lda ishlashda davom etadi.

Ishdan chiqishlarni bir vaqtda bitta dasturda ham ovozini o'chirish mumkin, diagnostika oxirida sizga taklif qiladigani ham shu. `omarchy crash mute hyprland` faqat o'sha dastur uchun bildirishnomalarni to'xtatadi, `omarchy crash mute hyprland off` ularni qaytaradi va `omarchy crash mute` o'z-o'zidan nimani ovozsizlantirganingizni ro'yxatlaydi. U binar faylning yo'lini ham uning nomi kabi mamnuniyat bilan qabul qiladi, shuning uchun `omarchy crash mute /usr/bin/hyprland` ham xuddi shunday qiladi. Ichida bo'shliq bo'lgan nomni qo'shtirnoqqa oling, masalan `omarchy crash mute 'Some App'`. Qolgan hamma narsa baribir xabar beradi va ovozsizlantirilgan dastur baribir ishdan chiqadi — bu eslatmani yashiradi, hech narsani tuzatmaydi.

### Ish stoli ilovalari

_Install > AI_ menyusi shuningdek bir nechta grafik AI ilovalarini ham olib yuradi: ChatGPT ish stoli ilovasi, Claude ish stoli ilovasi (Anthropic ning Linux betasi, Chat, Cowork va Claude Code yorliqlari bilan), xAI modellari bilan suhbatlashish uchun Grok Bot, Herdr Desktop, Hermes Desktop, OpenClaw, Perplexity ish stoli ilovasi va T3 Code. Grok Bot ish stoli suhbat ilovasidir. Kodlash agenti `grok` buyrug'idir.

Hermes Desktop bilishga arziydigani, chunki mashinada bitta Hermes bo'ladi va u ilovaniki bo'ladi: Hermes faqat ilova orqali o'rnatiladi va standart agent ishlatadigan `hermes` buyrug'i ilovanikidir. Hermes ni standart agent sifatida tanlash _Install > AI_ yozuvi qiladigan xuddi o'sha narsani o'rnatadi: paketni va Hermes ning o'z o'rnatuvchisi tomonidan sozlangan `~/.hermes` ostidagi Hermes ish vaqtini, bu birinchi marta bir necha daqiqa oladi. O'sha ish vaqti terminaldagi `hermes` buyrug'i, standart agent va ilova barchasi foydalanadigan yagona Hermes dir va u Omarchy relizini kutish o'rniga o'zini `hermes update` bilan yangilaydi. Uni o'rnatish shuningdek Hermes ga Omarchy mavzusini `omarchy` nomli teri sifatida topshiradi, har bir Hermes yuzasi siz mavzularni almashtirganingizda unga ergashadi; agar xohlamasangiz Hermes ning Appearance sozlamalari ostida yoki `/skin` bilan boshqasini tanlang va Omarchy o'sha tanlovni o'z holicha qoldiradi. Ilovani _Remove > AI_ ostida olib tashlash avval Hermes ni, shlyuzini ham qo'shib, yopadi, o'sha ish vaqtini u bilan birga olib ketadi va suhbatlaringiz, xotiralaringiz hamda Hermes o'zi uchun yozgan ko'nikmalarni saqlab qoladi, siz boshqacha aytmasangiz: u sukut bo'yicha yo'q deb, o'sha ma'lumotlar va ulanish sozlamalaringiz ham ketishi kerakmi deb so'raydi.

OpenClaw ning ish stoli tajribasi uning Control UI sidir, u o'zining mahalliy shlyuzi bilan ta'minlangan veb-ilova sifatida ochiladi. OpenClaw `~/.openclaw` da yashaydi va o'zini yangilaydi: Control UI ning "Update Gateway" tugmasidan foydalaning yoki `openclaw update` ni ishga tushiring va shlyuz yangi versiyada qayta ishga tushadi. Omarchy faqat yangi o'rnatish boshlanadigan relizni tanlaydi. OpenClaw ni _Remove > AI_ ostida olib tashlash shlyuz xizmati va ilovani u bilan birga olib ketadi va keyin `~/.openclaw` ham ketishi kerakmi deb so'raydi, chunki u yerda suhbatlaringiz va hisob ma'lumotlaringiz OpenClaw ning o'zi va u yuklab oladigan plagin ish vaqtlari bilan birga turadi; sukut uni saqlaydi va OpenClaw ni yana o'rnatish uni qayta tanlab oladi.

Herdr Desktop bu [Herdr](https://herdr.dev) ish stoli ilovasidir: oynani yopganingizda uning yadrosida ishlashda davom etadigan terminallar va kodlash agentlarining bo'shliqlari, yorliqlari va panellari. U paketdan emas, Herdr ning o'z o'rnatuvchisidan keladi, shuning uchun u `~/.local/share/herdr-app` da yashaydi, hali yo'q bo'lsa yadrosini `~/.local/bin/herdr-core` da o'zi bilan olib keladi va ikkalasini ham o'zi yangilaydi. U Omarchy `Super + Ctrl + Return` da yetkazadigan `herdr` buyrug'ining yonida turadi, uni almashtirmaydi va o'sha buyruqning to'g'ridan-to'g'ri tugmalarini oladi: `Alt + Return` va `Alt + Shift + Return` panelni pastga yoki o'ngga bo'ladi, `Alt + Escape` uni yopadi, `Ctrl + Alt + Arrow` panellar orasida harakatlanadi, `Alt + 1..9` va `Alt + Left/Right` yorliq tanlaydi va `Alt + Up/Down` bo'shliqlar orasida harakatlanadi. `Ctrl + 1..9` bo'shliq tanlaydi va `Alt + Shift + Up/Down` agentlar bo'ylab qadamlaydi. `Ctrl + Space` prefiks tugmalari faqat terminalda qoladi, chunki ilova ketma-ketlik uchun oddiy Ctrl tugmasini ushlab tura olmaydi. Omarchy bularni `~/.config/herdr-app/keys.json` ga yozadi va `omarchy-refresh-herdr-app` ularni qayta joyiga qo'yadi. Uni o'rnatish Herdr ning Omarchy mavzusini tanlaydi, u shundan keyin Omarchy mavzungizga ergashadi. Herdr yorug' rejim uchun bitta mavzu va qorong'u rejim uchun bitta mavzu saqlaydi, shuning uchun qorong'u va yorug' Omarchy mavzusi orasida almashgandan keyin, boshqa rejim uchun Herdr ning mavzu tanlagichida Omarchy ni yana bir marta tanlang.

T3 Code paketdan emas, `~/.local/share/t3code` dagi rasmiy AppImage relizidan ishlaydi, shuning uchun o'zini yangilaydi. Uni o'rnatish Stable yoki Nightly kanalda boshlashni so'raydi; keyinroq T3 Code sozlamalarida almashtiring. Mavzularingiz va sozlamalaringiz `~/.t3` da yashaydi va T3 Code ni _Remove > AI_ ostida olib tashlash ularni u bilan birga olib ketadi.

### Mahalliy modellar

Kodlash agentlaringiz uchun ochiq modelni o'z mashinangizda ishlating. Promptlaringiz va kodingiz mashinada qoladi; modelga yuborilgan hech narsa undan chiqmaydi. Quyidagidan boshlang:

```bash
omarchy agent local use best
```

Yoki yuqori paneldagi agentlar panelida + ni, keyin model bu mashinaga sig'ganda ko'rinadigan Local AI ni tanlang. Birinchi marta bu modellarni ishlatadigan Podman ni va NVIDIA mashinasida ularga GPU ni beradigan NVIDIA ning konteyner vositalar to'plamini o'rnatadi. Keyin Omarchy bu mashina uchun tavsiya qilingan modelni tanlaydi, uni yuklab oladi va ishga tushiradi. O'nlab GB yuklab olishni va model ishlayotganda mashina xotirasining katta qismi ishlatilishini kuting: Flash Next to'liq 256K konteksti bilan taxminan 100 GiB ishlatadi. Agar boshqa modellar unga kerak bo'lgan xotirani egallagan bo'lsa, u to'xtatilgan holda sozlanadi, birini to'xtatganingizdan keyin ishga tushishga tayyor bo'ladi. Model tizimdan chiqqanda to'xtaydi; xotira boshqa narsa uchun kerak bo'lganda uni o'zingiz to'xtating.

`omarchy agent local list` variantlarni ko'rsatadi va ba'zilari nega sig'masligini tushuntiradi. Boshqasini sozlash uchun `omarchy agent local use <recipe>` ni ishga tushiring. Bugun `qwen3.8-flash-next-gufo` va `qwen3.8-27b-gufo` 128 GB Strix Halo mashinalari uchun mavjud; 27B taxminan 40 GiB oladi, shuning uchun u boshqa ishlar uchun joy qoldiradi. Yangi retseptlar va tavsiyalar paket orqali `omarchy update` bilan keladi.

Sozlagan har bir modelingiz obunalaringiz yonida agentlar panelida o'z satriga ega bo'ladi: uni ishga tushirish uchun ijro, uni to'xtatish va xotirasini bo'shatish uchun pauza va unda agentingizni ochish uchun terminal tugmasi. Bir nechtasi xotiraga birga sig'sa bir vaqtda ishlashi mumkin; agar bittasi sig'masa, Omarchy qaysi ishlayotgan modelni to'xtatishni aytadi. Ularni qayta tartiblash uchun satrlarni sudrab torting va modelni va uning yuklab olinishini olib tashlash uchun tanlangan satrda Delete ni bosing.

Buyruq satridan `omarchy agent local start <recipe>` va `omarchy agent local stop <recipe>` xuddi shunday qiladi, `omarchy agent local status` har bir modelni ko'rsatadi va `omarchy agent --local` standart agentingizni oxirgi ishga tushirgan modelingizda ochadi (standart agentingiz mahalliy modeldan foydalana olmasa pi). Har qanday OpenAI ga mos mijoz ham ulana oladi: `status` har bir modelning manzilini ko'rsatadi (birinchisi `http://127.0.0.1:11435/v1`), retsept nomi modeldir va kalit `~/.config/omarchy/agent-local/key` da.

`omarchy agent local remove <recipe>` modelni va boshqa hech bir model foydalanmaydigan yuklab olishlarni o'chiradi.

Uchinchi tomon ish vaqtlari ularning nashriyotchisi bilan belgilanadi. Omarchy har bir modelni tarmoqqa kirishsiz ishlatadi.

### Mahalliy LLM lar

Omarchy mahalliy LLM modellarini ishlatishning ikki usulini tavsiya qiladi: LM Studio va Ollama. LM Studio ochiq vaznli modellarni topish, ularni o'rnatish va ishlatish uchun GUI interfeysini taqdim etadi. Bu oson boshlashning ajoyib usuli. Ollama xuddi shunday qilish uchun CLI taklif qiladi. Lekin agar siz mahalliy modellarga yangi bo'lsangiz, men LM Studio dan boshlagan bo'lardim. Ikkalasidan birini Omarchy Menu dagi _Install > AI_ ostida o'rnatishingiz mumkin.

### Omarchy ko'nikmasi

Agent ko'nikmalari AI ga aniq vositalardan aniq tarzda foydalanishga yordam beradi va Omarchy tizimni sozlash uchun standart ko'nikma bilan keladi. Hyprland konfiguratsiyangizni sozlash, panelni o'zgartirish yoki hatto noldan yangi mavzu yaratish kabi. U Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` va har bir `~/.hermes/profiles/*/skills`) va umumiy `~/.agents/skills` joylashuvi uchun ko'nikma kataloglariga ramziy bog'langan, shuning uchun ko'pchilik harnesslar uni avtomatik tanlab oladi.

Lekin bu ko'nikmani eksperimental deb hisoblashingiz kerak. Turli modellar undan turlicha samarada foydalanadi. Avval uni reja rejimida ishlatish eng yaxshisi, shunda agent nimani o'zgartirmoqchi ekani haqida tasavvurga ega bo'lasiz. Va keyin, agar agent hammasini chalkashtirib yuborsa, o'zgarishlarni orqaga qaytarishga yoki hatto `omarchy reinstall configs` ni chaqirishga tayyor bo'ling.
