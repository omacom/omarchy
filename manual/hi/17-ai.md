### Agents को install और update करना

Hermes को छोड़कर, ये agents mise के lazy installation का उपयोग करते हैं: पहला launch CLI को install करता है, और बाद के launches उसी का पुनः उपयोग करते हैं। mise किसी install किए गए agent के लिए नए release की जाँच हर चार घंटे में अधिकतम एक बार करता है, या तो उसके शुरू होने से ठीक पहले या shell prompt पर background में। यदि वह update विफल हो जाता है या आप offline हैं, तो install किया गया version चलता है। `omarchy update` Omarchy के बाकी हिस्से के साथ install किए गए agents को update करता है, और `mup` केवल mise-प्रबंधित tools को update करता है।

किसी agent का अपना updater, जैसे `claude update`, `codex update`, या किसी app में update button, mise-प्रबंधित install को update नहीं करता है। `codex update` विफल हो जाता है, और `claude update` सफलता की रिपोर्ट करते हुए एक अलग प्रति install कर सकता है जिसे mise track नहीं करता है। यदि आप इसके बजाय किसी agent के native installer और updater का उपयोग करना पसंद करते हैं, तो उसे `disable_tools` में जोड़ें; देखें [पहले से install किए गए CLI tools](18-development-tools.md#preinstalled-cli-tools)।

सभी configured lazy tools को उनकी आवश्यकता पड़ने से पहले install करने के लिए, `mise install --include-lazy` चलाएँ। इसमें agents के साथ-साथ Omarchy के अन्य default CLI tools भी शामिल हैं। एकल tool install करने या अपने स्वयं के installation का उपयोग करने के लिए देखें [पहले से install किए गए CLI tools](18-development-tools.md#preinstalled-cli-tools)।

`grok` mise के first-party `grok` package के माध्यम से install होता है, उसी तरह जैसे `claude` और `codex`। `grok` चलाएँ, या इसे _Setup > Defaults > Agent_ के अंतर्गत चुनें। x.ai पर `curl | bash` installer को छोड़ दें। वह मार्ग `~/.grok/bin` में एक दूसरी प्रति रखता है, उसे `PATH` पर सबसे पहले रखता है, और Omarchy के wrapper को overwrite कर देता है।

`dsh` अपना browser UI `127.0.0.1:3080` पर खोलता है, जिसमें launch directory उसका default workspace होता है। उसका browser UI कोई शुरुआती prompt नहीं लेता है, इसलिए `omarchy agent prompt` उसे आपके clipboard पर मौजूद prompt के साथ खोलता है जिसे आप paste कर सकें। Omarchy उसे DeepSeek के no-approval permission preset के साथ शुरू करता है। जब आप DeepSeek Harness के आधिकारिक model API का उपयोग करते हैं तो वह session logs को DeepSeek पर upload करता है; इसे उसके browser UI में _Settings > General > Upload Session Log_ के अंतर्गत बंद करें। आप जो feedback उसे भेजते हैं वह भी session के साथ upload होता है, जब तक कि आप उसे `DSH_TELEMETRY_MODE=DISABLED` के साथ शुरू न करें।

### Default agent

अपना default agent `omarchy default agent <name>` के साथ या Omarchy Menu (`Super + Space`) में _Setup > Defaults > Agent_ के अंतर्गत चुनें। यदि agent अभी तक install नहीं हुआ है, तो उसे चुनने पर वह पहले install हो जाता है। एक ताज़ा Omarchy आपको एक बार की सूचना के साथ यह चुनाव करने के लिए आमंत्रित करेगा।

Claude को चुनने पर Chromium, Chrome, Brave, Brave Origin, और Edge के लिए उसके browser extension को set up करने का भी प्रयास होता है। Extension setup सभी users पर लागू होता है और आपसे आपका system password माँग सकता है; रद्द करने या extension install विफल होने पर भी Claude चुना और launch होता है। अपना browser restart करें, संकेत मिलने पर extension सक्षम करें, और उसे जोड़ना पूरा करने के लिए Claude में sign in करें। Connection की जाँच करने के लिए Claude में `/chrome` चलाएँ। Firefox और Zen इस extension का समर्थन नहीं करते हैं। यदि यह setup जोड़े जाने से पहले Claude पहले से ही आपका default था, तो extension install करने के लिए उसे फिर से चुनें।

एक बार जब आप चुन लेते हैं, तो `Super + Shift + Ctrl + A` default agent को एक समर्पित terminal window में launch करता है (या यदि आपने अभी तक नहीं चुना है तो picker सामने लाता है)। आप उसे `omarchy agent prompt "Review this project"` के साथ सीधे किसी कार्य में भी launch कर सकते हैं। Freebuff और DeepSeek Harness कोई शुरुआती prompt नहीं लेते हैं, इसलिए वे इसके बजाय आपके clipboard पर मौजूद prompt के साथ खुलते हैं जिसे आप paste कर सकें। इस तरह launch किए गए agents अपने-अपने don't-stop-to-ask modes में बिना निगरानी के चलते हैं, इसलिए तैयार रहें कि वे वास्तव में कुछ करेंगे! MiniMax Code के पास उसके interactive sessions के लिए ऐसा कोई mode नहीं है, इसलिए वह हमेशा की तरह permissions माँगता है। और चूँकि agents आपकी home directory के लिए trust याद रखने से इनकार करते हैं, इसलिए `$HOME` से launches इसके बजाय `~/Work` में शुरू होते हैं।

Terminal shortcuts भी हैं: `a` वर्तमान terminal में ही default agent को चलाता है, जबकि `c`, `cx`, और `cy` OpenCode, Claude Code, और Codex को सीधे शुरू करते हैं (फिर से उनके auto-approving modes में)। Theme परिवर्तन भी agents के साथ sync होते हैं: जब आप Omarchy theme बदलते हैं तो Claude Code, Pi, OpenCode, और Hermes (एक बार जब Omarchy ने उसे install कर लिया हो) सभी साथ चलते हैं।

### Agents panel

Top bar में एक agents icon है। इससे पहले कि आपने कोई agent set up किया हो, उसका panel आपको Claude, Codex, या Grok में sign in करने की प्रक्रिया से ले जाता है, और पहला वाला आपका default agent बन जाता है। उसके बाद, panel हर subscription को एक ही page पर रखता है: प्रत्येक agent और account उसके plan के साथ, उसकी 5-घंटे की session और साप्ताहिक limits में से प्रत्येक के लिए एक meter जिसमें उसके reset होने तक का समय होता है (सटीक प्रतिशत के लिए hover करें), या शेष prepaid balance, एक ऐसी line के नीचे जो उन सभी में आपने जो कुछ उपयोग किया है उसमें से घूमती रहती है, जैसे इस सप्ताह के tokens और आपका सबसे अधिक उपयोग किया गया model। _Make something_ के अंतर्गत यह एक नई theme, plugin, या app के लिए starter prompts प्रदान करता है जो कार्य को आपके default agent को सौंप देते हैं। Apps उसी तरह बनाई जाती हैं जैसे Omarchy की अपनी Hype, Monologue, और Omacut बनाई गई हैं, C++ और Qt Quick में, omarchy-app agent skill का पालन करते हुए, और उन्हें आवश्यक compiler और Qt हिस्से install किए हुए आते हैं। Claude Code, Codex, Grok, Kimi, Cursor और उसके Grok Bot allowance, GitHub Copilot, Muse, Antigravity, Kimchi, और Devin अपनी limits के साथ पहले से ही शामिल हैं, और Hermes, Mistral Vibe, और Qwen Code जब आप उनका उपयोग कर लेते हैं तो अपने sessions और tokens दिखाते हैं। pi, omp, या opencode के माध्यम से आप जिन provider plans और keys का उपयोग करते हैं वे भी दिखाई देती हैं: OpenCode Zen और Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan, और Synthetic अपनी limits के साथ; Fireworks, OpenRouter, और DeepSeek अपने prepaid balances के साथ; और वे models जिन्हें आप Local models के अंतर्गत अपने स्वयं के hardware पर चलाते हैं। प्रत्येक agent को एक बार गिना जाता है, उसी के अंतर्गत जो उसे bill करता है, चाहे आप उसे कितने ही harnesses के माध्यम से चलाएँ।

Panel के लिए bar icon पर left-click करें, अपने default agent को launch करने के लिए right-click करें। इसके पीछे के usage records `omarchy agent usage-update` द्वारा हर 15 मिनट में फिर से बनाए जाते हैं, और panel एक synced folder के माध्यम से आपकी अन्य machines के usage को भी merge कर सकता है। पूर्ण settings के लिए `$OMARCHY_PATH/shell/plugins/agents/` के अंतर्गत README देखें।

### कई subscriptions

यदि आप एक से अधिक Claude, Codex, या Grok plan के लिए भुगतान करते हैं — मान लीजिए एक व्यक्तिगत Max और एक कार्य वाला — तो Omarchy उन सभी को signed in रख सकता है और उनके बीच जा सकता है। Agents panel में + के साथ एक subscription जोड़ें, जो आपको वहीं प्रक्रिया से ले जाता है, या `omarchy agent account add claude Work` (या `codex`, या `grok`) के साथ। यदि CLI मौजूद नहीं है तो वह उसे install कर देता है। किसी provider के लिए पहला account आपके सामान्य browser के माध्यम से sign in करता है, ठीक वहीं जहाँ CLI हमेशा देखता है। उसके बाद का प्रत्येक account एक private window के माध्यम से sign in करता है, ताकि वह account जिसे आपका browser पहले से signed in है गलती से न चुना जाए; वहाँ उस account के रूप में sign in करें जिसे आप जोड़ रहे हैं, और पहले से खुली हुई किसी भी private window को पहले बंद कर दें। ऐसा करने के लिए कभी भी CLI से log out न करें: log out करने से सहेजा गया sign-in रद्द हो जाता है, और उस account को फिर से जोड़ना होगा।

अपने subscription logins को SSH पर किसी अन्य Omarchy machine पर copy करने के लिए, `omarchy agent account copy user@laptop` चलाएँ। जब destination के पास कोई receiver install नहीं होता है तो sender एक अस्थायी receiver प्रदान करता है, ताकि पुरानी Omarchy machines बिना update के accounts प्राप्त कर सकें। Install किए गए receivers को प्राथमिकता मिलती है। यह सभी Claude, Codex, और Grok subscriptions को copy करता है; उन्हें चुनने के लिए provider names जोड़ें, जैसे `omarchy agent account copy laptop claude` में। Account names और command IDs source से मेल खाते हैं, जिनमें destination पर पहले से मौजूद accounts भी शामिल हैं। असंबंधित destination accounts के नामों में टकराव होने पर उन्हें एक संख्यात्मक suffix मिलता है, और settings, skills, plugins, और conversation history प्रत्येक machine पर स्थानीय रहते हैं।

Mौजूदा destination credentials रखे जाते हैं। वहाँ पहले से signed in कोई source account अपनी credentials को बदले बिना अपना नाम synchronized कर लेता है; अन्य accounts उसके साथ जोड़े जाते हैं। मेल खाने वाले accounts के लिए सहेजे गए credentials को बदलने के लिए, destination पर उस account के sessions छोड़ने के बाद `omarchy agent account copy --replace laptop claude` का उपयोग करें। एक ताज़ा destination को source का active account और switching preferences भी मिलती हैं; एक स्थापित destination अपने स्वयं के रखता है।

Credentials SSH के माध्यम से यात्रा करते हैं और destination पर private files में संग्रहीत होते हैं, इसलिए केवल उन्हीं machines पर copy करें जिन पर आप भरोसा करते हैं। यह एक बार की copy है, चल रहा synchronization नहीं। Codex refresh tokens को किसी अन्य machine द्वारा rotate किया जा सकता है, जिससे copy किया गया login नवीनीकरण की आवश्यकता में रह जाता है; कई machines पर एक साथ उपयोग के लिए अलग-अलग sign-ins सबसे विश्वसनीय विकल्प रहते हैं। देखें [Codex का account authentication मार्गदर्शन](https://developers.openai.com/codex/auth/ci-cd-auth)।

प्रति provider एक account सक्रिय होता है, और प्रत्येक नया session उसी के रूप में शुरू होता है: `cx`, `cy`, एक सादा `claude`, `codex`, या `grok`, `omarchy agent` के माध्यम से launch की गई कोई भी चीज़, और वे scripts या editors जो `PATH` पर CLI खोजते हैं। `omarchy agent account use work` के साथ switch करें (और `omarchy agent account use main` के साथ वापस), या panel में किसी account की संख्या दबाकर और फिर `Enter` दबाकर (या उसके Use button पर click करके)। पहले से चल रहे sessions उसी account पर रहते हैं जिसके साथ वे शुरू हुए थे। Conversation history, settings, skills, और plugins accounts में साझा होते हैं, इसलिए उसी folder में `claude --continue` नए account पर वहीं से आगे बढ़ता है जहाँ आपने छोड़ा था।

एक से अधिक account होने पर, panel प्रत्येक account की limits को साथ-साथ दिखाता है, जिसमें सक्रिय वाला चिह्नित होता है। डिफ़ॉल्ट रूप से Omarchy आपको तब सूचित करता है जब सक्रिय account किसी limit के 95% को पार कर जाता है, और सूचना पर click करने से सबसे अधिक headroom वाले account पर switch हो जाता है। Panel में किसी account की line पर hover करें और Use के बगल में दिखाई देने वाले Autoswitch पर click करें (या `m` दबाएँ), या इसके बजाय उसे स्वयं switch कराने के लिए `omarchy agent account mode auto` चलाएँ; जब यह चालू होता है, तो Autoswitch Use की जगह ले लेता है, और उसे फिर से click करने से सूचित करने पर वापस आ जाता है। Threshold बदलने के लिए एक संख्या जोड़ें, जैसे `omarchy agent account mode auto 90` में। यदि प्रत्येक account threshold से ऊपर है, तो आपको इसके बारे में एक बार सुनने को मिलेगा, साथ ही यह भी कि कौन सा account सबसे पहले मुक्त होगा। जबकि कोई सक्रिय account उसके threshold के 15 points के भीतर होता है (default पर 80%), उसकी limits की जाँच हर 15 के बजाय हर तीन मिनट में होती है।

`omarchy agent account list` प्रत्येक account और उसकी नवीनतम limits दिखाता है, `omarchy agent account remove work` एक को भुला देता है, और `omarchy agent account rename primary Hey` एक का नाम बदल देता है (या panel में किसी account के नाम पर click करें)। ये commands आपके default agent के accounts पर काम करते हैं; दूसरे provider तक पहुँचने के लिए, पहले उसका नाम दें, जैसे `omarchy agent account use codex side` में। `~/.claude` या `~/.codex` में आपके पास पहले से मौजूद login _Main_ account है और वहीं रहता है जहाँ वह है। लगभग आठ घंटे से अधिक समय तक अप्रयुक्त छोड़ा गया कोई account _Sign-in required_ दिखा सकता है; panel में ही उस account को फिर से sign in करने के लिए उस पर click करें, या उसमें एक session शुरू करें, जो sign-in को अपने आप refresh कर देता है। जब कोई account जोड़ा गया था तब आपके पास मौजूद MCP servers उसके साथ आ जाते हैं, लेकिन जिन्हें आप बाद में `claude mcp add` के साथ जोड़ते हैं वे केवल उसी account तक पहुँचते हैं जिसमें आपने उन्हें जोड़ा था। Claude Desktop और CLI binary के absolute path के साथ configured tools switch का पालन नहीं करते हैं। एक स्पष्ट `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, या `GROK_HOME` चुने गए account पर प्राथमिकता लेता है।

### Crash का निदान

Omarchy process crashes के लिए systemd-coredump को देखता है। जब कुछ segfault होता है, तो आपको एक "Process crashed" सूचना मिलेगी — उस पर click करें, और crash आपके default agent को Omarchy के diagnose-crash skill के साथ सौंप दिया जाता है, जो agent को core dump से तथ्यों को स्थापित करने और यह तय करने की प्रक्रिया से ले जाता है कि crash upstream रिपोर्ट करने योग्य है या नहीं। आप उसे किसी भी PID के विरुद्ध `coredumpctl list` से `omarchy agent crash <pid>` के साथ हाथ से भी चला सकते हैं।

देखना default रूप से चालू है। उसे _Trigger > Toggle > Crash Capture_ के अंतर्गत (या `omarchy toggle crash-capture` के साथ) बंद करें और सूचनाएँ बंद हो जाती हैं; `omarchy agent crash <pid>` हाथ से फिर भी काम करता है।

Crashes को एक समय में एक program के हिसाब से भी चुप किया जा सकता है, जो निदान अंत में आपको प्रदान करता है। `omarchy crash mute hyprland` केवल उस program के लिए सूचनाएँ बंद करता है, `omarchy crash mute hyprland off` उन्हें वापस लाता है, और अपने आप में `omarchy crash mute` सूचीबद्ध करता है कि आपने क्या mute किया है। यह binary के path को उसके नाम जितनी ही खुशी से लेता है, इसलिए `omarchy crash mute /usr/bin/hyprland` वही काम करता है। जिसमें space हो ऐसे नाम को quote करें, जैसे `omarchy crash mute 'Some App'` में। बाकी सब कुछ फिर भी सूचित करता है, और muted program फिर भी crash होता है — यह reminder को छिपाता है, यह कुछ भी ठीक नहीं करता है।

### Desktop ऐप्स

_Install > AI_ menu में कुछ graphical AI apps भी हैं: ChatGPT desktop app, Claude desktop app (Anthropic का Linux beta, Chat, Cowork, और Claude Code tabs के साथ), xAI के models के साथ chatting के लिए Grok Bot, Hermes Desktop, OpenClaw, Perplexity desktop app, और T3 Code। Grok Bot desktop chat app है। Coding agent `grok` command है।

Hermes Desktop वह है जिसके बारे में जानना ज़रूरी है, क्योंकि एक machine के पास एक Hermes होता है, और वह app का होता है: Hermes हमेशा केवल app के माध्यम से install होता है, और default agent जो `hermes` command चलाता है वह app का होता है। Hermes को default agent के रूप में चुनने पर वही चीज़ install होती है जो _Install > AI_ entry करती है: package, और `~/.hermes` के अंतर्गत Hermes runtime जो Hermes के अपने installer द्वारा set up किया जाता है, जिसमें पहली बार कुछ मिनट लगते हैं। वह runtime वह एक Hermes है जिसका terminal `hermes` command, default agent और app सभी उपयोग करते हैं, और वह Omarchy release की प्रतीक्षा करने के बजाय `hermes update` के साथ स्वयं को update करता है। उसे install करने पर Hermes को `omarchy` नाम की skin के रूप में Omarchy theme भी मिलता है, जिसका प्रत्येक Hermes surface आपके themes बदलने पर पालन करता है; यदि आप नहीं चाहते कि ऐसा हो तो Hermes की Appearance settings के अंतर्गत या `/skin` के साथ कोई दूसरा चुनें, और Omarchy उस चुनाव को अकेला छोड़ देता है। _Remove > AI_ के अंतर्गत app को हटाने से पहले Hermes बंद हो जाता है, gateway समेत, वह runtime उसके साथ चला जाता है, और आपकी chats, memories, और वे skills रखी जाती हैं जो Hermes ने स्वयं के लिए लिखी थीं जब तक कि आप उसे अन्यथा न कहें: यह पूछता है, जिसमें default नहीं होता है, कि क्या वह data और आपकी connection settings भी जानी चाहिए।

OpenClaw का desktop अनुभव उसका Control UI है, जो अपने स्वयं के local gateway द्वारा समर्थित एक web app के रूप में खुलता है। OpenClaw `~/.openclaw` में रहता है और स्वयं को update करता है: Control UI के "Update Gateway" button का उपयोग करें या `openclaw update` चलाएँ, और gateway नए version पर restart हो जाता है। Omarchy केवल उस release को चुनता है जिससे कोई ताज़ा install शुरू होता है। _Remove > AI_ के अंतर्गत OpenClaw को हटाने से gateway service और app उसके साथ चले जाते हैं और फिर पूछा जाता है कि क्या `~/.openclaw` भी जाना चाहिए, क्योंकि उसमें OpenClaw स्वयं और उसके द्वारा download किए गए plugin runtimes के साथ आपकी chats और credentials होते हैं; default उसे रखता है, और OpenClaw को फिर से install करने पर वह उसे फिर से उठा लेता है।

T3 Code package से नहीं बल्कि `~/.local/share/t3code` में अपनी आधिकारिक AppImage release से चलता है, इसलिए वह स्वयं को update करता है। उसे install करने पर पूछा जाता है कि Stable या Nightly channel पर शुरू करना है; बाद में T3 Code की settings में switch करें। आपके threads और settings `~/.t3` में रहते हैं, और _Remove > AI_ के अंतर्गत T3 Code को हटाने से वे उसके साथ चले जाते हैं।

### स्थानीय models

अपने coding agents के लिए अपनी स्वयं की machine पर एक open model चलाएँ। आपके prompts और code machine पर रहते हैं; model को भेजा गया कुछ भी उसे नहीं छोड़ता है। इससे शुरू करें:

```bash
omarchy agent local use best
```

या, top bar में agents panel में, + और फिर Local AI चुनें, जो तब दिखाई देता है जब कोई model इस machine पर fit होता है। पहली बार, यह Podman install करता है, जो models चलाता है, और NVIDIA machine पर NVIDIA का container toolkit, जो उन्हें GPU देता है। फिर Omarchy इस machine के लिए अनुशंसित model चुनता है, उसे download करता है, और शुरू करता है। जब model चलता है तो tens of GB के download और machine की अधिकांश memory उपयोग में होने की अपेक्षा करें: Flash Next अपने पूर्ण 256K context के साथ लगभग 100 GiB का उपयोग करता है। यदि अन्य models को उसकी आवश्यक memory मिली हुई है, तो वह रुका हुआ set up होता है, जब आप किसी एक को रोकते हैं तो शुरू करने के लिए तैयार। Model logout पर रुक जाता है; जब आपको किसी और चीज़ के लिए memory की आवश्यकता हो तो उसे स्वयं रोकें।

`omarchy agent local list` विकल्प दिखाता है और बताता है कि कुछ fit क्यों नहीं होते। दूसरा set up करने के लिए, `omarchy agent local use <recipe>` चलाएँ। आज, `qwen3.8-flash-next-gufo` और `qwen3.8-27b-gufo` 128 GB Strix Halo machines के लिए उपलब्ध हैं; 27B लगभग 40 GiB लेता है, इसलिए वह अन्य कार्य के लिए जगह छोड़ता है। नई recipes और सिफ़ारिशें package के माध्यम से `omarchy update` के साथ आती हैं।

आपके द्वारा set up किया गया प्रत्येक model agents panel में, आपकी subscriptions के बगल में, अपनी line प्राप्त करता है: उसे शुरू करने के लिए play, उसे रोकने और उसकी memory मुक्त करने के लिए pause, और उस पर अपना agent खोलने के लिए terminal button। कई एक साथ चल सकते हैं जब वे memory में एक साथ fit होते हैं; यदि कोई fit नहीं होता, तो Omarchy बताता है कि किस चल रहे model को रोकना है। उन्हें फिर से क्रमबद्ध करने के लिए lines को drag करें, और किसी model और उसके download को हटाने के लिए चुनी गई line पर Delete दबाएँ।

Command line से, `omarchy agent local start <recipe>` और `omarchy agent local stop <recipe>` वही करते हैं, `omarchy agent local status` प्रत्येक model दिखाता है, और `omarchy agent --local` आपके default agent को आपके द्वारा शुरू किए गए अंतिम model पर खोलता है (pi यदि आपका default agent local model का उपयोग नहीं कर सकता)। कोई भी OpenAI-संगत client भी connect कर सकता है: `status` प्रत्येक model का address दिखाता है (पहला `http://127.0.0.1:11435/v1` है), recipe name ही model है, और key `~/.config/omarchy/agent-local/key` में है।

`omarchy agent local remove <recipe>` किसी model और उन downloads को delete करता है जिनका कोई अन्य model उपयोग नहीं करता है।

Third-party runtimes को उनके publisher के साथ labeled किया जाता है। Omarchy प्रत्येक model को बिना network access के चलाता है।

### स्थानीय LLMs

Omarchy स्थानीय LLM models चलाने के दो तरीके सुझाता है: LM Studio और Ollama। LM Studio open-weight models खोजने, उन्हें install करने, और उन्हें चलाने के लिए एक GUI interface प्रदान करता है। यह आसानी से शुरू करने का एक शानदार तरीका है। Ollama इसी तरह करने के लिए एक CLI प्रदान करता है। लेकिन यदि आप स्थानीय models के लिए नए हैं, तो मैं LM Studio से शुरू करूँगा। आप Omarchy Menu में _Install > AI_ के अंतर्गत दोनों में से किसी को भी install कर सकते हैं।

### Omarchy Skill

Agent skills AI को विशिष्ट tools का विशिष्ट तरीके से उपयोग करने में मदद करती हैं, और Omarchy system को अनुकूलित करने के लिए एक default skill के साथ आता है। जैसे आपकी Hyprland config को tweak करना, bar को adjust करना, या यहाँ तक कि शुरू से एक नई theme बनाना। यह Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` और प्रत्येक `~/.hermes/profiles/*/skills`), और generic `~/.agents/skills` स्थान के लिए skill directories में symlinked है, इसलिए अधिकांश harnesses उसे स्वचालित रूप से उठा लेते हैं।

लेकिन आपको इस skill को प्रयोगात्मक मानना चाहिए। विभिन्न models उसे विभिन्न प्रभाव के साथ उपयोग करेंगे। पहले उसे plan mode में चलाना सबसे अच्छा है, ताकि आपको अंदाज़ा हो कि agent क्या बदलना चाहेगा। और फिर changes को rollback करने या यहाँ तक कि `omarchy reinstall configs` को invoke करने के लिए तैयार रहें, यदि agent सब कुछ गड़बड़ कर दे।
