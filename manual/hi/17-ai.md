# AI

Omarchy नीचे दिए गए coding agents के लिए launchers शामिल करता है, बिना आपके लिए कोई default चुने। पहली बार उपयोग पर इसका CLI install करने के लिए कोई command चलाएँ, फिर संकेत मिलने पर authenticate करें। Hermes और OpenClaw अपवाद हैं: उनके लिए mise के माध्यम से कुछ भी install नहीं होता, और किसी एक को चुनने पर उसकी अपनी self-updating copy set up हो जाती है, जैसा कि नीचे _डेस्कटॉप ऐप्स_ में बताया गया है।

### एजेंटों को install और update करना

Hermes और OpenClaw को छोड़कर, ये agents mise की lazy installation का उपयोग करते हैं: पहली launch CLI को install करती है, और बाद की launches उसी का पुनः उपयोग करती हैं। mise किसी installed agent के लिए अधिकतम हर चार घंटे में एक बार नई release की जाँच भी करता है, ठीक उसके शुरू होने से पहले या background में shell prompt पर। यदि वह update विफल हो जाए या आप offline हों, तो installed version चलता है। `omarchy update` बाकी Omarchy के साथ installed agents को update करता है, और `mup` केवल mise-managed tools को update करता है।

किसी agent का अपना updater, जैसे `claude update`, `codex update`, या किसी app में update button, mise-managed install को update नहीं करता। `codex update` विफल हो जाता है, और `claude update` सफलता बता सकता है जबकि वह एक अलग copy install कर देता है जिसे mise track नहीं करता। यदि आप इसके बजाय किसी agent के native installer और updater का उपयोग करना पसंद करते हैं, तो उसे `disable_tools` में जोड़ें; देखें [पहले से install किए गए CLI tools](18-development-tools.md#preinstalled-cli-tools)।

आपको ज़रूरत पड़ने से पहले सभी configured lazy tools को install करने के लिए, `mise install --include-lazy` चलाएँ। इसमें agents के साथ-साथ Omarchy के अन्य default CLI tools भी शामिल हैं। किसी एक tool को install करने या अपनी खुद की installation का उपयोग करने के लिए देखें [पहले से install किए गए CLI tools](18-development-tools.md#preinstalled-cli-tools)।

`grok` mise के first-party `grok` package के माध्यम से install होता है, उसी तरह जैसे `claude` और `codex`। `grok` चलाएँ, या उसे _Agent > Harness_ के अंतर्गत चुनें। x.ai पर मौजूद `curl | bash` installer को छोड़ दें। वह तरीका `~/.grok/bin` में दूसरी copy डाल देता है, उसे `PATH` में आगे जोड़ देता है, और Omarchy के wrapper को overwrite कर देता है।

`dsh` अपना browser UI `127.0.0.1:3080` पर खोलता है, जिसमें launch directory उसका default workspace होता है। उसका browser UI कोई starting prompt नहीं लेता, इसलिए `omarchy agent prompt` उसे prompt को आपके clipboard पर रखकर खोलता है ताकि आप उसे paste कर सकें। Omarchy उसे DeepSeek के no-approval permission preset के साथ शुरू करता है। DeepSeek Harness session logs को DeepSeek पर upload करता है जब आप उसके official model API का उपयोग करते हैं; उसे उसके browser UI में _Settings > General > Upload Session Log_ के अंतर्गत बंद करें। आप उसे जो feedback भेजते हैं वह भी session के साथ upload होता है, जब तक आप उसे `DSH_TELEMETRY_MODE=DISABLED` के साथ शुरू न करें।

### default agent

अपना default agent `omarchy default agent <name>` से या Omarchy Menu (`Super + Space`) में _Agent > Harness_ के अंतर्गत चुनें। यदि agent अभी install नहीं हुआ है, तो उसे चुनने पर वह पहले install होता है, और उसे app launcher में Agent के बगल में अपना खुद का launcher भी मिलता है। नया Omarchy आपको एक बार दिखने वाली notification के साथ यह चुनाव करने के लिए आमंत्रित करेगा।

Claude चुनने पर Chromium, Chrome, Brave, Brave Origin, और Edge के लिए उसके browser extension को set up करने का प्रयास भी होता है। extension setup सभी users पर लागू होता है और आपसे आपका system password माँग सकता है; extension install को रद्द करने या उसके विफल होने पर भी Claude चुना और launch किया जाता है। अपना browser restart करें, संकेत मिलने पर extension enable करें, और उसे connect करने की प्रक्रिया पूरी करने के लिए Claude में sign in करें। connection जाँचने के लिए Claude में `/chrome` चलाएँ। Firefox और Zen इस extension का समर्थन नहीं करते। यदि यह setup जोड़े जाने से पहले Claude पहले से ही आपका default था, तो extension install करने के लिए उसे फिर से चुनें।

एक बार चुन लेने के बाद, `Super + Shift + Ctrl + A` default agent को एक समर्पित terminal window में launch करता है (या यदि आपने अभी तक नहीं चुना है तो picker सामने लाता है)। आप उसे `omarchy agent prompt "Review this project"` के साथ सीधे किसी कार्य में भी launch कर सकते हैं। Freebuff और DeepSeek Harness कोई starting prompt नहीं लेते, इसलिए वे इसके बजाय prompt को आपके clipboard पर रखकर खुलते हैं ताकि आप उसे paste कर सकें। इस तरह launch किए गए agents अपने-अपने don't-stop-to-ask modes में बिना रुके चलते हैं, इसलिए तैयार रहें कि वे वास्तव में कुछ करेंगे! MiniMax Code के पास उसके interactive sessions के लिए ऐसा कोई mode नहीं है, इसलिए वह हमेशा की तरह permissions माँगता है। और चूँकि agents आपकी home directory के लिए trust याद रखने से इनकार करते हैं, इसलिए `$HOME` से launches इसके बजाय `~/Work` में शुरू होते हैं।

terminal shortcuts भी हैं: `a` current terminal में default agent को inline चलाता है, जबकि `c`, `cx`, और `cy` OpenCode, Claude Code, और Codex को सीधे शुरू करते हैं (फिर से उनके auto-approving modes में)। Theme बदलाव agents के साथ भी sync होते हैं: Claude Code, Pi, OpenCode, और Hermes (एक बार Omarchy ने उसे install कर दिया हो) सभी तब साथ बदलते हैं जब आप Omarchy theme बदलते हैं।

### आपके agent निर्देश

हर agent के लिए व्यक्तिगत नियम `~/.agents/AGENTS.md` में जाते हैं, साझा skills के बगल में `~/.agents/skills` में। उसे _Agent > Instructions_ के अंतर्गत खोलें, जो उसे प्रत्येक उस harness में भी link करता है जो अपनी खुद की global file रखता है: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, Copilot का `~/.copilot/copilot-instructions.md`, और इसी तरह अन्य। Crush और Amp `~/.config/AGENTS.md` link को पढ़ते हैं, जबकि omp, Kimi, और DeepSeek Harness `~/.agents/AGENTS.md` को सीधे पढ़ते हैं। default agent चुनने पर वह भी link हो जाता है। आपके पास पहले से मौजूद कोई instructions file साझा वाली बन जाती है यदि अभी तक कोई नहीं थी; अन्यथा उसे link के बगल में `.bak` के रूप में रखा जाता है। किसी अन्य agent को install करने के बाद फिर से link करने के लिए `omarchy agent instructions` चलाएँ।

### agents panel

top bar में एक agents icon है। इससे पहले कि आपने कोई agent set up किया हो, उसका panel आपको Claude, Codex, या Grok में sign in करने की प्रक्रिया से ले जाता है, और पहला वाला आपका default agent बन जाता है। उसके बाद, panel हर subscription को एक ही page पर रखता है: प्रत्येक agent और account उसके plan के साथ, उसके 5-hour session और weekly limits में से प्रत्येक के लिए एक meter के साथ reset होने तक के समय के साथ (सटीक percentage के लिए hover करें), या शेष prepaid balance के साथ, एक line के नीचे जो उन सभी में आपके उपयोग के बीच rotate होती रहती है, जैसे इस सप्ताह के tokens और आपका सबसे अधिक उपयोग किया गया model। _Make something cool_ के अंतर्गत यह नई theme, plugin, app, या game के लिए starter prompts देता है जो कार्य आपके default agent को सौंप देते हैं। Apps उसी तरह बनाई जाती हैं जैसे Omarchy की अपनी Hype, Monologue, और Omacut हैं, C++ और Qt Quick में, omarchy-make-app agent skill का पालन करते हुए, और उन्हें जिन compiler और Qt pieces की ज़रूरत होती है वे installed आते हैं। Games `~/Games/vibes` में एक single three.js page होती हैं, omarchy-make-game agent skill का पालन करते हुए, और सभी current theme में एक Game Vibes launcher से खुलती हैं; वे web से three.js load करती हैं, इसलिए उन्हें शुरू होने के लिए connection की ज़रूरत होती है। Claude Code, Codex, Grok, Kimi, Cursor और उसकी Grok Bot allowance, GitHub Copilot, Muse, Antigravity, और Devin अपनी limits के साथ out of the box शामिल हैं, Kimchi अपने plan, prepaid credits, और spend budgets के साथ, और Hermes, Mistral Vibe, और Qwen Code एक बार आपके द्वारा उनका उपयोग करने के बाद अपने sessions और tokens दिखाते हैं। pi, omp, या opencode के माध्यम से आप जिन provider plans और keys का उपयोग करते हैं वे भी दिखाई देते हैं: OpenCode Zen और Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan, और Synthetic अपनी limits के साथ; OpenRouter और DeepSeek अपने prepaid balances के साथ; Fireworks पिछले 30 दिनों में अपने spend के साथ। आपके अपने hardware पर चलाए जाने वाले models के tokens भी totals में गिने जाते हैं; models का खुद का अपना एक panel होता है, जिसका वर्णन [स्थानीय models](#local-models) के अंतर्गत किया गया है। हर agent को एक बार गिना जाता है, उसी के अंतर्गत जो उसे bill करता है, चाहे आप उसे कितने ही harnesses के माध्यम से चलाएँ।

bar icon पर Left-click करें या panel के लिए `Super + Ctrl + X` दबाएँ, अपने default agent को launch करने के लिए right-click करें, और refresh करने के लिए middle-click करें। इसके पीछे के usage records हर 15 मिनट में `omarchy agent usage update` द्वारा regenerate होते हैं, और panel synced folder के माध्यम से आपकी अन्य machines से usage को merge भी कर सकता है। पूरी settings के लिए `$OMARCHY_PATH/shell/plugins/agents/` के अंतर्गत README देखें।

### कई subscriptions

यदि आप एक से अधिक Claude, Codex, या Grok plan के लिए भुगतान करते हैं — मान लें एक personal Max और एक work वाला — तो Omarchy उन सभी को signed in रख सकता है और उनके बीच आवागमन कर सकता है। agents panel में + के साथ एक subscription जोड़ें, जो आपको वहीं उस प्रक्रिया से ले जाता है, या `omarchy agent account add claude Work` (या `codex`, या `grok`) के साथ। यदि CLI मौजूद नहीं है तो यह उसे install करता है। किसी provider के लिए पहला account आपके normal browser के माध्यम से sign in करता है, ठीक वहीं जहाँ CLI हमेशा देखता है। उसके बाद का हर account private window के माध्यम से sign in करता है, ताकि जिस account में आपका browser पहले से signed in है वह गलती से न चुन लिया जाए; वहाँ उस account के रूप में sign in करें जिसे आप जोड़ रहे हैं, और पहले से खुली किसी भी private window को पहले बंद कर दें। ऐसा करने के लिए CLI से कभी log out न करें: log out करने से saved sign-in रद्द हो जाता है, और उस account को फिर से जोड़ना पड़ेगा।

अपनी subscription logins को SSH पर किसी अन्य Omarchy machine पर copy करने के लिए, `omarchy agent account copy user@laptop` चलाएँ। जब destination के पास कोई installed receiver नहीं होता तो sender एक temporary receiver देता है, ताकि पुरानी Omarchy machines बिना update के accounts प्राप्त कर सकें। Installed receivers को प्राथमिकता मिलती है। यह सभी Claude, Codex, और Grok subscriptions को copy करता है; उन्हें चुनने के लिए provider names जोड़ें, जैसे `omarchy agent account copy laptop claude` में। Account names और command IDs source से मेल खाते हैं, destination पर पहले से मौजूद accounts समेत। असंबंधित destination accounts को numeric suffix मिलता है यदि उनके नाम टकराते हैं, और settings, skills, plugins, और conversation history प्रत्येक machine पर स्थानीय रहती हैं।

मौजूदा destination credentials रखे जाते हैं। वहाँ पहले से signed in किसी source account का नाम उसके credentials को बदले बिना synchronize किया जाता है; अन्य accounts उसके साथ जोड़े जाते हैं। मेल खाते accounts के लिए saved credentials को बदलने के लिए, destination पर उस account के sessions छोड़ने के बाद `omarchy agent account copy --replace laptop claude` का उपयोग करें। नया destination source का active account और switching preferences भी पाता है; स्थापित destination अपनी preferences रखता है।

Credentials SSH के माध्यम से यात्रा करते हैं और destination पर private files में संग्रहीत होते हैं, इसलिए केवल उन machines पर copy करें जिन पर आप भरोसा करते हैं। यह एक बार की copy है, निरंतर synchronization नहीं। Codex refresh tokens किसी अन्य machine द्वारा rotate किए जा सकते हैं, जिससे copied login को renewal की ज़रूरत पड़ सकती है; कई machines पर एक साथ उपयोग के लिए अलग-अलग sign-ins सबसे विश्वसनीय विकल्प बने रहते हैं। देखें [Codex का account authentication मार्गदर्शन](https://developers.openai.com/codex/auth/ci-cd-auth)।

प्रति provider एक account सक्रिय होता है, और हर नया session उसी के रूप में शुरू होता है: `cx`, `cy`, एक सादा `claude`, `codex`, या `grok`, `omarchy agent` के माध्यम से launch की गई कोई भी चीज़, और scripts या editors जो CLI को `PATH` पर पाते हैं। `omarchy agent account use work` से switch करें (और `omarchy agent account use main` से वापस), या panel में किसी account की संख्या दबाकर फिर `Enter` दबाकर (या उसके Use button पर click करके)। चल रहे Claude sessions भी, उनके अगले message से switch होते हैं: हर Claude session `~/.claude` में चलता है, जिसमें हमेशा active account का sign-in होता है। पुराने Omarchy द्वारा किसी account के अपने folder में शुरू किया गया Claude session उस sign-in को तब तक रखता है जब तक वह बंद न हो, इसलिए switch उन sessions के नाम बताता है और उनके चले जाने पर अपने आप पूरा हो जाता है। चल रहे Codex और Grok sessions उस account पर रहते हैं जिसके साथ वे शुरू हुए थे। Conversation history, settings, skills, और plugins accounts के बीच साझा होते हैं, इसलिए उसी folder में `claude --continue` नए account पर वहाँ से आगे बढ़ता है जहाँ आपने छोड़ा था।

एक से अधिक account के साथ, panel प्रत्येक account की limits को side by side दिखाता है, जिसमें active एक चिह्नित होता है। By default Omarchy आपको तब सूचित करता है जब active account किसी limit के 95% को पार कर जाता है, और notification पर click करने से सबसे अधिक headroom वाले account पर switch हो जाता है। panel में किसी account की line पर hover करें और Use के बगल में दिखाई देने वाले Autoswitch पर click करें (या `m` दबाएँ), या `omarchy agent account mode auto` चलाएँ, ताकि वह अपने आप switch हो; जबकि यह चालू है, Autoswitch Use की जगह ले लेता है, और उसे फिर से click करने से सूचित करने पर वापस आ जाता है। threshold बदलने के लिए एक संख्या जोड़ें, जैसे `omarchy agent account mode auto 90` में। यदि हर account threshold से ऊपर है, तो आपको एक बार इसके बारे में सुनने को मिलेगा, साथ ही यह भी कि कौन-सा account सबसे पहले मुक्त होता है। जब कोई active account अपने threshold के 15 points के भीतर होता है (default पर 80%), तो उसकी limits हर 15 की बजाय हर तीन मिनट में जाँची जाती हैं।

`omarchy agent account list` हर account और उसकी नवीनतम limits दिखाता है, `omarchy agent account remove work` एक को भुला देता है, और `omarchy agent account rename primary Hey` एक का नाम बदलता है (या panel में किसी account के नाम पर click करें)। ये commands आपके default agent के accounts पर काम करते हैं; दूसरे provider तक पहुँचने के लिए, पहले उसका नाम लें, जैसे `omarchy agent account use codex side` में। `~/.claude` या `~/.codex` में आपके पास पहले से मौजूद login _Main_ account है। Codex का वहीं रहता है जहाँ वह है; Claude का जब कोई अन्य account सक्रिय होता है तो अपने खुद के folder में प्रतीक्षा करता है। लगभग आठ घंटे से अधिक समय तक अप्रयुक्त छोड़ा गया account _Sign-in required_ दिखा सकता है; panel में ही उस account को फिर से sign in करने के लिए उस पर click करें, या उस पर switch करके एक session शुरू करें, जो sign-in को अपने आप refresh करता है। आप `claude mcp add` के साथ जो MCP servers जोड़ते हैं वे हर Claude account तक पहुँचते हैं, क्योंकि वे सभी `~/.claude` में चलते हैं; Codex और Grok के लिए, किसी account को जोड़े जाने के समय आपके पास मौजूद servers उसके साथ आते हैं, लेकिन बाद वाले केवल उस account तक पहुँचते हैं जिसमें आपने उन्हें जोड़ा था। Claude Desktop अपना खुद का sign-in रखता है, और CLI binary के absolute path के साथ configure किए गए Codex या Grok tools switch का पालन नहीं करते। स्पष्ट `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, या `GROK_HOME` चुने गए account पर प्राथमिकता लेता है।

### crash का निदान

Omarchy process crashes के लिए systemd-coredump को देखता है। एक बार आपने default agent चुन लिया, तो आपका कोई भी program जो core dump करता है एक "Process crashed" notification लाता है — उस पर click करें, और crash आपके default agent को Omarchy के omarchy-diagnose-crash skill के साथ सौंप दिया जाता है, जो agent को core dump से तथ्य स्थापित करने और यह तय करने की प्रक्रिया से ले जाता है कि क्या crash upstream report करने योग्य है। आप उसे `coredumpctl list` से किसी भी PID के विरुद्ध `omarchy agent crash <pid>` के साथ हाथ से भी चला सकते हैं।

यह देखना by default चालू है। उसे _Trigger > Toggle > Crash Capture Off_ के अंतर्गत (या `omarchy toggle crash-capture` के साथ) बंद करें और notifications बंद हो जाती हैं; `omarchy agent crash <pid>` फिर भी हाथ से काम करता है।

Crashes को एक बार में एक program के हिसाब से भी शांत किया जा सकता है, जो निदान आपको अंत में देता है। `omarchy crash mute hyprland` केवल उस program के लिए notifications रोकता है, `omarchy crash mute hyprland off` उन्हें वापस लाता है, और `omarchy crash mute` अपने आप में वह सूची देता है जो आपने mute किया है। यह binary के path को उसके नाम की तरह ही खुशी से लेता है, इसलिए `omarchy crash mute /usr/bin/hyprland` वही काम करता है। किसी ऐसे नाम को quote करें जिसमें space हो, जैसे `omarchy crash mute 'Some App'` में। बाकी सब कुछ फिर भी सूचित करता है, और muted program फिर भी crash होता है — यह reminder को छिपाता है, यह कुछ ठीक नहीं करता।

### डेस्कटॉप ऐप्स

_Install > AI_ menu कुछ graphical AI apps भी रखता है: Amp Desktop, Antigravity Desktop, ChatGPT desktop app, Claude desktop app (Anthropic का Linux beta, Chat, Cowork, और Claude Code tabs के साथ), xAI के models से chat करने के लिए Grok Bot, Herdr Desktop, Hermes Desktop, OpenClaw, Perplexity desktop app, और T3 Code। Grok Bot desktop chat app है। coding agent `grok` command है।

Hermes Desktop वह है जिसके बारे में जानना ज़रूरी है, क्योंकि किसी machine के पास एक Hermes होता है, और वह app का होता है: Hermes हमेशा केवल app के माध्यम से install होता है, और default agent जो `hermes` command चलाता है वह app का ही होता है। Hermes को default agent के रूप में चुनना वही चीज़ install करता है जो _Install > AI_ entry करती है: package, और Hermes के अपने installer द्वारा set up किया गया `~/.hermes` के अंतर्गत एक Hermes runtime, जिसमें पहली बार कुछ मिनट लगते हैं। वह runtime वही एक Hermes है जिसका terminal `hermes` command, default agent और app सभी उपयोग करते हैं, और वह Omarchy release की प्रतीक्षा करने के बजाय `hermes update` से खुद को update करता है। उसे install करना Hermes को Omarchy theme को `omarchy` नामक skin के रूप में भी देता है, जिसका हर Hermes surface आपके theme बदलने के साथ पालन करता है; यदि आप नहीं चाहते कि वह ऐसा करे तो Hermes की Appearance settings के अंतर्गत या `/skin` से कोई अन्य चुनें, और Omarchy उस चुनाव को अकेला छोड़ देता है। _Remove > AI_ के अंतर्गत app को हटाना पहले Hermes को बंद करता है, gateway समेत, उस runtime को अपने साथ ले जाता है, और आपकी chats, memories, और वे skills रखता है जो Hermes ने अपने लिए लिखी थीं जब तक आप उसे अन्यथा न कहें: यह पूछता है, default no रखते हुए, कि क्या वह data और आपकी connection settings भी जानी चाहिए।

OpenClaw का desktop अनुभव उसका Control UI है, जो अपने खुद के local gateway द्वारा समर्थित web app के रूप में खुलता है। OpenClaw `~/.openclaw` में रहता है और खुद को update करता है: Control UI के "Update Gateway" button का उपयोग करें या `openclaw update` चलाएँ, और gateway नए version पर restart होता है। Omarchy केवल वह release चुनता है जिससे कोई नया install शुरू होता है। OpenClaw आपका default agent भी हो सकता है: उसे _Agent > Harness_ के अंतर्गत चुनना `~/.openclaw` में उसी copy को set up करता है, और agent OpenClaw के terminal UI को उसके gateway से attached खोलता है। _Remove > AI_ के अंतर्गत OpenClaw को हटाना gateway service और app को अपने साथ ले जाता है और फिर पूछता है कि क्या `~/.openclaw` भी जाना चाहिए, क्योंकि उसमें OpenClaw खुद और उसके द्वारा download किए गए plugin runtimes के साथ आपकी chats और credentials होते हैं; default उसे रखता है, और OpenClaw को फिर से install करना उसे वापस ले लेता है।

Herdr Desktop [Herdr](https://herdr.dev) desktop app है: spaces, tabs, और terminals और coding agents के panes जो window बंद करने पर उसके core में चलते रहते हैं। यह package के बजाय Herdr के अपने installer से आता है, इसलिए यह `~/.local/share/herdr-app` में रहता है, जब आपके पास पहले से कोई नहीं होता तो `~/.local/bin/herdr-core` में अपना core साथ लाता है, और दोनों खुद को update करते हैं। यह उस `herdr` command के बगल में बैठता है जो Omarchy `Super + Ctrl + Return` पर देता है, उसे बदलने के बजाय, और उस command की direct keys पाता है: `Alt + Return` और `Alt + Shift + Return` किसी pane को नीचे या दाएँ split करते हैं, `Alt + Escape` उसे बंद करता है, `Ctrl + Alt + Arrow` panes के बीच जाता है, `Alt + 1..9` और `Alt + Left/Right` कोई tab चुनते हैं, और `Alt + Up/Down` spaces के बीच जाते हैं। `Ctrl + 1..9` कोई space चुनता है और `Alt + Shift + Up/Down` agents के बीच कदम बढ़ाता है। `Ctrl + Space` prefix keys केवल terminal के लिए रहती हैं, क्योंकि app किसी sequence के लिए सादा Ctrl key नहीं पकड़ सकता। Omarchy इन्हें `~/.config/herdr-app/keys.json` में लिखता है, और `omarchy-refresh-herdr-app` उन्हें वापस रखता है। उसे install करना Herdr की Omarchy theme चुनता है, जो उसके बाद से आपकी Omarchy theme का पालन करती है। Herdr light mode के लिए एक theme और dark के लिए एक theme रखता है, इसलिए dark और light Omarchy theme के बीच switch करने के बाद, दूसरे mode के लिए Herdr के theme picker में Omarchy को एक बार फिर चुनें।

T3 Code package के बजाय `~/.local/share/t3code` में अपने official AppImage release से चलता है, इसलिए वह खुद को update करता है। उसे install करना पूछता है कि Stable या Nightly channel पर शुरू करना है; बाद में T3 Code की settings में switch करें। आपकी threads और settings `~/.t3` में रहती हैं, और _Remove > AI_ के अंतर्गत T3 Code को हटाना उन्हें अपने साथ ले जाता है।

### स्थानीय models

अपने coding agents के लिए अपने खुद के machine पर कोई open model चलाएँ। आपके prompts और code machine पर रहते हैं; model को भेजा गया कुछ भी उसे नहीं छोड़ता। इससे शुरू करें:

```bash
omarchy models use best text
```

यह इस machine के लिए सबसे अच्छा text model set up करता है, उसी प्रकार का जिसका आपके agents उपयोग करते हैं। Image, video और music models का अपना-अपना सबसे अच्छा होता है: `omarchy models use best image`, `video` या `music`। प्रत्येक प्रकार की इस machine के लिए पसंद देखने के लिए `omarchy models use best` चलाएँ।

या top bar में agents icon के बगल में उसके sparkles icon से, या Super + Ctrl + Alt + X के साथ local models panel खोलें, और + चुनें। icon तब दिखाई देता है जब कोई model इस machine पर fit होता है। Podman, जो models चलाता है, Omarchy के साथ आता है, NVIDIA machine पर NVIDIA का container toolkit भी, जो उन्हें GPU देता है; यदि दोनों में से कोई मौजूद नहीं है, तो पहला setup उसे install करता है। फिर Omarchy इस machine के लिए recommended model चुनता है, उसे download करता है, और शुरू करता है। tens of GB के download की अपेक्षा करें और जब model चलता है तो machine की अधिकांश memory उपयोग में रहेगी: Flash Next अपने पूरे 256K context के साथ लगभग 100 GiB उपयोग करता है। यदि अन्य models वह memory रखे हैं जिसकी उसे ज़रूरत है, तो वह stopped set up होता है, एक बार आपके द्वारा एक को रोकने पर शुरू होने के लिए तैयार। model logout पर रुक जाता है; जब आपको किसी अन्य चीज़ के लिए memory चाहिए तो उसे खुद रोकें।

`omarchy models list` options दिखाता है और बताता है कि कुछ क्यों fit नहीं होते। किसी अन्य को set up करने के लिए, `omarchy models use <recipe>` चलाएँ। आज, 128 GB Strix Halo machines के लिए `qwen3.8-flash-next-gufo` और `qwen3.8-27b-gufo` उपलब्ध हैं; 27B लगभग 40 GiB लेता है, इसलिए वह अन्य काम के लिए जगह छोड़ता है। Intel के Arc B390 वाले 64 GB laptop पर, `qwen3.6-35b-a3b-llamacpp` लगभग 30 GiB में चलता है। नई recipes और recommendations package के माध्यम से `omarchy update` के साथ आती हैं।

आपके द्वारा set up किया गया हर model local models panel में अपनी खुद की line पाता है: उसे शुरू करने के लिए play, उसे रोकने और उसकी memory मुक्त करने के लिए pause, और उस पर अपना agent खोलने के लिए terminal button। ऊपर के पार, एक bar दिखाता है कि machine की memory Omarchy खुद (system और आपके apps), प्रत्येक चल रहे model, और जो मुक्त है, के बीच कैसे विभाजित है। किसी stopped model की ओर संकेत करें और bar दिखाता है कि वह fit होता है या नहीं, या वह कितना कम है। कई एक साथ चल सकते हैं जब वे memory में एक साथ fit होते हैं; यदि कोई fit नहीं होता, तो Omarchy बताता है कि किस चल रहे model को रोकना है। उन्हें reorder करने के लिए lines को उनके logo से drag करें, और किसी model और उसके download को हटाने के लिए चुनी गई line पर Delete दबाएँ।

आपके द्वारा set up किया गया हर model app launcher में भी अपनी खुद की entry पाता है, model के नाम के अंतर्गत और उसके maker के logo के साथ, उसी तरह जैसे Claude, Codex या Grok में sign in करना एक जोड़ता है। यह उस model पर आपका agent खोलता है, और यदि वह नहीं चल रहा है तो पहले model शुरू करता है: terminal उसे loading दिखाता है और वह तैयार होने पर agent को सौंप देता है। किसी model को हटाना उसकी entry हटा देता है।

हर model coding के लिए नहीं है। Image, video और music models इसके बजाय Fantasi में खुलते हैं, Omarchy का इस machine पर चल रहे model के साथ pictures, video और music बनाने का app, उनकी launcher entry से और local models panel में उनकी line से।

कोई model ठीक उसी तरह चलता रहता है जैसे वह set up किया गया था, इसलिए Omarchy update कभी आपके agents के नीचे उसे restart नहीं करता। जब Omarchy के पास आपके द्वारा set up किए गए model के लिए नया runtime या नए weights होते हैं, तो उसकी line एक update button दिखाती है: उसे दबाएँ और model background में फिर से set up होता है, केवल वही download करता है जो बदला है, और नए version पर restart होता है। जो model रुका हुआ था वह रुका रहता है। `omarchy models update` terminal से हर model के लिए वही करता है।

command line से, `omarchy models start <recipe>` और `omarchy models stop <recipe>` वही करते हैं, `omarchy models status` हर model दिखाता है, और `omarchy agent --local` आपके द्वारा शुरू किए गए अंतिम model पर आपका default agent खोलता है। pi, OpenCode और Qwen Code एक का उपयोग कर सकते हैं; किसी अन्य default के साथ यह pi में खुलता है, या OpenCode में यदि आपके पास pi नहीं है। pi आपके द्वारा set up किए गए हर model को, और उन machines पर मौजूद models को जिनके साथ आपने pair किया है, अपने खुद के model picker में भी सूचीबद्ध करता है, इसलिए सादा `pi` भी उन तक पहुँचता है। कोई भी OpenAI-compatible client भी connect कर सकता है: `status` प्रत्येक model का address दिखाता है (पहला `http://127.0.0.1:11435/v1` है), recipe name model है, और key `~/.config/omarchy/agent-local/key` में है।

`omarchy models remove <recipe>` किसी model और उन downloads को delete करता है जिनका कोई अन्य model उपयोग नहीं करता।

Third-party runtimes को उनके publisher के साथ label किया जाता है। Omarchy हर model को बिना network access के चलाता है।

### स्थानीय LLMs

Omarchy local LLM models चलाने के दो तरीके सुझाता है: LM Studio और Ollama। LM Studio open-weight models खोजने, उन्हें install करने, और उन्हें चलाने के लिए GUI interface देता है। आसानी से शुरू करने का यह बढ़िया तरीका है। Ollama ऐसा ही करने के लिए CLI देता है। लेकिन यदि आप local models में नए हैं, तो मैं LM Studio से शुरू करूँगा। आप दोनों में से किसी को भी Omarchy Menu में _Install > AI_ के अंतर्गत install कर सकते हैं।

### Omarchy skills

Agent skills AI को विशिष्ट tools का विशिष्ट तरीके से उपयोग करने में मदद करते हैं, और Omarchy उनमें से सात देता है। omarchy skill system को अनुकूल बनाने को cover करता है, जैसे आपकी Hyprland config को tweak करना या bar को adjust करना। omarchy-make-theme, omarchy-make-plugin, omarchy-make-app, और omarchy-make-game कुछ नया बनाने को cover करते हैं, omarchy-contribute bug report करने या upstream fix भेजने को cover करता है, और omarchy-diagnose-crash किसी crash के core dump पर काम करता है। वे Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` और प्रत्येक `~/.hermes/profiles/*/skills`), और generic `~/.agents/skills` location के लिए skill directories में symlinked हैं, इसलिए अधिकांश harnesses उन्हें अपने आप ले लेते हैं। समान नाम वाला आपका खुद का skill folder प्राथमिकता लेता है।

लेकिन आपको इन skills को experimental मानना चाहिए। अलग-अलग models इसे अलग-अलग प्रभाव से उपयोग करेंगे। पहले plan mode में चलाना सबसे अच्छा है, ताकि आपको अंदाज़ा हो कि agent क्या बदलना चाहेगा। और फिर बदलावों को rollback करने या यहाँ तक कि `omarchy reinstall configs` चलाने के लिए तैयार रहें, यदि agent सब कुछ गड़बड़ कर दे।
