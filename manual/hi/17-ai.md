### एजेंट इंस्टॉल और अपडेट करना

Hermes को छोड़कर, ये एजेंट mise की lazy इंस्टॉलेशन का उपयोग करते हैं: पहली बार लॉन्च करने पर CLI इंस्टॉल होता है, और बाद के लॉन्च उसी का पुनः उपयोग करते हैं। mise किसी इंस्टॉल किए गए एजेंट के लिए नए रिलीज़ की जाँच अधिकतम हर चार घंटे में एक बार करता है, शुरू होने से ठीक पहले या shell prompt पर पृष्ठभूमि में। यदि वह अपडेट विफल हो जाए या आप ऑफ़लाइन हों, तो इंस्टॉल किया गया संस्करण चलता है। `omarchy update` बाकी Omarchy के साथ इंस्टॉल किए गए एजेंट को अपडेट करता है, और `mup` केवल mise-प्रबंधित टूल को अपडेट करता है।

किसी एजेंट का अपना अपडेटर, जैसे `claude update`, `codex update`, या किसी ऐप में अपडेट बटन, mise-प्रबंधित इंस्टॉल को अपडेट नहीं करता। `codex update` विफल हो जाता है, और `claude update` सफलता की रिपोर्ट करते हुए एक अलग प्रति इंस्टॉल कर सकता है जिसे mise ट्रैक नहीं करता। यदि आप इसके बजाय किसी एजेंट के मूल इंस्टॉलर और अपडेटर का उपयोग करना पसंद करते हैं, तो उसे `disable_tools` में जोड़ें; देखें [पहले से इंस्टॉल किए गए CLI टूल](18-development-tools.md#preinstalled-cli-tools)।

ज़रूरत पड़ने से पहले सभी कॉन्फ़िगर किए गए lazy टूल इंस्टॉल करने के लिए, `mise install --include-lazy` चलाएँ। इसमें एजेंट के साथ-साथ Omarchy के अन्य डिफ़ॉल्ट CLI टूल भी शामिल हैं। एकल टूल इंस्टॉल करने या अपने स्वयं के इंस्टॉलेशन का उपयोग करने के लिए देखें [पहले से इंस्टॉल किए गए CLI टूल](18-development-tools.md#preinstalled-cli-tools)।

`grok` mise के first-party `grok` पैकेज के माध्यम से इंस्टॉल होता है, उसी तरह जैसे `claude` और `codex`। `grok` चलाएँ, या उसे _Agent > Harness_ के अंतर्गत चुनें। x.ai पर `curl | bash` इंस्टॉलर को छोड़ दें। वह तरीका `~/.grok/bin` में दूसरी प्रति रखता है, उसे `PATH` में सबसे आगे जोड़ता है, और Omarchy के wrapper को अधिलेखित कर देता है।

`dsh` अपना browser UI `127.0.0.1:3080` पर खोलता है, जिसमें लॉन्च डायरेक्टरी उसका डिफ़ॉल्ट workspace होती है। उसका browser UI कोई शुरुआती prompt नहीं लेता, इसलिए `omarchy agent prompt` उसे आपके clipboard पर prompt के साथ खोलता है जिसे आप paste कर सकें। Omarchy उसे DeepSeek के no-approval permission preset के साथ शुरू करता है। जब आप उसके आधिकारिक model API का उपयोग करते हैं तो DeepSeek Harness session log DeepSeek को अपलोड करता है; उसे उसके browser UI में _Settings > General > Upload Session Log_ के अंतर्गत बंद कर दें। आप उसे जो feedback भेजते हैं वह भी session के साथ अपलोड होता है, जब तक कि आप उसे `DSH_TELEMETRY_MODE=DISABLED` के साथ शुरू न करें।

### डिफ़ॉल्ट एजेंट

`omarchy default agent <name>` से या Omarchy Menu (`Super + Space`) में _Agent > Harness_ के अंतर्गत अपना डिफ़ॉल्ट एजेंट चुनें। यदि एजेंट अभी तक इंस्टॉल नहीं हुआ है, तो उसे चुनने पर वह पहले इंस्टॉल हो जाता है। नया Omarchy एक बार की सूचना के साथ आपको यह चुनाव करने के लिए आमंत्रित करेगा।

Claude चुनने पर Chromium, Chrome, Brave, Brave Origin, और Edge के लिए उसके browser extension को सेट अप करने का प्रयास भी होता है। extension सेटअप सभी उपयोगकर्ताओं पर लागू होता है और आपका system password माँग सकता है; extension इंस्टॉल रद्द करने या विफल होने पर भी Claude चुना और लॉन्च किया जाता है। अपना browser पुनः शुरू करें, संकेत मिलने पर extension सक्षम करें, और उसे जोड़ना पूरा करने के लिए Claude में sign in करें। कनेक्शन जाँचने के लिए Claude में `/chrome` चलाएँ। Firefox और Zen इस extension का समर्थन नहीं करते। यदि यह सेटअप जोड़े जाने से पहले ही Claude आपका डिफ़ॉल्ट था, तो extension इंस्टॉल करने के लिए उसे फिर से चुनें।

एक बार चुन लेने के बाद, `Super + Shift + Ctrl + A` डिफ़ॉल्ट एजेंट को एक समर्पित terminal window में लॉन्च करता है (या यदि आपने अभी तक नहीं चुना है तो picker सामने लाता है)। आप `omarchy agent prompt "Review this project"` के साथ उसे सीधे किसी कार्य में भी लॉन्च कर सकते हैं। Freebuff और DeepSeek Harness कोई शुरुआती prompt नहीं लेते, इसलिए वे इसके बजाय आपके clipboard पर prompt के साथ खुलते हैं जिसे आप paste कर सकें। इस तरह लॉन्च किए गए एजेंट अपने-अपने don't-stop-to-ask मोड में बिना निगरानी के चलते हैं, इसलिए तैयार रहें कि वे वास्तव में कुछ करेंगे! MiniMax Code के पास उसके interactive session के लिए ऐसा कोई मोड नहीं है, इसलिए वह हमेशा की तरह अनुमतियाँ माँगता है। और चूँकि एजेंट आपकी home directory के लिए trust याद रखने से इनकार करते हैं, इसलिए `$HOME` से लॉन्च `~/Work` में शुरू होते हैं।

terminal shortcut भी हैं: `a` वर्तमान terminal में डिफ़ॉल्ट एजेंट को inline चलाता है, जबकि `c`, `cx`, और `cy` OpenCode, Claude Code, और Codex को सीधे शुरू करते हैं (फिर से उनके auto-approving मोड में)। Theme बदलाव एजेंट के साथ भी sync होते हैं: जब आप Omarchy theme बदलते हैं तो Claude Code, Pi, OpenCode, और Hermes (एक बार Omarchy ने उसे इंस्टॉल कर दिया हो) सभी साथ चलते हैं।

### आपके एजेंट निर्देश

हर एजेंट के लिए व्यक्तिगत नियम `~/.agents/AGENTS.md` में जाते हैं, `~/.agents/skills` में साझा skills के बगल में। उसे _Agent > Instructions_ के अंतर्गत खोलें, जो उसे हर उस harness में भी लिंक करता है जो अपनी स्वयं की global फ़ाइल रखता है: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, Copilot की `~/.copilot/copilot-instructions.md`, और इसी तरह अन्य। Crush और Amp `~/.config/AGENTS.md` लिंक पढ़ते हैं, जबकि omp, Kimi, और DeepSeek Harness `~/.agents/AGENTS.md` को सीधे पढ़ते हैं। डिफ़ॉल्ट एजेंट चुनने पर वह भी लिंक हो जाता है। आपके पास पहले से मौजूद निर्देश फ़ाइल साझा वाली बन जाती है यदि पहले से कोई नहीं थी; अन्यथा उसे लिंक के बगल में `.bak` के रूप में रखा जाता है। कोई अन्य एजेंट इंस्टॉल करने के बाद फिर से लिंक करने के लिए `omarchy agent instructions` चलाएँ।

### एजेंट पैनल

शीर्ष बार में एक एजेंट आइकन है। किसी एजेंट को सेट अप करने से पहले, उसका पैनल आपको Claude, Codex, या Grok में sign in करने की प्रक्रिया से ले जाता है, और पहला वाला आपका डिफ़ॉल्ट एजेंट बन जाता है। उसके बाद, पैनल हर सब्सक्रिप्शन को एक पृष्ठ पर रखता है: प्रत्येक एजेंट और खाता उसके plan के साथ, उसकी प्रत्येक 5-घंटे की session और साप्ताहिक सीमा के लिए एक मीटर जिसके reset होने तक के समय के साथ (सटीक प्रतिशत के लिए hover करें), या शेष prepaid balance, एक पंक्ति के नीचे जो उन सभी में आपके उपयोग को बारी-बारी से दिखाती है, जैसे इस सप्ताह के tokens और आपका सबसे अधिक उपयोग किया गया मॉडल। _कुछ बनाएँ_ के अंतर्गत यह नई theme, plugin, या ऐप के लिए starter prompt प्रदान करता है जो कार्य आपके डिफ़ॉल्ट एजेंट को सौंप देते हैं। ऐप उसी तरह बनाए जाते हैं जैसे Omarchy के अपने Hype, Monologue, और Omacut बनाए गए हैं, C++ और Qt Quick में, omarchy-app agent skill का अनुसरण करते हुए, और उन्हें आवश्यक compiler और Qt हिस्से इंस्टॉल होकर आते हैं। Claude Code, Codex, Grok, Kimi, Cursor और उसकी Grok Bot भत्ता, GitHub Copilot, Muse, Antigravity, Kimchi, और Devin अपनी सीमाओं के साथ पहले से शामिल हैं, और Hermes, Mistral Vibe, और Qwen Code एक बार उपयोग करने के बाद अपने session और tokens दिखाते हैं। pi, omp, या opencode के माध्यम से उपयोग किए जाने वाले Provider plan और key भी दिखाई देते हैं: OpenCode Zen और Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan, और Synthetic अपनी सीमाओं के साथ; Fireworks, OpenRouter, और DeepSeek अपने prepaid balance के साथ; और वे मॉडल जिन्हें आप अपने स्वयं के hardware पर Local models के अंतर्गत चलाते हैं। हर एजेंट की गिनती एक बार होती है, उसी के अंतर्गत जो उसका बिल देता है, चाहे आप उसे कितने भी harness के माध्यम से चलाएँ।

पैनल के लिए बार आइकन पर left-click करें, अपने डिफ़ॉल्ट एजेंट को लॉन्च करने के लिए right-click करें। इसके पीछे के उपयोग रिकॉर्ड हर 15 मिनट में `omarchy agent usage-update` द्वारा फिर से बनाए जाते हैं, और पैनल synced folder के माध्यम से आपकी अन्य मशीनों के उपयोग को भी मिला सकता है। पूर्ण settings के लिए `$OMARCHY_PATH/shell/plugins/agents/` के अंतर्गत README देखें।

### कई सब्सक्रिप्शन

यदि आप एक से अधिक Claude, Codex, या Grok plan के लिए भुगतान करते हैं — उदाहरण के लिए एक व्यक्तिगत Max और एक कार्य वाला — तो Omarchy उन सभी को sign in रख सकता है और उनके बीच जा सकता है। एजेंट पैनल में + से कोई सब्सक्रिप्शन जोड़ें, जो आपको वहीं प्रक्रिया से ले जाता है, या `omarchy agent account add claude Work` (या `codex`, या `grok`) से जोड़ें। यदि CLI मौजूद नहीं है तो यह उसे इंस्टॉल कर देता है। किसी provider के लिए पहला खाता आपके सामान्य browser के माध्यम से sign in करता है, ठीक वहीं जहाँ CLI हमेशा देखता है। उसके बाद का हर खाता एक private window के माध्यम से sign in करता है, ताकि जिस खाते में आपका browser पहले से sign in है वह गलती से न चुना जाए; वहाँ उस खाते के रूप में sign in करें जिसे आप जोड़ रहे हैं, और पहले से खुली कोई भी private window पहले बंद कर दें। ऐसा करने के लिए CLI से कभी log out न करें: log out करने से सहेजा गया sign-in रद्द हो जाता है, और उस खाते को फिर से जोड़ना होगा।

अपने सब्सक्रिप्शन login को SSH पर किसी अन्य Omarchy मशीन पर कॉपी करने के लिए, `omarchy agent account copy user@laptop` चलाएँ। जब गंतव्य पर कोई इंस्टॉल नहीं होता तो प्रेषक एक अस्थायी receiver प्रदान करता है, ताकि पुरानी Omarchy मशीनें बिना अपडेट के खाते प्राप्त कर सकें। इंस्टॉल किए गए receiver को प्राथमिकता मिलती है। यह सभी Claude, Codex, और Grok सब्सक्रिप्शन कॉपी करता है; उन्हें चुनने के लिए provider के नाम जोड़ें, जैसे `omarchy agent account copy laptop claude` में। खातों के नाम और command ID स्रोत से मेल खाते हैं, गंतव्य पर पहले से मौजूद खातों सहित। असंबंधित गंतव्य खातों को नाम टकराने पर numeric suffix मिलता है, और settings, skills, plugins, और conversation history प्रत्येक मशीन पर स्थानीय रहते हैं।

मौजूदा गंतव्य credentials रखे जाते हैं। वहाँ पहले से sign in स्रोत खाते का नाम उसके credentials को बदले बिना synchronized हो जाता है; अन्य खाते उसके साथ जोड़ दिए जाते हैं। मेल खाने वाले खातों के लिए सहेजे गए credentials बदलने के लिए, गंतव्य पर उस खाते के session बंद करने के बाद `omarchy agent account copy --replace laptop claude` का उपयोग करें। नए गंतव्य को स्रोत का सक्रिय खाता और switching प्राथमिकताएँ भी मिलती हैं; स्थापित गंतव्य अपनी प्राथमिकताएँ रखता है।

Credentials SSH के माध्यम से जाते हैं और गंतव्य पर private फ़ाइलों में संग्रहीत होते हैं, इसलिए केवल उन्हीं मशीनों पर कॉपी करें जिन पर आप भरोसा करते हैं। यह एक बार की कॉपी है, निरंतर synchronization नहीं। Codex refresh token किसी अन्य मशीन द्वारा rotate किए जा सकते हैं, जिससे कॉपी किए गए login को नवीनीकरण की आवश्यकता पड़ सकती है; कई मशीनों पर एक साथ उपयोग के लिए अलग-अलग sign-in सबसे विश्वसनीय विकल्प बने रहते हैं। देखें [Codex का खाता प्रमाणीकरण मार्गदर्शन](https://developers.openai.com/codex/auth/ci-cd-auth)।

प्रति provider एक खाता सक्रिय होता है, और हर नया session उसी के रूप में शुरू होता है: `cx`, `cy`, सादा `claude`, `codex`, या `grok`, `omarchy agent` के माध्यम से लॉन्च की गई कोई भी चीज़, और script या editor जो CLI को `PATH` पर पाते हैं। `omarchy agent account use work` से स्विच करें (और `omarchy agent account use main` से वापस), या पैनल में खाते की संख्या दबाकर फिर `Enter` दबाकर (या उसके Use बटन पर क्लिक करके)। पहले से चल रहे session उस खाते पर रहते हैं जिससे वे शुरू हुए थे। Conversation history, settings, skills, और plugins खातों के बीच साझा होते हैं, इसलिए उसी folder में `claude --continue` नए खाते पर वहीं से आगे बढ़ता है जहाँ आपने छोड़ा था।

एक से अधिक खाते के साथ, पैनल प्रत्येक खाते की सीमाएँ साथ-साथ दिखाता है, सक्रिय खाता चिह्नित होता है। डिफ़ॉल्ट रूप से Omarchy आपको तब सूचित करता है जब सक्रिय खाता किसी सीमा के 95% को पार कर जाता है, और सूचना पर क्लिक करने से सबसे अधिक headroom वाले खाते पर स्विच हो जाता है। पैनल में खाते की पंक्ति पर hover करें और Use के बगल में दिखाई देने वाले Autoswitch पर क्लिक करें (या `m` दबाएँ), या इसके बजाय अपने आप स्विच करने के लिए `omarchy agent account mode auto` चलाएँ; जब यह चालू होता है, तो Autoswitch Use की जगह ले लेता है, और फिर से क्लिक करने से सूचित करने पर वापस आ जाता है। threshold बदलने के लिए कोई संख्या जोड़ें, जैसे `omarchy agent account mode auto 90` में। यदि हर खाता threshold से ऊपर है, तो आपको एक बार बताया जाएगा, साथ में यह भी कि कौन सा खाता सबसे पहले मुक्त होगा। जब सक्रिय खाता अपने threshold के 15 points के भीतर होता है (डिफ़ॉल्ट पर 80%), तो उसकी सीमाएँ हर 15 मिनट के बजाय हर तीन मिनट में जाँची जाती हैं।

`omarchy agent account list` हर खाता और उसकी नवीनतम सीमाएँ दिखाता है, `omarchy agent account remove work` एक को भुला देता है, और `omarchy agent account rename primary Hey` एक का नाम बदल देता है (या पैनल में खाते के नाम पर क्लिक करें)। ये कमांड आपके डिफ़ॉल्ट एजेंट के खातों पर काम करते हैं; अन्य provider तक पहुँचने के लिए, पहले उसका नाम दें, जैसे `omarchy agent account use codex side` में। `~/.claude` या `~/.codex` में आपके पास पहले से मौजूद login _Main_ खाता है और वहीं रहता है जहाँ वह है। लगभग आठ घंटे से अधिक समय तक अप्रयुक्त छोड़ा गया खाता _Sign-in required_ दिखा सकता है; उसे पैनल में ही फिर से sign in करने के लिए उस पर क्लिक करें, या उसमें कोई session शुरू करें, जो अपने आप sign-in को refresh कर देता है। खाता जोड़ते समय आपके पास मौजूद MCP server उसके साथ आ जाते हैं, लेकिन बाद में `claude mcp add` से जोड़े गए server केवल उस खाते तक पहुँचते हैं जिसमें आपने उन्हें जोड़ा था। Claude Desktop और CLI binary के absolute path के साथ कॉन्फ़िगर किए गए टूल स्विच का अनुसरण नहीं करते। स्पष्ट `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, या `GROK_HOME` चुने गए खाते पर प्राथमिकता लेता है।

### क्रैश निदान

Omarchy process crash के लिए systemd-coredump को देखता है। जब कोई चीज़ segfault होती है, तो आपको “Process crashed” सूचना मिलेगी — उस पर क्लिक करें, और क्रैश आपके डिफ़ॉल्ट एजेंट को Omarchy की diagnose-crash skill के साथ सौंप दिया जाता है, जो एजेंट को core dump से तथ्य स्थापित करने और यह तय करने की प्रक्रिया से ले जाती है कि क्रैश upstream रिपोर्ट करने योग्य है या नहीं। आप उसे `coredumpctl list` के किसी भी PID के विरुद्ध `omarchy agent crash <pid>` के साथ हाथ से भी चला सकते हैं।

यह देखना डिफ़ॉल्ट रूप से चालू है। उसे _Trigger > Toggle > Crash Capture_ के अंतर्गत (या `omarchy toggle crash-capture` से) बंद करें और सूचनाएँ बंद हो जाती हैं; `omarchy agent crash <pid>` हाथ से फिर भी काम करता है।

क्रैश को एक बार में एक program के लिए भी चुप किया जा सकता है, जो निदान अंत में आपको प्रदान करता है। `omarchy crash mute hyprland` केवल उस program के लिए सूचनाएँ बंद करता है, `omarchy crash mute hyprland off` उन्हें वापस लाता है, और अकेला `omarchy crash mute` वह सूची दिखाता है जो आपने mute किया है। यह binary का path उतनी ही आसानी से लेता है जितना उसका नाम, इसलिए `omarchy crash mute /usr/bin/hyprland` वही काम करता है। space वाले नाम को उद्धृत करें, जैसे `omarchy crash mute 'Some App'` में। बाकी सब कुछ अब भी सूचित करता है, और muted program अब भी क्रैश होता है — यह reminder छिपाता है, यह कुछ ठीक नहीं करता।

### डेस्कटॉप ऐप

_Install > AI_ मेनू में कुछ graphical AI ऐप भी हैं: ChatGPT desktop app, Claude desktop app (Anthropic का Linux beta, Chat, Cowork, और Claude Code tab के साथ), xAI के मॉडलों के साथ चैट करने के लिए Grok Bot, Herdr Desktop, Hermes Desktop, OpenClaw, Perplexity desktop app, और T3 Code। Grok Bot desktop chat app है। कोडिंग एजेंट `grok` कमांड है।

Hermes Desktop वह है जिसके बारे में जानना ज़रूरी है, क्योंकि किसी मशीन पर एक Hermes होता है, और वह ऐप का होता है: Hermes हमेशा केवल ऐप के माध्यम से इंस्टॉल होता है, और डिफ़ॉल्ट एजेंट जो `hermes` कमांड चलाता है वह ऐप का ही है। Hermes को डिफ़ॉल्ट एजेंट के रूप में चुनने पर वही इंस्टॉल होता है जो _Install > AI_ प्रविष्टि करती है: पैकेज, और Hermes के अपने इंस्टॉलर द्वारा सेट अप किया गया `~/.hermes` के अंतर्गत Hermes runtime, जिसमें पहली बार कुछ मिनट लगते हैं। वह runtime वही एक Hermes है जिसका उपयोग terminal `hermes` कमांड, डिफ़ॉल्ट एजेंट और ऐप सभी करते हैं, और वह Omarchy रिलीज़ की प्रतीक्षा करने के बजाय `hermes update` से स्वयं को अपडेट करता है। उसे इंस्टॉल करने पर Hermes को Omarchy theme `omarchy` नामक skin के रूप में भी मिलता है, जिसका अनुसरण हर Hermes surface आपके theme बदलने पर करता है; यदि आप नहीं चाहते कि ऐसा हो तो Hermes की Appearance settings के अंतर्गत या `/skin` से कोई अन्य चुनें, और Omarchy उस चुनाव को अकेला छोड़ देता है। _Remove > AI_ के अंतर्गत ऐप हटाने से पहले Hermes बंद होता है, gateway सहित, वह runtime उसके साथ ले जाता है, और आपकी चैट, memories, और वे skills जो Hermes ने स्वयं के लिए लिखी थीं, रखता है जब तक कि आप अन्यथा न कहें: यह पूछता है, डिफ़ॉल्ट no के साथ, कि क्या वह data और आपकी connection settings भी जानी चाहिए।

OpenClaw का desktop अनुभव उसका Control UI है, जो उसके अपने local gateway द्वारा समर्थित web app के रूप में खुलता है। OpenClaw `~/.openclaw` में रहता है और स्वयं को अपडेट करता है: Control UI के “Update Gateway” बटन का उपयोग करें या `openclaw update` चलाएँ, और gateway नए संस्करण पर पुनः शुरू हो जाता है। Omarchy केवल वह रिलीज़ चुनता है जिससे नया इंस्टॉल शुरू होता है। _Remove > AI_ के अंतर्गत OpenClaw हटाने से gateway service और ऐप उसके साथ जाते हैं और फिर पूछा जाता है कि क्या `~/.openclaw` भी जाना चाहिए, क्योंकि उसमें OpenClaw स्वयं और उसके द्वारा डाउनलोड किए गए plugin runtime के साथ आपकी चैट और credentials होते हैं; डिफ़ॉल्ट उसे रखता है, और OpenClaw फिर से इंस्टॉल करने पर उसे फिर से उठा लिया जाता है।

Herdr Desktop [Herdr](https://herdr.dev) desktop app है: terminal और कोडिंग एजेंट के spaces, tabs, और panes जो window बंद करने पर उसके core में चलते रहते हैं। यह किसी पैकेज के बजाय Herdr के अपने इंस्टॉलर से आता है, इसलिए यह `~/.local/share/herdr-app` में रहता है, जब आपके पास पहले से कोई नहीं होता तो `~/.local/bin/herdr-core` में अपना core साथ लाता है, और दोनों को स्वयं अपडेट करता है। यह Omarchy द्वारा `Super + Ctrl + Return` पर दिए गए `herdr` कमांड के बगल में बैठता है, उसे बदलता नहीं है, और उस कमांड की direct key प्राप्त करता है: `Alt + Return` और `Alt + Shift + Return` pane को नीचे या दाईं ओर विभाजित करते हैं, `Alt + Escape` उसे बंद करता है, `Ctrl + Alt + Arrow` pane के बीच जाता है, `Alt + 1..9` और `Alt + Left/Right` tab चुनते हैं, और `Alt + Up/Down` spaces के बीच जाते हैं। `Ctrl + 1..9` space चुनता है और `Alt + Shift + Up/Down` एजेंट के माध्यम से आगे बढ़ता है। `Ctrl + Space` prefix key केवल terminal के लिए रहती हैं, क्योंकि ऐप किसी sequence के लिए सादा Ctrl key नहीं रख सकता। Omarchy इन्हें `~/.config/herdr-app/keys.json` में लिखता है, और `omarchy-refresh-herdr-app` उन्हें वापस रखता है। उसे इंस्टॉल करने पर Herdr का Omarchy theme चुना जाता है, जो उसके बाद से आपके Omarchy theme का अनुसरण करता है। Herdr light mode के लिए एक theme और dark के लिए एक रखता है, इसलिए dark और light Omarchy theme के बीच स्विच करने के बाद, अन्य mode के लिए Herdr के theme picker में Omarchy को एक बार फिर चुनें।

T3 Code किसी पैकेज के बजाय `~/.local/share/t3code` में अपने आधिकारिक AppImage रिलीज़ से चलता है, इसलिए वह स्वयं को अपडेट करता है। उसे इंस्टॉल करने पर पूछा जाता है कि Stable या Nightly channel पर शुरू करना है; बाद में T3 Code की settings में स्विच करें। आपकी threads और settings `~/.t3` में रहती हैं, और _Remove > AI_ के अंतर्गत T3 Code हटाने से वे उसके साथ जाती हैं।

### स्थानीय मॉडल

अपने कोडिंग एजेंट के लिए अपनी स्वयं की मशीन पर कोई open मॉडल चलाएँ। आपके prompt और code मशीन पर रहते हैं; मॉडल को भेजी गई कोई भी चीज़ उसे छोड़कर नहीं जाती। इससे शुरू करें:

```bash
omarchy agent local use best
```

या, शीर्ष बार के एजेंट पैनल में, + और फिर Local AI चुनें, जो तब दिखाई देता है जब कोई मॉडल इस मशीन पर फिट होता है। पहली बार, यह Podman इंस्टॉल करता है, जो मॉडल चलाता है, और NVIDIA मशीन पर NVIDIA का container toolkit, जो उन्हें GPU देता है। फिर Omarchy इस मशीन के लिए अनुशंसित मॉडल चुनता है, उसे डाउनलोड करता है, और शुरू करता है। मॉडल चलने के दौरान tens of GB के डाउनलोड और मशीन की अधिकांश memory उपयोग में होने की अपेक्षा करें: Flash Next अपने पूर्ण 256K context के साथ लगभग 100 GiB उपयोग करता है। यदि अन्य मॉडल उसकी आवश्यक memory रखते हैं, तो वह रुका हुआ सेट अप होता है, एक को रोकने के बाद शुरू होने के लिए तैयार। मॉडल logout पर रुक जाता है; जब आपको किसी अन्य चीज़ के लिए memory चाहिए तो उसे स्वयं रोकें।

`omarchy agent local list` विकल्प दिखाता है और बताता है कि कुछ क्यों फिट नहीं होते। कोई अन्य सेट अप करने के लिए, `omarchy agent local use <recipe>` चलाएँ। आज, `qwen3.8-flash-next-gufo` और `qwen3.8-27b-gufo` 128 GB Strix Halo मशीनों के लिए उपलब्ध हैं; 27B लगभग 40 GiB लेता है, इसलिए वह अन्य कार्य के लिए जगह छोड़ता है। नई recipes और अनुशंसाएँ पैकेज के माध्यम से `omarchy update` के साथ आती हैं।

आपके द्वारा सेट अप किया गया हर मॉडल एजेंट पैनल में, आपके सब्सक्रिप्शन के बगल में, अपनी स्वयं की पंक्ति प्राप्त करता है: शुरू करने के लिए play, रोकने और उसकी memory मुक्त करने के लिए pause, और उस पर अपना एजेंट खोलने के लिए terminal बटन। कई एक साथ चल सकते हैं जब वे memory में साथ फिट होते हैं; यदि कोई फिट नहीं होता, तो Omarchy बताता है कि किस चल रहे मॉडल को रोकना है। उन्हें पुनः क्रमित करने के लिए पंक्तियाँ खींचें, और मॉडल और उसका डाउनलोड हटाने के लिए चुनी गई पंक्ति पर Delete दबाएँ।

command line से, `omarchy agent local start <recipe>` और `omarchy agent local stop <recipe>` वही करते हैं, `omarchy agent local status` हर मॉडल दिखाता है, और `omarchy agent --local` आपके डिफ़ॉल्ट एजेंट को आपके द्वारा शुरू किए गए अंतिम मॉडल पर खोलता है (pi यदि आपका डिफ़ॉल्ट एजेंट स्थानीय मॉडल का उपयोग नहीं कर सकता)। कोई भी OpenAI-compatible client भी जुड़ सकता है: `status` प्रत्येक मॉडल का पता दिखाता है (पहला `http://127.0.0.1:11435/v1` है), recipe नाम मॉडल है, और key `~/.config/omarchy/agent-local/key` में है।

`omarchy agent local remove <recipe>` किसी मॉडल और उन डाउनलोड को हटाता है जिनका कोई अन्य मॉडल उपयोग नहीं करता।

Third-party runtime उनके publisher के साथ लेबल किए जाते हैं। Omarchy हर मॉडल को बिना network access के चलाता है।

### स्थानीय LLM

Omarchy स्थानीय LLM मॉडल चलाने के दो तरीके अनुशंसित करता है: LM Studio और Ollama। LM Studio open-weight मॉडल खोजने, उन्हें इंस्टॉल करने, और उन्हें चलाने के लिए GUI interface प्रदान करता है। आसानी से शुरू करने का यह बहुत अच्छा तरीका है। Ollama इसी तरह करने के लिए CLI प्रदान करता है। लेकिन यदि आप स्थानीय मॉडलों में नए हैं, तो मैं LM Studio से शुरू करूँगा। आप दोनों में से किसी को भी Omarchy Menu में _Install > AI_ के अंतर्गत इंस्टॉल कर सकते हैं।

### Omarchy Skill

Agent skills AI को विशिष्ट टूल का विशिष्ट तरीके से उपयोग करने में मदद करती हैं, और Omarchy system को अनुकूलित करने के लिए एक डिफ़ॉल्ट skill के साथ आता है। जैसे आपकी Hyprland config को tweak करना, bar को समायोजित करना, या यहाँ तक कि शुरू से नई theme बनाना। यह Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` और प्रत्येक `~/.hermes/profiles/*/skills`), और generic `~/.agents/skills` स्थान के skill directory में symlinked है, इसलिए अधिकांश harness उसे अपने आप उठा लेते हैं।

लेकिन आपको इस skill को प्रयोगात्मक मानना चाहिए। विभिन्न मॉडल उसे विभिन्न प्रभाव के साथ उपयोग करेंगे। पहले plan mode में चलाना सबसे अच्छा है, ताकि आपको अंदाज़ा हो कि एजेंट क्या बदलना चाहेगा। और फिर बदलाव rollback करने या यहाँ तक कि `omarchy reinstall configs` चलाने के लिए तैयार रहें, यदि एजेंट सब कुछ गड़बड़ कर दे।
