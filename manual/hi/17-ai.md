### Agents को install और update करना

Hermes को छोड़कर, ये agents mise की lazy installation का उपयोग करते हैं: पहला launch CLI को install करता है, और बाद के launches उसका पुनः उपयोग करते हैं। mise किसी install किए गए agent के लिए नए release की जाँच भी अधिकतम हर चार घंटे में एक बार करता है, ठीक उसके शुरू होने से पहले या background में shell prompt पर। अगर वह update विफल हो जाता है या आप offline हैं, तो install किया गया version चलता है। `omarchy update` Omarchy के बाकी हिस्से के साथ install किए गए agents को update करता है, और `mup` केवल mise-प्रबंधित tools को update करता है।

किसी agent का अपना updater, जैसे `claude update`, `codex update`, या किसी app में update button, mise-प्रबंधित install को update नहीं करता। `codex update` विफल हो जाता है, और `claude update` सफलता की सूचना देते हुए एक अलग copy install कर सकता है जिसे mise track नहीं करता। अगर आप इसके बजाय किसी agent के native installer और updater का उपयोग करना पसंद करते हैं, तो उसे `disable_tools` में जोड़ें; [पहले से install किए गए CLI tools](18-development-tools.md#preinstalled-cli-tools) देखें।

ज़रूरत पड़ने से पहले सभी configured lazy tools को install करने के लिए, `mise install --include-lazy` चलाएँ। इसमें agents के साथ-साथ Omarchy के अन्य default CLI tools भी शामिल हैं। किसी एक tool को install करने या अपनी installation का उपयोग करने के लिए [पहले से install किए गए CLI tools](18-development-tools.md#preinstalled-cli-tools) देखें।

`grok` mise के first-party `grok` package के माध्यम से install होता है, उसी तरह जैसे `claude` और `codex`। `grok` चलाएँ, या उसे _Agent > Harness_ के अंतर्गत चुनें। x.ai पर `curl | bash` installer को छोड़ दें। वह तरीका `~/.grok/bin` में दूसरी copy डाल देता है, उसे `PATH` में सबसे आगे जोड़ देता है, और Omarchy के wrapper को overwrite कर देता है।

`dsh` अपना browser UI `127.0.0.1:3080` पर खोलता है, जिसमें launch directory उसका default workspace होता है। इसका browser UI कोई starting prompt नहीं लेता, इसलिए `omarchy agent prompt` उसे आपके clipboard पर मौजूद prompt के साथ खोलता है ताकि आप उसे paste कर सकें। Omarchy उसे DeepSeek के no-approval permission preset के साथ शुरू करता है। जब आप DeepSeek Harness के official model API का उपयोग करते हैं, तो यह session logs को DeepSeek पर upload करता है; इसे अपने browser UI में _Settings > General > Upload Session Log_ के अंतर्गत बंद करें। आप जो feedback उसे भेजते हैं, वह भी session के साथ upload होता है, जब तक कि आप उसे `DSH_TELEMETRY_MODE=DISABLED` के साथ शुरू न करें।

### डिफ़ॉल्ट एजेंट

अपना default agent `omarchy default agent <name>` के साथ या Omarchy Menu (`Super + Space`) में _Agent > Harness_ के अंतर्गत चुनें। अगर agent अभी install नहीं हुआ है, तो उसे चुनने पर वह पहले install हो जाता है। एक ताज़ा Omarchy आपको एक बार की notification के साथ यह चुनाव करने के लिए आमंत्रित करेगा।

Claude को चुनने पर Chromium, Chrome, Brave, Brave Origin, और Edge के लिए उसके browser extension को set up करने का भी प्रयास होता है। Extension setup सभी users पर लागू होता है और आपसे आपका system password माँग सकता है; extension install को रद्द करने या उसके विफल होने पर भी Claude चुना और launch हो जाता है। अपना browser restart करें, prompt आने पर extension enable करें, और उसे जोड़ना पूरा करने के लिए Claude में sign in करें। Connection की जाँच के लिए Claude में `/chrome` चलाएँ। Firefox और Zen इस extension का समर्थन नहीं करते। अगर यह setup जोड़े जाने से पहले ही Claude आपका default था, तो extension install करने के लिए उसे फिर से चुनें।

एक बार चुन लेने के बाद, `Super + Shift + Ctrl + A` default agent को एक समर्पित terminal window में launch करता है (या अगर आपने अभी तक नहीं चुना है तो picker सामने लाता है)। आप उसे `omarchy agent prompt "Review this project"` के साथ सीधे किसी task में भी launch कर सकते हैं। Freebuff और DeepSeek Harness कोई starting prompt नहीं लेते, इसलिए वे इसके बजाय आपके clipboard पर मौजूद prompt के साथ खुलते हैं ताकि आप उसे paste कर सकें। इस तरह launch किए गए agents अपने-अपने don't-stop-to-ask modes में बिना निगरानी के चलते हैं, इसलिए तैयार रहें कि वे वास्तव में कुछ करेंगे! MiniMax Code के पास उसके interactive sessions के लिए ऐसा कोई mode नहीं है, इसलिए वह हमेशा की तरह permissions माँगता है। और चूँकि agents आपकी home directory के लिए trust याद रखने से इनकार करते हैं, इसलिए `$HOME` से launches इसके बजाय `~/Work` में शुरू होते हैं।

Terminal shortcuts भी हैं: `a` वर्तमान terminal में ही default agent चलाता है, जबकि `c`, `cx`, और `cy` सीधे OpenCode, Claude Code, और Codex शुरू करते हैं (फिर से उनके auto-approving modes में)। Theme बदलाव भी agents के साथ sync होते हैं: जब आप Omarchy theme बदलते हैं, तो Claude Code, Pi, OpenCode, और Hermes (एक बार Omarchy ने उसे install कर लिया हो) सभी साथ-साथ बदल जाते हैं।

### आपके agent निर्देश

हर agent के लिए व्यक्तिगत नियम `~/.agents/AGENTS.md` में जाते हैं, `~/.agents/skills` में shared skills के बगल में। उसे _Agent > Instructions_ के अंतर्गत खोलें, जो उसे हर उस harness में भी link करता है जो अपनी global file रखता है: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, Copilot का `~/.copilot/copilot-instructions.md`, और इसी तरह अन्य। Crush और Amp `~/.config/AGENTS.md` link को पढ़ते हैं, जबकि omp, Kimi, और DeepSeek Harness सीधे `~/.agents/AGENTS.md` पढ़ते हैं। Default agent चुनने पर वह भी link हो जाता है। अगर पहले से कोई shared file नहीं थी तो आपके पास पहले से मौजूद instructions file ही shared file बन जाती है; अन्यथा उसे link के बगल में `.bak` के रूप में रखा जाता है। कोई दूसरा agent install करने के बाद फिर से link करने के लिए `omarchy agent instructions` चलाएँ।

### Agents पैनल

Top bar में एक agents icon है। इससे पहले कि आपने कोई agent set up किया हो, उसका panel आपको Claude, Codex, या Grok में sign in करने की प्रक्रिया से ले जाता है, और पहला वाला आपका default agent बन जाता है। उसके बाद, panel हर subscription को एक page पर रखता है: हर agent और account उसके plan के साथ, उसकी 5-hour session और weekly limits में से प्रत्येक के लिए एक meter और reset होने तक का समय (सटीक percentage के लिए hover करें), या बचा हुआ prepaid balance, एक ऐसी line के नीचे जो उन सभी में आपके उपयोग को बारी-बारी से दिखाती है, जैसे इस सप्ताह के tokens और आपका सबसे अधिक उपयोग किया गया model। _Make something_ के अंतर्गत यह एक नए theme, plugin, app, या game के लिए starter prompts देता है जो task को आपके default agent को सौंप देते हैं। Apps उसी तरह बनाए जाते हैं जैसे Omarchy के अपने Hype, Monologue, और Omacut बनाए गए हैं, C++ और Qt Quick में, omarchy-app agent skill का पालन करते हुए, और उन्हें जिस compiler और Qt हिस्सों की ज़रूरत होती है वे install होकर आते हैं। Games `~/Games/vibes` में एक single three.js page होते हैं, web-game agent skill का पालन करते हुए, और सभी वर्तमान theme में एक Game Vibes launcher से खुलते हैं; वे three.js को web से load करते हैं, इसलिए उन्हें शुरू होने के लिए connection की ज़रूरत होती है। Claude Code, Codex, Grok, Kimi, Cursor और उसका Grok Bot allowance, GitHub Copilot, Muse, Antigravity, Kimchi, और Devin अपनी limits के साथ पहले से ही शामिल हैं, और Hermes, Mistral Vibe, और Qwen Code एक बार आपके द्वारा उनका उपयोग कर लेने के बाद अपने sessions और tokens दिखाते हैं। pi, omp, या opencode के माध्यम से आप जिन provider plans और keys का उपयोग करते हैं वे भी दिखाई देते हैं: OpenCode Zen और Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan, और Synthetic अपनी limits के साथ; Fireworks, OpenRouter, और DeepSeek अपने prepaid balances के साथ; और Local models के अंतर्गत वे models जिन्हें आप अपने hardware पर चलाते हैं। हर agent को एक ही बार गिना जाता है, उसी के अंतर्गत जो उसे bill करता है, चाहे आप उसे कितने ही harnesses के माध्यम से चलाएँ।

Panel के लिए bar icon पर left-click करें, अपने default agent को launch करने के लिए right-click करें। इसके पीछे के usage records हर 15 मिनट में `omarchy agent usage-update` द्वारा फिर से बनाए जाते हैं, और panel एक synced folder के माध्यम से आपकी अन्य machines के usage को भी merge कर सकता है। पूरी settings के लिए `$OMARCHY_PATH/shell/plugins/agents/` के अंतर्गत README देखें।

### कई सब्सक्रिप्शन

अगर आप एक से अधिक Claude, Codex, या Grok plan के लिए भुगतान करते हैं — मान लीजिए एक personal Max और एक work वाला — तो Omarchy उन सभी को signed in रख सकता है और उनके बीच आ-जा सकता है। Agents panel में + के साथ कोई subscription जोड़ें, जो आपको वहीं इस प्रक्रिया से ले जाता है, या `omarchy agent account add claude Work` के साथ (या `codex`, या `grok`)। अगर CLI मौजूद नहीं है तो यह उसे install कर देता है। किसी provider के लिए पहला account आपके सामान्य browser के माध्यम से sign in करता है, ठीक वहाँ जहाँ CLI हमेशा देखता है। उसके बाद का हर account एक private window के माध्यम से sign in करता है, ताकि जिस account में आपका browser पहले से signed in है वह गलती से न चुना जाए; वहाँ उस account के रूप में sign in करें जिसे आप जोड़ रहे हैं, और पहले से खुली हुई किसी भी private window को पहले बंद कर दें। ऐसा करने के लिए CLI से कभी log out न करें: log out करने से saved sign-in रद्द हो जाता है, और उस account को फिर से जोड़ना पड़ेगा।

अपने subscription logins को SSH पर किसी दूसरी Omarchy machine पर copy करने के लिए, `omarchy agent account copy user@laptop` चलाएँ। जब destination पर कोई receiver install नहीं होता, तो sender एक temporary receiver देता है, ताकि पुरानी Omarchy machines बिना update के accounts प्राप्त कर सकें। Install किए गए receivers को प्राथमिकता मिलती है। यह सभी Claude, Codex, और Grok subscriptions को copy करता है; उन्हें चुनने के लिए provider names जोड़ें, जैसे `omarchy agent account copy laptop claude` में। Account names और command IDs source से मेल खाते हैं, जिनमें destination पर पहले से मौजूद accounts भी शामिल हैं। अगर असंबंधित destination accounts के नाम टकराते हैं तो उन्हें एक numeric suffix मिलता है, और settings, skills, plugins, और conversation history हर machine पर स्थानीय रहती है।

Destination के मौजूदा credentials रखे जाते हैं। वहाँ पहले से signed in किसी source account का नाम उसके credentials को बदले बिना synchronize हो जाता है; अन्य accounts उसके बगल में जोड़ दिए जाते हैं। मेल खाने वाले accounts के लिए saved credentials को बदलने के लिए, destination पर उस account के sessions बंद करने के बाद `omarchy agent account copy --replace laptop claude` का उपयोग करें। एक ताज़ा destination को source का active account और switching preferences भी मिलती हैं; एक स्थापित destination अपनी preferences रखता है।

Credentials SSH के माध्यम से जाते हैं और destination पर private files में संग्रहीत होते हैं, इसलिए केवल उन machines पर copy करें जिन पर आप भरोसा करते हैं। यह एक बार की copy है, चल रहा synchronization नहीं। Codex refresh tokens को किसी दूसरी machine द्वारा rotate किया जा सकता है, जिससे copy किए गए login को renewal की ज़रूरत पड़ सकती है; कई machines पर एक साथ उपयोग के लिए अलग-अलग sign-ins सबसे विश्वसनीय विकल्प बने रहते हैं। [Codex के account authentication मार्गदर्शन](https://developers.openai.com/codex/auth/ci-cd-auth) देखें।

प्रति provider एक account सक्रिय होता है, और हर नया session उसी के रूप में शुरू होता है: `cx`, `cy`, एक सादा `claude`, `codex`, या `grok`, `omarchy agent` के माध्यम से launch की गई कोई भी चीज़, और scripts या editors जो CLI को `PATH` पर पाते हैं। `omarchy agent account use work` के साथ switch करें (और `omarchy agent account use main` के साथ वापस), या panel में किसी account का number दबाकर फिर `Enter` दबाकर (या उसके Use button पर click करके)। चल रहे Claude sessions भी switch हो जाते हैं, उनके अगले message से: हर Claude session `~/.claude` में चलता है, जिसमें हमेशा active account का sign-in होता है। किसी पुराने Omarchy द्वारा किसी account के अपने folder में शुरू किया गया Claude session उस sign-in को तब तक रखता है जब तक वह बंद न हो जाए, इसलिए switch उन sessions के नाम बताता है और उनके चले जाने के बाद अपने आप पूरा हो जाता है। चल रहे Codex और Grok sessions उसी account पर रहते हैं जिसके साथ वे शुरू हुए थे। Conversation history, settings, skills, और plugins accounts के बीच साझा होते हैं, इसलिए उसी folder में `claude --continue` नए account पर वहीं से आगे बढ़ता है जहाँ आपने छोड़ा था।

एक से अधिक account के साथ, panel हर account की limits को साथ-साथ दिखाता है, जिसमें active वाला चिह्नित होता है। Default रूप से Omarchy आपको सूचित करता है जब active account किसी limit के 95% को पार कर जाता है, और notification पर click करने से सबसे अधिक headroom वाले account पर switch हो जाता है। Panel में किसी account की line पर hover करें और Use के बगल में दिखाई देने वाले Autoswitch पर click करें (या `m` दबाएँ), या इसके बजाय उसे अपने आप switch कराने के लिए `omarchy agent account mode auto` चलाएँ; जब यह चालू होता है, तो Autoswitch Use की जगह ले लेता है, और फिर से उस पर click करने से सूचित करने पर वापस आ जाता है। Threshold बदलने के लिए एक number जोड़ें, जैसे `omarchy agent account mode auto 90` में। अगर हर account threshold से ऊपर है, तो आपको एक बार इसके बारे में बताया जाएगा, साथ में यह भी कि कौन सा account सबसे पहले खाली होगा। जब कोई active account अपने threshold के 15 points के भीतर होता है (default पर 80%), तो उसकी limits की जाँच हर 15 के बजाय हर तीन मिनट में होती है।

`omarchy agent account list` हर account और उसकी नवीनतम limits दिखाता है, `omarchy agent account remove work` एक को भुला देता है, और `omarchy agent account rename primary Hey` एक का नाम बदल देता है (या panel में किसी account के नाम पर click करें)। ये commands आपके default agent के accounts पर काम करते हैं; दूसरे provider तक पहुँचने के लिए, पहले उसका नाम दें, जैसे `omarchy agent account use codex side` में। `~/.claude` या `~/.codex` में आपके पास पहले से मौजूद login ही _Main_ account है। Codex का वहीं रहता है जहाँ वह है; Claude का, जब कोई दूसरा account सक्रिय होता है, तो अपने folder में प्रतीक्षा करता है। लगभग आठ घंटे से अधिक समय तक अप्रयुक्त छोड़ा गया account _Sign-in required_ दिखा सकता है; panel में ही उस account को फिर से sign in करने के लिए उस पर click करें, या उस पर switch करके एक session शुरू करें, जिससे sign-in अपने आप refresh हो जाता है। `claude mcp add` के साथ आप जो MCP servers जोड़ते हैं वे हर Claude account तक पहुँचते हैं, क्योंकि वे सभी `~/.claude` में चलते हैं; Codex और Grok के लिए, किसी account को जोड़े जाने के समय आपके पास मौजूद servers उसके साथ आ जाते हैं, लेकिन बाद वाले केवल उसी account तक पहुँचते हैं जिसमें आपने उन्हें जोड़ा था। Claude Desktop अपना sign-in स्वयं रखता है, और किसी CLI binary के absolute path के साथ configure किए गए Codex या Grok tools switch का पालन नहीं करते। एक स्पष्ट `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, या `GROK_HOME` चुने गए account पर प्राथमिकता लेता है।

### क्रैश निदान

Omarchy process crashes के लिए systemd-coredump पर नज़र रखता है। जब कुछ segfault होता है, तो आपको एक "Process crashed" notification मिलेगा — उस पर click करें, और crash आपके default agent को Omarchy के diagnose-crash skill के साथ सौंप दिया जाता है, जो agent को core dump से तथ्य स्थापित करने और यह तय करने की प्रक्रिया से ले जाता है कि crash upstream रिपोर्ट करने योग्य है या नहीं। आप उसे `coredumpctl list` से किसी भी PID के खिलाफ `omarchy agent crash <pid>` के साथ हाथ से भी चला सकते हैं।

यह देखना default रूप से चालू है। उसे _Trigger > Toggle > Crash Capture_ के अंतर्गत (या `omarchy toggle crash-capture` के साथ) बंद करें और notifications बंद हो जाएँगे; `omarchy agent crash <pid>` हाथ से फिर भी काम करता है।

Crashes को एक समय में एक program के लिए भी चुप किया जा सकता है, जो निदान अंत में आपको देता है। `omarchy crash mute hyprland` केवल उस program के लिए notifications रोकता है, `omarchy crash mute hyprland off` उन्हें वापस लाता है, और अकेला `omarchy crash mute` वह सूची देता है जो आपने mute किया है। यह binary के path को उसके नाम जितनी ही खुशी से लेता है, इसलिए `omarchy crash mute /usr/bin/hyprland` वही काम करता है। किसी ऐसे नाम को quote करें जिसमें space हो, जैसे `omarchy crash mute 'Some App'` में। बाकी सब कुछ फिर भी सूचित करता है, और muted program फिर भी crash होता है — यह reminder को छिपाता है, यह कुछ ठीक नहीं करता।

### डेस्कटॉप ऐप्स

_Install > AI_ menu में कुछ graphical AI apps भी हैं: ChatGPT desktop app, Claude desktop app (Anthropic का Linux beta, Chat, Cowork, और Claude Code tabs के साथ), xAI के models के साथ chat करने के लिए Grok Bot, Herdr Desktop, Hermes Desktop, OpenClaw, Perplexity desktop app, और T3 Code। Grok Bot desktop chat app है। Coding agent `grok` command है।

Hermes Desktop वह है जिसके बारे में जानना ज़रूरी है, क्योंकि किसी machine पर एक ही Hermes होता है, और वह app का होता है: Hermes हमेशा केवल app के माध्यम से ही install होता है, और default agent जो `hermes` command चलाता है वह app का ही है। Hermes को default agent के रूप में चुनने पर वही चीज़ install होती है जो _Install > AI_ entry करती है: package, और Hermes के अपने installer द्वारा set up किया गया `~/.hermes` के अंतर्गत एक Hermes runtime, जिसमें पहली बार कुछ मिनट लगते हैं। वह runtime ही वह एक Hermes है जिसका उपयोग terminal `hermes` command, default agent और app सभी करते हैं, और वह Omarchy release की प्रतीक्षा करने के बजाय `hermes update` के साथ स्वयं को update करता है। उसे install करने पर Hermes को Omarchy theme भी `omarchy` नाम की skin के रूप में मिलता है, जिसका पालन हर Hermes surface आपके theme बदलने पर करता है; अगर आप ऐसा नहीं चाहते तो Hermes की Appearance settings के अंतर्गत या `/skin` के साथ कोई दूसरा चुनें, और Omarchy उस चुनाव को अकेला छोड़ देता है। _Remove > AI_ के अंतर्गत app को हटाने पर पहले Hermes बंद होता है, gateway समेत, वह runtime उसके साथ चला जाता है, और आपकी chats, memories, और वे skills जो Hermes ने स्वयं के लिए लिखी थीं, रखी जाती हैं जब तक कि आप उसे अन्यथा न कहें: यह पूछता है, जिसमें default no होता है, कि क्या वह data और आपकी connection settings भी जानी चाहिए।

OpenClaw का desktop अनुभव उसका Control UI है, जो उसके अपने local gateway द्वारा समर्थित एक web app के रूप में खुलता है। OpenClaw `~/.openclaw` में रहता है और स्वयं को update करता है: Control UI के "Update Gateway" button का उपयोग करें या `openclaw update` चलाएँ, और gateway नए version पर restart हो जाता है। Omarchy केवल वह release चुनता है जिससे कोई ताज़ा install शुरू होता है। _Remove > AI_ के अंतर्गत OpenClaw को हटाने पर gateway service और app उसके साथ चले जाते हैं और फिर पूछा जाता है कि क्या `~/.openclaw` को भी जाना चाहिए, क्योंकि उसमें OpenClaw स्वयं और उसके द्वारा download किए गए plugin runtimes के साथ आपकी chats और credentials होते हैं; default उसे रखता है, और OpenClaw को फिर से install करने पर वह फिर से मिल जाता है।

Herdr Desktop [Herdr](https://herdr.dev) desktop app है: terminals और coding agents के spaces, tabs, और panes जो आपके window बंद करने पर उसके core में चलते रहते हैं। यह किसी package के बजाय Herdr के अपने installer से आता है, इसलिए यह `~/.local/share/herdr-app` में रहता है, जब आपके पास पहले से कोई नहीं होता तो अपने core को `~/.local/bin/herdr-core` में साथ लाता है, और दोनों स्वयं को update करते हैं। यह Omarchy द्वारा `Super + Ctrl + Return` पर दिए गए `herdr` command को बदलने के बजाय उसके बगल में रहता है, और उस command की direct keys प्राप्त करता है: `Alt + Return` और `Alt + Shift + Return` किसी pane को नीचे या दाईं ओर split करते हैं, `Alt + Escape` उसे बंद करता है, `Ctrl + Alt + Arrow` panes के बीच ले जाता है, `Alt + 1..9` और `Alt + Left/Right` कोई tab चुनते हैं, और `Alt + Up/Down` spaces के बीच ले जाते हैं। `Ctrl + 1..9` कोई space चुनता है और `Alt + Shift + Up/Down` agents के माध्यम से आगे बढ़ता है। `Ctrl + Space` prefix keys केवल terminal के लिए रहती हैं, क्योंकि app किसी sequence के लिए एक सादी Ctrl key को पकड़कर नहीं रख सकता। Omarchy इन्हें `~/.config/herdr-app/keys.json` में लिखता है, और `omarchy-refresh-herdr-app` उन्हें वापस रख देता है। उसे install करने पर Herdr का Omarchy theme चुना जाता है, जो उसके बाद से आपके Omarchy theme का पालन करता है। Herdr light mode के लिए एक theme और dark के लिए एक theme रखता है, इसलिए किसी dark और light Omarchy theme के बीच switch करने के बाद, दूसरे mode के लिए Herdr के theme picker में एक बार फिर Omarchy चुनें।

T3 Code किसी package के बजाय `~/.local/share/t3code` में अपनी official AppImage release से चलता है, इसलिए वह स्वयं को update करता है। उसे install करने पर पूछा जाता है कि Stable या Nightly channel पर शुरू करना है; बाद में T3 Code की settings में switch करें। आपके threads और settings `~/.t3` में रहते हैं, और _Remove > AI_ के अंतर्गत T3 Code को हटाने पर वे उसके साथ चले जाते हैं।

### स्थानीय मॉडल

अपने coding agents के लिए अपनी machine पर कोई open model चलाएँ। आपके prompts और code machine पर ही रहते हैं; model को भेजी गई कोई भी चीज़ उसे छोड़कर नहीं जाती। इसके साथ शुरू करें:

```bash
omarchy agent local use best
```

या, top bar में agents panel में, + और फिर Local AI चुनें, जो तब दिखाई देता है जब कोई model इस machine पर fit बैठता है। पहली बार, यह Podman install करता है, जो models को चलाता है, और NVIDIA machine पर NVIDIA का container toolkit, जो उन्हें GPU देता है। फिर Omarchy इस machine के लिए अनुशंसित model चुनता है, उसे download करता है, और शुरू करता है। Tens of GB के download की अपेक्षा करें और model चलने के दौरान machine की अधिकांश memory उपयोग में रहेगी: Flash Next अपने पूरे 256K context के साथ लगभग 100 GiB का उपयोग करता है। अगर अन्य models को वह memory चाहिए जो इसे चाहिए, तो यह रुका हुआ set up होता है, आपके द्वारा किसी एक को रोकते ही शुरू होने के लिए तैयार। Model logout पर रुक जाता है; जब आपको किसी और चीज़ के लिए memory चाहिए तो उसे स्वयं रोकें।

`omarchy agent local list` विकल्प दिखाता है और बताता है कि कुछ क्यों fit नहीं बैठते। कोई दूसरा set up करने के लिए, `omarchy agent local use <recipe>` चलाएँ। आज, 128 GB Strix Halo machines के लिए `qwen3.8-flash-next-gufo` और `qwen3.8-27b-gufo` उपलब्ध हैं; 27B लगभग 40 GiB लेता है, इसलिए वह अन्य काम के लिए जगह छोड़ता है। Intel के Arc B390 वाले 64 GB laptop पर, `qwen3.6-35b-a3b-llamacpp` लगभग 30 GiB में चलता है। नई recipes और अनुशंसाएँ package के माध्यम से `omarchy update` के साथ आती हैं।

आपके द्वारा set up किया गया हर model agents panel में, आपके subscriptions के बगल में, अपनी line प्राप्त करता है: उसे शुरू करने के लिए play, उसे रोकने और उसकी memory खाली करने के लिए pause, और उस पर अपना agent खोलने के लिए terminal button। कई एक साथ चल सकते हैं जब वे memory में एक साथ fit बैठते हैं; अगर कोई fit नहीं बैठता, तो Omarchy बताता है कि किस चल रहे model को रोकना है। उन्हें फिर से क्रमबद्ध करने के लिए lines को drag करें, और किसी model और उसके download को हटाने के लिए चुनी गई line पर Delete दबाएँ।

आपके द्वारा set up किया गया हर model app launcher में भी अपनी entry प्राप्त करता है, model के नाम के अंतर्गत और उसके निर्माता के logo के साथ, उसी तरह जैसे Claude, Codex या Grok में sign in करने पर एक जुड़ता है। यह उस model पर आपका agent खोलता है, और अगर model नहीं चल रहा है तो पहले उसे शुरू करता है: terminal उसे load होते हुए दिखाता है और उसके तैयार होते ही agent को सौंप देता है। किसी model को हटाने पर उसकी entry हट जाती है।

Command line से, `omarchy agent local start <recipe>` और `omarchy agent local stop <recipe>` वही करते हैं, `omarchy agent local status` हर model दिखाता है, और `omarchy agent --local` आपके द्वारा शुरू किए गए अंतिम model पर आपका default agent खोलता है। pi, OpenCode और Qwen Code किसी एक का उपयोग कर सकते हैं; किसी अन्य default के साथ यह pi में खुलता है। pi आपके द्वारा set up किए गए हर model को, और उन machines पर मौजूद models को भी जिनके साथ आपने pair किया है, अपने model picker में सूचीबद्ध करता है, इसलिए सादा `pi` भी उन तक पहुँचता है। कोई भी OpenAI-compatible client भी जुड़ सकता है: `status` हर model का address दिखाता है (पहला `http://127.0.0.1:11435/v1` है), recipe name ही model है, और key `~/.config/omarchy/agent-local/key` में है।

`omarchy agent local remove <recipe>` किसी model को और उन downloads को delete कर देता है जिनका उपयोग कोई अन्य model नहीं करता।

Third-party runtimes को उनके publisher के साथ label किया जाता है। Omarchy हर model को बिना network access के चलाता है।

### स्थानीय LLMs

Omarchy स्थानीय LLM models चलाने के दो तरीके अनुशंसित करता है: LM Studio और Ollama। LM Studio open-weight models खोजने, उन्हें install करने, और उन्हें चलाने के लिए एक GUI interface देता है। यह आसानी से शुरू करने का एक शानदार तरीका है। Ollama इसी तरह करने के लिए एक CLI देता है। लेकिन अगर आप स्थानीय models के लिए नए हैं, तो मैं LM Studio से शुरू करूँगा। आप Omarchy Menu में _Install > AI_ के अंतर्गत किसी को भी install कर सकते हैं।

### Omarchy Skill

Agent skills AI को विशिष्ट tools का विशिष्ट तरीके से उपयोग करने में मदद करती हैं, और Omarchy system को tailor करने के लिए एक default skill के साथ आता है। जैसे आपकी Hyprland config को tweak करना, bar को adjust करना, या यहाँ तक कि शुरू से एक नया theme बनाना। यह Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` और प्रत्येक `~/.hermes/profiles/*/skills`), और generic `~/.agents/skills` स्थान के लिए skill directories में symlinked है, इसलिए अधिकांश harnesses उसे अपने आप उठा लेते हैं।

लेकिन आपको इस skill को प्रयोगात्मक मानना चाहिए। अलग-अलग models उसका अलग-अलग प्रभाव के साथ उपयोग करेंगे। सबसे अच्छा है कि पहले उसे plan mode में चलाएँ, ताकि आपको अंदाज़ा हो कि agent क्या बदलना चाहेगा। और फिर बदलावों को rollback करने या यहाँ तक कि `omarchy reinstall configs` चलाने के लिए तैयार रहें, अगर agent सब कुछ गड़बड़ कर दे।
