### Agents को install और update करना

Hermes और OpenClaw को छोड़कर, ये agents mise की lazy installation का इस्तेमाल करते हैं: पहली launch पर CLI install होता है, और बाद की launches उसी का फिर से इस्तेमाल करती हैं। mise किसी installed agent के लिए नए release की जाँच हर चार घंटे में ज़्यादा से ज़्यादा एक बार करता है, या तो उसके शुरू होने से ठीक पहले या shell prompt पर background में। अगर वह update fail हो जाए या आप offline हों, तो installed version चलता है। `omarchy update` बाकी Omarchy के साथ installed agents को update करता है, और `mup` केवल mise-managed tools को update करता है।

किसी agent का अपना updater, जैसे `claude update`, `codex update`, या किसी app में update button, mise-managed install को update नहीं करता। `codex update` fail हो जाता है, और `claude update` success report कर सकता है जबकि वह एक अलग copy install कर दे जिसे mise track नहीं करता। अगर आप इसके बजाय किसी agent के native installer और updater का इस्तेमाल करना पसंद करते हैं, तो उसे `disable_tools` में जोड़ें; देखें [पहले से install किए गए CLI tools](18-development-tools.md#preinstalled-cli-tools)।

ज़रूरत पड़ने से पहले सभी configured lazy tools को install करने के लिए `mise install --include-lazy` run करें। इसमें agents के साथ-साथ Omarchy के दूसरे default CLI tools भी शामिल हैं। किसी एक tool को install करने या अपनी खुद की installation का इस्तेमाल करने के लिए देखें [पहले से install किए गए CLI tools](18-development-tools.md#preinstalled-cli-tools)।

`grok` mise के first-party `grok` package के ज़रिए install होता है, उसी तरह जैसे `claude` और `codex`। `grok` run करें, या उसे _Agent > Harness_ के तहत चुनें। x.ai पर मौजूद `curl | bash` installer को छोड़ दें। वह path दूसरी copy को `~/.grok/bin` में डाल देता है, उसे `PATH` पर prepend कर देता है, और Omarchy के wrapper को overwrite कर देता है।

`dsh` अपना browser UI `127.0.0.1:3080` पर खोलता है, जिसमें launch directory उसका default workspace होता है। इसका browser UI कोई starting prompt नहीं लेता, इसलिए `omarchy agent prompt` इसे prompt को आपके clipboard पर रखकर खोलता है ताकि आप उसे paste कर सकें। Omarchy इसे DeepSeek के no-approval permission preset के साथ शुरू करता है। जब आप DeepSeek Harness के official model API का इस्तेमाल करते हैं तो वह session logs DeepSeek को upload करता है; उसके browser UI में _Settings > General > Upload Session Log_ के तहत इसे बंद करें। आप उसे जो feedback भेजते हैं वह भी session के साथ upload होता है, जब तक आप उसे `DSH_TELEMETRY_MODE=DISABLED` के साथ शुरू न करें।

### Default agent

अपने default agent को `omarchy default agent <name>` से या Omarchy Menu (`Super + Space`) में _Agent > Harness_ के तहत चुनें। अगर agent अभी install नहीं हुआ है, तो उसे चुनने पर वह पहले install होता है, और उसे app launcher में Agent के बगल में उसका अपना launcher भी मिलता है। एक नए Omarchy पर एक बार की notification के साथ आपको यह चुनाव करने के लिए आमंत्रित किया जाएगा।

Claude को चुनने पर Chromium, Chrome, Brave, Brave Origin और Edge के लिए उसके browser extension को setup करने का प्रयास भी होता है। Extension setup सभी users पर लागू होता है और आपसे आपका system password माँग सकता है; cancel करने या extension install fail होने पर भी Claude चुना और launch किया जाता है। अपना browser restart करें, prompt मिलने पर extension enable करें, और उसे connect करना पूरा करने के लिए Claude में sign in करें। Connection की जाँच करने के लिए Claude में `/chrome` run करें। Firefox और Zen इस extension को support नहीं करते। अगर इस setup के जुड़ने से पहले Claude पहले से आपका default था, तो extension install करने के लिए उसे फिर से चुनें।

एक बार चुन लेने के बाद, `Super + Shift + Ctrl + A` default agent को एक dedicated terminal window में launch करता है (या अगर आपने अभी तक नहीं चुना है तो picker सामने लाता है)। आप उसे `omarchy agent prompt "Review this project"` के साथ सीधे किसी task में भी launch कर सकते हैं। Freebuff और DeepSeek Harness कोई starting prompt नहीं लेते, इसलिए वे इसके बजाय prompt को आपके clipboard पर रखकर paste करने के लिए खुलते हैं। इस तरह launch किए गए agents अपने-अपने don't-stop-to-ask modes में unattended चलते हैं, इसलिए तैयार रहें कि वे सचमुच कुछ करेंगे! MiniMax Code के पास उसके interactive sessions के लिए ऐसा कोई mode नहीं है, इसलिए वह हमेशा की तरह permissions माँगता है। और चूँकि agents आपकी home directory के लिए trust को याद रखने से इनकार करते हैं, इसलिए `$HOME` से launches इसके बजाय `~/Work` में शुरू होते हैं।

Terminal shortcuts भी हैं: `a` default agent को current terminal में inline चलाता है, जबकि `c`, `cx` और `cy` OpenCode, Claude Code और Codex को सीधे शुरू करते हैं (फिर से उनके auto-approving modes में)। Theme बदलाव agents के साथ भी sync होते हैं: जब आप Omarchy theme बदलते हैं तो Claude Code, Pi, OpenCode और Hermes (एक बार Omarchy ने उसे install कर दिया हो) सभी साथ चलते हैं।

### आपके agent instructions

हर agent के लिए personal rules `~/.agents/AGENTS.md` में जाते हैं, shared skills के बगल में `~/.agents/skills` में। इसे _Agent > Instructions_ के तहत खोलें, जो इसे हर उस harness में भी link करता है जो अपनी global file रखता है: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, Copilot का `~/.copilot/copilot-instructions.md`, और इसी तरह अन्य। Crush और Amp `~/.config/AGENTS.md` link को पढ़ते हैं, जबकि omp, Kimi और DeepSeek Harness सीधे `~/.agents/AGENTS.md` को पढ़ते हैं। Default agent चुनने पर वह भी link हो जाता है। अगर पहले से कोई shared file नहीं थी तो आपकी पहले से मौजूद instructions file ही shared file बन जाती है; अन्यथा उसे link के बगल में `.bak` के रूप में रखा जाता है। किसी अन्य agent को install करने के बाद फिर से link करने के लिए `omarchy agent instructions` run करें।

### Agents panel

Top bar में एक agents icon है। इससे पहले कि आपने कोई agent setup किया हो, उसका panel आपको Claude, Codex या Grok में sign in करने की प्रक्रिया से ले जाता है, और पहला वाला आपका default agent बन जाता है। उसके बाद, panel हर subscription को एक ही page पर रखता है: हर agent और account उसके plan के साथ, उसके 5-hour session और weekly limits में से प्रत्येक के लिए एक meter के साथ reset होने तक के समय के साथ (सटीक percentage के लिए hover करें), या बचा हुआ prepaid balance, एक ऐसी line के नीचे जो उन सभी में आपके उपयोग के बीच rotate होती है, जैसे इस सप्ताह के tokens और आपका सबसे ज़्यादा इस्तेमाल किया गया model। _Make something cool_ के तहत यह किसी नए theme, plugin, app या game के लिए starter prompts देता है जो task को आपके default agent को सौंप देते हैं। Apps उसी तरह बनाई जाती हैं जैसे Omarchy की अपनी Hype, Monologue और Omacut हैं, C++ और Qt Quick में, omarchy-make-app agent skill का पालन करते हुए, और उनके लिए ज़रूरी compiler और Qt pieces installed आते हैं। Games `~/Games/vibes` में एक single three.js page होती हैं, omarchy-make-game agent skill का पालन करते हुए, और सभी current theme में एक Game Vibes launcher से खुलती हैं; वे web से three.js load करती हैं, इसलिए उन्हें शुरू होने के लिए connection चाहिए। Claude Code, Codex, Grok, Kimi, Cursor और उसके Grok Bot allowance, GitHub Copilot, Muse, Antigravity और Devin out of the box अपनी limits के साथ covered हैं, Kimchi अपने plan, prepaid credits और spend budgets के साथ, और Hermes, Mistral Vibe और Qwen Code एक बार आपने उन्हें इस्तेमाल कर लिया हो तो अपने sessions और tokens दिखाते हैं। pi, omp या opencode के ज़रिए आप जिन provider plans और keys का इस्तेमाल करते हैं वे भी दिखाई देते हैं: OpenCode Zen और Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan और Synthetic अपनी limits के साथ; OpenRouter और DeepSeek अपने prepaid balances के साथ; Fireworks पिछले 30 दिनों में उसके spend के साथ; और वे models जिन्हें आप अपने खुद के hardware पर चलाते हैं Local models के तहत। हर agent को एक बार गिना जाता है, उसी के तहत जो उसे bill करता है, चाहे आप उसे कितने भी harnesses के ज़रिए चलाएँ।

Panel के लिए bar icon पर left-click करें या `Super + Ctrl + X` दबाएँ, अपने default agent को launch करने के लिए right-click करें, और refresh करने के लिए middle-click करें। इसके पीछे के usage records हर 15 मिनट में `omarchy agent usage update` द्वारा regenerate होते हैं, और panel synced folder के ज़रिए आपकी दूसरी machines से usage को merge भी कर सकता है। Full settings के लिए `$OMARCHY_PATH/shell/plugins/agents/` के तहत README देखें।

### कई subscriptions

अगर आप एक से ज़्यादा Claude, Codex या Grok plan के लिए भुगतान करते हैं — जैसे एक personal Max और एक work वाला — तो Omarchy उन सभी को signed in रख सकता है और उनके बीच आ-जा सकता है। Agents panel में + के साथ subscription जोड़ें, जो आपको वहीं इस प्रक्रिया से ले जाता है, या `omarchy agent account add claude Work` (या `codex`, या `grok`) के साथ। अगर CLI missing है तो यह उसे install करता है। किसी provider के लिए पहला account आपके normal browser के ज़रिए sign in करता है, ठीक वहाँ जहाँ CLI हमेशा देखता है। उसके बाद का हर account एक private window के ज़रिए sign in करता है, ताकि जिस account में आपका browser पहले से signed in है वह गलती से न चुना जाए; वहाँ उस account के रूप में sign in करें जिसे आप जोड़ रहे हैं, और पहले से खुली किसी भी private window को पहले बंद कर दें। इसके लिए CLI से कभी log out न करें: log out करने से saved sign-in revoke हो जाता है, और उस account को फिर से जोड़ना पड़ेगा।

अपनी subscription logins को SSH पर किसी दूसरी Omarchy machine पर copy करने के लिए `omarchy agent account copy user@laptop` run करें। जब destination के पास कोई installed नहीं होता तो sender एक temporary receiver देता है, इसलिए पुरानी Omarchy machines बिना update के accounts receive कर सकती हैं। Installed receivers को precedence मिलती है। यह सभी Claude, Codex और Grok subscriptions को copy करता है; उन्हें चुनने के लिए provider names जोड़ें, जैसे `omarchy agent account copy laptop claude` में। Account names और command IDs source से match करते हैं, जिनमें destination पर पहले से मौजूद accounts भी शामिल हैं। असंबंधित destination accounts को अगर उनके names conflict करते हैं तो numeric suffix मिलता है, और settings, skills, plugins और conversation history हर machine पर local रहती हैं।

Destination की मौजूदा credentials रखी जाती हैं। कोई source account जो वहाँ पहले से signed in है, उसका name उसकी credentials को बदले बिना synchronize हो जाता है; दूसरे accounts उसके साथ जोड़ दिए जाते हैं। Matching accounts के लिए saved credentials को बदलने के लिए, destination पर उस account के sessions quit करने के बाद `omarchy agent account copy --replace laptop claude` का इस्तेमाल करें। एक नए destination को source का active account और switching preferences भी मिलते हैं; एक स्थापित destination अपनी preferences रखता है।

Credentials SSH के ज़रिए जाते हैं और destination पर private files में store होते हैं, इसलिए केवल उन machines पर copy करें जिन पर आप भरोसा करते हैं। यह एक बार की copy है, ongoing synchronization नहीं। Codex refresh tokens किसी दूसरी machine द्वारा rotate किए जा सकते हैं, जिससे copied login को renewal की ज़रूरत पड़ सकती है; कई machines पर एक साथ इस्तेमाल के लिए अलग-अलग sign-ins सबसे विश्वसनीय विकल्प रहते हैं। देखें [Codex की account authentication मार्गदर्शिका](https://developers.openai.com/codex/auth/ci-cd-auth)।

हर provider के लिए एक account active होता है, और हर नया session उसी के रूप में शुरू होता है: `cx`, `cy`, एक plain `claude`, `codex` या `grok`, `omarchy agent` के ज़रिए launch किया गया कुछ भी, और scripts या editors जो CLI को `PATH` पर पाते हैं। `omarchy agent account use work` के साथ switch करें (और `omarchy agent account use main` के साथ वापस), या panel में किसी account का number दबाकर फिर `Enter` दबाकर (या उसके Use button पर click करके)। चल रहे Claude sessions भी switch होते हैं, उनके अगले message से: हर Claude session `~/.claude` में चलता है, जिसमें हमेशा active account का sign-in होता है। किसी पुराने Omarchy द्वारा किसी account के अपने folder में शुरू किया गया Claude session उस sign-in को तब तक रखता है जब तक वह quit न हो, इसलिए switch उन sessions के नाम बताता है और उनके चले जाने पर अपने आप पूरा हो जाता है। चल रहे Codex और Grok sessions उस account पर रहते हैं जिसके साथ वे शुरू हुए थे। Conversation history, settings, skills और plugins accounts में shared होते हैं, इसलिए उसी folder में `claude --continue` नए account पर वहीं से आगे बढ़ता है जहाँ आपने छोड़ा था।

एक से ज़्यादा account होने पर, panel हर account की limits को साथ-साथ दिखाता है, जिसमें active account marked होता है। Default रूप से Omarchy आपको notify करता है जब active account किसी limit के 95% को पार कर जाता है, और notification पर click करने से सबसे ज़्यादा headroom वाले account पर switch हो जाता है। Panel में किसी account की line पर hover करें और Use के बगल में दिखाई देने वाले Autoswitch पर click करें (या `m` दबाएँ), या इसके बजाय उसे अपने आप switch कराने के लिए `omarchy agent account mode auto` run करें; जब यह on होता है, Autoswitch Use की जगह ले लेता है, और उस पर फिर click करने से notify करने पर वापस आ जाता है। Threshold बदलने के लिए एक number जोड़ें, जैसे `omarchy agent account mode auto 90` में। अगर हर account threshold से ऊपर है, तो आपको इसके बारे में एक बार सुनने को मिलेगा, साथ में यह भी कि कौन-सा account सबसे पहले free होता है। जब कोई active account अपने threshold के 15 points के अंदर होता है (default पर 80%), तो उसकी limits की जाँच हर 15 के बजाय हर तीन मिनट में होती है।

`omarchy agent account list` हर account और उसकी नवीनतम limits दिखाता है, `omarchy agent account remove work` एक को भुला देता है, और `omarchy agent account rename primary Hey` एक का नाम बदल देता है (या panel में किसी account के name पर click करें)। ये commands आपके default agent के accounts पर काम करते हैं; दूसरे provider तक पहुँचने के लिए, पहले उसका नाम दें, जैसे `omarchy agent account use codex side` में। `~/.claude` या `~/.codex` में आपके पास पहले से मौजूद login ही _Main_ account है। Codex का वहीं रहता है जहाँ वह है; Claude का तब अपने ही folder में इंतज़ार करता है जब कोई दूसरा account active होता है। लगभग आठ घंटे से ज़्यादा समय तक unused छोड़ा गया कोई account _Sign-in required_ दिखा सकता है; panel में ही उस account को फिर से sign in करने के लिए उस पर click करें, या उस पर switch करके एक session शुरू करें, जो अपने आप sign-in को refresh कर देता है। `claude mcp add` के साथ आप जो MCP servers जोड़ते हैं वे हर Claude account तक पहुँचते हैं, चूँकि वे सभी `~/.claude` में चलते हैं; Codex और Grok के लिए, किसी account को जोड़ते समय आपके पास मौजूद servers उसके साथ आ जाते हैं, लेकिन बाद वाले केवल उस account तक पहुँचते हैं जिसमें आपने उन्हें जोड़ा था। Claude Desktop अपना sign-in खुद रखता है, और CLI binary के absolute path के साथ configured Codex या Grok tools switch का पालन नहीं करते। एक explicit `CLAUDE_CONFIG_DIR`, `CODEX_HOME` या `GROK_HOME` चुने गए account पर precedence लेता है।

### Crash diagnosis

Omarchy process crashes के लिए systemd-coredump पर नज़र रखता है। एक बार आपने default agent चुन लिया हो, तो आपका कोई भी program जो core dump करता है एक "Process crashed" notification लाता है — उस पर click करें, और crash को आपके default agent को Omarchy की omarchy-diagnose-crash skill के साथ सौंप दिया जाता है, जो agent को core dump से तथ्यों को स्थापित करने और यह तय करने की प्रक्रिया से ले जाती है कि crash upstream report करने लायक है या नहीं। आप इसे `coredumpctl list` से किसी भी PID के खिलाफ `omarchy agent crash <pid>` के साथ हाथ से भी चला सकते हैं।

Watching default रूप से on है। इसे _Trigger > Toggle > Crash Capture Off_ के तहत (या `omarchy toggle crash-capture` के साथ) बंद करें और notifications रुक जाती हैं; `omarchy agent crash <pid>` हाथ से फिर भी काम करता है।

Crashes को एक बार में एक program के लिए भी silence किया जा सकता है, जो diagnosis अंत में आपको offer करता है। `omarchy crash mute hyprland` केवल उस program के लिए notifications रोकता है, `omarchy crash mute hyprland off` उन्हें वापस लाता है, और अकेले `omarchy crash mute` सूची देता है कि आपने क्या mute किया है। यह binary के path को उसके name जितनी ही खुशी से लेता है, इसलिए `omarchy crash mute /usr/bin/hyprland` वही काम करता है। किसी ऐसे name को quote करें जिसमें space हो, जैसे `omarchy crash mute 'Some App'` में। बाकी सब फिर भी notify करता है, और muted program फिर भी crash होता है — यह reminder को छिपाता है, यह कुछ ठीक नहीं करता।

### Desktop apps

_Install > AI_ menu में कुछ graphical AI apps भी हैं: Amp Desktop, Antigravity Desktop, ChatGPT desktop app, Claude desktop app (Anthropic का Linux beta, Chat, Cowork और Claude Code tabs के साथ), xAI के models के साथ chat करने के लिए Grok Bot, Herdr Desktop, Hermes Desktop, OpenClaw, Perplexity desktop app, और T3 Code। Grok Bot desktop chat app है। Coding agent `grok` command है।

Hermes Desktop वह है जिसके बारे में जानना ज़रूरी है, क्योंकि किसी machine में एक Hermes होता है, और वह app का होता है: Hermes हमेशा केवल app के ज़रिए ही install होता है, और default agent जो `hermes` command चलाता है वह app का ही होता है। Hermes को default agent के रूप में चुनने पर वही चीज़ install होती है जो _Install > AI_ entry करती है: package, और `~/.hermes` के तहत एक Hermes runtime जो Hermes के अपने installer द्वारा setup किया जाता है, जिसमें पहली बार कुछ मिनट लगते हैं। वह runtime ही वह एक Hermes है जिसका इस्तेमाल terminal `hermes` command, default agent और app सभी करते हैं, और यह Omarchy release का इंतज़ार करने के बजाय `hermes update` के साथ खुद को update करता है। इसे install करने पर Hermes को Omarchy theme भी एक skin के रूप में मिलता है जिसका नाम `omarchy` है, जिसका पालन हर Hermes surface आपके theme बदलने पर करता है; अगर आप नहीं चाहते कि ऐसा हो तो Hermes की Appearance settings के तहत या `/skin` के साथ कोई दूसरा चुनें, और Omarchy उस चुनाव को अकेला छोड़ देता है। _Remove > AI_ के तहत app को हटाने पर Hermes पहले बंद होता है, gateway समेत, वह runtime उसके साथ ले जाता है, और आपकी chats, memories और वे skills रखता है जो Hermes ने अपने लिए लिखी हैं जब तक आप उसे अन्यथा न कहें: यह पूछता है, default no रखते हुए, कि क्या वह data और आपकी connection settings भी जानी चाहिए।

OpenClaw का desktop experience उसका Control UI है, जो उसके अपने local gateway द्वारा backed एक web app के रूप में खुलता है। OpenClaw `~/.openclaw` में रहता है और खुद को update करता है: Control UI के "Update Gateway" button का इस्तेमाल करें या `openclaw update` run करें, और gateway नए version पर restart हो जाता है। Omarchy केवल वह release चुनता है जिससे एक fresh install शुरू होता है। OpenClaw आपका default agent भी हो सकता है: उसे _Agent > Harness_ के तहत चुनने पर `~/.openclaw` में वही copy setup हो जाती है, और agent OpenClaw के terminal UI को उसके gateway से जुड़ा हुआ खोलता है। _Remove > AI_ के तहत OpenClaw को हटाने पर gateway service और app उसके साथ जाते हैं और फिर पूछा जाता है कि क्या `~/.openclaw` भी जाना चाहिए, चूँकि उसमें OpenClaw खुद और उसके द्वारा download किए गए plugin runtimes के साथ आपकी chats और credentials होते हैं; default उसे रखता है, और OpenClaw को फिर से install करने पर वह उसे फिर से उठा लेता है।

Herdr Desktop [Herdr](https://herdr.dev) desktop app है: terminals और coding agents के spaces, tabs और panes जो window बंद करने पर उसके core में चलते रहते हैं। यह किसी package के बजाय Herdr के अपने installer से आता है, इसलिए यह `~/.local/share/herdr-app` में रहता है, जब आपके पास पहले से कोई न हो तो अपने core को `~/.local/bin/herdr-core` में साथ लाता है, और दोनों को खुद update करता है। यह उस `herdr` command के बगल में बैठता है जिसे Omarchy `Super + Ctrl + Return` पर देता है, उसे replace करने के बजाय, और उस command की direct keys पाता है: `Alt + Return` और `Alt + Shift + Return` एक pane को नीचे या दाईं ओर split करते हैं, `Alt + Escape` उसे बंद करता है, `Ctrl + Alt + Arrow` panes के बीच move करता है, `Alt + 1..9` और `Alt + Left/Right` एक tab चुनते हैं, और `Alt + Up/Down` spaces के बीच move करते हैं। `Ctrl + 1..9` एक space चुनता है और `Alt + Shift + Up/Down` agents के बीच step करता है। `Ctrl + Space` prefix keys केवल terminal तक रहती हैं, चूँकि app एक sequence के लिए plain Ctrl key को hold नहीं कर सकता। Omarchy इन्हें `~/.config/herdr-app/keys.json` में लिखता है, और `omarchy-refresh-herdr-app` उन्हें वापस रखता है। इसे install करने पर Herdr का Omarchy theme चुना जाता है, जो उसके बाद से आपके Omarchy theme का पालन करता है। Herdr light mode के लिए एक theme और dark के लिए एक रखता है, इसलिए dark और light Omarchy theme के बीच switch करने के बाद, दूसरे mode के लिए Herdr के theme picker में Omarchy को एक बार फिर चुनें।

T3 Code किसी package के बजाय `~/.local/share/t3code` में अपने official AppImage release से चलता है, इसलिए यह खुद को update करता है। इसे install करने पर पूछा जाता है कि Stable या Nightly channel पर शुरू करना है; बाद में T3 Code की settings में switch करें। आपकी threads और settings `~/.t3` में रहती हैं, और _Remove > AI_ के तहत T3 Code को हटाने पर वे उसके साथ जाती हैं।

### Local models

अपने coding agents के लिए अपने खुद के machine पर एक open model चलाएँ। आपके prompts और code machine पर रहते हैं; model को भेजा गया कुछ भी उसे नहीं छोड़ता। इससे शुरू करें:

```bash
omarchy agent local use best
```

या, top bar के agents panel में, + और फिर Local AI चुनें, जो तब दिखाई देता है जब कोई model इस machine पर fit बैठता है। Podman, जो models को चलाता है, Omarchy के साथ आता है, NVIDIA machine पर NVIDIA का container toolkit भी, जो उन्हें GPU देता है; अगर इनमें से कोई missing है, तो पहला setup उसे install करता है। फिर Omarchy इस machine के लिए recommended model चुनता है, उसे download करता है, और शुरू करता है। Tens of GB के download की और model चलने के दौरान machine की ज़्यादातर memory के इस्तेमाल में होने की उम्मीद करें: Flash Next अपने पूरे 256K context के साथ लगभग 100 GiB इस्तेमाल करता है। अगर दूसरे models को वह memory चाहिए जो उसे चाहिए, तो यह stopped setup होता है, एक बार आप किसी एक को रोक दें तो शुरू होने के लिए तैयार। Model logout पर रुक जाता है; जब आपको किसी और चीज़ के लिए memory चाहिए तो उसे खुद रोकें।

`omarchy agent local list` options दिखाता है और बताता है कि कुछ क्यों fit नहीं बैठते। किसी दूसरे को setup करने के लिए `omarchy agent local use <recipe>` run करें। आज, 128 GB Strix Halo machines के लिए `qwen3.8-flash-next-gufo` और `qwen3.8-27b-gufo` उपलब्ध हैं; 27B लगभग 40 GiB लेता है, इसलिए यह दूसरे काम के लिए जगह छोड़ता है। Intel के Arc B390 वाले 64 GB laptop पर, `qwen3.6-35b-a3b-llamacpp` लगभग 30 GiB में चलता है। New recipes और recommendations package के ज़रिए `omarchy update` के साथ आते हैं।

आपके द्वारा setup किया गया हर model agents panel में अपनी line पाता है, आपकी subscriptions के बगल में: उसे शुरू करने के लिए play, उसे रोकने और उसकी memory free करने के लिए pause, और उस पर अपने agent को खोलने के लिए terminal button। कई एक साथ चल सकते हैं जब वे memory में साथ fit बैठते हैं; अगर कोई fit नहीं बैठता, तो Omarchy बताता है कि किस running model को रोकना है। उन्हें reorder करने के लिए lines को drag करें, और किसी model और उसके download को हटाने के लिए selected line पर Delete दबाएँ।

आपके द्वारा setup किया गया हर model app launcher में अपनी entry भी पाता है, model के नाम के तहत और उसके maker के logo के साथ, उसी तरह जैसे Claude, Codex या Grok में sign in करने पर एक जुड़ता है। यह उस model पर आपके agent को खोलता है, और अगर model नहीं चल रहा है तो पहले उसे शुरू करता है: terminal उसे load होते दिखाता है और उसके up होने पर agent को सौंप देता है। किसी model को हटाने से उसकी entry हट जाती है।

हर model coding के लिए नहीं है। Image, video और music models इसके बजाय Fantasi में खुलते हैं, Omarchy का app इस machine पर चल रहे model के साथ pictures, video और music बनाने के लिए, उनकी launcher entry से और agents panel में उनकी line से।

कोई model ठीक उसी तरह चलता रहता है जैसे उसे setup किया गया था, इसलिए Omarchy update कभी आपके agents के नीचे किसी को restart नहीं करता। जब Omarchy के पास किसी ऐसे model के लिए नया runtime या नए weights हों जिसे आपने setup किया है, तो उसकी line एक update button दिखाती है: उसे दबाएँ और model background में फिर से setup होता है, केवल वही download करता है जो बदला है, और नए version पर restart होता है। जो model stopped था वह stopped रहता है। `omarchy agent local update` terminal से हर model के लिए वही करता है।

Command line से, `omarchy agent local start <recipe>` और `omarchy agent local stop <recipe>` वही करते हैं, `omarchy agent local status` हर model दिखाता है, और `omarchy agent --local` आपके default agent को अंतिम model पर खोलता है जिसे आपने शुरू किया था। pi, OpenCode और Qwen Code किसी एक का इस्तेमाल कर सकते हैं; किसी अन्य default के साथ यह pi में खुलता है, या OpenCode में अगर आपके पास pi नहीं है। pi आपके द्वारा setup किए गए हर model को, और उन machines पर जिन्हें आपने pair किया है, अपने model picker में list भी करता है, इसलिए plain `pi` भी उन तक पहुँचता है। कोई भी OpenAI-compatible client भी connect कर सकता है: `status` हर model का address दिखाता है (पहला `http://127.0.0.1:11435/v1` है), recipe name ही model है, और key `~/.config/omarchy/agent-local/key` में है।

`omarchy agent local remove <recipe>` किसी model और उन downloads को delete करता है जिनका कोई दूसरा model इस्तेमाल नहीं करता।

Third-party runtimes को उनके publisher के साथ labeled किया जाता है। Omarchy हर model को बिना network access के चलाता है।

### Local LLMs

Omarchy local LLM models चलाने के दो तरीके सुझाता है: LM Studio और Ollama। LM Studio open-weight models को खोजने, उन्हें install करने और चलाने के लिए GUI interface देता है। आसानी से शुरू करने का यह बेहतरीन तरीका है। Ollama इसी तरह करने के लिए CLI देता है। लेकिन अगर आप local models में नए हैं, तो मैं LM Studio से शुरुआत करूँगा। आप Omarchy Menu में _Install > AI_ के तहत किसी को भी install कर सकते हैं।

### Omarchy skills

Agent skills AI को specific tools को specific तरीके से इस्तेमाल करने में मदद करते हैं, और Omarchy उनमें से सात देता है। omarchy skill system को tailor करने को cover करता है, जैसे आपके Hyprland config को tweak करना या bar को adjust करना। omarchy-make-theme, omarchy-make-plugin, omarchy-make-app और omarchy-make-game कुछ नया बनाने को cover करते हैं, omarchy-contribute किसी bug को report करने या fix को upstream भेजने को cover करता है, और omarchy-diagnose-crash किसी crash के core dump पर काम करता है। वे Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` और हर `~/.hermes/profiles/*/skills`), और generic `~/.agents/skills` location के लिए skill directories में symlinked हैं, इसलिए ज़्यादातर harnesses उन्हें automatically उठा लेते हैं। समान नाम वाला आपका अपना skill folder precedence लेता है।

लेकिन आपको इन skills को experimental मानना चाहिए। अलग-अलग models इसे अलग-अलग प्रभाव के साथ इस्तेमाल करेंगे। सबसे अच्छा है कि पहले plan mode में चलाएँ, ताकि आपको अंदाज़ा हो कि agent क्या बदलना चाहेगा। और फिर changes को rollback करने या अगर agent सब कुछ गड़बड़ कर दे तो `omarchy reinstall configs` को invoke करने के लिए भी तैयार रहें।
