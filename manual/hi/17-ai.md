# AI

Omarchy आपके लिए डिफ़ॉल्ट चुने बिना नीचे दिए गए कोडिंग एजेंटों के लिए लॉन्चर शामिल करता है। पहली बार उपयोग करने पर उसका CLI इंस्टॉल करने के लिए कोई कमांड चलाएँ, फिर संकेत मिलने पर प्रमाणीकरण करें। Hermes इसका अपवाद है: पहली बार उपयोग करने पर उसके लिए कुछ भी इंस्टॉल नहीं होता, और उसे चुनने पर Hermes Desktop इंस्टॉल होता है, जैसा कि नीचे _डेस्कटॉप ऐप्स_ में बताया गया है।

### एजेंटों को इंस्टॉल करना और अपडेट करना

Hermes को छोड़कर, ये एजेंट mise की lazy installation का उपयोग करते हैं: पहला लॉन्च CLI को इंस्टॉल करता है, और बाद के लॉन्च उसी का पुनः उपयोग करते हैं। mise किसी इंस्टॉल किए गए एजेंट के लिए नए रिलीज़ की जाँच हर चार घंटे में अधिकतम एक बार करता है, या तो उसके शुरू होने से ठीक पहले या shell prompt पर पृष्ठभूमि में। यदि वह अपडेट विफल हो जाता है या आप ऑफ़लाइन हैं, तो इंस्टॉल किया गया संस्करण चलता है। `omarchy update` शेष Omarchy के साथ इंस्टॉल किए गए एजेंटों को अपडेट करता है, और `mup` केवल mise-प्रबंधित टूल को अपडेट करता है।

किसी एजेंट का अपना अपडेटर, जैसे `claude update`, `codex update`, या किसी ऐप में कोई अपडेट बटन, mise-प्रबंधित इंस्टॉल को अपडेट नहीं करता। `codex update` विफल हो जाता है, और `claude update` सफलता की रिपोर्ट करते हुए भी एक अलग प्रति इंस्टॉल कर सकता है जिसे mise ट्रैक नहीं करता। यदि आप इसके बजाय किसी एजेंट के मूल इंस्टॉलर और अपडेटर का उपयोग करना पसंद करते हैं, तो उसे `disable_tools` में जोड़ें; [Preinstalled CLI tools](18-development-tools.md#preinstalled-cli-tools) देखें।

आपको उनकी आवश्यकता पड़ने से पहले सभी कॉन्फ़िगर किए गए lazy टूल इंस्टॉल करने के लिए, `mise install --include-lazy` चलाएँ। इसमें एजेंटों के साथ-साथ Omarchy के अन्य डिफ़ॉल्ट CLI टूल भी शामिल हैं। किसी एक टूल को इंस्टॉल करने या अपने स्वयं के इंस्टॉलेशन का उपयोग करने के लिए [Preinstalled CLI tools](18-development-tools.md#preinstalled-cli-tools) देखें।

`grok` को mise के first-party `grok` पैकेज के माध्यम से इंस्टॉल किया जाता है, उसी तरह जैसे `claude` और `codex` को किया जाता है। `grok` चलाएँ, या उसे _Agent > Harness_ के अंतर्गत चुनें। x.ai पर दिए गए `curl | bash` इंस्टॉलर को छोड़ दें। वह तरीका `~/.grok/bin` में दूसरी प्रति डाल देता है, उसे `PATH` में सबसे आगे जोड़ देता है, और Omarchy के wrapper को अधिलेखित कर देता है।

`dsh` अपना browser UI `127.0.0.1:3080` पर खोलता है, जिसमें लॉन्च डायरेक्टरी उसका डिफ़ॉल्ट workspace होती है। उसका browser UI कोई प्रारंभिक prompt नहीं लेता, इसलिए `omarchy agent prompt` उसे आपके clipboard पर मौजूद prompt के साथ खोलता है ताकि आप उसे paste कर सकें। Omarchy उसे DeepSeek के no-approval permission preset के साथ शुरू करता है। जब आप DeepSeek Harness के आधिकारिक model API का उपयोग करते हैं तो वह session logs DeepSeek को अपलोड करता है; उसके browser UI में _Settings > General > Upload Session Log_ के अंतर्गत उसे बंद करें। आप जो feedback उसे भेजते हैं वह भी session के साथ अपलोड किया जाता है, जब तक कि आप उसे `DSH_TELEMETRY_MODE=DISABLED` के साथ शुरू न करें।

### डिफ़ॉल्ट एजेंट

अपना डिफ़ॉल्ट एजेंट `omarchy default agent <name>` से चुनें या Omarchy Menu (`Super + Space`) में _Agent > Harness_ के अंतर्गत चुनें। यदि एजेंट अभी तक इंस्टॉल नहीं है, तो उसे चुनने पर पहले वह इंस्टॉल होता है। नया Omarchy आपको एक बार दिखाई देने वाली सूचना के साथ यह विकल्प चुनने के लिए आमंत्रित करेगा।

Claude चुनने पर Chromium, Chrome, Brave, Brave Origin, और Edge के लिए उसके browser extension को सेट अप करने का भी प्रयास किया जाता है। extension सेटअप सभी उपयोगकर्ताओं पर लागू होता है और आपसे आपका system password माँग सकता है; extension इंस्टॉल रद्द करने या उसके विफल होने पर भी Claude चुना और लॉन्च किया जाता है। अपना browser पुनः शुरू करें, संकेत मिलने पर extension सक्षम करें, और उसे जोड़ना पूरा करने के लिए Claude में sign in करें। कनेक्शन की जाँच करने के लिए Claude में `/chrome` चलाएँ। Firefox और Zen इस extension का समर्थन नहीं करते। यदि यह सेटअप जुड़ने से पहले ही Claude आपका डिफ़ॉल्ट था, तो extension इंस्टॉल करने के लिए उसे फिर से चुनें।

एक बार चुन लेने के बाद, `Super + Shift + Ctrl + A` डिफ़ॉल्ट एजेंट को एक समर्पित terminal window में लॉन्च करता है (या यदि आपने अभी तक नहीं चुना है तो picker सामने लाता है)। आप उसे सीधे किसी कार्य के साथ भी लॉन्च कर सकते हैं, जैसे `omarchy agent prompt "Review this project"` से। Freebuff और DeepSeek Harness कोई प्रारंभिक prompt नहीं लेते, इसलिए वे इसके बजाय आपके clipboard पर मौजूद prompt के साथ खुलते हैं ताकि आप उसे paste कर सकें। इस तरह लॉन्च किए गए एजेंट अपने-अपने don't-stop-to-ask modes में बिना किसी निगरानी के चलते हैं, इसलिए तैयार रहें कि वे सचमुच कुछ करेंगे! MiniMax Code के पास उसके interactive sessions के लिए ऐसा कोई mode नहीं है, इसलिए वह हमेशा की तरह अनुमतियाँ माँगता है। और चूँकि एजेंट आपकी home directory के लिए trust याद रखने से इनकार करते हैं, इसलिए `$HOME` से किए गए लॉन्च इसके बजाय `~/Work` में शुरू होते हैं।

terminal shortcuts भी हैं: `a` डिफ़ॉल्ट एजेंट को वर्तमान terminal में inline चलाता है, जबकि `c`, `cx`, और `cy` OpenCode, Claude Code, और Codex को सीधे शुरू करते हैं (फिर से उनके auto-approving modes में)। Theme में बदलाव एजेंटों के साथ भी सिंक होते हैं: जब आप Omarchy theme बदलते हैं तो Claude Code, Pi, OpenCode, और Hermes (एक बार Omarchy ने उसे इंस्टॉल कर दिया हो) सभी उसके साथ चलते हैं।

### आपके एजेंट निर्देश

हर एजेंट के लिए व्यक्तिगत नियम `~/.agents/AGENTS.md` में जाते हैं, `~/.agents/skills` में shared skills के बगल में। उसे _Agent > Instructions_ के अंतर्गत खोलें, जो उसे प्रत्येक उस harness में भी लिंक करता है जो अपनी स्वयं की global file रखता है: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, Copilot की `~/.copilot/copilot-instructions.md`, इत्यादि। Crush और Amp `~/.config/AGENTS.md` लिंक को पढ़ते हैं, जबकि omp, Kimi, और DeepSeek Harness सीधे `~/.agents/AGENTS.md` को पढ़ते हैं। डिफ़ॉल्ट एजेंट चुनने पर वह भी लिंक हो जाता है। आपके पास पहले से मौजूद कोई instructions file shared वाली बन जाती है यदि अभी तक कोई नहीं थी; अन्यथा उसे लिंक के बगल में `.bak` के रूप में रखा जाता है। कोई अन्य एजेंट इंस्टॉल करने के बाद फिर से लिंक करने के लिए `omarchy agent instructions` चलाएँ।

### एजेंटों का पैनल

top bar में एक agents icon है। इससे पहले कि आपने कोई एजेंट सेट अप किया हो, उसका पैनल आपको Claude, Codex, या Grok में sign in करने की प्रक्रिया से ले जाता है, और पहला वाला आपका डिफ़ॉल्ट एजेंट बन जाता है। उसके बाद, पैनल हर subscription को एक ही पेज पर रखता है: प्रत्येक एजेंट और खाता उसकी योजना के साथ, उसके 5-hour session और weekly limits में से प्रत्येक के लिए एक मीटर जिसके साथ उसके reset होने तक का समय होता है (सटीक प्रतिशत के लिए hover करें), या शेष prepaid balance, एक ऐसी पंक्ति के नीचे जो उन सभी में आपके उपयोग को घुमाती रहती है, जैसे इस सप्ताह के tokens और आपका सबसे अधिक उपयोग किया गया मॉडल। _Make something_ के अंतर्गत यह नई theme, plugin, या app के लिए starter prompts प्रदान करता है जो कार्य आपके डिफ़ॉल्ट एजेंट को सौंप देते हैं। ऐप्स उसी तरह बनाए जाते हैं जैसे Omarchy के अपने Hype, Monologue, और Omacut बनाए गए हैं, C++ और Qt Quick में, omarchy-app agent skill का पालन करते हुए, और उन्हें आवश्यक compiler और Qt भाग पहले से इंस्टॉल आते हैं। Claude Code, Codex, Grok, Kimi, Cursor और उसकी Grok Bot अनुमति, GitHub Copilot, Muse, Antigravity, Kimchi, और Devin अपनी limits के साथ पहले से ही शामिल हैं, और Hermes, Mistral Vibe, और Qwen Code एक बार जब आप उनका उपयोग कर लेते हैं तो अपने sessions और tokens दिखाते हैं। pi, omp, या opencode के माध्यम से आप जिन provider plans और keys का उपयोग करते हैं वे भी दिखाई देते हैं: OpenCode Zen और Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan, और Synthetic अपनी limits के साथ; Fireworks, OpenRouter, और DeepSeek अपने prepaid balances के साथ; और वे मॉडल जिन्हें आप अपने स्वयं के hardware पर Local models के अंतर्गत चलाते हैं। प्रत्येक एजेंट को एक बार गिना जाता है, जिसके अंतर्गत उसे बिल किया जाता है, चाहे आप उसे कितने भी harness के माध्यम से चलाएँ।

पैनल के लिए bar icon पर left-click करें, अपने डिफ़ॉल्ट एजेंट को लॉन्च करने के लिए right-click करें। इसके पीछे के usage records हर 15 मिनट में `omarchy agent usage-update` द्वारा पुनः बनाए जाते हैं, और पैनल synced folder के माध्यम से आपकी अन्य मशीनों के उपयोग को भी मिला सकता है। पूर्ण settings के लिए `$OMARCHY_PATH/shell/plugins/agents/` के अंतर्गत README देखें।

### कई सब्सक्रिप्शन

यदि आप एक से अधिक Claude, Codex, या Grok योजना के लिए भुगतान करते हैं — मान लीजिए एक व्यक्तिगत Max और एक कार्य वाली — तो Omarchy उन सभी को signed in रख सकता है और उनके बीच जा सकता है। agents panel में + के साथ कोई subscription जोड़ें, जो आपको वहीं प्रक्रिया से ले जाता है, या `omarchy agent account add claude Work` (या `codex`, या `grok`) के साथ जोड़ें। यदि CLI मौजूद नहीं है तो वह उसे इंस्टॉल करता है। किसी provider के लिए पहला खाता आपके सामान्य browser के माध्यम से sign in करता है, ठीक वहीं जहाँ CLI हमेशा देखता है। उसके बाद का हर खाता एक private window के माध्यम से sign in करता है, ताकि जिस खाते में आपका browser पहले से signed in है वह गलती से न पकड़ा जाए; वहाँ उस खाते के रूप में sign in करें जिसे आप जोड़ रहे हैं, और पहले से खुली हुई किसी भी private window को पहले बंद करें। इसके लिए CLI से कभी log out न करें: log out करने से सहेजा गया sign-in रद्द हो जाता है, और उस खाते को फिर से जोड़ना पड़ेगा।

अपने subscription logins को SSH पर किसी अन्य Omarchy मशीन पर कॉपी करने के लिए, `omarchy agent account copy user@laptop` चलाएँ। जब destination के पास कोई इंस्टॉल नहीं होता तो sender एक अस्थायी receiver प्रदान करता है, इसलिए पुरानी Omarchy मशीनें बिना किसी अपडेट के खाते प्राप्त कर सकती हैं। इंस्टॉल किए गए receivers को प्राथमिकता मिलती है। यह सभी Claude, Codex, और Grok subscriptions की कॉपी करता है; उन्हें चुनने के लिए provider के नाम जोड़ें, जैसे `omarchy agent account copy laptop claude` में। खातों के नाम और command IDs source से मेल खाते हैं, जिनमें वे खाते भी शामिल हैं जो destination पर पहले से मौजूद हैं। असंबंधित destination खातों को संख्यात्मक प्रत्यय मिलता है यदि उनके नाम टकराते हैं, और settings, skills, plugins, और conversation history प्रत्येक मशीन पर स्थानीय रहते हैं।

मौजूदा destination credentials रखे जाते हैं। कोई source खाता जो वहाँ पहले से signed in है, उसके credentials को बदले बिना उसका नाम सिंक्रनाइज़ किया जाता है; अन्य खाते उसके साथ जोड़े जाते हैं। मेल खाते खातों के लिए सहेजे गए credentials को बदलने के लिए, destination पर उस खाते के sessions छोड़ने के बाद `omarchy agent account copy --replace laptop claude` का उपयोग करें। किसी नए destination को source का सक्रिय खाता और switching preferences भी मिलते हैं; कोई स्थापित destination अपने स्वयं के रखता है।

Credentials SSH के माध्यम से यात्रा करते हैं और destination पर निजी files में संग्रहीत होते हैं, इसलिए केवल उन मशीनों पर कॉपी करें जिन पर आप भरोसा करते हैं। यह एक बार की कॉपी है, निरंतर सिंक्रनाइज़ेशन नहीं। Codex refresh tokens किसी अन्य मशीन द्वारा rotate किए जा सकते हैं, जिससे कॉपी किए गए login को नवीनीकरण की आवश्यकता रह जाती है; कई मशीनों पर एक साथ उपयोग के लिए अलग-अलग sign-in सबसे विश्वसनीय विकल्प रहते हैं। [Codex's account authentication guidance](https://developers.openai.com/codex/auth/ci-cd-auth) देखें।

प्रत्येक provider के लिए एक खाता सक्रिय होता है, और हर नया session उसी के रूप में शुरू होता है: `cx`, `cy`, एक सादा `claude`, `codex`, या `grok`, `omarchy agent` के माध्यम से लॉन्च किया गया कुछ भी, और scripts या editors जो CLI को `PATH` पर पाते हैं। `omarchy agent account use work` से स्विच करें (और `omarchy agent account use main` से वापस), या पैनल में किसी खाते का नंबर दबाकर फिर `Enter` दबाकर (या उसके Use बटन पर क्लिक करके)। पहले से चल रहे Sessions उस खाते पर रहते हैं जिसके साथ वे शुरू हुए थे। Conversation history, settings, skills, और plugins खातों के बीच साझा किए जाते हैं, इसलिए उसी folder में `claude --continue` नए खाते पर वहीं से आगे बढ़ता है जहाँ आपने छोड़ा था।

एक से अधिक खाते के साथ, पैनल प्रत्येक खाते की limits को साथ-साथ दिखाता है, जिसमें सक्रिय खाता चिह्नित होता है। डिफ़ॉल्ट रूप से जब सक्रिय खाता किसी limit के 95% को पार करता है तो Omarchy आपको सूचित करता है, और सूचना पर क्लिक करने से सबसे अधिक गुंजाइश वाले खाते पर स्विच हो जाता है। पैनल में किसी खाते की पंक्ति पर hover करें और Use के बगल में दिखाई देने वाले Autoswitch पर क्लिक करें (या `m` दबाएँ), या इसके बजाय उसे अपने आप स्विच करने के लिए `omarchy agent account mode auto` चलाएँ; जब यह चालू होता है, तो Autoswitch Use की जगह ले लेता है, और उस पर फिर से क्लिक करने से सूचित करने पर वापस आ जाता है। threshold बदलने के लिए कोई संख्या जोड़ें, जैसे `omarchy agent account mode auto 90` में। यदि हर खाता threshold से ऊपर है, तो आपको एक बार इसके बारे में पता चलेगा, साथ में यह भी कि कौन-सा खाता सबसे पहले खाली होता है। जब कोई सक्रिय खाता अपने threshold के 15 points के भीतर होता है (डिफ़ॉल्ट पर 80%), तो उसकी limits की जाँच हर 15 के बजाय हर तीन मिनट में की जाती है।

`omarchy agent account list` हर खाता और उसकी नवीनतम limits दिखाता है, `omarchy agent account remove work` किसी एक को भूल जाता है, और `omarchy agent account rename primary Hey` किसी एक का नाम बदलता है (या पैनल में किसी खाते के नाम पर क्लिक करें)। ये commands आपके डिफ़ॉल्ट एजेंट के खातों पर काम करते हैं; अन्य provider तक पहुँचने के लिए, पहले उसका नाम दें, जैसे `omarchy agent account use codex side` में। `~/.claude` या `~/.codex` में आपके पास पहले से मौजूद login _Main_ खाता है और वहीं रहता है जहाँ वह है। लगभग आठ घंटे से अधिक समय तक अप्रयुक्त छोड़ा गया कोई खाता _Sign-in required_ दिखा सकता है; उस खाते में फिर से ठीक पैनल में sign in करने के लिए उस पर क्लिक करें, या उसमें कोई session शुरू करें, जो अपने आप sign-in को ताज़ा करते हैं। जब कोई खाता जोड़ा गया था तब आपके पास मौजूद MCP servers उसके साथ आ जाते हैं, लेकिन जिन्हें आप बाद में `claude mcp add` से जोड़ते हैं वे केवल उस खाते तक पहुँचते हैं जिसमें आपने उन्हें जोड़ा था। Claude Desktop और किसी CLI binary के absolute path के साथ कॉन्फ़िगर किए गए टूल स्विच का पालन नहीं करते। कोई स्पष्ट `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, या `GROK_HOME` चुने गए खाते पर प्राथमिकता लेता है।

### क्रैश का निदान

Omarchy process crashes के लिए systemd-coredump पर नजर रखता है। जब कुछ segfault होता है, तो आपको "Process crashed" सूचना मिलेगी — उस पर क्लिक करें, और क्रैश आपके डिफ़ॉल्ट एजेंट को Omarchy की diagnose-crash skill के साथ सौंप दिया जाता है, जो एजेंट को core dump से तथ्य स्थापित करने और यह तय करने की प्रक्रिया से ले जाती है कि क्रैश की रिपोर्ट upstream करना सार्थक है या नहीं। आप उसे `coredumpctl list` से किसी भी PID के विरुद्ध हाथ से भी चला सकते हैं, `omarchy agent crash <pid>` के साथ।

देखना डिफ़ॉल्ट रूप से चालू होता है। उसे _Trigger > Toggle > Crash Capture_ के अंतर्गत बंद करें (या `omarchy toggle crash-capture` के साथ) और सूचनाएँ बंद हो जाती हैं; `omarchy agent crash <pid>` हाथ से फिर भी काम करता है।

क्रैश को एक बार में एक प्रोग्राम के लिए भी शांत किया जा सकता है, जो निदान आपको अंत में प्रदान करता है। `omarchy crash mute hyprland` केवल उस प्रोग्राम के लिए सूचनाएँ बंद करता है, `omarchy crash mute hyprland off` उन्हें वापस लाता है, और अकेले `omarchy crash mute` वह सूचीबद्ध करता है जिसे आपने mute किया है। यह binary के path को उसके नाम की तरह ही खुशी से लेता है, इसलिए `omarchy crash mute /usr/bin/hyprland` वही काम करता है। किसी नाम को जिसमें space हो, quote करें, जैसे `omarchy crash mute 'Some App'` में। बाकी सब कुछ फिर भी सूचित करता है, और muted प्रोग्राम फिर भी क्रैश होता है — यह reminder को छिपाता है, यह कुछ भी ठीक नहीं करता।

### डेस्कटॉप ऐप्स

_Install > AI_ मेनू में कुछ graphical AI ऐप्स भी हैं: ChatGPT desktop app, Claude desktop app (Anthropic का Linux beta, Chat, Cowork, और Claude Code tabs के साथ), xAI के मॉडल के साथ चैट करने के लिए Grok Bot, Herdr Desktop, Hermes Desktop, OpenClaw, Perplexity desktop app, और T3 Code। Grok Bot desktop chat app है। कोडिंग एजेंट `grok` कमांड है।

Hermes Desktop वह है जिसके बारे में जानना ज़रूरी है, क्योंकि किसी मशीन के पास एक ही Hermes होता है, और वह ऐप का होता है: Hermes हमेशा केवल ऐप के माध्यम से इंस्टॉल होता है, और डिफ़ॉल्ट एजेंट जो `hermes` कमांड चलाता है वह ऐप का ही होता है। Hermes को डिफ़ॉल्ट एजेंट के रूप में चुनने पर वही चीज़ इंस्टॉल होती है जो _Install > AI_ प्रविष्टि करती है: पैकेज, और Hermes के अपने इंस्टॉलर द्वारा सेट अप किया गया `~/.hermes` के अंतर्गत एक Hermes runtime, जिसमें पहली बार कुछ मिनट लगते हैं। वह runtime ही वह एकमात्र Hermes है जिसका उपयोग terminal `hermes` कमांड, डिफ़ॉल्ट एजेंट और ऐप सभी करते हैं, और वह Omarchy रिलीज़ की प्रतीक्षा करने के बजाय `hermes update` से स्वयं को अपडेट करता है। उसे इंस्टॉल करने पर Hermes को Omarchy theme `omarchy` नाम की skin के रूप में भी मिलता है, जिसका पालन हर Hermes surface आपके theme बदलने पर करता है; यदि आप नहीं चाहते कि ऐसा हो तो Hermes की Appearance settings के अंतर्गत या `/skin` के साथ कोई अन्य चुनें, और Omarchy उस विकल्प को अकेला छोड़ देता है। _Remove > AI_ के अंतर्गत ऐप को हटाने पर पहले Hermes बंद होता है, gateway सहित, वह runtime उसके साथ ले जाता है, और आपकी chats, memories, और वे skills रखता है जो Hermes ने अपने लिए लिखी थीं, जब तक कि आप उसे अन्यथा न कहें: यह पूछता है, डिफ़ॉल्ट रूप से नहीं के साथ, कि क्या वह data और आपकी connection settings भी जानी चाहिए।

OpenClaw का desktop अनुभव उसका Control UI है, जो उसके अपने local gateway द्वारा समर्थित web app के रूप में खुलता है। OpenClaw `~/.openclaw` में रहता है और स्वयं को अपडेट करता है: Control UI के "Update Gateway" बटन का उपयोग करें या `openclaw update` चलाएँ, और gateway नए संस्करण पर पुनः शुरू होता है। Omarchy केवल वह रिलीज़ चुनता है जिससे कोई नया इंस्टॉल शुरू होता है। _Remove > AI_ के अंतर्गत OpenClaw को हटाने पर gateway service और ऐप उसके साथ जाते हैं और फिर पूछा जाता है कि क्या `~/.openclaw` भी जाना चाहिए, क्योंकि उसमें आपकी chats और credentials के साथ-साथ OpenClaw स्वयं और उसके द्वारा डाउनलोड किए गए plugin runtimes भी होते हैं; डिफ़ॉल्ट उसे रखता है, और OpenClaw को फिर से इंस्टॉल करने पर वह उसे फिर से उठा लेता है।

Herdr Desktop [Herdr](https://herdr.dev) desktop app है: terminals और कोडिंग एजेंटों के spaces, tabs, और panes जो आपके window बंद करने पर उसके core में चलते रहते हैं। यह किसी पैकेज के बजाय Herdr के अपने इंस्टॉलर से आता है, इसलिए यह `~/.local/share/herdr-app` में रहता है, जब आपके पास पहले से कोई नहीं होता तो `~/.local/bin/herdr-core` में अपने core को साथ लाता है, और दोनों को स्वयं अपडेट करता है। यह उस `herdr` कमांड के बगल में बैठता है जो Omarchy `Super + Ctrl + Return` पर प्रदान करता है, उसे बदलने के बजाय, और उस कमांड की direct keys प्राप्त करता है: `Alt + Return` और `Alt + Shift + Return` किसी pane को नीचे या दाईं ओर विभाजित करते हैं, `Alt + Escape` उसे बंद करता है, `Ctrl + Alt + Arrow` panes के बीच जाता है, `Alt + 1..9` और `Alt + Left/Right` कोई tab चुनते हैं, और `Alt + Up/Down` spaces के बीच जाते हैं। `Ctrl + 1..9` कोई space चुनता है और `Alt + Shift + Up/Down` एजेंटों के माध्यम से आगे बढ़ता है। `Ctrl + Space` prefix keys केवल terminal तक ही रहती हैं, क्योंकि ऐप किसी sequence के लिए साधारण Ctrl key नहीं रख सकता। Omarchy इन्हें `~/.config/herdr-app/keys.json` में लिखता है, और `omarchy-refresh-herdr-app` उन्हें वापस रखता है। उसे इंस्टॉल करने पर Herdr का Omarchy theme चुना जाता है, जो उसके बाद से आपके Omarchy theme का पालन करता है। Herdr light mode के लिए एक theme और dark के लिए एक रखता है, इसलिए dark और light Omarchy theme के बीच स्विच करने के बाद, अन्य mode के लिए Herdr के theme picker में एक बार फिर Omarchy चुनें।

T3 Code किसी पैकेज के बजाय `~/.local/share/t3code` में अपने आधिकारिक AppImage रिलीज़ से चलता है, इसलिए वह स्वयं को अपडेट करता है। उसे इंस्टॉल करने पर पूछा जाता है कि Stable या Nightly channel पर शुरू करना है; बाद में T3 Code की settings में स्विच करें। आपके threads और settings `~/.t3` में रहते हैं, और _Remove > AI_ के अंतर्गत T3 Code को हटाने पर वे उसके साथ जाते हैं।

### लोकल मॉडल

अपने कोडिंग एजेंटों के लिए अपने स्वयं की मशीन पर कोई open model चलाएँ। आपके prompts और code मशीन पर ही रहते हैं; मॉडल को भेजा गया कुछ भी उसे छोड़कर नहीं जाता। इससे शुरू करें:

```bash
omarchy agent local use best
```

या, top bar में agents panel में, + और फिर Local AI चुनें, जो तब दिखाई देता है जब कोई मॉडल इस मशीन के अनुकूल बैठता है। पहली बार, यह Podman इंस्टॉल करता है, जो मॉडल चलाता है, और NVIDIA मशीन पर NVIDIA का container toolkit, जो उन्हें GPU देता है। फिर Omarchy इस मशीन के लिए अनुशंसित मॉडल चुनता है, उसे डाउनलोड करता है, और उसे शुरू करता है। दसियों GB के डाउनलोड की अपेक्षा करें और जब मॉडल चलता है तो मशीन की अधिकांश memory उपयोग में होगी: Flash Next अपने पूर्ण 256K context के साथ लगभग 100 GiB उपयोग करता है। यदि अन्य मॉडल उसकी आवश्यक memory रखते हैं, तो वह रुका हुआ सेट अप किया जाता है, आपके द्वारा किसी एक को रोकने के बाद शुरू करने के लिए तैयार। मॉडल logout पर रुक जाता है; जब आपको किसी और चीज़ के लिए memory चाहिए तो उसे स्वयं रोकें।

`omarchy agent local list` विकल्प दिखाता है और बताता है कि कुछ क्यों अनुकूल नहीं बैठते। कोई अन्य सेट अप करने के लिए, `omarchy agent local use <recipe>` चलाएँ। आज, `qwen3.8-flash-next-gufo` और `qwen3.8-27b-gufo` 128 GB Strix Halo मशीनों के लिए उपलब्ध हैं; 27B लगभग 40 GiB लेता है, इसलिए वह अन्य काम के लिए जगह छोड़ता है। नई recipes और अनुशंसाएँ `omarchy update` के साथ, पैकेज के माध्यम से आती हैं।

आपके द्वारा सेट अप किया गया हर मॉडल agents panel में अपनी स्वयं की पंक्ति प्राप्त करता है, आपके subscriptions के बगल में: उसे शुरू करने के लिए play, उसे रोकने और उसकी memory खाली करने के लिए pause, और उस पर अपना एजेंट खोलने के लिए terminal बटन। कई एक साथ चल सकते हैं जब वे memory में एक साथ अनुकूल बैठते हैं; यदि कोई अनुकूल नहीं बैठता, तो Omarchy बताता है कि किस चल रहे मॉडल को रोकना है। उन्हें पुनः क्रमित करने के लिए पंक्तियों को खींचें, और किसी मॉडल और उसके डाउनलोड को हटाने के लिए चयनित पंक्ति पर Delete दबाएँ।

कमांड लाइन से, `omarchy agent local start <recipe>` और `omarchy agent local stop <recipe>` वही करते हैं, `omarchy agent local status` हर मॉडल दिखाता है, और `omarchy agent --local` आपके डिफ़ॉल्ट एजेंट को आपके द्वारा अंतिम बार शुरू किए गए मॉडल पर खोलता है। pi, OpenCode और Qwen Code किसी एक का उपयोग कर सकते हैं; किसी अन्य डिफ़ॉल्ट के साथ यह pi में खुलता है। pi आपके द्वारा सेट अप किए गए हर मॉडल, और उन मशीनों पर मौजूद मॉडल जिन्हें आपने उसके साथ जोड़ा है, को अपने स्वयं के model picker में भी सूचीबद्ध करता है, इसलिए सादा `pi` भी उन तक पहुँचता है। कोई भी OpenAI-compatible client भी जुड़ सकता है: `status` प्रत्येक मॉडल का पता दिखाता है (पहला `http://127.0.0.1:11435/v1` है), recipe का नाम ही मॉडल है, और key `~/.config/omarchy/agent-local/key` में है।

`omarchy agent local remove <recipe>` किसी मॉडल और उन डाउनलोड को हटाता है जिनका उपयोग कोई अन्य मॉडल नहीं करता।

Third-party runtimes को उनके publisher के साथ लेबल किया जाता है। Omarchy हर मॉडल को बिना किसी network access के चलाता है।

### लोकल LLM

Omarchy लोकल LLM मॉडल चलाने के दो तरीके अनुशंसित करता है: LM Studio और Ollama। LM Studio open-weight मॉडल खोजने, उन्हें इंस्टॉल करने, और उन्हें चलाने के लिए GUI interface प्रदान करता है। आसानी से शुरुआत करने का यह एक शानदार तरीका है। Ollama ऐसा ही करने के लिए CLI प्रदान करता है। लेकिन यदि आप लोकल मॉडल के लिए नए हैं, तो मैं LM Studio से शुरुआत करूँगा। आप Omarchy Menu में _Install > AI_ के अंतर्गत दोनों में से कोई भी इंस्टॉल कर सकते हैं।

### Omarchy Skill

Agent skills AI को विशिष्ट टूल का विशिष्ट तरीके से उपयोग करने में मदद करते हैं, और Omarchy system को अनुकूलित करने के लिए एक डिफ़ॉल्ट skill के साथ आता है। जैसे आपके Hyprland config को tweak करना, bar को समायोजित करना, या यहाँ तक कि शुरुआत से नई theme बनाना। यह Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` और प्रत्येक `~/.hermes/profiles/*/skills`), और generic `~/.agents/skills` स्थान के लिए skill directories में symlinked है, इसलिए अधिकांश harness उसे स्वचालित रूप से उठा लेते हैं।

लेकिन आपको इस skill को प्रयोगात्मक मानना चाहिए। विभिन्न मॉडल उसका उपयोग अलग-अलग प्रभाव के साथ करेंगे। पहले उसे plan mode में चलाना सबसे अच्छा है, ताकि आपको अंदाज़ा हो कि एजेंट क्या बदलना चाहेगा। और फिर बदलावों को rollback करने या यहाँ तक कि `omarchy reinstall configs` को invoke करने के लिए तैयार रहें, यदि एजेंट हर चीज़ की गड़बड़ी कर दे।
