# AI

### Agents को install और update करना

Hermes को छोड़कर, ये agents mise के lazy installation का उपयोग करते हैं: पहली launch पर CLI install होता है, और बाद की launches उसी का पुनः उपयोग करती हैं। mise किसी install किए गए agent के लिए नए release की जाँच हर चार घंटे में अधिकतम एक बार करता है, ठीक उसके शुरू होने से पहले या background में shell prompt पर। यदि वह update विफल हो जाए या आप offline हों, तो install किया गया version चलता है। `omarchy update` install किए गए agents को बाकी Omarchy के साथ update करता है, और `mup` केवल mise-प्रबंधित tools को update करता है।

किसी agent का अपना updater, जैसे `claude update`, `codex update`, या किसी app में update button, mise-प्रबंधित install को update नहीं करता। `codex update` विफल हो जाता है, और `claude update` सफलता बता सकता है जबकि वह एक अलग copy install कर दे जिसे mise track नहीं करता। यदि आप इसके बजाय किसी agent के native installer और updater का उपयोग करना पसंद करते हैं, तो उसे `disable_tools` में जोड़ें; देखें [पहले से install किए गए CLI tools](18-development-tools.md#preinstalled-cli-tools)।

सभी configured lazy tools को उनकी आवश्यकता पड़ने से पहले install करने के लिए `mise install --include-lazy` चलाएँ। इसमें agents के साथ-साथ Omarchy के अन्य default CLI tools भी शामिल हैं। किसी एक tool को install करने या अपने स्वयं के installation का उपयोग करने के लिए [पहले से install किए गए CLI tools](18-development-tools.md#preinstalled-cli-tools) देखें।

`grok` mise के first-party `grok` package के माध्यम से install होता है, उसी तरह जैसे `claude` और `codex`। `grok` चलाएँ, या उसे _Setup > Defaults > Agent_ के अंतर्गत चुनें। x.ai पर मौजूद `curl | bash` installer को छोड़ दें। वह तरीका `~/.grok/bin` में दूसरी copy डाल देता है, उसे `PATH` पर आगे जोड़ देता है, और Omarchy के wrapper को overwrite कर देता है।

`dsh` अपना browser UI `127.0.0.1:3080` पर खोलता है, जिसमें launch directory उसका default workspace होता है। उसका browser UI कोई starting prompt नहीं लेता, इसलिए `omarchy agent prompt` उसे आपके clipboard पर मौजूद prompt के साथ खोलता है ताकि आप उसे paste कर सकें। Omarchy उसे DeepSeek के no-approval permission preset के साथ शुरू करता है। जब आप उसके official model API का उपयोग करते हैं तो DeepSeek Harness session logs को DeepSeek पर upload करता है; उसके browser UI में _Settings > General > Upload Session Log_ के अंतर्गत इसे बंद कर दें। आप उसे जो feedback भेजते हैं वह भी session के साथ upload होता है, जब तक कि आप उसे `DSH_TELEMETRY_MODE=DISABLED` के साथ शुरू न करें।

### Default agent

अपना default agent `omarchy default agent <name>` से चुनें या Omarchy Menu (`Super + Space`) में _Setup > Defaults > Agent_ के अंतर्गत चुनें। यदि agent अभी तक install नहीं हुआ है, तो उसे चुनने पर पहले वह install हो जाता है। एक ताज़ा Omarchy एक बार दिखाई देने वाली notification के साथ आपको यह चुनाव करने के लिए आमंत्रित करेगा।

Claude को चुनने पर Chromium, Chrome, Brave, Brave Origin, और Edge के लिए उसके browser extension को set up करने का प्रयास भी होता है। Extension setup सभी users पर लागू होता है और आपका system password माँग सकता है; रद्द करने या extension install विफल होने पर भी Claude चुना और launch होता है। अपने browser को restart करें, prompt मिलने पर extension को enable करें, और उसे जोड़ना पूरा करने के लिए Claude में sign in करें। Connection की जाँच करने के लिए Claude में `/chrome` चलाएँ। Firefox और Zen इस extension का समर्थन नहीं करते। यदि यह setup जोड़े जाने से पहले Claude पहले से ही आपका default था, तो extension install करने के लिए उसे फिर से चुनें।

एक बार चुन लेने के बाद, `Super + Shift + Ctrl + A` default agent को एक समर्पित terminal window में launch करता है (या यदि आपने अभी तक नहीं चुना है तो picker सामने लाता है)। आप `omarchy agent prompt "Review this project"` के साथ उसे सीधे किसी task में भी launch कर सकते हैं। Freebuff और DeepSeek Harness कोई starting prompt नहीं लेते, इसलिए वे इसके बजाय आपके clipboard पर मौजूद prompt के साथ खुलते हैं ताकि आप उसे paste कर सकें। इस तरह launch किए गए agents अपने-अपने don't-stop-to-ask modes में unattended चलते हैं, इसलिए तैयार रहें कि वे वास्तव में कुछ करेंगे! MiniMax Code के पास उसके interactive sessions के लिए ऐसा कोई mode नहीं है, इसलिए वह हमेशा की तरह permissions माँगता है। और चूँकि agents आपकी home directory के लिए trust याद रखने से इनकार करते हैं, इसलिए `$HOME` से होने वाली launches इसके बजाय `~/Work` में शुरू होती हैं।

Terminal shortcuts भी हैं: `a` वर्तमान terminal में default agent को inline चलाता है, जबकि `c`, `cx`, और `cy` OpenCode, Claude Code, और Codex को सीधे शुरू करते हैं (फिर से उनके auto-approving modes में)। Theme बदलाव भी agents के साथ sync होते हैं: जब आप Omarchy theme बदलते हैं तो Claude Code, Pi, OpenCode, और Hermes (एक बार Omarchy ने उसे install कर लिया हो) सभी साथ-साथ बदलते हैं।

### Agents panel

Top bar में एक agents icon है। किसी agent को set up करने से पहले, उसका panel आपको Claude, Codex, या Grok में sign in करने की प्रक्रिया से ले जाता है, और पहला वाला आपका default agent बन जाता है। उसके बाद, panel हर subscription को एक ही page पर रखता है: प्रत्येक agent और account अपने plan के साथ, उसके 5-hour session और weekly limits में से प्रत्येक के लिए एक meter जिसके reset होने तक के समय के साथ (सटीक प्रतिशत के लिए hover करें), या बचा हुआ prepaid balance, उस line के नीचे जो उन सभी में आपके उपयोग को बारी-बारी से दिखाती है, जैसे इस सप्ताह के tokens और आपका सबसे अधिक उपयोग किया गया model। _Make something_ के अंतर्गत यह एक नई theme, plugin, या app के लिए starter prompts देता है जो task को आपके default agent को सौंप देते हैं। Apps उसी तरह बनाए जाते हैं जैसे Omarchy के अपने Hype, Monologue, और Omacut बनाए जाते हैं, C++ और Qt Quick में, omarchy-app agent skill का पालन करते हुए, और उन्हें जिस compiler और Qt हिस्सों की आवश्यकता होती है वे install किए हुए आते हैं। Claude Code, Codex, Grok, Kimi, Cursor और उसका Grok Bot allowance, GitHub Copilot, Muse, Antigravity, Kimchi, और Devin अपनी limits के साथ out of the box कवर किए गए हैं, और Hermes, Mistral Vibe, और Qwen Code एक बार जब आपने उनका उपयोग कर लिया हो तो अपने sessions और tokens दिखाते हैं। pi, omp, या opencode के माध्यम से उपयोग किए जाने वाले provider plans और keys भी दिखाई देते हैं: OpenCode Zen और Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan, और Synthetic अपनी limits के साथ; Fireworks, OpenRouter, और DeepSeek अपने prepaid balances के साथ; और वे models जिन्हें आप अपने स्वयं के hardware पर Local models के अंतर्गत चलाते हैं। प्रत्येक agent को एक ही बार गिना जाता है, उसी के अंतर्गत जो उसे bill करता है, चाहे आप उसे कितने भी harnesses के माध्यम से चलाएँ।

Panel के लिए bar icon पर left-click करें, अपने default agent को launch करने के लिए right-click करें। इसके पीछे मौजूद usage records हर 15 मिनट में `omarchy agent usage-update` द्वारा फिर से बनाए जाते हैं, और panel synced folder के माध्यम से आपकी अन्य machines के usage को भी merge कर सकता है। पूर्ण settings के लिए `$OMARCHY_PATH/shell/plugins/agents/` के अंतर्गत README देखें।

### कई subscriptions

यदि आप एक से अधिक Claude, Codex, या Grok plan के लिए भुगतान करते हैं — मान लीजिए एक personal Max और एक work वाला — तो Omarchy उन सभी को signed in रख सकता है और उनके बीच आ-जा सकता है। Agents panel में + के साथ एक subscription जोड़ें, जो आपको वहीं प्रक्रिया से ले जाता है, या `omarchy agent account add claude Work` (या `codex`, या `grok`) के साथ जोड़ें। यदि CLI मौजूद नहीं है तो यह उसे install कर देता है। किसी provider के लिए पहला account आपके सामान्य browser के माध्यम से sign in करता है, ठीक वहीं जहाँ CLI हमेशा देखता है। उसके बाद का प्रत्येक account एक private window के माध्यम से sign in करता है, ताकि जिस account में आपका browser पहले से signed in है वह गलती से न चुन लिया जाए; वहाँ उस account के रूप में sign in करें जिसे आप जोड़ रहे हैं, और पहले से खुली हुई किसी भी private window को पहले बंद कर दें। ऐसा करने के लिए CLI से कभी log out न करें: log out करने से saved sign-in रद्द हो जाता है, और उस account को फिर से जोड़ना पड़ेगा।

अपने subscription logins को SSH पर किसी अन्य Omarchy machine पर copy करने के लिए `omarchy agent account copy user@laptop` चलाएँ। जब destination पर कोई receiver install नहीं होता है तो sender एक temporary receiver उपलब्ध कराता है, इसलिए पुरानी Omarchy machines बिना update के accounts प्राप्त कर सकती हैं। Install किए गए receivers को प्राथमिकता मिलती है। यह सभी Claude, Codex, और Grok subscriptions को copy करता है; उन्हें चुनने के लिए provider names जोड़ें, जैसे `omarchy agent account copy laptop claude` में। Account names और command IDs source से मेल खाते हैं, उन accounts सहित जो destination पर पहले से मौजूद हैं। असंबंधित destination accounts के नामों में टकराव होने पर उन्हें numeric suffix मिलता है, और settings, skills, plugins, और conversation history प्रत्येक machine पर local रहती हैं।

मौजूदा destination credentials रखे जाते हैं। कोई source account जो वहाँ पहले से signed in है, उसके credentials को बदले बिना उसका नाम synchronize हो जाता है; अन्य accounts उसके साथ जोड़ दिए जाते हैं। मेल खाने वाले accounts के लिए saved credentials को बदलने के लिए, destination पर उस account के sessions बंद करने के बाद `omarchy agent account copy --replace laptop claude` का उपयोग करें। एक ताज़ा destination को source का active account और switching preferences भी मिलती हैं; एक स्थापित destination अपनी preferences रखता है।

Credentials SSH के माध्यम से जाती हैं और destination पर private files में stored होती हैं, इसलिए केवल उन्हीं machines पर copy करें जिन पर आप भरोसा करते हैं। यह एक बार की copy है, निरंतर synchronization नहीं। Codex refresh tokens किसी अन्य machine द्वारा rotate किए जा सकते हैं, जिससे copy किए गए login को renewal की आवश्यकता पड़ सकती है; कई machines पर एक साथ उपयोग के लिए अलग-अलग sign-ins सबसे विश्वसनीय विकल्प रहते हैं। [Codex का account authentication मार्गदर्शन](https://developers.openai.com/codex/auth/ci-cd-auth) देखें।

प्रत्येक provider के लिए एक account सक्रिय होता है, और प्रत्येक नया session उसी के रूप में शुरू होता है: `cx`, `cy`, एक सादा `claude`, `codex`, या `grok`, `omarchy agent` के माध्यम से launch की गई कोई भी चीज़, और वे scripts या editors जो CLI को `PATH` पर पाते हैं। `omarchy agent account use work` से switch करें (और `omarchy agent account use main` से वापस आएँ), या panel में किसी account की संख्या दबाकर फिर `Enter` दबाकर (या उसके Use button पर click करके)। जो sessions पहले से चल रहे हैं वे उसी account पर रहते हैं जिसके साथ वे शुरू हुए थे। Conversation history, settings, skills, और plugins accounts के बीच साझा होते हैं, इसलिए उसी folder में `claude --continue` नए account पर वहीं से आगे बढ़ता है जहाँ आपने छोड़ा था।

एक से अधिक account होने पर, panel प्रत्येक account की limits को साथ-साथ दिखाता है, जिसमें सक्रिय account चिह्नित होता है। Default रूप से Omarchy आपको तब सूचित करता है जब सक्रिय account किसी limit के 95% को पार कर जाता है, और notification पर click करने से सबसे अधिक headroom वाले account पर switch हो जाता है। Panel में किसी account की line पर hover करके Use के बगल में दिखाई देने वाले Autoswitch पर click करें (या `m` दबाएँ), या इसके बजाय उसे अपने आप switch कराने के लिए `omarchy agent account mode auto` चलाएँ; जब यह चालू होता है, तो Autoswitch Use की जगह ले लेता है, और उसे फिर से click करने पर वापस सूचित करने पर आ जाता है। Threshold बदलने के लिए एक संख्या जोड़ें, जैसे `omarchy agent account mode auto 90` में। यदि प्रत्येक account threshold से ऊपर है, तो आपको इसके बारे में एक बार सुनने को मिलेगा, साथ में यह भी कि कौन-सा account सबसे पहले मुक्त होगा। जब कोई सक्रिय account अपने threshold के 15 points के भीतर होता है (default पर 80%), तो उसकी limits की जाँच हर 15 के बजाय हर तीन मिनट में की जाती है।

`omarchy agent account list` प्रत्येक account और उसकी नवीनतम limits दिखाता है, `omarchy agent account remove work` किसी एक को भुला देता है, और `omarchy agent account rename primary Hey` किसी एक का नाम बदल देता है (या panel में किसी account के नाम पर click करें)। ये commands आपके default agent के accounts पर काम करते हैं; दूसरे provider तक पहुँचने के लिए पहले उसका नाम दें, जैसे `omarchy agent account use codex side` में। आपके पास `~/.claude` या `~/.codex` में पहले से मौजूद login ही _Main_ account है और वह वहीं रहता है जहाँ वह है। लगभग आठ घंटे से अधिक समय तक अप्रयुक्त छोड़ा गया account _Sign-in required_ दिखा सकता है; उस account को panel में ही फिर से sign in करने के लिए उस पर click करें, या उसमें एक session शुरू करें, जो sign-in को अपने आप refresh कर देता है। किसी account को जोड़े जाने के समय आपके पास मौजूद MCP servers उसके साथ आ जाते हैं, लेकिन बाद में `claude mcp add` से जोड़े गए servers केवल उसी account तक पहुँचते हैं जिसमें आपने उन्हें जोड़ा था। Claude Desktop और किसी CLI binary के absolute path के साथ configured tools switch का पालन नहीं करते। एक स्पष्ट `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, या `GROK_HOME` चुने गए account पर प्राथमिकता लेता है।

### Crash निदान

Omarchy process crashes के लिए systemd-coredump पर नजर रखता है। जब कुछ segfault करता है, तो आपको एक "Process crashed" notification मिलेगा — उस पर click करें, और crash आपके default agent को Omarchy की diagnose-crash skill के साथ सौंप दिया जाता है, जो agent को core dump से तथ्य स्थापित करने और यह तय करने की प्रक्रिया से ले जाती है कि crash की upstream रिपोर्ट करना सार्थक है या नहीं। आप इसे `coredumpctl list` से किसी भी PID के विरुद्ध `omarchy agent crash <pid>` के साथ हाथ से भी चला सकते हैं।

यह निगरानी default रूप से चालू है। इसे _Trigger > Toggle > Crash Capture_ के अंतर्गत बंद करें (या `omarchy toggle crash-capture` के साथ) और notifications बंद हो जाएँगी; `omarchy agent crash <pid>` हाथ से फिर भी काम करता है।

Crashes को एक समय में एक program के लिए भी शांत किया जा सकता है, जो diagnosis अंत में आपको पेश करता है। `omarchy crash mute hyprland` केवल उसी program के लिए notifications बंद करता है, `omarchy crash mute hyprland off` उन्हें वापस लाता है, और `omarchy crash mute` अपने आप में वह सूची देता है जो आपने mute किया है। यह binary का path उतनी ही खुशी से लेता है जितनी उसका नाम, इसलिए `omarchy crash mute /usr/bin/hyprland` भी वही काम करता है। किसी नाम में space हो तो उसे quote करें, जैसे `omarchy crash mute 'Some App'` में। बाकी सब कुछ फिर भी सूचित करता है, और muted program फिर भी crash होता है — यह reminder को छिपाता है, यह कुछ ठीक नहीं करता।

### Desktop ऐप्स

_Install > AI_ menu में कुछ graphical AI apps भी हैं: ChatGPT desktop app, Claude desktop app (Anthropic का Linux beta, Chat, Cowork, और Claude Code tabs के साथ), xAI के models के साथ chat करने के लिए Grok Bot, Hermes Desktop, OpenClaw, Perplexity desktop app, और T3 Code। Grok Bot desktop chat app है। Coding agent `grok` command है।

Hermes Desktop वह है जिसके बारे में जानना ज़रूरी है, क्योंकि किसी machine पर एक Hermes होता है, और वह app का होता है: Hermes हमेशा केवल app के माध्यम से ही install होता है, और default agent जो `hermes` command चलाता है वह app का ही होता है। Hermes को default agent के रूप में चुनने पर वही install होता है जो _Install > AI_ entry करती है: package, और Hermes के अपने installer द्वारा set up किया गया `~/.hermes` के अंतर्गत एक Hermes runtime, जिसमें पहली बार कुछ मिनट लगते हैं। वह runtime ही वह एकमात्र Hermes है जिसका उपयोग terminal का `hermes` command, default agent और app सभी करते हैं, और वह Omarchy release की प्रतीक्षा करने के बजाय `hermes update` से अपने आप update होता है। उसे install करने पर Hermes को Omarchy theme `omarchy` नाम की skin के रूप में भी मिलता है, जिसका पालन प्रत्येक Hermes surface आपके theme बदलने के साथ करता है; यदि आप नहीं चाहते कि ऐसा हो तो Hermes की Appearance settings के अंतर्गत या `/skin` के साथ कोई अन्य चुनें, और Omarchy उस चुनाव को अकेला छोड़ देता है। _Remove > AI_ के अंतर्गत app को हटाने से Hermes पहले बंद होता है, gateway सहित, वह runtime उसके साथ चला जाता है, और आपकी chats, memories, और वे skills जो Hermes ने अपने लिए लिखी थीं रखी जाती हैं जब तक आप अन्यथा न कहें: यह पूछता है, जिसका default no है, कि क्या वह data और आपकी connection settings भी जानी चाहिए।

OpenClaw का desktop experience उसका Control UI है, जो उसके अपने local gateway द्वारा समर्थित web app के रूप में खुलता है। OpenClaw `~/.openclaw` में रहता है और अपने आप update होता है: Control UI के "Update Gateway" button का उपयोग करें या `openclaw update` चलाएँ, और gateway नए version पर restart हो जाता है। Omarchy केवल वह release चुनता है जिससे कोई ताज़ा install शुरू होता है। _Remove > AI_ के अंतर्गत OpenClaw को हटाने से gateway service और app उसके साथ चले जाते हैं और फिर पूछा जाता है कि क्या `~/.openclaw` भी जाना चाहिए, क्योंकि उसमें OpenClaw के साथ-साथ आपकी chats और credentials और उसके द्वारा download किए गए plugin runtimes होते हैं; default उसे रखता है, और OpenClaw को फिर से install करने पर वह फिर से मिल जाता है।

T3 Code किसी package के बजाय `~/.local/share/t3code` में अपने official AppImage release से चलता है, इसलिए वह अपने आप update होता है। उसे install करने पर पूछा जाता है कि Stable या Nightly channel पर शुरू करना है; बाद में T3 Code की settings में switch करें। आपके threads और settings `~/.t3` में रहते हैं, और _Remove > AI_ के अंतर्गत T3 Code को हटाने पर वे उसके साथ चले जाते हैं।

### Local models

अपने coding agents के लिए अपनी स्वयं की machine पर एक open model चलाएँ। आपके prompts और code machine पर ही रहते हैं; model को भेजी गई कोई भी चीज़ उससे बाहर नहीं जाती। इससे शुरू करें:

```bash
omarchy agent local use best
```

या, top bar में agents panel में, + और फिर Local AI चुनें, जो तब दिखाई देता है जब कोई model इस machine पर fit होता है। पहली बार, यह Podman install करता है, जो models को चलाता है। फिर Omarchy इस machine के लिए अनुशंसित model चुनता है, उसे download करता है, और शुरू करता है। Tens of GB के download की अपेक्षा करें और model चलने के दौरान machine की अधिकांश memory उपयोग में रहेगी: Flash Next अपने पूर्ण 256K context के साथ लगभग 100 GiB का उपयोग करता है। यदि अन्य models को वह memory चाहिए जो उसे चाहिए, तो वह रुका हुआ set up होता है, एक को रोकते ही शुरू होने के लिए तैयार। Model logout पर रुक जाता है; जब आपको किसी और चीज़ के लिए memory चाहिए तो उसे स्वयं रोक दें।

`omarchy agent local list` विकल्प दिखाता है और बताता है कि कुछ क्यों fit नहीं होते। कोई दूसरा set up करने के लिए `omarchy agent local use <recipe>` चलाएँ। आज, 128 GB Strix Halo machines के लिए `qwen3.8-flash-next-halogen` और `qwen3.8-27b-gufo` उपलब्ध हैं। नई recipes और अनुशंसाएँ package के माध्यम से `omarchy update` के साथ आती हैं।

आपके द्वारा set up किया गया प्रत्येक model agents panel में, आपकी subscriptions के बगल में, अपनी अलग line पाता है: उसे शुरू करने के लिए play, उसे रोकने और उसकी memory मुक्त करने के लिए pause, और उस पर अपना agent खोलने के लिए terminal button। जब वे memory में एक साथ fit होते हैं तो कई एक साथ चल सकते हैं; यदि कोई fit नहीं होता, तो Omarchy बताता है कि किस चलते हुए model को रोकना है। Lines को फिर से क्रमबद्ध करने के लिए उन्हें drag करें, और किसी model और उसके download को हटाने के लिए चुनी गई line पर Delete दबाएँ।

Command line से, `omarchy agent local start <recipe>` और `omarchy agent local stop <recipe>` वही करते हैं, `omarchy agent local status` प्रत्येक model दिखाता है, और `omarchy agent --local` आपके default agent को आपके द्वारा शुरू किए गए अंतिम model पर खोलता है (pi यदि आपका default agent local model का उपयोग नहीं कर सकता)। कोई भी OpenAI-compatible client भी जुड़ सकता है: `status` प्रत्येक model का address दिखाता है (पहला `http://127.0.0.1:11435/v1` है), recipe name ही model है, और key `~/.config/omarchy/agent-local/key` में है।

`omarchy agent local remove <recipe>` किसी model और उन downloads को delete कर देता है जिनका कोई अन्य model उपयोग नहीं करता।

Third-party runtimes पर उनके publisher का label होता है। Omarchy प्रत्येक model को बिना network access के चलाता है।

### Local LLMs

Omarchy local LLM models चलाने के दो तरीके सुझाता है: LM Studio और Ollama। LM Studio open-weight models को खोजने, उन्हें install करने, और उन्हें चलाने के लिए एक GUI interface प्रदान करता है। आसानी से शुरू करने का यह एक बढ़िया तरीका है। Ollama भी ऐसा ही करने के लिए एक CLI देता है। लेकिन यदि आप local models के लिए नए हैं, तो मैं LM Studio से शुरू करूँगा। आप Omarchy Menu में _Install > AI_ के अंतर्गत किसी को भी install कर सकते हैं।

### Omarchy Skill

Agent skills AI को विशिष्ट tools का विशिष्ट तरीके से उपयोग करने में मदद करती हैं, और Omarchy system को अपने अनुरूप बनाने के लिए एक default skill के साथ आता है। जैसे आपकी Hyprland config को tweak करना, bar को adjust करना, या यहाँ तक कि शुरू से एक नई theme बनाना। यह Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` और प्रत्येक `~/.hermes/profiles/*/skills`), और generic `~/.agents/skills` location के लिए skill directories में symlinked है, इसलिए अधिकांश harnesses उसे अपने आप उठा लेते हैं।

लेकिन आपको इस skill को experimental मानना चाहिए। विभिन्न models उसे विभिन्न प्रभाव के साथ उपयोग करेंगे। पहले उसे plan mode में चलाना सबसे अच्छा है, ताकि आपको अंदाज़ा हो कि agent क्या बदलना चाहेगा। और फिर बदलावों को rollback करने या यहाँ तक कि `omarchy reinstall configs` को invoke करने के लिए तैयार रहें, यदि agent सब कुछ गड़बड़ कर दे।
