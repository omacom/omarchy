### एजेंट इंस्टॉल और अपडेट करना

Hermes को छोड़कर, ये agents mise के lazy installation का उपयोग करते हैं: पहली बार launch करने पर CLI इंस्टॉल होता है, और बाद के launches उसी का पुनः उपयोग करते हैं। mise किसी इंस्टॉल किए गए agent के लिए नए release की जाँच हर चार घंटे में अधिकतम एक बार करता है, ठीक शुरू होने से पहले या shell prompt पर background में। यदि वह update विफल हो जाए या आप offline हों, तो इंस्टॉल किया गया version चलता है। `omarchy update` बाकी Omarchy के साथ इंस्टॉल किए गए agents को भी update करता है, और `mup` केवल mise-managed tools को update करता है।

किसी agent का अपना updater, जैसे `claude update`, `codex update`, या किसी app में update button, mise-managed install को update नहीं करता। `codex update` विफल हो जाता है, और `claude update` सफलता बता सकता है जबकि वह एक अलग copy इंस्टॉल कर देता है जिसे mise track नहीं करता। यदि आप इसके बजाय किसी agent के native installer और updater का उपयोग करना पसंद करते हैं, तो उसे `disable_tools` में जोड़ें; देखें [Preinstalled CLI tools](18-development-tools.md#preinstalled-cli-tools)।

ज़रूरत पड़ने से पहले सभी configured lazy tools इंस्टॉल करने के लिए `mise install --include-lazy` चलाएँ। इसमें agents के साथ-साथ Omarchy के अन्य default CLI tools भी शामिल हैं। किसी एक tool को इंस्टॉल करने या अपनी खुद की installation उपयोग करने के लिए देखें [Preinstalled CLI tools](18-development-tools.md#preinstalled-cli-tools)।

`grok` mise के first-party `grok` package के माध्यम से इंस्टॉल होता है, उसी तरह जैसे `claude` और `codex`। `grok` चलाएँ, या इसे _Setup > Defaults > Agent_ के अंतर्गत चुनें। x.ai पर `curl | bash` installer छोड़ दें। वह तरीका `~/.grok/bin` में दूसरी copy रखता है, उसे `PATH` में आगे जोड़ता है, और Omarchy के wrapper को overwrite कर देता है।

`dsh` अपना browser UI `127.0.0.1:3080` पर खोलता है, जिसमें launch directory उसका default workspace होता है। उसका browser UI कोई starting prompt नहीं लेता, इसलिए `omarchy agent prompt` उसे prompt को आपके clipboard पर रखकर खोलता है ताकि आप उसे paste कर सकें। Omarchy उसे DeepSeek के no-approval permission preset के साथ शुरू करता है। जब आप DeepSeek के official model API का उपयोग करते हैं तो DeepSeek Harness session logs DeepSeek को upload करता है; उसके browser UI में _Settings > General > Upload Session Log_ के अंतर्गत इसे बंद करें। आप उसे जो feedback भेजते हैं वह भी session के साथ upload होता है, जब तक आप उसे `DSH_TELEMETRY_MODE=DISABLED` के साथ शुरू न करें।

### डिफ़ॉल्ट agent

अपना default agent `omarchy default agent <name>` से चुनें या Omarchy Menu (`Super + Space`) में _Setup > Defaults > Agent_ के अंतर्गत चुनें। यदि agent अभी इंस्टॉल नहीं है, तो उसे चुनने पर पहले वह इंस्टॉल हो जाता है। एक ताज़ा Omarchy एक बार दिखाई देने वाली notification के साथ आपको यह चुनाव करने के लिए आमंत्रित करेगा।

Claude चुनने पर यह Chromium, Chrome, Brave, Brave Origin और Edge के लिए उसके browser extension को setup करने का भी प्रयास करता है। Extension setup सभी users पर लागू होता है और आपका system password माँग सकता है; रद्द करने या extension install विफल होने पर भी Claude चुना और launch हो जाता है। अपना browser restart करें, संकेत मिलने पर extension enable करें, और उसे जोड़ना पूरा करने के लिए Claude में sign in करें। Connection जाँचने के लिए Claude में `/chrome` चलाएँ। Firefox और Zen इस extension का समर्थन नहीं करते। यदि यह setup जोड़े जाने से पहले ही Claude आपका default था, तो extension इंस्टॉल करने के लिए उसे फिर से चुनें।

एक बार चुन लेने के बाद, `Super + Shift + Ctrl + A` default agent को एक समर्पित terminal window में launch करता है (या यदि आपने अभी तक नहीं चुना है तो picker सामने लाता है)। आप उसे `omarchy agent prompt "Review this project"` के साथ सीधे किसी कार्य में भी लगा सकते हैं। Freebuff और DeepSeek Harness कोई starting prompt नहीं लेते, इसलिए वे इसके बजाय prompt को आपके clipboard पर रखकर खुलते हैं ताकि आप उसे paste कर सकें। इस तरह launch किए गए agents अपने-अपने don't-stop-to-ask modes में बिना निगरानी के चलते हैं, इसलिए तैयार रहें कि वे वास्तव में कुछ करेंगे! MiniMax Code के पास अपने interactive sessions के लिए ऐसा कोई mode नहीं है, इसलिए वह हमेशा की तरह permissions माँगता है। और चूँकि agents आपकी home directory के लिए trust याद रखने से इनकार करते हैं, इसलिए `$HOME` से launches इसके बजाय `~/Work` में शुरू होते हैं।

Terminal shortcuts भी हैं: `a` default agent को वर्तमान terminal में inline चलाता है, जबकि `c`, `cx` और `cy` OpenCode, Claude Code और Codex को सीधे शुरू करते हैं (फिर से उनके auto-approving modes में)। Theme changes भी agents के साथ sync होते हैं: जब आप Omarchy theme बदलते हैं, तो Claude Code, Pi, OpenCode और Hermes (एक बार Omarchy ने उसे इंस्टॉल कर लिया हो) सभी साथ-साथ बदलते हैं।

### agents panel

Top bar में एक agents icon है। किसी agent को setup करने से पहले, उसका panel आपको Claude, Codex या Grok में sign in करने की प्रक्रिया से ले जाता है, और पहला वाला आपका default agent बन जाता है। उसके बाद, panel हर subscription को एक ही page पर रखता है: प्रत्येक agent और account अपने plan के साथ, उसके 5-hour session और weekly limits में से प्रत्येक के लिए एक meter reset होने तक के समय के साथ (सटीक प्रतिशत के लिए hover करें), या शेष prepaid balance, एक ऐसी line के नीचे जो उन सभी में आपने क्या उपयोग किया है उससे होकर घूमती है, जैसे इस सप्ताह के tokens और आपका सबसे अधिक उपयोग किया गया model। _Make something_ के अंतर्गत यह एक नई theme, plugin या app के लिए starter prompts देता है जो कार्य को आपके default agent को सौंप देते हैं। Apps उसी तरह बनाए जाते हैं जैसे Omarchy के अपने Hype, Monologue और Omacut हैं, C++ और Qt Quick में, omarchy-app agent skill का पालन करते हुए, और उन्हें चाहिए compiler और Qt pieces इंस्टॉल आते हैं। Claude Code, Codex, Grok, Kimi, Cursor और उसकी Grok Bot allowance, GitHub Copilot, Muse, Antigravity, Kimchi और Devin अपनी limits के साथ पहले से covered हैं, और Hermes, Mistral Vibe और Qwen Code एक बार आप उन्हें उपयोग कर लें तो अपने sessions और tokens दिखाते हैं। pi, omp या opencode के माध्यम से आप जिन provider plans और keys का उपयोग करते हैं वे भी दिखाई देते हैं: OpenCode Zen और Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan और Synthetic अपनी limits के साथ; Fireworks, OpenRouter और DeepSeek अपने prepaid balances के साथ; और वे models जिन्हें आप अपने खुद के hardware पर चलाते हैं Local models के अंतर्गत। हर agent को एक बार गिना जाता है, उसी के अंतर्गत जो उसे bill करता है, चाहे आप उसे कितने ही harnesses से चलाएँ।

Panel के लिए bar icon पर left-click करें, अपने default agent को launch करने के लिए right-click करें। इसके पीछे के usage records हर 15 मिनट में `omarchy agent usage-update` द्वारा पुनः बनाए जाते हैं, और panel एक synced folder के माध्यम से आपकी अन्य machines के usage को भी मिला सकता है। पूरी settings के लिए `$OMARCHY_PATH/shell/plugins/agents/` के अंतर्गत README देखें।

### कई subscriptions

यदि आप एक से अधिक Claude, Codex या Grok plan के लिए भुगतान करते हैं — मान लें एक personal Max और एक work वाला — तो Omarchy उन सभी को signed in रख सकता है और उनके बीच जा सकता है। agents panel में + से subscription जोड़ें, जो आपको वहीं प्रक्रिया से ले जाता है, या `omarchy agent account add claude Work` (या `codex`, या `grok`) से जोड़ें। यदि CLI मौजूद नहीं है तो यह उसे इंस्टॉल कर देता है। किसी provider के लिए पहला account आपके सामान्य browser के माध्यम से sign in होता है, ठीक वहाँ जहाँ CLI हमेशा देखता है। उसके बाद हर एक private window के माध्यम से sign in होता है, ताकि जिस account में आपका browser पहले से signed in है वह गलती से न उठा लिया जाए; वहाँ उस account के रूप में sign in करें जिसे आप जोड़ रहे हैं, और पहले से खुली हुई किसी भी private window को पहले बंद कर दें। ऐसा करने के लिए CLI से कभी log out न करें: log out करने से saved sign-in रद्द हो जाता है, और उस account को फिर से जोड़ना होगा।

अपने subscription logins को SSH पर दूसरी Omarchy machine पर copy करने के लिए `omarchy agent account copy user@laptop` चलाएँ। जब destination पर कोई receiver इंस्टॉल नहीं होता, तो sender एक अस्थायी receiver देता है, इसलिए पुरानी Omarchy machines बिना update के accounts प्राप्त कर सकती हैं। इंस्टॉल किए गए receivers को प्राथमिकता मिलती है। यह सभी Claude, Codex और Grok subscriptions copy करता है; उन्हें चुनने के लिए provider names जोड़ें, जैसे `omarchy agent account copy laptop claude` में। Account names और command IDs source से मेल खाते हैं, destination पर पहले से मौजूद accounts सहित। असंबंधित destination accounts के नामों में टकराव होने पर उन्हें एक numeric suffix मिलता है, और settings, skills, plugins और conversation history प्रत्येक machine पर स्थानीय रहते हैं।

मौजूदा destination credentials रखे जाते हैं। वहाँ पहले से signed in किसी source account का नाम उसके credentials बदले बिना synchronize हो जाता है; अन्य accounts उसके साथ जोड़ दिए जाते हैं। मेल खाने वाले accounts के saved credentials बदलने के लिए, destination पर उस account के sessions बंद करने के बाद `omarchy agent account copy --replace laptop claude` उपयोग करें। एक ताज़ा destination को source का active account और switching preferences भी मिलते हैं; एक स्थापित destination अपने रखता है।

Credentials SSH के माध्यम से जाते हैं और destination पर private files में संग्रहीत होते हैं, इसलिए केवल उन्हीं machines पर copy करें जिन पर आप भरोसा करते हैं। यह एक बार की copy है, ongoing synchronization नहीं। Codex refresh tokens किसी अन्य machine द्वारा rotate किए जा सकते हैं, जिससे copy किए गए login को renewal की ज़रूरत पड़ सकती है; कई machines पर एक साथ उपयोग के लिए अलग sign-ins सबसे विश्वसनीय विकल्प रहते हैं। देखें [Codex का account authentication guidance](https://developers.openai.com/codex/auth/ci-cd-auth)।

प्रत्येक provider का एक account active होता है, और हर नया session उसी के रूप में शुरू होता है: `cx`, `cy`, एक सादा `claude`, `codex` या `grok`, `omarchy agent` के माध्यम से launch की गई कोई भी चीज़, और scripts या editors जो CLI को `PATH` पर पाते हैं। `omarchy agent account use work` से switch करें (और `omarchy agent account use main` से वापस), या panel में किसी account का number दबाकर फिर `Enter` दबाकर (या उसके Use button पर click करके)। पहले से चल रहे sessions उसी account पर रहते हैं जिससे वे शुरू हुए थे। Conversation history, settings, skills और plugins accounts के बीच साझा होते हैं, इसलिए उसी folder में `claude --continue` नए account पर वहीं से आगे बढ़ता है जहाँ आपने छोड़ा था।

एक से अधिक account होने पर, panel प्रत्येक account की limits साथ-साथ दिखाता है, जिसमें active एक चिह्नित होता है। डिफ़ॉल्ट रूप से Omarchy आपको तब सूचित करता है जब active account किसी limit के 95% से आगे निकल जाता है, और notification पर click करने से उस account पर switch हो जाता है जिसमें सबसे अधिक headroom है। Panel में किसी account की line पर hover करें और Use के पास दिखाई देने वाले Autoswitch पर click करें (या `m` दबाएँ), या `omarchy agent account mode auto` चलाएँ, ताकि वह इसके बजाय अपने आप switch हो; जब यह on होता है, तो Autoswitch Use की जगह ले लेता है, और उसे फिर click करने से आप notifying पर वापस आ जाते हैं। Threshold बदलने के लिए एक number जोड़ें, जैसे `omarchy agent account mode auto 90` में। यदि हर account threshold से ऊपर है, तो आपको इसके बारे में एक बार सुनने को मिलेगा, साथ में यह भी कि कौन-सा account सबसे पहले खाली होता है। जब कोई active account अपने threshold के 15 points के भीतर होता है (डिफ़ॉल्ट पर 80%), तो उसकी limits हर 15 के बजाय हर तीन मिनट में जाँची जाती हैं।

`omarchy agent account list` हर account और उसकी नवीनतम limits दिखाता है, `omarchy agent account remove work` एक को भुला देता है, और `omarchy agent account rename primary Hey` एक का नाम बदलता है (या panel में किसी account के नाम पर click करें)। ये commands आपके default agent के accounts पर काम करते हैं; दूसरे provider तक पहुँचने के लिए, पहले उसका नाम लें, जैसे `omarchy agent account use codex side` में। `~/.claude` या `~/.codex` में आपके पास पहले से मौजूद login _Main_ account है और जहाँ है वहीं रहता है। लगभग आठ घंटे से अधिक समय तक अप्रयुक्त छोड़ा गया account _Sign-in required_ दिखा सकता है; panel में ही उस account में फिर से sign in करने के लिए उसे click करें, या उसमें एक session शुरू करें, जो अपने आप sign-in refresh कर देता है। जब कोई account जोड़ा गया था तब आपके पास मौजूद MCP servers उसके साथ आ जाते हैं, लेकिन जिन्हें आप बाद में `claude mcp add` से जोड़ते हैं वे केवल उसी account तक पहुँचते हैं जिसमें आपने उन्हें जोड़ा था। Claude Desktop और किसी CLI binary के absolute path के साथ configured tools switch का पालन नहीं करते। एक स्पष्ट `CLAUDE_CONFIG_DIR`, `CODEX_HOME` या `GROK_HOME` चुने गए account पर प्राथमिकता लेता है।

### Crash diagnosis

Omarchy process crashes के लिए systemd-coredump पर नजर रखती है। जब कोई चीज़ segfault होती है, तो आपको एक "Process crashed" notification मिलेगा — उसे click करें, और crash आपके default agent को Omarchy की diagnose-crash skill के साथ सौंप दिया जाता है, जो agent को core dump से तथ्य स्थापित करने और यह तय करने की प्रक्रिया से ले जाती है कि crash upstream report करने लायक है या नहीं। आप इसे `coredumpctl list` से किसी भी PID के खिलाफ़ `omarchy agent crash <pid>` से हाथ से भी चला सकते हैं।

नजर रखना डिफ़ॉल्ट रूप से on है। इसे _Trigger > Toggle > Crash Capture_ के अंतर्गत (या `omarchy toggle crash-capture` से) बंद करें और notifications बंद हो जाएँगी; `omarchy agent crash <pid>` हाथ से फिर भी काम करता है।

Crashes को एक बार में एक program के लिए भी शांत किया जा सकता है, यही diagnosis अंत में आपको देता है। `omarchy crash mute hyprland` केवल उस program के लिए notifications रोकता है, `omarchy crash mute hyprland off` उन्हें वापस लाता है, और अकेला `omarchy crash mute` वही सूचीबद्ध करता है जो आपने mute किया है। यह binary का path उसके नाम जितनी ही खुशी से लेता है, इसलिए `omarchy crash mute /usr/bin/hyprland` वही काम करता है। किसी space वाले नाम को quote करें, जैसे `omarchy crash mute 'Some App'` में। बाकी सब कुछ फिर भी सूचित करता है, और muted program फिर भी crash होता है — यह reminder छिपाता है, यह कुछ ठीक नहीं करता।

### Desktop apps

_Install > AI_ menu में कुछ graphical AI apps भी हैं: ChatGPT desktop app, Claude desktop app (Anthropic का Linux beta, Chat, Cowork और Claude Code tabs के साथ), xAI के models से chat करने के लिए Grok Bot, Herdr Desktop, Hermes Desktop, OpenClaw, Perplexity desktop app और T3 Code। Grok Bot desktop chat app है। Coding agent `grok` command है।

Hermes Desktop वह है जिसके बारे में जानना ज़रूरी है, क्योंकि किसी machine पर एक Hermes होता है, और वह app का होता है: Hermes हमेशा केवल app के माध्यम से इंस्टॉल होता है, और default agent जो `hermes` command चलाता है वह app की होती है। Hermes को default agent के रूप में चुनने पर वही इंस्टॉल होता है जो _Install > AI_ entry इंस्टॉल करती है: package, और Hermes के अपने installer द्वारा `~/.hermes` के अंतर्गत setup किया गया एक Hermes runtime, जिसमें पहली बार कुछ मिनट लगते हैं। वह runtime ही वह एक Hermes है जिसे terminal `hermes` command, default agent और app सभी उपयोग करते हैं, और यह Omarchy release का इंतज़ार करने के बजाय `hermes update` से खुद को update करता है। उसे इंस्टॉल करने पर Hermes को Omarchy theme `omarchy` नाम की skin के रूप में भी मिलती है, जिसका हर Hermes surface आपके themes बदलने पर पालन करता है; यदि आप नहीं चाहते कि ऐसा हो तो Hermes की Appearance settings के अंतर्गत या `/skin` से कोई और चुनें, और Omarchy उस चुनाव को अकेला छोड़ देता है। _Remove > AI_ के अंतर्गत app हटाने से पहले Hermes बंद होता है, gateway सहित, वह runtime उसके साथ ले जाता है, और आपकी chats, memories और वे skills रखता है जो Hermes ने खुद के लिए लिखीं, जब तक आप उसे अन्यथा न कहें: यह पूछता है, डिफ़ॉल्ट रूप से no के साथ, कि क्या वह data और आपकी connection settings भी जानी चाहिए।

OpenClaw का desktop experience उसका Control UI है, जो उसके अपने local gateway द्वारा समर्थित एक web app के रूप में खुलता है। OpenClaw `~/.openclaw` में रहता है और खुद को update करता है: Control UI का "Update Gateway" button उपयोग करें या `openclaw update` चलाएँ, और gateway नए version पर restart हो जाता है। Omarchy केवल वह release चुनती है जिससे एक fresh install शुरू होता है। _Remove > AI_ के अंतर्गत OpenClaw हटाने से gateway service और app उसके साथ चले जाते हैं और फिर पूछा जाता है कि क्या `~/.openclaw` भी जाना चाहिए, क्योंकि उसमें OpenClaw खुद और उसके द्वारा download किए जाने वाले plugin runtimes के साथ-साथ आपकी chats और credentials रहते हैं; डिफ़ॉल्ट उसे रखता है, और OpenClaw फिर से इंस्टॉल करने पर वह उसे वापस उठा लेता है।

Herdr Desktop [Herdr](https://herdr.dev) desktop app है: terminals और coding agents के spaces, tabs और panes जो आपके window बंद करने पर उसके core में चलते रहते हैं। यह किसी package के बजाय Herdr के अपने installer से आता है, इसलिए यह `~/.local/share/herdr-app` में रहता है, जब आपके पास पहले से एक न हो तो अपने core को `~/.local/bin/herdr-core` में साथ लाता है, और दोनों को खुद update करता है। यह Omarchy द्वारा `Super + Ctrl + Return` पर दिए गए `herdr` command को बदलने के बजाय उसके पास बैठता है। उसे इंस्टॉल करने पर Herdr की Omarchy theme चुनी जाती है, जो उसके बाद से आपकी Omarchy theme का पालन करती है। Herdr light mode के लिए एक theme और dark के लिए एक रखता है, इसलिए dark और light Omarchy theme के बीच switch करने के बाद, दूसरे mode के लिए Herdr के theme picker में Omarchy एक बार फिर चुनें।

T3 Code किसी package के बजाय `~/.local/share/t3code` में अपने official AppImage release से चलता है, इसलिए यह खुद को update करता है। उसे इंस्टॉल करने पर पूछा जाता है कि Stable या Nightly channel पर शुरू करना है; बाद में T3 Code की settings में switch करें। आपके threads और settings `~/.t3` में रहते हैं, और _Remove > AI_ के अंतर्गत T3 Code हटाने से वे उसके साथ चले जाते हैं।

### Local models

अपने coding agents के लिए अपनी खुद की machine पर एक open model चलाएँ। आपके prompts और code machine पर ही रहते हैं; model को भेजी गई कोई भी चीज़ उससे बाहर नहीं जाती। इसके साथ शुरू करें:

```bash
omarchy agent local use best
```

या, top bar के agents panel में, + चुनें और फिर Local AI चुनें, जो तब दिखाई देता है जब कोई model इस machine पर fit बैठता हो। पहली बार, यह Podman इंस्टॉल करता है, जो models चलाता है, और NVIDIA machine पर NVIDIA का container toolkit, जो उन्हें GPU देता है। फिर Omarchy इस machine के लिए recommended model चुनती है, उसे download करती है, और शुरू करती है। Model चलने के दौरान tens of GB के download और machine की अधिकांश memory उपयोग में रहने की उम्मीद रखें: Flash Next अपने पूरे 256K context के साथ लगभग 100 GiB उपयोग करता है। यदि अन्य models को वह memory घेरे हुए हैं जो उसे चाहिए, तो यह रुका हुआ setup होता है, एक बार आप किसी एक को रोक दें तो शुरू होने के लिए तैयार। Model logout पर रुक जाता है; जब आपको memory किसी और काम के लिए चाहिए तो उसे खुद रोकें।

`omarchy agent local list` विकल्प दिखाता है और बताता है कि कुछ fit क्यों नहीं बैठते। एक और setup करने के लिए, `omarchy agent local use <recipe>` चलाएँ। आज, 128 GB Strix Halo machines के लिए `qwen3.8-flash-next-gufo` और `qwen3.8-27b-gufo` उपलब्ध हैं; 27B लगभग 40 GiB लेता है, इसलिए वह अन्य कार्यों के लिए जगह छोड़ता है। नई recipes और recommendations package के माध्यम से `omarchy update` के साथ आती हैं।

आपके द्वारा setup किया गया प्रत्येक model agents panel में, आपकी subscriptions के पास, अपनी line पाता है: उसे शुरू करने के लिए play, उसे रोकने और उसकी memory खाली करने के लिए pause, और उस पर अपना agent खोलने के लिए terminal button। कई एक साथ चल सकते हैं जब वे साथ में memory में fit बैठते हों; यदि कोई fit नहीं बैठता, तो Omarchy बताती है कि किस चल रहे model को रोकना है। उन्हें reorder करने के लिए lines खींचें, और किसी model और उसके download को हटाने के लिए चुनी हुई line पर Delete दबाएँ।

Command line से, `omarchy agent local start <recipe>` और `omarchy agent local stop <recipe>` वही करते हैं, `omarchy agent local status` प्रत्येक model दिखाता है, और `omarchy agent --local` आपके default agent को आपके द्वारा शुरू किए गए अंतिम model पर खोलता है (pi यदि आपका default agent local model उपयोग नहीं कर सकता)। कोई भी OpenAI-compatible client भी connect कर सकता है: `status` प्रत्येक model का address दिखाता है (पहला `http://127.0.0.1:11435/v1` है), recipe name ही model है, और key `~/.config/omarchy/agent-local/key` में है।

`omarchy agent local remove <recipe>` किसी model और उन downloads को delete करता है जिनका कोई अन्य model उपयोग नहीं करता।

Third-party runtimes को उनके publisher के साथ labeled किया जाता है। Omarchy हर model को बिना network access के चलाती है।

### Local LLMs

Omarchy local LLM models चलाने के दो तरीके सुझाती है: LM Studio और Ollama। LM Studio open-weight models खोजने, उन्हें इंस्टॉल करने और चलाने के लिए एक GUI interface प्रदान करता है। आसानी से शुरू करने का यह एक बढ़िया तरीका है। Ollama ऐसा ही करने के लिए एक CLI देता है। लेकिन यदि आप local models में नए हैं, तो मैं LM Studio से शुरू करूँगा। आप Omarchy Menu में _Install > AI_ के अंतर्गत दोनों में से कोई भी इंस्टॉल कर सकते हैं।

### The Omarchy Skill

Agent skills AI को विशिष्ट tools का विशिष्ट तरीके से उपयोग करने में मदद करती हैं, और Omarchy system को अपने अनुसार ढालने के लिए एक default skill के साथ आती है। जैसे अपनी Hyprland config को tweak करना, bar को adjust करना, या यहाँ तक कि शुरू से एक नई theme बनाना। यह Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` और प्रत्येक `~/.hermes/profiles/*/skills`), और generic `~/.agents/skills` location के skill directories में symlinked है, इसलिए अधिकांश harnesses उसे अपने आप उठा लेते हैं।

लेकिन आपको इस skill को experimental मानना चाहिए। अलग-अलग models इसका अलग प्रभाव के साथ उपयोग करेंगे। सबसे अच्छा है कि इसे पहले plan mode में चलाएँ, ताकि आपको अंदाज़ा हो कि agent क्या बदलना चाहेगा। और फिर, यदि agent सब गड़बड़ कर दे, तो changes rollback करने या यहाँ तक कि `omarchy reinstall configs` चलाने के लिए तैयार रहें।
