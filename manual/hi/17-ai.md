# AI

Omarchy आपके लिए कोई डिफ़ॉल्ट चुने बिना नीचे दिए गए coding agents के launchers शामिल करता है। पहली बार उपयोग करने पर उसका CLI इंस्टॉल करने के लिए कोई command चलाएँ, फिर संकेत मिलने पर authenticate करें। Hermes और OpenClaw अपवाद हैं: इनके लिए mise के ज़रिए कुछ भी इंस्टॉल नहीं होता, और इनमें से किसी को चुनने पर उसकी अपनी स्वयं-अपडेट होने वाली copy सेट अप हो जाती है, जैसा कि नीचे _डेस्कटॉप ऐप्स_ बताते हैं।

### Agents इंस्टॉल करना और अपडेट करना

Hermes और OpenClaw को छोड़कर, ये agents mise की lazy installation का उपयोग करते हैं: पहला launch CLI इंस्टॉल करता है, और बाद के launches उसका पुन: उपयोग करते हैं। mise किसी इंस्टॉल किए गए agent के लिए नए release की जाँच हर चार घंटों में अधिकतम एक बार करता है, ठीक उसके शुरू होने से पहले या shell prompt पर background में। यदि वह update विफल हो जाए या आप offline हों, तो इंस्टॉल किया गया version चलता है। `omarchy update` बाकी Omarchy के साथ इंस्टॉल किए गए agents को अपडेट करता है, और `mup` केवल mise-managed tools को अपडेट करता है।

किसी agent का अपना updater, जैसे `claude update`, `codex update`, या किसी app में update button, mise-managed install को अपडेट नहीं करता। `codex update` विफल हो जाता है, और `claude update` सफलता की रिपोर्ट कर सकता है जबकि वह एक अलग copy इंस्टॉल कर देता है जिसे mise track नहीं करता। यदि आप इसके बजाय किसी agent के native installer और updater का उपयोग करना पसंद करते हैं, तो उसे `disable_tools` में जोड़ें; [पहले से इंस्टॉल किए गए CLI tools](18-development-tools.md#preinstalled-cli-tools) देखें।

उनकी ज़रूरत पड़ने से पहले सभी configured lazy tools इंस्टॉल करने के लिए, `mise install --include-lazy` चलाएँ। इसमें agents के साथ-साथ Omarchy के अन्य डिफ़ॉल्ट CLI tools भी शामिल हैं। किसी एकल tool को इंस्टॉल करने या अपना स्वयं का installation उपयोग करने के लिए [पहले से इंस्टॉल किए गए CLI tools](18-development-tools.md#preinstalled-cli-tools) देखें।

`grok` mise के first-party `grok` package के माध्यम से इंस्टॉल होता है, उसी तरह जैसे `claude` और `codex`। `grok` चलाएँ, या agents panel में उसे star करें। x.ai पर मौजूद `curl | bash` installer को छोड़ दें। वह तरीका `~/.grok/bin` में एक दूसरी copy डाल देता है, उसे `PATH` में आगे जोड़ देता है, और Omarchy के wrapper को overwrite कर देता है।

`dsh` अपना browser UI `127.0.0.1:3080` पर खोलता है, जिसमें launch directory उसका डिफ़ॉल्ट workspace होता है। उसका browser UI कोई starting prompt नहीं लेता, इसलिए `omarchy agent prompt` उसे paste करने के लिए आपके clipboard पर मौजूद prompt के साथ खोलता है। Omarchy उसे DeepSeek के no-approval permission preset के साथ शुरू करता है। DeepSeek Harness session logs को DeepSeek पर upload करता है जब आप उसके official model API का उपयोग करते हैं; उसे उसके browser UI में _Settings > General > Upload Session Log_ के तहत बंद करें। आप जो feedback उसे भेजते हैं वह भी session के साथ upload होता है, जब तक कि आप उसे `DSH_TELEMETRY_MODE=DISABLED` के साथ शुरू न करें।

### डिफ़ॉल्ट agent

अपना डिफ़ॉल्ट agent agents panel में किसी agent के बगल में मौजूद star से चुनें, जो डिफ़ॉल्ट पर भरा हुआ होता है, या `omarchy default agent <name>` से चुनें, जो वहाँ एक line के बिना किसी भी harness को भी लेता है। यदि agent अभी तक इंस्टॉल नहीं हुआ है, तो उसे चुनने पर वह पहले इंस्टॉल होता है, और उसे app launcher में Agent के बगल में अपना खुद का launcher भी मिलता है। एक ताज़ा Omarchy आपको एक बार की notification के साथ एक सेट अप करने के लिए आमंत्रित करता है, जो agents panel खोलती है।

Claude चुनने पर Chromium, Chrome, Brave, Brave Origin, और Edge के लिए उसके browser extension को सेट अप करने का भी प्रयास किया जाता है। extension setup सभी users पर लागू होता है और आपका system password माँग सकता है; रद्द करने या विफल extension install के बावजूद Claude चुना और launch किया जाता है। अपने browser को restart करें, संकेत मिलने पर extension सक्षम करें, और उसे जोड़ना पूरा करने के लिए Claude में sign in करें। connection जाँचने के लिए Claude में `/chrome` चलाएँ। Firefox और Zen इस extension का समर्थन नहीं करते। यदि यह setup जोड़े जाने से पहले Claude पहले से आपका डिफ़ॉल्ट था, तो extension इंस्टॉल करने के लिए उसे फिर से चुनें।

जब आप चुन लेते हैं, तो `Super + Shift + Ctrl + A` डिफ़ॉल्ट agent को एक समर्पित terminal window में launch करता है (या यदि आपने अभी तक नहीं चुना है तो picker सामने लाता है)। आप उसे `omarchy agent prompt "Review this project"` के साथ सीधे किसी कार्य में भी launch कर सकते हैं। Freebuff और DeepSeek Harness कोई starting prompt नहीं लेते, इसलिए वे इसके बजाय paste करने के लिए आपके clipboard पर मौजूद prompt के साथ खुलते हैं। इस तरह launch किए गए agents अपने-अपने don't-stop-to-ask modes में अकेले चलते हैं, इसलिए उनके सचमुच कुछ करने के लिए तैयार रहें! MiniMax Code के पास अपने interactive sessions के लिए ऐसा कोई mode नहीं है, इसलिए वह हमेशा की तरह permissions माँगता है। और चूँकि agents आपके home directory के लिए trust याद रखने से इनकार करते हैं, इसलिए `$HOME` से होने वाले launches इसके बजाय `~/Work` में शुरू होते हैं।

terminal shortcuts भी हैं: `a` डिफ़ॉल्ट agent को वर्तमान terminal में inline चलाता है, जबकि `c`, `cx`, और `cy` OpenCode, Claude Code, और Codex को सीधे शुरू करते हैं (फिर से उनके auto-approving modes में)। Theme बदलाव agents के साथ भी sync होते हैं: जब आप Omarchy theme बदलते हैं तो Claude Code, Pi, OpenCode, और Hermes (एक बार Omarchy ने उसे इंस्टॉल कर दिया हो) सभी साथ चलते हैं।

### आपके agent निर्देश

हर agent के लिए व्यक्तिगत नियम `~/.agents/AGENTS.md` में जाते हैं, `~/.agents/skills` में shared skills के बगल में। उसे agents panel में + के बगल में मौजूद document icon से खोलें, या `omarchy agent instructions --edit` से खोलें, जो उसे हर उस harness में भी link करता है जो अपनी खुद की global file रखता है: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, Copilot का `~/.copilot/copilot-instructions.md`, और इसी तरह आगे। Crush और Amp `~/.config/AGENTS.md` link पढ़ते हैं, जबकि omp, Kimi, और DeepSeek Harness `~/.agents/AGENTS.md` को सीधे पढ़ते हैं। डिफ़ॉल्ट agent चुनने पर वह भी link हो जाता है। यदि पहले से कोई shared file नहीं थी तो आपकी पहले से मौजूद instructions file shared वाली बन जाती है; अन्यथा उसे link के बगल में `.bak` के रूप में रखा जाता है। कोई अन्य agent इंस्टॉल करने के बाद फिर से link करने के लिए `omarchy agent instructions` चलाएँ।

### agents panel

ऊपरी bar में एक agents icon होता है। किसी agent को सेट अप करने से पहले, उसका panel शुरू करने के तीन तरीके देता है: Claude, Codex, Grok, Gemini, Muse, Cursor, या Copilot subscription में sign in करें, या More के तहत OpenCode Go, MiniMax, Synthetic, या Z.ai coding plan में; Fireworks, OpenCode Zen and Go, OpenRouter के साथ, या More के तहत DeepSeek या किसी अन्य provider के साथ, जिसमें OpenCode sign in करता है, जैसे-जैसे उपयोग करें वैसे-वैसे भुगतान करें, सभी OpenCode में चलते हैं; या अपने computer के लिए सबसे अच्छा model चलाएँ, जब कोई उसके अनुकूल बैठता हो। आप जिस पहले को पूरा करते हैं वह आपका डिफ़ॉल्ट agent बन जाता है, और panel में मौजूद +, या Omarchy Menu में _Agent > Add_, बाद में वही तीनों विकल्प देता है। उसके बाद, panel हर subscription को एक page पर रखता है: हर agent और account उसके plan के साथ, उसके 5-hour session और weekly limits में से प्रत्येक के लिए एक meter और उसके reset होने तक का समय (सटीक प्रतिशत के लिए hover करें), या शेष prepaid balance, एक line के नीचे जो उन सभी में आपके उपयोग की गई चीज़ों को बारी-बारी से दिखाती है, जैसे इस सप्ताह के tokens और आपका सबसे अधिक उपयोग किया गया model। _Make something cool_ के तहत यह किसी नई theme, plugin, app, या game के लिए starter prompts देता है जो कार्य आपके डिफ़ॉल्ट agent को सौंप देते हैं। Apps उसी तरह बनाए जाते हैं जैसे Omarchy के अपने Hype, Monologue, और Omacut बनाए गए हैं, C++ और Qt Quick में, omarchy-make-app agent skill का पालन करते हुए, और उन्हें जिन compiler और Qt हिस्सों की ज़रूरत होती है वे इंस्टॉल आते हैं। Games `~/Games/vibes` में एक एकल three.js page होते हैं, omarchy-make-game agent skill का पालन करते हुए, और सभी वर्तमान theme में एक Game Vibes launcher से खुलते हैं; वे three.js को web से load करते हैं, इसलिए शुरू होने के लिए उन्हें connection की ज़रूरत होती है। Claude Code, Codex, Grok, Kimi, Cursor और उसका Grok Bot allowance, GitHub Copilot, Muse, Gemini (Antigravity के माध्यम से), और Devin अपनी limits के साथ बिल्कुल तैयार मिलते हैं, Kimchi अपने plan, prepaid credits, और spend budgets के साथ, और Hermes, Mistral Vibe, और Qwen Code आपके द्वारा उन्हें उपयोग किए जाने के बाद अपने sessions और tokens दिखाते हैं। pi, omp, या opencode के माध्यम से उपयोग किए जाने वाले Provider plans और keys भी दिखाई देते हैं: OpenCode Zen and Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan, और Synthetic अपनी limits के साथ; OpenRouter और DeepSeek अपने prepaid balances के साथ; Fireworks पिछले 30 दिनों में अपने spend के साथ। अपने खुद के hardware पर चलाए जाने वाले models से प्राप्त Tokens भी कुल में गिने जाते हैं; models का अपना अलग panel होता है, जिसका वर्णन [स्थानीय models](#local-models) के तहत किया गया है। हर agent को एक बार गिना जाता है, उसी के तहत जो उसे bill करता है, चाहे आप उसे कितने ही harnesses के माध्यम से चलाएँ।

panel के लिए bar icon पर left-click करें या `Super + Ctrl + X` दबाएँ, अपने डिफ़ॉल्ट agent को launch करने के लिए right-click करें, और refresh करने के लिए middle-click करें। इसके पीछे मौजूद usage records हर 15 मिनट में `omarchy agent usage update` द्वारा फिर से बनाए जाते हैं, और panel एक synced folder के माध्यम से आपकी अन्य machines से usage को भी मिला सकता है। पूर्ण settings के लिए `$OMARCHY_PATH/shell/plugins/agents/` के तहत README देखें।

### कई subscriptions

यदि आप एक से अधिक Claude, Codex, या Grok plan के लिए भुगतान करते हैं — मान लें, एक personal Max और एक work वाला — तो Omarchy उन सभी को signed in रख सकता है और उनके बीच आ-जा सकता है। agents panel में + के साथ subscription जोड़ें, जो आपको वहीं उसके माध्यम से ले जाता है, या `omarchy agent account add claude Work` (या `codex`, या `grok`) के साथ जोड़ें। वही + और command Gemini (`gemini`) और OpenCode (`opencode`) में sign in करते हैं, और OpenCode में Fireworks (`fireworks`) या OpenRouter (`openrouter`) API key सहेजते हैं; command Copilot (`copilot`), Cursor (`cursor`), और Muse (`muse`) में भी sign in करता है। वे प्रत्येक एक एकल sign-in रखते हैं। यदि CLI मौजूद नहीं है तो वह उसे इंस्टॉल करता है। किसी provider के लिए पहला account आपके सामान्य browser के माध्यम से sign in करता है, ठीक वहीं जहाँ CLI हमेशा देखता है। उसके बाद का हर account एक private window के माध्यम से sign in करता है, ताकि जिस account में आपका browser पहले से signed in है वह गलती से न चुना जाए; वहाँ उस account के रूप में sign in करें जिसे आप जोड़ रहे हैं, और पहले से खुली हुई किसी भी private window को पहले बंद कर दें। ऐसा करने के लिए CLI से कभी log out न करें: log out करने से सहेजा गया sign-in रद्द हो जाता है, और उस account को फिर से जोड़ना पड़ेगा।

किसी अन्य Omarchy machine पर SSH के माध्यम से अपने subscription logins copy करने के लिए, `omarchy agent account copy user@laptop` चलाएँ। जब destination पर कोई इंस्टॉल नहीं होता है तो sender एक temporary receiver देता है, ताकि पुरानी Omarchy machines बिना किसी update के accounts प्राप्त कर सकें। इंस्टॉल किए गए receivers को प्राथमिकता मिलती है। यह सभी Claude, Codex, और Grok subscriptions copy करता है; उन्हें चुनने के लिए provider names जोड़ें, जैसे `omarchy agent account copy laptop claude` में। Account names और command IDs source से मेल खाते हैं, जिनमें destination पर पहले से मौजूद accounts भी शामिल हैं। असंबंधित destination accounts को यदि उनके नाम टकराते हैं तो एक numeric suffix मिलता है, और settings, skills, plugins, और conversation history हर machine पर स्थानीय रहते हैं।

मौजूदा destination credentials रखे जाते हैं। वहाँ पहले से signed in किसी source account का नाम उसके credentials को बदले बिना synchronized किया जाता है; अन्य accounts उसके साथ जुड़ जाते हैं। मेल खाने वाले accounts के लिए सहेजे गए credentials बदलने के लिए, destination पर उस account के sessions छोड़ने के बाद `omarchy agent account copy --replace laptop claude` का उपयोग करें। एक ताज़ा destination को source का active account और switching preferences भी मिलते हैं; एक स्थापित destination अपने रखता है।

Credentials SSH के माध्यम से जाते हैं और destination पर private files में संग्रहीत होते हैं, इसलिए केवल उन machines पर copy करें जिन पर आप भरोसा करते हैं। यह एक बार की copy है, चल रहा synchronization नहीं। Codex refresh tokens किसी अन्य machine द्वारा rotate किए जा सकते हैं, जिससे copy किए गए login को नवीनीकरण की ज़रूरत पड़ जाती है; कई machines पर एक साथ उपयोग के लिए अलग-अलग sign-ins सबसे विश्वसनीय विकल्प बने रहते हैं। [Codex का account authentication मार्गदर्शन](https://developers.openai.com/codex/auth/ci-cd-auth) देखें।

प्रत्येक provider के लिए एक account सक्रिय होता है, और हर नया session उसी के रूप में शुरू होता है: `cx`, `cy`, एक सादा `claude`, `codex`, या `grok`, `omarchy agent` के माध्यम से launch की गई कोई भी चीज़, और वे scripts या editors जो CLI को `PATH` पर पाते हैं। `omarchy agent account use work` से switch करें (और `omarchy agent account use main` से वापस), या panel में किसी account का number दबाकर फिर `Enter` दबाकर (या उसके star पर click करके) switch करें। चल रहे Claude sessions भी switch हो जाते हैं, उनके अगले message से: हर Claude session `~/.claude` में चलता है, जिसमें हमेशा active account का sign-in होता है। किसी पुरानी Omarchy द्वारा किसी account के अपने folder में शुरू किया गया Claude session उस sign-in को तब तक रखता है जब तक वह बंद न हो जाए, इसलिए switch उन sessions के नाम बताता है और उनके खत्म होने पर स्वयं पूरा हो जाता है। चल रहे Codex और Grok sessions उस account पर रहते हैं जिसके साथ वे शुरू हुए थे। Conversation history, settings, skills, और plugins accounts के बीच साझा होते हैं, इसलिए उसी folder में `claude --continue` नए account पर वहीं से आगे बढ़ता है जहाँ आपने छोड़ा था।

एक से अधिक account होने पर, panel हर account की limits को साथ-साथ दिखाता है, जिसमें उपयोग में मौजूद account पर एक भरा हुआ star होता है। Omarchy आपको सूचित करता है जब active account किसी limit के 95% को पार कर जाता है, और notification पर click करने से सबसे अधिक गुंजाइश वाले account पर switch हो जाता है। यह स्वयं कभी switch नहीं करता। `omarchy agent account threshold 90` से threshold बदलें। यदि हर account threshold से ऊपर है, तो आपको इसके बारे में एक बार सुनने को मिलेगा, साथ में यह भी कि कौन सा account सबसे पहले मुक्त होगा। जब कोई active account अपने threshold के 15 points के भीतर होता है (डिफ़ॉल्ट पर 80%), तो उसकी limits हर 15 के बजाय हर तीन मिनट में जाँची जाती हैं।

`omarchy agent account list` हर account और उसकी नवीनतम limits दिखाता है, `omarchy agent account remove work` एक को भुला देता है, और `omarchy agent account rename primary Hey` एक का नाम बदलता है (या panel में किसी account के नाम पर click करें)। ये commands आपके डिफ़ॉल्ट agent के accounts पर काम करते हैं; अन्य provider तक पहुँचने के लिए, पहले उसका नाम दें, जैसे `omarchy agent account use codex side` में। `~/.claude` या `~/.codex` में आपके पास पहले से मौजूद login _Main_ account है। Codex का वहीं रहता है जहाँ वह है; Claude का तब अपने खुद के folder में प्रतीक्षा करता है जब कोई अन्य account सक्रिय होता है। लगभग आठ घंटों से अधिक समय तक अप्रयुक्त छोड़ा गया कोई account _Sign-in required_ दिखा सकता है; उस account में फिर से ठीक panel में sign in करने के लिए उस पर click करें, या उस पर switch करें और एक session शुरू करें, जो sign-in को स्वयं refresh कर देता है। `claude mcp add` के साथ आपके द्वारा जोड़े गए MCP servers हर Claude account तक पहुँचते हैं, क्योंकि वे सभी `~/.claude` में चलते हैं; Codex और Grok के लिए, जब कोई account जोड़ा गया था तब आपके पास मौजूद servers उसके साथ आ जाते हैं, लेकिन बाद वाले केवल उस account तक पहुँचते हैं जिसमें आपने उन्हें जोड़ा था। Claude Desktop अपना खुद का sign-in रखता है, और CLI binary के absolute path के साथ configured Codex या Grok tools switch का पालन नहीं करते। एक स्पष्ट `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, या `GROK_HOME` चुने गए account पर प्राथमिकता लेता है।

### Crash निदान

Omarchy process crashes के लिए systemd-coredump पर नज़र रखता है। जब आप एक डिफ़ॉल्ट agent चुन लेते हैं, तो आपका कोई भी program जो core dump करता है वह एक "Process crashed" notification लाता है — उस पर click करें, और crash Omarchy के omarchy-diagnose-crash skill के साथ आपके डिफ़ॉल्ट agent को सौंप दिया जाता है, जो agent को core dump से तथ्य स्थापित करने और यह तय करने के माध्यम से ले जाता है कि crash की रिपोर्ट upstream करना सार्थक है या नहीं। आप उसे `coredumpctl list` से किसी भी PID के विरुद्ध `omarchy agent crash <pid>` के साथ हाथ से भी चला सकते हैं।

नज़र रखना डिफ़ॉल्ट रूप से चालू होता है। उसे _Trigger > Toggle > Crash Capture Off_ के तहत बंद करें (या `omarchy toggle crash-capture` के साथ) और notifications बंद हो जाती हैं; `omarchy agent crash <pid>` हाथ से फिर भी काम करता है।

Crashes को एक समय में एक program के लिए भी शांत किया जा सकता है, जो diagnosis अंत में आपको देता है। `omarchy crash mute hyprland` केवल उस program के लिए notifications रोकता है, `omarchy crash mute hyprland off` उन्हें वापस लाता है, और `omarchy crash mute` अकेले वह सूची देता है जो आपने mute किया है। यह binary के path को उसके नाम जितनी ही खुशी से लेता है, इसलिए `omarchy crash mute /usr/bin/hyprland` वही काम करता है। किसी space वाले नाम को quote करें, जैसे `omarchy crash mute 'Some App'` में। बाकी सब कुछ फिर भी सूचित करता है, और muted program फिर भी crash होता है — यह reminder छिपाता है, यह कुछ ठीक नहीं करता।

### डेस्कटॉप apps

_Install > AI_ menu में कुछ graphical AI apps भी हैं: Amp Desktop, Antigravity Desktop, ChatGPT desktop app, Claude desktop app (Anthropic का Linux beta, Chat, Cowork, और Claude Code tabs के साथ), xAI के models के साथ chat करने के लिए Grok Bot, Herdr Desktop, Hermes Desktop, OpenClaw, Perplexity desktop app, और T3 Code। Grok Bot desktop chat app है। coding agent `grok` command है।

Hermes Desktop जानने योग्य है, क्योंकि किसी machine में एक Hermes होता है, और वह app का होता है: Hermes हमेशा केवल app के माध्यम से इंस्टॉल होता है, और डिफ़ॉल्ट agent जो `hermes` command चलाता है वह app का होता है। Hermes को डिफ़ॉल्ट agent के रूप में चुनने पर वही चीज़ इंस्टॉल होती है जो _Install > AI_ entry करती है: package, और `~/.hermes` के तहत Hermes runtime जो Hermes के अपने installer द्वारा सेट अप किया जाता है, जिसमें पहली बार कुछ मिनट लगते हैं। वह runtime वह एक Hermes है जिसका terminal `hermes` command, डिफ़ॉल्ट agent और app सभी उपयोग करते हैं, और वह Omarchy release की प्रतीक्षा करने के बजाय `hermes update` से स्वयं को अपडेट करता है। उसे इंस्टॉल करने पर Hermes को Omarchy theme `omarchy` नाम की skin के रूप में भी दिया जाता है, जिसका हर Hermes surface आपके themes बदलने पर पालन करता है; यदि आप नहीं चाहते कि वह ऐसा करे तो Hermes के Appearance settings के तहत या `/skin` के साथ कोई अन्य चुनें, और Omarchy उस पसंद को अकेला छोड़ देता है। _Remove > AI_ के तहत app हटाने पर पहले Hermes बंद होता है, gateway सहित, वह runtime उसके साथ ले जाता है, और आपके chats, memories, और Hermes ने अपने लिए लिखे skills रखता है जब तक आप उसे अन्यथा न कहें: यह पूछता है, डिफ़ॉल्ट रूप से नहीं के साथ, कि क्या वह data और आपकी connection settings भी जानी चाहिए।

OpenClaw का desktop अनुभव उसका Control UI है, जो उसके अपने local gateway द्वारा समर्थित web app के रूप में खुलता है। OpenClaw `~/.openclaw` में रहता है और स्वयं को अपडेट करता है: Control UI के "Update Gateway" button का उपयोग करें या `openclaw update` चलाएँ, और gateway नए version पर restart हो जाता है। Omarchy केवल वह release चुनता है जिससे कोई ताज़ा install शुरू होता है। OpenClaw आपका डिफ़ॉल्ट agent भी हो सकता है: उसे _Agent > Harness_ के तहत चुनने पर `~/.openclaw` में वही copy सेट अप हो जाती है, और agent OpenClaw के terminal UI को उसके gateway से जुड़ा हुआ खोलता है। _Remove > AI_ के तहत OpenClaw हटाने पर gateway service और app उसके साथ जाते हैं और फिर पूछा जाता है कि क्या `~/.openclaw` भी जाना चाहिए, क्योंकि उसमें OpenClaw स्वयं और उसके द्वारा download किए गए plugin runtimes के साथ आपके chats और credentials होते हैं; डिफ़ॉल्ट उसे रखता है, और OpenClaw को फिर से इंस्टॉल करने पर वह उसे फिर से उठा लेता है।

Herdr Desktop [Herdr](https://herdr.dev) desktop app है: terminals और coding agents के spaces, tabs, और panes जो आपके window बंद करने पर उसके core में चलते रहते हैं। यह किसी package के बजाय Herdr के अपने installer से आता है, इसलिए यह `~/.local/share/herdr-app` में रहता है, जब आपके पास पहले से कोई नहीं होता तो अपने core को `~/.local/bin/herdr-core` में साथ लाता है, और दोनों को स्वयं अपडेट करता है। यह Omarchy द्वारा `Super + Ctrl + Return` पर दिए गए `herdr` command के बगल में बैठता है, उसे बदलता नहीं है, और उस command की direct keys प्राप्त करता है: `Alt + Return` और `Alt + Shift + Return` किसी pane को नीचे या दाईं ओर split करते हैं, `Alt + Escape` उसे बंद करता है, `Ctrl + Alt + Arrow` panes के बीच ले जाता है, `Alt + 1..9` और `Alt + Left/Right` एक tab चुनते हैं, और `Alt + Up/Down` spaces के बीच ले जाते हैं। `Ctrl + 1..9` एक space चुनता है और `Alt + Shift + Up/Down` agents के माध्यम से कदम बढ़ाता है। `Ctrl + Space` prefix keys केवल terminal तक रहती हैं, क्योंकि app किसी sequence के लिए एक सादी Ctrl key पकड़ नहीं सकता। Omarchy इन्हें `~/.config/herdr-app/keys.json` में लिखता है, और `omarchy-refresh-herdr-app` उन्हें वापस रखता है। उसे इंस्टॉल करने पर Herdr की Omarchy theme चुनी जाती है, जो उसके बाद से आपकी Omarchy theme का पालन करती है। Herdr light mode के लिए एक theme और dark के लिए एक theme रखता है, इसलिए dark और light Omarchy theme के बीच switch करने के बाद, अन्य mode के लिए Herdr के theme picker में Omarchy को एक बार फिर चुनें।

T3 Code किसी package के बजाय `~/.local/share/t3code` में अपने official AppImage release से चलता है, इसलिए वह स्वयं को अपडेट करता है। उसे इंस्टॉल करने पर पूछा जाता है कि Stable या Nightly channel पर शुरू करना है; बाद में T3 Code के settings में switch करें। आपके threads और settings `~/.t3` में रहते हैं, और _Remove > AI_ के तहत T3 Code हटाने पर वे उसके साथ जाते हैं।

### स्थानीय models

अपने coding agents के लिए अपनी खुद की machine पर एक open model चलाएँ। आपके prompts और code machine पर रहते हैं; model को भेजी गई कोई भी चीज़ उसे नहीं छोड़ती। इससे शुरू करें:

```bash
omarchy models use best text
```

यह इस machine के लिए सबसे अच्छा text model सेट अप करता है, उसी तरह का जिसका आपके agents उपयोग करते हैं। Image, video और music models का अपना-अपना सबसे अच्छा होता है: `omarchy models use best image`, `video` या `music`। हर kind की इस machine के लिए पसंद देखने के लिए `omarchy models use best` चलाएँ।

या स्थानीय models panel को ऊपरी bar में उसके sparkles icon से, agents icon के बगल में, या Super + Ctrl + Alt + X से खोलें, और + चुनें। icon तब दिखाई देता है जब कोई model इस machine के अनुकूल बैठता है। Podman, जो models चलाता है, Omarchy के साथ आता है, NVIDIA machine पर NVIDIA का container toolkit भी आता है, जो उन्हें GPU देता है; यदि इनमें से कोई भी मौजूद नहीं है, तो पहला setup उसे इंस्टॉल करता है। फिर Omarchy इस machine के लिए अनुशंसित model चुनता है, उसे download करता है, और शुरू करता है। दसियों GB के download की और model चलने के दौरान machine की अधिकांश memory उपयोग में होने की अपेक्षा करें: Flash Next अपने पूर्ण 256K context के साथ लगभग 100 GiB उपयोग करता है। यदि अन्य models को वह memory चाहिए जो उसे चाहिए तो वह रुका हुआ सेट अप होता है, आपके एक को रोकने के बाद शुरू होने के लिए तैयार। model logout पर रुक जाता है; जब आपको किसी और चीज़ के लिए memory चाहिए तो उसे स्वयं रोकें।

`omarchy models list` विकल्प दिखाता है और बताता है कि कुछ क्यों अनुकूल नहीं बैठते। कोई अन्य सेट अप करने के लिए, `omarchy models use <recipe>` चलाएँ। आज, 128 GB Strix Halo machines के लिए `qwen3.8-flash-next-gufo` और `qwen3.8-27b-gufo` उपलब्ध हैं; 27B लगभग 40 GiB लेता है, इसलिए वह अन्य काम के लिए जगह छोड़ देता है। Intel के Arc B390 वाले 64 GB laptop पर, `qwen3.6-35b-a3b-llamacpp` लगभग 30 GiB में चलता है। नई recipes और अनुशंसाएँ package के माध्यम से `omarchy update` के साथ आती हैं।

आपके द्वारा सेट अप किया गया हर model स्थानीय models panel में अपनी खुद की line प्राप्त करता है: उसे शुरू करने के लिए play, उसे रोकने और उसकी memory मुक्त करने के लिए pause, और उस पर अपना agent खोलने के लिए terminal button। ऊपर की ओर, एक bar दिखाता है कि machine की memory Omarchy स्वयं (system और आपके apps), हर चल रहे model, और जो मुक्त है, के बीच कैसे विभाजित है। किसी रुके हुए model की ओर इंगित करें और bar दिखाता है कि वह अनुकूल बैठता है या नहीं, या वह कितना कम है। कई एक साथ चल सकते हैं जब वे memory में एक साथ अनुकूल बैठते हैं; यदि कोई अनुकूल नहीं बैठता, तो Omarchy बताता है कि किस चल रहे model को रोकना है। उन्हें फिर से क्रमबद्ध करने के लिए lines को उनके logo से drag करें, और किसी model और उसके download को हटाने के लिए चुनी गई line पर Delete दबाएँ।

आपके द्वारा सेट अप किया गया हर coding model app launcher में अपनी खुद की entry भी प्राप्त करता है, model के नाम के तहत और उसके निर्माता के logo के साथ, उसी तरह जैसे Claude, Codex या Grok में sign in करने पर एक जुड़ती है। यह उस model पर आपका agent खोलता है, और यदि model नहीं चल रहा है तो पहले उसे शुरू करता है: terminal उसे load होते हुए दिखाता है और उसके तैयार होने पर agent को सौंप देता है। किसी model को हटाने से उसकी entry हट जाती है।

हर model coding के लिए नहीं होता। Image, video और music models इसके बजाय Fantasi में खुलते हैं, जो इस machine पर चल रहे model के साथ pictures, video और music बनाने के लिए Omarchy का app है, वहाँ चुना गया या स्थानीय models panel में उनकी line से चुना गया।

कोई model ठीक उसी तरह चलता रहता है जैसे वह सेट अप किया गया था, इसलिए Omarchy update आपके agents के नीचे कभी किसी को restart नहीं करता। जब Omarchy के पास आपके द्वारा सेट अप किए गए model के लिए नया runtime या नए weights होते हैं, तो उसकी line एक update button दिखाती है: उसे दबाएँ और model background में फिर से सेट अप हो जाता है, केवल वही download करता है जो बदला है, और नए version पर restart हो जाता है। जो model रुका हुआ था वह रुका रहता है। `omarchy models update` terminal से हर model के लिए वही करता है।

command line से, `omarchy models start <recipe>` और `omarchy models stop <recipe>` वही करते हैं, `omarchy models status` हर model दिखाता है, और `omarchy agent --local-model <recipe>` उस model को pi में खोलता है, चाहे आपका डिफ़ॉल्ट agent जो भी हो। अपने स्थानीय model को वह बनाने के लिए जो agent hotkey, Quake console, और _Make something_ खोलते हैं, `omarchy default agent local` चलाएँ या _Agent > Harness_ के तहत _Local model_ चुनें। pi अपने खुद के model picker में आपके द्वारा सेट अप किए गए हर model को, और उन machines पर मौजूद models को जिनके साथ आपने pair किया है, भी सूचीबद्ध करता है, इसलिए सादा `pi` भी उन तक पहुँचता है। कोई भी OpenAI-compatible client भी जुड़ सकता है: `status` हर model का address दिखाता है (पहला `http://127.0.0.1:11435/v1` है), recipe name ही model है, और key `~/.config/omarchy/agent-local/key` में है।

`omarchy models remove <recipe>` किसी model और उन downloads को delete करता है जिनका कोई अन्य model उपयोग नहीं करता।

Third-party runtimes को उनके publisher के साथ label किया जाता है। Omarchy हर model को बिना network access के चलाता है।

### स्थानीय LLMs

Omarchy स्थानीय LLM models चलाने के दो तरीके अनुशंसित करता है: LM Studio और Ollama। LM Studio open-weight models खोजने, उन्हें इंस्टॉल करने, और चलाने के लिए एक GUI interface प्रदान करता है। आसानी से शुरू करने का यह एक बढ़िया तरीका है। Ollama ऐसा ही करने के लिए एक CLI देता है। लेकिन यदि आप स्थानीय models के लिए नए हैं, तो मैं LM Studio से शुरुआत करूँगा। आप दोनों में से किसी को भी Omarchy Menu में _Install > AI_ के तहत इंस्टॉल कर सकते हैं।

### Omarchy skills

Agent skills AI को विशिष्ट tools का विशिष्ट तरीके से उपयोग करने में मदद करते हैं, और Omarchy उनमें से सात भेजता है। omarchy skill system को अनुकूल बनाने को cover करता है, जैसे आपकी Hyprland config को tweak करना या bar को समायोजित करना। omarchy-make-theme, omarchy-make-plugin, omarchy-make-app, और omarchy-make-game कुछ नया बनाने को cover करते हैं, omarchy-contribute किसी bug की रिपोर्ट करने या fix upstream भेजने को cover करता है, और omarchy-diagnose-crash किसी crash के core dump पर काम करता है। वे Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` और हर `~/.hermes/profiles/*/skills`), और generic `~/.agents/skills` स्थान के लिए skill directories में symlinked होते हैं, इसलिए अधिकांश harnesses उन्हें स्वचालित रूप से उठा लेते हैं। उसी नाम वाला आपका खुद का skill folder प्राथमिकता लेता है।

लेकिन आपको इन skills को प्रयोगात्मक मानना चाहिए। अलग-अलग models इसका उपयोग अलग-अलग प्रभाव से करेंगे। पहले plan mode में चलाना सबसे अच्छा है, ताकि आपको अंदाज़ा हो कि agent क्या बदलना चाहेगा। और फिर बदलावों को rollback करने या यहाँ तक कि `omarchy reinstall configs` को invoke करने के लिए तैयार रहें, यदि agent सब कुछ अस्त-व्यस्त कर दे।
