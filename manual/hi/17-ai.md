# AI

Omarchy आपके लिए कोई डिफ़ॉल्ट चुने बिना नीचे दिए गए coding agents के लिए launchers शामिल करता है। _Install > AI > CLI_ से एक install करें, फिर संकेत मिलने पर authenticate करें। Hermes और OpenClaw अपवाद हैं: इनमें से किसी एक को चुनने पर उसकी अपनी self-updating copy set up हो जाती है, जैसा कि नीचे _Desktop apps_ में बताया गया है।

### Agents को install और update करना

Hermes और OpenClaw को छोड़कर, हर agent Omarchy के अपने repository से आया एक package है। _Install > AI > CLI_ से या `omarchy install ai cli <command>` के साथ एक install करें, और इसे _Remove > AI > CLI_ से फिर से हटा दें, जिससे इसके sign-ins और history अपनी जगह पर बनी रहती है। ऐसा agent चुनना जो अभी तक install नहीं हुआ है, उसे भी install कर देता है: agents panel में इसे star करना, `omarchy default agent <name>` के साथ इसे चुनना, या इसके subscription में sign in करना। Omarchy किसी agent की हर नई release को एक घंटे के भीतर, हर channel पर publish करता है, और `omarchy update` इसे बाकी system के साथ install कर देता है।

चूँकि pacman इन्हें current रखता है, इसलिए agents के अपने updaters बंद कर दिए गए हैं: `claude update` या किसी app में update button का कोई काम नहीं है। यदि आप किसी agent को उसके अपने installer से चलाना पसंद करते हैं, तो उसी का उपयोग करें और Omarchy के package को uninstalled छोड़ दें; आपकी `PATH` पर पहले से मौजूद copy को installed माना जाता है। ऐसे `curl | bash` installers से बचें जो Omarchy की copy से आगे `PATH` पर दूसरी copy रख देते हैं, जैसे `grok` के लिए x.ai का installer।

`dsh` अपना browser UI `127.0.0.1:3080` पर खोलता है, जिसमें launch directory उसका डिफ़ॉल्ट workspace होता है। इसका browser UI कोई starting prompt नहीं लेता, इसलिए `omarchy agent prompt` इसे आपके clipboard पर मौजूद prompt के साथ खोलता है ताकि आप उसे paste कर सकें। Omarchy इसे DeepSeek के no-approval permission preset के साथ शुरू करता है। जब आप DeepSeek के official model API का उपयोग करते हैं तो DeepSeek Harness session logs DeepSeek को upload करता है; इसे इसके browser UI में _Settings > General > Upload Session Log_ के अंतर्गत बंद कर दें। आप जो feedback इसे भेजते हैं, वह भी session के साथ upload हो जाता है, जब तक कि आप इसे `DSH_TELEMETRY_MODE=DISABLED` के साथ शुरू न करें।

### डिफ़ॉल्ट agent

Agents panel में किसी agent के बगल में मौजूद star के साथ अपना डिफ़ॉल्ट agent चुनें, जो डिफ़ॉल्ट पर भरा हुआ होता है, या `omarchy default agent <name>` के साथ, जो वहाँ कोई पंक्ति न रखने वाले किसी भी harness को भी लेता है। यदि agent अभी तक install नहीं हुआ है, तो इसे चुनने पर पहले यह install हो जाता है, और इसे app launcher में Agent के बगल में अपना एक launcher भी मिल जाता है। एक नई Omarchy आपको एक बार की notification के साथ एक agent set up करने के लिए आमंत्रित करती है, जो agents panel खोलती है।

Claude को चुनने पर Chromium, Chrome, Brave, Brave Origin, और Edge के लिए इसके browser extension को set up करने का भी प्रयास किया जाता है। Extension setup सभी users पर लागू होता है और आपसे आपका system password माँग सकता है; extension install को cancel करने या उसके विफल होने पर भी Claude चुना और launch किया जाता है। अपने browser को restart करें, संकेत मिलने पर extension को enable करें, और इसे जोड़ना पूरा करने के लिए Claude में sign in करें। Connection की जाँच करने के लिए Claude में `/chrome` चलाएँ। Firefox और Zen इस extension का समर्थन नहीं करते। यदि यह setup जोड़े जाने से पहले Claude पहले से आपका डिफ़ॉल्ट था, तो extension install करने के लिए इसे फिर से चुनें।

एक बार चुन लेने के बाद, `Super + Shift + Ctrl + A` डिफ़ॉल्ट agent को एक समर्पित terminal window में launch करता है (या यदि आपने अभी तक कोई नहीं चुना है तो picker सामने लाता है)। आप इसे `omarchy agent prompt "Review this project"` के साथ सीधे किसी कार्य में भी launch कर सकते हैं। Freebuff और DeepSeek Harness कोई starting prompt नहीं लेते, इसलिए वे इसके बजाय आपके clipboard पर मौजूद prompt को paste करने के लिए खोलते हैं। इस तरह launch किए गए agents अपने-अपने don't-stop-to-ask modes में बिना निगरानी के चलते हैं, इसलिए तैयार रहें कि वे वास्तव में कुछ करेंगे! MiniMax Code के पास अपने interactive sessions के लिए ऐसा कोई mode नहीं है, इसलिए यह हमेशा की तरह permissions माँगता है। और चूँकि agents आपकी home directory के लिए trust याद रखने से इनकार करते हैं, इसलिए `$HOME` से launches इसके बजाय `~/Work` में शुरू होते हैं।

Terminal shortcuts भी हैं: `a` वर्तमान terminal में डिफ़ॉल्ट agent को inline चलाता है, जबकि `c`, `cx`, `cy`, और `ca` OpenCode, Claude Code, Codex, और Antigravity को सीधे शुरू करते हैं (फिर से उनके auto-approving modes में)। Theme बदलाव भी agents के साथ sync होते हैं: जब आप Omarchy theme बदलते हैं तो Claude Code, Pi, OpenCode, और Hermes (एक बार Omarchy ने इसे install कर दिया हो) सभी साथ चलते हैं।

### आपके agent निर्देश

हर agent के लिए व्यक्तिगत नियम `~/.agents/AGENTS.md` में जाते हैं, `~/.agents/skills` में साझा skills के बगल में। इसे agents panel में + के बगल में मौजूद document icon के साथ खोलें, या `omarchy agent instructions --edit` के साथ, जो इसे हर उस harness में भी link कर देता है जो अपनी global file रखता है: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, Copilot की `~/.copilot/copilot-instructions.md`, इत्यादि। Crush और Amp `~/.config/AGENTS.md` link पढ़ते हैं, जबकि omp, Kimi, और DeepSeek Harness `~/.agents/AGENTS.md` को सीधे पढ़ते हैं। डिफ़ॉल्ट agent चुनने पर यह भी link हो जाता है। यदि पहले से कोई साझा instructions file नहीं थी, तो आपके पास पहले से मौजूद instructions file ही साझा वाली बन जाती है; अन्यथा इसे link के बगल में `.bak` के रूप में रखा जाता है। किसी अन्य agent को install करने के बाद फिर से link करने के लिए `omarchy agent instructions` चलाएँ।

### Agents panel

Top bar में एक agents icon है। इससे पहले कि आपने कोई agent set up किया हो, इसका panel शुरू करने के तीन तरीके पेश करता है: Claude, Codex, Grok, Gemini, Muse, Cursor, या Copilot subscription में sign in करें, या More के अंतर्गत OpenCode Go, MiniMax, Synthetic, या Z.ai coding plan में; Fireworks, OpenCode Zen and Go, OpenRouter के साथ pay as you go करें, या More के अंतर्गत DeepSeek या किसी अन्य provider में जिसमें OpenCode sign in करता है, ये सभी OpenCode में चलते हैं; या अपने computer के लिए सबसे अच्छा model चलाएँ, जब कोई इसमें fit बैठता हो। आप इनमें से जो पहला पूरा करते हैं, वह आपका डिफ़ॉल्ट agent बन जाता है, और panel में + बाद में भी वही तीनों पेश करता है। उसके बाद, panel हर subscription को एक page पर रख देता है: प्रत्येक agent और account उसके plan के साथ, उसके 5-hour session और weekly limits में से प्रत्येक के लिए एक meter reset होने तक के समय के साथ (सटीक percentage के लिए hover करें), या बचा हुआ prepaid balance, एक ऐसी पंक्ति के नीचे जो उन सभी में आपके द्वारा उपयोग की गई चीज़ों के बीच घूमती रहती है, जैसे इस सप्ताह के tokens और आपका सबसे अधिक उपयोग किया गया model। _Make something cool_ के अंतर्गत यह एक नई theme, plugin, app, या game के लिए starter prompts पेश करता है जो कार्य आपके डिफ़ॉल्ट agent को सौंप देते हैं। Apps उसी तरह बनाई जाती हैं जैसे Omarchy की अपनी Hype, Monologue, और Omacut बनाई गई हैं, C++ और Qt Quick में, omarchy-make-app agent skill का अनुसरण करते हुए, और उन्हें आवश्यक compiler और Qt parts installed आते हैं। Games `~/Games/vibes` में एक single three.js page होती हैं, omarchy-make-game agent skill का अनुसरण करते हुए, और सभी वर्तमान theme में एक Game Vibes launcher से खुलती हैं; वे three.js को web से load करती हैं, इसलिए उन्हें शुरू होने के लिए connection की आवश्यकता होती है। Claude Code, Codex, Grok, Kimi, Cursor और इसका Grok Bot allowance, GitHub Copilot, Muse, Gemini (Antigravity के माध्यम से), और Devin अपनी limits के साथ out of the box कवर किए गए हैं, Kimchi अपने plan, prepaid credits, और spend budgets के साथ, और Hermes, Mistral Vibe, और Qwen Code आपके द्वारा एक बार उपयोग किए जाने के बाद अपने sessions और tokens दिखाते हैं। pi, omp, या opencode के माध्यम से उपयोग किए जाने वाले Provider plans और keys भी दिखाई देते हैं: OpenCode Zen and Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan, और Synthetic अपनी limits के साथ; OpenRouter और DeepSeek अपने prepaid balances के साथ; Fireworks पिछले 30 दिनों में अपने spend के साथ। अपने स्वयं के hardware पर चलाए जाने वाले Coding models को अपनी अलग पंक्तियाँ मिलती हैं, और उनके tokens भी totals में गिने जाते हैं, जैसा कि [Local models](#local-models) के अंतर्गत बताया गया है। हर agent को एक बार गिना जाता है, जो भी इसे bill करता हो उसके अंतर्गत, चाहे आप इसे कितने भी harnesses के माध्यम से चलाएँ।

Panel के लिए bar icon पर left-click करें या `Super + Ctrl + X` दबाएँ, अपने डिफ़ॉल्ट agent को launch करने के लिए right-click करें, और refresh करने के लिए middle-click करें। इसके पीछे के usage records हर 15 मिनट में `omarchy agent usage update` द्वारा फिर से बनाए जाते हैं, और panel एक synced folder के माध्यम से आपकी अन्य machines से usage को merge भी कर सकता है। पूरी settings के लिए `$OMARCHY_PATH/shell/plugins/agents/` के अंतर्गत README देखें।

### कई subscriptions

यदि आप एक से अधिक Claude, Codex, या Grok plan के लिए भुगतान करते हैं — मान लीजिए, एक personal Max और एक work वाला — तो Omarchy उन सभी को signed in रख सकता है और उनके बीच आ-जा सकता है। Agents panel में + के साथ एक subscription जोड़ें, जो आपको वहीं इसके माध्यम से ले जाता है, या `omarchy agent account add claude Work` (या `codex`, या `grok`) के साथ। वही + और command Gemini (`gemini`) और OpenCode (`opencode`) में sign in करते हैं, और OpenCode में Fireworks (`fireworks`) या OpenRouter (`openrouter`) API key save करते हैं; command Copilot (`copilot`), Cursor (`cursor`), और Muse (`muse`) में भी sign in करता है। वे प्रत्येक एक single sign-in रखते हैं। यदि CLI missing है तो यह उसे install कर देता है। किसी provider के लिए पहला account आपके सामान्य browser के माध्यम से, वहीं sign in करता है जहाँ CLI हमेशा देखता है। उसके बाद का प्रत्येक account एक private window के माध्यम से sign in करता है, ताकि जिस account में आपका browser पहले से signed in है, वह गलती से न चुना जाए; वहाँ उस account के रूप में sign in करें जिसे आप जोड़ रहे हैं, और पहले से खुली हुई किसी भी private window को पहले बंद कर दें। ऐसा करने के लिए CLI से कभी log out न करें: log out करने से saved sign-in रद्द हो जाता है, और उस account को फिर से जोड़ना होगा।

SSH पर अपनी subscription logins को किसी अन्य Omarchy machine पर copy करने के लिए, `omarchy agent account copy user@laptop` चलाएँ। जब destination के पास कोई receiver installed नहीं होता, तो sender एक temporary receiver प्रदान करता है, इसलिए पुरानी Omarchy machines बिना किसी update के accounts प्राप्त कर सकती हैं। Installed receivers को प्राथमिकता मिलती है। यह सभी Claude, Codex, और Grok subscriptions को copy करता है; उन्हें चुनने के लिए provider names जोड़ें, जैसे `omarchy agent account copy laptop claude` में। Account names और command IDs source से मेल खाते हैं, जिनमें destination पर पहले से मौजूद accounts भी शामिल हैं। असंबंधित destination accounts को, यदि उनके नाम टकराते हैं, एक numeric suffix मिलता है, और settings, skills, plugins, और conversation history प्रत्येक machine पर local बनी रहती है।

मौजूदा destination credentials रखे जाते हैं। वहाँ पहले से signed in किसी source account का नाम उसकी credentials को बदले बिना synchronize किया जाता है; अन्य accounts उसके साथ जोड़ दिए जाते हैं। मेल खाने वाले accounts के लिए saved credentials को बदलने के लिए, destination पर उस account के sessions छोड़ने के बाद `omarchy agent account copy --replace laptop claude` का उपयोग करें। एक नए destination को source का active account और switching preferences भी मिलती हैं; एक स्थापित destination अपनी preferences रखता है।

Credentials SSH के माध्यम से यात्रा करती हैं और destination पर private files में संग्रहीत होती हैं, इसलिए केवल उन machines पर copy करें जिन पर आप भरोसा करते हैं। यह एक बार की copy है, चल रहा synchronization नहीं। Codex refresh tokens किसी अन्य machine द्वारा rotate किए जा सकते हैं, जिससे copied login को renewal की आवश्यकता पड़ सकती है; कई machines पर एक साथ उपयोग के लिए अलग-अलग sign-ins सबसे विश्वसनीय विकल्प बने रहते हैं। [Codex's account authentication guidance](https://developers.openai.com/codex/auth/ci-cd-auth) देखें।

प्रत्येक provider के लिए एक account सक्रिय होता है, और हर नया session उसी के रूप में शुरू होता है: `cx`, `cy`, एक plain `claude`, `codex`, या `grok`, `omarchy agent` के माध्यम से launch की गई कोई भी चीज़, और scripts या editors जो `PATH` पर CLI ढूँढते हैं। `omarchy agent account use work` के साथ switch करें (और `omarchy agent account use main` के साथ वापस), या panel में किसी account का number दबाकर फिर `Enter` दबाकर (या उसके star पर click करके)। चल रहे Claude sessions भी, उनके अगले message से switch हो जाते हैं: हर Claude session `~/.claude` में चलता है, जिसमें हमेशा active account का sign-in होता है। पुरानी Omarchy द्वारा किसी account के अपने folder में शुरू किया गया Claude session उस sign-in को तब तक रखता है जब तक वह बंद नहीं हो जाता, इसलिए switch उन sessions के नाम बताता है और उनके समाप्त होते ही अपने आप पूरा हो जाता है। चल रहे Codex और Grok sessions उसी account पर रहते हैं जिसके साथ वे शुरू हुए थे। Conversation history, settings, skills, और plugins accounts के बीच साझा किए जाते हैं, इसलिए उसी folder में `claude --continue` नए account पर वहीं से आगे बढ़ता है जहाँ आपने छोड़ा था।

एक से अधिक account के साथ, panel प्रत्येक account की limits को एक-दूसरे के बगल में दिखाता है, जिसमें उपयोग में मौजूद account पर एक भरा हुआ star होता है। जब active account किसी limit के 95% से आगे निकल जाता है तो Omarchy आपको सूचित करता है, और notification पर click करने से सबसे अधिक headroom वाले account पर switch हो जाता है। यह कभी अपने आप switch नहीं करता। Threshold को `omarchy agent account threshold 90` के साथ बदलें। यदि हर account threshold से ऊपर है, तो आपको इसके बारे में एक बार सुनने को मिलेगा, साथ ही यह भी कि कौन-सा account सबसे पहले मुक्त होगा। जब कोई active account अपने threshold के 15 points के भीतर होता है (डिफ़ॉल्ट पर 80%), तो उसकी limits हर 15 के बजाय हर तीन मिनट में जाँची जाती हैं।

`omarchy agent account list` हर account और उसकी नवीनतम limits दिखाता है, `omarchy agent account remove work` एक को भुला देता है, और `omarchy agent account rename primary Hey` एक का नाम बदल देता है (या panel में किसी account के नाम पर click करें)। ये commands आपके डिफ़ॉल्ट agent के accounts पर काम करते हैं; अन्य provider तक पहुँचने के लिए, पहले उसका नाम दें, जैसे `omarchy agent account use codex side` में। `~/.claude` या `~/.codex` में आपके पास पहले से मौजूद login ही _Main_ account है। Codex का login वहीं रहता है जहाँ वह है; Claude का login अपने एक folder में प्रतीक्षा करता है जबकि कोई अन्य account सक्रिय होता है। लगभग आठ घंटों से अधिक समय तक unused छोड़ा गया कोई account _Sign-in required_ दिखा सकता है; उस account में panel में ही फिर से sign in करने के लिए उस पर click करें, या उस पर switch करके एक session शुरू करें, जो अपने आप sign-in को refresh कर देता है। `claude mcp add` के साथ जोड़े गए MCP servers हर Claude account तक पहुँचते हैं, क्योंकि वे सभी `~/.claude` में चलते हैं; Codex और Grok के लिए, किसी account को जोड़ते समय आपके पास मौजूद servers उसके साथ आते हैं, लेकिन बाद वाले केवल उसी account तक पहुँचते हैं जिसमें आपने उन्हें जोड़ा था। Claude Desktop अपना एक अलग sign-in रखता है, और किसी CLI binary के absolute path के साथ configure किए गए Codex या Grok tools switch का अनुसरण नहीं करते। एक स्पष्ट `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, या `GROK_HOME` चुने गए account पर प्राथमिकता लेता है।

### Crash निदान

Omarchy process crashes के लिए systemd-coredump पर नजर रखता है। एक बार जब आप डिफ़ॉल्ट agent चुन लेते हैं, तो core dump करने वाला आपका कोई भी program एक "Process crashed" notification लाता है — उस पर click करें, और crash को Omarchy के omarchy-diagnose-crash skill के साथ आपके डिफ़ॉल्ट agent को सौंप दिया जाता है, जो core dump से तथ्यों को स्थापित करने और यह तय करने में agent का मार्गदर्शन करता है कि क्या crash को upstream report करना उचित है। आप इसे `coredumpctl list` से किसी भी PID के विरुद्ध `omarchy agent crash <pid>` के साथ हाथ से भी चला सकते हैं।

यह देखना डिफ़ॉल्ट रूप से चालू है। इसे _Trigger > Toggle > Crash Capture Off_ के अंतर्गत बंद कर दें (या `omarchy toggle crash-capture` के साथ) और notifications बंद हो जाती हैं; `omarchy agent crash <pid>` हाथ से अभी भी काम करता है।

Crashes को एक समय में एक program के लिए भी शांत किया जा सकता है, जो निदान अंत में आपको पेश करता है। `omarchy crash mute hyprland` केवल उस program के लिए notifications रोक देता है, `omarchy crash mute hyprland off` उन्हें वापस लाता है, और अकेले `omarchy crash mute` वह सूचीबद्ध करता है जो आपने mute किया है। यह binary के path को उसके नाम जितनी ही खुशी से लेता है, इसलिए `omarchy crash mute /usr/bin/hyprland` भी वही काम करता है। किसी ऐसे नाम को उद्धृत करें जिसमें space हो, जैसे `omarchy crash mute 'Some App'` में। बाकी सब कुछ अभी भी सूचित करता है, और muted program अभी भी crash होता है — यह reminder को छिपाता है, यह कुछ भी ठीक नहीं करता।

### Desktop apps

_Install > AI > Desktop_ में graphical AI apps हैं: Amp Desktop, Antigravity Desktop, ChatGPT desktop app, Claude desktop app (Anthropic का Linux beta, Chat, Cowork, और Claude Code tabs के साथ), xAI के models के साथ chat करने के लिए Grok Bot, Herdr Desktop, Hermes Desktop, OpenClaw, Perplexity desktop app, और T3 Code। Grok Bot desktop chat app है। Coding agent `grok` command है।

Hermes Desktop के बारे में जानना ज़रूरी है, क्योंकि किसी machine में एक Hermes होता है, और वह app का होता है: Hermes हमेशा केवल app के माध्यम से ही install होता है, और डिफ़ॉल्ट agent द्वारा चलाई जाने वाली `hermes` command app की ही होती है। Hermes को डिफ़ॉल्ट agent के रूप में चुनने पर वही चीज़ install होती है जो _Install > AI > Desktop_ entry करती है: package, और Hermes के अपने installer द्वारा set up किया गया `~/.hermes` के अंतर्गत एक Hermes runtime, जिसमें पहली बार कुछ मिनट लगते हैं। वह runtime ही वह एकमात्र Hermes है जिसका उपयोग terminal `hermes` command, डिफ़ॉल्ट agent और app सभी करते हैं, और यह Omarchy release की प्रतीक्षा करने के बजाय `hermes update` के साथ स्वयं को update करता है। इसे install करने पर Hermes को Omarchy theme `omarchy` नाम की skin के रूप में भी सौंपा जाता है, जिसका अनुसरण हर Hermes surface आपके theme बदलने के साथ करता है; यदि आप नहीं चाहते कि ऐसा हो तो Hermes की Appearance settings के अंतर्गत या `/skin` के साथ कोई अन्य चुनें, और Omarchy उस पसंद को अकेला छोड़ देता है। _Remove > AI > Desktop_ के अंतर्गत app को हटाने पर पहले Hermes बंद हो जाता है, gateway सहित, वह runtime उसके साथ चला जाता है, और आपकी chats, memories, और वे skills जो Hermes ने अपने लिए लिखीं, बनी रहती हैं जब तक कि आप इसे अन्यथा न कहें: यह पूछता है, डिफ़ॉल्ट रूप से no के साथ, कि क्या वह data और आपकी connection settings भी चली जानी चाहिए।

OpenClaw का desktop अनुभव उसका Control UI है, जो उसके अपने local gateway द्वारा समर्थित एक web app के रूप में खुलता है। OpenClaw `~/.openclaw` में रहता है और स्वयं को update करता है: Control UI के "Update Gateway" button का उपयोग करें या `openclaw update` चलाएँ, और gateway नए version पर restart हो जाता है। Omarchy केवल वह release चुनता है जिससे एक नया install शुरू होता है। OpenClaw आपका डिफ़ॉल्ट agent भी हो सकता है: इसे `omarchy default agent openclaw` के साथ चुनने पर `~/.openclaw` में वही copy set up हो जाती है, और agent OpenClaw के terminal UI को उसके gateway से जुड़ा हुआ खोलता है। _Remove > AI > Desktop_ के अंतर्गत OpenClaw को हटाने पर gateway service और app उसके साथ चले जाते हैं और फिर पूछा जाता है कि क्या `~/.openclaw` भी चला जाना चाहिए, क्योंकि उसमें OpenClaw स्वयं और उसके द्वारा download किए गए plugin runtimes के साथ आपकी chats और credentials होती हैं; डिफ़ॉल्ट इसे रखता है, और OpenClaw को फिर से install करने पर यह इसे फिर से उठा लेता है।

Herdr Desktop [Herdr](https://herdr.dev) desktop app है: terminals और coding agents के spaces, tabs, और panes जो आपके window बंद करने पर भी इसके core में चलते रहते हैं। यह किसी package के बजाय Herdr के अपने installer से आता है, इसलिए यह `~/.local/share/herdr-app` में रहता है, जब आपके पास पहले से कोई नहीं होता तो अपने core को `~/.local/bin/herdr-core` में साथ लाता है, और दोनों स्वयं को update करते हैं। यह `Super + Ctrl + Return` पर Omarchy द्वारा भेजी गई `herdr` command के बगल में बैठता है, उसे प्रतिस्थापित करने के बजाय, और उस command की direct keys प्राप्त करता है: `Alt + Return` और `Alt + Shift + Return` एक pane को नीचे या दाईं ओर विभाजित करते हैं, `Alt + Escape` इसे बंद करता है, `Ctrl + Alt + Arrow` panes के बीच जाता है, `Alt + 1..9` और `Alt + Left/Right` एक tab चुनते हैं, और `Alt + Up/Down` spaces के बीच जाते हैं। `Ctrl + 1..9` एक space चुनता है और `Alt + Shift + Up/Down` agents के माध्यम से आगे बढ़ता है। `Ctrl + Space` prefix keys केवल terminal के लिए ही रहती हैं, क्योंकि app किसी sequence के लिए एक plain Ctrl key को पकड़ नहीं सकता। Omarchy इन्हें `~/.config/herdr-app/keys.json` में लिखता है, और `omarchy-refresh-herdr-app` इन्हें वापस रख देता है। इसे install करने पर Herdr की Omarchy theme चुनी जाती है, जो उसके बाद से आपकी Omarchy theme का अनुसरण करती है। Herdr light mode के लिए एक theme और dark के लिए एक theme रखता है, इसलिए dark और light Omarchy theme के बीच switch करने के बाद, अन्य mode के लिए Herdr के theme picker में Omarchy को एक बार फिर चुनें।

T3 Code किसी package के बजाय `~/.local/share/t3code` में अपने official AppImage release से चलता है, इसलिए यह स्वयं को update करता है। इसे install करने पर पूछा जाता है कि Stable या Nightly channel पर शुरू करना है; बाद में T3 Code की settings में switch करें। आपके threads और settings `~/.t3` में रहते हैं, और _Remove > AI > Desktop_ के अंतर्गत T3 Code को हटाने पर वे उसके साथ चले जाते हैं।

### Local models

अपने coding agents के लिए अपनी machine पर एक open model चलाएँ। आपके prompts और code machine पर ही रहते हैं; model को भेजी गई कोई भी चीज़ उसे नहीं छोड़ती। इससे शुरू करें:

```bash
omarchy models use best text
```

यह इस machine के लिए सबसे अच्छा text model set up करता है, वह प्रकार जिसका उपयोग आपके agents करते हैं। Image, video और music models का अपना-अपना सबसे अच्छा होता है: `omarchy models use best image`, `video` या `music`। इस machine के लिए प्रत्येक प्रकार की पसंद देखने के लिए `omarchy models use best` चलाएँ।

या agents panel में + चुनें: _Use a local model_ के अंतर्गत यह हर उस coding model को सूचीबद्ध करता है जो इस machine में fit बैठता है, अनुशंसित वाला पहले। Podman, जो models चलाता है, Omarchy के साथ आता है, जैसा कि NVIDIA machine पर NVIDIA का container toolkit आता है, जो उन्हें GPU देता है; यदि इनमें से कोई भी missing है, तो पहला setup उसे install कर देता है। फिर Omarchy इस machine के लिए अनुशंसित model चुनता है, उसे download करता है, और उसे शुरू करता है। Tens of GB के download की और model के चलने के दौरान machine की अधिकांश memory के उपयोग में होने की अपेक्षा करें: Flash Next अपने पूरे 256K context के साथ लगभग 100 GiB का उपयोग करता है। यदि अन्य models को वह memory चाहिए जो इसे चाहिए, तो यह stopped set up होता है, आपके द्वारा किसी एक को रोकते ही शुरू होने के लिए तैयार। Model logout पर रुक जाता है; जब आपको किसी और चीज़ के लिए memory चाहिए तो इसे स्वयं रोक दें।

`omarchy models list` विकल्प दिखाता है और बताता है कि कुछ क्यों fit नहीं बैठते। किसी अन्य को set up करने के लिए, `omarchy models use <recipe>` चलाएँ। आज, 128 GB Strix Halo machines के लिए `qwen3.8-flash-next-gufo` और `qwen3.8-27b-gufo` उपलब्ध हैं; 27B लगभग 40 GiB लेता है, इसलिए यह अन्य काम के लिए जगह छोड़ देता है। Intel के Arc B390 वाले 64 GB laptop पर, `qwen3.6-35b-a3b-llamacpp` लगभग 30 GiB में चलता है। नई recipes और अनुशंसाएँ package के माध्यम से `omarchy update` के साथ आती हैं।

जोड़ा गया coding model agents panel में, आपकी subscriptions के बगल में, अपनी अलग पंक्ति प्राप्त करता है: इसे शुरू करने के लिए play, इसे रोकने और इसकी memory मुक्त करने के लिए pause, जब यह चल रहा हो तो इसे आपके tailnet पर अन्य machines के साथ साझा करने के लिए Tailscale mark, और इस पर अपना agent खोलने के लिए terminal button। इसकी पंक्ति download, load या stop को होते हुए दिखाती है, और जब इसे शुरू करने के लिए पर्याप्त मुक्त memory नहीं होती तो ऐसा कहती है, या जब यह किसी error के साथ रुकता है तो इसके logs से link करती है। जब वे memory में एक साथ fit बैठते हैं तो कई एक साथ चल सकते हैं। इस machine से model को, download सहित, हटाने के लिए किसी चुनी हुई पंक्ति पर Delete दबाएँ; + इसे फिर से set up कर सकता है। Terminal से set up किया गया coding model + के अंतर्गत तब तक प्रतीक्षा करता है जब तक आप इसे नहीं जोड़ते, और वे models भी जिन्हें आपके द्वारा paired की गई machine (`omarchy models pair <host>`) चलाती है।

आपके द्वारा set up किया गया हर coding model app launcher में भी, model के नाम के अंतर्गत और उसके निर्माता के logo के साथ, अपनी अलग entry प्राप्त करता है, उसी तरह जैसे Claude, Codex या Grok में sign in करने पर एक जुड़ती है। यह उस model पर आपका agent खोलता है, और यदि model नहीं चल रहा है तो पहले उसे शुरू करता है: terminal इसे load होते हुए दिखाता है और इसके तैयार होते ही agent को सौंप देता है। किसी model को हटाने से उसकी entry हट जाती है।

हर model coding के लिए नहीं होता। Image, video और music models इसके बजाय Fantasi में खुलते हैं, जो इस machine पर चल रहे model के साथ pictures, video और music बनाने के लिए Omarchy का app है, और वहाँ या `omarchy models` के साथ प्रबंधित किए जाते हैं।

कोई model ठीक उसी तरह चलता रहता है जैसे उसे set up किया गया था, इसलिए Omarchy update कभी आपके agents के नीचे किसी को restart नहीं करता। जब Omarchy के पास किसी ऐसे model के लिए नया runtime या नए weights होते हैं जिसे आपने set up किया है, तो इसकी पंक्ति एक update button दिखाती है: इसे दबाएँ और model background में फिर से set up हो जाता है, केवल वही download करता है जो बदला है, और नए version पर restart हो जाता है। जो model रुका हुआ था, वह रुका ही रहता है। `omarchy models update` terminal से हर model के लिए यही करता है।

Command line से, `omarchy models start <recipe>` और `omarchy models stop <recipe>` यही करते हैं, `omarchy models status` हर model दिखाता है, और `omarchy agent --local-model <recipe>` उस model को pi में खोलता है, चाहे आपका डिफ़ॉल्ट agent कोई भी हो। अपने local model को वह बनाने के लिए जो agent hotkey, Quake console, और _Make something_ खोलते हैं, `omarchy default agent local` चलाएँ या agents panel में किसी चलते हुए model को star करें। pi अपने स्वयं के model picker में आपके द्वारा set up किए गए हर model को, और उन machines पर मौजूद models को भी सूचीबद्ध करता है जिनके साथ आपने pair किया है, इसलिए plain `pi` भी उन तक पहुँचता है। कोई भी OpenAI-compatible client भी जुड़ सकता है: `status` प्रत्येक model का address दिखाता है (पहला `http://127.0.0.1:11435/v1` है), recipe name ही model है, और key `~/.config/omarchy/agent-local/key` में है।

`omarchy models remove <recipe>` किसी model को और उन downloads को delete कर देता है जिनका उपयोग कोई अन्य model नहीं करता।

Third-party runtimes को उनके publisher के साथ label किया जाता है। Omarchy हर model को बिना network access के चलाता है।

### Local LLMs

Omarchy local LLM models चलाने के दो तरीके अनुशंसित करता है: LM Studio और Ollama। LM Studio open-weight models खोजने, उन्हें install करने, और उन्हें चलाने के लिए एक GUI interface प्रदान करता है। यह आसानी से शुरू करने का एक शानदार तरीका है। Ollama ऐसा ही करने के लिए एक CLI प्रदान करता है। लेकिन यदि आप local models में नए हैं, तो मैं LM Studio से शुरू करूँगा। Omarchy Menu में LM Studio को _Install > AI > Desktop_ से और Ollama को _Install > AI > CLI_ से install करें।

### Omarchy skills

Agent skills AI को विशिष्ट tools का विशिष्ट तरीके से उपयोग करने में मदद करती हैं, और Omarchy उनमें से सात भेजता है। omarchy skill system को अनुकूलित करने को कवर करती है, जैसे आपकी Hyprland config को tweak करना या bar को adjust करना। omarchy-make-theme, omarchy-make-plugin, omarchy-make-app, और omarchy-make-game कुछ नया बनाने को कवर करती हैं, omarchy-contribute किसी bug को report करने या upstream कोई fix भेजने को कवर करती है, और omarchy-diagnose-crash किसी crash के core dump पर काम करती है। वे Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` और प्रत्येक `~/.hermes/profiles/*/skills`), और generic `~/.agents/skills` स्थान के लिए skill directories में symlinked हैं, इसलिए अधिकांश harnesses इन्हें स्वचालित रूप से उठा लेते हैं। समान नाम वाला आपका अपना skill folder प्राथमिकता लेता है।

लेकिन आपको इन skills को प्रयोगात्मक मानना चाहिए। अलग-अलग models इसका अलग-अलग प्रभाव से उपयोग करेंगे। पहले plan mode में चलाना सबसे अच्छा है, ताकि आपको अंदाज़ा हो कि agent क्या बदलना चाहेगा। और फिर बदलावों को rollback करने या यहाँ तक कि `omarchy reinstall configs` को invoke करने के लिए तैयार रहें, यदि agent सब कुछ गड़बड़ कर दे।
