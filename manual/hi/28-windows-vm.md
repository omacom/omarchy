# Windows VM

Omarchy x86_64 मशीनों पर Docker VM के माध्यम से Windows चलाने का एक आसान तरीका प्रदान करता है। आप इसे Omarchy मेनू (`Super + Space`) से _Install > Windows_ का उपयोग करके इंस्टॉल कर सकते हैं।

इसके लिए आपकी मशीन को KVM वर्चुअलाइज़ेशन की आवश्यकता है, जो अधिकांश मशीनों में होता है — लेकिन यह कभी-कभी BIOS में बंद होता है, और यदि ऐसा है तो इंस्टॉलर आपको बता देगा। आपको डिस्क स्थान की भी आवश्यकता होगी: जितना आप Windows को दें, साथ में इमेज के लिए लगभग 10GB।

इंस्टॉलर पूछता है कि कितनी RAM, कितने CPU कोर और कितनी डिस्क देनी है (64GB या अधिक समझदारी भरी न्यूनतम सीमा है), फिर Windows के लिए उपयोगकर्ता नाम और पासवर्ड पूछता है। उन्हें खाली छोड़ दें और आपको `docker` / `admin` मिलेंगे। डाउनलोड में कुछ समय लगता है — 10-15 मिनट सामान्य है — और आप `http://127.0.0.1:8006` पर ब्राउज़र में प्रगति देख सकते हैं। कंसोल खोलने से पहले ब्राउज़र वही उपयोगकर्ता नाम और पासवर्ड माँगता है।

## इसका उपयोग करना

एक बार यह इंस्टॉल हो जाए, तो ऐप लॉन्चर से _Windows_ लॉन्च करें। यह VM शुरू करता है, यदि वह पहले से नहीं चल रहा है, और आपको RDP के माध्यम से, पूर्ण स्क्रीन में, कनेक्ट करता है। कोल्ड स्टार्ट पर इसे 15-30 सेकंड दें।

RDP सत्र ध्वनि, आपका माइक्रोफ़ोन और एक साझा क्लिपबोर्ड ले जाता है, इसलिए Linux और Windows के बीच टेक्स्ट कॉपी करना बस काम करता है। रिज़ॉल्यूशन आपकी विंडो के अनुसार चलता है, और Omarchy आपकी डिस्प्ले स्केलिंग को आगे बढ़ाता है, इसलिए HiDPI स्क्रीन पर यह धुंधली गड़बड़ी नहीं बनता।

जब आप RDP विंडो बंद करते हैं, तो VM स्वचालित रूप से बंद हो जाता है। यदि आप इसे चलता रहने देना पसंद करते हैं — मान लीजिए वहाँ आपका कोई काम चल रहा है — तो इसके बजाय इसे `omarchy windows vm launch --keep-alive` के साथ लॉन्च करें।

बाकी नियंत्रण उसी कमांड पर हैं:

```bash
omarchy windows vm status    # is it running?
omarchy windows vm stop      # shut it down
omarchy windows vm launch    # start and connect
```

## फ़ाइलें साझा करना

आपकी होम डायरेक्टरी में `~/Windows` डायरेक्टरी स्वचालित रूप से VM के साथ साझा की जाती है। यदि आप चाहते हैं कि फ़ाइलें Windows के लिए सुलभ हों, तो उन्हें वहाँ रखें। VM के पास आपकी फ़ाइल प्रणाली के किसी अन्य भाग तक पहुँच नहीं है, इसलिए आप Windows की ओर की किसी भी खराब चीज़ से सुरक्षित हैं। इसकी अपनी वर्चुअल डिस्क `~/.windows` पर उपलब्ध है।

वे परिचित होम पथ अपनी-अपनी फ़ाइल प्रणालियों पर रहते हैं। वे आपके स्वामित्व वाली डायरेक्टरीज़ के सिमलिंक भी हो सकते हैं, जो तब उपयोगी होता है जब वर्चुअल डिस्क किसी बड़ी ड्राइव पर रहती है। इंस्टॉलर उस फ़ाइल प्रणाली पर मुक्त स्थान मापता है जिसमें वास्तव में `~/.windows` मौजूद है, न कि आवश्यक रूप से उस फ़ाइल प्रणाली पर जिसमें आपकी होम डायरेक्टरी है।

डिस्क और साझा पथों को अलग-अलग, गैर-अतिव्यापी डायरेक्टरीज़ के रूप में रखें। हटाना जानबूझकर डिस्क डायरेक्टरी को खाली करता है, लेकिन साझा डायरेक्टरी को संरक्षित रखता है। हटाने से ठीक पहले, Omarchy एक सीमित नियंत्रण जाँच करता है और यदि वह जाँच समय-समाप्त हो जाती है या यह साबित नहीं कर पाती कि दोनों ट्री अलग-अलग हैं, तो कुछ भी हटाने से इनकार कर देता है।

VM शुरू होने से पहले, Omarchy उन दो डायरेक्टरीज़ को खोलता है और पिन करता है, फिर सटीक डायरेक्टरी इनोड्स को `/var/lib/omarchy/windows/mounts` के नीचे निजी प्रति-उपयोगकर्ता एंकरों पर बाइंड-माउंट करता है। Docker केवल उन रूट-संरक्षित एंकरों को देखता है। यह कस्टम डिस्क स्थानों को संरक्षित करता है, जबकि आपके रूप में चल रही किसी अन्य प्रक्रिया को विशेषाधिकार प्राप्त कंटेनर द्वारा उपयोग किए जाने से पहले किसी जाँचे गए पथ को बदलने से रोकता है। मौजूदा डिस्क और साझा डायरेक्टरीज़ को माइग्रेशन के दौरान मोड `0700` तक कड़ा कर दिया जाता है, ताकि अन्य स्थानीय खाते उनकी सामग्री ब्राउज़ न कर सकें।

VM के पोर्ट केवल localhost से बंधे हैं, इसलिए आपके नेटवर्क पर कुछ भी Windows मशीन तक नहीं पहुँच सकता। वेब कंसोल को भी कॉन्फ़िगर किए गए Windows उपयोगकर्ता नाम और पासवर्ड की आवश्यकता होती है, जो किसी अन्य स्थानीय खाते को पोर्ट 8006 के माध्यम से VM चलाने से रोकता है।

## सीमाएँ और लाइसेंसिंग

इस सेटअप के साथ कोई GPU पासथ्रू नहीं है, इसलिए यह गेमिंग या वीडियो संपादन के लिए उपयुक्त नहीं है। यह Microsoft Office या जो कुछ भी आपको बिल्कुल चाहिए, उसे चलाने का एक शानदार तरीका है।

इंस्टॉल किया गया संस्करण Windows 11 Pro है, अनएक्टिवेटेड। गेट किए गए फ़ीचर्स का उपयोग करने के लिए आपको अपनी स्वयं की लाइसेंस कुंजी की आवश्यकता होगी।

यदि यह कंप्यूटर Windows के साथ आया था, तो OEM कुंजी Omarchy इंस्टॉल करने के बाद भी फ़र्मवेयर में बनी रहती है। इसे `omarchy windows key` के साथ प्रिंट करें। वह कुंजी इस मशीन से बंधी है — यह इस हार्डवेयर पर पुनः इंस्टॉल किए गए Windows को सक्रिय करेगी, लेकिन आमतौर पर यह VM को सक्रिय नहीं करेगी।

आप बाद में टर्मिनल में `omarchy windows vm install` चलाकर संसाधन आवंटन बदल सकते हैं, जो आपके उत्तरों से VM के कॉन्फ़िगरेशन को फिर से लिखता है। Compose फ़ाइल स्वयं अब `/var/lib/omarchy/windows/docker-compose.yml` पर रहती है और रूट के स्वामित्व में है — यह जानबूझकर किया गया है, ताकि आपके रूप में चल रही कोई प्रक्रिया इसे फिर से लिखकर विशेषाधिकार प्राप्त ब्रिंग-अप से आपकी पूरी डिस्क को कंटेनर में माउंट न करवा सके। यदि आपको इसे हाथ से संपादित करने की आवश्यकता है (उदाहरण के लिए USB डिवाइस माउंट करने के लिए), तो इसे `sudo` के साथ संपादित करें और [Dockur Windows प्रोजेक्ट](https://github.com/dockur/windows) पर सभी विकल्प देखें।

पूरी चीज़ से छुटकारा पाने के लिए, Omarchy मेनू से _Remove > Windows_ का उपयोग करें। यह `~/.windows` में VM की डिस्क और Windows के अंदर इंस्टॉल की गई हर चीज़ को हटा देता है, इसलिए पहले VM से अपनी ज़रूरत की हर चीज़ बाहर कॉपी कर लें। आपका साझा `~/Windows` फ़ोल्डर वैसा का वैसा छोड़ दिया जाता है।
