# विकास उपकरण

## वैकल्पिक संपादक

Omarchy नए इंस्टॉल पर डिफ़ॉल्ट संपादक के रूप में Plain के साथ आता है और [Neovim](https://neovim.io/) पहले से इंस्टॉल होता है, लेकिन अगर आप कुछ थोड़ा अधिक मुख्यधारा वाला और परिचित चाहते हैं, तो आप Omarchy Menu (`Super + Space`) चला सकते हैं और _Install > Editor_ के अंतर्गत विकल्प देख सकते हैं। वहाँ हमारे पास VSCode, Cursor, Zed, Sublime Text, Helix, Vim, और Emacs सूचीबद्ध हैं। अगर आपको वह नहीं मिलता जिसकी आप तलाश कर रहे हैं, तो _Install > Package_ देखें, और देखें कि क्या वह किसी Arch पैकेज में नहीं है (और अगर नहीं है, तो AUR की जाँच करने के लिए _Install > AUR_ आज़माएँ)।

मूल `vi` संपादक भी बॉक्स से बाहर उपलब्ध है। टर्मिनल में किसी फ़ाइल को संपादित करने के लिए `vi filename` चलाएँ।

`VSCode`, `Cursor`, `VSCodium`, और `Helix` के लिए थीम मिलान की सुविधा दी जाती है।

आप `Setup > Defaults > Editor` के अंतर्गत सिस्टम-व्यापी डिफ़ॉल्ट संपादक सेट कर सकते हैं।

## एनवायरनमेंट

Omarchy, Omarchy Menu (`Super + Space`) के _Install > Development_ अनुभाग के माध्यम से ढेर सारे डेवलपमेंट एनवायरनमेंट सेट अप करने का समर्थन करता है। आपको वहाँ निश्चित रूप से _Ruby on Rails_ मिलेगा, लेकिन JavaScript के तीनों प्रमुख रनटाइम (Node.js, Bun, Deno) भी मिलेंगे, साथ ही Laravel और Symfony जैसे लोकप्रिय PHP फ्रेमवर्क भी। अरे, और Go, Rust, Python, Java, Elixir (Phoenix के साथ), .NET, OCaml, Zig, Clojure, और Scala भी हैं। यह बहुत व्यापक चयन है!

इनमें से अधिकांश एनवायरनमेंट [Mise](https://mise.jdx.dev/) द्वारा प्रबंधित किए जाते हैं। यह एक ऐसा टूल है जो आपको एक ही मशीन पर किसी प्रोग्रामिंग भाषा के कई संस्करण इंस्टॉल करने और चलाने देता है। यह Ruby के लिए rbenv या rvm या Python के लिए virtualenv जैसा है, लेकिन यह कई अलग-अलग एनवायरनमेंट के लिए काम करता है।

उदाहरण के लिए, Ruby इंस्टॉल करने के लिए, आप `mise use -g ruby` चलाएँगे, जो Ruby को इंस्टॉल भी करेगा और उसे वैश्विक डिफ़ॉल्ट के रूप में सेट भी करेगा। या, अगर आपके प्रोजेक्ट में .ruby-version फ़ाइल है, तो आप उस प्रोजेक्ट की रूट में बस `mise i` चला सकते हैं।

## पहले से इंस्टॉल किए गए CLI टूल्स

Omarchy, [mise के लेज़ी इंस्टॉलेशन](https://mise.jdx.dev/dev-tools/shims.html#lazy-tools) के माध्यम से `gh`, `uv`, और अधिकांश [कोडिंग एजेंट](17-ai.md) जैसे टूल उपलब्ध कराता है। पहली बार जब आप उनमें से कोई एक चलाते हैं, तो mise उसे इंस्टॉल कर देता है। कोडिंग एजेंट फिर चलने से पहले अपडेट की जाँच करते हैं, हर चार घंटे में अधिकतम एक बार; अन्य टूल, जैसे `gh` और `uv`, इंस्टॉल किए गए संस्करण का तब तक पुन: उपयोग करते हैं जब तक आप अपडेट नहीं करते।

आप डिफ़ॉल्ट को देख भी सकते हैं या उन्हें पहले से इंस्टॉल भी कर सकते हैं:

```bash
mise ls --current              # List the tools configured for this directory
mise install gh               # Install one tool now
mise install --include-lazy    # Install all configured tools, including lazy tools
```

Omarchy के बाकी हिस्सों के साथ इंस्टॉल किए गए टूल को अपडेट करने के लिए `omarchy update` चलाएँ। `mup` उपनाम केवल mise द्वारा प्रबंधित टूल को अपडेट करता है। अपने खुद के कॉन्फ़िगरेशन में कोई अन्य टूल जोड़ने के लिए, `mise use -g <tool>` का उपयोग करें।

Python सेटअप भी mise के माध्यम से `uv` इंस्टॉल करता है। Python डेवलपमेंट एनवायरनमेंट को हटाने से `uv` एक स्वतंत्र टूल के रूप में उपलब्ध रहता है।

### अपना खुद का इंस्टॉलेशन उपयोग करना

mise के कमांड `PATH` पर `~/.local/bin` से पहले आते हैं, इसलिए कोई टूल जो आपने खुद इंस्टॉल किया था, उदाहरण के लिए Claude Code के या Cursor के अपने इंस्टॉलर के साथ, वह फिर भी mise की कॉपी चलाता है। डेस्कटॉप से लॉन्च किए गए ऐप भी सिस्टम पैकेजों से पहले mise के कमांड पाते हैं, इसलिए कोई ऐप जो `gh` चलाता है उसे mise की कॉपी मिलती है, भले ही आपने pacman के साथ `github-cli` इंस्टॉल किया हो, और mise पहली बार उस कॉपी को इंस्टॉल करता है। इसके बजाय अपने वाले का उपयोग करने के लिए, `~/.config/mise/config.toml` में mise की कॉपी को अक्षम करें। उदाहरण के लिए, यदि आपने Cursor CLI खुद इंस्टॉल किया था:

```toml
[settings]
disable_tools = ["cursor-agent"]
```

अगर आपके पास पहले से कोई `[settings]` टेबल है, तो प्रविष्टि वहाँ जोड़ें; किसी मौजूदा `disable_tools` सूची को बदलने के बजाय उसे बढ़ाएँ। सुनिश्चित करें कि आपका इंस्टॉलेशन `PATH` पर है। mise टूल नाम का उपयोग करें, जो उसके कमांड से अलग हो सकता है: उदाहरण के लिए, `oh-my-pi` `omp` प्रदान करता है। डिफ़ॉल्ट-एजेंट लॉन्चर भी `~/.local/bin` में उपयोगकर्ता द्वारा इंस्टॉल किए गए Cursor या Muse को प्राथमिकता देता है।

### डिफ़ॉल्ट हटाना और पुनर्स्थापित करना

_Remove > Preinstalls_ Omarchy के पहले से इंस्टॉल किए गए वेब ऐप, TUIs और ऐप को हटाता है, और mise को आपके उपयोगकर्ता के लिए Omarchy की टूल घोषणाओं को छोड़ने के लिए कहता है, उन्हें `~/.config/mise/miserc.toml` में `ignored_config_paths` में जोड़कर। _Install > Preinstalls_ उन्हें वापस लाता है और उस पंक्ति को फिर से हटा देता है। वे टूल जिन्हें आप खुद घोषित करते हैं, अपने खुद के कॉन्फ़िग में या किसी प्रोजेक्ट के `mise.toml` में, किसी भी तरह से काम करते रहते हैं। यदि आप प्रीइंस्टॉल हटाने के बाद कोई डिफ़ॉल्ट एजेंट चुनते हैं या Python सेट अप करते हैं, तो वह टूल आपके अपने कॉन्फ़िग में जोड़ दिया जाता है। mise सेटिंग केवल आपके उपयोगकर्ता पर लागू होती है, और अन्य उपयोगकर्ता अपनी पसंद रखते हैं; हालाँकि ऐप पैकेज हैं, इसलिए उन्हें हटाने या पुनर्स्थापित करने से मशीन पर सभी के लिए वे बदल जाते हैं।

## Docker

[Docker](https://www.docker.com/) को शायद ही किसी परिचय की आवश्यकता है। यह आपको अलग-थलग कंटेनर चलाने देता है, और Omarchy इसे अच्छी तरह चलाने के लिए आवश्यक सब कुछ इंस्टॉल करता है, जिसमें Docker खुद और [Docker Compose](https://docs.docker.com/compose/) शामिल हैं।

डिफ़ॉल्ट रूप से आपका उपयोगकर्ता `docker` समूह में *नहीं* है। वह समूह प्रभावी रूप से पासवर्ड-रहित root है — उसमें मौजूद कोई भी चीज़ `docker run -v /:/host` चला सकती है और मशीन पर कब्ज़ा कर सकती है — इसलिए आपके रूप में चलने वाली एक अकेली दुष्ट स्क्रिप्ट या डिपेंडेंसी अन्यथा root से केवल एक कमांड दूर होगी। इसलिए कमांड लाइन पर आप Docker को `sudo` के साथ चलाते हैं (`sudo docker ps`, `sudo docker compose up`), और वे ग्राफ़िकल टूल जो डेमन से बात करते हैं — Windows VM — आवश्यकता पड़ने पर प्राधिकरण माँगते हैं। अगर आप समूह-रहित सेटअप की सुविधा वापस चाहते हैं और समझौते को समझते हैं, तो इसे **Setup > Security > Sudoless Docker** से सक्षम करें (या `omarchy-setup-security-sudoless-docker` चलाएँ), जो चेतावनी के बाद आपको `docker` समूह में जोड़ता है; फिर सादा `docker` और `d` उपनाम फिर से `sudo` के बिना काम करते हैं।

आप Omarchy मेनू में _Install > Development > Docker DB_ का उपयोग करके स्थानीय विकास के लिए सामान्य डेटाबेस को Docker में सेट अप कर सकते हैं।

## GitHub CLI

[GitHub CLI](https://cli.github.com/) टर्मिनल से रिपॉज़िटरी, इश्यू और पुल रिक्वेस्ट के साथ काम करने के लिए `gh` के रूप में उपलब्ध है। पहले उपयोग पर इसे इंस्टॉल करने और प्रमाणित करने के लिए `gh auth login` चलाएँ, फिर किसी रिपॉज़िटरी को क्लोन करने के लिए `gh repo clone org/repo` चलाएँ। इसके कमांड देखने के लिए `gh --help` चलाएँ।

पुल रिक्वेस्ट के लिए टर्मिनल इंटरफ़ेस के लिए, `ghui` चलाएँ; mise पहली बार उपयोग करने पर इसे भी इंस्टॉल करता है। Git के साथ काम करने के लिए [Lazygit](https://github.com/jesseduffield/lazygit) पहले से इंस्टॉल है।
