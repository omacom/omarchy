# डेवलपमेंट टूल्स

## वैकल्पिक एडिटर

Omarchy नए इंस्टॉल पर डिफ़ॉल्ट एडिटर के रूप में Plain के साथ आता है और [Neovim](https://neovim.io/) पहले से इंस्टॉल रहता है, लेकिन अगर आप कुछ थोड़ा ज़्यादा मुख्यधारा वाला और परिचित चाहते हैं, तो आप Omarchy Menu (`Super + Space`) चला सकते हैं और _Install > Editor_ के अंतर्गत विकल्प देख सकते हैं। वहाँ हमारे पास VSCode, Cursor, Zed, Sublime Text, Helix, Vim, और Emacs सूचीबद्ध हैं। अगर आपको वह नहीं मिलता जिसकी आप तलाश कर रहे हैं, तो _Install > Package_ देखें, और देखें कि क्या वह किसी Arch पैकेज में नहीं है (और अगर नहीं है, तो AUR की जाँच के लिए _Install > AUR_ आज़माएँ)।

मूल `vi` एडिटर भी सीधे उपलब्ध है। टर्मिनल में किसी फ़ाइल को संपादित करने के लिए `vi filename` चलाएँ।

`VSCode`, `Cursor`, `VSCodium`, और `Helix` के लिए थीम मिलान की सुविधा दी जाती है।

आप सिस्टम-व्यापी डिफ़ॉल्ट एडिटर को `Setup > Defaults > Editor` के अंतर्गत सेट कर सकते हैं।

## एनवायरनमेंट

Omarchy, Omarchy Menu (`Super + Space`) के _Install > Development_ अनुभाग के माध्यम से ढेर सारे डेवलपमेंट एनवायरनमेंट सेट अप करने का समर्थन करता है। बेशक आपको वहाँ _Ruby on Rails_ मिलेगा, लेकिन JavaScript के तीनों प्रमुख रनटाइम (Node.js, Bun, Deno) भी मिलेंगे, साथ ही Laravel और Symfony जैसे लोकप्रिय PHP फ्रेमवर्क भी। अरे, और Go, Rust, Python, Java, Elixir (Phoenix के साथ), .NET, OCaml, Zig, Clojure, और Scala भी हैं। यह बहुत ही व्यापक चयन है!

इनमें से अधिकांश एनवायरनमेंट [Mise](https://mise.jdx.dev/) द्वारा प्रबंधित किए जाते हैं। यह एक ऐसा टूल है जो आपको एक ही मशीन पर किसी प्रोग्रामिंग भाषा के कई संस्करण इंस्टॉल करने और चलाने देता है। यह Ruby के लिए rbenv या rvm जैसा है या Python के लिए virtualenv जैसा है, लेकिन यह कई अलग-अलग एनवायरनमेंट के लिए काम करता है।

उदाहरण के लिए, Ruby इंस्टॉल करने के लिए आप `mise use -g ruby` चलाएँगे, जो Ruby को इंस्टॉल भी करेगा और उसे ग्लोबल डिफ़ॉल्ट के रूप में सेट भी करेगा। या, अगर आपके प्रोजेक्ट में कोई .ruby-version फ़ाइल है, तो आप उस प्रोजेक्ट की रूट में बस `mise i` चला सकते हैं।

## पहले से इंस्टॉल CLI टूल्स

`uv`, Node.js, और `playwright-cli` (एजेंटों के लिए इंस्टॉल किए गए Chrome का उपयोग करके ब्राउज़र चलाने के लिए) पैकेज के रूप में इंस्टॉल आते हैं, और `omarchy update` उन्हें बाकी सिस्टम के साथ वर्तमान रखता है। [Hunk](https://github.com/modem-dev/hunk) और GitHub, Basecamp, Cloudflare और HEY CLI _Install > CLI_ के अंतर्गत एक चयन की दूरी पर हैं, और [कोडिंग एजेंट](17-ai.md) _Install > AI > CLI_ के अंतर्गत हैं।

mise केवल उन्हीं रनटाइम को प्रबंधित करता है जिन्हें आप _Install > Development_ से सेट अप करते हैं; Omarchy इसके माध्यम से अपने आप कुछ भी इंस्टॉल नहीं करता। उन्हें बाकी Omarchy के साथ अपडेट करने के लिए `omarchy update` चलाएँ; `mup` अलियास केवल mise द्वारा प्रबंधित टूल्स को अपडेट करता है। अपने स्वयं के कॉन्फ़िगरेशन में कोई अन्य टूल जोड़ने के लिए, `mise use -g <tool>` का उपयोग करें।

## Docker

[Docker](https://www.docker.com/) को शायद ही किसी परिचय की आवश्यकता है। यह आपको आइसोलेट किए गए कंटेनर चलाने देता है, और Omarchy इसे अच्छी तरह चलाने के लिए आवश्यक सब कुछ इंस्टॉल करता है, जिसमें Docker स्वयं और [Docker Compose](https://docs.docker.com/compose/) शामिल हैं।

डिफ़ॉल्ट रूप से आपका उपयोगकर्ता `docker` ग्रुप में *नहीं* होता है। वह ग्रुप प्रभावी रूप से पासवर्ड-रहित root है — उसमें मौजूद कोई भी चीज़ `docker run -v /:/host` करके मशीन पर कब्ज़ा कर सकती है — इसलिए आपके रूप में चलने वाला कोई एक दुष्ट स्क्रिप्ट या डिपेंडेंसी अन्यथा root से एक कमांड की दूरी पर होगा। इसलिए कमांड लाइन पर आप Docker को `sudo` के साथ चलाते हैं (`sudo docker ps`, `sudo docker compose up`), और डेमन से बात करने वाले ग्राफ़िकल टूल्स — Windows VM — आवश्यकता पड़ने पर आपसे प्राधिकरण माँगते हैं। अगर आप बिना ग्रुप वाले सेटअप की सुविधा वापस चाहते हैं और इस समझौते को समझते हैं, तो इसे **Setup > Security > Sudoless Docker** से सक्षम करें (या `omarchy-setup-security-sudoless-docker` चलाएँ), जो एक चेतावनी के बाद आपको `docker` ग्रुप में जोड़ देता है; फिर सादा `docker` और `d` अलियास फिर से `sudo` के बिना काम करते हैं।

आप Omarchy मेनू में _Install > Development > Docker DB_ का उपयोग करके Docker में स्थानीय डेवलपमेंट के लिए सामान्य डेटाबेस सेट अप कर सकते हैं।

## GitHub CLI

[GitHub CLI](https://cli.github.com/) यानी `gh`, टर्मिनल से रिपॉज़िटरी, इश्यू और पुल रिक्वेस्ट के साथ काम करने के लिए है। _Setup > Git_ इसे तब इंस्टॉल करता है जब आप वहाँ GitHub में साइन इन करना चुनते हैं, या इसे _Install > CLI > GitHub_ से अलग से इंस्टॉल करें। फिर `gh repo clone org/repo` किसी रिपॉज़िटरी को क्लोन करता है; इसके कमांड देखने के लिए `gh --help` चलाएँ।

[Lazygit](https://github.com/jesseduffield/lazygit) Git के साथ काम करने के लिए पहले से इंस्टॉल आता है।
