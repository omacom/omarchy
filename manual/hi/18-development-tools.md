# डेवलपमेंट टूल्स

## वैकल्पिक एडिटर

Omarchy डिफ़ॉल्ट रूप से [Neovim](https://neovim.io/) के साथ आता है, लेकिन अगर आप कुछ थोड़ा ज़्यादा मुख्यधारा वाला और परिचित चाहते हैं, तो आप Omarchy Menu (`Super + Space`) चला सकते हैं और _Install > Editor_ के अंतर्गत विकल्प देख सकते हैं। वहाँ हमारे पास VSCode, Cursor, Zed, Sublime Text, Helix, Vim, और Emacs सूचीबद्ध हैं। अगर आपको वह नहीं मिलता जो आप ढूँढ रहे हैं, तो _Install > Package_ देखें, और देखें कि कहीं वह किसी Arch पैकेज में तो नहीं है (और अगर नहीं है, तो AUR देखने के लिए _Install > AUR_ आज़माएँ)।

मूल `vi` एडिटर भी तैयार-तैयार उपलब्ध है। टर्मिनल में किसी फ़ाइल को संपादित करने के लिए `vi filename` चलाएँ।

`VSCode`, `Cursor`, `VSCodium`, और `Helix` के लिए थीम मिलान दिया जाता है।

आप सिस्टम-व्यापी डिफ़ॉल्ट एडिटर को `Setup > Defaults > Editor` के अंतर्गत सेट कर सकते हैं।

## एनवायरनमेंट

Omarchy, Omarchy Menu (`Super + Space`) के _Install > Development_ सेक्शन के ज़रिए ढेर सारे डेवलपमेंट एनवायरनमेंट सेट अप करने का समर्थन करता है। वहाँ आपको निश्चित रूप से _Ruby on Rails_ मिलेगा, लेकिन JavaScript के तीनों प्रमुख रनटाइम (Node.js, Bun, Deno) भी मिलेंगे, साथ ही Laravel और Symfony जैसे लोकप्रिय PHP फ्रेमवर्क भी। अरे, और Go, Rust, Python, Java, Elixir (Phoenix के साथ), .NET, OCaml, Zig, Clojure, और Scala भी हैं। यह सचमुच बहुत विस्तृत चयन है!

इनमें से अधिकांश एनवायरनमेंट [Mise](https://mise.jdx.dev/) द्वारा प्रबंधित किए जाते हैं। यह एक ऐसा टूल है जो आपको एक ही मशीन पर किसी प्रोग्रामिंग भाषा के कई संस्करण इंस्टॉल करने और चलाने देता है। यह Ruby के लिए rbenv या rvm जैसा है या Python के लिए virtualenv जैसा, लेकिन यह कई अलग-अलग एनवायरनमेंट के लिए काम करता है।

उदाहरण के लिए, Ruby इंस्टॉल करने के लिए, आप `mise use -g ruby` चलाएँगे, जो Ruby को इंस्टॉल भी करेगा और उसे ग्लोबल डिफ़ॉल्ट के रूप में सेट भी करेगा। या, अगर आपकी परियोजना में .ruby-version फ़ाइल है, तो आप उस परियोजना के रूट में बस `mise i` चला सकते हैं।

## पहले से इंस्टॉल किए गए CLI टूल

Omarchy, [mise की लेज़ी इंस्टॉलेशन](https://mise.jdx.dev/dev-tools/shims.html#lazy-tools) सुविधा के ज़रिए `gh`, `uv`, और अधिकांश [कोडिंग एजेंट](17-ai.md) जैसे टूल उपलब्ध कराता है। पहली बार जब आप उनमें से किसी एक को चलाते हैं, तो mise उसे इंस्टॉल कर देता है। बाद के रन इंस्टॉल किए गए संस्करण का ही पुन: उपयोग करते हैं; वे हर लॉन्च पर अपडेट की जाँच नहीं करते।

आप डिफ़ॉल्ट भी देख सकते हैं या उन्हें पहले से इंस्टॉल कर सकते हैं:

```bash
mise ls --current              # List the tools configured for this directory
mise install gh               # Install one tool now
mise install --include-lazy    # Install all configured tools, including lazy tools
```

बाकी Omarchy के साथ इंस्टॉल किए गए टूल को अपडेट करने के लिए `omarchy update` चलाएँ। `mup` एलियास केवल mise द्वारा प्रबंधित टूल को अपडेट करता है। अपने खुद के कॉन्फ़िगरेशन में कोई अन्य टूल जोड़ने के लिए, `mise use -g <tool>` का उपयोग करें।

Python सेटअप mise के ज़रिए `uv` भी इंस्टॉल करता है। Python डेवलपमेंट एनवायरनमेंट हटाने पर भी `uv` एक स्वतंत्र टूल के रूप में उपलब्ध रहता है।

### अपनी खुद की इंस्टॉलेशन का उपयोग करना

mise के कमांड `PATH` पर `~/.local/bin` से पहले आते हैं, इसलिए आपने खुद जो टूल इंस्टॉल किया था, उदाहरण के लिए Claude Code के या Cursor के अपने इंस्टॉलर से, उसकी जगह फिर भी mise की कॉपी चलती है। डेस्कटॉप से लॉन्च किए गए ऐप भी सिस्टम पैकेजों से पहले mise के कमांड पाते हैं, इसलिए कोई ऐप जो `gh` चलाता है, उसे mise की कॉपी मिलती है, भले ही आपने pacman से `github-cli` इंस्टॉल किया हो, और mise उस कॉपी को पहली बार में इंस्टॉल कर देता है। इसके बजाय अपनी कॉपी का उपयोग करने के लिए, `~/.config/mise/config.toml` में mise की कॉपी को अक्षम करें। उदाहरण के लिए, अगर आपने Cursor CLI खुद इंस्टॉल किया था:

```toml
[settings]
disable_tools = ["cursor-agent"]
```

अगर आपके पास पहले से `[settings]` टेबल है, तो प्रविष्टि वहीं जोड़ें; किसी मौजूदा `disable_tools` सूची को बदलने के बजाय उसका विस्तार करें। सुनिश्चित करें कि आपकी इंस्टॉलेशन `PATH` पर है। mise टूल नाम का उपयोग करें, जो उसके कमांड से अलग हो सकता है: उदाहरण के लिए, `oh-my-pi` `omp` प्रदान करता है। डिफ़ॉल्ट-एजेंट लॉन्चर भी `~/.local/bin` में उपयोगकर्ता द्वारा इंस्टॉल किए गए Cursor या Muse को प्राथमिकता देता है।

### डिफ़ॉल्ट हटाना और पुनर्स्थापित करना

_Remove Preinstalls_ आपके उपयोगकर्ता के लिए mise से Omarchy की टूल घोषणाओं को छोड़ने को कहता है, उन्हें `~/.config/mise/miserc.toml` में `ignored_config_paths` में जोड़कर। _Restore Preinstalls_ उस पंक्ति को फिर से हटा देता है। आपने खुद जो टूल घोषित किए हैं, अपने खुद के कॉन्फ़िग में या किसी परियोजना के `mise.toml` में, वे किसी भी तरह काम करते रहते हैं। अगर आप प्रीइंस्टॉल हटाने के बाद कोई डिफ़ॉल्ट एजेंट चुनते हैं या Python सेट अप करते हैं, तो वह टूल आपके खुद के कॉन्फ़िग में जोड़ दिया जाता है। दोनों केवल आपके उपयोगकर्ता पर लागू होते हैं; मशीन पर अन्य उपयोगकर्ता अपनी पसंद अपने पास रखते हैं।

## Docker

[Docker](https://www.docker.com/) का परिचय देने की शायद ही कोई ज़रूरत है। यह आपको अलग-थलग कंटेनर चलाने देता है, और Omarchy इसे अच्छी तरह चलाने के लिए ज़रूरी सब कुछ इंस्टॉल करता है, जिसमें Docker खुद और [Docker Compose](https://docs.docker.com/compose/) शामिल हैं।

डिफ़ॉल्ट रूप से आपका उपयोगकर्ता `docker` ग्रुप में *नहीं* होता है। वह ग्रुप असल में बिना पासवर्ड वाला root है — उसमें मौजूद कोई भी चीज़ `docker run -v /:/host` कर सकती है और मशीन पर कब्ज़ा कर सकती है — इसलिए आपके रूप में चलने वाला कोई एक दुष्ट स्क्रिप्ट या डिपेंडेंसी अन्यथा root से बस एक कमांड दूर होता। इसलिए कमांड लाइन पर आप Docker को `sudo` के साथ चलाते हैं (`sudo docker ps`, `sudo docker compose up`), और डेमन से बात करने वाले ग्राफ़िकल टूल — Windows VM — ज़रूरत पड़ने पर आपसे प्राधिकरण माँगते हैं। अगर आप बिना ग्रुप वाले सेटअप की सुविधा वापस चाहते हैं और समझौते को समझते हैं, तो इसे **Setup > Security > Sudoless Docker** से सक्षम करें (या `omarchy-setup-security-sudoless-docker` चलाएँ), जो चेतावनी के बाद आपको `docker` ग्रुप में जोड़ देता है; फिर सादा `docker` और `d` एलियास फिर से बिना `sudo` के काम करते हैं।

आप Omarchy मेनू में _Install > Development > Docker DB_ का उपयोग करके Docker में स्थानीय डेवलपमेंट के लिए सामान्य डेटाबेस सेट अप कर सकते हैं।

## GitHub CLI

[GitHub CLI](https://cli.github.com/) टर्मिनल से रिपॉज़िटरी, इश्यू, और पुल रिक्वेस्ट के साथ काम करने के लिए `gh` के रूप में उपलब्ध है। इसे पहले उपयोग पर इंस्टॉल करने और प्रमाणित करने के लिए `gh auth login` चलाएँ, फिर किसी रिपॉज़िटरी को क्लोन करने के लिए `gh repo clone org/repo` चलाएँ। इसके कमांड देखने के लिए `gh --help` चलाएँ।

पुल रिक्वेस्ट के लिए टर्मिनल इंटरफ़ेस के लिए, `ghui` चलाएँ; mise इसे भी पहले उपयोग पर इंस्टॉल कर देता है। Git के साथ काम करने के लिए [Lazygit](https://github.com/jesseduffield/lazygit) पहले से इंस्टॉल है।
