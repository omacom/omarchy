# सुरक्षा

Omarchy सुरक्षा को बेहद गंभीरता से लेता है। यह एक ऐसा operating system बनने के लिए है जिसका उपयोग आप _असली दुनिया_ में _असली काम_ करने के लिए कर सकें। जहाँ लैपटॉप खो जाने से सुरक्षा आपातकाल न बन जाए। तो हम यह करते हैं:

1. *फुल-डिस्क एन्क्रिप्शन अनिवार्य है*: यह आपके डेटा की भौतिक सुरक्षा सुनिश्चित करने का सबसे महत्वपूर्ण कदम है। यदि आपका कंप्यूटर खो जाता है या चोरी हो जाता है, तो डेटा मानक LUKS (Linux Unified Key Setup) का उपयोग करके पूरी तरह एन्क्रिप्ट रहता है।
2. *Firewall डिफ़ॉल्ट रूप से सक्षम है*: [LocalSend](https://localsend.org/) के लिए port 53317 को छोड़कर सभी आने वाले traffic को डिफ़ॉल्ट रूप से ब्लॉक किया जाता है। ssh भी तब तक बंद रहता है जब तक आप इसे _Setup > Security > SSHD_ के माध्यम से चालू नहीं करते, जो setup के हिस्से के रूप में port 22 खोलता है (brute force के विरुद्ध rate limited)। हम Docker access को भी [ufw-docker](https://github.com/chaifeng/ufw-docker) setup का उपयोग करके लॉक डाउन करते हैं ताकि आपके containers गलती से दुनिया के सामने उजागर न हो जाएँ।
3. *Arch के पास हमेशा नवीनतम updates होते हैं*: Arch, वह अंतर्निहित distro जिस पर Omarchy बना है, एक rolling distribution है। इसका मतलब है कि किसी भी package में खोजी और ठीक की गई कोई भी सुरक्षा कमजोरी `omarchy-update` का उपयोग करके इंस्टॉल करने के लिए जल्दी उपलब्ध हो जाती है। इस तरह आप हमेशा हर चीज़ के नवीनतम, सबसे सुरक्षित संस्करण चला रहे होते हैं।
4. *Omarchy अपने स्वयं के packages और mirror बनाए रखता है*: Omarchy डिफ़ॉल्ट रूप से केवल Arch के स्वयं के core/extra/multilib repositories और अपने स्वयं के Omarchy Package Repository के packages पर निर्भर करता है। आप सीधे AUR से software इंस्टॉल कर सकते हैं, लेकिन base install ऐसा नहीं करता — केवल कुछ वैकल्पिक installs, जैसे third-party browsers, AUR से लेते हैं।
5. *Cloudflare हमें DDoS से बचाता है*: Omarchy distribution infrastructure — ISOs, Omarchy packages, Arch mirror — Cloudflare के दुर्जेय DDoS shield के पीछे सुरक्षित है और उनके CDN पर hosted है। यह बेहतरीन उपलब्धता प्रदान करता है।

## अपने पासवर्ड बदलना

एन्क्रिप्टेड install पर आपके पास दो पासवर्ड होते हैं: एक जो boot पर drive को अनलॉक करता है, और एक जिससे आप लॉग इन करते हैं और `sudo` का उपयोग करते हैं। Setup उन्हें एक समान बनाता है। दोनों को Omarchy menu में _Update > Password_ के अंतर्गत बदला जा सकता है — पहले के लिए _Drive Encryption_, दूसरे के लिए _User_। drive पासवर्ड बदलने पर पहले वर्तमान पासवर्ड माँगा जाता है, इसलिए उसे तैयार रखें। यदि कोई बदलाव बीच में बाधित हो जाए, तो _Drive Encryption_ फिर से चलाएँ: यह वह पासवर्ड माँगता है जो अभी drive को अनलॉक करता है और बदलाव पूरा करता है।

## पहले से उपयोग की गई मशीन किसी और को सौंपना

यदि आप अपनी मशीन किसी और को सौंप रहे हैं, तो आपको इसे फिर से इंस्टॉल करने की आवश्यकता नहीं है। Omarchy menu में _Setup > Reset Computer_ चलाएँ, पुष्टि करने के लिए `reset` टाइप करें, और reboot करें। यह हर उपयोगकर्ता खाते और `/home` में मौजूद हर चीज़ को मिटा देता है, installation के बाद से आपके द्वारा किए गए सभी packages और system बदलावों को फेंक देता है, और मशीन की पहचान साफ़ कर देता है — network connections, host keys, और सब कुछ। जो वापस आता है वह पहले boot का setup wizard है, जो अपने नए मालिक के लिए अपना नाम, पासवर्ड और एन्क्रिप्शन पासवर्ड दर्ज करने के लिए तैयार है।

यह installer द्वारा लिए गए baseline snapshot को पुनर्स्थापित करके काम करता है, इसलिए यह केवल Omarchy ISO से इंस्टॉल की गई मशीनों पर उपलब्ध है। और एन्क्रिप्शन के बिना drive पर, reset एक सुरक्षित मिटाव के बजाय deletion है, इसलिए यदि डेटा संवेदनशील था, तो इसके बजाय fresh install करें।

## बिना पासवर्ड वाला sudo

कभी-कभी आप चाहते हैं कि `sudo` पूछना बंद कर दे, सबसे अक्सर तब जब कोई AI agent आपके लिए लंबे समय तक system का काम कर रहा हो। _Setup > Security > Passwordless Sudo_ पूछता है कि कितने समय तक access की अनुमति दी जाए: **15 मिनट**, **1 Hour**, **1 Day**, या **Permanently**। जब access सक्रिय होता है तो अन्य menu bar indicators के बगल में एक लाल चेतावनी आइकन दिखाई देता है। access बंद करने के लिए उस पर क्लिक करें या कमांड फिर से चलाएँ। आप `omarchy-sudo-passwordless 30` के साथ अपने स्वयं के मिनटों की संख्या (1 से 1440 तक) भी दे सकते हैं, या `omarchy-sudo-passwordless permanent` का उपयोग कर सकते हैं।

समयबद्ध access स्वचालित रूप से समाप्त हो जाता है, जिसमें deadline पार करने वाले suspend से resume करने के तुरंत बाद भी शामिल है। कंप्यूटर को पुनरारंभ करने से यह पहले ही समाप्त हो जाता है। Permanent access reboots के बाद भी बना रहता है और तब तक सक्षम रहता है जब तक आप इसे अक्षम नहीं करते।

Omarchy के settings package को update या हटाने से कोई भी अस्थायी grant उसकी expiry support बदलने से पहले समाप्त हो जाता है। यदि कमांड authorization या cleanup error की रिपोर्ट करता है, तो एक और grant सक्षम करने का प्रयास करने से पहले उसका समाधान करें; error का मतलब यह नहीं है कि बिना पासवर्ड वाला access निष्क्रिय है।

इस बारे में स्पष्ट रहें: जब यह चालू होता है, तो आपके उपयोगकर्ता के रूप में चलने वाली कोई भी चीज़ बिना पूछे root के रूप में कुछ भी कर सकती है। यही इसका पूरा उद्देश्य है, और यही इसका पूरा जोखिम भी है।

## हस्ताक्षर कुंजियाँ

सभी ISO signatures और Omarchy repo package के लिए सार्वजनिक कुंजी `40DFB630FF42BCFFB047046CF0134EE680CAC571` है ([openpgp.org पर सत्यापित करें](https://keys.openpgp.org/search?q=pkgs%40omarchy.org))। `omarchy/omarchy-keyring` package में भी यह शामिल है और इसका उपयोग किसी भी संभावित updates को सहजता से rollout करने के लिए किया जाएगा।

आप किसी भी ISO release के लिए signature उसके URL में `.sig` जोड़कर पा सकते हैं, जैसे `https://iso.omarchy.org/omarchy-x.x.x.iso.sig`।
