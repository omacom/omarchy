# सुरक्षा

Omarchy सुरक्षा को बेहद गंभीरता से लेता है। इसका उद्देश्य एक ऐसा operating system होना है जिसका उपयोग आप _असली दुनिया_ में _असली काम_ करने के लिए कर सकें। जहाँ laptop खो जाने से सुरक्षा आपात स्थिति पैदा न हो। तो हम यह करते हैं:

1. *पूर्ण-डिस्क एन्क्रिप्शन डिफ़ॉल्ट रूप से चालू है*: यह आपके डेटा की भौतिक सुरक्षा सुनिश्चित करने के लिए सबसे महत्वपूर्ण कदम है। यदि आपका कंप्यूटर खो जाता है या चोरी हो जाता है, तो डेटा मानक LUKS (Linux Unified Key Setup) का उपयोग करके पूरी तरह एन्क्रिप्टेड रहता है। installer आपको एकबारगी उपयोग करके फेंकने वाली machines के लिए इससे बाहर निकलने का विकल्प देता है (देखें [शुरुआत करना](02-getting-started.md)); एन्क्रिप्शन के बिना किए गए install में यह सुरक्षा बिल्कुल नहीं होती, और ड्राइव जिसके पास भी हो, वह उसे पढ़ सकता है।
2. *फ़ायरवॉल डिफ़ॉल्ट रूप से सक्षम है*: आने वाला सारा ट्रैफ़िक डिफ़ॉल्ट रूप से अवरुद्ध रहता है, कुछ अपवादों के साथ: [LocalSend](https://localsend.org/) के लिए पोर्ट 53317; Docker bridge address (172.17.0.1) पर कंप्यूटर के अपने resolver को भेजे गए DNS प्रश्न, जो उन private address ranges से स्वीकार किए जाते हैं जो Docker अपने containers को देता है; और multicast DNS (पोर्ट 5353), जो आपके network पर मौजूद printers और अन्य devices को एक-दूसरे को खोजने देता है और वहाँ आपके कंप्यूटर का नाम भी घोषित करता है। इनके अतिरिक्त, फ़ायरवॉल ping, अपने router से address प्राप्त करने (DHCP), और UPnP discovery के लिए UFW की मानक अनुमतियों को बनाए रखता है। ssh भी तब तक बंद रहता है जब तक आप इसे _सेटअप > सुरक्षा > SSHD_ के माध्यम से चालू न करें, जो setup के हिस्से के रूप में पोर्ट 22 खोलता है (brute force के विरुद्ध rate limited)। हम [ufw-docker](https://github.com/chaifeng/ufw-docker) setup का उपयोग करके Docker access को भी बंद करके रखते हैं ताकि आपके containers गलती से दुनिया के सामने उजागर न हो जाएँ।
3. *Arch के पास हमेशा नवीनतम updates होते हैं*: Arch, वह अंतर्निहित distro जिस पर Omarchy बना है, एक rolling distribution है। इसका अर्थ है कि किसी भी package में खोजी गई और patch की गई कोई भी सुरक्षा भेद्यता `omarchy-update` का उपयोग करके install करने के लिए शीघ्र उपलब्ध हो जाती है। इस तरह आप हमेशा हर चीज़ के नवीनतम, सबसे सुरक्षित versions चला रहे होते हैं।
4. *Omarchy अपने स्वयं के packages और mirror बनाए रखता है*: Omarchy डिफ़ॉल्ट रूप से केवल Arch के अपने core/extra/multilib repositories और अपने स्वयं के Omarchy Package Repository के packages पर निर्भर करता है। आप सीधे AUR से software install कर सकते हैं, लेकिन base install ऐसा नहीं करता — केवल कुछ वैकल्पिक installs, जैसे third-party browsers, AUR से लेते हैं।
5. *Cloudflare हमें DDoS से बचाता है*: Omarchy distribution infrastructure — ISOs, Omarchy packages, Arch mirror — Cloudflare के दुर्जेय DDoS shield के पीछे संरक्षित है और उनके CDN पर hosted है। यह शानदार उपलब्धता प्रदान करता है।

## अपने passwords बदलना

एन्क्रिप्टेड install पर आपके पास दो passwords होते हैं: एक जो boot के समय ड्राइव को unlock करता है, और एक जिससे आप log in करते हैं और `sudo` का उपयोग करते हैं। Setup दोनों को एक समान बनाता है। दोनों को Omarchy menu में _अपडेट > पासवर्ड_ के अंतर्गत बदला जा सकता है — पहले के लिए _ड्राइव एन्क्रिप्शन_, दूसरे के लिए _उपयोगकर्ता_। ड्राइव का पासवर्ड बदलने पर पहले वर्तमान पासवर्ड माँगा जाता है, इसलिए उसे तैयार रखें। यदि बदलाव बीच में बाधित हो जाए, तो _ड्राइव एन्क्रिप्शन_ फिर से चलाएँ: यह वह पासवर्ड माँगेगा जो इस समय ड्राइव को unlock करता है और बदलाव को पूरा कर देगा।

## पहले से उपयोग की गई machine को आगे सौंपना

यदि आप अपनी machine किसी और को सौंप रहे हैं, तो आपको उसे फिर से install करने की आवश्यकता नहीं है। Omarchy menu में _हटाएँ > फ़ैक्टरी रीसेट_ चलाएँ, पुष्टि करने के लिए `reset` टाइप करें, और reboot करें। इससे हर user account और `/home` में मौजूद हर चीज़ मिट जाती है, installation के बाद से आपके द्वारा किए गए सभी packages और system बदलाव हटा दिए जाते हैं, और machine की पहचान साफ़ हो जाती है — network connections, host keys, सब कुछ। इसके बाद जो सामने आता है वह पहली boot वाला setup wizard होता है, जो अपने नए मालिक के लिए अपना नाम, पासवर्ड और एन्क्रिप्शन पासवर्ड दर्ज करने के लिए तैयार रहता है।

यह installer द्वारा लिए गए baseline snapshot को पुनर्स्थापित करके काम करता है, इसलिए यह केवल Omarchy ISO से install की गई machines पर उपलब्ध है। और एन्क्रिप्शन के बिना वाली ड्राइव पर, reset एक सुरक्षित मिटाना न होकर केवल deletion होता है, इसलिए यदि डेटा संवेदनशील था, तो इसके बजाय नया install करें।

## पासवर्ड-रहित sudo

कभी-कभी आप चाहते हैं कि `sudo` पूछना बंद कर दे, सबसे अक्सर तब जब कोई AI agent आपके लिए लंबे समय तक system का काम कर रहा हो। _सेटअप > सुरक्षा > पासवर्ड-रहित Sudo_ पूछता है कि कितने समय तक access की अनुमति दी जाए: **15 मिनट**, **1 घंटा**, **1 दिन**, या **स्थायी रूप से**। जब तक access सक्रिय रहता है, अन्य menu bar indicators के बगल में एक लाल चेतावनी चिह्न दिखाई देता है। access बंद करने के लिए उस पर click करें या command फिर से चलाएँ। आप `omarchy-sudo-passwordless 30` के साथ अपनी स्वयं की मिनटों की संख्या (1 से 1440 तक) भी दे सकते हैं, या `omarchy-sudo-passwordless permanent` का उपयोग कर सकते हैं।

समयबद्ध access स्वचालित रूप से समाप्त हो जाता है, जिसमें समय-सीमा पार कर चुके suspend से फिर शुरू होने के तुरंत बाद भी शामिल है। कंप्यूटर को restart करने से यह समय से पहले समाप्त हो जाता है। स्थायी access reboots के बाद भी बना रहता है और तब तक सक्षम रहता है जब तक आप इसे अक्षम न कर दें।

Omarchy के settings package को update या remove करने से किसी भी अस्थायी अनुदान की expiry support बदलने से पहले वह समाप्त हो जाता है। यदि command कोई authorization या cleanup त्रुटि बताए, तो दूसरा अनुदान सक्षम करने का प्रयास करने से पहले उसे हल करें; त्रुटि का अर्थ यह नहीं है कि पासवर्ड-रहित access निष्क्रिय है।

इस बारे में आँखें खुली रखें: जब तक यह चालू है, आपके user के रूप में चल रही कोई भी चीज़ बिना पूछे root के रूप में कुछ भी कर सकती है। यही इसका पूरा उद्देश्य है, और यही इसका पूरा जोखिम भी है।

## हस्ताक्षर कुंजियाँ

सभी ISO signatures और Omarchy repo package के लिए सार्वजनिक कुंजी `40DFB630FF42BCFFB047046CF0134EE680CAC571` है ([openpgp.org पर सत्यापित करें](https://keys.openpgp.org/search?q=pkgs%40omarchy.org))। `omarchy/omarchy-keyring` package में यह भी शामिल है और इसका उपयोग किसी भी संभावित updates को निर्बाध रूप से लागू करने के लिए किया जाएगा।

आप किसी भी ISO release के signature को उसके URL में `.sig` जोड़कर पा सकते हैं, जैसे `https://iso.omarchy.org/omarchy-x.x.x.iso.sig`।
