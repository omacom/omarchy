# Εγκαταστάσεις χωρίς επίβλεψη

Το ISO του Omarchy μπορεί να εγκατασταθεί μόνο του χωρίς κανέναν στο πληκτρολόγιο. Αν το πρόγραμμα εγκατάστασης βρει έναν δεύτερο δίσκο με ετικέτα `cidata` που περιέχει τα αρχεία ρυθμίσεών του, τα αντιγράφει, παραλείπει εντελώς τον οδηγό εγκατάστασης και επανεκκινεί από μόνο του στο ολοκληρωμένο σύστημα. Καμία ειδική έκδοση ISO, καμία επιπλέον καταχώριση στο μενού εκκίνησης — χωρίς συνδεδεμένο τέτοιο δίσκο, τίποτα δεν αλλάζει και παίρνετε τον κανονικό οδηγό.

Αυτό κάνει το Omarchy ιδανικό ως βασική εικόνα για αναλώσιμα περιβάλλοντα ανάπτυξης: δημιουργήστε ένα VM στο Proxmox ή με το Packer, εκκινήστε το, φύγετε, συνδεθείτε μέσω SSH. Το `cidata` είναι η ετικέτα `NoCloud` του cloud-init, οπότε όλα τα συνηθισμένα εργαλεία εικονικοποίησης ξέρουν ήδη πώς να συνδέσουν έναν τέτοιο δίσκο.

## Τα αρχεία ρυθμίσεων

Τα αρχεία είναι ακριβώς αυτά που γράφει ο ίδιος ο οδηγός του προγράμματος εγκατάστασης, οπότε ο ευκολότερος τρόπος για να πάρετε ένα αρχικό σύνολο είναι να εκτελέσετε μία διαδραστική εγκατάσταση (σε ένα VM, για παράδειγμα) και να αντιγράψετε όσα έγραψε στο `/root`:

| Αρχείο | Απαιτείται | Σκοπός |
|------|----------|---------|
| `user_configuration.json` | Ναι | Δίσκος, όνομα υπολογιστή, ζώνη ώρας, πληκτρολόγιο |
| `user_credentials.json` | Ναι | Όνομα χρήστη και κατακερματισμός κωδικού πρόσβασης, και η φράση πρόσβασης LUKS για μια κρυπτογραφημένη εγκατάσταση |
| `user_encrypt_installation.txt` | Όχι | `true` όταν οι ρυθμίσεις περιέχουν ένα μπλοκ `disk_encryption` |
| `authorized_keys` | Όχι | Δημόσια κλειδιά SSH, ένα ανά γραμμή |
| `tailscale_authkey` | Όχι | Κλειδί ελέγχου ταυτότητας Tailscale για σύνδεση στο tailnet σας κατά την πρώτη εκκίνηση |

Δημιουργήστε τον κατακερματισμό κωδικού πρόσβασης για το `user_credentials.json` με `openssl passwd -6 "yourpassword"`.

Το όνομα και το email για τα commit του git δεν αποτελούν μέρος της εγκατάστασης. Ορίστε τα μόλις το μηχάνημα είναι έτοιμο, μέσω SSH για παράδειγμα, με `omarchy setup git --name "Jane Doe" --email jane@example.com`.

Μπορείτε επίσης να ρίξετε ένα κενό αρχείο με όνομα `defer-provisioning` στη θέση του `user_credentials.json`. Αυτό εκτελεί την ίδια [εγκατάσταση προετοιμασίας για άλλον κάτοχο](02-getting-started.md) που μπορείτε να ενεργοποιήσετε διαδραστικά: το μηχάνημα εγκαθίσταται χωρίς προσωπικά στοιχεία, και όποιος το εκκινήσει πρώτος επιλέγει το πληκτρολόγιό του και δημιουργεί τον χρήστη του. Αυτή είναι η λειτουργία για μηχανήματα δημιουργίας εικόνων, όπου ο δίσκος δεν πρέπει να περιέχει καθόλου τα διαπιστευτήρια κανενός.

## Πρόσβαση SSH

Όταν υπάρχει το `authorized_keys`, η εγκατάσταση ορίζει τα κλειδιά ως το `~/.ssh/authorized_keys` του χρήστη, ενεργοποιεί το `sshd` και ανοίγει το τείχος προστασίας για αυτό. (Μια τυπική εγκατάσταση Omarchy παρέχεται με το openssh με την υπηρεσία απενεργοποιημένη και τη θύρα κλειστή, οπότε ένα μηχάνημα χωρίς επίβλεψη θα ήταν διαφορετικά απρόσιτο.) Η εγκατάσταση προσθέτει μόνο τα κλειδιά σας — δεν χαλαρώνει καμία από τις άλλες ρυθμίσεις ελέγχου ταυτότητας του δαίμονα SSH.

Όταν υπάρχει το `tailscale_authkey`, το μηχάνημα συνδέεται στο tailnet σας κατά την πρώτη εκκίνηση: το Tailscale εγκαθίσταται από τα πακέτα που συνοδεύουν το ISO, το τείχος προστασίας επιτρέπει τη διεπαφή του tailnet, και μια εργασία στο παρασκήνιο εκτελεί τη σύνδεση μόλις το μηχάνημα έχει πραγματικά δίκτυο, επαναλαμβάνοντας μέχρι να πετύχει. Χρησιμοποιήστε ένα επαναχρησιμοποιήσιμο, προεγκεκριμένο κλειδί ώστε μία εικόνα δίσκου να μπορεί να εξυπηρετήσει πολλά μηχανήματα.

## Δημιουργία του δίσκου cidata

Οποιοδήποτε σύστημα αρχείων με τη σωστή ετικέτα λειτουργεί. Ένα μικροσκοπικό ISO είναι ο εύκολος τρόπος:

```bash
mkdir cidata
cp user_configuration.json user_credentials.json authorized_keys cidata/
genisoimage -output cidata.iso -volid cidata -joliet -rock cidata/
```

Στη συνέχεια συνδέστε το στο VM δίπλα στο ISO του Omarchy. Ακολουθεί ένα πλήρες παράδειγμα Proxmox:

```bash
qm create 101 --name my-omarchy \
  --bios ovmf --machine q35 --cpu host --cores 4 --memory 8192 \
  --ostype l26 --scsihw virtio-scsi-single \
  --efidisk0 local-lvm:0,efitype=4m,pre-enrolled-keys=0 \
  --scsi0 local-lvm:40,discard=on,iothread=1 \
  --net0 virtio,bridge=vmbr0 --vga virtio --serial0 socket \
  --ide2 local:iso/omarchy.iso,media=cdrom \
  --ide3 local:iso/cidata.iso,media=cdrom \
  --boot order='scsi0;ide2'

qm start 101
```

Η σειρά εκκίνησης αναφέρει πρώτα τον δίσκο επίτηδες: ο άδειος δίσκος περνά στο ISO κατά την πρώτη εκκίνηση, και το εγκατεστημένο σύστημα εκκινεί από τον δίσκο από εκεί και πέρα.

## Δύο επιφυλάξεις

Οι κρυπτογραφημένες εγκαταστάσεις χωρίς επίβλεψη δεν είναι πλήρως χωρίς επίβλεψη — κάποιος πρέπει ακόμα να πληκτρολογήσει τη φράση πρόσβασης LUKS κατά την πρώτη εκκίνηση. Και αυτή η φράση πρόσβασης μπαίνει στο ανώτερο επίπεδο του `user_credentials.json` ως `encryption_password` — το archinstall το διαβάζει εκεί, όχι από το μπλοκ `disk_encryption` στο `user_configuration.json` — οπότε αντιμετωπίστε έναν δίσκο cidata που δημιουργήθηκε από μια κρυπτογραφημένη εγκατάσταση ως το μυστικό που είναι.
