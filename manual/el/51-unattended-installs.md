# Ανεπιτήρητες Εγκαταστάσεις

Το ISO του Omarchy μπορεί να εγκατασταθεί μόνο του χωρίς κανέναν στο πληκτρολόγιο. Αν το πρόγραμμα εγκατάστασης βρει μια δεύτερη μονάδα με ετικέτα `cidata` που περιέχει τα αρχεία ρυθμίσεών του, τα αντιγράφει, παραλείπει εντελώς τον οδηγό εγκατάστασης και επανεκκινεί μόνο του στο ολοκληρωμένο σύστημα. Δεν χρειάζεται ειδική έκδοση του ISO, ούτε πρόσθετη καταχώριση στο μενού εκκίνησης — χωρίς συνδεδεμένη τέτοια μονάδα, τίποτα δεν αλλάζει και εμφανίζεται ο κανονικός οδηγός.

Αυτό κάνει το Omarchy εξαιρετικό ως βασική εικόνα για αναλώσιμα περιβάλλοντα ανάπτυξης: δημιούργησε ένα VM στο Proxmox ή με το Packer, εκκίνησέ το, φύγε, και συνδέσου μέσω SSH. Το `cidata` είναι η ετικέτα `NoCloud` του cloud-init, οπότε όλα τα κοινά εργαλεία εικονικοποίησης γνωρίζουν ήδη πώς να συνδέσουν μια τέτοια μονάδα.

## Τα αρχεία ρυθμίσεων

Τα αρχεία είναι ακριβώς αυτά που γράφει ο ίδιος ο οδηγός του προγράμματος εγκατάστασης, οπότε ο ευκολότερος τρόπος για να πάρεις ένα αρχικό σύνολο είναι να εκτελέσεις μια διαδραστική εγκατάσταση (σε ένα VM, για παράδειγμα) και να αντιγράψεις ό,τι έγραψε στο `/root`:

| Αρχείο | Απαραίτητο | Σκοπός |
|------|----------|---------|
| `user_configuration.json` | Ναι | Δίσκος, hostname, ζώνη ώρας, πληκτρολόγιο |
| `user_credentials.json` | Ναι | Όνομα χρήστη και hash κωδικού πρόσβασης |
| `user_encrypt_installation.txt` | Όχι | `true` όταν οι ρυθμίσεις περιέχουν ένα μπλοκ `disk_encryption` |
| `authorized_keys` | Όχι | Δημόσια κλειδιά SSH, ένα ανά γραμμή |
| `tailscale_authkey` | Όχι | Κλειδί ταυτοποίησης Tailscale για σύνδεση στο tailnet σου κατά την πρώτη εκκίνηση |

Δημιούργησε το hash του κωδικού πρόσβασης για το `user_credentials.json` με `openssl passwd -6 "yourpassword"`.

Το όνομα και το email για τα git commits δεν αποτελούν μέρος της εγκατάστασης. Όρισέ τα μόλις το μηχάνημα είναι έτοιμο, μέσω SSH για παράδειγμα, με `omarchy setup git --name "Jane Doe" --email jane@example.com`.

Μπορείς επίσης να ρίξεις ένα κενό αρχείο με όνομα `defer-provisioning` στη θέση του `user_credentials.json`. Αυτό εκτελεί την ίδια [εγκατάσταση προετοιμασίας για άλλον ιδιοκτήτη](02-getting-started.md) που μπορείς να ενεργοποιήσεις και διαδραστικά: το μηχάνημα εγκαθίσταται χωρίς προσωπικά στοιχεία, και όποιος το εκκινήσει πρώτος επιλέγει το πληκτρολόγιό του και δημιουργεί τον χρήστη του. Αυτή είναι η λειτουργία για μηχανήματα δημιουργίας εικόνων, όπου η μονάδα δεν πρέπει να περιέχει καθόλου τα διαπιστευτήρια κανενός.

## Πρόσβαση SSH

Όταν υπάρχει το `authorized_keys`, η εγκατάσταση ρυθμίζει τα κλειδιά ως το `~/.ssh/authorized_keys` του χρήστη, ενεργοποιεί το `sshd` και ανοίγει το τείχος προστασίας για αυτό. (Μια τυπική εγκατάσταση Omarchy διατίθεται με το openssh με την υπηρεσία απενεργοποιημένη και τη θύρα κλειστή, οπότε ένα ανεπιτήρητο μηχάνημα θα ήταν διαφορετικά απρόσιτο.) Η εγκατάσταση προσθέτει μόνο τα κλειδιά σου — δεν χαλαρώνει καμία από τις άλλες ρυθμίσεις ταυτοποίησης του δαίμονα SSH.

Όταν υπάρχει το `tailscale_authkey`, το μηχάνημα συνδέεται στο tailnet σου κατά την πρώτη εκκίνηση: το Tailscale εγκαθίσταται από τα πακέτα που περιλαμβάνονται στο ISO, το τείχος προστασίας επιτρέπει τη διεπαφή του tailnet, και μια εργασία στο παρασκήνιο εκτελεί τη σύνδεση μόλις το μηχάνημα αποκτήσει πραγματικά δίκτυο, επαναλαμβάνοντας την προσπάθεια μέχρι να επιτύχει. Χρησιμοποίησε ένα επαναχρησιμοποιήσιμο, προεγκεκριμένο κλειδί, ώστε μία εικόνα μονάδας να μπορεί να εξυπηρετήσει πολλά μηχανήματα.

## Δημιουργία της μονάδας cidata

Οποιοδήποτε σύστημα αρχείων με τη σωστή ετικέτα λειτουργεί. Ένα μικροσκοπικό ISO είναι ο εύκολος τρόπος:

```bash
mkdir cidata
cp user_configuration.json user_credentials.json authorized_keys cidata/
genisoimage -output cidata.iso -volid cidata -joliet -rock cidata/
```

Στη συνέχεια σύνδεσέ το στο VM μαζί με το ISO του Omarchy. Ακολουθεί ένα πλήρες παράδειγμα με Proxmox:

```bash
qm create 101 --name my-omarchy \
  --bios ovmf --machine q35 --cpu host --cores 4 --memory 8192 \
  --ostype l26 --scsihw virtio-scsi-single \
  --efidisk0 local-lvm:0,efitype=4m,pre-enrolled-keys=0 \
  --scsi0 local-lvm:40,discard=on,iothread=1 \
  --net0 virtio,bridge=vmbr0 --vga virtio --serial0 socket \
  --ide2 local:iso/omarchy.iso,media=cdrom \
  --ide3 local:iso/cidata.iso,media=cdrom \
  --boot order='scsi0;ide2'

qm start 101
```

Η σειρά εκκίνησης αναφέρει σκόπιμα πρώτο τον δίσκο: ο κενός δίσκος περνά στο ISO κατά την πρώτη εκκίνηση, και το εγκατεστημένο σύστημα εκκινεί από τον δίσκο για πάντα μετά από αυτό.

## Δύο σημεία προσοχής

Οι κρυπτογραφημένες ανεπιτήρητες εγκαταστάσεις δεν είναι πλήρως ανεπιτήρητες — κάποιος πρέπει ακόμα να πληκτρολογήσει τη φράση πρόσβασης LUKS κατά την πρώτη εκκίνηση. Και το μπλοκ `disk_encryption` στο `user_configuration.json` περιέχει αυτή τη φράση πρόσβασης σε απλό κείμενο, οπότε αντιμετώπισε μια μονάδα cidata που δημιουργήθηκε από μια κρυπτογραφημένη εγκατάσταση ως το μυστικό που είναι.
