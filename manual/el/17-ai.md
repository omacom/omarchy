# AI

Το Omarchy περιλαμβάνει προγράμματα εκκίνησης για τους παρακάτω πράκτορες προγραμματισμού, χωρίς να επιλέγει προεπιλογή για εσάς. Εκτελέστε μια εντολή για να εγκατασταθεί το CLI της στην πρώτη χρήση και, στη συνέχεια, πραγματοποιήστε έλεγχο ταυτότητας όταν σας ζητηθεί. Το Hermes και το OpenClaw αποτελούν τις εξαιρέσεις: τίποτα δεν εγκαθίσταται γι' αυτά μέσω του mise, και η επιλογή οποιουδήποτε από τα δύο εγκαθιστά το δικό του αυτοενημερούμενο αντίγραφο, όπως εξηγεί παρακάτω η ενότητα _Εφαρμογές επιφάνειας εργασίας_.

### Εγκατάσταση και ενημέρωση πρακτόρων

Εκτός από το Hermes και το OpenClaw, αυτοί οι πράκτορες χρησιμοποιούν την τεμπέλικη εγκατάσταση του mise: η πρώτη εκκίνηση εγκαθιστά το CLI και οι επόμενες εκκινήσεις το επαναχρησιμοποιούν. Το mise ελέγχει επίσης έναν εγκατεστημένο πράκτορα για νέα έκδοση το πολύ μία φορά κάθε τέσσερις ώρες, λίγο πριν ξεκινήσει ή στο παρασκήνιο σε μια προτροπή κελύφους. Εάν αυτή η ενημέρωση αποτύχει ή είστε εκτός σύνδεσης, εκτελείται η εγκατεστημένη έκδοση. Η εντολή `omarchy update` ενημερώνει τους εγκατεστημένους πράκτορες μαζί με το υπόλοιπο Omarchy, και η εντολή `mup` ενημερώνει μόνο τα εργαλεία που διαχειρίζεται το mise.

Το πρόγραμμα ενημέρωσης ενός πράκτορα, όπως το `claude update`, το `codex update` ή ένα κουμπί ενημέρωσης σε μια εφαρμογή, δεν ενημερώνει την εγκατάσταση που διαχειρίζεται το mise. Η εντολή `codex update` αποτυγχάνει, και η εντολή `claude update` μπορεί να αναφέρει επιτυχία ενώ εγκαθιστά ένα ξεχωριστό αντίγραφο που το mise δεν παρακολουθεί. Εάν προτιμάτε να χρησιμοποιείτε το εγγενές πρόγραμμα εγκατάστασης και ενημέρωσης ενός πράκτορα, προσθέστε το στο `disable_tools`· δείτε το [Προεγκατεστημένα εργαλεία CLI](18-development-tools.md#preinstalled-cli-tools).

Για να εγκαταστήσετε όλα τα ρυθμισμένα τεμπέλικα εργαλεία πριν τα χρειαστείτε, εκτελέστε `mise install --include-lazy`. Αυτό περιλαμβάνει τόσο τα άλλα προεπιλεγμένα εργαλεία CLI του Omarchy όσο και τους πράκτορες. Δείτε το [Προεγκατεστημένα εργαλεία CLI](18-development-tools.md#preinstalled-cli-tools) για την εγκατάσταση ενός μεμονωμένου εργαλείου ή τη χρήση της δικής σας εγκατάστασης.

Το `grok` εγκαθίσταται μέσω του επίσημου πακέτου `grok` του mise, με τον ίδιο τρόπο όπως τα `claude` και `codex`. Εκτελέστε `grok` ή επιλέξτε το στο _Agent > Harness_. Παραλείψτε το πρόγραμμα εγκατάστασης `curl | bash` στο x.ai. Αυτή η διαδρομή τοποθετεί ένα δεύτερο αντίγραφο στο `~/.grok/bin`, το προτάσσει στο `PATH` και αντικαθιστά το wrapper του Omarchy.

Το `dsh` ανοίγει το UI του προγράμματος περιήγησής του στο `127.0.0.1:3080`, με τον κατάλογο εκκίνησης ως προεπιλεγμένο χώρο εργασίας του. Το UI του προγράμματος περιήγησής του δεν δέχεται αρχική προτροπή, οπότε η εντολή `omarchy agent prompt` το ανοίγει με την προτροπή στο πρόχειρό σας για επικόλληση. Το Omarchy το εκκινεί με την προεπιλογή δικαιωμάτων χωρίς έγκριση της DeepSeek. Το DeepSeek Harness ανεβάζει αρχεία καταγραφής συνεδριών στην DeepSeek όταν χρησιμοποιείτε το επίσημο API μοντέλων της· απενεργοποιήστε το στο _Settings > General > Upload Session Log_ στο UI του προγράμματος περιήγησής του. Τα σχόλια που του στέλνετε ανεβαίνουν επίσης μαζί με τη συνεδρία, εκτός εάν το εκκινήσετε με `DSH_TELEMETRY_MODE=DISABLED`.

### Ο προεπιλεγμένος πράκτορας

Επιλέξτε τον προεπιλεγμένο πράκτορά σας με `omarchy default agent <name>` ή στο _Agent > Harness_ στο Omarchy Menu (`Super + Space`). Εάν ο πράκτορας δεν είναι ακόμη εγκατεστημένος, η επιλογή του τον εγκαθιστά πρώτα, και αποκτά επίσης το δικό του πρόγραμμα εκκίνησης στο πρόγραμμα εκκίνησης εφαρμογών, δίπλα στο Agent. Ένα φρέσκο Omarchy θα σας προσκαλέσει να κάνετε αυτή την επιλογή με μια εφάπαξ ειδοποίηση.

Η επιλογή του Claude επιχειρεί επίσης να ρυθμίσει την επέκταση του προγράμματος περιήγησής του για Chromium, Chrome, Brave, Brave Origin και Edge. Η ρύθμιση της επέκτασης ισχύει για όλους τους χρήστες και μπορεί να ζητήσει τον κωδικό πρόσβασης του συστήματός σας· η ακύρωση ή μια αποτυχημένη εγκατάσταση επέκτασης εξακολουθεί να επιλέγει και να εκκινεί το Claude. Επανεκκινήστε το πρόγραμμα περιήγησής σας, ενεργοποιήστε την επέκταση εάν σας ζητηθεί και συνδεθείτε στο Claude για να ολοκληρώσετε τη σύνδεσή της. Εκτελέστε `/chrome` στο Claude για να ελέγξετε τη σύνδεση. Τα Firefox και Zen δεν υποστηρίζουν αυτή την επέκταση. Εάν το Claude ήταν ήδη η προεπιλογή σας πριν προστεθεί αυτή η ρύθμιση, επιλέξτε το ξανά για να εγκαταστήσετε την επέκταση.

Μόλις κάνετε την επιλογή, το `Super + Shift + Ctrl + A` εκκινεί τον προεπιλεγμένο πράκτορα σε ένα αποκλειστικό παράθυρο τερματικού (ή εμφανίζει το πρόγραμμα επιλογής εάν δεν έχετε επιλέξει ακόμη). Μπορείτε επίσης να τον εκκινήσετε απευθείας σε μια εργασία με `omarchy agent prompt "Review this project"`. Τα Freebuff και DeepSeek Harness δεν δέχονται αρχική προτροπή, οπότε ανοίγουν με την προτροπή στο πρόχειρό σας για επικόλληση. Οι πράκτορες που εκκινούνται με αυτόν τον τρόπο εκτελούνται χωρίς επίβλεψη στις αντίστοιχες λειτουργίες τους που δεν σταματούν για να ρωτήσουν, οπότε να είστε έτοιμοι να κάνουν πράγματα στ' αλήθεια! Το MiniMax Code δεν διαθέτει τέτοια λειτουργία για τις διαδραστικές συνεδρίες του, οπότε ζητά δικαιώματα ως συνήθως. Και επειδή οι πράκτορες αρνούνται να θυμούνται την εμπιστοσύνη για τον αρχικό κατάλογό σας, οι εκκινήσεις από το `$HOME` ξεκινούν αντ' αυτού στο `~/Work`.

Υπάρχουν και συντομεύσεις τερματικού: το `a` εκτελεί τον προεπιλεγμένο πράκτορα ενσωματωμένο στο τρέχον τερματικό, ενώ τα `c`, `cx` και `cy` εκκινούν απευθείας τα OpenCode, Claude Code και Codex (ξανά στις λειτουργίες αυτόματης έγκρισής τους). Οι αλλαγές θέματος συγχρονίζονται επίσης στους πράκτορες: τα Claude Code, Pi, OpenCode και Hermes (από τη στιγμή που το Omarchy το έχει εγκαταστήσει) ακολουθούν όλα όταν αλλάζετε το θέμα του Omarchy.

### Οι οδηγίες του πράκτορά σας

Οι προσωπικοί κανόνες για κάθε πράκτορα μπαίνουν στο `~/.agents/AGENTS.md`, δίπλα στα κοινόχρηστα skills στο `~/.agents/skills`. Ανοίξτε το στο _Agent > Instructions_, το οποίο το συνδέει επίσης σε κάθε harness που διατηρεί το δικό του καθολικό αρχείο: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, το `~/.copilot/copilot-instructions.md` του Copilot, και ούτω καθεξής. Τα Crush και Amp διαβάζουν τον σύνδεσμο `~/.config/AGENTS.md`, ενώ τα omp, Kimi και DeepSeek Harness διαβάζουν απευθείας το `~/.agents/AGENTS.md`. Η επιλογή ενός προεπιλεγμένου πράκτορα το συνδέει επίσης. Ένα αρχείο οδηγιών που είχατε ήδη γίνεται το κοινόχρηστο εάν δεν υπήρχε ακόμη κανένα· διαφορετικά διατηρείται δίπλα στον σύνδεσμο ως `.bak`. Εκτελέστε `omarchy agent instructions` για να επανασυνδέσετε μετά την εγκατάσταση ενός άλλου πράκτορα.

### Το πάνελ πρακτόρων

Η επάνω γραμμή έχει ένα εικονίδιο πρακτόρων. Πριν ρυθμίσετε έναν πράκτορα, το πάνελ του σας καθοδηγεί να συνδεθείτε στο Claude, το Codex ή το Grok, και το πρώτο γίνεται ο προεπιλεγμένος πράκτοράς σας. Μετά από αυτό, το πάνελ τοποθετεί κάθε συνδρομή σε μία σελίδα: κάθε πράκτορα και λογαριασμό με το πλάνο του, έναν μετρητή για καθένα από τα όρια συνεδρίας 5 ωρών και εβδομαδιαία όριά του με τον χρόνο μέχρι την επαναφορά του (περάστε το δείκτη για το ακριβές ποσοστό), ή το υπόλοιπο προπληρωμένο υπόλοιπο, κάτω από μια γραμμή που εναλλάσσεται ανάμεσα σε όσα έχετε χρησιμοποιήσει σε όλα αυτά, όπως tokens αυτή την εβδομάδα και το μοντέλο που χρησιμοποιείτε περισσότερο. Στο _Make something cool_ προσφέρει αρχικές προτροπές για ένα νέο θέμα, plugin, εφαρμογή ή παιχνίδι που παραδίδουν την εργασία στον προεπιλεγμένο πράκτορά σας. Οι εφαρμογές κατασκευάζονται με τον τρόπο που κατασκευάζονται τα ίδια τα Hype, Monologue και Omacut του Omarchy, σε C++ και Qt Quick, ακολουθώντας το agent skill omarchy-make-app, και ο μεταγλωττιστής και τα κομμάτια του Qt που χρειάζονται παρέχονται εγκατεστημένα. Τα παιχνίδια είναι μια ενιαία σελίδα three.js στο `~/Games/vibes`, ακολουθώντας το agent skill omarchy-make-game, και όλα ανοίγουν από ένα πρόγραμμα εκκίνησης Game Vibes στο τρέχον θέμα· φορτώνουν το three.js από το διαδίκτυο, οπότε χρειάζονται σύνδεση για να ξεκινήσουν. Τα Claude Code, Codex, Grok, Kimi, Cursor και το επίδομα Grok Bot του, GitHub Copilot, Muse, Antigravity και Devin καλύπτονται εξαρχής με τα όριά τους, το Kimchi με το πλάνο του, τις προπληρωμένες μονάδες και τους προϋπολογισμούς δαπανών του, και τα Hermes, Mistral Vibe και Qwen Code εμφανίζουν τις συνεδρίες και τα tokens τους μόλις τα χρησιμοποιήσετε. Τα πλάνα και τα κλειδιά παρόχων που χρησιμοποιείτε μέσω των pi, omp ή opencode εμφανίζονται επίσης: τα OpenCode Zen και Go, το Z.ai GLM Coding Plan, το Ollama Cloud, το MiniMax Token Plan και το Synthetic με τα όριά τους· τα OpenRouter και DeepSeek με τα προπληρωμένα υπόλοιπά τους· το Fireworks με τις δαπάνες του τις τελευταίες 30 ημέρες. Τα tokens από μοντέλα που εκτελείτε στο δικό σας υλικό προσμετρώνται επίσης στα σύνολα· τα ίδια τα μοντέλα έχουν το δικό τους πάνελ, που περιγράφεται στο [Τοπικά μοντέλα](#local-models). Κάθε πράκτορας καταμετράται μία φορά, σε όποιον τον χρεώνει, ανεξάρτητα από το πόσα harnesses τον οδηγείτε.

Κάντε αριστερό κλικ στο εικονίδιο της γραμμής ή πατήστε `Super + Ctrl + X` για το πάνελ, δεξί κλικ για να εκκινήσετε τον προεπιλεγμένο πράκτορά σας και μεσαίο κλικ για ανανέωση. Οι εγγραφές χρήσης πίσω από αυτό αναγεννώνται κάθε 15 λεπτά από το `omarchy agent usage update`, και το πάνελ μπορεί ακόμη και να συγχωνεύσει χρήση από τα άλλα μηχανήματά σας μέσω ενός συγχρονισμένου φακέλου. Δείτε το README στο `$OMARCHY_PATH/shell/plugins/agents/` για τις πλήρεις ρυθμίσεις.

### Πολλαπλές συνδρομές

Εάν πληρώνετε για περισσότερα από ένα πλάνα Claude, Codex ή Grok — ένα προσωπικό Max και ένα επαγγελματικό, ας πούμε — το Omarchy μπορεί να τα κρατήσει όλα συνδεδεμένα και να μετακινείται ανάμεσά τους. Προσθέστε μια συνδρομή με το + στο πάνελ πρακτόρων, το οποίο σας καθοδηγεί εκεί επιτόπου, ή με `omarchy agent account add claude Work` (ή `codex`, ή `grok`). Εγκαθιστά το CLI εάν λείπει. Ο πρώτος λογαριασμός για έναν πάροχο συνδέεται μέσω του κανονικού προγράμματος περιήγησής σας, ακριβώς εκεί που ψάχνει πάντα το CLI. Κάθε επόμενος συνδέεται μέσω ενός ιδιωτικού παραθύρου, οπότε ο λογαριασμός στον οποίο το πρόγραμμα περιήγησής σας είναι ήδη συνδεδεμένο δεν λαμβάνεται κατά λάθος· συνδεθείτε εκεί ως ο λογαριασμός που προσθέτετε, και κλείστε πρώτα όποιο ιδιωτικό παράθυρο είχατε ήδη ανοιχτό. Μην αποσυνδέεστε ποτέ από το CLI για να το κάνετε αυτό: η αποσύνδεση ανακαλεί την αποθηκευμένη σύνδεση, και αυτός ο λογαριασμός θα έπρεπε να προστεθεί ξανά.

Για να αντιγράψετε τις συνδέσεις συνδρομών σας σε ένα άλλο μηχάνημα Omarchy μέσω SSH, εκτελέστε `omarchy agent account copy user@laptop`. Ο αποστολέας παρέχει έναν προσωρινό παραλήπτη όταν ο προορισμός δεν έχει έναν εγκατεστημένο, οπότε παλαιότερα μηχανήματα Omarchy μπορούν να λάβουν λογαριασμούς χωρίς ενημέρωση. Οι εγκατεστημένοι παραλήπτες έχουν προτεραιότητα. Αυτό αντιγράφει όλες τις συνδρομές Claude, Codex και Grok· προσθέστε ονόματα παρόχων για να τις επιλέξετε, όπως στο `omarchy agent account copy laptop claude`. Τα ονόματα λογαριασμών και τα αναγνωριστικά εντολών ταιριάζουν με την πηγή, συμπεριλαμβανομένων λογαριασμών που υπάρχουν ήδη στον προορισμό. Άσχετοι λογαριασμοί προορισμού λαμβάνουν ένα αριθμητικό επίθημα εάν τα ονόματά τους συγκρούονται, και οι ρυθμίσεις, τα skills, τα plugins και το ιστορικό συνομιλιών παραμένουν τοπικά σε κάθε μηχάνημα.

Τα υπάρχοντα διαπιστευτήρια προορισμού διατηρούνται. Ένας λογαριασμός πηγής που είναι ήδη συνδεδεμένος εκεί συγχρονίζει το όνομά του χωρίς να αντικαθιστά τα διαπιστευτήριά του· άλλοι λογαριασμοί προστίθενται δίπλα του. Για να αντικαταστήσετε αποθηκευμένα διαπιστευτήρια για λογαριασμούς που ταιριάζουν, χρησιμοποιήστε `omarchy agent account copy --replace laptop claude` αφού κλείσετε τις συνεδρίες αυτού του λογαριασμού στον προορισμό. Ένας φρέσκος προορισμός λαμβάνει επίσης τον ενεργό λογαριασμό και τις προτιμήσεις εναλλαγής της πηγής· ένας καθιερωμένος προορισμός διατηρεί τις δικές του.

Τα διαπιστευτήρια ταξιδεύουν μέσω SSH και αποθηκεύονται σε ιδιωτικά αρχεία στον προορισμό, οπότε αντιγράψτε μόνο σε μηχανήματα που εμπιστεύεστε. Αυτή είναι μια εφάπαξ αντιγραφή, όχι συνεχιζόμενος συγχρονισμός. Τα refresh tokens του Codex μπορούν να εναλλαγούν από ένα άλλο μηχάνημα, αφήνοντας μια αντιγραμμένη σύνδεση να χρειάζεται ανανέωση· οι ξεχωριστές συνδέσεις παραμένουν η πιο αξιόπιστη επιλογή για ταυτόχρονη χρήση σε πολλά μηχανήματα. Δείτε τις [οδηγίες ελέγχου ταυτότητας λογαριασμού του Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Ένας λογαριασμός ανά πάροχο είναι ενεργός, και κάθε νέα συνεδρία ξεκινά ως αυτός: τα `cx`, `cy`, ένα απλό `claude`, `codex` ή `grok`, οτιδήποτε εκκινείται μέσω του `omarchy agent`, και scripts ή επεξεργαστές που βρίσκουν το CLI στο `PATH`. Εναλλαγή με `omarchy agent account use work` (και πίσω με `omarchy agent account use main`), ή στο πάνελ πατώντας τον αριθμό ενός λογαριασμού και στη συνέχεια `Enter` (ή κάνοντας κλικ στο κουμπί Use του). Οι συνεδρίες Claude που εκτελούνται εναλλάσσονται επίσης, από το επόμενό τους μήνυμα: κάθε συνεδρία Claude εκτελείται στο `~/.claude`, το οποίο διατηρεί πάντα τη σύνδεση του ενεργού λογαριασμού. Μια συνεδρία Claude που ξεκίνησε στον δικό της φάκελο ενός λογαριασμού από ένα παλαιότερο Omarchy διατηρεί αυτή τη σύνδεση μέχρι να κλείσει, οπότε η εναλλαγή ονομάζει αυτές τις συνεδρίες και ολοκληρώνεται μόνη της μόλις εξαφανιστούν. Οι συνεδρίες Codex και Grok που εκτελούνται παραμένουν στον λογαριασμό με τον οποίο ξεκίνησαν. Το ιστορικό συνομιλιών, οι ρυθμίσεις, τα skills και τα plugins μοιράζονται μεταξύ λογαριασμών, οπότε το `claude --continue` στον ίδιο φάκελο συνεχίζει από εκεί που σταματήσατε στον νέο λογαριασμό.

Με περισσότερους από έναν λογαριασμούς, το πάνελ εμφανίζει τα όρια κάθε λογαριασμού δίπλα-δίπλα, με τον ενεργό επισημασμένο. Από προεπιλογή το Omarchy σας ειδοποιεί όταν ο ενεργός λογαριασμός ξεπεράσει το 95% ενός ορίου, και κάνοντας κλικ στην ειδοποίηση εναλλάσσεστε στον λογαριασμό με το περισσότερο περιθώριο. Περάστε το δείκτη πάνω από τη γραμμή ενός λογαριασμού στο πάνελ και κάντε κλικ στο Autoswitch που εμφανίζεται δίπλα στο Use (ή πατήστε `m`), ή εκτελέστε `omarchy agent account mode auto`, για να γίνεται η εναλλαγή μόνη της· όσο είναι ενεργό, το Autoswitch παίρνει τη θέση του Use, και κάνοντας ξανά κλικ σε αυτό επιστρέφετε στην ειδοποίηση. Προσθέστε έναν αριθμό για να αλλάξετε το όριο, όπως στο `omarchy agent account mode auto 90`. Εάν κάθε λογαριασμός είναι πάνω από το όριο, θα το ακούσετε μία φορά, μαζί με το ποιος λογαριασμός ελευθερώνεται πρώτος. Όσο ένας ενεργός λογαριασμός βρίσκεται εντός 15 μονάδων από το όριό του (80% στην προεπιλογή), τα όριά του ελέγχονται κάθε τρία λεπτά αντί για κάθε 15.

Η εντολή `omarchy agent account list` εμφανίζει κάθε λογαριασμό και τα τελευταία όριά του, η `omarchy agent account remove work` ξεχνά έναν, και η `omarchy agent account rename primary Hey` μετονομάζει έναν (ή κάντε κλικ στο όνομα ενός λογαριασμού στο πάνελ). Αυτές οι εντολές λειτουργούν στους λογαριασμούς του προεπιλεγμένου πράκτορά σας· για να φτάσετε στον άλλο πάροχο, ονομάστε τον πρώτα, όπως στο `omarchy agent account use codex side`. Η σύνδεση που είχατε ήδη στο `~/.claude` ή στο `~/.codex` είναι ο λογαριασμός _Main_. Η σύνδεση του Codex παραμένει εκεί που είναι· η σύνδεση του Claude περιμένει σε δικό της φάκελο όσο ένας άλλος λογαριασμός είναι ενεργός. Ένας λογαριασμός που μένει αχρησιμοποίητος για περισσότερες από περίπου οκτώ ώρες μπορεί να εμφανίσει _Sign-in required_· κάντε κλικ σε αυτόν για να συνδεθείτε ξανά σε αυτόν τον λογαριασμό απευθείας στο πάνελ, ή εναλλαγείτε σε αυτόν και ξεκινήστε μια συνεδρία, η οποία ανανεώνει τη σύνδεση μόνη της. Οι διακομιστές MCP που προσθέτετε με `claude mcp add` φτάνουν σε κάθε λογαριασμό Claude, αφού όλοι εκτελούνται στο `~/.claude`· για τα Codex και Grok, οι διακομιστές που είχατε όταν προστέθηκε ένας λογαριασμός έρχονται μαζί του, αλλά οι μεταγενέστεροι φτάνουν μόνο στον λογαριασμό στον οποίο τους προσθέσατε. Το Claude Desktop διατηρεί μια δική του σύνδεση, και τα εργαλεία Codex ή Grok που έχουν ρυθμιστεί με απόλυτη διαδρομή προς ένα δυαδικό CLI δεν ακολουθούν την εναλλαγή. Ένα ρητό `CLAUDE_CONFIG_DIR`, `CODEX_HOME` ή `GROK_HOME` υπερισχύει του επιλεγμένου λογαριασμού.

### Διάγνωση καταρρεύσεων

Το Omarchy παρακολουθεί το systemd-coredump για καταρρεύσεις διεργασιών. Μόλις επιλέξετε έναν προεπιλεγμένο πράκτορα, οποιοδήποτε δικό σας πρόγραμμα που δημιουργεί core dump φέρνει μια ειδοποίηση "Process crashed" — κάντε κλικ σε αυτήν, και η κατάρρευση παραδίδεται στον προεπιλεγμένο πράκτορά σας μαζί με το skill omarchy-diagnose-crash του Omarchy, το οποίο καθοδηγεί τον πράκτορα να διαπιστώσει τα γεγονότα από το core dump και να αποφασίσει εάν η κατάρρευση αξίζει να αναφερθεί upstream. Μπορείτε επίσης να το εκτελέσετε χειροκίνητα για οποιοδήποτε PID από το `coredumpctl list` με `omarchy agent crash <pid>`.

Η παρακολούθηση είναι ενεργοποιημένη από προεπιλογή. Απενεργοποιήστε την στο _Trigger > Toggle > Crash Capture Off_ (ή με `omarchy toggle crash-capture`) και οι ειδοποιήσεις σταματούν· η εντολή `omarchy agent crash <pid>` εξακολουθεί να λειτουργεί χειροκίνητα.

Οι καταρρεύσεις μπορούν επίσης να σιγαστούν ένα πρόγραμμα κάθε φορά, πράγμα που σας προσφέρει η διάγνωση στο τέλος. Η εντολή `omarchy crash mute hyprland` σταματά τις ειδοποιήσεις μόνο για αυτό το πρόγραμμα, η `omarchy crash mute hyprland off` τις επαναφέρει, και η `omarchy crash mute` μόνη της απαριθμεί όσα έχετε σιγάσει. Δέχεται τη διαδρομή του δυαδικού τόσο ευχαρίστως όσο και το όνομά του, οπότε η `omarchy crash mute /usr/bin/hyprland` κάνει το ίδιο πράγμα. Βάλτε σε εισαγωγικά ένα όνομα με κενό, όπως στο `omarchy crash mute 'Some App'`. Όλα τα υπόλοιπα εξακολουθούν να ειδοποιούν, και το σιγασμένο πρόγραμμα εξακολουθεί να καταρρέει — αυτό κρύβει την υπενθύμιση, δεν διορθώνει τίποτα.

### Εφαρμογές επιφάνειας εργασίας

Το μενού _Install > AI_ φέρει επίσης μερικές γραφικές εφαρμογές AI: Amp Desktop, Antigravity Desktop, την εφαρμογή επιφάνειας εργασίας ChatGPT, την εφαρμογή επιφάνειας εργασίας Claude (τη Linux beta της Anthropic, με καρτέλες Chat, Cowork και Claude Code), Grok Bot για συνομιλία με τα μοντέλα της xAI, Herdr Desktop, Hermes Desktop, OpenClaw, την εφαρμογή επιφάνειας εργασίας Perplexity και T3 Code. Το Grok Bot είναι η εφαρμογή συνομιλίας επιφάνειας εργασίας. Ο πράκτορας προγραμματισμού είναι η εντολή `grok`.

Το Hermes Desktop είναι αυτό που πρέπει να ξέρετε, επειδή ένα μηχάνημα έχει ένα Hermes, και είναι αυτό της εφαρμογής: το Hermes εγκαθίσταται μόνο ποτέ μέσω της εφαρμογής, και η εντολή `hermes` που εκτελεί ο προεπιλεγμένος πράκτορας είναι αυτή της εφαρμογής. Η επιλογή του Hermes ως προεπιλεγμένου πράκτορα εγκαθιστά το ίδιο πράγμα που κάνει η καταχώριση _Install > AI_: το πακέτο, και ένα περιβάλλον εκτέλεσης Hermes στο `~/.hermes` ρυθμισμένο από το ίδιο το πρόγραμμα εγκατάστασης του Hermes, το οποίο χρειάζεται μερικά λεπτά την πρώτη φορά. Αυτό το περιβάλλον εκτέλεσης είναι το ένα Hermes που χρησιμοποιούν η εντολή `hermes` του τερματικού, ο προεπιλεγμένος πράκτορας και η εφαρμογή, και ενημερώνεται μόνο του με `hermes update` αντί να περιμένει μια έκδοση του Omarchy. Η εγκατάστασή του παραδίδει επίσης στο Hermes το θέμα του Omarchy ως skin με όνομα `omarchy`, το οποίο ακολουθεί κάθε επιφάνεια του Hermes καθώς αλλάζετε θέματα· επιλέξτε άλλο στις ρυθμίσεις Appearance του Hermes ή με `/skin` εάν προτιμάτε να μην το κάνει, και το Omarchy αφήνει αυτή την επιλογή ήσυχη. Η αφαίρεση της εφαρμογής στο _Remove > AI_ κλείνει πρώτα το Hermes, συμπεριλαμβανομένης της πύλης, παίρνει μαζί της αυτό το περιβάλλον εκτέλεσης και διατηρεί τις συνομιλίες, τις μνήμες και τα skills που το Hermes έγραψε για τον εαυτό του, εκτός εάν του πείτε διαφορετικά: ρωτά, με προεπιλογή το όχι, εάν αυτά τα δεδομένα και οι ρυθμίσεις σύνδεσής σας πρέπει να φύγουν επίσης.

Η εμπειρία επιφάνειας εργασίας του OpenClaw είναι το Control UI του, το οποίο ανοίγει ως εφαρμογή ιστού υποστηριζόμενη από τη δική του τοπική πύλη. Το OpenClaw ζει στο `~/.openclaw` και ενημερώνεται μόνο του: χρησιμοποιήστε το κουμπί "Update Gateway" του Control UI ή εκτελέστε `openclaw update`, και η πύλη επανεκκινεί στη νέα έκδοση. Το Omarchy επιλέγει μόνο την έκδοση από την οποία ξεκινά μια φρέσκια εγκατάσταση. Το OpenClaw μπορεί επίσης να είναι ο προεπιλεγμένος πράκτοράς σας: επιλέγοντάς το στο _Agent > Harness_ ρυθμίζει αυτό το ίδιο αντίγραφο στο `~/.openclaw`, και ο πράκτορας ανοίγει το τερματικό UI του OpenClaw συνδεδεμένο με την πύλη του. Η αφαίρεση του OpenClaw στο _Remove > AI_ παίρνει μαζί της την υπηρεσία πύλης και την εφαρμογή και στη συνέχεια ρωτά εάν το `~/.openclaw` πρέπει να φύγει επίσης, αφού αυτό διατηρεί τις συνομιλίες και τα διαπιστευτήριά σας μαζί με το ίδιο το OpenClaw και τα περιβάλλοντα εκτέλεσης plugins που κατεβάζει· η προεπιλογή το διατηρεί, και η εκ νέου εγκατάσταση του OpenClaw το ανακτά.

Το Herdr Desktop είναι η εφαρμογή επιφάνειας εργασίας [Herdr](https://herdr.dev): χώροι, καρτέλες και πλαίσια τερματικών και πρακτόρων προγραμματισμού που συνεχίζουν να εκτελούνται στον πυρήνα του όταν κλείνετε το παράθυρο. Προέρχεται από το ίδιο το πρόγραμμα εγκατάστασης του Herdr αντί για ένα πακέτο, οπότε ζει στο `~/.local/share/herdr-app`, φέρνει τον πυρήνα του στο `~/.local/bin/herdr-core` όταν δεν έχετε ακόμη έναν, και ενημερώνει και τα δύο μόνο του. Βρίσκεται δίπλα στην εντολή `herdr` που παρέχει το Omarchy στο `Super + Ctrl + Return` αντί να την αντικαθιστά, και αποκτά τα άμεσα πλήκτρα αυτής της εντολής: τα `Alt + Return` και `Alt + Shift + Return` διαιρούν ένα πλαίσιο προς τα κάτω ή προς τα δεξιά, το `Alt + Escape` το κλείνει, το `Ctrl + Alt + Arrow` μετακινείται ανάμεσα σε πλαίσια, τα `Alt + 1..9` και `Alt + Left/Right` επιλέγουν μια καρτέλα, και το `Alt + Up/Down` μετακινείται ανάμεσα σε χώρους. Το `Ctrl + 1..9` επιλέγει έναν χώρο και το `Alt + Shift + Up/Down` περνά από πράκτορες. Τα πλήκτρα προθέματος `Ctrl + Space` παραμένουν μόνο για τερματικό, αφού η εφαρμογή δεν μπορεί να κρατήσει ένα απλό πλήκτρο Ctrl για μια ακολουθία. Το Omarchy τα γράφει στο `~/.config/herdr-app/keys.json`, και το `omarchy-refresh-herdr-app` τα επαναφέρει. Η εγκατάστασή του επιλέγει το θέμα Omarchy του Herdr, το οποίο ακολουθεί το θέμα Omarchy σας από τότε και στο εξής. Το Herdr διατηρεί ένα θέμα για τη φωτεινή λειτουργία και ένα για τη σκοτεινή, οπότε αφού εναλλαγείτε ανάμεσα σε ένα σκοτεινό και ένα φωτεινό θέμα Omarchy, επιλέξτε το Omarchy στο πρόγραμμα επιλογής θέματος του Herdr μία ακόμη φορά για την άλλη λειτουργία.

Το T3 Code εκτελείται από την επίσημη έκδοση AppImage του στο `~/.local/share/t3code` αντί από ένα πακέτο, οπότε ενημερώνεται μόνο του. Η εγκατάστασή του ρωτά εάν θα ξεκινήσετε στο κανάλι Stable ή Nightly· αλλάξτε αργότερα στις ρυθμίσεις του T3 Code. Τα νήματα και οι ρυθμίσεις σας ζουν στο `~/.t3`, και η αφαίρεση του T3 Code στο _Remove > AI_ τα παίρνει μαζί της.

### Τοπικά μοντέλα

Εκτελέστε ένα ανοιχτό μοντέλο στο δικό σας μηχάνημα για τους πράκτορες προγραμματισμού σας. Οι προτροπές και ο κώδικάς σας παραμένουν στο μηχάνημα· τίποτα που στέλνεται στο μοντέλο δεν το εγκαταλείπει. Ξεκινήστε με:

```bash
omarchy models use best text
```

Αυτό ρυθμίζει το καλύτερο μοντέλο κειμένου για αυτό το μηχάνημα, το είδος που χρησιμοποιούν οι πράκτορές σας. Τα μοντέλα εικόνας, βίντεο και μουσικής έχουν το δικό τους καλύτερο: `omarchy models use best image`, `video` ή `music`. Εκτελέστε `omarchy models use best` για να δείτε την επιλογή κάθε είδους για αυτό το μηχάνημα.

Ή ανοίξτε το πάνελ τοπικών μοντέλων από το εικονίδιο με τις σπίθες του στην επάνω γραμμή, δίπλα στο εικονίδιο πρακτόρων, ή με Super + Ctrl + Shift + X, και επιλέξτε +. Το εικονίδιο εμφανίζεται όταν ένα μοντέλο ταιριάζει σε αυτό το μηχάνημα. Το Podman, που εκτελεί τα μοντέλα, παρέχεται με το Omarchy, όπως και το κιτ εργαλείων container της NVIDIA σε ένα μηχάνημα NVIDIA, που τους δίνει την GPU· εάν λείπει κάποιο από τα δύο, η πρώτη ρύθμιση το εγκαθιστά. Το Omarchy στη συνέχεια επιλέγει το προτεινόμενο μοντέλο για αυτό το μηχάνημα, το κατεβάζει και το εκκινεί. Αναμένετε λήψη δεκάδων GB και χρήση του μεγαλύτερου μέρους της μνήμης του μηχανήματος όσο εκτελείται το μοντέλο: το Flash Next χρησιμοποιεί περίπου 100 GiB με το πλήρες περιεχόμενό του 256K. Εάν άλλα μοντέλα κρατούν τη μνήμη που χρειάζεται, ρυθμίζεται σταματημένο, έτοιμο να ξεκινήσει μόλις σταματήσετε ένα. Το μοντέλο σταματά κατά την αποσύνδεση· σταματήστε το εσείς οι ίδιοι όταν χρειάζεστε τη μνήμη για κάτι άλλο.

Η εντολή `omarchy models list` εμφανίζει τις επιλογές και εξηγεί γιατί μερικές δεν ταιριάζουν. Για να ρυθμίσετε ένα άλλο, εκτελέστε `omarchy models use <recipe>`. Σήμερα, τα `qwen3.8-flash-next-gufo` και `qwen3.8-27b-gufo` είναι διαθέσιμα για μηχανήματα Strix Halo 128 GB· το 27B χρειάζεται περίπου 40 GiB, οπότε αφήνει χώρο για άλλη εργασία. Σε ένα φορητό 64 GB με Intel Arc B390, το `qwen3.6-35b-a3b-llamacpp` εκτελείται σε περίπου 30 GiB. Νέες συνταγές και προτάσεις φτάνουν με το `omarchy update`, μέσω του πακέτου.

Κάθε μοντέλο που ρυθμίζετε αποκτά τη δική του γραμμή στο πάνελ τοπικών μοντέλων: αναπαραγωγή για εκκίνηση, παύση για διακοπή και απελευθέρωση της μνήμης του, και το κουμπί τερματικού για να ανοίξετε τον πράκτορά σας σε αυτό. Στο επάνω μέρος, μια γραμμή δείχνει πώς η μνήμη του μηχανήματος διαιρείται ανάμεσα στο ίδιο το Omarchy (το σύστημα και τις εφαρμογές σας), κάθε μοντέλο που εκτελείται και ό,τι είναι ελεύθερο. Στρέψτε το δείκτη σε ένα σταματημένο μοντέλο και η γραμμή δείχνει εάν χωράει ή πόσο του λείπει. Πολλά μπορούν να εκτελούνται ταυτόχρονα όταν χωρούν μαζί στη μνήμη· εάν ένα δεν χωράει, το Omarchy λέει ποιο μοντέλο που εκτελείται να σταματήσετε. Σύρετε γραμμές από το λογότυπό τους για να τις αναδιατάξετε, και πατήστε Delete σε μια επιλεγμένη γραμμή για να αφαιρέσετε ένα μοντέλο και τη λήψη του.

Κάθε μοντέλο που ρυθμίζετε αποκτά επίσης τη δική του καταχώριση στο πρόγραμμα εκκίνησης εφαρμογών, με το όνομα του μοντέλου και το λογότυπο του κατασκευαστή του, με τον τρόπο που η σύνδεση στο Claude, το Codex ή το Grok προσθέτει μία. Ανοίγει τον πράκτορά σας σε αυτό το μοντέλο και εκκινεί πρώτα το μοντέλο εάν δεν εκτελείται: το τερματικό το δείχνει να φορτώνει και παραδίδει στον πράκτορα μόλις είναι έτοιμο. Η αφαίρεση ενός μοντέλου αφαιρεί την καταχώρισή του.

Δεν είναι κάθε μοντέλο για προγραμματισμό. Τα μοντέλα εικόνας, βίντεο και μουσικής ανοίγουν αντ' αυτού στο Fantasi, την εφαρμογή του Omarchy για τη δημιουργία εικόνων, βίντεο και μουσικής με ένα μοντέλο που εκτελείται σε αυτό το μηχάνημα, από την καταχώριση του προγράμματος εκκίνησής τους και από τη γραμμή τους στο πάνελ τοπικών μοντέλων.

Ένα μοντέλο συνεχίζει να εκτελείται ακριβώς όπως ρυθμίστηκε, οπότε μια ενημέρωση του Omarchy δεν επανεκκινεί ποτέ ένα κάτω από τους πράκτορές σας. Όταν το Omarchy διαθέτει νεότερο περιβάλλον εκτέλεσης ή νεότερα βάρη για ένα μοντέλο που έχετε ρυθμίσει, η γραμμή του εμφανίζει ένα κουμπί ενημέρωσης: πατήστε το και το μοντέλο ρυθμίζεται ξανά στο παρασκήνιο, κατεβάζοντας μόνο ό,τι άλλαξε, και επανεκκινεί στη νέα έκδοση. Ένα μοντέλο που ήταν σταματημένο παραμένει σταματημένο. Η εντολή `omarchy models update` κάνει το ίδιο για κάθε μοντέλο από ένα τερματικό.

Από τη γραμμή εντολών, οι `omarchy models start <recipe>` και `omarchy models stop <recipe>` κάνουν το ίδιο, η `omarchy models status` εμφανίζει κάθε μοντέλο, και η `omarchy agent --local` ανοίγει τον προεπιλεγμένο πράκτορά σας στο τελευταίο μοντέλο που εκκινήσατε. Τα pi, OpenCode και Qwen Code μπορούν να χρησιμοποιήσουν ένα· με οποιαδήποτε άλλη προεπιλογή ανοίγει στο pi, ή στο OpenCode εάν δεν έχετε pi. Το pi απαριθμεί επίσης κάθε μοντέλο που έχετε ρυθμίσει, καθώς και εκείνα σε μηχανήματα με τα οποία έχετε συνδεθεί, στο δικό του πρόγραμμα επιλογής μοντέλου, οπότε το απλό `pi` τα φτάνει επίσης. Οποιοσδήποτε πελάτης συμβατός με OpenAI μπορεί επίσης να συνδεθεί: η `status` εμφανίζει τη διεύθυνση κάθε μοντέλου (η πρώτη είναι `http://127.0.0.1:11435/v1`), το όνομα της συνταγής είναι το μοντέλο, και το κλειδί βρίσκεται στο `~/.config/omarchy/agent-local/key`.

Η εντολή `omarchy models remove <recipe>` διαγράφει ένα μοντέλο και τις λήψεις που δεν χρησιμοποιεί κανένα άλλο μοντέλο.

Τα περιβάλλοντα εκτέλεσης τρίτων επισημαίνονται με τον εκδότη τους. Το Omarchy εκτελεί κάθε μοντέλο χωρίς πρόσβαση στο δίκτυο.

### Τοπικά LLM

Το Omarchy προτείνει δύο τρόπους εκτέλεσης τοπικών μοντέλων LLM: το LM Studio και το Ollama. Το LM Studio παρέχει ένα GUI περιβάλλον για την εύρεση μοντέλων ανοιχτών βαρών, την εγκατάστασή τους και την εκτέλεσή τους. Είναι ένας εξαιρετικός τρόπος για να ξεκινήσετε εύκολα. Το Ollama προσφέρει ένα CLI για να κάνετε παρόμοια πράγματα. Αλλά εάν είστε νέοι στα τοπικά μοντέλα, εγώ θα ξεκινούσα με το LM Studio. Μπορείτε να εγκαταστήσετε οποιοδήποτε από τα δύο στο _Install > AI_ στο Omarchy Menu.

### Τα skills του Omarchy

Τα agent skills βοηθούν την AI να χρησιμοποιεί συγκεκριμένα εργαλεία με συγκεκριμένο τρόπο, και το Omarchy παρέχει επτά από αυτά. Το skill omarchy καλύπτει την προσαρμογή του συστήματος, όπως την τροποποίηση της διαμόρφωσης Hyprland σας ή την προσαρμογή της γραμμής. Τα omarchy-make-theme, omarchy-make-plugin, omarchy-make-app και omarchy-make-game καλύπτουν τη δημιουργία κάτι νέου, το omarchy-contribute καλύπτει την αναφορά ενός σφάλματος ή την αποστολή μιας διόρθωσης upstream, και το omarchy-diagnose-crash επεξεργάζεται το core dump μιας κατάρρευσης. Συνδέονται με συμβολικούς συνδέσμους στους καταλόγους skills για τα Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` και κάθε `~/.hermes/profiles/*/skills`), και τη γενική τοποθεσία `~/.agents/skills`, οπότε τα περισσότερα harnesses τα λαμβάνουν αυτόματα. Ένας δικός σας φάκελος skill με το ίδιο όνομα έχει προτεραιότητα.

Αλλά πρέπει να αντιμετωπίζετε αυτά τα skills ως πειραματικά. Διαφορετικά μοντέλα θα τα χρησιμοποιήσουν με διαφορετικό αποτέλεσμα. Είναι καλύτερο να εκτελείτε πρώτα σε λειτουργία σχεδιασμού, ώστε να έχετε μια ιδέα για το τι θα ήθελε να αλλάξει ο πράκτορας. Και στη συνέχεια να είστε έτοιμοι να αναιρέσετε αλλαγές ή ακόμη και να επικαλεστείτε το `omarchy reinstall configs`, εάν ο πράκτορας κάνει παντού χάλια.
