# AI

Η Omarchy περιλαμβάνει εκκινητές για τους παρακάτω πράκτορες προγραμματισμού χωρίς να επιλέγει προεπιλογή για εσάς. Εκτελέστε μια εντολή για να εγκατασταθεί το CLI της στην πρώτη χρήση και στη συνέχεια πιστοποιηθείτε όταν σας ζητηθεί. Οι Hermes και OpenClaw είναι οι εξαιρέσεις: τίποτα δεν εγκαθίσταται για αυτούς μέσω mise, και η επιλογή οποιουδήποτε από τους δύο εγκαθιστά το δικό του αυτοενημερούμενο αντίγραφο, όπως εξηγούν οι _Εφαρμογές desktop_ παρακάτω.

### Εγκατάσταση και ενημέρωση πρακτόρων

Εκτός από τους Hermes και OpenClaw, αυτοί οι πράκτορες χρησιμοποιούν τη lazy εγκατάσταση της mise: η πρώτη εκκίνηση εγκαθιστά το CLI και οι επόμενες εκκινήσεις το επαναχρησιμοποιούν. Η mise ελέγχει επίσης έναν εγκατεστημένο πράκτορα για νέα έκδοση το πολύ μία φορά κάθε τέσσερις ώρες, λίγο πριν ξεκινήσει ή στο παρασκήνιο σε ένα prompt κελύφους. Αν αυτή η ενημέρωση αποτύχει ή είστε εκτός σύνδεσης, εκτελείται η εγκατεστημένη έκδοση. Το `omarchy update` ενημερώνει τους εγκατεστημένους πράκτορες μαζί με την υπόλοιπη Omarchy, και το `mup` ενημερώνει μόνο τα εργαλεία που διαχειρίζεται η mise.

Ο δικός του updater ενός πράκτορα, όπως το `claude update`, το `codex update` ή ένα κουμπί ενημέρωσης σε μια εφαρμογή, δεν ενημερώνει την εγκατάσταση που διαχειρίζεται η mise. Το `codex update` αποτυγχάνει, και το `claude update` μπορεί να αναφέρει επιτυχία ενώ εγκαθιστά ένα ξεχωριστό αντίγραφο που η mise δεν παρακολουθεί. Αν προτιμάτε να χρησιμοποιείτε τον εγγενή installer και updater ενός πράκτορα, προσθέστε τον στο `disable_tools`; δείτε τα [Προεγκατεστημένα εργαλεία CLI](18-development-tools.md#preinstalled-cli-tools).

Για να εγκαταστήσετε όλα τα ρυθμισμένα lazy εργαλεία πριν τα χρειαστείτε, εκτελέστε `mise install --include-lazy`. Αυτό περιλαμβάνει τα άλλα προεπιλεγμένα εργαλεία CLI της Omarchy καθώς και τους πράκτορες. Δείτε τα [Προεγκατεστημένα εργαλεία CLI](18-development-tools.md#preinstalled-cli-tools) για την εγκατάσταση ενός μεμονωμένου εργαλείου ή τη χρήση δικής σας εγκατάστασης.

Το `grok` εγκαθίσταται μέσω του first-party πακέτου `grok` της mise, με τον ίδιο τρόπο όπως τα `claude` και `codex`. Εκτελέστε `grok` ή επιλέξτε το στο _Agent > Harness_. Παραλείψτε τον installer `curl | bash` στο x.ai. Αυτή η διαδρομή τοποθετεί ένα δεύτερο αντίγραφο στο `~/.grok/bin`, το προτάσσει στο `PATH` και αντικαθιστά το wrapper της Omarchy.

Το `dsh` ανοίγει το browser UI του στο `127.0.0.1:3080`, με τον κατάλογο εκκίνησης ως προεπιλεγμένο χώρο εργασίας του. Το browser UI του δεν δέχεται αρχικό prompt, οπότε το `omarchy agent prompt` το ανοίγει με το prompt στο πρόχειρό σας για επικόλληση. Η Omarchy το ξεκινά με το preset δικαιωμάτων no-approval της DeepSeek. Το DeepSeek Harness ανεβάζει αρχεία καταγραφής συνεδριών στην DeepSeek όταν χρησιμοποιείτε το επίσημο API μοντέλων της· απενεργοποιήστε το στο _Settings > General > Upload Session Log_ στο browser UI του. Τα σχόλια που του στέλνετε ανεβαίνουν επίσης μαζί με τη συνεδρία, εκτός αν το ξεκινήσετε με `DSH_TELEMETRY_MODE=DISABLED`.

### Ο προεπιλεγμένος πράκτορας

Επιλέξτε τον προεπιλεγμένο πράκτορά σας με `omarchy default agent <name>` ή στο _Agent > Harness_ στο Omarchy Menu (`Super + Space`). Αν ο πράκτορας δεν είναι εγκατεστημένος ακόμη, η επιλογή του τον εγκαθιστά πρώτα, και αποκτά επίσης δικό του εκκινητή στον app launcher, δίπλα στο Agent. Μια νέα Omarchy θα σας καλέσει να κάνετε αυτή την επιλογή με μια εφάπαξ ειδοποίηση.

Η επιλογή του Claude επιχειρεί επίσης να ρυθμίσει την επέκταση του browser του για Chromium, Chrome, Brave, Brave Origin και Edge. Η ρύθμιση της επέκτασης ισχύει για όλους τους χρήστες και μπορεί να ζητήσει τον κωδικό πρόσβασης του συστήματός σας· η ακύρωση ή μια αποτυχημένη εγκατάσταση επέκτασης εξακολουθεί να επιλέγει και να εκκινεί τον Claude. Επανεκκινήστε τον browser σας, ενεργοποιήστε την επέκταση αν σας ζητηθεί και συνδεθείτε στον Claude για να ολοκληρώσετε τη σύνδεσή της. Εκτελέστε `/chrome` στον Claude για να ελέγξετε τη σύνδεση. Τα Firefox και Zen δεν υποστηρίζουν αυτή την επέκταση. Αν ο Claude ήταν ήδη ο προεπιλεγμένος σας πριν προστεθεί αυτή η ρύθμιση, επιλέξτε τον ξανά για να εγκατασταθεί η επέκταση.

Μόλις επιλέξετε, το `Super + Shift + Ctrl + A` εκκινεί τον προεπιλεγμένο πράκτορα σε ένα αποκλειστικό παράθυρο τερματικού (ή εμφανίζει τον επιλογέα αν δεν έχετε επιλέξει ακόμη). Μπορείτε επίσης να τον εκκινήσετε κατευθείαν σε μια εργασία με `omarchy agent prompt "Review this project"`. Οι Freebuff και DeepSeek Harness δεν δέχονται αρχικό prompt, οπότε ανοίγουν με το prompt στο πρόχειρό σας για επικόλληση αντ' αυτού. Οι πράκτορες που εκκινούνται με αυτόν τον τρόπο εκτελούνται χωρίς επίβλεψη στις αντίστοιχες λειτουργίες don't-stop-to-ask τους, οπότε να είστε έτοιμοι να κάνουν πράγματι πράγματα! Το MiniMax Code δεν έχει τέτοια λειτουργία για τις διαδραστικές συνεδρίες του, οπότε ζητά δικαιώματα ως συνήθως. Και επειδή οι πράκτορες αρνούνται να θυμούνται την εμπιστοσύνη για τον αρχικό κατάλογό σας, οι εκκινήσεις από το `$HOME` ξεκινούν στο `~/Work` αντ' αυτού.

Υπάρχουν και συντομεύσεις τερματικού: το `a` εκτελεί τον προεπιλεγμένο πράκτορα ενσωματωμένο στο τρέχον τερματικό, ενώ τα `c`, `cx` και `cy` ξεκινούν τα OpenCode, Claude Code και Codex απευθείας (ξανά στις λειτουργίες αυτόματης έγκρισής τους). Οι αλλαγές θέματος συγχρονίζονται και στους πράκτορες: τα Claude Code, Pi, OpenCode και Hermes (αφού το έχει εγκαταστήσει η Omarchy) ακολουθούν όλα όταν αλλάζετε το θέμα της Omarchy.

### Οι οδηγίες του πράκτορά σας

Οι προσωπικοί κανόνες για κάθε πράκτορα πηγαίνουν στο `~/.agents/AGENTS.md`, δίπλα στις κοινόχρηστες δεξιότητες στο `~/.agents/skills`. Ανοίξτε το στο _Agent > Instructions_, το οποίο το συνδέει επίσης σε κάθε harness που διατηρεί το δικό του καθολικό αρχείο: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, το `~/.copilot/copilot-instructions.md` του Copilot και ούτω καθεξής. Τα Crush και Amp διαβάζουν τον σύνδεσμο `~/.config/AGENTS.md`, ενώ τα omp, Kimi και DeepSeek Harness διαβάζουν απευθείας το `~/.agents/AGENTS.md`. Η επιλογή προεπιλεγμένου πράκτορα το συνδέει επίσης. Ένα αρχείο οδηγιών που είχατε ήδη γίνεται το κοινόχρηστο αν δεν υπήρχε ακόμη κανένα· διαφορετικά διατηρείται δίπλα στον σύνδεσμο ως `.bak`. Εκτελέστε `omarchy agent instructions` για να επανασυνδέσετε μετά την εγκατάσταση άλλου πράκτορα.

### Το πάνελ πρακτόρων

Η κορυφαία γραμμή έχει ένα εικονίδιο πρακτόρων. Πριν ρυθμίσετε έναν πράκτορα, το πάνελ του σας καθοδηγεί στη σύνδεση σε Claude, Codex ή Grok, και ο πρώτος γίνεται ο προεπιλεγμένος πράκτοράς σας. Μετά από αυτό, το πάνελ βάζει κάθε συνδρομή σε μία σελίδα: κάθε πράκτορα και λογαριασμό με το πλάνο του, έναν μετρητή για καθένα από τα όρια συνεδρίας 5 ωρών και εβδομαδιαία όριά του με τον χρόνο μέχρι να μηδενιστεί (τοποθετήστε τον δείκτη για το ακριβές ποσοστό), ή το υπόλοιπο προπληρωμένο υπόλοιπο, κάτω από μια γραμμή που εναλλάσσεται ανάμεσα σε όσα έχετε χρησιμοποιήσει σε όλους τους, όπως tokens αυτή την εβδομάδα και το μοντέλο που χρησιμοποιείτε περισσότερο. Στο _Make something cool_ προσφέρει αρχικά prompts για ένα νέο θέμα, plugin, εφαρμογή ή παιχνίδι που αναθέτουν την εργασία στον προεπιλεγμένο πράκτορά σας. Οι εφαρμογές κατασκευάζονται με τον τρόπο που κατασκευάζονται τα ίδια τα Hype, Monologue και Omacut της Omarchy, σε C++ και Qt Quick, ακολουθώντας τη δεξιότητα πράκτορα omarchy-make-app, και ο compiler και τα κομμάτια Qt που χρειάζονται έρχονται εγκατεστημένα. Τα παιχνίδια είναι μία μόνο σελίδα three.js στο `~/Games/vibes`, ακολουθώντας τη δεξιότητα πράκτορα omarchy-make-game, και όλα ανοίγουν από έναν εκκινητή Game Vibes στο τρέχον θέμα· φορτώνουν το three.js από τον ιστό, οπότε χρειάζονται σύνδεση για να ξεκινήσουν. Τα Claude Code, Codex, Grok, Kimi, Cursor και η παροχή Grok Bot του, GitHub Copilot, Muse, Antigravity και Devin καλύπτονται εξαρχής με τα όριά τους, το Kimchi με το πλάνο του, τις προπληρωμένες μονάδες και τους προϋπολογισμούς δαπανών του, και τα Hermes, Mistral Vibe και Qwen Code εμφανίζουν τις συνεδρίες και τα tokens τους αφού τα χρησιμοποιήσετε. Τα πλάνα παρόχων και τα κλειδιά που χρησιμοποιείτε μέσω pi, omp ή opencode εμφανίζονται επίσης: τα OpenCode Zen και Go, το Z.ai GLM Coding Plan, το Ollama Cloud, το MiniMax Token Plan και το Synthetic με τα όριά τους· τα OpenRouter και DeepSeek με τα προπληρωμένα υπόλοιπά τους· το Fireworks με τις δαπάνες του τις τελευταίες 30 ημέρες. Τα tokens από μοντέλα που εκτελείτε στο δικό σας υλικό μετρούν επίσης στα σύνολα· τα ίδια τα μοντέλα έχουν δικό τους πάνελ, που περιγράφεται στα [Τοπικά μοντέλα](#local-models). Κάθε πράκτορας μετριέται μία φορά, σε όποιον τον χρεώνει, όσα harnesses και αν χρησιμοποιείτε για να τον οδηγείτε.

Κάντε αριστερό κλικ στο εικονίδιο της γραμμής ή πατήστε `Super + Ctrl + X` για το πάνελ, δεξί κλικ για να εκκινήσετε τον προεπιλεγμένο πράκτορά σας και μεσαίο κλικ για ανανέωση. Τα αρχεία χρήσης πίσω από αυτό αναγεννώνται κάθε 15 λεπτά από το `omarchy agent usage update`, και το πάνελ μπορεί ακόμη και να συγχωνεύει χρήση από τα άλλα μηχανήματά σας μέσω ενός συγχρονισμένου φακέλου. Δείτε το README στο `$OMARCHY_PATH/shell/plugins/agents/` για τις πλήρεις ρυθμίσεις.

### Πολλές συνδρομές

Αν πληρώνετε για περισσότερα από ένα πλάνα Claude, Codex ή Grok — ένα προσωπικό Max και ένα εργασιακό, ας πούμε — η Omarchy μπορεί να τα κρατήσει όλα συνδεδεμένα και να μετακινείται ανάμεσά τους. Προσθέστε μια συνδρομή με το + στο πάνελ πρακτόρων, το οποίο σας καθοδηγεί εκεί ακριβώς, ή με `omarchy agent account add claude Work` (ή `codex`, ή `grok`). Εγκαθιστά το CLI αν λείπει. Ο πρώτος λογαριασμός για έναν πάροχο συνδέεται μέσω του κανονικού σας browser, ακριβώς εκεί που πάντα κοιτά το CLI. Κάθε επόμενος συνδέεται μέσω ενός ιδιωτικού παραθύρου, οπότε ο λογαριασμός στον οποίο ο browser σας είναι ήδη συνδεδεμένος δεν επιλέγεται κατά λάθος· συνδεθείτε εκεί ως ο λογαριασμός που προσθέτετε, και κλείστε πρώτα οποιοδήποτε ιδιωτικό παράθυρο είχατε ήδη ανοιχτό. Μην αποσυνδέεστε ποτέ από το CLI για να το κάνετε αυτό: η αποσύνδεση ανακαλεί την αποθηκευμένη σύνδεση, και αυτός ο λογαριασμός θα έπρεπε να προστεθεί ξανά.

Για να αντιγράψετε τις συνδέσεις συνδρομών σας σε άλλο μηχάνημα Omarchy μέσω SSH, εκτελέστε `omarchy agent account copy user@laptop`. Ο αποστολέας παρέχει έναν προσωρινό παραλήπτη όταν ο προορισμός δεν έχει εγκατεστημένο έναν, οπότε παλαιότερα μηχανήματα Omarchy μπορούν να λάβουν λογαριασμούς χωρίς ενημέρωση. Οι εγκατεστημένοι παραλήπτες έχουν προτεραιότητα. Αυτό αντιγράφει όλες τις συνδρομές Claude, Codex και Grok· προσθέστε ονόματα παρόχων για να τις επιλέξετε, όπως στο `omarchy agent account copy laptop claude`. Τα ονόματα λογαριασμών και τα ID εντολών ταιριάζουν με την πηγή, συμπεριλαμβανομένων λογαριασμών που υπάρχουν ήδη στον προορισμό. Άσχετοι λογαριασμοί προορισμού λαμβάνουν ένα αριθμητικό επίθημα αν τα ονόματά τους συγκρούονται, και οι ρυθμίσεις, οι δεξιότητες, τα plugins και το ιστορικό συνομιλιών παραμένουν τοπικά σε κάθε μηχάνημα.

Τα υπάρχοντα διαπιστευτήρια προορισμού διατηρούνται. Ένας λογαριασμός πηγής που είναι ήδη συνδεδεμένος εκεί έχει το όνομά του συγχρονισμένο χωρίς να αντικατασταθούν τα διαπιστευτήριά του· οι άλλοι λογαριασμοί προστίθενται δίπλα του. Για να αντικαταστήσετε αποθηκευμένα διαπιστευτήρια για λογαριασμούς που ταιριάζουν, χρησιμοποιήστε `omarchy agent account copy --replace laptop claude` αφού κλείσετε τις συνεδρίες αυτού του λογαριασμού στον προορισμό. Ένας νέος προορισμός λαμβάνει επίσης τον ενεργό λογαριασμό και τις προτιμήσεις εναλλαγής της πηγής· ένας καθιερωμένος προορισμός διατηρεί τις δικές του.

Τα διαπιστευτήρια ταξιδεύουν μέσω SSH και αποθηκεύονται σε ιδιωτικά αρχεία στον προορισμό, οπότε αντιγράφετε μόνο σε μηχανήματα που εμπιστεύεστε. Αυτή είναι μια εφάπαξ αντιγραφή, όχι συνεχιζόμενος συγχρονισμός. Τα refresh tokens του Codex μπορούν να εναλλαγούν από άλλο μηχάνημα, αφήνοντας μια αντιγραμμένη σύνδεση να χρειάζεται ανανέωση· οι ξεχωριστές συνδέσεις παραμένουν η πιο αξιόπιστη επιλογή για ταυτόχρονη χρήση σε πολλά μηχανήματα. Δείτε την [καθοδήγηση πιστοποίησης λογαριασμού του Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Ένας λογαριασμός ανά πάροχο είναι ενεργός, και κάθε νέα συνεδρία ξεκινά ως αυτός: `cx`, `cy`, ένα απλό `claude`, `codex` ή `grok`, οτιδήποτε εκκινείται μέσω `omarchy agent`, και scripts ή επεξεργαστές που βρίσκουν το CLI στο `PATH`. Κάντε εναλλαγή με `omarchy agent account use work` (και πίσω με `omarchy agent account use main`), ή στο πάνελ πατώντας τον αριθμό ενός λογαριασμού και στη συνέχεια `Enter` (ή κάνοντας κλικ στο κουμπί Use του). Οι συνεδρίες Claude που εκτελούνται εναλλάσσονται επίσης, από το επόμενο μήνυμά τους: κάθε συνεδρία Claude εκτελείται στο `~/.claude`, το οποίο διατηρεί πάντα τη σύνδεση του ενεργού λογαριασμού. Μια συνεδρία Claude που ξεκίνησε στον δικό της φάκελο ενός λογαριασμού από μια παλαιότερη Omarchy διατηρεί αυτή τη σύνδεση μέχρι να κλείσει, οπότε η εναλλαγή ονομάζει αυτές τις συνεδρίες και ολοκληρώνεται από μόνη της μόλις εξαφανιστούν. Οι συνεδρίες Codex και Grok που εκτελούνται παραμένουν στον λογαριασμό με τον οποίο ξεκίνησαν. Το ιστορικό συνομιλιών, οι ρυθμίσεις, οι δεξιότητες και τα plugins είναι κοινόχρηστα ανάμεσα στους λογαριασμούς, οπότε το `claude --continue` στον ίδιο φάκελο συνεχίζει από εκεί που σταματήσατε στον νέο λογαριασμό.

Με περισσότερους από έναν λογαριασμούς, το πάνελ εμφανίζει τα όρια κάθε λογαριασμού δίπλα δίπλα, με τον ενεργό σημειωμένο. Από προεπιλογή η Omarchy σας ειδοποιεί όταν ο ενεργός λογαριασμός ξεπεράσει το 95% ενός ορίου, και κάνοντας κλικ στην ειδοποίηση εναλλάσσεστε στον λογαριασμό με το περισσότερο περιθώριο. Τοποθετήστε τον δείκτη πάνω στη γραμμή ενός λογαριασμού στο πάνελ και κάντε κλικ στο Autoswitch που εμφανίζεται δίπλα στο Use (ή πατήστε `m`), ή εκτελέστε `omarchy agent account mode auto`, για να γίνεται η εναλλαγή από μόνη της· όσο είναι ενεργό, το Autoswitch παίρνει τη θέση του Use, και κάνοντας κλικ ξανά επιστρέφει στην ειδοποίηση. Προσθέστε έναν αριθμό για να αλλάξετε το όριο, όπως στο `omarchy agent account mode auto 90`. Αν κάθε λογαριασμός είναι πάνω από το όριο, θα το ακούσετε μία φορά, μαζί με το ποιος λογαριασμός ελευθερώνεται πρώτος. Ενώ ένας ενεργός λογαριασμός βρίσκεται εντός 15 μονάδων από το όριό του (80% στην προεπιλογή), τα όριά του ελέγχονται κάθε τρία λεπτά αντί για κάθε 15.

Το `omarchy agent account list` εμφανίζει κάθε λογαριασμό και τα τελευταία όριά του, το `omarchy agent account remove work` ξεχνά έναν, και το `omarchy agent account rename primary Hey` μετονομάζει έναν (ή κάντε κλικ στο όνομα ενός λογαριασμού στο πάνελ). Αυτές οι εντολές λειτουργούν στους λογαριασμούς του προεπιλεγμένου πράκτορά σας· για να φτάσετε στον άλλον πάροχο, ονομάστε τον πρώτα, όπως στο `omarchy agent account use codex side`. Η σύνδεση που είχατε ήδη στο `~/.claude` ή στο `~/.codex` είναι ο λογαριασμός _Main_. Του Codex παραμένει εκεί που είναι· του Claude περιμένει σε δικό του φάκελο ενώ ένας άλλος λογαριασμός είναι ενεργός. Ένας λογαριασμός που αφήνεται αχρησιμοποίητος για περισσότερες από περίπου οκτώ ώρες μπορεί να εμφανίζει _Sign-in required_· κάντε κλικ σε αυτόν για να συνδεθείτε ξανά σε αυτόν τον λογαριασμό ακριβώς στο πάνελ, ή μεταβείτε σε αυτόν και ξεκινήστε μια συνεδρία, η οποία ανανεώνει τη σύνδεση από μόνη της. Οι MCP servers που προσθέτετε με `claude mcp add` φτάνουν σε κάθε λογαριασμό Claude, αφού όλοι εκτελούνται στο `~/.claude`· για Codex και Grok, οι servers που είχατε όταν προστέθηκε ένας λογαριασμός έρχονται μαζί του σε αυτόν, αλλά οι μεταγενέστεροι φτάνουν μόνο στον λογαριασμό στον οποίο τους προσθέσατε. Το Claude Desktop διατηρεί δική του σύνδεση, και τα εργαλεία Codex ή Grok που ρυθμίζονται με απόλυτη διαδρομή προς ένα δυαδικό CLI δεν ακολουθούν την εναλλαγή. Ένα ρητό `CLAUDE_CONFIG_DIR`, `CODEX_HOME` ή `GROK_HOME` έχει προτεραιότητα έναντι του επιλεγμένου λογαριασμού.

### Διάγνωση κρασαρισμάτων

Η Omarchy παρακολουθεί το systemd-coredump για κρασαρίσματα διεργασιών. Μόλις επιλέξετε έναν προεπιλεγμένο πράκτορα, οποιοδήποτε πρόγραμμά σας που κάνει dump core φέρνει μια ειδοποίηση "Process crashed" — κάντε κλικ σε αυτήν, και το κρασάρισμα παραδίδεται στον προεπιλεγμένο πράκτορά σας μαζί με τη δεξιότητα omarchy-diagnose-crash της Omarchy, η οποία καθοδηγεί τον πράκτορα στη διαπίστωση των γεγονότων από το core dump και στην απόφαση αν το κρασάρισμα αξίζει να αναφερθεί upstream. Μπορείτε επίσης να το εκτελέσετε με το χέρι έναντι οποιουδήποτε PID από το `coredumpctl list` με `omarchy agent crash <pid>`.

Η παρακολούθηση είναι ενεργή από προεπιλογή. Απενεργοποιήστε την στο _Trigger > Toggle > Crash Capture Off_ (ή με `omarchy toggle crash-capture`) και οι ειδοποιήσεις σταματούν· το `omarchy agent crash <pid>` εξακολουθεί να λειτουργεί με το χέρι.

Τα κρασαρίσματα μπορούν επίσης να σιγήσουν ένα πρόγραμμα τη φορά, πράγμα που σας προσφέρει η διάγνωση στο τέλος. Το `omarchy crash mute hyprland` σταματά τις ειδοποιήσεις μόνο για αυτό το πρόγραμμα, το `omarchy crash mute hyprland off` τις επαναφέρει, και το `omarchy crash mute` από μόνο του παραθέτει όσα έχετε σιγήσει. Δέχεται τη διαδρομή του δυαδικού εξίσου ευχαρίστως με το όνομά του, οπότε το `omarchy crash mute /usr/bin/hyprland` κάνει το ίδιο πράγμα. Βάλτε σε εισαγωγικά ένα όνομα με κενό, όπως στο `omarchy crash mute 'Some App'`. Όλα τα άλλα εξακολουθούν να ειδοποιούν, και το σιγημένο πρόγραμμα εξακολουθεί να κρασάρει — αυτό κρύβει την υπενθύμιση, δεν διορθώνει τίποτα.

### Εφαρμογές desktop

Το μενού _Install > AI_ φέρει επίσης μερικές γραφικές εφαρμογές AI: Amp Desktop, Antigravity Desktop, την εφαρμογή desktop ChatGPT, την εφαρμογή desktop Claude (το Linux beta της Anthropic, με καρτέλες Chat, Cowork και Claude Code), Grok Bot για συνομιλία με τα μοντέλα της xAI, Herdr Desktop, Hermes Desktop, OpenClaw, την εφαρμογή desktop Perplexity και T3 Code. Το Grok Bot είναι η εφαρμογή συνομιλίας desktop. Ο πράκτορας προγραμματισμού είναι η εντολή `grok`.

Το Hermes Desktop είναι αυτό που πρέπει να γνωρίζετε, επειδή ένα μηχάνημα έχει ένα Hermes, και είναι της εφαρμογής: το Hermes εγκαθίσταται πάντα μόνο μέσω της εφαρμογής, και η εντολή `hermes` που εκτελεί ο προεπιλεγμένος πράκτορας είναι της εφαρμογής. Η επιλογή του Hermes ως προεπιλεγμένου πράκτορα εγκαθιστά το ίδιο πράγμα που εγκαθιστά η καταχώριση _Install > AI_: το πακέτο, και ένα runtime Hermes στο `~/.hermes` που ρυθμίζεται από τον δικό του installer του Hermes, κάτι που παίρνει μερικά λεπτά την πρώτη φορά. Αυτό το runtime είναι το ένα Hermes που χρησιμοποιούν η εντολή τερματικού `hermes`, ο προεπιλεγμένος πράκτορας και η εφαρμογή, και ενημερώνεται μόνο του με `hermes update` αντί να περιμένει μια κυκλοφορία της Omarchy. Η εγκατάστασή του παραδίδει επίσης στο Hermes το θέμα της Omarchy ως skin με όνομα `omarchy`, το οποίο ακολουθεί κάθε επιφάνεια Hermes καθώς αλλάζετε θέματα· επιλέξτε άλλο στις ρυθμίσεις Appearance του Hermes ή με `/skin` αν προτιμάτε να μην το κάνει, και η Omarchy αφήνει αυτή την επιλογή ήσυχη. Η αφαίρεση της εφαρμογής στο _Remove > AI_ κλείνει πρώτα το Hermes, συμπεριλαμβανομένης της πύλης, παίρνει αυτό το runtime μαζί της, και διατηρεί τις συνομιλίες, τις μνήμες σας και τις δεξιότητες που έγραψε το Hermes για τον εαυτό του εκτός αν του πείτε διαφορετικά: ρωτά, με προεπιλογή το όχι, αν αυτά τα δεδομένα και οι ρυθμίσεις σύνδεσής σας πρέπει να φύγουν επίσης.

Η εμπειρία desktop του OpenClaw είναι το Control UI του, το οποίο ανοίγει ως web εφαρμογή υποστηριζόμενη από τη δική του τοπική πύλη. Το OpenClaw ζει στο `~/.openclaw` και ενημερώνεται μόνο του: χρησιμοποιήστε το κουμπί "Update Gateway" του Control UI ή εκτελέστε `openclaw update`, και η πύλη επανεκκινείται στη νέα έκδοση. Η Omarchy επιλέγει μόνο την κυκλοφορία από την οποία ξεκινά μια νέα εγκατάσταση. Το OpenClaw μπορεί επίσης να είναι ο προεπιλεγμένος πράκτοράς σας: η επιλογή του στο _Agent > Harness_ ρυθμίζει αυτό το ίδιο αντίγραφο στο `~/.openclaw`, και ο πράκτορας ανοίγει το terminal UI του OpenClaw συνδεδεμένο στην πύλη του. Η αφαίρεση του OpenClaw στο _Remove > AI_ παίρνει την υπηρεσία πύλης και την εφαρμογή μαζί της και στη συνέχεια ρωτά αν πρέπει να φύγει και το `~/.openclaw`, αφού αυτό διατηρεί τις συνομιλίες και τα διαπιστευτήριά σας μαζί με το ίδιο το OpenClaw και τα plugin runtimes που κατεβάζει· η προεπιλογή το διατηρεί, και η εγκατάσταση του OpenClaw ξανά το ξαναπαίρνει.

Το Herdr Desktop είναι η εφαρμογή desktop [Herdr](https://herdr.dev): χώροι, καρτέλες και panes τερματικών και πρακτόρων προγραμματισμού που συνεχίζουν να εκτελούνται στον πυρήνα του όταν κλείνετε το παράθυρο. Προέρχεται από τον δικό του installer του Herdr αντί για πακέτο, οπότε ζει στο `~/.local/share/herdr-app`, φέρνει τον πυρήνα του στο `~/.local/bin/herdr-core` όταν δεν έχετε ήδη έναν, και ενημερώνει και τα δύο μόνα τους. Βρίσκεται δίπλα στην εντολή `herdr` που διαθέτει η Omarchy στο `Super + Ctrl + Return` αντί να την αντικαθιστά, και παίρνει τα άμεσα πλήκτρα αυτής της εντολής: τα `Alt + Return` και `Alt + Shift + Return` χωρίζουν ένα pane προς τα κάτω ή δεξιά, το `Alt + Escape` το κλείνει, το `Ctrl + Alt + Arrow` μετακινείται ανάμεσα στα panes, τα `Alt + 1..9` και `Alt + Left/Right` επιλέγουν μια καρτέλα, και τα `Alt + Up/Down` μετακινούνται ανάμεσα στους χώρους. Το `Ctrl + 1..9` επιλέγει έναν χώρο και το `Alt + Shift + Up/Down` περνά μέσα από πράκτορες. Τα πλήκτρα προθέματος `Ctrl + Space` παραμένουν μόνο για τερματικό, αφού η εφαρμογή δεν μπορεί να κρατήσει ένα απλό πλήκτρο Ctrl για μια ακολουθία. Η Omarchy τα γράφει στο `~/.config/herdr-app/keys.json`, και το `omarchy-refresh-herdr-app` τα επαναφέρει. Η εγκατάστασή του επιλέγει το θέμα Omarchy του Herdr, το οποίο ακολουθεί το θέμα Omarchy σας από τότε και μετά. Το Herdr διατηρεί ένα θέμα για τη φωτεινή λειτουργία και ένα για τη σκοτεινή, οπότε αφού εναλλαγείτε ανάμεσα σε ένα σκοτεινό και ένα φωτεινό θέμα Omarchy, επιλέξτε Omarchy στον επιλογέα θεμάτων του Herdr άλλη μία φορά για την άλλη λειτουργία.

Το T3 Code εκτελείται από την επίσημη κυκλοφορία AppImage του στο `~/.local/share/t3code` αντί από πακέτο, οπότε ενημερώνεται μόνο του. Η εγκατάστασή του ρωτά αν θα ξεκινήσει στο κανάλι Stable ή Nightly· αλλάξτε αργότερα στις ρυθμίσεις του T3 Code. Τα νήματά σας και οι ρυθμίσεις σας ζουν στο `~/.t3`, και η αφαίρεση του T3 Code στο _Remove > AI_ τα παίρνει μαζί της.

### Τοπικά μοντέλα

Εκτελέστε ένα ανοιχτό μοντέλο στο δικό σας μηχάνημα για τους πράκτορες προγραμματισμού σας. Τα prompts και ο κώδικάς σας παραμένουν στο μηχάνημα· τίποτα που στέλνεται στο μοντέλο δεν φεύγει από αυτό. Ξεκινήστε με:

```bash
omarchy models use best text
```

Αυτό ρυθμίζει το καλύτερο μοντέλο κειμένου για αυτό το μηχάνημα, το είδος που χρησιμοποιούν οι πράκτορές σας. Τα μοντέλα εικόνας, βίντεο και μουσικής έχουν δικό τους καλύτερο: `omarchy models use best image`, `video` ή `music`. Εκτελέστε `omarchy models use best` για να δείτε την επιλογή κάθε είδους για αυτό το μηχάνημα.

Ή ανοίξτε το πάνελ τοπικών μοντέλων από το εικονίδιο με σπινθήρες του στην κορυφαία γραμμή, δίπλα στο εικονίδιο πρακτόρων, ή με Super + Ctrl + Alt + X, και επιλέξτε +. Το εικονίδιο εμφανίζεται όταν ένα μοντέλο ταιριάζει σε αυτό το μηχάνημα. Το Podman, το οποίο εκτελεί τα μοντέλα, έρχεται με την Omarchy, όπως και το container toolkit της NVIDIA σε μηχάνημα NVIDIA, το οποίο τους δίνει τη GPU· αν λείπει κάποιο από τα δύο, η πρώτη ρύθμιση το εγκαθιστά. Η Omarchy στη συνέχεια επιλέγει το συνιστώμενο μοντέλο για αυτό το μηχάνημα, το κατεβάζει και το ξεκινά. Περιμένετε μια λήψη δεκάδων GB και το μεγαλύτερο μέρος της μνήμης του μηχανήματος να χρησιμοποιείται ενώ εκτελείται το μοντέλο: το Flash Next χρησιμοποιεί περίπου 100 GiB με το πλήρες context 256K του. Αν άλλα μοντέλα κρατούν τη μνήμη που χρειάζεται, ρυθμίζεται σταματημένο, έτοιμο να ξεκινήσει μόλις σταματήσετε ένα. Το μοντέλο σταματά στην αποσύνδεση· σταματήστε το οι ίδιοι όταν χρειάζεστε τη μνήμη για κάτι άλλο.

Το `omarchy models list` εμφανίζει τις επιλογές και εξηγεί γιατί μερικές δεν ταιριάζουν. Για να ρυθμίσετε άλλο ένα, εκτελέστε `omarchy models use <recipe>`. Σήμερα, τα `qwen3.8-flash-next-gufo` και `qwen3.8-27b-gufo` είναι διαθέσιμα για μηχανήματα Strix Halo 128 GB· το 27B παίρνει περίπου 40 GiB, οπότε αφήνει χώρο για άλλη δουλειά. Σε ένα laptop 64 GB με Arc B390 της Intel, το `qwen3.6-35b-a3b-llamacpp` εκτελείται σε περίπου 30 GiB. Νέες συνταγές και συστάσεις φτάνουν με το `omarchy update`, μέσω του πακέτου.

Κάθε μοντέλο που ρυθμίζετε αποκτά δική του γραμμή στο πάνελ τοπικών μοντέλων: play για να το ξεκινήσετε, pause για να το σταματήσετε και να ελευθερώσετε τη μνήμη του, και το κουμπί τερματικού για να ανοίξετε τον πράκτορά σας σε αυτό. Πάνω πάνω, μια γραμμή δείχνει πώς η μνήμη του μηχανήματος χωρίζεται ανάμεσα στην ίδια την Omarchy (το σύστημα και οι εφαρμογές σας), κάθε μοντέλο που εκτελείται, και ό,τι είναι ελεύθερο. Δείξτε σε ένα σταματημένο μοντέλο και η γραμμή δείχνει αν χωρά, ή πόσο του λείπει. Πολλά μπορούν να εκτελούνται ταυτόχρονα όταν χωρούν μαζί στη μνήμη· αν ένα δεν χωρά, η Omarchy λέει ποιο μοντέλο που εκτελείται να σταματήσετε. Σύρετε γραμμές από το λογότυπό τους για να τις αναδιατάξετε, και πατήστε Delete σε μια επιλεγμένη γραμμή για να αφαιρέσετε ένα μοντέλο και τη λήψη του.

Κάθε μοντέλο προγραμματισμού που ρυθμίζετε αποκτά επίσης δική του καταχώριση στον app launcher, με το όνομα του μοντέλου και το λογότυπο του κατασκευαστή του, με τον τρόπο που η σύνδεση σε Claude, Codex ή Grok προσθέτει μία. Ανοίγει τον πράκτορά σας σε αυτό το μοντέλο, και ξεκινά πρώτα το μοντέλο αν δεν εκτελείται: το τερματικό το δείχνει να φορτώνει και παραδίδει στον πράκτορα μόλις είναι έτοιμο. Η αφαίρεση ενός μοντέλου αφαιρεί την καταχώρισή του.

Δεν είναι κάθε μοντέλο για προγραμματισμό. Τα μοντέλα εικόνας, βίντεο και μουσικής ανοίγουν στο Fantasi αντ' αυτού, την εφαρμογή της Omarchy για τη δημιουργία εικόνων, βίντεο και μουσικής με ένα μοντέλο που εκτελείται σε αυτό το μηχάνημα, επιλεγμένο εκεί ή από τη γραμμή τους στο πάνελ τοπικών μοντέλων.

Ένα μοντέλο συνεχίζει να εκτελείται ακριβώς όπως ρυθμίστηκε, οπότε μια ενημέρωση Omarchy δεν επανεκκινεί ποτέ ένα κάτω από τους πράκτορές σας. Όταν η Omarchy έχει νεότερο runtime ή νεότερα βάρη για ένα μοντέλο που έχετε ρυθμίσει, η γραμμή του εμφανίζει ένα κουμπί ενημέρωσης: πατήστε το και το μοντέλο ρυθμίζεται ξανά στο παρασκήνιο, κατεβάζοντας μόνο ό,τι άλλαξε, και επανεκκινείται στη νέα έκδοση. Ένα μοντέλο που ήταν σταματημένο παραμένει σταματημένο. Το `omarchy models update` κάνει το ίδιο για κάθε μοντέλο από τερματικό.

Από τη γραμμή εντολών, τα `omarchy models start <recipe>` και `omarchy models stop <recipe>` κάνουν το ίδιο, το `omarchy models status` εμφανίζει κάθε μοντέλο, και το `omarchy agent --local` ανοίγει τον προεπιλεγμένο πράκτορά σας στο τελευταίο μοντέλο που ξεκινήσατε. Τα pi, OpenCode και Qwen Code μπορούν να χρησιμοποιήσουν ένα· με οποιαδήποτε άλλη προεπιλογή ανοίγει στο pi, ή στο OpenCode αν δεν έχετε pi. Το pi παραθέτει επίσης κάθε μοντέλο που έχετε ρυθμίσει, και εκείνα σε μηχανήματα με τα οποία έχετε συζευχθεί, στον δικό του επιλογέα μοντέλων, οπότε το απλό `pi` τα φτάνει επίσης. Οποιοσδήποτε client συμβατός με OpenAI μπορεί να συνδεθεί επίσης: το `status` εμφανίζει τη διεύθυνση κάθε μοντέλου (η πρώτη είναι `http://127.0.0.1:11435/v1`), το όνομα της συνταγής είναι το μοντέλο, και το κλειδί βρίσκεται στο `~/.config/omarchy/agent-local/key`.

Το `omarchy models remove <recipe>` διαγράφει ένα μοντέλο και τις λήψεις που κανένα άλλο μοντέλο δεν χρησιμοποιεί.

Τα runtimes τρίτων επισημαίνονται με τον εκδότη τους. Η Omarchy εκτελεί κάθε μοντέλο χωρίς πρόσβαση δικτύου.

### Τοπικά LLMs

Η Omarchy συνιστά δύο τρόπους εκτέλεσης τοπικών μοντέλων LLM: LM Studio και Ollama. Το LM Studio παρέχει ένα GUI περιβάλλον για την εύρεση μοντέλων ανοιχτών βαρών, την εγκατάστασή τους και την εκτέλεσή τους. Είναι ένας εξαιρετικός τρόπος να ξεκινήσετε εύκολα. Το Ollama προσφέρει ένα CLI για να κάνετε το ίδιο με παρόμοιο τρόπο. Αλλά αν είστε νέοι στα τοπικά μοντέλα, θα ξεκινούσα με το LM Studio. Μπορείτε να εγκαταστήσετε οποιοδήποτε από τα δύο στο _Install > AI_ στο Omarchy Menu.

### Οι δεξιότητες της Omarchy

Οι δεξιότητες πρακτόρων βοηθούν την AI να χρησιμοποιεί συγκεκριμένα εργαλεία με συγκεκριμένο τρόπο, και η Omarchy διαθέτει επτά από αυτές. Η δεξιότητα omarchy καλύπτει την προσαρμογή του συστήματος, όπως την τροποποίηση του config Hyprland σας ή την προσαρμογή της γραμμής. Οι omarchy-make-theme, omarchy-make-plugin, omarchy-make-app και omarchy-make-game καλύπτουν τη δημιουργία κάτι νέου, η omarchy-contribute καλύπτει την αναφορά ενός bug ή την αποστολή μιας διόρθωσης upstream, και η omarchy-diagnose-crash δουλεύει μέσα από το core dump ενός κρασαρίσματος. Συνδέονται με συμβολικούς συνδέσμους στους καταλόγους δεξιοτήτων για Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` και κάθε `~/.hermes/profiles/*/skills`), και τη γενική τοποθεσία `~/.agents/skills`, οπότε τα περισσότερα harnesses τις εντοπίζουν αυτόματα. Ένας δικός σας φάκελος δεξιότητας με το ίδιο όνομα έχει προτεραιότητα.

Αλλά πρέπει να αντιμετωπίζετε αυτές τις δεξιότητες ως πειραματικές. Διαφορετικά μοντέλα θα τη χρησιμοποιούν με διαφορετικό αποτέλεσμα. Είναι καλύτερο να εκτελείτε πρώτα σε λειτουργία σχεδιασμού, ώστε να έχετε μια ιδέα για το τι θα ήθελε να αλλάξει ο πράκτορας. Και στη συνέχεια να είστε έτοιμοι να αναιρέσετε αλλαγές ή ακόμη και να καλέσετε το `omarchy reinstall configs`, αν ο πράκτορας τα κάνει όλα μπάχαλο.
