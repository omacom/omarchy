# AI

Το Omarchy περιλαμβάνει προγράμματα εκκίνησης για τους παρακάτω πράκτορες προγραμματισμού, χωρίς να επιλέγει προεπιλογή για εσάς. Εκτελέστε μια εντολή για να εγκαταστήσετε το CLI της κατά την πρώτη χρήση και στη συνέχεια πραγματοποιήστε έλεγχο ταυτότητας όταν σας ζητηθεί. Οι Hermes και OpenClaw αποτελούν τις εξαιρέσεις: τίποτα δεν εγκαθίσταται γι' αυτούς μέσω του mise, και η επιλογή οποιουδήποτε από τους δύο εγκαθιστά το δικό του αυτοενημερούμενο αντίγραφο, όπως εξηγεί παρακάτω η ενότητα _Εφαρμογές επιφάνειας εργασίας_.

### Εγκατάσταση και ενημέρωση πρακτόρων

Με εξαίρεση τους Hermes και OpenClaw, αυτοί οι πράκτορες χρησιμοποιούν την lazy εγκατάσταση του mise: η πρώτη εκκίνηση εγκαθιστά το CLI και οι επόμενες εκκινήσεις το επαναχρησιμοποιούν. Το mise ελέγχει επίσης έναν εγκατεστημένο πράκτορα για νέα έκδοση το πολύ μία φορά κάθε τέσσερις ώρες, αμέσως πριν ξεκινήσει ή στο παρασκήνιο σε μια προτροπή shell. Αν αυτή η ενημέρωση αποτύχει ή είστε εκτός σύνδεσης, εκτελείται η εγκατεστημένη έκδοση. Η εντολή `omarchy update` ενημερώνει τους εγκατεστημένους πράκτορες μαζί με την υπόλοιπη Omarchy, και η `mup` ενημερώνει μόνο τα εργαλεία που διαχειρίζεται το mise.

Το πρόγραμμα ενημέρωσης του ίδιου του πράκτορα, όπως το `claude update`, το `codex update` ή ένα κουμπί ενημέρωσης σε μια εφαρμογή, δεν ενημερώνει την εγκατάσταση που διαχειρίζεται το mise. Η `codex update` αποτυγχάνει, και η `claude update` μπορεί να αναφέρει επιτυχία ενώ εγκαθιστά ένα ξεχωριστό αντίγραφο που το mise δεν παρακολουθεί. Αν προτιμάτε να χρησιμοποιείτε το εγγενές πρόγραμμα εγκατάστασης και ενημέρωσης ενός πράκτορα, προσθέστε το στο `disable_tools`. Δείτε τα [Προεγκατεστημένα εργαλεία CLI](18-development-tools.md#preinstalled-cli-tools).

Για να εγκαταστήσετε όλα τα διαμορφωμένα lazy εργαλεία πριν τα χρειαστείτε, εκτελέστε `mise install --include-lazy`. Αυτό περιλαμβάνει τα υπόλοιπα προεπιλεγμένα εργαλεία CLI της Omarchy καθώς και τους πράκτορες. Δείτε τα [Προεγκατεστημένα εργαλεία CLI](18-development-tools.md#preinstalled-cli-tools) για την εγκατάσταση ενός μεμονωμένου εργαλείου ή τη χρήση της δικής σας εγκατάστασης.

Το `grok` εγκαθίσταται μέσω του επίσημου πακέτου `grok` του mise, με τον ίδιο τρόπο όπως τα `claude` και `codex`. Εκτελέστε `grok` ή επιλέξτε το στην ενότητα _Πράκτορας > Harness_. Παραλείψτε το πρόγραμμα εγκατάστασης `curl | bash` στο x.ai. Αυτή η διαδρομή τοποθετεί ένα δεύτερο αντίγραφο στο `~/.grok/bin`, το προτάσσει στο `PATH` και αντικαθιστά το wrapper της Omarchy.

Το `dsh` ανοίγει το UI του προγράμματος περιήγησής του στο `127.0.0.1:3080`, με τον κατάλογο εκκίνησης ως προεπιλεγμένο χώρο εργασίας του. Το UI του προγράμματος περιήγησής του δεν δέχεται αρχική προτροπή, οπότε η εντολή `omarchy agent prompt` το ανοίγει με την προτροπή στο πρόχειρό σας για επικόλληση. Η Omarchy το ξεκινά με την προεπιλογή δικαιωμάτων χωρίς έγκριση της DeepSeek. Το DeepSeek Harness ανεβάζει αρχεία καταγραφής συνεδριών στην DeepSeek όταν χρησιμοποιείτε το επίσημο API μοντέλων της. Απενεργοποιήστε το στην ενότητα _Ρυθμίσεις > Γενικά > Αποστολή αρχείου καταγραφής συνεδρίας_ στο UI του προγράμματος περιήγησής του. Τα σχόλια που του στέλνετε ανεβαίνουν επίσης μαζί με τη συνεδρία, εκτός αν το ξεκινήσετε με `DSH_TELEMETRY_MODE=DISABLED`.

### Ο προεπιλεγμένος πράκτορας

Επιλέξτε τον προεπιλεγμένο πράκτορά σας με `omarchy default agent <name>` ή στην ενότητα _Πράκτορας > Harness_ στο Μενού Omarchy (`Super + Space`). Αν ο πράκτορας δεν είναι ακόμη εγκατεστημένος, η επιλογή του τον εγκαθιστά πρώτα, και αποκτά επίσης το δικό του πρόγραμμα εκκίνησης στο πρόγραμμα εκκίνησης εφαρμογών, δίπλα στον Πράκτορα. Μια νέα Omarchy θα σας προσκαλέσει να κάνετε αυτή την επιλογή με μια εφάπαξ ειδοποίηση.

Η επιλογή του Claude επιχειρεί επίσης να ρυθμίσει την επέκταση του προγράμματος περιήγησής του για Chromium, Chrome, Brave, Brave Origin και Edge. Η ρύθμιση της επέκτασης ισχύει για όλους τους χρήστες και ενδέχεται να ζητήσει τον κωδικό πρόσβασης του συστήματός σας. Η ακύρωση ή μια αποτυχημένη εγκατάσταση επέκτασης εξακολουθεί να επιλέγει και να εκκινεί το Claude. Επανεκκινήστε το πρόγραμμα περιήγησής σας, ενεργοποιήστε την επέκταση αν σας ζητηθεί και συνδεθείτε στο Claude για να ολοκληρώσετε τη σύνδεσή της. Εκτελέστε `/chrome` στο Claude για να ελέγξετε τη σύνδεση. Τα Firefox και Zen δεν υποστηρίζουν αυτή την επέκταση. Αν το Claude ήταν ήδη ο προεπιλεγμένος πράκτοράς σας πριν προστεθεί αυτή η ρύθμιση, επιλέξτε το ξανά για να εγκαταστήσετε την επέκταση.

Αφού επιλέξετε, ο συνδυασμός `Super + Shift + Ctrl + A` εκκινεί τον προεπιλεγμένο πράκτορα σε ένα αποκλειστικό παράθυρο τερματικού (ή εμφανίζει τον επιλογέα αν δεν έχετε επιλέξει ακόμη). Μπορείτε επίσης να τον εκκινήσετε απευθείας σε μια εργασία με `omarchy agent prompt "Review this project"`. Τα Freebuff και DeepSeek Harness δεν δέχονται αρχική προτροπή, οπότε ανοίγουν με την προτροπή στο πρόχειρό σας για επικόλληση. Οι πράκτορες που εκκινούνται με αυτόν τον τρόπο εκτελούνται χωρίς επίβλεψη στις αντίστοιχες λειτουργίες τους που δεν σταματούν για να ρωτήσουν, οπότε να είστε έτοιμοι να κάνουν πράγματα στ' αλήθεια! Το MiniMax Code δεν διαθέτει τέτοια λειτουργία για τις διαδραστικές συνεδρίες του, οπότε ζητά δικαιώματα ως συνήθως. Και επειδή οι πράκτορες αρνούνται να θυμούνται την εμπιστοσύνη για τον αρχικό κατάλογό σας, οι εκκινήσεις από το `$HOME` ξεκινούν στο `~/Work` αντ' αυτού.

Υπάρχουν και συντομεύσεις τερματικού: το `a` εκτελεί τον προεπιλεγμένο πράκτορα ενσωματωμένο στο τρέχον τερματικό, ενώ τα `c`, `cx` και `cy` ξεκινούν απευθείας τα OpenCode, Claude Code και Codex (και πάλι στις λειτουργίες αυτόματης έγκρισής τους). Οι αλλαγές θέματος συγχρονίζονται και στους πράκτορες: τα Claude Code, Pi, OpenCode και Hermes (αφού η Omarchy το εγκαταστήσει) ακολουθούν όλα όταν αλλάζετε το θέμα της Omarchy.

### Οι οδηγίες του πράκτορά σας

Οι προσωπικοί κανόνες για κάθε πράκτορα βρίσκονται στο `~/.agents/AGENTS.md`, δίπλα στις κοινόχρηστες δεξιότητες στο `~/.agents/skills`. Ανοίξτε το στην ενότητα _Πράκτορας > Οδηγίες_, η οποία το συνδέει επίσης σε κάθε harness που διατηρεί το δικό του καθολικό αρχείο: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, το `~/.copilot/copilot-instructions.md` του Copilot και ούτω καθεξής. Τα Crush και Amp διαβάζουν τον σύνδεσμο `~/.config/AGENTS.md`, ενώ τα omp, Kimi και DeepSeek Harness διαβάζουν απευθείας το `~/.agents/AGENTS.md`. Η επιλογή ενός προεπιλεγμένου πράκτορα το συνδέει επίσης. Ένα αρχείο οδηγιών που είχατε ήδη γίνεται το κοινόχρηστο αν δεν υπήρχε ακόμη κανένα. Διαφορετικά διατηρείται δίπλα στον σύνδεσμο ως `.bak`. Εκτελέστε `omarchy agent instructions` για να επανασυνδέσετε μετά την εγκατάσταση ενός άλλου πράκτορα.

### Ο πίνακας πρακτόρων

Η επάνω γραμμή διαθέτει ένα εικονίδιο πρακτόρων. Πριν ρυθμίσετε έναν πράκτορα, ο πίνακάς του σας καθοδηγεί στη σύνδεση σε Claude, Codex ή Grok, και ο πρώτος γίνεται ο προεπιλεγμένος πράκτοράς σας. Μετά από αυτό, ο πίνακας συγκεντρώνει κάθε συνδρομή σε μία σελίδα: κάθε πράκτορα και λογαριασμό με το πρόγραμμά του, έναν μετρητή για κάθε όριο 5ωρης συνεδρίας και εβδομαδιαίο όριό του με τον χρόνο μέχρι την επαναφορά του (περάστε το δείκτη από πάνω για το ακριβές ποσοστό) ή το υπόλοιπο προπληρωμένο υπόλοιπο, κάτω από μια γραμμή που εναλλάσσεται σε ό,τι έχετε χρησιμοποιήσει σε όλους, όπως tokens αυτή την εβδομάδα και το μοντέλο που χρησιμοποιείτε περισσότερο. Στην ενότητα _Δημιουργήστε κάτι ωραίο_ προσφέρει αρχικές προτροπές για ένα νέο θέμα, πρόσθετο, εφαρμογή ή παιχνίδι που παραδίδουν την εργασία στον προεπιλεγμένο πράκτορά σας. Οι εφαρμογές κατασκευάζονται με τον τρόπο που κατασκευάζονται τα ίδια τα Hype, Monologue και Omacut της Omarchy, σε C++ και Qt Quick, ακολουθώντας τη δεξιότητα πράκτορα omarchy-make-app, και ο μεταγλωττιστής και τα τμήματα Qt που χρειάζονται παρέχονται εγκατεστημένα. Τα παιχνίδια είναι μια μεμονωμένη σελίδα three.js στο `~/Games/vibes`, ακολουθώντας τη δεξιότητα πράκτορα omarchy-make-game, και όλα ανοίγουν από ένα πρόγραμμα εκκίνησης Game Vibes στο τρέχον θέμα. Φορτώνουν το three.js από το διαδίκτυο, οπότε χρειάζονται σύνδεση για να ξεκινήσουν. Τα Claude Code, Codex, Grok, Kimi, Cursor και το επίδομα Grok Bot του, GitHub Copilot, Muse, Antigravity και Devin καλύπτονται εξαρχής με τα όριά τους, το Kimchi με το πρόγραμμά του, τις προπληρωμένες πιστώσεις και τους προϋπολογισμούς δαπανών του, και τα Hermes, Mistral Vibe και Qwen Code εμφανίζουν τις συνεδρίες και τα tokens τους αφού τα χρησιμοποιήσετε. Εμφανίζονται επίσης προγράμματα παρόχων και κλειδιά που χρησιμοποιείτε μέσω των pi, omp ή opencode: τα OpenCode Zen και Go, το Z.ai GLM Coding Plan, το Ollama Cloud, το MiniMax Token Plan και το Synthetic με τα όριά τους. Τα OpenRouter και DeepSeek με τα προπληρωμένα υπόλοιπά τους. Το Fireworks με τις δαπάνες του τις τελευταίες 30 ημέρες. Τα tokens από μοντέλα που εκτελείτε στο δικό σας υλικό προσμετρώνται επίσης στα σύνολα. Τα ίδια τα μοντέλα έχουν τον δικό τους πίνακα, που περιγράφεται στην ενότητα [Τοπικά μοντέλα](#local-models). Κάθε πράκτορας μετράται μία φορά, σε όποιον τον χρεώνει, ανεξάρτητα από το πόσα harnesses τον οδηγείτε.

Κάντε αριστερό κλικ στο εικονίδιο της γραμμής ή πατήστε `Super + Ctrl + X` για τον πίνακα, δεξί κλικ για να εκκινήσετε τον προεπιλεγμένο πράκτορά σας και μεσαίο κλικ για ανανέωση. Τα αρχεία χρήσης πίσω από αυτόν αναδημιουργούνται κάθε 15 λεπτά με την εντολή `omarchy agent usage update`, και ο πίνακας μπορεί ακόμη και να συγχωνεύσει τη χρήση από τα άλλα μηχανήματά σας μέσω ενός συγχρονισμένου φακέλου. Δείτε το README στο `$OMARCHY_PATH/shell/plugins/agents/` για τις πλήρεις ρυθμίσεις.

### Πολλαπλές συνδρομές

Αν πληρώνετε για περισσότερα από ένα προγράμματα Claude, Codex ή Grok — ένα προσωπικό Max και ένα επαγγελματικό, ας πούμε — η Omarchy μπορεί να τα κρατήσει όλα συνδεδεμένα και να μετακινείται μεταξύ τους. Προσθέστε μια συνδρομή με το + στον πίνακα πρακτόρων, ο οποίος σας καθοδηγεί εκεί επί τόπου, ή με `omarchy agent account add claude Work` (ή `codex`, ή `grok`). Εγκαθιστά το CLI αν λείπει. Ο πρώτος λογαριασμός για έναν πάροχο συνδέεται μέσω του κανονικού προγράμματος περιήγησής σας, ακριβώς εκεί όπου το CLI αναζητά πάντα. Κάθε επόμενος συνδέεται μέσω ενός ιδιωτικού παραθύρου, ώστε ο λογαριασμός στον οποίο το πρόγραμμα περιήγησής σας είναι ήδη συνδεδεμένο να μην επιλεγεί κατά λάθος. Συνδεθείτε εκεί ως ο λογαριασμός που προσθέτετε και κλείστε πρώτα οποιοδήποτε ιδιωτικό παράθυρο είχατε ήδη ανοιχτό. Μην αποσυνδέεστε ποτέ από το CLI για να το κάνετε αυτό: η αποσύνδεση ανακαλεί την αποθηκευμένη σύνδεση, και αυτός ο λογαριασμός θα έπρεπε να προστεθεί ξανά.

Για να αντιγράψετε τις συνδέσεις συνδρομών σας σε ένα άλλο μηχάνημα Omarchy μέσω SSH, εκτελέστε `omarchy agent account copy user@laptop`. Ο αποστολέας παρέχει έναν προσωρινό παραλήπτη όταν ο προορισμός δεν έχει εγκατεστημένο έναν, οπότε παλαιότερα μηχανήματα Omarchy μπορούν να λάβουν λογαριασμούς χωρίς ενημέρωση. Οι εγκατεστημένοι παραλήπτες έχουν προτεραιότητα. Αυτό αντιγράφει όλες τις συνδρομές Claude, Codex και Grok. Προσθέστε ονόματα παρόχων για να τις επιλέξετε, όπως στην εντολή `omarchy agent account copy laptop claude`. Τα ονόματα λογαριασμών και τα αναγνωριστικά εντολών ταιριάζουν με την πηγή, συμπεριλαμβανομένων λογαριασμών που υπάρχουν ήδη στον προορισμό. Άσχετοι λογαριασμοί προορισμού λαμβάνουν ένα αριθμητικό επίθημα αν τα ονόματά τους συγκρούονται, και οι ρυθμίσεις, οι δεξιότητες, τα πρόσθετα και το ιστορικό συνομιλιών παραμένουν τοπικά σε κάθε μηχάνημα.

Τα υπάρχοντα διαπιστευτήρια προορισμού διατηρούνται. Ένας λογαριασμός πηγής που είναι ήδη συνδεδεμένος εκεί έχει το όνομά του συγχρονισμένο χωρίς να αντικατασταθούν τα διαπιστευτήριά του. Άλλοι λογαριασμοί προστίθενται δίπλα του. Για να αντικαταστήσετε τα αποθηκευμένα διαπιστευτήρια για λογαριασμούς που ταιριάζουν, χρησιμοποιήστε `omarchy agent account copy --replace laptop claude` αφού κλείσετε τις συνεδρίες αυτού του λογαριασμού στον προορισμό. Ένας νέος προορισμός αποκτά επίσης τον ενεργό λογαριασμό και τις προτιμήσεις εναλλαγής της πηγής. Ένας καθιερωμένος προορισμός διατηρεί τις δικές του.

Τα διαπιστευτήρια ταξιδεύουν μέσω SSH και αποθηκεύονται σε ιδιωτικά αρχεία στον προορισμό, οπότε αντιγράψτε μόνο σε μηχανήματα που εμπιστεύεστε. Πρόκειται για εφάπαξ αντιγραφή, όχι για συνεχή συγχρονισμό. Τα tokens ανανέωσης του Codex μπορούν να ανανεωθούν κυκλικά από άλλο μηχάνημα, αφήνοντας μια αντιγραμμένη σύνδεση να χρειάζεται ανανέωση. Οι ξεχωριστές συνδέσεις παραμένουν η πιο αξιόπιστη επιλογή για ταυτόχρονη χρήση σε πολλά μηχανήματα. Δείτε τις [Οδηγίες ελέγχου ταυτότητας λογαριασμού του Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Ένας λογαριασμός ανά πάροχο είναι ενεργός, και κάθε νέα συνεδρία ξεκινά ως αυτός: `cx`, `cy`, ένα απλό `claude`, `codex` ή `grok`, οτιδήποτε εκκινείται μέσω του `omarchy agent`, και σενάρια ή προγράμματα επεξεργασίας που βρίσκουν το CLI στο `PATH`. Εναλλάξτε με `omarchy agent account use work` (και επιστρέψτε με `omarchy agent account use main`), ή στον πίνακα πατώντας τον αριθμό ενός λογαριασμού και στη συνέχεια `Enter` (ή κάνοντας κλικ στο κουμπί Χρήση του). Οι συνεδρίες Claude που εκτελούνται αλλάζουν επίσης, από το επόμενο μήνυμά τους: κάθε συνεδρία Claude εκτελείται στο `~/.claude`, το οποίο περιέχει πάντα τη σύνδεση του ενεργού λογαριασμού. Μια συνεδρία Claude που ξεκίνησε στον δικό του φάκελο ενός λογαριασμού από μια παλαιότερη Omarchy διατηρεί αυτή τη σύνδεση μέχρι να κλείσει, οπότε η εναλλαγή ονομάζει αυτές τις συνεδρίες και ολοκληρώνεται από μόνη της αφού φύγουν. Οι συνεδρίες Codex και Grok που εκτελούνται παραμένουν στον λογαριασμό με τον οποίο ξεκίνησαν. Το ιστορικό συνομιλιών, οι ρυθμίσεις, οι δεξιότητες και τα πρόσθετα είναι κοινόχρηστα μεταξύ λογαριασμών, οπότε η εντολή `claude --continue` στον ίδιο φάκελο συνεχίζει από εκεί που σταματήσατε στον νέο λογαριασμό.

Με περισσότερους από έναν λογαριασμούς, ο πίνακας εμφανίζει τα όρια κάθε λογαριασμού δίπλα δίπλα, με τον ενεργό επισημασμένο. Από προεπιλογή, η Omarchy σας ειδοποιεί όταν ο ενεργός λογαριασμός ξεπεράσει το 95% ενός ορίου, και κάνοντας κλικ στην ειδοποίηση γίνεται εναλλαγή στον λογαριασμό με το μεγαλύτερο περιθώριο. Περάστε το δείκτη πάνω από τη γραμμή ενός λογαριασμού στον πίνακα και κάντε κλικ στην Αυτόματη εναλλαγή που εμφανίζεται δίπλα στη Χρήση (ή πατήστε `m`), ή εκτελέστε `omarchy agent account mode auto`, για να γίνεται η εναλλαγή από μόνη της. Ενώ είναι ενεργή, η Αυτόματη εναλλαγή παίρνει τη θέση της Χρήσης, και κάνοντας ξανά κλικ σε αυτή επιστρέφετε στην ειδοποίηση. Προσθέστε έναν αριθμό για να αλλάξετε το όριο, όπως στο `omarchy agent account mode auto 90`. Αν κάθε λογαριασμός υπερβαίνει το όριο, θα ενημερωθείτε μία φορά, μαζί με το ποιος λογαριασμός ελευθερώνεται πρώτος. Ενώ ένας ενεργός λογαριασμός βρίσκεται εντός 15 μονάδων από το όριό του (80% στην προεπιλογή), τα όριά του ελέγχονται κάθε τρία λεπτά αντί για κάθε 15.

Η εντολή `omarchy agent account list` εμφανίζει κάθε λογαριασμό και τα τελευταία όριά του, η `omarchy agent account remove work` ξεχνά έναν, και η `omarchy agent account rename primary Hey` μετονομάζει έναν (ή κάντε κλικ στο όνομα ενός λογαριασμού στον πίνακα). Αυτές οι εντολές λειτουργούν στους λογαριασμούς του προεπιλεγμένου πράκτορά σας. Για να φτάσετε στον άλλο πάροχο, ονομάστε τον πρώτα, όπως στο `omarchy agent account use codex side`. Η σύνδεση που είχατε ήδη στο `~/.claude` ή στο `~/.codex` είναι ο _Κύριος_ λογαριασμός. Του Codex παραμένει εκεί που είναι. Του Claude περιμένει σε δικό του φάκελο ενώ ένας άλλος λογαριασμός είναι ενεργός. Ένας λογαριασμός που μένει αχρησιμοποίητος για περισσότερες από περίπου οκτώ ώρες μπορεί να εμφανίσει _Απαιτείται σύνδεση_. Κάντε κλικ σε αυτόν για να συνδεθείτε ξανά σε αυτόν τον λογαριασμό απευθείας στον πίνακα, ή μεταβείτε σε αυτόν και ξεκινήστε μια συνεδρία, η οποία ανανεώνει τη σύνδεση από μόνη της. Οι διακομιστές MCP που προσθέτετε με `claude mcp add` φτάνουν σε κάθε λογαριασμό Claude, αφού όλοι εκτελούνται στο `~/.claude`. Για τα Codex και Grok, οι διακομιστές που είχατε όταν προστέθηκε ένας λογαριασμός τον ακολουθούν σε αυτόν, αλλά οι μεταγενέστεροι φτάνουν μόνο στον λογαριασμό στον οποίο τους προσθέσατε. Το Claude Desktop διατηρεί δική του σύνδεση, και τα εργαλεία Codex ή Grok που έχουν ρυθμιστεί με απόλυτη διαδρομή προς ένα δυαδικό αρχείο CLI δεν ακολουθούν την εναλλαγή. Ένα ρητό `CLAUDE_CONFIG_DIR`, `CODEX_HOME` ή `GROK_HOME` έχει προτεραιότητα έναντι του επιλεγμένου λογαριασμού.

### Διάγνωση κατάρρευσης

Η Omarchy παρακολουθεί το systemd-coredump για καταρρεύσεις διεργασιών. Αφού επιλέξετε έναν προεπιλεγμένο πράκτορα, οποιοδήποτε δικό σας πρόγραμμα δημιουργήσει core dump φέρνει μια ειδοποίηση «Η διεργασία κατέρρευσε» — κάντε κλικ σε αυτήν, και η κατάρρευση παραδίδεται στον προεπιλεγμένο πράκτορά σας μαζί με τη δεξιότητα omarchy-diagnose-crash της Omarchy, η οποία καθοδηγεί τον πράκτορα στην εξακρίβωση των γεγονότων από το core dump και στην απόφαση αν η κατάρρευση αξίζει να αναφερθεί upstream. Μπορείτε επίσης να την εκτελέσετε χειροκίνητα σε οποιοδήποτε PID από το `coredumpctl list` με `omarchy agent crash <pid>`.

Η παρακολούθηση είναι ενεργή από προεπιλογή. Απενεργοποιήστε την στην ενότητα _Ενεργοποίηση > Εναλλαγή > Απενεργοποίηση καταγραφής καταρρεύσεων_ (ή με `omarchy toggle crash-capture`) και οι ειδοποιήσεις σταματούν. Η εντολή `omarchy agent crash <pid>` εξακολουθεί να λειτουργεί χειροκίνητα.

Οι καταρρεύσεις μπορούν επίσης να σιγήσουν ένα πρόγραμμα κάθε φορά, πράγμα που σας προσφέρει η διάγνωση στο τέλος. Η εντολή `omarchy crash mute hyprland` σταματά τις ειδοποιήσεις μόνο για αυτό το πρόγραμμα, η `omarchy crash mute hyprland off` τις επαναφέρει, και η `omarchy crash mute` από μόνη της παραθέτει τι έχετε θέσει σε σίγαση. Δέχεται τη διαδρομή του δυαδικού αρχείου εξίσου ευχαρίστως με το όνομά του, οπότε η `omarchy crash mute /usr/bin/hyprland` κάνει το ίδιο πράγμα. Βάλτε σε εισαγωγικά ένα όνομα με κενό, όπως στο `omarchy crash mute 'Some App'`. Όλα τα υπόλοιπα εξακολουθούν να ειδοποιούν, και το πρόγραμμα σε σίγαση εξακολουθεί να καταρρέει — αυτό κρύβει την υπενθύμιση, δεν διορθώνει τίποτα.

### Εφαρμογές επιφάνειας εργασίας

Το μενού _Εγκατάσταση > AI_ περιλαμβάνει επίσης μερικές γραφικές εφαρμογές AI: Amp Desktop, Antigravity Desktop, την εφαρμογή επιφάνειας εργασίας ChatGPT, την εφαρμογή επιφάνειας εργασίας Claude (τη Linux beta της Anthropic, με καρτέλες Chat, Cowork και Claude Code), Grok Bot για συνομιλία με τα μοντέλα της xAI, Herdr Desktop, Hermes Desktop, OpenClaw, την εφαρμογή επιφάνειας εργασίας Perplexity και T3 Code. Το Grok Bot είναι η εφαρμογή συνομιλίας επιφάνειας εργασίας. Ο πράκτορας προγραμματισμού είναι η εντολή `grok`.

Το Hermes Desktop είναι αυτό που πρέπει να γνωρίζετε, επειδή ένα μηχάνημα έχει ένα Hermes, και είναι αυτό της εφαρμογής: το Hermes εγκαθίσταται μόνο μέσω της εφαρμογής, και η εντολή `hermes` που εκτελεί ο προεπιλεγμένος πράκτορας είναι αυτή της εφαρμογής. Η επιλογή του Hermes ως προεπιλεγμένου πράκτορα εγκαθιστά το ίδιο πράγμα που κάνει η καταχώριση _Εγκατάσταση > AI_: το πακέτο, και ένα runtime του Hermes στο `~/.hermes` που έχει ρυθμιστεί από το ίδιο το πρόγραμμα εγκατάστασης του Hermes, το οποίο χρειάζεται μερικά λεπτά την πρώτη φορά. Αυτό το runtime είναι το ένα Hermes που χρησιμοποιούν η εντολή τερματικού `hermes`, ο προεπιλεγμένος πράκτορας και η εφαρμογή, και ενημερώνεται μόνο του με `hermes update` αντί να περιμένει μια έκδοση της Omarchy. Η εγκατάστασή του παραδίδει επίσης στο Hermes το θέμα της Omarchy ως skin με όνομα `omarchy`, το οποίο ακολουθεί κάθε επιφάνεια του Hermes καθώς αλλάζετε θέματα. Επιλέξτε ένα άλλο στις ρυθμίσεις Εμφάνισης του Hermes ή με `/skin` αν προτιμάτε να μην το κάνει, και η Omarchy αφήνει αυτή την επιλογή ήσυχη. Η αφαίρεση της εφαρμογής στην ενότητα _Αφαίρεση > AI_ κλείνει πρώτα το Hermes, συμπεριλαμβανομένης της πύλης, παίρνει μαζί της αυτό το runtime και διατηρεί τις συνομιλίες, τις μνήμες και τις δεξιότητες που έγραψε το Hermes για τον εαυτό του, εκτός αν του πείτε διαφορετικά: ρωτά, με προεπιλογή το όχι, αν αυτά τα δεδομένα και οι ρυθμίσεις σύνδεσής σας πρέπει να φύγουν επίσης.

Η εμπειρία επιφάνειας εργασίας του OpenClaw είναι το Control UI του, το οποίο ανοίγει ως εφαρμογή web υποστηριζόμενη από τη δική του τοπική πύλη. Το OpenClaw βρίσκεται στο `~/.openclaw` και ενημερώνεται μόνο του: χρησιμοποιήστε το κουμπί «Ενημέρωση πύλης» του Control UI ή εκτελέστε `openclaw update`, και η πύλη επανεκκινείται στη νέα έκδοση. Η Omarchy επιλέγει μόνο την έκδοση από την οποία ξεκινά μια νέα εγκατάσταση. Το OpenClaw μπορεί επίσης να είναι ο προεπιλεγμένος πράκτοράς σας: η επιλογή του στην ενότητα _Πράκτορας > Harness_ ρυθμίζει το ίδιο αντίγραφο στο `~/.openclaw`, και ο πράκτορας ανοίγει το UI τερματικού του OpenClaw συνδεδεμένο στην πύλη του. Η αφαίρεση του OpenClaw στην ενότητα _Αφαίρεση > AI_ παίρνει μαζί της την υπηρεσία πύλης και την εφαρμογή και στη συνέχεια ρωτά αν πρέπει να φύγει και το `~/.openclaw`, αφού αυτό περιέχει τις συνομιλίες και τα διαπιστευτήριά σας μαζί με το ίδιο το OpenClaw και τα runtimes προσθέτων που κατεβάζει. Η προεπιλογή το διατηρεί, και η εκ νέου εγκατάσταση του OpenClaw το ανακτά.

Το Herdr Desktop είναι η εφαρμογή επιφάνειας εργασίας [Herdr](https://herdr.dev): χώροι, καρτέλες και τμήματα παραθύρων τερματικών και πρακτόρων προγραμματισμού που συνεχίζουν να εκτελούνται στον πυρήνα του όταν κλείνετε το παράθυρο. Προέρχεται από το ίδιο το πρόγραμμα εγκατάστασης του Herdr αντί για ένα πακέτο, οπότε βρίσκεται στο `~/.local/share/herdr-app`, φέρνει μαζί του τον πυρήνα του στο `~/.local/bin/herdr-core` όταν δεν έχετε ακόμη έναν, και ενημερώνει και τα δύο μόνο του. Βρίσκεται δίπλα στην εντολή `herdr` που παρέχει η Omarchy στο `Super + Ctrl + Return` αντί να την αντικαθιστά, και αποκτά τα άμεσα πλήκτρα αυτής της εντολής: τα `Alt + Return` και `Alt + Shift + Return` διαιρούν ένα τμήμα παραθύρου προς τα κάτω ή προς τα δεξιά, το `Alt + Escape` το κλείνει, το `Ctrl + Alt + Arrow` μετακινεί μεταξύ τμημάτων παραθύρων, τα `Alt + 1..9` και `Alt + Left/Right` επιλέγουν μια καρτέλα, και τα `Alt + Up/Down` μετακινούν μεταξύ χώρων. Το `Ctrl + 1..9` επιλέγει έναν χώρο και το `Alt + Shift + Up/Down` περνά από πράκτορες. Τα πλήκτρα προθέματος `Ctrl + Space` παραμένουν μόνο για τερματικό, αφού η εφαρμογή δεν μπορεί να κρατήσει ένα απλό πλήκτρο Ctrl για μια ακολουθία. Η Omarchy τα γράφει στο `~/.config/herdr-app/keys.json`, και η εντολή `omarchy-refresh-herdr-app` τα επαναφέρει. Η εγκατάστασή του επιλέγει το θέμα Omarchy του Herdr, το οποίο ακολουθεί από τότε το θέμα της Omarchy σας. Το Herdr διατηρεί ένα θέμα για τη φωτεινή λειτουργία και ένα για τη σκοτεινή, οπότε αφού εναλλάξετε μεταξύ ενός σκοτεινού και ενός φωτεινού θέματος Omarchy, επιλέξτε το Omarchy στον επιλογέα θεμάτων του Herdr άλλη μια φορά για την άλλη λειτουργία.

Το T3 Code εκτελείται από την επίσημη έκδοση AppImage του στο `~/.local/share/t3code` αντί από ένα πακέτο, οπότε ενημερώνεται μόνο του. Η εγκατάστασή του ρωτά αν θα ξεκινήσει στο κανάλι Stable ή Nightly. Αλλάξτε αργότερα στις ρυθμίσεις του T3 Code. Τα νήματα και οι ρυθμίσεις σας βρίσκονται στο `~/.t3`, και η αφαίρεση του T3 Code στην ενότητα _Αφαίρεση > AI_ τα παίρνει μαζί της.

### Τοπικά μοντέλα

Εκτελέστε ένα ανοιχτό μοντέλο στο δικό σας μηχάνημα για τους πράκτορες προγραμματισμού σας. Οι προτροπές και ο κώδικάς σας παραμένουν στο μηχάνημα. Τίποτα που στέλνεται στο μοντέλο δεν φεύγει από αυτό. Ξεκινήστε με:

```bash
omarchy models use best text
```

Αυτό ρυθμίζει το καλύτερο μοντέλο κειμένου για αυτό το μηχάνημα, το είδος που χρησιμοποιούν οι πράκτορές σας. Τα μοντέλα εικόνας, βίντεο και μουσικής έχουν το δικό τους καλύτερο: `omarchy models use best image`, `video` ή `music`. Εκτελέστε `omarchy models use best` για να δείτε την επιλογή κάθε είδους για αυτό το μηχάνημα.

Ή ανοίξτε τον πίνακα τοπικών μοντέλων από το εικονίδιο με τις σπίθες στην επάνω γραμμή, δίπλα στο εικονίδιο πρακτόρων, ή με Super + Ctrl + Alt + X, και επιλέξτε +. Το εικονίδιο εμφανίζεται όταν ένα μοντέλο ταιριάζει σε αυτό το μηχάνημα. Το Podman, που εκτελεί τα μοντέλα, παρέχεται με την Omarchy, όπως και το κιτ εργαλείων container της NVIDIA σε ένα μηχάνημα NVIDIA, το οποίο τους δίνει τη GPU. Αν λείπει κάποιο από τα δύο, η πρώτη ρύθμιση το εγκαθιστά. Η Omarchy στη συνέχεια επιλέγει το συνιστώμενο μοντέλο για αυτό το μηχάνημα, το κατεβάζει και το ξεκινά. Αναμένετε μια λήψη δεκάδων GB και το μεγαλύτερο μέρος της μνήμης του μηχανήματος να χρησιμοποιείται ενώ το μοντέλο εκτελείται: το Flash Next χρησιμοποιεί περίπου 100 GiB με το πλήρες πλαίσιο 256K του. Αν άλλα μοντέλα κατέχουν τη μνήμη που χρειάζεται, ρυθμίζεται σταματημένο, έτοιμο να ξεκινήσει μόλις σταματήσετε ένα. Το μοντέλο σταματά κατά την αποσύνδεση. Σταματήστε το εσείς όταν χρειάζεστε τη μνήμη για κάτι άλλο.

Η εντολή `omarchy models list` εμφανίζει τις επιλογές και εξηγεί γιατί ορισμένες δεν ταιριάζουν. Για να ρυθμίσετε ένα άλλο, εκτελέστε `omarchy models use <recipe>`. Σήμερα, τα `qwen3.8-flash-next-gufo` και `qwen3.8-27b-gufo` είναι διαθέσιμα για μηχανήματα Strix Halo 128 GB. Το 27B χρειάζεται περίπου 40 GiB, οπότε αφήνει χώρο για άλλη εργασία. Σε έναν φορητό υπολογιστή 64 GB με Intel Arc B390, το `qwen3.6-35b-a3b-llamacpp` εκτελείται σε περίπου 30 GiB. Νέες συνταγές και συστάσεις φτάνουν με το `omarchy update`, μέσω του πακέτου.

Κάθε μοντέλο που ρυθμίζετε αποκτά τη δική του γραμμή στον πίνακα τοπικών μοντέλων: αναπαραγωγή για να το ξεκινήσετε, παύση για να το σταματήσετε και να ελευθερώσετε τη μνήμη του, και το κουμπί τερματικού για να ανοίξετε τον πράκτορά σας σε αυτό. Στο επάνω μέρος, μια γραμμή δείχνει πώς η μνήμη του μηχανήματος μοιράζεται μεταξύ της ίδιας της Omarchy (του συστήματος και των εφαρμογών σας), κάθε μοντέλου που εκτελείται και όσων είναι ελεύθερα. Δείξτε σε ένα σταματημένο μοντέλο και η γραμμή δείχνει αν χωράει ή πόσο του λείπει. Πολλά μπορούν να εκτελούνται ταυτόχρονα όταν χωρούν μαζί στη μνήμη. Αν ένα δεν χωράει, η Omarchy λέει ποιο μοντέλο που εκτελείται να σταματήσετε. Σύρετε γραμμές από το λογότυπό τους για να τις αναδιατάξετε, και πατήστε Delete σε μια επιλεγμένη γραμμή για να αφαιρέσετε ένα μοντέλο και τη λήψη του.

Κάθε μοντέλο προγραμματισμού που ρυθμίζετε αποκτά επίσης τη δική του καταχώριση στο πρόγραμμα εκκίνησης εφαρμογών, με το όνομα του μοντέλου και το λογότυπο του κατασκευαστή του, με τον τρόπο που η σύνδεση σε Claude, Codex ή Grok προσθέτει μία. Ανοίγει τον πράκτορά σας σε αυτό το μοντέλο και ξεκινά πρώτα το μοντέλο αν δεν εκτελείται: το τερματικό το δείχνει να φορτώνει και παραδίδει στον πράκτορα μόλις είναι έτοιμο. Η αφαίρεση ενός μοντέλου αφαιρεί την καταχώρισή του.

Δεν είναι κάθε μοντέλο για προγραμματισμό. Τα μοντέλα εικόνας, βίντεο και μουσικής ανοίγουν στο Fantasi αντ' αυτού, την εφαρμογή της Omarchy για τη δημιουργία εικόνων, βίντεο και μουσικής με ένα μοντέλο που εκτελείται σε αυτό το μηχάνημα, επιλεγμένο εκεί ή από τη γραμμή τους στον πίνακα τοπικών μοντέλων.

Ένα μοντέλο συνεχίζει να εκτελείται ακριβώς όπως ρυθμίστηκε, οπότε μια ενημέρωση της Omarchy δεν επανεκκινεί ποτέ ένα κάτω από τους πράκτορές σας. Όταν η Omarchy έχει νεότερο runtime ή νεότερα βάρη για ένα μοντέλο που έχετε ρυθμίσει, η γραμμή του εμφανίζει ένα κουμπί ενημέρωσης: πατήστε το και το μοντέλο ρυθμίζεται ξανά στο παρασκήνιο, κατεβάζοντας μόνο ό,τι άλλαξε, και επανεκκινείται στη νέα έκδοση. Ένα μοντέλο που ήταν σταματημένο παραμένει σταματημένο. Η εντολή `omarchy models update` κάνει το ίδιο για κάθε μοντέλο από ένα τερματικό.

Από τη γραμμή εντολών, οι `omarchy models start <recipe>` και `omarchy models stop <recipe>` κάνουν το ίδιο, η `omarchy models status` εμφανίζει κάθε μοντέλο, και η `omarchy agent --local` ανοίγει το τελευταίο μοντέλο που ξεκινήσατε στο pi, όποιος κι αν είναι ο προεπιλεγμένος πράκτοράς σας. Τα OpenCode και Qwen Code μπορούν επίσης να χρησιμοποιήσουν ένα τοπικό μοντέλο: οι `omarchy models harness opencode` ή `omarchy models harness qwen` τα ανοίγουν εκεί αντ' αυτού, και η `omarchy models harness pi` επιστρέφει. Το pi παραθέτει επίσης κάθε μοντέλο που έχετε ρυθμίσει, και εκείνα σε μηχανήματα με τα οποία έχετε συνδεθεί, στον δικό του επιλογέα μοντέλων, οπότε το απλό `pi` τα φτάνει επίσης. Οποιοσδήποτε client συμβατός με OpenAI μπορεί επίσης να συνδεθεί: η `status` εμφανίζει τη διεύθυνση κάθε μοντέλου (η πρώτη είναι `http://127.0.0.1:11435/v1`), το όνομα της συνταγής είναι το μοντέλο, και το κλειδί βρίσκεται στο `~/.config/omarchy/agent-local/key`.

Η εντολή `omarchy models remove <recipe>` διαγράφει ένα μοντέλο και τις λήψεις που δεν χρησιμοποιεί κανένα άλλο μοντέλο.

Τα runtimes τρίτων επισημαίνονται με τον εκδότη τους. Η Omarchy εκτελεί κάθε μοντέλο χωρίς πρόσβαση στο δίκτυο.

### Τοπικά LLM

Η Omarchy συνιστά δύο τρόπους εκτέλεσης τοπικών μοντέλων LLM: το LM Studio και το Ollama. Το LM Studio παρέχει μια διεπαφή GUI για την εύρεση μοντέλων ανοιχτών βαρών, την εγκατάστασή τους και την εκτέλεσή τους. Είναι ένας εξαιρετικός τρόπος να ξεκινήσετε εύκολα. Το Ollama προσφέρει ένα CLI για να κάνετε το ίδιο παρόμοια. Αλλά αν είστε νέοι στα τοπικά μοντέλα, θα ξεκινούσα με το LM Studio. Μπορείτε να εγκαταστήσετε οποιοδήποτε από τα δύο στην ενότητα _Εγκατάσταση > AI_ στο Μενού Omarchy.

### Οι δεξιότητες της Omarchy

Οι δεξιότητες πρακτόρων βοηθούν την AI να χρησιμοποιεί συγκεκριμένα εργαλεία με συγκεκριμένο τρόπο, και η Omarchy διαθέτει επτά από αυτές. Η δεξιότητα omarchy καλύπτει την προσαρμογή του συστήματος, όπως την τροποποίηση της διαμόρφωσης Hyprland σας ή την προσαρμογή της γραμμής. Οι omarchy-make-theme, omarchy-make-plugin, omarchy-make-app και omarchy-make-game καλύπτουν τη δημιουργία κάτι νέου, η omarchy-contribute καλύπτει την αναφορά ενός σφάλματος ή την αποστολή μιας διόρθωσης upstream, και η omarchy-diagnose-crash εξετάζει το core dump μιας κατάρρευσης. Συνδέονται συμβολικά στους καταλόγους δεξιοτήτων για Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` και κάθε `~/.hermes/profiles/*/skills`) και τη γενική τοποθεσία `~/.agents/skills`, οπότε τα περισσότερα harnesses τις εντοπίζουν αυτόματα. Ένας δικός σας φάκελος δεξιότητας με το ίδιο όνομα έχει προτεραιότητα.

Αλλά πρέπει να αντιμετωπίζετε αυτές τις δεξιότητες ως πειραματικές. Διαφορετικά μοντέλα θα τις χρησιμοποιήσουν με διαφορετικό αποτέλεσμα. Είναι καλύτερο να εκτελείτε πρώτα σε λειτουργία σχεδιασμού, ώστε να έχετε μια ιδέα για το τι θα ήθελε να αλλάξει ο πράκτορας. Και στη συνέχεια να είστε έτοιμοι να επαναφέρετε αλλαγές ή ακόμη και να καλέσετε την `omarchy reinstall configs`, αν ο πράκτορας τα κάνει θάλασσα.
