# AI

Το Omarchy περιλαμβάνει εκκινητές για τους παρακάτω coding agents χωρίς να επιλέγει προεπιλογή για εσάς. Εκτελέστε μια εντολή για να εγκαταστήσετε το CLI της στην πρώτη χρήση και στη συνέχεια πραγματοποιήστε έλεγχο ταυτότητας όταν σας ζητηθεί. Οι Hermes και OpenClaw αποτελούν τις εξαιρέσεις: τίποτα δεν εγκαθίσταται γι' αυτούς μέσω mise, και η επιλογή οποιουδήποτε από τους δύο εγκαθιστά το δικό του αυτοενημερούμενο αντίγραφο, όπως εξηγούν παρακάτω οι _Εφαρμογές επιφάνειας εργασίας_.

### Εγκατάσταση και ενημέρωση agents

Εκτός από τους Hermes και OpenClaw, αυτοί οι agents χρησιμοποιούν την lazy εγκατάσταση του mise: η πρώτη εκκίνηση εγκαθιστά το CLI και οι επόμενες εκκινήσεις το επαναχρησιμοποιούν. Το mise ελέγχει επίσης έναν εγκατεστημένο agent για νέα έκδοση το πολύ μία φορά κάθε τέσσερις ώρες, ακριβώς πριν ξεκινήσει ή στο παρασκήνιο σε μια προτροπή κελύφους. Εάν αυτή η ενημέρωση αποτύχει ή είστε εκτός σύνδεσης, εκτελείται η εγκατεστημένη έκδοση. Το `omarchy update` ενημερώνει τους εγκατεστημένους agents μαζί με το υπόλοιπο Omarchy, και το `mup` ενημερώνει μόνο τα εργαλεία που διαχειρίζεται το mise.

Το πρόγραμμα ενημέρωσης ενός ίδιου του agent, όπως το `claude update`, το `codex update` ή ένα κουμπί ενημέρωσης σε μια εφαρμογή, δεν ενημερώνει την εγκατάσταση που διαχειρίζεται το mise. Το `codex update` αποτυγχάνει, και το `claude update` μπορεί να αναφέρει επιτυχία ενώ εγκαθιστά ένα ξεχωριστό αντίγραφο που το mise δεν παρακολουθεί. Εάν προτιμάτε να χρησιμοποιείτε το εγγενές πρόγραμμα εγκατάστασης και ενημέρωσης ενός agent, προσθέστε το στο `disable_tools`. Δείτε τα [Προεγκατεστημένα εργαλεία CLI](18-development-tools.md#preinstalled-cli-tools).

Για να εγκαταστήσετε όλα τα ρυθμισμένα lazy εργαλεία πριν τα χρειαστείτε, εκτελέστε `mise install --include-lazy`. Αυτό περιλαμβάνει τα άλλα προεπιλεγμένα εργαλεία CLI του Omarchy καθώς και τους agents. Δείτε τα [Προεγκατεστημένα εργαλεία CLI](18-development-tools.md#preinstalled-cli-tools) για την εγκατάσταση ενός μεμονωμένου εργαλείου ή τη χρήση της δικής σας εγκατάστασης.

Το `grok` εγκαθίσταται μέσω του first-party πακέτου `grok` του mise, με τον ίδιο τρόπο όπως τα `claude` και `codex`. Εκτελέστε `grok` ή επιλέξτε το στην ενότητα _Agent > Harness_. Παραλείψτε το πρόγραμμα εγκατάστασης `curl | bash` στο x.ai. Αυτή η διαδρομή τοποθετεί ένα δεύτερο αντίγραφο στο `~/.grok/bin`, το προτάσσει στο `PATH` και αντικαθιστά το wrapper του Omarchy.

Το `dsh` ανοίγει το browser UI του στο `127.0.0.1:3080`, με τον κατάλογο εκκίνησης ως προεπιλεγμένο χώρο εργασίας του. Το browser UI του δεν δέχεται αρχική προτροπή, οπότε το `omarchy agent prompt` το ανοίγει με την προτροπή στο πρόχειρό σας για επικόλληση. Το Omarchy το ξεκινά με το προκαθορισμένο σύνολο δικαιωμάτων χωρίς έγκριση της DeepSeek. Το DeepSeek Harness ανεβάζει αρχεία καταγραφής συνεδριών στην DeepSeek όταν χρησιμοποιείτε το επίσημο model API της. Απενεργοποιήστε το στην ενότητα _Settings > General > Upload Session Log_ στο browser UI του. Τα σχόλια που του στέλνετε ανεβαίνουν επίσης μαζί με τη συνεδρία, εκτός εάν το ξεκινήσετε με `DSH_TELEMETRY_MODE=DISABLED`.

### Ο προεπιλεγμένος agent

Επιλέξτε τον προεπιλεγμένο agent σας με `omarchy default agent <name>` ή στην ενότητα _Agent > Harness_ στο Omarchy Menu (`Super + Space`). Εάν ο agent δεν έχει εγκατασταθεί ακόμα, η επιλογή του τον εγκαθιστά πρώτα, και αποκτά επίσης τον δικό του εκκινητή στον εκκινητή εφαρμογών, δίπλα στο Agent. Ένα φρέσκο Omarchy θα σας καλέσει να κάνετε αυτή την επιλογή με μια ειδοποίηση μίας φοράς.

Η επιλογή του Claude επιχειρεί επίσης να εγκαταστήσει την επέκταση του προγράμματος περιήγησής του για Chromium, Chrome, Brave, Brave Origin και Edge. Η εγκατάσταση της επέκτασης ισχύει για όλους τους χρήστες και μπορεί να ζητήσει τον κωδικό πρόσβασης του συστήματός σας. Η ακύρωση ή μια αποτυχημένη εγκατάσταση επέκτασης εξακολουθεί να επιλέγει και να εκκινεί τον Claude. Επανεκκινήστε το πρόγραμμα περιήγησής σας, ενεργοποιήστε την επέκταση εάν σας ζητηθεί και συνδεθείτε στον Claude για να ολοκληρώσετε τη σύνδεσή της. Εκτελέστε `/chrome` στον Claude για να ελέγξετε τη σύνδεση. Τα Firefox και Zen δεν υποστηρίζουν αυτή την επέκταση. Εάν ο Claude ήταν ήδη ο προεπιλεγμένος σας πριν προστεθεί αυτή η εγκατάσταση, επιλέξτε τον ξανά για να εγκαταστήσετε την επέκταση.

Μόλις κάνετε την επιλογή, το `Super + Shift + Ctrl + A` εκκινεί τον προεπιλεγμένο agent σε ένα αποκλειστικό παράθυρο τερματικού (ή εμφανίζει τον επιλογέα εάν δεν έχετε επιλέξει ακόμα). Μπορείτε επίσης να τον εκκινήσετε απευθείας σε μια εργασία με `omarchy agent prompt "Review this project"`. Τα Freebuff και DeepSeek Harness δεν δέχονται αρχική προτροπή, οπότε ανοίγουν αντί γι' αυτό με την προτροπή στο πρόχειρό σας για επικόλληση. Οι agents που εκκινούνται με αυτόν τον τρόπο εκτελούνται χωρίς επίβλεψη στις αντίστοιχες λειτουργίες τους «μη σταματάς να ρωτάς», οπότε να είστε έτοιμοι να κάνουν πράγματα στην πράξη! Το MiniMax Code δεν διαθέτει τέτοια λειτουργία για τις διαδραστικές συνεδρίες του, οπότε ζητά δικαιώματα ως συνήθως. Και επειδή οι agents αρνούνται να θυμούνται την εμπιστοσύνη για τον αρχικό κατάλογό σας, οι εκκινήσεις από το `$HOME` ξεκινούν αντί γι' αυτό στο `~/Work`.

Υπάρχουν και συντομεύσεις τερματικού: το `a` εκτελεί τον προεπιλεγμένο agent ενσωματωμένο στο τρέχον τερματικό, ενώ τα `c`, `cx` και `cy` ξεκινούν απευθείας τα OpenCode, Claude Code και Codex (και πάλι στις λειτουργίες αυτόματης έγκρισής τους). Οι αλλαγές θέματος συγχρονίζονται επίσης στους agents: τα Claude Code, Pi, OpenCode και Hermes (μόλις το Omarchy το έχει εγκαταστήσει) ακολουθούν όλα όταν αλλάζετε το θέμα του Omarchy.

### Οι οδηγίες του agent σας

Οι προσωπικοί κανόνες για κάθε agent πηγαίνουν στο `~/.agents/AGENTS.md`, δίπλα στις κοινόχρηστες δεξιότητες στο `~/.agents/skills`. Ανοίξτε το στην ενότητα _Agent > Instructions_, η οποία το συνδέει επίσης σε κάθε harness που διατηρεί το δικό του καθολικό αρχείο: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, το `~/.copilot/copilot-instructions.md` του Copilot, και ούτω καθεξής. Τα Crush και Amp διαβάζουν τον σύνδεσμο `~/.config/AGENTS.md`, ενώ τα omp, Kimi και DeepSeek Harness διαβάζουν απευθείας το `~/.agents/AGENTS.md`. Η επιλογή ενός προεπιλεγμένου agent το συνδέει επίσης. Ένα αρχείο οδηγιών που είχατε ήδη γίνεται το κοινόχρηστο εάν δεν υπήρχε κανένα ακόμα. Διαφορετικά διατηρείται δίπλα στον σύνδεσμο ως `.bak`. Εκτελέστε `omarchy agent instructions` για να επανασυνδέσετε μετά την εγκατάσταση άλλου agent.

### Ο πίνακας agents

Η επάνω γραμμή διαθέτει ένα εικονίδιο agents. Πριν εγκαταστήσετε έναν agent, ο πίνακάς του σας καθοδηγεί στη σύνδεση σε Claude, Codex ή Grok, και ο πρώτος γίνεται ο προεπιλεγμένος agent σας. Μετά από αυτό, ο πίνακας συγκεντρώνει κάθε συνδρομή σε μία σελίδα: κάθε agent και λογαριασμό με το πλάνο του, έναν μετρητή για καθένα από τα όρια συνεδρίας 5 ωρών και εβδομαδιαία όριά του με τον χρόνο μέχρι την επαναφορά του (τοποθετήστε τον δείκτη για το ακριβές ποσοστό), ή το υπόλοιπο προπληρωμένο υπόλοιπο, κάτω από μια γραμμή που εναλλάσσεται σε όσα έχετε χρησιμοποιήσει σε όλους τους, όπως tokens αυτή την εβδομάδα και το μοντέλο που χρησιμοποιείτε περισσότερο. Στην ενότητα _Make something cool_ προσφέρει αρχικές προτροπές για ένα νέο θέμα, πρόσθετο, εφαρμογή ή παιχνίδι που παραδίδουν την εργασία στον προεπιλεγμένο agent σας. Οι εφαρμογές κατασκευάζονται με τον τρόπο που κατασκευάζονται τα ίδια τα Hype, Monologue και Omacut του Omarchy, σε C++ και Qt Quick, ακολουθώντας την δεξιότητα agent omarchy-make-app, και ο μεταγλωττιστής και τα κομμάτια Qt που χρειάζονται έρχονται εγκατεστημένα. Τα παιχνίδια είναι μία μόνο σελίδα three.js στο `~/Games/vibes`, ακολουθώντας την δεξιότητα agent omarchy-make-game, και όλα ανοίγουν από έναν εκκινητή Game Vibes στο τρέχον θέμα. Φορτώνουν το three.js από το διαδίκτυο, οπότε χρειάζονται σύνδεση για να ξεκινήσουν. Τα Claude Code, Codex, Grok, Kimi, Cursor και η παροχή Grok Bot του, GitHub Copilot, Muse, Antigravity και Devin καλύπτονται εξαρχής με τα όριά τους, το Kimchi με το πλάνο του, τις προπληρωμένες πιστώσεις και τους προϋπολογισμούς δαπανών του, και τα Hermes, Mistral Vibe και Qwen Code εμφανίζουν τις συνεδρίες και τα tokens τους μόλις τα χρησιμοποιήσετε. Τα πλάνα παρόχων και τα κλειδιά που χρησιμοποιείτε μέσω pi, omp ή opencode εμφανίζονται επίσης: τα OpenCode Zen και Go, το Z.ai GLM Coding Plan, το Ollama Cloud, το MiniMax Token Plan και το Synthetic με τα όριά τους. Τα OpenRouter και DeepSeek με τα προπληρωμένα υπόλοιπά τους. Το Fireworks με τις δαπάνες του τις τελευταίες 30 ημέρες. Τα tokens από μοντέλα που εκτελείτε στο δικό σας υλικό προσμετρώνται επίσης στα σύνολα. Τα ίδια τα μοντέλα έχουν τον δικό τους πίνακα, που περιγράφεται στην ενότητα [Τοπικά μοντέλα](#local-models). Κάθε agent καταμετράται μία φορά, σε όποιον τον χρεώνει, ανεξάρτητα από πόσα harnesses τον οδηγείτε.

Κάντε αριστερό κλικ στο εικονίδιο της γραμμής ή πατήστε `Super + Ctrl + X` για τον πίνακα, δεξί κλικ για να εκκινήσετε τον προεπιλεγμένο agent σας και μεσαίο κλικ για ανανέωση. Οι εγγραφές χρήσης πίσω από αυτόν αναδημιουργούνται κάθε 15 λεπτά από το `omarchy agent usage update`, και ο πίνακας μπορεί ακόμη και να συγχωνεύσει χρήση από τα άλλα μηχανήματά σας μέσω ενός συγχρονισμένου φακέλου. Δείτε το README στο `$OMARCHY_PATH/shell/plugins/agents/` για τις πλήρεις ρυθμίσεις.

### Πολλαπλές συνδρομές

Εάν πληρώνετε για περισσότερα από ένα πλάνα Claude, Codex ή Grok — ένα προσωπικό Max και ένα εργασιακό, ας πούμε — το Omarchy μπορεί να τα κρατήσει όλα συνδεδεμένα και να μετακινείται μεταξύ τους. Προσθέστε μια συνδρομή με το + στον πίνακα agents, ο οποίος σας καθοδηγεί ακριβώς εκεί, ή με `omarchy agent account add claude Work` (ή `codex`, ή `grok`). Εγκαθιστά το CLI εάν λείπει. Ο πρώτος λογαριασμός για έναν πάροχο συνδέεται μέσω του κανονικού προγράμματος περιήγησής σας, ακριβώς εκεί που το CLI κοιτάζει πάντα. Κάθε επόμενος συνδέεται μέσω ενός ιδιωτικού παραθύρου, ώστε ο λογαριασμός στον οποίο το πρόγραμμα περιήγησής σας είναι ήδη συνδεδεμένο να μην παραληφθεί κατά λάθος. Συνδεθείτε εκεί ως ο λογαριασμός που προσθέτετε και κλείστε πρώτα οποιοδήποτε ιδιωτικό παράθυρο είχατε ήδη ανοιχτό. Μην αποσυνδέεστε ποτέ από το CLI για να το κάνετε αυτό: η αποσύνδεση ανακαλεί την αποθηκευμένη σύνδεση και αυτός ο λογαριασμός θα έπρεπε να προστεθεί ξανά.

Για να αντιγράψετε τις συνδέσεις της συνδρομής σας σε άλλο μηχάνημα Omarchy μέσω SSH, εκτελέστε `omarchy agent account copy user@laptop`. Ο αποστολέας παρέχει έναν προσωρινό δέκτη όταν ο προορισμός δεν έχει εγκατεστημένο έναν, ώστε παλαιότερα μηχανήματα Omarchy να μπορούν να λαμβάνουν λογαριασμούς χωρίς ενημέρωση. Οι εγκατεστημένοι δέκτες έχουν προτεραιότητα. Αυτό αντιγράφει όλες τις συνδρομές Claude, Codex και Grok. Προσθέστε ονόματα παρόχων για να τις επιλέξετε, όπως στο `omarchy agent account copy laptop claude`. Τα ονόματα λογαριασμών και τα αναγνωριστικά εντολών ταιριάζουν με την πηγή, συμπεριλαμβανομένων λογαριασμών που υπάρχουν ήδη στον προορισμό. Άσχετοι λογαριασμοί προορισμού λαμβάνουν ένα αριθμητικό επίθημα εάν τα ονόματά τους συγκρούονται, και οι ρυθμίσεις, οι δεξιότητες, τα πρόσθετα και το ιστορικό συνομιλιών παραμένουν τοπικά σε κάθε μηχάνημα.

Τα υπάρχοντα διαπιστευτήρια προορισμού διατηρούνται. Ένας λογαριασμός πηγής που είναι ήδη συνδεδεμένος εκεί έχει το όνομά του συγχρονισμένο χωρίς αντικατάσταση των διαπιστευτηρίων του. Άλλοι λογαριασμοί προστίθενται δίπλα του. Για να αντικαταστήσετε τα αποθηκευμένα διαπιστευτήρια για αντίστοιχους λογαριασμούς, χρησιμοποιήστε `omarchy agent account copy --replace laptop claude` αφού κλείσετε τις συνεδρίες αυτού του λογαριασμού στον προορισμό. Ένας φρέσκος προορισμός λαμβάνει επίσης τον ενεργό λογαριασμό και τις προτιμήσεις εναλλαγής της πηγής. Ένας καθιερωμένος προορισμός διατηρεί τις δικές του.

Τα διαπιστευτήρια ταξιδεύουν μέσω SSH και αποθηκεύονται σε ιδιωτικά αρχεία στον προορισμό, οπότε αντιγράψτε μόνο σε μηχανήματα που εμπιστεύεστε. Αυτή είναι μια αντιγραφή μίας φοράς, όχι συνεχής συγχρονισμός. Τα tokens ανανέωσης του Codex μπορούν να εναλλάσσονται από άλλο μηχάνημα, αφήνοντας μια αντιγραμμένη σύνδεση να χρειάζεται ανανέωση. Οι ξεχωριστές συνδέσεις παραμένουν η πιο αξιόπιστη επιλογή για ταυτόχρονη χρήση σε πολλά μηχανήματα. Δείτε τις [οδηγίες ελέγχου ταυτότητας λογαριασμού του Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Ένας λογαριασμός ανά πάροχο είναι ενεργός και κάθε νέα συνεδρία ξεκινά ως αυτός: `cx`, `cy`, ένα απλό `claude`, `codex` ή `grok`, οτιδήποτε εκκινείται μέσω `omarchy agent`, και σενάρια ή επεξεργαστές που βρίσκουν το CLI στο `PATH`. Αλλάξτε με `omarchy agent account use work` (και πίσω με `omarchy agent account use main`), ή στον πίνακα πατώντας τον αριθμό ενός λογαριασμού και στη συνέχεια `Enter` (ή κάνοντας κλικ στο κουμπί Use του). Οι συνεδρίες Claude που εκτελούνται αλλάζουν επίσης, από το επόμενο μήνυμά τους: κάθε συνεδρία Claude εκτελείται στο `~/.claude`, το οποίο διατηρεί πάντα τη σύνδεση του ενεργού λογαριασμού. Μια συνεδρία Claude που ξεκίνησε στον δικό της φάκελο ενός λογαριασμού από ένα παλαιότερο Omarchy διατηρεί αυτή τη σύνδεση μέχρι να τερματιστεί, οπότε η εναλλαγή ονομάζει αυτές τις συνεδρίες και ολοκληρώνεται από μόνη της μόλις εξαφανιστούν. Οι συνεδρίες Codex και Grok που εκτελούνται παραμένουν στον λογαριασμό με τον οποίο ξεκίνησαν. Το ιστορικό συνομιλιών, οι ρυθμίσεις, οι δεξιότητες και τα πρόσθετα μοιράζονται μεταξύ λογαριασμών, οπότε το `claude --continue` στον ίδιο φάκελο συνεχίζει από εκεί που σταματήσατε στον νέο λογαριασμό.

Με περισσότερους από έναν λογαριασμούς, ο πίνακας εμφανίζει τα όρια κάθε λογαριασμού δίπλα-δίπλα, με τον ενεργό επισημασμένο. Το Omarchy σας ειδοποιεί όταν ο ενεργός λογαριασμός ξεπεράσει το 95% ενός ορίου, και κάνοντας κλικ στην ειδοποίηση μεταβαίνετε στον λογαριασμό με το περισσότερο περιθώριο. Ποτέ δεν αλλάζει από μόνο του. Αλλάξτε το όριο με `omarchy agent account threshold 90`. Εάν κάθε λογαριασμός υπερβαίνει το όριο, θα ενημερωθείτε μία φορά, μαζί με το ποιος λογαριασμός ελευθερώνεται πρώτος. Ενώ ένας ενεργός λογαριασμός βρίσκεται εντός 15 μονάδων από το όριό του (80% στην προεπιλογή), τα όριά του ελέγχονται κάθε τρία λεπτά αντί για κάθε 15.

Το `omarchy agent account list` εμφανίζει κάθε λογαριασμό και τα τελευταία όριά του, το `omarchy agent account remove work` ξεχνά έναν, και το `omarchy agent account rename primary Hey` μετονομάζει έναν (ή κάντε κλικ στο όνομα ενός λογαριασμού στον πίνακα). Αυτές οι εντολές λειτουργούν στους λογαριασμούς του προεπιλεγμένου agent σας. Για να φτάσετε στον άλλο πάροχο, ονομάστε τον πρώτα, όπως στο `omarchy agent account use codex side`. Η σύνδεση που είχατε ήδη στο `~/.claude` ή στο `~/.codex` είναι ο λογαριασμός _Main_. Του Codex παραμένει εκεί που είναι. Του Claude περιμένει σε δικό του φάκελο ενώ ένας άλλος λογαριασμός είναι ενεργός. Ένας λογαριασμός που μένει αχρησιμοποίητος για περισσότερες από περίπου οκτώ ώρες μπορεί να εμφανίσει _Sign-in required_. Κάντε κλικ σε αυτόν για να συνδεθείτε ξανά σε αυτόν τον λογαριασμό ακριβώς στον πίνακα, ή μεταβείτε σε αυτόν και ξεκινήστε μια συνεδρία, η οποία ανανεώνει τη σύνδεση από μόνη της. Οι διακομιστές MCP που προσθέτετε με `claude mcp add` φτάνουν σε κάθε λογαριασμό Claude, αφού όλοι εκτελούνται στο `~/.claude`. Για Codex και Grok, οι διακομιστές που είχατε όταν προστέθηκε ένας λογαριασμός έρχονται μαζί του, αλλά οι μεταγενέστεροι φτάνουν μόνο στον λογαριασμό στον οποίο τους προσθέσατε. Το Claude Desktop διατηρεί δική του σύνδεση, και τα εργαλεία Codex ή Grok που έχουν ρυθμιστεί με απόλυτη διαδρομή προς ένα δυαδικό CLI δεν ακολουθούν την εναλλαγή. Ένα ρητό `CLAUDE_CONFIG_DIR`, `CODEX_HOME` ή `GROK_HOME` υπερισχύει του επιλεγμένου λογαριασμού.

### Διάγνωση κατάρρευσης

Το Omarchy παρακολουθεί το systemd-coredump για καταρρεύσεις διεργασιών. Μόλις επιλέξετε έναν προεπιλεγμένο agent, οποιοδήποτε δικό σας πρόγραμμα που δημιουργεί core dump φέρνει μια ειδοποίηση «Process crashed» — κάντε κλικ σε αυτήν και η κατάρρευση παραδίδεται στον προεπιλεγμένο agent σας μαζί με την δεξιότητα omarchy-diagnose-crash του Omarchy, η οποία καθοδηγεί τον agent στη διαπίστωση των γεγονότων από το core dump και στην απόφαση για το εάν η κατάρρευση αξίζει να αναφερθεί upstream. Μπορείτε επίσης να την εκτελέσετε χειροκίνητα για οποιοδήποτε PID από το `coredumpctl list` με `omarchy agent crash <pid>`.

Η παρακολούθηση είναι ενεργή από προεπιλογή. Απενεργοποιήστε την στην ενότητα _Trigger > Toggle > Crash Capture Off_ (ή με `omarchy toggle crash-capture`) και οι ειδοποιήσεις σταματούν. Το `omarchy agent crash <pid>` εξακολουθεί να λειτουργεί χειροκίνητα.

Οι καταρρεύσεις μπορούν επίσης να σιγαστούν ένα πρόγραμμα κάθε φορά, πράγμα που σας προσφέρει η διάγνωση στο τέλος. Το `omarchy crash mute hyprland` σταματά τις ειδοποιήσεις μόνο για αυτό το πρόγραμμα, το `omarchy crash mute hyprland off` τις επαναφέρει, και το `omarchy crash mute` από μόνο του παραθέτει όσα έχετε σιγάσει. Δέχεται τη διαδρομή του δυαδικού εξίσου ευχαρίστως με το όνομά του, οπότε το `omarchy crash mute /usr/bin/hyprland` κάνει το ίδιο πράγμα. Βάλτε σε εισαγωγικά ένα όνομα με κενό, όπως στο `omarchy crash mute 'Some App'`. Όλα τα υπόλοιπα εξακολουθούν να ειδοποιούν, και το σιγασμένο πρόγραμμα εξακολουθεί να καταρρέει — αυτό κρύβει την υπενθύμιση, δεν διορθώνει τίποτα.

### Εφαρμογές επιφάνειας εργασίας

Το μενού _Install > AI_ περιλαμβάνει επίσης μερικές γραφικές εφαρμογές AI: Amp Desktop, Antigravity Desktop, την εφαρμογή επιφάνειας εργασίας ChatGPT, την εφαρμογή επιφάνειας εργασίας Claude (τη beta για Linux της Anthropic, με καρτέλες Chat, Cowork και Claude Code), Grok Bot για συνομιλία με τα μοντέλα της xAI, Herdr Desktop, Hermes Desktop, OpenClaw, την εφαρμογή επιφάνειας εργασίας Perplexity και T3 Code. Το Grok Bot είναι η εφαρμογή συνομιλίας επιφάνειας εργασίας. Ο coding agent είναι η εντολή `grok`.

Το Hermes Desktop είναι αυτό που πρέπει να γνωρίζετε, επειδή ένα μηχάνημα έχει ένα Hermes, και είναι της εφαρμογής: το Hermes εγκαθίσταται μόνο ποτέ μέσω της εφαρμογής, και η εντολή `hermes` που εκτελεί ο προεπιλεγμένος agent είναι της εφαρμογής. Η επιλογή του Hermes ως προεπιλεγμένου agent εγκαθιστά το ίδιο πράγμα που κάνει η καταχώριση _Install > AI_: το πακέτο, και ένα περιβάλλον εκτέλεσης Hermes στο `~/.hermes` που εγκαθίσταται από το ίδιο το πρόγραμμα εγκατάστασης του Hermes, το οποίο χρειάζεται μερικά λεπτά την πρώτη φορά. Αυτό το περιβάλλον εκτέλεσης είναι το ένα Hermes που χρησιμοποιούν η εντολή τερματικού `hermes`, ο προεπιλεγμένος agent και η εφαρμογή, και ενημερώνεται μόνο του με `hermes update` αντί να περιμένει μια έκδοση του Omarchy. Η εγκατάστασή του παραδίδει επίσης στο Hermes το θέμα του Omarchy ως ένα skin με όνομα `omarchy`, το οποίο ακολουθεί κάθε επιφάνεια του Hermes καθώς αλλάζετε θέματα. Επιλέξτε άλλο στις ρυθμίσεις Appearance του Hermes ή με `/skin` εάν προτιμάτε να μην το κάνει, και το Omarchy αφήνει αυτή την επιλογή ήσυχη. Η αφαίρεση της εφαρμογής στην ενότητα _Remove > AI_ κλείνει πρώτα το Hermes, συμπεριλαμβανομένης της πύλης, παίρνει αυτό το περιβάλλον εκτέλεσης μαζί της και διατηρεί τις συνομιλίες, τις μνήμες και τις δεξιότητες που έγραψε το Hermes για τον εαυτό του, εκτός εάν του πείτε διαφορετικά: ρωτά, με προεπιλογή το όχι, εάν αυτά τα δεδομένα και οι ρυθμίσεις σύνδεσής σας πρέπει να φύγουν επίσης.

Η εμπειρία επιφάνειας εργασίας του OpenClaw είναι το Control UI του, το οποίο ανοίγει ως web εφαρμογή που υποστηρίζεται από τη δική του τοπική πύλη. Το OpenClaw ζει στο `~/.openclaw` και ενημερώνεται μόνο του: χρησιμοποιήστε το κουμπί «Update Gateway» του Control UI ή εκτελέστε `openclaw update`, και η πύλη επανεκκινείται στη νέα έκδοση. Το Omarchy επιλέγει μόνο την έκδοση από την οποία ξεκινά μια φρέσκια εγκατάσταση. Το OpenClaw μπορεί επίσης να είναι ο προεπιλεγμένος agent σας: η επιλογή του στην ενότητα _Agent > Harness_ εγκαθιστά αυτό το ίδιο αντίγραφο στο `~/.openclaw`, και ο agent ανοίγει το terminal UI του OpenClaw συνδεδεμένο στην πύλη του. Η αφαίρεση του OpenClaw στην ενότητα _Remove > AI_ παίρνει την υπηρεσία πύλης και την εφαρμογή μαζί της και στη συνέχεια ρωτά εάν το `~/.openclaw` πρέπει να φύγει επίσης, αφού αυτό διατηρεί τις συνομιλίες και τα διαπιστευτήριά σας δίπλα στο ίδιο το OpenClaw και τα περιβάλλοντα εκτέλεσης προσθέτων που κατεβάζει. Η προεπιλογή το διατηρεί, και η εκ νέου εγκατάσταση του OpenClaw το ξαναπαίρνει.

Το Herdr Desktop είναι η εφαρμογή επιφάνειας εργασίας [Herdr](https://herdr.dev): χώροι, καρτέλες και πλαίσια τερματικών και coding agents που συνεχίζουν να εκτελούνται στον πυρήνα του όταν κλείνετε το παράθυρο. Προέρχεται από το ίδιο το πρόγραμμα εγκατάστασης του Herdr αντί για ένα πακέτο, οπότε ζει στο `~/.local/share/herdr-app`, φέρνει τον πυρήνα του στο `~/.local/bin/herdr-core` όταν δεν έχετε ακόμα έναν, και ενημερώνει και τα δύο μόνο του. Βρίσκεται δίπλα στην εντολή `herdr` που παρέχει το Omarchy στο `Super + Ctrl + Return` αντί να την αντικαθιστά, και αποκτά τα απευθείας πλήκτρα αυτής της εντολής: τα `Alt + Return` και `Alt + Shift + Return` διαιρούν ένα πλαίσιο προς τα κάτω ή προς τα δεξιά, το `Alt + Escape` το κλείνει, το `Ctrl + Alt + Arrow` μετακινείται μεταξύ πλαισίων, τα `Alt + 1..9` και `Alt + Left/Right` επιλέγουν μια καρτέλα, και τα `Alt + Up/Down` μετακινούνται μεταξύ χώρων. Το `Ctrl + 1..9` επιλέγει έναν χώρο και τα `Alt + Shift + Up/Down` περνούν από τους agents. Τα πλήκτρα προθέματος `Ctrl + Space` παραμένουν μόνο για τερματικό, αφού η εφαρμογή δεν μπορεί να κρατήσει ένα απλό πλήκτρο Ctrl για μια ακολουθία. Το Omarchy τα γράφει στο `~/.config/herdr-app/keys.json`, και το `omarchy-refresh-herdr-app` τα επαναφέρει. Η εγκατάστασή του επιλέγει το θέμα Omarchy του Herdr, το οποίο ακολουθεί από τότε το θέμα Omarchy σας. Το Herdr διατηρεί ένα θέμα για τη φωτεινή λειτουργία και ένα για τη σκοτεινή, οπότε αφού αλλάξετε μεταξύ ενός σκοτεινού και ενός φωτεινού θέματος Omarchy, επιλέξτε Omarchy στον επιλογέα θέματος του Herdr άλλη μία φορά για την άλλη λειτουργία.

Το T3 Code εκτελείται από την επίσημη έκδοση AppImage του στο `~/.local/share/t3code` αντί από ένα πακέτο, οπότε ενημερώνεται μόνο του. Η εγκατάστασή του ρωτά εάν θα ξεκινήσει στο κανάλι Stable ή Nightly. Αλλάξτε αργότερα στις ρυθμίσεις του T3 Code. Τα νήματα και οι ρυθμίσεις σας ζουν στο `~/.t3`, και η αφαίρεση του T3 Code στην ενότητα _Remove > AI_ τα παίρνει μαζί της.

### Τοπικά μοντέλα

Εκτελέστε ένα ανοιχτό μοντέλο στο δικό σας μηχάνημα για τους coding agents σας. Οι προτροπές και ο κώδικάς σας παραμένουν στο μηχάνημα. Τίποτα που στέλνεται στο μοντέλο δεν το εγκαταλείπει. Ξεκινήστε με:

```bash
omarchy models use best text
```

Αυτό εγκαθιστά το καλύτερο μοντέλο κειμένου για αυτό το μηχάνημα, το είδος που χρησιμοποιούν οι agents σας. Τα μοντέλα εικόνας, βίντεο και μουσικής έχουν το δικό τους καλύτερο: `omarchy models use best image`, `video` ή `music`. Εκτελέστε `omarchy models use best` για να δείτε την επιλογή κάθε είδους για αυτό το μηχάνημα.

Ή ανοίξτε τον πίνακα τοπικών μοντέλων από το εικονίδιο με τα αστράκια στην επάνω γραμμή, δίπλα στο εικονίδιο agents, ή με Super + Ctrl + Alt + X, και επιλέξτε +. Το εικονίδιο εμφανίζεται όταν ένα μοντέλο ταιριάζει σε αυτό το μηχάνημα. Το Podman, το οποίο εκτελεί τα μοντέλα, έρχεται με το Omarchy, όπως και το κιτ εργαλείων container της NVIDIA σε ένα μηχάνημα NVIDIA, το οποίο τους δίνει το GPU. Εάν κάποιο από τα δύο λείπει, η πρώτη εγκατάσταση το εγκαθιστά. Το Omarchy στη συνέχεια επιλέγει το συνιστώμενο μοντέλο για αυτό το μηχάνημα, το κατεβάζει και το ξεκινά. Να περιμένετε μια λήψη δεκάδων GB και το μεγαλύτερο μέρος της μνήμης του μηχανήματος να χρησιμοποιείται ενώ το μοντέλο εκτελείται: το Flash Next χρησιμοποιεί περίπου 100 GiB με το πλήρες περιεχόμενό του 256K. Εάν άλλα μοντέλα κρατούν τη μνήμη που χρειάζεται, εγκαθίσταται σταματημένο, έτοιμο να ξεκινήσει μόλις σταματήσετε ένα. Το μοντέλο σταματά κατά την αποσύνδεση. Σταματήστε το μόνοι σας όταν χρειάζεστε τη μνήμη για κάτι άλλο.

Το `omarchy models list` εμφανίζει τις επιλογές και εξηγεί γιατί μερικές δεν ταιριάζουν. Για να εγκαταστήσετε άλλο ένα, εκτελέστε `omarchy models use <recipe>`. Σήμερα, τα `qwen3.8-flash-next-gufo` και `qwen3.8-27b-gufo` είναι διαθέσιμα για μηχανήματα Strix Halo 128 GB. Το 27B χρειάζεται περίπου 40 GiB, οπότε αφήνει χώρο για άλλη εργασία. Σε ένα laptop 64 GB με Intel Arc B390, το `qwen3.6-35b-a3b-llamacpp` εκτελείται σε περίπου 30 GiB. Νέες συνταγές και συστάσεις φτάνουν με το `omarchy update`, μέσω του πακέτου.

Κάθε μοντέλο που εγκαθιστάτε αποκτά τη δική του γραμμή στον πίνακα τοπικών μοντέλων: αναπαραγωγή για να το ξεκινήσετε, παύση για να το σταματήσετε και να ελευθερώσετε τη μνήμη του, και το κουμπί τερματικού για να ανοίξετε τον agent σας σε αυτό. Στο επάνω μέρος, μια γραμμή δείχνει πώς η μνήμη του μηχανήματος μοιράζεται μεταξύ του ίδιου του Omarchy (του συστήματος και των εφαρμογών σας), κάθε μοντέλου που εκτελείται, και όσων είναι ελεύθερα. Τοποθετήστε τον δείκτη σε ένα σταματημένο μοντέλο και η γραμμή δείχνει εάν χωράει ή πόσο του λείπει. Πολλά μπορούν να εκτελούνται ταυτόχρονα όταν χωρούν μαζί στη μνήμη. Εάν ένα δεν χωράει, το Omarchy λέει ποιο μοντέλο που εκτελείται να σταματήσετε. Σύρετε γραμμές από το λογότυπό τους για να τις αναδιατάξετε, και πατήστε Delete σε μια επιλεγμένη γραμμή για να αφαιρέσετε ένα μοντέλο και τη λήψη του.

Κάθε coding μοντέλο που εγκαθιστάτε αποκτά επίσης τη δική του καταχώριση στον εκκινητή εφαρμογών, με το όνομα του μοντέλου και με το λογότυπο του κατασκευαστή του, με τον τρόπο που η σύνδεση σε Claude, Codex ή Grok προσθέτει μία. Ανοίγει τον agent σας σε αυτό το μοντέλο και ξεκινά πρώτα το μοντέλο εάν δεν εκτελείται: το τερματικό το δείχνει να φορτώνει και παραδίδει στον agent μόλις είναι έτοιμο. Η αφαίρεση ενός μοντέλου αφαιρεί την καταχώρισή του.

Δεν είναι κάθε μοντέλο για coding. Τα μοντέλα εικόνας, βίντεο και μουσικής ανοίγουν αντί γι' αυτό στο Fantasi, την εφαρμογή του Omarchy για τη δημιουργία εικόνων, βίντεο και μουσικής με ένα μοντέλο που εκτελείται σε αυτό το μηχάνημα, επιλεγμένο εκεί ή από τη γραμμή τους στον πίνακα τοπικών μοντέλων.

Ένα μοντέλο συνεχίζει να εκτελείται ακριβώς όπως εγκαταστάθηκε, οπότε μια ενημέρωση του Omarchy ποτέ δεν επανεκκινεί ένα κάτω από τους agents σας. Όταν το Omarchy έχει νεότερο περιβάλλον εκτέλεσης ή νεότερα βάρη για ένα μοντέλο που έχετε εγκαταστήσει, η γραμμή του εμφανίζει ένα κουμπί ενημέρωσης: πατήστε το και το μοντέλο εγκαθίσταται ξανά στο παρασκήνιο, κατεβάζοντας μόνο όσα άλλαξαν, και επανεκκινείται στη νέα έκδοση. Ένα μοντέλο που ήταν σταματημένο παραμένει σταματημένο. Το `omarchy models update` κάνει το ίδιο για κάθε μοντέλο από ένα τερματικό.

Από τη γραμμή εντολών, τα `omarchy models start <recipe>` και `omarchy models stop <recipe>` κάνουν το ίδιο, το `omarchy models status` εμφανίζει κάθε μοντέλο, και το `omarchy agent --local` ανοίγει το τελευταίο μοντέλο που ξεκινήσατε στο pi, όποιος κι αν είναι ο προεπιλεγμένος agent σας. Τα OpenCode και Qwen Code μπορούν επίσης να χρησιμοποιήσουν ένα τοπικό μοντέλο: το `omarchy models harness opencode` ή το `omarchy models harness qwen` τα ανοίγει εκεί αντί γι' αυτό, και το `omarchy models harness pi` επιστρέφει. Το pi παραθέτει επίσης κάθε μοντέλο που έχετε εγκαταστήσει, και εκείνα σε μηχανήματα με τα οποία έχετε συνδεθεί, στον δικό του επιλογέα μοντέλου, οπότε το απλό `pi` τα φτάνει επίσης. Οποιοσδήποτε client συμβατός με OpenAI μπορεί επίσης να συνδεθεί: το `status` εμφανίζει τη διεύθυνση κάθε μοντέλου (η πρώτη είναι `http://127.0.0.1:11435/v1`), το όνομα της συνταγής είναι το μοντέλο, και το κλειδί βρίσκεται στο `~/.config/omarchy/agent-local/key`.

Το `omarchy models remove <recipe>` διαγράφει ένα μοντέλο και τις λήψεις που κανένα άλλο μοντέλο δεν χρησιμοποιεί.

Τα περιβάλλοντα εκτέλεσης τρίτων επισημαίνονται με τον εκδότη τους. Το Omarchy εκτελεί κάθε μοντέλο χωρίς πρόσβαση στο δίκτυο.

### Τοπικά LLMs

Το Omarchy συνιστά δύο τρόπους εκτέλεσης τοπικών μοντέλων LLM: LM Studio και Ollama. Το LM Studio παρέχει ένα GUI περιβάλλον για την εύρεση μοντέλων ανοιχτών βαρών, την εγκατάστασή τους και την εκτέλεσή τους. Είναι ένας εξαιρετικός τρόπος να ξεκινήσετε εύκολα. Το Ollama προσφέρει ένα CLI για να κάνετε το ίδιο με παρόμοιο τρόπο. Αλλά εάν είστε νέοι στα τοπικά μοντέλα, θα ξεκινούσα με το LM Studio. Μπορείτε να εγκαταστήσετε οποιοδήποτε από τα δύο στην ενότητα _Install > AI_ στο Omarchy Menu.

### Οι δεξιότητες του Omarchy

Οι δεξιότητες agent βοηθούν την AI να χρησιμοποιεί συγκεκριμένα εργαλεία με συγκεκριμένο τρόπο, και το Omarchy παρέχει επτά από αυτές. Η δεξιότητα omarchy καλύπτει την προσαρμογή του συστήματος, όπως την τροποποίηση της διαμόρφωσης Hyprland σας ή την προσαρμογή της γραμμής. Οι omarchy-make-theme, omarchy-make-plugin, omarchy-make-app και omarchy-make-game καλύπτουν τη δημιουργία κάτι νέου, η omarchy-contribute καλύπτει την αναφορά ενός σφάλματος ή την αποστολή μιας διόρθωσης upstream, και η omarchy-diagnose-crash επεξεργάζεται το core dump μιας κατάρρευσης. Συνδέονται με συμβολικούς συνδέσμους στους καταλόγους δεξιοτήτων για Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` και κάθε `~/.hermes/profiles/*/skills`), και τη γενική τοποθεσία `~/.agents/skills`, οπότε τα περισσότερα harnesses τις παραλαμβάνουν αυτόματα. Ένας δικός σας φάκελος δεξιοτήτων με το ίδιο όνομα έχει προτεραιότητα.

Αλλά πρέπει να αντιμετωπίζετε αυτές τις δεξιότητες ως πειραματικές. Διαφορετικά μοντέλα θα τις χρησιμοποιήσουν με διαφορετικό αποτέλεσμα. Είναι καλύτερο να εκτελείτε πρώτα σε λειτουργία σχεδιασμού, ώστε να έχετε μια ιδέα για το τι θα ήθελε να αλλάξει ο agent. Και μετά να είστε έτοιμοι να επαναφέρετε αλλαγές ή ακόμη και να επικαλεστείτε `omarchy reinstall configs`, εάν ο agent τα κάνει όλα άνω κάτω.
