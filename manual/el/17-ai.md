# AI

Το Omarchy περιλαμβάνει εκκινητές για τους παρακάτω agents κωδικοποίησης, χωρίς να επιλέγει κάποιον ως προεπιλογή για εσάς. Εκτελέστε μια εντολή για να εγκαταστήσετε το CLI της κατά την πρώτη χρήση και, στη συνέχεια, πραγματοποιήστε έλεγχο ταυτότητας όταν σας ζητηθεί. Το Hermes αποτελεί εξαίρεση: τίποτα δεν εγκαθίσταται γι' αυτό κατά την πρώτη χρήση και, αν το επιλέξετε, εγκαθίσταται το Hermes Desktop, όπως εξηγεί παρακάτω η ενότητα _Εφαρμογές desktop_.

### Εγκατάσταση και ενημέρωση agents

Εκτός από το Hermes, αυτοί οι agents χρησιμοποιούν την lazy εγκατάσταση του mise: η πρώτη εκκίνηση εγκαθιστά το CLI και οι επόμενες εκκινήσεις το επαναχρησιμοποιούν. Το mise ελέγχει επίσης έναν εγκατεστημένο agent για νέα έκδοση το πολύ μία φορά κάθε τέσσερις ώρες, λίγο πριν ξεκινήσει ή στο παρασκήνιο σε μια προτροπή shell. Αν αυτή η ενημέρωση αποτύχει ή είστε εκτός σύνδεσης, εκτελείται η εγκατεστημένη έκδοση. Η εντολή `omarchy update` ενημερώνει τους εγκατεστημένους agents μαζί με το υπόλοιπο Omarchy και η εντολή `mup` ενημερώνει μόνο τα εργαλεία που διαχειρίζεται το mise.

Το πρόγραμμα ενημέρωσης ενός agent, όπως το `claude update`, το `codex update` ή ένα κουμπί ενημέρωσης σε μια εφαρμογή, δεν ενημερώνει την εγκατάσταση που διαχειρίζεται το mise. Η εντολή `codex update` αποτυγχάνει και η εντολή `claude update` μπορεί να αναφέρει επιτυχία, ενώ εγκαθιστά ένα ξεχωριστό αντίγραφο που το mise δεν παρακολουθεί. Αν προτιμάτε να χρησιμοποιείτε το εγγενές πρόγραμμα εγκατάστασης και ενημέρωσης ενός agent, προσθέστε το στο `disable_tools`. Δείτε το [Προεγκατεστημένα εργαλεία CLI](18-development-tools.md#preinstalled-cli-tools).

Για να εγκαταστήσετε όλα τα ρυθμισμένα lazy εργαλεία πριν τα χρειαστείτε, εκτελέστε `mise install --include-lazy`. Αυτό περιλαμβάνει και τα άλλα προεπιλεγμένα εργαλεία CLI του Omarchy, καθώς και τους agents. Δείτε το [Προεγκατεστημένα εργαλεία CLI](18-development-tools.md#preinstalled-cli-tools) για την εγκατάσταση ενός μεμονωμένου εργαλείου ή τη χρήση δικής σας εγκατάστασης.

Το `grok` εγκαθίσταται μέσω του first-party πακέτου `grok` του mise, με τον ίδιο τρόπο όπως τα `claude` και `codex`. Εκτελέστε το `grok` ή επιλέξτε το στην ενότητα _Agent > Harness_. Παραλείψτε το πρόγραμμα εγκατάστασης `curl | bash` στο x.ai. Αυτή η διαδρομή τοποθετεί ένα δεύτερο αντίγραφο στο `~/.grok/bin`, το προσθέτει στην αρχή του `PATH` και αντικαθιστά το wrapper του Omarchy.

Το `dsh` ανοίγει το UI του προγράμματος περιήγησής του στο `127.0.0.1:3080`, με τον κατάλογο εκκίνησης ως προεπιλεγμένο χώρο εργασίας του. Το UI του προγράμματος περιήγησής του δεν δέχεται αρχική προτροπή, οπότε η εντολή `omarchy agent prompt` το ανοίγει με την προτροπή στο πρόχειρό σας για επικόλληση. Το Omarchy το ξεκινά με την προεπιλογή δικαιωμάτων χωρίς έγκριση της DeepSeek. Το DeepSeek Harness ανεβάζει αρχεία καταγραφής συνεδριών στην DeepSeek όταν χρησιμοποιείτε το επίσημο API μοντέλων της. Απενεργοποιήστε το στην ενότητα _Settings > General > Upload Session Log_ στο UI του προγράμματος περιήγησής του. Τα σχόλια που του στέλνετε ανεβαίνουν επίσης μαζί με τη συνεδρία, εκτός αν το ξεκινήσετε με `DSH_TELEMETRY_MODE=DISABLED`.

### Ο προεπιλεγμένος agent

Επιλέξτε τον προεπιλεγμένο agent σας με `omarchy default agent <name>` ή στην ενότητα _Agent > Harness_ στο Μενού Omarchy (`Super + Space`). Αν ο agent δεν έχει εγκατασταθεί ακόμη, η επιλογή του τον εγκαθιστά πρώτα. Μια νέα εγκατάσταση Omarchy θα σας καλέσει να κάνετε αυτή την επιλογή με μια εφάπαξ ειδοποίηση.

Η επιλογή του Claude επιχειρεί επίσης να ρυθμίσει την επέκταση προγράμματος περιήγησής του για τα Chromium, Chrome, Brave, Brave Origin και Edge. Η ρύθμιση της επέκτασης ισχύει για όλους τους χρήστες και ενδέχεται να ζητήσει τον κωδικό πρόσβασης του συστήματός σας. Η ακύρωση ή μια αποτυχημένη εγκατάσταση επέκτασης εξακολουθεί να επιλέγει και να εκκινεί το Claude. Επανεκκινήστε το πρόγραμμα περιήγησής σας, ενεργοποιήστε την επέκταση αν σας ζητηθεί και συνδεθείτε στο Claude για να ολοκληρώσετε τη σύνδεσή της. Εκτελέστε `/chrome` στο Claude για να ελέγξετε τη σύνδεση. Τα Firefox και Zen δεν υποστηρίζουν αυτή την επέκταση. Αν το Claude ήταν ήδη ο προεπιλεγμένος agent σας πριν προστεθεί αυτή η ρύθμιση, επιλέξτε το ξανά για να εγκαταστήσετε την επέκταση.

Αφού επιλέξετε, ο συνδυασμός `Super + Shift + Ctrl + A` εκκινεί τον προεπιλεγμένο agent σε ένα αποκλειστικό παράθυρο τερματικού (ή εμφανίζει τον επιλογέα αν δεν έχετε επιλέξει ακόμη). Μπορείτε επίσης να το εκκινήσετε απευθείας σε μια εργασία με `omarchy agent prompt "Review this project"`. Τα Freebuff και DeepSeek Harness δεν δέχονται αρχική προτροπή, οπότε ανοίγουν αντ' αυτού με την προτροπή στο πρόχειρό σας για επικόλληση. Οι agents που εκκινούνται με αυτόν τον τρόπο εκτελούνται χωρίς επίβλεψη στις αντίστοιχες λειτουργίες τους που δεν σταματούν για να ρωτήσουν, οπότε να είστε έτοιμοι να κάνουν πράγματα στην πράξη! Το MiniMax Code δεν διαθέτει τέτοια λειτουργία για τις διαδραστικές συνεδρίες του, οπότε ζητά δικαιώματα ως συνήθως. Και, επειδή οι agents αρνούνται να θυμούνται την εμπιστοσύνη για τον αρχικό κατάλογό σας, οι εκκινήσεις από το `$HOME` ξεκινούν αντ' αυτού στο `~/Work`.

Υπάρχουν και συντομεύσεις τερματικού: το `a` εκτελεί τον προεπιλεγμένο agent ενσωματωμένο στο τρέχον τερματικό, ενώ τα `c`, `cx` και `cy` ξεκινούν απευθείας τα OpenCode, Claude Code και Codex (ξανά στις λειτουργίες αυτόματης έγκρισής τους). Οι αλλαγές θέματος συγχρονίζονται επίσης στους agents: τα Claude Code, Pi, OpenCode και Hermes (αφού το Omarchy το έχει εγκαταστήσει) ακολουθούν όλα όταν αλλάζετε το θέμα Omarchy.

### Οι οδηγίες του agent σας

Οι προσωπικοί κανόνες για κάθε agent μπαίνουν στο `~/.agents/AGENTS.md`, δίπλα στις κοινόχρηστες δεξιότητες στο `~/.agents/skills`. Ανοίξτε το στην ενότητα _Agent > Instructions_, η οποία το συνδέει επίσης σε κάθε harness που διατηρεί το δικό του καθολικό αρχείο: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, το `~/.copilot/copilot-instructions.md` του Copilot και ούτω καθεξής. Τα Crush και Amp διαβάζουν τον σύνδεσμο `~/.config/AGENTS.md`, ενώ τα omp, Kimi και DeepSeek Harness διαβάζουν απευθείας το `~/.agents/AGENTS.md`. Η επιλογή ενός προεπιλεγμένου agent το συνδέει επίσης. Ένα αρχείο οδηγιών που είχατε ήδη γίνεται το κοινόχρηστο, αν δεν υπήρχε ακόμη κανένα. Διαφορετικά, διατηρείται δίπλα στον σύνδεσμο ως `.bak`. Εκτελέστε `omarchy agent instructions` για να επανασυνδέσετε αφού εγκαταστήσετε άλλον agent.

### Το πάνελ agents

Η επάνω γραμμή έχει ένα εικονίδιο agents. Πριν ρυθμίσετε έναν agent, το πάνελ του σάς καθοδηγεί στη σύνδεση στα Claude, Codex ή Grok και το πρώτο γίνεται ο προεπιλεγμένος agent σας. Μετά από αυτό, το πάνελ τοποθετεί κάθε συνδρομή σε μία σελίδα: κάθε agent και λογαριασμό με το πρόγραμμά του, έναν μετρητή για κάθε ένα από τα όρια συνεδρίας 5 ωρών και εβδομαδιαία όριά του με τον χρόνο μέχρι να γίνει επαναφορά (τοποθετήστε τον δείκτη για το ακριβές ποσοστό) ή το υπόλοιπο προπληρωμένο υπόλοιπο, κάτω από μια γραμμή που εναλλάσσεται κυκλικά ανάμεσα σε όσα έχετε χρησιμοποιήσει σε όλα αυτά, όπως tokens αυτή την εβδομάδα και το μοντέλο που χρησιμοποιείτε περισσότερο. Στην ενότητα _Make something_ προσφέρει αρχικές προτροπές για ένα νέο θέμα, πρόσθετο, εφαρμογή ή παιχνίδι που παραδίδουν την εργασία στον προεπιλεγμένο agent σας. Οι εφαρμογές δημιουργούνται με τον τρόπο που δημιουργούνται τα δικά του Omarchy Hype, Monologue και Omacut, σε C++ και Qt Quick, ακολουθώντας τη δεξιότητα agent omarchy-app, και ο μεταγλωττιστής και τα τμήματα Qt που χρειάζονται παρέχονται εγκατεστημένα. Τα παιχνίδια είναι μία μόνο σελίδα three.js στο `~/Games/vibes`, ακολουθώντας τη δεξιότητα agent web-game, και όλα ανοίγουν από έναν εκκινητή Game Vibes στο τρέχον θέμα. Φορτώνουν το three.js από τον ιστό, οπότε χρειάζονται σύνδεση για να ξεκινήσουν. Τα Claude Code, Codex, Grok, Kimi, Cursor και η παροχή Grok Bot του, GitHub Copilot, Muse, Antigravity, Kimchi και Devin καλύπτονται εξαρχής με τα όριά τους, ενώ τα Hermes, Mistral Vibe και Qwen Code εμφανίζουν τις συνεδρίες και τα tokens τους αφού τα χρησιμοποιήσετε. Τα προγράμματα και τα κλειδιά παρόχων που χρησιμοποιείτε μέσω των pi, omp ή opencode εμφανίζονται επίσης: τα OpenCode Zen και Go, το Z.ai GLM Coding Plan, το Ollama Cloud, το MiniMax Token Plan και το Synthetic με τα όριά τους, τα Fireworks, OpenRouter και DeepSeek με τα προπληρωμένα υπόλοιπά τους και τα μοντέλα που εκτελείτε στο δικό σας υλικό στην ενότητα Local models. Κάθε agent μετράται μία φορά, σε όποιον τον χρεώνει, ανεξάρτητα από το πόσα harnesses χρησιμοποιείτε για να τον οδηγείτε.

Κάντε αριστερό κλικ στο εικονίδιο της γραμμής για το πάνελ, δεξί κλικ για να εκκινήσετε τον προεπιλεγμένο agent σας. Τα αρχεία χρήσης πίσω από αυτό αναδημιουργούνται κάθε 15 λεπτά από την εντολή `omarchy agent usage-update` και το πάνελ μπορεί ακόμη και να συγχωνεύσει χρήση από τα άλλα μηχανήματά σας μέσω ενός συγχρονισμένου φακέλου. Δείτε το README στο `$OMARCHY_PATH/shell/plugins/agents/` για τις πλήρεις ρυθμίσεις.

### Πολλαπλές συνδρομές

Αν πληρώνετε για περισσότερα από ένα προγράμματα Claude, Codex ή Grok — ένα προσωπικό Max και ένα επαγγελματικό, ας πούμε — το Omarchy μπορεί να τα διατηρεί όλα συνδεδεμένα και να μετακινείται ανάμεσά τους. Προσθέστε μια συνδρομή με το + στο πάνελ agents, το οποίο σας καθοδηγεί εκεί επιτόπου, ή με `omarchy agent account add claude Work` (ή `codex` ή `grok`). Εγκαθιστά το CLI αν λείπει. Ο πρώτος λογαριασμός για έναν πάροχο συνδέεται μέσω του κανονικού προγράμματος περιήγησής σας, ακριβώς εκεί όπου το CLI αναζητά πάντα. Κάθε επόμενος συνδέεται μέσω ενός ιδιωτικού παραθύρου, ώστε ο λογαριασμός στον οποίο το πρόγραμμα περιήγησής σας είναι ήδη συνδεδεμένο να μην επιλεγεί κατά λάθος. Συνδεθείτε εκεί ως ο λογαριασμός που προσθέτετε και κλείστε πρώτα οποιοδήποτε ιδιωτικό παράθυρο είχατε ήδη ανοιχτό. Μην αποσυνδέεστε ποτέ από το CLI για να το κάνετε αυτό: η αποσύνδεση ανακαλεί την αποθηκευμένη σύνδεση και αυτός ο λογαριασμός θα έπρεπε να προστεθεί ξανά.

Για να αντιγράψετε τις συνδέσεις συνδρομών σας σε άλλο μηχάνημα Omarchy μέσω SSH, εκτελέστε `omarchy agent account copy user@laptop`. Ο αποστολέας παρέχει έναν προσωρινό παραλήπτη όταν ο προορισμός δεν έχει εγκατεστημένο κάποιον, οπότε παλαιότερα μηχανήματα Omarchy μπορούν να λάβουν λογαριασμούς χωρίς ενημέρωση. Οι εγκατεστημένοι παραλήπτες έχουν προτεραιότητα. Αυτό αντιγράφει όλες τις συνδρομές Claude, Codex και Grok. Προσθέστε ονόματα παρόχων για να τις επιλέξετε, όπως στο `omarchy agent account copy laptop claude`. Τα ονόματα λογαριασμών και τα αναγνωριστικά εντολών ταιριάζουν με την πηγή, συμπεριλαμβανομένων λογαριασμών που υπάρχουν ήδη στον προορισμό. Οι άσχετοι λογαριασμοί προορισμού λαμβάνουν ένα αριθμητικό επίθημα αν τα ονόματά τους συγκρούονται και οι ρυθμίσεις, οι δεξιότητες, τα πρόσθετα και το ιστορικό συνομιλιών παραμένουν τοπικά σε κάθε μηχάνημα.

Τα υπάρχοντα διαπιστευτήρια προορισμού διατηρούνται. Ένας λογαριασμός πηγής που είναι ήδη συνδεδεμένος εκεί έχει το όνομά του συγχρονισμένο χωρίς να αντικατασταθούν τα διαπιστευτήριά του. Οι άλλοι λογαριασμοί προστίθενται δίπλα του. Για να αντικαταστήσετε τα αποθηκευμένα διαπιστευτήρια για λογαριασμούς που ταιριάζουν, χρησιμοποιήστε `omarchy agent account copy --replace laptop claude` αφού κλείσετε τις συνεδρίες αυτού του λογαριασμού στον προορισμό. Ένας νέος προορισμός λαμβάνει επίσης τον ενεργό λογαριασμό και τις προτιμήσεις εναλλαγής της πηγής. Ένας καθιερωμένος προορισμός διατηρεί τις δικές του.

Τα διαπιστευτήρια ταξιδεύουν μέσω SSH και αποθηκεύονται σε ιδιωτικά αρχεία στον προορισμό, οπότε αντιγράφετε μόνο σε μηχανήματα που εμπιστεύεστε. Αυτή είναι μια εφάπαξ αντιγραφή, όχι συνεχής συγχρονισμός. Τα tokens ανανέωσης του Codex μπορούν να εναλλαχθούν από άλλο μηχάνημα, αφήνοντας μια αντιγραμμένη σύνδεση να χρειάζεται ανανέωση. Οι ξεχωριστές συνδέσεις παραμένουν η πιο αξιόπιστη επιλογή για ταυτόχρονη χρήση σε πολλά μηχανήματα. Δείτε την [Οδηγία ελέγχου ταυτότητας λογαριασμού του Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Ένας λογαριασμός ανά πάροχο είναι ενεργός και κάθε νέα συνεδρία ξεκινά ως αυτός: `cx`, `cy`, ένα απλό `claude`, `codex` ή `grok`, οτιδήποτε εκκινείται μέσω του `omarchy agent` και σενάρια ή προγράμματα επεξεργασίας που βρίσκουν το CLI στο `PATH`. Αλλάξτε με `omarchy agent account use work` (και επιστρέψτε με `omarchy agent account use main`) ή στο πάνελ πατώντας τον αριθμό ενός λογαριασμού και στη συνέχεια `Enter` (ή κάνοντας κλικ στο κουμπί Use του). Οι συνεδρίες Claude που εκτελούνται αλλάζουν επίσης, από το επόμενο μήνυμά τους: κάθε συνεδρία Claude εκτελείται στο `~/.claude`, το οποίο διατηρεί πάντα τη σύνδεση του ενεργού λογαριασμού. Μια συνεδρία Claude που ξεκίνησε στον δικό της φάκελο ενός λογαριασμού από ένα παλαιότερο Omarchy διατηρεί αυτή τη σύνδεση μέχρι να κλείσει, οπότε η εναλλαγή ονομάζει αυτές τις συνεδρίες και ολοκληρώνεται από μόνη της μόλις εξαφανιστούν. Οι συνεδρίες Codex και Grok που εκτελούνται παραμένουν στον λογαριασμό με τον οποίο ξεκίνησαν. Το ιστορικό συνομιλιών, οι ρυθμίσεις, οι δεξιότητες και τα πρόσθετα είναι κοινόχρηστα μεταξύ λογαριασμών, οπότε το `claude --continue` στον ίδιο φάκελο συνεχίζει από εκεί που σταματήσατε στον νέο λογαριασμό.

Με περισσότερους από έναν λογαριασμούς, το πάνελ εμφανίζει τα όρια κάθε λογαριασμού δίπλα-δίπλα, με τον ενεργό σημειωμένο. Από προεπιλογή, το Omarchy σας ειδοποιεί όταν ο ενεργός λογαριασμός ξεπεράσει το 95% ενός ορίου και, αν κάνετε κλικ στην ειδοποίηση, μεταβαίνει στον λογαριασμό με το μεγαλύτερο περιθώριο. Τοποθετήστε τον δείκτη πάνω από τη γραμμή ενός λογαριασμού στο πάνελ και κάντε κλικ στο Autoswitch που εμφανίζεται δίπλα στο Use (ή πατήστε `m`) ή εκτελέστε `omarchy agent account mode auto`, για να γίνεται η εναλλαγή από μόνη της. Ενώ είναι ενεργό, το Autoswitch παίρνει τη θέση του Use και, αν το κάνετε ξανά κλικ, επιστρέφει στην ειδοποίηση. Προσθέστε έναν αριθμό για να αλλάξετε το όριο, όπως στο `omarchy agent account mode auto 90`. Αν κάθε λογαριασμός υπερβαίνει το όριο, θα ενημερωθείτε μία φορά, μαζί με το ποιος λογαριασμός ελευθερώνεται πρώτος. Ενώ ένας ενεργός λογαριασμός βρίσκεται εντός 15 μονάδων από το όριό του (80% στην προεπιλογή), τα όριά του ελέγχονται κάθε τρία λεπτά και όχι κάθε 15.

Η εντολή `omarchy agent account list` εμφανίζει κάθε λογαριασμό και τα τελευταία όριά του, η `omarchy agent account remove work` ξεχνά έναν και η `omarchy agent account rename primary Hey` μετονομάζει έναν (ή κάντε κλικ στο όνομα ενός λογαριασμού στο πάνελ). Αυτές οι εντολές λειτουργούν στους λογαριασμούς του προεπιλεγμένου agent σας. Για να φτάσετε στον άλλο πάροχο, ονομάστε τον πρώτα, όπως στο `omarchy agent account use codex side`. Η σύνδεση που είχατε ήδη στο `~/.claude` ή στο `~/.codex` είναι ο λογαριασμός _Main_. Του Codex παραμένει εκεί που είναι. Του Claude περιμένει σε δικό του φάκελο ενώ ένας άλλος λογαριασμός είναι ενεργός. Ένας λογαριασμός που μένει αχρησιμοποίητος για περισσότερες από περίπου οκτώ ώρες μπορεί να εμφανίζει _Sign-in required_. Κάντε κλικ σε αυτόν για να συνδεθείτε ξανά σε αυτόν τον λογαριασμό απευθείας στο πάνελ ή μεταβείτε σε αυτόν και ξεκινήστε μια συνεδρία, η οποία ανανεώνει τη σύνδεση από μόνη της. Οι διακομιστές MCP που προσθέτετε με `claude mcp add` φτάνουν σε κάθε λογαριασμό Claude, αφού όλοι εκτελούνται στο `~/.claude`. Για τα Codex και Grok, οι διακομιστές που είχατε όταν προστέθηκε ένας λογαριασμός τον συνοδεύουν, αλλά οι μεταγενέστεροι φτάνουν μόνο στον λογαριασμό στον οποίο τους προσθέσατε. Το Claude Desktop διατηρεί δική του σύνδεση και τα εργαλεία Codex ή Grok που έχουν ρυθμιστεί με απόλυτη διαδρομή προς ένα δυαδικό αρχείο CLI δεν ακολουθούν την εναλλαγή. Ένα ρητό `CLAUDE_CONFIG_DIR`, `CODEX_HOME` ή `GROK_HOME` υπερισχύει του επιλεγμένου λογαριασμού.

### Διάγνωση καταρρεύσεων

Το Omarchy παρακολουθεί το systemd-coredump για καταρρεύσεις διεργασιών. Όταν κάτι παρουσιάζει segfault, θα λάβετε μια ειδοποίηση "Process crashed" — κάντε κλικ σε αυτήν και η κατάρρευση παραδίδεται στον προεπιλεγμένο agent σας μαζί με τη δεξιότητα diagnose-crash του Omarchy, η οποία καθοδηγεί τον agent στην εξακρίβωση των γεγονότων από το core dump και στην απόφαση για το αν η κατάρρευση αξίζει να αναφερθεί upstream. Μπορείτε επίσης να την εκτελέσετε χειροκίνητα για οποιοδήποτε PID από το `coredumpctl list` με `omarchy agent crash <pid>`.

Η παρακολούθηση είναι ενεργοποιημένη από προεπιλογή. Απενεργοποιήστε την στην ενότητα _Trigger > Toggle > Crash Capture_ (ή με `omarchy toggle crash-capture`) και οι ειδοποιήσεις σταματούν. Η εντολή `omarchy agent crash <pid>` εξακολουθεί να λειτουργεί χειροκίνητα.

Οι καταρρεύσεις μπορούν επίσης να σιγαστούν μία εφαρμογή τη φορά, πράγμα που σας προσφέρει η διάγνωση στο τέλος. Η εντολή `omarchy crash mute hyprland` σταματά τις ειδοποιήσεις μόνο για αυτό το πρόγραμμα, η `omarchy crash mute hyprland off` τις επαναφέρει και η `omarchy crash mute` από μόνη της παραθέτει όσα έχετε σιγάσει. Δέχεται τη διαδρομή του δυαδικού αρχείου εξίσου ευχαρίστως με το όνομά του, οπότε η `omarchy crash mute /usr/bin/hyprland` κάνει το ίδιο πράγμα. Βάλτε σε εισαγωγικά ένα όνομα με κενό, όπως στο `omarchy crash mute 'Some App'`. Όλα τα υπόλοιπα εξακολουθούν να ειδοποιούν και το σιγασμένο πρόγραμμα εξακολουθεί να καταρρέει — αυτό κρύβει την υπενθύμιση, δεν διορθώνει τίποτα.

### Εφαρμογές desktop

Το μενού _Install > AI_ περιλαμβάνει επίσης μερικές γραφικές εφαρμογές AI: την εφαρμογή desktop του ChatGPT, την εφαρμογή desktop του Claude (τη beta για Linux της Anthropic, με καρτέλες Chat, Cowork και Claude Code), το Grok Bot για συνομιλία με τα μοντέλα της xAI, το Herdr Desktop, το Hermes Desktop, το OpenClaw, την εφαρμογή desktop του Perplexity και το T3 Code. Το Grok Bot είναι η εφαρμογή συνομιλίας desktop. Ο agent κωδικοποίησης είναι η εντολή `grok`.

Το Hermes Desktop είναι αυτό που πρέπει να γνωρίζετε, επειδή ένα μηχάνημα έχει ένα Hermes και είναι αυτό της εφαρμογής: το Hermes εγκαθίσταται μόνο μέσω της εφαρμογής και η εντολή `hermes` που εκτελεί ο προεπιλεγμένος agent είναι αυτή της εφαρμογής. Η επιλογή του Hermes ως προεπιλεγμένου agent εγκαθιστά το ίδιο πράγμα που εγκαθιστά η καταχώριση _Install > AI_: το πακέτο και ένα περιβάλλον εκτέλεσης Hermes στο `~/.hermes` που ρυθμίζεται από το δικό του πρόγραμμα εγκατάστασης του Hermes, πράγμα που χρειάζεται μερικά λεπτά την πρώτη φορά. Αυτό το περιβάλλον εκτέλεσης είναι το μοναδικό Hermes που χρησιμοποιούν η εντολή τερματικού `hermes`, ο προεπιλεγμένος agent και η εφαρμογή, και ενημερώνεται μόνο του με `hermes update`, αντί να περιμένει μια έκδοση Omarchy. Η εγκατάστασή του δίνει επίσης στο Hermes το θέμα Omarchy ως skin με όνομα `omarchy`, το οποίο ακολουθεί κάθε επιφάνεια του Hermes καθώς αλλάζετε θέματα. Επιλέξτε άλλο στις ρυθμίσεις Appearance του Hermes ή με `/skin`, αν προτιμάτε να μην το κάνει, και το Omarchy αφήνει αυτή την επιλογή ήσυχη. Η κατάργηση της εφαρμογής στην ενότητα _Remove > AI_ κλείνει πρώτα το Hermes, συμπεριλαμβανομένης της πύλης, παίρνει μαζί της αυτό το περιβάλλον εκτέλεσης και διατηρεί τις συνομιλίες, τις μνήμες και τις δεξιότητες που το Hermes έγραψε για τον εαυτό του, εκτός αν του πείτε διαφορετικά: ρωτά, με προεπιλογή όχι, αν αυτά τα δεδομένα και οι ρυθμίσεις σύνδεσής σας πρέπει επίσης να φύγουν.

Η εμπειρία desktop του OpenClaw είναι το Control UI του, το οποίο ανοίγει ως εφαρμογή web που υποστηρίζεται από τη δική του τοπική πύλη. Το OpenClaw βρίσκεται στο `~/.openclaw` και ενημερώνεται μόνο του: χρησιμοποιήστε το κουμπί "Update Gateway" του Control UI ή εκτελέστε `openclaw update` και η πύλη επανεκκινείται στη νέα έκδοση. Το Omarchy επιλέγει μόνο την έκδοση από την οποία ξεκινά μια νέα εγκατάσταση. Η κατάργηση του OpenClaw στην ενότητα _Remove > AI_ παίρνει μαζί της την υπηρεσία πύλης και την εφαρμογή και στη συνέχεια ρωτά αν το `~/.openclaw` πρέπει επίσης να φύγει, αφού αυτό περιέχει τις συνομιλίες και τα διαπιστευτήριά σας μαζί με το ίδιο το OpenClaw και τα περιβάλλοντα εκτέλεσης προσθέτων που κατεβάζει. Η προεπιλογή το διατηρεί και η εκ νέου εγκατάσταση του OpenClaw το ανακτά.

Το Herdr Desktop είναι η εφαρμογή desktop [Herdr](https://herdr.dev): χώροι, καρτέλες και τμήματα παραθύρων τερματικών και agents κωδικοποίησης που συνεχίζουν να εκτελούνται στον πυρήνα του όταν κλείνετε το παράθυρο. Προέρχεται από το δικό του πρόγραμμα εγκατάστασης του Herdr και όχι από ένα πακέτο, οπότε βρίσκεται στο `~/.local/share/herdr-app`, φέρνει τον πυρήνα του στο `~/.local/bin/herdr-core` όταν δεν έχετε ακόμη έναν και ενημερώνει και τα δύο μόνο του. Βρίσκεται δίπλα στην εντολή `herdr` που παρέχει το Omarchy στο `Super + Ctrl + Return`, αντί να την αντικαθιστά, και λαμβάνει τα άμεσα πλήκτρα αυτής της εντολής: τα `Alt + Return` και `Alt + Shift + Return` διαιρούν ένα τμήμα παραθύρου προς τα κάτω ή προς τα δεξιά, το `Alt + Escape` το κλείνει, το `Ctrl + Alt + Arrow` μετακινεί ανάμεσα σε τμήματα παραθύρων, τα `Alt + 1..9` και `Alt + Left/Right` επιλέγουν μια καρτέλα και τα `Alt + Up/Down` μετακινούν ανάμεσα σε χώρους. Το `Ctrl + 1..9` επιλέγει έναν χώρο και τα `Alt + Shift + Up/Down` περνούν διαδοχικά από agents. Τα πλήκτρα προθέματος `Ctrl + Space` παραμένουν μόνο για τερματικό, αφού η εφαρμογή δεν μπορεί να κρατήσει ένα απλό πλήκτρο Ctrl για μια ακολουθία. Το Omarchy τα γράφει στο `~/.config/herdr-app/keys.json` και η εντολή `omarchy-refresh-herdr-app` τα επαναφέρει. Η εγκατάστασή του επιλέγει το θέμα Omarchy του Herdr, το οποίο ακολουθεί από τότε το θέμα Omarchy σας. Το Herdr διατηρεί ένα θέμα για τη φωτεινή λειτουργία και ένα για τη σκοτεινή, οπότε, αφού μεταβείτε ανάμεσα σε ένα σκοτεινό και ένα φωτεινό θέμα Omarchy, επιλέξτε το Omarchy στον επιλογέα θέματος του Herdr μία ακόμη φορά για την άλλη λειτουργία.

Το T3 Code εκτελείται από την επίσημη έκδοση AppImage του στο `~/.local/share/t3code` και όχι από ένα πακέτο, οπότε ενημερώνεται μόνο του. Η εγκατάστασή του ρωτά αν θα ξεκινήσει στο κανάλι Stable ή Nightly. Αλλάξτε αργότερα στις ρυθμίσεις του T3 Code. Τα νήματα και οι ρυθμίσεις σας βρίσκονται στο `~/.t3` και η κατάργηση του T3 Code στην ενότητα _Remove > AI_ τα παίρνει μαζί της.

### Τοπικά μοντέλα

Εκτελέστε ένα ανοιχτό μοντέλο στο δικό σας μηχάνημα για τους agents κωδικοποίησής σας. Οι προτροπές και ο κώδικάς σας παραμένουν στο μηχάνημα. Τίποτα που στέλνεται στο μοντέλο δεν φεύγει από αυτό. Ξεκινήστε με:

```bash
omarchy agent local use best
```

Ή, στο πάνελ agents στην επάνω γραμμή, επιλέξτε + και στη συνέχεια Local AI, το οποίο εμφανίζεται όταν ένα μοντέλο χωρά σε αυτό το μηχάνημα. Την πρώτη φορά, αυτό εγκαθιστά το Podman, το οποίο εκτελεί τα μοντέλα, και σε ένα μηχάνημα NVIDIA την εργαλειοθήκη container της NVIDIA, η οποία τους δίνει τη GPU. Στη συνέχεια, το Omarchy επιλέγει το συνιστώμενο μοντέλο για αυτό το μηχάνημα, το κατεβάζει και το ξεκινά. Αναμένετε μια λήψη δεκάδων GB και το μεγαλύτερο μέρος της μνήμης του μηχανήματος να χρησιμοποιείται ενώ το μοντέλο εκτελείται: το Flash Next χρησιμοποιεί περίπου 100 GiB με το πλήρες πλαίσιο 256K του. Αν άλλα μοντέλα κρατούν τη μνήμη που χρειάζεται, ρυθμίζεται σταματημένο, έτοιμο να ξεκινήσει μόλις σταματήσετε ένα. Το μοντέλο σταματά κατά την αποσύνδεση. Σταματήστε το μόνοι σας όταν χρειάζεστε τη μνήμη για κάτι άλλο.

Η εντολή `omarchy agent local list` εμφανίζει τις επιλογές και εξηγεί γιατί μερικές δεν χωρούν. Για να ρυθμίσετε άλλη μία, εκτελέστε `omarchy agent local use <recipe>`. Σήμερα, τα `qwen3.8-flash-next-gufo` και `qwen3.8-27b-gufo` είναι διαθέσιμα για μηχανήματα Strix Halo 128 GB. Το 27B καταλαμβάνει περίπου 40 GiB, οπότε αφήνει χώρο για άλλη εργασία. Σε ένα laptop 64 GB με Arc B390 της Intel, το `qwen3.6-35b-a3b-llamacpp` εκτελείται σε περίπου 30 GiB. Νέες συνταγές και συστάσεις φτάνουν με το `omarchy update`, μέσω του πακέτου.

Κάθε μοντέλο που ρυθμίζετε αποκτά τη δική του γραμμή στο πάνελ agents, δίπλα στις συνδρομές σας: play για να το ξεκινήσετε, pause για να το σταματήσετε και να ελευθερώσετε τη μνήμη του και το κουμπί τερματικού για να ανοίξετε τον agent σας σε αυτό. Πολλά μπορούν να εκτελούνται ταυτόχρονα όταν χωρούν μαζί στη μνήμη. Αν ένα δεν χωρά, το Omarchy λέει ποιο μοντέλο που εκτελείται να σταματήσετε. Σύρετε γραμμές για να τις αναδιατάξετε και πατήστε Delete σε μια επιλεγμένη γραμμή για να καταργήσετε ένα μοντέλο και τη λήψη του.

Κάθε μοντέλο που ρυθμίζετε αποκτά επίσης τη δική του καταχώριση στον εκκινητή εφαρμογών, με το όνομα του μοντέλου και το λογότυπο του δημιουργού του, με τον τρόπο που η σύνδεση στα Claude, Codex ή Grok προσθέτει μία. Ανοίγει τον agent σας σε αυτό το μοντέλο και ξεκινά πρώτα το μοντέλο, αν δεν εκτελείται: το τερματικό το δείχνει να φορτώνει και παραδίδει στον agent μόλις είναι έτοιμο. Η κατάργηση ενός μοντέλου καταργεί την καταχώρισή του.

Από τη γραμμή εντολών, οι εντολές `omarchy agent local start <recipe>` και `omarchy agent local stop <recipe>` κάνουν το ίδιο, η `omarchy agent local status` εμφανίζει κάθε μοντέλο και η `omarchy agent --local` ανοίγει τον προεπιλεγμένο agent σας στο τελευταίο μοντέλο που ξεκινήσατε. Τα pi, OpenCode και Qwen Code μπορούν να χρησιμοποιήσουν ένα. Με οποιονδήποτε άλλο προεπιλεγμένο, ανοίγει στο pi. Το pi παραθέτει επίσης κάθε μοντέλο που έχετε ρυθμίσει, καθώς και εκείνα σε μηχανήματα με τα οποία έχετε συνδεθεί, στον δικό του επιλογέα μοντέλων, οπότε το απλό `pi` τα φτάνει επίσης. Οποιοσδήποτε πελάτης συμβατός με OpenAI μπορεί επίσης να συνδεθεί: η εντολή `status` εμφανίζει τη διεύθυνση κάθε μοντέλου (η πρώτη είναι `http://127.0.0.1:11435/v1`), το όνομα της συνταγής είναι το μοντέλο και το κλειδί βρίσκεται στο `~/.config/omarchy/agent-local/key`.

Η εντολή `omarchy agent local remove <recipe>` διαγράφει ένα μοντέλο και τις λήψεις που δεν χρησιμοποιεί κανένα άλλο μοντέλο.

Τα περιβάλλοντα εκτέλεσης τρίτων επισημαίνονται με τον εκδότη τους. Το Omarchy εκτελεί κάθε μοντέλο χωρίς πρόσβαση σε δίκτυο.

### Τοπικά LLM

Το Omarchy συνιστά δύο τρόπους εκτέλεσης τοπικών μοντέλων LLM: το LM Studio και το Ollama. Το LM Studio παρέχει ένα GUI περιβάλλον για την εύρεση μοντέλων ανοιχτών βαρών, την εγκατάστασή τους και την εκτέλεσή τους. Είναι ένας εξαιρετικός τρόπος για να ξεκινήσετε εύκολα. Το Ollama προσφέρει ένα CLI για να κάνετε το ίδιο με παρόμοιο τρόπο. Αλλά, αν είστε νέοι στα τοπικά μοντέλα, θα ξεκινούσα με το LM Studio. Μπορείτε να εγκαταστήσετε οποιοδήποτε από τα δύο στην ενότητα _Install > AI_ στο Μενού Omarchy.

### Η Δεξιότητα Omarchy

Οι δεξιότητες agent βοηθούν το AI να χρησιμοποιεί συγκεκριμένα εργαλεία με συγκεκριμένο τρόπο και το Omarchy παρέχεται με μια προεπιλεγμένη δεξιότητα για την προσαρμογή του συστήματος. Όπως η ρύθμιση του config του Hyprland σας, η προσαρμογή της γραμμής ή ακόμη και η δημιουργία ενός νέου θέματος από το μηδέν. Είναι συνδεδεμένη με symlink στους καταλόγους δεξιοτήτων για τα Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` και κάθε `~/.hermes/profiles/*/skills`) και τη γενική θέση `~/.agents/skills`, οπότε τα περισσότερα harnesses την εντοπίζουν αυτόματα.

Αλλά πρέπει να αντιμετωπίζετε αυτή τη δεξιότητα ως πειραματική. Διαφορετικά μοντέλα θα τη χρησιμοποιούν με διαφορετικό αποτέλεσμα. Είναι καλύτερο να εκτελείται πρώτα σε λειτουργία σχεδιασμού, ώστε να έχετε μια ιδέα για το τι θα ήθελε να αλλάξει ο agent. Και στη συνέχεια να είστε έτοιμοι να επαναφέρετε αλλαγές ή ακόμη και να καλέσετε το `omarchy reinstall configs`, αν ο agent τα κάνει όλα άνω-κάτω.
