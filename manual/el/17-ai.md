# AI

Το Omarchy περιλαμβάνει launchers για τους παρακάτω coding agents χωρίς να επιλέγει προεπιλογή για εσάς. Εκτελέστε μια εντολή για να εγκαταστήσετε το CLI της κατά την πρώτη χρήση και στη συνέχεια πραγματοποιήστε έλεγχο ταυτότητας όταν σας ζητηθεί. Τα Hermes και OpenClaw αποτελούν εξαιρέσεις: δεν εγκαθίσταται τίποτα για αυτά μέσω mise και η επιλογή οποιουδήποτε από τα δύο εγκαθιστά το δικό του αντίγραφο που ενημερώνεται αυτόματα, όπως εξηγούν παρακάτω οι _Εφαρμογές επιφάνειας εργασίας_.

### Εγκατάσταση και ενημέρωση agents

Με εξαίρεση τα Hermes και OpenClaw, αυτοί οι agents χρησιμοποιούν την lazy εγκατάσταση του mise: η πρώτη εκκίνηση εγκαθιστά το CLI και οι επόμενες εκκινήσεις το επαναχρησιμοποιούν. Το mise ελέγχει επίσης έναν εγκατεστημένο agent για νέα έκδοση το πολύ μία φορά κάθε τέσσερις ώρες, λίγο πριν ξεκινήσει ή στο παρασκήνιο σε ένα shell prompt. Αν αυτή η ενημέρωση αποτύχει ή είστε εκτός σύνδεσης, εκτελείται η εγκατεστημένη έκδοση. Το `omarchy update` ενημερώνει τους εγκατεστημένους agents μαζί με το υπόλοιπο Omarchy, και το `mup` ενημερώνει μόνο τα εργαλεία που διαχειρίζεται το mise.

Ο updater του ίδιου του agent, όπως το `claude update`, το `codex update` ή ένα κουμπί ενημέρωσης σε μια εφαρμογή, δεν ενημερώνει την εγκατάσταση που διαχειρίζεται το mise. Το `codex update` αποτυγχάνει, και το `claude update` μπορεί να αναφέρει επιτυχία ενώ εγκαθιστά ένα ξεχωριστό αντίγραφο που το mise δεν παρακολουθεί. Αν προτιμάτε να χρησιμοποιείτε το native πρόγραμμα εγκατάστασης και updater ενός agent, προσθέστε το στο `disable_tools`· δείτε τα [Προεγκατεστημένα εργαλεία CLI](18-development-tools.md#preinstalled-cli-tools).

Για να εγκαταστήσετε όλα τα ρυθμισμένα lazy εργαλεία πριν τα χρειαστείτε, εκτελέστε `mise install --include-lazy`. Αυτό περιλαμβάνει τα άλλα προεπιλεγμένα εργαλεία CLI του Omarchy καθώς και τους agents. Δείτε τα [Προεγκατεστημένα εργαλεία CLI](18-development-tools.md#preinstalled-cli-tools) για την εγκατάσταση ενός μεμονωμένου εργαλείου ή τη χρήση της δικής σας εγκατάστασης.

Το `grok` εγκαθίσταται μέσω του first-party πακέτου `grok` του mise, με τον ίδιο τρόπο όπως τα `claude` και `codex`. Εκτελέστε το `grok`, ή βάλτε του αστέρι στο agents panel. Παραλείψτε το πρόγραμμα εγκατάστασης `curl | bash` στο x.ai. Αυτή η διαδρομή τοποθετεί ένα δεύτερο αντίγραφο στο `~/.grok/bin`, το προτάσσει στο `PATH` και αντικαθιστά το wrapper του Omarchy.

Το `dsh` ανοίγει το browser UI του στο `127.0.0.1:3080`, με τον κατάλογο εκκίνησης ως προεπιλεγμένο workspace του. Το browser UI του δεν δέχεται αρχικό prompt, οπότε το `omarchy agent prompt` το ανοίγει με το prompt στο clipboard σας για επικόλληση. Το Omarchy το ξεκινά με το preset δικαιωμάτων no-approval της DeepSeek. Το DeepSeek Harness ανεβάζει session logs στη DeepSeek όταν χρησιμοποιείτε το επίσημο model API του· απενεργοποιήστε το στην ενότητα _Settings > General > Upload Session Log_ στο browser UI του. Τα σχόλια που του στέλνετε ανεβαίνουν επίσης μαζί με το session, εκτός αν το ξεκινήσετε με `DSH_TELEMETRY_MODE=DISABLED`.

### Ο προεπιλεγμένος agent

Επιλέξτε τον προεπιλεγμένο agent σας με το αστέρι δίπλα σε έναν agent στο agents panel, το οποίο είναι γεμισμένο στον προεπιλεγμένο, ή με το `omarchy default agent <name>`, το οποίο δέχεται επίσης οποιοδήποτε harness χωρίς γραμμή εκεί. Αν ο agent δεν έχει εγκατασταθεί ακόμα, η επιλογή του τον εγκαθιστά πρώτα, και αποκτά επίσης δικό του launcher στο app launcher, δίπλα στο Agent. Ένα φρέσκο Omarchy σας καλεί να ρυθμίσετε έναν με μια εφάπαξ ειδοποίηση, η οποία ανοίγει το agents panel.

Η επιλογή του Claude επιχειρεί επίσης να ρυθμίσει την επέκταση browser του για Chromium, Chrome, Brave, Brave Origin και Edge. Η ρύθμιση της επέκτασης ισχύει για όλους τους χρήστες και μπορεί να ζητήσει τον κωδικό πρόσβασης του συστήματός σας· η ακύρωση ή μια αποτυχημένη εγκατάσταση επέκτασης εξακολουθεί να επιλέγει και να εκκινεί το Claude. Επανεκκινήστε τον browser σας, ενεργοποιήστε την επέκταση αν σας ζητηθεί και συνδεθείτε στο Claude για να ολοκληρώσετε τη σύνδεσή της. Εκτελέστε το `/chrome` στο Claude για να ελέγξετε τη σύνδεση. Τα Firefox και Zen δεν υποστηρίζουν αυτή την επέκταση. Αν το Claude ήταν ήδη ο προεπιλεγμένος σας προτού προστεθεί αυτή η ρύθμιση, επιλέξτε το ξανά για να εγκαταστήσετε την επέκταση.

Αφού επιλέξετε, το `Super + Shift + Ctrl + A` εκκινεί τον προεπιλεγμένο agent σε ένα αποκλειστικό παράθυρο terminal (ή εμφανίζει τον επιλογέα αν δεν έχετε επιλέξει ακόμα). Μπορείτε επίσης να τον εκκινήσετε απευθείας σε μια εργασία με το `omarchy agent prompt "Review this project"`. Τα Freebuff και DeepSeek Harness δεν δέχονται αρχικό prompt, οπότε ανοίγουν με το prompt στο clipboard σας για επικόλληση αντί αυτού. Οι agents που εκκινούνται με αυτόν τον τρόπο εκτελούνται χωρίς επίβλεψη στις αντίστοιχες λειτουργίες don't-stop-to-ask τους, οπότε να είστε έτοιμοι να κάνουν πράγματα στην πράξη! Το MiniMax Code δεν έχει τέτοια λειτουργία για τις interactive συνεδρίες του, οπότε ζητά δικαιώματα ως συνήθως. Και επειδή οι agents αρνούνται να θυμούνται την εμπιστοσύνη για τον home κατάλογό σας, οι εκκινήσεις από το `$HOME` ξεκινούν στο `~/Work` αντί αυτού.

Υπάρχουν επίσης συντομεύσεις terminal: το `a` εκτελεί τον προεπιλεγμένο agent inline στο τρέχον terminal, ενώ τα `c`, `cx`, `cy` και `ca` ξεκινούν απευθείας τα OpenCode, Claude Code, Codex και Antigravity (ξανά στις λειτουργίες auto-approving τους). Οι αλλαγές θέματος συγχρονίζονται επίσης στους agents: τα Claude Code, Pi, OpenCode και Hermes (αφού το Omarchy το έχει εγκαταστήσει) ακολουθούν όλα όταν αλλάζετε το θέμα του Omarchy.

### Οι οδηγίες του agent σας

Οι προσωπικοί κανόνες για κάθε agent μπαίνουν στο `~/.agents/AGENTS.md`, δίπλα στα shared skills στο `~/.agents/skills`. Ανοίξτε το με το εικονίδιο εγγράφου δίπλα στο + στο agents panel, ή με το `omarchy agent instructions --edit`, το οποίο το συνδέει επίσης σε κάθε harness που διατηρεί το δικό του global αρχείο: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, το `~/.copilot/copilot-instructions.md` του Copilot, και ούτω καθεξής. Τα Crush και Amp διαβάζουν τον σύνδεσμο `~/.config/AGENTS.md`, ενώ τα omp, Kimi και DeepSeek Harness διαβάζουν απευθείας το `~/.agents/AGENTS.md`. Η επιλογή ενός προεπιλεγμένου agent το συνδέει επίσης. Ένα αρχείο οδηγιών που είχατε ήδη γίνεται το shared αν δεν υπήρχε ακόμα κανένα· διαφορετικά διατηρείται δίπλα στον σύνδεσμο ως `.bak`. Εκτελέστε το `omarchy agent instructions` για να επανασυνδέσετε μετά την εγκατάσταση ενός άλλου agent.

### Το agents panel

Η επάνω μπάρα έχει ένα εικονίδιο agents. Πριν ρυθμίσετε έναν agent, το panel του προσφέρει τρεις τρόπους για να ξεκινήσετε: συνδεθείτε σε μια συνδρομή Claude, Codex, Grok, Gemini, Muse, Cursor ή Copilot, ή στην ενότητα More σε ένα coding plan OpenCode Go, MiniMax, Synthetic ή Z.ai· πληρώστε καθώς προχωράτε με Fireworks, OpenCode Zen and Go, OpenRouter, ή στην ενότητα More με DeepSeek ή οποιονδήποτε άλλο provider στον οποίο συνδέεται το OpenCode, όλα εκτελούνται στο OpenCode· ή εκτελέστε το καλύτερο μοντέλο για τον υπολογιστή σας, όταν ένα του ταιριάζει. Το πρώτο που ολοκληρώνετε γίνεται ο προεπιλεγμένος agent σας, και το + στο panel προσφέρει τα ίδια τρία αργότερα. Μετά από αυτό, το panel τοποθετεί κάθε συνδρομή σε μία σελίδα: κάθε agent και λογαριασμό με το plan του, έναν μετρητή για καθένα από τα όρια session 5 ωρών και εβδομαδιαία όριά του με τον χρόνο μέχρι να γίνει reset (τοποθετήστε τον δείκτη για το ακριβές ποσοστό), ή το υπόλοιπο προπληρωμένο υπόλοιπο, κάτω από μια γραμμή που εναλλάσσεται σε ό,τι έχετε χρησιμοποιήσει σε όλα αυτά, όπως tokens αυτή την εβδομάδα και το μοντέλο που χρησιμοποιείτε περισσότερο. Στην ενότητα _Make something cool_ προσφέρει starter prompts για ένα νέο θέμα, plugin, εφαρμογή ή παιχνίδι που παραδίδουν την εργασία στον προεπιλεγμένο agent σας. Οι εφαρμογές κατασκευάζονται με τον τρόπο που κατασκευάζονται τα ίδια τα Hype, Monologue και Omacut του Omarchy, σε C++ και Qt Quick, ακολουθώντας το omarchy-make-app agent skill, και ο compiler και τα κομμάτια Qt που χρειάζονται έρχονται εγκατεστημένα. Τα παιχνίδια είναι μία μόνο σελίδα three.js στο `~/Games/vibes`, ακολουθώντας το omarchy-make-game agent skill, και όλα ανοίγουν από έναν launcher Game Vibes στο τρέχον θέμα· φορτώνουν το three.js από τον ιστό, οπότε χρειάζονται σύνδεση για να ξεκινήσουν. Τα Claude Code, Codex, Grok, Kimi, Cursor και το επίδομα Grok Bot του, GitHub Copilot, Muse, Gemini (μέσω Antigravity) και Devin καλύπτονται εξαρχής με τα όριά τους, το Kimchi με το plan του, τα προπληρωμένα credits και τους προϋπολογισμούς δαπανών του, και τα Hermes, Mistral Vibe και Qwen Code εμφανίζουν τις συνεδρίες και τα tokens τους αφού τα χρησιμοποιήσετε. Τα provider plans και κλειδιά που χρησιμοποιείτε μέσω pi, omp ή opencode εμφανίζονται επίσης: τα OpenCode Zen and Go, το Z.ai GLM Coding Plan, το Ollama Cloud, το MiniMax Token Plan και το Synthetic με τα όριά τους· τα OpenRouter και DeepSeek με τα προπληρωμένα υπόλοιπά τους· το Fireworks με τις δαπάνες του τις τελευταίες 30 ημέρες. Τα coding models που εκτελείτε στο δικό σας hardware αποκτούν δικές τους γραμμές, και τα tokens τους μετρούν επίσης στα σύνολα, όπως περιγράφεται στα [Τοπικά μοντέλα](#local-models). Κάθε agent μετράται μία φορά, κάτω από όποιον τον χρεώνει, ανεξάρτητα από το πόσα harnesses τον οδηγείτε μέσω αυτών.

Κάντε αριστερό κλικ στο εικονίδιο της μπάρας ή πατήστε `Super + Ctrl + X` για το panel, δεξί κλικ για να εκκινήσετε τον προεπιλεγμένο agent σας και μεσαίο κλικ για ανανέωση. Τα αρχεία χρήσης πίσω από αυτό αναγεννώνται κάθε 15 λεπτά από το `omarchy agent usage update`, και το panel μπορεί ακόμη και να συγχωνεύσει χρήση από τα άλλα μηχανήματά σας μέσω ενός συγχρονισμένου φακέλου. Δείτε το README στο `$OMARCHY_PATH/shell/plugins/agents/` για τις πλήρεις ρυθμίσεις.

### Πολλές συνδρομές

Αν πληρώνετε για περισσότερα από ένα plans Claude, Codex ή Grok — ένα προσωπικό Max και ένα εργασιακό, ας πούμε — το Omarchy μπορεί να τα διατηρεί όλα συνδεδεμένα και να μετακινείται μεταξύ τους. Προσθέστε μια συνδρομή με το + στο agents panel, το οποίο σας καθοδηγεί εκεί, ή με το `omarchy agent account add claude Work` (ή `codex`, ή `grok`). Το ίδιο + και εντολή συνδέονται στο Gemini (`gemini`) και στο OpenCode (`opencode`), και αποθηκεύουν ένα κλειδί API Fireworks (`fireworks`) ή OpenRouter (`openrouter`) στο OpenCode· η εντολή συνδέεται επίσης στο Copilot (`copilot`), Cursor (`cursor`) και Muse (`muse`). Αυτά διατηρούν μία σύνδεση το καθένα. Εγκαθιστά το CLI αν λείπει. Ο πρώτος λογαριασμός για έναν provider συνδέεται μέσω του κανονικού browser σας, ακριβώς εκεί που το CLI πάντα ψάχνει. Κάθε ένας μετά από αυτόν συνδέεται μέσω ενός ιδιωτικού παραθύρου, ώστε ο λογαριασμός στον οποίο ο browser σας έχει ήδη συνδεθεί να μην ληφθεί κατά λάθος· συνδεθείτε εκεί ως ο λογαριασμός που προσθέτετε, και κλείστε πρώτα όποιο ιδιωτικό παράθυρο είχατε ήδη ανοιχτό. Ποτέ μην αποσυνδέεστε από το CLI για να το κάνετε αυτό: η αποσύνδεση ανακαλεί την αποθηκευμένη σύνδεση, και αυτός ο λογαριασμός θα πρέπει να προστεθεί ξανά.

Για να αντιγράψετε τις συνδέσεις συνδρομής σας σε άλλο μηχάνημα Omarchy μέσω SSH, εκτελέστε `omarchy agent account copy user@laptop`. Ο αποστολέας παρέχει έναν προσωρινό δέκτη όταν ο προορισμός δεν έχει έναν εγκατεστημένο, ώστε παλαιότερα μηχανήματα Omarchy να μπορούν να λάβουν λογαριασμούς χωρίς ενημέρωση. Οι εγκατεστημένοι δέκτες έχουν προτεραιότητα. Αυτό αντιγράφει όλες τις συνδρομές Claude, Codex και Grok· προσθέστε ονόματα provider για να τις επιλέξετε, όπως στο `omarchy agent account copy laptop claude`. Τα ονόματα λογαριασμών και τα αναγνωριστικά εντολών ταιριάζουν με την πηγή, συμπεριλαμβανομένων λογαριασμών που υπάρχουν ήδη στον προορισμό. Μη σχετικοί λογαριασμοί προορισμού λαμβάνουν ένα αριθμητικό επίθημα αν τα ονόματά τους συγκρούονται, και οι ρυθμίσεις, τα skills, τα plugins και το ιστορικό συνομιλιών παραμένουν τοπικά σε κάθε μηχάνημα.

Τα υπάρχοντα διαπιστευτήρια προορισμού διατηρούνται. Ένας λογαριασμός πηγής που έχει ήδη συνδεθεί εκεί έχει το όνομά του συγχρονισμένο χωρίς να αντικαθιστά τα διαπιστευτήριά του· οι άλλοι λογαριασμοί προστίθενται δίπλα του. Για να αντικαταστήσετε αποθηκευμένα διαπιστευτήρια για λογαριασμούς που ταιριάζουν, χρησιμοποιήστε `omarchy agent account copy --replace laptop claude` αφού κλείσετε τις συνεδρίες αυτού του λογαριασμού στον προορισμό. Ένας φρέσκος προορισμός λαμβάνει επίσης τον ενεργό λογαριασμό και τις προτιμήσεις εναλλαγής της πηγής· ένας καθιερωμένος προορισμός διατηρεί τις δικές του.

Τα διαπιστευτήρια ταξιδεύουν μέσω SSH και αποθηκεύονται σε ιδιωτικά αρχεία στον προορισμό, οπότε αντιγράψτε μόνο σε μηχανήματα που εμπιστεύεστε. Αυτή είναι μια εφάπαξ αντιγραφή, όχι συνεχιζόμενος συγχρονισμός. Τα Codex refresh tokens μπορεί να εναλλάσσονται από άλλο μηχάνημα, αφήνοντας μια αντιγραμμένη σύνδεση να χρειάζεται ανανέωση· ξεχωριστές συνδέσεις παραμένουν η πιο αξιόπιστη επιλογή για ταυτόχρονη χρήση σε πολλά μηχανήματα. Δείτε τις [Οδηγίες ελέγχου ταυτότητας λογαριασμού του Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Ένας λογαριασμός ανά provider είναι ενεργός, και κάθε νέα συνεδρία ξεκινά ως αυτός: `cx`, `cy`, ένα απλό `claude`, `codex` ή `grok`, οτιδήποτε εκκινείται μέσω `omarchy agent`, και scripts ή editors που βρίσκουν το CLI στο `PATH`. Εναλλάξτε με το `omarchy agent account use work` (και πίσω με το `omarchy agent account use main`), ή στο panel πατώντας τον αριθμό ενός λογαριασμού και στη συνέχεια `Enter` (ή κάνοντας κλικ στο αστέρι του). Οι τρέχουσες συνεδρίες Claude εναλλάσσονται επίσης, από το επόμενο μήνυμά τους: κάθε συνεδρία Claude εκτελείται στο `~/.claude`, το οποίο πάντα κρατά τη σύνδεση του ενεργού λογαριασμού. Μια συνεδρία Claude που ξεκίνησε στον δικό της φάκελο ενός λογαριασμού από παλαιότερο Omarchy κρατά αυτή τη σύνδεση μέχρι να κλείσει, οπότε η εναλλαγή ονομάζει αυτές τις συνεδρίες και ολοκληρώνεται από μόνη της μόλις φύγουν. Οι τρέχουσες συνεδρίες Codex και Grok παραμένουν στον λογαριασμό με τον οποίο ξεκίνησαν. Το ιστορικό συνομιλιών, οι ρυθμίσεις, τα skills και τα plugins μοιράζονται μεταξύ λογαριασμών, οπότε το `claude --continue` στον ίδιο φάκελο συνεχίζει από εκεί που σταματήσατε στον νέο λογαριασμό.

Με περισσότερους από έναν λογαριασμούς, το panel δείχνει τα όρια κάθε λογαριασμού δίπλα-δίπλα, με ένα γεμισμένο αστέρι σε αυτόν που χρησιμοποιείται. Το Omarchy σας ειδοποιεί όταν ο ενεργός λογαριασμός ξεπεράσει το 95% ενός ορίου, και κάνοντας κλικ στην ειδοποίηση μεταβαίνετε στον λογαριασμό με το περισσότερο περιθώριο. Ποτέ δεν μεταβαίνει από μόνο του. Αλλάξτε το όριο με το `omarchy agent account threshold 90`. Αν κάθε λογαριασμός είναι πάνω από το όριο, θα το ακούσετε μία φορά, μαζί με το ποιος λογαριασμός ελευθερώνεται πρώτος. Ενώ ένας ενεργός λογαριασμός βρίσκεται εντός 15 μονάδων από το όριό του (80% στην προεπιλογή), τα όριά του ελέγχονται κάθε τρία λεπτά αντί κάθε 15.

Το `omarchy agent account list` δείχνει κάθε λογαριασμό και τα τελευταία όριά του, το `omarchy agent account remove work` ξεχνά έναν, και το `omarchy agent account rename primary Hey` μετονομάζει έναν (ή κάντε κλικ στο όνομα ενός λογαριασμού στο panel). Αυτές οι εντολές λειτουργούν στους λογαριασμούς του προεπιλεγμένου agent σας· για να φτάσετε στον άλλο provider, ονομάστε τον πρώτα, όπως στο `omarchy agent account use codex side`. Η σύνδεση που ήδη είχατε στο `~/.claude` ή στο `~/.codex` είναι ο λογαριασμός _Main_. Του Codex παραμένει εκεί που είναι· του Claude περιμένει σε δικό του φάκελο ενώ ένας άλλος λογαριασμός είναι ενεργός. Ένας λογαριασμός που έμεινε αχρησιμοποίητος για περισσότερες από περίπου οκτώ ώρες μπορεί να δείξει _Sign-in required_· κάντε κλικ σε αυτόν για να συνδεθείτε ξανά σε αυτόν τον λογαριασμό ακριβώς στο panel, ή μεταβείτε σε αυτόν και ξεκινήστε μια συνεδρία, η οποία ανανεώνει τη σύνδεση από μόνη της. Οι MCP servers που προσθέτετε με το `claude mcp add` φτάνουν σε κάθε λογαριασμό Claude, αφού όλοι εκτελούνται στο `~/.claude`· για Codex και Grok, servers που είχατε όταν προστέθηκε ένας λογαριασμός έρχονται μαζί του σε αυτόν, αλλά οι μεταγενέστεροι φτάνουν μόνο στον λογαριασμό στον οποίο τους προσθέσατε. Το Claude Desktop διατηρεί δική του σύνδεση, και τα εργαλεία Codex ή Grok που έχουν ρυθμιστεί με απόλυτη διαδρομή σε ένα δυαδικό CLI δεν ακολουθούν την εναλλαγή. Ένα ρητό `CLAUDE_CONFIG_DIR`, `CODEX_HOME` ή `GROK_HOME` έχει προτεραιότητα έναντι του επιλεγμένου λογαριασμού.

### Διάγνωση καταρρεύσεων

Το Omarchy παρακολουθεί το systemd-coredump για καταρρεύσεις διεργασιών. Αφού επιλέξετε έναν προεπιλεγμένο agent, οποιοδήποτε δικό σας πρόγραμμα που δημιουργεί core dump φέρνει μια ειδοποίηση "Process crashed" — κάντε κλικ σε αυτήν, και η κατάρρευση παραδίδεται στον προεπιλεγμένο agent σας μαζί με το omarchy-diagnose-crash skill του Omarchy, το οποίο καθοδηγεί τον agent στην εξακρίβωση των γεγονότων από το core dump και στην απόφαση αν η κατάρρευση αξίζει να αναφερθεί upstream. Μπορείτε επίσης να το εκτελέσετε χειροκίνητα έναντι οποιουδήποτε PID από το `coredumpctl list` με το `omarchy agent crash <pid>`.

Η παρακολούθηση είναι ενεργή από προεπιλογή. Απενεργοποιήστε την στην ενότητα _Trigger > Toggle > Crash Capture Off_ (ή με το `omarchy toggle crash-capture`) και οι ειδοποιήσεις σταματούν· το `omarchy agent crash <pid>` εξακολουθεί να λειτουργεί χειροκίνητα.

Οι καταρρεύσεις μπορούν επίσης να σιγήσουν ένα πρόγραμμα τη φορά, που είναι αυτό που σας προσφέρει η διάγνωση στο τέλος. Το `omarchy crash mute hyprland` σταματά τις ειδοποιήσεις μόνο για αυτό το πρόγραμμα, το `omarchy crash mute hyprland off` τις επαναφέρει, και το `omarchy crash mute` από μόνο του παραθέτει τι έχετε θέσει σε σίγαση. Δέχεται τη διαδρομή του δυαδικού όσο ευχάριστα και το όνομά του, οπότε το `omarchy crash mute /usr/bin/hyprland` κάνει το ίδιο πράγμα. Βάλτε σε εισαγωγικά ένα όνομα με κενό, όπως στο `omarchy crash mute 'Some App'`. Οτιδήποτε άλλο εξακολουθεί να ειδοποιεί, και το πρόγραμμα σε σίγαση εξακολουθεί να καταρρέει — αυτό κρύβει την υπενθύμιση, δεν διορθώνει τίποτα.

### Εφαρμογές επιφάνειας εργασίας

Το μενού _Install > AI_ φέρει επίσης μερικές γραφικές εφαρμογές AI: Amp Desktop, Antigravity Desktop, την εφαρμογή desktop ChatGPT, την εφαρμογή desktop Claude (το Linux beta της Anthropic, με καρτέλες Chat, Cowork και Claude Code), Grok Bot για συνομιλία με τα μοντέλα της xAI, Herdr Desktop, Hermes Desktop, OpenClaw, την εφαρμογή desktop Perplexity και T3 Code. Το Grok Bot είναι η εφαρμογή συνομιλίας desktop. Ο coding agent είναι η εντολή `grok`.

Το Hermes Desktop είναι αυτό που πρέπει να γνωρίζετε, επειδή ένα μηχάνημα έχει ένα Hermes, και είναι της εφαρμογής: το Hermes εγκαθίσταται μόνο ποτέ μέσω της εφαρμογής, και η εντολή `hermes` που εκτελεί ο προεπιλεγμένος agent είναι της εφαρμογής. Η επιλογή του Hermes ως προεπιλεγμένου agent εγκαθιστά το ίδιο πράγμα που κάνει η καταχώριση _Install > AI_: το πακέτο, και ένα Hermes runtime κάτω από το `~/.hermes` που ρυθμίζεται από το δικό του πρόγραμμα εγκατάστασης του Hermes, το οποίο χρειάζεται λίγα λεπτά την πρώτη φορά. Αυτό το runtime είναι το ένα Hermes που χρησιμοποιούν η εντολή terminal `hermes`, ο προεπιλεγμένος agent και η εφαρμογή, και ενημερώνεται μόνο του με το `hermes update` αντί να περιμένει μια έκδοση του Omarchy. Η εγκατάστασή του δίνει επίσης στο Hermes το θέμα του Omarchy ως skin με όνομα `omarchy`, το οποίο ακολουθεί κάθε επιφάνεια του Hermes καθώς αλλάζετε θέματα· επιλέξτε άλλο στις ρυθμίσεις Appearance του Hermes ή με το `/skin` αν προτιμάτε να μην το κάνει, και το Omarchy αφήνει αυτή την επιλογή ήσυχη. Η αφαίρεση της εφαρμογής στην ενότητα _Remove > AI_ κλείνει πρώτα το Hermes, συμπεριλαμβανομένου του gateway, παίρνει αυτό το runtime μαζί της, και διατηρεί τις συνομιλίες σας, τις μνήμες και τα skills που το Hermes έγραψε για τον εαυτό του εκτός αν του πείτε διαφορετικά: ρωτά, με προεπιλογή το όχι, αν αυτά τα δεδομένα και οι ρυθμίσεις σύνδεσής σας πρέπει επίσης να φύγουν.

Η εμπειρία desktop του OpenClaw είναι το Control UI του, το οποίο ανοίγει ως web εφαρμογή που υποστηρίζεται από το δικό του τοπικό gateway. Το OpenClaw ζει στο `~/.openclaw` και ενημερώνεται μόνο του: χρησιμοποιήστε το κουμπί "Update Gateway" του Control UI ή εκτελέστε το `openclaw update`, και το gateway επανεκκινείται στη νέα έκδοση. Το Omarchy επιλέγει μόνο την έκδοση από την οποία ξεκινά μια φρέσκια εγκατάσταση. Το OpenClaw μπορεί επίσης να είναι ο προεπιλεγμένος agent σας: η επιλογή του με το `omarchy default agent openclaw` ρυθμίζει αυτό το ίδιο αντίγραφο στο `~/.openclaw`, και ο agent ανοίγει το terminal UI του OpenClaw προσαρτημένο στο gateway του. Η αφαίρεση του OpenClaw στην ενότητα _Remove > AI_ παίρνει την υπηρεσία gateway και την εφαρμογή μαζί της και στη συνέχεια ρωτά αν το `~/.openclaw` πρέπει επίσης να φύγει, αφού αυτό κρατά τις συνομιλίες και τα διαπιστευτήριά σας δίπλα στο ίδιο το OpenClaw και τα plugin runtimes που κατεβάζει· η προεπιλογή το διατηρεί, και η εγκατάσταση του OpenClaw ξανά το ξαναπαίρνει.

Το Herdr Desktop είναι η εφαρμογή desktop [Herdr](https://herdr.dev): spaces, tabs και panes από terminals και coding agents που συνεχίζουν να εκτελούνται στον πυρήνα του όταν κλείνετε το παράθυρο. Προέρχεται από το δικό του πρόγραμμα εγκατάστασης του Herdr αντί για πακέτο, οπότε ζει στο `~/.local/share/herdr-app`, φέρνει τον πυρήνα του στο `~/.local/bin/herdr-core` όταν δεν έχετε ήδη έναν, και ενημερώνει και τα δύο μόνα του. Βρίσκεται δίπλα στην εντολή `herdr` που παρέχει το Omarchy στο `Super + Ctrl + Return` αντί να την αντικαθιστά, και λαμβάνει τα άμεσα πλήκτρα αυτής της εντολής: το `Alt + Return` και το `Alt + Shift + Return` διαιρούν ένα pane προς τα κάτω ή δεξιά, το `Alt + Escape` το κλείνει, το `Ctrl + Alt + Arrow` μετακινείται μεταξύ panes, τα `Alt + 1..9` και `Alt + Left/Right` επιλέγουν ένα tab, και το `Alt + Up/Down` μετακινείται μεταξύ spaces. Το `Ctrl + 1..9` επιλέγει ένα space και το `Alt + Shift + Up/Down` περνά βήμα-βήμα από τους agents. Τα πλήκτρα προθέματος `Ctrl + Space` παραμένουν μόνο για terminal, αφού η εφαρμογή δεν μπορεί να κρατήσει ένα απλό πλήκτρο Ctrl για μια ακολουθία. Το Omarchy γράφει αυτά στο `~/.config/herdr-app/keys.json`, και το `omarchy-refresh-herdr-app` τα επαναφέρει. Η εγκατάστασή του επιλέγει το θέμα Omarchy του Herdr, το οποίο ακολουθεί το θέμα Omarchy σας από τότε και μετά. Το Herdr διατηρεί ένα θέμα για light mode και ένα για dark mode, οπότε αφού μεταβείτε μεταξύ ενός σκοτεινού και ενός ανοιχτού θέματος Omarchy, επιλέξτε το Omarchy στον επιλογέα θεμάτων του Herdr άλλη μια φορά για την άλλη λειτουργία.

Το T3 Code εκτελείται από την επίσημη έκδοση AppImage του στο `~/.local/share/t3code` αντί από πακέτο, οπότε ενημερώνεται μόνο του. Η εγκατάστασή του ρωτά αν θα ξεκινήσει στο κανάλι Stable ή Nightly· αλλάξτε αργότερα στις ρυθμίσεις του T3 Code. Τα threads και οι ρυθμίσεις σας ζουν στο `~/.t3`, και η αφαίρεση του T3 Code στην ενότητα _Remove > AI_ τα παίρνει μαζί της.

### Τοπικά μοντέλα

Εκτελέστε ένα ανοιχτό μοντέλο στο δικό σας μηχάνημα για τους coding agents σας. Τα prompts και ο κώδικάς σας παραμένουν στο μηχάνημα· τίποτα που στέλνεται στο μοντέλο δεν το αφήνει. Ξεκινήστε με:

```bash
omarchy models use best text
```

Αυτό ρυθμίζει το καλύτερο μοντέλο κειμένου για αυτό το μηχάνημα, το είδος που χρησιμοποιούν οι agents σας. Τα μοντέλα εικόνας, βίντεο και μουσικής έχουν το δικό τους καλύτερο: `omarchy models use best image`, `video` ή `music`. Εκτελέστε το `omarchy models use best` για να δείτε την επιλογή κάθε είδους για αυτό το μηχάνημα.

Ή επιλέξτε το + στο agents panel: στην ενότητα _Use a local model_ παραθέτει κάθε coding model που ταιριάζει σε αυτό το μηχάνημα, το προτεινόμενο πρώτο. Το Podman, το οποίο εκτελεί τα μοντέλα, έρχεται με το Omarchy, όπως και το container toolkit της NVIDIA σε ένα μηχάνημα NVIDIA, το οποίο τους δίνει το GPU· αν λείπει ένα από τα δύο, η πρώτη ρύθμιση το εγκαθιστά. Το Omarchy στη συνέχεια επιλέγει το προτεινόμενο μοντέλο για αυτό το μηχάνημα, το κατεβάζει και το ξεκινά. Αναμένετε λήψη δεκάδων GB και το μεγαλύτερο μέρος της μνήμης του μηχανήματος να χρησιμοποιείται ενώ το μοντέλο εκτελείται: το Flash Next χρησιμοποιεί περίπου 100 GiB με το πλήρες context 256K του. Αν άλλα μοντέλα κρατούν τη μνήμη που χρειάζεται, ρυθμίζεται σταματημένο, έτοιμο να ξεκινήσει μόλις σταματήσετε ένα. Το μοντέλο σταματά κατά την αποσύνδεση· σταματήστε το μόνοι σας όταν χρειάζεστε τη μνήμη για κάτι άλλο.

Το `omarchy models list` δείχνει τις επιλογές και εξηγεί γιατί μερικές δεν ταιριάζουν. Για να ρυθμίσετε άλλη μία, εκτελέστε `omarchy models use <recipe>`. Σήμερα, τα `qwen3.8-flash-next-gufo` και `qwen3.8-27b-gufo` είναι διαθέσιμα για μηχανήματα Strix Halo 128 GB· το 27B παίρνει περίπου 40 GiB, οπότε αφήνει χώρο για άλλη εργασία. Σε ένα laptop 64 GB με Arc B390 της Intel, το `qwen3.6-35b-a3b-llamacpp` εκτελείται σε περίπου 30 GiB. Νέες συνταγές και προτάσεις φτάνουν με το `omarchy update`, μέσω του πακέτου.

Ένα coding model που προσθέτετε λαμβάνει δική του γραμμή στο agents panel, δίπλα στις συνδρομές σας: play για να το ξεκινήσετε, pause για να το σταματήσετε και να ελευθερώσετε τη μνήμη του, το σημάδι Tailscale για να το μοιραστείτε με τα άλλα μηχανήματα στο tailnet σας ενώ εκτελείται, και το κουμπί terminal για να ανοίξετε τον agent σας σε αυτό. Η γραμμή του δείχνει τη λήψη, φόρτωση ή διακοπή καθώς προχωρά, και το λέει όταν δεν υπάρχει αρκετή ελεύθερη μνήμη για να το ξεκινήσει, ή συνδέει στα logs του όταν σταμάτησε με σφάλμα. Πολλά μπορούν να εκτελούνται ταυτόχρονα όταν χωρούν μαζί στη μνήμη. Πατήστε Delete σε μια επιλεγμένη γραμμή για να αφαιρέσετε το μοντέλο από αυτό το μηχάνημα, λήψη και όλα· το + μπορεί να το ρυθμίσει ξανά. Ένα coding model που ρυθμίζεται από terminal περιμένει κάτω από το + μέχρι να το προσθέσετε, και το ίδιο κάνουν τα μοντέλα που εκτελεί ένα μηχάνημα με το οποίο έχετε συζευχθεί (`omarchy models pair <host>`).

Κάθε coding model που ρυθμίζετε λαμβάνει επίσης δική του καταχώριση στο app launcher, με το όνομα του μοντέλου και με το λογότυπο του κατασκευαστή του, με τον τρόπο που η σύνδεση στο Claude, Codex ή Grok προσθέτει μία. Ανοίγει τον agent σας σε αυτό το μοντέλο, και ξεκινά το μοντέλο πρώτα αν δεν εκτελείται: το terminal δείχνει ότι φορτώνει και παραδίδει στον agent μόλις είναι έτοιμο. Η αφαίρεση ενός μοντέλου αφαιρεί την καταχώρισή του.

Δεν είναι κάθε μοντέλο για coding. Τα μοντέλα εικόνας, βίντεο και μουσικής ανοίγουν στο Fantasi αντί αυτού, την εφαρμογή του Omarchy για τη δημιουργία εικόνων, βίντεο και μουσικής με ένα μοντέλο που εκτελείται σε αυτό το μηχάνημα, και διαχειρίζονται εκεί ή με το `omarchy models`.

Ένα μοντέλο συνεχίζει να εκτελείται ακριβώς όπως ρυθμίστηκε, οπότε μια ενημέρωση του Omarchy ποτέ δεν επανεκκινεί ένα κάτω από τους agents σας. Όταν το Omarchy έχει ένα νεότερο runtime ή νεότερα weights για ένα μοντέλο που έχετε ρυθμίσει, η γραμμή του δείχνει ένα κουμπί ενημέρωσης: πατήστε το και το μοντέλο ρυθμίζεται ξανά στο παρασκήνιο, κατεβάζοντας μόνο ό,τι άλλαξε, και επανεκκινείται στη νέα έκδοση. Ένα μοντέλο που ήταν σταματημένο παραμένει σταματημένο. Το `omarchy models update` κάνει το ίδιο για κάθε μοντέλο από ένα terminal.

Από τη γραμμή εντολών, τα `omarchy models start <recipe>` και `omarchy models stop <recipe>` κάνουν το ίδιο, το `omarchy models status` δείχνει κάθε μοντέλο, και το `omarchy agent --local-model <recipe>` ανοίγει αυτό το μοντέλο στο pi, όποιος και αν είναι ο προεπιλεγμένος agent σας. Για να κάνετε το τοπικό μοντέλο σας αυτό που ανοίγουν το agent hotkey, η Quake console και το _Make something_, εκτελέστε `omarchy default agent local` ή βάλτε αστέρι σε ένα τρέχον μοντέλο στο agents panel. Το pi παραθέτει επίσης κάθε μοντέλο που έχετε ρυθμίσει, και αυτά σε μηχανήματα με τα οποία έχετε συζευχθεί, στον δικό του επιλογέα μοντέλου, οπότε το απλό `pi` τα φτάνει επίσης. Οποιοσδήποτε client συμβατός με OpenAI μπορεί επίσης να συνδεθεί: το `status` δείχνει τη διεύθυνση κάθε μοντέλου (η πρώτη είναι `http://127.0.0.1:11435/v1`), το όνομα της συνταγής είναι το μοντέλο, και το κλειδί βρίσκεται στο `~/.config/omarchy/agent-local/key`.

Το `omarchy models remove <recipe>` διαγράφει ένα μοντέλο και τις λήψεις που δεν χρησιμοποιεί κανένα άλλο μοντέλο.

Τα runtimes τρίτων επισημαίνονται με τον εκδότη τους. Το Omarchy εκτελεί κάθε μοντέλο χωρίς πρόσβαση δικτύου.

### Τοπικά LLMs

Το Omarchy προτείνει δύο τρόπους εκτέλεσης τοπικών μοντέλων LLM: LM Studio και Ollama. Το LM Studio παρέχει ένα GUI interface για την εύρεση μοντέλων open-weight, την εγκατάστασή τους και την εκτέλεσή τους. Είναι ένας εξαιρετικός τρόπος να ξεκινήσετε εύκολα. Το Ollama προσφέρει ένα CLI για να κάνετε το ίδιο παρόμοια. Αλλά αν είστε νέοι στα τοπικά μοντέλα, θα ξεκινούσα με το LM Studio. Μπορείτε να εγκαταστήσετε οποιοδήποτε από τα δύο στην ενότητα _Install > AI_ στο Omarchy Menu.

### Τα skills του Omarchy

Τα agent skills βοηθούν το AI να χρησιμοποιεί συγκεκριμένα εργαλεία με συγκεκριμένο τρόπο, και το Omarchy παρέχει επτά από αυτά. Το omarchy skill καλύπτει την προσαρμογή του συστήματος, όπως την τροποποίηση του Hyprland config σας ή τη ρύθμιση της μπάρας. Τα omarchy-make-theme, omarchy-make-plugin, omarchy-make-app και omarchy-make-game καλύπτουν τη δημιουργία κάτι νέου, το omarchy-contribute καλύπτει την αναφορά ενός bug ή την αποστολή μιας διόρθωσης upstream, και το omarchy-diagnose-crash επεξεργάζεται το core dump μιας κατάρρευσης. Συνδέονται με symlink στους καταλόγους skills για Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` και κάθε `~/.hermes/profiles/*/skills`), και τη γενική τοποθεσία `~/.agents/skills`, οπότε τα περισσότερα harnesses τα λαμβάνουν αυτόματα. Ένας φάκελος skill δικός σας με το ίδιο όνομα έχει προτεραιότητα.

Αλλά πρέπει να αντιμετωπίζετε αυτά τα skills ως πειραματικά. Διαφορετικά μοντέλα θα τα χρησιμοποιήσουν με διαφορετικό αποτέλεσμα. Είναι καλύτερο να εκτελείτε πρώτα σε plan mode, ώστε να έχετε μια ιδέα για το τι θα ήθελε να αλλάξει ο agent. Και μετά να είστε έτοιμοι να αναιρέσετε αλλαγές ή ακόμη και να επικαλεστείτε το `omarchy reinstall configs`, αν ο agent κάνει τα πάντα άνω κάτω.
