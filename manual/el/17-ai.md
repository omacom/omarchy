# AI

Το Omarchy περιλαμβάνει launchers για τους παρακάτω coding agents, χωρίς να επιλέγει έναν προεπιλεγμένο για εσάς. Εκτελέστε μια εντολή για να εγκατασταθεί το CLI της στην πρώτη χρήση και στη συνέχεια κάντε έλεγχο ταυτότητας όταν σας ζητηθεί. Οι Hermes και OpenClaw είναι οι εξαιρέσεις: τίποτα δεν εγκαθίσταται γι' αυτούς μέσω mise, και η επιλογή οποιουδήποτε από τους δύο εγκαθιστά το δικό του αντίγραφο που ενημερώνεται μόνο του, όπως εξηγεί η ενότητα _Desktop apps_ παρακάτω.

### Εγκατάσταση και ενημέρωση agents

Εκτός από τους Hermes και OpenClaw, αυτοί οι agents χρησιμοποιούν την lazy εγκατάσταση του mise: η πρώτη εκκίνηση εγκαθιστά το CLI και οι επόμενες εκκινήσεις το επαναχρησιμοποιούν. Το mise ελέγχει επίσης έναν εγκατεστημένο agent για νέα έκδοση το πολύ μία φορά κάθε τέσσερις ώρες, ακριβώς πριν ξεκινήσει ή στο παρασκήνιο σε ένα prompt του shell. Αν αυτή η ενημέρωση αποτύχει ή είστε εκτός σύνδεσης, εκτελείται η εγκατεστημένη έκδοση. Το `omarchy update` ενημερώνει τους εγκατεστημένους agents μαζί με το υπόλοιπο Omarchy, και το `mup` ενημερώνει μόνο τα εργαλεία που διαχειρίζεται το mise.

Ο δικός του updater ενός agent, όπως το `claude update`, το `codex update` ή ένα κουμπί ενημέρωσης σε μια εφαρμογή, δεν ενημερώνει την εγκατάσταση που διαχειρίζεται το mise. Το `codex update` αποτυγχάνει, και το `claude update` μπορεί να αναφέρει επιτυχία ενώ εγκαθιστά ένα ξεχωριστό αντίγραφο που το mise δεν παρακολουθεί. Αν προτιμάτε να χρησιμοποιείτε τον εγγενή installer και updater ενός agent, προσθέστε τον στο `disable_tools`· δείτε [Προεγκατεστημένα εργαλεία CLI](18-development-tools.md#preinstalled-cli-tools).

Για να εγκαταστήσετε όλα τα ρυθμισμένα lazy εργαλεία πριν τα χρειαστείτε, εκτελέστε `mise install --include-lazy`. Αυτό περιλαμβάνει τα άλλα προεπιλεγμένα εργαλεία CLI του Omarchy καθώς και τους agents. Δείτε [Προεγκατεστημένα εργαλεία CLI](18-development-tools.md#preinstalled-cli-tools) για την εγκατάσταση ενός μεμονωμένου εργαλείου ή τη χρήση της δικής σας εγκατάστασης.

Το `grok` εγκαθίσταται μέσω του first-party πακέτου `grok` του mise, με τον ίδιο τρόπο όπως τα `claude` και `codex`. Εκτελέστε `grok` ή βάλτε του αστέρι στον πίνακα agents. Παραλείψτε τον installer `curl | bash` στο x.ai. Αυτή η διαδρομή βάζει ένα δεύτερο αντίγραφο στο `~/.grok/bin`, το προτάσσει στο `PATH` και αντικαθιστά το wrapper του Omarchy.

Το `dsh` ανοίγει το browser UI του στο `127.0.0.1:3080`, με τον κατάλογο εκκίνησης ως προεπιλεγμένο workspace του. Το browser UI του δεν δέχεται αρχικό prompt, οπότε το `omarchy agent prompt` το ανοίγει με το prompt στο πρόχειρό σας για επικόλληση. Το Omarchy το ξεκινά με το preset δικαιωμάτων χωρίς έγκριση της DeepSeek. Το DeepSeek Harness ανεβάζει αρχεία καταγραφής συνεδριών στην DeepSeek όταν χρησιμοποιείτε το επίσημο model API του· απενεργοποιήστε το στο _Settings > General > Upload Session Log_ στο browser UI του. Τα σχόλια που του στέλνετε ανεβαίνουν επίσης μαζί με τη συνεδρία, εκτός αν το ξεκινήσετε με `DSH_TELEMETRY_MODE=DISABLED`.

### Ο προεπιλεγμένος agent

Διαλέξτε τον προεπιλεγμένο agent σας με το αστέρι δίπλα σε έναν agent στον πίνακα agents, το οποίο είναι γεμάτο στον προεπιλεγμένο, ή με `omarchy default agent <name>`, το οποίο δέχεται επίσης οποιοδήποτε harness χωρίς γραμμή εκεί. Αν ο agent δεν είναι εγκατεστημένος ακόμη, η επιλογή του τον εγκαθιστά πρώτα, και αποκτά επίσης δικό του launcher στον launcher εφαρμογών, δίπλα στο Agent. Ένα φρέσκο Omarchy σας προσκαλεί να ρυθμίσετε έναν με μια ειδοποίηση μίας φοράς, η οποία ανοίγει τον πίνακα agents.

Η επιλογή του Claude επιχειρεί επίσης να ρυθμίσει την επέκταση browser του για Chromium, Chrome, Brave, Brave Origin και Edge. Η ρύθμιση της επέκτασης ισχύει για όλους τους χρήστες και μπορεί να ζητήσει τον κωδικό πρόσβασης του συστήματός σας· η ακύρωση ή μια αποτυχημένη εγκατάσταση επέκτασης εξακολουθεί να επιλέγει και να εκκινεί τον Claude. Επανεκκινήστε τον browser σας, ενεργοποιήστε την επέκταση αν σας ζητηθεί και συνδεθείτε στον Claude για να ολοκληρώσετε τη σύνδεσή της. Εκτελέστε `/chrome` στον Claude για να ελέγξετε τη σύνδεση. Οι Firefox και Zen δεν υποστηρίζουν αυτή την επέκταση. Αν ο Claude ήταν ήδη ο προεπιλεγμένος σας πριν προστεθεί αυτή η ρύθμιση, επιλέξτε τον ξανά για να εγκαταστήσετε την επέκταση.

Μόλις επιλέξετε, το `Super + Shift + Ctrl + A` εκκινεί τον προεπιλεγμένο agent σε ένα αποκλειστικό παράθυρο τερματικού (ή εμφανίζει τον επιλογέα αν δεν έχετε επιλέξει ακόμη). Μπορείτε επίσης να τον εκκινήσετε κατευθείαν σε μια εργασία με `omarchy agent prompt "Review this project"`. Τα Freebuff και DeepSeek Harness δεν δέχονται αρχικό prompt, οπότε ανοίγουν με το prompt στο πρόχειρό σας για επικόλληση. Οι agents που εκκινούνται έτσι εκτελούνται χωρίς επίβλεψη στις αντίστοιχες λειτουργίες τους που δεν σταματούν για να ρωτήσουν, οπότε να είστε έτοιμοι να κάνουν πράγματι πράγματα! Το MiniMax Code δεν έχει τέτοια λειτουργία για τις διαδραστικές συνεδρίες του, οπότε ζητά δικαιώματα ως συνήθως. Και επειδή οι agents αρνούνται να θυμούνται την εμπιστοσύνη για τον αρχικό κατάλογό σας, οι εκκινήσεις από το `$HOME` ξεκινούν στο `~/Work` αντ' αυτού.

Υπάρχουν και συντομεύσεις τερματικού: το `a` εκτελεί τον προεπιλεγμένο agent ενσωματωμένο στο τρέχον τερματικό, ενώ τα `c`, `cx` και `cy` ξεκινούν απευθείας τα OpenCode, Claude Code και Codex (πάλι στις λειτουργίες αυτόματης έγκρισής τους). Οι αλλαγές θέματος συγχρονίζονται επίσης στους agents: τα Claude Code, Pi, OpenCode και Hermes (αφού το Omarchy το εγκαταστήσει) ακολουθούν όλα όταν αλλάζετε το θέμα του Omarchy.

### Οι οδηγίες του agent σας

Οι προσωπικοί κανόνες για κάθε agent μπαίνουν στο `~/.agents/AGENTS.md`, δίπλα στα κοινόχρηστα skills στο `~/.agents/skills`. Ανοίξτε το με το εικονίδιο εγγράφου δίπλα στο + στον πίνακα agents, ή με `omarchy agent instructions --edit`, το οποίο το συνδέει επίσης σε κάθε harness που κρατά το δικό του καθολικό αρχείο: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, το `~/.copilot/copilot-instructions.md` του Copilot, και ούτω καθεξής. Τα Crush και Amp διαβάζουν τον σύνδεσμο `~/.config/AGENTS.md`, ενώ τα omp, Kimi και DeepSeek Harness διαβάζουν απευθείας το `~/.agents/AGENTS.md`. Η επιλογή ενός προεπιλεγμένου agent το συνδέει επίσης. Ένα αρχείο οδηγιών που είχατε ήδη γίνεται το κοινόχρηστο αν δεν υπήρχε κανένα ακόμη· διαφορετικά κρατιέται δίπλα στον σύνδεσμο ως `.bak`. Εκτελέστε `omarchy agent instructions` για να επανασυνδέσετε αφού εγκαταστήσετε άλλον agent.

### Ο πίνακας agents

Η επάνω γραμμή έχει ένα εικονίδιο agents. Πριν ρυθμίσετε έναν agent, ο πίνακάς του προσφέρει τρεις τρόπους για να ξεκινήσετε: συνδεθείτε σε μια συνδρομή Claude, Codex, Grok, Gemini, Muse, Cursor ή Copilot, ή στο More σε ένα πλάνο προγραμματισμού OpenCode Go, MiniMax, Synthetic ή Z.ai· πληρώστε ανά χρήση με Fireworks, OpenCode Zen and Go, OpenRouter, ή στο More με DeepSeek ή οποιονδήποτε άλλον πάροχο στον οποίο συνδέεται το OpenCode, όλα εκτελούνται στο OpenCode· ή εκτελέστε το καλύτερο μοντέλο για τον υπολογιστή σας, όταν ένα του ταιριάζει. Το πρώτο που ολοκληρώνετε γίνεται ο προεπιλεγμένος agent σας, και το + στον πίνακα προσφέρει τα ίδια τρία αργότερα. Μετά από αυτό, ο πίνακας βάζει κάθε συνδρομή σε μία σελίδα: κάθε agent και λογαριασμό με το πλάνο του, έναν μετρητή για καθένα από τα όρια συνεδρίας 5 ωρών και τα εβδομαδιαία όριά του με τον χρόνο μέχρι να μηδενιστεί (περάστε το δείκτη από πάνω για το ακριβές ποσοστό), ή το υπόλοιπο προπληρωμένο υπόλοιπο, κάτω από μια γραμμή που εναλλάσσεται σε ό,τι έχετε χρησιμοποιήσει σε όλα αυτά, όπως tokens αυτή την εβδομάδα και το μοντέλο που χρησιμοποιείτε περισσότερο. Στο _Make something cool_ προσφέρει αρχικά prompts για ένα νέο θέμα, plugin, εφαρμογή ή παιχνίδι που παραδίδουν την εργασία στον προεπιλεγμένο agent σας. Οι εφαρμογές χτίζονται με τον τρόπο που χτίζονται τα δικά του Hype, Monologue και Omacut του Omarchy, σε C++ και Qt Quick, ακολουθώντας το agent skill omarchy-make-app, και ο compiler και τα κομμάτια Qt που χρειάζονται έρχονται εγκατεστημένα. Τα παιχνίδια είναι μία μόνο σελίδα three.js στο `~/Games/vibes`, ακολουθώντας το agent skill omarchy-make-game, και όλα ανοίγουν από έναν launcher Game Vibes στο τρέχον θέμα· φορτώνουν το three.js από το web, οπότε χρειάζονται σύνδεση για να ξεκινήσουν. Τα Claude Code, Codex, Grok, Kimi, Cursor και η παροχή Grok Bot του, GitHub Copilot, Muse, Gemini (μέσω Antigravity) και Devin καλύπτονται εξαρχής με τα όριά τους, το Kimchi με το πλάνο του, τις προπληρωμένες μονάδες και τους προϋπολογισμούς δαπανών του, και τα Hermes, Mistral Vibe και Qwen Code δείχνουν τις συνεδρίες και τα tokens τους αφού τα χρησιμοποιήσετε. Τα πλάνα και τα κλειδιά παρόχων που χρησιμοποιείτε μέσω pi, omp ή opencode εμφανίζονται επίσης: τα OpenCode Zen and Go, το Z.ai GLM Coding Plan, το Ollama Cloud, το MiniMax Token Plan και το Synthetic με τα όριά τους· τα OpenRouter και DeepSeek με τα προπληρωμένα υπόλοιπά τους· το Fireworks με τις δαπάνες του τις τελευταίες 30 ημέρες. Τα tokens από μοντέλα που εκτελείτε στο δικό σας hardware μετρούν επίσης στα σύνολα· τα ίδια τα μοντέλα έχουν δικό τους πίνακα, που περιγράφεται στο [Τοπικά μοντέλα](#local-models). Κάθε agent μετριέται μία φορά, σε όποιον τον χρεώνει, όσα harnesses κι αν χρησιμοποιήσετε για να τον οδηγήσετε.

Κάντε αριστερό κλικ στο εικονίδιο της γραμμής ή πατήστε `Super + Ctrl + X` για τον πίνακα, δεξί κλικ για να εκκινήσετε τον προεπιλεγμένο agent σας και μεσαίο κλικ για ανανέωση. Τα αρχεία χρήσης πίσω από αυτόν αναδημιουργούνται κάθε 15 λεπτά από το `omarchy agent usage update`, και ο πίνακας μπορεί ακόμη να συγχωνεύσει χρήση από τα άλλα μηχανήματά σας μέσω ενός συγχρονισμένου φακέλου. Δείτε το README στο `$OMARCHY_PATH/shell/plugins/agents/` για τις πλήρεις ρυθμίσεις.

### Πολλαπλές συνδρομές

Αν πληρώνετε για περισσότερα από ένα πλάνα Claude, Codex ή Grok — ένα προσωπικό Max και ένα επαγγελματικό, ας πούμε — το Omarchy μπορεί να τα κρατήσει όλα συνδεδεμένα και να μετακινείται ανάμεσά τους. Προσθέστε μια συνδρομή με το + στον πίνακα agents, το οποίο σας καθοδηγεί εκεί ακριβώς, ή με `omarchy agent account add claude Work` (ή `codex`, ή `grok`). Το ίδιο + και η ίδια εντολή συνδέονται σε Gemini (`gemini`) και OpenCode (`opencode`), και αποθηκεύουν ένα κλειδί API Fireworks (`fireworks`) ή OpenRouter (`openrouter`) στο OpenCode· η εντολή συνδέεται επίσης σε Copilot (`copilot`), Cursor (`cursor`) και Muse (`muse`). Αυτά κρατούν από μία σύνδεση το καθένα. Εγκαθιστά το CLI αν λείπει. Ο πρώτος λογαριασμός για έναν πάροχο συνδέεται μέσω του κανονικού browser σας, ακριβώς εκεί όπου το CLI κοιτά πάντα. Κάθε επόμενος συνδέεται μέσω ενός ιδιωτικού παραθύρου, ώστε ο λογαριασμός στον οποίο ο browser σας είναι ήδη συνδεδεμένος να μην επιλεγεί κατά λάθος· συνδεθείτε εκεί ως ο λογαριασμός που προσθέτετε, και κλείστε πρώτα οποιοδήποτε ιδιωτικό παράθυρο είχατε ήδη ανοιχτό. Μην αποσυνδέεστε ποτέ από το CLI για να το κάνετε αυτό: η αποσύνδεση ανακαλεί την αποθηκευμένη σύνδεση, και αυτός ο λογαριασμός θα έπρεπε να προστεθεί ξανά.

Για να αντιγράψετε τις συνδέσεις συνδρομών σας σε άλλο μηχάνημα Omarchy μέσω SSH, εκτελέστε `omarchy agent account copy user@laptop`. Ο αποστολέας παρέχει έναν προσωρινό δέκτη όταν ο προορισμός δεν έχει εγκατεστημένο έναν, ώστε παλαιότερα μηχανήματα Omarchy να μπορούν να λάβουν λογαριασμούς χωρίς ενημέρωση. Οι εγκατεστημένοι δέκτες έχουν προτεραιότητα. Αυτό αντιγράφει όλες τις συνδρομές Claude, Codex και Grok· προσθέστε ονόματα παρόχων για να τις επιλέξετε, όπως στο `omarchy agent account copy laptop claude`. Τα ονόματα λογαριασμών και τα ID εντολών ταιριάζουν με την πηγή, συμπεριλαμβανομένων λογαριασμών που υπάρχουν ήδη στον προορισμό. Άσχετοι λογαριασμοί προορισμού λαμβάνουν ένα αριθμητικό επίθημα αν τα ονόματά τους συγκρούονται, και οι ρυθμίσεις, τα skills, τα plugins και το ιστορικό συνομιλιών μένουν τοπικά σε κάθε μηχάνημα.

Τα υπάρχοντα διαπιστευτήρια προορισμού διατηρούνται. Ένας λογαριασμός πηγής που είναι ήδη συνδεδεμένος εκεί συγχρονίζει το όνομά του χωρίς να αντικαταστήσει τα διαπιστευτήριά του· άλλοι λογαριασμοί προστίθενται δίπλα του. Για να αντικαταστήσετε αποθηκευμένα διαπιστευτήρια για λογαριασμούς που ταιριάζουν, χρησιμοποιήστε `omarchy agent account copy --replace laptop claude` αφού κλείσετε τις συνεδρίες αυτού του λογαριασμού στον προορισμό. Ένας φρέσκος προορισμός παίρνει επίσης τον ενεργό λογαριασμό και τις προτιμήσεις εναλλαγής της πηγής· ένας καθιερωμένος προορισμός κρατά τις δικές του.

Τα διαπιστευτήρια ταξιδεύουν μέσω SSH και αποθηκεύονται σε ιδιωτικά αρχεία στον προορισμό, οπότε αντιγράψτε μόνο σε μηχανήματα που εμπιστεύεστε. Αυτή είναι μια αντιγραφή μίας φοράς, όχι συνεχής συγχρονισμός. Τα refresh tokens του Codex μπορούν να εναλλαγούν από άλλο μηχάνημα, αφήνοντας μια αντιγραμμένη σύνδεση να χρειάζεται ανανέωση· ξεχωριστές συνδέσεις παραμένουν η πιο αξιόπιστη επιλογή για ταυτόχρονη χρήση σε πολλά μηχανήματα. Δείτε τις [οδηγίες ελέγχου ταυτότητας λογαριασμού του Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Ένας λογαριασμός ανά πάροχο είναι ενεργός, και κάθε νέα συνεδρία ξεκινά ως αυτός: τα `cx`, `cy`, ένα απλό `claude`, `codex` ή `grok`, οτιδήποτε εκκινείται μέσω `omarchy agent`, και scripts ή editors που βρίσκουν το CLI στο `PATH`. Αλλάξτε με `omarchy agent account use work` (και πίσω με `omarchy agent account use main`), ή στον πίνακα πατώντας τον αριθμό ενός λογαριασμού και στη συνέχεια `Enter` (ή κάνοντας κλικ στο αστέρι του). Οι τρέχουσες συνεδρίες Claude αλλάζουν επίσης, από το επόμενο μήνυμά τους: κάθε συνεδρία Claude εκτελείται στο `~/.claude`, το οποίο κρατά πάντα τη σύνδεση του ενεργού λογαριασμού. Μια συνεδρία Claude που ξεκίνησε στον δικό του φάκελο ενός λογαριασμού από ένα παλαιότερο Omarchy κρατά αυτή τη σύνδεση μέχρι να κλείσει, οπότε η εναλλαγή ονομάζει αυτές τις συνεδρίες και ολοκληρώνεται μόνη της μόλις φύγουν. Οι τρέχουσες συνεδρίες Codex και Grok μένουν στον λογαριασμό με τον οποίο ξεκίνησαν. Το ιστορικό συνομιλιών, οι ρυθμίσεις, τα skills και τα plugins είναι κοινόχρηστα μεταξύ λογαριασμών, οπότε το `claude --continue` στον ίδιο φάκελο συνεχίζει από εκεί που σταματήσατε στον νέο λογαριασμό.

Με περισσότερους από έναν λογαριασμούς, ο πίνακας δείχνει τα όρια κάθε λογαριασμού δίπλα δίπλα, με ένα γεμάτο αστέρι σε αυτόν που χρησιμοποιείται. Το Omarchy σας ειδοποιεί όταν ο ενεργός λογαριασμός περάσει το 95% ενός ορίου, και το κλικ στην ειδοποίηση αλλάζει στον λογαριασμό με το περισσότερο περιθώριο. Δεν αλλάζει ποτέ μόνο του. Αλλάξτε το όριο με `omarchy agent account threshold 90`. Αν κάθε λογαριασμός είναι πάνω από το όριο, θα το ακούσετε μία φορά, μαζί με το ποιος λογαριασμός ελευθερώνεται πρώτος. Ενώ ένας ενεργός λογαριασμός είναι εντός 15 μονάδων από το όριό του (80% στην προεπιλογή), τα όριά του ελέγχονται κάθε τρία λεπτά αντί για κάθε 15.

Το `omarchy agent account list` δείχνει κάθε λογαριασμό και τα τελευταία όριά του, το `omarchy agent account remove work` ξεχνά έναν, και το `omarchy agent account rename primary Hey` μετονομάζει έναν (ή κάντε κλικ στο όνομα ενός λογαριασμού στον πίνακα). Αυτές οι εντολές λειτουργούν στους λογαριασμούς του προεπιλεγμένου agent σας· για να φτάσετε στον άλλον πάροχο, ονομάστε τον πρώτα, όπως στο `omarchy agent account use codex side`. Η σύνδεση που είχατε ήδη στο `~/.claude` ή στο `~/.codex` είναι ο λογαριασμός _Main_. Του Codex μένει εκεί που είναι· του Claude περιμένει σε δικό του φάκελο ενώ ένας άλλος λογαριασμός είναι ενεργός. Ένας λογαριασμός που μένει αχρησιμοποίητος για περισσότερες από περίπου οκτώ ώρες μπορεί να δείξει _Sign-in required_· κάντε κλικ σε αυτόν για να συνδεθείτε ξανά σε αυτόν τον λογαριασμό ακριβώς στον πίνακα, ή αλλάξτε σε αυτόν και ξεκινήστε μια συνεδρία, η οποία ανανεώνει τη σύνδεση μόνη της. Οι MCP servers που προσθέτετε με `claude mcp add` φτάνουν σε κάθε λογαριασμό Claude, αφού όλοι εκτελούνται στο `~/.claude`· για Codex και Grok, οι servers που είχατε όταν προστέθηκε ένας λογαριασμός έρχονται μαζί του, αλλά οι μεταγενέστεροι φτάνουν μόνο στον λογαριασμό στον οποίο τους προσθέσατε. Το Claude Desktop κρατά δική του σύνδεση, και τα εργαλεία Codex ή Grok που έχουν ρυθμιστεί με απόλυτη διαδρομή σε ένα δυαδικό CLI δεν ακολουθούν την εναλλαγή. Ένα ρητό `CLAUDE_CONFIG_DIR`, `CODEX_HOME` ή `GROK_HOME` υπερισχύει του επιλεγμένου λογαριασμού.

### Διάγνωση κατάρρευσης

Το Omarchy παρακολουθεί το systemd-coredump για καταρρεύσεις διεργασιών. Μόλις διαλέξετε έναν προεπιλεγμένο agent, οποιοδήποτε πρόγραμμά σας αδειάσει core φέρνει μια ειδοποίηση "Process crashed" — κάντε κλικ σε αυτήν, και η κατάρρευση παραδίδεται στον προεπιλεγμένο agent σας μαζί με το skill omarchy-diagnose-crash του Omarchy, το οποίο καθοδηγεί τον agent στην εξακρίβωση των γεγονότων από το core dump και στην απόφαση αν η κατάρρευση αξίζει να αναφερθεί upstream. Μπορείτε επίσης να το εκτελέσετε με το χέρι απέναντι σε οποιοδήποτε PID από το `coredumpctl list` με `omarchy agent crash <pid>`.

Η παρακολούθηση είναι ενεργή από προεπιλογή. Απενεργοποιήστε την στο _Trigger > Toggle > Crash Capture Off_ (ή με `omarchy toggle crash-capture`) και οι ειδοποιήσεις σταματούν· το `omarchy agent crash <pid>` εξακολουθεί να λειτουργεί με το χέρι.

Οι καταρρεύσεις μπορούν επίσης να σιγαστούν ένα πρόγραμμα κάθε φορά, πράγμα που η διάγνωση σας προσφέρει στο τέλος. Το `omarchy crash mute hyprland` σταματά τις ειδοποιήσεις μόνο για αυτό το πρόγραμμα, το `omarchy crash mute hyprland off` τις επαναφέρει, και το `omarchy crash mute` από μόνο του παραθέτει ό,τι έχετε σιγάσει. Δέχεται τη διαδρομή του δυαδικού εξίσου ευχαρίστως με το όνομά του, οπότε το `omarchy crash mute /usr/bin/hyprland` κάνει το ίδιο πράγμα. Βάλτε σε εισαγωγικά ένα όνομα με κενό σε αυτό, όπως στο `omarchy crash mute 'Some App'`. Όλα τα άλλα εξακολουθούν να ειδοποιούν, και το σιγασμένο πρόγραμμα εξακολουθεί να καταρρέει — αυτό κρύβει την υπενθύμιση, δεν διορθώνει τίποτα.

### Εφαρμογές desktop

Το μενού _Install > AI_ φέρει επίσης μερικές γραφικές εφαρμογές AI: Amp Desktop, Antigravity Desktop, την εφαρμογή desktop ChatGPT, την εφαρμογή desktop Claude (τη Linux beta της Anthropic, με καρτέλες Chat, Cowork και Claude Code), Grok Bot για συνομιλία με τα μοντέλα της xAI, Herdr Desktop, Hermes Desktop, OpenClaw, την εφαρμογή desktop Perplexity και T3 Code. Το Grok Bot είναι η εφαρμογή συνομιλίας desktop. Ο coding agent είναι η εντολή `grok`.

Το Hermes Desktop είναι αυτό που πρέπει να γνωρίζετε, επειδή ένα μηχάνημα έχει ένα Hermes, και είναι της εφαρμογής: το Hermes εγκαθίσταται μόνο ποτέ μέσω της εφαρμογής, και η εντολή `hermes` που εκτελεί ο προεπιλεγμένος agent είναι της εφαρμογής. Η επιλογή του Hermes ως προεπιλεγμένου agent εγκαθιστά το ίδιο πράγμα που εγκαθιστά η καταχώριση _Install > AI_: το πακέτο, και ένα runtime Hermes στο `~/.hermes` που ρυθμίζεται από τον δικό του installer του Hermes, πράγμα που παίρνει μερικά λεπτά την πρώτη φορά. Αυτό το runtime είναι το ένα Hermes που χρησιμοποιούν η εντολή τερματικού `hermes`, ο προεπιλεγμένος agent και η εφαρμογή, και ενημερώνεται μόνο του με `hermes update` αντί να περιμένει μια έκδοση του Omarchy. Η εγκατάστασή του δίνει επίσης στο Hermes το θέμα του Omarchy ως skin με όνομα `omarchy`, το οποίο κάθε επιφάνεια του Hermes ακολουθεί καθώς αλλάζετε θέματα· διαλέξτε άλλο στις ρυθμίσεις Appearance του Hermes ή με `/skin` αν προτιμάτε να μην το κάνει, και το Omarchy αφήνει αυτή την επιλογή ήσυχη. Η αφαίρεση της εφαρμογής στο _Remove > AI_ κλείνει πρώτα το Hermes, συμπεριλαμβανομένης της πύλης, παίρνει αυτό το runtime μαζί της, και κρατά τις συνομιλίες, τις μνήμες σας και τα skills που το Hermes έγραψε για τον εαυτό του, εκτός αν του πείτε διαφορετικά: ρωτά, με προεπιλογή όχι, αν αυτά τα δεδομένα και οι ρυθμίσεις σύνδεσής σας πρέπει να φύγουν επίσης.

Η εμπειρία desktop του OpenClaw είναι το Control UI του, το οποίο ανοίγει ως web app που υποστηρίζεται από τη δική του τοπική πύλη. Το OpenClaw ζει στο `~/.openclaw` και ενημερώνεται μόνο του: χρησιμοποιήστε το κουμπί "Update Gateway" του Control UI ή εκτελέστε `openclaw update`, και η πύλη επανεκκινείται στη νέα έκδοση. Το Omarchy επιλέγει μόνο την έκδοση από την οποία ξεκινά μια φρέσκια εγκατάσταση. Το OpenClaw μπορεί επίσης να είναι ο προεπιλεγμένος agent σας: η επιλογή του με `omarchy default agent openclaw` ρυθμίζει αυτό το ίδιο αντίγραφο στο `~/.openclaw`, και ο agent ανοίγει το terminal UI του OpenClaw συνδεδεμένο στην πύλη του. Η αφαίρεση του OpenClaw στο _Remove > AI_ παίρνει την υπηρεσία πύλης και την εφαρμογή μαζί της και στη συνέχεια ρωτά αν το `~/.openclaw` πρέπει να φύγει επίσης, αφού αυτό κρατά τις συνομιλίες και τα διαπιστευτήριά σας δίπλα στο ίδιο το OpenClaw και τα runtimes plugins που κατεβάζει· η προεπιλογή το κρατά, και η εκ νέου εγκατάσταση του OpenClaw το ξαναπαίρνει.

Το Herdr Desktop είναι η εφαρμογή desktop [Herdr](https://herdr.dev): χώροι, καρτέλες και panes τερματικών και coding agents που συνεχίζουν να εκτελούνται στον πυρήνα του όταν κλείνετε το παράθυρο. Προέρχεται από τον δικό του installer του Herdr αντί για πακέτο, οπότε ζει στο `~/.local/share/herdr-app`, φέρνει τον πυρήνα του στο `~/.local/bin/herdr-core` όταν δεν έχετε έναν ακόμη, και ενημερώνει και τα δύο μόνο του. Κάθεται δίπλα στην εντολή `herdr` που διαθέτει το Omarchy στο `Super + Ctrl + Return` αντί να την αντικαθιστά, και παίρνει τα άμεσα πλήκτρα αυτής της εντολής: τα `Alt + Return` και `Alt + Shift + Return` χωρίζουν ένα pane προς τα κάτω ή προς τα δεξιά, το `Alt + Escape` το κλείνει, το `Ctrl + Alt + Arrow` μετακινείται μεταξύ panes, τα `Alt + 1..9` και `Alt + Left/Right` διαλέγουν μια καρτέλα, και το `Alt + Up/Down` μετακινείται μεταξύ χώρων. Το `Ctrl + 1..9` διαλέγει έναν χώρο και το `Alt + Shift + Up/Down` περνά βηματικά από agents. Τα πλήκτρα προθέματος `Ctrl + Space` μένουν μόνο για τερματικό, αφού η εφαρμογή δεν μπορεί να κρατήσει ένα απλό πλήκτρο Ctrl για μια ακολουθία. Το Omarchy τα γράφει αυτά στο `~/.config/herdr-app/keys.json`, και το `omarchy-refresh-herdr-app` τα επαναφέρει. Η εγκατάστασή του διαλέγει το θέμα Omarchy του Herdr, το οποίο ακολουθεί το θέμα Omarchy σας από τότε και μετά. Το Herdr κρατά ένα θέμα για τη φωτεινή λειτουργία και ένα για τη σκοτεινή, οπότε αφού αλλάξετε μεταξύ ενός σκοτεινού και ενός φωτεινού θέματος Omarchy, διαλέξτε Omarchy στον επιλογέα θέματος του Herdr άλλη μια φορά για την άλλη λειτουργία.

Το T3 Code εκτελείται από την επίσημη έκδοση AppImage του στο `~/.local/share/t3code` αντί από πακέτο, οπότε ενημερώνεται μόνο του. Η εγκατάστασή του ρωτά αν θα ξεκινήσει στο κανάλι Stable ή Nightly· αλλάξτε αργότερα στις ρυθμίσεις του T3 Code. Τα νήματα και οι ρυθμίσεις σας ζουν στο `~/.t3`, και η αφαίρεση του T3 Code στο _Remove > AI_ τα παίρνει μαζί της.

### Τοπικά μοντέλα

Εκτελέστε ένα ανοιχτό μοντέλο στο δικό σας μηχάνημα για τους coding agents σας. Τα prompts και ο κώδικάς σας μένουν στο μηχάνημα· τίποτα που στέλνεται στο μοντέλο δεν φεύγει από αυτό. Ξεκινήστε με:

```bash
omarchy models use best text
```

Αυτό ρυθμίζει το καλύτερο μοντέλο κειμένου για αυτό το μηχάνημα, το είδος που χρησιμοποιούν οι agents σας. Τα μοντέλα εικόνας, βίντεο και μουσικής έχουν το δικό τους καλύτερο: `omarchy models use best image`, `video` ή `music`. Εκτελέστε `omarchy models use best` για να δείτε την επιλογή κάθε είδους για αυτό το μηχάνημα.

Ή ανοίξτε τον πίνακα τοπικών μοντέλων από το εικονίδιο με τις σπίθες του στην επάνω γραμμή, δίπλα στο εικονίδιο agents, ή με Super + Ctrl + Alt + X, και επιλέξτε +. Το εικονίδιο εμφανίζεται όταν ένα μοντέλο ταιριάζει σε αυτό το μηχάνημα. Το Podman, που εκτελεί τα μοντέλα, έρχεται με το Omarchy, όπως και το toolkit container της NVIDIA σε ένα μηχάνημα NVIDIA, το οποίο τους δίνει τη GPU· αν λείπει κάποιο από τα δύο, η πρώτη ρύθμιση το εγκαθιστά. Το Omarchy στη συνέχεια διαλέγει το συνιστώμενο μοντέλο για αυτό το μηχάνημα, το κατεβάζει και το ξεκινά. Περιμένετε ένα κατέβασμα δεκάδων GB και το μεγαλύτερο μέρος της μνήμης του μηχανήματος να χρησιμοποιείται ενώ το μοντέλο εκτελείται: το Flash Next χρησιμοποιεί περίπου 100 GiB με το πλήρες context 256K του. Αν άλλα μοντέλα κρατούν τη μνήμη που χρειάζεται, ρυθμίζεται σταματημένο, έτοιμο να ξεκινήσει μόλις σταματήσετε ένα. Το μοντέλο σταματά στην αποσύνδεση· σταματήστε το εσείς όταν χρειάζεστε τη μνήμη για κάτι άλλο.

Το `omarchy models list` δείχνει τις επιλογές και εξηγεί γιατί μερικές δεν ταιριάζουν. Για να ρυθμίσετε άλλο ένα, εκτελέστε `omarchy models use <recipe>`. Σήμερα, τα `qwen3.8-flash-next-gufo` και `qwen3.8-27b-gufo` είναι διαθέσιμα για μηχανήματα Strix Halo 128 GB· το 27B παίρνει περίπου 40 GiB, οπότε αφήνει χώρο για άλλη δουλειά. Σε ένα laptop 64 GB με Intel's Arc B390, το `qwen3.6-35b-a3b-llamacpp` εκτελείται σε περίπου 30 GiB. Νέες συνταγές και συστάσεις φτάνουν με το `omarchy update`, μέσω του πακέτου.

Κάθε μοντέλο που ρυθμίζετε αποκτά τη δική του γραμμή στον πίνακα τοπικών μοντέλων: play για να το ξεκινήσετε, pause για να το σταματήσετε και να ελευθερώσετε τη μνήμη του, και το κουμπί τερματικού για να ανοίξετε τον agent σας σε αυτό. Στο επάνω μέρος, μια γραμμή δείχνει πώς η μνήμη του μηχανήματος μοιράζεται μεταξύ του ίδιου του Omarchy (το σύστημα και οι εφαρμογές σας), κάθε μοντέλου που εκτελείται, και ό,τι είναι ελεύθερο. Δείξτε σε ένα σταματημένο μοντέλο και η γραμμή δείχνει αν ταιριάζει, ή πόσο του λείπει. Πολλά μπορούν να εκτελούνται ταυτόχρονα όταν ταιριάζουν μαζί στη μνήμη· αν ένα δεν ταιριάζει, το Omarchy λέει ποιο μοντέλο που εκτελείται να σταματήσετε. Σύρετε γραμμές από το λογότυπό τους για να τις αναδιατάξετε, και πατήστε Delete σε μια επιλεγμένη γραμμή για να αφαιρέσετε ένα μοντέλο και το κατέβασμά του.

Κάθε μοντέλο προγραμματισμού που ρυθμίζετε αποκτά επίσης τη δική του καταχώριση στον launcher εφαρμογών, με το όνομα του μοντέλου και το λογότυπο του κατασκευαστή του, με τον τρόπο που η σύνδεση σε Claude, Codex ή Grok προσθέτει μία. Ανοίγει τον agent σας σε αυτό το μοντέλο, και ξεκινά πρώτα το μοντέλο αν δεν εκτελείται: το τερματικό το δείχνει να φορτώνει και παραδίδει στον agent μόλις είναι έτοιμο. Η αφαίρεση ενός μοντέλου αφαιρεί την καταχώρισή του.

Δεν είναι κάθε μοντέλο για προγραμματισμό. Τα μοντέλα εικόνας, βίντεο και μουσικής ανοίγουν στο Fantasi αντ' αυτού, την εφαρμογή του Omarchy για να φτιάχνετε εικόνες, βίντεο και μουσική με ένα μοντέλο που εκτελείται σε αυτό το μηχάνημα, επιλεγμένο εκεί ή από τη γραμμή τους στον πίνακα τοπικών μοντέλων.

Ένα μοντέλο συνεχίζει να εκτελείται ακριβώς όπως ρυθμίστηκε, οπότε μια ενημέρωση του Omarchy δεν επανεκκινεί ποτέ ένα κάτω από τους agents σας. Όταν το Omarchy έχει ένα νεότερο runtime ή νεότερα weights για ένα μοντέλο που έχετε ρυθμίσει, η γραμμή του δείχνει ένα κουμπί ενημέρωσης: πατήστε το και το μοντέλο ρυθμίζεται ξανά στο παρασκήνιο, κατεβάζοντας μόνο ό,τι άλλαξε, και επανεκκινείται στη νέα έκδοση. Ένα μοντέλο που ήταν σταματημένο μένει σταματημένο. Το `omarchy models update` κάνει το ίδιο για κάθε μοντέλο από ένα τερματικό.

Από τη γραμμή εντολών, τα `omarchy models start <recipe>` και `omarchy models stop <recipe>` κάνουν το ίδιο, το `omarchy models status` δείχνει κάθε μοντέλο, και το `omarchy agent --local-model <recipe>` ανοίγει αυτό το μοντέλο στο pi, όποιος κι αν είναι ο προεπιλεγμένος agent σας. Για να κάνετε το τοπικό μοντέλο σας αυτό που ανοίγουν το hotkey του agent, η κονσόλα Quake και το _Make something_, εκτελέστε `omarchy default agent local` ή βάλτε αστέρι σε ένα μοντέλο που εκτελείται στον πίνακα agents. Το pi παραθέτει επίσης κάθε μοντέλο που έχετε ρυθμίσει, και αυτά σε μηχανήματα με τα οποία έχετε συνδεθεί, στον δικό του επιλογέα μοντέλου, οπότε το απλό `pi` τα φτάνει επίσης. Οποιοσδήποτε client συμβατός με OpenAI μπορεί επίσης να συνδεθεί: το `status` δείχνει τη διεύθυνση κάθε μοντέλου (η πρώτη είναι `http://127.0.0.1:11435/v1`), το όνομα της συνταγής είναι το μοντέλο, και το κλειδί βρίσκεται στο `~/.config/omarchy/agent-local/key`.

Το `omarchy models remove <recipe>` διαγράφει ένα μοντέλο και τα κατεβάσματα που κανένα άλλο μοντέλο δεν χρησιμοποιεί.

Τα runtimes τρίτων επισημαίνονται με τον εκδότη τους. Το Omarchy εκτελεί κάθε μοντέλο χωρίς πρόσβαση δικτύου.

### Τοπικά LLM

Το Omarchy συνιστά δύο τρόπους εκτέλεσης τοπικών μοντέλων LLM: το LM Studio και το Ollama. Το LM Studio παρέχει μια διεπαφή GUI για την εύρεση μοντέλων open-weight, την εγκατάστασή τους και την εκτέλεσή τους. Είναι ένας εξαιρετικός τρόπος να ξεκινήσετε εύκολα. Το Ollama προσφέρει ένα CLI για να κάνετε κάτι παρόμοιο. Αλλά αν είστε νέοι στα τοπικά μοντέλα, θα ξεκινούσα με το LM Studio. Μπορείτε να εγκαταστήσετε οποιοδήποτε από τα δύο στο _Install > AI_ στο Μενού Omarchy.

### Τα skills του Omarchy

Τα agent skills βοηθούν το AI να χρησιμοποιεί συγκεκριμένα εργαλεία με συγκεκριμένο τρόπο, και το Omarchy διαθέτει επτά από αυτά. Το skill omarchy καλύπτει την προσαρμογή του συστήματος, όπως την τροποποίηση του config Hyprland σας ή τη ρύθμιση της γραμμής. Τα omarchy-make-theme, omarchy-make-plugin, omarchy-make-app και omarchy-make-game καλύπτουν τη δημιουργία κάτι νέου, το omarchy-contribute καλύπτει την αναφορά ενός bug ή την αποστολή μιας διόρθωσης upstream, και το omarchy-diagnose-crash εξετάζει το core dump μιας κατάρρευσης. Είναι symlinked στους καταλόγους skills για Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` και κάθε `~/.hermes/profiles/*/skills`), και τη γενική τοποθεσία `~/.agents/skills`, οπότε τα περισσότερα harnesses τα παίρνουν αυτόματα. Ένας δικός σας φάκελος skill με το ίδιο όνομα έχει προτεραιότητα.

Αλλά πρέπει να αντιμετωπίζετε αυτά τα skills ως πειραματικά. Διαφορετικά μοντέλα θα το χρησιμοποιήσουν με διαφορετικό αποτέλεσμα. Είναι καλύτερο να εκτελείτε πρώτα σε λειτουργία plan, ώστε να έχετε μια ιδέα τι θα ήθελε να αλλάξει ο agent. Και στη συνέχεια να είστε έτοιμοι να επαναφέρετε αλλαγές ή ακόμη και να εκτελέσετε `omarchy reinstall configs`, αν ο agent τα κάνει όλα μπάχαλο.
