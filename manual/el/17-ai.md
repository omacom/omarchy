# AI

Το Omarchy περιλαμβάνει προγράμματα εκκίνησης για τους παρακάτω agents προγραμματισμού χωρίς να επιλέγει έναν προεπιλεγμένο για εσάς. Εκτελέστε μια εντολή για να εγκατασταθεί το CLI της στην πρώτη χρήση και στη συνέχεια πραγματοποιήστε έλεγχο ταυτότητας όταν σας ζητηθεί. Ο Hermes αποτελεί την εξαίρεση: τίποτα δεν εγκαθίσταται για αυτόν στην πρώτη χρήση και αν τον επιλέξετε εγκαθίσταται το Hermes Desktop, όπως εξηγεί η ενότητα _Desktop apps_ παρακάτω.

### Εγκατάσταση και ενημέρωση agents

Με εξαίρεση τον Hermes, αυτοί οι agents χρησιμοποιούν τη lazy εγκατάσταση του mise: η πρώτη εκκίνηση εγκαθιστά το CLI και οι επόμενες εκκινήσεις το επαναχρησιμοποιούν. Το mise ελέγχει επίσης έναν εγκατεστημένο agent για νέα έκδοση το πολύ μία φορά κάθε τέσσερις ώρες, ακριβώς πριν ξεκινήσει ή στο παρασκήνιο σε ένα prompt του shell. Εάν αυτή η ενημέρωση αποτύχει ή είστε εκτός σύνδεσης, εκτελείται η εγκατεστημένη έκδοση. Το `omarchy update` ενημερώνει τους εγκατεστημένους agents μαζί με το υπόλοιπο Omarchy, και το `mup` ενημερώνει μόνο τα εργαλεία που διαχειρίζεται το mise.

Το δικό του πρόγραμμα ενημέρωσης ενός agent, όπως το `claude update`, το `codex update` ή ένα κουμπί ενημέρωσης σε μια εφαρμογή, δεν ενημερώνει την εγκατάσταση που διαχειρίζεται το mise. Το `codex update` αποτυγχάνει, και το `claude update` μπορεί να αναφέρει επιτυχία ενώ εγκαθιστά ένα ξεχωριστό αντίγραφο που το mise δεν παρακολουθεί. Εάν προτιμάτε να χρησιμοποιείτε το εγγενές πρόγραμμα εγκατάστασης και ενημέρωσης ενός agent, προσθέστε τον στο `disable_tools`· δείτε το [Προεγκατεστημένα εργαλεία CLI](18-development-tools.md#preinstalled-cli-tools).

Για να εγκαταστήσετε όλα τα ρυθμισμένα lazy εργαλεία πριν τα χρειαστείτε, εκτελέστε το `mise install --include-lazy`. Αυτό περιλαμβάνει και τα άλλα προεπιλεγμένα εργαλεία CLI του Omarchy καθώς και τους agents. Δείτε το [Προεγκατεστημένα εργαλεία CLI](18-development-tools.md#preinstalled-cli-tools) για την εγκατάσταση ενός μεμονωμένου εργαλείου ή τη χρήση της δικής σας εγκατάστασης.

Το `grok` εγκαθίσταται μέσω του first-party πακέτου `grok` του mise, με τον ίδιο τρόπο όπως τα `claude` και `codex`. Εκτελέστε το `grok` ή επιλέξτε το στην ενότητα _Agent > Harness_. Παραλείψτε το πρόγραμμα εγκατάστασης `curl | bash` στο x.ai. Αυτή η διαδρομή τοποθετεί ένα δεύτερο αντίγραφο στο `~/.grok/bin`, το προτάσσει στο `PATH` και αντικαθιστά το wrapper του Omarchy.

Το `dsh` ανοίγει το UI του στον browser στη διεύθυνση `127.0.0.1:3080`, με τον κατάλογο εκκίνησης ως προεπιλεγμένο χώρο εργασίας του. Το UI του στον browser δεν δέχεται αρχικό prompt, οπότε το `omarchy agent prompt` το ανοίγει με το prompt στο πρόχειρό σας για επικόλληση. Το Omarchy το εκκινεί με το preset δικαιωμάτων χωρίς έγκριση της DeepSeek. Το DeepSeek Harness ανεβάζει τα αρχεία καταγραφής συνεδριών στην DeepSeek όταν χρησιμοποιείτε το επίσημο API μοντέλων της· απενεργοποιήστε το στην ενότητα _Settings > General > Upload Session Log_ στο UI του στον browser. Τα σχόλια που του στέλνετε ανεβαίνουν επίσης μαζί με τη συνεδρία, εκτός αν το εκκινήσετε με `DSH_TELEMETRY_MODE=DISABLED`.

### Ο προεπιλεγμένος agent

Επιλέξτε τον προεπιλεγμένο agent σας με το `omarchy default agent <name>` ή στην ενότητα _Agent > Harness_ στο Omarchy Menu (`Super + Space`). Εάν ο agent δεν έχει εγκατασταθεί ακόμη, αν τον επιλέξετε εγκαθίσταται πρώτα. Μια νέα εγκατάσταση Omarchy θα σας καλέσει να κάνετε αυτή την επιλογή με μια εφάπαξ ειδοποίηση.

Η επιλογή του Claude επιχειρεί επίσης να ρυθμίσει την επέκταση του browser του για Chromium, Chrome, Brave, Brave Origin και Edge. Η ρύθμιση της επέκτασης ισχύει για όλους τους χρήστες και ενδέχεται να ζητήσει τον κωδικό πρόσβασης του συστήματός σας· η ακύρωση ή μια αποτυχημένη εγκατάσταση επέκτασης εξακολουθεί να επιλέγει και να εκκινεί τον Claude. Επανεκκινήστε τον browser σας, ενεργοποιήστε την επέκταση εάν σας ζητηθεί και συνδεθείτε στον Claude για να ολοκληρώσετε τη σύνδεσή της. Εκτελέστε το `/chrome` στον Claude για να ελέγξετε τη σύνδεση. Τα Firefox και Zen δεν υποστηρίζουν αυτή την επέκταση. Εάν ο Claude ήταν ήδη ο προεπιλεγμένος σας προτού προστεθεί αυτή η ρύθμιση, επιλέξτε τον ξανά για να εγκατασταθεί η επέκταση.

Αφού κάνετε την επιλογή, το `Super + Shift + Ctrl + A` εκκινεί τον προεπιλεγμένο agent σε ένα αποκλειστικό παράθυρο τερματικού (ή εμφανίζει τον επιλογέα εάν δεν έχετε επιλέξει ακόμη). Μπορείτε επίσης να τον εκκινήσετε απευθείας σε μια εργασία με το `omarchy agent prompt "Review this project"`. Τα Freebuff και DeepSeek Harness δεν δέχονται αρχικό prompt, οπότε ανοίγουν με το prompt στο πρόχειρό σας για επικόλληση αντί για αυτό. Οι agents που εκκινούνται με αυτόν τον τρόπο εκτελούνται χωρίς επίβλεψη στις αντίστοιχες λειτουργίες τους τύπου «μη σταματάς να ρωτάς», οπότε να είστε έτοιμοι να κάνουν πράγματι πράγματα! Το MiniMax Code δεν έχει τέτοια λειτουργία για τις διαδραστικές συνεδρίες του, οπότε ζητά δικαιώματα ως συνήθως. Και επειδή οι agents αρνούνται να θυμούνται την εμπιστοσύνη για τον αρχικό κατάλογό σας, οι εκκινήσεις από το `$HOME` ξεκινούν στο `~/Work` αντί για αυτό.

Υπάρχουν και συντομεύσεις τερματικού: το `a` εκτελεί τον προεπιλεγμένο agent ενσωματωμένο στο τρέχον τερματικό, ενώ τα `c`, `cx` και `cy` εκκινούν απευθείας τα OpenCode, Claude Code και Codex (και πάλι στις λειτουργίες αυτόματης έγκρισής τους). Οι αλλαγές θέματος συγχρονίζονται και στους agents: τα Claude Code, Pi, OpenCode και Hermes (αφού το Omarchy το έχει εγκαταστήσει) ακολουθούν όλα όταν αλλάζετε το θέμα του Omarchy.

### Οι οδηγίες του agent σας

Οι προσωπικοί κανόνες για κάθε agent μπαίνουν στο `~/.agents/AGENTS.md`, δίπλα στα κοινόχρηστα skills στο `~/.agents/skills`. Ανοίξτε το στην ενότητα _Agent > Instructions_, η οποία το συνδέει επίσης σε κάθε harness που διατηρεί το δικό του καθολικό αρχείο: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, το `~/.copilot/copilot-instructions.md` του Copilot, και ούτω καθεξής. Τα Crush και Amp διαβάζουν τον σύνδεσμο `~/.config/AGENTS.md`, ενώ τα omp, Kimi και DeepSeek Harness διαβάζουν απευθείας το `~/.agents/AGENTS.md`. Η επιλογή ενός προεπιλεγμένου agent το συνδέει επίσης. Ένα αρχείο οδηγιών που είχατε ήδη γίνεται το κοινόχρηστο εάν δεν υπήρχε ακόμη κανένα· διαφορετικά διατηρείται δίπλα στον σύνδεσμο ως `.bak`. Εκτελέστε το `omarchy agent instructions` για να επανασυνδεθείτε αφού εγκαταστήσετε άλλον agent.

### Το πάνελ agents

Η επάνω μπάρα έχει ένα εικονίδιο agents. Προτού ρυθμίσετε έναν agent, το πάνελ του σας καθοδηγεί στη σύνδεση σε Claude, Codex ή Grok, και ο πρώτος γίνεται ο προεπιλεγμένος agent σας. Μετά από αυτό, το πάνελ τοποθετεί κάθε συνδρομή σε μία σελίδα: κάθε agent και λογαριασμό με το πλάνο του, έναν μετρητή για κάθε όριο συνεδρίας 5 ωρών και εβδομαδιαίο όριό του με τον χρόνο μέχρι να μηδενιστεί (τοποθετήστε τον δείκτη για το ακριβές ποσοστό), ή το υπόλοιπο προπληρωμένο υπόλοιπο, κάτω από μια γραμμή που εναλλάσσεται σε ό,τι έχετε χρησιμοποιήσει σε όλους τους, όπως tokens αυτή την εβδομάδα και το μοντέλο που χρησιμοποιείτε περισσότερο. Στην ενότητα _Make something_ προσφέρει αρχικά prompts για ένα νέο θέμα, plugin, εφαρμογή ή παιχνίδι που παραδίδουν την εργασία στον προεπιλεγμένο agent σας. Οι εφαρμογές κατασκευάζονται με τον τρόπο που κατασκευάζονται τα ίδια τα Hype, Monologue και Omacut του Omarchy, σε C++ και Qt Quick, ακολουθώντας το agent skill omarchy-make-app, και ο compiler και τα κομμάτια Qt που χρειάζονται έρχονται εγκατεστημένα. Τα παιχνίδια είναι μία μόνο σελίδα three.js στο `~/Games/vibes`, ακολουθώντας το agent skill omarchy-make-game, και όλα ανοίγουν από έναν launcher Game Vibes στο τρέχον θέμα· φορτώνουν το three.js από το web, οπότε χρειάζονται σύνδεση για να ξεκινήσουν. Τα Claude Code, Codex, Grok, Kimi, Cursor και η παροχή Grok Bot του, GitHub Copilot, Muse, Antigravity, Kimchi και Devin καλύπτονται εξαρχής με τα όριά τους, και τα Hermes, Mistral Vibe και Qwen Code εμφανίζουν τις συνεδρίες και τα tokens τους αφού τα χρησιμοποιήσετε. Τα πλάνα και τα κλειδιά παρόχων που χρησιμοποιείτε μέσω pi, omp ή opencode εμφανίζονται επίσης: τα OpenCode Zen και Go, το Z.ai GLM Coding Plan, το Ollama Cloud, το MiniMax Token Plan και το Synthetic με τα όριά τους· τα Fireworks, OpenRouter και DeepSeek με τα προπληρωμένα υπόλοιπά τους· και τα μοντέλα που εκτελείτε στο δικό σας hardware στην ενότητα Local models. Κάθε agent μετράται μία φορά, σε όποιον τον χρεώνει, όσα harnesses κι αν χρησιμοποιήσετε για αυτόν.

Κάντε αριστερό κλικ στο εικονίδιο της μπάρας για το πάνελ, δεξί κλικ για να εκκινήσετε τον προεπιλεγμένο agent σας. Τα αρχεία χρήσης πίσω από αυτό αναγεννώνται κάθε 15 λεπτά από το `omarchy agent usage-update`, και το πάνελ μπορεί ακόμη και να συγχωνεύσει τη χρήση από τα άλλα μηχανήματά σας μέσω ενός συγχρονισμένου φακέλου. Δείτε το README στο `$OMARCHY_PATH/shell/plugins/agents/` για τις πλήρεις ρυθμίσεις.

### Πολλές συνδρομές

Εάν πληρώνετε για περισσότερα από ένα πλάνα Claude, Codex ή Grok — ένα προσωπικό Max και ένα επαγγελματικό, ας πούμε — το Omarchy μπορεί να τα κρατήσει όλα συνδεδεμένα και να μετακινείται μεταξύ τους. Προσθέστε μια συνδρομή με το + στο πάνελ agents, το οποίο σας καθοδηγεί εκεί επί τόπου, ή με το `omarchy agent account add claude Work` (ή `codex`, ή `grok`). Εγκαθιστά το CLI εάν λείπει. Ο πρώτος λογαριασμός για έναν πάροχο συνδέεται μέσω του κανονικού browser σας, ακριβώς εκεί που το CLI ψάχνει πάντα. Κάθε επόμενος συνδέεται μέσω ενός ιδιωτικού παραθύρου, ώστε ο λογαριασμός στον οποίο ο browser σας είναι ήδη συνδεδεμένος να μην αναληφθεί κατά λάθος· συνδεθείτε εκεί ως ο λογαριασμός που προσθέτετε και κλείστε πρώτα οποιοδήποτε ιδιωτικό παράθυρο είχατε ήδη ανοιχτό. Μην αποσυνδέεστε ποτέ από το CLI για να το κάνετε αυτό: η αποσύνδεση ανακαλεί την αποθηκευμένη σύνδεση και αυτός ο λογαριασμός θα έπρεπε να προστεθεί ξανά.

Για να αντιγράψετε τις συνδέσεις των συνδρομών σας σε άλλο μηχάνημα Omarchy μέσω SSH, εκτελέστε το `omarchy agent account copy user@laptop`. Ο αποστολέας παρέχει έναν προσωρινό παραλήπτη όταν ο προορισμός δεν έχει εγκατεστημένο έναν, οπότε παλαιότερα μηχανήματα Omarchy μπορούν να λάβουν λογαριασμούς χωρίς ενημέρωση. Οι εγκατεστημένοι παραλήπτες έχουν προτεραιότητα. Αυτό αντιγράφει όλες τις συνδρομές Claude, Codex και Grok· προσθέστε ονόματα παρόχων για να τις επιλέξετε, όπως στο `omarchy agent account copy laptop claude`. Τα ονόματα λογαριασμών και τα ID εντολών ταιριάζουν με την πηγή, συμπεριλαμβανομένων λογαριασμών που υπάρχουν ήδη στον προορισμό. Οι άσχετοι λογαριασμοί προορισμού λαμβάνουν ένα αριθμητικό επίθημα εάν τα ονόματά τους συγκρούονται, και οι ρυθμίσεις, τα skills, τα plugins και το ιστορικό συνομιλιών παραμένουν τοπικά σε κάθε μηχάνημα.

Τα υπάρχοντα διαπιστευτήρια προορισμού διατηρούνται. Ένας λογαριασμός πηγής που είναι ήδη συνδεδεμένος εκεί έχει το όνομά του συγχρονισμένο χωρίς να αντικατασταθούν τα διαπιστευτήριά του· οι άλλοι λογαριασμοί προστίθενται δίπλα του. Για να αντικαταστήσετε τα αποθηκευμένα διαπιστευτήρια για λογαριασμούς που ταιριάζουν, χρησιμοποιήστε το `omarchy agent account copy --replace laptop claude` αφού τερματίσετε τις συνεδρίες αυτού του λογαριασμού στον προορισμό. Ένας νέος προορισμός λαμβάνει επίσης τον ενεργό λογαριασμό και τις προτιμήσεις εναλλαγής της πηγής· ένας καθιερωμένος προορισμός διατηρεί τις δικές του.

Τα διαπιστευτήρια ταξιδεύουν μέσω SSH και αποθηκεύονται σε ιδιωτικά αρχεία στον προορισμό, οπότε αντιγράψτε μόνο σε μηχανήματα που εμπιστεύεστε. Αυτή είναι μια εφάπαξ αντιγραφή, όχι συνεχιζόμενος συγχρονισμός. Τα refresh tokens του Codex μπορούν να εναλλαχθούν από άλλο μηχάνημα, αφήνοντας μια αντιγραμμένη σύνδεση να χρειάζεται ανανέωση· οι ξεχωριστές συνδέσεις παραμένουν η πιο αξιόπιστη επιλογή για ταυτόχρονη χρήση σε πολλά μηχανήματα. Δείτε το [Οδηγίες ελέγχου ταυτότητας λογαριασμού του Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Ένας λογαριασμός ανά πάροχο είναι ενεργός, και κάθε νέα συνεδρία ξεκινά ως αυτός: `cx`, `cy`, ένα απλό `claude`, `codex` ή `grok`, οτιδήποτε εκκινείται μέσω του `omarchy agent`, και scripts ή editors που βρίσκουν το CLI στο `PATH`. Εναλλαγή με το `omarchy agent account use work` (και πίσω με το `omarchy agent account use main`), ή στο πάνελ πατώντας τον αριθμό ενός λογαριασμού και στη συνέχεια `Enter` (ή κάνοντας κλικ στο κουμπί Use του). Οι συνεδρίες Claude που εκτελούνται εναλλάσσονται επίσης, από το επόμενο μήνυμά τους: κάθε συνεδρία Claude εκτελείται στο `~/.claude`, το οποίο διατηρεί πάντα τη σύνδεση του ενεργού λογαριασμού. Μια συνεδρία Claude που ξεκίνησε στον δικό της φάκελο ενός λογαριασμού από ένα παλαιότερο Omarchy διατηρεί αυτή τη σύνδεση μέχρι να τερματιστεί, οπότε η εναλλαγή ονομάζει αυτές τις συνεδρίες και ολοκληρώνεται από μόνη της μόλις φύγουν. Οι συνεδρίες Codex και Grok που εκτελούνται παραμένουν στον λογαριασμό με τον οποίο ξεκίνησαν. Το ιστορικό συνομιλιών, οι ρυθμίσεις, τα skills και τα plugins είναι κοινόχρηστα μεταξύ λογαριασμών, οπότε το `claude --continue` στον ίδιο φάκελο συνεχίζει από εκεί που σταματήσατε στον νέο λογαριασμό.

Με περισσότερους από έναν λογαριασμούς, το πάνελ εμφανίζει τα όρια κάθε λογαριασμού δίπλα-δίπλα, με τον ενεργό σημειωμένο. Από προεπιλογή το Omarchy σας ειδοποιεί όταν ο ενεργός λογαριασμός ξεπεράσει το 95% ενός ορίου, και κάνοντας κλικ στην ειδοποίηση γίνεται εναλλαγή στον λογαριασμό με το περισσότερο περιθώριο. Τοποθετήστε τον δείκτη σε μια γραμμή λογαριασμού στο πάνελ και κάντε κλικ στο Autoswitch που εμφανίζεται δίπλα στο Use (ή πατήστε `m`), ή εκτελέστε το `omarchy agent account mode auto`, για να γίνεται η εναλλαγή από μόνη της· όσο είναι ενεργό, το Autoswitch παίρνει τη θέση του Use, και κάνοντας ξανά κλικ σε αυτό επιστρέφετε στις ειδοποιήσεις. Προσθέστε έναν αριθμό για να αλλάξετε το όριο, όπως στο `omarchy agent account mode auto 90`. Εάν κάθε λογαριασμός είναι πάνω από το όριο, θα το ακούσετε μία φορά, μαζί με το ποιος λογαριασμός ελευθερώνεται πρώτος. Ενώ ένας ενεργός λογαριασμός βρίσκεται εντός 15 μονάδων από το όριό του (80% στην προεπιλογή), τα όριά του ελέγχονται κάθε τρία λεπτά αντί για κάθε 15.

Το `omarchy agent account list` εμφανίζει κάθε λογαριασμό και τα τελευταία όριά του, το `omarchy agent account remove work` ξεχνά έναν, και το `omarchy agent account rename primary Hey` μετονομάζει έναν (ή κάντε κλικ στο όνομα ενός λογαριασμού στο πάνελ). Αυτές οι εντολές λειτουργούν στους λογαριασμούς του προεπιλεγμένου agent σας· για να φτάσετε στον άλλο πάροχο, ονομάστε τον πρώτα, όπως στο `omarchy agent account use codex side`. Η σύνδεση που είχατε ήδη στο `~/.claude` ή στο `~/.codex` είναι ο λογαριασμός _Main_. Του Codex παραμένει εκεί που είναι· του Claude περιμένει σε δικό του φάκελο ενώ ένας άλλος λογαριασμός είναι ενεργός. Ένας λογαριασμός που μένει αχρησιμοποίητος για περισσότερες από περίπου οκτώ ώρες μπορεί να εμφανίζει _Sign-in required_· κάντε κλικ σε αυτόν για να συνδεθείτε ξανά σε αυτόν τον λογαριασμό απευθείας στο πάνελ, ή μεταβείτε σε αυτόν και ξεκινήστε μια συνεδρία, η οποία ανανεώνει τη σύνδεση από μόνη της. Οι διακομιστές MCP που προσθέτετε με το `claude mcp add` φτάνουν σε κάθε λογαριασμό Claude, αφού όλοι εκτελούνται στο `~/.claude`· για Codex και Grok, οι διακομιστές που είχατε όταν προστέθηκε ένας λογαριασμός έρχονται μαζί του σε αυτόν, αλλά οι μεταγενέστεροι φτάνουν μόνο στον λογαριασμό στον οποίο τους προσθέσατε. Το Claude Desktop διατηρεί δική του σύνδεση, και τα εργαλεία Codex ή Grok που έχουν ρυθμιστεί με απόλυτη διαδρομή σε ένα δυαδικό CLI δεν ακολουθούν την εναλλαγή. Ένα ρητό `CLAUDE_CONFIG_DIR`, `CODEX_HOME` ή `GROK_HOME` έχει προτεραιότητα έναντι του επιλεγμένου λογαριασμού.

### Διάγνωση καταρρεύσεων

Το Omarchy παρακολουθεί το systemd-coredump για καταρρεύσεις διεργασιών. Όταν κάτι παρουσιάσει segfault, θα λάβετε μια ειδοποίηση "Process crashed" — κάντε κλικ σε αυτήν, και η κατάρρευση παραδίδεται στον προεπιλεγμένο agent σας μαζί με το skill diagnose-crash του Omarchy, το οποίο καθοδηγεί τον agent στη διαπίστωση των γεγονότων από το core dump και στην απόφαση για το αν η κατάρρευση αξίζει να αναφερθεί upstream. Μπορείτε επίσης να το εκτελέσετε χειροκίνητα για οποιοδήποτε PID από το `coredumpctl list` με το `omarchy agent crash <pid>`.

Η παρακολούθηση είναι ενεργή από προεπιλογή. Απενεργοποιήστε την στην ενότητα _Trigger > Toggle > Crash Capture_ (ή με το `omarchy toggle crash-capture`) και οι ειδοποιήσεις σταματούν· το `omarchy agent crash <pid>` εξακολουθεί να λειτουργεί χειροκίνητα.

Οι καταρρεύσεις μπορούν επίσης να σιγαστούν ένα πρόγραμμα κάθε φορά, πράγμα που σας προσφέρει η διάγνωση στο τέλος. Το `omarchy crash mute hyprland` σταματά τις ειδοποιήσεις μόνο για αυτό το πρόγραμμα, το `omarchy crash mute hyprland off` τις επαναφέρει, και το `omarchy crash mute` από μόνο του παραθέτει ό,τι έχετε σιγάσει. Δέχεται τη διαδρομή του δυαδικού τόσο ευχαρίστως όσο και το όνομά του, οπότε το `omarchy crash mute /usr/bin/hyprland` κάνει το ίδιο πράγμα. Βάλτε σε εισαγωγικά ένα όνομα με κενό, όπως στο `omarchy crash mute 'Some App'`. Όλα τα άλλα εξακολουθούν να ειδοποιούν, και το σιγασμένο πρόγραμμα εξακολουθεί να καταρρέει — αυτό κρύβει την υπενθύμιση, δεν διορθώνει τίποτα.

### Εφαρμογές desktop

Το μενού _Install > AI_ περιλαμβάνει επίσης μερικές γραφικές εφαρμογές AI: την εφαρμογή desktop ChatGPT, την εφαρμογή desktop Claude (το Linux beta της Anthropic, με καρτέλες Chat, Cowork και Claude Code), το Grok Bot για συνομιλία με τα μοντέλα της xAI, το Herdr Desktop, το Hermes Desktop, το OpenClaw, την εφαρμογή desktop Perplexity και το T3 Code. Το Grok Bot είναι η εφαρμογή συνομιλίας για desktop. Ο agent προγραμματισμού είναι η εντολή `grok`.

Το Hermes Desktop είναι αυτό που πρέπει να γνωρίζετε, επειδή ένα μηχάνημα έχει έναν Hermes, και είναι της εφαρμογής: ο Hermes εγκαθίσταται μόνο ποτέ μέσω της εφαρμογής, και η εντολή `hermes` που εκτελεί ο προεπιλεγμένος agent είναι της εφαρμογής. Η επιλογή του Hermes ως προεπιλεγμένου agent εγκαθιστά το ίδιο πράγμα που εγκαθιστά η καταχώριση _Install > AI_: το πακέτο, και ένα runtime Hermes στο `~/.hermes` που ρυθμίζεται από το δικό του πρόγραμμα εγκατάστασης του Hermes, το οποίο χρειάζεται μερικά λεπτά την πρώτη φορά. Αυτό το runtime είναι ο ένας Hermes που χρησιμοποιούν η εντολή `hermes` στο τερματικό, ο προεπιλεγμένος agent και η εφαρμογή, και ενημερώνεται μόνο του με το `hermes update` αντί να περιμένει μια έκδοση του Omarchy. Η εγκατάστασή του παραδίδει επίσης στον Hermes το θέμα του Omarchy ως skin με όνομα `omarchy`, το οποίο ακολουθεί κάθε επιφάνεια του Hermes καθώς αλλάζετε θέματα· επιλέξτε άλλο στις ρυθμίσεις Appearance του Hermes ή με το `/skin` εάν προτιμάτε να μην το κάνει, και το Omarchy αφήνει αυτή την επιλογή ήσυχη. Η αφαίρεση της εφαρμογής στην ενότητα _Remove > AI_ κλείνει πρώτα τον Hermes, συμπεριλαμβανομένου του gateway, παίρνει αυτό το runtime μαζί της, και διατηρεί τις συνομιλίες σας, τις μνήμες σας και τα skills που ο Hermes έγραψε για τον εαυτό του, εκτός αν του πείτε διαφορετικά: ρωτά, με προεπιλογή το όχι, αν πρέπει να φύγουν και αυτά τα δεδομένα και οι ρυθμίσεις σύνδεσής σας.

Η εμπειρία desktop του OpenClaw είναι το Control UI του, το οποίο ανοίγει ως web εφαρμογή υποστηριζόμενη από το δικό του τοπικό gateway. Το OpenClaw ζει στο `~/.openclaw` και ενημερώνεται μόνο του: χρησιμοποιήστε το κουμπί "Update Gateway" του Control UI ή εκτελέστε το `openclaw update`, και το gateway επανεκκινείται στη νέα έκδοση. Το Omarchy επιλέγει μόνο την έκδοση από την οποία ξεκινά μια νέα εγκατάσταση. Η αφαίρεση του OpenClaw στην ενότητα _Remove > AI_ παίρνει μαζί της την υπηρεσία gateway και την εφαρμογή και στη συνέχεια ρωτά αν πρέπει να φύγει και το `~/.openclaw`, αφού αυτό διατηρεί τις συνομιλίες και τα διαπιστευτήριά σας δίπλα στο ίδιο το OpenClaw και τα runtimes των plugins που κατεβάζει· η προεπιλογή το διατηρεί, και η εκ νέου εγκατάσταση του OpenClaw το ξαναβρίσκει.

Το Herdr Desktop είναι η εφαρμογή desktop [Herdr](https://herdr.dev): χώροι, καρτέλες και panes τερματικών και agents προγραμματισμού που συνεχίζουν να εκτελούνται στον πυρήνα του όταν κλείνετε το παράθυρο. Προέρχεται από το δικό του πρόγραμμα εγκατάστασης του Herdr αντί για ένα πακέτο, οπότε ζει στο `~/.local/share/herdr-app`, φέρνει τον πυρήνα του στο `~/.local/bin/herdr-core` όταν δεν έχετε ακόμη έναν, και ενημερώνει και τα δύο μόνα τους. Βρίσκεται δίπλα στην εντολή `herdr` που παρέχει το Omarchy στο `Super + Ctrl + Return` αντί να την αντικαθιστά, και αποκτά τα άμεσα πλήκτρα αυτής της εντολής: τα `Alt + Return` και `Alt + Shift + Return` διαιρούν ένα pane προς τα κάτω ή προς τα δεξιά, το `Alt + Escape` το κλείνει, το `Ctrl + Alt + Arrow` μετακινεί μεταξύ panes, τα `Alt + 1..9` και `Alt + Left/Right` επιλέγουν μια καρτέλα, και τα `Alt + Up/Down` μετακινούν μεταξύ χώρων. Το `Ctrl + 1..9` επιλέγει έναν χώρο και το `Alt + Shift + Up/Down` περνά από agents. Τα πλήκτρα προθέματος `Ctrl + Space` παραμένουν μόνο για τερματικό, αφού η εφαρμογή δεν μπορεί να κρατήσει ένα απλό πλήκτρο Ctrl για μια ακολουθία. Το Omarchy τα γράφει στο `~/.config/herdr-app/keys.json`, και το `omarchy-refresh-herdr-app` τα επαναφέρει. Η εγκατάστασή του επιλέγει το θέμα Omarchy του Herdr, το οποίο ακολουθεί από τότε το θέμα του Omarchy σας. Το Herdr διατηρεί ένα θέμα για τη φωτεινή λειτουργία και ένα για τη σκοτεινή, οπότε αφού αλλάξετε μεταξύ ενός σκοτεινού και ενός φωτεινού θέματος Omarchy, επιλέξτε το Omarchy στον επιλογέα θέματος του Herdr άλλη μία φορά για την άλλη λειτουργία.

Το T3 Code εκτελείται από την επίσημη έκδοση AppImage του στο `~/.local/share/t3code` αντί από ένα πακέτο, οπότε ενημερώνεται μόνο του. Η εγκατάστασή του ρωτά αν θα ξεκινήσετε στο κανάλι Stable ή Nightly· αλλάξτε αργότερα στις ρυθμίσεις του T3 Code. Τα threads σας και οι ρυθμίσεις σας ζουν στο `~/.t3`, και η αφαίρεση του T3 Code στην ενότητα _Remove > AI_ τα παίρνει μαζί της.

### Τοπικά μοντέλα

Εκτελέστε ένα ανοιχτό μοντέλο στο δικό σας μηχάνημα για τους agents προγραμματισμού σας. Τα prompts και ο κώδικάς σας παραμένουν στο μηχάνημα· τίποτα που στέλνεται στο μοντέλο δεν φεύγει από αυτό. Ξεκινήστε με:

```bash
omarchy agent local use best
```

Ή, στο πάνελ agents στην επάνω μπάρα, επιλέξτε + και στη συνέχεια Local AI, το οποίο εμφανίζεται όταν ένα μοντέλο χωρά σε αυτό το μηχάνημα. Την πρώτη φορά, αυτό εγκαθιστά το Podman, το οποίο εκτελεί τα μοντέλα, και σε ένα μηχάνημα NVIDIA το container toolkit της NVIDIA, το οποίο τους δίνει τη GPU. Στη συνέχεια το Omarchy επιλέγει το συνιστώμενο μοντέλο για αυτό το μηχάνημα, το κατεβάζει και το εκκινεί. Περιμένετε μια λήψη δεκάδων GB και το μεγαλύτερο μέρος της μνήμης του μηχανήματος να χρησιμοποιείται ενώ εκτελείται το μοντέλο: το Flash Next χρησιμοποιεί περίπου 100 GiB με το πλήρες context 256K του. Εάν άλλα μοντέλα κρατούν τη μνήμη που χρειάζεται, ρυθμίζεται σταματημένο, έτοιμο να ξεκινήσει μόλις σταματήσετε ένα. Το μοντέλο σταματά στην αποσύνδεση· σταματήστε το μόνοι σας όταν χρειάζεστε τη μνήμη για κάτι άλλο.

Το `omarchy agent local list` εμφανίζει τις επιλογές και εξηγεί γιατί μερικές δεν χωρούν. Για να ρυθμίσετε άλλη μία, εκτελέστε το `omarchy agent local use <recipe>`. Σήμερα, τα `qwen3.8-flash-next-gufo` και `qwen3.8-27b-gufo` είναι διαθέσιμα για μηχανήματα Strix Halo 128 GB· το 27B χρειάζεται περίπου 40 GiB, οπότε αφήνει χώρο για άλλη δουλειά. Σε ένα laptop 64 GB με Intel's Arc B390, το `qwen3.6-35b-a3b-llamacpp` εκτελείται σε περίπου 30 GiB. Νέα recipes και συστάσεις φτάνουν με το `omarchy update`, μέσω του πακέτου.

Κάθε μοντέλο που ρυθμίζετε αποκτά τη δική του γραμμή στο πάνελ agents, δίπλα στις συνδρομές σας: play για να το ξεκινήσετε, pause για να το σταματήσετε και να ελευθερώσετε τη μνήμη του, και το κουμπί τερματικού για να ανοίξετε τον agent σας σε αυτό. Πολλά μπορούν να εκτελούνται ταυτόχρονα όταν χωρούν μαζί στη μνήμη· εάν ένα δεν χωρά, το Omarchy λέει ποιο μοντέλο που εκτελείται να σταματήσετε. Σύρετε γραμμές για να τις αναδιατάξετε, και πατήστε Delete σε μια επιλεγμένη γραμμή για να αφαιρέσετε ένα μοντέλο και τη λήψη του.

Κάθε μοντέλο που ρυθμίζετε αποκτά επίσης τη δική του καταχώριση στον launcher εφαρμογών, με το όνομα του μοντέλου και το λογότυπο του κατασκευαστή του, με τον τρόπο που η σύνδεση σε Claude, Codex ή Grok προσθέτει μία. Ανοίγει τον agent σας σε αυτό το μοντέλο, και ξεκινά πρώτα το μοντέλο εάν δεν εκτελείται: το τερματικό το δείχνει να φορτώνει και παραδίδει στον agent μόλις είναι έτοιμο. Η αφαίρεση ενός μοντέλου αφαιρεί την καταχώρισή του.

Ένα μοντέλο συνεχίζει να εκτελείται ακριβώς όπως ρυθμίστηκε, οπότε μια ενημέρωση του Omarchy δεν επανεκκινεί ποτέ ένα κάτω από τους agents σας. Όταν το Omarchy έχει ένα νεότερο runtime ή νεότερα weights για ένα μοντέλο που έχετε ρυθμίσει, η γραμμή του εμφανίζει ένα κουμπί ενημέρωσης: πατήστε το και το μοντέλο ρυθμίζεται ξανά στο παρασκήνιο, κατεβάζοντας μόνο ό,τι άλλαξε, και επανεκκινείται στη νέα έκδοση. Ένα μοντέλο που ήταν σταματημένο παραμένει σταματημένο. Το `omarchy agent local update` κάνει το ίδιο για κάθε μοντέλο από ένα τερματικό.

Από τη γραμμή εντολών, τα `omarchy agent local start <recipe>` και `omarchy agent local stop <recipe>` κάνουν το ίδιο, το `omarchy agent local status` εμφανίζει κάθε μοντέλο, και το `omarchy agent --local` ανοίγει τον προεπιλεγμένο agent σας στο τελευταίο μοντέλο που ξεκινήσατε. Τα pi, OpenCode και Qwen Code μπορούν να χρησιμοποιήσουν ένα· με οποιονδήποτε άλλο προεπιλεγμένο ανοίγει στο pi. Το pi παραθέτει επίσης κάθε μοντέλο που έχετε ρυθμίσει, και εκείνα σε μηχανήματα με τα οποία έχετε συνδεθεί, στον δικό του επιλογέα μοντέλου, οπότε και το απλό `pi` τα φτάνει. Οποιοσδήποτε client συμβατός με OpenAI μπορεί επίσης να συνδεθεί: το `status` εμφανίζει τη διεύθυνση κάθε μοντέλου (η πρώτη είναι `http://127.0.0.1:11435/v1`), το όνομα του recipe είναι το μοντέλο, και το κλειδί βρίσκεται στο `~/.config/omarchy/agent-local/key`.

Το `omarchy agent local remove <recipe>` διαγράφει ένα μοντέλο και τις λήψεις που δεν χρησιμοποιεί κανένα άλλο μοντέλο.

Τα runtimes τρίτων επισημαίνονται με τον εκδότη τους. Το Omarchy εκτελεί κάθε μοντέλο χωρίς πρόσβαση στο δίκτυο.

### Τοπικά LLMs

Το Omarchy συνιστά δύο τρόπους εκτέλεσης τοπικών μοντέλων LLM: το LM Studio και το Ollama. Το LM Studio παρέχει ένα GUI περιβάλλον για να βρίσκετε μοντέλα open-weight, να τα εγκαθιστάτε και να τα εκτελείτε. Είναι ένας εξαιρετικός τρόπος να ξεκινήσετε εύκολα. Το Ollama προσφέρει ένα CLI για να κάνετε κάτι παρόμοιο. Αλλά εάν είστε νέοι στα τοπικά μοντέλα, θα ξεκινούσα με το LM Studio. Μπορείτε να εγκαταστήσετε οποιοδήποτε από τα δύο στην ενότητα _Install > AI_ στο Omarchy Menu.

### Το Omarchy Skill

Τα agent skills βοηθούν την AI να χρησιμοποιεί συγκεκριμένα εργαλεία με συγκεκριμένο τρόπο, και το Omarchy παρέχεται με ένα προεπιλεγμένο skill για την προσαρμογή του συστήματος. Όπως η τροποποίηση του config του Hyprland σας, η προσαρμογή της μπάρας, ή ακόμη και η δημιουργία ενός νέου θέματος από το μηδέν. Είναι συνδεδεμένο με symlink στους καταλόγους skills για Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` και κάθε `~/.hermes/profiles/*/skills`), και τη γενική τοποθεσία `~/.agents/skills`, οπότε τα περισσότερα harnesses το αναλαμβάνουν αυτόματα.

Αλλά πρέπει να αντιμετωπίζετε αυτό το skill ως πειραματικό. Διαφορετικά μοντέλα θα το χρησιμοποιήσουν με διαφορετικό αποτέλεσμα. Είναι καλύτερο να εκτελείται πρώτα σε plan mode, ώστε να έχετε μια ιδέα για το τι θα ήθελε να αλλάξει ο agent. Και μετά να είστε έτοιμοι να επαναφέρετε αλλαγές ή ακόμη και να καλέσετε το `omarchy reinstall configs`, εάν ο agent κάνει άνω-κάτω τα πάντα.
