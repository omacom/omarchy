# AI

Το Omarchy περιλαμβάνει προγράμματα εκκίνησης για τους παρακάτω coding agents, χωρίς να επιλέγει προεπιλογή για εσάς. Εγκαταστήστε έναν από _Install > AI > CLI_, και στη συνέχεια κάντε ταυτοποίηση όταν σας ζητηθεί. Τα Hermes και OpenClaw αποτελούν τις εξαιρέσεις: η επιλογή οποιουδήποτε από τα δύο στήνει το δικό του αντίγραφο που ενημερώνεται μόνο του, όπως εξηγεί παρακάτω η ενότητα _Desktop apps_.

### Εγκατάσταση και ενημέρωση agents

Εκτός από τα Hermes και OpenClaw, κάθε agent είναι ένα πακέτο από το δικό του αποθετήριο του Omarchy. Εγκαταστήστε έναν από _Install > AI > CLI_ ή με `omarchy install ai cli <command>`, και αφαιρέστε τον ξανά από _Remove > AI > CLI_, κάτι που αφήνει ανέπαφες τις συνδέσεις και το ιστορικό του. Η επιλογή ενός agent που δεν έχει εγκατασταθεί ακόμα τον εγκαθιστά επίσης: το να του βάλετε αστέρι στον πίνακα agents, το να τον επιλέξετε με `omarchy default agent <name>`, ή το να συνδεθείτε στη συνδρομή του. Το Omarchy δημοσιεύει κάθε νέα έκδοση ενός agent μέσα σε μία ώρα, σε κάθε κανάλι, και το `omarchy update` την εγκαθιστά μαζί με το υπόλοιπο σύστημα.

Καθώς το pacman τους διατηρεί ενημερωμένους, οι δικοί τους updater είναι απενεργοποιημένοι: το `claude update` ή ένα κουμπί ενημέρωσης σε μια εφαρμογή δεν έχει τίποτα να κάνει. Αν προτιμάτε να εκτελείτε έναν agent από το δικό του πρόγραμμα εγκατάστασης, χρησιμοποιήστε αυτό και αφήστε το πακέτο του Omarchy μη εγκατεστημένο· ένα αντίγραφο που υπάρχει ήδη στο `PATH` σας μετράει ως εγκατεστημένο. Παραλείψτε προγράμματα εγκατάστασης `curl | bash` που βάζουν ένα δεύτερο αντίγραφο μπροστά από αυτό του Omarchy στο `PATH`, όπως αυτό της x.ai για το `grok`.

Το `dsh` ανοίγει το browser UI του στο `127.0.0.1:3080`, με τον κατάλογο εκκίνησης ως προεπιλεγμένο workspace του. Το browser UI του δεν δέχεται αρχικό prompt, οπότε το `omarchy agent prompt` το ανοίγει με το prompt στο πρόχειρό σας για επικόλληση. Το Omarchy το ξεκινά με το preset δικαιωμάτων no-approval της DeepSeek. Το DeepSeek Harness ανεβάζει αρχεία καταγραφής συνεδριών στην DeepSeek όταν χρησιμοποιείτε το επίσημο model API του· απενεργοποιήστε το από _Settings > General > Upload Session Log_ στο browser UI του. Τα σχόλια που του στέλνετε ανεβαίνουν επίσης μαζί με τη συνεδρία, εκτός αν το ξεκινήσετε με `DSH_TELEMETRY_MODE=DISABLED`.

### Ο προεπιλεγμένος agent

Επιλέξτε τον προεπιλεγμένο agent σας με το αστέρι δίπλα σε έναν agent στον πίνακα agents, το οποίο είναι γεμάτο στον προεπιλεγμένο, ή με `omarchy default agent <name>`, το οποίο δέχεται επίσης οποιοδήποτε harness χωρίς γραμμή εκεί. Αν ο agent δεν έχει εγκατασταθεί ακόμα, η επιλογή του τον εγκαθιστά πρώτα, και αποκτά επίσης το δικό του πρόγραμμα εκκίνησης στο app launcher, δίπλα στο Agent. Ένα φρέσκο Omarchy σας προσκαλεί να στήσετε έναν με μια εφάπαξ ειδοποίηση, η οποία ανοίγει τον πίνακα agents.

Η επιλογή του Claude επιχειρεί επίσης να στήσει την επέκταση browser του για Chromium, Chrome, Brave, Brave Origin και Edge. Η εγκατάσταση της επέκτασης ισχύει για όλους τους χρήστες και μπορεί να ζητήσει τον κωδικό πρόσβασης του συστήματός σας· η ακύρωση ή μια αποτυχημένη εγκατάσταση επέκτασης εξακολουθεί να επιλέγει και να εκκινεί το Claude. Επανεκκινήστε τον browser σας, ενεργοποιήστε την επέκταση αν σας ζητηθεί, και συνδεθείτε στο Claude για να ολοκληρώσετε τη σύνδεσή της. Εκτελέστε `/chrome` στο Claude για να ελέγξετε τη σύνδεση. Τα Firefox και Zen δεν υποστηρίζουν αυτήν την επέκταση. Αν το Claude ήταν ήδη ο προεπιλεγμένος σας πριν προστεθεί αυτή η εγκατάσταση, επιλέξτε το ξανά για να εγκαταστήσετε την επέκταση.

Μόλις επιλέξετε, το `Super + Shift + Ctrl + A` εκκινεί τον προεπιλεγμένο agent σε ένα αποκλειστικό παράθυρο τερματικού (ή εμφανίζει τον επιλογέα αν δεν έχετε επιλέξει ακόμα). Μπορείτε επίσης να τον εκκινήσετε απευθείας σε μια εργασία με `omarchy agent prompt "Review this project"`. Τα Freebuff και DeepSeek Harness δεν δέχονται αρχικό prompt, οπότε ανοίγουν με το prompt στο πρόχειρό σας για επικόλληση αντί αυτού. Οι agents που εκκινούνται με αυτόν τον τρόπο εκτελούνται χωρίς επίβλεψη στις αντίστοιχες λειτουργίες don't-stop-to-ask τους, οπότε να είστε έτοιμοι να κάνουν πράγματι πράγματα! Το MiniMax Code δεν έχει τέτοια λειτουργία για τις διαδραστικές συνεδρίες του, οπότε ζητά δικαιώματα ως συνήθως. Και καθώς οι agents αρνούνται να θυμούνται την εμπιστοσύνη για τον αρχικό κατάλογό σας, οι εκκινήσεις από το `$HOME` ξεκινούν στο `~/Work` αντί αυτού.

Υπάρχουν και συντομεύσεις τερματικού: το `a` εκτελεί τον προεπιλεγμένο agent ενσωματωμένα στο τρέχον τερματικό, ενώ τα `c`, `cx`, `cy` και `ca` ξεκινούν απευθείας τα OpenCode, Claude Code, Codex και Antigravity (πάλι στις λειτουργίες αυτόματης έγκρισής τους). Οι αλλαγές θέματος συγχρονίζονται επίσης στους agents: τα Claude Code, Pi, OpenCode και Hermes (μόλις το Omarchy το έχει εγκαταστήσει) ακολουθούν όλα όταν αλλάζετε το θέμα του Omarchy.

### Οι οδηγίες του agent σας

Οι προσωπικοί κανόνες για κάθε agent μπαίνουν στο `~/.agents/AGENTS.md`, δίπλα στα κοινόχρηστα skills στο `~/.agents/skills`. Ανοίξτε το με το εικονίδιο εγγράφου δίπλα στο + στον πίνακα agents, ή με `omarchy agent instructions --edit`, το οποίο το συνδέει επίσης σε κάθε harness που κρατά το δικό του καθολικό αρχείο: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, το `~/.copilot/copilot-instructions.md` του Copilot, και ούτω καθεξής. Τα Crush και Amp διαβάζουν τον σύνδεσμο `~/.config/AGENTS.md`, ενώ τα omp, Kimi και DeepSeek Harness διαβάζουν απευθείας το `~/.agents/AGENTS.md`. Η επιλογή ενός προεπιλεγμένου agent το συνδέει επίσης. Ένα αρχείο οδηγιών που είχατε ήδη γίνεται το κοινόχρηστο αν δεν υπήρχε ακόμα κανένα· διαφορετικά κρατείται δίπλα στον σύνδεσμο ως `.bak`. Εκτελέστε `omarchy agent instructions` για να επανασυνδέσετε μετά την εγκατάσταση άλλου agent.

### Ο πίνακας agents

Η επάνω μπάρα έχει ένα εικονίδιο agents. Πριν στήσετε έναν agent, ο πίνακάς του προσφέρει τρεις τρόπους για να ξεκινήσετε: συνδεθείτε σε μια συνδρομή Claude, Codex, Grok, Gemini, Muse, Cursor ή Copilot, ή κάτω από το More σε ένα coding plan OpenCode Go, MiniMax, Synthetic ή Z.ai· πληρώστε καθώς προχωράτε με Fireworks, OpenCode Zen and Go, OpenRouter, ή κάτω από το More με DeepSeek ή οποιονδήποτε άλλο πάροχο στον οποίο συνδέεται το OpenCode, όλα εκτελούνται στο OpenCode· ή εκτελέστε το καλύτερο μοντέλο για τον υπολογιστή σας, όταν ένα του ταιριάζει. Το πρώτο που ολοκληρώνετε γίνεται ο προεπιλεγμένος agent σας, και το + στον πίνακα προσφέρει τα ίδια τρία αργότερα. Μετά από αυτό, ο πίνακας βάζει κάθε συνδρομή σε μία σελίδα: κάθε agent και λογαριασμό με το πλάνο του, έναν μετρητή για καθένα από τα όρια συνεδρίας 5 ωρών και εβδομαδιαία όριά του με τον χρόνο μέχρι να μηδενιστεί (περάστε το δείκτη από πάνω για το ακριβές ποσοστό), ή το υπόλοιπο προπληρωμένο υπόλοιπο, κάτω από μια γραμμή που εναλλάσσεται ανάμεσα σε όσα έχετε χρησιμοποιήσει σε όλους τους, όπως tokens αυτή την εβδομάδα και το μοντέλο που χρησιμοποιείτε περισσότερο. Κάτω από το _Make something cool_ προσφέρει αρχικά prompts για ένα νέο θέμα, plugin, εφαρμογή ή παιχνίδι που παραδίδουν την εργασία στον προεπιλεγμένο agent σας. Οι εφαρμογές χτίζονται με τον τρόπο που χτίζονται τα ίδια τα Hype, Monologue και Omacut του Omarchy, σε C++ και Qt Quick, ακολουθώντας το omarchy-make-app agent skill, και ο compiler και τα κομμάτια Qt που χρειάζονται έρχονται εγκατεστημένα. Τα παιχνίδια είναι μια ενιαία σελίδα three.js στο `~/Games/vibes`, ακολουθώντας το omarchy-make-game agent skill, και όλα ανοίγουν από ένα πρόγραμμα εκκίνησης Game Vibes στο τρέχον θέμα· φορτώνουν το three.js από το web, οπότε χρειάζονται σύνδεση για να ξεκινήσουν. Τα Claude Code, Codex, Grok, Kimi, Cursor και η παροχή Grok Bot του, GitHub Copilot, Muse, Gemini (μέσω Antigravity) και Devin καλύπτονται εξαρχής με τα όριά τους, το Kimchi με το πλάνο του, τις προπληρωμένες μονάδες και τους προϋπολογισμούς δαπανών του, και τα Hermes, Mistral Vibe και Qwen Code δείχνουν τις συνεδρίες και τα tokens τους μόλις τα χρησιμοποιήσετε. Τα πλάνα και τα κλειδιά παρόχων που χρησιμοποιείτε μέσω pi, omp ή opencode εμφανίζονται επίσης: OpenCode Zen and Go, το Z.ai GLM Coding Plan, Ollama Cloud, το MiniMax Token Plan και Synthetic με τα όριά τους· OpenRouter και DeepSeek με τα προπληρωμένα υπόλοιπά τους· Fireworks με τις δαπάνες του τις τελευταίες 30 ημέρες. Τα coding models που εκτελείτε στο δικό σας hardware αποκτούν δικές τους γραμμές, και τα tokens τους μετρούν επίσης στα σύνολα, όπως περιγράφεται στην ενότητα [Τοπικά μοντέλα](#local-models). Κάθε agent μετριέται μία φορά, κάτω από όποιον τον χρεώνει, όσα harnesses κι αν χρησιμοποιήσετε για να τον οδηγήσετε.

Κάντε αριστερό κλικ στο εικονίδιο της μπάρας ή πατήστε `Super + Ctrl + X` για τον πίνακα, δεξί κλικ για να εκκινήσετε τον προεπιλεγμένο agent σας, και μεσαίο κλικ για ανανέωση. Τα αρχεία χρήσης πίσω από αυτόν αναδημιουργούνται κάθε 15 λεπτά από το `omarchy agent usage update`, και ο πίνακας μπορεί ακόμη να συγχωνεύσει χρήση από τα άλλα μηχανήματά σας μέσω ενός συγχρονισμένου φακέλου. Δείτε το README κάτω από το `$OMARCHY_PATH/shell/plugins/agents/` για τις πλήρεις ρυθμίσεις.

### Πολλαπλές συνδρομές

Αν πληρώνετε για περισσότερα από ένα πλάνα Claude, Codex ή Grok — ένα προσωπικό Max και ένα επαγγελματικό, ας πούμε — το Omarchy μπορεί να τα κρατήσει όλα συνδεδεμένα και να μετακινείται ανάμεσά τους. Προσθέστε μια συνδρομή με το + στον πίνακα agents, το οποίο σας καθοδηγεί εκεί επιτόπου, ή με `omarchy agent account add claude Work` (ή `codex`, ή `grok`). Το ίδιο + και η ίδια εντολή συνδέονται στο Gemini (`gemini`) και στο OpenCode (`opencode`), και αποθηκεύουν ένα κλειδί API Fireworks (`fireworks`) ή OpenRouter (`openrouter`) στο OpenCode· η εντολή συνδέεται επίσης στο Copilot (`copilot`), στο Cursor (`cursor`) και στο Muse (`muse`). Αυτά κρατούν από μία σύνδεση το καθένα. Εγκαθιστά το CLI αν λείπει. Ο πρώτος λογαριασμός για έναν πάροχο συνδέεται μέσω του κανονικού browser σας, ακριβώς εκεί που κοιτάζει πάντα το CLI. Κάθε επόμενος συνδέεται μέσω ενός ιδιωτικού παραθύρου, ώστε ο λογαριασμός στον οποίο είναι ήδη συνδεδεμένος ο browser σας να μην επιλεγεί κατά λάθος· συνδεθείτε εκεί ως ο λογαριασμός που προσθέτετε, και κλείστε πρώτα οποιοδήποτε ιδιωτικό παράθυρο είχατε ήδη ανοιχτό. Μην αποσυνδέεστε ποτέ από το CLI για να το κάνετε αυτό: η αποσύνδεση ανακαλεί την αποθηκευμένη σύνδεση, και αυτός ο λογαριασμός θα έπρεπε να προστεθεί ξανά.

Για να αντιγράψετε τις συνδέσεις συνδρομών σας σε άλλο μηχάνημα Omarchy μέσω SSH, εκτελέστε `omarchy agent account copy user@laptop`. Ο αποστολέας παρέχει έναν προσωρινό παραλήπτη όταν ο προορισμός δεν έχει εγκατεστημένο έναν, οπότε παλαιότερα μηχανήματα Omarchy μπορούν να λάβουν λογαριασμούς χωρίς ενημέρωση. Οι εγκατεστημένοι παραλήπτες έχουν προτεραιότητα. Αυτό αντιγράφει όλες τις συνδρομές Claude, Codex και Grok· προσθέστε ονόματα παρόχων για να τις επιλέξετε, όπως στο `omarchy agent account copy laptop claude`. Τα ονόματα λογαριασμών και τα ID εντολών ταιριάζουν με την πηγή, συμπεριλαμβανομένων λογαριασμών που υπάρχουν ήδη στον προορισμό. Άσχετοι λογαριασμοί προορισμού λαμβάνουν ένα αριθμητικό επίθημα αν τα ονόματά τους συγκρούονται, και οι ρυθμίσεις, τα skills, τα plugins και το ιστορικό συνομιλιών παραμένουν τοπικά σε κάθε μηχάνημα.

Τα υπάρχοντα διαπιστευτήρια προορισμού διατηρούνται. Ένας λογαριασμός πηγής που είναι ήδη συνδεδεμένος εκεί έχει το όνομά του συγχρονισμένο χωρίς να αντικατασταθούν τα διαπιστευτήριά του· άλλοι λογαριασμοί προστίθενται δίπλα του. Για να αντικαταστήσετε αποθηκευμένα διαπιστευτήρια για αντίστοιχους λογαριασμούς, χρησιμοποιήστε `omarchy agent account copy --replace laptop claude` αφού κλείσετε τις συνεδρίες αυτού του λογαριασμού στον προορισμό. Ένας φρέσκος προορισμός λαμβάνει επίσης τον ενεργό λογαριασμό και τις προτιμήσεις εναλλαγής της πηγής· ένας καθιερωμένος προορισμός κρατά τις δικές του.

Τα διαπιστευτήρια ταξιδεύουν μέσω SSH και αποθηκεύονται σε ιδιωτικά αρχεία στον προορισμό, οπότε αντιγράψτε μόνο σε μηχανήματα που εμπιστεύεστε. Αυτή είναι μια εφάπαξ αντιγραφή, όχι συνεχής συγχρονισμός. Τα refresh tokens του Codex μπορούν να εναλλαχθούν από άλλο μηχάνημα, αφήνοντας μια αντιγραμμένη σύνδεση να χρειάζεται ανανέωση· ξεχωριστές συνδέσεις παραμένουν η πιο αξιόπιστη επιλογή για ταυτόχρονη χρήση σε πολλά μηχανήματα. Δείτε τις [οδηγίες ταυτοποίησης λογαριασμού του Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Ένας λογαριασμός ανά πάροχο είναι ενεργός, και κάθε νέα συνεδρία ξεκινά ως αυτός: `cx`, `cy`, ένα απλό `claude`, `codex` ή `grok`, οτιδήποτε εκκινείται μέσω `omarchy agent`, και scripts ή επεξεργαστές που βρίσκουν το CLI στο `PATH`. Αλλάξτε με `omarchy agent account use work` (και πίσω με `omarchy agent account use main`), ή στον πίνακα πατώντας τον αριθμό ενός λογαριασμού και στη συνέχεια `Enter` (ή κάνοντας κλικ στο αστέρι του). Οι συνεδρίες Claude που εκτελούνται αλλάζουν επίσης, από το επόμενο μήνυμά τους: κάθε συνεδρία Claude εκτελείται στο `~/.claude`, το οποίο κρατά πάντα τη σύνδεση του ενεργού λογαριασμού. Μια συνεδρία Claude που ξεκίνησε στον δικό της φάκελο ενός λογαριασμού από ένα παλαιότερο Omarchy κρατά αυτή τη σύνδεση μέχρι να κλείσει, οπότε η εναλλαγή ονομάζει αυτές τις συνεδρίες και ολοκληρώνεται μόνη της μόλις φύγουν. Οι συνεδρίες Codex και Grok που εκτελούνται παραμένουν στον λογαριασμό με τον οποίο ξεκίνησαν. Το ιστορικό συνομιλιών, οι ρυθμίσεις, τα skills και τα plugins μοιράζονται ανάμεσα στους λογαριασμούς, οπότε το `claude --continue` στον ίδιο φάκελο συνεχίζει από εκεί που σταματήσατε στον νέο λογαριασμό.

Με περισσότερους από έναν λογαριασμούς, ο πίνακας δείχνει τα όρια κάθε λογαριασμού δίπλα-δίπλα, με ένα γεμάτο αστέρι σε αυτόν που χρησιμοποιείται. Το Omarchy σας ειδοποιεί όταν ο ενεργός λογαριασμός ξεπεράσει το 95% ενός ορίου, και κάνοντας κλικ στην ειδοποίηση αλλάζετε στον λογαριασμό με το περισσότερο περιθώριο. Δεν αλλάζει ποτέ μόνο του. Αλλάξτε το όριο με `omarchy agent account threshold 90`. Αν κάθε λογαριασμός είναι πάνω από το όριο, θα ενημερωθείτε μία φορά, μαζί με το ποιος λογαριασμός ελευθερώνεται πρώτος. Ενώ ένας ενεργός λογαριασμός βρίσκεται εντός 15 μονάδων από το όριό του (80% στην προεπιλογή), τα όριά του ελέγχονται κάθε τρία λεπτά αντί για κάθε 15.

Το `omarchy agent account list` δείχνει κάθε λογαριασμό και τα τελευταία όριά του, το `omarchy agent account remove work` ξεχνά έναν, και το `omarchy agent account rename primary Hey` μετονομάζει έναν (ή κάντε κλικ στο όνομα ενός λογαριασμού στον πίνακα). Αυτές οι εντολές λειτουργούν στους λογαριασμούς του προεπιλεγμένου agent σας· για να φτάσετε στον άλλο πάροχο, ονομάστε τον πρώτα, όπως στο `omarchy agent account use codex side`. Η σύνδεση που είχατε ήδη στο `~/.claude` ή στο `~/.codex` είναι ο λογαριασμός _Main_. Του Codex παραμένει εκεί που είναι· του Claude περιμένει σε δικό του φάκελο ενώ ένας άλλος λογαριασμός είναι ενεργός. Ένας λογαριασμός που μένει αχρησιμοποίητος για περισσότερες από περίπου οκτώ ώρες μπορεί να δείξει _Sign-in required_· κάντε κλικ σε αυτόν για να συνδεθείτε ξανά σε αυτόν τον λογαριασμό ακριβώς μέσα στον πίνακα, ή αλλάξτε σε αυτόν και ξεκινήστε μια συνεδρία, η οποία ανανεώνει τη σύνδεση μόνη της. Οι διακομιστές MCP που προσθέτετε με `claude mcp add` φτάνουν σε κάθε λογαριασμό Claude, καθώς όλοι εκτελούνται στο `~/.claude`· για Codex και Grok, οι διακομιστές που είχατε όταν προστέθηκε ένας λογαριασμός έρχονται μαζί του, αλλά οι μεταγενέστεροι φτάνουν μόνο στον λογαριασμό στον οποίο τους προσθέσατε. Το Claude Desktop κρατά δική του σύνδεση, και τα εργαλεία Codex ή Grok που έχουν ρυθμιστεί με απόλυτη διαδρομή προς ένα δυαδικό αρχείο CLI δεν ακολουθούν την εναλλαγή. Ένα ρητό `CLAUDE_CONFIG_DIR`, `CODEX_HOME` ή `GROK_HOME` έχει προτεραιότητα έναντι του επιλεγμένου λογαριασμού.

### Διάγνωση καταρρεύσεων

Το Omarchy παρακολουθεί το systemd-coredump για καταρρεύσεις διεργασιών. Μόλις επιλέξετε έναν προεπιλεγμένο agent, οποιοδήποτε δικό σας πρόγραμμα που κάνει dump core φέρνει μια ειδοποίηση "Process crashed" — κάντε κλικ σε αυτήν, και η κατάρρευση παραδίδεται στον προεπιλεγμένο agent σας μαζί με το omarchy-diagnose-crash skill του Omarchy, το οποίο καθοδηγεί τον agent στην εξακρίβωση των γεγονότων από το core dump και στην απόφαση αν η κατάρρευση αξίζει να αναφερθεί upstream. Μπορείτε επίσης να το εκτελέσετε χειροκίνητα απέναντι σε οποιοδήποτε PID από το `coredumpctl list` με `omarchy agent crash <pid>`.

Η παρακολούθηση είναι ενεργή από προεπιλογή. Απενεργοποιήστε την από _Trigger > Toggle > Crash Capture Off_ (ή με `omarchy toggle crash-capture`) και οι ειδοποιήσεις σταματούν· το `omarchy agent crash <pid>` εξακολουθεί να λειτουργεί χειροκίνητα.

Οι καταρρεύσεις μπορούν επίσης να σιγαστούν ένα πρόγραμμα κάθε φορά, κάτι που σας προσφέρει η διάγνωση στο τέλος. Το `omarchy crash mute hyprland` σταματά τις ειδοποιήσεις μόνο για αυτό το πρόγραμμα, το `omarchy crash mute hyprland off` τις επαναφέρει, και το `omarchy crash mute` από μόνο του παραθέτει όσα έχετε σιγάσει. Δέχεται τη διαδρομή του δυαδικού αρχείου με την ίδια χαρά όπως το όνομά του, οπότε το `omarchy crash mute /usr/bin/hyprland` κάνει το ίδιο πράγμα. Βάλτε σε εισαγωγικά ένα όνομα με κενό, όπως στο `omarchy crash mute 'Some App'`. Όλα τα άλλα εξακολουθούν να ειδοποιούν, και το σιγασμένο πρόγραμμα εξακολουθεί να καταρρέει — αυτό κρύβει την υπενθύμιση, δεν διορθώνει τίποτα.

### Εφαρμογές desktop

Το _Install > AI > Desktop_ φέρει τις γραφικές εφαρμογές AI: Amp Desktop, Antigravity Desktop, την εφαρμογή desktop ChatGPT, την εφαρμογή desktop Claude (το Linux beta της Anthropic, με καρτέλες Chat, Cowork και Claude Code), Grok Bot για συνομιλία με τα μοντέλα της xAI, Herdr Desktop, Hermes Desktop, OpenClaw, την εφαρμογή desktop Perplexity και T3 Code. Το Grok Bot είναι η εφαρμογή desktop για συνομιλία. Ο coding agent είναι η εντολή `grok`.

Το Hermes Desktop είναι αυτό που πρέπει να γνωρίζετε, επειδή ένα μηχάνημα έχει ένα Hermes, και είναι της εφαρμογής: το Hermes εγκαθίσταται πάντα μόνο μέσω της εφαρμογής, και η εντολή `hermes` που εκτελεί ο προεπιλεγμένος agent είναι της εφαρμογής. Η επιλογή του Hermes ως προεπιλεγμένου agent εγκαθιστά το ίδιο πράγμα που κάνει η καταχώριση _Install > AI > Desktop_: το πακέτο, και ένα runtime Hermes κάτω από το `~/.hermes` στημένο από το δικό του πρόγραμμα εγκατάστασης του Hermes, το οποίο χρειάζεται μερικά λεπτά την πρώτη φορά. Αυτό το runtime είναι το ένα Hermes που χρησιμοποιούν η εντολή τερματικού `hermes`, ο προεπιλεγμένος agent και η εφαρμογή, και ενημερώνεται μόνο του με `hermes update` αντί να περιμένει μια έκδοση Omarchy. Η εγκατάστασή του δίνει επίσης στο Hermes το θέμα Omarchy ως skin με όνομα `omarchy`, το οποίο ακολουθεί κάθε επιφάνεια Hermes καθώς αλλάζετε θέματα· επιλέξτε άλλο κάτω από τις ρυθμίσεις Appearance του Hermes ή με `/skin` αν προτιμάτε να μην το κάνει, και το Omarchy αφήνει αυτή την επιλογή ήσυχη. Η αφαίρεση της εφαρμογής από _Remove > AI > Desktop_ κλείνει πρώτα το Hermes, συμπεριλαμβανομένου του gateway, παίρνει αυτό το runtime μαζί της, και κρατά τις συνομιλίες, τις μνήμες και τα skills που έγραψε το Hermes για τον εαυτό του, εκτός αν του πείτε διαφορετικά: ρωτά, με προεπιλογή το όχι, αν αυτά τα δεδομένα και οι ρυθμίσεις σύνδεσής σας πρέπει να φύγουν επίσης.

Η εμπειρία desktop του OpenClaw είναι το Control UI του, το οποίο ανοίγει ως web εφαρμογή υποστηριζόμενη από το δικό του τοπικό gateway. Το OpenClaw ζει στο `~/.openclaw` και ενημερώνεται μόνο του: χρησιμοποιήστε το κουμπί "Update Gateway" του Control UI ή εκτελέστε `openclaw update`, και το gateway επανεκκινείται στη νέα έκδοση. Το Omarchy επιλέγει μόνο την έκδοση από την οποία ξεκινά μια φρέσκια εγκατάσταση. Το OpenClaw μπορεί επίσης να είναι ο προεπιλεγμένος agent σας: η επιλογή του με `omarchy default agent openclaw` στήνει αυτό το ίδιο αντίγραφο στο `~/.openclaw`, και ο agent ανοίγει το terminal UI του OpenClaw συνδεδεμένο στο gateway του. Η αφαίρεση του OpenClaw από _Remove > AI > Desktop_ παίρνει την υπηρεσία gateway και την εφαρμογή μαζί της και στη συνέχεια ρωτά αν το `~/.openclaw` πρέπει να φύγει επίσης, καθώς αυτό κρατά τις συνομιλίες και τα διαπιστευτήριά σας δίπλα στο ίδιο το OpenClaw και τα runtimes plugins που κατεβάζει· η προεπιλογή το κρατά, και η εγκατάσταση του OpenClaw ξανά το ξαναβρίσκει.

Το Herdr Desktop είναι η εφαρμογή desktop [Herdr](https://herdr.dev): χώροι, καρτέλες και πλαίσια τερματικών και coding agents που συνεχίζουν να εκτελούνται στον πυρήνα του όταν κλείνετε το παράθυρο. Προέρχεται από το δικό του πρόγραμμα εγκατάστασης του Herdr και όχι από πακέτο, οπότε ζει στο `~/.local/share/herdr-app`, φέρνει τον πυρήνα του στο `~/.local/bin/herdr-core` όταν δεν έχετε ήδη έναν, και ενημερώνει και τα δύο μόνο του. Κάθεται δίπλα στην εντολή `herdr` που παρέχει το Omarchy στο `Super + Ctrl + Return` αντί να την αντικαθιστά, και αποκτά τα άμεσα πλήκτρα αυτής της εντολής: τα `Alt + Return` και `Alt + Shift + Return` χωρίζουν ένα πλαίσιο προς τα κάτω ή προς τα δεξιά, το `Alt + Escape` το κλείνει, το `Ctrl + Alt + Arrow` μετακινεί ανάμεσα στα πλαίσια, τα `Alt + 1..9` και `Alt + Left/Right` επιλέγουν μια καρτέλα, και τα `Alt + Up/Down` μετακινούν ανάμεσα στους χώρους. Το `Ctrl + 1..9` επιλέγει έναν χώρο και τα `Alt + Shift + Up/Down` περνούν από τους agents. Τα πλήκτρα προθέματος `Ctrl + Space` παραμένουν μόνο για τερματικό, καθώς η εφαρμογή δεν μπορεί να κρατήσει ένα απλό πλήκτρο Ctrl για μια ακολουθία. Το Omarchy τα γράφει αυτά στο `~/.config/herdr-app/keys.json`, και το `omarchy-refresh-herdr-app` τα επαναφέρει. Η εγκατάστασή του επιλέγει το θέμα Omarchy του Herdr, το οποίο ακολουθεί από τότε το θέμα Omarchy σας. Το Herdr κρατά ένα θέμα για τη φωτεινή λειτουργία και ένα για τη σκοτεινή, οπότε αφού αλλάξετε ανάμεσα σε ένα σκοτεινό και ένα φωτεινό θέμα Omarchy, επιλέξτε το Omarchy στον επιλογέα θέματος του Herdr άλλη μία φορά για την άλλη λειτουργία.

Το T3 Code εκτελείται από την επίσημη έκδοση AppImage του στο `~/.local/share/t3code` και όχι από πακέτο, οπότε ενημερώνεται μόνο του. Η εγκατάστασή του ρωτά αν θα ξεκινήσει στο κανάλι Stable ή Nightly· αλλάξτε αργότερα στις ρυθμίσεις του T3 Code. Τα νήματα και οι ρυθμίσεις σας ζουν στο `~/.t3`, και η αφαίρεση του T3 Code από _Remove > AI > Desktop_ τα παίρνει μαζί της.

### Τοπικά μοντέλα

Εκτελέστε ένα ανοιχτό μοντέλο στο δικό σας μηχάνημα για τους coding agents σας. Τα prompts και ο κώδικάς σας παραμένουν στο μηχάνημα· τίποτα που στέλνεται στο μοντέλο δεν φεύγει από αυτό. Ξεκινήστε με:

```bash
omarchy models use best text
```

Αυτό στήνει το καλύτερο μοντέλο κειμένου για αυτό το μηχάνημα, το είδος που χρησιμοποιούν οι agents σας. Τα μοντέλα εικόνας, βίντεο και μουσικής έχουν το δικό τους καλύτερο: `omarchy models use best image`, `video` ή `music`. Εκτελέστε `omarchy models use best` για να δείτε την επιλογή κάθε είδους για αυτό το μηχάνημα.

Ή επιλέξτε + στον πίνακα agents: κάτω από το _Use a local model_ παραθέτει κάθε coding model που ταιριάζει σε αυτό το μηχάνημα, το προτεινόμενο πρώτο. Το Podman, το οποίο εκτελεί τα μοντέλα, έρχεται με το Omarchy, όπως και το container toolkit της NVIDIA σε ένα μηχάνημα NVIDIA, το οποίο τους δίνει το GPU· αν λείπει κάποιο από τα δύο, η πρώτη εγκατάσταση το εγκαθιστά. Το Omarchy στη συνέχεια επιλέγει το προτεινόμενο μοντέλο για αυτό το μηχάνημα, το κατεβάζει και το ξεκινά. Περιμένετε ένα κατέβασμα δεκάδων GB και το μεγαλύτερο μέρος της μνήμης του μηχανήματος να χρησιμοποιείται ενώ το μοντέλο εκτελείται: το Flash Next χρησιμοποιεί περίπου 100 GiB με το πλήρες context 256K του. Αν άλλα μοντέλα κρατούν τη μνήμη που χρειάζεται, στήνεται σταματημένο, έτοιμο να ξεκινήσει μόλις σταματήσετε ένα. Το μοντέλο σταματά κατά την αποσύνδεση· σταματήστε το μόνοι σας όταν χρειάζεστε τη μνήμη για κάτι άλλο.

Το `omarchy models list` δείχνει τις επιλογές και εξηγεί γιατί μερικές δεν ταιριάζουν. Για να στήσετε άλλο ένα, εκτελέστε `omarchy models use <recipe>`. Σήμερα, τα `qwen3.8-flash-next-gufo` και `qwen3.8-27b-gufo` είναι διαθέσιμα για μηχανήματα Strix Halo 128 GB· το 27B παίρνει περίπου 40 GiB, οπότε αφήνει χώρο για άλλη δουλειά. Σε ένα laptop 64 GB με Intel's Arc B390, το `qwen3.6-35b-a3b-llamacpp` εκτελείται σε περίπου 30 GiB. Νέες συνταγές και προτάσεις φτάνουν με το `omarchy update`, μέσω του πακέτου.

Ένα coding model που προσθέτετε αποκτά δική του γραμμή στον πίνακα agents, δίπλα στις συνδρομές σας: play για να το ξεκινήσετε, pause για να το σταματήσετε και να ελευθερώσετε τη μνήμη του, το σημάδι Tailscale για να το μοιραστείτε με τα άλλα μηχανήματα στο tailnet σας ενώ εκτελείται, και το κουμπί τερματικού για να ανοίξετε τον agent σας σε αυτό. Η γραμμή του δείχνει το κατέβασμα, τη φόρτωση ή το σταμάτημα καθώς προχωρά, και το λέει όταν δεν υπάρχει αρκετή ελεύθερη μνήμη για να ξεκινήσει, ή συνδέει στα αρχεία καταγραφής του όταν σταμάτησε με σφάλμα. Πολλά μπορούν να εκτελούνται ταυτόχρονα όταν χωρούν μαζί στη μνήμη. Πατήστε Delete σε μια επιλεγμένη γραμμή για να αφαιρέσετε το μοντέλο από αυτό το μηχάνημα, κατέβασμα και όλα· το + μπορεί να το στήσει ξανά. Ένα coding model που στήθηκε από τερματικό περιμένει κάτω από το + μέχρι να το προσθέσετε, και το ίδιο κάνουν τα μοντέλα που εκτελεί ένα μηχάνημα με το οποίο έχετε συζευχθεί (`omarchy models pair <host>`).

Κάθε coding model που στήνετε αποκτά επίσης δική του καταχώριση στο app launcher, κάτω από το όνομα του μοντέλου και με το λογότυπο του δημιουργού του, με τον τρόπο που η σύνδεση στο Claude, Codex ή Grok προσθέτει μία. Ανοίγει τον agent σας σε αυτό το μοντέλο, και ξεκινά πρώτα το μοντέλο αν δεν εκτελείται: το τερματικό το δείχνει να φορτώνει και παραδίδει στον agent μόλις είναι έτοιμο. Η αφαίρεση ενός μοντέλου αφαιρεί την καταχώρισή του.

Δεν είναι κάθε μοντέλο για coding. Τα μοντέλα εικόνας, βίντεο και μουσικής ανοίγουν αντί αυτού στο Fantasi, την εφαρμογή του Omarchy για δημιουργία εικόνων, βίντεο και μουσικής με ένα μοντέλο που εκτελείται σε αυτό το μηχάνημα, και διαχειρίζονται εκεί ή με `omarchy models`.

Ένα μοντέλο συνεχίζει να εκτελείται ακριβώς όπως στήθηκε, οπότε μια ενημέρωση Omarchy δεν επανεκκινεί ποτέ ένα κάτω από τους agents σας. Όταν το Omarchy έχει νεότερο runtime ή νεότερα βάρη για ένα μοντέλο που έχετε στήσει, η γραμμή του δείχνει ένα κουμπί ενημέρωσης: πατήστε το και το μοντέλο στήνεται ξανά στο παρασκήνιο, κατεβάζοντας μόνο ό,τι άλλαξε, και επανεκκινείται στη νέα έκδοση. Ένα μοντέλο που ήταν σταματημένο παραμένει σταματημένο. Το `omarchy models update` κάνει το ίδιο για κάθε μοντέλο από τερματικό.

Από τη γραμμή εντολών, τα `omarchy models start <recipe>` και `omarchy models stop <recipe>` κάνουν το ίδιο, το `omarchy models status` δείχνει κάθε μοντέλο, και το `omarchy agent --local-model <recipe>` ανοίγει αυτό το μοντέλο στο pi, όποιος κι αν είναι ο προεπιλεγμένος agent σας. Για να κάνετε το τοπικό μοντέλο σας αυτό που ανοίγουν το πλήκτρο συντόμευσης agent, η κονσόλα Quake και το _Make something_, εκτελέστε `omarchy default agent local` ή βάλτε αστέρι σε ένα μοντέλο που εκτελείται στον πίνακα agents. Το pi παραθέτει επίσης κάθε μοντέλο που έχετε στήσει, και αυτά σε μηχανήματα με τα οποία έχετε συζευχθεί, στον δικό του επιλογέα μοντέλων, οπότε το απλό `pi` τα φτάνει επίσης. Οποιοσδήποτε client συμβατός με OpenAI μπορεί επίσης να συνδεθεί: το `status` δείχνει τη διεύθυνση κάθε μοντέλου (η πρώτη είναι `http://127.0.0.1:11435/v1`), το όνομα της συνταγής είναι το μοντέλο, και το κλειδί βρίσκεται στο `~/.config/omarchy/agent-local/key`.

Το `omarchy models remove <recipe>` διαγράφει ένα μοντέλο και τα κατεβάσματα που δεν χρησιμοποιεί κανένα άλλο μοντέλο.

Τα runtimes τρίτων επισημαίνονται με τον εκδότη τους. Το Omarchy εκτελεί κάθε μοντέλο χωρίς πρόσβαση δικτύου.

### Τοπικά LLMs

Το Omarchy προτείνει δύο τρόπους εκτέλεσης τοπικών μοντέλων LLM: LM Studio και Ollama. Το LM Studio παρέχει ένα GUI περιβάλλον για εύρεση μοντέλων ανοιχτών βαρών, εγκατάστασή τους και εκτέλεσή τους. Είναι ένας εξαιρετικός τρόπος για να ξεκινήσετε εύκολα. Το Ollama προσφέρει ένα CLI για να κάνετε το ίδιο παρόμοια. Αλλά αν είστε νέοι στα τοπικά μοντέλα, θα ξεκινούσα με το LM Studio. Εγκαταστήστε το LM Studio από _Install > AI > Desktop_ και το Ollama από _Install > AI > CLI_ στο Μενού Omarchy.

### Τα skills του Omarchy

Τα agent skills βοηθούν την AI να χρησιμοποιεί συγκεκριμένα εργαλεία με συγκεκριμένο τρόπο, και το Omarchy παρέχει επτά από αυτά. Το omarchy skill καλύπτει την προσαρμογή του συστήματος, όπως την τροποποίηση του config Hyprland σας ή την προσαρμογή της μπάρας. Τα omarchy-make-theme, omarchy-make-plugin, omarchy-make-app και omarchy-make-game καλύπτουν τη δημιουργία κάτι νέου, το omarchy-contribute καλύπτει την αναφορά ενός bug ή την αποστολή μιας διόρθωσης upstream, και το omarchy-diagnose-crash δουλεύει πάνω στο core dump μιας κατάρρευσης. Είναι συνδεδεμένα με συμβολικούς συνδέσμους στους καταλόγους skills για Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` και κάθε `~/.hermes/profiles/*/skills`), και τη γενική τοποθεσία `~/.agents/skills`, οπότε τα περισσότερα harnesses τα βρίσκουν αυτόματα. Ένας δικός σας φάκελος skill με το ίδιο όνομα έχει προτεραιότητα.

Αλλά πρέπει να αντιμετωπίζετε αυτά τα skills ως πειραματικά. Διαφορετικά μοντέλα θα το χρησιμοποιήσουν με διαφορετικό αποτέλεσμα. Είναι καλύτερο να εκτελείτε πρώτα σε λειτουργία σχεδιασμού, ώστε να έχετε μια ιδέα για το τι θα ήθελε να αλλάξει ο agent. Και στη συνέχεια να είστε έτοιμοι να αναιρέσετε αλλαγές ή ακόμη και να επικαλεστείτε `omarchy reinstall configs`, αν ο agent κάνει τα πάντα χάλια.
