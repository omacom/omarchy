# AI

Το Omarchy περιλαμβάνει προγράμματα εκκίνησης για τους παρακάτω agents προγραμματισμού, χωρίς να επιλέγει προεπιλογή για εσάς. Εκτελέστε μια εντολή για να εγκαταστήσετε το CLI της κατά την πρώτη χρήση και, στη συνέχεια, πραγματοποιήστε έλεγχο ταυτότητας όταν σας ζητηθεί. Το Hermes αποτελεί εξαίρεση: τίποτα δεν εγκαθίσταται για αυτό κατά την πρώτη χρήση, και η επιλογή του εγκαθιστά το Hermes Desktop, όπως εξηγεί παρακάτω η ενότητα _Εφαρμογές desktop_.

### Εγκατάσταση και ενημέρωση agents

Εκτός από το Hermes, αυτοί οι agents χρησιμοποιούν την lazy εγκατάσταση του mise: η πρώτη εκκίνηση εγκαθιστά το CLI, και οι μεταγενέστερες εκκινήσεις το επαναχρησιμοποιούν. Το mise ελέγχει επίσης έναν εγκατεστημένο agent για νέα έκδοση το πολύ μία φορά κάθε τέσσερις ώρες, ακριβώς πριν ξεκινήσει ή στο παρασκήνιο σε μια προτροπή shell. Εάν αυτή η ενημέρωση αποτύχει ή είστε εκτός σύνδεσης, εκτελείται η εγκατεστημένη έκδοση. Το `omarchy update` ενημερώνει τους εγκατεστημένους agents μαζί με το υπόλοιπο Omarchy, και το `mup` ενημερώνει μόνο τα εργαλεία που διαχειρίζεται το mise.

Το πρόγραμμα ενημέρωσης ενός agent, όπως το `claude update`, το `codex update` ή ένα κουμπί ενημέρωσης σε μια εφαρμογή, δεν ενημερώνει την εγκατάσταση που διαχειρίζεται το mise. Το `codex update` αποτυγχάνει, και το `claude update` μπορεί να αναφέρει επιτυχία ενώ εγκαθιστά ένα ξεχωριστό αντίγραφο που το mise δεν παρακολουθεί. Εάν προτιμάτε να χρησιμοποιείτε το εγγενές πρόγραμμα εγκατάστασης και ενημέρωσης ενός agent, προσθέστε το στο `disable_tools`· δείτε το [Προεγκατεστημένα εργαλεία CLI](18-development-tools.md#preinstalled-cli-tools).

Για να εγκαταστήσετε όλα τα ρυθμισμένα lazy εργαλεία πριν τα χρειαστείτε, εκτελέστε `mise install --include-lazy`. Αυτό περιλαμβάνει τα άλλα προεπιλεγμένα εργαλεία CLI του Omarchy καθώς και τους agents. Δείτε το [Προεγκατεστημένα εργαλεία CLI](18-development-tools.md#preinstalled-cli-tools) για την εγκατάσταση ενός μεμονωμένου εργαλείου ή τη χρήση της δικής σας εγκατάστασης.

Το `grok` εγκαθίσταται μέσω του first-party πακέτου `grok` του mise, με τον ίδιο τρόπο όπως τα `claude` και `codex`. Εκτελέστε `grok`, ή επιλέξτε το στο _Agent > Harness_. Παραλείψτε το πρόγραμμα εγκατάστασης `curl | bash` στο x.ai. Αυτή η διαδρομή τοποθετεί ένα δεύτερο αντίγραφο στο `~/.grok/bin`, το προτάσσει στο `PATH`, και αντικαθιστά το wrapper του Omarchy.

Το `dsh` ανοίγει το UI του προγράμματος περιήγησής του στο `127.0.0.1:3080`, με τον κατάλογο εκκίνησης ως προεπιλεγμένο χώρο εργασίας του. Το UI του προγράμματος περιήγησής του δεν δέχεται προτροπή εκκίνησης, οπότε το `omarchy agent prompt` το ανοίγει με την προτροπή στο πρόχειρό σας για επικόλληση. Το Omarchy το ξεκινά με το preset δικαιωμάτων χωρίς έγκριση της DeepSeek. Το DeepSeek Harness ανεβάζει αρχεία καταγραφής συνεδριών στην DeepSeek όταν χρησιμοποιείτε το επίσημο API μοντέλων της· απενεργοποιήστε το στο _Settings > General > Upload Session Log_ στο UI του προγράμματος περιήγησής του. Τα σχόλια που του στέλνετε ανεβαίνουν επίσης μαζί με τη συνεδρία, εκτός εάν το ξεκινήσετε με `DSH_TELEMETRY_MODE=DISABLED`.

### Ο προεπιλεγμένος agent

Επιλέξτε τον προεπιλεγμένο agent σας με `omarchy default agent <name>` ή στο _Agent > Harness_ στο Omarchy Menu (`Super + Space`). Εάν ο agent δεν είναι εγκατεστημένος ακόμη, η επιλογή του τον εγκαθιστά πρώτα. Ένα νέο Omarchy θα σας καλέσει να κάνετε αυτή την επιλογή με μια εφάπαξ ειδοποίηση.

Η επιλογή του Claude επιχειρεί επίσης να ρυθμίσει την επέκταση προγράμματος περιήγησής του για Chromium, Chrome, Brave, Brave Origin και Edge. Η ρύθμιση της επέκτασης ισχύει για όλους τους χρήστες και ενδέχεται να ζητήσει τον κωδικό πρόσβασης του συστήματός σας· η ακύρωση ή μια αποτυχημένη εγκατάσταση επέκτασης εξακολουθεί να επιλέγει και να εκκινεί το Claude. Επανεκκινήστε το πρόγραμμα περιήγησής σας, ενεργοποιήστε την επέκταση εάν σας ζητηθεί, και συνδεθείτε στο Claude για να ολοκληρώσετε τη σύνδεσή της. Εκτελέστε `/chrome` στο Claude για να ελέγξετε τη σύνδεση. Τα Firefox και Zen δεν υποστηρίζουν αυτή την επέκταση. Εάν το Claude ήταν ήδη η προεπιλογή σας πριν προστεθεί αυτή η ρύθμιση, επιλέξτε το ξανά για να εγκαταστήσετε την επέκταση.

Αφού επιλέξετε, το `Super + Shift + Ctrl + A` εκκινεί τον προεπιλεγμένο agent σε ένα αποκλειστικό παράθυρο τερματικού (ή εμφανίζει τον επιλογέα εάν δεν έχετε επιλέξει ακόμη). Μπορείτε επίσης να τον εκκινήσετε απευθείας σε μια εργασία με `omarchy agent prompt "Review this project"`. Τα Freebuff και DeepSeek Harness δεν δέχονται προτροπή εκκίνησης, οπότε ανοίγουν με την προτροπή στο πρόχειρό σας για επικόλληση. Οι agents που εκκινούνται με αυτόν τον τρόπο εκτελούνται χωρίς επίβλεψη στις αντίστοιχες λειτουργίες τους που δεν σταματούν για να ρωτήσουν, οπότε να είστε έτοιμοι να κάνουν πράγματι πράγματα! Το MiniMax Code δεν διαθέτει τέτοια λειτουργία για τις διαδραστικές συνεδρίες του, οπότε ζητά δικαιώματα ως συνήθως. Και επειδή οι agents αρνούνται να θυμούνται την εμπιστοσύνη για τον αρχικό κατάλογό σας, οι εκκινήσεις από το `$HOME` ξεκινούν στο `~/Work` αντ' αυτού.

Υπάρχουν και συντομεύσεις τερματικού: το `a` εκτελεί τον προεπιλεγμένο agent ενσωματωμένο στο τρέχον τερματικό, ενώ τα `c`, `cx` και `cy` ξεκινούν απευθείας τα OpenCode, Claude Code και Codex (και πάλι στις λειτουργίες αυτόματης έγκρισής τους). Οι αλλαγές θέματος συγχρονίζονται επίσης στους agents: τα Claude Code, Pi, OpenCode και Hermes (αφού το Omarchy το εγκαταστήσει) ακολουθούν όλα όταν αλλάζετε το θέμα του Omarchy.

### Οι οδηγίες του agent σας

Οι προσωπικοί κανόνες για κάθε agent ανήκουν στο `~/.agents/AGENTS.md`, δίπλα στα κοινόχρηστα skills στο `~/.agents/skills`. Ανοίξτε το στο _Agent > Instructions_, το οποίο το συνδέει επίσης σε κάθε harness που διατηρεί το δικό του καθολικό αρχείο: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, το `~/.copilot/copilot-instructions.md` του Copilot, και ούτω καθεξής. Τα Crush και Amp διαβάζουν τον σύνδεσμο `~/.config/AGENTS.md`, ενώ τα omp, Kimi και DeepSeek Harness διαβάζουν απευθείας το `~/.agents/AGENTS.md`. Η επιλογή ενός προεπιλεγμένου agent το συνδέει επίσης. Ένα αρχείο οδηγιών που είχατε ήδη γίνεται το κοινόχρηστο εάν δεν υπήρχε κανένα ακόμη· διαφορετικά διατηρείται δίπλα στον σύνδεσμο ως `.bak`. Εκτελέστε `omarchy agent instructions` για να επανασυνδέσετε μετά την εγκατάσταση άλλου agent.

### Το πάνελ agents

Η επάνω γραμμή έχει ένα εικονίδιο agents. Πριν ρυθμίσετε έναν agent, το πάνελ του σας καθοδηγεί στη σύνδεση στο Claude, το Codex ή το Grok, και ο πρώτος γίνεται ο προεπιλεγμένος agent σας. Μετά από αυτό, το πάνελ τοποθετεί κάθε συνδρομή σε μία σελίδα: κάθε agent και λογαριασμό με το πλάνο του, έναν μετρητή για καθένα από τα όρια συνεδρίας 5 ωρών και τα εβδομαδιαία όριά του με τον χρόνο μέχρι την επαναφορά του (τοποθετήστε τον δείκτη για το ακριβές ποσοστό), ή το υπόλοιπο προπληρωμένο υπόλοιπο, κάτω από μια γραμμή που εναλλάσσεται ανάμεσα σε όσα έχετε χρησιμοποιήσει σε όλα αυτά, όπως τα tokens αυτής της εβδομάδας και το μοντέλο που χρησιμοποιείτε περισσότερο. Στο _Make something_ προσφέρει προτροπές εκκίνησης για ένα νέο θέμα, plugin ή εφαρμογή που παραδίδουν την εργασία στον προεπιλεγμένο agent σας. Οι εφαρμογές δημιουργούνται με τον τρόπο που δημιουργούνται οι ίδιες οι εφαρμογές Hype, Monologue και Omacut του Omarchy, σε C++ και Qt Quick, ακολουθώντας το agent skill omarchy-app, και ο μεταγλωττιστής και τα κομμάτια Qt που χρειάζονται παρέχονται εγκατεστημένα. Τα Claude Code, Codex, Grok, Kimi, Cursor και το επίδομα Grok Bot του, GitHub Copilot, Muse, Antigravity, Kimchi και Devin καλύπτονται εξαρχής με τα όριά τους, και τα Hermes, Mistral Vibe και Qwen Code εμφανίζουν τις συνεδρίες και τα tokens τους αφού τα χρησιμοποιήσετε. Τα πλάνα και τα κλειδιά παρόχων που χρησιμοποιείτε μέσω pi, omp ή opencode εμφανίζονται επίσης: τα OpenCode Zen και Go, το Z.ai GLM Coding Plan, το Ollama Cloud, το MiniMax Token Plan και το Synthetic με τα όριά τους· τα Fireworks, OpenRouter και DeepSeek με τα προπληρωμένα υπόλοιπά τους· και τα μοντέλα που εκτελείτε στο δικό σας hardware στο Local models. Κάθε agent μετράται μία φορά, σε όποιον τον χρεώνει, μέσω όσων harnesses και αν τον χρησιμοποιείτε.

Κάντε αριστερό κλικ στο εικονίδιο της γραμμής για το πάνελ, δεξί κλικ για να εκκινήσετε τον προεπιλεγμένο agent σας. Τα αρχεία χρήσης πίσω από αυτό αναδημιουργούνται κάθε 15 λεπτά από το `omarchy agent usage-update`, και το πάνελ μπορεί ακόμη και να συγχωνεύσει χρήση από τα άλλα μηχανήματά σας μέσω ενός συγχρονισμένου φακέλου. Δείτε το README στο `$OMARCHY_PATH/shell/plugins/agents/` για τις πλήρεις ρυθμίσεις.

### Πολλαπλές συνδρομές

Εάν πληρώνετε για περισσότερα από ένα πλάνα Claude, Codex ή Grok — ένα προσωπικό Max και ένα επαγγελματικό, για παράδειγμα — το Omarchy μπορεί να τα κρατήσει όλα συνδεδεμένα και να μετακινείται ανάμεσά τους. Προσθέστε μια συνδρομή με το + στο πάνελ agents, το οποίο σας καθοδηγεί εκεί επιτόπου, ή με `omarchy agent account add claude Work` (ή `codex`, ή `grok`). Εγκαθιστά το CLI εάν λείπει. Ο πρώτος λογαριασμός για έναν πάροχο συνδέεται μέσω του κανονικού προγράμματος περιήγησής σας, ακριβώς εκεί που ψάχνει πάντα το CLI. Κάθε επόμενος συνδέεται μέσω ιδιωτικού παραθύρου, ώστε ο λογαριασμός στον οποίο είναι ήδη συνδεδεμένο το πρόγραμμα περιήγησής σας να μην επιλεγεί κατά λάθος· συνδεθείτε εκεί ως ο λογαριασμός που προσθέτετε, και κλείστε πρώτα οποιοδήποτε ιδιωτικό παράθυρο είχατε ήδη ανοιχτό. Μην αποσυνδέεστε ποτέ από το CLI για να το κάνετε αυτό: η αποσύνδεση ανακαλεί την αποθηκευμένη σύνδεση, και αυτός ο λογαριασμός θα έπρεπε να προστεθεί ξανά.

Για να αντιγράψετε τις συνδέσεις συνδρομών σας σε άλλο μηχάνημα Omarchy μέσω SSH, εκτελέστε `omarchy agent account copy user@laptop`. Ο αποστολέας παρέχει έναν προσωρινό δέκτη όταν ο προορισμός δεν έχει εγκατεστημένο έναν, οπότε παλαιότερα μηχανήματα Omarchy μπορούν να λάβουν λογαριασμούς χωρίς ενημέρωση. Οι εγκατεστημένοι δέκτες έχουν προτεραιότητα. Αυτό αντιγράφει όλες τις συνδρομές Claude, Codex και Grok· προσθέστε ονόματα παρόχων για να τις επιλέξετε, όπως στο `omarchy agent account copy laptop claude`. Τα ονόματα λογαριασμών και τα ID εντολών ταιριάζουν με την πηγή, συμπεριλαμβανομένων λογαριασμών που υπάρχουν ήδη στον προορισμό. Άσχετοι λογαριασμοί προορισμού λαμβάνουν αριθμητικό επίθημα εάν τα ονόματά τους συγκρούονται, και οι ρυθμίσεις, τα skills, τα plugins και το ιστορικό συνομιλιών παραμένουν τοπικά σε κάθε μηχάνημα.

Τα υπάρχοντα διαπιστευτήρια προορισμού διατηρούνται. Ένας λογαριασμός πηγής που είναι ήδη συνδεδεμένος εκεί συγχρονίζει το όνομά του χωρίς να αντικαθιστά τα διαπιστευτήριά του· άλλοι λογαριασμοί προστίθενται δίπλα του. Για να αντικαταστήσετε αποθηκευμένα διαπιστευτήρια για λογαριασμούς που ταιριάζουν, χρησιμοποιήστε `omarchy agent account copy --replace laptop claude` αφού κλείσετε τις συνεδρίες αυτού του λογαριασμού στον προορισμό. Ένας νέος προορισμός λαμβάνει επίσης τον ενεργό λογαριασμό και τις προτιμήσεις εναλλαγής της πηγής· ένας καθιερωμένος προορισμός διατηρεί τις δικές του.

Τα διαπιστευτήρια ταξιδεύουν μέσω SSH και αποθηκεύονται σε ιδιωτικά αρχεία στον προορισμό, οπότε αντιγράψτε μόνο σε μηχανήματα που εμπιστεύεστε. Αυτή είναι μια εφάπαξ αντιγραφή, όχι συνεχής συγχρονισμός. Τα tokens ανανέωσης του Codex μπορούν να ανανεωθούν από άλλο μηχάνημα, αφήνοντας μια αντιγραμμένη σύνδεση να χρειάζεται ανανέωση· οι ξεχωριστές συνδέσεις παραμένουν η πιο αξιόπιστη επιλογή για ταυτόχρονη χρήση σε πολλά μηχανήματα. Δείτε τις [οδηγίες ελέγχου ταυτότητας λογαριασμού του Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Ένας λογαριασμός ανά πάροχο είναι ενεργός, και κάθε νέα συνεδρία ξεκινά ως αυτός: `cx`, `cy`, ένα απλό `claude`, `codex` ή `grok`, οτιδήποτε εκκινείται μέσω `omarchy agent`, και scripts ή επεξεργαστές που βρίσκουν το CLI στο `PATH`. Αλλάξτε με `omarchy agent account use work` (και επιστρέψτε με `omarchy agent account use main`), ή στο πάνελ πατώντας τον αριθμό ενός λογαριασμού και στη συνέχεια `Enter` (ή κάνοντας κλικ στο κουμπί Use του). Οι συνεδρίες που εκτελούνται ήδη παραμένουν στον λογαριασμό με τον οποίο ξεκίνησαν. Το ιστορικό συνομιλιών, οι ρυθμίσεις, τα skills και τα plugins μοιράζονται μεταξύ λογαριασμών, οπότε το `claude --continue` στον ίδιο φάκελο συνεχίζει από εκεί που σταματήσατε στον νέο λογαριασμό.

Με περισσότερους από έναν λογαριασμούς, το πάνελ εμφανίζει τα όρια κάθε λογαριασμού δίπλα-δίπλα, με τον ενεργό επισημασμένο. Από προεπιλογή, το Omarchy σας ειδοποιεί όταν ο ενεργός λογαριασμός ξεπεράσει το 95% ενός ορίου, και το κλικ στην ειδοποίηση αλλάζει στον λογαριασμό με το μεγαλύτερο περιθώριο. Τοποθετήστε τον δείκτη πάνω στη γραμμή ενός λογαριασμού στο πάνελ και κάντε κλικ στο Autoswitch που εμφανίζεται δίπλα στο Use (ή πατήστε `m`), ή εκτελέστε `omarchy agent account mode auto`, για να αλλάζει από μόνο του· ενώ είναι ενεργό, το Autoswitch παίρνει τη θέση του Use, και το κλικ ξανά επιστρέφει στην ειδοποίηση. Προσθέστε έναν αριθμό για να αλλάξετε το όριο, όπως στο `omarchy agent account mode auto 90`. Εάν κάθε λογαριασμός είναι πάνω από το όριο, θα ενημερωθείτε μία φορά, μαζί με το ποιος λογαριασμός ελευθερώνεται πρώτος. Ενώ ένας ενεργός λογαριασμός βρίσκεται εντός 15 μονάδων από το όριό του (80% στην προεπιλογή), τα όριά του ελέγχονται κάθε τρία λεπτά αντί για κάθε 15.

Το `omarchy agent account list` εμφανίζει κάθε λογαριασμό και τα τελευταία όριά του, το `omarchy agent account remove work` ξεχνά έναν, και το `omarchy agent account rename primary Hey` μετονομάζει έναν (ή κάντε κλικ στο όνομα ενός λογαριασμού στο πάνελ). Αυτές οι εντολές λειτουργούν στους λογαριασμούς του προεπιλεγμένου agent σας· για να φτάσετε στον άλλο πάροχο, ονομάστε τον πρώτα, όπως στο `omarchy agent account use codex side`. Η σύνδεση που είχατε ήδη στο `~/.claude` ή στο `~/.codex` είναι ο λογαριασμός _Main_ και παραμένει εκεί που είναι. Ένας λογαριασμός που μένει αχρησιμοποίητος για περισσότερες από περίπου οκτώ ώρες μπορεί να εμφανίσει _Sign-in required_· κάντε κλικ σε αυτόν για να συνδεθείτε ξανά σε αυτόν τον λογαριασμό απευθείας στο πάνελ, ή ξεκινήστε μια συνεδρία σε αυτόν, η οποία ανανεώνει τη σύνδεση από μόνη της. Οι διακομιστές MCP που είχατε όταν προστέθηκε ένας λογαριασμός έρχονται μαζί του, αλλά όσοι προσθέτετε αργότερα με `claude mcp add` φτάνουν μόνο στον λογαριασμό στον οποίο τους προσθέσατε. Το Claude Desktop και τα εργαλεία που έχουν ρυθμιστεί με απόλυτη διαδρομή σε ένα δυαδικό CLI δεν ακολουθούν την αλλαγή. Ένα ρητό `CLAUDE_CONFIG_DIR`, `CODEX_HOME` ή `GROK_HOME` έχει προτεραιότητα έναντι του επιλεγμένου λογαριασμού.

### Διάγνωση κατάρρευσης

Το Omarchy παρακολουθεί το systemd-coredump για καταρρεύσεις διεργασιών. Όταν κάτι παρουσιάσει segfault, θα λάβετε μια ειδοποίηση "Process crashed" — κάντε κλικ σε αυτήν, και η κατάρρευση παραδίδεται στον προεπιλεγμένο agent σας μαζί με το skill diagnose-crash του Omarchy, το οποίο καθοδηγεί τον agent στην εξακρίβωση των γεγονότων από το core dump και στην απόφαση για το αν η κατάρρευση αξίζει να αναφερθεί upstream. Μπορείτε επίσης να το εκτελέσετε χειροκίνητα για οποιοδήποτε PID από το `coredumpctl list` με `omarchy agent crash <pid>`.

Η παρακολούθηση είναι ενεργή από προεπιλογή. Απενεργοποιήστε την στο _Trigger > Toggle > Crash Capture_ (ή με `omarchy toggle crash-capture`) και οι ειδοποιήσεις σταματούν· το `omarchy agent crash <pid>` εξακολουθεί να λειτουργεί χειροκίνητα.

Οι καταρρεύσεις μπορούν επίσης να σιγήσουν ένα πρόγραμμα τη φορά, πράγμα που σας προσφέρει η διάγνωση στο τέλος. Το `omarchy crash mute hyprland` σταματά τις ειδοποιήσεις μόνο για αυτό το πρόγραμμα, το `omarchy crash mute hyprland off` τις επαναφέρει, και το `omarchy crash mute` μόνο του παραθέτει όσα έχετε θέσει σε σίγαση. Δέχεται τη διαδρομή του δυαδικού τόσο ευχαρίστως όσο το όνομά του, οπότε το `omarchy crash mute /usr/bin/hyprland` κάνει το ίδιο πράγμα. Βάλτε σε εισαγωγικά ένα όνομα με κενό, όπως στο `omarchy crash mute 'Some App'`. Όλα τα υπόλοιπα εξακολουθούν να ειδοποιούν, και το πρόγραμμα σε σίγαση εξακολουθεί να καταρρέει — αυτό κρύβει την υπενθύμιση, δεν διορθώνει τίποτα.

### Εφαρμογές desktop

Το μενού _Install > AI_ περιλαμβάνει επίσης μερικές γραφικές εφαρμογές AI: την εφαρμογή desktop ChatGPT, την εφαρμογή desktop Claude (το Linux beta της Anthropic, με καρτέλες Chat, Cowork και Claude Code), το Grok Bot για συνομιλία με τα μοντέλα της xAI, το Herdr Desktop, το Hermes Desktop, το OpenClaw, την εφαρμογή desktop Perplexity και το T3 Code. Το Grok Bot είναι η εφαρμογή desktop συνομιλίας. Ο agent προγραμματισμού είναι η εντολή `grok`.

Το Hermes Desktop είναι αυτό που πρέπει να γνωρίζετε, επειδή ένα μηχάνημα έχει ένα Hermes, και είναι της εφαρμογής: το Hermes εγκαθίσταται μόνο μέσω της εφαρμογής, και η εντολή `hermes` που εκτελεί ο προεπιλεγμένος agent είναι της εφαρμογής. Η επιλογή του Hermes ως προεπιλεγμένου agent εγκαθιστά το ίδιο πράγμα που εγκαθιστά η καταχώριση _Install > AI_: το πακέτο, και ένα runtime Hermes στο `~/.hermes` που ρυθμίζεται από το δικό του πρόγραμμα εγκατάστασης του Hermes, το οποίο διαρκεί μερικά λεπτά την πρώτη φορά. Αυτό το runtime είναι το ένα Hermes που χρησιμοποιούν η εντολή τερματικού `hermes`, ο προεπιλεγμένος agent και η εφαρμογή, και ενημερώνεται μόνο του με `hermes update` αντί να περιμένει μια έκδοση του Omarchy. Η εγκατάστασή του παραδίδει επίσης στο Hermes το θέμα Omarchy ως skin με το όνομα `omarchy`, το οποίο ακολουθεί κάθε επιφάνεια του Hermes καθώς αλλάζετε θέματα· επιλέξτε άλλο στις ρυθμίσεις Appearance του Hermes ή με `/skin` εάν προτιμάτε να μην το κάνει, και το Omarchy αφήνει αυτή την επιλογή ήσυχη. Η κατάργηση της εφαρμογής στο _Remove > AI_ κλείνει πρώτα το Hermes, συμπεριλαμβανομένης της πύλης, παίρνει αυτό το runtime μαζί της, και διατηρεί τις συνομιλίες, τις μνήμες σας και τα skills που έγραψε το Hermes για τον εαυτό του, εκτός εάν του πείτε διαφορετικά: ρωτά, με προεπιλογή το όχι, αν πρέπει να φύγουν και αυτά τα δεδομένα και οι ρυθμίσεις σύνδεσής σας.

Η εμπειρία desktop του OpenClaw είναι το Control UI του, το οποίο ανοίγει ως web εφαρμογή υποστηριζόμενη από τη δική του τοπική πύλη. Το OpenClaw βρίσκεται στο `~/.openclaw` και ενημερώνεται μόνο του: χρησιμοποιήστε το κουμπί "Update Gateway" του Control UI ή εκτελέστε `openclaw update`, και η πύλη επανεκκινεί στη νέα έκδοση. Το Omarchy επιλέγει μόνο την έκδοση από την οποία ξεκινά μια νέα εγκατάσταση. Η κατάργηση του OpenClaw στο _Remove > AI_ παίρνει την υπηρεσία πύλης και την εφαρμογή μαζί της και στη συνέχεια ρωτά αν πρέπει να φύγει και το `~/.openclaw`, καθώς αυτό περιέχει τις συνομιλίες και τα διαπιστευτήριά σας μαζί με το ίδιο το OpenClaw και τα runtimes plugins που κατεβάζει· η προεπιλογή το διατηρεί, και η εγκατάσταση του OpenClaw ξανά το ξαναβρίσκει.

Το Herdr Desktop είναι η εφαρμογή desktop [Herdr](https://herdr.dev): χώροι, καρτέλες και πλαίσια τερματικών και agents προγραμματισμού που συνεχίζουν να εκτελούνται στον πυρήνα του όταν κλείνετε το παράθυρο. Προέρχεται από το δικό του πρόγραμμα εγκατάστασης του Herdr αντί για πακέτο, οπότε βρίσκεται στο `~/.local/share/herdr-app`, φέρνει τον πυρήνα του στο `~/.local/bin/herdr-core` όταν δεν έχετε ήδη έναν, και ενημερώνει και τα δύο μόνο του. Βρίσκεται δίπλα στην εντολή `herdr` που παρέχει το Omarchy στο `Super + Ctrl + Return` αντί να την αντικαθιστά, και λαμβάνει τα άμεσα πλήκτρα αυτής της εντολής: τα `Alt + Return` και `Alt + Shift + Return` διαιρούν ένα πλαίσιο κάτω ή δεξιά, το `Alt + Escape` το κλείνει, το `Ctrl + Alt + Arrow` μετακινεί ανάμεσα σε πλαίσια, τα `Alt + 1..9` και `Alt + Left/Right` επιλέγουν μια καρτέλα, και τα `Alt + Up/Down` μετακινούν ανάμεσα σε χώρους. Το `Ctrl + 1..9` επιλέγει έναν χώρο και το `Alt + Shift + Up/Down` μετακινείται ανάμεσα σε agents. Τα πλήκτρα προθέματος `Ctrl + Space` παραμένουν μόνο για τερματικό, καθώς η εφαρμογή δεν μπορεί να κρατήσει ένα απλό πλήκτρο Ctrl για μια ακολουθία. Το Omarchy τα γράφει στο `~/.config/herdr-app/keys.json`, και το `omarchy-refresh-herdr-app` τα επαναφέρει. Η εγκατάστασή του επιλέγει το θέμα Omarchy του Herdr, το οποίο ακολουθεί από τότε το θέμα Omarchy σας. Το Herdr διατηρεί ένα θέμα για τη φωτεινή λειτουργία και ένα για τη σκοτεινή, οπότε αφού αλλάξετε ανάμεσα σε ένα σκοτεινό και ένα φωτεινό θέμα Omarchy, επιλέξτε Omarchy στον επιλογέα θεμάτων του Herdr μία ακόμη φορά για την άλλη λειτουργία.

Το T3 Code εκτελείται από την επίσημη έκδοση AppImage του στο `~/.local/share/t3code` αντί από πακέτο, οπότε ενημερώνεται μόνο του. Η εγκατάστασή του ρωτά αν θα ξεκινήσει στο κανάλι Stable ή Nightly· αλλάξτε αργότερα στις ρυθμίσεις του T3 Code. Τα νήματα και οι ρυθμίσεις σας βρίσκονται στο `~/.t3`, και η κατάργηση του T3 Code στο _Remove > AI_ τα παίρνει μαζί του.

### Τοπικά μοντέλα

Εκτελέστε ένα ανοιχτό μοντέλο στο δικό σας μηχάνημα για τους agents προγραμματισμού σας. Οι προτροπές και ο κώδικάς σας παραμένουν στο μηχάνημα· τίποτα που στέλνεται στο μοντέλο δεν φεύγει από αυτό. Ξεκινήστε με:

```bash
omarchy agent local use best
```

Ή, στο πάνελ agents στην επάνω γραμμή, επιλέξτε + και στη συνέχεια Local AI, το οποίο εμφανίζεται όταν ένα μοντέλο ταιριάζει σε αυτό το μηχάνημα. Την πρώτη φορά, αυτό εγκαθιστά το Podman, το οποίο εκτελεί τα μοντέλα, και σε μηχάνημα NVIDIA το container toolkit της NVIDIA, το οποίο τους δίνει την GPU. Στη συνέχεια, το Omarchy επιλέγει το συνιστώμενο μοντέλο για αυτό το μηχάνημα, το κατεβάζει και το ξεκινά. Αναμένετε λήψη δεκάδων GB και το μεγαλύτερο μέρος της μνήμης του μηχανήματος να χρησιμοποιείται ενώ εκτελείται το μοντέλο: το Flash Next χρησιμοποιεί περίπου 100 GiB με το πλήρες context 256K του. Εάν άλλα μοντέλα κρατούν τη μνήμη που χρειάζεται, ρυθμίζεται σταματημένο, έτοιμο να ξεκινήσει μόλις σταματήσετε ένα. Το μοντέλο σταματά κατά την αποσύνδεση· σταματήστε το μόνοι σας όταν χρειάζεστε τη μνήμη για κάτι άλλο.

Το `omarchy agent local list` εμφανίζει τις επιλογές και εξηγεί γιατί μερικές δεν ταιριάζουν. Για να ρυθμίσετε ένα άλλο, εκτελέστε `omarchy agent local use <recipe>`. Σήμερα, τα `qwen3.8-flash-next-gufo` και `qwen3.8-27b-gufo` είναι διαθέσιμα για μηχανήματα Strix Halo 128 GB· το 27B καταλαμβάνει περίπου 40 GiB, οπότε αφήνει χώρο για άλλη εργασία. Νέες συνταγές και συστάσεις φτάνουν με το `omarchy update`, μέσω του πακέτου.

Κάθε μοντέλο που ρυθμίζετε λαμβάνει τη δική του γραμμή στο πάνελ agents, δίπλα στις συνδρομές σας: αναπαραγωγή για να το ξεκινήσετε, παύση για να το σταματήσετε και να ελευθερώσετε τη μνήμη του, και το κουμπί τερματικού για να ανοίξετε τον agent σας σε αυτό. Πολλά μπορούν να εκτελούνται ταυτόχρονα όταν χωρούν μαζί στη μνήμη· εάν ένα δεν χωρά, το Omarchy λέει ποιο εκτελούμενο μοντέλο να σταματήσετε. Σύρετε γραμμές για να τις αναδιατάξετε, και πατήστε Delete σε μια επιλεγμένη γραμμή για να καταργήσετε ένα μοντέλο και τη λήψη του.

Από τη γραμμή εντολών, τα `omarchy agent local start <recipe>` και `omarchy agent local stop <recipe>` κάνουν το ίδιο, το `omarchy agent local status` εμφανίζει κάθε μοντέλο, και το `omarchy agent --local` ανοίγει τον προεπιλεγμένο agent σας στο τελευταίο μοντέλο που ξεκινήσατε (το pi εάν ο προεπιλεγμένος agent σας δεν μπορεί να χρησιμοποιήσει τοπικό μοντέλο). Οποιοσδήποτε client συμβατός με OpenAI μπορεί επίσης να συνδεθεί: το `status` εμφανίζει τη διεύθυνση κάθε μοντέλου (η πρώτη είναι `http://127.0.0.1:11435/v1`), το όνομα της συνταγής είναι το μοντέλο, και το κλειδί βρίσκεται στο `~/.config/omarchy/agent-local/key`.

Το `omarchy agent local remove <recipe>` διαγράφει ένα μοντέλο και τις λήψεις που δεν χρησιμοποιεί κανένα άλλο μοντέλο.

Τα runtimes τρίτων επισημαίνονται με τον εκδότη τους. Το Omarchy εκτελεί κάθε μοντέλο χωρίς πρόσβαση δικτύου.

### Τοπικά LLM

Το Omarchy συνιστά δύο τρόπους εκτέλεσης τοπικών μοντέλων LLM: το LM Studio και το Ollama. Το LM Studio παρέχει ένα GUI περιβάλλον για την εύρεση μοντέλων ανοιχτών βαρών, την εγκατάστασή τους και την εκτέλεσή τους. Είναι ένας εξαιρετικός τρόπος για να ξεκινήσετε εύκολα. Το Ollama προσφέρει ένα CLI για να κάνετε το ίδιο με παρόμοιο τρόπο. Αλλά εάν είστε νέοι στα τοπικά μοντέλα, θα ξεκινούσα με το LM Studio. Μπορείτε να εγκαταστήσετε οποιοδήποτε στο _Install > AI_ στο Omarchy Menu.

### Το Omarchy Skill

Τα agent skills βοηθούν την AI να χρησιμοποιεί συγκεκριμένα εργαλεία με συγκεκριμένο τρόπο, και το Omarchy παρέχεται με ένα προεπιλεγμένο skill για την προσαρμογή του συστήματος. Όπως η τροποποίηση της διαμόρφωσης Hyprland σας, η προσαρμογή της γραμμής, ή ακόμη και η δημιουργία ενός νέου θέματος από το μηδέν. Είναι συνδεδεμένο με symlink στους καταλόγους skills για Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` και κάθε `~/.hermes/profiles/*/skills`), και τη γενική τοποθεσία `~/.agents/skills`, οπότε τα περισσότερα harnesses το ανακαλύπτουν αυτόματα.

Αλλά πρέπει να αντιμετωπίζετε αυτό το skill ως πειραματικό. Διαφορετικά μοντέλα θα το χρησιμοποιούν με διαφορετικό αποτέλεσμα. Είναι καλύτερο να εκτελείται πρώτα σε λειτουργία σχεδιασμού, ώστε να έχετε μια ιδέα για το τι θα ήθελε να αλλάξει ο agent. Και στη συνέχεια να είστε έτοιμοι να επαναφέρετε αλλαγές ή ακόμη και να επικαλεστείτε το `omarchy reinstall configs`, εάν ο agent τα κάνει όλα χάλια.
