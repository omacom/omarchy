# AI

Το Omarchy περιλαμβάνει προγράμματα εκκίνησης για τους παρακάτω agents προγραμματισμού, χωρίς να επιλέγει κάποιον ως προεπιλεγμένο για εσάς. Εκτελέστε μια εντολή για να εγκαταστήσετε το CLI του κατά την πρώτη χρήση και στη συνέχεια κάντε έλεγχο ταυτότητας όταν σας ζητηθεί. Το Hermes και το OpenClaw αποτελούν τις εξαιρέσεις: τίποτα δεν εγκαθίσταται για αυτά μέσω mise και η επιλογή οποιουδήποτε από τα δύο εγκαθιστά το δικό του αντίγραφο που ενημερώνεται μόνο του, όπως εξηγεί παρακάτω η ενότητα _Desktop apps_.

### Εγκατάσταση και ενημέρωση agents

Με εξαίρεση το Hermes και το OpenClaw, αυτοί οι agents χρησιμοποιούν την lazy εγκατάσταση του mise: η πρώτη εκκίνηση εγκαθιστά το CLI και οι επόμενες εκκινήσεις το επαναχρησιμοποιούν. Το mise ελέγχει επίσης έναν εγκατεστημένο agent για νέα έκδοση το πολύ μία φορά κάθε τέσσερις ώρες, λίγο πριν ξεκινήσει ή στο παρασκήνιο σε ένα prompt του shell. Εάν αυτή η ενημέρωση αποτύχει ή είστε εκτός σύνδεσης, εκτελείται η εγκατεστημένη έκδοση. Το `omarchy update` ενημερώνει τους εγκατεστημένους agents μαζί με το υπόλοιπο Omarchy και το `mup` ενημερώνει μόνο τα εργαλεία που διαχειρίζεται το mise.

Το δικό του πρόγραμμα ενημέρωσης ενός agent, όπως το `claude update`, το `codex update` ή ένα κουμπί ενημέρωσης σε μια εφαρμογή, δεν ενημερώνει την εγκατάσταση που διαχειρίζεται το mise. Το `codex update` αποτυγχάνει και το `claude update` μπορεί να αναφέρει επιτυχία ενώ εγκαθιστά ένα ξεχωριστό αντίγραφο που το mise δεν παρακολουθεί. Εάν προτιμάτε να χρησιμοποιείτε το εγγενές πρόγραμμα εγκατάστασης και ενημέρωσης ενός agent, προσθέστε το στο `disable_tools`· δείτε τα [Προεγκατεστημένα εργαλεία CLI](18-development-tools.md#preinstalled-cli-tools).

Για να εγκαταστήσετε όλα τα ρυθμισμένα lazy εργαλεία πριν τα χρειαστείτε, εκτελέστε το `mise install --include-lazy`. Αυτό περιλαμβάνει και τα άλλα προεπιλεγμένα εργαλεία CLI του Omarchy καθώς και τους agents. Δείτε τα [Προεγκατεστημένα εργαλεία CLI](18-development-tools.md#preinstalled-cli-tools) για την εγκατάσταση ενός μεμονωμένου εργαλείου ή τη χρήση της δικής σας εγκατάστασης.

Το `grok` εγκαθίσταται μέσω του first-party πακέτου `grok` του mise, με τον ίδιο τρόπο όπως τα `claude` και `codex`. Εκτελέστε το `grok` ή βάλτε του αστέρι στο πάνελ agents. Παραλείψτε το πρόγραμμα εγκατάστασης `curl | bash` στο x.ai. Αυτή η διαδρομή τοποθετεί ένα δεύτερο αντίγραφο στο `~/.grok/bin`, το προτάσσει στο `PATH` και αντικαθιστά το wrapper του Omarchy.

Το `dsh` ανοίγει το UI του προγράμματος περιήγησής του στο `127.0.0.1:3080`, με τον κατάλογο εκκίνησης ως προεπιλεγμένο workspace του. Το UI του προγράμματος περιήγησής του δεν δέχεται αρχικό prompt, επομένως το `omarchy agent prompt` το ανοίγει με το prompt στο πρόχειρό σας για επικόλληση. Το Omarchy το ξεκινά με το preset δικαιωμάτων χωρίς έγκριση της DeepSeek. Το DeepSeek Harness ανεβάζει αρχεία καταγραφής συνεδριών στην DeepSeek όταν χρησιμοποιείτε το επίσημο API μοντέλων της· απενεργοποιήστε το στην ενότητα _Settings > General > Upload Session Log_ στο UI του προγράμματος περιήγησής του. Τα σχόλια που του στέλνετε ανεβαίνουν επίσης μαζί με τη συνεδρία, εκτός εάν το ξεκινήσετε με `DSH_TELEMETRY_MODE=DISABLED`.

### Ο προεπιλεγμένος agent

Επιλέξτε τον προεπιλεγμένο agent σας με το αστέρι δίπλα σε έναν agent στο πάνελ agents, το οποίο είναι γεμάτο στον προεπιλεγμένο, ή με το `omarchy default agent <name>`, το οποίο δέχεται επίσης οποιοδήποτε harness χωρίς γραμμή εκεί. Εάν ο agent δεν έχει εγκατασταθεί ακόμα, η επιλογή του τον εγκαθιστά πρώτα και επίσης αποκτά το δικό του πρόγραμμα εκκίνησης στο πρόγραμμα εκκίνησης εφαρμογών, δίπλα στο Agent. Ένα φρέσκο Omarchy σας προσκαλεί να ορίσετε έναν με μια ειδοποίηση μίας φοράς, η οποία ανοίγει το πάνελ agents.

Η επιλογή του Claude επιχειρεί επίσης να ρυθμίσει την επέκταση του προγράμματος περιήγησής του για Chromium, Chrome, Brave, Brave Origin και Edge. Η ρύθμιση της επέκτασης ισχύει για όλους τους χρήστες και ενδέχεται να ζητήσει τον κωδικό πρόσβασης του συστήματός σας· η ακύρωση ή μια αποτυχημένη εγκατάσταση επέκτασης εξακολουθεί να επιλέγει και να εκκινεί το Claude. Επανεκκινήστε το πρόγραμμα περιήγησής σας, ενεργοποιήστε την επέκταση εάν σας ζητηθεί και συνδεθείτε στο Claude για να ολοκληρώσετε τη σύνδεσή της. Εκτελέστε το `/chrome` στο Claude για να ελέγξετε τη σύνδεση. Το Firefox και το Zen δεν υποστηρίζουν αυτή την επέκταση. Εάν το Claude ήταν ήδη ο προεπιλεγμένος σας agent πριν προστεθεί αυτή η ρύθμιση, επιλέξτε το ξανά για να εγκαταστήσετε την επέκταση.

Μόλις επιλέξετε, το `Super + Shift + Ctrl + A` εκκινεί τον προεπιλεγμένο agent σε ένα αποκλειστικό παράθυρο τερματικού (ή εμφανίζει τον επιλογέα εάν δεν έχετε επιλέξει ακόμα). Μπορείτε επίσης να το εκκινήσετε κατευθείαν σε μια εργασία με το `omarchy agent prompt "Review this project"`. Το Freebuff και το DeepSeek Harness δεν δέχονται αρχικό prompt, επομένως ανοίγουν αντί αυτού με το prompt στο πρόχειρό σας για επικόλληση. Οι agents που εκκινούνται με αυτόν τον τρόπο εκτελούνται χωρίς επίβλεψη στις αντίστοιχες λειτουργίες τους που δεν σταματούν για να ρωτήσουν, οπότε να είστε έτοιμοι να κάνουν πράγματι πράγματα! Το MiniMax Code δεν διαθέτει τέτοια λειτουργία για τις διαδραστικές συνεδρίες του, επομένως ζητά δικαιώματα ως συνήθως. Και επειδή οι agents αρνούνται να θυμούνται την εμπιστοσύνη για τον αρχικό κατάλογό σας, οι εκκινήσεις από το `$HOME` ξεκινούν αντί αυτού στο `~/Work`.

Υπάρχουν και συντομεύσεις τερματικού: το `a` εκτελεί τον προεπιλεγμένο agent ενσωματωμένα στο τρέχον τερματικό, ενώ τα `c`, `cx` και `cy` ξεκινούν απευθείας τα OpenCode, Claude Code και Codex (και πάλι στις λειτουργίες αυτόματης έγκρισής τους). Οι αλλαγές θέματος συγχρονίζονται επίσης στους agents: τα Claude Code, Pi, OpenCode και Hermes (μόλις το Omarchy το έχει εγκαταστήσει) ακολουθούν όλα όταν αλλάζετε το θέμα του Omarchy.

### Οι οδηγίες για τον agent σας

Οι προσωπικοί κανόνες για κάθε agent βρίσκονται στο `~/.agents/AGENTS.md`, δίπλα στα κοινόχρηστα skills στο `~/.agents/skills`. Ανοίξτε το με το εικονίδιο εγγράφου δίπλα στο + στο πάνελ agents ή με το `omarchy agent instructions --edit`, το οποίο το συνδέει επίσης σε κάθε harness που διατηρεί το δικό του καθολικό αρχείο: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, το `~/.copilot/copilot-instructions.md` του Copilot και ούτω καθεξής. Τα Crush και Amp διαβάζουν τον σύνδεσμο `~/.config/AGENTS.md`, ενώ τα omp, Kimi και DeepSeek Harness διαβάζουν απευθείας το `~/.agents/AGENTS.md`. Η επιλογή ενός προεπιλεγμένου agent το συνδέει επίσης. Ένα αρχείο οδηγιών που είχατε ήδη γίνεται το κοινόχρηστο εάν δεν υπήρχε ακόμα κανένα· διαφορετικά διατηρείται δίπλα στον σύνδεσμο ως `.bak`. Εκτελέστε το `omarchy agent instructions` για να επανασυνδέσετε μετά την εγκατάσταση άλλου agent.

### Το πάνελ agents

Η επάνω γραμμή έχει ένα εικονίδιο agents. Πριν ρυθμίσετε έναν agent, το πάνελ του προσφέρει τρεις τρόπους για να ξεκινήσετε: συνδεθείτε σε μια συνδρομή Claude, Codex, Grok, Gemini, Muse, Cursor ή Copilot ή, στην ενότητα More, σε ένα πρόγραμμα προγραμματισμού OpenCode Go, MiniMax, Synthetic ή Z.ai· πληρώστε ανάλογα με τη χρήση με Fireworks, OpenCode Zen and Go, OpenRouter ή, στην ενότητα More, DeepSeek ή οποιονδήποτε άλλο πάροχο στον οποίο συνδέεται το OpenCode, όλα εκτελούνται στο OpenCode· ή εκτελέστε το καλύτερο μοντέλο για τον υπολογιστή σας, όταν κάποιο του ταιριάζει. Το πρώτο που ολοκληρώνετε γίνεται ο προεπιλεγμένος agent σας και το + στο πάνελ προσφέρει τα ίδια τρία αργότερα. Μετά από αυτό, το πάνελ τοποθετεί κάθε συνδρομή σε μία σελίδα: κάθε agent και λογαριασμό με το πρόγραμμά του, έναν μετρητή για καθένα από τα όρια συνεδρίας 5 ωρών και τα εβδομαδιαία όριά του με τον χρόνο μέχρι να επαναφερθεί (τοποθετήστε τον δείκτη για το ακριβές ποσοστό) ή το υπόλοιπο προπληρωμένο υπόλοιπο, κάτω από μια γραμμή που εναλλάσσεται σε ό,τι έχετε χρησιμοποιήσει σε όλα αυτά, όπως tokens αυτή την εβδομάδα και το μοντέλο που χρησιμοποιείτε περισσότερο. Στην ενότητα _Make something cool_ προσφέρει αρχικά prompts για ένα νέο θέμα, plugin, εφαρμογή ή παιχνίδι που παραδίδουν την εργασία στον προεπιλεγμένο agent σας. Οι εφαρμογές κατασκευάζονται με τον τρόπο που κατασκευάζονται τα δικά του Hype, Monologue και Omacut του Omarchy, σε C++ και Qt Quick, ακολουθώντας το agent skill omarchy-make-app, και ο compiler και τα κομμάτια Qt που χρειάζονται έρχονται εγκατεστημένα. Τα παιχνίδια είναι μία σελίδα three.js στο `~/Games/vibes`, ακολουθώντας το agent skill omarchy-make-game, και όλα ανοίγουν από ένα πρόγραμμα εκκίνησης Game Vibes στο τρέχον θέμα· φορτώνουν το three.js από τον ιστό, επομένως χρειάζονται σύνδεση για να ξεκινήσουν. Τα Claude Code, Codex, Grok, Kimi, Cursor και το επίδομα Grok Bot του, GitHub Copilot, Muse, Gemini (μέσω Antigravity) και Devin καλύπτονται εξαρχής με τα όριά τους, το Kimchi με το πρόγραμμά του, τις προπληρωμένες μονάδες και τους προϋπολογισμούς δαπανών του και τα Hermes, Mistral Vibe και Qwen Code εμφανίζουν τις συνεδρίες και τα tokens τους μόλις τα χρησιμοποιήσετε. Εμφανίζονται επίσης προγράμματα και κλειδιά παρόχων που χρησιμοποιείτε μέσω pi, omp ή opencode: τα OpenCode Zen and Go, το Z.ai GLM Coding Plan, το Ollama Cloud, το MiniMax Token Plan και το Synthetic με τα όριά τους· τα OpenRouter και DeepSeek με τα προπληρωμένα υπόλοιπά τους· το Fireworks με τις δαπάνες του τις τελευταίες 30 ημέρες. Τα μοντέλα προγραμματισμού που εκτελείτε στο δικό σας υλικό αποκτούν δικές τους γραμμές και τα tokens τους προσμετρώνται επίσης στα σύνολα, όπως περιγράφεται στην ενότητα [Τοπικά μοντέλα](#local-models). Κάθε agent καταμετράται μία φορά, σε όποιον τον χρεώνει, όσα harnesses και αν χρησιμοποιήσετε για να τον οδηγήσετε.

Κάντε αριστερό κλικ στο εικονίδιο της γραμμής ή πατήστε `Super + Ctrl + X` για το πάνελ, δεξί κλικ για να εκκινήσετε τον προεπιλεγμένο agent σας και μεσαίο κλικ για ανανέωση. Τα αρχεία χρήσης πίσω από αυτό αναγεννώνται κάθε 15 λεπτά από το `omarchy agent usage update` και το πάνελ μπορεί ακόμη και να συγχωνεύσει χρήση από τα άλλα μηχανήματά σας μέσω ενός συγχρονισμένου φακέλου. Δείτε το README στο `$OMARCHY_PATH/shell/plugins/agents/` για τις πλήρεις ρυθμίσεις.

### Πολλαπλές συνδρομές

Εάν πληρώνετε για περισσότερα από ένα προγράμματα Claude, Codex ή Grok — ένα προσωπικό Max και ένα επαγγελματικό, ας πούμε — το Omarchy μπορεί να τα κρατήσει όλα συνδεδεμένα και να μετακινείται μεταξύ τους. Προσθέστε μια συνδρομή με το + στο πάνελ agents, το οποίο σας καθοδηγεί ακριβώς εκεί, ή με το `omarchy agent account add claude Work` (ή `codex` ή `grok`). Το ίδιο + και η ίδια εντολή συνδέονται στο Gemini (`gemini`) και στο OpenCode (`opencode`) και αποθηκεύουν ένα κλειδί API Fireworks (`fireworks`) ή OpenRouter (`openrouter`) στο OpenCode· η εντολή συνδέεται επίσης στο Copilot (`copilot`), στο Cursor (`cursor`) και στο Muse (`muse`). Αυτά διατηρούν από μία σύνδεση το καθένα. Εγκαθιστά το CLI εάν λείπει. Ο πρώτος λογαριασμός για έναν πάροχο συνδέεται μέσω του κανονικού προγράμματος περιήγησής σας, ακριβώς εκεί όπου το CLI κοιτάζει πάντα. Κάθε επόμενος συνδέεται μέσω ενός ιδιωτικού παραθύρου, ώστε ο λογαριασμός στον οποίο το πρόγραμμα περιήγησής σας είναι ήδη συνδεδεμένο να μην παραληφθεί κατά λάθος· συνδεθείτε εκεί ως ο λογαριασμός που προσθέτετε και κλείστε πρώτα οποιοδήποτε ιδιωτικό παράθυρο είχατε ήδη ανοιχτό. Μην αποσυνδέεστε ποτέ από το CLI για να το κάνετε αυτό: η αποσύνδεση ανακαλεί την αποθηκευμένη σύνδεση και αυτός ο λογαριασμός θα έπρεπε να προστεθεί ξανά.

Για να αντιγράψετε τις συνδέσεις της συνδρομής σας σε άλλο μηχάνημα Omarchy μέσω SSH, εκτελέστε το `omarchy agent account copy user@laptop`. Ο αποστολέας παρέχει έναν προσωρινό παραλήπτη όταν ο προορισμός δεν έχει εγκατεστημένο έναν, επομένως παλαιότερα μηχανήματα Omarchy μπορούν να λάβουν λογαριασμούς χωρίς ενημέρωση. Οι εγκατεστημένοι παραλήπτες έχουν προτεραιότητα. Αυτό αντιγράφει όλες τις συνδρομές Claude, Codex και Grok· προσθέστε ονόματα παρόχων για να τις επιλέξετε, όπως στο `omarchy agent account copy laptop claude`. Τα ονόματα λογαριασμών και τα αναγνωριστικά εντολών ταιριάζουν με την πηγή, συμπεριλαμβανομένων λογαριασμών που υπάρχουν ήδη στον προορισμό. Άσχετοι λογαριασμοί προορισμού λαμβάνουν ένα αριθμητικό επίθημα εάν τα ονόματά τους συγκρούονται και οι ρυθμίσεις, τα skills, τα plugins και το ιστορικό συνομιλιών παραμένουν τοπικά σε κάθε μηχάνημα.

Τα υπάρχοντα διαπιστευτήρια προορισμού διατηρούνται. Ένας λογαριασμός πηγής που είναι ήδη συνδεδεμένος εκεί έχει το όνομά του συγχρονισμένο χωρίς να αντικατασταθούν τα διαπιστευτήριά του· άλλοι λογαριασμοί προστίθενται δίπλα του. Για να αντικαταστήσετε τα αποθηκευμένα διαπιστευτήρια για αντίστοιχους λογαριασμούς, χρησιμοποιήστε το `omarchy agent account copy --replace laptop claude` αφού κλείσετε τις συνεδρίες αυτού του λογαριασμού στον προορισμό. Ένας νέος προορισμός λαμβάνει επίσης τον ενεργό λογαριασμό και τις προτιμήσεις εναλλαγής της πηγής· ένας καθιερωμένος προορισμός διατηρεί τις δικές του.

Τα διαπιστευτήρια ταξιδεύουν μέσω SSH και αποθηκεύονται σε ιδιωτικά αρχεία στον προορισμό, επομένως αντιγράψτε μόνο σε μηχανήματα που εμπιστεύεστε. Αυτή είναι μια αντιγραφή μίας φοράς, όχι συνεχής συγχρονισμός. Τα tokens ανανέωσης του Codex μπορούν να εναλλαχθούν από άλλο μηχάνημα, αφήνοντας μια αντιγραμμένη σύνδεση να χρειάζεται ανανέωση· ξεχωριστές συνδέσεις παραμένουν η πιο αξιόπιστη επιλογή για ταυτόχρονη χρήση σε πολλά μηχανήματα. Δείτε τις [οδηγίες ελέγχου ταυτότητας λογαριασμού του Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Ένας λογαριασμός ανά πάροχο είναι ενεργός και κάθε νέα συνεδρία ξεκινά ως αυτός: `cx`, `cy`, ένα απλό `claude`, `codex` ή `grok`, οτιδήποτε εκκινείται μέσω του `omarchy agent` και scripts ή επεξεργαστές που βρίσκουν το CLI στο `PATH`. Κάντε εναλλαγή με το `omarchy agent account use work` (και πίσω με το `omarchy agent account use main`) ή στο πάνελ πατώντας τον αριθμό ενός λογαριασμού και στη συνέχεια `Enter` (ή κάνοντας κλικ στο αστέρι του). Οι συνεδρίες Claude που εκτελούνται κάνουν επίσης εναλλαγή, από το επόμενο μήνυμά τους: κάθε συνεδρία Claude εκτελείται στο `~/.claude`, το οποίο περιέχει πάντα τη σύνδεση του ενεργού λογαριασμού. Μια συνεδρία Claude που ξεκίνησε στον δικό της φάκελο ενός λογαριασμού από ένα παλαιότερο Omarchy διατηρεί αυτή τη σύνδεση μέχρι να κλείσει, επομένως η εναλλαγή ονομάζει αυτές τις συνεδρίες και ολοκληρώνεται από μόνη της μόλις εξαφανιστούν. Οι συνεδρίες Codex και Grok που εκτελούνται παραμένουν στον λογαριασμό με τον οποίο ξεκίνησαν. Το ιστορικό συνομιλιών, οι ρυθμίσεις, τα skills και τα plugins είναι κοινόχρηστα μεταξύ λογαριασμών, επομένως το `claude --continue` στον ίδιο φάκελο συνεχίζει από εκεί που σταματήσατε στον νέο λογαριασμό.

Με περισσότερους από έναν λογαριασμούς, το πάνελ εμφανίζει τα όρια κάθε λογαριασμού δίπλα-δίπλα, με ένα γεμάτο αστέρι σε αυτόν που χρησιμοποιείται. Το Omarchy σας ειδοποιεί όταν ο ενεργός λογαριασμός ξεπεράσει το 95% ενός ορίου και κάνοντας κλικ στην ειδοποίηση γίνεται εναλλαγή στον λογαριασμό με το μεγαλύτερο περιθώριο. Δεν κάνει ποτέ εναλλαγή από μόνο του. Αλλάξτε το όριο με το `omarchy agent account threshold 90`. Εάν κάθε λογαριασμός είναι πάνω από το όριο, θα ενημερωθείτε μία φορά, μαζί με το ποιος λογαριασμός ελευθερώνεται πρώτος. Ενώ ένας ενεργός λογαριασμός βρίσκεται εντός 15 μονάδων από το όριό του (80% στην προεπιλογή), τα όριά του ελέγχονται κάθε τρία λεπτά και όχι κάθε 15.

Το `omarchy agent account list` εμφανίζει κάθε λογαριασμό και τα τελευταία όριά του, το `omarchy agent account remove work` ξεχνά έναν και το `omarchy agent account rename primary Hey` μετονομάζει έναν (ή κάντε κλικ στο όνομα ενός λογαριασμού στο πάνελ). Αυτές οι εντολές λειτουργούν στους λογαριασμούς του προεπιλεγμένου agent σας· για να φτάσετε στον άλλο πάροχο, ονομάστε τον πρώτα, όπως στο `omarchy agent account use codex side`. Η σύνδεση που είχατε ήδη στο `~/.claude` ή στο `~/.codex` είναι ο λογαριασμός _Main_. Του Codex παραμένει εκεί που είναι· του Claude περιμένει σε δικό του φάκελο ενώ ένας άλλος λογαριασμός είναι ενεργός. Ένας λογαριασμός που μένει αχρησιμοποίητος για περισσότερες από περίπου οκτώ ώρες μπορεί να εμφανίσει _Sign-in required_· κάντε κλικ σε αυτόν για να συνδεθείτε ξανά σε αυτόν τον λογαριασμό ακριβώς στο πάνελ ή μεταβείτε σε αυτόν και ξεκινήστε μια συνεδρία, η οποία ανανεώνει τη σύνδεση από μόνη της. Οι διακομιστές MCP που προσθέτετε με το `claude mcp add` φτάνουν σε κάθε λογαριασμό Claude, αφού όλοι εκτελούνται στο `~/.claude`· για τα Codex και Grok, οι διακομιστές που είχατε όταν προστέθηκε ένας λογαριασμός έρχονται μαζί του σε αυτόν, αλλά οι μεταγενέστεροι φτάνουν μόνο στον λογαριασμό στον οποίο τους προσθέσατε. Το Claude Desktop διατηρεί δική του σύνδεση και τα εργαλεία Codex ή Grok που έχουν ρυθμιστεί με απόλυτη διαδρομή προς ένα δυαδικό αρχείο CLI δεν ακολουθούν την εναλλαγή. Ένα ρητό `CLAUDE_CONFIG_DIR`, `CODEX_HOME` ή `GROK_HOME` υπερισχύει του επιλεγμένου λογαριασμού.

### Διάγνωση καταρρεύσεων

Το Omarchy παρακολουθεί το systemd-coredump για καταρρεύσεις διεργασιών. Μόλις επιλέξετε έναν προεπιλεγμένο agent, οποιοδήποτε δικό σας πρόγραμμα καταρρεύσει φέρνει μια ειδοποίηση "Process crashed" — κάντε κλικ σε αυτήν και η κατάρρευση παραδίδεται στον προεπιλεγμένο agent σας μαζί με το skill omarchy-diagnose-crash του Omarchy, το οποίο καθοδηγεί τον agent στη διαπίστωση των γεγονότων από το core dump και στην απόφαση για το εάν η κατάρρευση αξίζει να αναφερθεί upstream. Μπορείτε επίσης να το εκτελέσετε χειροκίνητα απέναντι σε οποιοδήποτε PID από το `coredumpctl list` με το `omarchy agent crash <pid>`.

Η παρακολούθηση είναι ενεργοποιημένη από προεπιλογή. Απενεργοποιήστε την στην ενότητα _Trigger > Toggle > Crash Capture Off_ (ή με το `omarchy toggle crash-capture`) και οι ειδοποιήσεις σταματούν· το `omarchy agent crash <pid>` εξακολουθεί να λειτουργεί χειροκίνητα.

Οι καταρρεύσεις μπορούν επίσης να σιγαστούν ένα πρόγραμμα κάθε φορά, πράγμα που σας προσφέρει η διάγνωση στο τέλος. Το `omarchy crash mute hyprland` σταματά τις ειδοποιήσεις μόνο για αυτό το πρόγραμμα, το `omarchy crash mute hyprland off` τις επαναφέρει και το `omarchy crash mute` από μόνο του παραθέτει αυτά που έχετε σιγάσει. Δέχεται τη διαδρομή του δυαδικού αρχείου τόσο ευχαρίστως όσο και το όνομά του, επομένως το `omarchy crash mute /usr/bin/hyprland` κάνει το ίδιο πράγμα. Βάλτε σε εισαγωγικά ένα όνομα με κενό σε αυτό, όπως στο `omarchy crash mute 'Some App'`. Όλα τα υπόλοιπα εξακολουθούν να ειδοποιούν και το σιγασμένο πρόγραμμα εξακολουθεί να καταρρέει — αυτό κρύβει την υπενθύμιση, δεν διορθώνει τίποτα.

### Εφαρμογές desktop

Το μενού _Install > AI_ περιλαμβάνει επίσης μερικές γραφικές εφαρμογές AI: Amp Desktop, Antigravity Desktop, την εφαρμογή desktop ChatGPT, την εφαρμογή desktop Claude (τη beta για Linux της Anthropic, με καρτέλες Chat, Cowork και Claude Code), Grok Bot για συνομιλία με τα μοντέλα της xAI, Herdr Desktop, Hermes Desktop, OpenClaw, την εφαρμογή desktop Perplexity και T3 Code. Το Grok Bot είναι η εφαρμογή συνομιλίας desktop. Ο agent προγραμματισμού είναι η εντολή `grok`.

Το Hermes Desktop είναι αυτό που πρέπει να γνωρίζετε, επειδή ένα μηχάνημα έχει ένα Hermes και είναι αυτό της εφαρμογής: το Hermes εγκαθίσταται πάντα μόνο μέσω της εφαρμογής και η εντολή `hermes` που εκτελεί ο προεπιλεγμένος agent είναι αυτή της εφαρμογής. Η επιλογή του Hermes ως προεπιλεγμένου agent εγκαθιστά το ίδιο πράγμα που κάνει η καταχώριση _Install > AI_: το πακέτο και ένα runtime Hermes στο `~/.hermes` που ρυθμίζεται από το δικό του πρόγραμμα εγκατάστασης του Hermes, το οποίο χρειάζεται μερικά λεπτά την πρώτη φορά. Αυτό το runtime είναι το ένα Hermes που χρησιμοποιούν η εντολή τερματικού `hermes`, ο προεπιλεγμένος agent και η εφαρμογή και ενημερώνεται μόνο του με το `hermes update` αντί να περιμένει μια έκδοση του Omarchy. Η εγκατάστασή του παραδίδει επίσης στο Hermes το θέμα του Omarchy ως ένα skin με όνομα `omarchy`, το οποίο ακολουθεί κάθε επιφάνεια Hermes καθώς αλλάζετε θέματα· επιλέξτε άλλο στις ρυθμίσεις Appearance του Hermes ή με το `/skin` εάν προτιμάτε να μην το κάνει και το Omarchy αφήνει αυτή την επιλογή ήσυχη. Η αφαίρεση της εφαρμογής στην ενότητα _Remove > AI_ κλείνει πρώτα το Hermes, συμπεριλαμβανομένης της gateway, παίρνει αυτό το runtime μαζί της και διατηρεί τις συνομιλίες, τις μνήμες και τα skills που έγραψε το Hermes για τον εαυτό του, εκτός εάν του πείτε διαφορετικά: ρωτά, με προεπιλογή το όχι, εάν αυτά τα δεδομένα και οι ρυθμίσεις σύνδεσής σας πρέπει να φύγουν επίσης.

Η εμπειρία desktop του OpenClaw είναι το Control UI του, το οποίο ανοίγει ως μια εφαρμογή ιστού που υποστηρίζεται από τη δική του τοπική gateway. Το OpenClaw βρίσκεται στο `~/.openclaw` και ενημερώνεται μόνο του: χρησιμοποιήστε το κουμπί "Update Gateway" του Control UI ή εκτελέστε το `openclaw update` και η gateway επανεκκινείται στη νέα έκδοση. Το Omarchy επιλέγει μόνο την έκδοση από την οποία ξεκινά μια φρέσκια εγκατάσταση. Το OpenClaw μπορεί επίσης να είναι ο προεπιλεγμένος agent σας: η επιλογή του με το `omarchy default agent openclaw` ρυθμίζει αυτό το ίδιο αντίγραφο στο `~/.openclaw` και ο agent ανοίγει το UI τερματικού του OpenClaw συνδεδεμένο με τη gateway του. Η αφαίρεση του OpenClaw στην ενότητα _Remove > AI_ παίρνει μαζί της την υπηρεσία gateway και την εφαρμογή και στη συνέχεια ρωτά εάν το `~/.openclaw` πρέπει να φύγει επίσης, αφού αυτό περιέχει τις συνομιλίες και τα διαπιστευτήριά σας μαζί με το ίδιο το OpenClaw και τα runtimes plugins που κατεβάζει· η προεπιλογή το διατηρεί και η εκ νέου εγκατάσταση του OpenClaw το ανακτά ξανά.

Το Herdr Desktop είναι η εφαρμογή desktop [Herdr](https://herdr.dev): χώροι, καρτέλες και παράθυρα τερματικών και agents προγραμματισμού που συνεχίζουν να εκτελούνται στον πυρήνα του όταν κλείνετε το παράθυρο. Προέρχεται από το δικό του πρόγραμμα εγκατάστασης του Herdr και όχι από ένα πακέτο, επομένως βρίσκεται στο `~/.local/share/herdr-app`, φέρνει τον πυρήνα του μαζί στο `~/.local/bin/herdr-core` όταν δεν έχετε ακόμα έναν και ενημερώνει και τα δύο μόνο του. Βρίσκεται δίπλα στην εντολή `herdr` που παρέχει το Omarchy στο `Super + Ctrl + Return` αντί να την αντικαθιστά και αποκτά τα απευθείας πλήκτρα αυτής της εντολής: τα `Alt + Return` και `Alt + Shift + Return` χωρίζουν ένα παράθυρο προς τα κάτω ή προς τα δεξιά, το `Alt + Escape` το κλείνει, το `Ctrl + Alt + Arrow` μετακινεί μεταξύ παραθύρων, τα `Alt + 1..9` και `Alt + Left/Right` επιλέγουν μια καρτέλα και το `Alt + Up/Down` μετακινεί μεταξύ χώρων. Το `Ctrl + 1..9` επιλέγει έναν χώρο και το `Alt + Shift + Up/Down` περνά από agents. Τα πλήκτρα προθέματος `Ctrl + Space` παραμένουν μόνο για τερματικό, αφού η εφαρμογή δεν μπορεί να κρατήσει ένα απλό πλήκτρο Ctrl για μια ακολουθία. Το Omarchy τα γράφει στο `~/.config/herdr-app/keys.json` και το `omarchy-refresh-herdr-app` τα επαναφέρει. Η εγκατάστασή του επιλέγει το θέμα Omarchy του Herdr, το οποίο ακολουθεί το θέμα Omarchy σας από τότε και στο εξής. Το Herdr διατηρεί ένα θέμα για τη φωτεινή λειτουργία και ένα για τη σκοτεινή, επομένως αφού μεταβείτε μεταξύ ενός σκοτεινού και ενός φωτεινού θέματος Omarchy, επιλέξτε Omarchy στον επιλογέα θεμάτων του Herdr για άλλη μία φορά για την άλλη λειτουργία.

Το T3 Code εκτελείται από την επίσημη έκδοση AppImage του στο `~/.local/share/t3code` και όχι από ένα πακέτο, επομένως ενημερώνεται μόνο του. Η εγκατάστασή του ρωτά εάν θα ξεκινήσει στο κανάλι Stable ή Nightly· αλλάξτε αργότερα στις ρυθμίσεις του T3 Code. Τα νήματα και οι ρυθμίσεις σας βρίσκονται στο `~/.t3` και η αφαίρεση του T3 Code στην ενότητα _Remove > AI_ τα παίρνει μαζί του.

### Τοπικά μοντέλα

Εκτελέστε ένα ανοιχτό μοντέλο στο δικό σας μηχάνημα για τους agents προγραμματισμού σας. Τα prompts και ο κώδικάς σας παραμένουν στο μηχάνημα· τίποτα που στέλνεται στο μοντέλο δεν φεύγει από αυτό. Ξεκινήστε με:

```bash
omarchy models use best text
```

Αυτό ρυθμίζει το καλύτερο μοντέλο κειμένου για αυτό το μηχάνημα, το είδος που χρησιμοποιούν οι agents σας. Τα μοντέλα εικόνας, βίντεο και μουσικής έχουν το δικό τους καλύτερο: `omarchy models use best image`, `video` ή `music`. Εκτελέστε το `omarchy models use best` για να δείτε την επιλογή κάθε είδους για αυτό το μηχάνημα.

Ή επιλέξτε + στο πάνελ agents: στην ενότητα _Use a local model_ παραθέτει κάθε μοντέλο προγραμματισμού που ταιριάζει σε αυτό το μηχάνημα, το συνιστώμενο πρώτο. Το Podman, το οποίο εκτελεί τα μοντέλα, έρχεται με το Omarchy, όπως και το container toolkit της NVIDIA σε ένα μηχάνημα NVIDIA, το οποίο τους δίνει τη GPU· εάν λείπει κάποιο από τα δύο, η πρώτη ρύθμιση το εγκαθιστά. Το Omarchy στη συνέχεια επιλέγει το συνιστώμενο μοντέλο για αυτό το μηχάνημα, το κατεβάζει και το ξεκινά. Αναμένετε λήψη δεκάδων GB και το μεγαλύτερο μέρος της μνήμης του μηχανήματος να χρησιμοποιείται ενώ το μοντέλο εκτελείται: το Flash Next χρησιμοποιεί περίπου 100 GiB με το πλήρες context 256K του. Εάν άλλα μοντέλα κρατούν τη μνήμη που χρειάζεται, ρυθμίζεται σταματημένο, έτοιμο να ξεκινήσει μόλις σταματήσετε ένα. Το μοντέλο σταματά κατά την αποσύνδεση· σταματήστε το μόνοι σας όταν χρειάζεστε τη μνήμη για κάτι άλλο.

Το `omarchy models list` εμφανίζει τις επιλογές και εξηγεί γιατί ορισμένες δεν ταιριάζουν. Για να ρυθμίσετε άλλο ένα, εκτελέστε το `omarchy models use <recipe>`. Σήμερα, τα `qwen3.8-flash-next-gufo` και `qwen3.8-27b-gufo` είναι διαθέσιμα για μηχανήματα Strix Halo 128 GB· το 27B χρειάζεται περίπου 40 GiB, επομένως αφήνει χώρο για άλλη εργασία. Σε ένα laptop 64 GB με Arc B390 της Intel, το `qwen3.6-35b-a3b-llamacpp` εκτελείται σε περίπου 30 GiB. Νέες συνταγές και συστάσεις φτάνουν με το `omarchy update`, μέσω του πακέτου.

Ένα μοντέλο προγραμματισμού που προσθέτετε αποκτά τη δική του γραμμή στο πάνελ agents, δίπλα στις συνδρομές σας: play για να το ξεκινήσετε, pause για να το σταματήσετε και να ελευθερώσετε τη μνήμη του, το σημάδι Tailscale για να το μοιραστείτε με τα άλλα μηχανήματα στο tailnet σας ενώ εκτελείται και το κουμπί τερματικού για να ανοίξετε τον agent σας σε αυτό. Η γραμμή του εμφανίζει τη λήψη, τη φόρτωση ή τη διακοπή καθώς προχωρά και το λέει όταν δεν υπάρχει αρκετή ελεύθερη μνήμη για να ξεκινήσει ή συνδέεται με τα αρχεία καταγραφής του όταν σταμάτησε με σφάλμα. Πολλά μπορούν να εκτελούνται ταυτόχρονα όταν χωρούν μαζί στη μνήμη. Πατήστε Delete σε μια επιλεγμένη γραμμή για να αφαιρέσετε το μοντέλο από αυτό το μηχάνημα, μαζί με τη λήψη· το + μπορεί να το ρυθμίσει ξανά. Ένα μοντέλο προγραμματισμού που ρυθμίζεται από ένα τερματικό περιμένει στο + μέχρι να το προσθέσετε και το ίδιο κάνουν τα μοντέλα που εκτελεί ένα μηχάνημα με το οποίο έχετε κάνει σύζευξη (`omarchy models pair <host>`).

Κάθε μοντέλο προγραμματισμού που ρυθμίζετε αποκτά επίσης τη δική του καταχώριση στο πρόγραμμα εκκίνησης εφαρμογών, με το όνομα του μοντέλου και το λογότυπο του κατασκευαστή του, με τον τρόπο που η σύνδεση στο Claude, στο Codex ή στο Grok προσθέτει μία. Ανοίγει τον agent σας σε αυτό το μοντέλο και ξεκινά πρώτα το μοντέλο εάν δεν εκτελείται: το τερματικό δείχνει ότι φορτώνει και παραδίδει στον agent μόλις είναι έτοιμο. Η αφαίρεση ενός μοντέλου αφαιρεί την καταχώρισή του.

Δεν είναι κάθε μοντέλο για προγραμματισμό. Τα μοντέλα εικόνας, βίντεο και μουσικής ανοίγουν αντί αυτού στο Fantasi, την εφαρμογή του Omarchy για τη δημιουργία εικόνων, βίντεο και μουσικής με ένα μοντέλο που εκτελείται σε αυτό το μηχάνημα, και διαχειρίζονται εκεί ή με το `omarchy models`.

Ένα μοντέλο συνεχίζει να εκτελείται ακριβώς όπως ρυθμίστηκε, επομένως μια ενημέρωση του Omarchy δεν επανεκκινεί ποτέ ένα κάτω από τους agents σας. Όταν το Omarchy έχει ένα νεότερο runtime ή νεότερα weights για ένα μοντέλο που έχετε ρυθμίσει, η γραμμή του εμφανίζει ένα κουμπί ενημέρωσης: πατήστε το και το μοντέλο ρυθμίζεται ξανά στο παρασκήνιο, κατεβάζοντας μόνο ό,τι άλλαξε, και επανεκκινείται στη νέα έκδοση. Ένα μοντέλο που ήταν σταματημένο παραμένει σταματημένο. Το `omarchy models update` κάνει το ίδιο για κάθε μοντέλο από ένα τερματικό.

Από τη γραμμή εντολών, τα `omarchy models start <recipe>` και `omarchy models stop <recipe>` κάνουν το ίδιο, το `omarchy models status` εμφανίζει κάθε μοντέλο και το `omarchy agent --local-model <recipe>` ανοίγει αυτό το μοντέλο στο pi, όποιος και αν είναι ο προεπιλεγμένος agent σας. Για να κάνετε το τοπικό μοντέλο σας αυτό που ανοίγουν το πλήκτρο συντόμευσης agent, η κονσόλα Quake και το _Make something_, εκτελέστε το `omarchy default agent local` ή βάλτε αστέρι σε ένα μοντέλο που εκτελείται στο πάνελ agents. Το pi παραθέτει επίσης κάθε μοντέλο που έχετε ρυθμίσει και αυτά σε μηχανήματα με τα οποία έχετε κάνει σύζευξη, στον δικό του επιλογέα μοντέλων, επομένως το απλό `pi` τα φτάνει επίσης. Οποιοσδήποτε client συμβατός με OpenAI μπορεί επίσης να συνδεθεί: το `status` εμφανίζει τη διεύθυνση κάθε μοντέλου (η πρώτη είναι `http://127.0.0.1:11435/v1`), το όνομα της συνταγής είναι το μοντέλο και το κλειδί βρίσκεται στο `~/.config/omarchy/agent-local/key`.

Το `omarchy models remove <recipe>` διαγράφει ένα μοντέλο και τις λήψεις που δεν χρησιμοποιεί κανένα άλλο μοντέλο.

Τα runtimes τρίτων επισημαίνονται με τον εκδότη τους. Το Omarchy εκτελεί κάθε μοντέλο χωρίς πρόσβαση σε δίκτυο.

### Τοπικά LLM

Το Omarchy συνιστά δύο τρόπους εκτέλεσης τοπικών μοντέλων LLM: το LM Studio και το Ollama. Το LM Studio παρέχει μια διεπαφή GUI για την εύρεση μοντέλων ανοιχτών βαρών, την εγκατάστασή τους και την εκτέλεσή τους. Είναι ένας εξαιρετικός τρόπος για να ξεκινήσετε εύκολα. Το Ollama προσφέρει ένα CLI για να κάνετε το ίδιο παρόμοια. Αλλά εάν είστε νέοι στα τοπικά μοντέλα, εγώ θα ξεκινούσα με το LM Studio. Μπορείτε να εγκαταστήσετε οποιοδήποτε από τα δύο στην ενότητα _Install > AI_ στο Μενού Omarchy.

### Τα skills του Omarchy

Τα skills agents βοηθούν την AI να χρησιμοποιεί συγκεκριμένα εργαλεία με συγκεκριμένο τρόπο και το Omarchy περιλαμβάνει επτά από αυτά. Το skill omarchy καλύπτει την προσαρμογή του συστήματος, όπως την τροποποίηση της διαμόρφωσης Hyprland σας ή την προσαρμογή της γραμμής. Τα omarchy-make-theme, omarchy-make-plugin, omarchy-make-app και omarchy-make-game καλύπτουν τη δημιουργία κάτι νέου, το omarchy-contribute καλύπτει την αναφορά ενός σφάλματος ή την αποστολή μιας διόρθωσης upstream και το omarchy-diagnose-crash εξετάζει το core dump μιας κατάρρευσης. Συνδέονται με συμβολικούς συνδέσμους στους καταλόγους skills για Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` και κάθε `~/.hermes/profiles/*/skills`) και τη γενική τοποθεσία `~/.agents/skills`, επομένως τα περισσότερα harnesses τα παραλαμβάνουν αυτόματα. Ένας δικός σας φάκελος skill με το ίδιο όνομα έχει προτεραιότητα.

Αλλά θα πρέπει να αντιμετωπίζετε αυτά τα skills ως πειραματικά. Διαφορετικά μοντέλα θα το χρησιμοποιήσουν με διαφορετικό αποτέλεσμα. Είναι καλύτερο να εκτελείτε πρώτα σε λειτουργία σχεδιασμού, ώστε να έχετε μια ιδέα για το τι θα ήθελε να αλλάξει ο agent. Και στη συνέχεια να είστε έτοιμοι να επαναφέρετε αλλαγές ή ακόμη και να καλέσετε το `omarchy reinstall configs`, εάν ο agent κάνει τα πάντα άνω κάτω.
