# AI

Το Omarchy περιλαμβάνει εκκινητές για τους παρακάτω coding agents χωρίς να επιλέγει προεπιλογή για εσάς. Εκτελέστε μια εντολή για να εγκατασταθεί το CLI της κατά την πρώτη χρήση και στη συνέχεια πραγματοποιήστε έλεγχο ταυτότητας όταν σας ζητηθεί. Οι Hermes και OpenClaw αποτελούν τις εξαιρέσεις: δεν εγκαθίσταται τίποτα για αυτούς μέσω mise, και η επιλογή οποιουδήποτε από τους δύο εγκαθιστά το δικό του αυτοενημερούμενο αντίγραφο, όπως εξηγεί παρακάτω η ενότητα _Εφαρμογές desktop_.

### Εγκατάσταση και ενημέρωση agents

Με εξαίρεση τους Hermes και OpenClaw, αυτοί οι agents χρησιμοποιούν την lazy εγκατάσταση του mise: η πρώτη εκκίνηση εγκαθιστά το CLI και οι επόμενες εκκινήσεις το επαναχρησιμοποιούν. Το mise ελέγχει επίσης έναν εγκατεστημένο agent για νέα έκδοση το πολύ μία φορά κάθε τέσσερις ώρες, ακριβώς πριν ξεκινήσει ή στο παρασκήνιο σε ένα shell prompt. Εάν αυτή η ενημέρωση αποτύχει ή είστε εκτός σύνδεσης, εκτελείται η εγκατεστημένη έκδοση. Το `omarchy update` ενημερώνει τους εγκατεστημένους agents μαζί με το υπόλοιπο Omarchy, και το `mup` ενημερώνει μόνο τα εργαλεία που διαχειρίζεται το mise.

Ο δικός του updater ενός agent, όπως το `claude update`, το `codex update` ή ένα κουμπί ενημέρωσης σε μια εφαρμογή, δεν ενημερώνει την εγκατάσταση που διαχειρίζεται το mise. Το `codex update` αποτυγχάνει, και το `claude update` μπορεί να αναφέρει επιτυχία ενώ εγκαθιστά ένα ξεχωριστό αντίγραφο που το mise δεν παρακολουθεί. Εάν προτιμάτε να χρησιμοποιείτε τον εγγενή installer και updater ενός agent, προσθέστε τον στο `disable_tools`· δείτε το [Προεγκατεστημένα εργαλεία CLI](18-development-tools.md#preinstalled-cli-tools).

Για να εγκαταστήσετε όλα τα διαμορφωμένα lazy εργαλεία πριν τα χρειαστείτε, εκτελέστε το `mise install --include-lazy`. Αυτό περιλαμβάνει και τα άλλα προεπιλεγμένα εργαλεία CLI του Omarchy καθώς και τους agents. Δείτε το [Προεγκατεστημένα εργαλεία CLI](18-development-tools.md#preinstalled-cli-tools) για την εγκατάσταση ενός μεμονωμένου εργαλείου ή τη χρήση της δικής σας εγκατάστασης.

Το `grok` εγκαθίσταται μέσω του first-party πακέτου `grok` του mise, με τον ίδιο τρόπο όπως τα `claude` και `codex`. Εκτελέστε το `grok`, ή επιλέξτε το στο _Agent > Harness_. Παραλείψτε τον installer `curl | bash` στο x.ai. Αυτή η διαδρομή τοποθετεί ένα δεύτερο αντίγραφο στο `~/.grok/bin`, το προτάσσει στο `PATH`, και αντικαθιστά το wrapper του Omarchy.

Το `dsh` ανοίγει το browser UI του στο `127.0.0.1:3080`, με τον κατάλογο εκκίνησης ως προεπιλεγμένο workspace του. Το browser UI του δεν δέχεται αρχικό prompt, οπότε το `omarchy agent prompt` το ανοίγει με το prompt στο clipboard σας για επικόλληση. Το Omarchy το ξεκινά με το preset δικαιωμάτων no-approval της DeepSeek. Το DeepSeek Harness ανεβάζει τα session logs στην DeepSeek όταν χρησιμοποιείτε το επίσημο model API της· απενεργοποιήστε το στο _Settings > General > Upload Session Log_ στο browser UI του. Τα σχόλια που του στέλνετε ανεβαίνουν επίσης μαζί με το session, εκτός εάν το ξεκινήσετε με `DSH_TELEMETRY_MODE=DISABLED`.

### Ο προεπιλεγμένος agent

Επιλέξτε τον προεπιλεγμένο agent σας με το `omarchy default agent <name>` ή στο _Agent > Harness_ στο Omarchy Menu (`Super + Space`). Εάν ο agent δεν έχει εγκατασταθεί ακόμα, η επιλογή του τον εγκαθιστά πρώτα, και αποκτά επίσης τον δικό του εκκινητή στον app launcher, δίπλα στο Agent. Ένα φρέσκο Omarchy θα σας καλέσει να κάνετε αυτή την επιλογή με μια εφάπαξ ειδοποίηση.

Η επιλογή του Claude επιχειρεί επίσης να εγκαταστήσει την επέκταση browser του για Chromium, Chrome, Brave, Brave Origin και Edge. Η εγκατάσταση της επέκτασης ισχύει για όλους τους χρήστες και μπορεί να ζητήσει τον κωδικό πρόσβασης του συστήματός σας· η ακύρωση ή μια αποτυχημένη εγκατάσταση επέκτασης εξακολουθεί να επιλέγει και να εκκινεί τον Claude. Επανεκκινήστε τον browser σας, ενεργοποιήστε την επέκταση εάν σας ζητηθεί, και συνδεθείτε στον Claude για να ολοκληρώσετε τη σύνδεσή της. Εκτελέστε το `/chrome` στον Claude για να ελέγξετε τη σύνδεση. Τα Firefox και Zen δεν υποστηρίζουν αυτή την επέκταση. Εάν ο Claude ήταν ήδη ο προεπιλεγμένος σας πριν προστεθεί αυτή η εγκατάσταση, επιλέξτε τον ξανά για να εγκαταστήσετε την επέκταση.

Μόλις κάνετε την επιλογή, το `Super + Shift + Ctrl + A` εκκινεί τον προεπιλεγμένο agent σε ένα αποκλειστικό παράθυρο terminal (ή εμφανίζει τον επιλογέα εάν δεν έχετε επιλέξει ακόμα). Μπορείτε επίσης να τον εκκινήσετε απευθείας σε μια εργασία με το `omarchy agent prompt "Review this project"`. Οι Freebuff και DeepSeek Harness δεν δέχονται αρχικό prompt, οπότε ανοίγουν με το prompt στο clipboard σας για επικόλληση. Οι agents που εκκινούνται με αυτόν τον τρόπο εκτελούνται χωρίς επίβλεψη στις αντίστοιχες λειτουργίες don't-stop-to-ask τους, οπότε να είστε έτοιμοι να κάνουν πράγματα στ' αλήθεια! Το MiniMax Code δεν διαθέτει τέτοια λειτουργία για τα διαδραστικά sessions του, οπότε ζητά δικαιώματα ως συνήθως. Και επειδή οι agents αρνούνται να θυμούνται την εμπιστοσύνη για τον home κατάλογό σας, οι εκκινήσεις από το `$HOME` ξεκινούν στο `~/Work` αντ' αυτού.

Υπάρχουν και συντομεύσεις terminal: το `a` εκτελεί τον προεπιλεγμένο agent ενσωματωμένο στο τρέχον terminal, ενώ τα `c`, `cx` και `cy` ξεκινούν απευθείας τα OpenCode, Claude Code και Codex (και πάλι στις λειτουργίες auto-approving τους). Οι αλλαγές θέματος συγχρονίζονται και στους agents: τα Claude Code, Pi, OpenCode και Hermes (μόλις το Omarchy το έχει εγκαταστήσει) ακολουθούν όλα όταν αλλάζετε το θέμα του Omarchy.

### Οι οδηγίες του agent σας

Οι προσωπικοί κανόνες για κάθε agent πηγαίνουν στο `~/.agents/AGENTS.md`, δίπλα στα κοινόχρηστα skills στο `~/.agents/skills`. Ανοίξτε το στο _Agent > Instructions_, το οποίο το συνδέει επίσης σε κάθε harness που διατηρεί το δικό του καθολικό αρχείο: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, το `~/.copilot/copilot-instructions.md` του Copilot, και ούτω καθεξής. Οι Crush και Amp διαβάζουν τον σύνδεσμο `~/.config/AGENTS.md`, ενώ οι omp, Kimi και DeepSeek Harness διαβάζουν απευθείας το `~/.agents/AGENTS.md`. Η επιλογή ενός προεπιλεγμένου agent το συνδέει επίσης. Ένα αρχείο οδηγιών που είχατε ήδη γίνεται το κοινόχρηστο εάν δεν υπήρχε κανένα ακόμα· διαφορετικά διατηρείται δίπλα στον σύνδεσμο ως `.bak`. Εκτελέστε το `omarchy agent instructions` για να επανασυνδέσετε μετά την εγκατάσταση ενός άλλου agent.

### Το panel των agents

Η επάνω γραμμή έχει ένα εικονίδιο agents. Πριν εγκαταστήσετε έναν agent, το panel του σας καθοδηγεί στη σύνδεση στον Claude, τον Codex ή τον Grok, και ο πρώτος γίνεται ο προεπιλεγμένος agent σας. Μετά από αυτό, το panel τοποθετεί κάθε συνδρομή σε μία σελίδα: κάθε agent και λογαριασμό με το πλάνο του, έναν μετρητή για καθένα από τα όρια session 5 ωρών και εβδομαδιαία όριά του με τον χρόνο μέχρι να μηδενιστεί (τοποθετήστε τον δείκτη επάνω του για το ακριβές ποσοστό), ή το υπόλοιπο προπληρωμένο υπόλοιπο, κάτω από μια γραμμή που εναλλάσσεται κυκλικά σε όσα έχετε χρησιμοποιήσει σε όλους τους, όπως tokens αυτή την εβδομάδα και το μοντέλο που χρησιμοποιείτε περισσότερο. Στο _Make something cool_ προσφέρει αρχικά prompts για ένα νέο θέμα, plugin, εφαρμογή ή παιχνίδι που αναθέτουν την εργασία στον προεπιλεγμένο agent σας. Οι εφαρμογές δημιουργούνται με τον τρόπο που δημιουργούνται τα δικά του Hype, Monologue και Omacut του Omarchy, σε C++ και Qt Quick, ακολουθώντας το agent skill omarchy-make-app, και ο compiler και τα κομμάτια Qt που χρειάζονται έρχονται εγκατεστημένα. Τα παιχνίδια είναι μία μοναδική σελίδα three.js στο `~/Games/vibes`, ακολουθώντας το agent skill omarchy-make-game, και όλα ανοίγουν από έναν εκκινητή Game Vibes στο τρέχον θέμα· φορτώνουν το three.js από το web, οπότε χρειάζονται σύνδεση για να ξεκινήσουν. Τα Claude Code, Codex, Grok, Kimi, Cursor και η παροχή Grok Bot του, GitHub Copilot, Muse, Antigravity και Devin καλύπτονται εξαρχής με τα όριά τους, το Kimchi με το πλάνο του, τις προπληρωμένες μονάδες και τους προϋπολογισμούς δαπανών του, και τα Hermes, Mistral Vibe και Qwen Code εμφανίζουν τα sessions και τα tokens τους μόλις τα χρησιμοποιήσετε. Τα πλάνα και τα κλειδιά παρόχων που χρησιμοποιείτε μέσω pi, omp ή opencode εμφανίζονται επίσης: τα OpenCode Zen και Go, το Z.ai GLM Coding Plan, το Ollama Cloud, το MiniMax Token Plan και το Synthetic με τα όριά τους· τα OpenRouter και DeepSeek με τα προπληρωμένα υπόλοιπά τους· το Fireworks με τις δαπάνες του τις τελευταίες 30 ημέρες· και τα μοντέλα που εκτελείτε στο δικό σας υλικό στην ενότητα Local models. Κάθε agent μετράται μία φορά, σε όποιον τον χρεώνει, ανεξάρτητα από το πόσα harnesses τον οδηγείτε.

Κάντε αριστερό κλικ στο εικονίδιο της γραμμής ή πατήστε `Super + Ctrl + X` για το panel, δεξί κλικ για να εκκινήσετε τον προεπιλεγμένο agent σας, και μεσαίο κλικ για ανανέωση. Οι εγγραφές χρήσης πίσω από αυτό αναγεννώνται κάθε 15 λεπτά από το `omarchy agent usage update`, και το panel μπορεί ακόμη και να συγχωνεύσει χρήση από τα άλλα μηχανήματά σας μέσω ενός συγχρονισμένου φακέλου. Δείτε το README στο `$OMARCHY_PATH/shell/plugins/agents/` για τις πλήρεις ρυθμίσεις.

### Πολλαπλές συνδρομές

Εάν πληρώνετε για περισσότερα από ένα πλάνα Claude, Codex ή Grok — ένα προσωπικό Max και ένα εργασιακό, ας πούμε — το Omarchy μπορεί να τα διατηρεί όλα συνδεδεμένα και να μετακινείται μεταξύ τους. Προσθέστε μια συνδρομή με το + στο panel των agents, το οποίο σας καθοδηγεί εκεί επί τόπου, ή με το `omarchy agent account add claude Work` (ή `codex`, ή `grok`). Εγκαθιστά το CLI εάν λείπει. Ο πρώτος λογαριασμός για έναν πάροχο συνδέεται μέσω του κανονικού browser σας, ακριβώς εκεί που το CLI ψάχνει πάντα. Κάθε επόμενος συνδέεται μέσω ενός ιδιωτικού παραθύρου, ώστε ο λογαριασμός στον οποίο ο browser σας είναι ήδη συνδεδεμένος να μην επιλεγεί κατά λάθος· συνδεθείτε εκεί ως ο λογαριασμός που προσθέτετε, και κλείστε πρώτα οποιοδήποτε ιδιωτικό παράθυρο είχατε ήδη ανοιχτό. Μην αποσυνδέεστε ποτέ από το CLI για να το κάνετε αυτό: η αποσύνδεση ανακαλεί την αποθηκευμένη σύνδεση, και αυτός ο λογαριασμός θα έπρεπε να προστεθεί ξανά.

Για να αντιγράψετε τις συνδέσεις συνδρομών σας σε ένα άλλο μηχάνημα Omarchy μέσω SSH, εκτελέστε το `omarchy agent account copy user@laptop`. Ο αποστολέας παρέχει έναν προσωρινό δέκτη όταν ο προορισμός δεν έχει εγκατεστημένο κάποιον, ώστε παλαιότερα μηχανήματα Omarchy να μπορούν να λάβουν λογαριασμούς χωρίς ενημέρωση. Οι εγκατεστημένοι δέκτες έχουν προτεραιότητα. Αυτό αντιγράφει όλες τις συνδρομές Claude, Codex και Grok· προσθέστε ονόματα παρόχων για να τις επιλέξετε, όπως στο `omarchy agent account copy laptop claude`. Τα ονόματα λογαριασμών και τα αναγνωριστικά εντολών ταιριάζουν με την πηγή, συμπεριλαμβανομένων λογαριασμών που υπάρχουν ήδη στον προορισμό. Άσχετοι λογαριασμοί προορισμού λαμβάνουν ένα αριθμητικό επίθημα εάν τα ονόματά τους συγκρούονται, και οι ρυθμίσεις, τα skills, τα plugins και το ιστορικό συνομιλιών παραμένουν τοπικά σε κάθε μηχάνημα.

Τα υπάρχοντα διαπιστευτήρια προορισμού διατηρούνται. Ένας λογαριασμός πηγής που είναι ήδη συνδεδεμένος εκεί έχει το όνομά του συγχρονισμένο χωρίς να αντικατασταθούν τα διαπιστευτήριά του· οι άλλοι λογαριασμοί προστίθενται δίπλα του. Για να αντικαταστήσετε τα αποθηκευμένα διαπιστευτήρια για λογαριασμούς που ταιριάζουν, χρησιμοποιήστε το `omarchy agent account copy --replace laptop claude` αφού κλείσετε τα sessions αυτού του λογαριασμού στον προορισμό. Ένας φρέσκος προορισμός λαμβάνει επίσης τον ενεργό λογαριασμό και τις προτιμήσεις εναλλαγής της πηγής· ένας καθιερωμένος προορισμός διατηρεί τις δικές του.

Τα διαπιστευτήρια ταξιδεύουν μέσω SSH και αποθηκεύονται σε ιδιωτικά αρχεία στον προορισμό, οπότε αντιγράψτε μόνο σε μηχανήματα που εμπιστεύεστε. Αυτή είναι μια εφάπαξ αντιγραφή, όχι συνεχιζόμενος συγχρονισμός. Τα refresh tokens του Codex μπορούν να εναλλαγούν από ένα άλλο μηχάνημα, αφήνοντας μια αντιγραμμένη σύνδεση να χρειάζεται ανανέωση· οι ξεχωριστές συνδέσεις παραμένουν η πιο αξιόπιστη επιλογή για ταυτόχρονη χρήση σε πολλά μηχανήματα. Δείτε τις [Οδηγίες ελέγχου ταυτότητας λογαριασμού του Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Ένας λογαριασμός ανά πάροχο είναι ενεργός, και κάθε νέο session ξεκινά ως αυτός: `cx`, `cy`, ένα απλό `claude`, `codex` ή `grok`, οτιδήποτε εκκινείται μέσω του `omarchy agent`, και scripts ή editors που βρίσκουν το CLI στο `PATH`. Εναλλάξτε με το `omarchy agent account use work` (και πίσω με το `omarchy agent account use main`), ή στο panel πατώντας τον αριθμό ενός λογαριασμού και στη συνέχεια `Enter` (ή κάνοντας κλικ στο κουμπί Use του). Τα sessions του Claude που εκτελούνται εναλλάσσονται επίσης, από το επόμενο μήνυμά τους: κάθε session του Claude εκτελείται στο `~/.claude`, το οποίο διατηρεί πάντα τη σύνδεση του ενεργού λογαριασμού. Ένα session του Claude που ξεκίνησε στον δικό του φάκελο ενός λογαριασμού από ένα παλαιότερο Omarchy διατηρεί αυτή τη σύνδεση μέχρι να κλείσει, οπότε η εναλλαγή ονομάζει αυτά τα sessions και ολοκληρώνεται από μόνη της μόλις εξαφανιστούν. Τα sessions των Codex και Grok που εκτελούνται παραμένουν στον λογαριασμό με τον οποίο ξεκίνησαν. Το ιστορικό συνομιλιών, οι ρυθμίσεις, τα skills και τα plugins είναι κοινόχρηστα μεταξύ λογαριασμών, οπότε το `claude --continue` στον ίδιο φάκελο συνεχίζει από εκεί που σταματήσατε στον νέο λογαριασμό.

Με περισσότερους από έναν λογαριασμούς, το panel εμφανίζει τα όρια κάθε λογαριασμού δίπλα-δίπλα, με τον ενεργό σημειωμένο. Από προεπιλογή το Omarchy σας ειδοποιεί όταν ο ενεργός λογαριασμός ξεπεράσει το 95% ενός ορίου, και κάνοντας κλικ στην ειδοποίηση εναλλάσσει στον λογαριασμό με το περισσότερο περιθώριο. Τοποθετήστε τον δείκτη πάνω στη γραμμή ενός λογαριασμού στο panel και κάντε κλικ στο Autoswitch που εμφανίζεται δίπλα στο Use (ή πατήστε `m`), ή εκτελέστε το `omarchy agent account mode auto`, για να τον κάνει να εναλλάσσεται από μόνος του αντ' αυτού· όσο είναι ενεργό, το Autoswitch παίρνει τη θέση του Use, και κάνοντας κλικ ξανά επιστρέφει στην ειδοποίηση. Προσθέστε έναν αριθμό για να αλλάξετε το όριο, όπως στο `omarchy agent account mode auto 90`. Εάν κάθε λογαριασμός είναι πάνω από το όριο, θα ενημερωθείτε μία φορά, μαζί με το ποιος λογαριασμός ελευθερώνεται πρώτος. Όσο ένας ενεργός λογαριασμός βρίσκεται εντός 15 μονάδων από το όριό του (80% στην προεπιλογή), τα όριά του ελέγχονται κάθε τρία λεπτά αντί για κάθε 15.

Το `omarchy agent account list` εμφανίζει κάθε λογαριασμό και τα τελευταία όριά του, το `omarchy agent account remove work` ξεχνά έναν, και το `omarchy agent account rename primary Hey` μετονομάζει έναν (ή κάντε κλικ στο όνομα ενός λογαριασμού στο panel). Αυτές οι εντολές λειτουργούν στους λογαριασμούς του προεπιλεγμένου agent σας· για να φτάσετε στον άλλο πάροχο, ονομάστε τον πρώτα, όπως στο `omarchy agent account use codex side`. Η σύνδεση που είχατε ήδη στα `~/.claude` ή `~/.codex` είναι ο λογαριασμός _Main_. Του Codex παραμένει εκεί που είναι· του Claude περιμένει σε δικό του φάκελο όσο ένας άλλος λογαριασμός είναι ενεργός. Ένας λογαριασμός που έμεινε αχρησιμοποίητος για περισσότερες από περίπου οκτώ ώρες μπορεί να εμφανίζει _Sign-in required_· κάντε κλικ σε αυτόν για να συνδεθείτε ξανά σε αυτόν τον λογαριασμό ακριβώς στο panel, ή εναλλάξτε σε αυτόν και ξεκινήστε ένα session, το οποίο ανανεώνει τη σύνδεση από μόνο του. Οι MCP servers που προσθέτετε με το `claude mcp add` φτάνουν σε κάθε λογαριασμό Claude, αφού όλοι εκτελούνται στο `~/.claude`· για τους Codex και Grok, οι servers που είχατε όταν προστέθηκε ένας λογαριασμός έρχονται μαζί του σε αυτόν, αλλά οι μεταγενέστεροι φτάνουν μόνο στον λογαριασμό στον οποίο τους προσθέσατε. Το Claude Desktop διατηρεί δική του σύνδεση, και τα εργαλεία Codex ή Grok που έχουν διαμορφωθεί με μια απόλυτη διαδρομή προς ένα δυαδικό CLI δεν ακολουθούν την εναλλαγή. Ένα ρητό `CLAUDE_CONFIG_DIR`, `CODEX_HOME` ή `GROK_HOME` έχει προτεραιότητα έναντι του επιλεγμένου λογαριασμού.

### Διάγνωση crash

Το Omarchy παρακολουθεί το systemd-coredump για καταρρεύσεις διεργασιών. Μόλις επιλέξετε έναν προεπιλεγμένο agent, οποιοδήποτε δικό σας πρόγραμμα που κάνει dump core φέρνει μια ειδοποίηση "Process crashed" — κάντε κλικ σε αυτήν, και η κατάρρευση παραδίδεται στον προεπιλεγμένο agent σας μαζί με το skill omarchy-diagnose-crash του Omarchy, το οποίο καθοδηγεί τον agent στην εξακρίβωση των γεγονότων από το core dump και στην απόφαση για το εάν η κατάρρευση αξίζει να αναφερθεί upstream. Μπορείτε επίσης να το εκτελέσετε χειροκίνητα εναντίον οποιουδήποτε PID από το `coredumpctl list` με το `omarchy agent crash <pid>`.

Η παρακολούθηση είναι ενεργή από προεπιλογή. Απενεργοποιήστε την στο _Trigger > Toggle > Crash Capture Off_ (ή με το `omarchy toggle crash-capture`) και οι ειδοποιήσεις σταματούν· το `omarchy agent crash <pid>` εξακολουθεί να λειτουργεί χειροκίνητα.

Οι καταρρεύσεις μπορούν επίσης να σιγαστούν ένα πρόγραμμα κάθε φορά, το οποίο είναι αυτό που σας προσφέρει η διάγνωση στο τέλος. Το `omarchy crash mute hyprland` σταματά τις ειδοποιήσεις μόνο για αυτό το πρόγραμμα, το `omarchy crash mute hyprland off` τις επαναφέρει, και το `omarchy crash mute` από μόνο του απαριθμεί όσα έχετε σιγάσει. Δέχεται τη διαδρομή του δυαδικού με την ίδια χαρά όπως το όνομά του, οπότε το `omarchy crash mute /usr/bin/hyprland` κάνει το ίδιο πράγμα. Βάλτε σε εισαγωγικά ένα όνομα με κενό σε αυτό, όπως στο `omarchy crash mute 'Some App'`. Όλα τα υπόλοιπα εξακολουθούν να ειδοποιούν, και το σιγασμένο πρόγραμμα εξακολουθεί να καταρρέει — αυτό κρύβει την υπενθύμιση, δεν διορθώνει τίποτα.

### Εφαρμογές desktop

Το μενού _Install > AI_ φέρει επίσης μερικές γραφικές εφαρμογές AI: Amp Desktop, Antigravity Desktop, την εφαρμογή desktop ChatGPT, την εφαρμογή desktop Claude (τη beta Linux της Anthropic, με καρτέλες Chat, Cowork και Claude Code), Grok Bot για συνομιλία με τα μοντέλα της xAI, Herdr Desktop, Hermes Desktop, OpenClaw, την εφαρμογή desktop Perplexity, και T3 Code. Το Grok Bot είναι η εφαρμογή desktop συνομιλίας. Ο coding agent είναι η εντολή `grok`.

Το Hermes Desktop είναι αυτό που πρέπει να γνωρίζετε, επειδή ένα μηχάνημα έχει ένα Hermes, και είναι της εφαρμογής: το Hermes εγκαθίσταται μόνο ποτέ μέσω της εφαρμογής, και η εντολή `hermes` που εκτελεί ο προεπιλεγμένος agent είναι της εφαρμογής. Η επιλογή του Hermes ως προεπιλεγμένου agent εγκαθιστά το ίδιο πράγμα που κάνει η καταχώριση _Install > AI_: το πακέτο, και ένα runtime Hermes στο `~/.hermes` που εγκαθίσταται από τον δικό του installer του Hermes, το οποίο χρειάζεται μερικά λεπτά την πρώτη φορά. Αυτό το runtime είναι το ένα Hermes που χρησιμοποιούν η εντολή terminal `hermes`, ο προεπιλεγμένος agent και η εφαρμογή, και ενημερώνεται από μόνο του με το `hermes update` αντί να περιμένει μια κυκλοφορία του Omarchy. Η εγκατάστασή του δίνει επίσης στο Hermes το θέμα του Omarchy ως ένα skin με όνομα `omarchy`, το οποίο κάθε επιφάνεια του Hermes ακολουθεί καθώς αλλάζετε θέματα· επιλέξτε ένα άλλο στις ρυθμίσεις Appearance του Hermes ή με το `/skin` εάν προτιμάτε να μην το κάνει, και το Omarchy αφήνει αυτή την επιλογή ήσυχη. Η αφαίρεση της εφαρμογής στο _Remove > AI_ κλείνει πρώτα το Hermes, συμπεριλαμβανομένου του gateway, παίρνει αυτό το runtime μαζί της, και διατηρεί τις συνομιλίες, τις μνήμες σας, και τα skills που το Hermes έγραψε για τον εαυτό του εκτός εάν του πείτε διαφορετικά: ρωτά, με προεπιλογή όχι, εάν αυτά τα δεδομένα και οι ρυθμίσεις σύνδεσής σας πρέπει να φύγουν επίσης.

Η εμπειρία desktop του OpenClaw είναι το Control UI του, το οποίο ανοίγει ως μια web εφαρμογή υποστηριζόμενη από το δικό του τοπικό gateway. Το OpenClaw ζει στο `~/.openclaw` και ενημερώνεται από μόνο του: χρησιμοποιήστε το κουμπί "Update Gateway" του Control UI ή εκτελέστε το `openclaw update`, και το gateway επανεκκινείται στη νέα έκδοση. Το Omarchy επιλέγει μόνο την κυκλοφορία από την οποία ξεκινά μια φρέσκια εγκατάσταση. Το OpenClaw μπορεί επίσης να είναι ο προεπιλεγμένος agent σας: η επιλογή του στο _Agent > Harness_ εγκαθιστά αυτό το ίδιο αντίγραφο στο `~/.openclaw`, και ο agent ανοίγει το terminal UI του OpenClaw συνδεδεμένο με το gateway του. Η αφαίρεση του OpenClaw στο _Remove > AI_ παίρνει την υπηρεσία gateway και την εφαρμογή μαζί της και στη συνέχεια ρωτά εάν το `~/.openclaw` πρέπει να φύγει επίσης, αφού αυτό διατηρεί τις συνομιλίες και τα διαπιστευτήριά σας δίπλα στο ίδιο το OpenClaw και τα plugin runtimes που κατεβάζει· η προεπιλογή το διατηρεί, και η εγκατάσταση του OpenClaw ξανά το ξαναπαίρνει.

Το Herdr Desktop είναι η εφαρμογή desktop [Herdr](https://herdr.dev): spaces, tabs και panes από terminals και coding agents που συνεχίζουν να εκτελούνται στον πυρήνα του όταν κλείνετε το παράθυρο. Προέρχεται από τον δικό του installer του Herdr αντί για ένα πακέτο, οπότε ζει στο `~/.local/share/herdr-app`, φέρνει τον πυρήνα του μαζί στο `~/.local/bin/herdr-core` όταν δεν έχετε έναν ακόμα, και ενημερώνει και τα δύο από μόνο του. Βρίσκεται δίπλα στην εντολή `herdr` που παρέχει το Omarchy στο `Super + Ctrl + Return` αντί να την αντικαθιστά, και αποκτά τα άμεσα πλήκτρα αυτής της εντολής: τα `Alt + Return` και `Alt + Shift + Return` διαιρούν ένα pane προς τα κάτω ή προς τα δεξιά, το `Alt + Escape` το κλείνει, το `Ctrl + Alt + Arrow` μετακινείται μεταξύ panes, τα `Alt + 1..9` και `Alt + Left/Right` επιλέγουν ένα tab, και τα `Alt + Up/Down` μετακινούνται μεταξύ spaces. Το `Ctrl + 1..9` επιλέγει ένα space και τα `Alt + Shift + Up/Down` προχωρούν βηματικά στους agents. Τα πλήκτρα προθέματος `Ctrl + Space` παραμένουν μόνο για terminal, αφού η εφαρμογή δεν μπορεί να κρατήσει ένα απλό πλήκτρο Ctrl για μια ακολουθία. Το Omarchy τα γράφει αυτά στο `~/.config/herdr-app/keys.json`, και το `omarchy-refresh-herdr-app` τα επαναφέρει. Η εγκατάστασή του επιλέγει το θέμα Omarchy του Herdr, το οποίο ακολουθεί το θέμα Omarchy σας από τότε και στο εξής. Το Herdr διατηρεί ένα θέμα για τη φωτεινή λειτουργία και ένα για τη σκοτεινή, οπότε μετά την εναλλαγή μεταξύ ενός σκοτεινού και ενός φωτεινού θέματος Omarchy, επιλέξτε το Omarchy στον επιλογέα θέματος του Herdr μία ακόμη φορά για την άλλη λειτουργία.

Το T3 Code εκτελείται από την επίσημη κυκλοφορία AppImage του στο `~/.local/share/t3code` αντί από ένα πακέτο, οπότε ενημερώνεται από μόνο του. Η εγκατάστασή του ρωτά εάν να ξεκινήσει στο κανάλι Stable ή Nightly· εναλλάξτε αργότερα στις ρυθμίσεις του T3 Code. Τα threads και οι ρυθμίσεις σας ζουν στο `~/.t3`, και η αφαίρεση του T3 Code στο _Remove > AI_ τα παίρνει μαζί της.

### Τοπικά μοντέλα

Εκτελέστε ένα ανοιχτό μοντέλο στο δικό σας μηχάνημα για τους coding agents σας. Τα prompts και ο κώδικάς σας παραμένουν στο μηχάνημα· τίποτα που στέλνεται στο μοντέλο δεν το αφήνει. Ξεκινήστε με:

```bash
omarchy agent local use best
```

Ή, στο panel των agents στην επάνω γραμμή, επιλέξτε + και στη συνέχεια Local AI, το οποίο εμφανίζεται όταν ένα μοντέλο χωρά σε αυτό το μηχάνημα. Το Podman, που εκτελεί τα μοντέλα, έρχεται με το Omarchy, όπως και το container toolkit της NVIDIA σε ένα μηχάνημα NVIDIA, το οποίο τους δίνει τη GPU· εάν λείπει κάποιο από τα δύο, η πρώτη εγκατάσταση το εγκαθιστά. Στη συνέχεια το Omarchy επιλέγει το συνιστώμενο μοντέλο για αυτό το μηχάνημα, το κατεβάζει, και το ξεκινά. Αναμένετε ένα κατέβασμα δεκάδων GB και το μεγαλύτερο μέρος της μνήμης του μηχανήματος να χρησιμοποιείται όσο εκτελείται το μοντέλο: το Flash Next χρησιμοποιεί περίπου 100 GiB με το πλήρες context 256K του. Εάν άλλα μοντέλα κρατούν τη μνήμη που χρειάζεται, εγκαθίσταται σταματημένο, έτοιμο να ξεκινήσει μόλις σταματήσετε ένα. Το μοντέλο σταματά κατά την αποσύνδεση· σταματήστε το εσείς οι ίδιοι όταν χρειάζεστε τη μνήμη για κάτι άλλο.

Το `omarchy agent local list` εμφανίζει τις επιλογές και εξηγεί γιατί μερικές δεν χωρούν. Για να εγκαταστήσετε ένα άλλο, εκτελέστε το `omarchy agent local use <recipe>`. Σήμερα, τα `qwen3.8-flash-next-gufo` και `qwen3.8-27b-gufo` είναι διαθέσιμα για μηχανήματα Strix Halo 128 GB· το 27B παίρνει περίπου 40 GiB, οπότε αφήνει χώρο για άλλη εργασία. Σε ένα laptop 64 GB με την Arc B390 της Intel, το `qwen3.6-35b-a3b-llamacpp` εκτελείται σε περίπου 30 GiB. Νέες συνταγές και συστάσεις φτάνουν με το `omarchy update`, μέσω του πακέτου.

Κάθε μοντέλο που εγκαθιστάτε αποκτά τη δική του γραμμή στο panel των agents, δίπλα στις συνδρομές σας: play για να το ξεκινήσετε, pause για να το σταματήσετε και να ελευθερώσετε τη μνήμη του, και το κουμπί terminal για να ανοίξετε τον agent σας σε αυτό. Πολλά μπορούν να εκτελούνται ταυτόχρονα όταν χωρούν μαζί στη μνήμη· εάν ένα δεν χωρά, το Omarchy λέει ποιο μοντέλο που εκτελείται να σταματήσετε. Σύρετε τις γραμμές για να τις αναδιατάξετε, και πατήστε Delete σε μια επιλεγμένη γραμμή για να αφαιρέσετε ένα μοντέλο και το κατέβασμά του.

Κάθε μοντέλο που εγκαθιστάτε αποκτά επίσης τη δική του καταχώριση στον app launcher, με το όνομα του μοντέλου και με το λογότυπο του κατασκευαστή του, με τον τρόπο που η σύνδεση στον Claude, τον Codex ή τον Grok προσθέτει μία. Ανοίγει τον agent σας σε αυτό το μοντέλο, και ξεκινά το μοντέλο πρώτα εάν δεν εκτελείται: το terminal το εμφανίζει να φορτώνει και παραδίδει στον agent μόλις είναι έτοιμο. Η αφαίρεση ενός μοντέλου αφαιρεί την καταχώρισή του.

Δεν είναι κάθε μοντέλο για coding. Τα μοντέλα εικόνας, βίντεο και μουσικής ανοίγουν στο Fantasi αντ' αυτού, την εφαρμογή του Omarchy για τη δημιουργία εικόνων, βίντεο και μουσικής με ένα μοντέλο που εκτελείται σε αυτό το μηχάνημα, από την καταχώριση του εκκινητή τους και από τη γραμμή τους στο panel των agents.

Ένα μοντέλο συνεχίζει να εκτελείται ακριβώς όπως εγκαταστάθηκε, οπότε μια ενημέρωση του Omarchy δεν επανεκκινεί ποτέ ένα κάτω από τους agents σας. Όταν το Omarchy έχει ένα νεότερο runtime ή νεότερα weights για ένα μοντέλο που έχετε εγκαταστήσει, η γραμμή του εμφανίζει ένα κουμπί ενημέρωσης: πατήστε το και το μοντέλο εγκαθίσταται ξανά στο παρασκήνιο, κατεβάζοντας μόνο ό,τι άλλαξε, και επανεκκινείται στη νέα έκδοση. Ένα μοντέλο που ήταν σταματημένο παραμένει σταματημένο. Το `omarchy agent local update` κάνει το ίδιο για κάθε μοντέλο από ένα terminal.

Από τη γραμμή εντολών, τα `omarchy agent local start <recipe>` και `omarchy agent local stop <recipe>` κάνουν το ίδιο, το `omarchy agent local status` εμφανίζει κάθε μοντέλο, και το `omarchy agent --local` ανοίγει τον προεπιλεγμένο agent σας στο τελευταίο μοντέλο που ξεκινήσατε. Τα pi, OpenCode και Qwen Code μπορούν να χρησιμοποιήσουν ένα· με οποιαδήποτε άλλη προεπιλογή ανοίγει στο pi, ή στο OpenCode εάν δεν έχετε το pi. Το pi απαριθμεί επίσης κάθε μοντέλο που έχετε εγκαταστήσει, και εκείνα σε μηχανήματα με τα οποία έχετε συνδεθεί, στον δικό του επιλογέα μοντέλων, οπότε το απλό `pi` τα φτάνει επίσης. Οποιοσδήποτε client συμβατός με OpenAI μπορεί να συνδεθεί επίσης: το `status` εμφανίζει τη διεύθυνση κάθε μοντέλου (η πρώτη είναι `http://127.0.0.1:11435/v1`), το όνομα της συνταγής είναι το μοντέλο, και το κλειδί βρίσκεται στο `~/.config/omarchy/agent-local/key`.

Το `omarchy agent local remove <recipe>` διαγράφει ένα μοντέλο και τα κατεβάσματα που κανένα άλλο μοντέλο δεν χρησιμοποιεί.

Τα runtimes τρίτων επισημαίνονται με τον εκδότη τους. Το Omarchy εκτελεί κάθε μοντέλο χωρίς πρόσβαση δικτύου.

### Τοπικά LLM

Το Omarchy συνιστά δύο τρόπους εκτέλεσης τοπικών μοντέλων LLM: το LM Studio και το Ollama. Το LM Studio παρέχει ένα περιβάλλον GUI για την εύρεση μοντέλων open-weight, την εγκατάστασή τους, και την εκτέλεσή τους. Είναι ένας εξαιρετικός τρόπος να ξεκινήσετε εύκολα. Το Ollama προσφέρει ένα CLI για να κάνετε κάτι παρόμοιο. Αλλά εάν είστε νέοι στα τοπικά μοντέλα, θα ξεκινούσα με το LM Studio. Μπορείτε να εγκαταστήσετε οποιοδήποτε από τα δύο στο _Install > AI_ στο Omarchy Menu.

### Τα skills του Omarchy

Τα agent skills βοηθούν την AI να χρησιμοποιεί συγκεκριμένα εργαλεία με συγκεκριμένο τρόπο, και το Omarchy παρέχει επτά από αυτά. Το skill omarchy καλύπτει την προσαρμογή του συστήματος, όπως την τροποποίηση του config του Hyprland σας ή την προσαρμογή της γραμμής. Τα omarchy-make-theme, omarchy-make-plugin, omarchy-make-app και omarchy-make-game καλύπτουν τη δημιουργία κάτι νέου, το omarchy-contribute καλύπτει την αναφορά ενός bug ή την αποστολή μιας διόρθωσης upstream, και το omarchy-diagnose-crash εξετάζει το core dump μιας κατάρρευσης. Είναι symlinked στους καταλόγους skills για τα Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` και κάθε `~/.hermes/profiles/*/skills`), και τη γενική τοποθεσία `~/.agents/skills`, οπότε τα περισσότερα harnesses τα λαμβάνουν αυτόματα. Ένας δικός σας φάκελος skill με το ίδιο όνομα έχει προτεραιότητα.

Αλλά πρέπει να αντιμετωπίζετε αυτά τα skills ως πειραματικά. Διαφορετικά μοντέλα θα το χρησιμοποιήσουν με διαφορετικό αποτέλεσμα. Είναι καλύτερο να εκτελείτε πρώτα σε plan mode, ώστε να έχετε μια ιδέα για το τι θα ήθελε να αλλάξει ο agent. Και στη συνέχεια να είστε έτοιμοι να αναιρέσετε αλλαγές ή ακόμη και να επικαλεστείτε το `omarchy reinstall configs`, εάν ο agent κάνει τα πάντα άνω κάτω.
