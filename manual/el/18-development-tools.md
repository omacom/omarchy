# Εργαλεία Ανάπτυξης

## Εναλλακτικοί Επεξεργαστές

Το Omarchy έρχεται με το [Neovim](https://neovim.io/) από προεπιλογή, αλλά αν θέλετε κάτι λίγο πιο διαδεδομένο και οικείο, μπορείτε να ανοίξετε το Omarchy Menu (`Super + Space`) και να δείτε τις επιλογές στην ενότητα _Εγκατάσταση > Επεξεργαστής_. Εκεί θα βρείτε τα VSCode, Cursor, Zed, Sublime Text, Helix, Vim και Emacs. Αν δεν βρείτε αυτό που ψάχνετε, ρίξτε μια ματιά στο _Εγκατάσταση > Πακέτο_ και δείτε μήπως υπάρχει σε πακέτο Arch (και αν όχι, δοκιμάστε το _Εγκατάσταση > AUR_ για να ελέγξετε το AUR).

Ο αρχικός επεξεργαστής `vi` είναι επίσης διαθέσιμος εξαρχής. Εκτελέστε `vi filename` για να επεξεργαστείτε ένα αρχείο στο τερματικό.

Η αντιστοίχιση θέματος προσφέρεται για τα `VSCode`, `Cursor`, `VSCodium` και `Helix`.

Μπορείτε να ορίσετε τον προεπιλεγμένο επεξεργαστή για όλο το σύστημα στην ενότητα `Ρύθμιση > Προεπιλογές > Επεξεργαστής`.

## Περιβάλλον

Το Omarchy υποστηρίζει τη ρύθμιση μιας ολόκληρης σειράς περιβαλλόντων ανάπτυξης μέσω της ενότητας _Εγκατάσταση > Ανάπτυξη_ του Omarchy Menu (`Super + Space`). Θα βρείτε φυσικά το _Ruby on Rails_, αλλά και τα τρία κύρια runtimes για JavaScript (Node.js, Bun, Deno), καθώς και δημοφιλή frameworks της PHP, όπως τα Laravel και Symfony. Α, και υπάρχουν επίσης τα Go, Rust, Python, Java, Elixir (με Phoenix), .NET, OCaml, Zig, Clojure και Scala. Είναι μια πολύ ευρεία επιλογή!

Η πλειονότητα αυτών των περιβαλλόντων διαχειρίζεται από το [Mise](https://mise.jdx.dev/). Είναι ένα εργαλείο που σας επιτρέπει να εγκαθιστάτε και να εκτελείτε πολλές εκδόσεις μιας γλώσσας προγραμματισμού στο ίδιο μηχάνημα. Είναι σαν το rbenv ή το rvm για Ruby ή το virtualenv για Python, αλλά λειτουργεί για πολλά διαφορετικά περιβάλλοντα.

Για να εγκαταστήσετε, για παράδειγμα, τη Ruby, θα εκτελούσατε `mise use -g ruby`, το οποίο θα εγκαταστήσει τη Ruby και θα την ορίσει ως καθολική προεπιλογή. Ή, αν το έργο σας έχει ένα αρχείο .ruby-version, μπορείτε απλώς να εκτελέσετε `mise i` στη ρίζα αυτού του έργου.

## Προεγκατεστημένα εργαλεία CLI

Το Omarchy καθιστά εργαλεία όπως τα `gh`, `uv` και οι περισσότεροι [πράκτορες προγραμματισμού](17-ai.md) διαθέσιμα μέσω της [τεμπέλικης εγκατάστασης του mise](https://mise.jdx.dev/dev-tools/shims.html#lazy-tools). Την πρώτη φορά που εκτελείτε ένα από αυτά, το mise το εγκαθιστά. Οι επόμενες εκτελέσεις επαναχρησιμοποιούν την εγκατεστημένη έκδοση· δεν ελέγχουν για ενημέρωση σε κάθε εκκίνηση.

Μπορείτε επίσης να δείτε τις προεπιλογές ή να τα εγκαταστήσετε εκ των προτέρων:

```bash
mise ls --current              # List the tools configured for this directory
mise install gh               # Install one tool now
mise install --include-lazy    # Install all configured tools, including lazy tools
```

Εκτελέστε `omarchy update` για να ενημερώσετε τα εγκατεστημένα εργαλεία μαζί με την υπόλοιπη εγκατάσταση του Omarchy. Το ψευδώνυμο `mup` ενημερώνει μόνο τα εργαλεία που διαχειρίζεται το mise. Για να προσθέσετε ένα άλλο εργαλείο στη δική σας διαμόρφωση, χρησιμοποιήστε `mise use -g <tool>`.

Η ρύθμιση της Python εγκαθιστά επίσης το `uv` μέσω του mise. Η αφαίρεση του περιβάλλοντος ανάπτυξης Python αφήνει το `uv` διαθέσιμο ως ανεξάρτητο εργαλείο.

### Χρήση της δικής σας εγκατάστασης

Οι εντολές του mise προηγούνται του `~/.local/bin` στο `PATH`, οπότε ένα εργαλείο που εγκαταστήσατε εσείς, για παράδειγμα με το πρόγραμμα εγκατάστασης του Claude Code ή του Cursor, εξακολουθεί να εκτελεί το αντίγραφο του mise. Οι εφαρμογές που εκκινούνται από την επιφάνεια εργασίας βρίσκουν επίσης τις εντολές του mise πριν από τα πακέτα του συστήματος, οπότε μια εφαρμογή που εκτελεί `gh` λαμβάνει το αντίγραφο του mise ακόμα κι αν εγκαταστήσατε το `github-cli` με το pacman, και το mise εγκαθιστά αυτό το αντίγραφο την πρώτη φορά. Για να χρησιμοποιήσετε αντ' αυτού το δικό σας, απενεργοποιήστε το αντίγραφο του mise στο `~/.config/mise/config.toml`. Για παράδειγμα, αν εγκαταστήσατε εσείς το Cursor CLI:

```toml
[settings]
disable_tools = ["cursor-agent"]
```

Αν έχετε ήδη έναν πίνακα `[settings]`, προσθέστε την καταχώριση εκεί· επεκτείνετε μια υπάρχουσα λίστα `disable_tools` αντί να την αντικαταστήσετε. Βεβαιωθείτε ότι η εγκατάστασή σας βρίσκεται στο `PATH`. Χρησιμοποιήστε το όνομα εργαλείου του mise, το οποίο μπορεί να διαφέρει από την εντολή του: το `oh-my-pi` παρέχει το `omp`, για παράδειγμα. Το πρόγραμμα εκκίνησης του προεπιλεγμένου πράκτορα προτιμά επίσης ένα Cursor ή Muse εγκατεστημένο από τον χρήστη στο `~/.local/bin`.

### Αφαίρεση και επαναφορά προεπιλογών

Η επιλογή _Αφαίρεση προεγκατεστημένων_ κάνει το mise να παραλείπει τις δηλώσεις εργαλείων του Omarchy για τον χρήστη σας, προσθέτοντάς τες στο `ignored_config_paths` στο `~/.config/mise/miserc.toml`. Η επιλογή _Επαναφορά προεγκατεστημένων_ αφαιρεί ξανά αυτή τη γραμμή. Τα εργαλεία που δηλώνετε εσείς, στη δική σας διαμόρφωση ή στο `mise.toml` ενός έργου, συνεχίζουν να λειτουργούν σε κάθε περίπτωση. Αν επιλέξετε έναν προεπιλεγμένο πράκτορα ή ρυθμίσετε την Python μετά την αφαίρεση των προεγκατεστημένων, αυτό το εργαλείο προστίθεται στη δική σας διαμόρφωση. Και οι δύο επιλογές ισχύουν μόνο για τον χρήστη σας· οι άλλοι χρήστες στο μηχάνημα διατηρούν τη δική τους επιλογή.

## Docker

Το [Docker](https://www.docker.com/) δεν χρειάζεται ιδιαίτερες συστάσεις. Σας επιτρέπει να εκτελείτε απομονωμένα containers, και το Omarchy εγκαθιστά όλα όσα χρειάζονται για να λειτουργεί σωστά, συμπεριλαμβανομένου του ίδιου του Docker και του [Docker Compose](https://docs.docker.com/compose/).

Από προεπιλογή ο χρήστης σας *δεν* ανήκει στην ομάδα `docker`. Αυτή η ομάδα είναι ουσιαστικά root χωρίς κωδικό πρόσβασης — οτιδήποτε ανήκει σε αυτή μπορεί να εκτελέσει `docker run -v /:/host` και να καταλάβει το μηχάνημα — οπότε ένα μόνο κακόβουλο σενάριο ή εξάρτηση που εκτελείται ως εσείς θα βρισκόταν διαφορετικά μία εντολή μακριά από το root. Έτσι, στη γραμμή εντολών εκτελείτε το Docker με `sudo` (`sudo docker ps`, `sudo docker compose up`), και τα γραφικά εργαλεία που επικοινωνούν με τον δαίμονα — το Windows VM — ζητούν εξουσιοδότηση όταν τη χρειάζονται. Αν θέλετε πίσω την ευκολία μιας ρύθμισης χωρίς ομάδα και καταλαβαίνετε τον συμβιβασμό, ενεργοποιήστε την από την ενότητα **Ρύθμιση > Ασφάλεια > Docker χωρίς sudo** (ή εκτελέστε `omarchy-setup-security-sudoless-docker`), η οποία σας προσθέτει στην ομάδα `docker` μετά από μια προειδοποίηση· τότε το απλό `docker` και το ψευδώνυμο `d` λειτουργούν ξανά χωρίς `sudo`.

Μπορείτε να ρυθμίσετε τις συνηθισμένες βάσεις δεδομένων για τοπική ανάπτυξη στο Docker χρησιμοποιώντας την ενότητα _Εγκατάσταση > Ανάπτυξη > Docker DB_ στο μενού του Omarchy.

## GitHub CLI

Το [GitHub CLI](https://cli.github.com/) είναι διαθέσιμο ως `gh` για εργασία με αποθετήρια, ζητήματα και pull requests από το τερματικό. Εκτελέστε `gh auth login` για να το εγκαταστήσετε κατά την πρώτη χρήση και να πιστοποιηθείτε, και στη συνέχεια `gh repo clone org/repo` για να κλωνοποιήσετε ένα αποθετήριο. Εκτελέστε `gh --help` για να εξερευνήσετε τις εντολές του.

Για μια διεπαφή τερματικού για τα pull requests, εκτελέστε `ghui`· το mise το εγκαθιστά επίσης κατά την πρώτη χρήση. Το [Lazygit](https://github.com/jesseduffield/lazygit) είναι προεγκατεστημένο για εργασία με το ίδιο το Git.
