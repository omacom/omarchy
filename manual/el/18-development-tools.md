# Εργαλεία ανάπτυξης

## Εναλλακτικοί επεξεργαστές

Το Omarchy διατίθεται με το Plain ως προεπιλεγμένο επεξεργαστή στις νέες εγκαταστάσεις και με το [Neovim](https://neovim.io/) προεγκατεστημένο, αλλά αν θέλετε κάτι λίγο πιο διαδεδομένο και οικείο, μπορείτε να εκτελέσετε το Omarchy Menu (`Super + Space`) και να δείτε τις επιλογές στο _Εγκατάσταση > Επεξεργαστής_. Εκεί θα βρείτε τα VSCode, Cursor, Zed, Sublime Text, Helix, Vim και Emacs. Αν δεν βρείτε αυτό που ψάχνετε, ρίξτε μια ματιά στο _Εγκατάσταση > Πακέτο_ και δείτε μήπως υπάρχει σε κάποιο πακέτο Arch (και αν όχι, δοκιμάστε το _Εγκατάσταση > AUR_ για να ελέγξετε το AUR).

Ο αρχικός επεξεργαστής `vi` είναι επίσης διαθέσιμος εξαρχής. Εκτελέστε `vi filename` για να επεξεργαστείτε ένα αρχείο στο τερματικό.

Η αντιστοίχιση θέματος προσφέρεται για τα `VSCode`, `Cursor`, `VSCodium` και `Helix`.

Μπορείτε να ορίσετε τον προεπιλεγμένο επεξεργαστή σε όλο το σύστημα στο `Setup > Defaults > Editor`.

## Περιβάλλον

Το Omarchy υποστηρίζει τη ρύθμιση μιας ολόκληρης σειράς περιβαλλόντων ανάπτυξης μέσω της ενότητας _Εγκατάσταση > Ανάπτυξη_ του Omarchy Menu (`Super + Space`). Φυσικά θα βρείτε το _Ruby on Rails_, αλλά και τους τρεις κύριους χρόνους εκτέλεσης για JavaScript (Node.js, Bun, Deno), καθώς και δημοφιλή frameworks PHP όπως τα Laravel και Symfony. Α, και υπάρχουν επίσης τα Go, Rust, Python, Java, Elixir (με Phoenix), .NET, OCaml, Zig, Clojure και Scala. Είναι μια πολύ ευρεία επιλογή!

Τα περισσότερα από αυτά τα περιβάλλοντα τα διαχειρίζεται το [Mise](https://mise.jdx.dev/). Είναι ένα εργαλείο που σας επιτρέπει να εγκαθιστάτε και να εκτελείτε πολλαπλές εκδόσεις μιας γλώσσας προγραμματισμού στο ίδιο μηχάνημα. Είναι σαν το rbenv ή το rvm για Ruby ή το virtualenv για Python, αλλά λειτουργεί για ένα σωρό διαφορετικά περιβάλλοντα.

Για να εγκαταστήσετε, ας πούμε, τη Ruby, θα εκτελέσετε `mise use -g ruby`, το οποίο θα εγκαταστήσει τη Ruby και θα την ορίσει ως καθολική προεπιλογή. Ή, αν το έργο σας έχει ένα αρχείο .ruby-version, μπορείτε απλώς να εκτελέσετε `mise i` στη ρίζα αυτού του έργου.

## Προεγκατεστημένα εργαλεία CLI

Το `uv`, το Node.js και το `playwright-cli` (για να οδηγούν οι πράκτορες ένα πρόγραμμα περιήγησης, χρησιμοποιώντας το εγκατεστημένο Chrome) διατίθενται εγκατεστημένα ως πακέτα, και το `omarchy update` τα κρατά ενημερωμένα μαζί με το υπόλοιπο σύστημα. Το `ghui`, το [Hunk](https://github.com/modem-dev/hunk) και τα CLI των Basecamp, Cloudflare και HEY απέχουν μόλις μία επιλογή στο _Εγκατάσταση > CLI_, και οι [πράκτορες προγραμματισμού](17-ai.md) στο _Εγκατάσταση > AI > CLI_.

Το mise διαχειρίζεται μόνο τους χρόνους εκτέλεσης που ρυθμίζετε από το _Εγκατάσταση > Ανάπτυξη_· το Omarchy δεν εγκαθιστά τίποτα μέσω αυτού από μόνο του. Εκτελέστε `omarchy update` για να τα ενημερώσετε μαζί με το υπόλοιπο Omarchy· το ψευδώνυμο `mup` ενημερώνει μόνο τα εργαλεία που διαχειρίζεται το mise. Για να προσθέσετε ένα άλλο εργαλείο στη δική σας διαμόρφωση, χρησιμοποιήστε το `mise use -g <tool>`.

## Docker

Το [Docker](https://www.docker.com/) δεν χρειάζεται ιδιαίτερες συστάσεις. Σας επιτρέπει να εκτελείτε απομονωμένα containers, και το Omarchy εγκαθιστά όλα όσα χρειάζονται για να λειτουργεί καλά, συμπεριλαμβανομένου του ίδιου του Docker και του [Docker Compose](https://docs.docker.com/compose/).

Από προεπιλογή, ο χρήστης σας *δεν* ανήκει στην ομάδα `docker`. Αυτή η ομάδα είναι ουσιαστικά root χωρίς κωδικό πρόσβασης — οτιδήποτε ανήκει σε αυτήν μπορεί να εκτελέσει `docker run -v /:/host` και να καταλάβει το μηχάνημα — οπότε ένα μόνο κακόβουλο σενάριο ή εξάρτηση που εκτελείται ως εσείς θα απείχε διαφορετικά μόλις μία εντολή από το root. Έτσι, στη γραμμή εντολών εκτελείτε το Docker με `sudo` (`sudo docker ps`, `sudo docker compose up`), και τα γραφικά εργαλεία που επικοινωνούν με τον δαίμονα — το Windows VM — ζητούν εξουσιοδότηση όταν τη χρειάζονται. Αν θέλετε πίσω την ευκολία μιας λειτουργίας χωρίς συμμετοχή σε ομάδα και κατανοείτε τον συμβιβασμό, ενεργοποιήστε την από το **Ρύθμιση > Ασφάλεια > Sudoless Docker** (ή εκτελέστε `omarchy-setup-security-sudoless-docker`), το οποίο σας προσθέτει στην ομάδα `docker` μετά από μια προειδοποίηση· τότε το απλό `docker` και το ψευδώνυμο `d` λειτουργούν ξανά χωρίς `sudo`.

Μπορείτε να ρυθμίσετε τις κοινές βάσεις δεδομένων για τοπική ανάπτυξη στο Docker χρησιμοποιώντας το _Εγκατάσταση > Ανάπτυξη > Docker DB_ στο μενού Omarchy.

## GitHub CLI

Το [GitHub CLI](https://cli.github.com/) είναι το `gh`, για να εργάζεστε με αποθετήρια, issues και pull requests από το τερματικό. Το _Ρύθμιση > Git_ το εγκαθιστά όταν επιλέξετε να συνδεθείτε στο GitHub εκεί, και στη συνέχεια το `gh repo clone org/repo` κλωνοποιεί ένα αποθετήριο. Εκτελέστε `gh --help` για να εξερευνήσετε τις εντολές του.

Το _Εγκατάσταση > CLI > GitHub_ εγκαθιστά το GitHub CLI, το `gh`, μαζί με το `ghui`, μια διεπαφή τερματικού για pull requests. Το [Lazygit](https://github.com/jesseduffield/lazygit) είναι προεγκατεστημένο για εργασία με το ίδιο το Git.
