# Εργαλεία Ανάπτυξης

## Εναλλακτικοί επεξεργαστές

Το Omarchy διατίθεται με το Plain ως προεπιλεγμένο επεξεργαστή στις νέες εγκαταστάσεις και με το [Neovim](https://neovim.io/) προεγκατεστημένο, αλλά αν θέλετε κάτι λίγο πιο mainstream και οικείο, μπορείτε να εκτελέσετε το Omarchy Menu (`Super + Space`) και να δείτε τις επιλογές στην ενότητα _Install > Editor_. Εκεί έχουμε καταχωρισμένα τα VSCode, Cursor, Zed, Sublime Text, Helix, Vim και Emacs. Αν δεν βρείτε αυτό που ψάχνετε, ρίξτε μια ματιά στο _Install > Package_ και δείτε μήπως υπάρχει σε κάποιο πακέτο Arch (και αν όχι, δοκιμάστε το _Install > AUR_ για να ελέγξετε το AUR).

Ο αρχικός επεξεργαστής `vi` είναι επίσης διαθέσιμος εξαρχής. Εκτελέστε `vi filename` για να επεξεργαστείτε ένα αρχείο στο τερματικό.

Η αντιστοίχιση θέματος προσφέρεται για τα `VSCode`, `Cursor`, `VSCodium` και `Helix`.

Μπορείτε να ορίσετε τον προεπιλεγμένο επεξεργαστή σε όλο το σύστημα από το `Setup > Defaults > Editor`.

## Περιβάλλον

Το Omarchy υποστηρίζει τη ρύθμιση μιας ολόκληρης σειράς περιβαλλόντων ανάπτυξης μέσα από την ενότητα _Install > Development_ του Omarchy Menu (`Super + Space`). Θα βρείτε φυσικά το _Ruby on Rails_, αλλά και τους τρεις κύριους χρόνους εκτέλεσης για JavaScript (Node.js, Bun, Deno), καθώς και δημοφιλή frameworks PHP όπως τα Laravel και Symfony. Α, και υπάρχουν επίσης Go, Rust, Python, Java, Elixir (με Phoenix), .NET, OCaml, Zig, Clojure και Scala. Είναι μια πολύ ευρεία επιλογή!

Τα περισσότερα από αυτά τα περιβάλλοντα διαχειρίζονται από το [Mise](https://mise.jdx.dev/). Είναι ένα εργαλείο που σας επιτρέπει να εγκαθιστάτε και να εκτελείτε πολλές εκδόσεις μιας γλώσσας προγραμματισμού στο ίδιο μηχάνημα. Είναι σαν το rbenv ή το rvm για Ruby ή το virtualenv για Python, αλλά λειτουργεί για ένα σωρό διαφορετικά περιβάλλοντα.

Για να εγκαταστήσετε, ας πούμε, τη Ruby, θα εκτελούσατε `mise use -g ruby`, το οποίο θα εγκαταστήσει τη Ruby και θα την ορίσει ως καθολική προεπιλογή. Ή, αν το έργο σας έχει ένα αρχείο .ruby-version, μπορείτε απλώς να εκτελέσετε `mise i` στη ρίζα αυτού του έργου.

## Προεγκατεστημένα εργαλεία CLI

Το Omarchy καθιστά εργαλεία όπως τα `gh`, `uv` και τους περισσότερους [πράκτορες προγραμματισμού](17-ai.md) διαθέσιμα μέσω της [lazy installation του mise](https://mise.jdx.dev/dev-tools/shims.html#lazy-tools). Την πρώτη φορά που εκτελείτε ένα από αυτά, το mise το εγκαθιστά. Οι πράκτορες προγραμματισμού ελέγχουν στη συνέχεια για ενημέρωση πριν εκτελεστούν, το πολύ μία φορά κάθε τέσσερις ώρες· άλλα εργαλεία, όπως τα `gh` και `uv`, επαναχρησιμοποιούν την εγκατεστημένη έκδοση μέχρι να κάνετε ενημέρωση.

Μπορείτε επίσης να ελέγξετε τις προεπιλογές ή να τα εγκαταστήσετε εκ των προτέρων:

```bash
mise ls --current              # List the tools configured for this directory
mise install gh               # Install one tool now
mise install --include-lazy    # Install all configured tools, including lazy tools
```

Εκτελέστε `omarchy update` για να ενημερώσετε τα εγκατεστημένα εργαλεία μαζί με το υπόλοιπο Omarchy. Το ψευδώνυμο `mup` ενημερώνει μόνο τα εργαλεία που διαχειρίζεται το mise. Για να προσθέσετε ένα άλλο εργαλείο στη δική σας διαμόρφωση, χρησιμοποιήστε `mise use -g <tool>`.

Η ρύθμιση της Python εγκαθιστά επίσης το `uv` μέσω mise. Η αφαίρεση του περιβάλλοντος ανάπτυξης Python αφήνει το `uv` διαθέσιμο ως ανεξάρτητο εργαλείο.

### Χρήση της δικής σας εγκατάστασης

Οι εντολές του mise έρχονται πριν από το `~/.local/bin` στο `PATH`, οπότε ένα εργαλείο που εγκαταστήσατε εσείς, για παράδειγμα με το δικό του πρόγραμμα εγκατάστασης του Claude Code ή του Cursor, εξακολουθεί να εκτελεί το αντίγραφο του mise. Οι εφαρμογές που εκκινούνται από την επιφάνεια εργασίας βρίσκουν επίσης τις εντολές του mise πριν από τα πακέτα συστήματος, οπότε μια εφαρμογή που εκτελεί το `gh` λαμβάνει το αντίγραφο του mise ακόμη κι αν εγκαταστήσατε το `github-cli` με pacman, και το mise εγκαθιστά αυτό το αντίγραφο την πρώτη φορά. Για να χρησιμοποιήσετε το δικό σας αντί αυτού, απενεργοποιήστε το αντίγραφο του mise στο `~/.config/mise/config.toml`. Για παράδειγμα, αν εγκαταστήσατε εσείς το Cursor CLI:

```toml
[settings]
disable_tools = ["cursor-agent"]
```

Αν έχετε ήδη έναν πίνακα `[settings]`, προσθέστε την καταχώριση εκεί· επεκτείνετε μια υπάρχουσα λίστα `disable_tools` αντί να την αντικαταστήσετε. Βεβαιωθείτε ότι η εγκατάστασή σας βρίσκεται στο `PATH`. Χρησιμοποιήστε το όνομα εργαλείου του mise, το οποίο μπορεί να διαφέρει από την εντολή του: το `oh-my-pi` παρέχει το `omp`, για παράδειγμα. Το πρόγραμμα εκκίνησης του προεπιλεγμένου πράκτορα προτιμά επίσης ένα Cursor ή Muse εγκατεστημένο από τον χρήστη στο `~/.local/bin`.

### Αφαίρεση και επαναφορά προεπιλογών

Το _Remove > Preinstalls_ αφαιρεί τις προεγκατεστημένες εφαρμογές web, τα TUIs και τις εφαρμογές του Omarchy και κάνει το mise να παραλείπει τις δηλώσεις εργαλείων του Omarchy για τον χρήστη σας, προσθέτοντάς τες στο `ignored_config_paths` στο `~/.config/mise/miserc.toml`. Το _Install > Preinstalls_ τις επαναφέρει και αφαιρεί ξανά αυτή τη γραμμή. Τα εργαλεία που δηλώνετε εσείς, στη δική σας διαμόρφωση ή στο `mise.toml` ενός έργου, συνεχίζουν να λειτουργούν σε κάθε περίπτωση. Αν επιλέξετε έναν προεπιλεγμένο πράκτορα ή ρυθμίσετε την Python μετά την αφαίρεση των προεγκατεστημένων, αυτό το εργαλείο προστίθεται στη δική σας διαμόρφωση. Η ρύθμιση του mise ισχύει μόνο για τον χρήστη σας και οι άλλοι χρήστες διατηρούν τη δική τους επιλογή· οι εφαρμογές όμως είναι πακέτα, οπότε η αφαίρεση ή η επαναφορά τους τις αλλάζει για όλους στο μηχάνημα.

## Docker

Το [Docker](https://www.docker.com/) δεν χρειάζεται ιδιαίτερες συστάσεις. Σας επιτρέπει να εκτελείτε απομονωμένα containers και το Omarchy εγκαθιστά όλα όσα χρειάζονται για να λειτουργεί καλά, συμπεριλαμβανομένου του ίδιου του Docker και του [Docker Compose](https://docs.docker.com/compose/).

Από προεπιλογή ο χρήστης σας *δεν* βρίσκεται στην ομάδα `docker`. Αυτή η ομάδα είναι ουσιαστικά root χωρίς κωδικό πρόσβασης — οτιδήποτε βρίσκεται σε αυτήν μπορεί να εκτελέσει `docker run -v /:/host` και να καταλάβει το μηχάνημα — οπότε ένα μόνο κακόβουλο σενάριο ή εξάρτηση που εκτελείται ως εσείς θα βρισκόταν διαφορετικά μία εντολή μακριά από το root. Έτσι στη γραμμή εντολών εκτελείτε το Docker με `sudo` (`sudo docker ps`, `sudo docker compose up`) και τα γραφικά εργαλεία που επικοινωνούν με τον δαίμονα — το Windows VM — ζητούν εξουσιοδότηση όταν τη χρειάζονται. Αν θέλετε πίσω την ευκολία μιας ρύθμισης χωρίς ομάδα και κατανοείτε το αντάλλαγμα, ενεργοποιήστε την από το **Setup > Security > Sudoless Docker** (ή εκτελέστε `omarchy-setup-security-sudoless-docker`), το οποίο σας προσθέτει στην ομάδα `docker` μετά από μια προειδοποίηση· τότε το σκέτο `docker` και το ψευδώνυμο `d` λειτουργούν ξανά χωρίς `sudo`.

Μπορείτε να ρυθμίσετε τις κοινές βάσεις δεδομένων για τοπική ανάπτυξη στο Docker χρησιμοποιώντας το _Install > Development > Docker DB_ στο μενού Omarchy.

## GitHub CLI

Το [GitHub CLI](https://cli.github.com/) είναι διαθέσιμο ως `gh` για εργασία με αποθετήρια, ζητήματα και pull requests από το τερματικό. Εκτελέστε `gh auth login` για να το εγκαταστήσετε κατά την πρώτη χρήση και να πιστοποιηθείτε, στη συνέχεια `gh repo clone org/repo` για να κλωνοποιήσετε ένα αποθετήριο. Εκτελέστε `gh --help` για να εξερευνήσετε τις εντολές του.

Για μια διεπαφή τερματικού για pull requests, εκτελέστε το `ghui`· το mise το εγκαθιστά επίσης κατά την πρώτη χρήση. Το [Lazygit](https://github.com/jesseduffield/lazygit) είναι προεγκατεστημένο για εργασία με το ίδιο το Git.
