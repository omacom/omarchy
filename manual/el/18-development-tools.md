# Εργαλεία ανάπτυξης

## Εναλλακτικά προγράμματα επεξεργασίας

Το Omarchy διατίθεται με το Plain ως προεπιλεγμένο πρόγραμμα επεξεργασίας στις νέες εγκαταστάσεις και με προεγκατεστημένο το [Neovim](https://neovim.io/), αλλά αν θέλετε κάτι λίγο πιο mainstream και οικείο, μπορείτε να ανοίξετε το Omarchy Menu (`Super + Space`) και να δείτε τις επιλογές στην ενότητα _Εγκατάσταση > Επεξεργαστής_. Εκεί θα βρείτε τα VSCode, Cursor, Zed, Sublime Text, Helix, Vim και Emacs. Αν δεν βρείτε αυτό που ψάχνετε, ρίξτε μια ματιά στο _Εγκατάσταση > Πακέτο_ και δείτε μήπως δεν υπάρχει σε κάποιο πακέτο Arch (και αν όχι, δοκιμάστε το _Εγκατάσταση > AUR_ για να ελέγξετε το AUR).

Το αρχικό πρόγραμμα επεξεργασίας `vi` είναι επίσης διαθέσιμο εξαρχής. Εκτελέστε `vi filename` για να επεξεργαστείτε ένα αρχείο στο τερματικό.

Η αντιστοίχιση θέματος προσφέρεται για τα `VSCode`, `Cursor`, `VSCodium` και `Helix`.

Μπορείτε να ορίσετε το προεπιλεγμένο πρόγραμμα επεξεργασίας για όλο το σύστημα από το `Setup > Defaults > Editor`.

## Περιβάλλον

Το Omarchy υποστηρίζει τη ρύθμιση μιας ολόκληρης σειράς περιβαλλόντων ανάπτυξης μέσω της ενότητας _Εγκατάσταση > Ανάπτυξη_ του Omarchy Menu (`Super + Space`). Φυσικά θα βρείτε το _Ruby on Rails_, αλλά και τα τρία μεγάλα runtimes για JavaScript (Node.js, Bun, Deno), καθώς και δημοφιλή frameworks PHP όπως τα Laravel και Symfony. Α, και υπάρχουν επίσης τα Go, Rust, Python, Java, Elixir (με Phoenix), .NET, OCaml, Zig, Clojure και Scala. Είναι μια πολύ ευρεία επιλογή!

Τα περισσότερα από αυτά τα περιβάλλοντα διαχειρίζονται μέσω του [Mise](https://mise.jdx.dev/). Είναι ένα εργαλείο που σας επιτρέπει να εγκαθιστάτε και να εκτελείτε πολλαπλές εκδόσεις μιας γλώσσας προγραμματισμού στον ίδιο υπολογιστή. Είναι σαν το rbenv ή το rvm για Ruby ή το virtualenv για Python, αλλά λειτουργεί για μια σειρά από διαφορετικά περιβάλλοντα.

Για να εγκαταστήσετε, ας πούμε, τη Ruby, θα εκτελούσατε το `mise use -g ruby`, το οποίο θα εγκαταστήσει τη Ruby και θα την ορίσει ως καθολική προεπιλογή. Ή, αν το έργο σας έχει ένα αρχείο .ruby-version, μπορείτε απλώς να εκτελέσετε το `mise i` στη ρίζα αυτού του έργου.

## Προεγκατεστημένα εργαλεία CLI

Τα `uv`, Node.js και `playwright-cli` (για να οδηγούν οι agents ένα πρόγραμμα περιήγησης, χρησιμοποιώντας το εγκατεστημένο Chrome) διατίθενται εγκατεστημένα ως πακέτα, και το `omarchy update` τα διατηρεί ενημερωμένα μαζί με την υπόλοιπη εγκατάσταση. Το [Hunk](https://github.com/modem-dev/hunk) και τα CLI των GitHub, Basecamp, Cloudflare και HEY απέχουν μία επιλογή, στο _Εγκατάσταση > CLI_, και οι [agents προγραμματισμού](17-ai.md) στο _Εγκατάσταση > AI > CLI_.

Το mise διαχειρίζεται μόνο τα runtimes που ρυθμίζετε από το _Εγκατάσταση > Ανάπτυξη_· το Omarchy δεν εγκαθιστά τίποτα μέσω αυτού από μόνο του. Εκτελέστε το `omarchy update` για να τα ενημερώσετε μαζί με το υπόλοιπο Omarchy· το ψευδώνυμο `mup` ενημερώνει μόνο τα εργαλεία που διαχειρίζεται το mise. Για να προσθέσετε ένα άλλο εργαλείο στη δική σας διαμόρφωση, χρησιμοποιήστε το `mise use -g <tool>`.

## Docker

Το [Docker](https://www.docker.com/) δεν χρειάζεται ιδιαίτερες συστάσεις. Σας επιτρέπει να εκτελείτε απομονωμένα containers, και το Omarchy εγκαθιστά όλα όσα χρειάζονται για να λειτουργεί σωστά, συμπεριλαμβανομένων του ίδιου του Docker και του [Docker Compose](https://docs.docker.com/compose/).

Από προεπιλογή, ο χρήστης σας *δεν* ανήκει στην ομάδα `docker`. Αυτή η ομάδα είναι ουσιαστικά root χωρίς κωδικό πρόσβασης — οτιδήποτε ανήκει σε αυτήν μπορεί να εκτελέσει το `docker run -v /:/host` και να καταλάβει τον υπολογιστή — οπότε ένα και μόνο κακόβουλο σενάριο ή εξάρτηση που εκτελείται ως εσείς θα απείχε διαφορετικά μία εντολή από το root. Έτσι, στη γραμμή εντολών εκτελείτε το Docker με `sudo` (`sudo docker ps`, `sudo docker compose up`), και τα γραφικά εργαλεία που επικοινωνούν με τον daemon — το Windows VM — ζητούν εξουσιοδότηση όταν τη χρειάζονται. Αν θέλετε πίσω την ευκολία μιας ρύθμισης χωρίς sudo και καταλαβαίνετε το αντάλλαγμα, ενεργοποιήστε την από το **Ρύθμιση > Ασφάλεια > Sudoless Docker** (ή εκτελέστε το `omarchy-setup-security-sudoless-docker`), το οποίο σας προσθέτει στην ομάδα `docker` μετά από μια προειδοποίηση· τότε το σκέτο `docker` και το ψευδώνυμο `d` λειτουργούν ξανά χωρίς `sudo`.

Μπορείτε να ρυθμίσετε τις κοινές βάσεις δεδομένων για τοπική ανάπτυξη στο Docker χρησιμοποιώντας το _Εγκατάσταση > Ανάπτυξη > Docker DB_ στο Omarchy menu.

## GitHub CLI

Το [GitHub CLI](https://cli.github.com/) είναι το `gh`, για εργασία με αποθετήρια, ζητήματα και pull requests από το τερματικό. Το _Ρύθμιση > Git_ το εγκαθιστά όταν επιλέγετε να συνδεθείτε στο GitHub εκεί, ή εγκαταστήστε το ξεχωριστά από το _Εγκατάσταση > CLI > GitHub_. Στη συνέχεια, το `gh repo clone org/repo` κλωνοποιεί ένα αποθετήριο· εκτελέστε το `gh --help` για να εξερευνήσετε τις εντολές του.

Το [Lazygit](https://github.com/jesseduffield/lazygit) είναι προεγκατεστημένο για εργασία με το ίδιο το Git.
