# KI

Omarchy enthält Starter für die unten aufgeführten Coding-Agenten, ohne dir einen Standard vorzuschreiben. Führe einen Befehl aus, um seine CLI bei der ersten Verwendung zu installieren, und authentifiziere dich dann, wenn du dazu aufgefordert wirst. Hermes ist die Ausnahme: Dafür wird bei der ersten Verwendung nichts installiert, und wenn du es auswählst, wird Hermes Desktop installiert, wie unten unter _Desktop-Apps_ erklärt wird.

### Agenten installieren und aktualisieren

Mit Ausnahme von Hermes verwenden diese Agenten die Lazy-Installation von mise: Der erste Start installiert die CLI, und spätere Starts verwenden sie wieder. mise prüft außerdem höchstens einmal alle vier Stunden, ob es für einen installierten Agenten eine neue Version gibt, kurz bevor er startet oder im Hintergrund an einem Shell-Prompt. Wenn dieses Update fehlschlägt oder du offline bist, läuft die installierte Version. `omarchy update` aktualisiert installierte Agenten zusammen mit dem Rest von Omarchy, und `mup` aktualisiert nur von mise verwaltete Tools.

Das eigene Update-Programm eines Agenten, wie `claude update`, `codex update` oder ein Update-Button in einer App, aktualisiert die von mise verwaltete Installation nicht. `codex update` schlägt fehl, und `claude update` kann Erfolg melden, während es eine separate Kopie installiert, die mise nicht verfolgt. Wenn du lieber das native Installations- und Update-Programm eines Agenten verwenden möchtest, füge ihn zu `disable_tools` hinzu; siehe [Vorinstallierte CLI-Tools](18-development-tools.md#preinstalled-cli-tools).

Um alle konfigurierten Lazy-Tools zu installieren, bevor du sie brauchst, führe `mise install --include-lazy` aus. Dies umfasst Omarchys andere Standard-CLI-Tools ebenso wie die Agenten. Siehe [Vorinstallierte CLI-Tools](18-development-tools.md#preinstalled-cli-tools) zum Installieren eines einzelnen Tools oder zur Verwendung deiner eigenen Installation.

`grok` wird über mises First-Party-Paket `grok` installiert, genauso wie `claude` und `codex`. Führe `grok` aus oder wähle es unter _Agent > Harness_. Überspringe den `curl | bash`-Installer auf x.ai. Dieser Weg legt eine zweite Kopie in `~/.grok/bin` ab, stellt sie auf dem `PATH` voran und überschreibt Omarchys Wrapper.

`dsh` öffnet seine Browser-Oberfläche unter `127.0.0.1:3080`, mit dem Startverzeichnis als Standard-Workspace. Seine Browser-Oberfläche akzeptiert keinen Start-Prompt, daher öffnet `omarchy agent prompt` sie mit dem Prompt in deiner Zwischenablage zum Einfügen. Omarchy startet es mit DeepSeeks Berechtigungs-Preset ohne Genehmigungen. DeepSeek Harness lädt Sitzungsprotokolle zu DeepSeek hoch, wenn du seine offizielle Model-API verwendest; schalte das unter _Settings > General > Upload Session Log_ in seiner Browser-Oberfläche aus. Feedback, das du ihm sendest, wird ebenfalls mit der Sitzung hochgeladen, es sei denn, du startest es mit `DSH_TELEMETRY_MODE=DISABLED`.

### Der Standard-Agent

Wähle deinen Standard-Agenten mit `omarchy default agent <name>` oder unter _Agent > Harness_ im Omarchy Menu (`Super + Space`). Wenn der Agent noch nicht installiert ist, installiert ihn die Auswahl zuerst. Ein frisches Omarchy wird dich mit einer einmaligen Benachrichtigung einladen, diese Auswahl zu treffen.

Die Auswahl von Claude versucht außerdem, seine Browser-Erweiterung für Chromium, Chrome, Brave, Brave Origin und Edge einzurichten. Die Einrichtung der Erweiterung gilt für alle Benutzer und kann nach deinem Systempasswort fragen; das Abbrechen oder eine fehlgeschlagene Installation der Erweiterung wählt Claude trotzdem aus und startet es. Starte deinen Browser neu, aktiviere die Erweiterung, wenn du dazu aufgefordert wirst, und melde dich bei Claude an, um die Verbindung abzuschließen. Führe `/chrome` in Claude aus, um die Verbindung zu überprüfen. Firefox und Zen unterstützen diese Erweiterung nicht. Wenn Claude bereits dein Standard war, bevor diese Einrichtung hinzugefügt wurde, wähle es erneut aus, um die Erweiterung zu installieren.

Sobald du gewählt hast, startet `Super + Shift + Ctrl + A` den Standard-Agenten in einem dedizierten Terminalfenster (oder zeigt die Auswahl an, wenn du noch nicht gewählt hast). Du kannst ihn auch direkt mit einer Aufgabe starten, mit `omarchy agent prompt "Review this project"`. Freebuff und DeepSeek Harness akzeptieren keinen Start-Prompt, daher öffnen sie stattdessen mit dem Prompt in deiner Zwischenablage zum Einfügen. Auf diese Weise gestartete Agenten laufen unbeaufsichtigt in ihren jeweiligen Modi, in denen sie nicht anhalten, um zu fragen, also sei darauf gefasst, dass sie tatsächlich Dinge tun! MiniMax Code hat für seine interaktiven Sitzungen keinen solchen Modus, also fragt es wie üblich nach Berechtigungen. Und da Agenten sich weigern, Vertrauen für dein Home-Verzeichnis zu merken, starten Starts aus `$HOME` stattdessen in `~/Work`.

Es gibt auch Terminal-Kurzbefehle: `a` führt den Standard-Agenten inline im aktuellen Terminal aus, während `c`, `cx` und `cy` OpenCode, Claude Code und Codex direkt starten (wieder in ihren Modi mit automatischer Genehmigung). Theme-Wechsel synchronisieren sich ebenfalls mit den Agenten: Claude Code, Pi, OpenCode und Hermes (sobald Omarchy es installiert hat) folgen alle, wenn du das Omarchy-Theme wechselst.

### Deine Agenten-Anweisungen

Persönliche Regeln für jeden Agenten gehören in `~/.agents/AGENTS.md`, neben die geteilten Skills in `~/.agents/skills`. Öffne sie unter _Agent > Instructions_, was sie auch in jedes Harness verlinkt, das seine eigene globale Datei führt: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, Copilots `~/.copilot/copilot-instructions.md` und so weiter. Crush und Amp lesen den Link `~/.config/AGENTS.md`, während omp, Kimi und DeepSeek Harness `~/.agents/AGENTS.md` direkt lesen. Die Auswahl eines Standard-Agenten verlinkt sie ebenfalls. Eine Anweisungsdatei, die du bereits hattest, wird zur geteilten, wenn es noch keine gab; andernfalls wird sie als `.bak` neben dem Link aufbewahrt. Führe `omarchy agent instructions` aus, um nach der Installation eines weiteren Agenten neu zu verlinken.

### Das Agenten-Panel

Die obere Leiste hat ein Agenten-Symbol. Bevor du einen Agenten eingerichtet hast, führt dich sein Panel durch die Anmeldung bei Claude, Codex oder Grok, und der erste wird zu deinem Standard-Agenten. Danach bringt das Panel jedes Abonnement auf eine Seite: jeden Agenten und jedes Konto mit seinem Plan, eine Anzeige für jedes seiner Limits für 5-Stunden-Sitzungen und wöchentlichen Limits mit der Zeit bis zum Zurücksetzen (fahre darüber für den genauen Prozentsatz) oder das verbleibende Prepaid-Guthaben, unter einer Zeile, die durchwechselt, was du über alle hinweg verbraucht hast, wie Tokens diese Woche und dein am meisten verwendetes Modell. Unter _Make something_ bietet es Starter-Prompts für ein neues Theme, Plugin oder eine neue App, die die Aufgabe an deinen Standard-Agenten übergeben. Apps werden so gebaut, wie Omarchys eigene Hype, Monologue und Omacut, in C++ und Qt Quick, nach dem omarchy-app Agent Skill, und der Compiler und die Qt-Teile, die sie brauchen, kommen installiert mit. Claude Code, Codex, Grok, Kimi, Cursor und sein Grok Bot-Kontingent, GitHub Copilot, Muse, Antigravity, Kimchi und Devin sind von Haus aus mit ihren Limits abgedeckt, und Hermes, Mistral Vibe und Qwen Code zeigen ihre Sitzungen und Tokens, sobald du sie verwendet hast. Provider-Pläne und Schlüssel, die du über pi, omp oder opencode verwendest, tauchen ebenfalls auf: OpenCode Zen und Go, der Z.ai GLM Coding Plan, Ollama Cloud, der MiniMax Token Plan und Synthetic mit ihren Limits; Fireworks, OpenRouter und DeepSeek mit ihren Prepaid-Guthaben; und die Modelle, die du auf deiner eigenen Hardware unter Local models ausführst. Jeder Agent wird einmal gezählt, unter dem, der ihn abrechnet, egal durch wie viele Harnesses du ihn betreibst.

Linksklicke auf das Leistensymbol für das Panel, rechtsklicke, um deinen Standard-Agenten zu starten. Die dahinterliegenden Nutzungsaufzeichnungen werden alle 15 Minuten von `omarchy agent usage-update` neu erstellt, und das Panel kann sogar die Nutzung von deinen anderen Maschinen über einen synchronisierten Ordner zusammenführen. Siehe das README unter `$OMARCHY_PATH/shell/plugins/agents/` für alle Einstellungen.

### Mehrere Abonnements

Wenn du für mehr als einen Claude-, Codex- oder Grok-Plan bezahlst — etwa einen persönlichen Max und einen für die Arbeit — kann Omarchy sie alle angemeldet halten und zwischen ihnen wechseln. Füge ein Abonnement mit dem + im Agenten-Panel hinzu, das dich direkt dort hindurchführt, oder mit `omarchy agent account add claude Work` (oder `codex` oder `grok`). Es installiert die CLI, wenn sie fehlt. Das erste Konto für einen Provider meldet sich über deinen normalen Browser an, genau dort, wo die CLI immer nachsieht. Jedes weitere meldet sich über ein privates Fenster an, damit das Konto, mit dem dein Browser bereits angemeldet ist, nicht versehentlich übernommen wird; melde dich dort als das Konto an, das du hinzufügst, und schließe vorher jedes private Fenster, das du bereits offen hattest. Melde dich dafür niemals aus der CLI ab: Das Abmelden widerruft die gespeicherte Anmeldung, und dieses Konto müsste erneut hinzugefügt werden.

Um deine Abonnement-Anmeldungen über SSH auf eine andere Omarchy-Maschine zu kopieren, führe `omarchy agent account copy user@laptop` aus. Der Sender stellt einen temporären Empfänger bereit, wenn das Ziel keinen installiert hat, sodass ältere Omarchy-Maschinen Konten ohne Update empfangen können. Installierte Empfänger haben Vorrang. Dies kopiert alle Claude-, Codex- und Grok-Abonnements; füge Provider-Namen hinzu, um sie auszuwählen, wie bei `omarchy agent account copy laptop claude`. Kontonamen und Befehls-IDs stimmen mit der Quelle überein, einschließlich Konten, die bereits auf dem Ziel vorhanden sind. Unverbundene Zielkonten erhalten ein numerisches Suffix, wenn ihre Namen konfligieren, und Einstellungen, Skills, Plugins und Gesprächsverlauf bleiben lokal auf jeder Maschine.

Vorhandene Ziel-Anmeldedaten bleiben erhalten. Ein Quellkonto, das dort bereits angemeldet ist, bekommt seinen Namen synchronisiert, ohne seine Anmeldedaten zu ersetzen; andere Konten werden daneben hinzugefügt. Um gespeicherte Anmeldedaten für übereinstimmende Konten zu ersetzen, verwende `omarchy agent account copy --replace laptop claude`, nachdem du die Sitzungen dieses Kontos auf dem Ziel beendet hast. Ein frisches Ziel erhält außerdem das aktive Konto und die Wechsel-Einstellungen der Quelle; ein bereits eingerichtetes Ziel behält seine eigenen.

Anmeldedaten reisen über SSH und werden in privaten Dateien auf dem Ziel gespeichert, kopiere also nur auf Maschinen, denen du vertraust. Dies ist eine einmalige Kopie, keine laufende Synchronisierung. Codex-Refresh-Tokens können von einer anderen Maschine rotiert werden, wodurch eine kopierte Anmeldung erneuert werden muss; separate Anmeldungen bleiben die zuverlässigste Wahl für die gleichzeitige Nutzung auf mehreren Maschinen. Siehe [Codex' Anleitung zur Konto-Authentifizierung](https://developers.openai.com/codex/auth/ci-cd-auth).

Pro Provider ist ein Konto aktiv, und jede neue Sitzung startet als dieses: `cx`, `cy`, ein einfaches `claude`, `codex` oder `grok`, alles, was über `omarchy agent` gestartet wird, und Skripte oder Editoren, die die CLI auf dem `PATH` finden. Wechsle mit `omarchy agent account use work` (und zurück mit `omarchy agent account use main`) oder im Panel, indem du die Nummer eines Kontos drückst und dann `Enter` (oder auf seinen Use-Button klickst). Sitzungen, die bereits laufen, bleiben bei dem Konto, mit dem sie gestartet sind. Gesprächsverlauf, Einstellungen, Skills und Plugins werden über Konten hinweg geteilt, sodass `claude --continue` im selben Ordner dort weitermacht, wo du auf dem neuen Konto aufgehört hast.

Bei mehr als einem Konto zeigt das Panel die Limits jedes Kontos nebeneinander an, mit dem aktiven markiert. Standardmäßig benachrichtigt dich Omarchy, wenn das aktive Konto 95 % eines Limits überschreitet, und ein Klick auf die Benachrichtigung wechselt zu dem Konto mit dem meisten Spielraum. Fahre über die Zeile eines Kontos im Panel und klicke auf das Autoswitch, das neben Use erscheint (oder drücke `m`), oder führe `omarchy agent account mode auto` aus, damit es stattdessen von selbst wechselt; während es an ist, nimmt Autoswitch die Stelle von Use ein, und ein erneuter Klick darauf schaltet zurück zum Benachrichtigen. Füge eine Zahl hinzu, um die Schwelle zu ändern, wie bei `omarchy agent account mode auto 90`. Wenn jedes Konto über der Schwelle liegt, erfährst du es einmal, zusammen damit, welches Konto zuerst frei wird. Während ein aktives Konto innerhalb von 15 Punkten an seiner Schwelle liegt (80 % beim Standard), werden seine Limits alle drei Minuten statt alle 15 geprüft.

`omarchy agent account list` zeigt jedes Konto und seine neuesten Limits, `omarchy agent account remove work` vergisst eines, und `omarchy agent account rename primary Hey` benennt eines um (oder klicke auf den Namen eines Kontos im Panel). Diese Befehle arbeiten auf den Konten deines Standard-Agenten; um den anderen Provider zu erreichen, nenne ihn zuerst, wie bei `omarchy agent account use codex side`. Die Anmeldung, die du bereits in `~/.claude` oder `~/.codex` hattest, ist das _Main_-Konto und bleibt, wo sie ist. Ein Konto, das mehr als etwa acht Stunden ungenutzt geblieben ist, kann _Sign-in required_ zeigen; klicke darauf, um dieses Konto direkt im Panel erneut anzumelden, oder starte eine Sitzung darin, was die Anmeldung von selbst auffrischt. MCP-Server, die du hattest, als ein Konto hinzugefügt wurde, kommen mit zu ihm, aber solche, die du später mit `claude mcp add` hinzufügst, erreichen nur das Konto, in dem du sie hinzugefügt hast. Claude Desktop und Tools, die mit einem absoluten Pfad zu einer CLI-Binärdatei konfiguriert sind, folgen dem Wechsel nicht. Ein explizites `CLAUDE_CONFIG_DIR`, `CODEX_HOME` oder `GROK_HOME` hat Vorrang vor dem ausgewählten Konto.

### Absturzdiagnose

Omarchy überwacht systemd-coredump auf Prozessabstürze. Wenn etwas segfaultet, erhältst du eine Benachrichtigung „Process crashed“ — klicke darauf, und der Absturz wird an deinen Standard-Agenten übergeben, zusammen mit Omarchys diagnose-crash Skill, der den Agenten dadurch führt, die Fakten aus dem Core Dump zu ermitteln und zu entscheiden, ob der Absturz es wert ist, upstream gemeldet zu werden. Du kannst es auch von Hand gegen jede PID aus `coredumpctl list` mit `omarchy agent crash <pid>` ausführen.

Die Überwachung ist standardmäßig an. Schalte sie unter _Trigger > Toggle > Crash Capture_ aus (oder mit `omarchy toggle crash-capture`), und die Benachrichtigungen hören auf; `omarchy agent crash <pid>` funktioniert weiterhin von Hand.

Abstürze können auch für ein Programm nach dem anderen stummgeschaltet werden, was die Diagnose dir am Ende anbietet. `omarchy crash mute hyprland` stoppt die Benachrichtigungen nur für dieses Programm, `omarchy crash mute hyprland off` bringt sie zurück, und `omarchy crash mute` allein listet auf, was du stummgeschaltet hast. Es akzeptiert den Pfad der Binärdatei genauso gern wie ihren Namen, sodass `omarchy crash mute /usr/bin/hyprland` dasselbe tut. Setze einen Namen mit einem Leerzeichen darin in Anführungszeichen, wie bei `omarchy crash mute 'Some App'`. Alles andere benachrichtigt weiterhin, und das stummgeschaltete Programm stürzt weiterhin ab — dies verbirgt die Erinnerung, es repariert nichts.

### Desktop-Apps

Das Menü _Install > AI_ enthält auch einige grafische KI-Apps: die ChatGPT Desktop-App, die Claude Desktop-App (Anthropics Linux-Beta, mit Chat-, Cowork- und Claude Code-Tabs), Grok Bot zum Chatten mit xAIs Modellen, Herdr Desktop, Hermes Desktop, OpenClaw, die Perplexity Desktop-App und T3 Code. Grok Bot ist die Desktop-Chat-App. Der Coding-Agent ist der Befehl `grok`.

Hermes Desktop ist die, die du kennen solltest, denn eine Maschine hat ein Hermes, und es ist das der App: Hermes wird nur je über die App installiert, und der Befehl `hermes`, den der Standard-Agent ausführt, ist der der App. Hermes als Standard-Agenten zu wählen, installiert dasselbe wie der Eintrag _Install > AI_: das Paket und eine Hermes-Runtime unter `~/.hermes`, eingerichtet durch Hermes' eigenen Installer, was beim ersten Mal einige Minuten dauert. Diese Runtime ist das eine Hermes, das der Terminal-Befehl `hermes`, der Standard-Agent und die App alle verwenden, und sie aktualisiert sich selbst mit `hermes update`, statt auf ein Omarchy-Release zu warten. Ihre Installation übergibt Hermes außerdem das Omarchy-Theme als Skin namens `omarchy`, dem jede Hermes-Oberfläche folgt, wenn du Themes wechselst; wähle ein anderes unter Hermes' Appearance-Einstellungen oder mit `/skin`, wenn du lieber nicht möchtest, dass es das tut, und Omarchy lässt diese Wahl in Ruhe. Das Entfernen der App unter _Remove > AI_ schließt Hermes zuerst, Gateway eingeschlossen, nimmt diese Runtime mit und behält deine Chats, Erinnerungen und die Skills, die Hermes für sich selbst geschrieben hat, es sei denn, du sagst es anders: Es fragt, standardmäßig auf Nein, ob diese Daten und deine Verbindungseinstellungen auch gehen sollen.

OpenClaws Desktop-Erfahrung ist seine Control UI, die als Web-App öffnet, gestützt auf sein eigenes lokales Gateway. OpenClaw lebt in `~/.openclaw` und aktualisiert sich selbst: Verwende den Button „Update Gateway“ der Control UI oder führe `openclaw update` aus, und das Gateway startet mit der neuen Version neu. Omarchy wählt nur das Release, mit dem eine frische Installation startet. Das Entfernen von OpenClaw unter _Remove > AI_ nimmt den Gateway-Dienst und die App mit und fragt dann, ob `~/.openclaw` auch gehen soll, da das deine Chats und Anmeldedaten neben OpenClaw selbst und den Plugin-Runtimes enthält, die es herunterlädt; der Standard behält es, und eine erneute Installation von OpenClaw nimmt es wieder auf.

Herdr Desktop ist die [Herdr](https://herdr.dev) Desktop-App: Spaces, Tabs und Panes von Terminals und Coding-Agenten, die in ihrem Kern weiterlaufen, wenn du das Fenster schließt. Sie stammt von Herdrs eigenem Installer statt von einem Paket, also lebt sie in `~/.local/share/herdr-app`, bringt ihren Kern in `~/.local/bin/herdr-core` mit, wenn du noch keinen hast, und aktualisiert beides selbst. Sie sitzt neben dem Befehl `herdr`, den Omarchy auf `Super + Ctrl + Return` ausliefert, statt ihn zu ersetzen, und bekommt die direkten Tasten dieses Befehls: `Alt + Return` und `Alt + Shift + Return` teilen ein Pane nach unten oder rechts, `Alt + Escape` schließt es, `Ctrl + Alt + Arrow` bewegt sich zwischen Panes, `Alt + 1..9` und `Alt + Left/Right` wählen einen Tab, und `Alt + Up/Down` bewegen sich zwischen Spaces. `Ctrl + 1..9` wählt einen Space und `Alt + Shift + Up/Down` geht durch Agenten. Die Präfix-Tasten `Ctrl + Space` bleiben nur fürs Terminal, da die App keine einfache Ctrl-Taste für eine Sequenz halten kann. Omarchy schreibt diese nach `~/.config/herdr-app/keys.json`, und `omarchy-refresh-herdr-app` stellt sie zurück. Ihre Installation wählt Herdrs Omarchy-Theme, das von da an deinem Omarchy-Theme folgt. Herdr behält ein Theme für den hellen Modus und eins für den dunklen, also wähle nach dem Wechsel zwischen einem dunklen und einem hellen Omarchy-Theme Omarchy in Herdrs Theme-Auswahl noch einmal für den anderen Modus.

T3 Code läuft aus seinem offiziellen AppImage-Release in `~/.local/share/t3code` statt aus einem Paket, also aktualisiert es sich selbst. Seine Installation fragt, ob du auf dem Stable- oder Nightly-Kanal starten möchtest; wechsle später in T3 Codes Einstellungen. Deine Threads und Einstellungen leben in `~/.t3`, und das Entfernen von T3 Code unter _Remove > AI_ nimmt sie mit.

### Lokale Modelle

Führe ein offenes Modell auf deiner eigenen Maschine für deine Coding-Agenten aus. Deine Prompts und dein Code bleiben auf der Maschine; nichts, was an das Modell gesendet wird, verlässt sie. Beginne mit:

```bash
omarchy agent local use best
```

Oder wähle im Agenten-Panel in der oberen Leiste + und dann Local AI, was auftaucht, wenn ein Modell auf diese Maschine passt. Beim ersten Mal installiert dies Podman, das die Modelle ausführt, und auf einer NVIDIA-Maschine NVIDIAs Container-Toolkit, das ihnen die GPU gibt. Omarchy wählt dann das empfohlene Modell für diese Maschine, lädt es herunter und startet es. Erwarte einen Download von Dutzenden GB und dass der Großteil des Speichers der Maschine in Verwendung ist, während das Modell läuft: Flash Next verwendet etwa 100 GiB mit seinem vollen 256K-Kontext. Wenn andere Modelle den Speicher belegen, den es braucht, wird es gestoppt eingerichtet, bereit zu starten, sobald du eines stoppst. Das Modell stoppt bei der Abmeldung; stoppe es selbst, wenn du den Speicher für etwas anderes brauchst.

`omarchy agent local list` zeigt die Optionen und erklärt, warum manche nicht passen. Um ein anderes einzurichten, führe `omarchy agent local use <recipe>` aus. Heute sind `qwen3.8-flash-next-gufo` und `qwen3.8-27b-gufo` für 128 GB Strix Halo-Maschinen verfügbar; das 27B nimmt etwa 40 GiB, also lässt es Raum für andere Arbeit. Neue Recipes und Empfehlungen kommen mit `omarchy update`, über das Paket.

Jedes Modell, das du einrichtest, bekommt seine eigene Zeile im Agenten-Panel, neben deinen Abonnements: Play, um es zu starten, Pause, um es zu stoppen und seinen Speicher freizugeben, und der Terminal-Button, um deinen Agenten darauf zu öffnen. Mehrere können gleichzeitig laufen, wenn sie zusammen in den Speicher passen; wenn eines nicht passt, sagt Omarchy, welches laufende Modell du stoppen sollst. Ziehe Zeilen, um sie neu zu ordnen, und drücke Delete auf einer ausgewählten Zeile, um ein Modell und seinen Download zu entfernen.

Von der Befehlszeile aus tun `omarchy agent local start <recipe>` und `omarchy agent local stop <recipe>` dasselbe, `omarchy agent local status` zeigt jedes Modell, und `omarchy agent --local` öffnet deinen Standard-Agenten auf dem letzten Modell, das du gestartet hast (pi, wenn dein Standard-Agent kein lokales Modell verwenden kann). Jeder OpenAI-kompatible Client kann sich ebenfalls verbinden: `status` zeigt die Adresse jedes Modells (die erste ist `http://127.0.0.1:11435/v1`), der Recipe-Name ist das Modell, und der Schlüssel liegt in `~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` löscht ein Modell und die Downloads, die kein anderes Modell verwendet.

Runtimes von Drittanbietern sind mit ihrem Publisher gekennzeichnet. Omarchy führt jedes Modell ohne Netzwerkzugriff aus.

### Lokale LLMs

Omarchy empfiehlt zwei Wege, lokale LLM-Modelle auszuführen: LM Studio und Ollama. LM Studio bietet eine GUI-Oberfläche, um Open-Weight-Modelle zu finden, sie zu installieren und sie auszuführen. Es ist eine großartige Möglichkeit, einfach loszulegen. Ollama bietet dafür ähnlich eine CLI. Aber wenn du neu bei lokalen Modellen bist, würde ich mit LM Studio beginnen. Du kannst beides unter _Install > AI_ im Omarchy Menu installieren.

### Der Omarchy Skill

Agent Skills helfen KI, bestimmte Tools auf eine bestimmte Weise zu verwenden, und Omarchy liefert einen Standard-Skill zum Anpassen des Systems aus. Wie deine Hyprland-Konfiguration zu tweaken, die Leiste anzupassen oder sogar ein neues Theme von Grund auf zu erstellen. Er ist in die Skill-Verzeichnisse für Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` und jedes `~/.hermes/profiles/*/skills`) und den generischen Ort `~/.agents/skills` symlinked, sodass die meisten Harnesses ihn automatisch aufgreifen.

Aber du solltest diesen Skill als experimentell behandeln. Verschiedene Modelle werden ihn mit unterschiedlicher Wirkung verwenden. Es ist am besten, zuerst im Plan-Modus zu laufen, damit du eine Vorstellung davon hast, was der Agent ändern möchte. Und sei dann bereit, Änderungen zurückzurollen oder sogar `omarchy reinstall configs` aufzurufen, wenn der Agent alles durcheinanderbringt.
