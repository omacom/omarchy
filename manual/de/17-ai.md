# AI

Omarchy enthält Starter für die unten aufgeführten Coding-Agents, ohne einen Standard für dich auszuwählen. Führe einen Befehl aus, um seine CLI bei der ersten Verwendung zu installieren, und authentifiziere dich dann, wenn du dazu aufgefordert wirst. Hermes ist die Ausnahme: Für ihn wird bei der ersten Verwendung nichts installiert, und wenn du ihn auswählst, wird Hermes Desktop installiert, wie _Desktop-Apps_ unten erklärt.

### Agents installieren und aktualisieren

Außer Hermes nutzen diese Agents mises Lazy-Installation: Beim ersten Start wird die CLI installiert, und spätere Starts nutzen sie wieder. mise prüft außerdem höchstens alle vier Stunden, ob es für einen installierten Agent eine neue Version gibt, kurz bevor er startet oder im Hintergrund an einem Shell-Prompt. Wenn dieses Update fehlschlägt oder du offline bist, läuft die installierte Version. `omarchy update` aktualisiert installierte Agents zusammen mit dem Rest von Omarchy, und `mup` aktualisiert nur mise-verwaltete Tools.

Das eigene Update-Programm eines Agents, wie `claude update`, `codex update` oder ein Update-Button in einer App, aktualisiert die mise-verwaltete Installation nicht. `codex update` schlägt fehl, und `claude update` kann Erfolg melden, während es eine separate Kopie installiert, die mise nicht verfolgt. Wenn du lieber das native Installations- und Update-Programm eines Agents verwenden möchtest, füge ihn zu `disable_tools` hinzu; siehe [Vorinstallierte CLI-Tools](18-development-tools.md#preinstalled-cli-tools).

Um alle konfigurierten Lazy-Tools zu installieren, bevor du sie brauchst, führe `mise install --include-lazy` aus. Das umfasst Omarchys andere Standard-CLI-Tools ebenso wie die Agents. Siehe [Vorinstallierte CLI-Tools](18-development-tools.md#preinstalled-cli-tools), um ein einzelnes Tool zu installieren oder deine eigene Installation zu verwenden.

`grok` wird über mises First-Party-Paket `grok` installiert, auf die gleiche Weise wie `claude` und `codex`. Führe `grok` aus oder wähle es unter _Agent > Harness_. Überspringe den `curl | bash`-Installer auf x.ai. Dieser Weg legt eine zweite Kopie in `~/.grok/bin` ab, stellt sie in `PATH` voran und überschreibt Omarchys Wrapper.

`dsh` öffnet seine Browser-Oberfläche auf `127.0.0.1:3080`, mit dem Startverzeichnis als Standard-Workspace. Seine Browser-Oberfläche nimmt keinen Start-Prompt entgegen, sodass `omarchy agent prompt` ihn mit dem Prompt in deiner Zwischenablage zum Einfügen öffnet. Omarchy startet ihn mit DeepSeeks Berechtigungs-Preset ohne Genehmigung. DeepSeek Harness lädt Sitzungsprotokolle zu DeepSeek hoch, wenn du seine offizielle Modell-API verwendest; schalte das in seiner Browser-Oberfläche unter _Settings > General > Upload Session Log_ aus. Feedback, das du ihm sendest, wird ebenfalls mit der Sitzung hochgeladen, es sei denn, du startest ihn mit `DSH_TELEMETRY_MODE=DISABLED`.

### Der Standard-Agent

Wähle deinen Standard-Agent mit `omarchy default agent <name>` oder unter _Agent > Harness_ im Omarchy Menu (`Super + Space`). Wenn der Agent noch nicht installiert ist, installiert ihn die Auswahl zuerst. Ein frisches Omarchy lädt dich mit einer einmaligen Benachrichtigung ein, diese Auswahl zu treffen.

Die Auswahl von Claude versucht auch, seine Browser-Erweiterung für Chromium, Chrome, Brave, Brave Origin und Edge einzurichten. Die Einrichtung der Erweiterung gilt für alle Benutzer und fragt möglicherweise nach deinem Systempasswort; das Abbrechen oder eine fehlgeschlagene Installation der Erweiterung wählt Claude trotzdem aus und startet ihn. Starte deinen Browser neu, aktiviere die Erweiterung, wenn du dazu aufgefordert wirst, und melde dich bei Claude an, um die Verbindung fertigzustellen. Führe `/chrome` in Claude aus, um die Verbindung zu prüfen. Firefox und Zen unterstützen diese Erweiterung nicht. Wenn Claude bereits dein Standard war, bevor diese Einrichtung hinzugefügt wurde, wähle ihn erneut, um die Erweiterung zu installieren.

Sobald du gewählt hast, startet `Super + Shift + Ctrl + A` den Standard-Agent in einem eigenen Terminalfenster (oder zeigt die Auswahl an, wenn du noch nicht gewählt hast). Du kannst ihn auch direkt in eine Aufgabe starten mit `omarchy agent prompt "Review this project"`. Freebuff und DeepSeek Harness nehmen keinen Start-Prompt entgegen, sodass sie stattdessen mit dem Prompt in deiner Zwischenablage zum Einfügen öffnen. Auf diese Weise gestartete Agents laufen unbeaufsichtigt in ihren jeweiligen Modi, in denen sie nicht anhalten, um zu fragen, also sei darauf gefasst, dass sie tatsächlich Dinge tun! MiniMax Code hat für seine interaktiven Sitzungen keinen solchen Modus, sodass er wie üblich um Berechtigungen bittet. Und da Agents sich weigern, sich Vertrauen für dein Home-Verzeichnis zu merken, starten Starts aus `$HOME` stattdessen in `~/Work`.

Es gibt auch Terminal-Kürzel: `a` führt den Standard-Agent inline im aktuellen Terminal aus, während `c`, `cx` und `cy` OpenCode, Claude Code und Codex direkt starten (wiederum in ihren automatisch genehmigenden Modi). Themenwechsel synchronisieren sich ebenfalls zu den Agents: Claude Code, Pi, OpenCode und Hermes (sobald Omarchy ihn installiert hat) machen alle mit, wenn du das Omarchy-Thema wechselst.

### Deine Agent-Anweisungen

Persönliche Regeln für jeden Agent gehören in `~/.agents/AGENTS.md`, neben die geteilten Skills in `~/.agents/skills`. Öffne sie unter _Agent > Instructions_, was sie auch in jeden Harness verlinkt, der seine eigene globale Datei behält: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, Copilots `~/.copilot/copilot-instructions.md` und so weiter. Crush und Amp lesen den Link `~/.config/AGENTS.md`, während omp, Kimi und DeepSeek Harness `~/.agents/AGENTS.md` direkt lesen. Die Auswahl eines Standard-Agents verlinkt sie ebenfalls. Eine Anweisungsdatei, die du bereits hattest, wird die geteilte, wenn es noch keine gab; andernfalls wird sie neben dem Link als `.bak` behalten. Führe `omarchy agent instructions` aus, um nach der Installation eines weiteren Agents erneut zu verlinken.

### Das Agenten-Panel

Die obere Leiste hat ein Agents-Symbol. Bevor du einen Agent eingerichtet hast, führt dich sein Panel durch die Anmeldung bei Claude, Codex oder Grok, und der erste wird dein Standard-Agent. Danach bringt das Panel jedes Abonnement auf eine Seite: jeden Agent und jedes Konto mit seinem Plan, eine Anzeige für jedes seiner Limits für 5-stündige Sitzungen und für wöchentliche Limits mit der Zeit bis zu ihrem Zurücksetzen (fahre mit der Maus darüber für den genauen Prozentsatz) oder den verbleibenden Prepaid-Restbetrag, unter einer Zeile, die durchwechselt, was du über alle hinweg verbraucht hast, wie Tokens in dieser Woche und dein am häufigsten verwendetes Modell. Unter _Make something_ bietet es Starter-Prompts für ein neues Thema, Plugin, eine neue App oder ein neues Spiel, die die Aufgabe an deinen Standard-Agent übergeben. Apps werden so gebaut, wie Omarchys eigene Hype, Monologue und Omacut gebaut werden, in C++ und Qt Quick, nach dem Agent-Skill omarchy-make-app, und der Compiler und die Qt-Teile, die sie brauchen, werden mitinstalliert. Spiele sind eine einzelne three.js-Seite in `~/Games/vibes`, nach dem Agent-Skill omarchy-make-game, und alle öffnen aus einem Game Vibes-Starter im aktuellen Thema; sie laden three.js aus dem Web, sodass sie eine Verbindung zum Starten brauchen. Claude Code, Codex, Grok, Kimi, Cursor und seine Grok Bot-Zuteilung, GitHub Copilot, Muse, Antigravity, Kimchi und Devin werden mit ihren Limits von Haus aus abgedeckt, und Hermes, Mistral Vibe und Qwen Code zeigen ihre Sitzungen und Tokens, sobald du sie verwendet hast. Anbieterpläne und Schlüssel, die du über pi, omp oder opencode verwendest, tauchen ebenfalls auf: OpenCode Zen und Go, der Z.ai GLM Coding Plan, Ollama Cloud, der MiniMax Token Plan und Synthetic mit ihren Limits; Fireworks, OpenRouter und DeepSeek mit ihren Prepaid-Restbeträgen; und die Modelle, die du auf deiner eigenen Hardware ausführst, unter Lokale Modelle. Jeder Agent wird einmal gezählt, unter dem, der ihn abrechnet, ganz gleich, durch wie viele Harnesses du ihn steuerst.

Klicke mit der linken Maustaste auf das Leistensymbol für das Panel, mit der rechten Maustaste, um deinen Standard-Agent zu starten. Die dahinterliegenden Nutzungsaufzeichnungen werden alle 15 Minuten von `omarchy agent usage-update` neu erzeugt, und das Panel kann sogar Nutzung von deinen anderen Maschinen über einen synchronisierten Ordner zusammenführen. Siehe die README unter `$OMARCHY_PATH/shell/plugins/agents/` für die vollständigen Einstellungen.

### Mehrere Abonnements

Wenn du für mehr als einen Claude-, Codex- oder Grok-Plan bezahlst — zum Beispiel einen privaten Max und einen beruflichen — kann Omarchy sie alle angemeldet halten und zwischen ihnen wechseln. Füge ein Abonnement mit dem + im Agenten-Panel hinzu, das dich direkt dort hindurchführt, oder mit `omarchy agent account add claude Work` (oder `codex` oder `grok`). Es installiert die CLI, wenn sie fehlt. Das erste Konto für einen Anbieter meldet sich über deinen normalen Browser an, genau dort, wo die CLI immer nachsieht. Jedes danach meldet sich über ein privates Fenster an, sodass das Konto, bei dem dein Browser bereits angemeldet ist, nicht versehentlich aufgegriffen wird; melde dich dort als das Konto an, das du hinzufügst, und schließe zuerst jedes private Fenster, das du bereits offen hattest. Melde dich dafür niemals aus der CLI ab: Abmelden widerruft die gespeicherte Anmeldung, und dieses Konto müsste erneut hinzugefügt werden.

Um deine Abonnement-Anmeldungen über SSH auf eine andere Omarchy-Maschine zu kopieren, führe `omarchy agent account copy user@laptop` aus. Der Absender stellt einen temporären Empfänger bereit, wenn das Ziel keinen installiert hat, sodass ältere Omarchy-Maschinen Konten ohne Update empfangen können. Installierte Empfänger haben Vorrang. Das kopiert alle Claude-, Codex- und Grok-Abonnements; füge Anbieternamen hinzu, um sie auszuwählen, wie bei `omarchy agent account copy laptop claude`. Kontonamen und Befehls-IDs stimmen mit der Quelle überein, einschließlich Konten, die auf dem Ziel bereits vorhanden sind. Nicht verwandte Zielkonten erhalten ein numerisches Suffix, wenn ihre Namen kollidieren, und Einstellungen, Skills, Plugins und Gesprächsverlauf bleiben lokal zu jeder Maschine.

Vorhandene Zielanmeldeinformationen werden behalten. Ein Quellkonto, das dort bereits angemeldet ist, bekommt seinen Namen synchronisiert, ohne seine Anmeldeinformationen zu ersetzen; andere Konten werden daneben hinzugefügt. Um gespeicherte Anmeldeinformationen für übereinstimmende Konten zu ersetzen, verwende `omarchy agent account copy --replace laptop claude`, nachdem du die Sitzungen dieses Kontos auf dem Ziel beendet hast. Ein frisches Ziel bekommt außerdem das aktive Konto und die Wechselvorlieben der Quelle; ein etabliertes Ziel behält seine eigenen.

Anmeldeinformationen reisen über SSH und werden in privaten Dateien auf dem Ziel gespeichert, also kopiere nur auf Maschinen, denen du vertraust. Das ist eine einmalige Kopie, keine laufende Synchronisierung. Codex-Refresh-Tokens können von einer anderen Maschine rotiert werden, wodurch eine kopierte Anmeldung erneuert werden muss; separate Anmeldungen bleiben die zuverlässigste Wahl für die gleichzeitige Verwendung auf mehreren Maschinen. Siehe [Codex' Anleitung zur Kontoauthentifizierung](https://developers.openai.com/codex/auth/ci-cd-auth).

Ein Konto pro Anbieter ist aktiv, und jede neue Sitzung startet als dieses: `cx`, `cy`, ein einfaches `claude`, `codex` oder `grok`, alles, was über `omarchy agent` gestartet wird, und Skripte oder Editoren, die die CLI auf `PATH` finden. Wechsle mit `omarchy agent account use work` (und zurück mit `omarchy agent account use main`) oder im Panel, indem du die Nummer eines Kontos und dann `Enter` drückst (oder auf seinen Use-Button klickst). Laufende Claude-Sitzungen wechseln ebenfalls, ab ihrer nächsten Nachricht: Jede Claude-Sitzung läuft in `~/.claude`, das immer die Anmeldung des aktiven Kontos enthält. Eine Claude-Sitzung, die von einem älteren Omarchy in einem kontoeigenen Ordner gestartet wurde, behält diese Anmeldung, bis sie beendet wird, sodass der Wechsel diese Sitzungen benennt und von selbst abschließt, sobald sie weg sind. Laufende Codex- und Grok-Sitzungen bleiben auf dem Konto, mit dem sie gestartet sind. Gesprächsverlauf, Einstellungen, Skills und Plugins werden über Konten hinweg geteilt, sodass `claude --continue` im selben Ordner dort weitermacht, wo du auf dem neuen Konto aufgehört hast.

Mit mehr als einem Konto zeigt das Panel die Limits jedes Kontos Seite an Seite, mit dem aktiven markiert. Standardmäßig benachrichtigt dich Omarchy, wenn das aktive Konto 95 % eines Limits überschreitet, und ein Klick auf die Benachrichtigung wechselt zu dem Konto mit dem meisten Spielraum. Fahre über die Zeile eines Kontos im Panel und klicke auf das Autoswitch, das neben Use erscheint (oder drücke `m`), oder führe `omarchy agent account mode auto` aus, damit es stattdessen von selbst wechselt; während es an ist, nimmt Autoswitch den Platz von Use ein, und ein erneuter Klick darauf geht zum Benachrichtigen zurück. Füge eine Zahl hinzu, um den Schwellenwert zu ändern, wie bei `omarchy agent account mode auto 90`. Wenn jedes Konto über dem Schwellenwert liegt, hörst du einmal davon, zusammen damit, welches Konto zuerst frei wird. Während ein aktives Konto innerhalb von 15 Punkten seines Schwellenwerts liegt (80 % beim Standard), werden seine Limits alle drei Minuten geprüft statt alle 15.

`omarchy agent account list` zeigt jedes Konto und seine neuesten Limits, `omarchy agent account remove work` vergisst eines, und `omarchy agent account rename primary Hey` benennt eines um (oder klicke auf den Namen eines Kontos im Panel). Diese Befehle arbeiten an den Konten deines Standard-Agents; um den anderen Anbieter zu erreichen, nenne ihn zuerst, wie bei `omarchy agent account use codex side`. Die Anmeldung, die du bereits in `~/.claude` oder `~/.codex` hattest, ist das _Main_-Konto. Die von Codex bleibt, wo sie ist; die von Claude wartet in einem eigenen Ordner, während ein anderes Konto aktiv ist. Ein Konto, das mehr als etwa acht Stunden ungenutzt gelassen wurde, kann _Sign-in required_ zeigen; klicke es, um dieses Konto direkt im Panel erneut anzumelden, oder wechsle zu ihm und starte eine Sitzung, was die Anmeldung von selbst auffrischt. MCP-Server, die du mit `claude mcp add` hinzufügst, erreichen jedes Claude-Konto, da sie alle in `~/.claude` laufen; für Codex und Grok kommen Server, die du hattest, als ein Konto hinzugefügt wurde, mit zu ihm, aber spätere erreichen nur das Konto, in dem du sie hinzugefügt hast. Claude Desktop behält eine eigene Anmeldung, und Codex- oder Grok-Tools, die mit einem absoluten Pfad zu einer CLI-Binärdatei konfiguriert sind, folgen dem Wechsel nicht. Ein explizites `CLAUDE_CONFIG_DIR`, `CODEX_HOME` oder `GROK_HOME` hat Vorrang vor dem ausgewählten Konto.

### Absturzdiagnose

Omarchy beobachtet systemd-coredump auf Prozessabstürze. Wenn etwas einen Segfault hat, bekommst du eine „Process crashed“-Benachrichtigung — klicke sie, und der Absturz wird deinem Standard-Agent übergeben, zusammen mit Omarchys Skill diagnose-crash, der den Agent dabei hindurchführt, die Fakten aus dem Core Dump zu ermitteln und zu entscheiden, ob der Absturz es wert ist, ihn upstream zu melden. Du kannst ihn auch von Hand gegen jede PID aus `coredumpctl list` mit `omarchy agent crash <pid>` ausführen.

Die Beobachtung ist standardmäßig an. Schalte sie unter _Trigger > Toggle > Crash Capture_ aus (oder mit `omarchy toggle crash-capture`), und die Benachrichtigungen hören auf; `omarchy agent crash <pid>` funktioniert weiterhin von Hand.

Abstürze können auch ein Programm nach dem anderen stummgeschaltet werden, was dir die Diagnose am Ende anbietet. `omarchy crash mute hyprland` stoppt die Benachrichtigungen nur für dieses Programm, `omarchy crash mute hyprland off` bringt sie zurück, und `omarchy crash mute` für sich allein listet auf, was du stummgeschaltet hast. Es nimmt den Pfad der Binärdatei genauso bereitwillig wie ihren Namen, sodass `omarchy crash mute /usr/bin/hyprland` dasselbe tut. Setze einen Namen mit einem Leerzeichen darin in Anführungszeichen, wie bei `omarchy crash mute 'Some App'`. Alles andere benachrichtigt weiterhin, und das stummgeschaltete Programm stürzt weiterhin ab — das versteckt die Erinnerung, es repariert nichts.

### Desktop-Apps

Das Menü _Install > AI_ führt auch ein paar grafische AI-Apps: Antigravity Desktop, die Desktop-App von ChatGPT, die Desktop-App von Claude (Anthropics Linux-Beta, mit Chat-, Cowork- und Claude Code-Tabs), Grok Bot, um mit xAIs Modellen zu chatten, Herdr Desktop, Hermes Desktop, OpenClaw, die Desktop-App von Perplexity und T3 Code. Grok Bot ist die Desktop-Chat-App. Der Coding-Agent ist der Befehl `grok`.

Hermes Desktop ist der, den du kennen solltest, denn eine Maschine hat ein Hermes, und es gehört der App: Hermes wird nur jemals über die App installiert, und der Befehl `hermes`, den der Standard-Agent ausführt, gehört der App. Hermes als Standard-Agent auszuwählen installiert dasselbe wie der Eintrag _Install > AI_: das Paket und eine Hermes-Laufzeitumgebung unter `~/.hermes`, die von Hermes' eigenem Installer eingerichtet wird, was beim ersten Mal ein paar Minuten dauert. Diese Laufzeitumgebung ist das eine Hermes, das der Terminal-Befehl `hermes`, der Standard-Agent und die App alle verwenden, und sie aktualisiert sich selbst mit `hermes update`, statt auf ein Omarchy-Release zu warten. Ihre Installation übergibt Hermes auch das Omarchy-Thema als Skin namens `omarchy`, dem jede Hermes-Oberfläche folgt, während du Themen wechselst; wähle einen anderen unter Hermes' Appearance-Einstellungen oder mit `/skin`, wenn du das lieber nicht möchtest, und Omarchy lässt diese Wahl in Ruhe. Das Entfernen der App unter _Remove > AI_ schließt zuerst Hermes, Gateway eingeschlossen, nimmt diese Laufzeitumgebung mit und behält deine Chats, Erinnerungen und die Skills, die Hermes für sich selbst geschrieben hat, es sei denn, du sagst ihm etwas anderes: Es fragt, mit Nein als Standard, ob diese Daten und deine Verbindungseinstellungen ebenfalls gehen sollen.

OpenClaws Desktop-Erlebnis ist seine Control UI, die als Web-App öffnet, gestützt von seinem eigenen lokalen Gateway. OpenClaw lebt in `~/.openclaw` und aktualisiert sich selbst: Verwende die Schaltfläche „Update Gateway“ der Control UI oder führe `openclaw update` aus, und das Gateway startet mit der neuen Version neu. Omarchy wählt nur das Release, mit dem eine frische Installation startet. Das Entfernen von OpenClaw unter _Remove > AI_ nimmt den Gateway-Dienst und die App mit und fragt dann, ob `~/.openclaw` ebenfalls gehen soll, da das deine Chats und Anmeldeinformationen neben OpenClaw selbst und den Plugin-Laufzeitumgebungen enthält, die es herunterlädt; der Standard behält es, und die erneute Installation von OpenClaw greift es wieder auf.

Herdr Desktop ist die Desktop-App von [Herdr](https://herdr.dev): Spaces, Tabs und Panes von Terminals und Coding-Agents, die in seinem Kern weiterlaufen, wenn du das Fenster schließt. Sie kommt aus Herdrs eigenem Installer statt aus einem Paket, sodass sie in `~/.local/share/herdr-app` lebt, ihren Kern in `~/.local/bin/herdr-core` mitbringt, wenn du noch keinen hast, und beides selbst aktualisiert. Sie sitzt neben dem Befehl `herdr`, den Omarchy auf `Super + Ctrl + Return` liefert, statt ihn zu ersetzen, und bekommt die direkten Tasten dieses Befehls: `Alt + Return` und `Alt + Shift + Return` teilen ein Pane nach unten oder nach rechts, `Alt + Escape` schließt es, `Ctrl + Alt + Arrow` bewegt sich zwischen Panes, `Alt + 1..9` und `Alt + Left/Right` wählen einen Tab, und `Alt + Up/Down` bewegen sich zwischen Spaces. `Ctrl + 1..9` wählt einen Space und `Alt + Shift + Up/Down` schreitet durch Agents. Die Prefix-Tasten `Ctrl + Space` bleiben nur fürs Terminal, da die App keine einfache Ctrl-Taste für eine Sequenz halten kann. Omarchy schreibt diese nach `~/.config/herdr-app/keys.json`, und `omarchy-refresh-herdr-app` stellt sie zurück. Ihre Installation wählt Herdrs Omarchy-Thema, das von da an deinem Omarchy-Thema folgt. Herdr behält ein Thema für den hellen Modus und eines für den dunklen, sodass du, nach dem Wechsel zwischen einem dunklen und einem hellen Omarchy-Thema, Omarchy in Herdrs Themenauswahl noch einmal für den anderen Modus wählst.

T3 Code läuft aus seinem offiziellen AppImage-Release in `~/.local/share/t3code` statt aus einem Paket, sodass es sich selbst aktualisiert. Seine Installation fragt, ob auf dem Stable- oder Nightly-Kanal gestartet werden soll; wechsle später in T3 Codes Einstellungen. Deine Threads und Einstellungen leben in `~/.t3`, und das Entfernen von T3 Code unter _Remove > AI_ nimmt sie mit.

### Lokale Modelle

Führe ein offenes Modell auf deiner eigenen Maschine für deine Coding-Agents aus. Deine Prompts und dein Code bleiben auf der Maschine; nichts, was an das Modell gesendet wird, verlässt sie. Beginne mit:

```bash
omarchy agent local use best
```

Oder wähle im Agenten-Panel in der oberen Leiste + und dann Local AI, das erscheint, wenn ein Modell auf diese Maschine passt. Beim ersten Mal installiert das Podman, das die Modelle ausführt, und auf einer NVIDIA-Maschine NVIDIAs Container-Toolkit, das ihnen die GPU gibt. Omarchy wählt dann das empfohlene Modell für diese Maschine, lädt es herunter und startet es. Erwarte einen Download von Dutzenden GB und dass der Großteil des Speichers der Maschine in Verwendung ist, während das Modell läuft: Flash Next verwendet etwa 100 GiB mit seinem vollen 256K-Kontext. Wenn andere Modelle den Speicher halten, den es braucht, wird es gestoppt eingerichtet, bereit zu starten, sobald du eines stoppst. Das Modell stoppt beim Abmelden; stoppe es selbst, wenn du den Speicher für etwas anderes brauchst.

`omarchy agent local list` zeigt die Optionen und erklärt, warum manche nicht passen. Um ein weiteres einzurichten, führe `omarchy agent local use <recipe>` aus. Heute sind `qwen3.8-flash-next-gufo` und `qwen3.8-27b-gufo` für 128 GB Strix Halo-Maschinen verfügbar; das 27B nimmt etwa 40 GiB, sodass es Raum für andere Arbeit lässt. Auf einem 64 GB Laptop mit Intels Arc B390 läuft `qwen3.6-35b-a3b-llamacpp` in etwa 30 GiB. Neue Recipes und Empfehlungen kommen mit `omarchy update`, über das Paket.

Jedes Modell, das du einrichtest, bekommt seine eigene Zeile im Agenten-Panel, neben deinen Abonnements: Abspielen, um es zu starten, Pause, um es zu stoppen und seinen Speicher freizugeben, und die Terminal-Schaltfläche, um deinen Agent darauf zu öffnen. Mehrere können gleichzeitig laufen, wenn sie zusammen in den Speicher passen; wenn eines nicht passt, sagt Omarchy, welches laufende Modell du stoppen sollst. Ziehe Zeilen, um sie neu zu ordnen, und drücke Delete auf einer ausgewählten Zeile, um ein Modell und seinen Download zu entfernen.

Jedes Modell, das du einrichtest, bekommt auch seinen eigenen Eintrag im App-Starter, unter dem Namen des Modells und mit dem Logo seines Herstellers, so wie die Anmeldung bei Claude, Codex oder Grok einen hinzufügt. Er öffnet deinen Agent auf diesem Modell und startet das Modell zuerst, wenn es nicht läuft: Das Terminal zeigt, wie es lädt, und übergibt an den Agent, sobald es bereit ist. Das Entfernen eines Modells entfernt seinen Eintrag.

Ein Modell läuft weiterhin genau so, wie es eingerichtet wurde, sodass ein Omarchy-Update niemals eines unter deinen Agents neu startet. Wenn Omarchy eine neuere Laufzeitumgebung oder neuere Gewichte für ein Modell hat, das du eingerichtet hast, zeigt seine Zeile eine Update-Schaltfläche: Drücke sie, und das Modell wird im Hintergrund erneut eingerichtet, lädt nur herunter, was sich geändert hat, und startet mit der neuen Version neu. Ein Modell, das gestoppt war, bleibt gestoppt. `omarchy agent local update` tut dasselbe für jedes Modell von einem Terminal aus.

Von der Befehlszeile aus tun `omarchy agent local start <recipe>` und `omarchy agent local stop <recipe>` dasselbe, `omarchy agent local status` zeigt jedes Modell, und `omarchy agent --local` öffnet deinen Standard-Agent auf dem letzten Modell, das du gestartet hast. pi, OpenCode und Qwen Code können eines verwenden; bei jedem anderen Standard öffnet es in pi. pi listet auch jedes Modell, das du eingerichtet hast, und die auf Maschinen, mit denen du gepaart hast, in seiner eigenen Modellauswahl, sodass einfaches `pi` sie ebenfalls erreicht. Jeder OpenAI-kompatible Client kann sich ebenfalls verbinden: `status` zeigt die Adresse jedes Modells (die erste ist `http://127.0.0.1:11435/v1`), der Recipe-Name ist das Modell, und der Schlüssel liegt in `~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` löscht ein Modell und die Downloads, die kein anderes Modell verwendet.

Laufzeitumgebungen von Drittanbietern sind mit ihrem Herausgeber gekennzeichnet. Omarchy führt jedes Modell ohne Netzwerkzugriff aus.

### Lokale LLMs

Omarchy empfiehlt zwei Wege, lokale LLM-Modelle auszuführen: LM Studio und Ollama. LM Studio bietet eine GUI-Oberfläche, um offen gewichtete Modelle zu finden, sie zu installieren und auszuführen. Es ist ein großartiger Weg, einfach loszulegen. Ollama bietet eine CLI, um dasselbe auf ähnliche Weise zu tun. Aber wenn du neu bei lokalen Modellen bist, würde ich mit LM Studio anfangen. Du kannst beides unter _Install > AI_ im Omarchy Menu installieren.

### Der Omarchy Skill

Agent-Skills helfen AI, bestimmte Tools auf eine bestimmte Weise zu verwenden, und Omarchy liefert einen Standard-Skill, um das System maßzuschneidern. Wie deine Hyprland-Konfiguration zu tweaken, die Leiste anzupassen oder sogar ein neues Thema von Grund auf zu erstellen. Er ist in die Skill-Verzeichnisse für Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` und jedes `~/.hermes/profiles/*/skills`) und den generischen Ort `~/.agents/skills` symlinkt, sodass die meisten Harnesses ihn automatisch aufgreifen.

Aber du solltest diesen Skill als experimentell behandeln. Verschiedene Modelle werden ihn mit unterschiedlicher Wirkung verwenden. Es ist am besten, zuerst im Plan-Modus zu laufen, sodass du eine Vorstellung davon hast, was der Agent gern ändern würde. Und sei dann bereit, Änderungen zurückzurollen oder sogar `omarchy reinstall configs` aufzurufen, wenn der Agent aus allem ein Chaos macht.
