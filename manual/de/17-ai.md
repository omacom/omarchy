# AI

Omarchy enthält Launcher für die unten aufgeführten Coding-Agenten, ohne einen Standard für dich auszuwählen. Führe einen Befehl aus, um dessen CLI bei der ersten Verwendung zu installieren, und authentifiziere dich dann, wenn du dazu aufgefordert wirst. Hermes ist die Ausnahme: Dafür wird bei der ersten Verwendung nichts installiert, und wenn du es auswählst, wird Hermes Desktop installiert, wie _Desktop-Apps_ weiter unten erklärt.

### Agenten installieren und aktualisieren

Mit Ausnahme von Hermes verwenden diese Agenten die Lazy-Installation von mise: Beim ersten Start wird die CLI installiert, und spätere Starts verwenden sie wieder. mise prüft außerdem höchstens einmal alle vier Stunden, ob es für einen installierten Agenten eine neue Version gibt, kurz vor dessen Start oder im Hintergrund an einem Shell-Prompt. Wenn dieses Update fehlschlägt oder du offline bist, läuft die installierte Version. `omarchy update` aktualisiert installierte Agenten zusammen mit dem Rest von Omarchy, und `mup` aktualisiert nur von mise verwaltete Tools.

Das eigene Update-Programm eines Agenten, wie `claude update`, `codex update` oder ein Update-Button in einer App, aktualisiert die von mise verwaltete Installation nicht. `codex update` schlägt fehl, und `claude update` kann Erfolg melden, während es eine separate Kopie installiert, die mise nicht verfolgt. Wenn du lieber das native Installations- und Update-Programm eines Agenten verwenden willst, füge ihn zu `disable_tools` hinzu; siehe [Vorinstallierte CLI-Tools](18-development-tools.md#preinstalled-cli-tools).

Um alle konfigurierten Lazy-Tools zu installieren, bevor du sie brauchst, führe `mise install --include-lazy` aus. Dies umfasst auch Omarchys andere Standard-CLI-Tools sowie die Agenten. Siehe [Vorinstallierte CLI-Tools](18-development-tools.md#preinstalled-cli-tools), um ein einzelnes Tool zu installieren oder deine eigene Installation zu verwenden.

`grok` wird über mises First-Party-Paket `grok` installiert, auf die gleiche Weise wie `claude` und `codex`. Führe `grok` aus oder wähle es unter _Agent > Harness_ aus. Überspringe das `curl | bash`-Installationsprogramm auf x.ai. Dieser Weg legt eine zweite Kopie in `~/.grok/bin` ab, stellt sie auf dem `PATH` voran und überschreibt Omarchys Wrapper.

`dsh` öffnet seine Browser-UI auf `127.0.0.1:3080`, mit dem Startverzeichnis als Standard-Workspace. Seine Browser-UI nimmt keinen Start-Prompt entgegen, deshalb öffnet `omarchy agent prompt` ihn mit dem Prompt in deiner Zwischenablage zum Einfügen. Omarchy startet ihn mit DeepSeeks Berechtigungs-Preset ohne Genehmigung. DeepSeek Harness lädt Sitzungsprotokolle zu DeepSeek hoch, wenn du seine offizielle Modell-API verwendest; schalte das unter _Settings > General > Upload Session Log_ in seiner Browser-UI aus. Feedback, das du ihm sendest, wird ebenfalls mit der Sitzung hochgeladen, es sei denn, du startest ihn mit `DSH_TELEMETRY_MODE=DISABLED`.

### Der Standardagent

Wähle deinen Standardagenten mit `omarchy default agent <name>` oder unter _Agent > Harness_ im Omarchy Menu (`Super + Space`). Wenn der Agent noch nicht installiert ist, installiert ihn die Auswahl zuerst. Ein frisches Omarchy lädt dich mit einer einmaligen Benachrichtigung dazu ein, diese Auswahl zu treffen.

Die Auswahl von Claude versucht auch, seine Browser-Erweiterung für Chromium, Chrome, Brave, Brave Origin und Edge einzurichten. Die Einrichtung der Erweiterung gilt für alle Benutzer und fragt möglicherweise nach deinem Systempasswort; Abbrechen oder eine fehlgeschlagene Installation der Erweiterung wählt Claude dennoch aus und startet ihn. Starte deinen Browser neu, aktiviere die Erweiterung, wenn du dazu aufgefordert wirst, und melde dich bei Claude an, um die Verbindung fertigzustellen. Führe `/chrome` in Claude aus, um die Verbindung zu prüfen. Firefox und Zen unterstützen diese Erweiterung nicht. Wenn Claude bereits dein Standard war, bevor diese Einrichtung hinzugefügt wurde, wähle ihn erneut aus, um die Erweiterung zu installieren.

Sobald du gewählt hast, startet `Super + Shift + Ctrl + A` den Standardagenten in einem eigenen Terminalfenster (oder öffnet den Picker, wenn du noch nicht gewählt hast). Du kannst ihn auch direkt in eine Aufgabe starten mit `omarchy agent prompt "Review this project"`. Freebuff und DeepSeek Harness nehmen keinen Start-Prompt entgegen, deshalb öffnen sie stattdessen mit dem Prompt in deiner Zwischenablage zum Einfügen. Auf diese Weise gestartete Agenten laufen unbeaufsichtigt in ihren jeweiligen Modi, in denen sie nicht anhalten, um zu fragen, also sei bereit, dass sie tatsächlich Dinge tun! MiniMax Code hat keinen solchen Modus für seine interaktiven Sitzungen, deshalb fragt er wie üblich nach Berechtigungen. Und da Agenten sich weigern, Vertrauen für dein Home-Verzeichnis zu speichern, starten Starts aus `$HOME` stattdessen in `~/Work`.

Es gibt auch Terminal-Kürzel: `a` führt den Standardagenten inline im aktuellen Terminal aus, während `c`, `cx` und `cy` OpenCode, Claude Code und Codex direkt starten (wieder in ihren automatisch genehmigenden Modi). Themenwechsel synchronisieren sich ebenfalls zu den Agenten: Claude Code, Pi, OpenCode und Hermes (sobald Omarchy ihn installiert hat) machen alle mit, wenn du das Omarchy-Thema wechselst.

### Deine Agenten-Anweisungen

Persönliche Regeln für jeden Agenten gehören in `~/.agents/AGENTS.md`, neben die gemeinsamen Skills in `~/.agents/skills`. Öffne sie unter _Agent > Instructions_, was sie auch in jedes Harness verlinkt, das seine eigene globale Datei führt: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, Copilots `~/.copilot/copilot-instructions.md` und so weiter. Crush und Amp lesen den Link `~/.config/AGENTS.md`, während omp, Kimi und DeepSeek Harness `~/.agents/AGENTS.md` direkt lesen. Die Auswahl eines Standardagenten verlinkt sie ebenfalls. Eine Anweisungsdatei, die du bereits hattest, wird zur gemeinsamen, wenn es noch keine gab; andernfalls wird sie neben dem Link als `.bak` behalten. Führe `omarchy agent instructions` aus, um nach der Installation eines weiteren Agenten neu zu verlinken.

### Das Agenten-Panel

Die obere Leiste hat ein Agenten-Symbol. Bevor du einen Agenten eingerichtet hast, führt dich sein Panel durch die Anmeldung bei Claude, Codex oder Grok, und der erste wird dein Standardagent. Danach stellt das Panel jedes Abonnement auf eine Seite: jeden Agenten und jedes Konto mit seinem Tarif, eine Anzeige für jedes seiner 5-Stunden-Sitzungslimits und wöchentlichen Limits mit der Zeit bis zum Zurücksetzen (fahre mit der Maus darüber für den genauen Prozentsatz) oder das verbleibende Prepaid-Guthaben, unter einer Zeile, die durchwechselt, was du über alle hinweg verwendet hast, wie Tokens in dieser Woche und dein am meisten verwendetes Modell. Unter _Make something_ bietet es Starter-Prompts für ein neues Thema, Plugin, eine App oder ein Spiel, die die Aufgabe an deinen Standardagenten übergeben. Apps werden so gebaut, wie Omarchys eigene Hype, Monologue und Omacut, in C++ und Qt Quick, nach dem omarchy-app Agent Skill, und der Compiler und die Qt-Teile, die sie brauchen, sind installiert. Spiele sind eine einzelne three.js-Seite in `~/Games/vibes`, nach dem web-game Agent Skill, und alle öffnen sich aus einem Game Vibes Launcher im aktuellen Thema; sie laden three.js aus dem Web, deshalb brauchen sie eine Verbindung zum Starten. Claude Code, Codex, Grok, Kimi, Cursor und sein Grok Bot-Kontingent, GitHub Copilot, Muse, Antigravity, Kimchi und Devin sind mit ihren Limits sofort abgedeckt, und Hermes, Mistral Vibe und Qwen Code zeigen ihre Sitzungen und Tokens, sobald du sie verwendet hast. Provider-Tarife und Schlüssel, die du über pi, omp oder opencode verwendest, tauchen ebenfalls auf: OpenCode Zen und Go, der Z.ai GLM Coding Plan, Ollama Cloud, der MiniMax Token Plan und Synthetic mit ihren Limits; Fireworks, OpenRouter und DeepSeek mit ihren Prepaid-Guthaben; und die Modelle, die du auf deiner eigenen Hardware laufen lässt, unter Lokale Modelle. Jeder Agent wird einmal gezählt, unter dem, der ihn abrechnet, egal durch wie viele Harnesses du ihn betreibst.

Klicke mit der linken Maustaste auf das Leistensymbol für das Panel, mit der rechten, um deinen Standardagenten zu starten. Die dahinterliegenden Nutzungsaufzeichnungen werden alle 15 Minuten durch `omarchy agent usage-update` neu erstellt, und das Panel kann sogar Nutzung von deinen anderen Maschinen über einen synchronisierten Ordner zusammenführen. Siehe die README unter `$OMARCHY_PATH/shell/plugins/agents/` für alle Einstellungen.

### Mehrere Abonnements

Wenn du für mehr als einen Claude-, Codex- oder Grok-Tarif bezahlst — sagen wir einen persönlichen Max und einen beruflichen — kann Omarchy sie alle angemeldet halten und zwischen ihnen wechseln. Füge ein Abonnement mit dem + im Agenten-Panel hinzu, das dich direkt dort hindurchführt, oder mit `omarchy agent account add claude Work` (oder `codex` oder `grok`). Es installiert die CLI, wenn sie fehlt. Das erste Konto für einen Provider meldet sich über deinen normalen Browser an, genau dort, wo die CLI immer sucht. Jedes danach meldet sich über ein privates Fenster an, damit das Konto, bei dem dein Browser bereits angemeldet ist, nicht versehentlich übernommen wird; melde dich dort als das Konto an, das du hinzufügst, und schließe vorher jedes private Fenster, das du bereits offen hast. Melde dich dafür niemals aus der CLI ab: Abmelden widerruft die gespeicherte Anmeldung, und dieses Konto müsste erneut hinzugefügt werden.

Um deine Abonnement-Anmeldungen über SSH auf eine andere Omarchy-Maschine zu kopieren, führe `omarchy agent account copy user@laptop` aus. Der Sender stellt einen temporären Empfänger bereit, wenn das Ziel keinen installiert hat, sodass ältere Omarchy-Maschinen Konten ohne ein Update empfangen können. Installierte Empfänger haben Vorrang. Dies kopiert alle Claude-, Codex- und Grok-Abonnements; füge Provider-Namen hinzu, um sie auszuwählen, wie bei `omarchy agent account copy laptop claude`. Kontonamen und Befehls-IDs stimmen mit der Quelle überein, auch bei Konten, die bereits auf dem Ziel vorhanden sind. Nicht verwandte Zielkonten erhalten ein numerisches Suffix, wenn ihre Namen kollidieren, und Einstellungen, Skills, Plugins und Gesprächsverlauf bleiben lokal auf jeder Maschine.

Vorhandene Ziel-Anmeldedaten bleiben erhalten. Ein Quellkonto, das dort bereits angemeldet ist, bekommt seinen Namen synchronisiert, ohne seine Anmeldedaten zu ersetzen; andere Konten werden daneben hinzugefügt. Um gespeicherte Anmeldedaten für übereinstimmende Konten zu ersetzen, verwende `omarchy agent account copy --replace laptop claude`, nachdem du die Sitzungen dieses Kontos auf dem Ziel beendet hast. Ein frisches Ziel erhält auch das aktive Konto und die Wechsel-Einstellungen der Quelle; ein etabliertes Ziel behält seine eigenen.

Anmeldedaten reisen über SSH und werden auf dem Ziel in privaten Dateien gespeichert, kopiere also nur auf Maschinen, denen du vertraust. Dies ist eine einmalige Kopie, keine laufende Synchronisierung. Codex-Aktualisierungs-Tokens können von einer anderen Maschine rotiert werden, wodurch eine kopierte Anmeldung erneuert werden muss; separate Anmeldungen bleiben die zuverlässigste Wahl für gleichzeitige Verwendung auf mehreren Maschinen. Siehe [Codex' Anleitung zur Kontoauthentifizierung](https://developers.openai.com/codex/auth/ci-cd-auth).

Ein Konto pro Provider ist aktiv, und jede neue Sitzung startet als dieses: `cx`, `cy`, ein einfaches `claude`, `codex` oder `grok`, alles, was über `omarchy agent` gestartet wird, und Skripte oder Editoren, die die CLI auf dem `PATH` finden. Wechsle mit `omarchy agent account use work` (und zurück mit `omarchy agent account use main`) oder im Panel, indem du die Nummer eines Kontos und dann `Enter` drückst (oder auf seinen Use-Button klickst). Laufende Claude-Sitzungen wechseln ebenfalls, ab ihrer nächsten Nachricht: Jede Claude-Sitzung läuft in `~/.claude`, was immer die Anmeldung des aktiven Kontos enthält. Eine Claude-Sitzung, die von einem älteren Omarchy im eigenen Ordner eines Kontos gestartet wurde, behält diese Anmeldung, bis sie beendet wird, deshalb benennt der Wechsel diese Sitzungen und beendet sich von selbst, sobald sie weg sind. Laufende Codex- und Grok-Sitzungen bleiben bei dem Konto, mit dem sie gestartet sind. Gesprächsverlauf, Einstellungen, Skills und Plugins werden über Konten hinweg geteilt, deshalb macht `claude --continue` im selben Ordner auf dem neuen Konto dort weiter, wo du aufgehört hast.

Mit mehr als einem Konto zeigt das Panel die Limits jedes Kontos nebeneinander, mit dem aktiven markiert. Standardmäßig benachrichtigt dich Omarchy, wenn das aktive Konto 95% eines Limits überschreitet, und ein Klick auf die Benachrichtigung wechselt zu dem Konto mit dem meisten Spielraum. Fahre mit der Maus über die Zeile eines Kontos im Panel und klicke auf das Autoswitch, das neben Use erscheint (oder drücke `m`), oder führe `omarchy agent account mode auto` aus, damit es stattdessen von selbst wechselt; während es an ist, nimmt Autoswitch den Platz von Use ein, und ein erneuter Klick darauf kehrt zum Benachrichtigen zurück. Füge eine Zahl hinzu, um den Schwellenwert zu ändern, wie bei `omarchy agent account mode auto 90`. Wenn jedes Konto über dem Schwellenwert liegt, hörst du einmal davon, zusammen damit, welches Konto zuerst frei wird. Während ein aktives Konto innerhalb von 15 Punkten seines Schwellenwerts liegt (80% beim Standard), werden seine Limits alle drei Minuten statt alle 15 geprüft.

`omarchy agent account list` zeigt jedes Konto und seine neuesten Limits, `omarchy agent account remove work` vergisst eines, und `omarchy agent account rename primary Hey` benennt eines um (oder klicke auf den Namen eines Kontos im Panel). Diese Befehle arbeiten mit den Konten deines Standardagenten; um den anderen Provider zu erreichen, nenne ihn zuerst, wie bei `omarchy agent account use codex side`. Die Anmeldung, die du bereits in `~/.claude` oder `~/.codex` hattest, ist das _Main_-Konto. Codex' bleibt, wo sie ist; Claudes wartet in einem eigenen Ordner, während ein anderes Konto aktiv ist. Ein Konto, das länger als etwa acht Stunden ungenutzt blieb, kann _Sign-in required_ zeigen; klicke darauf, um dieses Konto direkt im Panel erneut anzumelden, oder wechsle zu ihm und starte eine Sitzung, was die Anmeldung von selbst auffrischt. MCP-Server, die du mit `claude mcp add` hinzufügst, erreichen jedes Claude-Konto, da sie alle in `~/.claude` laufen; bei Codex und Grok kommen Server, die du hattest, als ein Konto hinzugefügt wurde, mit zu ihm, aber spätere erreichen nur das Konto, in dem du sie hinzugefügt hast. Claude Desktop behält eine eigene Anmeldung, und Codex- oder Grok-Tools, die mit einem absoluten Pfad zu einer CLI-Binärdatei konfiguriert sind, folgen dem Wechsel nicht. Ein explizites `CLAUDE_CONFIG_DIR`, `CODEX_HOME` oder `GROK_HOME` hat Vorrang vor dem ausgewählten Konto.

### Absturzdiagnose

Omarchy beobachtet systemd-coredump auf Prozessabstürze. Wenn etwas segfaultet, erhältst du eine "Process crashed"-Benachrichtigung — klicke darauf, und der Absturz wird an deinen Standardagenten übergeben, zusammen mit Omarchys diagnose-crash Skill, der den Agenten dadurch führt, die Fakten aus dem Core Dump festzustellen und zu entscheiden, ob der Absturz es wert ist, upstream gemeldet zu werden. Du kannst ihn auch von Hand gegen jede PID aus `coredumpctl list` mit `omarchy agent crash <pid>` ausführen.

Die Beobachtung ist standardmäßig an. Schalte sie unter _Trigger > Toggle > Crash Capture_ aus (oder mit `omarchy toggle crash-capture`), und die Benachrichtigungen hören auf; `omarchy agent crash <pid>` funktioniert weiterhin von Hand.

Abstürze können auch einzeln pro Programm stummgeschaltet werden, was die Diagnose dir am Ende anbietet. `omarchy crash mute hyprland` stoppt die Benachrichtigungen nur für dieses Programm, `omarchy crash mute hyprland off` bringt sie zurück, und `omarchy crash mute` allein listet auf, was du stummgeschaltet hast. Es nimmt den Pfad der Binärdatei genauso gern wie ihren Namen, sodass `omarchy crash mute /usr/bin/hyprland` das Gleiche tut. Setze einen Namen mit einem Leerzeichen in Anführungszeichen, wie bei `omarchy crash mute 'Some App'`. Alles andere benachrichtigt weiterhin, und das stummgeschaltete Programm stürzt weiterhin ab — dies verbirgt die Erinnerung, es behebt nichts.

### Desktop-Apps

Das Menü _Install > AI_ enthält auch einige grafische AI-Apps: die ChatGPT Desktop-App, die Claude Desktop-App (Anthropics Linux-Beta, mit Chat-, Cowork- und Claude Code-Tabs), Grok Bot zum Chatten mit xAIs Modellen, Herdr Desktop, Hermes Desktop, OpenClaw, die Perplexity Desktop-App und T3 Code. Grok Bot ist die Desktop-Chat-App. Der Coding-Agent ist der `grok`-Befehl.

Hermes Desktop ist diejenige, die du kennen solltest, denn eine Maschine hat ein Hermes, und es ist das der App: Hermes wird nur jemals über die App installiert, und der `hermes`-Befehl, den der Standardagent ausführt, ist der der App. Hermes als Standardagenten auszuwählen installiert das Gleiche wie der Eintrag _Install > AI_: das Paket und eine Hermes-Laufzeitumgebung unter `~/.hermes`, eingerichtet durch Hermes' eigenes Installationsprogramm, was beim ersten Mal ein paar Minuten dauert. Diese Laufzeitumgebung ist das eine Hermes, das der Terminal-`hermes`-Befehl, der Standardagent und die App alle verwenden, und sie aktualisiert sich selbst mit `hermes update`, statt auf ein Omarchy-Release zu warten. Ihre Installation übergibt Hermes auch das Omarchy-Thema als Skin namens `omarchy`, dem jede Hermes-Oberfläche folgt, wenn du Themen wechselst; wähle einen anderen unter Hermes' Appearance-Einstellungen oder mit `/skin`, wenn du das lieber nicht willst, und Omarchy lässt diese Wahl in Ruhe. Das Entfernen der App unter _Remove > AI_ schließt Hermes zuerst, Gateway eingeschlossen, nimmt diese Laufzeitumgebung mit und behält deine Chats, Erinnerungen und die Skills, die Hermes für sich selbst geschrieben hat, es sei denn, du sagst ihm etwas anderes: Es fragt, mit Nein als Standard, ob diese Daten und deine Verbindungseinstellungen auch weg sollen.

OpenClaws Desktop-Erlebnis ist seine Control UI, die sich als Web-App öffnet, gestützt durch sein eigenes lokales Gateway. OpenClaw lebt in `~/.openclaw` und aktualisiert sich selbst: Verwende den "Update Gateway"-Button der Control UI oder führe `openclaw update` aus, und das Gateway startet auf der neuen Version neu. Omarchy wählt nur das Release, mit dem eine frische Installation startet. Das Entfernen von OpenClaw unter _Remove > AI_ nimmt den Gateway-Dienst und die App mit und fragt dann, ob `~/.openclaw` auch weg soll, da das deine Chats und Anmeldedaten neben OpenClaw selbst und den Plugin-Laufzeitumgebungen enthält, die es herunterlädt; der Standard behält es, und eine erneute Installation von OpenClaw greift es wieder auf.

Herdr Desktop ist die [Herdr](https://herdr.dev) Desktop-App: Spaces, Tabs und Panes von Terminals und Coding-Agenten, die in ihrem Kern weiterlaufen, wenn du das Fenster schließt. Sie kommt von Herdrs eigenem Installationsprogramm statt aus einem Paket, deshalb lebt sie in `~/.local/share/herdr-app`, bringt ihren Kern in `~/.local/bin/herdr-core` mit, wenn du noch keinen hast, und aktualisiert beides selbst. Sie sitzt neben dem `herdr`-Befehl, den Omarchy auf `Super + Ctrl + Return` liefert, statt ihn zu ersetzen, und bekommt die direkten Tasten dieses Befehls: `Alt + Return` und `Alt + Shift + Return` teilen ein Pane nach unten oder rechts, `Alt + Escape` schließt es, `Ctrl + Alt + Arrow` bewegt sich zwischen Panes, `Alt + 1..9` und `Alt + Left/Right` wählen einen Tab, und `Alt + Up/Down` bewegen sich zwischen Spaces. `Ctrl + 1..9` wählt einen Space und `Alt + Shift + Up/Down` geht durch Agenten. Die `Ctrl + Space`-Präfix-Tasten bleiben nur fürs Terminal, da die App eine einfache Ctrl-Taste nicht für eine Sequenz halten kann. Omarchy schreibt diese nach `~/.config/herdr-app/keys.json`, und `omarchy-refresh-herdr-app` stellt sie wieder her. Ihre Installation wählt Herdrs Omarchy-Thema, das von da an deinem Omarchy-Thema folgt. Herdr behält ein Thema für den hellen Modus und eins für den dunklen, deshalb wähle nach dem Wechsel zwischen einem dunklen und einem hellen Omarchy-Thema Omarchy in Herdrs Themen-Picker noch einmal für den anderen Modus.

T3 Code läuft aus seinem offiziellen AppImage-Release in `~/.local/share/t3code` statt aus einem Paket, deshalb aktualisiert es sich selbst. Seine Installation fragt dich, ob du auf dem Stable- oder Nightly-Kanal starten willst; wechsle später in T3 Codes Einstellungen. Deine Threads und Einstellungen leben in `~/.t3`, und das Entfernen von T3 Code unter _Remove > AI_ nimmt sie mit.

### Lokale Modelle

Lasse ein offenes Modell auf deiner eigenen Maschine für deine Coding-Agenten laufen. Deine Prompts und dein Code bleiben auf der Maschine; nichts, was an das Modell gesendet wird, verlässt sie. Starte mit:

```bash
omarchy agent local use best
```

Oder wähle im Agenten-Panel in der oberen Leiste + und dann Local AI, was auftaucht, wenn ein Modell zu dieser Maschine passt. Beim ersten Mal installiert dies Podman, das die Modelle ausführt, und auf einer NVIDIA-Maschine NVIDIAs Container-Toolkit, das ihnen die GPU gibt. Omarchy wählt dann das empfohlene Modell für diese Maschine, lädt es herunter und startet es. Erwarte einen Download von Dutzenden GB und dass der Großteil des Speichers der Maschine in Verwendung ist, während das Modell läuft: Flash Next verwendet mit seinem vollen 256K-Kontext etwa 100 GiB. Wenn andere Modelle den Speicher halten, den es braucht, wird es gestoppt eingerichtet, bereit zu starten, sobald du eines stoppst. Das Modell stoppt bei der Abmeldung; stoppe es selbst, wenn du den Speicher für etwas anderes brauchst.

`omarchy agent local list` zeigt die Optionen und erklärt, warum manche nicht passen. Um ein weiteres einzurichten, führe `omarchy agent local use <recipe>` aus. Heute sind `qwen3.8-flash-next-gufo` und `qwen3.8-27b-gufo` für 128 GB Strix Halo-Maschinen verfügbar; das 27B nimmt etwa 40 GiB, deshalb lässt es Raum für andere Arbeit. Auf einem 64 GB Laptop mit Intels Arc B390 läuft `qwen3.6-35b-a3b-llamacpp` in etwa 30 GiB. Neue Rezepte und Empfehlungen kommen mit `omarchy update`, über das Paket.

Jedes Modell, das du einrichtest, bekommt seine eigene Zeile im Agenten-Panel, neben deinen Abonnements: Play, um es zu starten, Pause, um es zu stoppen und seinen Speicher freizugeben, und der Terminal-Button, um deinen Agenten darauf zu öffnen. Mehrere können gleichzeitig laufen, wenn sie zusammen in den Speicher passen; wenn eines nicht passt, sagt Omarchy, welches laufende Modell du stoppen sollst. Ziehe Zeilen, um sie neu zu ordnen, und drücke Delete auf einer ausgewählten Zeile, um ein Modell und seinen Download zu entfernen.

Jedes Modell, das du einrichtest, bekommt auch seinen eigenen Eintrag im App-Launcher, unter dem Namen des Modells und mit dem Logo seines Herstellers, so wie die Anmeldung bei Claude, Codex oder Grok einen hinzufügt. Es öffnet deinen Agenten auf diesem Modell und startet das Modell zuerst, wenn es nicht läuft: Das Terminal zeigt, wie es lädt, und übergibt an den Agenten, sobald es bereit ist. Das Entfernen eines Modells entfernt seinen Eintrag.

Von der Befehlszeile aus tun `omarchy agent local start <recipe>` und `omarchy agent local stop <recipe>` das Gleiche, `omarchy agent local status` zeigt jedes Modell, und `omarchy agent --local` öffnet deinen Standardagenten auf dem letzten Modell, das du gestartet hast. pi, OpenCode und Qwen Code können eines verwenden; mit jedem anderen Standard öffnet es sich in pi. pi listet auch jedes Modell, das du eingerichtet hast, und die auf Maschinen, mit denen du dich gekoppelt hast, in seinem eigenen Modell-Picker, sodass ein einfaches `pi` sie ebenfalls erreicht. Jeder OpenAI-kompatible Client kann sich ebenfalls verbinden: `status` zeigt die Adresse jedes Modells (die erste ist `http://127.0.0.1:11435/v1`), der Rezeptname ist das Modell, und der Schlüssel ist in `~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` löscht ein Modell und die Downloads, die kein anderes Modell verwendet.

Laufzeitumgebungen von Dritten sind mit ihrem Publisher gekennzeichnet. Omarchy führt jedes Modell ohne Netzwerkzugang aus.

### Lokale LLMs

Omarchy empfiehlt zwei Wege, lokale LLM-Modelle auszuführen: LM Studio und Ollama. LM Studio bietet eine GUI-Oberfläche, um Open-Weight-Modelle zu finden, sie zu installieren und auszuführen. Es ist ein großartiger Weg, um leicht loszulegen. Ollama bietet eine CLI, um dies ähnlich zu tun. Aber wenn du neu bei lokalen Modellen bist, würde ich mit LM Studio anfangen. Du kannst beide unter _Install > AI_ im Omarchy Menu installieren.

### Der Omarchy Skill

Agent Skills helfen AI, bestimmte Tools auf eine bestimmte Weise zu verwenden, und Omarchy liefert einen Standard-Skill zum Anpassen des Systems. Wie deine Hyprland-Konfiguration zu tweaken, die Leiste anzupassen oder sogar ein neues Thema von Grund auf zu erstellen. Er ist in die Skill-Verzeichnisse für Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` und jedes `~/.hermes/profiles/*/skills`) und den generischen `~/.agents/skills`-Ort symlinkt, sodass die meisten Harnesses ihn automatisch aufnehmen.

Aber du solltest diesen Skill als experimentell behandeln. Verschiedene Modelle werden ihn mit unterschiedlicher Wirkung verwenden. Am besten lässt du ihn zuerst im Plan-Modus laufen, damit du eine Vorstellung davon hast, was der Agent ändern möchte. Und sei dann bereit, Änderungen zurückzunehmen oder sogar `omarchy reinstall configs` aufzurufen, wenn der Agent alles durcheinanderbringt.
