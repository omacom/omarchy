# KI

Omarchy enthält Launcher für die unten stehenden Coding-Agents, ohne einen Standard für dich auszuwählen. Führe einen Befehl aus, um seine CLI bei der ersten Verwendung zu installieren, und authentifiziere dich dann, wenn du dazu aufgefordert wirst. Hermes und OpenClaw sind die Ausnahmen: Für sie wird nichts über mise installiert, und die Auswahl eines von beiden richtet seine eigene, sich selbst aktualisierende Kopie ein, wie _Desktop-Apps_ weiter unten erklärt.

### Agents installieren und aktualisieren

Außer Hermes und OpenClaw verwenden diese Agents mises Lazy-Installation: Beim ersten Start wird die CLI installiert, und spätere Starts verwenden sie wieder. mise prüft außerdem höchstens einmal alle vier Stunden, ob es für einen installierten Agent ein neues Release gibt, kurz bevor er startet oder im Hintergrund an einem Shell-Prompt. Schlägt dieses Update fehl oder bist du offline, läuft die installierte Version. `omarchy update` aktualisiert installierte Agents zusammen mit dem Rest von Omarchy, und `mup` aktualisiert nur mise-verwaltete Tools.

Ein agent-eigener Updater, wie `claude update`, `codex update` oder ein Update-Button in einer App, aktualisiert die mise-verwaltete Installation nicht. `codex update` schlägt fehl, und `claude update` kann Erfolg melden, während es eine separate Kopie installiert, die mise nicht verfolgt. Wenn du lieber den nativen Installer und Updater eines Agents verwenden möchtest, füge ihn zu `disable_tools` hinzu; siehe [Vorinstallierte CLI-Tools](18-development-tools.md#preinstalled-cli-tools).

Um alle konfigurierten Lazy-Tools zu installieren, bevor du sie brauchst, führe `mise install --include-lazy` aus. Dazu gehören Omarchys andere Standard-CLI-Tools ebenso wie die Agents. Siehe [Vorinstallierte CLI-Tools](18-development-tools.md#preinstalled-cli-tools), um ein einzelnes Tool zu installieren oder deine eigene Installation zu verwenden.

`grok` wird über mises First-Party-Paket `grok` installiert, genauso wie `claude` und `codex`. Führe `grok` aus oder wähle es unter _Agent > Harness_. Überspringe den `curl | bash`-Installer auf x.ai. Dieser Pfad legt eine zweite Kopie in `~/.grok/bin` ab, stellt sie auf `PATH` voran und überschreibt Omarchys Wrapper.

`dsh` öffnet seine Browser-UI auf `127.0.0.1:3080`, mit dem Startverzeichnis als seinem Standard-Workspace. Seine Browser-UI nimmt keinen Start-Prompt entgegen, sodass `omarchy agent prompt` sie mit dem Prompt auf deiner Zwischenablage zum Einfügen öffnet. Omarchy startet es mit DeepSeeks No-Approval-Permission-Preset. DeepSeek Harness lädt Sitzungsprotokolle zu DeepSeek hoch, wenn du seine offizielle Modell-API verwendest; schalte das unter _Settings > General > Upload Session Log_ in seiner Browser-UI aus. Feedback, das du ihm sendest, wird ebenfalls zusammen mit der Sitzung hochgeladen, es sei denn, du startest es mit `DSH_TELEMETRY_MODE=DISABLED`.

### Der Standard-Agent

Wähle deinen Standard-Agent mit `omarchy default agent <name>` oder unter _Agent > Harness_ im Omarchy Menu (`Super + Space`). Wenn der Agent noch nicht installiert ist, installiert ihn die Auswahl zuerst, und er bekommt außerdem seinen eigenen Launcher im App-Launcher, neben Agent. Ein frisches Omarchy lädt dich mit einer einmaligen Benachrichtigung ein, diese Auswahl zu treffen.

Die Auswahl von Claude versucht außerdem, seine Browser-Erweiterung für Chromium, Chrome, Brave, Brave Origin und Edge einzurichten. Die Einrichtung der Erweiterung gilt für alle Benutzer und fragt möglicherweise nach deinem Systempasswort; Abbrechen oder eine fehlgeschlagene Installation der Erweiterung wählt Claude trotzdem aus und startet ihn. Starte deinen Browser neu, aktiviere die Erweiterung, wenn du dazu aufgefordert wirst, und melde dich bei Claude an, um die Verbindung fertigzustellen. Führe `/chrome` in Claude aus, um die Verbindung zu prüfen. Firefox und Zen unterstützen diese Erweiterung nicht. Wenn Claude bereits dein Standard war, bevor diese Einrichtung hinzugefügt wurde, wähle ihn erneut aus, um die Erweiterung zu installieren.

Sobald du gewählt hast, startet `Super + Shift + Ctrl + A` den Standard-Agent in einem eigenen Terminalfenster (oder ruft die Auswahl auf, wenn du noch nicht gewählt hast). Du kannst ihn auch direkt mit einer Aufgabe starten, mit `omarchy agent prompt "Review this project"`. Freebuff und DeepSeek Harness nehmen keinen Start-Prompt entgegen, sodass sie stattdessen mit dem Prompt auf deiner Zwischenablage zum Einfügen öffnen. So gestartete Agents laufen unbeaufsichtigt in ihren jeweiligen Don't-stop-to-ask-Modi, sei also bereit, dass sie tatsächlich Dinge tun! MiniMax Code hat keinen solchen Modus für seine interaktiven Sitzungen, sodass es wie üblich um Berechtigungen bittet. Und da Agents sich weigern, sich Vertrauen für dein Home-Verzeichnis zu merken, starten Starts aus `$HOME` stattdessen in `~/Work`.

Es gibt auch Terminal-Kürzel: `a` führt den Standard-Agent inline im aktuellen Terminal aus, während `c`, `cx` und `cy` OpenCode, Claude Code und Codex direkt starten (wiederum in ihren Auto-Approving-Modi). Theme-Wechsel synchronisieren sich ebenfalls zu den Agents: Claude Code, Pi, OpenCode und Hermes (sobald Omarchy ihn installiert hat) ziehen alle mit, wenn du das Omarchy-Theme wechselst.

### Deine Agent-Anweisungen

Persönliche Regeln für jeden Agent gehören in `~/.agents/AGENTS.md`, neben die gemeinsamen Skills in `~/.agents/skills`. Öffne sie unter _Agent > Instructions_, was sie außerdem in jeden Harness verlinkt, der seine eigene globale Datei führt: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, Copilots `~/.copilot/copilot-instructions.md` und so weiter. Crush und Amp lesen den Link `~/.config/AGENTS.md`, während omp, Kimi und DeepSeek Harness `~/.agents/AGENTS.md` direkt lesen. Die Auswahl eines Standard-Agents verlinkt sie ebenfalls. Eine Anweisungsdatei, die du bereits hattest, wird zur gemeinsamen, falls es noch keine gab; andernfalls wird sie neben dem Link als `.bak` behalten. Führe `omarchy agent instructions` aus, um nach der Installation eines weiteren Agents erneut zu verlinken.

### Das Agents-Panel

Die obere Leiste hat ein Agents-Symbol. Bevor du einen Agent eingerichtet hast, führt dich sein Panel durch die Anmeldung bei Claude, Codex oder Grok, und der erste wird dein Standard-Agent. Danach bringt das Panel jedes Abonnement auf eine Seite: jeden Agent und jedes Konto mit seinem Plan, einen Messbalken für jedes seiner 5-Stunden-Sitzungs- und wöchentlichen Limits mit der Zeit bis zum Zurücksetzen (fahre mit der Maus darüber für den genauen Prozentsatz) oder das verbleibende Prepaid-Guthaben, unter einer Zeile, die durchrotiert, was du über alle hinweg verwendet hast, wie Tokens diese Woche und dein am meisten verwendetes Modell. Unter _Make something cool_ bietet es Starter-Prompts für ein neues Theme, Plugin, eine App oder ein Spiel an, die die Aufgabe an deinen Standard-Agent übergeben. Apps werden so gebaut wie Omarchys eigene Hype, Monologue und Omacut, in C++ und Qt Quick, nach dem omarchy-make-app Agent-Skill, und der Compiler und die Qt-Teile, die sie brauchen, kommen mit installiert. Spiele sind eine einzelne three.js-Seite in `~/Games/vibes`, nach dem omarchy-make-game Agent-Skill, und alle öffnen sich aus einem Game Vibes-Launcher im aktuellen Theme; sie laden three.js aus dem Web, sodass sie eine Verbindung zum Starten brauchen. Claude Code, Codex, Grok, Kimi, Cursor und sein Grok Bot-Kontingent, GitHub Copilot, Muse, Antigravity und Devin werden out of the box mit ihren Limits abgedeckt, Kimchi mit seinem Plan, Prepaid-Credits und Spend-Budgets, und Hermes, Mistral Vibe und Qwen Code zeigen ihre Sitzungen und Tokens, sobald du sie verwendet hast. Provider-Pläne und -Keys, die du über pi, omp oder opencode verwendest, tauchen ebenfalls auf: OpenCode Zen und Go, der Z.ai GLM Coding Plan, Ollama Cloud, der MiniMax Token Plan und Synthetic mit ihren Limits; OpenRouter und DeepSeek mit ihren Prepaid-Guthaben; Fireworks mit seinen Ausgaben über die letzten 30 Tage. Tokens von Modellen, die du auf deiner eigenen Hardware laufen lässt, zählen ebenfalls zu den Summen; die Modelle selbst haben ein eigenes Panel, beschrieben unter [Lokale Modelle](#local-models). Jeder Agent wird einmal gezählt, unter dem, der ihn abrechnet, egal durch wie viele Harnesses du ihn betreibst.

Klicke mit links auf das Leistensymbol oder drücke `Super + Ctrl + X` für das Panel, klicke mit rechts, um deinen Standard-Agent zu starten, und mit der mittleren Taste, um zu aktualisieren. Die dahinterliegenden Nutzungsaufzeichnungen werden alle 15 Minuten durch `omarchy agent usage update` neu erzeugt, und das Panel kann sogar Nutzung von deinen anderen Maschinen über einen synchronisierten Ordner zusammenführen. Siehe das README unter `$OMARCHY_PATH/shell/plugins/agents/` für die vollständigen Einstellungen.

### Mehrere Abonnements

Wenn du für mehr als einen Claude-, Codex- oder Grok-Plan bezahlst — etwa ein persönliches Max und ein berufliches — kann Omarchy sie alle angemeldet halten und zwischen ihnen wechseln. Füge ein Abonnement mit dem + im Agents-Panel hinzu, das dich direkt dort hindurchführt, oder mit `omarchy agent account add claude Work` (oder `codex` oder `grok`). Es installiert die CLI, falls sie fehlt. Das erste Konto für einen Provider meldet sich über deinen normalen Browser an, genau dort, wo die CLI immer nachsieht. Jedes weitere meldet sich über ein privates Fenster an, sodass das Konto, bei dem dein Browser bereits angemeldet ist, nicht versehentlich übernommen wird; melde dich dort als das Konto an, das du hinzufügst, und schließe vorher jedes private Fenster, das du bereits offen hattest. Melde dich dafür niemals von der CLI ab: Abmelden widerruft die gespeicherte Anmeldung, und dieses Konto müsste erneut hinzugefügt werden.

Um deine Abonnement-Anmeldungen über SSH auf eine andere Omarchy-Maschine zu kopieren, führe `omarchy agent account copy user@laptop` aus. Der Sender stellt einen temporären Empfänger bereit, wenn das Ziel keinen installiert hat, sodass ältere Omarchy-Maschinen Konten ohne ein Update empfangen können. Installierte Empfänger haben Vorrang. Dies kopiert alle Claude-, Codex- und Grok-Abonnements; füge Provider-Namen hinzu, um sie auszuwählen, wie bei `omarchy agent account copy laptop claude`. Konto-Namen und Befehls-IDs stimmen mit der Quelle überein, einschließlich bereits auf dem Ziel vorhandener Konten. Nicht verwandte Zielkonten erhalten ein numerisches Suffix, wenn ihre Namen kollidieren, und Einstellungen, Skills, Plugins und Konversationsverlauf bleiben lokal auf jeder Maschine.

Bestehende Ziel-Zugangsdaten bleiben erhalten. Ein Quellkonto, das dort bereits angemeldet ist, bekommt seinen Namen synchronisiert, ohne seine Zugangsdaten zu ersetzen; andere Konten werden daneben hinzugefügt. Um gespeicherte Zugangsdaten für übereinstimmende Konten zu ersetzen, verwende `omarchy agent account copy --replace laptop claude`, nachdem du die Sitzungen dieses Kontos auf dem Ziel beendet hast. Ein frisches Ziel bekommt außerdem das aktive Konto und die Wechsel-Einstellungen der Quelle; ein etabliertes Ziel behält seine eigenen.

Zugangsdaten reisen über SSH und werden in privaten Dateien auf dem Ziel gespeichert, kopiere also nur auf Maschinen, denen du vertraust. Dies ist eine einmalige Kopie, keine laufende Synchronisierung. Codex-Refresh-Tokens können von einer anderen Maschine rotiert werden, sodass eine kopierte Anmeldung erneuert werden muss; separate Anmeldungen bleiben die zuverlässigste Wahl für gleichzeitige Verwendung auf mehreren Maschinen. Siehe [Codex' Anleitung zur Kontoauthentifizierung](https://developers.openai.com/codex/auth/ci-cd-auth).

Ein Konto pro Provider ist aktiv, und jede neue Sitzung startet als dieses: `cx`, `cy`, ein einfaches `claude`, `codex` oder `grok`, alles, was über `omarchy agent` gestartet wird, und Skripte oder Editoren, die die CLI auf `PATH` finden. Wechsle mit `omarchy agent account use work` (und zurück mit `omarchy agent account use main`) oder im Panel, indem du die Nummer eines Kontos und dann `Enter` drückst (oder auf seinen Use-Button klickst). Laufende Claude-Sitzungen wechseln ebenfalls, ab ihrer nächsten Nachricht: Jede Claude-Sitzung läuft in `~/.claude`, das immer die Anmeldung des aktiven Kontos enthält. Eine Claude-Sitzung, die von einem älteren Omarchy im eigenen Ordner eines Kontos gestartet wurde, hält diese Anmeldung, bis sie beendet wird, sodass der Wechsel diese Sitzungen benennt und von selbst abschließt, sobald sie weg sind. Laufende Codex- und Grok-Sitzungen bleiben bei dem Konto, mit dem sie gestartet sind. Konversationsverlauf, Einstellungen, Skills und Plugins werden zwischen Konten geteilt, sodass `claude --continue` im selben Ordner dort weitermacht, wo du auf dem neuen Konto aufgehört hast.

Mit mehr als einem Konto zeigt das Panel die Limits jedes Kontos nebeneinander, mit dem aktiven markiert. Standardmäßig benachrichtigt dich Omarchy, wenn das aktive Konto 95% eines Limits überschreitet, und ein Klick auf die Benachrichtigung wechselt zum Konto mit dem meisten Spielraum. Fahre mit der Maus über die Zeile eines Kontos im Panel und klicke auf das Autoswitch, das neben Use erscheint (oder drücke `m`), oder führe `omarchy agent account mode auto` aus, damit es stattdessen von selbst wechselt; solange es an ist, nimmt Autoswitch den Platz von Use ein, und erneutes Klicken schaltet zurück auf Benachrichtigen. Füge eine Zahl hinzu, um den Schwellenwert zu ändern, wie bei `omarchy agent account mode auto 90`. Wenn jedes Konto über dem Schwellenwert liegt, hörst du einmal davon, zusammen damit, welches Konto zuerst frei wird. Während ein aktives Konto innerhalb von 15 Punkten seines Schwellenwerts liegt (80% beim Standard), werden seine Limits alle drei Minuten statt alle 15 geprüft.

`omarchy agent account list` zeigt jedes Konto und seine neuesten Limits, `omarchy agent account remove work` vergisst eines, und `omarchy agent account rename primary Hey` benennt eines um (oder klicke auf den Namen eines Kontos im Panel). Diese Befehle arbeiten mit den Konten deines Standard-Agents; um den anderen Provider zu erreichen, nenne ihn zuerst, wie bei `omarchy agent account use codex side`. Die Anmeldung, die du bereits in `~/.claude` oder `~/.codex` hattest, ist das _Main_-Konto. Codex' bleibt, wo sie ist; Claudes wartet in einem eigenen Ordner, während ein anderes Konto aktiv ist. Ein Konto, das mehr als etwa acht Stunden ungenutzt blieb, kann _Sign-in required_ zeigen; klicke es an, um dieses Konto direkt im Panel erneut anzumelden, oder wechsle zu ihm und starte eine Sitzung, was die Anmeldung von selbst auffrischt. MCP-Server, die du mit `claude mcp add` hinzufügst, erreichen jedes Claude-Konto, da sie alle in `~/.claude` laufen; bei Codex und Grok kommen Server, die du hattest, als ein Konto hinzugefügt wurde, mit zu ihm, aber spätere erreichen nur das Konto, in dem du sie hinzugefügt hast. Claude Desktop behält eine eigene Anmeldung, und Codex- oder Grok-Tools, die mit einem absoluten Pfad zu einer CLI-Binärdatei konfiguriert sind, folgen dem Wechsel nicht. Ein explizites `CLAUDE_CONFIG_DIR`, `CODEX_HOME` oder `GROK_HOME` hat Vorrang vor dem ausgewählten Konto.

### Crash-Diagnose

Omarchy beobachtet systemd-coredump auf Prozessabstürze. Sobald du einen Standard-Agent gewählt hast, bringt jedes deiner Programme, das einen Core Dump erzeugt, eine "Process crashed"-Benachrichtigung — klicke sie an, und der Absturz wird deinem Standard-Agent übergeben, zusammen mit Omarchys omarchy-diagnose-crash-Skill, das den Agent dadurch führt, die Fakten aus dem Core Dump zu ermitteln und zu entscheiden, ob der Absturz es wert ist, upstream gemeldet zu werden. Du kannst es auch von Hand gegen jede PID aus `coredumpctl list` mit `omarchy agent crash <pid>` ausführen.

Das Beobachten ist standardmäßig an. Schalte es unter _Trigger > Toggle > Crash Capture Off_ aus (oder mit `omarchy toggle crash-capture`), und die Benachrichtigungen hören auf; `omarchy agent crash <pid>` funktioniert von Hand weiterhin.

Abstürze können auch ein Programm nach dem anderen stummgeschaltet werden, was die Diagnose dir am Ende anbietet. `omarchy crash mute hyprland` stoppt die Benachrichtigungen nur für dieses Programm, `omarchy crash mute hyprland off` bringt sie zurück, und `omarchy crash mute` allein listet auf, was du stummgeschaltet hast. Es nimmt den Pfad der Binärdatei genauso gern wie ihren Namen, sodass `omarchy crash mute /usr/bin/hyprland` dasselbe tut. Setze einen Namen mit einem Leerzeichen in Anführungszeichen, wie bei `omarchy crash mute 'Some App'`. Alles andere benachrichtigt weiterhin, und das stummgeschaltete Programm stürzt weiterhin ab — das versteckt die Erinnerung, es repariert nichts.

### Desktop-Apps

Das Menü _Install > AI_ führt außerdem ein paar grafische KI-Apps: Amp Desktop, Antigravity Desktop, die ChatGPT Desktop-App, die Claude Desktop-App (Anthropics Linux-Beta, mit Chat-, Cowork- und Claude Code-Tabs), Grok Bot zum Chatten mit xAIs Modellen, Herdr Desktop, Hermes Desktop, OpenClaw, die Perplexity Desktop-App und T3 Code. Grok Bot ist die Desktop-Chat-App. Der Coding-Agent ist der Befehl `grok`.

Hermes Desktop ist die, die man kennen sollte, weil eine Maschine ein Hermes hat, und es ist das der App: Hermes wird nur je über die App installiert, und der Befehl `hermes`, den der Standard-Agent ausführt, ist der der App. Hermes als Standard-Agent auszuwählen installiert dasselbe wie der Eintrag _Install > AI_: das Paket und eine Hermes-Runtime unter `~/.hermes`, eingerichtet durch Hermes' eigenen Installer, was beim ersten Mal ein paar Minuten dauert. Diese Runtime ist das eine Hermes, das der Terminal-Befehl `hermes`, der Standard-Agent und die App alle verwenden, und sie aktualisiert sich selbst mit `hermes update`, statt auf ein Omarchy-Release zu warten. Ihre Installation übergibt Hermes außerdem das Omarchy-Theme als Skin namens `omarchy`, dem jede Hermes-Oberfläche folgt, wenn du Themes wechselst; wähle einen anderen unter Hermes' Appearance-Einstellungen oder mit `/skin`, wenn du das lieber nicht möchtest, und Omarchy lässt diese Wahl in Ruhe. Das Entfernen der App unter _Remove > AI_ schließt Hermes zuerst, Gateway inklusive, nimmt diese Runtime mit und behält deine Chats, Erinnerungen und die Skills, die Hermes für sich selbst geschrieben hat, es sei denn, du sagst ihm etwas anderes: Es fragt, mit Standard Nein, ob diese Daten und deine Verbindungseinstellungen ebenfalls gehen sollen.

OpenClaws Desktop-Erlebnis ist seine Control UI, die als Web-App öffnet, gestützt auf sein eigenes lokales Gateway. OpenClaw lebt in `~/.openclaw` und aktualisiert sich selbst: Verwende den "Update Gateway"-Button der Control UI oder führe `openclaw update` aus, und das Gateway startet auf der neuen Version neu. Omarchy wählt nur das Release, mit dem eine frische Installation startet. OpenClaw kann auch dein Standard-Agent sein: Ihn unter _Agent > Harness_ auszuwählen richtet dieselbe Kopie in `~/.openclaw` ein, und der Agent öffnet OpenClaws Terminal-UI, angebunden an sein Gateway. Das Entfernen von OpenClaw unter _Remove > AI_ nimmt den Gateway-Dienst und die App mit und fragt dann, ob `~/.openclaw` ebenfalls gehen soll, da das deine Chats und Zugangsdaten neben OpenClaw selbst und den Plugin-Runtimes enthält, die es herunterlädt; der Standard behält es, und OpenClaw erneut zu installieren greift es wieder auf.

Herdr Desktop ist die [Herdr](https://herdr.dev) Desktop-App: Spaces, Tabs und Panes von Terminals und Coding-Agents, die in seinem Core weiterlaufen, wenn du das Fenster schließt. Sie kommt aus Herdrs eigenem Installer statt aus einem Paket, sodass sie in `~/.local/share/herdr-app` lebt, seinen Core in `~/.local/bin/herdr-core` mitbringt, wenn du noch keinen hast, und beide aktualisieren sich selbst. Sie sitzt neben dem Befehl `herdr`, den Omarchy auf `Super + Ctrl + Return` ausliefert, statt ihn zu ersetzen, und bekommt die direkten Tasten dieses Befehls: `Alt + Return` und `Alt + Shift + Return` teilen ein Pane nach unten oder rechts, `Alt + Escape` schließt es, `Ctrl + Alt + Arrow` bewegt sich zwischen Panes, `Alt + 1..9` und `Alt + Left/Right` wählen einen Tab, und `Alt + Up/Down` bewegen sich zwischen Spaces. `Ctrl + 1..9` wählt einen Space und `Alt + Shift + Up/Down` schreitet durch Agents. Die `Ctrl + Space` Prefix-Tasten bleiben nur fürs Terminal, da die App keine einfache Ctrl-Taste für eine Sequenz halten kann. Omarchy schreibt diese nach `~/.config/herdr-app/keys.json`, und `omarchy-refresh-herdr-app` setzt sie zurück. Ihre Installation wählt Herdrs Omarchy-Theme, das von da an deinem Omarchy-Theme folgt. Herdr behält ein Theme für den hellen Modus und eines für den dunklen, sodass du nach dem Wechsel zwischen einem dunklen und einem hellen Omarchy-Theme Omarchy in Herdrs Theme-Picker noch einmal für den anderen Modus wählst.

T3 Code läuft aus seinem offiziellen AppImage-Release in `~/.local/share/t3code` statt aus einem Paket, sodass es sich selbst aktualisiert. Seine Installation fragt, ob auf dem Stable- oder Nightly-Kanal gestartet werden soll; wechsle später in T3 Codes Einstellungen. Deine Threads und Einstellungen leben in `~/.t3`, und das Entfernen von T3 Code unter _Remove > AI_ nimmt sie mit.

### Lokale Modelle

Lasse ein offenes Modell auf deiner eigenen Maschine für deine Coding-Agents laufen. Deine Prompts und dein Code bleiben auf der Maschine; nichts, was an das Modell gesendet wird, verlässt sie. Beginne mit:

```bash
omarchy models use best text
```

Das richtet das beste Textmodell für diese Maschine ein, die Art, die deine Agents verwenden. Bild-, Video- und Musikmodelle haben ihr eigenes Bestes: `omarchy models use best image`, `video` oder `music`. Führe `omarchy models use best` aus, um die Auswahl jeder Art für diese Maschine zu sehen.

Oder öffne das Panel für lokale Modelle über sein Sparkles-Symbol in der oberen Leiste, neben dem Agents-Symbol, oder mit Super + Ctrl + Alt + X, und wähle +. Das Symbol taucht auf, wenn ein Modell auf diese Maschine passt. Podman, das die Modelle laufen lässt, kommt mit Omarchy, ebenso wie NVIDIAs Container-Toolkit auf einer NVIDIA-Maschine, das ihnen die GPU gibt; falls eines von beiden fehlt, installiert es die erste Einrichtung. Omarchy wählt dann das empfohlene Modell für diese Maschine, lädt es herunter und startet es. Erwarte einen Download von zig GB und dass der Großteil des Speichers der Maschine in Verwendung ist, während das Modell läuft: Flash Next verwendet etwa 100 GiB mit seinem vollen 256K-Kontext. Wenn andere Modelle den Speicher halten, den es braucht, wird es gestoppt eingerichtet, bereit zu starten, sobald du eines stoppst. Das Modell stoppt bei Abmeldung; stoppe es selbst, wenn du den Speicher für etwas anderes brauchst.

`omarchy models list` zeigt die Optionen und erklärt, warum manche nicht passen. Um ein anderes einzurichten, führe `omarchy models use <recipe>` aus. Heute sind `qwen3.8-flash-next-gufo` und `qwen3.8-27b-gufo` für 128 GB Strix Halo-Maschinen verfügbar; das 27B nimmt etwa 40 GiB, sodass es Raum für andere Arbeit lässt. Auf einem 64 GB Laptop mit Intels Arc B390 läuft `qwen3.6-35b-a3b-llamacpp` in etwa 30 GiB. Neue Recipes und Empfehlungen kommen mit `omarchy update`, über das Paket.

Jedes Modell, das du einrichtest, bekommt seine eigene Zeile im Panel für lokale Modelle: Play, um es zu starten, Pause, um es zu stoppen und seinen Speicher freizugeben, und den Terminal-Button, um deinen Agent darauf zu öffnen. Quer über die Oberseite zeigt eine Leiste, wie der Speicher der Maschine aufgeteilt ist zwischen Omarchy selbst (dem System und deinen Apps), jedem laufenden Modell und dem, was frei ist. Zeige auf ein gestopptes Modell, und die Leiste zeigt, ob es passt oder wie viel ihm fehlt. Mehrere können gleichzeitig laufen, wenn sie zusammen in den Speicher passen; wenn eines nicht passt, sagt Omarchy, welches laufende Modell zu stoppen ist. Ziehe Zeilen an ihrem Logo, um sie neu zu ordnen, und drücke Delete auf einer ausgewählten Zeile, um ein Modell und seinen Download zu entfernen.

Jedes Coding-Modell, das du einrichtest, bekommt außerdem seinen eigenen Eintrag im App-Launcher, unter dem Namen des Modells und mit dem Logo seines Herstellers, so wie die Anmeldung bei Claude, Codex oder Grok einen hinzufügt. Es öffnet deinen Agent auf diesem Modell und startet das Modell zuerst, falls es nicht läuft: Das Terminal zeigt es beim Laden und übergibt an den Agent, sobald es bereit ist. Das Entfernen eines Modells entfernt seinen Eintrag.

Nicht jedes Modell ist zum Coden da. Bild-, Video- und Musikmodelle öffnen stattdessen in Fantasi, Omarchys App zum Erstellen von Bildern, Video und Musik mit einem Modell, das auf dieser Maschine läuft, dort ausgewählt oder aus ihrer Zeile im Panel für lokale Modelle.

Ein Modell läuft weiterhin genau so, wie es eingerichtet wurde, sodass ein Omarchy-Update niemals eines unter deinen Agents neu startet. Wenn Omarchy eine neuere Runtime oder neuere Weights für ein Modell hat, das du eingerichtet hast, zeigt seine Zeile einen Update-Button: Drücke ihn, und das Modell wird im Hintergrund erneut eingerichtet, lädt nur herunter, was sich geändert hat, und startet auf der neuen Version neu. Ein Modell, das gestoppt war, bleibt gestoppt. `omarchy models update` tut dasselbe für jedes Modell aus einem Terminal.

Von der Kommandozeile tun `omarchy models start <recipe>` und `omarchy models stop <recipe>` dasselbe, `omarchy models status` zeigt jedes Modell, und `omarchy agent --local` öffnet deinen Standard-Agent auf dem letzten Modell, das du gestartet hast. pi, OpenCode und Qwen Code können eines verwenden; mit jedem anderen Standard öffnet es in pi oder in OpenCode, wenn du pi nicht hast. pi listet außerdem jedes Modell, das du eingerichtet hast, und die auf Maschinen, mit denen du gepaart hast, in seinem eigenen Modell-Picker, sodass ein einfaches `pi` sie ebenfalls erreicht. Jeder OpenAI-kompatible Client kann sich ebenfalls verbinden: `status` zeigt die Adresse jedes Modells (die erste ist `http://127.0.0.1:11435/v1`), der Recipe-Name ist das Modell, und der Key liegt in `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` löscht ein Modell und die Downloads, die kein anderes Modell verwendet.

Third-Party-Runtimes sind mit ihrem Publisher gekennzeichnet. Omarchy lässt jedes Modell ohne Netzwerkzugriff laufen.

### Lokale LLMs

Omarchy empfiehlt zwei Wege, lokale LLM-Modelle laufen zu lassen: LM Studio und Ollama. LM Studio bietet eine GUI-Oberfläche zum Finden von Open-Weight-Modellen, zum Installieren und zum Laufenlassen. Es ist eine großartige Möglichkeit, einfach loszulegen. Ollama bietet eine CLI, um dasselbe ähnlich zu tun. Aber wenn du neu bei lokalen Modellen bist, würde ich mit LM Studio beginnen. Du kannst beides unter _Install > AI_ im Omarchy Menu installieren.

### Die Omarchy-Skills

Agent-Skills helfen KI, spezifische Tools auf eine spezifische Weise zu verwenden, und Omarchy liefert sieben von ihnen aus. Der omarchy-Skill deckt das Maßschneidern des Systems ab, wie deine Hyprland-Konfig zu tweaken oder die Leiste anzupassen. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app und omarchy-make-game decken das Erstellen von etwas Neuem ab, omarchy-contribute deckt das Melden eines Bugs oder das Senden eines Fixes upstream ab, und omarchy-diagnose-crash arbeitet sich durch den Core Dump eines Absturzes. Sie sind in die Skill-Verzeichnisse für Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` und jedes `~/.hermes/profiles/*/skills`) und den generischen Ort `~/.agents/skills` symlinked, sodass die meisten Harnesses sie automatisch aufgreifen. Ein eigener Skill-Ordner mit demselben Namen hat Vorrang.

Aber du solltest diese Skills als experimentell betrachten. Verschiedene Modelle werden sie zu unterschiedlicher Wirkung verwenden. Es ist am besten, zuerst im Plan-Modus zu laufen, sodass du eine Vorstellung davon hast, was der Agent gern ändern würde. Und sei dann bereit, Änderungen zurückzurollen oder sogar `omarchy reinstall configs` aufzurufen, wenn der Agent aus allem ein Chaos macht.
