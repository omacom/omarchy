# AI

Omarchy enthält Launcher für die unten aufgeführten Coding-Agenten, ohne einen Standard für dich auszuwählen. Führe einen Befehl aus, um dessen CLI bei der ersten Verwendung zu installieren, und authentifiziere dich dann, wenn du dazu aufgefordert wirst. Hermes ist die Ausnahme: Bei der ersten Verwendung wird dafür nichts installiert, und wenn du es auswählst, wird Hermes Desktop installiert, wie _Desktop apps_ unten erklärt.

### Agenten installieren und aktualisieren

Mit Ausnahme von Hermes nutzen diese Agenten mises Lazy-Installation: Der erste Start installiert die CLI, und spätere Starts verwenden sie wieder. mise prüft außerdem höchstens einmal alle vier Stunden, ob es für einen installierten Agenten eine neue Version gibt, kurz bevor er startet oder im Hintergrund an einer Shell-Eingabeaufforderung. Wenn diese Aktualisierung fehlschlägt oder du offline bist, läuft die installierte Version. `omarchy update` aktualisiert installierte Agenten zusammen mit dem Rest von Omarchy, und `mup` aktualisiert nur von mise verwaltete Tools.

Der eigene Updater eines Agenten, wie `claude update`, `codex update` oder eine Update-Schaltfläche in einer App, aktualisiert die von mise verwaltete Installation nicht. `codex update` schlägt fehl, und `claude update` kann einen Erfolg melden, während es eine separate Kopie installiert, die mise nicht verfolgt. Wenn du stattdessen lieber den nativen Installer und Updater eines Agenten verwenden möchtest, füge ihn zu `disable_tools` hinzu; siehe [Vorinstallierte CLI-Tools](18-development-tools.md#preinstalled-cli-tools).

Um alle konfigurierten Lazy-Tools zu installieren, bevor du sie brauchst, führe `mise install --include-lazy` aus. Dazu gehören Omarchys andere Standard-CLI-Tools ebenso wie die Agenten. Siehe [Vorinstallierte CLI-Tools](18-development-tools.md#preinstalled-cli-tools) zum Installieren eines einzelnen Tools oder zur Verwendung deiner eigenen Installation.

`grok` wird über mises First-Party-Paket `grok` installiert, auf die gleiche Weise wie `claude` und `codex`. Führe `grok` aus oder wähle es unter _Setup > Defaults > Agent_ aus. Überspringe den `curl | bash`-Installer auf x.ai. Dieser Weg legt eine zweite Kopie in `~/.grok/bin` ab, stellt sie in `PATH` voran und überschreibt Omarchys Wrapper.

`dsh` öffnet seine Browser-UI auf `127.0.0.1:3080`, mit dem Startverzeichnis als Standard-Workspace. Seine Browser-UI nimmt keinen Start-Prompt entgegen, sodass `omarchy agent prompt` sie mit dem Prompt in deiner Zwischenablage zum Einfügen öffnet. Omarchy startet es mit DeepSeeks Berechtigungs-Preset ohne Genehmigung. DeepSeek Harness lädt Sitzungsprotokolle zu DeepSeek hoch, wenn du dessen offizielle Modell-API verwendest; schalte das in seiner Browser-UI unter _Settings > General > Upload Session Log_ aus. Feedback, das du ihm sendest, wird ebenfalls mit der Sitzung hochgeladen, es sei denn, du startest es mit `DSH_TELEMETRY_MODE=DISABLED`.

### Der Standard-Agent

Wähle deinen Standard-Agenten mit `omarchy default agent <name>` oder unter _Setup > Defaults > Agent_ im Omarchy Menu (`Super + Space`). Wenn der Agent noch nicht installiert ist, wird er durch die Auswahl zuerst installiert. Ein frisches Omarchy wird dich mit einer einmaligen Benachrichtigung dazu einladen, diese Wahl zu treffen.

Die Auswahl von Claude versucht außerdem, seine Browser-Erweiterung für Chromium, Chrome, Brave, Brave Origin und Edge einzurichten. Die Einrichtung der Erweiterung gilt für alle Benutzer und kann nach deinem Systempasswort fragen; ein Abbruch oder eine fehlgeschlagene Installation der Erweiterung wählt Claude trotzdem aus und startet es. Starte deinen Browser neu, aktiviere die Erweiterung, wenn du dazu aufgefordert wirst, und melde dich bei Claude an, um die Verbindung fertigzustellen. Führe `/chrome` in Claude aus, um die Verbindung zu prüfen. Firefox und Zen unterstützen diese Erweiterung nicht. Wenn Claude bereits dein Standard war, bevor diese Einrichtung hinzugefügt wurde, wähle es erneut aus, um die Erweiterung zu installieren.

Sobald du gewählt hast, startet `Super + Shift + Ctrl + A` den Standard-Agenten in einem dedizierten Terminalfenster (oder ruft die Auswahl auf, wenn du noch nicht gewählt hast). Du kannst ihn auch direkt mit einer Aufgabe starten, mit `omarchy agent prompt "Review this project"`. Freebuff und DeepSeek Harness nehmen keinen Start-Prompt entgegen, sodass sie stattdessen mit dem Prompt in deiner Zwischenablage zum Einfügen öffnen. So gestartete Agenten laufen unbeaufsichtigt in ihren jeweiligen Modi, die nicht anhalten, um zu fragen, also sei bereit, dass sie tatsächlich Dinge tun! MiniMax Code hat keinen solchen Modus für seine interaktiven Sitzungen, sodass es wie gewohnt nach Berechtigungen fragt. Und da Agenten sich weigern, Vertrauen für dein Home-Verzeichnis zu merken, starten Starts aus `$HOME` stattdessen in `~/Work`.

Es gibt auch Terminal-Kürzel: `a` führt den Standard-Agenten inline im aktuellen Terminal aus, während `c`, `cx` und `cy` OpenCode, Claude Code und Codex direkt starten (ebenfalls in ihren Modi mit automatischer Genehmigung). Theme-Wechsel werden auch mit den Agenten synchronisiert: Claude Code, Pi, OpenCode und Hermes (sobald Omarchy es installiert hat) folgen alle, wenn du das Omarchy-Theme wechselst.

### Das Agenten-Panel

Die obere Leiste hat ein Agenten-Symbol. Bevor du einen Agenten eingerichtet hast, führt dich sein Panel durch die Anmeldung bei Claude, Codex oder Grok, und der erste davon wird dein Standard-Agent. Danach stellt das Panel jedes Abonnement auf eine Seite: jeden Agenten und jedes Konto mit seinem Tarif, eine Anzeige für jedes seiner Limits für 5-Stunden-Sitzungen und wöchentliche Limits mit der Zeit bis zum Zurücksetzen (fahre mit der Maus darüber für den genauen Prozentsatz) oder das verbleibende Prepaid-Guthaben, unter einer Zeile, die durch das rotiert, was du über alle hinweg verwendet hast, wie Tokens diese Woche und dein am meisten verwendetes Modell. Unter _Make something_ bietet es Starter-Prompts für ein neues Theme, Plugin oder eine neue App an, die die Aufgabe an deinen Standard-Agenten übergeben. Apps werden so gebaut wie Omarchys eigene Hype, Monologue und Omacut, in C++ und Qt Quick, nach dem omarchy-app Agent Skill, und der Compiler und die Qt-Teile, die sie brauchen, sind bereits installiert. Claude Code, Codex, Grok, Kimi, Cursor und sein Grok Bot-Kontingent, GitHub Copilot, Muse, Antigravity, Kimchi und Devin sind mit ihren Limits sofort abgedeckt, und Hermes, Mistral Vibe und Qwen Code zeigen ihre Sitzungen und Tokens, sobald du sie verwendet hast. Provider-Tarife und Schlüssel, die du über pi, omp oder opencode verwendest, tauchen ebenfalls auf: OpenCode Zen und Go, der Z.ai GLM Coding Plan, Ollama Cloud, der MiniMax Token Plan und Synthetic mit ihren Limits; Fireworks, OpenRouter und DeepSeek mit ihren Prepaid-Guthaben; und die Modelle, die du auf deiner eigenen Hardware ausführst, unter Local models. Jeder Agent wird einmal gezählt, unter demjenigen, der ihn abrechnet, egal durch wie viele Harnesses du ihn betreibst.

Klicke mit der linken Maustaste auf das Symbol in der Leiste für das Panel, klicke mit der rechten Maustaste, um deinen Standard-Agenten zu starten. Die dahinterliegenden Nutzungsaufzeichnungen werden alle 15 Minuten von `omarchy agent usage-update` neu erzeugt, und das Panel kann sogar die Nutzung von deinen anderen Maschinen über einen synchronisierten Ordner zusammenführen. Siehe die README unter `$OMARCHY_PATH/shell/plugins/agents/` für die vollständigen Einstellungen.

### Mehrere Abonnements

Wenn du für mehr als einen Claude-, Codex- oder Grok-Tarif bezahlst — zum Beispiel einen persönlichen Max und einen beruflichen — kann Omarchy sie alle angemeldet halten und zwischen ihnen wechseln. Füge ein Abonnement mit dem + im Agenten-Panel hinzu, das dich direkt dort hindurchführt, oder mit `omarchy agent account add claude Work` (oder `codex` oder `grok`). Es installiert die CLI, wenn sie fehlt. Das erste Konto für einen Provider meldet sich über deinen normalen Browser an, genau dort, wo die CLI immer nachsieht. Jedes weitere meldet sich über ein privates Fenster an, sodass das Konto, bei dem dein Browser bereits angemeldet ist, nicht versehentlich übernommen wird; melde dich dort als das Konto an, das du hinzufügst, und schließe vorher jedes private Fenster, das du bereits geöffnet hattest. Melde dich dafür niemals aus der CLI ab: Abmelden widerruft die gespeicherte Anmeldung, und dieses Konto müsste erneut hinzugefügt werden.

Um deine Abonnement-Anmeldungen über SSH auf eine andere Omarchy-Maschine zu kopieren, führe `omarchy agent account copy user@laptop` aus. Der Sender stellt einen temporären Empfänger bereit, wenn das Ziel keinen installiert hat, sodass ältere Omarchy-Maschinen Konten ohne Update empfangen können. Installierte Empfänger haben Vorrang. Dies kopiert alle Claude-, Codex- und Grok-Abonnements; füge Provider-Namen hinzu, um sie auszuwählen, wie in `omarchy agent account copy laptop claude`. Kontonamen und Befehls-IDs stimmen mit der Quelle überein, einschließlich Konten, die auf dem Ziel bereits vorhanden sind. Nicht verwandte Zielkonten erhalten ein numerisches Suffix, wenn ihre Namen kollidieren, und Einstellungen, Skills, Plugins und der Gesprächsverlauf bleiben lokal auf jeder Maschine.

Vorhandene Ziel-Anmeldedaten bleiben erhalten. Ein Quellkonto, das dort bereits angemeldet ist, bekommt seinen Namen synchronisiert, ohne seine Anmeldedaten zu ersetzen; andere Konten werden daneben hinzugefügt. Um gespeicherte Anmeldedaten für übereinstimmende Konten zu ersetzen, verwende `omarchy agent account copy --replace laptop claude`, nachdem du die Sitzungen dieses Kontos auf dem Ziel beendet hast. Ein frisches Ziel erhält außerdem das aktive Konto und die Wechsel-Einstellungen der Quelle; ein etabliertes Ziel behält seine eigenen.

Anmeldedaten reisen über SSH und werden in privaten Dateien auf dem Ziel gespeichert, kopiere also nur auf Maschinen, denen du vertraust. Dies ist eine einmalige Kopie, keine laufende Synchronisierung. Codex-Refresh-Tokens können von einer anderen Maschine rotiert werden, wodurch eine kopierte Anmeldung erneuert werden muss; separate Anmeldungen bleiben die zuverlässigste Wahl für die gleichzeitige Verwendung auf mehreren Maschinen. Siehe [Codex' Anleitung zur Kontoauthentifizierung](https://developers.openai.com/codex/auth/ci-cd-auth).

Ein Konto pro Provider ist aktiv, und jede neue Sitzung startet als dieses: `cx`, `cy`, ein einfaches `claude`, `codex` oder `grok`, alles, was über `omarchy agent` gestartet wird, und Skripte oder Editoren, die die CLI auf `PATH` finden. Wechsle mit `omarchy agent account use work` (und zurück mit `omarchy agent account use main`) oder im Panel, indem du die Nummer eines Kontos und dann `Enter` drückst (oder auf seine Use-Schaltfläche klickst). Sitzungen, die bereits laufen, bleiben bei dem Konto, mit dem sie gestartet sind. Gesprächsverlauf, Einstellungen, Skills und Plugins werden über Konten hinweg geteilt, sodass `claude --continue` im selben Ordner dort weitermacht, wo du auf dem neuen Konto aufgehört hast.

Mit mehr als einem Konto zeigt das Panel die Limits jedes Kontos nebeneinander, mit dem aktiven markiert. Standardmäßig benachrichtigt dich Omarchy, wenn das aktive Konto 95 % eines Limits überschreitet, und ein Klick auf die Benachrichtigung wechselt zu dem Konto mit dem meisten Spielraum. Fahre mit der Maus über die Zeile eines Kontos im Panel und klicke auf das Autoswitch, das neben Use erscheint (oder drücke `m`), oder führe `omarchy agent account mode auto` aus, damit es stattdessen von selbst wechselt; solange es an ist, nimmt Autoswitch den Platz von Use ein, und ein erneuter Klick darauf kehrt zum Benachrichtigen zurück. Füge eine Zahl hinzu, um den Schwellenwert zu ändern, wie in `omarchy agent account mode auto 90`. Wenn jedes Konto über dem Schwellenwert liegt, hörst du einmal davon, zusammen damit, welches Konto zuerst frei wird. Solange ein aktives Konto innerhalb von 15 Punkten an seinem Schwellenwert liegt (80 % beim Standard), werden seine Limits alle drei Minuten statt alle 15 geprüft.

`omarchy agent account list` zeigt jedes Konto und seine neuesten Limits, `omarchy agent account remove work` vergisst eines, und `omarchy agent account rename primary Hey` benennt eines um (oder klicke auf den Namen eines Kontos im Panel). Diese Befehle arbeiten auf den Konten deines Standard-Agenten; um den anderen Provider zu erreichen, nenne ihn zuerst, wie in `omarchy agent account use codex side`. Die Anmeldung, die du bereits in `~/.claude` oder `~/.codex` hattest, ist das _Main_-Konto und bleibt, wo sie ist. Ein Konto, das mehr als etwa acht Stunden ungenutzt bleibt, kann _Sign-in required_ anzeigen; klicke darauf, um dieses Konto direkt im Panel erneut anzumelden, oder starte eine Sitzung darin, was die Anmeldung von selbst auffrischt. MCP-Server, die du hattest, als ein Konto hinzugefügt wurde, kommen mit zu ihm, aber solche, die du später mit `claude mcp add` hinzufügst, erreichen nur das Konto, in dem du sie hinzugefügt hast. Claude Desktop und Tools, die mit einem absoluten Pfad zu einer CLI-Binärdatei konfiguriert sind, folgen dem Wechsel nicht. Ein explizites `CLAUDE_CONFIG_DIR`, `CODEX_HOME` oder `GROK_HOME` hat Vorrang vor dem ausgewählten Konto.

### Absturzdiagnose

Omarchy beobachtet systemd-coredump auf Prozessabstürze. Wenn etwas segfaultet, erhältst du eine "Process crashed"-Benachrichtigung — klicke darauf, und der Absturz wird zusammen mit Omarchys diagnose-crash Skill an deinen Standard-Agenten übergeben, der den Agenten hindurchführt, die Fakten aus dem Core Dump zu ermitteln und zu entscheiden, ob der Absturz es wert ist, upstream gemeldet zu werden. Du kannst es auch von Hand gegen jede PID aus `coredumpctl list` mit `omarchy agent crash <pid>` ausführen.

Die Beobachtung ist standardmäßig an. Schalte sie unter _Trigger > Toggle > Crash Capture_ aus (oder mit `omarchy toggle crash-capture`), und die Benachrichtigungen hören auf; `omarchy agent crash <pid>` funktioniert weiterhin von Hand.

Abstürze können auch ein Programm nach dem anderen stummgeschaltet werden, was dir die Diagnose am Ende anbietet. `omarchy crash mute hyprland` stoppt die Benachrichtigungen nur für dieses Programm, `omarchy crash mute hyprland off` bringt sie zurück, und `omarchy crash mute` allein listet auf, was du stummgeschaltet hast. Es nimmt den Pfad der Binärdatei genauso gern wie ihren Namen, sodass `omarchy crash mute /usr/bin/hyprland` dasselbe tut. Setze einen Namen mit einem Leerzeichen darin in Anführungszeichen, wie in `omarchy crash mute 'Some App'`. Alles andere benachrichtigt weiterhin, und das stummgeschaltete Programm stürzt weiterhin ab — dies verbirgt die Erinnerung, es behebt nichts.

### Desktop-Apps

Das Menü _Install > AI_ enthält auch ein paar grafische AI-Apps: die ChatGPT Desktop-App, die Claude Desktop-App (Anthropics Linux-Beta, mit Chat-, Cowork- und Claude Code-Tabs), Grok Bot zum Chatten mit xAIs Modellen, Hermes Desktop, OpenClaw, die Perplexity Desktop-App und T3 Code. Grok Bot ist die Desktop-Chat-App. Der Coding-Agent ist der Befehl `grok`.

Hermes Desktop ist diejenige, die man kennen sollte, denn eine Maschine hat ein Hermes, und es ist das der App: Hermes wird nur jemals über die App installiert, und der Befehl `hermes`, den der Standard-Agent ausführt, ist der der App. Hermes als Standard-Agenten zu wählen installiert dasselbe wie der Eintrag _Install > AI_: das Paket und eine Hermes-Laufzeitumgebung unter `~/.hermes`, die von Hermes' eigenem Installer eingerichtet wird, was beim ersten Mal ein paar Minuten dauert. Diese Laufzeitumgebung ist das eine Hermes, das der Terminal-Befehl `hermes`, der Standard-Agent und die App alle verwenden, und sie aktualisiert sich selbst mit `hermes update`, statt auf ein Omarchy-Release zu warten. Ihre Installation übergibt Hermes außerdem das Omarchy-Theme als Skin namens `omarchy`, dem jede Hermes-Oberfläche folgt, wenn du Themes wechselst; wähle einen anderen unter Hermes' Appearance-Einstellungen oder mit `/skin`, wenn du das lieber nicht möchtest, und Omarchy lässt diese Wahl in Ruhe. Das Entfernen der App unter _Remove > AI_ schließt Hermes zuerst, Gateway eingeschlossen, nimmt diese Laufzeitumgebung mit und behält deine Chats, Erinnerungen und die Skills, die Hermes für sich selbst geschrieben hat, es sei denn, du sagst ihm etwas anderes: Es fragt, mit Nein als Standard, ob diese Daten und deine Verbindungseinstellungen auch weg sollen.

OpenClaws Desktop-Erlebnis ist seine Control UI, die als Web-App öffnet, gestützt von seinem eigenen lokalen Gateway. OpenClaw lebt in `~/.openclaw` und aktualisiert sich selbst: Verwende die "Update Gateway"-Schaltfläche der Control UI oder führe `openclaw update` aus, und das Gateway startet mit der neuen Version neu. Omarchy wählt nur das Release, mit dem eine frische Installation startet. Das Entfernen von OpenClaw unter _Remove > AI_ nimmt den Gateway-Dienst und die App mit und fragt dann, ob `~/.openclaw` auch weg soll, da das deine Chats und Anmeldedaten neben OpenClaw selbst und den Plugin-Laufzeitumgebungen enthält, die es herunterlädt; der Standard behält es, und eine erneute Installation von OpenClaw nimmt es wieder auf.

T3 Code läuft aus seinem offiziellen AppImage-Release in `~/.local/share/t3code` statt aus einem Paket, sodass es sich selbst aktualisiert. Seine Installation fragt, ob du auf dem Stable- oder Nightly-Kanal starten möchtest; wechsle später in T3 Codes Einstellungen. Deine Threads und Einstellungen leben in `~/.t3`, und das Entfernen von T3 Code unter _Remove > AI_ nimmt sie mit.

### Lokale LLMs

Omarchy empfiehlt zwei Wege, lokale LLM-Modelle auszuführen: LM Studio und Ollama. LM Studio bietet eine GUI-Oberfläche, um Open-Weight-Modelle zu finden, sie zu installieren und sie auszuführen. Es ist eine großartige Möglichkeit, einfach loszulegen. Ollama bietet eine CLI, um dasselbe auf ähnliche Weise zu tun. Aber wenn du neu bei lokalen Modellen bist, würde ich mit LM Studio anfangen. Du kannst beides unter _Install > AI_ im Omarchy Menu installieren.

### Der Omarchy Skill

Agent Skills helfen AI, spezifische Tools auf eine spezifische Weise zu verwenden, und Omarchy liefert einen Standard-Skill zum Maßschneidern des Systems mit. Wie deine Hyprland-Konfiguration anzupassen, die Leiste zu justieren oder sogar ein neues Theme von Grund auf zu erstellen. Er ist in die Skill-Verzeichnisse für Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` und jedes `~/.hermes/profiles/*/skills`) und den generischen Ort `~/.agents/skills` symlinkt, sodass die meisten Harnesses ihn automatisch aufnehmen.

Aber du solltest diesen Skill als experimentell behandeln. Verschiedene Modelle werden ihn mit unterschiedlicher Wirkung verwenden. Am besten lässt du ihn zuerst im Plan-Modus laufen, sodass du eine Vorstellung davon hast, was der Agent gern ändern würde. Und sei dann bereit, Änderungen zurückzurollen oder sogar `omarchy reinstall configs` aufzurufen, wenn der Agent aus allem ein Chaos macht.
