# KI

Omarchy behandelt KI-Coding-Agenten als Bürger erster Klasse, wählt aber keinen Favoriten für dich aus. Stattdessen ist jede wichtige Coding-Agent-CLI vorverkabelt als lazy-loaded Launcher mit dabei. Die Launcher sind winzige, von [mise](https://mise.jdx.dev/) verwaltete Stubs in `~/.local/bin/`, sodass nichts heruntergeladen wird, bis du einen davon zum ersten Mal tatsächlich ausführst. Hermes ist die Ausnahme: Dafür wird kein Stub angelegt, und wenn du es auswählst, wird Hermes Desktop installiert, wie unten unter _Desktop-Apps_ erklärt wird. Rufe einen davon auf und authentifiziere dich, wenn du dazu aufgefordert wirst:

| Befehl    | Agent                                                            |
|------------|------------------------------------------------------------------|
| `claude`   | [Claude Code](https://code.claude.com/docs/en/overview)          |
| `codex`    | [OpenAI Codex](https://github.com/openai/codex)                  |
| `opencode` | [OpenCode](https://opencode.ai/)                                 |
| `agy`      | [Google Antigravity CLI](https://github.com/google-antigravity/antigravity-cli) |
| `copilot`  | [GitHub Copilot CLI](https://github.com/github/copilot-cli)      |
| `crush`    | [Crush](https://github.com/charmbracelet/crush)                  |
| `grok`     | [Grok Build](https://x.ai/build) von xAI                        |
| `kimi`     | [Kimi Code](https://www.kimi.com/code/docs/en/)                  |
| `pi`       | [Mario Zechners Pi](https://github.com/badlogic/pi-mono)        |
| `omp`      | [Oh My Pi](https://github.com/can1357/oh-my-pi)                  |
| `ori`      | [Ori](https://openrouter.ai/docs/guides/ori/harness), OpenRouters Harness |
| `hermes`   | [Hermes](https://hermes-agent.nousresearch.com/), Agent von Nous Research  |
| `muse`     | [Muse Code](https://dev.meta.ai), Metas Coding-Agent           |
| `cursor-agent` | [Cursor CLI](https://cursor.com/cli)                         |

`ori` ist der Sonderfall: Es führt die anderen Harnesses gegen OpenRouters gesamten Modellkatalog aus, sodass `ori claude`, `ori codex` oder `ori opencode` diese Agenten auf welchem Modell auch immer starten, auf das du sie ausrichtest, und `ori code` ist Oris eigener Agent.

Um eine zusätzliche CLI auf die gleiche Weise einzubinden, führe `omarchy-mise-install <package> [command-name]` aus. Die Stubs werden zusammen mit allem anderen, was mise verwaltet, aktuell gehalten, wenn du `omarchy update` (oder den Alias `mup`) ausführst.

`grok` wird über mises offizielles `grok`-Paket installiert, auf die gleiche Weise wie `claude` und `codex`. Führe `grok` aus oder wähle es unter _Setup > Defaults > Agent_ aus. Lass den `curl | bash`-Installer auf x.ai weg. Dieser Weg legt eine zweite Kopie in `~/.grok/bin` ab, stellt es im `PATH` an den Anfang und überschreibt Omarchys Wrapper.

### Der Standard-Agent

Wähle deinen Standard-Agenten mit `omarchy default agent <name>` oder im Omarchy Menu (`Super + Space`) unter _Setup > Defaults > Agent_. Wenn der Agent noch nicht installiert ist, wird er durch die Auswahl zuerst installiert. Ein frisches Omarchy lädt dich mit einer einmaligen Benachrichtigung dazu ein, diese Auswahl zu treffen.

Wenn du Claude wählst, wird auch versucht, dessen Browser-Erweiterung für Chromium, Chrome, Brave, Brave Origin und Edge einzurichten. Die Einrichtung der Erweiterung gilt für alle Benutzer und fragt möglicherweise nach deinem Systempasswort; Abbrechen oder eine fehlgeschlagene Installation der Erweiterung wählt Claude trotzdem aus und startet es. Starte deinen Browser neu, aktiviere die Erweiterung, falls du dazu aufgefordert wirst, und melde dich bei Claude an, um die Verbindung fertigzustellen. Führe in Claude `/chrome` aus, um die Verbindung zu prüfen. Firefox und Zen unterstützen diese Erweiterung nicht. Wenn Claude bereits dein Standard war, bevor diese Einrichtung hinzugefügt wurde, wähle es erneut aus, um die Erweiterung zu installieren.

[Muse Code](https://dev.meta.ai) — Metas `muse` — nutzt wie die anderen Agenten einen vorinstallierten mise-Stub. Wenn du es als Standard auswählst, wird Metas offizieller Launcher über mises HTTP-Backend installiert. Der Launcher überprüft und aktualisiert die native Binärdatei für deine Maschine.

Sobald du gewählt hast, startet `Super + Shift + Ctrl + A` den Standard-Agenten in einem dedizierten Terminalfenster (oder ruft die Auswahl auf, wenn du noch nicht gewählt hast). Du kannst ihn mit `omarchy agent prompt "Review this project"` auch direkt in eine Aufgabe starten. Auf diese Weise gestartete Agenten laufen unbeaufsichtigt in ihren jeweiligen „nicht anhalten, um zu fragen“-Modi, also sei darauf gefasst, dass sie tatsächlich Dinge tun! Und da Agenten sich weigern, sich Vertrauen für dein Home-Verzeichnis zu merken, starten Starts von `$HOME` stattdessen in `~/Work`.

Es gibt auch Terminal-Shortcuts: `a` führt den Standard-Agenten inline im aktuellen Terminal aus, während `c`, `cx` und `cy` OpenCode, Claude Code und Codex direkt starten (wieder in ihren automatisch genehmigenden Modi). Theme-Wechsel werden auch mit den Agenten synchronisiert: Claude Code, Pi, OpenCode und Hermes (s sobald Omarchy es installiert hat) folgen alle, wenn du das Omarchy-Theme wechselst.

### Das Agenten-Panel

Die obere Leiste hat ein Agenten-Symbol. Bevor du einen Agenten eingerichtet hast, führt sein Panel dich durch die Anmeldung bei Claude, Codex oder Grok, und der erste wird dein Standard-Agent. Danach stellt das Panel jedes Abonnement auf eine Seite: jeder Agent und jedes Konto mit seinem Plan, eine Anzeige für jedes seiner 5-stündigen Sitzungs- und wöchentlichen Limits mit der Zeit bis zum Zurücksetzen (bewege den Zeiger darüber für den exakten Prozentsatz) oder das verbleibende Prepaid-Guthaben, unter einer Zeile, die durchrotiert, was du über alle hinweg verbraucht hast, wie Token in dieser Woche und dein am häufigsten genutztes Modell. Unter _Make something_ bietet es Starter-Prompts für ein neues Theme, Plugin oder eine App, die die Aufgabe an deinen Standard-Agenten übergeben. Apps werden so gebaut, wie Omarchys eigene Hype, Monologue und Omacut gebaut werden, in C++ und Qt Quick, nach dem omarchy-app-Agent-Skill, und der Compiler sowie die Qt-Teile, die sie brauchen, sind installiert dabei. Claude Code, Codex, Grok, Fireworks und Kimi werden direkt ab Werk abgedeckt. Kimi meldet derzeit Kontingentlimits für das Konto, ohne lokale Token- oder Prompt-Statistiken.

Klicke mit der linken Maustaste auf das Leisten-Symbol für das Panel, mit der rechten, um deinen Standard-Agenten zu starten. Die dahinterliegenden Nutzungsdatensätze werden alle 15 Minuten von `omarchy agent usage-update` neu erzeugt, und das Panel kann sogar die Nutzung von deinen anderen Maschinen über einen synchronisierten Ordner zusammenführen. Sieh dir für die vollständigen Einstellungen die README unter `$OMARCHY_PATH/shell/plugins/agents/` an.

### Mehrere Abonnements

Wenn du für mehr als einen Claude-, Codex- oder Grok-Plan zahlst — sagen wir ein persönliches Max und eins für die Arbeit — kann Omarchy sie alle angemeldet halten und zwischen ihnen wechseln. Füge ein Abonnement mit dem + im Agenten-Panel hinzu, das dich direkt dort hindurchführt, oder mit `omarchy agent account add claude Work` (oder `codex` oder `grok`). Es installiert die CLI, wenn sie fehlt. Das erste Konto für einen Anbieter meldet sich über deinen normalen Browser an, genau dort, wo die CLI immer nachsieht. Jedes danach meldet sich über ein privates Fenster an, damit das Konto, bei dem dein Browser bereits angemeldet ist, nicht versehentlich aufgeschnappt wird; melde dich dort als das Konto an, das du hinzufügst, und schließe zuerst jedes private Fenster, das du bereits offen hattest. Melde dich dafür niemals von der CLI ab: Abmelden widerruft die gespeicherte Anmeldung, und dieses Konto müsste erneut hinzugefügt werden.

Um deine Abonnement-Anmeldungen über SSH auf eine andere Omarchy-Maschine zu kopieren, führe `omarchy agent account copy user@laptop` aus. Der Sender liefert einen temporären Empfänger, wenn das Ziel keinen installiert hat, sodass ältere Omarchy-Maschinen Konten ohne ein Update empfangen können. Installierte Empfänger haben Vorrang. Dies kopiert alle Claude-, Codex- und Grok-Abonnements; füge Anbieternamen hinzu, um sie auszuwählen, wie in `omarchy agent account copy laptop claude`. Kontonamen und Befehls-IDs stimmen mit der Quelle überein, einschließlich Konten, die bereits auf dem Ziel vorhanden sind. Nicht zugehörige Zielkonten erhalten ein numerisches Suffix, wenn ihre Namen in Konflikt geraten, und Einstellungen, Skills, Plugins sowie der Gesprächsverlauf bleiben lokal auf jeder Maschine.

Bestehende Zugangsdaten auf dem Ziel bleiben erhalten. Bei einem Quellkonto, das dort bereits angemeldet ist, wird sein Name synchronisiert, ohne seine Zugangsdaten zu ersetzen; andere Konten werden daneben hinzugefügt. Um gespeicherte Zugangsdaten für übereinstimmende Konten zu ersetzen, verwende `omarchy agent account copy --replace laptop claude`, nachdem du die Sitzungen dieses Kontos auf dem Ziel beendet hast. Ein frisches Ziel bekommt auch das aktive Konto und die Wechselpräferenzen der Quelle; ein eingerichtetes Ziel behält seine eigenen.

Zugangsdaten reisen durch SSH und werden auf dem Ziel in privaten Dateien gespeichert, also kopiere nur auf Maschinen, denen du vertraust. Dies ist eine einmalige Kopie, keine laufende Synchronisierung. Codex-Refresh-Token können von einer anderen Maschine rotiert werden, wodurch eine kopierte Anmeldung erneuert werden muss; separate Anmeldungen bleiben die zuverlässigste Wahl für die gleichzeitige Nutzung auf mehreren Maschinen. Siehe [Anleitung von Codex zur Kontoauthentifizierung](https://developers.openai.com/codex/auth/ci-cd-auth).

Ein Konto pro Anbieter ist aktiv, und jede neue Sitzung startet als dieses: `cx`, `cy`, ein einfaches `claude`, `codex` oder `grok`, alles, was über `omarchy agent` gestartet wird, und Skripte oder Editoren, die die CLI im `PATH` finden. Wechsle mit `omarchy agent account use work` (und zurück mit `omarchy agent account use main`) oder im Panel, indem du die Nummer eines Kontos drückst und dann `Enter` (oder auf seine Use-Schaltfläche klickst). Sitzungen, die bereits laufen, bleiben bei dem Konto, mit dem sie gestartet sind. Gesprächsverlauf, Einstellungen, Skills und Plugins werden über Konten hinweg geteilt, sodass `claude --continue` im selben Ordner dort weitermacht, wo du auf dem neuen Konto aufgehört hast.

Mit mehr als einem Konto zeigt das Panel die Limits jedes Kontos nebeneinander, wobei das aktive markiert ist. Standardmäßig benachrichtigt Omarchy dich, wenn das aktive Konto 95 % eines Limits überschreitet, und ein Klick auf die Benachrichtigung wechselt zu dem Konto mit dem meisten Spielraum. Bewege den Zeiger über die Zeile eines Kontos im Panel und klicke auf den Autoswitch, der neben Use erscheint (oder drücke `m`), oder führe `omarchy agent account mode auto` aus, damit es stattdessen von selbst wechselt; solange es aktiv ist, nimmt Autoswitch den Platz von Use ein, und ein erneuter Klick darauf geht zurück zum Benachrichtigen. Füge eine Zahl hinzu, um den Schwellenwert zu ändern, wie in `omarchy agent account mode auto 90`. Wenn jedes Konto über dem Schwellenwert ist, erfährst du es einmal, zusammen damit, welches Konto zuerst wieder frei wird. Solange ein aktives Konto innerhalb von 15 Punkten an seinem Schwellenwert ist (80 % beim Standard), werden seine Limits alle drei Minuten anstatt alle 15 geprüft.

`omarchy agent account list` zeigt jedes Konto und seine neuesten Limits, `omarchy agent account remove work` vergisst eines, und `omarchy agent account rename primary Hey` benennt eines um (oder klicke im Panel auf den Namen eines Kontos). Diese Befehle wirken auf die Konten deines Standard-Agenten; um den anderen Anbieter zu erreichen, nenne ihn zuerst, wie in `omarchy agent account use codex side`. Die Anmeldung, die du bereits in `~/.claude` oder `~/.codex` hattest, ist das _Main_-Konto und bleibt, wo sie ist. Ein Konto, das mehr als etwa acht Stunden ungenutzt geblieben ist, kann _Sign-in required_ anzeigen; klicke darauf, um dieses Konto direkt im Panel erneut anzumelden, oder starte eine Sitzung darin, was die Anmeldung von selbst auffrischt. MCP-Server, die du hattest, als ein Konto hinzugefügt wurde, kommen mit zu ihm, aber solche, die du später mit `claude mcp add` hinzufügst, erreichen nur das Konto, in dem du sie hinzugefügt hast. Claude Desktop und Tools, die mit einem absoluten Pfad zu einer CLI-Binärdatei konfiguriert sind, folgen dem Wechsel nicht. Ein explizites `CLAUDE_CONFIG_DIR`, `CODEX_HOME` oder `GROK_HOME` hat Vorrang vor dem ausgewählten Konto.

### Absturzdiagnose

Omarchy überwacht systemd-coredump auf Prozessabstürze. Wenn etwas einen Segfault hat, bekommst du eine "Process crashed"-Benachrichtigung — klicke darauf, und der Absturz wird zusammen mit Omarchys diagnose-crash-Skill an deinen Standard-Agenten übergeben, der den Agenten hindurchführt, die Fakten aus dem Core Dump festzustellen und zu entscheiden, ob der Absturz es wert ist, upstream gemeldet zu werden. Du kannst ihn auch von Hand gegen jede PID aus `coredumpctl list` mit `omarchy agent crash <pid>` ausführen.

Die Überwachung ist standardmäßig aktiviert. Schalte sie unter _Trigger > Toggle > Crash Capture_ (oder mit `omarchy toggle crash-capture`) aus und die Benachrichtigungen hören auf; `omarchy agent crash <pid>` funktioniert immer noch von Hand.

Abstürze können auch ein Programm nach dem anderen stummgeschaltet werden, was dir die Diagnose am Ende anbietet. `omarchy crash mute hyprland` stoppt die Benachrichtigungen nur für dieses Programm, `omarchy crash mute hyprland off` bringt sie zurück, und `omarchy crash mute` für sich allein listet auf, was du stummgeschaltet hast. Es nimmt den Pfad der Binärdatei ebenso gern wie ihren Namen, sodass `omarchy crash mute /usr/bin/hyprland` dasselbe tut. Setze einen Namen mit einem Leerzeichen in Anführungszeichen, wie in `omarchy crash mute 'Some App'`. Alles andere benachrichtigt weiterhin, und das stummgeschaltete Programm stürzt weiterhin ab — dies verbirgt die Erinnerung, es repariert nichts.

### Desktop-Apps

Das Menü _Install > AI_ enthält auch ein paar grafische KI-Apps: die ChatGPT-Desktop-App, die Claude-Desktop-App (Anthropics Linux-Beta, mit Chat-, Cowork- und Claude Code-Tabs), Grok Bot zum Chatten mit xAIs Modellen, Hermes Desktop, OpenClaw und die Perplexity-Desktop-App. Grok Bot ist die Desktop-Chat-App. Der Coding-Agent ist der `grok`-Befehl.

Hermes Desktop ist die, über die man Bescheid wissen muss, denn eine Maschine hat ein Hermes, und es gehört der App: Hermes wird immer nur über die App installiert, und der `hermes`-Befehl, den der Standard-Agent ausführt, gehört der App. Hermes als Standard-Agent zu wählen installiert dasselbe wie der Eintrag _Install > AI_: das Paket und eine Hermes-Laufzeitumgebung unter `~/.hermes`, eingerichtet von Hermes' eigenem Installer, was beim ersten Mal ein paar Minuten dauert. Diese Laufzeitumgebung ist das eine Hermes, das der Terminal-Befehl `hermes`, der Standard-Agent und die App alle verwenden, und sie aktualisiert sich selbst mit `hermes update`, anstatt auf ein Omarchy-Release zu warten. Die Installation übergibt Hermes auch das Omarchy-Theme als Skin namens `omarchy`, dem jede Hermes-Oberfläche folgt, während du Themes wechselst; wähle unter Hermes' Appearance-Einstellungen oder mit `/skin` einen anderen, wenn du lieber willst, dass er das nicht tut, und Omarchy lässt diese Wahl in Ruhe. Das Entfernen der App unter _Remove > AI_ schließt Hermes zuerst, Gateway eingeschlossen, nimmt diese Laufzeitumgebung mit und behält deine Chats, Erinnerungen und die Skills, die Hermes für sich selbst geschrieben hat, es sei denn, du sagst ihm etwas anderes: Es fragt, mit Nein als Standard, ob diese Daten und deine Verbindungseinstellungen auch weg sollen.

OpenClaws Desktop-Erlebnis ist seine Control UI, die sich als Web-App öffnet, gestützt von seinem eigenen lokalen Gateway. OpenClaw lebt in `~/.openclaw` und aktualisiert sich selbst: Verwende die "Update Gateway"-Schaltfläche der Control UI oder führe `openclaw update` aus, und das Gateway startet mit der neuen Version neu. Omarchy wählt nur das Release, von dem eine frische Installation startet. Das Entfernen von OpenClaw unter _Remove > AI_ nimmt den Gateway-Dienst und die App mit und fragt dann, ob `~/.openclaw` auch weg soll, da dies deine Chats und Zugangsdaten neben OpenClaw selbst und den Plugin-Laufzeitumgebungen enthält, die es herunterlädt; der Standard behält es, und OpenClaw erneut zu installieren greift es wieder auf.

### Lokale LLMs

Omarchy empfiehlt zwei Wege, lokale LLM-Modelle auszuführen: LM Studio und Ollama. LM Studio bietet eine GUI-Oberfläche, um Open-Weight-Modelle zu finden, sie zu installieren und sie auszuführen. Das ist ein großartiger Weg, um einfach loszulegen. Ollama bietet eine CLI, um dasselbe ähnlich zu tun. Aber wenn lokale Modelle neu für dich sind, würde ich mit LM Studio anfangen. Du kannst beides im Omarchy Menu unter _Install > AI_ installieren.

### Der Omarchy-Skill

Agent-Skills helfen KI, bestimmte Tools auf eine bestimmte Weise zu nutzen, und Omarchy wird mit einem Standard-Skill ausgeliefert, um das System maßzuschneidern. Wie deine Hyprland-Konfiguration zu tweaken, die Leiste anzupassen oder sogar ein neues Theme von Grund auf zu erstellen. Er ist in die Skill-Verzeichnisse für Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` und jedes `~/.hermes/profiles/*/skills`) sowie den generischen Ort `~/.agents/skills` symgelinkt, sodass die meisten Harnesses ihn automatisch aufgreifen.

Aber du solltest diesen Skill als experimentell behandeln. Verschiedene Modelle werden ihn mit unterschiedlicher Wirkung nutzen. Es ist am besten, zuerst im Plan-Modus zu laufen, damit du eine Vorstellung davon hast, was der Agent gern ändern würde. Und sei dann bereit, Änderungen zurückzunehmen oder sogar `omarchy reinstall configs` aufzurufen, wenn der Agent aus allem ein Chaos macht.
