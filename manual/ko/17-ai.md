# AI

Omarchy는 아래 코딩 에이전트용 런처를 포함하지만, 기본값을 대신 골라 주지는 않는다. 명령을 실행하면 처음 사용할 때 해당 CLI를 설치하고, 안내가 나오면 인증한다. Hermes와 OpenClaw는 예외다: mise를 통해 설치되는 것은 아무것도 없으며, 둘 중 하나를 선택하면 자체 업데이트되는 자체 복사본을 설정하는데, 아래 _Desktop apps_에서 설명한다.

### 에이전트 설치 및 업데이트

Hermes와 OpenClaw를 제외하고, 이 에이전트들은 mise의 지연 설치를 사용한다: 처음 실행할 때 CLI를 설치하고, 이후 실행에서는 그것을 재사용한다. mise는 또한 시작 직전이나 셸 프롬프트에서 백그라운드로, 최대 네 시간에 한 번 설치된 에이전트의 새 릴리스가 있는지 확인한다. 업데이트가 실패하거나 오프라인 상태이면, 설치된 버전이 실행된다. `omarchy update`는 Omarchy의 나머지 부분과 함께 설치된 에이전트들을 업데이트하고, `mup`은 mise가 관리하는 도구만 업데이트한다.

`claude update`, `codex update`와 같은 에이전트 자체 업데이터나 앱의 업데이트 버튼은 mise가 관리하는 설치를 업데이트하지 않는다. `codex update`는 실패하고, `claude update`는 성공했다고 보고하면서도 mise가 추적하지 않는 별도의 복사본을 설치할 수 있다. 차라리 에이전트의 기본 설치 프로그램과 업데이터를 사용하고 싶다면, 그것을 `disable_tools`에 추가하라; [사전 설치된 CLI 도구](18-development-tools.md#preinstalled-cli-tools)를 보라.

필요해지기 전에 구성된 모든 지연 도구를 설치하려면, `mise install --include-lazy`를 실행하라. 여기에는 에이전트뿐만 아니라 Omarchy의 다른 기본 CLI 도구도 포함된다. 단일 도구를 설치하거나 직접 설치한 것을 사용하는 방법은 [사전 설치된 CLI 도구](18-development-tools.md#preinstalled-cli-tools)를 보라.

`grok`은 `claude` 및 `codex`와 같은 방식으로 mise의 공식 `grok` 패키지를 통해 설치된다. `grok`을 실행하거나, 에이전트 패널에서 별표를 표시하라. x.ai의 `curl | bash` 설치 프로그램은 건너뛰라. 그 경로는 `~/.grok/bin`에 두 번째 복사본을 넣고, 그것을 `PATH` 앞에 추가하며, Omarchy의 래퍼를 덮어쓴다.

`dsh`는 `127.0.0.1:3080`에서 브라우저 UI를 열며, 실행 디렉터리를 기본 워크스페이스로 사용한다. 브라우저 UI는 시작 프롬프트를 받지 않으므로, `omarchy agent prompt`는 붙여 넣을 수 있도록 프롬프트를 클립보드에 담은 채로 그것을 연다. Omarchy는 DeepSeek의 무승인 권한 프리셋으로 그것을 시작한다. DeepSeek Harness는 공식 모델 API를 사용할 때 세션 로그를 DeepSeek에 업로드한다; 브라우저 UI의 _Settings > General > Upload Session Log_ 아래에서 그것을 끌 수 있다. 전송하는 피드백도 세션과 함께 업로드되며, `DSH_TELEMETRY_MODE=DISABLED`로 시작하면 그렇지 않다.

### 기본 에이전트

에이전트 패널에서 에이전트 옆의 별표로 기본 에이전트를 선택한다. 별표는 기본 에이전트에서 채워져 있다. 또는 `omarchy default agent <name>`으로도 선택할 수 있으며, 이 명령은 거기에 줄이 없는 하네스도 무엇이든 받는다. 에이전트가 아직 설치되지 않았다면, 선택하면 먼저 설치하고, 앱 런처에서 Agent 옆에 자체 런처도 생긴다. 새로 설치한 Omarchy는 일회성 알림으로 설정을 권유하며, 이 알림은 에이전트 패널을 연다.

Claude를 선택하면 Chromium, Chrome, Brave, Brave Origin, 그리고 Edge용 브라우저 확장 프로그램도 설정을 시도한다. 확장 프로그램 설정은 모든 사용자에게 적용되며 시스템 비밀번호를 물을 수 있다; 확장 프로그램 설치를 취소하거나 실패하더라도 Claude는 여전히 선택되고 실행된다. 브라우저를 다시 시작하고, 안내가 나오면 확장 프로그램을 활성화한 뒤, Claude에 로그인하여 연결을 완료하라. Claude에서 `/chrome`를 실행하여 연결을 확인하라. Firefox와 Zen은 이 확장 프로그램을 지원하지 않는다. 이 설정이 추가되기 전에 이미 Claude가 기본값이었다면, 그것을 다시 선택하여 확장 프로그램을 설치하라.

선택을 마쳤으면, `Super + Shift + Ctrl + A`는 전용 터미널 창에서 기본 에이전트를 실행한다(또는 아직 선택하지 않았다면 선택기를 띄운다). `omarchy agent prompt "Review this project"`로 작업을 바로 맡기며 실행할 수도 있다. Freebuff와 DeepSeek Harness는 시작 프롬프트를 받지 않으므로, 대신 붙여 넣을 프롬프트를 클립보드에 담은 채로 열린다. 이런 방식으로 실행된 에이전트들은 각자의 묻지 않고 멈추지 않는 모드에서 무인으로 실행되므로, 실제로 무언가를 해낼 각오를 하라! MiniMax Code는 대화형 세션에 그런 모드가 없어서, 평소대로 권한을 묻는다. 그리고 에이전트들은 홈 디렉터리에 대한 신뢰를 기억하기를 거부하므로, `$HOME`에서 실행하면 대신 `~/Work`에서 시작한다.

터미널 단축키도 있다: `a`는 현재 터미널 안에서 인라인으로 기본 에이전트를 실행하고, `c`, `cx`, 그리고 `cy`는 OpenCode, Claude Code, 그리고 Codex를 직접 시작한다(역시 자동 승인 모드로). 테마 변경도 에이전트에 동기화된다: Omarchy 테마를 전환하면 Claude Code, Pi, OpenCode, 그리고 Hermes(Omarchy가 설치한 후) 모두 따라온다.

### 에이전트 지침

모든 에이전트를 위한 개인 규칙은 `~/.agents/skills`의 공유 스킬 옆에 있는 `~/.agents/AGENTS.md`에 들어간다. 에이전트 패널에서 + 옆의 문서 아이콘으로 열거나, `omarchy agent instructions --edit`로 연다. 후자는 자체 전역 파일을 유지하는 각 하네스에도 그것을 연결한다: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, Copilot의 `~/.copilot/copilot-instructions.md` 등이다. Crush와 Amp는 `~/.config/AGENTS.md` 링크를 읽고, omp, Kimi, 그리고 DeepSeek Harness는 `~/.agents/AGENTS.md`를 직접 읽는다. 기본 에이전트를 선택하면 그것도 연결된다. 이미 가지고 있던 지침 파일은 아직 공유 파일이 없었다면 공유 파일이 되고, 그렇지 않다면 링크 옆에 `.bak`으로 보관된다. 다른 에이전트를 설치한 후 다시 연결하려면 `omarchy agent instructions`를 실행하라.

### 에이전트 패널

상단 바에는 에이전트 아이콘이 있다. 에이전트를 설정하기 전에, 그 패널은 시작할 수 있는 세 가지 방법을 제공한다: Claude, Codex, Grok, Gemini, Muse, Cursor, 또는 Copilot 구독에 로그인하거나, More 아래의 OpenCode Go, MiniMax, Synthetic, 또는 Z.ai 코딩 플랜에 로그인하는 것; Fireworks, OpenCode Zen and Go, OpenRouter로 사용한 만큼 지불하거나, More 아래의 DeepSeek 또는 OpenCode가 로그인하는 다른 어떤 제공자로 지불하는 것으로, 모두 OpenCode에서 실행된다; 또는 컴퓨터에 맞는 모델이 있을 때, 컴퓨터에 가장 좋은 모델을 실행하는 것이다. 처음 완료한 것이 기본 에이전트가 되고, 패널의 +는 나중에 같은 세 가지를 제공한다. 그 후, 패널은 모든 구독을 한 페이지에 표시한다: 각 에이전트와 계정 및 플랜, 각 5시간 세션 및 주간 한도에 대한 미터와 재설정까지 남은 시간(정확한 백분율은 마우스를 올려 확인), 또는 남은 선불 잔액이, 이번 주 토큰 수와 가장 많이 사용한 모델처럼 전체에서 사용한 내용을 순환하며 보여주는 줄 아래에 표시된다. _Make something cool_ 아래에서는 새 테마, 플러그인, 앱, 또는 게임을 위한 시작 프롬프트를 제공하며, 작업을 기본 에이전트에게 맡긴다. 앱은 Omarchy 자체의 Hype, Monologue, 그리고 Omacut이 만들어진 방식대로 C++와 Qt Quick으로 만들어지며, omarchy-make-app 에이전트 스킬을 따르고, 필요한 컴파일러와 Qt 구성 요소는 설치되어 제공된다. 게임은 `~/Games/vibes`에 있는 단일 three.js 페이지로, omarchy-make-game 에이전트 스킬을 따르며, 모두 현재 테마의 하나의 Game Vibes 런처에서 열린다; three.js를 웹에서 불러오므로 시작하려면 연결이 필요하다. Claude Code, Codex, Grok, Kimi, Cursor와 그 Grok Bot 할당량, GitHub Copilot, Muse, Gemini(Antigravity를 통해), 그리고 Devin은 한도와 함께 기본으로 다루어지고, Kimchi는 플랜, 선불 크레딧, 그리고 지출 예산과 함께 다루어지며, Hermes, Mistral Vibe, 그리고 Qwen Code는 사용한 후 세션과 토큰을 표시한다. pi, omp, 또는 opencode를 통해 사용하는 제공자 플랜과 키도 표시된다: OpenCode Zen and Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan, 그리고 Synthetic이 한도와 함께 표시되고; OpenRouter와 DeepSeek는 선불 잔액과 함께 표시되며; Fireworks는 지난 30일간 지출과 함께 표시된다. 자신의 하드웨어에서 실행하는 코딩 모델은 자체 줄을 가지며, 그 토큰도 [로컬 모델](#local-models) 아래에서 설명한 대로 합계에 포함된다. 모든 에이전트는 몇 개의 하네스를 통해 구동하든, 요금을 청구하는 쪽 아래에서 한 번만 집계된다.

바 아이콘을 왼쪽 클릭하거나 `Super + Ctrl + X`를 눌러 패널을 열고, 오른쪽 클릭하여 기본 에이전트를 실행하며, 가운데 클릭하여 새로 고친다. 그 뒤의 사용 기록은 `omarchy agent usage update`에 의해 15분마다 재생성되며, 패널은 동기화된 폴더를 통해 다른 컴퓨터의 사용량까지 병합할 수 있다. 전체 설정은 `$OMARCHY_PATH/shell/plugins/agents/` 아래의 README를 보라.

### 여러 구독

개인 Max와 업무용처럼, Claude, Codex, 또는 Grok 플랜을 두 개 이상 지불하고 있다면, Omarchy는 모두 로그인 상태를 유지하고 그 사이를 이동할 수 있다. 에이전트 패널의 +로 구독을 추가하면 거기에서 바로 과정을 안내하거나, `omarchy agent account add claude Work`(또는 `codex`, 또는 `grok`)로 추가한다. 같은 +와 명령으로 Gemini(`gemini`)와 OpenCode(`opencode`)에 로그인하고, Fireworks(`fireworks`) 또는 OpenRouter(`openrouter`) API 키를 OpenCode에 저장한다; 이 명령은 Copilot(`copilot`), Cursor(`cursor`), 그리고 Muse(`muse`)에도 로그인한다. 이것들은 각각 단일 로그인을 유지한다. 누락되었다면 CLI를 설치한다. 제공자의 첫 번째 계정은 CLI가 항상 찾는 곳에서, 일반 브라우저를 통해 로그인한다. 그 이후의 모든 계정은 비공개 창을 통해 로그인하므로, 브라우저에 이미 로그인된 계정이 실수로 선택되지 않는다; 거기에서 추가하려는 계정으로 로그인하고, 이미 열려 있던 비공개 창은 먼저 닫으라. 이를 위해 CLI에서 절대 로그아웃하지 마라: 로그아웃하면 저장된 로그인이 취소되며, 그 계정을 다시 추가해야 한다.

SSH를 통해 구독 로그인을 다른 Omarchy 컴퓨터로 복사하려면, `omarchy agent account copy user@laptop`을 실행하라. 목적지에 수신기가 설치되어 있지 않으면 발신자가 임시 수신기를 제공하므로, 구형 Omarchy 컴퓨터도 업데이트 없이 계정을 받을 수 있다. 설치된 수신기가 우선한다. 이는 모든 Claude, Codex, 그리고 Grok 구독을 복사한다; `omarchy agent account copy laptop claude`처럼 제공자 이름을 추가하여 선택할 수 있다. 계정 이름과 명령 ID는 목적지에 이미 있는 계정을 포함하여 소스와 일치한다. 이름이 충돌하는 관련 없는 목적지 계정은 숫자 접미사를 받으며, 설정, 스킬, 플러그인, 그리고 대화 기록은 각 컴퓨터에 로컬로 남는다.

기존 목적지 자격 증명은 유지된다. 거기에 이미 로그인된 소스 계정은 자격 증명을 교체하지 않고 이름이 동기화되고; 다른 계정들은 그 옆에 추가된다. 일치하는 계정의 저장된 자격 증명을 교체하려면, 목적지에서 그 계정의 세션을 종료한 후 `omarchy agent account copy --replace laptop claude`를 사용하라. 새로운 목적지는 소스의 활성 계정과 전환 기본 설정도 받으며; 확립된 목적지는 자체 설정을 유지한다.

자격 증명은 SSH를 통해 이동하고 목적지의 비공개 파일에 저장되므로, 신뢰하는 컴퓨터로만 복사하라. 이는 일회성 복사이며 지속적인 동기화가 아니다. Codex 새로 고침 토큰은 다른 컴퓨터에 의해 교체될 수 있어, 복사된 로그인을 갱신해야 할 수 있다; 여러 컴퓨터에서 동시에 사용하려면 별도의 로그인이 가장 확실한 선택으로 남는다. [Codex's account authentication guidance](https://developers.openai.com/codex/auth/ci-cd-auth)를 보라.

제공자당 하나의 계정이 활성화되며, 모든 새 세션은 그 계정으로 시작한다: `cx`, `cy`, 일반적인 `claude`, `codex`, 또는 `grok`, `omarchy agent`를 통해 실행되는 모든 것, 그리고 `PATH`에서 CLI를 찾는 스크립트나 편집기가 그렇다. `omarchy agent account use work`로 전환하고(`omarchy agent account use main`으로 돌아온다), 또는 패널에서 계정의 번호를 누른 뒤 `Enter`를 누르거나(또는 별표를 클릭하여) 전환한다. 실행 중인 Claude 세션도 다음 메시지부터 전환한다: 모든 Claude 세션은 항상 활성 계정의 로그인을 보유하는 `~/.claude`에서 실행된다. 구형 Omarchy에 의해 계정 자체 폴더에서 시작된 Claude 세션은 종료될 때까지 그 로그인을 유지하므로, 전환은 해당 세션들의 이름을 표시하고 그것들이 사라지면 저절로 완료된다. 실행 중인 Codex와 Grok 세션은 시작할 때 사용한 계정에 머무른다. 대화 기록, 설정, 스킬, 그리고 플러그인은 계정 간에 공유되므로, 같은 폴더에서 `claude --continue`를 실행하면 새 계정에서 중단한 곳부터 이어간다.

계정이 두 개 이상이면, 패널은 각 계정의 한도를 나란히 표시하고, 사용 중인 계정에는 채워진 별표가 표시된다. Omarchy는 활성 계정이 한도의 95%를 초과하면 알리고, 알림을 클릭하면 가장 여유가 많은 계정으로 전환한다. 저절로 전환하지는 않는다. `omarchy agent account threshold 90`으로 임계값을 변경하라. 모든 계정이 임계값을 초과하면, 어떤 계정이 가장 먼저 여유가 생기는지와 함께 한 번 알림을 받는다. 활성 계정이 임계값에서 15포인트 이내에 있는 동안(기본값에서는 80%), 한도는 15분마다가 아니라 3분마다 확인된다.

`omarchy agent account list`는 모든 계정과 최신 한도를 표시하고, `omarchy agent account remove work`는 하나를 잊으며, `omarchy agent account rename primary Hey`는 하나의 이름을 바꾼다(또는 패널에서 계정 이름을 클릭한다). 이 명령들은 기본 에이전트의 계정에 대해 동작한다; 다른 제공자에 접근하려면 `omarchy agent account use codex side`처럼 먼저 이름을 지정하라. `~/.claude` 또는 `~/.codex`에 이미 가지고 있던 로그인이 _Main_ 계정이다. Codex의 것은 있던 자리에 머무르고; Claude의 것은 다른 계정이 활성화되어 있는 동안 자체 폴더에서 기다린다. 약 여덟 시간 이상 사용되지 않은 계정은 _Sign-in required_를 표시할 수 있다; 클릭하면 패널에서 바로 그 계정에 다시 로그인하거나, 그 계정으로 전환하고 세션을 시작하면 저절로 로그인이 새로 고쳐진다. `claude mcp add`로 추가하는 MCP 서버는 모든 Claude 계정에 도달하는데, 모두 `~/.claude`에서 실행되기 때문이다; Codex와 Grok의 경우, 계정이 추가될 때 가지고 있던 서버는 함께 이동하지만, 나중의 서버는 추가한 계정에만 도달한다. Claude Desktop은 자체 로그인을 유지하고, CLI 바이너리에 대한 절대 경로로 구성된 Codex 또는 Grok 도구는 전환을 따르지 않는다. 명시적인 `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, 또는 `GROK_HOME`는 선택한 계정보다 우선한다.

### 충돌 진단

Omarchy는 systemd-coredump에서 프로세스 충돌을 감시한다. 기본 에이전트를 선택했으면, 코어를 덤프하는 자신의 프로그램은 "Process crashed" 알림을 가져온다 — 클릭하면, 충돌이 Omarchy의 omarchy-diagnose-crash 스킬과 함께 기본 에이전트에게 전달되며, 이 스킬은 코어 덤프에서 사실을 확립하고 충돌을 업스트림에 보고할 가치가 있는지 결정하는 과정을 에이전트에게 안내한다. `coredumpctl list`의 어떤 PID에 대해서도 `omarchy agent crash <pid>`로 수동으로 실행할 수도 있다.

감시는 기본적으로 켜져 있다. _Trigger > Toggle > Crash Capture Off_ 아래에서(또는 `omarchy toggle crash-capture`로) 끄면 알림이 중단되고; `omarchy agent crash <pid>`는 여전히 수동으로 동작한다.

충돌은 프로그램별로 한 번에 하나씩 침묵시킬 수도 있는데, 진단이 마지막에 제공하는 것이 바로 그것이다. `omarchy crash mute hyprland`는 그 프로그램에 대해서만 알림을 중단하고, `omarchy crash mute hyprland off`는 다시 가져오며, `omarchy crash mute`만 실행하면 음소거한 항목을 나열한다. 이름만큼이나 바이너리의 경로도 즐겨 받으므로, `omarchy crash mute /usr/bin/hyprland`도 같은 일을 한다. `omarchy crash mute 'Some App'`처럼 공백이 있는 이름은 인용하라. 다른 모든 것은 여전히 알리고, 음소거된 프로그램은 여전히 충돌한다 — 이는 알림을 숨길 뿐, 아무것도 고치지 않는다.

### 데스크톱 앱

_Install > AI_ 메뉴에는 몇 가지 그래픽 AI 앱도 있다: Amp Desktop, Antigravity Desktop, ChatGPT desktop app, Claude desktop app(Chat, Cowork, 그리고 Claude Code 탭이 있는 Anthropic의 Linux 베타), xAI 모델과 채팅하기 위한 Grok Bot, Herdr Desktop, Hermes Desktop, OpenClaw, Perplexity desktop app, 그리고 T3 Code. Grok Bot은 데스크톱 채팅 앱이다. 코딩 에이전트는 `grok` 명령이다.

Hermes Desktop은 알아 두어야 할 앱인데, 컴퓨터에는 하나의 Hermes가 있고, 그것은 앱의 것이기 때문이다: Hermes는 오직 앱을 통해서만 설치되며, 기본 에이전트가 실행하는 `hermes` 명령은 앱의 것이다. Hermes를 기본 에이전트로 선택하면 _Install > AI_ 항목이 하는 것과 같은 것을 설치한다: 패키지, 그리고 Hermes 자체 설치 프로그램이 설정한 `~/.hermes` 아래의 Hermes 런타임으로, 처음에는 몇 분이 걸린다. 그 런타임은 터미널 `hermes` 명령, 기본 에이전트, 그리고 앱이 모두 사용하는 유일한 Hermes이며, Omarchy 릴리스를 기다리지 않고 `hermes update`로 자체 업데이트된다. 설치하면 Hermes에게 Omarchy 테마를 `omarchy`라는 이름의 스킨으로 전달하기도 하며, 모든 Hermes 표면은 테마를 전환할 때 그것을 따른다; 차라리 그렇지 않기를 원한다면 Hermes의 Appearance 설정 아래에서 또는 `/skin`으로 다른 것을 선택하라. 그러면 Omarchy는 그 선택을 그대로 둔다. _Remove > AI_ 아래에서 앱을 제거하면 먼저 게이트웨이를 포함해 Hermes를 닫고, 그 런타임을 함께 가져가며, 그렇지 말라고 지시하지 않는 한 채팅, 메모리, 그리고 Hermes가 스스로를 위해 작성한 스킬은 유지한다: 그 데이터와 연결 설정도 함께 제거할지 묻고, 기본값은 아니오다.

OpenClaw의 데스크톱 경험은 자체 로컬 게이트웨이가 뒷받침하는 웹 앱으로 열리는 Control UI다. OpenClaw는 `~/.openclaw`에 살며 자체 업데이트된다: Control UI의 "Update Gateway" 버튼을 사용하거나 `openclaw update`를 실행하면, 게이트웨이가 새 버전으로 다시 시작한다. Omarchy는 새 설치가 시작할 릴리스만 선택한다. OpenClaw는 기본 에이전트도 될 수 있다: `omarchy default agent openclaw`로 선택하면 `~/.openclaw`에 같은 복사본을 설정하고, 에이전트는 게이트웨이에 연결된 OpenClaw의 터미널 UI를 연다. _Remove > AI_ 아래에서 OpenClaw를 제거하면 게이트웨이 서비스와 앱을 함께 가져간 뒤, 채팅과 자격 증명은 물론 OpenClaw 자체와 다운로드하는 플러그인 런타임을 담고 있는 `~/.openclaw`도 제거할지 묻는다; 기본값은 유지하는 것이며, OpenClaw를 다시 설치하면 그것을 다시 가져온다.

Herdr Desktop은 [Herdr](https://herdr.dev) 데스크톱 앱이다: 창을 닫아도 핵심에서 계속 실행되는 터미널과 코딩 에이전트의 공간, 탭, 그리고 창이다. 패키지가 아니라 Herdr 자체 설치 프로그램에서 제공되므로, `~/.local/share/herdr-app`에 살고, 아직 없을 때 `~/.local/bin/herdr-core`에 핵심을 함께 가져오며, 둘 다 자체 업데이트된다. 이는 교체가 아니라, `Super + Ctrl + Return`으로 Omarchy가 제공하는 `herdr` 명령 옆에 위치하며, 그 명령의 직접 키를 받는다: `Alt + Return`과 `Alt + Shift + Return`은 창을 아래나 오른쪽으로 나누고, `Alt + Escape`는 닫으며, `Ctrl + Alt + Arrow`는 창 사이를 이동하고, `Alt + 1..9`와 `Alt + Left/Right`는 탭을 선택하며, `Alt + Up/Down`은 공간 사이를 이동한다. `Ctrl + 1..9`는 공간을 선택하고 `Alt + Shift + Up/Down`은 에이전트들을 단계적으로 이동한다. `Ctrl + Space` 접두사 키는 터미널 전용으로 남는데, 앱은 시퀀스를 위해 일반 Ctrl 키를 유지할 수 없기 때문이다. Omarchy는 이들을 `~/.config/herdr-app/keys.json`에 쓰고, `omarchy-refresh-herdr-app`가 다시 넣는다. 설치하면 Herdr의 Omarchy 테마를 선택하며, 그 이후 Omarchy 테마를 따른다. Herdr는 밝은 모드용 테마 하나와 어두운 모드용 테마 하나를 유지하므로, 어두운 Omarchy 테마와 밝은 Omarchy 테마 사이를 전환한 후에는, 다른 모드를 위해 Herdr의 테마 선택기에서 Omarchy를 한 번 더 선택하라.

T3 Code는 패키지가 아니라 `~/.local/share/t3code`에 있는 공식 AppImage 릴리스로 실행되므로, 자체 업데이트된다. 설치하면 Stable 채널로 시작할지 Nightly 채널로 시작할지 묻는다; 나중에 T3 Code 설정에서 전환하라. 스레드와 설정은 `~/.t3`에 살며, _Remove > AI_ 아래에서 T3 Code를 제거하면 함께 가져간다.

### 로컬 모델

코딩 에이전트를 위해 자신의 컴퓨터에서 열린 모델을 실행하라. 프롬프트와 코드는 컴퓨터에 머무르고; 모델로 전송된 것은 아무것도 컴퓨터를 떠나지 않는다. 다음으로 시작하라:

```bash
omarchy models use best text
```

이는 이 컴퓨터에 가장 좋은 텍스트 모델, 에이전트가 사용하는 종류를 설정한다. 이미지, 비디오, 그리고 음악 모델은 각자 가장 좋은 것이 있다: `omarchy models use best image`, `video`, 또는 `music`. 이 컴퓨터에서 각 종류의 선택을 보려면 `omarchy models use best`를 실행하라.

또는 에이전트 패널에서 +를 선택하라: _Use a local model_ 아래에서는 이 컴퓨터에 맞는 모든 코딩 모델을 추천 항목을 맨 앞에 두고 나열한다. 모델을 실행하는 Podman은 Omarchy와 함께 제공되며, NVIDIA 컴퓨터에서는 GPU를 제공하는 NVIDIA의 컨테이너 툴킷도 마찬가지다; 어느 하나라도 누락되었다면, 첫 설정에서 설치한다. 그런 다음 Omarchy는 이 컴퓨터에 추천되는 모델을 선택하고, 다운로드하고, 시작한다. 수십 GB의 다운로드와 모델이 실행되는 동안 컴퓨터 메모리의 대부분이 사용될 것으로 예상하라: Flash Next는 전체 256K 컨텍스트와 함께 약 100 GiB를 사용한다. 필요한 메모리를 다른 모델이 차지하고 있으면, 중지된 상태로 설정되어, 하나를 중지하면 시작할 준비가 된다. 모델은 로그아웃 시 중지된다; 다른 용도로 메모리가 필요할 때 직접 중지하라.

`omarchy models list`는 옵션을 표시하고 일부가 맞지 않는 이유를 설명한다. 다른 것을 설정하려면, `omarchy models use <recipe>`를 실행하라. 현재, `qwen3.8-flash-next-gufo`와 `qwen3.8-27b-gufo`는 128 GB Strix Halo 컴퓨터에서 사용할 수 있다; 27B는 약 40 GiB를 차지하므로, 다른 작업을 위한 공간을 남긴다. Intel의 Arc B390이 있는 64 GB 노트북에서는, `qwen3.6-35b-a3b-llamacpp`가 약 30 GiB에서 실행된다. 새로운 레시피와 추천은 패키지를 통해 `omarchy update`와 함께 제공된다.

추가한 코딩 모델은 구독 옆에, 에이전트 패널에서 자체 줄을 가진다: 시작하려면 재생, 중지하고 메모리를 해제하려면 일시 정지, 실행되는 동안 tailnet의 다른 컴퓨터와 공유하려면 Tailscale 표시, 그리고 그 모델에서 에이전트를 열려면 터미널 버튼이 있다. 그 줄은 진행됨에 따라 다운로드, 로드, 또는 중지를 표시하고, 시작할 여유 메모리가 충분하지 않을 때 그렇게 말하거나, 오류로 중지되었을 때 로그로 연결한다. 메모리에 함께 들어갈 수 있으면 여러 개를 동시에 실행할 수 있다. 선택한 줄에서 Delete를 눌러 다운로드까지 포함해 이 컴퓨터에서 모델을 제거하라; +로 다시 설정할 수 있다. 터미널에서 설정한 코딩 모델은 추가할 때까지 + 아래에서 기다리며, 페어링한 컴퓨터(`omarchy models pair <host>`)가 실행하는 모델도 마찬가지다.

설정한 모든 코딩 모델은 Claude, Codex, 또는 Grok에 로그인하면 추가되는 것처럼, 모델 이름과 제작자의 로고와 함께 앱 런처에도 자체 항목을 가진다. 그 모델에서 에이전트를 열고, 실행되고 있지 않으면 먼저 모델을 시작한다: 터미널은 로드되는 모습을 표시하고 준비가 되면 에이전트에게 넘긴다. 모델을 제거하면 그 항목도 제거된다.

모든 모델이 코딩용은 아니다. 이미지, 비디오, 그리고 음악 모델은 대신 이 컴퓨터에서 실행되는 모델로 사진, 비디오, 그리고 음악을 만들기 위한 Omarchy의 앱인 Fantasi에서 열리고, 거기에서 또는 `omarchy models`로 관리된다.

모델은 설정된 그대로 계속 실행되므로, Omarchy 업데이트가 에이전트 아래에서 모델을 다시 시작하는 일은 절대 없다. Omarchy에 설정한 모델을 위한 더 새로운 런타임이나 더 새로운 가중치가 있으면, 그 줄에 업데이트 버튼이 표시된다: 누르면 모델이 백그라운드에서 다시 설정되고, 변경된 것만 다운로드하며, 새 버전으로 다시 시작한다. 중지되었던 모델은 중지된 상태로 남는다. `omarchy models update`는 터미널에서 모든 모델에 대해 같은 일을 한다.

명령줄에서, `omarchy models start <recipe>`와 `omarchy models stop <recipe>`가 같은 일을 하고, `omarchy models status`는 모든 모델을 표시하며, `omarchy agent --local-model <recipe>`는 기본 에이전트가 무엇이든 pi에서 그 모델을 연다. 로컬 모델을 에이전트 단축키, Quake 콘솔, 그리고 _Make something_이 여는 것으로 만들려면, `omarchy default agent local`을 실행하거나 에이전트 패널에서 실행 중인 모델에 별표를 표시하라. pi는 또한 자체 모델 선택기에 설정한 모든 모델과 페어링한 컴퓨터에 있는 모델을 나열하므로, 일반적인 `pi`도 그것들에 도달한다. 모든 OpenAI 호환 클라이언트도 연결할 수 있다: `status`는 각 모델의 주소를 표시하고(첫 번째는 `http://127.0.0.1:11435/v1`), 레시피 이름이 모델이며, 키는 `~/.config/omarchy/agent-local/key`에 있다.

`omarchy models remove <recipe>`는 모델과 다른 어떤 모델도 사용하지 않는 다운로드를 삭제한다.

서드파티 런타임은 게시자로 표시된다. Omarchy는 모든 모델을 네트워크 액세스 없이 실행한다.

### 로컬 LLM

Omarchy는 로컬 LLM 모델을 실행하는 두 가지 방법을 추천한다: LM Studio와 Ollama. LM Studio는 공개 가중치 모델을 찾고, 설치하고, 실행하기 위한 GUI 인터페이스를 제공한다. 쉽게 시작하기에 좋은 방법이다. Ollama는 비슷하게 하기 위한 CLI를 제공한다. 하지만 로컬 모델이 처음이라면, 나는 LM Studio부터 시작하겠다. Omarchy Menu의 _Install > AI_ 아래에서 어느 쪽이든 설치할 수 있다.

### Omarchy 스킬

에이전트 스킬은 AI가 특정 도구를 특정 방식으로 사용하도록 돕고, Omarchy는 일곱 개를 제공한다. omarchy 스킬은 Hyprland 구성 조정이나 바 조정과 같은 시스템 맞춤 설정을 다룬다. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app, 그리고 omarchy-make-game은 새로운 것을 만드는 것을 다루고, omarchy-contribute는 버그를 보고하거나 업스트림에 수정을 보내는 것을 다루며, omarchy-diagnose-crash는 충돌의 코어 덤프를 분석한다. 이들은 Claude Code(`~/.claude/skills`), Codex(`~/.codex/skills`), Pi(`~/.pi/agent/skills`), Antigravity(`~/.gemini/config/skills`), Hermes(`~/.hermes/skills`와 각 `~/.hermes/profiles/*/skills`), 그리고 일반적인 `~/.agents/skills` 위치의 스킬 디렉터리에 심볼릭 링크되어 있어서, 대부분의 하네스가 자동으로 가져간다. 같은 이름의 자체 스킬 폴더가 우선한다.

하지만 이 스킬들은 실험적인 것으로 취급해야 한다. 모델마다 다른 효과를 내며 사용할 것이다. 먼저 계획 모드로 실행하여 에이전트가 무엇을 바꾸고 싶어 하는지 파악하는 것이 가장 좋다. 그리고 에이전트가 모든 것을 엉망으로 만들면, 변경 사항을 롤백하거나 심지어 `omarchy reinstall configs`를 호출할 준비를 하라.
