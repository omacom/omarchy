### 에이전트 설치 및 업데이트

Hermes를 제외하고, 이 에이전트들은 mise의 지연 설치를 사용합니다. 처음 실행할 때 CLI가 설치되고, 이후 실행에서는 그것을 재사용합니다. mise는 또한 설치된 에이전트에 새 릴리스가 있는지 최대 네 시간에 한 번, 시작 직전이나 셸 프롬프트에서 백그라운드로 확인합니다. 업데이트에 실패하거나 오프라인 상태이면 설치된 버전이 실행됩니다. `omarchy update`는 나머지 Omarchy와 함께 설치된 에이전트를 업데이트하고, `mup`은 mise로 관리되는 도구만 업데이트합니다.

`claude update`, `codex update`, 앱 안의 업데이트 버튼 같은 에이전트 자체 업데이터는 mise로 관리되는 설치를 업데이트하지 않습니다. `codex update`는 실패하고, `claude update`는 mise가 추적하지 않는 별도 복사본을 설치하면서 성공했다고 보고할 수 있습니다. 에이전트 자체 설치 프로그램과 업데이터를 대신 사용하고 싶다면, 그것을 `disable_tools`에 추가하세요. [미리 설치된 CLI 도구](18-development-tools.md#preinstalled-cli-tools)를 참조하세요.

구성된 모든 지연 도구를 필요해지기 전에 설치하려면 `mise install --include-lazy`를 실행하세요. 여기에는 에이전트뿐 아니라 Omarchy의 다른 기본 CLI 도구도 포함됩니다. 단일 도구를 설치하거나 직접 설치한 것을 사용하는 방법은 [미리 설치된 CLI 도구](18-development-tools.md#preinstalled-cli-tools)를 참조하세요.

`grok`은 `claude`와 `codex`와 같은 방식으로 mise의 공식 `grok` 패키지를 통해 설치됩니다. `grok`을 실행하거나, _Setup > Defaults > Agent_에서 선택하세요. x.ai의 `curl | bash` 설치 프로그램은 건너뛰세요. 그 경로는 `~/.grok/bin`에 두 번째 복사본을 넣고, 그것을 `PATH` 앞에 추가하며, Omarchy의 래퍼를 덮어씁니다.

`dsh`는 `127.0.0.1:3080`에서 브라우저 UI를 열며, 실행 디렉터리가 기본 워크스페이스가 됩니다. 브라우저 UI는 시작 프롬프트를 받지 않으므로, `omarchy agent prompt`는 붙여넣을 수 있도록 프롬프트를 클립보드에 담은 상태로 그것을 엽니다. Omarchy는 DeepSeek의 승인 없음 권한 프리셋으로 그것을 시작합니다. DeepSeek Harness는 공식 모델 API를 사용할 때 세션 로그를 DeepSeek에 업로드합니다. 브라우저 UI의 _Settings > General > Upload Session Log_에서 이를 끄세요. 보내는 피드백도 세션과 함께 업로드됩니다. 단, `DSH_TELEMETRY_MODE=DISABLED`로 시작하면 그렇지 않습니다.

### 기본 에이전트

`omarchy default agent <name>`으로, 또는 Omarchy Menu(`Super + Space`)의 _Setup > Defaults > Agent_에서 기본 에이전트를 선택하세요. 에이전트가 아직 설치되지 않았다면, 선택하면 먼저 설치됩니다. 새로 설치한 Omarchy는 일회성 알림으로 이 선택을 하도록 권합니다.

Claude를 선택하면 Chromium, Chrome, Brave, Brave Origin, Edge용 브라우저 확장 프로그램도 설정하려 시도합니다. 확장 프로그램 설정은 모든 사용자에게 적용되며 시스템 비밀번호를 물을 수 있습니다. 취소하거나 확장 프로그램 설치에 실패해도 Claude는 여전히 선택되고 실행됩니다. 브라우저를 다시 시작하고, 안내가 나오면 확장 프로그램을 활성화한 뒤, Claude에 로그인해 연결을 완료하세요. Claude에서 `/chrome`를 실행해 연결을 확인하세요. Firefox와 Zen은 이 확장 프로그램을 지원하지 않습니다. 이 설정이 추가되기 전에 이미 Claude가 기본값이었다면, 다시 선택해 확장 프로그램을 설치하세요.

선택을 마치면 `Super + Shift + Ctrl + A`가 전용 터미널 창에서 기본 에이전트를 실행합니다. 아직 선택하지 않았다면 선택 화면을 띄웁니다. `omarchy agent prompt "Review this project"`로 곧바로 작업에 투입할 수도 있습니다. Freebuff와 DeepSeek Harness는 시작 프롬프트를 받지 않으므로, 대신 붙여넣을 수 있도록 프롬프트를 클립보드에 담은 상태로 열립니다. 이렇게 실행된 에이전트는 각자의 멈추고 묻지 않는 모드로 무인 실행되니, 실제로 일을 벌일 각오를 하세요! MiniMax Code는 대화형 세션에 그런 모드가 없어서, 평소대로 권한을 묻습니다. 그리고 에이전트는 홈 디렉터리에 대한 신뢰를 기억하려 하지 않으므로, `$HOME`에서의 실행은 대신 `~/Work`에서 시작합니다.

터미널 단축키도 있습니다. `a`는 현재 터미널 안에서 기본 에이전트를 실행하고, `c`, `cx`, `cy`는 OpenCode, Claude Code, Codex를 직접 시작합니다. 역시 자동 승인 모드입니다. 테마 변경도 에이전트에 동기화됩니다. Claude Code, Pi, OpenCode, 그리고 Hermes(Omarchy가 설치한 뒤에)는 Omarchy 테마를 바꿀 때 모두 따라갑니다.

### 에이전트 패널

상단 바에는 에이전트 아이콘이 있습니다. 에이전트를 설정하기 전에는, 그 패널이 Claude, Codex, Grok 중 하나에 로그인하는 과정을 안내하고, 첫 번째로 설정한 것이 기본 에이전트가 됩니다. 그 뒤에는 패널이 모든 구독을 한 페이지에 모읍니다. 각 에이전트와 계정에 요금제, 각 5시간 세션 한도와 주간 한도에 대한 게이지와 초기화까지 남은 시간(정확한 백분율은 마우스를 올리세요), 또는 남은 선불 잔액이 표시되며, 그 위의 한 줄은 이번 주 토큰 수와 가장 많이 쓴 모델처럼 전체에서 사용한 내용을 번갈아 보여줍니다. _Make something_ 아래에서는 새 테마, 플러그인, 앱을 위한 시작 프롬프트를 제공하며, 작업을 기본 에이전트에게 맡깁니다. 앱은 Omarchy 자체의 Hype, Monologue, Omacut이 만들어지는 방식대로, omarchy-app 에이전트 스킬을 따라 C++와 Qt Quick로 만들어지며, 필요한 컴파일러와 Qt 구성 요소는 설치되어 제공됩니다. Claude Code, Codex, Grok, Kimi, Cursor와 그 Grok Bot 허용량, GitHub Copilot, Muse, Antigravity, Kimchi, Devin은 한도와 함께 기본으로 지원됩니다. Hermes, Mistral Vibe, Qwen Code는 사용한 뒤에 세션과 토큰을 표시합니다. pi, omp, opencode를 통해 사용하는 제공업체 요금제와 키도 나타납니다. 한도가 있는 OpenCode Zen과 Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan, Synthetic, 선불 잔액이 있는 Fireworks, OpenRouter, DeepSeek, 그리고 자체 하드웨어에서 실행하는 모델인 Local models가 있습니다. 모든 에이전트는 청구 주체 아래에서 한 번만 셉니다. 몇 개의 하니스를 통해 구동하든 마찬가지입니다.

바 아이콘을 왼쪽 클릭하면 패널이 열리고, 오른쪽 클릭하면 기본 에이전트가 실행됩니다. 그 뒤의 사용 기록은 `omarchy agent usage-update`가 15분마다 다시 생성하며, 패널은 동기화된 폴더를 통해 다른 컴퓨터의 사용량까지 합칠 수 있습니다. 전체 설정은 `$OMARCHY_PATH/shell/plugins/agents/` 아래의 README를 참조하세요.

### 여러 구독

개인 Max와 업무용처럼 Claude, Codex, Grok 요금제를 둘 이상 결제하고 있다면, Omarchy는 모두 로그인 상태를 유지하고 그 사이를 오갈 수 있습니다. 에이전트 패널의 +로 구독을 추가하면 바로 그 자리에서 과정을 안내합니다. 또는 `omarchy agent account add claude Work`(또는 `codex`, 또는 `grok`)로 추가하세요. CLI가 없으면 설치합니다. 제공업체의 첫 번째 계정은 CLI가 항상 찾는 바로 그곳에서, 평소 쓰는 브라우저를 통해 로그인합니다. 그 이후의 모든 계정은 비공개 창을 통해 로그인하므로, 브라우저에 이미 로그인된 계정이 실수로 선택되지 않습니다. 거기에서 추가하려는 계정으로 로그인하고, 이미 열어 둔 비공개 창이 있다면 먼저 닫으세요. 이를 위해 절대로 CLI에서 로그아웃하지 마세요. 로그아웃하면 저장된 로그인이 취소되어, 그 계정을 다시 추가해야 합니다.

구독 로그인을 SSH를 통해 다른 Omarchy 컴퓨터에 복사하려면 `omarchy agent account copy user@laptop`을 실행하세요. 대상에 수신기가 설치되어 있지 않으면 보내는 쪽이 임시 수신기를 제공하므로, 오래된 Omarchy 컴퓨터도 업데이트 없이 계정을 받을 수 있습니다. 설치된 수신기가 우선합니다. 이는 모든 Claude, Codex, Grok 구독을 복사합니다. `omarchy agent account copy laptop claude`처럼 제공업체 이름을 추가해 선택하세요. 계정 이름과 명령 ID는 대상에 이미 있는 계정을 포함해 원본과 일치합니다. 관련 없는 대상 계정은 이름이 충돌하면 숫자 접미사를 받으며, 설정, 스킬, 플러그인, 대화 기록은 각 컴퓨터에 로컬로 남습니다.

기존 대상 자격 증명은 유지됩니다. 거기에 이미 로그인된 원본 계정은 자격 증명을 교체하지 않고 이름만 동기화됩니다. 다른 계정은 그 옆에 추가됩니다. 일치하는 계정의 저장된 자격 증명을 교체하려면, 대상에서 그 계정의 세션을 종료한 뒤 `omarchy agent account copy --replace laptop claude`를 사용하세요. 새 대상은 원본의 활성 계정과 전환 환경 설정도 받습니다. 이미 자리 잡은 대상은 자체 설정을 유지합니다.

자격 증명은 SSH를 통해 이동하고 대상의 비공개 파일에 저장되므로, 신뢰하는 컴퓨터에만 복사하세요. 이는 일회성 복사이며 지속적인 동기화가 아닙니다. Codex 갱신 토큰은 다른 컴퓨터가 교체할 수 있어, 복사된 로그인을 갱신해야 하는 상태로 만들 수 있습니다. 여러 컴퓨터에서 동시에 사용하는 가장 믿을 만한 선택은 여전히 별도로 로그인하는 것입니다. [Codex의 계정 인증 안내](https://developers.openai.com/codex/auth/ci-cd-auth)를 참조하세요.

제공업체당 하나의 계정이 활성화되며, 모든 새 세션은 그 계정으로 시작합니다. `cx`, `cy`, 평범한 `claude`, `codex`, `grok`, `omarchy agent`를 통해 실행되는 모든 것, 그리고 `PATH`에서 CLI를 찾는 스크립트나 편집기가 그렇습니다. `omarchy agent account use work`로 전환하고, `omarchy agent account use main`으로 돌아오세요. 또는 패널에서 계정의 번호를 누른 뒤 `Enter`를 누르거나, Use 버튼을 클릭하세요. 이미 실행 중인 세션은 시작한 계정에 그대로 머뭅니다. 대화 기록, 설정, 스킬, 플러그인은 계정 간에 공유되므로, 같은 폴더에서 `claude --continue`를 실행하면 새 계정에서 중단한 지점부터 이어갑니다.

계정이 둘 이상이면 패널은 각 계정의 한도를 나란히 표시하고, 활성 계정을 표시합니다. 기본적으로 Omarchy는 활성 계정이 한도의 95%를 넘으면 알리고, 알림을 클릭하면 여유가 가장 많은 계정으로 전환합니다. 패널에서 계정 줄에 마우스를 올리고 Use 옆에 나타나는 Autoswitch를 클릭하거나(`m` 키를 눌러도 됩니다), `omarchy agent account mode auto`를 실행하면 대신 알아서 전환합니다. 켜져 있는 동안 Autoswitch가 Use를 대신하고, 다시 클릭하면 알림으로 돌아갑니다. `omarchy agent account mode auto 90`처럼 숫자를 추가해 임계값을 바꾸세요. 모든 계정이 임계값을 넘으면, 어느 계정이 가장 먼저 풀리는지와 함께 한 번 알려줍니다. 활성 계정이 임계값에서 15포인트 이내에 있으면(기본값에서는 80%), 한도를 15분이 아니라 3분마다 확인합니다.

`omarchy agent account list`는 모든 계정과 최신 한도를 표시하고, `omarchy agent account remove work`는 하나를 잊으며, `omarchy agent account rename primary Hey`는 하나의 이름을 바꿉니다. 패널에서 계정 이름을 클릭해도 됩니다. 이 명령들은 기본 에이전트의 계정에 대해 작동합니다. 다른 제공업체에 접근하려면 `omarchy agent account use codex side`처럼 먼저 이름을 지정하세요. `~/.claude`나 `~/.codex`에 이미 있던 로그인이 _Main_ 계정이며 제자리에 남습니다. 약 여덟 시간 넘게 사용하지 않은 계정은 _Sign-in required_를 표시할 수 있습니다. 클릭해 패널에서 바로 그 계정에 다시 로그인하거나, 그 계정으로 세션을 시작하면 저절로 로그인이 새로 고쳐집니다. 계정이 추가될 때 있던 MCP 서버는 그 계정으로 따라오지만, 나중에 `claude mcp add`로 추가한 것은 추가한 계정에만 도달합니다. Claude Desktop과 CLI 바이너리에 대한 절대 경로로 구성된 도구는 전환을 따르지 않습니다. 명시적인 `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, `GROK_HOME`가 선택한 계정보다 우선합니다.

### 충돌 진단

Omarchy는 systemd-coredump에서 프로세스 충돌을 감시합니다. 무언가 세그멘테이션 오류를 일으키면 "Process crashed" 알림을 받습니다. 클릭하면, 충돌이 Omarchy의 diagnose-crash 스킬과 함께 기본 에이전트에게 넘겨지며, 이 스킬은 코어 덤프에서 사실을 확정하고 충돌을 업스트림에 보고할 가치가 있는지 판단하는 과정을 에이전트에게 안내합니다. `coredumpctl list`의 모든 PID에 대해 `omarchy agent crash <pid>`로 직접 실행할 수도 있습니다.

감시는 기본적으로 켜져 있습니다. _Trigger > Toggle > Crash Capture_에서, 또는 `omarchy toggle crash-capture`로 끄면 알림이 중단됩니다. `omarchy agent crash <pid>`는 여전히 직접 사용할 수 있습니다.

충돌은 한 번에 한 프로그램씩 묵음 처리할 수도 있는데, 진단이 마지막에 제안하는 것이 바로 그것입니다. `omarchy crash mute hyprland`는 그 프로그램에 대해서만 알림을 중단하고, `omarchy crash mute hyprland off`는 되돌리며, `omarchy crash mute`만 실행하면 묵음 처리한 목록을 표시합니다. 이름만큼이나 바이너리 경로도 잘 받아들이므로, `omarchy crash mute /usr/bin/hyprland`도 같은 일을 합니다. `omarchy crash mute 'Some App'`처럼 공백이 있는 이름은 따옴표로 감싸세요. 다른 모든 것은 여전히 알리고, 묵음 처리된 프로그램은 여전히 충돌합니다. 이는 알림을 숨길 뿐, 아무것도 고치지 않습니다.

### 데스크톱 앱

_Install > AI_ 메뉴에는 그래픽 AI 앱도 몇 가지 있습니다. ChatGPT 데스크톱 앱, Claude 데스크톱 앱(Anthropic의 Linux 베타로, Chat, Cowork, Claude Code 탭 포함), xAI의 모델과 채팅하는 Grok Bot, Hermes Desktop, OpenClaw, Perplexity 데스크톱 앱, T3 Code입니다. Grok Bot은 데스크톱 채팅 앱입니다. 코딩 에이전트는 `grok` 명령입니다.

알아둘 것은 Hermes Desktop입니다. 컴퓨터에는 하나의 Hermes가 있고, 그것은 앱의 것이기 때문입니다. Hermes는 오직 앱을 통해서만 설치되며, 기본 에이전트가 실행하는 `hermes` 명령은 앱의 것입니다. Hermes를 기본 에이전트로 선택하면 _Install > AI_ 항목이 설치하는 것과 같은 것을 설치합니다. 패키지, 그리고 Hermes 자체 설치 프로그램이 설정하는 `~/.hermes` 아래의 Hermes 런타임인데, 처음에는 몇 분이 걸립니다. 그 런타임이 터미널의 `hermes` 명령, 기본 에이전트, 앱이 모두 사용하는 유일한 Hermes이며, Omarchy 릴리스를 기다리지 않고 `hermes update`로 자체 업데이트합니다. 설치하면 Hermes에 `omarchy`라는 이름의 스킨으로 Omarchy 테마도 건네며, 모든 Hermes 표면이 테마를 바꿀 때 이를 따릅니다. 그러지 않았으면 좋겠다면 Hermes의 Appearance 설정에서, 또는 `/skin`으로 다른 것을 선택하세요. Omarchy는 그 선택을 그대로 둡니다. _Remove > AI_에서 앱을 제거하면 먼저 게이트웨이를 포함해 Hermes를 닫고, 그 런타임을 함께 가져가며, 달리 말하지 않는 한 채팅, 메모리, Hermes가 스스로 작성한 스킬은 유지합니다. 그 데이터와 연결 설정도 함께 지울지 묻는데, 기본값은 아니요입니다.

OpenClaw의 데스크톱 경험은 Control UI로, 자체 로컬 게이트웨이를 백엔드로 하는 웹 앱으로 열립니다. OpenClaw는 `~/.openclaw`에 살며 자체 업데이트합니다. Control UI의 "Update Gateway" 버튼을 사용하거나 `openclaw update`를 실행하면, 게이트웨이가 새 버전으로 다시 시작합니다. Omarchy는 새 설치가 시작하는 릴리스만 선택합니다. _Remove > AI_에서 OpenClaw를 제거하면 게이트웨이 서비스와 앱을 함께 가져간 뒤, `~/.openclaw`도 함께 지울지 묻습니다. 거기에는 OpenClaw 자체와 다운로드하는 플러그인 런타임과 함께 채팅과 자격 증명이 들어 있기 때문입니다. 기본값은 유지하는 것이며, OpenClaw를 다시 설치하면 그대로 되찾습니다.

T3 Code는 패키지가 아니라 `~/.local/share/t3code`에 있는 공식 AppImage 릴리스에서 실행되므로 자체 업데이트합니다. 설치하면 Stable 채널로 시작할지 Nightly 채널로 시작할지 묻습니다. 나중에 T3 Code의 설정에서 바꾸세요. 스레드와 설정은 `~/.t3`에 살며, _Remove > AI_에서 T3 Code를 제거하면 함께 가져갑니다.

### 로컬 LLM

Omarchy는 로컬 LLM 모델을 실행하는 두 가지 방법을 권장합니다. LM Studio와 Ollama입니다. LM Studio는 오픈 웨이트 모델을 찾고, 설치하고, 실행하는 GUI 인터페이스를 제공합니다. 쉽게 시작하기에 좋은 방법입니다. Ollama는 비슷하게 하는 CLI를 제공합니다. 하지만 로컬 모델이 처음이라면, 나는 LM Studio로 시작하겠습니다. Omarchy Menu의 _Install > AI_에서 둘 중 하나를 설치할 수 있습니다.

### Omarchy 스킬

에이전트 스킬은 AI가 특정 도구를 특정 방식으로 사용하도록 돕고, Omarchy는 시스템을 맞춤화하는 기본 스킬을 함께 제공합니다. Hyprland 설정을 조정하거나, 바를 조절하거나, 심지어 새 테마를 처음부터 만드는 것 같은 일입니다. 이는 Claude Code(`~/.claude/skills`), Codex(`~/.codex/skills`), Pi(`~/.pi/agent/skills`), Antigravity(`~/.gemini/config/skills`), Hermes(`~/.hermes/skills`와 각 `~/.hermes/profiles/*/skills`), 그리고 일반적인 `~/.agents/skills` 위치의 스킬 디렉터리에 심볼릭 링크되어 있어, 대부분의 하니스가 자동으로 가져갑니다.

하지만 이 스킬은 실험적인 것으로 취급해야 합니다. 모델마다 이를 활용하는 정도가 다릅니다. 먼저 계획 모드로 실행하는 것이 가장 좋습니다. 그래야 에이전트가 무엇을 바꾸고 싶은지 알 수 있습니다. 그리고 에이전트가 모든 것을 엉망으로 만들면, 변경 사항을 되돌리거나 심지어 `omarchy reinstall configs`를 실행할 준비를 하세요.
