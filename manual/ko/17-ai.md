### 에이전트 설치 및 업데이트

Hermes를 제외하면, 이 에이전트들은 mise의 지연 설치를 사용한다: 처음 실행할 때 CLI가 설치되고, 이후 실행에서는 그것을 재사용한다. mise는 또한 설치된 에이전트에 새 릴리스가 있는지 최대 네 시간에 한 번, 시작 직전이나 셸 프롬프트에서 백그라운드로 확인한다. 업데이트가 실패하거나 오프라인 상태이면, 설치된 버전이 실행된다. `omarchy update`는 나머지 Omarchy와 함께 설치된 에이전트들을 업데이트하고, `mup`은 mise가 관리하는 도구만 업데이트한다.

`claude update`, `codex update` 같은 에이전트 자체 업데이터나 앱 안의 업데이트 버튼으로는 mise가 관리하는 설치본이 업데이트되지 않는다. `codex update`는 실패하고, `claude update`는 성공했다고 보고하면서 mise가 추적하지 않는 별도 복사본을 설치할 수 있다. 에이전트의 네이티브 설치 프로그램과 업데이터를 대신 사용하고 싶다면, 그것을 `disable_tools`에 추가하라; [미리 설치된 CLI 도구](18-development-tools.md#preinstalled-cli-tools)를 보라.

필요해지기 전에 구성된 모든 지연 도구를 설치하려면 `mise install --include-lazy`를 실행하라. 여기에는 에이전트뿐만 아니라 Omarchy의 다른 기본 CLI 도구도 포함된다. 단일 도구를 설치하거나 직접 설치한 것을 사용하는 방법은 [미리 설치된 CLI 도구](18-development-tools.md#preinstalled-cli-tools)를 보라.

`grok`은 `claude`와 `codex`와 같은 방식으로 mise의 퍼스트파티 `grok` 패키지를 통해 설치된다. `grok`을 실행하거나, _Agent > Harness_에서 선택하라. x.ai에 있는 `curl | bash` 설치 프로그램은 건너뛰어라. 그 경로는 `~/.grok/bin`에 두 번째 복사본을 넣고, 그것을 `PATH` 앞에 붙이며, Omarchy의 래퍼를 덮어쓴다.

`dsh`는 실행 디렉터리를 기본 워크스페이스로 삼아 `127.0.0.1:3080`에서 브라우저 UI를 연다. 브라우저 UI는 시작 프롬프트를 받지 않으므로, `omarchy agent prompt`는 붙여넣을 수 있도록 프롬프트를 클립보드에 넣어 연다. Omarchy는 DeepSeek의 무승인 권한 프리셋으로 시작한다. DeepSeek Harness는 공식 모델 API를 사용할 때 세션 로그를 DeepSeek에 업로드한다; 브라우저 UI의 _Settings > General > Upload Session Log_에서 끌 수 있다. 보내는 피드백도 세션과 함께 업로드되며, `DSH_TELEMETRY_MODE=DISABLED`로 시작하면 그렇지 않다.

### 기본 에이전트

기본 에이전트는 `omarchy default agent <name>`으로, 또는 Omarchy Menu(`Super + Space`)의 _Agent > Harness_에서 선택하라. 에이전트가 아직 설치되지 않았다면, 선택하면 먼저 설치한다. 새로 설치한 Omarchy는 일회성 알림으로 이 선택을 하도록 권한다.

Claude를 선택하면 Chromium, Chrome, Brave, Brave Origin, Edge용 브라우저 확장 프로그램도 설정을 시도한다. 확장 프로그램 설정은 모든 사용자에게 적용되며 시스템 비밀번호를 물을 수 있다; 취소하거나 확장 프로그램 설치가 실패해도 Claude는 여전히 선택되고 실행된다. 브라우저를 다시 시작하고, 안내가 나오면 확장 프로그램을 활성화한 뒤, Claude에 로그인해 연결을 마무리하라. 연결 상태는 Claude에서 `/chrome`을 실행해 확인하라. Firefox와 Zen은 이 확장 프로그램을 지원하지 않는다. 이 설정이 추가되기 전에 이미 Claude가 기본값이었다면, 다시 선택해 확장 프로그램을 설치하라.

선택을 마쳤으면, `Super + Shift + Ctrl + A`는 전용 터미널 창에서 기본 에이전트를 실행한다(아직 선택하지 않았다면 선택 화면을 띄운다). `omarchy agent prompt "Review this project"`로 곧바로 작업에 투입할 수도 있다. Freebuff와 DeepSeek Harness는 시작 프롬프트를 받지 않으므로, 대신 붙여넣을 수 있도록 프롬프트를 클립보드에 넣어 연다. 이렇게 실행된 에이전트들은 각자의 묻지 않고 멈추지 않는 모드로 무인 실행되니, 실제로 일을 벌일 각오를 하라! MiniMax Code는 대화형 세션에 그런 모드가 없어서, 평소대로 권한을 묻는다. 그리고 에이전트들은 홈 디렉터리에 대한 신뢰를 기억하기를 거부하므로, `$HOME`에서 실행하면 대신 `~/Work`에서 시작한다.

터미널 단축키도 있다: `a`는 현재 터미널 안에서 기본 에이전트를 인라인으로 실행하고, `c`, `cx`, `cy`는 OpenCode, Claude Code, Codex를 직접 시작한다(역시 자동 승인 모드로). 테마 변경도 에이전트에 동기화된다: Claude Code, Pi, OpenCode, Hermes(Omarchy가 설치한 이후)는 Omarchy 테마를 바꿀 때 모두 따라온다.

### 에이전트 지침

모든 에이전트에 대한 개인 규칙은 `~/.agents/skills`의 공유 스킬 옆에 있는 `~/.agents/AGENTS.md`에 들어간다. _Agent > Instructions_에서 열면 되며, 이곳에서 자체 전역 파일을 유지하는 각 하네스에도 연결된다: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, Copilot의 `~/.copilot/copilot-instructions.md` 등이다. Crush와 Amp는 `~/.config/AGENTS.md` 링크를 읽고, omp, Kimi, DeepSeek Harness는 `~/.agents/AGENTS.md`를 직접 읽는다. 기본 에이전트를 선택하면 그것도 연결된다. 이미 가지고 있던 지침 파일이 있고 공유 파일이 아직 없었다면 그 파일이 공유 파일이 되고, 그렇지 않다면 링크 옆에 `.bak`으로 유지된다. 다른 에이전트를 설치한 뒤에는 `omarchy agent instructions`를 실행해 다시 연결하라.

### 에이전트 패널

상단 바에는 에이전트 아이콘이 있다. 에이전트를 설정하기 전에는, 그 패널이 Claude, Codex, Grok 중 하나에 로그인하는 과정을 안내하고, 첫 번째로 설정한 것이 기본 에이전트가 된다. 그 이후에는 패널이 모든 구독을 한 페이지에 모은다: 각 에이전트와 계정에 그 요금제를 표시하고, 5시간 세션 한도와 주간 한도 각각에 대해 초기화까지 남은 시간과 함께 미터를 보여주거나(정확한 퍼센트는 마우스를 올려 확인), 남은 선불 잔액을 보여주며, 그 위에는 이번 주 토큰 수와 가장 많이 쓴 모델처럼 전체에서 사용한 내용을 번갈아 보여주는 줄이 있다. _Make something_ 아래에서는 새 테마, 플러그인, 앱, 게임용 시작 프롬프트를 제공해 작업을 기본 에이전트에 맡긴다. 앱은 Omarchy 자체의 Hype, Monologue, Omacut이 만들어지는 방식대로 C++와 Qt Quick으로 만들어지며, omarchy-make-app 에이전트 스킬을 따르고, 필요한 컴파일러와 Qt 구성 요소는 설치되어 제공된다. 게임은 `~/Games/vibes`에 있는 단일 three.js 페이지로, omarchy-make-game 에이전트 스킬을 따르며, 모두 현재 테마의 하나의 Game Vibes 런처에서 열린다; three.js를 웹에서 불러오므로 시작하려면 연결이 필요하다. Claude Code, Codex, Grok, Kimi, Cursor와 그 Grok Bot 할당량, GitHub Copilot, Muse, Antigravity, Kimchi, Devin은 한도와 함께 기본으로 지원되고, Hermes, Mistral Vibe, Qwen Code는 사용한 뒤에 세션과 토큰을 보여준다. pi, omp, opencode를 통해 사용하는 제공업체 요금제와 키도 나타난다: 한도와 함께 OpenCode Zen과 Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan, Synthetic; 선불 잔액과 함께 Fireworks, OpenRouter, DeepSeek; 그리고 Local models 아래에 자체 하드웨어에서 실행하는 모델들이다. 모든 에이전트는 몇 개의 하네스를 통해 구동하든 청구 주체 아래에서 한 번만 셈으로써 중복되지 않는다.

패널은 바 아이콘을 왼쪽 클릭하고, 기본 에이전트 실행은 오른쪽 클릭으로 한다. 그 뒤에 있는 사용 기록은 `omarchy agent usage-update`가 15분마다 다시 생성하며, 패널은 동기화된 폴더를 통해 다른 기기의 사용량까지 병합할 수도 있다. 전체 설정은 `$OMARCHY_PATH/shell/plugins/agents/` 아래의 README를 보라.

### 여러 구독

개인용 Max와 업무용처럼 Claude, Codex, Grok 요금제를 하나보다 많이 결제하고 있다면, Omarchy는 모두 로그인 상태를 유지하고 그 사이를 오갈 수 있다. 에이전트 패널의 +로 구독을 추가하면 그 자리에서 과정을 안내하고, 또는 `omarchy agent account add claude Work`(또는 `codex`, 또는 `grok`)로 추가하라. CLI가 없으면 설치한다. 제공업체의 첫 번째 계정은 CLI가 항상 찾는 바로 그곳인, 일반 브라우저를 통해 로그인한다. 그 이후의 계정은 모두 비공개 창을 통해 로그인하므로, 브라우저에 이미 로그인된 계정이 실수로 선택되지 않는다; 추가하려는 계정으로 거기서 로그인하고, 이미 열어 둔 비공개 창이 있으면 먼저 닫아라. 이를 위해 절대로 CLI에서 로그아웃하지 마라: 로그아웃하면 저장된 로그인이 취소되고, 그 계정을 다시 추가해야 한다.

구독 로그인을 SSH를 통해 다른 Omarchy 기기로 복사하려면 `omarchy agent account copy user@laptop`을 실행하라. 대상에 수신기가 설치되어 있지 않으면 송신 측이 임시 수신기를 제공하므로, 오래된 Omarchy 기기도 업데이트 없이 계정을 받을 수 있다. 설치된 수신기가 우선한다. 이는 모든 Claude, Codex, Grok 구독을 복사한다; `omarchy agent account copy laptop claude`처럼 제공업체 이름을 추가해 선택하라. 계정 이름과 명령어 ID는 대상에 이미 있는 계정을 포함해 원본과 일치한다. 관련 없는 대상 계정은 이름이 충돌하면 숫자 접미사를 받으며, 설정, 스킬, 플러그인, 대화 기록은 각 기기에 로컬로 남는다.

기존 대상 자격 증명은 유지된다. 이미 거기에 로그인되어 있는 원본 계정은 자격 증명을 교체하지 않고 이름만 동기화되고, 다른 계정들은 그 옆에 추가된다. 일치하는 계정의 저장된 자격 증명을 교체하려면, 대상에서 해당 계정의 세션을 종료한 뒤 `omarchy agent account copy --replace laptop claude`를 사용하라. 새 대상은 원본의 활성 계정과 전환 환경 설정도 받는다; 이미 사용 중인 대상은 자체 설정을 유지한다.

자격 증명은 SSH를 통해 이동하고 대상의 비공개 파일에 저장되므로, 신뢰하는 기기에만 복사하라. 이는 일회성 복사이지 지속적인 동기화가 아니다. Codex 새로고침 토큰은 다른 기기에 의해 교체될 수 있어, 복사된 로그인을 갱신해야 하는 상태로 남길 수 있다; 여러 기기에서 동시에 사용하는 가장 믿을 만한 선택은 여전히 별도로 로그인하는 것이다. [Codex의 계정 인증 안내](https://developers.openai.com/codex/auth/ci-cd-auth)를 보라.

제공업체당 하나의 계정이 활성화되며, 모든 새 세션은 그 계정으로 시작한다: `cx`, `cy`, 평범한 `claude`, `codex`, `grok`, `omarchy agent`를 통해 실행되는 모든 것, 그리고 `PATH`에서 CLI를 찾는 스크립트나 편집기까지다. `omarchy agent account use work`로 전환하고(`omarchy agent account use main`으로 되돌아온다), 또는 패널에서 계정 번호를 누른 뒤 `Enter`를 누르거나(Use 버튼을 클릭하거나) 전환하라. 실행 중인 Claude 세션도 다음 메시지부터 전환된다: 모든 Claude 세션은 항상 활성 계정의 로그인을 보유하는 `~/.claude`에서 실행된다. 오래된 Omarchy가 계정 자체 폴더에서 시작한 Claude 세션은 종료될 때까지 그 로그인을 유지하므로, 전환 시 그 세션들의 이름을 알려주고, 세션들이 사라지면 스스로 마무리한다. 실행 중인 Codex와 Grok 세션은 시작한 계정에 그대로 남는다. 대화 기록, 설정, 스킬, 플러그인은 계정 간에 공유되므로, 같은 폴더에서 `claude --continue`를 하면 새 계정에서 중단한 곳부터 이어갈 수 있다.

계정이 하나보다 많으면 패널은 각 계정의 한도를 나란히 보여주고, 활성 계정에 표시를 한다. 기본적으로 Omarchy는 활성 계정이 한도의 95%를 넘으면 알리며, 알림을 클릭하면 여유가 가장 많은 계정으로 전환한다. 대신 스스로 전환하게 하려면, 패널에서 계정 줄에 마우스를 올리고 Use 옆에 나타나는 Autoswitch를 클릭하거나(`m` 키를 누르거나), `omarchy agent account mode auto`를 실행하라; 켜져 있는 동안에는 Autoswitch가 Use의 자리를 대신하고, 다시 클릭하면 알림으로 돌아간다. `omarchy agent account mode auto 90`처럼 숫자를 추가해 임계값을 바꾸라. 모든 계정이 임계값을 넘으면, 어느 계정이 가장 먼저 여유를 얻는지도 함께 한 번 알린다. 활성 계정이 임계값의 15포인트 이내(기본값에서는 80%)에 있는 동안에는, 한도를 15분이 아니라 3분마다 확인한다.

`omarchy agent account list`는 모든 계정과 최신 한도를 보여주고, `omarchy agent account remove work`는 하나를 잊으며, `omarchy agent account rename primary Hey`는 하나의 이름을 바꾼다(또는 패널에서 계정 이름을 클릭하라). 이 명령어들은 기본 에이전트의 계정에 대해 동작한다; 다른 제공업체에 접근하려면 `omarchy agent account use codex side`처럼 먼저 이름을 지정하라. `~/.claude`나 `~/.codex`에 이미 가지고 있던 로그인이 _Main_ 계정이다. Codex의 것은 제자리에 그대로 있고; Claude의 것은 다른 계정이 활성 상태인 동안 자체 폴더에서 대기한다. 약 여덟 시간 넘게 사용하지 않은 계정은 _Sign-in required_를 표시할 수 있다; 클릭해 패널에서 바로 그 계정에 다시 로그인하거나, 그 계정으로 전환하고 세션을 시작하면 저절로 로그인이 갱신된다. `claude mcp add`로 추가한 MCP 서버는 모든 Claude 세션이 `~/.claude`에서 실행되므로 모든 Claude 계정에 도달한다; Codex와 Grok에서는 계정이 추가될 때 가지고 있던 서버는 그 계정으로 함께 가지만, 이후의 서버는 추가한 계정에만 도달한다. Claude Desktop은 자체 로그인을 유지하고, CLI 바이너리에 대한 절대 경로로 구성된 Codex나 Grok 도구는 전환을 따르지 않는다. 명시적인 `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, `GROK_HOME`는 선택한 계정보다 우선한다.

### 충돌 진단

Omarchy는 프로세스 충돌을 위해 systemd-coredump를 감시한다. 무언가 segfault하면 "Process crashed" 알림을 받는다 — 클릭하면, 충돌이 기본 에이전트에 Omarchy의 diagnose-crash 스킬과 함께 넘겨지며, 이 스킬은 에이전트가 코어 덤프에서 사실을 확립하고 충돌을 상류에 보고할 가치가 있는지 판단하도록 안내한다. `coredumpctl list`의 어떤 PID에 대해서도 `omarchy agent crash <pid>`로 직접 실행할 수도 있다.

감시는 기본적으로 켜져 있다. _Trigger > Toggle > Crash Capture_에서 끄거나(또는 `omarchy toggle crash-capture`로) 하면 알림이 멈춘다; `omarchy agent crash <pid>`는 수동으로는 계속 동작한다.

충돌은 한 번에 한 프로그램씩 묵음 처리할 수도 있는데, 진단이 마지막에 제안하는 것이 바로 그것이다. `omarchy crash mute hyprland`는 그 프로그램에 대한 알림만 멈추고, `omarchy crash mute hyprland off`는 다시 켜며, `omarchy crash mute`를 단독으로 실행하면 묵음 처리한 목록을 보여준다. 이름만큼이나 바이너리 경로도 잘 받아들이므로, `omarchy crash mute /usr/bin/hyprland`도 같은 일을 한다. `omarchy crash mute 'Some App'`처럼 공백이 있는 이름은 인용하라. 그 외의 모든 것은 여전히 알리며, 묵음 처리된 프로그램은 여전히 충돌한다 — 이는 알림을 숨길 뿐, 아무것도 고치지 않는다.

### 데스크톱 앱

_Install > AI_ 메뉴에는 몇 가지 그래픽 AI 앱도 있다: ChatGPT 데스크톱 앱, Claude 데스크톱 앱(Anthropic의 Linux 베타, Chat, Cowork, Claude Code 탭 포함), xAI의 모델과 대화하는 Grok Bot, Herdr Desktop, Hermes Desktop, OpenClaw, Perplexity 데스크톱 앱, T3 Code. Grok Bot은 데스크톱 채팅 앱이다. 코딩 에이전트는 `grok` 명령어다.

Hermes Desktop은 알아둘 만한 녀석인데, 기기에는 하나의 Hermes가 있고 그건 앱의 것이기 때문이다: Hermes는 오로지 앱을 통해서만 설치되며, 기본 에이전트가 실행하는 `hermes` 명령어도 앱의 것이다. Hermes를 기본 에이전트로 선택하면 _Install > AI_ 항목이 설치하는 것과 같은 것을 설치한다: 패키지와, Hermes 자체 설치 프로그램이 `~/.hermes` 아래에 설정하는 Hermes 런타임으로, 처음에는 몇 분이 걸린다. 그 런타임이 터미널 `hermes` 명령어, 기본 에이전트, 앱이 모두 사용하는 유일한 Hermes이며, Omarchy 릴리스를 기다리지 않고 `hermes update`로 스스로 업데이트한다. 설치하면 Omarchy 테마를 `omarchy`라는 이름의 스킨으로 Hermes에 건네주기도 하며, 모든 Hermes 화면이 테마를 전환할 때 이를 따른다; 원하지 않는다면 Hermes의 Appearance 설정에서나 `/skin`으로 다른 것을 선택하라, 그러면 Omarchy는 그 선택을 그대로 둔다. _Remove > AI_에서 앱을 제거하면 먼저 게이트웨이를 포함해 Hermes를 닫고, 그 런타임을 함께 가져가며, 달리 말하지 않는 한 채팅, 메모리, Hermes가 스스로 작성한 스킬은 유지한다: 그 데이터와 연결 설정도 함께 지울지 묻는데, 기본값은 아니오다.

OpenClaw의 데스크톱 경험은 자체 로컬 게이트웨이가 뒷받침하는 웹 앱으로 열리는 Control UI다. OpenClaw는 `~/.openclaw`에 살고 스스로 업데이트한다: Control UI의 "Update Gateway" 버튼을 사용하거나 `openclaw update`를 실행하면, 게이트웨이가 새 버전으로 재시작한다. Omarchy는 새로 설치할 때 시작할 릴리스만 선택한다. _Remove > AI_에서 OpenClaw를 제거하면 게이트웨이 서비스와 앱을 함께 가져간 다음, OpenClaw 자체와 다운로드하는 플러그인 런타임과 함께 채팅과 자격 증명을 보관하는 `~/.openclaw`도 함께 지울지 묻는다; 기본값은 유지하는 것이며, OpenClaw를 다시 설치하면 다시 가져온다.

Herdr Desktop은 [Herdr](https://herdr.dev) 데스크톱 앱이다: 창을 닫아도 코어에서 계속 실행되는 터미널과 코딩 에이전트의 공간, 탭, 창이다. 패키지가 아니라 Herdr 자체 설치 프로그램으로 제공되므로 `~/.local/share/herdr-app`에 살고, 아직 없을 때는 `~/.local/bin/herdr-core`에 코어를 함께 가져오며, 둘 다 스스로 업데이트한다. Omarchy가 `Super + Ctrl + Return`으로 제공하는 `herdr` 명령어를 대체하기보다는 그 곁에 있으며, 그 명령어의 직접 키를 받는다: `Alt + Return`과 `Alt + Shift + Return`은 창을 아래로 또는 오른쪽으로 분할하고, `Alt + Escape`는 닫으며, `Ctrl + Alt + Arrow`는 창 사이를 이동하고, `Alt + 1..9`와 `Alt + Left/Right`는 탭을 선택하며, `Alt + Up/Down`은 공간 사이를 이동한다. `Ctrl + 1..9`는 공간을 선택하고 `Alt + Shift + Up/Down`은 에이전트 사이를 이동한다. `Ctrl + Space` 접두 키는 터미널 전용으로 남는데, 앱은 시퀀스를 위해 평범한 Ctrl 키를 유지할 수 없기 때문이다. Omarchy는 이를 `~/.config/herdr-app/keys.json`에 쓰고, `omarchy-refresh-herdr-app`가 되돌려 놓는다. 설치하면 Herdr의 Omarchy 테마를 선택하며, 그 이후부터 Omarchy 테마를 따른다. Herdr는 밝은 모드용 테마 하나와 어두운 모드용 테마 하나를 유지하므로, 어두운 Omarchy 테마와 밝은 Omarchy 테마 사이를 전환한 후에는 다른 모드를 위해 Herdr의 테마 선택기에서 Omarchy를 한 번 더 선택하라.

T3 Code는 패키지가 아니라 `~/.local/share/t3code`에 있는 공식 AppImage 릴리스에서 실행되므로, 스스로 업데이트한다. 설치하면 Stable 채널로 시작할지 Nightly 채널로 시작할지 묻는다; 나중에 T3 Code의 설정에서 바꾸라. 스레드와 설정은 `~/.t3`에 살고, _Remove > AI_에서 T3 Code를 제거하면 함께 가져간다.

### 로컬 모델

코딩 에이전트를 위해 자체 기기에서 오픈 모델을 실행하라. 프롬프트와 코드는 기기에 남는다; 모델로 보내는 어떤 것도 기기를 떠나지 않는다. 다음으로 시작하라:

```bash
omarchy agent local use best
```

또는, 상단 바의 에이전트 패널에서 +를 선택한 뒤 Local AI를 선택하라, 이는 이 기기에 맞는 모델이 있을 때 나타난다. 처음에는 모델을 실행하는 Podman이 설치되고, NVIDIA 기기에서는 GPU를 제공하는 NVIDIA의 컨테이너 툴킷이 설치된다. 그 다음 Omarchy는 이 기기에 권장되는 모델을 골라 다운로드하고 시작한다. 수십 GB의 다운로드와, 모델이 실행되는 동안 기기 메모리의 대부분이 사용될 것을 예상하라: Flash Next는 전체 256K 컨텍스트로 약 100 GiB를 사용한다. 필요한 메모리를 다른 모델이 차지하고 있으면, 하나를 중지하면 시작할 준비가 된 상태로 중지된 채 설정된다. 모델은 로그아웃 시 중지된다; 다른 용도로 메모리가 필요할 때는 직접 중지하라.

`omarchy agent local list`는 옵션을 보여주고 일부가 맞지 않는 이유를 설명한다. 또 다른 것을 설정하려면 `omarchy agent local use <recipe>`를 실행하라. 오늘 기준으로는 128 GB Strix Halo 기기용으로 `qwen3.8-flash-next-gufo`와 `qwen3.8-27b-gufo`가 제공된다; 27B는 약 40 GiB를 사용하므로 다른 작업을 위한 공간이 남는다. Intel의 Arc B390이 달린 64 GB 노트북에서는 `qwen3.6-35b-a3b-llamacpp`가 약 30 GiB로 실행된다. 새 레시피와 권장 사항은 패키지를 통해 `omarchy update`와 함께 제공된다.

설정한 모든 모델은 구독 옆의 에이전트 패널에 자체 줄을 갖는다: 재생하면 시작하고, 일시정지하면 중지해 메모리를 해제하며, 터미널 버튼을 누르면 그 모델 위에서 에이전트를 연다. 메모리 안에 함께 들어갈 때는 여러 개를 동시에 실행할 수 있다; 하나가 들어가지 않으면 Omarchy는 실행 중인 어떤 모델을 중지해야 하는지 알려준다. 줄을 드래그해 순서를 바꾸고, 선택한 줄에서 Delete를 눌러 모델과 그 다운로드를 제거하라.

설정한 모든 모델은 앱 런처에도 자체 항목을 얻는데, 모델 이름 아래에 제작자 로고와 함께, Claude, Codex, Grok에 로그인하면 항목이 추가되는 것과 같은 방식이다. 그 모델 위에서 에이전트를 열고, 실행 중이 아니면 먼저 모델을 시작한다: 터미널은 로딩을 보여주고, 준비되면 에이전트에 넘긴다. 모델을 제거하면 항목도 제거된다.

모델은 설정된 그대로 계속 실행되므로, Omarchy 업데이트가 에이전트 아래에서 모델을 절대로 재시작하지 않는다. 설정한 모델에 대해 Omarchy에 더 새로운 런타임이나 가중치가 있으면, 그 줄에 업데이트 버튼이 나타난다: 누르면 모델이 백그라운드에서 다시 설정되며, 바뀐 것만 다운로드하고, 새 버전으로 재시작한다. 중지된 모델은 중지된 상태로 남는다. `omarchy agent local update`는 터미널에서 모든 모델에 대해 같은 일을 한다.

명령줄에서는 `omarchy agent local start <recipe>`와 `omarchy agent local stop <recipe>`가 같은 일을 하고, `omarchy agent local status`는 모든 모델을 보여주며, `omarchy agent --local`은 마지막으로 시작한 모델 위에서 기본 에이전트를 연다. pi, OpenCode, Qwen Code는 하나를 사용할 수 있다; 기본값이 다른 것이라면 pi에서 열린다. pi는 또한 자체 모델 선택기에서 설정한 모든 모델과, 페어링한 기기에 있는 모델도 나열하므로, 평범한 `pi`도 도달할 수 있다. OpenAI 호환 클라이언트도 연결할 수 있다: `status`는 각 모델의 주소를 보여주고(첫 번째는 `http://127.0.0.1:11435/v1`), 레시피 이름이 모델이며, 키는 `~/.config/omarchy/agent-local/key`에 있다.

`omarchy agent local remove <recipe>`는 모델과 다른 모델이 사용하지 않는 다운로드를 삭제한다.

서드파티 런타임은 게시자 이름으로 표시된다. Omarchy는 모든 모델을 네트워크 접근 없이 실행한다.

### 로컬 LLM

Omarchy는 로컬 LLM 모델을 실행하는 두 가지 방법을 권장한다: LM Studio와 Ollama. LM Studio는 오픈 웨이트 모델을 찾아 설치하고 실행할 수 있는 GUI 인터페이스를 제공한다. 쉽게 시작하기에 훌륭한 방법이다. Ollama는 비슷하게 할 수 있는 CLI를 제공한다. 하지만 로컬 모델이 처음이라면, 나는 LM Studio로 시작하겠다. 둘 다 Omarchy Menu의 _Install > AI_에서 설치할 수 있다.

### Omarchy Skill

에이전트 스킬은 AI가 특정 도구를 특정 방식으로 사용하도록 돕고, Omarchy는 시스템을 맞춤화하기 위한 기본 스킬을 제공한다. Hyprland 설정을 조정하거나, 바를 고치거나, 심지어 새 테마를 처음부터 만드는 것과 같은 일이다. 이는 Claude Code(`~/.claude/skills`), Codex(`~/.codex/skills`), Pi(`~/.pi/agent/skills`), Antigravity(`~/.gemini/config/skills`), Hermes(`~/.hermes/skills` 및 각 `~/.hermes/profiles/*/skills`), 그리고 일반적인 `~/.agents/skills` 위치의 스킬 디렉터리에 심볼릭 링크되어 있어, 대부분의 하네스가 자동으로 가져간다.

하지만 이 스킬은 실험적인 것으로 취급해야 한다. 모델마다 다르게 활용할 것이다. 먼저 플랜 모드로 실행하는 것이 가장 좋으니, 에이전트가 무엇을 바꾸고 싶어 하는지 감을 잡을 수 있다. 그리고 에이전트가 모든 것을 엉망으로 만들면 변경 사항을 되돌리거나 심지어 `omarchy reinstall configs`를 호출할 준비를 하라.
