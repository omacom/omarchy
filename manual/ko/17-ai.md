# AI

Omarchy에는 아래 코딩 에이전트용 런처가 포함되어 있지만, 기본값을 대신 골라 주지는 않는다. 명령을 실행하면 처음 사용할 때 해당 CLI가 설치되고, 그다음 안내에 따라 인증하면 된다. Hermes와 OpenClaw는 예외다: mise를 통해 설치되는 것은 없으며, 둘 중 하나를 선택하면 아래 _데스크톱 앱_에서 설명하듯 자체 업데이트되는 자체 복사본이 설치된다.

### 에이전트 설치 및 업데이트

Hermes와 OpenClaw를 제외하고, 이들 에이전트는 mise의 지연 설치를 사용한다: 처음 실행할 때 CLI가 설치되고, 이후 실행에서는 그것을 재사용한다. mise는 또 설치된 에이전트에 새 릴리스가 있는지 최대 4시간에 한 번, 시작 직전이나 셸 프롬프트에서 백그라운드로 확인한다. 그 업데이트가 실패하거나 오프라인 상태이면, 설치된 버전이 실행된다. `omarchy update`는 Omarchy의 나머지 부분과 함께 설치된 에이전트를 업데이트하고, `mup`은 mise로 관리되는 도구만 업데이트한다.

`claude update`, `codex update` 같은 에이전트 자체 업데이터나 앱의 업데이트 버튼은 mise로 관리되는 설치본을 업데이트하지 않는다. `codex update`는 실패하고, `claude update`는 성공했다고 보고하면서도 mise가 추적하지 않는 별도 복사본을 설치할 수 있다. 에이전트의 네이티브 설치 프로그램과 업데이터를 대신 사용하고 싶다면, 그것을 `disable_tools`에 추가하라; [사전 설치된 CLI 도구](18-development-tools.md#preinstalled-cli-tools)를 보라.

필요해지기 전에 구성된 모든 lazy 도구를 설치하려면 `mise install --include-lazy`를 실행하라. 여기에는 에이전트뿐 아니라 Omarchy의 다른 기본 CLI 도구도 포함된다. 단일 도구를 설치하거나 직접 설치한 것을 사용하는 방법은 [사전 설치된 CLI 도구](18-development-tools.md#preinstalled-cli-tools)를 보라.

`grok`은 `claude`와 `codex`와 같은 방식으로 mise의 퍼스트파티 `grok` 패키지를 통해 설치된다. `grok`을 실행하거나 _에이전트 > 하니스_에서 선택하라. x.ai의 `curl | bash` 설치 프로그램은 건너뛰어라. 그 경로는 `~/.grok/bin`에 두 번째 복사본을 넣고, 그것을 `PATH` 앞에 추가하며, Omarchy의 래퍼를 덮어쓴다.

`dsh`는 `127.0.0.1:3080`에서 브라우저 UI를 열며, 실행 디렉터리가 기본 워크스페이스가 된다. 그 브라우저 UI는 시작 프롬프트를 받지 않으므로, `omarchy agent prompt`는 프롬프트를 클립보드에 넣어 붙여넣을 수 있게 한 상태로 그것을 연다. Omarchy는 DeepSeek의 승인 없음 권한 프리셋으로 그것을 시작한다. DeepSeek Harness는 공식 모델 API를 사용할 때 세션 로그를 DeepSeek에 업로드한다; 브라우저 UI의 _설정 > 일반 > 세션 로그 업로드_에서 끌 수 있다. 보내는 피드백도 세션과 함께 업로드되며, `DSH_TELEMETRY_MODE=DISABLED`로 시작하면 예외다.

### 기본 에이전트

`omarchy default agent <name>`으로, 또는 Omarchy Menu(`Super + Space`)의 _에이전트 > 하니스_에서 기본 에이전트를 선택하라. 에이전트가 아직 설치되지 않았다면, 선택하면 먼저 설치되고, Agent 옆 앱 런처에 자체 런처도 생긴다. 새로 설치한 Omarchy는 일회성 알림으로 이 선택을 하도록 안내한다.

Claude를 선택하면 Chromium, Chrome, Brave, Brave Origin, Edge용 브라우저 확장 프로그램 설정도 시도한다. 확장 프로그램 설정은 모든 사용자에게 적용되며 시스템 비밀번호를 물을 수 있다; 확장 프로그램 설치를 취소하거나 실패해도 Claude는 여전히 선택되고 실행된다. 브라우저를 재시작하고, 안내가 나오면 확장 프로그램을 활성화한 뒤, Claude에 로그인해 연결을 마무리하라. Claude에서 `/chrome`을 실행해 연결을 확인하라. Firefox와 Zen은 이 확장 프로그램을 지원하지 않는다. 이 설정이 추가되기 전에 이미 Claude가 기본값이었다면, 다시 선택해 확장 프로그램을 설치하라.

선택을 마치면, `Super + Shift + Ctrl + A`가 전용 터미널 창에서 기본 에이전트를 실행한다(아직 선택하지 않았다면 선택 화면을 띄운다). `omarchy agent prompt "Review this project"`처럼 작업과 함께 바로 실행할 수도 있다. Freebuff와 DeepSeek Harness는 시작 프롬프트를 받지 않으므로, 대신 프롬프트를 클립보드에 넣어 붙여넣을 수 있게 한 상태로 열린다. 이런 방식으로 실행된 에이전트는 각자의 멈추지 않고 묻지 않는 모드로 무인 실행되므로, 실제로 뭔가를 해 버릴 각오를 하라! MiniMax Code에는 대화형 세션용 그런 모드가 없어서, 평소대로 권한을 묻는다. 그리고 에이전트들은 홈 디렉터리에 대한 신뢰를 기억하기를 거부하므로, `$HOME`에서 실행하면 대신 `~/Work`에서 시작한다.

터미널 단축키도 있다: `a`는 현재 터미널 안에서 기본 에이전트를 실행하고, `c`, `cx`, `cy`는 OpenCode, Claude Code, Codex를 직접 시작한다(역시 자동 승인 모드로). 테마 변경도 에이전트에 동기화된다: Omarchy 테마를 바꾸면 Claude Code, Pi, OpenCode, 그리고 (Omarchy가 설치한 뒤의) Hermes가 모두 따라온다.

### 에이전트 지침

모든 에이전트에 대한 개인 규칙은 `~/.agents/skills`의 공유 스킬 옆 `~/.agents/AGENTS.md`에 넣는다. _에이전트 > 지침_에서 열면, 자체 전역 파일을 유지하는 각 하니스에도 링크된다: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, Copilot의 `~/.copilot/copilot-instructions.md` 등이다. Crush와 Amp는 `~/.config/AGENTS.md` 링크를 읽고, omp, Kimi, DeepSeek Harness는 `~/.agents/AGENTS.md`를 직접 읽는다. 기본 에이전트를 선택하면 그쪽에도 링크된다. 이미 가지고 있던 지침 파일은 공유 파일이 아직 없을 경우 공유 파일이 되고, 그렇지 않으면 링크 옆에 `.bak`으로 보관된다. 다른 에이전트를 설치한 뒤 다시 링크하려면 `omarchy agent instructions`를 실행하라.

### 에이전트 패널

상단 바에는 에이전트 아이콘이 있다. 에이전트를 설정하기 전에는, 그 패널이 Claude, Codex, Grok 중 하나에 로그인하는 과정을 안내하고, 첫 번째로 설정한 것이 기본 에이전트가 된다. 그 이후에는 패널이 모든 구독을 한 페이지에 모은다: 각 에이전트와 계정, 그 요금제, 5시간 세션 한도와 주간 한도 각각의 미터와 초기화까지 남은 시간(정확한 백분율은 마우스를 올리면 표시), 또는 남은 선불 잔액을, 이번 주 토큰 수와 가장 많이 사용한 모델처럼 전체에서 사용한 내용을 번갈아 보여 주는 한 줄 아래에 표시한다. _멋진 것 만들기_ 아래에서는 새 테마, 플러그인, 앱, 게임용 시작 프롬프트를 제공하며, 작업을 기본 에이전트에 맡긴다. 앱은 Omarchy 자체의 Hype, Monologue, Omacut이 만들어진 방식대로 C++와 Qt Quick으로 빌드되며, omarchy-make-app 에이전트 스킬을 따르고, 필요한 컴파일러와 Qt 구성 요소가 설치되어 온다. 게임은 omarchy-make-game 에이전트 스킬을 따라 `~/Games/vibes`에 있는 단일 three.js 페이지이며, 모두 현재 테마의 하나의 Game Vibes 런처에서 열린다; three.js를 웹에서 불러오므로 시작하려면 연결이 필요하다. Claude Code, Codex, Grok, Kimi, Cursor와 그 Grok Bot 허용량, GitHub Copilot, Muse, Antigravity, Devin은 한도와 함께 기본으로 지원되고, Kimchi는 요금제, 선불 크레딧, 지출 예산과 함께, Hermes, Mistral Vibe, Qwen Code는 사용한 뒤 세션과 토큰을 보여 준다. pi, omp, opencode를 통해 사용하는 제공자 요금제와 키도 표시된다: 한도와 함께 OpenCode Zen과 Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan, Synthetic; 선불 잔액과 함께 OpenRouter와 DeepSeek; 최근 30일 지출과 함께 Fireworks. 자체 하드웨어에서 실행하는 모델의 토큰도 합계에 포함된다; 모델 자체에는 [로컬 모델](#local-models)에 설명된 전용 패널이 있다. 모든 에이전트는 몇 개의 하니스를 통해 구동하든 청구 주체 기준으로 한 번만 계산된다.

바 아이콘을 왼쪽 클릭하거나 `Super + Ctrl + X`를 누르면 패널이 열리고, 오른쪽 클릭하면 기본 에이전트가 실행되며, 가운데 클릭하면 새로고침한다. 그 뒤의 사용 기록은 `omarchy agent usage update`가 15분마다 재생성하며, 패널은 동기화된 폴더를 통해 다른 컴퓨터의 사용량까지 병합할 수도 있다. 전체 설정은 `$OMARCHY_PATH/shell/plugins/agents/` 아래 README를 보라.

### 여러 구독

개인 Max와 업무용처럼 Claude, Codex, Grok 요금제를 하나 이상 결제하고 있다면, Omarchy는 모두 로그인 상태를 유지하고 그 사이를 오갈 수 있다. 에이전트 패널의 +로 구독을 추가하면 그 자리에서 과정을 안내하고, 또는 `omarchy agent account add claude Work`(또는 `codex`, 또는 `grok`)로 추가한다. 누락된 경우 CLI를 설치한다. 제공자의 첫 번째 계정은 CLI가 항상 찾는 바로 그곳에서 일반 브라우저를 통해 로그인한다. 그 이후의 모든 계정은 프라이빗 창을 통해 로그인하므로, 브라우저에 이미 로그인된 계정이 실수로 선택되지 않는다; 추가하려는 계정으로 거기서 로그인하고, 이미 열어 둔 프라이빗 창은 먼저 닫아라. 이를 위해 CLI에서 절대 로그아웃하지 마라: 로그아웃하면 저장된 로그인이 취소되어, 그 계정을 다시 추가해야 한다.

SSH를 통해 다른 Omarchy 컴퓨터로 구독 로그인을 복사하려면 `omarchy agent account copy user@laptop`을 실행하라. 대상에 수신기가 설치되어 있지 않으면 발신자가 임시 수신기를 제공하므로, 오래된 Omarchy 컴퓨터도 업데이트 없이 계정을 받을 수 있다. 설치된 수신기가 우선한다. 이는 모든 Claude, Codex, Grok 구독을 복사한다; `omarchy agent account copy laptop claude`처럼 제공자 이름을 추가해 선택하라. 계정 이름과 명령 ID는 대상에 이미 있는 계정을 포함해 원본과 일치한다. 관련 없는 대상 계정은 이름이 충돌하면 숫자 접미사를 받으며, 설정, 스킬, 플러그인, 대화 기록은 각 컴퓨터에 로컬로 남는다.

기존 대상 자격 증명은 유지된다. 대상에 이미 로그인된 원본 계정은 자격 증명을 교체하지 않고 이름만 동기화되고, 다른 계정은 그 옆에 추가된다. 일치하는 계정의 저장된 자격 증명을 교체하려면, 대상에서 그 계정의 세션을 종료한 뒤 `omarchy agent account copy --replace laptop claude`를 사용하라. 새로 설정한 대상은 원본의 활성 계정과 전환 기본 설정도 받는다; 이미 사용 중인 대상은 자체 설정을 유지한다.

자격 증명은 SSH를 통해 이동하고 대상의 비공개 파일에 저장되므로, 신뢰하는 컴퓨터에만 복사하라. 이는 일회성 복사이지 지속적인 동기화가 아니다. Codex 새로고침 토큰은 다른 컴퓨터가 교체할 수 있어, 복사된 로그인에 갱신이 필요해질 수 있다; 여러 컴퓨터에서 동시에 사용하려면 별도 로그인이 가장 안정적이다. [Codex의 계정 인증 가이드](https://developers.openai.com/codex/auth/ci-cd-auth)를 보라.

제공자당 하나의 계정이 활성화되고, 모든 새 세션은 그 계정으로 시작한다: `cx`, `cy`, 일반 `claude`, `codex`, `grok`, `omarchy agent`를 통해 실행되는 모든 것, 그리고 `PATH`에서 CLI를 찾는 스크립트나 편집기가 그렇다. `omarchy agent account use work`로 전환하고(`omarchy agent account use main`으로 돌아온다), 또는 패널에서 계정 번호를 누른 뒤 `Enter`를 누르거나(또는 Use 버튼 클릭) 전환한다. 실행 중인 Claude 세션도 다음 메시지부터 전환된다: 모든 Claude 세션은 항상 활성 계정의 로그인 정보를 담고 있는 `~/.claude`에서 실행된다. 이전 Omarchy가 계정 전용 폴더에서 시작한 Claude 세션은 종료될 때까지 그 로그인 정보를 유지하므로, 전환 시 해당 세션들을 알려 주고 사라지면 스스로 마무리한다. 실행 중인 Codex와 Grok 세션은 시작한 계정에 머무른다. 대화 기록, 설정, 스킬, 플러그인은 계정 간에 공유되므로, 같은 폴더에서 `claude --continue`를 하면 새 계정에서 중단한 지점부터 이어진다.

계정이 하나보다 많으면, 패널은 각 계정의 한도를 나란히 보여 주고 활성 계정을 표시한다. 활성 계정이 한도의 95%를 넘으면 Omarchy가 알리고, 알림을 클릭하면 여유가 가장 많은 계정으로 전환한다. 스스로 전환하지는 않는다. 임계값은 `omarchy agent account threshold 90`으로 바꾼다. 모든 계정이 임계값을 넘으면, 어느 계정이 가장 먼저 여유가 생기는지와 함께 한 번 알린다. 활성 계정이 임계값에서 15포인트 이내(기본값에서는 80%)에 있으면, 한도를 15분이 아니라 3분마다 확인한다.

`omarchy agent account list`는 모든 계정과 최신 한도를 보여 주고, `omarchy agent account remove work`는 하나를 잊으며, `omarchy agent account rename primary Hey`는 이름을 바꾼다(또는 패널에서 계정 이름 클릭). 이들 명령은 기본 에이전트의 계정에 대해 동작한다; 다른 제공자에 접근하려면 `omarchy agent account use codex side`처럼 먼저 이름을 지정하라. `~/.claude` 또는 `~/.codex`에 이미 있던 로그인이 _Main_ 계정이다. Codex의 것은 제자리에 남는다; Claude의 것은 다른 계정이 활성일 동안 자체 폴더에서 대기한다. 약 8시간 이상 사용하지 않은 계정은 _로그인 필요_로 표시될 수 있다; 클릭하면 패널에서 바로 그 계정에 다시 로그인하거나, 그 계정으로 전환해 세션을 시작하면 로그인 정보가 스스로 새로고침된다. `claude mcp add`로 추가한 MCP 서버는 모두 `~/.claude`에서 실행되므로 모든 Claude 계정에 도달한다; Codex와 Grok의 경우, 계정이 추가될 때 있던 서버는 그 계정으로 따라오지만, 나중에 추가한 서버는 추가한 계정에만 도달한다. Claude Desktop은 자체 로그인을 유지하고, CLI 바이너리에 대한 절대 경로로 구성된 Codex 또는 Grok 도구는 전환을 따르지 않는다. 명시적인 `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, `GROK_HOME`은 선택한 계정보다 우선한다.

### 충돌 진단

Omarchy는 systemd-coredump로 프로세스 충돌을 감시한다. 기본 에이전트를 선택한 뒤에는, 코어를 덤프하는 당신의 프로그램이 "Process crashed" 알림을 띄운다 — 클릭하면, 충돌이 Omarchy의 omarchy-diagnose-crash 스킬과 함께 기본 에이전트에 전달되며, 그 스킬은 코어 덤프에서 사실을 확정하고 충돌을 업스트림에 보고할 가치가 있는지 결정하는 과정을 에이전트에게 안내한다. `coredumpctl list`의 아무 PID에 대해 `omarchy agent crash <pid>`로 직접 실행할 수도 있다.

감시는 기본으로 켜져 있다. _트리거 > 토글 > 충돌 캡처 끄기_에서 끄거나(또는 `omarchy toggle crash-capture`로) 하면 알림이 중단된다; `omarchy agent crash <pid>`는 수동으로는 여전히 동작한다.

충돌은 프로그램별로도 음소거할 수 있으며, 이는 진단이 마지막에 제안하는 것이다. `omarchy crash mute hyprland`는 그 프로그램에 대해서만 알림을 중단하고, `omarchy crash mute hyprland off`는 다시 켜며, `omarchy crash mute`만 실행하면 음소거한 목록을 보여 준다. 바이너리의 이름만큼이나 그 경로도 잘 받아들이므로, `omarchy crash mute /usr/bin/hyprland`도 같은 일을 한다. 공백이 있는 이름은 `omarchy crash mute 'Some App'`처럼 인용하라. 다른 모든 것은 여전히 알리고, 음소거된 프로그램은 여전히 충돌한다 — 이는 알림을 숨길 뿐, 아무것도 고치지 않는다.

### 데스크톱 앱

_설치 > AI_ 메뉴에는 몇 가지 그래픽 AI 앱도 있다: Amp Desktop, Antigravity Desktop, ChatGPT 데스크톱 앱, Claude 데스크톱 앱(Anthropic의 Linux 베타, Chat, Cowork, Claude Code 탭 포함), xAI 모델과 채팅하는 Grok Bot, Herdr Desktop, Hermes Desktop, OpenClaw, Perplexity 데스크톱 앱, T3 Code. Grok Bot은 데스크톱 채팅 앱이다. 코딩 에이전트는 `grok` 명령이다.

Hermes Desktop은 알아둘 만한 것이다, 컴퓨터에는 하나의 Hermes만 있고 그것은 앱의 것이기 때문이다: Hermes는 오직 앱을 통해서만 설치되며, 기본 에이전트가 실행하는 `hermes` 명령은 앱의 것이다. Hermes를 기본 에이전트로 선택하면 _설치 > AI_ 항목이 하는 것과 같은 것이 설치된다: 패키지와, Hermes 자체 설치 프로그램이 `~/.hermes` 아래 설정하는 Hermes 런타임으로, 처음에는 몇 분이 걸린다. 그 런타임이 터미널 `hermes` 명령, 기본 에이전트, 앱이 모두 사용하는 유일한 Hermes이며, Omarchy 릴리스를 기다리지 않고 `hermes update`로 자체 업데이트한다. 설치하면 Omarchy 테마를 `omarchy`라는 이름의 스킨으로 Hermes에 제공하며, 모든 Hermes 화면은 테마를 바꿀 때 이를 따르고; 원하지 않으면 Hermes의 Appearance 설정이나 `/skin`으로 다른 것을 선택하면 Omarchy는 그 선택을 그대로 둔다. _제거 > AI_에서 앱을 제거하면 먼저 게이트웨이를 포함해 Hermes를 종료하고, 그 런타임을 함께 제거하며, 달리 지시하지 않는 한 채팅, 메모리, Hermes가 스스로 작성한 스킬을 유지한다: 그 데이터와 연결 설정도 함께 지울지 묻고, 기본값은 아니오다.

OpenClaw의 데스크톱 경험은 Control UI로, 자체 로컬 게이트웨이를 백엔드로 하는 웹 앱으로 열린다. OpenClaw는 `~/.openclaw`에 살고 자체 업데이트한다: Control UI의 "Update Gateway" 버튼을 사용하거나 `openclaw update`를 실행하면, 게이트웨이가 새 버전으로 재시작한다. Omarchy는 새로 설치할 때 시작할 릴리스만 선택한다. OpenClaw는 기본 에이전트도 될 수 있다: _에이전트 > 하니스_에서 선택하면 `~/.openclaw`에 같은 복사본이 설치되고, 에이전트는 게이트웨이에 연결된 OpenClaw의 터미널 UI를 연다. _제거 > AI_에서 OpenClaw를 제거하면 게이트웨이 서비스와 앱을 함께 제거한 뒤, 채팅과 자격 증명은 물론 OpenClaw 자체와 다운로드하는 플러그인 런타임이 들어 있는 `~/.openclaw`도 지울지 묻는다; 기본값은 유지하는 것이며, OpenClaw를 다시 설치하면 그것을 다시 사용한다.

Herdr Desktop은 [Herdr](https://herdr.dev) 데스크톱 앱이다: 창을 닫아도 그 코어에서 계속 실행되는 터미널과 코딩 에이전트의 공간, 탭, 페인을 제공한다. 패키지가 아니라 Herdr 자체 설치 프로그램에서 오므로 `~/.local/share/herdr-app`에 살고, 아직 없을 때 `~/.local/bin/herdr-core`에 그 코어를 함께 가져오며, 둘 다 자체 업데이트한다. 그것은 Omarchy가 `Super + Ctrl + Return`으로 제공하는 `herdr` 명령을 대체하지 않고 그 옆에 자리하며, 그 명령의 직접 키를 받는다: `Alt + Return`과 `Alt + Shift + Return`은 페인을 아래나 오른쪽으로 나누고, `Alt + Escape`는 닫으며, `Ctrl + Alt + Arrow`는 페인 사이를 이동하고, `Alt + 1..9`와 `Alt + Left/Right`는 탭을 선택하며, `Alt + Up/Down`은 공간 사이를 이동한다. `Ctrl + 1..9`는 공간을 선택하고 `Alt + Shift + Up/Down`은 에이전트를 오간다. `Ctrl + Space` 접두 키는 터미널 전용으로 남는다, 앱이 시퀀스를 위해 일반 Ctrl 키를 유지할 수 없기 때문이다. Omarchy는 이를 `~/.config/herdr-app/keys.json`에 쓰고, `omarchy-refresh-herdr-app`가 되돌려 놓는다. 설치하면 Herdr의 Omarchy 테마를 선택하며, 이후로 Omarchy 테마를 따른다. Herdr는 라이트 모드용 테마 하나와 다크 모드용 테마 하나를 유지하므로, 다크 Omarchy 테마와 라이트 Omarchy 테마 사이를 전환한 뒤에는 다른 모드에 대해 Herdr의 테마 선택기에서 Omarchy를 한 번 더 선택하라.

T3 Code는 패키지가 아니라 `~/.local/share/t3code`의 공식 AppImage 릴리스에서 실행되므로 자체 업데이트한다. 설치하면 Stable 채널로 시작할지 Nightly 채널로 시작할지 묻는다; 나중에 T3 Code 설정에서 전환한다. 스레드와 설정은 `~/.t3`에 살고, _제거 > AI_에서 T3 Code를 제거하면 함께 제거된다.

### 로컬 모델

코딩 에이전트를 위해 자체 컴퓨터에서 오픈 모델을 실행하라. 프롬프트와 코드는 컴퓨터에 남는다; 모델로 보낸 어떤 것도 컴퓨터를 떠나지 않는다. 다음으로 시작하라:

```bash
omarchy models use best text
```

이는 이 컴퓨터에 가장 적합한 텍스트 모델, 에이전트가 사용하는 종류를 설정한다. 이미지, 비디오, 음악 모델에도 각각 최고의 선택이 있다: `omarchy models use best image`, `video`, 또는 `music`. `omarchy models use best`를 실행하면 각 종류의 이 컴퓨터용 선택을 볼 수 있다.

또는 상단 바의 에이전트 아이콘 옆 반짝이 아이콘에서, 또는 Super + Ctrl + Alt + X로 로컬 모델 패널을 열고 +를 선택하라. 아이콘은 모델이 이 컴퓨터에 맞을 때 표시된다. 모델을 실행하는 Podman은 Omarchy와 함께 오고, NVIDIA 컴퓨터에서는 GPU를 제공하는 NVIDIA 컨테이너 툴킷도 함께 온다; 둘 중 하나가 없으면 첫 설정 시 설치된다. 그다음 Omarchy는 이 컴퓨터에 권장되는 모델을 선택하고, 다운로드하고, 시작한다. 수십 GB의 다운로드와 모델 실행 중 컴퓨터 메모리의 대부분이 사용될 것을 예상하라: Flash Next는 전체 256K 컨텍스트로 약 100 GiB를 사용한다. 다른 모델이 필요한 메모리를 차지하고 있으면, 중지 상태로 설정되어 하나를 중지하면 시작할 준비가 된다. 모델은 로그아웃 시 중지된다; 다른 용도로 메모리가 필요할 때 직접 중지하라.

`omarchy models list`는 옵션을 보여 주고 일부가 맞지 않는 이유를 설명한다. 다른 것을 설정하려면 `omarchy models use <recipe>`를 실행하라. 오늘 기준, `qwen3.8-flash-next-gufo`와 `qwen3.8-27b-gufo`는 128 GB Strix Halo 컴퓨터용으로 제공된다; 27B는 약 40 GiB를 사용하므로 다른 작업을 위한 공간을 남긴다. Intel Arc B390이 있는 64 GB 노트북에서는 `qwen3.6-35b-a3b-llamacpp`가 약 30 GiB로 실행된다. 새 레시피와 권장 사항은 패키지를 통해 `omarchy update`와 함께 제공된다.

설정한 모든 모델은 로컬 모델 패널에 자체 줄을 받는다: 재생하면 시작하고, 일시정지하면 중지해 메모리를 해제하며, 터미널 버튼을 누르면 그 모델에서 에이전트를 연다. 상단에는 바가 Omarchy 자체(시스템과 앱), 실행 중인 각 모델, 여유 공간 사이에 컴퓨터 메모리가 어떻게 나뉘는지 보여 준다. 중지된 모델을 가리키면 바가 맞는지, 또는 얼마나 부족한지 보여 준다. 메모리 안에서 함께 맞으면 여러 개가 동시에 실행될 수 있다; 맞지 않으면 Omarchy는 어느 실행 중인 모델을 중지해야 하는지 알려 준다. 로고로 줄을 드래그해 순서를 바꾸고, 선택한 줄에서 Delete를 눌러 모델과 그 다운로드를 제거하라.

설정한 모든 코딩 모델은 앱 런처에도 모델 이름과 제작사 로고와 함께 자체 항목을 받으며, Claude, Codex, Grok에 로그인하면 하나가 추가되는 방식과 같다. 그것은 그 모델에서 에이전트를 열고, 실행 중이 아니면 먼저 모델을 시작한다: 터미널이 로딩을 보여 주고 준비되면 에이전트에게 넘긴다. 모델을 제거하면 그 항목도 제거된다.

모든 모델이 코딩용은 아니다. 이미지, 비디오, 음악 모델은 대신 Fantasi에서 열리며, Fantasi는 이 컴퓨터에서 실행되는 모델로 사진, 비디오, 음악을 만드는 Omarchy 앱으로, 거기서 또는 로컬 모델 패널의 해당 줄에서 선택한다.

모델은 설정된 그대로 계속 실행되므로, Omarchy 업데이트가 에이전트 아래에서 모델을 절대 재시작하지 않는다. Omarchy에 설정한 모델에 대한 더 새로운 런타임이나 더 새로운 가중치가 있으면, 그 줄에 업데이트 버튼이 표시된다: 누르면 모델이 백그라운드에서 다시 설정되며 변경된 것만 다운로드하고, 새 버전으로 재시작한다. 중지된 모델은 중지된 상태로 남는다. `omarchy models update`는 터미널에서 모든 모델에 대해 같은 일을 한다.

명령줄에서 `omarchy models start <recipe>`와 `omarchy models stop <recipe>`가 같은 일을 하고, `omarchy models status`는 모든 모델을 보여 주며, `omarchy agent --local`은 기본 에이전트가 무엇이든 마지막으로 시작한 모델을 pi에서 연다. OpenCode와 Qwen Code도 로컬 모델을 사용할 수 있다: `omarchy models harness opencode` 또는 `omarchy models harness qwen`은 대신 거기서 열고, `omarchy models harness pi`는 돌아간다. pi는 설정한 모든 모델과, 페어링한 컴퓨터에 있는 모델도 자체 모델 선택기에 나열하므로, 일반 `pi`도 그것들에 도달할 수 있다. OpenAI 호환 클라이언트도 연결할 수 있다: `status`는 각 모델의 주소를 보여 주고(첫 번째는 `http://127.0.0.1:11435/v1`), 레시피 이름이 모델이며, 키는 `~/.config/omarchy/agent-local/key`에 있다.

`omarchy models remove <recipe>`는 모델과 다른 어떤 모델도 사용하지 않는 다운로드를 삭제한다.

타사 런타임은 게시자 이름으로 표시된다. Omarchy는 모든 모델을 네트워크 액세스 없이 실행한다.

### 로컬 LLM

Omarchy는 로컬 LLM 모델을 실행하는 두 가지 방법을 권장한다: LM Studio와 Ollama. LM Studio는 오픈 웨이트 모델을 찾고, 설치하고, 실행하는 GUI 인터페이스를 제공한다. 쉽게 시작하기 좋은 방법이다. Ollama는 비슷하게 하는 CLI를 제공한다. 하지만 로컬 모델이 처음이라면, 나는 LM Studio부터 시작하겠다. 둘 다 Omarchy Menu의 _설치 > AI_에서 설치할 수 있다.

### Omarchy 스킬

에이전트 스킬은 AI가 특정 도구를 특정 방식으로 사용하도록 돕고, Omarchy는 그중 일곱 가지를 제공한다. omarchy 스킬은 Hyprland 설정을 조정하거나 바를 조정하는 등 시스템을 맞춤 설정하는 일을 다룬다. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app, omarchy-make-game은 새로운 것을 만드는 일을 다루고, omarchy-contribute는 버그를 보고하거나 업스트림에 수정 사항을 보내는 일을, omarchy-diagnose-crash는 충돌의 코어 덤프를 분석하는 일을 다룬다. 이들은 Claude Code(`~/.claude/skills`), Codex(`~/.codex/skills`), Pi(`~/.pi/agent/skills`), Antigravity(`~/.gemini/config/skills`), Hermes(`~/.hermes/skills`와 각 `~/.hermes/profiles/*/skills`), 그리고 일반 `~/.agents/skills` 위치의 스킬 디렉터리에 심링크되어 있어, 대부분의 하니스가 자동으로 가져간다. 같은 이름의 직접 만든 스킬 폴더가 우선한다.

하지만 이들 스킬은 실험적인 것으로 취급해야 한다. 모델마다 이를 활용하는 효과가 다를 것이다. 에이전트가 무엇을 바꾸고 싶어 하는지 감을 잡을 수 있도록, 먼저 계획 모드로 실행하는 것이 가장 좋다. 그리고 에이전트가 모든 것을 엉망으로 만들면, 변경 사항을 롤백하거나 심지어 `omarchy reinstall configs`를 호출할 준비를 하라.
