### 에이전트 설치 및 업데이트

Hermes를 제외하고, 이 에이전트들은 mise의 지연 설치를 사용한다: 처음 실행하면 CLI를 설치하고, 이후 실행에서는 그것을 재사용한다. mise는 또한 설치된 에이전트에 새 릴리스가 있는지 시작 직전 또는 셸 프롬프트에서 백그라운드로 최대 네 시간에 한 번 확인한다. 그 업데이트가 실패하거나 오프라인 상태이면, 설치된 버전이 실행된다. `omarchy update`는 Omarchy의 나머지와 함께 설치된 에이전트를 업데이트하고, `mup`은 mise가 관리하는 도구만 업데이트한다.

`claude update`, `codex update` 같은 에이전트 자체의 업데이터나 앱 안의 업데이트 버튼은 mise가 관리하는 설치를 업데이트하지 않는다. `codex update`는 실패하고, `claude update`는 성공했다고 보고하면서도 mise가 추적하지 않는 별도의 복사본을 설치할 수 있다. 에이전트의 네이티브 인스톨러와 업데이터를 쓰고 싶다면, 그것을 `disable_tools`에 추가하라; [Preinstalled CLI tools](18-development-tools.md#preinstalled-cli-tools)를 보라.

필요해지기 전에 구성된 모든 지연 도구를 설치하려면, `mise install --include-lazy`를 실행하라. 여기에는 에이전트뿐 아니라 Omarchy의 다른 기본 CLI 도구도 포함된다. 단일 도구를 설치하거나 직접 설치한 것을 사용하는 방법은 [Preinstalled CLI tools](18-development-tools.md#preinstalled-cli-tools)를 보라.

`grok`은 `claude`와 `codex`와 같은 방식으로 mise의 퍼스트파티 `grok` 패키지를 통해 설치된다. `grok`을 실행하거나, _Agent > Harness_에서 그것을 선택하라. x.ai의 `curl | bash` 인스톨러는 건너뛰어라. 그 경로는 `~/.grok/bin`에 두 번째 복사본을 넣고, 그것을 `PATH` 앞에 붙이며, Omarchy의 래퍼를 덮어쓴다.

`dsh`는 실행 디렉터리를 기본 워크스페이스로 삼아 `127.0.0.1:3080`에서 브라우저 UI를 연다. 그 브라우저 UI는 시작 프롬프트를 받지 않으므로, `omarchy agent prompt`는 프롬프트를 클립보드에 넣어 붙여넣을 수 있게 한 채로 그것을 연다. Omarchy는 DeepSeek의 무승인 권한 프리셋으로 그것을 시작한다. DeepSeek Harness는 공식 모델 API를 사용할 때 세션 로그를 DeepSeek에 업로드한다; 브라우저 UI의 _Settings > General > Upload Session Log_에서 그것을 꺼라. 네가 보내는 피드백도 `DSH_TELEMETRY_MODE=DISABLED`로 시작하지 않는 한 세션과 함께 업로드된다.

### 기본 에이전트

`omarchy default agent <name>`으로, 또는 Omarchy Menu(`Super + Space`)의 _Agent > Harness_에서 기본 에이전트를 선택하라. 에이전트가 아직 설치되지 않았다면, 선택하면 먼저 그것을 설치한다. 새 Omarchy는 일회성 알림으로 이 선택을 하도록 초대할 것이다.

Claude를 선택하면 Chromium, Chrome, Brave, Brave Origin, 그리고 Edge용 브라우저 확장도 설정을 시도한다. 확장 설정은 모든 사용자에게 적용되며 시스템 비밀번호를 물을 수 있다; 확장 설치를 취소하거나 실패해도 Claude는 여전히 선택되고 실행된다. 브라우저를 재시작하고, 안내가 나오면 확장을 활성화한 뒤, Claude에 로그인하여 연결을 마쳐라. Claude에서 `/chrome`을 실행해 연결을 확인하라. Firefox와 Zen은 이 확장을 지원하지 않는다. 이 설정이 추가되기 전에 이미 Claude가 기본이었다면, 그것을 다시 선택해 확장을 설치하라.

선택을 마쳤으면, `Super + Shift + Ctrl + A`는 기본 에이전트를 전용 터미널 창에서 실행한다(또는 아직 선택하지 않았다면 선택기를 띄운다). `omarchy agent prompt "Review this project"`로 작업을 바로 맡기며 실행할 수도 있다. Freebuff와 DeepSeek Harness는 시작 프롬프트를 받지 않으므로, 대신 프롬프트를 클립보드에 넣어 붙여넣을 수 있게 한 채로 열린다. 이렇게 실행된 에이전트는 각자의 묻지 않고 멈추지 않는 모드로 무인 실행되니, 실제로 일을 저지를 준비를 하라! MiniMax Code는 대화형 세션에 그런 모드가 없어서 평소대로 권한을 묻는다. 그리고 에이전트들은 홈 디렉터리에 대한 신뢰를 기억하기를 거부하므로, `$HOME`에서 실행하면 대신 `~/Work`에서 시작한다.

터미널 단축키도 있다: `a`는 현재 터미널 안에서 기본 에이전트를 인라인으로 실행하고, `c`, `cx`, `cy`는 OpenCode, Claude Code, Codex를 직접 시작한다(역시 자동 승인 모드로). 테마 변경도 에이전트에 동기화된다: Claude Code, Pi, OpenCode, 그리고 Hermes(Omarchy가 설치한 뒤)는 모두 Omarchy 테마를 바꿀 때 따라간다.

### 에이전트 지침

모든 에이전트에 대한 개인 규칙은 `~/.agents/skills`의 공유 스킬 옆인 `~/.agents/AGENTS.md`에 들어간다. _Agent > Instructions_에서 그것을 열어라. 그곳은 또한 각 하네스가 자체 전역 파일을 두는 곳으로 그것을 링크한다: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, Copilot의 `~/.copilot/copilot-instructions.md` 등등. Crush와 Amp는 `~/.config/AGENTS.md` 링크를 읽고, omp, Kimi, DeepSeek Harness는 `~/.agents/AGENTS.md`를 직접 읽는다. 기본 에이전트를 선택하면 그것도 링크한다. 이미 갖고 있던 지침 파일이 있는데 공유 파일이 아직 없었다면 그것이 공유 파일이 되고; 그렇지 않으면 링크 옆에 `.bak`으로 보관된다. 다른 에이전트를 설치한 뒤 다시 링크하려면 `omarchy agent instructions`를 실행하라.

### 에이전트 패널

상단 바에는 에이전트 아이콘이 있다. 에이전트를 설정하기 전에는, 그 패널이 Claude, Codex, 또는 Grok에 로그인하는 과정을 안내하고, 그중 첫 번째가 기본 에이전트가 된다. 그 뒤에는, 패널이 모든 구독을 한 페이지에 모은다: 각 에이전트와 계정에 그 요금제를, 5시간 세션 한도와 주간 한도 각각에 대한 게이지를 재설정까지 남은 시간과 함께(정확한 백분율은 호버), 또는 남은 선불 잔액을, 그리고 그 모든 것을 통틀어 네가 사용한 것(예: 이번 주 토큰과 가장 많이 사용한 모델)을 순환 표시하는 줄 아래에 보여준다. _Make something_ 아래에서는 새 테마, 플러그인, 또는 앱을 위한 시작 프롬프트를 제공하며, 작업을 기본 에이전트에게 넘긴다. 앱은 Omarchy 자체의 Hype, Monologue, Omacut이 만들어지는 방식대로, C++와 Qt Quick으로, omarchy-app 에이전트 스킬을 따라 만들어지며, 필요한 컴파일러와 Qt 구성 요소는 설치된 채로 제공된다. Claude Code, Codex, Grok, Kimi, Cursor와 그 Grok Bot 할당량, GitHub Copilot, Muse, Antigravity, Kimchi, Devin은 한도와 함께 기본으로 커버되고, Hermes, Mistral Vibe, Qwen Code는 사용한 뒤 세션과 토큰을 보여준다. pi, omp, 또는 opencode를 통해 사용하는 제공자 요금제와 키도 나타난다: OpenCode Zen과 Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan, Synthetic은 한도와 함께; Fireworks, OpenRouter, DeepSeek는 선불 잔액과 함께; 그리고 Local models 아래에서는 자체 하드웨어에서 실행하는 모델들을 보여준다. 모든 에이전트는 몇 개의 하네스를 통해 구동하든, 요금을 청구하는 쪽 아래에서 한 번만 집계된다.

패널은 바 아이콘을 왼쪽 클릭하고, 기본 에이전트 실행은 오른쪽 클릭하라. 그 뒤의 사용 기록은 `omarchy agent usage-update`에 의해 15분마다 재생성되며, 패널은 동기화된 폴더를 통해 다른 머신의 사용량까지 병합할 수 있다. 전체 설정은 `$OMARCHY_PATH/shell/plugins/agents/` 아래의 README를 보라.

### 여러 구독

개인 Max와 업무용 하나처럼, Claude, Codex, 또는 Grok 요금제를 둘 이상 결제한다면, Omarchy는 모두 로그인된 상태로 유지하고 그 사이를 이동할 수 있다. 에이전트 패널의 +로 구독을 추가하면 그 자리에서 과정을 안내하고, 또는 `omarchy agent account add claude Work`(또는 `codex`, 또는 `grok`)로 추가하라. CLI가 없으면 설치한다. 제공자의 첫 번째 계정은 CLI가 항상 찾는 바로 그곳인 일반 브라우저를 통해 로그인한다. 그 뒤의 모든 계정은 비공개 창을 통해 로그인하므로, 브라우저에 이미 로그인된 계정이 실수로 선택되지 않는다; 거기서 추가하려는 계정으로 로그인하고, 이미 열어둔 비공개 창이 있으면 먼저 닫아라. 이를 위해 CLI에서 절대 로그아웃하지 마라: 로그아웃하면 저장된 로그인이 취소되고, 그 계정을 다시 추가해야 할 것이다.

구독 로그인을 SSH를 통해 다른 Omarchy 머신에 복사하려면, `omarchy agent account copy user@laptop`를 실행하라. 대상에 수신기가 설치되어 있지 않으면 발신자가 임시 수신기를 제공하므로, 오래된 Omarchy 머신도 업데이트 없이 계정을 받을 수 있다. 설치된 수신기가 우선한다. 이는 모든 Claude, Codex, Grok 구독을 복사한다; 선택하려면 `omarchy agent account copy laptop claude`처럼 제공자 이름을 추가하라. 계정 이름과 명령 ID는 대상에 이미 있는 계정을 포함해 원본과 일치한다. 관련 없는 대상 계정은 이름이 충돌하면 숫자 접미사를 받으며, 설정, 스킬, 플러그인, 대화 기록은 각 머신에 로컬로 남는다.

기존 대상 자격 증명은 유지된다. 원본 계정이 이미 거기 로그인되어 있으면 자격 증명을 교체하지 않고 이름이 동기화되고; 다른 계정은 그 옆에 추가된다. 일치하는 계정의 저장된 자격 증명을 교체하려면, 대상에서 그 계정의 세션을 종료한 뒤 `omarchy agent account copy --replace laptop claude`를 사용하라. 새 대상은 원본의 활성 계정과 전환 환경 설정도 받는다; 이미 자리 잡은 대상은 자체 것을 유지한다.

자격 증명은 SSH를 통해 이동하고 대상의 비공개 파일에 저장되니, 신뢰하는 머신에만 복사하라. 이는 일회성 복사이지 지속적인 동기화가 아니다. Codex 리프레시 토큰은 다른 머신에 의해 교체될 수 있어, 복사된 로그인이 갱신이 필요한 상태로 남을 수 있다; 여러 머신에서 동시에 사용하는 가장 신뢰할 수 있는 선택은 여전히 별도 로그인이다. [Codex의 계정 인증 가이드](https://developers.openai.com/codex/auth/ci-cd-auth)를 보라.

제공자당 하나의 계정이 활성화되며, 모든 새 세션은 그 계정으로 시작한다: `cx`, `cy`, 평범한 `claude`, `codex`, 또는 `grok`, `omarchy agent`를 통해 실행되는 모든 것, 그리고 `PATH`에서 CLI를 찾는 스크립트나 편집기. `omarchy agent account use work`로 전환하고(`omarchy agent account use main`으로 돌아오라), 또는 패널에서 계정의 번호를 누른 뒤 `Enter`를 누르거나(또는 Use 버튼을 클릭) 전환하라. 이미 실행 중인 세션은 시작한 계정에 그대로 머문다. 대화 기록, 설정, 스킬, 플러그인은 계정 간에 공유되므로, 같은 폴더의 `claude --continue`는 새 계정에서 중단한 곳부터 이어간다.

계정이 둘 이상이면, 패널은 각 계정의 한도를 나란히 보여주며 활성 계정을 표시한다. 기본적으로 Omarchy는 활성 계정이 한도의 95%를 넘으면 알리고, 알림을 클릭하면 여유가 가장 많은 계정으로 전환한다. 패널에서 계정 줄에 호버하고 Use 옆에 나타나는 Autoswitch를 클릭하거나(또는 `m`을 누르거나), `omarchy agent account mode auto`를 실행하면 대신 스스로 전환한다; 켜져 있는 동안 Autoswitch가 Use 자리를 차지하고, 다시 클릭하면 알림으로 돌아간다. `omarchy agent account mode auto 90`처럼 숫자를 추가해 임계값을 바꿔라. 모든 계정이 임계값을 넘으면, 어떤 계정이 가장 먼저 풀리는지와 함께 한 번 알려준다. 활성 계정이 임계값에서 15 포인트 이내에 있는 동안(기본값에서는 80%), 그 한도는 15분이 아니라 3분마다 확인된다.

`omarchy agent account list`는 모든 계정과 그 최신 한도를 보여주고, `omarchy agent account remove work`는 하나를 잊으며, `omarchy agent account rename primary Hey`는 하나의 이름을 바꾼다(또는 패널에서 계정 이름을 클릭하라). 이 명령들은 기본 에이전트의 계정에 대해 동작한다; 다른 제공者に 닿으려면, `omarchy agent account use codex side`처럼 먼저 이름을 대라. `~/.claude`나 `~/.codex`에 이미 갖고 있던 로그인은 _Main_ 계정이며 제자리에 남는다. 약 여덟 시간 넘게 사용하지 않은 계정은 _Sign-in required_를 표시할 수 있다; 그것을 클릭해 패널에서 바로 그 계정에 다시 로그인하거나, 그 계정으로 세션을 시작하면 저절로 로그인이 새로고침된다. 계정이 추가될 때 갖고 있던 MCP 서버는 그 계정으로 따라오지만, 나중에 `claude mcp add`로 추가한 것은 추가한 계정에만 닿는다. 절대 경로로 CLI 바이너리를 지정해 구성한 Claude Desktop과 도구는 전환을 따르지 않는다. 명시적인 `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, 또는 `GROK_HOME`는 선택된 계정보다 우선한다.

### 충돌 진단

Omarchy는 systemd-coredump를 감시해 프로세스 충돌을 찾는다. 무언가 세그멘테이션 오류를 일으키면, "Process crashed" 알림을 받을 것이다 — 그것을 클릭하면, 충돌이 Omarchy의 diagnose-crash 스킬과 함께 기본 에이전트에게 넘겨지며, 그 스킬은 에이전트를 코어 덤프에서 사실을 확립하고 충돌이 업스트림에 보고할 가치가 있는지 결정하는 과정으로 안내한다. `coredumpctl list`의 어떤 PID에 대해서든 `omarchy agent crash <pid>`로 손으로 실행할 수도 있다.

감시는 기본적으로 켜져 있다. _Trigger > Toggle > Crash Capture_에서(또는 `omarchy toggle crash-capture`로) 끄면 알림이 멈춘다; `omarchy agent crash <pid>`는 손으로는 여전히 동작한다.

충돌은 프로그램 단위로 하나씩 침묵시킬 수도 있는데, 진단이 마지막에 네게 제안하는 것이 바로 그것이다. `omarchy crash mute hyprland`는 그 프로그램에 대한 알림만 멈추고, `omarchy crash mute hyprland off`는 되돌리며, `omarchy crash mute`만 실행하면 음소거한 것을 나열한다. 이름만큼이나 바이너리 경로도 잘 받아들이므로, `omarchy crash mute /usr/bin/hyprland`도 같은 일을 한다. `omarchy crash mute 'Some App'`처럼 공백이 있는 이름은 따옴표로 감싸라. 나머지는 여전히 알리고, 음소거된 프로그램은 여전히 충돌한다 — 이는 알림을 숨길 뿐, 아무것도 고치지 않는다.

### 데스크톱 앱

_Install > AI_ 메뉴에는 몇 가지 그래픽 AI 앱도 있다: ChatGPT 데스크톱 앱, Claude 데스크톱 앱(Anthropic의 Linux 베타, Chat, Cowork, Claude Code 탭 포함), xAI 모델과 채팅하는 Grok Bot, Herdr Desktop, Hermes Desktop, OpenClaw, Perplexity 데스크톱 앱, 그리고 T3 Code. Grok Bot은 데스크톱 채팅 앱이다. 코딩 에이전트는 `grok` 명령이다.

Hermes Desktop은 알아둘 만한 녀석인데, 한 머신에는 하나의 Hermes가 있고, 그것은 앱의 것이기 때문이다: Hermes는 오직 앱을 통해서만 설치되며, 기본 에이전트가 실행하는 `hermes` 명령은 앱의 것이다. Hermes를 기본 에이전트로 선택하면 _Install > AI_ 항목이 하는 것과 같은 것이 설치된다: 패키지, 그리고 Hermes 자체 인스톨러가 설정한 `~/.hermes` 아래의 Hermes 런타임으로, 처음에는 몇 분이 걸린다. 그 런타임이 터미널 `hermes` 명령, 기본 에이전트, 앱이 모두 사용하는 유일한 Hermes이며, Omarchy 릴리스를 기다리지 않고 `hermes update`로 스스로 업데이트한다. 설치하면 또한 Hermes에 Omarchy 테마를 `omarchy`라는 이름의 스킨으로 건네주며, 모든 Hermes 표면은 테마를 바꿀 때 그것을 따르지만; 원하지 않으면 Hermes의 Appearance 설정이나 `/skin`으로 다른 것을 선택하라, 그러면 Omarchy는 그 선택을 그대로 둔다. _Remove > AI_에서 앱을 제거하면 먼저 Hermes를 게이트웨이까지 포함해 닫고, 그 런타임을 함께 가져가며, 네가 달리 지시하지 않는 한 채팅, 메모리, Hermes가 스스로 작성한 스킬은 유지한다: 그 데이터와 연결 설정도 함께 지울지 묻는데, 기본값은 아니오다.

OpenClaw의 데스크톱 경험은 그 Control UI로, 자체 로컬 게이트웨이를 백엔드로 하는 웹 앱으로 열린다. OpenClaw는 `~/.openclaw`에 살고 스스로 업데이트한다: Control UI의 "Update Gateway" 버튼을 사용하거나 `openclaw update`를 실행하면, 게이트웨이가 새 버전으로 재시작한다. Omarchy는 새 설치가 시작할 릴리스만 선택한다. _Remove > AI_에서 OpenClaw를 제거하면 게이트웨이 서비스와 앱을 함께 가져간 뒤 `~/.openclaw`도 지울지 묻는데, 거기에는 OpenClaw 자체와 그것이 다운로드하는 플러그인 런타임과 함께 채팅과 자격 증명이 들어 있기 때문이다; 기본값은 유지하는 것이고, OpenClaw를 다시 설치하면 그것을 다시 집어 든다.

Herdr Desktop은 [Herdr](https://herdr.dev) 데스크톱 앱이다: 창을 닫아도 그 코어 안에서 계속 실행되는 터미널과 코딩 에이전트의 스페이스, 탭, 패인(pane). 패키지가 아니라 Herdr 자체 인스톨러에서 오므로, `~/.local/share/herdr-app`에 살고, 아직 없을 때는 `~/.local/bin/herdr-core`에 그 코어를 함께 가져오며, 둘 다 스스로 업데이트한다. 그것은 Omarchy가 `Super + Ctrl + Return`에 제공하는 `herdr` 명령을 대체하는 것이 아니라 그 옆에 앉으며, 그 명령의 직접 키를 받는다: `Alt + Return`과 `Alt + Shift + Return`은 패인을 아래나 오른쪽으로 나누고, `Alt + Escape`는 닫으며, `Ctrl + Alt + Arrow`는 패인 사이를 이동하고, `Alt + 1..9`와 `Alt + Left/Right`는 탭을 선택하며, `Alt + Up/Down`은 스페이스 사이를 이동한다. `Ctrl + 1..9`는 스페이스를 선택하고 `Alt + Shift + Up/Down`은 에이전트를 단계별로 오간다. `Ctrl + Space` 접두 키는 터미널 전용으로 남는데, 앱은 시퀀스를 위해 평범한 Ctrl 키를 붙잡을 수 없기 때문이다. Omarchy는 이를 `~/.config/herdr-app/keys.json`에 쓰며, `omarchy-refresh-herdr-app`가 되돌려 놓는다. 설치하면 Herdr의 Omarchy 테마를 선택하며, 그 뒤로는 Omarchy 테마를 따른다. Herdr는 라이트 모드용 테마 하나와 다크 모드용 테마 하나를 유지하므로, 다크 Omarchy 테마와 라이트 Omarchy 테마 사이를 전환한 뒤에는, 다른 모드를 위해 Herdr의 테마 선택기에서 Omarchy를 한 번 더 선택하라.

T3 Code는 패키지가 아니라 `~/.local/share/t3code`의 공식 AppImage 릴리스에서 실행되므로, 스스로 업데이트한다. 설치하면 Stable 채널로 시작할지 Nightly 채널로 시작할지 묻는다; 나중에는 T3 Code 설정에서 전환하라. 스레드와 설정은 `~/.t3`에 살고, _Remove > AI_에서 T3 Code를 제거하면 함께 가져간다.

### 로컬 모델

코딩 에이전트를 위해 오픈 모델을 자체 머신에서 실행하라. 프롬프트와 코드는 머신에 남는다; 모델로 보낸 어떤 것도 머신을 떠나지 않는다. 다음으로 시작하라:

```bash
omarchy agent local use best
```

또는, 상단 바의 에이전트 패널에서 +를 선택한 뒤 Local AI를 선택하는데, 이는 모델이 이 머신에 맞을 때 나타난다. 처음에는, 모델을 실행하는 Podman을 설치하고, NVIDIA 머신에서는 모델에 GPU를 제공하는 NVIDIA의 컨테이너 툴킷을 설치한다. 그런 뒤 Omarchy는 이 머신에 권장되는 모델을 골라 다운로드하고 시작한다. 수십 GB의 다운로드와, 모델이 실행되는 동안 머신 메모리 대부분이 사용될 것을 예상하라: Flash Next는 전체 256K 컨텍스트로 약 100 GiB를 사용한다. 다른 모델이 필요한 메모리를 차지하고 있으면, 그것은 멈춘 상태로 설정되어, 하나를 멈추면 시작할 준비가 된다. 모델은 로그아웃 시 멈춘다; 다른 일을 위해 메모리가 필요할 때는 직접 멈춰라.

`omarchy agent local list`는 옵션을 보여주고 일부가 맞지 않는 이유를 설명한다. 다른 것을 설정하려면, `omarchy agent local use <recipe>`를 실행하라. 오늘날, 128 GB Strix Halo 머신용으로 `qwen3.8-flash-next-gufo`와 `qwen3.8-27b-gufo`가 제공된다; 27B는 약 40 GiB를 차지하므로 다른 작업을 위한 여유를 남긴다. 새 레시피와 권장 사항은 패키지를 통해 `omarchy update`와 함께 도착한다.

설정한 모든 모델은 구독 옆 에이전트 패널에 자체 줄을 갖는다: 시작하려면 재생, 멈추고 메모리를 풀려면 일시정지, 그리고 그것에서 에이전트를 열려면 터미널 버튼. 메모리에 함께 들어가는 한 여러 개가 동시에 실행될 수 있다; 하나가 들어가지 않으면, Omarchy는 어떤 실행 중인 모델을 멈춰야 하는지 말한다. 줄을 끌어 순서를 바꾸고, 선택한 줄에서 Delete를 눌러 모델과 그 다운로드를 제거하라.

명령줄에서는, `omarchy agent local start <recipe>`와 `omarchy agent local stop <recipe>`가 같은 일을 하고, `omarchy agent local status`는 모든 모델을 보여주며, `omarchy agent --local`은 마지막으로 시작한 모델에서 기본 에이전트를 연다. pi, OpenCode, Qwen Code가 하나를 사용할 수 있다; 다른 기본값에서는 pi에서 열린다. pi는 또한 네가 설정한 모든 모델과, 페어링한 머신의 모델들을 자체 모델 선택기에 나열하므로, 평범한 `pi`로도 닿을 수 있다. OpenAI 호환 클라이언트라면 무엇이든 연결할 수 있다: `status`는 각 모델의 주소를 보여주고(첫 번째는 `http://127.0.0.1:11435/v1`), 레시피 이름이 모델이며, 키는 `~/.config/omarchy/agent-local/key`에 있다.

`omarchy agent local remove <recipe>`는 모델과 다른 어떤 모델도 사용하지 않는 다운로드를 삭제한다.

서드파티 런타임은 그 게시자로 레이블이 붙는다. Omarchy는 모든 모델을 네트워크 액세스 없이 실행한다.

### 로컬 LLM

Omarchy는 로컬 LLM 모델을 실행하는 두 가지 방법을 권장한다: LM Studio와 Ollama. LM Studio는 오픈 웨이트 모델을 찾고, 설치하고, 실행하는 GUI 인터페이스를 제공한다. 쉽게 시작하기에 훌륭한 방법이다. Ollama는 비슷하게 하는 CLI를 제공한다. 하지만 로컬 모델이 처음이라면, 나는 LM Studio부터 시작하겠다. Omarchy Menu의 _Install > AI_에서 어느 쪽이든 설치할 수 있다.

### Omarchy Skill

에이전트 스킬은 AI가 특정 도구를 특정 방식으로 사용하도록 돕고, Omarchy는 시스템을 맞춤 설정하기 위한 기본 스킬을 제공한다. Hyprland 설정을 손보거나, 바를 조정하거나, 심지어 새 테마를 처음부터 만드는 것처럼. 그것은 Claude Code(`~/.claude/skills`), Codex(`~/.codex/skills`), Pi(`~/.pi/agent/skills`), Antigravity(`~/.gemini/config/skills`), Hermes(`~/.hermes/skills` 및 각 `~/.hermes/profiles/*/skills`), 그리고 일반적인 `~/.agents/skills` 위치의 스킬 디렉터리로 심링크되어 있어, 대부분의 하네스가 자동으로 집어 든다.

하지만 이 스킬은 실험적인 것으로 취급해야 한다. 모델마다 그것을 다른 효과로 사용할 것이다. 먼저 플랜 모드로 실행해, 에이전트가 무엇을 바꾸고 싶어할지 감을 잡는 것이 가장 좋다. 그리고 에이전트가 모든 것을 엉망으로 만들면, 변경을 롤백하거나 심지어 `omarchy reinstall configs`를 호출할 준비를 하라.
