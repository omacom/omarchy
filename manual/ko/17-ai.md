### 에이전트 설치 및 업데이트

Hermes를 제외하고, 이 에이전트들은 mise의 지연 설치를 사용한다: 처음 실행할 때 CLI를 설치하고, 이후 실행에서는 그것을 재사용한다. mise는 또한 설치된 에이전트의 새 릴리스를 최대 4시간에 한 번, 시작 직전이나 셸 프롬프트에서 백그라운드로 확인한다. 그 업데이트에 실패하거나 오프라인이면 설치된 버전이 실행된다. `omarchy update`는 Omarchy의 나머지 부분과 함께 설치된 에이전트를 업데이트하고, `mup`은 mise가 관리하는 도구만 업데이트한다.

`claude update`, `codex update` 같은 에이전트 자체 업데이터나 앱의 업데이트 버튼은 mise가 관리하는 설치를 업데이트하지 않는다. `codex update`는 실패하고, `claude update`는 성공했다고 보고하면서 mise가 추적하지 않는 별도 사본을 설치할 수 있다. 에이전트의 기본 설치 프로그램과 업데이터를 대신 사용하고 싶다면, 그것을 `disable_tools`에 추가하라; [사전 설치된 CLI 도구](18-development-tools.md#preinstalled-cli-tools)를 보라.

필요하기 전에 구성된 모든 지연 도구를 설치하려면 `mise install --include-lazy`를 실행하라. 여기에는 에이전트뿐 아니라 Omarchy의 다른 기본 CLI 도구도 포함된다. 단일 도구를 설치하거나 직접 설치한 것을 사용하는 방법은 [사전 설치된 CLI 도구](18-development-tools.md#preinstalled-cli-tools)를 보라.

`grok`은 mise의 공식 `grok` 패키지를 통해 `claude` 및 `codex`와 같은 방식으로 설치된다. `grok`을 실행하거나 _설정 > 기본값 > 에이전트_에서 선택하라. x.ai의 `curl | bash` 설치 프로그램은 건너뛰어라. 그 경로는 `~/.grok/bin`에 두 번째 사본을 넣고, 그것을 `PATH` 앞에 추가하며, Omarchy의 래퍼를 덮어쓴다.

`dsh`는 `127.0.0.1:3080`에서 브라우저 UI를 열며, 실행 디렉터리가 기본 작업 공간이다. 그 브라우저 UI는 시작 프롬프트를 받지 않으므로, `omarchy agent prompt`는 클립보드에 프롬프트를 담아 붙여넣을 수 있게 연다. Omarchy는 DeepSeek의 승인 없음 권한 프리셋으로 그것을 시작한다. DeepSeek Harness는 공식 모델 API를 사용할 때 세션 로그를 DeepSeek에 업로드한다; 그 브라우저 UI의 _설정 > 일반 > 세션 로그 업로드_에서 끌 수 있다. 보내는 피드백도 `DSH_TELEMETRY_MODE=DISABLED`로 시작하지 않는 한 세션과 함께 업로드된다.

### 기본 에이전트

기본 에이전트는 `omarchy default agent <name>`으로, 또는 Omarchy 메뉴(`Super + Space`)의 _설정 > 기본값 > 에이전트_에서 선택한다. 에이전트가 아직 설치되지 않았다면, 선택하면 먼저 설치한다. 새로 설치한 Omarchy는 일회성 알림으로 이 선택을 하도록 안내한다.

Claude를 선택하면 Chromium, Chrome, Brave, Brave Origin, Edge용 브라우저 확장 프로그램 설정도 시도한다. 확장 프로그램 설정은 모든 사용자에게 적용되며 시스템 비밀번호를 물을 수 있다; 취소하거나 확장 프로그램 설치에 실패해도 Claude는 여전히 선택되고 실행된다. 브라우저를 다시 시작하고, 안내가 나오면 확장 프로그램을 활성화한 뒤, Claude에 로그인해 연결을 마쳐라. Claude에서 `/chrome`을 실행해 연결을 확인하라. Firefox와 Zen은 이 확장 프로그램을 지원하지 않는다. 이 설정이 추가되기 전에 이미 Claude가 기본값이었다면, 다시 선택해 확장 프로그램을 설치하라.

선택한 뒤에는 `Super + Shift + Ctrl + A`가 전용 터미널 창에서 기본 에이전트를 실행한다(아직 선택하지 않았다면 선택 화면을 띄운다). `omarchy agent prompt "Review this project"`처럼 작업과 함께 바로 실행할 수도 있다. Freebuff와 DeepSeek Harness는 시작 프롬프트를 받지 않으므로, 대신 클립보드에 프롬프트를 담아 붙여넣을 수 있게 열린다. 이 방식으로 실행된 에이전트는 각자의 묻지 않고 계속하는 모드로 무인 실행되니, 실제로 일을 저지를 준비를 해 두어라! MiniMax Code는 대화형 세션에 그런 모드가 없어 평소대로 권한을 묻는다. 그리고 에이전트들이 홈 디렉터리에 대한 신뢰를 기억하기를 거부하므로, `$HOME`에서 실행하면 대신 `~/Work`에서 시작한다.

터미널 단축키도 있다: `a`는 현재 터미널 안에서 기본 에이전트를 실행하고, `c`, `cx`, `cy`는 OpenCode, Claude Code, Codex를 직접 시작한다(역시 자동 승인 모드로). 테마 변경도 에이전트에 동기화된다: Claude Code, Pi, OpenCode, 그리고 Hermes(Omarchy가 설치한 뒤에)는 Omarchy 테마를 전환하면 모두 따라 바뀐다.

### 에이전트 패널

상단 바에 에이전트 아이콘이 있다. 에이전트를 설정하기 전에는, 그 패널이 Claude, Codex, 또는 Grok에 로그인하는 과정을 안내하고, 첫 번째로 설정한 것이 기본 에이전트가 된다. 그 이후에는 패널이 모든 구독을 한 페이지에 모은다: 각 에이전트와 계정, 그 요금제, 5시간 세션 한도와 주간 한도 각각에 대한 미터와 초기화까지 남은 시간(정확한 백분율은 마우스를 올려 확인), 또는 남은 선불 잔액을, 이번 주 토큰 수와 가장 많이 사용한 모델처럼 전체에서 사용한 내용을 순환 표시하는 한 줄 아래에 보여준다. _뭔가 만들기_ 아래에서는 새 테마, 플러그인, 또는 앱을 위한 시작 프롬프트를 제공하며, 작업을 기본 에이전트에게 맡긴다. 앱은 Omarchy 자체의 Hype, Monologue, Omacut이 만들어진 방식대로, omarchy-app 에이전트 스킬을 따라 C++와 Qt Quick으로 빌드되며, 필요한 컴파일러와 Qt 구성 요소는 설치되어 온다. Claude Code, Codex, Grok, Kimi, Cursor와 그 Grok Bot 허용량, GitHub Copilot, Muse, Antigravity, Kimchi, Devin은 한도와 함께 기본으로 지원되고, Hermes, Mistral Vibe, Qwen Code는 사용한 뒤에 세션과 토큰을 보여준다. pi, omp, 또는 opencode를 통해 사용하는 제공업체 요금제와 키도 표시된다: 한도와 함께 OpenCode Zen과 Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan, Synthetic; 선불 잔액과 함께 Fireworks, OpenRouter, DeepSeek; 그리고 자체 하드웨어에서 실행하는 모델은 로컬 모델 아래에 표시된다. 모든 에이전트는 청구 주체 아래에서, 몇 개의 하네스를 통해 구동하든 한 번만 집계된다.

패널을 열려면 바 아이콘을 왼쪽 클릭하고, 기본 에이전트를 실행하려면 오른쪽 클릭하라. 그 뒤의 사용 기록은 15분마다 `omarchy agent usage-update`로 재생성되며, 패널은 동기화된 폴더를 통해 다른 머신의 사용량까지 병합할 수 있다. 전체 설정은 `$OMARCHY_PATH/shell/plugins/agents/` 아래 README를 보라.

### 여러 구독

Claude, Codex, 또는 Grok 요금제를 하나 이상 결제하고 있다면 — 예를 들어 개인용 Max와 업무용 하나 — Omarchy는 모두 로그인 상태를 유지하고 그 사이를 이동할 수 있다. 에이전트 패널의 +로 구독을 추가하면 그 자리에서 과정을 안내하고, 또는 `omarchy agent account add claude Work`(또는 `codex`, 또는 `grok`)로 추가한다. CLI가 없으면 설치한다. 제공업체의 첫 번째 계정은 CLI가 항상 찾는 곳에서 평소 브라우저를 통해 로그인한다. 그 이후의 모든 계정은 시크릿 창을 통해 로그인하므로, 브라우저에 이미 로그인된 계정이 실수로 선택되지 않는다; 거기서 추가하려는 계정으로 로그인하고, 이미 열어 둔 시크릿 창이 있으면 먼저 닫아라. 이를 위해 CLI에서 절대 로그아웃하지 마라: 로그아웃하면 저장된 로그인이 취소되고, 그 계정을 다시 추가해야 한다.

SSH를 통해 구독 로그인을 다른 Omarchy 머신에 복사하려면 `omarchy agent account copy user@laptop`을 실행하라. 대상에 수신기가 설치되어 있지 않으면 발신자가 임시 수신기를 제공하므로, 이전 Omarchy 머신도 업데이트 없이 계정을 받을 수 있다. 설치된 수신기가 우선한다. 이는 모든 Claude, Codex, Grok 구독을 복사한다; `omarchy agent account copy laptop claude`처럼 제공업체 이름을 추가해 선택하라. 계정 이름과 명령어 ID는 대상에 이미 있는 계정을 포함해 원본과 일치한다. 관련 없는 대상 계정은 이름이 충돌하면 숫자 접미사를 받고, 설정, 스킬, 플러그인, 대화 기록은 각 머신에 로컬로 남는다.

기존 대상 자격 증명은 유지된다. 대상에 이미 로그인된 원본 계정은 자격 증명을 교체하지 않고 이름이 동기화되고; 다른 계정은 그 옆에 추가된다. 일치하는 계정의 저장된 자격 증명을 교체하려면, 대상에서 그 계정의 세션을 종료한 뒤 `omarchy agent account copy --replace laptop claude`를 사용하라. 새 대상은 원본의 활성 계정과 전환 기본 설정도 가져오고; 이미 자리 잡은 대상은 자체 설정을 유지한다.

자격 증명은 SSH를 통해 이동하고 대상의 비공개 파일에 저장되므로, 신뢰하는 머신에만 복사하라. 이는 일회성 복사이지 지속적인 동기화가 아니다. Codex 새로고침 토큰은 다른 머신에 의해 교체될 수 있어 복사된 로그인을 갱신해야 할 수 있다; 여러 머신에서 동시에 사용하려면 별도 로그인이 가장 안정적이다. [Codex의 계정 인증 가이드](https://developers.openai.com/codex/auth/ci-cd-auth)를 보라.

제공업체당 하나의 계정이 활성화되며, 모든 새 세션은 그 계정으로 시작한다: `cx`, `cy`, 일반 `claude`, `codex`, 또는 `grok`, `omarchy agent`를 통해 실행되는 모든 것, 그리고 `PATH`에서 CLI를 찾는 스크립트나 편집기도 마찬가지다. `omarchy agent account use work`로 전환하고(`omarchy agent account use main`로 돌아온다), 또는 패널에서 계정 번호를 누른 뒤 `Enter`를 누르거나(또는 사용 버튼을 클릭) 전환한다. 이미 실행 중인 세션은 시작한 계정에 그대로 남는다. 대화 기록, 설정, 스킬, 플러그인은 계정 간에 공유되므로, 같은 폴더에서 `claude --continue`를 실행하면 새 계정에서 중단한 곳부터 이어간다.

계정이 둘 이상이면 패널은 각 계정의 한도를 나란히 보여주고 활성 계정을 표시한다. 기본적으로 Omarchy는 활성 계정이 한도의 95%를 넘으면 알리고, 알림을 클릭하면 여유가 가장 많은 계정으로 전환한다. 패널에서 계정 줄에 마우스를 올리고 사용 옆에 나타나는 자동 전환을 클릭하거나(`m` 키를 눌러도 된다), 또는 `omarchy agent account mode auto`를 실행하면 대신 자동으로 전환한다; 활성화되어 있는 동안 자동 전환이 사용의 자리를 차지하고, 다시 클릭하면 알림으로 돌아간다. `omarchy agent account mode auto 90`처럼 숫자를 추가해 임계값을 바꿔라. 모든 계정이 임계값을 넘으면, 어떤 계정이 가장 먼저 여유가 생기는지와 함께 한 번 알림을 받는다. 활성 계정이 임계값에서 15포인트 이내(기본값에서는 80%)에 있는 동안에는, 한도를 15분이 아닌 3분마다 확인한다.

`omarchy agent account list`는 모든 계정과 최신 한도를 보여주고, `omarchy agent account remove work`는 하나를 잊으며, `omarchy agent account rename primary Hey`는 이름을 바꾼다(또는 패널에서 계정 이름을 클릭한다). 이 명령들은 기본 에이전트의 계정에 작동한다; 다른 제공업체에 접근하려면 `omarchy agent account use codex side`처럼 먼저 이름을 지정하라. `~/.claude` 또는 `~/.codex`에 이미 있던 로그인은 _Main_ 계정이며 제자리에 남는다. 약 8시간 넘게 사용하지 않은 계정은 _로그인 필요_라고 표시될 수 있다; 클릭해 패널에서 바로 그 계정에 다시 로그인하거나, 그 계정으로 세션을 시작하면 저절로 로그인이 새로고침된다. 계정이 추가될 때 있던 MCP 서버는 그 계정을 따라가지만, 나중에 `claude mcp add`로 추가한 서버는 추가한 계정에만 도달한다. CLI 바이너리에 대한 절대 경로로 구성된 Claude Desktop과 도구는 전환을 따르지 않는다. 명시적인 `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, 또는 `GROK_HOME`이 선택한 계정보다 우선한다.

### 충돌 진단

Omarchy는 systemd-coredump에서 프로세스 충돌을 감시한다. 무언가 세그멘테이션 오류를 일으키면 "프로세스 충돌" 알림을 받는다 — 클릭하면, 충돌이 Omarchy의 diagnose-crash 스킬과 함께 기본 에이전트에게 전달되며, 이 스킬은 코어 덤프에서 사실을 확립하고 충돌을 업스트림에 보고할 가치가 있는지 결정하는 과정을 에이전트에게 안내한다. `coredumpctl list`의 아무 PID에 대해 `omarchy agent crash <pid>`로 직접 실행할 수도 있다.

감시는 기본적으로 켜져 있다. _트리거 > 토글 > 충돌 캡처_에서(또는 `omarchy toggle crash-capture`로) 끄면 알림이 중단되고; `omarchy agent crash <pid>`는 수동으로 여전히 작동한다.

충돌은 프로그램별로 하나씩 무음으로 할 수도 있으며, 이는 진단 마지막에 제안하는 것이다. `omarchy crash mute hyprland`는 그 프로그램에 대해서만 알림을 중단하고, `omarchy crash mute hyprland off`는 되돌리며, `omarchy crash mute`만 실행하면 무음 처리한 목록을 보여준다. 이름만큼이나 바이너리 경로도 잘 받아들이므로, `omarchy crash mute /usr/bin/hyprland`도 같은 일을 한다. `omarchy crash mute 'Some App'`처럼 공백이 있는 이름은 따옴표로 감싸라. 다른 모든 것은 여전히 알리고, 무음 처리된 프로그램은 여전히 충돌한다 — 이는 알림을 숨길 뿐, 아무것도 고치지 않는다.

### 데스크톱 앱

_설치 > AI_ 메뉴에는 몇 가지 그래픽 AI 앱도 있다: ChatGPT 데스크톱 앱, Claude 데스크톱 앱(Chat, Cowork, Claude Code 탭이 있는 Anthropic의 Linux 베타), xAI 모델과 채팅하는 Grok Bot, Hermes Desktop, OpenClaw, Perplexity 데스크톱 앱, 그리고 T3 Code. Grok Bot은 데스크톱 채팅 앱이다. 코딩 에이전트는 `grok` 명령어다.

Hermes Desktop은 알아둘 만한데, 머신에는 하나의 Hermes만 있고, 그것은 앱의 것이기 때문이다: Hermes는 오직 앱을 통해서만 설치되며, 기본 에이전트가 실행하는 `hermes` 명령어는 앱의 것이다. Hermes를 기본 에이전트로 선택하면 _설치 > AI_ 항목이 하는 것과 같은 것이 설치된다: 패키지, 그리고 Hermes 자체 설치 프로그램이 설정한 `~/.hermes` 아래 Hermes 런타임으로, 처음에는 몇 분이 걸린다. 그 런타임이 터미널 `hermes` 명령어, 기본 에이전트, 앱이 모두 사용하는 유일한 Hermes이며, Omarchy 릴리스를 기다리지 않고 `hermes update`로 자체 업데이트한다. 설치하면 Hermes에게 Omarchy 테마를 `omarchy`라는 이름의 스킨으로 제공하는데, 모든 Hermes 표면이 테마를 전환할 때 따라 바뀐다; 원하지 않으면 Hermes의 외관 설정에서 또는 `/skin`으로 다른 것을 선택하라, 그러면 Omarchy는 그 선택을 그대로 둔다. _제거 > AI_에서 앱을 제거하면 먼저 게이트웨이를 포함해 Hermes를 닫고, 그 런타임을 함께 가져가며, 알려주지 않는 한 채팅, 메모리, Hermes가 스스로 작성한 스킬은 유지한다: 그 데이터와 연결 설정도 함께 제거할지 묻는데, 기본값은 아니다.

OpenClaw의 데스크톱 경험은 Control UI이며, 자체 로컬 게이트웨이를 백엔드로 하는 웹 앱으로 열린다. OpenClaw는 `~/.openclaw`에 살며 자체 업데이트한다: Control UI의 "게이트웨이 업데이트" 버튼을 사용하거나 `openclaw update`를 실행하면, 게이트웨이가 새 버전으로 다시 시작한다. Omarchy는 새로 설치한 것이 시작할 릴리스만 선택한다. _제거 > AI_에서 OpenClaw를 제거하면 게이트웨이 서비스와 앱을 함께 가져간 뒤 `~/.openclaw`도 제거할지 묻는데, 거기에는 채팅과 자격 증명, 그리고 OpenClaw 자체와 다운로드한 플러그인 런타임이 함께 있기 때문이다; 기본값은 유지하는 것이고, OpenClaw를 다시 설치하면 그것을 다시 가져온다.

T3 Code는 패키지가 아닌 `~/.local/share/t3code`의 공식 AppImage 릴리스에서 실행되므로 자체 업데이트한다. 설치하면 Stable 채널로 시작할지 Nightly 채널로 시작할지 묻는다; 나중에 T3 Code 설정에서 전환하라. 스레드와 설정은 `~/.t3`에 살고, _제거 > AI_에서 T3 Code를 제거하면 함께 가져간다.

### 로컬 모델

코딩 에이전트를 위해 자체 머신에서 오픈 모델을 실행하라. 프롬프트와 코드는 머신에 남는다; 모델에 보낸 어떤 것도 머신을 떠나지 않는다. 다음으로 시작하라:

```bash
omarchy agent local use best
```

또는, 상단 바의 에이전트 패널에서 +를 선택한 뒤 로컬 AI를 선택하면, 이 머신에 맞는 모델이 있을 때 표시된다. 처음에는 모델을 실행하는 Podman을 설치하고, NVIDIA 머신에서는 GPU를 제공하는 NVIDIA 컨테이너 툴킷을 설치한다. 그러면 Omarchy가 이 머신에 권장되는 모델을 선택해 다운로드하고 시작한다. 수십 GB의 다운로드와, 모델이 실행되는 동안 머신 메모리 대부분이 사용될 것을 예상하라: Flash Next는 전체 256K 컨텍스트로 약 100 GiB를 사용한다. 필요한 메모리를 다른 모델이 차지하고 있으면, 중지된 상태로 설정되어 하나를 중지하면 바로 시작할 수 있다. 모델은 로그아웃 시 중지된다; 다른 일을 위해 메모리가 필요할 때 직접 중지하라.

`omarchy agent local list`는 옵션을 보여주고 일부가 맞지 않는 이유를 설명한다. 다른 것을 설정하려면 `omarchy agent local use <recipe>`를 실행하라. 현재 128 GB Strix Halo 머신용으로 `qwen3.8-flash-next-gufo`와 `qwen3.8-27b-gufo`를 사용할 수 있다; 27B는 약 40 GiB를 차지해 다른 작업을 위한 여유를 남긴다. 새 레시피와 권장 사항은 패키지를 통해 `omarchy update`와 함께 제공된다.

설정한 모든 모델은 구독 옆 에이전트 패널에 자체 줄을 갖는다: 재생하면 시작하고, 일시 정지하면 중지해 메모리를 해제하며, 터미널 버튼으로 그 모델에서 에이전트를 연다. 메모리에 함께 들어갈 수 있으면 여러 개를 동시에 실행할 수 있다; 하나가 들어가지 않으면 Omarchy가 어떤 실행 중인 모델을 중지할지 알려준다. 줄을 드래그해 순서를 바꾸고, 선택한 줄에서 Delete를 눌러 모델과 다운로드를 제거하라.

명령줄에서는 `omarchy agent local start <recipe>`와 `omarchy agent local stop <recipe>`가 같은 일을 하고, `omarchy agent local status`는 모든 모델을 보여주며, `omarchy agent --local`은 마지막으로 시작한 모델에서 기본 에이전트를 연다(기본 에이전트가 로컬 모델을 사용할 수 없으면 pi). OpenAI 호환 클라이언트도 연결할 수 있다: `status`는 각 모델의 주소를 보여주고(첫 번째는 `http://127.0.0.1:11435/v1`), 레시피 이름이 모델이며, 키는 `~/.config/omarchy/agent-local/key`에 있다.

`omarchy agent local remove <recipe>`는 모델과 다른 모델이 사용하지 않는 다운로드를 삭제한다.

타사 런타임에는 게시자가 표시된다. Omarchy는 모든 모델을 네트워크 액세스 없이 실행한다.

### 로컬 LLM

Omarchy는 로컬 LLM 모델을 실행하는 두 가지 방법을 권장한다: LM Studio와 Ollama. LM Studio는 오픈 웨이트 모델을 찾고, 설치하고, 실행하는 GUI 인터페이스를 제공한다. 쉽게 시작하기에 좋은 방법이다. Ollama는 비슷하게 하는 CLI를 제공한다. 하지만 로컬 모델이 처음이라면, 나라면 LM Studio부터 시작하겠다. 둘 다 Omarchy 메뉴의 _설치 > AI_에서 설치할 수 있다.

### Omarchy 스킬

에이전트 스킬은 AI가 특정 도구를 특정 방식으로 사용하도록 돕고, Omarchy는 시스템을 맞춤 설정하기 위한 기본 스킬과 함께 제공된다. Hyprland 설정을 조정하거나, 바를 조정하거나, 심지어 새 테마를 처음부터 만드는 것 같은 일이다. 이는 Claude Code(`~/.claude/skills`), Codex(`~/.codex/skills`), Pi(`~/.pi/agent/skills`), Antigravity(`~/.gemini/config/skills`), Hermes(`~/.hermes/skills`와 각 `~/.hermes/profiles/*/skills`), 그리고 일반 `~/.agents/skills` 위치의 스킬 디렉터리에 심볼릭 링크되어 있어, 대부분의 하네스가 자동으로 가져온다.

하지만 이 스킬은 실험적인 것으로 취급해야 한다. 모델마다 이를 다른 효과로 사용할 것이다. 먼저 계획 모드로 실행해 에이전트가 무엇을 바꾸고 싶어하는지 파악하는 것이 가장 좋다. 그리고 에이전트가 모든 것을 엉망으로 만들면, 변경 사항을 롤백하거나 심지어 `omarchy reinstall configs`를 실행할 준비를 해 두어라.
