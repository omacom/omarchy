# AI

Omarchy는 아래 코딩 에이전트들을 위한 런처를 포함하지만, 기본값을 대신 선택해 주지는 않습니다. _Install > AI > CLI_에서 하나를 설치한 뒤, 메시지가 표시되면 인증하세요. Hermes와 OpenClaw는 예외입니다. 둘 중 하나를 선택하면 자체 업데이트되는 자체 복사본을 설정하며, 아래 _Desktop apps_에서 설명합니다.

### 에이전트 설치 및 업데이트

Hermes와 OpenClaw를 제외하고, 모든 에이전트는 Omarchy 자체 저장소의 패키지입니다. _Install > AI > CLI_에서 또는 `omarchy install ai cli <command>`로 하나를 설치하고, _Remove > AI > CLI_에서 다시 제거하세요. 제거해도 로그인 정보와 기록은 그대로 남습니다. 아직 설치되지 않은 에이전트를 선택하면 그것도 설치됩니다. 에이전트 패널에서 별표를 표시하거나, `omarchy default agent <name>`로 선택하거나, 해당 구독에 로그인하면 됩니다. Omarchy는 에이전트의 새 릴리스가 나오면 1시간 이내에 모든 채널에 게시하고, `omarchy update`가 시스템의 나머지 부분과 함께 설치합니다.

pacman이 이들을 최신 상태로 유지하므로 에이전트 자체 업데이터는 꺼져 있습니다. `claude update`나 앱의 업데이트 버튼은 할 일이 없습니다. 에이전트를 자체 설치 프로그램으로 실행하고 싶다면 그렇게 하고 Omarchy 패키지는 설치하지 않은 상태로 두세요. 이미 `PATH`에 있는 복사본은 설치된 것으로 간주됩니다. `grok`용 x.ai 설치 프로그램처럼 Omarchy보다 `PATH`에서 앞에 두 번째 복사본을 배치하는 `curl | bash` 설치 프로그램은 건너뛰세요.

`dsh`는 실행 디렉토리를 기본 작업 공간으로 하여 `127.0.0.1:3080`에서 브라우저 UI를 엽니다. 브라우저 UI는 시작 프롬프트를 받지 않으므로, `omarchy agent prompt`는 붙여넣을 수 있도록 프롬프트를 클립보드에 넣어 엽니다. Omarchy는 DeepSeek의 승인 불필요 권한 프리셋으로 시작합니다. 공식 모델 API를 사용할 때 DeepSeek Harness는 세션 로그를 DeepSeek에 업로드합니다. 브라우저 UI의 _Settings > General > Upload Session Log_에서 이를 끄세요. 보내는 피드백도 세션과 함께 업로드됩니다. 단, `DSH_TELEMETRY_MODE=DISABLED`로 시작하면 예외입니다.

### 기본 에이전트

에이전트 패널에서 에이전트 옆의 별표로 기본 에이전트를 선택하세요. 기본 에이전트에서는 별표가 채워집니다. 또는 `omarchy default agent <name>`로 선택할 수도 있으며, 여기에 표시되지 않은 하네스도 지정할 수 있습니다. 에이전트가 아직 설치되지 않았다면, 선택하면 먼저 설치하고, 앱 런처에서 Agent 옆에 자체 런처도 생깁니다. 새로 설치한 Omarchy는 일회성 알림으로 설정을 권유하며, 이를 열면 에이전트 패널이 열립니다.

Claude를 선택하면 Chromium, Chrome, Brave, Brave Origin, Edge용 브라우저 확장 프로그램도 설정을 시도합니다. 확장 프로그램 설정은 모든 사용자에게 적용되며 시스템 비밀번호를 물을 수 있습니다. 확장 프로그램 설치를 취소하거나 실패해도 Claude는 여전히 선택되고 실행됩니다. 브라우저를 다시 시작하고, 메시지가 표시되면 확장 프로그램을 활성화한 뒤, Claude에 로그인하여 연결을 완료하세요. Claude에서 `/chrome`를 실행하여 연결을 확인하세요. Firefox와 Zen은 이 확장 프로그램을 지원하지 않습니다. 이 설정이 추가되기 전에 이미 Claude가 기본값이었다면, 다시 선택하여 확장 프로그램을 설치하세요.

선택을 마치면 `Super + Shift + Ctrl + A`가 전용 터미널 창에서 기본 에이전트를 실행합니다. 아직 선택하지 않았다면 선택기가 표시됩니다. `omarchy agent prompt "Review this project"`를 사용하면 작업과 함께 바로 실행할 수도 있습니다. Freebuff와 DeepSeek Harness는 시작 프롬프트를 받지 않으므로, 대신 붙여넣을 수 있도록 프롬프트를 클립보드에 넣어 엽니다. 이런 방식으로 실행된 에이전트는 각자의 중단 없이 묻지 않는 모드로 무인 실행되므로, 실제로 작업을 수행할 준비를 하세요! MiniMax Code는 대화형 세션에 그런 모드가 없으므로 평소대로 권한을 묻습니다. 또한 에이전트들은 홈 디렉토리에 대한 신뢰를 기억하기를 거부하므로, `$HOME`에서 실행하면 대신 `~/Work`에서 시작합니다.

터미널 단축키도 있습니다. `a`는 현재 터미널에서 인라인으로 기본 에이전트를 실행하고, `c`, `cx`, `cy`, `ca`는 OpenCode, Claude Code, Codex, Antigravity를 직접 시작합니다. 역시 자동 승인 모드입니다. 테마 변경도 에이전트와 동기화됩니다. Claude Code, Pi, OpenCode, Hermes(Omarchy가 설치한 후)는 Omarchy 테마를 전환할 때 모두 따라갑니다.

### 에이전트 지침

모든 에이전트에 대한 개인 규칙은 `~/.agents/skills`의 공유 스킬 옆에 있는 `~/.agents/AGENTS.md`에 넣으세요. 에이전트 패널의 + 옆에 있는 문서 아이콘으로 열거나, `omarchy agent instructions --edit`로 여세요. 이 명령은 자체 전역 파일을 유지하는 각 하네스에도 이를 연결합니다: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, Copilot의 `~/.copilot/copilot-instructions.md` 등입니다. Crush와 Amp는 `~/.config/AGENTS.md` 링크를 읽고, omp, Kimi, DeepSeek Harness는 `~/.agents/AGENTS.md`를 직접 읽습니다. 기본 에이전트를 선택하면 이 파일도 연결됩니다. 이미 가지고 있던 지침 파일이 있고 공유 파일이 아직 없었다면 그 파일이 공유 파일이 됩니다. 그렇지 않으면 링크 옆에 `.bak`로 보관됩니다. 다른 에이전트를 설치한 후 다시 연결하려면 `omarchy agent instructions`를 실행하세요.

### 에이전트 패널

상단 바에는 에이전트 아이콘이 있습니다. 에이전트를 설정하기 전에는 패널에서 시작하는 세 가지 방법을 제공합니다: Claude, Codex, Grok, Gemini, Muse, Cursor, 또는 Copilot 구독에 로그인하거나, More 아래에서 OpenCode Go, MiniMax, Synthetic, 또는 Z.ai 코딩 플랜에 로그인하기; Fireworks, OpenCode Zen and Go, OpenRouter로 종량제로 사용하거나, More 아래에서 DeepSeek 또는 OpenCode가 로그인하는 다른 모든 제공업체를 사용하기(모두 OpenCode에서 실행됨); 또는 컴퓨터에 맞는 모델이 있을 때 컴퓨터에 가장 적합한 모델 실행하기. 처음 완료한 것이 기본 에이전트가 되며, 패널의 +는 나중에 같은 세 가지 방법을 제공합니다. 그 후 패널은 모든 구독을 한 페이지에 표시합니다: 각 에이전트와 계정에 플랜, 5시간 세션 및 주간 한도 각각에 대한 미터와 재설정까지 남은 시간(정확한 백분율을 보려면 마우스를 올리세요), 또는 남은 선불 잔액이 표시되며, 그 위에는 이번 주 토큰 수와 가장 많이 사용한 모델처럼 전체에서 사용한 내용을 순환 표시하는 줄이 있습니다. _Make something cool_ 아래에서는 기본 에이전트에 작업을 맡기는 새 테마, 플러그인, 앱, 게임을 위한 시작 프롬프트를 제공합니다. 앱은 Omarchy 자체의 Hype, Monologue, Omacut과 같은 방식으로, omarchy-make-app 에이전트 스킬을 따라 C++와 Qt Quick으로 빌드되며, 필요한 컴파일러와 Qt 구성 요소는 설치된 상태로 제공됩니다. 게임은 omarchy-make-game 에이전트 스킬을 따라 `~/Games/vibes`에 있는 단일 three.js 페이지이며, 모두 현재 테마의 하나의 Game Vibes 런처에서 열립니다. 웹에서 three.js를 로드하므로 시작하려면 연결이 필요합니다. Claude Code, Codex, Grok, Kimi, Cursor와 그 Grok Bot 허용량, GitHub Copilot, Muse, Gemini(Antigravity를 통해), Devin은 한도와 함께 기본으로 제공되고, Kimchi는 플랜, 선불 크레딧, 지출 예산과 함께 제공되며, Hermes, Mistral Vibe, Qwen Code는 사용한 후 세션과 토큰을 표시합니다. pi, omp, opencode를 통해 사용하는 제공업체 플랜과 키도 표시됩니다: 한도가 있는 OpenCode Zen and Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan, Synthetic; 선불 잔액이 있는 OpenRouter와 DeepSeek; 지난 30일간의 지출이 있는 Fireworks. 자체 하드웨어에서 실행하는 코딩 모델도 자체 줄을 가지며, 그 토큰도 [로컬 모델](#local-models)에서 설명한 대로 총계에 포함됩니다. 모든 에이전트는 몇 개의 하네스를 통해 구동하든 청구 주체 아래에서 한 번만 계산됩니다.

바 아이콘을 왼쪽 클릭하거나 `Super + Ctrl + X`를 누르면 패널이 열리고, 오른쪽 클릭하면 기본 에이전트가 실행되며, 가운데 클릭하면 새로고침됩니다. 그 뒤에 있는 사용 기록은 `omarchy agent usage update`에 의해 15분마다 재생성되며, 패널은 동기화된 폴더를 통해 다른 컴퓨터의 사용량까지 병합할 수 있습니다. 전체 설정은 `$OMARCHY_PATH/shell/plugins/agents/` 아래의 README를 참조하세요.

### 여러 구독

개인용 Max와 업무용처럼 하나 이상의 Claude, Codex, 또는 Grok 플랜에 비용을 지불하는 경우, Omarchy는 모두 로그인 상태를 유지하고 그 사이를 이동할 수 있습니다. 에이전트 패널의 +로 구독을 추가하세요. 바로 거기서 과정을 안내합니다. 또는 `omarchy agent account add claude Work`(또는 `codex`, 또는 `grok`)로 추가하세요. 같은 +와 명령으로 Gemini(`gemini`)와 OpenCode(`opencode`)에 로그인하고, OpenCode에 Fireworks(`fireworks`) 또는 OpenRouter(`openrouter`) API 키를 저장할 수 있습니다. 이 명령은 Copilot(`copilot`), Cursor(`cursor`), Muse(`muse`)에도 로그인합니다. 이들은 각각 하나의 로그인만 유지합니다. CLI가 없으면 설치합니다. 제공업체의 첫 번째 계정은 CLI가 항상 찾는 바로 그곳, 일반 브라우저를 통해 로그인합니다. 그 이후의 모든 계정은 비공개 창을 통해 로그인하므로, 브라우저에 이미 로그인된 계정이 실수로 선택되지 않습니다. 추가하려는 계정으로 거기에 로그인하고, 이미 열어 둔 비공개 창은 먼저 닫으세요. 이를 위해 CLI에서 절대 로그아웃하지 마세요: 로그아웃하면 저장된 로그인이 취소되며, 해당 계정을 다시 추가해야 합니다.

구독 로그인을 SSH를 통해 다른 Omarchy 컴퓨터에 복사하려면 `omarchy agent account copy user@laptop`을 실행하세요. 대상에 수신기가 설치되어 있지 않으면 송신자가 임시 수신기를 제공하므로, 이전 Omarchy 컴퓨터도 업데이트 없이 계정을 받을 수 있습니다. 설치된 수신기가 우선합니다. 이는 모든 Claude, Codex, Grok 구독을 복사합니다. 선택하려면 제공업체 이름을 추가하세요. 예: `omarchy agent account copy laptop claude`. 계정 이름과 명령 ID는 대상에 이미 있는 계정을 포함하여 소스와 일치합니다. 관련 없는 대상 계정의 이름이 충돌하면 숫자 접미사를 받으며, 설정, 스킬, 플러그인, 대화 기록은 각 컴퓨터에 로컬로 유지됩니다.

기존 대상 자격 증명은 유지됩니다. 이미 거기에 로그인된 소스 계정은 자격 증명을 교체하지 않고 이름만 동기화됩니다. 다른 계정은 그 옆에 추가됩니다. 일치하는 계정의 저장된 자격 증명을 교체하려면, 대상에서 해당 계정의 세션을 종료한 후 `omarchy agent account copy --replace laptop claude`를 사용하세요. 새 대상은 소스의 활성 계정과 전환 기본 설정도 받습니다. 이미 확립된 대상은 자체 설정을 유지합니다.

자격 증명은 SSH를 통해 이동하고 대상의 비공개 파일에 저장되므로, 신뢰하는 컴퓨터에만 복사하세요. 이는 일회성 복사이며 지속적인 동기화가 아닙니다. Codex 새로고침 토큰은 다른 컴퓨터에 의해 교체될 수 있어, 복사된 로그인을 갱신해야 할 수 있습니다. 여러 컴퓨터에서 동시에 사용하는 경우 별도의 로그인이 여전히 가장 안정적인 선택입니다. [Codex의 계정 인증 가이드](https://developers.openai.com/codex/auth/ci-cd-auth)를 참조하세요.

제공업체당 하나의 계정이 활성화되며, 모든 새 세션은 그 계정으로 시작합니다: `cx`, `cy`, 일반적인 `claude`, `codex`, 또는 `grok`, `omarchy agent`를 통해 실행되는 모든 것, 그리고 `PATH`에서 CLI를 찾는 스크립트나 편집기가 그렇습니다. `omarchy agent account use work`로 전환하고(`omarchy agent account use main`로 돌아오기), 또는 패널에서 계정 번호를 누른 뒤 `Enter`를 누르거나(또는 별표를 클릭하여) 전환하세요. 실행 중인 Claude 세션도 다음 메시지부터 전환됩니다: 모든 Claude 세션은 `~/.claude`에서 실행되며, 여기에는 항상 활성 계정의 로그인 정보가 들어 있습니다. 이전 Omarchy에 의해 계정 자체 폴더에서 시작된 Claude 세션은 종료될 때까지 그 로그인 정보를 유지하므로, 전환 시 해당 세션을 명명하고 사라지면 저절로 완료됩니다. 실행 중인 Codex와 Grok 세션은 시작한 계정에 그대로 머무릅니다. 대화 기록, 설정, 스킬, 플러그인은 계정 간에 공유되므로, 같은 폴더에서 `claude --continue`를 실행하면 새 계정에서 중단한 곳부터 이어집니다.

계정이 두 개 이상이면 패널은 각 계정의 한도를 나란히 표시하고, 사용 중인 계정에 채워진 별표를 표시합니다. 활성 계정이 한도의 95%를 초과하면 Omarchy가 알리며, 알림을 클릭하면 여유가 가장 많은 계정으로 전환됩니다. 스스로 전환하지는 않습니다. `omarchy agent account threshold 90`으로 임계값을 변경하세요. 모든 계정이 임계값을 초과하면, 어떤 계정이 가장 먼저 여유가 생기는지와 함께 한 번 알립니다. 활성 계정이 임계값에서 15포인트 이내(기본값에서는 80%)에 있는 동안에는 한도를 15분이 아니라 3분마다 확인합니다.

`omarchy agent account list`는 모든 계정과 최신 한도를 표시하고, `omarchy agent account remove work`는 하나를 잊으며, `omarchy agent account rename primary Hey`는 하나의 이름을 바꿉니다(또는 패널에서 계정 이름을 클릭). 이 명령들은 기본 에이전트의 계정에 대해 작동합니다. 다른 제공업체에 접근하려면 먼저 이름을 지정하세요. 예: `omarchy agent account use codex side`. `~/.claude`나 `~/.codex`에 이미 가지고 있던 로그인이 _Main_ 계정입니다. Codex의 것은 있던 자리에 그대로 있고, Claude의 것은 다른 계정이 활성화된 동안 자체 폴더에서 대기합니다. 약 8시간 이상 사용하지 않은 계정은 _Sign-in required_를 표시할 수 있습니다. 이를 클릭하여 패널에서 바로 해당 계정에 다시 로그인하거나, 해당 계정으로 전환하고 세션을 시작하면 저절로 로그인 정보가 새로고침됩니다. `claude mcp add`로 추가한 MCP 서버는 모든 Claude 계정에 도달합니다. 모두 `~/.claude`에서 실행되기 때문입니다. Codex와 Grok의 경우, 계정이 추가될 때 가지고 있던 서버는 해당 계정에 따라가지만, 나중에 추가한 서버는 추가한 계정에만 도달합니다. Claude Desktop은 자체 로그인을 유지하며, CLI 바이너리에 대한 절대 경로로 구성된 Codex 또는 Grok 도구는 전환을 따르지 않습니다. 명시적인 `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, 또는 `GROK_HOME`가 선택한 계정보다 우선합니다.

### 충돌 진단

Omarchy는 systemd-coredump에서 프로세스 충돌을 감시합니다. 기본 에이전트를 선택하면, 코어를 덤프하는 사용자의 모든 프로그램은 "Process crashed" 알림을 가져옵니다. 이를 클릭하면 충돌이 Omarchy의 omarchy-diagnose-crash 스킬과 함께 기본 에이전트에 전달됩니다. 이 스킬은 에이전트가 코어 덤프에서 사실을 확립하고 충돌을 업스트림에 보고할 가치가 있는지 결정하도록 안내합니다. `coredumpctl list`의 모든 PID에 대해 `omarchy agent crash <pid>`로 수동으로 실행할 수도 있습니다.

감시는 기본적으로 켜져 있습니다. _Trigger > Toggle > Crash Capture Off_에서(또는 `omarchy toggle crash-capture`로) 끄면 알림이 중지됩니다. `omarchy agent crash <pid>`는 여전히 수동으로 작동합니다.

충돌은 한 번에 하나의 프로그램씩 음소거할 수도 있으며, 이는 진단이 마지막에 제공하는 것입니다. `omarchy crash mute hyprland`는 해당 프로그램에 대한 알림만 중지하고, `omarchy crash mute hyprland off`는 다시 가져오며, `omarchy crash mute`만 실행하면 음소거한 항목을 나열합니다. 이름만큼이나 바이너리 경로도 잘 받아들이므로, `omarchy crash mute /usr/bin/hyprland`도 같은 일을 합니다. 공백이 포함된 이름은 따옴표로 감싸세요. 예: `omarchy crash mute 'Some App'`. 그 밖의 모든 것은 여전히 알리며, 음소거된 프로그램은 여전히 충돌합니다. 이는 알림을 숨길 뿐, 아무것도 고치지 않습니다.

### 데스크톱 앱

_Install > AI > Desktop_에는 그래픽 AI 앱이 있습니다: Amp Desktop, Antigravity Desktop, ChatGPT 데스크톱 앱, Claude 데스크톱 앱(Anthropic의 Linux 베타, Chat, Cowork, Claude Code 탭 포함), xAI의 모델과 채팅하기 위한 Grok Bot, Herdr Desktop, Hermes Desktop, OpenClaw, Perplexity 데스크톱 앱, T3 Code. Grok Bot은 데스크톱 채팅 앱입니다. 코딩 에이전트는 `grok` 명령입니다.

Hermes Desktop은 알아둘 만한 것입니다. 컴퓨터에는 하나의 Hermes가 있고 그것은 앱의 것이기 때문입니다: Hermes는 오직 앱을 통해서만 설치되며, 기본 에이전트가 실행하는 `hermes` 명령은 앱의 것입니다. Hermes를 기본 에이전트로 선택하면 _Install > AI > Desktop_ 항목이 설치하는 것과 같은 것을 설치합니다: 패키지, 그리고 Hermes 자체 설치 프로그램이 설정한 `~/.hermes` 아래의 Hermes 런타임으로, 처음에는 몇 분이 걸립니다. 그 런타임이 터미널 `hermes` 명령, 기본 에이전트, 앱이 모두 사용하는 하나의 Hermes이며, Omarchy 릴리스를 기다리지 않고 `hermes update`로 자체 업데이트합니다. 설치하면 Hermes에 `omarchy`라는 이름의 스킨으로 Omarchy 테마도 제공되며, 모든 Hermes 표면은 테마를 전환할 때 이를 따릅니다. 원하지 않는다면 Hermes의 Appearance 설정에서 또는 `/skin`으로 다른 것을 선택하세요. 그러면 Omarchy는 그 선택을 그대로 둡니다. _Remove > AI > Desktop_에서 앱을 제거하면 먼저 게이트웨이를 포함해 Hermes를 닫고, 그 런타임을 함께 가져가며, 달리 지시하지 않는 한 채팅, 메모리, Hermes가 스스로 작성한 스킬은 유지합니다: 그 데이터와 연결 설정도 함께 삭제할지 묻고, 기본값은 아니오입니다.

OpenClaw의 데스크톱 경험은 자체 로컬 게이트웨이를 백엔드로 하는 웹 앱으로 열리는 Control UI입니다. OpenClaw는 `~/.openclaw`에 있으며 자체 업데이트합니다: Control UI의 "Update Gateway" 버튼을 사용하거나 `openclaw update`를 실행하면 게이트웨이가 새 버전으로 다시 시작됩니다. Omarchy는 새로 설치할 때 시작할 릴리스만 선택합니다. OpenClaw가 기본 에이전트가 될 수도 있습니다: `omarchy default agent openclaw`로 선택하면 `~/.openclaw`에 같은 복사본을 설정하고, 에이전트는 게이트웨이에 연결된 OpenClaw의 터미널 UI를 엽니다. _Remove > AI > Desktop_에서 OpenClaw를 제거하면 게이트웨이 서비스와 앱을 함께 가져간 다음, `~/.openclaw`도 삭제할지 묻습니다. 그곳에는 OpenClaw 자체와 다운로드하는 플러그인 런타임과 함께 채팅과 자격 증명이 들어 있기 때문입니다. 기본값은 유지하는 것이며, OpenClaw를 다시 설치하면 다시 가져옵니다.

Herdr Desktop은 [Herdr](https://herdr.dev) 데스크톱 앱입니다: 창을 닫아도 핵심에서 계속 실행되는 터미널과 코딩 에이전트의 공간, 탭, 창입니다. 패키지가 아니라 Herdr 자체 설치 프로그램에서 제공되므로 `~/.local/share/herdr-app`에 있으며, 아직 없을 때 `~/.local/bin/herdr-core`에 핵심을 함께 가져오고, 두 가지 모두 자체 업데이트합니다. Omarchy가 `Super + Ctrl + Return`으로 제공하는 `herdr` 명령을 대체하지 않고 그 옆에 있으며, 해당 명령의 직접 키를 받습니다: `Alt + Return`과 `Alt + Shift + Return`은 창을 아래쪽이나 오른쪽으로 분할하고, `Alt + Escape`는 닫으며, `Ctrl + Alt + Arrow`는 창 사이를 이동하고, `Alt + 1..9`와 `Alt + Left/Right`는 탭을 선택하며, `Alt + Up/Down`은 공간 사이를 이동합니다. `Ctrl + 1..9`는 공간을 선택하고 `Alt + Shift + Up/Down`은 에이전트를 단계별로 이동합니다. `Ctrl + Space` 접두사 키는 터미널 전용으로 유지됩니다. 앱이 시퀀스를 위해 일반 Ctrl 키를 유지할 수 없기 때문입니다. Omarchy는 이를 `~/.config/herdr-app/keys.json`에 쓰고, `omarchy-refresh-herdr-app`가 되돌려 놓습니다. 설치하면 Herdr의 Omarchy 테마를 선택하며, 그 후부터 Omarchy 테마를 따릅니다. Herdr는 밝은 모드용 테마 하나와 어두운 모드용 테마 하나를 유지하므로, 어두운 Omarchy 테마와 밝은 Omarchy 테마 사이를 전환한 후에는 다른 모드를 위해 Herdr의 테마 선택기에서 Omarchy를 한 번 더 선택하세요.

T3 Code는 패키지가 아니라 `~/.local/share/t3code`에 있는 공식 AppImage 릴리스에서 실행되므로 자체 업데이트합니다. 설치하면 Stable 채널에서 시작할지 Nightly 채널에서 시작할지 묻습니다. 나중에 T3 Code의 설정에서 전환하세요. 스레드와 설정은 `~/.t3`에 있으며, _Remove > AI > Desktop_에서 T3 Code를 제거하면 함께 가져갑니다.

### 로컬 모델

코딩 에이전트를 위해 자체 컴퓨터에서 개방형 모델을 실행하세요. 프롬프트와 코드는 컴퓨터에 그대로 머무릅니다. 모델에 보낸 어떤 것도 컴퓨터를 떠나지 않습니다. 다음으로 시작하세요:

```bash
omarchy models use best text
```

이는 이 컴퓨터에 가장 적합한 텍스트 모델, 즉 에이전트들이 사용하는 종류를 설정합니다. 이미지, 비디오, 음악 모델도 각자 가장 적합한 것이 있습니다: `omarchy models use best image`, `video`, 또는 `music`. `omarchy models use best`를 실행하면 각 종류별로 이 컴퓨터에 대한 선택을 볼 수 있습니다.

또는 에이전트 패널에서 +를 선택하세요: _Use a local model_ 아래에는 이 컴퓨터에 맞는 모든 코딩 모델이 권장 항목을 먼저 표시하여 나열됩니다. 모델을 실행하는 Podman은 Omarchy와 함께 제공되며, NVIDIA 컴퓨터에서 NVIDIA의 컨테이너 툴킷도 마찬가지여서 GPU를 제공합니다. 어느 하나라도 없으면 첫 번째 설정에서 설치합니다. 그러면 Omarchy는 이 컴퓨터에 권장되는 모델을 선택하고, 다운로드하고, 시작합니다. 수십 GB의 다운로드와 모델 실행 중 컴퓨터 메모리의 대부분이 사용될 것으로 예상하세요: Flash Next는 전체 256K 컨텍스트와 함께 약 100 GiB를 사용합니다. 다른 모델이 필요한 메모리를 점유하고 있으면 중지된 상태로 설정되며, 하나를 중지하면 시작할 준비가 됩니다. 모델은 로그아웃 시 중지됩니다. 다른 용도로 메모리가 필요할 때 직접 중지하세요.

`omarchy models list`는 옵션을 표시하고 일부가 맞지 않는 이유를 설명합니다. 다른 것을 설정하려면 `omarchy models use <recipe>`를 실행하세요. 현재 128 GB Strix Halo 컴퓨터에서는 `qwen3.8-flash-next-gufo`와 `qwen3.8-27b-gufo`를 사용할 수 있습니다. 27B는 약 40 GiB를 차지하므로 다른 작업을 위한 공간을 남깁니다. Intel의 Arc B390을 탑재한 64 GB 노트북에서는 `qwen3.6-35b-a3b-llamacpp`가 약 30 GiB에서 실행됩니다. 새 레시피와 권장 사항은 패키지를 통해 `omarchy update`와 함께 제공됩니다.

추가한 코딩 모델은 구독 옆에 에이전트 패널에서 자체 줄을 가집니다: 시작하려면 재생, 중지하고 메모리를 해제하려면 일시중지, 실행 중 다른 tailnet 컴퓨터와 공유하려면 Tailscale 표시, 해당 모델에서 에이전트를 열려면 터미널 버튼이 있습니다. 그 줄은 진행됨에 따라 다운로드, 로드, 중지를 표시하고, 시작하기에 충분한 여유 메모리가 없으면 그렇게 알려주며, 오류로 중지되면 로그에 연결합니다. 메모리 안에 함께 들어갈 수 있으면 여러 개를 동시에 실행할 수 있습니다. 선택한 줄에서 Delete를 누르면 다운로드까지 포함해 이 컴퓨터에서 모델을 제거합니다. +로 다시 설정할 수 있습니다. 터미널에서 설정한 코딩 모델은 추가할 때까지 + 아래에서 대기하며, 페어링한 컴퓨터(`omarchy models pair <host>`)가 실행하는 모델도 마찬가지입니다.

설정한 모든 코딩 모델은 Claude, Codex, Grok에 로그인하면 하나가 추가되는 것처럼, 모델 이름 아래에 제작사 로고와 함께 앱 런처에도 자체 항목을 가집니다. 이는 해당 모델에서 에이전트를 열고, 실행 중이 아니면 먼저 모델을 시작합니다: 터미널은 로딩을 표시하고 준비가 되면 에이전트에 넘깁니다. 모델을 제거하면 해당 항목도 제거됩니다.

모든 모델이 코딩용은 아닙니다. 이미지, 비디오, 음악 모델은 대신 Fantasi에서 열립니다. Fantasi는 이 컴퓨터에서 실행되는 모델로 사진, 비디오, 음악을 만들기 위한 Omarchy 앱이며, 거기서 또는 `omarchy models`로 관리됩니다.

모델은 설정된 그대로 계속 실행되므로, Omarchy 업데이트가 에이전트 아래에서 모델을 다시 시작하지는 않습니다. 설정한 모델에 대해 Omarchy에 더 새로운 런타임이나 더 새로운 가중치가 있으면, 그 줄에 업데이트 버튼이 표시됩니다: 이를 누르면 모델이 백그라운드에서 다시 설정되고, 변경된 것만 다운로드하며, 새 버전으로 다시 시작됩니다. 중지된 모델은 중지된 상태를 유지합니다. `omarchy models update`는 터미널에서 모든 모델에 대해 같은 작업을 합니다.

명령줄에서는 `omarchy models start <recipe>`와 `omarchy models stop <recipe>`가 같은 작업을 하고, `omarchy models status`는 모든 모델을 표시하며, `omarchy agent --local-model <recipe>`는 기본 에이전트가 무엇이든 pi에서 해당 모델을 엽니다. 에이전트 단축키, Quake 콘솔, _Make something_이 로컬 모델을 열게 하려면 `omarchy default agent local`을 실행하거나 에이전트 패널에서 실행 중인 모델에 별표를 표시하세요. pi도 자체 모델 선택기에 설정한 모든 모델과 페어링한 컴퓨터의 모델을 나열하므로, 일반적인 `pi`도 이에 도달할 수 있습니다. OpenAI 호환 클라이언트도 연결할 수 있습니다: `status`는 각 모델의 주소를 표시하고(첫 번째는 `http://127.0.0.1:11435/v1`), 레시피 이름이 모델이며, 키는 `~/.config/omarchy/agent-local/key`에 있습니다.

`omarchy models remove <recipe>`는 모델과 다른 모델이 사용하지 않는 다운로드를 삭제합니다.

타사 런타임에는 게시자가 표시됩니다. Omarchy는 네트워크 액세스 없이 모든 모델을 실행합니다.

### 로컬 LLM

Omarchy는 로컬 LLM 모델을 실행하는 두 가지 방법을 권장합니다: LM Studio와 Ollama. LM Studio는 개방형 가중치 모델을 찾고, 설치하고, 실행하기 위한 GUI 인터페이스를 제공합니다. 쉽게 시작하기에 좋은 방법입니다. Ollama는 비슷하게 이를 수행하는 CLI를 제공합니다. 하지만 로컬 모델이 처음이라면, 저는 LM Studio부터 시작하겠습니다. Omarchy Menu의 _Install > AI > Desktop_에서 LM Studio를 설치하고, _Install > AI > CLI_에서 Ollama를 설치하세요.

### Omarchy 스킬

에이전트 스킬은 AI가 특정 도구를 특정 방식으로 사용하도록 돕고, Omarchy는 일곱 가지를 제공합니다. omarchy 스킬은 Hyprland 설정을 조정하거나 바를 조정하는 것처럼 시스템을 맞춤 설정하는 것을 다룹니다. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app, omarchy-make-game는 새로운 것을 만드는 것을 다루고, omarchy-contribute는 버그를 보고하거나 수정 사항을 업스트림에 보내는 것을 다루며, omarchy-diagnose-crash는 충돌의 코어 덤프를 بررسی합니다. 이들은 Claude Code(`~/.claude/skills`), Codex(`~/.codex/skills`), Pi(`~/.pi/agent/skills`), Antigravity(`~/.gemini/config/skills`), Hermes(`~/.hermes/skills`와 각 `~/.hermes/profiles/*/skills`), 그리고 일반적인 `~/.agents/skills` 위치의 스킬 디렉토리에 심볼릭 링크되어 있으므로, 대부분의 하네스가 자동으로 가져옵니다. 같은 이름의 자체 스킬 폴더가 우선합니다.

하지만 이 스킬들은 실험적인 것으로 취급해야 합니다. 모델마다 이를 사용하는 효과가 다를 것입니다. 먼저 플랜 모드로 실행하는 것이 가장 좋습니다. 그래야 에이전트가 무엇을 변경하고 싶은지 알 수 있습니다. 그리고 에이전트가 모든 것을 엉망으로 만들면 변경 사항을 롤백하거나 심지어 `omarchy reinstall configs`를 호출할 준비를 하세요.
