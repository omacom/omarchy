# AI

Omarchy는 기본값을 대신 정해주지 않고 아래 코딩 에이전트들의 실행 프로그램을 포함한다. 명령을 실행하면 처음 사용할 때 해당 CLI가 설치되고, 안내가 나오면 인증하라. Hermes와 OpenClaw는 예외다: 이 둘은 mise를 통해 아무것도 설치되지 않으며, 둘 중 하나를 선택하면 아래 _데스크톱 앱_에서 설명하듯 자체 업데이트되는 자체 복사본을 설정한다.

### 에이전트 설치와 업데이트

Hermes와 OpenClaw를 제외하고, 이 에이전트들은 mise의 지연 설치를 사용한다: 처음 실행할 때 CLI가 설치되고, 이후 실행에서는 그것을 재사용한다. mise는 또한 시작 직전이나 셸 프롬프트에서 백그라운드로, 최대 네 시간에 한 번 설치된 에이전트의 새 릴리스가 있는지 확인한다. 그 업데이트가 실패하거나 오프라인 상태이면 설치된 버전이 실행된다. `omarchy update`는 나머지 Omarchy와 함께 설치된 에이전트들을 업데이트하고, `mup`은 mise가 관리하는 도구만 업데이트한다.

`claude update`, `codex update` 같은 에이전트 자체 업데이터나 앱 안의 업데이트 버튼은 mise가 관리하는 설치본을 업데이트하지 않는다. `codex update`는 실패하고, `claude update`는 mise가 추적하지 않는 별도 복사본을 설치하면서 성공했다고 보고할 수 있다. 에이전트의 네이티브 설치 프로그램과 업데이터를 대신 사용하고 싶다면, 그것을 `disable_tools`에 추가하라; [미리 설치된 CLI 도구](18-development-tools.md#preinstalled-cli-tools)를 보라.

필요해지기 전에 구성된 모든 지연 도구를 설치하려면 `mise install --include-lazy`를 실행하라. 여기에는 에이전트들뿐 아니라 Omarchy의 다른 기본 CLI 도구들도 포함된다. 단일 도구를 설치하거나 직접 설치한 것을 사용하는 방법은 [미리 설치된 CLI 도구](18-development-tools.md#preinstalled-cli-tools)를 보라.

`grok`은 `claude`와 `codex`와 같은 방식으로 mise의 퍼스트파티 `grok` 패키지를 통해 설치된다. `grok`을 실행하거나, 에이전트 패널에서 별표를 표시하라. x.ai에 있는 `curl | bash` 설치 프로그램은 건너뛰어라. 그 경로는 `~/.grok/bin`에 두 번째 복사본을 넣고, 그것을 `PATH` 앞에 추가하며, Omarchy의 래퍼를 덮어쓴다.

`dsh`는 실행 디렉터리를 기본 워크스페이스로 삼아 `127.0.0.1:3080`에서 브라우저 UI를 연다. 그 브라우저 UI는 시작 프롬프트를 받지 않으므로, `omarchy agent prompt`는 붙여넣을 수 있도록 프롬프트를 클립보드에 담은 상태로 그것을 연다. Omarchy는 DeepSeek의 승인 없음 권한 프리셋으로 그것을 시작한다. DeepSeek Harness는 공식 모델 API를 사용할 때 세션 로그를 DeepSeek에 업로드한다; 브라우저 UI의 _Settings > General > Upload Session Log_에서 그것을 꺼라. 당신이 보내는 피드백도 세션과 함께 업로드되며, `DSH_TELEMETRY_MODE=DISABLED`로 시작하면 예외다.

### 기본 에이전트

에이전트 패널에서 에이전트 옆의 별표로 기본 에이전트를 고르라. 기본 에이전트의 별표는 채워져 있다. 또는 거기에 줄이 없는 하네스도 무엇이든 받을 수 있는 `omarchy default agent <name>`으로도 고를 수 있다. 에이전트가 아직 설치되지 않았다면, 고르는 것이 먼저 그것을 설치하고, 앱 실행 프로그램에서 Agent 옆에 자체 실행 프로그램도 생긴다. 새로 설치한 Omarchy는 한 번만 표시되는 알림으로 설정하라고 권하며, 그 알림은 에이전트 패널을 연다.

Claude를 선택하면 Chromium, Chrome, Brave, Brave Origin, Edge용 브라우저 확장 프로그램도 설정을 시도한다. 확장 프로그램 설정은 모든 사용자에게 적용되며 시스템 비밀번호를 물을 수 있다; 취소하거나 확장 프로그램 설치가 실패해도 Claude는 여전히 선택되고 실행된다. 브라우저를 다시 시작하고, 안내가 나오면 확장 프로그램을 활성화한 뒤, Claude에 로그인해 연결을 마쳐라. 연결을 확인하려면 Claude에서 `/chrome`을 실행하라. Firefox와 Zen은 이 확장 프로그램을 지원하지 않는다. 이 설정이 추가되기 전에 이미 Claude가 기본값이었다면, 확장 프로그램을 설치하기 위해 다시 선택하라.

선택을 마친 뒤에는 `Super + Shift + Ctrl + A`가 전용 터미널 창에서 기본 에이전트를 실행한다(아직 선택하지 않았다면 선택기를 띄운다). `omarchy agent prompt "Review this project"`로 바로 작업에 투입할 수도 있다. Freebuff와 DeepSeek Harness는 시작 프롬프트를 받지 않으므로, 대신 붙여넣을 수 있도록 프롬프트를 클립보드에 담은 상태로 열린다. 이런 방식으로 실행된 에이전트들은 각자의 묻지 않고 멈추지 않는 모드로 무인 실행되니, 실제로 일을 벌일 준비를 해라! MiniMax Code는 대화형 세션에 그런 모드가 없어서 평소대로 권한을 묻는다. 그리고 에이전트들은 홈 디렉터리에 대한 신뢰를 기억하기를 거부하므로, `$HOME`에서 실행하면 대신 `~/Work`에서 시작한다.

터미널 단축키도 있다: `a`는 현재 터미널 안에서 인라인으로 기본 에이전트를 실행하고, `c`, `cx`, `cy`는 OpenCode, Claude Code, Codex를 직접 시작한다(역시 자동 승인 모드다). 테마 변경도 에이전트들에 동기화된다: Claude Code, Pi, OpenCode, 그리고 Hermes(Omarchy가 설치한 뒤부터)는 Omarchy 테마를 바꿀 때 함께 따라온다.

### 내 에이전트 지침

모든 에이전트에 대한 개인 규칙은 `~/.agents/skills`에 있는 공유 스킬 옆의 `~/.agents/AGENTS.md`에 들어간다. 에이전트 패널의 + 옆에 있는 문서 아이콘으로 열거나, `omarchy agent instructions --edit`로 열라. 이 명령은 자체 전역 파일을 유지하는 각 하네스에도 그것을 연결한다: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, Copilot의 `~/.copilot/copilot-instructions.md` 등이다. Crush와 Amp는 `~/.config/AGENTS.md` 링크를 읽고, omp, Kimi, DeepSeek Harness는 `~/.agents/AGENTS.md`를 직접 읽는다. 기본 에이전트를 고르는 것도 그것을 연결한다. 이미 갖고 있던 지침 파일이 있고 공유 파일이 아직 없었다면 그것이 공유 파일이 되고, 그렇지 않다면 링크 옆에 `.bak`으로 보관된다. 다른 에이전트를 설치한 뒤에는 `omarchy agent instructions`를 실행해 다시 연결하라.

### 에이전트 패널

상단 바에는 에이전트 아이콘이 있다. 에이전트를 설정하기 전에는, 그 패널이 시작하는 세 가지 방법을 제공한다: Claude, Codex, Grok, Gemini, Muse, Cursor, Copilot 구독에 로그인하거나, More 아래의 OpenCode Go, MiniMax, Synthetic, Z.ai 코딩 플랜에 로그인하는 것; Fireworks, OpenCode Zen and Go, OpenRouter로, 또는 More 아래의 DeepSeek나 OpenCode가 로그인하는 다른 어떤 제공자로든 종량제로 지불하며, 모두 OpenCode에서 실행되는 것; 또는 내 컴퓨터에 맞는 모델이 있을 때 그 컴퓨터에 가장 좋은 모델을 실행하는 것이다. 처음 완료한 것이 기본 에이전트가 되고, 패널의 +나 Omarchy Menu의 _Agent > Add_가 나중에 같은 세 가지를 제공한다. 그 뒤에는 패널이 모든 구독을 한 페이지에 담는다: 각 에이전트와 계정에 그 플랜, 5시간 세션 한도와 주간 한도 각각에 대한 게이지와 초기화까지 남은 시간(정확한 백분율은 마우스를 올려 확인), 또는 남은 선불 잔액이, 이번 주 토큰과 가장 많이 쓴 모델처럼 전체에서 사용한 내용을 번갈아 보여주는 줄 아래에 표시된다. _Make something cool_ 아래에서는 기본 에이전트에 작업을 넘기는 새 테마, 플러그인, 앱, 게임을 위한 시작 프롬프트들을 제공한다. 앱은 Omarchy 자체의 Hype, Monologue, Omacut이 만들어지는 방식대로 C++와 Qt Quick으로 만들어지며, omarchy-make-app 에이전트 스킬을 따르고, 필요한 컴파일러와 Qt 구성 요소들이 설치되어 온다. 게임은 omarchy-make-game 에이전트 스킬을 따르는 `~/Games/vibes` 안의 단일 three.js 페이지이며, 모두 현재 테마의 하나의 Game Vibes 실행 프로그램에서 열린다; three.js를 웹에서 불러오므로 시작하려면 연결이 필요하다. Claude Code, Codex, Grok, Kimi, Cursor와 그 Grok Bot 허용량, GitHub Copilot, Muse, Gemini(Antigravity를 통해), Devin은 한도와 함께 기본으로 다뤄지고, Kimchi는 그 플랜, 선불 크레딧, 지출 예산과 함께, Hermes, Mistral Vibe, Qwen Code는 한 번 사용한 뒤부터 세션과 토큰을 보여준다. pi, omp, opencode를 통해 사용하는 제공자 플랜과 키도 나타난다: OpenCode Zen and Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan, Synthetic은 한도와 함께; OpenRouter와 DeepSeek는 선불 잔액과 함께; Fireworks는 지난 30일간 지출과 함께 나타난다. 자체 하드웨어에서 실행하는 모델의 토큰도 합계에 포함된다; 모델 자체에는 [로컬 모델](#local-models)에서 설명하는 자체 패널이 있다. 모든 에이전트는 몇 개의 하네스를 통해 구동하든 청구 주체 아래에 한 번만 집계된다.

바 아이콘을 왼쪽 클릭하거나 `Super + Ctrl + X`를 누르면 패널이 열리고, 오른쪽 클릭하면 기본 에이전트가 실행되며, 가운데 클릭하면 새로고침된다. 그 뒤에 있는 사용 기록은 `omarchy agent usage update`에 의해 15분마다 재생성되며, 패널은 동기화된 폴더를 통해 다른 컴퓨터들의 사용량까지 병합할 수도 있다. 전체 설정은 `$OMARCHY_PATH/shell/plugins/agents/` 아래의 README를 보라.

### 여러 구독

Claude, Codex, Grok 플랜을 하나 이상 결제한다면 — 예를 들어 개인용 Max와 업무용 하나 — Omarchy는 모두 로그인 상태를 유지하고 그 사이를 오갈 수 있다. 에이전트 패널의 +로 구독을 추가하면 바로 거기서 단계별로 안내하거나, `omarchy agent account add claude Work`(또는 `codex`, 또는 `grok`)로 추가하라. 같은 +와 명령으로 Gemini(`gemini`)와 OpenCode(`opencode`)에 로그인하고, Fireworks(`fireworks`)나 OpenRouter(`openrouter`) API 키를 OpenCode에 저장한다; 이 명령은 Copilot(`copilot`), Cursor(`cursor`), Muse(`muse`)에도 로그인한다. 그것들은 각각 하나의 로그인만 유지한다. CLI가 없으면 설치한다. 제공자의 첫 계정은 CLI가 항상 찾는 바로 그곳에서 일반 브라우저를 통해 로그인한다. 그 뒤의 모든 계정은 시크릿 창을 통해 로그인하므로, 브라우저에 이미 로그인된 계정이 실수로 선택되지 않는다; 거기서 추가하려는 계정으로 로그인하고, 이미 열어 둔 시크릿 창은 먼저 닫아라. 이를 위해 절대로 CLI에서 로그아웃하지 마라: 로그아웃하면 저장된 로그인이 취소되어, 그 계정을 다시 추가해야 한다.

SSH를 통해 다른 Omarchy 컴퓨터에 구독 로그인을 복사하려면 `omarchy agent account copy user@laptop`을 실행하라. 대상에 수신기가 설치되어 있지 않으면 송신 측이 임시 수신기를 제공하므로, 오래된 Omarchy 컴퓨터도 업데이트 없이 계정을 받을 수 있다. 설치된 수신기가 우선한다. 이는 모든 Claude, Codex, Grok 구독을 복사한다; 제공자 이름을 추가해 선택하라. 예를 들어 `omarchy agent account copy laptop claude`다. 계정 이름과 명령 ID는 대상에 이미 있는 계정을 포함해 원본과 일치한다. 관련 없는 대상 계정은 이름이 충돌하면 숫자 접미사를 받고, 설정, 스킬, 플러그인, 대화 기록은 각 컴퓨터에 로컬로 남는다.

대상에 있는 기존 자격 증명은 유지된다. 거기에 이미 로그인된 원본 계정은 자격 증명을 교체하지 않고 이름이 동기화되고, 다른 계정들은 그 옆에 추가된다. 일치하는 계정의 저장된 자격 증명을 교체하려면, 대상에서 그 계정의 세션을 종료한 뒤 `omarchy agent account copy --replace laptop claude`를 사용하라. 새로 설정한 대상은 원본의 활성 계정과 전환 환경 설정도 받는다; 이미 자리 잡은 대상은 자체 것을 유지한다.

자격 증명은 SSH를 통해 이동하고 대상의 비공개 파일에 저장되므로, 신뢰하는 컴퓨터에만 복사하라. 이는 일회성 복사이며 지속적인 동기화가 아니다. Codex 갱신 토큰은 다른 컴퓨터에 의해 교체될 수 있어, 복사된 로그인을 갱신해야 하는 상태로 남길 수 있다; 여러 컴퓨터에서 동시에 사용하는 가장 믿을 만한 선택은 여전히 별도로 로그인하는 것이다. [Codex의 계정 인증 안내](https://developers.openai.com/codex/auth/ci-cd-auth)를 보라.

제공자당 하나의 계정이 활성화되고, 모든 새 세션은 그것으로 시작한다: `cx`, `cy`, 평범한 `claude`, `codex`, `grok`, `omarchy agent`를 통해 실행되는 모든 것, 그리고 `PATH`에서 CLI를 찾는 스크립트나 편집기가 그렇다. `omarchy agent account use work`로 전환하고(`omarchy agent account use main`으로 되돌아간다), 패널에서는 계정 번호를 누른 뒤 `Enter`를 누르거나(또는 별표를 클릭하거나) 전환하라. 실행 중인 Claude 세션도 다음 메시지부터 전환된다: 모든 Claude 세션은 항상 활성 계정의 로그인을 담고 있는 `~/.claude`에서 실행된다. 오래된 Omarchy에 의해 계정 자체 폴더에서 시작된 Claude 세션은 종료될 때까지 그 로그인을 유지하므로, 전환은 그런 세션들의 이름을 알려주고 그것들이 사라지면 저절로 완료된다. 실행 중인 Codex와 Grok 세션은 시작한 계정에 머문다. 대화 기록, 설정, 스킬, 플러그인은 계정 간에 공유되므로, 같은 폴더에서 `claude --continue`를 실행하면 새 계정에서 중단한 곳부터 이어간다.

계정이 하나보다 많으면, 패널은 각 계정의 한도를 나란히 보여주고 사용 중인 것에 채워진 별표를 표시한다. Omarchy는 활성 계정이 한도의 95%를 넘으면 알려주고, 알림을 클릭하면 여유가 가장 많은 계정으로 전환한다. 절대로 저절로 전환하지 않는다. 임계값은 `omarchy agent account threshold 90`으로 바꿔라. 모든 계정이 임계값을 넘으면, 어떤 계정이 가장 먼저 여유가 생기는지와 함께 한 번 알려준다. 활성 계정이 임계값에서 15포인트 이내에 있는 동안(기본값에서는 80%), 한도는 15분마다가 아니라 3분마다 확인된다.

`omarchy agent account list`는 모든 계정과 그 최신 한도를 보여주고, `omarchy agent account remove work`는 하나를 잊으며, `omarchy agent account rename primary Hey`는 하나의 이름을 바꾼다(또는 패널에서 계정 이름을 클릭하라). 이 명령들은 기본 에이전트의 계정에 대해 작동한다; 다른 제공자에 접근하려면 먼저 그 이름을 대라. 예를 들어 `omarchy agent account use codex side`다. `~/.claude`나 `~/.codex`에 이미 갖고 있던 로그인이 _Main_ 계정이다. Codex의 것은 있던 자리에 머문다; Claude의 것은 다른 계정이 활성화된 동안 자체 폴더에서 기다린다. 약 여덟 시간보다 오래 사용되지 않은 계정은 _Sign-in required_를 보여줄 수 있다; 클릭하면 패널에서 바로 그 계정에 다시 로그인하거나, 그 계정으로 전환해 세션을 시작하면 로그인이 저절로 새로고침된다. `claude mcp add`로 추가한 MCP 서버는 모든 Claude 계정에 닿는데, 모두 `~/.claude`에서 실행되기 때문이다; Codex와 Grok에서는 계정이 추가될 때 갖고 있던 서버는 그 계정으로 함께 가지만, 나중의 서버는 추가한 계정에만 닿는다. Claude Desktop은 자체 로그인을 유지하고, CLI 바이너리에 대한 절대 경로로 구성된 Codex나 Grok 도구는 전환을 따르지 않는다. 명시적인 `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, `GROK_HOME`은 선택된 계정보다 우선한다.

### 충돌 진단

Omarchy는 systemd-coredump에서 프로세스 충돌을 감시한다. 기본 에이전트를 고른 뒤에는, 코어를 덤프하는 내 프로그램이 있으면 "Process crashed" 알림이 뜨고 — 클릭하면 충돌이 Omarchy의 omarchy-diagnose-crash 스킬과 함께 기본 에이전트에 넘겨지며, 이 스킬은 코어 덤프에서 사실을 확정하고 충돌을 업스트림에 보고할 가치가 있는지 결정하는 과정을 에이전트에게 단계별로 안내한다. `coredumpctl list`의 어떤 PID에 대해서도 `omarchy agent crash <pid>`로 직접 실행할 수도 있다.

감시는 기본적으로 켜져 있다. _Trigger > Toggle > Crash Capture Off_ 아래에서(또는 `omarchy toggle crash-capture`로) 끄면 알림이 멈춘다; `omarchy agent crash <pid>`는 여전히 직접 실행할 수 있다.

충돌은 한 번에 하나의 프로그램씩 침묵시킬 수도 있는데, 진단이 마지막에 제공하는 것이 바로 그것이다. `omarchy crash mute hyprland`는 그 프로그램에 대해서만 알림을 멈추고, `omarchy crash mute hyprland off`는 다시 켜며, `omarchy crash mute`만 실행하면 음소거한 목록을 보여준다. 이름만큼이나 바이너리 경로도 잘 받아들이므로, `omarchy crash mute /usr/bin/hyprland`도 같은 일을 한다. 공백이 있는 이름은 `omarchy crash mute 'Some App'`처럼 따옴표로 감싸라. 다른 모든 것은 여전히 알리고, 음소거된 프로그램은 여전히 충돌한다 — 이는 알림을 숨길 뿐, 아무것도 고치지 않는다.

### 데스크톱 앱

_Install > AI_ 메뉴에는 몇 가지 그래픽 AI 앱도 있다: Amp Desktop, Antigravity Desktop, ChatGPT 데스크톱 앱, Claude 데스크톱 앱(Anthropic의 Linux 베타, Chat, Cowork, Claude Code 탭 포함), xAI의 모델과 채팅하는 Grok Bot, Herdr Desktop, Hermes Desktop, OpenClaw, Perplexity 데스크톱 앱, T3 Code다. Grok Bot은 데스크톱 채팅 앱이다. 코딩 에이전트는 `grok` 명령이다.

Hermes Desktop은 알아둘 만한데, 컴퓨터에는 하나의 Hermes가 있고 그건 앱의 것이기 때문이다: Hermes는 오직 앱을 통해서만 설치되며, 기본 에이전트가 실행하는 `hermes` 명령은 앱의 것이다. Hermes를 기본 에이전트로 선택하면 _Install > AI_ 항목이 하는 것과 같은 것이 설치된다: 패키지, 그리고 Hermes 자체 설치 프로그램이 설정하는 `~/.hermes` 아래의 Hermes 런타임으로, 처음에는 몇 분이 걸린다. 그 런타임이 터미널의 `hermes` 명령, 기본 에이전트, 앱이 모두 사용하는 유일한 Hermes이며, Omarchy 릴리스를 기다리지 않고 `hermes update`로 자체 업데이트된다. 설치하면 Omarchy 테마를 `omarchy`라는 이름의 스킨으로 Hermes에 넘겨주기도 하며, 모든 Hermes 표면은 테마를 바꿀 때 이를 따른다; 따르지 않게 하고 싶다면 Hermes의 Appearance 설정에서나 `/skin`으로 다른 것을 고르라. 그러면 Omarchy는 그 선택을 그대로 둔다. _Remove > AI_ 아래에서 앱을 제거하면 먼저 게이트웨이를 포함해 Hermes를 닫고, 그 런타임을 함께 가져가며, 달리 말하지 않는 한 채팅, 메모리, Hermes가 자신을 위해 쓴 스킬을 유지한다: 그 데이터와 연결 설정도 함께 지울지 묻고, 기본값은 아니오다.

OpenClaw의 데스크톱 경험은 자체 로컬 게이트웨이가 뒷받침하는 웹 앱으로 열리는 Control UI다. OpenClaw는 `~/.openclaw`에 살며 자체 업데이트된다: Control UI의 "Update Gateway" 버튼을 사용하거나 `openclaw update`를 실행하면 게이트웨이가 새 버전으로 다시 시작한다. Omarchy는 새로 설치한 것이 시작할 릴리스만 선택한다. OpenClaw는 기본 에이전트도 될 수 있다: _Agent > Harness_ 아래에서 선택하면 `~/.openclaw`에 같은 복사본을 설정하고, 에이전트는 게이트웨이에 연결된 OpenClaw의 터미널 UI를 연다. _Remove > AI_ 아래에서 OpenClaw를 제거하면 게이트웨이 서비스와 앱을 함께 가져간 뒤, 채팅과 자격 증명이 OpenClaw 자체와 다운로드한 플러그인 런타임과 함께 들어 있으므로 `~/.openclaw`도 함께 지울지 묻는다; 기본값은 유지하는 것이며, OpenClaw를 다시 설치하면 그것을 다시 가져간다.

Herdr Desktop은 [Herdr](https://herdr.dev) 데스크톱 앱이다: 창을 닫아도 그 코어에서 계속 실행되는 터미널과 코딩 에이전트들의 스페이스, 탭, 창이다. 패키지가 아니라 Herdr 자체 설치 프로그램에서 오므로 `~/.local/share/herdr-app`에 살고, 아직 없을 때 `~/.local/bin/herdr-core`에 그 코어를 함께 가져오며, 둘 다 자체 업데이트된다. Omarchy가 `Super + Ctrl + Return`에 제공하는 `herdr` 명령을 교체하는 대신 그 옆에 있으며, 그 명령의 직접 키를 받는다: `Alt + Return`과 `Alt + Shift + Return`은 창을 아래나 오른쪽으로 나누고, `Alt + Escape`는 닫으며, `Ctrl + Alt + Arrow`는 창 사이를 이동하고, `Alt + 1..9`와 `Alt + Left/Right`는 탭을 고르고, `Alt + Up/Down`은 스페이스 사이를 이동한다. `Ctrl + 1..9`는 스페이스를 고르고 `Alt + Shift + Up/Down`은 에이전트를 단계별로 오간다. `Ctrl + Space` 접두 키는 앱이 연속 입력용으로 일반 Ctrl 키를 잡아둘 수 없으므로 터미널 전용으로 남는다. Omarchy는 이를 `~/.config/herdr-app/keys.json`에 쓰고, `omarchy-refresh-herdr-app`가 되돌려 놓는다. 설치하면 Herdr의 Omarchy 테마를 고르며, 이후부터 내 Omarchy 테마를 따른다. Herdr는 라이트 모드용 테마 하나와 다크 모드용 테마 하나를 유지하므로, 다크 Omarchy 테마와 라이트 Omarchy 테마 사이를 전환한 뒤에는 다른 모드에 대해 Herdr의 테마 선택기에서 Omarchy를 한 번 더 골라라.

T3 Code는 패키지가 아니라 `~/.local/share/t3code`에 있는 공식 AppImage 릴리스에서 실행되므로 자체 업데이트된다. 설치하면 Stable 채널로 시작할지 Nightly 채널로 시작할지 묻는다; 나중에 T3 Code의 설정에서 전환하라. 스레드와 설정은 `~/.t3`에 살며, _Remove > AI_ 아래에서 T3 Code를 제거하면 함께 가져간다.

### 로컬 모델

내 컴퓨터에서 코딩 에이전트용으로 오픈 모델을 실행하라. 프롬프트와 코드는 컴퓨터에 남는다; 모델로 보낸 어떤 것도 컴퓨터를 떠나지 않는다. 다음으로 시작하라:

```bash
omarchy models use best text
```

이는 이 컴퓨터에 가장 좋은 텍스트 모델, 에이전트들이 사용하는 종류를 설정한다. 이미지, 비디오, 음악 모델에도 각각 가장 좋은 것이 있다: `omarchy models use best image`, `video`, `music`이다. 각 종류의 이 컴퓨터용 선택을 보려면 `omarchy models use best`를 실행하라.

또는 상단 바에서 에이전트 아이콘 옆에 있는 반짝이 아이콘으로, 또는 Super + Ctrl + Alt + X로 로컬 모델 패널을 열고 +를 선택하라. 아이콘은 이 컴퓨터에 맞는 모델이 있을 때 나타난다. 모델을 실행하는 Podman은 Omarchy와 함께 오고, NVIDIA 컴퓨터에서는 모델에 GPU를 제공하는 NVIDIA의 컨테이너 툴킷도 함께 온다; 어느 하나라도 없으면 첫 설정이 설치한다. 그러면 Omarchy가 이 컴퓨터에 권장되는 모델을 고르고, 다운로드하며, 시작한다. 수십 GB의 다운로드와 모델이 실행되는 동안 컴퓨터 메모리의 대부분이 사용될 것을 예상하라: Flash Next는 전체 256K 컨텍스트에 약 100 GiB를 사용한다. 다른 모델들이 필요한 메모리를 차지하고 있으면, 멈춘 상태로 설정되어 하나를 멈추면 시작할 준비가 된다. 모델은 로그아웃 때 멈춘다; 다른 일에 메모리가 필요할 때 직접 멈춰라.

`omarchy models list`는 선택지를 보여주고 일부가 맞지 않는 이유를 설명한다. 다른 것을 설정하려면 `omarchy models use <recipe>`를 실행하라. 현재 128 GB Strix Halo 컴퓨터에는 `qwen3.8-flash-next-gufo`와 `qwen3.8-27b-gufo`가 있고; 27B는 약 40 GiB를 차지하므로 다른 작업을 위한 공간을 남긴다. Intel의 Arc B390이 있는 64 GB 노트북에서는 `qwen3.6-35b-a3b-llamacpp`가 약 30 GiB에서 실행된다. 새 레시피와 권장 사항은 패키지를 통해 `omarchy update`와 함께 제공된다.

설정한 모든 모델은 로컬 모델 패널에 자체 줄을 얻는다: 재생하면 시작하고, 일시정지하면 멈추어 메모리를 비우며, 터미널 버튼을 누르면 그 모델에서 에이전트를 연다. 상단 전체에 걸쳐 있는 바는 컴퓨터 메모리가 Omarchy 자체(시스템과 내 앱), 실행 중인 각 모델, 비어 있는 부분으로 어떻게 나뉘는지 보여준다. 멈춘 모델을 가리키면 바는 맞는지, 또는 얼마나 부족한지 보여준다. 메모리에 함께 맞으면 여러 개가 동시에 실행될 수 있다; 맞지 않으면 Omarchy는 어떤 실행 중인 모델을 멈춰야 하는지 말한다. 로고로 줄을 끌어 순서를 바꾸고, 선택한 줄에서 Delete를 눌러 모델과 그 다운로드를 제거하라.

설정한 모든 코딩 모델은 앱 실행 프로그램에도 모델 이름과 제작사 로고로 자체 항목을 얻는데, 이는 Claude, Codex, Grok에 로그인하면 하나가 추가되는 방식과 같다. 그것은 그 모델에서 에이전트를 열고, 실행 중이 아니면 모델을 먼저 시작한다: 터미널은 로딩되는 모습을 보여주고 준비되면 에이전트에 넘긴다. 모델을 제거하면 그 항목도 제거된다.

모든 모델이 코딩용은 아니다. 이미지, 비디오, 음악 모델은 대신 Fantasi에서 열리며, 이는 이 컴퓨터에서 실행되는 모델로 사진, 비디오, 음악을 만드는 Omarchy 앱으로, 거기서 또는 로컬 모델 패널의 해당 줄에서 고른다.

모델은 설정된 그대로 계속 실행되므로, Omarchy 업데이트가 에이전트 아래에서 모델을 절대로 다시 시작하지 않는다. 설정한 모델에 대해 Omarchy가 더 새로운 런타임이나 더 새로운 가중치를 갖고 있을 때, 그 줄에는 업데이트 버튼이 표시된다: 누르면 모델이 백그라운드에서 다시 설정되며, 바뀐 부분만 다운로드하고, 새 버전으로 다시 시작한다. 멈춰 있던 모델은 멈춘 상태를 유지한다. `omarchy models update`는 터미널에서 모든 모델에 대해 같은 일을 한다.

명령줄에서는 `omarchy models start <recipe>`와 `omarchy models stop <recipe>`가 같은 일을 하고, `omarchy models status`는 모든 모델을 보여주며, `omarchy agent --local-model <recipe>`는 기본 에이전트가 무엇이든 그 모델을 pi에서 연다. 로컬 모델을 에이전트 단축키, Quake 콘솔, _Make something_이 여는 것으로 만들려면 `omarchy default agent local`을 실행하거나 _Agent > Harness_ 아래에서 _Local model_을 고르라. pi는 자체 모델 선택기에도 설정한 모든 모델과 페어링한 컴퓨터에 있는 모델들을 나열하므로, 평범한 `pi`도 그것들에 닿는다. 모든 OpenAI 호환 클라이언트도 연결할 수 있다: `status`는 각 모델의 주소를 보여주고(첫 번째는 `http://127.0.0.1:11435/v1`), 레시피 이름이 모델이며, 키는 `~/.config/omarchy/agent-local/key`에 있다.

`omarchy models remove <recipe>`는 모델과 다른 어떤 모델도 사용하지 않는 다운로드들을 삭제한다.

서드파티 런타임에는 게시자가 표시된다. Omarchy는 모든 모델을 네트워크 접근 없이 실행한다.

### 로컬 LLM

Omarchy는 로컬 LLM 모델을 실행하는 두 가지 방법을 권장한다: LM Studio와 Ollama다. LM Studio는 오픈 웨이트 모델을 찾고, 설치하고, 실행하는 GUI 인터페이스를 제공한다. 쉽게 시작하는 훌륭한 방법이다. Ollama도 비슷하게 하는 CLI를 제공한다. 하지만 로컬 모델이 처음이라면, 나는 LM Studio부터 시작하겠다. Omarchy Menu의 _Install > AI_ 아래에서 어느 쪽이든 설치할 수 있다.

### Omarchy 스킬

에이전트 스킬은 AI가 특정 도구를 특정 방식으로 사용하도록 돕고, Omarchy는 그 중 일곱 가지를 제공한다. omarchy 스킬은 Hyprland 설정을 조정하거나 바를 조절하는 것처럼 시스템을 맞춤화하는 것을 다룬다. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app, omarchy-make-game은 새로운 것을 만드는 것을 다루고, omarchy-contribute는 버그를 보고하거나 업스트림에 수정 사항을 보내는 것을 다루며, omarchy-diagnose-crash는 충돌의 코어 덤프를 끝까지 파고든다. 이들은 Claude Code(`~/.claude/skills`), Codex(`~/.codex/skills`), Pi(`~/.pi/agent/skills`), Antigravity(`~/.gemini/config/skills`), Hermes(`~/.hermes/skills`와 각 `~/.hermes/profiles/*/skills`), 그리고 일반적인 `~/.agents/skills` 위치의 스킬 디렉터리에 심볼릭 링크되어 있어, 대부분의 하네스가 자동으로 가져간다. 같은 이름의 내 스킬 폴더가 우선한다.

하지만 이 스킬들을 실험적인 것으로 취급해야 한다. 모델마다 그것을 쓰는 효과가 다를 것이다. 에이전트가 무엇을 바꾸고 싶어할지 알 수 있도록 먼저 계획 모드로 실행하는 것이 가장 좋다. 그리고 에이전트가 모든 것을 엉망으로 만들면, 변경 사항을 되돌리거나 심지어 `omarchy reinstall configs`를 호출할 준비를 해라.
