# 문제 해결

### 업데이트하다가 시스템을 망가뜨렸어요!

먼저 최근 업데이트 이전 버전으로 [시스템을 롤백](47-system-snapshots.md) 해 보세요. 그래도 안 되면 `omarchy-debug`를 사용해 Discord의 #omarchy-help에 문제를 공유하세요. 그리고 그마저도 안 되면 `omarchy-reinstall`을 사용해 기본 설정과 패키지를 다시 설치할 수 있습니다.

### 왜 일부 앱이 디스플레이에서 너무 크게 보이나요?

Omarchy는 2x 고해상도 디스플레이를 가정하므로, 모니터 패널에서 배율을 선택하기 전까지 `GDK_SCALE`을 2로 설정합니다. 1x 디스플레이를 사용하는데 GTK 또는 X11 앱이 너무 크게 나온다면, 모니터 패널에서 해당 디스플레이에 1x를 선택하거나, `~/.config/hypr/monitors.lua`에 `hl.env("GDK_SCALE", "1")`을 추가하세요(그런 다음 너무 크게 보이는 앱을 다시 시작하세요). [모니터에 관한 매뉴얼](33-monitors.md)을 참조하세요.

Spotify에서는 `Ctrl + Minus`를 사용해 UI를 축소할 수 있습니다(그리고 `Ctrl + Plus`를 사용하면 더 크게 만들 수 있습니다).

### 왜 모든 Super 키 바인딩이 갑자기 작동하지 않나요?

일부 ASUS ROG 및 TUF 노트북에서는 `Fn + Super`가 쉽게 놓치기 쉬운 조합인데, 이 조합은 펌웨어 Windows 키 잠금을 토글합니다(게임 중에 실수로 게임에서 나가지 않도록 만든 기능입니다). 화면에는 이 일이 일어났다는 어떤 표시도 나타나지 않습니다. 잠금이 켜져 있는 동안에는 Super가 아무것도 출력하지 않으므로, Super를 사용하는 모든 Omarchy 바인딩이 그냥 멈추고, 마치 Hyprland가 고장 난 것처럼 보입니다.

`~/.config/hypr/`를 파헤치기 전에 `Fn + Super`를 한 번 누르세요. 그래도 Super가 돌아오지 않으면, 잠금을 켠 채로 두지 않도록 다시 한 번 누르세요. 이것은 F 키 행의 동작만 바꾸는 Fn-lock이 아닙니다.

### Wi-Fi, Bluetooth, 오디오 또는 트랙패드가 갑자기 작동을 멈췄어요

재부팅하기 전에, 문제가 생긴 하위 시스템만 따로 다시 시작해 보세요. Omarchy 메뉴의 _업데이트 > 하드웨어_에는 Wi-Fi, Bluetooth, 오디오, 트랙패드가 있으며, 이 중 하나를 다시 로드하면 "5분 전까지만 해도 됐는데" 하는 상황의 대부분이 해결됩니다. 다시 연결되지 않는 Bluetooth 헤드셋, 절전 모드에서 깨어난 뒤 죽어버린 트랙패드, 모니터를 뽑았을 때 사라진 소리 같은 경우입니다.

### 왜 외부 스피커에서 소리가 나지 않나요?

아마 기본 출력으로 설정되어 있지 않기 때문일 것입니다. 바 오른쪽에 있는 스피커 아이콘을 클릭하면 볼륨 팝업이 열리며, 거기에서 출력 장치를 선택할 수 있습니다(앱별 볼륨을 믹싱할 수도 있습니다).

### 노트북 스피커 소리가 이상해요

일부 노트북에서는 Omarchy가 내장 스피커의 주파수 응답을 보정하는 스피커 튜닝을 자동으로 적용합니다. `omarchy audio tuning status`는 사용 중인 컴퓨터에서 튜닝이 활성화되어 있는지 알려주고, 스피커 소리를 원음 그대로 듣고 싶다면 `omarchy audio tuning off`로 끌 수 있습니다.

### 왜 비밀번호로 로그인하거나 sudo를 사용할 수 없나요?

아마 비밀번호를 너무 여러 번 잘못 입력해서 잠긴 것일 것입니다. 잠금 화면에서 이런 일이 발생한다면, `CTRL + ALT + F2`를 눌러 root로 로그인할 수 있는 새 TTY를 시작한 다음, `faillock --reset --user [your-username]`을 실행하세요. 그러면 잠금이 초기화되고, 다시 사용할 수 있게 됩니다.

### 비밀번호는 맞는데 로그인 화면으로 돌아와요

세션 환경 파일이 깨지면 비밀번호가 맞아도 데스크톱이 시작되지 않을 수 있습니다. 특히 `~/.config/uwsm/env.d/`를 편집한 뒤에는 이 점을 확인할 가치가 있습니다.

`Ctrl + Alt + F2`를 누르고, 평소 사용하는 사용자 이름과 비밀번호로 로그인한 다음, 현재 부팅의 사용자 저널을 살펴보세요:

```bash
journalctl --user -b -t uwsm_env-preloader --no-pager
```

env 출력 표시를 찾을 수 없다는 메시지 바로 앞에, `bad substitution`처럼 자신의 환경 파일 중 하나를 지목하는 오류가 있는지 찾아보세요. 다시 로그인하기 전에 그 파일을 `env.d` 밖으로 이동하세요. 예를 들어, 오류가 `99-custom`을 지목한다면:

```bash
mkdir -p ~/.config/uwsm/disabled
mv -i ~/.config/uwsm/env.d/99-custom ~/.config/uwsm/disabled/
```

UWSM은 구문 오류가 있는 파일은 건너뛰지만, `bad substitution`처럼 파일이 실행될 때만 나타나는 치명적인 오류는 여전히 데스크톱 시작을 막을 수 있습니다. 시스템 스냅샷 롤백으로는 이 파일들이 복구되지 않는데, `/home`은 롤백되지 않기 때문입니다.

로그인할 수 있게 되면, 저장된 복사본을 고친 뒤 다시 이동하세요. `sh -n`은 파일을 실행하지 않고 구문 오류를 잡아내지만, 파일을 소스로 읽을 때 발생하는 모든 오류를 잡아낼 수는 없습니다. 변경 사항을 테스트하는 동안에는 작동하는 터미널을 열어 두세요.

### 왜 1Password SSH Agent / CLI에 대한 1Password 인증 프롬프트가 나타나지 않나요?

이유는 두 가지일 수 있습니다:

풍부한 승인 프롬프트가 나타나려면 설정 > 고급 > 하드웨어 가속 사용이 켜져 있어야 합니다. _참고: 작동을 시작하려면 재부팅이 필요합니다._

 ![troubleshooting-1password](images/troubleshooting-1password.webp)

또는 부팅한 이후 1Password를 실행한 적이 없다면, 프롬프트가 나타나지 않습니다.
