# 문제 해결

### 업데이트하다가 시스템을 망가뜨렸어요!

먼저 최근 업데이트 이전 버전으로 [시스템을 롤백](47-system-snapshots.md)해 보세요. 그래도 안 되면 `omarchy-debug`를 사용해 Discord의 #omarchy-help에 문제를 공유하세요. 그마저도 실패하면 `omarchy-reinstall`을 사용해 기본 설정과 패키지를 다시 설치할 수 있습니다.

### 일부 앱이 디스플레이에서 왜 이렇게 크게 보이나요?

Omarchy는 2x 고해상도 디스플레이를 가정하므로, 모니터 패널에서 배율을 선택하기 전까지 `GDK_SCALE`을 2로 설정합니다. 1x 디스플레이에서 GTK 또는 X11 앱이 너무 크게 나온다면 모니터 패널에서 해당 디스플레이에 1x를 선택하거나, `~/.config/hypr/monitors.lua`에 `hl.env("GDK_SCALE", "1")`를 추가하세요(그런 다음 너무 크게 보이는 앱을 모두 다시 시작하세요). [모니터 매뉴얼](33-monitors.md)을 참조하세요.

Spotify에서는 `Ctrl + Minus`를 눌러 UI를 축소할 수 있습니다(`Ctrl + Plus`를 누르면 커집니다).

### Super 키 바인딩이 전부 작동하지 않는 이유는 무엇인가요?

일부 ASUS ROG 및 TUF 노트북에서는 `Fn + Super`가 실수로 누르기 쉬운 조합으로, 펌웨어 Windows 키 잠금을 토글합니다(게임 중 실수로 게임을 나가는 것을 막기 위한 기능입니다). 화면에는 아무런 표시도 나타나지 않습니다. 잠금이 켜져 있는 동안에는 Super가 아무것도 내보내지 않으므로, Super를 사용하는 모든 Omarchy 바인딩이 그냥 멈추고, Hyprland가 고장 난 것처럼 보입니다.

`~/.config/hypr/`를 파고들기 전에 `Fn + Super`를 한 번 누르고, 그래도 Super가 돌아오지 않으면 잠금을 켠 채로 두지 않도록 다시 한 번 누르세요. 이는 F키 행의 동작만 바꾸는 Fn-lock과는 다릅니다.

### Wi-Fi, Bluetooth, 오디오 또는 트랙패드가 갑자기 작동하지 않아요

재부팅하기 전에 문제가 있는 하위 시스템만 단독으로 다시 시작해 보세요. Omarchy 메뉴의 _Update > Hardware_에는 Wi-Fi, Bluetooth, Audio, Trackpad가 있으며, 이 중 하나를 다시 로드하면 “5분 전까지만 해도 잘 됐는데” 하는 상황의 대부분이 해결됩니다 — 다시 연결되지 않는 Bluetooth 헤드셋, 절전 모드에서 깨어난 뒤 먹통이 된 트랙패드, 모니터를 뽑았을 때 사라진 소리 같은 경우입니다.

### 외부 스피커에서 소리가 나지 않는 이유는 무엇인가요?

아마 기본 출력으로 설정되어 있지 않기 때문일 것입니다. 바 오른쪽의 스피커 아이콘을 클릭하면 볼륨 팝업이 열리며, 여기서 출력 장치를 선택할 수 있습니다(앱별 볼륨을 믹싱할 수도 있습니다).

### 노트북 스피커 소리가 이상해요

일부 노트북에서는 Omarchy가 내장 스피커의 주파수 응답을 보정하는 스피커 튜닝을 자동으로 적용합니다. `omarchy audio tuning status`는 사용 중인 기기에 튜닝이 활성화되어 있는지 알려주고, 스피커 소리를 가공 없이 그대로 듣고 싶다면 `omarchy audio tuning off`로 끌 수 있습니다.

### 비밀번호로 로그인하거나 sudo를 사용할 수 없는 이유는 무엇인가요?

아마 비밀번호를 열 번 잘못 입력해서 잠긴 것일 겁니다. 잠금은 2분이 지나면 저절로 풀립니다. 기다릴 수 없고 잠금 화면에서 이런 일이 발생했다면 `CTRL + ALT + F2`를 눌러 새 TTY를 시작한 뒤 root로 로그인하고 `faillock --reset --user [your-username]`를 실행할 수 있습니다. 그러면 잠금이 초기화되고 바로 사용할 수 있습니다.

### 비밀번호는 맞는데 로그인 화면으로 돌아와요

세션 환경 파일이 손상되면 비밀번호가 맞아도 데스크톱이 시작되지 않을 수 있습니다. `~/.config/uwsm/env.d/`를 편집한 뒤에는 특히 이를 확인할 가치가 있습니다.

`Ctrl + Alt + F2`를 누르고 평소 사용하는 사용자 이름과 비밀번호로 로그인한 뒤, 현재 부팅의 사용자 저널을 검사하세요:

```bash
journalctl --user -b -t uwsm_env-preloader --no-pager
```

`bad substitution`처럼 환경 파일 중 하나의 이름을 가리키는 오류가, env output mark를 찾을 수 없다는 메시지 바로 앞에 있는지 찾아보세요. 다시 로그인하기 전에 그 파일을 `env.d` 밖으로 옮기세요. 예를 들어 오류가 `99-custom`을 가리킨다면 다음과 같이 하세요:

```bash
mkdir -p ~/.config/uwsm/disabled
mv -i ~/.config/uwsm/env.d/99-custom ~/.config/uwsm/disabled/
```

UWSM은 구문 오류가 있는 파일은 건너뛰지만, `bad substitution`처럼 파일이 실행될 때만 나타나는 치명적인 오류는 여전히 데스크톱 시작을 막을 수 있습니다. 시스템 스냅샷 롤백으로는 이 파일들이 복구되지 않습니다. `/home`은 롤백되지 않기 때문입니다.

로그인할 수 있게 되면 저장해 둔 복사본을 고친 뒤에야 다시 옮기세요. `sh -n`은 파일을 실행하지 않고 구문 오류를 잡아내지만, 파일을 소싱할 때 발생하는 모든 오류를 잡아낼 수는 없습니다. 변경 사항을 테스트하는 동안 작동하는 터미널을 하나 열어 두세요.

### 1Password SSH Agent / CLI용 1Password 인증 프롬프트가 나타나지 않는 이유는 무엇인가요?

이는 2가지 이유 때문에 발생할 수 있습니다:

자세한 승인 프롬프트가 나타나려면 Settings > Advanced > Use Hardware Acceleration이 켜져 있어야 합니다. _참고: 이 설정을 적용하려면 재부팅해야 합니다._

 ![troubleshooting-1password](images/troubleshooting-1password.webp)

또는 부팅한 뒤 1Password를 실행한 적이 없다면 프롬프트가 나타나지 않습니다.
