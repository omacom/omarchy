# 보안

Omarchy는 보안을 극도로 진지하게 생각합니다. 이는 _실제 세상_에서 _진짜 일_을 하는 데 사용할 수 있는 운영체제가 되기 위한 것입니다. 노트북을 잃어버리는 일이 보안 비상 사태로 이어져서는 안 되는 곳입니다. 그러니 저희가 하는 일은 다음과 같습니다:

1. *전체 디스크 암호화는 필수입니다*: 이는 데이터의 물리적 보호를 지키는 가장 중요한 단계입니다. 컴퓨터를 분실하거나 도난당해도 데이터는 표준 LUKS(Linux Unified Key Setup)를 사용해 완전히 암호화되어 있습니다.
2. *방화벽이 기본으로 활성화되어 있습니다*: [LocalSend](https://localsend.org/)용 53317번 포트를 제외하고 들어오는 모든 트래픽이 기본으로 차단됩니다. SSH마저 _설정 > 보안 > SSHD_로 켤 때까지 꺼져 있으며, 이를 실행하면 설정의 일환으로 22번 포트(무차별 대입 공격을 막기 위해 속도 제한됨)가 열립니다. 심지어 [ufw-docker](https://github.com/chaifeng/ufw-docker) 설정을 사용해 Docker 접근을 잠가 두어 컨테이너가 세상에 우연히 노출되는 것을 막습니다.
3. *Arch는 항상 최신 업데이트를 제공합니다*: Omarchy가 기반으로 하는 하위 배포판인 Arch는 롤링 배포판입니다. 이는 어떤 패키지에서든 발견되어 패치된 보안 취약점은 `omarchy-update`를 사용해 빠르게 설치할 수 있다는 뜻입니다. 그렇게 항상 모든 것의 최신이자 가장 안전한 버전을 실행합니다.
4. *Omarchy는 자체 패키지와 미러를 유지합니다*: Omarchy는 기본으로 Arch 자체 core/extra/multilib 저장소와 자체 Omarchy 패키지 저장소의 패키지에만 의존합니다. AUR에서 직접 소프트웨어를 설치할 수 있지만 기본 설치는 그렇게 하지 않습니다 — 서드파티 브라우저 같은 몇 가지 선택 사항 설치만 AUR에서 가져옵니다.
5. *Cloudflare가 DDoS로부터 저희를 보호합니다*: 모든 Omarchy 배포 인프라 — ISO, Omarchy 패키지, Arch 미러 — 는 Cloudflare의 막강한 DDoS 방패 뒤에 보호되며 그들의 CDN에 호스팅됩니다. 이는 뛰어난 가용성을 제공합니다.

## 비밀번호 바꾸기

암호화된 설치에서는 두 개의 비밀번호가 있습니다: 부팅할 때 드라이브를 잠금 해제하는 비밀번호와, 로그인하고 `sudo`에 사용하는 비밀번호입니다. 설치 과정에서는 둘을 같게 만듭니다. 둘 다 Omarchy 메뉴의 _업데이트 > 비밀번호_에서 바꿀 수 있습니다 — 첫 번째는 _드라이브 암호화_, 두 번째는 _사용자_입니다. 드라이브 비밀번호를 바꾸려면 먼저 현재 비밀번호를 요구하므로 손에 들고 계세요. 변경이 중단되면 _드라이브 암호화_를 다시 실행하세요: 지금 드라이브를 잠금 해제하는 비밀번호를 묻고 변경을 마무리합니다.

## 이미 사용한 컴퓨터를 다른 사람에게 넘기기

컴퓨터를 다른 사람에게 넘기는 경우 다시 설치할 필요가 없습니다. Omarchy 메뉴에서 _설정 > 컴퓨터 재설정_을 실행하고, 확인으로 `reset`을 입력한 뒤 재부팅하세요. 그러면 모든 사용자 계정과 `/home`의 모든 것이 지워지고, 설치 이후 만든 모든 패키지와 시스템 변경이 버려지며, 컴퓨터의 정체성 — 네트워크 연결, 호스트 키, 그리고 전부 — 이 지워집니다. 돌아오는 것은 첫 부팅 때의 설치 마법사로, 새 소유자가 자신의 이름, 비밀번호, 암호화 비밀번호를 입력할 준비가 됩니다.

이는 설치 프로그램이 찍은 기준 스냅샷을 복원하는 방식으로 작동하므로 Omarchy ISO에서 설치한 컴퓨터에서만 사용할 수 있습니다. 그리고 암호화가 없는 드라이브에서는 재설정이 안전한 지우기가 아니라 삭제이므로, 데이터가 민감했다면 대신 새로 설치하세요.

## 비밀번호 없는 sudo

때로는 `sudo`가 묻지 않기를 원할 때가 있습니다. 대부분 AI 에이전트가 당신을 대신해 오랜 시스템 작업을 하고 있을 때 그렇습니다. _설정 > 보안 > 비밀번호 없는 sudo_는 접근을 얼마 동안 허용할지 묻습니다: **15분**, **1시간**, **1일**, 또는 **영구적으로**. 접근이 활성화되어 있는 동안에는 다른 메뉴 막대 표시기 옆에 빨간 경고 아이콘이 나타납니다. 클릭하거나 명령을 다시 실행해 접근을 끄세요. `omarchy-sudo-passwordless 30`로 분 수(1부터 1440까지)를 직접 전달할 수도 있고, `omarchy-sudo-passwordless permanent`를 사용할 수도 있습니다.

시간 제한 접근은 기한을 넘은 일시 중단에서 깨어난 직후를 포함해 자동으로 만료됩니다. 컴퓨터를 재시작하면 일찍 종료됩니다. 영구적인 접근은 재부팅 후에도 살아남으며 비활성화할 때까지 활성화된 채로 유지됩니다.

Omarchy의 설정 패키지를 업데이트하거나 제거하면 만료 지원이 바뀌기 전에 모든 임시 승인이 종료됩니다. 명령이 승인 또는 정리 오류를 보고하면 다른 승인을 활성화하기 전에 해결하세요. 오류가 비밀번호 없는 접근이 비활성화되었다는 뜻은 아닙니다.

이 점은 똑똑히 알아 두세요: 이것이 켜져 있는 동안 사용자로 실행되는 모든 것은 묻지 않고 루트로서 무엇이든 할 수 있습니다. 그게 바로 요점이자, 바로 위험입니다.

## 서명 키

모든 ISO 서명과 Omarchy 저장소 패키지의 공개 키는 `40DFB630FF42BCFFB047046CF0134EE680CAC571`입니다([openpgp.org에서 확인하세요](https://keys.openpgp.org/search?q=pkgs%40omarchy.org)). `omarchy/omarchy-keyring` 패키지에도 이것이 들어 있으며, 향후 업데이트를 원활하게 배포하는 데 사용될 것입니다.

모든 ISO 릴리스의 서명은 URL에 .sig를 추가해 찾을 수 있습니다. 예: https://iso.omarchy.org/omarchy-x.x.x.iso.sig.
