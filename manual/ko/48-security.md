# 보안

Omarchy는 보안을 극도로 진지하게 취급합니다. 이것은 _실제 업무_를 _실제 세상_에서 수행하는 데 사용할 수 있는 운영체제를 목표로 합니다. 노트북을 잃어버려도 보안 긴급 사태로 이어질 수 없는 운영체제 말입니다. 그래서 저희가 하는 일은 다음과 같습니다:

1. *기본적으로 전체 디스크 암호화가 켜져 있습니다*: 이것은 데이터의 물리적 보호를 확보하는 가장 중요한 단계입니다. 컴퓨터를 분실하거나 도난당해도 데이터는 표준 LUKS (Linux Unified Key Setup)를 사용해 완전히 암호화되어 있습니다. 설치 프로그램에서는 일회용 기기의 경우 이를 선택 해제할 수 있습니다([시작하기](02-getting-started.md) 참조). 암호화 없이 설치하면 이러한 보호가 전혀 없으며, 드라이브를 손에 넣은 누구나 이를 읽을 수 있습니다.
2. *기본적으로 방화벽이 활성화되어 있습니다*: 모든 수신 트래픽은 기본적으로 차단되며, 몇 가지 예외가 있습니다: [LocalSend](https://localsend.org/)를 위한 포트 53317; Docker 브리지 주소(172.17.0.1)에 있는 컴퓨터 자체 리졸버에 대한 DNS 쿼리로, Docker가 컨테이너에 제공하는 사설 주소 범위에서 들어온 경우 허용됩니다; 그리고 멀티캐스트 DNS(포트 5353)로, 이를 통해 네트워크상의 프린터와 다른 기기들이 서로를 찾을 수 있고 그곳에 컴퓨터의 이름도 알립니다. 그 외에도 방화벽은 ping, 라우터에서 주소 받기(DHCP), UPnP 검색에 대한 UFW의 표준 허용을 유지합니다. ssh조차 _설정 > 보안 > SSHD_를 통해 켜기 전까지는 꺼져 있으며, 이 설정은 SSH 키를 승인하고, 비밀번호 로그인을 끄고, 그제서야 포트 22를 엽니다(무차별 대입 공격에 대비해 속도 제한 적용). 컨테이너가 실수로 세상에 노출되는 것을 방지하기 위해 [ufw-docker](https://github.com/chaifeng/ufw-docker) 설정을 사용해 Docker 접근까지 잠급니다.
3. *Arch는 항상 최신 업데이트를 유지합니다*: Omarchy가 기반으로 구축된 하위 배포판인 Arch는 롤링 배포판입니다. 즉, 어떤 패키지에서든 보안 취약점이 발견되고 패치되면 `omarchy-update`를 사용해 빠르게 설치할 수 있습니다. 그렇게 하면 항상 모든 것의 최신이자 가장 안전한 버전을 실행하게 됩니다.
4. *Omarchy는 자체 패키지와 미러를 유지합니다*: Omarchy는 기본적으로 Arch 자체의 core/extra/multilib 저장소(ARM 기기에서는 Arch Linux ARM, 그리고 Apple Silicon에서는 Asahi ALARM 추가)와 자체 Omarchy Package Repository의 패키지에만 의존합니다. AUR에서 직접 소프트웨어를 설치할 수는 있지만, 기본 설치는 그렇게 하지 않습니다 — 타사 브라우저와 같은 몇 가지 선택 설치 항목만 AUR에서 가져옵니다.
5. *Cloudflare가 DDoS로부터 저희를 보호합니다*: Omarchy 배포 인프라 — ISO, Omarchy 패키지, Arch 미러 — 는 Cloudflare의 강력한 DDoS 방어막 뒤에서 보호되며 그들의 CDN에 호스팅됩니다. 이는 탁월한 가용성을 제공합니다.

## 비밀번호 변경하기

암호화된 설치에서는 두 개의 비밀번호가 있습니다: 부팅 시 드라이브를 잠금 해제하는 비밀번호와, 로그인하고 `sudo`를 실행할 때 사용하는 비밀번호입니다. 설정 과정에서 둘은 동일하게 설정됩니다. 둘 다 Omarchy 메뉴의 _업데이트 > 비밀번호_에서 변경할 수 있습니다 — 첫 번째는 _드라이브 암호화_, 두 번째는 _사용자_입니다. 드라이브 비밀번호를 변경하려면 먼저 현재 비밀번호를 묻습니다. 그러니 준비해 두세요. 변경이 중단되면 _드라이브 암호화_를 다시 실행하세요: 지금 드라이브를 잠금 해제하는 비밀번호를 묻고 변경을 완료합니다.

## 이미 사용한 기기 넘기기

기기를 다른 사람에게 넘기는 경우 재설치할 필요는 없습니다. Omarchy 메뉴에서 _제거 > 공장 초기화_를 실행하고, 확인을 위해 `reset`을 입력하고, 요청하면 드라이브 암호화 비밀번호를 입력한 뒤 재부팅하세요. 그러면 모든 사용자 계정과 `/home` 안의 모든 것이 삭제되고, 설치 이후 추가한 모든 패키지와 시스템 변경 사항이 버려지며, 기기의 신원 정보 — 네트워크 연결, 호스트 키 등 전부 — 가 지워집니다. 다시 부팅되면 첫 부팅 때의 설정 마법사가 나타나 새 소유자가 자신의 이름, 비밀번호, 암호화 비밀번호를 입력할 준비가 됩니다.

이는 설치 프로그램이 찍어 둔 기준 스냅샷을 복원하는 방식으로 작동하므로 Omarchy ISO로 설치한 기기에서만 사용할 수 있습니다. 그리고 암호화가 없는 드라이브에서는 초기화가 보안 삭제가 아니라 단순 삭제이므로, 데이터가 민감했다면 대신 새로 설치하세요.

## 비밀번호 없는 sudo

때로는 `sudo`가 묻지 않기를 원할 때가 있습니다. AI 에이전트가 당신을 대신해 긴 시스템 작업을 수행할 때가 가장 흔합니다. _설정 > 보안 > 비밀번호 없는 sudo_는 접근을 얼마나 허용할지 묻습니다: **15분**, **1시간**, **1일** 또는 **영구적으로**. 접근이 활성화되어 있는 동안 다른 메뉴 바 표시기 옆에 빨간색 경고 아이콘이 나타납니다. 이를 클릭하거나 명령을 다시 실행하면 접근이 꺼집니다. `omarchy-sudo-passwordless 30`으로 자신만의 분 수(1부터 1440까지)를 전달할 수도 있고, `omarchy-sudo-passwordless permanent`를 사용할 수도 있습니다.

시간 제한 접근은 자동으로 만료되며, 마감 기한을 넘긴 일시 중단에서 복귀한 직후에도 마찬가지입니다. 컴퓨터를 재시작하면 조기에 종료됩니다. 영구 접근은 재부팅 후에도 유지되며 비활성화할 때까지 계속 활성화됩니다.

Omarchy의 설정 패키지를 업데이트하거나 제거하면 임시 권한 부여는 만료 지원이 변경되기 전에 종료됩니다. 명령이 권한 부여 또는 정리 오류를 보고하면 다른 권한 부여를 활성화하려고 시도하기 전에 이를 해결하세요; 오류가 있다고 해서 비밀번호 없는 접근이 비활성화된 것은 아닙니다.

이 점은 냉정하게 인식하세요: 켜져 있는 동안, 당신의 사용자로 실행되는 모든 것은 묻지 않고 root로서 무엇이든 할 수 있습니다. 그것이 바로 목적이며, 동시에 바로 그 위험입니다.

## 서명 키

모든 ISO 서명과 Omarchy repo 패키지에 대한 공개 키는 `40DFB630FF42BCFFB047046CF0134EE680CAC571`입니다([openpgp.org에서 확인](https://keys.openpgp.org/search?q=pkgs%40omarchy.org)). `omarchy/omarchy-keyring` 패키지에도 이것이 포함되어 있으며, 잠재적인 업데이트를 원활하게 배포하는 데 사용될 것입니다.

모든 ISO 릴리스의 서명은 URL에 `.sig`를 추가하여 찾을 수 있습니다. 예: `https://iso.omarchy.org/omarchy-x.x.x.iso.sig`.
