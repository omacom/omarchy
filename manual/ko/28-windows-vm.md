# Windows VM

Omarchy는 x86_64 컴퓨터에서 Docker VM을 통해 Windows를 실행할 수 있는 쉬운 방법을 제공합니다. Omarchy 메뉴(`Super + Space`)에서 _Install > Windows_를 이용해 설치할 수 있습니다.

이 기능을 사용하려면 컴퓨터에 KVM 가상화가 필요합니다. 대부분의 컴퓨터가 지원하지만 BIOS에서 꺼져 있는 경우도 있으며, 그런 경우 설치 프로그램이 알려줍니다. 디스크 공간도 필요합니다. Windows에 할당할 용량에 이미지 자체를 위한 약 10GB를 더한 만큼입니다.

설치 프로그램은 RAM 용량, CPU 코어 수, 디스크 용량을 얼마나 넘겨줄지(64GB 이상이 합리적인 최소값입니다) 묻고, 이어서 Windows 사용자 이름과 비밀번호를 묻습니다. 비워 두면 `docker` / `admin`이 됩니다. 다운로드에는 시간이 걸립니다. 10-15분이 정상입니다. 브라우저에서 `http://127.0.0.1:8006`으로 진행 상황을 확인할 수 있습니다. 브라우저는 콘솔을 열기 전에 같은 사용자 이름과 비밀번호를 묻습니다.

## 사용하기

설치가 끝나면 앱 실행기에서 _Windows_를 실행하세요. VM이 아직 실행 중이 아니면 시작하고 RDP로 전체 화면 연결합니다. 콜드 스타트 시 15-30초 정도 기다리세요.

RDP 세션은 소리, 마이크, 공유 클립보드를 지원하므로 Linux와 Windows 사이에서 텍스트를 복사하는 것이 그냥 됩니다. 해상도는 창을 따라가며, Omarchy가 디스플레이 배율을 그대로 전달하므로 HiDPI 화면에서도 흐릿하게 엉망이 되지 않습니다.

RDP 창을 닫으면 VM이 자동으로 종료됩니다. 계속 실행해 두고 싶다면, 예를 들어 안에서 무언가 작업 중이라면, 대신 `omarchy windows vm launch --keep-alive`로 실행하세요.

나머지 제어 기능도 같은 명령에 있습니다:

```bash
omarchy windows vm status    # is it running?
omarchy windows vm stop      # shut it down
omarchy windows vm launch    # start and connect
```

## 파일 공유

홈 디렉터리의 `~/Windows` 디렉터리는 VM과 자동으로 공유됩니다. Windows에서 접근해야 할 파일은 거기에 넣으세요. VM은 파일 시스템의 다른 어떤 부분에도 접근할 수 없으므로 Windows 쪽에 있는 악성 요소로부터 안전합니다. VM 자체의 가상 디스크는 `~/.windows`에 있습니다.

이 익숙한 홈 경로는 각자의 파일 시스템에 그대로 머무릅니다. 사용자가 소유한 디렉터리를 가리키는 심볼릭 링크일 수도 있는데, 가상 디스크가 더 큰 드라이브에 있을 때 유용합니다. 설치 프로그램은 홈 디렉터리가 있는 파일 시스템이 아니라 `~/.windows`를 실제로 포함하는 파일 시스템의 여유 공간을 측정합니다.

디스크 경로와 공유 경로는 서로 겹치지 않는 별도의 디렉터리로 유지하세요. 제거 시에는 디스크 디렉터리를 의도적으로 비우지만 공유 디렉터리는 보존합니다. 삭제 직전에 Omarchy는 시간 제한이 있는 포함 관계 검사를 수행하며, 검사가 시간 초과되거나 두 트리가 분리되어 있음을 증명할 수 없으면 아무것도 제거하지 않습니다.

VM이 시작되기 전에 Omarchy는 이 두 디렉터리를 열고 고정한 뒤, 정확한 디렉터리 inode를 `/var/lib/omarchy/windows/mounts` 아래의 사용자별 비공개 앵커에 바인드 마운트합니다. Docker는 root로 보호되는 이 앵커만 볼 수 있습니다. 이렇게 하면 사용자 지정 디스크 위치를 유지하면서, 사용자로 실행 중인 다른 프로세스가 권한 있는 컨테이너가 확인된 경로를 사용하기 전에 이를 바꿔치기하는 것을 막을 수 있습니다. 기존 디스크 및 공유 디렉터리는 마이그레이션 중에 모드 `0700`으로 강화되어 다른 로컬 계정이 내용을 들여다볼 수 없습니다.

VM의 포트는 localhost에만 바인딩되므로 네트워크상의 어떤 것도 Windows 컴퓨터에 접근할 수 없습니다. 웹 콘솔도 구성된 Windows 사용자 이름과 비밀번호를 요구하므로, 다른 로컬 계정이 포트 8006을 통해 VM을 조작할 수 없습니다.

## 제한 사항 및 라이선스

이 구성에는 GPU 패스스루가 없으므로 게임이나 영상 편집에는 적합하지 않습니다. Microsoft Office나 그 밖에 꼭 있어야 하는 프로그램을 실행하기에는 훌륭한 방법입니다.

설치되는 버전은 정품 인증되지 않은 Windows 11 Pro입니다. 제한된 기능을 사용하려면 본인의 라이선스 키가 필요합니다.

이 컴퓨터가 Windows가 탑재된 상태로 출고되었다면 Omarchy를 설치한 뒤에도 OEM 키는 펌웨어에 남아 있습니다. `omarchy windows key`로 출력하세요. 이 키는 이 컴퓨터에 묶여 있습니다. 이 하드웨어에 Windows를 재설치하면 정품 인증이 되지만, VM은 대개 인증되지 않습니다.

나중에 리소스 할당을 바꾸려면 터미널에서 `omarchy windows vm install`을 실행하세요. 답변한 내용을 바탕으로 VM 구성을 다시 씁니다. compose 파일 자체는 이제 `/var/lib/omarchy/windows/docker-compose.yml`에 있으며 root가 소유합니다. 이는 의도적인 것입니다. 사용자로 실행 중인 프로세스가 이를 다시 써서 권한 있는 시작 과정에서 전체 디스크를 컨테이너에 마운트하게 만드는 일을 막기 위해서입니다. 직접 편집해야 한다면(예를 들어 USB 장치를 마운트하려면) `sudo`로 편집하고, 모든 옵션은 [Dockur Windows 프로젝트](https://github.com/dockur/windows)에서 확인하세요.

전체를 없애려면 Omarchy 메뉴에서 _Remove > Windows_를 사용하세요. `~/.windows`에 있는 VM 디스크와 Windows 안에 설치된 모든 것이 삭제되므로, 먼저 필요한 것은 VM 밖으로 복사해 두세요. 공유 폴더인 `~/Windows`는 그대로 둡니다.
