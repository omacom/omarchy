# AI

Omarchy כוללת משגרים לסוכני הקידוד שלהלן מבלי לבחור עבורך ברירת מחדל. הרץ פקודה כדי להתקין את ה-CLI שלה בשימוש הראשון, ולאחר מכן התחבר כשתתבקש. Hermes הוא היוצא מן הכלל: שום דבר לא מותקן עבורו בשימוש הראשון, ובחירה בו מתקינה את Hermes Desktop, כפי שמסביר _אפליקציות שולחניות_ להלן.

### התקנה ועדכון של סוכנים

למעט Hermes, הסוכנים האלה משתמשים בהתקנה העצלה של mise: ההפעלה הראשונה מתקינה את ה-CLI, והפעלות מאוחרות יותר משתמשות בו שוב. mise גם בודק אם יצאה גרסה חדשה לסוכן מותקן לכל היותר פעם בארבע שעות, ממש לפני שהוא מופעל או ברקע בשורת ה-shell. אם העדכון הזה נכשל או שאתה לא מחובר, הגרסה המותקנת מופעלת. `omarchy update` מעדכן סוכנים מותקנים יחד עם שאר Omarchy, ו-`mup` מעדכן רק כלים המנוהלים על ידי mise.

המעדכן של סוכן עצמו, כגון `claude update`, `codex update` או כפתור עדכון באפליקציה, לא מעדכן את ההתקנה המנוהלת על ידי mise. `codex update` נכשל, ו-`claude update` יכול לדווח על הצלחה תוך התקנת עותק נפרד ש-mise לא עוקב אחריו. אם אתה מעדיף להשתמש במתקין ובמעדכן המקוריים של סוכן, הוסף אותו ל-`disable_tools`; ראה [כלי CLI מותקנים מראש](18-development-tools.md#preinstalled-cli-tools).

כדי להתקין את כל הכלים העצלים שהוגדרו לפני שתצטרך אותם, הרץ `mise install --include-lazy`. זה כולל גם את כלי ה-CLI האחרים של Omarchy כברירת מחדל וגם את הסוכנים. ראה [כלי CLI מותקנים מראש](18-development-tools.md#preinstalled-cli-tools) להתקנת כלי בודד או לשימוש בהתקנה משלך.

`grok` מותקן דרך חבילת `grok` הרשמית של mise, באותו אופן כמו `claude` ו-`codex`. הרץ `grok`, או בחר אותו תחת _Agent > Harness_. דלג על מתקין `curl | bash` ב-x.ai. הנתיב הזה שם עותק שני ב-`~/.grok/bin`, מקדים אותו ב-`PATH`, ודורס את ה-wrapper של Omarchy.

`dsh` פותח את ממשק הדפדפן שלו ב-`127.0.0.1:3080`, כאשר ספריית ההפעלה היא סביבת העבודה ברירת המחדל שלו. ממשק הדפדפן שלו לא מקבל prompt התחלתי, כך ש-`omarchy agent prompt` פותח אותו כשה-prompt נמצא בלוח ההעתקה שלך כדי להדביק. Omarchy מפעילה אותו עם הגדרת ההרשאות no-approval של DeepSeek. DeepSeek Harness מעלה יומני session ל-DeepSeek כאשר אתה משתמש ב-API הרשמי של המודלים שלה; כבה זאת תחת _Settings > General > Upload Session Log_ בממשק הדפדפן שלו. גם משוב שאתה שולח לו מועלה יחד עם ה-session, אלא אם תפעיל אותו עם `DSH_TELEMETRY_MODE=DISABLED`.

### הסוכן ברירת המחדל

בחר את סוכן ברירת המחדל שלך עם `omarchy default agent <name>` או תחת _Agent > Harness_ בתפריט Omarchy (`Super + Space`). אם הסוכן עדיין לא מותקן, בחירה בו תתקין אותו תחילה. Omarchy טרי יזמין אותך לבצע בחירה זו בהתראה חד-פעמית.

בחירה ב-Claude גם מנסה להגדיר את תוסף הדפדפן שלו עבור Chromium, Chrome, Brave, Brave Origin ו-Edge. הגדרת התוסף חלה על כל המשתמשים ועלולה לבקש את סיסמת המערכת שלך; ביטול או התקנת תוסף שנכשלה עדיין בוחרים ומפעילים את Claude. הפעל מחדש את הדפדפן, אפשר את התוסף אם תתבקש, והתחבר ל-Claude כדי לסיים את חיבורו. הרץ `/chrome` ב-Claude כדי לבדוק את החיבור. Firefox ו-Zen לא תומכים בתוסף זה. אם Claude כבר היה סוכן ברירת המחדל שלך לפני שהגדרה זו נוספה, בחר אותו שוב כדי להתקין את התוסף.

לאחר שבחרת, `Super + Shift + Ctrl + A` מפעיל את סוכן ברירת המחדל בחלון טרמינל ייעודי (או מציג את הבורר אם עדיין לא בחרת). אתה יכול גם להפעיל אותו ישירות למשימה עם `omarchy agent prompt "Review this project"`. Freebuff ו-DeepSeek Harness לא מקבלים prompt התחלתי, כך שהם נפתחים כשה-prompt נמצא בלוח ההעתקה שלך כדי להדביק במקום זאת. סוכנים המופעלים כך רצים ללא פיקוח במצבי ה-don't-stop-to-ask שלהם, אז תהיה מוכן לכך שהם באמת יעשו דברים! ל-MiniMax Code אין מצב כזה עבור ה-sessions האינטראקטיביים שלו, כך שהוא מבקש הרשאות כרגיל. ומאחר שסוכנים מסרבים לזכור אמון עבור ספריית הבית שלך, הפעלות מ-`$HOME` מתחילות ב-`~/Work` במקום זאת.

יש גם קיצורי טרמינל: `a` מריץ את סוכן ברירת המחדל inline בטרמינל הנוכחי, בעוד `c`, `cx` ו-`cy` מפעילים את OpenCode, Claude Code ו-Codex ישירות (שוב במצבי האישור האוטומטי שלהם). שינויי ערכת נושא מסתנכרנים גם לסוכנים: Claude Code, Pi, OpenCode ו-Hermes (ברגע ש-Omarchy התקינה אותו) כולם עוקבים אחריך כשאתה מחליף את ערכת הנושא של Omarchy.

### הוראות הסוכן שלך

כללים אישיים לכל סוכן נמצאים ב-`~/.agents/AGENTS.md`, לצד ה-skills המשותפים ב-`~/.agents/skills`. פתח אותו תחת _Agent > Instructions_, שגם מקשר אותו לכל harness ששומר קובץ גלובלי משלו: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, ה-`~/.copilot/copilot-instructions.md` של Copilot, וכן הלאה. Crush ו-Amp קוראים את הקישור `~/.config/AGENTS.md`, בעוד omp, Kimi ו-DeepSeek Harness קוראים את `~/.agents/AGENTS.md` ישירות. בחירת סוכן ברירת מחדל מקשרת אותו גם כן. קובץ הוראות שכבר היה לך הופך למשותף אם עדיין לא היה אחד כזה; אחרת הוא נשמר לצד הקישור כ-`.bak`. הרץ `omarchy agent instructions` כדי לקשר מחדש לאחר התקנת סוכן נוסף.

### פאנל הסוכנים

בסרגל העליון יש אייקון סוכנים. לפני שהגדרת סוכן, הפאנל שלו מלווה אותך בהתחברות ל-Claude, Codex או Grok, והראשון הופך לסוכן ברירת המחדל שלך. לאחר מכן, הפאנל שם כל מנוי בעמוד אחד: כל סוכן וחשבון עם התוכנית שלו, מד לכל אחת ממגבלות ה-session של 5 שעות והמגבלות השבועיות שלו עם הזמן עד שהוא מתאפס (העבר מעליו את העכבר לאחוז המדויק), או היתרה הנותרת ששולמה מראש, מתחת לשורה שמתחלפת בין מה שהשתמשת בו בכל כולם, כמו tokens השבוע והמודל שהשתמשת בו הכי הרבה. תחת _Make something_ הוא מציע prompts פותחים לערכת נושא חדשה, plugin, אפליקציה או משחק שמעבירים את המשימה לסוכן ברירת המחדל שלך. אפליקציות נבנות כפי ש-Hype, Monologue ו-Omacut של Omarchy עצמה נבנות, ב-C++ ו-Qt Quick, לפי ה-skill של הסוכן omarchy-make-app, והמהדר וחלקי ה-Qt שהן צריכות מגיעים מותקנים. משחקים הם עמוד three.js יחיד ב-`~/Games/vibes`, לפי ה-skill של הסוכן omarchy-make-game, וכולם נפתחים מ-launcher אחד של Game Vibes בערכת הנושא הנוכחית; הם טוענים את three.js מהרשת, כך שהם צריכים חיבור כדי להתחיל. Claude Code, Codex, Grok, Kimi, Cursor והקצבת ה-Grok Bot שלו, GitHub Copilot, Muse, Antigravity, Kimchi ו-Devin מכוסים מהקופסה עם המגבלות שלהם, ו-Hermes, Mistral Vibe ו-Qwen Code מציגים את ה-sessions וה-tokens שלהם ברגע שהשתמשת בהם. תוכניות ספקים ומפתחות שאתה משתמש בהם דרך pi, omp או opencode מופיעים גם כן: OpenCode Zen ו-Go, ה-Z.ai GLM Coding Plan, Ollama Cloud, ה-MiniMax Token Plan ו-Synthetic עם המגבלות שלהם; Fireworks, OpenRouter ו-DeepSeek עם היתרות ששולמו מראש שלהם; והמודלים שאתה מריץ על החומרה שלך תחת Local models. כל סוכן נספר פעם אחת, תחת מי שמחייב עליו, לא משנה כמה harnesses אתה מפעיל אותו דרכם.

לחיצה שמאלית על אייקון הסרגל עבור הפאנל, לחיצה ימנית להפעלת סוכן ברירת המחדל שלך. רשומות השימוש שמאחוריו מתחדשות כל 15 דקות על ידי `omarchy agent usage-update`, והפאנל יכול אפילו למזג שימוש מהמכונות האחרות שלך דרך תיקייה מסונכרנת. ראה את ה-README תחת `$OMARCHY_PATH/shell/plugins/agents/` להגדרות המלאות.

### מספר מנויים

אם אתה משלם עבור יותר מתוכנית Claude, Codex או Grok אחת — Max אישי ואחד לעבודה, נניח — Omarchy יכול לשמור את כולם מחוברים ולעבור ביניהם. הוסף מנוי עם ה-+ בפאנל הסוכנים, שמלווה אותך ממש שם, או עם `omarchy agent account add claude Work` (או `codex`, או `grok`). הוא מתקין את ה-CLI אם הוא חסר. החשבון הראשון עבור ספק מתחבר דרך הדפדפן הרגיל שלך, בדיוק במקום שבו ה-CLI תמיד מחפש. כל אחד אחריו מתחבר דרך חלון פרטי, כדי שהחשבון שהדפדפן שלך כבר מחובר אליו לא ייבחר בטעות; התחבר שם כחשבון שאתה מוסיף, וסגור תחילה כל חלון פרטי שכבר פתוח אצלך. לעולם אל תתנתק מה-CLI כדי לעשות זאת: התנתקות מבטלת את ההתחברות השמורה, וחשבון זה יצטרך להתווסף שוב.

כדי להעתיק את התחברויות המנוי שלך למכונת Omarchy אחרת דרך SSH, הרץ `omarchy agent account copy user@laptop`. השולח מספק מקלט זמני כאשר ליעד אין אחד מותקן, כך שמכונות Omarchy ישנות יכולות לקבל חשבונות ללא עדכון. מקלטים מותקנים מקבלים עדיפות. זה מעתיק את כל מנויי Claude, Codex ו-Grok; הוסף שמות ספקים כדי לבחור אותם, כמו ב-`omarchy agent account copy laptop claude`. שמות חשבונות ומזהי פקודה תואמים למקור, כולל חשבונות שכבר קיימים ביעד. חשבונות יעד לא קשורים מקבלים סיומת מספרית אם שמותיהם מתנגשים, והגדרות, skills, plugins והיסטוריית שיחות נשארים מקומיים לכל מכונה.

אישורי יעד קיימים נשמרים. חשבון מקור שכבר מחובר שם מסונכרן בשמו מבלי להחליף את אישוריו; חשבונות אחרים מתווספים לצידו. כדי להחליף אישורים שמורים עבור חשבונות תואמים, השתמש ב-`omarchy agent account copy --replace laptop claude` לאחר יציאה מה-sessions של אותו חשבון ביעד. יעד טרי גם מקבל את החשבון הפעיל ואת העדפות ההחלפה של המקור; יעד מבוסס שומר את שלו.

אישורים עוברים דרך SSH ונשמרים בקבצים פרטיים ביעד, כך שהעתק רק למכונות שאתה סומך עליהן. זו העתקה חד-פעמית, לא סנכרון מתמשך. tokens לרענון של Codex יכולים להיות מוחלפים על ידי מכונה אחרת, ולהשאיר התחברות שהועתקה הזקוקה לחידוש; התחברויות נפרדות נשארות הבחירה האמינה ביותר לשימוש בו-זמני במספר מכונות. ראה [הנחיות האימות לחשבון של Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

חשבון אחד לכל ספק פעיל, וכל session חדש מתחיל כמוהו: `cx`, `cy`, `claude`, `codex` או `grok` רגילים, כל דבר המופעל דרך `omarchy agent`, ו-scripts או עורכים שמוצאים את ה-CLI ב-`PATH`. החלף עם `omarchy agent account use work` (וחזרה עם `omarchy agent account use main`), או בפאנל על ידי לחיצה על מספרו של חשבון ואז `Enter` (או לחיצה על כפתור ה-Use שלו). sessions פועלים של Claude גם מחליפים, מההודעה הבאה שלהם: כל session של Claude רץ ב-`~/.claude`, שתמיד מחזיק את ההתחברות של החשבון הפעיל. session של Claude שהתחיל בתיקייה של חשבון עצמו על ידי Omarchy ישן מחזיק בהתחברות זו עד שהוא יוצא, כך שההחלפה מציינת את ה-sessions האלה ומסיימת מעצמה ברגע שהם נעלמים. sessions פועלים של Codex ו-Grok נשארים בחשבון שהם התחילו איתו. היסטוריית שיחות, הגדרות, skills ו-plugins משותפים בין חשבונות, כך ש-`claude --continue` באותה תיקייה ממשיך מהמקום שהפסקת בו בחשבון החדש.

עם יותר מחשבון אחד, הפאנל מציג את המגבלות של כל חשבון זו לצד זו, כאשר הפעיל מסומן. כברירת מחדל Omarchy מודיעה לך כאשר החשבון הפעיל עובר 95% ממגבלה, ולחיצה על ההתראה מחליפה לחשבון עם המרווח הגדול ביותר. העבר את העכבר מעל שורת חשבון בפאנל ולחץ על ה-Autoswitch שמופיע לצד Use (או לחץ `m`), או הרץ `omarchy agent account mode auto`, כדי שהוא יחליף מעצמו במקום זאת; בזמן שזה פועל, Autoswitch תופס את מקומו של Use, ולחיצה עליו שוב חוזרת להתראה. הוסף מספר כדי לשנות את הסף, כמו ב-`omarchy agent account mode auto 90`. אם כל חשבון מעל הסף, תשמע על כך פעם אחת, יחד עם איזה חשבון משתחרר ראשון. בזמן שחשבון פעיל נמצא בתוך 15 נקודות מהסף שלו (80% בברירת המחדל), המגבלות שלו נבדקות כל שלוש דקות ולא כל 15.

`omarchy agent account list` מציג כל חשבון ואת המגבלות האחרונות שלו, `omarchy agent account remove work` שוכח אחד, ו-`omarchy agent account rename primary Hey` משנה שם של אחד (או לחץ על שמו של חשבון בפאנל). פקודות אלה פועלות על החשבונות של סוכן ברירת המחדל שלך; כדי להגיע לספק האחר, ציין אותו תחילה, כמו ב-`omarchy agent account use codex side`. ההתחברות שכבר הייתה לך ב-`~/.claude` או ב-`~/.codex` היא חשבון ה-_Main_. זו של Codex נשארת במקום שהיא נמצאת בו; זו של Claude ממתינה בתיקייה משלה בזמן שחשבון אחר פעיל. חשבון שלא נעשה בו שימוש יותר מכשמונה שעות יכול להציג _Sign-in required_; לחץ עליו כדי להתחבר לאותו חשבון שוב ממש בפאנל, או החלף אליו והתחל session, שמרענן את ההתחברות מעצמו. שרתי MCP שאתה מוסיף עם `claude mcp add` מגיעים לכל חשבון Claude, מאחר שכולם רצים ב-`~/.claude`; עבור Codex ו-Grok, שרתים שהיו לך כאשר חשבון נוסף באים איתו, אבל שרתים מאוחרים יותר מגיעים רק לחשבון שהוספת אותם בו. Claude Desktop שומר התחברות משלה, וכלים של Codex או Grok שהוגדרו עם נתיב מוחלט לקובץ בינארי של CLI לא עוקבים אחרי ההחלפה. `CLAUDE_CONFIG_DIR`, `CODEX_HOME` או `GROK_HOME` מפורשים מקבלים עדיפות על החשבון שנבחר.

### אבחון קריסות

Omarchy עוקבת אחר systemd-coredump לגבי קריסות תהליכים. כאשר משהו עושה segfault, תקבל התראת "Process crashed" — לחץ עליה, והקריסה מועברת לסוכן ברירת המחדל שלך יחד עם ה-skill diagnose-crash של Omarchy, שמלווה את הסוכן בקביעת העובדות מה-core dump ובהחלטה האם הקריסה שווה דיווח ל-upstream. אתה יכול גם להריץ אותו ידנית מול כל PID מ-`coredumpctl list` עם `omarchy agent crash <pid>`.

המעקב פועל כברירת מחדל. כבה אותו תחת _Trigger > Toggle > Crash Capture_ (או עם `omarchy toggle crash-capture`) וההתראות יפסיקו; `omarchy agent crash <pid>` עדיין עובד ידנית.

קריסות יכולות גם להיות מושתקות תוכנית אחת בכל פעם, וזה מה שהאבחון מציע לך בסוף. `omarchy crash mute hyprland` עוצר את ההתראות רק לאותה תוכנית, `omarchy crash mute hyprland off` מחזיר אותן, ו-`omarchy crash mute` לבדו מפרט את מה שהשתקת. הוא מקבל נתיב של binary באותה שמחה כמו את שמו, כך ש-`omarchy crash mute /usr/bin/hyprland` עושה את אותו הדבר. שים במרכאות שם שיש בו רווח, כמו ב-`omarchy crash mute 'Some App'`. כל השאר עדיין מתריע, והתוכנית המושתקת עדיין קורסת — זה מסתיר את התזכורת, זה לא מתקן שום דבר.

### אפליקציות שולחניות

תפריט _Install > AI_ נושא גם כמה אפליקציות AI גרפיות: Antigravity Desktop, אפליקציית שולחן העבודה של ChatGPT, אפליקציית שולחן העבודה של Claude (הבטא ל-Linux של Anthropic, עם לשוניות Chat, Cowork ו-Claude Code), Grok Bot לשיחה עם המודלים של xAI, Herdr Desktop, Hermes Desktop, OpenClaw, אפליקציית שולחן העבודה של Perplexity ו-T3 Code. Grok Bot היא אפליקציית הצ'אט לשולחן העבודה. סוכן הקידוד הוא פקודת `grok`.

Hermes Desktop היא זו שצריך לדעת עליה, כי למכונה יש Hermes אחד, והוא של האפליקציה: Hermes מותקן רק אי פעם דרך האפליקציה, ופקודת `hermes` שסוכן ברירת המחדל מריץ היא של האפליקציה. בחירת Hermes כסוכן ברירת המחדל מתקינה את אותו הדבר שערך _Install > AI_ עושה: החבילה, ו-runtime של Hermes תחת `~/.hermes` שהוגדר על ידי המתקין של Hermes עצמו, שלוקח כמה דקות בפעם הראשונה. ה-runtime הזה הוא ה-Hermes האחד שפקודת ה-`hermes` בטרמינל, סוכן ברירת המחדל והאפליקציה כולם משתמשים בו, והוא מעדכן את עצמו עם `hermes update` ולא מחכה לגרסה של Omarchy. התקנתו גם נותנת ל-Hermes את ערכת הנושא של Omarchy כ-skin בשם `omarchy`, שכל משטח של Hermes עוקב אחריו כשאתה מחליף ערכות נושא; בחר אחרת תחת הגדרות ה-Appearance של Hermes או עם `/skin` אם אתה מעדיף שלא, ו-Omarchy משאיר את הבחירה הזו לבדה. הסרת האפליקציה תחת _Remove > AI_ סוגרת תחילה את Hermes, כולל ה-gateway, לוקחת איתה את ה-runtime הזה, ושומרת את הצ'אטים, הזיכרונות וה-skills ש-Hermes כתב לעצמו אלא אם תגיד לו אחרת: הוא שואל, כברירת מחדל לא, האם גם הנתונים האלה והגדרות החיבור שלך צריכים להיעלם.

חוויית שולחן העבודה של OpenClaw היא ה-Control UI שלו, שנפתח כ-web app המגובה על ידי ה-gateway המקומי שלו עצמו. OpenClaw חי ב-`~/.openclaw` ומעדכן את עצמו: השתמש בכפתור "Update Gateway" של ה-Control UI או הרץ `openclaw update`, וה-gateway מופעל מחדש בגרסה החדשה. Omarchy בוחר רק את הגרסה שהתקנה טרייה מתחילה ממנה. הסרת OpenClaw תחת _Remove > AI_ לוקחת איתה את שירות ה-gateway ואת האפליקציה ואז שואלת האם גם `~/.openclaw` צריך להיעלם, מאחר שהוא מחזיק את הצ'אטים והאישורים שלך לצד OpenClaw עצמו ו-runtime-ים של plugins שהוא מוריד; ברירת המחדל שומרת אותו, והתקנת OpenClaw שוב תופסת אותו בחזרה.

Herdr Desktop היא אפליקציית שולחן העבודה [Herdr](https://herdr.dev): spaces, tabs ו-panes של טרמינלים וסוכני קידוד שממשיכים לרוץ ב-core שלו כשאתה סוגר את החלון. היא מגיעה מהמתקין של Herdr עצמו ולא מחבילה, כך שהיא חיה ב-`~/.local/share/herdr-app`, מביאה איתה את ה-core שלה ב-`~/.local/bin/herdr-core` כשאין לך אחד עדיין, ומעדכנת את עצמה ואותו. היא יושבת לצד פקודת `herdr` ש-Omarchy מספק ב-`Super + Ctrl + Return` ולא מחליפה אותה, ומקבלת את המקשים הישירים של אותה פקודה: `Alt + Return` ו-`Alt + Shift + Return` מפצלים pane למטה או ימינה, `Alt + Escape` סוגר אותו, `Ctrl + Alt + Arrow` עובר בין panes, `Alt + 1..9` ו-`Alt + Left/Right` בוחרים tab, ו-`Alt + Up/Down` עוברים בין spaces. `Ctrl + 1..9` בוחר space ו-`Alt + Shift + Up/Down` עובר בין סוכנים. מקשי הקידומת `Ctrl + Space` נשארים לטרמינל בלבד, מאחר שהאפליקציה לא יכולה להחזיק מקש Ctrl רגיל עבור רצף. Omarchy כותב את אלה ל-`~/.config/herdr-app/keys.json`, ו-`omarchy-refresh-herdr-app` מחזיר אותם. התקנתה בוחרת את ערכת הנושא Omarchy של Herdr, שעוקבת אחרי ערכת הנושא של Omarchy שלך מעתה ואילך. Herdr שומר ערכת נושא אחת למצב בהיר ואחת למצב כהה, כך שלאחר מעבר בין ערכת נושא כהה לבהירה של Omarchy, בחר Omarchy בבוחר ערכות הנושא של Herdr פעם נוספת עבור המצב האחר.

T3 Code רץ מגרסת ה-AppImage הרשמית שלו ב-`~/.local/share/t3code` ולא מחבילה, כך שהוא מעדכן את עצמו. התקנתו שואלת האם להתחיל בערוץ Stable או Nightly; החלף מאוחר יותר בהגדרות של T3 Code. ה-threads וההגדרות שלך חיים ב-`~/.t3`, והסרת T3 Code תחת _Remove > AI_ לוקחת אותם איתה.

### מודלים מקומיים

הרץ מודל פתוח על המכונה שלך עצמה עבור סוכני הקידוד שלך. ה-prompts והקוד שלך נשארים על המכונה; שום דבר שנשלח למודל לא עוזב אותה. התחל עם:

```bash
omarchy agent local use best
```

או, בפאנל הסוכנים בסרגל העליון, בחר + ואז Local AI, שמופיע כאשר מודל מתאים למכונה זו. בפעם הראשונה, זה מתקין את Podman, שמריץ את המודלים, ובמכונת NVIDIA את ערכת הכלים ל-container של NVIDIA, שנותנת להם את ה-GPU. Omarchy אז בוחרת את המודל המומלץ למכונה זו, מורידה אותו ומפעילה אותו. צפה להורדה של עשרות GB ולכך שרוב זיכרון המכונה יהיה בשימוש בזמן שהמודל רץ: Flash Next משתמש בכ-100 GiB עם הקשר ה-256K המלא שלו. אם מודלים אחרים מחזיקים בזיכרון שהוא צריך, הוא מוגדר כמופסק, מוכן להתחיל ברגע שתעצור אחד מהם. המודל עוצר בהתנתקות; עצור אותו בעצמך כאשר אתה צריך את הזיכרון למשהו אחר.

`omarchy agent local list` מציג את האפשרויות ומסביר מדוע חלקן לא מתאימות. כדי להגדיר אחד אחר, הרץ `omarchy agent local use <recipe>`. כיום, `qwen3.8-flash-next-gufo` ו-`qwen3.8-27b-gufo` זמינים למכונות Strix Halo של 128 GB; ה-27B לוקח כ-40 GiB, כך שהוא משאיר מקום לעבודה אחרת. במחשב נייד של 64 GB עם Arc B390 של Intel, `qwen3.6-35b-a3b-llamacpp` רץ בכ-30 GiB. recipes והמלצות חדשים מגיעים עם `omarchy update`, דרך החבילה.

כל מודל שאתה מגדיר מקבל שורה משלו בפאנל הסוכנים, לצד המנויים שלך: play כדי להפעיל אותו, pause כדי לעצור אותו ולשחרר את זיכרונו, וכפתור הטרמינל כדי לפתוח את הסוכן שלך עליו. כמה מהם יכולים לרוץ בו-זמנית כאשר הם מתאימים בזיכרון יחד; אם אחד לא מתאים, Omarchy אומר איזה מודל פועל לעצור. גרור שורות כדי לסדר אותן מחדש, ולחץ Delete על שורה נבחרת כדי להסיר מודל ואת ההורדה שלו.

כל מודל שאתה מגדיר מקבל גם ערך משלו ב-launcher האפליקציות, תחת שם המודל ועם הלוגו של יוצרו, כפי שהתחברות ל-Claude, Codex או Grok מוסיפה אחד. הוא פותח את הסוכן שלך על אותו מודל, ומפעיל את המודל תחילה אם הוא לא רץ: הטרמינל מציג אותו נטען ומעביר לסוכן ברגע שהוא עולה. הסרת מודל מסירה את הערך שלו.

מודל ממשיך לרוץ בדיוק כפי שהוגדר, כך שעדכון Omarchy אף פעם לא מפעיל מחדש אחד תחת הסוכנים שלך. כאשר ל-Omarchy יש runtime חדש יותר או משקלים חדשים יותר למודל שהגדרת, השורה שלו מציגה כפתור עדכון: לחץ עליו והמודל מוגדר שוב ברקע, כשהוא מוריד רק את מה שהשתנה, ומופעל מחדש בגרסה החדשה. מודל שהיה מופסק נשאר מופסק. `omarchy agent local update` עושה את אותו הדבר לכל מודל מטרמינל.

משורת הפקודה, `omarchy agent local start <recipe>` ו-`omarchy agent local stop <recipe>` עושים את אותו הדבר, `omarchy agent local status` מציג כל מודל, ו-`omarchy agent --local` פותח את סוכן ברירת המחדל שלך על המודל האחרון שהפעלת. pi, OpenCode ו-Qwen Code יכולים להשתמש באחד; עם כל ברירת מחדל אחרת הוא נפתח ב-pi. pi גם מפרט כל מודל שהגדרת, ואלה הנמצאים במכונות שחיברת אליהן, בבוחר המודלים שלו עצמו, כך שגם `pi` רגיל מגיע אליהם. כל client תואם OpenAI יכול להתחבר גם כן: `status` מציג את כתובתו של כל מודל (הראשון הוא `http://127.0.0.1:11435/v1`), שם ה-recipe הוא המודל, והמפתח נמצא ב-`~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` מוחק מודל ואת ההורדות שאף מודל אחר לא משתמש בהן.

runtime-ים של צד שלישי מסומנים עם המפרסם שלהם. Omarchy מריץ כל מודל ללא גישת רשת.

### LLM מקומיים

Omarchy ממליץ על שתי דרכים להריץ מודלי LLM מקומיים: LM Studio ו-Ollama. LM Studio מספק ממשק GUI למציאת מודלים במשקלים פתוחים, התקנתם והרצתם. זו דרך מעולה להתחיל בקלות. Ollama מציע CLI לעשות זאת באופן דומה. אבל אם אתה חדש במודלים מקומיים, הייתי מתחיל עם LM Studio. אתה יכול להתקין כל אחד מהם תחת _Install > AI_ בתפריט Omarchy.

### ה-Skill של Omarchy

skills של סוכנים עוזרים ל-AI להשתמש בכלים ספציפיים בדרך ספציפית, ו-Omarchy מגיע עם skill ברירת מחדל להתאמת המערכת. כמו לכוונן את תצורת Hyprland שלך, להתאים את הסרגל, או אפילו ליצור ערכת נושא חדשה מאפס. הוא מקושר בסמליות לתיקיות ה-skill עבור Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` וכל `~/.hermes/profiles/*/skills`), והמיקום הגנרי `~/.agents/skills`, כך שרוב ה-harnesses תופסים אותו אוטומטית.

אבל עליך להתייחס ל-skill הזה כניסיוני. מודלים שונים ישתמשו בו להשפעה שונה. הכי טוב לרוץ תחילה במצב plan, כדי שיהיה לך מושג מה הסוכן היה רוצה לשנות. ואז תהיה מוכן לשחזר שינויים או אפילו להפעיל `omarchy reinstall configs`, אם הסוכן עושה בלגן מהכל.
