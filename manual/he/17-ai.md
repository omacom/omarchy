# AI

Omarchy כוללת משגרים לסוכני הקידוד שלמטה מבלי לבחור עבורכם ברירת מחדל. הריצו פקודה כדי להתקין את ה-CLI שלה בשימוש הראשון, ולאחר מכן התחברו כשתתבקשו. Hermes הוא היוצא מן הכלל: שום דבר לא מותקן עבורו בשימוש הראשון, ובחירתו מתקינה את Hermes Desktop, כפי ש_אפליקציות שולחניות_ למטה מסביר.

### התקנה ועדכון של סוכנים

למעט Hermes, הסוכנים האלה משתמשים בהתקנה העצלה של mise: ההפעלה הראשונה מתקינה את ה-CLI, והפעלות מאוחרות יותר משתמשות בו שוב. mise גם בודק אם קיימת גרסה חדשה לסוכן מותקן לכל היותר אחת לארבע שעות, ממש לפני שהוא מתחיל או ברקע ב-prompt של ה-shell. אם העדכון הזה נכשל או שאתם לא מחוברים, הגרסה המותקנת רצה. `omarchy update` מעדכן סוכנים מותקנים עם שאר Omarchy, ו-`mup` מעדכן רק כלים המנוהלים על ידי mise.

המעדכן של סוכן עצמו, כגון `claude update`, `codex update` או כפתור עדכון באפליקציה, לא מעדכן את ההתקנה המנוהלת על ידי mise. `codex update` נכשל, ו-`claude update` יכול לדווח על הצלחה תוך התקנת עותק נפרד ש-mise לא עוקב אחריו. אם אתם מעדיפים להשתמש במתקין ובמעדכן המקוריים של סוכן, הוסיפו אותו ל-`disable_tools`; ראו [כלי CLI מותקנים מראש](18-development-tools.md#preinstalled-cli-tools).

כדי להתקין את כל הכלים העצלים המוגדרים לפני שתצטרכו אותם, הריצו `mise install --include-lazy`. זה כולל גם את כלי ה-CLI האחרים של Omarchy כברירת מחדל וגם את הסוכנים. ראו [כלי CLI מותקנים מראש](18-development-tools.md#preinstalled-cli-tools) להתקנת כלי בודד או לשימוש בהתקנה משלכם.

`grok` מותקן דרך חבילת `grok` הרשמית של mise, באותו אופן כמו `claude` ו-`codex`. הריצו `grok`, או בחרו אותו תחת _Setup > Defaults > Agent_. דלגו על מתקין ה-`curl | bash` שב-x.ai. הנתיב הזה שם עותק שני ב-`~/.grok/bin`, שם אותו בתחילת `PATH`, ודורס את ה-wrapper של Omarchy.

`dsh` פותח את ממשק הדפדפן שלו ב-`127.0.0.1:3080`, כאשר תיקיית ההפעלה היא סביבת העבודה ברירת המחדל שלו. ממשק הדפדפן שלו לא מקבל prompt התחלתי, כך ש-`omarchy agent prompt` פותח אותו עם ה-prompt בלוח שלכם להדבקה. Omarchy מפעילה אותו עם הגדרת ההרשאות no-approval של DeepSeek. DeepSeek Harness מעלה יומני session ל-DeepSeek כאשר אתם משתמשים ב-API הרשמי שלו למודלים; כבו זאת תחת _Settings > General > Upload Session Log_ בממשק הדפדפן שלו. גם משוב שתשלחו לו מועלה עם ה-session, אלא אם תפעילו אותו עם `DSH_TELEMETRY_MODE=DISABLED`.

### הסוכן ברירת המחדל

בחרו את סוכן ברירת המחדל שלכם עם `omarchy default agent <name>` או תחת _Setup > Defaults > Agent_ בתפריט Omarchy (`Super + Space`). אם הסוכן עדיין לא מותקן, בחירתו תתקין אותו תחילה. Omarchy טרייה תזמין אתכם לעשות את הבחירה הזאת בהתראה חד-פעמית.

בחירת Claude גם מנסה להגדיר את תוסף הדפדפן שלו עבור Chromium, Chrome, Brave, Brave Origin ו-Edge. הגדרת התוסף חלה על כל המשתמשים ועשויה לבקש את סיסמת המערכת שלכם; ביטול או התקנת תוסף שנכשלה עדיין בוחרים ומפעילים את Claude. הפעילו מחדש את הדפדפן, הפעילו את התוסף אם תתבקשו, והתחברו ל-Claude כדי לסיים לחבר אותו. הריצו `/chrome` ב-Claude כדי לבדוק את החיבור. Firefox ו-Zen לא תומכים בתוסף הזה. אם Claude כבר היה ברירת המחדל שלכם לפני שההגדרה הזאת נוספה, בחרו אותו שוב כדי להתקין את התוסף.

לאחר שבחרתם, `Super + Shift + Ctrl + A` מפעיל את סוכן ברירת המחדל בחלון טרמינל ייעודי (או מעלה את הבוחר אם עדיין לא בחרתם). אתם יכולים גם להפעיל אותו ישירות למשימה עם `omarchy agent prompt "Review this project"`. Freebuff ו-DeepSeek Harness לא מקבלים prompt התחלתי, כך שהם נפתחים עם ה-prompt בלוח שלכם להדבקה במקום זאת. סוכנים שמופעלים כך רצים ללא פיקוח במצבי אל-תעצור-לשאול הייחודיים לכל אחד מהם, אז תהיו מוכנים לכך שהם בעצם יעשו דברים! ל-MiniMax Code אין מצב כזה ל-sessions האינטראקטיביים שלו, כך שהוא מבקש הרשאות כרגיל. ומכיוון שסוכנים מסרבים לזכור אמון עבור תיקיית הבית שלכם, הפעלות מ-`$HOME` מתחילות ב-`~/Work` במקום זאת.

יש גם קיצורי טרמינל: `a` מריץ את סוכן ברירת המחדל inline בטרמינל הנוכחי, בעוד `c`, `cx` ו-`cy` מפעילים את OpenCode, Claude Code ו-Codex ישירות (שוב במצבי האישור האוטומטי שלהם). גם שינויי ערכת נושא מסתנכרנים לסוכנים: Claude Code, Pi, OpenCode ו-Hermes (לאחר ש-Omarchy התקינה אותו) כולם עוקבים כשאתם מחליפים את ערכת הנושא של Omarchy.

### פאנל הסוכנים

בשורה העליונה יש אייקון סוכנים. לפני שהגדרתם סוכן, הפאנל שלו מלווה אתכם בהתחברות ל-Claude, Codex או Grok, והראשון הופך לסוכן ברירת המחדל שלכם. לאחר מכן, הפאנל שם כל מנוי בעמוד אחד: כל סוכן וחשבון עם התוכנית שלו, מד לכל אחת ממגבלות ה-session של 5 שעות והמגבלות השבועיות שלו עם הזמן עד לאיפוס (רחפו לקבלת האחוז המדויק), או היתרה הנותרת ששולמה מראש, מתחת לשורה שמסתובבת בין מה שהשתמשתם בו בכל אלה, כמו tokens השבוע והמודל שבו השתמשתם הכי הרבה. תחת _Make something_ הוא מציע prompts התחלתיים לערכת נושא, plugin או אפליקציה חדשים שמעבירים את המשימה לסוכן ברירת המחדל שלכם. אפליקציות נבנות כפי שבנויות האפליקציות של Omarchy עצמה, Hype, Monologue ו-Omacut, ב-C++ וב-Qt Quick, לפי ה-agent skill בשם omarchy-app, והקומפיילר וחלקי Qt שהן צריכות מגיעים מותקנים. Claude Code, Codex, Grok, Kimi, Cursor ומכסת Grok Bot שלו, GitHub Copilot, Muse, Antigravity, Kimchi ו-Devin מכוסים מהקופסה עם המגבלות שלהם, ו-Hermes, Mistral Vibe ו-Qwen Code מציגים את ה-sessions וה-tokens שלהם לאחר שהשתמשתם בהם. גם תוכניות ומפתחות של ספקים שאתם משתמשים בהם דרך pi, omp או opencode מופיעים: OpenCode Zen ו-Go, ה-Z.ai GLM Coding Plan, Ollama Cloud, ה-MiniMax Token Plan ו-Synthetic עם המגבלות שלהם; Fireworks, OpenRouter ו-DeepSeek עם היתרות ששולמו מראש שלהן; והמודלים שאתם מריצים על החומרה שלכם תחת Local models. כל סוכן נספר פעם אחת, תחת מי שמחייב עליו, לא משנה דרך כמה harnesses אתם מפעילים אותו.

לחיצה שמאלית על אייקון השורה לפאנל, לחיצה ימנית להפעלת סוכן ברירת המחדל שלכם. רשומות השימוש שמאחוריו מתחדשות כל 15 דקות על ידי `omarchy agent usage-update`, והפאנל אפילו יכול למזג שימוש מהמכונות האחרות שלכם דרך תיקייה מסונכרנת. ראו את ה-README תחת `$OMARCHY_PATH/shell/plugins/agents/` להגדרות המלאות.

### כמה מנויים

אם אתם משלמים על יותר מתוכנית Claude, Codex או Grok אחת — Max אישי ואחד לעבודה, נגיד — Omarchy יכולה להשאיר את כולם מחוברים ולעבור ביניהם. הוסיפו מנוי עם ה-+ בפאנל הסוכנים, שמלווה אתכם שם ממש, או עם `omarchy agent account add claude Work` (או `codex`, או `grok`). הוא מתקין את ה-CLI אם הוא חסר. החשבון הראשון עבור ספק מתחבר דרך הדפדפן הרגיל שלכם, בדיוק במקום שבו ה-CLI תמיד מחפש. כל אחד אחריו מתחבר דרך חלון פרטי, כך שהחשבון שהדפדפן שלכם כבר מחובר אליו לא יילקח בטעות; התחברו שם כחשבון שאתם מוסיפים, וסגרו קודם כל חלון פרטי שכבר פתוח. לעולם אל תתנתקו מה-CLI כדי לעשות זאת: התנתקות מבטלת את ההתחברות השמורה, והחשבון הזה יצטרך להתווסף שוב.

כדי להעתיק את התחברויות המנוי שלכם למכונת Omarchy אחרת דרך SSH, הריצו `omarchy agent account copy user@laptop`. השולח מספק מקלט זמני כאשר ליעד אין אחד מותקן, כך שמכונות Omarchy ישנות יותר יכולות לקבל חשבונות ללא עדכון. מקלטים מותקנים מקבלים עדיפות. זה מעתיק את כל מנויי Claude, Codex ו-Grok; הוסיפו שמות ספקים כדי לבחור אותם, כמו ב-`omarchy agent account copy laptop claude`. שמות חשבונות ומזהי פקודות תואמים למקור, כולל חשבונות שכבר קיימים ביעד. חשבונות יעד לא קשורים מקבלים סיומת מספרית אם השמות שלהם מתנגשים, והגדרות, skills, plugins והיסטוריית שיחות נשארים מקומיים לכל מכונה.

אישורי יעד קיימים נשמרים. חשבון מקור שכבר מחובר שם מקבל סנכרון של שמו מבלי שיחליפו את האישורים שלו; חשבונות אחרים מתווספים לצידו. כדי להחליף אישורים שמורים לחשבונות תואמים, השתמשו ב-`omarchy agent account copy --replace laptop claude` לאחר שיצאתם מה-sessions של החשבון הזה ביעד. יעד טרי גם מקבל את החשבון הפעיל והעדפות ההחלפה של המקור; יעד מבוסס שומר את שלו.

אישורים עוברים דרך SSH ומאוחסנים בקבצים פרטיים ביעד, אז העתיקו רק למכונות שאתם סומכים עליהן. זו העתקה חד-פעמית, לא סנכרון מתמשך. Refresh tokens של Codex יכולים להיות מוחלפים על ידי מכונה אחרת, מה שמשאיר התחברות מועתקת כזקוקה לחידוש; התחברויות נפרדות נשארות הבחירה האמינה ביותר לשימוש בו-זמני בכמה מכונות. ראו [הנחיות אימות החשבון של Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

חשבון אחד לכל ספק פעיל, וכל session חדש מתחיל כמוהו: `cx`, `cy`, `claude`, `codex` או `grok` פשוטים, כל דבר שמופעל דרך `omarchy agent`, ו-scripts או עורכים שמוצאים את ה-CLI ב-`PATH`. החליפו עם `omarchy agent account use work` (וחזרה עם `omarchy agent account use main`), או בפאנל על ידי לחיצה על מספר חשבון ולאחר מכן `Enter` (או לחיצה על כפתור Use שלו). Sessions שכבר רצים נשארים בחשבון שבו התחילו. היסטוריית שיחות, הגדרות, skills ו-plugins משותפים בין חשבונות, כך ש-`claude --continue` באותה תיקייה ממשיך איפה שהפסקתם בחשבון החדש.

עם יותר מחשבון אחד, הפאנל מציג את מגבלות כל חשבון זו לצד זו, כאשר הפעיל מסומן. כברירת מחדל Omarchy מתריעה לכם כאשר החשבון הפעיל עובר 95% ממגבלה, ולחיצה על ההתראה מחליפה לחשבון עם הכי הרבה מרווח. רחפו מעל שורת חשבון בפאנל ולחצו על Autoswitch שמופיע לצד Use (או לחצו `m`), או הריצו `omarchy agent account mode auto`, כדי שהוא יחליף בעצמו במקום זאת; בזמן שהוא פעיל, Autoswitch תופס את מקום Use, ולחיצה נוספת עליו חוזרת להתריע. הוסיפו מספר כדי לשנות את הסף, כמו ב-`omarchy agent account mode auto 90`. אם כל חשבון מעל הסף, תשמעו על כך פעם אחת, יחד עם איזה חשבון מתפנה קודם. בזמן שחשבון פעיל נמצא בתוך 15 נקודות מהסף שלו (80% בברירת המחדל), המגבלות שלו נבדקות כל שלוש דקות ולא כל 15.

`omarchy agent account list` מציג כל חשבון ואת המגבלות האחרונות שלו, `omarchy agent account remove work` שוכח אחד, ו-`omarchy agent account rename primary Hey` משנה שם של אחד (או לחצו על שם חשבון בפאנל). הפקודות האלה עובדות על החשבונות של סוכן ברירת המחדל שלכם; כדי להגיע לספק האחר, ציינו אותו תחילה, כמו ב-`omarchy agent account use codex side`. ההתחברות שכבר היתה לכם ב-`~/.claude` או ב-`~/.codex` היא חשבון ה-_Main_ והיא נשארת היכן שהיא. חשבון שלא היה בשימוש יותר מכשמונה שעות יכול להציג _Sign-in required_; לחצו עליו כדי להתחבר שוב לחשבון ההוא ממש בפאנל, או התחילו session בו, שמרענן את ההתחברות מעצמו. שרתי MCP שהיו לכם כאשר חשבון נוסף מגיעים איתו אליו, אבל אלה שתוסיפו מאוחר יותר עם `claude mcp add` מגיעים רק לחשבון שבו הוספתם אותם. Claude Desktop וכלים שהוגדרו עם נתיב מוחלט לקובץ בינארי של CLI לא עוקבים אחר ההחלפה. `CLAUDE_CONFIG_DIR`, `CODEX_HOME` או `GROK_HOME` מפורשים מקבלים עדיפות על החשבון שנבחר.

### אבחון קריסות

Omarchy עוקבת אחר systemd-coredump לקריסות תהליכים. כאשר משהו עושה segfault, תקבלו התראת "Process crashed" — לחצו עליה, והקריסה מועברת לסוכן ברירת המחדל שלכם יחד עם ה-skill בשם diagnose-crash של Omarchy, שמלווה את הסוכן בביסוס העובדות מה-core dump ובהחלטה האם הקריסה שווה דיווח ל-upstream. אתם יכולים גם להריץ אותו ידנית מול כל PID מ-`coredumpctl list` עם `omarchy agent crash <pid>`.

המעקב פעיל כברירת מחדל. כבו אותו תחת _Trigger > Toggle > Crash Capture_ (או עם `omarchy toggle crash-capture`) וההתראות מפסיקות; `omarchy agent crash <pid>` עדיין עובד ידנית.

אפשר גם להשתיק קריסות תוכנית אחר תוכנית, וזה מה שהאבחון מציע לכם בסוף. `omarchy crash mute hyprland` עוצר את ההתראות עבור התוכנית ההיא בלבד, `omarchy crash mute hyprland off` מחזיר אותן, ו-`omarchy crash mute` לבדו מציג מה השתקתם. הוא מקבל נתיב של קובץ בינארי בשמחה כמו את שמו, כך ש-`omarchy crash mute /usr/bin/hyprland` עושה אותו דבר. צטטו שם עם רווח בתוכו, כמו ב-`omarchy crash mute 'Some App'`. כל השאר עדיין מתריע, והתוכנית המושתקת עדיין קורסת — זה מסתיר את התזכורת, זה לא מתקן כלום.

### אפליקציות שולחניות

תפריט _Install > AI_ נושא גם כמה אפליקציות AI גרפיות: אפליקציית ChatGPT לשולחן העבודה, אפליקציית Claude לשולחן העבודה (בטא ה-Linux של Anthropic, עם לשוניות Chat, Cowork ו-Claude Code), Grok Bot לשיחה עם המודלים של xAI, Hermes Desktop, OpenClaw, אפליקציית Perplexity לשולחן העבודה ו-T3 Code. Grok Bot היא אפליקציית הצ'אט לשולחן העבודה. סוכן הקידוד הוא פקודת `grok`.

Hermes Desktop היא זו שצריך להכיר, כי למכונה יש Hermes אחד, והוא של האפליקציה: Hermes מותקן רק אי-פעם דרך האפליקציה, ופקודת `hermes` שסוכן ברירת המחדל מריץ היא של האפליקציה. בחירת Hermes כסוכן ברירת המחדל מתקינה אותו דבר שערך _Install > AI_ מתקין: את החבילה, ו-runtime של Hermes תחת `~/.hermes` שמוגדר על ידי המתקין של Hermes עצמו, שלוקח כמה דקות בפעם הראשונה. ה-runtime הזה הוא ה-Hermes האחד שפקודת הטרמינל `hermes`, סוכן ברירת המחדל והאפליקציה כולם משתמשים בו, והוא מעדכן את עצמו עם `hermes update` ולא ממתין לגרסה של Omarchy. התקנתו גם מעבירה ל-Hermes את ערכת הנושא של Omarchy כ-skin בשם `omarchy`, שכל משטח של Hermes עוקב אחריו כשאתם מחליפים ערכות נושא; בחרו אחר תחת הגדרות Appearance של Hermes או עם `/skin` אם אתם מעדיפים שלא, ו-Omarchy עוזבת את הבחירה הזאת בשקט. הסרת האפליקציה תחת _Remove > AI_ סוגרת את Hermes תחילה, כולל ה-gateway, לוקחת איתה את ה-runtime הזה, ושומרת את הצ'אטים, הזיכרונות וה-skills ש-Hermes כתב לעצמו אלא אם תאמרו לה אחרת: היא שואלת, כשברירת המחדל היא לא, האם גם הנתונים האלה והגדרות החיבור שלכם צריכים ללכת.

חוויית שולחן העבודה של OpenClaw היא ה-Control UI שלו, שנפתח כאפליקציית web המגובה ב-gateway מקומי משלו. OpenClaw חי ב-`~/.openclaw` ומעדכן את עצמו: השתמשו בכפתור "Update Gateway" של ה-Control UI או הריצו `openclaw update`, וה-gateway מתחיל מחדש בגרסה החדשה. Omarchy רק בוחרת את הגרסה שהתקנה טרייה מתחילה ממנה. הסרת OpenClaw תחת _Remove > AI_ לוקחת איתה את שירות ה-gateway והאפליקציה ואז שואלת האם גם `~/.openclaw` צריך ללכת, שכן הוא מחזיק את הצ'אטים והאישורים שלכם לצד OpenClaw עצמו וה-runtimes של ה-plugins שהוא מוריד; ברירת המחדל שומרת אותו, והתקנת OpenClaw שוב אוספת אותו בחזרה.

T3 Code רץ מה-AppImage הרשמי שלו ב-`~/.local/share/t3code` ולא מחבילה, כך שהוא מעדכן את עצמו. התקנתו שואלת האם להתחיל בערוץ Stable או Nightly; החליפו מאוחר יותר בהגדרות של T3 Code. ה-threads וההגדרות שלכם חיים ב-`~/.t3`, והסרת T3 Code תחת _Remove > AI_ לוקחת אותם איתו.

### מודלים מקומיים

הריצו מודל פתוח על המכונה שלכם עבור סוכני הקידוד שלכם. ה-prompts והקוד שלכם נשארים על המכונה; שום דבר שנשלח למודל לא יוצא ממנה. התחילו עם:

```bash
omarchy agent local use best
```

או, בפאנל הסוכנים בשורה העליונה, בחרו + ולאחר מכן Local AI, שמופיע כאשר מודל מתאים למכונה הזו. בפעם הראשונה, זה מתקין את Podman, שמריץ את המודלים. Omarchy אז בוחרת את המודל המומלץ למכונה הזו, מורידה אותו ומפעילה אותו. צפו להורדה של עשרות GB ולכך שרוב זיכרון המכונה יהיה בשימוש בזמן שהמודל רץ: Flash Next משתמש בכ-100 GiB עם הקשר ה-256K המלא שלו. אם מודלים אחרים תופסים את הזיכרון שהוא צריך, הוא מוגדר כמופסק, מוכן להתחיל ברגע שתעצרו אחד. המודל עוצר בהתנתקות; עצרו אותו בעצמכם כשאתם צריכים את הזיכרון למשהו אחר.

`omarchy agent local list` מציג את האפשרויות ומסביר מדוע חלק לא מתאימים. כדי להגדיר עוד אחד, הריצו `omarchy agent local use <recipe>`. כיום, `qwen3.8-flash-next-halogen` ו-`qwen3.8-27b-gufo` זמינים למכונות Strix Halo בנפח 128 GB. recipes והמלצות חדשים מגיעים עם `omarchy update`, דרך החבילה.

כל מודל שאתם מגדירים מקבל שורה משלו בפאנל הסוכנים, לצד המנויים שלכם: play כדי להפעיל אותו, pause כדי לעצור אותו ולשחרר את הזיכרון שלו, וכפתור הטרמינל כדי לפתוח את הסוכן שלכם עליו. כמה יכולים לרוץ בבת אחת כאשר הם מתאימים בזיכרון יחד; אם אחד לא מתאים, Omarchy אומרת איזה מודל רץ לעצור. גררו שורות כדי לסדר אותן מחדש, ולחצו Delete על שורה נבחרת כדי להסיר מודל וההורדה שלו.

משורת הפקודה, `omarchy agent local start <recipe>` ו-`omarchy agent local stop <recipe>` עושים אותו דבר, `omarchy agent local status` מציג כל מודל, ו-`omarchy agent --local` פותח את סוכן ברירת המחדל שלכם על המודל האחרון שהפעלתם (pi אם סוכן ברירת המחדל שלכם לא יכול להשתמש במודל מקומי). כל לקוח תואם OpenAI יכול להתחבר גם: `status` מציג את כתובת כל מודל (הראשון הוא `http://127.0.0.1:11435/v1`), שם ה-recipe הוא המודל, והמפתח נמצא ב-`~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` מוחק מודל ואת ההורדות שאף מודל אחר לא משתמש בהן.

runtimes של צד שלישי מתויגים עם המפיץ שלהם. Omarchy מריצה כל מודל ללא גישה לרשת.

### מודלי LLM מקומיים

Omarchy ממליצה על שתי דרכים להריץ מודלי LLM מקומיים: LM Studio ו-Ollama. LM Studio מספק ממשק GUI למציאת מודלים במשקל פתוח, התקנתם והרצתם. זו דרך מעולה להתחיל בקלות. Ollama מציע CLI לעשות זאת באופן דומה. אבל אם אתם חדשים למודלים מקומיים, הייתי מתחיל עם LM Studio. אתם יכולים להתקין כל אחד מהם תחת _Install > AI_ בתפריט Omarchy.

### ה-Skill של Omarchy

skills של סוכנים עוזרים ל-AI להשתמש בכלים ספציפיים בדרך ספציפית, ו-Omarchy מגיעה עם skill ברירת מחדל להתאמת המערכת. כמו לכוון את הקונפיג של Hyprland שלכם, להתאים את השורה, או אפילו ליצור ערכת נושא חדשה מאפס. הוא מקושר באמצעות symlink לתיקיות ה-skills עבור Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` וכל `~/.hermes/profiles/*/skills`), והמיקום הגנרי `~/.agents/skills`, כך שרוב ה-harnesses קולטים אותו אוטומטית.

אבל עליכם להתייחס ל-skill הזה כניסיוני. מודלים שונים ישתמשו בו ביעילות שונה. הכי טוב להריץ במצב plan תחילה, כך שיהיה לכם מושג מה הסוכן היה רוצה לשנות. ואז להיות מוכנים לבטל שינויים או אפילו להפעיל `omarchy reinstall configs`, אם הסוכן עושה בלאגן מהכל.
