# AI

Omarchy כוללת משגרים לסוכני הקידוד שלמטה מבלי לבחור עבורך ברירת מחדל. הרץ פקודה כדי להתקין את ה-CLI שלה בשימוש הראשון, ולאחר מכן בצע אימות כשתתבקש. Hermes ו-OpenClaw הם היוצאים מן הכלל: שום דבר לא מותקן עבורם דרך mise, ובחירה בכל אחד מהם מתקינה עותק משלו שמעדכן את עצמו, כפי שמסביר הסעיף _אפליקציות שולחניות_ שלמטה.

### התקנה ועדכון של סוכנים

למעט Hermes ו-OpenClaw, הסוכנים האלה משתמשים בהתקנה העצלה של mise: ההפעלה הראשונה מתקינה את ה-CLI, והפעלות מאוחרות יותר משתמשות בו שוב. mise גם בודק אם קיימת גרסה חדשה לסוכן מותקן לכל היותר אחת לארבע שעות, ממש לפני שהוא מופעל או ברקע בהנחיית מעטפת. אם העדכון הזה נכשל או שאתה לא מחובר, הגרסה המותקנת רצה. `omarchy update` מעדכן סוכנים מותקנים יחד עם שאר Omarchy, ו-`mup` מעדכן רק כלים המנוהלים על ידי mise.

מעדכן עצמאי של סוכן, כגון `claude update`, `codex update`, או כפתור עדכון באפליקציה, אינו מעדכן את ההתקנה המנוהלת על ידי mise. `codex update` נכשל, ו-`claude update` יכול לדווח על הצלחה תוך התקנת עותק נפרד ש-mise אינו עוקב אחריו. אם אתה מעדיף להשתמש במתקין ובמעדכן המקוריים של סוכן, הוסף אותו ל-`disable_tools`; ראה [כלים CLI מותקנים מראש](18-development-tools.md#preinstalled-cli-tools).

כדי להתקין את כל הכלים העצלים המוגדרים לפני שתצטרך אותם, הרץ `mise install --include-lazy`. זה כולל גם את כלי ה-CLI האחרים של ברירת המחדל של Omarchy וגם את הסוכנים. ראה [כלים CLI מותקנים מראש](18-development-tools.md#preinstalled-cli-tools) להתקנת כלי יחיד או לשימוש בהתקנה שלך.

`grok` מותקן דרך חבילת ה-`grok` הרשמית של mise, באותו אופן כמו `claude` ו-`codex`. הרץ `grok`, או בחר אותו תחת _סוכן > Harness_. דלג על מתקין ה-`curl | bash` ב-x.ai. נתיב זה מציב עותק שני ב-`~/.grok/bin`, מקדים אותו ב-`PATH`, ודורס את העוטף של Omarchy.

`dsh` פותח את ממשק הדפדפן שלו ב-`127.0.0.1:3080`, כאשר ספריית ההפעלה היא סביבת העבודה המוגדרת כברירת מחדל שלו. ממשק הדפדפן שלו אינו מקבל הנחיית פתיחה, ולכן `omarchy agent prompt` פותח אותו כשההנחיה על הלוח שלך להדבקה. Omarchy מפעילה אותו עם הגדרת ההרשאות ללא אישור של DeepSeek. DeepSeek Harness מעלה יומני הפעלה ל-DeepSeek כשאתה משתמש ב-API הרשמי של המודלים שלה; כבה זאת תחת _הגדרות > כללי > Upload Session Log_ בממשק הדפדפן שלו. משוב שאתה שולח לה מועלה גם הוא עם ההפעלה, אלא אם תפעיל אותה עם `DSH_TELEMETRY_MODE=DISABLED`.

### ברירת המחדל של הסוכן

בחר את סוכן ברירת המחדל שלך עם `omarchy default agent <name>` או תחת _סוכן > Harness_ בתפריט Omarchy (`Super + Space`). אם הסוכן עדיין לא מותקן, בחירתו מתקינה אותו תחילה, והוא מקבל גם משגר משלו במשגר היישומים, לצד Agent. Omarchy טרייה תזמין אותך לבצע בחירה זו עם הודעה חד-פעמית.

בחירה ב-Claude מנסה גם להגדיר את תוסף הדפדפן שלו עבור Chromium, Chrome, Brave, Brave Origin, ו-Edge. הגדרת התוסף חלה על כל המשתמשים ועלולה לבקש את סיסמת המערכת שלך; ביטול או כשל בהתקנת התוסף עדיין בוחרים ומפעילים את Claude. הפעל מחדש את הדפדפן, אפשר את התוסף אם תתבקש, והיכנס ל-Claude כדי לסיים לחבר אותו. הרץ `/chrome` ב-Claude כדי לבדוק את החיבור. Firefox ו-Zen אינם תומכים בתוסף זה. אם Claude כבר היה ברירת המחדל שלך לפני שהגדרה זו נוספה, בחר אותו שוב כדי להתקין את התוסף.

לאחר שבחרת, `Super + Shift + Ctrl + A` מפעיל את סוכן ברירת המחדל בחלון טרמינל ייעודי (או מציג את הבורר אם עדיין לא בחרת). ניתן גם להפעיל אותו ישירות למשימה עם `omarchy agent prompt "Review this project"`. Freebuff ו-DeepSeek Harness אינם מקבלים הנחיית פתיחה, ולכן הם נפתחים כשההנחיה על הלוח שלך להדבקה במקום זאת. סוכנים המופעלים כך רצים ללא פיקוח במצבי אל-תעצור-לשאול שלהם, אז היה מוכן שהם באמת יעשו דברים! ל-MiniMax Code אין מצב כזה להפעלות האינטראקטיביות שלו, ולכן הוא מבקש הרשאות כרגיל. ומאחר שסוכנים מסרבים לזכור אמון עבור ספריית הבית שלך, הפעלות מ-`$HOME` מתחילות ב-`~/Work` במקום זאת.

יש גם קיצורי טרמינל: `a` מריץ את סוכן ברירת המחדל בתוך הטרמינל הנוכחי, בעוד `c`, `cx`, ו-`cy` מפעילים את OpenCode, Claude Code, ו-Codex ישירות (שוב במצבי האישור האוטומטי שלהם). שינויי ערכת נושא מסתנכרנים גם לסוכנים: Claude Code, Pi, OpenCode, ו-Hermes (לאחר ש-Omarchy התקינה אותו) כולם מצטרפים כשאתה מחליף את ערכת הנושא של Omarchy.

### הוראות הסוכן שלך

כללים אישיים לכל סוכן שייכים ל-`~/.agents/AGENTS.md`, לצד הכישורים המשותפים ב-`~/.agents/skills`. פתח אותו תחת _סוכן > הוראות_, מה שגם מקשר אותו לכל harness ששומר קובץ גלובלי משלו: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, ה-`~/.copilot/copilot-instructions.md` של Copilot, וכן הלאה. Crush ו-Amp קוראים את הקישור `~/.config/AGENTS.md`, בעוד omp, Kimi, ו-DeepSeek Harness קוראים ישירות את `~/.agents/AGENTS.md`. בחירת סוכן ברירת מחדל מקשרת אותו גם כן. קובץ הוראות שכבר היה לך הופך למשותף אם עדיין לא היה כזה; אחרת הוא נשמר לצד הקישור כ-`.bak`. הרץ `omarchy agent instructions` כדי לקשר מחדש לאחר התקנת סוכן נוסף.

### פאנל הסוכנים

בסרגל העליון יש אייקון סוכנים. לפני שהגדרת סוכן, הפאנל שלו מדריך אותך בכניסה ל-Claude, Codex, או Grok, והראשון הופך לסוכן ברירת המחדל שלך. לאחר מכן, הפאנל מציב כל מנוי בעמוד אחד: כל סוכן וחשבון עם התוכנית שלו, מד לכל אחת ממגבלות ההפעלה של 5 שעות והמגבלות השבועיות שלו עם הזמן עד לאיפוס (רחף לקבלת האחוז המדויק), או יתרת התשלום מראש שנותרה, תחת שורה שמסתובבת בין מה שהשתמשת בו בכולם, כמו טוקנים השבוע והמודל שהשתמשת בו הכי הרבה. תחת _צור משהו מגניב_ הוא מציע הנחיות פתיחה לערכת נושא, תוסף, אפליקציה, או משחק חדשים שמוסרים את המשימה לסוכן ברירת המחדל שלך. אפליקציות נבנות באותו אופן שבו נבנות Hype, Monologue, ו-Omacut של Omarchy עצמה, ב-C++ וב-Qt Quick, בעקבות כישור הסוכן omarchy-make-app, והמהדר וחלקי ה-Qt שהם צריכים מגיעים מותקנים. משחקים הם עמוד three.js יחיד ב-`~/Games/vibes`, בעקבות כישור הסוכן omarchy-make-game, וכולם נפתחים ממשגר Game Vibes אחד בערכת הנושא הנוכחית; הם טוענים את three.js מהרשת, ולכן הם צריכים חיבור כדי להתחיל. Claude Code, Codex, Grok, Kimi, Cursor והקצבת ה-Grok Bot שלו, GitHub Copilot, Muse, Antigravity, ו-Devin מכוסים מהקופסה עם המגבלות שלהם, Kimchi עם התוכנית שלה, קרדיטים בתשלום מראש, ותקציבי הוצאה, ו-Hermes, Mistral Vibe, ו-Qwen Code מציגים את ההפעלות והטוקנים שלהם לאחר שהשתמשת בהם. תוכניות ומפתחות ספקים שאתה משתמש בהם דרך pi, omp, או opencode מופיעים גם כן: OpenCode Zen ו-Go, תוכנית ה-GLM Coding Plan של Z.ai, Ollama Cloud, תוכנית ה-Token Plan של MiniMax, ו-Synthetic עם המגבלות שלהם; OpenRouter ו-DeepSeek עם יתרות התשלום מראש שלהם; Fireworks עם ההוצאה שלה ב-30 הימים האחרונים. טוקנים ממודלים שאתה מריץ על החומרה שלך נספרים גם הם בסכומים; למודלים עצמם יש פאנל משלהם, המתואר תחת [מודלים מקומיים](#local-models). כל סוכן נספר פעם אחת, תחת מי שמחייב אותו, לא משנה כמה harnesses אתה מניע אותו דרכם.

לחץ לחיצה שמאלית על אייקון הסרגל או לחץ `Super + Ctrl + X` לפאנל, לחיצה ימנית להפעלת סוכן ברירת המחדל שלך, ולחיצה אמצעית לריענון. רשומות השימוש שמאחוריו נוצרות מחדש כל 15 דקות על ידי `omarchy agent usage update`, והפאנל יכול אפילו למזג שימוש ממכונות אחרות שלך דרך תיקייה מסונכרנת. עיין ב-README תחת `$OMARCHY_PATH/shell/plugins/agents/` להגדרות המלאות.

### מספר מנויים

אם אתה משלם עבור יותר מתוכנית Claude, Codex, או Grok אחת — תוכנית Max אישית ואחת לעבודה, נניח — Omarchy יכולה להשאיר את כולן מחוברות ולעבור ביניהן. הוסף מנוי עם ה-+ בפאנל הסוכנים, שידריך אותך שם, או עם `omarchy agent account add claude Work` (או `codex`, או `grok`). זה מתקין את ה-CLI אם הוא חסר. החשבון הראשון לספק נכנס דרך הדפדפן הרגיל שלך, בדיוק היכן שה-CLI תמיד מחפש. כל אחד לאחר מכן נכנס דרך חלון פרטי, כך שהחשבון שהדפדפן שלך כבר מחובר אליו לא ייבחר בטעות; היכנס שם כחשבון שאתה מוסיף, וסגור תחילה כל חלון פרטי שכבר פתוח. לעולם אל תצא מה-CLI כדי לעשות זאת: יציאה מבטלת את הכניסה השמורה, וחשבון זה יצטרך להתווסף שוב.

כדי להעתיק את כניסות המנוי שלך למכונת Omarchy אחרת דרך SSH, הרץ `omarchy agent account copy user@laptop`. השולח מספק מקלט זמני כאשר ליעד אין אחד מותקן, כך שמכונות Omarchy ישנות יותר יכולות לקבל חשבונות ללא עדכון. מקלטים מותקנים מקבלים עדיפות. זה מעתיק את כל מנויי Claude, Codex, ו-Grok; הוסף שמות ספקים כדי לבחור אותם, כמו ב-`omarchy agent account copy laptop claude`. שמות חשבונות ומזהי פקודות תואמים למקור, כולל חשבונות שכבר קיימים ביעד. חשבונות יעד לא קשורים מקבלים סיומת מספרית אם שמותיהם מתנגשים, והגדרות, כישורים, תוספים, והיסטוריית שיחות נשארים מקומיים לכל מכונה.

אישורי יעד קיימים נשמרים. חשבון מקור שכבר מחובר שם שמו מסונכרן מבלי להחליף את אישוריו; חשבונות אחרים מתווספים לצידו. כדי להחליף אישורים שמורים לחשבונות תואמים, השתמש ב-`omarchy agent account copy --replace laptop claude` לאחר סגירת ההפעלות של חשבון זה ביעד. יעד טרי מקבל גם את החשבון הפעיל והעדפות ההחלפה של המקור; יעד מבוסס שומר את שלו.

אישורים עוברים דרך SSH ונשמרים בקבצים פרטיים ביעד, אז העתק רק למכונות שאתה בוטח בהן. זו העתקה חד-פעמית, לא סנכרון מתמשך. אסימוני רענון של Codex יכולים להיות מוחלפים על ידי מכונה אחרת, מה שמשאיר כניסה מועתקת הזקוקה לחידוש; כניסות נפרדות נשארות הבחירה האמינה ביותר לשימוש בו-זמני במספר מכונות. ראה [הנחיות אימות חשבון של Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

חשבון אחד לכל ספק פעיל, וכל הפעלה חדשה מתחילה כמותו: `cx`, `cy`, `claude`, `codex`, או `grok` רגילים, כל דבר המופעל דרך `omarchy agent`, וסקריפטים או עורכים שמוצאים את ה-CLI ב-`PATH`. החלף עם `omarchy agent account use work` (ובחזרה עם `omarchy agent account use main`), או בפאנל על ידי לחיצה על מספר חשבון ולאחר מכן `Enter` (או לחיצה על כפתור ה-Use שלו). הפעלות Claude רצות עוברות גם כן, מההודעה הבאה שלהן: כל הפעלת Claude רצה ב-`~/.claude`, שתמיד מחזיקה את כניסת החשבון הפעיל. הפעלת Claude שהחלה בתיקיית חשבון משלה על ידי Omarchy ישנה יותר מחזיקה כניסה זו עד שהיא נסגרת, ולכן ההחלפה מציינת את ההפעלות האלה ומסתיימת מעצמה לאחר שהן נעלמות. הפעלות Codex ו-Grok רצות נשארות על החשבון שהן התחילו איתו. היסטוריית שיחות, הגדרות, כישורים ותוספים משותפים בין חשבונות, ולכן `claude --continue` באותה תיקייה ממשיך מהמקום שהפסקת בחשבון החדש.

עם יותר מחשבון אחד, הפאנל מציג את המגבלות של כל חשבון זה לצד זה, כשהפעיל מסומן. Omarchy מודיעה לך כאשר החשבון הפעיל עובר 95% ממגבלה, ולחיצה על ההודעה עוברת לחשבון עם הכי הרבה מרווח. היא לעולם לא עוברת מעצמה. שנה את הסף עם `omarchy agent account threshold 90`. אם כל חשבון מעל הסף, תשמע על כך פעם אחת, יחד עם איזה חשבון מתפנה ראשון. בעוד חשבון פעיל נמצא בתוך 15 נקודות מהסף שלו (80% בברירת המחדל), מגבלותיו נבדקות כל שלוש דקות ולא כל 15.

`omarchy agent account list` מציג כל חשבון ואת מגבלותיו העדכניות ביותר, `omarchy agent account remove work` שוכח אחד, ו-`omarchy agent account rename primary Hey` משנה שם של אחד (או לחץ על שם חשבון בפאנל). פקודות אלה פועלות על חשבונות סוכן ברירת המחדל שלך; כדי להגיע לספק האחר, ציין אותו תחילה, כמו ב-`omarchy agent account use codex side`. הכניסה שכבר הייתה לך ב-`~/.claude` או `~/.codex` היא חשבון ה-_Main_. של Codex נשארת היכן שהיא; של Claude ממתינה בתיקייה משלה בעוד חשבון אחר פעיל. חשבון שנשאר ללא שימוש יותר מכשמונה שעות יכול להציג _נדרשת כניסה_; לחץ עליו כדי להיכנס לחשבון זה שוב ממש בפאנל, או עבור אליו והתחל הפעלה, שמרעננת את הכניסה מעצמה. שרתי MCP שאתה מוסיף עם `claude mcp add` מגיעים לכל חשבון Claude, מאחר שכולם רצים ב-`~/.claude`; עבור Codex ו-Grok, שרתים שהיו לך כאשר חשבון נוסף מגיעים אליו, אבל מאוחרים יותר מגיעים רק לחשבון שהוספת אותם בו. Claude Desktop שומר כניסה משלו, וכלי Codex או Grok שהוגדרו עם נתיב מוחלט לקובץ בינארי של CLI אינם עוקבים אחר ההחלפה. `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, או `GROK_HOME` מפורשים מקבלים עדיפות על החשבון שנבחר.

### אבחון קריסה

Omarchy צופה ב-systemd-coredump לקריסות תהליכים. לאחר שבחרת סוכן ברירת מחדל, כל תוכנית שלך שמבצעת dump לליבה מביאה הודעת "Process crashed" — לחץ עליה, והקריסה נמסרת לסוכן ברירת המחדל שלך יחד עם כישור ה-omarchy-diagnose-crash של Omarchy, שמדריך את הסוכן בקביעת העובדות מה-core dump ובהחלטה האם הקריסה שווה דיווח ל-upstream. ניתן גם להריץ אותו ידנית מול כל PID מ-`coredumpctl list` עם `omarchy agent crash <pid>`.

הצפייה מופעלת כברירת מחדל. כבה אותה תחת _טריגר > החלפה > Crash Capture Off_ (או עם `omarchy toggle crash-capture`) וההודעות מפסיקות; `omarchy agent crash <pid>` עדיין עובד ידנית.

קריסות יכולות להיות מושתקות גם תוכנית אחת בכל פעם, וזה מה שהאבחון מציע לך בסוף. `omarchy crash mute hyprland` מפסיק את ההודעות לאותה תוכנית בלבד, `omarchy crash mute hyprland off` מחזיר אותן, ו-`omarchy crash mute` לבדו מציג את מה שהשתקת. הוא מקבל את נתיב הקובץ הבינארי בשמחה כמו את שמו, ולכן `omarchy crash mute /usr/bin/hyprland` עושה אותו דבר. צטט שם עם רווח בו, כמו ב-`omarchy crash mute 'Some App'`. כל השאר עדיין מודיע, והתוכנית המושתקת עדיין קורסת — זה מסתיר את התזכורת, זה לא מתקן כלום.

### אפליקציות שולחניות

תפריט _התקנה > AI_ נושא גם כמה אפליקציות AI גרפיות: Amp Desktop, Antigravity Desktop, אפליקציית שולחן העבודה של ChatGPT, אפליקציית שולחן העבודה של Claude (בטא לינוקס של Anthropic, עם לשוניות Chat, Cowork, ו-Claude Code), Grok Bot לצ'אט עם המודלים של xAI, Herdr Desktop, Hermes Desktop, OpenClaw, אפליקציית שולחן העבודה של Perplexity, ו-T3 Code. Grok Bot היא אפליקציית הצ'אט לשולחן העבודה. סוכן הקידוד הוא פקודת `grok`.

Hermes Desktop היא זו שכדאי להכיר, כי למכונה יש Hermes אחד, והוא של האפליקציה: Hermes מותקנת אי פעם רק דרך האפליקציה, ופקודת `hermes` שסוכן ברירת המחדל מריץ היא של האפליקציה. בחירת Hermes כסוכן ברירת מחדל מתקינה את אותו דבר שהערך _התקנה > AI_ עושה: החבילה, וזמן ריצה של Hermes תחת `~/.hermes` שהוגדר על ידי המתקין של Hermes עצמה, שלוקח כמה דקות בפעם הראשונה. זמן ריצה זה הוא ה-Hermes האחד שפקודת ה-`hermes` בטרמינל, סוכן ברירת המחדל והאפליקציה כולם משתמשים בו, והוא מעדכן את עצמו עם `hermes update` ולא ממתין לגרסת Omarchy. התקנתו גם מעניקה ל-Hermes את ערכת הנושא של Omarchy כ-skin בשם `omarchy`, שכל משטח של Hermes עוקב אחריו כשאתה מחליף ערכות נושא; בחר אחר תחת הגדרות המראה של Hermes או עם `/skin` אם אתה מעדיף שלא, ו-Omarchy משאירה בחירה זו לבד. הסרת האפליקציה תחת _הסרה > AI_ סוגרת את Hermes תחילה, כולל השער, לוקחת את זמן הריצה הזה איתה, ושומרת את הצ'אטים, הזיכרונות, והכישורים ש-Hermes כתבה לעצמה אלא אם תאמר לה אחרת: היא שואלת, כשברירת המחדל היא לא, האם גם הנתונים והגדרות החיבור שלך צריכים להיעלם.

חוויית שולחן העבודה של OpenClaw היא ה-Control UI שלה, שנפתח כאפליקציית רשת המגובה בשער מקומי משלו. OpenClaw חיה ב-`~/.openclaw` ומעדכנת את עצמה: השתמש בכפתור "Update Gateway" של ה-Control UI או הרץ `openclaw update`, והשער מתחיל מחדש בגרסה החדשה. Omarchy בוחרת רק את הגרסה שהתקנה טרייה מתחילה ממנה. OpenClaw יכולה להיות גם סוכן ברירת המחדל שלך: בחירתה תחת _סוכן > Harness_ מגדירה את אותו עותק ב-`~/.openclaw`, והסוכן פותח את ממשק הטרמינל של OpenClaw המחובר לשער שלו. הסרת OpenClaw תחת _הסרה > AI_ לוקחת את שירות השער והאפליקציה איתה ולאחר מכן שואלת האם גם `~/.openclaw` צריך להיעלם, מאחר שזה מחזיק את הצ'אטים והאישורים שלך לצד OpenClaw עצמה וזמני הריצה של התוספים שהיא מורידה; ברירת המחדל שומרת אותו, והתקנת OpenClaw שוב מרימה אותו בחזרה.

Herdr Desktop היא אפליקציית שולחן העבודה [Herdr](https://herdr.dev): מרחבים, לשוניות, וחלוניות של טרמינלים וסוכני קידוד שממשיכים לרוץ בליבה שלה כשאתה סוגר את החלון. היא מגיעה מהמתקין של Herdr עצמה ולא מחבילה, ולכן היא חיה ב-`~/.local/share/herdr-app`, מביאה את הליבה שלה ב-`~/.local/bin/herdr-core` כשעדיין אין לך אחת, ומעדכנת את שניהם בעצמה. היא יושבת לצד פקודת `herdr` ש-Omarchy מספקת ב-`Super + Ctrl + Return` ולא מחליפה אותה, ומקבלת את המקשים הישירים של פקודה זו: `Alt + Return` ו-`Alt + Shift + Return` מפצלים חלונית למטה או ימינה, `Alt + Escape` סוגר אותה, `Ctrl + Alt + Arrow` עובר בין חלוניות, `Alt + 1..9` ו-`Alt + Left/Right` בוחרים לשונית, ו-`Alt + Up/Down` עוברים בין מרחבים. `Ctrl + 1..9` בוחר מרחב ו-`Alt + Shift + Up/Down` עובר בין סוכנים. מקשי הקידומת `Ctrl + Space` נשארים לטרמינל בלבד, מאחר שהאפליקציה לא יכולה להחזיק מקש Ctrl רגיל לרצף. Omarchy כותבת אלה ל-`~/.config/herdr-app/keys.json`, ו-`omarchy-refresh-herdr-app` מחזיר אותם. התקנתה בוחרת את ערכת הנושא Omarchy של Herdr, שעוקבת אחר ערכת הנושא של Omarchy שלך מאז. Herdr שומרת ערכת נושא אחת למצב בהיר ואחת למצב כהה, ולכן לאחר מעבר בין ערכת נושא כהה ובהירה של Omarchy, בחר Omarchy בבוחר ערכות הנושא של Herdr פעם נוספת עבור המצב האחר.

T3 Code רצה מגרסת ה-AppImage הרשמית שלה ב-`~/.local/share/t3code` ולא מחבילה, ולכן היא מעדכנת את עצמה. התקנתה שואלת האם להתחיל בערוץ Stable או Nightly; החלף מאוחר יותר בהגדרות של T3 Code. השרשורים וההגדרות שלך חיים ב-`~/.t3`, והסרת T3 Code תחת _הסרה > AI_ לוקחת אותם איתה.

### מודלים מקומיים

הרץ מודל פתוח במכונה שלך עבור סוכני הקידוד שלך. ההנחיות והקוד שלך נשארים במכונה; שום דבר שנשלח למודל לא עוזב אותה. התחל עם:

```bash
omarchy models use best text
```

זה מגדיר את מודל הטקסט הטוב ביותר למכונה זו, הסוג שהסוכנים שלך משתמשים בו. למודלי תמונה, וידאו ומוזיקה יש טוב ביותר משלהם: `omarchy models use best image`, `video` או `music`. הרץ `omarchy models use best` כדי לראות את הבחירה של כל סוג למכונה זו.

או פתח את פאנל המודלים המקומיים מאייקון הנצנצים שלו בסרגל העליון, לצד אייקון הסוכנים, או עם Super + Ctrl + Alt + X, ובחר +. האייקון מופיע כאשר מודל מתאים למכונה זו. Podman, שמריץ את המודלים, מגיע עם Omarchy, וכך גם ערכת הכלים לקונטיינרים של NVIDIA במכונת NVIDIA, שנותנת להם את ה-GPU; אם אחד מהם חסר, ההתקנה הראשונה מתקינה אותו. Omarchy אז בוחרת את המודל המומלץ למכונה זו, מורידה אותו, ומפעילה אותו. צפה להורדה של עשרות GB ולרוב זיכרון המכונה בשימוש בעוד המודל רץ: Flash Next משתמשת בכ-100 GiB עם הקשר מלא של 256K שלה. אם מודלים אחרים מחזיקים את הזיכרון שהיא צריכה, היא מוגדרת כמופסקת, מוכנה להתחיל לאחר שתפסיק אחד. המודל מפסיק בהתנתקות; הפסק אותו בעצמך כשאתה צריך את הזיכרון למשהו אחר.

`omarchy models list` מציג את האפשרויות ומסביר מדוע חלקן לא מתאימות. כדי להגדיר אחר, הרץ `omarchy models use <recipe>`. כיום, `qwen3.8-flash-next-gufo` ו-`qwen3.8-27b-gufo` זמינים למכונות Strix Halo עם 128 GB; ה-27B לוקחת כ-40 GiB, ולכן היא משאירה מקום לעבודה אחרת. במחשב נייד עם 64 GB עם Arc B390 של Intel, `qwen3.6-35b-a3b-llamacpp` רצה בכ-30 GiB. מתכונים והמלצות חדשים מגיעים עם `omarchy update`, דרך החבילה.

כל מודל שאתה מגדיר מקבל שורה משלו בפאנל המודלים המקומיים: play כדי להפעיל אותו, pause כדי להפסיק אותו ולפנות את זיכרונו, וכפתור הטרמינל כדי לפתוח את הסוכן שלך עליו. בחלק העליון, סרגל מציג כיצד זיכרון המכונה מחולק בין Omarchy עצמה (המערכת והאפליקציות שלך), כל מודל רץ, ומה פנוי. הצבע על מודל מופסק והסרגל מציג האם הוא מתאים, או כמה חסר לו. כמה יכולים לרוץ בבת אחת כשהם מתאימים בזיכרון יחד; אם אחד לא מתאים, Omarchy אומרת איזה מודל רץ להפסיק. גרור שורות לפי הלוגו שלהן כדי לסדר אותן מחדש, ולחץ Delete על שורה נבחרת כדי להסיר מודל ואת ההורדה שלו.

כל מודל קידוד שאתה מגדיר מקבל גם ערך משלו במשגר היישומים, תחת שם המודל ועם הלוגו של היוצר שלו, באותו אופן שכניסה ל-Claude, Codex או Grok מוסיפה אחד. הוא פותח את הסוכן שלך על מודל זה, ומפעיל את המודל תחילה אם הוא לא רץ: הטרמינל מציג אותו נטען ומעביר לסוכן לאחר שהוא פעיל. הסרת מודל מסירה את הערך שלו.

לא כל מודל מיועד לקידוד. מודלי תמונה, וידאו ומוזיקה נפתחים ב-Fantasi במקום זאת, האפליקציה של Omarchy ליצירת תמונות, וידאו ומוזיקה עם מודל שרץ במכונה זו, נבחר שם או מהשורה שלהם בפאנל המודלים המקומיים.

מודל ממשיך לרוץ בדיוק כפי שהוגדר, ולכן עדכון של Omarchy לעולם לא מפעיל מחדש אחד תחת הסוכנים שלך. כאשר ל-Omarchy יש זמן ריצה חדש יותר או משקולות חדשות יותר למודל שהגדרת, השורה שלו מציגה כפתור עדכון: לחץ עליו והמודל מוגדר שוב ברקע, מוריד רק את מה שהשתנה, ומתחיל מחדש בגרסה החדשה. מודל שהיה מופסק נשאר מופסק. `omarchy models update` עושה אותו דבר לכל מודל מטרמינל.

משורת הפקודה, `omarchy models start <recipe>` ו-`omarchy models stop <recipe>` עושים אותו דבר, `omarchy models status` מציג כל מודל, ו-`omarchy agent --local` פותח את המודל האחרון שהפעלת ב-pi, יהיה סוכן ברירת המחדל שלך אשר יהיה. OpenCode ו-Qwen Code יכולים להשתמש במודל מקומי גם כן: `omarchy models harness opencode` או `omarchy models harness qwen` פותח אותם שם במקום זאת, ו-`omarchy models harness pi` חוזר. pi מציג גם כל מודל שהגדרת, ואלה במכונות ששייכת אליהן, בבוחר המודלים שלו, ולכן `pi` רגיל מגיע אליהם גם כן. כל לקוח תואם OpenAI יכול להתחבר גם כן: `status` מציג את כתובת כל מודל (הראשונה היא `http://127.0.0.1:11435/v1`), שם המתכון הוא המודל, והמפתח נמצא ב-`~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` מוחק מודל ואת ההורדות ששום מודל אחר לא משתמש בהן.

זמני ריצה של צד שלישי מתויגים עם המו"ל שלהם. Omarchy מריצה כל מודל ללא גישה לרשת.

### מודלי LLM מקומיים

Omarchy ממליצה על שתי דרכים להרצת מודלי LLM מקומיים: LM Studio ו-Ollama. LM Studio מספקת ממשק GUI למציאת מודלים פתוחי-משקל, התקנתם, והרצתם. זו דרך מעולה להתחיל בקלות. Ollama מציעה CLI לעשות זאת באופן דומה. אבל אם אתה חדש במודלים מקומיים, הייתי מתחיל עם LM Studio. ניתן להתקין כל אחד תחת _התקנה > AI_ בתפריט Omarchy.

### כישורי Omarchy

כישורי סוכן עוזרים ל-AI להשתמש בכלים ספציפיים בדרך ספציפית, ו-Omarchy מספקת שבעה מהם. כישור ה-omarchy מכסה התאמת המערכת, כמו כוונון תצורת Hyprland שלך או התאמת הסרגל. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app, ו-omarchy-make-game מכסים יצירת משהו חדש, omarchy-contribute מכסה דיווח על באג או שליחת תיקון ל-upstream, ו-omarchy-diagnose-crash עובד על ה-core dump של קריסה. הם מקושרים בסמליות לספריות הכישורים עבור Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` וכל `~/.hermes/profiles/*/skills`), והמיקום הגנרי `~/.agents/skills`, ולכן רוב ה-harnesses קולטים אותם אוטומטית. תיקיית כישור משלך עם אותו שם מקבלת עדיפות.

אבל עליך להתייחס לכישורים האלה כניסיוניים. מודלים שונים ישתמשו בהם להשפעה שונה. הכי טוב לרוץ במצב תכנון תחילה, כדי שיהיה לך מושג מה הסוכן היה רוצה לשנות. ולאחר מכן היה מוכן לבטל שינויים או אפילו להפעיל `omarchy reinstall configs`, אם הסוכן עושה בלגן מהכל.
