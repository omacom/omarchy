# AI

Omarchy כוללת משגרים לסוכני הקידוד שלהלן מבלי לבחור עבורך ברירת מחדל. הפעל פקודה כדי להתקין את ה-CLI שלה בשימוש הראשון, ולאחר מכן בצע אימות כשתתבקש. Hermes היא החריגה: שום דבר לא מותקן עבורה בשימוש הראשון, ובחירתה מתקינה את Hermes Desktop, כפי שמסביר הסעיף _Desktop apps_ להלן.

### התקנה ועדכון של סוכנים

למעט Hermes, הסוכנים האלה משתמשים בהתקנה העצלה של mise: ההפעלה הראשונה מתקינה את ה-CLI, והפעלות מאוחרות יותר משתמשות בו שוב. mise גם בודקת אם קיימת גרסה חדשה לסוכן מותקן לכל היותר פעם בארבע שעות, ממש לפני שהוא מתחיל או ברקע בפרומפט של ה-shell. אם העדכון הזה נכשל או שאתה לא מחובר, הגרסה המותקנת רצה. `omarchy update` מעדכנת סוכנים מותקנים יחד עם שאר Omarchy, ו-`mup` מעדכנת רק כלים המנוהלים על ידי mise.

המעדכן של סוכן עצמו, כמו `claude update`, `codex update`, או כפתור עדכון באפליקציה, לא מעדכן את ההתקנה המנוהלת על ידי mise. `codex update` נכשל, ו-`claude update` יכול לדווח על הצלחה תוך התקנת עותק נפרד ש-mise לא עוקבת אחריו. אם אתה מעדיף להשתמש במתקין ובמעדכן המקוריים של סוכן, הוסף אותו ל-`disable_tools`; ראה [כלי CLI מותקנים מראש](18-development-tools.md#preinstalled-cli-tools).

כדי להתקין את כל הכלים העצלים שהוגדרו לפני שתצטרך אותם, הרץ `mise install --include-lazy`. זה כולל את שאר כלי ה-CLI המוגדרים כברירת מחדל של Omarchy וגם את הסוכנים. ראה [כלי CLI מותקנים מראש](18-development-tools.md#preinstalled-cli-tools) להתקנת כלי בודד או לשימוש בהתקנה משלך.

`grok` מותקנת דרך חבילת `grok` הרשמית של mise, באותו אופן כמו `claude` ו-`codex`. הרץ `grok`, או בחר אותה תחת _Agent > Harness_. דלג על מתקין ה-`curl | bash` ב-x.ai. הנתיב הזה שם עותק שני ב-`~/.grok/bin`, מוסיף אותו בתחילת ה-`PATH`, ודורס את ה-wrapper של Omarchy.

`dsh` פותחת את ממשק הדפדפן שלה ב-`127.0.0.1:3080`, כשספריית ההפעלה היא סביבת העבודה המוגדרת כברירת מחדל שלה. ממשק הדפדפן שלה לא מקבל הנחיית התחלה, כך ש-`omarchy agent prompt` פותח אותה עם ההנחיה בלוח ההדבקה שלך כדי שתדביק אותה. Omarchy מפעילה אותה עם הגדרת ההרשאות ללא אישור של DeepSeek. DeepSeek Harness מעלה יומני הפעלה ל-DeepSeek כשאתה משתמש ב-API הרשמי של המודלים שלה; כבה את זה תחת _Settings > General > Upload Session Log_ בממשק הדפדפן שלה. משוב שאתה שולח לה מועלה יחד עם ההפעלה גם הוא, אלא אם תפעיל אותה עם `DSH_TELEMETRY_MODE=DISABLED`.

### סוכן ברירת המחדל

בחר את סוכן ברירת המחדל שלך עם `omarchy default agent <name>` או תחת _Agent > Harness_ בתפריט Omarchy (`Super + Space`). אם הסוכן עדיין לא מותקן, בחירתו תתקין אותו תחילה. Omarchy חדשה תזמין אותך לבצע את הבחירה הזו בהתראה חד-פעמית.

בחירת Claude גם מנסה להגדיר את תוסף הדפדפן שלה עבור Chromium, Chrome, Brave, Brave Origin ו-Edge. הגדרת התוסף חלה על כל המשתמשים ועשויה לבקש את הסיסמה של המערכת שלך; ביטול או התקנת תוסף שנכשלה עדיין בוחרים ומפעילים את Claude. הפעל מחדש את הדפדפן, הפעל את התוסף אם תתבקש, והיכנס ל-Claude כדי לסיים לחבר אותו. הרץ `/chrome` ב-Claude כדי לבדוק את החיבור. Firefox ו-Zen אינם תומכים בתוסף הזה. אם Claude כבר הייתה ברירת המחדל שלך לפני שההגדרה הזו נוספה, בחר אותה שוב כדי להתקין את התוסף.

לאחר שבחרת, `Super + Shift + Ctrl + A` מפעיל את סוכן ברירת המחדל בחלון טרמינל ייעודי (או מעלה את הבוחר אם עדיין לא בחרת). אתה יכול גם להפעיל אותו ישירות למשימה עם `omarchy agent prompt "Review this project"`. Freebuff ו-DeepSeek Harness לא מקבלות הנחיית התחלה, אז הן נפתחות עם ההנחיה בלוח ההדבקה שלך כדי שתדביק אותה במקום זאת. סוכנים המופעלים כך רצים ללא השגחה במצבי אל-תעצור-לשאול שלהם, אז תהיה מוכן שהם באמת יעשו דברים! ל-MiniMax Code אין מצב כזה להפעלות אינטראקטיביות, אז היא מבקשת הרשאות כרגיל. ומאחר שסוכנים מסרבים לזכור אמון עבור ספריית הבית שלך, הפעלות מ-`$HOME` מתחילות ב-`~/Work` במקום זאת.

יש גם קיצורי דרך לטרמינל: `a` מריץ את סוכן ברירת המחדל בתוך הטרמינל הנוכחי, בעוד `c`, `cx` ו-`cy` מפעילים את OpenCode, Claude Code ו-Codex ישירות (שוב במצבי האישור האוטומטי שלהם). שינויי ערכת נושא מסתנכרנים גם לסוכנים: Claude Code, Pi, OpenCode ו-Hermes (ברגע ש-Omarchy התקינה אותה) כולם עוקבים כשאתה מחליף את ערכת הנושא של Omarchy.

### הוראות הסוכן שלך

כללים אישיים לכל סוכן נמצאים ב-`~/.agents/AGENTS.md`, ליד ה-skills המשותפים ב-`~/.agents/skills`. פתח אותו תחת _Agent > Instructions_, שגם מקשר אותו לכל harness ששומר קובץ גלובלי משלו: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` של Copilot, וכן הלאה. Crush ו-Amp קוראות את הקישור `~/.config/AGENTS.md`, בעוד omp, Kimi ו-DeepSeek Harness קוראות את `~/.agents/AGENTS.md` ישירות. בחירת סוכן ברירת מחדל מקשרת אותו גם כן. קובץ הוראות שכבר היה לך הופך למשותף אם עדיין לא היה אחד; אחרת הוא נשמר ליד הקישור כ-`.bak`. הרץ `omarchy agent instructions` כדי לקשר מחדש לאחר התקנת סוכן נוסף.

### פאנל הסוכנים

בסרגל העליון יש אייקון סוכנים. לפני שהגדרת סוכן, הפאנל שלו מדריך אותך דרך כניסה ל-Claude, Codex או Grok, והראשון הופך לסוכן ברירת המחדל שלך. לאחר מכן, הפאנל שם כל מנוי בעמוד אחד: כל סוכן וחשבון עם התוכנית שלו, מד לכל אחת ממגבלות ההפעלה של 5 שעות והמגבלות השבועיות שלו עם הזמן עד שהוא מתאפס (רחף לקבלת האחוז המדויק), או היתרה הנותרת ששולמה מראש, מתחת לשורה שמתחלפת בין מה שהשתמשת בו בכל כולם, כמו טוקנים השבוע והמודל שהשתמשת בו הכי הרבה. תחת _Make something_ הוא מציע הנחיות התחלה לערכת נושא, תוסף, אפליקציה או משחק חדשים שמעבירות את המשימה לסוכן ברירת המחדל שלך. אפליקציות נבנות באותו האופן שבו נבנות Hype, Monologue ו-Omacut של Omarchy עצמה, ב-C++ וב-Qt Quick, בהתאם ל-skill הסוכן omarchy-make-app, והמהדר וחלקי Qt שהם צריכים מגיעים מותקנים. משחקים הם עמוד three.js יחיד ב-`~/Games/vibes`, בהתאם ל-skill הסוכן omarchy-make-game, וכולם נפתחים ממשגר Game Vibes אחד בערכת הנושא הנוכחית; הם טוענים את three.js מהאינטרנט, כך שהם צריכים חיבור כדי להתחיל. Claude Code, Codex, Grok, Kimi, Cursor והקצבת Grok Bot שלו, GitHub Copilot, Muse, Antigravity, Kimchi ו-Devin מכוסים מהקופסה עם המגבלות שלהם, ו-Hermes, Mistral Vibe ו-Qwen Code מציגות את ההפעלות והטוקנים שלהן ברגע שהשתמשת בהן. תוכניות ספקים ומפתחות שאתה משתמש בהם דרך pi, omp או opencode מופיעים גם כן: OpenCode Zen ו-Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan ו-Synthetic עם המגבלות שלהם; Fireworks, OpenRouter ו-DeepSeek עם היתרות ששולמו מראש שלהם; והמודלים שאתה מריץ על החומרה שלך תחת Local models. כל סוכן נספר פעם אחת, תחת מי שמחייב עליו, לא משנה דרך כמה harnesses אתה מפעיל אותו.

לחץ לחיצה שמאלית על אייקון הסרגל לפאנל, לחיצה ימנית להפעלת סוכן ברירת המחדל שלך. רשומות השימוש שמאחוריו נוצרות מחדש כל 15 דקות על ידי `omarchy agent usage-update`, והפאנל יכול אפילו למזג שימוש מהמכונות האחרות שלך באמצעות תיקייה מסונכרנת. ראה את ה-README תחת `$OMARCHY_PATH/shell/plugins/agents/` להגדרות המלאות.

### מספר מנויים

אם אתה משלם עבור יותר מתוכנית Claude, Codex או Grok אחת — Max אישית ואחת של עבודה, נניח — Omarchy יכולה להשאיר את כולן מחוברות ולעבור ביניהן. הוסף מנוי עם ה-+ בפאנל הסוכנים, שמדריך אותך שם במקום, או עם `omarchy agent account add claude Work` (או `codex`, או `grok`). זה מתקין את ה-CLI אם הוא חסר. החשבון הראשון של ספק נכנס דרך הדפדפן הרגיל שלך, בדיוק היכן שה-CLI תמיד מחפש. כל אחד אחריו נכנס דרך חלון פרטי, כך שהחשבון שהדפדפן שלך כבר מחובר אליו לא ייבחר בטעות; היכנס שם כחשבון שאתה מוסיף, וסגור כל חלון פרטי שכבר פתוח לך קודם. לעולם אל תצא מה-CLI כדי לעשות זאת: יציאה מבטלת את הכניסה השמורה, והחשבון הזה יצטרך להתווסף שוב.

כדי להעתיק כניסות מנוי למכונת Omarchy אחרת דרך SSH, הרץ `omarchy agent account copy user@laptop`. השולח מספק מקלט זמני כאשר ליעד אין אחד מותקן, כך שמכונות Omarchy ישנות יותר יכולות לקבל חשבונות ללא עדכון. מקלטים מותקנים מקבלים קדימות. פעולה זו מעתיקה את כל מנויי Claude, Codex ו-Grok; הוסף שמות ספקים כדי לבחור אותם, כמו ב-`omarchy agent account copy laptop claude`. שמות חשבונות ומזהי פקודות תואמים למקור, כולל חשבונות שכבר קיימים ביעד. חשבונות יעד לא קשורים מקבלים סיומת מספרית אם שמותיהם מתנגשים, והגדרות, skills, תוספים והיסטוריית שיחות נשארים מקומיים לכל מכונה.

אישורי יעד קיימים נשמרים. חשבון מקור שכבר מחובר שם מסתנכרן בשמו מבלי להחליף את האישורים שלו; חשבונות אחרים מתווספים לצדו. כדי להחליף אישורים שמורים לחשבונות תואמים, השתמש ב-`omarchy agent account copy --replace laptop claude` לאחר שיצאת מההפעלות של אותו חשבון ביעד. יעד חדש גם מקבל את החשבון הפעיל והעדפות ההחלפה של המקור; יעד מבוסס שומר את שלו.

אישורים עוברים דרך SSH ונשמרים בקבצים פרטיים ביעד, אז העתק רק למכונות שאתה בוטח בהן. זוהי העתקה חד-פעמית, לא סנכרון מתמשך. טוקני רענון של Codex יכולים להיות מוחלפים על ידי מכונה אחרת, ולהשאיר כניסה מועתקת הזקוקה לחידוש; כניסות נפרדות נשארות הבחירה האמינה ביותר לשימוש בו-זמני במספר מכונות. ראה את [הנחיות אימות החשבון של Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

חשבון אחד לספק פעיל, וכל הפעלה חדשה מתחילה כמותו: `cx`, `cy`, `claude`, `codex` או `grok` פשוטים, כל דבר המופעל דרך `omarchy agent`, וסקריפטים או עורכים שמוצאים את ה-CLI ב-`PATH`. החלף עם `omarchy agent account use work` (וחזרה עם `omarchy agent account use main`), או בפאנל על ידי לחיצה על מספר חשבון ואז `Enter` (או לחיצה על כפתור Use שלו). הפעלות Claude רצות עוברות גם הן, מההודעה הבאה שלהן: כל הפעלת Claude רצה ב-`~/.claude`, שתמיד מחזיקה את הכניסה של החשבון הפעיל. הפעלת Claude שהתחילה בתיקייה של חשבון על ידי Omarchy ישנה יותר מחזיקה את הכניסה הזו עד שהיא יוצאת, אז ההחלפה מציינת את ההפעלות האלה ומסיימת מעצמה ברגע שהן נעלמות. הפעלות Codex ו-Grok רצות נשארות בחשבון שבו התחילו. היסטוריית שיחות, הגדרות, skills ותוספים משותפים בין חשבונות, כך ש-`claude --continue` באותה תיקייה ממשיך איפה שהפסקת בחשבון החדש.

עם יותר מחשבון אחד, הפאנל מציג את מגבלות כל חשבון זה לצד זה, כשהפעיל מסומן. כברירת מחדל Omarchy מודיעה לך כאשר החשבון הפעיל עובר 95% ממגבלה, ולחיצה על ההתראה עוברת לחשבון עם הכי הרבה מרווח. רחף מעל שורת חשבון בפאנל ולחץ על Autoswitch שמופיע ליד Use (או לחץ `m`), או הרץ `omarchy agent account mode auto`, כדי שיעבור מעצמו במקום זאת; בזמן שזה פעיל, Autoswitch תופס את מקומו של Use, ולחיצה עליו שוב חוזרת להתראות. הוסף מספר כדי לשנות את הסף, כמו ב-`omarchy agent account mode auto 90`. אם כל החשבונות מעל הסף, תשמע על כך פעם אחת, יחד עם איזה חשבון מתפנה ראשון. בזמן שחשבון פעיל נמצא בתוך 15 נקודות מהסף שלו (80% בברירת המחדל), המגבלות שלו נבדקות כל שלוש דקות ולא כל 15.

`omarchy agent account list` מציגה כל חשבון ואת המגבלות האחרונות שלו, `omarchy agent account remove work` שוכחת אחד, ו-`omarchy agent account rename primary Hey` משנה שם של אחד (או לחץ על שם חשבון בפאנל). פקודות אלה פועלות על החשבונות של סוכן ברירת המחדל שלך; כדי להגיע לספק האחר, ציין אותו קודם, כמו ב-`omarchy agent account use codex side`. הכניסה שכבר הייתה לך ב-`~/.claude` או `~/.codex` היא חשבון ה-_Main_. של Codex נשארת היכן שהיא; של Claude ממתינה בתיקייה משלה בזמן שחשבון אחר פעיל. חשבון שלא נעשה בו שימוש יותר מכשמונה שעות יכול להציג _Sign-in required_; לחץ עליו כדי להיכנס לאותו חשבון שוב ממש בפאנל, או עבור אליו והתחל הפעלה, שמרעננת את הכניסה מעצמה. שרתי MCP שאתה מוסיף עם `claude mcp add` מגיעים לכל חשבון Claude, מאחר שכולם רצים ב-`~/.claude`; עבור Codex ו-Grok, שרתים שהיו לך כאשר חשבון התווסף מגיעים אליו, אבל מאוחרים יותר מגיעים רק לחשבון שבו הוספת אותם. Claude Desktop שומרת כניסה משלה, וכלי Codex או Grok שהוגדרו עם נתיב מוחלט לקובץ בינארי של CLI לא עוקבים אחר ההחלפה. `CLAUDE_CONFIG_DIR`, `CODEX_HOME` או `GROK_HOME` מפורשים מקבלים קדימות על החשבון שנבחר.

### אבחון קריסות

Omarchy צופה ב-systemd-coredump לקריסות תהליכים. כאשר משהו עושה segfault, תקבל התראה "Process crashed" — לחץ עליה, והקריסה נמסרת לסוכן ברירת המחדל שלך יחד עם ה-skill diagnose-crash של Omarchy, שמדריך את הסוכן דרך ביסוס העובדות מה-core dump והחלטה אם הקריסה שווה דיווח ל-upstream. אתה יכול גם להריץ אותה ידנית נגד כל PID מ-`coredumpctl list` עם `omarchy agent crash <pid>`.

הצפייה פועלת כברירת מחדל. כבה אותה תחת _Trigger > Toggle > Crash Capture_ (או עם `omarchy toggle crash-capture`) וההתראות מפסיקות; `omarchy agent crash <pid>` עדיין עובד ידנית.

קריסות יכולות גם להיות מושתקות תוכנית אחת בכל פעם, וזה מה שהאבחון מציע לך בסוף. `omarchy crash mute hyprland` עוצר את ההתראות לאותה תוכנית בלבד, `omarchy crash mute hyprland off` מחזיר אותן, ו-`omarchy crash mute` לבדו מפרט את מה שהשתקת. הוא מקבל את נתיב הקובץ הבינארי בשמחה כמו את שמו, כך ש-`omarchy crash mute /usr/bin/hyprland` עושה את אותו הדבר. שם עם רווח בתוכו יש לצטט, כמו ב-`omarchy crash mute 'Some App'`. כל השאר עדיין מודיע, והתוכנית המושתקת עדיין קורסת — זה מסתיר את התזכורת, זה לא מתקן כלום.

### אפליקציות שולחן עבודה

תפריט _Install > AI_ כולל גם כמה אפליקציות AI גרפיות: אפליקציית שולחן העבודה של ChatGPT, אפליקציית שולחן העבודה של Claude (גרסת הבטא ל-Linux של Anthropic, עם לשוניות Chat, Cowork ו-Claude Code), Grok Bot לשיחה עם המודלים של xAI, Herdr Desktop, Hermes Desktop, OpenClaw, אפליקציית שולחן העבודה של Perplexity ו-T3 Code. Grok Bot היא אפליקציית הצ'אט לשולחן העבודה. סוכן הקידוד הוא הפקודה `grok`.

Hermes Desktop היא זו שצריך להכיר, כי למכונה יש Hermes אחת, והיא של האפליקציה: Hermes מותקנת רק אי פעם דרך האפליקציה, והפקודה `hermes` שסוכן ברירת המחדל מריץ היא של האפליקציה. בחירת Hermes כסוכן ברירת המחדל מתקינה את אותו הדבר שהערך _Install > AI_ עושה: החבילה, ו-runtime של Hermes תחת `~/.hermes` שמוגדר על ידי המתקין של Hermes עצמה, שלוקח כמה דקות בפעם הראשונה. ה-runtime הזה הוא ה-Hermes האחת שהפקודה `hermes` בטרמינל, סוכן ברירת המחדל והאפליקציה כולם משתמשים בה, והיא מעדכנת את עצמה עם `hermes update` ולא ממתינה לגרסת Omarchy. התקנתה גם נותנת ל-Hermes את ערכת הנושא של Omarchy כ-skin בשם `omarchy`, שכל משטח של Hermes עוקב אחריה כשאתה מחליף ערכות נושא; בחר אחרת תחת הגדרות Appearance של Hermes או עם `/skin` אם אתה מעדיף שלא, ו-Omarchy משאירה את הבחירה הזו בשקט. הסרת האפליקציה תחת _Remove > AI_ סוגרת את Hermes קודם, כולל ה-gateway, לוקחת את ה-runtime הזה איתה, ושומרת את הצ'אטים, הזיכרונות וה-skills ש-Hermes כתבה לעצמה אלא אם תגיד לה אחרת: היא שואלת, כברירת מחדל לא, אם גם הנתונים האלה והגדרות החיבור שלך צריכים להיעלם.

חוויית שולחן העבודה של OpenClaw היא ה-Control UI שלה, שנפתח כאפליקציית אינטרנט המגובה ב-gateway מקומי משלה. OpenClaw חיה ב-`~/.openclaw` ומעדכנת את עצמה: השתמש בכפתור "Update Gateway" של ה-Control UI או הרץ `openclaw update`, וה-gateway מתחיל מחדש בגרסה החדשה. Omarchy בוחרת רק את הגרסה שהתקנה חדשה מתחילה ממנה. הסרת OpenClaw תחת _Remove > AI_ לוקחת את שירות ה-gateway והאפליקציה איתה ואז שואלת אם `~/.openclaw` צריכה להיעלם גם כן, מאחר שהיא מחזיקה את הצ'אטים והאישורים שלך לצד OpenClaw עצמה ו-runtime התוספים שהיא מורידה; ברירת המחדל שומרת אותה, והתקנת OpenClaw שוב בוחרת אותה בחזרה.

Herdr Desktop היא אפליקציית שולחן העבודה [Herdr](https://herdr.dev): spaces, tabs ו-panes של טרמינלים וסוכני קידוד שממשיכים לרוץ בליבה שלה כשאתה סוגר את החלון. היא מגיעה מהמתקין של Herdr עצמה ולא מחבילה, כך שהיא חיה ב-`~/.local/share/herdr-app`, מביאה את הליבה שלה ב-`~/.local/bin/herdr-core` כשעדיין אין לך אחת, ומעדכנת את שניהם. היא יושבת לצד הפקודה `herdr` ש-Omarchy מספקת ב-`Super + Ctrl + Return` ולא מחליפה אותה, ומקבלת את מקשי הישיר של אותה פקודה: `Alt + Return` ו-`Alt + Shift + Return` מפצלים pane למטה או ימינה, `Alt + Escape` סוגר אותו, `Ctrl + Alt + Arrow` עובר בין panes, `Alt + 1..9` ו-`Alt + Left/Right` בוחרים tab, ו-`Alt + Up/Down` עוברים בין spaces. `Ctrl + 1..9` בוחר space ו-`Alt + Shift + Up/Down` עובר בין סוכנים. מקשי הקידומת `Ctrl + Space` נשארים לטרמינל בלבד, מאחר שהאפליקציה לא יכולה להחזיק מקש Ctrl רגיל לרצף. Omarchy כותבת אותם ל-`~/.config/herdr-app/keys.json`, ו-`omarchy-refresh-herdr-app` מחזיר אותם. התקנתה בוחרת את ערכת הנושא Omarchy של Herdr, שעוקבת אחר ערכת הנושא של Omarchy שלך מאז. Herdr שומרת ערכת נושא אחת למצב בהיר ואחת למצב כהה, כך שלאחר מעבר בין ערכת נושא כהה לבהירה של Omarchy, בחר Omarchy בבוחר ערכות הנושא של Herdr פעם נוספת למצב האחר.

T3 Code רצה מהגרסת AppImage הרשמית שלה ב-`~/.local/share/t3code` ולא מחבילה, כך שהיא מעדכנת את עצמה. התקנתה שואלת אם להתחיל בערוץ Stable או Nightly; החלף מאוחר יותר בהגדרות T3 Code. ה-threads וההגדרות שלך חיים ב-`~/.t3`, והסרת T3 Code תחת _Remove > AI_ לוקחת אותם איתה.

### מודלים מקומיים

הרץ מודל פתוח על המכונה שלך עבור סוכני הקידוד שלך. ההנחיות והקוד שלך נשארים על המכונה; שום דבר שנשלח למודל לא עוזב אותה. התחל עם:

```bash
omarchy agent local use best
```

או, בפאנל הסוכנים בסרגל העליון, בחר + ואז Local AI, שמופיעה כאשר מודל מתאים למכונה זו. בפעם הראשונה, זה מתקין את Podman, שמריץ את המודלים, ובמכונת NVIDIA את ערכת הכלים של מכולות NVIDIA, שנותנת להם את ה-GPU. Omarchy אז בוחרת את המודל המומלץ למכונה זו, מורידה אותו ומפעילה אותו. צפה להורדה של עשרות GB ולרוב זיכרון המכונה להיות בשימוש בזמן שהמודל רץ: Flash Next משתמשת בכ-100 GiB עם הקשר 256K המלא שלה. אם מודלים אחרים מחזיקים את הזיכרון שהיא צריכה, היא מוגדרת עצורה, מוכנה להתחיל ברגע שתעצור אחד. המודל נעצר ביציאה; עצור אותו בעצמך כשאתה צריך את הזיכרון למשהו אחר.

`omarchy agent local list` מציגה את האפשרויות ומסבירה מדוע חלקן לא מתאימות. כדי להגדיר אחת נוספת, הרץ `omarchy agent local use <recipe>`. היום, `qwen3.8-flash-next-gufo` ו-`qwen3.8-27b-gufo` זמינות למכונות Strix Halo של 128 GB; ה-27B לוקחת כ-40 GiB, כך שהיא משאירה מקום לעבודה אחרת. במחשב נייד של 64 GB עם Arc B390 של Intel, `qwen3.6-35b-a3b-llamacpp` רצה בכ-30 GiB. מתכונים והמלצות חדשים מגיעים עם `omarchy update`, דרך החבילה.

כל מודל שאתה מגדיר מקבל שורה משלו בפאנל הסוכנים, ליד המנויים שלך: הפעל כדי להתחיל אותו, השהה כדי לעצור אותו ולשחרר את הזיכרון שלו, וכפתור הטרמינל כדי לפתוח את הסוכן שלך עליו. כמה יכולים לרוץ בבת אחת כשהם מתאימים בזיכרון יחד; אם אחד לא מתאים, Omarchy אומרת איזה מודל רץ לעצור. גרור שורות כדי לסדר אותן מחדש, ולחץ Delete על שורה נבחרת כדי להסיר מודל וההורדה שלו.

כל מודל שאתה מגדיר מקבל גם ערך משלו במשגר האפליקציות, תחת שם המודל ועם הלוגו של היוצר שלו, באותו אופן שכניסה ל-Claude, Codex או Grok מוסיפה אחד. הוא פותח את הסוכן שלך על אותו מודל, ומפעיל את המודל קודם אם הוא לא רץ: הטרמינל מציג אותו נטען ומעביר לסוכן ברגע שהוא מוכן. הסרת מודל מסירה את הערך שלו.

מודל ממשיך לרוץ בדיוק כפי שהוגדר, כך שעדכון Omarchy לעולם לא מפעיל אחד מחדש מתחת לסוכנים שלך. כאשר ל-Omarchy יש runtime חדש יותר או משקולות חדשות יותר למודל שהגדרת, השורה שלו מציגה כפתור עדכון: לחץ עליו והמודל מוגדר שוב ברקע, מוריד רק את מה שהשתנה, ומתחיל מחדש בגרסה החדשה. מודל שהיה עצור נשאר עצור. `omarchy agent local update` עושה את אותו הדבר לכל מודל מטרמינל.

משורת הפקודה, `omarchy agent local start <recipe>` ו-`omarchy agent local stop <recipe>` עושות את אותו הדבר, `omarchy agent local status` מציגה כל מודל, ו-`omarchy agent --local` פותחת את סוכן ברירת המחדל שלך על המודל האחרון שהפעלת. pi, OpenCode ו-Qwen Code יכולות להשתמש באחד; עם כל ברירת מחדל אחרת הוא נפתח ב-pi. pi גם מפרטת כל מודל שהגדרת, ואלו שבמכונות שציוותת איתן, בבוחר המודלים שלה, כך ש-`pi` פשוטה מגיעה אליהם גם כן. כל לקוח תואם OpenAI יכול להתחבר גם כן: `status` מציגה את כתובת כל מודל (הראשונה היא `http://127.0.0.1:11435/v1`), שם המתכון הוא המודל, והמפתח נמצא ב-`~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` מוחקת מודל ואת ההורדות שאף מודל אחר לא משתמש בהן.

runtimes של צד שלישי מסומנים עם המוציא לאור שלהם. Omarchy מריצה כל מודל ללא גישה לרשת.

### Local LLMs

Omarchy ממליצה על שתי דרכים להריץ מודלי LLM מקומיים: LM Studio ו-Ollama. LM Studio מספקת ממשק GUI למציאת מודלים בעלי משקולות פתוחות, התקנתם והרצתם. זוהי דרך נהדרת להתחיל בקלות. Ollama מציעה CLI לעשות זאת באופן דומה. אבל אם אתה חדש במודלים מקומיים, הייתי מתחיל עם LM Studio. אתה יכול להתקין כל אחת מהן תחת _Install > AI_ בתפריט Omarchy.

### The Omarchy Skill

skills של סוכנים עוזרים ל-AI להשתמש בכלים ספציפיים בדרך ספציפית, ו-Omarchy מגיעה עם skill ברירת מחדל להתאמת המערכת. כמו לכוונן את קונפיגורציית Hyprland שלך, להתאים את הסרגל, או אפילו ליצור ערכת נושא חדשה מאפס. הוא מקושר בסמליות לתיקיות ה-skill של Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` וכל `~/.hermes/profiles/*/skills`), והמיקום הגנרי `~/.agents/skills`, כך שרוב ה-harnesses קולטים אותו אוטומטית.

אבל כדאי להתייחס ל-skill הזה כניסיוני. מודלים שונים ישתמשו בו להשפעה שונה. הכי טוב להריץ במצב תכנון קודם, כדי שיהיה לך מושג מה הסוכן היה רוצה לשנות. ואז תהיה מוכן לשחזר שינויים או אפילו להפעיל את `omarchy reinstall configs`, אם הסוכן עושה בלגן מהכול.
