# AI

Omarchy כוללת משגרים לסוכני הקידוד שלמטה מבלי לבחור עבורכם ברירת מחדל. הריצו פקודה כדי להתקין את ה-CLI שלה בשימוש הראשון, ואז התחברו כאשר תתבקשו. Hermes ו-OpenClaw הם היוצאים מן הכלל: שום דבר לא מותקן עבורם באמצעות mise, ובחירה בכל אחד מהם מתקינה עותק משלו שמתעדכן בעצמו, כפי שמסביר _אפליקציות שולחן עבודה_ בהמשך.

### התקנה ועדכון של סוכנים

למעט Hermes ו-OpenClaw, הסוכנים האלה משתמשים בהתקנה העצלה של mise: ההפעלה הראשונה מתקינה את ה-CLI, והפעלות מאוחרות יותר משתמשות בו שוב. mise גם בודק אם יש גרסה חדשה לסוכן מותקן לכל היותר פעם בארבע שעות, ממש לפני שהוא מופעל או ברקע בשורת מעטפת. אם העדכון הזה נכשל או שאתם לא מחוברים, הגרסה המותקנת רצה. `omarchy update` מעדכן סוכנים מותקנים יחד עם שאר Omarchy, ו-`mup` מעדכן רק כלים המנוהלים על ידי mise.

המעדכן העצמי של סוכן, כמו `claude update`, `codex update`, או כפתור עדכון באפליקציה, אינו מעדכן את ההתקנה המנוהלת על ידי mise. `codex update` נכשל, ו-`claude update` יכול לדווח על הצלחה תוך התקנת עותק נפרד ש-mise אינו עוקב אחריו. אם אתם מעדיפים להשתמש במתקין ובמעדכן המקוריים של סוכן, הוסיפו אותו ל-`disable_tools`; ראו [כלי CLI מותקנים מראש](18-development-tools.md#preinstalled-cli-tools).

כדי להתקין את כל כלי ה-lazy המוגדרים לפני שתצטרכו אותם, הריצו `mise install --include-lazy`. זה כולל גם את כלי ה-CLI האחרים של ברירת המחדל של Omarchy וגם את הסוכנים. ראו [כלי CLI מותקנים מראש](18-development-tools.md#preinstalled-cli-tools) להתקנת כלי בודד או לשימוש בהתקנה משלכם.

`grok` מותקן דרך חבילת `grok` הרשמית של mise, באותו אופן כמו `claude` ו-`codex`. הריצו `grok`, או סמנו אותו בכוכב בפאנל הסוכנים. דלגו על מתקין ה-`curl | bash` ב-x.ai. הנתיב הזה מניח עותק שני ב-`~/.grok/bin`, מקדים אותו ב-`PATH`, ודורס את העוטף של Omarchy.

`dsh` פותח את ממשק הדפדפן שלו ב-`127.0.0.1:3080`, כאשר תיקיית ההפעלה היא סביבת העבודה של ברירת המחדל שלו. ממשק הדפדפן שלו אינו מקבל הנחיית פתיחה, ולכן `omarchy agent prompt` פותח אותו כשההנחיה על לוח ההעתקה שלכם להדבקה. Omarchy מפעילה אותו עם הגדרת ההרשאות ללא-אישור של DeepSeek. DeepSeek Harness מעלה יומני הפעלה ל-DeepSeek כאשר אתם משתמשים ב-API הרשמי של המודלים שלו; כבו זאת תחת _הגדרות > כללי > Upload Session Log_ בממשק הדפדפן שלו. גם משוב שאתם שולחים אליו מועלה עם ההפעלה, אלא אם תפעילו אותו עם `DSH_TELEMETRY_MODE=DISABLED`.

### סוכן ברירת המחדל

בחרו את סוכן ברירת המחדל שלכם באמצעות הכוכב שליד סוכן בפאנל הסוכנים, שמלא על ברירת המחדל, או באמצעות `omarchy default agent <name>`, שמקבל גם כל harness שאין לו שורה שם. אם הסוכן עדיין לא מותקן, בחירתו מתקינה אותו תחילה, והוא גם מקבל משגר משלו במשגר האפליקציות, ליד Agent. Omarchy טרייה מזמינה אתכם להגדיר אחד באמצעות התראה חד-פעמית, שפותחת את פאנל הסוכנים.

בחירה ב-Claude מנסה גם להגדיר את תוסף הדפדפן שלו עבור Chromium, Chrome, Brave, Brave Origin, ו-Edge. הגדרת התוסף חלה על כל המשתמשים ועלולה לבקש את סיסמת המערכת שלכם; ביטול או התקנת תוסף שנכשלה עדיין בוחרים ומפעילים את Claude. הפעילו מחדש את הדפדפן, הפעילו את התוסף אם תתבקשו, והתחברו ל-Claude כדי לסיים לחבר אותו. הריצו `/chrome` ב-Claude כדי לבדוק את החיבור. Firefox ו-Zen אינם תומכים בתוסף הזה. אם Claude כבר היה ברירת המחדל שלכם לפני שההגדרה הזו נוספה, בחרו אותו שוב כדי להתקין את התוסף.

לאחר שבחרתם, `Super + Shift + Ctrl + A` מפעיל את סוכן ברירת המחדל בחלון טרמינל ייעודי (או מציג את הבורר אם עדיין לא בחרתם). אתם יכולים גם להפעיל אותו ישירות לתוך משימה עם `omarchy agent prompt "Review this project"`. Freebuff ו-DeepSeek Harness אינם מקבלים הנחיית פתיחה, ולכן הם נפתחים במקום זאת כשההנחיה על לוח ההעתקה שלכם להדבקה. סוכנים המופעלים כך רצים ללא השגחה במצבי אל-תעצור-כדי-לשאול שלהם, אז היו מוכנים לכך שהם באמת יעשו דברים! ל-MiniMax Code אין מצב כזה להפעלות האינטראקטיביות שלו, ולכן הוא מבקש הרשאות כרגיל. ומכיוון שסוכנים מסרבים לזכור אמון עבור תיקיית הבית שלכם, הפעלות מ-`$HOME` מתחילות במקום זאת ב-`~/Work`.

יש גם קיצורי טרמינל: `a` מריץ את סוכן ברירת המחדל בתוך הטרמינל הנוכחי, בעוד `c`, `cx`, ו-`cy` מפעילים את OpenCode, Claude Code, ו-Codex ישירות (שוב במצבי האישור האוטומטי שלהם). שינויי ערכת נושא מסתנכרנים גם אל הסוכנים: Claude Code, Pi, OpenCode, ו-Hermes (לאחר ש-Omarchy התקינה אותו) כולם עוקבים כאשר אתם מחליפים את ערכת הנושא של Omarchy.

### הוראות הסוכן שלכם

כללים אישיים לכל סוכן נכנסים ל-`~/.agents/AGENTS.md`, ליד הכישורים המשותפים ב-`~/.agents/skills`. פתחו אותו עם אייקון המסמך שליד ה-+ בפאנל הסוכנים, או `omarchy agent instructions --edit`, שגם מקשר אותו לכל harness ששומר קובץ גלובלי משלו: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` של Copilot, וכן הלאה. Crush ו-Amp קוראים את הקישור `~/.config/AGENTS.md`, בעוד omp, Kimi, ו-DeepSeek Harness קוראים את `~/.agents/AGENTS.md` ישירות. בחירת סוכן ברירת מחדל מקשרת אותו גם כן. קובץ הוראות שכבר היה לכם הופך למשותף אם עדיין לא היה כזה; אחרת הוא נשמר ליד הקישור כ-`.bak`. הריצו `omarchy agent instructions` כדי לקשר מחדש לאחר התקנת סוכן נוסף.

### פאנל הסוכנים

בסרגל העליון יש אייקון סוכנים. לפני שהגדרתם סוכן, הפאנל שלו מציע שלוש דרכים להתחיל: התחברו למנוי Claude, Codex, Grok, Gemini, Muse, Cursor, או Copilot, או תחת _עוד_ תוכנית קידוד של OpenCode Go, MiniMax, Synthetic, או Z.ai; שלמו לפי שימוש עם Fireworks, OpenCode Zen ו-Go, OpenRouter, או תחת _עוד_ DeepSeek או כל ספק אחר ש-OpenCode מתחבר אליו, כולם רצים ב-OpenCode; או הריצו את המודל הטוב ביותר למחשב שלכם, כאשר אחד מתאים לו. הראשון שתסיימו הופך לסוכן ברירת המחדל שלכם, וה-+ בפאנל, או _סוכן > הוספה_ בתפריט Omarchy, מציע את אותן שלוש מאוחר יותר. לאחר מכן, הפאנל מציב כל מנוי בעמוד אחד: כל סוכן וחשבון עם התוכנית שלו, מד לכל אחת ממגבלות ההפעלה של 5 שעות והמגבלות השבועיות שלו עם הזמן עד שהוא מתאפס (עברו מעליו לקבלת האחוז המדויק), או יתרת התשלום מראש שנותרה, תחת שורה שמתחלפת בין מה שהשתמשתם בו בכל אלה, כמו טוקנים השבוע והמודל שבו השתמשתם הכי הרבה. תחת _צרו משהו מגניב_ הוא מציע הנחיות פתיחה לערכת נושא, תוסף, אפליקציה או משחק חדשים שמוסרות את המשימה לסוכן ברירת המחדל שלכם. אפליקציות נבנות באופן שבו נבנו Hype, Monologue, ו-Omacut של Omarchy עצמה, ב-C++ וב-Qt Quick, בהתאם לכישור הסוכן omarchy-make-app, והמהדר וחלקי Qt שהן זקוקות להם מגיעים מותקנים. משחקים הם עמוד three.js יחיד ב-`~/Games/vibes`, בהתאם לכישור הסוכן omarchy-make-game, וכולם נפתחים ממשגר Game Vibes אחד בערכת הנושא הנוכחית; הם טוענים three.js מהרשת, ולכן זקוקים לחיבור כדי להתחיל. Claude Code, Codex, Grok, Kimi, Cursor והקצבת Grok Bot שלו, GitHub Copilot, Muse, Gemini (דרך Antigravity), ו-Devin מכוסים מהקופסה עם המגבלות שלהם, Kimchi עם התוכנית, הקרדיטים ששולמו מראש ותקציבי ההוצאות שלו, ו-Hermes, Mistral Vibe, ו-Qwen Code מציגים את ההפעלות והטוקנים שלהם לאחר שהשתמשתם בהם. תוכניות ספקים ומפתחות שבהם אתם משתמשים דרך pi, omp, או opencode מופיעים גם כן: OpenCode Zen ו-Go, תוכנית הקידוד Z.ai GLM, Ollama Cloud, תוכנית הטוקנים של MiniMax, ו-Synthetic עם המגבלות שלהם; OpenRouter ו-DeepSeek עם היתרות ששולמו מראש שלהם; Fireworks עם ההוצאות שלו ב-30 הימים האחרונים. גם טוקנים ממודלים שאתם מריצים על החומרה שלכם נספרים בסיכומים; למודלים עצמם יש פאנל משלהם, המתואר תחת [מודלים מקומיים](#local-models). כל סוכן נספר פעם אחת, תחת מי שמחייב עליו, לא משנה כמה harnesses אתם מפעילים אותו דרכם.

לחיצה שמאלית על אייקון הסרגל או לחיצה על `Super + Ctrl + X` עבור הפאנל, לחיצה ימנית להפעלת סוכן ברירת המחדל שלכם, ולחיצה אמצעית לרענון. רשומות השימוש שמאחוריו נוצרות מחדש כל 15 דקות על ידי `omarchy agent usage update`, והפאנל יכול אפילו למזג שימוש מהמכונות האחרות שלכם דרך תיקייה מסונכרנת. ראו את ה-README תחת `$OMARCHY_PATH/shell/plugins/agents/` להגדרות המלאות.

### מספר מנויים

אם אתם משלמים על יותר מתוכנית Claude, Codex, או Grok אחת — Max אישית ואחת של עבודה, למשל — Omarchy יכולה להשאיר את כולן מחוברות ולעבור ביניהן. הוסיפו מנוי באמצעות ה-+ בפאנל הסוכנים, שמוביל אתכם שם ממש, או באמצעות `omarchy agent account add claude Work` (או `codex`, או `grok`). אותו + ופקודה מתחברים ל-Gemini (`gemini`) ול-OpenCode (`opencode`), ושומרים מפתח API של Fireworks (`fireworks`) או OpenRouter (`openrouter`) ב-OpenCode; הפקודה גם מתחברת ל-Copilot (`copilot`), Cursor (`cursor`), ו-Muse (`muse`). אלה שומרים חיבור אחד כל אחד. היא מתקינה את ה-CLI אם הוא חסר. החשבון הראשון עבור ספק מתחבר דרך הדפדפן הרגיל שלכם, ממש במקום שבו ה-CLI תמיד מחפש. כל אחד אחריו מתחבר דרך חלון פרטי, כך שהחשבון שהדפדפן שלכם כבר מחובר אליו לא ייבחר בטעות; התחברו שם כחשבון שאתם מוסיפים, וסגרו קודם כל חלון פרטי שכבר פתוח לכם. לעולם אל תתנתקו מה-CLI כדי לעשות זאת: התנתקות מבטלת את החיבור השמור, ואותו חשבון יצטרך להתווסף שוב.

כדי להעתיק את חיבורי המנויים שלכם למכונת Omarchy אחרת דרך SSH, הריצו `omarchy agent account copy user@laptop`. השולח מספק מקלט זמני כאשר ליעד אין אחד מותקן, כך שמכונות Omarchy ישנות יותר יכולות לקבל חשבונות ללא עדכון. מקלטים מותקנים מקבלים קדימות. זה מעתיק את כל מנויי Claude, Codex, ו-Grok; הוסיפו שמות ספקים כדי לבחור אותם, כמו ב-`omarchy agent account copy laptop claude`. שמות חשבונות ומזהי פקודות תואמים למקור, כולל חשבונות שכבר קיימים ביעד. חשבונות יעד לא קשורים מקבלים סיומת מספרית אם שמותיהם מתנגשים, והגדרות, כישורים, תוספים והיסטוריית שיחות נשארים מקומיים לכל מכונה.

אישורי יעד קיימים נשמרים. חשבון מקור שכבר מחובר שם, שמו מסונכרן מבלי להחליף את האישורים שלו; חשבונות אחרים מתווספים לצדו. כדי להחליף אישורים שמורים עבור חשבונות תואמים, השתמשו ב-`omarchy agent account copy --replace laptop claude` לאחר יציאה מההפעלות של אותו חשבון ביעד. יעד טרי מקבל גם את החשבון הפעיל של המקור ואת העדפות המעבר שלו; יעד מבוסס שומר את שלו.

האישורים עוברים דרך SSH ומאוחסנים בקבצים פרטיים ביעד, אז העתיקו רק למכונות שאתם סומכים עליהן. זו העתקה חד-פעמית, לא סנכרון מתמשך. טוקני רענון של Codex יכולים להתחלף על ידי מכונה אחרת, ולהשאיר חיבור מועתק הזקוק לחידוש; חיבורים נפרדים נשארים הבחירה האמינה ביותר לשימוש בו-זמני במספר מכונות. ראו [הנחיות אימות החשבון של Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

חשבון אחד לכל ספק פעיל, וכל הפעלה חדשה מתחילה כמוהו: `cx`, `cy`, `claude`, `codex`, או `grok` רגילים, כל דבר המופעל דרך `omarchy agent`, ותסריטים או עורכים שמוצאים את ה-CLI ב-`PATH`. החליפו עם `omarchy agent account use work` (וחזרה עם `omarchy agent account use main`), או בפאנל על ידי לחיצה על מספר חשבון ואז `Enter` (או לחיצה על הכוכב שלו). גם הפעלות Claude פועלות מתחלפות, מההודעה הבאה שלהן: כל הפעלת Claude רצה ב-`~/.claude`, שמחזיקה תמיד את החיבור של החשבון הפעיל. הפעלת Claude שהתחילה בתיקייה של חשבון עצמו על ידי Omarchy ישנה יותר מחזיקה את אותו חיבור עד שהיא יוצאת, ולכן המעבר מזכיר את אותן הפעלות ומסיים מעצמו ברגע שהן נעלמות. הפעלות Codex ו-Grok פועלות נשארות על החשבון איתו התחילו. היסטוריית שיחות, הגדרות, כישורים ותוספים משותפים בין חשבונות, כך ש-`claude --continue` באותה תיקייה ממשיך איפה שהפסקתם בחשבון החדש.

עם יותר מחשבון אחד, הפאנל מציג את מגבלות כל חשבון זה לצד זה, עם כוכב מלא על זה שבשימוש. Omarchy מודיעה לכם כאשר החשבון הפעיל עובר 95% ממגבלה, ולחיצה על ההתראה עוברת לחשבון עם הכי הרבה מרווח. היא לעולם לא עוברת מעצמה. שנו את הסף עם `omarchy agent account threshold 90`. אם כל חשבון מעל הסף, תשמעו על כך פעם אחת, יחד עם איזה חשבון מתפנה ראשון. בעוד חשבון פעיל נמצא בתוך 15 נקודות מהסף שלו (80% בברירת המחדל), המגבלות שלו נבדקות כל שלוש דקות ולא כל 15.

`omarchy agent account list` מציג כל חשבון ואת המגבלות האחרונות שלו, `omarchy agent account remove work` שוכח אחד, ו-`omarchy agent account rename primary Hey` משנה שם של אחד (או לחצו על שם חשבון בפאנל). פקודות אלה פועלות על חשבונות סוכן ברירת המחדל שלכם; כדי להגיע לספק האחר, תנו את שמו תחילה, כמו ב-`omarchy agent account use codex side`. החיבור שכבר היה לכם ב-`~/.claude` או ב-`~/.codex` הוא החשבון _Main_. של Codex נשאר במקום שבו הוא; של Claude ממתין בתיקייה משלו בעוד חשבון אחר פעיל. חשבון שנשאר לא בשימוש יותר מכשמונה שעות יכול להציג _נדרש חיבור_; לחצו עליו כדי לחבר את אותו חשבון שוב ממש בפאנל, או החליפו אליו והתחילו הפעלה, שמרעננת את החיבור מעצמה. שרתי MCP שאתם מוסיפים עם `claude mcp add` מגיעים לכל חשבון Claude, מכיוון שכולם רצים ב-`~/.claude`; עבור Codex ו-Grok, שרתים שהיו לכם כשחשבון נוסף מגיעים איתו אליו, אבל מאוחרים יותר מגיעים רק לחשבון שבו הוספתם אותם. Claude Desktop שומר חיבור משלו, וכלי Codex או Grok המוגדרים עם נתיב מוחלט לקובץ בינארי של CLI אינם עוקבים אחר המעבר. `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, או `GROK_HOME` מפורש מקבל קדימות על פני החשבון הנבחר.

### אבחון קריסות

Omarchy עוקבת אחר systemd-coredump לקריסות תהליכים. לאחר שבחרתם סוכן ברירת מחדל, כל תוכנית שלכם שמטילה ליבה מביאה התראת "Process crashed" — לחצו עליה, והקריסה נמסרת לסוכן ברירת המחדל שלכם יחד עם כישור omarchy-diagnose-crash של Omarchy, שמוביל את הסוכן בביסוס העובדות מהטלת הליבה ובהחלטה האם הקריסה שווה דיווח ל-upstream. אתם יכולים גם להריץ אותו ידנית מול כל PID מ-`coredumpctl list` עם `omarchy agent crash <pid>`.

המעקב מופעל כברירת מחדל. כבו אותו תחת _טריגר > הפעלה/כיבוי > כיבוי לכידת קריסות_ (או עם `omarchy toggle crash-capture`) וההתראות מפסיקות; `omarchy agent crash <pid>` עדיין פועל ידנית.

ניתן גם להשתיק קריסות תוכנית אחת בכל פעם, וזה מה שהאבחון מציע לכם בסוף. `omarchy crash mute hyprland` מפסיק את ההתראות עבור אותה תוכנית בלבד, `omarchy crash mute hyprland off` מחזיר אותן, ו-`omarchy crash mute` בפני עצמו מפרט מה השתקתם. הוא מקבל את נתיב הקובץ הבינארי באותה שמחה כמו את שמו, כך ש-`omarchy crash mute /usr/bin/hyprland` עושה את אותו הדבר. צטטו שם עם רווח בו, כמו ב-`omarchy crash mute 'Some App'`. כל דבר אחר עדיין מודיע, והתוכנית המושתקת עדיין קורסת — זה מסתיר את התזכורת, זה לא מתקן שום דבר.

### אפליקציות שולחן עבודה

תפריט _התקנה > AI_ נושא גם כמה אפליקציות AI גרפיות: Amp Desktop, Antigravity Desktop, אפליקציית שולחן העבודה של ChatGPT, אפליקציית שולחן העבודה של Claude (הבטא ל-Linux של Anthropic, עם לשוניות Chat, Cowork, ו-Claude Code), Grok Bot לצ'אט עם המודלים של xAI, Herdr Desktop, Hermes Desktop, OpenClaw, אפליקציית שולחן העבודה של Perplexity, ו-T3 Code. Grok Bot היא אפליקציית הצ'אט לשולחן העבודה. סוכן הקידוד הוא פקודת `grok`.

Hermes Desktop היא זו שכדאי להכיר, מכיוון שלמכונה יש Hermes אחד, והוא של האפליקציה: Hermes מותקן תמיד רק דרך האפליקציה, ופקודת `hermes` שסוכן ברירת המחדל מריץ היא של האפליקציה. בחירת Hermes כסוכן ברירת המחדל מתקינה את אותו דבר שהערך _התקנה > AI_ עושה: החבילה, וזמן ריצה של Hermes תחת `~/.hermes` שהמתקין של Hermes עצמו מגדיר, שלוקח כמה דקות בפעם הראשונה. זמן הריצה הזה הוא ה-Hermes האחד שפקודת ה-`hermes` בטרמינל, סוכן ברירת המחדל והאפליקציה כולם משתמשים בו, והוא מעדכן את עצמו עם `hermes update` במקום לחכות לגרסת Omarchy. התקנתו גם נותנת ל-Hermes את ערכת הנושא של Omarchy כ-skin בשם `omarchy`, שכל משטח Hermes עוקב אחריו כאשר אתם מחליפים ערכות נושא; בחרו אחר תחת הגדרות Appearance של Hermes או עם `/skin` אם אתם מעדיפים שלא, ו-Omarchy משאירה את הבחירה הזו לבד. הסרת האפליקציה תחת _הסרה > AI_ סוגרת תחילה את Hermes, כולל ה-gateway, לוקחת את זמן הריצה הזה איתה, ושומרת את הצ'אטים, הזיכרונות והכישורים ש-Hermes כתב לעצמו אלא אם תגידו אחרת: היא שואלת, כשברירת המחדל היא לא, האם גם הנתונים האלה והגדרות החיבור שלכם צריכים להיעלם.

חוויית שולחן העבודה של OpenClaw היא ה-Control UI שלו, שנפתח כאפליקציית רשת בגיבוי ה-gateway המקומי שלו. OpenClaw חי ב-`~/.openclaw` ומעדכן את עצמו: השתמשו בכפתור "Update Gateway" של ה-Control UI או הריצו `openclaw update`, וה-gateway מופעל מחדש על הגרסה החדשה. Omarchy בוחרת רק את ההפצה שהתקנה טרייה מתחילה ממנה. OpenClaw יכול להיות גם סוכן ברירת המחדל שלכם: בחירתו תחת _סוכן > Harness_ מגדירה את אותו עותק ב-`~/.openclaw`, והסוכן פותח את ממשק הטרמינל של OpenClaw המחובר ל-gateway שלו. הסרת OpenClaw תחת _הסרה > AI_ לוקחת את שירות ה-gateway ואת האפליקציה איתה ואז שואלת האם גם `~/.openclaw` צריך להיעלם, מכיוון שזה מחזיק את הצ'אטים והאישורים שלכם לצד OpenClaw עצמו וזמני הריצה של התוספים שהוא מוריד; ברירת המחדל שומרת אותו, והתקנת OpenClaw שוב מרימה אותו חזרה.

Herdr Desktop היא אפליקציית שולחן העבודה [Herdr](https://herdr.dev): מרחבים, לשוניות וחלוניות של טרמינלים וסוכני קידוד שממשיכים לרוץ בליבה שלה כאשר אתם סוגרים את החלון. היא מגיעה מהמתקין של Herdr עצמו ולא מחבילה, ולכן חיה ב-`~/.local/share/herdr-app`, מביאה את הליבה שלה ב-`~/.local/bin/herdr-core` כאשר עדיין אין לכם אחת, ומעדכנת את שניהם בעצמה. היא יושבת לצד פקודת `herdr` ש-Omarchy מספקת ב-`Super + Ctrl + Return` ולא מחליפה אותה, ומקבלת את המקשים הישירים של אותה פקודה: `Alt + Return` ו-`Alt + Shift + Return` מפצלים חלונית למטה או ימינה, `Alt + Escape` סוגר אותה, `Ctrl + Alt + Arrow` עובר בין חלוניות, `Alt + 1..9` ו-`Alt + Left/Right` בוחרים לשונית, ו-`Alt + Up/Down` עוברים בין מרחבים. `Ctrl + 1..9` בוחר מרחב ו-`Alt + Shift + Up/Down` עובר בין סוכנים. מקשי הקידומת `Ctrl + Space` נשארים לטרמינל בלבד, מכיוון שהאפליקציה לא יכולה להחזיק מקש Ctrl רגיל לרצף. Omarchy כותבת אלה ל-`~/.config/herdr-app/keys.json`, ו-`omarchy-refresh-herdr-app` מחזיר אותם. התקנתה בוחרת את ערכת הנושא Omarchy של Herdr, שעוקבת אחר ערכת הנושא של Omarchy שלכם מאז. Herdr שומרת ערכת נושא אחת למצב בהיר ואחת למצב כהה, כך שלאחר מעבר בין ערכת נושא כהה לבהירה של Omarchy, בחרו Omarchy בבוחר ערכות הנושא של Herdr פעם נוספת עבור המצב האחר.

T3 Code רץ מהפצת AppImage הרשמית שלו ב-`~/.local/share/t3code` ולא מחבילה, ולכן מעדכן את עצמו. התקנתו שואלת האם להתחיל בערוץ Stable או Nightly; החליפו מאוחר יותר בהגדרות של T3 Code. השרשורים וההגדרות שלכם חיים ב-`~/.t3`, והסרת T3 Code תחת _הסרה > AI_ לוקחת אותם איתה.

### מודלים מקומיים

הריצו מודל פתוח במכונה שלכם עבור סוכני הקידוד שלכם. ההנחיות והקוד שלכם נשארים במכונה; שום דבר שנשלח למודל לא עוזב אותה. התחילו עם:

```bash
omarchy models use best text
```

זה מגדיר את מודל הטקסט הטוב ביותר למכונה זו, הסוג שהסוכנים שלכם משתמשים בו. למודלי תמונה, וידאו ומוזיקה יש טוב ביותר משלהם: `omarchy models use best image`, `video` או `music`. הריצו `omarchy models use best` כדי לראות את הבחירה של כל סוג למכונה זו.

או פתחו את פאנל המודלים המקומיים מאייקון הניצוצות שלו בסרגל העליון, ליד אייקון הסוכנים, או עם Super + Ctrl + Alt + X, ובחרו +. האייקון מופיע כאשר מודל מתאים למכונה זו. Podman, שמריץ את המודלים, מגיע עם Omarchy, וכך גם ערכת הכלים למכולות של NVIDIA במכונת NVIDIA, שנותנת להם את ה-GPU; אם אחד מהם חסר, ההגדרה הראשונה מתקינה אותו. Omarchy אז בוחרת את המודל המומלץ למכונה זו, מורידה אותו ומפעילה אותו. צפו להורדה של עשרות GB ושרוב זיכרון המכונה יהיה בשימוש בזמן שהמודל רץ: Flash Next משתמש בכ-100 GiB עם הקשר ה-256K המלא שלו. אם מודלים אחרים מחזיקים את הזיכרון שהוא צריך, הוא מוגדר מופסק, מוכן להתחיל ברגע שתעצרו אחד. המודל נעצר בעת התנתקות; עצרו אותו בעצמכם כאשר אתם צריכים את הזיכרון למשהו אחר.

`omarchy models list` מציג את האפשרויות ומסביר מדוע חלקן לא מתאימות. כדי להגדיר אחד אחר, הריצו `omarchy models use <recipe>`. היום, `qwen3.8-flash-next-gufo` ו-`qwen3.8-27b-gufo` זמינים למכונות Strix Halo עם 128 GB; ה-27B לוקח כ-40 GiB, כך שהוא משאיר מקום לעבודה אחרת. במחשב נייד עם 64 GB עם Arc B390 של Intel, `qwen3.6-35b-a3b-llamacpp` רץ בכ-30 GiB. מתכונים והמלצות חדשים מגיעים עם `omarchy update`, דרך החבילה.

כל מודל שאתם מגדירים מקבל שורה משלו בפאנל המודלים המקומיים: הפעילו כדי להתחיל אותו, השהו כדי לעצור אותו ולפנות את זיכרונו, וכפתור הטרמינל כדי לפתוח את הסוכן שלכם עליו. לרוחב החלק העליון, סרגל מציג איך זיכרון המכונה מתחלק בין Omarchy עצמה (המערכת והאפליקציות שלכם), כל מודל פועל, ומה פנוי. הצביעו על מודל מופסק והסרגל מציג האם הוא מתאים, או כמה חסר לו. מספר מודלים יכולים לרוץ בו-זמנית כאשר הם מתאימים יחד בזיכרון; אם אחד לא מתאים, Omarchy אומרת איזה מודל פועל לעצור. גררו שורות לפי הלוגו שלהן כדי לסדר אותן מחדש, ולחצו Delete על שורה נבחרת כדי להסיר מודל ואת ההורדה שלו.

כל מודל קידוד שאתם מגדירים מקבל גם ערך משלו במשגר האפליקציות, תחת שם המודל ועם הלוגו של יוצרו, באופן שבו חיבור ל-Claude, Codex או Grok מוסיף אחד. הוא פותח את הסוכן שלכם על אותו מודל, ומפעיל את המודל תחילה אם הוא לא רץ: הטרמינל מציג אותו נטען ומוסר לסוכן ברגע שהוא מוכן. הסרת מודל מסירה את הערך שלו.

לא כל מודל הוא לקידוד. מודלי תמונה, וידאו ומוזיקה נפתחים במקום זאת ב-Fantasi, האפליקציה של Omarchy ליצירת תמונות, וידאו ומוזיקה עם מודל שרץ במכונה זו, שנבחר שם או מהשורה שלהם בפאנל המודלים המקומיים.

מודל ממשיך לרוץ בדיוק כפי שהוגדר, כך שעדכון Omarchy לעולם לא מפעיל מחדש אחד תחת הסוכנים שלכם. כאשר ל-Omarchy יש זמן ריצה חדש יותר או משקולות חדשות יותר למודל שהגדרתם, השורה שלו מציגה כפתור עדכון: לחצו עליו והמודל מוגדר שוב ברקע, מוריד רק מה שהשתנה, ומופעל מחדש על הגרסה החדשה. מודל שהיה מופסק נשאר מופסק. `omarchy models update` עושה את אותו הדבר לכל מודל מטרמינל.

משורת הפקודה, `omarchy models start <recipe>` ו-`omarchy models stop <recipe>` עושים את אותו הדבר, `omarchy models status` מציג כל מודל, ו-`omarchy agent --local` פותח את המודל האחרון שהתחלתם ב-pi, לא משנה מה סוכן ברירת המחדל שלכם. כדי להפוך את אותו מודל למה שמקש הסוכן, קונסולת Quake, ו-_צרו משהו_ פותחים, הריצו `omarchy default agent local` או בחרו _מודל מקומי_ תחת _סוכן > Harness_. pi גם מפרט כל מודל שהגדרתם, ואלה במכונות שחיברתם אליהן, בבוחר המודלים שלו, כך ש-`pi` רגיל מגיע אליהם גם כן. כל לקוח תואם OpenAI יכול להתחבר גם כן: `status` מציג את כתובת כל מודל (הראשונה היא `http://127.0.0.1:11435/v1`), שם המתכון הוא המודל, והמפתח נמצא ב-`~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` מוחק מודל ואת ההורדות שאף מודל אחר לא משתמש בהן.

זמני ריצה של צד שלישי מסומנים עם המו"ל שלהם. Omarchy מריצה כל מודל ללא גישה לרשת.

### מודלי LLM מקומיים

Omarchy ממליצה על שתי דרכים להריץ מודלי LLM מקומיים: LM Studio ו-Ollama. LM Studio מספקת ממשק GUI למציאת מודלים פתוחים במשקליהם, להתקנתם ולהרצתם. זו דרך מעולה להתחיל בקלות. Ollama מציעה CLI לעשות זאת באופן דומה. אבל אם אתם חדשים במודלים מקומיים, הייתי מתחיל עם LM Studio. אתם יכולים להתקין כל אחת תחת _התקנה > AI_ בתפריט Omarchy.

### כישורי Omarchy

כישורי סוכן עוזרים ל-AI להשתמש בכלים ספציפיים בדרך ספציפית, ו-Omarchy מספקת שבעה מהם. כישור omarchy מכסה התאמת המערכת, כמו שינוי תצורת Hyprland שלכם או התאמת הסרגל. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app, ו-omarchy-make-game מכסים יצירת משהו חדש, omarchy-contribute מכסה דיווח על באג או שליחת תיקון ל-upstream, ו-omarchy-diagnose-crash עובר על הטלת ליבה של קריסה. הם מקושרים באמצעות קישורים סימבוליים לתיקיות הכישורים עבור Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` וכל `~/.hermes/profiles/*/skills`), והמיקום הגנרי `~/.agents/skills`, כך שרוב ה-harnesses קולטים אותם אוטומטית. תיקיית כישור משלכם עם אותו שם מקבלת קדימות.

אבל עליכם להתייחס לכישורים אלה כניסיוניים. מודלים שונים ישתמשו בהם להשפעה שונה. עדיף לרוץ במצב תכנון תחילה, כך שיהיה לכם מושג מה הסוכן היה רוצה לשנות. ואז היו מוכנים לבטל שינויים או אפילו להפעיל `omarchy reinstall configs`, אם הסוכן מבלגן הכל.
