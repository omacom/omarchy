# AI

Omarchy כוללת משגרים לסוכני הקידוד שלמטה מבלי לבחור עבורך ברירת מחדל. הרץ פקודה כדי להתקין את ה־CLI שלה בשימוש הראשון, ולאחר מכן בצע אימות כשתתבקש. Hermes הוא היוצא מן הכלל: שום דבר לא מותקן עבורו בשימוש הראשון, ובחירתו מתקינה את Hermes Desktop, כפי שמסביר הקטע _אפליקציות שולחניות_ שלמטה.

### התקנה ועדכון של סוכנים

למעט Hermes, סוכנים אלה משתמשים בהתקנה העצלה של mise: ההפעלה הראשונה מתקינה את ה־CLI, והפעלות מאוחרות יותר משתמשות בו מחדש. mise גם בודק אם קיימת גרסה חדשה לסוכן מותקן לכל היותר פעם בארבע שעות, ממש לפני שהוא מופעל או ברקע בהנחיית מעטפת. אם העדכון הזה נכשל או שאתה במצב לא מקוון, הגרסה המותקנת מופעלת. `omarchy update` מעדכן סוכנים מותקנים יחד עם שאר Omarchy, ו־`mup` מעדכן רק כלים המנוהלים על ידי mise.

המעדכן של סוכן עצמו, כגון `claude update`, `codex update`, או כפתור עדכון באפליקציה, לא מעדכן את ההתקנה המנוהלת על ידי mise. `codex update` נכשל, ו־`claude update` יכול לדווח על הצלחה תוך התקנת עותק נפרד ש־mise לא עוקב אחריו. אם אתה מעדיף להשתמש במתקין ובמעדכן המקוריים של סוכן, הוסף אותו אל `disable_tools`; ראה [כלי CLI מותקנים מראש](18-development-tools.md#preinstalled-cli-tools).

כדי להתקין את כל הכלים העצלים שהוגדרו לפני שתזדקק להם, הרץ `mise install --include-lazy`. זה כולל את כלי ה־CLI המוגדרים כברירת מחדל האחרים של Omarchy וגם את הסוכנים. ראה [כלי CLI מותקנים מראש](18-development-tools.md#preinstalled-cli-tools) להתקנת כלי יחיד או לשימוש בהתקנה משלך.

`grok` מותקן דרך חבילת `grok` הראשונה במעלה של mise, באותה דרך כמו `claude` ו־`codex`. הרץ `grok`, או בחר אותו תחת _הגדרות > ברירות מחדל > סוכן_. דלג על מתקין ה־`curl | bash` ב־x.ai. מסלול זה מכניס עותק שני אל `~/.grok/bin`, מקדים אותו ב־`PATH`, ודורס את העטיפה של Omarchy.

`dsh` פותח את ממשק הדפדפן שלו על `127.0.0.1:3080`, כאשר תיקיית ההפעלה היא סביבת העבודה המוגדרת כברירת מחדל שלו. ממשק הדפדפן שלו לא מקבל הנחיית פתיחה, ולכן `omarchy agent prompt` פותח אותו כשההנחיה על הלוח שלך להדבקה. Omarchy מפעילה אותו עם הגדרת ההרשאות מראש ללא אישור של DeepSeek. DeepSeek Harness מעלה יומני הפעלה אל DeepSeek כאשר אתה משתמש ב־API הדגמים הרשמי שלו; כבה זאת תחת _הגדרות > כללי > Upload Session Log_ בממשק הדפדפן שלו. משוב שאתה שולח לו מועלה יחד עם ההפעלה, אלא אם כן אתה מפעיל אותו עם `DSH_TELEMETRY_MODE=DISABLED`.

### סוכן ברירת המחדל

בחר את סוכן ברירת המחדל שלך עם `omarchy default agent <name>` או תחת _הגדרות > ברירות מחדל > סוכן_ בתפריט Omarchy (`Super + Space`). אם הסוכן עדיין לא מותקן, בחירתו מתקינה אותו תחילה. Omarchy טרייה תזמין אותך לבחור זאת בהודעת מערכת חד־פעמית.

בחירת Claude גם מנסה להגדיר את התוסף לדפדפן שלו עבור Chromium, Chrome, Brave, Brave Origin ו־Edge. הגדרת התוסף חלה על כל המשתמשים ועשויה לבקש את סיסמת המערכת שלך; ביטול או כשל בהתקנת התוסף עדיין בוחרים ומפעילים את Claude. הפעל מחדש את הדפדפן, הפעל את התוסף אם תתבקש, והיכנס אל Claude כדי לסיים את החיבור אליו. הרץ `/chrome` ב־Claude כדי לבדוק את החיבור. Firefox ו־Zen לא תומכים בתוסף זה. אם Claude כבר היה ברירת המחדל שלך לפני שההגדרה הזאת נוספה, בחר אותו שוב כדי להתקין את התוסף.

לאחר שבחרת, `Super + Shift + Ctrl + A` מפעיל את סוכן ברירת המחדל בחלון מסוף ייעודי (או מציג את הבורר אם עדיין לא בחרת). אפשר גם להפעיל אותו ישירות לתוך משימה עם `omarchy agent prompt "Review this project"`. Freebuff ו־DeepSeek Harness לא מקבלים הנחיית פתיחה, ולכן הם במקום זאת נפתחים כשההנחיה על הלוח שלך להדבקה. סוכנים המופעלים כך פועלים ללא השגחה במצבי אל־תעצור־לשאול שלהם, אז היה מוכן לכך שהם באמת יעשו דברים! ל־MiniMax Code אין מצב כזה להפעלות האינטראקטיביות שלו, ולכן הוא מבקש הרשאות כרגיל. ומאחר שסוכנים מסרבים לזכור אמון בתיקיית הבית שלך, הפעלות מתוך `$HOME` מתחילות במקום זאת בתוך `~/Work`.

יש גם קיצורי דרך למסוף: `a` מריץ את סוכן ברירת המחדל בתוך המסוף הנוכחי, בעוד `c`, `cx` ו־`cy` מפעילים ישירות את OpenCode, Claude Code ו־Codex (שוב במצבי האישור האוטומטי שלהם). שינויי ערכת נושא מסתנכרנים גם אל הסוכנים: Claude Code, Pi, OpenCode, ו־Hermes (לאחר ש־Omarchy התקינה אותו) כולם עוקבים אחריך כשאתה מחליף את ערכת הנושא של Omarchy.

### פאנל הסוכנים

בפס העליון יש סמל סוכנים. לפני שהקמת סוכן, הפאנל שלו מדריך אותך דרך כניסה אל Claude, Codex או Grok, והראשון שבהם הופך לסוכן ברירת המחדל שלך. לאחר מכן, הפאנל מכניס כל מנוי לעמוד אחד: כל סוכן וחשבון עם התוכנית שלו, מד לכל אחת ממגבלות הפעלת 5 השעות והמגבלות השבועיות שלו עם הזמן עד לאיפוסו (רחף כדי לראות את האחוז המדויק), או יתרת התשלום מראש שנותרה, תחת שורה שמתחלפת בין מה שהשתמשת בו בכולם, כמו אסימונים השבוע והדגם שבו השתמשת הכי הרבה. תחת _צור משהו_ הוא מציע הנחיות פתיחה לערכת נושא, תוסף, או אפליקציה חדשים שמעבירים את המשימה אל סוכן ברירת המחדל שלך. אפליקציות נבנות באותה דרך שבה נבנות Hype, Monologue ו־Omacut של Omarchy עצמה, ב־C++ וב־Qt Quick, לפי ה־skill של omarchy-app לסוכנים, והמהדר ורכיבי ה־Qt שהן זקוקות להם מגיעים מותקנים. Claude Code, Codex, Grok, Kimi, Cursor והקצבת Grok Bot שלו, GitHub Copilot, Muse, Antigravity, Kimchi ו־Devin מכוסים מהקופסה עם המגבלות שלהם, ו־Hermes, Mistral Vibe ו־Qwen Code מציגים את ההפעלות והאסימונים שלהם ברגע שהשתמשת בהם. תוכניות ומפתחות של ספקים שבהם אתה משתמש דרך pi, omp או opencode מופיעים גם כן: OpenCode Zen ו־Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan ו־Synthetic עם המגבלות שלהם; Fireworks, OpenRouter ו־DeepSeek עם יתרות התשלום מראש שלהם; והדגמים שאתה מריץ על החומרה שלך תחת דגמים מקומיים. כל סוכן נספר פעם אחת, תחת מי שמחייב עליו, לא משנה דרך כמה harnesses אתה מפעיל אותו.

לחיצה שמאלית על סמל הפס מציגה את הפאנל, לחיצה ימנית מפעילה את סוכן ברירת המחדל שלך. רשומות השימוש שמאחוריו נוצרות מחדש כל 15 דקות על ידי `omarchy agent usage-update`, והפאנל יכול אפילו למזג שימוש מהמכונות האחרות שלך דרך תיקייה מסונכרנת. ראה את ה־README תחת `$OMARCHY_PATH/shell/plugins/agents/` להגדרות המלאות.

### מספר מנויים

אם אתה משלם על יותר מתוכנית Claude, Codex או Grok אחת — תוכנית Max אישית ותוכנית עבודה, נניח — Omarchy יכולה לשמור את כולן מחוברות ולעבור ביניהן. הוסף מנוי עם ה־+ בפאנל הסוכנים, שידריך אותך דרך זה שם, או עם `omarchy agent account add claude Work` (או `codex`, או `grok`). זה מתקין את ה־CLI אם הוא חסר. החשבון הראשון לספק נכנס דרך הדפדפן הרגיל שלך, בדיוק היכן שה־CLI תמיד מחפש. כל אחד אחרי זה נכנס דרך חלון פרטי, כדי שהחשבון אליו הדפדפן שלך כבר מחובר לא ייבחר בטעות; היכנס שם בתור החשבון שאתה מוסיף, וסגור תחילה כל חלון פרטי כבר פתוח שהיה לך. לעולם אל תצא מה־CLI כדי לעשות זאת: יציאה מבטלת את הכניסה השמורה, ואותו חשבון יצטרך להתווסף שוב.

כדי להעתיק את כניסות המנוי שלך למכונת Omarchy אחרת דרך SSH, הרץ `omarchy agent account copy user@laptop`. השולח מספק מקלט זמני כאשר ליעד אין אחד מותקן, כדי שמכונות Omarchy ותיקות יותר יוכלו לקבל חשבונות בלי עדכון. מקלטים מותקנים מקבלים קדימות. זה מעתיק את כל המנויים של Claude, Codex ו־Grok; הוסף שמות ספקים כדי לבחור אותם, כגון `omarchy agent account copy laptop claude`. שמות החשבונות ומזהי הפקודות תואמים את המקור, כולל חשבונות שכבר קיימים ביעד. חשבונות יעד לא קשורים מקבלים סיומת מספרית אם שמותיהם מתנגשים, והגדרות, skills, תוספים והיסטוריית שיחות נשארים מקומיים לכל מכונה.

אישורים קיימים ביעד נשמרים. חשבון מקור שכבר מחובר שם מקבל את שמו מסונכרן בלי להחליף את האישורים שלו; חשבונות אחרים מתווספים לצידו. כדי להחליף אישורים שמורים לחשבונות תואמים, השתמש ב־`omarchy agent account copy --replace laptop claude` לאחר שסיימת את ההפעלות של אותו חשבון ביעד. יעד חדש מקבל גם את החשבון הפעיל של המקור ואת העדפות המעבר שלו; יעד שהוקם כבר שומר על שלו.

אישורים עוברים דרך SSH ונשמרים בקבצים פרטיים ביעד, אז העתק רק למכונות שאתה בוטח בהן. זו העתקה חד־פעמית, לא סנכרון שוטף. אסימוני רענון של Codex יכולים להתחלף על ידי מכונה אחרת, ולהותיר כניסה מועתקת כשהיא זקוקה לחידוש; כניסות נפרדות נשארות הבחירה האמינה ביותר לשימוש בו־זמני במספר מכונות. ראה [הנחיות אימות החשבון של Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

חשבון אחד לכל ספק פעיל, וכל הפעלה חדשה מתחילה בתורו: `cx`, `cy`, `claude`, `codex` או `grok` רגילים, כל דבר המופעל דרך `omarchy agent`, וסקריפטים או עורכים שמוצאים את ה־CLI ב־`PATH`. עבור עם `omarchy agent account use work` (ובחזרה עם `omarchy agent account use main`), או בפאנל על ידי לחיצה על מספר של חשבון ולאחר מכן `Enter` (או לחיצה על כפתור השימוש שלו). הפעלות שכבר פועלות נשארות על החשבון איתו הן התחילו. היסטוריית שיחות, הגדרות, skills ותוספים משותפים בין חשבונות, כך ש־`claude --continue` באותה תיקייה ממשיך היכן שעצרת בחשבון החדש.

עם יותר מחשבון אחד, הפאנל מציג את המגבלות של כל חשבון זה לצד זה, כאשר הפעיל מסומן. כברירת מחדל Omarchy מודיעה לך כאשר החשבון הפעיל עובר 95% ממגבלה, ולחיצה על ההודעה מעבירה אל החשבון עם הכי הרבה מרווח. רחף מעל שורה של חשבון בפאנל ולחץ על Autoswitch שמופיע לצד Use (או לחץ `m`), או הרץ `omarchy agent account mode auto`, כדי שהוא יעבור מעצמו במקום זאת; בזמן שהוא פועל, Autoswitch תופס את מקומו של Use, ולחיצה עליו שוב חוזרת להתרעה. הוסף מספר כדי לשנות את הסף, כגון `omarchy agent account mode auto 90`. אם כל חשבון חורג מהסף, תשמע על כך פעם אחת, יחד עם איזה חשבון מתפנה ראשון. בזמן שחשבון פעיל נמצא בתוך 15 נקודות מהסף שלו (80% בברירת המחדל), המגבלות שלו נבדקות כל שלוש דקות ולא כל 15.

`omarchy agent account list` מציג כל חשבון ואת המגבלות האחרונות שלו, `omarchy agent account remove work` שוכח אחד, ו־`omarchy agent account rename primary Hey` משנה שם של אחד (או לחץ על שמו של חשבון בפאנל). פקודות אלה פועלות על חשבונות סוכן ברירת המחדל שלך; כדי להגיע לספק האחר, תן לו שם תחילה, כגון `omarchy agent account use codex side`. הכניסה שכבר הייתה לך ב־`~/.claude` או `~/.codex` היא החשבון _Main_ והיא נשארת היכן שהיא. חשבון שנותר ללא שימוש יותר מכשמונה שעות יכול להציג _נדרשת כניסה_; לחץ עליו כדי להיכנס אל אותו חשבון שוב ממש בפאנל, או התחל הפעלה בו, שתרענן את הכניסה מעצמה. שרתי MCP שהיו לך כאשר חשבון נוסף מגיעים איתו אליו, אבל כאלה שתוסיף מאוחר יותר עם `claude mcp add` מגיעים רק אל החשבון שהוספת אותם בו. Claude Desktop וכלים שהוגדרו עם נתיב מוחלט לקובץ בינארי של CLI לא עוקבים אחרי המעבר. `CLAUDE_CONFIG_DIR`, `CODEX_HOME` או `GROK_HOME` מפורשים מקבלים קדימות על פני החשבון שנבחר.

### אבחון קריסות

Omarchy עוקבת אחרי systemd-coredump אחרי קריסות תהליכים. כאשר משהו מבצע segfault, תקבל הודעה על "Process crashed" — לחץ עליה, והקריסה מועברת אל סוכן ברירת המחדל שלך יחד עם ה־skill של Omarchy לאבחון קריסות, שמדריך את הסוכן דרך קביעת העובדות מה־core dump וההחלטה האם הקריסה שווה דיווח ל־upstream. אפשר גם להריץ אותו ידנית מול כל PID מתוך `coredumpctl list` עם `omarchy agent crash <pid>`.

המעקב מופעל כברירת מחדל. כבה אותו תחת _Trigger > Toggle > Crash Capture_ (או עם `omarchy toggle crash-capture`) וההודעות ייפסקו; `omarchy agent crash <pid>` עדיין עובד ידנית.

אפשר גם להשתיק קריסות תוכנית אחת בכל פעם, וזה מה שהאבחון מציע לך בסוף. `omarchy crash mute hyprland` מפסיק את ההודעות לאותה תוכנית בלבד, `omarchy crash mute hyprland off` מחזיר אותן, ו־`omarchy crash mute` בפני עצמו מפרט את מה שהשתקת. הוא מקבל את נתיב הקובץ הבינארי בשמחה בדיוק כמו את שמו, כך ש־`omarchy crash mute /usr/bin/hyprland` עושה את אותו הדבר. גרוש שם עם רווח בתוכו, כגון `omarchy crash mute 'Some App'`. כל דבר אחר עדיין מודיע, והתוכנית המושתקת עדיין קורסת — זה מסתיר את התזכורת, זה לא מתקן שום דבר.

### אפליקציות שולחניות

תפריט _התקנה > AI_ נושא גם כמה אפליקציות AI גרפיות: אפליקציית שולחן העבודה של ChatGPT, אפליקציית שולחן העבודה של Claude (גרסת הבטא של Anthropic ל־Linux, עם לשוניות Chat, Cowork ו־Claude Code), Grok Bot לשיחה עם הדגמים של xAI, Hermes Desktop, OpenClaw, אפליקציית שולחן העבודה של Perplexity ו־T3 Code. Grok Bot היא אפליקציית הצ'אט לשולחן העבודה. סוכן הקידוד הוא הפקודה `grok`.

Hermes Desktop היא זו שצריך לדעת עליה, כי למכונה יש Hermes אחד, והוא של האפליקציה: Hermes מותקן רק אי־פעם דרך האפליקציה, והפקודה `hermes` שסוכן ברירת המחדל מריץ היא של האפליקציה. בחירת Hermes כסוכן ברירת המחדל מתקינה את אותו דבר שמתקין הערך _התקנה > AI_: את החבילה, ו־runtime של Hermes תחת `~/.hermes` המוקם על ידי המתקין של Hermes עצמו, שלוקח כמה דקות בפעם הראשונה. אותו runtime הוא ה־Hermes היחיד שהפקודה `hermes` במסוף, סוכן ברירת המחדל והאפליקציה כולם משתמשים בו, והוא מעדכן את עצמו עם `hermes update` ולא מחכה לגרסה של Omarchy. התקנתו גם מעבירה אל Hermes את ערכת הנושא של Omarchy כסקין בשם `omarchy`, שכל משטח של Hermes עוקב אחריו כשאתה מחליף ערכות נושא; בחר אחרת תחת הגדרות המראה של Hermes או עם `/skin` אם אתה מעדיף שלא, ו־Omarchy משאירה את הבחירה הזאת בשקט. הסרת האפליקציה תחת _הסרה > AI_ סוגרת תחילה את Hermes, כולל ה־gateway, לוקחת איתה את אותו runtime, ושומרת את הצ'אטים, הזיכרונות וה־skills ש־Hermes כתב לעצמו אלא אם כן אתה אומר לה אחרת: היא שואלת, כשברירת המחדל היא לא, האם הנתונים האלה והגדרות החיבור שלך צריכים ללכת גם הם.

חוויית שולחן העבודה של OpenClaw היא ממשק הבקרה שלו, שנפתח כאפליקציית אינטרנט המגובה על ידי ה־gateway המקומי שלו עצמו. OpenClaw חי בתוך `~/.openclaw` ומעדכן את עצמו: השתמש בכפתור "Update Gateway" של ממשק הבקרה או הרץ `openclaw update`, וה־gateway מופעל מחדש על הגרסה החדשה. Omarchy בוחרת רק את הגרסה שממנה מתחילה התקנה טרייה. הסרת OpenClaw תחת _הסרה > AI_ לוקחת איתה את שירות ה־gateway ואת האפליקציה, ולאחר מכן שואלת האם `~/.openclaw` צריך ללכת גם הוא, מאחר שהוא מכיל את הצ'אטים והאישורים שלך לצד OpenClaw עצמו ו־runtime־י התוספים שהוא מוריד; ברירת המחדל שומרת אותו, והתקנת OpenClaw שוב תאסוף אותו בחזרה.

T3 Code פועל מגרסת ה־AppImage הרשמית שלו בתוך `~/.local/share/t3code` ולא מתוך חבילה, ולכן הוא מעדכן את עצמו. התקנתו שואלת האם להתחיל בערוץ Stable או Nightly; החלף מאוחר יותר בהגדרות של T3 Code. השרשורים וההגדרות שלך חיים בתוך `~/.t3`, והסרת T3 Code תחת _הסרה > AI_ לוקחת אותם איתה.

### דגמים מקומיים

הרץ דגם פתוח על המכונה שלך עבור סוכני הקידוד שלך. ההנחיות והקוד שלך נשארים על המכונה; שום דבר שנשלח אל הדגם לא עוזב אותה. התחל עם:

```bash
omarchy agent local use best
```

או, בפאנל הסוכנים בפס העליון, בחר + ולאחר מכן Local AI, שמופיע כאשר דגם מתאים למכונה הזאת. בפעם הראשונה, זה מתקין את Podman, שמריץ את הדגמים, ובמכונת NVIDIA את ערכת הכלים של NVIDIA למכולות, שנותנת להם את ה־GPU. Omarchy לאחר מכן בוחרת את הדגם המומלץ למכונה הזאת, מורידה אותו ומפעילה אותו. צפה להורדה של עשרות GB ולכך שרוב זיכרון המכונה יהיה בשימוש בזמן שהדגם פועל: Flash Next משתמש בכ־100 GiB עם הקשר ה־256K המלא שלו. אם דגמים אחרים מחזיקים את הזיכרון שהוא זקוק לו, הוא מוקם כשהוא מופסק, מוכן להתחיל ברגע שתפסיק אחד. הדגם נעצר ביציאה; עצור אותו בעצמך כאשר אתה זקוק לזיכרון למשהו אחר.

`omarchy agent local list` מציג את האפשרויות ומסביר מדוע חלקן לא מתאימות. כדי להקים אחד אחר, הרץ `omarchy agent local use <recipe>`. נכון להיום, `qwen3.8-flash-next-halogen` ו־`qwen3.8-27b-gufo` זמינים למכונות Strix Halo עם 128 GB. מתכונים והמלצות חדשים מגיעים עם `omarchy update`, דרך החבילה.

כל דגם שאתה מקים מקבל שורה משלו בפאנל הסוכנים, לצד המנויים שלך: הפעל כדי להתחיל אותו, השהה כדי לעצור אותו ולשחרר את הזיכרון שלו, וכפתור המסוף כדי לפתוח את הסוכן שלך עליו. כמה מהם יכולים לפעול בו־זמנית כאשר הם נכנסים לזיכרון יחד; אם אחד לא נכנס, Omarchy אומרת איזה דגם פועל להפסיק. גרור שורות כדי לסדר אותן מחדש, ולחץ על Delete בשורה שנבחרה כדי להסיר דגם ואת הורדתו.

משורת הפקודה, `omarchy agent local start <recipe>` ו־`omarchy agent local stop <recipe>` עושים את אותו הדבר, `omarchy agent local status` מציג כל דגם, ו־`omarchy agent --local` פותח את סוכן ברירת המחדל שלך על הדגם האחרון שהפעלת (pi אם סוכן ברירת המחדל שלך לא יכול להשתמש בדגם מקומי). גם כל לקוח תואם OpenAI יכול להתחבר: `status` מציג את הכתובת של כל דגם (הראשון הוא `http://127.0.0.1:11435/v1`), שם המתכון הוא הדגם, והמפתח נמצא בתוך `~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` מוחק דגם ואת ההורדות שאף דגם אחר לא משתמש בהן.

סביבות זמן ריצה של צד שלישי מתויגות עם המפרסם שלהן. Omarchy מריצה כל דגם ללא גישה לרשת.

### מודלי LLM מקומיים

Omarchy ממליצה על שתי דרכים להריץ מודלי LLM מקומיים: LM Studio ו־Ollama. LM Studio מספקת ממשק GUI למצוא מודלים עם משקלים פתוחים, להתקין אותם ולהריץ אותם. זו דרך מעולה להתחיל בקלות. Ollama מציעה CLI לעשות זאת באופן דומה. אבל אם אתה חדש בדגמים מקומיים, הייתי מתחיל עם LM Studio. אפשר להתקין כל אחד מהם תחת _התקנה > AI_ בתפריט Omarchy.

### ה־Skill של Omarchy

כישורי סוכנים עוזרים ל־AI להשתמש בכלים ספציפיים בדרך ספציפית, ו־Omarchy מגיעה עם skill ברירת מחדל להתאמת המערכת. כמו לכוונן את תצורת Hyprland שלך, להתאים את הפס, או אפילו ליצור ערכת נושא חדשה מאפס. הוא מקושר באופן סמלי אל תיקיות ה־skill של Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` וכל `~/.hermes/profiles/*/skills`), והמיקום הגנרי `~/.agents/skills`, כך שרוב ה־harnesses אוספים אותו אוטומטית.

אבל כדאי להתייחס אל ה־skill הזה כאל ניסיוני. דגמים שונים ישתמשו בו להשפעה שונה. הכי טוב להריץ תחילה במצב תכנון, כדי שיהיה לך מושג מה הסוכן היה רוצה לשנות. ולאחר מכן היה מוכן לשחזר שינויים או אפילו להפעיל את `omarchy reinstall configs`, אם הסוכן יעשה בלגן מהכול.
