### התקנה ועדכון של סוכנים

למעט Hermes ו-OpenClaw, הסוכנים האלה משתמשים בהתקנה העצלה של mise: ההפעלה הראשונה מתקינה את ה-CLI, והפעלות מאוחרות יותר משתמשות בו שוב. mise גם בודקת אם יש גרסה חדשה לסוכן מותקן לכל היותר פעם בארבע שעות, ממש לפני שהוא מופעל או ברקע בשורת ה-shell. אם העדכון הזה נכשל או שאתם לא מחוברים, הגרסה המותקנת מופעלת. `omarchy update` מעדכנת סוכנים מותקנים יחד עם שאר Omarchy, ו-`mup` מעדכנת רק כלים המנוהלים על ידי mise.

המעדכן של סוכן עצמו, כמו `claude update`, `codex update`, או כפתור עדכון באפליקציה, לא מעדכן את ההתקנה המנוהלת על ידי mise. `codex update` נכשלת, ו-`claude update` יכולה לדווח על הצלחה תוך התקנת עותק נפרד ש-mise לא עוקבת אחריו. אם אתם מעדיפים להשתמש במתקין ובמעדכן המקוריים של סוכן, הוסיפו אותו ל-`disable_tools`; ראו [כלי CLI מותקנים מראש](18-development-tools.md#preinstalled-cli-tools).

כדי להתקין את כל הכלים העצלים המוגדרים לפני שתצטרכו אותם, הפעילו את `mise install --include-lazy`. זה כולל את כלי ה-CLI האחרים של Omarchy המוגדרים כברירת מחדל וגם את הסוכנים. ראו [כלי CLI מותקנים מראש](18-development-tools.md#preinstalled-cli-tools) להתקנת כלי בודד או לשימוש בהתקנה שלכם.

`grok` מותקנת דרך חבילת `grok` הרשמית של mise, באותו אופן כמו `claude` ו-`codex`. הפעילו את `grok`, או בחרו אותה תחת _Agent > Harness_. דלגו על מתקין ה-`curl | bash` שב-x.ai. הנתיב הזה מניח עותק שני ב-`~/.grok/bin`, מקדים אותו ב-`PATH`, ודורס את ה-wrapper של Omarchy.

`dsh` פותחת את ממשק הדפדפן שלה ב-`127.0.0.1:3080`, כאשר תיקיית ההפעלה היא סביבת העבודה המוגדרת כברירת מחדל. ממשק הדפדפן שלה לא מקבל הנחיית פתיחה, ולכן `omarchy agent prompt` פותחת אותו עם ההנחיה על הלוח שלכם להדבקה. Omarchy מפעילה אותו עם הגדרת ההרשאות no-approval של DeepSeek. DeepSeek Harness מעלה יומני הפעלה ל-DeepSeek כאשר אתם משתמשים ב-API הרשמי של המודלים שלה; כבו זאת תחת _Settings > General > Upload Session Log_ בממשק הדפדפן שלה. גם משוב שאתם שולחים לה מועלה עם ההפעלה, אלא אם תפעילו אותה עם `DSH_TELEMETRY_MODE=DISABLED`.

### הסוכן שמוגדר כברירת מחדל

בחרו את הסוכן שמוגדר אצלכם כברירת מחדל עם `omarchy default agent <name>` או תחת _Agent > Harness_ בתפריט Omarchy (`Super + Space`). אם הסוכן עדיין לא מותקן, בחירה בו תתקין אותו תחילה, והוא גם יקבל משגר משלו במשגר האפליקציות, לצד Agent. Omarchy טרייה תזמין אתכם לבצע את הבחירה הזו בהתראה חד-פעמית.

בחירה ב-Claude גם מנסה להתקין את תוסף הדפדפן שלה עבור Chromium, Chrome, Brave, Brave Origin ו-Edge. התקנת התוסף חלה על כל המשתמשים ועלולה לבקש את סיסמת המערכת שלכם; ביטול או כישלון של התקנת התוסף עדיין בוחרים ומפעילים את Claude. הפעילו מחדש את הדפדפן, הפעילו את התוסף אם תתבקשו, והתחברו ל-Claude כדי לסיים את החיבור שלו. הפעילו את `/chrome` ב-Claude כדי לבדוק את החיבור. Firefox ו-Zen לא תומכים בתוסף הזה. אם Claude כבר הייתה מוגדרת אצלכם כברירת מחדל לפני שההתקנה הזו נוספה, בחרו בה שוב כדי להתקין את התוסף.

לאחר שבחרתם, `Super + Shift + Ctrl + A` מפעילה את הסוכן שמוגדר כברירת מחדל בחלון טרמינל ייעודי (או מעלה את הבוחר אם עדיין לא בחרתם). אתם יכולים גם להפעיל אותה ישירות לתוך משימה עם `omarchy agent prompt "Review this project"`. Freebuff ו-DeepSeek Harness לא מקבלות הנחיית פתיחה, ולכן הן נפתחות עם ההנחיה על הלוח שלכם להדבקה במקום זאת. סוכנים המופעלים כך פועלים ללא השגחה במצבי don't-stop-to-ask שלהם, אז היו מוכנים לכך שהם באמת יעשו דברים! ל-MiniMax Code אין מצב כזה להפעלות האינטראקטיביות שלה, ולכן היא מבקשת הרשאות כרגיל. ומכיוון שסוכנים מסרבים לזכור אמון עבור תיקיית הבית שלכם, הפעלות מ-`$HOME` מתחילות ב-`~/Work` במקום זאת.

יש גם קיצורי דרך לטרמינל: `a` מפעילה את הסוכן שמוגדר כברירת מחדל בתוך הטרמינל הנוכחי, בעוד `c`, `cx` ו-`cy` מפעילים את OpenCode, Claude Code ו-Codex ישירות (שוב במצבי האישור האוטומטי שלהם). גם שינויי ערכת נושא מסתנכרנים לסוכנים: Claude Code, Pi, OpenCode ו-Hermes (ברגע ש-Omarchy התקינה אותה) כולם מתאימים את עצמם כאשר אתם מחליפים את ערכת הנושא של Omarchy.

### הוראות הסוכן שלכם

כללים אישיים לכל סוכן נמצאים ב-`~/.agents/AGENTS.md`, לצד הסקילים המשותפים ב-`~/.agents/skills`. פתחו אותו תחת _Agent > Instructions_, שגם מקשר אותו לכל harness ששומר קובץ גלובלי משלו: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` של Copilot, וכן הלאה. Crush ו-Amp קוראות את הקישור `~/.config/AGENTS.md`, בעוד omp, Kimi ו-DeepSeek Harness קוראות את `~/.agents/AGENTS.md` ישירות. גם בחירת סוכן כברירת מחדל מקשרת אותו. קובץ הוראות שכבר היה לכם הופך למשותף אם עדיין לא היה כזה; אחרת הוא נשמר לצד הקישור כ-`.bak`. הפעילו את `omarchy agent instructions` כדי לקשר מחדש לאחר התקנת סוכן נוסף.

### חלונית הסוכנים

בסרגל העליון יש סמל סוכנים. לפני שהגדרתם סוכן, החלונית שלו מלווה אתכם בהתחברות ל-Claude, Codex או Grok, והראשון הופך לסוכן שמוגדר אצלכם כברירת מחדל. לאחר מכן, החלונית מציבה כל מנוי בעמוד אחד: כל סוכן וחשבון עם התוכנית שלו, מד לכל אחת ממגבלות ההפעלה של 5 שעות והמגבלות השבועיות שלו עם הזמן עד שהוא מתאפס (רחפו לקבלת האחוז המדויק), או יתרת התשלום מראש שנותרה, תחת שורה שמתחלפת בין מה שהשתמשתם בו בכל אלה, כמו טוקנים השבוע והמודל שהשתמשתם בו הכי הרבה. תחת _Make something cool_ היא מציעה הנחיות פתיחה לערכת נושא, תוסף, אפליקציה או משחק חדשים שמעבירים את המשימה לסוכן שמוגדר אצלכם כברירת מחדל. אפליקציות נבנות באותו אופן שבו נבנו Hype, Monologue ו-Omacut של Omarchy עצמה, ב-C++ וב-Qt Quick, בהתאם לסקיל הסוכן omarchy-make-app, והמהדר ורכיבי Qt שהם צריכים מגיעים מותקנים. משחקים הם עמוד three.js יחיד ב-`~/Games/vibes`, בהתאם לסקיל הסוכן omarchy-make-game, וכולם נפתחים ממשגר Game Vibes אחד בערכת הנושא הנוכחית; הם טוענים את three.js מהאינטרנט, ולכן הם צריכים חיבור כדי להתחיל. Claude Code, Codex, Grok, Kimi, Cursor והקצאת Grok Bot שלה, GitHub Copilot, Muse, Antigravity ו-Devin מכוסים מהקופסה עם המגבלות שלהם, Kimchi עם התוכנית, הזיכויים ששולמו מראש ותקציבי ההוצאה שלה, ו-Hermes, Mistral Vibe ו-Qwen Code מציגים את ההפעלות והטוקנים שלהם ברגע שהשתמשתם בהם. גם תוכניות ומפתחות של ספקים שאתם משתמשים בהם דרך pi, omp או opencode מופיעים: OpenCode Zen ו-Go, תוכנית Z.ai GLM Coding Plan, Ollama Cloud, תוכנית MiniMax Token Plan ו-Synthetic עם המגבלות שלהם; OpenRouter ו-DeepSeek עם יתרות התשלום מראש שלהם; Fireworks עם ההוצאה שלה ב-30 הימים האחרונים. גם טוקנים ממודלים שאתם מריצים על החומרה שלכם נספרים בסכומים; למודלים עצמם יש חלונית משלהם, המתוארת תחת [מודלים מקומיים](#local-models). כל סוכן נספר פעם אחת, תחת מי שמחייב עליו, לא משנה כמה harness-ים אתם מפעילים אותו דרכם.

לחצו לחיצה שמאלית על סמל הסרגל או לחצו על `Super + Ctrl + X` לחלונית, לחיצה ימנית להפעלת הסוכן שמוגדר אצלכם כברירת מחדל, ולחיצה אמצעית לרענון. רשומות השימוש שמאחוריה נוצרות מחדש כל 15 דקות על ידי `omarchy agent usage update`, והחלונית יכולה אפילו למזג שימוש ממכונות אחרות שלכם דרך תיקייה מסונכרנת. ראו את ה-README תחת `$OMARCHY_PATH/shell/plugins/agents/` להגדרות המלאות.

### כמה מנויים

אם אתם משלמים על יותר מתוכנית Claude, Codex או Grok אחת — Max אישית ואחת של עבודה, נניח — Omarchy יכולה להשאיר את כולן מחוברות ולעבור ביניהן. הוסיפו מנוי עם ה-+ בחלונית הסוכנים, שמלווה אתכם שם במקום, או עם `omarchy agent account add claude Work` (או `codex`, או `grok`). היא מתקינה את ה-CLI אם הוא חסר. החשבון הראשון של ספק מתחבר דרך הדפדפן הרגיל שלכם, בדיוק במקום שבו ה-CLI תמיד מחפש. כל אחד אחרי זה מתחבר דרך חלון פרטי, כך שהחשבון שהדפדפן שלכם כבר מחובר אליו לא יילקח בטעות; התחברו שם כחשבון שאתם מוסיפים, וסגרו קודם כל חלון פרטי שכבר פתוח. לעולם אל תתנתקו מה-CLI כדי לעשות זאת: התנתקות מבטלת את ההתחברות השמורה, והחשבון הזה יצטרך להתווסף שוב.

כדי להעתיק את התחברויות המנוי שלכם למכונת Omarchy אחרת דרך SSH, הפעילו את `omarchy agent account copy user@laptop`. השולח מספק מקלט זמני כאשר ליעד אין אחד מותקן, כך שמכונות Omarchy ישנות יותר יכולות לקבל חשבונות ללא עדכון. מקלטים מותקנים מקבלים עדיפות. זה מעתיק את כל מנויי Claude, Codex ו-Grok; הוסיפו שמות ספקים כדי לבחור בהם, כמו ב-`omarchy agent account copy laptop claude`. שמות החשבונות ומזהי הפקודות תואמים למקור, כולל חשבונות שכבר קיימים ביעד. חשבונות יעד לא קשורים מקבלים סיומת מספרית אם שמותיהם מתנגשים, והגדרות, סקילים, תוספים והיסטוריית שיחות נשארים מקומיים לכל מכונה.

אישורי יעד קיימים נשמרים. לחשבון מקור שכבר מחובר שם השם מסונכרן מבלי להחליף את האישורים שלו; חשבונות אחרים מתווספים לצידו. כדי להחליף אישורים שמורים עבור חשבונות תואמים, השתמשו ב-`omarchy agent account copy --replace laptop claude` לאחר שיצאתם מההפעלות של החשבון הזה ביעד. יעד טרי מקבל גם את החשבון הפעיל של המקור ואת העדפות המעבר שלו; יעד מבוסס שומר את שלו.

אישורים עוברים דרך SSH ונשמרים בקבצים פרטיים ביעד, אז העתיקו רק למכונות שאתם סומכים עליהן. זו העתקה חד-פעמית, לא סנכרון מתמשך. אסימוני רענון של Codex יכולים להיות מוחלפים על ידי מכונה אחרת, ולהשאיר התחברות מועתקת הזקוקה לחידוש; התחברויות נפרדות נשארות הבחירה האמינה ביותר לשימוש בו-זמני בכמה מכונות. ראו [הנחיות אימות החשבון של Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

חשבון אחד לספק פעיל, וכל הפעלה חדשה מתחילה כמוהו: `cx`, `cy`, `claude`, `codex` או `grok` פשוטים, כל דבר המופעל דרך `omarchy agent`, וסקריפטים או עורכים שמוצאים את ה-CLI ב-`PATH`. החליפו עם `omarchy agent account use work` (וחזרו עם `omarchy agent account use main`), או בחלונית על ידי לחיצה על מספר של חשבון ואז `Enter` (או לחיצה על כפתור Use שלו). גם הפעלות Claude פועלות מתחלפות, מההודעה הבאה שלהן: כל הפעלת Claude פועלת ב-`~/.claude`, שתמיד מחזיקה את ההתחברות של החשבון הפעיל. הפעלת Claude שהחלה בתיקייה של חשבון עצמו על ידי Omarchy ישנה יותר מחזיקה את ההתחברות הזו עד שהיא יוצאת, ולכן המעבר מזכיר את ההפעלות האלה ומסיים מעצמו ברגע שהן נעלמות. הפעלות Codex ו-Grok פועלות נשארות על החשבון שבו התחילו. היסטוריית שיחות, הגדרות, סקילים ותוספים משותפים בין חשבונות, כך ש-`claude --continue` באותה תיקייה ממשיכה מהמקום שהפסקתם בחשבון החדש.

עם יותר מחשבון אחד, החלונית מציגה את מגבלות כל חשבון זו לצד זו, כאשר הפעיל מסומן. כברירת מחדל Omarchy מודיעה לכם כאשר החשבון הפעיל עובר 95% ממגבלה, ולחיצה על ההתראה עוברת לחשבון עם הכי הרבה מרווח. רחפו מעל שורה של חשבון בחלונית ולחצו על Autoswitch שמופיע לצד Use (או לחצו על `m`), או הפעילו את `omarchy agent account mode auto`, כדי שהיא תעבור מעצמה במקום זאת; בזמן שזה פועל, Autoswitch תופס את מקומו של Use, ולחיצה עליו שוב חוזרת להתראה. הוסיפו מספר כדי לשנות את הסף, כמו ב-`omarchy agent account mode auto 90`. אם כל חשבון מעל הסף, תשמעו על כך פעם אחת, יחד עם איזה חשבון משתחרר ראשון. בזמן שחשבון פעיל נמצא בתוך 15 נקודות מהסף שלו (80% בברירת המחדל), המגבלות שלו נבדקות כל שלוש דקות ולא כל 15.

`omarchy agent account list` מציגה כל חשבון ואת המגבלות האחרונות שלו, `omarchy agent account remove work` שוכחת אחד, ו-`omarchy agent account rename primary Hey` משנה שם של אחד (או לחצו על שם של חשבון בחלונית). הפקודות האלה פועלות על החשבונות של הסוכן שמוגדר אצלכם כברירת מחדל; כדי להגיע לספק האחר, תנו את שמו תחילה, כמו ב-`omarchy agent account use codex side`. ההתחברות שכבר הייתה לכם ב-`~/.claude` או ב-`~/.codex` היא חשבון ה-_Main_. זה של Codex נשאר במקומו; זה של Claude ממתין בתיקייה משלו בזמן שחשבון אחר פעיל. חשבון שנשאר לא בשימוש יותר מכשמונה שעות יכול להציג _Sign-in required_; לחצו עליו כדי לחבר את החשבון הזה שוב ממש בחלונית, או עברו אליו והתחילו הפעלה, שמרעננת את ההתחברות מעצמה. שרתי MCP שאתם מוסיפים עם `claude mcp add` מגיעים לכל חשבון Claude, מכיוון שכולם פועלים ב-`~/.claude`; עבור Codex ו-Grok, שרתים שהיו לכם כאשר חשבון התווסף מגיעים אליו, אבל מאוחרים יותר מגיעים רק לחשבון שבו הוספתם אותם. Claude Desktop שומרת התחברות משלה, וכלים של Codex או Grok המוגדרים עם נתיב מוחלט לקובץ הבינארי של CLI לא עוקבים אחר המעבר. `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, או `GROK_HOME` מפורשים מקבלים עדיפות על פני החשבון שנבחר.

### אבחון קריסות

Omarchy עוקבת אחר systemd-coredump לאיתור קריסות תהליכים. ברגע שבחרתם סוכן שמוגדר כברירת מחדל, כל תוכנית שלכם שמטילה ליבה מעלה התראת "Process crashed" — לחצו עליה, והקריסה נמסרת לסוכן שמוגדר אצלכם כברירת מחדל יחד עם סקיל omarchy-diagnose-crash של Omarchy, שמלווה את הסוכן בביסוס העובדות מהטלת הליבה ובהחלטה אם הקריסה שווה דיווח ל-upstream. אתם יכולים גם להפעיל אותה ידנית נגד כל PID מתוך `coredumpctl list` עם `omarchy agent crash <pid>`.

המעקב פועל כברירת מחדל. כבו אותו תחת _Trigger > Toggle > Crash Capture Off_ (או עם `omarchy toggle crash-capture`) וההתראות מפסיקות; `omarchy agent crash <pid>` עדיין פועלת ידנית.

קריסות יכולות גם להיות מושתקות תוכנית אחת בכל פעם, שזה מה שהאבחון מציע לכם בסוף. `omarchy crash mute hyprland` מפסיקה את ההתראות עבור התוכנית הזו בלבד, `omarchy crash mute hyprland off` מחזירה אותן, ו-`omarchy crash mute` בפני עצמה מפרטת את מה שהשתקתם. היא מקבלת את נתיב הקובץ הבינארי באותה שמחה כמו את שמו, כך ש-`omarchy crash mute /usr/bin/hyprland` עושה את אותו הדבר. צטטו שם עם רווח בתוכו, כמו ב-`omarchy crash mute 'Some App'`. כל השאר עדיין מודיע, והתוכנית המושתקת עדיין קורסת — זה מסתיר את התזכורת, זה לא מתקן כלום.

### אפליקציות שולחניות

תפריט _Install > AI_ נושא גם כמה אפליקציות AI גרפיות: Amp Desktop, Antigravity Desktop, אפליקציית ChatGPT לשולחן העבודה, אפליקציית Claude לשולחן העבודה (הבטא ל-Linux של Anthropic, עם לשוניות Chat, Cowork ו-Claude Code), Grok Bot לשיחה עם המודלים של xAI, Herdr Desktop, Hermes Desktop, OpenClaw, אפליקציית Perplexity לשולחן העבודה ו-T3 Code. Grok Bot היא אפליקציית הצ'אט לשולחן העבודה. סוכן הקידוד הוא הפקודה `grok`.

Hermes Desktop היא זו שכדאי להכיר, מכיוון שלמכונה יש Hermes אחד, והוא של האפליקציה: Hermes מותקנת רק אי פעם דרך האפליקציה, והפקודה `hermes` שהסוכן שמוגדר כברירת מחדל מפעיל היא של האפליקציה. בחירה ב-Hermes כסוכן שמוגדר כברירת מחדל מתקינה את אותו הדבר שערך _Install > AI_ עושה: את החבילה, ואת סביבת הריצה של Hermes תחת `~/.hermes` המוגדרת על ידי המתקין של Hermes עצמה, שלוקח כמה דקות בפעם הראשונה. סביבת הריצה הזו היא ה-Hermes האחת שהפקודה הטרמינלית `hermes`, הסוכן שמוגדר כברירת מחדל והאפליקציה כולם משתמשים בה, והיא מעדכנת את עצמה עם `hermes update` ולא ממתינה לגרסת Omarchy. התקנתה גם נותנת ל-Hermes את ערכת הנושא של Omarchy כסקין בשם `omarchy`, שכל משטח של Hermes עוקב אחריו כאשר אתם מחליפים ערכות נושא; בחרו אחר תחת הגדרות Appearance של Hermes או עם `/skin` אם אתם מעדיפים שלא, ו-Omarchy משאירה את הבחירה הזו בשקט. הסרת האפליקציה תחת _Remove > AI_ סוגרת תחילה את Hermes, כולל השער, לוקחת את סביבת הריצה הזו איתה, ושומרת את הצ'אטים, הזכרונות והסקילים ש-Hermes כתבה לעצמה אלא אם תגידו אחרת: היא שואלת, עם ברירת מחדל של לא, האם גם הנתונים האלה והגדרות החיבור שלכם צריכים להיעלם.

חוויית שולחן העבודה של OpenClaw היא ה-Control UI שלה, שנפתח כאפליקציית אינטרנט המגובה בשער המקומי שלה עצמה. OpenClaw חיה ב-`~/.openclaw` ומעדכנת את עצמה: השתמשו בכפתור "Update Gateway" של ה-Control UI או הפעילו את `openclaw update`, והשער מופעל מחדש בגרסה החדשה. Omarchy בוחרת רק את הגרסה שהתקנה טרייה מתחילה ממנה. OpenClaw יכולה גם להיות הסוכן שמוגדר אצלכם כברירת מחדל: בחירה בה תחת _Agent > Harness_ מגדירה את אותו עותק ב-`~/.openclaw`, והסוכן פותח את ממשק המשתמש הטרמינלי של OpenClaw המחובר לשער שלה. הסרת OpenClaw תחת _Remove > AI_ לוקחת איתה את שירות השער ואת האפליקציה ואז שואלת האם גם `~/.openclaw` צריכה להיעלם, מכיוון שזה מחזיק את הצ'אטים והאישורים שלכם לצד OpenClaw עצמה וסביבות הריצה של התוספים שהיא מורידה; ברירת המחדל שומרת אותה, והתקנת OpenClaw שוב לוקחת אותה בחזרה.

Herdr Desktop היא אפליקציית שולחן העבודה של [Herdr](https://herdr.dev): מרחבים, לשוניות וחלוניות של טרמינלים וסוכני קידוד שממשיכים לפעול בליבה שלה כאשר אתם סוגרים את החלון. היא מגיעה מהמתקין של Herdr עצמה ולא מחבילה, ולכן היא חיה ב-`~/.local/share/herdr-app`, מביאה את הליבה שלה ב-`~/.local/bin/herdr-core` כאשר עדיין אין לכם אחת, ומעדכנת את שתיהן בעצמה. היא נמצאת לצד הפקודה `herdr` ש-Omarchy מספקת ב-`Super + Ctrl + Return` ולא מחליפה אותה, ומקבלת את המקשים הישירים של הפקודה הזו: `Alt + Return` ו-`Alt + Shift + Return` מפצלים חלונית למטה או ימינה, `Alt + Escape` סוגר אותה, `Ctrl + Alt + Arrow` נע בין חלוניות, `Alt + 1..9` ו-`Alt + Left/Right` בוחרים לשונית, ו-`Alt + Up/Down` נעים בין מרחבים. `Ctrl + 1..9` בוחר מרחב ו-`Alt + Shift + Up/Down` עוברים בין סוכנים. מקשי הקידומת `Ctrl + Space` נשארים לטרמינל בלבד, מכיוון שהאפליקציה לא יכולה להחזיק מקש Ctrl רגיל עבור רצף. Omarchy כותבת אותם ל-`~/.config/herdr-app/keys.json`, ו-`omarchy-refresh-herdr-app` מחזירה אותם. התקנתה בוחרת את ערכת הנושא Omarchy של Herdr, שעוקבת אחר ערכת הנושא של Omarchy שלכם מאז ואילך. Herdr שומרת ערכת נושא אחת למצב בהיר ואחת למצב כהה, ולכן לאחר מעבר בין ערכת נושא כהה לבהירה של Omarchy, בחרו ב-Omarchy בבוחר ערכות הנושא של Herdr פעם נוספת עבור המצב האחר.

T3 Code פועלת מהגרסה הרשמית שלה כ-AppImage ב-`~/.local/share/t3code` ולא מחבילה, ולכן היא מעדכנת את עצמה. התקנתה שואלת האם להתחיל בערוץ Stable או Nightly; החליפו מאוחר יותר בהגדרות של T3 Code. השרשורים וההגדרות שלכם חיים ב-`~/.t3`, והסרת T3 Code תחת _Remove > AI_ לוקחת אותם איתה.

### מודלים מקומיים

הפעילו מודל פתוח במכונה שלכם עבור סוכני הקידוד שלכם. ההנחיות והקוד שלכם נשארים במכונה; שום דבר שנשלח למודל לא עוזב אותה. התחילו עם:

```bash
omarchy models use best text
```

זה מגדיר את מודל הטקסט הטוב ביותר למכונה הזו, הסוג שהסוכנים שלכם משתמשים בו. למודלי תמונה, וידאו ומוזיקה יש את הטוב ביותר משלהם: `omarchy models use best image`, `video` או `music`. הפעילו את `omarchy models use best` כדי לראות את הבחירה של כל סוג למכונה הזו.

או פתחו את חלונית המודלים המקומיים מסמל הנצנצים שלה בסרגל העליון, לצד סמל הסוכנים, או עם Super + Ctrl + Alt + X, ובחרו ב-+. הסמל מופיע כאשר מודל מתאים למכונה הזו. Podman, שמריץ את המודלים, מגיע עם Omarchy, וכך גם ערכת הכלים של NVIDIA למיכלים במכונת NVIDIA, שנותנת להם את ה-GPU; אם אחד מהם חסר, ההתקנה הראשונה מתקינה אותו. Omarchy אז בוחרת את המודל המומלץ למכונה הזו, מורידה אותו, ומפעילה אותו. צפו להורדה של עשרות GB ולכך שרוב זיכרון המכונה יהיה בשימוש בזמן שהמודל פועל: Flash Next משתמשת בכ-100 GiB עם הקשר ה-256K המלא שלה. אם מודלים אחרים מחזיקים את הזיכרון שהיא צריכה, היא מוגדרת כמופסקת, מוכנה להתחיל ברגע שתעצרו אחד. המודל נעצר בעת התנתקות; עצרו אותו בעצמכם כאשר אתם צריכים את הזיכרון למשהו אחר.

`omarchy models list` מציגה את האפשרויות ומסבירה מדוע חלקן לא מתאימות. כדי להגדיר אחד נוסף, הפעילו את `omarchy models use <recipe>`. כיום, `qwen3.8-flash-next-gufo` ו-`qwen3.8-27b-gufo` זמינים למכונות Strix Halo של 128 GB; ה-27B לוקחת כ-40 GiB, ולכן היא משאירה מקום לעבודה אחרת. במחשב נייד של 64 GB עם Arc B390 של Intel, `qwen3.6-35b-a3b-llamacpp` פועלת בכ-30 GiB. מתכונים והמלצות חדשים מגיעים עם `omarchy update`, דרך החבילה.

כל מודל שאתם מגדירים מקבל שורה משלו בחלונית המודלים המקומיים: הפעלה כדי להתחיל אותו, השהיה כדי לעצור אותו ולשחרר את הזיכרון שלו, וכפתור הטרמינל כדי לפתוח את הסוכן שלכם עליו. לרוחב החלק העליון, סרגל מציג כיצד זיכרון המכונה מתחלק בין Omarchy עצמה (המערכת והאפליקציות שלכם), כל מודל פועל, ומה פנוי. הצביעו על מודל מופסק והסרגל מציג האם הוא מתאים, או כמה חסר לו. כמה יכולים לפעול בבת אחת כאשר הם מתאימים יחד בזיכרון; אם אחד לא מתאים, Omarchy אומרת איזה מודל פועל לעצור. גררו שורות לפי הלוגו שלהן כדי לסדר אותן מחדש, ולחצו על Delete בשורה נבחרת כדי להסיר מודל ואת ההורדה שלו.

כל מודל שאתם מגדירים מקבל גם ערך משלו במשגר האפליקציות, תחת שם המודל ועם הלוגו של היוצר שלו, באותו אופן שבו התחברות ל-Claude, Codex או Grok מוסיפה אחד. הוא פותח את הסוכן שלכם על המודל הזה, ומפעיל את המודל תחילה אם הוא לא פועל: הטרמינל מציג אותו נטען ומעביר לסוכן ברגע שהוא מוכן. הסרת מודל מסירה את הערך שלו.

לא כל מודל מיועד לקידוד. מודלי תמונה, וידאו ומוזיקה נפתחים במקום זאת ב-Fantasi, האפליקציה של Omarchy ליצירת תמונות, וידאו ומוזיקה עם מודל הפועל במכונה הזו, מערך המשגר שלהם ומהשורה שלהם בחלונית המודלים המקומיים.

מודל ממשיך לפעול בדיוק כפי שהוגדר, כך שעדכון Omarchy לעולם לא מפעיל מחדש אחד תחת הסוכנים שלכם. כאשר ל-Omarchy יש סביבת ריצה חדשה יותר או משקולות חדשות יותר למודל שהגדרתם, השורה שלו מציגה כפתור עדכון: לחצו עליו והמודל מוגדר שוב ברקע, מוריד רק את מה שהשתנה, ומופעל מחדש בגרסה החדשה. מודל שהיה מופסק נשאר מופסק. `omarchy models update` עושה את אותו הדבר עבור כל מודל מטרמינל.

משורת הפקודה, `omarchy models start <recipe>` ו-`omarchy models stop <recipe>` עושים את אותו הדבר, `omarchy models status` מציגה כל מודל, ו-`omarchy agent --local` פותחת את הסוכן שמוגדר אצלכם כברירת מחדל על המודל האחרון שהפעלתם. pi, OpenCode ו-Qwen Code יכולות להשתמש באחד; עם כל ברירת מחדל אחרת היא נפתחת ב-pi, או ב-OpenCode אם אין לכם pi. pi גם מפרטת כל מודל שהגדרתם, ואלה שבמכונות שציוותתם אליהן, בבוחר המודלים שלה עצמה, כך ש-`pi` פשוטה מגיעה גם אליהם. כל לקוח תואם OpenAI יכול גם להתחבר: `status` מציגה את הכתובת של כל מודל (הראשונה היא `http://127.0.0.1:11435/v1`), שם המתכון הוא המודל, והמפתח נמצא ב-`~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` מוחקת מודל ואת ההורדות שאף מודל אחר לא משתמש בהן.

סביבות ריצה של צד שלישי מתויגות עם המפרסם שלהן. Omarchy מריצה כל מודל ללא גישה לרשת.

### מודלי LLM מקומיים

Omarchy ממליצה על שתי דרכים להפעלת מודלי LLM מקומיים: LM Studio ו-Ollama. LM Studio מספקת ממשק GUI למציאת מודלים פתוחי משקולות, התקנתם והפעלתם. זו דרך מעולה להתחיל בקלות. Ollama מציעה CLI לעשות זאת באופן דומה. אבל אם אתם חדשים במודלים מקומיים, הייתי מתחיל עם LM Studio. אתם יכולים להתקין כל אחת מהן תחת _Install > AI_ בתפריט Omarchy.

### הסקילים של Omarchy

סקילים של סוכנים עוזרים ל-AI להשתמש בכלים ספציפיים בדרך ספציפית, ו-Omarchy מספקת שבעה מהם. הסקיל omarchy מכסה התאמה אישית של המערכת, כמו שינוי תצורת Hyprland שלכם או התאמת הסרגל. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app ו-omarchy-make-game מכסים יצירת משהו חדש, omarchy-contribute מכסה דיווח על באג או שליחת תיקון ל-upstream, ו-omarchy-diagnose-crash עוברת על הטלת ליבה של קריסה. הם מקושרים בסמליות לתיקיות הסקילים עבור Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` וכל `~/.hermes/profiles/*/skills`), והמיקום הגנרי `~/.agents/skills`, כך שרוב ה-harness-ים קולטים אותם אוטומטית. תיקיית סקיל משלכם עם אותו שם מקבלת עדיפות.

אבל כדאי להתייחס לסקילים האלה כניסיוניים. מודלים שונים ישתמשו בהם להשפעה שונה. הכי טוב להפעיל תחילה במצב תכנון, כך שיש לכם מושג מה הסוכן היה רוצה לשנות. ואז היו מוכנים לבטל שינויים או אפילו להפעיל את `omarchy reinstall configs`, אם הסוכן עושה בלגן מהכל.
