# AI

Omarchy כוללת משגרים לסוכני הקידוד שלמטה מבלי לבחור עבורכם ברירת מחדל. הריצו פקודה כדי להתקין את ה-CLI שלה בשימוש הראשון, ואז התחברו כשתתבקשו. Hermes היא היוצאת מן הכלל: שום דבר לא מותקן עבורה בשימוש הראשון, ובחירה בה מתקינה את Hermes Desktop, כפי ש-_אפליקציות שולחניות_ שלמטה מסביר.

### התקנה ועדכון של סוכנים

למעט Hermes, הסוכנים האלה משתמשים בהתקנה העצלה של mise: ההפעלה הראשונה מתקינה את ה-CLI, והפעלות מאוחרות יותר משתמשות בו שוב. mise גם בודק אם יצאה גרסה חדשה של סוכן מותקן לכל היותר פעם בארבע שעות, ממש לפני שהוא מתחיל או ברקע בשורת ה-shell. אם העדכון הזה נכשל או שאתם לא מחוברים לרשת, הגרסה המותקנת רצה. `omarchy update` מעדכן סוכנים מותקנים יחד עם שאר Omarchy, ו-`mup` מעדכן רק כלים המנוהלים על ידי mise.

המעדכן של סוכן עצמו, כמו `claude update`, `codex update`, או כפתור עדכון באפליקציה, לא מעדכן את ההתקנה המנוהלת על ידי mise. `codex update` נכשל, ו-`claude update` יכול לדווח על הצלחה תוך התקנת עותק נפרד ש-mise לא עוקב אחריו. אם אתם מעדיפים להשתמש במתקין ובמעדכן המקוריים של סוכן, הוסיפו אותו ל-`disable_tools`; ראו [כלי CLI מותקנים מראש](18-development-tools.md#preinstalled-cli-tools).

כדי להתקין את כל הכלים העצלים שהוגדרו לפני שתצטרכו אותם, הריצו `mise install --include-lazy`. זה כולל את כלי ה-CLI האחרים של Omarchy בברירת מחדל וגם את הסוכנים. ראו [כלי CLI מותקנים מראש](18-development-tools.md#preinstalled-cli-tools) להתקנת כלי יחיד או לשימוש בהתקנה משלכם.

`grok` מותקן דרך החבילה הרשמית `grok` של mise, באותה דרך כמו `claude` ו-`codex`. הריצו `grok`, או בחרו אותו תחת _Setup > Defaults > Agent_. דלגו על המתקין `curl | bash` ב-x.ai. הדרך הזאת שמה עותק שני ב-`~/.grok/bin`, מקדימה אותו ב-`PATH`, ודורסת את ה-wrapper של Omarchy.

`dsh` פותח את ממשק הדפדפן שלו ב-`127.0.0.1:3080`, כשספריית ההפעלה היא סביבת העבודה בברירת מחדל שלו. לממשק הדפדפן שלו אין prompt להתחלה, כך ש-`omarchy agent prompt` פותח אותו כשה-prompt על הלוח שלכם כדי שתדביקו אותו. Omarchy מפעילה אותו עם הגדרת ההרשאות ללא אישור של DeepSeek. DeepSeek Harness מעלה יומני session ל-DeepSeek כשאתם משתמשים ב-API הרשמי של המודלים שלו; כבו את זה תחת _Settings > General > Upload Session Log_ בממשק הדפדפן שלו. גם משוב שאתם שולחים אליו מועלה יחד עם ה-session, אלא אם מפעילים אותו עם `DSH_TELEMETRY_MODE=DISABLED`.

### סוכן ברירת המחדל

בחרו את סוכן ברירת המחדל שלכם עם `omarchy default agent <name>` או תחת _Setup > Defaults > Agent_ בתפריט Omarchy (`Super + Space`). אם הסוכן עדיין לא מותקן, בחירה בו מתקינה אותו קודם. Omarchy חדשה תזמין אתכם לעשות את הבחירה הזאת עם התראה חד-פעמית.

בחירה ב-Claude מנסה גם להגדיר את תוסף הדפדפן שלו עבור Chromium, Chrome, Brave, Brave Origin ו-Edge. הגדרת התוסף חלה על כל המשתמשים ועשויה לבקש את סיסמת המערכת שלכם; ביטול או כישלון בהתקנת התוסף עדיין בוחרים ומפעילים את Claude. הפעילו מחדש את הדפדפן, אפשרו את התוסף אם תתבקשו, והתחברו ל-Claude כדי לסיים לחבר אותו. הריצו `/chrome` ב-Claude כדי לבדוק את החיבור. Firefox ו-Zen לא תומכים בתוסף הזה. אם Claude כבר היה ברירת המחדל שלכם לפני שההגדרה הזאת נוספה, בחרו אותו שוב כדי להתקין את התוסף.

אחרי שבחרתם, `Super + Shift + Ctrl + A` מפעיל את סוכן ברירת המחדל בחלון טרמינל ייעודי (או מעלה את הבוחר אם עדיין לא בחרתם). אפשר גם להפעיל אותו ישירות למשימה עם `omarchy agent prompt "Review this project"`. Freebuff ו-DeepSeek Harness לא מקבלים prompt להתחלה, אז במקום זאת הם נפתחים כשה-prompt על הלוח שלכם כדי שתדביקו אותו. סוכנים המופעלים כך רצים ללא פיקוח במצבי אל-תעצרו-לשאול המתאימים שלהם, אז תהיו מוכנים לזה שהם באמת יעשו דברים! ל-MiniMax Code אין מצב כזה ל-sessions האינטראקטיביים שלו, אז הוא מבקש הרשאות כרגיל. ומכיוון שסוכנים מסרבים לזכור אמון עבור ספריית הבית שלכם, הפעלות מ-`$HOME` מתחילות ב-`~/Work` במקום זאת.

יש גם קיצורי טרמינל: `a` מריץ את סוכן ברירת המחדל בתוך הטרמינל הנוכחי, בעוד `c`, `cx` ו-`cy` מפעילים את OpenCode, Claude Code ו-Codex ישירות (שוב במצבי האישור האוטומטי שלהם). שינויי ערכת נושא מסתנכרנים גם לסוכנים: Claude Code, Pi, OpenCode ו-Hermes (ברגע ש-Omarchy התקינה אותו) כולם עוקבים כשאתם מחליפים את ערכת הנושא של Omarchy.

### פאנל הסוכנים

בסרגל העליון יש סמל סוכנים. לפני שהגדרתם סוכן, הפאנל שלו מלווה אתכם בהתחברות ל-Claude, Codex או Grok, והראשון הופך לסוכן ברירת המחדל שלכם. אחרי זה, הפאנל שם כל מנוי בעמוד אחד: כל סוכן וחשבון עם התוכנית שלו, מד לכל אחת ממגבלות ה-session של 5 השעות והמגבלות השבועיות שלו עם הזמן עד שהוא מתאפס (רחפו לקבלת האחוז המדויק), או היתרה הנותרת ששולמה מראש, מתחת לשורה המתחלפת בין מה שהשתמשתם בו בכל אלה, כמו טוקנים השבוע והמודל שהכי השתמשתם בו. תחת _Make something_ הוא מציע prompt-ים להתחלה לערכת נושא, תוסף או אפליקציה חדשים, שמוסרים את המשימה לסוכן ברירת המחדל שלכם. אפליקציות נבנות באותה דרך שבה נבנו Hype, Monologue ו-Omacut של Omarchy עצמה, ב-C++ וב-Qt Quick, לפי ה-agent skill של omarchy-app, והקומפיילר וחלקי Qt שהם צריכים מגיעים מותקנים. Claude Code, Codex, Grok, Kimi, Cursor ומכסת ה-Grok Bot שלו, GitHub Copilot, Muse, Antigravity, Kimchi ו-Devin מכוסים מהקופסה עם המגבלות שלהם, ו-Hermes, Mistral Vibe ו-Qwen Code מראים את ה-sessions והטוקנים שלהם ברגע שהשתמשתם בהם. גם תוכניות ספקים ומפתחות שאתם משתמשים בהם דרך pi, omp או opencode מופיעים: OpenCode Zen ו-Go, ה-Z.ai GLM Coding Plan, Ollama Cloud, ה-MiniMax Token Plan ו-Synthetic עם המגבלות שלהם; Fireworks, OpenRouter ו-DeepSeek עם היתרות ששולמו מראש שלהם; והמודלים שאתם מריצים על החומרה שלכם תחת Local models. כל סוכן נספר פעם אחת, תחת מי שמחייב עליו, לא משנה דרך כמה harnesses אתם מפעילים אותו.

לחיצה שמאלית על סמל הסרגל לפאנל, לחיצה ימנית להפעלת סוכן ברירת המחדל שלכם. רשומות השימוש שמאחוריו נוצרות מחדש כל 15 דקות על ידי `omarchy agent usage-update`, והפאנל יכול אפילו למזג שימוש מהמכונות האחרות שלכם דרך תיקייה מסונכרנת. ראו את ה-README תחת `$OMARCHY_PATH/shell/plugins/agents/` להגדרות המלאות.

### כמה מנויים

אם אתם משלמים על יותר מתוכנית Claude, Codex או Grok אחת — Max אישית ואחת של העבודה, נניח — Omarchy יכולה לשמור את כולן מחוברות ולעבור ביניהן. הוסיפו מנוי עם ה-+ בפאנל הסוכנים, שמלווה אתכם בזה ממש שם, או עם `omarchy agent account add claude Work` (או `codex`, או `grok`). זה מתקין את ה-CLI אם הוא חסר. החשבון הראשון של ספק מתחבר דרך הדפדפן הרגיל שלכם, בדיוק במקום שבו ה-CLI תמיד מחפש. כל אחד אחרי זה מתחבר דרך חלון פרטי, כך שהחשבון שהדפדפן שלכם כבר מחובר אליו לא ייבחר בטעות; התחברו שם כחשבון שאתם מוסיפים, וסגרו קודם כל חלון פרטי שכבר פתוח אצלכם. לעולם אל תתנתקו מה-CLI כדי לעשות את זה: התנתקות מבטלת את ההתחברות השמורה, והחשבון הזה יצטרך להתווסף שוב.

כדי להעתיק את התחברויות המנויים שלכם למכונת Omarchy אחרת דרך SSH, הריצו `omarchy agent account copy user@laptop`. השולח מספק מקלט זמני כשאין אחד מותקן ביעד, כך שמכונות Omarchy ישנות יותר יכולות לקבל חשבונות בלי עדכון. מקלטים מותקנים מקבלים עדיפות. זה מעתיק את כל מנויי Claude, Codex ו-Grok; הוסיפו שמות ספקים כדי לבחור בהם, כמו ב-`omarchy agent account copy laptop claude`. שמות חשבונות ומזהי פקודות תואמים את המקור, כולל חשבונות שכבר קיימים ביעד. חשבונות יעד לא קשורים מקבלים סיומת מספרית אם השמות שלהם מתנגשים, והגדרות, skills, תוספים והיסטוריית שיחות נשארים מקומיים לכל מכונה.

אישורי יעד קיימים נשמרים. חשבון מקור שכבר מחובר שם מקבל את שמו מסונכרן בלי להחליף את האישורים שלו; חשבונות אחרים מתווספים לצידו. כדי להחליף אישורים שמורים לחשבונות תואמים, השתמשו ב-`omarchy agent account copy --replace laptop claude` אחרי שסגרתם את ה-sessions של החשבון הזה ביעד. יעד חדש מקבל גם את החשבון הפעיל ואת העדפות המעבר של המקור; יעד מבוסס שומר את שלו.

אישורים עוברים דרך SSH ונשמרים בקבצים פרטיים ביעד, אז העתיקו רק למכונות שאתם סומכים עליהן. זו העתקה חד-פעמית, לא סנכרון מתמשך. טוקני רענון של Codex יכולים להתחלף על ידי מכונה אחרת, ולהשאיר התחברות מועתקת הזקוקה לחידוש; התחברויות נפרדות נשארות הבחירה האמינה ביותר לשימוש בו-זמני בכמה מכונות. ראו את [הנחיות אימות החשבון של Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

חשבון אחד לכל ספק פעיל, וכל session חדש מתחיל כמוהו: `cx`, `cy`, `claude`, `codex` או `grok` רגילים, כל דבר המופעל דרך `omarchy agent`, וסקריפטים או עורכים שמוצאים את ה-CLI ב-`PATH`. החליפו עם `omarchy agent account use work` (וחזרה עם `omarchy agent account use main`), או בפאנל בלחיצה על מספר של חשבון ואז `Enter` (או לחיצה על כפתור ה-Use שלו). Sessions שכבר רצים נשארים על החשבון שהם התחילו איתו. היסטוריית שיחות, הגדרות, skills ותוספים משותפים בין חשבונות, כך ש-`claude --continue` באותה תיקייה ממשיך איפה שהפסקתם בחשבון החדש.

עם יותר מחשבון אחד, הפאנל מראה את המגבלות של כל חשבון זה לצד זה, כשהפעיל מסומן. בברירת מחדל Omarchy מודיעה לכם כשהחשבון הפעיל עובר 95% ממגבלה, ולחיצה על ההתראה עוברת לחשבון עם הכי הרבה מרווח. רחפו מעל שורה של חשבון בפאנל ולחצו על ה-Autoswitch שמופיע ליד Use (או לחצו `m`), או הריצו `omarchy agent account mode auto`, כדי שהוא יעבור מעצמו במקום זאת; בזמן שהוא פעיל, Autoswitch תופס את מקומו של Use, ולחיצה עליו שוב חוזרת להתראה. הוסיפו מספר כדי לשנות את הסף, כמו ב-`omarchy agent account mode auto 90`. אם כל חשבון מעל הסף, תשמעו על זה פעם אחת, יחד עם איזה חשבון משתחרר ראשון. בזמן שחשבון פעיל נמצא בתוך 15 נקודות מהסף שלו (80% בברירת המחדל), המגבלות שלו נבדקות כל שלוש דקות ולא כל 15.

`omarchy agent account list` מראה כל חשבון ואת המגבלות האחרונות שלו, `omarchy agent account remove work` שוכח אחד, ו-`omarchy agent account rename primary Hey` משנה שם של אחד (או לחצו על שם של חשבון בפאנל). הפקודות האלה עובדות על החשבונות של סוכן ברירת המחדל שלכם; כדי להגיע לספק האחר, ציינו אותו קודם, כמו ב-`omarchy agent account use codex side`. ההתחברות שכבר הייתה לכם ב-`~/.claude` או ב-`~/.codex` היא חשבון ה-_Main_ והיא נשארת איפה שהיא. חשבון שנשאר ללא שימוש יותר מכשמונה שעות יכול להראות _Sign-in required_; לחצו עליו כדי לחבר את החשבון הזה שוב ממש בפאנל, או התחילו בו session, שמרענן את ההתחברות מעצמו. שרתי MCP שהיו לכם כשחשבון נוסף מגיעים איתו אליו, אבל אלה שאתם מוסיפים אחר כך עם `claude mcp add` מגיעים רק לחשבון שהוספתם אותם בו. Claude Desktop וכלים שהוגדרו עם נתיב מוחלט לבינארי של CLI לא עוקבים אחר המעבר. `CLAUDE_CONFIG_DIR`, `CODEX_HOME` או `GROK_HOME` מפורשים מקבלים עדיפות על פני החשבון הנבחר.

### אבחון קריסות

Omarchy עוקבת אחר systemd-coredump לקריסות תהליכים. כשמשהו עושה segfault, תקבלו התראת "Process crashed" — לחצו עליה, והקריסה נמסרת לסוכן ברירת המחדל שלכם יחד עם ה-skill של diagnose-crash של Omarchy, שמלווה את הסוכן בקביעת העובדות מה-core dump ובהחלטה אם הקריסה שווה דיווח ל-upstream. אפשר גם להריץ אותו ידנית מול כל PID מ-`coredumpctl list` עם `omarchy agent crash <pid>`.

המעקב פעיל בברירת מחדל. כבו אותו תחת _Trigger > Toggle > Crash Capture_ (או עם `omarchy toggle crash-capture`) וההתראות מפסיקות; `omarchy agent crash <pid>` עדיין עובד ידנית.

אפשר גם להשתיק קריסות תוכנית אחת בכל פעם, שזה מה שהאבחון מציע לכם בסוף. `omarchy crash mute hyprland` מפסיק את ההתראות על התוכנית הזאת בלבד, `omarchy crash mute hyprland off` מחזיר אותן, ו-`omarchy crash mute` בפני עצמו מפרט מה השתקתם. הוא מקבל את נתיב הבינארי באותה שמחה כמו את שמו, כך ש-`omarchy crash mute /usr/bin/hyprland` עושה את אותו דבר. שימו שם עם רווח במרכאות, כמו ב-`omarchy crash mute 'Some App'`. כל השאר עדיין מתריע, והתוכנית המושתקת עדיין קורסת — זה מסתיר את התזכורת, זה לא מתקן כלום.

### אפליקציות שולחניות

תפריט _Install > AI_ נושא גם כמה אפליקציות AI גרפיות: אפליקציית שולחן העבודה של ChatGPT, אפליקציית שולחן העבודה של Claude (הבטא ל-Linux של Anthropic, עם לשוניות Chat, Cowork ו-Claude Code), Grok Bot לשיחה עם המודלים של xAI, Herdr Desktop, Hermes Desktop, OpenClaw, אפליקציית שולחן העבודה של Perplexity ו-T3 Code. Grok Bot היא אפליקציית הצ'אט לשולחן העבודה. סוכן הקידוד הוא הפקודה `grok`.

Hermes Desktop היא זו שצריך להכיר, כי למכונה יש Hermes אחד, והוא של האפליקציה: Hermes מותקן רק אי פעם דרך האפליקציה, והפקודה `hermes` שסוכן ברירת המחדל מריץ היא של האפליקציה. בחירה ב-Hermes כסוכן ברירת המחדל מתקינה את אותו דבר שהערך _Install > AI_ מתקין: את החבילה, ו-runtime של Hermes תחת `~/.hermes` שמוגדר על ידי המתקין של Hermes עצמו, שלוקח כמה דקות בפעם הראשונה. ה-runtime הזה הוא ה-Hermes האחד שפקודת ה-`hermes` בטרמינל, סוכן ברירת המחדל והאפליקציה כולם משתמשים בו, והוא מעדכן את עצמו עם `hermes update` במקום לחכות לגרסה של Omarchy. התקנתו גם מוסרת ל-Hermes את ערכת הנושא של Omarchy כסקין בשם `omarchy`, שכל משטח של Hermes עוקב אחריו כשאתם מחליפים ערכות נושא; בחרו אחר תחת הגדרות ה-Appearance של Hermes או עם `/skin` אם אתם מעדיפים שהוא לא יעשה זאת, ו-Omarchy משאירה את הבחירה הזאת בשקט. הסרת האפליקציה תחת _Remove > AI_ סוגרת קודם את Hermes, כולל ה-gateway, לוקחת איתה את ה-runtime הזה, ושומרת את הצ'אטים, הזיכרונות וה-skills ש-Hermes כתב לעצמו אלא אם תגידו לו אחרת: היא שואלת, בברירת מחדל לא, אם גם הנתונים האלה והגדרות החיבור שלכם צריכים ללכת.

חוויית שולחן העבודה של OpenClaw היא ה-Control UI שלו, שנפתח כאפליקציית רשת המגובה על ידי ה-gateway המקומי שלו עצמו. OpenClaw חי ב-`~/.openclaw` ומעדכן את עצמו: השתמשו בכפתור "Update Gateway" של ה-Control UI או הריצו `openclaw update`, וה-gateway מתחיל מחדש על הגרסה החדשה. Omarchy רק בוחרת את הגרסה שהתקנה חדשה מתחילה ממנה. הסרת OpenClaw תחת _Remove > AI_ לוקחת איתה את שירות ה-gateway ואת האפליקציה ואז שואלת אם גם `~/.openclaw` צריך ללכת, מכיוון שזה מחזיק את הצ'אטים והאישורים שלכם לצד OpenClaw עצמו וה-plugin runtimes שהוא מוריד; ברירת המחדל שומרת אותו, והתקנת OpenClaw שוב אוספת אותו חזרה.

Herdr Desktop היא אפליקציית שולחן העבודה של [Herdr](https://herdr.dev): מרחבים, לשוניות וחלוניות של טרמינלים וסוכני קידוד שממשיכים לרוץ בליבה שלו כשאתם סוגרים את החלון. היא מגיעה מהמתקין של Herdr עצמו ולא מחבילה, כך שהיא חיה ב-`~/.local/share/herdr-app`, מביאה איתה את הליבה שלה ב-`~/.local/bin/herdr-core` כשעדיין אין לכם אחת, ומעדכנת את שניהם בעצמה. היא יושבת לצד הפקודה `herdr` ש-Omarchy שולחת ב-`Super + Ctrl + Return` במקום להחליף אותה, ומקבלת את מקשי הישיר של הפקודה הזאת: `Alt + Return` ו-`Alt + Shift + Return` מפצלים חלונית למטה או ימינה, `Alt + Escape` סוגר אותה, `Ctrl + Alt + Arrow` עובר בין חלוניות, `Alt + 1..9` ו-`Alt + Left/Right` בוחרים לשונית, ו-`Alt + Up/Down` עוברים בין מרחבים. `Ctrl + 1..9` בוחר מרחב ו-`Alt + Shift + Up/Down` עובר בין סוכנים. מקשי הקידומת `Ctrl + Space` נשארים לטרמינל בלבד, מכיוון שהאפליקציה לא יכולה להחזיק מקש Ctrl רגיל לרצף. Omarchy כותבת אלה ל-`~/.config/herdr-app/keys.json`, ו-`omarchy-refresh-herdr-app` מחזיר אותם. התקנתה בוחרת את ערכת הנושא Omarchy של Herdr, שעוקבת מעתה אחרי ערכת הנושא של Omarchy שלכם. Herdr שומר ערכת נושא אחת למצב בהיר ואחת למצב כהה, כך שאחרי מעבר בין ערכת נושא כהה לבהירה של Omarchy, בחרו שוב ב-Omarchy בבוחר ערכות הנושא של Herdr למצב האחר.

T3 Code רץ מהגרסה הרשמית AppImage שלו ב-`~/.local/share/t3code` ולא מחבילה, כך שהוא מעדכן את עצמו. התקנתו שואלת אם להתחיל בערוץ Stable או Nightly; החליפו אחר כך בהגדרות של T3 Code. ה-threads וההגדרות שלכם חיים ב-`~/.t3`, והסרת T3 Code תחת _Remove > AI_ לוקחת אותם איתה.

### מודלים מקומיים

הריצו מודל פתוח על המכונה שלכם עבור סוכני הקידוד שלכם. ה-prompt-ים והקוד שלכם נשארים על המכונה; שום דבר שנשלח למודל לא יוצא ממנה. התחילו עם:

```bash
omarchy agent local use best
```

או, בפאנל הסוכנים בסרגל העליון, בחרו + ואז Local AI, שמופיע כשמודל מתאים למכונה הזאת. בפעם הראשונה, זה מתקין את Podman, שמריץ את המודלים, ובמכונת NVIDIA את ערכת הכלים של NVIDIA למכולות, שנותנת להם את ה-GPU. Omarchy אז בוחרת את המודל המומלץ למכונה הזאת, מורידה אותו, ומפעילה אותו. צפו להורדה של עשרות GB ולרוב זיכרון המכונה בשימוש בזמן שהמודל רץ: Flash Next משתמש בכ-100 GiB עם ההקשר המלא של 256K שלו. אם מודלים אחרים מחזיקים את הזיכרון שהוא צריך, הוא מוגדר כעצור, מוכן להתחיל ברגע שתעצרו אחד. המודל עוצר ביציאה מהמערכת; עצרו אותו בעצמכם כשאתם צריכים את הזיכרון למשהו אחר.

`omarchy agent local list` מראה את האפשרויות ומסביר למה חלק לא מתאימות. כדי להגדיר אחד אחר, הריצו `omarchy agent local use <recipe>`. היום, `qwen3.8-flash-next-gufo` ו-`qwen3.8-27b-gufo` זמינים למכונות Strix Halo של 128 GB; ה-27B לוקח כ-40 GiB, כך שהוא משאיר מקום לעבודה אחרת. מתכונים והמלצות חדשים מגיעים עם `omarchy update`, דרך החבילה.

כל מודל שאתם מגדירים מקבל שורה משלו בפאנל הסוכנים, ליד המנויים שלכם: הפעלה כדי להפעיל אותו, השהיה כדי לעצור אותו ולשחרר את הזיכרון שלו, וכפתור הטרמינל כדי לפתוח את הסוכן שלכם עליו. כמה יכולים לרוץ בבת אחת כשהם מתאימים יחד בזיכרון; אם אחד לא מתאים, Omarchy אומרת איזה מודל רץ לעצור. גררו שורות כדי לסדר אותן מחדש, ולחצו Delete על שורה נבחרת כדי להסיר מודל ואת ההורדה שלו.

משורת הפקודה, `omarchy agent local start <recipe>` ו-`omarchy agent local stop <recipe>` עושים את אותו דבר, `omarchy agent local status` מראה כל מודל, ו-`omarchy agent --local` פותח את סוכן ברירת המחדל שלכם על המודל האחרון שהפעלתם (pi אם סוכן ברירת המחדל שלכם לא יכול להשתמש במודל מקומי). כל לקוח תואם OpenAI יכול להתחבר גם: `status` מראה את הכתובת של כל מודל (הראשון הוא `http://127.0.0.1:11435/v1`), שם המתכון הוא המודל, והמפתח נמצא ב-`~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` מוחק מודל ואת ההורדות ששום מודל אחר לא משתמש בהן.

Runtimes של צד שלישי מסומנים עם המפיץ שלהם. Omarchy מריצה כל מודל ללא גישה לרשת.

### LLMs מקומיים

Omarchy ממליצה על שתי דרכים להרצת מודלי LLM מקומיים: LM Studio ו-Ollama. LM Studio מספק ממשק GUI למציאת מודלים במשקלים פתוחים, התקנתם והרצתם. זו דרך מעולה להתחיל בקלות. Ollama מציע CLI לעשות זאת באופן דומה. אבל אם אתם חדשים במודלים מקומיים, הייתי מתחיל עם LM Studio. אפשר להתקין כל אחד מהם תחת _Install > AI_ בתפריט Omarchy.

### ה-Skill של Omarchy

Agent skills עוזרים ל-AI להשתמש בכלים ספציפיים בדרך ספציפית, ו-Omarchy מגיעה עם skill בברירת מחדל להתאמת המערכת. כמו לכוונן את תצורת Hyprland שלכם, להתאים את הסרגל, או אפילו ליצור ערכת נושא חדשה מאפס. הוא מקושר בסימבולית לתיקיות ה-skill של Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` וכל `~/.hermes/profiles/*/skills`), והמיקום הגנרי `~/.agents/skills`, כך שרוב ה-harnesses אוספים אותו אוטומטית.

אבל כדאי להתייחס ל-skill הזה כניסיוני. מודלים שונים ישתמשו בו להשפעה שונה. עדיף לרוץ קודם במצב תכנון, כדי שיהיה לכם מושג מה הסוכן היה רוצה לשנות. ואז תהיו מוכנים לבטל שינויים או אפילו להפעיל `omarchy reinstall configs`, אם הסוכן עושה בלגן מהכל.
