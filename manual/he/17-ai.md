# AI

Omarchy מתייחסת לסוכני קידוד מבוססי AI כאזרחים מהשורה הראשונה, אבל היא לא בוחרת עבורך פייבוריט. במקום זאת, כל CLI מרכזי של סוכן קידוד מגיע מחווט מראש כמשגר בטעינה עצלה. המשגרים הם stubs זעירים המנוהלים על ידי [mise](https://mise.jdx.dev/) ב-`~/.local/bin/`, כך ששום דבר לא מורד עד הפעם הראשונה שבה אתה באמת מריץ אחד מהם. Hermes הוא היוצא מן הכלל: שום דבר לא מוכן עבורו כ-stub, ובחירה בו מתקינה את Hermes Desktop, כפי שמסביר הפרק _אפליקציות שולחן עבודה_ להלן. הפעל כל אחד מאלה והזדהה כשתתבקש:

| פקודה    | סוכן                                                            |
|------------|------------------------------------------------------------------|
| `claude`   | [Claude Code](https://code.claude.com/docs/en/overview)          |
| `codex`    | [OpenAI Codex](https://github.com/openai/codex)                  |
| `opencode` | [OpenCode](https://opencode.ai/)                                 |
| `agy`      | [Google Antigravity CLI](https://github.com/google-antigravity/antigravity-cli) |
| `copilot`  | [GitHub Copilot CLI](https://github.com/github/copilot-cli)      |
| `crush`    | [Crush](https://github.com/charmbracelet/crush)                  |
| `grok`     | [Grok Build](https://x.ai/build) מבית xAI                        |
| `kimi`     | [Kimi Code](https://www.kimi.com/code/docs/en/)                  |
| `pi`       | [Pi של Mario Zechner](https://github.com/badlogic/pi-mono)        |
| `omp`      | [Oh My Pi](https://github.com/can1357/oh-my-pi)                  |
| `ori`      | [Ori](https://openrouter.ai/docs/guides/ori/harness), ה-harness של OpenRouter |
| `hermes`   | [Hermes](https://hermes-agent.nousresearch.com/), הסוכן של Nous Research  |
| `muse`     | [Muse Code](https://dev.meta.ai), סוכן הקידוד של Meta           |
| `cursor-agent` | [Cursor CLI](https://cursor.com/cli)                         |

`ori` הוא היוצא דופן: הוא מריץ את ה-harnesses האחרים מול כל קטלוג המודלים של OpenRouter, כך ש-`ori claude`, `ori codex` או `ori opencode` מפעילים את הסוכנים האלה על כל מודל שתכוון אותם אליו, ו-`ori code` הוא הסוכן של Ori עצמו.

כדי לעטוף CLI נוסף באותו אופן, הרץ `omarchy-mise-install <package> [command-name]`. ה-stubs נשארים מעודכנים יחד עם כל השאר ש-mise מנהל כשאתה מריץ `omarchy update` (או את הכינוי `mup`).

`grok` מותקן דרך חבילת ה-`grok` הרשמית של mise, באותו אופן כמו `claude` ו-`codex`. הרץ `grok`, או בחר אותו תחת _Setup > Defaults > Agent_. דלג על מתקין ה-`curl | bash` שב-x.ai. הנתיב ההוא שם עותק שני ב-`~/.grok/bin`, מקדים אותו ב-`PATH`, ודורס את העטיפה של Omarchy.

### סוכן ברירת המחדל

בחר את סוכן ברירת המחדל שלך עם `omarchy default agent <name>` או תחת _Setup > Defaults > Agent_ בתפריט Omarchy (`Super + Space`). אם הסוכן עדיין לא מותקן, בחירה בו תתקין אותו תחילה. Omarchy טרייה תזמין אותך לבצע את הבחירה הזו עם התראה חד-פעמית.

בחירה ב-Claude מנסה גם להגדיר את תוסף הדפדפן שלו עבור Chromium, Chrome, Brave, Brave Origin ו-Edge. הגדרת התוסף חלה על כל המשתמשים ועשויה לבקש את סיסמת המערכת שלך; ביטול או כשל בהתקנת התוסף עדיין בוחרים ומשגרים את Claude. הפעל מחדש את הדפדפן שלך, אפשר את התוסף אם תתבקש, והתחבר ל-Claude כדי לסיים לחבר אותו. הרץ `/chrome` ב-Claude כדי לבדוק את החיבור. Firefox ו-Zen אינם תומכים בתוסף הזה. אם Claude כבר היה ברירת המחדל שלך לפני שההגדרה הזו נוספה, בחר אותו שוב כדי להתקין את התוסף.

[Muse Code](https://dev.meta.ai) — ה-`muse` של Meta — משתמש ב-stub של mise המותקן מראש כמו הסוכנים האחרים. בחירה בו כברירת מחדל מתקינה את המשגר הרשמי של Meta דרך ה-HTTP backend של mise. המשגר מאמת ומעדכן את הבינארי המקורי עבור המכונה שלך.

ברגע שבחרת, `Super + Shift + Ctrl + A` משגר את סוכן ברירת המחדל בחלון טרמינל ייעודי (או מעלה את הבורר אם עדיין לא בחרת). אתה יכול גם לשגר אותו ישירות לתוך משימה עם `omarchy agent prompt "Review this project"`. סוכנים המשוגרים כך רצים ללא השגחה במצבי אל-תעצור-לשאול שלהם, אז תתכונן לכך שהם באמת יעשו דברים! ומכיוון שסוכנים מסרבים לזכור אמון עבור ספריית הבית שלך, שיגורים מ-`$HOME` מתחילים ב-`~/Work` במקום זאת.

יש גם קיצורי טרמינל: `a` מריץ את סוכן ברירת המחדל בתוך הטרמינל הנוכחי, בעוד ש-`c`, `cx` ו-`cy` מפעילים ישירות את OpenCode, Claude Code ו-Codex (שוב במצבי האישור האוטומטי שלהם). שינויי ערכת נושא מסתנכרנים גם לסוכנים: Claude Code, Pi, OpenCode ו-Hermes (ברגע ש-Omarchy התקינה אותו) כולם עוקבים אחריך כשאתה מחליף את ערכת הנושא של Omarchy.

### פאנל הסוכנים

בסרגל העליון יש אייקון סוכנים. לפני שהגדרת סוכן, הפאנל שלו מלווה אותך בהתחברות ל-Claude, Codex או Grok, והראשון הופך לסוכן ברירת המחדל שלך. אחרי זה, הפאנל שם כל מנוי בעמוד אחד: כל סוכן וחשבון עם התוכנית שלו, מד לכל אחת ממגבלות ההפעלה של 5 שעות והמגבלות השבועיות שלו עם הזמן עד שהוא מתאפס (רחף לקבלת האחוז המדויק), או יתרת התשלום מראש שנותרה, מתחת לשורה שמסתובבת בין מה שהשתמשת בו בכולם, כמו טוקנים השבוע והמודל שבו אתה משתמש הכי הרבה. תחת _Make something_ הוא מציע הנחיות פתיחה לערכת נושא, תוסף או אפליקציה חדשים שמוסרים את המשימה לסוכן ברירת המחדל שלך. אפליקציות נבנות כפי שנבנות Hype, Monologue ו-Omacut של Omarchy עצמה, ב-C++ וב-Qt Quick, בעקבות skill הסוכן omarchy-app, והקומפיילר ורכיבי ה-Qt שהם צריכים מגיעים מותקנים. Claude Code, Codex, Grok, Fireworks ו-Kimi מכוסים מהקופסה. Kimi מדווח כרגע על מגבלות מכסת חשבון ללא סטטיסטיקות מקומיות של טוקנים או הנחיות.

לחץ לחיצה שמאלית על אייקון הסרגל לפאנל, לחיצה ימנית כדי לשגר את סוכן ברירת המחדל שלך. רשומות השימוש שמאחוריו מתרעננות כל 15 דקות על ידי `omarchy agent usage-update`, והפאנל יכול אפילו למזג שימוש מהמכונות האחרות שלך דרך תיקייה מסונכרנת. ראה את ה-README תחת `$OMARCHY_PATH/shell/plugins/agents/` לקבלת ההגדרות המלאות.

### כמה מנויים

אם אתה משלם עבור יותר מתוכנית Claude, Codex או Grok אחת — Max אישית ואחת לעבודה, נגיד — Omarchy יכולה להשאיר את כולם מחוברים ולעבור ביניהם. הוסף מנוי עם ה-+ בפאנל הסוכנים, שמלווה אותך בתהליך ממש שם, או עם `omarchy agent account add claude Work` (או `codex`, או `grok`). הוא מתקין את ה-CLI אם הוא חסר. החשבון הראשון עבור ספק מתחבר דרך הדפדפן הרגיל שלך, בדיוק איפה שה-CLI תמיד מחפש. כל אחד אחרי זה מתחבר דרך חלון פרטי, כך שהחשבון שהדפדפן שלך כבר מחובר אליו לא ייבחר בטעות; התחבר שם כחשבון שאתה מוסיף, וסגור קודם כל חלון פרטי שכבר היה פתוח לך. לעולם אל תתנתק מה-CLI כדי לעשות זאת: התנתקות מבטלת את ההתחברות השמורה, והחשבון ההוא יצטרך להתווסף שוב.

כדי להעתיק את התחברויות המנוי שלך למכונת Omarchy אחרת דרך SSH, הרץ `omarchy agent account copy user@laptop`. השולח מספק מקלט זמני כשליעד אין אחד מותקן, כך שמכונות Omarchy ישנות יותר יכולות לקבל חשבונות ללא עדכון. מקלטים מותקנים מקבלים עדיפות. זה מעתיק את כל מנויי Claude, Codex ו-Grok; הוסף שמות ספקים כדי לבחור אותם, כמו ב-`omarchy agent account copy laptop claude`. שמות חשבונות ומזהי פקודות תואמים את המקור, כולל חשבונות שכבר קיימים ביעד. חשבונות יעד לא קשורים מקבלים סיומת מספרית אם שמותיהם מתנגשים, והגדרות, skills, תוספים והיסטוריית שיחות נשארים מקומיים לכל מכונה.

אישורי יעד קיימים נשמרים. חשבון מקור שכבר מחובר שם מסנכרן את שמו מבלי להחליף את האישורים שלו; חשבונות אחרים נוספים לצידו. כדי להחליף אישורים שמורים לחשבונות תואמים, השתמש ב-`omarchy agent account copy --replace laptop claude` לאחר שיצאת מההפעלות של אותו חשבון ביעד. יעד טרי מקבל גם את החשבון הפעיל ואת העדפות המעבר של המקור; יעד מבוסס שומר על שלו.

אישורים עוברים דרך SSH ונשמרים בקבצים פרטיים ביעד, אז העתק רק למכונות שאתה סומך עליהן. זו העתקה חד-פעמית, לא סנכרון מתמשך. טוקני רענון של Codex יכולים להיות מוחלפים על ידי מכונה אחרת, ולהשאיר התחברות מועתקת הזקוקה לחידוש; התחברויות נפרדות נשארות הבחירה האמינה ביותר לשימוש בו-זמני בכמה מכונות. ראה את [הנחיות אימות החשבון של Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

חשבון אחד לכל ספק פעיל, וכל הפעלה חדשה מתחילה בתורו: `cx`, `cy`, `claude`, `codex` או `grok` רגילים, כל דבר המשוגר דרך `omarchy agent`, וסקריפטים או עורכים שמוצאים את ה-CLI ב-`PATH`. החלף עם `omarchy agent account use work` (ובחזרה עם `omarchy agent account use main`), או בפאנל על ידי לחיצה על מספר של חשבון ואז על `Enter` (או לחיצה על כפתור ה-Use שלו). הפעלות שכבר רצות נשארות על החשבון שבו התחילו. היסטוריית שיחות, הגדרות, skills ותוספים משותפים בין חשבונות, כך ש-`claude --continue` באותה תיקייה ממשיך מאיפה שהפסקת בחשבון החדש.

עם יותר מחשבון אחד, הפאנל מציג את המגבלות של כל חשבון זה לצד זה, כשזה הפעיל מסומן. כברירת מחדל Omarchy מודיעה לך כשהחשבון הפעיל עובר 95% ממגבלה, ולחיצה על ההתראה עוברת לחשבון עם הכי הרבה מרווח. רחף מעל שורת חשבון בפאנל ולחץ על Autoswitch שמופיע ליד Use (או לחץ על `m`), או הרץ `omarchy agent account mode auto`, כדי שיעבור לבד במקום זאת; בזמן שהוא פעיל, Autoswitch תופס את מקומו של Use, ולחיצה עליו שוב חוזרת להתראה. הוסף מספר כדי לשנות את הסף, כמו ב-`omarchy agent account mode auto 90`. אם כל חשבון מעל הסף, תשמע על כך פעם אחת, יחד עם איזה חשבון מתפנה ראשון. בזמן שחשבון פעיל נמצא במרחק של 15 נקודות מהסף שלו (80% בברירת המחדל), המגבלות שלו נבדקות כל שלוש דקות ולא כל 15.

`omarchy agent account list` מציג כל חשבון ואת המגבלות העדכניות שלו, `omarchy agent account remove work` שוכח אחד, ו-`omarchy agent account rename primary Hey` משנה שם של אחד (או לחץ על שמו של חשבון בפאנל). הפקודות האלה פועלות על החשבונות של סוכן ברירת המחדל שלך; כדי להגיע לספק האחר, ציין אותו תחילה, כמו ב-`omarchy agent account use codex side`. ההתחברות שכבר הייתה לך ב-`~/.claude` או ב-`~/.codex` היא החשבון _Main_ ונשארת איפה שהיא. חשבון שנשאר ללא שימוש יותר מכשמונה שעות יכול להציג _Sign-in required_; לחץ עליו כדי לחבר את אותו חשבון שוב ממש בפאנל, או התחל בו הפעלה, שמרעננת את ההתחברות לבדה. שרתי MCP שהיו לך כשחשבון נוסף מגיעים איתו, אבל כאלה שאתה מוסיף אחר כך עם `claude mcp add` מגיעים רק לחשבון שבו הוספת אותם. Claude Desktop וכלים המוגדרים עם נתיב מוחלט לבינארי CLI אינם עוקבים אחר המעבר. `CLAUDE_CONFIG_DIR`, `CODEX_HOME` או `GROK_HOME` מפורשים מקבלים עדיפות על החשבון שנבחר.

### אבחון קריסות

Omarchy עוקבת אחר systemd-coredump לאיתור קריסות תהליכים. כשמשהו קורס עם segfault, תקבל התראה "Process crashed" — לחץ עליה, והקריסה נמסרת לסוכן ברירת המחדל שלך יחד עם skill ה-diagnose-crash של Omarchy, שמלווה את הסוכן בביסוס העובדות מ-core dump ובהחלטה האם הקריסה שווה דיווח במעלה הזרם. אתה יכול גם להריץ אותו ידנית מול כל PID מ-`coredumpctl list` עם `omarchy agent crash <pid>`.

המעקב פעיל כברירת מחדל. כבה אותו תחת _Trigger > Toggle > Crash Capture_ (או עם `omarchy toggle crash-capture`) וההתראות יפסיקו; `omarchy agent crash <pid>` עדיין עובד ידנית.

קריסות יכולות להשתתק גם תוכנית אחת בכל פעם, וזה מה שהאבחון מציע לך בסוף. `omarchy crash mute hyprland` עוצר את ההתראות עבור אותה תוכנית בלבד, `omarchy crash mute hyprland off` מחזיר אותן, ו-`omarchy crash mute` בפני עצמו מפרט מה השתקת. הוא מקבל את נתיב הבינארי בשמחה כמו את שמו, כך ש-`omarchy crash mute /usr/bin/hyprland` עושה את אותו הדבר. צטט שם עם רווח בתוכו, כמו ב-`omarchy crash mute 'Some App'`. כל השאר עדיין מתריע, והתוכנית המושתקת עדיין קורסת — זה מסתיר את התזכורת, זה לא מתקן שום דבר.

### אפליקציות שולחן עבודה

התפריט _Install > AI_ נושא גם כמה אפליקציות AI גרפיות: אפליקציית שולחן העבודה של ChatGPT, אפליקציית שולחן העבודה של Claude (הבטא של Anthropic ללינוקס, עם לשוניות Chat, Cowork ו-Claude Code), Grok Bot לשיחה עם המודלים של xAI, Hermes Desktop, OpenClaw, ואפליקציית שולחן העבודה של Perplexity. Grok Bot היא אפליקציית הצ'אט לשולחן העבודה. סוכן הקידוד הוא הפקודה `grok`.

Hermes Desktop היא זו שכדאי לדעת עליה, כי למכונה יש Hermes אחד, והוא של האפליקציה: Hermes מותקן רק דרך האפליקציה, ופקודת ה-`hermes` שסוכן ברירת המחדל מריץ היא של האפליקציה. בחירה ב-Hermes כסוכן ברירת המחדל מתקינה את אותו הדבר שהרישום _Install > AI_ מתקין: החבילה, ו-runtime של Hermes תחת `~/.hermes` המוגדר על ידי המתקין של Hermes עצמו, שלוקח כמה דקות בפעם הראשונה. ה-runtime ההוא הוא ה-Hermes האחד שפקודת הטרמינל `hermes`, סוכן ברירת המחדל והאפליקציה כולם משתמשים בו, והוא מעדכן את עצמו עם `hermes update` במקום לחכות לגרסת Omarchy. ההתקנה מוסרת ל-Hermes גם את ערכת הנושא של Omarchy כ-skin בשם `omarchy`, שכל משטח Hermes עוקב אחריו כשאתה מחליף ערכות נושא; בחר אחר תחת הגדרות Appearance של Hermes או עם `/skin` אם אתה מעדיף שלא, ו-Omarchy משאירה את הבחירה הזו בשקט. הסרת האפליקציה תחת _Remove > AI_ סוגרת קודם את Hermes, כולל ה-gateway, לוקחת את ה-runtime ההוא איתה, ושומרת את הצ'אטים, הזיכרונות וה-skills ש-Hermes כתב לעצמו אלא אם תגיד לו אחרת: הוא שואל, עם ברירת מחדל של לא, האם גם הנתונים האלה והגדרות החיבור שלך צריכים ללכת.

חוויית שולחן העבודה של OpenClaw היא ה-Control UI שלה, שנפתחת כאפליקציית אינטרנט בגיבוי ה-gateway המקומי שלה. OpenClaw חי ב-`~/.openclaw` ומעדכן את עצמו: השתמש בכפתור "Update Gateway" של ה-Control UI או הרץ `openclaw update`, וה-gateway מופעל מחדש על הגרסה החדשה. Omarchy בוחרת רק את הגרסה שממנה מתחילה התקנה טרייה. הסרת OpenClaw תחת _Remove > AI_ לוקחת איתה את שירות ה-gateway ואת האפליקציה ואז שואלת האם גם `~/.openclaw` צריך ללכת, כי זה מחזיק את הצ'אטים והאישורים שלך לצד OpenClaw עצמה וריצות התוספים שהיא מורידה; ברירת המחדל שומרת אותו, והתקנת OpenClaw שוב קולטת אותו בחזרה.

### LLMs מקומיים

Omarchy ממליצה על שתי דרכים להריץ מודלי LLM מקומיים: LM Studio ו-Ollama. LM Studio מספק ממשק GUI למציאת מודלים פתוחי משקלים, התקנתם והרצתם. זו דרך מצוינת להתחיל בקלות. Ollama מציע CLI לעשות זאת באופן דומה. אבל אם אתה חדש במודלים מקומיים, הייתי מתחיל עם LM Studio. אתה יכול להתקין כל אחד מהם תחת _Install > AI_ בתפריט Omarchy.

### ה-Skill של Omarchy

Skills של סוכנים עוזרים ל-AI להשתמש בכלים ספציפיים בדרך ספציפית, ו-Omarchy מגיעה עם skill ברירת מחדל להתאמת המערכת. כמו לכוונן את תצורת Hyprland שלך, להתאים את הסרגל, או אפילו ליצור ערכת נושא חדשה מאפס. הוא מקושר בסימפלינק לתיקיות ה-skill עבור Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` וכל `~/.hermes/profiles/*/skills`), והמיקום הגנרי `~/.agents/skills`, כך שרוב ה-harnesses קולטים אותו אוטומטית.

אבל כדאי שתתייחס ל-skill הזה כניסיוני. מודלים שונים ישתמשו בו ביעילות שונה. הכי טוב לרוץ קודם במצב תכנון, כדי שתהיה לך תמונה של מה שהסוכן היה רוצה לשנות. ואז תהיה מוכן לבטל שינויים או אפילו להפעיל `omarchy reinstall configs`, אם הסוכן עושה בלגן מהכול.
