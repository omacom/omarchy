# AI

Omarchy כוללת משגרים עבור סוכני הקידוד שלהלן מבלי לבחור עבורך ברירת מחדל. הרץ פקודה כדי להתקין את ה-CLI שלה בשימוש הראשון, ולאחר מכן התחבר כאשר תתבקש לעשות זאת. Hermes הוא היוצא מן הכלל: שום דבר לא מותקן עבורו בשימוש הראשון, ובחירתו מתקינה את Hermes Desktop, כפי ש-_אפליקציות שולחניות_ להלן מסביר.

### התקנה ועדכון של סוכנים

פרט ל-Hermes, הסוכנים הללו משתמשים בהתקנה העצלה של mise: ההפעלה הראשונה מתקינה את ה-CLI, והפעלות מאוחרות יותר עושות בו שימוש חוזר. mise גם בודק אם קיימת גרסה חדשה לסוכן מותקן לכל היותר אחת לארבע שעות, ממש לפני שהוא מתחיל או ברקע בשורת המעטפת. אם העדכון הזה נכשל או שאתה לא מחובר, הגרסה המותקנת רצה. `omarchy update` מעדכן סוכנים מותקנים עם שאר Omarchy, ו-`mup` מעדכן רק כלים המנוהלים על ידי mise.

המעדכן העצמי של סוכן, כגון `claude update`, `codex update` או כפתור עדכון באפליקציה, אינו מעדכן את ההתקנה המנוהלת על ידי mise. `codex update` נכשל, ו-`claude update` יכול לדווח על הצלחה תוך התקנת עותק נפרד ש-mise אינו עוקב אחריו. אם אתה מעדיף להשתמש במתקין ובמעדכן המקוריים של סוכן, הוסף אותו ל-`disable_tools`; ראה [כלי CLI מותקנים מראש](18-development-tools.md#preinstalled-cli-tools).

כדי להתקין את כל הכלים העצלים המוגדרים לפני שתזדקק להם, הרץ `mise install --include-lazy`. זה כולל גם את כלי ה-CLI האחרים של Omarchy כברירת מחדל וגם את הסוכנים. ראה [כלי CLI מותקנים מראש](18-development-tools.md#preinstalled-cli-tools) להתקנת כלי יחיד או לשימוש בהתקנה משלך.

`grok` מותקן דרך חבילת ה-`grok` של mise עצמה, באותו אופן כמו `claude` ו-`codex`. הרץ `grok`, או בחר בו תחת _Agent > Harness_. דלג על מתקין ה-`curl | bash` ב-x.ai. הנתיב הזה מציב עותק שני ב-`~/.grok/bin`, מקדים אותו ב-`PATH`, ודורס את העוטף של Omarchy.

`dsh` פותח את ממשק הדפדפן שלו ב-`127.0.0.1:3080`, כאשר ספריית ההפעלה היא סביבת העבודה המוגדרת כברירת מחדל שלו. ממשק הדפדפן שלו אינו מקבל הנחיית התחלה, ולכן `omarchy agent prompt` פותח אותו כאשר ההנחיה נמצאת בלוח הגזירים שלך כדי להדביק אותה. Omarchy מפעילה אותו עם תצורת ההרשאות ללא-אישור של DeepSeek. DeepSeek Harness מעלה יומני הפעלה ל-DeepSeek כאשר אתה משתמש ב-API הרשמי של המודלים שלה; כבה זאת תחת _Settings > General > Upload Session Log_ בממשק הדפדפן שלו. גם משוב שאתה שולח לו מועלה עם ההפעלה, אלא אם תפעיל אותו עם `DSH_TELEMETRY_MODE=DISABLED`.

### סוכן ברירת המחדל

בחר את סוכן ברירת המחדל שלך עם `omarchy default agent <name>` או תחת _Agent > Harness_ בתפריט Omarchy (`Super + Space`). אם הסוכן עדיין לא מותקן, בחירתו תתקין אותו תחילה. Omarchy חדשה תזמין אותך לבצע בחירה זו בהודעה חד-פעמית.

בחירת Claude מנסה גם להגדיר את תוסף הדפדפן שלו עבור Chromium, Chrome, Brave, Brave Origin ו-Edge. הגדרת התוסף חלה על כל המשתמשים ועשויה לבקש את סיסמת המערכת שלך; ביטול או כשל בהתקנת התוסף עדיין בוחרים ומפעילים את Claude. הפעל מחדש את הדפדפן, אפשר את התוסף אם תתבקש, והתחבר ל-Claude כדי לסיים לחבר אותו. הרץ `/chrome` ב-Claude כדי לבדוק את החיבור. Firefox ו-Zen אינם תומכים בתוסף זה. אם Claude כבר היה ברירת המחדל שלך לפני שהגדרה זו נוספה, בחר בו שוב כדי להתקין את התוסף.

לאחר שבחרת, `Super + Shift + Ctrl + A` מפעיל את סוכן ברירת המחדל בחלון מסוף ייעודי (או מעלה את הבוחר אם עדיין לא בחרת). אתה יכול גם להפעיל אותו ישירות למשימה עם `omarchy agent prompt "Review this project"`. Freebuff ו-DeepSeek Harness אינם מקבלים הנחיית התחלה, ולכן הם נפתחים כאשר ההנחיה נמצאת בלוח הגזירים שלך כדי להדביק אותה במקום זאת. סוכנים המופעלים כך רצים ללא השגחה במצבי האל-תעצור-לשאול שלהם, אז היה מוכן לכך שהם באמת יעשו דברים! ל-MiniMax Code אין מצב כזה להפעלות האינטראקטיביות שלו, ולכן הוא מבקש הרשאות כרגיל. ומאחר שסוכנים מסרבים לזכור אמון עבור ספריית הבית שלך, הפעלות מ-`$HOME` מתחילות ב-`~/Work` במקום זאת.

יש גם קיצורי מסוף: `a` מריץ את סוכן ברירת המחדל בתוך המסוף הנוכחי, בעוד `c`, `cx` ו-`cy` מפעילים את OpenCode, Claude Code ו-Codex ישירות (שוב במצבי האישור האוטומטי שלהם). שינויי ערכת נושא מסתנכרנים גם לסוכנים: Claude Code, Pi, OpenCode ו-Hermes (לאחר ש-Omarchy התקינה אותו) כולם עוקבים כאשר אתה מחליף את ערכת הנושא של Omarchy.

### הוראות הסוכן שלך

כללים אישיים לכל סוכן נמצאים ב-`~/.agents/AGENTS.md`, ליד המיומנויות המשותפות ב-`~/.agents/skills`. פתח אותו תחת _Agent > Instructions_, שגם מקשר אותו לכל harness ששומר קובץ גלובלי משלו: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, ה-`~/.copilot/copilot-instructions.md` של Copilot, וכן הלאה. Crush ו-Amp קוראים את הקישור `~/.config/AGENTS.md`, בעוד omp, Kimi ו-DeepSeek Harness קוראים את `~/.agents/AGENTS.md` ישירות. בחירת סוכן ברירת מחדל מקשרת אותו גם כן. קובץ הוראות שכבר היה לך הופך למשותף אם עדיין לא היה כזה; אחרת הוא נשמר ליד הקישור כ-`.bak`. הרץ `omarchy agent instructions` כדי לקשר מחדש לאחר התקנת סוכן נוסף.

### פאנל הסוכנים

בסרגל העליון יש אייקון סוכנים. לפני שהגדרת סוכן, הפאנל שלו מדריך אותך בהתחברות ל-Claude, Codex או Grok, והראשון הופך לסוכן ברירת המחדל שלך. לאחר מכן, הפאנל מציב כל מנוי בעמוד אחד: כל סוכן וחשבון עם התוכנית שלו, מד לכל אחת ממגבלות ההפעלה של 5 שעות והמגבלות השבועיות שלו עם הזמן עד לאיפוס (רחף לקבלת האחוז המדויק), או היתרה הנותרת ששולמה מראש, תחת שורה המתחלפת בין מה שהשתמשת בו בכולם, כמו טוקנים השבוע והמודל שבו השתמשת הכי הרבה. תחת _Make something_ הוא מציע הנחיות התחלה לערכת נושא, תוסף או אפליקציה חדשים שמעבירים את המשימה לסוכן ברירת המחדל שלך. אפליקציות נבנות באותו אופן שבו נבנו Hype, Monologue ו-Omacut של Omarchy עצמה, ב-C++ וב-Qt Quick, לפי מיומנות הסוכן omarchy-app, והמהדר וחלקי Qt שהם צריכים מגיעים מותקנים. Claude Code, Codex, Grok, Kimi, Cursor והקצבת ה-Grok Bot שלו, GitHub Copilot, Muse, Antigravity, Kimchi ו-Devin מכוסים מהקופסה עם המגבלות שלהם, ו-Hermes, Mistral Vibe ו-Qwen Code מציגים את ההפעלות והטוקנים שלהם לאחר שהשתמשת בהם. תוכניות ספקים ומפתחות שאתה משתמש בהם דרך pi, omp או opencode מופיעים גם כן: OpenCode Zen ו-Go, תוכנית Z.ai GLM Coding Plan, Ollama Cloud, תוכנית MiniMax Token Plan ו-Synthetic עם המגבלות שלהם; Fireworks, OpenRouter ו-DeepSeek עם היתרות ששולמו מראש שלהם; והמודלים שאתה מריץ על החומרה שלך תחת Local models. כל סוכן נספר פעם אחת, תחת מי שמחייב עליו, לא משנה כמה harnesses אתה מפעיל אותו דרכם.

לחץ לחיצה שמאלית על אייקון הסרגל לפאנל, לחיצה ימנית להפעלת סוכן ברירת המחדל שלך. רשומות השימוש שמאחוריו נוצרות מחדש כל 15 דקות על ידי `omarchy agent usage-update`, והפאנל יכול אפילו למזג שימוש ממכונות אחרות שלך דרך תיקייה מסונכרנת. ראה את ה-README תחת `$OMARCHY_PATH/shell/plugins/agents/` להגדרות המלאות.

### מספר מנויים

אם אתה משלם עבור יותר מתוכנית Claude, Codex או Grok אחת — תוכנית Max אישית ואחת של העבודה, נגיד — Omarchy יכולה להשאיר את כולן מחוברות ולעבור ביניהן. הוסף מנוי עם ה-+ בפאנל הסוכנים, שמדריך אותך שם ממש, או עם `omarchy agent account add claude Work` (או `codex`, או `grok`). זה מתקין את ה-CLI אם הוא חסר. החשבון הראשון עבור ספק מתחבר דרך הדפדפן הרגיל שלך, בדיוק היכן שה-CLI תמיד מחפש. כל אחד לאחר מכן מתחבר דרך חלון פרטי, כדי שהחשבון שהדפדפן שלך כבר מחובר אליו לא ייבחר בטעות; התחבר שם כחשבון שאתה מוסיף, וסגור תחילה כל חלון פרטי שכבר פתוח אצלך. לעולם אל תתנתק מה-CLI כדי לעשות זאת: התנתקות מבטלת את ההתחברות השמורה, וחשבון זה יצטרך להתווסף שוב.

כדי להעתיק את התחברויות המנויים שלך למכונת Omarchy אחרת דרך SSH, הרץ `omarchy agent account copy user@laptop`. השולח מספק מקלט זמני כאשר ליעד אין אחד מותקן, כך שמכונות Omarchy ישנות יכולות לקבל חשבונות ללא עדכון. מקלטים מותקנים מקבלים עדיפות. זה מעתיק את כל מנויי Claude, Codex ו-Grok; הוסף שמות ספקים כדי לבחור אותם, כמו ב-`omarchy agent account copy laptop claude`. שמות חשבונות ומזהי פקודות תואמים את המקור, כולל חשבונות שכבר קיימים ביעד. חשבונות יעד לא קשורים מקבלים סיומת מספרית אם שמותיהם מתנגשים, והגדרות, מיומנויות, תוספים והיסטוריית שיחות נשארים מקומיים לכל מכונה.

אישורי יעד קיימים נשמרים. חשבון מקור שכבר מחובר שם, שמו מסונכרן מבלי להחליף את אישוריו; חשבונות אחרים מתווספים לצדו. כדי להחליף אישורים שמורים עבור חשבונות תואמים, השתמש ב-`omarchy agent account copy --replace laptop claude` לאחר יציאה מההפעלות של אותו חשבון ביעד. יעד חדש מקבל גם את החשבון הפעיל והעדפות ההחלפה של המקור; יעד מבוסס שומר את שלו.

אישורים עוברים דרך SSH ומאוחסנים בקבצים פרטיים ביעד, לכן העתק רק למכונות שאתה בוטח בהן. זו העתקה חד-פעמית, לא סנכרון מתמשך. טוקני רענון של Codex יכולים להיות מוחלפים על ידי מכונה אחרת, מה שמשאיר התחברות מועתקת זקוקה לחידוש; התחברויות נפרדות נשארות הבחירה האמינה ביותר לשימוש בו-זמני במספר מכונות. ראה [הנחיות אימות החשבון של Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

חשבון אחד לכל ספק פעיל, וכל הפעלה חדשה מתחילה כמוהו: `cx`, `cy`, `claude`, `codex` או `grok` רגילים, כל דבר המופעל דרך `omarchy agent`, וסקריפטים או עורכים שמוצאים את ה-CLI ב-`PATH`. החלף עם `omarchy agent account use work` (וחזרה עם `omarchy agent account use main`), או בפאנל על ידי לחיצה על מספרו של חשבון ולאחר מכן `Enter` (או לחיצה על כפתור ה-Use שלו). הפעלות שכבר רצות נשארות על החשבון שבו התחילו. היסטוריית שיחות, הגדרות, מיומנויות ותוספים משותפים בין חשבונות, כך ש-`claude --continue` באותה תיקייה ממשיך מהמקום שבו הפסקת בחשבון החדש.

עם יותר מחשבון אחד, הפאנל מציג את מגבלות כל חשבון זו לצד זו, כאשר הפעיל מסומן. כברירת מחדל Omarchy מודיעה לך כאשר החשבון הפעיל עובר 95% ממגבלה, ולחיצה על ההודעה מחליפה לחשבון עם הכי הרבה מרווח. רחף מעל שורת חשבון בפאנל ולחץ על ה-Autoswitch שמופיע ליד Use (או לחץ `m`), או הרץ `omarchy agent account mode auto`, כדי שהוא יחליף בעצמו במקום זאת; בזמן שזה פעיל, Autoswitch תופס את מקומו של Use, ולחיצה עליו שוב חוזרת להתרעה. הוסף מספר כדי לשנות את הסף, כמו ב-`omarchy agent account mode auto 90`. אם כל חשבון מעל הסף, תשמע על כך פעם אחת, יחד עם איזה חשבון משתחרר ראשון. בזמן שחשבון פעיל נמצא בתוך 15 נקודות מהסף שלו (80% כברירת מחדל), מגבלותיו נבדקות כל שלוש דקות ולא כל 15.

`omarchy agent account list` מציג כל חשבון ואת מגבלותיו האחרונות, `omarchy agent account remove work` שוכח אחד, ו-`omarchy agent account rename primary Hey` משנה שם של אחד (או לחץ על שם חשבון בפאנל). פקודות אלה פועלות על חשבונות סוכן ברירת המחדל שלך; כדי להגיע לספק האחר, ציין אותו תחילה, כמו ב-`omarchy agent account use codex side`. ההתחברות שכבר הייתה לך ב-`~/.claude` או ב-`~/.codex` היא חשבון ה-_Main_ ונשארת היכן שהיא. חשבון שנשאר לא בשימוש יותר מכשמונה שעות יכול להציג _Sign-in required_; לחץ עליו כדי לחבר את אותו חשבון שוב ממש בפאנל, או התחל הפעלה בו, שמרעננת את ההתחברות מעצמה. שרתי MCP שהיו לך כאשר חשבון נוסף מגיעים איתו אליו, אך כאלה שאתה מוסיף מאוחר יותר עם `claude mcp add` מגיעים רק לחשבון שבו הוספת אותם. Claude Desktop וכלים שהוגדרו עם נתיב מוחלט לקובץ בינארי של CLI אינם עוקבים אחר ההחלפה. `CLAUDE_CONFIG_DIR`, `CODEX_HOME` או `GROK_HOME` מפורשים מקבלים עדיפות על החשבון הנבחר.

### אבחון קריסות

Omarchy עוקבת אחר systemd-coredump אחר קריסות תהליכים. כאשר משהו מבצע segfault, תקבל הודעת "Process crashed" — לחץ עליה, והקריסה מועברת לסוכן ברירת המחדל שלך יחד עם מיומנות diagnose-crash של Omarchy, שמדריכה את הסוכן בקביעת העובדות מה-core dump ובהחלטה האם הקריסה שווה דיווח ל-upstream. אתה יכול גם להריץ אותה ידנית נגד כל PID מ-`coredumpctl list` עם `omarchy agent crash <pid>`.

המעקב פעיל כברירת מחדל. כבה אותו תחת _Trigger > Toggle > Crash Capture_ (או עם `omarchy toggle crash-capture`) וההודעות מפסיקות; `omarchy agent crash <pid>` עדיין עובד ידנית.

ניתן להשתיק קריסות גם תוכנית אחת בכל פעם, וזה מה שהאבחון מציע לך בסוף. `omarchy crash mute hyprland` עוצר את ההודעות עבור אותה תוכנית בלבד, `omarchy crash mute hyprland off` מחזיר אותן, ו-`omarchy crash mute` בפני עצמו מפרט מה השתקת. הוא מקבל את נתיב הקובץ הבינארי באותה שמחה כמו את שמו, כך ש-`omarchy crash mute /usr/bin/hyprland` עושה אותו דבר. צטט שם עם רווח בתוכו, כמו ב-`omarchy crash mute 'Some App'`. כל השאר עדיין מודיע, והתוכנית המושתקת עדיין קורסת — זה מסתיר את התזכורת, זה לא מתקן כלום.

### אפליקציות שולחניות

תפריט _Install > AI_ נושא גם מספר אפליקציות AI גרפיות: אפליקציית שולחן העבודה של ChatGPT, אפליקציית שולחן העבודה של Claude (גרסת הבטא ל-Linux של Anthropic, עם לשוניות Chat, Cowork ו-Claude Code), Grok Bot לשיחה עם המודלים של xAI, Herdr Desktop, Hermes Desktop, OpenClaw, אפליקציית שולחן העבודה של Perplexity ו-T3 Code. Grok Bot היא אפליקציית הצ'אט השולחנית. סוכן הקידוד הוא פקודת `grok`.

Hermes Desktop היא זו שכדאי להכיר, כי למכונה יש Hermes אחד, והוא של האפליקציה: Hermes מותקן רק אי-פעם דרך האפליקציה, ופקודת `hermes` שסוכן ברירת המחדל מריץ היא של האפליקציה. בחירת Hermes כסוכן ברירת המחדל מתקינה אותו דבר שהערך _Install > AI_ מתקין: החבילה, וזמן ריצה של Hermes תחת `~/.hermes` המוגדר על ידי המתקין של Hermes עצמו, שלוקח כמה דקות בפעם הראשונה. זמן ריצה זה הוא ה-Hermes האחד שפקודת ה-`hermes` במסוף, סוכן ברירת המחדל והאפליקציה כולם משתמשים בו, והוא מעדכן את עצמו עם `hermes update` ולא ממתין לגרסה של Omarchy. התקנתו גם מעניקה ל-Hermes את ערכת הנושא של Omarchy כסקין בשם `omarchy`, שכל משטח של Hermes עוקב אחריו כאשר אתה מחליף ערכות נושא; בחר אחר תחת הגדרות Appearance של Hermes או עם `/skin` אם אתה מעדיף שלא, ו-Omarchy משאירה את הבחירה הזו בשקט. הסרת האפליקציה תחת _Remove > AI_ סוגרת תחילה את Hermes, כולל השער, לוקחת את זמן הריצה הזה איתה, ושומרת את הצ'אטים, הזיכרונות והמיומנויות ש-Hermes כתב לעצמו אלא אם תאמר לה אחרת: היא שואלת, עם ברירת מחדל של לא, האם גם הנתונים האלה והגדרות החיבור שלך צריכים להיעלם.

חוויית שולחן העבודה של OpenClaw היא ה-Control UI שלו, שנפתח כאפליקציית ווב המגובה בשער מקומי משלו. OpenClaw חי ב-`~/.openclaw` ומעדכן את עצמו: השתמש בכפתור "Update Gateway" של ה-Control UI או הרץ `openclaw update`, והשער מופעל מחדש בגרסה החדשה. Omarchy בוחרת רק את הגרסה שממנה התקנה חדשה מתחילה. הסרת OpenClaw תחת _Remove > AI_ לוקחת את שירות השער והאפליקציה איתה ולאחר מכן שואלת האם גם `~/.openclaw` צריך להיעלם, מאחר שזה מחזיק את הצ'אטים והאישורים שלך לצד OpenClaw עצמו וזמני הריצה של התוספים שהוא מוריד; ברירת המחדל שומרת אותו, והתקנת OpenClaw שוב מרימה אותו בחזרה.

Herdr Desktop היא אפליקציית שולחן העבודה [Herdr](https://herdr.dev): מרחבים, לשוניות וחלוניות של מסופים וסוכני קידוד שממשיכים לרוץ בליבה שלה כאשר אתה סוגר את החלון. היא מגיעה מהמתקין של Herdr עצמו ולא מחבילה, לכן היא חיה ב-`~/.local/share/herdr-app`, מביאה את הליבה שלה ב-`~/.local/bin/herdr-core` כאשר עדיין אין לך אחת, ומעדכנת את שניהם בעצמה. היא יושבת לצד פקודת `herdr` ש-Omarchy מספקת ב-`Super + Ctrl + Return` ולא מחליפה אותה, ומקבלת את המקשים הישירים של אותה פקודה: `Alt + Return` ו-`Alt + Shift + Return` מפצלים חלונית למטה או ימינה, `Alt + Escape` סוגר אותה, `Ctrl + Alt + Arrow` נע בין חלוניות, `Alt + 1..9` ו-`Alt + Left/Right` בוחרים לשונית, ו-`Alt + Up/Down` נעים בין מרחבים. `Ctrl + 1..9` בוחר מרחב ו-`Alt + Shift + Up/Down` עובר בין סוכנים. מקשי הקידומת `Ctrl + Space` נשארים למסוף בלבד, מאחר שהאפליקציה אינה יכולה להחזיק מקש Ctrl רגיל לרצף. Omarchy כותבת אלה ל-`~/.config/herdr-app/keys.json`, ו-`omarchy-refresh-herdr-app` מחזירה אותם. התקנתה בוחרת את ערכת הנושא Omarchy של Herdr, שעוקבת אחר ערכת הנושא של Omarchy שלך מאז ואילך. Herdr שומרת ערכת נושא אחת למצב בהיר ואחת למצב כהה, לכן לאחר מעבר בין ערכת נושא כהה לבהירה של Omarchy, בחר ב-Omarchy בבוחר ערכות הנושא של Herdr פעם נוספת עבור המצב האחר.

T3 Code רץ מגרסת ה-AppImage הרשמית שלו ב-`~/.local/share/t3code` ולא מחבילה, לכן הוא מעדכן את עצמו. התקנתו שואלת האם להתחיל בערוץ Stable או Nightly; החלף מאוחר יותר בהגדרות של T3 Code. השרשורים וההגדרות שלך חיים ב-`~/.t3`, והסרת T3 Code תחת _Remove > AI_ לוקחת אותם איתה.

### מודלים מקומיים

הרץ מודל פתוח על המכונה שלך עבור סוכני הקידוד שלך. ההנחיות והקוד שלך נשארים על המכונה; שום דבר שנשלח למודל לא עוזב אותה. התחל עם:

```bash
omarchy agent local use best
```

או, בפאנל הסוכנים בסרגל העליון, בחר + ולאחר מכן Local AI, שמופיע כאשר מודל מתאים למכונה זו. בפעם הראשונה, זה מתקין את Podman, שמריץ את המודלים, ובמכונת NVIDIA את ערכת כלי הקונטיינרים של NVIDIA, שמעניקה להם את ה-GPU. Omarchy בוחרת אז את המודל המומלץ למכונה זו, מורידה אותו ומפעילה אותו. צפה להורדה של עשרות GB ולכך שרוב זיכרון המכונה יהיה בשימוש בזמן שהמודל רץ: Flash Next משתמש בכ-100 GiB עם הקשר מלא של 256K. אם מודלים אחרים מחזיקים את הזיכרון שהוא צריך, הוא מוגדר כמופסק, מוכן להתחיל לאחר שתעצור אחד. המודל עוצר בהתנתקות; עצור אותו בעצמך כאשר אתה צריך את הזיכרון למשהו אחר.

`omarchy agent local list` מציג את האפשרויות ומסביר מדוע חלקן לא מתאימות. כדי להגדיר אחד נוסף, הרץ `omarchy agent local use <recipe>`. כיום, `qwen3.8-flash-next-gufo` ו-`qwen3.8-27b-gufo` זמינים למכונות Strix Halo עם 128 GB; ה-27B לוקח כ-40 GiB, לכן הוא משאיר מקום לעבודה אחרת. מתכונים והמלצות חדשים מגיעים עם `omarchy update`, דרך החבילה.

כל מודל שאתה מגדיר מקבל שורה משלו בפאנל הסוכנים, ליד המנויים שלך: הפעל כדי להתחיל אותו, השהה כדי לעצור אותו ולפנות את זיכרונו, וכפתור המסוף כדי לפתוח את הסוכן שלך עליו. כמה יכולים לרוץ בו-זמנית כאשר הם מתאימים בזיכרון יחד; אם אחד לא מתאים, Omarchy אומרת איזה מודל רץ לעצור. גרור שורות כדי לסדר אותן מחדש, ולחץ Delete על שורה נבחרת כדי להסיר מודל ואת ההורדה שלו.

משורת הפקודה, `omarchy agent local start <recipe>` ו-`omarchy agent local stop <recipe>` עושים אותו דבר, `omarchy agent local status` מציג כל מודל, ו-`omarchy agent --local` פותח את סוכן ברירת המחדל שלך על המודל האחרון שהפעלת. pi, OpenCode ו-Qwen Code יכולים להשתמש באחד; עם כל ברירת מחדל אחרת הוא נפתח ב-pi. pi מפרט גם כל מודל שהגדרת, ואלה במכונות שצימדת איתן, בבוחר המודלים שלו, כך שגם `pi` רגיל מגיע אליהם. כל לקוח תואם OpenAI יכול להתחבר גם כן: `status` מציג את כתובת כל מודל (הראשון הוא `http://127.0.0.1:11435/v1`), שם המתכון הוא המודל, והמפתח נמצא ב-`~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` מוחק מודל ואת ההורדות ששום מודל אחר לא משתמש בהן.

זמני ריצה של צד שלישי מסומנים עם המפרסם שלהם. Omarchy מריצה כל מודל ללא גישה לרשת.

### מודלי LLM מקומיים

Omarchy ממליצה על שתי דרכים להריץ מודלי LLM מקומיים: LM Studio ו-Ollama. LM Studio מספק ממשק GUI למציאת מודלים במשקל-פתוח, התקנתם והרצתם. זו דרך מעולה להתחיל בקלות. Ollama מציע CLI לעשות זאת באופן דומה. אבל אם אתה חדש במודלים מקומיים, הייתי מתחיל עם LM Studio. אתה יכול להתקין כל אחד מהם תחת _Install > AI_ בתפריט Omarchy.

### ה-Skill של Omarchy

מיומנויות סוכן עוזרות ל-AI להשתמש בכלים ספציפיים בדרך ספציפית, ו-Omarchy מגיעה עם מיומנות ברירת מחדל להתאמת המערכת. כמו כוונון תצורת Hyprland שלך, התאמת הסרגל, או אפילו יצירת ערכת נושא חדשה מאפס. היא מקושרת באמצעות קישור סמלי לספריות המיומנויות עבור Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` וכל `~/.hermes/profiles/*/skills`), והמיקום הגנרי `~/.agents/skills`, כך שרוב ה-harnesses קולטים אותה אוטומטית.

אבל עליך להתייחס למיומנות זו כניסיונית. מודלים שונים ישתמשו בה להשפעה שונה. הכי טוב לרוץ במצב תכנון תחילה, כדי שיהיה לך מושג מה הסוכן היה רוצה לשנות. ולאחר מכן היה מוכן להחזיר שינויים לאחור או אפילו להפעיל `omarchy reinstall configs`, אם הסוכן מבלגן הכל.
