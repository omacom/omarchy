# AI

Omarchy כוללת משגרים לסוכני הקידוד שלמטה מבלי לבחור עבורך ברירת מחדל. הרץ פקודה כדי להתקין את ה-CLI שלה בשימוש הראשון, ואז התחבר כאשר תתבקש לעשות זאת. Hermes ו-OpenClaw הם היוצאים מן הכלל: שום דבר לא מותקן עבורם דרך mise, ובחירה בכל אחד מהם מתקינה עותק משלו שמתעדכן בעצמו, כפי ש-_אפליקציות שולחניות_ בהמשך מסביר.

### התקנה ועדכון של סוכנים

למעט Hermes ו-OpenClaw, הסוכנים האלה משתמשים בהתקנה העצלה של mise: ההפעלה הראשונה מתקינה את ה-CLI, והפעלות מאוחרות יותר משתמשות בו שוב. mise גם בודק אם יצאה גרסה חדשה לסוכן מותקן לכל היותר אחת לארבע שעות, ממש לפני שהוא מתחיל או ברקע בהנחיית shell. אם העדכון הזה נכשל או שאתה לא מחובר, הגרסה המותקנת רצה. `omarchy update` מעדכן סוכנים מותקנים יחד עם שאר Omarchy, ו-`mup` מעדכן רק כלים המנוהלים על ידי mise.

המעדכן של סוכן עצמו, כמו `claude update`, `codex update`, או כפתור עדכון באפליקציה, לא מעדכן את ההתקנה המנוהלת על ידי mise. `codex update` נכשל, ו-`claude update` יכול לדווח על הצלחה תוך התקנת עותק נפרד ש-mise לא עוקב אחריו. אם אתה מעדיף להשתמש במתקין ובמעדכן המקוריים של סוכן, הוסף אותו ל-`disable_tools`; ראה [כלי CLI מותקנים מראש](18-development-tools.md#preinstalled-cli-tools).

כדי להתקין את כל הכלים העצלים המוגדרים לפני שתצטרך אותם, הרץ `mise install --include-lazy`. זה כולל גם את כלי ה-CLI המוגדרים כברירת מחדל האחרים של Omarchy וגם את הסוכנים. ראה [כלי CLI מותקנים מראש](18-development-tools.md#preinstalled-cli-tools) להתקנת כלי בודד או לשימוש בהתקנה משלך.

`grok` מותקן דרך חבילת `grok` הרשמית של mise, באותה דרך כמו `claude` ו-`codex`. הרץ `grok`, או בחר אותו תחת _Agent > Harness_. דלג על מתקין ה-`curl | bash` ב-x.ai. הנתיב הזה שם עותק שני ב-`~/.grok/bin`, מוסיף אותו בתחילת `PATH`, ודורס את ה-wrapper של Omarchy.

`dsh` פותח את ממשק הדפדפן שלו ב-`127.0.0.1:3080`, כשספריית ההפעלה היא סביבת העבודה המוגדרת כברירת מחדל שלו. ממשק הדפדפן שלו לא מקבל הנחיית פתיחה, ולכן `omarchy agent prompt` פותח אותו עם ההנחיה על הלוח שלך להדבקה. Omarchy מפעילה אותו עם הגדרת ההרשאות ללא אישור של DeepSeek. DeepSeek Harness מעלה יומני session ל-DeepSeek כאשר אתה משתמש ב-API הרשמי של המודל שלו; כבה זאת תחת _Settings > General > Upload Session Log_ בממשק הדפדפן שלו. גם משוב שאתה שולח אליו מועלה עם ה-session, אלא אם אתה מפעיל אותו עם `DSH_TELEMETRY_MODE=DISABLED`.

### סוכן ברירת המחדל

בחר את סוכן ברירת המחדל שלך עם `omarchy default agent <name>` או תחת _Agent > Harness_ בתפריט Omarchy (`Super + Space`). אם הסוכן עדיין לא מותקן, בחירתו מתקינה אותו תחילה, והוא גם מקבל משגר משלו במשגר האפליקציות, ליד Agent. Omarchy חדשה תזמין אותך לבצע את הבחירה הזו בהתראה חד-פעמית.

בחירה ב-Claude מנסה גם להגדיר את תוסף הדפדפן שלו עבור Chromium, Chrome, Brave, Brave Origin ו-Edge. הגדרת התוסף חלה על כל המשתמשים ויכולה לבקש את סיסמת המערכת שלך; ביטול או התקנת תוסף שנכשלה עדיין בוחרים ומפעילים את Claude. הפעל מחדש את הדפדפן, הפעל את התוסף אם תתבקש, והתחבר ל-Claude כדי לסיים לחבר אותו. הרץ `/chrome` ב-Claude כדי לבדוק את החיבור. Firefox ו-Zen לא תומכים בתוסף הזה. אם Claude כבר היה ברירת המחדל שלך לפני שההגדרה הזו נוספה, בחר אותו שוב כדי להתקין את התוסף.

לאחר שבחרת, `Super + Shift + Ctrl + A` מפעיל את סוכן ברירת המחדל בחלון טרמינל ייעודי (או מעלה את הבוחר אם עדיין לא בחרת). אתה יכול גם להפעיל אותו ישירות למשימה עם `omarchy agent prompt "Review this project"`. ‏Freebuff ו-DeepSeek Harness לא מקבלים הנחיית פתיחה, ולכן הם נפתחים עם ההנחיה על הלוח שלך להדבקה במקום זאת. סוכנים המופעלים כך רצים ללא השגחה במצבי אל-תעצור-לשאול שלהם, אז תהיה מוכן לכך שהם באמת יעשו דברים! ל-MiniMax Code אין מצב כזה עבור ה-sessions האינטראקטיביים שלו, ולכן הוא מבקש הרשאות כרגיל. ומכיוון שסוכנים מסרבים לזכור אמון עבור ספריית הבית שלך, הפעלות מ-`$HOME` מתחילות ב-`~/Work` במקום זאת.

יש גם קיצורי דרך לטרמינל: `a` מריץ את סוכן ברירת המחדל בתוך הטרמינל הנוכחי, בעוד `c`, `cx` ו-`cy` מפעילים את OpenCode, Claude Code ו-Codex ישירות (שוב במצבי האישור האוטומטי שלהם). שינויי ערכת נושא מסתנכרנים גם לסוכנים: Claude Code, Pi, OpenCode ו-Hermes (לאחר ש-Omarchy התקינה אותו) כולם הולכים בעקבותיך כאשר אתה מחליף את ערכת הנושא של Omarchy.

### הוראות הסוכן שלך

כללים אישיים לכל סוכן נמצאים ב-`~/.agents/AGENTS.md`, ליד ה-skills המשותפים ב-`~/.agents/skills`. פתח אותו תחת _Agent > Instructions_, שגם מקשר אותו לכל harness ששומר קובץ גלובלי משלו: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` של Copilot, וכן הלאה. ‏Crush ו-Amp קוראים את הקישור `~/.config/AGENTS.md`, בעוד omp, Kimi ו-DeepSeek Harness קוראים את `~/.agents/AGENTS.md` ישירות. גם בחירת סוכן ברירת מחדל מקשרת אותו. קובץ הוראות שכבר היה לך הופך לקובץ המשותף אם עדיין לא היה כזה; אחרת הוא נשמר ליד הקישור כ-`.bak`. הרץ `omarchy agent instructions` כדי לקשר מחדש לאחר התקנת סוכן נוסף.

### פאנל הסוכנים

בסרגל העליון יש אייקון סוכנים. לפני שהגדרת סוכן, הפאנל שלו מדריך אותך בהתחברות ל-Claude, Codex או Grok, והראשון הופך לסוכן ברירת המחדל שלך. לאחר מכן, הפאנל שם כל מנוי בעמוד אחד: כל סוכן וחשבון עם התוכנית שלו, מד לכל אחת ממגבלות ה-session של 5 שעות והמגבלות השבועיות שלו עם הזמן עד שהוא מתאפס (רחף לקבלת האחוז המדויק), או יתרת התשלום מראש שנותרה, תחת שורה שמתחלפת בין מה שהשתמשת בו בכולם, כמו טוקנים השבוע והמודל שבו אתה משתמש הכי הרבה. תחת _Make something cool_ הוא מציע הנחיות פתיחה לערכת נושא, תוסף, אפליקציה או משחק חדשים שמוסרים את המשימה לסוכן ברירת המחדל שלך. אפליקציות נבנות בדרך שבה בנויות Hype, Monologue ו-Omacut של Omarchy עצמה, ב-C++ וב-Qt Quick, בעקבות ה-skill של הסוכן omarchy-make-app, והקומפיילר וחלקי ה-Qt שהן צריכות מגיעים מותקנים. משחקים הם עמוד three.js יחיד ב-`~/Games/vibes`, בעקבות ה-skill של הסוכן omarchy-make-game, וכולם נפתחים ממשגר Game Vibes אחד בערכת הנושא הנוכחית; הם טוענים את three.js מהרשת, ולכן הם צריכים חיבור כדי להתחיל. ‏Claude Code, Codex, Grok, Kimi, Cursor והקצאת ה-Grok Bot שלו, GitHub Copilot, Muse, Antigravity ו-Devin מכוסים מהקופסה עם המגבלות שלהם, Kimchi עם התוכנית שלו, קרדיטים בתשלום מראש ותקציבי הוצאה, ו-Hermes, Mistral Vibe ו-Qwen Code מציגים את ה-sessions והטוקנים שלהם לאחר שהשתמשת בהם. תוכניות ומפתחות של ספקים שאתה משתמש בהם דרך pi, omp או opencode מופיעים גם כן: OpenCode Zen ו-Go, ה-Z.ai GLM Coding Plan, Ollama Cloud, ה-MiniMax Token Plan ו-Synthetic עם המגבלות שלהם; OpenRouter ו-DeepSeek עם יתרות התשלום מראש שלהם; Fireworks עם ההוצאה שלו ב-30 הימים האחרונים. גם טוקנים ממודלים שאתה מריץ על החומרה שלך נספרים בסכומים; למודלים עצמם יש פאנל משלהם, המתואר תחת [מודלים מקומיים](#local-models). כל סוכן נספר פעם אחת, תחת מי שמחייב אותו, לא משנה בכמה harnesses אתה מנהל אותו.

לחץ לחיצה שמאלית על אייקון הסרגל או לחץ `Super + Ctrl + X` לפאנל, לחץ לחיצה ימנית כדי להפעיל את סוכן ברירת המחדל שלך, ולחץ לחיצה אמצעית כדי לרענן. רשומות השימוש שמאחוריו נוצרות מחדש כל 15 דקות על ידי `omarchy agent usage update`, והפאנל יכול אפילו למזג שימוש מהמכונות האחרות שלך דרך תיקייה מסונכרנת. ראה את ה-README תחת `$OMARCHY_PATH/shell/plugins/agents/` להגדרות המלאות.

### מספר מנויים

אם אתה משלם עבור יותר מתוכנית Claude, Codex או Grok אחת — תוכנית Max אישית ותוכנית עבודה, נניח — Omarchy יכולה להשאיר את כולן מחוברות ולעבור ביניהן. הוסף מנוי עם ה-+ בפאנל הסוכנים, שמדריך אותך שם ממש, או עם `omarchy agent account add claude Work` (או `codex`, או `grok`). הוא מתקין את ה-CLI אם הוא חסר. החשבון הראשון עבור ספק מתחבר דרך הדפדפן הרגיל שלך, בדיוק במקום שבו ה-CLI תמיד מחפש. כל חשבון אחרי כן מתחבר דרך חלון פרטי, כדי שהחשבון שהדפדפן שלך כבר מחובר אליו לא יילקח בטעות; התחבר שם כחשבון שאתה מוסיף, וסגור תחילה כל חלון פרטי שכבר פתוח. אל תתנתק מה-CLI כדי לעשות זאת לעולם: התנתקות מבטלת את ההתחברות השמורה, ואותו חשבון יצטרך להתווסף שוב.

כדי להעתיק את התחברויות המנוי שלך למכונת Omarchy אחרת דרך SSH, הרץ `omarchy agent account copy user@laptop`. השולח מספק מקלט זמני כאשר ליעד אין אחד מותקן, כך שמכונות Omarchy ישנות יותר יכולות לקבל חשבונות בלי עדכון. מקלטים מותקנים מקבלים עדיפות. זה מעתיק את כל מנויי Claude, Codex ו-Grok; הוסף שמות ספקים כדי לבחור אותם, כמו ב-`omarchy agent account copy laptop claude`. שמות חשבונות ומזהי פקודות תואמים למקור, כולל חשבונות שכבר קיימים ביעד. חשבונות יעד לא קשורים מקבלים סיומת מספרית אם שמותיהם מתנגשים, והגדרות, skills, תוספים והיסטוריית שיחות נשארים מקומיים לכל מכונה.

אישורי יעד קיימים נשמרים. לחשבון מקור שכבר מחובר שם שמו מסונכרן מבלי להחליף את האישורים שלו; חשבונות אחרים מתווספים לצדו. כדי להחליף אישורים שמורים עבור חשבונות תואמים, השתמש ב-`omarchy agent account copy --replace laptop claude` לאחר שסיימת את ה-sessions של אותו חשבון ביעד. יעד חדש מקבל גם את החשבון הפעיל והעדפות ההחלפה של המקור; יעד מבוסס שומר את שלו.

אישורים עוברים דרך SSH ומאוחסנים בקבצים פרטיים ביעד, אז העתק רק למכונות שאתה בוטח בהן. זו העתקה חד-פעמית, לא סנכרון מתמשך. טוקני רענון של Codex יכולים להיות מוחלפים על ידי מכונה אחרת, ולהשאיר התחברות מועתקת הזקוקה לחידוש; התחברויות נפרדות נשארות הבחירה האמינה ביותר לשימוש בו-זמני במספר מכונות. ראה [הנחיות אימות החשבון של Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

חשבון אחד לכל ספק פעיל, וכל session חדש מתחיל כמוהו: `cx`, `cy`, `claude`, `codex` או `grok` רגילים, כל דבר המופעל דרך `omarchy agent`, וסקריפטים או עורכים שמוצאים את ה-CLI ב-`PATH`. החלף עם `omarchy agent account use work` (וחזרה עם `omarchy agent account use main`), או בפאנל על ידי לחיצה על מספר החשבון ואז על `Enter` (או לחיצה על כפתור ה-Use שלו). גם sessions רצים של Claude מתחלפים, מההודעה הבאה שלהם: כל session של Claude רץ ב-`~/.claude`, שתמיד מחזיק את התחברות החשבון הפעיל. ‏session של Claude שהתחיל בתיקייה של חשבון עצמו על ידי Omarchy ישנה יותר מחזיק את ההתחברות הזו עד שהוא יוצא, ולכן ההחלפה מציינת את אותם sessions ומסיימת מעצמה לאחר שהם נעלמים. ‏sessions רצים של Codex ו-Grok נשארים על החשבון שהם התחילו איתו. היסטוריית שיחות, הגדרות, skills ותוספים משותפים בין חשבונות, ולכן `claude --continue` באותה תיקייה ממשיך מהמקום שהפסקת בו בחשבון החדש.

עם יותר מחשבון אחד, הפאנל מציג את מגבלות כל חשבון זה לצד זה, כשהפעיל מסומן. כברירת מחדל Omarchy מודיעה לך כאשר החשבון הפעיל עובר 95% ממגבלה, ולחיצה על ההתראה מחליפה לחשבון עם הכי הרבה מרווח. רחף מעל שורת חשבון בפאנל ולחץ על Autoswitch המופיע ליד Use (או לחץ `m`), או הרץ `omarchy agent account mode auto`, כדי שהוא יתחלף מעצמו במקום זאת; בזמן שהוא פועל, Autoswitch תופס את מקומו של Use, ולחיצה עליו שוב חוזרת להתראות. הוסף מספר כדי לשנות את הסף, כמו ב-`omarchy agent account mode auto 90`. אם כל חשבון חורג מהסף, תשמע על כך פעם אחת, יחד עם איזה חשבון משתחרר ראשון. בזמן שחשבון פעיל נמצא במרחק של 15 נקודות מהסף שלו (80% כברירת מחדל), המגבלות שלו נבדקות כל שלוש דקות ולא כל 15.

`omarchy agent account list` מציג כל חשבון ואת המגבלות האחרונות שלו, `omarchy agent account remove work` שוכח אחד, ו-`omarchy agent account rename primary Hey` משנה שם של אחד (או לחץ על שם חשבון בפאנל). הפקודות האלה עובדות על החשבונות של סוכן ברירת המחדל שלך; כדי להגיע לספק האחר, ציין אותו תחילה, כמו ב-`omarchy agent account use codex side`. ההתחברות שכבר הייתה לך ב-`~/.claude` או `~/.codex` היא החשבון _Main_. זו של Codex נשארת במקומה; זו של Claude מחכה בתיקייה משלה בזמן שחשבון אחר פעיל. חשבון שנשאר ללא שימוש יותר מכשמונה שעות יכול להציג _Sign-in required_; לחץ עליו כדי לחבר את אותו חשבון שוב ממש בפאנל, או החלף אליו והתחל session, שמרענן את ההתחברות מעצמו. שרתי MCP שאתה מוסיף עם `claude mcp add` מגיעים לכל חשבון Claude, מכיוון שכולם רצים ב-`~/.claude`; עבור Codex ו-Grok, שרתים שהיו לך כאשר חשבון נוסף באים איתו, אבל מאוחרים יותר מגיעים רק לחשבון שהוספת אותם בו. ‏Claude Desktop שומר התחברות משלו, וכלי Codex או Grok המוגדרים עם נתיב מוחלט לקובץ בינארי של CLI לא עוקבים אחרי ההחלפה. `CLAUDE_CONFIG_DIR`, `CODEX_HOME` או `GROK_HOME` מפורשים מקבלים עדיפות על פני החשבון הנבחר.

### אבחון קריסות

Omarchy עוקבת אחר systemd-coredump לקריסות תהליכים. לאחר שבחרת סוכן ברירת מחדל, כל תוכנית שלך שזורקת core מביאה התראה "Process crashed" — לחץ עליה, והקריסה מועברת לסוכן ברירת המחדל שלך יחד עם ה-skill omarchy-diagnose-crash של Omarchy, שמדריך את הסוכן בביסוס העובדות מה-core dump ובהחלטה אם הקריסה שווה דיווח ל-upstream. אתה יכול גם להריץ אותו ידנית מול כל PID מ-`coredumpctl list` עם `omarchy agent crash <pid>`.

המעקב פועל כברירת מחדל. כבה אותו תחת _Trigger > Toggle > Crash Capture Off_ (או עם `omarchy toggle crash-capture`) וההתראות מפסיקות; `omarchy agent crash <pid>` עדיין עובד ידנית.

ניתן להשתיק קריסות גם תוכנית אחת בכל פעם, וזה מה שהאבחון מציע לך בסוף. `omarchy crash mute hyprland` עוצר את ההתראות עבור אותה תוכנית בלבד, `omarchy crash mute hyprland off` מחזיר אותן, ו-`omarchy crash mute` בפני עצמו מפרט את מה שהשתקת. הוא מקבל את נתיב הקובץ הבינארי באותה נכונות כמו את שמו, כך ש-`omarchy crash mute /usr/bin/hyprland` עושה את אותו הדבר. צטט שם עם רווח בו, כמו ב-`omarchy crash mute 'Some App'`. כל השאר עדיין מתריע, והתוכנית המושתקת עדיין קורסת — זה מסתיר את התזכורת, זה לא מתקן כלום.

### אפליקציות שולחניות

תפריט _Install > AI_ נושא גם כמה אפליקציות AI גרפיות: Amp Desktop, Antigravity Desktop, אפליקציית שולחן העבודה של ChatGPT, אפליקציית שולחן העבודה של Claude (הבטא של Anthropic ל-Linux, עם לשוניות Chat, Cowork ו-Claude Code), Grok Bot לשיחה עם המודלים של xAI, Herdr Desktop, Hermes Desktop, OpenClaw, אפליקציית שולחן העבודה של Perplexity ו-T3 Code. ‏Grok Bot היא אפליקציית הצ'אט לשולחן העבודה. סוכן הקידוד הוא הפקודה `grok`.

Hermes Desktop היא זו שצריך להכיר, מכיוון שלמכונה יש Hermes אחד, והוא של האפליקציה: Hermes מותקן רק אי פעם דרך האפליקציה, והפקודה `hermes` שסוכן ברירת המחדל מריץ היא של האפליקציה. בחירה ב-Hermes כסוכן ברירת המחדל מתקינה את אותו הדבר שעושה הערך _Install > AI_: החבילה, ו-runtime של Hermes תחת `~/.hermes` המוגדר על ידי המתקין של Hermes עצמו, שלוקח כמה דקות בפעם הראשונה. אותו runtime הוא ה-Hermes האחד שפקודת הטרמינל `hermes`, סוכן ברירת המחדל והאפליקציה כולם משתמשים בו, והוא מעדכן את עצמו עם `hermes update` במקום לחכות לגרסה של Omarchy. התקנתו גם נותנת ל-Hermes את ערכת הנושא של Omarchy כ-skin בשם `omarchy`, שכל משטח של Hermes הולך בעקבותיו כאשר אתה מחליף ערכות נושא; בחר אחר תחת הגדרות ה-Appearance של Hermes או עם `/skin` אם אתה מעדיף שלא, ו-Omarchy משאירה את הבחירה הזו בשקט. הסרת האפליקציה תחת _Remove > AI_ סוגרת תחילה את Hermes, כולל ה-gateway, לוקחת את אותו runtime איתה, ושומרת את הצ'אטים, הזיכרונות וה-skills ש-Hermes כתב לעצמו אלא אם אתה אומר לה אחרת: היא שואלת, כברירת מחדל לא, אם גם הנתונים האלה והגדרות החיבור שלך צריכים ללכת.

חוויית שולחן העבודה של OpenClaw היא ה-Control UI שלו, שנפתח כאפליקציית רשת המגובה ב-gateway מקומי משלו. ‏OpenClaw חי ב-`~/.openclaw` ומעדכן את עצמו: השתמש בכפתור "Update Gateway" של ה-Control UI או הרץ `openclaw update`, וה-gateway מתחיל מחדש בגרסה החדשה. ‏Omarchy בוחרת רק את הגרסה שהתקנה חדשה מתחילה ממנה. ‏OpenClaw יכול להיות גם סוכן ברירת המחדל שלך: בחירתו תחת _Agent > Harness_ מגדירה את אותו עותק ב-`~/.openclaw`, והסוכן פותח את ממשק הטרמינל של OpenClaw המחובר ל-gateway שלו. הסרת OpenClaw תחת _Remove > AI_ לוקחת איתה את שירות ה-gateway ואת האפליקציה ואז שואלת אם גם `~/.openclaw` צריך ללכת, מכיוון שהוא מחזיק את הצ'אטים והאישורים שלך יחד עם OpenClaw עצמו ו-runtime-ים של תוספים שהוא מוריד; ברירת המחדל שומרת אותו, והתקנת OpenClaw שוב אוספת אותו בחזרה.

Herdr Desktop היא אפליקציית שולחן העבודה של [Herdr](https://herdr.dev): מרחבים, לשוניות וחלוניות של טרמינלים וסוכני קידוד שממשיכים לרוץ ב-core שלו כאשר אתה סוגר את החלון. היא מגיעה מהמתקין של Herdr עצמו ולא מחבילה, ולכן היא חיה ב-`~/.local/share/herdr-app`, מביאה את ה-core שלה ב-`~/.local/bin/herdr-core` כאשר עדיין אין לך אחד, ומעדכנת את שניהם בעצמה. היא יושבת ליד הפקודה `herdr` ש-Omarchy מספקת ב-`Super + Ctrl + Return` במקום להחליף אותה, ומקבלת את מקשי הישיר של אותה פקודה: `Alt + Return` ו-`Alt + Shift + Return` מפצלים חלונית למטה או ימינה, `Alt + Escape` סוגר אותה, `Ctrl + Alt + Arrow` נע בין חלוניות, `Alt + 1..9` ו-`Alt + Left/Right` בוחרים לשונית, ו-`Alt + Up/Down` נעים בין מרחבים. `Ctrl + 1..9` בוחר מרחב ו-`Alt + Shift + Up/Down` עובר בין סוכנים. מקשי הקידומת `Ctrl + Space` נשארים לטרמינל בלבד, מכיוון שהאפליקציה לא יכולה להחזיק מקש Ctrl רגיל לרצף. ‏Omarchy כותבת אותם ל-`~/.config/herdr-app/keys.json`, ו-`omarchy-refresh-herdr-app` מחזיר אותם. התקנתה בוחרת את ערכת הנושא Omarchy של Herdr, שהולכת בעקבות ערכת הנושא Omarchy שלך מאז. ‏Herdr שומר ערכת נושא אחת למצב בהיר ואחת למצב כהה, ולכן לאחר החלפה בין ערכת נושא Omarchy כהה לבהירה, בחר Omarchy בבוחר ערכות הנושא של Herdr פעם נוספת עבור המצב האחר.

T3 Code רץ מגרסת ה-AppImage הרשמית שלו ב-`~/.local/share/t3code` ולא מחבילה, ולכן הוא מעדכן את עצמו. התקנתו שואלת אם להתחיל בערוץ Stable או Nightly; החלף מאוחר יותר בהגדרות T3 Code. ה-threads וההגדרות שלך חיים ב-`~/.t3`, והסרת T3 Code תחת _Remove > AI_ לוקחת אותם איתה.

### מודלים מקומיים

הרץ מודל פתוח על המכונה שלך עבור סוכני הקידוד שלך. ההנחיות והקוד שלך נשארים על המכונה; שום דבר שנשלח למודל לא עוזב אותה. התחל עם:

```bash
omarchy models use best text
```

זה מגדיר את מודל הטקסט הטוב ביותר למכונה הזו, מהסוג שהסוכנים שלך משתמשים בו. למודלי תמונה, וידאו ומוזיקה יש טוב ביותר משלהם: `omarchy models use best image`, `video` או `music`. הרץ `omarchy models use best` כדי לראות את הבחירה של כל סוג למכונה הזו.

או פתח את פאנל המודלים המקומיים מאייקון הנצנצים שלו בסרגל העליון, ליד אייקון הסוכנים, או עם Super + Ctrl + Shift + X, ובחר +. האייקון מופיע כאשר מודל מתאים למכונה הזו. ‏Podman, שמריץ את המודלים, מגיע עם Omarchy, וכך גם ערכת הכלים של NVIDIA למכונה של NVIDIA, שנותנת להם את ה-GPU; אם אחד מהם חסר, ההגדרה הראשונה מתקינה אותו. ‏Omarchy אז בוחרת את המודל המומלץ למכונה הזו, מורידה אותו ומפעילה אותו. צפה להורדה של עשרות GB ולכך שרוב זיכרון המכונה יהיה בשימוש בזמן שהמודל רץ: Flash Next משתמש בכ-100 GiB עם הקשר ה-256K המלא שלו. אם מודלים אחרים מחזיקים את הזיכרון שהוא צריך, הוא מוגדר כמופסק, מוכן להתחיל לאחר שתעצור אחד. המודל נעצר בהתנתקות; עצור אותו בעצמך כאשר אתה צריך את הזיכרון למשהו אחר.

`omarchy models list` מציג את האפשרויות ומסביר מדוע חלקן לא מתאימות. כדי להגדיר מודל נוסף, הרץ `omarchy models use <recipe>`. היום, `qwen3.8-flash-next-gufo` ו-`qwen3.8-27b-gufo` זמינים למכונות Strix Halo של 128 GB; ה-27B לוקח כ-40 GiB, כך שהוא משאיר מקום לעבודה אחרת. במחשב נייד של 64 GB עם Arc B390 של Intel, `qwen3.6-35b-a3b-llamacpp` רץ בכ-30 GiB. מתכונים והמלצות חדשים מגיעים עם `omarchy update`, דרך החבילה.

כל מודל שאתה מגדיר מקבל שורה משלו בפאנל המודלים המקומיים: play כדי להתחיל אותו, pause כדי לעצור אותו ולפנות את הזיכרון שלו, וכפתור הטרמינל כדי לפתוח את הסוכן שלך עליו. לרוחב החלק העליון, סרגל מציג כיצד זיכרון המכונה מחולק בין Omarchy עצמה (המערכת והאפליקציות שלך), כל מודל רץ, ומה פנוי. הצבע על מודל מופסק והסרגל מציג אם הוא מתאים, או בכמה הוא חסר. כמה יכולים לרוץ בו-זמנית כאשר הם מתאימים יחד בזיכרון; אם אחד לא מתאים, Omarchy אומרת איזה מודל רץ לעצור. גרור שורות לפי הלוגו שלהן כדי לסדר אותן מחדש, ולחץ Delete על שורה נבחרת כדי להסיר מודל ואת ההורדה שלו.

כל מודל שאתה מגדיר מקבל גם ערך משלו במשגר האפליקציות, תחת שם המודל ועם הלוגו של היוצר שלו, בדרך שבה התחברות ל-Claude, Codex או Grok מוסיפה אחד. הוא פותח את הסוכן שלך על אותו מודל, ומפעיל את המודל תחילה אם הוא לא רץ: הטרמינל מציג אותו נטען ומוסר לסוכן לאחר שהוא מוכן. הסרת מודל מסירה את הערך שלו.

לא כל מודל הוא לקידוד. מודלי תמונה, וידאו ומוזיקה נפתחים ב-Fantasi במקום זאת, האפליקציה של Omarchy ליצירת תמונות, וידאו ומוזיקה עם מודל שרץ על המכונה הזו, מהערך שלהם במשגר ומהשורה שלהם בפאנל המודלים המקומיים.

מודל ממשיך לרוץ בדיוק כפי שהוגדר, כך שעדכון של Omarchy אף פעם לא מפעיל מחדש אחד תחת הסוכנים שלך. כאשר ל-Omarchy יש runtime חדש יותר או משקולות חדשות יותר למודל שהגדרת, השורה שלו מציגה כפתור עדכון: לחץ עליו והמודל מוגדר שוב ברקע, מוריד רק את מה שהשתנה, ומתחיל מחדש בגרסה החדשה. מודל שהיה מופסק נשאר מופסק. `omarchy models update` עושה את אותו הדבר לכל מודל מטרמינל.

משורת הפקודה, `omarchy models start <recipe>` ו-`omarchy models stop <recipe>` עושים את אותו הדבר, `omarchy models status` מציג כל מודל, ו-`omarchy agent --local` פותח את סוכן ברירת המחדל שלך על המודל האחרון שהפעלת. ‏pi, OpenCode ו-Qwen Code יכולים להשתמש באחד; עם כל ברירת מחדל אחרת הוא נפתח ב-pi, או ב-OpenCode אם אין לך pi. ‏pi גם מפרט כל מודל שהגדרת, ואלה שעל מכונות שהתאמת איתן, בבוחר המודלים שלו עצמו, כך ש-`pi` רגיל מגיע אליהם גם כן. כל לקוח תואם OpenAI יכול להתחבר גם כן: `status` מציג את כתובת כל מודל (הראשונה היא `http://127.0.0.1:11435/v1`), שם המתכון הוא המודל, והמפתח נמצא ב-`~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` מוחק מודל ואת ההורדות ששום מודל אחר לא משתמש בהן.

runtimes של צד שלישי מסומנים עם המפרסם שלהם. ‏Omarchy מריצה כל מודל ללא גישה לרשת.

### מודלי LLM מקומיים

Omarchy ממליצה על שתי דרכים להרצת מודלי LLM מקומיים: LM Studio ו-Ollama. ‏LM Studio מספק ממשק GUI למציאת מודלים במשקולות פתוחות, התקנתם והרצתם. זו דרך מעולה להתחיל בקלות. ‏Ollama מציע CLI לעשות זאת באופן דומה. אבל אם אתה חדש במודלים מקומיים, הייתי מתחיל עם LM Studio. אתה יכול להתקין כל אחד מהם תחת _Install > AI_ בתפריט Omarchy.

### ה-Skills של Omarchy

Skills של סוכן עוזרים ל-AI להשתמש בכלים ספציפיים בדרך ספציפית, ו-Omarchy מספקת שבעה מהם. ה-skill omarchy מכסה התאמת המערכת, כמו שינוי תצורת Hyprland שלך או התאמת הסרגל. ‏omarchy-make-theme, omarchy-make-plugin, omarchy-make-app ו-omarchy-make-game מכסים יצירת משהו חדש, omarchy-contribute מכסה דיווח על באג או שליחת תיקון ל-upstream, ו-omarchy-diagnose-crash עובד דרך ה-core dump של קריסה. הם מקושרים בסימן לספריות ה-skill עבור Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` וכל `~/.hermes/profiles/*/skills`), והמיקום הגנרי `~/.agents/skills`, כך שרוב ה-harnesses קולטים אותם אוטומטית. תיקיית skill משלך עם אותו שם מקבלת עדיפות.

אבל עליך להתייחס ל-skills האלה כניסיוניים. מודלים שונים ישתמשו בזה לאפקט שונה. עדיף לרוץ תחילה במצב תכנון, כדי שיהיה לך מושג מה הסוכן היה רוצה לשנות. ואז תהיה מוכן לבטל שינויים או אפילו להפעיל `omarchy reinstall configs`, אם הסוכן עושה בלגן מהכול.
