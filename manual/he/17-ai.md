# AI

Omarchy כוללת משגרים לסוכני הקידוד שלמטה מבלי לבחור עבורך ברירת מחדל. הרץ פקודה כדי להתקין את ה-CLI שלה בשימוש הראשון, ואז התחבר כשתתבקש. Hermes ו-OpenClaw הם היוצאים מן הכלל: שום דבר לא מותקן עבורם דרך mise, ובחירה באחד מהם מתקינה עותק משלו שמתעדכן בעצמו, כפי שמסביר _Desktop apps_ למטה.

### התקנה ועדכון של סוכנים

למעט Hermes ו-OpenClaw, הסוכנים האלה משתמשים בהתקנה העצלה של mise: ההפעלה הראשונה מתקינה את ה-CLI, והפעלות מאוחרות יותר משתמשות בו שוב. mise גם בודק אם קיימת מהדורה חדשה לסוכן מותקן לכל היותר אחת לארבע שעות, ממש לפני שהוא מופעל או ברקע ב-prompt של ה-shell. אם העדכון נכשל או שאתה לא מחובר, הגרסה המותקנת רצה. `omarchy update` מעדכן סוכנים מותקנים יחד עם שאר Omarchy, ו-`mup` מעדכן רק כלים המנוהלים על ידי mise.

המעדכן של הסוכן עצמו, כגון `claude update`, `codex update`, או כפתור עדכון באפליקציה, לא מעדכן את ההתקנה המנוהלת על ידי mise. `codex update` נכשל, ו-`claude update` יכול לדווח על הצלחה תוך התקנת עותק נפרד ש-mise לא עוקב אחריו. אם אתה מעדיף להשתמש במתקין ובמעדכן המקוריים של סוכן, הוסף אותו ל-`disable_tools`; ראה [כלי CLI מותקנים מראש](18-development-tools.md#preinstalled-cli-tools).

כדי להתקין את כל הכלים העצלים המוגדרים לפני שתצטרך אותם, הרץ `mise install --include-lazy`. זה כולל גם את כלי ה-CLI ברירת המחדל האחרים של Omarchy וגם את הסוכנים. ראה [כלי CLI מותקנים מראש](18-development-tools.md#preinstalled-cli-tools) להתקנת כלי יחיד או שימוש בהתקנה משלך.

`grok` מותקן דרך החבילה הרשמית `grok` של mise, באותו אופן כמו `claude` ו-`codex`. הרץ `grok`, או סמן אותו בכוכב בפאנל הסוכנים. דלג על מתקין ה-`curl | bash` ב-x.ai. הנתיב הזה מניח עותק שני ב-`~/.grok/bin`, מקדים אותו ב-`PATH`, ודורס את ה-wrapper של Omarchy.

`dsh` פותח את ממשק הדפדפן שלו ב-`127.0.0.1:3080`, עם תיקיית ההפעלה כסביבת העבודה ברירת המחדל שלו. ממשק הדפדפן שלו לא מקבל prompt התחלתי, כך ש-`omarchy agent prompt` פותח אותו עם ה-prompt על הלוח שלך להדבקה. Omarchy מפעילה אותו עם הגדרת ההרשאות no-approval של DeepSeek. DeepSeek Harness מעלה יומני הפעלה ל-DeepSeek כשאתה משתמש ב-API המודלים הרשמי שלו; כבה זאת תחת _Settings > General > Upload Session Log_ בממשק הדפדפן שלו. גם משוב שאתה שולח אליו מועלה יחד עם ההפעלה, אלא אם תפעיל אותו עם `DSH_TELEMETRY_MODE=DISABLED`.

### סוכן ברירת המחדל

בחר את סוכן ברירת המחדל שלך עם הכוכב שליד סוכן בפאנל הסוכנים, שמלא על ברירת המחדל, או עם `omarchy default agent <name>`, שמקבל גם כל harness שאין לו שורה שם. אם הסוכן עדיין לא מותקן, בחירתו מתקינה אותו תחילה, והוא מקבל גם משגר משלו במשגר האפליקציות, לצד Agent. Omarchy חדשה מזמינה אותך להגדיר אחד באמצעות התראה חד-פעמית, שפותחת את פאנל הסוכנים.

בחירה ב-Claude גם מנסה להגדיר את תוסף הדפדפן שלו עבור Chromium, Chrome, Brave, Brave Origin, ו-Edge. הגדרת התוסף חלה על כל המשתמשים ועלולה לבקש את סיסמת המערכת שלך; ביטול או התקנת תוסף שנכשלה עדיין בוחרים ומפעילים את Claude. הפעל מחדש את הדפדפן, הפעל את התוסף אם תתבקש, והתחבר ל-Claude כדי לסיים לחבר אותו. הרץ `/chrome` ב-Claude כדי לבדוק את החיבור. Firefox ו-Zen לא תומכים בתוסף הזה. אם Claude כבר היה ברירת המחדל שלך לפני שההגדרה הזו נוספה, בחר בו שוב כדי להתקין את התוסף.

לאחר שבחרת, `Super + Shift + Ctrl + A` מפעיל את סוכן ברירת המחדל בחלון טרמינל ייעודי (או מעלה את הבוחר אם עדיין לא בחרת). אתה יכול גם להפעיל אותו ישירות לתוך משימה עם `omarchy agent prompt "Review this project"`. Freebuff ו-DeepSeek Harness לא מקבלים prompt התחלתי, כך שהם נפתחים עם ה-prompt על הלוח שלך להדבקה במקום זאת. סוכנים המופעלים כך רצים ללא השגחה במצבי ה-don't-stop-to-ask המתאימים שלהם, אז תהיה מוכן שהם באמת יעשו דברים! ל-MiniMax Code אין מצב כזה עבור ההפעלות האינטראקטיביות שלו, כך שהוא מבקש הרשאות כרגיל. ומכיוון שסוכנים מסרבים לזכור אמון עבור תיקיית הבית שלך, הפעלות מ-`$HOME` מתחילות ב-`~/Work` במקום זאת.

יש גם קיצורי דרך לטרמינל: `a` מריץ את סוכן ברירת המחדל inline בטרמינל הנוכחי, בעוד `c`, `cx`, ו-`cy` מפעילים את OpenCode, Claude Code, ו-Codex ישירות (שוב במצבי האישור האוטומטי שלהם). שינויי ערכת נושא מסתנכרנים גם לסוכנים: Claude Code, Pi, OpenCode, ו-Hermes (לאחר ש-Omarchy התקינה אותו) כולם הולכים בעקבותיך כשאתה מחליף את ערכת הנושא של Omarchy.

### הוראות הסוכן שלך

כללים אישיים לכל סוכן נכנסים ל-`~/.agents/AGENTS.md`, לצד הכישורים המשותפים ב-`~/.agents/skills`. פתח אותו עם אייקון המסמך שליד ה-+ בפאנל הסוכנים, או עם `omarchy agent instructions --edit`, שגם מקשר אותו לכל harness ששומר קובץ גלובלי משלו: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, ה-`~/.copilot/copilot-instructions.md` של Copilot, וכן הלאה. Crush ו-Amp קוראים את הקישור `~/.config/AGENTS.md`, בעוד omp, Kimi, ו-DeepSeek Harness קוראים את `~/.agents/AGENTS.md` ישירות. גם בחירת סוכן ברירת מחדל מקשרת אותו. קובץ הוראות שכבר היה לך הופך למשותף אם עדיין לא היה כזה; אחרת הוא נשמר לצד הקישור כ-`.bak`. הרץ `omarchy agent instructions` כדי לקשר מחדש לאחר התקנת סוכן נוסף.

### פאנל הסוכנים

בסרגל העליון יש אייקון סוכנים. לפני שהגדרת סוכן, הפאנל שלו מציע שלוש דרכים להתחיל: להתחבר למנוי Claude, Codex, Grok, Gemini, Muse, Cursor, או Copilot, או תחת More לתוכנית קידוד של OpenCode Go, MiniMax, Synthetic, או Z.ai; לשלם לפי שימוש עם Fireworks, OpenCode Zen and Go, OpenRouter, או תחת More עם DeepSeek או כל ספק אחר ש-OpenCode מתחבר אליו, כולם רצים ב-OpenCode; או להריץ את המודל הטוב ביותר למחשב שלך, כשאחד מתאים לו. הראשון שתסיים הופך לסוכן ברירת המחדל שלך, וה-+ בפאנל מציע את אותן שלוש מאוחר יותר. לאחר מכן, הפאנל שם כל מנוי בעמוד אחד: כל סוכן וחשבון עם התוכנית שלו, מד לכל אחת ממגבלות ההפעלה של 5 שעות והמגבלות השבועיות שלו עם הזמן עד שהוא מתאפס (רחף לאחוז המדויק), או יתרת ה-prepaid הנותרת, תחת שורה שמסתובבת בין מה שהשתמשת בו בכולם, כמו טוקנים השבוע והמודל שהשתמשת בו הכי הרבה. תחת _Make something cool_ הוא מציע prompts התחלתיים לערכת נושא, תוסף, אפליקציה, או משחק חדשים שמוסרים את המשימה לסוכן ברירת המחדל שלך. אפליקציות נבנות באותו האופן שבו נבנות Hype, Monologue, ו-Omacut של Omarchy עצמה, ב-C++ וב-Qt Quick, בעקבות כישור הסוכן omarchy-make-app, והמהדר וחלקי ה-Qt שהם צריכים מגיעים מותקנים. משחקים הם עמוד three.js יחיד ב-`~/Games/vibes`, בעקבות כישור הסוכן omarchy-make-game, וכולם נפתחים ממשגר Game Vibes יחיד בערכת הנושא הנוכחית; הם טוענים את three.js מהרשת, כך שהם צריכים חיבור כדי להתחיל. Claude Code, Codex, Grok, Kimi, Cursor ומכסת ה-Grok Bot שלו, GitHub Copilot, Muse, Gemini (דרך Antigravity), ו-Devin מכוסים מהקופסה עם המגבלות שלהם, Kimchi עם התוכנית שלו, קרדיטי prepaid, ותקציבי הוצאה, ו-Hermes, Mistral Vibe, ו-Qwen Code מציגים את ההפעלות והטוקנים שלהם לאחר שהשתמשת בהם. גם תוכניות ומפתחות של ספקים שאתה משתמש בהם דרך pi, omp, או opencode מופיעים: OpenCode Zen and Go, ה-Z.ai GLM Coding Plan, Ollama Cloud, ה-MiniMax Token Plan, ו-Synthetic עם המגבלות שלהם; OpenRouter ו-DeepSeek עם יתרות ה-prepaid שלהם; Fireworks עם ההוצאה שלו ב-30 הימים האחרונים. גם טוקנים ממודלים שאתה מריץ על החומרה שלך נספרים בסיכומים; למודלים עצמם יש פאנל משלהם, המתואר תחת [מודלים מקומיים](#local-models). כל סוכן נספר פעם אחת, תחת מי שמחייב עליו, לא משנה בכמה harnesses אתה מפעיל אותו.

לחץ לחיצה שמאלית על אייקון הסרגל או לחץ על `Super + Ctrl + X` לפאנל, לחיצה ימנית להפעלת סוכן ברירת המחדל שלך, ולחיצה אמצעית לריענון. רשומות השימוש שמאחוריו נוצרות מחדש כל 15 דקות על ידי `omarchy agent usage update`, והפאנל יכול אפילו למזג שימוש מהמכונות האחרות שלך דרך תיקייה מסונכרנת. ראה את ה-README תחת `$OMARCHY_PATH/shell/plugins/agents/` להגדרות המלאות.

### כמה מנויים

אם אתה משלם על יותר מתוכנית Claude, Codex, או Grok אחת — Max אישית ואחת של עבודה, נניח — Omarchy יכולה להשאיר את כולן מחוברות ולעבור ביניהן. הוסף מנוי עם ה-+ בפאנל הסוכנים, שמדריך אותך שם ממש, או עם `omarchy agent account add claude Work` (או `codex`, או `grok`). אותו + ואותה פקודה מתחברים גם ל-Gemini‏ (`gemini`) ול-OpenCode‏ (`opencode`), ושומרים מפתח API של Fireworks‏ (`fireworks`) או OpenRouter‏ (`openrouter`) ב-OpenCode; הפקודה גם מתחברת ל-Copilot‏ (`copilot`), Cursor‏ (`cursor`), ו-Muse‏ (`muse`). אלה שומרים התחברות אחת כל אחד. היא מתקינה את ה-CLI אם הוא חסר. החשבון הראשון עבור ספק מתחבר דרך הדפדפן הרגיל שלך, בדיוק היכן שה-CLI תמיד מחפש. כל אחד אחריו מתחבר דרך חלון פרטי, כך שהחשבון שהדפדפן שלך כבר מחובר אליו לא ייבחר בטעות; התחבר שם כחשבון שאתה מוסיף, וסגור כל חלון פרטי שכבר היה לך פתוח קודם. לעולם אל תתנתק מה-CLI כדי לעשות זאת: התנתקות מבטלת את ההתחברות השמורה, והחשבון הזה יצטרך להתווסף שוב.

כדי להעתיק את התחברויות המנוי שלך למכונת Omarchy אחרת דרך SSH, הרץ `omarchy agent account copy user@laptop`. השולח מספק receiver זמני כשליעד אין אחד מותקן, כך שמכונות Omarchy ישנות יותר יכולות לקבל חשבונות ללא עדכון. receivers מותקנים מקבלים עדיפות. זה מעתיק את כל מנויי Claude, Codex, ו-Grok; הוסף שמות ספקים כדי לבחור אותם, כמו ב-`omarchy agent account copy laptop claude`. שמות חשבונות ומזהי פקודות תואמים למקור, כולל חשבונות שכבר קיימים ביעד. חשבונות יעד לא קשורים מקבלים סיומת מספרית אם שמותיהם מתנגשים, והגדרות, כישורים, תוספים, והיסטוריית שיחות נשארים מקומיים לכל מכונה.

אישורי יעד קיימים נשמרים. חשבון מקור שכבר מחובר שם מקבל את שמו מסונכרן מבלי להחליף את האישורים שלו; חשבונות אחרים מתווספים לצדו. כדי להחליף אישורים שמורים עבור חשבונות תואמים, השתמש ב-`omarchy agent account copy --replace laptop claude` לאחר שסיימת את הפעלות החשבון הזה ביעד. יעד חדש גם מקבל את החשבון הפעיל והעדפות ההחלפה של המקור; יעד מבוסס שומר את שלו.

אישורים עוברים דרך SSH ומאוחסנים בקבצים פרטיים ביעד, אז העתק רק למכונות שאתה בוטח בהן. זו העתקה חד-פעמית, לא סנכרון מתמשך. ניתן לסובב אסימוני ריענון של Codex על ידי מכונה אחרת, ולהשאיר התחברות מועתקת הזקוקה לחידוש; התחברויות נפרדות נשארות הבחירה האמינה ביותר לשימוש בו-זמני בכמה מכונות. ראה [הנחיות אימות החשבון של Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

חשבון אחד לכל ספק פעיל, וכל הפעלה חדשה מתחילה כמוהו: `cx`, `cy`, `claude`, `codex`, או `grok` רגילים, כל דבר המופעל דרך `omarchy agent`, וסקריפטים או עורכים שמוצאים את ה-CLI ב-`PATH`. החלף עם `omarchy agent account use work` (ובחזרה עם `omarchy agent account use main`), או בפאנל על ידי לחיצה על מספר של חשבון ואז `Enter` (או לחיצה על הכוכב שלו). גם הפעלות Claude רצות מחליפות, מההודעה הבאה שלהן: כל הפעלת Claude רצה ב-`~/.claude`, שתמיד מחזיקה את התחברות החשבון הפעיל. הפעלת Claude שהתחילה בתיקייה של חשבון עצמו על ידי Omarchy ישנה יותר מחזיקה את ההתחברות הזו עד שהיא מסתיימת, כך שההחלפה מציינת את ההפעלות האלה ומסתיימת מעצמה לאחר שהן נעלמות. הפעלות Codex ו-Grok רצות נשארות על החשבון שהן התחילו איתו. היסטוריית שיחות, הגדרות, כישורים, ותוספים משותפים בין חשבונות, כך ש-`claude --continue` באותה תיקייה ממשיך היכן שהפסקת בחשבון החדש.

עם יותר מחשבון אחד, הפאנל מציג את מגבלות כל חשבון זו לצד זו, עם כוכב מלא על זה שבשימוש. Omarchy מודיעה לך כשהחשבון הפעיל עובר 95% ממגבלה, ולחיצה על ההתראה מחליפה לחשבון עם הכי הרבה מרווח. היא לעולם לא מחליפה מעצמה. שנה את הסף עם `omarchy agent account threshold 90`. אם כל חשבון מעל הסף, תשמע על כך פעם אחת, יחד עם איזה חשבון מתפנה ראשון. בעוד חשבון פעיל נמצא בתוך 15 נקודות מהסף שלו (80% בברירת המחדל), המגבלות שלו נבדקות כל שלוש דקות ולא כל 15.

`omarchy agent account list` מציג כל חשבון ואת המגבלות האחרונות שלו, `omarchy agent account remove work` שוכח אחד, ו-`omarchy agent account rename primary Hey` משנה שם של אחד (או לחץ על שם חשבון בפאנל). פקודות אלה פועלות על חשבונות סוכן ברירת המחדל שלך; כדי להגיע לספק האחר, ציין אותו תחילה, כמו ב-`omarchy agent account use codex side`. ההתחברות שכבר הייתה לך ב-`~/.claude` או `~/.codex` היא חשבון ה-_Main_. זו של Codex נשארת היכן שהיא; זו של Claude מחכה בתיקייה משלה בעוד חשבון אחר פעיל. חשבון שנשאר ללא שימוש יותר מכשמונה שעות יכול להציג _Sign-in required_; לחץ עליו כדי לחבר את החשבון הזה שוב ממש בפאנל, או החלף אליו והתחל הפעלה, שמרעננת את ההתחברות מעצמה. שרתי MCP שאתה מוסיף עם `claude mcp add` מגיעים לכל חשבון Claude, מכיוון שכולם רצים ב-`~/.claude`; עבור Codex ו-Grok, שרתים שהיו לך כשהחשבון נוסף באים איתו, אבל מאוחרים יותר מגיעים רק לחשבון שהוספת אותם בו. Claude Desktop שומר התחברות משלו, וכלי Codex או Grok המוגדרים עם נתיב מוחלט לקובץ בינארי של CLI לא עוקבים אחר ההחלפה. `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, או `GROK_HOME` מפורשים מקבלים עדיפות על פני החשבון הנבחר.

### אבחון קריסות

Omarchy צופה ב-systemd-coredump אחר קריסות תהליכים. לאחר שבחרת סוכן ברירת מחדל, כל תוכנית שלך שזורקת core מביאה התראת "Process crashed" — לחץ עליה, והקריסה נמסרת לסוכן ברירת המחדל שלך יחד עם כישור ה-omarchy-diagnose-crash של Omarchy, שמדריך את הסוכן בקביעת העובדות מה-core dump ובהחלטה האם הקריסה שווה דיווח upstream. אתה יכול גם להריץ אותו ידנית מול כל PID מ-`coredumpctl list` עם `omarchy agent crash <pid>`.

הצפייה מופעלת בברירת מחדל. כבה אותה תחת _Trigger > Toggle > Crash Capture Off_ (או עם `omarchy toggle crash-capture`) וההתראות מפסיקות; `omarchy agent crash <pid>` עדיין עובד ידנית.

ניתן גם להשתיק קריסות תוכנית אחת בכל פעם, שזה מה שהאבחון מציע לך בסוף. `omarchy crash mute hyprland` עוצר את ההתראות עבור התוכנית הזו בלבד, `omarchy crash mute hyprland off` מחזיר אותן, ו-`omarchy crash mute` לבדו מציג את מה שהשתקת. הוא מקבל את נתיב הקובץ הבינארי בשמחה כמו את שמו, כך ש-`omarchy crash mute /usr/bin/hyprland` עושה את אותו הדבר. צטט שם עם רווח בו, כמו ב-`omarchy crash mute 'Some App'`. כל השאר עדיין מודיע, והתוכנית המושתקת עדיין קורסת — זה מסתיר את התזכורת, זה לא מתקן כלום.

### אפליקציות שולחניות

תפריט _Install > AI_ נושא גם כמה אפליקציות AI גרפיות: Amp Desktop, Antigravity Desktop, אפליקציית שולחן העבודה של ChatGPT, אפליקציית שולחן העבודה של Claude (הבטא ל-Linux של Anthropic, עם לשוניות Chat, Cowork, ו-Claude Code), Grok Bot לצ'אט עם המודלים של xAI, Herdr Desktop, Hermes Desktop, OpenClaw, אפליקציית שולחן העבודה של Perplexity, ו-T3 Code. Grok Bot היא אפליקציית הצ'אט לשולחן העבודה. סוכן הקידוד הוא פקודת ה-`grok`.

Hermes Desktop היא זו שכדאי לדעת עליה, מכיוון שלמכונה יש Hermes אחד, והוא של האפליקציה: Hermes מותקן רק אי פעם דרך האפליקציה, ופקודת ה-`hermes` שסוכן ברירת המחדל מריץ היא של האפליקציה. בחירת Hermes כסוכן ברירת מחדל מתקינה את אותו הדבר שעושה הערך _Install > AI_: החבילה, וסביבת ריצה של Hermes תחת `~/.hermes` המוגדרת על ידי המתקין של Hermes עצמו, שלוקח כמה דקות בפעם הראשונה. סביבת הריצה הזו היא ה-Hermes היחיד שפקודת ה-`hermes` הטרמינלית, סוכן ברירת המחדל והאפליקציה כולם משתמשים בו, והיא מתעדכנת בעצמה עם `hermes update` במקום לחכות למהדורת Omarchy. התקנתה גם מוסרת ל-Hermes את ערכת הנושא של Omarchy כ-skin בשם `omarchy`, שכל משטח של Hermes עוקב אחריו כשאתה מחליף ערכות נושא; בחר אחרת תחת הגדרות ה-Appearance של Hermes או עם `/skin` אם אתה מעדיף שלא, ו-Omarchy משאירה את הבחירה הזו לבד. הסרת האפליקציה תחת _Remove > AI_ סוגרת תחילה את Hermes, כולל ה-gateway, לוקחת את סביבת הריצה הזו איתה, ושומרת את הצ'אטים, הזיכרונות, והכישורים ש-Hermes כתב לעצמו אלא אם תאמר לה אחרת: היא שואלת, עם ברירת מחדל של לא, האם גם הנתונים האלה והגדרות החיבור שלך צריכים ללכת.

חוויית שולחן העבודה של OpenClaw היא ה-Control UI שלו, שנפתח כאפליקציית רשת הנתמכת על ידי ה-gateway המקומי שלו עצמו. OpenClaw חי ב-`~/.openclaw` ומתעדכן בעצמו: השתמש בכפתור "Update Gateway" של ה-Control UI או הרץ `openclaw update`, וה-gateway מופעל מחדש בגרסה החדשה. Omarchy רק בוחרת את המהדורה שהתקנה חדשה מתחילה ממנה. OpenClaw יכול להיות גם סוכן ברירת המחדל שלך: בחירתו עם `omarchy default agent openclaw` מגדירה את אותו עותק ב-`~/.openclaw`, והסוכן פותח את ממשק המשתמש הטרמינלי של OpenClaw המחובר ל-gateway שלו. הסרת OpenClaw תחת _Remove > AI_ לוקחת איתה את שירות ה-gateway ואת האפליקציה ואז שואלת האם גם `~/.openclaw` צריך ללכת, מכיוון שזה מחזיק את הצ'אטים והאישורים שלך לצד OpenClaw עצמו וסביבות ריצת התוספים שהוא מוריד; ברירת המחדל שומרת אותו, והתקנת OpenClaw שוב מרימה אותו בחזרה.

Herdr Desktop היא אפליקציית שולחן העבודה [Herdr](https://herdr.dev): מרחבים, לשוניות, וחלוניות של טרמינלים וסוכני קידוד שממשיכים לרוץ בליבה שלו כשאתה סוגר את החלון. היא מגיעה מהמתקין של Herdr עצמו ולא מחבילה, כך שהיא חיה ב-`~/.local/share/herdr-app`, מביאה את הליבה שלה איתה ב-`~/.local/bin/herdr-core` כשעדיין אין לך אחת, ומעדכנת את שניהם בעצמה. היא יושבת לצד פקודת ה-`herdr` ש-Omarchy מספקת ב-`Super + Ctrl + Return` במקום להחליף אותה, ומקבלת את המקשים הישירים של הפקודה הזו: `Alt + Return` ו-`Alt + Shift + Return` מפצלים חלונית למטה או ימינה, `Alt + Escape` סוגר אותה, `Ctrl + Alt + Arrow` עובר בין חלוניות, `Alt + 1..9` ו-`Alt + Left/Right` בוחרים לשונית, ו-`Alt + Up/Down` עוברים בין מרחבים. `Ctrl + 1..9` בוחר מרחב ו-`Alt + Shift + Up/Down` עובר בין סוכנים. מקשי הקידומת `Ctrl + Space` נשארים לטרמינל בלבד, מכיוון שהאפליקציה לא יכולה להחזיק מקש Ctrl רגיל לרצף. Omarchy כותבת את אלה ל-`~/.config/herdr-app/keys.json`, ו-`omarchy-refresh-herdr-app` מחזיר אותם. התקנתה בוחרת את ערכת הנושא Omarchy של Herdr, שעוקבת אחר ערכת הנושא של Omarchy שלך מאז. Herdr שומר ערכת נושא אחת למצב בהיר ואחת למצב כהה, כך שלאחר מעבר בין ערכת נושא Omarchy כהה לבהירה, בחר שוב ב-Omarchy בבוחר ערכות הנושא של Herdr עבור המצב האחר.

T3 Code רץ ממהדורת ה-AppImage הרשמית שלו ב-`~/.local/share/t3code` ולא מחבילה, כך שהוא מתעדכן בעצמו. התקנתו שואלת האם להתחיל בערוץ Stable או Nightly; החלף מאוחר יותר בהגדרות של T3 Code. השרשורים וההגדרות שלך חיים ב-`~/.t3`, והסרת T3 Code תחת _Remove > AI_ לוקחת אותם איתה.

### מודלים מקומיים

הרץ מודל פתוח על המכונה שלך עבור סוכני הקידוד שלך. ה-prompts והקוד שלך נשארים על המכונה; שום דבר שנשלח למודל לא עוזב אותה. התחל עם:

```bash
omarchy models use best text
```

זה מגדיר את מודל הטקסט הטוב ביותר למכונה הזו, הסוג שהסוכנים שלך משתמשים בו. למודלי תמונה, וידאו ומוזיקה יש טוב ביותר משלהם: `omarchy models use best image`, `video` או `music`. הרץ `omarchy models use best` כדי לראות את הבחירה של כל סוג למכונה הזו.

או פתח את פאנל המודלים המקומיים מאייקון הניצוצות שלו בסרגל העליון, לצד אייקון הסוכנים, או עם Super + Ctrl + Alt + X, ובחר +. האייקון מופיע כשמודל מתאים למכונה הזו. Podman, שמריץ את המודלים, מגיע עם Omarchy, וכך גם ערכת הכלים למכולות של NVIDIA במכונת NVIDIA, שנותנת להם את ה-GPU; אם אחד מהם חסר, ההגדרה הראשונה מתקינה אותו. Omarchy אז בוחרת את המודל המומלץ למכונה הזו, מורידה אותו, ומפעילה אותו. צפה להורדה של עשרות GB ולרוב זיכרון המכונה בשימוש בעוד המודל רץ: Flash Next משתמש בכ-100 GiB עם הקשר ה-256K המלא שלו. אם מודלים אחרים מחזיקים את הזיכרון שהוא צריך, הוא מוגדר עצור, מוכן להתחיל לאחר שתעצור אחד. המודל נעצר בהתנתקות; עצור אותו בעצמך כשאתה צריך את הזיכרון למשהו אחר.

`omarchy models list` מציג את האפשרויות ומסביר מדוע חלקן לא מתאימות. כדי להגדיר אחד נוסף, הרץ `omarchy models use <recipe>`. כיום, `qwen3.8-flash-next-gufo` ו-`qwen3.8-27b-gufo` זמינים למכונות Strix Halo של 128 GB; ה-27B לוקח כ-40 GiB, כך שהוא משאיר מקום לעבודה אחרת. במחשב נייד של 64 GB עם Arc B390 של Intel,‏ `qwen3.6-35b-a3b-llamacpp` רץ בכ-30 GiB. מתכונים והמלצות חדשים מגיעים עם `omarchy update`, דרך החבילה.

כל מודל שאתה מגדיר מקבל שורה משלו בפאנל המודלים המקומיים: הפעל כדי להתחיל אותו, השהה כדי לעצור אותו ולשחרר את הזיכרון שלו, וכפתור הטרמינל כדי לפתוח את הסוכן שלך עליו. לרוחב החלק העליון, סרגל מציג כיצד זיכרון המכונה מחולק בין Omarchy עצמה (המערכת והאפליקציות שלך), כל מודל רץ, ומה פנוי. הצבע על מודל עצור והסרגל מציג האם הוא מתאים, או בכמה הוא חסר. כמה יכולים לרוץ בבת אחת כשהם מתאימים בזיכרון יחד; אם אחד לא מתאים, Omarchy אומרת איזה מודל רץ לעצור. גרור שורות לפי הלוגו שלהן כדי לסדר אותן מחדש, ולחץ על Delete בשורה נבחרת כדי להסיר מודל ואת ההורדה שלו.

כל מודל קידוד שאתה מגדיר מקבל גם ערך משלו במשגר האפליקציות, תחת שם המודל ועם הלוגו של היוצר שלו, באותו האופן שבו התחברות ל-Claude, Codex או Grok מוסיפה אחד. הוא פותח את הסוכן שלך על המודל הזה, ומפעיל את המודל תחילה אם הוא לא רץ: הטרמינל מציג אותו נטען ומוסר לסוכן לאחר שהוא עלה. הסרת מודל מסירה את הערך שלו.

לא כל מודל הוא לקידוד. מודלי תמונה, וידאו ומוזיקה נפתחים ב-Fantasi במקום זאת, האפליקציה של Omarchy ליצירת תמונות, וידאו ומוזיקה עם מודל שרץ על המכונה הזו, הנבחר שם או מהשורה שלהם בפאנל המודלים המקומיים.

מודל ממשיך לרוץ בדיוק כפי שהוגדר, כך שעדכון Omarchy לעולם לא מפעיל מחדש אחד תחת הסוכנים שלך. כש-Omarchy יש סביבת ריצה חדשה יותר או משקולות חדשות יותר למודל שהגדרת, השורה שלו מציגה כפתור עדכון: לחץ עליו והמודל מוגדר מחדש ברקע, מוריד רק את מה שהשתנה, ומופעל מחדש בגרסה החדשה. מודל שהיה עצור נשאר עצור. `omarchy models update` עושה את אותו הדבר לכל מודל מהטרמינל.

משורת הפקודה, `omarchy models start <recipe>` ו-`omarchy models stop <recipe>` עושים את אותו הדבר, `omarchy models status` מציג כל מודל, ו-`omarchy agent --local-model <recipe>` פותח את המודל הזה ב-pi, לא משנה מה סוכן ברירת המחדל שלך. כדי להפוך את המודל המקומי שלך למה שמקש הסוכן, קונסולת ה-Quake, ו-_Make something_ פותחים, הרץ `omarchy default agent local` או סמן בכוכב מודל רץ בפאנל הסוכנים. pi גם מציג כל מודל שהגדרת, ואלה במכונות שציוותת איתן, בבוחר המודלים שלו עצמו, כך ש-`pi` רגיל מגיע אליהם גם. כל לקוח תואם OpenAI יכול להתחבר גם: `status` מציג את כתובת כל מודל (הראשונה היא `http://127.0.0.1:11435/v1`), שם המתכון הוא המודל, והמפתח נמצא ב-`~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` מוחק מודל ואת ההורדות שאף מודל אחר לא משתמש בהן.

סביבות ריצה של צד שלישי מסומנות עם המפרסם שלהן. Omarchy מריצה כל מודל ללא גישת רשת.

### מודלי LLM מקומיים

Omarchy ממליצה על שתי דרכים להריץ מודלי LLM מקומיים: LM Studio ו-Ollama.‏ LM Studio מספק ממשק GUI למציאת מודלים פתוחי-משקל, התקנתם, והרצתם. זו דרך מעולה להתחיל בקלות. Ollama מציע CLI לעשות זאת באופן דומה. אבל אם אתה חדש במודלים מקומיים, הייתי מתחיל עם LM Studio. אתה יכול להתקין אחד מהם תחת _Install > AI_ בתפריט Omarchy.

### הכישורים של Omarchy

כישורי סוכן עוזרים ל-AI להשתמש בכלים ספציפיים בדרך ספציפית, ו-Omarchy מספקת שבעה מהם. הכישור omarchy מכסה התאמת המערכת, כמו כוונון תצורת Hyprland שלך או התאמת הסרגל. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app, ו-omarchy-make-game מכסים יצירת משהו חדש, omarchy-contribute מכסה דיווח על באג או שליחת תיקון upstream, ו-omarchy-diagnose-crash עובר על core dump של קריסה. הם מקושרים סימבולית לתיקיות הכישורים עבור Claude Code‏ (`~/.claude/skills`), Codex‏ (`~/.codex/skills`), Pi‏ (`~/.pi/agent/skills`), Antigravity‏ (`~/.gemini/config/skills`), Hermes‏ (`~/.hermes/skills` וכל `~/.hermes/profiles/*/skills`), והמיקום הגנרי `~/.agents/skills`, כך שרוב ה-harnesses אוספים אותם אוטומטית. תיקיית כישור משלך עם אותו שם מקבלת עדיפות.

אבל כדאי להתייחס לכישורים האלה כניסיוניים. מודלים שונים ישתמשו בהם להשפעה שונה. עדיף לרוץ תחילה במצב תכנון, כך שיש לך מושג מה הסוכן היה רוצה לשנות. ואז תהיה מוכן לבטל שינויים או אפילו להפעיל `omarchy reinstall configs`, אם הסוכן עושה בלגן מהכל.
