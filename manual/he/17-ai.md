# AI

Omarchy כוללת משגרים לסוכני הקידוד שלהלן מבלי לבחור עבורך ברירת מחדל. התקן אחד מתוך _התקנה > AI > CLI_, ולאחר מכן בצע אימות כשתתבקש. Hermes ו-OpenClaw הם היוצאים מן הכלל: בחירת אחד מהם מתקינה עותק משלו שמתעדכן בעצמו, כפי שמסביר הסעיף _אפליקציות שולחניות_ להלן.

### התקנה ועדכון של סוכנים

מלבד Hermes ו-OpenClaw, כל סוכן הוא חבילה מהמאגר של Omarchy עצמה. התקן אחד מתוך _התקנה > AI > CLI_ או באמצעות `omarchy install ai cli <command>`, והסר אותו שוב מתוך _הסרה > AI > CLI_, מה שמשאיר את הכניסות וההיסטוריה שלו במקומם. בחירת סוכן שעדיין לא מותקן מתקינה אותו גם כן: סימונו בכוכב בלוח הסוכנים, בחירתו באמצעות `omarchy default agent <name>`, או כניסה למנוי שלו. Omarchy מפרסמת כל מהדורה חדשה של סוכן בתוך שעה, לכל הערוצים, ו-`omarchy update` מתקין אותה יחד עם שאר המערכת.

מכיוון ש-pacman שומר אותם מעודכנים, המעדכנים של הסוכנים עצמם כבויים: ל-`claude update` או לכפתור עדכון באפליקציה אין מה לעשות. אם אתה מעדיף להפעיל סוכן מהמתקין שלו עצמו, השתמש בו והשאר את החבילה של Omarchy לא מותקנת; עותק שכבר נמצא ב-`PATH` שלך נחשב מותקן. דלג על מתקיני `curl | bash` ששמים עותק שני לפני זה של Omarchy ב-`PATH`, כמו זה של x.ai עבור `grok`.

`dsh` פותח את ממשק הדפדפן שלו ב-`127.0.0.1:3080`, עם ספריית ההשקה כסביבת העבודה של ברירת המחדל שלו. ממשק הדפדפן שלו לא מקבל הנחיית התחלה, ולכן `omarchy agent prompt` פותח אותו עם ההנחיה בלוח הגזירים שלך להדבקה. Omarchy מפעילה אותו עם הגדרת ההרשאות ללא אישור של DeepSeek. DeepSeek Harness מעלה יומני הפעלה ל-DeepSeek כשאתה משתמש ב-API הרשמי שלו למודלים; כבה זאת תחת _הגדרות > כללי > העלאת יומן הפעלה_ בממשק הדפדפן שלו. משוב שאתה שולח לו מועלה יחד עם ההפעלה גם כן, אלא אם תפעיל אותו עם `DSH_TELEMETRY_MODE=DISABLED`.

### סוכן ברירת המחדל

בחר את סוכן ברירת המחדל שלך עם הכוכב שליד סוכן בלוח הסוכנים, שהוא מלא אצל ברירת המחדל, או באמצעות `omarchy default agent <name>`, שמקבל גם כל harness שאין לו שורה שם. אם הסוכן עדיין לא מותקן, בחירתו מתקינה אותו תחילה, והוא מקבל גם משגר משלו במשגר האפליקציות, ליד Agent. Omarchy טרייה מזמינה אותך להגדיר אחד עם התראה חד-פעמית, שפותחת את לוח הסוכנים.

בחירת Claude מנסה גם להגדיר את תוסף הדפדפן שלו עבור Chromium, Chrome, Brave, Brave Origin, ו-Edge. הגדרת התוסף חלה על כל המשתמשים ועשויה לבקש את סיסמת המערכת שלך; ביטול או התקנת תוסף שנכשלה עדיין בוחרים ומפעילים את Claude. הפעל מחדש את הדפדפן, הפעל את התוסף אם תתבקש, והיכנס ל-Claude כדי לסיים לחבר אותו. הפעל `/chrome` ב-Claude כדי לבדוק את החיבור. Firefox ו-Zen אינם תומכים בתוסף זה. אם Claude כבר היה ברירת המחדל שלך לפני שהגדרה זו נוספה, בחר בו שוב כדי להתקין את התוסף.

לאחר שבחרת, `Super + Shift + Ctrl + A` מפעיל את סוכן ברירת המחדל בחלון טרמינל ייעודי (או מעלה את הבוחר אם עדיין לא בחרת). אתה יכול גם להפעיל אותו ישירות למשימה עם `omarchy agent prompt "Review this project"`. Freebuff ו-DeepSeek Harness לא מקבלים הנחיית התחלה, ולכן הם נפתחים עם ההנחיה בלוח הגזירים שלך להדבקה במקום. סוכנים שמופעלים כך רצים ללא השגחה במצבי האל-תעצור-לשאול שלהם, אז היה מוכן שהם באמת יעשו דברים! ל-MiniMax Code אין מצב כזה להפעלות האינטראקטיביות שלו, ולכן הוא מבקש הרשאות כרגיל. ומכיוון שסוכנים מסרבים לזכור אמון עבור ספריית הבית שלך, הפעלות מ-`$HOME` מתחילות ב-`~/Work` במקום.

יש גם קיצורי טרמינל: `a` מפעיל את סוכן ברירת המחדל בתוך הטרמינל הנוכחי, בעוד `c`, `cx`, `cy`, ו-`ca` מפעילים את OpenCode, Claude Code, Codex, ו-Antigravity ישירות (שוב במצבי האישור האוטומטי שלהם). שינויי ערכת נושא מסתנכרנים גם לסוכנים: Claude Code, Pi, OpenCode, ו-Hermes (ברגע ש-Omarchy התקינה אותו) כולם עוקבים כשאתה מחליף את ערכת הנושא של Omarchy.

### הוראות הסוכן שלך

כללים אישיים לכל סוכן נכנסים ל-`~/.agents/AGENTS.md`, ליד הכישורים המשותפים ב-`~/.agents/skills`. פתח אותו עם אייקון המסמך שליד ה-+ בלוח הסוכנים, או `omarchy agent instructions --edit`, שגם מקשר אותו לכל harness ששומר קובץ גלובלי משלו: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, ה-`~/.copilot/copilot-instructions.md` של Copilot, וכן הלאה. Crush ו-Amp קוראים את הקישור `~/.config/AGENTS.md`, בעוד omp, Kimi, ו-DeepSeek Harness קוראים את `~/.agents/AGENTS.md` ישירות. בחירת סוכן ברירת מחדל מקשרת אותו גם כן. קובץ הוראות שכבר היה לך הופך למשותף אם עדיין לא היה אחד; אחרת הוא נשמר ליד הקישור כ-`.bak`. הפעל `omarchy agent instructions` כדי לקשר מחדש לאחר התקנת סוכן נוסף.

### לוח הסוכנים

בשורה העליונה יש אייקון סוכנים. לפני שהגדרת סוכן, הלוח שלו מציע שלוש דרכים להתחיל: להיכנס למנוי Claude, Codex, Grok, Gemini, Muse, Cursor, או Copilot, או תחת עוד תוכנית קידוד OpenCode Go, MiniMax, Synthetic, או Z.ai; לשלם לפי שימוש עם Fireworks, OpenCode Zen ו-Go, OpenRouter, או תחת עוד DeepSeek או כל ספק אחר ש-OpenCode נכנס אליו, כולם רצים ב-OpenCode; או להפעיל את המודל הטוב ביותר למחשב שלך, כשאחד מתאים לו. הראשון שתסיים הופך לסוכן ברירת המחדל שלך, וה-+ בלוח מציע את אותן שלוש מאוחר יותר. לאחר מכן, הלוח שם כל מנוי בעמוד אחד: כל סוכן וחשבון עם התוכנית שלו, מד לכל אחת ממגבלות ההפעלה של 5 שעות והמגבלות השבועיות שלו עם הזמן עד שהוא מתאפס (רחף לאחוז המדויק), או יתרת התשלום מראש שנותרה, תחת שורה שמתחלפת בין מה שהשתמשת בו בכל כולם, כמו טוקנים השבוע והמודל שהשתמשת בו הכי הרבה. תחת _צור משהו מגניב_ הוא מציע הנחיות התחלה לערכת נושא, תוסף, אפליקציה או משחק חדשים שמוסרים את המשימה לסוכן ברירת המחדל שלך. אפליקציות נבנות כפי שבנויות Hype, Monologue, ו-Omacut של Omarchy עצמה, ב-C++ וב-Qt Quick, לפי כישור הסוכן omarchy-make-app, והמהדר וחלקי Qt שהם צריכים מגיעים מותקנים. משחקים הם עמוד three.js יחיד ב-`~/Games/vibes`, לפי כישור הסוכן omarchy-make-game, וכולם נפתחים ממשגר Game Vibes אחד בערכת הנושא הנוכחית; הם טוענים three.js מהאינטרנט, ולכן הם צריכים חיבור כדי להתחיל. Claude Code, Codex, Grok, Kimi, Cursor וקצבת Grok Bot שלו, GitHub Copilot, Muse, Gemini (דרך Antigravity), ו-Devin מכוסים מהקופסה עם המגבלות שלהם, Kimchi עם התוכנית שלו, הקרדיטים ששולמו מראש, ותקציבי ההוצאה, ו-Hermes, Mistral Vibe, ו-Qwen Code מראים את ההפעלות והטוקנים שלהם ברגע שהשתמשת בהם. תוכניות ומפתחות ספקים שאתה משתמש בהם דרך pi, omp, או opencode מופיעים גם כן: OpenCode Zen ו-Go, תוכנית Z.ai GLM Coding Plan, Ollama Cloud, תוכנית MiniMax Token Plan, ו-Synthetic עם המגבלות שלהם; OpenRouter ו-DeepSeek עם יתרות התשלום מראש שלהם; Fireworks עם ההוצאה שלו ב-30 הימים האחרונים. מודלי קידוד שאתה מפעיל על החומרה שלך מקבלים שורות משלהם, והטוקנים שלהם נספרים גם לסכומים, כפי שמתואר תחת [מודלים מקומיים](#local-models). כל סוכן נספר פעם אחת, תחת מי שמחייב אותו, לא משנה בכמה harnesses אתה מפעיל אותו.

לחץ לחיצה שמאלית על אייקון השורה או לחץ `Super + Ctrl + X` ללוח, לחץ לחיצה ימנית כדי להפעיל את סוכן ברירת המחדל שלך, ולחץ לחיצה אמצעית כדי לרענן. רשומות השימוש שמאחוריו נוצרות מחדש כל 15 דקות על ידי `omarchy agent usage update`, והלוח יכול אפילו למזג שימוש מהמכונות האחרות שלך דרך תיקייה מסונכרנת. ראה את ה-README תחת `$OMARCHY_PATH/shell/plugins/agents/` להגדרות המלאות.

### מספר מנויים

אם אתה משלם עבור יותר מתוכנית Claude, Codex, או Grok אחת — Max אישי ואחת לעבודה, נניח — Omarchy יכולה להשאיר את כולם מחוברים ולעבור ביניהם. הוסף מנוי עם ה-+ בלוח הסוכנים, שמוביל אותך דרכו ממש שם, או באמצעות `omarchy agent account add claude Work` (או `codex`, או `grok`). אותו + ואותה פקודה מכניסים ל-Gemini (`gemini`) ול-OpenCode (`opencode`), ושומרים מפתח API של Fireworks (`fireworks`) או OpenRouter (`openrouter`) ב-OpenCode; הפקודה גם מכניסה ל-Copilot (`copilot`), Cursor (`cursor`), ו-Muse (`muse`). אלה שומרים כניסה יחידה כל אחד. היא מתקינה את ה-CLI אם הוא חסר. החשבון הראשון לספק נכנס דרך הדפדפן הרגיל שלך, ממש במקום שה-CLI תמיד מחפש. כל אחד אחרי זה נכנס דרך חלון פרטי, כדי שהחשבון שהדפדפן שלך כבר מחובר אליו לא יילקח בטעות; היכנס שם כחשבון שאתה מוסיף, וסגור תחילה כל חלון פרטי שכבר פתחת. לעולם אל תצא מה-CLI כדי לעשות זאת: יציאה מבטלת את הכניסה השמורה, והחשבון ההוא יצטרך להתווסף שוב.

כדי להעתיק את כניסות המנוי שלך למכונת Omarchy אחרת דרך SSH, הפעל `omarchy agent account copy user@laptop`. השולח מספק מקלט זמני כשליעד אין אחד מותקן, ולכן מכונות Omarchy ישנות יותר יכולות לקבל חשבונות ללא עדכון. מקלטים מותקנים מקבלים עדיפות. זה מעתיק את כל מנויי Claude, Codex, ו-Grok; הוסף שמות ספקים כדי לבחור אותם, כמו ב-`omarchy agent account copy laptop claude`. שמות חשבונות ומזהי פקודות תואמים את המקור, כולל חשבונות שכבר קיימים ביעד. חשבונות יעד לא קשורים מקבלים סיומת מספרית אם שמותיהם מתנגשים, והגדרות, כישורים, תוספים, והיסטוריית שיחות נשארים מקומיים לכל מכונה.

אישורי יעד קיימים נשמרים. חשבון מקור שכבר מחובר שם שמו מסונכרן מבלי להחליף את אישוריו; חשבונות אחרים מתווספים לצדו. כדי להחליף אישורים שמורים לחשבונות תואמים, השתמש ב-`omarchy agent account copy --replace laptop claude` לאחר יציאה מהפעלות החשבון ההוא ביעד. יעד טרי מקבל גם את החשבון הפעיל של המקור והעדפות ההחלפה שלו; יעד מבוסס שומר את שלו.

אישורים עוברים דרך SSH ונשמרים בקבצים פרטיים ביעד, ולכן העתק רק למכונות שאתה בוטח בהן. זו העתקה חד-פעמית, לא סנכרון מתמשך. טוקני רענון של Codex יכולים להיות מוחלפים על ידי מכונה אחרת, מה שמשאיר כניסה מועתקת זקוקה לחידוש; כניסות נפרדות נשארות הבחירה האמינה ביותר לשימוש בו-זמני במספר מכונות. ראה [הנחיות אימות החשבון של Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

חשבון אחד לספק פעיל, וכל הפעלה חדשה מתחילה כמוהו: `cx`, `cy`, `claude`, `codex`, או `grok` רגילים, כל דבר שמופעל דרך `omarchy agent`, וסקריפטים או עורכים שמוצאים את ה-CLI ב-`PATH`. החלף עם `omarchy agent account use work` (וחזרה עם `omarchy agent account use main`), או בלוח על ידי לחיצה על מספר חשבון ולאחר מכן `Enter` (או לחיצה על הכוכב שלו). הפעלות Claude רצות גם מחליפות, מההודעה הבאה שלהן: כל הפעלת Claude רצה ב-`~/.claude`, שתמיד מחזיקה את כניסת החשבון הפעיל. הפעלת Claude שהתחילה בתיקיית חשבון עצמה על ידי Omarchy ישנה יותר מחזיקה את הכניסה הזו עד שהיא יוצאת, ולכן ההחלפה מציינת את ההפעלות האלה ומסתיימת מעצמה ברגע שהן אינן. הפעלות Codex ו-Grok רצות נשארות על החשבון שהן התחילו איתו. היסטוריית שיחות, הגדרות, כישורים, ותוספים משותפים בין חשבונות, ולכן `claude --continue` באותה תיקייה ממשיך איפה שהפסקת בחשבון החדש.

עם יותר מחשבון אחד, הלוח מראה את מגבלות כל חשבון זו לצד זו, עם כוכב מלא על זה שבשימוש. Omarchy מודיעה לך כשהחשבון הפעיל עובר 95% ממגבלה, ולחיצה על ההתראה מחליפה לחשבון עם הכי הרבה מרווח. היא לעולם לא מחליפה מעצמה. שנה את הסף עם `omarchy agent account threshold 90`. אם כל חשבון מעל הסף, תשמע על כך פעם אחת, יחד עם איזה חשבון משתחרר ראשון. בזמן שחשבון פעיל נמצא בתוך 15 נקודות מהסף שלו (80% בברירת המחדל), המגבלות שלו נבדקות כל שלוש דקות ולא כל 15.

`omarchy agent account list` מראה כל חשבון ואת המגבלות האחרונות שלו, `omarchy agent account remove work` שוכח אחד, ו-`omarchy agent account rename primary Hey` משנה שם של אחד (או לחץ על שם חשבון בלוח). פקודות אלה עובדות על חשבונות סוכן ברירת המחדל שלך; כדי להגיע לספק האחר, ציין אותו תחילה, כמו ב-`omarchy agent account use codex side`. הכניסה שכבר הייתה לך ב-`~/.claude` או `~/.codex` היא חשבון ה-_Main_. של Codex נשארת היכן שהיא; של Claude ממתינה בתיקייה משלה בזמן שחשבון אחר פעיל. חשבון שנשאר לא בשימוש יותר מכשמונה שעות יכול להראות _נדרשת כניסה_; לחץ עליו כדי להיכנס לחשבון זה שוב ממש בלוח, או החלף אליו והתחל הפעלה, שמרעננת את הכניסה מעצמה. שרתי MCP שאתה מוסיף עם `claude mcp add` מגיעים לכל חשבון Claude, מכיוון שכולם רצים ב-`~/.claude`; עבור Codex ו-Grok, שרתים שהיו לך כשהחשבון נוסף באים איתו, אבל מאוחרים יותר מגיעים רק לחשבון שהוספת אותם בו. Claude Desktop שומר כניסה משלו, וכלי Codex או Grok שמוגדרים עם נתיב מוחלט לקובץ בינארי של CLI לא עוקבים אחר ההחלפה. `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, או `GROK_HOME` מפורשים מקבלים עדיפות על החשבון הנבחר.

### אבחון קריסה

Omarchy צופה ב-systemd-coredump אחר קריסות תהליכים. ברגע שבחרת סוכן ברירת מחדל, כל תוכנית שלך שזורקת core מביאה התראת "Process crashed" — לחץ עליה, והקריסה נמסרת לסוכן ברירת המחדל שלך יחד עם כישור omarchy-diagnose-crash של Omarchy, שמוביל את הסוכן דרך קביעת העובדות מה-core dump והחלטה האם הקריסה שווה דיווח ל-upstream. אתה יכול גם להפעיל אותו ידנית נגד כל PID מתוך `coredumpctl list` עם `omarchy agent crash <pid>`.

הצפייה מופעלת כברירת מחדל. כבה אותה תחת _הפעלה > החלפה > כיבוי לכידת קריסה_ (או עם `omarchy toggle crash-capture`) וההתראות מפסיקות; `omarchy agent crash <pid>` עדיין עובד ידנית.

קריסות יכולות גם להיות מושתקות תוכנית אחת בכל פעם, שזה מה שהאבחון מציע לך בסוף. `omarchy crash mute hyprland` עוצר את ההתראות לתוכנית זו בלבד, `omarchy crash mute hyprland off` מחזיר אותן, ו-`omarchy crash mute` בפני עצמו מפרט מה השתקת. הוא מקבל את נתיב הבינארי בשמחה כמו את שמו, ולכן `omarchy crash mute /usr/bin/hyprland` עושה אותו דבר. צטט שם עם רווח בו, כמו ב-`omarchy crash mute 'Some App'`. כל השאר עדיין מודיע, והתוכנית המושתקת עדיין קורסת — זה מסתיר את התזכורת, זה לא מתקן כלום.

### אפליקציות שולחניות

_התקנה > AI > שולחן עבודה_ נושא את אפליקציות ה-AI הגרפיות: Amp Desktop, Antigravity Desktop, אפליקציית שולחן העבודה של ChatGPT, אפליקציית שולחן העבודה של Claude (הבטא ל-Linux של Anthropic, עם לשוניות Chat, Cowork, ו-Claude Code), Grok Bot לצ'אט עם המודלים של xAI, Herdr Desktop, Hermes Desktop, OpenClaw, אפליקציית שולחן העבודה של Perplexity, ו-T3 Code. Grok Bot היא אפליקציית הצ'אט לשולחן העבודה. סוכן הקידוד הוא פקודת `grok`.

Hermes Desktop היא זו שכדאי להכיר, כי למכונה יש Hermes אחד, והוא של האפליקציה: Hermes מותקן רק אי פעם דרך האפליקציה, ופקודת `hermes` שסוכן ברירת המחדל מפעיל היא של האפליקציה. בחירת Hermes כסוכן ברירת המחדל מתקינה אותו דבר שהערך _התקנה > AI > שולחן עבודה_ עושה: החבילה, וזמן ריצה של Hermes תחת `~/.hermes` שמוגדר על ידי המתקין של Hermes עצמו, שלוקח כמה דקות בפעם הראשונה. זמן ריצה זה הוא ה-Hermes האחד שפקודת `hermes` בטרמינל, סוכן ברירת המחדל והאפליקציה כולם משתמשים בו, והוא מעדכן את עצמו עם `hermes update` במקום לחכות למהדורת Omarchy. התקנתו גם נותנת ל-Hermes את ערכת הנושא של Omarchy כעור בשם `omarchy`, שכל משטח Hermes עוקב אחריו כשאתה מחליף ערכות נושא; בחר אחר תחת הגדרות המראה של Hermes או עם `/skin` אם אתה מעדיף שלא, ו-Omarchy משאירה את הבחירה הזו לבד. הסרת האפליקציה תחת _הסרה > AI > שולחן עבודה_ סוגרת את Hermes תחילה, כולל השער, לוקחת איתה את זמן הריצה הזה, ושומרת את הצ'אטים, הזיכרונות, והכישורים ש-Hermes כתב לעצמו אלא אם תגיד לו אחרת: היא שואלת, בברירת מחדל לא, האם הנתונים האלה והגדרות החיבור שלך צריכים ללכת גם כן.

חוויית שולחן העבודה של OpenClaw היא ממשק הבקרה שלו, שנפתח כאפליקציית אינטרנט מגובה בשער מקומי משלו. OpenClaw גר ב-`~/.openclaw` ומעדכן את עצמו: השתמש בכפתור "Update Gateway" של ממשק הבקרה או הפעל `openclaw update`, והשער מופעל מחדש בגרסה החדשה. Omarchy רק בוחרת את המהדורה שהתקנה טרייה מתחילה ממנה. OpenClaw יכול להיות גם סוכן ברירת המחדל שלך: בחירתו עם `omarchy default agent openclaw` מגדירה את אותו עותק ב-`~/.openclaw`, והסוכן פותח את ממשק הטרמינל של OpenClaw המחובר לשער שלו. הסרת OpenClaw תחת _הסרה > AI > שולחן עבודה_ לוקחת את שירות השער והאפליקציה איתה ולאחר מכן שואלת האם `~/.openclaw` צריך ללכת גם כן, מכיוון שזה מחזיק את הצ'אטים והאישורים שלך לצד OpenClaw עצמו וזמני הריצה של התוספים שהוא מוריד; ברירת המחדל שומרת אותו, והתקנת OpenClaw שוב מרימה אותו חזרה.

Herdr Desktop היא אפליקציית שולחן העבודה [Herdr](https://herdr.dev): מרחבים, לשוניות, וחלוניות של טרמינלים וסוכני קידוד שממשיכים לרוץ בליבתה כשאתה סוגר את החלון. היא באה מהמתקין של Herdr עצמו במקום מחבילה, ולכן היא גרה ב-`~/.local/share/herdr-app`, מביאה את ליבתה ב-`~/.local/bin/herdr-core` כשעדיין אין לך אחת, ומעדכנת את שניהם בעצמה. היא יושבת לצד פקודת `herdr` ש-Omarchy שולחת ב-`Super + Ctrl + Return` במקום להחליף אותה, ומקבלת את המקשים הישירים של פקודה זו: `Alt + Return` ו-`Alt + Shift + Return` מפצלים חלונית למטה או ימינה, `Alt + Escape` סוגר אותה, `Ctrl + Alt + Arrow` נע בין חלוניות, `Alt + 1..9` ו-`Alt + Left/Right` בוחרים לשונית, ו-`Alt + Up/Down` נעים בין מרחבים. `Ctrl + 1..9` בוחר מרחב ו-`Alt + Shift + Up/Down` עובר בין סוכנים. מקשי הקידומת `Ctrl + Space` נשארים לטרמינל בלבד, מכיוון שהאפליקציה לא יכולה להחזיק מקש Ctrl רגיל לרצף. Omarchy כותבת אלה ל-`~/.config/herdr-app/keys.json`, ו-`omarchy-refresh-herdr-app` מחזיר אותם. התקנתה בוחרת את ערכת הנושא Omarchy של Herdr, שעוקבת אחר ערכת הנושא של Omarchy שלך מאז. Herdr שומרת ערכת נושא אחת למצב בהיר ואחת לכהה, ולכן לאחר מעבר בין ערכת נושא כהה ובהירה של Omarchy, בחר Omarchy בבוחר ערכות הנושא של Herdr פעם נוספת למצב האחר.

T3 Code רץ ממהדורת ה-AppImage הרשמית שלו ב-`~/.local/share/t3code` במקום מחבילה, ולכן הוא מעדכן את עצמו. התקנתו שואלת האם להתחיל בערוץ Stable או Nightly; החלף מאוחר יותר בהגדרות T3 Code. השרשורים וההגדרות שלך גרים ב-`~/.t3`, והסרת T3 Code תחת _הסרה > AI > שולחן עבודה_ לוקחת אותם איתה.

### מודלים מקומיים

הפעל מודל פתוח על המכונה שלך עבור סוכני הקידוד שלך. ההנחיות והקוד שלך נשארים על המכונה; שום דבר שנשלח למודל לא עוזב אותה. התחל עם:

```bash
omarchy models use best text
```

זה מגדיר את מודל הטקסט הטוב ביותר למכונה זו, הסוג שהסוכנים שלך משתמשים בו. למודלי תמונה, וידאו ומוזיקה יש טוב ביותר משלהם: `omarchy models use best image`, `video` או `music`. הפעל `omarchy models use best` כדי לראות את הבחירה של כל סוג למכונה זו.

או בחר + בלוח הסוכנים: תחת _השתמש במודל מקומי_ הוא מפרט כל מודל קידוד שמתאים למכונה זו, המומלץ ראשון. Podman, שמפעיל את המודלים, מגיע עם Omarchy, וכך גם ערכת הכלים למכולות של NVIDIA במכונת NVIDIA, שנותנת להם את ה-GPU; אם אחד מהם חסר, ההגדרה הראשונה מתקינה אותו. Omarchy אז בוחרת את המודל המומלץ למכונה זו, מורידה אותו, ומפעילה אותו. צפה להורדה של עשרות GB ולרוב זיכרון המכונה להיות בשימוש בזמן שהמודל רץ: Flash Next משתמש בכ-100 GiB עם הקשר ה-256K המלא שלו. אם מודלים אחרים מחזיקים את הזיכרון שהוא צריך, הוא מוגדר מופסק, מוכן להתחיל ברגע שתעצור אחד. המודל עוצר ביציאה; עצור אותו בעצמך כשאתה צריך את הזיכרון למשהו אחר.

`omarchy models list` מראה את האפשרויות ומסביר מדוע חלקן לא מתאימות. כדי להגדיר אחד אחר, הפעל `omarchy models use <recipe>`. כיום, `qwen3.8-flash-next-gufo` ו-`qwen3.8-27b-gufo` זמינים למכונות Strix Halo של 128 GB; ה-27B לוקח כ-40 GiB, ולכן הוא משאיר מקום לעבודה אחרת. במחשב נייד של 64 GB עם Arc B390 של Intel, `qwen3.6-35b-a3b-llamacpp` רץ בכ-30 GiB. מתכונים והמלצות חדשים מגיעים עם `omarchy update`, דרך החבילה.

מודל קידוד שאתה מוסיף מקבל שורה משלו בלוח הסוכנים, לצד המנויים שלך: הפעל כדי להתחיל אותו, השהה כדי לעצור אותו ולשחרר את זיכרונו, סימן Tailscale כדי לשתף אותו עם המכונות האחרות ב-tailnet שלך בזמן שהוא רץ, וכפתור הטרמינל כדי לפתוח את הסוכן שלך עליו. השורה שלו מראה את ההורדה, הטעינה או העצירה תוך כדי, ואומרת זאת כשאין מספיק זיכרון פנוי כדי להתחיל אותו, או מקשרת ליומניו כשעצר עם שגיאה. כמה יכולים לרוץ בבת אחת כשהם מתאימים יחד בזיכרון. לחץ Delete על שורה נבחרת כדי להסיר את המודל ממכונה זו, הורדה והכל; + יכול להגדיר אותו שוב. מודל קידוד שהוגדר מטרמינל ממתין תחת + עד שתוסיף אותו, וכך גם המודלים שמכונה שציוותת איתה (`omarchy models pair <host>`) מפעילה.

כל מודל קידוד שאתה מגדיר מקבל גם ערך משלו במשגר האפליקציות, תחת שם המודל ועם הלוגו של יוצרו, כפי שכניסה ל-Claude, Codex או Grok מוסיפה אחד. הוא פותח את הסוכן שלך על מודל זה, ומפעיל את המודל תחילה אם הוא לא רץ: הטרמינל מראה אותו נטען ומוסר לסוכן ברגע שהוא מוכן. הסרת מודל מסירה את הערך שלו.

לא כל מודל הוא לקידוד. מודלי תמונה, וידאו ומוזיקה נפתחים ב-Fantasi במקום, האפליקציה של Omarchy ליצירת תמונות, וידאו ומוזיקה עם מודל שרץ על מכונה זו, ומנוהלים שם או עם `omarchy models`.

מודל ממשיך לרוץ בדיוק כפי שהוגדר, ולכן עדכון Omarchy לעולם לא מפעיל מחדש אחד תחת הסוכנים שלך. כש-Omarchy יש זמן ריצה חדש יותר או משקלים חדשים יותר למודל שהגדרת, השורה שלו מראה כפתור עדכון: לחץ עליו והמודל מוגדר שוב ברקע, מוריד רק מה שהשתנה, ומופעל מחדש בגרסה החדשה. מודל שהיה מופסק נשאר מופסק. `omarchy models update` עושה אותו דבר לכל מודל מטרמינל.

משורת הפקודה, `omarchy models start <recipe>` ו-`omarchy models stop <recipe>` עושים אותו דבר, `omarchy models status` מראה כל מודל, ו-`omarchy agent --local-model <recipe>` פותח מודל זה ב-pi, לא משנה מה סוכן ברירת המחדל שלך. כדי להפוך את המודל המקומי שלך למה שמקש הקיצור של הסוכן, קונסולת Quake, ו-_צור משהו_ פותחים, הפעל `omarchy default agent local` או סמן בכוכב מודל רץ בלוח הסוכנים. pi גם מפרט כל מודל שהגדרת, ואלה במכונות שציוותת איתן, בבוחר המודלים שלו עצמו, ולכן `pi` רגיל מגיע אליהם גם כן. כל לקוח תואם OpenAI יכול להתחבר גם כן: `status` מראה את כתובת כל מודל (הראשונה היא `http://127.0.0.1:11435/v1`), שם המתכון הוא המודל, והמפתח נמצא ב-`~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` מוחק מודל ואת ההורדות ששום מודל אחר לא משתמש בהן.

זמני ריצה של צד שלישי מסומנים עם המו"ל שלהם. Omarchy מפעילה כל מודל ללא גישה לרשת.

### מודלי LLM מקומיים

Omarchy ממליצה על שתי דרכים להפעלת מודלי LLM מקומיים: LM Studio ו-Ollama. LM Studio מספקת ממשק GUI למציאת מודלים במשקל פתוח, התקנתם, והפעלתם. זו דרך מעולה להתחיל בקלות. Ollama מציעה CLI לעשות זאת באופן דומה. אבל אם אתה חדש במודלים מקומיים, הייתי מתחיל עם LM Studio. התקן את LM Studio מתוך _התקנה > AI > שולחן עבודה_ ואת Ollama מתוך _התקנה > AI > CLI_ בתפריט Omarchy.

### כישורי Omarchy

כישורי סוכן עוזרים ל-AI להשתמש בכלים ספציפיים בדרך ספציפית, ו-Omarchy שולחת שבעה מהם. כישור omarchy מכסה התאמת המערכת, כמו כוונון תצורת Hyprland שלך או התאמת השורה. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app, ו-omarchy-make-game מכסים יצירת משהו חדש, omarchy-contribute מכסה דיווח על באג או שליחת תיקון ל-upstream, ו-omarchy-diagnose-crash עובר על core dump של קריסה. הם מקושרים בסימן לספריות הכישורים עבור Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` וכל `~/.hermes/profiles/*/skills`), והמיקום הגנרי `~/.agents/skills`, ולכן רוב ה-harnesses מרימים אותם אוטומטית. תיקיית כישור שלך עם אותו שם מקבלת עדיפות.

אבל עליך להתייחס לכישורים אלה כניסיוניים. מודלים שונים ישתמשו בזה להשפעה שונה. הכי טוב לרוץ במצב תכנון תחילה, כדי שיהיה לך מושג מה הסוכן היה רוצה לשנות. ואז להיות מוכן לשחזר שינויים או אפילו להפעיל `omarchy reinstall configs`, אם הסוכן עושה בלגן מהכל.
