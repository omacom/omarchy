# AI

Omarchy כוללת משגרים לסוכני הקידוד שלמטה מבלי לבחור עבורך ברירת מחדל. הרץ פקודה כדי להתקין את ה-CLI שלה בשימוש הראשון, ולאחר מכן בצע אימות כשתתבקש. Hermes ו-OpenClaw הם היוצאים מן הכלל: שום דבר לא מותקן עבורם באמצעות mise, ובחירה באחד מהם מתקינה עותק משלו שמתעדכן בעצמו, כפי שמסביר הסעיף _אפליקציות שולחניות_ שלהלן.

### התקנה ועדכון של סוכנים

למעט Hermes ו-OpenClaw, הסוכנים האלה משתמשים בהתקנה העצלה של mise: ההפעלה הראשונה מתקינה את ה-CLI, והפעלות מאוחרות יותר משתמשות בו שוב. mise גם בודק אם קיימת גרסה חדשה לסוכן מותקן לכל היותר פעם בארבע שעות, ממש לפני שהוא מופעל או ברקע בהנחיית מעטפת. אם העדכון הזה נכשל או שאתה במצב לא מקוון, הגרסה המותקנת תרוץ. `omarchy update` מעדכן סוכנים מותקנים יחד עם שאר Omarchy, ו-`mup` מעדכן רק כלים המנוהלים על ידי mise.

המעדכן של סוכן עצמו, כגון `claude update`, `codex update`, או כפתור עדכון באפליקציה, אינו מעדכן את ההתקנה המנוהלת על ידי mise. `codex update` נכשל, ו-`claude update` יכול לדווח על הצלחה תוך התקנת עותק נפרד ש-mise אינו עוקב אחריו. אם אתה מעדיף להשתמש במתקין ובמעדכן המקוריים של סוכן, הוסף אותו ל-`disable_tools`; ראה [כלי CLI מותקנים מראש](18-development-tools.md#preinstalled-cli-tools).

כדי להתקין את כל הכלים העצלים המוגדרים לפני שתזדקק להם, הרץ `mise install --include-lazy`. זה כולל גם את כלי ה-CLI האחרים של Omarchy כברירת מחדל וגם את הסוכנים. ראה [כלי CLI מותקנים מראש](18-development-tools.md#preinstalled-cli-tools) להתקנת כלי יחיד או לשימוש בהתקנה משלך.

`grok` מותקן באמצעות החבילה המקורית `grok` של mise, באותו אופן כמו `claude` ו-`codex`. הרץ `grok`, או סמן אותו בכוכב בפאנל הסוכנים. דלג על המתקין `curl | bash` ב-x.ai. הנתיב הזה מניח עותק שני ב-`~/.grok/bin`, מוסיף אותו בתחילת `PATH`, ודורס את העוטף של Omarchy.

`dsh` פותח את ממשק הדפדפן שלו ב-`127.0.0.1:3080`, כשספריית ההפעלה היא סביבת העבודה המוגדרת כברירת מחדל שלו. ממשק הדפדפן שלו אינו מקבל הנחיית התחלה, ולכן `omarchy agent prompt` פותח אותו כשההנחיה על הלוח שלך להדבקה. Omarchy מפעילה אותו עם הגדרת ההרשאות ללא אישור של DeepSeek. DeepSeek Harness מעלה יומני הפעלה ל-DeepSeek כשאתה משתמש ב-API הרשמי של המודל שלו; כבה זאת תחת _Settings > General > Upload Session Log_ בממשק הדפדפן שלו. גם משוב שתשלח אליו מועלה עם ההפעלה, אלא אם תפעיל אותו עם `DSH_TELEMETRY_MODE=DISABLED`.

### הסוכן המוגדר כברירת מחדל

בחר את הסוכן המוגדר כברירת מחדל שלך באמצעות הכוכב שליד סוכן בפאנל הסוכנים, שמלא על ברירת המחדל, או באמצעות `omarchy default agent <name>`, שמקבל גם כל harness שאין לו שורה שם. אם הסוכן עדיין לא מותקן, בחירה בו מתקינה אותו תחילה, והוא גם מקבל משגר משלו במשגר האפליקציות, ליד Agent. Omarchy חדשה מזמינה אותך להגדיר אחד עם התראה חד-פעמית, שפותחת את פאנל הסוכנים.

בחירה ב-Claude מנסה גם להגדיר את התוסף לדפדפן שלו עבור Chromium, Chrome, Brave, Brave Origin ו-Edge. הגדרת התוסף חלה על כל המשתמשים ועלולה לבקש את סיסמת המערכת שלך; ביטול או התקנת תוסף שנכשלה עדיין בוחרים ומפעילים את Claude. הפעל מחדש את הדפדפן, הפעל את התוסף אם תתבקש, והיכנס ל-Claude כדי לסיים לחבר אותו. הרץ `/chrome` ב-Claude כדי לבדוק את החיבור. Firefox ו-Zen אינם תומכים בתוסף זה. אם Claude כבר היה ברירת המחדל שלך לפני שההגדרה הזו נוספה, בחר בו שוב כדי להתקין את התוסף.

לאחר שבחרת, `Super + Shift + Ctrl + A` מפעיל את הסוכן המוגדר כברירת מחדל בחלון טרמינל ייעודי (או מציג את הבורר אם עדיין לא בחרת). אתה יכול גם להפעיל אותו ישירות לתוך משימה עם `omarchy agent prompt "Review this project"`. Freebuff ו-DeepSeek Harness אינם מקבלים הנחיית התחלה, ולכן הם נפתחים כשההנחיה על הלוח שלך להדבקה במקום זאת. סוכנים המופעלים בדרך זו רצים ללא השגחה במצבי אל-תעצור-לשאול שלהם, אז תהיה מוכן לכך שהם באמת יעשו דברים! ל-MiniMax Code אין מצב כזה להפעלות האינטראקטיביות שלו, ולכן הוא מבקש הרשאות כרגיל. ומכיוון שסוכנים מסרבים לזכור אמון עבור ספריית הבית שלך, הפעלות מ-`$HOME` מתחילות ב-`~/Work` במקום זאת.

יש גם קיצורי דרך בטרמינל: `a` מריץ את הסוכן המוגדר כברירת מחדל בתוך הטרמינל הנוכחי, בעוד `c`, `cx`, `cy` ו-`ca` מפעילים את OpenCode, Claude Code, Codex ו-Antigravity ישירות (שוב במצבי האישור האוטומטי שלהם). שינויי ערכת נושא מסתנכרנים גם לסוכנים: Claude Code, Pi, OpenCode ו-Hermes (ברגע ש-Omarchy התקינה אותו) כולם עוקבים כשאתה מחליף את ערכת הנושא של Omarchy.

### הוראות הסוכן שלך

כללים אישיים לכל סוכן נכנסים ל-`~/.agents/AGENTS.md`, ליד הכישורים המשותפים ב-`~/.agents/skills`. פתח אותו עם סמל המסמך שליד ה-+ בפאנל הסוכנים, או `omarchy agent instructions --edit`, שגם מקשר אותו לכל harness ששומר קובץ גלובלי משלו: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, ה-`~/.copilot/copilot-instructions.md` של Copilot, וכן הלאה. Crush ו-Amp קוראים את הקישור `~/.config/AGENTS.md`, בעוד omp, Kimi ו-DeepSeek Harness קוראים את `~/.agents/AGENTS.md` ישירות. גם בחירת סוכן ברירת מחדל מקשרת אותו. קובץ הוראות שכבר היה לך הופך למשותף אם עדיין לא היה אחד; אחרת הוא נשמר ליד הקישור כ-`.bak`. הרץ `omarchy agent instructions` כדי לקשר מחדש לאחר התקנת סוכן נוסף.

### פאנל הסוכנים

בסרגל העליון יש סמל סוכנים. לפני שהגדרת סוכן, הפאנל שלו מציע שלוש דרכים להתחיל: להיכנס למנוי Claude, Codex, Grok, Gemini, Muse, Cursor או Copilot, או תחת More תוכנית קידוד של OpenCode Go, MiniMax, Synthetic או Z.ai; לשלם לפי שימוש עם Fireworks, OpenCode Zen and Go, OpenRouter, או תחת More DeepSeek או כל ספק אחר ש-OpenCode נכנס אליו, כולם רצים ב-OpenCode; או להריץ את המודל הטוב ביותר עבור המחשב שלך, כשאחד מתאים לו. הראשון שתסיים הופך לסוכן ברירת המחדל שלך, וה-+ בפאנל מציע את אותן שלוש מאוחר יותר. לאחר מכן, הפאנל מציב כל מנוי בעמוד אחד: כל סוכן וחשבון עם התוכנית שלו, מד לכל אחת ממגבלות ההפעלה של 5 שעות והמגבלות השבועיות שלו עם הזמן עד שהוא מתאפס (רחף לקבלת האחוז המדויק), או יתרת התשלום מראש שנותרה, תחת שורה שמתחלפת בין מה שהשתמשת בו בכל אלה, כמו אסימונים השבוע והמודל שהשתמשת בו הכי הרבה. תחת _Make something cool_ הוא מציע הנחיות פתיחה לערכת נושא, תוסף, אפליקציה או משחק חדשים שמוסרים את המשימה לסוכן ברירת המחדל שלך. אפליקציות נבנות כפי שאפליקציות Hype, Monologue ו-Omacut של Omarchy עצמה נבנות, ב-C++ וב-Qt Quick, בהתאם לכישור הסוכן omarchy-make-app, והמהדר וחלקי Qt שהן צריכות מגיעים מותקנים. משחקים הם עמוד three.js יחיד ב-`~/Games/vibes`, בהתאם לכישור הסוכן omarchy-make-game, וכולם נפתחים ממשגר Game Vibes אחד בערכת הנושא הנוכחית; הם טוענים את three.js מהאינטרנט, ולכן הם צריכים חיבור כדי להתחיל. Claude Code, Codex, Grok, Kimi, Cursor והקצאת Grok Bot שלו, GitHub Copilot, Muse, Gemini (באמצעות Antigravity) ו-Devin מכוסים מהקופסה עם המגבלות שלהם, Kimchi עם התוכנית שלו, קרדיטים בתשלום מראש ותקציבי הוצאה, ו-Hermes, Mistral Vibe ו-Qwen Code מציגים את ההפעלות והאסימונים שלהם ברגע שהשתמשת בהם. גם תוכניות ומפתחות של ספקים שאתה משתמש בהם באמצעות pi, omp או opencode מופיעים: OpenCode Zen and Go, תוכנית הקידוד Z.ai GLM, Ollama Cloud, תוכנית האסימונים של MiniMax ו-Synthetic עם המגבלות שלהם; OpenRouter ו-DeepSeek עם יתרות התשלום מראש שלהם; Fireworks עם ההוצאה שלו ב-30 הימים האחרונים. מודלי קידוד שאתה מריץ על החומרה שלך מקבלים שורות משלהם, וגם האסימונים שלהם נספרים בסיכומים, כמתואר תחת [מודלים מקומיים](#local-models). כל סוכן נספר פעם אחת, תחת מי שמחייב עליו, לא משנה כמה harnesses אתה מפעיל אותו באמצעותם.

לחץ לחיצה שמאלית על סמל הסרגל או לחץ על `Super + Ctrl + X` לפאנל, לחץ לחיצה ימנית כדי להפעיל את סוכן ברירת המחדל שלך, ולחץ לחיצה אמצעית כדי לרענן. רשומות השימוש שמאחוריו נוצרות מחדש כל 15 דקות על ידי `omarchy agent usage update`, והפאנל יכול אפילו למזג שימוש מהמחשבים האחרים שלך באמצעות תיקייה מסונכרנת. ראה את ה-README תחת `$OMARCHY_PATH/shell/plugins/agents/` לקבלת ההגדרות המלאות.

### מספר מנויים

אם אתה משלם עבור יותר מתוכנית Claude, Codex או Grok אחת — תוכנית Max אישית ותוכנית עבודה, נניח — Omarchy יכולה להשאיר את כולם מחוברים ולעבור ביניהם. הוסף מנוי עם ה-+ בפאנל הסוכנים, שמוביל אותך דרך זה ממש שם, או עם `omarchy agent account add claude Work` (או `codex`, או `grok`). אותו + ואותה פקודה נכנסים ל-Gemini (`gemini`) ול-OpenCode (`opencode`), ושומרים מפתח API של Fireworks (`fireworks`) או OpenRouter (`openrouter`) ב-OpenCode; הפקודה נכנסת גם ל-Copilot (`copilot`), Cursor (`cursor`) ו-Muse (`muse`). אלה שומרים כניסה יחידה כל אחד. היא מתקינה את ה-CLI אם הוא חסר. החשבון הראשון עבור ספק נכנס באמצעות הדפדפן הרגיל שלך, בדיוק במקום שבו ה-CLI תמיד מחפש. כל אחד לאחר מכן נכנס באמצעות חלון פרטי, כך שהחשבון שהדפדפן שלך כבר מחובר אליו לא יילקח בטעות; היכנס שם כחשבון שאתה מוסיף, וסגור כל חלון פרטי שכבר פתוח לך תחילה. לעולם אל תצא מה-CLI כדי לעשות זאת: יציאה מבטלת את הכניסה השמורה, והחשבון הזה יצטרך להתווסף שוב.

כדי להעתיק את כניסות המנוי שלך למחשב Omarchy אחר באמצעות SSH, הרץ `omarchy agent account copy user@laptop`. השולח מספק מקלט זמני כשליעד אין אחד מותקן, כך שמחשבי Omarchy ישנים יותר יכולים לקבל חשבונות ללא עדכון. מקלטים מותקנים מקבלים עדיפות. זה מעתיק את כל מנויי Claude, Codex ו-Grok; הוסף שמות ספקים כדי לבחור אותם, כמו ב-`omarchy agent account copy laptop claude`. שמות חשבונות ומזהי פקודות תואמים את המקור, כולל חשבונות שכבר קיימים ביעד. חשבונות יעד לא קשורים מקבלים סיומת מספרית אם שמותיהם מתנגשים, והגדרות, כישורים, תוספים והיסטוריית שיחות נשארים מקומיים לכל מחשב.

אישורי יעד קיימים נשמרים. חשבון מקור שכבר מחובר שם שמו מסונכרן מבלי להחליף את האישורים שלו; חשבונות אחרים מתווספים לצידו. כדי להחליף אישורים שמורים עבור חשבונות תואמים, השתמש ב-`omarchy agent account copy --replace laptop claude` לאחר שסיימת את ההפעלות של החשבון הזה ביעד. יעד חדש מקבל גם את החשבון הפעיל והעדפות ההחלפה של המקור; יעד מבוסס שומר את שלו.

אישורים עוברים באמצעות SSH ומאוחסנים בקבצים פרטיים ביעד, אז העתק רק למחשבים שאתה בוטח בהם. זו העתקה חד-פעמית, לא סנכרון מתמשך. אסימוני רענון של Codex יכולים להיות מוחלפים על ידי מחשב אחר, ולהשאיר כניסה מועתקת הזקוקה לחידוש; כניסות נפרדות נשארות הבחירה האמינה ביותר לשימוש בו-זמני במספר מחשבים. ראה את [הנחיות אימות החשבון של Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

חשבון אחד לכל ספק פעיל, וכל הפעלה חדשה מתחילה כמוהו: `cx`, `cy`, `claude`, `codex` או `grok` רגילים, כל דבר המופעל באמצעות `omarchy agent`, ותסריטים או עורכים שמוצאים את ה-CLI ב-`PATH`. החלף עם `omarchy agent account use work` (וחזרה עם `omarchy agent account use main`), או בפאנל על ידי לחיצה על מספר של חשבון ולאחר מכן `Enter` (או לחיצה על הכוכב שלו). גם הפעלות Claude פועלות מחליפות, מההודעה הבאה שלהן: כל הפעלת Claude רצה ב-`~/.claude`, שתמיד מכילה את הכניסה של החשבון הפעיל. הפעלת Claude שהתחילה בתיקייה של חשבון עצמו על ידי Omarchy ישנה יותר שומרת את הכניסה הזו עד שהיא מסתיימת, כך שההחלפה מציינת את ההפעלות האלה ומסתיימת מעצמה ברגע שהן נעלמות. הפעלות Codex ו-Grok פועלות נשארות על החשבון שהן התחילו איתו. היסטוריית שיחות, הגדרות, כישורים ותוספים משותפים בין חשבונות, כך ש-`claude --continue` באותה תיקייה ממשיך מהמקום שבו הפסקת בחשבון החדש.

עם יותר מחשבון אחד, הפאנל מציג את המגבלות של כל חשבון זה לצד זה, עם כוכב מלא על זה שבשימוש. Omarchy מודיעה לך כאשר החשבון הפעיל עובר 95% ממגבלה, ולחיצה על ההתראה עוברת לחשבון עם הכי הרבה מרווח. היא לעולם לא עוברת מעצמה. שנה את הסף עם `omarchy agent account threshold 90`. אם כל חשבון מעל הסף, תשמע על כך פעם אחת, יחד עם איזה חשבון מתפנה ראשון. כאשר חשבון פעיל נמצא בטווח של 15 נקודות מהסף שלו (80% בברירת המחדל), המגבלות שלו נבדקות כל שלוש דקות ולא כל 15.

`omarchy agent account list` מציג כל חשבון והמגבלות האחרונות שלו, `omarchy agent account remove work` שוכח אחד, ו-`omarchy agent account rename primary Hey` משנה שם של אחד (או לחץ על שם של חשבון בפאנל). פקודות אלה פועלות על החשבונות של סוכן ברירת המחדל שלך; כדי להגיע לספק האחר, ציין אותו תחילה, כמו ב-`omarchy agent account use codex side`. הכניסה שכבר הייתה לך ב-`~/.claude` או ב-`~/.codex` היא החשבון _Main_. זו של Codex נשארת היכן שהיא; זו של Claude מחכה בתיקייה משלה כאשר חשבון אחר פעיל. חשבון שנותר ללא שימוש יותר מכשמונה שעות יכול להציג _Sign-in required_; לחץ עליו כדי להיכנס לחשבון הזה שוב ממש בפאנל, או עבור אליו והתחל הפעלה, שמרעננת את הכניסה מעצמה. שרתי MCP שאתה מוסיף עם `claude mcp add` מגיעים לכל חשבון Claude, מכיוון שכולם רצים ב-`~/.claude`; עבור Codex ו-Grok, שרתים שהיו לך כאשר חשבון התווסף מגיעים אליו, אבל מאוחרים יותר מגיעים רק לחשבון שהוספת אותם בו. Claude Desktop שומר כניסה משלו, וכלים של Codex או Grok המוגדרים עם נתיב מוחלט לקובץ בינארי של CLI אינם עוקבים אחרי ההחלפה. `CLAUDE_CONFIG_DIR`, `CODEX_HOME` או `GROK_HOME` מפורשים מקבלים עדיפות על החשבון הנבחר.

### אבחון קריסה

Omarchy עוקבת אחר systemd-coredump לקריסות תהליכים. ברגע שבחרת סוכן ברירת מחדל, כל תוכנית שלך שמבצעת dump לליבה מביאה התראת "Process crashed" — לחץ עליה, והקריסה נמסרת לסוכן ברירת המחדל שלך יחד עם כישור omarchy-diagnose-crash של Omarchy, שמוביל את הסוכן בביסוס העובדות מה-core dump ובהחלטה אם הקריסה שווה דיווח למפתחים במעלה הזרם. אתה יכול גם להריץ אותו ידנית מול כל PID מ-`coredumpctl list` עם `omarchy agent crash <pid>`.

המעקב פועל כברירת מחדל. כבה אותו תחת _Trigger > Toggle > Crash Capture Off_ (או עם `omarchy toggle crash-capture`) וההתראות מפסיקות; `omarchy agent crash <pid>` עדיין עובד ידנית.

ניתן להשתיק קריסות גם תוכנית אחת בכל פעם, וזה מה שהאבחון מציע לך בסוף. `omarchy crash mute hyprland` מפסיק את ההתראות עבור התוכנית הזו בלבד, `omarchy crash mute hyprland off` מחזיר אותן, ו-`omarchy crash mute` בפני עצמו מפרט את מה שהשתקת. הוא מקבל את נתיב הקובץ הבינארי בשמחה כמו את שמו, כך ש-`omarchy crash mute /usr/bin/hyprland` עושה את אותו הדבר. צטט שם עם רווח בו, כמו ב-`omarchy crash mute 'Some App'`. כל דבר אחר עדיין מודיע, והתוכנית המושתקת עדיין קורסת — זה מסתיר את התזכורת, זה לא מתקן שום דבר.

### אפליקציות שולחניות

תפריט _Install > AI_ נושא גם כמה אפליקציות AI גרפיות: Amp Desktop, Antigravity Desktop, אפליקציית שולחן העבודה של ChatGPT, אפליקציית שולחן העבודה של Claude (הבטא ל-Linux של Anthropic, עם לשוניות Chat, Cowork ו-Claude Code), Grok Bot לשיחה עם המודלים של xAI, Herdr Desktop, Hermes Desktop, OpenClaw, אפליקציית שולחן העבודה של Perplexity ו-T3 Code. Grok Bot היא אפליקציית הצ'אט לשולחן העבודה. סוכן הקידוד הוא הפקודה `grok`.

Hermes Desktop היא זו שכדאי להכיר, מכיוון שלמחשב יש Hermes אחד, והוא של האפליקציה: Hermes מותקנת רק אי פעם באמצעות האפליקציה, והפקודה `hermes` שסוכן ברירת המחדל מריץ היא של האפליקציה. בחירת Hermes כסוכן ברירת המחדל מתקינה את אותו הדבר שערך _Install > AI_ עושה: החבילה, וזמן ריצה של Hermes תחת `~/.hermes` המוגדר על ידי המתקין של Hermes עצמה, שלוקח כמה דקות בפעם הראשונה. זמן הריצה הזה הוא ה-Hermes האחד שפקודת ה-`hermes` בטרמינל, סוכן ברירת המחדל והאפליקציה כולם משתמשים בו, והוא מעדכן את עצמו עם `hermes update` ולא מחכה לגרסת Omarchy. התקנתו גם מעניקה ל-Hermes את ערכת הנושא של Omarchy כ-skin בשם `omarchy`, שכל משטח של Hermes עוקב אחריו כשאתה מחליף ערכות נושא; בחר אחר תחת הגדרות Appearance של Hermes או עם `/skin` אם אתה מעדיף שלא, ו-Omarchy משאירה את הבחירה הזו לבד. הסרת האפליקציה תחת _Remove > AI_ סוגרת תחילה את Hermes, כולל השער, לוקחת את זמן הריצה הזה איתה, ושומרת את הצ'אטים, הזיכרונות והכישורים ש-Hermes כתבה לעצמה אלא אם תגיד לה אחרת: היא שואלת, כברירת מחדל לא, אם הנתונים האלה והגדרות החיבור שלך צריכים להיעלם גם כן.

חוויית שולחן העבודה של OpenClaw היא ה-Control UI שלו, שנפתח כאפליקציית אינטרנט המגובה בשער המקומי שלו עצמו. OpenClaw חי ב-`~/.openclaw` ומעדכן את עצמו: השתמש בכפתור "Update Gateway" של ה-Control UI או הרץ `openclaw update`, והשער מופעל מחדש על הגרסה החדשה. Omarchy בוחרת רק את הגרסה שהתקנה חדשה מתחילה ממנה. OpenClaw יכול להיות גם סוכן ברירת המחדל שלך: בחירתו עם `omarchy default agent openclaw` מגדירה את אותו עותק ב-`~/.openclaw`, והסוכן פותח את ממשק המשתמש הטרמינלי של OpenClaw המחובר לשער שלו. הסרת OpenClaw תחת _Remove > AI_ לוקחת את שירות השער ואת האפליקציה איתו ולאחר מכן שואלת אם גם `~/.openclaw` צריך להיעלם, מכיוון שזה מכיל את הצ'אטים והאישורים שלך לצד OpenClaw עצמה וזמני הריצה של התוספים שהיא מורידה; ברירת המחדל שומרת אותו, והתקנת OpenClaw שוב מרימה אותו בחזרה.

Herdr Desktop היא אפליקציית שולחן העבודה [Herdr](https://herdr.dev): מרחבים, לשוניות וחלוניות של טרמינלים וסוכני קידוד שממשיכים לרוץ בליבה שלה כשאתה סוגר את החלון. היא מגיעה מהמתקין של Herdr עצמה ולא מחבילה, כך שהיא חיה ב-`~/.local/share/herdr-app`, מביאה את הליבה שלה ב-`~/.local/bin/herdr-core` כאשר עדיין אין לך אחת, ומעדכנת את שניהם בעצמה. היא יושבת לצד הפקודה `herdr` ש-Omarchy מספקת ב-`Super + Ctrl + Return` ולא מחליפה אותה, ומקבלת את המקשים הישירים של הפקודה הזו: `Alt + Return` ו-`Alt + Shift + Return` מפצלים חלונית למטה או ימינה, `Alt + Escape` סוגר אותה, `Ctrl + Alt + Arrow` נע בין חלוניות, `Alt + 1..9` ו-`Alt + Left/Right` בוחרים לשונית, ו-`Alt + Up/Down` נעים בין מרחבים. `Ctrl + 1..9` בוחר מרחב ו-`Alt + Shift + Up/Down` עוברים בין סוכנים. מקשי הקידומת `Ctrl + Space` נשארים לטרמינל בלבד, מכיוון שהאפליקציה אינה יכולה להחזיק מקש Ctrl רגיל לרצף. Omarchy כותבת אלה ל-`~/.config/herdr-app/keys.json`, ו-`omarchy-refresh-herdr-app` מחזירה אותם. התקנתה בוחרת את ערכת הנושא Omarchy של Herdr, שעוקבת אחר ערכת הנושא של Omarchy שלך מאז. Herdr שומרת ערכת נושא אחת למצב בהיר ואחת למצב כהה, כך שלאחר מעבר בין ערכת נושא כהה לבהירה של Omarchy, בחר Omarchy בבוחר ערכות הנושא של Herdr פעם נוספת עבור המצב האחר.

T3 Code רץ מגרסת ה-AppImage הרשמית שלו ב-`~/.local/share/t3code` ולא מחבילה, כך שהוא מעדכן את עצמו. התקנתו שואלת אם להתחיל בערוץ Stable או Nightly; החלף מאוחר יותר בהגדרות של T3 Code. השרשורים וההגדרות שלך חיים ב-`~/.t3`, והסרת T3 Code תחת _Remove > AI_ לוקחת אותם איתה.

### מודלים מקומיים

הרץ מודל פתוח על המחשב שלך עבור סוכני הקידוד שלך. ההנחיות והקוד שלך נשארים על המחשב; שום דבר שנשלח למודל לא עוזב אותו. התחל עם:

```bash
omarchy models use best text
```

זה מגדיר את מודל הטקסט הטוב ביותר עבור מחשב זה, מהסוג שסוכניך משתמשים בו. למודלי תמונה, וידאו ומוזיקה יש טוב ביותר משלהם: `omarchy models use best image`, `video` או `music`. הרץ `omarchy models use best` כדי לראות את הבחירה של כל סוג עבור מחשב זה.

או בחר + בפאנל הסוכנים: תחת _Use a local model_ הוא מפרט כל מודל קידוד שמתאים למחשב זה, המומלץ ראשון. Podman, שמריץ את המודלים, מגיע עם Omarchy, כמו גם ערכת הכלים של NVIDIA למכלים על מחשב NVIDIA, שמעניקה להם את ה-GPU; אם אחד מהם חסר, ההגדרה הראשונה מתקינה אותו. Omarchy לאחר מכן בוחרת את המודל המומלץ עבור מחשב זה, מורידה אותו ומפעילה אותו. צפה להורדה של עשרות GB ולרוב זיכרון המחשב בשימוש בזמן שהמודל רץ: Flash Next משתמש בכ-100 GiB עם הקשר 256K המלא שלו. אם מודלים אחרים מחזיקים את הזיכרון שהוא צריך, הוא מוגדר כמופסק, מוכן להתחיל ברגע שתעצור אחד. המודל עוצר ביציאה; עצור אותו בעצמך כשאתה צריך את הזיכרון למשהו אחר.

`omarchy models list` מציג את האפשרויות ומסביר מדוע חלקן אינן מתאימות. כדי להגדיר אחד אחר, הרץ `omarchy models use <recipe>`. היום, `qwen3.8-flash-next-gufo` ו-`qwen3.8-27b-gufo` זמינים למחשבי Strix Halo עם 128 GB; ה-27B לוקח כ-40 GiB, כך שהוא משאיר מקום לעבודה אחרת. על מחשב נייד עם 64 GB עם Arc B390 של Intel, `qwen3.6-35b-a3b-llamacpp` רץ בכ-30 GiB. מתכונים והמלצות חדשים מגיעים עם `omarchy update`, באמצעות החבילה.

מודל קידוד שתוסיף מקבל שורה משלו בפאנל הסוכנים, לצד המנויים שלך: הפעל כדי להתחיל אותו, השהה כדי לעצור אותו ולפנות את זיכרונו, סימן Tailscale כדי לשתף אותו עם המחשבים האחרים ב-tailnet שלך בזמן שהוא רץ, וכפתור הטרמינל כדי לפתוח את הסוכן שלך עליו. השורה שלו מציגה את ההורדה, הטעינה או העצירה תוך כדי, ואומרת זאת כשאין מספיק זיכרון חופשי כדי להתחיל אותו, או מקשרת ליומנים שלו כשהוא הפסיק עם שגיאה. כמה יכולים לרוץ בבת אחת כשהם מתאימים בזיכרון יחד. לחץ על Delete על שורה נבחרת כדי להסיר את המודל ממחשב זה, הורדה והכל; + יכול להגדיר אותו שוב. מודל קידוד המוגדר מטרמינל מחכה תחת + עד שתוסיף אותו, וכך גם המודלים שמחשב ששידכת איתו (`omarchy models pair <host>`) מריץ.

כל מודל קידוד שתגדיר מקבל גם ערך משלו במשגר האפליקציות, תחת שם המודל ועם הלוגו של היוצר שלו, כפי שכניסה ל-Claude, Codex או Grok מוסיפה אחד. הוא פותח את הסוכן שלך על המודל הזה, ומפעיל את המודל תחילה אם הוא אינו רץ: הטרמינל מציג אותו נטען ומוסר לסוכן ברגע שהוא מוכן. הסרת מודל מסירה את הערך שלו.

לא כל מודל מיועד לקידוד. מודלי תמונה, וידאו ומוזיקה נפתחים במקום זאת ב-Fantasi, האפליקציה של Omarchy ליצירת תמונות, וידאו ומוזיקה עם מודל שרץ על מחשב זה, ומנוהלים שם או עם `omarchy models`.

מודל ממשיך לרוץ בדיוק כפי שהוא הוגדר, כך שעדכון Omarchy לעולם אינו מפעיל מחדש אחד תחת הסוכנים שלך. כש-Omarchy יש זמן ריצה חדש יותר או משקלים חדשים יותר למודל שהגדרת, השורה שלו מציגה כפתור עדכון: לחץ עליו והמודל מוגדר שוב ברקע, מוריד רק את מה שהשתנה, ומופעל מחדש על הגרסה החדשה. מודל שהיה מופסק נשאר מופסק. `omarchy models update` עושה את אותו הדבר עבור כל מודל מטרמינל.

משורת הפקודה, `omarchy models start <recipe>` ו-`omarchy models stop <recipe>` עושים את אותו הדבר, `omarchy models status` מציג כל מודל, ו-`omarchy agent --local-model <recipe>` פותח את המודל הזה ב-pi, יהיה סוכן ברירת המחדל שלך אשר יהיה. כדי להפוך את המודל המקומי שלך למה שמקש הקיצור של הסוכן, קונסולת Quake ו-_Make something_ פותחים, הרץ `omarchy default agent local` או סמן בכוכב מודל רץ בפאנל הסוכנים. pi גם מפרט כל מודל שהגדרת, ואלה על מחשבים ששידכת איתם, בבוחר המודלים שלו עצמו, כך שגם `pi` רגיל מגיע אליהם. כל לקוח תואם OpenAI יכול להתחבר גם כן: `status` מציג את הכתובת של כל מודל (הראשון הוא `http://127.0.0.1:11435/v1`), שם המתכון הוא המודל, והמפתח נמצא ב-`~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` מוחק מודל ואת ההורדות שאף מודל אחר אינו משתמש בהן.

זמני ריצה של צד שלישי מסומנים עם המו"ל שלהם. Omarchy מריצה כל מודל ללא גישה לרשת.

### מודלי LLM מקומיים

Omarchy ממליצה על שתי דרכים להריץ מודלי LLM מקומיים: LM Studio ו-Ollama. LM Studio מספקת ממשק GUI למציאת מודלים פתוחים במשקל, התקנתם והרצתם. זו דרך מעולה להתחיל בקלות. Ollama מציעה CLI לעשות זאת באופן דומה. אבל אם אתה חדש במודלים מקומיים, הייתי מתחיל עם LM Studio. אתה יכול להתקין אחד מהם תחת _Install > AI_ בתפריט Omarchy.

### כישורי Omarchy

כישורי סוכן עוזרים ל-AI להשתמש בכלים ספציפיים בדרך ספציפית, ו-Omarchy מספקת שבעה מהם. כישור omarchy מכסה התאמת המערכת, כמו שינוי תצורת Hyprland שלך או התאמת הסרגל. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app ו-omarchy-make-game מכסים יצירת משהו חדש, omarchy-contribute מכסה דיווח על באג או שליחת תיקון למפתחים, ו-omarchy-diagnose-crash עובר על ה-core dump של קריסה. הם מקושרים בסמל לתיקיות הכישורים עבור Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` וכל `~/.hermes/profiles/*/skills`), והמיקום הגנרי `~/.agents/skills`, כך שרוב ה-harnesses קולטים אותם אוטומטית. תיקיית כישור משלך עם אותו שם מקבלת עדיפות.

אבל כדאי להתייחס לכישורים האלה כניסיוניים. מודלים שונים ישתמשו בהם להשפעה שונה. עדיף לרוץ במצב תכנון תחילה, כך שיהיה לך מושג מה הסוכן היה רוצה לשנות. ולאחר מכן תהיה מוכן לבטל שינויים או אפילו להפעיל `omarchy reinstall configs`, אם הסוכן יעשה בלגן מהכול.
