# AI

Omarchy כוללת משגרים עבור סוכני הקידוד שלהלן מבלי לבחור עבורך ברירת מחדל. הרץ פקודה כדי להתקין את ה-CLI שלה בשימוש הראשון, ולאחר מכן התחבר כאשר תתבקש לעשות זאת. Hermes ו-OpenClaw הם היוצאים מן הכלל: שום דבר לא מותקן עבורם באמצעות mise, ובחירה באחד מהם מתקינה עותק משלו שמעדכן את עצמו, כפי שמסביר הסעיף _אפליקציות שולחניות_ שלהלן.

### התקנה ועדכון של סוכנים

למעט Hermes ו-OpenClaw, הסוכנים האלה משתמשים בהתקנה העצלה של mise: ההפעלה הראשונה מתקינה את ה-CLI, והפעלות מאוחרות יותר עושות בו שימוש חוזר. mise גם בודק אם קיימת גרסה חדשה לסוכן מותקן לכל היותר פעם בארבע שעות, ממש לפני שהוא מופעל או ברקע בהנחיית מעטפת. אם העדכון הזה נכשל או שאתה לא מחובר, הגרסה המותקנת תרוץ. `omarchy update` מעדכן סוכנים מותקנים יחד עם שאר Omarchy, ו-`mup` מעדכן רק כלים המנוהלים על ידי mise.

המעדכן של סוכן עצמו, כגון `claude update`, `codex update`, או כפתור עדכון באפליקציה, אינו מעדכן את ההתקנה המנוהלת על ידי mise. `codex update` נכשל, ו-`claude update` יכול לדווח על הצלחה תוך התקנת עותק נפרד ש-mise אינו עוקב אחריו. אם אתה מעדיף להשתמש במתקין ובמעדכן המקוריים של סוכן, הוסף אותו ל-`disable_tools`; ראה [כלי CLI מותקנים מראש](18-development-tools.md#preinstalled-cli-tools).

כדי להתקין את כל הכלים העצלים המוגדרים לפני שתזדקק להם, הרץ `mise install --include-lazy`. זה כולל את כלי ה-CLI המוגדרים כברירת מחדל האחרים של Omarchy וגם את הסוכנים. ראה [כלי CLI מותקנים מראש](18-development-tools.md#preinstalled-cli-tools) להתקנת כלי בודד או לשימוש בהתקנה משלך.

`grok` מותקן דרך חבילת `grok` הרשמית של mise, באותו אופן כמו `claude` ו-`codex`. הרץ `grok`, או בחר בו תחת _Agent > Harness_. דלג על מתקין ה-`curl | bash` באתר x.ai. המסלול הזה מציב עותק שני ב-`~/.grok/bin`, מוסיף אותו בתחילת `PATH`, ודורס את ה-wrapper של Omarchy.

`dsh` פותח את ממשק הדפדפן שלו ב-`127.0.0.1:3080`, כאשר ספריית ההפעלה היא סביבת העבודה המוגדרת כברירת מחדל שלו. ממשק הדפדפן שלו אינו מקבל הנחיית התחלה, ולכן `omarchy agent prompt` פותח אותו כשההנחיה על הלוח שלך להדבקה. Omarchy מפעילה אותו עם הגדרת ההרשאות ללא אישור של DeepSeek. DeepSeek Harness מעלה יומני הפעלה ל-DeepSeek כאשר אתה משתמש ב-API הרשמי של המודלים שלו; כבה זאת תחת _Settings > General > Upload Session Log_ בממשק הדפדפן שלו. משוב שאתה שולח אליו מועלה גם הוא יחד עם ההפעלה, אלא אם תפעיל אותו עם `DSH_TELEMETRY_MODE=DISABLED`.

### סוכן ברירת המחדל

בחר את סוכן ברירת המחדל שלך עם `omarchy default agent <name>` או תחת _Agent > Harness_ בתפריט Omarchy (`Super + Space`). אם הסוכן עדיין לא מותקן, בחירה בו תתקין אותו תחילה, והוא גם יקבל משגר משלו במשגר האפליקציות, ליד Agent. Omarchy חדשה תזמין אותך לבצע את הבחירה הזו בהתראה חד-פעמית.

בחירה ב-Claude מנסה גם להגדיר את תוסף הדפדפן שלו עבור Chromium, Chrome, Brave, Brave Origin ו-Edge. הגדרת התוסף חלה על כל המשתמשים ועשויה לבקש את סיסמת המערכת שלך; ביטול או התקנת תוסף שנכשלה עדיין בוחרים ומפעילים את Claude. הפעל מחדש את הדפדפן שלך, הפעל את התוסף אם תתבקש, והתחבר ל-Claude כדי לסיים את חיבורו. הרץ `/chrome` ב-Claude כדי לבדוק את החיבור. Firefox ו-Zen אינם תומכים בתוסף הזה. אם Claude כבר היה ברירת המחדל שלך לפני שההגדרה הזו נוספה, בחר בו שוב כדי להתקין את התוסף.

לאחר שבחרת, `Super + Shift + Ctrl + A` מפעיל את סוכן ברירת המחדל בחלון טרמינל ייעודי (או מעלה את הבוחר אם עדיין לא בחרת). אתה יכול גם להפעיל אותו ישירות למשימה עם `omarchy agent prompt "Review this project"`. Freebuff ו-DeepSeek Harness אינם מקבלים הנחיית התחלה, ולכן הם נפתחים כשההנחיה על הלוח שלך להדבקה במקום זאת. סוכנים המופעלים בדרך זו רצים ללא השגחה במצבי אל-תעצור-לשאול שלהם, אז היה מוכן לכך שהם באמת יעשו דברים! ל-MiniMax Code אין מצב כזה עבור ההפעלות האינטראקטיביות שלו, ולכן הוא מבקש הרשאות כרגיל. ומכיוון שסוכנים מסרבים לזכור אמון עבור ספריית הבית שלך, הפעלות מ-`$HOME` מתחילות ב-`~/Work` במקום זאת.

יש גם קיצורי דרך בטרמינל: `a` מריץ את סוכן ברירת המחדל בתוך הטרמינל הנוכחי, בעוד ש-`c`, `cx` ו-`cy` מפעילים ישירות את OpenCode, Claude Code ו-Codex (שוב במצבי האישור האוטומטי שלהם). שינויי ערכת נושא מסתנכרנים גם לסוכנים: Claude Code, Pi, OpenCode ו-Hermes (לאחר ש-Omarchy התקינה אותו) כולם מתעדכנים יחד איתך כאשר אתה מחליף את ערכת הנושא של Omarchy.

### הוראות הסוכן שלך

כללים אישיים לכל סוכן נמצאים ב-`~/.agents/AGENTS.md`, ליד ה-skills המשותפים ב-`~/.agents/skills`. פתח אותו תחת _Agent > Instructions_, שגם מקשר אותו לכל harness ששומר קובץ גלובלי משלו: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` של Copilot, וכן הלאה. Crush ו-Amp קוראים את הקישור `~/.config/AGENTS.md`, בעוד ש-omp, Kimi ו-DeepSeek Harness קוראים ישירות את `~/.agents/AGENTS.md`. בחירת סוכן ברירת מחדל מקשרת אותו גם כן. קובץ הוראות שכבר היה לך הופך לקובץ המשותף אם עדיין לא היה כזה; אחרת הוא נשמר ליד הקישור כ-`.bak`. הרץ `omarchy agent instructions` כדי לקשר מחדש לאחר התקנת סוכן נוסף.

### פאנל הסוכנים

לבר העליון יש אייקון סוכנים. לפני שהגדרת סוכן, הפאנל שלו מלווה אותך בהתחברות ל-Claude, Codex או Grok, והראשון הופך לסוכן ברירת המחדל שלך. לאחר מכן, הפאנל מציב כל מנוי בעמוד אחד: כל סוכן וחשבון עם התוכנית שלו, מד לכל אחת ממגבלות ההפעלה של 5 שעות והמגבלות השבועיות שלו יחד עם הזמן עד לאיפוסו (רחף לקבלת האחוז המדויק), או יתרת התשלום מראש שנותרה, תחת שורה המתחלפת בין מה שהשתמשת בו בכל אלה, כגון טוקנים השבוע והמודל שבו השתמשת הכי הרבה. תחת _Make something cool_ הוא מציע הנחיות פתיחה לערכת נושא, תוסף, אפליקציה או משחק חדשים שמעבירים את המשימה לסוכן ברירת המחדל שלך. אפליקציות נבנות באופן שבו נבנו Hype, Monologue ו-Omacut של Omarchy עצמה, ב-C++ וב-Qt Quick, בהתאם למיומנות הסוכן omarchy-make-app, והמהדר וחלקי Qt שהם זקוקים להם מגיעים מותקנים. משחקים הם עמוד three.js יחיד ב-`~/Games/vibes`, בהתאם למיומנות הסוכן omarchy-make-game, וכולם נפתחים ממשגר Game Vibes אחד בערכת הנושא הנוכחית; הם טוענים את three.js מהאינטרנט, ולכן הם זקוקים לחיבור כדי להתחיל. Claude Code, Codex, Grok, Kimi, Cursor והקצבת Grok Bot שלו, GitHub Copilot, Muse, Antigravity ו-Devin מכוסים מהקופסה עם המגבלות שלהם, Kimchi עם התוכנית שלו, קרדיטים בתשלום מראש ותקציבי הוצאות, ו-Hermes, Mistral Vibe ו-Qwen Code מציגים את ההפעלות והטוקנים שלהם לאחר שהשתמשת בהם. תוכניות ומפתחות של ספקים שאתה משתמש בהם דרך pi, omp או opencode מופיעים גם הם: OpenCode Zen ו-Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan ו-Synthetic עם המגבלות שלהם; OpenRouter ו-DeepSeek עם יתרות התשלום מראש שלהם; Fireworks עם ההוצאות שלו ב-30 הימים האחרונים; והמודלים שאתה מריץ על החומרה שלך תחת מודלים מקומיים. כל סוכן נספר פעם אחת, תחת מי שמחייב עליו, בכל מספר ה-harnesses שדרכם תפעיל אותו.

לחץ לחיצה שמאלית על אייקון הבר או לחץ `Super + Ctrl + X` לפאנל, לחץ לחיצה ימנית כדי להפעיל את סוכן ברירת המחדל שלך, ולחץ לחיצה אמצעית כדי לרענן. רשומות השימוש שמאחוריו נוצרות מחדש כל 15 דקות על ידי `omarchy agent usage update`, והפאנל יכול אפילו למזג שימוש מהמכונות האחרות שלך דרך תיקייה מסונכרנת. ראה את ה-README תחת `$OMARCHY_PATH/shell/plugins/agents/` להגדרות המלאות.

### מספר מנויים

אם אתה משלם על יותר מתוכנית Claude, Codex או Grok אחת — תוכנית Max אישית ואחת לעבודה, נניח — Omarchy יכולה להשאיר את כולן מחוברות ולעבור ביניהן. הוסף מנוי עם ה-+ בפאנל הסוכנים, שמלווה אותך בתהליך ממש שם, או עם `omarchy agent account add claude Work` (או `codex`, או `grok`). זה מתקין את ה-CLI אם הוא חסר. החשבון הראשון עבור ספק מתחבר דרך הדפדפן הרגיל שלך, בדיוק במקום שבו ה-CLI תמיד מחפש. כל אחד לאחר מכן מתחבר דרך חלון פרטי, כך שהחשבון שהדפדפן שלך כבר מחובר אליו לא יילקח בטעות; התחבר שם כחשבון שאתה מוסיף, וסגור תחילה כל חלון פרטי שכבר פתוח אצלך. לעולם אל תתנתק מה-CLI כדי לעשות זאת: התנתקות מבטלת את ההתחברות השמורה, ויהיה צורך להוסיף את החשבון הזה שוב.

כדי להעתיק את התחברויות המנוי שלך למכונת Omarchy אחרת דרך SSH, הרץ `omarchy agent account copy user@laptop`. השולח מספק מקלט זמני כאשר ליעד אין אחד מותקן, כך שמכונות Omarchy ישנות יותר יכולות לקבל חשבונות ללא עדכון. מקלטים מותקנים מקבלים עדיפות. זה מעתיק את כל מנויי Claude, Codex ו-Grok; הוסף שמות ספקים כדי לבחור אותם, כגון `omarchy agent account copy laptop claude`. שמות חשבונות ומזהי פקודות תואמים את המקור, כולל חשבונות שכבר קיימים ביעד. חשבונות יעד לא קשורים מקבלים סיומת מספרית אם שמותיהם מתנגשים, והגדרות, skills, תוספים והיסטוריית שיחות נשארים מקומיים לכל מכונה.

אישורי יעד קיימים נשמרים. לחשבון מקור שכבר מחובר שם מסונכרן השם מבלי להחליף את אישוריו; חשבונות אחרים מתווספים לצידו. כדי להחליף אישורים שמורים עבור חשבונות תואמים, השתמש ב-`omarchy agent account copy --replace laptop claude` לאחר שיצאת מההפעלות של אותו חשבון ביעד. יעד חדש מקבל גם את החשבון הפעיל והעדפות ההחלפה של המקור; יעד מבוסס שומר את שלו.

אישורים עוברים דרך SSH ונשמרים בקבצים פרטיים ביעד, ולכן העתק רק למכונות שאתה סומך עליהן. זו העתקה חד-פעמית, לא סנכרון מתמשך. אסימוני רענון של Codex יכולים להתחלף על ידי מכונה אחרת, מה שמשאיר התחברות מועתקת הזקוקה לחידוש; התחברויות נפרדות נשארות הבחירה האמינה ביותר לשימוש בו-זמני במספר מכונות. ראה [הנחיות אימות החשבון של Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

חשבון אחד לכל ספק פעיל, וכל הפעלה חדשה מתחילה כמוהו: `cx`, `cy`, `claude`, `codex` או `grok` רגילים, כל דבר המופעל דרך `omarchy agent`, וסקריפטים או עורכים שמוצאים את ה-CLI ב-`PATH`. החלף עם `omarchy agent account use work` (וחזרה עם `omarchy agent account use main`), או בפאנל על ידי לחיצה על מספר של חשבון ולאחר מכן `Enter` (או לחיצה על כפתור Use שלו). הפעלות Claude פעילות מתחלפות גם הן, מההודעה הבאה שלהן: כל הפעלת Claude רצה ב-`~/.claude`, שתמיד מחזיקה את ההתחברות של החשבון הפעיל. הפעלת Claude שהתחילה בתיקייה של חשבון עצמו על ידי Omarchy ישנה יותר מחזיקה את ההתחברות הזו עד שהיא יוצאת, ולכן ההחלפה מציינת את ההפעלות האלה ומסתיימת מעצמה לאחר שהן נעלמות. הפעלות Codex ו-Grok פעילות נשארות בחשבון שבו התחילו. היסטוריית שיחות, הגדרות, skills ותוספים משותפים בין חשבונות, ולכן `claude --continue` באותה תיקייה ממשיך מהמקום שבו הפסקת בחשבון החדש.

עם יותר מחשבון אחד, הפאנל מציג את מגבלות כל חשבון זו לצד זו, כשהפעיל מסומן. כברירת מחדל Omarchy מודיעה לך כאשר החשבון הפעיל עובר 95% ממגבלה, ולחיצה על ההתראה מחליפה לחשבון עם מרווח הראש הגדול ביותר. רחף מעל שורה של חשבון בפאנל ולחץ על Autoswitch המופיע ליד Use (או לחץ `m`), או הרץ `omarchy agent account mode auto`, כדי שהוא יתחלף מעצמו במקום זאת; בזמן שהוא פעיל, Autoswitch תופס את מקומו של Use, ולחיצה עליו שוב חוזרת להתראה. הוסף מספר כדי לשנות את הסף, כגון `omarchy agent account mode auto 90`. אם כל חשבון מעל הסף, תשמע על כך פעם אחת, יחד עם איזה חשבון מתפנה ראשון. בזמן שחשבון פעיל נמצא בתוך 15 נקודות מהסף שלו (80% בברירת המחדל), מגבלותיו נבדקות כל שלוש דקות ולא כל 15.

`omarchy agent account list` מציג כל חשבון ואת מגבלותיו האחרונות, `omarchy agent account remove work` שוכח אחד, ו-`omarchy agent account rename primary Hey` משנה שם של אחד (או לחץ על שם חשבון בפאנל). פקודות אלה עובדות על החשבונות של סוכן ברירת המחדל שלך; כדי להגיע לספק האחר, ציין אותו תחילה, כגון `omarchy agent account use codex side`. ההתחברות שכבר הייתה לך ב-`~/.claude` או ב-`~/.codex` היא חשבון ה-_Main_. זו של Codex נשארת במקום שבו היא נמצאת; זו של Claude ממתינה בתיקייה משלה בזמן שחשבון אחר פעיל. חשבון שנשאר ללא שימוש יותר מכשמונה שעות יכול להציג _Sign-in required_; לחץ עליו כדי להתחבר לאותו חשבון שוב ממש בפאנל, או החלף אליו והתחל הפעלה, שמרעננת את ההתחברות מעצמה. שרתי MCP שאתה מוסיף עם `claude mcp add` מגיעים לכל חשבון Claude, מכיוון שכולם רצים ב-`~/.claude`; עבור Codex ו-Grok, שרתים שהיו לך כאשר חשבון נוסף מגיעים איתו אליו, אבל מאוחרים יותר מגיעים רק לחשבון שבו הוספת אותם. Claude Desktop שומר התחברות משלו, וכלים של Codex או Grok המוגדרים עם נתיב מוחלט לקובץ בינארי של CLI אינם עוקבים אחר ההחלפה. `CLAUDE_CONFIG_DIR`, `CODEX_HOME` או `GROK_HOME` מפורשים מקבלים עדיפות על פני החשבון שנבחר.

### אבחון קריסות

Omarchy עוקבת אחר systemd-coredump לאיתור קריסות תהליכים. לאחר שבחרת סוכן ברירת מחדל, כל תוכנית שלך שזורקת core מביאה התראת "Process crashed" — לחץ עליה, והקריסה נמסרת לסוכן ברירת המחדל שלך יחד עם מיומנות omarchy-diagnose-crash של Omarchy, שמלווה את הסוכן בביסוס העובדות מתוך ה-core dump ובהחלטה אם הקריסה שווה דיווח במעלה הזרם. אתה יכול גם להריץ אותה ידנית מול כל PID מתוך `coredumpctl list` עם `omarchy agent crash <pid>`.

המעקב פעיל כברירת מחדל. כבה אותו תחת _Trigger > Toggle > Crash Capture Off_ (או עם `omarchy toggle crash-capture`) וההתראות מפסיקות; `omarchy agent crash <pid>` עדיין עובד ידנית.

ניתן גם להשתיק קריסות תוכנית אחת בכל פעם, וזה מה שהאבחון מציע לך בסוף. `omarchy crash mute hyprland` מפסיק את ההתראות עבור התוכנית הזו בלבד, `omarchy crash mute hyprland off` מחזיר אותן, ו-`omarchy crash mute` בפני עצמו מפרט את מה שהשתקת. הוא מקבל את נתיב הקובץ הבינארי בשמחה כמו את שמו, ולכן `omarchy crash mute /usr/bin/hyprland` עושה את אותו הדבר. צטט שם עם רווח בתוכו, כגון `omarchy crash mute 'Some App'`. כל דבר אחר עדיין מתריע, והתוכנית המושתקת עדיין קורסת — זה מסתיר את התזכורת, זה לא מתקן שום דבר.

### אפליקציות שולחניות

תפריט _Install > AI_ נושא גם כמה אפליקציות AI גרפיות: Amp Desktop, Antigravity Desktop, אפליקציית שולחן העבודה של ChatGPT, אפליקציית שולחן העבודה של Claude (גרסת הבטא ל-Linux של Anthropic, עם לשוניות Chat, Cowork ו-Claude Code), Grok Bot לצ'אט עם המודלים של xAI, Herdr Desktop, Hermes Desktop, OpenClaw, אפליקציית שולחן העבודה של Perplexity ו-T3 Code. Grok Bot היא אפליקציית הצ'אט השולחנית. סוכן הקידוד הוא פקודת `grok`.

Hermes Desktop היא זו שכדאי להכיר, מכיוון שלמכונה יש Hermes אחד, והוא של האפליקציה: Hermes מותקן תמיד רק דרך האפליקציה, ופקודת `hermes` שסוכן ברירת המחדל מריץ היא של האפליקציה. בחירת Hermes כסוכן ברירת המחדל מתקינה את אותו הדבר שעושה הערך _Install > AI_: את החבילה, וסביבת ריצה של Hermes תחת `~/.hermes` המוגדרת על ידי המתקין של Hermes עצמו, מה שלוקח כמה דקות בפעם הראשונה. סביבת הריצה הזו היא ה-Hermes האחד שפקודת ה-`hermes` בטרמינל, סוכן ברירת המחדל והאפליקציה כולם משתמשים בו, והיא מעדכנת את עצמה עם `hermes update` במקום להמתין לגרסה של Omarchy. התקנתה גם מעניקה ל-Hermes את ערכת הנושא של Omarchy כ-skin בשם `omarchy`, שכל משטח של Hermes עוקב אחריו ככל שאתה מחליף ערכות נושא; בחר אחר תחת הגדרות Appearance של Hermes או עם `/skin` אם אתה מעדיף שהוא לא יעשה זאת, ו-Omarchy משאירה את הבחירה הזו בשקט. הסרת האפליקציה תחת _Remove > AI_ סוגרת תחילה את Hermes, כולל השער, לוקחת איתה את סביבת הריצה הזו, ושומרת את הצ'אטים, הזיכרונות וה-skills ש-Hermes כתב לעצמו אלא אם תאמר לה אחרת: היא שואלת, כשברירת המחדל היא לא, האם גם הנתונים האלה והגדרות החיבור שלך צריכים להיעלם.

חוויית שולחן העבודה של OpenClaw היא ה-Control UI שלו, שנפתח כאפליקציית אינטרנט המגובה בשער המקומי שלו עצמו. OpenClaw חי ב-`~/.openclaw` ומעדכן את עצמו: השתמש בכפתור "Update Gateway" של ה-Control UI או הרץ `openclaw update`, והשער מופעל מחדש על הגרסה החדשה. Omarchy בוחרת רק את הגרסה שממנה מתחילה התקנה חדשה. OpenClaw יכול להיות גם סוכן ברירת המחדל שלך: בחירתו תחת _Agent > Harness_ מגדירה את אותו עותק ב-`~/.openclaw`, והסוכן פותח את ממשק המשתמש הטרמינלי של OpenClaw המחובר לשער שלו. הסרת OpenClaw תחת _Remove > AI_ לוקחת איתה את שירות השער ואת האפליקציה ולאחר מכן שואלת האם גם `~/.openclaw` צריך להיעלם, מכיוון שזה מחזיק את הצ'אטים והאישורים שלך לצד OpenClaw עצמו וסביבות הריצה של התוספים שהוא מוריד; ברירת המחדל שומרת אותו, והתקנת OpenClaw שוב לוקחת אותו בחזרה.

Herdr Desktop היא אפליקציית שולחן העבודה [Herdr](https://herdr.dev): מרחבים, לשוניות וחלוניות של טרמינלים וסוכני קידוד שממשיכים לרוץ בליבה שלה כאשר אתה סוגר את החלון. היא מגיעה מהמתקין של Herdr עצמו ולא מחבילה, ולכן היא חיה ב-`~/.local/share/herdr-app`, מביאה את הליבה שלה ב-`~/.local/bin/herdr-core` כאשר עדיין אין לך אחת, ומעדכנת את שניהם בעצמה. היא נמצאת לצד פקודת `herdr` ש-Omarchy מספקת ב-`Super + Ctrl + Return` במקום להחליף אותה, ומקבלת את המקשים הישירים של אותה פקודה: `Alt + Return` ו-`Alt + Shift + Return` מפצלים חלונית למטה או ימינה, `Alt + Escape` סוגר אותה, `Ctrl + Alt + Arrow` עובר בין חלוניות, `Alt + 1..9` ו-`Alt + Left/Right` בוחרים לשונית, ו-`Alt + Up/Down` עוברים בין מרחבים. `Ctrl + 1..9` בוחר מרחב ו-`Alt + Shift + Up/Down` עוברים צעד-צעד בין סוכנים. מקשי הקידומת `Ctrl + Space` נשארים לטרמינל בלבד, מכיוון שהאפליקציה אינה יכולה להחזיק מקש Ctrl רגיל לרצף. Omarchy כותבת אלה ל-`~/.config/herdr-app/keys.json`, ו-`omarchy-refresh-herdr-app` מחזירה אותם. התקנתה בוחרת את ערכת הנושא Omarchy של Herdr, שעוקבת אחר ערכת הנושא של Omarchy שלך מאז ואילך. Herdr שומרת ערכת נושא אחת למצב בהיר ואחת למצב כהה, ולכן לאחר מעבר בין ערכת נושא כהה לבהירה של Omarchy, בחר Omarchy בבוחר ערכות הנושא של Herdr פעם נוספת עבור המצב האחר.

T3 Code רץ מגרסת ה-AppImage הרשמית שלו ב-`~/.local/share/t3code` ולא מחבילה, ולכן הוא מעדכן את עצמו. התקנתו שואלת האם להתחיל בערוץ Stable או Nightly; החלף מאוחר יותר בהגדרות של T3 Code. השרשורים וההגדרות שלך חיים ב-`~/.t3`, והסרת T3 Code תחת _Remove > AI_ לוקחת אותם איתה.

### מודלים מקומיים

הפעל מודל פתוח על המכונה שלך עבור סוכני הקידוד שלך. ההנחיות והקוד שלך נשארים על המכונה; שום דבר שנשלח למודל לא עוזב אותה. התחל עם:

```bash
omarchy agent local use best
```

או, בפאנל הסוכנים בבר העליון, בחר + ולאחר מכן Local AI, שמופיע כאשר מודל מתאים למכונה הזו. Podman, שמריץ את המודלים, מגיע עם Omarchy, וכך גם ערכת הכלים למכולות של NVIDIA במכונת NVIDIA, המעניקה להם את ה-GPU; אם אחד מהם חסר, ההגדרה הראשונה מתקינה אותו. Omarchy בוחרת אז את המודל המומלץ למכונה זו, מורידה אותו ומפעילה אותו. צפה להורדה של עשרות GB ולכך שרוב זיכרון המכונה יהיה בשימוש בזמן שהמודל רץ: Flash Next משתמש בכ-100 GiB עם הקשר ה-256K המלא שלו. אם מודלים אחרים מחזיקים בזיכרון שהוא זקוק לו, הוא מוגדר כמופסק, מוכן להתחיל לאחר שתעצור אחד. המודל נעצר בעת התנתקות; עצור אותו בעצמך כאשר אתה זקוק לזיכרון למשהו אחר.

`omarchy agent local list` מציג את האפשרויות ומסביר מדוע חלקן אינן מתאימות. כדי להגדיר אחד אחר, הרץ `omarchy agent local use <recipe>`. כיום, `qwen3.8-flash-next-gufo` ו-`qwen3.8-27b-gufo` זמינים למכונות Strix Halo עם 128 GB; ה-27B לוקח כ-40 GiB, כך שהוא משאיר מקום לעבודה אחרת. במחשב נייד עם 64 GB עם Arc B390 של Intel, `qwen3.6-35b-a3b-llamacpp` רץ בכ-30 GiB. מתכונים והמלצות חדשים מגיעים עם `omarchy update`, דרך החבילה.

כל מודל שאתה מגדיר מקבל שורה משלו בפאנל הסוכנים, ליד המנויים שלך: הפעל כדי להתחיל אותו, השהה כדי לעצור אותו ולפנות את הזיכרון שלו, וכפתור הטרמינל כדי לפתוח את הסוכן שלך עליו. כמה יכולים לרוץ בבת אחת כאשר הם נכנסים בזיכרון יחד; אם אחד לא נכנס, Omarchy אומרת איזה מודל רץ לעצור. גרור שורות כדי לסדר אותן מחדש, ולחץ Delete על שורה נבחרת כדי להסיר מודל ואת ההורדה שלו.

כל מודל שאתה מגדיר מקבל גם ערך משלו במשגר האפליקציות, תחת שם המודל ועם הלוגו של היוצר שלו, באופן שבו התחברות ל-Claude, Codex או Grok מוסיפה אחד. הוא פותח את הסוכן שלך על המודל הזה, ומפעיל את המודל תחילה אם הוא לא רץ: הטרמינל מציג אותו נטען ומעביר לסוכן לאחר שהוא מוכן. הסרת מודל מסירה את הערך שלו.

לא כל מודל מיועד לקידוד. מודלי תמונה, וידאו ומוזיקה נפתחים ב-Fantasi במקום זאת, האפליקציה של Omarchy ליצירת תמונות, וידאו ומוזיקה עם מודל הרץ על מכונה זו, מהערך שלהם במשגר ומהשורה שלהם בפאנל הסוכנים.

מודל ממשיך לרוץ בדיוק כפי שהוגדר, כך שעדכון Omarchy לעולם אינו מפעיל אחד מחדש תחת הסוכנים שלך. כאשר ל-Omarchy יש סביבת ריצה חדשה יותר או משקולות חדשות יותר למודל שהגדרת, השורה שלו מציגה כפתור עדכון: לחץ עליו והמודל מוגדר שוב ברקע, מוריד רק את מה שהשתנה, ומופעל מחדש על הגרסה החדשה. מודל שהיה מופסק נשאר מופסק. `omarchy agent local update` עושה את אותו הדבר לכל מודל מטרמינל.

משורת הפקודה, `omarchy agent local start <recipe>` ו-`omarchy agent local stop <recipe>` עושים את אותו הדבר, `omarchy agent local status` מציג כל מודל, ו-`omarchy agent --local` פותח את סוכן ברירת המחדל שלך על המודל האחרון שהפעלת. pi, OpenCode ו-Qwen Code יכולים להשתמש באחד; עם כל ברירת מחדל אחרת הוא נפתח ב-pi, או ב-OpenCode אם אין לך pi. pi גם מפרט כל מודל שהגדרת, ואלה על מכונות שציוותת אליהן, בבוחר המודלים שלו עצמו, ולכן `pi` רגיל מגיע גם אליהם. כל לקוח תואם OpenAI יכול להתחבר גם כן: `status` מציג את כתובת כל מודל (הראשון הוא `http://127.0.0.1:11435/v1`), שם המתכון הוא המודל, והמפתח נמצא ב-`~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` מוחק מודל ואת ההורדות שאף מודל אחר לא משתמש בהן.

סביבות ריצה של צד שלישי מסומנות עם המפרסם שלהן. Omarchy מריצה כל מודל ללא גישת רשת.

### מודלי LLM מקומיים

Omarchy ממליצה על שתי דרכים להרצת מודלי LLM מקומיים: LM Studio ו-Ollama. LM Studio מספק ממשק GUI למציאת מודלים במשקולות פתוחות, התקנתם והרצתם. זו דרך מעולה להתחיל בקלות. Ollama מציע CLI לביצוע דומה. אבל אם אתה חדש במודלים מקומיים, הייתי מתחיל עם LM Studio. אתה יכול להתקין אחד מהם תחת _Install > AI_ בתפריט Omarchy.

### ה-skills של Omarchy

מיומנויות סוכן עוזרות ל-AI להשתמש בכלים ספציפיים בדרך ספציפית, ו-Omarchy מספקת שבע מהן. מיומנות omarchy מכסה התאמת המערכת, כגון כוונון תצורת Hyprland שלך או התאמת הבר. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app ו-omarchy-make-game מכסות יצירת משהו חדש, omarchy-contribute מכסה דיווח על באג או שליחת תיקון במעלה הזרם, ו-omarchy-diagnose-crash עוברת על ה-core dump של קריסה. הן מקושרות בסמליות לתיקיות ה-skills עבור Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` וכל `~/.hermes/profiles/*/skills`), והמיקום הגנרי `~/.agents/skills`, כך שרוב ה-harnesses קולטים אותן אוטומטית. תיקיית skill משלך עם אותו שם מקבלת עדיפות.

אבל עליך להתייחס ל-skills האלה כניסיוניים. מודלים שונים ישתמשו בהם להשפעה שונה. הכי טוב לרוץ תחילה במצב תכנון, כדי שיהיה לך מושג מה הסוכן היה רוצה לשנות. ולאחר מכן היה מוכן לבטל שינויים או אפילו להפעיל `omarchy reinstall configs`, אם הסוכן עושה בלגן מהכול.
