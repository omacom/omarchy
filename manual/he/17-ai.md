# AI

Omarchy כוללת משגרים לסוכני הקידוד שלמטה בלי לבחור עבורך ברירת מחדל. הרץ פקודה כדי להתקין את ה-CLI שלה בשימוש הראשון, ואז התאמת כשיתבקש. Hermes ו-OpenClaw הם היוצאים מן הכלל: שום דבר לא מותקן עבורם דרך mise, ובחירה באחד מהם מתקינה עותק משלו שמתעדכן בעצמו, כפי ש-_אפליקציות שולחניות_ למטה מסביר.

### התקנה ועדכון של סוכנים

למעט Hermes ו-OpenClaw, הסוכנים האלה משתמשים בהתקנה העצלה של mise: ההפעלה הראשונה מתקינה את ה-CLI, והפעלות מאוחרות יותר משתמשות בו שוב. mise גם בודקת אם יש גרסה חדשה לסוכן מותקן לכל היותר פעם בארבע שעות, ממש לפני שהוא מופעל או ברקע ב-prompt של ה-shell. אם העדכון הזה נכשל או שאתה לא מחובר, הגרסה המותקנת רצה. `omarchy update` מעדכן סוכנים מותקנים יחד עם שאר Omarchy, ו-`mup` מעדכן רק כלים שמנוהלים על ידי mise.

המעדכן העצמי של סוכן, כמו `claude update`, `codex update`, או כפתור עדכון באפליקציה, לא מעדכן את ההתקנה שמנוהלת על ידי mise. `codex update` נכשל, ו-`claude update` יכול לדווח על הצלחה תוך שהוא מתקין עותק נפרד ש-mise לא עוקבת אחריו. אם אתה מעדיף להשתמש במתקין ובמעדכן המקוריים של סוכן, הוסף אותו ל-`disable_tools`; ראה [כלי CLI מותקנים מראש](18-development-tools.md#preinstalled-cli-tools).

כדי להתקין את כל הכלים העצלים שהוגדרו לפני שתצטרך אותם, הרץ `mise install --include-lazy`. זה כולל גם את שאר כלי ה-CLI ברירת המחדל של Omarchy וגם את הסוכנים. ראה [כלי CLI מותקנים מראש](18-development-tools.md#preinstalled-cli-tools) להתקנת כלי בודד או לשימוש בהתקנה משלך.

`grok` מותקן דרך חבילת `grok` הרשמית של mise, באותו אופן כמו `claude` ו-`codex`. הרץ `grok`, או בחר אותו תחת _Agent > Harness_. דלג על מתקין ה-`curl | bash` באתר x.ai. הדרך הזו שמה עותק שני ב-`~/.grok/bin`, מוסיפה אותו בתחילת `PATH`, ודורסת את ה-wrapper של Omarchy.

`dsh` פותח את ממשק הדפדפן שלו ב-`127.0.0.1:3080`, עם תיקיית ההפעלה כסביבת העבודה ברירת המחדל שלו. ממשק הדפדפן שלו לא מקבל prompt התחלתי, כך ש-`omarchy agent prompt` פותח אותו עם ה-prompt בלוח ההעתקה שלך כדי שתדביק אותו. Omarchy מפעילה אותו עם הגדרת ההרשאות ללא אישור של DeepSeek. DeepSeek Harness מעלה יומני session ל-DeepSeek כשאתה משתמש ב-API הרשמי של המודלים שלו; כבה את זה תחת _Settings > General > Upload Session Log_ בממשק הדפדפן שלו. גם משוב שאתה שולח לו מועלה יחד עם ה-session, אלא אם אתה מפעיל אותו עם `DSH_TELEMETRY_MODE=DISABLED`.

### הסוכן ברירת המחדל

בחר את סוכן ברירת המחדל שלך עם `omarchy default agent <name>` או תחת _Agent > Harness_ בתפריט Omarchy (`Super + Space`). אם הסוכן עדיין לא מותקן, בחירה בו תתקין אותו קודם, והוא גם יקבל משגר משלו במשגר האפליקציות, לצד Agent. Omarchy טרייה תזמין אותך לבחור באמצעות התראה חד-פעמית.

בחירה ב-Claude גם מנסה להגדיר את תוסף הדפדפן שלו עבור Chromium, Chrome, Brave, Brave Origin ו-Edge. הגדרת התוסף חלה על כל המשתמשים ועלולה לבקש את סיסמת המערכת שלך; ביטול או כשל בהתקנת התוסף עדיין בוחרים ומפעילים את Claude. הפעל מחדש את הדפדפן שלך, הפעל את התוסף אם תתבקש, והיכנס ל-Claude כדי לסיים לחבר אותו. הרץ `/chrome` ב-Claude כדי לבדוק את החיבור. Firefox ו-Zen לא תומכים בתוסף הזה. אם Claude כבר היה ברירת המחדל שלך לפני שההגדרה הזו נוספה, בחר אותו שוב כדי להתקין את התוסף.

לאחר שבחרת, `Super + Shift + Ctrl + A` מפעיל את סוכן ברירת המחדל בחלון טרמינל ייעודי (או מציג את הבורר אם עדיין לא בחרת). אתה יכול גם להפעיל אותו ישירות לתוך משימה עם `omarchy agent prompt "Review this project"`. Freebuff ו-DeepSeek Harness לא מקבלים prompt התחלתי, אז הם נפתחים עם ה-prompt בלוח ההעתקה שלך כדי שתדביק אותו במקום זאת. סוכנים שמופעלים כך רצים ללא השגחה במצבי אל-תעצור-לשאול שלהם, אז תהיה מוכן שהם באמת יעשו דברים! ל-MiniMax Code אין מצב כזה עבור ה-sessions האינטראקטיביים שלו, אז הוא מבקש הרשאות כרגיל. ומאחר שסוכנים מסרבים לזכור אמון בתיקיית הבית שלך, הפעלות מ-`$HOME` מתחילות ב-`~/Work` במקום זאת.

יש גם קיצורי טרמינל: `a` מריץ את סוכן ברירת המחדל בתוך הטרמינל הנוכחי, בעוד ש-`c`, `cx` ו-`cy` מפעילים את OpenCode, Claude Code ו-Codex ישירות (שוב במצבי האישור האוטומטי שלהם). גם שינויי ערכת נושא מסתנכרנים לסוכנים: Claude Code, Pi, OpenCode ו-Hermes (לאחר ש-Omarchy התקינה אותו) כולם הולכים אחריך כשאתה מחליף את ערכת הנושא של Omarchy.

### הוראות הסוכן שלך

כללים אישיים לכל סוכן נמצאים ב-`~/.agents/AGENTS.md`, לצד ה-skills המשותפים ב-`~/.agents/skills`. פתח אותו תחת _Agent > Instructions_, שגם מקשר אותו לכל harness ששומר קובץ גלובלי משלו: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, ה-`~/.copilot/copilot-instructions.md` של Copilot, וכן הלאה. Crush ו-Amp קוראים את הקישור `~/.config/AGENTS.md`, בעוד ש-omp, Kimi ו-DeepSeek Harness קוראים את `~/.agents/AGENTS.md` ישירות. גם בחירת סוכן ברירת מחדל מקשרת אותו. קובץ הוראות שכבר היה לך הופך לקובץ המשותף אם עדיין לא היה אחד; אחרת הוא נשמר לצד הקישור כ-`.bak`. הרץ `omarchy agent instructions` כדי לקשר מחדש לאחר התקנת סוכן נוסף.

### פאנל הסוכנים

בסרגל העליון יש אייקון סוכנים. לפני שהגדרת סוכן, הפאנל שלו מלווה אותך בהתחברות ל-Claude, Codex או Grok, והראשון הופך לסוכן ברירת המחדל שלך. לאחר מכן, הפאנל שם כל מנוי בעמוד אחד: כל סוכן וחשבון עם התוכנית שלו, מד לכל אחת ממגבלות ה-session של 5 שעות והמגבלות השבועיות שלו עם הזמן עד שהוא מתאפס (רחף לקבלת האחוז המדויק), או יתרת התשלום מראש שנותרה, מתחת לשורה שמסתובבת בין מה שהשתמשת בו בכל כולם, כמו טוקנים השבוע והמודל שהשתמשת בו הכי הרבה. תחת _Make something cool_ הוא מציע prompts התחלתיים לערכת נושא, תוסף, אפליקציה או משחק חדשים שמוסרים את המשימה לסוכן ברירת המחדל שלך. אפליקציות נבנות באותו אופן שבו נבנות Hype, Monologue ו-Omacut של Omarchy עצמה, ב-C++ וב-Qt Quick, לפי ה-agent skill של omarchy-make-app, והקומפיילר וחלקי ה-Qt שהן צריכות מגיעים מותקנים. משחקים הם עמוד three.js בודד ב-`~/Games/vibes`, לפי ה-agent skill של omarchy-make-game, וכולם נפתחים ממשגר Game Vibes אחד בערכת הנושא הנוכחית; הם טוענים את three.js מהאינטרנט, אז הם צריכים חיבור כדי להתחיל. Claude Code, Codex, Grok, Kimi, Cursor והקצאת ה-Grok Bot שלו, GitHub Copilot, Muse, Antigravity ו-Devin מכוסים מהקופסה עם המגבלות שלהם, Kimchi עם התוכנית, הקרדיטים ששולמו מראש ותקציבי ההוצאות שלו, ו-Hermes, Mistral Vibe ו-Qwen Code מציגים את ה-sessions והטוקנים שלהם לאחר שהשתמשת בהם. גם תוכניות ומפתחות של ספקים שאתה משתמש בהם דרך pi, omp או opencode מופיעים: OpenCode Zen ו-Go, ה-Z.ai GLM Coding Plan, Ollama Cloud, ה-MiniMax Token Plan ו-Synthetic עם המגבלות שלהם; OpenRouter ו-DeepSeek עם היתרות ששולמו מראש שלהם; Fireworks עם ההוצאות שלו ב-30 הימים האחרונים. גם טוקנים ממודלים שאתה מריץ על החומרה שלך נספרים בסיכומים; למודלים עצמם יש פאנל משלהם, המתואר תחת [מודלים מקומיים](#local-models). כל סוכן נספר פעם אחת, תחת מי שמחייב אותו, לא משנה בכמה harnesses אתה מפעיל אותו.

לחץ שמאלית על אייקון הסרגל או לחץ `Super + Ctrl + X` לקבלת הפאנל, לחץ ימנית כדי להפעיל את סוכן ברירת המחדל שלך, ולחץ באמצע כדי לרענן. רשומות השימוש שמאחוריו נוצרות מחדש כל 15 דקות על ידי `omarchy agent usage update`, והפאנל אף יכול למזג שימוש ממכונות אחרות שלך דרך תיקייה מסונכרנת. ראה את ה-README תחת `$OMARCHY_PATH/shell/plugins/agents/` להגדרות המלאות.

### כמה מנויים

אם אתה משלם על יותר מתוכנית Claude, Codex או Grok אחת — Max אישית ואחת של עבודה, נניח — Omarchy יכולה להשאיר את כולן מחוברות ולעבור ביניהן. הוסף מנוי עם ה-+ בפאנל הסוכנים, שמלווה אותך בזה ממש שם, או עם `omarchy agent account add claude Work` (או `codex`, או `grok`). הוא מתקין את ה-CLI אם הוא חסר. החשבון הראשון של ספק מתחבר דרך הדפדפן הרגיל שלך, בדיוק במקום שה-CLI תמיד מסתכל. כל אחד אחריו מתחבר דרך חלון פרטי, כך שהחשבון שהדפדפן שלך כבר מחובר אליו לא ייבחר בטעות; התחבר שם כחשבון שאתה מוסיף, וסגור כל חלון פרטי שכבר היה פתוח קודם. לעולם אל תתנתק מה-CLI כדי לעשות זאת: התנתקות מבטלת את ההתחברות השמורה, והחשבון הזה יצטרך להתווסף שוב.

כדי להעתיק את התחברויות המנוי שלך למכונת Omarchy אחרת דרך SSH, הרץ `omarchy agent account copy user@laptop`. השולח מספק מקלט זמני כאשר ליעד אין אחד מותקן, כך שמכונות Omarchy ישנות יותר יכולות לקבל חשבונות ללא עדכון. מקלטים מותקנים מקבלים עדיפות. זה מעתיק את כל מנויי Claude, Codex ו-Grok; הוסף שמות ספקים כדי לבחור אותם, כמו ב-`omarchy agent account copy laptop claude`. שמות החשבונות ומזהי הפקודות תואמים את המקור, כולל חשבונות שכבר קיימים ביעד. חשבונות יעד לא קשורים מקבלים סיומת מספרית אם שמותיהם מתנגשים, והגדרות, skills, תוספים והיסטוריית שיחות נשארים מקומיים לכל מכונה.

אישורי יעד קיימים נשמרים. לחשבון מקור שכבר מחובר שם השם מסונכרן מבלי להחליף את האישורים שלו; חשבונות אחרים מתווספים לצדו. כדי להחליף אישורים שמורים לחשבונות תואמים, השתמש ב-`omarchy agent account copy --replace laptop claude` לאחר שסיימת את ה-sessions של החשבון הזה ביעד. יעד טרי גם מקבל את החשבון הפעיל והעדפות ההחלפה של המקור; יעד מבוסס שומר את שלו.

אישורים עוברים דרך SSH ונשמרים בקבצים פרטיים ביעד, אז העתק רק למכונות שאתה בוטח בהן. זו העתקה חד-פעמית, לא סנכרון מתמשך. אסימוני רענון של Codex יכולים להיות מוחלפים על ידי מכונה אחרת, מה שמשאיר התחברות מועתקת הזקוקה לחידוש; התחברויות נפרדות נשארות הבחירה האמינה ביותר לשימוש בו-זמני בכמה מכונות. ראה את [מדריך אימות החשבון של Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

חשבון אחד לכל ספק פעיל, וכל session חדש מתחיל כמוהו: `cx`, `cy`, `claude`, `codex` או `grok` פשוטים, כל דבר שמופעל דרך `omarchy agent`, וסקריפטים או עורכים שמוצאים את ה-CLI ב-`PATH`. החלף עם `omarchy agent account use work` (ובחזרה עם `omarchy agent account use main`), או בפאנל על ידי לחיצה על מספר החשבון ואז `Enter` (או לחיצה על כפתור ה-Use שלו). גם sessions של Claude פעילים מתחלפים, מההודעה הבאה שלהם: כל session של Claude רץ ב-`~/.claude`, שתמיד מחזיק את ההתחברות של החשבון הפעיל. session של Claude שהופעל בתיקייה של חשבון עצמו על ידי Omarchy ישנה יותר מחזיק את ההתחברות הזו עד שהוא יוצא, אז ההחלפה מציינת את ה-sessions האלה ומסיימת מעצמה לאחר שהם נעלמים. sessions פעילים של Codex ו-Grok נשארים בחשבון שהם התחילו איתו. היסטוריית שיחות, הגדרות, skills ותוספים משותפים בין חשבונות, כך ש-`claude --continue` באותה תיקייה ממשיך איפה שהפסקת בחשבון החדש.

עם יותר מחשבון אחד, הפאנל מציג את מגבלות כל חשבון זו לצד זו, כשהפעיל מסומן. כברירת מחדל Omarchy מודיעה לך כשחשבון פעיל עובר 95% ממגבלה, ולחיצה על ההתראה מחליפה לחשבון עם הכי הרבה מרווח. רחף מעל שורת חשבון בפאנל ולחץ על ה-Autoswitch שמופיע לצד Use (או לחץ `m`), או הרץ `omarchy agent account mode auto`, כדי שהוא יחליף מעצמו במקום זאת; בזמן שהוא פעיל, Autoswitch תופס את מקומו של Use, ולחיצה עליו שוב חוזרת להתראות. הוסף מספר כדי לשנות את הסף, כמו ב-`omarchy agent account mode auto 90`. אם כל חשבון מעל הסף, תשמע על כך פעם אחת, יחד עם איזה חשבון מתפנה ראשון. בזמן שחשבון פעיל נמצא בתוך 15 נקודות מהסף שלו (80% כברירת מחדל), המגבלות שלו נבדקות כל שלוש דקות ולא כל 15.

`omarchy agent account list` מציג כל חשבון ואת המגבלות האחרונות שלו, `omarchy agent account remove work` שוכח אחד, ו-`omarchy agent account rename primary Hey` משנה שם של אחד (או לחץ על שם חשבון בפאנל). פקודות אלה פועלות על החשבונות של סוכן ברירת המחדל שלך; כדי להגיע לספק האחר, ציין אותו קודם, כמו ב-`omarchy agent account use codex side`. ההתחברות שכבר הייתה לך ב-`~/.claude` או ב-`~/.codex` היא חשבון ה-_Main_. של Codex נשאר איפה שהוא; של Claude ממתין בתיקייה משלו בזמן שחשבון אחר פעיל. חשבון שנותר ללא שימוש יותר מכשמונה שעות יכול להציג _Sign-in required_; לחץ עליו כדי לחבר את החשבון הזה שוב ממש בפאנל, או החלף אליו והתחל session, שמרענן את ההתחברות מעצמו. שרתי MCP שאתה מוסיף עם `claude mcp add` מגיעים לכל חשבון Claude, מאחר שכולם רצים ב-`~/.claude`; עבור Codex ו-Grok, שרתים שהיו לך כשחשבון התווסף באים איתו, אבל מאוחרים יותר מגיעים רק לחשבון שהוספת אותם בו. Claude Desktop שומר התחברות משלו, וכלי Codex או Grok שהוגדרו עם נתיב מוחלט לבינארי CLI לא עוקבים אחר ההחלפה. `CLAUDE_CONFIG_DIR`, `CODEX_HOME` או `GROK_HOME` מפורשים מקבלים עדיפות על פני החשבון הנבחר.

### אבחון קריסות

Omarchy עוקבת אחר systemd-coredump לקריסות תהליכים. לאחר שבחרת סוכן ברירת מחדל, כל תוכנית שלך שמבצעת dump לליבה מביאה התראת "Process crashed" — לחץ עליה, והקריסה נמסרת לסוכן ברירת המחדל שלך יחד עם ה-skill של omarchy-diagnose-crash של Omarchy, שמלווה את הסוכן בקביעת העובדות מה-core dump ובהחלטה האם הקריסה שווה דיווח ל-upstream. אתה יכול גם להריץ אותו ידנית מול כל PID מ-`coredumpctl list` עם `omarchy agent crash <pid>`.

המעקב פעיל כברירת מחדל. כבה אותו תחת _Trigger > Toggle > Crash Capture Off_ (או עם `omarchy toggle crash-capture`) וההתראות מפסיקות; `omarchy agent crash <pid>` עדיין עובד ידנית.

קריסות יכולות גם להיות מושתקות תוכנית אחת בכל פעם, שזה מה שהאבחון מציע לך בסוף. `omarchy crash mute hyprland` עוצר את ההתראות לאותה תוכנית בלבד, `omarchy crash mute hyprland off` מחזיר אותן, ו-`omarchy crash mute` בפני עצמו מפרט מה השתקת. הוא מקבל את נתיב הבינארי באותה שמחה כמו את שמו, כך ש-`omarchy crash mute /usr/bin/hyprland` עושה את אותו דבר. שם עם רווח יש לצטט, כמו ב-`omarchy crash mute 'Some App'`. כל השאר עדיין מתריעים, והתוכנית המושתקת עדיין קורסת — זה מסתיר את התזכורת, זה לא מתקן כלום.

### אפליקציות שולחניות

תפריט _Install > AI_ נושא גם כמה אפליקציות AI גרפיות: Amp Desktop, Antigravity Desktop, אפליקציית שולחן העבודה של ChatGPT, אפליקציית שולחן העבודה של Claude (הבטא ל-Linux של Anthropic, עם לשוניות Chat, Cowork ו-Claude Code), Grok Bot לשיחה עם המודלים של xAI, Herdr Desktop, Hermes Desktop, OpenClaw, אפליקציית שולחן העבודה של Perplexity ו-T3 Code. Grok Bot היא אפליקציית הצ'אט השולחנית. סוכן הקידוד הוא פקודת `grok`.

Hermes Desktop היא זו שכדאי לדעת עליה, כי למכונה יש Hermes אחד, והוא של האפליקציה: Hermes מותקן רק אי פעם דרך האפליקציה, ופקודת `hermes` שסוכן ברירת המחדל מריץ היא של האפליקציה. בחירת Hermes כסוכן ברירת המחדל מתקינה את אותו דבר שהערך _Install > AI_ מתקין: החבילה, ו-runtime של Hermes תחת `~/.hermes` שהמתקין של Hermes עצמו מגדיר, שלוקח כמה דקות בפעם הראשונה. ה-runtime הזה הוא ה-Hermes האחד שפקודת ה-`hermes` בטרמינל, סוכן ברירת המחדל והאפליקציה כולם משתמשים בו, והוא מעדכן את עצמו עם `hermes update` במקום לחכות לגרסה של Omarchy. התקנתו גם נותנת ל-Hermes את ערכת הנושא של Omarchy כ-skin בשם `omarchy`, שכל משטח של Hermes עוקב אחריו כשאתה מחליף ערכות נושא; בחר אחר תחת הגדרות ה-Appearance של Hermes או עם `/skin` אם אתה מעדיף שלא, ו-Omarchy משאירה את הבחירה הזו לבד. הסרת האפליקציה תחת _Remove > AI_ סוגרת את Hermes קודם, כולל ה-gateway, לוקחת את ה-runtime הזה איתה, ושומרת את הצ'אטים, הזיכרונות וה-skills ש-Hermes כתב לעצמו אלא אם אתה אומר לה אחרת: היא שואלת, עם ברירת מחדל לא, האם גם הנתונים האלה והגדרות החיבור שלך צריכים ללכת.

חוויית שולחן העבודה של OpenClaw היא ה-Control UI שלו, שנפתח כאפליקציית אינטרנט המגובה ב-gateway המקומי שלו עצמו. OpenClaw חי ב-`~/.openclaw` ומעדכן את עצמו: השתמש בכפתור "Update Gateway" של ה-Control UI או הרץ `openclaw update`, וה-gateway יופעל מחדש בגרסה החדשה. Omarchy רק בוחרת את הגרסה שהתקנה טרייה מתחילה ממנה. OpenClaw יכול גם להיות סוכן ברירת המחדל שלך: בחירתו תחת _Agent > Harness_ מגדירה את אותו עותק ב-`~/.openclaw`, והסוכן פותח את ממשק הטרמינל של OpenClaw המחובר ל-gateway שלו. הסרת OpenClaw תחת _Remove > AI_ לוקחת איתה את שירות ה-gateway ואת האפליקציה ואז שואלת האם גם `~/.openclaw` צריך ללכת, מאחר שזה מחזיק את הצ'אטים והאישורים שלך לצד OpenClaw עצמו ו-runtime-ים של תוספים שהוא מוריד; ברירת המחדל שומרת אותו, והתקנת OpenClaw שוב מרימה אותו בחזרה.

Herdr Desktop היא אפליקציית שולחן העבודה [Herdr](https://herdr.dev): מרחבים, לשוניות ופאנלים של טרמינלים וסוכני קידוד שממשיכים לרוץ בליבה שלה כשאתה סוגר את החלון. היא מגיעה מהמתקין של Herdr עצמו ולא מחבילה, כך שהיא חיה ב-`~/.local/share/herdr-app`, מביאה את הליבה שלה ב-`~/.local/bin/herdr-core` כשעדיין אין לך אחת, ומעדכנת את שניהם בעצמה. היא יושבת לצד פקודת `herdr` ש-Omarchy מספקת ב-`Super + Ctrl + Return` במקום להחליף אותה, ומקבלת את מקשי הישיר של אותה פקודה: `Alt + Return` ו-`Alt + Shift + Return` מפצלים פאנל למטה או ימינה, `Alt + Escape` סוגר אותו, `Ctrl + Alt + Arrow` נע בין פאנלים, `Alt + 1..9` ו-`Alt + Left/Right` בוחרים לשונית, ו-`Alt + Up/Down` נעים בין מרחבים. `Ctrl + 1..9` בוחר מרחב ו-`Alt + Shift + Up/Down` עובר בין סוכנים. מקשי הקידומת `Ctrl + Space` נשארים לטרמינל בלבד, מאחר שהאפליקציה לא יכולה להחזיק מקש Ctrl פשוט לרצף. Omarchy כותבת אלה ל-`~/.config/herdr-app/keys.json`, ו-`omarchy-refresh-herdr-app` מחזיר אותם. התקנתה בוחרת את ערכת הנושא Omarchy של Herdr, שעוקבת אחר ערכת הנושא שלך ב-Omarchy מאז והלאה. Herdr שומרת ערכת נושא אחת למצב בהיר ואחת לכהה, כך שלאחר החלפה בין ערכת נושא כהה לבהירה של Omarchy, בחר ב-Omarchy בבוחר ערכות הנושא של Herdr פעם נוספת למצב האחר.

T3 Code רץ מגרסת ה-AppImage הרשמית שלו ב-`~/.local/share/t3code` ולא מחבילה, כך שהוא מעדכן את עצמו. התקנתו שואלת האם להתחיל בערוץ Stable או Nightly; החלף מאוחר יותר בהגדרות של T3 Code. ה-threads וההגדרות שלך חיים ב-`~/.t3`, והסרת T3 Code תחת _Remove > AI_ לוקחת אותם איתה.

### מודלים מקומיים

הרץ מודל פתוח במכונה שלך עבור סוכני הקידוד שלך. ה-prompts והקוד שלך נשארים במכונה; שום דבר שנשלח למודל לא עוזב אותה. התחל עם:

```bash
omarchy models use best text
```

זה מגדיר את מודל הטקסט הטוב ביותר למכונה זו, הסוג שהסוכנים שלך משתמשים בו. למודלי תמונה, וידאו ומוזיקה יש טוב ביותר משלהם: `omarchy models use best image`, `video` או `music`. הרץ `omarchy models use best` כדי לראות את הבחירה של כל סוג למכונה זו.

או פתח את פאנל המודלים המקומיים מאייקון הנצנצים שלו בסרגל העליון, לצד אייקון הסוכנים, או עם Super + Ctrl + Alt + X, ובחר +. האייקון מופיע כאשר מודל מתאים למכונה זו. Podman, שמריץ את המודלים, מגיע עם Omarchy, וכך גם ערכת הכלים ל-container של NVIDIA במכונת NVIDIA, שנותנת להם את ה-GPU; אם אחד מהם חסר, ההגדרה הראשונה מתקינה אותו. Omarchy אז בוחרת את המודל המומלץ למכונה זו, מורידה אותו, ומפעילה אותו. צפה להורדה של עשרות GB ולרוב זיכרון המכונה בשימוש בזמן שהמודל רץ: Flash Next משתמש בכ-100 GiB עם הקשר ה-256K המלא שלו. אם מודלים אחרים מחזיקים את הזיכרון שהוא צריך, הוא מוגדר מופסק, מוכן להתחיל לאחר שתעצור אחד. המודל עוצר בהתנתקות; עצור אותו בעצמך כשאתה צריך את הזיכרון למשהו אחר.

`omarchy models list` מציג את האפשרויות ומסביר מדוע חלקן לא מתאימות. כדי להגדיר אחר, הרץ `omarchy models use <recipe>`. היום, `qwen3.8-flash-next-gufo` ו-`qwen3.8-27b-gufo` זמינים למכונות Strix Halo של 128 GB; ה-27B לוקח כ-40 GiB, כך שהוא משאיר מקום לעבודה אחרת. במחשב נייד של 64 GB עם Arc B390 של Intel, `qwen3.6-35b-a3b-llamacpp` רץ בכ-30 GiB. מתכונים והמלצות חדשים מגיעים עם `omarchy update`, דרך החבילה.

כל מודל שאתה מגדיר מקבל שורה משלו בפאנל המודלים המקומיים: הפעל כדי להתחיל אותו, השהה כדי לעצור אותו ולפנות את זיכרונו, וכפתור הטרמינל כדי לפתוח את הסוכן שלך עליו. בחלק העליון, סרגל מציג כיצד זיכרון המכונה מחולק בין Omarchy עצמה (המערכת והאפליקציות שלך), כל מודל פעיל, ומה פנוי. הצבע על מודל מופסק והסרגל מציג האם הוא מתאים, או בכמה הוא חסר. כמה יכולים לרוץ בו-זמנית כשהם מתאימים בזיכרון יחד; אם אחד לא מתאים, Omarchy אומרת איזה מודל פעיל לעצור. גרור שורות לפי הלוגו שלהן כדי לסדר אותן מחדש, ולחץ Delete על שורה נבחרת כדי להסיר מודל ואת ההורדה שלו.

כל מודל קידוד שאתה מגדיר מקבל גם ערך משלו במשגר האפליקציות, תחת שם המודל ועם הלוגו של היוצר שלו, באותו אופן שבו התחברות ל-Claude, Codex או Grok מוסיפה אחד. הוא פותח את הסוכן שלך על המודל הזה, ומפעיל את המודל קודם אם הוא לא רץ: הטרמינל מציג אותו נטען ומוסר לסוכן לאחר שהוא עולה. הסרת מודל מסירה את הערך שלו.

לא כל מודל מיועד לקידוד. מודלי תמונה, וידאו ומוזיקה נפתחים ב-Fantasi במקום זאת, האפליקציה של Omarchy ליצירת תמונות, וידאו ומוזיקה עם מודל שרץ במכונה זו, שנבחר שם או מהשורה שלהם בפאנל המודלים המקומיים.

מודל ממשיך לרוץ בדיוק כפי שהוגדר, כך שעדכון Omarchy לעולם לא מפעיל מחדש אחד מתחת לסוכנים שלך. כאשר ל-Omarchy יש runtime חדש יותר או משקולות חדשות יותר למודל שהגדרת, השורה שלו מציגה כפתור עדכון: לחץ עליו והמודל מוגדר שוב ברקע, מוריד רק מה שהשתנה, ומופעל מחדש בגרסה החדשה. מודל שהיה מופסק נשאר מופסק. `omarchy models update` עושה את אותו דבר לכל מודל מטרמינל.

משורת הפקודה, `omarchy models start <recipe>` ו-`omarchy models stop <recipe>` עושים את אותו דבר, `omarchy models status` מציג כל מודל, ו-`omarchy agent --local` פותח את המודל האחרון שהפעלת ב-pi, לא משנה מה סוכן ברירת המחדל שלך. גם OpenCode ו-Qwen Code יכולים להשתמש במודל מקומי: `omarchy models harness opencode` או `omarchy models harness qwen` פותח אותם שם במקום זאת, ו-`omarchy models harness pi` חוזר. pi גם מפרט כל מודל שהגדרת, ואלה במכונות שציוותת איתן, בבוחר המודלים שלו עצמו, כך ש-`pi` פשוט מגיע אליהם גם כן. כל לקוח תואם OpenAI יכול להתחבר גם כן: `status` מציג את כתובת כל מודל (הראשון הוא `http://127.0.0.1:11435/v1`), שם המתכון הוא המודל, והמפתח נמצא ב-`~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` מוחק מודל ואת ההורדות שאף מודל אחר לא משתמש בהן.

runtimes של צד שלישי מסומנים עם המו"ל שלהם. Omarchy מריצה כל מודל ללא גישת רשת.

### מודלי LLM מקומיים

Omarchy ממליצה על שתי דרכים להרצת מודלי LLM מקומיים: LM Studio ו-Ollama. LM Studio מספק ממשק GUI למציאת מודלים במשקל פתוח, התקנתם והרצתם. זו דרך מעולה להתחיל בקלות. Ollama מציע CLI לעשות זאת באופן דומה. אבל אם אתה חדש במודלים מקומיים, אני הייתי מתחיל עם LM Studio. אתה יכול להתקין כל אחד מהם תחת _Install > AI_ בתפריט Omarchy.

### ה-skills של Omarchy

Agent skills עוזרים ל-AI להשתמש בכלים ספציפיים בדרך ספציפית, ו-Omarchy מספקת שבעה מהם. ה-skill של omarchy מכסה התאמת המערכת, כמו שינוי תצורת Hyprland שלך או התאמת הסרגל. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app ו-omarchy-make-game מכסים יצירת משהו חדש, omarchy-contribute מכסה דיווח על באג או שליחת תיקון ל-upstream, ו-omarchy-diagnose-crash עובר על ה-core dump של קריסה. הם מקושרים בסמליות לתיקיות ה-skill של Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` וכל `~/.hermes/profiles/*/skills`), והמיקום הגנרי `~/.agents/skills`, כך שרוב ה-harnesses מרימים אותם אוטומטית. תיקיית skill משלך עם אותו שם מקבלת עדיפות.

אבל עליך להתייחס ל-skills אלה כניסיוניים. מודלים שונים ישתמשו בהם להשפעה שונה. עדיף לרוץ במצב תכנון קודם, כך שיהיה לך מושג מה הסוכן היה רוצה לשנות. ואז תהיה מוכן לבטל שינויים או אפילו להפעיל `omarchy reinstall configs`, אם הסוכן מבלגן הכל.
