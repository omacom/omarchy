# AI

Omarchy כוללת משגרים עבור סוכני הקידוד שלמטה מבלי לבחור עבורך ברירת מחדל. הרץ פקודה כדי להתקין את ה-CLI שלה בשימוש הראשון, ולאחר מכן בצע אימות כשתתבקש. Hermes ו-OpenClaw הם היוצאים מן הכלל: שום דבר לא מותקן עבורם דרך mise, ובחירה באחד מהם מתקינה עותק משלו שמתעדכן בעצמו, כפי ש-_אפליקציות שולחניות_ שלמטה מסביר.

### התקנה ועדכון של סוכנים

פרט ל-Hermes ו-OpenClaw, סוכנים אלה משתמשים בהתקנה העצלה של mise: ההפעלה הראשונה מתקינה את ה-CLI, והפעלות מאוחרות יותר משתמשות בו שוב. mise גם בודקת סוכן מותקן אם יש גרסה חדשה לכל היותר פעם בארבע שעות, ממש לפני שהוא מתחיל או ברקע בשורת המעטפת. אם אותו עדכון נכשל או שאתה לא מחובר, הגרסה המותקנת רצה. `omarchy update` מעדכן סוכנים מותקנים עם שאר Omarchy, ו-`mup` מעדכן כלים המנוהלים על ידי mise בלבד.

המעדכן של סוכן עצמו, כמו `claude update`, `codex update`, או כפתור עדכון באפליקציה, אינו מעדכן את ההתקנה המנוהלת על ידי mise. `codex update` נכשל, ו-`claude update` יכול לדווח על הצלחה בעודו מתקין עותק נפרד ש-mise אינה עוקבת אחריו. אם אתה מעדיף להשתמש במתקין ובמעדכן המקוריים של סוכן, הוסף אותו ל-`disable_tools`; ראה [כלי CLI מותקנים מראש](18-development-tools.md#preinstalled-cli-tools).

כדי להתקין את כל הכלים העצלים שהוגדרו לפני שאתה צריך אותם, הרץ `mise install --include-lazy`. זה כולל את כלי ה-CLI האחרים המוגדרים כברירת מחדל של Omarchy וכן את הסוכנים. ראה [כלי CLI מותקנים מראש](18-development-tools.md#preinstalled-cli-tools) להתקנת כלי יחיד או לשימוש בהתקנה שלך.

`grok` מותקן דרך החבילה הרשמית `grok` של mise, באותו אופן כמו `claude` ו-`codex`. הרץ `grok`, או סמן אותו בכוכב בלוח הסוכנים. דלג על המתקין `curl | bash` ב-x.ai. אותה דרך שמה עותק שני ב-`~/.grok/bin`, מוסיפה אותו בתחילת `PATH`, ודורסת את העטיפה של Omarchy.

`dsh` פותח את ממשק הדפדפן שלו ב-`127.0.0.1:3080`, עם ספריית ההפעלה כסביבת העבודה המוגדרת כברירת מחדל שלו. ממשק הדפדפן שלו אינו מקבל הנחיית פתיחה, ולכן `omarchy agent prompt` פותח אותו עם ההנחיה על לוח ההעתקה שלך כדי להדביק. Omarchy מפעילה אותו עם הגדרת ההרשאות ללא אישור של DeepSeek. DeepSeek Harness מעלה יומני הפעלה ל-DeepSeek כאשר אתה משתמש ב-API הרשמי של המודל שלו; כבה זאת תחת _הגדרות > כללי > העלאת יומן הפעלה_ בממשק הדפדפן שלו. משוב שאתה שולח אליו מועלה עם ההפעלה גם כן, אלא אם תפעיל אותו עם `DSH_TELEMETRY_MODE=DISABLED`.

### סוכן ברירת המחדל

בחר את סוכן ברירת המחדל שלך עם הכוכב שליד סוכן בלוח הסוכנים, שמלא אצל ברירת המחדל, או עם `omarchy default agent <name>`, שמקבל גם כל harness שאין לו שורה שם. אם הסוכן עדיין לא מותקן, בחירתו מתקינה אותו תחילה, והוא מקבל גם משגר משלו במשגר האפליקציות, לצד Agent. Omarchy חדשה מזמינה אותך להגדיר אחד עם התראה חד-פעמית, שפותחת את לוח הסוכנים.

בחירה ב-Claude מנסה גם להגדיר את תוסף הדפדפן שלו עבור Chromium, Chrome, Brave, Brave Origin ו-Edge. הגדרת התוסף חלה על כל המשתמשים ועשויה לבקש את סיסמת המערכת שלך; ביטול או כשל בהתקנת התוסף עדיין בוחרים ומפעילים את Claude. הפעל מחדש את הדפדפן, הפעל את התוסף אם תתבקש, והיכנס ל-Claude כדי לסיים לחבר אותו. הרץ `/chrome` ב-Claude כדי לבדוק את החיבור. Firefox ו-Zen אינם תומכים בתוסף הזה. אם Claude כבר היה ברירת המחדל שלך לפני שההגדרה הזו נוספה, בחר אותו שוב כדי להתקין את התוסף.

ברגע שבחרת, `Super + Shift + Ctrl + A` מפעיל את סוכן ברירת המחדל בחלון טרמינל ייעודי (או מעלה את הבוחר אם עדיין לא בחרת). אפשר גם להפעיל אותו ישירות לתוך משימה עם `omarchy agent prompt "Review this project"`. Freebuff ו-DeepSeek Harness אינם מקבלים הנחיית פתיחה, ולכן הם נפתחים עם ההנחיה על לוח ההעתקה שלך כדי להדביק במקום זאת. סוכנים שמופעלים כך רצים ללא השגחה במצבי אל-תעצור-לשאול המתאימים שלהם, אז היה מוכן שהם באמת יעשו דברים! ל-MiniMax Code אין מצב כזה עבור ההפעלות האינטראקטיביות שלו, ולכן הוא מבקש הרשאות כרגיל. ומכיוון שסוכנים מסרבים לזכור אמון עבור ספריית הבית שלך, הפעלות מ-`$HOME` מתחילות ב-`~/Work` במקום זאת.

יש גם קיצורי טרמינל: `a` מריץ את סוכן ברירת המחדל בתוך הטרמינל הנוכחי, בעוד `c`, `cx` ו-`cy` מפעילים את OpenCode, Claude Code ו-Codex ישירות (שוב במצבי האישור האוטומטי שלהם). שינויי ערכת נושא מסתנכרנים גם לסוכנים: Claude Code, Pi, OpenCode ו-Hermes (ברגע ש-Omarchy התקינה אותו) כולם עוקבים כשאתה מחליף את ערכת הנושא של Omarchy.

### הוראות הסוכן שלך

כללים אישיים עבור כל סוכן נכנסים ל-`~/.agents/AGENTS.md`, לצד הכישורים המשותפים ב-`~/.agents/skills`. פתח אותו עם סמל המסמך שליד ה-+ בלוח הסוכנים, או `omarchy agent instructions --edit`, שגם מקשר אותו לכל harness ששומר קובץ גלובלי משלו: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` של Copilot, וכן הלאה. Crush ו-Amp קוראים את הקישור `~/.config/AGENTS.md`, בעוד omp, Kimi ו-DeepSeek Harness קוראים את `~/.agents/AGENTS.md` ישירות. בחירת סוכן ברירת מחדל מקשרת אותו גם כן. קובץ הוראות שכבר היה לך הופך למשותף אם עדיין לא היה אחד כזה; אחרת הוא נשמר לצד הקישור כ-`.bak`. הרץ `omarchy agent instructions` כדי לקשר מחדש לאחר התקנת סוכן נוסף.

### לוח הסוכנים

בשורה העליונה יש סמל סוכנים. לפני שהגדרת סוכן, הלוח שלו מציע שלוש דרכים להתחיל: להיכנס למנוי Claude, Codex, Grok, Gemini, Muse, Cursor או Copilot, או תחת More לתוכנית קידוד של OpenCode Go, MiniMax, Synthetic או Z.ai; לשלם לפי שימוש עם Fireworks, OpenCode Zen and Go, OpenRouter, או תחת More עם DeepSeek או כל ספק אחר ש-OpenCode מתחבר אליו, כולם רצים ב-OpenCode; או להריץ את המודל הטוב ביותר עבור המחשב שלך, כשאחד מתאים לו. הראשון שאתה מסיים הופך לסוכן ברירת המחדל שלך, וה-+ בלוח מציע את אותן שלוש אפשרויות מאוחר יותר. לאחר מכן, הלוח שם כל מנוי בעמוד אחד: כל סוכן וחשבון עם התוכנית שלו, מד עבור כל אחד ממגבלות ההפעלה של 5 שעות והמגבלות השבועיות שלו עם הזמן עד שהוא מתאפס (החזק את הסמן מעליו כדי לראות את האחוז המדויק), או יתרת התשלום מראש שנותרה, תחת שורה שמתחלפת בין מה שהשתמשת בו בכל אלה, כמו טוקנים השבוע והמודל שהכי השתמשת בו. תחת _צור משהו מגניב_ הוא מציע הנחיות פתיחה לערכת נושא, תוסף, אפליקציה או משחק חדשים שמוסרים את המשימה לסוכן ברירת המחדל שלך. אפליקציות נבנות כפי שאפליקציות Hype, Monologue ו-Omacut של Omarchy עצמה נבנות, ב-C++ וב-Qt Quick, לפי כישור הסוכן omarchy-make-app, והמהדר וחלקי Qt שהם צריכים מותקנים. משחקים הם עמוד three.js יחיד ב-`~/Games/vibes`, לפי כישור הסוכן omarchy-make-game, וכולם נפתחים ממשגר Game Vibes אחד בערכת הנושא הנוכחית; הם טוענים three.js מהרשת, ולכן הם צריכים חיבור כדי להתחיל. Claude Code, Codex, Grok, Kimi, Cursor והקצבת Grok Bot שלו, GitHub Copilot, Muse, Gemini (דרך Antigravity) ו-Devin מכוסים מיד עם המגבלות שלהם, Kimchi עם התוכנית שלה, קרדיטים בתשלום מראש ותקציבי הוצאה, ו-Hermes, Mistral Vibe ו-Qwen Code מציגים את ההפעלות והטוקנים שלהם ברגע שהשתמשת בהם. תוכניות ומפתחות של ספקים שאתה משתמש בהם דרך pi, omp או opencode מופיעים גם כן: OpenCode Zen and Go, תוכנית Z.ai GLM Coding Plan, Ollama Cloud, תוכנית MiniMax Token Plan ו-Synthetic עם המגבלות שלהם; OpenRouter ו-DeepSeek עם יתרות התשלום מראש שלהם; Fireworks עם ההוצאה שלו במהלך 30 הימים האחרונים. מודלי קידוד שאתה מריץ על החומרה שלך מקבלים שורות משלהם, וגם הטוקנים שלהם נספרים בסיכומים, כפי שמתואר תחת [מודלים מקומיים](#local-models). כל סוכן נספר פעם אחת, תחת מי שמחייב עליו, לא משנה כמה harnesses אתה מפעיל אותו דרכם.

לחיצה שמאלית על סמל השורה או לחיצה על `Super + Ctrl + X` עבור הלוח, לחיצה ימנית להפעלת סוכן ברירת המחדל שלך, ולחיצה אמצעית לריענון. רשומות השימוש שמאחוריו נוצרות מחדש כל 15 דקות על ידי `omarchy agent usage update`, והלוח יכול אפילו למזג שימוש ממכונות אחרות שלך באמצעות תיקייה מסונכרנת. ראה את README תחת `$OMARCHY_PATH/shell/plugins/agents/` לקבלת ההגדרות המלאות.

### מספר מנויים

אם אתה משלם על יותר מתוכנית Claude, Codex או Grok אחת — Max אישית ואחת של עבודה, למשל — Omarchy יכולה להשאיר את כולם מחוברים ולעבור ביניהם. הוסף מנוי עם ה-+ בלוח הסוכנים, שמוביל אותך דרכו ממש שם, או עם `omarchy agent account add claude Work` (או `codex`, או `grok`). אותו + ואותה פקודה מתחברים ל-Gemini (`gemini`) ול-OpenCode (`opencode`), ושומרים מפתח API של Fireworks (`fireworks`) או OpenRouter (`openrouter`) ב-OpenCode; הפקודה גם מתחברת ל-Copilot (`copilot`), Cursor (`cursor`) ו-Muse (`muse`). אלה שומרים כניסה יחידה כל אחד. היא מתקינה את ה-CLI אם הוא חסר. החשבון הראשון עבור ספק נכנס דרך הדפדפן הרגיל שלך, בדיוק איפה שה-CLI תמיד מחפש. כל אחד אחריו נכנס דרך חלון פרטי, כך שהחשבון שהדפדפן שלך כבר מחובר אליו לא ייבחר בטעות; היכנס שם כחשבון שאתה מוסיף, וסגור כל חלון פרטי שכבר פתוח אצלך תחילה. לעולם אל תתנתק מה-CLI כדי לעשות זאת: התנתקות מבטלת את הכניסה השמורה, ואותו חשבון יצטרך להתווסף שוב.

כדי להעתיק את כניסות המנוי שלך למכונת Omarchy אחרת דרך SSH, הרץ `omarchy agent account copy user@laptop`. השולח מספק מקלט זמני כאשר ליעד אין אחד מותקן, כך שמכונות Omarchy ישנות יותר יכולות לקבל חשבונות ללא עדכון. מקלטים מותקנים מקבלים עדיפות. זה מעתיק את כל מנויי Claude, Codex ו-Grok; הוסף שמות ספקים כדי לבחור אותם, כמו ב-`omarchy agent account copy laptop claude`. שמות חשבונות ומזהי פקודות תואמים למקור, כולל חשבונות שכבר קיימים ביעד. חשבונות יעד לא קשורים מקבלים סיומת מספרית אם שמותיהם מתנגשים, והגדרות, כישורים, תוספים והיסטוריית שיחות נשארים מקומיים לכל מכונה.

אישורי יעד קיימים נשמרים. חשבון מקור שכבר מחובר שם מסונכרן בשמו מבלי להחליף את האישורים שלו; חשבונות אחרים מתווספים לצדו. כדי להחליף אישורים שמורים עבור חשבונות תואמים, השתמש ב-`omarchy agent account copy --replace laptop claude` לאחר שסיימת את ההפעלות של אותו חשבון ביעד. יעד חדש מקבל גם את החשבון הפעיל של המקור ואת העדפות המעבר שלו; יעד מבוסס שומר את שלו.

אישורים עוברים דרך SSH ונשמרים בקבצים פרטיים ביעד, אז העתק רק למכונות שאתה בוטח בהן. זו העתקה חד-פעמית, לא סנכרון מתמשך. טוקני ריענון של Codex יכולים להתחלף על ידי מכונה אחרת, וישאירו כניסה מועתקת הזקוקה לחידוש; כניסות נפרדות נשארות הבחירה האמינה ביותר לשימוש בו-זמני במספר מכונות. ראה [הנחיות אימות החשבון של Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

חשבון אחד לכל ספק פעיל, וכל הפעלה חדשה מתחילה כמוהו: `cx`, `cy`, `claude`, `codex` או `grok` רגילים, כל דבר שמופעל דרך `omarchy agent`, ותסריטים או עורכים שמוצאים את ה-CLI על `PATH`. החלף עם `omarchy agent account use work` (וחזרה עם `omarchy agent account use main`), או בלוח על ידי לחיצה על מספר החשבון ולאחר מכן `Enter` (או לחיצה על הכוכב שלו). הפעלות Claude רצות גם מחליפות, מההודעה הבאה שלהן: כל הפעלת Claude רצה ב-`~/.claude`, שתמיד מחזיקה את הכניסה של החשבון הפעיל. הפעלת Claude שהתחילה בתיקייה של חשבון עצמו על ידי Omarchy ישנה יותר מחזיקה את אותה כניסה עד שהיא יוצאת, ולכן המעבר מציין את אותן הפעלות ומסיים בעצמו ברגע שהן אינן. הפעלות Codex ו-Grok רצות נשארות בחשבון שבו התחילו. היסטוריית שיחות, הגדרות, כישורים ותוספים משותפים בין חשבונות, כך ש-`claude --continue` באותה תיקייה ממשיך איפה שהפסקת בחשבון החדש.

עם יותר מחשבון אחד, הלוח מציג את המגבלות של כל חשבון זה לצד זה, עם כוכב מלא על זה שבשימוש. Omarchy מודיעה לך כאשר החשבון הפעיל עובר 95% ממגבלה, ולחיצה על ההתראה עוברת לחשבון עם הכי הרבה מרווח. היא לעולם לא עוברת מעצמה. שנה את הסף עם `omarchy agent account threshold 90`. אם כל חשבון מעל הסף, תשמע על כך פעם אחת, יחד עם איזה חשבון מתפנה קודם. בעוד חשבון פעיל נמצא במרחק של עד 15 נקודות מהסף שלו (80% בברירת המחדל), המגבלות שלו נבדקות כל שלוש דקות ולא כל 15.

`omarchy agent account list` מציג כל חשבון ואת המגבלות האחרונות שלו, `omarchy agent account remove work` שוכח אחד, ו-`omarchy agent account rename primary Hey` משנה שם של אחד (או לחץ על שם חשבון בלוח). פקודות אלה פועלות על חשבונות סוכן ברירת המחדל שלך; כדי להגיע לספק האחר, ציין אותו תחילה, כמו ב-`omarchy agent account use codex side`. הכניסה שכבר הייתה לך ב-`~/.claude` או ב-`~/.codex` היא החשבון ה-_Main_. זה של Codex נשאר איפה שהוא; זה של Claude מחכה בתיקייה משלו בעוד חשבון אחר פעיל. חשבון שלא נעשה בו שימוש יותר מכשמונה שעות יכול להציג _נדרשת כניסה_; לחץ עליו כדי להיכנס לאותו חשבון שוב ממש בלוח, או עבור אליו והתחל הפעלה, שמרעננת את הכניסה מעצמה. שרתים של MCP שאתה מוסיף עם `claude mcp add` מגיעים לכל חשבון Claude, מכיוון שכולם רצים ב-`~/.claude`; עבור Codex ו-Grok, שרתים שהיו לך כאשר חשבון התווסף באים איתו אליו, אבל מאוחרים יותר מגיעים רק לחשבון שהוספת אותם בו. Claude Desktop שומר כניסה משלו, וכלי Codex או Grok שהוגדרו עם נתיב מוחלט לקובץ בינארי של CLI אינם עוקבים אחרי המעבר. `CLAUDE_CONFIG_DIR`, `CODEX_HOME` או `GROK_HOME` מפורשים מקבלים עדיפות על החשבון שנבחר.

### אבחון קריסות

Omarchy עוקבת אחר systemd-coredump לקריסות תהליכים. ברגע שבחרת סוכן ברירת מחדל, כל תוכנית שלך שמבצעת dump לליבה מביאה התראה "Process crashed" — לחץ עליה, והקריסה נמסרת לסוכן ברירת המחדל שלך יחד עם כישור omarchy-diagnose-crash של Omarchy, שמוביל את הסוכן בביסוס העובדות מה-core dump ובהחלטה אם הקריסה שווה דיווח למפתחים המקוריים. אפשר גם להריץ אותו ידנית מול כל PID מ-`coredumpctl list` עם `omarchy agent crash <pid>`.

המעקב מופעל כברירת מחדל. כבה אותו תחת _Trigger > Toggle > Crash Capture Off_ (או עם `omarchy toggle crash-capture`) וההתראות מפסיקות; `omarchy agent crash <pid>` עדיין עובד ידנית.

אפשר גם להשתיק קריסות תוכנית אחת בכל פעם, שזה מה שהאבחון מציע לך בסוף. `omarchy crash mute hyprland` מפסיק את ההתראות עבור אותה תוכנית בלבד, `omarchy crash mute hyprland off` מחזיר אותן, ו-`omarchy crash mute` בפני עצמו מפרט מה השתקת. הוא מקבל נתיב של קובץ בינארי בקלות כמו את שמו, כך ש-`omarchy crash mute /usr/bin/hyprland` עושה את אותו הדבר. צטט שם עם רווח בו, כמו ב-`omarchy crash mute 'Some App'`. כל דבר אחר עדיין מודיע, והתוכנית המושתקת עדיין קורסת — זה מסתיר את התזכורת, זה לא מתקן כלום.

### אפליקציות שולחניות

תפריט _התקנה > AI_ נושא גם כמה אפליקציות AI גרפיות: Amp Desktop, Antigravity Desktop, אפליקציית שולחן העבודה של ChatGPT, אפליקציית שולחן העבודה של Claude (גרסת הבטא ל-Linux של Anthropic, עם לשוניות Chat, Cowork ו-Claude Code), Grok Bot לצ'אט עם המודלים של xAI, Herdr Desktop, Hermes Desktop, OpenClaw, אפליקציית שולחן העבודה של Perplexity ו-T3 Code. Grok Bot היא אפליקציית הצ'אט לשולחן העבודה. סוכן הקידוד הוא הפקודה `grok`.

Hermes Desktop היא זו שכדאי להכיר, מכיוון שלמכונה יש Hermes אחד, והוא של האפליקציה: Hermes מותקן רק אי פעם דרך האפליקציה, והפקודה `hermes` שסוכן ברירת המחדל מריץ היא של האפליקציה. בחירת Hermes כסוכן ברירת המחדל מתקינה את אותו הדבר שהערך _התקנה > AI_ מתקין: החבילה, וזמן ריצה של Hermes תחת `~/.hermes` שהותקן על ידי המתקין של Hermes עצמו, שלוקח כמה דקות בפעם הראשונה. זמן הריצה הזה הוא ה-Hermes היחיד שהפקודה הטרמינלית `hermes`, סוכן ברירת המחדל והאפליקציה כולם משתמשים בו, והוא מתעדכן בעצמו עם `hermes update` ולא מחכה לגרסת Omarchy. התקנתו גם נותנת ל-Hermes את ערכת הנושא של Omarchy כ-skin בשם `omarchy`, שכל משטח של Hermes עוקב אחריו כשאתה מחליף ערכות נושא; בחר אחר תחת הגדרות Appearance של Hermes או עם `/skin` אם אתה מעדיף שלא, ו-Omarchy משאירה את הבחירה הזו לבד. הסרת האפליקציה תחת _הסרה > AI_ סוגרת את Hermes תחילה, כולל השער, לוקחת את זמן הריצה הזה איתה, ושומרת את הצ'אטים, הזיכרונות והכישורים ש-Hermes כתב לעצמו אלא אם תגיד לו אחרת: היא שואלת, כשברירת המחדל היא לא, האם גם הנתונים האלה והגדרות החיבור שלך צריכים ללכת.

חוויית שולחן העבודה של OpenClaw היא Control UI שלו, שנפתח כאפליקציית רשת שמגובה בשער מקומי משלו. OpenClaw חי ב-`~/.openclaw` ומתעדכן בעצמו: השתמש בכפתור "Update Gateway" של Control UI או הרץ `openclaw update`, והשער מתחיל מחדש על הגרסה החדשה. Omarchy בוחרת רק את הגרסה שהתקנה חדשה מתחילה ממנה. OpenClaw יכול גם להיות סוכן ברירת המחדל שלך: בחירתו עם `omarchy default agent openclaw` מגדירה את אותו עותק ב-`~/.openclaw`, והסוכן פותח את ממשק המשתמש הטרמינלי של OpenClaw המחובר לשער שלו. הסרת OpenClaw תחת _הסרה > AI_ לוקחת את שירות השער ואת האפליקציה איתה ולאחר מכן שואלת האם גם `~/.openclaw` צריך ללכת, מכיוון שזה מחזיק את הצ'אטים והאישורים שלך לצד OpenClaw עצמו וזמני הריצה של התוספים שהוא מוריד; ברירת המחדל שומרת אותו, והתקנת OpenClaw שוב מרימה אותו חזרה.

Herdr Desktop היא אפליקציית שולחן העבודה [Herdr](https://herdr.dev): מרחבים, לשוניות וחלוניות של טרמינלים וסוכני קידוד שממשיכים לרוץ בליבה שלה כשאתה סוגר את החלון. היא באה מהמתקין של Herdr עצמו ולא מחבילה, ולכן היא חיה ב-`~/.local/share/herdr-app`, מביאה את הליבה שלה ב-`~/.local/bin/herdr-core` כשעדיין אין לך אחד, ומעדכנת את שניהם בעצמה. היא יושבת לצד הפקודה `herdr` ש-Omarchy מספקת על `Super + Ctrl + Return` ולא מחליפה אותה, ומקבלת את המקשים הישירים של אותה פקודה: `Alt + Return` ו-`Alt + Shift + Return` מפצלים חלונית למטה או ימינה, `Alt + Escape` סוגר אותה, `Ctrl + Alt + Arrow` עובר בין חלוניות, `Alt + 1..9` ו-`Alt + Left/Right` בוחרים לשונית, ו-`Alt + Up/Down` עוברים בין מרחבים. `Ctrl + 1..9` בוחר מרחב ו-`Alt + Shift + Up/Down` עוברים בין סוכנים. מקשי הקידומת `Ctrl + Space` נשארים לטרמינל בלבד, מכיוון שהאפליקציה לא יכולה להחזיק מקש Ctrl רגיל לרצף. Omarchy כותבת אותם ל-`~/.config/herdr-app/keys.json`, ו-`omarchy-refresh-herdr-app` מחזיר אותם. התקנתה בוחרת את ערכת הנושא Omarchy של Herdr, שעוקבת אחרי ערכת הנושא של Omarchy שלך מאז ואילך. Herdr שומרת ערכת נושא אחת למצב בהיר ואחת למצב כהה, ולכן לאחר מעבר בין ערכת נושא כהה לבהירה של Omarchy, בחר את Omarchy בבוחר ערכות הנושא של Herdr פעם נוספת עבור המצב האחר.

T3 Code רץ מגרסת AppImage הרשמית שלו ב-`~/.local/share/t3code` ולא מחבילה, ולכן הוא מתעדכן בעצמו. התקנתו שואלת האם להתחיל בערוץ Stable או Nightly; החלף מאוחר יותר בהגדרות של T3 Code. האשכולות וההגדרות שלך חיים ב-`~/.t3`, והסרת T3 Code תחת _הסרה > AI_ לוקחת אותם איתה.

### מודלים מקומיים

הרץ מודל פתוח במכונה שלך עבור סוכני הקידוד שלך. ההנחיות והקוד שלך נשארים במכונה; שום דבר שנשלח למודל לא עוזב אותה. התחל עם:

```bash
omarchy models use best text
```

זה מגדיר את מודל הטקסט הטוב ביותר למכונה זו, הסוג שהסוכנים שלך משתמשים בו. למודלי תמונה, וידאו ומוזיקה יש טוב ביותר משלהם: `omarchy models use best image`, `video` או `music`. הרץ `omarchy models use best` כדי לראות את הבחירה של כל סוג למכונה זו.

או בחר + בלוח הסוכנים: תחת _השתמש במודל מקומי_ הוא מפרט כל מודל קידוד שמתאים למכונה זו, המומלץ ראשון. Podman, שמריץ את המודלים, מגיע עם Omarchy, וכך גם ערכת הכלים למכולות של NVIDIA במכונת NVIDIA, שנותנת להם את ה-GPU; אם אחד מהם חסר, ההגדרה הראשונה מתקינה אותו. Omarchy אז בוחרת את המודל המומלץ למכונה זו, מורידה אותו ומפעילה אותו. צפה להורדה של עשרות GB ולרוב זיכרון המכונה בשימוש בעוד המודל רץ: Flash Next משתמש בכ-100 GiB עם הקשר 256K המלא שלו. אם מודלים אחרים מחזיקים את הזיכרון שהוא צריך, הוא מוגדר עצור, מוכן להתחיל ברגע שתעצור אחד. המודל עוצר ביציאה מהמערכת; עצור אותו בעצמך כשאתה צריך את הזיכרון למשהו אחר.

`omarchy models list` מציג את האפשרויות ומסביר מדוע חלקן לא מתאימות. כדי להגדיר אחד אחר, הרץ `omarchy models use <recipe>`. היום, `qwen3.8-flash-next-gufo` ו-`qwen3.8-27b-gufo` זמינים למכונות Strix Halo של 128 GB; ה-27B לוקח כ-40 GiB, ולכן הוא משאיר מקום לעבודה אחרת. במחשב נייד של 64 GB עם Arc B390 של Intel, `qwen3.6-35b-a3b-llamacpp` רץ בכ-30 GiB. מתכונים והמלצות חדשים מגיעים עם `omarchy update`, דרך החבילה.

מודל קידוד שאתה מוסיף מקבל שורה משלו בלוח הסוכנים, לצד המנויים שלך: הפעל כדי להתחיל אותו, השהה כדי לעצור אותו ולפנות את זיכרונו, סימן Tailscale כדי לשתף אותו עם המכונות האחרות ב-tailnet שלך בעודו רץ, וכפתור הטרמינל כדי לפתוח את הסוכן שלך עליו. השורה שלו מציגה את ההורדה, הטעינה או העצירה תוך כדי, ואומרת כך כשאין מספיק זיכרון פנוי להפעיל אותו, או מקשרת ליומנים שלו כשהוא עצר עם שגיאה. כמה יכולים לרוץ בבת אחת כשהם מתאימים בזיכרון יחד. לחץ על Delete בשורה נבחרת כדי להסיר את המודל מהמכונה זו, כולל ההורדה; + יכול להגדיר אותו שוב. מודל קידוד שהוגדר מטרמינל מחכה תחת + עד שתוסיף אותו, וכך גם המודלים שמכונה שצימדת איתה (`omarchy models pair <host>`) מריצה.

כל מודל קידוד שאתה מגדיר מקבל גם ערך משלו במשגר האפליקציות, תחת שם המודל ועם הלוגו של היוצר שלו, כפי שכניסה ל-Claude, Codex או Grok מוסיפה אחד. הוא פותח את הסוכן שלך על אותו מודל, ומפעיל את המודל תחילה אם הוא לא רץ: הטרמינל מציג אותו נטען ומוסר לסוכן ברגע שהוא מוכן. הסרת מודל מסירה את הערך שלו.

לא כל מודל מיועד לקידוד. מודלי תמונה, וידאו ומוזיקה נפתחים ב-Fantasi במקום זאת, האפליקציה של Omarchy ליצירת תמונות, וידאו ומוזיקה עם מודל שרץ במכונה זו, ומנוהלים שם או עם `omarchy models`.

מודל ממשיך לרוץ בדיוק כפי שהוגדר, ולכן עדכון Omarchy לעולם לא מפעיל מחדש אחד תחת הסוכנים שלך. כאשר ל-Omarchy יש זמן ריצה חדש יותר או משקולות חדשות יותר למודל שהגדרת, השורה שלו מציגה כפתור עדכון: לחץ עליו והמודל מוגדר שוב ברקע, מוריד רק את מה שהשתנה, ומתחיל מחדש על הגרסה החדשה. מודל שהיה עצור נשאר עצור. `omarchy models update` עושה את אותו הדבר עבור כל מודל מטרמינל.

משורת הפקודה, `omarchy models start <recipe>` ו-`omarchy models stop <recipe>` עושים את אותו הדבר, `omarchy models status` מציג כל מודל, ו-`omarchy agent --local-model <recipe>` פותח את אותו מודל ב-pi, לא משנה מה סוכן ברירת המחדל שלך. כדי להפוך את המודל המקומי שלך למה שמקש הקיצור של הסוכן, קונסולת Quake ו-_צור משהו_ פותחים, הרץ `omarchy default agent local` או סמן בכוכב מודל רץ בלוח הסוכנים. pi גם מפרט כל מודל שהגדרת, ואלה במכונות שצימדת איתן, בבוחר המודלים שלו, כך ש-`pi` רגיל מגיע אליהם גם כן. כל לקוח תואם OpenAI יכול להתחבר גם כן: `status` מציג את הכתובת של כל מודל (הראשון הוא `http://127.0.0.1:11435/v1`), שם המתכון הוא המודל, והמפתח נמצא ב-`~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` מוחק מודל ואת ההורדות שאף מודל אחר לא משתמש בהן.

זמני ריצה של צד שלישי מסומנים עם המו"ל שלהם. Omarchy מריצה כל מודל ללא גישה לרשת.

### מודלי LLM מקומיים

Omarchy ממליצה על שתי דרכים להריץ מודלי LLM מקומיים: LM Studio ו-Ollama. LM Studio מספקת ממשק GUI למציאת מודלים פתוחי משקל, התקנתם והרצתם. זו דרך מעולה להתחיל בקלות. Ollama מציעה CLI לעשות זאת באופן דומה. אבל אם אתה חדש במודלים מקומיים, הייתי מתחיל עם LM Studio. אפשר להתקין אחד מהם תחת _התקנה > AI_ בתפריט Omarchy.

### כישורי Omarchy

כישורי סוכן עוזרים ל-AI להשתמש בכלים ספציפיים בדרך ספציפית, ו-Omarchy מספקת שבעה מהם. הכישור omarchy מכסה התאמת המערכת, כמו כוונון תצורת Hyprland שלך או התאמת השורה. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app ו-omarchy-make-game מכסים יצירת משהו חדש, omarchy-contribute מכסה דיווח על באג או שליחת תיקון למפתחים המקוריים, ו-omarchy-diagnose-crash עובר על core dump של קריסה. הם מקושרים בסמליות לספריות הכישורים עבור Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` וכל `~/.hermes/profiles/*/skills`), והמיקום הגנרי `~/.agents/skills`, כך שרוב ה-harnesses מרימים אותם אוטומטית. תיקיית כישור משלך עם אותו שם מקבלת עדיפות.

אבל כדאי להתייחס לכישורים אלה כניסיוניים. מודלים שונים ישתמשו בהם להשפעה שונה. הכי טוב לרוץ במצב תכנון תחילה, כדי שיהיה לך מושג מה הסוכן היה רוצה לשנות. ואז היה מוכן לבטל שינויים או אפילו להפעיל `omarchy reinstall configs`, אם הסוכן מבלגן הכל.
