# AI

Omarchy כוללת משגרים לסוכני הקידוד שלמטה מבלי לבחור עבורך ברירת מחדל. הרץ פקודה כדי להתקין את ה-CLI שלה בשימוש הראשון, ואז בצע אימות כאשר תתבקש. Hermes הוא היוצא מן הכלל: שום דבר לא מותקן עבורו בשימוש הראשון, ובחירה בו מתקינה את Hermes Desktop, כפי ש-_Desktop apps_ שלמטה מסביר.

### התקנה ועדכון של סוכנים

למעט Hermes, הסוכנים האלה משתמשים בהתקנה העצלה של mise: ההפעלה הראשונה מתקינה את ה-CLI, והפעלות מאוחרות יותר משתמשות בו שוב. mise גם בודק אם קיימת גרסה חדשה לסוכן מותקן לכל היותר פעם בארבע שעות, ממש לפני שהוא מתחיל או ברקע בהנחיית shell. אם העדכון נכשל או שאתה לא מחובר, הגרסה המותקנת רצה. `omarchy update` מעדכן סוכנים מותקנים יחד עם שאר Omarchy, ו-`mup` מעדכן רק כלים המנוהלים על ידי mise.

המעדכן של סוכן עצמו, כגון `claude update`, `codex update`, או כפתור עדכון באפליקציה, לא מעדכן את ההתקנה המנוהלת על ידי mise. `codex update` נכשל, ו-`claude update` יכול לדווח על הצלחה תוך התקנת עותק נפרד ש-mise לא עוקב אחריו. אם אתה מעדיף להשתמש במתקין ובמעדכן המקוריים של סוכן, הוסף אותו ל-`disable_tools`; ראה [כלי CLI מותקנים מראש](18-development-tools.md#preinstalled-cli-tools).

כדי להתקין את כל הכלים העצלים המוגדרים לפני שתזדקק להם, הרץ `mise install --include-lazy`. זה כולל את כלי ה-CLI ברירת המחדל האחרים של Omarchy וגם את הסוכנים. ראה [כלי CLI מותקנים מראש](18-development-tools.md#preinstalled-cli-tools) להתקנת כלי בודד או לשימוש בהתקנה משלך.

`grok` מותקן דרך חבילת `grok` הרשמית של mise, באותה דרך כמו `claude` ו-`codex`. הרץ `grok`, או בחר אותו תחת _Setup > Defaults > Agent_. דלג על המתקין `curl | bash` ב-x.ai. הנתיב הזה שם עותק שני ב-`~/.grok/bin`, מוסיף אותו בתחילת `PATH`, ודרס את המעטפת של Omarchy.

`dsh` פותח את ממשק הדפדפן שלו ב-`127.0.0.1:3080`, כאשר תיקיית ההפעלה היא סביבת העבודה ברירת המחדל שלו. ממשק הדפדפן שלו לא מקבל הנחיית פתיחה, ולכן `omarchy agent prompt` פותח אותו עם ההנחיה בלוח ההעתקה שלך כדי להדביק. Omarchy מפעילה אותו עם הגדרת ההרשאות ללא אישור של DeepSeek. DeepSeek Harness מעלה יומני הפעלה ל-DeepSeek כאשר אתה משתמש ב-API הרשמי של המודלים שלו; כבה זאת תחת _Settings > General > Upload Session Log_ בממשק הדפדפן שלו. משוב שאתה שולח אליו מועלה גם הוא עם ההפעלה, אלא אם כן אתה מפעיל אותו עם `DSH_TELEMETRY_MODE=DISABLED`.

### הסוכן ברירת המחדל

בחר את סוכן ברירת המחדל שלך עם `omarchy default agent <name>` או תחת _Setup > Defaults > Agent_ בתפריט Omarchy (`Super + Space`). אם הסוכן עדיין לא מותקן, בחירה בו מתקינה אותו קודם. Omarchy טרייה תזמין אותך לבצע את הבחירה הזו עם התראה חד-פעמית.

בחירה ב-Claude גם מנסה להגדיר את תוסף הדפדפן שלו עבור Chromium, Chrome, Brave, Brave Origin ו-Edge. הגדרת התוסף חלה על כל המשתמשים ועלולה לבקש את סיסמת המערכת שלך; ביטול או כשל בהתקנת התוסף עדיין בוחרים ומפעילים את Claude. הפעל מחדש את הדפדפן, אפשר את התוסף אם תתבקש, והיכנס ל-Claude כדי לסיים את החיבור שלו. הרץ `/chrome` ב-Claude כדי לבדוק את החיבור. Firefox ו-Zen לא תומכים בתוסף הזה. אם Claude כבר היה ברירת המחדל שלך לפני שההגדרה הזו נוספה, בחר אותו שוב כדי להתקין את התוסף.

ברגע שבחרת, `Super + Shift + Ctrl + A` מפעיל את סוכן ברירת המחדל בחלון טרמינל ייעודי (או מציג את הבורר אם עדיין לא בחרת). אתה יכול גם להפעיל אותו ישירות למשימה עם `omarchy agent prompt "Review this project"`. Freebuff ו-DeepSeek Harness לא מקבלים הנחיית פתיחה, ולכן הם נפתחים עם ההנחיה בלוח ההעתקה שלך כדי להדביק במקום. סוכנים המופעלים בדרך זו רצים ללא השגחה במצבי אל-תעצור-לשאול המתאימים שלהם, אז תהיה מוכן לכך שהם באמת יעשו דברים! ל-MiniMax Code אין מצב כזה להפעלות האינטראקטיביות שלו, ולכן הוא מבקש הרשאות כרגיל. ומכיוון שסוכנים מסרבים לזכור אמון עבור תיקיית הבית שלך, הפעלות מ-`$HOME` מתחילות ב-`~/Work` במקום.

יש גם קיצורי דרך בטרמינל: `a` מריץ את סוכן ברירת המחדל בתוך הטרמינל הנוכחי, בעוד `c`, `cx` ו-`cy` מפעילים את OpenCode, Claude Code ו-Codex ישירות (שוב, במצבי האישור האוטומטי שלהם). שינויי ערכת נושא מסתנכרנים גם לסוכנים: Claude Code, Pi, OpenCode ו-Hermes (ברגע ש-Omarchy התקינה אותו) כולם הולכים בעקבותיך כאשר אתה מחליף את ערכת הנושא של Omarchy.

### פאנל הסוכנים

בסרגל העליון יש אייקון סוכנים. לפני שהגדרת סוכן, הפאנל שלו מלווה אותך בהתחברות ל-Claude, Codex או Grok, והראשון הופך לסוכן ברירת המחדל שלך. לאחר מכן, הפאנל שם כל מנוי בעמוד אחד: כל סוכן וחשבון עם התוכנית שלו, מד לכל אחת ממגבלות ההפעלה של 5 שעות והמגבלות השבועיות שלו עם הזמן עד שהוא מתאפס (עמוד מעליו לאחוז המדויק), או יתרת התשלום מראש שנותרה, מתחת לשורה המתחלפת בין מה שהשתמשת בו בכולם, כמו טוקנים השבוע והמודל שהכי השתמשת בו. תחת _Make something_ הוא מציע הנחיות התחלה לערכת נושא, תוסף או אפליקציה חדשים המעבירים את המשימה לסוכן ברירת המחדל שלך. אפליקציות נבנות כפי שהאפליקציות של Omarchy עצמה, Hype, Monologue ו-Omacut, נבנות, ב-C++ וב-Qt Quick, לפי ה-skill של סוכן omarchy-app, והמהדר וחלקי Qt שהם צריכים מגיעים מותקנים. Claude Code, Codex, Grok, Kimi, Cursor והקצבת Grok Bot שלו, GitHub Copilot, Muse, Antigravity, Kimchi ו-Devin מכוסים מהקופסה עם המגבלות שלהם, ו-Hermes, Mistral Vibe ו-Qwen Code מציגים את ההפעלות והטוקנים שלהם ברגע שהשתמשת בהם. תוכניות ספקים ומפתחות שאתה משתמש בהם דרך pi, omp או opencode מופיעים גם כן: OpenCode Zen ו-Go, תוכנית Z.ai GLM Coding Plan, Ollama Cloud, תוכנית MiniMax Token Plan ו-Synthetic עם המגבלות שלהם; Fireworks, OpenRouter ו-DeepSeek עם יתרות התשלום מראש שלהם; והמודלים שאתה מריץ על החומרה שלך תחת Local models. כל סוכן נספר פעם אחת, תחת מי שמחייב אותו, לא משנה בכמה harnesses אתה מפעיל אותו.

לחץ לחיצה שמאלית על אייקון הסרגל לפאנל, לחיצה ימנית להפעלת סוכן ברירת המחדל שלך. רשומות השימוש שמאחוריו נוצרות מחדש כל 15 דקות על ידי `omarchy agent usage-update`, והפאנל יכול אפילו למזג שימוש מהמכונות האחרות שלך דרך תיקייה מסונכרנת. ראה את ה-README תחת `$OMARCHY_PATH/shell/plugins/agents/` להגדרות המלאות.

### כמה מנויים

אם אתה משלם על יותר מתוכנית Claude, Codex או Grok אחת — Max אישית ועבודה אחת, נאמר — Omarchy יכולה לשמור את כולם מחוברים ולעבור ביניהם. הוסף מנוי עם ה-+ בפאנל הסוכנים, המלווה אותך דרך זה שם, או עם `omarchy agent account add claude Work` (או `codex`, או `grok`). זה מתקין את ה-CLI אם הוא חסר. החשבון הראשון עבור ספק מתחבר דרך הדפדפן הרגיל שלך, בדיוק היכן שה-CLI תמיד מחפש. כל אחד אחריו מתחבר דרך חלון פרטי, כך שהחשבון שהדפדפן שלך כבר מחובר אליו לא נקלט בטעות; התחבר שם כחשבון שאתה מוסיף, וסגור כל חלון פרטי שכבר היה פתוח קודם. אף פעם אל תתנתק מה-CLI כדי לעשות זאת: התנתקות מבטלת את ההתחברות השמורה, ואותו חשבון יצטרך להתווסף שוב.

כדי להעתיק את חיבורי המנויים שלך למכונת Omarchy אחרת דרך SSH, הרץ `omarchy agent account copy user@laptop`. השולח מספק מקלט זמני כאשר ליעד אין אחד מותקן, כך שמכונות Omarchy ותיקות יותר יכולות לקבל חשבונות ללא עדכון. מקלטים מותקנים מקבלים עדיפות. זה מעתיק את כל מנויי Claude, Codex ו-Grok; הוסף שמות ספקים כדי לבחור אותם, כמו ב-`omarchy agent account copy laptop claude`. שמות חשבונות ומזהי פקודות תואמים למקור, כולל חשבונות שכבר קיימים ביעד. חשבונות יעד לא קשורים מקבלים סיומת מספרית אם שמותיהם מתנגשים, והגדרות, skills, תוספים והיסטוריית שיחות נשארים מקומיים לכל מכונה.

פרטי כניסה קיימים ביעד נשמרים. חשבון מקור שכבר מחובר שם מסונכרן בשמו מבלי להחליף את פרטי הכניסה שלו; חשבונות אחרים מתווספים לצידו. כדי להחליף פרטי כניסה שמורים לחשבונות תואמים, השתמש ב-`omarchy agent account copy --replace laptop claude` לאחר שסיימת את ההפעלות של אותו חשבון ביעד. יעד חדש מקבל גם את החשבון הפעיל של המקור ואת העדפות המעבר שלו; יעד מבוסס שומר את שלו.

פרטי כניסה עוברים דרך SSH ומאוחסנים בקבצים פרטיים ביעד, ולכן העתק רק למכונות שאתה סומך עליהן. זו העתקה חד-פעמית, לא סנכרון מתמשך. אסימוני רענון של Codex יכולים להיות מוחלפים על ידי מכונה אחרת, מה שמשאיר חיבור מועתק הזקוק לחידוש; חיבורים נפרדים נשארים הבחירה האמינה ביותר לשימוש בו-זמני בכמה מכונות. ראה [הנחיות אימות החשבון של Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

חשבון אחד לכל ספק פעיל, וכל הפעלה חדשה מתחילה כמוהו: `cx`, `cy`, `claude`, `codex` או `grok` רגילים, כל דבר המופעל דרך `omarchy agent`, ותסריטים או עורכים שמוצאים את ה-CLI ב-`PATH`. עבור עם `omarchy agent account use work` (וחזרה עם `omarchy agent account use main`), או בפאנל על ידי לחיצה על מספר של חשבון ואז `Enter` (או לחיצה על כפתור ה-Use שלו). הפעלות שכבר רצות נשארות על החשבון שהתחילו איתו. היסטוריית שיחות, הגדרות, skills ותוספים משותפים בין חשבונות, כך ש-`claude --continue` באותה תיקייה ממשיך היכן שהפסקת בחשבון החדש.

עם יותר מחשבון אחד, הפאנל מציג את המגבלות של כל חשבון זה לצד זה, עם הפעיל מסומן. כברירת מחדל Omarchy מודיעה לך כאשר החשבון הפעיל עובר 95% ממגבלה, ולחיצה על ההתראה מעבירה לחשבון עם הכי הרבה מרווח. עמוד מעל שורה של חשבון בפאנל ולחץ על ה-Autoswitch שמופיע ליד Use (או לחץ `m`), או הרץ `omarchy agent account mode auto`, כדי שזה יעבור מעצמו במקום; enquanto הוא פעיל, Autoswitch תופס את מקומו של Use, ולחיצה עליו שוב חוזרת להתראה. הוסף מספר כדי לשנות את הסף, כמו ב-`omarchy agent account mode auto 90`. אם כל חשבון מעל הסף, תשמע על כך פעם אחת, יחד עם איזה חשבון מתפנה ראשון. כאשר חשבון פעיל נמצא בתוך 15 נקודות מהסף שלו (80% בברירת המחדל), המגבלות שלו נבדקות כל שלוש דקות ולא כל 15.

`omarchy agent account list` מציג כל חשבון ואת המגבלות האחרונות שלו, `omarchy agent account remove work` שוכח אחד, ו-`omarchy agent account rename primary Hey` משנה שם של אחד (או לחץ על שם של חשבון בפאנל). פקודות אלו עובדות על חשבונות סוכן ברירת המחדל שלך; כדי להגיע לספק האחר, ציין אותו קודם, כמו ב-`omarchy agent account use codex side`. החיבור שכבר היה לך ב-`~/.claude` או `~/.codex` הוא חשבון _Main_ והוא נשאר היכן שהוא. חשבון שנשאר לא בשימוש יותר מכשמונה שעות יכול להציג _Sign-in required_; לחץ עליו כדי לחבר את אותו חשבון שוב ישירות בפאנל, או התחל הפעלה בו, מה שמרענן את החיבור מעצמו. שרתי MCP שהיו לך כאשר חשבון התווסף באים איתו איתו, אבל אלה שאתה מוסיף מאוחר יותר עם `claude mcp add` רק מגיעים לחשבון שהוספת אותם בו. Claude Desktop וכלים המוגדרים עם נתיב מוחלט לבינארי של CLI לא הולכים בעקבות המעבר. `CLAUDE_CONFIG_DIR`, `CODEX_HOME` או `GROK_HOME` מפורשים מקבלים עדיפות על החשבון שנבחר.

### אבחון קריסות

Omarchy צופה ב-systemd-coredump אחר קריסות תהליכים. כאשר משהו עושה segfault, תקבל התראת "Process crashed" — לחץ עליה, והקריסה נמסרת לסוכן ברירת המחדל שלך יחד עם ה-skill של diagnose-crash של Omarchy, המלווה את הסוכן בביסוס העובדות מה-core dump ובהחלטה האם הקריסה שווה דיווח ל-upstream. אתה יכול גם להריץ אותה ידנית מול כל PID מ-`coredumpctl list` עם `omarchy agent crash <pid>`.

הצפייה פועלת כברירת מחדל. כבה אותה תחת _Trigger > Toggle > Crash Capture_ (או עם `omarchy toggle crash-capture`) וההתראות מפסיקות; `omarchy agent crash <pid>` עדיין עובד ידנית.

קריסות יכולות גם להיות מושתקות תוכנית אחת בכל פעם, וזה מה שהאבחון מציע לך בסוף. `omarchy crash mute hyprland` מפסיק את ההתראות עבור אותה תוכנית בלבד, `omarchy crash mute hyprland off` מחזיר אותן, ו-`omarchy crash mute` בפני עצמו מפרט מה השתקת. הוא מקבל את נתיב הבינארי באותה שמחה כמו את שמו, ולכן `omarchy crash mute /usr/bin/hyprland` עושה את אותו דבר. שם עם רווח בתוכו יש לצטט במרכאות, כמו ב-`omarchy crash mute 'Some App'`. כל דבר אחר עדיין מתריע, והתוכנית המושתקת עדיין קורסת — זה מסתיר את התזכורת, זה לא מתקן כלום.

### אפליקציות שולחן עבודה

תפריט _Install > AI_ נושא גם כמה אפליקציות AI גרפיות: אפליקציית שולחן העבודה של ChatGPT, אפליקציית שולחן העבודה של Claude (בטא Linux של Anthropic, עם לשוניות Chat, Cowork ו-Claude Code), Grok Bot לשיחה עם המודלים של xAI, Hermes Desktop, OpenClaw, אפליקציית שולחן העבודה של Perplexity ו-T3 Code. Grok Bot היא אפליקציית הצ'אט לשולחן העבודה. סוכן הקידוד הוא פקודת `grok`.

Hermes Desktop היא זו שצריך להכיר, כי למכונה יש Hermes אחד, והוא שייך לאפליקציה: Hermes מותקן רק אי פעם דרך האפליקציה, ופקודת `hermes` שסוכן ברירת המחדל מריץ היא של האפליקציה. בחירת Hermes כסוכן ברירת המחדל מתקינה את אותו דבר שהרשומה _Install > AI_ עושה: החבילה, וזמן ריצה של Hermes תחת `~/.hermes` המוגדר על ידי המתקין של Hermes עצמו, מה שלוקח כמה דקות בפעם הראשונה. זמן הריצה הזה הוא ה-Hermes היחיד שפקודת `hermes` בטרמינל, סוכן ברירת המחדל והאפליקציה כולם משתמשים בו, והוא מעדכן את עצמו עם `hermes update` ולא ממתין לגרסת Omarchy. התקנתו גם מעבירה ל-Hermes את ערכת הנושא של Omarchy כ-skin בשם `omarchy`, שכל משטח של Hermes עוקב אחריו כאשר אתה מחליף ערכות נושא; בחר אחר תחת הגדרות Appearance של Hermes או עם `/skin` אם אתה מעדיף שלא, ו-Omarchy משאירה את הבחירה הזו בשקט. הסרת האפליקציה תחת _Remove > AI_ סוגרת את Hermes קודם, כולל ה-gateway, לוקחת את זמן הריצה הזה איתה, ושומרת את הצ'אטים, הזיכרונות וה-skills ש-Hermes כתב לעצמו אלא אם כן אתה אומר לה אחרת: היא שואלת, בברירת מחדל לא, האם גם הנתונים האלה והגדרות החיבור שלך צריכים ללכת.

חוויית שולחן העבודה של OpenClaw היא ה-Control UI שלה, הנפתח כאפליקציית רשת המגובה על ידי ה-gateway המקומי שלה. OpenClaw גר ב-`~/.openclaw` ומעדכן את עצמו: השתמש בכפתור "Update Gateway" של ה-Control UI או הרץ `openclaw update`, וה-gateway מתחיל מחדש בגרסה החדשה. Omarchy רק בוחרת את הגרסה שהתקנה טרייה מתחילה ממנה. הסרת OpenClaw תחת _Remove > AI_ לוקחת איתה את שירות ה-gateway ואת האפליקציה ואז שואלת האם גם `~/.openclaw` צריך ללכת, מכיוון שזה מחזיק את הצ'אטים ופרטי הכניסה שלך לצד OpenClaw עצמו וזמני הריצה של תוספים שהוא מוריד; ברירת המחדל שומרת אותו, והתקנת OpenClaw שוב קולטת אותו בחזרה.

T3 Code רץ מגרסת ה-AppImage הרשמית שלו ב-`~/.local/share/t3code` ולא מחבילה, ולכן הוא מעדכן את עצמו. התקנתו שואלת האם להתחיל בערוץ Stable או Nightly; עבור מאוחר יותר בהגדרות T3 Code. החוטים וההגדרות שלך גרים ב-`~/.t3`, והסרת T3 Code תחת _Remove > AI_ לוקחת אותם איתה.

### מודלי LLM מקומיים

Omarchy ממליצה על שתי דרכים להריץ מודלי LLM מקומיים: LM Studio ו-Ollama. LM Studio מספק ממשק GUI למציאת מודלים פתוחי משקל, התקנתם והרצתם. זו דרך מעולה להתחיל בקלות. Ollama מציע CLI לעשות זאת באותה צורה. אבל אם אתה חדש במודלים מקומיים, הייתי מתחיל עם LM Studio. אתה יכול להתקין אחד מהם תחת _Install > AI_ בתפריט Omarchy.

### ה-Skill של Omarchy

Skills של סוכנים עוזרים ל-AI להשתמש בכלים ספציפיים בדרך ספציפית, ו-Omarchy מגיעה עם skill ברירת מחדל להתאמת המערכת. כמו לכוונן את הגדרות Hyprland שלך, להתאים את הסרגל, או אפילו ליצור ערכת נושא חדשה מאפס. הוא מסונכרן בקישור סמלי לתיקיות ה-skill עבור Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` וכל `~/.hermes/profiles/*/skills`), והמיקום הגנרי `~/.agents/skills`, ולכן רוב ה-harnesses קולטים אותו אוטומטית.

אבל אתה צריך להתייחס ל-skill הזה כניסיוני. מודלים שונים ישתמשו בו להשפעה שונה. עדיף להריץ במצב תכנון קודם, כדי שיהיה לך מושג מה הסוכן היה רוצה לשנות. ואז תהיה מוכן לבטל שינויים או אפילו להפעיל `omarchy reinstall configs`, אם הסוכן עושה בלגן מהכל.
