# AI

Omarchy כוללת משגרים עבור סוכני הקידוד שלמטה מבלי לבחור עבורך ברירת מחדל. הרץ פקודה כדי להתקין את ה-CLI שלה בשימוש הראשון, ולאחר מכן התחבר כשתתבקש. Hermes הוא היוצא מן הכלל: שום דבר לא מותקן עבורו בשימוש הראשון, ובחירה בו מתקינה את Hermes Desktop, כפי ש-_אפליקציות שולחניות_ שלמטה מסביר.

### התקנה ועדכון של סוכנים

למעט Hermes, הסוכנים האלה משתמשים בהתקנה העצלה של mise: ההפעלה הראשונה מתקינה את ה-CLI, והפעלות מאוחרות יותר משתמשות בו שוב. mise גם בודק אם קיימת גרסה חדשה לסוכן מותקן לכל היותר פעם בארבע שעות, ממש לפני שהוא מופעל או ברקע בשורת ה-shell. אם העדכון הזה נכשל או שאתה לא מחובר, הגרסה המותקנת רצה. `omarchy update` מעדכן סוכנים מותקנים יחד עם שאר Omarchy, ו-`mup` מעדכן רק כלים המנוהלים על ידי mise.

המעדכן של סוכן עצמו, כמו `claude update`, `codex update`, או כפתור עדכון באפליקציה, לא מעדכן את ההתקנה המנוהלת על ידי mise. `codex update` נכשל, ו-`claude update` יכול לדווח על הצלחה תוך התקנת עותק נפרד ש-mise לא עוקב אחריו. אם אתה מעדיף להשתמש במתקין ובמעדכן המקוריים של סוכן, הוסף אותו ל-`disable_tools`; ראה [כלי CLI מותקנים מראש](18-development-tools.md#preinstalled-cli-tools).

כדי להתקין את כל הכלים העצלים המוגדרים לפני שתצטרך אותם, הרץ `mise install --include-lazy`. זה כולל גם את כלי ה-CLI האחרים של ברירת המחדל של Omarchy וגם את הסוכנים. ראה [כלי CLI מותקנים מראש](18-development-tools.md#preinstalled-cli-tools) להתקנת כלי בודד או לשימוש בהתקנה משלך.

`grok` מותקן דרך חבילת ה-`grok` הרשמית של mise, באותו אופן כמו `claude` ו-`codex`. הרץ `grok`, או בחר אותו תחת _Agent > Harness_. דלג על מתקין ה-`curl | bash` ב-x.ai. הנתיב הזה שם עותק שני ב-`~/.grok/bin`, מקדים אותו ב-`PATH`, ודורס את ה-wrapper של Omarchy.

`dsh` פותח את ממשק הדפדפן שלו ב-`127.0.0.1:3080`, כאשר ספריית ההפעלה היא סביבת העבודה של ברירת המחדל שלו. ממשק הדפדפן שלו לא מקבל הנחיית פתיחה, ולכן `omarchy agent prompt` פותח אותו כשההנחיה נמצאת בלוח שלך כדי שתדביק אותה. Omarchy מפעיל אותו עם הגדרת ההרשאות ללא אישור של DeepSeek. DeepSeek Harness מעלה יומני session ל-DeepSeek כשאתה משתמש ב-API הרשמי שלו למודלים; כבה זאת תחת _Settings > General > Upload Session Log_ בממשק הדפדפן שלו. גם משוב שאתה שולח לו מועלה יחד עם ה-session, אלא אם אתה מפעיל אותו עם `DSH_TELEMETRY_MODE=DISABLED`.

### סוכן ברירת המחדל

בחר את סוכן ברירת המחדל שלך עם `omarchy default agent <name>` או תחת _Agent > Harness_ בתפריט Omarchy (`Super + Space`). אם הסוכן עדיין לא מותקן, בחירה בו תתקין אותו תחילה. Omarchy טרייה תזמין אותך לבצע את הבחירה הזו עם התראה חד-פעמית.

בחירה ב-Claude מנסה גם להגדיר את תוסף הדפדפן שלו עבור Chromium, Chrome, Brave, Brave Origin ו-Edge. הגדרת התוסף חלה על כל המשתמשים ועלולה לבקש את סיסמת המערכת שלך; ביטול או כשל בהתקנת התוסף עדיין בוחרים ומפעילים את Claude. הפעל מחדש את הדפדפן, אפשר את התוסף אם תתבקש, והתחבר ל-Claude כדי לסיים את חיבורו. הרץ `/chrome` ב-Claude כדי לבדוק את החיבור. Firefox ו-Zen לא תומכים בתוסף הזה. אם Claude כבר היה ברירת המחדל שלך לפני שההגדרה הזו נוספה, בחר אותו שוב כדי להתקין את התוסף.

לאחר שבחרת, `Super + Shift + Ctrl + A` מפעיל את סוכן ברירת המחדל בחלון טרמינל ייעודי (או מציג את הבורר אם עדיין לא בחרת). אתה יכול גם להפעיל אותו ישירות למשימה עם `omarchy agent prompt "Review this project"`. Freebuff ו-DeepSeek Harness לא מקבלים הנחיית פתיחה, ולכן הם נפתחים במקום זאת כשההנחיה נמצאת בלוח שלך כדי שתדביק אותה. סוכנים שמופעלים כך רצים ללא השגחה במצבי אל-תעצור-כדי-לשאול שלהם, אז תהיה מוכן לכך שהם באמת יעשו דברים! ל-MiniMax Code אין מצב כזה עבור ה-sessions האינטראקטיביים שלו, ולכן הוא מבקש הרשאות כרגיל. ומכיוון שסוכנים מסרבים לזכור אמון עבור ספריית הבית שלך, הפעלות מ-`$HOME` מתחילות במקום זאת ב-`~/Work`.

יש גם קיצורי טרמינל: `a` מריץ את סוכן ברירת המחדל בתוך הטרמינל הנוכחי, בעוד ש-`c`, `cx` ו-`cy` מפעילים את OpenCode, Claude Code ו-Codex ישירות (שוב במצבי האישור האוטומטי שלהם). שינויי ערכת נושא מסתנכרנים גם לסוכנים: Claude Code, Pi, OpenCode ו-Hermes (לאחר ש-Omarchy התקין אותו) כולם עוקבים אחריך כשאתה מחליף את ערכת הנושא של Omarchy.

### הוראות הסוכן שלך

כללים אישיים לכל סוכן נכנסים ל-`~/.agents/AGENTS.md`, ליד ה-skills המשותפים ב-`~/.agents/skills`. פתח אותו תחת _Agent > Instructions_, שגם מקשר אותו לכל harness ששומר קובץ גלובלי משלו: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, ה-`~/.copilot/copilot-instructions.md` של Copilot, וכן הלאה. Crush ו-Amp קוראים את הקישור `~/.config/AGENTS.md`, בעוד ש-omp, Kimi ו-DeepSeek Harness קוראים את `~/.agents/AGENTS.md` ישירות. גם בחירת סוכן ברירת מחדל מקשרת אותו. קובץ הוראות שכבר היה לך הופך למשותף אם עדיין לא היה אחד; אחרת הוא נשמר ליד הקישור כ-`.bak`. הרץ `omarchy agent instructions` כדי לקשר מחדש לאחר התקנת סוכן נוסף.

### פאנל הסוכנים

בסרגל העליון יש סמל סוכנים. לפני שהגדרת סוכן, הפאנל שלו מדריך אותך בהתחברות ל-Claude, Codex או Grok, והראשון הופך לסוכן ברירת המחדל שלך. לאחר מכן, הפאנל שם כל מנוי בעמוד אחד: כל סוכן וחשבון עם התוכנית שלו, מד לכל אחת ממגבלות ה-session של 5 שעות והמגבלות השבועיות שלו יחד עם הזמן עד לאיפוס (רחף לקבלת האחוז המדויק), או היתרה הנותרת ששולמה מראש, מתחת לשורה שמסתובבת בין מה שהשתמשת בו בכל אלה, כמו טוקנים השבוע והמודל שבו השתמשת הכי הרבה. תחת _Make something_ הוא מציע הנחיות התחלה לערכת נושא, תוסף או אפליקציה חדשים שמוסרים את המשימה לסוכן ברירת המחדל שלך. אפליקציות נבנות באותו אופן שבו נבנות Hype, Monologue ו-Omacut של Omarchy עצמה, ב-C++ וב-Qt Quick, לפי ה-agent skill של omarchy-app, והקומפיילר וחלקי ה-Qt שהן צריכות מגיעים מותקנים. Claude Code, Codex, Grok, Kimi, Cursor ומכסת ה-Grok Bot שלו, GitHub Copilot, Muse, Antigravity, Kimchi ו-Devin מכוסים מהקופסה עם המגבלות שלהם, ו-Hermes, Mistral Vibe ו-Qwen Code מציגים את ה-sessions והטוקנים שלהם לאחר שהשתמשת בהם. גם תוכניות ומפתחות של ספקים שאתה משתמש בהם דרך pi, omp או opencode מופיעים: OpenCode Zen ו-Go, ה-Z.ai GLM Coding Plan, Ollama Cloud, ה-MiniMax Token Plan ו-Synthetic עם המגבלות שלהם; Fireworks, OpenRouter ו-DeepSeek עם היתרות ששולמו מראש שלהם; והמודלים שאתה מריץ על החומרה שלך תחת Local models. כל סוכן נספר פעם אחת, תחת מי שמחייב עליו, לא משנה דרך כמה harness-ים אתה מפעיל אותו.

לחיצה שמאלית על סמל הסרגל עבור הפאנל, לחיצה ימנית להפעלת סוכן ברירת המחדל שלך. רשומות השימוש שמאחוריו נוצרות מחדש כל 15 דקות על ידי `omarchy agent usage-update`, והפאנל יכול אפילו למזג שימוש מהמכונות האחרות שלך דרך תיקייה מסונכרנת. ראה את ה-README תחת `$OMARCHY_PATH/shell/plugins/agents/` להגדרות המלאות.

### כמה מנויים

אם אתה משלם על יותר מתוכנית Claude, Codex או Grok אחת — Max אישית ואחת לעבודה, למשל — Omarchy יכול להשאיר את כולן מחוברות ולעבור ביניהן. הוסף מנוי עם ה-+ בפאנל הסוכנים, שמדריך אותך בכך ממש שם, או עם `omarchy agent account add claude Work` (או `codex`, או `grok`). הוא מתקין את ה-CLI אם הוא חסר. החשבון הראשון של ספק מתחבר דרך הדפדפן הרגיל שלך, בדיוק במקום שבו ה-CLI תמיד מחפש. כל אחד אחריו מתחבר דרך חלון פרטי, כדי שהחשבון שהדפדפן שלך כבר מחובר אליו לא ייבחר בטעות; התחבר שם כחשבון שאתה מוסיף, וסגור תחילה כל חלון פרטי שכבר פתוח אצלך. לעולם אל תתנתק מה-CLI כדי לעשות זאת: התנתקות מבטלת את ההתחברות השמורה, והחשבון הזה יצטרך להתווסף שוב.

כדי להעתיק את התחברויות המנוי שלך למכונת Omarchy אחרת דרך SSH, הרץ `omarchy agent account copy user@laptop`. השולח מספק מקלט זמני כאשר ליעד אין אחד מותקן, כך שמכונות Omarchy ישנות יותר יכולות לקבל חשבונות בלי עדכון. מקלטים מותקנים מקבלים עדיפות. זה מעתיק את כל מנויי Claude, Codex ו-Grok; הוסף שמות ספקים כדי לבחור אותם, כמו ב-`omarchy agent account copy laptop claude`. שמות החשבונות ומזהי הפקודות תואמים את המקור, כולל חשבונות שכבר נמצאים ביעד. חשבונות יעד לא קשורים מקבלים סיומת מספרית אם שמותיהם מתנגשים, והגדרות, skills, תוספים והיסטוריית שיחות נשארים מקומיים לכל מכונה.

אישורי יעד קיימים נשמרים. חשבון מקור שכבר מחובר שם — שמו מסונכרן מבלי להחליף את אישוריו; חשבונות אחרים מתווספים לצדו. כדי להחליף אישורים שמורים עבור חשבונות תואמים, השתמש ב-`omarchy agent account copy --replace laptop claude` לאחר יציאה מה-sessions של אותו חשבון ביעד. יעד טרי מקבל גם את החשבון הפעיל ואת העדפות המעבר של המקור; יעד מבוסס שומר את שלו.

אישורים עוברים דרך SSH ונשמרים בקבצים פרטיים ביעד, אז העתק רק למכונות שאתה סומך עליהן. זו העתקה חד-פעמית, לא סנכרון מתמשך. טוקני רענון של Codex יכולים להיות מוחלפים על ידי מכונה אחרת, מה שמשאיר התחברות מועתקת הזקוקה לחידוש; התחברויות נפרדות נשארות הבחירה האמינה ביותר לשימוש בו-זמני בכמה מכונות. ראה [הנחיות אימות החשבון של Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

חשבון אחד לכל ספק פעיל, וכל session חדש מתחיל כמוהו: `cx`, `cy`, `claude`, `codex` או `grok` פשוטים, כל דבר שמופעל דרך `omarchy agent`, וסקריפטים או עורכים שמוצאים את ה-CLI ב-`PATH`. עבור עם `omarchy agent account use work` (וחזרה עם `omarchy agent account use main`), או בפאנל על ידי לחיצה על מספר של חשבון ולאחר מכן `Enter` (או לחיצה על כפתור ה-Use שלו). Sessions שכבר רצים נשארים עם החשבון שאיתו התחילו. היסטוריית שיחות, הגדרות, skills ותוספים משותפים בין חשבונות, כך ש-`claude --continue` באותה תיקייה ממשיך מהמקום שבו הפסקת בחשבון החדש.

עם יותר מחשבון אחד, הפאנל מציג את המגבלות של כל חשבון זה לצד זה, כאשר הפעיל מסומן. כברירת מחדל Omarchy מודיע לך כאשר החשבון הפעיל עובר 95% ממגבלה, ולחיצה על ההתראה מעבירה לחשבון עם הכי הרבה מרווח. רחף מעל שורת חשבון בפאנל ולחץ על Autoswitch שמופיע ליד Use (או לחץ `m`), או הרץ `omarchy agent account mode auto`, כדי שיעבור בעצמו במקום זאת; כשזה מופעל, Autoswitch תופס את מקומו של Use, ולחיצה עליו שוב חוזרת להתראות. הוסף מספר כדי לשנות את הסף, כמו ב-`omarchy agent account mode auto 90`. אם כל חשבון מעל הסף, תשמע על כך פעם אחת, יחד עם איזה חשבון מתפנה ראשון. כאשר חשבון פעיל נמצא בתוך 15 נקודות מהסף שלו (80% בברירת המחדל), המגבלות שלו נבדקות כל שלוש דקות במקום כל 15.

`omarchy agent account list` מציג כל חשבון ואת המגבלות האחרונות שלו, `omarchy agent account remove work` שוכח אחד, ו-`omarchy agent account rename primary Hey` משנה שם של אחד (או לחץ על שם חשבון בפאנל). הפקודות האלה עובדות על החשבונות של סוכן ברירת המחדל שלך; כדי להגיע לספק האחר, נקוב בשמו תחילה, כמו ב-`omarchy agent account use codex side`. ההתחברות שכבר הייתה לך ב-`~/.claude` או ב-`~/.codex` היא חשבון ה-_Main_ והיא נשארת במקומה. חשבון שלא נעשה בו שימוש במשך יותר מכשמונה שעות יכול להציג _Sign-in required_; לחץ עליו כדי לחבר את אותו חשבון שוב ממש בפאנל, או התחל session בו, מה שמרענן את ההתחברות מעצמו. שרתי MCP שהיו לך כאשר חשבון נוסף באים איתו, אבל אלה שאתה מוסיף מאוחר יותר עם `claude mcp add` מגיעים רק לחשבון שבו הוספת אותם. Claude Desktop וכלים המוגדרים עם נתיב מוחלט לקובץ בינארי של CLI לא עוקבים אחרי המעבר. `CLAUDE_CONFIG_DIR`, `CODEX_HOME` או `GROK_HOME` מפורשים מקבלים עדיפות על פני החשבון שנבחר.

### אבחון קריסות

Omarchy עוקב אחר systemd-coredump אחר קריסות תהליכים. כשמשהו עושה segfault, תקבל התראת "Process crashed" — לחץ עליה, והקריסה מועברת לסוכן ברירת המחדל שלך יחד עם ה-skill של Omarchy בשם diagnose-crash, שמדריך את הסוכן בביסוס העובדות מה-core dump ובהחלטה אם הקריסה שווה דיווח upstream. אתה יכול גם להריץ אותו ידנית מול כל PID מ-`coredumpctl list` עם `omarchy agent crash <pid>`.

המעקב מופעל כברירת מחדל. כבה אותו תחת _Trigger > Toggle > Crash Capture_ (או עם `omarchy toggle crash-capture`) וההתראות יפסיקו; `omarchy agent crash <pid>` עדיין עובד ידנית.

אפשר גם להשתיק קריסות תוכנית אחת בכל פעם, וזה מה שהאבחון מציע לך בסוף. `omarchy crash mute hyprland` מפסיק את ההתראות עבור התוכנית הזו בלבד, `omarchy crash mute hyprland off` מחזיר אותן, ו-`omarchy crash mute` כשלעצמו מפרט מה השתקת. הוא מקבל את נתיב הקובץ הבינארי באותה שמחה כמו את שמו, כך ש-`omarchy crash mute /usr/bin/hyprland` עושה את אותו הדבר. שם עם רווח בתוכו יש לצטט, כמו ב-`omarchy crash mute 'Some App'`. כל השאר עדיין מתריע, והתוכנית המושתקת עדיין קורסת — זה מסתיר את התזכורת, זה לא מתקן שום דבר.

### אפליקציות שולחניות

תפריט ה-_Install > AI_ נושא גם כמה אפליקציות AI גרפיות: אפליקציית שולחן העבודה של ChatGPT, אפליקציית שולחן העבודה של Claude (גרסת הבטא של Anthropic ל-Linux, עם לשוניות Chat, Cowork ו-Claude Code), Grok Bot לשיחה עם המודלים של xAI, Herdr Desktop, Hermes Desktop, OpenClaw, אפליקציית שולחן העבודה של Perplexity ו-T3 Code. Grok Bot היא אפליקציית הצ'אט לשולחן העבודה. סוכן הקידוד הוא פקודת ה-`grok`.

Hermes Desktop היא זו שכדאי להכיר, כי למכונה יש Hermes אחד, והוא של האפליקציה: Hermes מותקן תמיד רק דרך האפליקציה, ופקודת ה-`hermes` שסוכן ברירת המחדל מריץ היא של האפליקציה. בחירת Hermes כסוכן ברירת המחדל מתקינה אותו דבר שהערך _Install > AI_ מתקין: את החבילה, ו-runtime של Hermes תחת `~/.hermes` שמוגדר על ידי המתקין של Hermes עצמו, מה שלוקח כמה דקות בפעם הראשונה. ה-runtime הזה הוא ה-Hermes האחד שפקודת ה-`hermes` בטרמינל, סוכן ברירת המחדל והאפליקציה כולם משתמשים בו, והוא מעדכן את עצמו עם `hermes update` במקום לחכות לגרסה של Omarchy. התקנתו גם נותנת ל-Hermes את ערכת הנושא של Omarchy כ-skin בשם `omarchy`, שכל משטח של Hermes עוקב אחריו כשאתה מחליף ערכות נושא; בחר אחר תחת הגדרות ה-Appearance של Hermes או עם `/skin` אם אתה מעדיף שלא, ו-Omarchy ישאיר את הבחירה הזו לבד. הסרת האפליקציה תחת _Remove > AI_ סוגרת תחילה את Hermes, כולל ה-gateway, לוקחת איתה את ה-runtime הזה, ושומרת את הצ'אטים, הזיכרונות וה-skills ש-Hermes כתב לעצמו אלא אם אתה אומר לו אחרת: הוא שואל, כאשר ברירת המחדל היא לא, האם גם הנתונים האלה והגדרות החיבור שלך צריכים להיעלם.

חוויית שולחן העבודה של OpenClaw היא ה-Control UI שלו, שנפתח כאפליקציית web המגובה על ידי ה-gateway המקומי שלו. OpenClaw חי ב-`~/.openclaw` ומעדכן את עצמו: השתמש בכפתור "Update Gateway" של ה-Control UI או הרץ `openclaw update`, וה-gateway מופעל מחדש בגרסה החדשה. Omarchy בוחר רק את הגרסה שהתקנה טרייה מתחילה ממנה. הסרת OpenClaw תחת _Remove > AI_ לוקחת איתה את שירות ה-gateway ואת האפליקציה ולאחר מכן שואלת האם גם `~/.openclaw` צריך להיעלם, מכיוון שזה מחזיק את הצ'אטים והאישורים שלך לצד OpenClaw עצמו ו-runtime-ים של תוספים שהוא מוריד; ברירת המחדל שומרת אותו, והתקנת OpenClaw שוב מרימה אותו בחזרה.

Herdr Desktop היא אפליקציית שולחן העבודה של [Herdr](https://herdr.dev): מרחבים, לשוניות וחלוניות של טרמינלים וסוכני קידוד שממשיכים לרוץ בליבה שלו כשאתה סוגר את החלון. היא מגיעה מהמתקין של Herdr עצמו ולא מחבילה, כך שהיא חיה ב-`~/.local/share/herdr-app`, מביאה איתה את הליבה שלה ב-`~/.local/bin/herdr-core` כשעדיין אין לך אחת, ומעדכנת את שניהם בעצמה. היא יושבת לצד פקודת ה-`herdr` ש-Omarchy מספק ב-`Super + Ctrl + Return` ולא מחליפה אותה, ומקבלת את המקשים הישירים של אותה פקודה: `Alt + Return` ו-`Alt + Shift + Return` מחלקים חלונית כלפי מטה או ימינה, `Alt + Escape` סוגר אותה, `Ctrl + Alt + Arrow` עובר בין חלוניות, `Alt + 1..9` ו-`Alt + Left/Right` בוחרים לשונית, ו-`Alt + Up/Down` עוברים בין מרחבים. `Ctrl + 1..9` בוחר מרחב ו-`Alt + Shift + Up/Down` עובר בין סוכנים. מקשי הקידומת `Ctrl + Space` נשארים לטרמינל בלבד, מכיוון שהאפליקציה לא יכולה להחזיק מקש Ctrl פשוט עבור רצף. Omarchy כותב אותם ל-`~/.config/herdr-app/keys.json`, ו-`omarchy-refresh-herdr-app` מחזיר אותם. התקנתו בוחרת את ערכת הנושא של Omarchy של Herdr, שעוקבת מאז אחרי ערכת הנושא שלך ב-Omarchy. Herdr שומר ערכת נושא אחת למצב בהיר ואחת למצב כהה, כך שלאחר מעבר בין ערכת נושא כהה לבהירה של Omarchy, בחר שוב ב-Omarchy בבורר ערכות הנושא של Herdr עבור המצב האחר.

T3 Code רץ מגרסת ה-AppImage הרשמית שלו ב-`~/.local/share/t3code` ולא מחבילה, כך שהוא מעדכן את עצמו. התקנתו שואלת אם להתחיל בערוץ Stable או Nightly; עבור מאוחר יותר בהגדרות של T3 Code. השרשורים וההגדרות שלך חיים ב-`~/.t3`, והסרת T3 Code תחת _Remove > AI_ לוקחת אותם איתה.

### מודלים מקומיים

הרץ מודל פתוח במכונה שלך עבור סוכני הקידוד שלך. ההנחיות והקוד שלך נשארים במכונה; שום דבר שנשלח למודל לא עוזב אותה. התחל עם:

```bash
omarchy agent local use best
```

או, בפאנל הסוכנים בסרגל העליון, בחר + ולאחר מכן Local AI, שמופיע כאשר מודל מתאים למכונה זו. בפעם הראשונה, זה מתקין את Podman, שמריץ את המודלים, ובמכונת NVIDIA את ערכת הכלים ל-containers של NVIDIA, שנותנת להם את ה-GPU. לאחר מכן Omarchy בוחר את המודל המומלץ למכונה זו, מוריד אותו ומפעיל אותו. צפה להורדה של עשרות GB ולכך שרוב זיכרון המכונה יהיה בשימוש בזמן שהמודל רץ: Flash Next משתמש בכ-100 GiB עם ההקשר המלא שלו של 256K. אם מודלים אחרים מחזיקים את הזיכרון שהוא צריך, הוא מוגדר כמופסק, מוכן להתחיל ברגע שתעצור אחד. המודל נעצר בהתנתקות; עצור אותו בעצמך כאשר אתה צריך את הזיכרון למשהו אחר.

`omarchy agent local list` מציג את האפשרויות ומסביר מדוע חלקן לא מתאימות. כדי להגדיר אחד נוסף, הרץ `omarchy agent local use <recipe>`. כיום, `qwen3.8-flash-next-gufo` ו-`qwen3.8-27b-gufo` זמינים למכונות Strix Halo בנפח 128 GB; ה-27B לוקח כ-40 GiB, כך שהוא משאיר מקום לעבודה אחרת. מתכונים והמלצות חדשים מגיעים עם `omarchy update`, דרך החבילה.

כל מודל שאתה מגדיר מקבל שורה משלו בפאנל הסוכנים, ליד המנויים שלך: play כדי להפעיל אותו, pause כדי לעצור אותו ולפנות את הזיכרון שלו, וכפתור הטרמינל כדי לפתוח את הסוכן שלך עליו. כמה יכולים לרוץ בבת אחת כאשר הם מתאימים בזיכרון יחד; אם אחד לא מתאים, Omarchy אומר איזה מודל רץ לעצור. גרור שורות כדי לסדר אותן מחדש, ולחץ Delete על שורה נבחרת כדי להסיר מודל ואת ההורדה שלו.

משורת הפקודה, `omarchy agent local start <recipe>` ו-`omarchy agent local stop <recipe>` עושים את אותו הדבר, `omarchy agent local status` מציג כל מודל, ו-`omarchy agent --local` פותח את סוכן ברירת המחדל שלך על המודל האחרון שהפעלת (pi אם סוכן ברירת המחדל שלך לא יכול להשתמש במודל מקומי). גם כל לקוח תואם OpenAI יכול להתחבר: `status` מציג את הכתובת של כל מודל (הראשון הוא `http://127.0.0.1:11435/v1`), שם המתכון הוא המודל, והמפתח נמצא ב-`~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` מוחק מודל ואת ההורדות שאף מודל אחר לא משתמש בהן.

Runtime-ים של צד שלישי מסומנים עם המוציא לאור שלהם. Omarchy מריץ כל מודל ללא גישה לרשת.

### מודלי LLM מקומיים

Omarchy ממליץ על שתי דרכים להרצת מודלי LLM מקומיים: LM Studio ו-Ollama. LM Studio מספק ממשק GUI למציאת מודלים פתוחים, התקנתם והרצתם. זו דרך מעולה להתחיל בקלות. Ollama מציע CLI לעשות זאת באופן דומה. אבל אם אתה חדש במודלים מקומיים, אני הייתי מתחיל עם LM Studio. אתה יכול להתקין כל אחד מהם תחת _Install > AI_ בתפריט Omarchy.

### ה-Skill של Omarchy

Skills של סוכנים עוזרים ל-AI להשתמש בכלים ספציפיים בדרך ספציפית, ו-Omarchy מגיע עם skill של ברירת מחדל להתאמת המערכת. כמו לכוונן את קונפיגורציית ה-Hyprland שלך, להתאים את הסרגל, או אפילו ליצור ערכת נושא חדשה מאפס. הוא מקושר בסימפתיה לתיקיות ה-skills של Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` וכל `~/.hermes/profiles/*/skills`), והמיקום הגנרי `~/.agents/skills`, כך שרוב ה-harness-ים קולטים אותו אוטומטית.

אבל אתה צריך להתייחס ל-skill הזה כניסיוני. מודלים שונים ישתמשו בו להשפעה שונה. הכי טוב לרוץ תחילה במצב תכנון, כך שיהיה לך מושג מה הסוכן היה רוצה לשנות. ואז תהיה מוכן לבטל שינויים או אפילו להפעיל `omarchy reinstall configs`, אם הסוכן עושה בלגן מהכל.
