# AI

Omarchy כוללת משגרים לסוכני הקידוד שלמטה מבלי לבחור עבורך אחד כברירת מחדל. הרץ פקודה כדי להתקין את ה-CLI שלה בשימוש הראשון, ואז בצע אימות כאשר תתבקש לכך. Hermes ו-OpenClaw הם היוצאים מן הכלל: שום דבר אינו מותקן עבורם דרך mise, ובחירה באחד מהם מתקינה עותק משלו שמעדכן את עצמו, כפי ש-_אפליקציות שולחניות_ להלן מסביר.

### התקנה ועדכון של סוכנים

למעט Hermes ו-OpenClaw, סוכנים אלה משתמשים בהתקנה העצלה של mise: ההשקה הראשונה מתקינה את ה-CLI, והשקות מאוחרות יותר עושות בו שימוש חוזר. mise גם בודק אם יצאה גרסה חדשה לסוכן מותקן לכל היותר פעם בארבע שעות, ממש לפני שהוא מתחיל או ברקע בהנחיית shell. אם העדכון הזה נכשל או שאתה במצב לא מקוון, הגרסה המותקנת רצה. `omarchy update` מעדכן סוכנים מותקנים יחד עם שאר Omarchy, ו-`mup` מעדכן רק כלים המנוהלים על ידי mise.

המעדכן של סוכן עצמו, כגון `claude update`, `codex update` או כפתור עדכון באפליקציה, אינו מעדכן את ההתקנה המנוהלת על ידי mise. `codex update` נכשל, ו-`claude update` יכול לדווח על הצלחה תוך התקנת עותק נפרד ש-mise אינו עוקב אחריו. אם אתה מעדיף להשתמש במתקין ובמעדכן המקוריים של סוכן, הוסף אותו אל `disable_tools`; ראה [כלי CLI מותקנים מראש](18-development-tools.md#preinstalled-cli-tools).

כדי להתקין את כל הכלים העצלים המוגדרים לפני שתזדקק להם, הרץ `mise install --include-lazy`. זה כולל את כלי ה-CLI האחרים של Omarchy המוגדרים כברירת מחדל וגם את הסוכנים. ראה [כלי CLI מותקנים מראש](18-development-tools.md#preinstalled-cli-tools) להתקנת כלי בודד או לשימוש בהתקנה משלך.

`grok` מותקן דרך חבילת ה-`grok` של mise עצמה, באותו אופן כמו `claude` ו-`codex`. הרץ `grok`, או בחר אותו תחת _Agent > Harness_. דלג על מתקין ה-`curl | bash` שב-x.ai. הנתיב הזה שם עותק שני ב-`~/.grok/bin`, מקדים אותו ב-`PATH` ודורס את המעטפת של Omarchy.

`dsh` פותח את ממשק הדפדפן שלו ב-`127.0.0.1:3080`, כשספריית ההשקה היא סביבת העבודה המוגדרת כברירת מחדל שלו. ממשק הדפדפן שלו אינו מקבל הנחיית התחלה, כך ש-`omarchy agent prompt` פותח אותו כשההנחיה נמצאת בלוח ההעתקה שלך כדי שתדביק אותה. Omarchy משיקה אותו עם ערכת ההרשאות ללא-אישור של DeepSeek. DeepSeek Harness מעלה יומני מושב אל DeepSeek כאשר אתה משתמש ב-API הרשמי של המודלים שלו; כבה זאת תחת _Settings > General > Upload Session Log_ בממשק הדפדפן שלו. משוב שאתה שולח אליו מועלה גם הוא עם המושב, אלא אם תשיק אותו עם `DSH_TELEMETRY_MODE=DISABLED`.

### סוכן ברירת המחדל

בחר את סוכן ברירת המחדל שלך עם `omarchy default agent <name>` או תחת _Agent > Harness_ בתפריט Omarchy (`Super + Space`). אם הסוכן עדיין לא מותקן, בחירה בו תתקין אותו תחילה, והוא גם מקבל משגר משלו במשגר האפליקציות, ליד Agent. מערכת Omarchy טרייה תזמין אותך לבחור בחירה זו באמצעות התראה חד-פעמית.

בחירת Claude גם מנסה להגדיר את תוסף הדפדפן שלו עבור Chromium, Chrome, Brave, Brave Origin ו-Edge. הגדרת התוסף חלה על כל המשתמשים ועלולה לבקש את סיסמת המערכת שלך; ביטול או התקנת תוסף שנכשלה עדיין בוחרים ומשיקים את Claude. הפעל מחדש את הדפדפן שלך, הפעל את התוסף אם תתבקש, והתחבר אל Claude כדי לסיים לחבר אותו. הרץ `/chrome` ב-Claude כדי לבדוק את החיבור. Firefox ו-Zen אינם תומכים בתוסף זה. אם Claude כבר היה סוכן ברירת המחדל שלך לפני שהגדרה זו נוספה, בחר אותו שוב כדי להתקין את התוסף.

לאחר שבחרת, `Super + Shift + Ctrl + A` משיק את סוכן ברירת המחדל בחלון טרמינל ייעודי (או מעלה את הבורר אם עדיין לא בחרת). אתה יכול גם להשיק אותו ישירות אל תוך משימה עם `omarchy agent prompt "Review this project"`. Freebuff ו-DeepSeek Harness אינם מקבלים הנחיית התחלה, כך שהם נפתחים כשההנחיה נמצאת בלוח ההעתקה שלך כדי שתדביק אותה במקום זאת. סוכנים המושקים כך רצים ללא השגחה במצבי אל-תעצור-כדי-לשאול שלהם, אז היה מוכן לכך שהם באמת יעשו דברים! ל-MiniMax Code אין מצב כזה למושבים האינטראקטיביים שלו, כך שהוא מבקש הרשאות כרגיל. ומכיוון שסוכנים מסרבים לזכור אמון עבור ספריית הבית שלך, השקות מתוך `$HOME` מתחילות במקום זאת ב-`~/Work`.

יש גם קיצורי דרך בטרמינל: `a` מריץ את סוכן ברירת המחדל באופן מוטמע בטרמינל הנוכחי, בעוד `c`, `cx` ו-`cy` משיקים את OpenCode, Claude Code ו-Codex ישירות (שוב במצבי האישור-האוטומטי שלהם). שינויי ערכת נושא מסתנכרנים גם אל הסוכנים: Claude Code, Pi, OpenCode ו-Hermes (לאחר ש-Omarchy התקינה אותו) כולם עוקבים אחריך כאשר אתה מחליף את ערכת הנושא של Omarchy.

### הוראות הסוכן שלך

כללים אישיים עבור כל סוכן נמצאים ב-`~/.agents/AGENTS.md`, ליד המיומנויות המשותפות שב-`~/.agents/skills`. פתח אותו תחת _Agent > Instructions_, שגם מקשר אותו אל כל harness ששומר קובץ גלובלי משלו: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, ה-`~/.copilot/copilot-instructions.md` של Copilot, וכן הלאה. Crush ו-Amp קוראים את הקישור `~/.config/AGENTS.md`, בעוד omp, Kimi ו-DeepSeek Harness קוראים את `~/.agents/AGENTS.md` ישירות. בחירת סוכן ברירת מחדל מקשרת גם אותו. קובץ הוראות שכבר היה לך הופך לקובץ המשותף אם עדיין לא היה כזה; אחרת הוא נשמר ליד הקישור כ-`.bak`. הרץ `omarchy agent instructions` כדי לקשר מחדש לאחר התקנת סוכן נוסף.

### פאנל הסוכנים

בשורה העליונה יש אייקון סוכנים. לפני שהגדרת סוכן, הפאנל שלו מדריך אותך בהתחברות אל Claude, Codex או Grok, והראשון הופך לסוכן ברירת המחדל שלך. לאחר מכן, הפאנל שם כל מנוי בעמוד אחד: כל סוכן וחשבון עם התוכנית שלו, מד לכל אחת ממגבלות המושב בנות 5 השעות והמגבלות השבועיות שלו יחד עם הזמן עד לאיפוסה (רחף לקבלת האחוז המדויק), או יתרת התשלום מראש שנותרה, תחת שורה המתחלפת בין מה שהשתמשת בו בכולם, כגון טוקנים השבוע והמודל שהשתמשת בו הכי הרבה. תחת _Make something cool_ הוא מציע הנחיות התחלה לערכת נושא, תוסף, אפליקציה או משחק חדשים שמעבירים את המשימה לסוכן ברירת המחדל שלך. אפליקציות נבנות באותו אופן שבו בנויות Hype, Monologue ו-Omacut של Omarchy עצמה, ב-C++ וב-Qt Quick, לפי מיומנות הסוכן omarchy-make-app, והמהדר ורכיבי ה-Qt שהן צריכות מגיעים מותקנים. משחקים הם עמוד three.js יחיד ב-`~/Games/vibes`, לפי מיומנות הסוכן omarchy-make-game, וכולם נפתחים ממשגר Game Vibes יחיד בערכת הנושא הנוכחית; הם טוענים את three.js מהאינטרנט, כך שהם צריכים חיבור כדי להתחיל. Claude Code, Codex, Grok, Kimi, Cursor והקצאת ה-Grok Bot שלו, GitHub Copilot, Muse, Antigravity ו-Devin מכוסים כבר מהקופסה עם המגבלות שלהם, Kimchi עם התוכנית שלו, הקרדיטים ששולמו מראש ותקציבי ההוצאה שלו, ו-Hermes, Mistral Vibe ו-Qwen Code מציגים את המושבים והטוקנים שלהם לאחר שהשתמשת בהם. גם תוכניות ומפתחות של ספקים שאתה משתמש בהם דרך pi, omp או opencode מופיעים: OpenCode Zen ו-Go, ה-Z.ai GLM Coding Plan, Ollama Cloud, ה-MiniMax Token Plan ו-Synthetic עם המגבלות שלהם; OpenRouter ו-DeepSeek עם יתרות התשלום מראש שלהם; Fireworks עם ההוצאה שלו במהלך 30 הימים האחרונים. גם טוקנים ממודלים שאתה מריץ על החומרה שלך נספרים בסיכומים; למודלים עצמם יש פאנל משלהם, המתואר תחת [מודלים מקומיים](#local-models). כל סוכן נספר פעם אחת, תחת מי שמחייב עליו, לא משנה דרך כמה harnesses אתה מפעיל אותו.

לחיצה שמאלית על אייקון השורה או לחיצה על `Super + Ctrl + X` פותחות את הפאנל, לחיצה ימנית משיקה את סוכן ברירת המחדל שלך, ולחיצה אמצעית מרעננת. רשומות השימוש שמאחוריו נוצרות מחדש כל 15 דקות על ידי `omarchy agent usage update`, והפאנל יכול אפילו למזג שימוש מהמכונות האחרות שלך באמצעות תיקייה מסונכרנת. ראה את ה-README תחת `$OMARCHY_PATH/shell/plugins/agents/` לקבלת ההגדרות המלאות.

### מספר מנויים

אם אתה משלם על יותר מתוכנית אחת של Claude, Codex או Grok — לדוגמה תוכנית Max אישית ואחת של עבודה — Omarchy יכולה להשאיר את כולן מחוברות ולעבור ביניהן. הוסף מנוי באמצעות ה-+ שבפאנל הסוכנים, שמדריך אותך בכך ממש שם, או באמצעות `omarchy agent account add claude Work` (או `codex`, או `grok`). הוא מתקין את ה-CLI אם הוא חסר. החשבון הראשון של ספק מתחבר דרך הדפדפן הרגיל שלך, בדיוק במקום שבו ה-CLI תמיד מחפש. כל חשבון שלאחר מכן מתחבר דרך חלון פרטי, כך שהחשבון שהדפדפן שלך כבר מחובר אליו לא ייבחר בטעות; התחבר שם בתור החשבון שאתה מוסיף, וסגור תחילה כל חלון פרטי שכבר פתוח אצלך. לעולם אל תתנתק מה-CLI כדי לעשות זאת: התנתקות מבטלת את ההתחברות השמורה, ויהיה צורך להוסיף את החשבון הזה שוב.

כדי להעתיק את חיבורי המנויים שלך למכונת Omarchy אחרת דרך SSH, הרץ `omarchy agent account copy user@laptop`. השולח מספק מקלט זמני כאשר ביעד אין אחד מותקן, כך שמכונות Omarchy ישנות יותר יכולות לקבל חשבונות ללא עדכון. מקלטים מותקנים מקבלים עדיפות. פעולה זו מעתיקה את כל מנויי Claude, Codex ו-Grok; הוסף שמות ספקים כדי לבחור בהם, כמו ב-`omarchy agent account copy laptop claude`. שמות חשבונות ומזהי פקודות תואמים למקור, כולל חשבונות שכבר קיימים ביעד. חשבונות יעד לא קשורים מקבלים סיומת מספרית אם שמותיהם מתנגשים, והגדרות, מיומנויות, תוספים והיסטוריית שיחות נשארים מקומיים בכל מכונה.

אישורי יעד קיימים נשמרים. שם של חשבון מקור שכבר מחובר שם מסונכרן מבלי להחליף את האישורים שלו; חשבונות אחרים נוספים לצידו. כדי להחליף אישורים שמורים עבור חשבונות תואמים, השתמש ב-`omarchy agent account copy --replace laptop claude` לאחר שיצאת מהמושבים של אותו חשבון ביעד. יעד טרי מקבל גם את החשבון הפעיל והעדפות ההחלפה של המקור; יעד מבוסס שומר על שלו.

אישורים עוברים דרך SSH ומאוחסנים בקבצים פרטיים ביעד, כך שהעתק רק למכונות שאתה בוטח בהן. זהו העתקה חד-פעמית, לא סנכרון מתמשך. אסימוני רענון של Codex יכולים להתחלף על ידי מכונה אחרת, מה שמותיר חיבור מועתק הזקוק לחידוש; חיבורים נפרדים נשארים הבחירה האמינה ביותר לשימוש בו-זמני בכמה מכונות. ראה [הנחיות אימות החשבון של Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

חשבון אחד לכל ספק פעיל, וכל מושב חדש מתחיל כמוהו: `cx`, `cy`, `claude`, `codex` או `grok` רגילים, כל דבר המושק דרך `omarchy agent`, וסקריפטים או עורכים שמוצאים את ה-CLI על `PATH`. החלף באמצעות `omarchy agent account use work` (ובחזרה באמצעות `omarchy agent account use main`), או בפאנל על ידי לחיצה על מספרו של חשבון ולאחר מכן על `Enter` (או לחיצה על כפתור ה-Use שלו). גם מושבי Claude רצים מתחלפים, החל מההודעה הבאה שלהם: כל מושב Claude רץ ב-`~/.claude`, שתמיד מחזיקה את החיבור של החשבון הפעיל. מושב Claude שהתחיל בתיקייה של חשבון עצמו על ידי Omarchy ישנה יותר מחזיק את החיבור הזה עד שהוא יוצא, כך שההחלפה מציינת את המושבים האלה ומסתיימת מעצמה לאחר שהם נעלמים. מושבי Codex ו-Grok רצים נשארים בחשבון שאיתו התחילו. היסטוריית שיחות, הגדרות, מיומנויות ותוספים משותפים בין חשבונות, כך ש-`claude --continue` באותה תיקייה ממשיך מהמקום שהפסקת בו בחשבון החדש.

עם יותר מחשבון אחד, הפאנל מציג את המגבלות של כל חשבון זו לצד זו, כשזו הפעילה מסומנת. כברירת מחדל Omarchy מודיעה לך כאשר החשבון הפעיל עובר 95% ממגבלה, ולחיצה על ההתראה עוברת לחשבון עם מרווח הראש הגדול ביותר. רחף מעל שורה של חשבון בפאנל ולחץ על ה-Autoswitch שמופיע ליד Use (או לחץ `m`), או הרץ `omarchy agent account mode auto`, כדי שהוא יתחלף מעצמו במקום זאת; בזמן שזה מופעל, Autoswitch תופס את מקומו של Use, ולחיצה עליו שוב מחזירה להתראה. הוסף מספר כדי לשנות את הסף, כמו ב-`omarchy agent account mode auto 90`. אם כל חשבון נמצא מעל הסף, תשמע על כך פעם אחת, יחד עם איזה חשבון מתפנה ראשון. בזמן שחשבון פעיל נמצא בתוך 15 נקודות מהסף שלו (80% בברירת המחדל), המגבלות שלו נבדקות כל שלוש דקות ולא כל 15.

`omarchy agent account list` מציג כל חשבון ואת המגבלות האחרונות שלו, `omarchy agent account remove work` שוכח אחד, ו-`omarchy agent account rename primary Hey` משנה שם של אחד (או לחץ על שמו של חשבון בפאנל). פקודות אלה פועלות על החשבונות של סוכן ברירת המחדל שלך; כדי להגיע לספק האחר, ציין אותו תחילה, כמו ב-`omarchy agent account use codex side`. החיבור שכבר היה לך ב-`~/.claude` או ב-`~/.codex` הוא חשבון ה-_Main_. זה של Codex נשאר היכן שהוא נמצא; זה של Claude ממתין בתיקייה משלו בזמן שחשבון אחר פעיל. חשבון שנותר ללא שימוש במשך יותר מכשמונה שעות יכול להציג _Sign-in required_; לחץ עליו כדי לחבר את החשבון הזה שוב ממש בפאנל, או החלף אליו והתחל מושב, מה שמרענן את החיבור מעצמו. שרתי MCP שאתה מוסיף באמצעות `claude mcp add` מגיעים לכל חשבון Claude, מכיוון שכולם רצים ב-`~/.claude`; עבור Codex ו-Grok, שרתים שהיו לך כאשר חשבון נוסף מגיעים יחד איתו, אך שרתים מאוחרים יותר מגיעים רק לחשבון שבו הוספת אותם. Claude Desktop שומר חיבור משלו, וכלי Codex או Grok שהוגדרו עם נתיב מוחלט לבינארי של CLI אינם עוקבים אחר ההחלפה. `CLAUDE_CONFIG_DIR`, `CODEX_HOME` או `GROK_HOME` מפורשים מקבלים עדיפות על פני החשבון הנבחר.

### אבחון קריסות

Omarchy עוקבת אחר systemd-coredump אחר קריסות של תהליכים. לאחר שבחרת סוכן ברירת מחדל, כל תוכנית שלך שמבצעת dump לליבה מביאה התראה של "Process crashed" — לחץ עליה, והקריסה נמסרת לסוכן ברירת המחדל שלך יחד עם מיומנות omarchy-diagnose-crash של Omarchy, שמדריכה את הסוכן בביסוס העובדות מתוך ה-core dump ובהחלטה האם הקריסה שווה דיווח במעלה הזרם. אתה יכול גם להפעיל אותה ידנית כנגד כל PID מתוך `coredumpctl list` באמצעות `omarchy agent crash <pid>`.

המעקב מופעל כברירת מחדל. כבה אותו תחת _Trigger > Toggle > Crash Capture Off_ (או באמצעות `omarchy toggle crash-capture`) וההתראות ייפסקו; `omarchy agent crash <pid>` עדיין עובד ידנית.

ניתן גם להשתיק קריסות תוכנית אחת בכל פעם, וזה מה שהאבחון מציע לך בסוף. `omarchy crash mute hyprland` עוצר את ההתראות עבור אותה תוכנית בלבד, `omarchy crash mute hyprland off` מחזיר אותן, ו-`omarchy crash mute` בפני עצמו מפרט מה השתקת. הוא מקבל נתיב של בינארי באותה שמחה כמו את שמו, כך ש-`omarchy crash mute /usr/bin/hyprland` עושה את אותו דבר. הקף במרכאות שם שיש בו רווח, כמו ב-`omarchy crash mute 'Some App'`. כל השאר עדיין מתריעים, והתוכנית המושתקת עדיין קורסת — זה מסתיר את התזכורת, זה לא מתקן שום דבר.

### אפליקציות שולחניות

תפריט _Install > AI_ נושא גם כמה אפליקציות AI גרפיות: Amp Desktop, Antigravity Desktop, אפליקציית שולחן העבודה של ChatGPT, אפליקציית שולחן העבודה של Claude (הבטא ל-Linux של Anthropic, עם לשוניות Chat, Cowork ו-Claude Code), Grok Bot לשיחה עם המודלים של xAI, Herdr Desktop, Hermes Desktop, OpenClaw, אפליקציית שולחן העבודה של Perplexity ו-T3 Code. Grok Bot היא אפליקציית הצ'אט לשולחן העבודה. סוכן הקידוד הוא פקודת ה-`grok`.

Hermes Desktop היא זו שכדאי להכיר, מכיוון שלמכונה יש Hermes אחד, והוא של האפליקציה: Hermes מותקן תמיד רק דרך האפליקציה, ופקודת ה-`hermes` שסוכן ברירת המחדל מריץ היא של האפליקציה. בחירת Hermes כסוכן ברירת המחדל מתקינה את אותו דבר שערך ה-_Install > AI_ מתקין: החבילה, וסביבת ריצה של Hermes תחת `~/.hermes` שהמתקין של Hermes עצמו הגדיר, מה שלוקח כמה דקות בפעם הראשונה. סביבת הריצה הזו היא ה-Hermes היחיד שפקודת ה-`hermes` בטרמינל, סוכן ברירת המחדל והאפליקציה כולם משתמשים בו, והיא מעדכנת את עצמה באמצעות `hermes update` במקום לחכות לגרסה של Omarchy. התקנתה גם נותנת ל-Hermes את ערכת הנושא של Omarchy כמעטפת בשם `omarchy`, שכל פני השטח של Hermes עוקבים אחריה כאשר אתה מחליף ערכות נושא; בחר אחרת תחת הגדרות ה-Appearance של Hermes או באמצעות `/skin` אם אתה מעדיף שלא תעשה זאת, ו-Omarchy משאירה את הבחירה הזו בשקט. הסרת האפליקציה תחת _Remove > AI_ סוגרת תחילה את Hermes, כולל ה-gateway, לוקחת את סביבת הריצה הזו איתה, ושומרת את הצ'אטים, הזיכרונות והמיומנויות ש-Hermes כתב לעצמו אלא אם תגיד לה אחרת: היא שואלת, עם ברירת מחדל של לא, האם גם הנתונים האלה והגדרות החיבור שלך צריכים להיעלם.

חוויית שולחן העבודה של OpenClaw היא ה-Control UI שלו, שנפתח כאפליקציית רשת המגובה על ידי ה-gateway המקומי שלו עצמו. OpenClaw חי ב-`~/.openclaw` ומעדכן את עצמו: השתמש בכפתור "Update Gateway" של ה-Control UI או הרץ `openclaw update`, וה-gateway מתחיל מחדש בגרסה החדשה. Omarchy בוחרת רק את הגרסה שהתקנה טרייה מתחילה ממנה. OpenClaw יכול להיות גם סוכן ברירת המחדל שלך: בחירתו תחת _Agent > Harness_ מגדירה את אותו עותק ב-`~/.openclaw`, והסוכן פותח את ממשק הטרמינל של OpenClaw המחובר ל-gateway שלו. הסרת OpenClaw תחת _Remove > AI_ לוקחת איתה את שירות ה-gateway ואת האפליקציה ולאחר מכן שואלת האם גם `~/.openclaw` צריך להיעלם, מכיוון שהוא מחזיק את הצ'אטים והאישורים שלך לצד OpenClaw עצמו וסביבות הריצה של התוספים שהוא מוריד; ברירת המחדל היא לשמור אותו, והתקנת OpenClaw שוב תבחר אותו בחזרה.

Herdr Desktop היא אפליקציית שולחן העבודה של [Herdr](https://herdr.dev): מרחבים, לשוניות וחלוניות של טרמינלים וסוכני קידוד שממשיכים לרוץ בליבה שלה כאשר אתה סוגר את החלון. היא מגיעה מהמתקין של Herdr עצמו ולא מחבילה, כך שהיא חיה ב-`~/.local/share/herdr-app`, מביאה איתה את הליבה שלה ב-`~/.local/bin/herdr-core` כאשר עדיין אין לך אחת, ומעדכנת את עצמה ואותה. היא יושבת לצד פקודת ה-`herdr` ש-Omarchy מספקת ב-`Super + Ctrl + Return` במקום להחליף אותה, ומקבלת את המקשים הישירים של אותה פקודה: `Alt + Return` ו-`Alt + Shift + Return` מפצלים חלונית כלפי מטה או ימינה, `Alt + Escape` סוגר אותה, `Ctrl + Alt + Arrow` נע בין חלוניות, `Alt + 1..9` ו-`Alt + Left/Right` בוחרים לשונית, ו-`Alt + Up/Down` נעים בין מרחבים. `Ctrl + 1..9` בוחר מרחב ו-`Alt + Shift + Up/Down` עוברים בין סוכנים. מקשי הקידומת של `Ctrl + Space` נשארים לטרמינל בלבד, מכיוון שהאפליקציה אינה יכולה להחזיק מקש Ctrl רגיל עבור רצף. Omarchy כותבת את אלה אל `~/.config/herdr-app/keys.json`, ו-`omarchy-refresh-herdr-app` מחזיר אותם. התקנתה בוחרת את ערכת הנושא Omarchy של Herdr, שעוקבת מאז אחר ערכת הנושא של Omarchy שלך. Herdr שומרת ערכת נושא אחת למצב בהיר ואחת למצב כהה, כך שלאחר מעבר בין ערכת נושא כהה לבהירה של Omarchy, בחר שוב ב-Omarchy בבוחר ערכות הנושא של Herdr עבור המצב האחר.

T3 Code רץ מגרסת ה-AppImage הרשמית שלו ב-`~/.local/share/t3code` ולא מחבילה, כך שהוא מעדכן את עצמו. התקנתו שואלת האם להתחיל בערוץ Stable או Nightly; החלף מאוחר יותר בהגדרות של T3 Code. השרשורים וההגדרות שלך חיים ב-`~/.t3`, והסרת T3 Code תחת _Remove > AI_ לוקחת אותם איתה.

### מודלים מקומיים

הרץ מודל פתוח במכונה שלך עבור סוכני הקידוד שלך. ההנחיות והקוד שלך נשארים במכונה; שום דבר שנשלח למודל לא עוזב אותה. התחל עם:

```bash
omarchy models use best text
```

זה מגדיר את מודל הטקסט הטוב ביותר עבור מכונה זו, הסוג שבו הסוכנים שלך משתמשים. למודלי תמונה, וידאו ומוזיקה יש מודל טוב ביותר משלהם: `omarchy models use best image`, `video` או `music`. הרץ `omarchy models use best` כדי לראות את הבחירה של כל סוג עבור מכונה זו.

או פתח את פאנל המודלים המקומיים מאייקון הנצנוצים שלו בשורה העליונה, ליד אייקון הסוכנים, או באמצעות Super + Ctrl + Alt + X, ובחר ב-+. האייקון מופיע כאשר מודל מתאים למכונה זו. Podman, שמריץ את המודלים, מגיע עם Omarchy, וכך גם ערכת כלי המכולות של NVIDIA במכונת NVIDIA, שנותנת להם את ה-GPU; אם אחד מהם חסר, ההגדרה הראשונה מתקינה אותו. לאחר מכן Omarchy בוחרת את המודל המומלץ עבור מכונה זו, מורידה אותו ומתחילה אותו. צפה להורדה של עשרות GB ולכך שרוב זיכרון המכונה יהיה בשימוש בזמן שהמודל רץ: Flash Next משתמש בכ-100 GiB עם ההקשר המלא שלו בגודל 256K. אם מודלים אחרים מחזיקים את הזיכרון שהוא צריך, הוא מוגדר במצב מופסק, מוכן להתחיל לאחר שתעצור אחד מהם. המודל עוצר עם ההתנתקות; עצור אותו בעצמך כאשר אתה צריך את הזיכרון למשהו אחר.

`omarchy models list` מציג את האפשרויות ומסביר מדוע חלק מהן אינן מתאימות. כדי להגדיר אחד אחר, הרץ `omarchy models use <recipe>`. כיום, `qwen3.8-flash-next-gufo` ו-`qwen3.8-27b-gufo` זמינים עבור מכונות Strix Halo בגודל 128 GB; ה-27B לוקח כ-40 GiB, כך שהוא משאיר מקום לעבודה אחרת. במחשב נייד בגודל 64 GB עם ה-Arc B390 של Intel, `qwen3.6-35b-a3b-llamacpp` רץ בכ-30 GiB. מתכונים והמלצות חדשים מגיעים עם `omarchy update`, דרך החבילה.

כל מודל שאתה מגדיר מקבל שורה משלו בפאנל המודלים המקומיים: הפעל כדי להתחיל אותו, השהה כדי לעצור אותו ולפנות את הזיכרון שלו, וכפתור הטרמינל כדי לפתוח את הסוכן שלך עליו. לרוחב החלק העליון, סרגל מציג כיצד זיכרון המכונה מתחלק בין Omarchy עצמה (המערכת והאפליקציות שלך), כל מודל רץ, ומה פנוי. הצבע על מודל מופסק והסרגל מציג האם הוא מתאים, או בכמה הוא חסר. כמה מודלים יכולים לרוץ בבת אחת כאשר הם מתאימים יחד בזיכרון; אם אחד אינו מתאים, Omarchy מציינת איזה מודל רץ לעצור. גרור שורות לפי הלוגו שלהן כדי לסדר אותן מחדש, ולחץ על Delete בשורה נבחרת כדי להסיר מודל ואת ההורדה שלו.

כל מודל קידוד שאתה מגדיר מקבל גם רשומה משלו במשגר האפליקציות, תחת שמו של המודל ועם הלוגו של היצרן שלו, באותו אופן שבו התחברות אל Claude, Codex או Grok מוסיפה אחת. הוא פותח את הסוכן שלך על אותו מודל, ומתחיל את המודל תחילה אם הוא אינו רץ: הטרמינל מציג אותו נטען ומעביר את השליטה לסוכן לאחר שהוא מוכן. הסרת מודל מסירה את הרשומה שלו.

לא כל מודל מיועד לקידוד. מודלי תמונה, וידאו ומוזיקה נפתחים במקום זאת ב-Fantasi, האפליקציה של Omarchy ליצירת תמונות, וידאו ומוזיקה באמצעות מודל שרץ במכונה זו, הנבחר שם או מהשורה שלהם בפאנל המודלים המקומיים.

מודל ממשיך לרוץ בדיוק כפי שהוגדר, כך שעדכון של Omarchy לעולם אינו מתחיל מחדש אחד מהם תחת הסוכנים שלך. כאשר ל-Omarchy יש סביבת ריצה חדשה יותר או משקולות חדשות יותר עבור מודל שהגדרת, השורה שלו מציגה כפתור עדכון: לחץ עליו והמודל מוגדר שוב ברקע, מוריד רק את מה שהשתנה, ומתחיל מחדש בגרסה החדשה. מודל שהיה מופסק נשאר מופסק. `omarchy models update` עושה את אותו הדבר עבור כל מודל מטרמינל.

משורת הפקודה, `omarchy models start <recipe>` ו-`omarchy models stop <recipe>` עושים את אותו הדבר, `omarchy models status` מציג כל מודל, ו-`omarchy agent --local` פותח את סוכן ברירת המחדל שלך על המודל האחרון שהתחלת. pi, OpenCode ו-Qwen Code יכולים להשתמש באחד; עם כל ברירת מחדל אחרת הוא נפתח ב-pi, או ב-OpenCode אם אין לך pi. pi גם מפרט כל מודל שהגדרת, ואת אלה שבמכונות שציוותת איתן, בבוחר המודלים שלו עצמו, כך שגם `pi` רגיל מגיע אליהם. כל לקוח תואם-OpenAI יכול להתחבר גם הוא: `status` מציג את הכתובת של כל מודל (הראשונה היא `http://127.0.0.1:11435/v1`), שם המתכון הוא המודל, והמפתח נמצא ב-`~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` מוחק מודל ואת ההורדות ששום מודל אחר אינו משתמש בהן.

סביבות ריצה של צד שלישי מתויגות עם המפרסם שלהן. Omarchy מריצה כל מודל ללא גישה לרשת.

### מודלי LLM מקומיים

Omarchy ממליצה על שתי דרכים להריץ מודלי LLM מקומיים: LM Studio ו-Ollama. LM Studio מספקת ממשק GUI למציאת מודלים בעלי משקולות פתוחות, להתקנתם ולהרצתם. זו דרך מעולה להתחיל בקלות. Ollama מציעה CLI לעשות זאת באופן דומה. אבל אם אתה חדש במודלים מקומיים, הייתי מתחיל עם LM Studio. אתה יכול להתקין כל אחד מהם תחת _Install > AI_ בתפריט Omarchy.

### מיומנויות Omarchy

מיומנויות סוכן עוזרות ל-AI להשתמש בכלים ספציפיים בדרך ספציפית, ו-Omarchy מספקת שבע מהן. מיומנות omarchy מכסה התאמה אישית של המערכת, כגון כוונון תצורת Hyprland שלך או התאמת השורה. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app ו-omarchy-make-game מכסות יצירת משהו חדש, omarchy-contribute מכסה דיווח על באג או שליחת תיקון במעלה הזרם, ו-omarchy-diagnose-crash עוברת על ה-core dump של קריסה. הן מקושרות אל ספריות המיומנויות עבור Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` וכל `~/.hermes/profiles/*/skills`), והמיקום הגנרי `~/.agents/skills`, כך שרוב ה-harnesses קולטים אותן באופן אוטומטי. תיקיית מיומנות משלך עם אותו שם מקבלת עדיפות.

אבל עליך להתייחס למיומנויות אלה כניסיוניות. מודלים שונים ישתמשו בהן במידת השפעה שונה. עדיף לרוץ תחילה במצב תכנון, כדי שיהיה לך מושג מה הסוכן היה רוצה לשנות. ואז היה מוכן לשחזר שינויים או אפילו להפעיל את `omarchy reinstall configs`, אם הסוכן יעשה בלגן מהכול.
