# בינה מלאכותית

Omarchy כוללת משגרים לסוכני הקידוד שלהלן מבלי לבחור עבורך ברירת מחדל. הרץ את הפקודה כדי להתקין את ה-CLI שלה בשימוש הראשון, ולאחר מכן התחבר כשתתבקש. Hermes ו-OpenClaw הם היוצאים מן הכלל: עבורם לא מותקן דבר דרך mise, ובחירה בכל אחד מהם מתקינה עותק משלו שמתעדכן בעצמו, כפי שמסביר הסעיף _אפליקציות שולחן עבודה_ בהמשך.

### התקנה ועדכון של סוכנים

פרט ל-Hermes ול-OpenClaw, הסוכנים האלה משתמשים בהתקנה העצלה של mise: ההפעלה הראשונה מתקינה את ה-CLI, והפעלות מאוחרות יותר משתמשות בו שוב. mise גם בודק אם קיימת גרסה חדשה לסוכן מותקן לכל היותר פעם בארבע שעות, ממש לפני שהוא מופעל או ברקע בשורת הפקודה של המעטפת. אם העדכון הזה נכשל או שאינך מחובר, הגרסה המותקנת תרוץ. `omarchy update` מעדכן סוכנים מותקנים יחד עם שאר Omarchy, ו-`mup` מעדכן רק כלים המנוהלים על ידי mise.

המעדכן של הסוכן עצמו, כמו `claude update`, `codex update` או כפתור עדכון באפליקציה, אינו מעדכן את ההתקנה המנוהלת על ידי mise. `codex update` נכשל, ו-`claude update` עלול לדווח על הצלחה תוך התקנת עותק נפרד ש-mise אינו עוקב אחריו. אם אתה מעדיף להשתמש במתקין ובמעדכן המקוריים של סוכן, הוסף אותו ל-`disable_tools`; ראה [כלי CLI מותקנים מראש](18-development-tools.md#preinstalled-cli-tools).

כדי להתקין את כל הכלים העצלים שהוגדרו לפני שתצטרך אותם, הרץ `mise install --include-lazy`. זה כולל את כלי ה-CLI האחרים של Omarchy כברירת מחדל וכן את הסוכנים. ראה [כלי CLI מותקנים מראש](18-development-tools.md#preinstalled-cli-tools) להתקנת כלי יחיד או לשימוש בהתקנה משלך.

`grok` מותקן דרך חבילת ה-`grok` הרשמית של mise, באותו אופן כמו `claude` ו-`codex`. הרץ את `grok`, או סמן אותו בכוכב בחלונית הסוכנים. דלג על מתקין ה-`curl | bash` ב-x.ai. המסלול הזה מציב עותק שני ב-`~/.grok/bin`, מקדים אותו ב-`PATH`, ודורס את העטיפה של Omarchy.

`dsh` פותח את ממשק הדפדפן שלו ב-`127.0.0.1:3080`, כאשר ספריית ההפעלה היא סביבת העבודה המוגדרת כברירת מחדל שלו. ממשק הדפדפן שלו אינו מקבל הנחיית פתיחה, ולכן `omarchy agent prompt` פותח אותו כשההנחיה נמצאת בלוח ההדבקה שלך כדי שתדביק אותה. Omarchy מפעילה אותו עם הגדרת ההרשאות המוגדרת מראש של DeepSeek ללא אישור. DeepSeek Harness מעלה יומני הפעלות ל-DeepSeek כאשר אתה משתמש ב-API הרשמי של המודל שלו; כבה זאת תחת _הגדרות > כללי > העלאת יומן הפעלה_ בממשק הדפדפן שלו. גם משוב שאתה שולח לו מועלה יחד עם ההפעלה, אלא אם תפעיל אותו עם `DSH_TELEMETRY_MODE=DISABLED`.

### הסוכן המוגדר כברירת מחדל

בחר את סוכן ברירת המחדל שלך עם הכוכב שליד סוכן בחלונית הסוכנים, שמלא אצל ברירת המחדל, או עם `omarchy default agent <name>`, שמקבל גם כל רתמה שאין לה שורה שם. אם הסוכן עדיין לא מותקן, בחירתו תתקין אותו תחילה, והוא גם יקבל משגר משלו במשגר האפליקציות, ליד Agent. Omarchy טרייה מזמינה אותך להגדיר אחד עם הודעה חד-פעמית, שפותחת את חלונית הסוכנים.

בחירה ב-Claude גם מנסה להגדיר את תוסף הדפדפן שלו עבור Chromium, Chrome, Brave, Brave Origin ו-Edge. הגדרת התוסף חלה על כל המשתמשים ועשויה לבקש את סיסמת המערכת שלך; ביטול או התקנת תוסף שנכשלה עדיין בוחרים ומפעילים את Claude. הפעל מחדש את הדפדפן, הפעל את התוסף אם תתבקש, והתחבר ל-Claude כדי לסיים את חיבורו. הרץ `/chrome` ב-Claude כדי לבדוק את החיבור. Firefox ו-Zen אינם תומכים בתוסף הזה. אם Claude כבר היה ברירת המחדל שלך לפני שההגדרה הזו נוספה, בחר אותו שוב כדי להתקין את התוסף.

לאחר שבחרת, `Super + Shift + Ctrl + A` מפעיל את סוכן ברירת המחדל בחלון טרמינל ייעודי (או מעלה את הבוחר אם עדיין לא בחרת). תוכל גם להפעיל אותו ישירות למשימה עם `omarchy agent prompt "Review this project"`. Freebuff ו-DeepSeek Harness אינם מקבלים הנחיית פתיחה, ולכן במקום זאת הם נפתחים כשההנחיה בלוח ההדבקה שלך להדבקה. סוכנים המופעלים בדרך זו רצים ללא השגחה במצבי אל-תעצור-כדי-לשאול שלהם, אז תהיה מוכן לכך שהם באמת יעשו דברים! ל-MiniMax Code אין מצב כזה עבור ההפעלות האינטראקטיביות שלו, ולכן הוא מבקש הרשאות כרגיל. ומאחר שסוכנים מסרבים לזכור אמון עבור ספריית הבית שלך, הפעלות מ-`$HOME` מתחילות במקום זאת ב-`~/Work`.

יש גם קיצורי דרך לטרמינל: `a` מריץ את סוכן ברירת המחדל בתוך הטרמינל הנוכחי, בעוד `c`, `cx` ו-`cy` מפעילים ישירות את OpenCode, Claude Code ו-Codex (שוב במצבי האישור האוטומטי שלהם). גם שינויי ערכת נושא מסתנכרנים לסוכנים: Claude Code, Pi, OpenCode ו-Hermes (לאחר ש-Omarchy התקינה אותו) כולם עוקבים כשאתה מחליף את ערכת הנושא של Omarchy.

### הוראות הסוכן שלך

כללים אישיים לכל סוכן נכנסים ל-`~/.agents/AGENTS.md`, ליד המיומנויות המשותפות ב-`~/.agents/skills`. פתח אותו עם סמל המסמך שליד ה-+ בחלונית הסוכנים, או עם `omarchy agent instructions --edit`, שגם מקשר אותו לכל רתמה ששומרת קובץ גלובלי משלה: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, ה-`~/.copilot/copilot-instructions.md` של Copilot, וכן הלאה. Crush ו-Amp קוראים את הקישור `~/.config/AGENTS.md`, בעוד omp, Kimi ו-DeepSeek Harness קוראים את `~/.agents/AGENTS.md` ישירות. גם בחירת סוכן ברירת מחדל מקשרת אותו. קובץ הוראות שכבר היה לך הופך למשותף אם עדיין לא היה אחד; אחרת הוא נשמר ליד הקישור כ-`.bak`. הרץ `omarchy agent instructions` כדי לקשר מחדש לאחר התקנת סוכן נוסף.

### חלונית הסוכנים

בסרגל העליון יש סמל סוכנים. לפני שהגדרת סוכן, החלונית שלו מציעה שלוש דרכים להתחיל: התחבר למנוי Claude, Codex, Grok, Gemini, Muse, Cursor או Copilot, או תחת עוד תוכנית קידוד OpenCode Go, MiniMax, Synthetic או Z.ai; שלם לפי שימוש עם Fireworks, OpenCode Zen and Go, OpenRouter, או תחת עוד DeepSeek או כל ספק אחר ש-OpenCode מתחבר אליו, כולם רצים ב-OpenCode; או הרץ את המודל הטוב ביותר עבור המחשב שלך, כשאחד מתאים לו. הראשון שתסיים הופך לסוכן ברירת המחדל שלך, וה-+ בחלונית, או _סוכן > הוספה_ בתפריט Omarchy, מציע את אותן שלוש אפשרויות מאוחר יותר. לאחר מכן, החלונית מציבה כל מנוי בעמוד אחד: כל סוכן וחשבון עם התוכנית שלו, מד לכל אחת ממגבלות ההפעלה של 5 שעות והמגבלות השבועיות שלו יחד עם הזמן עד לאיפוס (רחף לקבלת האחוז המדויק), או יתרת התשלום מראש שנותרה, תחת שורה שמתחלפת בין מה שהשתמשת בו בכל אלה, כמו טוקנים השבוע והמודל שבו השתמשת הכי הרבה. תחת _צרו משהו מגניב_ היא מציעה הנחיות התחלה לערכת נושא, תוסף, אפליקציה או משחק חדשים שמעבירים את המשימה לסוכן ברירת המחדל שלך. אפליקציות נבנות באופן שבו נבנו Hype, Monologue ו-Omacut של Omarchy עצמה, ב-C++ וב-Qt Quick, לפי מיומנות הסוכן omarchy-make-app, והמהדר וחלקי ה-Qt שהן צריכות מגיעים מותקנים. משחקים הם עמוד three.js יחיד ב-`~/Games/vibes`, לפי מיומנות הסוכן omarchy-make-game, וכולם נפתחים ממשגר Game Vibes אחד בערכת הנושא הנוכחית; הם טוענים את three.js מהרשת, ולכן הם צריכים חיבור כדי להתחיל. Claude Code, Codex, Grok, Kimi, Cursor והקצאת ה-Grok Bot שלו, GitHub Copilot, Muse, Gemini (דרך Antigravity) ו-Devin מכוסים מהקופסה עם המגבלות שלהם, Kimchi עם התוכנית שלו, קרדיטים ששולמו מראש ותקציבי הוצאה, ו-Hermes, Mistral Vibe ו-Qwen Code מציגים את ההפעלות והטוקנים שלהם לאחר שהשתמשת בהם. גם תוכניות ומפתחות של ספקים שאתה משתמש בהם דרך pi, omp או opencode מופיעים: OpenCode Zen and Go, ה-Z.ai GLM Coding Plan, Ollama Cloud, ה-MiniMax Token Plan ו-Synthetic עם המגבלות שלהם; OpenRouter ו-DeepSeek עם יתרות התשלום מראש שלהם; Fireworks עם ההוצאה שלו ב-30 הימים האחרונים. גם טוקנים ממודלים שאתה מריץ על החומרה שלך נספרים בסיכומים; למודלים עצמם יש חלונית משלהם, המתוארת תחת [מודלים מקומיים](#local-models). כל סוכן נספר פעם אחת, תחת מי שמחייב עליו, לא משנה כמה רתמות אתה מפעיל אותו דרכן.

לחץ לחיצה שמאלית על סמל הסרגל או לחץ `Super + Ctrl + X` עבור החלונית, לחץ לחיצה ימנית כדי להפעיל את סוכן ברירת המחדל שלך, ולחץ לחיצה אמצעית כדי לרענן. רשומות השימוש שמאחוריה נוצרות מחדש כל 15 דקות על ידי `omarchy agent usage update`, והחלונית יכולה אפילו למזג שימוש מהמכונות האחרות שלך דרך תיקייה מסונכרנת. ראה את ה-README תחת `$OMARCHY_PATH/shell/plugins/agents/` לקבלת ההגדרות המלאות.

### מספר מנויים

אם אתה משלם עבור יותר מתוכנית Claude, Codex או Grok אחת — נניח Max אישית ואחת של עבודה — Omarchy יכולה להשאיר את כולן מחוברות ולעבור ביניהן. הוסף מנוי עם ה-+ בחלונית הסוכנים, שמדריך אותך בתהליך ממש שם, או עם `omarchy agent account add claude Work` (או `codex`, או `grok`). אותו + ואותה פקודה מחברים ל-Gemini (`gemini`) ול-OpenCode (`opencode`), ושומרים מפתח API של Fireworks (`fireworks`) או OpenRouter (`openrouter`) ב-OpenCode; הפקודה גם מחברת ל-Copilot (`copilot`), Cursor (`cursor`) ו-Muse (`muse`). אלה שומרים התחברות אחת כל אחד. היא מתקינה את ה-CLI אם הוא חסר. החשבון הראשון עבור ספק מתחבר דרך הדפדפן הרגיל שלך, בדיוק במקום שבו ה-CLI תמיד מחפש. כל אחד אחריו מתחבר דרך חלון פרטי, כדי שהחשבון שהדפדפן שלך כבר מחובר אליו לא ייבחר בטעות; התחבר שם כחשבון שאתה מוסיף, וסגור תחילה כל חלון פרטי שכבר פתוח אצלך. לעולם אל תתנתק מה-CLI כדי לעשות זאת: התנתקות מבטלת את ההתחברות השמורה, ואותו חשבון יצטרך להתווסף שוב.

כדי להעתיק את התחברויות המנוי שלך למכונת Omarchy אחרת דרך SSH, הרץ `omarchy agent account copy user@laptop`. השולח מספק מקלט זמני כאשר ליעד אין אחד מותקן, כך שמכונות Omarchy ישנות יותר יכולות לקבל חשבונות ללא עדכון. למקלטים מותקנים יש עדיפות. פעולה זו מעתיקה את כל מנויי Claude, Codex ו-Grok; הוסף שמות ספקים כדי לבחור אותם, כמו ב-`omarchy agent account copy laptop claude`. שמות חשבונות ומזהי פקודות תואמים את המקור, כולל חשבונות שכבר קיימים ביעד. חשבונות יעד לא קשורים מקבלים סיומת מספרית אם שמותיהם מתנגשים, והגדרות, מיומנויות, תוספים והיסטוריית שיחות נשארים מקומיים לכל מכונה.

אישורי יעד קיימים נשמרים. לחשבון מקור שכבר מחובר שם השם מסונכרן מבלי להחליף את האישורים שלו; חשבונות אחרים מתווספים לצדו. כדי להחליף אישורים שמורים עבור חשבונות תואמים, השתמש ב-`omarchy agent account copy --replace laptop claude` לאחר יציאה מההפעלות של אותו חשבון ביעד. יעד טרי מקבל גם את החשבון הפעיל ואת העדפות המעבר של המקור; יעד מבוסס שומר את שלו.

אישורים עוברים דרך SSH ונשמרים בקבצים פרטיים ביעד, ולכן העתק רק למכונות שאתה בוטח בהן. זו העתקה חד-פעמית, לא סנכרון מתמשך. אסימוני רענון של Codex יכולים להיות מוחלפים על ידי מכונה אחרת, מה שמשאיר התחברות מועתקת הזקוקה לחידוש; התחברויות נפרדות נשארות הבחירה האמינה ביותר לשימוש בו-זמני במספר מכונות. ראה את [הנחיות אימות החשבון של Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

חשבון אחד לכל ספק פעיל, וכל הפעלה חדשה מתחילה כמוהו: `cx`, `cy`, `claude`, `codex` או `grok` רגילים, כל דבר המופעל דרך `omarchy agent`, וסקריפטים או עורכים שמוצאים את ה-CLI ב-`PATH`. החלף עם `omarchy agent account use work` (ובחזרה עם `omarchy agent account use main`), או בחלונית על ידי לחיצה על מספר של חשבון ולאחר מכן `Enter` (או לחיצה על הכוכב שלו). גם הפעלות Claude רצות עוברות, מההודעה הבאה שלהן: כל הפעלת Claude רצה ב-`~/.claude`, שתמיד מחזיקה את ההתחברות של החשבון הפעיל. הפעלת Claude שהחלה בתיקייה של חשבון על ידי Omarchy ישנה יותר מחזיקה את אותה התחברות עד שהיא יוצאת, ולכן המעבר מציין את אותן הפעלות בשם ומסיים מעצמו לאחר שהן נעלמות. הפעלות Codex ו-Grok רצות נשארות בחשבון שבו התחילו. היסטוריית שיחות, הגדרות, מיומנויות ותוספים משותפים בין חשבונות, כך ש-`claude --continue` באותה תיקייה ממשיך מהמקום שבו הפסקת בחשבון החדש.

עם יותר מחשבון אחד, החלונית מציגה את מגבלות כל חשבון זו לצד זו, עם כוכב מלא על זה שבשימוש. Omarchy מודיעה לך כאשר החשבון הפעיל עובר 95% ממגבלה, ולחיצה על ההודעה עוברת לחשבון עם מרווח הראש הגדול ביותר. היא לעולם לא עוברת מעצמה. שנה את הסף עם `omarchy agent account threshold 90`. אם כל חשבון מעל הסף, תשמע על כך פעם אחת, יחד עם איזה חשבון משתחרר ראשון. בזמן שחשבון פעיל נמצא בטווח של 15 נקודות מהסף שלו (80% בברירת המחדל), המגבלות שלו נבדקות כל שלוש דקות ולא כל 15.

`omarchy agent account list` מציג כל חשבון ואת המגבלות האחרונות שלו, `omarchy agent account remove work` שוכח אחד, ו-`omarchy agent account rename primary Hey` משנה שם של אחד (או לחץ על שם חשבון בחלונית). הפקודות האלה פועלות על חשבונות סוכן ברירת המחדל שלך; כדי להגיע לספק האחר, ציין אותו תחילה, כמו ב-`omarchy agent account use codex side`. ההתחברות שכבר הייתה לך ב-`~/.claude` או ב-`~/.codex` היא החשבון _הראשי_. זו של Codex נשארת במקומה; זו של Claude ממתינה בתיקייה משלה בזמן שחשבון אחר פעיל. חשבון שנותר ללא שימוש במשך יותר מכשמונה שעות יכול להציג _נדרשת התחברות_; לחץ עליו כדי לחבר את אותו חשבון שוב ממש בחלונית, או עבור אליו והתחל הפעלה, שמרעננת את ההתחברות מעצמה. שרתי MCP שאתה מוסיף עם `claude mcp add` מגיעים לכל חשבון Claude, מאחר שכולם רצים ב-`~/.claude`; עבור Codex ו-Grok, שרתים שהיו לך כאשר חשבון התווסף מגיעים איתו, אבל מאוחרים יותר מגיעים רק לחשבון שבו הוספת אותם. Claude Desktop שומר התחברות משלו, וכלי Codex או Grok שהוגדרו עם נתיב מוחלט לקובץ בינארי של CLI אינם עוקבים אחר המעבר. `CLAUDE_CONFIG_DIR`, `CODEX_HOME` או `GROK_HOME` מפורשים מקבלים עדיפות על פני החשבון שנבחר.

### אבחון קריסות

Omarchy עוקבת אחר systemd-coredump לאיתור קריסות תהליכים. לאחר שבחרת סוכן ברירת מחדל, כל תוכנית שלך שזורקת core מביאה הודעת "התהליך קרס" — לחץ עליה, והקריסה מועברת לסוכן ברירת המחדל שלך יחד עם מיומנות omarchy-diagnose-crash של Omarchy, שמדריכה את הסוכן בביסוס העובדות מה-core dump ובהחלטה אם הקריסה שווה דיווח ל-upstream. תוכל גם להריץ זאת ידנית מול כל PID מ-`coredumpctl list` עם `omarchy agent crash <pid>`.

המעקב מופעל כברירת מחדל. כבה אותו תחת _הפעלה > החלפת מצב > כיבוי לכידת קריסות_ (או עם `omarchy toggle crash-capture`) וההודעות ייפסקו; `omarchy agent crash <pid>` עדיין פועל ידנית.

קריסות ניתנות גם להשתקה תוכנית אחת בכל פעם, וזה מה שהאבחון מציע לך בסוף. `omarchy crash mute hyprland` מפסיק את ההודעות עבור אותה תוכנית בלבד, `omarchy crash mute hyprland off` מחזיר אותן, ו-`omarchy crash mute` בפני עצמו מפרט את מה שהשתקת. הוא מקבל את נתיב הקובץ הבינארי בשמחה כמו את שמו, ולכן `omarchy crash mute /usr/bin/hyprland` עושה את אותו דבר. עטוף במרכאות שם שיש בו רווח, כמו ב-`omarchy crash mute 'Some App'`. כל השאר עדיין מודיע, והתוכנית המושתקת עדיין קורסת — זה מסתיר את התזכורת, זה לא מתקן דבר.

### אפליקציות שולחן עבודה

תפריט _התקנה > AI_ נושא גם כמה אפליקציות AI גרפיות: Amp Desktop, Antigravity Desktop, אפליקציית שולחן העבודה של ChatGPT, אפליקציית שולחן העבודה של Claude (גרסת הבטא ל-Linux של Anthropic, עם לשוניות Chat, Cowork ו-Claude Code), Grok Bot לשיחה עם המודלים של xAI, Herdr Desktop, Hermes Desktop, OpenClaw, אפליקציית שולחן העבודה של Perplexity ו-T3 Code. Grok Bot היא אפליקציית הצ'אט לשולחן העבודה. סוכן הקידוד הוא פקודת `grok`.

Hermes Desktop היא זו שכדאי להכיר, כי למכונה יש Hermes אחד, והוא של האפליקציה: Hermes מותקן רק אי-פעם דרך האפליקציה, ופקודת ה-`hermes` שסוכן ברירת המחדל מריץ היא של האפליקציה. בחירת Hermes כסוכן ברירת המחדל מתקינה את אותו דבר שהערך _התקנה > AI_ מתקין: את החבילה, וזמן ריצה של Hermes תחת `~/.hermes` שהוגדר על ידי המתקין של Hermes עצמו, מה שלוקח כמה דקות בפעם הראשונה. זמן הריצה הזה הוא ה-Hermes האחד שפקודת ה-`hermes` בטרמינל, סוכן ברירת המחדל והאפליקציה כולם משתמשים בו, והוא מעדכן את עצמו עם `hermes update` במקום לחכות לגרסה של Omarchy. התקנתו גם מעניקה ל-Hermes את ערכת הנושא של Omarchy כמעטפת בשם `omarchy`, שכל משטח של Hermes עוקב אחריה כשאתה מחליף ערכות נושא; בחר אחרת תחת הגדרות המראה של Hermes או עם `/skin` אם אתה מעדיף שלא, ו-Omarchy משאירה את הבחירה הזו בשקט. הסרת האפליקציה תחת _הסרה > AI_ סוגרת תחילה את Hermes, כולל השער, לוקחת את זמן הריצה הזה איתה, ושומרת את הצ'אטים, הזיכרונות והמיומנויות ש-Hermes כתב לעצמו אלא אם תאמר לה אחרת: היא שואלת, כשברירת המחדל היא לא, אם גם הנתונים האלה והגדרות החיבור שלך צריכים להיעלם.

חוויית שולחן העבודה של OpenClaw היא ה-Control UI שלו, שנפתח כאפליקציית רשת המגובה בשער מקומי משלו. OpenClaw חי ב-`~/.openclaw` ומעדכן את עצמו: השתמש בכפתור "עדכן שער" של ה-Control UI או הרץ `openclaw update`, והשער יופעל מחדש בגרסה החדשה. Omarchy רק בוחרת את הגרסה שהתקנה טרייה מתחילה ממנה. OpenClaw יכול להיות גם סוכן ברירת המחדל שלך: בחירתו תחת _סוכן > רתמה_ מגדירה את אותו עותק ב-`~/.openclaw`, והסוכן פותח את ממשק הטרמינל של OpenClaw המחובר לשער שלו. הסרת OpenClaw תחת _הסרה > AI_ לוקחת איתה את שירות השער ואת האפליקציה ולאחר מכן שואלת אם גם `~/.openclaw` צריך להיעלם, מאחר שהוא מחזיק את הצ'אטים והאישורים שלך לצד OpenClaw עצמו וזמני הריצה של התוספים שהוא מוריד; ברירת המחדל שומרת אותו, והתקנת OpenClaw שוב תאסוף אותו בחזרה.

Herdr Desktop היא אפליקציית שולחן העבודה [Herdr](https://herdr.dev): מרחבים, לשוניות וחלוניות של טרמינלים וסוכני קידוד שממשיכים לרוץ בליבה שלה כשאתה סוגר את החלון. היא מגיעה מהמתקין של Herdr עצמו ולא מחבילה, ולכן היא חיה ב-`~/.local/share/herdr-app`, מביאה את הליבה שלה ב-`~/.local/bin/herdr-core` כשעדיין אין לך אחת, ומעדכנת את שניהם בעצמה. היא יושבת לצד פקודת ה-`herdr` ש-Omarchy מספקת ב-`Super + Ctrl + Return` במקום להחליף אותה, ומקבלת את המקשים הישירים של אותה פקודה: `Alt + Return` ו-`Alt + Shift + Return` מפצלים חלונית למטה או ימינה, `Alt + Escape` סוגר אותה, `Ctrl + Alt + Arrow` עובר בין חלוניות, `Alt + 1..9` ו-`Alt + Left/Right` בוחרים לשונית, ו-`Alt + Up/Down` עוברים בין מרחבים. `Ctrl + 1..9` בוחר מרחב ו-`Alt + Shift + Up/Down` עובר בין סוכנים. מקשי הקידומת `Ctrl + Space` נשארים לטרמינל בלבד, מאחר שהאפליקציה אינה יכולה להחזיק מקש Ctrl רגיל לרצף. Omarchy כותבת אלה ל-`~/.config/herdr-app/keys.json`, ו-`omarchy-refresh-herdr-app` מחזירה אותם. התקנתה בוחרת את ערכת הנושא Omarchy של Herdr, שעוקבת אחר ערכת הנושא של Omarchy שלך מאז. Herdr שומרת ערכת נושא אחת למצב בהיר ואחת למצב כהה, ולכן לאחר מעבר בין ערכת נושא כהה לבהירה של Omarchy, בחר שוב ב-Omarchy בבוחר ערכות הנושא של Herdr עבור המצב האחר.

T3 Code רץ מגרסת ה-AppImage הרשמית שלו ב-`~/.local/share/t3code` ולא מחבילה, ולכן הוא מעדכן את עצמו. התקנתו שואלת אם להתחיל בערוץ Stable או Nightly; החלף מאוחר יותר בהגדרות של T3 Code. השרשורים וההגדרות שלך חיים ב-`~/.t3`, והסרת T3 Code תחת _הסרה > AI_ לוקחת אותם איתה.

### מודלים מקומיים

הרץ מודל פתוח על המכונה שלך עבור סוכני הקידוד שלך. ההנחיות והקוד שלך נשארים במכונה; שום דבר שנשלח למודל לא יוצא ממנה. התחל עם:

```bash
omarchy models use best text
```

זה מגדיר את מודל הטקסט הטוב ביותר עבור מכונה זו, הסוג שבו הסוכנים שלך משתמשים. למודלי תמונה, וידאו ומוזיקה יש את הטוב ביותר משלהם: `omarchy models use best image`, `video` או `music`. הרץ `omarchy models use best` כדי לראות את הבחירה של כל סוג עבור מכונה זו.

או פתח את חלונית המודלים המקומיים מסמל הניצוצות שלה בסרגל העליון, ליד סמל הסוכנים, או עם Super + Ctrl + Alt + X, ובחר +. הסמל מופיע כאשר מודל מתאים למכונה זו. Podman, שמריץ את המודלים, מגיע עם Omarchy, וכך גם ערכת הכלים לקונטיינרים של NVIDIA במכונת NVIDIA, שמעניקה להם את ה-GPU; אם אחד מהם חסר, ההגדרה הראשונה מתקינה אותו. לאחר מכן Omarchy בוחרת את המודל המומלץ עבור מכונה זו, מורידה אותו ומפעילה אותו. צפה להורדה של עשרות GB ולכך שרוב זיכרון המכונה יהיה בשימוש בזמן שהמודל רץ: Flash Next משתמש בכ-100 GiB עם הקשר ה-256K המלא שלו. אם מודלים אחרים מחזיקים את הזיכרון שהוא צריך, הוא מוגדר כמופסק, מוכן להתחיל ברגע שתעצור אחד. המודל נעצר בעת התנתקות; עצור אותו בעצמך כשאתה צריך את הזיכרון למשהו אחר.

`omarchy models list` מציג את האפשרויות ומסביר מדוע חלקן אינן מתאימות. כדי להגדיר אחד אחר, הרץ `omarchy models use <recipe>`. כיום, `qwen3.8-flash-next-gufo` ו-`qwen3.8-27b-gufo` זמינים למכונות Strix Halo בנפח 128 GB; ה-27B תופס כ-40 GiB, ולכן הוא משאיר מקום לעבודה אחרת. במחשב נייד בנפח 64 GB עם Arc B390 של Intel, `qwen3.6-35b-a3b-llamacpp` רץ בכ-30 GiB. מתכונים והמלצות חדשים מגיעים עם `omarchy update`, דרך החבילה.

כל מודל שאתה מגדיר מקבל שורה משלו בחלונית המודלים המקומיים: הפעל כדי להתחיל אותו, השהה כדי לעצור אותו ולפנות את הזיכרון שלו, וכפתור הטרמינל כדי לפתוח את הסוכן שלך עליו. בחלק העליון, סרגל מציג כיצד זיכרון המכונה מתחלק בין Omarchy עצמה (המערכת והאפליקציות שלך), כל מודל רץ, ומה פנוי. הצבע על מודל מופסק והסרגל מציג אם הוא מתאים, או כמה חסר לו. כמה יכולים לרוץ בו-זמנית כשהם מתאימים יחד בזיכרון; אם אחד לא מתאים, Omarchy אומרת איזה מודל רץ לעצור. גרור שורות לפי הלוגו שלהן כדי לסדר אותן מחדש, ולחץ Delete על שורה נבחרת כדי להסיר מודל ואת ההורדה שלו.

כל מודל קידוד שאתה מגדיר מקבל גם ערך משלו במשגר האפליקציות, תחת שם המודל ועם הלוגו של היוצר שלו, באופן שבו התחברות ל-Claude, Codex או Grok מוסיפה אחד. הוא פותח את הסוכן שלך על אותו מודל, ומפעיל תחילה את המודל אם אינו רץ: הטרמינל מציג אותו נטען ומעביר לסוכן ברגע שהוא פעיל. הסרת מודל מסירה את הערך שלו.

לא כל מודל מיועד לקידוד. מודלי תמונה, וידאו ומוזיקה נפתחים במקום זאת ב-Fantasi, האפליקציה של Omarchy ליצירת תמונות, וידאו ומוזיקה עם מודל הרץ על מכונה זו, שנבחר שם או מהשורה שלהם בחלונית המודלים המקומיים.

מודל ממשיך לרוץ בדיוק כפי שהוגדר, ולכן עדכון של Omarchy לעולם לא מפעיל מחדש אחד תחת הסוכנים שלך. כאשר ל-Omarchy יש זמן ריצה חדש יותר או משקולות חדשות יותר עבור מודל שהגדרת, השורה שלו מציגה כפתור עדכון: לחץ עליו והמודל מוגדר שוב ברקע, מוריד רק את מה שהשתנה, ומופעל מחדש בגרסה החדשה. מודל שהיה מופסק נשאר מופסק. `omarchy models update` עושה את אותו דבר עבור כל מודל מטרמינל.

משורת הפקודה, `omarchy models start <recipe>` ו-`omarchy models stop <recipe>` עושים את אותו דבר, `omarchy models status` מציג כל מודל, ו-`omarchy agent --local-model <recipe>` פותח את אותו מודל ב-pi, לא משנה מה סוכן ברירת המחדל שלך. כדי להפוך את המודל המקומי שלך למה שמקש הקיצור של הסוכן, קונסולת Quake ו-_צרו משהו_ פותחים, הרץ `omarchy default agent local` או בחר _מודל מקומי_ תחת _סוכן > רתמה_. pi גם מפרט כל מודל שהגדרת, ואלה שבמכונות שהתאמת אליהן, בבוחר המודלים שלו, כך שגם `pi` רגיל מגיע אליהם. גם כל לקוח תואם OpenAI יכול להתחבר: `status` מציג את כתובת כל מודל (הראשונה היא `http://127.0.0.1:11435/v1`), שם המתכון הוא המודל, והמפתח נמצא ב-`~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` מוחק מודל ואת ההורדות שאף מודל אחר לא משתמש בהן.

זמני ריצה של צד שלישי מתויגים עם המפרסם שלהם. Omarchy מריצה כל מודל ללא גישה לרשת.

### מודלי LLM מקומיים

Omarchy ממליצה על שתי דרכים להריץ מודלי LLM מקומיים: LM Studio ו-Ollama. LM Studio מספק ממשק GUI למציאת מודלים במשקולות פתוחות, להתקנתם ולהרצתם. זו דרך מעולה להתחיל בקלות. Ollama מציע CLI לעשות זאת באופן דומה. אבל אם אתה חדש במודלים מקומיים, הייתי מתחיל עם LM Studio. תוכל להתקין כל אחד מהם תחת _התקנה > AI_ בתפריט Omarchy.

### המיומנויות של Omarchy

מיומנויות סוכן עוזרות ל-AI להשתמש בכלים ספציפיים בדרך ספציפית, ו-Omarchy מספקת שבע מהן. מיומנות omarchy מכסה התאמת המערכת, כמו כוונון תצורת Hyprland שלך או התאמת הסרגל. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app ו-omarchy-make-game מכסות יצירת משהו חדש, omarchy-contribute מכסה דיווח על באג או שליחת תיקון ל-upstream, ו-omarchy-diagnose-crash מטפלת ב-core dump של קריסה. הן מקושרות בקישורים סימבוליים לתיקיות המיומנויות עבור Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` וכל `~/.hermes/profiles/*/skills`), והמיקום הגנרי `~/.agents/skills`, כך שרוב הרתמות קולטות אותן אוטומטית. תיקיית מיומנות משלך עם אותו שם מקבלת עדיפות.

אבל עליך להתייחס למיומנויות האלה כניסיוניות. מודלים שונים ישתמשו בה להשפעה שונה. עדיף לרוץ תחילה במצב תכנון, כדי שיהיה לך מושג מה הסוכן היה רוצה לשנות. ואז היה מוכן לשחזר שינויים או אפילו להפעיל את `omarchy reinstall configs`, אם הסוכן עושה בלגן מהכול.
