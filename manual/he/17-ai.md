### התקנה ועדכון של סוכנים

למעט Hermes, סוכנים אלה משתמשים בהתקנה העצלה של mise: ההפעלה הראשונה מתקינה את ה-CLI, והפעלות מאוחרות יותר משתמשות בו שוב. mise גם בודקת אם קיים שחרור חדש לסוכן מותקן לכל היותר פעם בארבע שעות, ממש לפני שהוא מופעל או ברקע בשורת פקודה של shell. אם אותו עדכון נכשל או שאתה לא מחובר, הגרסה המותקנת פועלת. `omarchy update` מעדכן סוכנים מותקנים יחד עם שאר Omarchy, ו-`mup` מעדכן רק כלים המנוהלים על ידי mise.

המעדכן של סוכן עצמו, כגון `claude update`, `codex update`, או כפתור עדכון באפליקציה, אינו מעדכן את ההתקנה המנוהלת על ידי mise. `codex update` נכשל, ו-`claude update` יכול לדווח על הצלחה תוך התקנת עותק נפרד ש-mise אינה עוקבת אחריו. אם אתה מעדיף להשתמש במתקין ובמעדכן המקוריים של סוכן, הוסף אותו ל-`disable_tools`; ראה [כלי CLI מותקנים מראש](18-development-tools.md#preinstalled-cli-tools).

כדי להתקין את כל הכלים העצלים המוגדרים לפני שתזדקק להם, הרץ `mise install --include-lazy`. זה כולל גם את כלי ה-CLI האחרים של ברירת המחדל של Omarchy וגם את הסוכנים. ראה [כלי CLI מותקנים מראש](18-development-tools.md#preinstalled-cli-tools) להתקנת כלי בודד או לשימוש בהתקנה משלך.

`grok` מותקן דרך חבילת ה-`grok` הרשמית של mise, באותו אופן כמו `claude` ו-`codex`. הרץ `grok`, או בחר בו תחת _Agent > Harness_. דלג על מתקין ה-`curl | bash` ב-x.ai. נתיב זה מציב עותק שני ב-`~/.grok/bin`, מקדים אותו ב-`PATH`, ודורס את העטיפה של Omarchy.

`dsh` פותח את ממשק הדפדפן שלו ב-`127.0.0.1:3080`, כאשר ספריית ההפעלה היא סביבת העבודה של ברירת המחדל שלו. ממשק הדפדפן שלו אינו מקבל הנחיית התחלה, לכן `omarchy agent prompt` פותח אותו כשההנחיה על לוח ההעתקה שלך כדי להדביק. Omarchy מפעילה אותו עם הגדרת ההרשאות ללא אישור של DeepSeek. DeepSeek Harness מעלה יומני הפעלה ל-DeepSeek כאשר אתה משתמש ב-API הרשמי של המודל שלה; כבה זאת תחת _Settings > General > Upload Session Log_ בממשק הדפדפן שלו. משוב שתשלח אליה מועלה גם הוא יחד עם ההפעלה, אלא אם תפעיל אותה עם `DSH_TELEMETRY_MODE=DISABLED`.

### סוכן ברירת המחדל

בחר את סוכן ברירת המחדל שלך עם `omarchy default agent <name>` או תחת _Agent > Harness_ בתפריט Omarchy (`Super + Space`). אם הסוכן עדיין לא מותקן, בחירתו תתקין אותו תחילה. Omarchy חדשה תזמין אותך לבחור באמצעות הודעה חד-פעמית.

בחירת Claude גם מנסה להגדיר את תוסף הדפדפן שלו עבור Chromium, Chrome, Brave, Brave Origin ו-Edge. הגדרת התוסף חלה על כל המשתמשים ועלולה לבקש את סיסמת המערכת שלך; ביטול או התקנת תוסף שנכשלה עדיין בוחרים ומפעילים את Claude. הפעל מחדש את הדפדפן, אפשר את התוסף אם תתבקש, והתחבר ל-Claude כדי לסיים את חיבורו. הרץ `/chrome` ב-Claude כדי לבדוק את החיבור. Firefox ו-Zen אינם תומכים בתוסף זה. אם Claude כבר היה ברירת המחדל שלך לפני שהגדרה זו נוספה, בחר בו שוב כדי להתקין את התוסף.

לאחר שבחרת, `Super + Shift + Ctrl + A` מפעיל את סוכן ברירת המחדל בחלון מסוף ייעודי (או מעלה את הבוחר אם עדיין לא בחרת). ניתן גם להפעיל אותו ישירות למשימה עם `omarchy agent prompt "Review this project"`. Freebuff ו-DeepSeek Harness אינם מקבלים הנחיית התחלה, לכן הם נפתחים כשההנחיה על לוח ההעתקה שלך כדי להדביק במקום זאת. סוכנים המופעלים כך פועלים ללא השגחה במצבי אל-תעצור-לשאול שלהם, לכן היה מוכן לכך שהם באמת יעשו דברים! ל-MiniMax Code אין מצב כזה להפעלות האינטראקטיביות שלו, לכן הוא מבקש הרשאות כרגיל. ומכיוון שסוכנים מסרבים לזכור אמון עבור ספריית הבית שלך, הפעלות מ-`$HOME` מתחילות ב-`~/Work` במקום זאת.

יש גם קיצורי מסוף: `a` מריץ את סוכן ברירת המחדל בתוך המסוף הנוכחי, בעוד `c`, `cx` ו-`cy` מפעילים את OpenCode, Claude Code ו-Codex ישירות (שוב במצבי האישור האוטומטי שלהם). שינויי נושא מסתנכרנים גם לסוכנים: Claude Code, Pi, OpenCode ו-Hermes (לאחר ש-Omarchy התקינה אותו) כולם עוקבים כאשר אתה מחליף את נושא Omarchy.

### הוראות הסוכן שלך

כללים אישיים לכל סוכן נמצאים ב-`~/.agents/AGENTS.md`, לצד הכישורים המשותפים ב-`~/.agents/skills`. פתח אותו תחת _Agent > Instructions_, שגם מקשר אותו לכל harness ששומר קובץ גלובלי משלו: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, ה-`~/.copilot/copilot-instructions.md` של Copilot, וכן הלאה. Crush ו-Amp קוראים את הקישור `~/.config/AGENTS.md`, בעוד omp, Kimi ו-DeepSeek Harness קוראים את `~/.agents/AGENTS.md` ישירות. בחירת סוכן ברירת מחדל מקשרת אותו גם כן. קובץ הוראות שכבר היה לך הופך למשותף אם עדיין לא היה כזה; אחרת הוא נשמר לצד הקישור כ-`.bak`. הרץ `omarchy agent instructions` כדי לקשר מחדש לאחר התקנת סוכן נוסף.

### פאנל הסוכנים

בסרגל העליון יש סמל סוכנים. לפני שהגדרת סוכן, הפאנל שלו מלווה אותך בהתחברות ל-Claude, Codex או Grok, והראשון הופך לסוכן ברירת המחדל שלך. לאחר מכן, הפאנל מציב כל מנוי בעמוד אחד: כל סוכן וחשבון עם התוכנית שלו, מד לכל אחת ממגבלות ההפעלה של 5 שעות והמגבלות השבועיות שלו יחד עם הזמן עד לאיפוס (רחף לקבלת האחוז המדויק), או יתרת התשלום מראש שנותרה, מתחת לשורה המתחלפת בין מה שהשתמשת בו בכל כולם, כמו טוקנים השבוע והמודל שבו השתמשת הכי הרבה. תחת _Make something_ הוא מציע הנחיות התחלה לנושא, תוסף, אפליקציה או משחק חדשים שמעבירים את המשימה לסוכן ברירת המחדל שלך. אפליקציות נבנות כפי שנבנו Hype, Monologue ו-Omacut של Omarchy עצמה, ב-C++ וב-Qt Quick, בהתאם לכישור הסוכן omarchy-app, והמהדר וחלקי Qt שהם צריכים מגיעים מותקנים. משחקים הם עמוד three.js בודד ב-`~/Games/vibes`, בהתאם לכישור הסוכן web-game, וכולם נפתחים ממשגר Game Vibes אחד בנושא הנוכחי; הם טוענים את three.js מהאינטרנט, לכן הם זקוקים לחיבור כדי להתחיל. Claude Code, Codex, Grok, Kimi, Cursor וקצבת Grok Bot שלו, GitHub Copilot, Muse, Antigravity, Kimchi ו-Devin מכוסים מהקופסה עם המגבלות שלהם, ו-Hermes, Mistral Vibe ו-Qwen Code מציגים את ההפעלות והטוקנים שלהם לאחר שהשתמשת בהם. תוכניות ומפתחות של ספקים שבהם אתה משתמש דרך pi, omp או opencode מופיעים גם כן: OpenCode Zen ו-Go, ה-Z.ai GLM Coding Plan, Ollama Cloud, ה-MiniMax Token Plan ו-Synthetic עם המגבלות שלהם; Fireworks, OpenRouter ו-DeepSeek עם יתרות התשלום מראש שלהם; והמודלים שאתה מריץ על החומרה שלך תחת מודלים מקומיים. כל סוכן נספר פעם אחת, תחת מי שמחייב עליו, לא משנה בכמה harnesses אתה מפעיל אותו.

לחץ לחיצה שמאלית על סמל הסרגל עבור הפאנל, לחץ לחיצה ימנית כדי להפעיל את סוכן ברירת המחדל שלך. רשומות השימוש שמאחוריו נוצרות מחדש כל 15 דקות על ידי `omarchy agent usage-update`, והפאנל יכול אפילו למזג שימוש מהמכונות האחרות שלך דרך תיקייה מסונכרנת. ראה את ה-README תחת `$OMARCHY_PATH/shell/plugins/agents/` להגדרות המלאות.

### מספר מנויים

אם אתה משלם עבור יותר מתוכנית Claude, Codex או Grok אחת — Max אישית ואחת לעבודה, נניח — Omarchy יכולה להשאיר את כולן מחוברות ולעבור ביניהן. הוסף מנוי עם ה-+ בפאנל הסוכנים, שילווה אותך בכך ממש שם, או עם `omarchy agent account add claude Work` (או `codex`, או `grok`). היא מתקינה את ה-CLI אם הוא חסר. החשבון הראשון עבור ספק מתחבר דרך הדפדפן הרגיל שלך, בדיוק במקום שה-CLI תמיד מחפש. כל אחד לאחר מכן מתחבר דרך חלון פרטי, כדי שהחשבון שהדפדפן שלך כבר מחובר אליו לא ייבחר בטעות; התחבר שם כחשבון שאתה מוסיף, וסגור תחילה כל חלון פרטי שכבר פתוח אצלך. לעולם אל תתנתק מה-CLI כדי לעשות זאת: התנתקות מבטלת את ההתחברות השמורה, ואותו חשבון יצטרך להתווסף שוב.

כדי להעתיק את התחברויות המנוי שלך למכונת Omarchy אחרת דרך SSH, הרץ `omarchy agent account copy user@laptop`. השולח מספק מקלט זמני כאשר ליעד אין אחד מותקן, כך שמכונות Omarchy ישנות יותר יכולות לקבל חשבונות ללא עדכון. מקלטים מותקנים מקבלים עדיפות. פעולה זו מעתיקה את כל מנויי Claude, Codex ו-Grok; הוסף שמות ספקים כדי לבחור בהם, כמו ב-`omarchy agent account copy laptop claude`. שמות חשבונות ומזהי פקודה תואמים את המקור, כולל חשבונות שכבר קיימים ביעד. חשבונות יעד לא קשורים מקבלים סיומת מספרית אם שמותיהם מתנגשים, והגדרות, כישורים, תוספים והיסטוריית שיחות נשארים מקומיים לכל מכונה.

אישורי יעד קיימים נשמרים. חשבון מקור שכבר מחובר שם מסונכרן בשמו מבלי להחליף את אישוריו; חשבונות אחרים מתווספים לצדו. כדי להחליף אישורים שמורים עבור חשבונות תואמים, השתמש ב-`omarchy agent account copy --replace laptop claude` לאחר שיצאת מההפעלות של אותו חשבון ביעד. יעד חדש מקבל גם את החשבון הפעיל ואת העדפות המעבר של המקור; יעד מבוסס שומר את שלו.

אישורים עוברים דרך SSH ומאוחסנים בקבצים פרטיים ביעד, לכן העתק רק למכונות שאתה בוטח בהן. זו העתקה חד-פעמית, לא סנכרון מתמשך. טוקני רענון של Codex יכולים להתחלף על ידי מכונה אחרת, ולהשאיר התחברות מועתקת הזקוקה לחידוש; התחברויות נפרדות נשארות הבחירה האמינה ביותר לשימוש בו-זמני במספר מכונות. ראה את [הנחיות אימות החשבון של Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

חשבון אחד לכל ספק פעיל, וכל הפעלה חדשה מתחילה כמותו: `cx`, `cy`, `claude`, `codex` או `grok` רגילים, כל דבר המופעל דרך `omarchy agent`, ותסריטים או עורכים שמוצאים את ה-CLI ב-`PATH`. החלף עם `omarchy agent account use work` (וחזרה עם `omarchy agent account use main`), או בפאנל על ידי לחיצה על מספר חשבון ולאחר מכן `Enter` (או לחיצה על כפתור Use שלו). הפעלות Claude פעילות מחליפות גם הן, החל מההודעה הבאה שלהן: כל הפעלת Claude פועלת ב-`~/.claude`, שתמיד מכילה את ההתחברות של החשבון הפעיל. הפעלת Claude שהחלה בתיקייה של חשבון עצמו על ידי Omarchy ישנה יותר שומרת את אותה התחברות עד שהיא יוצאת, לכן המעבר מציין את אותן הפעלות ומסיים מעצמו לאחר שהן נעלמות. הפעלות Codex ו-Grok פעילות נשארות בחשבון שבו התחילו. היסטוריית שיחות, הגדרות, כישורים ותוספים משותפים בין חשבונות, לכן `claude --continue` באותה תיקייה ממשיך מהמקום שהפסקת בחשבון החדש.

עם יותר מחשבון אחד, הפאנל מציג את מגבלות כל חשבון זו לצד זו, כשהפעיל מסומן. כברירת מחדל Omarchy מודיעה לך כאשר החשבון הפעיל עובר 95% ממגבלה, ולחיצה על ההודעה מחליפה לחשבון עם המרווח הפנוי הגדול ביותר. רחף מעל שורת חשבון בפאנל ולחץ על Autoswitch שמופיע לצד Use (או לחץ `m`), או הרץ `omarchy agent account mode auto`, כדי שהיא תחליף מעצמה במקום זאת; בזמן שהיא פועלת, Autoswitch תופס את מקום Use, ולחיצה עליו שוב חוזרת למצב הודעה. הוסף מספר כדי לשנות את הסף, כמו ב-`omarchy agent account mode auto 90`. אם כל חשבון מעל הסף, תשמע על כך פעם אחת, יחד עם איזה חשבון מתפנה ראשון. בזמן שחשבון פעיל נמצא בתוך 15 נקודות מהסף שלו (80% כברירת מחדל), המגבלות שלו נבדקות כל שלוש דקות ולא כל 15.

`omarchy agent account list` מציג כל חשבון ואת המגבלות העדכניות שלו, `omarchy agent account remove work` שוכח אחד, ו-`omarchy agent account rename primary Hey` משנה שם של אחד (או לחץ על שם חשבון בפאנל). פקודות אלה פועלות על חשבונות סוכן ברירת המחדל שלך; כדי להגיע לספק האחר, ציין אותו תחילה, כמו ב-`omarchy agent account use codex side`. ההתחברות שכבר הייתה לך ב-`~/.claude` או `~/.codex` היא חשבון ה-_Main_. זה של Codex נשאר במקומו; זה של Claude ממתין בתיקייה משלו בזמן שחשבון אחר פעיל. חשבון שלא נעשה בו שימוש במשך יותר מכשמונה שעות יכול להציג _Sign-in required_; לחץ עליו כדי לחבר את אותו חשבון שוב ממש בפאנל, או החלף אליו והתחל הפעלה, שמרעננת את ההתחברות מעצמה. שרתי MCP שאתה מוסיף עם `claude mcp add` מגיעים לכל חשבון Claude, מכיוון שכולם פועלים ב-`~/.claude`; עבור Codex ו-Grok, שרתים שהיו לך כאשר חשבון התווסף באים איתו, אבל מאוחרים יותר מגיעים רק לחשבון שבו הוספת אותם. Claude Desktop שומר התחברות משלו, וכלי Codex או Grok המוגדרים עם נתיב מוחלט לקובץ בינארי של CLI אינם עוקבים אחר המעבר. `CLAUDE_CONFIG_DIR`, `CODEX_HOME` או `GROK_HOME` מפורש מקבל עדיפות על החשבון הנבחר.

### אבחון קריסות

Omarchy עוקבת אחר systemd-coredump לקריסות תהליכים. כאשר משהו מבצע segfault, תקבל הודעת "Process crashed" — לחץ עליה, והקריסה נמסרת לסוכן ברירת המחדל שלך יחד עם כישור diagnose-crash של Omarchy, שילווה את הסוכן בביסוס העובדות מתוך ה-core dump ובהחלטה אם הקריסה שווה דיווח ל-upstream. ניתן גם להריץ אותו ידנית מול כל PID מתוך `coredumpctl list` עם `omarchy agent crash <pid>`.

המעקב פועל כברירת מחדל. כבה אותו תחת _Trigger > Toggle > Crash Capture_ (או עם `omarchy toggle crash-capture`) וההודעות מפסיקות; `omarchy agent crash <pid>` עדיין פועל ידנית.

ניתן גם להשתיק קריסות תוכנית אחת בכל פעם, שזה מה שהאבחון מציע לך בסוף. `omarchy crash mute hyprland` עוצר את ההודעות עבור אותה תוכנית בלבד, `omarchy crash mute hyprland off` מחזיר אותן, ו-`omarchy crash mute` לבדו מפרט מה השתקת. הוא מקבל את נתיב הקובץ הבינארי בשמחה כמו את שמו, לכן `omarchy crash mute /usr/bin/hyprland` עושה את אותו דבר. צטט שם עם רווח בו, כמו ב-`omarchy crash mute 'Some App'`. כל דבר אחר עדיין מודיע, והתוכנית המושתקת עדיין קורסת — זה מסתיר את התזכורת, זה לא מתקן דבר.

### אפליקציות שולחניות

תפריט _Install > AI_ נושא גם כמה אפליקציות AI גרפיות: אפליקציית ChatGPT לשולחן העבודה, אפליקציית Claude לשולחן העבודה (גרסת הבטא ל-Linux של Anthropic, עם לשוניות Chat, Cowork ו-Claude Code), Grok Bot לשיחה עם המודלים של xAI, Herdr Desktop, Hermes Desktop, OpenClaw, אפליקציית Perplexity לשולחן העבודה ו-T3 Code. Grok Bot היא אפליקציית הצ'אט לשולחן העבודה. סוכן הקידוד הוא פקודת `grok`.

Hermes Desktop היא זו שכדאי להכיר, מכיוון שלמכונה יש Hermes אחד, והוא של האפליקציה: Hermes מותקנת רק אי פעם דרך האפליקציה, ופקודת `hermes` שסוכן ברירת המחדל מריץ היא של האפליקציה. בחירת Hermes כסוכן ברירת המחדל מתקינה את אותו דבר שהערך _Install > AI_ מתקין: את החבילה, ואת סביבת הריצה של Hermes תחת `~/.hermes` המוגדרת על ידי המתקין של Hermes עצמה, שלוקח כמה דקות בפעם הראשונה. סביבת ריצה זו היא ה-Hermes האחת שפקודת `hermes` במסוף, סוכן ברירת המחדל והאפליקציה כולם משתמשים בה, והיא מעדכנת את עצמה עם `hermes update` במקום להמתין לשחרור Omarchy. התקנתה גם מעניקה ל-Hermes את נושא Omarchy כעור בשם `omarchy`, שכל משטח של Hermes עוקב אחריו כשאתה מחליף נושאים; בחר אחר תחת הגדרות Appearance של Hermes או עם `/skin` אם אתה מעדיף שלא, ו-Omarchy משאירה את הבחירה הזו לבד. הסרת האפליקציה תחת _Remove > AI_ סוגרת תחילה את Hermes, כולל ה-gateway, לוקחת איתה את סביבת הריצה הזו, ושומרת את הצ'אטים, הזיכרונות והכישורים ש-Hermes כתבה לעצמה אלא אם תאמר לה אחרת: היא שואלת, כברירת מחדל לא, אם גם הנתונים והגדרות החיבור שלך צריכים להיעלם.

חוויית שולחן העבודה של OpenClaw היא ה-Control UI שלו, שנפתח כאפליקציית אינטרנט המגובה על ידי ה-gateway המקומי שלו. OpenClaw חיה ב-`~/.openclaw` ומעדכנת את עצמה: השתמש בכפתור "Update Gateway" של ה-Control UI או הרץ `openclaw update`, וה-gateway מופעל מחדש על הגרסה החדשה. Omarchy בוחרת רק את השחרור שממנו התקנה חדשה מתחילה. הסרת OpenClaw תחת _Remove > AI_ לוקחת איתה את שירות ה-gateway ואת האפליקציה ולאחר מכן שואלת אם גם `~/.openclaw` צריכה להיעלם, מכיוון שזה מחזיק את הצ'אטים והאישורים שלך לצד OpenClaw עצמה וסביבות הריצה של התוספים שהיא מורידה; ברירת המחדל שומרת אותו, והתקנת OpenClaw שוב מרימה אותו בחזרה.

Herdr Desktop היא אפליקציית שולחן העבודה [Herdr](https://herdr.dev): מרחבים, לשוניות וחלוניות של מסופים וסוכני קידוד שממשיכים לפעול בליבה שלה כשאתה סוגר את החלון. היא מגיעה מהמתקין של Herdr עצמה ולא מחבילה, לכן היא חיה ב-`~/.local/share/herdr-app`, מביאה את הליבה שלה ב-`~/.local/bin/herdr-core` כשעדיין אין לך אחת, ומעדכנת את שניהם בעצמה. היא יושבת לצד פקודת `herdr` ש-Omarchy מספקת ב-`Super + Ctrl + Return` ולא מחליפה אותה, ומקבלת את המקשים הישירים של אותה פקודה: `Alt + Return` ו-`Alt + Shift + Return` מפצלים חלונית למטה או ימינה, `Alt + Escape` סוגר אותה, `Ctrl + Alt + Arrow` עובר בין חלוניות, `Alt + 1..9` ו-`Alt + Left/Right` בוחרים לשונית, ו-`Alt + Up/Down` עוברים בין מרחבים. `Ctrl + 1..9` בוחר מרחב ו-`Alt + Shift + Up/Down` עובר בין סוכנים. מקשי הקידומת `Ctrl + Space` נשארים למסוף בלבד, מכיוון שהאפליקציה אינה יכולה להחזיק מקש Ctrl רגיל לרצף. Omarchy כותבת אלה ל-`~/.config/herdr-app/keys.json`, ו-`omarchy-refresh-herdr-app` מחזיר אותם. התקנתה בוחרת את נושא Omarchy של Herdr, שעוקב אחר נושא Omarchy שלך מאז. Herdr שומרת נושא אחד למצב בהיר ואחד למצב כהה, לכן לאחר מעבר בין נושא Omarchy כהה לבהיר, בחר ב-Omarchy בבוחר הנושאים של Herdr פעם נוספת עבור המצב האחר.

T3 Code פועלת משחרור ה-AppImage הרשמי שלה ב-`~/.local/share/t3code` ולא מחבילה, לכן היא מעדכנת את עצמה. התקנתה שואלת אם להתחיל בערוץ Stable או Nightly; החלף מאוחר יותר בהגדרות T3 Code. השרשורים וההגדרות שלך חיים ב-`~/.t3`, והסרת T3 Code תחת _Remove > AI_ לוקחת אותם איתה.

### מודלים מקומיים

הרץ מודל פתוח במכונה שלך עבור סוכני הקידוד שלך. ההנחיות והקוד שלך נשארים במכונה; שום דבר שנשלח למודל לא עוזב אותה. התחל עם:

```bash
omarchy agent local use best
```

או, בפאנל הסוכנים בסרגל העליון, בחר + ולאחר מכן Local AI, שמופיע כאשר מודל מתאים למכונה זו. בפעם הראשונה, זה מתקין את Podman, שמריץ את המודלים, ובמכונת NVIDIA את ערכת הכלים למכולות של NVIDIA, שמעניקה להם את ה-GPU. Omarchy לאחר מכן בוחרת את המודל המומלץ למכונה זו, מורידה אותו ומפעילה אותו. צפה להורדה של עשרות GB ולכך שרוב זיכרון המכונה יהיה בשימוש בזמן שהמודל פועל: Flash Next משתמש בכ-100 GiB עם הקשר ה-256K המלא שלו. אם מודלים אחרים מחזיקים בזיכרון שהוא צריך, הוא מוגדר עצור, מוכן להתחיל לאחר שתעצור אחד. המודל עוצר בעת התנתקות; עצור אותו בעצמך כשאתה צריך את הזיכרון למשהו אחר.

`omarchy agent local list` מציג את האפשרויות ומסביר מדוע חלקן אינן מתאימות. כדי להגדיר אחד נוסף, הרץ `omarchy agent local use <recipe>`. כיום, `qwen3.8-flash-next-gufo` ו-`qwen3.8-27b-gufo` זמינים למכונות Strix Halo בנפח 128 GB; ה-27B לוקח כ-40 GiB, לכן הוא משאיר מקום לעבודה אחרת. במחשב נייד בנפח 64 GB עם Arc B390 של Intel, `qwen3.6-35b-a3b-llamacpp` פועל בכ-30 GiB. מתכונים והמלצות חדשים מגיעים עם `omarchy update`, דרך החבילה.

כל מודל שתגדיר מקבל שורה משלו בפאנל הסוכנים, לצד המנויים שלך: הפעל כדי להתחיל אותו, השהה כדי לעצור אותו ולפנות את זיכרונו, וכפתור המסוף כדי לפתוח את הסוכן שלך עליו. כמה יכולים לפעול בו-זמנית כאשר הם מתאימים יחד בזיכרון; אם אחד אינו מתאים, Omarchy אומרת איזה מודל פעיל לעצור. גרור שורות כדי לסדר אותן מחדש, ולחץ Delete על שורה נבחרת כדי להסיר מודל ואת ההורדה שלו.

כל מודל שתגדיר מקבל גם ערך משלו במשגר האפליקציות, תחת שם המודל ועם הלוגו של יוצרו, כפי שהתחברות ל-Claude, Codex או Grok מוסיפה אחד. הוא פותח את הסוכן שלך על אותו מודל, ומפעיל את המודל תחילה אם הוא אינו פועל: המסוף מראה אותו נטען ומעביר לסוכן לאחר שהוא מוכן. הסרת מודל מסירה את הערך שלו.

מהשורת פקודה, `omarchy agent local start <recipe>` ו-`omarchy agent local stop <recipe>` עושים את אותו דבר, `omarchy agent local status` מציג כל מודל, ו-`omarchy agent --local` פותח את סוכן ברירת המחדל שלך על המודל האחרון שהפעלת. pi, OpenCode ו-Qwen Code יכולים להשתמש באחד; עם כל ברירת מחדל אחרת הוא נפתח ב-pi. pi מפרט גם כל מודל שהגדרת, ואלה שבמכונות שחיברת אליהן, בבוחר המודלים שלו, לכן גם `pi` רגיל מגיע אליהם. כל לקוח תואם OpenAI יכול להתחבר גם כן: `status` מציג את כתובת כל מודל (הראשונה היא `http://127.0.0.1:11435/v1`), שם המתכון הוא המודל, והמפתח נמצא ב-`~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` מוחק מודל ואת ההורדות ששום מודל אחר לא משתמש בהן.

סביבות ריצה של צד שלישי מסומנות עם המפרסם שלהן. Omarchy מריצה כל מודל ללא גישה לרשת.

### מודלי LLM מקומיים

Omarchy ממליצה על שתי דרכים להרצת מודלי LLM מקומיים: LM Studio ו-Ollama. LM Studio מספקת ממשק GUI למציאת מודלים במשקל פתוח, התקנתם והרצתם. זו דרך מעולה להתחיל בקלות. Ollama מציעה CLI לעשות זאת באופן דומה. אבל אם אתה חדש במודלים מקומיים, הייתי מתחיל עם LM Studio. ניתן להתקין כל אחד תחת _Install > AI_ בתפריט Omarchy.

### כישור Omarchy

כישורי סוכן עוזרים ל-AI להשתמש בכלים ספציפיים בדרך ספציפית, ו-Omarchy מסופקת עם כישור ברירת מחדל להתאמת המערכת. כמו כוונון תצורת Hyprland שלך, התאמת הסרגל, או אפילו יצירת נושא חדש מאפס. הוא מקושר באופן סמלי לספריות הכישורים עבור Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` וכל `~/.hermes/profiles/*/skills`), והמיקום הגנרי `~/.agents/skills`, לכן רוב ה-harnesses קולטים אותו אוטומטית.

אבל עליך להתייחס לכישור זה כניסיוני. מודלים שונים ישתמשו בו ביעילות שונה. עדיף להריץ תחילה במצב תכנון, כדי שיהיה לך מושג מה הסוכן היה רוצה לשנות. ולאחר מכן היה מוכן לבטל שינויים או אפילו להפעיל `omarchy reinstall configs`, אם הסוכן מבלגן הכל.
