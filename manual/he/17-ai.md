# AI

Omarchy כוללת משגרים לסוכני הקידוד שלהלן מבלי לבחור עבורך ברירת מחדל. הרץ פקודה כדי להתקין את ה-CLI שלה בשימוש הראשון, ולאחר מכן היכנס כשתתבקש. Hermes הוא היוצא מן הכלל: בשימוש הראשון לא מותקן עבורו דבר, ובחירה בו מתקינה את Hermes Desktop, כפי שמסביר _אפליקציות שולחניות_ בהמשך.

### התקנה ועדכון של סוכנים

למעט Hermes, הסוכנים הללו משתמשים בהתקנה העצלה של mise: ההפעלה הראשונה מתקינה את ה-CLI, והפעלות מאוחרות יותר משתמשות בו שוב. mise גם בודק אם קיימת גרסה חדשה לסוכן מותקן לכל היותר פעם בארבע שעות, ממש לפני שהוא מופעל או ברקע ב-shell prompt. אם העדכון הזה נכשל או שאתה לא מחובר, הגרסה המותקנת תרוץ. `omarchy update` מעדכן סוכנים מותקנים יחד עם שאר Omarchy, ו-`mup` מעדכן רק כלים המנוהלים על ידי mise.

המעדכן של סוכן עצמו, כמו `claude update`, `codex update`, או כפתור עדכון באפליקציה, לא מעדכן את ההתקנה המנוהלת על ידי mise. `codex update` נכשל, ו-`claude update` עלול לדווח על הצלחה תוך התקנת עותק נפרד ש-mise לא עוקב אחריו. אם אתה מעדיף להשתמש במתקין ובמעדכן המקוריים של סוכן, הוסף אותו ל-`disable_tools`; ראה [כלי CLI מותקנים מראש](18-development-tools.md#preinstalled-cli-tools).

כדי להתקין את כל הכלים העצלים המוגדרים לפני שתזדקק להם, הרץ `mise install --include-lazy`. זה כולל את כלי ה-CLI האחרים של Omarchy שהם ברירת מחדל, וגם את הסוכנים. ראה [כלי CLI מותקנים מראש](18-development-tools.md#preinstalled-cli-tools) להתקנת כלי יחיד או לשימוש בהתקנה משלך.

`grok` מותקן דרך חבילת ה-`grok` הרשמית של mise, באותה דרך כמו `claude` ו-`codex`. הרץ `grok`, או בחר אותו תחת _Setup > Defaults > Agent_. דלג על מתקין ה-`curl | bash` ב-x.ai. הנתיב הזה שם עותק שני ב-`~/.grok/bin`, מקדים אותו ב-`PATH`, ודורס את ה-wrapper של Omarchy.

`dsh` פותח את ממשק הדפדפן שלו ב-`127.0.0.1:3080`, כשספריית ההפעלה היא סביבת העבודה של ברירת המחדל שלו. ממשק הדפדפן שלו לא מקבל prompt התחלתי, ולכן `omarchy agent prompt` פותח אותו כשה-prompt נמצא בלוח שלך להדבקה. Omarchy מפעילה אותו עם הגדרת ההרשאות ללא אישור של DeepSeek. DeepSeek Harness מעלה יומני session ל-DeepSeek כשאתה משתמש ב-API הרשמי של המודל שלו; כבה זאת תחת _Settings > General > Upload Session Log_ בממשק הדפדפן שלו. משוב שאתה שולח אליו מועלה גם הוא יחד עם ה-session, אלא אם תפעיל אותו עם `DSH_TELEMETRY_MODE=DISABLED`.

### סוכן ברירת המחדל

בחר את סוכן ברירת המחדל שלך עם `omarchy default agent <name>` או תחת _Setup > Defaults > Agent_ בתפריט Omarchy (`Super + Space`). אם הסוכן עדיין לא מותקן, בחירה בו תתקין אותו תחילה. Omarchy חדשה תזמין אותך לבצע את הבחירה הזו בהתראה חד-פעמית.

בחירה ב-Claude גם מנסה להגדיר את תוסף הדפדפן שלו עבור Chromium, Chrome, Brave, Brave Origin ו-Edge. הגדרת התוסף חלה על כל המשתמשים ועלולה לבקש את סיסמת המערכת שלך; ביטול או התקנת תוסף שנכשלה עדיין בוחרים ב-Claude ומפעילים אותו. הפעל מחדש את הדפדפן, הפעל את התוסף אם תתבקש, והיכנס ל-Claude כדי לסיים את חיבורו. הרץ `/chrome` ב-Claude כדי לבדוק את החיבור. Firefox ו-Zen לא תומכים בתוסף הזה. אם Claude כבר היה ברירת המחדל שלך לפני שההגדרה הזו נוספה, בחר בו שוב כדי להתקין את התוסף.

לאחר שבחרת, `Super + Shift + Ctrl + A` מפעיל את סוכן ברירת המחדל בחלון terminal ייעודי (או מעלה את הבוחר אם עדיין לא בחרת). אפשר גם להפעיל אותו ישירות למשימה עם `omarchy agent prompt "Review this project"`. Freebuff ו-DeepSeek Harness לא מקבלים prompt התחלתי, ולכן הם נפתחים כשה-prompt נמצא בלוח שלך להדבקה במקום זאת. סוכנים המופעלים כך רצים ללא השגחה במצבי אל-תעצור-לשאול המתאימים שלהם, אז תהיה מוכן לכך שהם באמת יעשו דברים! ל-MiniMax Code אין מצב כזה עבור ה-sessions האינטראקטיביים שלו, ולכן הוא מבקש הרשאות כרגיל. ומאחר שסוכנים מסרבים לזכור אמון עבור ספריית הבית שלך, הפעלות מ-`$HOME` מתחילות ב-`~/Work` במקום זאת.

יש גם קיצורי terminal: `a` מריץ את סוכן ברירת המחדל בתוך ה-terminal הנוכחי, בעוד `c`, `cx` ו-`cy` מפעילים את OpenCode, Claude Code ו-Codex ישירות (שוב במצבי האישור האוטומטי שלהם). שינויי ערכת נושא מסתנכרנים גם לסוכנים: Claude Code, Pi, OpenCode ו-Hermes (לאחר ש-Omarchy התקינה אותו) כולם הולכים בעקבותיך כשאתה מחליף את ערכת הנושא של Omarchy.

### פאנל הסוכנים

בסרגל העליון יש סמל סוכנים. לפני שהגדרת סוכן, הפאנל שלו מדריך אותך בכניסה ל-Claude, Codex או Grok, והראשון שבהם הופך לסוכן ברירת המחדל שלך. לאחר מכן, הפאנל שם כל מנוי בעמוד אחד: כל סוכן וחשבון עם התוכנית שלו, מד לכל אחת ממגבלות ה-session של 5 שעות והמגבלות השבועיות שלו יחד עם הזמן עד לאיפוסו (רחף כדי לראות את האחוז המדויק), או היתרה הנותרת ששולמה מראש, תחת שורה שמסתובבת בין מה שהשתמשת בו בכולם, כמו טוקנים השבוע והמודל שהשתמשת בו הכי הרבה. תחת _Make something_ הוא מציע prompt-ים התחלתיים לערכת נושא, תוסף או אפליקציה חדשים, שמעבירים את המשימה לסוכן ברירת המחדל שלך. אפליקציות נבנות באותה דרך שבה נבנו Hype, Monologue ו-Omacut של Omarchy עצמה, ב-C++ וב-Qt Quick, לפי מיומנות הסוכן omarchy-app, והמהדר וחלקי ה-Qt שהם צריכים מגיעים מותקנים. Claude Code, Codex, Grok, Kimi, Cursor והקצאת Grok Bot שלו, GitHub Copilot, Muse, Antigravity, Kimchi ו-Devin מכוסים מהקופסה עם המגבלות שלהם, ו-Hermes, Mistral Vibe ו-Qwen Code מציגים את ה-sessions והטוקנים שלהם לאחר שהשתמשת בהם. גם תוכניות ומפתחות של ספקים שאתה משתמש בהם דרך pi, omp או opencode מופיעים: OpenCode Zen ו-Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan ו-Synthetic עם המגבלות שלהם; Fireworks, OpenRouter ו-DeepSeek עם היתרות ששולמו מראש שלהם; והמודלים שאתה מריץ על החומרה שלך תחת Local models. כל סוכן נספר פעם אחת, תחת מי שמחייב עליו, לא משנה דרך כמה harnesses אתה מפעיל אותו.

לחץ לחיצה שמאלית על סמל הסרגל כדי לפתוח את הפאנל, ולחיצה ימנית כדי להפעיל את סוכן ברירת המחדל שלך. רשומות השימוש שמאחוריו נוצרות מחדש כל 15 דקות על ידי `omarchy agent usage-update`, והפאנל יכול אפילו למזג שימוש מהמכונות האחרות שלך דרך תיקייה מסונכרנת. ראה את ה-README תחת `$OMARCHY_PATH/shell/plugins/agents/` להגדרות המלאות.

### מספר מנויים

אם אתה משלם על יותר מתוכנית Claude, Codex או Grok אחת — Max אישית ואחת של העבודה, נניח — Omarchy יכולה להשאיר את כולן מחוברות ולנוע ביניהן. הוסף מנוי עם ה-+ בפאנל הסוכנים, שמדריך אותך בכך ממש שם, או עם `omarchy agent account add claude Work` (או `codex`, או `grok`). זה מתקין את ה-CLI אם הוא חסר. החשבון הראשון של ספק נכנס דרך הדפדפן הרגיל שלך, ממש במקום שבו ה-CLI תמיד מחפש. כל אחד אחריו נכנס דרך חלון פרטי, כדי שהחשבון שהדפדפן שלך כבר מחובר אליו לא ייבחר בטעות; היכנס שם כחשבון שאתה מוסיף, וסגור תחילה כל חלון פרטי שכבר פתוח אצלך. לעולם אל תצא מה-CLI כדי לעשות זאת: יציאה מבטלת את הכניסה השמורה, ואת החשבון הזה יהיה צריך להוסיף שוב.

כדי להעתיק את כניסות המנוי שלך למכונת Omarchy אחרת דרך SSH, הרץ `omarchy agent account copy user@laptop`. השולח מספק מקלט זמני כשאין אחד מותקן ביעד, כך שמכונות Omarchy ישנות יותר יכולות לקבל חשבונות בלי עדכון. מקלטים מותקנים מקבלים עדיפות. זה מעתיק את כל מנויי Claude, Codex ו-Grok; הוסף שמות ספקים כדי לבחור בהם, כמו ב-`omarchy agent account copy laptop claude`. שמות החשבונות ומזהי הפקודות תואמים את המקור, כולל חשבונות שכבר קיימים ביעד. חשבונות יעד לא קשורים מקבלים סיומת מספרית אם שמותיהם מתנגשים, והגדרות, מיומנויות, תוספים והיסטוריית שיחות נשארים מקומיים לכל מכונה.

פרטי ההתחברות הקיימים ביעד נשמרים. חשבון מקור שכבר מחובר שם מסונכרן בשמו בלי להחליף את פרטי ההתחברות שלו; חשבונות אחרים נוספים לצידו. כדי להחליף פרטי התחברות שמורים עבור חשבונות תואמים, השתמש ב-`omarchy agent account copy --replace laptop claude` לאחר שסיימת את ה-sessions של החשבון הזה ביעד. יעד חדש מקבל גם את החשבון הפעיל והעדפות ההחלפה של המקור; יעד מבוסס שומר על שלו.

פרטי התחברות עוברים דרך SSH ומאוחסנים בקבצים פרטיים ביעד, לכן העתק רק למכונות שאתה סומך עליהן. זו העתקה חד-פעמית, לא סנכרון מתמשך. טוקני רענון של Codex עלולים להיות מוחלפים על ידי מכונה אחרת, ולהשאיר כניסה מועתקת הזקוקה לחידוש; כניסות נפרדות נשארות הבחירה האמינה ביותר לשימוש בו-זמני במספר מכונות. ראה [הנחיות אימות החשבון של Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

חשבון אחד לכל ספק פעיל, וכל session חדש מתחיל כמוהו: `cx`, `cy`, `claude`, `codex` או `grok` plain, כל דבר המופעל דרך `omarchy agent`, וסקריפטים או עורכים שמוצאים את ה-CLI ב-`PATH`. החלף עם `omarchy agent account use work` (וחזרה עם `omarchy agent account use main`), או בפאנל על ידי לחיצה על מספר של חשבון ולאחר מכן `Enter` (או לחיצה על כפתור ה-Use שלו). Sessions שכבר רצים נשארים על החשבון שהם התחילו איתו. היסטוריית שיחות, הגדרות, מיומנויות ותוספים משותפים בין חשבונות, כך ש-`claude --continue` באותה תיקייה ממשיך איפה שהפסקת בחשבון החדש.

עם יותר מחשבון אחד, הפאנל מציג את מגבלות כל חשבון זו לצד זו, כשהפעיל מסומן. כברירת מחדל Omarchy מודיעה לך כשהחשבון הפעיל עובר 95% ממגבלה, ולחיצה על ההתראה מחליפה לחשבון עם הכי הרבה מרווח. רחף מעל שורת חשבון בפאנל ולחץ על Autoswitch שמופיע לצד Use (או לחץ `m`), או הרץ `omarchy agent account mode auto`, כדי שהוא יחליף בעצמו במקום זאת; בזמן שהוא פעיל, Autoswitch תופס את מקומו של Use, ולחיצה עליו שוב חוזרת להתראות. הוסף מספר כדי לשנות את הסף, כמו ב-`omarchy agent account mode auto 90`. אם כל חשבון מעל הסף, תשמע על כך פעם אחת, יחד עם איזה חשבון מתפנה ראשון. בזמן שחשבון פעיל נמצא בתוך 15 נקודות מהסף שלו (80% בברירת המחדל), מגבלותיו נבדקות כל שלוש דקות ולא כל 15.

`omarchy agent account list` מציג כל חשבון ואת מגבלותיו האחרונות, `omarchy agent account remove work` שוכח אחד, ו-`omarchy agent account rename primary Hey` משנה שם של אחד (או לחץ על שם חשבון בפאנל). הפקודות הללו עובדות על חשבונות סוכן ברירת המחדל שלך; כדי להגיע לספק האחר, ציין אותו תחילה, כמו ב-`omarchy agent account use codex side`. הכניסה שכבר הייתה לך ב-`~/.claude` או ב-`~/.codex` היא חשבון ה-_Main_ ונשארת איפה שהיא. חשבון שהושאר ללא שימוש יותר מכשמונה שעות עלול להציג _Sign-in required_; לחץ עליו כדי להיכנס לחשבון הזה שוב ממש בפאנל, או התחל בו session, שמרענן את הכניסה מעצמו. שרתי MCP שהיו לך כשהחשבון נוסף באים איתו אליו, אבל כאלה שתוסיף מאוחר יותר עם `claude mcp add` מגיעים רק לחשבון שהוספת אותם בו. Claude Desktop וכלים המוגדרים עם נתיב מוחלט לקובץ בינארי של CLI לא עוקבים אחרי ההחלפה. `CLAUDE_CONFIG_DIR`, `CODEX_HOME` או `GROK_HOME` מפורשים מקבלים עדיפות על פני החשבון הנבחר.

### אבחון קריסות

Omarchy עוקבת אחר systemd-coredump לאיתור קריסות תהליכים. כשמשהו עושה segfault, תקבל התראת “Process crashed” — לחץ עליה, והקריסה מועברת לסוכן ברירת המחדל שלך יחד עם מיומנות diagnose-crash של Omarchy, שמדריכה את הסוכן בביסוס העובדות מה-core dump ובהחלטה אם הקריסה שווה דיווח ל-upstream. אפשר גם להריץ אותה ידנית מול כל PID מתוך `coredumpctl list` עם `omarchy agent crash <pid>`.

המעקב פעיל כברירת מחדל. כבה אותו תחת _Trigger > Toggle > Crash Capture_ (או עם `omarchy toggle crash-capture`) וההתראות ייפסקו; `omarchy agent crash <pid>` עדיין עובד ידנית.

אפשר גם להשתיק קריסות תוכנית אחת בכל פעם, וזה מה שהאבחון מציע לך בסוף. `omarchy crash mute hyprland` מפסיק את ההתראות עבור התוכנית הזו בלבד, `omarchy crash mute hyprland off` מחזיר אותן, ו-`omarchy crash mute` לבדו מרט את מה שהשתקת. הוא מקבל את נתיב הקובץ הבינארי בשמחה כמו את שמו, כך ש-`omarchy crash mute /usr/bin/hyprland` עושה אותו דבר. שים שם עם רווח במרכאות, כמו ב-`omarchy crash mute 'Some App'`. כל השאר עדיין שולח התראות, והתוכנית המושתקת עדיין קורסת — זה מסתיר את התזכורת, זה לא מתקן כלום.

### אפליקציות שולחניות

תפריט _Install > AI_ כולל גם כמה אפליקציות AI גרפיות: אפליקציית שולחן העבודה של ChatGPT, אפליקציית שולחן העבודה של Claude (גרסת ה-beta של Anthropic ל-Linux, עם לשוניות Chat, Cowork ו-Claude Code), Grok Bot לשיחה עם המודלים של xAI, Herdr Desktop, Hermes Desktop, OpenClaw, אפליקציית שולחן העבודה של Perplexity ו-T3 Code. Grok Bot היא אפליקציית הצ'אט לשולחן העבודה. סוכן הקידוד הוא פקודת `grok`.

Hermes Desktop היא זו שכדאי להכיר, כי למכונה יש Hermes אחד, והוא של האפליקציה: Hermes מותקן רק אי-פעם דרך האפליקציה, ופקודת `hermes` שסוכן ברירת המחדל מריץ היא של האפליקציה. בחירה ב-Hermes כסוכן ברירת המחדל מתקינה אותו דבר שהערך _Install > AI_ מתקין: את החבילה, ו-runtime של Hermes תחת `~/.hermes` המוגדר על ידי המתקין של Hermes עצמו, שלוקח כמה דקות בפעם הראשונה. ה-runtime הזה הוא ה-Hermes האחד שפקודת `hermes` ב-terminal, סוכן ברירת המחדל והאפליקציה כולם משתמשים בו, והוא מעדכן את עצמו עם `hermes update` ולא מחכה לגרסת Omarchy. התקנתו גם נותנת ל-Hermes את ערכת הנושא של Omarchy כ-skin בשם `omarchy`, שכל משטחי Hermes עוקבים אחריו כשאתה מחליף ערכות נושא; בחר אחר תחת הגדרות Appearance של Hermes או עם `/skin` אם אתה מעדיף שלא, ו-Omarchy משאירה את הבחירה הזו בשקט. הסרת האפליקציה תחת _Remove > AI_ סוגרת תחילה את Hermes, כולל ה-gateway, לוקחת איתה את ה-runtime הזה, ושומרת את הצ'אטים, הזיכרונות והמיומנויות ש-Hermes כתב לעצמו אלא אם תגיד אחרת: היא שואלת, כשברירת המחדל היא לא, אם גם הנתונים הללו והגדרות החיבור שלך צריכים ללכת.

חוויית שולחן העבודה של OpenClaw היא ה-Control UI שלו, שנפתח כאפליקציית web המגובה ב-gateway מקומי משלו. OpenClaw חי ב-`~/.openclaw` ומעדכן את עצמו: השתמש בכפתור “Update Gateway” של ה-Control UI או הרץ `openclaw update`, וה-gateway יופעל מחדש על הגרסה החדשה. Omarchy רק בוחרת את הגרסה שהתקנה חדשה מתחילה ממנה. הסרת OpenClaw תחת _Remove > AI_ לוקחת איתה את שירות ה-gateway ואת האפליקציה ולאחר מכן שואלת אם גם `~/.openclaw` צריך ללכת, מאחר שהוא מחזיק את הצ'אטים ופרטי ההתחברות שלך לצד OpenClaw עצמו ו-runtime-י התוספים שהוא מוריד; ברירת המחדל שומרת אותו, והתקנת OpenClaw שוב מרימה אותו בחזרה.

Herdr Desktop היא אפליקציית שולחן העבודה [Herdr](https://herdr.dev): מרחבים, לשוניות וחלוניות של terminal-ים וסוכני קידוד שממשיכים לרוץ בליבה שלה כשאתה סוגר את החלון. היא מגיעה מהמתקין של Herdr עצמו ולא מחבילה, לכן היא חיה ב-`~/.local/share/herdr-app`, מביאה איתה את הליבה שלה ב-`~/.local/bin/herdr-core` כשעדיין אין לך אחת, ומעדכנת את שניהם. היא יושבת לצד פקודת `herdr` ש-Omarchy מספקת ב-`Super + Ctrl + Return` ולא מחליפה אותה. התקנתה בוחרת את ערכת הנושא Omarchy של Herdr, שעוקבת מאז אחרי ערכת הנושא של Omarchy שלך. Herdr שומרת ערכת נושא אחת למצב בהיר ואחת לכהה, לכן לאחר מעבר בין ערכת נושא כהה לבהירה של Omarchy, בחר שוב ב-Omarchy בבוחר ערכות הנושא של Herdr עבור המצב האחר.

T3 Code רץ מגרסת ה-AppImage הרשמית שלו ב-`~/.local/share/t3code` ולא מחבילה, לכן הוא מעדכן את עצמו. התקנתו שואלת אם להתחיל בערוץ Stable או Nightly; החלף מאוחר יותר בהגדרות T3 Code. ה-threads וההגדרות שלך חיים ב-`~/.t3`, והסרת T3 Code תחת _Remove > AI_ לוקחת אותם איתה.

### מודלים מקומיים

הרץ מודל פתוח על המכונה שלך עבור סוכני הקידוד שלך. ה-prompt-ים והקוד שלך נשארים על המכונה; שום דבר שנשלח למודל לא עוזב אותה. התחל עם:

```bash
omarchy agent local use best
```

או, בפאנל הסוכנים בסרגל העליון, בחר + ולאחר מכן Local AI, שמופיע כשמודל מתאים למכונה הזו. בפעם הראשונה, זה מתקין את Podman, שמריץ את המודלים, ובמכונת NVIDIA את ערכת כלי ה-container של NVIDIA, שנותנת להם את ה-GPU. Omarchy אז בוחרת את המודל המומלץ למכונה הזו, מורידה אותו ומפעילה אותו. צפה להורדה של עשרות GB ולכך שרוב זיכרון המכונה יהיה בשימוש בזמן שהמודל רץ: Flash Next משתמש בכ-100 GiB עם הקשר ה-256K המלא שלו. אם מודלים אחרים מחזיקים את הזיכרון שהוא צריך, הוא מוגדר כמופסק, מוכן להתחיל ברגע שתעצור אחד. המודל נעצר ביציאה; עצור אותו בעצמך כשאתה צריך את הזיכרון למשהו אחר.

`omarchy agent local list` מציג את האפשרויות ומסביר למה חלקן לא מתאימות. כדי להגדיר אחד אחר, הרץ `omarchy agent local use <recipe>`. כיום, `qwen3.8-flash-next-gufo` ו-`qwen3.8-27b-gufo` זמינים למכונות Strix Halo של 128 GB; ה-27B לוקח כ-40 GiB, כך שהוא משאיר מקום לעבודה אחרת. מתכונים והמלצות חדשים מגיעים עם `omarchy update`, דרך החבילה.

כל מודל שאתה מגדיר מקבל שורה משלו בפאנל הסוכנים, לצד המנויים שלך: play כדי להפעיל אותו, pause כדי לעצור אותו ולשחרר את זיכרונו, וכפתור ה-terminal כדי לפתוח עליו את הסוכן שלך. כמה יכולים לרוץ בבת אחת כשהם מתאימים יחד בזיכרון; אם אחד לא מתאים, Omarchy אומרת איזה מודל רץ לעצור. גרור שורות כדי לסדר אותן מחדש, ולחץ Delete על שורה נבחרת כדי להסיר מודל ואת ההורדה שלו.

משורת הפקודה, `omarchy agent local start <recipe>` ו-`omarchy agent local stop <recipe>` עושים אותו דבר, `omarchy agent local status` מציג כל מודל, ו-`omarchy agent --local` פותח את סוכן ברירת המחדל שלך על המודל האחרון שהפעלת (pi אם סוכן ברירת המחדל שלך לא יכול להשתמש במודל מקומי). גם כל לקוח תואם OpenAI יכול להתחבר: `status` מציג את כתובת כל מודל (הראשונה היא `http://127.0.0.1:11435/v1`), שם המתכון הוא המודל, והמפתח נמצא ב-`~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` מוחק מודל ואת ההורדות שאף מודל אחר לא משתמש בהן.

Runtime-ים של צד שלישי מסומנים עם המפיץ שלהם. Omarchy מריצה כל מודל ללא גישה לרשת.

### מודלי LLM מקומיים

Omarchy ממליצה על שתי דרכים להרצת מודלי LLM מקומיים: LM Studio ו-Ollama. LM Studio מספק ממשק GUI למציאת מודלים במשקל פתוח, התקנתם והרצתם. זו דרך מעולה להתחיל בקלות. Ollama מציע CLI לעשות זאת באופן דומה. אבל אם אתה חדש במודלים מקומיים, הייתי מתחיל עם LM Studio. אפשר להתקין כל אחד מהם תחת _Install > AI_ בתפריט Omarchy.

### מיומנות Omarchy

מיומנויות סוכן עוזרות ל-AI להשתמש בכלים ספציפיים בדרך ספציפית, ו-Omarchy מגיעה עם מיומנות ברירת מחדל להתאמת המערכת. כמו לכוונן את קונפיגורציית Hyprland שלך, להתאים את הסרגל, או אפילו ליצור ערכת נושא חדשה מאפס. היא מקושרת בסימבולינק לתיקיות המיומנויות של Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` וכל `~/.hermes/profiles/*/skills`), והמיקום הגנרי `~/.agents/skills`, כך שרוב ה-harnesses קולטים אותה אוטומטית.

אבל עליך להתייחס למיומנות הזו כאל ניסיונית. מודלים שונים ישתמשו בה במידת הצלחה שונה. הכי טוב לרוץ תחילה במצב plan, כך שיהיה לך מושג מה הסוכן היה רוצה לשנות. ואז תהיה מוכן לבטל שינויים או אפילו להפעיל את `omarchy reinstall configs`, אם הסוכן מבלגן הכול.
