# Windows VM

Omarchy מציעה דרך קלה להריץ את Windows דרך VM של Docker במכונות x86_64. אפשר להתקין אותה באמצעות _Install > Windows_ מתפריט Omarchy (`Super + Space`).

המכונה שלך זקוקה לווירטואליזציית KVM בשביל זה, ורוב המכונות תומכות בכך — אבל לפעמים היא כבויה ב-BIOS, והמתקין יודיע לך אם זה המצב. תצטרך גם מקום פנוי בדיסק: כל מה שתיתן ל-Windows, ועוד כ-10GB עבור התמונה עצמה.

המתקין שואל כמה RAM, כמה ליבות CPU וכמה מקום בדיסק להקצות (64GB או יותר זה הרף ההגיוני), ואז מבקש שם משתמש וסיסמה ל-Windows. אם תשאיר אותם ריקים, תקבל `docker` / `admin`. ההורדה לוקחת זמן — 10-15 דקות זה נורמלי — ואפשר לעקוב אחר ההתקדמות בדפדפן בכתובת `http://127.0.0.1:8006`. הדפדפן יבקש את אותו שם משתמש וסיסמה לפני פתיחת המסוף.

## שימוש בה

לאחר ההתקנה, הפעל את _Windows_ ממפעיל היישומים. זה יפעיל את ה-VM אם היא עדיין לא פועלת ויחבר אותך אליה דרך RDP, במסך מלא. תן לה 15-30 שניות בהתחלה קרה.

ההפעלה ב-RDP מעבירה שמע, את המיקרופון שלך ולוח העתקה משותף, כך שהעתקת טקסט בין Linux ל-Windows פשוט עובדת. הרזולוציה מתאימה את עצמה לחלון שלך, ו-Omarchy מעבירה את קנה המידה של התצוגה שלך, כך שזה לא נראה כמו בלגן מטושטש במסך HiDPI.

כאשר סוגרים את חלון ה-RDP, ה-VM נכבית אוטומטית. אם אתה מעדיף להשאיר אותה פועלת — למשל יש לך משהו שממשיך לעבוד בתוכה — הפעל אותה במקום זאת עם `omarchy windows vm launch --keep-alive`.

שאר הפקדים נמצאים באותה פקודה:

```bash
omarchy windows vm status    # is it running?
omarchy windows vm stop      # shut it down
omarchy windows vm launch    # start and connect
```

## שיתוף קבצים

הספרייה `~/Windows` בספריית הבית שלך משותפת אוטומטית עם ה-VM. שים שם קבצים אם אתה רוצה שהם יהיו נגישים ל-Windows. ל-VM אין גישה לשום חלק אחר של מערכת הקבצים שלך, כך שאתה מוגן מכל דבר מזיק בצד של Windows. הדיסק הווירטואלי שלה עצמה זמין ב-`~/.windows`.

נתיבי הבית המוכרים האלה נשארים במערכות הקבצים שלהם. הם יכולים להיות גם קישורים סמליים לספריות שבבעלותך, מה שימושי כאשר הדיסק הווירטואלי נמצא בכונן גדול יותר. המתקין מודד את המקום הפנוי במערכת הקבצים שמכילה בפועל את `~/.windows`, ולא בהכרח במערכת הקבצים שמכילה את ספריית הבית שלך.

שמור על נתיבי הדיסק והשיתוף כספריות נפרדות שאינן חופפות. ההסרה מרוקנת בכוונה את ספריית הדיסק, אך משמרת את ספריית השיתוף. מיד לפני המחיקה, Omarchy מבצעת בדיקת הכלה מוגבלת ומסרבת להסיר כל דבר אם הבדיקה חורגת מהזמן שהוקצב לה או אינה יכולה להוכיח ששני העצים נפרדים.

לפני שה-VM מתחילה, Omarchy פותחת ומקבעת את שתי הספריות האלה, ואז מבצעת bind-mount של ה-inodes המדויקים של הספריות אל עוגנים פרטיים לכל משתמש מתחת ל-`/var/lib/omarchy/windows/mounts`. ‏Docker רואה רק את העוגנים האלה, המוגנים על ידי root. זה משמר מיקומי דיסק מותאמים אישית, ובו בזמן מונע מתהליך אחר הפועל כמשתמש שלך להחליף נתיב שנבדק לפני שהקונטיינר בעל ההרשאות משתמש בו. ספריות הדיסק והשיתוף הקיימות מהודקות למצב `0700` במהלך ההעברה, כך שחשבונות מקומיים אחרים אינם יכולים לעיין בתוכן שלהן.

היציאות של ה-VM מאוגדות ל-localhost בלבד, כך ששום דבר ברשת שלך אינו יכול להגיע למכונת Windows. מסוף האינטרנט דורש גם את שם המשתמש והסיסמה של Windows שהוגדרו, מה שמונע מחשבון מקומי אחר להפעיל את ה-VM דרך יציאה 8006.

## מגבלות ורישוי

אין GPU passthrough בהגדרה הזו, כך שהיא אינה מתאימה למשחקים או לעריכת וידאו. זו דרך מצוינת להריץ את Microsoft Office או כל דבר אחר שאתה פשוט חייב.

הגרסה המותקנת היא Windows 11 Pro, לא מופעלת. תזדקק למפתח רישיון משלך כדי להשתמש בתכונות המוגבלות.

אם המחשב הזה הגיע עם Windows, מפתח ה-OEM עדיין נמצא בקושחה גם לאחר התקנת Omarchy. הדפס אותו עם `omarchy windows key`. המפתח הזה קשור למכונה הזו — הוא יפעיל את Windows שיותקן מחדש על החומרה הזו, אבל בדרך כלל הוא לא יפעיל את ה-VM.

אפשר לשנות את הקצאת המשאבים מאוחר יותר על ידי הרצת `omarchy windows vm install` בטרמינל, שכותבת מחדש את התצורה של ה-VM לפי התשובות שלך. קובץ ה-compose עצמו נמצא כעת ב-`/var/lib/omarchy/windows/docker-compose.yml` ובבעלות root — זה בכוונה, כך שתהליך הפועל כמשתמש שלך אינו יכול לכתוב אותו מחדש ולגרום להפעלה בעלת ההרשאות לעגן את כל הדיסק שלך לתוך הקונטיינר. אם אתה צריך לערוך אותו ידנית (למשל כדי לעגן התקן USB), ערוך אותו עם `sudo` וראה את כל האפשרויות ב[פרויקט Dockur Windows](https://github.com/dockur/windows).

כדי להיפטר מכל העניין, השתמש ב-_Remove > Windows_ מתפריט Omarchy. זה מוחק את הדיסק של ה-VM ב-`~/.windows` ואת כל מה שמותקן בתוך Windows, אז העתק תחילה מה-VM כל מה שאתה צריך. תיקיית השיתוף `~/Windows` שלך נשארת כמות שהיא.
