# כלי פיתוח

## עורכים חלופיים

Omarchy מגיעה עם Plain כעורך ברירת המחדל בהתקנות חדשות ועם [Neovim](https://neovim.io/) מותקן מראש, אבל אם תרצו משהו קצת יותר מיינסטרימי ומוכר, תוכלו לפתוח את תפריט Omarchy (`Super + Space`) ולראות את האפשרויות תחת _התקנה > עורך_. רשומים שם VSCode, Cursor, Zed, Sublime Text, Helix, Vim ו-Emacs. אם אינכם מוצאים את מה שאתם מחפשים, בדקו את _התקנה > חבילה_, ובדקו אם הוא אינו קיים כחבילת Arch (ואם לא, נסו את _התקנה > AUR_ כדי לבדוק ב-AUR).

עורך `vi` המקורי זמין גם הוא מהקופסה. הריצו `vi filename` כדי לערוך קובץ בטרמינל.

התאמת ערכת נושא מוצעת עבור `VSCode`, `Cursor`, `VSCodium` ו-`Helix`.

תוכלו לקבוע את עורך ברירת המחדל של המערכת תחת `Setup > Defaults > Editor`.

## סביבה

Omarchy תומכת בהגדרת שפע שלם של סביבות פיתוח דרך החלק _התקנה > פיתוח_ בתפריט Omarchy (`Super + Space`). תמצאו שם כמובן את _Ruby on Rails_, אבל גם את כל שלושת סביבות הריצה העיקריות עבור JavaScript (Node.js, Bun, Deno), וגם פריימוורקים פופולריים של PHP כמו Laravel ו-Symfony. אה, ויש גם Go, Rust, Python, Java, Elixir (עם Phoenix), .NET, OCaml, Zig, Clojure ו-Scala. זו בחירה רחבה מאוד!

רוב הסביבות האלה מנוהלות על ידי [Mise](https://mise.jdx.dev/). זהו כלי שמאפשר לכם להתקין ולהריץ גרסאות מרובות של שפת תכנות על אותה מכונה. זה כמו rbenv או rvm עבור Ruby או virtualenv עבור Python, אבל הוא עובד עבור שלל סביבות שונות.

כדי להתקין, נניח, את Ruby, תריצו `mise use -g ruby`, מה שגם יתקין את Ruby וגם יקבע אותה כברירת המחדל הגלובלית. או, אם בפרויקט שלכם יש קובץ .ruby-version, תוכלו פשוט להריץ `mise i` בשורש הפרויקט הזה.

## כלי CLI מותקנים מראש

Omarchy הופכת כלים כמו `gh`, `uv`, ורוב [סוכני הקידוד](17-ai.md) לזמינים דרך [ההתקנה העצלה של mise](https://mise.jdx.dev/dev-tools/shims.html#lazy-tools). בפעם הראשונה שאתם מריצים אחד מהם, mise מתקין אותו. סוכני קידוד בודקים אז אם יש עדכון לפני שהם רצים, לכל היותר פעם בארבע שעות; כלים אחרים, כמו `gh` ו-`uv`, עושים שימוש חוזר בגרסה המותקנת עד שתעדכנו.

תוכלו גם לבדוק את ברירות המחדל או להתקין אותן מראש:

```bash
mise ls --current              # List the tools configured for this directory
mise install gh               # Install one tool now
mise install --include-lazy    # Install all configured tools, including lazy tools
```

הריצו `omarchy update` כדי לעדכן כלים מותקנים יחד עם שאר Omarchy. הכינוי `mup` מעדכן רק כלים המנוהלים על ידי mise. כדי להוסיף כלי נוסף לתצורה שלכם, השתמשו ב-`mise use -g <tool>`.

התקנת Python מתקינה גם את `uv` דרך mise. הסרת סביבת הפיתוח של Python משאירה את `uv` זמין ככלי עצמאי.

### שימוש בהתקנה שלכם

הפקודות של mise קודמות ל-`~/.local/bin` ב-`PATH`, כך שכלי שהתקנתם בעצמכם, לדוגמה עם המתקין של Claude Code או של Cursor, עדיין מריץ את העותק של mise. אפליקציות המופעלות משולחן העבודה מוצאות גם הן את הפקודות של mise לפני חבילות המערכת, כך שאפליקציה המריצה `gh` מקבלת את העותק של mise גם אם התקנתם את `github-cli` עם pacman, ו-mise מתקין את העותק הזה בפעם הראשונה. כדי להשתמש בשלכם במקום זאת, השביתו את העותק של mise ב-`~/.config/mise/config.toml`. לדוגמה, אם התקנתם את Cursor CLI בעצמכם:

```toml
[settings]
disable_tools = ["cursor-agent"]
```

אם כבר יש לכם טבלת `[settings]`, הוסיפו את הערך שם; הרחיבו רשימת `disable_tools` קיימת במקום להחליף אותה. ודאו שההתקנה שלכם נמצאת ב-`PATH`. השתמשו בשם הכלי של mise, שיכול להיות שונה מהפקודה שלו: `oh-my-pi` מספק את `omp`, לדוגמה. משגר סוכן ברירת המחדל מעדיף גם הוא Cursor או Muse שהמשתמש התקין ב-`~/.local/bin`.

### הסרת ברירות המחדל ושחזורן

_הסרה > התקנות מראש_ מסיר את אפליקציות הרשת, ה-TUIs והאפליקציות המותקנות מראש של Omarchy, וגורם ל-mise לדלג על הצהרות הכלים של Omarchy עבור המשתמש שלכם, על ידי הוספתן ל-`ignored_config_paths` ב-`~/.config/mise/miserc.toml`. _התקנה > התקנות מראש_ מחזיר אותן ומסיר את השורה הזאת שוב. כלים שאתם מצהירים עליהם בעצמכם, בתצורה שלכם או ב-`mise.toml` של פרויקט, ממשיכים לעבוד בכל מקרה. אם תבחרו סוכן ברירת מחדל או תתקינו את Python לאחר הסרת ההתקנות מראש, הכלי הזה מתווסף לתצורה שלכם. הגדרת mise חלה רק על המשתמש שלכם, ומשתמשים אחרים שומרים על הבחירה שלהם; האפליקציות הן חבילות, עם זאת, כך שהסרתן או שחזורן משנה אותן עבור כל מי שעל המכונה.

## Docker

[Docker](https://www.docker.com/) כמעט אינו זקוק להצגה. הוא מאפשר לכם להריץ קונטיינרים מבודדים, ו-Omarchy מתקינה כל מה שצריך כדי להריץ אותו היטב, כולל Docker עצמו ו-[Docker Compose](https://docs.docker.com/compose/).

כברירת מחדל המשתמש שלכם *אינו* נמצא בקבוצת `docker`. הקבוצה הזאת היא למעשה root ללא סיסמה — כל מה שבתוכה יכול להריץ `docker run -v /:/host` ולהשתלט על המכונה — כך שסקריפט סורר יחיד או תלות יחידה הרצים כמשתמש שלכם היו אחרת במרחק פקודה אחת מ-root. לכן בשורת הפקודה אתם מריצים את Docker עם `sudo` (`sudo docker ps`, `sudo docker compose up`), והכלים הגרפיים המתקשרים עם הדמון — ה-VM של Windows — מבקשים הרשאה כשהם זקוקים לה. אם אתם רוצים את הנוחות של הגדרה ללא קבוצה בחזרה ומבינים את הפשרה, הפעילו אותה מתוך **הגדרות > אבטחה > Sudoless Docker** (או הריצו `omarchy-setup-security-sudoless-docker`), מה שמוסיף אתכם לקבוצת `docker` לאחר אזהרה; אז `docker` רגיל והכינוי `d` עובדים שוב ללא `sudo`.

תוכלו להגדיר את מסדי הנתונים הנפוצים לפיתוח מקומי ב-Docker באמצעות _התקנה > פיתוח > Docker DB_ בתפריט Omarchy.

## GitHub CLI

[GitHub CLI](https://cli.github.com/) זמין כ-`gh` לעבודה עם מאגרים, issues ו-pull requests מהטרמינל. הריצו `gh auth login` כדי להתקין אותו בשימוש הראשון ולהתחבר, ואז `gh repo clone org/repo` כדי לשכפל מאגר. הריצו `gh --help` כדי לחקור את הפקודות שלו.

לממשק טרמינל ל-pull requests, הריצו את `ghui`; mise מתקין גם אותו בשימוש הראשון. [Lazygit](https://github.com/jesseduffield/lazygit) מותקן מראש לעבודה עם Git עצמו.
