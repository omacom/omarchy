# AI

Omarchy include launcher per gli agent di coding indicati di seguito senza sceglierne uno predefinito per te. Esegui un comando per installare la sua CLI al primo utilizzo, poi autenticati quando richiesto. Hermes è l'eccezione: al primo utilizzo non viene installato nulla per lui, e sceglierlo installa Hermes Desktop, come spiega _App desktop_ più avanti.

### Installare e aggiornare gli agent

A parte Hermes, questi agent usano l'installazione lazy di mise: il primo avvio installa la CLI, e gli avvii successivi la riutilizzano. mise controlla inoltre se per un agent installato è disponibile una nuova release al massimo una volta ogni quattro ore, subito prima dell'avvio o in background al prompt della shell. Se quell'aggiornamento fallisce o sei offline, viene eseguita la versione installata. `omarchy update` aggiorna gli agent installati insieme al resto di Omarchy, e `mup` aggiorna solo gli strumenti gestiti da mise.

L'updater proprietario di un agent, come `claude update`, `codex update` o un pulsante di aggiornamento in un'app, non aggiorna l'installazione gestita da mise. `codex update` fallisce, e `claude update` può segnalare successo installando però una copia separata che mise non traccia. Se preferisci usare l'installer e l'updater nativi di un agent, aggiungilo a `disable_tools`; vedi [Strumenti CLI preinstallati](18-development-tools.md#preinstalled-cli-tools).

Per installare tutti gli strumenti lazy configurati prima di averne bisogno, esegui `mise install --include-lazy`. Questo include anche gli altri strumenti CLI predefiniti di Omarchy oltre agli agent. Vedi [Strumenti CLI preinstallati](18-development-tools.md#preinstalled-cli-tools) per installare un singolo strumento o usare una tua installazione.

`grok` viene installato tramite il pacchetto first-party `grok` di mise, allo stesso modo di `claude` e `codex`. Esegui `grok`, oppure sceglilo sotto _Setup > Defaults > Agent_. Salta l'installer `curl | bash` su x.ai. Quel percorso mette una seconda copia in `~/.grok/bin`, la antepone su `PATH` e sovrascrive il wrapper di Omarchy.

`dsh` apre la sua UI nel browser su `127.0.0.1:3080`, con la directory di avvio come workspace predefinito. La sua UI nel browser non accetta un prompt iniziale, quindi `omarchy agent prompt` la apre con il prompt negli appunti da incollare. Omarchy lo avvia con il preset di permessi senza approvazione di DeepSeek. DeepSeek Harness carica i log di sessione su DeepSeek quando usi la sua API ufficiale per i modelli; disattivalo sotto _Settings > General > Upload Session Log_ nella sua UI nel browser. Anche i feedback che gli invii vengono caricati insieme alla sessione, a meno che tu non lo avvii con `DSH_TELEMETRY_MODE=DISABLED`.

### L'agent predefinito

Scegli il tuo agent predefinito con `omarchy default agent <name>` o sotto _Setup > Defaults > Agent_ nel Menu di Omarchy (`Super + Space`). Se l'agent non è ancora installato, sceglierlo lo installa prima. Un Omarchy appena installato ti inviterà a fare questa scelta con una notifica una tantum.

Scegliere Claude tenta anche di configurare la sua estensione per il browser per Chromium, Chrome, Brave, Brave Origin ed Edge. La configurazione dell'estensione si applica a tutti gli utenti e potrebbe chiederti la password di sistema; annullare o un'installazione dell'estensione fallita seleziona e avvia comunque Claude. Riavvia il browser, abilita l'estensione se richiesto e accedi a Claude per completare la connessione. Esegui `/chrome` in Claude per verificare la connessione. Firefox e Zen non supportano questa estensione. Se Claude era già il tuo predefinito prima che questa configurazione venisse aggiunta, selezionalo di nuovo per installare l'estensione.

Una volta scelto, `Super + Shift + Ctrl + A` avvia l'agent predefinito in una finestra terminale dedicata (oppure mostra il selettore se non hai ancora scelto). Puoi anche avviarlo direttamente su un compito con `omarchy agent prompt "Review this project"`. Freebuff e DeepSeek Harness non accettano un prompt iniziale, quindi si aprono con il prompt negli appunti da incollare. Gli agent avviati in questo modo lavorano senza supervisione nelle rispettive modalità non fermarti a chiedere, quindi preparati al fatto che facciano davvero cose! MiniMax Code non ha una modalità del genere per le sue sessioni interattive, quindi chiede i permessi come al solito. E poiché gli agent si rifiutano di ricordare la fiducia per la tua directory home, gli avvii da `$HOME` partono invece in `~/Work`.

Ci sono anche scorciatoie da terminale: `a` esegue l'agent predefinito inline nel terminale corrente, mentre `c`, `cx` e `cy` avviano direttamente OpenCode, Claude Code e Codex (sempre nelle loro modalità con approvazione automatica). Anche i cambi di tema si sincronizzano con gli agent: Claude Code, Pi, OpenCode ed Hermes (una volta che Omarchy lo ha installato) seguono tutti quando cambi il tema di Omarchy.

### Il pannello degli agent

La barra superiore ha un'icona degli agent. Prima che tu abbia configurato un agent, il suo pannello ti guida nell'accesso a Claude, Codex o Grok, e il primo diventa il tuo agent predefinito. Dopo di che, il pannello mette ogni abbonamento su un'unica pagina: ogni agent e account con il suo piano, un indicatore per ciascuno dei suoi limiti di sessione di 5 ore e settimanali con il tempo rimanente al reset (passa il mouse per la percentuale esatta), oppure il saldo prepagato rimanente, sotto una riga che ruota tra ciò che hai usato in tutti loro, come i token di questa settimana e il modello che usi di più. Sotto _Make something_ offre prompt iniziali per un nuovo tema, plugin o app che affidano il compito al tuo agent predefinito. Le app sono costruite allo stesso modo di Hype, Monologue e Omacut di Omarchy, in C++ e Qt Quick, seguendo la skill per agent omarchy-app, e il compilatore e i componenti Qt di cui hanno bisogno sono già installati. Claude Code, Codex, Grok, Kimi, Cursor e la sua quota Grok Bot, GitHub Copilot, Muse, Antigravity, Kimchi e Devin sono coperti fin da subito con i loro limiti, ed Hermes, Mistral Vibe e Qwen Code mostrano le loro sessioni e i token dopo che li hai usati. Compaiono anche i piani e le chiavi dei provider che usi tramite pi, omp o opencode: OpenCode Zen e Go, il Z.ai GLM Coding Plan, Ollama Cloud, il MiniMax Token Plan e Synthetic con i loro limiti; Fireworks, OpenRouter e DeepSeek con i loro saldi prepagati; e i modelli che esegui sul tuo hardware sotto Local models. Ogni agent viene contato una sola volta, sotto chi lo fattura, indipendentemente da quanti harness usi per gestirlo.

Fai clic sinistro sull'icona nella barra per il pannello, clic destro per avviare il tuo agent predefinito. I record di utilizzo dietro di esso vengono rigenerati ogni 15 minuti da `omarchy agent usage-update`, e il pannello può persino unire l'utilizzo dalle tue altre macchine tramite una cartella sincronizzata. Vedi il README sotto `$OMARCHY_PATH/shell/plugins/agents/` per tutte le impostazioni.

### Più abbonamenti

Se paghi più di un piano Claude, Codex o Grok — un Max personale e uno di lavoro, ad esempio — Omarchy può mantenerli tutti connessi e passare dall'uno all'altro. Aggiungi un abbonamento con il + nel pannello degli agent, che ti guida lì sul posto, oppure con `omarchy agent account add claude Work` (o `codex`, o `grok`). Installa la CLI se manca. Il primo account per un provider accede tramite il tuo browser normale, proprio dove la CLI cerca sempre. Ogni account successivo accede tramite una finestra privata, così l'account a cui il tuo browser è già connesso non viene scelto per errore; accedi lì come l'account che stai aggiungendo, e prima chiudi qualsiasi finestra privata che avevi già aperto. Non disconnetterti mai dalla CLI per farlo: disconnettersi revoca l'accesso salvato, e quell'account dovrebbe essere aggiunto di nuovo.

Per copiare gli accessi ai tuoi abbonamenti su un'altra macchina Omarchy via SSH, esegui `omarchy agent account copy user@laptop`. Il mittente fornisce un ricevitore temporaneo quando la destinazione non ne ha uno installato, così le macchine Omarchy più vecchie possono ricevere account senza un aggiornamento. I ricevitori installati hanno la precedenza. Questo copia tutti gli abbonamenti Claude, Codex e Grok; aggiungi i nomi dei provider per selezionarli, come in `omarchy agent account copy laptop claude`. I nomi degli account e gli ID dei comandi corrispondono alla sorgente, inclusi gli account già presenti sulla destinazione. Gli account di destinazione non correlati ricevono un suffisso numerico se i loro nomi sono in conflitto, e impostazioni, skill, plugin e cronologia delle conversazioni restano locali a ciascuna macchina.

Le credenziali di destinazione esistenti vengono mantenute. Un account sorgente già connesso lì ha il nome sincronizzato senza sostituire le sue credenziali; gli altri account vengono aggiunti accanto ad esso. Per sostituire le credenziali salvate per gli account corrispondenti, usa `omarchy agent account copy --replace laptop claude` dopo aver chiuso le sessioni di quell'account sulla destinazione. Una destinazione nuova riceve anche l'account attivo e le preferenze di cambio della sorgente; una destinazione già consolidata mantiene le proprie.

Le credenziali viaggiano tramite SSH e vengono archiviate in file privati sulla destinazione, quindi copia solo su macchine di cui ti fidi. Questa è una copia una tantum, non una sincronizzazione continua. I token di refresh di Codex possono essere ruotati da un'altra macchina, lasciando un accesso copiato bisognoso di rinnovo; accessi separati restano la scelta più affidabile per l'uso simultaneo su più macchine. Vedi la [guida all'autenticazione degli account di Codex](https://developers.openai.com/codex/auth/ci-cd-auth).

Un account per provider è attivo, e ogni nuova sessione parte come tale: `cx`, `cy`, un semplice `claude`, `codex` o `grok`, qualsiasi cosa lanciata tramite `omarchy agent`, e script o editor che trovano la CLI su `PATH`. Cambia con `omarchy agent account use work` (e torna indietro con `omarchy agent account use main`), oppure nel pannello premendo il numero di un account e poi `Enter` (o facendo clic sul suo pulsante Use). Le sessioni già in esecuzione restano sull'account con cui sono partite. Cronologia delle conversazioni, impostazioni, skill e plugin sono condivisi tra gli account, quindi `claude --continue` nella stessa cartella riprende da dove avevi lasciato sul nuovo account.

Con più di un account, il pannello mostra i limiti di ciascun account fianco a fianco, con quello attivo contrassegnato. Per impostazione predefinita Omarchy ti avvisa quando l'account attivo supera il 95% di un limite, e fare clic sulla notifica passa all'account con più margine. Passa il mouse sulla riga di un account nel pannello e fai clic su Autoswitch che compare accanto a Use (o premi `m`), oppure esegui `omarchy agent account mode auto`, per farlo cambiare da solo; mentre è attivo, Autoswitch prende il posto di Use, e farci clic di nuovo torna ad avvisare. Aggiungi un numero per cambiare la soglia, come in `omarchy agent account mode auto 90`. Se ogni account è oltre la soglia, lo saprai una volta, insieme a quale account si libererà per primo. Mentre un account attivo è entro 15 punti dalla sua soglia (80% con quella predefinita), i suoi limiti vengono controllati ogni tre minuti invece che ogni 15.

`omarchy agent account list` mostra ogni account e i suoi limiti più recenti, `omarchy agent account remove work` ne dimentica uno, e `omarchy agent account rename primary Hey` ne rinomina uno (o fai clic sul nome di un account nel pannello). Questi comandi funzionano sugli account del tuo agent predefinito; per raggiungere l'altro provider, nominalo prima, come in `omarchy agent account use codex side`. L'accesso che avevi già in `~/.claude` o `~/.codex` è l'account _Main_ e resta dov'è. Un account lasciato inutilizzato per più di circa otto ore può mostrare _Sign-in required_; fai clic su di esso per accedere di nuovo a quell'account direttamente nel pannello, oppure avvia una sessione in esso, che aggiorna l'accesso da sola. I server MCP che avevi quando un account è stato aggiunto lo seguono, ma quelli che aggiungi dopo con `claude mcp add` raggiungono solo l'account in cui li hai aggiunti. Claude Desktop e gli strumenti configurati con un percorso assoluto a un binario CLI non seguono il cambio. Un `CLAUDE_CONFIG_DIR`, `CODEX_HOME` o `GROK_HOME` esplicito ha la precedenza sull'account selezionato.

### Diagnosi dei crash

Omarchy osserva systemd-coredump per i crash dei processi. Quando qualcosa va in segfault, riceverai una notifica "Process crashed" — fai clic su di essa, e il crash viene affidato al tuo agent predefinito insieme alla skill diagnose-crash di Omarchy, che guida l'agent a stabilire i fatti dal core dump e a decidere se vale la pena segnalare il crash a monte. Puoi anche eseguirlo a mano su qualsiasi PID da `coredumpctl list` con `omarchy agent crash <pid>`.

L'osservazione è attiva per impostazione predefinita. Disattivala sotto _Trigger > Toggle > Crash Capture_ (o con `omarchy toggle crash-capture`) e le notifiche si fermano; `omarchy agent crash <pid>` continua a funzionare a mano.

I crash possono anche essere silenziati un programma alla volta, che è ciò che la diagnosi ti propone alla fine. `omarchy crash mute hyprland` ferma le notifiche solo per quel programma, `omarchy crash mute hyprland off` le riporta, e `omarchy crash mute` da solo elenca ciò che hai silenziato. Accetta il percorso del binario con la stessa felicità del suo nome, quindi `omarchy crash mute /usr/bin/hyprland` fa la stessa cosa. Metti tra virgolette un nome con uno spazio, come in `omarchy crash mute 'Some App'`. Tutto il resto continua ad avvisare, e il programma silenziato continua a crashare — questo nasconde il promemoria, non risolve nulla.

### App desktop

Il menu _Install > AI_ include anche alcune app AI grafiche: l'app desktop di ChatGPT, l'app desktop di Claude (la beta Linux di Anthropic, con schede Chat, Cowork e Claude Code), Grok Bot per chattare con i modelli di xAI, Hermes Desktop, OpenClaw, l'app desktop di Perplexity e T3 Code. Grok Bot è l'app di chat desktop. L'agent di coding è il comando `grok`.

Hermes Desktop è quella da conoscere, perché una macchina ha un solo Hermes, ed è quello dell'app: Hermes viene installato solo e sempre tramite l'app, e il comando `hermes` che l'agent predefinito esegue è quello dell'app. Scegliere Hermes come agent predefinito installa la stessa cosa che fa la voce _Install > AI_: il pacchetto, e un runtime di Hermes sotto `~/.hermes` configurato dall'installer proprietario di Hermes, che la prima volta richiede qualche minuto. Quel runtime è l'unico Hermes che usano il comando `hermes` da terminale, l'agent predefinito e l'app, e si aggiorna da solo con `hermes update` invece di aspettare una release di Omarchy. Installarlo dà anche a Hermes il tema di Omarchy come skin chiamata `omarchy`, che ogni superficie di Hermes segue quando cambi tema; scegline un'altra nelle impostazioni Appearance di Hermes o con `/skin` se preferisci che non lo faccia, e Omarchy lascia stare quella scelta. Rimuovere l'app sotto _Remove > AI_ chiude prima Hermes, gateway incluso, porta via quel runtime con sé, e mantiene le tue chat, i ricordi e le skill che Hermes ha scritto per sé, a meno che tu non gli dica diversamente: chiede, con no come predefinito, se anche quei dati e le tue impostazioni di connessione debbano sparire.

L'esperienza desktop di OpenClaw è la sua Control UI, che si apre come web app supportata dal suo gateway locale. OpenClaw vive in `~/.openclaw` e si aggiorna da solo: usa il pulsante "Update Gateway" della Control UI o esegui `openclaw update`, e il gateway si riavvia sulla nuova versione. Omarchy sceglie solo la release da cui parte un'installazione nuova. Rimuovere OpenClaw sotto _Remove > AI_ porta via con sé il servizio gateway e l'app e poi chiede se anche `~/.openclaw` debba sparire, poiché contiene le tue chat e credenziali insieme a OpenClaw stesso e ai runtime dei plugin che scarica; l'impostazione predefinita lo mantiene, e installare di nuovo OpenClaw lo riprende.

T3 Code viene eseguito dalla sua release ufficiale AppImage in `~/.local/share/t3code` invece che da un pacchetto, quindi si aggiorna da solo. Installarlo chiede se partire sul canale Stable o Nightly; cambia in seguito nelle impostazioni di T3 Code. I tuoi thread e le tue impostazioni vivono in `~/.t3`, e rimuovere T3 Code sotto _Remove > AI_ li porta via con sé.

### Modelli locali

Esegui un modello aperto sulla tua macchina per i tuoi agent di coding. I tuoi prompt e il tuo codice restano sulla macchina; nulla di ciò che viene inviato al modello la lascia. Inizia con:

```bash
omarchy agent local use best
```

Oppure, nel pannello degli agent nella barra superiore, scegli + e poi Local AI, che compare quando un modello si adatta a questa macchina. La prima volta, questo installa Podman, che esegue i modelli, e su una macchina NVIDIA il container toolkit di NVIDIA, che dà loro la GPU. Omarchy poi sceglie il modello consigliato per questa macchina, lo scarica e lo avvia. Aspettati un download di decine di GB e la maggior parte della memoria della macchina in uso mentre il modello è in esecuzione: Flash Next usa circa 100 GiB con il suo contesto completo da 256K. Se altri modelli occupano la memoria di cui ha bisogno, viene configurato fermo, pronto a partire una volta che ne fermi uno. Il modello si ferma alla disconnessione; fermalo tu quando ti serve la memoria per altro.

`omarchy agent local list` mostra le opzioni e spiega perché alcune non si adattano. Per configurarne un altro, esegui `omarchy agent local use <recipe>`. Oggi, `qwen3.8-flash-next-gufo` e `qwen3.8-27b-gufo` sono disponibili per macchine Strix Halo da 128 GB; il 27B occupa circa 40 GiB, quindi lascia spazio per altro lavoro. Nuove recipe e raccomandazioni arrivano con `omarchy update`, tramite il pacchetto.

Ogni modello che configuri ottiene la sua riga nel pannello degli agent, accanto ai tuoi abbonamenti: play per avviarlo, pausa per fermarlo e liberare la sua memoria, e il pulsante terminale per aprire il tuo agent su di esso. Più modelli possono funzionare contemporaneamente quando stanno insieme in memoria; se uno non ci sta, Omarchy dice quale modello in esecuzione fermare. Trascina le righe per riordinarle, e premi Delete su una riga selezionata per rimuovere un modello e il suo download.

Da riga di comando, `omarchy agent local start <recipe>` e `omarchy agent local stop <recipe>` fanno la stessa cosa, `omarchy agent local status` mostra ogni modello, e `omarchy agent --local` apre il tuo agent predefinito sull'ultimo modello che hai avviato (pi se il tuo agent predefinito non può usare un modello locale). Anche qualsiasi client compatibile con OpenAI può connettersi: `status` mostra l'indirizzo di ciascun modello (il primo è `http://127.0.0.1:11435/v1`), il nome della recipe è il modello, e la chiave è in `~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` elimina un modello e i download che nessun altro modello usa.

I runtime di terze parti sono etichettati con il loro editore. Omarchy esegue ogni modello senza accesso alla rete.

### LLM locali

Omarchy consiglia due modi per eseguire modelli LLM locali: LM Studio e Ollama. LM Studio fornisce un'interfaccia GUI per trovare modelli open-weight, installarli ed eseguirli. È un ottimo modo per partire facilmente. Ollama offre una CLI per fare lo stesso in modo simile. Ma se sei nuovo ai modelli locali, io partirei con LM Studio. Puoi installare l'uno o l'altro sotto _Install > AI_ nel Menu di Omarchy.

### La Skill di Omarchy

Le skill per agent aiutano l'AI a usare strumenti specifici in un modo specifico, e Omarchy include una skill predefinita per personalizzare il sistema. Come ritoccare la tua config di Hyprland, regolare la barra, o persino creare un nuovo tema da zero. È collegata tramite symlink nelle directory delle skill per Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` e ciascuna `~/.hermes/profiles/*/skills`), e nella posizione generica `~/.agents/skills`, così la maggior parte degli harness la rileva automaticamente.

Ma dovresti trattare questa skill come sperimentale. Modelli diversi la useranno con effetti diversi. È meglio eseguire prima in modalità plan, così hai un'idea di ciò che l'agent vorrebbe cambiare. E poi preparati a fare rollback delle modifiche o persino a invocare `omarchy reinstall configs`, se l'agent fa un disastro totale.
