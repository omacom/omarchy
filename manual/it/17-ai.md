# AI

Omarchy include launcher per gli agent di coding indicati sotto senza sceglierne uno predefinito per te. Esegui un comando per installare la sua CLI al primo utilizzo, poi autenticati quando richiesto. Hermes è l'eccezione: al primo utilizzo non viene installato nulla per lui e, scegliendolo, viene installato Hermes Desktop, come spiega _App desktop_ più sotto.

### Installazione e aggiornamento degli agent

Tranne Hermes, questi agent usano l'installazione lazy di mise: il primo avvio installa la CLI e gli avvii successivi la riutilizzano. mise controlla inoltre se per un agent installato è disponibile una nuova release al massimo una volta ogni quattro ore, subito prima del suo avvio o in background al prompt della shell. Se quell'aggiornamento fallisce o sei offline, viene eseguita la versione installata. `omarchy update` aggiorna gli agent installati insieme al resto di Omarchy, e `mup` aggiorna solo gli strumenti gestiti da mise.

L'updater proprietario di un agent, come `claude update`, `codex update` o un pulsante di aggiornamento in un'app, non aggiorna l'installazione gestita da mise. `codex update` fallisce e `claude update` può segnalare un successo installando però una copia separata di cui mise non tiene traccia. Se preferisci usare l'installer e l'updater nativi di un agent, aggiungilo a `disable_tools`; vedi [Strumenti CLI preinstallati](18-development-tools.md#preinstalled-cli-tools).

Per installare tutti gli strumenti lazy configurati prima di averne bisogno, esegui `mise install --include-lazy`. Questo include anche gli altri strumenti CLI predefiniti di Omarchy oltre agli agent. Vedi [Strumenti CLI preinstallati](18-development-tools.md#preinstalled-cli-tools) per installare un singolo strumento o usare una tua installazione.

`grok` viene installato tramite il pacchetto first-party `grok` di mise, allo stesso modo di `claude` e `codex`. Esegui `grok`, oppure sceglilo sotto _Agent > Harness_. Salta l'installer `curl | bash` su x.ai. Quel percorso mette una seconda copia in `~/.grok/bin`, la antepone su `PATH` e sovrascrive il wrapper di Omarchy.

`dsh` apre la sua interfaccia browser su `127.0.0.1:3080`, con la directory di avvio come workspace predefinito. La sua interfaccia browser non accetta un prompt iniziale, quindi `omarchy agent prompt` la apre con il prompt negli appunti da incollare. Omarchy lo avvia con il preset di permessi senza approvazione di DeepSeek. DeepSeek Harness carica i log di sessione su DeepSeek quando usi la sua API ufficiale per i modelli; disattivalo sotto _Settings > General > Upload Session Log_ nella sua interfaccia browser. Anche i feedback che gli invii vengono caricati insieme alla sessione, a meno che tu non lo avvii con `DSH_TELEMETRY_MODE=DISABLED`.

### L'agent predefinito

Scegli il tuo agent predefinito con `omarchy default agent <name>` oppure sotto _Agent > Harness_ nel Menu Omarchy (`Super + Space`). Se l'agent non è ancora installato, sceglierlo lo installa prima. Un Omarchy appena installato ti inviterà a fare questa scelta con una notifica una tantum.

La scelta di Claude tenta anche di configurare la sua estensione browser per Chromium, Chrome, Brave, Brave Origin ed Edge. La configurazione dell'estensione si applica a tutti gli utenti e potrebbe richiedere la tua password di sistema; annullare o un'installazione dell'estensione fallita seleziona e avvia comunque Claude. Riavvia il browser, abilita l'estensione se richiesto e accedi a Claude per completare la connessione. Esegui `/chrome` in Claude per controllare la connessione. Firefox e Zen non supportano questa estensione. Se Claude era già il tuo predefinito prima che questa configurazione venisse aggiunta, selezionalo di nuovo per installare l'estensione.

Una volta scelto, `Super + Shift + Ctrl + A` avvia l'agent predefinito in una finestra di terminale dedicata (oppure mostra il selettore se non hai ancora scelto). Puoi anche avviarlo direttamente su un'attività con `omarchy agent prompt "Review this project"`. Freebuff e DeepSeek Harness non accettano un prompt iniziale, quindi si aprono con il prompt negli appunti da incollare al suo posto. Gli agent avviati in questo modo lavorano senza supervisione nelle rispettive modalità non fermarti a chiedere, quindi preparati al fatto che faranno davvero delle cose! MiniMax Code non ha una modalità simile per le sue sessioni interattive, quindi chiede i permessi come al solito. E poiché gli agent si rifiutano di ricordare la fiducia per la tua directory home, gli avvii da `$HOME` partono invece in `~/Work`.

Esistono anche scorciatoie da terminale: `a` esegue l'agent predefinito inline nel terminale corrente, mentre `c`, `cx` e `cy` avviano direttamente OpenCode, Claude Code e Codex (di nuovo nelle loro modalità di approvazione automatica). Anche le modifiche al tema si sincronizzano con gli agent: Claude Code, Pi, OpenCode e Hermes (una volta che Omarchy lo ha installato) seguono tutti quando cambi il tema di Omarchy.

### Le tue istruzioni per gli agent

Le regole personali per ogni agent vanno in `~/.agents/AGENTS.md`, accanto alle skill condivise in `~/.agents/skills`. Aprilo sotto _Agent > Instructions_, che lo collega anche in ogni harness che mantiene un proprio file globale: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` di Copilot, e così via. Crush e Amp leggono il collegamento `~/.config/AGENTS.md`, mentre omp, Kimi e DeepSeek Harness leggono direttamente `~/.agents/AGENTS.md`. Anche la scelta di un agent predefinito lo collega. Un file di istruzioni che avevi già diventa quello condiviso se non ce n'era ancora uno; altrimenti viene conservato accanto al collegamento come `.bak`. Esegui `omarchy agent instructions` per ricollegarlo dopo aver installato un altro agent.

### Il pannello degli agent

La barra superiore ha un'icona degli agent. Prima che tu abbia configurato un agent, il suo pannello ti guida nell'accesso a Claude, Codex o Grok, e il primo diventa il tuo agent predefinito. Dopodiché, il pannello mette ogni abbonamento su un'unica pagina: ogni agent e account con il suo piano, un indicatore per ciascuno dei suoi limiti di sessione di 5 ore e settimanali con il tempo mancante al reset (passa il mouse sopra per la percentuale esatta), oppure il saldo prepagato rimanente, sotto una riga che ruota tra ciò che hai usato in tutti loro, come i token di questa settimana e il tuo modello più usato. Sotto _Make something_ offre prompt iniziali per un nuovo tema, plugin, app o gioco che affidano l'attività al tuo agent predefinito. Le app sono costruite nel modo in cui sono costruite Hype, Monologue e Omacut di Omarchy stessa, in C++ e Qt Quick, seguendo la agent skill omarchy-make-app, e il compilatore e i componenti Qt di cui hanno bisogno sono già installati. I giochi sono una singola pagina three.js in `~/Games/vibes`, seguendo la agent skill omarchy-make-game, e si aprono tutti da un unico launcher Game Vibes nel tema corrente; caricano three.js dal web, quindi hanno bisogno di una connessione per avviarsi. Claude Code, Codex, Grok, Kimi, Cursor e la sua quota Grok Bot, GitHub Copilot, Muse, Antigravity, Kimchi e Devin sono coperti immediatamente con i loro limiti, e Hermes, Mistral Vibe e Qwen Code mostrano le loro sessioni e i loro token una volta che li hai usati. Compaiono anche i piani e le chiavi dei provider che usi tramite pi, omp o opencode: OpenCode Zen e Go, il Z.ai GLM Coding Plan, Ollama Cloud, il MiniMax Token Plan e Synthetic con i loro limiti; Fireworks, OpenRouter e DeepSeek con i loro saldi prepagati; e i modelli che esegui sul tuo hardware sotto Modelli locali. Ogni agent viene contato una sola volta, sotto chiunque lo fatturi, indipendentemente da quanti harness usi per pilotarlo.

Fai clic con il pulsante sinistro sull'icona nella barra per il pannello, con il pulsante destro per avviare il tuo agent predefinito. I record di utilizzo dietro di esso vengono rigenerati ogni 15 minuti da `omarchy agent usage-update`, e il pannello può persino unire l'utilizzo dalle tue altre macchine tramite una cartella sincronizzata. Vedi il README sotto `$OMARCHY_PATH/shell/plugins/agents/` per le impostazioni complete.

### Più abbonamenti

Se paghi per più di un piano Claude, Codex o Grok — un Max personale e uno di lavoro, ad esempio — Omarchy può mantenerli tutti connessi e passare tra loro. Aggiungi un abbonamento con il + nel pannello degli agent, che ti guida lì sul posto, oppure con `omarchy agent account add claude Work` (oppure `codex`, oppure `grok`). Installa la CLI se manca. Il primo account per un provider accede tramite il tuo browser normale, proprio dove la CLI guarda sempre. Ogni account successivo accede tramite una finestra privata, così l'account a cui il tuo browser è già connesso non viene intercettato per errore; accedi lì come l'account che stai aggiungendo e chiudi prima qualsiasi finestra privata che avevi già aperto. Non disconnetterti mai dalla CLI per farlo: disconnettersi revoca l'accesso salvato e quell'account dovrebbe essere aggiunto di nuovo.

Per copiare i tuoi accessi agli abbonamenti su un'altra macchina Omarchy tramite SSH, esegui `omarchy agent account copy user@laptop`. Il mittente fornisce un ricevitore temporaneo quando la destinazione non ne ha uno installato, così le macchine Omarchy più vecchie possono ricevere account senza un aggiornamento. I ricevitori installati hanno la precedenza. Questo copia tutti gli abbonamenti Claude, Codex e Grok; aggiungi i nomi dei provider per selezionarli, come in `omarchy agent account copy laptop claude`. I nomi degli account e gli ID dei comandi corrispondono alla sorgente, inclusi gli account già presenti sulla destinazione. Gli account di destinazione non correlati ricevono un suffisso numerico se i loro nomi sono in conflitto, e impostazioni, skill, plugin e cronologia delle conversazioni restano locali su ogni macchina.

Le credenziali esistenti sulla destinazione vengono conservate. Un account sorgente già connesso lì vede il suo nome sincronizzato senza sostituire le sue credenziali; gli altri account vengono aggiunti accanto ad esso. Per sostituire le credenziali salvate per gli account corrispondenti, usa `omarchy agent account copy --replace laptop claude` dopo aver chiuso le sessioni di quell'account sulla destinazione. Una destinazione nuova riceve anche l'account attivo e le preferenze di cambio della sorgente; una destinazione già consolidata mantiene le proprie.

Le credenziali viaggiano tramite SSH e sono conservate in file privati sulla destinazione, quindi copia solo su macchine di cui ti fidi. Questa è una copia una tantum, non una sincronizzazione continua. I token di refresh di Codex possono essere ruotati da un'altra macchina, lasciando un accesso copiato bisognoso di rinnovo; accessi separati restano la scelta più affidabile per l'uso simultaneo su più macchine. Vedi la [guida di Codex all'autenticazione degli account](https://developers.openai.com/codex/auth/ci-cd-auth).

Un account per provider è attivo, e ogni nuova sessione inizia come esso: `cx`, `cy`, un semplice `claude`, `codex` o `grok`, qualsiasi cosa avviata tramite `omarchy agent`, e script o editor che trovano la CLI su `PATH`. Cambia con `omarchy agent account use work` (e torna indietro con `omarchy agent account use main`), oppure nel pannello premendo il numero di un account e poi `Enter` (o facendo clic sul suo pulsante Use). Anche le sessioni Claude in esecuzione cambiano, dal loro prossimo messaggio: ogni sessione Claude viene eseguita in `~/.claude`, che contiene sempre l'accesso dell'account attivo. Una sessione Claude avviata nella cartella propria di un account da un Omarchy più vecchio mantiene quell'accesso finché non si chiude, quindi il cambio nomina quelle sessioni e si completa da solo una volta che sono scomparse. Le sessioni Codex e Grok in esecuzione restano sull'account con cui sono iniziate. Cronologia delle conversazioni, impostazioni, skill e plugin sono condivisi tra gli account, quindi `claude --continue` nella stessa cartella riprende da dove avevi interrotto sul nuovo account.

Con più di un account, il pannello mostra i limiti di ciascun account fianco a fianco, con quello attivo contrassegnato. Per impostazione predefinita Omarchy ti avvisa quando l'account attivo supera il 95% di un limite, e facendo clic sulla notifica passi all'account con più margine. Passa il mouse sulla riga di un account nel pannello e fai clic su Autoswitch che appare accanto a Use (oppure premi `m`), oppure esegui `omarchy agent account mode auto`, per farlo cambiare da solo; mentre è attivo, Autoswitch prende il posto di Use, e facendo di nuovo clic su di esso torni alla notifica. Aggiungi un numero per cambiare la soglia, come in `omarchy agent account mode auto 90`. Se ogni account è oltre la soglia, ne sentirai parlare una sola volta, insieme a quale account si libera per primo. Mentre un account attivo è entro 15 punti dalla sua soglia (80% con l'impostazione predefinita), i suoi limiti vengono controllati ogni tre minuti anziché ogni 15.

`omarchy agent account list` mostra ogni account e i suoi limiti più recenti, `omarchy agent account remove work` ne dimentica uno e `omarchy agent account rename primary Hey` ne rinomina uno (oppure fai clic sul nome di un account nel pannello). Questi comandi funzionano sugli account del tuo agent predefinito; per raggiungere l'altro provider, nominalo prima, come in `omarchy agent account use codex side`. L'accesso che avevi già in `~/.claude` o `~/.codex` è l'account _Main_. Quello di Codex resta dove si trova; quello di Claude resta in attesa in una cartella propria mentre un altro account è attivo. Un account lasciato inutilizzato per più di circa otto ore può mostrare _Sign-in required_; fai clic su di esso per accedere di nuovo a quell'account direttamente nel pannello, oppure passa ad esso e avvia una sessione, che aggiorna l'accesso da sola. I server MCP che aggiungi con `claude mcp add` raggiungono ogni account Claude, poiché tutti vengono eseguiti in `~/.claude`; per Codex e Grok, i server che avevi quando un account è stato aggiunto lo accompagnano, ma quelli successivi raggiungono solo l'account in cui li hai aggiunti. Claude Desktop mantiene un accesso proprio, e gli strumenti Codex o Grok configurati con un percorso assoluto a un binario CLI non seguono il cambio. Un `CLAUDE_CONFIG_DIR`, `CODEX_HOME` o `GROK_HOME` esplicito ha la precedenza sull'account selezionato.

### Diagnosi dei crash

Omarchy osserva systemd-coredump per i crash dei processi. Quando qualcosa va in segfault, riceverai una notifica "Process crashed" — facci clic sopra, e il crash viene affidato al tuo agent predefinito insieme alla skill diagnose-crash di Omarchy, che guida l'agent nello stabilire i fatti dal core dump e nel decidere se il crash vale la pena di essere segnalato upstream. Puoi anche eseguirla manualmente contro qualsiasi PID da `coredumpctl list` con `omarchy agent crash <pid>`.

Il monitoraggio è attivo per impostazione predefinita. Disattivalo sotto _Trigger > Toggle > Crash Capture_ (oppure con `omarchy toggle crash-capture`) e le notifiche si interrompono; `omarchy agent crash <pid>` continua a funzionare manualmente.

I crash possono anche essere silenziati un programma alla volta, che è ciò che la diagnosi ti offre alla fine. `omarchy crash mute hyprland` interrompe le notifiche solo per quel programma, `omarchy crash mute hyprland off` le riporta, e `omarchy crash mute` da solo elenca ciò che hai silenziato. Accetta il percorso del binario con la stessa facilità del suo nome, quindi `omarchy crash mute /usr/bin/hyprland` fa la stessa cosa. Metti tra virgolette un nome con uno spazio, come in `omarchy crash mute 'Some App'`. Tutto il resto continua a notificare, e il programma silenziato continua ad andare in crash — questo nasconde il promemoria, non risolve nulla.

### App desktop

Il menu _Install > AI_ contiene anche alcune app AI grafiche: Antigravity Desktop, l'app desktop ChatGPT, l'app desktop Claude (la beta Linux di Anthropic, con schede Chat, Cowork e Claude Code), Grok Bot per chattare con i modelli di xAI, Herdr Desktop, Hermes Desktop, OpenClaw, l'app desktop Perplexity e T3 Code. Grok Bot è l'app desktop di chat. L'agent di coding è il comando `grok`.

Hermes Desktop è quella da conoscere, perché una macchina ha un solo Hermes, ed è quello dell'app: Hermes viene installato solo ed esclusivamente tramite l'app, e il comando `hermes` che l'agent predefinito esegue è quello dell'app. Scegliere Hermes come agent predefinito installa la stessa cosa che installa la voce _Install > AI_: il pacchetto, e un runtime Hermes sotto `~/.hermes` configurato dall'installer proprietario di Hermes, che la prima volta richiede alcuni minuti. Quel runtime è l'unico Hermes che usano il comando `hermes` da terminale, l'agent predefinito e l'app, e si aggiorna da solo con `hermes update` anziché aspettare una release di Omarchy. Installarlo consegna inoltre a Hermes il tema Omarchy come skin chiamata `omarchy`, che ogni superficie Hermes segue mentre cambi tema; scegline un'altra nelle impostazioni Appearance di Hermes oppure con `/skin` se preferisci che non lo faccia, e Omarchy lascia in pace quella scelta. Rimuovere l'app sotto _Remove > AI_ chiude prima Hermes, gateway incluso, porta con sé quel runtime e conserva le tue chat, le tue memorie e le skill che Hermes ha scritto per sé, a meno che tu non gli dica altrimenti: chiede, con impostazione predefinita no, se anche quei dati e le tue impostazioni di connessione debbano sparire.

L'esperienza desktop di OpenClaw è la sua Control UI, che si apre come web app supportata dal suo gateway locale proprietario. OpenClaw vive in `~/.openclaw` e si aggiorna da solo: usa il pulsante "Update Gateway" della Control UI oppure esegui `openclaw update`, e il gateway si riavvia sulla nuova versione. Omarchy sceglie solo la release da cui parte un'installazione nuova. Rimuovere OpenClaw sotto _Remove > AI_ porta con sé il servizio gateway e l'app e poi chiede se anche `~/.openclaw` debba sparire, poiché contiene le tue chat e credenziali insieme a OpenClaw stesso e ai runtime dei plugin che scarica; l'impostazione predefinita lo conserva, e installare di nuovo OpenClaw lo riprende.

Herdr Desktop è l'app desktop [Herdr](https://herdr.dev): spazi, schede e pannelli di terminali e agent di coding che continuano a funzionare nel suo core quando chiudi la finestra. Proviene dall'installer proprietario di Herdr anziché da un pacchetto, quindi vive in `~/.local/share/herdr-app`, porta con sé il suo core in `~/.local/bin/herdr-core` quando non ne hai ancora uno e aggiorna entrambi da soli. Si affianca al comando `herdr` che Omarchy fornisce su `Super + Ctrl + Return` anziché sostituirlo, e riceve i tasti diretti di quel comando: `Alt + Return` e `Alt + Shift + Return` dividono un pannello in basso o a destra, `Alt + Escape` lo chiude, `Ctrl + Alt + Arrow` sposta tra i pannelli, `Alt + 1..9` e `Alt + Left/Right` scelgono una scheda, e `Alt + Up/Down` spostano tra gli spazi. `Ctrl + 1..9` sceglie uno spazio e `Alt + Shift + Up/Down` scorre tra gli agent. I tasti prefisso `Ctrl + Space` restano solo per il terminale, poiché l'app non può tenere un semplice tasto Ctrl per una sequenza. Omarchy scrive questi in `~/.config/herdr-app/keys.json`, e `omarchy-refresh-herdr-app` li rimette a posto. Installarlo sceglie il tema Omarchy di Herdr, che da quel momento segue il tuo tema Omarchy. Herdr mantiene un tema per la modalità chiara e uno per la modalità scura, quindi dopo essere passato tra un tema Omarchy scuro e uno chiaro, scegli di nuovo Omarchy nel selettore temi di Herdr un'altra volta per l'altra modalità.

T3 Code viene eseguito dalla sua release ufficiale AppImage in `~/.local/share/t3code` anziché da un pacchetto, quindi si aggiorna da solo. Installarlo chiede se iniziare sul canale Stable o Nightly; cambia più tardi nelle impostazioni di T3 Code. Le tue discussioni e impostazioni vivono in `~/.t3`, e rimuovere T3 Code sotto _Remove > AI_ le porta con sé.

### Modelli locali

Esegui un modello aperto sulla tua macchina per i tuoi agent di coding. I tuoi prompt e il tuo codice restano sulla macchina; nulla di ciò che viene inviato al modello la lascia. Inizia con:

```bash
omarchy agent local use best
```

Oppure, nel pannello degli agent nella barra superiore, scegli + e poi Local AI, che compare quando un modello si adatta a questa macchina. La prima volta, questo installa Podman, che esegue i modelli, e su una macchina NVIDIA il container toolkit di NVIDIA, che dà loro la GPU. Omarchy poi sceglie il modello consigliato per questa macchina, lo scarica e lo avvia. Aspettati un download di decine di GB e la maggior parte della memoria della macchina in uso mentre il modello è in esecuzione: Flash Next usa circa 100 GiB con il suo contesto completo da 256K. Se altri modelli occupano la memoria di cui ha bisogno, viene configurato arrestato, pronto ad avviarsi una volta che ne arresti uno. Il modello si arresta al logout; arrestalo tu stesso quando ti serve la memoria per qualcos'altro.

`omarchy agent local list` mostra le opzioni e spiega perché alcune non si adattano. Per configurarne un altro, esegui `omarchy agent local use <recipe>`. Oggi, `qwen3.8-flash-next-gufo` e `qwen3.8-27b-gufo` sono disponibili per macchine Strix Halo da 128 GB; il 27B occupa circa 40 GiB, quindi lascia spazio per altro lavoro. Su un laptop da 64 GB con Arc B390 di Intel, `qwen3.6-35b-a3b-llamacpp` viene eseguito in circa 30 GiB. Nuove recipe e raccomandazioni arrivano con `omarchy update`, tramite il pacchetto.

Ogni modello che configuri ottiene una sua riga nel pannello degli agent, accanto ai tuoi abbonamenti: play per avviarlo, pause per arrestarlo e liberare la sua memoria, e il pulsante terminale per aprire il tuo agent su di esso. Più modelli possono funzionare contemporaneamente quando entrano insieme in memoria; se uno non entra, Omarchy dice quale modello in esecuzione arrestare. Trascina le righe per riordinarle, e premi Delete su una riga selezionata per rimuovere un modello e il suo download.

Ogni modello che configuri ottiene anche una sua voce nel launcher delle app, sotto il nome del modello e con il logo del suo produttore, nel modo in cui accedere a Claude, Codex o Grok ne aggiunge una. Apre il tuo agent su quel modello, e avvia prima il modello se non è in esecuzione: il terminale lo mostra mentre si carica e passa la mano all'agent una volta che è attivo. Rimuovere un modello rimuove la sua voce.

Un modello continua a funzionare esattamente come è stato configurato, quindi un aggiornamento di Omarchy non ne riavvia mai uno sotto i tuoi agent. Quando Omarchy ha un runtime più nuovo o pesi più nuovi per un modello che hai configurato, la sua riga mostra un pulsante di aggiornamento: premilo e il modello viene configurato di nuovo in background, scaricando solo ciò che è cambiato, e si riavvia sulla nuova versione. Un modello che era arrestato resta arrestato. `omarchy agent local update` fa lo stesso per ogni modello da un terminale.

Da riga di comando, `omarchy agent local start <recipe>` e `omarchy agent local stop <recipe>` fanno lo stesso, `omarchy agent local status` mostra ogni modello, e `omarchy agent --local` apre il tuo agent predefinito sull'ultimo modello che hai avviato. pi, OpenCode e Qwen Code possono usarne uno; con qualsiasi altro predefinito si apre in pi. pi elenca anche ogni modello che hai configurato, e quelli sulle macchine con cui hai effettuato l'accoppiamento, nel suo selettore di modelli proprietario, quindi anche un semplice `pi` li raggiunge. Può connettersi anche qualsiasi client compatibile con OpenAI: `status` mostra l'indirizzo di ogni modello (il primo è `http://127.0.0.1:11435/v1`), il nome della recipe è il modello, e la chiave si trova in `~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` elimina un modello e i download che nessun altro modello usa.

I runtime di terze parti sono etichettati con il loro publisher. Omarchy esegue ogni modello senza accesso alla rete.

### LLM locali

Omarchy consiglia due modi per eseguire modelli LLM locali: LM Studio e Ollama. LM Studio fornisce un'interfaccia GUI per trovare modelli open-weight, installarli ed eseguirli. È un ottimo modo per iniziare facilmente. Ollama offre una CLI per fare lo stesso in modo simile. Ma se sei nuovo ai modelli locali, io inizierei con LM Studio. Puoi installare l'uno o l'altro sotto _Install > AI_ nel Menu Omarchy.

### La Skill Omarchy

Le agent skill aiutano l'AI a usare strumenti specifici in un modo specifico, e Omarchy viene fornito con una skill predefinita per personalizzare il sistema. Come modificare la tua config di Hyprland, regolare la barra, o persino creare un nuovo tema da zero. È collegata tramite symlink nelle directory delle skill per Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` e ciascun `~/.hermes/profiles/*/skills`), e nella posizione generica `~/.agents/skills`, quindi la maggior parte degli harness la rileva automaticamente.

Ma dovresti trattare questa skill come sperimentale. Modelli diversi la useranno con effetti diversi. È meglio eseguirla prima in modalità plan, così hai un'idea di ciò che l'agent vorrebbe cambiare. E poi preparati a ripristinare le modifiche o persino a invocare `omarchy reinstall configs`, se l'agent fa un disastro di tutto.
