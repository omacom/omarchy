# AI

Omarchy include launcher per gli agent di coding qui sotto senza sceglierne uno predefinito per te. Esegui un comando per installare la sua CLI al primo utilizzo, poi autenticati quando richiesto. Hermes e OpenClaw sono le eccezioni: per loro non viene installato nulla tramite mise, e sceglierne uno configura la sua copia autoaggiornante, come spiega più sotto _App desktop_.

### Installare e aggiornare gli agent

Fatta eccezione per Hermes e OpenClaw, questi agent usano l'installazione lazy di mise: il primo avvio installa la CLI, e gli avvii successivi la riutilizzano. mise controlla inoltre se per un agent installato è disponibile una nuova release al massimo una volta ogni quattro ore, subito prima del suo avvio o in background al prompt della shell. Se quell'aggiornamento fallisce o sei offline, viene eseguita la versione installata. `omarchy update` aggiorna gli agent installati insieme al resto di Omarchy, e `mup` aggiorna solo gli strumenti gestiti da mise.

L'updater proprio di un agent, come `claude update`, `codex update`, o un pulsante di aggiornamento in un'app, non aggiorna l'installazione gestita da mise. `codex update` fallisce, e `claude update` può segnalare successo installando però una copia separata che mise non tiene tracciata. Se preferisci usare l'installer e l'updater nativi di un agent, aggiungilo a `disable_tools`; vedi [Strumenti CLI preinstallati](18-development-tools.md#preinstalled-cli-tools).

Per installare tutti gli strumenti lazy configurati prima di averne bisogno, esegui `mise install --include-lazy`. Questo include anche gli altri strumenti CLI predefiniti di Omarchy, oltre agli agent. Vedi [Strumenti CLI preinstallati](18-development-tools.md#preinstalled-cli-tools) per installare un singolo strumento o usare una tua installazione.

`grok` viene installato tramite il pacchetto first-party `grok` di mise, allo stesso modo di `claude` e `codex`. Esegui `grok`, o sceglilo sotto _Agent > Harness_. Salta l'installer `curl | bash` su x.ai. Quel percorso mette una seconda copia in `~/.grok/bin`, la antepone su `PATH`, e sovrascrive il wrapper di Omarchy.

`dsh` apre la sua UI nel browser su `127.0.0.1:3080`, con la directory di avvio come workspace predefinito. La sua UI nel browser non accetta un prompt iniziale, quindi `omarchy agent prompt` la apre con il prompt negli appunti da incollare. Omarchy lo avvia con il preset di permessi senza approvazione di DeepSeek. DeepSeek Harness carica i log di sessione su DeepSeek quando usi la sua API ufficiale del modello; disattivalo sotto _Settings > General > Upload Session Log_ nella sua UI nel browser. Anche i feedback che gli invii vengono caricati insieme alla sessione, a meno che tu non lo avvii con `DSH_TELEMETRY_MODE=DISABLED`.

### L'agent predefinito

Scegli il tuo agent predefinito con `omarchy default agent <name>` o sotto _Agent > Harness_ nel Menu di Omarchy (`Super + Space`). Se l'agent non è ancora installato, sceglierlo lo installa prima, e ottiene anche un suo launcher nel launcher delle app, accanto ad Agent. Un Omarchy fresco ti inviterà a fare questa scelta con una notifica una tantum.

Scegliere Claude tenta anche di configurare la sua estensione per browser per Chromium, Chrome, Brave, Brave Origin, e Edge. La configurazione dell'estensione si applica a tutti gli utenti e potrebbe chiederti la password di sistema; annullare o un'installazione dell'estensione fallita seleziona e avvia comunque Claude. Riavvia il browser, abilita l'estensione se richiesto, e accedi a Claude per finire di collegarla. Esegui `/chrome` in Claude per controllare la connessione. Firefox e Zen non supportano questa estensione. Se Claude era già il tuo predefinito prima che questa configurazione venisse aggiunta, selezionalo di nuovo per installare l'estensione.

Una volta scelto, `Super + Shift + Ctrl + A` avvia l'agent predefinito in una finestra di terminale dedicata (o apre il selettore se non hai ancora scelto). Puoi anche avviarlo direttamente su un'attività con `omarchy agent prompt "Review this project"`. Freebuff e DeepSeek Harness non accettano un prompt iniziale, quindi si aprono con il prompt negli appunti da incollare invece. Gli agent avviati in questo modo funzionano senza supervisione nelle rispettive modalità non-fermarti-a-chiedere, quindi preparati al fatto che faranno davvero delle cose! MiniMax Code non ha una modalità del genere per le sue sessioni interattive, quindi chiede i permessi come al solito. E poiché gli agent si rifiutano di ricordare la fiducia per la tua directory home, gli avvii da `$HOME` partono invece in `~/Work`.

Ci sono anche scorciatoie da terminale: `a` esegue l'agent predefinito inline nel terminale corrente, mentre `c`, `cx`, e `cy` avviano direttamente OpenCode, Claude Code, e Codex (di nuovo nelle loro modalità di approvazione automatica). Anche i cambi di tema si sincronizzano con gli agent: Claude Code, Pi, OpenCode, e Hermes (una volta che Omarchy lo ha installato) seguono tutti quando cambi il tema di Omarchy.

### Le tue istruzioni per gli agent

Le regole personali per ogni agent vanno in `~/.agents/AGENTS.md`, accanto alle skill condivise in `~/.agents/skills`. Aprilo sotto _Agent > Instructions_, che lo collega anche in ogni harness che mantiene un suo file globale: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` di Copilot, e così via. Crush e Amp leggono il collegamento `~/.config/AGENTS.md`, mentre omp, Kimi, e DeepSeek Harness leggono direttamente `~/.agents/AGENTS.md`. Anche scegliere un agent predefinito lo collega. Un file di istruzioni che avevi già diventa quello condiviso se non ce n'era ancora uno; altrimenti viene tenuto accanto al collegamento come `.bak`. Esegui `omarchy agent instructions` per ricollegarlo dopo aver installato un altro agent.

### Il pannello degli agent

La barra superiore ha un'icona degli agent. Prima di aver configurato un agent, il suo pannello ti guida ad accedere a Claude, Codex, o Grok, e il primo diventa il tuo agent predefinito. Dopo di che, il pannello mette ogni abbonamento su un'unica pagina: ogni agent e account con il suo piano, un indicatore per ciascuno dei suoi limiti di sessione di 5 ore e settimanali con il tempo mancante al reset (passa il mouse per la percentuale esatta), o il saldo prepagato rimanente, sotto una riga che ruota tra ciò che hai usato in tutti loro, come i token di questa settimana e il modello che usi di più. Sotto _Make something cool_ offre prompt iniziali per un nuovo tema, plugin, app, o gioco che affidano l'attività al tuo agent predefinito. Le app sono costruite nel modo in cui sono costruite le stesse Hype, Monologue, e Omacut di Omarchy, in C++ e Qt Quick, seguendo la skill agent omarchy-make-app, e il compilatore e i pezzi Qt di cui hanno bisogno sono già installati. I giochi sono una singola pagina three.js in `~/Games/vibes`, che segue la skill agent omarchy-make-game, e si aprono tutti da un unico launcher Game Vibes nel tema corrente; caricano three.js dal web, quindi hanno bisogno di una connessione per partire. Claude Code, Codex, Grok, Kimi, Cursor e la sua dotazione Grok Bot, GitHub Copilot, Muse, Antigravity, e Devin sono coperti fin da subito con i loro limiti, Kimchi con il suo piano, i crediti prepagati, e i budget di spesa, e Hermes, Mistral Vibe, e Qwen Code mostrano le loro sessioni e token una volta che li hai usati. Anche i piani e le chiavi dei provider che usi tramite pi, omp, o opencode compaiono: OpenCode Zen e Go, il Z.ai GLM Coding Plan, Ollama Cloud, il MiniMax Token Plan, e Synthetic con i loro limiti; OpenRouter e DeepSeek con i loro saldi prepagati; Fireworks con la sua spesa negli ultimi 30 giorni. Anche i token dei modelli che esegui sul tuo hardware contano nei totali; i modelli stessi hanno un loro pannello, descritto sotto [Modelli locali](#local-models). Ogni agent viene contato una sola volta, sotto chi lo fattura, indipendentemente da quanti harness lo guidino.

Fai clic sinistro sull'icona nella barra o premi `Super + Ctrl + X` per il pannello, clic destro per avviare il tuo agent predefinito, e clic centrale per aggiornare. I record di utilizzo dietro di esso vengono rigenerati ogni 15 minuti da `omarchy agent usage update`, e il pannello può persino unire l'utilizzo dalle altre tue macchine tramite una cartella sincronizzata. Vedi il README sotto `$OMARCHY_PATH/shell/plugins/agents/` per tutte le impostazioni.

### Più abbonamenti

Se paghi per più di un piano Claude, Codex, o Grok — uno Max personale e uno di lavoro, diciamo — Omarchy può mantenerli tutti connessi e passare tra loro. Aggiungi un abbonamento con il + nel pannello degli agent, che ti guida lì stesso, o con `omarchy agent account add claude Work` (o `codex`, o `grok`). Installa la CLI se manca. Il primo account per un provider accede tramite il tuo browser normale, proprio dove la CLI guarda sempre. Ogni successivo accede tramite una finestra privata, così l'account a cui il tuo browser è già connesso non viene preso per sbaglio; accedi lì come l'account che stai aggiungendo, e chiudi prima qualsiasi finestra privata che avevi già aperto. Non disconnetterti mai dalla CLI per fare questo: disconnettersi revoca l'accesso salvato, e quell'account dovrebbe essere aggiunto di nuovo.

Per copiare i login dei tuoi abbonamenti su un'altra macchina Omarchy via SSH, esegui `omarchy agent account copy user@laptop`. Il mittente fornisce un ricevitore temporaneo quando la destinazione non ne ha uno installato, così le macchine Omarchy più vecchie possono ricevere account senza un aggiornamento. I ricevitori installati hanno la precedenza. Questo copia tutti gli abbonamenti Claude, Codex, e Grok; aggiungi nomi di provider per selezionarli, come in `omarchy agent account copy laptop claude`. I nomi degli account e gli ID dei comandi corrispondono alla sorgente, inclusi gli account già presenti sulla destinazione. Gli account di destinazione non correlati ricevono un suffisso numerico se i loro nomi sono in conflitto, e impostazioni, skill, plugin, e cronologia delle conversazioni restano locali a ciascuna macchina.

Le credenziali di destinazione esistenti vengono mantenute. Un account sorgente già connesso lì vede il suo nome sincronizzato senza sostituire le sue credenziali; altri account vengono aggiunti accanto ad esso. Per sostituire le credenziali salvate per gli account corrispondenti, usa `omarchy agent account copy --replace laptop claude` dopo aver chiuso le sessioni di quell'account sulla destinazione. Una destinazione fresca ottiene anche l'account attivo e le preferenze di cambio della sorgente; una destinazione già consolidata mantiene le sue.

Le credenziali viaggiano tramite SSH e sono conservate in file privati sulla destinazione, quindi copia solo su macchine di cui ti fidi. Questa è una copia una tantum, non una sincronizzazione continua. I token di refresh di Codex possono essere ruotati da un'altra macchina, lasciando un login copiato bisognoso di rinnovo; accessi separati restano la scelta più affidabile per l'uso simultaneo su più macchine. Vedi la [guida di Codex sull'autenticazione degli account](https://developers.openai.com/codex/auth/ci-cd-auth).

Un account per provider è attivo, e ogni nuova sessione inizia come quello: `cx`, `cy`, un semplice `claude`, `codex`, o `grok`, qualsiasi cosa avviata tramite `omarchy agent`, e script o editor che trovano la CLI su `PATH`. Cambia con `omarchy agent account use work` (e torna indietro con `omarchy agent account use main`), o nel pannello premendo il numero di un account e poi `Enter` (o facendo clic sul suo pulsante Use). Anche le sessioni Claude in esecuzione cambiano, dal loro prossimo messaggio: ogni sessione Claude gira in `~/.claude`, che contiene sempre l'accesso dell'account attivo. Una sessione Claude avviata nella cartella propria di un account da un Omarchy più vecchio mantiene quell'accesso finché non si chiude, quindi il cambio nomina quelle sessioni e si completa da solo una volta che sono sparite. Le sessioni Codex e Grok in esecuzione restano sull'account con cui sono partite. Cronologia delle conversazioni, impostazioni, skill, e plugin sono condivisi tra account, quindi `claude --continue` nella stessa cartella riprende da dove avevi lasciato sul nuovo account.

Con più di un account, il pannello mostra i limiti di ciascun account fianco a fianco, con quello attivo contrassegnato. Per impostazione predefinita Omarchy ti avvisa quando l'account attivo supera il 95% di un limite, e fare clic sulla notifica passa all'account con più margine. Passa il mouse sulla riga di un account nel pannello e fai clic su Autoswitch che appare accanto a Use (o premi `m`), o esegui `omarchy agent account mode auto`, per farlo cambiare da solo; mentre è attivo, Autoswitch prende il posto di Use, e farvi clic di nuovo torna ad avvisare. Aggiungi un numero per cambiare la soglia, come in `omarchy agent account mode auto 90`. Se ogni account è oltre la soglia, lo saprai una volta, insieme a quale account si libera per primo. Mentre un account attivo è entro 15 punti dalla sua soglia (80% con il valore predefinito), i suoi limiti vengono controllati ogni tre minuti anziché ogni 15.

`omarchy agent account list` mostra ogni account e i suoi limiti più recenti, `omarchy agent account remove work` ne dimentica uno, e `omarchy agent account rename primary Hey` ne rinomina uno (o fai clic sul nome di un account nel pannello). Questi comandi funzionano sugli account del tuo agent predefinito; per raggiungere l'altro provider, nominalo prima, come in `omarchy agent account use codex side`. Il login che avevi già in `~/.claude` o `~/.codex` è l'account _Main_. Quello di Codex resta dove si trova; quello di Claude aspetta in una sua cartella mentre un altro account è attivo. Un account lasciato inutilizzato per più di circa otto ore può mostrare _Sign-in required_; fai clic su di esso per accedere di nuovo a quell'account direttamente nel pannello, o passa ad esso e avvia una sessione, che aggiorna l'accesso da sola. I server MCP che aggiungi con `claude mcp add` raggiungono ogni account Claude, poiché girano tutti in `~/.claude`; per Codex e Grok, i server che avevi quando un account è stato aggiunto lo accompagnano, ma quelli successivi raggiungono solo l'account in cui li hai aggiunti. Claude Desktop mantiene un suo accesso, e gli strumenti Codex o Grok configurati con un percorso assoluto a un binario CLI non seguono il cambio. Un `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, o `GROK_HOME` esplicito ha la precedenza sull'account selezionato.

### Diagnosi dei crash

Omarchy osserva systemd-coredump per i crash dei processi. Una volta scelto un agent predefinito, qualsiasi tuo programma che fa dump del core porta una notifica "Process crashed" — fai clic su di essa, e il crash viene affidato al tuo agent predefinito insieme alla skill omarchy-diagnose-crash di Omarchy, che guida l'agent a stabilire i fatti dal core dump e a decidere se il crash vale la pena di essere segnalato upstream. Puoi anche eseguirla a mano contro qualsiasi PID da `coredumpctl list` con `omarchy agent crash <pid>`.

L'osservazione è attiva per impostazione predefinita. Disattivala sotto _Trigger > Toggle > Crash Capture Off_ (o con `omarchy toggle crash-capture`) e le notifiche si fermano; `omarchy agent crash <pid>` funziona ancora a mano.

I crash possono anche essere silenziati un programma alla volta, che è ciò che la diagnosi ti offre alla fine. `omarchy crash mute hyprland` ferma le notifiche solo per quel programma, `omarchy crash mute hyprland off` le riporta, e `omarchy crash mute` da solo elenca ciò che hai silenziato. Accetta il percorso del binario tanto volentieri quanto il suo nome, quindi `omarchy crash mute /usr/bin/hyprland` fa la stessa cosa. Metti tra virgolette un nome con uno spazio, come in `omarchy crash mute 'Some App'`. Tutto il resto continua ad avvisare, e il programma silenziato continua a crashare — questo nasconde il promemoria, non risolve nulla.

### App desktop

Il menu _Install > AI_ include anche alcune app AI grafiche: Amp Desktop, Antigravity Desktop, l'app desktop ChatGPT, l'app desktop Claude (la beta Linux di Anthropic, con schede Chat, Cowork, e Claude Code), Grok Bot per chattare con i modelli di xAI, Herdr Desktop, Hermes Desktop, OpenClaw, l'app desktop Perplexity, e T3 Code. Grok Bot è l'app di chat desktop. L'agent di coding è il comando `grok`.

Hermes Desktop è quella da conoscere, perché una macchina ha un solo Hermes, ed è quello dell'app: Hermes viene installato solo tramite l'app, e il comando `hermes` che l'agent predefinito esegue è quello dell'app. Scegliere Hermes come agent predefinito installa la stessa cosa che fa la voce _Install > AI_: il pacchetto, e un runtime Hermes sotto `~/.hermes` configurato dall'installer proprio di Hermes, che impiega alcuni minuti la prima volta. Quel runtime è l'unico Hermes che usano il comando `hermes` da terminale, l'agent predefinito e l'app, e si aggiorna da solo con `hermes update` anziché aspettare una release di Omarchy. Installarlo consegna anche a Hermes il tema Omarchy come skin chiamata `omarchy`, che ogni superficie Hermes segue mentre cambi tema; scegline un'altra sotto le impostazioni Appearance di Hermes o con `/skin` se preferisci che non lo faccia, e Omarchy lascia stare quella scelta. Rimuovere l'app sotto _Remove > AI_ chiude prima Hermes, gateway incluso, porta via quel runtime con sé, e mantiene le tue chat, memorie, e le skill che Hermes ha scritto per sé a meno che tu non gli dica altrimenti: chiede, con no come predefinito, se anche quei dati e le tue impostazioni di connessione devono andarsene.

L'esperienza desktop di OpenClaw è la sua Control UI, che si apre come web app supportata dal suo gateway locale. OpenClaw vive in `~/.openclaw` e si aggiorna da solo: usa il pulsante "Update Gateway" della Control UI o esegui `openclaw update`, e il gateway si riavvia sulla nuova versione. Omarchy sceglie solo la release da cui parte un'installazione fresca. OpenClaw può anche essere il tuo agent predefinito: sceglierlo sotto _Agent > Harness_ configura quella stessa copia in `~/.openclaw`, e l'agent apre l'interfaccia terminale di OpenClaw collegata al suo gateway. Rimuovere OpenClaw sotto _Remove > AI_ porta via il servizio gateway e l'app e poi chiede se anche `~/.openclaw` deve andarsene, poiché contiene le tue chat e credenziali insieme a OpenClaw stesso e ai runtime dei plugin che scarica; per impostazione predefinita lo mantiene, e installare di nuovo OpenClaw lo riprende.

Herdr Desktop è l'app desktop [Herdr](https://herdr.dev): spazi, schede, e pannelli di terminali e agent di coding che continuano a funzionare nel suo core quando chiudi la finestra. Viene dall'installer proprio di Herdr anziché da un pacchetto, quindi vive in `~/.local/share/herdr-app`, porta con sé il suo core in `~/.local/bin/herdr-core` quando non ne hai ancora uno, e aggiorna entrambi da sola. Sta accanto al comando `herdr` che Omarchy fornisce su `Super + Ctrl + Return` anziché sostituirlo, e ottiene i tasti diretti di quel comando: `Alt + Return` e `Alt + Shift + Return` dividono un pannello in basso o a destra, `Alt + Escape` lo chiude, `Ctrl + Alt + Arrow` si sposta tra i pannelli, `Alt + 1..9` e `Alt + Left/Right` scelgono una scheda, e `Alt + Up/Down` si spostano tra spazi. `Ctrl + 1..9` sceglie uno spazio e `Alt + Shift + Up/Down` scorre tra gli agent. I tasti prefisso `Ctrl + Space` restano solo per il terminale, poiché l'app non può tenere un semplice tasto Ctrl per una sequenza. Omarchy scrive questi in `~/.config/herdr-app/keys.json`, e `omarchy-refresh-herdr-app` li rimette a posto. Installarla sceglie il tema Omarchy di Herdr, che da allora segue il tuo tema Omarchy. Herdr mantiene un tema per la modalità chiara e uno per la scura, quindi dopo essere passato tra un tema Omarchy scuro e uno chiaro, scegli Omarchy nel selettore temi di Herdr ancora una volta per l'altra modalità.

T3 Code gira dalla sua release ufficiale AppImage in `~/.local/share/t3code` anziché da un pacchetto, quindi si aggiorna da solo. Installarlo chiede se partire sul canale Stable o Nightly; cambia più tardi nelle impostazioni di T3 Code. I tuoi thread e impostazioni vivono in `~/.t3`, e rimuovere T3 Code sotto _Remove > AI_ li porta via con sé.

### Modelli locali

Esegui un modello aperto sulla tua macchina per i tuoi agent di coding. I tuoi prompt e il tuo codice restano sulla macchina; nulla inviato al modello la lascia. Inizia con:

```bash
omarchy models use best text
```

Questo configura il miglior modello testuale per questa macchina, il tipo che usano i tuoi agent. Anche i modelli per immagini, video e musica hanno un loro migliore: `omarchy models use best image`, `video` o `music`. Esegui `omarchy models use best` per vedere la scelta di ogni tipo per questa macchina.

Oppure apri il pannello dei modelli locali dalla sua icona con scintille nella barra superiore, accanto all'icona degli agent, o con Super + Ctrl + Alt + X, e scegli +. L'icona compare quando un modello si adatta a questa macchina. Podman, che esegue i modelli, viene con Omarchy, così come il container toolkit di NVIDIA su una macchina NVIDIA, che gli dà la GPU; se uno dei due manca, la prima configurazione lo installa. Omarchy poi sceglie il modello consigliato per questa macchina, lo scarica, e lo avvia. Aspettati un download di decine di GB e la maggior parte della memoria della macchina in uso mentre il modello gira: Flash Next usa circa 100 GiB con il suo contesto completo da 256K. Se altri modelli occupano la memoria di cui ha bisogno, viene configurato fermo, pronto a partire una volta che ne fermi uno. Il modello si ferma al logout; fermalo tu stesso quando hai bisogno della memoria per qualcos'altro.

`omarchy models list` mostra le opzioni e spiega perché alcune non si adattano. Per configurarne un altro, esegui `omarchy models use <recipe>`. Oggi, `qwen3.8-flash-next-gufo` e `qwen3.8-27b-gufo` sono disponibili per macchine Strix Halo da 128 GB; il 27B occupa circa 40 GiB, quindi lascia spazio per altro lavoro. Su un laptop da 64 GB con Arc B390 di Intel, `qwen3.6-35b-a3b-llamacpp` gira in circa 30 GiB. Nuove recipe e raccomandazioni arrivano con `omarchy update`, tramite il pacchetto.

Ogni modello che configuri ottiene una sua riga nel pannello dei modelli locali: play per avviarlo, pausa per fermarlo e liberare la sua memoria, e il pulsante terminale per aprire il tuo agent su di esso. In alto, una barra mostra come la memoria della macchina è divisa tra Omarchy stesso (il sistema e le tue app), ciascun modello in esecuzione, e ciò che è libero. Punta a un modello fermo e la barra mostra se ci sta, o di quanto è corto. Più modelli possono girare contemporaneamente quando stanno insieme in memoria; se uno non ci sta, Omarchy dice quale modello in esecuzione fermare. Trascina le righe per il loro logo per riordinarle, e premi Delete su una riga selezionata per rimuovere un modello e il suo download.

Ogni modello di coding che configuri ottiene anche una sua voce nel launcher delle app, sotto il nome del modello e con il logo del suo produttore, nel modo in cui accedere a Claude, Codex o Grok ne aggiunge una. Apre il tuo agent su quel modello, e avvia prima il modello se non è in esecuzione: il terminale lo mostra mentre si carica e passa la mano all'agent una volta che è pronto. Rimuovere un modello rimuove la sua voce.

Non ogni modello è per il coding. I modelli per immagini, video e musica si aprono invece in Fantasi, l'app di Omarchy per creare immagini, video e musica con un modello in esecuzione su questa macchina, scelto lì o dalla loro riga nel pannello dei modelli locali.

Un modello continua a girare esattamente come è stato configurato, quindi un aggiornamento di Omarchy non ne riavvia mai uno sotto i tuoi agent. Quando Omarchy ha un runtime più nuovo o pesi più nuovi per un modello che hai configurato, la sua riga mostra un pulsante di aggiornamento: premilo e il modello viene configurato di nuovo in background, scaricando solo ciò che è cambiato, e si riavvia sulla nuova versione. Un modello che era fermo resta fermo. `omarchy models update` fa lo stesso per ogni modello da un terminale.

Dalla riga di comando, `omarchy models start <recipe>` e `omarchy models stop <recipe>` fanno lo stesso, `omarchy models status` mostra ogni modello, e `omarchy agent --local` apre l'ultimo modello che hai avviato in pi, qualunque sia il tuo agent predefinito. Anche OpenCode e Qwen Code possono usare un modello locale: `omarchy models harness opencode` o `omarchy models harness qwen` li apre lì invece, e `omarchy models harness pi` torna indietro. pi elenca anche ogni modello che hai configurato, e quelli sulle macchine con cui hai fatto pairing, nel suo selettore di modelli, quindi anche un semplice `pi` li raggiunge. Anche qualsiasi client compatibile con OpenAI può collegarsi: `status` mostra l'indirizzo di ciascun modello (il primo è `http://127.0.0.1:11435/v1`), il nome della recipe è il modello, e la chiave è in `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` elimina un modello e i download che nessun altro modello usa.

I runtime di terze parti sono etichettati con il loro publisher. Omarchy esegue ogni modello senza accesso alla rete.

### LLM locali

Omarchy consiglia due modi per eseguire modelli LLM locali: LM Studio e Ollama. LM Studio fornisce un'interfaccia GUI per trovare modelli open-weight, installarli, ed eseguirli. È un ottimo modo per partire facilmente. Ollama offre una CLI per fare lo stesso in modo simile. Ma se sei nuovo ai modelli locali, io partirei con LM Studio. Puoi installare l'uno o l'altro sotto _Install > AI_ nel Menu di Omarchy.

### Le skill di Omarchy

Le skill per agent aiutano l'AI a usare strumenti specifici in un modo specifico, e Omarchy ne fornisce sette. La skill omarchy copre la personalizzazione del sistema, come ritoccare la tua config di Hyprland o regolare la barra. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app, e omarchy-make-game coprono la creazione di qualcosa di nuovo, omarchy-contribute copre la segnalazione di un bug o l'invio di una correzione upstream, e omarchy-diagnose-crash esamina il core dump di un crash. Sono collegate tramite symlink nelle directory delle skill per Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` e ciascun `~/.hermes/profiles/*/skills`), e la posizione generica `~/.agents/skills`, quindi la maggior parte degli harness le raccoglie automaticamente. Una tua cartella skill con lo stesso nome ha la precedenza.

Ma dovresti trattare queste skill come sperimentali. Modelli diversi le useranno con effetti diversi. È meglio eseguire prima in modalità plan, così hai un'idea di ciò che l'agent vorrebbe cambiare. E poi essere pronto a fare rollback delle modifiche o persino a invocare `omarchy reinstall configs`, se l'agent fa un disastro di tutto.
