# ИИ

Omarchy включает средства запуска для перечисленных ниже агентов для программирования, не выбирая для вас вариант по умолчанию. Выполните команду, чтобы при первом использовании установить её CLI, а затем при появлении запроса выполните аутентификацию. Hermes и OpenClaw — исключения: для них через mise ничего не устанавливается, а выбор любого из них настраивает его собственную самообновляющуюся копию, как объясняется ниже в разделе _Настольные приложения_.

### Установка и обновление агентов

За исключением Hermes и OpenClaw, эти агенты используют ленивую установку mise: первый запуск устанавливает CLI, а последующие запуски используют его повторно. mise также проверяет установленный агент на наличие нового релиза не чаще одного раза в четыре часа, непосредственно перед его запуском или в фоновом режиме при приглашении оболочки. Если это обновление не удаётся или вы не в сети, запускается установленная версия. `omarchy update` обновляет установленные агенты вместе с остальной частью Omarchy, а `mup` обновляет только инструменты, управляемые mise.

Собственное средство обновления агента, такое как `claude update`, `codex update` или кнопка обновления в приложении, не обновляет установку, управляемую mise. `codex update` завершается с ошибкой, а `claude update` может сообщить об успехе, установив при этом отдельную копию, которую mise не отслеживает. Если вы предпочитаете использовать собственный установщик и средство обновления агента, добавьте его в `disable_tools`; см. [Предустановленные инструменты CLI](18-development-tools.md#preinstalled-cli-tools).

Чтобы установить все настроенные ленивые инструменты до того, как они вам понадобятся, выполните `mise install --include-lazy`. Это включает другие инструменты CLI Omarchy по умолчанию, а также агентов. См. [Предустановленные инструменты CLI](18-development-tools.md#preinstalled-cli-tools) для установки одного инструмента или использования собственной установки.

`grok` устанавливается через фирменный пакет `grok` от mise, так же как `claude` и `codex`. Выполните `grok` или отметьте его звёздочкой на панели агентов. Пропустите установщик `curl | bash` на x.ai. Этот путь помещает вторую копию в `~/.grok/bin`, добавляет её в начало `PATH` и перезаписывает оболочку Omarchy.

`dsh` открывает свой браузерный UI на `127.0.0.1:3080`, используя каталог запуска в качестве рабочего пространства по умолчанию. Его браузерный UI не принимает начальный запрос, поэтому `omarchy agent prompt` открывает его с запросом в вашем буфере обмена, чтобы вы могли его вставить. Omarchy запускает его с предустановкой разрешений DeepSeek без подтверждений. DeepSeek Harness загружает журналы сессий в DeepSeek, когда вы используете его официальный API моделей; отключите это в его браузерном UI в разделе _Settings > General > Upload Session Log_. Отправляемая вами обратная связь также загружается вместе с сессией, если только вы не запустите его с `DSH_TELEMETRY_MODE=DISABLED`.

### Агент по умолчанию

Выберите агента по умолчанию с помощью звёздочки рядом с агентом на панели агентов, которая заполнена у агента по умолчанию, или с помощью `omarchy default agent <name>`, которая также принимает любой харнесс, для которого там нет строки. Если агент ещё не установлен, выбор сначала установит его, а также он получит собственное средство запуска в средстве запуска приложений, рядом с Agent. Свежая установка Omarchy предлагает вам настроить одного с помощью одноразового уведомления, которое открывает панель агентов.

Выбор Claude также пытается настроить его расширение для браузера для Chromium, Chrome, Brave, Brave Origin и Edge. Настройка расширения применяется ко всем пользователям и может запросить ваш системный пароль; отмена или неудачная установка расширения всё равно выбирает и запускает Claude. Перезапустите браузер, включите расширение при появлении запроса и войдите в Claude, чтобы завершить его подключение. Выполните `/chrome` в Claude, чтобы проверить соединение. Firefox и Zen не поддерживают это расширение. Если Claude уже был вашим агентом по умолчанию до добавления этой настройки, выберите его снова, чтобы установить расширение.

После того как вы сделали выбор, `Super + Shift + Ctrl + A` запускает агента по умолчанию в отдельном окне терминала (или вызывает средство выбора, если вы ещё не выбрали). Вы также можете запустить его сразу с задачей с помощью `omarchy agent prompt "Review this project"`. Freebuff и DeepSeek Harness не принимают начальный запрос, поэтому вместо этого они открываются с запросом в вашем буфере обмена, чтобы вы могли его вставить. Агенты, запущенные таким образом, работают без присмотра в своих соответствующих режимах «не останавливайся, чтобы спросить», так что будьте готовы к тому, что они действительно начнут что-то делать! У MiniMax Code нет такого режима для его интерактивных сессий, поэтому он запрашивает разрешения как обычно. А поскольку агенты отказываются запоминать доверие для вашего домашнего каталога, запуски из `$HOME` вместо этого начинаются в `~/Work`.

Есть и ярлыки терминала: `a` запускает агента по умолчанию встроенно в текущем терминале, а `c`, `cx` и `cy` запускают OpenCode, Claude Code и Codex напрямую (опять же в их режимах с автоматическим подтверждением). Изменения темы также синхронизируются с агентами: Claude Code, Pi, OpenCode и Hermes (после того как Omarchy его установила) следуют за вами, когда вы переключаете тему Omarchy.

### Инструкции для ваших агентов

Личные правила для каждого агента размещаются в `~/.agents/AGENTS.md`, рядом с общими навыками в `~/.agents/skills`. Откройте его с помощью значка документа рядом с + на панели агентов или с помощью `omarchy agent instructions --edit`, которая также связывает его с каждым харнессом, который хранит свой собственный глобальный файл: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` у Copilot и так далее. Crush и Amp читают ссылку `~/.config/AGENTS.md`, а omp, Kimi и DeepSeek Harness читают `~/.agents/AGENTS.md` напрямую. Выбор агента по умолчанию также связывает его. Уже имевшийся у вас файл инструкций становится общим, если его ещё не было; в противном случае он сохраняется рядом со ссылкой как `.bak`. Выполните `omarchy agent instructions`, чтобы повторно связать после установки другого агента.

### Панель агентов

На верхней панели есть значок агентов. Прежде чем вы настроите агента, его панель предлагает три способа начать: войти по подписке Claude, Codex, Grok, Gemini, Muse, Cursor или Copilot, или в разделе More по тарифному плану для программирования OpenCode Go, MiniMax, Synthetic или Z.ai; платить по мере использования через Fireworks, OpenCode Zen and Go, OpenRouter, или в разделе More через DeepSeek или любого другого провайдера, в которого OpenCode выполняет вход, всё это запускается в OpenCode; или запустить лучшую модель для вашего компьютера, когда такая для него подходит. Первый завершённый вами вариант становится вашим агентом по умолчанию, а + на панели или _Agent > Add_ в меню Omarchy позже предлагает те же три варианта. После этого панель размещает каждую подписку на одной странице: каждый агент и учётная запись с её тарифом, индикатор для каждого из её 5-часовых сессионных и недельных лимитов со временем до его сброса (наведите курсор, чтобы увидеть точный процент), или оставшийся предоплаченный баланс, под строкой, которая поочерёдно показывает, что вы использовали по всем ним, например токены за эту неделю и вашу наиболее используемую модель. В разделе _Make something cool_ она предлагает стартовые запросы для новой темы, плагина, приложения или игры, которые передают задачу вашему агенту по умолчанию. Приложения создаются так же, как собственные Hype, Monologue и Omacut от Omarchy, на C++ и Qt Quick, следуя навыку агента omarchy-make-app, а нужные им компилятор и компоненты Qt поставляются установленными. Игры представляют собой одну страницу three.js в `~/Games/vibes`, следуя навыку агента omarchy-make-game, и все открываются из одного средства запуска Game Vibes в текущей теме; они загружают three.js из сети, поэтому для запуска им нужно соединение. Claude Code, Codex, Grok, Kimi, Cursor и его квота Grok Bot, GitHub Copilot, Muse, Gemini (через Antigravity) и Devin поддерживаются из коробки с их лимитами, Kimchi — с его тарифом, предоплаченными кредитами и бюджетами расходов, а Hermes, Mistral Vibe и Qwen Code показывают свои сессии и токены, как только вы ими воспользовались. Тарифы провайдеров и ключи, которые вы используете через pi, omp или opencode, также отображаются: OpenCode Zen and Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan и Synthetic с их лимитами; OpenRouter и DeepSeek с их предоплаченными балансами; Fireworks с его расходами за последние 30 дней. Токены от моделей, которые вы запускаете на собственном оборудовании, также засчитываются в итоги; у самих моделей есть собственная панель, описанная в разделе [Локальные модели](#local-models). Каждый агент учитывается один раз, у того, кто выставляет за него счёт, независимо от того, через сколько харнессов вы им управляете.

Щёлкните левой кнопкой мыши по значку на панели или нажмите `Super + Ctrl + X`, чтобы открыть панель, щёлкните правой кнопкой, чтобы запустить агента по умолчанию, и средней кнопкой, чтобы обновить. Записи об использовании, лежащие в её основе, перегенерируются каждые 15 минут командой `omarchy agent usage update`, а панель может даже объединять использование с других ваших машин через синхронизируемую папку. Полные настройки см. в README в `$OMARCHY_PATH/shell/plugins/agents/`.

### Несколько подписок

Если вы платите за более чем один тариф Claude, Codex или Grok — например, личный Max и рабочий, — Omarchy может держать их все вошедшими и перемещаться между ними. Добавьте подписку с помощью + на панели агентов, которая проведёт вас через это прямо там, или с помощью `omarchy agent account add claude Work` (или `codex`, или `grok`). Тот же + и та же команда выполняют вход в Gemini (`gemini`) и OpenCode (`opencode`) и сохраняют ключ API Fireworks (`fireworks`) или OpenRouter (`openrouter`) в OpenCode; команда также выполняет вход в Copilot (`copilot`), Cursor (`cursor`) и Muse (`muse`). Они сохраняют по одному входу каждый. Если CLI отсутствует, она его устанавливает. Первая учётная запись для провайдера выполняет вход через ваш обычный браузер, прямо там, где CLI всегда его ищет. Каждая последующая после этого выполняет вход через приватное окно, чтобы учётная запись, в которую ваш браузер уже вошёл, не была случайно подхвачена; войдите там как учётная запись, которую вы добавляете, и сначала закройте любое уже открытое у вас приватное окно. Никогда не выходите из CLI для этого: выход отзывает сохранённый вход, и эту учётную запись придётся добавлять снова.

Чтобы скопировать ваши входы по подпискам на другую машину Omarchy через SSH, выполните `omarchy agent account copy user@laptop`. Отправитель предоставляет временного получателя, когда на месте назначения он не установлен, поэтому более старые машины Omarchy могут получать учётные записи без обновления. Установленные получатели имеют приоритет. Это копирует все подписки Claude, Codex и Grok; добавьте имена провайдеров, чтобы выбрать их, как в `omarchy agent account copy laptop claude`. Имена учётных записей и идентификаторы команд соответствуют источнику, включая учётные записи, уже присутствующие на месте назначения. Несвязанные учётные записи на месте назначения получают числовой суффикс, если их имена конфликтуют, а настройки, навыки, плагины и история разговоров остаются локальными на каждой машине.

Существующие учётные данные на месте назначения сохраняются. Учётная запись источника, уже вошедшая там, синхронизирует своё имя без замены её учётных данных; другие учётные записи добавляются рядом с ней. Чтобы заменить сохранённые учётные данные для совпадающих учётных записей, используйте `omarchy agent account copy --replace laptop claude` после завершения сессий этой учётной записи на месте назначения. Свежее место назначения также получает активную учётную запись источника и предпочтения переключения; устоявшееся место назначения сохраняет свои собственные.

Учётные данные перемещаются через SSH и хранятся в приватных файлах на месте назначения, поэтому копируйте только на машины, которым вы доверяете. Это одноразовая копия, а не постоянная синхронизация. Токены обновления Codex могут быть ротированы другой машиной, в результате чего скопированный вход будет нуждаться в обновлении; отдельные входы остаются самым надёжным выбором для одновременного использования на нескольких машинах. См. [руководство Codex по аутентификации учётных записей](https://developers.openai.com/codex/auth/ci-cd-auth).

Одна учётная запись на провайдера активна, и каждая новая сессия начинается как она: `cx`, `cy`, обычный `claude`, `codex` или `grok`, всё, что запускается через `omarchy agent`, а также скрипты или редакторы, которые находят CLI в `PATH`. Переключайтесь с помощью `omarchy agent account use work` (и обратно с помощью `omarchy agent account use main`) или на панели, нажав номер учётной записи, а затем `Enter` (или щёлкнув по её звёздочке). Работающие сессии Claude также переключаются, со следующего сообщения: каждая сессия Claude работает в `~/.claude`, который всегда содержит вход активной учётной записи. Сессия Claude, запущенная в собственной папке учётной записи более старой Omarchy, сохраняет этот вход до своего завершения, поэтому переключение называет эти сессии и завершается само по себе, как только они исчезнут. Работающие сессии Codex и Grok остаются на учётной записи, с которой они начали. История разговоров, настройки, навыки и плагины являются общими для всех учётных записей, поэтому `claude --continue` в той же папке продолжит с того места, где вы остановились, на новой учётной записи.

При наличии более одной учётной записи панель показывает лимиты каждой учётной записи рядом, с заполненной звёздочкой на используемой. Omarchy уведомляет вас, когда активная учётная запись превышает 95% лимита, и щелчок по уведомлению переключает на учётную запись с наибольшим запасом. Она никогда не переключается сама по себе. Измените порог с помощью `omarchy agent account threshold 90`. Если каждая учётная запись превышает порог, вы услышите об этом один раз, вместе с тем, какая учётная запись освободится первой. Пока активная учётная запись находится в пределах 15 пунктов от своего порога (80% при значении по умолчанию), её лимиты проверяются каждые три минуты, а не каждые 15.

`omarchy agent account list` показывает каждую учётную запись и её последние лимиты, `omarchy agent account remove work` забывает одну, а `omarchy agent account rename primary Hey` переименовывает одну (или щёлкните по имени учётной записи на панели). Эти команды работают с учётными записями вашего агента по умолчанию; чтобы обратиться к другому провайдеру, сначала назовите его, как в `omarchy agent account use codex side`. Вход, который у вас уже был в `~/.claude` или `~/.codex`, — это учётная запись _Main_. У Codex она остаётся там, где она есть; у Claude она ждёт в своей собственной папке, пока активна другая учётная запись. Учётная запись, не использовавшаяся более примерно восьми часов, может показать _Sign-in required_; щёлкните по ней, чтобы снова войти в эту учётную запись прямо на панели, или переключитесь на неё и начните сессию, которая обновит вход сама по себе. Серверы MCP, которые вы добавляете с помощью `claude mcp add`, достигают каждой учётной записи Claude, поскольку все они работают в `~/.claude`; для Codex и Grok серверы, которые у вас были при добавлении учётной записи, переходят вместе с ней, но более поздние достигают только той учётной записи, в которой вы их добавили. Claude Desktop сохраняет собственный вход, а инструменты Codex или Grok, настроенные с абсолютным путём к двоичному файлу CLI, не следуют за переключением. Явный `CLAUDE_CONFIG_DIR`, `CODEX_HOME` или `GROK_HOME` имеет приоритет над выбранной учётной записью.

### Диагностика сбоев

Omarchy следит за systemd-coredump на предмет сбоев процессов. После того как вы выбрали агента по умолчанию, любая ваша программа, которая создаёт дамп ядра, вызывает уведомление «Process crashed» — щёлкните по нему, и сбой будет передан вашему агенту по умолчанию вместе с навыком omarchy-diagnose-crash от Omarchy, который проводит агента через установление фактов из дампа ядра и решение, стоит ли сообщать о сбое вверх по цепочке. Вы также можете запустить его вручную для любого PID из `coredumpctl list` с помощью `omarchy agent crash <pid>`.

Отслеживание включено по умолчанию. Отключите его в разделе _Trigger > Toggle > Crash Capture Off_ (или с помощью `omarchy toggle crash-capture`), и уведомления прекратятся; `omarchy agent crash <pid>` по-прежнему работает вручную.

Сбои также можно заглушить по одной программе за раз, что диагностика и предлагает вам в конце. `omarchy crash mute hyprland` останавливает уведомления только для этой программы, `omarchy crash mute hyprland off` возвращает их, а `omarchy crash mute` сам по себе перечисляет то, что вы заглушили. Он принимает путь к двоичному файлу так же охотно, как и его имя, поэтому `omarchy crash mute /usr/bin/hyprland` делает то же самое. Заключите имя с пробелом в кавычки, как в `omarchy crash mute 'Some App'`. Всё остальное по-прежнему уведомляет, а заглушённая программа по-прежнему завершается со сбоем — это скрывает напоминание, оно ничего не исправляет.

### Настольные приложения

Меню _Install > AI_ также содержит несколько графических приложений ИИ: Amp Desktop, Antigravity Desktop, настольное приложение ChatGPT, настольное приложение Claude (бета-версия Anthropic для Linux с вкладками Chat, Cowork и Claude Code), Grok Bot для общения с моделями xAI, Herdr Desktop, Hermes Desktop, OpenClaw, настольное приложение Perplexity и T3 Code. Grok Bot — это настольное приложение для чата. Агентом для программирования является команда `grok`.

Hermes Desktop — это то, о чём нужно знать, потому что на машине есть один Hermes, и он принадлежит приложению: Hermes устанавливается только через приложение, и команда `hermes`, которую запускает агент по умолчанию, принадлежит приложению. Выбор Hermes в качестве агента по умолчанию устанавливает то же самое, что и пункт _Install > AI_: пакет и среду выполнения Hermes в `~/.hermes`, настроенную собственным установщиком Hermes, что при первом разе занимает несколько минут. Эта среда выполнения — та единственная Hermes, которую используют терминальная команда `hermes`, агент по умолчанию и приложение, и она обновляет себя с помощью `hermes update`, а не ждёт релиза Omarchy. Её установка также передаёт Hermes тему Omarchy в виде скина с именем `omarchy`, которому следует каждая поверхность Hermes при переключении тем; выберите другую в настройках Appearance у Hermes или с помощью `/skin`, если вы предпочитаете, чтобы этого не было, и Omarchy оставит этот выбор в покое. Удаление приложения в разделе _Remove > AI_ сначала закрывает Hermes, включая шлюз, забирает эту среду выполнения с собой и сохраняет ваши чаты, воспоминания и навыки, которые Hermes написала для себя, если только вы не скажете ей иное: она спрашивает, по умолчанию — нет, должна ли эта информация и ваши настройки подключения также исчезнуть.

Настольный опыт OpenClaw — это его Control UI, который открывается как веб-приложение, поддерживаемое его собственным локальным шлюзом. OpenClaw живёт в `~/.openclaw` и обновляет себя: используйте кнопку «Update Gateway» в Control UI или выполните `openclaw update`, и шлюз перезапустится на новой версии. Omarchy только выбирает релиз, с которого начинается свежая установка. OpenClaw также может быть вашим агентом по умолчанию: выбор его в разделе _Agent > Harness_ настраивает ту же копию в `~/.openclaw`, и агент открывает терминальный UI OpenClaw, подключённый к его шлюзу. Удаление OpenClaw в разделе _Remove > AI_ забирает с собой службу шлюза и приложение, а затем спрашивает, должна ли также исчезнуть `~/.openclaw`, поскольку там хранятся ваши чаты и учётные данные наряду с самим OpenClaw и средами выполнения плагинов, которые он загружает; по умолчанию она сохраняется, и повторная установка OpenClaw подхватит её обратно.

Herdr Desktop — это настольное приложение [Herdr](https://herdr.dev): пространства, вкладки и панели терминалов и агентов для программирования, которые продолжают работать в его ядре, когда вы закрываете окно. Оно поставляется из собственного установщика Herdr, а не из пакета, поэтому оно живёт в `~/.local/share/herdr-app`, приносит своё ядро в `~/.local/bin/herdr-core`, когда у вас его ещё нет, и обновляет и себя, и его. Оно находится рядом с командой `herdr`, которую Omarchy поставляет на `Super + Ctrl + Return`, а не заменяет её, и получает прямые клавиши этой команды: `Alt + Return` и `Alt + Shift + Return` разделяют панель вниз или вправо, `Alt + Escape` закрывает её, `Ctrl + Alt + Arrow` перемещается между панелями, `Alt + 1..9` и `Alt + Left/Right` выбирают вкладку, а `Alt + Up/Down` перемещаются между пространствами. `Ctrl + 1..9` выбирает пространство, а `Alt + Shift + Up/Down` перемещается по агентам. Префиксные клавиши `Ctrl + Space` остаются только для терминала, поскольку приложение не может удерживать обычную клавишу Ctrl для последовательности. Omarchy записывает их в `~/.config/herdr-app/keys.json`, а `omarchy-refresh-herdr-app` возвращает их обратно. Его установка выбирает тему Omarchy для Herdr, которая с этого момента следует вашей теме Omarchy. Herdr хранит одну тему для светлого режима и одну для тёмного, поэтому после переключения между тёмной и светлой темой Omarchy выберите Omarchy в средстве выбора тем Herdr ещё раз для другого режима.

T3 Code работает из своего официального релиза AppImage в `~/.local/share/t3code`, а не из пакета, поэтому он обновляет себя. Его установка спрашивает, начинать ли с канала Stable или Nightly; переключите позже в настройках T3 Code. Ваши потоки и настройки живут в `~/.t3`, и удаление T3 Code в разделе _Remove > AI_ забирает их с собой.

### Локальные модели

Запускайте открытую модель на собственной машине для ваших агентов для программирования. Ваши запросы и код остаются на машине; ничто, отправленное модели, не покидает её. Начните с:

```bash
omarchy models use best text
```

Это настраивает лучшую текстовую модель для этой машины, ту, которую используют ваши агенты. У моделей изображений, видео и музыки есть своя лучшая: `omarchy models use best image`, `video` или `music`. Выполните `omarchy models use best`, чтобы увидеть выбор каждого вида для этой машины.

Или откройте панель локальных моделей с помощью её значка с блёстками на верхней панели, рядом со значком агентов, или с помощью Super + Ctrl + Alt + X и выберите +. Значок появляется, когда модель подходит для этой машины. Podman, который запускает модели, поставляется с Omarchy, как и набор инструментов контейнеров NVIDIA на машине NVIDIA, который даёт им GPU; если что-то из этого отсутствует, первая настройка установит это. Затем Omarchy выбирает рекомендуемую модель для этой машины, загружает её и запускает. Ожидайте загрузку в десятки GB и использование большей части памяти машины во время работы модели: Flash Next использует около 100 GiB при полном контексте 256K. Если другие модели удерживают нужную ей память, она настраивается остановленной, готовой к запуску, как только вы остановите одну. Модель останавливается при выходе из системы; остановите её сами, когда вам нужна память для чего-то другого.

`omarchy models list` показывает варианты и объясняет, почему некоторые не подходят. Чтобы настроить другую, выполните `omarchy models use <recipe>`. Сегодня `qwen3.8-flash-next-gufo` и `qwen3.8-27b-gufo` доступны для машин Strix Halo со 128 GB; 27B занимает около 40 GiB, поэтому она оставляет место для другой работы. На ноутбуке с 64 GB и Intel Arc B390 `qwen3.6-35b-a3b-llamacpp` работает примерно в 30 GiB. Новые рецепты и рекомендации поступают с `omarchy update` через пакет.

Каждая настроенная вами модель получает свою строку на панели локальных моделей: воспроизведение, чтобы запустить её, пауза, чтобы остановить её и освободить её память, и кнопка терминала, чтобы открыть вашего агента на ней. Вверху полоса показывает, как память машины разделена между самой Omarchy (системой и вашими приложениями), каждой работающей моделью и тем, что свободно. Наведите курсор на остановленную модель, и полоса покажет, подходит ли она или насколько ей не хватает. Несколько могут работать одновременно, когда они вместе помещаются в памяти; если одна не помещается, Omarchy говорит, какую работающую модель остановить. Перетаскивайте строки за их логотип, чтобы изменить их порядок, и нажмите Delete на выбранной строке, чтобы удалить модель и её загрузку.

Каждая настроенная вами модель для программирования также получает собственную запись в средстве запуска приложений, под именем модели и с логотипом её создателя, так же как вход в Claude, Codex или Grok добавляет одну. Она открывает вашего агента на этой модели и сначала запускает модель, если она не работает: терминал показывает её загрузку и передаёт управление агенту, как только она будет готова. Удаление модели удаляет её запись.

Не каждая модель предназначена для программирования. Модели изображений, видео и музыки вместо этого открываются в Fantasi, приложении Omarchy для создания изображений, видео и музыки с моделью, работающей на этой машине, выбранной там или из их строки на панели локальных моделей.

Модель продолжает работать точно так, как она была настроена, поэтому обновление Omarchy никогда не перезапускает одну под вашими агентами. Когда у Omarchy есть более новая среда выполнения или более новые веса для настроенной вами модели, её строка показывает кнопку обновления: нажмите её, и модель будет настроена снова в фоновом режиме, загружая только то, что изменилось, и перезапустится на новой версии. Модель, которая была остановлена, остаётся остановленной. `omarchy models update` делает то же самое для каждой модели из терминала.

Из командной строки `omarchy models start <recipe>` и `omarchy models stop <recipe>` делают то же самое, `omarchy models status` показывает каждую модель, а `omarchy agent --local-model <recipe>` открывает эту модель в pi, каким бы ни был ваш агент по умолчанию. Чтобы сделать вашу локальную модель тем, что открывают горячая клавиша агента, консоль Quake и _Make something_, выполните `omarchy default agent local` или выберите _Local model_ в разделе _Agent > Harness_. pi также перечисляет каждую настроенную вами модель и те, что находятся на машинах, с которыми вы выполнили сопряжение, в своём собственном средстве выбора моделей, поэтому обычный `pi` также достигает их. Любой клиент, совместимый с OpenAI, также может подключиться: `status` показывает адрес каждой модели (первый — `http://127.0.0.1:11435/v1`), имя рецепта — это модель, а ключ находится в `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` удаляет модель и загрузки, которые не использует ни одна другая модель.

Сторонние среды выполнения помечены их издателем. Omarchy запускает каждую модель без доступа к сети.

### Локальные LLM

Omarchy рекомендует два способа запуска локальных моделей LLM: LM Studio и Ollama. LM Studio предоставляет графический интерфейс для поиска моделей с открытыми весами, их установки и запуска. Это отличный способ легко начать. Ollama предлагает CLI для того же самого. Но если вы новичок в локальных моделях, я бы начал с LM Studio. Вы можете установить любое из них в разделе _Install > AI_ в меню Omarchy.

### Навыки Omarchy

Навыки агентов помогают ИИ использовать конкретные инструменты конкретным образом, и Omarchy поставляет семь из них. Навык omarchy охватывает настройку системы, например настройку вашей конфигурации Hyprland или регулировку панели. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app и omarchy-make-game охватывают создание чего-то нового, omarchy-contribute охватывает сообщение об ошибке или отправку исправления вверх по цепочке, а omarchy-diagnose-crash работает с дампом ядра сбоя. Они связаны символическими ссылками с каталогами навыков для Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` и каждый `~/.hermes/profiles/*/skills`) и общим расположением `~/.agents/skills`, поэтому большинство харнессов подхватывают их автоматически. Ваша собственная папка навыка с тем же именем имеет приоритет.

Но вам следует относиться к этим навыкам как к экспериментальным. Разные модели будут использовать их с разным эффектом. Лучше сначала запускать в режиме планирования, чтобы у вас было представление о том, что агент хотел бы изменить. А затем будьте готовы откатить изменения или даже вызвать `omarchy reinstall configs`, если агент всё испортит.
