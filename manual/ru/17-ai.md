# ИИ

В Omarchy есть лаунчеры для перечисленных ниже coding-агентов, но агент по умолчанию за вас не выбран. Запустите команду, чтобы при первом использовании установить её CLI, а затем при появлении запроса пройдите аутентификацию. Hermes и OpenClaw — исключения: для них через mise ничего не устанавливается, а выбор любого из них настраивает его собственную самообновляющуюся копию, как объясняется ниже в разделе _Настольные приложения_.

### Установка и обновление агентов

За исключением Hermes и OpenClaw, эти агенты используют ленивую установку mise: при первом запуске устанавливается CLI, а при последующих запусках используется уже установленная версия. mise также проверяет, не вышла ли новая версия установленного агента, не чаще одного раза в четыре часа, прямо перед его запуском или в фоновом режиме в приглашении оболочки. Если это обновление завершается неудачей или вы не в сети, запускается установленная версия. `omarchy update` обновляет установленных агентов вместе с остальной частью Omarchy, а `mup` обновляет только инструменты, управляемые mise.

Собственный механизм обновления агента, например `claude update`, `codex update` или кнопка обновления в приложении, не обновляет установку, управляемую mise. `codex update` завершается неудачей, а `claude update` может сообщить об успехе, при этом установив отдельную копию, которую mise не отслеживает. Если вы предпочитаете использовать родной установщик и механизм обновления агента, добавьте его в `disable_tools`; см. [Предустановленные инструменты CLI](18-development-tools.md#preinstalled-cli-tools).

Чтобы установить все настроенные ленивые инструменты до того, как они вам понадобятся, запустите `mise install --include-lazy`. Это включает другие инструменты CLI Omarchy по умолчанию, а также агентов. См. [Предустановленные инструменты CLI](18-development-tools.md#preinstalled-cli-tools) об установке одного инструмента или использовании собственной установки.

`grok` устанавливается через собственный пакет mise `grok`, точно так же, как `claude` и `codex`. Запустите `grok` или отметьте его звёздочкой на панели агентов. Пропустите установщик `curl | bash` на x.ai. Тот путь помещает вторую копию в `~/.grok/bin`, ставит её первой на `PATH` и перезаписывает обёртку Omarchy.

`dsh` открывает свой браузерный UI на `127.0.0.1:3080`, где каталог запуска является рабочим пространством по умолчанию. Его браузерный UI не принимает стартовый промпт, поэтому `omarchy agent prompt` открывает его с промптом в вашем буфере обмена, чтобы вы могли его вставить. Omarchy запускает его с пресетом разрешений DeepSeek без подтверждений. DeepSeek Harness загружает журналы сессий в DeepSeek, когда вы используете его официальный API моделей; отключите это в его браузерном UI в разделе _Settings > General > Upload Session Log_. Отправляемая вами обратная связь также загружается вместе с сессией, если только вы не запустите его с `DSH_TELEMETRY_MODE=DISABLED`.

### Агент по умолчанию

Выберите агента по умолчанию с помощью звёздочки рядом с агентом на панели агентов, которая заполнена у агента по умолчанию, или с помощью `omarchy default agent <name>`, которая также принимает любой harness, для которого там нет строки. Если агент ещё не установлен, при его выборе он сначала устанавливается, а также получает собственный лаунчер в лаунчере приложений, рядом с Agent. Свежая Omarchy предлагает вам настроить одного с помощью одноразового уведомления, которое открывает панель агентов.

Выбор Claude также пытается настроить его расширение для браузера для Chromium, Chrome, Brave, Brave Origin и Edge. Настройка расширения применяется ко всем пользователям и может запросить ваш системный пароль; отмена или неудачная установка расширения всё равно выбирает и запускает Claude. Перезапустите браузер, включите расширение при появлении запроса и войдите в Claude, чтобы завершить его подключение. Запустите `/chrome` в Claude, чтобы проверить соединение. Firefox и Zen не поддерживают это расширение. Если Claude уже был вашим агентом по умолчанию до того, как была добавлена эта настройка, выберите его снова, чтобы установить расширение.

После того как вы сделали выбор, `Super + Shift + Ctrl + A` запускает агента по умолчанию в отдельном окне терминала (или вызывает средство выбора, если вы ещё ничего не выбрали). Вы также можете запустить его сразу для выполнения задачи с помощью `omarchy agent prompt "Review this project"`. Freebuff и DeepSeek Harness не принимают стартовый промпт, поэтому вместо этого они открываются с промптом в вашем буфере обмена, чтобы вы могли его вставить. Запущенные таким способом агенты работают без присмотра в своих соответствующих режимах «не останавливайся, чтобы спросить», так что будьте готовы к тому, что они действительно будут что-то делать! У MiniMax Code нет такого режима для его интерактивных сессий, поэтому он запрашивает разрешения как обычно. А поскольку агенты отказываются запоминать доверие для вашего домашнего каталога, запуски из `$HOME` вместо этого начинаются в `~/Work`.

Есть и ярлыки терминала: `a` запускает агента по умолчанию прямо в текущем терминале, а `c`, `cx`, `cy` и `ca` запускают OpenCode, Claude Code, Codex и Antigravity напрямую (снова в их режимах с автоматическим одобрением). Изменения темы также синхронизируются с агентами: Claude Code, Pi, OpenCode и Hermes (после того как Omarchy его установила) следуют за вами, когда вы переключаете тему Omarchy.

### Ваши инструкции для агентов

Личные правила для каждого агента помещаются в `~/.agents/AGENTS.md`, рядом с общими скиллами в `~/.agents/skills`. Откройте его с помощью значка документа рядом с + на панели агентов или с помощью `omarchy agent instructions --edit`, которая также связывает его с каждым harness, у которого есть собственный глобальный файл: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` у Copilot и так далее. Crush и Amp читают ссылку `~/.config/AGENTS.md`, а omp, Kimi и DeepSeek Harness читают `~/.agents/AGENTS.md` напрямую. Выбор агента по умолчанию также связывает его. Файл инструкций, который у вас уже был, становится общим, если общего ещё не было; в противном случае он сохраняется рядом со ссылкой как `.bak`. Запустите `omarchy agent instructions`, чтобы повторно связать после установки другого агента.

### Панель агентов

На верхней панели есть значок агентов. До того как вы настроите агента, его панель предлагает три способа начать: войти по подписке Claude, Codex, Grok, Gemini, Muse, Cursor или Copilot, или в разделе More по coding-плану OpenCode Go, MiniMax, Synthetic или Z.ai; платить по мере использования с Fireworks, OpenCode Zen and Go, OpenRouter или в разделе More с DeepSeek или любым другим провайдером, в который входит OpenCode, всё это работает в OpenCode; или запустить лучшую модель для вашего компьютера, когда для него есть подходящая. Первый вариант, который вы завершите, становится вашим агентом по умолчанию, а + на панели позже предлагает те же три варианта. После этого панель размещает каждую подписку на одной странице: каждый агент и аккаунт с его планом, индикатор для каждого из его 5-часового лимита сессии и недельных лимитов со временем до его сброса (наведите курсор, чтобы увидеть точный процент) или остаток предоплаченного баланса, под строкой, которая по кругу показывает, что вы использовали по всем ним, например токены за эту неделю и вашу самую используемую модель. В разделе _Make something cool_ она предлагает стартовые промпты для новой темы, плагина, приложения или игры, которые передают задачу вашему агенту по умолчанию. Приложения создаются так же, как собственные Hype, Monologue и Omacut в Omarchy, на C++ и Qt Quick, следуя скиллу агента omarchy-make-app, а компилятор и компоненты Qt, которые им нужны, уже установлены. Игры — это одна страница three.js в `~/Games/vibes`, созданная по скиллу агента omarchy-make-game, и все они открываются из одного лаунчера Game Vibes в текущей теме; они загружают three.js из сети, поэтому для запуска им нужно соединение. Claude Code, Codex, Grok, Kimi, Cursor и его лимит Grok Bot, GitHub Copilot, Muse, Gemini (через Antigravity) и Devin покрываются из коробки со своими лимитами, Kimchi — со своим планом, предоплаченными кредитами и бюджетами расходов, а Hermes, Mistral Vibe и Qwen Code показывают свои сессии и токены после того, как вы ими воспользовались. Планы и ключи провайдеров, которые вы используете через pi, omp или opencode, также отображаются: OpenCode Zen and Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan и Synthetic со своими лимитами; OpenRouter и DeepSeek со своими предоплаченными балансами; Fireworks с его расходами за последние 30 дней. Coding-модели, которые вы запускаете на собственном оборудовании, получают свои собственные строки, и их токены также засчитываются в общие итоги, как описано в разделе [Локальные модели](#local-models). Каждый агент учитывается один раз, по тому, кто выставляет за него счёт, независимо от того, через сколько harness вы им управляете.

Щёлкните левой кнопкой мыши по значку панели или нажмите `Super + Ctrl + X`, чтобы открыть панель, щёлкните правой кнопкой, чтобы запустить агента по умолчанию, и средней кнопкой, чтобы обновить. Записи об использовании, лежащие в её основе, перегенерируются каждые 15 минут с помощью `omarchy agent usage update`, а панель может даже объединять использование с ваших других машин через синхронизируемую папку. См. README в `$OMARCHY_PATH/shell/plugins/agents/` для полных настроек.

### Несколько подписок

Если вы платите за несколько планов Claude, Codex или Grok — например, личный Max и рабочий — Omarchy может держать их все вошедшими в систему и перемещаться между ними. Добавьте подписку с помощью + на панели агентов, которая проведёт вас через это прямо там, или с помощью `omarchy agent account add claude Work` (или `codex`, или `grok`). Тот же + и та же команда выполняют вход в Gemini (`gemini`) и OpenCode (`opencode`) и сохраняют ключ API Fireworks (`fireworks`) или OpenRouter (`openrouter`) в OpenCode; команда также выполняет вход в Copilot (`copilot`), Cursor (`cursor`) и Muse (`muse`). У них у каждого сохраняется один вход. Она устанавливает CLI, если его нет. Первый аккаунт провайдера входит через ваш обычный браузер, прямо там, где CLI всегда его ищет. Каждый следующий после него входит через приватное окно, чтобы аккаунт, в который ваш браузер уже вошёл, не был подхвачен по ошибке; войдите там как аккаунт, который вы добавляете, и сначала закройте любое приватное окно, которое у вас уже открыто. Никогда не выходите из CLI, чтобы сделать это: выход отзывает сохранённый вход, и этот аккаунт придётся добавлять снова.

Чтобы скопировать входы по подпискам на другую машину с Omarchy по SSH, запустите `omarchy agent account copy user@laptop`. Отправитель предоставляет временного получателя, когда на месте назначения он не установлен, чтобы более старые машины с Omarchy могли получать аккаунты без обновления. Установленные получатели имеют приоритет. Это копирует все подписки Claude, Codex и Grok; добавьте имена провайдеров, чтобы выбрать их, как в `omarchy agent account copy laptop claude`. Имена аккаунтов и ID команд совпадают с источником, включая аккаунты, уже присутствующие на месте назначения. Не связанные с ними аккаунты места назначения получают числовой суффикс, если их имена конфликтуют, а настройки, скиллы, плагины и история разговоров остаются локальными для каждой машины.

Существующие учётные данные места назначения сохраняются. Аккаунт источника, уже вошедший там, получает синхронизацию своего имени без замены его учётных данных; другие аккаунты добавляются рядом с ним. Чтобы заменить сохранённые учётные данные для совпадающих аккаунтов, используйте `omarchy agent account copy --replace laptop claude`, предварительно завершив сессии этого аккаунта на месте назначения. Свежее место назначения также получает активный аккаунт источника и его предпочтения переключения; устоявшееся место назначения сохраняет свои собственные.

Учётные данные передаются через SSH и хранятся в приватных файлах на месте назначения, поэтому копируйте только на машины, которым вы доверяете. Это одноразовое копирование, а не постоянная синхронизация. Токены обновления Codex могут быть ротированы другой машиной, из-за чего скопированному входу потребуется обновление; отдельные входы остаются самым надёжным выбором для одновременного использования на нескольких машинах. См. [руководство Codex по аутентификации аккаунтов](https://developers.openai.com/codex/auth/ci-cd-auth).

Один аккаунт на провайдера активен, и каждая новая сессия начинается как он: `cx`, `cy`, обычный `claude`, `codex` или `grok`, всё, что запускается через `omarchy agent`, а также скрипты или редакторы, которые находят CLI на `PATH`. Переключайтесь с помощью `omarchy agent account use work` (и обратно с помощью `omarchy agent account use main`) или на панели, нажав номер аккаунта, а затем `Enter` (или щёлкнув по его звёздочке). Работающие сессии Claude тоже переключаются, со следующего сообщения: каждая сессия Claude работает в `~/.claude`, где всегда находится вход активного аккаунта. Сессия Claude, запущенная в собственной папке аккаунта более старой Omarchy, сохраняет этот вход до своего завершения, поэтому переключение называет эти сессии и завершается само, как только они исчезнут. Работающие сессии Codex и Grok остаются на аккаунте, с которым они начали работу. История разговоров, настройки, скиллы и плагины являются общими для всех аккаунтов, поэтому `claude --continue` в той же папке продолжит с того места, где вы остановились, на новом аккаунте.

При наличии нескольких аккаунтов панель показывает лимиты каждого аккаунта рядом друг с другом, с заполненной звёздочкой у используемого. Omarchy уведомляет вас, когда активный аккаунт превышает 95% лимита, и щелчок по уведомлению переключает на аккаунт с наибольшим запасом. Она никогда не переключается сама. Измените порог с помощью `omarchy agent account threshold 90`. Если каждый аккаунт превышает порог, вы услышите об этом один раз, а также о том, какой аккаунт освободится первым. Пока активный аккаунт находится в пределах 15 пунктов от своего порога (80% при значении по умолчанию), его лимиты проверяются каждые три минуты, а не каждые 15.

`omarchy agent account list` показывает каждый аккаунт и его последние лимиты, `omarchy agent account remove work` забывает один, а `omarchy agent account rename primary Hey` переименовывает один (или щёлкните по имени аккаунта на панели). Эти команды работают с аккаунтами вашего агента по умолчанию; чтобы обратиться к другому провайдеру, сначала назовите его, как в `omarchy agent account use codex side`. Вход, который у вас уже был в `~/.claude` или `~/.codex`, — это аккаунт _Main_. У Codex он остаётся на месте; у Claude он ждёт в собственной папке, пока активен другой аккаунт. Аккаунт, который не использовался более примерно восьми часов, может показывать _Sign-in required_; щёлкните по нему, чтобы снова войти в этот аккаунт прямо на панели, или переключитесь на него и запустите сессию, что само обновит вход. Серверы MCP, которые вы добавляете с помощью `claude mcp add`, доступны каждому аккаунту Claude, поскольку все они работают в `~/.claude`; для Codex и Grok серверы, которые у вас были на момент добавления аккаунта, переходят в него, но более поздние доступны только тому аккаунту, в котором вы их добавили. Claude Desktop сохраняет собственный вход, а инструменты Codex или Grok, настроенные с абсолютным путём к бинарному файлу CLI, не следуют за переключением. Явный `CLAUDE_CONFIG_DIR`, `CODEX_HOME` или `GROK_HOME` имеет приоритет над выбранным аккаунтом.

### Диагностика сбоев

Omarchy следит за systemd-coredump на предмет сбоев процессов. После того как вы выберете агента по умолчанию, любая ваша программа, которая сбрасывает core, вызывает уведомление «Process crashed» — щёлкните по нему, и сбой будет передан вашему агенту по умолчанию вместе со скиллом omarchy-diagnose-crash в Omarchy, который проведёт агента через установление фактов из дампа ядра и принятие решения о том, стоит ли сообщать о сбое в upstream. Вы также можете запустить его вручную для любого PID из `coredumpctl list` с помощью `omarchy agent crash <pid>`.

Наблюдение включено по умолчанию. Отключите его в разделе _Trigger > Toggle > Crash Capture Off_ (или с помощью `omarchy toggle crash-capture`), и уведомления прекратятся; `omarchy agent crash <pid>` по-прежнему работает вручную.

Сбои также можно заглушить по одной программе за раз, что диагностика и предлагает вам в конце. `omarchy crash mute hyprland` прекращает уведомления только для этой программы, `omarchy crash mute hyprland off` возвращает их, а `omarchy crash mute` сама по себе перечисляет то, что вы заглушили. Она так же охотно принимает путь к бинарному файлу, как и его имя, поэтому `omarchy crash mute /usr/bin/hyprland` делает то же самое. Заключите имя с пробелом в кавычки, как в `omarchy crash mute 'Some App'`. Всё остальное по-прежнему уведомляет, а заглушенная программа по-прежнему падает — это скрывает напоминание, а не исправляет что-либо.

### Настольные приложения

Меню _Install > AI_ также содержит несколько графических приложений ИИ: Amp Desktop, Antigravity Desktop, настольное приложение ChatGPT, настольное приложение Claude (бета-версия Anthropic для Linux, с вкладками Chat, Cowork и Claude Code), Grok Bot для общения с моделями xAI, Herdr Desktop, Hermes Desktop, OpenClaw, настольное приложение Perplexity и T3 Code. Grok Bot — это настольное приложение для чата. Coding-агентом является команда `grok`.

Hermes Desktop — это то, о чём стоит знать, потому что у машины один Hermes, и он принадлежит приложению: Hermes всегда устанавливается только через приложение, а команда `hermes`, которую запускает агент по умолчанию, принадлежит приложению. Выбор Hermes в качестве агента по умолчанию устанавливает то же самое, что и пункт _Install > AI_: пакет и среду выполнения Hermes в `~/.hermes`, настроенную собственным установщиком Hermes, что в первый раз занимает несколько минут. Эта среда выполнения — это тот единственный Hermes, который используют терминальная команда `hermes`, агент по умолчанию и приложение, и она обновляет сама себя с помощью `hermes update`, а не ждёт релиза Omarchy. Её установка также передаёт Hermes тему Omarchy как скин с именем `omarchy`, которому следует каждая поверхность Hermes при переключении вами тем; выберите другой в настройках Appearance в Hermes или с помощью `/skin`, если вы предпочитаете, чтобы этого не было, и Omarchy оставит этот выбор в покое. Удаление приложения в разделе _Remove > AI_ сначала закрывает Hermes, включая шлюз, забирает эту среду выполнения с собой и сохраняет ваши чаты, воспоминания и скиллы, которые Hermes написал для себя, если только вы не скажете ей иное: она спрашивает, по умолчанию отвечая «нет», должны ли эти данные и ваши настройки подключения также исчезнуть.

Рабочий процесс OpenClaw на рабочем столе — это его Control UI, который открывается как веб-приложение, поддерживаемое его собственным локальным шлюзом. OpenClaw живёт в `~/.openclaw` и обновляет сам себя: используйте кнопку «Update Gateway» в Control UI или запустите `openclaw update`, и шлюз перезапустится на новой версии. Omarchy только выбирает релиз, с которого начинается свежая установка. OpenClaw также может быть вашим агентом по умолчанию: выбор его с помощью `omarchy default agent openclaw` настраивает ту же копию в `~/.openclaw`, а агент открывает терминальный UI OpenClaw, подключённый к его шлюзу. Удаление OpenClaw в разделе _Remove > AI_ забирает с собой службу шлюза и приложение, а затем спрашивает, должен ли `~/.openclaw` также исчезнуть, поскольку там хранятся ваши чаты и учётные данные наряду с самим OpenClaw и средами выполнения плагинов, которые он загружает; по умолчанию он сохраняется, а повторная установка OpenClaw снова его подхватывает.

Herdr Desktop — это настольное приложение [Herdr](https://herdr.dev): пространства, вкладки и панели терминалов и coding-агентов, которые продолжают работать в его ядре, когда вы закрываете окно. Оно поставляется собственным установщиком Herdr, а не пакетом, поэтому живёт в `~/.local/share/herdr-app`, приносит своё ядро в `~/.local/bin/herdr-core`, когда у вас его ещё нет, и обновляет обе части само. Оно находится рядом с командой `herdr`, которую Omarchy поставляет на `Super + Ctrl + Return`, а не заменяет её, и получает прямые клавиши этой команды: `Alt + Return` и `Alt + Shift + Return` разделяют панель вниз или вправо, `Alt + Escape` закрывает её, `Ctrl + Alt + Arrow` перемещает между панелями, `Alt + 1..9` и `Alt + Left/Right` выбирают вкладку, а `Alt + Up/Down` перемещают между пространствами. `Ctrl + 1..9` выбирает пространство, а `Alt + Shift + Up/Down` перебирает агентов. Клавиши с префиксом `Ctrl + Space` остаются только для терминала, поскольку приложение не может удерживать обычную клавишу Ctrl для последовательности. Omarchy записывает их в `~/.config/herdr-app/keys.json`, а `omarchy-refresh-herdr-app` возвращает их обратно. При его установке выбирается тема Omarchy для Herdr, которая с тех пор следует за вашей темой Omarchy. Herdr хранит одну тему для светлого режима и одну для тёмного, поэтому после переключения между тёмной и светлой темой Omarchy ещё раз выберите Omarchy в средстве выбора темы Herdr для другого режима.

T3 Code работает из своего официального релиза AppImage в `~/.local/share/t3code`, а не из пакета, поэтому он обновляет сам себя. При его установке спрашивается, начинать ли на канале Stable или Nightly; переключите позже в настройках T3 Code. Ваши треды и настройки живут в `~/.t3`, и удаление T3 Code в разделе _Remove > AI_ забирает их с собой.

### Локальные модели

Запускайте открытую модель на своей собственной машине для ваших coding-агентов. Ваши промпты и код остаются на машине; ничто из отправленного модели не покидает её. Начните с:

```bash
omarchy models use best text
```

Это настраивает лучшую текстовую модель для этой машины, ту, которую используют ваши агенты. У моделей изображений, видео и музыки есть своя лучшая: `omarchy models use best image`, `video` или `music`. Запустите `omarchy models use best`, чтобы увидеть выбор каждого вида для этой машины.

Или выберите + на панели агентов: в разделе _Use a local model_ перечислена каждая coding-модель, подходящая для этой машины, рекомендуемая — первой. Podman, который запускает модели, поставляется с Omarchy, как и инструментарий контейнеров NVIDIA на машине с NVIDIA, который даёт им GPU; если чего-то из этого нет, первая настройка устанавливает это. Затем Omarchy выбирает рекомендуемую модель для этой машины, загружает её и запускает. Ожидайте загрузку в десятки GB и использование большей части памяти машины во время работы модели: Flash Next использует около 100 GiB с его полным контекстом 256K. Если другие модели занимают нужную ей память, она настраивается остановленной, готовой к запуску, как только вы остановите одну из них. Модель останавливается при выходе из системы; останавливайте её сами, когда вам нужна память для чего-то другого.

`omarchy models list` показывает варианты и объясняет, почему некоторые не подходят. Чтобы настроить другую, запустите `omarchy models use <recipe>`. Сегодня `qwen3.8-flash-next-gufo` и `qwen3.8-27b-gufo` доступны для машин Strix Halo со 128 GB; 27B занимает около 40 GiB, поэтому она оставляет место для другой работы. На ноутбуке с 64 GB и Intel Arc B390 `qwen3.6-35b-a3b-llamacpp` работает примерно в 30 GiB. Новые рецепты и рекомендации поступают с `omarchy update`, через пакет.

Coding-модель, которую вы добавляете, получает собственную строку на панели агентов, рядом с вашими подписками: «play» для её запуска, «pause» для её остановки и освобождения её памяти, метка Tailscale для совместного использования её с другими машинами в вашем tailnet во время её работы и кнопка терминала для открытия вашего агента на ней. Её строка показывает загрузку, загрузку в память или остановку по мере выполнения и сообщает, когда не хватает свободной памяти для её запуска, или ссылается на её журналы, когда она остановилась с ошибкой. Несколько могут работать одновременно, когда они вместе помещаются в памяти. Нажмите Delete на выбранной строке, чтобы удалить модель с этой машины, вместе с загрузкой; + может настроить её снова. Coding-модель, настроенная из терминала, ждёт под +, пока вы её не добавите, и так же делают модели, которые запускает машина, с которой вы выполнили сопряжение (`omarchy models pair <host>`).

Каждая coding-модель, которую вы настраиваете, также получает собственную запись в лаунчере приложений, под именем модели и с логотипом её создателя, так же, как вход в Claude, Codex или Grok добавляет такую запись. Она открывает вашего агента на этой модели и сначала запускает модель, если она не работает: терминал показывает её загрузку и передаёт управление агенту, как только она будет готова. Удаление модели удаляет её запись.

Не каждая модель предназначена для coding. Модели изображений, видео и музыки вместо этого открываются в Fantasi, приложении Omarchy для создания изображений, видео и музыки с помощью модели, работающей на этой машине, и управляются там или с помощью `omarchy models`.

Модель продолжает работать точно так, как она была настроена, поэтому обновление Omarchy никогда не перезапускает её под вашими агентами. Когда у Omarchy есть более новая среда выполнения или более новые веса для модели, которую вы настроили, её строка показывает кнопку обновления: нажмите её, и модель будет настроена снова в фоновом режиме, загружая только то, что изменилось, и перезапустится на новой версии. Модель, которая была остановлена, остаётся остановленной. `omarchy models update` делает то же самое для каждой модели из терминала.

Из командной строки `omarchy models start <recipe>` и `omarchy models stop <recipe>` делают то же самое, `omarchy models status` показывает каждую модель, а `omarchy agent --local-model <recipe>` открывает эту модель в pi, независимо от того, какой у вас агент по умолчанию. Чтобы сделать вашу локальную модель тем, что открывают горячая клавиша агента, консоль Quake и _Make something_, запустите `omarchy default agent local` или отметьте звёздочкой работающую модель на панели агентов. pi также перечисляет каждую модель, которую вы настроили, и те, что находятся на машинах, с которыми вы выполнили сопряжение, в своём собственном средстве выбора модели, поэтому обычный `pi` также до них добирается. Любой клиент, совместимый с OpenAI, тоже может подключиться: `status` показывает адрес каждой модели (первый — `http://127.0.0.1:11435/v1`), имя рецепта — это модель, а ключ находится в `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` удаляет модель и загрузки, которые не использует ни одна другая модель.

Сторонние среды выполнения помечены их издателем. Omarchy запускает каждую модель без доступа к сети.

### Локальные LLM

Omarchy рекомендует два способа запуска локальных моделей LLM: LM Studio и Ollama. LM Studio предоставляет GUI-интерфейс для поиска моделей с открытыми весами, их установки и запуска. Это отличный способ легко начать. Ollama предлагает CLI для того же самого аналогичным образом. Но если вы новичок в локальных моделях, я бы начал с LM Studio. Вы можете установить любое из них в разделе _Install > AI_ в меню Omarchy.

### Скиллы Omarchy

Скиллы агентов помогают ИИ использовать конкретные инструменты конкретным способом, и Omarchy поставляет семь из них. Скилл omarchy охватывает настройку системы под себя, например настройку вашей конфигурации Hyprland или регулировку панели. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app и omarchy-make-game охватывают создание чего-то нового, omarchy-contribute охватывает сообщение об ошибке или отправку исправления в upstream, а omarchy-diagnose-crash работает с дампом ядра сбоя. Они связаны символическими ссылками в каталоги скиллов для Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` и каждый `~/.hermes/profiles/*/skills`) и общее расположение `~/.agents/skills`, поэтому большинство harness подхватывают их автоматически. Ваша собственная папка скилла с тем же именем имеет приоритет.

Но вы должны относиться к этим скиллам как к экспериментальным. Разные модели будут использовать их с разным эффектом. Лучше сначала запускать в режиме планирования, чтобы у вас было представление о том, что агент хотел бы изменить. А затем будьте готовы откатить изменения или даже выполнить `omarchy reinstall configs`, если агент устроит во всём полный бардак.
