# ИИ

Omarchy включает средства запуска для перечисленных ниже агентов для написания кода, не выбирая за вас агента по умолчанию. Запустите команду, чтобы установить её CLI при первом использовании, затем выполните аутентификацию по запросу. Hermes — исключение: при первом использовании для него ничего не устанавливается, а его выбор устанавливает Hermes Desktop, как объясняется ниже в разделе _Приложения для рабочего стола_.

### Установка и обновление агентов

За исключением Hermes, эти агенты используют ленивую установку через mise: первый запуск устанавливает CLI, а последующие запуски используют его повторно. mise также проверяет установленный агент на наличие нового выпуска не чаще одного раза в четыре часа, непосредственно перед его запуском или в фоне в приглашении оболочки. Если это обновление не удаётся или вы не в сети, запускается установленная версия. `omarchy update` обновляет установленные агенты вместе с остальной частью Omarchy, а `mup` обновляет только инструменты, управляемые mise.

Собственное средство обновления агента, такое как `claude update`, `codex update` или кнопка обновления в приложении, не обновляет установку, управляемую mise. `codex update` завершается с ошибкой, а `claude update` может сообщить об успехе, установив при этом отдельную копию, которую mise не отслеживает. Если вы предпочитаете использовать собственный установщик и средство обновления агента, добавьте его в `disable_tools`; см. [Предустановленные инструменты CLI](18-development-tools.md#preinstalled-cli-tools).

Чтобы установить все настроенные ленивые инструменты до того, как они вам понадобятся, запустите `mise install --include-lazy`. Это включает другие инструменты CLI Omarchy по умолчанию, а также агентов. См. [Предустановленные инструменты CLI](18-development-tools.md#preinstalled-cli-tools) для установки одного инструмента или использования собственной установки.

`grok` устанавливается через собственный пакет `grok` от mise, так же как `claude` и `codex`. Запустите `grok` или выберите его в _Setup > Defaults > Agent_. Пропустите установщик `curl | bash` на x.ai. Этот путь помещает вторую копию в `~/.grok/bin`, добавляет её в начало `PATH` и перезаписывает обёртку Omarchy.

`dsh` открывает свой интерфейс в браузере на `127.0.0.1:3080`, используя каталог запуска в качестве рабочего пространства по умолчанию. Его интерфейс в браузере не принимает начальный запрос, поэтому `omarchy agent prompt` открывает его с запросом в буфере обмена для вставки. Omarchy запускает его с предустановкой разрешений DeepSeek без подтверждения. DeepSeek Harness загружает журналы сеансов в DeepSeek, когда вы используете его официальный API моделей; отключите это в _Settings > General > Upload Session Log_ в его интерфейсе в браузере. Отзывы, которые вы ему отправляете, также загружаются вместе с сеансом, если только вы не запустите его с `DSH_TELEMETRY_MODE=DISABLED`.

### Агент по умолчанию

Выберите агента по умолчанию с помощью `omarchy default agent <name>` или в _Setup > Defaults > Agent_ в Omarchy Menu (`Super + Space`). Если агент ещё не установлен, его выбор сначала установит его. Свежая установка Omarchy предложит вам сделать этот выбор с помощью однократного уведомления.

Выбор Claude также пытается настроить его расширение для браузера для Chromium, Chrome, Brave, Brave Origin и Edge. Настройка расширения применяется ко всем пользователям и может запросить ваш системный пароль; отмена или неудачная установка расширения по-прежнему выбирает и запускает Claude. Перезапустите браузер, включите расширение при появлении запроса и войдите в Claude, чтобы завершить его подключение. Запустите `/chrome` в Claude, чтобы проверить подключение. Firefox и Zen не поддерживают это расширение. Если Claude уже был вашим агентом по умолчанию до того, как была добавлена эта настройка, выберите его снова, чтобы установить расширение.

После того как вы сделаете выбор, `Super + Shift + Ctrl + A` запускает агента по умолчанию в отдельном окне терминала (или открывает средство выбора, если вы ещё не выбрали). Вы также можете запустить его сразу с задачей с помощью `omarchy agent prompt "Review this project"`. Freebuff и DeepSeek Harness не принимают начальный запрос, поэтому вместо этого они открываются с запросом в буфере обмена для вставки. Агенты, запущенные таким образом, работают без присмотра в своих соответствующих режимах «не останавливайся, чтобы спросить», так что будьте готовы к тому, что они действительно будут делать вещи! У MiniMax Code нет такого режима для его интерактивных сеансов, поэтому он запрашивает разрешения как обычно. А поскольку агенты отказываются запоминать доверие для вашего домашнего каталога, запуски из `$HOME` вместо этого начинаются в `~/Work`.

Есть и сокращения для терминала: `a` запускает агента по умолчанию прямо в текущем терминале, а `c`, `cx` и `cy` запускают OpenCode, Claude Code и Codex напрямую (опять же в их режимах с автоматическим подтверждением). Смены темы также синхронизируются с агентами: Claude Code, Pi, OpenCode и Hermes (после того как Omarchy его установит) следуют за вами, когда вы переключаете тему Omarchy.

### Панель агентов

На верхней панели есть значок агентов. До того как вы настроите агента, его панель проведёт вас через вход в Claude, Codex или Grok, и первый из них станет вашим агентом по умолчанию. После этого панель размещает каждую подписку на одной странице: каждого агента и учётную запись с её планом, индикатор для каждого из её лимитов 5-часового сеанса и недельных лимитов со временем до его сброса (наведите указатель для точного процента) или оставшийся предоплаченный баланс, под строкой, которая циклически показывает, что вы использовали по всем ним, например токены за эту неделю и вашу наиболее используемую модель. В разделе _Make something_ она предлагает начальные запросы для новой темы, плагина или приложения, которые передают задачу вашему агенту по умолчанию. Приложения создаются так же, как собственные Hype, Monologue и Omacut от Omarchy, на C++ и Qt Quick, следуя навыку агента omarchy-app, а нужные им компилятор и компоненты Qt поставляются установленными. Claude Code, Codex, Grok, Kimi, Cursor и его лимит Grok Bot, GitHub Copilot, Muse, Antigravity, Kimchi и Devin покрываются из коробки с их лимитами, а Hermes, Mistral Vibe и Qwen Code показывают свои сеансы и токены после того, как вы ими воспользуетесь. Планы провайдеров и ключи, которые вы используете через pi, omp или opencode, также появляются: OpenCode Zen и Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan и Synthetic с их лимитами; Fireworks, OpenRouter и DeepSeek с их предоплаченными балансами; и модели, которые вы запускаете на собственном оборудовании, в разделе Local models. Каждый агент учитывается один раз, у того, кто выставляет за него счёт, независимо от того, через сколько оболочек вы им управляете.

Щелчок левой кнопкой по значку на панели открывает панель, щелчок правой кнопкой запускает вашего агента по умолчанию. Записи об использовании, лежащие в её основе, перегенерируются каждые 15 минут с помощью `omarchy agent usage-update`, а панель может даже объединять использование с ваших других машин через синхронизируемую папку. См. README в `$OMARCHY_PATH/shell/plugins/agents/` для полных настроек.

### Несколько подписок

Если вы платите за более чем один план Claude, Codex или Grok — например, личный Max и рабочий — Omarchy может держать их все вошедшими и перемещаться между ними. Добавьте подписку с помощью + на панели агентов, которая проведёт вас через это прямо там, или с помощью `omarchy agent account add claude Work` (или `codex`, или `grok`). Она устанавливает CLI, если он отсутствует. Первая учётная запись для провайдера входит через ваш обычный браузер, прямо там, где CLI всегда ищет. Каждая следующая после этого входит через приватное окно, чтобы учётная запись, в которую ваш браузер уже вошёл, не была подхвачена по ошибке; войдите там как учётная запись, которую вы добавляете, и сначала закройте любое уже открытое приватное окно. Никогда не выходите из CLI для этого: выход отзывает сохранённый вход, и эту учётную запись придётся добавлять снова.

Чтобы скопировать входы ваших подписок на другую машину Omarchy через SSH, запустите `omarchy agent account copy user@laptop`. Отправитель предоставляет временного получателя, когда на месте назначения он не установлен, поэтому более старые машины Omarchy могут получать учётные записи без обновления. Установленные получатели имеют приоритет. Это копирует все подписки Claude, Codex и Grok; добавьте имена провайдеров, чтобы выбрать их, как в `omarchy agent account copy laptop claude`. Имена учётных записей и ID команд соответствуют источнику, включая учётные записи, уже присутствующие на месте назначения. Несвязанные учётные записи на месте назначения получают числовой суффикс, если их имена конфликтуют, а настройки, навыки, плагины и история разговоров остаются локальными для каждой машины.

Существующие учётные данные на месте назначения сохраняются. Исходная учётная запись, уже вошедшая там, синхронизирует своё имя без замены её учётных данных; другие учётные записи добавляются рядом с ней. Чтобы заменить сохранённые учётные данные для совпадающих учётных записей, используйте `omarchy agent account copy --replace laptop claude` после выхода из сеансов этой учётной записи на месте назначения. Свежее место назначения также получает активную учётную запись источника и предпочтения переключения; устоявшееся место назначения сохраняет свои собственные.

Учётные данные перемещаются через SSH и хранятся в приватных файлах на месте назначения, поэтому копируйте только на машины, которым вы доверяете. Это однократное копирование, а не постоянная синхронизация. Токены обновления Codex могут быть ротированы другой машиной, из-за чего скопированный вход будет нуждаться в обновлении; отдельные входы остаются самым надёжным выбором для одновременного использования на нескольких машинах. См. [руководство Codex по аутентификации учётных записей](https://developers.openai.com/codex/auth/ci-cd-auth).

Одна учётная запись на провайдера активна, и каждый новый сеанс начинается как она: `cx`, `cy`, обычный `claude`, `codex` или `grok`, всё, что запускается через `omarchy agent`, и скрипты или редакторы, которые находят CLI в `PATH`. Переключайтесь с помощью `omarchy agent account use work` (и обратно с помощью `omarchy agent account use main`) или на панели, нажав номер учётной записи, а затем `Enter` (или щёлкнув её кнопку Use). Сеансы, которые уже запущены, остаются на учётной записи, с которой они начали. История разговоров, настройки, навыки и плагины являются общими для учётных записей, поэтому `claude --continue` в той же папке продолжит с того места, где вы остановились на новой учётной записи.

При наличии более одной учётной записи панель показывает лимиты каждой учётной записи рядом друг с другом, с отмеченной активной. По умолчанию Omarchy уведомляет вас, когда активная учётная запись превышает 95% лимита, и щелчок по уведомлению переключает на учётную запись с наибольшим запасом. Наведите указатель на строку учётной записи на панели и щёлкните Autoswitch, который появляется рядом с Use (или нажмите `m`), или запустите `omarchy agent account mode auto`, чтобы она переключалась сама; пока это включено, Autoswitch занимает место Use, а повторный щелчок по нему возвращает к уведомлениям. Добавьте число, чтобы изменить порог, как в `omarchy agent account mode auto 90`. Если каждая учётная запись превышает порог, вы услышите об этом один раз, а также о том, какая учётная запись освободится первой. Пока активная учётная запись находится в пределах 15 пунктов от своего порога (80% по умолчанию), её лимиты проверяются каждые три минуты, а не каждые 15.

`omarchy agent account list` показывает каждую учётную запись и её последние лимиты, `omarchy agent account remove work` забывает одну, а `omarchy agent account rename primary Hey` переименовывает одну (или щёлкните имя учётной записи на панели). Эти команды работают с учётными записями вашего агента по умолчанию; чтобы обратиться к другому провайдеру, сначала назовите его, как в `omarchy agent account use codex side`. Вход, который у вас уже был в `~/.claude` или `~/.codex`, является учётной записью _Main_ и остаётся там, где он есть. Учётная запись, оставленная без использования более чем примерно на восемь часов, может показать _Sign-in required_; щёлкните её, чтобы снова войти в эту учётную запись прямо на панели, или начните сеанс в ней, что само по себе обновит вход. Серверы MCP, которые у вас были, когда учётная запись была добавлена, приходят вместе с ней, но те, которые вы добавляете позже с помощью `claude mcp add`, достигают только той учётной записи, в которую вы их добавили. Claude Desktop и инструменты, настроенные с абсолютным путём к бинарному файлу CLI, не следуют за переключением. Явный `CLAUDE_CONFIG_DIR`, `CODEX_HOME` или `GROK_HOME` имеет приоритет над выбранной учётной записью.

### Диагностика сбоев

Omarchy следит за systemd-coredump на предмет сбоев процессов. Когда что-то завершается с ошибкой сегментации, вы получите уведомление "Process crashed" — щёлкните его, и сбой будет передан вашему агенту по умолчанию вместе с навыком diagnose-crash от Omarchy, который проводит агента через установление фактов из дампа ядра и решение, стоит ли сообщать о сбое в вышестоящий проект. Вы также можете запустить его вручную для любого PID из `coredumpctl list` с помощью `omarchy agent crash <pid>`.

Наблюдение включено по умолчанию. Отключите его в _Trigger > Toggle > Crash Capture_ (или с помощью `omarchy toggle crash-capture`), и уведомления прекратятся; `omarchy agent crash <pid>` по-прежнему работает вручную.

Сбои также можно заглушать по одной программе за раз, что диагностика и предлагает вам в конце. `omarchy crash mute hyprland` останавливает уведомления только для этой программы, `omarchy crash mute hyprland off` возвращает их, а `omarchy crash mute` сам по себе перечисляет то, что вы заглушили. Он с таким же удовольствием принимает путь бинарного файла, как и его имя, поэтому `omarchy crash mute /usr/bin/hyprland` делает то же самое. Заключите имя с пробелом в кавычки, как в `omarchy crash mute 'Some App'`. Всё остальное по-прежнему уведомляет, а заглушённая программа по-прежнему завершается с ошибкой — это скрывает напоминание, оно ничего не исправляет.

### Приложения для рабочего стола

Меню _Install > AI_ также содержит несколько графических приложений ИИ: настольное приложение ChatGPT, настольное приложение Claude (бета-версия Anthropic для Linux, с вкладками Chat, Cowork и Claude Code), Grok Bot для общения с моделями xAI, Hermes Desktop, OpenClaw, настольное приложение Perplexity и T3 Code. Grok Bot — это настольное приложение для чата. Агент для написания кода — это команда `grok`.

Hermes Desktop — это то, о чём нужно знать, потому что на машине есть один Hermes, и он принадлежит приложению: Hermes устанавливается только через приложение, а команда `hermes`, которую запускает агент по умолчанию, принадлежит приложению. Выбор Hermes в качестве агента по умолчанию устанавливает то же самое, что и пункт _Install > AI_: пакет и среду выполнения Hermes в `~/.hermes`, настроенную собственным установщиком Hermes, что занимает несколько минут при первом запуске. Эта среда выполнения — тот единственный Hermes, который используют команда `hermes` в терминале, агент по умолчанию и приложение, и она обновляется сама с помощью `hermes update`, а не ждёт выпуска Omarchy. Её установка также передаёт Hermes тему Omarchy в качестве оформления с именем `omarchy`, которому следует каждая поверхность Hermes при переключении тем; выберите другое в настройках Appearance в Hermes или с помощью `/skin`, если вы предпочитаете, чтобы этого не было, и Omarchy оставит этот выбор в покое. Удаление приложения в _Remove > AI_ сначала закрывает Hermes, включая шлюз, забирает эту среду выполнения с собой и сохраняет ваши чаты, воспоминания и навыки, которые Hermes написал для себя, если только вы не скажете иначе: оно спрашивает, по умолчанию отвечая нет, должны ли эти данные и ваши настройки подключения также уйти.

Настольный опыт OpenClaw — это его Control UI, который открывается как веб-приложение, поддерживаемое его собственным локальным шлюзом. OpenClaw живёт в `~/.openclaw` и обновляется сам: используйте кнопку "Update Gateway" в Control UI или запустите `openclaw update`, и шлюз перезапустится на новой версии. Omarchy только выбирает выпуск, с которого начинается свежая установка. Удаление OpenClaw в _Remove > AI_ забирает службу шлюза и приложение с собой, а затем спрашивает, должен ли `~/.openclaw` также уйти, поскольку там хранятся ваши чаты и учётные данные наряду с самим OpenClaw и средами выполнения плагинов, которые он загружает; по умолчанию он сохраняется, и повторная установка OpenClaw подхватит его обратно.

T3 Code запускается из своего официального выпуска AppImage в `~/.local/share/t3code`, а не из пакета, поэтому он обновляется сам. Его установка спрашивает, начинать ли на канале Stable или Nightly; переключите позже в настройках T3 Code. Ваши потоки и настройки живут в `~/.t3`, а удаление T3 Code в _Remove > AI_ забирает их с собой.

### Локальные модели

Запустите открытую модель на своей собственной машине для ваших агентов для написания кода. Ваши запросы и код остаются на машине; ничто из отправленного модели не покидает её. Начните с:

```bash
omarchy agent local use best
```

Или на панели агентов в верхней панели выберите + и затем Local AI, что появляется, когда модель подходит этой машине. В первый раз это устанавливает Podman, который запускает модели. Затем Omarchy выбирает рекомендуемую модель для этой машины, загружает её и запускает. Ожидайте загрузки в десятки GB и использования большей части памяти машины, пока модель работает: Flash Next использует около 100 GiB с его полным контекстом 256K. Если другие модели удерживают нужную ей память, она настраивается остановленной, готовой к запуску, как только вы остановите одну. Модель останавливается при выходе из системы; останавливайте её сами, когда вам нужна память для чего-то другого.

`omarchy agent local list` показывает варианты и объясняет, почему некоторые не подходят. Чтобы настроить другую, запустите `omarchy agent local use <recipe>`. Сегодня `qwen3.8-flash-next-halogen` и `qwen3.8-27b-gufo` доступны для машин Strix Halo с 128 GB. Новые рецепты и рекомендации приходят с `omarchy update`, через пакет.

Каждая настроенная вами модель получает свою собственную строку на панели агентов, рядом с вашими подписками: воспроизведение, чтобы запустить её, пауза, чтобы остановить её и освободить её память, и кнопка терминала, чтобы открыть вашего агента на ней. Несколько могут работать одновременно, когда они помещаются в памяти вместе; если одна не помещается, Omarchy говорит, какую запущенную модель остановить. Перетаскивайте строки, чтобы изменить их порядок, и нажимайте Delete на выбранной строке, чтобы удалить модель и её загрузку.

Из командной строки `omarchy agent local start <recipe>` и `omarchy agent local stop <recipe>` делают то же самое, `omarchy agent local status` показывает каждую модель, а `omarchy agent --local` открывает вашего агента по умолчанию на последней запущенной вами модели (pi, если ваш агент по умолчанию не может использовать локальную модель). Любой клиент, совместимый с OpenAI, также может подключиться: `status` показывает адрес каждой модели (первый — `http://127.0.0.1:11435/v1`), имя рецепта является моделью, а ключ находится в `~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` удаляет модель и загрузки, которые не использует ни одна другая модель.

Сторонние среды выполнения помечены их издателем. Omarchy запускает каждую модель без доступа к сети.

### Локальные LLM

Omarchy рекомендует два способа запуска локальных моделей LLM: LM Studio и Ollama. LM Studio предоставляет графический интерфейс для поиска моделей с открытыми весами, их установки и запуска. Это отличный способ легко начать. Ollama предлагает CLI для подобного. Но если вы новичок в локальных моделях, я бы начал с LM Studio. Вы можете установить любой из них в _Install > AI_ в Omarchy Menu.

### Навык Omarchy

Навыки агентов помогают ИИ использовать конкретные инструменты конкретным образом, и Omarchy поставляется с навыком по умолчанию для настройки системы. Как настройка вашей конфигурации Hyprland, настройка панели или даже создание новой темы с нуля. Он создаётся символьной ссылкой в каталогах навыков для Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` и каждого `~/.hermes/profiles/*/skills`) и общего расположения `~/.agents/skills`, поэтому большинство оболочек подхватывают его автоматически.

Но вы должны относиться к этому навыку как к экспериментальному. Разные модели будут использовать его с разным эффектом. Лучше сначала запускать в режиме планирования, чтобы у вас было представление о том, что агент хотел бы изменить. А затем будьте готовы откатить изменения или даже вызвать `omarchy reinstall configs`, если агент устроит беспорядок во всём.
