# AI

Omarchy включает средства запуска для перечисленных ниже агентов для программирования, не выбирая за вас вариант по умолчанию. Запустите команду, чтобы при первом использовании установить её CLI, а затем при появлении запроса пройдите аутентификацию. Hermes — исключение: при первом использовании для него ничего не устанавливается, и его выбор устанавливает Hermes Desktop, как объясняется ниже в разделе _Настольные приложения_.

### Установка и обновление агентов

За исключением Hermes, эти агенты используют ленивую установку mise: первый запуск устанавливает CLI, а последующие запуски используют его повторно. mise также проверяет установленный агент на наличие нового выпуска не чаще одного раза в четыре часа, непосредственно перед его запуском или в фоне в приглашении оболочки. Если это обновление не удастся или вы офлайн, запустится установленная версия. `omarchy update` обновляет установленные агенты вместе с остальной частью Omarchy, а `mup` обновляет только инструменты, управляемые mise.

Собственное средство обновления агента, такое как `claude update`, `codex update` или кнопка обновления в приложении, не обновляет установку, управляемую mise. `codex update` завершается с ошибкой, а `claude update` может сообщить об успехе, установив при этом отдельную копию, которую mise не отслеживает. Если вы предпочитаете использовать собственный установщик и средство обновления агента, добавьте его в `disable_tools`; см. [Предустановленные инструменты CLI](18-development-tools.md#preinstalled-cli-tools).

Чтобы установить все настроенные ленивые инструменты до того, как они вам понадобятся, запустите `mise install --include-lazy`. Сюда входят другие инструменты CLI Omarchy по умолчанию, а также агенты. См. [Предустановленные инструменты CLI](18-development-tools.md#preinstalled-cli-tools) об установке одного инструмента или использовании собственной установки.

`grok` устанавливается через фирменный пакет mise `grok`, так же как `claude` и `codex`. Запустите `grok` или выберите его в _Настройка > Значения по умолчанию > Агент_. Пропустите установщик `curl | bash` на x.ai. Этот путь помещает вторую копию в `~/.grok/bin`, ставит её в начало `PATH` и перезаписывает обёртку Omarchy.

`dsh` открывает свой интерфейс в браузере на `127.0.0.1:3080`, с каталогом запуска в качестве рабочего пространства по умолчанию. Его интерфейс в браузере не принимает начальный запрос, поэтому `omarchy agent prompt` открывает его с запросом в вашем буфере обмена, чтобы вы могли его вставить. Omarchy запускает его с предустановкой разрешений DeepSeek без подтверждений. DeepSeek Harness загружает журналы сессий в DeepSeek, когда вы используете его официальный API моделей; отключите это в его интерфейсе в браузере в _Settings > General > Upload Session Log_. Отправляемая вами обратная связь также загружается вместе с сессией, если только вы не запустите его с `DSH_TELEMETRY_MODE=DISABLED`.

### Агент по умолчанию

Выберите агента по умолчанию с помощью `omarchy default agent <name>` или в _Настройка > Значения по умолчанию > Агент_ в меню Omarchy (`Super + Space`). Если агент ещё не установлен, при выборе он сначала установится. Свежая Omarchy предложит вам сделать этот выбор однократным уведомлением.

Выбор Claude также пытается настроить его расширение для браузера для Chromium, Chrome, Brave, Brave Origin и Edge. Настройка расширения применяется ко всем пользователям и может запросить ваш системный пароль; отмена или неудачная установка расширения всё равно выбирает и запускает Claude. Перезапустите браузер, включите расширение при появлении запроса и войдите в Claude, чтобы завершить его подключение. Запустите `/chrome` в Claude, чтобы проверить соединение. Firefox и Zen не поддерживают это расширение. Если Claude уже был вашим вариантом по умолчанию до добавления этой настройки, выберите его снова, чтобы установить расширение.

После выбора `Super + Shift + Ctrl + A` запускает агента по умолчанию в отдельном окне терминала (или вызывает средство выбора, если вы ещё не выбрали). Вы также можете запустить его сразу с задачей с помощью `omarchy agent prompt "Review this project"`. Freebuff и DeepSeek Harness не принимают начальный запрос, поэтому вместо этого они открываются с запросом в вашем буфере обмена для вставки. Запущенные таким образом агенты работают без присмотра в своих соответствующих режимах «не останавливайся, чтобы спросить», поэтому будьте готовы к тому, что они действительно будут что-то делать! У MiniMax Code нет такого режима для его интерактивных сессий, поэтому он запрашивает разрешения как обычно. А поскольку агенты отказываются запоминать доверие для вашего домашнего каталога, запуски из `$HOME` вместо этого начинаются в `~/Work`.

Есть и ярлыки терминала: `a` запускает агента по умолчанию прямо в текущем терминале, а `c`, `cx` и `cy` запускают OpenCode, Claude Code и Codex напрямую (опять же в их режимах с автоматическим одобрением). Смена темы также синхронизируется с агентами: Claude Code, Pi, OpenCode и Hermes (после того как Omarchy его установила) следуют за вами при переключении темы Omarchy.

### Панель агентов

На верхней панели есть значок агентов. До того как вы настроите агента, его панель проведёт вас через вход в Claude, Codex или Grok, и первый из них станет вашим агентом по умолчанию. После этого панель собирает каждую подписку на одной странице: каждый агент и аккаунт с его планом, счётчик для каждого из его 5-часового лимита сессии и недельных лимитов со временем до сброса (наведите курсор для точного процента) или оставшийся предоплаченный баланс, под строкой, которая по очереди показывает, что вы использовали по всем ним, например токены за эту неделю и вашу наиболее используемую модель. В разделе _Сделать что-нибудь_ она предлагает стартовые запросы для новой темы, плагина или приложения, которые передают задачу вашему агенту по умолчанию. Приложения создаются так же, как собственные Hype, Monologue и Omacut от Omarchy, на C++ и Qt Quick, следуя навыку агента omarchy-app, а компилятор и нужные им компоненты Qt поставляются установленными. Claude Code, Codex, Grok, Kimi, Cursor и его лимит Grok Bot, GitHub Copilot, Muse, Antigravity, Kimchi и Devin поддерживаются из коробки со своими лимитами, а Hermes, Mistral Vibe и Qwen Code показывают свои сессии и токены после того, как вы ими воспользуетесь. Планы провайдеров и ключи, которые вы используете через pi, omp или opencode, также отображаются: OpenCode Zen и Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan и Synthetic со своими лимитами; Fireworks, OpenRouter и DeepSeek с их предоплаченными балансами; и модели, которые вы запускаете на собственном оборудовании, в разделе Local models. Каждый агент учитывается один раз, по тому, кто выставляет за него счёт, независимо от того, через сколько harness-ов вы им управляете.

Щёлкните левой кнопкой мыши по значку на панели для панели, щёлкните правой кнопкой, чтобы запустить агента по умолчанию. Записи об использовании, лежащие в её основе, перегенерируются каждые 15 минут командой `omarchy agent usage-update`, а панель может даже объединять использование с ваших других машин через синхронизируемую папку. Полные настройки см. в README в `$OMARCHY_PATH/shell/plugins/agents/`.

### Несколько подписок

Если вы платите более чем за один план Claude, Codex или Grok — например, личный Max и рабочий, — Omarchy может держать их все вошедшими и перемещаться между ними. Добавьте подписку с помощью + на панели агентов, которая проведёт вас через это прямо там, или с помощью `omarchy agent account add claude Work` (или `codex`, или `grok`). Она устанавливает CLI, если он отсутствует. Первый аккаунт для провайдера входит через ваш обычный браузер, именно там, где CLI всегда ищет. Каждый последующий входит через приватное окно, чтобы аккаунт, в который ваш браузер уже вошёл, не подхватился по ошибке; войдите там как аккаунт, который вы добавляете, и сначала закройте любое приватное окно, которое у вас уже открыто. Никогда не выходите из CLI для этого: выход отзывает сохранённый вход, и этот аккаунт придётся добавлять снова.

Чтобы скопировать входы по подпискам на другую машину с Omarchy по SSH, запустите `omarchy agent account copy user@laptop`. Отправитель предоставляет временного получателя, когда на месте назначения он не установлен, поэтому старые машины с Omarchy могут получать аккаунты без обновления. Установленные получатели имеют приоритет. Это копирует все подписки Claude, Codex и Grok; добавьте имена провайдеров, чтобы выбрать их, как в `omarchy agent account copy laptop claude`. Имена аккаунтов и ID команд совпадают с источником, включая аккаунты, уже присутствующие на месте назначения. Несвязанные аккаунты места назначения получают числовой суффикс при конфликте имён, а настройки, навыки, плагины и история разговоров остаются локальными для каждой машины.

Существующие учётные данные места назначения сохраняются. Аккаунт источника, уже вошедший там, синхронизирует своё имя без замены учётных данных; другие аккаунты добавляются рядом с ним. Чтобы заменить сохранённые учётные данные для совпадающих аккаунтов, используйте `omarchy agent account copy --replace laptop claude` после завершения сессий этого аккаунта на месте назначения. Свежее место назначения также получает активный аккаунт источника и предпочтения переключения; устоявшееся место назначения сохраняет свои собственные.

Учётные данные передаются через SSH и хранятся в приватных файлах на месте назначения, поэтому копируйте только на машины, которым доверяете. Это однократное копирование, а не постоянная синхронизация. Токены обновления Codex могут быть ротированы другой машиной, из-за чего скопированный вход будет нуждаться в обновлении; отдельные входы остаются самым надёжным выбором для одновременного использования на нескольких машинах. См. [руководство Codex по аутентификации аккаунтов](https://developers.openai.com/codex/auth/ci-cd-auth).

Для каждого провайдера активен один аккаунт, и каждая новая сессия начинается как он: `cx`, `cy`, обычные `claude`, `codex` или `grok`, всё, что запускается через `omarchy agent`, а также скрипты или редакторы, которые находят CLI в `PATH`. Переключайтесь с помощью `omarchy agent account use work` (и обратно с помощью `omarchy agent account use main`) или на панели, нажав номер аккаунта, а затем `Enter` (или щёлкнув по его кнопке Use). Уже запущенные сессии остаются на аккаунте, с которым они стартовали. История разговоров, настройки, навыки и плагины являются общими для аккаунтов, поэтому `claude --continue` в той же папке продолжит с того места, где вы остановились, на новом аккаунте.

При наличии более одного аккаунта панель показывает лимиты каждого аккаунта рядом, с отмеченным активным. По умолчанию Omarchy уведомляет вас, когда активный аккаунт превышает 95% лимита, и щелчок по уведомлению переключает на аккаунт с наибольшим запасом. Наведите курсор на строку аккаунта на панели и щёлкните Autoswitch, который появляется рядом с Use (или нажмите `m`), или запустите `omarchy agent account mode auto`, чтобы он переключался сам; пока это включено, Autoswitch занимает место Use, а повторный щелчок по нему возвращает к уведомлениям. Добавьте число, чтобы изменить порог, как в `omarchy agent account mode auto 90`. Если каждый аккаунт превышает порог, вы услышите об этом один раз, вместе с тем, какой аккаунт освободится первым. Пока активный аккаунт находится в пределах 15 пунктов от своего порога (80% по умолчанию), его лимиты проверяются каждые три минуты, а не каждые 15.

`omarchy agent account list` показывает каждый аккаунт и его последние лимиты, `omarchy agent account remove work` забывает один, а `omarchy agent account rename primary Hey` переименовывает один (или щёлкните по имени аккаунта на панели). Эти команды работают с аккаунтами вашего агента по умолчанию; чтобы обратиться к другому провайдеру, сначала назовите его, как в `omarchy agent account use codex side`. Вход, который у вас уже был в `~/.claude` или `~/.codex`, — это аккаунт _Main_, и он остаётся там, где он есть. Аккаунт, остававшийся без использования более примерно восьми часов, может показать _Sign-in required_; щёлкните по нему, чтобы снова войти в этот аккаунт прямо на панели, или начните в нём сессию, что само по себе обновляет вход. Серверы MCP, которые у вас были при добавлении аккаунта, переходят вместе с ним, но те, что вы добавите позже с помощью `claude mcp add`, попадут только в аккаунт, в который вы их добавили. Claude Desktop и инструменты, настроенные с абсолютным путём к бинарному файлу CLI, не следуют за переключением. Явный `CLAUDE_CONFIG_DIR`, `CODEX_HOME` или `GROK_HOME` имеет приоритет над выбранным аккаунтом.

### Диагностика сбоев

Omarchy следит за systemd-coredump на предмет сбоев процессов. Когда что-то сегфолтится, вы получите уведомление «Process crashed» — щёлкните по нему, и сбой будет передан вашему агенту по умолчанию вместе с навыком diagnose-crash от Omarchy, который проводит агента через установление фактов из дампа ядра и принятие решения, стоит ли сообщать о сбое вверх по цепочке. Вы также можете запустить его вручную по любому PID из `coredumpctl list` с помощью `omarchy agent crash <pid>`.

Отслеживание включено по умолчанию. Отключите его в _Trigger > Toggle > Crash Capture_ (или с помощью `omarchy toggle crash-capture`), и уведомления прекратятся; `omarchy agent crash <pid>` по-прежнему работает вручную.

Сбои также можно заглушить по одной программе за раз, что диагностика и предлагает вам в конце. `omarchy crash mute hyprland` прекращает уведомления только для этой программы, `omarchy crash mute hyprland off` возвращает их, а `omarchy crash mute` сам по себе перечисляет то, что вы заглушили. Он так же охотно принимает путь к бинарному файлу, как и его имя, поэтому `omarchy crash mute /usr/bin/hyprland` делает то же самое. Заключайте в кавычки имя с пробелом, как в `omarchy crash mute 'Some App'`. Всё остальное по-прежнему уведомляет, а заглушенная программа по-прежнему падает — это скрывает напоминание, а не чинит что-либо.

### Настольные приложения

Меню _Установить > AI_ также содержит несколько графических приложений AI: настольное приложение ChatGPT, настольное приложение Claude (бета-версия Anthropic для Linux, с вкладками Chat, Cowork и Claude Code), Grok Bot для общения с моделями xAI, Hermes Desktop, OpenClaw, настольное приложение Perplexity и T3 Code. Grok Bot — это настольное приложение чата. Агент для программирования — это команда `grok`.

Hermes Desktop — тот, о котором нужно знать, потому что на машине один Hermes, и он принадлежит приложению: Hermes устанавливается только через приложение, и команда `hermes`, которую запускает агент по умолчанию, принадлежит приложению. Выбор Hermes в качестве агента по умолчанию устанавливает то же самое, что и пункт _Установить > AI_: пакет и среду выполнения Hermes в `~/.hermes`, настроенную собственным установщиком Hermes, что в первый раз занимает несколько минут. Эта среда выполнения — тот единственный Hermes, который используют терминальная команда `hermes`, агент по умолчанию и приложение, и он обновляет себя с помощью `hermes update`, а не ждёт выпуска Omarchy. Его установка также передаёт Hermes тему Omarchy в качестве скина с именем `omarchy`, которому следует каждый интерфейс Hermes при переключении тем; выберите другой в настройках Appearance в Hermes или с помощью `/skin`, если вы предпочитаете, чтобы этого не было, и Omarchy оставит этот выбор в покое. Удаление приложения в _Удалить > AI_ сначала закрывает Hermes, включая шлюз, забирает эту среду выполнения с собой и сохраняет ваши чаты, воспоминания и навыки, которые Hermes написал для себя, если только вы не скажете иначе: оно спрашивает, по умолчанию нет, следует ли также удалить эти данные и ваши настройки подключения.

Настольный опыт OpenClaw — это его Control UI, который открывается как веб-приложение, поддерживаемое его собственным локальным шлюзом. OpenClaw живёт в `~/.openclaw` и обновляет себя: используйте кнопку «Update Gateway» в Control UI или запустите `openclaw update`, и шлюз перезапустится на новой версии. Omarchy выбирает только выпуск, с которого начинается свежая установка. Удаление OpenClaw в _Удалить > AI_ забирает с собой службу шлюза и приложение, а затем спрашивает, следует ли также удалить `~/.openclaw`, поскольку там хранятся ваши чаты и учётные данные наряду с самим OpenClaw и средами выполнения плагинов, которые он загружает; по умолчанию он сохраняется, и повторная установка OpenClaw подхватит его обратно.

T3 Code запускается из своего официального выпуска AppImage в `~/.local/share/t3code`, а не из пакета, поэтому он обновляет себя. Его установка спрашивает, начинать ли на канале Stable или Nightly; переключитесь позже в настройках T3 Code. Ваши потоки и настройки живут в `~/.t3`, и удаление T3 Code в _Удалить > AI_ забирает их с собой.

### Локальные LLM

Omarchy рекомендует два способа запуска локальных моделей LLM: LM Studio и Ollama. LM Studio предоставляет GUI-интерфейс для поиска моделей с открытыми весами, их установки и запуска. Это отличный способ легко начать. Ollama предлагает CLI для того же самого. Но если вы новичок в локальных моделях, я бы начал с LM Studio. Вы можете установить любой из них в _Установить > AI_ в меню Omarchy.

### Навык Omarchy

Навыки агентов помогают AI использовать конкретные инструменты конкретным способом, и Omarchy поставляется с навыком по умолчанию для настройки системы. Например, подкрутить вашу конфигурацию Hyprland, настроить панель или даже создать новую тему с нуля. Он создаётся символьной ссылкой в каталогах навыков для Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` и каждого `~/.hermes/profiles/*/skills`) и в общем расположении `~/.agents/skills`, поэтому большинство harness-ов подхватывают его автоматически.

Но вы должны относиться к этому навыку как к экспериментальному. Разные модели будут использовать его с разным эффектом. Лучше всего сначала запускать в режиме планирования, чтобы у вас было представление о том, что агент хотел бы изменить. А затем будьте готовы откатить изменения или даже вызвать `omarchy reinstall configs`, если агент устроит во всём беспорядок.
