# ИИ

Omarchy включает средства запуска для перечисленных ниже агентов для программирования, не выбирая за вас вариант по умолчанию. Выполните команду, чтобы при первом использовании установить её CLI, а затем при появлении запроса выполните аутентификацию. Hermes — исключение: при первом использовании для него ничего не устанавливается, а при его выборе устанавливается Hermes Desktop, как объясняется ниже в разделе _Приложения для рабочего стола_.

### Установка и обновление агентов

За исключением Hermes, эти агенты используют ленивую установку через mise: при первом запуске устанавливается CLI, а при последующих запусках он используется повторно. mise также проверяет установленный агент на наличие нового выпуска не чаще одного раза в четыре часа, непосредственно перед его запуском или в фоновом режиме при появлении приглашения оболочки. Если это обновление завершается неудачей или вы не в сети, запускается установленная версия. `omarchy update` обновляет установленные агенты вместе с остальной частью Omarchy, а `mup` обновляет только инструменты, управляемые mise.

Собственное средство обновления агента, такое как `claude update`, `codex update` или кнопка обновления в приложении, не обновляет установку, управляемую mise. `codex update` завершается неудачей, а `claude update` может сообщить об успехе, установив при этом отдельную копию, которую mise не отслеживает. Если вы предпочитаете использовать собственный установщик и средство обновления агента, добавьте его в `disable_tools`; см. [Предустановленные инструменты CLI](18-development-tools.md#preinstalled-cli-tools).

Чтобы установить все настроенные лениво устанавливаемые инструменты до того, как они вам понадобятся, выполните `mise install --include-lazy`. Сюда входят другие инструменты CLI Omarchy по умолчанию, а также агенты. Об установке одного инструмента или использовании собственной установки см. [Предустановленные инструменты CLI](18-development-tools.md#preinstalled-cli-tools).

`grok` устанавливается через фирменный пакет mise `grok`, так же как `claude` и `codex`. Выполните `grok` или выберите его в меню _Настройка > По умолчанию > Агент_. Пропустите установщик `curl | bash` на x.ai. Этот путь помещает вторую копию в `~/.grok/bin`, ставит её первой в `PATH` и перезаписывает оболочку запуска Omarchy.

`dsh` открывает свой интерфейс в браузере по адресу `127.0.0.1:3080`, используя каталог запуска в качестве рабочего пространства по умолчанию. Его интерфейс в браузере не принимает начальный запрос, поэтому `omarchy agent prompt` открывает его с запросом в вашем буфере обмена, чтобы вы могли его вставить. Omarchy запускает его с предустановкой разрешений DeepSeek без подтверждения. DeepSeek Harness загружает журналы сеансов в DeepSeek, когда вы используете его официальный API моделей; отключите это в его интерфейсе в браузере в разделе _Настройки > Общие > Загружать журнал сеанса_. Отправляемая вами обратная связь также загружается вместе с сеансом, если только вы не запустите его с `DSH_TELEMETRY_MODE=DISABLED`.

### Агент по умолчанию

Выберите агента по умолчанию с помощью `omarchy default agent <name>` или в меню _Настройка > По умолчанию > Агент_ в Omarchy Menu (`Super + Space`). Если агент ещё не установлен, при его выборе он сначала установится. Новая установка Omarchy предложит вам сделать этот выбор с помощью одноразового уведомления.

При выборе Claude также предпринимается попытка настроить его расширение для браузера для Chromium, Chrome, Brave, Brave Origin и Edge. Настройка расширения применяется ко всем пользователям и может запросить ваш системный пароль; отмена или неудачная установка расширения всё равно выбирает и запускает Claude. Перезапустите браузер, включите расширение, если появится запрос, и войдите в Claude, чтобы завершить его подключение. Выполните `/chrome` в Claude, чтобы проверить соединение. Firefox и Zen не поддерживают это расширение. Если Claude уже был вашим агентом по умолчанию до добавления этой настройки, выберите его снова, чтобы установить расширение.

После того как вы сделали выбор, `Super + Shift + Ctrl + A` запускает агента по умолчанию в отдельном окне терминала (или открывает средство выбора, если вы ещё не сделали выбор). Вы также можете запустить его сразу для выполнения задачи с помощью `omarchy agent prompt "Review this project"`. Freebuff и DeepSeek Harness не принимают начальный запрос, поэтому вместо этого они открываются с запросом в вашем буфере обмена, чтобы вы могли его вставить. Запущенные таким образом агенты работают без присмотра в своих соответствующих режимах «не останавливаться, чтобы спросить», поэтому будьте готовы к тому, что они действительно будут что-то делать! У MiniMax Code нет такого режима для его интерактивных сеансов, поэтому он запрашивает разрешения как обычно. А поскольку агенты отказываются запоминать доверие для вашего домашнего каталога, запуски из `$HOME` вместо этого начинаются в `~/Work`.

Есть и ярлыки в терминале: `a` запускает агента по умолчанию прямо в текущем терминале, а `c`, `cx` и `cy` запускают OpenCode, Claude Code и Codex напрямую (опять же в их режимах с автоматическим подтверждением). Смена темы также синхронизируется с агентами: Claude Code, Pi, OpenCode и Hermes (после того как Omarchy его установит) следуют за вами, когда вы переключаете тему Omarchy.

### Панель агентов

На верхней панели есть значок агентов. До того как вы настроите агента, его панель проведёт вас через вход в Claude, Codex или Grok, и первый из них станет вашим агентом по умолчанию. После этого панель размещает каждую подписку на одной странице: каждый агент и учётная запись с её планом, индикатор для каждого из её 5-часовых сеансовых и недельных лимитов со временем до его сброса (наведите курсор, чтобы увидеть точный процент) или остаток предоплаченного баланса, под строкой, которая по очереди показывает, что вы использовали по всем ним, например токены за эту неделю и вашу самую используемую модель. В разделе _Создать что-нибудь_ она предлагает начальные запросы для новой темы, плагина или приложения, которые передают задачу вашему агенту по умолчанию. Приложения создаются так же, как собственные Hype, Monologue и Omacut в Omarchy, на C++ и Qt Quick, с соблюдением навыка агента omarchy-app, а необходимый им компилятор и компоненты Qt поставляются установленными. Claude Code, Codex, Grok, Kimi, Cursor и его квота Grok Bot, GitHub Copilot, Muse, Antigravity, Kimchi и Devin поддерживаются из коробки с их лимитами, а Hermes, Mistral Vibe и Qwen Code показывают свои сеансы и токены после того, как вы ими воспользуетесь. Планы провайдеров и ключи, которые вы используете через pi, omp или opencode, также отображаются: OpenCode Zen и Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan и Synthetic с их лимитами; Fireworks, OpenRouter и DeepSeek с их предоплаченными балансами; и модели, которые вы запускаете на собственном оборудовании, в разделе «Локальные модели». Каждый агент учитывается один раз, по тому, кто выставляет за него счёт, сколько бы харнессов вы ни использовали для работы с ним.

Щёлкните левой кнопкой мыши по значку на панели, чтобы открыть панель, и правой кнопкой мыши, чтобы запустить агента по умолчанию. Лежащие в её основе записи об использовании перегенерируются каждые 15 минут с помощью `omarchy agent usage-update`, а панель может даже объединять данные об использовании с ваших других машин через синхронизируемую папку. Полные настройки см. в README в `$OMARCHY_PATH/shell/plugins/agents/`.

### Несколько подписок

Если вы платите за более чем один план Claude, Codex или Grok — например, личный Max и рабочий, — Omarchy может держать их все вошедшими в систему и перемещаться между ними. Добавьте подписку с помощью + на панели агентов, которая проведёт вас через это прямо там, или с помощью `omarchy agent account add claude Work` (или `codex`, или `grok`). Если CLI отсутствует, он установится. Первая учётная запись для провайдера входит через ваш обычный браузер, именно там, где CLI всегда её ищет. Каждая следующая после неё входит через приватное окно, чтобы учётная запись, в которую ваш браузер уже вошёл, не была подхвачена по ошибке; войдите там как учётная запись, которую вы добавляете, и сначала закройте любое приватное окно, которое у вас уже открыто. Никогда не выходите из CLI, чтобы сделать это: выход отзывает сохранённый вход, и эту учётную запись придётся добавлять снова.

Чтобы скопировать данные входа по подпискам на другую машину с Omarchy через SSH, выполните `omarchy agent account copy user@laptop`. Отправитель предоставляет временного получателя, когда на месте назначения он не установлен, поэтому старые машины с Omarchy могут получать учётные записи без обновления. Установленные получатели имеют приоритет. Это копирует все подписки Claude, Codex и Grok; добавьте названия провайдеров, чтобы выбрать их, как в `omarchy agent account copy laptop claude`. Названия учётных записей и идентификаторы команд соответствуют источнику, включая учётные записи, уже присутствующие на месте назначения. Несвязанные учётные записи на месте назначения получают числовой суффикс, если их названия конфликтуют, а настройки, навыки, плагины и история разговоров остаются локальными для каждой машины.

Существующие учётные данные на месте назначения сохраняются. У исходной учётной записи, уже вошедшей там, её название синхронизируется без замены её учётных данных; другие учётные записи добавляются рядом с ней. Чтобы заменить сохранённые учётные данные для совпадающих учётных записей, используйте `omarchy agent account copy --replace laptop claude` после завершения сеансов этой учётной записи на месте назначения. Новое место назначения также получает активную учётную запись источника и предпочтения переключения; устоявшееся место назначения сохраняет свои собственные.

Учётные данные передаются через SSH и хранятся в приватных файлах на месте назначения, поэтому копируйте только на машины, которым доверяете. Это одноразовое копирование, а не постоянная синхронизация. Токены обновления Codex могут быть ротированы другой машиной, из-за чего скопированный вход будет нуждаться в обновлении; отдельные входы остаются самым надёжным выбором для одновременного использования на нескольких машинах. См. [руководство Codex по аутентификации учётных записей](https://developers.openai.com/codex/auth/ci-cd-auth).

Одна учётная запись на провайдера активна, и каждый новый сеанс начинается как она: `cx`, `cy`, обычный `claude`, `codex` или `grok`, всё, что запускается через `omarchy agent`, а также скрипты или редакторы, которые находят CLI в `PATH`. Переключайтесь с помощью `omarchy agent account use work` (и обратно с помощью `omarchy agent account use main`) или на панели, нажав номер учётной записи, а затем `Enter` (или щёлкнув её кнопку «Использовать»). Уже запущенные сеансы остаются на той учётной записи, с которой они начали работу. История разговоров, настройки, навыки и плагины являются общими для всех учётных записей, поэтому `claude --continue` в той же папке продолжит с того места, где вы остановились, на новой учётной записи.

При наличии более чем одной учётной записи панель показывает лимиты каждой учётной записи рядом, с отмеченной активной. По умолчанию Omarchy уведомляет вас, когда активная учётная запись превышает 95% лимита, и щелчок по уведомлению переключает на учётную запись с наибольшим запасом. Наведите курсор на строку учётной записи на панели и щёлкните «Автопереключение», которое появляется рядом с «Использовать» (или нажмите `m`), или выполните `omarchy agent account mode auto`, чтобы переключение происходило само по себе; пока этот режим включён, «Автопереключение» занимает место «Использовать», а повторный щелчок по нему возвращает к уведомлениям. Добавьте число, чтобы изменить порог, как в `omarchy agent account mode auto 90`. Если каждая учётная запись превышает порог, вы услышите об этом один раз, вместе с тем, какая учётная запись освободится первой. Пока активная учётная запись находится в пределах 15 пунктов от своего порога (80% при значении по умолчанию), её лимиты проверяются каждые три минуты, а не каждые 15.

`omarchy agent account list` показывает каждую учётную запись и её последние лимиты, `omarchy agent account remove work` забывает одну, а `omarchy agent account rename primary Hey` переименовывает одну (или щёлкните название учётной записи на панели). Эти команды работают с учётными записями вашего агента по умолчанию; чтобы обратиться к другому провайдеру, сначала назовите его, как в `omarchy agent account use codex side`. Вход, который у вас уже был в `~/.claude` или `~/.codex`, является учётной записью _Main_ и остаётся там, где он есть. Учётная запись, не использовавшаяся более примерно восьми часов, может показывать _Требуется вход_; щёлкните её, чтобы снова войти в эту учётную запись прямо на панели, или начните сеанс в ней, что само по себе обновит вход. Серверы MCP, которые у вас были при добавлении учётной записи, переходят вместе с ней, но те, которые вы добавите позже с помощью `claude mcp add`, попадут только в ту учётную запись, в которой вы их добавили. Claude Desktop и инструменты, настроенные с абсолютным путём к бинарному файлу CLI, не следуют за переключением. Явно заданные `CLAUDE_CONFIG_DIR`, `CODEX_HOME` или `GROK_HOME` имеют приоритет над выбранной учётной записью.

### Диагностика сбоев

Omarchy следит за systemd-coredump на предмет сбоев процессов. Когда что-то вызывает segfault, вы получите уведомление «Процесс упал» — щёлкните его, и сбой будет передан вашему агенту по умолчанию вместе с навыком diagnose-crash в Omarchy, который проводит агента через установление фактов из дампа памяти и принятие решения о том, стоит ли сообщать о сбое разработчикам выше по цепочке. Вы также можете запустить его вручную для любого PID из `coredumpctl list` с помощью `omarchy agent crash <pid>`.

Отслеживание включено по умолчанию. Отключите его в разделе _Триггер > Переключить > Захват сбоев_ (или с помощью `omarchy toggle crash-capture`), и уведомления прекратятся; `omarchy agent crash <pid>` по-прежнему работает вручную.

Сбои также можно заглушить по одной программе за раз, что диагностика и предлагает вам в конце. `omarchy crash mute hyprland` останавливает уведомления только для этой программы, `omarchy crash mute hyprland off` возвращает их, а `omarchy crash mute` сам по себе перечисляет то, что вы заглушили. Он с одинаковой охотой принимает путь к бинарному файлу и его название, поэтому `omarchy crash mute /usr/bin/hyprland` делает то же самое. Заключите название с пробелом в кавычки, как в `omarchy crash mute 'Some App'`. Всё остальное по-прежнему уведомляет, а заглушенная программа по-прежнему падает — это скрывает напоминание, а не исправляет что-либо.

### Приложения для рабочего стола

Меню _Установка > ИИ_ также содержит несколько графических приложений ИИ: настольное приложение ChatGPT, настольное приложение Claude (бета-версия Anthropic для Linux с вкладками Chat, Cowork и Claude Code), Grok Bot для общения с моделями xAI, Hermes Desktop, OpenClaw, настольное приложение Perplexity и T3 Code. Grok Bot — это настольное приложение для чата. Агент для программирования — это команда `grok`.

Hermes Desktop — это то, о чём стоит знать, потому что на машине есть один Hermes, и он принадлежит приложению: Hermes устанавливается только через приложение, и команда `hermes`, которую запускает агент по умолчанию, принадлежит приложению. Выбор Hermes в качестве агента по умолчанию устанавливает то же самое, что и пункт _Установка > ИИ_: пакет и среду выполнения Hermes в `~/.hermes`, настроенную собственным установщиком Hermes, что в первый раз занимает несколько минут. Эта среда выполнения — это тот единственный Hermes, который используют команда `hermes` в терминале, агент по умолчанию и приложение, и она обновляется сама с помощью `hermes update`, а не ждёт выпуска Omarchy. При её установке Hermes также получает тему Omarchy в виде оформления с названием `omarchy`, которому следует каждая поверхность Hermes при переключении вами тем; выберите другое в настройках внешнего вида Hermes или с помощью `/skin`, если вы предпочитаете, чтобы этого не было, и Omarchy оставит этот выбор в покое. Удаление приложения в разделе _Удаление > ИИ_ сначала закрывает Hermes, включая шлюз, уносит с собой эту среду выполнения и сохраняет ваши чаты, воспоминания и навыки, которые Hermes написал для себя, если только вы не скажете иначе: оно спрашивает, по умолчанию отвечая «нет», должны ли эти данные и ваши настройки подключения также быть удалены.

Настольный опыт OpenClaw — это его Control UI, который открывается как веб-приложение, поддерживаемое его собственным локальным шлюзом. OpenClaw находится в `~/.openclaw` и обновляется сам: используйте кнопку «Обновить шлюз» в Control UI или выполните `openclaw update`, и шлюз перезапустится на новой версии. Omarchy выбирает только выпуск, с которого начинается новая установка. Удаление OpenClaw в разделе _Удаление > ИИ_ уносит с собой службу шлюза и приложение, а затем спрашивает, должна ли папка `~/.openclaw` также быть удалена, поскольку она хранит ваши чаты и учётные данные наряду с самим OpenClaw и средами выполнения плагинов, которые он загружает; по умолчанию она сохраняется, и повторная установка OpenClaw подхватит её обратно.

T3 Code работает из своего официального выпуска AppImage в `~/.local/share/t3code`, а не из пакета, поэтому он обновляется сам. При его установке спрашивается, начинать ли с канала Stable или Nightly; переключитесь позже в настройках T3 Code. Ваши ветки обсуждений и настройки находятся в `~/.t3`, и удаление T3 Code в разделе _Удаление > ИИ_ уносит их с собой.

### Локальные модели

Запускайте открытую модель на своей собственной машине для своих агентов для программирования. Ваши запросы и код остаются на машине; ничто из отправленного модели не покидает её. Начните с:

```bash
omarchy agent local use best
```

Или на панели агентов на верхней панели выберите + и затем Local AI, который появляется, когда модель подходит для этой машины. В первый раз это устанавливает Podman, который запускает модели, а на машине с NVIDIA — инструментарий контейнеров NVIDIA, который даёт им доступ к GPU. Затем Omarchy выбирает рекомендуемую модель для этой машины, загружает её и запускает. Ожидайте загрузки в десятки GB и использования большей части памяти машины во время работы модели: Flash Next использует около 100 GiB со своим полным контекстом 256K. Если другие модели удерживают необходимую ей память, она настраивается в остановленном состоянии, готовая к запуску, как только вы остановите одну из них. Модель останавливается при выходе из системы; останавливайте её сами, когда вам нужна память для чего-то другого.

`omarchy agent local list` показывает варианты и объясняет, почему некоторые не подходят. Чтобы настроить другую модель, выполните `omarchy agent local use <recipe>`. На сегодняшний день `qwen3.8-flash-next-gufo` и `qwen3.8-27b-gufo` доступны для машин Strix Halo со 128 GB; 27B занимает около 40 GiB, поэтому она оставляет место для другой работы. Новые рецепты и рекомендации поступают с `omarchy update`, через пакет.

Каждая настроенная вами модель получает свою собственную строку на панели агентов, рядом с вашими подписками: кнопка воспроизведения, чтобы запустить её, кнопка паузы, чтобы остановить её и освободить её память, и кнопка терминала, чтобы открыть вашего агента на ней. Несколько моделей могут работать одновременно, когда они вместе помещаются в памяти; если одна не помещается, Omarchy говорит, какую запущенную модель остановить. Перетаскивайте строки, чтобы изменить их порядок, и нажмите Delete на выбранной строке, чтобы удалить модель и её загрузку.

Из командной строки `omarchy agent local start <recipe>` и `omarchy agent local stop <recipe>` делают то же самое, `omarchy agent local status` показывает каждую модель, а `omarchy agent --local` открывает вашего агента по умолчанию на последней запущенной вами модели (pi, если ваш агент по умолчанию не может использовать локальную модель). Любой клиент, совместимый с OpenAI, также может подключиться: `status` показывает адрес каждой модели (первый — `http://127.0.0.1:11435/v1`), название рецепта — это модель, а ключ находится в `~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` удаляет модель и загрузки, которые не использует ни одна другая модель.

Сторонние среды выполнения помечены их издателем. Omarchy запускает каждую модель без доступа к сети.

### Локальные LLM

Omarchy рекомендует два способа запуска локальных моделей LLM: LM Studio и Ollama. LM Studio предоставляет графический интерфейс для поиска моделей с открытыми весами, их установки и запуска. Это отличный способ легко начать. Ollama предлагает CLI для аналогичных действий. Но если вы новичок в локальных моделях, я бы начал с LM Studio. Вы можете установить любой из них в разделе _Установка > ИИ_ в Omarchy Menu.

### Навык Omarchy

Навыки агентов помогают ИИ использовать определённые инструменты определённым образом, и Omarchy поставляется с навыком по умолчанию для настройки системы под себя. Например, настройка вашей конфигурации Hyprland, регулировка панели или даже создание новой темы с нуля. Он подключён символической ссылкой в каталоги навыков для Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` и каждый `~/.hermes/profiles/*/skills`) и общее расположение `~/.agents/skills`, поэтому большинство харнессов подхватывают его автоматически.

Но вам следует относиться к этому навыку как к экспериментальному. Разные модели будут использовать его с разным эффектом. Лучше всего сначала запускать в режиме планирования, чтобы у вас было представление о том, что агент хотел бы изменить. А затем будьте готовы откатить изменения или даже выполнить `omarchy reinstall configs`, если агент устроит полный беспорядок.
