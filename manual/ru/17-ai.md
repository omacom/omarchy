# AI

Hermes — исключение: при первом использовании для него ничего не устанавливается, а его выбор устанавливает Hermes Desktop, как объясняется ниже в разделе _Настольные приложения_.

### Установка и обновление агентов

За исключением Hermes, эти агенты используют ленивую установку mise: первый запуск устанавливает CLI, а последующие запуски используют его повторно. mise также проверяет установленный агент на наличие нового выпуска не чаще одного раза в четыре часа, непосредственно перед его запуском или в фоновом режиме в приглашении оболочки. Если это обновление не удаётся или вы не в сети, запускается установленная версия. `omarchy update` обновляет установленных агентов вместе с остальной частью Omarchy, а `mup` обновляет только инструменты, управляемые mise.

Собственное средство обновления агента, например `claude update`, `codex update` или кнопка обновления в приложении, не обновляет установку, управляемую mise. `codex update` завершается ошибкой, а `claude update` может сообщить об успехе, установив при этом отдельную копию, которую mise не отслеживает. Если вы предпочитаете использовать собственный установщик и средство обновления агента, добавьте его в `disable_tools`; см. [Предустановленные инструменты CLI](18-development-tools.md#preinstalled-cli-tools).

Чтобы установить все настроенные ленивые инструменты до того, как они вам понадобятся, выполните `mise install --include-lazy`. Сюда входят другие инструменты CLI Omarchy по умолчанию, а также агенты. См. [Предустановленные инструменты CLI](18-development-tools.md#preinstalled-cli-tools) о том, как установить один инструмент или использовать собственную установку.

`grok` устанавливается через собственный пакет mise `grok`, так же как `claude` и `codex`. Выполните `grok` или выберите его в _Setup > Defaults > Agent_. Пропустите установщик `curl | bash` на x.ai. Этот путь помещает вторую копию в `~/.grok/bin`, ставит её первой в `PATH` и перезаписывает обёртку Omarchy.

`dsh` открывает свой интерфейс в браузере по адресу `127.0.0.1:3080`, а каталог запуска используется как его рабочее пространство по умолчанию. Его интерфейс в браузере не принимает начальный запрос, поэтому `omarchy agent prompt` открывает его, помещая запрос в ваш буфер обмена для вставки. Omarchy запускает его с предустановкой разрешений DeepSeek без одобрения. DeepSeek Harness загружает журналы сеансов в DeepSeek, когда вы используете его официальный API моделей; отключите это в его интерфейсе в браузере в разделе _Settings > General > Upload Session Log_. Отправляемые вами отзывы также загружаются вместе с сеансом, если только вы не запустите его с `DSH_TELEMETRY_MODE=DISABLED`.

### Агент по умолчанию

Выберите агента по умолчанию с помощью `omarchy default agent <name>` или в _Setup > Defaults > Agent_ в меню Omarchy (`Super + Space`). Если агент ещё не установлен, его выбор сначала установит его. Свежая установка Omarchy предложит вам сделать этот выбор с помощью одноразового уведомления.

Выбор Claude также пытается настроить его расширение для браузера для Chromium, Chrome, Brave, Brave Origin и Edge. Настройка расширения применяется ко всем пользователям и может запросить ваш системный пароль; отмена или неудачная установка расширения всё равно выбирает и запускает Claude. Перезапустите браузер, включите расширение при появлении запроса и войдите в Claude, чтобы завершить его подключение. Выполните `/chrome` в Claude, чтобы проверить соединение. Firefox и Zen не поддерживают это расширение. Если Claude уже был вашим вариантом по умолчанию до добавления этой настройки, выберите его снова, чтобы установить расширение.

После того как вы сделали выбор, `Super + Shift + Ctrl + A` запускает агента по умолчанию в отдельном окне терминала (или открывает средство выбора, если вы ещё не сделали выбор). Вы также можете запустить его сразу с задачей с помощью `omarchy agent prompt "Review this project"`. Freebuff и DeepSeek Harness не принимают начальный запрос, поэтому вместо этого они открываются с запросом в вашем буфере обмена для вставки. Запущенные таким образом агенты работают без присмотра в своих соответствующих режимах «не останавливайся, чтобы спрашивать», поэтому будьте готовы к тому, что они действительно будут что-то делать! MiniMax Code не имеет такого режима для своих интерактивных сеансов, поэтому он запрашивает разрешения как обычно. А поскольку агенты отказываются запоминать доверие для вашего домашнего каталога, запуски из `$HOME` вместо этого начинаются в `~/Work`.

Есть также сокращения в терминале: `a` запускает агента по умолчанию прямо в текущем терминале, а `c`, `cx` и `cy` запускают OpenCode, Claude Code и Codex напрямую (опять же в их режимах автоматического одобрения). Смена темы также синхронизируется с агентами: Claude Code, Pi, OpenCode и Hermes (после того как Omarchy его установила) следуют за вами, когда вы переключаете тему Omarchy.

### Панель агентов

На верхней панели есть значок агентов. До того как вы настроили агента, её панель проведёт вас через вход в Claude, Codex или Grok, и первый из них станет вашим агентом по умолчанию. После этого панель размещает каждую подписку на одной странице: каждый агент и учётная запись с её тарифом, измеритель для каждого из её 5-часовых сеансных и недельных лимитов со временем до его сброса (наведите курсор, чтобы увидеть точный процент) или оставшийся предоплаченный баланс, под строкой, которая по очереди показывает, что вы использовали по всем ним, например токены за эту неделю и вашу наиболее используемую модель. В разделе _Make something_ она предлагает стартовые запросы для новой темы, плагина или приложения, которые передают задачу вашему агенту по умолчанию. Приложения создаются так же, как собственные Hype, Monologue и Omacut в Omarchy, на C++ и Qt Quick, следуя навыку агента omarchy-app, а компилятор и нужные им компоненты Qt поставляются установленными. Claude Code, Codex, Grok, Kimi, Cursor и его лимит Grok Bot, GitHub Copilot, Muse, Antigravity, Kimchi и Devin поддерживаются из коробки с их лимитами, а Hermes, Mistral Vibe и Qwen Code показывают свои сеансы и токены после того, как вы ими воспользовались. Тарифы провайдеров и ключи, которые вы используете через pi, omp или opencode, также отображаются: OpenCode Zen и Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan и Synthetic с их лимитами; Fireworks, OpenRouter и DeepSeek с их предоплаченными балансами; и модели, которые вы запускаете на собственном оборудовании, под заголовком Local models. Каждый агент учитывается один раз, у того, кто выставляет за него счёт, независимо от того, через сколько оболочек вы им управляете.

Щёлкните левой кнопкой мыши по значку на панели, чтобы открыть панель, щёлкните правой кнопкой, чтобы запустить агента по умолчанию. Записи об использовании, лежащие в её основе, обновляются каждые 15 минут с помощью `omarchy agent usage-update`, а панель может даже объединять данные об использовании с ваших других машин через синхронизируемую папку. См. README в `$OMARCHY_PATH/shell/plugins/agents/` для всех настроек.

### Несколько подписок

Если вы платите за более чем один тариф Claude, Codex или Grok — например, личный Max и рабочий, — Omarchy может держать их все вошедшими и перемещаться между ними. Добавьте подписку с помощью + на панели агентов, которая проведёт вас через это прямо там, или с помощью `omarchy agent account add claude Work` (или `codex`, или `grok`). Она установит CLI, если он отсутствует. Первая учётная запись для провайдера входит через ваш обычный браузер, именно там, где CLI всегда ищет. Каждая следующая после этого входит через приватное окно, чтобы учётная запись, в которую ваш браузер уже вошёл, не была подхвачена по ошибке; войдите там как учётная запись, которую вы добавляете, и сначала закройте любое уже открытое у вас приватное окно. Никогда не выходите из CLI для этого: выход отзывает сохранённый вход, и эту учётную запись придётся добавлять снова.

Чтобы скопировать входы по подпискам на другую машину Omarchy по SSH, выполните `omarchy agent account copy user@laptop`. Отправитель предоставляет временного получателя, когда на месте назначения он не установлен, поэтому старые машины Omarchy могут получать учётные записи без обновления. Установленные получатели имеют приоритет. Это копирует все подписки Claude, Codex и Grok; добавьте имена провайдеров, чтобы выбрать их, как в `omarchy agent account copy laptop claude`. Имена учётных записей и ID команд соответствуют источнику, включая учётные записи, уже имеющиеся на месте назначения. Несвязанные учётные записи на месте назначения получают числовой суффикс, если их имена конфликтуют, а настройки, навыки, плагины и история разговоров остаются локальными для каждой машины.

Существующие учётные данные на месте назначения сохраняются. Исходная учётная запись, уже вошедшая там, синхронизирует своё имя без замены её учётных данных; другие учётные записи добавляются рядом с ней. Чтобы заменить сохранённые учётные данные для совпадающих учётных записей, используйте `omarchy agent account copy --replace laptop claude` после завершения сеансов этой учётной записи на месте назначения. Свежее место назначения также получает активную учётную запись источника и предпочтения переключения; устоявшееся место назначения сохраняет свои собственные.

Учётные данные перемещаются через SSH и хранятся в приватных файлах на месте назначения, поэтому копируйте только на машины, которым доверяете. Это одноразовое копирование, а не постоянная синхронизация. Токены обновления Codex могут быть сменены другой машиной, из-за чего скопированный вход будет нуждаться в обновлении; отдельные входы остаются самым надёжным выбором для одновременного использования на нескольких машинах. См. [руководство Codex по аутентификации учётных записей](https://developers.openai.com/codex/auth/ci-cd-auth).

Одна учётная запись на провайдера активна, и каждый новый сеанс начинается как она: `cx`, `cy`, обычный `claude`, `codex` или `grok`, всё, что запущено через `omarchy agent`, и сценарии или редакторы, которые находят CLI в `PATH`. Переключайтесь с помощью `omarchy agent account use work` (и обратно с помощью `omarchy agent account use main`) или на панели, нажав номер учётной записи, а затем `Enter` (или щёлкнув её кнопку Use). Уже запущенные сеансы остаются на учётной записи, с которой они начались. История разговоров, настройки, навыки и плагины являются общими для всех учётных записей, поэтому `claude --continue` в той же папке продолжит с того места, где вы остановились на новой учётной записи.

При наличии более одной учётной записи панель показывает лимиты каждой учётной записи рядом, с отмеченной активной. По умолчанию Omarchy уведомляет вас, когда активная учётная запись превышает 95% лимита, а щёлчок по уведомлению переключает на учётную запись с наибольшим запасом. Наведите курсор на строку учётной записи на панели и щёлкните Autoswitch, которое появляется рядом с Use (или нажмите `m`), или выполните `omarchy agent account mode auto`, чтобы она переключалась сама; пока оно включено, Autoswitch занимает место Use, а повторный щёлчок по нему возвращает к уведомлениям. Добавьте число, чтобы изменить порог, как в `omarchy agent account mode auto 90`. Если каждая учётная запись превышает порог, вы услышите об этом один раз, вместе с тем, какая учётная запись освободится первой. Пока активная учётная запись находится в пределах 15 пунктов от своего порога (80% при значении по умолчанию), её лимиты проверяются каждые три минуты, а не каждые 15.

`omarchy agent account list` показывает каждую учётную запись и её последние лимиты, `omarchy agent account remove work` забывает одну, а `omarchy agent account rename primary Hey` переименовывает одну (или щёлкните имя учётной записи на панели). Эти команды работают с учётными записями вашего агента по умолчанию; чтобы обратиться к другому провайдеру, сначала назовите его, как в `omarchy agent account use codex side`. Вход, который у вас уже был в `~/.claude` или `~/.codex`, является учётной записью _Main_ и остаётся там, где он есть. Учётная запись, оставленная без использования более примерно восьми часов, может показать _Sign-in required_; щёлкните её, чтобы снова войти в эту учётную запись прямо на панели, или начните в ней сеанс, который обновит вход сам по себе. Серверы MCP, которые у вас были, когда учётная запись была добавлена, переходят вместе с ней, но те, которые вы добавляете позже с помощью `claude mcp add`, попадают только в учётную запись, в которой вы их добавили. Claude Desktop и инструменты, настроенные с абсолютным путём к бинарному файлу CLI, не следуют за переключением. Явный `CLAUDE_CONFIG_DIR`, `CODEX_HOME` или `GROK_HOME` имеет приоритет над выбранной учётной записью.

### Диагностика сбоев

Omarchy следит за systemd-coredump на предмет сбоев процессов. Когда что-то завершается с ошибкой сегментации, вы получите уведомление "Process crashed" — щёлкните его, и сбой будет передан вашему агенту по умолчанию вместе с навыком diagnose-crash в Omarchy, который проведёт агента через установление фактов из дампа памяти и решение, стоит ли сообщать о сбое разработчикам. Вы также можете запустить его вручную для любого PID из `coredumpctl list` с помощью `omarchy agent crash <pid>`.

Наблюдение включено по умолчанию. Отключите его в _Trigger > Toggle > Crash Capture_ (или с помощью `omarchy toggle crash-capture`), и уведомления прекратятся; `omarchy agent crash <pid>` по-прежнему работает вручную.

Сбои также можно заглушить по одной программе за раз, что диагностика и предлагает вам в конце. `omarchy crash mute hyprland` останавливает уведомления только для этой программы, `omarchy crash mute hyprland off` возвращает их, а `omarchy crash mute` сам по себе перечисляет то, что вы заглушили. Он принимает путь к бинарному файлу так же охотно, как и его имя, поэтому `omarchy crash mute /usr/bin/hyprland` делает то же самое. Заключите имя с пробелом в кавычки, как в `omarchy crash mute 'Some App'`. Всё остальное по-прежнему уведомляет, а заглушённая программа по-прежнему падает — это скрывает напоминание, оно ничего не исправляет.

### Настольные приложения

Меню _Install > AI_ также содержит несколько графических приложений AI: настольное приложение ChatGPT, настольное приложение Claude (бета-версия Anthropic для Linux, с вкладками Chat, Cowork и Claude Code), Grok Bot для общения с моделями xAI, Herdr Desktop, Hermes Desktop, OpenClaw, настольное приложение Perplexity и T3 Code. Grok Bot — это настольное приложение для чата. Агент для программирования — это команда `grok`.

О Hermes Desktop стоит знать, потому что на машине есть один Hermes, и он принадлежит приложению: Hermes устанавливается только через приложение, и команда `hermes`, которую запускает агент по умолчанию, принадлежит приложению. Выбор Hermes в качестве агента по умолчанию устанавливает то же самое, что устанавливает пункт _Install > AI_: пакет и среду выполнения Hermes в `~/.hermes`, настроенную собственным установщиком Hermes, что в первый раз занимает несколько минут. Эта среда выполнения — та единственная Hermes, которую используют команда `hermes` в терминале, агент по умолчанию и приложение, и она обновляется сама с помощью `hermes update`, а не ждёт выпуска Omarchy. Её установка также передаёт Hermes тему Omarchy как оформление с именем `omarchy`, которому следует каждая поверхность Hermes при переключении тем; выберите другое в настройках Appearance в Hermes или с помощью `/skin`, если вы предпочитаете, чтобы этого не было, и Omarchy оставит этот выбор в покое. Удаление приложения в _Remove > AI_ сначала закрывает Hermes, включая шлюз, уносит с собой эту среду выполнения и сохраняет ваши чаты, воспоминания и навыки, которые Hermes написал для себя, если вы не скажете иначе: оно спрашивает, по умолчанию — нет, следует ли также удалить эти данные и ваши настройки подключения.

Настольный опыт OpenClaw — это его Control UI, который открывается как веб-приложение, поддерживаемое его собственным локальным шлюзом. OpenClaw живёт в `~/.openclaw` и обновляется сам: используйте кнопку "Update Gateway" в Control UI или выполните `openclaw update`, и шлюз перезапустится на новой версии. Omarchy выбирает только выпуск, с которого начинается свежая установка. Удаление OpenClaw в _Remove > AI_ уносит с собой службу шлюза и приложение, а затем спрашивает, следует ли также удалить `~/.openclaw`, поскольку там хранятся ваши чаты и учётные данные наряду с самим OpenClaw и средами выполнения плагинов, которые он загружает; по умолчанию он сохраняется, а повторная установка OpenClaw снова его подхватит.

Herdr Desktop — это настольное приложение [Herdr](https://herdr.dev): пространства, вкладки и панели терминалов и агентов для программирования, которые продолжают работать в его ядре, когда вы закрываете окно. Оно поставляется собственным установщиком Herdr, а не пакетом, поэтому оно живёт в `~/.local/share/herdr-app`, приносит своё ядро в `~/.local/bin/herdr-core`, когда у вас его ещё нет, и обновляет и себя, и его. Оно располагается рядом с командой `herdr`, которую Omarchy предоставляет на `Super + Ctrl + Return`, а не заменяет её, и получает прямые клавиши этой команды: `Alt + Return` и `Alt + Shift + Return` разделяют панель вниз или вправо, `Alt + Escape` закрывает её, `Ctrl + Alt + Arrow` перемещает между панелями, `Alt + 1..9` и `Alt + Left/Right` выбирают вкладку, а `Alt + Up/Down` перемещают между пространствами. `Ctrl + 1..9` выбирает пространство, а `Alt + Shift + Up/Down` проходит по агентам. Клавиши с префиксом `Ctrl + Space` остаются только для терминала, поскольку приложение не может удерживать обычную клавишу Ctrl для последовательности. Omarchy записывает их в `~/.config/herdr-app/keys.json`, а `omarchy-refresh-herdr-app` возвращает их обратно. Его установка выбирает тему Omarchy для Herdr, которая с этого момента следует вашей теме Omarchy. Herdr хранит одну тему для светлого режима и одну для тёмного, поэтому после переключения между тёмной и светлой темой Omarchy ещё раз выберите Omarchy в средстве выбора темы Herdr для другого режима.

T3 Code запускается из своего официального выпуска AppImage в `~/.local/share/t3code`, а не из пакета, поэтому он обновляется сам. Его установка спрашивает, начинать ли на канале Stable или Nightly; переключите позже в настройках T3 Code. Ваши треды и настройки живут в `~/.t3`, и удаление T3 Code в _Remove > AI_ забирает их с собой.

### Локальные модели

Запускайте открытую модель на своей собственной машине для ваших агентов для программирования. Ваши запросы и код остаются на машине; ничего из отправленного модели не покидает её. Начните с:

```bash
omarchy agent local use best
```

Или на панели агентов в верхней панели выберите + , а затем Local AI, который появляется, когда модель подходит этой машине. В первый раз это устанавливает Podman, который запускает модели, а на машине NVIDIA — набор инструментов контейнеров NVIDIA, который даёт им GPU. Затем Omarchy выбирает рекомендуемую модель для этой машины, загружает её и запускает. Ожидайте загрузку в десятки ГБ и использование большей части памяти машины, пока модель работает: Flash Next использует около 100 GiB при полном контексте 256K. Если другие модели занимают нужную ей память, она настраивается остановленной, готовой к запуску, как только вы остановите одну. Модель останавливается при выходе из системы; останавливайте её сами, когда вам нужна память для чего-то другого.

`omarchy agent local list` показывает варианты и объясняет, почему некоторые не подходят. Чтобы настроить другую, выполните `omarchy agent local use <recipe>`. Сегодня `qwen3.8-flash-next-gufo` и `qwen3.8-27b-gufo` доступны для машин Strix Halo со 128 GB; 27B занимает около 40 GiB, поэтому она оставляет место для другой работы. Новые рецепты и рекомендации поступают с `omarchy update`, через пакет.

Каждая настроенная вами модель получает собственную строку на панели агентов, рядом с вашими подписками: воспроизведение, чтобы запустить её, пауза, чтобы остановить её и освободить её память, и кнопка терминала, чтобы открыть на ней вашего агента. Несколько могут работать одновременно, когда они вместе помещаются в память; если одна не помещается, Omarchy говорит, какую запущенную модель остановить. Перетаскивайте строки, чтобы изменить их порядок, и нажимайте Delete на выбранной строке, чтобы удалить модель и её загрузку.

Из командной строки `omarchy agent local start <recipe>` и `omarchy agent local stop <recipe>` делают то же самое, `omarchy agent local status` показывает каждую модель, а `omarchy agent --local` открывает вашего агента по умолчанию на последней запущенной вами модели (pi, если ваш агент по умолчанию не может использовать локальную модель). Любой клиент, совместимый с OpenAI, также может подключиться: `status` показывает адрес каждой модели (первый — `http://127.0.0.1:11435/v1`), имя рецепта — это модель, а ключ находится в `~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` удаляет модель и загрузки, которые не использует никакая другая модель.

Сторонние среды выполнения помечены их издателем. Omarchy запускает каждую модель без доступа к сети.

### Локальные LLM

Omarchy рекомендует два способа запуска локальных моделей LLM: LM Studio и Ollama. LM Studio предоставляет графический интерфейс для поиска моделей с открытыми весами, их установки и запуска. Это отличный способ легко начать. Ollama предлагает CLI для этого аналогичным образом. Но если вы новичок в локальных моделях, я бы начал с LM Studio. Вы можете установить любой из них в _Install > AI_ в меню Omarchy.

### Навык Omarchy

Навыки агентов помогают AI использовать конкретные инструменты конкретным способом, и Omarchy поставляется с навыком по умолчанию для настройки системы под себя. Например, настройка вашей конфигурации Hyprland, регулировка панели или даже создание новой темы с нуля. Он является символической ссылкой в каталогах навыков для Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` и каждый `~/.hermes/profiles/*/skills`) и общего расположения `~/.agents/skills`, поэтому большинство оболочек подхватывают его автоматически.

Но вы должны относиться к этому навыку как к экспериментальному. Разные модели будут использовать его с разным эффектом. Лучше всего сначала запускать в режиме планирования, чтобы у вас было представление о том, что агент хотел бы изменить. А затем будьте готовы откатить изменения или даже вызвать `omarchy reinstall configs`, если агент наведёт беспорядок во всём.
