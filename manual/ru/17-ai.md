Hermes — исключение: для него при первом использовании ничего не устанавливается, а его выбор устанавливает Hermes Desktop, как объясняет раздел _Десктопные приложения_ ниже.

### Установка и обновление агентов

За исключением Hermes, эти агенты используют ленивую установку mise: первый запуск устанавливает CLI, а последующие запуски используют её повторно. mise также проверяет установленного агента на наличие нового релиза не чаще одного раза в четыре часа, прямо перед его запуском или в фоне в приглашении оболочки. Если это обновление не удаётся или вы офлайн, запускается установленная версия. `omarchy update` обновляет установленных агентов вместе с остальной частью Omarchy, а `mup` обновляет только инструменты, управляемые mise.

Собственный обновлятор агента, такой как `claude update`, `codex update` или кнопка обновления в приложении, не обновляет установку, управляемую mise. `codex update` завершается ошибкой, а `claude update` может сообщить об успехе, установив при этом отдельную копию, которую mise не отслеживает. Если вы предпочитаете использовать нативный установщик и обновлятор агента, добавьте его в `disable_tools`; см. [Preinstalled CLI tools](18-development-tools.md#preinstalled-cli-tools).

Чтобы установить все настроенные ленивые инструменты до того, как они понадобятся, запустите `mise install --include-lazy`. Это включает другие CLI-инструменты Omarchy по умолчанию, а также агентов. См. [Preinstalled CLI tools](18-development-tools.md#preinstalled-cli-tools) для установки одного инструмента или использования собственной установки.

`grok` устанавливается через фирменный пакет mise `grok`, так же, как `claude` и `codex`. Запустите `grok` или выберите его в _Agent > Harness_. Пропустите установщик `curl | bash` на x.ai. Этот путь ставит вторую копию в `~/.grok/bin`, добавляет её в начало `PATH` и перезаписывает обёртку Omarchy.

`dsh` открывает свой браузерный интерфейс на `127.0.0.1:3080`, с каталогом запуска в качестве рабочего пространства по умолчанию. Его браузерный интерфейс не принимает стартовый промпт, поэтому `omarchy agent prompt` открывает его с промптом в буфере обмена, чтобы вы могли вставить его. Omarchy запускает его с пресетом разрешений без подтверждений от DeepSeek. DeepSeek Harness загружает логи сессий в DeepSeek, когда вы используете его официальный API моделей; отключите это в его браузерном интерфейсе в _Settings > General > Upload Session Log_. Отправляемая вами обратная связь также загружается вместе с сессией, если только вы не запустите его с `DSH_TELEMETRY_MODE=DISABLED`.

### Агент по умолчанию

Выберите агента по умолчанию с помощью `omarchy default agent <name>` или в _Agent > Harness_ в Omarchy Menu (`Super + Space`). Если агент ещё не установлен, его выбор сначала установит его. Свежая Omarchy предложит вам сделать этот выбор одноразовым уведомлением.

Выбор Claude также пытается настроить его расширение для браузера для Chromium, Chrome, Brave, Brave Origin и Edge. Настройка расширения применяется ко всем пользователям и может запросить ваш системный пароль; отмена или неудачная установка расширения всё равно выбирает и запускает Claude. Перезапустите браузер, включите расширение при запросе и войдите в Claude, чтобы завершить его подключение. Запустите `/chrome` в Claude, чтобы проверить соединение. Firefox и Zen не поддерживают это расширение. Если Claude уже был вашим агентом по умолчанию до добавления этой настройки, выберите его снова, чтобы установить расширение.

После выбора `Super + Shift + Ctrl + A` запускает агента по умолчанию в отдельном окне терминала (или показывает выбор, если вы ещё не выбрали). Вы также можете запустить его сразу с задачей с помощью `omarchy agent prompt "Review this project"`. Freebuff и DeepSeek Harness не принимают стартовый промпт, поэтому вместо этого они открываются с промптом в буфере обмена для вставки. Агенты, запущенные таким образом, работают без присмотра в своих режимах «не останавливайся, чтобы спросить», так что будьте готовы к тому, что они действительно будут что-то делать! У MiniMax Code нет такого режима для интерактивных сессий, поэтому он запрашивает разрешения как обычно. А поскольку агенты отказываются запоминать доверие для вашего домашнего каталога, запуски из `$HOME` вместо этого стартуют в `~/Work`.

Есть и ярлыки терминала: `a` запускает агента по умолчанию прямо в текущем терминале, а `c`, `cx` и `cy` запускают OpenCode, Claude Code и Codex напрямую (опять же в их режимах автоматического подтверждения). Смена темы также синхронизируется с агентами: Claude Code, Pi, OpenCode и Hermes (после того как Omarchy его установила) следуют за вами при смене темы Omarchy.

### Ваши инструкции для агентов

Личные правила для каждого агента находятся в `~/.agents/AGENTS.md`, рядом с общими навыками в `~/.agents/skills`. Откройте его в _Agent > Instructions_, который также связывает его с каждой оболочкой, хранящей собственный глобальный файл: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` у Copilot и так далее. Crush и Amp читают ссылку `~/.config/AGENTS.md`, а omp, Kimi и DeepSeek Harness читают `~/.agents/AGENTS.md` напрямую. Выбор агента по умолчанию также связывает его. Файл инструкций, который у вас уже был, становится общим, если его ещё не было; в противном случае он сохраняется рядом со ссылкой как `.bak`. Запустите `omarchy agent instructions`, чтобы перепривязать после установки другого агента.

### Панель агентов

В верхней панели есть значок агентов. До того как вы настроите агента, его панель проведёт вас через вход в Claude, Codex или Grok, и первый из них станет вашим агентом по умолчанию. После этого панель собирает каждую подписку на одной странице: каждый агент и аккаунт с его планом, измеритель для каждого из его 5-часовых сессионных и недельных лимитов со временем до сброса (наведите курсор для точного процента) или оставшийся предоплаченный баланс, под строкой, которая по кругу показывает, что вы использовали по всем ним, например токены за эту неделю и вашу самую используемую модель. В _Make something_ она предлагает стартовые промпты для новой темы, плагина, приложения или игры, которые передают задачу вашему агенту по умолчанию. Приложения собираются так же, как собственные Hype, Monologue и Omacut у Omarchy, на C++ и Qt Quick, следуя агентскому навыку omarchy-make-app, а нужные им компилятор и компоненты Qt поставляются установленными. Игры — это одна страница three.js в `~/Games/vibes`, следующая агентскому навыку omarchy-make-game, и все они открываются из одного лаунчера Game Vibes в текущей теме; они загружают three.js из сети, поэтому для запуска им нужно соединение. Claude Code, Codex, Grok, Kimi, Cursor и его лимит Grok Bot, GitHub Copilot, Muse, Antigravity, Kimchi и Devin покрываются из коробки со своими лимитами, а Hermes, Mistral Vibe и Qwen Code показывают свои сессии и токены, как только вы ими воспользуетесь. Планы провайдеров и ключи, которые вы используете через pi, omp или opencode, тоже отображаются: OpenCode Zen и Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan и Synthetic со своими лимитами; Fireworks, OpenRouter и DeepSeek со своими предоплаченными балансами; и модели, которые вы запускаете на собственном оборудовании, в разделе Local models. Каждый агент учитывается один раз, у того, кто выставляет за него счёт, сколько бы оболочек вы через него ни прогнали.

Щелчок левой кнопкой по значку в панели открывает панель, щелчок правой кнопкой запускает вашего агента по умолчанию. Записи использования за ней перегенерируются каждые 15 минут командой `omarchy agent usage-update`, а панель может даже объединять использование с ваших других машин через синхронизируемую папку. См. README в `$OMARCHY_PATH/shell/plugins/agents/` для полных настроек.

### Несколько подписок

Если вы платите за несколько планов Claude, Codex или Grok — скажем, личный Max и рабочий, — Omarchy может держать их все вошедшими и переключаться между ними. Добавьте подписку с помощью + в панели агентов, которая проведёт вас через это прямо там, или с помощью `omarchy agent account add claude Work` (или `codex`, или `grok`). Она устанавливает CLI, если его не хватает. Первый аккаунт провайдера входит через ваш обычный браузер, прямо там, где CLI всегда ищет. Каждый последующий входит через приватное окно, чтобы аккаунт, в который ваш браузер уже вошёл, не подхватился по ошибке; войдите там как аккаунт, который добавляете, и сначала закройте любое приватное окно, которое у вас уже открыто. Никогда не выходите из CLI для этого: выход отзывает сохранённый вход, и этот аккаунт придётся добавлять снова.

Чтобы скопировать входы подписок на другую машину Omarchy по SSH, запустите `omarchy agent account copy user@laptop`. Отправитель предоставляет временного получателя, когда на месте назначения он не установлен, поэтому старые машины Omarchy могут получать аккаунты без обновления. Установленные получатели имеют приоритет. Это копирует все подписки Claude, Codex и Grok; добавьте имена провайдеров, чтобы выбрать их, как в `omarchy agent account copy laptop claude`. Имена аккаунтов и ID команд соответствуют источнику, включая аккаунты, уже присутствующие на месте назначения. Несвязанные аккаунты места назначения получают числовой суффикс при конфликте имён, а настройки, навыки, плагины и история разговоров остаются локальными для каждой машины.

Существующие учётные данные места назначения сохраняются. Аккаунт источника, уже вошедший там, синхронизирует своё имя без замены учётных данных; другие аккаунты добавляются рядом с ним. Чтобы заменить сохранённые учётные данные для совпадающих аккаунтов, используйте `omarchy agent account copy --replace laptop claude` после завершения сессий этого аккаунта на месте назначения. Свежее место назначения также получает активный аккаунт источника и предпочтения переключения; устоявшееся место назначения сохраняет свои собственные.

Учётные данные перемещаются через SSH и хранятся в приватных файлах на месте назначения, поэтому копируйте только на машины, которым доверяете. Это разовое копирование, а не постоянная синхронизация. Токены обновления Codex могут быть ротированы другой машиной, из-за чего скопированному входу потребуется обновление; отдельные входы остаются самым надёжным выбором для одновременного использования на нескольких машинах. См. [руководство Codex по аутентификации аккаунтов](https://developers.openai.com/codex/auth/ci-cd-auth).

Один аккаунт на провайдера активен, и каждая новая сессия начинается как он: `cx`, `cy`, обычный `claude`, `codex` или `grok`, всё, что запущено через `omarchy agent`, и скрипты или редакторы, которые находят CLI в `PATH`. Переключайтесь с помощью `omarchy agent account use work` (и обратно с помощью `omarchy agent account use main`) или в панели, нажав номер аккаунта, а затем `Enter` (или нажав его кнопку Use). Запущенные сессии Claude тоже переключаются, со следующего сообщения: каждая сессия Claude работает в `~/.claude`, который всегда хранит вход активного аккаунта. Сессия Claude, запущенная в собственной папке аккаунта более старой Omarchy, сохраняет этот вход до своего завершения, поэтому переключение называет эти сессии и завершается само, как только они исчезнут. Запущенные сессии Codex и Grok остаются на аккаунте, с которым стартовали. История разговоров, настройки, навыки и плагины являются общими для аккаунтов, поэтому `claude --continue` в той же папке подхватывает с того места, где вы остановились, на новом аккаунте.

При нескольких аккаунтах панель показывает лимиты каждого аккаунта рядом, с отмеченным активным. По умолчанию Omarchy уведомляет вас, когда активный аккаунт превышает 95% лимита, а нажатие на уведомление переключает на аккаунт с наибольшим запасом. Наведите курсор на строку аккаунта в панели и нажмите Autoswitch, который появляется рядом с Use (или нажмите `m`), или запустите `omarchy agent account mode auto`, чтобы он переключался сам; пока это включено, Autoswitch занимает место Use, а повторное нажатие на него возвращает к уведомлениям. Добавьте число, чтобы изменить порог, как в `omarchy agent account mode auto 90`. Если каждый аккаунт превышает порог, вы услышите об этом один раз, вместе с тем, какой аккаунт освободится первым. Пока активный аккаунт находится в пределах 15 пунктов от своего порога (80% по умолчанию), его лимиты проверяются каждые три минуты, а не каждые 15.

`omarchy agent account list` показывает каждый аккаунт и его последние лимиты, `omarchy agent account remove work` забывает один, а `omarchy agent account rename primary Hey` переименовывает один (или нажмите на имя аккаунта в панели). Эти команды работают с аккаунтами вашего агента по умолчанию; чтобы добраться до другого провайдера, сначала назовите его, как в `omarchy agent account use codex side`. Вход, который у вас уже был в `~/.claude` или `~/.codex`, — это аккаунт _Main_. У Codex он остаётся на месте; у Claude он ждёт в собственной папке, пока активен другой аккаунт. Аккаунт, не использовавшийся более примерно восьми часов, может показать _Sign-in required_; нажмите на него, чтобы снова войти в этот аккаунт прямо в панели, или переключитесь на него и запустите сессию, что само обновит вход. MCP-серверы, которые вы добавляете с помощью `claude mcp add`, достаются каждому аккаунту Claude, поскольку все они работают в `~/.claude`; для Codex и Grok серверы, которые у вас были при добавлении аккаунта, переходят к нему, но более поздние достаются только аккаунту, в котором вы их добавили. Claude Desktop хранит собственный вход, а инструменты Codex или Grok, настроенные с абсолютным путём к бинарнику CLI, не следуют за переключением. Явный `CLAUDE_CONFIG_DIR`, `CODEX_HOME` или `GROK_HOME` имеет приоритет над выбранным аккаунтом.

### Диагностика сбоев

Omarchy следит за systemd-coredump на предмет сбоев процессов. Когда что-то сегфолтится, вы получите уведомление «Process crashed» — нажмите на него, и сбой будет передан вашему агенту по умолчанию вместе с навыком diagnose-crash у Omarchy, который проводит агента через установление фактов из дампа ядра и решение, стоит ли сообщать о сбое в апстрим. Вы также можете запустить это вручную для любого PID из `coredumpctl list` с помощью `omarchy agent crash <pid>`.

Наблюдение включено по умолчанию. Отключите его в _Trigger > Toggle > Crash Capture_ (или с помощью `omarchy toggle crash-capture`), и уведомления прекратятся; `omarchy agent crash <pid>` по-прежнему работает вручную.

Сбои также можно заглушить по одной программе за раз, что диагностика и предлагает вам в конце. `omarchy crash mute hyprland` останавливает уведомления только для этой программы, `omarchy crash mute hyprland off` возвращает их, а `omarchy crash mute` сама по себе перечисляет, что вы заглушили. Она принимает путь к бинарнику так же охотно, как и его имя, поэтому `omarchy crash mute /usr/bin/hyprland` делает то же самое. Заключите имя с пробелом в кавычки, как в `omarchy crash mute 'Some App'`. Всё остальное по-прежнему уведомляет, а заглушенная программа по-прежнему падает — это скрывает напоминание, а не чинит что-либо.

### Десктопные приложения

Меню _Install > AI_ также содержит несколько графических приложений ИИ: десктопное приложение ChatGPT, десктопное приложение Claude (бета Anthropic для Linux, с вкладками Chat, Cowork и Claude Code), Grok Bot для общения с моделями xAI, Herdr Desktop, Hermes Desktop, OpenClaw, десктопное приложение Perplexity и T3 Code. Grok Bot — это десктопное приложение для чата. Кодинг-агент — это команда `grok`.

Hermes Desktop — то, о чём стоит знать, потому что у машины есть один Hermes, и он принадлежит приложению: Hermes устанавливается только через приложение, а команда `hermes`, которую запускает агент по умолчанию, принадлежит приложению. Выбор Hermes в качестве агента по умолчанию устанавливает то же самое, что и пункт _Install > AI_: пакет и среду выполнения Hermes в `~/.hermes`, настроенную собственным установщиком Hermes, что занимает несколько минут в первый раз. Эта среда выполнения — тот единственный Hermes, который используют терминальная команда `hermes`, агент по умолчанию и приложение, и она обновляет себя с помощью `hermes update`, а не ждёт релиза Omarchy. Её установка также передаёт Hermes тему Omarchy как скин с именем `omarchy`, за которым следует каждая поверхность Hermes при смене тем; выберите другой в настройках Appearance у Hermes или с помощью `/skin`, если предпочитаете, чтобы этого не было, и Omarchy оставит этот выбор в покое. Удаление приложения в _Remove > AI_ сначала закрывает Hermes, включая шлюз, забирает эту среду выполнения с собой и сохраняет ваши чаты, воспоминания и навыки, которые Hermes написал для себя, если только вы не скажете иначе: оно спрашивает, по умолчанию — нет, должны ли эти данные и ваши настройки подключения тоже уйти.

Десктопный опыт OpenClaw — это его Control UI, который открывается как веб-приложение, опирающееся на собственный локальный шлюз. OpenClaw живёт в `~/.openclaw` и обновляет себя: используйте кнопку «Update Gateway» в Control UI или запустите `openclaw update`, и шлюз перезапустится на новой версии. Omarchy выбирает только релиз, с которого начинается свежая установка. Удаление OpenClaw в _Remove > AI_ забирает с собой службу шлюза и приложение, а затем спрашивает, должен ли `~/.openclaw` тоже уйти, поскольку там хранятся ваши чаты и учётные данные рядом с самим OpenClaw и средами выполнения плагинов, которые он загружает; по умолчанию он сохраняется, и повторная установка OpenClaw снова его подхватит.

Herdr Desktop — это десктопное приложение [Herdr](https://herdr.dev): пространства, вкладки и панели терминалов и кодинг-агентов, которые продолжают работать в его ядре, когда вы закрываете окно. Оно поступает из собственного установщика Herdr, а не из пакета, поэтому живёт в `~/.local/share/herdr-app`, приносит своё ядро в `~/.local/bin/herdr-core`, когда у вас его ещё нет, и обновляет их оба само. Оно располагается рядом с командой `herdr`, которую Omarchy поставляет на `Super + Ctrl + Return`, а не заменяет её, и получает прямые клавиши этой команды: `Alt + Return` и `Alt + Shift + Return` делят панель вниз или вправо, `Alt + Escape` закрывает её, `Ctrl + Alt + Arrow` перемещает между панелями, `Alt + 1..9` и `Alt + Left/Right` выбирают вкладку, а `Alt + Up/Down` перемещают между пространствами. `Ctrl + 1..9` выбирает пространство, а `Alt + Shift + Up/Down` проходит по агентам. Префиксные клавиши `Ctrl + Space` остаются только для терминала, поскольку приложение не может удерживать обычную клавишу Ctrl для последовательности. Omarchy записывает их в `~/.config/herdr-app/keys.json`, а `omarchy-refresh-herdr-app` возвращает их на место. При установке выбирается тема Omarchy у Herdr, которая с этого момента следует за вашей темой Omarchy. Herdr хранит одну тему для светлого режима и одну для тёмного, поэтому после переключения между тёмной и светлой темой Omarchy выберите Omarchy в выборе темы Herdr ещё раз для другого режима.

T3 Code работает из официального релиза AppImage в `~/.local/share/t3code`, а не из пакета, поэтому обновляет себя сам. При установке спрашивается, начинать ли на канале Stable или Nightly; переключите позже в настройках T3 Code. Ваши треды и настройки живут в `~/.t3`, а удаление T3 Code в _Remove > AI_ забирает их с собой.

### Локальные модели

Запустите открытую модель на собственной машине для ваших кодинг-агентов. Ваши промпты и код остаются на машине; ничто из отправленного модели не покидает её. Начните с:

```bash
omarchy agent local use best
```

Или в панели агентов в верхней панели выберите + и затем Local AI, что появляется, когда модель подходит этой машине. В первый раз это устанавливает Podman, который запускает модели, а на машине с NVIDIA — инструментарий контейнеров NVIDIA, который даёт им GPU. Затем Omarchy выбирает рекомендуемую модель для этой машины, загружает её и запускает. Ожидайте загрузку на десятки GB и использование большей части памяти машины во время работы модели: Flash Next использует около 100 GiB со своим полным контекстом 256K. Если другие модели удерживают нужную ей память, она настраивается остановленной, готовой к запуску, как только вы остановите одну из них. Модель останавливается при выходе из системы; останавливайте её сами, когда память нужна для чего-то другого.

`omarchy agent local list` показывает варианты и объясняет, почему некоторые не подходят. Чтобы настроить другую, запустите `omarchy agent local use <recipe>`. Сегодня для машин Strix Halo со 128 GB доступны `qwen3.8-flash-next-gufo` и `qwen3.8-27b-gufo`; 27B занимает около 40 GiB, поэтому оставляет место для другой работы. На ноутбуке с 64 GB и Intel Arc B390 `qwen3.6-35b-a3b-llamacpp` работает примерно в 30 GiB. Новые рецепты и рекомендации поступают с `omarchy update`, через пакет.

Каждая настроенная вами модель получает собственную строку в панели агентов, рядом с вашими подписками: play, чтобы запустить её, pause, чтобы остановить и освободить память, и кнопка терминала, чтобы открыть на ней вашего агента. Несколько могут работать одновременно, когда они вместе помещаются в память; если одна не помещается, Omarchy говорит, какую работающую модель остановить. Перетаскивайте строки, чтобы изменить их порядок, и нажимайте Delete на выбранной строке, чтобы удалить модель и её загрузку.

Каждая настроенная вами модель также получает собственную запись в лаунчере приложений, под именем модели и с логотипом её создателя, так же, как вход в Claude, Codex или Grok добавляет такую запись. Она открывает вашего агента на этой модели и сначала запускает модель, если она не работает: терминал показывает её загрузку и передаёт управление агенту, как только она поднимется. Удаление модели удаляет её запись.

Модель продолжает работать ровно так, как была настроена, поэтому обновление Omarchy никогда не перезапускает её под вашими агентами. Когда у Omarchy есть более новая среда выполнения или более новые веса для настроенной вами модели, её строка показывает кнопку обновления: нажмите её, и модель будет настроена снова в фоне, загружая только то, что изменилось, и перезапустится на новой версии. Остановленная модель остаётся остановленной. `omarchy agent local update` делает то же самое для каждой модели из терминала.

Из командной строки `omarchy agent local start <recipe>` и `omarchy agent local stop <recipe>` делают то же самое, `omarchy agent local status` показывает каждую модель, а `omarchy agent --local` открывает вашего агента по умолчанию на последней запущенной вами модели. pi, OpenCode и Qwen Code могут использовать одну из них; при любом другом агенте по умолчанию она открывается в pi. pi также перечисляет каждую настроенную вами модель и модели на машинах, с которыми вы спаривались, в собственном выборе моделей, поэтому обычный `pi` тоже до них добирается. Любой клиент, совместимый с OpenAI, тоже может подключиться: `status` показывает адрес каждой модели (первый — `http://127.0.0.1:11435/v1`), имя рецепта — это модель, а ключ находится в `~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` удаляет модель и загрузки, которые не использует ни одна другая модель.

Сторонние среды выполнения помечены их издателем. Omarchy запускает каждую модель без доступа к сети.

### Локальные LLM

Omarchy рекомендует два способа запуска локальных моделей LLM: LM Studio и Ollama. LM Studio предоставляет GUI-интерфейс для поиска моделей с открытыми весами, их установки и запуска. Это отличный способ легко начать. Ollama предлагает CLI для того же самого. Но если вы новичок в локальных моделях, я бы начал с LM Studio. Вы можете установить любой из них в _Install > AI_ в Omarchy Menu.

### Навык Omarchy

Агентские навыки помогают ИИ использовать конкретные инструменты конкретным образом, и Omarchy поставляется с навыком по умолчанию для настройки системы. Например, подкрутить вашу конфигурацию Hyprland, настроить панель или даже создать новую тему с нуля. Он симлинкуется в каталоги навыков для Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` и каждый `~/.hermes/profiles/*/skills`) и общее расположение `~/.agents/skills`, поэтому большинство оболочек подхватывают его автоматически.

Но вы должны относиться к этому навыку как к экспериментальному. Разные модели будут использовать его с разным эффектом. Лучше сначала запускать в режиме планирования, чтобы иметь представление о том, что агент хотел бы изменить. А затем будьте готовы откатить изменения или даже вызвать `omarchy reinstall configs`, если агент устроит из всего беспорядок.
