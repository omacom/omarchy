# ИИ

В Omarchy есть лаунчеры для перечисленных ниже агентов для программирования, но вариант по умолчанию за вас никто не выбирает. Установите одного из них через _Install > AI > CLI_, а затем пройдите аутентификацию, когда появится запрос. Hermes и OpenClaw — исключения: выбор любого из них устанавливает его собственную самообновляющуюся копию, как объясняется ниже в разделе _Настольные приложения_.

### Установка и обновление агентов

За исключением Hermes и OpenClaw, каждый агент — это пакет из собственного репозитория Omarchy. Установите одного из них через _Install > AI > CLI_ или командой `omarchy install ai cli <command>`, и удалите его снова через _Remove > AI > CLI_, при этом его входы в аккаунты и история останутся на месте. Выбор ещё не установленного агента тоже устанавливает его: отметка звёздочкой на панели агентов, выбор командой `omarchy default agent <name>` или вход в его подписку. Omarchy публикует каждый новый релиз агента в течение часа на всех каналах, и `omarchy update` устанавливает его вместе с остальной системой.

Поскольку pacman поддерживает их в актуальном состоянии, собственные средства обновления агентов отключены: команде `claude update` или кнопке обновления в приложении нечего делать. Если вы предпочитаете запускать агента из его собственного установщика, используйте его и оставьте пакет Omarchy неустановленным; копия, уже находящаяся в вашем `PATH`, считается установленной. Избегайте установщиков `curl | bash`, которые ставят вторую копию впереди копии Omarchy в `PATH`, например установщика x.ai для `grok`.

`dsh` открывает свой браузерный UI на `127.0.0.1:3080`, при этом каталог запуска используется как его рабочее пространство по умолчанию. Его браузерный UI не принимает начальный промпт, поэтому `omarchy agent prompt` открывает его с промптом в вашем буфере обмена, чтобы вы могли вставить его. Omarchy запускает его с пресетом разрешений DeepSeek без подтверждений. DeepSeek Harness загружает журналы сессий в DeepSeek, когда вы используете его официальный API моделей; отключите это в его браузерном UI в разделе _Settings > General > Upload Session Log_. Отправляемая вами обратная связь также загружается вместе с сессией, если только вы не запустите его с `DSH_TELEMETRY_MODE=DISABLED`.

### Агент по умолчанию

Выберите агента по умолчанию звёздочкой рядом с агентом на панели агентов, которая заполнена у агента по умолчанию, или командой `omarchy default agent <name>`, которая также принимает любой харнес, для которого там нет строки. Если агент ещё не установлен, выбор сначала устанавливает его, а также он получает собственный лаунчер в лаунчере приложений, рядом с Agent. Свежая установка Omarchy предлагает вам настроить одного из них одноразовым уведомлением, которое открывает панель агентов.

Выбор Claude также пытается настроить его расширение для браузера для Chromium, Chrome, Brave, Brave Origin и Edge. Настройка расширения применяется ко всем пользователям и может запросить ваш системный пароль; отмена или неудачная установка расширения всё равно выбирает и запускает Claude. Перезапустите браузер, включите расширение, если появится запрос, и войдите в Claude, чтобы завершить его подключение. Выполните `/chrome` в Claude, чтобы проверить соединение. Firefox и Zen не поддерживают это расширение. Если Claude уже был вашим агентом по умолчанию до добавления этой настройки, выберите его снова, чтобы установить расширение.

После выбора сочетание `Super + Shift + Ctrl + A` запускает агента по умолчанию в отдельном окне терминала (или показывает средство выбора, если вы ещё не выбрали). Вы также можете запустить его сразу с задачей командой `omarchy agent prompt "Review this project"`. Freebuff и DeepSeek Harness не принимают начальный промпт, поэтому вместо этого они открываются с промптом в вашем буфере обмена для вставки. Агенты, запущенные таким способом, работают без присмотра в своих соответствующих режимах «не останавливайся, чтобы спросить», так что будьте готовы к тому, что они действительно будут что-то делать! У MiniMax Code нет такого режима для его интерактивных сессий, поэтому он запрашивает разрешения как обычно. А поскольку агенты отказываются запоминать доверие для вашего домашнего каталога, запуски из `$HOME` вместо этого стартуют в `~/Work`.

Есть и сокращения в терминале: `a` запускает агента по умолчанию прямо в текущем терминале, а `c`, `cx`, `cy` и `ca` запускают OpenCode, Claude Code, Codex и Antigravity напрямую (опять же в их режимах с автоматическим одобрением). Смена темы также синхронизируется с агентами: Claude Code, Pi, OpenCode и Hermes (после того, как Omarchy его установил) следуют за вами, когда вы переключаете тему Omarchy.

### Инструкции для ваших агентов

Личные правила для каждого агента находятся в `~/.agents/AGENTS.md`, рядом с общими навыками в `~/.agents/skills`. Откройте его значком документа рядом с + на панели агентов или командой `omarchy agent instructions --edit`, которая также связывает его с каждым харнесом, хранящим собственный глобальный файл: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` у Copilot, и так далее. Crush и Amp читают ссылку `~/.config/AGENTS.md`, а omp, Kimi и DeepSeek Harness читают `~/.agents/AGENTS.md` напрямую. Выбор агента по умолчанию также связывает его. Файл инструкций, который у вас уже был, становится общим, если его ещё не было; в противном случае он сохраняется рядом со ссылкой как `.bak`. Выполните `omarchy agent instructions`, чтобы повторно связать после установки другого агента.

### Панель агентов

В верхней панели есть значок агентов. Пока вы не настроили агента, его панель предлагает три способа начать: войти по подписке Claude, Codex, Grok, Gemini, Muse, Cursor или Copilot, или в разделе More — по плану программирования OpenCode Go, MiniMax, Synthetic или Z.ai; платить по мере использования через Fireworks, OpenCode Zen and Go, OpenRouter, или в разделе More — DeepSeek или любого другого провайдера, в которого входит OpenCode, при этом всё работает в OpenCode; или запустить лучшую модель для вашего компьютера, когда такая для него подходит. Первый завершённый вами вариант становится вашим агентом по умолчанию, а + на панели позже предлагает те же три варианта. После этого панель размещает каждую подписку на одной странице: каждый агент и аккаунт с его планом, индикатор для каждого из его 5-часовых сессионных и недельных лимитов со временем до его сброса (наведите курсор, чтобы увидеть точный процент), или оставшийся предоплаченный баланс, под строкой, которая по очереди показывает, что вы использовали по всем ним, например токены за эту неделю и вашу самую используемую модель. В разделе _Make something cool_ она предлагает стартовые промпты для новой темы, плагина, приложения или игры, которые передают задачу вашему агенту по умолчанию. Приложения создаются так же, как собственные приложения Omarchy Hype, Monologue и Omacut, на C++ и Qt Quick, следуя агентскому навыку omarchy-make-app, а нужные им компилятор и компоненты Qt поставляются установленными. Игры — это одна страница three.js в `~/Games/vibes`, следующая агентскому навыку omarchy-make-game, и все открываются из одного лаунчера Game Vibes в текущей теме; они загружают three.js из веба, поэтому для запуска им нужно соединение. Claude Code, Codex, Grok, Kimi, Cursor и его лимит Grok Bot, GitHub Copilot, Muse, Gemini (через Antigravity) и Devin покрываются из коробки со своими лимитами, Kimchi — со своим планом, предоплаченными кредитами и бюджетами расходов, а Hermes, Mistral Vibe и Qwen Code показывают свои сессии и токены, как только вы ими воспользуетесь. Планы и ключи провайдеров, которые вы используете через pi, omp или opencode, также отображаются: OpenCode Zen and Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan и Synthetic со своими лимитами; OpenRouter и DeepSeek со своими предоплаченными балансами; Fireworks с его расходами за последние 30 дней. Модели для программирования, которые вы запускаете на собственном оборудовании, получают собственные строки, и их токены также учитываются в итогах, как описано в разделе [Локальные модели](#local-models). Каждый агент учитывается один раз, у того, кто выставляет за него счёт, независимо от того, через сколько харнесов вы им управляете.

Щёлкните левой кнопкой мыши по значку на панели или нажмите `Super + Ctrl + X` для панели, щёлкните правой кнопкой мыши, чтобы запустить вашего агента по умолчанию, и средней кнопкой мыши, чтобы обновить. Записи об использовании, лежащие в её основе, перегенерируются каждые 15 минут командой `omarchy agent usage update`, а панель может даже объединять использование с ваших других машин через синхронизируемую папку. Полные настройки смотрите в README в `$OMARCHY_PATH/shell/plugins/agents/`.

### Несколько подписок

Если вы платите за несколько планов Claude, Codex или Grok — например, личный Max и рабочий, — Omarchy может держать их все вошедшими и переключаться между ними. Добавьте подписку с помощью + на панели агентов, которая проведёт вас через это прямо там, или командой `omarchy agent account add claude Work` (или `codex`, или `grok`). Тот же + и та же команда входят в Gemini (`gemini`) и OpenCode (`opencode`) и сохраняют ключ API Fireworks (`fireworks`) или OpenRouter (`openrouter`) в OpenCode; команда также входит в Copilot (`copilot`), Cursor (`cursor`) и Muse (`muse`). У них сохраняется по одному входу у каждого. Она устанавливает CLI, если он отсутствует. Первый аккаунт для провайдера входит через ваш обычный браузер, прямо там, где CLI всегда ищет. Каждый следующий после него входит через приватное окно, чтобы аккаунт, в который ваш браузер уже вошёл, не подхватился по ошибке; войдите там как аккаунт, который вы добавляете, и сначала закройте любое уже открытое у вас приватное окно. Никогда не выходите из CLI для этого: выход отзывает сохранённый вход, и этот аккаунт придётся добавлять снова.

Чтобы скопировать входы по вашим подпискам на другую машину Omarchy через SSH, выполните `omarchy agent account copy user@laptop`. Отправитель предоставляет временного приёмника, когда на пункте назначения его нет, поэтому старые машины Omarchy могут получать аккаунты без обновления. Установленные приёмники имеют приоритет. Это копирует все подписки Claude, Codex и Grok; добавьте имена провайдеров, чтобы выбрать их, как в `omarchy agent account copy laptop claude`. Имена аккаунтов и ID команд совпадают с источником, включая аккаунты, уже присутствующие на пункте назначения. Несвязанные аккаунты на пункте назначения получают числовой суффикс, если их имена конфликтуют, а настройки, навыки, плагины и история разговоров остаются локальными на каждой машине.

Существующие учётные данные на пункте назначения сохраняются. Аккаунт источника, уже вошедший там, синхронизирует своё имя без замены своих учётных данных; другие аккаунты добавляются рядом с ним. Чтобы заменить сохранённые учётные данные для совпадающих аккаунтов, используйте `omarchy agent account copy --replace laptop claude`, предварительно завершив сессии этого аккаунта на пункте назначения. Свежий пункт назначения также получает активный аккаунт источника и предпочтения переключения; устоявшийся пункт назначения сохраняет свои собственные.

Учётные данные перемещаются через SSH и хранятся в приватных файлах на пункте назначения, поэтому копируйте только на машины, которым вы доверяете. Это одноразовая копия, а не постоянная синхронизация. Токены обновления Codex могут быть ротированы другой машиной, из-за чего скопированный вход будет нуждаться в обновлении; отдельные входы остаются самым надёжным выбором для одновременного использования на нескольких машинах. См. [руководство Codex по аутентификации аккаунтов](https://developers.openai.com/codex/auth/ci-cd-auth).

Один аккаунт на провайдера активен, и каждая новая сессия начинается с него: `cx`, `cy`, обычный `claude`, `codex` или `grok`, всё, что запущено через `omarchy agent`, а также скрипты или редакторы, которые находят CLI в `PATH`. Переключайтесь командой `omarchy agent account use work` (и обратно командой `omarchy agent account use main`) или на панели, нажав номер аккаунта, а затем `Enter` (или щёлкнув его звёздочку). Запущенные сессии Claude тоже переключаются, со следующего сообщения: каждая сессия Claude работает в `~/.claude`, где всегда хранится вход активного аккаунта. Сессия Claude, запущенная в собственной папке аккаунта более старой версией Omarchy, хранит этот вход до своего завершения, поэтому переключатель называет эти сессии и завершается сам, как только они исчезнут. Запущенные сессии Codex и Grok остаются на аккаунте, с которого они стартовали. История разговоров, настройки, навыки и плагины являются общими для всех аккаунтов, поэтому `claude --continue` в той же папке продолжит с того места, где вы остановились, на новом аккаунте.

При наличии нескольких аккаунтов панель показывает лимиты каждого аккаунта рядом, с заполненной звёздочкой на используемом. Omarchy уведомляет вас, когда активный аккаунт превышает 95% лимита, и щелчок по уведомлению переключает на аккаунт с наибольшим запасом. Он никогда не переключается сам по себе. Измените порог командой `omarchy agent account threshold 90`. Если каждый аккаунт превышает порог, вы услышите об этом один раз, вместе с информацией о том, какой аккаунт освободится первым. Пока активный аккаунт находится в пределах 15 пунктов от своего порога (80% при значении по умолчанию), его лимиты проверяются каждые три минуты, а не каждые 15.

`omarchy agent account list` показывает каждый аккаунт и его последние лимиты, `omarchy agent account remove work` забывает один, а `omarchy agent account rename primary Hey` переименовывает один (или щёлкните имя аккаунта на панели). Эти команды работают с аккаунтами вашего агента по умолчанию; чтобы обратиться к другому провайдеру, сначала назовите его, как в `omarchy agent account use codex side`. Вход, который у вас уже был в `~/.claude` или `~/.codex`, — это аккаунт _Main_. У Codex он остаётся там, где был; у Claude он ждёт в собственной папке, пока активен другой аккаунт. Аккаунт, не использовавшийся более примерно восьми часов, может показывать _Sign-in required_; щёлкните его, чтобы снова войти в этот аккаунт прямо на панели, или переключитесь на него и начните сессию, которая обновит вход сама по себе. MCP-серверы, которые вы добавляете командой `claude mcp add`, доступны каждому аккаунту Claude, поскольку все они работают в `~/.claude`; для Codex и Grok серверы, которые у вас были, когда аккаунт был добавлен, переходят вместе с ним, но более поздние доступны только тому аккаунту, в котором вы их добавили. Claude Desktop хранит собственный вход, а инструменты Codex или Grok, настроенные с абсолютным путём к бинарному файлу CLI, не следуют за переключением. Явный `CLAUDE_CONFIG_DIR`, `CODEX_HOME` или `GROK_HOME` имеет приоритет над выбранным аккаунтом.

### Диагностика сбоев

Omarchy следит за systemd-coredump на предмет сбоев процессов. Как только вы выбрали агента по умолчанию, любая ваша программа, сбрасывающая core, вызывает уведомление "Process crashed" — щёлкните его, и сбой будет передан вашему агенту по умолчанию вместе с навыком Omarchy omarchy-diagnose-crash, который проводит агента через установление фактов из дампа ядра и принятие решения, стоит ли сообщать о сбое в upstream. Вы также можете запустить его вручную для любого PID из `coredumpctl list` командой `omarchy agent crash <pid>`.

Отслеживание включено по умолчанию. Отключите его в разделе _Trigger > Toggle > Crash Capture Off_ (или командой `omarchy toggle crash-capture`), и уведомления прекратятся; `omarchy agent crash <pid>` по-прежнему работает вручную.

Сбои также можно заглушить по одной программе за раз, что диагностика и предлагает вам в конце. `omarchy crash mute hyprland` останавливает уведомления только для этой программы, `omarchy crash mute hyprland off` возвращает их, а `omarchy crash mute` сам по себе перечисляет то, что вы заглушили. Он принимает путь к бинарному файлу так же охотно, как и его имя, поэтому `omarchy crash mute /usr/bin/hyprland` делает то же самое. Заключайте имя с пробелом в кавычки, как в `omarchy crash mute 'Some App'`. Всё остальное по-прежнему уведомляет, а заглушённая программа по-прежнему падает — это скрывает напоминание, а не исправляет что-либо.

### Настольные приложения

_Install > AI > Desktop_ содержит графические приложения ИИ: Amp Desktop, Antigravity Desktop, десктопное приложение ChatGPT, десктопное приложение Claude (бета-версия Anthropic для Linux, с вкладками Chat, Cowork и Claude Code), Grok Bot для общения с моделями xAI, Herdr Desktop, Hermes Desktop, OpenClaw, десктопное приложение Perplexity и T3 Code. Grok Bot — это десктопное приложение для чата. Агент для программирования — это команда `grok`.

Hermes Desktop — это то, о чём стоит знать, потому что на машине один Hermes, и он принадлежит приложению: Hermes устанавливается только через приложение, и команда `hermes`, которую запускает агент по умолчанию, принадлежит приложению. Выбор Hermes в качестве агента по умолчанию устанавливает то же самое, что и пункт _Install > AI > Desktop_: пакет и среду выполнения Hermes в `~/.hermes`, настроенную собственным установщиком Hermes, что занимает несколько минут в первый раз. Эта среда выполнения — тот единственный Hermes, который используют терминальная команда `hermes`, агент по умолчанию и приложение, и он обновляет сам себя командой `hermes update`, а не ждёт релиза Omarchy. Установка также передаёт Hermes тему Omarchy в виде скина с именем `omarchy`, которому следует каждая поверхность Hermes при переключении тем; выберите другой в настройках Appearance в Hermes или командой `/skin`, если вы предпочитаете, чтобы он этого не делал, и Omarchy оставит этот выбор в покое. Удаление приложения в разделе _Remove > AI > Desktop_ сначала закрывает Hermes, включая шлюз, забирает эту среду выполнения с собой и сохраняет ваши чаты, воспоминания и навыки, которые Hermes написал для себя, если вы не скажете иначе: он спрашивает, по умолчанию отвечая «нет», должны ли эти данные и ваши настройки подключения также исчезнуть.

Десктопный опыт OpenClaw — это его Control UI, который открывается как веб-приложение, поддерживаемое его собственным локальным шлюзом. OpenClaw живёт в `~/.openclaw` и обновляет сам себя: используйте кнопку "Update Gateway" в Control UI или выполните `openclaw update`, и шлюз перезапустится на новой версии. Omarchy выбирает только релиз, с которого начинается свежая установка. OpenClaw также может быть вашим агентом по умолчанию: выбор его командой `omarchy default agent openclaw` устанавливает ту же копию в `~/.openclaw`, а агент открывает терминальный UI OpenClaw, подключённый к его шлюзу. Удаление OpenClaw в разделе _Remove > AI > Desktop_ забирает службу шлюза и приложение с собой, а затем спрашивает, должен ли `~/.openclaw` также исчезнуть, поскольку там хранятся ваши чаты и учётные данные вместе с самим OpenClaw и средами выполнения плагинов, которые он загружает; по умолчанию он сохраняется, и повторная установка OpenClaw подхватит его обратно.

Herdr Desktop — это десктопное приложение [Herdr](https://herdr.dev): пространства, вкладки и панели терминалов и агентов для программирования, которые продолжают работать в его ядре, когда вы закрываете окно. Оно поставляется из собственного установщика Herdr, а не из пакета, поэтому живёт в `~/.local/share/herdr-app`, приносит своё ядро в `~/.local/bin/herdr-core`, когда у вас его ещё нет, и обновляет и то, и другое само. Оно находится рядом с командой `herdr`, которую Omarchy поставляет на `Super + Ctrl + Return`, а не заменяет её, и получает прямые клавиши этой команды: `Alt + Return` и `Alt + Shift + Return` разделяют панель вниз или вправо, `Alt + Escape` закрывает её, `Ctrl + Alt + Arrow` перемещается между панелями, `Alt + 1..9` и `Alt + Left/Right` выбирают вкладку, а `Alt + Up/Down` перемещаются между пространствами. `Ctrl + 1..9` выбирает пространство, а `Alt + Shift + Up/Down` перемещается по агентам. Клавиши с префиксом `Ctrl + Space` остаются только для терминала, поскольку приложение не может удерживать обычную клавишу Ctrl для последовательности. Omarchy записывает их в `~/.config/herdr-app/keys.json`, а `omarchy-refresh-herdr-app` возвращает их обратно. При установке выбирается тема Omarchy для Herdr, которая с этого момента следует вашей теме Omarchy. Herdr хранит одну тему для светлого режима и одну для тёмного, поэтому после переключения между тёмной и светлой темой Omarchy выберите Omarchy в средстве выбора темы Herdr ещё раз для другого режима.

T3 Code работает из его официального релиза AppImage в `~/.local/share/t3code`, а не из пакета, поэтому он обновляет сам себя. При установке спрашивается, начинать ли на канале Stable или Nightly; переключите позже в настройках T3 Code. Ваши треды и настройки живут в `~/.t3`, а удаление T3 Code в разделе _Remove > AI > Desktop_ забирает их с собой.

### Локальные модели

Запустите открытую модель на своей собственной машине для ваших агентов для программирования. Ваши промпты и код остаются на машине; ничто из отправленного модели не покидает её. Начните с:

```bash
omarchy models use best text
```

Это настраивает лучшую текстовую модель для этой машины, ту, которую используют ваши агенты. У моделей изображений, видео и музыки есть своя лучшая: `omarchy models use best image`, `video` или `music`. Выполните `omarchy models use best`, чтобы увидеть выбор каждого типа для этой машины.

Или выберите + на панели агентов: в разделе _Use a local model_ перечислены все модели для программирования, которые подходят этой машине, рекомендованная — первой. Podman, который запускает модели, поставляется с Omarchy, как и контейнерный инструментарий NVIDIA на машине с NVIDIA, который даёт им GPU; если чего-то из этого не хватает, первая настройка устанавливает это. Затем Omarchy выбирает рекомендованную модель для этой машины, загружает её и запускает её. Ожидайте загрузки в десятки GB и использования большей части памяти машины, пока модель работает: Flash Next использует около 100 GiB при своём полном контексте 256K. Если другие модели занимают нужную ей память, она настраивается остановленной, готовой к запуску, как только вы остановите одну из них. Модель останавливается при выходе из системы; останавливайте её сами, когда вам нужна память для чего-то другого.

`omarchy models list` показывает варианты и объясняет, почему некоторые не подходят. Чтобы настроить другую, выполните `omarchy models use <recipe>`. Сегодня для машин Strix Halo с 128 GB доступны `qwen3.8-flash-next-gufo` и `qwen3.8-27b-gufo`; 27B занимает около 40 GiB, поэтому оставляет место для другой работы. На ноутбуке с 64 GB и Intel Arc B390 `qwen3.6-35b-a3b-llamacpp` работает примерно в 30 GiB. Новые рецепты и рекомендации поступают с `omarchy update`, через пакет.

Модель для программирования, которую вы добавляете, получает собственную строку на панели агентов, рядом с вашими подписками: play, чтобы запустить её, pause, чтобы остановить её и освободить её память, отметку Tailscale, чтобы поделиться ею с другими машинами в вашем tailnet, пока она работает, и кнопку терминала, чтобы открыть вашего агента на ней. Её строка показывает загрузку, запуск или остановку по мере выполнения и сообщает, когда не хватает свободной памяти для её запуска, или ссылается на её журналы, когда она остановилась с ошибкой. Несколько могут работать одновременно, когда они помещаются в память вместе. Нажмите Delete на выбранной строке, чтобы удалить модель с этой машины, вместе с загрузкой; + может настроить её снова. Модель для программирования, настроенная из терминала, ждёт под + до тех пор, пока вы её не добавите, как и модели, которые запускает машина, с которой вы выполнили сопряжение (`omarchy models pair <host>`).

Каждая настроенная вами модель для программирования также получает собственную запись в лаунчере приложений, под именем модели и с логотипом её создателя, так же, как вход в Claude, Codex или Grok добавляет такую запись. Она открывает вашего агента на этой модели и сначала запускает модель, если она не работает: терминал показывает её загрузку и передаёт управление агенту, как только она будет готова. Удаление модели удаляет её запись.

Не каждая модель предназначена для программирования. Модели изображений, видео и музыки открываются вместо этого в Fantasi, приложении Omarchy для создания картинок, видео и музыки с моделью, работающей на этой машине, и управляются там или командой `omarchy models`.

Модель продолжает работать ровно так, как она была настроена, поэтому обновление Omarchy никогда не перезапускает её под вашими агентами. Когда у Omarchy есть более новая среда выполнения или более новые веса для настроенной вами модели, её строка показывает кнопку обновления: нажмите её, и модель будет настроена снова в фоновом режиме, загружая только то, что изменилось, и перезапустится на новой версии. Модель, которая была остановлена, остаётся остановленной. `omarchy models update` делает то же самое для каждой модели из терминала.

Из командной строки `omarchy models start <recipe>` и `omarchy models stop <recipe>` делают то же самое, `omarchy models status` показывает каждую модель, а `omarchy agent --local-model <recipe>` открывает эту модель в pi, независимо от вашего агента по умолчанию. Чтобы сделать вашу локальную модель тем, что открывают горячая клавиша агента, консоль Quake и _Make something_, выполните `omarchy default agent local` или отметьте звёздочкой работающую модель на панели агентов. pi также перечисляет каждую настроенную вами модель, а также те, что на машинах, с которыми вы выполнили сопряжение, в своём собственном средстве выбора моделей, поэтому обычный `pi` также может к ним обращаться. Любой клиент, совместимый с OpenAI, тоже может подключиться: `status` показывает адрес каждой модели (первый — `http://127.0.0.1:11435/v1`), имя рецепта — это модель, а ключ находится в `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` удаляет модель и загрузки, которые не использует ни одна другая модель.

Сторонние среды выполнения помечены их издателем. Omarchy запускает каждую модель без доступа к сети.

### Локальные LLM

Omarchy рекомендует два способа запуска локальных моделей LLM: LM Studio и Ollama. LM Studio предоставляет GUI-интерфейс для поиска моделей с открытыми весами, их установки и запуска. Это отличный способ легко начать. Ollama предлагает CLI для аналогичных действий. Но если вы новичок в локальных моделях, я бы начал с LM Studio. Установите LM Studio из _Install > AI > Desktop_, а Ollama из _Install > AI > CLI_ в меню Omarchy.

### Навыки Omarchy

Навыки агентов помогают ИИ использовать конкретные инструменты конкретным способом, и Omarchy поставляет семь из них. Навык omarchy охватывает настройку системы под себя, например настройку вашей конфигурации Hyprland или регулировку панели. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app и omarchy-make-game охватывают создание чего-то нового, omarchy-contribute охватывает сообщение об ошибке или отправку исправления в upstream, а omarchy-diagnose-crash работает с дампом ядра сбоя. Они связаны символическими ссылками в каталоги навыков для Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` и каждый `~/.hermes/profiles/*/skills`), а также в общее расположение `~/.agents/skills`, поэтому большинство харнесов подхватывают их автоматически. Собственная папка навыка с тем же именем имеет приоритет.

Но вам следует относиться к этим навыкам как к экспериментальным. Разные модели будут использовать их с разным эффектом. Лучше сначала запускать в режиме планирования, чтобы у вас было представление о том, что агент хотел бы изменить. А затем будьте готовы откатить изменения или даже вызвать `omarchy reinstall configs`, если агент устроит во всём беспорядок.
