# ИИ

В Omarchy есть лаунчеры для перечисленных ниже агентов программирования, но агент по умолчанию за вас не выбирается. Запустите команду, чтобы при первом использовании установить её CLI, а затем пройдите аутентификацию, когда появится запрос. Hermes и OpenClaw — исключения: для них через mise ничего не устанавливается, а при выборе любого из них настраивается его собственная самообновляющаяся копия, как объясняется ниже в разделе _Настольные приложения_.

### Установка и обновление агентов

За исключением Hermes и OpenClaw, эти агенты используют ленивую установку mise: при первом запуске устанавливается CLI, а при последующих запусках он переиспользуется. mise также проверяет установленный агент на наличие нового релиза не чаще одного раза в четыре часа, непосредственно перед его запуском или в фоне в приглашении оболочки. Если это обновление не удаётся или вы офлайн, запускается установленная версия. `omarchy update` обновляет установленные агенты вместе с остальной частью Omarchy, а `mup` обновляет только инструменты, управляемые mise.

Собственное средство обновления агента, такое как `claude update`, `codex update` или кнопка обновления в приложении, не обновляет установку, управляемую mise. `codex update` завершается с ошибкой, а `claude update` может сообщить об успехе, установив при этом отдельную копию, которую mise не отслеживает. Если вы предпочитаете использовать родной установщик и средство обновления агента, добавьте его в `disable_tools`; см. [Предустановленные инструменты CLI](18-development-tools.md#preinstalled-cli-tools).

Чтобы установить все настроенные ленивые инструменты до того, как они вам понадобятся, запустите `mise install --include-lazy`. Сюда входят и другие инструменты CLI Omarchy по умолчанию, а также агенты. См. [Предустановленные инструменты CLI](18-development-tools.md#preinstalled-cli-tools) для установки одного инструмента или использования вашей собственной установки.

`grok` устанавливается через фирменный пакет mise `grok`, так же как `claude` и `codex`. Запустите `grok` или выберите его в _Agent > Harness_. Пропустите установщик `curl | bash` на x.ai. Этот путь помещает вторую копию в `~/.grok/bin`, ставит её первой в `PATH` и перезаписывает обёртку Omarchy.

`dsh` открывает свой браузерный UI на `127.0.0.1:3080`, а каталог запуска используется как его рабочее пространство по умолчанию. Его браузерный UI не принимает начальный промпт, поэтому `omarchy agent prompt` открывает его с промптом в вашем буфере обмена, чтобы вы могли вставить его. Omarchy запускает его с пресетом разрешений DeepSeek без одобрения. DeepSeek Harness загружает журналы сессий в DeepSeek, когда вы используете его официальный API моделей; отключите это в его браузерном UI в _Settings > General > Upload Session Log_. Отправляемая вами обратная связь также загружается вместе с сессией, если только вы не запустите его с `DSH_TELEMETRY_MODE=DISABLED`.

### Агент по умолчанию

Выберите агента по умолчанию с помощью `omarchy default agent <name>` или в _Agent > Harness_ в меню Omarchy (`Super + Space`). Если агент ещё не установлен, при выборе он сначала устанавливается, а также получает собственный лаунчер в лаунчере приложений, рядом с Agent. Свежая Omarchy предложит вам сделать этот выбор одноразовым уведомлением.

Выбор Claude также пытается настроить его расширение для браузера для Chromium, Chrome, Brave, Brave Origin и Edge. Настройка расширения применяется ко всем пользователям и может запросить ваш системный пароль; отмена или неудачная установка расширения всё равно выбирает и запускает Claude. Перезапустите браузер, включите расширение, если появится запрос, и войдите в Claude, чтобы завершить его подключение. Запустите `/chrome` в Claude, чтобы проверить соединение. Firefox и Zen не поддерживают это расширение. Если Claude уже был вашим агентом по умолчанию до добавления этой настройки, выберите его снова, чтобы установить расширение.

После того как вы сделали выбор, `Super + Shift + Ctrl + A` запускает агента по умолчанию в отдельном окне терминала (или вызывает средство выбора, если вы ещё не выбрали). Вы также можете запустить его сразу с задачей с помощью `omarchy agent prompt "Review this project"`. Freebuff и DeepSeek Harness не принимают начальный промпт, поэтому вместо этого они открываются с промптом в вашем буфере обмена для вставки. Агенты, запущенные таким образом, работают без присмотра в своих соответствующих режимах «не останавливайся, чтобы спросить», так что будьте готовы к тому, что они действительно будут что-то делать! У MiniMax Code нет такого режима для его интерактивных сессий, поэтому он запрашивает разрешения как обычно. А поскольку агенты отказываются запоминать доверие для вашего домашнего каталога, запуски из `$HOME` вместо этого начинаются в `~/Work`.

Есть и ярлыки терминала: `a` запускает агента по умолчанию прямо в текущем терминале, а `c`, `cx` и `cy` запускают OpenCode, Claude Code и Codex напрямую (опять же в их режимах с автоматическим одобрением). Смена темы также синхронизируется с агентами: Claude Code, Pi, OpenCode и Hermes (после того как Omarchy его установила) следуют за вами, когда вы переключаете тему Omarchy.

### Инструкции для вашего агента

Личные правила для каждого агента помещаются в `~/.agents/AGENTS.md`, рядом с общими навыками в `~/.agents/skills`. Откройте его в _Agent > Instructions_, который также связывает его с каждой оболочкой, хранящей собственный глобальный файл: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` у Copilot и так далее. Crush и Amp читают ссылку `~/.config/AGENTS.md`, а omp, Kimi и DeepSeek Harness читают `~/.agents/AGENTS.md` напрямую. Выбор агента по умолчанию также связывает его. Уже имевшийся у вас файл инструкций становится общим, если его ещё не было; в противном случае он сохраняется рядом со ссылкой как `.bak`. Запустите `omarchy agent instructions`, чтобы повторно связать после установки другого агента.

### Панель агентов

На верхней панели есть значок агентов. До того как вы настроите агента, его панель проведёт вас через вход в Claude, Codex или Grok, и первый из них станет вашим агентом по умолчанию. После этого панель размещает каждую подписку на одной странице: каждый агент и аккаунт с его планом, индикатор для каждого из его 5-часовых сессионных и недельных лимитов со временем до его сброса (наведите курсор, чтобы увидеть точный процент) или оставшийся предоплаченный баланс, под строкой, которая циклически показывает, что вы использовали по всем ним, например токены за эту неделю и вашу наиболее используемую модель. В разделе _Make something cool_ она предлагает стартовые промпты для новой темы, плагина, приложения или игры, которые передают задачу вашему агенту по умолчанию. Приложения создаются так же, как собственные Hype, Monologue и Omacut в Omarchy, на C++ и Qt Quick, следуя навыку агента omarchy-make-app, а нужные им компилятор и компоненты Qt поставляются установленными. Игры представляют собой одну страницу three.js в `~/Games/vibes`, следуя навыку агента omarchy-make-game, и все открываются из одного лаунчера Game Vibes в текущей теме; они загружают three.js из сети, поэтому для запуска им нужно соединение. Claude Code, Codex, Grok, Kimi, Cursor и его квота Grok Bot, GitHub Copilot, Muse, Antigravity и Devin покрываются из коробки со своими лимитами, Kimchi — со своим планом, предоплаченными кредитами и бюджетами расходов, а Hermes, Mistral Vibe и Qwen Code показывают свои сессии и токены после того, как вы ими воспользуетесь. Планы провайдеров и ключи, которые вы используете через pi, omp или opencode, также отображаются: OpenCode Zen и Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan и Synthetic со своими лимитами; OpenRouter и DeepSeek с их предоплаченными балансами; Fireworks с его расходами за последние 30 дней. Токены от моделей, которые вы запускаете на собственном оборудовании, также учитываются в итогах; у самих моделей есть собственная панель, описанная в разделе [Локальные модели](#local-models). Каждый агент учитывается один раз, по тому, кто выставляет за него счёт, независимо от того, через сколько оболочек вы им управляете.

Щёлкните левой кнопкой мыши по значку на панели или нажмите `Super + Ctrl + X`, чтобы открыть панель, щёлкните правой кнопкой, чтобы запустить агента по умолчанию, и средней кнопкой, чтобы обновить. Записи об использовании, лежащие в её основе, перегенерируются каждые 15 минут с помощью `omarchy agent usage update`, а панель может даже объединять использование с ваших других машин через синхронизируемую папку. Полные настройки см. в README в `$OMARCHY_PATH/shell/plugins/agents/`.

### Несколько подписок

Если вы платите за более чем один план Claude, Codex или Grok — например, личный Max и рабочий, — Omarchy может держать их все вошедшими и перемещаться между ними. Добавьте подписку с помощью + на панели агентов, которая проведёт вас через это прямо там, или с помощью `omarchy agent account add claude Work` (или `codex`, или `grok`). Она устанавливает CLI, если его нет. Первый аккаунт для провайдера входит через ваш обычный браузер, прямо там, где CLI всегда ищет. Каждый последующий входит через приватное окно, чтобы аккаунт, в который ваш браузер уже вошёл, не был подхвачен по ошибке; войдите там как аккаунт, который вы добавляете, и сначала закройте любое приватное окно, которое у вас уже открыто. Никогда не выходите из CLI для этого: выход отзывает сохранённый вход, и этот аккаунт придётся добавлять снова.

Чтобы скопировать входы по подпискам на другую машину Omarchy по SSH, запустите `omarchy agent account copy user@laptop`. Отправитель предоставляет временного получателя, когда на месте назначения он не установлен, поэтому более старые машины Omarchy могут получать аккаунты без обновления. Установленные получатели имеют приоритет. Это копирует все подписки Claude, Codex и Grok; добавьте имена провайдеров, чтобы выбрать их, как в `omarchy agent account copy laptop claude`. Имена аккаунтов и ID команд соответствуют источнику, включая аккаунты, уже присутствующие на месте назначения. Несвязанным аккаунтам места назначения при конфликте имён присваивается числовой суффикс, а настройки, навыки, плагины и история разговоров остаются локальными для каждой машины.

Существующие учётные данные места назначения сохраняются. Аккаунт источника, уже вошедший там, синхронизирует своё имя без замены его учётных данных; другие аккаунты добавляются рядом с ним. Чтобы заменить сохранённые учётные данные для совпадающих аккаунтов, используйте `omarchy agent account copy --replace laptop claude`, предварительно завершив сессии этого аккаунта на месте назначения. Свежее место назначения также получает активный аккаунт источника и предпочтения переключения; устоявшееся место назначения сохраняет свои собственные.

Учётные данные перемещаются через SSH и хранятся в приватных файлах на месте назначения, поэтому копируйте только на машины, которым вы доверяете. Это одноразовая копия, а не постоянная синхронизация. Токены обновления Codex могут быть ротированы другой машиной, из-за чего скопированному входу потребуется обновление; отдельные входы остаются самым надёжным выбором для одновременного использования на нескольких машинах. См. [руководство Codex по аутентификации аккаунтов](https://developers.openai.com/codex/auth/ci-cd-auth).

Один аккаунт на провайдера активен, и каждая новая сессия начинается как он: `cx`, `cy`, обычный `claude`, `codex` или `grok`, всё, что запускается через `omarchy agent`, а также скрипты или редакторы, которые находят CLI в `PATH`. Переключайтесь с помощью `omarchy agent account use work` (и обратно с помощью `omarchy agent account use main`) или на панели, нажав номер аккаунта, а затем `Enter` (или щёлкнув его кнопку Use). Запущенные сессии Claude тоже переключаются, со следующего сообщения: каждая сессия Claude работает в `~/.claude`, где всегда находится вход активного аккаунта. Сессия Claude, запущенная в собственной папке аккаунта более старой Omarchy, хранит этот вход до своего завершения, поэтому переключение называет эти сессии и завершается само, как только они исчезнут. Запущенные сессии Codex и Grok остаются на аккаунте, с которым они стартовали. История разговоров, настройки, навыки и плагины являются общими для всех аккаунтов, поэтому `claude --continue` в той же папке продолжит с того места, где вы остановились на новом аккаунте.

При наличии более одного аккаунта панель показывает лимиты каждого аккаунта рядом, с отмеченным активным. По умолчанию Omarchy уведомляет вас, когда активный аккаунт превышает 95% лимита, и щелчок по уведомлению переключает на аккаунт с наибольшим запасом. Наведите курсор на строку аккаунта на панели и щёлкните появившийся рядом с Use Autoswitch (или нажмите `m`), или запустите `omarchy agent account mode auto`, чтобы он переключался сам; пока это включено, Autoswitch занимает место Use, а повторный щелчок по нему возвращает к уведомлениям. Добавьте число, чтобы изменить порог, как в `omarchy agent account mode auto 90`. Если каждый аккаунт превышает порог, вы услышите об этом один раз, вместе с тем, какой аккаунт освободится первым. Пока активный аккаунт находится в пределах 15 пунктов от своего порога (80% по умолчанию), его лимиты проверяются каждые три минуты, а не каждые 15.

`omarchy agent account list` показывает каждый аккаунт и его последние лимиты, `omarchy agent account remove work` забывает один, а `omarchy agent account rename primary Hey` переименовывает один (или щёлкните имя аккаунта на панели). Эти команды работают с аккаунтами вашего агента по умолчанию; чтобы обратиться к другому провайдеру, сначала назовите его, как в `omarchy agent account use codex side`. Вход, который у вас уже был в `~/.claude` или `~/.codex`, является аккаунтом _Main_. У Codex он остаётся там, где был; у Claude он ждёт в собственной папке, пока активен другой аккаунт. Аккаунт, не использовавшийся более примерно восьми часов, может показывать _Sign-in required_; щёлкните его, чтобы снова войти в этот аккаунт прямо на панели, или переключитесь на него и начните сессию, которая обновит вход сама. MCP-серверы, которые вы добавляете с помощью `claude mcp add`, достигают каждого аккаунта Claude, поскольку все они работают в `~/.claude`; для Codex и Grok серверы, которые у вас были при добавлении аккаунта, переходят в него, но более поздние достигают только того аккаунта, в котором вы их добавили. Claude Desktop хранит собственный вход, а инструменты Codex или Grok, настроенные с абсолютным путём к бинарному файлу CLI, не следуют за переключением. Явный `CLAUDE_CONFIG_DIR`, `CODEX_HOME` или `GROK_HOME` имеет приоритет над выбранным аккаунтом.

### Диагностика сбоев

Omarchy следит за systemd-coredump на предмет сбоев процессов. После того как вы выбрали агента по умолчанию, любая ваша программа, которая сбрасывает core, вызывает уведомление "Process crashed" — щёлкните его, и сбой будет передан вашему агенту по умолчанию вместе с навыком omarchy-diagnose-crash в Omarchy, который проводит агента через установление фактов из дампа core и решение, стоит ли сообщать о сбое вверх по течению. Вы также можете запустить его вручную для любого PID из `coredumpctl list` с помощью `omarchy agent crash <pid>`.

Наблюдение включено по умолчанию. Отключите его в _Trigger > Toggle > Crash Capture Off_ (или с помощью `omarchy toggle crash-capture`), и уведомления прекратятся; `omarchy agent crash <pid>` по-прежнему работает вручную.

Сбои также можно заглушить по одной программе за раз, что диагностика и предлагает вам в конце. `omarchy crash mute hyprland` останавливает уведомления только для этой программы, `omarchy crash mute hyprland off` возвращает их, а `omarchy crash mute` сам по себе перечисляет то, что вы заглушили. Он принимает путь бинарного файла так же охотно, как и его имя, поэтому `omarchy crash mute /usr/bin/hyprland` делает то же самое. Заключите имя с пробелом в кавычки, как в `omarchy crash mute 'Some App'`. Всё остальное по-прежнему уведомляет, а заглушённая программа по-прежнему падает — это скрывает напоминание, а не чинит что-либо.

### Настольные приложения

Меню _Install > AI_ также содержит несколько графических приложений ИИ: Amp Desktop, Antigravity Desktop, настольное приложение ChatGPT, настольное приложение Claude (бета-версия Anthropic для Linux, с вкладками Chat, Cowork и Claude Code), Grok Bot для общения с моделями xAI, Herdr Desktop, Hermes Desktop, OpenClaw, настольное приложение Perplexity и T3 Code. Grok Bot — это настольное чат-приложение. Агент программирования — это команда `grok`.

Hermes Desktop — это то, о чём стоит знать, потому что на машине один Hermes, и он принадлежит приложению: Hermes устанавливается только через приложение, и команда `hermes`, которую запускает агент по умолчанию, принадлежит приложению. Выбор Hermes в качестве агента по умолчанию устанавливает то же самое, что и пункт _Install > AI_: пакет и среду выполнения Hermes в `~/.hermes`, настроенную собственным установщиком Hermes, что при первом разе занимает несколько минут. Эта среда выполнения — тот единственный Hermes, который используют терминальная команда `hermes`, агент по умолчанию и приложение, и она обновляет себя с помощью `hermes update`, а не ждёт релиза Omarchy. При установке она также передаёт Hermes тему Omarchy в виде скина с именем `omarchy`, которому следует каждая поверхность Hermes при переключении тем; выберите другой в настройках Appearance в Hermes или с помощью `/skin`, если вы предпочитаете, чтобы этого не было, и Omarchy оставит этот выбор в покое. Удаление приложения в _Remove > AI_ сначала закрывает Hermes, включая шлюз, уносит с собой эту среду выполнения и сохраняет ваши чаты, воспоминания и навыки, которые Hermes написал для себя, если вы не скажете иначе: оно спрашивает, по умолчанию — нет, должны ли эти данные и ваши настройки подключения также уйти.

Настольный опыт OpenClaw — это его Control UI, который открывается как веб-приложение, поддерживаемое его собственным локальным шлюзом. OpenClaw живёт в `~/.openclaw` и обновляет себя: используйте кнопку "Update Gateway" в Control UI или запустите `openclaw update`, и шлюз перезапустится на новой версии. Omarchy выбирает только релиз, с которого начинается свежая установка. OpenClaw также может быть вашим агентом по умолчанию: выбор его в _Agent > Harness_ настраивает ту же копию в `~/.openclaw`, а агент открывает терминальный UI OpenClaw, подключённый к его шлюзу. Удаление OpenClaw в _Remove > AI_ уносит с собой службу шлюза и приложение, а затем спрашивает, должен ли `~/.openclaw` также уйти, поскольку там хранятся ваши чаты и учётные данные вместе с самим OpenClaw и средами выполнения плагинов, которые он загружает; по умолчанию он сохраняется, и повторная установка OpenClaw подхватит его обратно.

Herdr Desktop — это настольное приложение [Herdr](https://herdr.dev): пространства, вкладки и панели терминалов и агентов программирования, которые продолжают работать в его ядре, когда вы закрываете окно. Оно происходит от собственного установщика Herdr, а не из пакета, поэтому оно живёт в `~/.local/share/herdr-app`, приносит своё ядро в `~/.local/bin/herdr-core`, когда у вас его ещё нет, и обновляет и себя, и его. Оно находится рядом с командой `herdr`, которую Omarchy поставляет на `Super + Ctrl + Return`, а не заменяет её, и получает прямые клавиши этой команды: `Alt + Return` и `Alt + Shift + Return` разделяют панель вниз или вправо, `Alt + Escape` закрывает её, `Ctrl + Alt + Arrow` перемещает между панелями, `Alt + 1..9` и `Alt + Left/Right` выбирают вкладку, а `Alt + Up/Down` перемещают между пространствами. `Ctrl + 1..9` выбирает пространство, а `Alt + Shift + Up/Down` проходит по агентам. Клавиши с префиксом `Ctrl + Space` остаются только для терминала, поскольку приложение не может удерживать обычную клавишу Ctrl для последовательности. Omarchy записывает их в `~/.config/herdr-app/keys.json`, а `omarchy-refresh-herdr-app` возвращает их обратно. При установке выбирается тема Omarchy в Herdr, которая с этого момента следует вашей теме Omarchy. Herdr хранит одну тему для светлого режима и одну для тёмного, поэтому после переключения между тёмной и светлой темой Omarchy ещё раз выберите Omarchy в средстве выбора темы Herdr для другого режима.

T3 Code запускается из своего официального релиза AppImage в `~/.local/share/t3code`, а не из пакета, поэтому он обновляет себя сам. При установке спрашивается, начинать ли на канале Stable или Nightly; позже переключитесь в настройках T3 Code. Ваши потоки и настройки живут в `~/.t3`, а удаление T3 Code в _Remove > AI_ уносит их с собой.

### Локальные модели

Запустите открытую модель на собственной машине для ваших агентов программирования. Ваши промпты и код остаются на машине; ничего из отправленного модели не покидает её. Начните с:

```bash
omarchy models use best text
```

Это настраивает лучшую текстовую модель для этой машины, ту, которую используют ваши агенты. У моделей изображений, видео и музыки есть своя лучшая: `omarchy models use best image`, `video` или `music`. Запустите `omarchy models use best`, чтобы увидеть выбор каждого вида для этой машины.

Или откройте панель локальных моделей с помощью её значка с блёстками на верхней панели, рядом со значком агентов, или с помощью Super + Ctrl + Alt + X, и выберите +. Значок появляется, когда модель подходит этой машине. Podman, который запускает модели, поставляется с Omarchy, как и контейнерный инструментарий NVIDIA на машине NVIDIA, который даёт им GPU; если чего-либо из них нет, первая настройка установит его. Затем Omarchy выбирает рекомендуемую модель для этой машины, загружает её и запускает. Ожидайте загрузку в десятки GB и использование большей части памяти машины во время работы модели: Flash Next использует около 100 GiB при полном контексте 256K. Если другие модели удерживают нужную ей память, она настраивается остановленной, готовой к запуску, как только вы остановите одну. Модель останавливается при выходе из системы; останавливайте её сами, когда вам нужна память для чего-то другого.

`omarchy models list` показывает варианты и объясняет, почему некоторые не подходят. Чтобы настроить другую, запустите `omarchy models use <recipe>`. Сегодня для машин Strix Halo со 128 GB доступны `qwen3.8-flash-next-gufo` и `qwen3.8-27b-gufo`; 27B занимает около 40 GiB, поэтому она оставляет место для другой работы. На ноутбуке с 64 GB и Intel's Arc B390 `qwen3.6-35b-a3b-llamacpp` работает примерно в 30 GiB. Новые рецепты и рекомендации поступают с `omarchy update`, через пакет.

Каждая настроенная вами модель получает собственную строку на панели локальных моделей: play — чтобы запустить её, pause — чтобы остановить её и освободить её память, и кнопка терминала — чтобы открыть вашего агента на ней. Вверху полоса показывает, как память машины разделена между самой Omarchy (системой и вашими приложениями), каждой работающей моделью и тем, что свободно. Наведите курсор на остановленную модель, и полоса покажет, подходит ли она или насколько ей не хватает. Несколько могут работать одновременно, когда они вместе помещаются в памяти; если одна не помещается, Omarchy говорит, какую работающую модель остановить. Перетаскивайте строки за их логотип, чтобы изменить их порядок, и нажмите Delete на выбранной строке, чтобы удалить модель и её загрузку.

Каждая настроенная вами модель также получает собственную запись в лаунчере приложений, под именем модели и с логотипом её создателя, так же как вход в Claude, Codex или Grok добавляет одну. Она открывает вашего агента на этой модели и сначала запускает модель, если она не работает: терминал показывает её загрузку и передаёт управление агенту, как только она будет готова. Удаление модели удаляет её запись.

Не каждая модель предназначена для программирования. Модели изображений, видео и музыки вместо этого открываются в Fantasi, приложении Omarchy для создания картинок, видео и музыки с моделью, работающей на этой машине, из их записи в лаунчере и из их строки на панели локальных моделей.

Модель продолжает работать точно так, как она была настроена, поэтому обновление Omarchy никогда не перезапускает её под вашими агентами. Когда у Omarchy есть более новая среда выполнения или более новые веса для настроенной вами модели, её строка показывает кнопку обновления: нажмите её, и модель будет настроена заново в фоне, загрузив только то, что изменилось, и перезапустится на новой версии. Модель, которая была остановлена, остаётся остановленной. `omarchy models update` делает то же самое для каждой модели из терминала.

Из командной строки `omarchy models start <recipe>` и `omarchy models stop <recipe>` делают то же самое, `omarchy models status` показывает каждую модель, а `omarchy agent --local` открывает вашего агента по умолчанию на последней запущенной вами модели. pi, OpenCode и Qwen Code могут использовать одну; при любом другом агенте по умолчанию она открывается в pi или в OpenCode, если у вас нет pi. pi также перечисляет каждую настроенную вами модель и те, что на машинах, с которыми вы выполнили сопряжение, в своём собственном средстве выбора модели, поэтому обычный `pi` также достигает их. Любой клиент, совместимый с OpenAI, также может подключиться: `status` показывает адрес каждой модели (первый — `http://127.0.0.1:11435/v1`), имя рецепта является моделью, а ключ находится в `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` удаляет модель и загрузки, которые не использует никакая другая модель.

Сторонние среды выполнения помечены их издателем. Omarchy запускает каждую модель без доступа к сети.

### Локальные LLM

Omarchy рекомендует два способа запуска локальных моделей LLM: LM Studio и Ollama. LM Studio предоставляет GUI-интерфейс для поиска моделей с открытыми весами, их установки и запуска. Это отличный способ легко начать. Ollama предлагает CLI для подобного. Но если вы новичок в локальных моделях, я бы начал с LM Studio. Вы можете установить любой из них в _Install > AI_ в меню Omarchy.

### Навыки Omarchy

Навыки агентов помогают ИИ использовать конкретные инструменты конкретным образом, и Omarchy поставляет семь из них. Навык omarchy охватывает настройку системы под себя, например настройку вашей конфигурации Hyprland или регулировку панели. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app и omarchy-make-game охватывают создание чего-то нового, omarchy-contribute охватывает сообщение об ошибке или отправку исправления вверх по течению, а omarchy-diagnose-crash работает с дампом core сбоя. Они связаны символическими ссылками в каталоги навыков для Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` и каждый `~/.hermes/profiles/*/skills`) и общее местоположение `~/.agents/skills`, поэтому большинство оболочек подхватывают их автоматически. Собственная папка навыка с тем же именем имеет приоритет.

Но вам следует относиться к этим навыкам как к экспериментальным. Разные модели будут использовать их с разным эффектом. Лучше сначала запускать в режиме планирования, чтобы у вас было представление о том, что агент хотел бы изменить. А затем будьте готовы откатить изменения или даже вызвать `omarchy reinstall configs`, если агент устроит во всём беспорядок.
