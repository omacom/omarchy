# AI

### Установка и обновление агентов

За исключением Hermes, эти агенты используют ленивую установку mise: при первом запуске устанавливается CLI, а при последующих запусках он используется повторно. mise также проверяет, не вышла ли новая версия установленного агента, не чаще одного раза в четыре часа, непосредственно перед его запуском или в фоновом режиме при приглашении оболочки. Если это обновление не удаётся или вы не в сети, запускается установленная версия. `omarchy update` обновляет установленных агентов вместе с остальной частью Omarchy, а `mup` обновляет только инструменты, управляемые mise.

Собственный механизм обновления агента, например `claude update`, `codex update` или кнопка обновления в приложении, не обновляет установку, управляемую mise. `codex update` завершается с ошибкой, а `claude update` может сообщить об успехе, установив при этом отдельную копию, которую mise не отслеживает. Если вы предпочитаете использовать собственный установщик и механизм обновления агента, добавьте его в `disable_tools`; см. [Preinstalled CLI tools](18-development-tools.md#preinstalled-cli-tools).

Чтобы установить все настроенные ленивые инструменты до того, как они вам понадобятся, запустите `mise install --include-lazy`. Это включает другие инструменты CLI Omarchy по умолчанию, а также агентов. См. [Preinstalled CLI tools](18-development-tools.md#preinstalled-cli-tools) об установке одного инструмента или использовании собственной установки.

`grok` устанавливается через официальный пакет `grok` в mise, так же, как `claude` и `codex`. Запустите `grok` или выберите его в меню _Agent > Harness_. Пропустите установщик `curl | bash` на x.ai. Этот путь помещает вторую копию в `~/.grok/bin`, ставит её первой на `PATH` и перезаписывает обёртку Omarchy.

`dsh` открывает свой браузерный интерфейс на `127.0.0.1:3080`, с каталогом запуска в качестве рабочего пространства по умолчанию. Его браузерный интерфейс не принимает стартовый промпт, поэтому `omarchy agent prompt` открывает его с промптом в буфере обмена для вставки. Omarchy запускает его с пресетом разрешений без одобрения от DeepSeek. DeepSeek Harness загружает журналы сессий в DeepSeek, когда вы используете его официальный API моделей; отключите это в его браузерном интерфейсе в разделе _Settings > General > Upload Session Log_. Отправляемая вами обратная связь также загружается вместе с сессией, если только вы не запустите его с `DSH_TELEMETRY_MODE=DISABLED`.

### Агент по умолчанию

Выберите агента по умолчанию с помощью `omarchy default agent <name>` или в меню _Agent > Harness_ в меню Omarchy (`Super + Space`). Если агент ещё не установлен, при его выборе он сначала установится. Свежая установка Omarchy предложит вам сделать этот выбор с помощью одноразового уведомления.

При выборе Claude также предпринимается попытка настроить его расширение для браузера для Chromium, Chrome, Brave, Brave Origin и Edge. Настройка расширения применяется ко всем пользователям и может запросить ваш системный пароль; отмена или неудачная установка расширения всё равно выбирает и запускает Claude. Перезапустите браузер, включите расширение, если появится запрос, и войдите в Claude, чтобы завершить его подключение. Запустите `/chrome` в Claude, чтобы проверить соединение. Firefox и Zen не поддерживают это расширение. Если Claude уже был вашим агентом по умолчанию до добавления этой настройки, выберите его снова, чтобы установить расширение.

После того как вы сделали выбор, `Super + Shift + Ctrl + A` запускает агента по умолчанию в отдельном окне терминала (или открывает средство выбора, если вы ещё не сделали выбор). Вы также можете запустить его сразу с задачей с помощью `omarchy agent prompt "Review this project"`. Freebuff и DeepSeek Harness не принимают стартовый промпт, поэтому вместо этого они открываются с промптом в буфере обмена для вставки. Агенты, запущенные таким образом, работают без присмотра в своих соответствующих режимах «не останавливайся, чтобы спрашивать», поэтому будьте готовы к тому, что они действительно будут что-то делать! У MiniMax Code нет такого режима для интерактивных сессий, поэтому он запрашивает разрешения как обычно. А поскольку агенты отказываются запоминать доверие для вашего домашнего каталога, запуски из `$HOME` вместо этого начинаются в `~/Work`.

Есть и ярлыки в терминале: `a` запускает агента по умолчанию прямо в текущем терминале, а `c`, `cx` и `cy` запускают напрямую OpenCode, Claude Code и Codex (снова в их режимах с автоматическим одобрением). Изменения темы также синхронизируются с агентами: Claude Code, Pi, OpenCode и Hermes (после того как Omarchy его установила) следуют за вами при смене темы Omarchy.

### Ваши инструкции для агентов

Личные правила для каждого агента находятся в `~/.agents/AGENTS.md`, рядом с общими навыками в `~/.agents/skills`. Откройте его в меню _Agent > Instructions_, которое также связывает его с каждой оболочкой, хранящей собственный глобальный файл: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` у Copilot и так далее. Crush и Amp читают ссылку `~/.config/AGENTS.md`, а omp, Kimi и DeepSeek Harness читают `~/.agents/AGENTS.md` напрямую. При выборе агента по умолчанию он также связывается. Уже имевшийся у вас файл инструкций становится общим, если его ещё не было; в противном случае он сохраняется рядом со ссылкой как `.bak`. Запустите `omarchy agent instructions`, чтобы повторно создать ссылки после установки другого агента.

### Панель агентов

В верхней панели есть значок агентов. До того как вы настроите агента, его панель проведёт вас через вход в Claude, Codex или Grok, и первый из них станет вашим агентом по умолчанию. После этого панель размещает каждую подписку на одной странице: каждый агент и аккаунт с его планом, индикатор для каждого из его 5-часовых сессионных и недельных лимитов со временем до его сброса (наведите курсор, чтобы увидеть точный процент) или остаток предоплаченного баланса, под строкой, которая по кругу показывает, что вы использовали по всем ним, например токены за эту неделю и вашу самую используемую модель. В разделе _Make something_ она предлагает стартовые промпты для новой темы, плагина, приложения или игры, которые передают задачу вашему агенту по умолчанию. Приложения создаются так же, как собственные приложения Omarchy Hype, Monologue и Omacut, на C++ и Qt Quick, следуя навыку агента omarchy-app, и нужные им компилятор и компоненты Qt уже установлены. Игры представляют собой одну страницу three.js в `~/Games/vibes`, следующую навыку агента web-game, и все открываются из одного запускатора Game Vibes в текущей теме; они загружают three.js из сети, поэтому для запуска им нужно соединение. Claude Code, Codex, Grok, Kimi, Cursor и его лимит Grok Bot, GitHub Copilot, Muse, Antigravity, Kimchi и Devin поддерживаются из коробки со своими лимитами, а Hermes, Mistral Vibe и Qwen Code показывают свои сессии и токены после того, как вы ими воспользуетесь. Планы провайдеров и ключи, которые вы используете через pi, omp или opencode, также отображаются: OpenCode Zen и Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan и Synthetic со своими лимитами; Fireworks, OpenRouter и DeepSeek со своими предоплаченными балансами; и модели, которые вы запускаете на собственном оборудовании, в разделе Local models. Каждый агент учитывается один раз, у того, кто выставляет за него счёт, независимо от того, через сколько оболочек вы им управляете.

Щёлкните левой кнопкой мыши по значку на панели, чтобы открыть панель, щёлкните правой кнопкой, чтобы запустить агента по умолчанию. Записи об использовании, лежащие в её основе, обновляются каждые 15 минут с помощью `omarchy agent usage-update`, и панель может даже объединять использование с других ваших машин через синхронизируемую папку. См. README в `$OMARCHY_PATH/shell/plugins/agents/` для всех настроек.

### Несколько подписок

Если вы платите за несколько планов Claude, Codex или Grok — например, личный Max и рабочий, — Omarchy может держать их все вошедшими в систему и переключаться между ними. Добавьте подписку с помощью + на панели агентов, которая проведёт вас через это прямо там, или с помощью `omarchy agent account add claude Work` (или `codex`, или `grok`). При необходимости она установит CLI. Первый аккаунт для провайдера входит через ваш обычный браузер, прямо там, где CLI всегда его ищет. Каждый следующий после этого входит через приватное окно, чтобы аккаунт, в который ваш браузер уже вошёл, не был подхвачен по ошибке; войдите там как аккаунт, который вы добавляете, и сначала закройте любое уже открытое приватное окно. Никогда не выходите из CLI для этого: выход отзывает сохранённый вход, и этот аккаунт придётся добавлять снова.

Чтобы скопировать входы по подпискам на другую машину с Omarchy по SSH, запустите `omarchy agent account copy user@laptop`. Отправитель предоставляет временный получатель, когда на месте назначения он не установлен, поэтому более старые машины с Omarchy могут получать аккаунты без обновления. Установленные получатели имеют приоритет. Это копирует все подписки Claude, Codex и Grok; добавьте имена провайдеров, чтобы выбрать их, как в `omarchy agent account copy laptop claude`. Имена аккаунтов и ID команд соответствуют источнику, включая аккаунты, уже присутствующие в месте назначения. Несвязанным аккаунтам в месте назначения при конфликте имён добавляется числовой суффикс, а настройки, навыки, плагины и история разговоров остаются локальными для каждой машины.

Существующие учётные данные в месте назначения сохраняются. Аккаунт источника, уже вошедший там, получает синхронизацию своего имени без замены его учётных данных; другие аккаунты добавляются рядом с ним. Чтобы заменить сохранённые учётные данные для совпадающих аккаунтов, используйте `omarchy agent account copy --replace laptop claude` после завершения сессий этого аккаунта в месте назначения. Свежее место назначения также получает активный аккаунт источника и его предпочтения по переключению; устоявшееся место назначения сохраняет свои собственные.

Учётные данные передаются через SSH и хранятся в приватных файлах в месте назначения, поэтому копируйте только на машины, которым вы доверяете. Это одноразовая копия, а не постоянная синхронизация. Токены обновления Codex могут быть ротированы другой машиной, из-за чего скопированный вход будет нуждаться в обновлении; отдельные входы остаются самым надёжным выбором для одновременного использования на нескольких машинах. См. [Codex's account authentication guidance](https://developers.openai.com/codex/auth/ci-cd-auth).

Один аккаунт на провайдера активен, и каждая новая сессия начинается как он: `cx`, `cy`, обычный `claude`, `codex` или `grok`, всё, что запущено через `omarchy agent`, и скрипты или редакторы, которые находят CLI на `PATH`. Переключайтесь с помощью `omarchy agent account use work` (и обратно с помощью `omarchy agent account use main`) или на панели, нажав номер аккаунта, а затем `Enter` (или нажав его кнопку Use). Запущенные сессии Claude тоже переключаются, со следующего сообщения: каждая сессия Claude работает в `~/.claude`, который всегда содержит вход активного аккаунта. Сессия Claude, запущенная в собственной папке аккаунта более старой версией Omarchy, сохраняет этот вход до своего завершения, поэтому переключение называет эти сессии и завершается само по себе, как только они исчезнут. Запущенные сессии Codex и Grok остаются на аккаунте, с которым они стартовали. История разговоров, настройки, навыки и плагины являются общими для аккаунтов, поэтому `claude --continue` в той же папке продолжит с того места, где вы остановились на новом аккаунте.

При наличии более чем одного аккаунта панель показывает лимиты каждого аккаунта рядом, при этом активный отмечен. По умолчанию Omarchy уведомляет вас, когда активный аккаунт превышает 95% лимита, и нажатие на уведомление переключает на аккаунт с наибольшим запасом. Наведите курсор на строку аккаунта на панели и нажмите Autoswitch, который появляется рядом с Use (или нажмите `m`), или запустите `omarchy agent account mode auto`, чтобы он переключался сам; пока это включено, Autoswitch занимает место Use, и повторное нажатие на него возвращает к уведомлениям. Добавьте число, чтобы изменить порог, как в `omarchy agent account mode auto 90`. Если каждый аккаунт превышает порог, вы услышите об этом один раз, вместе с тем, какой аккаунт освободится первым. Пока активный аккаунт находится в пределах 15 пунктов от своего порога (80% по умолчанию), его лимиты проверяются каждые три минуты, а не каждые 15.

`omarchy agent account list` показывает каждый аккаунт и его последние лимиты, `omarchy agent account remove work` забывает один, а `omarchy agent account rename primary Hey` переименовывает один (или нажмите на имя аккаунта на панели). Эти команды работают с аккаунтами вашего агента по умолчанию; чтобы обратиться к другому провайдеру, сначала укажите его имя, как в `omarchy agent account use codex side`. Вход, который у вас уже был в `~/.claude` или `~/.codex`, является аккаунтом _Main_. У Codex он остаётся на месте; у Claude он ждёт в собственной папке, пока активен другой аккаунт. Аккаунт, не использовавшийся более примерно восьми часов, может показывать _Sign-in required_; нажмите на него, чтобы снова войти в этот аккаунт прямо на панели, или переключитесь на него и начните сессию, что само по себе обновляет вход. MCP-серверы, которые вы добавляете с помощью `claude mcp add`, доступны каждому аккаунту Claude, поскольку все они работают в `~/.claude`; для Codex и Grok серверы, которые у вас были при добавлении аккаунта, переносятся на него, но более поздние доступны только тому аккаунту, в котором вы их добавили. Claude Desktop сохраняет собственный вход, а инструменты Codex или Grok, настроенные с абсолютным путём к бинарному файлу CLI, не следуют за переключением. Явно заданный `CLAUDE_CONFIG_DIR`, `CODEX_HOME` или `GROK_HOME` имеет приоритет над выбранным аккаунтом.

### Диагностика сбоев

Omarchy наблюдает за systemd-coredump на предмет сбоев процессов. Когда что-то сегфолтится, вы получите уведомление "Process crashed» — нажмите на него, и сбой будет передан вашему агенту по умолчанию вместе с навыком diagnose-crash от Omarchy, который проводит агента через установление фактов из дампа ядра и решение, стоит ли сообщать о сбое в upstream. Вы также можете запустить его вручную для любого PID из `coredumpctl list` с помощью `omarchy agent crash <pid>`.

Наблюдение включено по умолчанию. Отключите его в меню _Trigger > Toggle > Crash Capture_ (или с помощью `omarchy toggle crash-capture`), и уведомления прекратятся; `omarchy agent crash <pid>` по-прежнему работает вручную.

Сбои также можно заглушить по одной программе за раз, что диагностика и предлагает вам в конце. `omarchy crash mute hyprland` останавливает уведомления только для этой программы, `omarchy crash mute hyprland off` возвращает их, а `omarchy crash mute` сам по себе перечисляет, что вы заглушили. Он с одинаковой готовностью принимает путь к бинарному файлу, как и его имя, поэтому `omarchy crash mute /usr/bin/hyprland` делает то же самое. Заключите имя с пробелом в кавычки, как в `omarchy crash mute 'Some App'`. Всё остальное по-прежнему уведомляет, а заглушённая программа по-прежнему падает — это скрывает напоминание, а не чинит что-либо.

### Настольные приложения

Меню _Install > AI_ также содержит несколько графических приложений AI: настольное приложение ChatGPT, настольное приложение Claude (бета-версия Anthropic для Linux, с вкладками Chat, Cowork и Claude Code), Grok Bot для общения с моделями xAI, Herdr Desktop, Hermes Desktop, OpenClaw, настольное приложение Perplexity и T3 Code. Grok Bot — это настольное приложение для чата. Агент для программирования — это команда `grok`.

Hermes Desktop — это то, о чём нужно знать, потому что у машины один Hermes, и он принадлежит приложению: Hermes устанавливается только через приложение, и команда `hermes`, которую запускает агент по умолчанию, принадлежит приложению. Выбор Hermes в качестве агента по умолчанию устанавливает то же самое, что и пункт _Install > AI_: пакет и среду выполнения Hermes в `~/.hermes`, настроенную собственным установщиком Hermes, что в первый раз занимает несколько минут. Эта среда выполнения — тот единственный Hermes, который используют терминальная команда `hermes`, агент по умолчанию и приложение, и она обновляет себя с помощью `hermes update`, а не ждёт релиза Omarchy. При её установке Hermes также получает тему Omarchy в виде скина с именем `omarchy`, которому следует каждая поверхность Hermes при смене тем; выберите другой в настройках Appearance в Hermes или с помощью `/skin`, если вы предпочитаете, чтобы этого не было, и Omarchy оставит этот выбор в покое. При удалении приложения в меню _Remove > AI_ Hermes сначала закрывается, включая шлюз, среда выполнения удаляется вместе с ним, а ваши чаты, воспоминания и навыки, которые Hermes написал для себя, сохраняются, если вы не скажете обратное: оно спрашивает, по умолчанию — нет, должна ли эта информация и ваши настройки подключения также быть удалены.

Настольный опыт OpenClaw — это его Control UI, который открывается как веб-приложение, поддерживаемое собственным локальным шлюзом. OpenClaw живёт в `~/.openclaw` и обновляет себя сам: используйте кнопку "Update Gateway» в Control UI или запустите `openclaw update`, и шлюз перезапустится на новой версии. Omarchy выбирает только релиз, с которого начинается свежая установка. При удалении OpenClaw в меню _Remove > AI_ удаляются служба шлюза и приложение вместе с ним, а затем спрашивается, должен ли `~/.openclaw` также быть удалён, поскольку там хранятся ваши чаты и учётные данные вместе с самим OpenClaw и средами выполнения плагинов, которые он загружает; по умолчанию он сохраняется, и повторная установка OpenClaw снова его подхватит.

Herdr Desktop — это настольное приложение [Herdr](https://herdr.dev): пространства, вкладки и панели терминалов и агентов для программирования, которые продолжают работать в его ядре, когда вы закрываете окно. Оно поставляется собственным установщиком Herdr, а не пакетом, поэтому оно живёт в `~/.local/share/herdr-app`, при необходимости привозит своё ядро в `~/.local/bin/herdr-core`, когда у вас его ещё нет, и обновляет и то, и другое само. Оно находится рядом с командой `herdr`, которую Omarchy поставляет на `Super + Ctrl + Return`, а не заменяет её, и получает прямые клавиши этой команды: `Alt + Return` и `Alt + Shift + Return` разделяют панель вниз или вправо, `Alt + Escape` закрывает её, `Ctrl + Alt + Arrow` перемещает между панелями, `Alt + 1..9` и `Alt + Left/Right` выбирают вкладку, а `Alt + Up/Down` перемещают между пространствами. `Ctrl + 1..9` выбирает пространство, а `Alt + Shift + Up/Down` проходит по агентам. Клавиши с префиксом `Ctrl + Space` остаются только для терминала, поскольку приложение не может удерживать обычную клавишу Ctrl для последовательности. Omarchy записывает их в `~/.config/herdr-app/keys.json`, а `omarchy-refresh-herdr-app` возвращает их на место. При установке выбирается тема Omarchy для Herdr, которая с этого момента следует за вашей темой Omarchy. Herdr хранит одну тему для светлого режима и одну для тёмного, поэтому после переключения между тёмной и светлой темой Omarchy ещё раз выберите Omarchy в средстве выбора тем Herdr для другого режима.

T3 Code запускается из его официального релиза AppImage в `~/.local/share/t3code`, а не из пакета, поэтому он обновляет себя сам. При установке спрашивается, начинать ли на канале Stable или Nightly; переключайтесь позже в настройках T3 Code. Ваши треды и настройки живут в `~/.t3`, и при удалении T3 Code в меню _Remove > AI_ они удаляются вместе с ним.

### Локальные модели

Запустите открытую модель на своей машине для своих агентов для программирования. Ваши промпты и код остаются на машине; ничто, отправленное модели, не покидает её. Начните с:

```bash
omarchy agent local use best
```

Или на панели агентов в верхней панели выберите + и затем Local AI, который появляется, когда модель подходит для этой машины. В первый раз это устанавливает Podman, который запускает модели, а на машине с NVIDIA — инструментарий контейнеров NVIDIA, который даёт им GPU. Затем Omarchy выбирает рекомендованную модель для этой машины, загружает её и запускает. Ожидайте загрузку в десятки GB и использование большей части памяти машины во время работы модели: Flash Next использует около 100 GiB со своим полным контекстом 256K. Если другие модели удерживают нужную ей память, она настраивается остановленной, готовой к запуску, как только вы остановите одну из них. Модель останавливается при выходе из системы; остановите её сами, когда вам нужна память для чего-то другого.

`omarchy agent local list` показывает варианты и объясняет, почему некоторые не подходят. Чтобы настроить другой, запустите `omarchy agent local use <recipe>`. Сегодня `qwen3.8-flash-next-gufo` и `qwen3.8-27b-gufo` доступны для машин Strix Halo со 128 GB; модель 27B занимает около 40 GiB, поэтому оставляет место для другой работы. На ноутбуке с 64 GB и Intel Arc B390 `qwen3.6-35b-a3b-llamacpp` работает примерно в 30 GiB. Новые рецепты и рекомендации приходят с `omarchy update` через пакет.

Каждая настроенная вами модель получает собственную строку на панели агентов, рядом с вашими подписками: кнопка воспроизведения, чтобы запустить её, пауза, чтобы остановить её и освободить её память, и кнопка терминала, чтобы открыть вашего агента на ней. Несколько могут работать одновременно, когда они помещаются в память вместе; если одна не помещается, Omarchy говорит, какую работающую модель остановить. Перетаскивайте строки, чтобы изменить их порядок, и нажмите Delete на выбранной строке, чтобы удалить модель и её загрузку.

Каждая настроенная вами модель также получает собственную запись в запускаторе приложений, под именем модели и с логотипом её создателя, так же, как вход в Claude, Codex или Grok добавляет одну. Она открывает вашего агента на этой модели и сначала запускает модель, если она не работает: терминал показывает её загрузку и передаёт управление агенту, как только она будет готова. Удаление модели удаляет её запись.

Из командной строки `omarchy agent local start <recipe>` и `omarchy agent local stop <recipe>` делают то же самое, `omarchy agent local status` показывает каждую модель, а `omarchy agent --local` открывает вашего агента по умолчанию на последней запущенной вами модели. pi, OpenCode и Qwen Code могут использовать одну; при любом другом агенте по умолчанию она открывается в pi. pi также перечисляет каждую настроенную вами модель и те, что на машинах, с которыми вы связали свою, в своём собственном средстве выбора модели, поэтому обычный `pi` также может к ним обращаться. Любой клиент, совместимый с OpenAI, также может подключиться: `status` показывает адрес каждой модели (первый — `http://127.0.0.1:11435/v1`), имя рецепта — это модель, а ключ находится в `~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` удаляет модель и загрузки, которые не использует ни одна другая модель.

Сторонние среды выполнения помечены именем их издателя. Omarchy запускает каждую модель без доступа к сети.

### Локальные LLM

Omarchy рекомендует два способа запуска локальных моделей LLM: LM Studio и Ollama. LM Studio предоставляет GUI-интерфейс для поиска моделей с открытыми весами, их установки и запуска. Это отличный способ легко начать. Ollama предлагает CLI для того же самого. Но если вы новичок в локальных моделях, я бы начал с LM Studio. Вы можете установить любой из них в меню _Install > AI_ в меню Omarchy.

### Навык Omarchy

Навыки агентов помогают AI использовать конкретные инструменты конкретным способом, и Omarchy поставляется с навыком по умолчанию для настройки системы. Например, настройка конфигурации Hyprland, регулировка панели или даже создание новой темы с нуля. Он связан символической ссылкой в каталоги навыков для Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` и каждый `~/.hermes/profiles/*/skills`) и общее местоположение `~/.agents/skills`, поэтому большинство оболочек подхватывают его автоматически.

Но вам следует относиться к этому навыку как к экспериментальному. Разные модели будут использовать его с разным эффектом. Лучше сначала запускать его в режиме планирования, чтобы у вас было представление о том, что агент хотел бы изменить. А затем будьте готовы откатить изменения или даже выполнить `omarchy reinstall configs`, если агент всё испортит.
