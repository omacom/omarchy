# AI

Omarchy включает средства запуска для перечисленных ниже агентов программирования, не выбирая за вас вариант по умолчанию. Запустите команду, чтобы при первом использовании установить её CLI, а затем при появлении запроса пройдите аутентификацию. Hermes и OpenClaw — исключения: для них через mise ничего не устанавливается, а выбор любого из них настраивает его собственную самообновляющуюся копию, как объясняется ниже в разделе _Desktop apps_.

### Установка и обновление агентов

За исключением Hermes и OpenClaw, эти агенты используют ленивую установку mise: при первом запуске устанавливается CLI, а при последующих запусках он используется повторно. mise также проверяет, не вышла ли новая версия установленного агента, не чаще одного раза в четыре часа, непосредственно перед его запуском или в фоновом режиме при приглашении оболочки. Если это обновление не удаётся или вы не в сети, запускается установленная версия. `omarchy update` обновляет установленные агенты вместе с остальной частью Omarchy, а `mup` обновляет только инструменты, управляемые mise.

Собственное средство обновления агента, например `claude update`, `codex update` или кнопка обновления в приложении, не обновляет установку, управляемую mise. `codex update` завершается ошибкой, а `claude update` может сообщить об успехе, установив при этом отдельную копию, которую mise не отслеживает. Если вы предпочитаете использовать собственные установщик и средство обновления агента, добавьте его в `disable_tools`; см. [Предустановленные инструменты CLI](18-development-tools.md#preinstalled-cli-tools).

Чтобы установить все настроенные ленивые инструменты до того, как они вам понадобятся, запустите `mise install --include-lazy`. Сюда входят и другие инструменты CLI Omarchy по умолчанию, а также агенты. См. [Предустановленные инструменты CLI](18-development-tools.md#preinstalled-cli-tools), чтобы узнать, как установить один инструмент или использовать собственную установку.

`grok` устанавливается через фирменный пакет mise `grok`, так же, как `claude` и `codex`. Запустите `grok` или выберите его в _Agent > Harness_. Пропустите установщик `curl | bash` на x.ai. Этот путь помещает вторую копию в `~/.grok/bin`, ставит её первой в `PATH` и перезаписывает обёртку Omarchy.

`dsh` открывает свой интерфейс в браузере по адресу `127.0.0.1:3080`, используя каталог запуска в качестве рабочего пространства по умолчанию. Его интерфейс в браузере не принимает начальный запрос, поэтому `omarchy agent prompt` открывает его с запросом в вашем буфере обмена, чтобы вы могли его вставить. Omarchy запускает его с предустановкой разрешений DeepSeek без подтверждений. DeepSeek Harness загружает журналы сессий в DeepSeek, когда вы используете его официальный API моделей; отключите это в его интерфейсе в браузере в _Settings > General > Upload Session Log_. Отзывы, которые вы ему отправляете, также загружаются вместе с сессией, если только вы не запустите его с `DSH_TELEMETRY_MODE=DISABLED`.

### Агент по умолчанию

Выберите агента по умолчанию с помощью `omarchy default agent <name>` или в _Agent > Harness_ в меню Omarchy (`Super + Space`). Если агент ещё не установлен, при выборе он сначала устанавливается, а также получает собственное средство запуска в средстве запуска приложений, рядом с Agent. Свежая установка Omarchy предложит вам сделать этот выбор с помощью одноразового уведомления.

При выборе Claude также предпринимается попытка настроить его расширение для браузера для Chromium, Chrome, Brave, Brave Origin и Edge. Настройка расширения применяется ко всем пользователям и может запросить ваш системный пароль; отмена или неудачная установка расширения всё равно выбирает и запускает Claude. Перезапустите браузер, включите расширение при появлении запроса и войдите в Claude, чтобы завершить его подключение. Запустите `/chrome` в Claude, чтобы проверить соединение. Firefox и Zen не поддерживают это расширение. Если Claude уже был вашим агентом по умолчанию до добавления этой настройки, выберите его снова, чтобы установить расширение.

После того как вы сделали выбор, `Super + Shift + Ctrl + A` запускает агента по умолчанию в отдельном окне терминала (или вызывает средство выбора, если вы ещё не выбрали). Вы также можете запустить его сразу с задачей с помощью `omarchy agent prompt "Review this project"`. Freebuff и DeepSeek Harness не принимают начальный запрос, поэтому вместо этого они открываются с запросом в вашем буфере обмена, чтобы вы могли его вставить. Агенты, запущенные таким способом, работают без присмотра в своих соответствующих режимах «не останавливайся, чтобы спросить», так что будьте готовы к тому, что они действительно будут что-то делать! У MiniMax Code нет такого режима для его интерактивных сессий, поэтому он запрашивает разрешения как обычно. А поскольку агенты отказываются запоминать доверие для вашего домашнего каталога, запуски из `$HOME` вместо этого начинаются в `~/Work`.

Есть и сочетания в терминале: `a` запускает агента по умолчанию прямо в текущем терминале, а `c`, `cx` и `cy` запускают непосредственно OpenCode, Claude Code и Codex (снова в их режимах с автоматическим одобрением). Смены темы также синхронизируются с агентами: Claude Code, Pi, OpenCode и Hermes (после того как Omarchy его установил) следуют за вами, когда вы переключаете тему Omarchy.

### Инструкции для вашего агента

Личные правила для каждого агента находятся в `~/.agents/AGENTS.md`, рядом с общими навыками в `~/.agents/skills`. Откройте его в _Agent > Instructions_, который также связывает его с каждым харнессом, хранящим собственный глобальный файл: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` у Copilot и так далее. Crush и Amp читают ссылку `~/.config/AGENTS.md`, а omp, Kimi и DeepSeek Harness читают `~/.agents/AGENTS.md` напрямую. Выбор агента по умолчанию также связывает его. Файл инструкций, который у вас уже был, становится общим, если общего ещё не было; в противном случае он хранится рядом со ссылкой как `.bak`. Запустите `omarchy agent instructions`, чтобы повторно связать после установки ещё одного агента.

### Панель агентов

В верхней панели есть значок агентов. До того как вы настроите агента, его панель проведёт вас через вход в Claude, Codex или Grok, и первый из них станет вашим агентом по умолчанию. После этого панель размещает каждую подписку на одной странице: каждый агент и учётная запись с её планом, индикатор для каждого из её 5-часовых сессионных и недельных лимитов со временем до его сброса (наведите курсор, чтобы увидеть точный процент) или остаток предоплаченного баланса, под строкой, которая по очереди показывает, что вы использовали по всем ним, например токены за эту неделю и вашу наиболее используемую модель. В разделе _Make something cool_ она предлагает стартовые запросы для новой темы, плагина, приложения или игры, которые передают задачу вашему агенту по умолчанию. Приложения создаются так же, как собственные Hype, Monologue и Omacut от Omarchy, на C++ и Qt Quick, следуя агентскому навыку omarchy-make-app, а компилятор и компоненты Qt, которые им нужны, уже установлены. Игры — это одна страница three.js в `~/Games/vibes`, следующая агентскому навыку omarchy-make-game, и все они открываются из одного средства запуска Game Vibes в текущей теме; они загружают three.js из сети, поэтому для запуска им нужно соединение. Claude Code, Codex, Grok, Kimi, Cursor и его лимит Grok Bot, GitHub Copilot, Muse, Antigravity и Devin поддерживаются из коробки с их лимитами, Kimchi с его планом, предоплаченными кредитами и бюджетами расходов, а Hermes, Mistral Vibe и Qwen Code показывают свои сессии и токены после того, как вы ими воспользуетесь. Планы и ключи провайдеров, которые вы используете через pi, omp или opencode, также отображаются: OpenCode Zen и Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan и Synthetic с их лимитами; OpenRouter и DeepSeek с их предоплаченными балансами; Fireworks с его расходами за последние 30 дней. Токены от моделей, которые вы запускаете на собственном оборудовании, также засчитываются в общие итоги; у самих моделей есть собственная панель, описанная в [Локальные модели](#local-models). Каждый агент учитывается один раз, у того, кто выставляет за него счёт, независимо от того, через сколько харнессов вы им управляете.

Щёлкните левой кнопкой мыши по значку в панели или нажмите `Super + Ctrl + X`, чтобы открыть панель, щёлкните правой кнопкой, чтобы запустить агента по умолчанию, и средней кнопкой, чтобы обновить. Записи об использовании, лежащие в её основе, перегенерируются каждые 15 минут с помощью `omarchy agent usage update`, а панель может даже объединять данные об использовании с ваших других машин через синхронизируемую папку. См. README в `$OMARCHY_PATH/shell/plugins/agents/` для всех настроек.

### Несколько подписок

Если вы платите более чем за один план Claude, Codex или Grok — например, личный Max и рабочий, — Omarchy может держать их всех вошедшими и переключаться между ними. Добавьте подписку с помощью + в панели агентов, которая проведёт вас через это прямо там, или с помощью `omarchy agent account add claude Work` (или `codex`, или `grok`). Она устанавливает CLI, если его нет. Первая учётная запись для провайдера входит через ваш обычный браузер, прямо там, где CLI всегда её ищет. Каждая следующая входит через приватное окно, чтобы учётная запись, в которую ваш браузер уже вошёл, не была случайно подхвачена; войдите там как учётная запись, которую вы добавляете, и сначала закройте любое уже открытое приватное окно. Никогда не выходите из CLI для этого: выход отзывает сохранённый вход, и эту учётную запись придётся добавлять снова.

Чтобы скопировать ваши входы по подпискам на другую машину Omarchy по SSH, запустите `omarchy agent account copy user@laptop`. Отправитель предоставляет временного получателя, когда на месте назначения он не установлен, поэтому старые машины Omarchy могут получать учётные записи без обновления. Установленные получатели имеют приоритет. Это копирует все подписки Claude, Codex и Grok; добавьте названия провайдеров, чтобы выбрать их, как в `omarchy agent account copy laptop claude`. Названия учётных записей и идентификаторы команд совпадают с источником, включая учётные записи, уже присутствующие на месте назначения. Несвязанным учётным записям на месте назначения при конфликте названий присваивается числовой суффикс, а настройки, навыки, плагины и история разговоров остаются локальными для каждой машины.

Существующие учётные данные на месте назначения сохраняются. Учётная запись источника, уже вошедшая там, синхронизирует своё название без замены её учётных данных; другие учётные записи добавляются рядом с ней. Чтобы заменить сохранённые учётные данные для совпадающих учётных записей, используйте `omarchy agent account copy --replace laptop claude` после закрытия сессий этой учётной записи на месте назначения. Свежее место назначения также получает активную учётную запись и предпочтения переключения источника; устоявшееся место назначения сохраняет свои собственные.

Учётные данные передаются через SSH и хранятся в приватных файлах на месте назначения, поэтому копируйте только на машины, которым вы доверяете. Это одноразовое копирование, а не постоянная синхронизация. Токены обновления Codex могут быть ротированы другой машиной, из-за чего скопированный вход будет нуждаться в обновлении; отдельные входы остаются самым надёжным выбором для одновременного использования на нескольких машинах. См. [Руководство Codex по аутентификации учётных записей](https://developers.openai.com/codex/auth/ci-cd-auth).

Одна учётная запись на провайдера активна, и каждая новая сессия начинается как она: `cx`, `cy`, обычный `claude`, `codex` или `grok`, всё, что запускается через `omarchy agent`, и скрипты или редакторы, которые находят CLI в `PATH`. Переключайтесь с помощью `omarchy agent account use work` (и обратно с помощью `omarchy agent account use main`) или в панели, нажав номер учётной записи, а затем `Enter` (или нажав её кнопку Use). Запущенные сессии Claude тоже переключаются, со следующего сообщения: каждая сессия Claude работает в `~/.claude`, который всегда хранит вход активной учётной записи. Сессия Claude, запущенная в собственной папке учётной записи более старой версией Omarchy, сохраняет этот вход до своего завершения, поэтому переключение называет эти сессии и завершается само, как только они исчезнут. Запущенные сессии Codex и Grok остаются на учётной записи, с которой они начали. История разговоров, настройки, навыки и плагины общие для всех учётных записей, поэтому `claude --continue` в той же папке продолжает с того места, где вы остановились на новой учётной записи.

При наличии более чем одной учётной записи панель показывает лимиты каждой учётной записи рядом, с отмеченной активной. По умолчанию Omarchy уведомляет вас, когда активная учётная запись превышает 95% лимита, и нажатие на уведомление переключает на учётную запись с наибольшим запасом. Наведите курсор на строку учётной записи в панели и нажмите Autoswitch, который появляется рядом с Use (или нажмите `m`), или запустите `omarchy agent account mode auto`, чтобы она переключалась сама; пока это включено, Autoswitch занимает место Use, и повторное нажатие на него возвращается к уведомлениям. Добавьте число, чтобы изменить порог, как в `omarchy agent account mode auto 90`. Если каждая учётная запись превышает порог, вы услышите об этом один раз, вместе с тем, какая учётная запись освободится первой. Пока активная учётная запись находится в пределах 15 пунктов от своего порога (80% при значении по умолчанию), её лимиты проверяются каждые три минуты, а не каждые 15.

`omarchy agent account list` показывает каждую учётную запись и её последние лимиты, `omarchy agent account remove work` забывает одну, а `omarchy agent account rename primary Hey` переименовывает одну (или нажмите на название учётной записи в панели). Эти команды работают с учётными записями вашего агента по умолчанию; чтобы обратиться к другому провайдеру, сначала назовите его, как в `omarchy agent account use codex side`. Вход, который у вас уже был в `~/.claude` или `~/.codex`, — это учётная запись _Main_. У Codex она остаётся там, где есть; у Claude она ждёт в собственной папке, пока активна другая учётная запись. Учётная запись, не использовавшаяся более примерно восьми часов, может показывать _Sign-in required_; нажмите на неё, чтобы снова войти в эту учётную запись прямо в панели, или переключитесь на неё и начните сессию, которая сама обновит вход. MCP-серверы, которые вы добавляете с помощью `claude mcp add`, достигают каждой учётной записи Claude, поскольку все они работают в `~/.claude`; для Codex и Grok серверы, которые у вас были, когда учётная запись была добавлена, переходят вместе с ней, но более поздние достигают только той учётной записи, в которой вы их добавили. Claude Desktop хранит собственный вход, а инструменты Codex или Grok, настроенные с абсолютным путём к бинарному файлу CLI, не следуют за переключением. Явный `CLAUDE_CONFIG_DIR`, `CODEX_HOME` или `GROK_HOME` имеет приоритет над выбранной учётной записью.

### Диагностика аварийных завершений

Omarchy следит за systemd-coredump на предмет сбоев процессов. После того как вы выберете агента по умолчанию, любая ваша программа, которая сбрасывает core, вызывает уведомление "Process crashed» — нажмите на него, и сбой будет передан вашему агенту по умолчанию вместе с навыком omarchy-diagnose-crash от Omarchy, который проводит агента через установление фактов из дампа ядра и решение, стоит ли сообщать о сбое вверх по цепочке. Вы также можете запустить его вручную для любого PID из `coredumpctl list` с помощью `omarchy agent crash <pid>`.

Наблюдение включено по умолчанию. Отключите его в _Trigger > Toggle > Crash Capture Off_ (или с помощью `omarchy toggle crash-capture`), и уведомления прекратятся; `omarchy agent crash <pid>` по-прежнему работает вручную.

Сбои также можно заглушить по одной программе за раз, что диагностика и предлагает вам в конце. `omarchy crash mute hyprland` останавливает уведомления только для этой программы, `omarchy crash mute hyprland off` возвращает их, а `omarchy crash mute` сам по себе перечисляет, что вы заглушили. Он принимает путь к бинарному файлу так же охотно, как и его название, поэтому `omarchy crash mute /usr/bin/hyprland` делает то же самое. Заключайте название с пробелом в кавычки, как в `omarchy crash mute 'Some App'`. Всё остальное по-прежнему уведомляет, а заглушенная программа по-прежнему падает — это скрывает напоминание, оно ничего не исправляет.

### Настольные приложения

Меню _Install > AI_ также содержит несколько графических приложений ИИ: Amp Desktop, Antigravity Desktop, настольное приложение ChatGPT, настольное приложение Claude (бета-версия Anthropic для Linux, с вкладками Chat, Cowork и Claude Code), Grok Bot для общения с моделями xAI, Herdr Desktop, Hermes Desktop, OpenClaw, настольное приложение Perplexity и T3 Code. Grok Bot — это настольное приложение для чата. Агент программирования — это команда `grok`.

Hermes Desktop — это то, о чём нужно знать, потому что на машине есть один Hermes, и он принадлежит приложению: Hermes устанавливается только через приложение, а команда `hermes`, которую запускает агент по умолчанию, принадлежит приложению. Выбор Hermes в качестве агента по умолчанию устанавливает то же, что и пункт _Install > AI_: пакет и среду выполнения Hermes в `~/.hermes`, настроенную собственным установщиком Hermes, что при первом разе занимает несколько минут. Эта среда выполнения — это тот единственный Hermes, который используют терминальная команда `hermes`, агент по умолчанию и приложение, и она обновляется сама с помощью `hermes update`, а не ждёт релиза Omarchy. При её установке Hermes также получает тему Omarchy в виде скина с названием `omarchy`, которому следует каждая поверхность Hermes при переключении тем; выберите другую в настройках Appearance у Hermes или с помощью `/skin`, если вы предпочитаете, чтобы этого не было, и Omarchy оставит этот выбор в покое. Удаление приложения в _Remove > AI_ сначала закрывает Hermes, включая шлюз, забирает эту среду выполнения с собой и сохраняет ваши чаты, воспоминания и навыки, которые Hermes написал для себя, если вы не скажете ему иное: оно спрашивает, по умолчанию отвечая «нет», должны ли эти данные и ваши настройки подключения также исчезнуть.

Настольный опыт OpenClaw — это его Control UI, который открывается как веб-приложение, поддерживаемое его собственным локальным шлюзом. OpenClaw живёт в `~/.openclaw` и обновляется сам: используйте кнопку "Update Gateway" в Control UI или запустите `openclaw update`, и шлюз перезапустится на новой версии. Omarchy выбирает только релиз, с которого начинается свежая установка. OpenClaw также может быть вашим агентом по умолчанию: выбор его в _Agent > Harness_ настраивает ту же копию в `~/.openclaw`, а агент открывает терминальный интерфейс OpenClaw, подключённый к его шлюзу. Удаление OpenClaw в _Remove > AI_ забирает службу шлюза и приложение с собой, а затем спрашивает, должен ли `~/.openclaw` также исчезнуть, поскольку там хранятся ваши чаты и учётные данные вместе с самим OpenClaw и средами выполнения плагинов, которые он загружает; по умолчанию он сохраняется, и повторная установка OpenClaw подхватит его обратно.

Herdr Desktop — это настольное приложение [Herdr](https://herdr.dev): пространства, вкладки и панели терминалов и агентов программирования, которые продолжают работать в его ядре, когда вы закрываете окно. Оно поставляется из собственного установщика Herdr, а не из пакета, поэтому оно живёт в `~/.local/share/herdr-app`, приносит своё ядро в `~/.local/bin/herdr-core`, когда у вас его ещё нет, и обновляет и себя, и его. Оно находится рядом с командой `herdr`, которую Omarchy поставляет на `Super + Ctrl + Return`, а не заменяет её, и получает прямые клавиши этой команды: `Alt + Return` и `Alt + Shift + Return` разделяют панель вниз или вправо, `Alt + Escape` закрывает её, `Ctrl + Alt + Arrow` перемещает между панелями, `Alt + 1..9` и `Alt + Left/Right` выбирают вкладку, а `Alt + Up/Down` перемещают между пространствами. `Ctrl + 1..9` выбирает пространство, а `Alt + Shift + Up/Down` проходит по агентам. Клавиши с префиксом `Ctrl + Space` остаются только для терминала, поскольку приложение не может удерживать обычную клавишу Ctrl для последовательности. Omarchy записывает их в `~/.config/herdr-app/keys.json`, а `omarchy-refresh-herdr-app` возвращает их на место. При его установке выбирается тема Omarchy для Herdr, которая с этого момента следует за вашей темой Omarchy. Herdr хранит одну тему для светлого режима и одну для тёмного, поэтому после переключения между тёмной и светлой темой Omarchy ещё раз выберите Omarchy в средстве выбора тем Herdr для другого режима.

T3 Code запускается из его официального релиза AppImage в `~/.local/share/t3code`, а не из пакета, поэтому он обновляется сам. При его установке спрашивается, начинать ли на канале Stable или Nightly; переключите позже в настройках T3 Code. Ваши треды и настройки живут в `~/.t3`, и удаление T3 Code в _Remove > AI_ забирает их с собой.

### Локальные модели

Запустите открытую модель на собственной машине для ваших агентов программирования. Ваши запросы и код остаются на машине; ничего из отправленного модели не покидает её. Начните с:

```bash
omarchy models use best text
```

Это настраивает лучшую текстовую модель для этой машины, ту, которую используют ваши агенты. У моделей изображений, видео и музыки есть своя лучшая: `omarchy models use best image`, `video` или `music`. Запустите `omarchy models use best`, чтобы увидеть выбор каждого вида для этой машины.

Или откройте панель локальных моделей с помощью её значка с блёстками в верхней панели, рядом со значком агентов, или с помощью Super + Ctrl + Alt + X, и выберите +. Значок появляется, когда модель подходит этой машине. Podman, который запускает модели, поставляется с Omarchy, как и контейнерный инструментарий NVIDIA на машине с NVIDIA, который даёт им GPU; если чего-то из этого нет, первая настройка устанавливает это. Затем Omarchy выбирает рекомендуемую модель для этой машины, загружает её и запускает. Ожидайте загрузку в десятки GB и использование большей части памяти машины во время работы модели: Flash Next использует около 100 GiB с его полным контекстом 256K. Если другие модели удерживают нужную ей память, она настраивается остановленной, готовой к запуску, как только вы остановите одну из них. Модель останавливается при выходе из системы; останавливайте её сами, когда вам нужна память для чего-то другого.

`omarchy models list` показывает варианты и объясняет, почему некоторые не подходят. Чтобы настроить другую, запустите `omarchy models use <recipe>`. Сегодня для машин Strix Halo со 128 GB доступны `qwen3.8-flash-next-gufo` и `qwen3.8-27b-gufo`; 27B занимает около 40 GiB, поэтому она оставляет место для другой работы. На ноутбуке с 64 GB и Intel Arc B390 `qwen3.6-35b-a3b-llamacpp` работает примерно в 30 GiB. Новые рецепты и рекомендации поступают с `omarchy update`, через пакет.

Каждая настроенная вами модель получает собственную строку в панели локальных моделей: кнопка воспроизведения, чтобы запустить её, кнопка паузы, чтобы остановить её и освободить её память, и кнопка терминала, чтобы открыть вашего агента на ней. Вверху полоса показывает, как память машины разделена между самой Omarchy (системой и вашими приложениями), каждой работающей моделью и тем, что свободно. Наведите курсор на остановленную модель, и полоса покажет, подходит ли она или насколько ей не хватает. Несколько могут работать одновременно, когда они вместе помещаются в памяти; если одна не помещается, Omarchy скажет, какую работающую модель остановить. Перетаскивайте строки за их логотип, чтобы изменить их порядок, и нажмите Delete на выбранной строке, чтобы удалить модель и её загрузку.

Каждая настроенная вами модель для программирования также получает собственную запись в средстве запуска приложений, под названием модели и с логотипом её создателя, так же, как вход в Claude, Codex или Grok добавляет такую запись. Она открывает вашего агента на этой модели и сначала запускает модель, если она не работает: терминал показывает её загрузку и передаёт управление агенту, как только она будет готова. Удаление модели удаляет её запись.

Не каждая модель предназначена для программирования. Модели изображений, видео и музыки вместо этого открываются в Fantasi, приложении Omarchy для создания картинок, видео и музыки с моделью, работающей на этой машине, выбранной там или из их строки в панели локальных моделей.

Модель продолжает работать точно так, как она была настроена, поэтому обновление Omarchy никогда не перезапускает её под вашими агентами. Когда у Omarchy есть более новая среда выполнения или более новые веса для настроенной вами модели, в её строке появляется кнопка обновления: нажмите её, и модель будет настроена снова в фоновом режиме, загружая только то, что изменилось, и перезапустится на новой версии. Модель, которая была остановлена, остаётся остановленной. `omarchy models update` делает то же самое для каждой модели из терминала.

Из командной строки `omarchy models start <recipe>` и `omarchy models stop <recipe>` делают то же самое, `omarchy models status` показывает каждую модель, а `omarchy agent --local` открывает вашего агента по умолчанию на последней запущенной вами модели. pi, OpenCode и Qwen Code могут использовать одну из них; при любом другом варианте по умолчанию она открывается в pi или в OpenCode, если у вас нет pi. pi также перечисляет каждую настроенную вами модель и те, что на машинах, с которыми вы выполнили сопряжение, в своём собственном средстве выбора моделей, поэтому обычный `pi` также добирается до них. Любой клиент, совместимый с OpenAI, также может подключиться: `status` показывает адрес каждой модели (первый — `http://127.0.0.1:11435/v1`), название рецепта — это модель, а ключ находится в `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` удаляет модель и загрузки, которые не использует никакая другая модель.

Сторонние среды выполнения помечены их издателем. Omarchy запускает каждую модель без доступа к сети.

### Локальные LLM

Omarchy рекомендует два способа запуска локальных моделей LLM: LM Studio и Ollama. LM Studio предоставляет графический интерфейс для поиска моделей с открытыми весами, их установки и запуска. Это отличный способ легко начать. Ollama предлагает CLI для того же самого похожим образом. Но если вы новичок в локальных моделях, я бы начал с LM Studio. Вы можете установить любой из них в _Install > AI_ в меню Omarchy.

### Навыки Omarchy

Агентские навыки помогают ИИ использовать конкретные инструменты конкретным способом, и Omarchy поставляет семь из них. Навык omarchy охватывает настройку системы под себя, например тонкую настройку вашей конфигурации Hyprland или регулировку панели. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app и omarchy-make-game охватывают создание чего-то нового, omarchy-contribute охватывает сообщение об ошибке или отправку исправления вверх по цепочке, а omarchy-diagnose-crash разбирает дамп ядра при сбое. Они связаны символическими ссылками в каталоги навыков для Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` и каждый `~/.hermes/profiles/*/skills`) и общее расположение `~/.agents/skills`, поэтому большинство харнессов подхватывают их автоматически. Собственная папка навыка с тем же названием имеет приоритет.

Но вам следует относиться к этим навыкам как к экспериментальным. Разные модели будут использовать их с разным эффектом. Лучше сначала запускать в режиме планирования, чтобы у вас было представление о том, что агент хотел бы изменить. А затем будьте готовы откатить изменения или даже вызвать `omarchy reinstall configs`, если агент всё испортит.
