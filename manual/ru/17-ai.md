# ИИ

Omarchy включает лаунчеры для перечисленных ниже агентов для программирования, не выбирая за вас вариант по умолчанию. Запустите команду, чтобы при первом использовании установить её CLI, а затем пройдите аутентификацию по запросу. Hermes и OpenClaw — исключения: для них через mise ничего не устанавливается, а выбор любого из них настраивает его собственную самообновляющуюся копию, как объясняется ниже в разделе _Настольные приложения_.

### Установка и обновление агентов

За исключением Hermes и OpenClaw, эти агенты используют ленивую установку mise: при первом запуске устанавливается CLI, а при последующих запусках он используется повторно. mise также проверяет установленный агент на наличие нового релиза не чаще одного раза в четыре часа, непосредственно перед его запуском или в фоне в приглашении оболочки. Если это обновление завершается неудачей или вы офлайн, запускается установленная версия. `omarchy update` обновляет установленные агенты вместе с остальной частью Omarchy, а `mup` обновляет только инструменты, управляемые mise.

Собственный инструмент обновления агента, такой как `claude update`, `codex update` или кнопка обновления в приложении, не обновляет установку, управляемую mise. `codex update` завершается неудачей, а `claude update` может сообщить об успехе, установив при этом отдельную копию, которую mise не отслеживает. Если вы предпочитаете использовать родной установщик и инструмент обновления агента, добавьте его в `disable_tools`; см. [Предустановленные инструменты CLI](18-development-tools.md#preinstalled-cli-tools).

Чтобы установить все настроенные ленивые инструменты до того, как они вам понадобятся, запустите `mise install --include-lazy`. Сюда входят и другие инструменты CLI Omarchy по умолчанию, а также агенты. См. [Предустановленные инструменты CLI](18-development-tools.md#preinstalled-cli-tools) для установки одного инструмента или использования собственной установки.

`grok` устанавливается через фирменный пакет `grok` от mise, так же как `claude` и `codex`. Запустите `grok` или выберите его в _Agent > Harness_. Пропустите установщик `curl | bash` на x.ai. Этот путь помещает вторую копию в `~/.grok/bin`, ставит её в начало `PATH` и перезаписывает обёртку Omarchy.

`dsh` открывает свой браузерный UI на `127.0.0.1:3080`, используя каталог запуска как рабочее пространство по умолчанию. Его браузерный UI не принимает начальный промпт, поэтому `omarchy agent prompt` открывает его с промптом в вашем буфере обмена, чтобы вы могли его вставить. Omarchy запускает его с пресетом разрешений без подтверждения от DeepSeek. DeepSeek Harness загружает журналы сессий в DeepSeek, когда вы используете его официальный API моделей; отключите это в его браузерном UI в _Settings > General > Upload Session Log_. Отправляемая вами обратная связь также загружается вместе с сессией, если только вы не запустите его с `DSH_TELEMETRY_MODE=DISABLED`.

### Агент по умолчанию

Выберите агента по умолчанию с помощью `omarchy default agent <name>` или в _Agent > Harness_ в меню Omarchy (`Super + Space`). Если агент ещё не установлен, при выборе он сначала устанавливается, а также получает собственный лаунчер в лаунчере приложений, рядом с Agent. Свежая Omarchy предложит вам сделать этот выбор с помощью однократного уведомления.

Выбор Claude также пытается настроить его расширение для браузера для Chromium, Chrome, Brave, Brave Origin и Edge. Настройка расширения применяется ко всем пользователям и может запросить ваш системный пароль; отмена или неудачная установка расширения всё равно выбирает и запускает Claude. Перезапустите ваш браузер, включите расширение, если будет предложено, и войдите в Claude, чтобы завершить его подключение. Запустите `/chrome` в Claude, чтобы проверить соединение. Firefox и Zen это расширение не поддерживают. Если Claude уже был вашим вариантом по умолчанию до добавления этой настройки, выберите его снова, чтобы установить расширение.

После того как вы сделали выбор, `Super + Shift + Ctrl + A` запускает агента по умолчанию в отдельном окне терминала (или вызывает средство выбора, если вы ещё не выбрали). Вы также можете запустить его сразу с задачей с помощью `omarchy agent prompt "Review this project"`. Freebuff и DeepSeek Harness не принимают начальный промпт, поэтому вместо этого они открываются с промптом в вашем буфере обмена для вставки. Агенты, запущенные таким образом, работают без присмотра в своих соответствующих режимах «не останавливайся, чтобы спросить», так что будьте готовы к тому, что они действительно будут что-то делать! У MiniMax Code такого режима для его интерактивных сессий нет, поэтому он запрашивает разрешения как обычно. А поскольку агенты отказываются запоминать доверие для вашего домашнего каталога, запуски из `$HOME` вместо этого начинаются в `~/Work`.

Есть и ярлыки в терминале: `a` запускает агента по умолчанию прямо в текущем терминале, а `c`, `cx` и `cy` запускают OpenCode, Claude Code и Codex напрямую (опять же в их режимах с автоматическим одобрением). Изменения темы также синхронизируются с агентами: Claude Code, Pi, OpenCode и Hermes (после того как Omarchy его установила) все следуют за вами, когда вы переключаете тему Omarchy.

### Ваши инструкции для агента

Личные правила для каждого агента находятся в `~/.agents/AGENTS.md`, рядом с общими навыками в `~/.agents/skills`. Откройте его в _Agent > Instructions_, который также связывает его с каждым харнессом, который хранит собственный глобальный файл: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` у Copilot и так далее. Crush и Amp читают ссылку `~/.config/AGENTS.md`, а omp, Kimi и DeepSeek Harness читают `~/.agents/AGENTS.md` напрямую. Выбор агента по умолчанию также связывает его. Уже имевшийся у вас файл инструкций становится общим, если такого ещё не было; в противном случае он сохраняется рядом со ссылкой как `.bak`. Запустите `omarchy agent instructions`, чтобы повторно связать после установки другого агента.

### Панель агентов

На верхней панели есть значок агентов. До того как вы настроите агента, его панель проведёт вас через вход в Claude, Codex или Grok, и первый из них станет вашим агентом по умолчанию. После этого панель размещает каждую подписку на одной странице: каждый агент и аккаунт с его планом, индикатор для каждого из его 5-часовых сессионных и недельных лимитов со временем до его сброса (наведите курсор, чтобы увидеть точный процент) или оставшийся предоплаченный баланс, под строкой, которая циклически показывает, что вы использовали по всем ним, например токены за эту неделю и вашу самую используемую модель. В разделе _Make something cool_ она предлагает стартовые промпты для новой темы, плагина, приложения или игры, которые передают задачу вашему агенту по умолчанию. Приложения создаются так же, как собственные Hype, Monologue и Omacut от Omarchy, на C++ и Qt Quick, следуя агентскому навыку omarchy-make-app, а компилятор и компоненты Qt, которые им нужны, поставляются установленными. Игры представляют собой одну страницу three.js в `~/Games/vibes`, следуя агентскому навыку omarchy-make-game, и все открываются из одного лаунчера Game Vibes в текущей теме; они загружают three.js из интернета, поэтому для запуска им нужно соединение. Claude Code, Codex, Grok, Kimi, Cursor и его allowance Grok Bot, GitHub Copilot, Muse, Antigravity и Devin покрываются из коробки со своими лимитами, Kimchi — со своим планом, предоплаченными кредитами и бюджетами расходов, а Hermes, Mistral Vibe и Qwen Code показывают свои сессии и токены, после того как вы ими воспользовались. Планы провайдеров и ключи, которые вы используете через pi, omp или opencode, также отображаются: OpenCode Zen и Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan и Synthetic со своими лимитами; OpenRouter и DeepSeek с их предоплаченными балансами; Fireworks с его расходами за последние 30 дней. Токены от моделей, которые вы запускаете на собственном оборудовании, также засчитываются в общие итоги; у самих моделей есть собственная панель, описанная в разделе [Локальные модели](#local-models). Каждый агент подсчитывается один раз, по тому, кто выставляет за него счёт, независимо от того, через сколько харнессов вы им управляете.

Щелчок левой кнопкой мыши по значку на панели или нажатие `Super + Ctrl + X` открывает панель, щелчок правой кнопкой запускает вашего агента по умолчанию, а щелчок средней кнопкой обновляет. Записи использования, лежащие в её основе, перегенерируются каждые 15 минут с помощью `omarchy agent usage update`, а панель может даже объединять использование с ваших других машин через синхронизируемую папку. См. README в `$OMARCHY_PATH/shell/plugins/agents/` для всех настроек.

### Несколько подписок

Если вы платите за более чем один план Claude, Codex или Grok — скажем, личный Max и рабочий, — Omarchy может держать их все вошедшими и переключаться между ними. Добавьте подписку с помощью + в панели агентов, которая проведёт вас через это прямо там, или с помощью `omarchy agent account add claude Work` (или `codex`, или `grok`). Она устанавливает CLI, если его нет. Первый аккаунт для провайдера входит через ваш обычный браузер, прямо там, где CLI всегда его ищет. Каждый следующий после этого входит через приватное окно, чтобы аккаунт, в который ваш браузер уже вошёл, не был подхвачен по ошибке; войдите там как аккаунт, который вы добавляете, и сначала закройте любое приватное окно, которое у вас уже открыто. Никогда не выходите из CLI для этого: выход отзывает сохранённый вход, и этот аккаунт придётся добавлять снова.

Чтобы скопировать ваши входы по подпискам на другую машину Omarchy по SSH, запустите `omarchy agent account copy user@laptop`. Отправитель предоставляет временного получателя, когда на месте назначения он не установлен, поэтому старые машины Omarchy могут получать аккаунты без обновления. Установленные получатели имеют приоритет. Это копирует все подписки Claude, Codex и Grok; добавьте имена провайдеров, чтобы выбрать их, как в `omarchy agent account copy laptop claude`. Имена аккаунтов и ID команд соответствуют источнику, включая аккаунты, уже присутствующие на месте назначения. Несвязанные аккаунты назначения получают цифровой суффикс, если их имена конфликтуют, а настройки, навыки, плагины и история разговоров остаются локальными для каждой машины.

Существующие учётные данные назначения сохраняются. Аккаунт источника, уже вошедший там, синхронизирует своё имя без замены его учётных данных; другие аккаунты добавляются рядом с ним. Чтобы заменить сохранённые учётные данные для совпадающих аккаунтов, используйте `omarchy agent account copy --replace laptop claude` после выхода из сессий этого аккаунта на месте назначения. Свежее место назначения также получает активный аккаунт источника и предпочтения переключения; устоявшееся место назначения сохраняет свои собственные.

Учётные данные перемещаются через SSH и хранятся в приватных файлах на месте назначения, поэтому копируйте только на машины, которым вы доверяете. Это однократное копирование, а не постоянная синхронизация. Refresh-токены Codex могут быть ротированы другой машиной, в результате чего скопированному входу потребуется обновление; отдельные входы остаются самым надёжным выбором для одновременного использования на нескольких машинах. См. [Руководство Codex по аутентификации аккаунтов](https://developers.openai.com/codex/auth/ci-cd-auth).

Один аккаунт на провайдера активен, и каждая новая сессия начинается как он: `cx`, `cy`, обычный `claude`, `codex` или `grok`, всё, что запущено через `omarchy agent`, а также скрипты или редакторы, которые находят CLI в `PATH`. Переключайтесь с помощью `omarchy agent account use work` (и обратно с помощью `omarchy agent account use main`) или в панели, нажав номер аккаунта, а затем `Enter` (или щёлкнув по его кнопке Use). Запущенные сессии Claude тоже переключаются, со следующего сообщения: каждая сессия Claude работает в `~/.claude`, в котором всегда хранится вход активного аккаунта. Сессия Claude, запущенная в собственной папке аккаунта более старой Omarchy, сохраняет этот вход до тех пор, пока не завершится, поэтому переключение называет эти сессии и завершается само, как только они исчезнут. Запущенные сессии Codex и Grok остаются на аккаунте, с которым они начали. История разговоров, настройки, навыки и плагины являются общими для всех аккаунтов, поэтому `claude --continue` в той же папке продолжит с того места, где вы остановились, на новом аккаунте.

При наличии более чем одного аккаунта панель показывает лимиты каждого аккаунта рядом, с отмеченным активным. Omarchy уведомляет вас, когда активный аккаунт превышает 95% лимита, и щелчок по уведомлению переключает на аккаунт с наибольшим запасом. Она никогда не переключается сама. Измените порог с помощью `omarchy agent account threshold 90`. Если каждый аккаунт превышает порог, вы услышите об этом один раз, а также о том, какой аккаунт освободится первым. Пока активный аккаунт находится в пределах 15 пунктов от его порога (80% при значении по умолчанию), его лимиты проверяются каждые три минуты, а не каждые 15.

`omarchy agent account list` показывает каждый аккаунт и его последние лимиты, `omarchy agent account remove work` забывает один, а `omarchy agent account rename primary Hey` переименовывает один (или щёлкните по имени аккаунта в панели). Эти команды работают с аккаунтами вашего агента по умолчанию; чтобы добраться до другого провайдера, сначала назовите его, как в `omarchy agent account use codex side`. Вход, который у вас уже был в `~/.claude` или `~/.codex`, — это аккаунт _Main_. У Codex он остаётся там, где он есть; у Claude он ждёт в собственной папке, пока активен другой аккаунт. Аккаунт, не использовавшийся более примерно восьми часов, может показать _Sign-in required_; щёлкните по нему, чтобы снова войти в этот аккаунт прямо в панели, или переключитесь на него и запустите сессию, которая обновит вход сама. MCP-серверы, которые вы добавляете с помощью `claude mcp add`, достигают каждого аккаунта Claude, поскольку все они работают в `~/.claude`; для Codex и Grok серверы, которые у вас были, когда аккаунт был добавлен, переходят вместе с ним, но более поздние достигают только того аккаунта, в котором вы их добавили. Claude Desktop хранит собственный вход, а инструменты Codex или Grok, настроенные с абсолютным путём к бинарному файлу CLI, не следуют за переключением. Явный `CLAUDE_CONFIG_DIR`, `CODEX_HOME` или `GROK_HOME` имеет приоритет над выбранным аккаунтом.

### Диагностика сбоев

Omarchy следит за systemd-coredump на предмет сбоев процессов. После того как вы выбрали агента по умолчанию, любая ваша программа, которая сбрасывает core, приводит к уведомлению "Process crashed" — щёлкните по нему, и сбой будет передан вашему агенту по умолчанию вместе с навыком omarchy-diagnose-crash от Omarchy, который проведёт агента через установление фактов из дампа ядра и решение, стоит ли сообщать о сбое вышестоящему проекту. Вы также можете запустить его вручную для любого PID из `coredumpctl list` с помощью `omarchy agent crash <pid>`.

Наблюдение включено по умолчанию. Отключите его в _Trigger > Toggle > Crash Capture Off_ (или с помощью `omarchy toggle crash-capture`), и уведомления прекратятся; `omarchy agent crash <pid>` по-прежнему работает вручную.

Сбои также можно заглушить по одной программе за раз, что диагностика и предлагает вам в конце. `omarchy crash mute hyprland` останавливает уведомления только для этой программы, `omarchy crash mute hyprland off` возвращает их обратно, а `omarchy crash mute` сам по себе перечисляет то, что вы заглушили. Он принимает путь к бинарному файлу так же охотно, как его имя, поэтому `omarchy crash mute /usr/bin/hyprland` делает то же самое. Заключите имя с пробелом в кавычки, как в `omarchy crash mute 'Some App'`. Всё остальное по-прежнему уведомляет, а заглушённая программа по-прежнему падает — это скрывает напоминание, оно ничего не исправляет.

### Настольные приложения

Меню _Install > AI_ также содержит несколько графических приложений ИИ: Amp Desktop, Antigravity Desktop, настольное приложение ChatGPT, настольное приложение Claude (Linux-бета от Anthropic, с вкладками Chat, Cowork и Claude Code), Grok Bot для общения с моделями xAI, Herdr Desktop, Hermes Desktop, OpenClaw, настольное приложение Perplexity и T3 Code. Grok Bot — это настольное чат-приложение. Агент для программирования — это команда `grok`.

Hermes Desktop — это то, о чём нужно знать, потому что на машине есть один Hermes, и он принадлежит приложению: Hermes устанавливается только когда-либо через приложение, и команда `hermes`, которую запускает агент по умолчанию, принадлежит приложению. Выбор Hermes в качестве агента по умолчанию устанавливает то же самое, что устанавливает запись _Install > AI_: пакет и среду выполнения Hermes в `~/.hermes`, настроенную собственным установщиком Hermes, что занимает несколько минут при первом запуске. Эта среда выполнения — это тот единственный Hermes, который используют терминальная команда `hermes`, агент по умолчанию и приложение, и она обновляет себя с помощью `hermes update`, а не ждёт релиза Omarchy. Её установка также передаёт Hermes тему Omarchy как скин с именем `omarchy`, которому следует каждая поверхность Hermes, когда вы переключаете темы; выберите другой в настройках Appearance у Hermes или с помощью `/skin`, если вы предпочитаете, чтобы он этого не делал, и Omarchy оставит этот выбор в покое. Удаление приложения в _Remove > AI_ сначала закрывает Hermes, включая шлюз, забирает эту среду выполнения с собой и сохраняет ваши чаты, воспоминания и навыки, которые Hermes написал для себя, если только вы не скажете ему иное: оно спрашивает, по умолчанию отвечая нет, должны ли эти данные и ваши настройки подключения также уйти.

Настольный опыт OpenClaw — это его Control UI, который открывается как веб-приложение, поддерживаемое его собственным локальным шлюзом. OpenClaw живёт в `~/.openclaw` и обновляет себя: используйте кнопку "Update Gateway" в Control UI или запустите `openclaw update`, и шлюз перезапустится на новой версии. Omarchy только выбирает релиз, с которого начинается свежая установка. OpenClaw также может быть вашим агентом по умолчанию: выбор его в _Agent > Harness_ настраивает ту же копию в `~/.openclaw`, а агент открывает терминальный UI OpenClaw, подключённый к его шлюзу. Удаление OpenClaw в _Remove > AI_ забирает сервис шлюза и приложение с собой, а затем спрашивает, должен ли `~/.openclaw` также уйти, поскольку там хранятся ваши чаты и учётные данные наряду с самим OpenClaw и средами выполнения плагинов, которые он скачивает; по умолчанию он сохраняется, и повторная установка OpenClaw подхватит его обратно.

Herdr Desktop — это настольное приложение [Herdr](https://herdr.dev): пространства, вкладки и панели терминалов и агентов для программирования, которые продолжают работать в его ядре, когда вы закрываете окно. Оно поставляется из собственного установщика Herdr, а не из пакета, поэтому оно живёт в `~/.local/share/herdr-app`, приносит своё ядро в `~/.local/bin/herdr-core`, когда у вас его ещё нет, и обновляет и само себя, и его. Оно находится рядом с командой `herdr`, которую Omarchy поставляет на `Super + Ctrl + Return`, а не заменяет её, и получает прямые клавиши этой команды: `Alt + Return` и `Alt + Shift + Return` разделяют панель вниз или вправо, `Alt + Escape` закрывает её, `Ctrl + Alt + Arrow` перемещает между панелями, `Alt + 1..9` и `Alt + Left/Right` выбирают вкладку, а `Alt + Up/Down` перемещают между пространствами. `Ctrl + 1..9` выбирает пространство, а `Alt + Shift + Up/Down` проходит по агентам. Префиксные клавиши `Ctrl + Space` остаются только для терминала, поскольку приложение не может удерживать обычную клавишу Ctrl для последовательности. Omarchy записывает их в `~/.config/herdr-app/keys.json`, а `omarchy-refresh-herdr-app` возвращает их обратно. Его установка выбирает тему Omarchy у Herdr, которая с этого момента следует вашей теме Omarchy. Herdr хранит одну тему для светлого режима и одну для тёмного, поэтому после переключения между тёмной и светлой темой Omarchy выберите Omarchy в средстве выбора тем Herdr ещё раз для другого режима.

T3 Code работает из его официального релиза AppImage в `~/.local/share/t3code`, а не из пакета, поэтому он обновляет себя. Его установка спрашивает, начинать ли на канале Stable или Nightly; переключите позже в настройках T3 Code. Ваши треды и настройки живут в `~/.t3`, и удаление T3 Code в _Remove > AI_ забирает их с собой.

### Локальные модели

Запустите открытую модель на своей собственной машине для ваших агентов для программирования. Ваши промпты и код остаются на машине; ничего из отправленного модели не покидает её. Начните с:

```bash
omarchy models use best text
```

Это настраивает лучшую текстовую модель для этой машины, ту, которую используют ваши агенты. У моделей изображений, видео и музыки есть своя лучшая: `omarchy models use best image`, `video` или `music`. Запустите `omarchy models use best`, чтобы увидеть выбор каждого вида для этой машины.

Или откройте панель локальных моделей с её значка с блёстками на верхней панели, рядом со значком агентов, или с помощью Super + Ctrl + Alt + X, и выберите +. Значок появляется, когда модель подходит этой машине. Podman, который запускает модели, поставляется с Omarchy, как и контейнерный инструментарий NVIDIA на машине NVIDIA, который даёт им GPU; если чего-либо из этого не хватает, первая настройка устанавливает это. Затем Omarchy выбирает рекомендуемую модель для этой машины, скачивает её и запускает. Ожидайте скачивания в десятки GB и использования большей части памяти машины, пока модель работает: Flash Next использует около 100 GiB с его полным контекстом 256K. Если другие модели удерживают нужную ей память, она настраивается остановленной, готовой к запуску, как только вы остановите одну. Модель останавливается при выходе из системы; остановите её сами, когда вам нужна память для чего-то другого.

`omarchy models list` показывает варианты и объясняет, почему некоторые не подходят. Чтобы настроить другую, запустите `omarchy models use <recipe>`. Сегодня `qwen3.8-flash-next-gufo` и `qwen3.8-27b-gufo` доступны для машин Strix Halo с 128 GB; 27B занимает около 40 GiB, поэтому она оставляет место для другой работы. На ноутбуке с 64 GB с Intel's Arc B390, `qwen3.6-35b-a3b-llamacpp` работает примерно в 30 GiB. Новые рецепты и рекомендации поступают с `omarchy update`, через пакет.

Каждая настроенная вами модель получает собственную строку в панели локальных моделей: кнопка воспроизведения запускает её, пауза останавливает её и освобождает её память, а кнопка терминала открывает вашего агента на ней. Вдоль верха полоса показывает, как память машины разделена между самой Omarchy (системой и вашими приложениями), каждой запущенной моделью и тем, что свободно. Наведите курсор на остановленную модель, и полоса покажет, подходит ли она, или насколько ей не хватает. Несколько могут работать одновременно, когда они вместе помещаются в память; если одна не помещается, Omarchy говорит, какую запущенную модель остановить. Перетаскивайте строки за их логотип, чтобы изменить их порядок, и нажмите Delete на выбранной строке, чтобы удалить модель и её скачивание.

Каждая модель для программирования, которую вы настраиваете, также получает собственную запись в лаунчере приложений, под именем модели и с логотипом её создателя, так же как вход в Claude, Codex или Grok добавляет одну. Она открывает вашего агента на этой модели и сначала запускает модель, если она не работает: терминал показывает её загрузку и передаёт управление агенту, как только она будет готова. Удаление модели удаляет её запись.

Не каждая модель предназначена для программирования. Модели изображений, видео и музыки открываются вместо этого в Fantasi, приложении Omarchy для создания картинок, видео и музыки с моделью, работающей на этой машине, выбранной там или из их строки в панели локальных моделей.

Модель продолжает работать именно так, как она была настроена, поэтому обновление Omarchy никогда не перезапускает её под вашими агентами. Когда у Omarchy есть более новая среда выполнения или более новые веса для модели, которую вы настроили, её строка показывает кнопку обновления: нажмите её, и модель будет настроена снова в фоне, скачивая только то, что изменилось, и перезапустится на новой версии. Модель, которая была остановлена, остаётся остановленной. `omarchy models update` делает то же самое для каждой модели из терминала.

Из командной строки `omarchy models start <recipe>` и `omarchy models stop <recipe>` делают то же самое, `omarchy models status` показывает каждую модель, а `omarchy agent --local` открывает последнюю запущенную вами модель в pi, независимо от того, какой у вас агент по умолчанию. OpenCode и Qwen Code также могут использовать локальную модель: `omarchy models harness opencode` или `omarchy models harness qwen` открывает их там вместо этого, а `omarchy models harness pi` возвращается обратно. pi также перечисляет каждую модель, которую вы настроили, и те, что на машинах, с которыми вы связались, в своём собственном средстве выбора моделей, поэтому обычный `pi` также до них добирается. Любой клиент, совместимый с OpenAI, также может подключиться: `status` показывает адрес каждой модели (первый — `http://127.0.0.1:11435/v1`), имя рецепта — это модель, а ключ находится в `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` удаляет модель и скачивания, которые не использует никакая другая модель.

Сторонние среды выполнения помечены их издателем. Omarchy запускает каждую модель без доступа к сети.

### Локальные LLM

Omarchy рекомендует два способа запуска локальных моделей LLM: LM Studio и Ollama. LM Studio предоставляет интерфейс GUI для поиска моделей с открытыми весами, их установки и запуска. Это отличный способ легко начать. Ollama предлагает CLI для того же самого аналогичным образом. Но если вы новичок в локальных моделях, я бы начал с LM Studio. Вы можете установить любой из них в _Install > AI_ в меню Omarchy.

### Навыки Omarchy

Агентские навыки помогают ИИ использовать конкретные инструменты конкретным образом, и Omarchy поставляет семь из них. Навык omarchy охватывает настройку системы под себя, например настройку вашей конфигурации Hyprland или регулировку панели. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app и omarchy-make-game охватывают создание чего-то нового, omarchy-contribute охватывает сообщение об ошибке или отправку исправления вышестоящему проекту, а omarchy-diagnose-crash работает с дампом ядра сбоя. Они связаны символическими ссылками в каталоги навыков для Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` и каждый `~/.hermes/profiles/*/skills`) и общее местоположение `~/.agents/skills`, поэтому большинство харнессов подхватывают их автоматически. Собственная папка навыка с тем же именем имеет приоритет.

Но вы должны относиться к этим навыкам как к экспериментальным. Разные модели будут использовать его с разным эффектом. Лучше сначала запускать в режиме планирования, чтобы у вас было представление о том, что агент хотел бы изменить. А затем будьте готовы откатить изменения или даже вызвать `omarchy reinstall configs`, если агент всё испортит.
