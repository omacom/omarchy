# ИИ

В Omarchy есть средства запуска для перечисленных ниже агентов для программирования, но агент по умолчанию за вас не выбирается. Запустите команду, чтобы при первом использовании установить её CLI, а затем пройдите аутентификацию, когда появится запрос. Hermes и OpenClaw — исключения: для них через mise ничего не устанавливается, и при выборе любого из них настраивается его собственная самообновляющаяся копия, как объяснено ниже в разделе _Настольные приложения_.

### Установка и обновление агентов

За исключением Hermes и OpenClaw, эти агенты используют ленивую установку mise: при первом запуске устанавливается CLI, а при последующих запусках он используется повторно. mise также проверяет, не вышла ли новая версия установленного агента, не чаще одного раза в четыре часа, непосредственно перед его запуском или в фоновом режиме при появлении приглашения оболочки. Если это обновление не удастся или вы будете офлайн, запустится установленная версия. `omarchy update` обновляет установленных агентов вместе с остальной частью Omarchy, а `mup` обновляет только инструменты, управляемые mise.

Собственное средство обновления агента, например `claude update`, `codex update` или кнопка обновления в приложении, не обновляет установку, управляемую mise. `codex update` завершается с ошибкой, а `claude update` может сообщить об успехе, установив при этом отдельную копию, которую mise не отслеживает. Если вы предпочитаете использовать родной установщик и средство обновления агента, добавьте его в `disable_tools`; см. [Предустановленные инструменты CLI](18-development-tools.md#preinstalled-cli-tools).

Чтобы установить все настроенные ленивые инструменты до того, как они вам понадобятся, запустите `mise install --include-lazy`. Это включает другие инструменты CLI Omarchy по умолчанию, а также агентов. Сведения об установке одного инструмента или использовании собственной установки см. в [Предустановленные инструменты CLI](18-development-tools.md#preinstalled-cli-tools).

`grok` устанавливается через фирменный пакет mise `grok`, так же как `claude` и `codex`. Запустите `grok` или отметьте его звёздочкой на панели агентов. Пропустите установщик `curl | bash` на x.ai. Этот путь помещает вторую копию в `~/.grok/bin`, ставит её первой в `PATH` и перезаписывает обёртку Omarchy.

`dsh` открывает свой браузерный UI по адресу `127.0.0.1:3080`, где каталог запуска является рабочим пространством по умолчанию. Его браузерный UI не принимает начальный запрос, поэтому `omarchy agent prompt` открывает его с запросом в вашем буфере обмена, чтобы вы могли его вставить. Omarchy запускает его с предустановкой разрешений DeepSeek без подтверждений. DeepSeek Harness загружает журналы сессий в DeepSeek, когда вы используете его официальный API моделей; отключите это в его браузерном UI в разделе _Settings > General > Upload Session Log_. Отправляемая вами обратная связь также загружается вместе с сессией, если только вы не запустите его с `DSH_TELEMETRY_MODE=DISABLED`.

### Агент по умолчанию

Выберите агента по умолчанию с помощью звёздочки рядом с агентом на панели агентов, которая заполнена у агента по умолчанию, или с помощью `omarchy default agent <name>`, которая также принимает любой harness, для которого там нет строки. Если агент ещё не установлен, при его выборе он сначала устанавливается, а также получает собственное средство запуска в средстве запуска приложений, рядом с Agent. Свежая установка Omarchy предлагает вам настроить одного с помощью однократного уведомления, которое открывает панель агентов.

При выборе Claude также предпринимается попытка настроить его расширение для браузера для Chromium, Chrome, Brave, Brave Origin и Edge. Настройка расширения применяется ко всем пользователям и может запросить ваш системный пароль; отмена или неудачная установка расширения всё равно выбирает и запускает Claude. Перезапустите браузер, включите расширение, если появится запрос, и войдите в Claude, чтобы завершить его подключение. Запустите `/chrome` в Claude, чтобы проверить соединение. Firefox и Zen не поддерживают это расширение. Если Claude уже был вашим агентом по умолчанию до добавления этой настройки, выберите его снова, чтобы установить расширение.

После того как вы сделали выбор, `Super + Shift + Ctrl + A` запускает агента по умолчанию в отдельном окне терминала (или вызывает средство выбора, если вы ещё не выбрали). Вы также можете запустить его сразу с задачей с помощью `omarchy agent prompt "Review this project"`. Freebuff и DeepSeek Harness не принимают начальный запрос, поэтому вместо этого они открываются с запросом в вашем буфере обмена, чтобы вы могли его вставить. Агенты, запущенные таким образом, работают без присмотра в своих соответствующих режимах «не останавливайся, чтобы спросить», так что будьте готовы к тому, что они действительно будут что-то делать! У MiniMax Code нет такого режима для его интерактивных сессий, поэтому он запрашивает разрешения как обычно. А поскольку агенты отказываются запоминать доверие для вашего домашнего каталога, запуски из `$HOME` вместо этого начинаются в `~/Work`.

Есть и ярлыки для терминала: `a` запускает агента по умолчанию прямо в текущем терминале, а `c`, `cx` и `cy` запускают OpenCode, Claude Code и Codex напрямую (снова в их режимах с автоматическим одобрением). Изменения темы также синхронизируются с агентами: Claude Code, Pi, OpenCode и Hermes (после того как Omarchy его установила) следуют за вами, когда вы переключаете тему Omarchy.

### Ваши инструкции для агентов

Личные правила для каждого агента помещаются в `~/.agents/AGENTS.md`, рядом с общими навыками в `~/.agents/skills`. Откройте его с помощью значка документа рядом с + на панели агентов или с помощью `omarchy agent instructions --edit`, которая также связывает его с каждым harness, который хранит свой собственный глобальный файл: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` у Copilot и так далее. Crush и Amp читают ссылку `~/.config/AGENTS.md`, а omp, Kimi и DeepSeek Harness читают `~/.agents/AGENTS.md` напрямую. При выборе агента по умолчанию он также связывается. Файл инструкций, который у вас уже был, становится общим, если его ещё не было; в противном случае он сохраняется рядом со ссылкой как `.bak`. Запустите `omarchy agent instructions`, чтобы повторно связать после установки другого агента.

### Панель агентов

На верхней панели есть значок агентов. До того как вы настроите агента, его панель предлагает три способа начать: войти в подписку Claude, Codex, Grok, Gemini, Muse, Cursor или Copilot, или в разделе More — в план для программирования OpenCode Go, MiniMax, Synthetic или Z.ai; платить по мере использования с Fireworks, OpenCode Zen and Go, OpenRouter, или в разделе More — с DeepSeek или любым другим провайдером, в который входит OpenCode, всё запускается в OpenCode; или запустить лучшую модель для вашего компьютера, когда ему подходит какая-либо. Первый завершённый вами способ становится вашим агентом по умолчанию, а + на панели, или _Agent > Add_ в Omarchy Menu, позже предлагает те же три способа. После этого панель размещает каждую подписку на одной странице: каждый агент и аккаунт с его планом, индикатор для каждого из его 5-часовых сессионных и недельных лимитов со временем до его сброса (наведите курсор, чтобы увидеть точный процент), или оставшийся предоплаченный баланс, под строкой, в которой по очереди показывается, что вы использовали по всем ним, например токены за эту неделю и ваша самая используемая модель. В разделе _Make something cool_ она предлагает начальные запросы для новой темы, плагина, приложения или игры, которые передают задачу вашему агенту по умолчанию. Приложения создаются так же, как собственные приложения Omarchy Hype, Monologue и Omacut, на C++ и Qt Quick, следуя навыку агента omarchy-make-app, а нужные им компилятор и компоненты Qt уже установлены. Игры — это одна страница three.js в `~/Games/vibes`, следующая навыку агента omarchy-make-game, и все они открываются из одного средства запуска Game Vibes в текущей теме; они загружают three.js из сети, поэтому для запуска им нужно соединение. Claude Code, Codex, Grok, Kimi, Cursor и его лимит Grok Bot, GitHub Copilot, Muse, Gemini (через Antigravity) и Devin покрываются из коробки с их лимитами, Kimchi — с его планом, предоплаченными кредитами и бюджетами расходов, а Hermes, Mistral Vibe и Qwen Code показывают свои сессии и токены после того, как вы ими воспользовались. Планы и ключи провайдеров, которые вы используете через pi, omp или opencode, тоже отображаются: OpenCode Zen and Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan и Synthetic с их лимитами; OpenRouter и DeepSeek с их предоплаченными балансами; Fireworks с его расходами за последние 30 дней. Токены от моделей, которые вы запускаете на собственном оборудовании, тоже засчитываются в общие итоги; у самих моделей есть своя панель, описанная в разделе [Локальные модели](#local-models). Каждый агент учитывается один раз, по тому, кто выставляет за него счёт, независимо от того, через сколько harness вы им управляете.

Щелчок левой кнопкой по значку на панели или нажатие `Super + Ctrl + X` открывает панель, щелчок правой кнопкой запускает вашего агента по умолчанию, а щелчок средней кнопкой обновляет данные. Записи об использовании, на которых она основана, перегенерируются каждые 15 минут командой `omarchy agent usage update`, и панель даже может объединять использование с других ваших машин через синхронизируемую папку. Полные настройки см. в README в `$OMARCHY_PATH/shell/plugins/agents/`.

### Несколько подписок

Если вы платите за более чем один план Claude, Codex или Grok — например, личный Max и рабочий, — Omarchy может держать их все вошедшими и перемещаться между ними. Добавьте подписку с помощью + на панели агентов, которая проведёт вас через это прямо там, или с помощью `omarchy agent account add claude Work` (или `codex`, или `grok`). Тот же + и та же команда выполняют вход в Gemini (`gemini`) и OpenCode (`opencode`), а также сохраняют ключ API Fireworks (`fireworks`) или OpenRouter (`openrouter`) в OpenCode; команда также выполняет вход в Copilot (`copilot`), Cursor (`cursor`) и Muse (`muse`). Они сохраняют по одному входу каждый. Она устанавливает CLI, если он отсутствует. Первый аккаунт для провайдера входит через ваш обычный браузер, именно там, где CLI всегда его ищет. Каждый последующий аккаунт входит через приватное окно, чтобы аккаунт, в который ваш браузер уже вошёл, не был подхвачен по ошибке; войдите там как аккаунт, который вы добавляете, и сначала закройте любое приватное окно, которое у вас уже было открыто. Никогда не выходите из CLI для этого: выход отзывает сохранённый вход, и этот аккаунт придётся добавлять снова.

Чтобы скопировать ваши входы в подписки на другую машину с Omarchy через SSH, запустите `omarchy agent account copy user@laptop`. Отправитель предоставляет временного получателя, когда на месте назначения он не установлен, поэтому старые машины с Omarchy могут получать аккаунты без обновления. Установленные получатели имеют приоритет. Это копирует все подписки Claude, Codex и Grok; добавьте названия провайдеров, чтобы выбрать их, например `omarchy agent account copy laptop claude`. Названия аккаунтов и ID команд соответствуют источнику, включая аккаунты, уже присутствующие на месте назначения. Несвязанные аккаунты на месте назначения получают цифровой суффикс, если их названия конфликтуют, а настройки, навыки, плагины и история разговоров остаются локальными для каждой машины.

Существующие учётные данные на месте назначения сохраняются. Аккаунт источника, уже вошедший там, синхронизирует своё название без замены своих учётных данных; другие аккаунты добавляются рядом с ним. Чтобы заменить сохранённые учётные данные для совпадающих аккаунтов, используйте `omarchy agent account copy --replace laptop claude` после выхода из сессий этого аккаунта на месте назначения. Свежее место назначения также получает активный аккаунт источника и его предпочтения переключения; устоявшееся место назначения сохраняет свои собственные.

Учётные данные перемещаются через SSH и хранятся в приватных файлах на месте назначения, поэтому копируйте только на машины, которым вы доверяете. Это одноразовая копия, а не постоянная синхронизация. Токены обновления Codex могут быть ротированы другой машиной, из-за чего скопированный вход будет нуждаться в обновлении; отдельные входы остаются самым надёжным выбором для одновременного использования на нескольких машинах. См. [руководство Codex по аутентификации аккаунтов](https://developers.openai.com/codex/auth/ci-cd-auth).

Один аккаунт на провайдера активен, и каждая новая сессия начинается как он: `cx`, `cy`, обычный `claude`, `codex` или `grok`, всё, что запущено через `omarchy agent`, и скрипты или редакторы, которые находят CLI в `PATH`. Переключайтесь с помощью `omarchy agent account use work` (и обратно с помощью `omarchy agent account use main`), или на панели, нажав номер аккаунта, а затем `Enter` (или щёлкнув по его звёздочке). Запущенные сессии Claude тоже переключаются, со следующего их сообщения: каждая сессия Claude запускается в `~/.claude`, в котором всегда хранится вход активного аккаунта. Сессия Claude, запущенная в собственной папке аккаунта более старой версией Omarchy, хранит этот вход до своего завершения, поэтому переключение называет эти сессии и завершается само по себе, как только они исчезнут. Запущенные сессии Codex и Grok остаются на аккаунте, с которого они начались. История разговоров, настройки, навыки и плагины являются общими для всех аккаунтов, поэтому `claude --continue` в той же папке продолжит с того места, где вы остановились, на новом аккаунте.

При наличии более одного аккаунта панель показывает лимиты каждого аккаунта рядом, с заполненной звёздочкой на используемом. Omarchy уведомляет вас, когда активный аккаунт превышает 95% лимита, и щелчок по уведомлению переключает на аккаунт с наибольшим запасом. Она никогда не переключается сама по себе. Измените порог с помощью `omarchy agent account threshold 90`. Если каждый аккаунт превышает порог, вы услышите об этом один раз, вместе с тем, какой аккаунт освободится первым. Пока активный аккаунт находится в пределах 15 пунктов от своего порога (80% при значении по умолчанию), его лимиты проверяются каждые три минуты, а не каждые 15.

`omarchy agent account list` показывает каждый аккаунт и его последние лимиты, `omarchy agent account remove work` забывает один, а `omarchy agent account rename primary Hey` переименовывает один (или щёлкните по названию аккаунта на панели). Эти команды работают с аккаунтами вашего агента по умолчанию; чтобы обратиться к другому провайдеру, сначала назовите его, например `omarchy agent account use codex side`. Вход, который у вас уже был в `~/.claude` или `~/.codex`, — это аккаунт _Main_. У Codex он остаётся там, где он есть; у Claude он ожидает в своей собственной папке, пока активен другой аккаунт. Аккаунт, оставленный без использования более примерно восьми часов, может показать _Sign-in required_; щёлкните по нему, чтобы снова войти в этот аккаунт прямо на панели, или переключитесь на него и начните сессию, что само по себе обновит вход. Серверы MCP, которые вы добавляете с помощью `claude mcp add`, достигают каждого аккаунта Claude, поскольку все они запускаются в `~/.claude`; для Codex и Grok серверы, которые у вас были, когда аккаунт был добавлен, переходят к нему, но более поздние достигают только того аккаунта, в который вы их добавили. Claude Desktop хранит свой собственный вход, а инструменты Codex или Grok, настроенные с абсолютным путём к бинарному файлу CLI, не следуют за переключением. Явный `CLAUDE_CONFIG_DIR`, `CODEX_HOME` или `GROK_HOME` имеет приоритет над выбранным аккаунтом.

### Диагностика сбоев

Omarchy следит за systemd-coredump на предмет сбоев процессов. После того как вы выберете агента по умолчанию, любая ваша программа, которая создаёт дамп ядра, вызывает уведомление «Process crashed» — щёлкните по нему, и сбой будет передан вашему агенту по умолчанию вместе с навыком Omarchy omarchy-diagnose-crash, который проводит агента через установление фактов из дампа ядра и решение, стоит ли сообщать о сбое вверх по цепочке. Вы также можете запустить его вручную для любого PID из `coredumpctl list` с помощью `omarchy agent crash <pid>`.

Наблюдение включено по умолчанию. Отключите его в разделе _Trigger > Toggle > Crash Capture Off_ (или с помощью `omarchy toggle crash-capture`), и уведомления прекратятся; `omarchy agent crash <pid>` по-прежнему работает вручную.

Сбои также можно заглушить по одной программе за раз, что диагностика и предлагает вам в конце. `omarchy crash mute hyprland` останавливает уведомления только для этой программы, `omarchy crash mute hyprland off` возвращает их, а `omarchy crash mute` сам по себе перечисляет то, что вы заглушили. Он принимает путь к бинарному файлу так же охотно, как и его название, поэтому `omarchy crash mute /usr/bin/hyprland` делает то же самое. Заключите название с пробелом в кавычки, например `omarchy crash mute 'Some App'`. Всё остальное по-прежнему уведомляет, а заглушённая программа по-прежнему падает — это скрывает напоминание, это ничего не исправляет.

### Настольные приложения

Меню _Install > AI_ также содержит несколько графических приложений ИИ: Amp Desktop, Antigravity Desktop, настольное приложение ChatGPT, настольное приложение Claude (бета-версия Anthropic для Linux, с вкладками Chat, Cowork и Claude Code), Grok Bot для общения с моделями xAI, Herdr Desktop, Hermes Desktop, OpenClaw, настольное приложение Perplexity и T3 Code. Grok Bot — это настольное приложение для чата. Агент для программирования — это команда `grok`.

Hermes Desktop — это то, о чём стоит знать, потому что на машине есть один Hermes, и он принадлежит приложению: Hermes устанавливается только через приложение, и команда `hermes`, которую запускает агент по умолчанию, принадлежит приложению. При выборе Hermes в качестве агента по умолчанию устанавливается то же самое, что делает пункт _Install > AI_: пакет и среда выполнения Hermes в `~/.hermes`, настроенная собственным установщиком Hermes, что в первый раз занимает несколько минут. Эта среда выполнения — это тот единственный Hermes, который используют терминальная команда `hermes`, агент по умолчанию и приложение, и она обновляет себя с помощью `hermes update`, а не ждёт релиза Omarchy. При её установке Hermes также получает тему Omarchy в качестве скина с названием `omarchy`, которому следует каждая поверхность Hermes при переключении вами тем; выберите другую в настройках Appearance у Hermes или с помощью `/skin`, если вы предпочитаете, чтобы он этого не делал, и Omarchy оставит этот выбор в покое. При удалении приложения в разделе _Remove > AI_ сначала закрывается Hermes, включая шлюз, среда выполнения уносится с ним, а ваши чаты, воспоминания и навыки, которые Hermes написал для себя, сохраняются, если только вы не скажете иначе: оно спрашивает, по умолчанию — нет, должны ли эти данные и ваши настройки соединения тоже исчезнуть.

Настольный опыт OpenClaw — это его Control UI, который открывается как веб-приложение, поддерживаемое его собственным локальным шлюзом. OpenClaw живёт в `~/.openclaw` и обновляет себя сам: используйте кнопку «Update Gateway» в Control UI или запустите `openclaw update`, и шлюз перезапустится на новой версии. Omarchy выбирает только релиз, с которого начинается свежая установка. OpenClaw также может быть вашим агентом по умолчанию: при его выборе в разделе _Agent > Harness_ настраивается та же копия в `~/.openclaw`, и агент открывает терминальный UI OpenClaw, подключённый к его шлюзу. При удалении OpenClaw в разделе _Remove > AI_ уносятся служба шлюза и приложение, а затем спрашивается, должен ли `~/.openclaw` тоже исчезнуть, поскольку там хранятся ваши чаты и учётные данные рядом с самим OpenClaw и средами выполнения плагинов, которые он загружает; по умолчанию он сохраняется, и при повторной установке OpenClaw он подхватывается обратно.

Herdr Desktop — это настольное приложение [Herdr](https://herdr.dev): пространства, вкладки и панели терминалов и агентов для программирования, которые продолжают работать в его ядре, когда вы закрываете окно. Оно происходит из собственного установщика Herdr, а не из пакета, поэтому оно живёт в `~/.local/share/herdr-app`, приносит своё ядро в `~/.local/bin/herdr-core`, когда у вас его ещё нет, и обновляет их обоих само. Оно находится рядом с командой `herdr`, которую Omarchy поставляет на `Super + Ctrl + Return`, а не заменяет её, и получает прямые клавиши этой команды: `Alt + Return` и `Alt + Shift + Return` разделяют панель вниз или вправо, `Alt + Escape` закрывает её, `Ctrl + Alt + Arrow` перемещает между панелями, `Alt + 1..9` и `Alt + Left/Right` выбирают вкладку, а `Alt + Up/Down` перемещают между пространствами. `Ctrl + 1..9` выбирает пространство, а `Alt + Shift + Up/Down` проходит по агентам. Префиксные клавиши `Ctrl + Space` остаются только для терминала, поскольку приложение не может удерживать обычную клавишу Ctrl для последовательности. Omarchy записывает их в `~/.config/herdr-app/keys.json`, а `omarchy-refresh-herdr-app` возвращает их обратно. При его установке выбирается тема Omarchy у Herdr, которая с этого момента следует за вашей темой Omarchy. Herdr хранит одну тему для светлого режима и одну для тёмного, поэтому после переключения между тёмной и светлой темами Omarchy выберите Omarchy в средстве выбора тем Herdr ещё раз для другого режима.

T3 Code запускается из своего официального релиза AppImage в `~/.local/share/t3code`, а не из пакета, поэтому он обновляет себя сам. При его установке спрашивается, начинать ли на канале Stable или Nightly; переключите позже в настройках T3 Code. Ваши потоки и настройки живут в `~/.t3`, и при удалении T3 Code в разделе _Remove > AI_ они уносятся с ним.

### Локальные модели

Запускайте открытую модель на своей собственной машине для своих агентов для программирования. Ваши запросы и код остаются на машине; ничего из отправленного модели не покидает её. Начните с:

```bash
omarchy models use best text
```

Это настраивает лучшую текстовую модель для этой машины, ту, которую используют ваши агенты. У моделей изображений, видео и музыки есть своя лучшая: `omarchy models use best image`, `video` или `music`. Запустите `omarchy models use best`, чтобы увидеть выбор каждого вида для этой машины.

Или откройте панель локальных моделей с её значка с блёстками на верхней панели, рядом со значком агентов, или с помощью Super + Ctrl + Alt + X, и выберите +. Значок появляется, когда модель подходит этой машине. Podman, который запускает модели, поставляется с Omarchy, как и набор инструментов контейнеров NVIDIA на машине с NVIDIA, который даёт им GPU; если чего-либо из них не хватает, первая настройка устанавливает это. Затем Omarchy выбирает рекомендуемую модель для этой машины, загружает её и запускает. Ожидайте загрузку в десятки GB и использование большей части памяти машины во время работы модели: Flash Next использует около 100 GiB со своим полным контекстом 256K. Если другие модели удерживают нужную ей память, она настраивается остановленной, готовой к запуску, как только вы остановите одну из них. Модель останавливается при выходе из системы; останавливайте её сами, когда вам нужна память для чего-то другого.

`omarchy models list` показывает варианты и объясняет, почему некоторые не подходят. Чтобы настроить другую, запустите `omarchy models use <recipe>`. Сегодня `qwen3.8-flash-next-gufo` и `qwen3.8-27b-gufo` доступны для машин Strix Halo со 128 GB; 27B занимает около 40 GiB, поэтому она оставляет место для другой работы. На ноутбуке с 64 GB и Intel Arc B390 `qwen3.6-35b-a3b-llamacpp` работает примерно в 30 GiB. Новые рецепты и рекомендации приходят с `omarchy update`, через пакет.

Каждая настроенная вами модель получает свою собственную строку на панели локальных моделей: воспроизведение, чтобы запустить её, пауза, чтобы остановить её и освободить её память, и кнопка терминала, чтобы открыть вашего агента на ней. Вверху полоса показывает, как память машины разделена между самой Omarchy (системой и вашими приложениями), каждой работающей моделью и тем, что свободно. Наведите курсор на остановленную модель, и полоса покажет, помещается ли она, или насколько ей не хватает. Несколько могут работать одновременно, когда они вместе помещаются в памяти; если одна не помещается, Omarchy говорит, какую работающую модель остановить. Перетаскивайте строки за их логотип, чтобы изменить их порядок, и нажимайте Delete на выбранной строке, чтобы удалить модель и её загрузку.

Каждая настроенная вами модель для программирования также получает свою собственную запись в средстве запуска приложений, под названием модели и с логотипом её создателя, так же как вход в Claude, Codex или Grok добавляет одну. Она открывает вашего агента на этой модели и сначала запускает модель, если она не работает: терминал показывает её загрузку и передаёт управление агенту, как только она будет готова. При удалении модели удаляется её запись.

Не каждая модель предназначена для программирования. Модели изображений, видео и музыки вместо этого открываются в Fantasi, приложении Omarchy для создания картинок, видео и музыки с моделью, работающей на этой машине, выбранной там или из их строки на панели локальных моделей.

Модель продолжает работать именно так, как она была настроена, поэтому обновление Omarchy никогда не перезапускает одну из них под вашими агентами. Когда у Omarchy есть более новая среда выполнения или более новые веса для модели, которую вы настроили, её строка показывает кнопку обновления: нажмите её, и модель будет настроена снова в фоновом режиме, загружая только то, что изменилось, и перезапустится на новой версии. Модель, которая была остановлена, остаётся остановленной. `omarchy models update` делает то же самое для каждой модели из терминала.

Из командной строки `omarchy models start <recipe>` и `omarchy models stop <recipe>` делают то же самое, `omarchy models status` показывает каждую модель, а `omarchy agent --local` открывает последнюю запущенную вами модель в pi, независимо от того, какой у вас агент по умолчанию. Чтобы сделать эту модель той, которую открывают горячая клавиша агента, консоль Quake и _Make something_, запустите `omarchy default agent local` или выберите _Local model_ в разделе _Agent > Harness_. pi также перечисляет каждую настроенную вами модель, и те, что на машинах, с которыми вы выполнили сопряжение, в своём собственном средстве выбора моделей, поэтому обычный `pi` тоже достигает их. Любой клиент, совместимый с OpenAI, тоже может подключиться: `status` показывает адрес каждой модели (первый — `http://127.0.0.1:11435/v1`), название рецепта — это модель, а ключ находится в `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` удаляет модель и загрузки, которые не использует никакая другая модель.

Сторонние среды выполнения помечены их издателем. Omarchy запускает каждую модель без доступа к сети.

### Локальные LLM

Omarchy рекомендует два способа запуска локальных моделей LLM: LM Studio и Ollama. LM Studio предоставляет графический интерфейс для поиска моделей с открытыми весами, их установки и запуска. Это отличный способ легко начать. Ollama предлагает CLI для того же самого похожим образом. Но если вы новичок в локальных моделях, я бы начал с LM Studio. Вы можете установить любое из них в разделе _Install > AI_ в Omarchy Menu.

### Навыки Omarchy

Навыки агентов помогают ИИ использовать конкретные инструменты конкретным образом, и Omarchy поставляет семь из них. Навык omarchy охватывает настройку системы под себя, например настройку вашей конфигурации Hyprland или регулировку панели. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app и omarchy-make-game охватывают создание чего-то нового, omarchy-contribute охватывает сообщение об ошибке или отправку исправления вверх по цепочке, а omarchy-diagnose-crash работает с дампом ядра сбоя. Они связаны символическими ссылками в каталоги навыков для Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` и каждый `~/.hermes/profiles/*/skills`) и общее расположение `~/.agents/skills`, поэтому большинство harness подхватывают их автоматически. Ваша собственная папка навыка с тем же названием имеет приоритет.

Но вы должны относиться к этим навыкам как к экспериментальным. Разные модели будут использовать их с разным эффектом. Лучше всего сначала запускать в режиме планирования, чтобы у вас было представление о том, что агент хотел бы изменить. А затем будьте готовы откатить изменения или даже вызвать `omarchy reinstall configs`, если агент устроит беспорядок во всём.
