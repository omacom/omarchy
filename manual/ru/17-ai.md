### Установка и обновление агентов

За исключением Hermes, эти агенты используют ленивую установку через mise: первый запуск устанавливает CLI, а последующие запуски используют его повторно. mise также проверяет, не вышла ли новая версия установленного агента, не чаще одного раза в четыре часа, непосредственно перед его запуском или в фоновом режиме в приглашении оболочки. Если это обновление не удастся или вы будете офлайн, запустится установленная версия. `omarchy update` обновляет установленные агенты вместе с остальной частью Omarchy, а `mup` обновляет только инструменты, управляемые mise.

Собственный механизм обновления агента, например `claude update`, `codex update` или кнопка обновления в приложении, не обновляет установку, управляемую mise. `codex update` завершается с ошибкой, а `claude update` может сообщить об успехе, установив при этом отдельную копию, которую mise не отслеживает. Если вы предпочитаете использовать родной установщик и механизм обновления агента, добавьте его в `disable_tools`; см. [Preinstalled CLI tools](18-development-tools.md#preinstalled-cli-tools).

Чтобы установить все настроенные ленивые инструменты до того, как они вам понадобятся, запустите `mise install --include-lazy`. Сюда входят и другие CLI-инструменты Omarchy по умолчанию, а также агенты. См. [Preinstalled CLI tools](18-development-tools.md#preinstalled-cli-tools) об установке одного инструмента или использовании собственной установки.

`grok` устанавливается через фирменный пакет mise `grok`, точно так же, как `claude` и `codex`. Запустите `grok` или выберите его в _Agent > Harness_. Пропустите установщик `curl | bash` на x.ai. Этот путь помещает вторую копию в `~/.grok/bin`, ставит её в начало `PATH` и перезаписывает обёртку Omarchy.

`dsh` открывает свой браузерный UI на `127.0.0.1:3080`, используя каталог запуска в качестве рабочего пространства по умолчанию. Его браузерный UI не принимает стартовый промпт, поэтому `omarchy agent prompt` открывает его с промптом в вашем буфере обмена, чтобы вы могли его вставить. Omarchy запускает его с пресетом разрешений DeepSeek без подтверждений. DeepSeek Harness загружает журналы сессий в DeepSeek, когда вы используете его официальный API моделей; отключите это в его браузерном UI в _Settings > General > Upload Session Log_. Отправляемая вами обратная связь также загружается вместе с сессией, если только вы не запустите его с `DSH_TELEMETRY_MODE=DISABLED`.

### Агент по умолчанию

Выберите агента по умолчанию с помощью `omarchy default agent <name>` или в _Agent > Harness_ в Omarchy Menu (`Super + Space`). Если агент ещё не установлен, его выбор сначала установит его. Свежая Omarchy предложит вам сделать этот выбор с помощью одноразового уведомления.

Выбор Claude также пытается настроить его расширение для браузера для Chromium, Chrome, Brave, Brave Origin и Edge. Настройка расширения применяется ко всем пользователям и может запросить ваш системный пароль; отмена или неудачная установка расширения всё равно выбирает и запускает Claude. Перезапустите браузер, включите расширение, если появится запрос, и войдите в Claude, чтобы завершить его подключение. Запустите `/chrome` в Claude, чтобы проверить соединение. Firefox и Zen не поддерживают это расширение. Если Claude уже был вашим агентом по умолчанию до того, как была добавлена эта настройка, выберите его снова, чтобы установить расширение.

После того как вы сделали выбор, `Super + Shift + Ctrl + A` запускает агента по умолчанию в отдельном окне терминала (или открывает выбор, если вы ещё не выбрали). Вы также можете запустить его сразу с задачей с помощью `omarchy agent prompt "Review this project"`. Freebuff и DeepSeek Harness не принимают стартовый промпт, поэтому вместо этого они открываются с промптом в вашем буфере обмена, чтобы вы могли его вставить. Агенты, запущенные таким способом, работают без присмотра в своих соответствующих режимах «не останавливайся, чтобы спросить», так что будьте готовы к тому, что они действительно будут что-то делать! У MiniMax Code нет такого режима для его интерактивных сессий, поэтому он запрашивает разрешения как обычно. А поскольку агенты отказываются запоминать доверие для вашего домашнего каталога, запуски из `$HOME` вместо этого стартуют в `~/Work`.

Есть и ярлыки терминала: `a` запускает агента по умолчанию прямо в текущем терминале, а `c`, `cx` и `cy` запускают OpenCode, Claude Code и Codex напрямую (опять же в их режимах автоматического одобрения). Изменения темы также синхронизируются с агентами: Claude Code, Pi, OpenCode и Hermes (после того как Omarchy его установила) следуют за вами, когда вы переключаете тему Omarchy.

### Ваши инструкции для агентов

Личные правила для каждого агента находятся в `~/.agents/AGENTS.md`, рядом с общими скиллами в `~/.agents/skills`. Откройте его в _Agent > Instructions_, который также связывает его с каждым харнессом, хранящим собственный глобальный файл: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` у Copilot и так далее. Crush и Amp читают ссылку `~/.config/AGENTS.md`, а omp, Kimi и DeepSeek Harness читают `~/.agents/AGENTS.md` напрямую. Выбор агента по умолчанию также связывает его. Файл инструкций, который у вас уже был, становится общим, если его ещё не было; в противном случае он сохраняется рядом со ссылкой как `.bak`. Запустите `omarchy agent instructions`, чтобы повторно связать после установки другого агента.

### Панель агентов

На верхней панели есть значок агентов. До того как вы настроите агента, его панель проведёт вас через вход в Claude, Codex или Grok, и первый из них станет вашим агентом по умолчанию. После этого панель размещает каждую подписку на одной странице: каждый агент и аккаунт с его планом, индикатор для каждого из его 5-часовых сессионных и недельных лимитов со временем до его сброса (наведите курсор, чтобы увидеть точный процент) или оставшийся предоплаченный баланс, под строкой, которая по очереди показывает, что вы использовали по всем ним, например токены за эту неделю и вашу самую используемую модель. В _Make something_ она предлагает стартовые промпты для новой темы, плагина, приложения или игры, которые передают задачу вашему агенту по умолчанию. Приложения создаются так же, как собственные Hype, Monologue и Omacut у Omarchy, на C++ и Qt Quick, следуя агентскому скиллу omarchy-make-app, а компилятор и нужные им компоненты Qt поставляются установленными. Игры — это одна страница three.js в `~/Games/vibes`, следующая агентскому скиллу omarchy-make-game, и все они открываются из одного лаунчера Game Vibes в текущей теме; они загружают three.js из веба, поэтому для запуска им нужно соединение. Claude Code, Codex, Grok, Kimi, Cursor и его лимит Grok Bot, GitHub Copilot, Muse, Antigravity, Kimchi и Devin поддерживаются из коробки с их лимитами, а Hermes, Mistral Vibe и Qwen Code показывают свои сессии и токены после того, как вы ими воспользуетесь. Планы провайдеров и ключи, которые вы используете через pi, omp или opencode, также отображаются: OpenCode Zen и Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan и Synthetic с их лимитами; Fireworks, OpenRouter и DeepSeek с их предоплаченными балансами; и модели, которые вы запускаете на собственном оборудовании, в разделе Local models. Каждый агент учитывается один раз, по тому, кто выставляет за него счёт, независимо от того, через сколько харнессов вы им управляете.

Щелчок левой кнопкой мыши по значку на панели открывает панель, щелчок правой кнопкой запускает вашего агента по умолчанию. Записи об использовании, лежащие в её основе, обновляются каждые 15 минут с помощью `omarchy agent usage-update`, а панель может даже объединять использование с ваших других машин через синхронизируемую папку. См. README в `$OMARCHY_PATH/shell/plugins/agents/` для всех настроек.

### Несколько подписок

Если вы платите более чем за один план Claude, Codex или Grok — скажем, личный Max и рабочий, — Omarchy может держать их все вошедшими и перемещаться между ними. Добавьте подписку с помощью + на панели агентов, которая проведёт вас через это прямо там, или с помощью `omarchy agent account add claude Work` (или `codex`, или `grok`). Она установит CLI, если его не хватает. Первый аккаунт для провайдера входит через ваш обычный браузер, прямо там, где CLI всегда ищет. Каждый последующий после этого входит через приватное окно, чтобы аккаунт, в который ваш браузер уже вошёл, не был подхвачен по ошибке; войдите там как аккаунт, который вы добавляете, и сначала закройте любое приватное окно, которое у вас уже открыто. Никогда не выходите из CLI для этого: выход отзывает сохранённый вход, и этот аккаунт придётся добавлять снова.

Чтобы скопировать входы по подпискам на другую машину Omarchy по SSH, запустите `omarchy agent account copy user@laptop`. Отправитель предоставляет временного получателя, когда на месте назначения он не установлен, поэтому более старые машины Omarchy могут получать аккаунты без обновления. Установленные получатели имеют приоритет. Это копирует все подписки Claude, Codex и Grok; добавьте имена провайдеров, чтобы выбрать их, как в `omarchy agent account copy laptop claude`. Имена аккаунтов и ID команд соответствуют источнику, включая аккаунты, уже присутствующие на месте назначения. Несвязанные аккаунты на месте назначения получают числовой суффикс, если их имена конфликтуют, а настройки, скиллы, плагины и история разговоров остаются локальными для каждой машины.

Существующие учётные данные на месте назначения сохраняются. Аккаунт источника, уже вошедший там, синхронизирует своё имя без замены его учётных данных; другие аккаунты добавляются рядом с ним. Чтобы заменить сохранённые учётные данные для совпадающих аккаунтов, используйте `omarchy agent account copy --replace laptop claude` после завершения сессий этого аккаунта на месте назначения. Свежее место назначения также получает активный аккаунт источника и предпочтения переключения; устоявшееся место назначения сохраняет свои собственные.

Учётные данные перемещаются через SSH и хранятся в приватных файлах на месте назначения, поэтому копируйте только на машины, которым вы доверяете. Это одноразовое копирование, а не постоянная синхронизация. Токены обновления Codex могут быть ротированы другой машиной, из-за чего скопированный вход будет нуждаться в обновлении; отдельные входы остаются самым надёжным выбором для одновременного использования на нескольких машинах. См. [руководство Codex по аутентификации аккаунтов](https://developers.openai.com/codex/auth/ci-cd-auth).

Один аккаунт на провайдера активен, и каждая новая сессия начинается как он: `cx`, `cy`, обычный `claude`, `codex` или `grok`, всё, что запущено через `omarchy agent`, а также скрипты или редакторы, которые находят CLI в `PATH`. Переключайтесь с помощью `omarchy agent account use work` (и обратно с помощью `omarchy agent account use main`) или на панели, нажав номер аккаунта, а затем `Enter` (или нажав его кнопку Use). Запущенные сессии Claude тоже переключаются, со своего следующего сообщения: каждая сессия Claude работает в `~/.claude`, который всегда хранит вход активного аккаунта. Сессия Claude, запущенная в собственной папке аккаунта более старой Omarchy, хранит этот вход до своего завершения, поэтому переключение называет эти сессии и завершается само, как только они исчезнут. Запущенные сессии Codex и Grok остаются на аккаунте, с которого они стартовали. История разговоров, настройки, скиллы и плагины являются общими для всех аккаунтов, поэтому `claude --continue` в той же папке продолжит с того места, где вы остановились на новом аккаунте.

При наличии более чем одного аккаунта панель показывает лимиты каждого аккаунта рядом, с отмеченным активным. По умолчанию Omarchy уведомляет вас, когда активный аккаунт превышает 95% лимита, и нажатие на уведомление переключает на аккаунт с наибольшим запасом. Наведите курсор на строку аккаунта на панели и нажмите Autoswitch, который появляется рядом с Use (или нажмите `m`), или запустите `omarchy agent account mode auto`, чтобы он переключался сам; пока он включён, Autoswitch занимает место Use, а повторное нажатие на него возвращает к уведомлениям. Добавьте число, чтобы изменить порог, как в `omarchy agent account mode auto 90`. Если каждый аккаунт превышает порог, вы услышите об этом один раз, вместе с тем, какой аккаунт освободится первым. Пока активный аккаунт находится в пределах 15 пунктов от своего порога (80% по умолчанию), его лимиты проверяются каждые три минуты, а не каждые 15.

`omarchy agent account list` показывает каждый аккаунт и его последние лимиты, `omarchy agent account remove work` забывает один, а `omarchy agent account rename primary Hey` переименовывает один (или нажмите на имя аккаунта на панели). Эти команды работают с аккаунтами вашего агента по умолчанию; чтобы добраться до другого провайдера, сначала назовите его, как в `omarchy agent account use codex side`. Вход, который у вас уже был в `~/.claude` или `~/.codex`, — это аккаунт _Main_. У Codex он остаётся там, где он есть; у Claude он ждёт в собственной папке, пока активен другой аккаунт. Аккаунт, оставленный неиспользованным более чем примерно на восемь часов, может показать _Sign-in required_; нажмите на него, чтобы снова войти в этот аккаунт прямо на панели, или переключитесь на него и начните сессию, которая обновит вход сама. MCP-серверы, которые вы добавляете с помощью `claude mcp add`, достигают каждого аккаунта Claude, поскольку все они работают в `~/.claude`; для Codex и Grok серверы, которые у вас были, когда аккаунт был добавлен, переходят вместе с ним, но более поздние достигают только того аккаунта, в котором вы их добавили. Claude Desktop хранит собственный вход, а инструменты Codex или Grok, настроенные с абсолютным путём к бинарному файлу CLI, не следуют за переключением. Явный `CLAUDE_CONFIG_DIR`, `CODEX_HOME` или `GROK_HOME` имеет приоритет над выбранным аккаунтом.

### Диагностика сбоев

Omarchy следит за systemd-coredump на предмет сбоев процессов. Когда что-то сегфолтится, вы получите уведомление "Process crashed" — нажмите на него, и сбой будет передан вашему агенту по умолчанию вместе со скиллом diagnose-crash у Omarchy, который проводит агента через установление фактов из дампа ядра и решение, стоит ли сообщать о сбое вверх по цепочке. Вы также можете запустить его вручную для любого PID из `coredumpctl list` с помощью `omarchy agent crash <pid>`.

Наблюдение включено по умолчанию. Отключите его в _Trigger > Toggle > Crash Capture_ (или с помощью `omarchy toggle crash-capture`), и уведомления прекратятся; `omarchy agent crash <pid>` по-прежнему работает вручную.

Сбои также можно заглушить по одной программе за раз, что диагностика и предлагает вам в конце. `omarchy crash mute hyprland` останавливает уведомления только для этой программы, `omarchy crash mute hyprland off` возвращает их обратно, а `omarchy crash mute` сам по себе перечисляет то, что вы заглушили. Он принимает путь к бинарному файлу так же охотно, как и его имя, поэтому `omarchy crash mute /usr/bin/hyprland` делает то же самое. Заключите имя с пробелом в кавычки, как в `omarchy crash mute 'Some App'`. Всё остальное по-прежнему уведомляет, а заглушенная программа по-прежнему падает — это скрывает напоминание, а не исправляет что-либо.

### Десктопные приложения

Меню _Install > AI_ также содержит несколько графических приложений ИИ: Antigravity Desktop, десктопное приложение ChatGPT, десктопное приложение Claude (бета-версия Anthropic для Linux, с вкладками Chat, Cowork и Claude Code), Grok Bot для общения с моделями xAI, Herdr Desktop, Hermes Desktop, OpenClaw, десктопное приложение Perplexity и T3 Code. Grok Bot — это десктопное приложение для чата. Кодинг-агент — это команда `grok`.

Hermes Desktop — это то, о чём стоит знать, потому что на машине один Hermes, и он принадлежит приложению: Hermes устанавливается только через приложение, и команда `hermes`, которую запускает агент по умолчанию, принадлежит приложению. Выбор Hermes в качестве агента по умолчанию устанавливает то же самое, что и пункт _Install > AI_: пакет и среду выполнения Hermes в `~/.hermes`, настроенную собственным установщиком Hermes, что в первый раз занимает несколько минут. Эта среда выполнения — это тот самый Hermes, который используют терминальная команда `hermes`, агент по умолчанию и приложение, и она обновляется сама с помощью `hermes update`, а не ждёт релиза Omarchy. Её установка также передаёт Hermes тему Omarchy в виде скина с именем `omarchy`, которому следует каждая поверхность Hermes при переключении вами тем; выберите другой в настройках Appearance у Hermes или с помощью `/skin`, если вы предпочитаете, чтобы он этого не делал, и Omarchy оставит этот выбор в покое. Удаление приложения в _Remove > AI_ сначала закрывает Hermes, включая шлюз, забирает эту среду выполнения с собой и сохраняет ваши чаты, воспоминания и скиллы, которые Hermes написал для себя, если только вы не скажете иначе: оно спрашивает, по умолчанию — нет, должна ли эта информация и ваши настройки подключения тоже уйти.

Десктопный опыт OpenClaw — это его Control UI, который открывается как веб-приложение, поддерживаемое его собственным локальным шлюзом. OpenClaw живёт в `~/.openclaw` и обновляется сам: используйте кнопку "Update Gateway" в Control UI или запустите `openclaw update`, и шлюз перезапустится на новой версии. Omarchy только выбирает релиз, с которого начинается свежая установка. Удаление OpenClaw в _Remove > AI_ забирает с собой службу шлюза и приложение, а затем спрашивает, должен ли `~/.openclaw` тоже уйти, поскольку там хранятся ваши чаты и учётные данные рядом с самим OpenClaw и средами выполнения плагинов, которые он загружает; по умолчанию он сохраняется, и повторная установка OpenClaw подхватит его обратно.

Herdr Desktop — это десктопное приложение [Herdr](https://herdr.dev): пространства, вкладки и панели терминалов и кодинг-агентов, которые продолжают работать в его ядре, когда вы закрываете окно. Оно поставляется из собственного установщика Herdr, а не из пакета, поэтому оно живёт в `~/.local/share/herdr-app`, приносит своё ядро с собой в `~/.local/bin/herdr-core`, когда у вас его ещё нет, и обновляет и то, и другое само. Оно находится рядом с командой `herdr`, которую Omarchy поставляет на `Super + Ctrl + Return`, а не заменяет её, и получает прямые клавиши этой команды: `Alt + Return` и `Alt + Shift + Return` делят панель вниз или вправо, `Alt + Escape` закрывает её, `Ctrl + Alt + Arrow` перемещает между панелями, `Alt + 1..9` и `Alt + Left/Right` выбирают вкладку, а `Alt + Up/Down` перемещают между пространствами. `Ctrl + 1..9` выбирает пространство, а `Alt + Shift + Up/Down` перебирает агентов. Префиксные клавиши `Ctrl + Space` остаются только для терминала, поскольку приложение не может удерживать обычную клавишу Ctrl для последовательности. Omarchy записывает их в `~/.config/herdr-app/keys.json`, а `omarchy-refresh-herdr-app` возвращает их обратно. Его установка выбирает тему Omarchy у Herdr, которая с этого момента следует за вашей темой Omarchy. Herdr хранит одну тему для светлого режима и одну для тёмного, поэтому после переключения между тёмной и светлой темой Omarchy выберите Omarchy в выборе темы Herdr ещё раз для другого режима.

T3 Code работает из своего официального релиза AppImage в `~/.local/share/t3code`, а не из пакета, поэтому он обновляется сам. Его установка спрашивает, начинать ли на канале Stable или Nightly; переключите позже в настройках T3 Code. Ваши треды и настройки живут в `~/.t3`, а удаление T3 Code в _Remove > AI_ забирает их с собой.

### Локальные модели

Запустите открытую модель на своей собственной машине для своих кодинг-агентов. Ваши промпты и код остаются на машине; ничто из отправленного модели не покидает её. Начните с:

```bash
omarchy agent local use best
```

Или на панели агентов на верхней панели выберите + , а затем Local AI, который появляется, когда модель подходит для этой машины. В первый раз это устанавливает Podman, который запускает модели, а на машине NVIDIA — контейнерный инструментарий NVIDIA, который даёт им GPU. Затем Omarchy выбирает рекомендуемую модель для этой машины, загружает её и запускает. Ожидайте загрузки в десятки GB и того, что большая часть памяти машины будет использоваться, пока модель работает: Flash Next использует около 100 GiB со своим полным контекстом 256K. Если другие модели занимают нужную ей память, она настраивается остановленной, готовой к запуску, как только вы остановите одну из них. Модель останавливается при выходе из системы; останавливайте её сами, когда вам нужна память для чего-то другого.

`omarchy agent local list` показывает варианты и объясняет, почему некоторые не подходят. Чтобы настроить другую, запустите `omarchy agent local use <recipe>`. На сегодняшний день `qwen3.8-flash-next-gufo` и `qwen3.8-27b-gufo` доступны для машин Strix Halo со 128 GB; 27B занимает около 40 GiB, поэтому она оставляет место для другой работы. На ноутбуке с 64 GB и Intel Arc B390 `qwen3.6-35b-a3b-llamacpp` работает примерно в 30 GiB. Новые рецепты и рекомендации поступают с `omarchy update` через пакет.

Каждая модель, которую вы настраиваете, получает свою собственную строку на панели агентов, рядом с вашими подписками: кнопка воспроизведения, чтобы запустить её, пауза, чтобы остановить её и освободить её память, и кнопка терминала, чтобы открыть вашего агента на ней. Несколько могут работать одновременно, когда они вместе помещаются в памяти; если одна не помещается, Omarchy говорит, какую запущенную модель остановить. Перетаскивайте строки, чтобы изменить их порядок, и нажимайте Delete на выбранной строке, чтобы удалить модель и её загрузку.

Каждая модель, которую вы настраиваете, также получает свою собственную запись в лаунчере приложений, под именем модели и с логотипом её создателя, так же как вход в Claude, Codex или Grok добавляет одну. Она открывает вашего агента на этой модели и сначала запускает модель, если она не работает: терминал показывает её загрузку и передаёт управление агенту, как только она будет готова. Удаление модели удаляет её запись.

Модель продолжает работать именно так, как она была настроена, поэтому обновление Omarchy никогда не перезапускает её под вашими агентами. Когда у Omarchy есть более новая среда выполнения или более новые веса для модели, которую вы настроили, её строка показывает кнопку обновления: нажмите её, и модель будет настроена снова в фоновом режиме, загружая только то, что изменилось, и перезапустится на новой версии. Модель, которая была остановлена, остаётся остановленной. `omarchy agent local update` делает то же самое для каждой модели из терминала.

Из командной строки `omarchy agent local start <recipe>` и `omarchy agent local stop <recipe>` делают то же самое, `omarchy agent local status` показывает каждую модель, а `omarchy agent --local` открывает вашего агента по умолчанию на последней модели, которую вы запустили. pi, OpenCode и Qwen Code могут использовать одну; при любом другом варианте по умолчанию она открывается в pi. pi также перечисляет каждую модель, которую вы настроили, и те, что находятся на машинах, с которыми вы сопряжены, в своём собственном выборе моделей, поэтому обычный `pi` тоже до них добирается. Любой клиент, совместимый с OpenAI, тоже может подключиться: `status` показывает адрес каждой модели (первый — `http://127.0.0.1:11435/v1`), имя рецепта — это модель, а ключ находится в `~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` удаляет модель и загрузки, которые не использует ни одна другая модель.

Сторонние среды выполнения помечены их издателем. Omarchy запускает каждую модель без доступа к сети.

### Локальные LLM

Omarchy рекомендует два способа запуска локальных моделей LLM: LM Studio и Ollama. LM Studio предоставляет графический интерфейс для поиска моделей с открытыми весами, их установки и запуска. Это отличный способ легко начать. Ollama предлагает CLI для того же самого похожим образом. Но если вы новичок в локальных моделях, я бы начал с LM Studio. Вы можете установить любой из них в _Install > AI_ в Omarchy Menu.

### Скилл Omarchy

Агентские скиллы помогают ИИ использовать конкретные инструменты конкретным способом, и Omarchy поставляется со скиллом по умолчанию для настройки системы. Например, настройка вашей конфигурации Hyprland, регулировка панели или даже создание новой темы с нуля. Он симлинкуется в каталоги скиллов для Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` и каждый `~/.hermes/profiles/*/skills`) и общее расположение `~/.agents/skills`, поэтому большинство харнессов подхватывают его автоматически.

Но вы должны относиться к этому скиллу как к экспериментальному. Разные модели будут использовать его с разным эффектом. Лучше всего сначала запускать в режиме планирования, чтобы у вас было представление о том, что агент хотел бы изменить. А затем будьте готовы откатить изменения или даже вызвать `omarchy reinstall configs`, если агент устроит беспорядок во всём.
