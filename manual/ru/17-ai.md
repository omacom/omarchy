# AI

Omarchy включает лаунчеры для перечисленных ниже агентов для программирования, не выбирая за вас вариант по умолчанию. Выполните команду, чтобы при первом использовании установить её CLI, затем пройдите аутентификацию, когда появится запрос. Hermes и OpenClaw — исключения: для них через mise ничего не устанавливается, а выбор любого из них настраивает его собственную самообновляющуюся копию, как объясняется в разделе _Desktop apps_ ниже.

### Установка и обновление агентов

За исключением Hermes и OpenClaw, эти агенты используют ленивую установку mise: при первом запуске устанавливается CLI, а при последующих запусках используется он. mise также проверяет установленный агент на наличие нового релиза не чаще одного раза в четыре часа, непосредственно перед его запуском или в фоне в приглашении оболочки. Если это обновление не удаётся или вы офлайн, запускается установленная версия. `omarchy update` обновляет установленные агенты вместе с остальной частью Omarchy, а `mup` обновляет только инструменты, управляемые mise.

Собственный обновлятор агента, такой как `claude update`, `codex update` или кнопка обновления в приложении, не обновляет установку, управляемую mise. `codex update` завершается ошибкой, а `claude update` может сообщить об успехе, при этом установив отдельную копию, которую mise не отслеживает. Если вы предпочитаете использовать нативный установщик и обновлятор агента, добавьте его в `disable_tools`; см. [Предустановленные инструменты CLI](18-development-tools.md#preinstalled-cli-tools).

Чтобы установить все настроенные ленивые инструменты до того, как они понадобятся, выполните `mise install --include-lazy`. Это включает также другие инструменты CLI Omarchy по умолчанию, а также агентов. См. [Предустановленные инструменты CLI](18-development-tools.md#preinstalled-cli-tools) для установки одного инструмента или использования вашей собственной установки.

`grok` устанавливается через фирменный пакет `grok` в mise, так же как `claude` и `codex`. Запустите `grok` или выберите его в _Agent > Harness_. Пропустите установщик `curl | bash` на x.ai. Этот путь помещает вторую копию в `~/.grok/bin`, ставит её первой в `PATH` и перезаписывает обёртку Omarchy.

`dsh` открывает его браузерный UI на `127.0.0.1:3080`, с каталогом запуска в качестве рабочего пространства по умолчанию. Его браузерный UI не принимает начальный запрос, поэтому `omarchy agent prompt` открывает его с запросом в буфере обмена для вставки. Omarchy запускает его с пресетом разрешений DeepSeek без подтверждений. DeepSeek Harness загружает журналы сессий в DeepSeek, когда вы используете его официальный API моделей; отключите это в _Settings > General > Upload Session Log_ в его браузерном UI. Отправляемая вами обратная связь также загружается вместе с сессией, если вы не запустите его с `DSH_TELEMETRY_MODE=DISABLED`.

### Агент по умолчанию

Выберите агента по умолчанию с помощью `omarchy default agent <name>` или в _Agent > Harness_ в меню Omarchy (`Super + Space`). Если агент ещё не установлен, выбор его сначала установит его, и у него также появится собственный лаунчер в лаунчере приложений, рядом с Agent. Свежая Omarchy пригласит вас сделать этот выбор с помощью однократного уведомления.

Выбор Claude также пытается настроить его расширение для браузера для Chromium, Chrome, Brave, Brave Origin и Edge. Настройка расширения применяется ко всем пользователям и может запросить ваш системный пароль; отмена или неудачная установка расширения всё равно выбирает и запускает Claude. Перезапустите браузер, включите расширение, если появится запрос, и войдите в Claude, чтобы завершить подключение. Запустите `/chrome` в Claude, чтобы проверить соединение. Firefox и Zen не поддерживают это расширение. Если Claude уже был вашим агентом по умолчанию до добавления этой настройки, выберите его снова, чтобы установить расширение.

После того как вы сделали выбор, `Super + Shift + Ctrl + A` запускает агента по умолчанию в отдельном окне терминала (или вызывает выбор, если вы ещё не выбрали). Вы также можете запустить его сразу для задачи с помощью `omarchy agent prompt "Review this project"`. Freebuff и DeepSeek Harness не принимают начальный запрос, поэтому они открываются с запросом в буфере обмена для вставки вместо этого. Агенты, запущенные таким образом, работают без присмотра в их соответствующих режимах «не останавливайся, чтобы спросить», поэтому будьте готовы к тому, что они действительно будут что-то делать! У MiniMax Code нет такого режима для его интерактивных сессий, поэтому он запрашивает разрешения как обычно. И поскольку агенты отказываются запоминать доверие для вашего домашнего каталога, запуски из `$HOME` начинаются в `~/Work` вместо этого.

Также есть ярлыки терминала: `a` запускает агента по умолчанию встроенно в текущем терминале, в то время как `c`, `cx` и `cy` запускают OpenCode, Claude Code и Codex напрямую (снова в их режимах автоматического подтверждения). Изменения темы также синхронизируются с агентами: Claude Code, Pi, OpenCode и Hermes (после того как Omarchy установила его) все следуют за вами, когда вы переключаете тему Omarchy.

### Инструкции вашего агента

Личные правила для каждого агента помещаются в `~/.agents/AGENTS.md`, рядом с общими навыками в `~/.agents/skills`. Откройте его в _Agent > Instructions_, который также связывает его с каждой обёрткой, которая хранит свой собственный глобальный файл: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` у Copilot и так далее. Crush и Amp читают ссылку `~/.config/AGENTS.md`, в то время как omp, Kimi и DeepSeek Harness читают `~/.agents/AGENTS.md` напрямую. Выбор агента по умолчанию также связывает его. Файл инструкций, который у вас уже был, становится общим, если его ещё не было; в противном случае он сохраняется рядом со ссылкой как `.bak`. Выполните `omarchy agent instructions`, чтобы повторно связать после установки другого агента.

### Панель агентов

На верхней панели есть значок агентов. До того как вы настроили агента, его панель проведёт вас через вход в Claude, Codex или Grok, и первый из них станет вашим агентом по умолчанию. После этого панель размещает каждую подписку на одной странице: каждый агент и учётная запись с его планом, измеритель для каждого из его 5-часовых сессионных и недельных лимитов со временем до его сброса (наведите курсор для точного процента), или оставшийся предоплаченный баланс, под строкой, которая чередует то, что вы использовали по всем ним, например токены на этой неделе и вашу наиболее используемую модель. В разделе _Make something cool_ она предлагает стартовые запросы для новой темы, плагина, приложения или игры, которые передают задачу вашему агенту по умолчанию. Приложения создаются так же, как собственные Hype, Monologue и Omacut в Omarchy, на C++ и Qt Quick, следуя навыку агента omarchy-make-app, и компилятор и части Qt, которые им нужны, поставляются установленными. Игры представляют собой одну страницу three.js в `~/Games/vibes`, следуя навыку агента omarchy-make-game, и все открываются из одного лаунчера Game Vibes в текущей теме; они загружают three.js из веба, поэтому им нужно соединение для запуска. Claude Code, Codex, Grok, Kimi, Cursor и его лимит Grok Bot, GitHub Copilot, Muse, Antigravity и Devin покрываются из коробки с их лимитами, Kimchi с его планом, предоплаченными кредитами и бюджетами расходов, а Hermes, Mistral Vibe и Qwen Code показывают их сессии и токены после того, как вы их использовали. Планы провайдеров и ключи, которые вы используете через pi, omp или opencode, также отображаются: OpenCode Zen и Go, план Z.ai GLM Coding Plan, Ollama Cloud, план MiniMax Token Plan и Synthetic с их лимитами; OpenRouter и DeepSeek с их предоплаченными балансами; Fireworks с его расходами за последние 30 дней. Токены от моделей, которые вы запускаете на своём собственном оборудовании, также учитываются в итоговых суммах; сами модели имеют собственную панель, описанную в [Локальные модели](#local-models). Каждый агент учитывается один раз, по тому, кто его оплачивает, независимо от того, через сколько обёрток вы его используете.

Щёлкните левой кнопкой мыши на значке панели или нажмите `Super + Ctrl + X` для панели, правой кнопкой — чтобы запустить вашего агента по умолчанию, а средней кнопкой — чтобы обновить. Записи об использовании, лежащие в его основе, перегенерируются каждые 15 минут с помощью `omarchy agent usage update`, и панель может даже объединять использование с ваших других машин через синхронизируемую папку. См. README в `$OMARCHY_PATH/shell/plugins/agents/` для полного списка настроек.

### Несколько подписок

Если вы платите более чем за один план Claude, Codex или Grok — личный Max и рабочий, скажем, — Omarchy может держать их всех вошедшими и перемещаться между ними. Добавьте подписку с помощью + на панели агентов, которая проведёт вас через это прямо там, или с помощью `omarchy agent account add claude Work` (или `codex`, или `grok`). Она устанавливает CLI, если он отсутствует. Первая учётная запись для провайдера входит через ваш обычный браузер, прямо там, где CLI всегда ищет. Каждая следующая после этого входит через приватное окно, чтобы учётная запись, в которую ваш браузер уже вошёл, не была выбрана по ошибке; войдите там как учётная запись, которую вы добавляете, и сначала закройте любое уже открытое приватное окно. Никогда не выходите из CLI для этого: выход отзывает сохранённый вход, и эту учётную запись придётся добавлять снова.

Чтобы скопировать входы вашей подписки на другую машину Omarchy по SSH, выполните `omarchy agent account copy user@laptop`. Отправитель предоставляет временного получателя, когда на месте назначения он не установлен, поэтому старые машины Omarchy могут получать учётные записи без обновления. Установленные получатели имеют приоритет. Это копирует все подписки Claude, Codex и Grok; добавьте имена провайдеров, чтобы выбрать их, как в `omarchy agent account copy laptop claude`. Имена учётных записей и ID команд соответствуют источнику, включая учётные записи, уже присутствующие на месте назначения. Не связанные учётные записи на месте назначения получают числовой суффикс, если их имена конфликтуют, а настройки, навыки, плагины и история разговоров остаются локальными для каждой машины.

Существующие учётные данные на месте назначения сохраняются. Учётная запись источника, уже вошедшая там, синхронизирует своё имя без замены её учётных данных; другие учётные записи добавляются рядом с ней. Чтобы заменить сохранённые учётные данные для совпадающих учётных записей, используйте `omarchy agent account copy --replace laptop claude` после выхода из сессий этой учётной записи на месте назначения. Свежее место назначения также получает активную учётную запись источника и предпочтения переключения; устоявшееся место назначения сохраняет свои собственные.

Учётные данные перемещаются через SSH и хранятся в приватных файлах на месте назначения, поэтому копируйте только на машины, которым вы доверяете. Это однократное копирование, а не постоянная синхронизация. Токены обновления Codex могут быть ротированы другой машиной, из-за чего скопированный вход будет нуждаться в обновлении; отдельные входы остаются наиболее надёжным выбором для одновременного использования на нескольких машинах. См. [Руководство Codex по аутентификации учётной записи](https://developers.openai.com/codex/auth/ci-cd-auth).

Одна учётная запись на провайдера активна, и каждая новая сессия начинается как она: `cx`, `cy`, обычный `claude`, `codex` или `grok`, всё, что запускается через `omarchy agent`, и скрипты или редакторы, которые находят CLI в `PATH`. Переключайтесь с помощью `omarchy agent account use work` (и обратно с помощью `omarchy agent account use main`), или на панели, нажав номер учётной записи, а затем `Enter` (или нажав её кнопку Use). Запущенные сессии Claude также переключаются, со следующего сообщения: каждая сессия Claude запускается в `~/.claude`, которая всегда содержит вход активной учётной записи. Сессия Claude, запущенная в собственной папке учётной записи старой Omarchy, сохраняет этот вход до выхода, поэтому переключатель называет эти сессии и завершается самостоятельно после их исчезновения. Запущенные сессии Codex и Grok остаются на учётной записи, с которой они начали. История разговоров, настройки, навыки и плагины общие для всех учётных записей, поэтому `claude --continue` в той же папке продолжит с того места, где вы остановились на новой учётной записи.

С более чем одной учётной записью панель показывает лимиты каждой учётной записи бок о бок, с отмеченной активной. По умолчанию Omarchy уведомляет вас, когда активная учётная запись превышает 95% лимита, и нажатие на уведомление переключается на учётную запись с наибольшим запасом. Наведите курсор на строку учётной записи на панели и нажмите Autoswitch, который появляется рядом с Use (или нажмите `m`), или выполните `omarchy agent account mode auto`, чтобы он переключался сам; пока он включён, Autoswitch занимает место Use, и повторное нажатие на него возвращает к уведомлениям. Добавьте число, чтобы изменить порог, как в `omarchy agent account mode auto 90`. Если каждая учётная запись превышает порог, вы услышите об этом один раз, вместе с тем, какая учётная запись освободится первой. Пока активная учётная запись находится в пределах 15 пунктов от её порога (80% по умолчанию), её лимиты проверяются каждые три минуты, а не каждые 15.

`omarchy agent account list` показывает каждую учётную запись и её последние лимиты, `omarchy agent account remove work` забывает одну, а `omarchy agent account rename primary Hey` переименовывает одну (или нажмите на имя учётной записи на панели). Эти команды работают с учётными записями вашего агента по умолчанию; чтобы добраться до другого провайдера, сначала назовите его, как в `omarchy agent account use codex side`. Вход, который у вас уже был в `~/.claude` или `~/.codex`, является учётной записью _Main_. У Codex она остаётся там, где она есть; у Claude она ждёт в собственной папке, пока активна другая учётная запись. Учётная запись, оставленная неиспользованной более примерно восьми часов, может показать _Sign-in required_; нажмите на неё, чтобы снова войти в эту учётную запись прямо на панели, или переключитесь на неё и начните сессию, которая обновит вход сама. MCP-серверы, которые вы добавляете с помощью `claude mcp add`, достигают каждой учётной записи Claude, поскольку все они запускаются в `~/.claude`; для Codex и Grok серверы, которые у вас были, когда учётная запись была добавлена, переходят вместе с ней, но более поздние достигают только учётной записи, в которой вы их добавили. Claude Desktop хранит собственный вход, а инструменты Codex или Grok, настроенные с абсолютным путём к бинарнику CLI, не следуют за переключателем. Явный `CLAUDE_CONFIG_DIR`, `CODEX_HOME` или `GROK_HOME` имеет приоритет над выбранной учётной записью.

### Диагностика сбоев

Omarchy следит за systemd-coredump на предмет сбоев процессов. После того как вы выбрали агента по умолчанию, любая ваша программа, которая сбрасывает core, вызывает уведомление "Process crashed" — нажмите на него, и сбой передаётся вашему агенту по умолчанию вместе с навыком omarchy-diagnose-crash Omarchy, который проводит агента через установление фактов из дампа core и решение, стоит ли сообщать о сбое в upstream. Вы также можете запустить его вручную для любого PID из `coredumpctl list` с помощью `omarchy agent crash <pid>`.

Наблюдение включено по умолчанию. Отключите его в _Trigger > Toggle > Crash Capture Off_ (или с помощью `omarchy toggle crash-capture`), и уведомления прекратятся; `omarchy agent crash <pid>` по-прежнему работает вручную.

Сбои также можно заглушить по одной программе за раз, что диагностика предлагает вам в конце. `omarchy crash mute hyprland` прекращает уведомления только для этой программы, `omarchy crash mute hyprland off` возвращает их, а `omarchy crash mute` сам по себе перечисляет то, что вы заглушили. Он принимает путь бинарника так же охотно, как его имя, поэтому `omarchy crash mute /usr/bin/hyprland` делает то же самое. Заключите имя с пробелом в кавычки, как в `omarchy crash mute 'Some App'`. Всё остальное по-прежнему уведомляет, а заглушённая программа по-прежнему вылетает — это скрывает напоминание, это ничего не исправляет.

### Настольные приложения

Меню _Install > AI_ также содержит несколько графических приложений AI: Amp Desktop, Antigravity Desktop, настольное приложение ChatGPT, настольное приложение Claude (бета-версия Anthropic для Linux, с вкладками Chat, Cowork и Claude Code), Grok Bot для общения с моделями xAI, Herdr Desktop, Hermes Desktop, OpenClaw, настольное приложение Perplexity и T3 Code. Grok Bot — это настольное приложение для чата. Агент для программирования — это команда `grok`.

Hermes Desktop — это то, о чём стоит знать, потому что у машины один Hermes, и он принадлежит приложению: Hermes устанавливается только через приложение, и команда `hermes`, которую запускает агент по умолчанию, принадлежит приложению. Выбор Hermes в качестве агента по умолчанию устанавливает то же, что и запись _Install > AI_: пакет и среду выполнения Hermes в `~/.hermes`, настроенную собственным установщиком Hermes, что занимает несколько минут в первый раз. Эта среда выполнения — тот единственный Hermes, который используют терминальная команда `hermes`, агент по умолчанию и приложение, и она обновляет себя с помощью `hermes update`, а не ждёт релиза Omarchy. Установка его также даёт Hermes тему Omarchy в качестве скина с именем `omarchy`, которому следует каждая поверхность Hermes при переключении тем; выберите другую в настройках Appearance Hermes или с помощью `/skin`, если вы предпочитаете, чтобы этого не было, и Omarchy оставит этот выбор в покое. Удаление приложения в _Remove > AI_ сначала закрывает Hermes, включая шлюз, забирает эту среду выполнения с собой и сохраняет ваши чаты, воспоминания и навыки, которые Hermes написал для себя, если вы не скажете иначе: оно спрашивает, по умолчанию — нет, должна ли эта информация и ваши настройки подключения также уйти.

Настольный опыт OpenClaw — это его Control UI, который открывается как веб-приложение, поддерживаемое его собственным локальным шлюзом. OpenClaw живёт в `~/.openclaw` и обновляет себя: используйте кнопку "Update Gateway" в Control UI или выполните `openclaw update`, и шлюз перезапустится на новой версии. Omarchy выбирает только релиз, с которого начинается свежая установка. OpenClaw также может быть вашим агентом по умолчанию: выбор его в _Agent > Harness_ настраивает ту же копию в `~/.openclaw`, и агент открывает терминальный UI OpenClaw, подключённый к его шлюзу. Удаление OpenClaw в _Remove > AI_ забирает службу шлюза и приложение с собой, а затем спрашивает, должна ли `~/.openclaw` также уйти, поскольку там хранятся ваши чаты и учётные данные вместе с самим OpenClaw и средами выполнения плагинов, которые он загружает; по умолчанию она сохраняется, и повторная установка OpenClaw снова её подхватит.

Herdr Desktop — это настольное приложение [Herdr](https://herdr.dev): пространства, вкладки и панели терминалов и агентов для программирования, которые продолжают работать в его ядре, когда вы закрываете окно. Оно поставляется из собственного установщика Herdr, а не из пакета, поэтому оно живёт в `~/.local/share/herdr-app`, приносит своё ядро вместе в `~/.local/bin/herdr-core`, когда у вас его ещё нет, и обновляет оба самостоятельно. Оно находится рядом с командой `herdr`, которую Omarchy поставляет на `Super + Ctrl + Return`, а не заменяет её, и получает прямые клавиши этой команды: `Alt + Return` и `Alt + Shift + Return` делят панель вниз или вправо, `Alt + Escape` закрывает её, `Ctrl + Alt + Arrow` перемещается между панелями, `Alt + 1..9` и `Alt + Left/Right` выбирают вкладку, а `Alt + Up/Down` перемещаются между пространствами. `Ctrl + 1..9` выбирает пространство, а `Alt + Shift + Up/Down` проходит по агентам. Префиксные клавиши `Ctrl + Space` остаются только терминальными, поскольку приложение не может удерживать обычную клавишу Ctrl для последовательности. Omarchy записывает их в `~/.config/herdr-app/keys.json`, а `omarchy-refresh-herdr-app` возвращает их обратно. Установка его выбирает тему Omarchy в Herdr, которая с тех пор следует вашей теме Omarchy. Herdr хранит одну тему для светлого режима и одну для тёмного, поэтому после переключения между тёмной и светлой темой Omarchy выберите Omarchy в выборе тем Herdr ещё раз для другого режима.

T3 Code запускается из его официального релиза AppImage в `~/.local/share/t3code`, а не из пакета, поэтому обновляет себя сам. Установка его спрашивает, начинать ли с канала Stable или Nightly; переключите позже в настройках T3 Code. Ваши потоки и настройки живут в `~/.t3`, и удаление T3 Code в _Remove > AI_ забирает их с собой.

### Локальные модели

Запустите открытую модель на своей собственной машине для ваших агентов для программирования. Ваши запросы и код остаются на машине; ничего, отправленного модели, не покидает её. Начните с:

```bash
omarchy models use best text
```

Это настраивает лучшую текстовую модель для этой машины, тип, который используют ваши агенты. Модели изображений, видео и музыки имеют свою лучшую: `omarchy models use best image`, `video` или `music`. Выполните `omarchy models use best`, чтобы увидеть выбор каждого типа для этой машины.

Или откройте панель локальных моделей с её значка блёсток на верхней панели, рядом со значком агентов, или с помощью Super + Ctrl + Shift + X, и выберите +. Значок появляется, когда модель подходит для этой машины. Podman, который запускает модели, поставляется с Omarchy, как и набор инструментов контейнера NVIDIA на машине NVIDIA, который даёт им GPU; если чего-либо из этого не хватает, первая настройка устанавливает его. Затем Omarchy выбирает рекомендуемую модель для этой машины, загружает её и запускает. Ожидайте загрузки в десятки GB и использования большей части памяти машины во время работы модели: Flash Next использует около 100 GiB с его полным контекстом 256K. Если другие модели удерживают нужную ей память, она настраивается остановленной, готовой к запуску после того, как вы остановите одну. Модель останавливается при выходе из системы; остановите её сами, когда вам нужна память для чего-то другого.

`omarchy models list` показывает варианты и объясняет, почему некоторые не подходят. Чтобы настроить другую, выполните `omarchy models use <recipe>`. Сегодня `qwen3.8-flash-next-gufo` и `qwen3.8-27b-gufo` доступны для машин Strix Halo на 128 GB; 27B занимает около 40 GiB, поэтому оставляет место для другой работы. На ноутбуке 64 GB с Intel's Arc B390 `qwen3.6-35b-a3b-llamacpp` работает примерно в 30 GiB. Новые рецепты и рекомендации поступают с `omarchy update`, через пакет.

Каждая модель, которую вы настраиваете, получает свою собственную строку на панели локальных моделей: play, чтобы запустить её, pause, чтобы остановить её и освободить её память, и кнопка терминала, чтобы открыть вашего агента на ней. В верхней части полоса показывает, как память машины разделена между самой Omarchy (системой и вашими приложениями), каждой работающей моделью и тем, что свободно. Укажите на остановленную модель, и полоса покажет, подходит ли она или насколько ей не хватает. Несколько могут работать одновременно, когда они помещаются в памяти вместе; если одна не подходит, Omarchy говорит, какую работающую модель остановить. Перетаскивайте строки за их логотип, чтобы переупорядочить их, и нажимайте Delete на выбранной строке, чтобы удалить модель и её загрузку.

Каждая модель, которую вы настраиваете, также получает свою собственную запись в лаунчере приложений, под именем модели и с логотипом её создателя, так же как вход в Claude, Codex или Grok добавляет одну. Она открывает вашего агента на этой модели и сначала запускает модель, если она не работает: терминал показывает её загрузку и передаёт управление агенту, как только она будет готова. Удаление модели удаляет её запись.

Не каждая модель предназначена для программирования. Модели изображений, видео и музыки открываются в Fantasi вместо этого, приложении Omarchy для создания картинок, видео и музыки с моделью, работающей на этой машине, из их записи лаунчера и из их строки на панели локальных моделей.

Модель продолжает работать точно так, как была настроена, поэтому обновление Omarchy никогда не перезапускает её под вашими агентами. Когда у Omarchy есть более новая среда выполнения или более новые веса для модели, которую вы настроили, её строка показывает кнопку обновления: нажмите её, и модель настраивается снова в фоне, загружая только то, что изменилось, и перезапускается на новой версии. Модель, которая была остановлена, остаётся остановленной. `omarchy models update` делает то же самое для каждой модели из терминала.

Из командной строки `omarchy models start <recipe>` и `omarchy models stop <recipe>` делают то же самое, `omarchy models status` показывает каждую модель, а `omarchy agent --local` открывает вашего агента по умолчанию на последней модели, которую вы запустили. pi, OpenCode и Qwen Code могут использовать одну; с любым другим по умолчанию она открывается в pi или в OpenCode, если у вас нет pi. pi также перечисляет каждую модель, которую вы настроили, и те, что на машинах, с которыми вы спарились, в своём собственном выборе моделей, поэтому обычный `pi` также достигает их. Любой клиент, совместимый с OpenAI, также может подключиться: `status` показывает адрес каждой модели (первый — `http://127.0.0.1:11435/v1`), имя рецепта является моделью, а ключ находится в `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` удаляет модель и загрузки, которые никакая другая модель не использует.

Сторонние среды выполнения помечаются их издателем. Omarchy запускает каждую модель без доступа к сети.

### Локальные LLM

Omarchy рекомендует два способа запуска локальных моделей LLM: LM Studio и Ollama. LM Studio предоставляет графический интерфейс для поиска моделей с открытыми весами, их установки и запуска. Это отличный способ легко начать. Ollama предлагает CLI для того же самого похожим образом. Но если вы новичок в локальных моделях, я бы начал с LM Studio. Вы можете установить любой из них в _Install > AI_ в меню Omarchy.

### Навыки Omarchy

Навыки агента помогают AI использовать конкретные инструменты конкретным способом, и Omarchy поставляет семь из них. Навык omarchy охватывает настройку системы, например настройку вашей конфигурации Hyprland или регулировку панели. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app и omarchy-make-game охватывают создание чего-то нового, omarchy-contribute охватывает сообщение об ошибке или отправку исправления в upstream, а omarchy-diagnose-crash работает с дампом core сбоя. Они симлинкуются в каталоги навыков для Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` и каждый `~/.hermes/profiles/*/skills`) и общее местоположение `~/.agents/skills`, поэтому большинство обёрток подхватывают их автоматически. Папка навыков вашей собственной с тем же именем имеет приоритет.

Но вы должны относиться к этим навыкам как к экспериментальным. Разные модели будут использовать его с разным эффектом. Лучше сначала запускать в режиме плана, чтобы у вас было представление о том, что агент хотел бы изменить. А затем быть готовым откатить изменения или даже вызвать `omarchy reinstall configs`, если агент устроит беспорядок во всём.
