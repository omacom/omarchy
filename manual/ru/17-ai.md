# AI

В Omarchy есть лаунчеры для перечисленных ниже агентов для кодинга, и ни один из них не выбран за вас по умолчанию. Запустите команду, чтобы при первом использовании установить её CLI, а затем при появлении запроса пройдите аутентификацию. Hermes и OpenClaw — исключения: для них через mise ничего не устанавливается, а выбор любого из них устанавливает его собственную самообновляющуюся копию, как объясняется ниже в разделе _Десктопные приложения_.

### Установка и обновление агентов

За исключением Hermes и OpenClaw, эти агенты используют ленивую установку mise: первый запуск устанавливает CLI, а последующие запуски используют его повторно. mise также проверяет, не вышла ли новая версия установленного агента, не чаще одного раза в четыре часа, непосредственно перед его запуском или в фоне в приглашении оболочки. Если это обновление не удаётся или вы не в сети, запускается установленная версия. `omarchy update` обновляет установленных агентов вместе с остальной частью Omarchy, а `mup` обновляет только инструменты, управляемые mise.

Собственный механизм обновления агента, например `claude update`, `codex update` или кнопка обновления в приложении, не обновляет установку, управляемую mise. `codex update` завершается ошибкой, а `claude update` может сообщить об успехе, установив при этом отдельную копию, которую mise не отслеживает. Если вы предпочитаете использовать родной установщик и механизм обновления агента, добавьте его в `disable_tools`; см. [Предустановленные инструменты CLI](18-development-tools.md#preinstalled-cli-tools).

Чтобы установить все настроенные ленивые инструменты до того, как они вам понадобятся, выполните `mise install --include-lazy`. Это включает другие инструменты CLI Omarchy по умолчанию, а также агентов. См. [Предустановленные инструменты CLI](18-development-tools.md#preinstalled-cli-tools) для установки одного инструмента или использования собственной установки.

`grok` устанавливается через фирменный пакет `grok` в mise, так же, как `claude` и `codex`. Запустите `grok` или выберите его в _Agent > Harness_. Пропустите установщик `curl | bash` на x.ai. Этот путь помещает вторую копию в `~/.grok/bin`, ставит её первой в `PATH` и перезаписывает обёртку Omarchy.

`dsh` открывает свой браузерный UI на `127.0.0.1:3080`, а каталог запуска используется как рабочее пространство по умолчанию. Его браузерный UI не принимает стартовый промпт, поэтому `omarchy agent prompt` открывает его с промптом в буфере обмена, чтобы вы могли его вставить. Omarchy запускает его с пресетом разрешений DeepSeek без подтверждений. DeepSeek Harness загружает журналы сессий в DeepSeek, когда вы используете его официальный API моделей; отключите это в _Settings > General > Upload Session Log_ в его браузерном UI. Отправляемые вами отзывы также загружаются вместе с сессией, если только вы не запустите его с `DSH_TELEMETRY_MODE=DISABLED`.

### Агент по умолчанию

Выберите агента по умолчанию с помощью `omarchy default agent <name>` или в _Agent > Harness_ в Omarchy Menu (`Super + Space`). Если агент ещё не установлен, выбор сначала установит его, и у него также появится собственный лаунчер в лаунчере приложений, рядом с Agent. Свежая установка Omarchy предложит вам сделать этот выбор однократным уведомлением.

Выбор Claude также пытается настроить его расширение для браузера для Chromium, Chrome, Brave, Brave Origin и Edge. Настройка расширения применяется ко всем пользователям и может запросить ваш системный пароль; отмена или неудачная установка расширения всё равно выбирает и запускает Claude. Перезапустите браузер, включите расширение при появлении запроса и войдите в Claude, чтобы завершить его подключение. Выполните `/chrome` в Claude, чтобы проверить соединение. Firefox и Zen это расширение не поддерживают. Если Claude уже был вашим агентом по умолчанию до добавления этой настройки, выберите его снова, чтобы установить расширение.

После того как вы сделали выбор, `Super + Shift + Ctrl + A` запускает агента по умолчанию в отдельном окне терминала (или вызывает выбор, если вы ещё не выбрали). Вы также можете запустить его сразу с задачей с помощью `omarchy agent prompt "Review this project"`. Freebuff и DeepSeek Harness не принимают стартовый промпт, поэтому вместо этого они открываются с промптом в буфере обмена, чтобы вы могли его вставить. Запущенные таким образом агенты работают без присмотра в своих режимах «не останавливайся, чтобы спросить», так что будьте готовы к тому, что они действительно будут что-то делать! У MiniMax Code такого режима для интерактивных сессий нет, поэтому он запрашивает разрешения как обычно. А поскольку агенты отказываются запоминать доверие для вашего домашнего каталога, запуски из `$HOME` вместо этого начинаются в `~/Work`.

Есть и ярлыки в терминале: `a` запускает агента по умолчанию прямо в текущем терминале, а `c`, `cx` и `cy` запускают OpenCode, Claude Code и Codex напрямую (опять же в их режимах с автоматическим подтверждением). Смена темы также синхронизируется с агентами: Claude Code, Pi, OpenCode и Hermes (после того как Omarchy его установит) следуют за вами, когда вы переключаете тему Omarchy.

### Инструкции для ваших агентов

Личные правила для каждого агента находятся в `~/.agents/AGENTS.md`, рядом с общими скиллами в `~/.agents/skills`. Откройте его в _Agent > Instructions_, который также связывает его с каждым harness-ом, хранящим свой собственный глобальный файл: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` у Copilot и так далее. Crush и Amp читают ссылку `~/.config/AGENTS.md`, а omp, Kimi и DeepSeek Harness читают `~/.agents/AGENTS.md` напрямую. Выбор агента по умолчанию также связывает его. Файл инструкций, который у вас уже был, становится общим, если его ещё не было; в противном случае он сохраняется рядом со ссылкой как `.bak`. Выполните `omarchy agent instructions`, чтобы повторно связать после установки ещё одного агента.

### Панель агентов

В верхней панели есть значок агентов. Пока вы не настроили агента, его панель проведёт вас через вход в Claude, Codex или Grok, и первый из них станет вашим агентом по умолчанию. После этого панель размещает все подписки на одной странице: каждый агент и аккаунт с его тарифом, индикатор для каждого из его лимитов 5-часовой сессии и недельного лимита со временем до сброса (наведите курсор, чтобы увидеть точный процент) или остаток предоплаченного баланса, под строкой, которая по очереди показывает, что вы использовали по всем ним, например токены за эту неделю и вашу самую используемую модель. В разделе _Make something cool_ она предлагает стартовые промпты для новой темы, плагина, приложения или игры, которые передают задачу вашему агенту по умолчанию. Приложения создаются так же, как собственные приложения Omarchy Hype, Monologue и Omacut, на C++ и Qt Quick, следуя скиллу агента omarchy-make-app, а необходимый им компилятор и компоненты Qt уже установлены. Игры — это одна страница three.js в `~/Games/vibes`, созданная по скиллу агента omarchy-make-game, и все они открываются из одного лаунчера Game Vibes в текущей теме; они загружают three.js из сети, поэтому для запуска им нужно соединение. Claude Code, Codex, Grok, Kimi, Cursor и его лимит Grok Bot, GitHub Copilot, Muse, Antigravity и Devin поддерживаются из коробки с их лимитами, Kimchi — с его тарифом, предоплаченными кредитами и бюджетами расходов, а Hermes, Mistral Vibe и Qwen Code показывают свои сессии и токены, как только вы ими воспользуетесь. Тарифы провайдеров и ключи, которые вы используете через pi, omp или opencode, также отображаются: OpenCode Zen и Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan и Synthetic с их лимитами; OpenRouter и DeepSeek с их предоплаченными балансами; Fireworks с его расходами за последние 30 дней; и модели, которые вы запускаете на собственном оборудовании, в разделе Local models. Каждый агент учитывается один раз, у того, кто выставляет за него счёт, независимо от того, через сколько harness-ов вы им управляете.

Щёлкните левой кнопкой мыши по значку на панели или нажмите `Super + Ctrl + X`, чтобы открыть панель, щёлкните правой кнопкой, чтобы запустить агента по умолчанию, и средней кнопкой, чтобы обновить. Записи об использовании, лежащие в её основе, перегенерируются каждые 15 минут с помощью `omarchy agent usage update`, а панель может даже объединять использование с ваших других машин через синхронизируемую папку. См. README в `$OMARCHY_PATH/shell/plugins/agents/` для всех настроек.

### Несколько подписок

Если вы платите за несколько тарифов Claude, Codex или Grok — например, личный Max и рабочий, — Omarchy может держать их все авторизованными и переключаться между ними. Добавьте подписку с помощью + в панели агентов, которая проведёт вас через это прямо там, или с помощью `omarchy agent account add claude Work` (или `codex`, или `grok`). Если CLI отсутствует, он будет установлен. Первый аккаунт провайдера входит через ваш обычный браузер, именно там, где CLI всегда его ищет. Каждый последующий входит через приватное окно, чтобы аккаунт, в который ваш браузер уже вошёл, не был подхвачен по ошибке; войдите там как аккаунт, который вы добавляете, и сначала закройте любое уже открытое приватное окно. Никогда не выходите из CLI для этого: выход отзывает сохранённый вход, и этот аккаунт придётся добавлять снова.

Чтобы скопировать входы по подпискам на другую машину с Omarchy через SSH, выполните `omarchy agent account copy user@laptop`. Отправитель предоставляет временного получателя, когда на месте назначения он не установлен, поэтому более старые машины Omarchy могут получать аккаунты без обновления. Установленные получатели имеют приоритет. Это копирует все подписки Claude, Codex и Grok; добавьте имена провайдеров, чтобы выбрать их, как в `omarchy agent account copy laptop claude`. Имена аккаунтов и ID команд соответствуют источнику, включая аккаунты, уже присутствующие в месте назначения. Несвязанные аккаунты в месте назначения получают числовой суффикс при конфликте имён, а настройки, скиллы, плагины и история разговоров остаются локальными для каждой машины.

Существующие учётные данные в месте назначения сохраняются. У аккаунта источника, уже вошедшего там, имя синхронизируется без замены его учётных данных; другие аккаунты добавляются рядом с ним. Чтобы заменить сохранённые учётные данные для совпадающих аккаунтов, используйте `omarchy agent account copy --replace laptop claude` после завершения сессий этого аккаунта в месте назначения. Свежее место назначения также получает активный аккаунт источника и предпочтения переключения; устоявшееся место назначения сохраняет свои собственные.

Учётные данные передаются через SSH и хранятся в приватных файлах в месте назначения, поэтому копируйте только на машины, которым доверяете. Это однократное копирование, а не постоянная синхронизация. Токены обновления Codex могут быть ротированы другой машиной, из-за чего скопированному входу потребуется обновление; отдельные входы остаются самым надёжным выбором для одновременного использования на нескольких машинах. См. [руководство Codex по аутентификации аккаунтов](https://developers.openai.com/codex/auth/ci-cd-auth).

Один аккаунт на провайдера активен, и каждая новая сессия начинается как он: `cx`, `cy`, обычный `claude`, `codex` или `grok`, всё, что запускается через `omarchy agent`, а также скрипты или редакторы, которые находят CLI в `PATH`. Переключайтесь с помощью `omarchy agent account use work` (и обратно с помощью `omarchy agent account use main`) или в панели, нажав номер аккаунта, а затем `Enter` (или щёлкнув его кнопку Use). Запущенные сессии Claude тоже переключаются, со следующего сообщения: каждая сессия Claude работает в `~/.claude`, который всегда содержит вход активного аккаунта. Сессия Claude, запущенная более старой версией Omarchy в собственной папке аккаунта, сохраняет этот вход до своего завершения, поэтому переключение называет эти сессии и завершается само, как только они исчезнут. Запущенные сессии Codex и Grok остаются на аккаунте, с которым они стартовали. История разговоров, настройки, скиллы и плагины общие для всех аккаунтов, поэтому `claude --continue` в той же папке продолжит с того места, где вы остановились, на новом аккаунте.

При наличии нескольких аккаунтов панель показывает лимиты каждого аккаунта рядом, с отмеченным активным. По умолчанию Omarchy уведомляет вас, когда активный аккаунт превышает 95% лимита, и щелчок по уведомлению переключает на аккаунт с наибольшим запасом. Наведите курсор на строку аккаунта в панели и щёлкните Autoswitch, который появляется рядом с Use (или нажмите `m`), или выполните `omarchy agent account mode auto`, чтобы он переключался сам; пока это включено, Autoswitch занимает место Use, а повторный щелчок возвращает к уведомлениям. Добавьте число, чтобы изменить порог, как в `omarchy agent account mode auto 90`. Если каждый аккаунт превышает порог, вы узнаете об этом один раз, вместе с тем, какой аккаунт освободится первым. Пока активный аккаунт находится в пределах 15 пунктов от своего порога (80% по умолчанию), его лимиты проверяются каждые три минуты, а не каждые 15.

`omarchy agent account list` показывает каждый аккаунт и его последние лимиты, `omarchy agent account remove work` забывает один, а `omarchy agent account rename primary Hey` переименовывает один (или щёлкните имя аккаунта в панели). Эти команды работают с аккаунтами вашего агента по умолчанию; чтобы обратиться к другому провайдеру, сначала укажите его имя, как в `omarchy agent account use codex side`. Вход, который у вас уже был в `~/.claude` или `~/.codex`, — это аккаунт _Main_. У Codex он остаётся там, где был; у Claude он ждёт в собственной папке, пока активен другой аккаунт. Аккаунт, не использовавшийся более примерно восьми часов, может показать _Sign-in required_; щёлкните по нему, чтобы снова войти в этот аккаунт прямо в панели, или переключитесь на него и начните сессию, что само по себе обновит вход. MCP-серверы, которые вы добавляете с помощью `claude mcp add`, доступны каждому аккаунту Claude, поскольку все они работают в `~/.claude`; для Codex и Grok серверы, которые у вас были при добавлении аккаунта, переходят в него, но более поздние доступны только тому аккаунту, в котором вы их добавили. Claude Desktop сохраняет собственный вход, а инструменты Codex или Grok, настроенные с абсолютным путём к бинарнику CLI, не следуют за переключением. Явно заданный `CLAUDE_CONFIG_DIR`, `CODEX_HOME` или `GROK_HOME` имеет приоритет над выбранным аккаунтом.

### Диагностика аварийных завершений

Omarchy следит за systemd-coredump на предмет сбоев процессов. Как только вы выбрали агента по умолчанию, любая ваша программа, сбрасывающая core, вызывает уведомление «Process crashed» — щёлкните по нему, и сбой будет передан вашему агенту по умолчанию вместе со скиллом Omarchy omarchy-diagnose-crash, который проводит агента через установление фактов из дампа core и решение, стоит ли сообщать о сбое в upstream. Вы также можете запустить его вручную для любого PID из `coredumpctl list` с помощью `omarchy agent crash <pid>`.

Наблюдение включено по умолчанию. Отключите его в _Trigger > Toggle > Crash Capture Off_ (или с помощью `omarchy toggle crash-capture`), и уведомления прекратятся; `omarchy agent crash <pid>` по-прежнему работает вручную.

Сбои также можно заглушить по одной программе за раз, что диагностика и предлагает вам в конце. `omarchy crash mute hyprland` прекращает уведомления только для этой программы, `omarchy crash mute hyprland off` возвращает их, а `omarchy crash mute` сам по себе перечисляет то, что вы заглушили. Он с одинаковой готовностью принимает путь к бинарнику и его имя, поэтому `omarchy crash mute /usr/bin/hyprland` делает то же самое. Заключите имя с пробелом в кавычки, как в `omarchy crash mute 'Some App'`. Всё остальное по-прежнему уведомляет, а заглушенная программа по-прежнему падает — это скрывает напоминание, а не исправляет что-либо.

### Десктопные приложения

Меню _Install > AI_ также содержит несколько графических приложений AI: Amp Desktop, Antigravity Desktop, десктопное приложение ChatGPT, десктопное приложение Claude (бета-версия Anthropic для Linux с вкладками Chat, Cowork и Claude Code), Grok Bot для общения с моделями xAI, Herdr Desktop, Hermes Desktop, OpenClaw, десктопное приложение Perplexity и T3 Code. Grok Bot — это десктопное приложение для чата. Агент для кодинга — это команда `grok`.

Hermes Desktop — то, о чём стоит знать, потому что на машине один Hermes, и он принадлежит приложению: Hermes устанавливается только через приложение, и команда `hermes`, которую запускает агент по умолчанию, принадлежит приложению. Выбор Hermes в качестве агента по умолчанию устанавливает то же самое, что и пункт _Install > AI_: пакет и среду выполнения Hermes в `~/.hermes`, настроенную собственным установщиком Hermes, что занимает несколько минут при первом запуске. Эта среда выполнения — тот единственный Hermes, который используют терминальная команда `hermes`, агент по умолчанию и приложение, и она обновляется сама с помощью `hermes update`, а не ждёт релиза Omarchy. Установка также передаёт Hermes тему Omarchy как скин с именем `omarchy`, которому следует каждая поверхность Hermes при переключении тем; выберите другой в настройках Appearance в Hermes или с помощью `/skin`, если вы предпочитаете, чтобы этого не было, и Omarchy оставит этот выбор в покое. Удаление приложения в _Remove > AI_ сначала закрывает Hermes, включая шлюз, забирает эту среду выполнения с собой и сохраняет ваши чаты, воспоминания и скиллы, которые Hermes написал для себя, если вы не скажете иначе: оно спрашивает, по умолчанию отвечая «нет», должны ли эти данные и ваши настройки подключения также быть удалены.

Десктопный опыт OpenClaw — это его Control UI, который открывается как веб-приложение, поддерживаемое его собственным локальным шлюзом. OpenClaw живёт в `~/.openclaw` и обновляется сам: используйте кнопку «Update Gateway» в Control UI или выполните `openclaw update`, и шлюз перезапустится на новой версии. Omarchy выбирает только релиз, с которого начинается свежая установка. OpenClaw также может быть вашим агентом по умолчанию: выбор его в _Agent > Harness_ настраивает ту же копию в `~/.openclaw`, а агент открывает терминальный UI OpenClaw, подключённый к его шлюзу. Удаление OpenClaw в _Remove > AI_ забирает с собой службу шлюза и приложение, а затем спрашивает, должен ли `~/.openclaw` также быть удалён, поскольку там хранятся ваши чаты и учётные данные наряду с самим OpenClaw и средами выполнения плагинов, которые он загружает; по умолчанию он сохраняется, и повторная установка OpenClaw подхватит его обратно.

Herdr Desktop — это десктопное приложение [Herdr](https://herdr.dev): пространства, вкладки и панели терминалов и агентов для кодинга, которые продолжают работать в его ядре, когда вы закрываете окно. Оно поставляется собственным установщиком Herdr, а не пакетом, поэтому живёт в `~/.local/share/herdr-app`, приносит своё ядро в `~/.local/bin/herdr-core`, когда у вас его ещё нет, и обновляет и то, и другое само. Оно находится рядом с командой `herdr`, которую Omarchy поставляет на `Super + Ctrl + Return`, а не заменяет её, и получает прямые клавиши этой команды: `Alt + Return` и `Alt + Shift + Return` делят панель вниз или вправо, `Alt + Escape` закрывает её, `Ctrl + Alt + Arrow` перемещает между панелями, `Alt + 1..9` и `Alt + Left/Right` выбирают вкладку, а `Alt + Up/Down` перемещают между пространствами. `Ctrl + 1..9` выбирает пространство, а `Alt + Shift + Up/Down` проходит по агентам. Префиксные клавиши `Ctrl + Space` остаются только для терминала, поскольку приложение не может удерживать обычную клавишу Ctrl для последовательности. Omarchy записывает их в `~/.config/herdr-app/keys.json`, а `omarchy-refresh-herdr-app` возвращает их обратно. Установка выбирает тему Omarchy для Herdr, которая с этого момента следует за вашей темой Omarchy. Herdr хранит одну тему для светлого режима и одну для тёмного, поэтому после переключения между тёмной и светлой темой Omarchy ещё раз выберите Omarchy в выборе темы Herdr для другого режима.

T3 Code работает из официального релиза AppImage в `~/.local/share/t3code`, а не из пакета, поэтому обновляется сам. Установка спрашивает, начинать ли на канале Stable или Nightly; переключите позже в настройках T3 Code. Ваши треды и настройки живут в `~/.t3`, и удаление T3 Code в _Remove > AI_ забирает их с собой.

### Локальные модели

Запускайте открытую модель на своей машине для своих агентов для кодинга. Ваши промпты и код остаются на машине; ничто из отправленного модели не покидает её. Начните с:

```bash
omarchy agent local use best
```

Или в панели агентов в верхней панели выберите + и затем Local AI, который появляется, когда модель подходит этой машине. Podman, который запускает модели, поставляется с Omarchy, как и контейнерный инструментарий NVIDIA на машине с NVIDIA, который даёт им GPU; если чего-то из этого не хватает, первая настройка устанавливает это. Затем Omarchy выбирает рекомендуемую модель для этой машины, загружает её и запускает. Ожидайте загрузки в десятки GB, и что большая часть памяти машины будет занята, пока модель работает: Flash Next использует около 100 GiB при полном контексте 256K. Если другие модели занимают нужную ей память, она настраивается остановленной, готовой к запуску, как только вы остановите одну из них. Модель останавливается при выходе из системы; останавливайте её сами, когда память нужна вам для чего-то другого.

`omarchy agent local list` показывает варианты и объясняет, почему некоторые не подходят. Чтобы настроить ещё одну, выполните `omarchy agent local use <recipe>`. Сегодня `qwen3.8-flash-next-gufo` и `qwen3.8-27b-gufo` доступны для машин Strix Halo со 128 GB; 27B занимает около 40 GiB, поэтому оставляет место для другой работы. На ноутбуке с 64 GB и Intel Arc B390 `qwen3.6-35b-a3b-llamacpp` работает примерно в 30 GiB. Новые рецепты и рекомендации поступают с `omarchy update`, через пакет.

Каждая настроенная вами модель получает собственную строку в панели агентов, рядом с вашими подписками: play, чтобы запустить её, pause, чтобы остановить и освободить память, и кнопку терминала, чтобы открыть вашего агента на ней. Несколько могут работать одновременно, когда они вместе помещаются в память; если одна не помещается, Omarchy говорит, какую работающую модель остановить. Перетаскивайте строки, чтобы изменить их порядок, и нажимайте Delete на выбранной строке, чтобы удалить модель и её загрузку.

Каждая настроенная вами модель также получает собственную запись в лаунчере приложений, под именем модели и с логотипом её создателя, так же, как вход в Claude, Codex или Grok добавляет такую запись. Она открывает вашего агента на этой модели и сначала запускает модель, если она не работает: терминал показывает её загрузку и передаёт управление агенту, как только она будет готова. Удаление модели удаляет её запись.

Не каждая модель предназначена для кодинга. Модели изображений, видео и музыки вместо этого открываются в Fantasi, приложении Omarchy для создания картинок, видео и музыки с моделью, работающей на этой машине, из их записи в лаунчере и из их строки в панели агентов.

Модель продолжает работать именно так, как была настроена, поэтому обновление Omarchy никогда не перезапускает её под вашими агентами. Когда у Omarchy есть более новая среда выполнения или более новые веса для настроенной вами модели, в её строке появляется кнопка обновления: нажмите её, и модель будет настроена заново в фоне, загрузив только то, что изменилось, и перезапустится на новой версии. Остановленная модель остаётся остановленной. `omarchy agent local update` делает то же самое для каждой модели из терминала.

Из командной строки `omarchy agent local start <recipe>` и `omarchy agent local stop <recipe>` делают то же самое, `omarchy agent local status` показывает каждую модель, а `omarchy agent --local` открывает вашего агента по умолчанию на последней запущенной вами модели. pi, OpenCode и Qwen Code могут использовать такую модель; при любом другом агенте по умолчанию он открывается в pi или в OpenCode, если у вас нет pi. pi также перечисляет каждую настроенную вами модель и модели на машинах, с которыми вы выполнили сопряжение, в своём собственном выборе моделей, поэтому обычный `pi` тоже может к ним обращаться. Любой клиент, совместимый с OpenAI, также может подключиться: `status` показывает адрес каждой модели (первый — `http://127.0.0.1:11435/v1`), имя рецепта — это модель, а ключ находится в `~/.config/omarchy/agent-local/key`.

`omarchy agent local remove <recipe>` удаляет модель и загрузки, которые не использует ни одна другая модель.

Сторонние среды выполнения помечены их издателем. Omarchy запускает каждую модель без доступа к сети.

### Локальные LLM

Omarchy рекомендует два способа запуска локальных моделей LLM: LM Studio и Ollama. LM Studio предоставляет графический интерфейс для поиска моделей с открытыми весами, их установки и запуска. Это отличный способ легко начать. Ollama предлагает CLI для того же самого аналогичным образом. Но если вы новичок в локальных моделях, я бы начал с LM Studio. Вы можете установить любое из них в _Install > AI_ в Omarchy Menu.

### Скиллы Omarchy

Скиллы агентов помогают AI использовать конкретные инструменты конкретным образом, и Omarchy поставляет семь из них. Скилл omarchy охватывает настройку системы под себя, например настройку вашей конфигурации Hyprland или регулировку панели. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app и omarchy-make-game охватывают создание чего-то нового, omarchy-contribute охватывает сообщение об ошибке или отправку исправления в upstream, а omarchy-diagnose-crash разбирает дамп core сбоя. Они связаны симлинками с каталогами скиллов для Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` и каждый `~/.hermes/profiles/*/skills`) и общего расположения `~/.agents/skills`, поэтому большинство harness-ов подхватывают их автоматически. Собственная папка скилла с тем же именем имеет приоритет.

Но вам следует относиться к этим скиллам как к экспериментальным. Разные модели будут использовать их с разным эффектом. Лучше сначала запускать в режиме планирования, чтобы у вас было представление о том, что агент хотел бы изменить. А затем будьте готовы откатить изменения или даже вызвать `omarchy reinstall configs`, если агент устроит во всём беспорядок.
