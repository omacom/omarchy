# ИИ

Omarchy включает средства запуска для перечисленных ниже агентов для программирования, не выбирая за вас вариант по умолчанию. Запустите команду, чтобы при первом использовании установить её CLI, а затем пройдите аутентификацию по запросу. Hermes и OpenClaw — исключения: для них через mise ничего не устанавливается, а выбор любого из них настраивает его собственную самообновляющуюся копию, как объясняется ниже в разделе _Настольные приложения_.

### Установка и обновление агентов

За исключением Hermes и OpenClaw, эти агенты используют ленивую установку mise: первый запуск устанавливает CLI, а последующие запуски используют его повторно. mise также проверяет установленный агент на наличие нового релиза не чаще одного раза в четыре часа, непосредственно перед его запуском или в фоновом режиме при приглашении оболочки. Если это обновление не удаётся или вы не в сети, запускается установленная версия. `omarchy update` обновляет установленные агенты вместе с остальной частью Omarchy, а `mup` обновляет только инструменты, управляемые mise.

Собственное средство обновления агента, такое как `claude update`, `codex update` или кнопка обновления в приложении, не обновляет установку, управляемую mise. `codex update` завершается с ошибкой, а `claude update` может сообщить об успехе, установив при этом отдельную копию, которую mise не отслеживает. Если вы предпочитаете использовать родной установщик и средство обновления агента, добавьте его в `disable_tools`; см. [Предустановленные инструменты CLI](18-development-tools.md#preinstalled-cli-tools).

Чтобы установить все настроенные ленивые инструменты до того, как они вам понадобятся, выполните `mise install --include-lazy`. Это включает другие инструменты CLI Omarchy по умолчанию, а также агентов. См. [Предустановленные инструменты CLI](18-development-tools.md#preinstalled-cli-tools) для установки одного инструмента или использования вашей собственной установки.

`grok` устанавливается через фирменный пакет `grok` от mise, так же как `claude` и `codex`. Запустите `grok` или отметьте его звёздочкой на панели агентов. Пропустите установщик `curl | bash` на x.ai. Этот путь помещает вторую копию в `~/.grok/bin`, добавляет её в начало `PATH` и перезаписывает обёртку Omarchy.

`dsh` открывает свой браузерный интерфейс на `127.0.0.1:3080`, где каталог запуска является его рабочей областью по умолчанию. Его браузерный интерфейс не принимает начальный промпт, поэтому `omarchy agent prompt` открывает его с промптом в вашем буфере обмена для вставки. Omarchy запускает его с пресетом разрешений без подтверждения от DeepSeek. DeepSeek Harness загружает журналы сессий в DeepSeek, когда вы используете его официальный API моделей; отключите это в его браузерном интерфейсе в разделе _Settings > General > Upload Session Log_. Отправляемые вами отзывы также загружаются вместе с сессией, если только вы не запустите его с `DSH_TELEMETRY_MODE=DISABLED`.

### Агент по умолчанию

Выберите агента по умолчанию с помощью звёздочки рядом с агентом на панели агентов, которая закрашена у агента по умолчанию, или с помощью `omarchy default agent <name>`, которая также принимает любой харнесс, для которого там нет строки. Если агент ещё не установлен, при его выборе он сначала устанавливается, а также получает собственный лаунчер в лаунчере приложений, рядом с Agent. Свежая установка Omarchy предлагает вам настроить такого агента с помощью однократного уведомления, которое открывает панель агентов.

Выбор Claude также пытается настроить его расширение для браузера для Chromium, Chrome, Brave, Brave Origin и Edge. Настройка расширения применяется ко всем пользователям и может запросить ваш системный пароль; отмена или неудачная установка расширения всё равно выбирает и запускает Claude. Перезапустите браузер, включите расширение при запросе и войдите в Claude, чтобы завершить его подключение. Выполните `/chrome` в Claude, чтобы проверить соединение. Firefox и Zen не поддерживают это расширение. Если Claude уже был вашим агентом по умолчанию до добавления этой настройки, выберите его снова, чтобы установить расширение.

После выбора `Super + Shift + Ctrl + A` запускает агента по умолчанию в отдельном окне терминала (или вызывает средство выбора, если вы ещё не выбрали). Вы также можете запустить его сразу с задачей с помощью `omarchy agent prompt "Review this project"`. Freebuff и DeepSeek Harness не принимают начальный промпт, поэтому вместо этого они открываются с промптом в вашем буфере обмена для вставки. Агенты, запущенные таким образом, работают без присмотра в своих соответствующих режимах «не останавливайся, чтобы спросить», поэтому будьте готовы к тому, что они действительно будут что-то делать! У MiniMax Code нет такого режима для его интерактивных сессий, поэтому он запрашивает разрешения как обычно. А поскольку агенты отказываются запоминать доверие для вашего домашнего каталога, запуски из `$HOME` вместо этого начинаются в `~/Work`.

Есть и сочетания в терминале: `a` запускает агента по умолчанию прямо в текущем терминале, а `c`, `cx` и `cy` запускают OpenCode, Claude Code и Codex напрямую (опять же в их режимах автоматического подтверждения). Смена темы также синхронизируется с агентами: Claude Code, Pi, OpenCode и Hermes (после того как Omarchy его установила) следуют за вами, когда вы переключаете тему Omarchy.

### Ваши инструкции для агентов

Личные правила для каждого агента помещаются в `~/.agents/AGENTS.md`, рядом с общими навыками в `~/.agents/skills`. Откройте его с помощью значка документа рядом с + на панели агентов или с помощью `omarchy agent instructions --edit`, которая также связывает его с каждым харнессом, хранящим собственный глобальный файл: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.copilot/copilot-instructions.md` у Copilot и так далее. Crush и Amp читают ссылку `~/.config/AGENTS.md`, а omp, Kimi и DeepSeek Harness читают `~/.agents/AGENTS.md` напрямую. Выбор агента по умолчанию также связывает его. Файл инструкций, который у вас уже был, становится общим, если его ещё не было; в противном случае он сохраняется рядом со ссылкой как `.bak`. Выполните `omarchy agent instructions`, чтобы повторно связать после установки другого агента.

### Панель агентов

В верхней панели есть значок агентов. До того как вы настроите агента, его панель предлагает три способа начать: войти в подписку Claude, Codex, Grok, Gemini, Muse, Cursor или Copilot, или в разделе More — в план для программирования OpenCode Go, MiniMax, Synthetic или Z.ai; платить по мере использования с Fireworks, OpenCode Zen and Go, OpenRouter или в разделе More — DeepSeek или любым другим провайдером, в который входит OpenCode, всё это работает в OpenCode; или запустить лучшую модель для вашего компьютера, когда для него найдётся подходящая. Первый завершённый вами вариант становится вашим агентом по умолчанию, а + на панели позже предлагает те же три варианта. После этого панель размещает каждую подписку на одной странице: каждого агента и аккаунт с его планом, индикатор для каждого из его 5-часовых сессионных и еженедельных лимитов со временем до его сброса (наведите курсор, чтобы увидеть точный процент) или остаток предоплаченного баланса, под строкой, которая по очереди показывает, что вы использовали по всем ним, например токены за эту неделю и вашу наиболее используемую модель. В разделе _Make something cool_ она предлагает стартовые промпты для новой темы, плагина, приложения или игры, которые передают задачу вашему агенту по умолчанию. Приложения создаются так же, как собственные Hype, Monologue и Omacut от Omarchy, на C++ и Qt Quick, с соблюдением навыка агента omarchy-make-app, а компилятор и компоненты Qt, которые им нужны, уже установлены. Игры — это одна страница three.js в `~/Games/vibes`, с соблюдением навыка агента omarchy-make-game, и все они открываются из одного лаунчера Game Vibes в текущей теме; они загружают three.js из сети, поэтому для запуска им нужно соединение. Claude Code, Codex, Grok, Kimi, Cursor и его лимит Grok Bot, GitHub Copilot, Muse, Gemini (через Antigravity) и Devin поддерживаются из коробки с их лимитами, Kimchi — с его планом, предоплаченными кредитами и бюджетами расходов, а Hermes, Mistral Vibe и Qwen Code показывают свои сессии и токены после того, как вы ими воспользуетесь. Планы и ключи провайдеров, которые вы используете через pi, omp или opencode, также отображаются: OpenCode Zen and Go, Z.ai GLM Coding Plan, Ollama Cloud, MiniMax Token Plan и Synthetic с их лимитами; OpenRouter и DeepSeek с их предоплаченными балансами; Fireworks с его расходами за последние 30 дней. Модели для программирования, которые вы запускаете на собственном оборудовании, получают собственные строки, и их токены также учитываются в итогах, как описано в разделе [Локальные модели](#local-models). Каждый агент учитывается один раз, у того, кто выставляет за него счёт, независимо от того, через сколько харнессов вы им управляете.

Щелчок левой кнопкой мыши по значку в панели или нажатие `Super + Ctrl + X` открывает панель, щелчок правой кнопкой запускает вашего агента по умолчанию, а щелчок средней кнопкой обновляет. Записи об использовании, лежащие в его основе, перегенерируются каждые 15 минут с помощью `omarchy agent usage update`, а панель может даже объединять данные об использовании с ваших других машин через синхронизируемую папку. Полные настройки смотрите в README в `$OMARCHY_PATH/shell/plugins/agents/`.

### Несколько подписок

Если вы платите за более чем один план Claude, Codex или Grok — скажем, личный Max и рабочий, — Omarchy может держать их все вошедшими и перемещаться между ними. Добавьте подписку с помощью + на панели агентов, который проведёт вас через это прямо там, или с помощью `omarchy agent account add claude Work` (или `codex`, или `grok`). Тот же + и та же команда выполняют вход в Gemini (`gemini`) и OpenCode (`opencode`) и сохраняют ключ API Fireworks (`fireworks`) или OpenRouter (`openrouter`) в OpenCode; команда также выполняет вход в Copilot (`copilot`), Cursor (`cursor`) и Muse (`muse`). Они хранят по одному входу каждый. Она устанавливает CLI, если он отсутствует. Первый аккаунт провайдера входит через ваш обычный браузер, именно там, где CLI всегда ищет. Каждый последующий входит через приватное окно, чтобы аккаунт, в который ваш браузер уже вошёл, не был выбран по ошибке; войдите там как аккаунт, который вы добавляете, и сначала закройте любое уже открытое у вас приватное окно. Никогда не выходите из CLI для этого: выход отзывает сохранённый вход, и этот аккаунт придётся добавлять снова.

Чтобы скопировать входы по вашей подписке на другую машину Omarchy по SSH, выполните `omarchy agent account copy user@laptop`. Отправитель предоставляет временный приёмник, когда на месте назначения он не установлен, поэтому более старые машины Omarchy могут получать аккаунты без обновления. Установленные приёмники имеют приоритет. Это копирует все подписки Claude, Codex и Grok; добавьте имена провайдеров, чтобы выбрать их, как в `omarchy agent account copy laptop claude`. Имена аккаунтов и идентификаторы команд соответствуют источнику, включая аккаунты, уже имеющиеся на месте назначения. Несвязанные аккаунты места назначения получают числовой суффикс, если их имена конфликтуют, а настройки, навыки, плагины и история разговоров остаются локальными для каждой машины.

Существующие учётные данные места назначения сохраняются. У исходного аккаунта, уже вошедшего там, его имя синхронизируется без замены его учётных данных; другие аккаунты добавляются рядом с ним. Чтобы заменить сохранённые учётные данные для совпадающих аккаунтов, используйте `omarchy agent account copy --replace laptop claude` после выхода из сессий этого аккаунта на месте назначения. Свежее место назначения также получает активный аккаунт источника и предпочтения переключения; устоявшееся место назначения сохраняет свои собственные.

Учётные данные передаются через SSH и хранятся в приватных файлах на месте назначения, поэтому копируйте только на машины, которым доверяете. Это однократное копирование, а не постоянная синхронизация. Токены обновления Codex могут быть ротированы другой машиной, из-за чего скопированному входу потребуется обновление; отдельные входы остаются самым надёжным выбором для одновременного использования на нескольких машинах. См. [руководство Codex по аутентификации аккаунтов](https://developers.openai.com/codex/auth/ci-cd-auth).

Один аккаунт на провайдера активен, и каждая новая сессия начинается как он: `cx`, `cy`, обычный `claude`, `codex` или `grok`, всё, что запускается через `omarchy agent`, и скрипты или редакторы, которые находят CLI в `PATH`. Переключайтесь с помощью `omarchy agent account use work` (и обратно с помощью `omarchy agent account use main`) или на панели, нажав номер аккаунта, а затем `Enter` (или щёлкнув его звёздочку). Запущенные сессии Claude тоже переключаются, начиная со следующего сообщения: каждая сессия Claude работает в `~/.claude`, который всегда содержит вход активного аккаунта. Сессия Claude, запущенная более старой Omarchy в собственной папке аккаунта, сохраняет этот вход до своего завершения, поэтому переключение называет эти сессии и завершается само, как только они исчезнут. Запущенные сессии Codex и Grok остаются на аккаунте, с которым они started. История разговоров, настройки, навыки и плагины являются общими для всех аккаунтов, поэтому `claude --continue` в той же папке продолжит с того места, где вы остановились, на новом аккаунте.

При наличии более чем одного аккаунта панель показывает лимиты каждого аккаунта рядом друг с другом, с закрашенной звёздочкой у используемого. Omarchy уведомляет вас, когда активный аккаунт превышает 95% лимита, и щелчок по уведомлению переключает на аккаунт с наибольшим запасом. Она никогда не переключается сама. Измените порог с помощью `omarchy agent account threshold 90`. Если каждый аккаунт превышает порог, вы услышите об этом один раз, а также о том, какой аккаунт освободится первым. Пока активный аккаунт находится в пределах 15 пунктов от своего порога (80% при значении по умолчанию), его лимиты проверяются каждые три минуты, а не каждые 15.

`omarchy agent account list` показывает каждый аккаунт и его последние лимиты, `omarchy agent account remove work` забывает один, а `omarchy agent account rename primary Hey` переименовывает один (или щёлкните имя аккаунта на панели). Эти команды работают с аккаунтами вашего агента по умолчанию; чтобы обратиться к другому провайдеру, сначала назовите его, как в `omarchy agent account use codex side`. Вход, который у вас уже был в `~/.claude` или `~/.codex`, — это аккаунт _Main_. У Codex он остаётся там, где находится; у Claude он ожидает в собственной папке, пока активен другой аккаунт. Аккаунт, оставленный без использования более примерно восьми часов, может показывать _Sign-in required_; щёлкните его, чтобы снова войти в этот аккаунт прямо на панели, или переключитесь на него и начните сессию, что само обновит вход. Серверы MCP, которые вы добавляете с помощью `claude mcp add`, достигают каждого аккаунта Claude, поскольку все они работают в `~/.claude`; для Codex и Grok серверы, которые у вас были при добавлении аккаунта, переходят вместе с ним, но более поздние достигают только того аккаунта, в котором вы их добавили. Claude Desktop сохраняет собственный вход, а инструменты Codex или Grok, настроенные с абсолютным путём к бинарному файлу CLI, не следуют за переключением. Явно заданный `CLAUDE_CONFIG_DIR`, `CODEX_HOME` или `GROK_HOME` имеет приоритет над выбранным аккаунтом.

### Диагностика сбоев

Omarchy наблюдает за systemd-coredump на предмет сбоев процессов. После того как вы выберете агента по умолчанию, любая ваша программа, которая создаёт дамп ядра, вызывает уведомление «Process crashed» — щёлкните его, и сбой будет передан вашему агенту по умолчанию вместе с навыком omarchy-diagnose-crash от Omarchy, который проводит агента через установление фактов из дампа ядра и принятие решения о том, стоит ли сообщать о сбое вверх по течению. Вы также можете запустить его вручную для любого PID из `coredumpctl list` с помощью `omarchy agent crash <pid>`.

Наблюдение включено по умолчанию. Отключите его в разделе _Trigger > Toggle > Crash Capture Off_ (или с помощью `omarchy toggle crash-capture`), и уведомления прекратятся; `omarchy agent crash <pid>` по-прежнему работает вручную.

Сбои также можно заглушить по одной программе за раз, что диагностика и предлагает вам в конце. `omarchy crash mute hyprland` прекращает уведомления только для этой программы, `omarchy crash mute hyprland off` возвращает их, а `omarchy crash mute` сама по себе перечисляет то, что вы заглушили. Она так же охотно принимает путь к бинарному файлу, как и его имя, поэтому `omarchy crash mute /usr/bin/hyprland` делает то же самое. Заключайте имя с пробелом в кавычки, как в `omarchy crash mute 'Some App'`. Всё остальное по-прежнему уведомляет, а заглушенная программа по-прежнему падает — это скрывает напоминание, а не исправляет что-либо.

### Настольные приложения

Меню _Install > AI_ также содержит несколько графических приложений ИИ: Amp Desktop, Antigravity Desktop, настольное приложение ChatGPT, настольное приложение Claude (бета-версия Anthropic для Linux, с вкладками Chat, Cowork и Claude Code), Grok Bot для общения с моделями xAI, Herdr Desktop, Hermes Desktop, OpenClaw, настольное приложение Perplexity и T3 Code. Grok Bot — это настольное приложение для чата. Агент для программирования — это команда `grok`.

О Hermes Desktop следует знать особо, потому что на машине один Hermes, и он принадлежит приложению: Hermes устанавливается только через приложение, а команда `hermes`, которую запускает агент по умолчанию, принадлежит приложению. Выбор Hermes в качестве агента по умолчанию устанавливает то же самое, что и пункт _Install > AI_: пакет и среду выполнения Hermes в `~/.hermes`, настроенную собственным установщиком Hermes, что в первый раз занимает несколько минут. Эта среда выполнения — тот единственный Hermes, который используют терминальная команда `hermes`, агент по умолчанию и приложение, и она обновляет себя с помощью `hermes update`, а не ждёт релиза Omarchy. Её установка также передаёт Hermes тему Omarchy в виде скина с именем `omarchy`, которому следует каждая поверхность Hermes при переключении вами тем; выберите другой в настройках Appearance у Hermes или с помощью `/skin`, если вы предпочитаете, чтобы этого не было, и Omarchy оставит этот выбор в покое. Удаление приложения в разделе _Remove > AI_ сначала закрывает Hermes, включая шлюз, уносит с собой эту среду выполнения и сохраняет ваши чаты, воспоминания и навыки, которые Hermes написал для себя, если вы не скажете ей иное: она спрашивает, по умолчанию — нет, должны ли эти данные и ваши настройки подключения также удалиться.

Настольный опыт OpenClaw — это его Control UI, который открывается как веб-приложение, поддерживаемое его собственным локальным шлюзом. OpenClaw живёт в `~/.openclaw` и обновляет себя: используйте кнопку «Update Gateway» в Control UI или выполните `openclaw update`, и шлюз перезапустится на новой версии. Omarchy выбирает только релиз, с которого начинается свежая установка. OpenClaw также может быть вашим агентом по умолчанию: выбор его с помощью `omarchy default agent openclaw` настраивает ту же копию в `~/.openclaw`, а агент открывает терминальный интерфейс OpenClaw, подключённый к его шлюзу. Удаление OpenClaw в разделе _Remove > AI_ уносит с собой службу шлюза и приложение, а затем спрашивает, должен ли `~/.openclaw` также удалиться, поскольку там хранятся ваши чаты и учётные данные наряду с самим OpenClaw и средами выполнения плагинов, которые он загружает; по умолчанию он сохраняется, и повторная установка OpenClaw подхватит его обратно.

Herdr Desktop — это настольное приложение [Herdr](https://herdr.dev): пространства, вкладки и панели терминалов и агентов для программирования, которые продолжают работать в его ядре, когда вы закрываете окно. Оно поставляется собственным установщиком Herdr, а не пакетом, поэтому живёт в `~/.local/share/herdr-app`, приносит с собой своё ядро в `~/.local/bin/herdr-core`, когда у вас его ещё нет, и обновляет и себя, и его. Оно находится рядом с командой `herdr`, которую Omarchy поставляет на `Super + Ctrl + Return`, а не заменяет её, и получает прямые клавиши этой команды: `Alt + Return` и `Alt + Shift + Return` разделяют панель вниз или вправо, `Alt + Escape` закрывает её, `Ctrl + Alt + Arrow` перемещает между панелями, `Alt + 1..9` и `Alt + Left/Right` выбирают вкладку, а `Alt + Up/Down` перемещают между пространствами. `Ctrl + 1..9` выбирает пространство, а `Alt + Shift + Up/Down` проходит по агентам. Клавиши префикса `Ctrl + Space` остаются только для терминала, поскольку приложение не может удерживать обычную клавишу Ctrl для последовательности. Omarchy записывает их в `~/.config/herdr-app/keys.json`, а `omarchy-refresh-herdr-app` возвращает их обратно. Его установка выбирает тему Omarchy у Herdr, которая с этого момента следует вашей теме Omarchy. Herdr хранит одну тему для светлого режима и одну для тёмного, поэтому после переключения между тёмной и светлой темой Omarchy ещё раз выберите Omarchy в средстве выбора темы Herdr для другого режима.

T3 Code работает из своего официального релиза AppImage в `~/.local/share/t3code`, а не из пакета, поэтому обновляет себя сам. Его установка спрашивает, начинать ли на канале Stable или Nightly; переключите позже в настройках T3 Code. Ваши потоки и настройки живут в `~/.t3`, а удаление T3 Code в разделе _Remove > AI_ уносит их с собой.

### Локальные модели

Запустите открытую модель на собственной машине для ваших агентов для программирования. Ваши промпты и код остаются на машине; ничего из отправленного модели не покидает её. Начните с:

```bash
omarchy models use best text
```

Это настраивает лучшую текстовую модель для этой машины, ту, которую используют ваши агенты. У моделей изображений, видео и музыки есть своя лучшая: `omarchy models use best image`, `video` или `music`. Выполните `omarchy models use best`, чтобы увидеть выбор каждого вида для этой машины.

Или выберите + на панели агентов: в разделе _Use a local model_ она перечисляет каждую модель для программирования, подходящую этой машине, рекомендованную первой. Podman, который запускает модели, поставляется с Omarchy, как и набор инструментов контейнеров NVIDIA на машине NVIDIA, который даёт им GPU; если чего-либо из них не хватает, первая настройка устанавливает это. Затем Omarchy выбирает рекомендованную модель для этой машины, загружает её и запускает. Ожидайте загрузки в десятки GB и использования большей части памяти машины во время работы модели: Flash Next использует около 100 GiB при полном контексте 256K. Если другие модели удерживают нужную ей память, она настраивается остановленной, готовой к запуску, как только вы остановите одну из них. Модель останавливается при выходе из системы; останавливайте её сами, когда вам нужна память для чего-то другого.

`omarchy models list` показывает варианты и объясняет, почему некоторые не подходят. Чтобы настроить другую, выполните `omarchy models use <recipe>`. Сегодня `qwen3.8-flash-next-gufo` и `qwen3.8-27b-gufo` доступны для машин Strix Halo со 128 GB; 27B занимает около 40 GiB, поэтому оставляет место для другой работы. На ноутбуке с 64 GB и Intel Arc B390 `qwen3.6-35b-a3b-llamacpp` работает примерно в 30 GiB. Новые рецепты и рекомендации поступают с `omarchy update`, через пакет.

Модель для программирования, которую вы добавляете, получает собственную строку на панели агентов, рядом с вашими подписками: воспроизведение — чтобы запустить её, пауза — чтобы остановить её и освободить её память, отметка Tailscale — чтобы поделиться ею с другими машинами в вашем tailnet, пока она работает, и кнопка терминала — чтобы открыть вашего агента на ней. Её строка показывает загрузку, запуск или остановку по мере выполнения, и сообщает, когда не хватает свободной памяти для её запуска, или ссылается на её журналы, когда она остановилась с ошибкой. Несколько могут работать одновременно, когда они вместе помещаются в памяти. Нажмите Delete на выбранной строке, чтобы удалить модель с этой машины, вместе с загрузкой; + может настроить её снова. Модель для программирования, настроенная из терминала, ожидает под + до тех пор, пока вы её не добавите, как и модели, которые запускает машина, с которой вы выполнили сопряжение (`omarchy models pair <host>`).

Каждая модель для программирования, которую вы настраиваете, также получает собственную запись в лаунчере приложений, под именем модели и с логотипом её создателя, так же как вход в Claude, Codex или Grok добавляет такую запись. Она открывает вашего агента на этой модели и сначала запускает модель, если она не работает: терминал показывает её загрузку и передаёт управление агенту, как только она будет готова. Удаление модели удаляет её запись.

Не каждая модель предназначена для программирования. Модели изображений, видео и музыки вместо этого открываются в Fantasi, приложении Omarchy для создания изображений, видео и музыки с моделью, работающей на этой машине, и управляются там или с помощью `omarchy models`.

Модель продолжает работать именно так, как была настроена, поэтому обновление Omarchy никогда не перезапускает её под вашими агентами. Когда у Omarchy есть более новая среда выполнения или более новые веса для модели, которую вы настроили, её строка показывает кнопку обновления: нажмите её, и модель будет настроена снова в фоновом режиме, загружая только то, что изменилось, и перезапустится на новой версии. Модель, которая была остановлена, остаётся остановленной. `omarchy models update` делает то же самое для каждой модели из терминала.

Из командной строки `omarchy models start <recipe>` и `omarchy models stop <recipe>` делают то же самое, `omarchy models status` показывает каждую модель, а `omarchy agent --local-model <recipe>` открывает эту модель в pi, каким бы ни был ваш агент по умолчанию. Чтобы сделать вашу локальную модель тем, что открывают горячая клавиша агента, консоль Quake и _Make something_, выполните `omarchy default agent local` или отметьте звёздочкой работающую модель на панели агентов. pi также перечисляет каждую настроенную вами модель и те, что на машинах, с которыми вы выполнили сопряжение, в собственном средстве выбора модели, поэтому обычный `pi` также достигает их. Любой клиент, совместимый с OpenAI, также может подключиться: `status` показывает адрес каждой модели (первый — `http://127.0.0.1:11435/v1`), имя рецепта является моделью, а ключ находится в `~/.config/omarchy/agent-local/key`.

`omarchy models remove <recipe>` удаляет модель и загрузки, которые не использует ни одна другая модель.

Сторонние среды выполнения помечены их издателем. Omarchy запускает каждую модель без доступа к сети.

### Локальные LLM

Omarchy рекомендует два способа запуска локальных моделей LLM: LM Studio и Ollama. LM Studio предоставляет графический интерфейс для поиска моделей с открытыми весами, их установки и запуска. Это отличный способ легко начать. Ollama предлагает CLI для аналогичного выполнения. Но если вы новичок в локальных моделях, я бы начал с LM Studio. Вы можете установить любое из них в разделе _Install > AI_ в меню Omarchy.

### Навыки Omarchy

Навыки агентов помогают ИИ использовать конкретные инструменты конкретным образом, и Omarchy поставляет семь из них. Навык omarchy охватывает настройку системы под себя, например настройку вашей конфигурации Hyprland или регулировку панели. omarchy-make-theme, omarchy-make-plugin, omarchy-make-app и omarchy-make-game охватывают создание чего-то нового, omarchy-contribute охватывает сообщение об ошибке или отправку исправления вверх по течению, а omarchy-diagnose-crash работает с дампом ядра сбоя. Они связаны символическими ссылками в каталоги навыков для Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`), Hermes (`~/.hermes/skills` и каждый `~/.hermes/profiles/*/skills`) и общее расположение `~/.agents/skills`, поэтому большинство харнессов подхватывают их автоматически. Ваша собственная папка навыка с тем же именем имеет приоритет.

Но вы должны относиться к этим навыкам как к экспериментальным. Разные модели будут использовать их с разным эффектом. Лучше сначала запускать в режиме планирования, чтобы у вас было представление о том, что агент хотел бы изменить. А затем будьте готовы откатить изменения или даже вызвать `omarchy reinstall configs`, если агент устроит беспорядок во всём.
