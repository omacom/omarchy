# Dotfiles

Omarchy настраивается в первую очередь через так называемые dotfiles, которые живут в `~/.config`. Они считаются вашими файлами для ваших изменений. Файлы, которые живут в `/usr/share/omarchy`, принадлежат самой Omarchy, и вам не следует с ними возиться. Если вам нужно изменить что-либо в `/usr/share/omarchy`, вместо этого вам следует переопределить значение в `~/.config`.

Ключевые конфиги можно редактировать прямо из меню Omarchy (`Super + Space`), например _Setup > Keybindings_, _Setup > Input_ и _Setup > Config > [file]_. Когда вы делаете это таким способом, любой процесс, который нужно перезапустить после правок конфига, будет автоматически перезапущен после того, как вы выйдете из редактора (по умолчанию Neovim — `:wq`, помните! — но вы можете изменить это через _Setup > Defaults > Editor_).

Вот список ключевых файлов в `~/.config` и того, чем они управляют:

| File                  | Purpose              |
| ----------------------- | --------------------- |
| `~/.config/hypr/hyprland.lua` | Главный конфиг Hyprland. Загружает настройки Omarchy по умолчанию плюс ваши файлы переопределений ниже. [Подробнее о конфигах Hyprland](https://wiki.hypr.land/Configuring/).  |
| `~/.config/hypr/bindings.lua` | Ваши собственные сочетания клавиш и переопределения значений по умолчанию. |
| `~/.config/hypr/monitors.lua` | Настройки монитора, которые не охватывает панель мониторов, например поворот, дополнительные режимы или отключение монитора. |
| `~/.config/hypr/input.lua` | Управляет раскладкой клавиатуры, настройками мыши и трекпада. |
| `~/.config/hypr/looknfeel.lua` | Управляет отступами, рамками, анимациями и остальным внешним видом. |
| `~/.config/hypr/autostart.lua` | Управляет дополнительными процессами, запускаемыми вместе с сессией. |
| `~/.config/omarchy/shell.json` | Управляет оболочкой Omarchy: положением панели, раскладкой и виджетами, а также таймингами заставки, блокировки и простоя. |
| `~/.config/foot/foot.ini` | Управляет вашим терминалом (по умолчанию foot). |
| `~/.XCompose` | Определяет ваш быстрый доступ к эмодзи и автодополнение имени/email. Обязательно выполните `omarchy-restart-xcompose` после внесения изменений. |

Если в итоге вы внесёте много изменений, чтобы настроить собственную систему, будет хорошей идеей сделать резервную копию всех этих dotfiles. [Stow — отличный способ сделать это](https://www.youtube.com/watch?v=NoFiYOqnC4o).

### Запуск собственных приложений вместе с сессией

Если вы хотите, чтобы что-то запускалось каждый раз при входе — демон синхронизации, приложение чата, ваш собственный скрипт — поместите это в `~/.config/hypr/autostart.lua`:

```lua
o.launch_on_start("my-service")
```

Это запускает команду как часть сессии, поэтому она корректно завершается, когда вы снова выходите из системы.

### Запуск скриптов по системным событиям

Omarchy запускает хуки в нескольких точках, и вы можете навесить на них свои собственные скрипты. Они живут в `~/.config/omarchy/hooks/<event>.d/`, по одному каталогу на событие, и каждый исполняемый файл в нём запускается, когда событие происходит:

| Event | When it runs |
| ----- | ------------ |
| `post-boot` | Сразу после запуска рабочего стола |
| `post-update` | Ближе к концу `omarchy update`, после пакетов, миграций и перезапусков служб, до обновления инструментов mise |
| `pre-refresh-pacman` | После того как `omarchy refresh pacman` повторно синхронизирует конфиг пакетов, до того как обновит пакеты; переключение канала запускает его на том же шаге обновления |
| `theme-set` | После смены темы (название темы в `$1`) |
| `font-set` | После смены шрифта (название шрифта в `$1`) |
| `battery-low` | Когда заряд батареи становится низким (процент в `$1`) |

Хук `pre-refresh-pacman` — это место, куда принадлежат пользовательские репозитории или строки `IgnorePkg`, поскольку он запускается до транзакции пакетов. Оба хука, связанных с обновлением, запускаются от вашего пользователя после того, как Omarchy сбрасывает свою кэшированную авторизацию sudo, поэтому хуку, использующему `sudo`, нужна собственная авторизация, и он может запросить ваш пароль.

В каждом из этих каталогов уже есть файл `.sample`, показывающий форму хука — уберите `.sample` из имени, чтобы запустить его в работу. Чтобы установить скрипт, который вы написали в другом месте, используйте `omarchy hook install post-boot ~/my-hook`, что скопирует его и сделает исполняемым.

### Добавление собственных пунктов меню

Меню Omarchy (`Super + Space`) можно расширить своими собственными строками, отредактировав `~/.config/omarchy/extensions/omarchy-menu.jsonc`. Записи ключиваются точечным id, и именно id помещает их в дерево, поэтому `personal` появляется в корневом меню, а `personal.notes` появляется внутри него:

```jsonc
"personal": {"icon":"","label":"Personal"},
"personal.notes": {"icon":"󰎞","label":"Notes","action":"omarchy-launch-editor ~/notes"},
```

Повторно используйте существующий id, и вы переопределите эту строку вместо добавления новой. Файл поставляется со всеми доступными полями, задокументированными в виде комментариев.

### Добавление собственных экспортов оболочки, функций и алиасов

Omarchy поставляется с кучей эргономичных алиасов и полезных функций, но очень часто хочется добавить свои собственные. Вам следует добавлять и алиасы, и функции, и экспорты в `~/.bashrc`. Этот файл не будет перезаписан при обновлениях. Если вы хотите изменить какие-либо значения Omarchy по умолчанию, вы также можете безопасно добавить их сюда.

### Настройка переменных окружения для рабочего стола

Экспорты сессии рабочего стола принадлежат `~/.config/uwsm/env.d/`. Эти файлы запускаются до запуска вашего рабочего стола, поэтому ошибка оболочки может отправить вас обратно на экран входа. Держите рабочий терминал открытым, пока редактируете их. Чтобы отключить переопределение, переместите его из `env.d`. Смотрите [восстановление входа](45-troubleshooting.md#my-password-is-accepted-but-i-return-to-the-login-screen), если изменение препятствует входу.

### Изменение внутренних файлов Omarchy

Послушайте, это ваш компьютер. Вы можете делать с ним всё, что хотите, но я бы не советовал вносить изменения в файлы в `/usr/share/omarchy` напрямую. Они принадлежат пакету Omarchy в pacman, поэтому ваши изменения просто будут перезаписаны при следующем обновлении. Вам лучше просто переопределить любые значения по умолчанию, которые вам не нравятся, в папке `~/.config/*` вместо этого.

Таким способом вы можете изменить практически всё, например сочетания клавиш по умолчанию. Просто отредактируйте `~/.config/hypr/bindings.lua`, чтобы, скажем, заменить [Obsidian](https://obsidian.md/) на [Joplin](https://joplinapp.org/) (устанавливается с помощью `omarchy-pkg-add joplin-bin`):

```lua
o.rebind("SUPER + SHIFT + O", "Joplin", "joplin-desktop")
```

`o.rebind` удаляет существующее сочетание перед добавлением его замены. Он принимает те же аргументы, что и `o.bind`, включая помощники запуска и параметры привязки. Используйте `o.bind`, чтобы добавить привязку, или `hl.unbind`, чтобы удалить её без замены.

Если вы настаиваете на том, чтобы ковыряться во внутренних файлах Omarchy, переключитесь на канал dev через _Update > Channel > Dev_. Это связывает Omarchy с git-копией исходного кода в `~/omarchy`, которую вы свободны изменять сколько душе угодно. Никто здесь не будет указывать вам, что делать!

### Сброс любых изменений

Если в итоге вы устроили беспорядок в конфигурациях, вы всегда можете вернуть их к значениям по умолчанию через _Update > Config_ в меню Omarchy. Или выполнив `omarchy reinstall configs`, чтобы сбросить всё.
