# Дотфайлы

Omarchy в основном настраивается через так называемые дотфайлы, которые живут в `~/.config`. Они считаются вашими файлами для ваших изменений. Файлы, которые живут в `/usr/share/omarchy`, принадлежат самой Omarchy, и вам не стоит с ними возиться. Если нужно изменить что-то в `/usr/share/omarchy`, вместо этого следует переопределить значение в `~/.config`.

Ключевые конфигурации можно редактировать прямо из меню Omarchy (`Super + Space`), например _Настройка > Мониторы_, _Настройка > Сочетания клавиш_, _Настройка > Ввод_ и _Setup > Config > [file]_. Когда вы делаете это таким способом, любой процесс, который нужно перезапустить после редактирования конфигурации, будет автоматически перезапущен после выхода из редактора (по умолчанию Neovim — `:wq`, помните! — но это можно изменить через _Setup > Defaults > Editor_).

Вот список ключевых файлов в `~/.config` и того, чем они управляют:

| File                  | Purpose              |
| ----------------------- | --------------------- |
| `~/.config/hypr/hyprland.lua` | Главная конфигурация Hyprland. Загружает умолчания Omarchy плюс ваши файлы переопределений ниже. [Узнайте больше о конфигурациях Hyprland](https://wiki.hypr.land/Configuring/).  |
| `~/.config/hypr/bindings.lua` | Ваши собственные сочетания клавиш и переопределения умолчаний. |
| `~/.config/hypr/monitors.lua` | Управляет вашими мониторами, разрешением и позицией. |
| `~/.config/hypr/input.lua` | Управляет раскладкой клавиатуры, мышью и настройками тачпада. |
| `~/.config/hypr/looknfeel.lua` | Управляет зазорами, рамками, анимациями и остальным внешним видом. |
| `~/.config/hypr/autostart.lua` | Управляет дополнительными процессами, запускаемыми с сессией. |
| `~/.config/omarchy/shell.json` | Управляет оболочкой Omarchy: позицией панели, раскладкой и виджетами, плюс таймингами заставки, блокировки и простоя. |
| `~/.config/foot/foot.ini` | Управляет вашим терминалом (foot — вариант по умолчанию). |
| `~/.XCompose` | Определяет ваши эмодзи быстрого доступа и автодополнение имени/email. Не забудьте выполнить `omarchy-restart-xcompose` после внесения изменений. |

Если вы в итоге вносите много изменений, чтобы настроить свою систему, хорошая идея — сделать резервную копию всех этих дотфайлов. [Stow — отличный способ это сделать](https://www.youtube.com/watch?v=NoFiYOqnC4o).

### Запуск собственных приложений вместе с сессией

Если вы хотите, чтобы что-то запускалось при каждом входе — демон синхронизации, чат-приложение, ваш собственный скрипт, — поместите это в `~/.config/hypr/autostart.lua`:

```lua
o.launch_on_start("my-service")
```

Это запускает команду как часть сессии, так что она корректно очищается при повторном выходе.

### Запуск скриптов по системным событиям

Omarchy вызывает хуки в горстке моментов, и вы можете подвесить на них собственные скрипты. Они живут в `~/.config/omarchy/hooks/<event>.d/`, по одному каталогу на событие, и каждый исполняемый файл там запускается, когда событие происходит:

| Event | When it runs |
| ----- | ------------ |
| `post-boot` | Сразу после запуска рабочего стола |
| `post-update` | Ближе к концу `omarchy update`, после пакетов, миграций и перезапусков служб, до обновления инструментов mise |
| `pre-refresh-pacman` | После того как `omarchy refresh pacman` повторно синхронизирует конфигурацию пакетов, до обновления пакетов; переключение канала запускает его на том же шаге обновления |
| `theme-set` | После смены темы (имя темы в `$1`) |
| `font-set` | После смены шрифта (имя шрифта в `$1`) |
| `battery-low` | Когда батарея разряжается (процент в `$1`) |

Хук `pre-refresh-pacman` — это место, куда принадлежат пользовательские репозитории или строки `IgnorePkg`, поскольку он запускается до транзакции пакетов. Оба хука, связанные с обновлением, запускаются от вашего пользователя после того, как Omarchy очищает кэшированную авторизацию sudo, поэтому хуку, использующему `sudo`, нужна собственная авторизация, и он может попросить ваш пароль.

В каждом из этих каталогов уже лежит файл `.sample`, показывающий форму хука, — уберите `.sample` из имени, чтобы пустить его в работу. Чтобы установить скрипт, написанный где-то ещё, используйте `omarchy hook install post-boot ~/my-hook`, что скопирует его внутрь и сделает исполняемым.

### Добавление собственных пунктов меню

Меню Omarchy (`Super + Space`) можно расширить собственными строками, отредактировав `~/.config/omarchy/extensions/omarchy-menu.jsonc`. Записи ключуются точечным id, и именно id размещает их в дереве, так что `personal` появляется в корневом меню, а `personal.notes` — внутри него:

```jsonc
"personal": {"icon":"","label":"Personal"},
"personal.notes": {"icon":"󰎞","label":"Notes","action":"omarchy-launch-editor ~/notes"},
```

Повторно используйте существующий id — и вы переопределите эту строку вместо добавления новой. Файл поставляется со всеми доступными полями, задокументированными в виде комментариев.

### Добавление собственных экспортов, функций и alias оболочки

Omarchy поставляется с кучей эргономичных alias и полезных функций, но очень часто хочется добавить свои собственные. И alias, и функции, и экспорты следует добавлять в `~/.bashrc`. Этот файл не будет перезаписан при обновлениях. Если вы хотите изменить какое-либо из умолчаний Omarchy, их также можно безопасно добавить сюда.

### Изменение внутренних файлов Omarchy

Слушайте, это ваш компьютер. Вы можете делать с ним всё что хотите, но я бы посоветовал не вносить изменения в файлы в `/usr/share/omarchy` напрямую. Они принадлежат пакету pacman Omarchy, поэтому ваши изменения просто будут перезаписаны при следующем обновлении. Вам лучше просто переопределить любые значения по умолчанию, которые вам не нравятся, в папке `~/.config/*`.

Таким способом можно изменить почти всё, например сочетания клавиш по умолчанию. Просто отредактируйте `~/.config/hypr/bindings.lua`, чтобы, скажем, заменить [Obsidian](https://obsidian.md/) на [Joplin](https://joplinapp.org/) (установить командой `omarchy-pkg-add joplin-bin`):

```lua
o.rebind("SUPER + SHIFT + O", "Joplin", "joplin-desktop")
```

`o.rebind` удаляет существующую привязку перед добавлением её замены. Он принимает те же аргументы, что и `o.bind`, включая помощники запуска и параметры привязки. Используйте `o.bind`, чтобы добавить привязку, или `hl.unbind`, чтобы удалить привязку без замены.

Если вы настаиваете на взломе внутренних файлов Omarchy, переключитесь на канал dev через _Обновление > Channel > Dev_. Это свяжет Omarchy с git-копией исходного кода в `~/omarchy`, которую вы вольны изменять сколько душе угодно. Никто здесь не будет указывать вам, что делать!

### Сброс любых изменений

Если вы в итоге устроили беспорядок в конфигурациях, их всегда можно вернуть к умолчаниям через _Обновление > Config_ в меню Omarchy. Или выполнив `omarchy reinstall configs`, чтобы сбросить всё.
