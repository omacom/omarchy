# Дотфайлы

Omarchy в основном настраивается через так называемые дотфайлы, которые находятся в `~/.config`. Они считаются вашими файлами для ваших изменений. Файлы, которые находятся в `/usr/share/omarchy`, принадлежат самой Omarchy, и с ними лучше не связываться. Если вам нужно изменить что-то в `/usr/share/omarchy`, вместо этого следует переопределить значение в `~/.config`.

Ключевые конфиги можно редактировать прямо из меню Omarchy (`Super + Space`), например _Setup > Keyboard > Keybindings_, _Setup > Input_ и _Setup > Config > [file]_. Если делать это таким способом, любой процесс, который нужно перезапустить после правок конфига, будет перезапущен автоматически после выхода из редактора (по умолчанию это Neovim — `:wq`, помните! — но его можно изменить через _Setup > Defaults > Editor_).

Вот список ключевых файлов в `~/.config` и того, чем они управляют:

| File                  | Purpose              |
| ----------------------- | --------------------- |
| `~/.config/hypr/hyprland.lua` | Главный конфиг Hyprland. Загружает настройки Omarchy по умолчанию плюс ваши файлы переопределений ниже. [Подробнее о конфигах Hyprland](https://wiki.hypr.land/Configuring/).  |
| `~/.config/hypr/bindings.lua` | Ваши собственные сочетания клавиш и переопределения значений по умолчанию. |
| `~/.config/hypr/monitors.lua` | Настройки мониторов, которые не покрывает панель мониторов, например поворот, дополнительные режимы или отключение монитора. |
| `~/.config/hypr/input.lua` | Управляет раскладкой клавиатуры, настройками мыши и трекпада. |
| `~/.config/hypr/looknfeel.lua` | Управляет отступами, рамками, анимациями и остальным внешним видом. |
| `~/.config/hypr/autostart.lua` | Управляет дополнительными процессами, запускаемыми вместе с сессией. |
| `~/.config/omarchy/shell.json` | Управляет оболочкой Omarchy: положением панели, компоновкой и виджетами, а также таймингами заставки, блокировки и простоя. |
| `~/.config/foot/foot.ini` | Управляет вашим терминалом (по умолчанию это foot). |
| `~/.XCompose` | Определяет ваш быстрый доступ к эмодзи и автодополнение имени/email. Не забудьте выполнить `omarchy-restart-xcompose` после внесения изменений. |

Если вы в итоге внесёте много изменений, чтобы настроить всё под себя, будет хорошей идеей сделать резервную копию всех этих дотфайлов. [Stow — отличный способ это сделать](https://www.youtube.com/watch?v=NoFiYOqnC4o).

### Запуск своих приложений вместе с сессией

Если вы хотите, чтобы что-то запускалось каждый раз при входе в систему — демон синхронизации, приложение для чата, ваш собственный скрипт, — поместите это в `~/.config/hypr/autostart.lua`:

```lua
o.launch_on_start("my-service")
```

Это запускает команду как часть сессии, поэтому при выходе из системы она корректно завершается.

### Запуск скриптов по системным событиям

Omarchy запускает хуки в несколько моментов, и вы можете навесить на них свои собственные скрипты. Они находятся в `~/.config/omarchy/hooks/<event>.d/`, по одному каталогу на событие, и каждый исполняемый файл в нём запускается, когда происходит это событие:

| Event | When it runs |
| ----- | ------------ |
| `post-boot` | Сразу после запуска рабочего стола |
| `post-update` | Ближе к концу `omarchy update`, после пакетов, миграций и перезапуска служб, до обновления инструментов mise |
| `pre-refresh-pacman` | После того как `omarchy refresh pacman` повторно синхронизирует конфигурацию пакетов, до обновления пакетов; переключение канала запускает его на том же шаге обновления |
| `theme-set` | После смены темы (название темы в `$1`) |
| `font-set` | После смены шрифта (название шрифта в `$1`) |
| `battery-low` | Когда заряд батареи становится низким (процент в `$1`) |

Именно в хук `pre-refresh-pacman` следует помещать пользовательские репозитории или строки `IgnorePkg`, поскольку он запускается до транзакции пакетов. Оба хука, связанные с обновлениями, запускаются от вашего пользователя после того, как Omarchy сбрасывает кэшированную авторизацию sudo, поэтому хуку, который использует `sudo`, нужна собственная авторизация, и он может запросить ваш пароль.

В каждом из этих каталогов уже есть файл `.sample`, показывающий форму хука — уберите `.sample` из названия, чтобы он заработал. Чтобы установить скрипт, написанный вами где-то ещё, используйте `omarchy hook install post-boot ~/my-hook` — эта команда скопирует его и сделает исполняемым.

### Добавление своих пунктов меню

Меню Omarchy (`Super + Space`) можно расширить своими собственными строками, отредактировав `~/.config/omarchy/extensions/omarchy-menu.jsonc`. Записи задаются точечным id, и именно id определяет их место в дереве, поэтому `personal` появляется в корневом меню, а `personal.notes` появляется внутри него:

```jsonc
"personal": {"icon":"","label":"Personal"},
"personal.notes": {"icon":"󰎞","label":"Notes","action":"omarchy-launch-editor ~/notes"},
```

Используйте существующий id повторно — и вы переопределите эту строку вместо добавления новой. В файле все доступные поля задокументированы в виде комментариев.

### Добавление своих экспортов оболочки, функций и алиасов

Omarchy поставляется с кучей эргономичных алиасов и полезных функций, но очень часто хочется добавить свои собственные. И алиасы, и функции, и экспорты следует добавлять в `~/.bashrc`. Этот файл не будет перезаписан при обновлениях. Если вы хотите изменить какие-либо значения Omarchy по умолчанию, их тоже можно безопасно добавить сюда.

### Настройка переменных окружения для рабочего стола

Экспорты сессии рабочего стола относятся к `~/.config/uwsm/env.d/`. Эти файлы выполняются до запуска рабочего стола, поэтому ошибка оболочки может отправить вас обратно на экран входа. Держите рабочий терминал открытым, пока редактируете их. Чтобы отключить переопределение, переместите его из `env.d`. См. [восстановление входа](45-troubleshooting.md#my-password-is-accepted-but-i-return-to-the-login-screen), если изменение не даёт войти в систему.

### Изменение внутренних файлов Omarchy

Слушайте, это ваш компьютер. Вы можете делать с ним всё, что хотите, но я бы не советовал вносить изменения напрямую в файлы в `/usr/share/omarchy`. Они принадлежат пакету Omarchy в pacman, поэтому ваши изменения просто будут перезаписаны при следующем обновлении. Лучше просто переопределите в папке `~/.config/*` любые значения по умолчанию, которые вам не нравятся.

Таким способом можно изменить почти всё, например сочетания клавиш по умолчанию. Просто отредактируйте `~/.config/hypr/bindings.lua`, чтобы, скажем, заменить [Obsidian](https://obsidian.md/) на [Joplin](https://joplinapp.org/) (устанавливается командой `omarchy-pkg-add joplin-bin`):

```lua
o.rebind("SUPER + SHIFT + O", "Joplin", "joplin-desktop")
```

`o.rebind` удаляет существующее сочетание перед добавлением его замены. Он принимает те же аргументы, что и `o.bind`, включая помощники запуска и опции сочетаний. Используйте `o.bind`, чтобы добавить сочетание, или `hl.unbind`, чтобы удалить его без замены.

Если вы настаиваете на взломе внутренних файлов Omarchy, переключитесь на dev-канал через _Update > Channel > Dev_. Это свяжет Omarchy с git-копией исходного кода в `~/omarchy`, которую вы вольны менять сколько душе угодно. Да и никто здесь не будет указывать вам, что делать!

### Сброс любых изменений

Если вы в итоге устроили беспорядок в конфигурациях, вы всегда можете вернуть их к значениям по умолчанию через _Update > Config_ в меню Omarchy. Или выполнив `omarchy reinstall configs`, чтобы сбросить всё.
