# Dotfiles

Настройка Omarchy выполняется в основном через так называемые dotfiles, которые находятся в `~/.config`. Считайте, что это ваши файлы для ваших изменений. Файлы, находящиеся в `/usr/share/omarchy`, принадлежат самой Omarchy, и трогать их не следует. Если вам нужно изменить что-либо в `/usr/share/omarchy`, вместо этого следует переопределить значение в `~/.config`.

Ключевые конфиги можно редактировать прямо из меню Omarchy (`Super + Space`), например _Setup > Keyboard > Keybindings_, _Setup > Input_ и _Setup > Config > [file]_. Если делать это так, любой процесс, который нужно перезапустить после правок конфига, будет автоматически перезапущен после выхода из редактора (по умолчанию это Neovim — `:wq`, не забудьте! — но это можно изменить через _Setup > Defaults > Editor_).

Вот список ключевых файлов в `~/.config` и того, чем они управляют:

| Файл                  | Назначение              |
| ----------------------- | --------------------- |
| `~/.config/hypr/hyprland.lua` | Главный конфиг Hyprland. Загружает настройки Omarchy по умолчанию плюс ваши файлы переопределений ниже. [Подробнее о конфигах Hyprland](https://wiki.hypr.land/Configuring/).  |
| `~/.config/hypr/bindings.lua` | Ваши собственные сочетания клавиш и переопределения настроек по умолчанию. |
| `~/.config/hypr/monitors.lua` | Настройки монитора, которые не покрывает панель мониторов, например поворот, дополнительные режимы или отключение монитора. |
| `~/.config/hypr/input.lua` | Управляет раскладкой клавиатуры, настройками мыши и тачпада. |
| `~/.config/hypr/looknfeel.lua` | Управляет отступами, рамками, анимациями и остальным внешним видом. |
| `~/.config/hypr/autostart.lua` | Управляет дополнительными процессами, запускаемыми вместе с сеансом. |
| `~/.config/omarchy/shell.json` | Управляет оболочкой Omarchy: положением панели, компоновкой и виджетами, а также заставкой, блокировкой и таймингами простоя. |
| `~/.config/foot/foot.ini` | Управляет вашим терминалом (по умолчанию это foot). |
| `~/.XCompose` | Определяет ваши эмодзи для быстрого доступа и автодополнение имени/email. Не забудьте выполнить `omarchy-restart-xcompose` после внесения изменений. |

Если в итоге вы внесёте много изменений, чтобы настроить всё под себя, будет хорошей идеей сделать резервную копию всех этих dotfiles. [Stow — отличный способ это сделать](https://www.youtube.com/watch?v=NoFiYOqnC4o).

### Запуск собственных приложений вместе с сеансом

Если вы хотите, чтобы что-то запускалось при каждом входе в систему — демон синхронизации, чат-приложение, ваш собственный скрипт — поместите это в `~/.config/hypr/autostart.lua`:

```lua
o.launch_on_start("my-service")
```

Это запускает команду как часть сеанса, поэтому при выходе из системы всё будет корректно завершено.

### Запуск скриптов при системных событиях

Omarchy запускает хуки в несколько моментов, и вы можете навесить на них свои собственные скрипты. Они находятся в `~/.config/omarchy/hooks/<event>.d/`, по одному каталогу на событие, и каждый файл в нём, имя которого не заканчивается на `.sample`, выполняется через bash при наступлении события:

| Событие | Когда запускается |
| ----- | ------------ |
| `post-boot` | Сразу после запуска рабочего стола |
| `post-update` | Ближе к концу `omarchy update`, после пакетов, миграций и перезапуска служб, до обновления инструментов mise |
| `pre-refresh-pacman` | После того как `omarchy refresh pacman` повторно синхронизирует конфиг пакетов, до обновления пакетов; переключение канала запускает его на том же самом шаге обновления |
| `theme-set` | После смены темы (название темы в `$1`) |
| `font-set` | После смены шрифта (название шрифта в `$1`) |
| `battery-low` | Когда заряд батареи становится низким (процент в `$1`) |

Хук `pre-refresh-pacman` — это место, куда следует помещать пользовательские репозитории или строки `IgnorePkg`, поскольку он запускается до транзакции пакетов. Оба запускаются от вашего пользователя. `post-update` запускается, пока авторизация sudo для `omarchy update` ещё действительна, поэтому хук, использующий `sudo`, не будет снова запрашивать ваш пароль; `pre-refresh-pacman` запускается сразу после того, как `omarchy refresh pacman` сама использовала sudo.

В каждом из этих каталогов уже есть файл `.sample`, показывающий, как должен выглядеть хук, — уберите `.sample` из имени, чтобы он заработал. Чтобы установить скрипт, написанный вами в другом месте, используйте `omarchy hook install post-boot ~/my-hook` — эта команда скопирует его туда и сделает исполняемым.

### Добавление собственных пунктов меню

Меню Omarchy (`Super + Space`) можно расширить своими собственными пунктами, отредактировав `~/.config/omarchy/extensions/omarchy-menu.jsonc`. Записи идентифицируются точечным id, и именно id определяет их место в дереве, поэтому `personal` появляется в корневом меню, а `personal.notes` — внутри него:

```jsonc
"personal": {"icon":"","label":"Personal"},
"personal.notes": {"icon":"󰎞","label":"Notes","action":"omarchy-launch-editor ~/notes"},
```

Если повторно использовать существующий id, вы переопределите этот пункт вместо добавления нового. В файле все доступные поля задокументированы в виде комментариев.

### Добавление собственных экспортов оболочки, функций и алиасов

Omarchy поставляется с набором эргономичных алиасов и полезных функций, но очень часто хочется добавить свои собственные. И алиасы, и функции, и экспорты следует добавлять в `~/.bashrc`. Этот файл не будет перезаписан при обновлениях. Если вы хотите изменить какие-либо настройки Omarchy по умолчанию, их также можно безопасно добавить сюда.

### Установка переменных окружения для рабочего стола

Экспорты сеанса рабочего стола следует помещать в `~/.config/uwsm/env.d/`. Эти файлы выполняются до запуска рабочего стола, поэтому ошибка оболочки может выбросить вас обратно на экран входа. Держите работающий терминал открытым, пока редактируете их. Чтобы отключить переопределение, переместите его из `env.d`. См. [восстановление входа](45-troubleshooting.md#my-password-is-accepted-but-i-return-to-the-login-screen), если изменение препятствует входу.

### Изменение внутренних файлов Omarchy

Слушайте, это ваш компьютер. Вы можете делать с ним всё, что хотите, но я бы не советовал вносить изменения непосредственно в файлы в `/usr/share/omarchy`. Они принадлежат пакету Omarchy в pacman, поэтому ваши изменения просто будут перезаписаны при следующем обновлении. Вместо этого вам лучше просто переопределить любые значения по умолчанию, которые вам не нравятся, в папке `~/.config/*`.

Таким способом можно изменить практически всё, например сочетания клавиш по умолчанию. Просто отредактируйте `~/.config/hypr/bindings.lua`, чтобы, скажем, заменить [Obsidian](https://obsidian.md/) на [Joplin](https://joplinapp.org/) (устанавливается с помощью `omarchy-pkg-add joplin-bin`):

```lua
o.rebind("SUPER + SHIFT + O", "Joplin", "joplin-desktop")
```

`o.rebind` удаляет существующую привязку перед добавлением её замены. Она принимает те же аргументы, что и `o.bind`, включая помощники запуска и параметры привязки. Используйте `o.bind`, чтобы добавить привязку, или `hl.unbind`, чтобы удалить её без замены.

Если вы настаиваете на том, чтобы покопаться во внутренних файлах Omarchy, переключитесь на канал dev через _Update > Channel > Dev_. Это свяжет Omarchy с git-копией исходного кода в `~/omarchy`, которую вы можете свободно изменять сколько душе угодно. Здесь никто не будет указывать вам, что делать!

### Сброс любых изменений

Если вы в итоге наведёте беспорядок в конфигурациях, вы всегда можете вернуть их к значениям по умолчанию через _Update > Config_ в меню Omarchy. Или выполнив `omarchy reinstall configs`, чтобы сбросить всё.
