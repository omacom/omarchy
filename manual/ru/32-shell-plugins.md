# Плагины шелла

Десктоп Omarchy едет одним долгоживущим процессом Quickshell под именем `omarchy-shell` — и почти всё, что видишь на экране, это плагин внутри него. Панель — плагин. Панели, выпадающие из него, — тоже. Фулскрин-оверлеи вроде пикера эмодзи и менеджера буфера, само меню Omarchy, локскрин, polkit-диалог и хедлесс-сервисы, что смотрят батарею и греют экран по ночам.

И это не деталь реализации. Значит, куски десктопа можно гасить, менять или писать свои, не трогая строку исходников Omarchy.

Фёстпати-плагины едут с Omarchy и живут в `$OMARCHY_PATH/shell/plugins/`. Всё, что добавил сам — свои эксперименты или найденное на GitHub, — живёт в `~/.config/omarchy/plugins/`. На старте находятся одинаково, но встроенным достаются доверенные интерфейсы шелла, а сторонним — ограниченный интерфейс в скоупе их сервиса и жизненного цикла. Клоны встроенных уносят только конфиг под источник и UI-вызовы, нужные под исходное поведение.

## Что есть

```
omarchy plugin list
```

Печатает каждый найденный плагин: id, включён ли, фёст- или тёртипати, kinds и display name. Добавь `--json`, если скармливаешь чему-то ещё.

Id плагинов неймспейсные. Встроенные все начинаются с `omarchy.` — `omarchy.clock`, `omarchy.network`, `omarchy.notifications` — и неймспейс зарезервирован: сторонний плагин его занять не сможет.

## Включение и выключение

```
omarchy plugin enable omarchy.tailscale
omarchy plugin disable omarchy.weather
```

Или через меню: в _Настройки > Плагины_ лежат Enable, Disable, Add, Clone и Remove — у каждого пикер, предлагающий только плагины, которым там место.

Состояние включения хранится в `~/.config/omarchy/shell.json`, и правило чуть разное для двух сортов плагинов. Тёртипати-плагин включён ровно когда его id светится где-то в том файле — записью layout панели, записью в `plugins[]` или как `bar.id`. Фёстпати-плагины не-виджеты панели — наоборот: включены по умолчанию и гасятся, только попав в `disabledPlugins[]`.

У полного плагина панели выключенного состояния вообще нет. Панель всегда ровно один — заменяешь включением другого. Расстановка виджетов панели — в [верхней панели](05-the-top-bar.md).

## Плагин из гита

Тёртипати-плагин — это просто git-репо с `manifest.json` в корне.

```
omarchy plugin add https://github.com/acme/omarchy-weather.git --enable
```

Прежде чем что-то делать, он прямым текстом скажет: плагины бегут произвольным непесочным кодом внутри твоего долгоживущего шелл-процесса, покажет URL и попросит подтвердить. Отнесись серьёзно. Интерфейс тёртипати-плагинов напрямую не отдаёт сервисы аутентификации, а заменяющий панель получает только ограниченные капабилити под настроенный неаутентификационный UI. Визуальные плагины делят QML-сцену шелла и гуляют по обычным родительским объектам, а весь код плагинов бежит со всем, до чего дотягивается твой юзер-аккаунт. Состояние аутентификации защищено отдельно — сервисы лежат вне достижимого графа хост-объектов. Добавляй только репо, которые готов гонять, и читай их до включения.

Заменяющий панель умеет рендерить поставленные виджеты, но сервис-бэкенд тёртипати-виджеты могут урезаться в функциональности — панели нельзя запрашивать живой сервис-объект другого плагина. Вернись на встроенный `omarchy.bar`, если такому виджету нужен его компаньон-сервис.

Дальше он клонит репо в стейджинг-каталог, валидирует манифест, отказывает в установке, если id уже занят другим плагином, и переезжает в `~/.config/omarchy/plugins/<id>/`. Без `--enable` спросит, включать ли прямо сейчас, — можно сказать нет и пойти читать код сначала. Он ничего не запускает из плагина, не исполняет install-хук и не просит sudo — клонит файлы, чекает манифест и щёлкает бит по IPC.

Обновление — фастфорвард-пулл того же чекаута:

```
omarchy plugin update acme.weather
omarchy plugin update
```

Без id обновляет каждый твой git-управляемый плагин. Покажет дифф до применения, откажет в обновлении, если есть локальные правки, через которые не фастфорвардится, и откатит, если новая ревизия не валидируется.

```
omarchy plugin remove acme.weather
```

Снос сначала дизейблит плагин, потом удаляет, если это git-чекаут (репо как было апстримом), или отлинковывает, если симлинк. Рукодельная папка плагина без git-репо едет в бэкап с меткой времени внутри каталога плагинов вместо удаления.

## Клон встроенного под себя

Моя любимая часть. Хочешь поменять поведение встроенного виджета — не правь файлы под `$OMARCHY_PATH`: они пакетные, следующее обновление затрет. Клонируй вместо этого:

```
omarchy plugin clone omarchy.clock
```

Скопирует весь плагин в `~/.config/omarchy/plugins/dhh.clock` (твой юзернейм, не мой), переименует в "My Clock", включит и переключит шелл со встроенного на твою копию — с сохранением позиции и настроек существующего виджета панели. Добавь `--edit`, чтобы сразу открыть новый каталог в `$EDITOR`, — менюшное _Настройки > Плагины > Clone Plugin_ делает это за тебя.

Юзернейм-префикс держит id клона твоим — шаринг ни с кем не столкнётся. Вызовы оригинального встроенного id роутит на твой клон — ничего, что ссылалось на `omarchy.clock`, обновлять не надо. А намесишь — `omarchy plugin remove dhh.clock` вернёт встроенный.

Сейв файла где угодно под `~/.config/omarchy/plugins/` перезагружает код плагина автоматом — оставь редактор открытым и смотри, как правки приземляются.

## Свой с нуля

Плагин — каталог с `manifest.json` и немного QML. Манифест декларит `schemaVersion: 1`, `id`, `name`, `version`, один или несколько `kinds` и объект `entryPoints` на QML-файл каждого kind:

| Kind | Что это |
|------|------------|
| `bar-widget` | Компонент, который активный панель роняет в секцию |
| `panel` | Персистентное или вызываемое плавающее окно |
| `overlay` | Фулскрин-оверлей |
| `menu` | Вызываемая поверхность меню |
| `service` | Хедлесс-синглтон без UI |
| `bar` | Полный панель вместо встроенного |

Плагин может декларить несколько kinds сразу — медиа-плагин и `service`, и `bar-widget`. Виджеты панели получают лишний блок `barWidget` с display name, категорией, опциональным `defaultSection` и `allowMultiple` — есть ли смысл больше одного на панели. Большинство виджетов ставит `false`; спейсеры и индикаторы — `true`.

Прежде чем публиковать — проверь:

```
omarchy plugin validate ./my-plugin
```

Гоняет те же чеки, что шелл при загрузке: версия схемы, обязательные поля, незарезервированный id, entry points — безопасными относительными путями и реально существующие, entry point на каждый заявленный kind и никаких симлинков в папке.

Под разработку плагинов — [референс шелла](https://github.com/omacom/omarchy/blob/quattro/docs/omarchy-shell.md) и [каталог фёстпати-плагинов](https://github.com/omacom/omarchy/blob/quattro/shell/plugins/README.md).

## Своим делишься с миром

Сделал что нравится — положи в публичное git-репо. Весь механизм дистрибуции: любой прогоняет `omarchy plugin add` на твой URL — и через секунды оно бежит.

Чтобы находили, листи на [omarchyplugins.com](https://omarchyplugins.com). Это комьюнити-каталог шелл-плагинов Omarchy — первое место глянуть, не построил ли уже кто виджет, который собрался писать. Броузь его до старта!
