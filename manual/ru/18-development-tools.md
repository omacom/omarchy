# Инструменты разработки

## Альтернативные редакторы

По умолчанию Omarchy поставляется с [Neovim](https://neovim.io/), но если вам нужно что-то более привычное и массовое, откройте меню Omarchy (`Super + Space`) и посмотрите варианты в разделе _Установить > Editor_. Там есть VSCode, Cursor, Zed, Sublime Text, Helix, Vim и Emacs. Если вы не нашли то, что ищете, загляните в _Установить > Package_ и проверьте, нет ли нужного в пакетах Arch (а если нет, попробуйте _Установить > AUR_ и проверьте AUR).

Оригинальный редактор `vi` тоже доступен из коробки. Выполните `vi filename`, чтобы отредактировать файл в терминале.

Подбор темы предлагается для `VSCode`, `Cursor`, `VSCodium` и `Helix`.

Системный редактор по умолчанию можно задать в разделе `Setup > Defaults > Editor`.

## Окружения

Omarchy поддерживает настройку целого ряда окружений разработки через раздел _Установить > Development_ в меню Omarchy (`Super + Space`). Там, конечно, есть _Ruby on Rails_, но также все три основных рантайма для JavaScript (Node.js, Bun, Deno), а также популярные PHP-фреймворки, такие как Laravel и Symfony. Ах да, и там есть Go, Rust, Python, Java, Elixir (с Phoenix), .NET, OCaml, Zig, Clojure и Scala. Выбор очень широкий!

Большинство этих окружений управляется через [Mise](https://mise.jdx.dev/). Это инструмент, который позволяет устанавливать и запускать несколько версий языка программирования на одном компьютере. Это как rbenv или rvm для Ruby или virtualenv для Python, но работает для множества разных окружений.

Чтобы установить, скажем, Ruby, выполните `mise use -g ruby` — это и установит Ruby, и задаст его как глобальный вариант по умолчанию. А если в вашем проекте есть файл .ruby-version, можно просто выполнить `mise i` в корне проекта.

## Docker

[Docker](https://www.docker.com/) едва ли нуждается в представлении. Он позволяет запускать изолированные контейнеры, и Omarchy устанавливает всё необходимое для хорошей работы, включая сам Docker и [Docker Compose](https://docs.docker.com/compose/).

По умолчанию ваш пользователь *не входит* в группу `docker`. Эта группа фактически даёт root без пароля — любой её участник может выполнить `docker run -v /:/host` и захватить компьютер — поэтому один-единственный вредоносный скрипт или зависимость, запущенная от вашего имени, иначе была бы в одной команде от root. Поэтому в командной строке Docker запускают через `sudo` (`sudo docker ps`, `sudo docker compose up`), а графические инструменты, которые обращаются к демону, — виртуальная машина Windows — запрашивают авторизацию, когда она нужна. Если вы хотите вернуть удобство работы без группы и понимаете, чем за это платите, включите это в разделе **Setup > Security > Sudoless Docker** (или выполните `omarchy-setup-security-sudoless-docker`), который добавит вас в группу `docker` после предупреждения; тогда обычный `docker` и alias `d` снова заработают без `sudo`.

Вы можете настроить распространённые базы данных для локальной разработки в Docker через _Установить > Development > Docker DB_ в меню Omarchy.

## GitHub CLI

[GitHub CLI](https://cli.github.com/) позволяет аутентифицироваться в вашей учётной записи GitHub и клонировать с её помощью приватные репозитории. Он подключён как одна из лениво загружаемых заглушек mise, поэтому при первом запуске `gh` он установит сам себя. Для аутентификации выполните `gh auth login`. Затем можно получать приватные репозитории командой `gh repo clone org/repo`.

С помощью этой команды можно также выполнять множество других операций GitHub. Просто выполните `gh`, чтобы увидеть все возможности.

Есть также лениво устанавливающаяся заглушка `ghui` для управления pull request в TUI. А [lazygit](https://github.com/jesseduffield/lazygit) предустановлен, если вы хотите управлять самим git тоже из TUI.
