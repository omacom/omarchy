# Инструменты разработки

## Альтернативные редакторы

Omarchy поставляется с Plain в качестве редактора по умолчанию при новых установках и предустановленным [Neovim](https://neovim.io/), но если вам хочется чего-то более распространённого и знакомого, вы можете открыть меню Omarchy (`Super + Space`) и посмотреть варианты в разделе _Install > Editor_. Там у нас указаны VSCode, Cursor, Zed, Sublime Text, Helix, Vim и Emacs. Если вы не найдёте то, что ищете, загляните в _Install > Package_ и посмотрите, нет ли этого в пакете Arch (а если нет, попробуйте _Install > AUR_, чтобы проверить AUR).

Оригинальный редактор `vi` также доступен из коробки. Запустите `vi filename`, чтобы отредактировать файл в терминале.

Сопоставление тем предлагается для `VSCode`, `Cursor`, `VSCodium` и `Helix`.

Общесистемный редактор по умолчанию можно задать в `Setup > Defaults > Editor`.

## Среда

Omarchy поддерживает настройку целого множества сред разработки через раздел _Install > Development_ меню Omarchy (`Super + Space`). Там, конечно, найдётся _Ruby on Rails_, но также все три основные среды выполнения для JavaScript (Node.js, Bun, Deno), а ещё популярные PHP-фреймворки, такие как Laravel и Symfony. Ах да, там также есть Go, Rust, Python, Java, Elixir (с Phoenix), .NET, OCaml, Zig, Clojure и Scala. Выбор очень широкий!

Большинство этих сред управляются [Mise](https://mise.jdx.dev/). Это инструмент, который позволяет устанавливать и запускать несколько версий языка программирования на одном компьютере. Это как rbenv или rvm для Ruby или virtualenv для Python, но работает для множества разных сред.

Чтобы установить, скажем, Ruby, нужно запустить `mise use -g ruby`: это и установит Ruby, и задаст его глобально по умолчанию. Или, если у вашего проекта есть файл .ruby-version, можно просто запустить `mise i` в корне этого проекта.

## Предустановленные инструменты CLI

`uv`, Node.js и `playwright-cli` (чтобы агенты могли управлять браузером, используя установленный Chrome) поставляются установленными в виде пакетов, и `omarchy update` поддерживает их актуальность вместе с остальной системой. [Hunk](https://github.com/modem-dev/hunk) и CLI для GitHub, Basecamp, Cloudflare и HEY находятся на расстоянии одного выбора в _Install > CLI_, а [агенты программирования](17-ai.md) — в _Install > AI > CLI_.

mise управляет только теми средами выполнения, которые вы настраиваете из _Install > Development_; Omarchy сама по себе ничего не устанавливает через него. Запускайте `omarchy update`, чтобы обновлять их вместе с остальным Omarchy; псевдоним `mup` обновляет только инструменты, управляемые mise. Чтобы добавить другой инструмент в вашу собственную конфигурацию, используйте `mise use -g <tool>`.

## Docker

[Docker](https://www.docker.com/) вряд ли нуждается в представлении. Он позволяет запускать изолированные контейнеры, и Omarchy устанавливает всё необходимое для его полноценной работы, включая сам Docker и [Docker Compose](https://docs.docker.com/compose/).

По умолчанию ваш пользователь *не* входит в группу `docker`. Эта группа фактически даёт root без пароля — любой, кто в неё входит, может запустить `docker run -v /:/host` и захватить компьютер, — поэтому один-единственный вредоносный скрипт или зависимость, запущенная от вашего имени, в противном случае оказался бы в одной команде от root. Поэтому в командной строке Docker запускают с `sudo` (`sudo docker ps`, `sudo docker compose up`), а графические инструменты, которые общаются с демоном — VM с Windows, — запрашивают авторизацию, когда она им нужна. Если вы хотите вернуть удобство конфигурации без sudo и понимаете компромисс, включите её в **Setup > Security > Sudoless Docker** (или запустите `omarchy-setup-security-sudoless-docker`): после предупреждения вас добавят в группу `docker`; после этого обычный `docker` и псевдоним `d` снова будут работать без `sudo`.

Вы можете настроить распространённые базы данных для локальной разработки в Docker, используя _Install > Development > Docker DB_ в меню Omarchy.

## GitHub CLI

[GitHub CLI](https://cli.github.com/) — это `gh`, для работы с репозиториями, issues и pull requests из терминала. _Setup > Git_ устанавливает его, когда вы решаете войти там в GitHub, или установите его отдельно из _Install > CLI > GitHub_. Затем `gh repo clone org/repo` клонирует репозиторий; запустите `gh --help`, чтобы изучить его команды.

[Lazygit](https://github.com/jesseduffield/lazygit) предустановлен для работы с самим Git.
