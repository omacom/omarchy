# Инструменты разработки

## Альтернативные редакторы

Omarchy поставляется с Plain в качестве редактора по умолчанию на новых установках и с предустановленным [Neovim](https://neovim.io/), но если вам хочется чего-то более массового и привычного, вы можете открыть Omarchy Menu (`Super + Space`) и посмотреть варианты в разделе _Установка > Редактор_. Там у нас есть VSCode, Cursor, Zed, Sublime Text, Helix, Vim и Emacs. Если вы не найдёте то, что ищете, загляните в _Установка > Пакет_ и посмотрите, нет ли этого в пакете Arch (а если нет, попробуйте _Установка > AUR_, чтобы проверить AUR).

Оригинальный редактор `vi` также доступен из коробки. Запустите `vi filename`, чтобы отредактировать файл в терминале.

Подбор темы оформления предлагается для `VSCode`, `Cursor`, `VSCodium` и `Helix`.

Вы можете задать редактор по умолчанию для всей системы в `Setup > Defaults > Editor`.

## Среда разработки

Omarchy поддерживает настройку целого множества сред разработки через раздел _Установка > Разработка_ в Omarchy Menu (`Super + Space`). Там вы, конечно, найдёте _Ruby on Rails_, но также все три основных среды выполнения для JavaScript (Node.js, Bun, Deno), а также популярные PHP-фреймворки, такие как Laravel и Symfony. Ах да, там ещё есть Go, Rust, Python, Java, Elixir (с Phoenix), .NET, OCaml, Zig, Clojure и Scala. Выбор очень широкий!

Большинство этих сред управляются через [Mise](https://mise.jdx.dev/). Это инструмент, который позволяет устанавливать и запускать несколько версий языка программирования на одном компьютере. Это как rbenv или rvm для Ruby или virtualenv для Python, но он работает для множества разных сред.

Чтобы установить, скажем, Ruby, нужно запустить `mise use -g ruby` — это и установит Ruby, и задаст его в качестве глобального варианта по умолчанию. Или, если в вашем проекте есть файл .ruby-version, вы можете просто запустить `mise i` в корне этого проекта.

## Предустановленные инструменты командной строки

Omarchy делает такие инструменты, как `gh`, `uv`, и большинство [агентов для программирования](17-ai.md) доступными через [ленивую установку mise](https://mise.jdx.dev/dev-tools/shims.html#lazy-tools). При первом запуске одного из них mise его устанавливает. Затем агенты для программирования перед запуском проверяют наличие обновления, не чаще одного раза в четыре часа; другие инструменты, такие как `gh` и `uv`, продолжают использовать установленную версию, пока вы её не обновите.

Вы также можете посмотреть настройки по умолчанию или установить их заранее:

```bash
mise ls --current              # List the tools configured for this directory
mise install gh               # Install one tool now
mise install --include-lazy    # Install all configured tools, including lazy tools
```

Запустите `omarchy update`, чтобы обновить установленные инструменты вместе с остальной частью Omarchy. Псевдоним `mup` обновляет только инструменты, управляемые mise. Чтобы добавить ещё один инструмент в вашу собственную конфигурацию, используйте `mise use -g <tool>`.

Настройка Python также устанавливает `uv` через mise. Удаление среды разработки Python оставляет `uv` доступным как независимый инструмент.

### Использование собственной установки

Команды mise стоят перед `~/.local/bin` в `PATH`, поэтому инструмент, который вы установили сами, например с помощью собственного установщика Claude Code или Cursor, всё равно будет запускать копию mise. Приложения, запущенные с рабочего стола, также находят команды mise раньше системных пакетов, поэтому приложение, которое запускает `gh`, получит копию mise, даже если вы установили `github-cli` с помощью pacman, и mise установит эту копию при первом использовании. Чтобы вместо этого использовать вашу копию, отключите копию mise в `~/.config/mise/config.toml`. Например, если вы сами установили Cursor CLI:

```toml
[settings]
disable_tools = ["cursor-agent"]
```

Если у вас уже есть таблица `[settings]`, добавьте запись туда; расширяйте существующий список `disable_tools`, а не заменяйте его. Убедитесь, что ваша установка находится в `PATH`. Используйте имя инструмента mise, которое может отличаться от его команды: например, `oh-my-pi` предоставляет `omp`. Программа запуска агента по умолчанию также отдаёт предпочтение установленным пользователем Cursor или Muse в `~/.local/bin`.

### Удаление и восстановление настроек по умолчанию

_Удаление > Предустановленные_ удаляет предустановленные веб-приложения, TUI и приложения Omarchy и заставляет mise пропускать объявления инструментов Omarchy для вашего пользователя, добавляя их в `ignored_config_paths` в `~/.config/mise/miserc.toml`. _Установка > Предустановленные_ возвращает их и снова удаляет эту строку. Инструменты, которые вы объявляете сами, в своей собственной конфигурации или в `mise.toml` проекта, в любом случае продолжают работать. Если после удаления предустановленных компонентов вы выберете агента по умолчанию или настроите Python, этот инструмент будет добавлен в вашу собственную конфигурацию. Настройка mise применяется только к вашему пользователю, и у других пользователей сохраняется их собственный выбор; однако приложения — это пакеты, поэтому их удаление или восстановление меняет их для всех на компьютере.

## Docker

[Docker](https://www.docker.com/) в представлении вряд ли нуждается. Он позволяет запускать изолированные контейнеры, и Omarchy устанавливает всё необходимое для его хорошей работы, включая сам Docker и [Docker Compose](https://docs.docker.com/compose/).

По умолчанию ваш пользователь *не* входит в группу `docker`. Эта группа фактически даёт root без пароля — всё, что в неё входит, может выполнить `docker run -v /:/host` и захватить компьютер, — поэтому один-единственный вредоносный скрипт или зависимость, запущенные от вашего имени, в противном случае оказались бы в одной команде от root. Поэтому в командной строке вы запускаете Docker с `sudo` (`sudo docker ps`, `sudo docker compose up`), а графические инструменты, которые общаются с демоном, — Windows VM — запрашивают авторизацию, когда она им нужна. Если вы хотите вернуть себе удобство работы без sudo и понимаете, на какой компромисс идёте, включите это в **Настройка > Безопасность > Sudoless Docker** (или запустите `omarchy-setup-security-sudoless-docker`) — эта настройка добавит вас в группу `docker` после предупреждения; после этого обычный `docker` и псевдоним `d` снова будут работать без `sudo`.

Вы можете настроить распространённые базы данных для локальной разработки в Docker с помощью _Установка > Разработка > Docker DB_ в меню Omarchy.

## GitHub CLI

[GitHub CLI](https://cli.github.com/) доступен как `gh` для работы с репозиториями, задачами и pull request из терминала. Запустите `gh auth login`, чтобы установить его при первом использовании и пройти аутентификацию, затем `gh repo clone org/repo`, чтобы клонировать репозиторий. Запустите `gh --help`, чтобы изучить его команды.

Для терминального интерфейса для pull request запустите `ghui`; mise также устанавливает его при первом использовании. [Lazygit](https://github.com/jesseduffield/lazygit) предустановлен для работы с самим Git.
