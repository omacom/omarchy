# Инструменты разработки

## Альтернативные редакторы

Omarchy поставляется с Plain в качестве редактора по умолчанию при новых установках и с предустановленным [Neovim](https://neovim.io/), но если вам хочется чего-то чуть более массового и привычного, вы можете открыть Omarchy Menu (`Super + Space`) и посмотреть варианты в разделе _Install > Editor_. Там у нас перечислены VSCode, Cursor, Zed, Sublime Text, Helix, Vim и Emacs. Если вы не найдёте то, что ищете, загляните в _Install > Package_ и посмотрите, нет ли этого в пакете Arch (а если нет, попробуйте _Install > AUR_, чтобы проверить AUR).

Оригинальный редактор `vi` также доступен из коробки. Выполните `vi filename`, чтобы отредактировать файл в терминале.

Сопоставление тем оформления предлагается для `VSCode`, `Cursor`, `VSCodium` и `Helix`.

Вы можете задать редактор по умолчанию для всей системы в разделе `Setup > Defaults > Editor`.

## Окружение

Omarchy поддерживает настройку целого множества окружений разработки через раздел _Install > Development_ в Omarchy Menu (`Super + Space`). Разумеется, вы найдёте там _Ruby on Rails_, а также все три основные среды выполнения JavaScript (Node.js, Bun, Deno), а ещё популярные PHP-фреймворки, такие как Laravel и Symfony. Ах да, там также есть Go, Rust, Python, Java, Elixir (с Phoenix), .NET, OCaml, Zig, Clojure и Scala. Выбор очень широкий!

Большинством этих окружений управляет [Mise](https://mise.jdx.dev/). Это инструмент, который позволяет устанавливать и запускать несколько версий языка программирования на одной машине. Это как rbenv или rvm для Ruby или virtualenv для Python, но работает для множества разных окружений.

Чтобы установить, скажем, Ruby, вы выполните `mise use -g ruby` — это и установит Ruby, и задаст его как глобальное значение по умолчанию. Или, если в вашем проекте есть файл .ruby-version, вы можете просто выполнить `mise i` в корне этого проекта.

## Предустановленные инструменты CLI

`uv`, Node.js и `playwright-cli` (чтобы агенты могли управлять браузером, используя установленный Chrome) поставляются установленными в виде пакетов, а `omarchy update` поддерживает их в актуальном состоянии вместе с остальной системой. `ghui`, [Hunk](https://github.com/modem-dev/hunk), а также CLI для Basecamp, Cloudflare и HEY находятся всего в одном выборе в разделе _Install > CLI_, а [агенты для программирования](17-ai.md) — в _Install > AI > CLI_.

mise управляет только теми средами выполнения, которые вы настроили в _Install > Development_; сам по себе Omarchy ничего через него не устанавливает. Выполните `omarchy update`, чтобы обновить их вместе с остальным Omarchy; псевдоним `mup` обновляет только инструменты, управляемые mise. Чтобы добавить ещё один инструмент в свою конфигурацию, используйте `mise use -g <tool>`.

## Docker

[Docker](https://www.docker.com/) едва ли нуждается в представлении. Он позволяет запускать изолированные контейнеры, и Omarchy устанавливает всё необходимое для его хорошей работы, включая сам Docker и [Docker Compose](https://docs.docker.com/compose/).

По умолчанию ваш пользователь *не* входит в группу `docker`. Эта группа фактически даёт root без пароля — любой участник может выполнить `docker run -v /:/host` и захватить машину, — поэтому один-единственный вредоносный скрипт или зависимость, запущенные от вашего имени, в противном случае оказались бы всего в одной команде от root. Поэтому в командной строке вы запускаете Docker с `sudo` (`sudo docker ps`, `sudo docker compose up`), а графические инструменты, которые взаимодействуют с демоном, — Windows VM — запрашивают авторизацию, когда она им нужна. Если вы хотите вернуть удобство конфигурации без группы и понимаете компромисс, включите её в **Setup > Security > Sudoless Docker** (или выполните `omarchy-setup-security-sudoless-docker`), что добавит вас в группу `docker` после предупреждения; тогда обычный `docker` и псевдоним `d` снова будут работать без `sudo`.

Вы можете настроить распространённые базы данных для локальной разработки в Docker с помощью _Install > Development > Docker DB_ в меню Omarchy.

## GitHub CLI

[GitHub CLI](https://cli.github.com/) — это `gh`, для работы с репозиториями, issues и pull requests из терминала. _Setup > Git_ устанавливает его, когда вы выбираете войти там в GitHub, после чего `gh repo clone org/repo` клонирует репозиторий. Выполните `gh --help`, чтобы изучить его команды.

_Install > CLI > GitHub_ устанавливает GitHub CLI, `gh`, вместе с `ghui`, терминальным интерфейсом для pull requests. [Lazygit](https://github.com/jesseduffield/lazygit) предустановлен для работы с самим Git.
