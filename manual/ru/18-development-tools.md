# Инструменты разработки

## Альтернативные редакторы

Omarchy по умолчанию поставляется с [Neovim](https://neovim.io/), но если вам хочется чего-то более массового и привычного, вы можете открыть Omarchy Menu (`Super + Space`) и посмотреть варианты в разделе _Install > Editor_. Там перечислены VSCode, Cursor, Zed, Sublime Text, Helix, Vim и Emacs. Если вы не найдёте то, что ищете, загляните в _Install > Package_ и проверьте, нет ли этого в пакете Arch (а если нет, попробуйте _Install > AUR_, чтобы проверить AUR).

Оригинальный редактор `vi` также доступен из коробки. Выполните `vi filename`, чтобы отредактировать файл в терминале.

Подбор темы под оформление системы предлагается для `VSCode`, `Cursor`, `VSCodium` и `Helix`.

Редактор по умолчанию для всей системы можно задать в `Setup > Defaults > Editor`.

## Окружение

Omarchy поддерживает настройку целого множества сред разработки через раздел _Install > Development_ в Omarchy Menu (`Super + Space`). Разумеется, вы найдёте там _Ruby on Rails_, а также все три основные среды выполнения для JavaScript (Node.js, Bun, Deno) и популярные фреймворки PHP, такие как Laravel и Symfony. Ах да, там также есть Go, Rust, Python, Java, Elixir (с Phoenix), .NET, OCaml, Zig, Clojure и Scala. Выбор очень широкий!

Большинство этих окружений управляется с помощью [Mise](https://mise.jdx.dev/). Это инструмент, который позволяет устанавливать и запускать несколько версий языка программирования на одной машине. Это как rbenv или rvm для Ruby или virtualenv для Python, но работает для множества разных окружений.

Чтобы установить, скажем, Ruby, нужно выполнить `mise use -g ruby` — это и установит Ruby, и задаст его глобально по умолчанию. Или, если в вашем проекте есть файл .ruby-version, вы можете просто выполнить `mise i` в корне этого проекта.

## Предустановленные инструменты CLI

Omarchy предоставляет такие инструменты, как `gh`, `uv`, и большинство [агентов для программирования](17-ai.md) через [ленивую установку mise](https://mise.jdx.dev/dev-tools/shims.html#lazy-tools). При первом запуске одного из них mise его устанавливает. Последующие запуски используют установленную версию; они не проверяют наличие обновления при каждом запуске.

Вы также можете просмотреть значения по умолчанию или установить их заранее:

```bash
mise ls --current              # List the tools configured for this directory
mise install gh               # Install one tool now
mise install --include-lazy    # Install all configured tools, including lazy tools
```

Выполните `omarchy update`, чтобы обновить установленные инструменты вместе с остальной частью Omarchy. Псевдоним `mup` обновляет только инструменты, управляемые mise. Чтобы добавить другой инструмент в вашу собственную конфигурацию, используйте `mise use -g <tool>`.

Настройка Python также устанавливает `uv` через mise. Удаление среды разработки Python оставляет `uv` доступным как независимый инструмент.

### Использование собственной установки

Команды mise стоят перед `~/.local/bin` в `PATH`, поэтому инструмент, установленный вами самостоятельно, например с помощью собственного установщика Claude Code или Cursor, по-прежнему будет запускать копию mise. Приложения, запущенные с рабочего стола, также находят команды mise раньше системных пакетов, поэтому приложение, запускающее `gh`, получит копию mise, даже если вы установили `github-cli` через pacman, и mise установит эту копию при первом запуске. Чтобы вместо этого использовать вашу копию, отключите копию mise в `~/.config/mise/config.toml`. Например, если вы самостоятельно установили Cursor CLI:

```toml
[settings]
disable_tools = ["cursor-agent"]
```

Если у вас уже есть таблица `[settings]`, добавьте запись в неё; расширьте существующий список `disable_tools`, а не заменяйте его. Убедитесь, что ваша установка находится в `PATH`. Используйте имя инструмента mise, которое может отличаться от его команды: например, `oh-my-pi` предоставляет `omp`. Программа запуска агента по умолчанию также предпочитает установленные пользователем Cursor или Muse в `~/.local/bin`.

### Удаление и восстановление значений по умолчанию

_Remove Preinstalls_ заставляет mise пропускать объявления инструментов Omarchy для вашего пользователя, добавляя их в `ignored_config_paths` в `~/.config/mise/miserc.toml`. _Restore Preinstalls_ снова удаляет эту строку. Инструменты, объявленные вами самостоятельно — в вашей собственной конфигурации или в `mise.toml` проекта, — продолжают работать в любом случае. Если вы выберете агента по умолчанию или настроите Python после удаления предустановок, этот инструмент будет добавлен в вашу собственную конфигурацию. Оба действия применяются только к вашему пользователю; другие пользователи на машине сохраняют свой собственный выбор.

## Docker

[Docker](https://www.docker.com/) едва ли нуждается в представлении. Он позволяет запускать изолированные контейнеры, и Omarchy устанавливает всё необходимое для его хорошей работы, включая сам Docker и [Docker Compose](https://docs.docker.com/compose/).

По умолчанию ваш пользователь *не* входит в группу `docker`. Эта группа фактически даёт root без пароля — любой, кто в неё входит, может выполнить `docker run -v /:/host` и захватить машину, — поэтому один вредоносный скрипт или зависимость, запущенная от вашего имени, в противном случае оказалась бы в одной команде от root. Поэтому в командной строке вы запускаете Docker через `sudo` (`sudo docker ps`, `sudo docker compose up`), а графические инструменты, взаимодействующие с демоном, — Windows VM, — при необходимости запрашивают авторизацию. Если вы хотите вернуть удобство настройки без группы и понимаете компромисс, включите это в **Setup > Security > Sudoless Docker** (или выполните `omarchy-setup-security-sudoless-docker`), что добавит вас в группу `docker` после предупреждения; тогда обычный `docker` и псевдоним `d` снова будут работать без `sudo`.

Вы можете настроить распространённые базы данных для локальной разработки в Docker с помощью _Install > Development > Docker DB_ в меню Omarchy.

## GitHub CLI

[GitHub CLI](https://cli.github.com/) доступен как `gh` для работы с репозиториями, задачами и pull request из терминала. Выполните `gh auth login`, чтобы установить его при первом использовании и пройти аутентификацию, затем `gh repo clone org/repo`, чтобы клонировать репозиторий. Выполните `gh --help`, чтобы изучить его команды.

Для терминального интерфейса к pull request выполните `ghui`; mise также устанавливает его при первом использовании. [Lazygit](https://github.com/jesseduffield/lazygit) предустановлен для работы с самим Git.
