# Установка без участия пользователя

ISO-образ Omarchy может установить сам себя, когда за клавиатурой никого нет. Если установщик находит второй диск с меткой `cidata`, на котором лежат его файлы конфигурации, он копирует их оттуда, полностью пропускает мастер настройки и сам перезагружается в готовую систему. Никакой специальной сборки ISO, никакого дополнительного пункта в меню загрузки — если такого диска не подключено, ничего не меняется и вы получаете обычный мастер.

Благодаря этому Omarchy отлично подходит в качестве базового образа для одноразовых сред разработки: создайте VM в Proxmox или с помощью Packer, загрузите её, отойдите в сторону и заходите по SSH. `cidata` — это метка `NoCloud` из cloud-init, поэтому все распространённые инструменты виртуализации уже умеют подключать такой диск.

## Файлы конфигурации

Эти файлы — ровно те, что пишет собственный мастер установщика, поэтому самый простой способ получить начальный набор — выполнить одну интерактивную установку (например, в VM) и скопировать то, что он записал в `/root`:

| Файл | Обязательный | Назначение |
|------|----------|---------|
| `user_configuration.json` | Да | Диск, имя хоста, часовой пояс, клавиатура |
| `user_credentials.json` | Да | Имя пользователя и хэш пароля, а также парольная фраза LUKS для установки с шифрованием |
| `user_encrypt_installation.txt` | Нет | `true`, когда в конфигурации есть блок `disk_encryption` |
| `authorized_keys` | Нет | Открытые ключи SSH, по одному на строку |
| `tailscale_authkey` | Нет | Ключ аутентификации Tailscale для подключения к вашему tailnet при первой загрузке |

Сгенерируйте хэш пароля для `user_credentials.json` с помощью `openssl passwd -6 "yourpassword"`.

Имя и адрес электронной почты для коммитов git не входят в установку. Задайте их, когда машина уже будет работать, например по SSH, с помощью `omarchy setup git --name "Jane Doe" --email jane@example.com`.

Вы также можете вместо `user_credentials.json` положить пустой файл с именем `defer-provisioning`. Это запустит ту же [установку с подготовкой для другого владельца](02-getting-started.md), которую можно выбрать интерактивно: машина устанавливается без личных данных, а тот, кто загрузит её первым, выберет свою клавиатуру и создаст своего пользователя. Это режим для стендов создания образов, где на диске вообще не должно быть ничьих учётных данных.

## Доступ по SSH

Когда присутствует `authorized_keys`, установка настраивает эти ключи как `~/.ssh/authorized_keys` пользователя, включает `sshd` и открывает для него firewall. (В обычной установке Omarchy поставляется openssh с отключённой службой и закрытым портом, поэтому машина без участия пользователя иначе была бы недоступна.) Установка только добавляет ваши ключи — она не ослабляет никакие другие параметры аутентификации демона SSH.

Когда вместо этого присутствует `tailscale_authkey`, машина при первой загрузке подключается к вашему tailnet: Tailscale устанавливается из пакетов, включённых в ISO, firewall разрешает интерфейс tailnet, а фоновое задание выполняет подключение, как только у машины действительно появится сеть, и повторяет попытки до успешного результата. Используйте многоразовый, предварительно авторизованный ключ, чтобы один образ диска мог обслуживать множество машин.

## Создание диска cidata

Подойдёт любая файловая система с правильной меткой. Простой способ — крошечный ISO:

```bash
mkdir cidata
cp user_configuration.json user_credentials.json authorized_keys cidata/
genisoimage -output cidata.iso -volid cidata -joliet -rock cidata/
```

Затем подключите его к VM вместе с ISO Omarchy. Вот полный пример для Proxmox:

```bash
qm create 101 --name my-omarchy \
  --bios ovmf --machine q35 --cpu host --cores 4 --memory 8192 \
  --ostype l26 --scsihw virtio-scsi-single \
  --efidisk0 local-lvm:0,efitype=4m,pre-enrolled-keys=0 \
  --scsi0 local-lvm:40,discard=on,iothread=1 \
  --net0 virtio,bridge=vmbr0 --vga virtio --serial0 socket \
  --ide2 local:iso/omarchy.iso,media=cdrom \
  --ide3 local:iso/cidata.iso,media=cdrom \
  --boot order='scsi0;ide2'

qm start 101
```

Диск указан первым в порядке загрузки намеренно: пустой диск при первой загрузке пропускает загрузку дальше к ISO, а установленная система с тех пор всегда загружается с диска.

## Два важных замечания

Установка с шифрованием без участия пользователя не полностью автоматическая — кому-то всё равно придётся ввести парольную фразу LUKS при первой загрузке. И эта парольная фраза указывается на верхнем уровне `user_credentials.json` как `encryption_password` — archinstall читает её именно оттуда, а не из блока `disk_encryption` в `user_configuration.json`, — поэтому относитесь к диску cidata, созданному на основе установки с шифрованием, как к секрету, которым он и является.
