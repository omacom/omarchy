# Автоматическая установка

ISO Omarchy ставится само, без никого за клавиатурой. Найдёт инсталлер второй драйв с меткой `cidata` и его конфигами — скопирует, скипнет визард сетапа целиком и ребутнётся в готовую систему само. Без спец-сборки ISO, без лишней записи в boot-меню: нет такого драйва — ничего не меняется, получаешь обычный визард.

Так Omarchy отлично едет базовым образом под одноразовые дев-окружения: создай VM в Proxmox или Packer, загрузи, уходи, заходи по SSH. `cidata` — cloud-init-метка `NoCloud`, так что весь ходовой виртуализационный тулинг и так умеет цеплять такой драйв.

## Файлы конфигурации

Файлы — ровно те, что пишет визард самого инсталлера, так что легче всего взять стартовый набор, прогнав одну интерактивную установку (в VM, скажем) и скопировав написанное в `/root`:

| Файл | Обязателен | Назначение |
|------|----------|---------|
| `user_configuration.json` | Да | Диск, hostname, часовой пояс, клавиатура |
| `user_credentials.json` | Да | Юзернейм и хеш пароля |
| `user_full_name.txt` | Нет | Git полное имя |
| `user_email_address.txt` | Нет | Git почта |
| `user_encrypt_installation.txt` | Нет | `true`, когда в конфигурации есть блок `disk_encryption` |
| `authorized_keys` | Нет | SSH-публичные ключи, по одному на строку |
| `tailscale_authkey` | Нет | Tailscale auth-ключ под вход в твой тейлнет на первой загрузке |

Хеш пароля под `user_credentials.json` генерится через `openssl passwd -6 "твойпароль"`.

Можно кинуть пустой файл `defer-provisioning` вместо `user_credentials.json`. Прогонит ту же установку [подготовки под другого владельца](02-getting-started.md), что триггерится интерактивно: машина встанет без личных данных, а кто первый загрузится — выберет клаву и заведёт юзера. Режим под imaging-риги, где на драйве вообще не должно быть ничьих кредов.

## SSH-доступ

Лежит `authorized_keys` — установка кладёт ключи как `~/.ssh/authorized_keys` юзера, включает `sshd` и открывает под него фаервол. (Стоковая установка Omarchy везёт openssh с выключенным сервисом и закрытым портом — так что unattended-машина иначе была бы недостижима.) Установка только добавляет твои ключи — остальные настройки аутентификации SSH-демона не ослабляет.

Лежит `tailscale_authkey` — машина вместо этого входит в твой тейлнет на первой загрузке: Tailscale ставится из пакетов, вшитых в ISO, фаервол открывает интерфейс тейлнета, а фоновая задача выполняет подключение, как только у машины реально появляется сеть, до успешного подключения. Бери переиспользуемый предавторизованный ключ — один образ драйва послужит многим машинам.

## Сборка cidata-драйва

Годится любая файловая система с правильной меткой. Крошечный ISO — лёгкий путь:

```bash
mkdir cidata
cp user_configuration.json user_credentials.json authorized_keys cidata/
genisoimage -output cidata.iso -volid cidata -joliet -rock cidata/
```

Дальше прицепи его к VM рядом с ISO Omarchy. Вот полный пример Proxmox:

```bash
qm create 101 --name my-omarchy \
  --bios ovmf --machine q35 --cpu host --cores 4 --memory 8192 \
  --ostype l26 --scsihw virtio-scsi-single \
  --efidisk0 local-lvm:0,efitype=4m,pre-enrolled-keys=0 \
  --scsi0 local-lvm:40,discard=on,iothread=1 \
  --net0 virtio,bridge=vmbr0 --vga virtio --serial0 socket \
  --ide2 local:iso/omarchy.iso,media=cdrom \
  --ide3 local:iso/cidata.iso,media=cdrom \
  --boot order='scsi0;ide2'

qm start 101
```

Диск первым в порядке загрузки — не зря: пустой диск проваливается к ISO на первой загрузке, а поставленная система грузится с диска дальше всегда.

## Два кавеата

Шифрованные unattended-установки не полностью unattended — LUKS-пароль на первой загрузке всё равно вбивать кому-то. А блок `disk_encryption` в `user_configuration.json` несёт тот пароль плейнтекстом — так что к cidata-драйву, собранному из шифрованной установки, относись как к секрету, которым он является.
