# Установка без участия пользователя

ISO-образ Omarchy может установить систему сам, когда за клавиатурой никого нет. Если установщик найдёт второй диск с меткой `cidata`, содержащий его файлы конфигурации, он скопирует их, полностью пропустит мастер настройки и самостоятельно перезагрузится в готовую систему. Никакой специальной сборки ISO, никакого дополнительного пункта в меню загрузки — если такого диска нет, ничего не меняется, и вы получаете обычный мастер.

Это делает Omarchy отличным базовым образом для одноразовых сред разработки: создайте VM в Proxmox или с помощью Packer, загрузите её, отойдите и подключитесь по SSH. `cidata` — это метка cloud-init `NoCloud`, поэтому все распространённые инструменты виртуализации уже умеют подключать такой диск.

## Файлы конфигурации

Эти файлы — в точности те, что записывает собственный мастер установщика, поэтому проще всего получить стартовый набор, выполнив одну интерактивную установку (например, в VM) и скопировав то, что он записал в `/root`:

| Файл | Обязательный | Назначение |
|------|----------|---------|
| `user_configuration.json` | Да | Диск, имя хоста, часовой пояс, клавиатура |
| `user_credentials.json` | Да | Имя пользователя и хэш пароля |
| `user_encrypt_installation.txt` | Нет | `true`, когда конфигурация содержит блок `disk_encryption` |
| `authorized_keys` | Нет | Публичные ключи SSH, по одному на строку |
| `tailscale_authkey` | Нет | Ключ аутентификации Tailscale для подключения к вашему tailnet при первой загрузке |

Хэш пароля для `user_credentials.json` генерируется командой `openssl passwd -6 "yourpassword"`.

Имя и email для коммитов git не входят в установку. Задайте их, когда машина заработает, например по SSH, командой `omarchy setup git --name "Jane Doe" --email jane@example.com`.

Вместо `user_credentials.json` можно также положить пустой файл с именем `defer-provisioning`. Это запустит ту же [установку с подготовкой для другого владельца](02-getting-started.md), которую можно выбрать интерактивно: машина устанавливается без чьих-либо личных данных, а тот, кто загрузит её первым, выберет свою клавиатуру и создаст своего пользователя. Это режим для стендов развёртывания образов, где на диске вообще не должно быть ничьих учётных данных.

## Доступ по SSH

Когда присутствует `authorized_keys`, установка настраивает эти ключи как `~/.ssh/authorized_keys` пользователя, включает `sshd` и открывает для него firewall. (В стандартной установке Omarchy поставляется openssh с отключённой службой и закрытым портом, поэтому машина без присмотра иначе была бы недоступна.) Установка только добавляет ваши ключи — она не ослабляет никакие другие настройки аутентификации демона SSH.

Когда присутствует `tailscale_authkey`, машина при первой загрузке вместо этого подключается к вашему tailnet: Tailscale устанавливается из пакетов, включённых в ISO, firewall разрешает интерфейс tailnet, а фоновое задание выполняет подключение, как только у машины действительно появится сеть, повторяя попытки до успеха. Используйте многоразовый, предварительно авторизованный ключ, чтобы один образ диска мог обслуживать множество машин.

## Создание диска cidata

Подойдёт любая файловая система с правильной меткой. Проще всего сделать крошечный ISO:

```bash
mkdir cidata
cp user_configuration.json user_credentials.json authorized_keys cidata/
genisoimage -output cidata.iso -volid cidata -joliet -rock cidata/
```

Затем подключите его к VM вместе с ISO Omarchy. Вот полный пример для Proxmox:

```bash
qm create 101 --name my-omarchy \
  --bios ovmf --machine q35 --cpu host --cores 4 --memory 8192 \
  --ostype l26 --scsihw virtio-scsi-single \
  --efidisk0 local-lvm:0,efitype=4m,pre-enrolled-keys=0 \
  --scsi0 local-lvm:40,discard=on,iothread=1 \
  --net0 virtio,bridge=vmbr0 --vga virtio --serial0 socket \
  --ide2 local:iso/omarchy.iso,media=cdrom \
  --ide3 local:iso/cidata.iso,media=cdrom \
  --boot order='scsi0;ide2'

qm start 101
```

Порядок загрузки намеренно ставит диск первым: при первой загрузке пустой диск пропускает загрузку дальше к ISO, а после этого установленная система всегда загружается с диска.

## Два предупреждения

Зашифрованные установки без участия пользователя не полностью обходятся без участия — кому-то всё равно придётся ввести парольную фразу LUKS при первой загрузке. А блок `disk_encryption` в `user_configuration.json` содержит эту парольную фразу открытым текстом, поэтому относитесь к диску cidata, созданному из зашифрованной установки, как к секрету, которым он и является.
