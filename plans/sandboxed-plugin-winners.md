## Shared host dependencies

All four import the original `qs.Commons` and `qs.Ui` modules. Those modules are not just colors and controls: `Color.qml` watches the current theme, `Style.qml` reads theme configuration and compositor options, and panel/widget primitives consume bar geometry, popup ownership, focus and lifecycle. Packaging unchanged plugin QML with inert defaults would not establish theme or panel parity.

The native host uses one logical `SandboxedPluginSession` with a `SandboxedOutputSurface` per output, not a single largest-screen canvas. Independent widget placements share one worker/service, including in a trusted replacement bar. Omarchy owns panel placement and focus; roaming is owner-output-only unless the host explicitly selects the all-output policy. Omarchy separately stages the shared loader, Commons/Ui and compatibility facade; the host supplies that trusted runtime to Ward by directory descriptor. These changes retain own-service/overlay lifecycle and live detached settings/style without loading plugin QML in the host. All four review forks declare sandbox requests. Generic tests cover mixed-DPI streams, ownership transfer, hotplug, zero outputs and crash/restart, alongside slot resizing, all four bar edges, popup anchoring, pointer handoff, movement, hiding and replacement-bar switching. Shared tooltips and gesture-gated keyboard panel switching remain covered. Installed/physical output verification, full font-asset parity and original-plugin desktop acceptance are still required; generic fixture results do not check off those plugin features.

The shared presentation contract owns fractional scaling and output changes; plugin-specific coordinate needs must not create another protocol. Omagotchi's optional geometry grant supplies output identity, origin, reserved edges and window rectangles separately from its required drawable allocations. Radio Atlas receives host-owned screensaver dismissal through its own-panel lifecycle. Neither mechanism exposes the raw Hyprland command socket. See the [architecture reference](../docs/ward-architecture.md) for the implemented boundaries.
