# Display-panel layout persistence

The monitor scaling command applies the requested layout with live IPC, checks the resulting geometry, and saves it as framed data in `$XDG_STATE_HOME/omarchy/monitor-layout` (default `~/.local/state/omarchy/monitor-layout`). It never writes the owner's `hypr/monitors.lua` or disables Hyprland's config watches. Saving the state file does not itself request a whole-config reload.

`default.hypr.toggles` invokes the data loader after the personal monitor config and before explicit disable/mirror/clamshell toggle rules. The loader reads data with `io.open`; it does not execute the state file or register it as a sourced config file. A valid record contains the exact owner-file bytes plus the verified output modes, positions, scales and transforms. A record containing only one output also saves the rounded GDK scale when the owner file uses the standard `omarchy_gdk_scale` convention. Layouts use the actual verified output modes. The loader applies the record only while the owner file is byte-identical to that baseline.

An owner edit to `monitors.lua`, including a comment edit, invalidates the saved layout so the owner's new configuration takes precedence on the next normal reload. Scale changes saved afterward create a record against the new baseline. Unrelated sourced-file watches remain enabled throughout. The managed data file is owned by this command; tools modifying it must use the same runtime lock. It is not an owner configuration file.

If an owner edit is detected before or during publication, the command cancels the save, restores the previous managed record, and explicitly reloads current owner configuration. Geometry/readback/publication errors and catchable termination use the same recovery. An intentionally disabled-autoreload policy is preserved: recovery instead restores the previous live monitor rules and reports that owner edits await an explicit reload. Publication never targets the owner file, so an editor save between comparison and publication cannot be overwritten. An edit after the last comparison remains subject to normal watches and baseline invalidation.

Every helper IPC call and the CLI's initial monitor queries have ten-second deadlines. INT/TERM/HUP enter cleanup; repeated signals during state restoration and bounded recovery are deferred until the remaining cleanup completes. Recovery failure is reported with the saved-state path and `hyprctl reload` as the owner action once the compositor responds. SIGKILL, process crashes, compositor death and power loss cannot guarantee live recovery; no global autoreload flag is left modified by this implementation.

Install the command, Python helper, data loader and updated `default/hypr/toggles.lua` together. Applying only the helper omits next-session restoration. The prior no-reload prototype's synchronous global watch-pause protocol is superseded by this data-store design. No compositor refresh-barrier extension is required.

After publication, the helper verifies live topology, physical modes, logical rectangles, scales and transforms again and requires two consecutive matching samples. It then rechecks both the saved record and owner baseline bytes. An unrelated reload that consumed the old record can undo the prepublication eval; that outcome now cancels the save and recovers current config rather than reporting success from stored bytes. These are bounded final observations, not serialization or a guarantee against future owner/compositor changes.

The scaling helper reads live geometry after acquiring the runtime writer lock, including when resolving relative `up`/`down` requests. Clamshell reconciliation holds that same lock across reading managed state, recovery, scale comparison and live application. The Python supervisor keeps the lock out of child descriptors, runs the entire reconciliation in its own process group with a 30-second deadline, and kills outstanding helpers before releasing the lock on timeout, failure or a catchable signal. It restores the saved mode, position, scale and transform instead of substituting numeric owner defaults. Disable/mirror/clamshell toggles still take precedence over saved geometry.

A save retains disconnected outputs from a byte-valid prior record. It resizes their remembered adjacency graph around the connected outputs, preserves absent outputs' modes/scales/transforms, then translates the result to the live anchor. All common outputs must agree with that projected graph and the merged rectangles must not overlap. A disconnected record with no common output, an ambiguous rearranged subset, or a changed transform is rejected before live writes; reconnect and arrange the outputs before saving in those cases. Owner baseline invalidation also invalidates remembered disconnected preferences. The helper does not probe disconnected hardware or apply rules to it through live IPC.
