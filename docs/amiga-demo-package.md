# Native Amiga Demos screensaver

## Menu and lifecycle

`Style > Screensaver > Amiga` invokes `omarchy-setup-screensaver amiga` directly. It first performs a silent, headless readiness check: when the installed runtime and Top pack verify, it selects Amiga with no terminal, window or notification. Only a not-ready result opens the Omarchy presentation terminal for `amiga --install`; that installer rechecks readiness internally to close the preflight/install race. The choice is transactional: installation uses the single fixed `omarchy-amiga` bundle through `omarchy-pkg-add`, verifies the target architecture, every required runtime hash, Top pack checksums and declared counts, and only then atomically persists `~/.config/omarchy/screensaver`. A failed, cancelled, partial, unsupported-architecture or checksum-rejected installation preserves the prior selection and reports a localized error; rerunning the same row retries. `Default` writes only the upstream mode and never probes or installs Amiga dependencies. Neither choice uninstalls or overwrites user media. `Preview` invokes the selected backend with `force`; normal idle activation uses the same launcher without `force` and never installs anything. The original Omarchy text screensaver and its branding editor remain available. Amiga failure never falls back to Default, text, ttfx, video or another emulator.

The native idle service lazily loads the optional guard from a real filesystem URL. Missing native dependencies therefore do not prevent the desktop or text screensaver from loading. The input guard is part of the existing desktop process, not a background plugin or a second production Quickshell instance. The existing lock timer, recent bounded lock IPC authorization and guard lease remain independent of the emulator. Selection does not alter Stay Awake or `screensaver-off`; Preview does not prove automatic activation.

The guard covers every output with an opaque Overlay layer. Its focused output exports only the exact token-matched FS-UAE toplevel, not an output capture. The source must read back as a floating 640×480 window before presentation; forcing the source to monitor-sized fullscreen reintroduces the observed software SHM export distortion. The controller additionally checks the window's ancestry, emulator process name and separate PID/user/mount/network namespaces before any window operation. Other panels and windows are never closed or reconfigured.

Physical M toggles session mute, consuming press/release and ignoring repeat. A native Qt relative-pointer observer handles real relative motion, while a Qt event filter observes classified buttons/wheel before QML hit testing. Absolute cursor changes are not dismissal evidence. There is no unclassified idle-resume M grace period. The guard reports requested versus confirmed mute separately; only successful exact-stream Pulse readback acknowledges a toggle. The bottom hint lasts 2000ms on entry and acknowledgement. The controller reads locale fields from the running shell's `amigaLocale` IPC, applies Omarchy locale precedence/regional fallback and system gettext catalogs, then application-only gaps in `i18n.json` for es/fr/de/ru. No user/global language or system audio setting is changed.

## Package boundary

`packages/amiga-runtime/` is the source-only runtime component for the intended architecture-specific `omarchy-amiga` bundle. The production bundle contract includes that target-native runtime and the minimal Top v1 content pack; it is **not published** and no repository or release-asset URL is invented by this change. The menu checks `pacman -Si omarchy-amiga` before invoking the privileged package helper, and an unavailable bundle produces a clear localized error without changing selection. Kuyen acceptance uses the already built x86_64 runtime and already installed actual Top v1 pack through the explicit user-prefix development seam, so it neither downloads the verified assets again nor represents a published install test.

The runtime owns `/usr/lib/omarchy-amiga-runtime/`: `fs-uae/bin/fs-uae` with its adjacent data, `audio/libopenal.so.1`, `audio/libamiga-pulse.so`, `bin/gl-probe`, and `guard/Guard.qml` plus the `AmigaInput` Qt module. The final package must generate `runtime-manifest.json` after staging by running `packages/amiga-runtime/write-runtime-manifest.py`; readiness rejects the wrong architecture, missing manifest entries, symlinks and hash mismatches. The bundle's Top installer must use the existing staged checksum-verified merge, preserving an existing collection on every preflight or commit failure and never deleting user media. These artifacts must be built together for each supported architecture and rebuilt against compatible Qt. The hash-bound `fs-uae/FRAME_PROTOCOL` marker must be version 1, and the emulator must actually emit its owned-generation records; an old binary cannot be upgraded by changing the marker. Build instructions and source pins are in `packages/amiga-runtime/README.md`. No binaries, demo disks, snapshots, ROMs, captures or user previews belong in the Omarchy Git change. License and redistribution review plus publication of the runtime package and Top release asset remain gates; possession of a demo is not permission to redistribute it.

FS-UAE runs in mandatory bubblewrap isolation with a private writable home/state, immutable hash-checked assets and only the exact Wayland/Pulse sockets plus one probed render node. The controller probes a real hidden desktop GL context inside the intended sandbox and uses hardware only when the result is a non-software renderer; it falls back to software only after actual sandbox context failure. No host home/runtime directory, D-Bus, network, card/input device or raw audio device is shared. The private OpenAL Soft is linked directly to Pulse (`ALSOFT_DLOPEN=OFF`) because a dlopen backend can bypass ordinary interposition. The emulator-only Pulse wrapper atomically sets `PA_STREAM_START_MUTED`, clears `START_UNMUTED` and sets 0.10 linear amplitude (−20dB). Runtime M changes only the random child application ID's sink-input; it never changes a default sink or unrelated stream.

A persistent flock prevents concurrent controllers. Each child is registered as a real Popen handle with a Linux pidfd, and parent-death protection complements bubblewrap's `--die-with-parent`. Cleanup rejects mock/unregistered handles and PIDs at or below 1; it never signals a name or process group. The same guard owner survives rotations, while every child has a new window token and fresh log/state. An explicit cover clears the prior capture before stopping the old child. Cancellation, missing ending, child failure or IPC failure terminates the session instead of advancing or retrying indefinitely. The last child log is retained at `~/.local/state/omarchy/amiga/emulator.log`; restore detection reads only the current child's fresh log.

## Prepared Top assets and playback

The saved-state controller reads only `~/Wallpapers/AMIGA/`, matching the pack's `AMIGA/` archive root. It requires the `amiga-fullpack-v1` / `top-minimal` catalog, checksum-bound titles, previews, configurations, states and every required disk, exact declared production/configuration counts, and `Ok` approval for each included variant. One approved primary configuration is selected per production. That curator approval is not a claim that every state has been restored or fully watched on the destination machine.

Configuration options are allowlisted. Disk settings must bind to the catalog's contained files and exact embedded `/media/...` paths. The controller revalidates the selected catalog binding before every child, copies its state and disks into private scratch space and rehashes those copies. Only one effective `--state-dir=/restore` and `--load-state=1` are passed. Presentation requires frame protocol 1 from the newly built private FS-UAE: the fresh child token, restore generation, producer-row provenance, matching upload/completed draw and successful OpenGL readback/swap, plus the independently checked owned source geometry. Ordered stock completion text alone is rejected. Reported restore errors override frame readiness; missing states, instrumentation or frames stop the session instead of authorizing cold-boot playback. This mechanical gate is not scene approval or compositor presentation proof.

Left/Right traverse the session's actual navigation history and restore a fresh child for each transition; M retains the requested mute choice across transitions. The current pack does not supply a verified full-demo ending contract. Playback therefore stays on the selected restored demo until explicit navigation or classified dismissal: elapsed time is never treated as completion, and there is no automatic timed rotation. Legacy cold-disk, OCR endpoint and prepared-duration controllers are not shipped.

## Verification and release gates

Tests must run only through the reviewed outer namespace runner (or a disposable VM), never raw process-lifecycle tests on a desktop. The regression fixtures exercise menu parsing and actual selection commands with temporary HOME/package stubs, Top catalog bindings, immutable state/media copies, hash rechecks, navigation history, M handler ordering/repeat, timer expiry, locale precedence, exact-stream mute guards, source geometry, lock authorization and pidfd/parent-death cleanup. Synthetic fixtures are explicitly not playback attestations.

Local-prefix validation builds the native extension, Pulse wrapper, private OpenAL and FS-UAE from pinned sources. The separate package fixture can execute the installed native module through QtTest, a compiled Pulse interposition fixture and an explicitly authorized no-media FS-UAE software-renderer boot with exact cleanup. These package checks are not part of `test/all`. Qt offscreen has no Quickshell PanelWindow backend: it does not prove full guard rendering, menu visibility, audio audibility or compositor transitions.

The supported user-scoped native idle clone and menu extension are deployed on Kuyen for immediate menu testing without replacing `/usr/share/omarchy` or restarting the desktop shell. Both Default and Amiga checked states were read back and visually captured; selection did not start FS-UAE or alter Stay Awake, idle timeouts or `screensaver-off`. Before frame protocol 1 was introduced, the x86_64 development runtime manifest and actual Top v1 pack passed the earlier readiness checks with 31 demos, 35 configurations and all 135 checksum entries verified. That installed runtime has not been replaced or revalidated against the new frame gate. This does not remove the release gates: `omarchy-amiga` and its Top release asset are not published, the OPR/package review is incomplete, and the Kuyen deployment uses the explicit existing-runtime/content development seam. Complete sustained playback, thermal behavior, automatic-idle activation and the publication install path remain unaccepted; CPU/thermal investigation is deferred.
