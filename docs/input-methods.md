# Input methods

The install keyboard picker selects a console keymap plus an optional Fcitx engine. `install/provisioning/setup-form.sh` is shared by the ISO configurator and deferred first-boot owner setup. Its rows are `label|console keymap|input method|desktop XKB override`; the last two fields are optional, so ordinary keyboard choices keep their existing meaning.

The ISO carries the extra fields in `omarchy_install.input_method` and `omarchy_install.input_xkb_layout`. Both installation paths persist them in `/etc/omarchy/input-method` as `INPUT_METHOD` and `XKB_LAYOUT`. This file is parsed as data, never sourced. Korean and Lao have a real US console keymap and a `kr:kr104` or `la` desktop override (Lao is non-Latin, so US still leads on the desktop). Korean takes `kr104`, carried as layout and variant, so 한/영 and 한자 work both as dedicated keys and on keyboards that send Right Alt and Right Ctrl for them; plain `kr`, which earlier installs saved, is still accepted; Japanese uses `jp106`, or US when the US-keyboard choice is selected. Console and disk-unlock input remain ordinary keymaps.

`install/user/input-method.sh` calls `omarchy-input-method configure --seed` during user finalization, before graphical login. The standard engines are in the base package set so deferred provisioning and factory resets do not need network access to configure typing. `default/input-methods/presets.json` is the engine catalog used by the post-install selector.

`default/input-methods/configure.py` owns the shared configuration behavior. Offline seeding replaces only a missing profile or Fcitx's untouched single `keyboard-us` guess. The group layout matches Hyprland's effective leading layout and variant; non-Latin layouts retain the US-leading behavior used for desktop bindings. The selected composition engine is the group's `DefaultIM`, with `ActiveByDefault=False` so initial typing remains Latin. Existing multilingual profiles and explicitly chosen keyboard layouts are preserved.

`omarchy setup input <engine>` installs the selected engine's packages, then appends it through the same path as the Input Methods picker. Selecting an engine whose package is installed but which the running Fcitx has not discovered (one an update installed, say) restarts the supervised Fcitx unit once and waits for it; an engine whose package is missing is refused with the package name. Changes go through `InputMethodGroupInfo`, `SetInputMethodGroupInfo`, and `Save`, keeping the group name, layout, existing methods in their switching order, and their layout overrides. There is no parallel unsupervised daemon. A per-user D-Bus activation file delegates `org.fcitx.Fcitx5` to `omarchy-fcitx5.service`.

`Setup > Typing > Keyboard Layouts` and `Input Methods` use the native menu's multi-select mode, with current entries checked and changes applied immediately. `default/input-methods/typing_setup.py` uses the installer’s keyboard choices, converted to desktop layouts through systemd’s keymap table, and reads the current input group. Input selection replaces only the non-keyboard group items and retains selected engines' layout overrides; deselection does not uninstall packages. Hangul, Zhuyin, and Cangjie are positional, so a preset's `layout` keeps them on US key positions when the leading layout is another Latin arrangement (Dvorak, Colemak, AZERTY); Korean and JIS groups keep their own keys, since those carry 한/영 and 半角/全角. Changing the leading layout re-decides only overrides Omarchy set. The standard composition engines are already shipped in the base package set. Closing a picker keeps changes already applied. Failed updates leave its checked state unchanged.

Keyboard selections are persisted as data in `~/.config/omarchy/keyboard-layouts`; `default.hypr.keyboard.selected()` reads them before falling back to installation defaults. Personal Hyprland overrides still take precedence. A save reloads and validates the compositor, aligns the Fcitx group's primary keyboard with the leading layout/variant, and restores the previous configuration and group on failure. Non-Latin selections keep the installer's Latin-leading rule for desktop shortcuts. System console, disk-unlock, and greeter layouts are unchanged.

The bar reads Fcitx through one long-running reader, `default/input-methods/indicator.py`, started by `shell/Commons/InputMethodState.qml`. Fcitx signals neither a method switch nor a configuration change over D-Bus (Controller1's `InputMethodGroupsChanged` stays silent for both), so the reader reads once at startup and again when the `org.fcitx.Fcitx5` bus name changes owner or the profile changes. The profile is `$FCITX_CONFIG_HOME/profile`, else `$XDG_CONFIG_HOME/fcitx5/profile`, located from the environment of the process that owns the bus name each time it appears, so a service drop-in that moves it is followed. The file watch follows saves that rename a new profile into place; a dotfiles directory relinked while Fcitx runs is picked up at Fcitx's next start. It polls every 500 ms only while there is something to switch between: more than one method in the current group, a lone composition engine (which still toggles and steps aside in password fields), or more than one group. A read that fails while the service is running is retried every 2 s. A single-method setup costs no wakeups.

Shortcut defaults reserve Ctrl+Space for Tmux/Herdr, Super+Space for the menu, Super+Shift+Space for the bar, and Super+grave for the console. Hyprland owns Super+I to cycle all selected compositor layouts followed by the configured Fcitx input methods, independently of Fcitx switching keys. With keyboard layouts alone, the same shortcut cycles the compositor layouts, keeping matching devices in sync even without the bar widget. The widget is enabled in the default right-hand bar layout and appears only when more than one input method or keyboard layout is configured. Fcitx handles Zenkaku/Hankaku and Hangul; Henkan activates and Muhenkan deactivates. Ctrl+Space is never a Fcitx toggle: `configure --defaults` removes it from any TriggerKeys list, keeping the user's other keys, and writes Omarchy's list where none exists, since Fcitx's built-in default includes it. Other existing lists, including empty ones, are preserved, and stock generated lists are repaired only while the user still has the single-keyboard default profile. A terminal Ctrl+Space returns to direct input before the following key, with a 300 ms timeout and no D-Bus activation. Wayland and XCB addons do not override the compositor's XKB settings.

The OSD observes confirmed input changes from the same reader. The reader includes an ordered switch counter in its existing JSON output and receives Hyprland layout events through the shell's existing connection and command pipe. Pending selections are announced only after Fcitx accepts them; starting or restarting the reader stays silent. Native cycles reuse the compositor query already needed for switching. External Fcitx changes, including per-application restores, use the existing 500 ms observation interval. Restoring a different input method shows a notice; focusing an app with the same selection stays silent. Display failures do not change input selection. Names come from Qt's native language names, using Fcitx's language code or the system XKB catalog, with the input method's name as a fallback.

Fcitx's ordinary switch and focus notices are controlled by `Behavior/ShowInputMethodInformation` and `Behavior/showInputMethodInformationWhenFocusIn`. Disabling these leaves preedit and candidate selection available. The candidate window follows the Omarchy theme; see *Fcitx candidate window* in `docs/theming.md`.

New installs disable those two notices in the shipped Fcitx config. The OSD migration updates only those settings on existing installs, following config symlinks, file permissions, and the running Fcitx process's config location. It skips users who disabled the stock OSD, including those using a clone. A running Fcitx reloads its config without restarting; a failed reload restores the file and leaves the migration pending. Offline changes take effect when Fcitx starts. The normal update restarts the shell after migrations; the migration does not restart it itself.

The migration installs the standard engines and applies conservative defaults. It aligns an untouched Fcitx keyboard profile with the install layout, using the live controller when Fcitx is running. It leaves existing multilingual profiles and working trigger keys alone. Atomic file writes follow configuration symlinks, preserve file modes, and roll back on a failed seed or migration so a retry can complete. Migration bus errors defer profile alignment to the next login and do not restart input. If a pre-update daemon has not discovered a new engine, the migration aligns only its keyboard and prints the setup command.

Input selection does not change the system locale, repository region, desktop language, or Latin interface font. A new language setup seeds a CJK fallback preference once; additional languages do not overwrite it. That preference is one file, `~/.config/fontconfig/conf.d/50-omarchy-input-method.conf`, which accepts a Noto CJK variant after `sans-serif`, `serif`, `monospace` and the Latin families `50-omarchy.conf` replaces them with, so Chromium's family-less per-character fallback finds it too while the Latin font stays first. `omarchy font cjk <jp|kr|sc|tc|hk|default>` (Style > Font > Chinese, Japanese, Korean) rewrites or removes it through `configure.py font`; `--seed` writes it only when absent. Because the accept is weak, text tagged with a language and a CJK session `LANG` both keep their own variant through `50-omarchy.conf`'s strong rules; the preference decides untagged text in every other language. `omarchy-language` seeds it for Japanese, Korean, Simplified and Traditional Chinese through `typing_setup.py seed-language`, which also adds Mozc, Hangul, Pinyin or Chewing when the live Fcitx group has no composition engine yet; with no reachable Fcitx the language still switches and the command names where to add the engine. With no preference, `default/fontconfig/conf.avail/50-omarchy.conf` accepts Japanese forms after the same Latin families, so untagged Han matches across apps and CJK punctuation stays out of Noto Sans Mongolian in Chromium; the preference file loads later and inserts ahead of it.

Focused checks live in `test/shell.d/input-method-test.sh`, `setup-form-test.sh`, `hyprland-keyboard-layout-test.sh`, and `hyprland-jis-bindings-test.sh`. `test/acceptance.d/input-methods-test.sh` exercises real composition in a disposable installed VM and restores the original user configuration. The ISO repository's keyboard tests cover transport and target persistence. Browser input must be verified against the shipped browser versions; the language selector is not a place to guess flags from older guides.

Default key values are checked against [Fcitx global configuration](https://github.com/fcitx/fcitx5/blob/master/src/lib/fcitx/globalconfig.cpp).
